ギアドテスト¶

このファイルは、ギアによって提供されるUSB機能の基本的なテストに関する情報をまとめています。

1. ACM機能¶

この機能はusb_f_acm.koモジュールによって提供されています。

関数固有のconfigfsインターフェース¶

関数ディレクトリを作成する際の関数名は「acm」です。ACM機能は関数ディレクトリにただ1つの属性を提供します：

port_num

この属性は読み取り専用です。

システムには最大で4つのACM/汎用シリアル/OBEXポートが存在できます。

ACM機能のテスト¶

ホスト側では：

cat > /dev/ttyACM<X>

デバイス側では：

cat /dev/ttyGS<Y>

逆に

デバイス側では：

cat > /dev/ttyGS<Y>

ホスト側では：

cat /dev/ttyACM<X>

2. ECM機能¶

この機能はusb_f_ecm.koモジュールによって提供されています。

関数固有のconfigfsインターフェース¶

関数ディレクトリを作成する際の関数名は「ecm」です。ECM機能は関数ディレクトリに以下の属性を提供します：

ifname

この機能インスタンスに関連するネットワークデバイスインターフェース名

qmult

高速およびスーパー速度用のキュー長乗算子

host_addr

このUSBエセッターリンクのホスト側のMACアドレス

dev_addr

このUSBエセッターリンクのデバイス側のMACアドレス

functions/ecm.<instance name>を作成した後、これらは次のデフォルト値を含みます：qmultは5、dev_addrおよびhost_addrはランダムに選択されます。関数がバインドされていない場合、ifnameは書き込むことができます。書き込みには「usb%d」というインターフェースパターンを指定する必要があります。これにより、ネットワークコアが次の空きusbXインターフェースを選択します。デフォルトでは「usb%d」が設定されています。

ECM機能のテスト¶

デバイスとホストのIPアドレスを設定します。その後：

デバイス側では：

ping <host's IP>

ホスト側では：

ping <device's IP>

5. FFS機能¶

この機能はusb_f_fs.koモジュールによって提供されています。

関数固有のconfigfsインターフェース¶

関数ディレクトリを作成する際の関数名は「ffs」です。関数ディレクトリは意図的に空であり、変更できません。

ディレクトリを作成した後、システムにFunctionFSの新しいインスタンス（「デバイス」と呼ばれる）が利用可能になります。デバイスが利用可能になったら、ユーザーはFunctionFSの標準的な使用手順（マウントし、機能を実装するユーザー空間プロセスを実行）に従う必要があります。ギガットを有効にするには、usb_gadget/<gadget>/UDCに適切な文字列を書き込む必要があります。

FFS機能のテスト¶

デバイス側：機能のユーザー空間デーモンを起動し、ギガットを有効化する

ホスト側：デバイスが提供するUSB機能を使用する

6. HID機能¶

この機能はusb_f_hid.koモジュールによって提供されます。

関数固有のconfigfsインターフェース¶

機能ディレクトリを作成する際の機能名は「hid」です。HID機能は、その機能ディレクトリに次の属性を提供します：

protocol

使用するHIDプロトコル

report_desc

HIDレポートで使用するデータ（/dev/hidg<X>で渡されたデータを除く）

report_length

HIDレポート長

subclass

使用するHIDサブクラス

キーボードの場合、プロトコルおよびサブクラスは1で、レポート長は8で、レポート_descは以下のようになります：

$ hd my_report_desc
00000000  05 01 09 06 a1 01 05 07  19 e0 29 e7 15 00 25 01  |..........)...%.|
00000010  75 01 95 08 81 02 95 01  75 08 81 03 95 05 75 01  |u.......u.....u.|
00000020  05 08 19 01 29 05 91 02  95 01 75 03 91 03 95 06  |....).....u.....|
00000030  75 08 15 00 25 65 05 07  19 00 29 65 81 00 c0     |u...%e....)e...|
0000003f

このようなバイト列は、echoコマンドで属性に保存できます：

$ echo -ne \\x05\\x01\\x09\\x06\\xa1.....

HID機能のテスト¶

デバイス：

  • ギガットを作成する

  • ギガットをホストに接続し、ギガットを制御したホストとは異なるホストを使用することを推奨します

  • /dev/hidg<N>に書き込むプログラムを実行します（例：tools/usb/に存在するユーザー空間プログラム） Linux USB HID gadgetドライバ:

    $ ./hid_gadget_test /dev/hidg0 keyboard

ホスト：

  • ギガットからのキーボード入力を観察する

8. MASS STORAGE機能¶

この機能はusb_f_mass_storage.koモジュールによって提供されます。

関数固有のconfigfsインターフェース¶

機能ディレクトリを作成する際の機能名は「mass_storage」です。MASS STORAGE機能は、そのディレクトリに次の属性を提供します：files:

ストール

機能がバルクエンドポイントを停止できるようにするにはこの値を設定してください。一部のUSBデバイスでは動作しない可能性があるため無効になっています。trueに設定してください。

num_buffers

パイプラインバッファの数。有効な数値は2〜4です。CONFIG_USB_GADGET_DEBUG_FILESが設定されている場合にのみ利用可能です。

およびデフォルトのlun.0ディレクトリ（SCSI LUN #0に相当）

新しいlunはmkdirコマンドで追加できます：

$ mkdir functions/mass_storage.0/partition.5

lunの番号は連続する必要はありません（lun #0はデフォルトで作成されます）。最大8つのlunを指定でき、すべてのlunは<name>.<number>の形式で名前をつける必要があります。番号は0..8の範囲です。おそらく良い慣習はlunを「lun.<number>」と名付けることです（必須ではありません）。

各lunディレクトリには次の属性ファイルがあります：

ファイル

LUNのバックインファイルへのパス。LUNが挿抜可能でない場合、必須です。

ro

LUNへのアクセスが読み取り専用であることを指定するフラグ。CD-ROMエミュレーションが有効になっている場合や「filename」をR/Wモードで開けなかった場合に自動的に設定されます。

removable

LUNが挿抜可能であることを示すフラグ。

cdrom

LUNがCD-ROMであることをレポートするフラグ。

nofua

SCSI WRITE(10,12)のFUAフラグを指定するフラグ

MASS STORAGE機能のテスト¶

デバイス：ギガットを接続し、有効にする ホスト：dmesgを実行し、USBドライブが表示されるのを確認する（システムが自動マウントを設定している場合）

9. MIDI機能¶

この機能はusb_f_midi.koモジュールによって提供されます。

関数固有のconfigfsインターフェース¶

関数ディレクトリを作成する際には「midi」という関数名を使用します。MIDI関数はその関数ディレクトリで以下の属性を提供します：

buflen

MIDIバッファ長

id

USB MIDIアダプターのID文字列

in_ports

MIDI入力ポート数

index

USB MIDIアダプターのインデックス値

out_ports

MIDI出力ポート数

qlen

USB読み込みリクエストキュー長

MIDI関数のテスト¶

2つのケースがあります：ギアットからホストへのMIDI再生と、ホストからギアットへのMIDI再生です。

  1. ギアットからホストへのMIDI再生：

ホスト：

$ arecordmidi -l
 Port    Client name                      Port name
 14:0    Midi Through                     Midi Through Port-0
 24:0    MIDI Gadget                      MIDI Gadget MIDI 1
$ arecordmidi -p 24:0 from_gadget.mid

ギアット：

$ aplaymidi -l
 Port    Client name                      Port name
 20:0    f_midi                           f_midi

$ aplaymidi -p 20:0 to_host.mid

  1. ホストからギアットへのMIDI再生

ギアット：

$ arecordmidi -l
 Port    Client name                      Port name
 20:0    f_midi                           f_midi

$ arecordmidi -p 20:0 from_host.mid

ホスト：

$ aplaymidi -l
 Port    Client name                      Port name
 14:0    Midi Through                     Midi Through Port-0
 24:0    MIDI Gadget                      MIDI Gadget MIDI 1

$ aplaymidi -p24:0 to_gadget.mid

from_gadget.midはto_host.midと音が同じになる必要があります。

from_host.idはto_gadget.midと音が同じになる必要があります。

MIDIファイルはtimidityがインストールされている場合、スピーカー/ヘッドホンに再生できます：

$ aplaymidi -l
 Port    Client name                      Port name
 14:0    Midi Through                     Midi Through Port-0
 24:0    MIDI Gadget                      MIDI Gadget MIDI 1
128:0    TiMidity                         TiMidity port 0
128:1    TiMidity                         TiMidity port 1
128:2    TiMidity                         TiMidity port 2
128:3    TiMidity                         TiMidity port 3

$ aplaymidi -p 128:0 file.mid

MIDIポートはaconnectユーティリティを使用して論理的に接続できます。例：

$ aconnect 24:0 128:0 # try it on the host

ギアットのMIDIポートがtimidityのMIDIポートに接続されると、aplaymidi -lでギアット側で再生した音はホストのスピーカー/ヘッドホンで聞こえます。

PHONET関数のテスト¶

SOCK_STREAMプロトコルをテストするには特定のハードウェアが必要なので、テストされたのはSOCK_DGRAMのみです。後者の動作には、過去にここで述べたパッチを適用する必要がありました：

http://www.spinics.net/lists/linux-usb/msg85689.html

必要なツールは以下の通りです：

git://git.gitorious.org/meego-cellular/phonet-utils.git

ホスト側では：

$ ./phonet -a 0x10 -i usbpn0
$ ./pnroute add 0x6c usbpn0
$./pnroute add 0x10 usbpn0
$ ifconfig usbpn0 up

デバイス側では：

$ ./phonet -a 0x6c -i upnlink0
$ ./pnroute add 0x10 upnlink0
$ ifconfig upnlink0 up

その後、テストプログラムを使用できます：

http://www.spinics.net/lists/linux-usb/msg85690.html

デバイス側では：

$ ./pnxmit -a 0x6c -r

ホスト側では：

$ ./pnxmit -a 0x10 -s 0x6c

結果として、ホストからデバイスへのデータ送信が行われるべきです。その後、逆方向で：

ホスト側では：

$ ./pnxmit -a 0x10 -r

デバイス側では：

$ ./pnxmit -a 0x6c -s 0x10

これらの属性には合理的なデフォルト値が設定されています。

UAC2関数のテスト¶

デバイス: ガジェットホスト: aplay -l # USBオーディオガジェットをリスト表示する必要があります

この関数は実際のハードウェアサポートを必要とせず、ホストとの間でオーディオデータのストリームを送信するだけです。デバイス側で実際に音声を聞くには、以下のコマンドのようなものが必要です:

$ arecord -f dat -t wav -D hw:2,0 | aplay -D hw:0,0 &

e.g.:

$ arecord -f dat -t wav -D hw:CARD=UAC2Gadget,DEV=0 | \
  aplay -D default:CARD=OdroidU3

18. UVC関数¶

この関数はusb_f_uvc.koモジュールによって提供されます。

関数固有のconfigfsインターフェース¶

関数ディレクトリを作成する際には「uvc」という関数名を使用します。uvc関数は、その関数ディレクトリに次の属性を提供します:

streaming_interval

データ転送用エンドポイントのポーリング間隔

streaming_maxburst

スーパースピードコンパニオン記述子のbMaxBurst

streaming_maxpacket

この設定が選択されたときに、このエンドポイントが送信または受信できる最大パケットサイズ

function_name

インターフェースの名前

また、「コントロール」と「ストリーミング」のサブディレクトリも存在し、それぞれが複数のサブディレクトリを含みます。ある程度のデフォルト設定は提供されていますが、ユーザーは以下のものを提供する必要があります：

コントロールヘッダー

control/headerに作成し、control/class/fsおよび/またはcontrol/class/ssからリンクを張る

ストリーミングヘッダー

streaming/headerに作成し、streaming/class/fsおよび/またはstreaming/class/hsおよび/またはstreaming/class/ssからリンクを張る

フォーマット記述

streaming/mjpegおよび/またはstreaming/uncompressedに作成する

フレーム記述

streaming/mjpeg/<format>および/またはstreaming/uncompressed/<format>に作成する

各フレーム記述にはフレーム間隔の指定が含まれており、各指定は1行ずつにinterval値を含む複数の行で構成されます。上述のルールは以下の例でより明確になります：

# mkdir functions/uvc.usb0/control/header/h
# cd functions/uvc.usb0/control/
# ln -s header/h class/fs
# ln -s header/h class/ss
# mkdir -p functions/uvc.usb0/streaming/uncompressed/u/360p
# cat <<EOF > functions/uvc.usb0/streaming/uncompressed/u/360p/dwFrameInterval
666666
1000000
5000000
EOF
# cd $GADGET_CONFIGFS_ROOT
# mkdir functions/uvc.usb0/streaming/header/h
# cd functions/uvc.usb0/streaming/header/h
# ln -s ../../uncompressed/u
# cd ../../class/fs
# ln -s ../../header/h
# cd ../../class/hs
# ln -s ../../header/h
# cd ../../class/ss
# ln -s ../../header/h

UVC機能のテスト¶

デバイス：ギャクットを実行し、modprobe vividを実行：

# uvc-gadget -u /dev/video<uvc video node #> -v /dev/video<vivid video node #>
uvc-gadgetはこのプログラムで、

http://git.ideasonboard.org/uvc-gadget.git

以下のパッチを使用します：

http://www.spinics.net/lists/linux-usb/msg99220.html

ホスト：

luvcview -f yuv

19. PRINTER機能¶

この機能はusb_f_printer.koモジュールによって提供されます。

関数固有のconfigfsインターフェース¶

機能ディレクトリを作成する際の機能名は「printer」です。printer機能は以下の属性をその機能ディレクトリに提供します：

pnp_string

pnp string にホストに渡すデータ

q_len

エンドポイントごとのリクエスト数

PRINTER機能のテスト¶

最も基本的なテスト：

デバイス：ギャクットを実行：

# ls -l /devices/virtual/usb_printer_gadget/

g_printer<number>が表示されるべきです。

udevが有効な場合、/dev/g_printer<number>が自動的に出現するはずです。

ホスト：

udevが有効な場合、例えば/dev/usb/lp0が出現するはずです。

ホスト→デバイスの送信：

デバイス:

# cat /dev/g_printer<number>

ホスト：

# cat > /dev/usb/lp0

デバイス→ホストの送信：

# cat > /dev/g_printer<number>

ホスト：

# cat /dev/usb/lp0

より高度なテストはprn_exampleで行えます（ Linux USBプリンタギアドライバ.

20. UAC1機能（仮想ALSAカード、u_audio APIを使用）¶

この機能はusb_f_uac1.koモジュールによって提供され、仮想ALSAカードを作成し、オーディオストリームはこのカードに単純にsinkされ、sourceされます。

関数固有のconfigfsインターフェース¶

機能ディレクトリを作成する際の機能名は「uac1」です。uac1機能は以下の属性をその機能ディレクトリに提供します：

c_chmask

キャプチャーチャンネルマスク

c_srate

キャプチャーサンプリングレート（カンマ区切り）

c_ssize

キャプチャーサンプルサイズ（バイト）

c_mute_present

キャプチャーミュート制御の有効化

c_volume_present

キャプチャーボリューム制御の有効化

c_volume_min

キャプチャーボリューム制御の最小値（1/256 dB単位）

c_volume_max

キャプチャーボリューム制御の最大値（1/256 dB単位）

c_volume_res

キャプチャーボリューム制御の分解能（1/256 dB単位）

p_chmask

プレイバックチャンネルマスク

p_srate

プレイバックサンプリングレート（カンマ区切り）

p_ssize

プレイバックサンプルサイズ（バイト）

p_mute_present

プレイバックミュート制御の有効化

p_volume_present

再生音量制御の有効化

p_volume_min

再生音量制御の最小値（1/2,56 dB単位）

p_volume_max

再生音量制御の最大値（1/2,56 dB単位）

p_volume_res

再生音量制御の解像度（1/2,56 dB単位）

req_number

キャプチャおよび再生用の事前に割り当てられたリクエストの数

function_name

インターフェースの名前

これらの属性には合理的なデフォルト値が設定されています。
