マルチファンクションコンポジットギアド¶

概要¶

マルチファンクションコンポジットギア（またはg_multi）は、コンポジットフレームワークを幅広く利用して、マルチファンクションギアを提供するコンポジットギアです。

標準的な設定では、単一のUSB構成を提供し、RNDIS[1]（つまりイーサネット）、USB CDC[2] ACM（つまりシリアル）およびUSBメモリストレージ機能を備えています。

CDC ECM（イーサネット）機能はKconfigオプションを通じて有効化され、RNDISは無効化できます。両方を有効にすると、ギアは2つの構成を持つことになります——RNDISを含むものと、CDC ECMを含むものです[3]。

非標準の構成（つまりCDC ECMを有効化）を使用する場合、ベンダーおよび/または製品IDを変更する必要があります。

ホストドライバ¶

ギアを使用するには、ホスト側で動作させる必要があります。それがないと、ギアで何らかの成果を上げるのは不可能です。システムによって必要な作業は異なります。

Linuxホストドライバ¶

ギアは標準的なコンポジットフレームワークを使用し、Linuxホスト側で特別なドライバを必要としません。すべての機能は、それらに特化したドライバによって処理されます。

これは、RNDIS構成が最初の設定である二つの構成設定にも当てはまります。Linuxホストは、CDC ECMを含む第二の構成を使用し、Linuxではより良い動作を示すはずです。

Windowsホストドライバ¶

ギアがWindowsで動作するには、以下の2つの条件を満たす必要があります：

コンポジットギアとして検出¶

まず、WindowsはギアをUSBコンポジットギアとして検出する必要があります。これは独自の条件[4]があります。それらが満たされると、WindowsはUSBジェネリックパラントドライバ[5]でデバイスを処理し、各インターフェースに適したドライバをマッチングしようとします（詳しくは気にしなくてよいです）。

良いニュースは、ほとんどの条件について心配する必要がないことです！

心配すべきことは、ギアが単一の構成を持つ必要があることです。双方向のRNDISとCDC ECMギアは、適切なINFを作成しない限り動作しません。もちろん、それを作成して提出すれば良いです。

各機能にドライバをインストールする¶

もう一つ、難しいのは、Windowsが各機能にドライバをインストールするようにするということです。

メモリストレージの場合、WindowsがUSBメモリストレージクラスを実装するインターフェースと検出し、適切なドライバを選択します。

RNDISとCDC ACMの場合、状況は複雑です。

RNDIS¶

Windowsがギアの最初の機能にRNDISドライバを選択するには、[[file:linux.inf]] で提供されているファイルです。このドキュメントが提供する「ギガット」の最初のインターフェースに Windows の RNDIS ドライバーを「接続」します。

テスト中に RNDIS が最初のインターフェースでない場合、いくつかの問題[6]が発生しました。自作のギガットを開発している場合でなければ、気にする必要はありません。ただし、そのようなバグに注意してください。

CDC ACM¶

同様に、[[file:linux-cdc-acm.inf]] は CDC ACM 用に提供されています。

ギガットのカスタマイズ¶

g_multi ギガットをカスタマイズする予定がある場合は、機能を並び替えると各機能のインターフェース番号が変化します。その結果、提供されている INF ファイルはインターフェース番号がハードコードされているため動作しなくなるでしょう（ただし、それらを変更するのは難しくありません[7]）。

これにより、g_multi と提供されている機能を変更した後、ギガットのベンダーおよび/または製品 ID を変更する必要があります。これにより、他のカスタマイズされたギガットや元のギガットとの衝突を防ぎます。

この作業を省略すると、意図しない動作の原因を数時間悩んで調べるうちに Windows がドライバー情報をキャッシュしていることが判明し、頭がおかしくなる可能性があります（USB ポートを変更するなど試してみるのも有効ですし、USBDeview[8] を使って幻のデバイスを削除するのも試してみてください）。

INF ファイルのテスト¶

提供されている INF ファイルは Windows XP SP3、Windows Vista、Windows 7（すべて 32 ビット版）でテストされています。64 ビット版でも動作する可能性がありますが、Windows XP SP2 以前のバージョンでは動作しない可能性が高いです。

その他のシステム¶

現在、他のシステム用のドライバーはテストされていません。macOS は BSD をベースにしているため、BSD はオープンソースであることを考慮すると、おそらく（読み: 「どうなるかはわかりません」）デフォルトで動作するでしょう。

より特殊なシステムについては、ほとんど何も言えないです…

テストやドライバーの追加 あります 歓迎します!
