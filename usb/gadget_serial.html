前提条件¶

gadget serialドライバーのバージョンは2.4 Linuxカーネル用に利用可能ですが、このドキュメントは2.6 Linuxカーネルでv2.3以降のgadget serialドライバーを使用していることを前提としています。

このドキュメントはLinuxとWindowsに関する知識を持ち、Linuxカーネルの構成とビルド、標準ユーティリティの実行、minicomおよびHyperTerminalの使用、USBおよびシリアルデバイスの操作に精通していることを前提としています。また、Linux gadgetおよびUSBドライバーをモジュールとして構成していることも前提としています。

ドライバーのバージョン2.3以降では、主装置ノードとサブ装置ノードが静的に定義されなくなりました。Linuxベースのシステムでは/sysにsysfsをマウントし、mdev（Busybox内）またはudevを使用して、sysfsの/sys/class/ttyファイルに一致する/devノードを作成する必要があります。

概要¶

gadget serialドライバーはLinux USB gadgetドライバーであり、USBデバイス側のドライバーです。これはUSBデバイス側ハードウェアを持つLinuxシステムで動作します。たとえば、PDA、埋め込みLinuxシステム、またはUSB開発ボード搭載PCなどが該当します。

gadget serialドライバーは、ホストPC上に動作するCDC ACMドライバーまたは汎用USBシリアルドライバーとUSB経由で通信します。

 Host
 --------------------------------------
| Host-Side   CDC ACM       USB Host   |
| Operating |   or        | Controller |   USB
| System    | Generic USB | Driver     |--------
| (Linux or | Serial      | and        |        |
| Windows)    Driver        USB Stack  |        |
 --------------------------------------         |
                                                |
                                                |
                                                |
 Gadget                                         |
 --------------------------------------         |
| Gadget                   USB Periph. |        |
| Device-Side |  Gadget  | Controller  |        |
| Linux       |  Serial  | Driver      |--------
| Operating   |  Driver  | and         |
| System                   USB Stack   |
 --------------------------------------

デバイス側のLinuxシステムでは、gadget serialドライバーはシリアルデバイスとして見えます。

ホスト側のシステムでは、gadget serialデバイスはCDC ACM準拠のクラスデバイスまたは単純なベンダー固有デバイスとして見え、バULKインおよびバULKアウトエンドポイントを持つため、他のシリアルデバイスと同様に扱われます。

ホスト側ドライバーは、ACM準拠ドライバーまたは単純なバULKイン/アウトインターフェースを持つデバイスと通信できる任意のドライバーです。gadget serialはLinux ACMドライバー、Windows usbser.sys ACMドライバー、Linux USB汎用シリアルドライバーとテストされています。

gadget serialドライバーとホスト側ACMまたは汎用シリアルドライバーが動作している場合、ホストとgadget側システム間でシリアルケーブルを接続したように通信できるはずです。

Gadgetシリアルドライバーは、単純で信頼性のないデータ通信のみを提供します。フロー制御や通常のシリアルデバイスの多くの機能を処理するにはまだ対応していません。

Gadgetシリアルドライバーのインストール¶

Gadgetシリアルドライバーを使用するには、Linux gadget側のカーネルで「USB Gadgetサポート」の項目に「USB Gadgetのサポート」、「USBペリフェラルコントローラー」（例: net2280）、「シリアルGadgetドライバー」を有効にする必要があります。これらはすべて「USB Gadgetサポート」の下で設定できます。その後、カーネルまたはモジュールを再構築してインストールしてください。

次に、gadgetシリアルドライバーをロードする必要があります。相互運用性のために推奨されるACMデバイスとしてロードする場合は、以下を行ってください：

modprobe g_serial

ベンダー固有のバルクイン/アウトデバイスとしてロードする場合は、以下を行ってください：

modprobe g_serial use_acm=0

これにより、基盤となるgadgetペリフェラルコントローラードライバーも自動的にロードされます。gadget側のLinuxシステムを再起動するたびにこの手順を実行する必要があります。必要に応じて、起動スクリプトに追加することもできます。

システムはmdev（busyboxからのもの）またはudevを使用してデバイスノードを作成します。このgadgetドライバーが設定されると、/dev/ttyGS0ノードが表示されるはずです：

# ls -l /dev/ttyGS0 | cat
crw-rw----    1 root     root     253,   0 May  8 14:10 /dev/ttyGS0
#

主装置番号（上記例では253）はシステム固有です。/devノードを手動で作成する必要がある場合は、/sys/class/tty/ttyGS0/devファイルに記載されている正しい番号を使用してください。

このgadgetドライバーを早めにリンク（静的でも可）する場合、/etc/inittabにエントリを設定して「getty」を実行するようにするのもよいでしょう。/dev/ttyGSのラインは通常のシリアルポートと同様に動作するはずです。

gadgetシリアルがACMデバイスとしてロードされている場合、ホスト側ではWindowsまたはLinuxのACMドライバーを使用することを推奨します。gadgetシリアルがバルクイン/アウトデバイスとしてロードされている場合、ホスト側ではLinuxの汎用シリアルドライバーを使用することを推奨します。適切な手順に従ってホスト側ドライバーをインストールしてください。

Windowsホスト用ACMドライバーのインストール¶

Windows ACMドライバーを使用するには、「linux-cdc-acm.inf」ファイル（このドキュメントに同梱）が必要です。これはすべての最近のWindowsバージョンをサポートしています。

gadgetシリアルドライバーがロードされ、USBケーブルでWindowsホストにUSBデバイスが接続されると、Windowsはgadgetシリアルデバイスを認識し、ドライバーの取得を求めるはずです。Windowsに「linux-cdc-acm.inf」ファイルを含むフォルダからドライバーを検索するように指示してください。

たとえば、Windows XPでは、Gadgetシリアルデバイスが初めて挿すと、「Found New Hardware Wizard（新規ハードウェアの検出ウィザード）」が起動します。『リストからインストールするか特定の場所からインストールする（高度な設定）』を選択し、次の画面で『この場所を検索に含める』を選択して、「linux-cdc-acm.inf」ファイルを含むフォルダのパスを入力するか、ブラウジングしてフォルダを選択します。WindowsはGadgetシリアルドライバーがWindowsロゴテストを通過していないと警告しますが、「無理に続行」を選択してドライバーのインストールを完了してください。

Windows XPでは、「デバイスマネージャー」（「コントロールパネル」→「システム」→「ハードウェア」）で「Ports (COM & LPT)」項目を展開し、「Gadget Serial」がCOMポートの一つに割り当てられていることを確認してください。

「Gadget Serial」ドライバーのWindows XP用ドライバーをアンインストールするには、「デバイスマネージャー」内の「Gadget Serial」項目を右クリックし、「アンインストール」を選択してください。

Linuxホスト用ACMドライバーのインストール¶

Linux ACMドライバーを使用するには、Linuxホスト側のカーネルに「ホスト側USBのサポート」および「USBモデム（CDC ACM）のサポート」を有効にする必要があります。

Gadgetシリアルドライバーがロードされ、USBケーブルでLinuxホストに接続されたら、ホストシステムはGadgetシリアルデバイスを認識するはずです。たとえば、コマンド：

cat /sys/kernel/debug/usb/devices

は以下のような表示がされるはずです::

T:  Bus=01 Lev=01 Prnt=01 Port=01 Cnt=02 Dev#=  5 Spd=480 MxCh= 0
D:  Ver= 2.00 Cls=02(comm.) Sub=00 Prot=00 MxPS=64 #Cfgs=  1
P:  Vendor=0525 ProdID=a4a7 Rev= 2.01
S:  Manufacturer=Linux 2.6.8.1 with net2280
S:  Product=Gadget Serial
S:  SerialNumber=0
C:* #Ifs= 2 Cfg#= 2 Atr=c0 MxPwr=  2mA
I:  If#= 0 Alt= 0 #EPs= 1 Cls=02(comm.) Sub=02 Prot=01 Driver=acm
E:  Ad=83(I) Atr=03(Int.) MxPS=   8 Ivl=32ms
I:  If#= 1 Alt= 0 #EPs= 2 Cls=0a(data ) Sub=00 Prot=00 Driver=acm
E:  Ad=81(I) Atr=02(Bulk) MxPS= 512 Ivl=0ms
E:  Ad=02(O) Atr=02(Bulk) MxPS= 512 Ivl=0ms

ホスト側のLinuxシステムが正しく設定されている場合、ACMドライバーは自動的にロードされます。「lsmod」コマンドで「acm」モジュールがロードされていることを確認してください。

Linuxホスト用汎用USBシリアルドライバーのインストール¶

Linux汎用USBシリアルドライバーを使用するには、Linuxホスト側のカーネルに「ホスト側USBのサポート」、「USBシリアルコンバーターのサポート」、および「USB汎用シリアルドライバー」を有効にする必要があります。

Gadgetシリアルドライバーがロードされ、USBケーブルでLinuxホストに接続されたら、ホストシステムはGadgetシリアルデバイスを認識するはずです。たとえば、コマンド：

cat /sys/kernel/debug/usb/devices

は以下のような表示がされるはずです::

T:  Bus=01 Lev=01 Prnt=01 Port=01 Cnt=02 Dev#=  6 Spd=480 MxCh= 0
D:  Ver= 2.00 Cls=ff(vend.) Sub=00 Prot=00 MxPS=64 #Cfgs=  1
P:  Vendor=0525 ProdID=a4a6 Rev= 2.01
S:  Manufacturer=Linux 2.6.8.1 with net2280
S:  Product=Gadget Serial
S:  SerialNumber=0
C:* #Ifs= 1 Cfg#= 1 Atr=c0 MxPwr=  2mA
I:  If#= 0 Alt= 0 #EPs= 2 Cls=0a(data ) Sub=00 Prot=00 Driver=serial
E:  Ad=81(I) Atr=02(Bulk) MxPS= 512 Ivl=0ms
E:  Ad=02(O) Atr=02(Bulk) MxPS= 512 Ivl=0ms

usbserialドライバーをロードし、明示的にパラメータを設定してGadgetシリアルデバイスを認識するように構成する必要があります。以下のようにします：

echo 0x0525 0xA4A6 >/sys/bus/usb-serial/drivers/generic/new_id

伝統的な方法はモジュールパラメータを使用することです：

modprobe usbserial vendor=0x0525 product=0xA4A6

すべてが正常に動作している場合、usbserialはシステムログに「Gadget SerialコンバーターがttyUSB0に接続されました」というメッセージを出力します。

MinicomまたはHyperTerminalでのテスト¶

Gadgetシリアルドライバーとホストドライバーがどちらもインストールされ、USBケーブルでGadgetデバイスとホストが接続されると、Gadgetとホストシステム間でUSB経由での通信が可能になります。MinicomまたはHyperTerminalを使用してこのテストを行ってください。

デバイス側では「minicom -s」を実行して新しいminicomセッションを設定します。『シリアルポート設定』で「/dev/ttygserial」を「シリアルデバイス」に設定します。ボーレート、データビット、パリティ、ストップビットをそれぞれ9600、8、none、1に設定します（これらの設定は基本的に問題ありません）。『モデムとダイヤル設定』ではすべてのモデムおよびダイヤル文字列を削除してください。

ACMドライバを実行しているLinuxホストでは、minicomを同様に設定しますが、「シリアルデバイス」に「/dev/ttyACM0」を使用します。（他のACMデバイスを接続している場合は、デバイス名を適切に変更してください。）

USB汎用シリアルドライバを実行しているLinuxホストでは、minicomを同様に設定しますが、「シリアルデバイス」に「/dev/ttyUSB0」を使用します。（他のUSBシリアルデバイスを接続している場合は、デバイス名を適切に変更してください。）

Windowsホストでは、Gadgetシリアルに割り当てられたCOMポートを使用する新しいHyperTerminalセッションを設定します。HyperTerminalがGadgetシリアルデバイスに接続する際、ポート設定は自動的に設定されるため、デフォルト値を維持しておきましょう（これらの設定は基本的に問題ありません）。

デバイス側でminicomが設定・動作しており、ホスト側でminicomまたはHyperTerminalが設定・動作している場合、デバイス側とホスト側のシステム間でデータをやり取りできるようになります。デバイス側のターミナルウィンドウで入力した内容はホスト側のターミナルウィンドウに表示され、逆も同様です。
