PMBus コアドライバーおよび内部API¶

はじめに¶

[pmbus.orgから] パワー管理バス（PMBus）は、電源コンバーターおよび電源システム内の他のデバイスと通信を容易にする完全に定義されたコマンド言語を備えたオープンスタンダードの電源管理プロトコルです。このプロトコルは産業標準のSMBusシリアルインターフェース上で実装され、コンプライアンスを持つ電源変換製品のプログラミング、制御、リアルタイムモニタリングを可能にします。この柔軟で高機能な標準により、アナログおよびデジタル技術に基づくデバイス間の通信が可能となり、真の相互運用性が実現され、電源システム設計者にとって設計複雑性が低減され、市場投入までの期間が短縮されます。このオープンな電源システム標準は、リーディングな電源供給および半導体企業が先導し、PMBus Implementers Forum（PMBus-IF）によって維持・推進されており、30以上の導入企業が参加しています。

残念ながら、PMBusコマンドは標準化されていますが、必須のコマンドは存在せず、メーカーは好きなだけ非標準コマンドを追加できます。また、非サポートコマンドが実行された場合、PMBusデバイスの動作はメーカーによって異なります。一部のデバイスはエラーを返し、一部は0xffまたは0xffffを返してステータスエラーフラグを設定し、一部は単にハングアップする場合もあります。

これらの困難にもかかわらず、ジェネリックなPMBusデバイスドライバは依然として有用であり、カーネルバージョン2.6.39からサポートされています。しかし、コアPMBusドライバに加えてデバイス固有の拡張機能をサポートする必要があり、次に登場する新しいデバイス固有機能が予測不可能なためです。

デバイス固有拡張機能を最大限にスケーラブルにするため、また新しいデバイスに対応するたびにコアPMBusドライバを繰り返し変更する必要を避けるため、PMBusドライバはコア、ジェネリック、デバイス固有のコードに分離されました。コアコード（pmbus_core.c）はジェネリックな機能を提供し、ジェネリックコード（pmbus.c）はジェネリックなPMBusデバイスのサポートを行います。デバイス固有コードはデバイス固有の初期化を担当し、必要に応じてデバイス固有機能をジェネリック機能にマッピングします。これはある程度、PCIコードと比較可能で、ジェネリックコードにデバイス種類ごとのキュークスを追加して拡張する仕組みに似ています。

PMBusデバイスの機能自動検出¶

汎用のPMBusデバイスの場合、pmbus.c内のコードはサポートされているすべてのPMBusコマンドを自動検出しようとしています。ただし、自動検出は制限があり、考慮すべき変数が非常に多いからです。たとえば、PMBusコマンドがページングされるものか、すべてのページで複製されるものかを自動検出するのはほぼ不可能です（詳細はPMBus仕様書を参照してください）。

そのため、すべてのコマンドが自動検出できない場合、デバイス固有のドライバーを提供することが多くの場合意味があります。このドライバー内のデータ構造は、コアドライバーに個々のチップがサポートする機能を通知するために使用できます。

一部のコマンドは常に自動検出されます。これはすべての制限コマンド（lcrit、min、max、crit属性）および関連するアラーム属性にも適用されます。制限およびアラーム属性は自動検出されるのは、提供可能な組み合わせが極めて多く、手動で設定するインターフェースを提供するのが現実的でないためです。

PMBus内部API¶

コアとデバイス固有のPMBusコード間のAPIはdrivers/hwmon/pmbus/pmbus.hに定義されています。この内部APIに加えて、pmbus.hは標準PMBusコマンドと仮想PMBusコマンドを定義しています。

標準PMBusコマンド¶

標準PMBusコマンド（コマンド値0x00から0xff）はPMBus仕様書に記載されています。

仮想PMBusコマンド¶

仮想PMBusコマンドは、複数のチップベンダーが実装した非標準機能をサポートするために提供されます。これにより、サポートが望ましい機能を提供できます。

仮想PMBusコマンドはコマンド値0x100から始まり、標準PMBusコマンド（0xff以下の値のみ）と区別しやすくなっています。仮想PMBusコマンドのサポートはデバイス固有であり、デバイス固有のコードで実装する必要があります。

仮想コマンドはPMBUS_VIRT_xxxと名付けられ、PMBUS_VIRT_BASEから始まります。すべての仮想コマンドはワードサイズです。

現在、仮想コマンドには2つの種類があります。

  • READコマンドは読み取り専用であり、書き込みは無視されるかエラーを返します。

  • RESETコマンドは読み書き可能です。リセットレジスタを読み取るとゼロが返され（検出用）、任意の値を書き込むと関連する履歴がリセットされます。

仮想コマンドはデバイス固有のドライバコードで処理する必要があります。チップドライバコードは、仮想コマンドがサポートされている場合に非負の値を返し、サポートされていない場合は負のエラーコードを返します。この場合、チップドライバは-ENODATAや他のLinuxエラーコードを返すことができますが、-ENODATA以外のエラーコードはより効率的に処理されるため、推奨されます。いずれの場合も、呼び出し元のPMBusコアコードは、仮想レジスタの読み書き時にチップドライバがエラーコードを返した場合、処理を中止します（つまり、PMBusコアコードはチップに仮想コマンドを送信しません）。

PMBusドライバ情報¶

PMBusドライバ情報（struct pmbus_driver_infoで定義）は、デバイス固有のドライバがコアPMBusドライバに情報を渡す主な手段です。具体的には、以下の情報を提供します。

  • Direct Data Formatでデータをサポートするデバイスには、レジスタ値を正規化データに変換するための係数を提供します。このデータは通常、チップメーカーがデバイスデータシートで提供します。

  • サポートされているチップ機能をコアドライバに提供できます。これは、非サポートコマンドが実行されると動作が不安定なチップや、デバイスの検出・初期化を高速化する場合に必要です。

  • 汎用コマンド実行をオーバーライドおよび拡張するための複数の関数エントリポイントが提供されています。この機能は、非標準のPMBusコマンドを標準コマンドにマッピングするか、標準コマンドの返却値にデバイス固有情報を追加するために使用できます。

API関数¶

チップドライバが提供する関数¶

すべての関数は成功時にコマンドの返却値（読み込み）またはゼロ（書き込み）を返します。-ENODATAの返却値は、メーカー固有のコマンドが存在しないが、標準PMBusコマンドが存在する場合を示します。他の負の返却値は、このチップではコマンドが存在しないことを示し、標準コマンドの読み書きを試行すべきではありません。

上記のように、仮想コマンドについてはこのルールの例外があります。 grace periodsを尊重しなければなりませんし、 ドライバ固有のコードで処理します。詳細は上記の「仮想PMBusコマンド」を参照してください。

コアPMBusドライバコードでのコマンド実行は以下の通りです：

if (chip_access_function) {
        status = chip_access_function();
        if (status != -ENODATA)
                return status;
}
if (command >= PMBUS_VIRT_BASE) /* For word commands/registers only */
        return -EINVAL;
return generic_access();

チップドライバはstruct pmbus_driver_infoに以下の関数へのポインタを提供できます。すべての関数はオプションです。

int (*read_byte_data)(struct i2c_client *client, int page, int reg);

ページ<page>、レジスタ<reg>からバイトを読み込む。<page>は-1を指定すると「現在のページ」を意味します。

int (*read_word_data)(struct i2c_client *client, int page, int phase,
                      int reg);

ページ <page>、フェーズ <phase>、レジスタ <reg> からワードを読み取る。チップが複数フェーズをサポートしない場合、フェーズパラメータは無視される。チップが複数フェーズをサポートする場合、フェーズ値 0xff はすべてのフェーズを指定する。

int (*write_word_data)(struct i2c_client *client, int page, int reg,
                       u16 word);

ページ <page>、レジスタ <reg> にワードを書き込む。

int (*write_byte)(struct i2c_client *client, int page, u8 value);

ページ <page>、レジスタ <reg> にバイトを書き込む。<page> が -1 の場合、「現在のページ」を意味する。

int (*identify)(struct i2c_client *client, struct pmbus_driver_info *info);

サポートされているPMBus機能を判定する。この関数は、チップドライバが複数チップをサポートし、チップ機能が事前に決まっていない場合にのみ必要となる。現在はジェネリックなpmbusドライバ（pmbus.c）でのみ使用されている。

コアドライバがエクスポートする関数¶

チップドライバは、PMBusレジスタを読み書きする際には以下の関数を使用することが期待される。チップドライバは直接I2Cコマンドを使用することも可能である。直接I2Cコマンドを使用する場合、チップドライバコードは現在のページを直接変更してはならない。選択されたページはコアドライバでキャッシュされており、コアドライバはそれが選択されていると仮定するためである。新しいページを選択するにはpmbus_set_page()を使用することが必須である。

int pmbus_set_page(struct i2c_client *client, u8 page, u8 phase);

次のコマンドのためにPMBusページレジスタを <page> および <phase> に設定する。チップが複数フェーズをサポートしない場合、フェーズパラメータは無視される。サポートする場合、フェーズ値 0xff はすべてのフェーズを指定する。

int pmbus_read_word_data(struct i2c_client *client, u8 page, u8 phase,
                         u8 reg);

<page>、<phase>、<reg> からワードデータを読み取る。これは i2c_smbus_read_word_data()と同様だが、まずページとフェーズを選択する。チップが複数フェーズをサポートしない場合、フェーズパラメータは無視される。サポートする場合、フェーズ値 0xff はすべてのフェーズを指定する。

int pmbus_write_word_data(struct i2c_client *client, u8 page, u8 reg,
                          u16 word);

<page>、<reg> にワードデータを書き込む。これは i2c_smbus_write_word_data()と同様だが、まずページを選択する。

int pmbus_read_byte_data(struct i2c_client *client, int page, u8 reg);

<page>、<reg> からバイトデータを読み取る。これは i2c_smbus_read_byte_data()と同様だが、まずページを選択する。<page> が -1 の場合、「現在のページ」を意味する。

int pmbus_write_byte(struct i2c_client *client, int page, u8 value);

<page>、<reg> にバイトデータを書き込む。これは i2c_smbus_write_byte()と同様だが、まずページを選択する。<page> が -1 の場合、「現在のページ」を意味する。

void pmbus_clear_faults(struct i2c_client *client);

すべてのチップページでPMBusの「故障クリア」コマンドを実行する。この関数はデバイス固有のwrite_byte関数が定義されている場合にその関数を呼び出すため、この関数はその関数から呼び出してはならない。

bool pmbus_check_byte_register(struct i2c_client *client, int page, int reg);

バイトレジスタが存在するか確認する。レジスタが存在する場合はtrueを返し、それ以外はfalseを返す。この関数はデバイス固有のwrite_byte関数が定義されている場合にチップステータスを取得するためにその関数を呼び出すため、この関数はその関数から呼び出してはならない。

bool pmbus_check_word_register(struct i2c_client *client, int page, int reg);

ワードレジスタが存在するか確認する。レジスタが存在する場合はtrueを返し、それ以外はfalseを返す。この関数はデバイス固有のwrite_byte関数が定義されている場合にチップステータスを取得するためにその関数を呼び出すため、この関数はその関数から呼び出してはならない。

int pmbus_do_probe(struct i2c_client *client, struct pmbus_driver_info *info);

プローブ関数を実行します。他のドライバの標準的なプローブ関数と同様ですが、struct pmbus_driver_infoへのポインタを追加の引数として受け取ります。サポートされている場合はidentify関数を呼び出します。デバイスプローブ関数からのみ呼び出す必要があります。

void pmbus_do_remove(struct i2c_client *client);

ドライバ削除関数を実行します。標準のドライバ削除関数と同様です。

const struct pmbus_driver_info
      *pmbus_get_driver_info(struct i2c_client *client);

pmbus_do_probe()に渡されたstruct pmbus_driver_infoへのポインタを返します。

PMBusドライバプラットフォームデータ¶

PMBusプラットフォームデータはinclude/linux/pmbus.hで定義されています。プラットフォームデータは現在、1ビットのフラグフィールドのみを提供しています:

#define PMBUS_SKIP_STATUS_CHECK (1 << 0)

struct pmbus_platform_data {
        u32 flags;              /* Device specific flags */
};

フラグ¶

PMBUS_SKIP_STATUS_CHECK

レジスタ検出中に、通信またはコマンドエラーのステータスレジスタの確認をスキップします。

一部のPMBusチップは、サポートされていないレジスタを読み込む際に有効なデータを返します。このようなチップでは、チップレジスタが存在するかどうかを判定する際にステータスレジスタの確認は必須です。一方で、他のPMBusチップはSTATUS_CMLレジスタをサポートしていない、または理由のない通信エラーを報告する場合があります。このようなチップでは、ステータスレジスタの確認を無効にする必要があります。

一部のI2Cコントローラーは、単一バイトコマンド（データのない書き込みコマンド、 i2c_smbus_write_byte())をサポートしていません。このようなコントローラーでは、ステータスレジスタのクリアが不可能であり、PMBUS_SKIP_STATUS_CHECKフラグを設定する必要があります。
