モジュールパラメータ¶

  • init int

    (default 1)

    Use ‘init=0’ to bypass initializing the chip. Try this if your computer crashes when you load the module.

  • reset int

    (default 0) The driver used to reset the chip on load, but does no more. Use ‘reset=1’ to restore the old behavior. Report if you need to do this.

force_subclients=bus,caddr,saddr,saddr

This is used to force the i2c addresses for subclients of a certain chip. Typical usage is force_subclients=0,0x2d,0x4a,0x4b to force the subclients of chip 0x2d on bus 0 to i2c addresses 0x4a and 0x4b. This parameter is useful for certain Tyan boards.

説明¶

This driver implements support for the Winbond W83781D, W83782D, W83783S chips, and the Asus AS99127F chips. We will refer to them collectively as W8378* chips.

There is quite some difference between these chips, but they are similar enough that it was sensible to put them together in one driver. The Asus chips are similar to an I2C-only W83782D.

Detection of these chips can sometimes be foiled because they can be in an internal state that allows no clean access. If you know the address of the chip, use a ‘force’ parameter; this will put them into a more well-behaved state first.

The W8378* implements temperature sensors (three on the W83781D and W83782D, two on the W83783S), three fan rotation speed sensors, voltage sensors (seven on the W83781D, nine on the W83782D and six on the W83783S), VID lines, alarms with beep warnings, and some miscellaneous stuff.

Temperatures are measured in degrees Celsius. There is always one main temperature sensor, and one (W83783S) or two (W83781D and W83782D) other sensors. An alarm is triggered for the main sensor once when the Overtemperature Shutdown limit is crossed; it is triggered again as soon as it drops below the Hysteresis value. A more useful behavior can be found by setting the Hysteresis value to +127 degrees Celsius; in this case, alarms are issued during all the time when the actual temperature is above the Overtemperature Shutdown value. The driver sets the hysteresis value for temp1 to 127 at initialization.

他の温度センサー（複数ある場合も）では、温度がOvertemperature Shutdown値を超えたときにアラームが発生します。温度がHysteresis値を下回るまでアラームは継続します。しかしW83781Dでは、他のセンサー双方に機能するアラームは1つだけです！温度は-55度から+125度の範囲で保証されています。主な温度センサーは1度の分解能を持ち、他のセンサー（複数ある場合も）は0.5度の分解能を持ちます。

ファンの回転速度はRPM（分あたりの回転数）で報告されます。回転速度がプログラマブルな限界値を下回ったときにアラームが発生します。ファンの読み取り値はプログラマブルなディバイダー（W83781Dでは1、2、4、8；他の機種では1、2、4、8、16、32、64、128）で割ることで、読み取り値の範囲や精度を向上させることができます。すべてのRPM値を正確に表現することはできませんので、一部の四捨五入が行われます。ディバイダーが2の場合、最低表現可能な値は約2600 RPMです。

電圧センサー（INセンサーとも呼ばれる）はボルト単位で値を報告します。電圧がプログラマブルな最小または最大限界を越えた場合にアラームがトリガーされます。注意点として、ここでの「最小」は常に「ゼロに近い」ことを意味します。これは負の電圧測定において重要です。すべての電圧入力は0〜4.08ボルトの範囲で測定でき、0.016ボルトの分解能を持ちます。

VIDラインはコア電圧値をエンコードします：プロセッサが動作するための電圧レベルです。これはマザーボードおよび/またはプロセッサ自体によってハードコードされています。これはボルト単位の値です。接続されていない場合、ここに3.50 Vが表示されることが一般的です。

W83782DおよびW83783Sの温度変換機は、いくつかの温度プローブについて理解しています。センサーのファイルでいわゆるベータ値をプログラミングできます。'1'はPII/Celeronダイオード、'2'はTN3904トランジスタ、'3435'はデフォルトのサーミスタ値です。他の値は（まだ）サポートされていません。

上記のアラームに加えて、チップにはケースが開いているときにアラームをトリガーするCHASアラームがあります。

アラームが鳴るとき、コンピュータスピーカーを通じて蜂鳴信号で警告されます。すべての蜂鳴をグローバルに有効にするか、一部のアラームのみの蜂鳴を有効にすることができます。

アラームがトリガーされた場合、ハードウェアレジスタが少なくとも1回読み込まれるまでアラームは継続します。これはアラームの原因がすでに消えている可能性があることを意味します！注意点として、現在の実装では、データが読み込まれたたびにすべてのハードウェアレジスタが読み込まれます（最後の更新から1.5秒以上経過していない場合を除く）。これにより、一度しか発生しないアラームを簡単に見逃す可能性があります。

チップは1.5秒ごとに値を更新します。読み取りをより頻繁に行うことは害にはなりませんが、古い値を返すだけです。

AS99127Fの問題¶

AS99127Fのサポートはデータシートなしで開発されました。ほとんどの場合、w83781dとして扱われますが（AS99127Fのリビジョン2はw83782dに似ています）。このサポートはデータシートが公開されるまでベータ版として扱われます。1人のユーザーはファンが時折停止する問題を報告しています。

個別蜂鳴ビットは他のチップとは逆の論理で動作します。ドライバーがこれを処理するため、ユーザー空間アプリケーションはこれを気にする必要がありません。

既知の問題:

  • ダイオード/サーミスタ設定の問題（サポートされていますか？）

  • 1人のユーザーは高負荷のサーバー環境でファンが停止する問題を報告しています。

  • リビジョン2は2つのPWMレジスタを持つように見えますが、どのように処理するかはわかりません。詳細は下記の通りです。

datasheetを入手しない限り修正されません。問題がある場合はAsusに働きかけてdatasheetの公開を求めてください。残念ながら他の人も同様の試みをしたが成功しませんでした。AsusのAS99127Fに関するサポートを求めるメールはお控えください。datasheetがなければ私たちは最大限の努力をしたつもりです。datasheetやAsusに働きかけることに関する問い合わせはお控えください。私たちはお手伝いできません。

ノート¶

783sはin1を持たないため、in[2-6]は781d/782dと互換性があります。

783sのピンは-5Vまたはtemp1のいずれかに設定可能で、デフォルトでは-5Vです。ドライバでは制御が行われないためtemp1は動作しません。

782dと783sのdatasheetではpwm1とpwm2の対応が異なります。私たちは782dを採用しました。

782dと783sのピンはファン3入力またはpwm2出力に設定可能で、デフォルトではファン3入力です。pwm2が有効化されている場合（echo 255 1 > pwm2で有効化）、ファン3は0を報告します。

782dはISA用にpwm1-2、i2c用にpwm1-4を持ちます。（pwm3-4はISAピンとピンを共有しています）

Asusのクローン¶

Asusクローン（AS99127FおよびASB100 Bach）のdatasheetは入手していません。Alex Van Kaam氏からこれらのチップの検出方法や値の読み取り方法について非常に有用な情報を得ました。また、別のAsusチップセットであるMozart-2（現在はサポートしていません）に関するアドバイスも提供しています。Alex氏、ありがとうございます！

一部の部分を再構成し、個人的なコメントを追加しました。

検出¶

AS99127F rev.1、AS99127F rev.2およびASB100: - I2Cアドレス範囲: 0x29 - 0x2F - レジスタ0x58が0x31を保持している場合、Asus（ASB100またはAS99127F）であると判断できます。どちらかはレジスタ0x4F（メーカーID）によって決まります：

  • 0x06または0x94: ASB100

  • 0x12または0xC3: AS99127F rev.1

  • 0x5Cまたは0xA3: AS99127F rev.2

0x5CA3はWinbondのID（WEC）であり、AsusがAS99127F rev.2をWinbondから直接取得している可能性を示唆しています。他のコードはATTとDVCをそれぞれ意味します。ATTはAsustekの何かを表している可能性があります（ただし私見では非常に不適切です）、DVCの意味は不明です。これらのコードはこのように解釈する意図がないかもしれません。

Mozart-2: - I2Cアドレス: 0x77 - レジスタ0x58が0x56または0x10を保持している場合、Mozart-2であると判断できます。Mozartには3つのタイプがあります：

  • 0x58=0x56、0x4E=0x94、0x4F=0x36: Asus ASM58 Mozart-2

  • 0x58=0x56、0x4E=0x94、0x4F=0x06: Asus AS2K129R Mozart-2

  • 0x58=0x10、0x4E=0x5C、0x4F=0xA3: Asus ??? Mozart-2

これら3つのタイプはすべて同じ方法で処理できます :)

PWM¶

  • AS99127FのPWMに関する追加情報（他のASUSチップにも適用される可能性あり）Jean Delvareによる、2004年4月9日時点での情報:

AS99127F rev.2はレジスタ0x59と0x5AにPWMレジスタを持ち、温度センサータイプセレクターは0x5Bにあります（これはWinbondチップと比較してレジスタ0x59と0x5Bを交換しているため）。rev.1のチップでも温度センサータイプセレクターは0x5Bにありますが、PWMレジスタは効果を持たないようです。

温度センサータイプ選択の仕組みは正確にはわかりません。ビット1-0がtemp1、ビット3-2がtemp2、ビット5-4がtemp3に対応している可能性がありますが、各々で最上位ビットのみが重要である可能性もあります。これまでのところ、0以外の値は読み取りを破壊するようです。

PWMレジスタは2つの部分に分かれているようです。ビット7はモードセレクターで、他のビットは値やしきい値を定義していると考えられます。

ビット7がクリアされている場合、ビット6-0はしきい値として扱われます。値が指定された限界値よりも低い場合、ファンは低速で動作し、値が限界値を上回る場合、ファンはフルスピードで動作します。限界値が何を表しているかは不明です。また、このモードではインラジオの影響がある可能性があり、速度変更には時間がかかるかもしれません。さらに、ヒステリシスメカニズムが疑われており、しきい値を増減して確認した結果、わずかに異なる限界値が得られました。

ビット7が設定されている場合、ビット3-0はしきい値を保持しているように見え、ビット6-4は重要ではないと考えられます。値が指定された限界値以下であればファンはフルスピードで動作し、限界値以上であれば低速で動作します（これは他のモードとは逆の動作になります）。ここでもまた、限界値が何を表しているのかは不明です。

注目すべき点は、ファンが持つ速度が通常のPWMで見られる連続的な範囲ではなく、2〜3つの異なる速度（過渡状態を除く）しかないことです。

結論として、PWMレジスタに0x00または0x8Fを書き込むことでファンを低速で動作させ、0x7Fまたは0x80を書き込むことでフルスピードで動作させることができます。

動作仕様が分かればご連絡ください。現時点では不明な点が多いため、w83781dドライバーはAS99127FチップのPWMをまったく処理していません。
