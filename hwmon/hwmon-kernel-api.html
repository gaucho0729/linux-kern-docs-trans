Linux ハードウェアモニタリングカーネルAPI¶

Guenter Roeck

はじめに¶

このドキュメントは、ハードウェアモニタリングフレームワークを使用したいハードウェアモニタリングドライバが使用できるAPIについて説明しています。

このドキュメントではハードウェアモニタリング（hwmon）ドライバまたはデバイスの定義は説明していません。また、ユーザー空間がハードウェアモニタリングデバイスと通信するためのAPIについても説明していません。この情報が必要であれば、以下のファイルを参照してください： sysfsファイルの命名規則とデータフォーマット標準.

hwmonドライバの作成・改善に関する追加ガイドラインについては、以下のファイルも参照してください Hwmon サブシステムにパッチを採用してもらう方法.

API¶

各ハードウェアモニタリングドライバは #include <linux/hwmon.h> を実施し、ほとんどの場合 <linux/hwmon-sysfs.h> も含める必要があります。linux/hwmon.h は以下の登録/解除関数を宣言しています：

struct device *
hwmon_device_register_with_groups(struct device *dev, const char *name,
                                  void *drvdata,
                                  const struct attribute_group **groups);

struct device *
devm_hwmon_device_register_with_groups(struct device *dev,
                                       const char *name, void *drvdata,
                                       const struct attribute_group **groups);

struct device *
hwmon_device_register_with_info(struct device *dev,
                                const char *name, void *drvdata,
                                const struct hwmon_chip_info *info,
                                const struct attribute_group **extra_groups);

struct device *
devm_hwmon_device_register_with_info(struct device *dev,
                                     const char *name,
                                     void *drvdata,
                                     const struct hwmon_chip_info *info,
                                     const struct attribute_group **extra_groups);

void hwmon_device_unregister(struct device *dev);

void devm_hwmon_device_unregister(struct device *dev);

hwmon_device_register_with_groups はハードウェアモニタリングデバイスを登録します。この関数の最初のパラメータは親デバイスへのポインタです。name パラメータはhwmonデバイス名へのポインタです。登録関数はこのnameを指すsysfs属性を作成します。drvdata パラメータはローカルドライバデータへのポインタです。hwmon_device_register_with_groups はこのポインタを新たに割り当てたhwmonデバイスにアタッチします。ドライバはhwmonデバイスポインタに対して dev_get_drvdata() を使用してこのポインタを取得できます。groups パラメータはsysfs属性グループのリストへのポインタです。リストはNULL終端する必要があります。hwmon_device_register_with_groups はname属性とともに、hwmonデバイスにアタッチされるすべてのsysfs属性を含むhwmonデバイスを作成します。この関数は新たに作成されたハードウェアモニタリングデバイスへのポインタを返します。失敗時はPTR_ERRを返します。

devm_hwmon_device_register_with_groups はhwmon_device_register_with_groupsと似ています。ただし、デバイス管理されたものであり、削除関数で明示的にhwmonデバイスを削除する必要がありません。

hwmon_device_register_with_info はハードウェアモニタリングデバイスを登録するための最も包括的で推奨される方法です。この関数はハードウェアモニタリングコアに標準のsysfs属性を作成し、ドライバはチップの読み取り・書き込みに集中できるようになります。親デバイスパラメータは非NULLチップ情報を持つ場合にNULLにはできません。パラメータの詳細については下記で説明します。

devm_hwmon_device_register_with_info はhwmon_device_register_with_infoと似ています。ただし、デバイス管理されたものであり、削除関数で明示的にhwmonデバイスを削除する必要がありません。

hwmon_device_unregisterは、登録済みのハードウェアモニタリングデバイスの登録を解除します。この関数のパラメータは、登録済みハードウェアモニタリングデバイス構造体へのポインタです。ハードウェアモニタリングデバイスがhwmon_device_register_with_groupsまたはhwmon_device_register_with_infoで登録された場合、ドライバのremove関数からこの関数を呼び出す必要があります。

devm_hwmon_device_unregisterは通常呼び出す必要はありません。エラー処理のためのみ必要であり、devm_hwmon_device_register_with_groupsまたはhwmon_device_register_with_infoの呼び出し後にドライバのprobeが失敗した場合にのみ必要です。この場合、自動的な（デバイス管理された）削除が遅すぎる可能性があるためです。

すべてのサポートされているhwmonデバイス登録関数は、有効なデバイス名のみを受け入れます。無効な文字（空白、'*'、'-'）を含むデバイス名は拒否されます。'name'パラメータは必須です。

devm_hwmon_device_register_with_info()の使用¶

hwmon_device_register_with_info()はハードウェアモニタリングデバイスを登録します。この関数のパラメータは

struct device *dev

親デバイスへのポインタ

const char *name

デバイス名

void *drvdata

ドライバプライベートデータ

const struct hwmon_chip_info *info

チップ説明へのポインタ。

const struct attribute_group **extra_groups

追加の非標準sysfs属性グループのヌル終端リスト。

この関数は成功時に作成されたハードウェアモニタリングデバイスへのポインタを返し、失敗時には負のエラーコードを返します。

hwmon_chip_info構造体は以下のようになります：

struct hwmon_chip_info {
        const struct hwmon_ops *ops;
        const struct hwmon_channel_info **info;
};

これは以下のフィールドを含みます：

  • ops:

    デバイス操作へのポインタ。

  • info:

    NULL終端のデバイスチャネル記述子リスト。

hwmon操作のリストは以下のようになります：

struct hwmon_ops {
      umode_t (*is_visible)(const void *, enum hwmon_sensor_types type,
                            u32 attr, int);
      int (*read)(struct device *, enum hwmon_sensor_types type,
                  u32 attr, int, long *);
      int (*write)(struct device *, enum hwmon_sensor_types type,
                   u32 attr, int, long);
};

これは以下の操作を定義します。

  • is_visible:

    サポートされている属性ごとのファイルモードを返す関数へのポインタ。この関数は必須です。

  • read:

    チップから値を読み取る関数へのポインタ。この関数はオプションですが、読み取り可能な属性が存在する場合は必須です。

  • write:

    チップに値を書き込む関数へのポインタ。この関数はオプションですが、書き込み可能な属性が存在する場合は必須です。

各センサーチャネルはstruct hwmon_channel_infoで記述され、以下のように定義されます：

struct hwmon_channel_info {
        enum hwmon_sensor_types type;
        u32 *config;
};

これは以下のフィールドを含みます：

  • type:

    ハードウェアモニタリングセンサーのタイプ。

    サポートされているセンサータイプは

    hwmon_chip

    仮想センサータイプで、特定の入力または出力に束縛されない属性を記述するために使用されます

    hwmon_temp

    温度センサー

    hwmon_in

    電圧センサー

    hwmon_curr

    電流センサー

    hwmon_power

    電力センサー

    hwmon_energy

    エネルギーセンサー

    hwmon_humidity

    湿度センサー

    hwmon_fan

    ファン速度センサー

    hwmon_pwm

    PWM制御
  • config:

    指定されたセンサー種別の各センサー用の構成値を0で終端するリストへのポインタ。各値は、単一のセンサーが持つ属性を記述するビット値の組み合わせです。

例として、LM75互換センサチップの完全な説明ファイルを以下に示します。このチップは単一の温度センサーを持ち、ドライバは熱制御サブシステム（HWMON_C_REGISTER_TZ）に登録したいと考えています。また、update_interval属性（HWMON_C_UPDATE_INTERVAL）をサポートしています。チップは温度の読み取り（HWMON_T_INPUT）をサポートし、最大温度レジスタ（HWMON_T_MAX）および最大温度ヒステリシスレジスタ（HWMON_T_MAX_HYST）も持っています：

static const u32 lm75_chip_config[] = {
        HWMON_C_REGISTER_TZ | HWMON_C_UPDATE_INTERVAL,
        0
};

static const struct hwmon_channel_info lm75_chip = {
        .type = hwmon_chip,
        .config = lm75_chip_config,
};

static const u32 lm75_temp_config[] = {
        HWMON_T_INPUT | HWMON_T_MAX | HWMON_T_MAX_HYST,
        0
};

static const struct hwmon_channel_info lm75_temp = {
        .type = hwmon_temp,
        .config = lm75_temp_config,
};

static const struct hwmon_channel_info *lm75_info[] = {
        &lm75_chip,
        &lm75_temp,
        NULL
};

The HWMON_CHANNEL_INFO() macro can and should be used when possible.
With this macro, the above example can be simplified to

static const struct hwmon_channel_info *lm75_info[] = {
        HWMON_CHANNEL_INFO(chip,
                        HWMON_C_REGISTER_TZ | HWMON_C_UPDATE_INTERVAL),
        HWMON_CHANNEL_INFO(temp,
                        HWMON_T_INPUT | HWMON_T_MAX | HWMON_T_MAX_HYST),
        NULL
};

The remaining declarations are as follows.

static const struct hwmon_ops lm75_hwmon_ops = {
        .is_visible = lm75_is_visible,
        .read = lm75_read,
        .write = lm75_write,
};

static const struct hwmon_chip_info lm75_chip_info = {
        .ops = &lm75_hwmon_ops,
        .info = lm75_info,
};

個々の属性サポートを示すビット値の完全な一覧は、include/linux/hwmon.hに定義されています。定義のプレフィックスは以下の通りです。

HWMON_C_xxxx

チップ属性。hwmon_chipで使用します。

HWMON_T_xxxx

温度属性。hwmon_tempで使用します。

HWMON_I_xxxx

電圧属性。hwmon_inで使用します。

HWMON_C_xxxx

電流属性。hwmon_currで使用します。チップ属性と重複するプレフィックスに注意してください。

HWMON_P_xxxx

電力属性。hwmon_powerで使用します。

HWMON_E_xxxx

エネルギー属性。hwmon_energyで使用します。

HWMON_H_xxxx

湿度属性。hwmon_humidityで使用します。

HWMON_F_xxxx

ファン速度属性。hwmon_fanで使用します。

HWMON_PWM_xxxx

PWM制御属性。hwmon_pwmで使用します。

ドライバコールバック関数¶

各ドライバはis_visible、read、write関数を提供します。これらの関数のパラメータおよび戻り値は以下の通りです：

umode_t is_visible_func(const void *data, enum hwmon_sensor_types type,
                        u32 attr, int channel)
パラメータ:
data:

デバイス専用データ構造へのポインタ。

type:

センサーの種類。

attr:

特定の属性に関連する属性識別子。例えば、HWMON_T_INPUTの属性値はhwmon_temp_inputになります。ビットフィールドと属性値の完全なマッピングについては、include/linux/hwmon.hを参照してください。

channel:

センサーのチャンネル番号。

戻り値:

この属性のファイルモード。通常は0（属性が作成されない）、S_IRUGO、または「S_IRUGO | S_IWUSR」になります。

int read_func(struct device *dev, enum hwmon_sensor_types type,
              u32 attr, int channel, long *val)
パラメータ:
dev:

ハードウェアモニタリングデバイスへのポインタ。

type:

センサーの種類。

attr:

特定の属性に関連付けられた属性識別子です。たとえば、HWMON_T_INPUTの属性値はhwmon_temp_inputになります。完全なマッピングについては、include/linux/hwmon.hを参照してください。

channel:

センサーのチャンネル番号。

val:

属性値へのポインタ。

戻り値:

成功時は0、エラー時は負のエラーナンバー。

int write_func(struct device *dev, enum hwmon_sensor_types type,
               u32 attr, int channel, long val)
パラメータ:
dev:

ハードウェアモニタリングデバイスへのポインタ。

type:

センサーの種類。

attr:

特定の属性に関連付けられた属性識別子です。たとえば、HWMON_T_INPUTの属性値はhwmon_temp_inputになります。完全なマッピングについては、include/linux/hwmon.hを参照してください。

channel:

センサーのチャンネル番号。

val:

チップに書き込む値。

戻り値:

成功時は0、エラー時は負のエラーナンバー。

ドライバが提供するsysfs属性¶

ハードウェアモニタリングデバイスがhwmon_device_register_with_infoまたはdevm_hwmon_device_register_with_infoで登録されている場合、sysfs属性を提供する必要は通常ありません。これらの登録関数を使用する場合、追加の非標準sysfs属性のみを提供する必要があります。

ヘッダーファイルlinux/hwmon-sysfs.hには、ハードウェアモニタリング用sysfs属性を宣言・使用するための多くの有用なマクロが提供されています。

多くの場合、既存の定義DEVICE_ATTRやその変種DEVICE_ATTR_{RW,RO,WO}を使用してこのような属性を宣言できます。属性に追加のコンテキストがなければ可能です。しかし、多くの場合、センサーインデックスなどの追加情報が必要となり、これをsysfs属性ハンドリング関数に渡す必要があります。

SENSOR_DEVICE_ATTRおよびSENSOR_DEVICE_ATTR_2を使用して、追加のコンテキスト情報を必要とする属性を定義できます。SENSOR_DEVICE_ATTRは1つの追加引数、SENSOR_DEVICE_ATTR_2は2つの追加引数を必要とします。

標準的な属性パーミッションと関数名が使用可能な場合、SENSOR_DEVICE_ATTRおよびSENSOR_DEVICE_ATTR_2の簡略版を使用すべきです。標準的なパーミッションは、SENSOR_DEVICE_ATTR[_2]_RWで0644、SENSOR_DEVICE_ATTR[_2]_ROで0444、SENSOR_DEVICE_ATTR[_2]_WOで0200です。標準的な関数はDEVICE_ATTR_{RW,RO,WO}と同様で、提供された関数名に_showおよび_storeが追加されます。

SENSOR_DEVICE_ATTRおよびその変種は、struct sensor_device_attribute変数を定義します。この構造体には次のフィールドがあります：

struct sensor_device_attribute {
        struct device_attribute dev_attr;
        int index;
};

属性読み込みまたは書き込み関数からこの構造体へのポインタを取得するには、to_sensor_dev_attrを使用します。そのパラメータは、属性がアタッチされているデバイスです。

SENSOR_DEVICE_ATTR_2およびその変種は、struct sensor_device_attribute_2変数を定義します。これは以下のようになります：

struct sensor_device_attribute_2 {
        struct device_attribute dev_attr;
        u8 index;
        u8 nr;
};

この構造体へのポインタを取得するには、to_sensor_dev_attr_2を使用します。そのパラメータは、属性がアタッチされているデバイスです。
