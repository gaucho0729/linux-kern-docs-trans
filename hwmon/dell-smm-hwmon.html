説明¶

多くのデルノートPCでは、システム管理モード（SMM）BIOSを介してファンや温度センサーの状態を照会できます。ユーザー空間のユーティリティなど sensors を使用して読み取りを行うことができます。ユーザー空間のツールキット i8kutils もセンサーを読み取ってファン速度を自動調整するためにも使用できます（注意：現在は非推奨の /proc/i8k インターフェースを使用しています）。

sysfs インターフェース¶

温度センサーおよびファンは、 hwmon インターフェースを介して sysfsのディレクトリ /sys/class/hwmon/hwmonX のいくつかの値で X （ X このような /sys/class/hwmon/hwmonX/name にコンテンツがある） dell_smm。いくつかの他の属性も読み取れたり、書き換えたりできます：

自動BIOSファン制御の無効化¶

一部のノートPCでは、BIOSが数秒ごとにファン速度を自動設定します。そのため、このドライバを介して設定したファン速度はすぐに上書きされます。

自動BIOSファン制御の無効化に対する実験的なサポートがあります。少なくとも、対応するSMMコマンドがわかっているノートPCでは、属性 1 に値 pwm1_enable を書き込むことで無効化できます（ 2 を書き込むと自動BIOS制御が再び有効になります）。複数のファンがある場合でも、すべてのファンが同時に有効化または無効化され、名称とは関係なく、 pwm1_enable すべてのファンに対して自動制御を設定します。

もし pwm1_enable が利用できない場合、それはSMMコードで自動BIOSファン制御を有効化・無効化するためのコードがハードウェアごとに白リストに登録されていないことを意味します。他のノートPCで動作するコードがあなたのハードウェアでも動作する可能性がありますし、あるいは新しいコードを発見する必要があります。

を確認してください i8k_whitelist_fan_control ファイル drivers/hwmon/dell-smm-hwmon.c 内のカーネルツリーで：最初の試みとして、あなたのマシンを追加し、既知のコードペアを使用してみてください。カーネルを再コンパイルした後、 pwm1_enable が存在し動作する（つまり、手動でファン速度を制御できる）場合、あなたの発見をカーネルパッチとして提出してください。他のユーザーが利用できるようにしてください。詳しくは パッチの送信: コードをカーネルに取り込むためのエッセンシャルガイド パッチの送信に関する情報。

あなたのマシンで動作する既知のコードが見つからない場合、探査を行う必要があります。残念ながらDellは自身のSMM用データシートを公開していません。このリポジトリ内のコードを このリポジトリ を用いてマシンのBIOSを調査し、適切なコードを発見してください。

再度、新しいコードを発見した場合は、パッチを共有していただけますと幸いです！

モジュールパラメータ¶

  • force:bool

    サポートされているモデルの確認せずに強制的にロードする。(デフォルト: 0)

  • ignore_dmi:bool

    DMIデータが一致しない場合でもハードウェアの探査を継続する。(デフォルト: 0)

  • restricted:bool

    ファン制御を実行できるプロセスは、 CAP_SYS_ADMIN capabilityが設定されているプロセスまたはroot権限で実行されているプロセスに限る。この場合、通常のユーザーは温度とファン状態を読み取ることはできるが、ファンを制御することはできない。ノートPCが他のユーザーと共有されており、信頼できないユーザーがいる場合はこのオプションを使用することを検討してください。(デフォルト: 1、かつ /proc/i8k インターフェースでのみ有効) CONFIG_I8K)

  • power_status:bool

    AC状態を /proc/i8kで報告する。(デフォルト: 0、かつ CONFIG_I8K)

  • fan_mult:uint

    ファン速度に掛ける係数。(デフォルト: 自動検出)

  • fan_max:uint

    最大の設定可能なファン速度。(デフォルト: 自動検出)

Legacy /proc インターフェース¶

警告

このインターフェースは非推奨であり、新規アプリケーションでは使用しないでください。このインターフェースは、カーネルがオプション CONFIG_I8K.

でコンパイルされている場合にのみ利用可能です。カーネルドライバーが提供する情報は、単に /proc/i8k ファイルを読み込むことでアクセス可能です。例えば：

$ cat /proc/i8k
1.0 A17 2J59L02 52 2 1 8040 6420 1 2

から読み取ったフィールドは、 /proc/i8k は:

1.0 A17 2J59L02 52 2 1 8040 6420 1 2
|   |   |       |  | | |    |    | |
|   |   |       |  | | |    |    | +------- 10. buttons status
|   |   |       |  | | |    |    +--------- 9.  AC status
|   |   |       |  | | |    +-------------- 8.  fan0 RPM
|   |   |       |  | | +------------------- 7.  fan1 RPM
|   |   |       |  | +--------------------- 6.  fan0 status
|   |   |       |  +----------------------- 5.  fan1 status
|   |   |       +-------------------------- 4.  temp0 reading (Celsius)
|   |   +---------------------------------- 3.  Dell service tag (later known as 'serial number')
|   +-------------------------------------- 2.  BIOS version
+------------------------------------------ 1.  /proc/i8k format version

負の値（例：-22）はBIOSが該当の情報を返さないことを示します。これは一部のモデル/BIOSで正常な挙動です。

パフォーマンスの観点から、 /proc/i8k はデフォルトでAC状態を報告しません。このSMMコールは実行に時間がかかり、実際には必要ないためです。AC状態を /proc/i8k で表示するには、insmodにパラメータ power_status=1 を明示的に有効化する必要があります。AC状態が利用不可な場合は-1が表示されます。

ドライバーはまた、ioctlインターフェースを提供しており、これを使用して同じ情報を取得し、ファン状態を制御できます。ioctlインターフェースはCプログラムやshellからi8kctlユーティリティを使用してアクセス可能です。詳しくは、 i8kutils のソースファイルを参照してください。
