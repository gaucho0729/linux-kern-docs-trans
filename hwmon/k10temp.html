説明¶

このドライバはAMD Family 10h/11h/12h/14h/15h/16hプロセッサの内部温度センサーを読み取ることができます。

これらのプロセッサすべてにセンサーがありますが、Socket FまたはAM2+のプロセッサではセンサーが不正確な値を返す可能性があります（エラタ319）。ドライバはこれらのリビジョンでロードを拒否します。ただし、「force=1」モジュールパラメータを指定すればロード可能です。

技術的な理由により、ドライバはメインボードのソケットタイプのみを検出可能です。したがって、AM3プロセッサをAM2+メインボードで使用している場合、「force=1」パラメータを安全に使用できます。

Family 17h以前のCPUでは、温度測定値が1つあり、sysfsのtemp1_inputで利用可能です。これは摂氏で、1/8度の精度があります。注意点として、AMDマニュアルではこの値が相対値として定義されています。

Tctl is the processor temperature control value, used by the platform to
control cooling systems. Tctl is a non-physical temperature on an
arbitrary scale measured in degrees. It does _not_ represent an actual
physical temperature like die or case temperature. Instead, it specifies
the processor temperature relative to the point at which the system must
supply the maximum cooling for the processor's specified maximum case
temperature and maximum thermal power dissipation.

Tctlの最大値はtemp1_maxファイルに記載されています。

BIOSがハードウェア温度制御を有効にしている場合、プロセッサが自己制御で温度を下げて損傷を防ぐ閾値はtemp1_critおよびtemp1_crit_hystに記録されています。

一部のAMD CPUでは、ダイ温度（Tdie）と報告される温度（Tctl）の間に差があります。Tdieは実際の測定温度であり、Tctlはファン制御に使用されます。Tctlは常にtemp1_inputとして利用可能ですが、ドライバーはTdieをサポートするCPUに対してtemp2_inputとしてエクスポートします。

17hファミリのモデルでは相対温度が報告されるため、ドライバーは実際の温度を補正して報告することを目的としています。

17hファミリおよび18hファミリのCPUでは、コア複合ダイ（CCD）温度を報告する追加の温度センサーが存在する場合があります。最大8つの温度がtemp{3..10}_inputとして報告され、Tccd{1..8}とラベル付けされます。実際のサポートはCPUのバリエーションによります。

さまざまな17hおよび18hファミリのCPUが電圧および電流のテレメトリ情報（測定データ）を報告します。以下の属性が報告される場合があります。

属性 ラベル 説明 =============== ======= ================ in0_input Vcore コア電圧 in1_input Vsoc SoC電圧 curr1_input Icore コア電流 curr2_input Isoc SoC電流 =============== ======= ================

電流値はCPUが報告する未スケーリングの値であり、コア電流は1A / LSBの単位で報告されます。SoC電流は0.25A / LSBの単位で報告されます。実際の電流値は基板固有です。報告される電流値は概算であり、基板に応じてsensors3.confでスケーリングする必要があります。
