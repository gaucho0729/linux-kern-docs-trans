BPF_PROG_TYPE_CGROUP_SYSCTL¶

このドキュメントは BPF_PROG_TYPE_CGROUP_SYSCTL cgroup-bpf ハイカットを提供するプログラムタイプについて説明します。

このハイカットは cgroup にアタッチされ、その cgroup 内のプロセスが proc 内の sysctl ハンドルを読み書きするたびに呼び出されます。

1. アタッチタイプ¶

BPF_CGROUP_SYSCTL アタッチタイプは、プログラムを cgroup にアタッチするために使用されます。 BPF_PROG_TYPE_CGROUP_SYSCTL プログラムを cgroup にアタッチするために使用されます。

2. コンテキスト¶

BPF_PROG_TYPE_CGROUP_SYSCTL BPF プログラムから以下のコンテキストにアクセスできます：

struct bpf_sysctl {
    __u32 write;
    __u32 file_pos;
};

  • write sysctl 値が読み込まれているかどうか（0) または書き込まれているかどうか（1）。このフィールドは読み取り専用です。

  • file_pos sysctl がアクセスされるファイル位置を示します。読み取りまたは書き込み時に使用されます。このフィールドは読み取り/書き込み可能です。フィールドに書き込むと、sysctl proc ファイルの開始位置が設定されます read(2) 読み取りまたは write(2) 書き込みに使用されます。フィールドにゼロを書き込むことで、例えば全体の sysctl 値を上書きできます bpf_sysctl_set_new_value() on write(2) ユーザー空間から呼び出されても file_pos > 0。フィールドにゼロ以外の値を書き込むことで、指定された位置から sysctl 値の一部にアクセスできます file_pos。すべての sysctl がこのアクセスをサポートしているわけではありません file_pos != 0、例えば数値型の sysctl エントリへの書き込みは常にファイル位置 0。詳細は kernel.sysctl_writes_strict sysctl。

参照 linux/bpf.h をご参照ください。

3. 戻り値¶

BPF_PROG_TYPE_CGROUP_SYSCTL プログラムは以下の戻り値のいずれかを返さなければなりません：

  • 0 sysctl のアクセスを拒否します；

  • 1 アクセスを許可します。

プログラムが 0 を返すと、ユーザー空間は -1 from read(2) または write(2) および errno が設定されます EPERM.

4. ヘルパー¶

sysctl ハンドルは名前と値で表されるため、sysctl 特有の BPF ヘルパーはこれらのプロパティへのアクセスを提供することに焦点を当てています：

  • bpf_sysctl_get_name() sysctl 名を取得するには、 /proc/sys BPF プログラムのバッファにコピーします；

  • bpf_sysctl_get_current_value() sysctl が保持している文字列値を BPF プログラムのバッファにコピーします。このヘルパーは read(2) からと write(2) へに利用可能です；

  • bpf_sysctl_get_new_value() 実際に書き込みが行われる前に、sysctl に現在書き込まれている新しい文字列値を取得します。このヘルパーは ctx->write == 1;

  • bpf_sysctl_set_new_value() にのみ利用可能です。sysctl 値は現在の ctx->file_posから上書きされます。全体を上書きする場合は、BPF プログラムが file_pos をゼロに設定してからヘルパーを呼び出す必要があります。このヘルパーは ctx->write == 1ヘルパーアクセスによって設定された新しい文字列値は、ユーザー空間から渡された同等の文字列と同じようにカーネルによって処理および検証されます。

BPFプログラムは、プロックファイルシステムにおいてユーザー空間が見るように、sysctl値を文字列として見ます。多くのsysctl値が整数または整数のベクトルを表すため、以下のヘルパー関数を使用して文字列から数値を取得できます：

  • bpf_strtol() ユーザー空間と同じように文字列の初期部分をlong整数に変換します strtol(3);

  • bpf_strtoul() ユーザー空間と同じように文字列の初期部分をunsigned long整数に変換します strtoul(3);

参照 linux/bpf.h ここで説明したヘルパー関数についての詳細は、以下を参照してください。

5. 例¶

参照 test_sysctl_prog.c BPFプログラムがsysctl名と値にアクセスし、文字列値を解析して整数ベクトルを取得し、その結果をもとにsysctlへのアクセスを許可または拒否するかどうかを決定する例です。

6. 注意事項¶

BPF_PROG_TYPE_CGROUP_SYSCTL は以下のような環境で使用することを意図しています 信頼できる root環境で使用され、例えばアプリケーションが別個のcgroupで実行されている場合にsysctlの使用状況を監視したり、不適切な値を設定しようとするのを検出したりするためのものです。

なぜなら task_dfl_cgroup(current) は以下のようなタイミングで呼ばれます sys_read / sys_write その結果、sys_openのタイミングとは異なる結果を返す可能性があります sys_open つまり、プロックファイルシステムでsysctlファイルを開いたプロセスと、そのファイルから読み書きしようとしているプロセスが異なる可能性があり、これらが異なるcgroupで実行されている場合があります。このため、 BPF_PROG_TYPE_CGROUP_SYSCTL sysctlの使用を制限するセキュリティメカニズムとして使用すべきではありません。

cgroup-bpfプログラムと同様に、管理者がアタッチしたBPFプログラムを、cgroup内でrootとして実行するアプリケーションが剥がし取ったり置き換えたりすることを許可しないように注意が必要です。
