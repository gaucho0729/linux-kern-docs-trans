BPF_PROG_TYPE_CGROUP_SOCKOPT¶

BPF_PROG_TYPE_CGROUP_SOCKOPT program type can be attached to two cgroup hooks:

  • BPF_CGROUP_GETSOCKOPT - called every time process executes getsockopt システムコールで読み取ることができます。

  • BPF_CGROUP_SETSOCKOPT - called every time process executes setsockopt システムコールで読み取ることができます。

The context (struct bpf_sockopt) has associated socket (sk) and all input arguments: level, optname, optval および optlen.

BPF_CGROUP_SETSOCKOPT¶

BPF_CGROUP_SETSOCKOPT is triggered before the kernel handling of sockopt and it has writable context: it can modify the supplied arguments before passing them down to the kernel. This hook has access to the cgroup and socket local storage.

If BPF program sets optlen to -1, the control will be returned back to the userspace after all other BPF programs in the cgroup chain finish (i.e. kernel setsockopt handling will ではありません be executed).

Note, that optlen can not be increased beyond the user-supplied value. It can only be decreased or set to -1. Any other value will trigger EFAULT.

Return Type¶

  • 0 - reject the syscall, EPERM will be returned to the userspace.

  • 1 - success, continue with next BPF program in the cgroup chain.

BPF_CGROUP_GETSOCKOPT¶

BPF_CGROUP_GETSOCKOPT is triggered RCU保護データ構造からデータ要素を削除した後、 the kernel handing of sockopt. The BPF hook can observe optval, optlen および retval if it’s interested in whatever kernel has returned. BPF hook can override the values above, adjust optlen and reset retval to 0. If optlen has been increased above initial getsockopt value (i.e. userspace buffer is too small), EFAULT nilを返します。

This hook has access to the cgroup and socket local storage.

Note, that the only acceptable value to set to retval is 0 and the original value that the kernel returned. Any other value will trigger EFAULT.

Return Type¶

  • 0 - reject the syscall, EPERM will be returned to the userspace.

  • 1 - success: copy optval および optlen to userspace, return retval from the syscall (note that this can be overwritten by the BPF program from the parent cgroup).

Cgroup Inheritance¶

Suppose, there is the following cgroup hierarchy where each cgroup has BPF_CGROUP_GETSOCKOPT attached at each level with BPF_F_ALLOW_MULTI flag:

A (root, parent)
 \
  B (child)

When the application calls getsockopt syscall from the cgroup B, the programs are executed from the bottom up: B, A. First program (B) sees the result of kernel’s getsockopt. It can optionally adjust optval, optlen and reset retval to 0. After that control will be passed to the second (A) program which will see the same context as B including any potential modifications.

同じように BPF_CGROUP_SETSOCKOPT: プログラムがAとBにアタッチされている場合、トリガーの順序はBからAになります。Bが入力引数に対して変更を加える場合（level, optname, optval, optlen）、チェーンの次のプログラム（A）はその変更を確認します。 ではありません 元の入力 setsockopt 引数。潜在的に変更された値はその後、カーネルに渡されます。

Large optval¶

When the optval が「 PAGE_SIZE」より大きい場合、BPFプログラムはそのデータの最初の PAGE_SIZE のみにアクセスできます。そのための選択肢は2つあります：

  • Set optlen をゼロに設定すると、カーネルがユーザースペースからの元のバッファを使用することを示します。BPFプログラムが optval に加えた変更は無視されます。

  • Set optlen を「 PAGE_SIZE」より小さい値に設定すると、カーネルがBPFのトリム済み optval.

を扱う際の状態を示します。BPFプログラムが「 optlen 」より大きい値を返すと、ユーザースペースは PAGE_SIZEerrno. EFAULT を受信します。
