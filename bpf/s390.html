s390でBPFをテストする¶

1. はじめに¶

IBM Zはメインフレームコンピュータであり、1964年のIBM System/360から派生した機種です。Linuxカーネルでは「s390」としてサポートされており、このドキュメントではs390 QEMUゲストでBPFをテストする方法について説明します。

2. 一時的なセットアップ¶

テストスイートをビルドして実行するには以下のものが必要です：

  • s390 GCC

  • s390開発用ヘッダーファイルとライブラリ

  • BPFサポートを持つClang

  • s390サポートを持つQEMU

  • s390 rootfsを含むディスクイメージ

Debianではs390用コンパイラやライブラリを箱から出荷時からインストール可能です。他のディストリビューションを使用する場合はdebootstrapを用いてDebian chrootを設定できます：

sudo debootstrap \
  --variant=minbase \
  --include=sudo \
  testing \
  ./s390-toolchain
sudo mount --rbind /dev ./s390-toolchain/dev
sudo mount --rbind /proc ./s390-toolchain/proc
sudo mount --rbind /sys ./s390-toolchain/sys
sudo chroot ./s390-toolchain

Debianに移行した後、ビルドに必要な前提条件は以下のコマンドでインストール可能です：

sudo dpkg --add-architecture s390x
sudo apt-get update
sudo apt-get install \
  bc \
  bison \
  cmake \
  debootstrap \
  dwarves \
  flex \
  g++ \
  gcc \
  g++-s390x-linux-gnu \
  gcc-s390x-linux-gnu \
  gdb-multiarch \
  git \
  make \
  python3 \
  qemu-system-misc \
  qemu-utils \
  rsync \
  libcap-dev:s390x \
  libelf-dev:s390x \
  libncurses-dev

BPFをターゲットとした最新のClangは以下のコマンドでインストール可能です：

git clone https://github.com/llvm/llvm-project.git
ln -s ../../clang llvm-project/llvm/tools/
mkdir llvm-project-build
cd llvm-project-build
cmake \
  -DLLVM_TARGETS_TO_BUILD=BPF \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_INSTALL_PREFIX=/opt/clang-bpf \
  ../llvm-project/llvm
make
sudo make install
export PATH=/opt/clang-bpf/bin:$PATH

ディスクイメージはループバックマウントとdebootstrapを用いて準備可能です：

qemu-img create -f raw ./s390.img 1G
sudo losetup -f ./s390.img
sudo mkfs.ext4 /dev/loopX
mkdir ./s390.rootfs
sudo mount /dev/loopX ./s390.rootfs
sudo debootstrap \
  --foreign \
  --arch=s390x \
  --variant=minbase \
  --include=" \
    iproute2, \
    iputils-ping, \
    isc-dhcp-client, \
    kmod, \
    libcap2, \
    libelf1, \
    netcat, \
    procps" \
  testing \
  ./s390.rootfs
sudo umount ./s390.rootfs
sudo losetup -d /dev/loopX

3. コンパイル¶

通常のKconfigオプションに加え、BPFテストスイートを実行するために以下のオプションも選択することをお勧めします：

CONFIG_NET_9P=y
CONFIG_9P_FS=y
CONFIG_NET_9P_VIRTIO=y
CONFIG_VIRTIO_PCI=y

これによりs390仮想マシンとファイルを簡単に共有できるようになります。

カーネル、モジュール、テストスイートのコンパイルおよびデバッグを簡素化するためのgdbスクリプトの準備は以下のコマンドで行えます：

make ARCH=s390 CROSS_COMPILE=s390x-linux-gnu- menuconfig
make ARCH=s390 CROSS_COMPILE=s390x-linux-gnu- bzImage modules scripts_gdb
make ARCH=s390 CROSS_COMPILE=s390x-linux-gnu- \
  -C tools/testing/selftests \
  TARGETS=bpf \
  INSTALL_PATH=$PWD/tools/testing/selftests/kselftest_install \
  install

4. テストスイートの実行¶

仮想マシンを起動するには以下のコマンドを使用します：

qemu-system-s390x \
  -cpu max,zpci=on \
  -smp 2 \
  -m 4G \
  -kernel linux/arch/s390/boot/compressed/vmlinux \
  -drive file=./s390.img,if=virtio,format=raw \
  -nographic \
  -append 'root=/dev/vda rw console=ttyS1' \
  -virtfs local,path=./linux,security_model=none,mount_tag=linux \
  -object rng-random,filename=/dev/urandom,id=rng0 \
  -device virtio-rng-ccw,rng=rng0 \
  -netdev user,id=net0 \
  -device virtio-net-ccw,netdev=net0

実際のIBM Zで使用する場合、 -enable-kvm パフォーマンス向上のために追加されることがあります。初めて仮想マシンを起動する際には以下のコマンドでディスクイメージの設定を完了する必要があります：

/debootstrap/debootstrap --second-stage

ホストでビルドされたコードが含まれるディレクトリおよび /proc および /sys は以下のコマンドでマウントする必要があります：

mkdir -p /linux
mount -t 9p linux /linux
mount -t proc proc /proc
mount -t sysfs sys /sys

その後、以下のコマンドでテストスイートを実行できます：

cd /linux/tools/testing/selftests/kselftest_install
./run_kselftest.sh

通常通り、個々のテストも以下のコマンドで実行可能です：

cd /linux/tools/testing/selftests/bpf
./test_verifier

5. デバッグ¶

QEMU GDBスタブを用いてs390カーネルのデバッグが可能です。これはQEMUに以下のパラメータを渡すことで有効になります： -s GDBは以下のコマンドで接続できます：

KASLRをオフにすることで、gdbがメモリ内でのカーネルイメージの位置を把握できるようになります。これには以下のオプションでカーネルをビルドします：

RANDOMIZE_BASE=n

GDBは以下のコマンドで接続できます：

gdb-multiarch -ex 'target remote localhost:1234' ./vmlinux

6. ネットワーク¶

仮想マシン内でネットワークを使用する必要がある場合（例：追加パッケージのインストールなど）、以下のコマンドで設定できます：

dhclient eth0
