セキュア暗号化仮想化（SEV）¶

概要¶

セキュア暗号化仮想化（SEV）は、AMD プロセッサに搭載されている機能です。

SEV は AMD-V アーキテクチャの拡張機能であり、ハイパーバイザーの制御下で仮想マシン（VM）を実行することをサポートします。有効化された場合、VM のメモリ内容はその VM に固有の鍵で透明性を保ちながら暗号化されます。

ハイパーバイザーは CPUID 命令を通じて SEV のサポートを確認できます。CPUID 関数 0x8000001f は SEV に関する情報を報告します:

0x8000001f[eax]:
                Bit[1]  indicates support for SEV
    ...
          [ecx]:
                Bits[31:0]  Number of encrypted guests supported simultaneously

SEV のサポートがある場合、MSR 0xc001_0010（MSR_K8_SYSCFG）および MSR 0xc001_0015（MSR_K7_HWCR）を使用して、有効化が可能かどうかを確認できます:

0xc001_0010:
        Bit[23]    1 = memory encryption can be enabled
                   0 = memory encryption can not be enabled

0xc001_0015:
        Bit[0]     1 = memory encryption can be enabled
                   0 = memory encryption can not be enabled

SEV のサポートが利用可能な場合、VMRUN を実行する前にその VM で SEV ビットを設定することで、特定の VM で有効化できます。

VMCB[0x90]:
        Bit[1]      1 = SEV is enabled
                    0 = SEV is disabled

SEV ハードウェアは ASID を使って VM とメモリ暗号化鍵を関連付けるため、SEV が有効なゲストの ASID は CPUID 0x8000001f[ecx] フィールドで定義された最大値以下の 1 〜最大値の範囲内でなければなりません。

SEV キー管理¶

SEV ゲストのキー管理は、AMD セキュアプロセッサ（AMD-SP）と呼ばれる別個のプロセッサによって処理されます。AMD-SP 内で実行されるファームウェアは、ハイパーバイザーの一般的な操作（ブートストラップコードの暗号化、スナップショット、ゲストの移動およびデバッグ）を安全に実行するためのキーマネジメントインターフェースを提供します。詳細については、SEV キー管理仕様を参照してください。 [api-spec]

SEV にアクセスする主な ioctl は KVM_MEMORY_ENCRYPT_OP です。KVM_MEMORY_ENCRYPT_OP の引数が NULL の場合、SEV が有効であれば ioctl は 0 を返します。 ENOTTY` if it is disabled (on some older versions of Linux, the ioctl runs normally even with a NULL argument, and therefore will likely return ``EFAULTNULL でない場合、KVM_MEMORY_ENCRYPT_OP の引数は struct kvm_sev_cmd でなければなりません:

struct kvm_sev_cmd {
        __u32 id;
        __u64 data;
        __u32 error;
        __u32 sev_fd;
};

以下の id フィールドにはサブコマンドが含まれ、 data フィールドはコマンドに固有の引数を含む別の struct へのポインタを指します。 sev_fd 必要に応じて、デバイスに開かれたファイルディスクリプタへのポインタを指す必要があります（個々のコマンドを参照してください）。 /dev/sev 出力では、

成功時は 0、エラーの場合はエラーコードになります。エラーコードは error で定義されています。 <linux/psp-dev.h>.

KVM は SEV ゲストの一般的なライフサイクルイベント（起動、実行、スナップショット、移動、退役）をサポートするため、以下のコマンドを実装しています。

1. KVM_SEV_INIT¶

KVM_SEV_INIT コマンドはハイパーバイザーが SEV プラットフォームコンテキストを初期化するために使用されます。通常のワークフローでは、このコマンドが最初に実行されるべきです。

戻り値: 成功時は 0、エラー時は -負の値

2. KVM_SEV_LAUNCH_START¶

KVM_SEV_LAUNCH_START コマンドはメモリ暗号化コンテキストの作成に使用されます。暗号化コンテキストを作成するには、ユーザーがゲストポリシー、所有者の公開 Diffie-Hellman（PDH）鍵、およびセッション情報を提供する必要があります。

パラメータ: struct kvm_sev_launch_start (入出力)

戻り値: 成功時は 0、エラー時は -負の値

struct kvm_sev_launch_start {
        __u32 handle;           /* if zero then firmware creates a new handle */
        __u32 policy;           /* guest's policy */

        __u64 dh_uaddr;         /* userspace address pointing to the guest owner's PDH key */
        __u32 dh_len;

        __u64 session_addr;     /* userspace address which points to the guest session information */
        __u32 session_len;
};

成功した場合、'handle' フィールドには新しいハンドルが含まれ、エラーの場合は負の値が返されます。

KVM_SEV_LAUNCH_START は、フィールドが有効であることを要します。 sev_fd フィールドが有効である必要があります。

詳細については、SEV データ仕様のセクション 6.2 を参照してください。

3. KVM_SEV_LAUNCH_UPDATE_DATA¶

KVM_SEV_LAUNCH_UPDATE_DATA はメモリ領域を暗号化するためのコマンドであり、メモリの内容の測定も行います。この測定はメモリ内容の署名であり、ファームウェアが暗号化を正しく実行したことをゲスト所有者に attest するための情報として送信できます。

パラメータ (入力): struct kvm_sev_launch_update_data

戻り値: 成功時は 0、エラー時は -負の値

struct kvm_sev_launch_update {
        __u64 uaddr;    /* userspace address to be encrypted (must be 16-byte aligned) */
        __u32 len;      /* length of the data to be encrypted (must be 16-byte aligned) */
};

詳細については、SEV データ仕様のセクション 6.3 を参照してください。

4. KVM_SEV_LAUNCH_MEASURE¶

KVM_SEV_LAUNCH_MEASURE コマンドは、KVM_SEV_LAUNCH_UPDATE_DATA コマンドで暗号化されたデータの測定を取得するために使用されます。ゲスト所有者は、測定を確認できるまで、ゲストに機密情報を提供を控えることができます。ゲスト所有者は起動時にゲストの初期内容を知っているため、測定をゲスト所有者が予期する内容と比較することで確認できます。

パラメータ (入力): struct kvm_sev_launch_measure

戻り値: 成功時は 0、エラー時は -負の値

struct kvm_sev_launch_measure {
        __u64 uaddr;    /* where to copy the measurement */
        __u32 len;      /* length of measurement blob */
};

測定確認フローについての詳細は、SEV データ仕様のセクション 6.4 を参照してください。

5. KVM_SEV_LAUNCH_FINISH¶

起動フローが完了した後、KVM_SEV_LAUNCH_FINISH コマンドを実行してゲストの実行準備をします。

戻り値: 成功時は 0、エラー時は -負の値

6. KVM_SEV_GUEST_STATUS¶

KVM_SEV_GUEST_STATUS コマンドは、SEV 有効化されたゲストの状態情報を取得するために使用されます。

パラメータ (出力): struct kvm_sev_guest_status

戻り値: 成功時は 0、エラー時は -負の値

struct kvm_sev_guest_status {
        __u32 handle;   /* guest handle */
        __u32 policy;   /* guest policy */
        __u8 state;     /* guest state (see enum below) */
};

SEV ゲスト状態:

enum {
SEV_STATE_INVALID = 0;
SEV_STATE_LAUNCHING,    /* guest is currently being launched */
SEV_STATE_SECRET,       /* guest is being launched and ready to accept the ciphertext data */
SEV_STATE_RUNNING,      /* guest is fully launched and running */
SEV_STATE_RECEIVING,    /* guest is being migrated in from another SEV machine */
SEV_STATE_SENDING       /* guest is getting migrated out to another SEV machine */
};

7. KVM_SEV_DBG_DECRYPT¶

KVM_SEV_DEBUG_DECRYPT コマンドは、ハイパーバイザーが指定されたメモリ領域のデータをファームウェアに暗号化を依頼するためのコマンドです。

パラメータ (入力): struct kvm_sev_dbg

戻り値: 成功時は 0、エラー時は -負の値

struct kvm_sev_dbg {
        __u64 src_uaddr;        /* userspace address of data to decrypt */
        __u64 dst_uaddr;        /* userspace address of destination */
        __u32 len;              /* length of memory region to decrypt */
};

ゲストポリシーがデバッグを許可しない場合、このコマンドはエラーを返します。

8. KVM_SEV_DBG_ENCRYPT¶

KVM_SEV_DEBUG_ENCRYPT コマンドは、ハイパーバイザーが指定されたメモリ領域のデータをファームウェアに暗号化を依頼するためのコマンドです。

パラメータ (入力): struct kvm_sev_dbg

戻り値: 成功時は 0、エラー時は -負の値

struct kvm_sev_dbg {
        __u64 src_uaddr;        /* userspace address of data to encrypt */
        __u64 dst_uaddr;        /* userspace address of destination */
        __u32 len;              /* length of memory region to encrypt */
};

ゲストポリシーがデバッグを許可しない場合、このコマンドはエラーを返します。

9. KVM_SEV_LAUNCH_SECRET¶

KVM_SEV_LAUNCH_SECRET コマンドは、ゲスト所有者が測定を確認した後、ハイパーバイザーがシークレットデータを注入するためのコマンドです。

パラメータ (入力): struct kvm_sev_launch_secret

戻り値: 成功時は 0、エラー時は -負の値

struct kvm_sev_launch_secret {
        __u64 hdr_uaddr;        /* userspace address containing the packet header */
        __u32 hdr_len;

        __u64 guest_uaddr;      /* the guest memory region where the secret should be injected */
        __u32 guest_len;

        __u64 trans_uaddr;      /* the hypervisor memory region which contains the secret */
        __u32 trans_len;
};
