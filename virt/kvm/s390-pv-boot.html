s390（IBM Z）保護仮想マシンのブート/IPL¶

Summary¶

保護された仮想マシン (PVM) のメモリは、I/O またはハイパーバイザーにアクセスできません。ハイパーバイザーが PVM のメモリにアクセスする必要がある場合、そのメモリをアクセス可能にする必要があります。ハイパーバイザーにアクセス可能なメモリは暗号化されます。詳細は s390（IBM Z） Ultravisorと保護仮想マシン をご参照ください。

IPL (ブート) では、暗号化されたコンポーネントに関する情報と、KVM が保護された仮想マシンを復号するために必要なメタデータを提供する小さな平文ブートローダーが起動されます。

このデータに基づき、KVM は Ultravisor (UV) に保護された仮想マシンを通知し、メモリのセキュリティ確保、コンポーネントの復号、データおよびアドレスリストハッシュの検証を行うよう指示します。これにより、KVM は UV が代行して SIE 指令を実行することで PVM を実行できます。

ゲストイメージは、自身で PV モードに切り替える透過的なカーネルイメージと同様であり、ユーザーはネットワーク、DASD、SCSI、直接カーネルなど、すべての利用可能な方法で暗号化されたゲスト実行ファイルとデータをロードできます。ブートプロセスの変更は必要ありません。

Diag308¶

この診断指令は、仮想マシンの IPL および関連操作を処理する基本的なメカニズムです。VM は IPL 情報ブロックを設定および取得し、IPL 方法/デバイスを指定し、VM メモリおよびサブシステムのリセットを要求し、IPL を実行できます。

PVM ではこの概念に新しいサブコードが追加されました:

サブコード 8: タイプ5のIPL情報ブロックを設定する サブコード 9: 保存されたブロックをゲストメモリに保存する サブコード 10: 保護された仮想化モードに移行する

新しいPVロードデバイス固有パラメータフィールドは、PVモードに移行するために必要なすべてのデータを指定します。

  • PVヘッダーオリジン

  • PVヘッダーレンジ

  • コンポーネントリスト（以下の要素を含む）

    • AES-XTSツイックプレフィックス

    • オリジン

    • Size

PVヘッダーには、UV が PV を復号および検証するために使用する鍵とハッシュ、制御フラグ、および開始PSWが含まれます。

コンポーネントは暗号化されたカーネル、カーネルパラメータ、initrd などです。コンポーネントは UV によって復号されます。

暗号化データの初期インポート後、すべての定義されたページにはゲストコンテンツが含まれます。指定されていないページは、最初のアクセス時にゼロページとして初期化されます。

保護された仮想化モードで実行している場合、一部のサブコードは例外を発生させるかエラーを返します。

ゲストメモリをクリアしない操作を指定するサブコード4および7は、仕様例外を引き起こします。これは、セキュアVMが削除される際、UVがすべてのメモリをクリアするため、クリアしないIPLサブコードは許可されないからです。

サブコード8、9、10は仕様例外を引き起こします。保護モードへの再IPLは、非保護モードへの迂回経路を通じてのみ可能です。

キー¶

すべてのCECは、ツールが暗号化されたイメージを構築できるようにする一意の公開鍵を持ちます。参照 s390-tools ツールに関する情報
