KVM固有のMSR¶

著者

Glauber Costa <glommer@redhat.com>, Red Hat Inc, 2010

KVMは一部のカスタムMSRを使用して、特定のリクエストを処理します。

カスタムMSRには、0x4b564d00から0x4b564dffまでの範囲が予約されています。この範囲外にもMSRは存在しますが、それらは非推奨であり、使用は控えられるべきです。

カスタムMSRリスト¶

現在サポートされているカスタムMSRの一覧は以下の通りです：

MSR_KVM_WALL_CLOCK_NEW:

0x4b564d00

data:

4バイトアライメントされた物理アドレスで、ゲストRAMに存在するメモリ領域。このメモリは、以下の構造体のコピーを保持すると期待されます：

struct pvclock_wall_clock {
       u32   version;
       u32   sec;
       u32   nsec;
 } __attribute__((__packed__));

ハイパーバイザーによってデータが埋め込まれます。ハイパーバイザーは、MSRの書き込み時にのみこのデータを更新することを保証しています。この情報に信頼性を持って複数回問い合わせたいユーザーは、このMSRを複数回書き込む必要があります。フィールドの意味は以下の通りです：

バージョン:

ゲストは、時間情報を取得する前後でバージョンを確認し、それらが等しく偶数であることを確認する必要があります。奇数のバージョンは、進行中の更新を示します。

sec:

起動時のウォールクロックの秒数。

nsec:

起動時のウォールクロックのナノ秒数。

現在のウォールクロック時間を取得するには、MSR_KVM_SYSTEM_TIME_NEWからsystem_timeを加算する必要があります。

注意: 一部のMSRはCPUごとに存在するが、この特定のMSRの効果はグローバルです。

このMSRの利用前には、0x4000001 cpuid leafのビット3を確認して利用可能かどうかを確認する必要があります。

MSR_KVM_SYSTEM_TIME_NEW:

0x4b564d01

data:

4バイトアライメントされた物理アドレスで、ゲストRAMに存在するメモリ領域。さらに、ビット0にエナビリティビットが含まれます。このメモリは、以下の構造体のコピーを保持すると期待されます：

struct pvclock_vcpu_time_info {
      u32   version;
      u32   pad0;
      u64   tsc_timestamp;
      u64   system_time;
      u32   tsc_to_system_mul;
      s8    tsc_shift;
      u8    flags;
      u8    pad[2];
} __attribute__((__packed__)); /* 32 bytes */

ハイパーバイザーが定期的にデータを埋め込みます。各VCPUに対して1回の書き込みまたは登録で十分です。この構造体の更新間隔は任意で、実装依存です。ハイパーバイザーは、ビット0が0になるまで、いつでも更新を行うことができます。

フィールドの意味は以下の通りです：

バージョン:

ゲストは、時間情報を取得する前後でバージョンを確認し、それらが等しく偶数であることを確認する必要があります。奇数のバージョンは、進行中の更新を示します。

tsc_timestamp:

この構造体の更新時の現在のVCPUのTSC値。ゲストは、この値を現在のTSCから引くことで、構造体更新からの経過時間を算出できます。

system_time:

ホストの単調時刻の概念を表し、この構造体が最後に更新された時点のスリープ時間を含みます。単位はナノ秒です。

tsc_to_system_mul:

TSC関連の量をナノ秒に変換する際の乗数

tsc_shift:

tsc関連の量をナノ秒に変換する際に使用されるシフト値。このシフトにより、tsc_to_system_mulとの乗算がオーバーフローしないようにします。正の値は左シフトを、負の値は右シフトを表します。

tscをナノ秒に変換する際には、さらに32ビット右シフトが行われます。この情報からゲストは、以下の手順で各CPUごとの時間を算出できます：

time = (current_tsc - tsc_timestamp)
if (tsc_shift >= 0)
        time <<= tsc_shift;
else
        time >>= -tsc_shift;
time = (time * tsc_to_system_mul) >> 32
time = time + system_time
フラグ:

このフィールドのビットは、ゲストとホスト仮想化ソフトウェア間で協調して使用される拡張機能を示します。特定のフラグの有無は、0x40000001 cpuidシートで確認する必要があります。現在のフラグは以下の通りです：

フラグビット

cpuidビット

意味

0

24

複数のCPUをまたがる時間測定は常に単調増加を保証します

1

N/A

ホストによってゲストのvcpuが一時停止されました。詳しくはapi.txtの4.70節を参照してください。

このMSRの利用前には、0x4000001 cpuid leafのビット3を確認して利用可能かどうかを確認する必要があります。

MSR_KVM_WALL_CLOCK:

0x11

データおよび機能：

MSR_KVM_WALL_CLOCK_NEWと同じです。代わりにそのものを使用してください。

このMSRは予約されたKVM範囲外にあり、今後削除される可能性があります。使用は非推奨です。

このMSRの使用前に、0x4000001 cpuidシートのビット0を確認する必要があります。

MSR_KVM_SYSTEM_TIME:

0x12

データおよび機能：

MSR_KVM_SYSTEM_TIME_NEWと同じです。代わりにそのものを使用してください。

このMSRは予約されたKVM範囲外にあり、今後削除される可能性があります。使用は非推奨です。

このMSRの使用前に、0x4000001 cpuidシートのビット0を確認する必要があります。

KVMclockの存在を検出するための推奨アルゴリズムは以下の通りです：

if (!kvm_para_available())    /* refer to cpuid.txt */
        return NON_PRESENT;

flags = cpuid_eax(0x40000001);
if (flags & 3) {
        msr_kvm_system_time = MSR_KVM_SYSTEM_TIME_NEW;
        msr_kvm_wall_clock = MSR_KVM_WALL_CLOCK_NEW;
        return PRESENT;
} else if (flags & 0) {
        msr_kvm_system_time = MSR_KVM_SYSTEM_TIME;
        msr_kvm_wall_clock = MSR_KVM_WALL_CLOCK;
        return PRESENT;
} else
        return NON_PRESENT;
MSR_KVM_ASYNC_PF_EN:

0x4b564d02

data:

非同期ページフォールト（APF）制御MSR。

ビット63-6は、ゲストRAMに配置されゼロに初期化された64バイトのメモリ領域の64バイトアライメントされた物理アドレスを保持します。このメモリは以下の構造体のコピーを保持する必要があります：

struct kvm_vcpu_pv_apf_data {
      /* Used for 'page not present' events delivered via #PF */
      __u32 flags;

      /* Used for 'page ready' events delivered via interrupt notification */
      __u32 token;

      __u8 pad[56];
      __u32 enabled;
};

MSRのビット5-4は予約されており、ゼロに設定する必要があります。ビット0は、vcpuで非同期ページフォールトが有効な場合1、無効な場合0になります。ビット1は、vcpuがcpl == 0の状態で非同期ページフォールトをインジェクトできる場合1になります。ビット2は、L1に#PF vmexitとして非同期ページフォールトが配信される場合1になります。このビット2は、CPUIDにKVM_FEATURE_ASYNC_PF_VMEXITが存在する場合のみ設定可能です。ビット3は、ページ準備イベントの割り込みベースの配信を有効にします。このビット3は、CPUIDにKVM_FEATURE_ASYNC_PF_INTが存在する場合のみ設定可能です。

「ページが存在しない」イベントは現在、常に合成 #PF 例外として配信されます。これらのイベントの配信中に APF CR2 レジスタには、欠損ページが利用可能になったときにゲストに通知するために使用されるトークンが含まれています。また、実際の #PF と APF を区別できるように、ホストがインジェクション時に 64 バイトのメモリ領域（「フラグ」）の最初の 4 バイトにホストが書き込みます。現在は「フラグ」の最初のビットのみがサポートされており、設定されている場合、ゲストが非同期の「ページが存在しない」イベントを処理していることを示します。ページフォールト中に APF の「フラグ」が「0」の場合、これは通常のページフォールトです。ゲストは #PF 例外の処理が完了した後、「フラグ」をクリアする必要があります。これにより次のイベントが配信されるようになります。

注意として、APF の「ページが存在しない」イベントは通常のページフォールトと同じ例外ベクターを使用するため、ゲストは通常のページフォールトを生成する可能性のある操作を行う前に、「フラグ」を「0」に戻す必要があります。

APF の「ページが準備完了」イベントインジェクション時に、64 バイトのメモリ領域（「トークン」）の 5〜7 バイトにホストが書き込みます。これらのバイトの内容は、以前に「ページが存在しない」イベントとして配信されたトークンです。このイベントはページが現在利用可能になったことを示します。ゲストは「ページが準備完了」イベントの処理が完了した後、「トークン」に「0」を書き込み、位置をクリアした後に MSR_KVM_ASYNC_PF_ACK に「1」を書き込みます。MSR への書き込みは KVM にキューを再スキャンさせ、次の待機中の通知を配信させるよう強制します。

注意として、APF メカニズムを MSR_KVM_ASYNC_PF_EN で有効にする前に、MSR_KVM_ASYNC_PF_INT に「ページが準備完了」APF 配信の割込みベクターを指定する MSR を書き込む必要があります。MSR は KVM_FEATURE_ASYNC_PF_INT が CPUID に存在する場合に利用可能です。

注意として、以前は「ページが準備完了」イベントは「ページが存在しない」イベントと同じ #PF 例外を介して配信されていましたが、これは現在非推奨です。ビット 3（割込みベースの配信）が設定されていない場合、APF イベントは配信されません。

APF が無効化されている間、未処理の APF は配信されません。

現在、「ページが準備完了」APF イベントは「ページが存在しない」イベントが発生した同じ vcpu で常に配信されます。ただし、ゲストはこの動作に依存すべきではありません。

MSR_KVM_STEAL_TIME:

0x4b564d03

data:

ゲスト RAM に存在する必要のあるメモリ領域の 64 バイトアライメント物理アドレス、およびビット 0 の有効化ビット。このメモリは以下の構造体のコピーを保持すると予想されます:

struct kvm_steal_time {
      __u64 steal;
      __u32 version;
      __u32 flags;
      __u8  preempted;
      __u8  u8_pad[3];
      __u32 pad[11];
}

この構造体のデータはハイパーバイザが定期的に埋めます。各VCPUに対して1回の書き込みまたは登録で十分です。この構造体の更新間隔は任意で、実装依存です。ハイパーバイザは、bit0 == 0の値が書き込まれるまで、いつでもこの構造体を更新できます。ゲストはこの構造体をゼロに初期化する必要があります。

フィールドの意味は以下の通りです：

バージョン:

シーケンスカウンタです。言い換えれば、ゲストは時間情報を取得する前後でこのフィールドを確認し、両方が等しく偶数であることを確認する必要があります。奇数のバージョンは更新中のことを示します。

フラグ:

この時点では常にゼロです。将来この構造体の変更を示すために使用できます。

ステール:

このvCPUが実行されなかった時間（ナノ秒単位）。vCPUがアイドル状態にある時間は、ステール時間として報告されません。

プリエンプト:

この構造体を所有するvCPUが実行中か否かを示します。ゼロ以外の値はvCPUがプリエンプトされたことを意味します。ゼロはvCPUがプリエンプトされていないことを示します。注意: ハイパーバイザがこのフィールドをサポートしない場合、常にゼロです。

MSR_KVM_EOI_EN:

0x4b564d04

data:

bit0は、vcpuでPVの割込み終了が有効な場合1、無効な場合0です。bit1は予約されており、ゼロでなければなりません。PVの割込み終了が有効（bit0が設定されている場合）、bit63-2は4バイトアライメントされた物理アドレスを保持し、ゲストRAMに存在し、ゼロに初期化されている必要があります。

4バイトメモリ領域の最下位ビットは、ハイパーバイザが割込みの注入時に書き込みます。値が1の場合は、ゲストはAPICへのEOI書き込み（MSRまたはMMIO書き込み）をスキップできます。代わりに、ゲストメモリ内のビットをクリアすることでEOIを通知するだけで十分です。この場所は後でハイパーバイザがポーリングします。値が0の場合はEOIの書き込みが必要です。

ゲストは最適化を無視してもAPIC EOIの書き込みを行うことが常に安全です。

ハイパーバイザは現在のVCPUコンテキスト内でのみこの最下位ビットを変更するため、ゲストはロックプリフィックスやメモリ順序プリミティブを使用する必要がありません。

ただし、ハイパーバイザーはいつでもこのメモリビットを設定およびクリアできます。したがって、ゲストがこのメモリ領域の最下位ビットをテストしてEOI APIC書き込みをスキップできるかを検出する間に、およびゲストがEOIをハイパーバイザーに通知するためにクリアする間にハイパーバイザーがゲストを中断しないようにするためには、ゲストは単一のCPU指令（例：テストアンドクリア、または比較アンドエクスチェンジ）を使用して、このメモリ領域の最下位ビットを読み取ってからクリアする必要があります。

MSR_KVM_POLL_CONTROL:

0x4b564d05

ホスト側のポーリングを制御します。

data:

ビット0はホスト側HLTポーリングロジックを有効（1）または無効（0）にします。

KVMゲストは、自分自身でポーリングを行っている場合など、ホスト側にHLTのポーリングを行わないようにリクエストできます。

MSR_KVM_ASYNC_PF_INT:

0x4b564d06

data:

第二の非同期ページフォールト（APF）制御MSR。

ビット0〜7：'ページ準備完了' APFイベントの配信用APICベクター。ビット8〜63：予約済み

非同期の'ページ準備完了'通知の配信に使用する割り込みベクターです。このベクターは、MSR_KVM_ASYNC_PF_ENで非同期ページフォールトメカニズムが有効になる前に設定する必要があります。このMSRは、CPUIDにKVM_FEATURE_ASYNC_PF_INTが存在する場合にのみ利用可能です。

MSR_KVM_ASYNC_PF_ACK:

0x4b564d07

data:

非同期ページフォールト（APF）の確認。

ゲストが'ページ準備完了' APFイベントの処理を終え、'struct kvm_vcpu_pv_apf_data'内の'token'フィールドをクリアした後、このMSRのビット0に'1'を書き込む必要があります。これにより、ホストがキューを再スキャンし、未処理の通知がまだあるかを確認します。このMSRは、CPUIDにKVM_FEATURE_ASYNC_PF_INTが存在する場合にのみ利用可能です。
