Linux KVMハイパーコール¶

X86:

KVM ハイパーコールは、vmcall または vmmcall 命令の3バイトのシーケンスを使用します。ハイパーコアは、サポートが保証されている命令に置き換えることができます。

rbx、rcx、rdx、rsi に最大4つの引数を渡すことができます。ハイパーコール番号は rax に配置し、戻り値は rax に配置されます。他のレジスタは、ハイパーコールが明示的に指定する限り破壊されません。

S390:

R2-R7 はパラメータ1〜6に使用されます。さらに、R1 はハイパーコール番号に使用されます。戻り値は R2 に書き込まれます。

S390 は diagnose 命令（0x500）をハイパーコールとして使用し、ハイパーコール番号は R1 に配置されます。

KVM がサポートする S390 diagnose 呼び出しに関する詳細情報については、 s390（IBM Z）KVM DIAGNOSEコール.

PowerPC:

R3-R10 と R11 にハイパーコール番号を使用します。R4-R11 は出力レジスタとして使用され、戻り値は R3 に配置されます。

KVM ハイパーコールは、デバイスツリーの/hypervisor ノード内の'hypercall-instructions'プロパティで4バイトのオプコードをパッチングします。詳細情報については、 PPC KVM パラバーチャルインターフェース

MIPS:

KVM ハイパーコールは、コード0のHYPCALL命令を使用し、ハイパーコール番号は $2（v0）に配置されます。最大4つの引数は $4-$7（a0-a3）に配置され、戻り値は $2（v0）に配置されます。

KVM Hypercalls ドキュメンテーション¶

各ハイパーコールのテンプレートは次の通りです：1. ハイパーコール名。2. アーキテクチャ（複数可）。3. 状態（非推奨、廃止、有効）。4. 目的

1. KVM_HC_VAPIC_POLL_IRQ¶

アーキテクチャ

x86

Status

アクティブ

目的

ゲストが再入時に待機中の割込みをホストが確認できるように、ゲストの終了をトリガーします。

2. KVM_HC_MMU_OP¶

アーキテクチャ

x86

Status

非推奨。

目的

PTEへの書き込み、TLBのフラッシュ、PTの解放などのMMU操作をサポートします。

3. KVM_HC_FEATURES¶

アーキテクチャ

PPC

Status

アクティブ

目的

ゲストにハイパーコールの可用性を公開します。x86プラットフォームでは cpuid が使用され、利用可能なハイパーコールを列挙します。PPCでは、デバイスツリーベースの検索（EPAPRが規定しているもの）またはKVM固有の列挙メカニズム（このハイパーコール）のいずれかを使用できます。

4. KVM_HC_PPC_MAP_MAGIC_PAGE¶

アーキテクチャ

PPC

Status

アクティブ

目的

ハイパーコアとゲスト間の通信を可能にする共有ページがあり、これはスーパーバイザービジョンレジスタ状態の一部を含みます。ゲストはこのハイパーコールを使用して、共有ページをマップし、メモリ経由でスーパーバイザーレジスタにアクセスできます。

5. KVM_HC_KICK_CPU¶

アーキテクチャ

x86

Status

アクティブ

目的

HLT状態のvcpuを再起動するためのハイパーコール

使用例

パラバーティリゼーションゲストのvCPUがゲストカーネルモードでイベントが発生するのをビジー待機している場合、ビジー待機時間がしきい値を超えた後、HLT命令を実行できる。HLT命令の実行によりハイパーサイズはvCPUを眠らせる。同じゲストの他のvCPUはKVM_HC_KICK_CPUハイパーコールを発行し、起動するvCPUのAPIC ID（a1）を指定することで眠っているvCPUを起こすことができる。このハイパーコールでは今後の用途に備えて追加の引数（a0）が使用される。

6. KVM_HC_CLOCK_PAIRING¶

アーキテクチャ

x86

Status

アクティブ

目的

ホストとゲストのクロックを同期するためのハイパーコール。

使用方法:

a0: ホストがコピーする「struct kvm_clock_offset」構造体のゲスト物理アドレス。

a1: クロックタイプ。ATMではKVM_CLOCK_PAIRING_WALLCLOCK（0）のみサポートされる（ホストのCLOCK_REALTIMEクロックに対応）。

struct kvm_clock_pairing {
        __s64 sec;
        __s64 nsec;
        __u64 tsc;
        __u32 flags;
        __u32 pad[9];
};
以下では:

  • sec: clock_typeクロックからの秒数。

  • nsec: clock_typeクロックからのナノ秒数。

  • tsc: ゲストTSC値（sec/nsecペアを計算するために使用）

  • flags: フラグ、現在は未使用（0）。

このハイパーコールにより、ゲストはホストとゲストを跨ぐ正確なタイムスタンプを計算できる。ゲストは返されたTSC値を使用して、その時点でのCLOCK_REALTIMEを計算できる。

ホストがTSCクロックソースを使用していない場合、またはクロックタイプがKVM_CLOCK_PAIRING_WALLCLOCKと異なる場合、KVM_EOPNOTSUPPを返す。

6. KVM_HC_SEND_IPI¶

アーキテクチャ

x86

Status

アクティブ

目的

複数のvCPUにIPIを送信する。

  • a0: 送信先APIC IDのビットマップの下位部分

  • a1: 送信先APIC IDのビットマップの上位部分

  • a2: ビットマップ内の最低APIC ID

  • a3: APIC ICR

このハイパーコールにより、ゲストはマルチキャストIPIを送信できる。64ビットモードでは1回のハイパーコールで最大128個の送信先、32ビットモードでは最大64個のvCPUを送信可能。送信先は最初の2つの引数（a0とa1）に含まれるビットマップで表される。a0のビット0は第3引数（a2）のAPIC IDに対応し、ビット1はa2+1のAPIC IDに対応する。

IPIが成功して送信されたCPUの数を返す。

7. KVM_HC_SCHED_YIELD¶

アーキテクチャ

x86

Status

アクティブ

目的

IPIターゲットvCPUがプリエンプトされた場合にユーティリティを提供するハイパーコール。

a0: 送信先APIC ID

使用例

vCPUにcall-function IPI-manyを送信する際、IPIターゲットvCPUがプリエンプトされた場合はユーティリティを提供する。
