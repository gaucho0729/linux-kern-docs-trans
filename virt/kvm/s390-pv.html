s390（IBM Z） Ultravisorと保護仮想マシン¶

Summary¶

保護された仮想マシン（PVM）は、KVM がゲストメモリやゲストレジスタなどの VM 状態にアクセスできない KVM 仮想マシンです。代わりに PVM は、新たに導入された Ultravisor（UV）というエンティティによって主に管理されます。UV は PVM および KVM が管理操作をリクエストするために使用できる API を提供します。

各ゲストは保護されていないモードで起動し、その後保護モードに移行するリクエストを出すことができます。移行時に KVM はゲストとその VCPU を Ultravisor に登録し、その実行に必要な準備を行います。

Ultravisor はゲストのブートメモリ（つまりカーネル/initrd）をセキュリティで保護し、暗号化解除します。ゲストが実行中である間、VCPU の起動/停止やインジェクションされた割り込みなどの状態変更も保護します。

ゲストの状態（例：SIE 状態記述）へのアクセスは通常 VM の実行に必要ですが、SIE 指令の挙動にいくつかの変更が加えられました。PVM においては、一部のフィールドの意味が異なる新しいフォーマット4の状態記述が導入されました。SIE からのエクスイットを可能な限り最小限に抑え、速度向上とゲスト状態の露出を減らすことが目的です。

割込みの注入¶

割り込みインジェクションは Ultravisor によって保護されています。KVM が VCPU のローコアにアクセスできないため、インジェクションはフォーマット4の状態記述を通じて処理されます。

マシンチェック、外部、IO および再起動割り込みは、割り込みインジェクション制御フィールド（オフセット 0x54）内のビットを介して SIE エントリ時にインジェクション可能です。インジェクション時のゲストCPUが該当割り込みを有効にしていない場合、有効性検出が認識されます。フォーマット4の状態記述には、割り込みに関連するデータを輸送するための検出データブロック内のフィールドが含まれています。

プログラムおよびサービスコール例外にはもう1層の保護が加えられています。これらは KVM にインターセプトされた指令のみにインジェクション可能です。例外は KVM による指令エミュレーションの有効な結果である必要があります。例えば、SIE で報告されるため KVM がゲストメモリにアクセスできないため、アドレッシング例外のインジェクションは許容されません。

マスク通知のインターセプション¶

KVMは、PVMが特定の割込みクラスを有効にするタイミングを通知するため、lctl(g)およびlpsw(e)のインターセプションをもはや行えません。代替として、2つの新しいインターセプションコードが導入されました：1つはCR0、CR6、またはCR14の内容が変更されたことを示し、異なる割込みサブクラスを表します。もう1つはPSWビット13が変更されたことを示し、マシンチェック介入が要求されたことを示します。これらは現在有効になっています。

インストラクションのエミュレーション¶

PVM用のフォーマット4の状態記述では、SIE命令はフォーマット2よりも多くの命令を解釈できます。ただしすべての命令を解釈できるわけではなく、一部のタスクをKVMに委譲する必要があります。そのため、SIEと超ビジョアのセキュリティエミュレーション入出力が実行されます。

SIEに関連する制御構造は、セキュアインストラクションデータ領域（SIDA）、インターセプションパラメータ（IP）、およびセキュアインターセプション汎用レジスタ保存領域を提供します。ゲストのGR（汎用レジスタ）や、I/Oデータ構造などの大部分のインストラクションデータはフィルタリングされます。必要に応じてインストラクションデータはSIDAとコピーされます。ゲストのGRはセキュアインターセプション汎用レジスタ保存領域に保存・取得されます。

インストラクションのエミュレーションに必要なGR値のみがこの保存領域にコピーされ、実際のレジスタ番号は隠されます。

インターセプションパラメータの状態記述フィールドには、インストラクションテキストのバイトが含まれていますが、実際のレジスタ値ではなく事前に設定された値が使用されます。つまり、各インストラクションは常に同じテキストを使用します。これにより、ゲストのインストラクションテキストが漏らされません。これにより、ゲストがr<n>で保持していたレジスタ内容は、ハイパーサーの観点ではr<m>に表示される可能性があります。

セキュアインストラクションデータ領域にはインストラクションの保存データが含まれます。インストラクションデータ（例：sclp用のSCCBなど）はSIDAを介して移動されます。インストラクションがインターセプトされた場合、SIEはこのインストラクションのデータとプログラム割込みのみを前述の2つのデータ領域を介してゲストに移動させます。他のデータは無視されるか、有効性のインターセプトを引き起こします。

インストラクションエミュレーションインターセプション¶

SIEのセキュアインストラクションインターセプトには、通常型と通知型の2種類があります。通常型のセキュアインストラクションインターセプトでは、ゲストがインターセプトされたインストラクションタイプの完了を待機します。つまり、SIEエントリ時にKVMから提供されたデータをもとにインストラクションのエミュレーションを試行します。これはプログラム例外またはインストラクション完了になる可能性があります。

通知タイプは、ゲスト指令の解釈によりゲスト環境が変化したことをKVMに通知します。このようなインターセプトは、たとえばストアプレフィックス指令を処理して新しいロワーコアの位置を提供するなど、特定のケースで認識されます。SIE再入時にデータ領域内のKVMデータは無視され、ゲスト指令が完了したかのように実行が継続されます。そのため、KVMはプログラム割込みを注入することが許可されていません。
