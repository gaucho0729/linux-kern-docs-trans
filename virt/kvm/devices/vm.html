汎用的仮想マシンインターフェース¶

仮想マシンの「デバイス」は、KVM_SET_DEVICE_ATTR、KVM_GET_DEVICE_ATTR、および KVM_HAS_DEVICE_ATTR という ioctls も受け付けます。インターフェースは他のデバイスと同じ struct kvm_device_attr を使用しますが、VM全体の設定と制御を対象としています。

仮想マシンごとのグループと属性（存在する場合）は、アーキテクチャに依存します。

1. グループ: KVM_S390_VM_MEM_CTRL¶

アーキテクチャ

s390

1.1. 属性: KVM_S390_VM_MEM_ENABLE_CMMA¶

パラメータ

none

を渡します。

vcpu がすでに定義されている場合は -EBUSY、それ以外は 0 を返します

仮想マシンに協調メモリ管理支援 (CMMA) を有効化します。

1.2. 属性: KVM_S390_VM_MEM_CLR_CMMA¶

パラメータ

none

を渡します。

CMMA が有効でない場合は -EINVAL、それ以外は 0 を返します

すべてのゲストページの CMMA 状態をクリアします。これにより、ゲストが未使用としてマークしたページが再び使用可能となり、ホストによって回収されない可能性があります。

1.3. 属性 KVM_S390_VM_MEM_LIMIT_SIZE¶

パラメータ

attr->addr に新しいゲストメモリの制限アドレスを指定します

を渡します。

指定されたアドレスがアクセス不可の場合は -EFAULT、仮想マシンが UCONTROL 型の場合は -EINVAL、指定されたゲストメモリがマシンに適合しない場合は -E2BIG、vcpu がすでに定義されている場合は -EBUSY、新しいシャドウゲストマッピングに十分なメモリが不足している場合は -ENOMEM、それ以外は 0 を返します。

ユーザー空間がゲストメモリの最大サイズの実際の制限を照会し、新しい制限を設定できるようにします。この制限はページテーブルレベルの数によって制御されるため、2048 MB、4096 GB、8192 TB に四捨五入されます。制限が設定されていない場合は、KVM_S390_NO_MEM_LIMIT (U64_MAX) に設定します。

2. グループ: KVM_S390_VM_CPU_MODEL¶

アーキテクチャ

s390

2.1. 属性: KVM_S390_VM_CPU_MACHINE (読み取り専用)¶

ユーザー空間がマシンおよび KVM 特有の CPU 関連情報を取得できるようにします:

struct kvm_s390_vm_cpu_machine {
     __u64 cpuid;           # CPUID of host
     __u32 ibc;             # IBC level range offered by host
     __u8  pad[4];
     __u64 fac_mask[256];   # set of cpu facilities enabled by KVM
     __u64 fac_list[256];   # set of cpu facilities offered by host
}
パラメータ

マシン関連の CPU データを格納するバッファのアドレス（struct kvm_s390_vm_cpu_machine* 型）

を渡します。

指定されたアドレスがカーネル空間からアクセスできない場合は -EFAULT、ioctl の処理に十分なメモリが不足している場合は -ENOMEM、成功した場合は 0 を返します。

2.2. 属性: KVM_S390_VM_CPU_PROCESSOR (読み書き可能)¶

ユーザー空間が vcpu に関する CPU 関連情報を取得または変更できるようにします:

struct kvm_s390_vm_cpu_processor {
     __u64 cpuid;           # CPUID currently (to be) used by this vcpu
     __u16 ibc;             # IBC level currently (to be) used by this vcpu
     __u8  pad[6];
     __u64 fac_list[256];   # set of cpu facilities currently (to be) used
                            # by this vcpu
}

KVM は CPU モデルデータの形式で制限や強制を課していません。KVM_S390_VM_CPU_MACHINE で取得した情報を合理的な設定のヒントとして利用してください。KVM で処理されていない追加のファシリティビットによってトリガーされる指令のインターセプトは、VM ドライバコード内で実装する必要があります。

パラメータ

プロセッサ関連の CPU データを格納/設定するバッファのアドレス（struct kvm_s390_vm_cpu_processor* 型）

を渡します。

1つ以上のvcpuがすでにアクティブになっている場合(-EBUSY)。これは書き込み操作の場合にのみ適用されます。指定されたアドレスがカーネル空間からアクセスできない場合(-EFAULT)。ioctl処理に十分なメモリが不足している場合(-ENOMEM)。成功した場合(0)。

2.3. 属性: KVM_S390_VM_CPU_MACHINE_FEAT (読み取り専用)¶

ユーザー空間が利用可能なCPU機能を取得できるようにします。機能がハードウェアによって提供され、KVMがサポートしている場合にのみ利用可能です。理論上、CPU機能はKVMによって完全にエミュレートされる可能性もあります。

struct kvm_s390_vm_cpu_feat {
      __u64 feat[16]; # Bitmap (1 = feature available), MSB 0 bit numbering
};
パラメータ

機能リストをロードするためのバッファのアドレス。

を渡します。

指定されたアドレスがカーネル空間からアクセスできない場合(-EFAULT)。成功した場合(0)。

2.4. 属性: KVM_S390_VM_CPU_PROCESSOR_FEAT (読み取り/書き込み)¶

ユーザー空間がVM内のすべてのVCPUsの有効なCPU機能を取得または変更できるようにします。利用不可能な機能は有効化できません。

参照 2.3. 属性: KVM_S390_VM_CPU_MACHINE_FEAT (読み取り専用) パラメータ構造体の説明については。

パラメータ

機能リストを読み込むためのバッファのアドレス。

を渡します。

指定されたアドレスがカーネル空間からアクセスできない場合(-EFAULT)。利用不可能なCPU機能を有効化しようとした場合(-EINVAL)。少なくとも1つのVCPUがすでに定義されている場合(-EBUSY)。成功した場合(0)。

2.5. 属性: KVM_S390_VM_CPU_MACHINE_SUBFUNC (読み取り専用)¶

ユーザー空間がセットIBCによるフィルタリングなしで利用可能なCPUサブファンクションを取得できるようにします。これらのサブファンクションは、ゲストVCPUsにクエリまたは「テストビット」サブファンクションを通じて示され、cpacf関数、plo、ptffなどに使用されます。

サブファンクションブロックは、KVM_S390_VM_CPU_MACHINEにSTFL(E)ビットが含まれている場合にのみ有効です。影響を受ける命令が「クエリサブファンクション」を通じてサブファンクションを示す場合、応答ブロックは返された構造体に含まれます。影響を受ける命令が「テストビット」メカニズムを通じてサブファンクションを示す場合、サブファンクションコードは返された構造体のMSB 0ビット番号で含まれます。

struct kvm_s390_vm_cpu_subfunc {
     u8 plo[32];           # always valid (ESA/390 feature)
     u8 ptff[16];          # valid with TOD-clock steering
     u8 kmac[16];          # valid with Message-Security-Assist
     u8 kmc[16];           # valid with Message-Security-Assist
     u8 km[16];            # valid with Message-Security-Assist
     u8 kimd[16];          # valid with Message-Security-Assist
     u8 klmd[16];          # valid with Message-Security-Assist
     u8 pckmo[16];         # valid with Message-Security-Assist-Extension 3
     u8 kmctr[16];         # valid with Message-Security-Assist-Extension 4
     u8 kmf[16];           # valid with Message-Security-Assist-Extension 4
     u8 kmo[16];           # valid with Message-Security-Assist-Extension 4
     u8 pcc[16];           # valid with Message-Security-Assist-Extension 4
     u8 ppno[16];          # valid with Message-Security-Assist-Extension 5
     u8 kma[16];           # valid with Message-Security-Assist-Extension 8
     u8 kdsa[16];          # valid with Message-Security-Assist-Extension 9
     u8 reserved[1792];    # reserved for future instructions
};
パラメータ

サブファンクションブロックをロードするためのバッファのアドレス。

を渡します。

指定されたアドレスがカーネル空間からアクセスできない場合(-EFAULT)。成功した場合(0)。

2.6. 属性: KVM_S390_VM_CPU_PROCESSOR_SUBFUNC (読み取り/書き込み)¶

ユーザー空間がVM内のすべてのVCPUsに示されるCPUサブファンクションを取得または変更できるようにします。この属性は、カーネルとハードウェアのサポートが存在する場合にのみ利用可能です。

カーネルは設定されたサブファンクションブロックを使用してゲストに示します。サブファンクションブロックは、関連するSTFL(E)ビットがユーザー空間によって無効化されていない場合（つまり、クエリされる命令がゲストにとって実際に利用可能である場合）にのみ使用されます。

データが書き込まれていない限り、読み込みは失敗します。この場合、IBCが利用されてサブ機能の利用可能な項目を判定し、後方互換性を保証します。

参照 2.5. 属性: KVM_S390_VM_CPU_MACHINE_SUBFUNC (読み取り専用) パラメータ構造体の説明については。

パラメータ

サブ機能ブロックを読み込み/書き込みするバッファのアドレス。

を渡します。

-EFAULTが指定されたアドレスがカーネル空間からアクセス不可の場合、-EINVALが読み込み時にまだ書き込みが行われていない場合、-EBUSYが少なくとも1つのVCPUがすでに定義されている場合、成功時は0を返します。
