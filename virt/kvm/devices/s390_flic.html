FLIC (浮動割込み制御装置)¶

FLIC は浮動（非CPUごとの）割り込み、つまりI/O、サービスおよび一部のマシンチェック割り込みを処理します。すべての割り込みは、仮想マシンごとの待機中の割り込みリストに保存され、FLIC はこのリストに対して操作を行います。

FLIC インスタンスは1つだけ生成できます。

FLIC は以下の操作をサポートします - 割り込みを追加 (KVM_DEV_FLIC_ENQUEUE) - 現在の待機中の割り込みを確認 (KVM_FLIC_GET_ALL_IRQS) - すべての待機中の浮動割り込みを削除 (KVM_DEV_FLIC_CLEAR_IRQS) - 1つの待機中の浮動I/O割り込みを削除 (KVM_DEV_FLIC_CLEAR_IO_IRQ) - ゲストに対する透過的非同期ページフォールトの有効/無効 - アダプタ割り込みソースの登録および変更 (KVM_DEV_FLIC_ADAPTER_*) - AIS (アダプタ割り込み抑制) モードの状態を変更 (KVM_DEV_FLIC_AISM) - 指定されたアダプタにアダプタ割り込みを注入 (KVM_DEV_FLIC_AIRQ_INJECT) - すべての AIS モード状態を取得/設定 (KVM_DEV_FLIC_AISM_ALL)

グループ:
KVM_DEV_FLIC_ENQUEUE

ユーザー空間からカーネルにバッファと長さを渡し、これを待機中の割り込みリストに注入します。attr->addr にはバッファへのポインタ、attr->attr にはバッファの長さが含まれます。データ構造 kvm_s390_irq のフォーマットは、usr/include/linux/kvm.h に定義されています。

KVM_DEV_FLIC_GET_ALL_IRQS

ユーザー空間で提供されたバッファにすべての浮動割り込みをコピーします。バッファが小さすぎる場合、-ENOMEM を返します。これはユーザー空間がより大きなバッファで再試行するサインです。

-ENOBUFS はカーネル空間バッファの割り当てに失敗した場合に返されます。

-EFAULT はユーザー空間へのデータコピーに失敗した場合に返されます。すべての割り込みは待機状態のまま、つまり待機中の割り込みリストから削除されません。attr->addr にはすべての割り込みデータをコピーするユーザー空間バッファのアドレスが含まれ、attr->attr にはバッファのバイト数が含まれます。

KVM_DEV_FLIC_CLEAR_IRQS

現在待機中の浮動割り込みリストのすべての要素を削除します。ゲストに割り込みが注入されません。

KVM_DEV_FLIC_CLEAR_IO_IRQ

指定されたバッファ（attr->addr および attr->attr で指定）に渡されたサブチャンネルのサブシステム識別語によって特定されるI/O割り込みを1つ（存在すれば）削除します。

KVM_DEV_FLIC_APF_ENABLE

ゲストに対して非同期ページフォールトを有効化します。これにより、重大なページフォールトが発生した場合でもホストがこれを処理し、ゲストの実行を継続できます。

KVM_DEV_FLIC_APF_DISABLE_WAIT

ゲストに対して非同期ページフォールトを無効にして、既に待機中の非同期ページフォールトが完了するのを待つ。これは、割込みリストを移行する前に、すべての初期化割込みに対して完了割込みをトリガーする必要があるためです。

KVM_DEV_FLIC_ADAPTER_REGISTER

I/Oアダプタ割込みソースを登録します。登録するアダプタを記述するkvm_s390_io_adapterを指定します:

struct kvm_s390_io_adapter {
        __u32 id;
        __u8 isc;
        __u8 maskable;
        __u8 swap;
        __u8 flags;
};

idはアダプタの一意なID、iscは使用するI/O中断サブクラス、maskableはこのアダプタがマスク可能（割込みが無効化可能）かどうか、swapはインジケーターにバイトスワップが必要かどうか、flagsはアダプタの追加的な特徴を表します。

現在定義されている'flags'の値は以下の通りです:

  • KVM_S390_ADAPTER_SUPPRESSIBLE: このアダプタはAIS（アダプタ割込み抑制）機能の対象です。このフラグはAIS機能が有効になっている場合にのみ効果を持ちます。

未知のフラグ値は無視されます。

KVM_DEV_FLIC_ADAPTER_MODIFY

既存のI/Oアダプタ割込みソースの属性を変更します。変更するアダプタと操作を指定するkvm_s390_io_adapter_reqを指定します:

struct kvm_s390_io_adapter_req {
        __u32 id;
        __u8 type;
        __u8 mask;
        __u16 pad0;
        __u64 addr;
};

idはアダプタを指定し、typeは操作の種類です。サポートされている操作は以下の通りです:

KVM_S390_IO_ADAPTER_MASK

maskパラメータで指定されたようにアダプタをマスク（無効化）またはアンマスク（有効化）します。

KVM_S390_IO_ADAPTER_MAP

これは現在無効です。マッピングはIRQルートによってのみ行われます。

KVM_S390_IO_ADAPTER_UNMAP

これは現在無効です。マッピングはIRQルートによってのみ行われます。

KVM_DEV_FLIC_AISM

AIS機能が有効な場合、指定されたiscに対してアダプタ割込み抑制モードを変更します。kvm_s390_ais_reqで以下を記述します:

struct kvm_s390_ais_req {
        __u8 isc;
        __u16 mode;
};

iscは対象のI/O中断サブクラス、modeは対象のアダプタ割込み抑制モードです。現在サポートされているモードは以下の通りです:

  • KVM_S390_AIS_MODE_ALL: すべての割込みモード、つまりairqのインジェクションは常に許可されます;

  • KVM_S390_AIS_MODE_SINGLE: 単一割込みモード、つまりairqのインジェクションは一度だけ許可され、その後のアダプタ割込みはモードがすべての割込みモードまたは単一割込みモードに戻るまで抑制されます。

KVM_DEV_FLIC_AIRQ_INJECT

指定されたアダプタにアダプタ割込みをインジェクションします。attr->attrはアダプタの一意なIDを含み、アダプタ固有のチェックや操作を可能にします。AIS対象のアダプタでは、AIS機能が有効な条件で、指定されたiscのairqインジェクション抑制をアダプタ割込み抑制モードに応じて処理します。

KVM_DEV_FLIC_AISM_ALL

すべてのISCsのアダプタ割込み抑制モードを取得または設定します。kvm_s390_ais_allで以下を記述します:

struct kvm_s390_ais_all {
       __u8 simm; /* Single-Interruption-Mode mask */
       __u8 nimm; /* No-Interruption-Mode mask *
};

simmはすべてのISCに対するシングル割込みモードのマスクを、nimmはすべてのISCに対するノーアイテラプションモードのマスクを表します。simmとnimmの各ビットは、ISC（MSB0ビット0はISC 0に対応など）に対応しており、simmビットとnimmビットの組み合わせはISCのAISモードを示します。

KVM_DEV_FLIC_AISM_ALLはKVM_CAP_S390_AIS_MIGRATIONによって示されます。

注意：FLICで未登録のグループまたは属性に対してKVM_SET_DEVICE_ATTR/KVM_GET_DEVICE_ATTRデバイスioctlを実行すると、APIドキュメンテーションで指定されているENXIOではなくエラーコードEINVALが返されます。使用試行によって生じるエラーコードからFLIC操作が利用不可であることを結論付けることはできません。

注意

KVM_DEV_FLIC_CLEAR_IO_IRQ ioctlはゼロのschidが指定された場合、EINVALを返します。
