汎用vcpuインターフェース¶

仮想CPU「デバイス」は、KVM_SET_DEVICE_ATTR、KVM_GET_DEVICE_ATTR、および KVM_HAS_DEVICE_ATTR という ioctls も受け入れます。このインターフェースは他のデバイスと同じ struct kvm_device_attr を使用しますが、VCPU全体の設定と制御を対象としています。

仮想CPUごとのグループおよび属性（存在する場合）は、アーキテクチャに依存します。

1. グループ: KVM_ARM_VCPU_PMU_V3_CTRL¶

アーキテクチャ

ARM64

1.1 属性: KVM_ARM_VCPU_PMU_V3_IRQ¶

パラメータ

kvm_device_attr.addr における PMU オーバーフロー割込みのアドレスは、int へのポインタです

戻り値:

-EBUSY

PMU オーバーフロー割込みはすでに設定されています

-EFAULT

割込み番号の読み込みエラー

-ENXIO

PMUv3 がサポートされていないか、またはオーバーフロー割込みが設定されていない状態で取得を試行しています

-ENODEV

VCPU に KVM_ARM_VCPU_PMU_V3 フィーチャーが不足しています

-EINVAL

無効な PMU オーバーフロー割込み番号が提供されたか、カーネル内IRQチップを使用せずにIRQ番号を設定しようとしています

この vcpu の PMUv3（パフォーマンスモニターユニット v3）オーバーフロー割込み番号を記述する値です。この割込みは PPI または SPI である可能性がありますが、各 vcpu で割込みの種類は同じでなければなりません。PPI として使用する場合、すべての vcpus で割込み番号は同じです。SPI として使用する場合、各 vcpu ごとに別個の番号を指定する必要があります。

1.2 属性: KVM_ARM_VCPU_PMU_V3_INIT¶

パラメータ

kvm_device_attr.addr には追加のパラメータがありません

戻り値:

-EEXIST

割込み番号がすでに使用されています

-ENODEV

PMUv3 がサポートされていないか、GIC が初期化されていません

-ENXIO

PMUv3 がサポートされていない、VCPU フィーチャーが不足しているか、割込み番号が設定されていない

-EBUSY

PMUv3 はすでに初期化されています

PMUv3 の初期化を要求します。PMUv3 をカーネル内仮想 GIC 実装と併用する場合、この初期化はカーネル内IRQチップを初期化した後に実行する必要があります。

1.3 属性: KVM_ARM_VCPU_PMU_V3_FILTER¶

パラメータ

kvm_device_attr.addr における PMU イベントフィルタのアドレスは、struct kvm_pmu_event_filter へのポインタです

を渡します。

-ENODEV

PMUv3 がサポートされていないか、GIC が初期化されていません

-ENXIO

PMUv3 が正しく構成されていないか、カーネル内IRQチップが必要な設定で初期化されていない状態でこの属性を呼び出しています

-EBUSY

PMUv3 はすでに初期化されています

-EINVAL

無効なフィルタ範囲

以下の通り PMU イベントフィルタのインストールを要求します:

struct kvm_pmu_event_filter {
        __u16       base_event;
        __u16       nevents;

#define KVM_PMU_EVENT_ALLOW 0
#define KVM_PMU_EVENT_DENY  1

        __u8        action;
        __u8        pad[3];
};

フィルタ範囲とは [@base_event, @base_event + @nevents) の範囲に加え、@action（KVM_PMU_EVENT_ALLOW または KVM_PMU_EVENT_DENY）を指定したものです。最初に登録された範囲がグローバルポリシーを定義します（最初の @action が DENY の場合はグローバル ALLOW、最初の @action が ALLOW の場合はグローバル DENY）。複数の範囲を設定できますが、PMU アーキテクチャで定義されるイベント空間内に収める必要があります（ARMv8.0 では 10 ビット、ARMv8.1 以降では 16 ビット）。

注意: 同じ範囲に対して逆のアクションを登録してフィルタをキャンセルしても、デフォルトのアクションは変更されません。たとえば、イベント範囲[0:10)に対して最初にALLOWフィルタをインストールし、その後同じ範囲に対してDENYアクションを適用しても、全体の範囲は無効のままになります。

制限事項: イベント0 (SW_INCR)はハードウェアイベントとしてカウントされないため、常にフィルタされません。また、イベント0x1E (CHAIN)は厳密にはイベントとは言えないため、フィルタの効果はありません。サイクルカウンタのフィルタはイベント0x11 (CPU_CYCLES)を使用して可能です。

2. グループ: KVM_ARM_VCPU_TIMER_CTRL¶

アーキテクチャ

ARM, ARM64

2.1. 属性: KVM_ARM_VCPU_TIMER_IRQ_VTIMER, KVM_ARM_VCPU_TIMER_IRQ_PTIMER¶

パラメータ

kvm_device_attr.addrのアドレスはタイマーアイテントerruptのポインタを指します

戻り値:

-EINVAL

無効なタイマーアイテントerrupt番号

-EBUSY

1つ以上の仮想CPUがすでに実行されています

内核仮想GICに接続した場合のアーキテクチャタイマーアイテントerrupt番号を記述する値です。これらはPPI（16 <= intid < 32）でなければなりません。属性の設定はデフォルト値を上書きします（以下を参照）。

KVM_ARM_VCPU_TIMER_IRQ_VTIMER

EL1仮想タイマーアイテントerrupt番号（デフォルト: 27）

KVM_ARM_VCPU_TIMER_IRQ_PTIMER

EL1物理タイマーアイテントerrupt番号（デフォルト: 30）

異なるタイマーに同じPPIを設定すると仮想CPUの実行が妨げられます。タイマーごとの中断番号を仮想CPUに設定すると、その時点で作成されたすべての仮想CPUが指定された番号を使用します。ユーザー空間では、すべての仮想CPUを作成した後で少なくとも1つの仮想CPUに中断番号を設定し、それらを実行する前に設定を行う必要があります。

3. グループ: KVM_ARM_VCPU_PVTIME_CTRL¶

アーキテクチャ

ARM64

3.1 属性: KVM_ARM_VCPU_PVTIME_IPA¶

パラメータ

64ビットベースアドレス

戻り値:

-ENXIO

ステロイド時間の実装未完了

-EEXIST

この仮想CPUに対してベースアドレスがすでに設定されています

-EINVAL

ベースアドレスが64バイトアライメントされていません

この仮想CPUのステロイド時間構造体のベースアドレスを指定します。ベースアドレスは64バイトアライメントされていなければならず、有効なゲストメモリ領域内に存在する必要があります。詳しくは arm64向けパラバーチャライズド時間サポート ステロイド時間構造体のレイアウトを含む情報にアクセスしてください。
