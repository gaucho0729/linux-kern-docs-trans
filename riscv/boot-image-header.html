以下の64バイトのヘッダーは、展開後のLinuxカーネルイメージに存在します：

u32 code0;                /* Executable code */
u32 code1;                /* Executable code */
u64 text_offset;          /* Image load offset, little endian */
u64 image_size;           /* Effective Image size, little endian */
u64 flags;                /* kernel flags, little endian */
u32 version;              /* Version of this header */
u32 res1 = 0;             /* Reserved */
u64 res2 = 0;             /* Reserved */
u64 magic = 0x5643534952; /* Magic number, little endian, "RISCV" */
u32 magic2 = 0x05435352;  /* Magic number 2, little endian, "RSC\x05" */
u32 res3;                 /* Reserved for PE COFF offset */

このヘッダー形式はPE/COFFヘッダーに準拠しており、ARM64ヘッダーから largely インスピレーションを受けたものです。したがって、今後ARM64とRISC-Vのヘッダーを1つの共通ヘッダーに統合することが可能です。

備考¶

  • このヘッダーは今後RISC-V用EFIスタブのサポートにも再利用可能です。EFI仕様では、カーネルイメージの先頭にPE/COFFヘッダーが必要であり、それをEFIアプリケーションとしてロードするためのものです。EFIスタブをサポートするためには、code0を「MZ」マジック文字列に置き換え、res3（オフセット0x3c）をPE/COFFヘッダーの残り部分にポインタを指す必要があります。

  • バージョンフィールドはヘッダーのバージョン番号を示します

    ビット0:15

    マイナーバージョン

    ビット16:31

    メジャーバージョン

    これにより、新しいバージョンと古いバージョンのヘッダー間での互換性が維持されます。現在のバージョンは0.2として定義されています。

  • 「magic」フィールドはバージョン0.2から非推奨となりました。今後のリリースでは削除される可能性があります。これは元々ARM64ヘッダーの「magic」フィールドと一致すべきでしたが、残念ながら一致していません。代わりに「magic2」フィールドが使用され、ARM64ヘッダーと一致しています。

  • 現在のヘッダーでは、フラグフィールドは1つのフィールドのみを持っています。

    ビット0

    カーネルのエンディアン。BEの場合は1、LEの場合は0。

  • ブートローダーがカーネルイメージをロードするためにイメージサイズは必須です。イメージサイズがなければブートは失敗します。
