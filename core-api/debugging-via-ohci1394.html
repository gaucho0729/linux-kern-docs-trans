OHCI-1394 FireWireコントローラーが提供する物理DMAを用いたデバッグ¶

はじめに¶

現在使用されているほぼすべてのFireWireコントローラーはOHCI-1394仕様に準拠しており、この仕様ではコントローラーをPCIバスマスターとして定義し、CPUからデータ転送をオフロードするDMAを用い、OHCI-1394ドライバで定義されたフィルタを適用した後にPCIバスマスターDMAを実行する「Physical Response Unit」を備えている。

適切に設定された場合、リモートマシンはOHCI-1394コントローラーに読み込み・書き込みリクエストを実行させ、読み込みリクエストでは物理メモリの読み込み結果をリクエスターに返すことができる。

これにより、printkバッファやプロセステーブルなどの興味深いメモリ位置を読み込むことで、デバッグが可能となる。

FireWireを介してシステム全体のメモリダンプを取得することも可能で、データ転送速度は10MB/s以上となる。

ほとんどのFireWireコントローラーでは、物理アドレス空間の低4GBにメモリアクセスが制限される。これはIA64マシンではメモリがこの制限を超えて配置されるため問題となるが、x86、x86-64、PowerPCなどの一般的なハードウェアではほとんど問題にならない。

LSI FW643eおよびFW643e2コントローラーは物理アドレス4GB以上へのアクセスをサポートしているが、この機能は現在Linuxで有効化されていない。

OHCI-1394コントローラーの早期初期化と併せて、ACPIなどの領域でのシステム起動失敗時の早期ブート問題のデバッグにprintkバッファ内の長いデバッグログを確認するのに非常に有用である。シリアルポートなどの他のデバッグ手段が利用不可（ノートPC）または遅すぎて大量のデバッグ情報に不向き（ACPIなど）な場合でも有効である。

ドライバ¶

drivers/firewireに配置されているfirewire-ohciドライバはデフォルトでフィルタされた物理DMAを用いるが、これはセキュアだがリモートデバッグには不向きである。リモートDMAを有効にするにはドライバにremote_dma=1パラメータを渡す。

firewire-ohciドライバはPCIエナメーションの完了に依存しているため、x86ではコンソール初期化が呼ばれる前、つまりprintkバッファがコンソールに表示される前にも実行される初期化ルーチンが実装されている。

これを有効にするには、CONFIG_PROVIDE_OHCI1394_DMA_INIT（カーネルハッキングメニュー: ファイアワイヤーによる早期ブート時のリモートデバッグ）を有効にして、再コンパイルしたカーネルをブート時に「ohci1394_dma=early」というパラメータを渡して起動してください。

ツール¶

firescope - これはBenjamin Herrenschmidtによって最初に開発され、Andi KleenがPowerPCからx86およびx83_64に移植し、機能を追加したツールです。現在、firescopeはリモートマシンのprintkバッファを表示でき、ライブアップデートにも対応しています。

Bernhard Kaindlはfirescopeを拡張し、32ビットのfirescopeから64ビットマシンへのアクセスをサポートし、逆も可能にしました： http://v3.sk/~lkundrak/firescope/

また、彼は高速システムダンプ（アルファ版 - README.txtを参照）を実装しました： http://halobates.de/firewire/firedump-0.1.tar.bz2

さらに、ファイアワイヤー用のgdbプロキシがあり、gdbを用いてvmlinuxから見つかったシンボルで参照可能なデータにアクセスできます： http://halobates.de/firewire/fireproxy-0.33.tar.bz2

このgdbプロキシの最新バージョン（fireproxy-0.34）は、メモリベースの通信モジュール（kgdbom）を介してkgdbと通信できます（現時点では安定していません）。

はじめに¶

OHCI-1394仕様では、OHCI-1394コントローラーが各バスリセット時にすべての物理DMAを無効にする必要があります。

これは、割り込みが無効になっているシステム状態でデバッグを行う場合、またはOHCI-1394コントローラーのバスリセットを確認するポーリングが行われない状態でデバッグを行う場合、システムがその状態に入る前に、ファイアワイヤーケーブル接続を確立し、すべてのファイアワイヤーハードウェアを完全に初期化する必要があります。

早期OHCI初期化を用いたfirescopeの使用手順：

  1. ハードウェアがサポートされているか確認してください：

    firewire-ohciモジュールをロードし、カーネルログを確認してください。以下のような行が表示されるはずです：

    firewire_ohci 0000:15:00.1: added OHCI v1.0 device as card 2, 4 IR + 4 IT
... contexts, quirks 0x11

    ドライバをロードする際。サポートされていないコントローラーを搭載している場合、多くのPCI、CardBus、さらにはOHCI-1394仕様に完全に準拠しているExpressカードが利用可能です。Windowsでドライバが不要な場合、その機器はサポートされている可能性が高いです。専門店でしか入手できない非準拠カードはTI PCILynxチップベースで、Windows専用ドライバを必要とします。

    上記のカーネルログメッセージには「physUB」という文字列が含まれています。これは、コントローラーが書き込み可能な物理上界レジスタを実装していることを示します。これは物理DMAを4GB以上で使用するための要件ですが、Linuxではまだ利用されていません。

  2. 動作するファイアワイヤーケーブル接続を確立してください：

    電気的および機械的に安定した接続を提供し、接続端子が一致する（小型の4ピンと大型の6ピンのファイアワイヤーポート）ファイアワイヤーケーブルであれば問題ありません。

    両マシンでドライバが動作している場合、以下のような行が表示されます：

    firewire_core 0000:15:00.1: created device fw1: GUID 00061b0020105917, S400

    ケーブルを挿して2台のマシンが接続されたときに、両方のマシンのカーネルログに表示されます。

  3. ファイアスコープを使用して物理DMAをテストする:

    デバッグホストで/dev/fw*がアクセス可能であることを確認し、次にファイアスコープを起動する:

        $ firescope
    Port 0 (/dev/fw1) opened, 2 nodes detected

    FireScope
    ---------
    Target : <unspecified>
    Gen    : 1
    [Ctrl-T] choose target
    [Ctrl-H] this menu
    [Ctrl-Q] quit

------> Press Ctrl-T now, the output should be similar to:

    2 nodes available, local node is: 0
     0: ffc0, uuid: 00000000 00000000 [LOCAL]
     1: ffc1, uuid: 00279000 ba4bb801

    [LOCAL]ノード以外のノードを表示し、エラー メッセージが表示されないことを確認する必要があります。

  4. 早期OHCI-1394初期化でのデバッグ準備:

    4.1) デバッグ対象マシンでのカーネルのコンパイルとインストール

    デバッグ用のカーネルをコンパイルし、CONFIG_PROVIDE_OHCI1394_DMA_INIT (カーネルのハッキング: ファイアワイヤーでのDMAを起動するためのコードを提供) を有効にして、デバッグ対象マシンにインストールする。

    4.2) デバッグ対象カーネルのSystem.mapをデバッグホストに転送する

    デバッグ対象カーネルのSystem.mapをデバッグホストにコピーする (ファイアワイヤーケーブルで接続されたデバッグ対象マシンに接続したホスト)

  5. printkバッファの内容を取得する:

    ファイアワイヤーケーブルを接続し、デバッグホストのOHCI-1394ドライバーをロードした後、デバッグ対象マシンを再起動し、CONFIG_PROVIDE_OHCI1394_DMA_INITが有効なカーネルで起動し、ohci1394_dma=earlyオプションを指定して起動する。

    その後、デバッグホストでファイアスコープを実行する、たとえば-Aオプションを使用する:

    firescope -A System.map-of-debug-target-kernel

    注意: -Aは最初の非ローカルノードに自動的に接続します。これはファイアワイヤーで2台のマシンのみが接続されている場合にのみ信頼性があります。

    デバッグ対象マシンに接続した後、Ctrl-Dを押して完全なprintkバッファを表示するか、Ctrl-Uを押して自動更新モードに入り、デバッグ対象マシンで最近ログされたカーネルメッセージのリアルタイム表示を取得する。

    firescope -hを実行して、オプションの詳細情報を取得する。
