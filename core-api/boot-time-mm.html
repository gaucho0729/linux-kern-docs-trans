ブート時のメモリ管理¶

早期システム初期化では「通常」のメモリ管理を使用できないのは、まだ設定されていないからです。ただし、さまざまなデータ構造のメモリ割り当てが必要なため、例えば物理ページアロケータなどにメモリを確保する必要があります。

専用のアロケータとして呼ばれる memblock がブート時のメモリ管理を行います。アーキテクチャ固有の初期化では、これをの初期化に設定し、の終了時に破棄する必要があります。 setup_arch() の初期化に設定し、の終了時に破棄する必要があります。 mem_init() 関数の終わりを注釈する必要があります。

早期メモリ管理が利用可能になると、メモリ割り当て用のさまざまな関数やマクロが提供されます。割り当て要求は、NUMAシステムでは最初の（おそらく唯一の）ノードまたは特定のノードに指定できます。割り当て失敗時にpanicするAPI変体と、そうでない変体があります。

Memblockは自身の挙動を制御するためのさまざまなAPIも提供しています。

Memblock 概要¶

Memblockは、通常のカーネルメモリアロケータが動作していない早期ブート期間におけるメモリ領域の管理方法です。

Memblockはシステムメモリを連続領域のコレクションとして扱います。このようなコレクションの種類はいくつかあります：

  • memory - カーネルに利用可能な物理メモリを記述します。これはシステムにインストールされた実際の物理メモリと異なる場合があります（例：コマンドラインパラメータでメモリ制限をかけた場合） mem= コマンドラインパラメータ

  • reserved - 割り当てられた領域を記述します

  • physmem - ブート時の実際の物理メモリを記述します。これはメモリ制限やホットプラグ/ホットアンプラグに関係なく、ブート時の実際の物理メモリを示します。この「physmem」タイプは一部のアーキテクチャでのみ利用可能です。 physmem タイプ

各領域は struct memblock_region で表され、これは領域の範囲、属性、NUMAシステムでのNUMAノードIDを定義します。すべてのメモリタイプは struct memblock_type で記述され、これはメモリ領域の配列とアロケータメタデータを含みます。『memory』および『reserved』タイプは、がこれらをラップしています。 struct memblockこの構造体はビルド時に静的に初期化されます。領域配列は初期サイズとして『memory』用に『reserved』用に『physmem』用に『』が設定されます。 INIT_MEMBLOCK_REGIONS 『memory』用に『』 INIT_MEMBLOCK_RESERVED_REGIONS 『reserved』用に『』 INIT_PHYSMEM_REGIONS『physmem』用に『』

早期アーキテクチャの設定では、memblockに物理メモリレイアウトを伝えるために memblock_add() または memblock_add_node() 関数です。最初の関数は、リージョンをNUMAノードに割り当てません。UMAシステムに適しています。ただし、NUMAシステムでも使用可能で、設定プロセスの後半でリージョンをNUMAノードに割り当てることができます。 memblock_set_node()の部分で、 memblock_add_node() この関数は、直接その割り当てを行います。

memblockが設定されると、メモリは以下のAPI変体のいずれかを使用して割り当てることができます：

  • memblock_phys_alloc*() - これらの関数は、 物理 割り当てられたメモリのアドレスを返します

  • memblock_alloc*() - これらの関数は、 仮想 割り当てられたメモリのアドレスを返します。

両方のAPI変体は、許可されたメモリ範囲に関する暗黙の仮定とフォールバックメソッドを使用します。詳細な説明については、 memblock_alloc_internal() および memblock_alloc_range_nid() 関数のドキュメンテーションを参照してください。

システムの起動が進むにつれて、アーキテクチャ固有のmem_init()関数がすべてのメモリを buddy page allocator に解放します。

アーキテクチャがこれを有効にしない限り、 CONFIG_ARCH_KEEP_MEMBLOCKmemblockデータ構造（「physmem」を除く）はシステム初期化が完了後に破棄されます。

関数と構造体¶

ここに、memblockデータ構造、関数、マクロの説明があります。一部は内部的に使用されるものですが、ドキュメンテーションされているため省略するのは馬鹿げています。さらに、内部関数の説明を読むことで、裏側で実際に起きていることの理解が深まります。
