ISAおよびLPCデバイスでのDMA¶

著者

Pierre Ossman <drzeus@drzeus.cx>

このドキュメントでは、古いISA DMAコントローラーを使用したDMA転送の方法について説明します。ISAは現在ではほぼ使われていませんが、LPCバスは同じDMAシステムを使用しているため、しばらくは利用可能のままです。

ヘッダと依存関係¶

ISAスタイルのDMAを行うには、2つのヘッダをインクルードする必要があります：

#include <linux/dma-mapping.h>
#include <asm/dma.h>

最初のヘッダは、仮想アドレスをバスアドレスに変換するための汎用DMA APIです（参照： 汎用デバイスを使用した動的DMAマッピング を参照してください）。

2番目のヘッダにはISA DMA転送に特化した関数が含まれています。この機能はすべてのプラットフォームで利用できるわけではありませんので、Kconfigの構築時にISA_DMA_API（ISAではなく）に依存させるようにし、非対応プラットフォームでのドライバビルドを防ぎましょう。

バッファの割り当て¶

ISA DMAコントローラーは、アクセス可能なメモリに非常に厳しい制限があるため、バッファの割り当てには特別な注意が必要です。

(DMA転送には通常、通常のデータ構造ではなく、特別なバッファが必要です。)

DMA可能なアドレス空間は、物理メモリの最低16MBです。また、転送ブロックはページ境界を越えてはいけません（ページサイズは使用するチャネルによって64KiBまたは128KiBです）。

すべてのこれらの要件を満たすメモリを割り当てるには、kmallocにGFP_DMAフラグを渡します。

残念ながらISA DMA用のメモリは限られているため、ブートアップ時にメモリを割り当てない限り、__GFP_RETRY_MAYFAILと__GFP_NOWARNも渡して、アロケータが少し頑張って取得するようにしましょう。

(この希少性から、バッファはできるだけ早く割り当て、ドライバがアンロードされるまで解放しないのが望ましいです。)

アドレス変換¶

仮想アドレスをバスアドレスに変換するには、通常のDMA APIを使用してください。isa_virt_to_bus()は同じ動作をしますが、使用しないでください。理由は、isa_virt_to_bus()関数はISAへのKconfig依存を必要とし、実際にはISA_DMA_APIのみで十分なためです。記憶してください、DMAコントローラーはISAの起源を持つものの、他の場所でも使用されています。

注意：x86_64ではISA用DMA APIが以前は破損していましたが、それ以来修正されています。アーキテクチャに問題がある場合は、DMA APIを修正するのではなくISA関数に戻るのではなく、修正してください。

チャネル¶

通常のISA DMAコントローラーは8チャネルを持ち、下位4つは8ビット転送用、上位4つは16ビット転送用です。

実際にはDMAコントローラーは本当に2つの別々のコントローラーで、チャネル4は2番目のコントローラー（0-3）にDMAアクセスを提供します。これは、4つの16ビットチャネルのうち3つしか使用できません。

すべての基本リソースと同じようにこれらのリソースを割り当てます:

extern int request_dma(unsigned int dmanr, const char * device_id); extern void free_dma(unsigned int dmanr);

16ビットまたは8ビットの転送を使用できるかどうかは、ドライバ作成者ではなくハードウェアがサポートするかどうかに依存します。仕様を確認するか、さまざまなチャネルをテストしてください。

データの転送¶

実際にDMA転送を行う、いわゆる本番です。:)

ISA DMAルーチンを使用する前に、claim_dma_lock()を使用してDMAロックを取得する必要があります。これは、一部のDMA操作が非原子的であるため、一度に1つのドライバのみがレジスタを操作できるようにするためです。

DMAコントローラーを使用する最初のタイミングではclear_dma_ff()を呼び出してください。これはDMAコントローラー内の内部レジスタをクリアし、非原子的な操作に使用されます。ロック関数を使用する限り、あなた（および他の誰も）が一度だけリセットする必要があるだけです。

次に、set_dma_mode()を使用して転送の方向をコントローラーに指定します。現在はDMA_MODE_READとDMA_MODE_WRITEの2つのオプションがあります。

転送を開始するアドレス（16ビットアライメントが必要です）と転送するバイト数を設定します。注意点として、これは「バイト」です。DMAルーチンはDMAコントローラーが理解できる値にすべての変換を行います。

最終的なステップはDMAチャネルを有効化し、DMAロックを解放することです。

DMA転送が完了（またはタイムアウト）した後は、チャネルを再度無効化する必要があります。また、get_dma_residue()を確認してすべてのデータが転送されたことを確認してください。

例:

int flags, residue;

flags = claim_dma_lock();

clear_dma_ff();

set_dma_mode(channel, DMA_MODE_WRITE);
set_dma_addr(channel, phys_addr);
set_dma_count(channel, num_bytes);

dma_enable(channel);

release_dma_lock(flags);

while (!device_done());

flags = claim_dma_lock();

dma_disable(channel);

residue = dma_get_residue(channel);
if (residue != 0)
        printk(KERN_ERR "driver: Incomplete DMA transfer!"
                " %d bytes left!\n", residue);

release_dma_lock(flags);

スリープ/再開¶

ドライバはDMA転送が進行中にマシンがスリープしないようにする責任があります。また、システムがスリープするとすべてのDMA設定が失われます。ドライバがDMAコントローラーが特定の状態にあることを依存している場合、再開時にこれらのレジスタを復元する必要があります。
