はじめに¶

トレースポイントは、カーネル内の戦略的な場所に配置された静的なプローブポイントです。'プローブ'は、コールバックメカニズムを通じてトレースポイントに登録/解除されます。'プローブ'は、各トレースポイントが定義する一意のパラメータセットを引数として受け取る厳密に型付けされた関数です。

このシンプルなコールバックメカニズムにより、'プローブ'はカーネルの挙動をプロファイリング、デバッグ、理解するためのツールとして利用できます。'プローブ'を活用するためのフレームワークを提供するツールには、Systemtap、ftrace、LTTngがあります。

トレースポイントは、複数のヘッダーファイル内のマクロを通じて定義されます。したがって、このドキュメントの目的は、利用可能なトレースポイントを明確に記載することです。意図は、現在利用可能なトレースポイントだけでなく、今後追加される可能性のあるトレースポイントの場所を理解することです。

提示されるAPIには、次の形式の関数があります： trace_tracepointname(function parameters). これらは、コード全体にわたるトレースポイントのコールバックです。これらのコールバックサイトにプローブを登録および解除する方法については、 Documentation/trace/* directory.

void trace_signal_generate(int sig, struct kernel_siginfo *info, struct task_struct *task, int group, int 結果)¶

シグナルが生成されたときに呼ばれる

パラメータ

int sig

シグナル番号

struct kernel_siginfo *info

struct siginfoへのポインタ

struct task_struct *task

struct task_structへのポインタ

int group

共有またはプライベート

int result

TRACE_SIGNAL_*

説明

現在のプロセスが「task」プロセスに「sig」シグナルを送信し、「info」siginfoを用いる。もし「info」がSEND_SIG_NOINFOまたはSEND_SIG_PRIVの場合、「info」はポインタではなく、フィールドにアクセスできない。代わりに、SEND_SIG_NOINFOはsi_codeがSI_USERを意味し、SEND_SIG_PRIVはsi_codeがSI_KERNELを意味する。

void trace_signal_deliver(int sig, struct kernel_siginfo *info, struct k_sigaction *ka)¶

シグナルが送信されたときに呼ばれる

パラメータ

int sig

シグナル番号

struct kernel_siginfo *info

struct siginfoへのポインタ

struct k_sigaction *ka

struct k_sigactionへのポインタ

説明

現在のプロセスに「sig」シグナルが送信され、「info」siginfoで処理される。これは「ka」で処理される。「ka->sa.sa_handler」はSIG_IGNまたはSIG_DFLになる可能性がある。注意点として、signal_generateトレースポイントで報告される一部のシグナルは、このトレースポイントに到達する前に失われる、無視される、またはデバッガーによって変更される可能性がある。これは、実際に届いたシグナルを示すが、生成されたシグナルと届いたシグナルの一致は正確でない可能性がある。
