はじめに¶

ジェネリック割込みハンドリングレイヤーは、デバイスドライバが割込み処理を抽象化できるように設計されています。さまざまな割込みコントローラハードウェアのタイプを処理可能です。デバイスドライバはジェネリックAPI関数を使用して割込みをリクエスト、有効化、無効化、解放します。ドライバは割込みハードウェアの詳細について何も知る必要がなく、コード変更なしでさまざまなプラットフォームで使用可能です。

このドキュメンテーションは、ジェネリックIRQハンドリングレイヤーの支援を受けてアーキテクチャごとの割込みサブシステムを実装したい開発者向けに提供されています。

理由¶

Linuxにおける元の割込みハンドリング実装は、すべての割込み論理を処理可能な__do_IRQ()スーパーハンドラを使用していました。

当初、Russell KingはARM割込みハンドラ実装（Linux 2.5/2.6）のために、さまざまなハンドラタイプを識別し、比較的汎用的なセットを作成しました。彼は以下のように区別しました：

  • レベルタイプ

  • エッジタイプ

  • シンプルタイプ

実装中に別のタイプが識別されました：

  • ファストEOIタイプ

__do_IRQ()スーパーハンドラのSMP世界では別のタイプが識別されました：

  • パーセパーセルタイプ

高レベルIRQハンドラの分割実装により、各割込みタイプごとの処理フローを最適化できます。これにより特定のコードパスの複雑さが減らされ、特定のタイプの最適化処理が可能になります。

元の一般的IRQ実装はhw_interrupt_type構造体とその ->ack, ->end [etc.]コールバック関数を使用してスーパーハンドラ内のフローロジックを区別していました。これによりフローロジックと低レベルハードウェアロジックが混在し、不要なコードの複製が生じました：例えばi386では、低レベル詳細は似ていますがフローハンドリングが異なる ioapic_level_irq そして ioapic_edge_irq IRQタイプがあります。

より自然な抽象化は「割込みフロー」と「チップ詳細」の明確な分離です。

いくつかのアーキテクチャのIRQサブシステム実装を分析すると、ほとんどのアーキテクチャがジェネリックな「割込みフロー」メソッドを使用し、チップレベルの特定コードを追加するだけで十分であることがわかります。この分離は、チップ詳細には影響を与えず、割込みフロー自体に特定のクイックが必要な（サブ）アーキテクチャにも価値があり、より透明なIRQサブシステム設計を提供します。

各割込み記述子には、通常は汎用実装のいずれかが割り当てられる高レベルフローハンドラが割り当てられます。(この高レベルフローハンドラの実装により、さまざまなアーキテクチャの埋め込みプラットフォームで見られるデマルチプレクスハンドラの提供も簡単になります。)

この分離により、汎用割込み処理レイヤーはより柔軟で拡張性が高くなります。たとえば、(サブ)アーキテクチャは「レベル型」割込みに汎用IRQフロー実装を使用し、「エッジ型」割込みに(サブ)アーキテクチャ固有の実装を追加することができます。

既存の実装の破損を防ぎ、新しいモデルへの移行を容易にするため、__do_IRQ()スーパーハンドラは引き続き利用可能です。これにより、一時的に二重構造が存在します。時間とともに新しいモデルがより多くのアーキテクチャで使用されるようになり、これによりより小型で整ったIRQサブシステムが実現されます。この機能は3年前から非推奨になっており、現在は削除される予定です。

抽象レイヤー¶

割込みコードには3つの主な抽象レベルがあります：

  1. 高レベルドライバAPI

  2. 高レベルIRQフローハンドラ

  3. チップレベルハードウェアのカプセル化

割込み制御フロー¶

各割込みはirq_desc構造体で記述され、割込みは「unsigned int」の数値で参照され、この数値はディスクリプタ構造体配列内の対応する割込み記述子構造体を選択します。ディスクリプタ構造体にはステータス情報と、この割込みに割り当てられた割込みフローメソッドと割込みチップ構造体へのポインタが含まれています。

割込みがトリガーされた際、低レベルアーキテクチャコードはdesc->handle_irq()を呼び出して汎用割込みコードに呼び出します。この高レベルIRQ処理関数は、割り当てられたチップ記述子構造体で参照されるdesc->irq_data.chipのプリミティブのみを使用します。

割込みフローハンドラ(事前に定義されたか、アーキテクチャ固有のもの)は、アーキテクチャが起動時またはデバイス初期化時に特定の割込みに割り当てられます。

ヘルパー関数¶

補助関数はチッププリミティブを呼び出し、デフォルトフロー実装で使用されます。以下の補助関数が実装されています(簡略化された抜粋)：

default_enable(struct irq_data *data)
{
    desc->irq_data.chip->irq_unmask(data);
}

default_disable(struct irq_data *data)
{
    if (!delay_disable(data))
        desc->irq_data.chip->irq_mask(data);
}

default_ack(struct irq_data *data)
{
    chip->irq_ack(data);
}

default_mask_ack(struct irq_data *data)
{
    if (chip->irq_mask_ack) {
        chip->irq_mask_ack(data);
    } else {
        chip->irq_mask(data);
        chip->irq_ack(data);
    }
}

noop(struct irq_data *data))

デフォルトフローハンドラ実装¶

デフォルトレベルIRQフローハンドラ¶

handle_level_irqはレベルトリガー型割り込みのための汎用的な実装を提供します。

以下に示す制御フローが実装されています（簡略化された抜粋）：

desc->irq_data.chip->irq_mask_ack();
handle_irq_event(desc->action);
desc->irq_data.chip->irq_unmask();
デフォルトの高速EOI割り込みフローハンドラ¶

handle_fasteoi_irqは、ハンドラの終わりにEOIのみが必要な割り込みのための汎用的な実装を提供します。

以下に示す制御フローが実装されています（簡略化された抜粋）：

handle_irq_event(desc->action);
desc->irq_data.chip->irq_eoi();
デフォルトのエッジ割り込みフローハンドラ¶

handle_edge_irqはエッジトリガー型割り込みのための汎用的な実装を提供します。

以下に示す制御フローが実装されています（簡略化された抜粋）：

if (desc->status & running) {
    desc->irq_data.chip->irq_mask_ack();
    desc->status |= pending | masked;
    return;
}
desc->irq_data.chip->irq_ack();
desc->status |= running;
do {
    if (desc->status & masked)
        desc->irq_data.chip->irq_unmask();
    desc->status &= ~pending;
    handle_irq_event(desc->action);
} while (status & pending);
desc->status &= ~running;
デフォルトのシンプルな割り込みフローハンドラ¶

handle_simple_irqはシンプルな割り込みのための汎用的な実装を提供します。

注意

シンプルなフローハンドラは、ハンドラ/チップのプリミティブを呼び出しません。

以下に示す制御フローが実装されています（簡略化された抜粋）：

handle_irq_event(desc->action);
デフォルトのパーセルCPUフローハンドラ¶

handle_percpu_irqはパーセルCPU割り込みのための汎用的な実装を提供します。

パーセルCPU割り込みはSMPでのみ利用可能で、ハンドラはロックなしの簡略化されたバージョンを提供します。

以下に示す制御フローが実装されています（簡略化された抜粋）：

if (desc->irq_data.chip->irq_ack)
    desc->irq_data.chip->irq_ack();
handle_irq_event(desc->action);
if (desc->irq_data.chip->irq_eoi)
    desc->irq_data.chip->irq_eoi();
EOIエッジ割り込みフローハンドラ¶

handle_edge_eoi_irqは、powerpc/cellの壊れたIRQコントローラーを制御するために単独で使用されるエッジハンドラの変異形を提供します。

不良なIRQフローハンドラ¶

handle_bad_irqは、実際のハンドラが割り当てられていない偽の割り込みに使用されます。

クイックと最適化¶

汎用的な関数は、「クリーン」なアーキテクチャおよびチップ（プラットフォーム固有のIRQハンドリングクイックを持たないもの）のために設計されています。アーキテクチャが「フロー」レベルでクイックを実装する必要がある場合、ハイレベルのirq-flowハンドラをオーバーライドすることで実現できます。

遅延された割り込み無効化¶

この割り込みごとの選択可能な機能は、Russell KingがARM割り込み実装で導入したもので、ハードウェアレベルでの割り込みの無効化は行われません。 disable_irq() 呼び出される。割り込みは有効のまま維持され、割り込みイベントが発生した際にフローハンドラで無効化されます。これにより、ハードウェアが割り込みイベントを無効化されている間保存しない場合、エッジ割り込みが失われることを防ぎます。IRQ_DISABLEDフラグが設定されている間割り込みが到達した場合、ハードウェアレベルで割り込みが無効化され、IRQ_PENDINGビットが設定されます。割り込みが再有効化される際には、 enable_irq() 待機ビットが確認され、設定されている場合、ハードウェアまたはソフトウェアの再送メカニズムを介して割り込みが再送信されます。(遅延された割り込み無効化機能を使用したい場合、ハードウェアが割り込みを再トリガーできない場合は、CONFIG_HARDIRQS_SW_RESENDを有効にする必要があります。) 遅延された割り込み無効化は設定可能ではありません。

チップレベルハードウェアのカプセル化¶

チップレベルのハードウェア記述子構造体 irq_chip チップに関連するすべての直接的な関数を含み、irqフロー実装で利用できます。

  • irq_ack

  • irq_mask_ack - オプション、パフォーマンス向上のために推奨

  • irq_mask

  • irq_unmask

  • irq_eoi - オプション（EOIフローハンドラが必要）

  • irq_retrigger - オプション

  • irq_set_type - オプション

  • irq_set_wake - オプション

これらのプリミティブは、まさにその意味を厳密に意味するように設計されています。ACKはACK、IRQラインのマスキングはマスティングなどです。フローエンドハンドラがこれらの低レベル機能の基本単位を適切に使用する必要があります。

__do_IRQエントリポイント¶

元の実装__do_IRQ()は、すべての種類の割込みに対する代替エントリポイントでしたが、現在は存在しなくなりました。

このハンドラはすべての割込みハードウェアに適切でなかったため、エッジ/レベル/シンプル/ペルCPU割込みに分離された機能で再実装されました。これは単なる機能最適化にとどまらず、割込み処理のコードパスを短縮する効果もあります。

SMPでのロック¶

チップレジスタのロックは、チッププリミティブを定義するアーキテクチャの責任です。パーセルIRQ構造体は、ジェネリックレイヤーによってdesc->lockで保護されます。

ジェネリック割込みチップ¶

同じIRQチップの実装を複製することを避けるため、コアは構成可能なジェネリック割込みチップの実装を提供します。開発者は、ジェネリックチップが自身のニーズに合致するかを慎重に確認した上で、同じ機能をわずかに異なる方法で実装すべきではありません。

void irq_disable(struct irq_desc *desc)¶

割り込みを無効化する

パラメータ

struct irq_desc *desc

無効化するべき割り込みデスクリプタ

説明

チップがirq_disableコールバックを実装していない場合、ラズィーな無効化アプローチを使用します。つまり、割り込みを無効化するマークを残しますが、ハードウェアはアンマスクのままにします。これは、割り込みが無効化された後で発生しないという一般的なケースでハードウェアアクセスを避けるための最適化です。割り込みが発生した場合、割り込みフローハンドラがハードウェアレベルでラインをマスクし、それを待機状態にします。

割り込みチップがirq_disableコールバックを実装していない場合、ドライバは特定の割り込みラインに対して「irq_set_status_flags(irq, IRQ_DISABLE_UNLAZY)」を呼び出して、ラズィアプローチを無効化できます。これは、特定の状況においてデバイスレベルで割り込みを無効化できないデバイスで、代わりにdisable_irq[_nosync]を使用する必要がある場合に利用されます。
