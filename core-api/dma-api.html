汎用デバイスを使用した動的DMAマッピング¶

著者

James E.J. Bottomley <James.Bottomley@HansenPartnership.com>

このドキュメントはDMA APIについて説明しています。APIのよりやさしい紹介（および実際の例）については、以下を参照してください 動的DMAマッピングガイド.

このAPIは2つの部分に分かれています。パートIは基本的なAPIを、パートIIは非一貫メモリマシンをサポートする拡張機能を説明しています。あなたのドライバが絶対に非一貫プラットフォームをサポートしなければならない（これは通常はレガシープラットフォームのみ）場合を除き、パートIに記載されているAPIのみを使用してください。

パートI - dma_API¶

dma_APIを使用するには、#include <linux/dma-mapping.h>を実行する必要があります。これはdma_addr_tと以下のインターフェースを提供します。

dma_addr_tはプラットフォームの有効なDMAアドレスを保持できます。デバイスにDMAソースまたはターゲットとして使用できます。CPUはdma_addr_tを直接参照できません。なぜなら、物理アドレス空間とDMAアドレス空間の間で変換が発生する可能性があるからです。

パートIa - 大容量DMA一貫バッファの使用¶

void *
dma_alloc_coherent(struct device *dev, size_t size,
                   dma_addr_t *dma_handle, gfp_t flag)

一貫メモリは、デバイスまたはプロセッサが書き込んだデータが、プロセッサまたはデバイスによって即座に読み取れるメモリです（プロセッサのライトバッファをデバイスに読み込むよう指示する前に、フラッシュする必要があるかもしれません）。

この関数は、<size>バイトの一貫メモリ領域を割り当てます。

割り当てられた領域へのポインタ（プロセッサの仮想アドレス空間内）を返します。割り当てに失敗した場合はNULLを返します。

また、<dma_handle>も返します。これはバスの幅と同じ幅の符号なし整数にキャストして、デバイスにその領域のDMAアドレスベースとして渡すことができます。

注意: 一部のプラットフォームでは一貫メモリの使用がコストがかかる場合があります。最小割り当て長はページサイズと同程度になるため、一貫メモリの要求をできるだけまとめたほうがよいです。最も簡単な方法はdma_poolコール（以下を参照）を使用することです。

フラグパラメータ（dma_alloc_coherent()専用）は、呼び出し元が割り当てに使用するフラグを指定できます。 GFP_ フラグ（ kmalloc()) についての説明（実装は返されたメモリの位置に影響するフラグ（例: GFP_DMA）を無視する可能性があります）。

void
dma_free_coherent(struct device *dev, size_t size, void *cpu_addr,
                  dma_addr_t dma_handle)

以前に割り当てた一貫メモリ領域を解放します。dev、size、dma_handleはdma_alloc_coherent()に渡したものと一致する必要があります。cpu_addrはdma_alloc_coherent()が返した仮想アドレスでなければなりません。

注意: これらの関数は、他の割り当て関数とは異なり、IRQが有効になっている状態でしか呼び出すことができません。

パートIb - 小容量DMA一貫バッファの使用¶

dma_APIのこの部分を使用するには、#include <linux/dmapool.h>が必要です。

多くのドライバはDMAディスクリプターやI/Oバッファ用に多数の小さなDMAコンセントなメモリ領域を必要とします。dma_alloc_coherent()でページ単位で割り当てることではなく、DMAプールを使用できます。これらはstruct kmem_cacheと似ていますが、DMAコンセントなアロケータを使用し、__get_free_pages()ではなく動作します。また、キューヘッドなどハードウェアのアライメント制約を理解しており、Nバイト境界でのアライメントが必要な場合があります。

struct dma_pool *
dma_pool_create(const char *name, struct device *dev,
                size_t size, size_t align, size_t alloc);

dma_pool_create() 指定されたデバイス用にDMAコンセントなバッファプールを初期化します。スリープ可能なコンテキストで呼び出す必要があります。

「name」は診断用（struct kmem_cacheの名前のように）で、devとsizeはdma_alloc_coherent()に渡すパラメータと同様です。「align」はデバイスのハードウェアアライメント要件で、バイト単位で表され、2の累乗である必要があります。デバイスに境界制限がない場合はallocに0を、4096を指定するとこのプールから割り当てたメモリが4Kバイト境界を越えないようにします。

void *
dma_pool_zalloc(struct dma_pool *pool, gfp_t mem_flags,
                dma_addr_t *handle)

ラップ dma_pool_alloc() および割り当てが成功した場合、返されたメモリをゼロ初期化します。

void *
dma_pool_alloc(struct dma_pool *pool, gfp_t gfp_flags,
               dma_addr_t *dma_handle);

プールからメモリを割り当てます。返されたメモリは作成時のサイズとアライメント要件を満たします。ブロッキングを防ぐにはGFP_ATOMICを指定し、許可されている場合は（中断処理外でSMPロックを保持していない場合）GFP_KERNELを指定してブロッキングを許可します。dma_alloc_coherent()と同様に、この関数はCPUが使用可能なアドレスと、プールのデバイスが使用可能なDMAアドレスの2つの値を返します。

void
dma_pool_free(struct dma_pool *pool, void *vaddr,
              dma_addr_t addr);

プールにメモリを戻します。プールは dma_pool_alloc()に渡されたもので、CPU（vaddr）とDMAアドレスはその関数でメモリを割り当てた際に返された値です。

void
dma_pool_destroy(struct dma_pool *pool);

dma_pool_destroy() プールのリソースを解放します。スリープ可能なコンテキストで呼び出す必要があります。プールを破壊する前にすべての割り当てたメモリをプールに戻すことを確認してください。

パートIc - DMAアドレス制限¶

int
dma_set_mask_and_coherent(struct device *dev, u64 mask)

マスクが可能かどうかを確認し、可能であればデバイスのストリーミングDMAマスクとコンセントDMAマスクパラメータを更新します。

成功時は0を、失敗時は負のエラーコードを返します。

int
dma_set_mask(struct device *dev, u64 mask)

マスクが可能かどうかを確認し、可能であればデバイスパラメータを更新します。

成功時は0を、失敗時は負のエラーコードを返します。

int
dma_set_coherent_mask(struct device *dev, u64 mask)

マスクが可能かどうかを確認し、可能であればデバイスパラメータを更新します。

成功時は0を、失敗時は負のエラーコードを返します。

u64
dma_get_required_mask(struct device *dev)

このAPIはプラットフォームが効率的に動作するために必要なマスクを返します。通常は返されたマスクがすべてのメモリをカバーする最小限の値です。必要なマスクを確認することで、変動するディスクリプタサイズを持つドライバが必要に応じて小さなディスクリプタを使用できるようになります。

必要なマスクを要求しても現在のマスクは変更されません。このマスクを有効にする場合は、dma_set_mask()を呼び出してマスクを返された値に設定する必要があります。

size_t
dma_max_mapping_size(struct device *dev);

デバイスのマッピングの最大サイズを返します。dma_map_single()、dma_map_page()などのマッピング関数のsizeパラメータは、返された値を超えてはなりません。

bool
dma_need_sync(struct device *dev, dma_addr_t dma_addr);

dma_sync_single_for_{device,cpu}呼び出しがメモリ所有権の転送に必要かどうかを返します。必要ない場合は%falseを返します。

unsigned long
dma_get_merge_boundary(struct device *dev);

DMAマージ境界を返します。デバイスがDMAアドレスセグメントをマージできない場合、関数は0を返します。

パートID - ストリーミングDMAマッピング¶

dma_addr_t
dma_map_single(struct device *dev, void *cpu_addr, size_t size,
               enum dma_data_direction direction)

プロセッサの仮想メモリの一部をデバイスがアクセスできるようにマッピングし、そのメモリのDMAアドレスを返します。

両方のAPIの方向はキャストによって自由に変換可能です。ただし、dma_APIは方向を強型の列挙子で扱います。

DMA_NONE

方向なし（デバッグ用）

DMA_TO_DEVICE

データがメモリからデバイスへ送られます

DMA_FROM_DEVICE

データがデバイスからメモリへ届きます

DMA_BIDIRECTIONAL

方向が不明です

注意

このAPIでマッピング可能なメモリ領域は機械全体で必ずしもすべてではありません。また、連続するカーネル仮想空間が物理メモリで連続しているとは限りません。このAPIはスキャッタ/ギャッター機能を提供しないため、ユーザーが非物理的に連続していないメモリをマッピングしようとすると失敗します。そのため、このAPIでマッピングするメモリは、物理的に連続していることを保証するソース（kmallocなど）から取得する必要があります。

さらに、メモリのDMAアドレスはデバイスのdma_mask内に収める必要があります（dma_maskはデバイスのアドレス可能領域のビットマスクです。DMAアドレスとdma_maskをANDした結果がDMAアドレスと一致する場合、デバイスがDMAを実行できます）。kmallocで確保したメモリがdma_mask内に収まるようにするには、ドライバがプラットフォームに依存したフラグを指定してDMAアドレス範囲を制限できます（例：x86ではGFP_DMAが最初の16MBのDMAアドレス内を保証します）。

また、プラットフォームにIOMMU（I/O DMAアドレスを物理メモリアドレスにマッピングするデバイス）がある場合、上述の物理連続性やdma_maskに関する制約は適用されない可能性があります。ただし、移植性を確保するため、デバイスドライバ開発者は ではありません IOMMUが存在すると仮定する必要があります。

警告

メモリのコヒーレンシーはキャッシュライン幅という粒度で動作します。このAPIでマッピングされたメモリが正しく動作するためには、マッピングされた領域はキャッシュライン境界を正確に開始し、終了する必要があります（2つの別個のマッピング領域が1つのキャッシュラインを共有しないようにするため）。キャッシュラインサイズがコンパイル時に判明しない場合、APIはこの要件を強制しません。したがって、キャッシュラインサイズを実行時に特定しないドライバ開発者は、ページ境界を開始および終了する仮想領域のみをマッピングする必要があります（ページ境界はキャッシュライン境界としても保証されています）。

DMA_TO_DEVICEの同期は、ソフトウェアによるメモリ領域の最後の変更後でなければならず、デバイスに渡す前に実行する必要があります。このプリミティブを使用した後は、このプリミティブでカバーされるメモリはデバイスによって読み取り専用と扱われるべきです。デバイスがいつでも書き込む可能性がある場合は、DMA_BIDIRECTIONAL（以下参照）を使用する必要があります。

DMA_FROM_DEVICEの同期は、ドライバがデバイスによって変更される可能性のあるデータにアクセスする前に実行する必要があります。このメモリはドライバによって読み取り専用と扱われるべきです。ドライバがいつでも書き込む必要がある場合は、DMA_BIDIRECTIONAL（以下参照）を使用する必要があります。

DMA_BIDIRECTIONALには特別な処理が必要です：ドライバがメモリがデバイスに渡す前になぜか変更されていたか、またはデバイスが変更する可能性があるかを確定できません。したがって、双方向メモリは常に2回同期する必要があります。1回目はメモリがデバイスに渡す前に実行し、すべてのメモリ変更がプロセッサからフラッシュされるようにし、2回目はデバイスによって使用された後でデータがアクセスされる前に実行し、プロセッサキャッシュラインがデバイスが変更したデータで更新されるようにします。

void
dma_unmap_single(struct device *dev, dma_addr_t dma_addr, size_t size,
                 enum dma_data_direction direction)

以前にマッピングされた領域をアンマッピングします。すべてのパラメータはマッピングAPIで渡された（および返却された）ものと同一でなければなりません。

dma_addr_t
dma_map_page(struct device *dev, struct page *page,
             unsigned long offset, size_t size,
             enum dma_data_direction direction)

void
dma_unmap_page(struct device *dev, dma_addr_t dma_address, size_t size,
               enum dma_data_direction direction)

ページのマッピングおよびアンマッピング用のAPIです。他のマッピングAPIにおけるすべての注意点および警告はここにも適用されます。また、<offset>および<size>パラメータは部分的なページマッピングを行うために提供されていますが、キャッシュ幅が判明している場合を除き、これらを使用すべきではありません。

dma_addr_t
dma_map_resource(struct device *dev, phys_addr_t phys_addr, size_t size,
                 enum dma_data_direction dir, unsigned long attrs)

void
dma_unmap_resource(struct device *dev, dma_addr_t addr, size_t size,
                   enum dma_data_direction dir, unsigned long attrs)

MMIOリソースのマッピングおよびアンマッピング用のAPIです。他のマッピングAPIにおけるすべての注意点および警告はここにも適用されます。このAPIはデバイスのMMIOリソースのみをマッピングするために使用するべきで、RAMのマッピングは許可されていません。

int
dma_mapping_error(struct device *dev, dma_addr_t dma_addr)

dma_map_single()、dma_map_page()、dma_map_resource()のいずれかがマッピングの作成に失敗する状況もあります。ドライバーは、返されたDMAアドレスをdma_mapping_error()でテストすることで、これらのエラーを検出できます。ゼロ以外の戻り値はマッピングが作成できなかったことを示し、ドライバーは適切な対応（例：現在のDMAマッピングの使用量を減らすか、後で再試行するなど）を行う必要があります。

int
dma_map_sg(struct device *dev, struct scatterlist *sg,
           int nents, enum dma_data_direction direction)

戻り値: マッピングされたDMAアドレスセグメントの数（scatter/gatherリストの一部の要素が物理的にまたは仮想的に隣接しており、IOMMUで1つのエントリでマッピングされる場合、<nents>に渡した値より短くなる可能性があります）。

注意: 一度マッピングされたsgは再度マッピングすることはできません。マッピングプロセスではsg内の情報を破壊することが許可されます。

他のマッピングインターフェースと同様に、dma_map_sg()も失敗することがあります。失敗した場合、0が返され、ドライバーは適切な対応を取らなければなりません。ブロックドライバーが要求を中止するか、あるいはオブジェクトが発生するよりも、何もしないことなくファイルシステムを破壊するのを避けることが重要です。

scatterlistsでは、結果のマッピングを次のように使用します:

int i, count = dma_map_sg(dev, sglist, nents, direction);
struct scatterlist *sg;

for_each_sg(sglist, sg, count, i) {
        hw_address[i] = sg_dma_address(sg);
        hw_len[i] = sg_dma_len(sg);
}

ここで、nentsはsglist内のエントリ数を表します。

実装は、複数の連続するsglistエントリを1つに統合することが許可されます（例：IOMMUの場合、または複数のページが物理的に連続している場合）。実際のマッピングに使用されたsgエントリ数を返します。失敗した場合は0が返されます。

次にcount回ループします（注意：これはnents回よりも少ない場合があります）。以前にsg->addressとsg->lengthにアクセスした場所で、sg_dma_address()とsg_dma_len()マクロを使用してください。

void
dma_unmap_sg(struct device *dev, struct scatterlist *sg,
             int nents, enum dma_data_direction direction)

以前にマッピングされたscatter/gatherリストをアンマッピングします。すべてのパラメータは、scatter/gatherマッピングAPIに渡したときと同じでなければなりません。

注意: <nents>は渡した数でなければなりません、 ではありません 返されたDMAアドレスエントリの数。

void
dma_sync_single_for_cpu(struct device *dev, dma_addr_t dma_handle,
                        size_t size,
                        enum dma_data_direction direction)

void
dma_sync_single_for_device(struct device *dev, dma_addr_t dma_handle,
                           size_t size,
                           enum dma_data_direction direction)

void
dma_sync_sg_for_cpu(struct device *dev, struct scatterlist *sg,
                    int nents,
                    enum dma_data_direction direction)

void
dma_sync_sg_for_device(struct device *dev, struct scatterlist *sg,
                       int nents,
                       enum dma_data_direction direction)

CPUとデバイスのための単一の連続またはscatter/gatherマッピングを同期します。sync_sg APIでは、すべてのパラメータは単一マッピングAPIに渡したときと同じでなければなりません。sync_single APIでは、単一マッピングAPIに渡したパラメータと異なるdma_handleとsizeパラメータを使用して部分的な同期が可能です。

注意

以下の操作を行ってください:

  • デバイスからDMAで書かれた値を読み取る前に（DMA_FROM_DEVICE方向を使用）

  • デバイスにDMAで書き込む値を書いた後（DMA_TO_DEVICE方向を使用）

  • before および デバイスにメモリを渡した後で、メモリがDMA_BIDIRECTIONALの場合

dma_map_single()も参照してください。

dma_addr_t
dma_map_single_attrs(struct device *dev, void *cpu_addr, size_t size,
                     enum dma_data_direction dir,
                     unsigned long attrs)

void
dma_unmap_single_attrs(struct device *dev, dma_addr_t dma_addr,
                       size_t size, enum dma_data_direction dir,
                       unsigned long attrs)

int
dma_map_sg_attrs(struct device *dev, struct scatterlist *sgl,
                 int nents, enum dma_data_direction dir,
                 unsigned long attrs)

void
dma_unmap_sg_attrs(struct device *dev, struct scatterlist *sgl,

上記の4つの関数は、_attrsサフィックスのない対応する関数と同様ですが、オプションでdma_attrsを渡します。

DMA属性の解釈はアーキテクチャ固有であり、各属性は DMA属性.

dma_attrs が 0 の場合、これらの関数のセマンティクスは、_attrs サフィックスが付いていない対応する関数と同一です。したがって、dma_map_single_attrs() は一般的に dma_map_single() などに置き換えることができます。

使用例として、 *_attrs 関数の使い方として、DMA メモリマッピング時に属性 DMA_ATTR_FOO を渡す方法は以下の通りです：

#include <linux/dma-mapping.h>
/* DMA_ATTR_FOO should be defined in linux/dma-mapping.h and
* documented in Documentation/core-api/dma-attributes.rst */
...

        unsigned long attr;
        attr |= DMA_ATTR_FOO;
        ....
        n = dma_map_sg_attrs(dev, sg, nents, DMA_TO_DEVICE, attr);
        ....

DMA_ATTR_FOO を考慮するアーキテクチャは、マッピングおよびアンマッピングルーチンの実装でその存在を確認します。例えば、

                             size_t size, enum dma_data_direction dir,
                             unsigned long attrs)
{
        ....
        if (attrs & DMA_ATTR_FOO)
                /* twizzle the frobnozzle */
        ....
}

第2部 - 非コヒーレント DMA アロケーション¶

これらの API は、渡されたデバイスによって DMA でアドレス可能と保証されたページを割り当てることを可能にします。ただし、カーネルとデバイス間でのメモリ所有権の明示的な管理が必要です。

プロセッサと I/O デバイス間のキャッシュラインのコヒーレンシーの仕組みを理解していない場合は、この API のこの部分を使用しないでください。

void *
dma_alloc_noncoherent(struct device *dev, size_t size,
                dma_addr_t *dma_handle, enum dma_data_direction dir,
                gfp_t gfp)

このルーチンは、<size> バイトの一貫性のあるメモリ領域を割り当てます。割り当てに成功した場合、プロセッサの仮想アドレス空間内の割り当てられた領域へのポインタを返します。失敗した場合は NULL を返します。返されたメモリは、カーネルの直接マッピング内に含まれる場合もしくは含まれない場合があります。ドライバは、返されたメモリ領域に対して virt_to_page を呼び出してはなりません。

また、<dma_handle>も返します。これはバスの幅と同じ幅の符号なし整数にキャストして、デバイスにその領域のDMAアドレスベースとして渡すことができます。

dir パラメータはデバイスがデータを読み込みおよび/または書き込みするかどうかを指定します。詳細については dma_map_single() を参照してください。

gfp パラメータは呼び出し元が割当を行う際の設定を指定できますが、GFP_DMA や GFP_HIGHMEM などのメモリゾーンを指定するフラグは拒否します。 GFP_ フラグ（ kmalloc()) 割当において、メモリゾーンを指定するフラグは拒否します。

デバイスにメモリを提供する前に dma_sync_single_for_device() を呼び出す必要があります。また、デバイスによって書かれたメモリを読み込む前に dma_sync_single_for_cpu() を呼び出す必要があります。これは再利用されるストリーミングDMAマッピングの場合と同じです。

void
dma_free_noncoherent(struct device *dev, size_t size, void *cpu_addr,
                dma_addr_t dma_handle, enum dma_data_direction dir)

dma_alloc_noncoherent() で以前に割当されたメモリ領域を解放します。dev、size、dma_handle および dir は dma_alloc_noncoherent() に渡したものとすべて同じでなければなりません。cpu_addr は dma_alloc_noncoherent() が返した仮想アドレスでなければなりません。

struct page *
dma_alloc_pages(struct device *dev, size_t size, dma_addr_t *dma_handle,
                enum dma_data_direction dir, gfp_t gfp)

この関数は <size> バイトの非一貫性メモリ領域を割当ます。割当てに失敗した場合は NULL を返します。結果の struct page は、struct page が適切に使用できるすべての用途に利用できます。

また、<dma_handle>も返します。これはバスの幅と同じ幅の符号なし整数にキャストして、デバイスにその領域のDMAアドレスベースとして渡すことができます。

dir パラメータはデバイスがデータを読み込みおよび/または書き込みするかどうかを指定します。詳細については dma_map_single() を参照してください。

gfp パラメータは呼び出し元が割当を行う際の設定を指定できますが、GFP_DMA や GFP_HIGHMEM などのメモリゾーンを指定するフラグは拒否します。 GFP_ フラグ（ kmalloc()) 割当において、メモリゾーンを指定するフラグは拒否します。

デバイスにメモリを提供する前に dma_sync_single_for_device() を呼び出す必要があります。また、デバイスによって書かれたメモリを読み込む前に dma_sync_single_for_cpu() を呼び出す必要があります。これは再利用されるストリーミングDMAマッピングの場合と同じです。

void
dma_free_pages(struct device *dev, size_t size, struct page *page,
                dma_addr_t dma_handle, enum dma_data_direction dir)

dma_alloc_pages() で以前に割当されたメモリ領域を解放します。dev、size、dma_handle および dir は dma_alloc_noncoherent() に渡したものとすべて同じでなければなりません。page は dma_alloc_pages() が返したポインタでなければなりません。

int
dma_get_cache_alignment(void)

プロセッサキャッシュのアライメントを返します。これは絶対最小のアライメントです。 および メモリのマッピングや部分的なフラッシュを行う際に遵守しなければならない幅。

注意

このAPIは数値を返すことがあります より大きい 実際のキャッシュラインよりも大きい値を返すかもしれませんが、この呼び出しで返す幅に合わせて1つ以上のキャッシュラインが正確に収まるように保証します。また、常に2の累乗になるため、簡単なアライメントが可能です。

第3部 - DMA-APIのデバッグ用ドライバの使用¶

上記のDMA-APIはいくつかの制約があります。DMAアドレスは同じサイズの関数で解放する必要があります。IOMMUハードウェアの登場により、ドライバがこれらの制約を破らないことがますます重要になっています。最悪の場合、このような違反はデータ破損やファイルシステムの破壊に至る可能性があります。

ドライバのデバッグおよびDMA-APIの使用に関するバグの検出には、カーネルにチェックコードをコンパイルすることで開発者にその違反を通知します。あなたのアーキテクチャがサポートする場合、カーネル構成で「DMA-APIの使用をデバッグする機能を有効にする」オプションを選択できます。このオプションを有効にするとパフォーマンスに影響を与えるため、本番環境のカーネルでは有効にしないでください。

カーネルを起動すると、DMAメモリの割り当てを記録するコードが含まれています。このコードがエラーを検出すると、カーネルログに警告メッセージと詳細情報を出力します。警告メッセージの例は以下のようになります：

ドライバ開発者は、警告を引き起こしたDMA-API呼び出しのスタックトレースを含むドライバとデバイスを特定できます。

デフォルトでは、最初のエラーのみ警告メッセージとして出力され、他のエラーは無音でカウントされます。この制限はカーネルログを埋め尽くすのを防ぐためです。デバッグ用にこの制限を解除するにはdebugfsを使用できます。詳細は下記のdebugfsインターフェースドキュメンテーションを参照してください。

DMA-APIデバッグコードのdebugfsディレクトリは「dma-api/」と呼ばれます。このディレクトリには現在以下のファイルが存在します：

dma-api/all_errors

このファイルは数値を含み、この値がゼロでない場合、デバッグコードは見つかったすべてのエラーに対してカーネルログに警告を出力します。このオプションはログを簡単に埋め尽くす可能性があるため注意してください。

dma-api/disabled

この読み取り専用ファイルは、デバッグコードが無効になっている場合に'Y'を含みます。これはメモリ不足になったり、起動時に無効に設定された場合に発生します。

dma-api/dump

この読み取り専用ファイルは現在のDMAマッピングを含みます。

dma-api/error_count

このファイルは読み取り専用で、見つかったエラーの合計数を表示します。

dma-api/num_errors

このファイル内の数値は、停止するまでに表示される警告メッセージの数を示します。この数値はシステム起動時に1に初期化され、このファイルに書き込むことで設定できます。

dma-api/min_free_entries

この読み取り専用ファイルは、アロケータがこれまでに観測した最小の空きdma_debug_entries数を取得するために読み取れます。この値がゼロになる場合、コードはnr_total_entriesを増やすことを試みます。

dma-api/num_free_entries

アロケータ内の現在の空きdma_debug_entries数。

dma-api/nr_total_entries

アロケータ内のdma_debug_entriesの総数（空きと使用中のものを含む）。

dma-api/driver_filter

このファイルにドライバの名前を書き込むことで、デバッグ出力が特定のドライバからのリクエストに限定されます。空文字列を書き込むとフィルタが無効になり、すべてのエラーが再び表示されます。

このコードがカーネルに組み込まれている場合、デフォルトで有効になります。カーネル起動時にこの機能を無効にする場合は、'dma_debug=off'をブートパラメータとして指定できます。これによりDMA-APIのデバッグが無効になります。注意点として、ランタイムで再度有効にすることができず、再起動が必要です。

特定のデバイスドライバのみのデバッグメッセージを表示したい場合は、'dma_debug_driver=<drivername>'をパラメータとして指定します。これにより、起動時にドライバフィルタが有効になります。その後、デバッグコードはそのドライバのみのエラーを表示します。このフィルタはdebugfsを使用して後から無効化または変更できます。

コードがランタイムで自身を無効にする場合、これはdma_debug_entriesが不足し、オンデマンドでより多くの割当ができなかったことが原因です。起動時に65536個のエントリが事前に割り当てられます。この数が足りない場合は、'dma_debug_entries=<your_desired_number>'をブートパラメータとして指定してデフォルトを上書きできます。注意点として、コードはバッチ単位でエントリを割り当てるので、事前に割り当てたエントリ数は実際のリクエスト数より多くなる可能性があります。コードは、最初に事前に割り当てた数と同じだけ動的に割り当てたたびにカーネルログに記録します。これは、より大きな事前割り当てサイズが必要であることを示唆するか、継続的に発生する場合、ドライバがマッピングをリークしている可能性があることを示します。

void
debug_dma_mapping_error(struct device *dev, dma_addr_t dma_addr);

dma-debugインターフェースは、dma_map_single()およびdma_map_page()インターフェースで返されるアドレスにおけるDMAマッピングエラーを検出できていないドライバのデバッグに使用されるdebug_dma_mapping_error()インターフェースです。このインターフェースは、debug_dma_map_page()で設定されたフラグをクリアし、DMAマッピングエラーがドライバによって呼び出されたことを示します。ドライバがアンマップを行う際、debug_dma_unmap()はこのフラグを確認し、フラグがまだ設定されている場合、アンマップに至る呼び出しスタックを含む警告メッセージを出力します。このインターフェースはdma_mapping_error()ルーチンから呼び出され、DMAマッピングエラーのチェックデバッグを有効化します。
