genalloc/genpoolサブシステム¶

カーネルには特殊なニーズに対応するためのメモリ割り当てサブシステムがいくつかありますが、時折カーネル開発者が特定の特殊用途メモリ範囲用に新しいアロケータを実装する必要があります。このメモリはしばしばデバイスのどこかに配置されています。そのデバイスのドライバの作成者は小さなアロケータを書くこともできますが、これによりカーネルに数十のテストされていないアロケータが埋め込まれる可能性があります。2005年にはJes Sorensenがsym53c8xx_2ドライバから一つのアロケータを取り出して、即興のメモリアロケータ用の汎用モジュールとして公開しました。 公開した このコードは2.6.13リリースでマージされ、それ以降大幅に変更されています。

このアロケータを使用するコードは<linux/genalloc.h>をインクルードする必要があります。動作は以下の関数を用いてプールの生成から始まります:

管理されたgen_pool_create

パラメータ

通常のkmalloc/kfreeインターフェースで管理されない特殊用途メモリを管理するために使用できる新しい特殊メモリプールを生成します。このプールはデバイス管理コードによって自動的に破壊されます。

呼び出しを行うことで gen_pool_create() プールを生成します。割り当ての粒度はmin_alloc_orderで設定され、これはページアロケータで使用されるような2の対数形式ですが、ページではなくバイトを指します。したがって、min_alloc_orderを3として渡すと、すべての割り当ては8バイトの倍数になります。min_alloc_orderを増やすことで、プール内のメモリを追跡するのに必要なメモリ量は減少します。nidパラメータは、ハウスキーピング構造体の割り当てに使用するNUMAノードを指定します。呼び出し元が気にしない場合は-1を指定できます。

「管理された」インターフェース devm_gen_pool_create() プールを特定のデバイスに結びつけます。その他の機能として、指定されたデバイスが破壊されるときにプールを自動的にクリーンアップします。

プールは以下の関数で停止します:

void gen_pool_destroy(struct gen_pool *プール)¶

特殊メモリプールを破壊する

パラメータ

struct gen_pool *pool

破壊するプール

説明

指定された特殊メモリプールを破壊します。未完了の割り当てがないことを確認します。

指定されたプールからまだ割り当てられていないメモリがある場合、この関数は極端な手段としてBUG()を呼び出してシステム全体をクラッシュする可能性があります。ご注意ください。

新規に作成されたプールはメモリを割り当てることができません。この状態ではほぼ使い物になりませんので、通常最初の重要な作業の一つはプールにメモリを追加することです。これを行うには以下のいずれかを使用できます。

void gen_pool_set_algo(struct gen_pool *プール, genpool_algo_t algo, void *data)¶

割り当てアルゴリズムを設定する

パラメータ

struct gen_pool *pool

割り当てアルゴリズムを変更するプール

genpool_algo_t algo

カスタムアルゴリズム関数

void *data

使用される追加データ algo

説明

を呼び出して、MMIOまたはIOポート範囲を利用可能にします。これを実施しないと、ドライバの再ロードができない状態になります。 algo プール内の各メモリ割り当てに対して。もし algo NULLの場合はgen_pool_first_fitをデフォルトのメモリ割り当て関数として使用します。

gen_pool_alloc_algoで割り当てられるメモリは、割り当てられるメモリを選択するためのアルゴリズムを指定します。デフォルトアルゴリズムは gen_pool_set_algo()で設定できます。データ値はアルゴリズムに渡され、多くの場合無視されますが、必要に応じて使用されます。自然に、専用のアルゴリズムを書くこともできますが、すでに十分な数のアルゴリズムが用意されています：

  • gen_pool_first_fitは単純なfirst-fit割り当て器です。これ以上指定されていない場合のデフォルトアルゴリズムです。

  • gen_pool_first_fit_alignは、指定されたアライメント（genpool_data_align構造体を介してdataパラメータで渡されます）を強制します。

  • gen_pool_first_fit_order_alignは、割り当てのアライメントをサイズのオーダーに合わせます。たとえば、60バイトの割り当ては64バイトアライメントになります。

  • gen_pool_best_fitは、予想通りのシンプルなbest-fit割り当て器です。

  • gen_pool_fixed_allocは、プール内の特定のオフセット（genpool_data_fixed構造体を介してdataパラメータで渡されます）でメモリを割り当てます。指定されたメモリが利用不可な場合、割り当ては失敗します。

他にもいくつかの関数がありますが、主にプール内の空き領域を照会する目的やメモリチャンクを繰り返し処理する目的などに使用されます。しかし、ほとんどのユーザーはこれまで説明した内容を超える必要はありません。幸いにも、このモジュールの広範な認知が、今後専用のメモリ割り当て器の作成を防ぐ助けになるでしょう。
