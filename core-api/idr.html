IDの割り当て¶

著者

Matthew Wilcox

概要¶

解決すべき一般的な問題の一つは、識別子（ID）の割り当てです。IDは通常、小さな数値で、何かを特定します。例としてファイルディスクリプタ、プロセスID、ネットワークプロトコルのパケットID、SCSIタグ、デバイスインスタンス番号が挙げられます。IDRとIDAは、すべての人が独自の方法を考案するのを防ぐための合理的な解決策を提供します。IDRはIDをポインタにマッピングする機能を持ち、IDAはIDの割り当てのみを提供するため、メモリ効率がはるかに高いです。

idr_find() はRCUを使用してロックレスで呼び出せます。呼び出し元はこの関数を、 rcu_read_lock() 領域内で呼び出す必要があります。他の読者（ロックレスでもそれ以外でも）や変更処理が同時に実行される可能性があります。

呼び出し元がアイテムの同期とライフタイムを管理する必要があります。RCUロックフリーの検索が使用される場合、通常これはアイテムが独自のロックを持つか、ロックフリーでアクセス可能であるか、またアイテムがRCUで解放される（またはidrツリーから削除された後に解放される）ことが求められます。 および a synchronize_rcu() グレースペリオド。

IDAの使用方法¶

IDAはIDとポインタを関連付ける機能を提供しないID割当器です。そのため、IDごとに1ビットのみを保存する必要があり、IDRよりも空間効率が良いです。IDAを使用するには、DEFINE_IDA()で定義するか（またはデータ構造に埋め込むことで）、ida_init()で初期化します。 struct ida 新しいIDを割当てるには、 ida_alloc(), ida_alloc_min(), ida_alloc_max() または ida_alloc_range()を呼び出します。IDを解放するには、 ida_free().

ida_destroy() を使用してIDAを解放する必要はなく、個々のIDを解放する必要はありません。ida_is_empty()を使用して、IDAに現在割当てられたIDが存在するかどうかを確認できます。

IDAは自身のロックを管理します。コード内で同期処理を行わずにIDA関数を呼び出すことが安全です。

現在のIDは[0-INT_MAX]の範囲に制限されています。この制限が不都合な場合、最大値を上げるのはそれほど難しくありません。
