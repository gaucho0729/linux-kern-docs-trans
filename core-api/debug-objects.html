オブジェクトのライフタイムを監視するデバッグインフラストラクチャ¶

著者

Thomas Gleixner

はじめに¶

debugobjectsは、カーネルオブジェクトのライフタイムを追跡し、それらの操作を検証する汎用的なインフラストラクチャです。

debugobjectsは以下のエラーパターンをチェックするために役立ちます:

  • 未初期化オブジェクトのアクティベーション

  • アクティブなオブジェクトの初期化

  • 解放/破壊されたオブジェクトの使用

debugobjectsは実際のオブジェクトのデータ構造を変更しないため、最小限のランタイム影響でコンパイル可能で、カーネルコマンドラインオプションでオンデマンドで有効化できます。

debugobjectsの使い方¶

カーネルサブシステムは、オブジェクトタイプを記述するデータ構造を提供し、適切な場所にデバッグコードの呼び出しを追加する必要があります。オブジェクトタイプを記述するデータ構造には、少なくともオブジェクトタイプの名前が必要です。検出された問題を修正するためのオプションの関数を提供し、カーネルが継続して動作し、ライブシステムからデバッグ情報を取得できるようにする必要があります。シリアルコンソールやモニターからのスタックトレース転記によるハードコアデバッグではなく。

debugobjectsが提供するデバッグ関数は以下の通りです:

  • debug_object_init

  • debug_object_init_on_stack

  • debug_object_activate

  • debug_object_deactivate

  • debug_object_destroy

  • debug_object_free

  • debug_object_assert_init

これらの関数は、実際のオブジェクトのアドレスと、オブジェクトタイプに特化したデバッグ記述構造へのポインタを引数として受け取ります。

検出されたエラーは統計情報に報告され、一部のエラーはprintkで出力され、完全なスタックトレースが含まれます。

統計情報は/sys/kernel/debug/debug_objects/statsから取得できます。これは警告の数や成功した修正の数、内部トラッキングオブジェクトの使用状況、内部トラッキングオブジェクトプールの状態に関する情報を提供します。

デバッグ関数¶

void debug_object_init(void *addr, const struct debug_obj_descr *descr)¶

オブジェクトが初期化されるときに実行されるデバッグチェック

パラメータ

void *addr

オブジェクトのアドレス

const struct debug_obj_descr *descr

オブジェクト固有のデバッグ記述構造へのポインタ

この関数は、実際のオブジェクトの初期化関数が呼ばれるたびに呼び出されます。

実際のオブジェクトがすでにdebugobjectsによって追跡されている場合、そのオブジェクトが初期化可能かどうかを確認します。アクティブな状態または破壊されたオブジェクトの初期化は許可されません。debugobjectsがエラーを検出すると、呼び出し元が提供したオブジェクトタイプの説明構造体にfixup_init関数を呼び出します。このfixup関数は、実際の初期化が行われる前に問題を修正できます。例えば、サブシステムへの損害を防ぐためにアクティブなオブジェクトを無効化することが可能です。

実際のオブジェクトがまだdebugobjectsによって追跡されていない場合、debugobjectsは実際のオブジェクトにトラッカー・オブジェクトを割り当て、トラッカー・オブジェクトの状態をODEBUG_STATE_INITに設定します。オブジェクトが呼び出し元のスタック上にあるかを確認します。呼び出し元のスタック上にある場合、警告メッセージとスタックトレースをprintkで出力します。呼び出しコードは、 debug_object_init_on_stack() オブジェクトを関数から抜け出す前に削除する必要があります。次のセクションを参照してください。

int debug_object_activate(void *addr, const struct debug_obj_descr *descr)¶

オブジェクトがアクティブ化される際のデバッグチェック

パラメータ

void *addr

オブジェクトのアドレス

const struct debug_obj_descr *descr

オブジェクト固有のデバッグ記述構造体へのポインタ。成功時は0を返します。チェックに失敗した場合は-EINVALを返します。

この関数は、実際のオブジェクトのアクティベーション関数が呼ばれるたびに呼び出されます。

実際のオブジェクトがすでにdebugobjectsによって追跡されている場合、そのオブジェクトがアクティブ化可能かどうかを確認します。アクティブな状態または破壊されたオブジェクトのアクティブ化は許可されません。debugobjectsがエラーを検出すると、呼び出し元が提供したオブジェクトタイプの説明構造体にfixup_activate関数を呼び出します。このfixup関数は、実際のアクティブ化が行われる前に問題を修正できます。例えば、サブシステムへの損害を防ぐためにアクティブなオブジェクトを無効化することが可能です。

debugobjectsで実際のオブジェクトがまだ追跡されていない場合、fixup_activate関数が利用可能であれば呼び出されます。これは静的に割り当てられ初期化されたオブジェクトの正当なアクティベーションを許可するためのものです。fixup関数はオブジェクトが有効かどうかを確認し、debug_objects_init()関数を呼び出してこのオブジェクトの追跡を初期化します。

アクティベーションが正当な場合、関連するトラッカー・オブジェクトの状態をODEBUG_STATE_ACTIVEに設定します。

void debug_object_deactivate(void *addr, const struct debug_obj_descr *descr)¶

オブジェクトが非アクティブ化される際のデバッグチェック

パラメータ

void *addr

オブジェクトのアドレス

const struct debug_obj_descr *descr

オブジェクト固有のデバッグ記述構造へのポインタ

実際のオブジェクトの非アクティブ化関数が呼ばれたときにこの関数が呼び出されます。

debugobjectsで実際のオブジェクトが追跡されている場合、そのオブジェクトが非アクティブ化可能かどうかを確認します。未追跡または破壊されたオブジェクトの非アクティブ化は許可されません。

非アクティブ化が正当な場合、関連するトラッカー・オブジェクトの状態をODEBUG_STATE_INACTIVEに設定します。

void debug_object_destroy(void *addr, const struct debug_obj_descr *descr)¶

オブジェクトが破壊される際のデバッグチェック

パラメータ

void *addr

オブジェクトのアドレス

const struct debug_obj_descr *descr

オブジェクト固有のデバッグ記述構造へのポインタ

この関数はオブジェクトを破壊したことをマークするために呼び出されます。これは無効なオブジェクト（メモリ内にまだ存在する静的に割り当てられたオブジェクトまたは後で解放されるオブジェクト）の使用を防ぐために役立ちます。

debugobjectsで実際のオブジェクトが追跡されている場合、そのオブジェクトが破壊可能かどうかを確認します。アクティブまたは破壊されたオブジェクトの破壊は許可されません。debugobjectsがエラーを検出すると、呼び出し元が提供したオブジェクト型記述構造体のfixup_destroy関数を呼び出します。fixup関数は実際のオブジェクトの破壊前に問題を修正できます。例えば、サブシステムへの損害を防ぐためにアクティブなオブジェクトを非アクティブ化できます。

破壊が正当な場合、関連するトラッカー・オブジェクトの状態をODEBUG_STATE_DESTROYEDに設定します。

void debug_object_free(void *addr, const struct debug_obj_descr *descr)¶

オブジェクトが解放される際のデバッグチェック

パラメータ

void *addr

オブジェクトのアドレス

const struct debug_obj_descr *descr

オブジェクト固有のデバッグ記述構造へのポインタ

オブジェクトが解放される前にこの関数が呼び出されます。

debugobjectsで実際のオブジェクトが追跡されている場合、そのオブジェクトが解放可能かどうかを確認します。アクティブなオブジェクトの解放は許可されません。debugobjectsがエラーを検出すると、呼び出し元が提供したオブジェクト型記述構造体のfixup_free関数を呼び出します。fixup関数は実際のオブジェクトの解放前に問題を修正できます。例えば、サブシステムへの損害を防ぐためにアクティブなオブジェクトを非アクティブ化できます。

debug_object_freeはオブジェクトをトラッカーから削除します。後続のオブジェクトの使用は他のデバッグチェックによって検出されます。

void debug_object_assert_init(void *addr, const struct debug_obj_descr *descr)¶

オブジェクトが初期化されるべき場合のデバッグチェック

パラメータ

void *addr

オブジェクトのアドレス

const struct debug_obj_descr *descr

オブジェクト固有のデバッグ記述構造へのポインタ

この関数は、オブジェクトが初期化されていることを確認するために呼び出されます。

実際のオブジェクトがdebugobjectsによって追跡されていない場合、呼び出し元が提供したオブジェクトタイプの説明構造体のfixup_assert_init関数が呼び出され、ハードコードされたオブジェクト状態ODEBUG_NOT_AVAILABLEが渡されます。fixup関数はdebug_object_initやその他の特定の初期化関数を呼び出して問題を修正できます。

実際のオブジェクトがすでにdebugobjectsによって追跡されている場合は無視されます。

fixup_init¶

debug_object_initで問題が検出されたときにデバッグコードから呼び出される関数。オブジェクトのアドレスとトラッカーに記録されている現在の状態を受け取ります。

debug_object_initから呼び出される際のオブジェクト状態は:

  • ODEBUG_STATE_ACTIVE

fixupが成功した場合はtrueを返し、失敗した場合はfalseを返します。返却値は統計情報を更新するために使用されます。

関数は、修復後に再度呼び出さなければならないことに注意してください。 debug_object_init() 修復後、状態を一貫させることを目的として関数を再度呼び出さなければなりません。

fixup_activate¶

debug_object_activateで問題が検出されたときにデバッグコードから呼び出される関数です。

debug_object_activateから呼び出される際のオブジェクト状態は:

  • ODEBUG_STATE_NOTAVAILABLE

  • ODEBUG_STATE_ACTIVE

fixupが成功した場合はtrueを返し、失敗した場合はfalseを返します。返却値は統計情報を更新するために使用されます。

修復後に再度関数を呼び出さなければならないことに注意してください。 debug_object_activate() 修復後、状態を一貫させることを目的として関数を再度呼び出さなければなりません。

静的に初期化されたオブジェクトのアクティベートは特別なケースです。When debug_object_activate() このオブジェクトアドレスにトラックされたオブジェクトが存在しない場合、fixup_activate()はオブジェクト状態ODEBUG_STATE_NOTAVAILABLEで呼び出されます。fixup関数は、これは静的初期化オブジェクトの正当なケースかどうかを確認する必要があります。その場合、fixup関数は debug_object_init() および debug_object_activate() トラッカーにオブジェクトを認識させ、アクティブにマークする必要があります。この場合、関数はfalseを返すべきです。これは実際のfixupではありません。

fixup_destroy¶

debug_object_destroyで問題が検出されたときに、この関数がデバッグコードから呼び出されます。

debug_object_destroyから呼び出され、オブジェクトの状態が:

  • ODEBUG_STATE_ACTIVE

fixupが成功した場合はtrueを返し、失敗した場合はfalseを返します。返却値は統計情報を更新するために使用されます。

fixup_free¶

debug_object_freeで問題が検出されたときに、この関数がデバッグコードから呼び出されます。さらに、kfree/vfreeのデバッグチェックでアクティブなオブジェクトが検出された場合、debug_check_no_obj_freed()の健全性チェックからも呼び出されることがあります。

Called from debug_object_free() またはdebug_check_no_obj_freed()から呼び出され、オブジェクトの状態が:

  • ODEBUG_STATE_ACTIVE

fixupが成功した場合はtrueを返し、失敗した場合はfalseを返します。返却値は統計情報を更新するために使用されます。

fixup_assert_init¶

debug_object_assert_initで問題が検出されたときに、この関数がデバッグコードから呼び出されます。

Called from debug_object_assert_init() デバッグバケットにオブジェクトが見つからない場合、ハードコードされた状態ODEBUG_STATE_NOTAVAILABLEで呼び出されます。

fixupが成功した場合はtrueを返し、失敗した場合はfalseを返します。返却値は統計情報を更新するために使用されます。

注意: この関数は debug_object_init() 戻る前に呼び出される必要があります。

静的初期化オブジェクトの処理は特別なケースです。fixup関数は、これは静的初期化オブジェクトの正当なケースかどうかを確認する必要があります。このような場合、 debug_object_init() トラッカーにオブジェクトを認識させるために呼び出される必要があります。その後、関数はfalseを返すべきです。これは実際のfixupではありません。
