printkのフォーマット指定子を正しく使用する方法¶

著者

Randy Dunlap <rdunlap@infradead.org>

著者

Andrew Murray <amurray@mpc-data.co.uk>

整数型¶

If variable is of Type,         use printk format specifier:
------------------------------------------------------------
        char                    %d or %x
        unsigned char           %u or %x
        short int               %d or %x
        unsigned short int      %u or %x
        int                     %d or %x
        unsigned int            %u or %x
        long                    %ld or %lx
        unsigned long           %lu or %lx
        long long               %lld or %llx
        unsigned long long      %llu or %llx
        size_t                  %zu or %zx
        ssize_t                 %zd or %zx
        s8                      %d or %x
        u8                      %u or %x
        s16                     %d or %x
        u16                     %u or %x
        s32                     %d or %x
        u32                     %u or %x
        s64                     %lld or %llx
        u64                     %llu or %llx

<type>がコンフィギュレーションオプションに依存してサイズが決まる（例: sector_t, blkcnt_t）か、アーキテクチャに依存してサイズが決まる（例: tcflag_t）場合は、最大の可能型のフォーマット指定子を使用し、明示的にキャストしてから使用してください。

例:

printk("test: sector number/total blocks: %llu/%llu\n",
        (unsigned long long)sector, (unsigned long long)blockcount);

補足: sizeof()は型のサイズをsize_tで返します。

カーネルのprintfは%nをサポートしていません。浮動小数点フォーマット（%e, %f, %g, %a）も明確な理由によりサポートされていません。サポートされていない指定子または長さ修飾子の使用はWARNを出力し、早期に返します。 vsnprintf().

ポインタ型¶

rawなポインタ値は%pで表示できます。これはアドレスをハッシュ処理した後に表示します。カーネルは、異なる種類のポインタを表示するための拡張指定子もサポートしています。

一部の拡張指定子は、指定されたアドレスのデータを表示するのではなく、そのアドレス自体を表示します。この場合、以下のエラー メッセージが表示される可能性があります。

(null)   data on plain NULL address
(efault) data on invalid address
(einval) invalid data on a valid address

通常のポインタ¶

%p      abcdef12 or 00000000abcdef12

拡張指定子を付けずに%pで表示されるポインタは、カーネル メモリレイアウトに関する情報漏洩を防ぐためにハッシュ処理されます。これにより一意の識別子も提供されます。64ビットマシンでは最初の32ビットがゼロになります。カーネルは (ptrval) 十分なエントロピーを収集するまで表示します。もし 本当に アドレスを表示したい場合は、%pxを参照してください。

エラーポインタ¶

%pe     -ENOSPC

エラーポインタ（IS_ERR()が真となるポインタ）をシンボリックなエラー名として表示する場合に使用します。シンボリックな名前が分からないエラーバリューは10進数で表示され、%peに非ERR_PTRを引数として渡すと通常の%pとして扱われます。

シンボル/関数ポインタ¶

%pS     versatile_init+0x0/0x110
%ps     versatile_init
%pSR    versatile_init+0x9/0x110
        (with __builtin_extract_return_addr() translation)
%pB     prev_fn_of_versatile_init+0x88/0x88

以下の S および s ポインタをシンボリックな形式で表示するために使用されます。これは（S）オフセットを含むか（s）オフセットを含まないかによってシンボル名を表示します。KALLSYMSが無効な場合は、シンボルアドレスを表示します。

以下の B 指定子はオフセット付きのシンボル名を表示し、スタックバックトレースを表示する際に使用すべきです。この指定子は、テールコールが使用され、noreturn GCC属性でマークされた場合のコンパイラ最適化の影響を考慮します。

BPF/トレーシングからのプローブポインタ¶

%pks    kernel string
%pus    user string

以下の k および u 指定子は、カーネルメモリ（k）またはユーザーメモリ（u）からの以前にプローブされたメモリを表示するために使用されます。その後の s 指定子は文字列を表示します。通常の vsnprintf() （k）および（u）の注釈は無視されますが、BPFのbpf_trace_printk()の外側で使用される場合、そのポインタが指すメモリを読み込む際にフォールトを発生させることなく読み込みます。

カーネルポインタ¶

%pK     01234567 or 0123456789abcdef

権限のないユーザーから隠すべきカーネルポインタを印刷する場合に使用します。%pKの動作はkptr_restrict sysctlに依存します - 詳細については ドキュメンテーション for /proc/sys/kernel/ 詳細についてはこちら。

未変更アドレス¶

%px     01234567 or 0123456789abcdef

ポインタを印刷する際には 本当に アドレスを印刷したい場合、カーネルメモリレイアウトに関する機密情報の漏洩を考慮する必要があります。%pxは%lx（または%lu）と機能的に同等ですが、%pxはgrepで検索しやすいという点で推奨されます。今後カーネルがポインタ印刷の処理方法を変更する必要が生じた場合、呼び出し元を特定する際により効率的になります。

ポインタ差分¶

%td     2560
%tx     a00

ポインタ差分を印刷する際には、ptrdiff_t用に%t修飾子を使用してください。

例:

printk("test: difference between pointers: %td\n", ptr2 - ptr1);

構造体リソース¶

%pr     [mem 0x60000000-0x6fffffff flags 0x2200] or
        [mem 0x0000000060000000-0x000000006fffffff flags 0x2200]
%pR     [mem 0x60000000-0x6fffffff pref] or
        [mem 0x0000000060000000-0x000000006fffffff pref]

構造体リソースを印刷する場合、 R および r 指定子により、デコードされたフラグメンバ（R）または未デコードのフラグメンバ（r）を持つリソースが印刷されます。

物理アドレス型 phys_addr_t¶

%pa[p]  0x01234567 or 0x0123456789abcdef

phys_addr_t型（resource_size_tなどの派生型を含む）を印刷する場合、ビルドオプションにより変化する可能性があるため、CPUデータパス幅とは関係なく印刷します。

DMAアドレス型 dma_addr_t¶

%pad    0x01234567 or 0x0123456789abcdef

dma_addr_t型を印刷する場合、ビルドオプションにより変化する可能性があるため、CPUデータパス幅とは関係なく印刷します。

参照渡し

エスケープ文字列としてのrawバッファ¶

%*pE[achnops]

rawバッファをエスケープ文字列として印刷する場合、以下のバッファに対して

1b 62 20 5c 43 07 22 90 0d 5d

変換の例をいくつか示します（周辺の引用符は除きます）：

%*pE            "\eb \C\a"\220\r]"
%*pEhp          "\x1bb \C\x07"\x90\x0d]"
%*pEa           "\e\142\040\\\103\a\042\220\r\135"

変換規則は、オプションで指定可能なフラグの組み合わせに従って適用されます（詳細は string_escape_mem() カーネルドキュメンテーションを参照してください）：

  • a - ESCAPE_ANY

  • c - ESCAPE_SPECIAL

  • h - ESCAPE_HEX

  • n - ESCAPE_NULL

  • o - ESCAPE_OCTAL

  • p - ESCAPE_NP

  • s - ESCAPE_SPACE

デフォルトではESCAPE_ANY_NPが使用されます。

ESCAPE_ANY_NPは多くの場合、特にSSIDを印刷する際の合理的な選択肢です。

フィールド幅が指定されていない場合、1バイトのみがエスケープされます。

rawバッファとしての16進文字列¶

%*ph    00 01 02  ...  3f
%*phC   00:01:02: ... :3f
%*phD   00-01-02- ... -3f
%*phN   000102 ... 3f

小規模なバッファ（最大64バイト）を特定のセパレータで16進文字列として印刷します。大規模なバッファについては print_hex_dump().

MAC/FDDIアドレス¶

%pM     00:01:02:03:04:05
%pMR    05:04:03:02:01:00
%pMF    00-01-02-03-04-05
%pm     000102030405
%pmR    050403020100

6バイトのMAC/FDDIアドレスを16進表記で印刷します。 M および m 指定子により、（M）または（m）のバイトセパレータを持つアドレスが印刷されます。デフォルトのバイトセパレータはコロン（:）です。

FDDIアドレスについては、 F 指定子を M 指定子の後に使用することで、デフォルトのセパレータ（コロン）ではなくハイフン（-）セパレータを使用できます。

Bluetoothアドレスについては、 R 指定子を M 指定子の後に使用することで、ビジュアル的にBluetoothアドレス（リトルエンディアン順）を解釈するのに適した逆バイト順を使用できます。

参照渡し

IPv4アドレス¶

%pI4    1.2.3.4
%pi4    001.002.003.004
%p[Ii]4[hnbl]

IPv4ドット区切りの十進数アドレスを印刷するための。 I4 および i4 指定子により、リーディングゼロが含まれる(i4)または含まれない(I4)形式のアドレスが印刷されます。

追加の h, n, b, and l 指定子は、ホスト、ネットワーク、ビッグエンディアンまたはリトルエンディアンのアドレスを指定するために使用されます。指定子が提供されていない場合、デフォルトのネットワーク/ビッグエンディアン順序が使用されます。

参照渡し

IPv6アドレス¶

%pI6    0001:0002:0003:0004:0005:0006:0007:0008
%pi6    00010002000300040005000600070008
%pI6c   1:2:3:4:5:6:7:8

IPv6ネットワーク順の16ビットの16進数アドレスを印刷するための。 I6 および i6 指定子により、コロンセパレータが含まれる(I6)または含まれない(i6)形式のアドレスが印刷されます。リーディングゼロは常に使用されます。

追加の c 指定子は、 I 指定子と組み合わせて、記述された圧縮IPv6アドレスを印刷できます。 https://tools.ietf.org/html/rfc5952

参照渡し

IPv4/IPv6アドレス（汎用、ポート、フローフォーム、スコープ付き）¶

%pIS    1.2.3.4         or 0001:0002:0003:0004:0005:0006:0007:0008
%piS    001.002.003.004 or 00010002000300040005000600070008
%pISc   1.2.3.4         or 1:2:3:4:5:6:7:8
%pISpc  1.2.3.4:12345   or [1:2:3:4:5:6:7:8]:12345
%p[Ii]S[pfschnbl]

AF_INETまたはAF_INET6のいずれかのタイプであるかを区別することなくIPアドレスを印刷するための。有効なstruct sockaddrへのポインタを指定して IS または iSこのフォーマット指定子に渡すことができます。

追加の p, f, and s 指定子は、ポート（IPv4、IPv6）、フローフォーム（IPv6）、スコープ（IPv6）を指定するために使用されます。ポートには : プレフィックス、フローフォームには / スコープには %、それぞれ実際の値が続きます。

IPv6アドレスの場合、記述された圧縮IPv6アドレスが使用されます。 https://tools.ietf.org/html/rfc5952 追加の指定子が指定されている場合、 c が指定されている場合、IPv6アドレスは [, ] 追加の指定子がある場合 p, f または s によって提案された https://tools.ietf.org/html/draft-ietf-6man-text-addr-representation-07

IPv4アドレスの場合、追加の h, n, b, and l 指定子も使用でき、IPv6アドレスの場合には無視されます。

参照渡し

さらに例を示します:

%pISfc          1.2.3.4         or [1:2:3:4:5:6:7:8]/123456789
%pISsc          1.2.3.4         or [1:2:3:4:5:6:7:8]%1234567890
%pISpfc         1.2.3.4:12345   or [1:2:3:4:5:6:7:8]:12345/123456789

UUID/GUIDアドレス¶

%pUb    00010203-0405-0607-0809-0a0b0c0d0e0f
%pUB    00010203-0405-0607-0809-0A0B0C0D0E0F
%pUl    03020100-0504-0706-0809-0a0b0c0e0e0f
%pUL    03020100-0504-0706-0809-0A0B0C0E0E0F

16バイトのUUID/GUIDアドレスを印刷するための。追加の l, L, b および B 指定子は、小端形式（小文字(l)または大文字(L)の16進表記）と大端形式（小文字(b)または大文字(B)の16進表記）を指定するために使用されます。

追加の指定子が使用されない場合、デフォルトの大端形式で小文字の16進表記が印刷されます。

参照渡し

dentry名¶

%pd{,2,3,4}
%pD{,2,3,4}

dentry名を印刷するための；我々が d_move()と競合すると、名前が古いものと新しいものの混合になる可能性がありますが、oopsは起こりません。%pd dentryは以前使用していた%s dentry->d_name.nameのより安全な同等物です。%pd<n>は n 最後のコンポーネントを印刷します。%pDはstruct fileにも同じ動作を行います。

参照渡し

block_device名¶

%pg     sda, sda1 or loop0p1

block_deviceポインタの名前を印刷するための。

struct va_format¶

%pV

struct va_format構造体を印刷するための。これらは次の通り、フォーマット文字列とva_listを含みます:

struct va_format {
        const char *fmt;
        va_list *va;
};

「再帰的なvsnprintf」を実装します。

フォーマット文字列とva_list引数の正しさを確認するメカニズムがないと、この機能を使用しないでください。

参照渡し

デバイスツリーのノード¶

%pOF[fnpPcCF]

デバイスツリーのノード構造体を印刷します。デフォルトの動作は %pOFf と同等です。

  • f - デバイスノードのフルネーム

  • n - デバイスノード名

  • p - デバイスノードのphandle

  • P - デバイスノードのパス仕様（name + @unit）

  • F - デバイスノードのフラグ

  • c - 主な互換性文字列

  • C - 完全な互換性文字列

複数の引数を使用する場合のセパレーターは ‘:’ です。

例:

%pOF    /foo/bar@0                      - Node full name
%pOFf   /foo/bar@0                      - Same as above
%pOFfp  /foo/bar@0:10                   - Node full name + phandle
%pOFfcF /foo/bar@0:foo,device:--P-      - Node full name +
                                          major compatible string +
                                          node flags
                                                D - dynamic
                                                d - detached
                                                P - Populated
                                                B - Populated bus

参照渡し

Fwnode ハンドル¶

%pfw[fP]

Fwnode ハンドルに関する情報を印刷します。デフォルトでは、パスを含むフルノード名を印刷します。修正子は上記の %pOF と機能的に同等です。

  • f - ノードのフルネーム（パスを含む）

  • P - アドレスを含むノード名（アドレスがある場合）

例 (ACPI):

%pfwf   \_SB.PCI0.CIO2.port@1.endpoint@0        - Full node name
%pfwP   endpoint@0                              - Node name

例 (OF):

%pfwf   /ocp@68000000/i2c@48072000/camera@10/port/endpoint - Full name
%pfwP   endpoint                                - Node name

時刻と日付¶

%pt[RT]                 YYYY-mm-ddTHH:MM:SS
%pt[RT]d                YYYY-mm-dd
%pt[RT]t                HH:MM:SS
%pt[RT][dt][r]

時刻と日付を表す形式で印刷します：

R  struct rtc_time structure
T  time64_t type

人間が読みやすい形式で。

デフォルトでは、年は1900年に加算され、月は1に加算されます。この挙動を抑制するには、%pt[RT]r (raw) を使用してください。

参照渡し

struct clk¶

%pC     pll1
%pCn    pll1

struct clk 構造体を印刷します。%pC および %pCn は時計の名前（Common Clock Framework）または一意の 32 ビット ID（legacy clock framework）を印刷します。

参照渡し

ビットマップおよびその派生形式（cpumask、nodemask など）¶

%*pb    0779
%*pbl   0,3-6,8-10

ビットマップおよびその派生形式（cpumask、nodemask など）を印刷する場合、%*pb はビット数をフィールド幅としてビットマップを出力し、%*pbl はビット数をフィールド幅として範囲リストとしてビットマップを出力します。

参照渡し

フラグビットフィールド（page flags、gfp_flags など）¶

%pGp    referenced|uptodate|lru|active|private
%pGg    GFP_USER|GFP_DMA32|GFP_NOWARN
%pGv    read|exec|mayread|maywrite|mayexec|denywrite

フラグビットフィールドをシンボリック定数のコレクションとして印刷します。フラグの種類は3番目の文字で指定されます。現在サポートされているのは [p]age flags、[v]ma_flags（どちらも unsigned long *) および [g]fp_flags（ gfp_t *)。フラグ名と印刷順序は特定のタイプに依存します。

この形式は、 TP_printk() トレースポイントの一部として直接使用しないでください。代わりに、<trace/events/mmflags.h> から show_*_flags() 関数を使用してください。

参照渡し
