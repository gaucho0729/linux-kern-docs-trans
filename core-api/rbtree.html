赤黒木とは何ですか？そして、その用途は何ですか？¶

赤黒木は、並び替え可能なキー/値データペアを格納するために使用される自己平衡二分探索木の一種です。これは、長整数インデックスを用いてノードを挿入/アクセス/削除するための効率的なスパース配列を格納するためのラジックス木とは異なり、順序で簡単にトラバースできるようにするためにソートされないハッシュテーブルとは異なり、rbtreeは任意のキーを柔軟にスケーラブルに格納できるため、特定のサイズとハッシュ関数に合わせてチューニングする必要があるハッシュテーブルとは異なります。

赤黒木はAVL木と似ていますが、挿入および削除のためのリアルタイムでの最悪ケースの制限付きパフォーマンスが高速で（それぞれ最大2回、3回の回転操作で木をバランスさせます）、わずかに遅いですが（それでもO(log n)の検索時間）です。

Linux Weekly News からの引用:

カーネル内には複数の赤黒木が使用されています。デッドラインとCFQ I/Oスケジューラはrbtreeをリクエストを追跡するために使用し、パケットCD/DVDドライバも同様です。高解像度タイマーコードはrbtreeを未処理のタイマーリクエストを整理するために使用します。ext3ファイルシステムはディレクトリエントリを赤黒木で追跡します。仮想メモリ領域（VMAs）は赤黒木で追跡され、epollファイルディスクリプタ、暗号化キー、そして「階層的トークンバケット」スケジューラでのネットワークパケットも同様です。

Linuxにおける赤黒木の実装¶

Linuxのrbtree実装は「lib/rbtree.c」ファイルにあります。使用するには「#include <linux/rbtree.h>」を記述してください。

Linuxのrbtree実装は高速化のために1層少ない間接参照（キャッシュローカリティがより良い）で設計されており、より伝統的な木実装よりも優れています。rb_nodeとデータ構造を分離したポインタではなく、各struct rb_nodeのインスタンスはそのデータ構造を整理する構造体に埋め込まれています。また、比較コールバック関数ポインタではなく、ユーザーが独自の木検索および挿入関数を書くことを期待し、提供されたrbtree関数を呼び出します。ロック処理もrbtreeコードの利用者に委ねられています。

新しいrbtreeの作成¶

rbtreeのデータノードは、struct rb_nodeメンバを含む構造体です:

struct mytype {
      struct rb_node node;
      char *keystring;
};

埋め込まれた構造体 rb_node へのポインタを扱う場合、標準のマクロを使用して含むデータ構造にアクセスできます。 container_of() 個々のメンバは rb_entry(node, type, member) によって直接アクセス可能です。

各 rbtree のルートには rb_root 構造体があり、これは RB_ROOT で初期化されて空になります:

struct rb_root mytree = RB_ROOT;

rbtree 内の値の検索¶

自分の木に対して検索関数を書くのは比較的簡単です: ルートから始めて、各値を比較し、必要に応じて左または右の枝に進みます。

例:

struct mytype *my_search(struct rb_root *root, char *string)
{
      struct rb_node *node = root->rb_node;

      while (node) {
              struct mytype *data = container_of(node, struct mytype, node);
              int result;

              result = strcmp(string, data->keystring);

              if (result < 0)
                      node = node->rb_left;
              else if (result > 0)
                      node = node->rb_right;
              else
                      return data;
      }
      return NULL;
}

rbtree へのデータの挿入¶

データを挿入する際はまず挿入位置を検索し、その後ノードを挿入して木を再バランス調整（再色付け）します。

挿入時の検索は以前の検索と異なり、新しいノードを接ぎ木するポインタの位置を特定します。新しいノードは再バランス調整のため、親ノードへのリンクが必要です。

例:

int my_insert(struct rb_root *root, struct mytype *data)
{
      struct rb_node **new = &(root->rb_node), *parent = NULL;

      /* Figure out where to put new node */
      while (*new) {
              struct mytype *this = container_of(*new, struct mytype, node);
              int result = strcmp(data->keystring, this->keystring);

              parent = *new;
              if (result < 0)
                      new = &((*new)->rb_left);
              else if (result > 0)
                      new = &((*new)->rb_right);
              else
                      return FALSE;
      }

      /* Add new node and rebalance tree. */
      rb_link_node(&data->node, parent, new);
      rb_insert_color(&data->node, root);

      return TRUE;
}

rbtree 内の既存データの削除または置き換え¶

既存ノードを木から削除するには、以下のように呼び出します:

void rb_erase(struct rb_node *victim, struct rb_root *tree);

例:

struct mytype *data = mysearch(&mytree, "walrus");

if (data) {
      rb_erase(&data->node, &mytree);
      myfree(data);
}

同じキーを持つ新しいノードで既存ノードを置き換えるには、以下のように呼び出します:

void rb_replace_node(struct rb_node *old, struct rb_node *new,
                      struct rb_root *tree);

このようにノードを置き換えると木は再ソートされません: 新しいノードが古いノードと同じキーを持たない場合、rbtree は破損する可能性があります。

rbtree 内に保存された要素をソート順で反復処理¶

ソート順で rbtree の内容を反復処理するための関数は4つ用意されています。これらは任意の木に対して動作し、ロック処理を除いて変更やラッパーの必要はありません:

struct rb_node *rb_first(struct rb_root *tree);
struct rb_node *rb_last(struct rb_root *tree);
struct rb_node *rb_next(struct rb_node *node);
struct rb_node *rb_prev(struct rb_node *node);

反復処理を開始するには、rb_first() または rb_last() を木のルートへのポインタを引数に呼び出し、最初または最後の要素のノード構造へのポインタを返します。継続するには、現在のノードに対して rb_next() または rb_prev() を呼び出して次のノードまたは前のノードを取得します。これにより、ノードがなくなった場合は NULL が返されます。

反復処理関数は埋め込まれた rb_node 構造体へのポインタを返し、標準のマクロを使用して含むデータ構造にアクセスできます。また、個々のメンバは rb_entry(node, type, member) によって直接アクセス可能です。 container_of() マクロを使用して含むデータ構造にアクセスできます。また、個々のメンバは rb_entry(node, type, member) によって直接アクセス可能です。

例:

struct rb_node *node;
for (node = rb_first(&mytree); node; node = rb_next(node))
      printk("key=%s\n", rb_entry(node, struct mytype, node)->keystring);

キャッシュされた rbtree¶

二分探索木における左端（最小）ノードの計算は、たとえばトラバーサルや特定の順序を自分のロジックに依存しているユーザーにとって非常に一般的なタスクです。このため、ユーザーは「struct rb_root_cached」を使用して、rb_first()呼び出しのO(logN)の計算を単純なポインタ取得に最適化できます。これは維持コストのほとんどないランタイムオーバーヘッドで実行されますが、メモリ使用量がやや大きくなります。

rb_root構造体と同様に、キャッシュされたrbtreeは空に初期化される方法は以下の通りです：

struct rb_root_cached mytree = RB_ROOT_CACHED;

キャッシュされたrbtreeは単に通常のrb_rootに左端ノードをキャッシュするポインタを追加したものです。これによりrb_root_cachedはrb_rootと同じ場所で存在でき、拡張された木のサポートやいくつかの追加インターフェースも可能になります：

struct rb_node *rb_first_cached(struct rb_root_cached *tree);
void rb_insert_color_cached(struct rb_node *, struct rb_root_cached *, bool);
void rb_erase_cached(struct rb_node *node, struct rb_root_cached *);

挿入および削除呼び出しにはそれぞれ拡張された木の対応する処理があります：

void rb_insert_augmented_cached(struct rb_node *node, struct rb_root_cached *,
                                bool, struct rb_augment_callbacks *);
void rb_erase_augmented_cached(struct rb_node *, struct rb_root_cached *,
                               struct rb_augment_callbacks *);

拡張されたrbtreeのサポート¶

拡張されたrbtreeは各ノードに「一部」の追加データを保持したrbtreeであり、ノードNの追加データはNを根とするサブツリー内のすべてのノードの内容の関数として定義されます。このデータはrbtreeに新たな機能を追加するための拡張情報を提供します。拡張されたrbtreeは基本的なrbtreeインフラストラクチャ上で構築されるオプション機能であり、この機能を必要とするユーザーはノードの挿入・削除時にユーザーが提供した拡張コールバック関数を呼び出す必要があります。

拡張されたrbtreeの操作を実装するCファイルは<linux/rbtree_augmented.h>を代わりにインクルードする必要があります。<linux/rb3tree.h>ではなく。注意点として、linux/rbtree_augmented.hは一部のrbtreeの実装詳細を公開していますが、これらに依存すべきではありません。ドキュメント化されたAPIにのみ依存し、ヘッダーファイルから<linux/rbtree_augmented.h>をインクルードしないようにしてください。

挿入時にユーザーは挿入ノードまでのパスの拡張情報を更新した後、通常通りrb_link_node()を呼び出し、rb_insert_color()の代わりにrb_augment_inserted()を呼び出します。rb_augment_inserted()がrbtreeを再バランスする場合、ユーザーが提供した関数をコールバックして影響を受けたサブツリーの拡張情報を更新します。

ノードを削除する際には、rb_erase()の代わりにrb_erase_augmented()を呼び出します。rb_erase_augmented()はユーザーが提供した関数をコールバックして影響を受けたサブツリーの拡張情報を更新します。

いずれの場合も、コールバックはstruct rb_augment_callbacksを通じて提供され、3つのコールバック関数を定義する必要があります：

  • 指定された停止ポイントまで（NULLを指定してルートまで更新することも可能）のノードとその先祖ノードの拡張値を更新するための伝播コールバック。

  • 指定されたサブツリーの拡張値を新たに割り当てられたサブツリーのルートにコピーするためのコピー コールバック。

  • 指定されたサブツリーの拡張値を新たに割り当てられたサブツリーのルートにコピーし、かつ以前のサブツリーのルートの拡張情報を再計算するためのツリー回転コールバック。

rb_erase_augmented()のコンパイルコードは伝播コールバックとコピー コールバックをインライン化する可能性があり、これにより関数が非常に大きくなるため、各拡張rbtreeのユーザーはrb_erase_augmented()の呼び出し先を1か所に制限してコンパイルコードのサイズを抑える必要があります。

サンプルの使用例¶

インターバルツリーは拡張rbtreeの例です。参照 - コルメン、レイジェーセン、リーブスト、ストーン著『アルゴリズムの導入』。インターバルツリーについての詳細情報：

古典的なrbtreeは単一のキーしか持ち、区間範囲[lo:hi]を直接保存したり、新しいlo:hiと重複するかを素早く検索したり、新しいlo:既存のlo:hiに完全一致があるかを確認したりすることができません。

しかし、rbtreeはこのような区間範囲を構造化して保存するように拡張することで、効率的な検索と完全一致の検出が可能になります。

各ノードに保存されるこの「追加情報」は、そのノードのすべての後継ノードの最大hi（max_hi）値です。この情報は、ノード自身とその直下の子ノードを確認するだけで維持可能です。この情報は、O(log n)の時間で最小の一致（すべての可能一致の中での最小の開始アドレス）を検索する際に使用されます。

struct interval_tree_node *
interval_tree_first_match(struct rb_root *root,
                          unsigned long start, unsigned long last)
{
      struct interval_tree_node *node;

      if (!root->rb_node)
              return NULL;
      node = rb_entry(root->rb_node, struct interval_tree_node, rb);

      while (true) {
              if (node->rb.rb_left) {
                      struct interval_tree_node *left =
                              rb_entry(node->rb.rb_left,
                                       struct interval_tree_node, rb);
                      if (left->__subtree_last >= start) {
                              /*
                               * Some nodes in left subtree satisfy Cond2.
                               * Iterate to find the leftmost such node N.
                               * If it also satisfies Cond1, that's the match
                               * we are looking for. Otherwise, there is no
                               * matching interval as nodes to the right of N
                               * can't satisfy Cond1 either.
                               */
                              node = left;
                              continue;
                      }
              }
              if (node->start <= last) {              /* Cond1 */
                      if (node->last >= start)        /* Cond2 */
                              return node;    /* node is leftmost match */
                      if (node->rb.rb_right) {
                              node = rb_entry(node->rb.rb_right,
                                      struct interval_tree_node, rb);
                              if (node->__subtree_last >= start)
                                      continue;
                      }
              }
              return NULL;    /* No match */
      }
}

挿入/削除は以下の拡張コールバックを使用して定義されます：

static inline unsigned long
compute_subtree_last(struct interval_tree_node *node)
{
      unsigned long max = node->last, subtree_last;
      if (node->rb.rb_left) {
              subtree_last = rb_entry(node->rb.rb_left,
                      struct interval_tree_node, rb)->__subtree_last;
              if (max < subtree_last)
                      max = subtree_last;
      }
      if (node->rb.rb_right) {
              subtree_last = rb_entry(node->rb.rb_right,
                      struct interval_tree_node, rb)->__subtree_last;
              if (max < subtree_last)
                      max = subtree_last;
      }
      return max;
}

static void augment_propagate(struct rb_node *rb, struct rb_node *stop)
{
      while (rb != stop) {
              struct interval_tree_node *node =
                      rb_entry(rb, struct interval_tree_node, rb);
              unsigned long subtree_last = compute_subtree_last(node);
              if (node->__subtree_last == subtree_last)
                      break;
              node->__subtree_last = subtree_last;
              rb = rb_parent(&node->rb);
      }
}

static void augment_copy(struct rb_node *rb_old, struct rb_node *rb_new)
{
      struct interval_tree_node *old =
              rb_entry(rb_old, struct interval_tree_node, rb);
      struct interval_tree_node *new =
              rb_entry(rb_new, struct interval_tree_node, rb);

      new->__subtree_last = old->__subtree_last;
}

static void augment_rotate(struct rb_node *rb_old, struct rb_node *rb_new)
{
      struct interval_tree_node *old =
              rb_entry(rb_old, struct interval_tree_node, rb);
      struct interval_tree_node *new =
              rb_entry(rb_new, struct interval_tree_node, rb);

      new->__subtree_last = old->__subtree_last;
      old->__subtree_last = compute_subtree_last(old);
}

static const struct rb_augment_callbacks augment_callbacks = {
      augment_propagate, augment_copy, augment_rotate
};

void interval_tree_insert(struct interval_tree_node *node,
                          struct rb_root *root)
{
      struct rb_node **link = &root->rb_node, *rb_parent = NULL;
      unsigned long start = node->start, last = node->last;
      struct interval_tree_node *parent;

      while (*link) {
              rb_parent = *link;
              parent = rb_entry(rb_parent, struct interval_tree_node, rb);
              if (parent->__subtree_last < last)
                      parent->__subtree_last = last;
              if (start < parent->start)
                      link = &parent->rb.rb_left;
              else
                      link = &parent->rb.rb_right;
      }

      node->__subtree_last = last;
      rb_link_node(&node->rb, rb_parent, link);
      rb_insert_augmented(&node->rb, root, &augment_callbacks);
}

void interval_tree_remove(struct interval_tree_node *node,
                          struct rb_root *root)
{
      rb_erase_augmented(&node->rb, root, &augment_callbacks);
}
