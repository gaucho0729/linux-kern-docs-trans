irq_domain 割込み番号マッピングライブラリ¶

Linux カーネルの現在の設計では、単一の大きな番号空間を使用しており、それぞれのIRQソースに異なる番号を割り当てています。これは1つの割り込みコントローラーしかない場合にはシンプルですが、複数の割り込みコントローラーを持つシステムでは、カーネルがそれぞれにLinux IRQ番号の重複しない割り当てを行う必要があります。

割り込みコントローラーとして登録されたユニークなirqchipの数は増加しています。たとえば、GPIOコントローラーなどのさまざまなサブドライバーは、IRQコアシステムで同じコールバックメカニズムを再実装することを避けるため、割り込みハンドラをirqchipとしてモデル化し、つまり効果的に割り込みコントローラーをカスケードする形で実装されています。

ここでは、割り込み番号はハードウェア割り込み番号と一切の対応を持たなくなりました。過去にはIRQ番号をハードウェアのIRQラインに直接マッチさせることが可能でしたが、現在ではその番号は単なる数字に過ぎません。

そのため、コントローラー固有の割り込み番号（ハードウェアIRQ）とLinux IRQ番号を分離するメカニズムが必要です。

irq_alloc_desc*()とirq_free_desc*() APIはIRQ番号の割り当てを提供しますが、コントローラー固有のIRQ（hwirq）番号をLinux IRQ番号空間に逆引きマッピングするサポートは提供していません。

irq_domainライブラリはirq_alloc_desc*() APIの上にhwirqとIRQ番号のマッピングを追加します。マッピングを管理するirq_domainの使用は、割り込みコントローラードライバが独自の逆マッピングスキームを実装するよりも優れています。

irq_domainは抽象的なirq_fwspec構造体をhwirq番号（デバイスツリーおよびACPI GSIを含む）に変換し、他のIRQトポロジデータソースへのサポート拡張も容易です。

irq_domainの使用方法¶

割り込みコントローラードライバは、irq_domain_add_*()関数のいずれかを呼び出してirq_domainを作成・登録します（各マッピングメソッドには異なるアロケータ関数があります、後述します）。関数が成功すると、irq_domainへのポインタを返します。呼び出し元はアロケータ関数にirq_domain_ops構造体を提供する必要があります。

ほとんどの場合、irq_domainはhwirqとIRQ番号のマッピングがまったくない状態で開始されます。マッピングはirq_create_mapping()関数を呼び出すことでirq_domainとhwirq番号を引数として追加されます。hwirqに対するマッピングがすでに存在しない場合、新しいLinux irq_descを割り当て、hwirqと関連付けて、ドライバがハードウェアの設定を行うために.map()コールバックを呼び出します。

割り込みが受信された際には、hwirq番号からLinux IRQ番号を取得するためにirq_find_mapping()関数を使用する必要があります。

irq_create_mapping()関数は 少なくとも1回は irq_find_mapping()関数の呼び出しの前に呼び出さなければ、割り当てが行われない可能性があります。

ドライバがLinux IRQ番号またはirq_dataポインタを保有し、hwirq番号を取得する必要がある場合（例：irq_chipコールバック内）は、irq_data->hwirqから直接取得できます。

irq_domainマッピングの種類¶

hwirqからLinux IRQへの逆引きマッピングにはいくつかのメカニズムがあり、それぞれ異なる割り当て関数を使用します。使用ケースによって適切な逆引きマッピングタイプを選択する必要があります。以下に各逆引きマッピングタイプについて説明します。

Linear（線形）¶

irq_domain_add_linear()
irq_domain_create_linear()

Linear逆引きマッピングはhwirq番号でインデックスされる固定サイズのテーブルを維持します。hwirqがマッピングされるとき、irq_descが割り当てられ、IRQ番号がテーブルに保存されます。

hwirqの最大数が固定で比較的小さい（~256未満）場合にLinearマッピングは適切です。このマッピングの利点はIRQ番号の固定時間での検索であり、irq_descは使用中のIRQのみに割り当てられます。欠点はテーブルが最大のhwirq番号に合わせて大きくなければならないことです。

irq_domain_add_linear()とirq_domain_create_linear()は機能的に同等ですが、最初の引数が異なります。前者はOpen Firmware固有の'struct device_node'を受け取り、後者はより一般的な'struct fwnode_handle'を受け取ります。

ほとんどのドライバはLinearマッピングを使用すべきです。

Tree（木構造）¶

irq_domain_add_tree()
irq_domain_create_tree()

irq_domainはradix treeを用いてhwirq番号からLinux IRQへのマッピングを維持します。hwirqがマッピングされるとき、irq_descが割り当てられ、radix treeの検索キーとしてhwirqが使用されます。

hwirq番号が非常に大きい場合にTreeマッピングは適切です。なぜなら、テーブルを最大のhwirq番号に合わせて大きくする必要がないからです。欠点はhwirqからIRQ番号への検索時間がテーブル内のエントリ数に依存することです。

irq_domain_add_tree() と irq_domain_create_tree() は機能的に同等ですが、最初の引数が異なります。前者は Open Firmware 特有の 'struct device_node' を受け取り、後者はより一般的な抽象化である 'struct fwnode_handle' を受け取ります。

このマッピングを必要とするドライバーは極めて少数です。

No Map¶

irq_domain_add_nomap()

hwirq 番号がハードウェアでプログラマブルな場合に 'No Map' マッピングを使用します。この場合、Linux の IRQ 番号をハードウェア自体に直接設定することで、マッピングが不要になります。irq_create_direct_mapping() を呼び出すと、Linux の IRQ 番号が割り当てられ、.map() コールバックが呼ばれてドライバーが Linux の IRQ 番号をハードウェアに設定できます。

ほとんどのドライバーはこのマッピングを使用できません。

Legacy¶

irq_domain_add_simple()
irq_domain_add_legacy()
irq_domain_add_legacy_isa()

Legacy マッピングは、すでに hwirq 用に irq_desc が割り当てられているドライバー向けの特別なケースです。ドライバーが直ちに線形マッピングに変換できない場合に使用します。たとえば、多くの埋め込みシステムのボードサポートファイルは、IRQ 番号を #defines で定義し、それを struct device 登録に渡しています。その場合、Linux の IRQ 番号は動的に割り当てられず、Legacy マッピングを使用する必要があります。

Legacy マッピングは、制御器が連続した IRQ 番号の範囲をすでに割り当てており、hwirq 番号に固定オフセットを加えることで IRQ 番号を計算できると仮定しています。欠点は、割り込み制御器が IRQ 割り当てを管理する必要があり、未使用の hwirq でも irq_desc が割り当てられることです。

Legacy マッピングは、固定 IRQ マッピングをサポートする必要がある場合にのみ使用すべきです。たとえば、ISA 制御器は Linux の IRQ 0-15 を Legacy マッピングでマッピングし、既存の ISA ドライバーが正しい IRQ 番号を取得できるようにします。

Legacy マッピングを必要とするほとんどのユーザーは irq_domain_add_simple() を使用すべきです。この関数は、システムが IRQ 範囲を提供した場合に Legacy ドメインのみを使用し、それ以外の場合は線形ドメインマッピングを使用します。この関数のセマンティクスは、IRQ 範囲が指定されている場合、その範囲に即座に irq_desc を割り当て、範囲が指定されていない場合は irq_domain_add_linear() にフォールバックします。 no irq_desc が割り当てられます。

シンプルドメインの典型的な使用例は、irqchip プロバイダーが動的および静的な IRQ 割り当てをサポートする場合です。

線形ドメインが使用され、どのディスクリプタも割り当てられない状態に陥らないようにするため、ドライバが単純なドメインのirq_create_mapping()を呼び出す前に、irq_find_mapping()を呼び出すことが非常に重要です。後者の関数は静的IRQ割り当てのケースで実際に動作するからです。

階層IRQドメイン¶

一部のアーキテクチャでは、デバイスからターゲットCPUへの割込みを届ける際に複数の割込み制御器が関与する場合があります。x86プラットフォームにおける典型的な割込み届けの経路を見てみましょう:

Device --> IOAPIC -> Interrupt remapping Controller -> Local APIC -> CPU

関与する割込み制御器は以下の3つです:

  1. IOAPIC制御器

  2. 割込みリマッピング制御器

  3. ローカルAPIC制御器

このようなハードウェアのトポロジをサポートし、ソフトウェアアーキテクチャがハードウェアアーキテクチャと一致するようにするため、各割込み制御器に対してirq_domainデータ構造が構築され、それらのirq_domainは階層構造として組織化されます。irq_domain階層を構築する際、デバイスに近いirq_domainは子で、CPUに近いirq_domainは親になります。したがって、上記の例に対して以下のような階層構造が構築されます:

CPU Vector irq_domain (root irq_domain to manage CPU vectors)
        ^
        |
Interrupt Remapping irq_domain (manage irq_remapping entries)
        ^
        |
IOAPIC irq_domain (manage IOAPIC delivery entries/pins)

階層IRQドメインを使用するための4つの主要なインターフェースがあります:

  1. irq_domain_alloc_irqs(): これらの割込みを届けるためにIRQディスクリプタと割込み制御器関連のリソースを割り当てます。

  2. irq_domain_free_irqs(): これらの割込みに関連するIRQディスクリプタと割込み制御器関連のリソースを解放します。

  3. irq_domain_activate_irq(): 割込み制御器ハードウェアをアクティブ化し、割込みを届けるようにします。

  4. irq_domain_deactivate_irq(): 割込み制御器ハードウェアを非アクティブ化し、割込みの届けを停止します。

階層IRQドメインをサポートするためには以下の変更が必要です:

  1. struct irq_domainに新しいフィールド'parent'が追加され、irq_domain階層情報を維持するために使用されます。

  2. struct irq_domainに新しいフィールド'parent_data'が追加され、 struct irq_data; 階層irq_dataを階層irq_domainsと一致させるために使用されます。irq_dataはirq_domainポインタとハードウェア割込み番号を保存するために使用されます。

  3. struct irq_domain_opsに新しいコールバックが追加され、階層irq_domain操作をサポートするために使用されます。

階層irq_domainとirq_dataのサポートが完了したら、各割込み制御器に対してirq_domain構造体が構築され、各irq_domainに関連するIRQに対してirq_data構造体が割り当てられます。これにより、スタックされた（階層）irq_chipのサポートが可能になります。つまり、階層に沿って各irq_dataに対してirq_chipが関連付けられ、子irq_chipは自身で必要なアクションを実装するか、親irq_chipと協力して実装することが可能です。

スタックされたirq_chipを使用することで、割り込み制御デバイスドライバーは自身が管理するハードウェアのみを扱う必要があり、必要に応じて親のirq_chipからサービスを依頼できます。これにより、ソフトウェアアーキテクチャをはるかにクリーンにすることが可能です。

割り込み制御デバイスドライバーが階層的なirq_domainをサポートするには、以下が必要です:

  1. irq_domain_ops.allocとirq_domain_ops.freeを実装する必要があります。

  2. irq_domain_ops.activateとirq_domain_ops.deactivateを任意で実装する必要があります。

  3. 割り込み制御デバイスのハードウェアを管理するirq_chipを任意で実装する必要があります。

  4. irq_domain_ops.mapとirq_domain_ops.unmapを実装する必要はありません。これらは階層的なirq_domainでは使用されません。

階層的なirq_domainはx86に特化しているわけではなく、ARM、ARM64などの他のアーキテクチャをサポートするために積極的に利用されています。

デバッグ¶

CONFIG_GENERIC_IRQ_DEBUGFSを有効にすることで、IRQサブシステムの大部分の内部構造がdebugfsで公開されています。
