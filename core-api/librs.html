Reed-Solomon Library Programming Interface¶

著者

Thomas Gleixner

はじめに¶

一般的なReed-Solomon Libraryは、符号化、復号およびエラー訂正機能を提供します。

Reed-Solomon符号は、通信およびストレージアプリケーションでデータの整合性を確保するために使用されます。

このドキュメンテーションは、ライブラリが提供する機能を活用したい開発者向けに提供されています。

既知のバグと仮定¶

なし。

使い方¶

この章では、ライブラリの使用方法の例を示します。

初期化¶

init_rs関数は、指定された多項式で符号化、復号およびエラー訂正を行うために必要な情報を保持するrsデコーダー構造体へのポインタを返します。既存のマッチングデコーダーを使用するか、新しいデコーダーを作成します。作成時には高速符号化/復号用のすべての検索テーブルが作成されるため、関数呼び出しには時間がかかる場合があります。クリティカルなコードパスで呼び出すのは避けましょう。

/* the Reed Solomon control structure */
static struct rs_control *rs_decoder;

/* Symbolsize is 10 (bits)
 * Primitive polynomial is x^10+x^3+1
 * first consecutive root is 0
 * primitive element to generate roots = 1
 * generator polynomial degree (number of roots) = 6
 */
rs_decoder = init_rs (10, 0x409, 0, 1, 6);

符号化¶

エンコーダーは、指定されたデータ長に基づいてReed-Solomon符号を計算し、結果をパリティバッファに保存します。注意点として、エンコーダーを呼び出す前にパリティバッファを初期化しておく必要があります。

拡張データは、非ゼロの反転マスクを提供することで即座に反転できます。拡張データはマスクとXORされます。これは例えばFLASH ECCで、すべての0xFFが0x00に反転される用途に使用されます。すべての0x00のReed-Solomon符号はすべての0x00になります。符号をFLASHに保存する前に反転させることで0xFFになります。これにより、消去されたFLASHから読み込む際にECCエラーを防ぎます。

データバイトは、指定されたシンボルサイズに即座に拡張されます。現在はシンボルサイズが8以外の連続ビットストリームの符号化をサポートしていません。必要であれば実装はそれほど難しくありません。

/* Parity buffer. Size = number of roots */
uint16_t par[6];
/* Initialize the parity buffer */
memset(par, 0, sizeof(par));
/* Encode 512 byte in data8. Store parity in buffer par */
encode_rs8 (rs_decoder, data8, 512, par, 0);

復号¶

デコーダーは、指定されたデータ長と受信したパリティ符号に基づいてsyndromeを計算し、データ内のエラーを訂正します。

ハードウェアデコーダーからsyndromeが提供されている場合は、syndrome計算はスキップされます。

デコーダーに補正パターンバッファとエラー位置バッファを提供することで、データバッファの補正を抑制できます。デコーダーは計算されたエラー位置と補正ビットマスクを指定されたバッファに保存します。これは、異常なビット順序スキーマを使用するハードウェアデコーダーで有用です。

データバイトは、指定されたシンボルサイズに即座に拡張されます。現在はシンボルサイズが8以外の連続ビットストリームの復号をサポートしていません。必要であれば実装はそれほど難しくありません。

syndrome計算による復号、直接データ補正¶

/* Parity buffer. Size = number of roots */
uint16_t par[6];
uint8_t  data[512];
int numerr;
/* Receive data */
.....
/* Receive parity */
.....
/* Decode 512 byte in data8.*/
numerr = decode_rs8 (rs_decoder, data8, par, 512, NULL, 0, NULL, 0, NULL);

ハードウェアデコーダーによって生成されたsyndromeを使用した復号、直接データ訂正¶

/* Parity buffer. Size = number of roots */
uint16_t par[6], syn[6];
uint8_t  data[512];
int numerr;
/* Receive data */
.....
/* Receive parity */
.....
/* Get syndrome from hardware decoder */
.....
/* Decode 512 byte in data8.*/
numerr = decode_rs8 (rs_decoder, data8, par, 512, syn, 0, NULL, 0, NULL);

ハードウェアデコーダーによって生成されたsyndromeを使用した復号、直接データ訂正なし。¶

注意: デコーダーにデータと受信したパリティを提供する必要はありません。

/* Parity buffer. Size = number of roots */
uint16_t par[6], syn[6], corr[8];
uint8_t  data[512];
int numerr, errpos[8];
/* Receive data */
.....
/* Receive parity */
.....
/* Get syndrome from hardware decoder */
.....
/* Decode 512 byte in data8.*/
numerr = decode_rs8 (rs_decoder, NULL, NULL, 512, syn, 0, errpos, 0, corr);
for (i = 0; i < numerr; i++) {
    do_error_correction_in_your_buffer(errpos[i], corr[i]);
}

クリーンアップ¶

free_rs関数は、呼び出し元がデコーダーの最後のユーザーである場合、割り当てられたリソースを解放します。

/* Release resources */
free_rs(rs_decoder);

構造体¶

この章は、Reed-Solomonライブラリで使用される構造体の自動生成ドキュメンテーションを含んでいます。これらは開発者にとって重要です。

struct rs_codec¶

rs codecデータ

定義

struct rs_codec {
  int mm;
  int nn;
  uint16_t *alpha_to;
  uint16_t *index_of;
  uint16_t *genpoly;
  int nroots;
  int fcr;
  int prim;
  int iprim;
  int gfpoly;
  int (*gffunc)(int);
  int users;
  struct list_head list;
};

メンバ

mm

シンボルあたりのビット数

nn

ブロックあたりのシンボル数 (= (1<<mm)-1)

alpha_to

ログ検索テーブル

index_of

アンチログ検索テーブル

genpoly

生成多項式

nroots

生成多項式の根の数 = パリティシンボルの数

fcr

連続する最初の根、インデックス形式

prim

原始要素、インデックス形式

iprim

prim-th根の1、インデックス形式

gfpoly

原始生成多項式

gffunc

非標準表現を使用する場合のフィールド生成関数

users

この構造体のユーザー

list

rs codecリストのリストエントリ

struct rs_control¶

インスタンスごとのrs制御構造体

定義

struct rs_control {
  struct rs_codec *codec;
  uint16_t buffers[];
};

メンバ

codec

このインスタンスに使用されるコーデック

buffers

decode_rs()呼び出しで使用される内部一時バッファ

struct rs_control *init_rs(int symsize, int gfpoly, int fcr, int prim, int nroots)¶

RS制御構造体を作成し、初期化します

パラメータ

int symsize

シンボルサイズ（ビット数）

int gfpoly

拡張ガロア体生成多項式の係数、0番目の係数は低位ビットに配置。多項式は原始的でなければなりません;

int fcr

rsコード生成多項式の連続する最初の根、インデックス形式

int prim

多項式根を生成する原始要素

int nroots

RSコード生成多項式の次数（根の数）

説明

割当はGFP_KERNELを使用します。

int encode_rs8(struct rs_control *rsc, uint8_t *data, int len, uint16_t *par, uint16_t invmsk)¶

データ値のパリティを計算する（8bitデータ幅）

パラメータ

struct rs_control *rsc

rs制御構造体

uint8_t *data

指定された型のデータフィールド

int len

データ長

uint16_t *par

パリティデータ、呼び出し元が初期化する必要がある（通常はすべて0）

uint16_t invmsk

データマスクを反転（データに排他的論理和される）

パリティはuint16_tデータ型を使用して符号サイズを8bit以上に可能にする。呼び出し元はこのコードを呼び出す前に、症候結果の符号化と受信パリティの復号を担当する必要がある。

int decode_rs8(struct rs_control *rsc, uint8_t *data, uint16_t *par, int len, uint16_t *s, int no_eras, int *eras_pos, uint16_t invmsk, uint16_t *corr)¶

符号語を復号する（8bitデータ幅）

パラメータ

struct rs_control *rsc

rs制御構造体

uint8_t *data

指定された型のデータフィールド

uint16_t *par

受信したパリティデータフィールド

int len

データ長

uint16_t *s

症候データフィールド、インデックス形式でなければならない（NULLの場合は症候を計算する）

int no_eras

消去数

int *eras_pos

消去位置、NULLでも可

uint16_t invmsk

データマスクを反転（データに排他的論理和される、パリティには適用されない！）

uint16_t *corr

eras_posに修正ビットマスクを保存するバッファ

症候およびパリティはuint16_tデータ型を使用して符号サイズを8bit以上に可能にする。呼び出し元はこのコードを呼び出す前に、症候結果の復号と受信パリティの処理を担当する必要がある。

注意

rs_control構造体 rsc デコードに使用されるバッファを含む

デコード処理はシリアル化されていなければならないため、呼び出し元が確保しなければならない。

修正された符号数を返す。修正不能なエラーの場合は-EBADMSGを返す。カウントにはパリティのエラーも含まれる。
