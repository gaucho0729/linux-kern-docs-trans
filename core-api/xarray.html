概要¶

XArrayは、非常に大きなポインタ配列のように振る舞う抽象データ型です。ハッシュや従来の可変長配列と同じようなニーズを満たします。ハッシュとは異なり、キャッシュ効率的に次のエントリや前のエントリに移動できるようにします。可変長配列とは異なり、配列を拡張するにはデータのコピーやMMUマッピングの変更が不要です。二重連結リストよりもメモリ効率が高く、並列処理可能でキャッシュフレンドリーです。RCUを活用してロックなしで検索が可能です。

使用されるインデックスが密集していれば、XArrayの実装は効率的です。オブジェクトをハッシュ化してそのハッシュをインデックスとして使用すると性能が低下します。XArrayは小さなインデックスに最適化されていますが、大きなインデックスでも良好なパフォーマンスを発揮します。インデックスがより大きい場合、XArrayは適していない可能性があります。 ULONG_MAX ページキャッシュがXArrayの最も重要なユーザーです。

通常のポインタはXArrayに直接格納できます。4バイトアライメントが必要で、これはの返すポインタやalloc_page()の返すポインタでは常に成立します。 kmalloc() 任意のユーザー空間ポインタや関数ポインタではこの条件が満たされません。静的配列で確保されたオブジェクトへのポインタを格納できますが、そのオブジェクトは少なくとも4バイトのアライメントを備える必要があります。

XArrayには0からまでの整数を格納することもできます。 LONG_MAX まずを呼び出してエントリに変換する必要があります。 xa_mk_value()XArrayからエントリを取得した際、それが値エントリかどうかを確認するにはを呼び出します。 xa_is_value()これを整数に戻すために呼び出します xa_to_value().

一部のユーザーは、XArrayに保存するポインタをタグ付けしたいと考えています。呼び出すことができます xa_tag_pointer() タグ付きのエントリを作成するには xa_untag_pointer() タグ付きのエントリをタグなしのポインタに戻すには、 xa_pointer_tag() エントリのタグを取得するには。タグ付きポインタは、値エントリと通常のポインタを区別するためのビットと同じビットを使用するため、特定のXArrayに値エントリを保存するかタグ付きポインタを保存するかを決定する必要があります

XArrayはIS_ERR()ポインタの保存をサポートしていません。これは値エントリや内部エントリと衝突するためです

XArrayの特徴として、範囲を占めるエントリを作成できる機能があります。一度保存されると、範囲内のどのインデックスも同じエントリを返します。どのインデックスに保存しても、すべてのインデックスに保存されます。複数インデックスのエントリは明示的に小さなエントリに分割できます、または保存する場合、 NULL どのエントリにも保存すると、XArrayはその範囲を忘れます

{
    int err;

    xa_lock_bh(&foo->array);
    err = xa_err(__xa_store(&foo->array, index, entry, GFP_KERNEL));
    if (!err)
        foo->count++;
    xa_unlock_bh(&foo->array);
    return err;
}

/* foo_erase() is only called from softirq context */
void foo_erase(struct foo *foo, unsigned long index)
{
    xa_lock(&foo->array);
    __xa_erase(&foo->array, index);
    foo->count--;
    xa_unlock(&foo->array);
}

高度なAPI¶

高度なAPIは、インターフェースが使いにくく safeguards も少なくなる代償として、より柔軟でパフォーマンスが向上します。高度なAPIは自動的にロックを取得しません。配列を変更する際には必ずxa_lockを使用する必要があります。読み取り専用操作を行う際には、xa_lockまたはRCUロックのどちらを使用するかを選択可能です。同じ配列に対して高度な操作と通常操作を混在させることも可能です。実際、通常APIは高度なAPIに基づいて実装されています。高度なAPIはGPL互換ライセンスを持つモジュールにのみ利用可能です。

高度なAPIはxa_stateに基づいています。これは、スタック上に宣言する透過的なデータ構造で、マクロを使用して宣言します。 XA_STATE() このマクロは、XArrayを走査する準備を整えたxa_stateを初期化します。これはXArray内の位置を保持するカーソルとして使用され、複数の操作を組み合わせて実行する際には毎回からやり直す必要がなく、操作の順序を維持します。

xa_stateはエラーも保持します。エラーを取得するには、 xas_error() を呼び出します。すべての操作は、xa_stateがエラー状態にあるかどうかを事前に確認してから進みますので、各呼び出し後にエラーを確認する必要はありません。連続的に複数の呼び出しを実行し、適切なタイミングで一度だけエラーを確認するだけでよいです。現在、XArrayコード自体が生成するエラーは ENOMEM および EINVALのみですが、任意のエラーをサポートしており、必要に応じて xas_set_err() を呼び出すことができます。

XArrayは複数のインデックスを結びつける機能を持ち、1つのインデックスに対する操作がすべてのインデックスに影響を及ぼす。たとえば、どのインデックスにも保存を行うと、どのインデックスからも取得したエントリの値が変更される。どのインデックスにもマークを設定またはクリアすると、すべての結びつけられたインデックスにも同じ操作が行われる。現在の実装では、2の累乗に合わせた範囲のみを結びつけることができる。例えば、インデックス64-127は結びつけられるが、2-6は結びつけられない。これはメモリを大幅に節約できる。例えば、512のエントリを結びつけることで4KB以上のメモリ節約が可能である。

マルチインデックスエントリを作成するには、以下のコマンドを使用する。 XA_STATE_ORDER() または xas_set_order() その後、以下のコールバックを呼び出す。 xas_store()。コールバックを呼び出す際、マルチインデックスxa_stateを使用すると、ツリー内の正しい位置にxa_stateを移動するが、返却値は意味を持たず、内部エントリ xas_load() であっても、範囲内にエントリが存在する場合でも、返却値は意味を持たない。コールバックを呼び出す際、 NULL 範囲内にエントリが存在しても、返却値は意味を持たない。 xas_find_conflict() 範囲内の最初のエントリを返します。ただし、 NULL 範囲内にエントリが存在しない場合。イテレータは xas_for_each_conflict() 指定された範囲と重なるすべてのエントリをイテレータで処理します。

もし xas_load() 複数インデックスのエントリに遭遇すると、xa_state内のxa_indexは変更されません。XArrayをイテレータ処理するか、呼び出すときに xas_find()、もし初期インデックスがマルチインデックスエントリの中間にある場合、変更されません。その後の呼び出しまたは反復処理では、インデックスが範囲内の最初のインデックスに移動します。各エントリは一度しか返されません。エントリが占有するインデックス数に関係なくです。

Using xas_next() または xas_prev() マルチインデックスエントリではxa_stateのサポートはできません。これらの関数をマルチインデックスエントリで使用すると、姉妹エントリが表示されます。これらは呼び出し元でスキップする必要があります。
