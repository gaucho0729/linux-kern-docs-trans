ローカルアトミック操作のセマンティクス¶

著者

Mathieu Desnoyers

このドキュメントでは、ローカルアトミック操作の目的、任意のアーキテクチャで実装する方法、そして適切に使用する方法を説明します。また、メモリの書き込み順序が重要である場合に、複数のCPU間でローカル変数を読み取る際の注意点も強調しています。

注意

注意してください local_t ベース操作は一般的なカーネル用途には推奨されていません。代替として、 this_cpu 操作を使用してください。特に特殊な目的がない限り、ほとんどのカーネルでの local_t の使用は this_cpu 操作に置き換えられています。 this_cpu 操作は、再配置と local_t のセマンティクスを1つのインストラクションで組み合わせ、よりコンパクトで高速に実行されるコードを生成します。

ローカルアトミック操作の目的¶

ローカルアトミック操作は、高速で再入可能なCPUごとのカウンターを提供することを目的としています。標準のアトミック操作のパフォーマンスコストを最小化するために、LOCKプレフィックスとメモリバリアを通常必要とする同期を削除します。

高速なCPUごとのアトミックカウンターは多くの場合役立ちます：割込みハンドラの保護に割込みを無効化する必要がなく、NMIハンドラでも整合性のあるカウンターが可能です。トレース目的やさまざまなパフォーマンスモニタリングカウンターに特に有用です。

ローカルアトミック操作は、データを所有するCPUに対してのみ変数の修飾がアトミックであることを保証します。したがって、複数のCPUが local_t データを書き込むことを防ぐためには、注意が必要です。これは、CPUごとのデータを使用し、プリエンプション安全なコンテキスト内で変更することによって実現します。ただし、 local_t データは任意のCPUから読み取ることができます：その場合、所有CPUの他のメモリ書き込みに対して順序が逆になるように見えます。

特定のアーキテクチャでの実装¶

標準のアトミック操作をわずかに変更することで実現可能です：UPバリアントのみを保持します。これは通常、i386およびx86_64ではLOCKプレフィックス（LOCK prefix）を削除し、SMP同期バリアをすべて削除することを意味します。アーキテクチャがSMPとUPで異なる動作を持たない場合、 asm-generic/local.h をアーキテクチャの local.h に含めることで十分です。

以下の local_t 型は透過的型として定義され、 signed long を構造体に埋め込むことで実現されます。これにより、この型から atomic_long_t 型へのキャストは失敗します。定義は以下のようになります： long ローカルアトミック操作を使用する際のルール

typedef struct { atomic_long_t a; } local_t;

ローカルアトミック操作の使い方¶

#include <linux/percpu.h>
#include <asm/local.h>

static DEFINE_PER_CPU(local_t, counters) = LOCAL_INIT(0);

カウント¶

カウントは符号付き長整数のすべてのビットで行われます。

プリエンプション可能なコンテキストでは、 get_cpu_var() および put_cpu_var() ローカルアトミック操作の周辺で使用する: これにより、ペアーコンピュータ変数への書き込みアクセスの周辺でプリエンプションが無効になります。例えば:

local_inc(&get_cpu_var(counters));
put_cpu_var(counters);

すでにプリエンプション安全なコンテキストにいる場合は、 this_cpu_ptr() 代わりに:

local_inc(this_cpu_ptr(&counters));

カウンタの読み取り¶

これらのローカルカウンタは、外国のCPUから読み取って合計を計算できます。注意点として、local_readによって複数のCPUで見られるデータは、データを所有するCPUでの他のメモリ書き込み操作に対して順序が無視される可能性があるため、

long sum = 0;
for_each_online_cpu(cpu)
        sum += local_read(&per_cpu(counters, cpu));

複数のCPU間でリソースへのアクセスを同期するためにリモートのlocal_readを使用する場合、明示的な smp_wmb() および smp_rmb() メモリバリアーをそれぞれの書き込みCPUと読み込みCPUで使用する必要があります。バッファに書かれたバイト数をカウントする変数として使用する場合など、このような状況が発生します。 local_t 変数をバッファに書かれたバイト数のカウンタとして使用する場合: バッファの書き込みとカウンタのインクリメントの間に smp_wmb() バッファの書き込みとカウンタのインクリメントの間に、 smp_rmb() カウンタの読み取りとバッファの読み取りの間に

以下は、ペアーコンピュータカウンタを実装するサンプルモジュールです。 local.h:

/* test-local.c
 *
 * Sample module for local.h usage.
 */


#include <asm/local.h>
#include <linux/module.h>
#include <linux/timer.h>

static DEFINE_PER_CPU(local_t, counters) = LOCAL_INIT(0);

static struct timer_list test_timer;

/* IPI called on each CPU. */
static void test_each(void *info)
{
        /* Increment the counter from a non preemptible context */
        printk("Increment on cpu %d\n", smp_processor_id());
        local_inc(this_cpu_ptr(&counters));

        /* This is what incrementing the variable would look like within a
         * preemptible context (it disables preemption) :
         *
         * local_inc(&get_cpu_var(counters));
         * put_cpu_var(counters);
         */
}

static void do_test_timer(unsigned long data)
{
        int cpu;

        /* Increment the counters */
        on_each_cpu(test_each, NULL, 1);
        /* Read all the counters */
        printk("Counters read from CPU %d\n", smp_processor_id());
        for_each_online_cpu(cpu) {
                printk("Read : CPU %d, count %ld\n", cpu,
                        local_read(&per_cpu(counters, cpu)));
        }
        mod_timer(&test_timer, jiffies + 1000);
}

static int __init test_init(void)
{
        /* initialize the timer that will increment the counter */
        timer_setup(&test_timer, do_test_timer, 0);
        mod_timer(&test_timer, jiffies + 1);

        return 0;
}

static void __exit test_exit(void)
{
        del_timer_sync(&test_timer);
}

module_init(test_init);
module_exit(test_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("Mathieu Desnoyers");
MODULE_DESCRIPTION("Local Atomic Ops");
