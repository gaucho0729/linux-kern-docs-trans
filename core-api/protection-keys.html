Memory Protection Keys¶

メモリ保護キー（PKU とも呼ばれる PKEYs）は、インテルのスカリック（および後継）「スケーラブルプロセッサ」サーバーCPUに搭載されている機能です。今後の非サーバーインテル製品およびAMDプロセッサにも導入される予定です。

この機能をテストまたは使用したいユーザーは、アマゾンのEC2 C5インスタンスで利用可能で、Ubuntu 17.04イメージを使用して動作確認済みです。

メモリ保護キーは、アプリケーションが保護ドメインを変更する際にページテーブルの変更を必要とせずにページベースの保護を強制するメカニズムを提供します。これにより、各ページテーブルエントリに4つの以前無視されていたビットを「保護キー」として割り当て、16種類のキーが利用可能になります。

また、ユーザーがアクセス可能なレジスタ（PKRU）が新たに追加され、各キーに対して2つの別々のビット（アクセス無効化と書き込み無効化）が用意されています。CPUレジスタであるため、PKRUは本来的にスレッドローカルであり、他のスレッドとの間で異なる保護設定を各スレッドに提供する可能性があります。

読み書き用の新しい命令（RDPKRU/WRPKRU）が追加されました。この機能は64ビットモードでのみ利用可能で、理論的にはPAE PTEsにもスペースがありますが、データアクセスでのみ実行権限が強制され、インストラクションフェッチには影響を与えません。

システムコール¶

pkeysと直接やり取りするシステムコールは3つあります：

int pkey_alloc(unsigned long flags, unsigned long init_access_rights)
int pkey_free(int pkey);
int pkey_mprotect(unsigned long start, size_t len,
                  unsigned long prot, int pkey);

pkeyを使用する前に、pkey_alloc()でまず割り当てなければなりません。アプリケーションはWRPKRU命令を直接呼び出して、キーで保護されたメモリのアクセス権を変更します。この例ではWRPKRUがC関数pkey_set()でラップされています。

int real_prot = PROT_READ|PROT_WRITE;
pkey = pkey_alloc(0, PKEY_DISABLE_WRITE);
ptr = mmap(NULL, PAGE_SIZE, PROT_NONE, MAP_ANONYMOUS|MAP_PRIVATE, -1, 0);
ret = pkey_mprotect(ptr, PAGE_SIZE, real_prot, pkey);
... application runs here

アプリケーションが'ptr'のデータを更新する必要がある場合、アクセスして更新し、その後書き込みアクセスを解除できます：

pkey_set(pkey, 0); // clear PKEY_DISABLE_WRITE
*ptr = foo; // assign something
pkey_set(pkey, PKEY_DISABLE_WRITE); // set PKEY_DISABLE_WRITE again

メモリを解放する際には、もはや使用されないためpkeyも同時に解放されます：

munmap(ptr, PAGE_SIZE);
pkey_free(pkey);

注意

pkey_set()はRDPKRUおよびWRPKRU命令をラップした関数です。実装例はtools/testing/selftests/x86/protection_keys.cにあります。

動作¶

カーネルは保護キーが通常のmprotect()の挙動と整合性を保つようにします。例えば以下を行った場合：

mprotect(ptr, size, PROT_NONE);
something(ptr);

保護キーを使用して同じ効果が得られます：

pkey = pkey_alloc(0, PKEY_DISABLE_WRITE | PKEY_DISABLE_READ);
pkey_mprotect(ptr, size, PROT_READ|PROT_WRITE, pkey);
something(ptr);

something()が'ptr'への直接アクセスのように：

*ptr = foo;

またはカーネルがアプリケーションの代わりにアクセスを行う場合のようにread()でアクセスする場合でも同様です：

read(fd, ptr, 1);

カーネルは両方の場合にSIGSEGVを送信しますが、保護キーの違反の場合にはsi_codeがSEGV_PKERRに設定され、通常のmprotect()の許可が違反された場合にはSEGV_ACCERRになります。
