リングバッファ¶

著者

David Howells <dhowells@redhat.com>

著者

Paul E. McKenney <paulmck@linux.ibm.com>

Linuxはリングバッファを実装するために使用できるいくつかの機能を提供しています。このような機能は2つのセットに分類されます:

  1. 2のべき乗サイズのバッファに関する情報を取得するための便利な関数。

  2. バッファ内のオブジェクトのプロデューサーとコンシューマーがロックを共有したくない場合のメモリバリア。

これらの機能を使用するには、以下の説明のように、ただ一つのプロデューサーとただ一つのコンシューマーが必要です。複数のプロデューサーを処理するにはそれらをシリアル化し、複数のコンシューマーを処理するにはそれらをシリアル化することで可能です。

リングバッファとは何ですか？¶

まず、リングバッファとは何ですか？リングバッファは、固定された有限のサイズのバッファで、その中に2つのインデックスがあります。

  1. 「ヘッド」インデックス - プロデューサーがバッファにアイテムを挿入するポイント。

  2. 「テール」インデックス - コンシューマーがバッファ内の次のアイテムを見つけるポイント。

通常、テールポインタがヘッドポインタと等しい場合、バッファは空です。ヘッドポインタがテールポインタよりも1つ小さい場合、バッファは満杯になります。

アイテムが追加されるたびにヘッドインデックスがインクリメントされ、アイテムが削除されるたびにテールインデックスがインクリメントされます。テールインデックスはヘッドインデックスを越えてはならないため、バッファの終わりに達した場合、両方のインデックスは0に戻る必要があります。これにより、バッファを介して無限のデータが流れることが可能になります。

通常、アイテムはすべて同じ単位サイズですが、以下の技術を使用するには厳密には必要ではありません。バッファに複数のアイテムまたは可変サイズのアイテムを含める場合、インデックスを1より多く増やすことができます。ただし、どちらのインデックスも他を越えてはなりません。実装者は注意が必要です。なぜなら、1単位以上の領域がバッファの終わりを巻き取り、2つのセグメントに分断される可能性があるからです。

2のべき乗サイズのバッファの測定¶

任意のサイズのリングバッファの占有量または残り容量を計算するには通常、modulus（除算）命令を使用する遅い操作が必要です。しかし、バッファのサイズが2のべき乗である場合、より速いbitwise-AND命令を使用できます。

Linuxは2のべき乗サイズのリングバッファを処理するためのマクロセットを提供しています。これらは以下の通り利用できます:

#include <linux/circ_buf.h>

マクロは以下の通りです:

  1. バッファの残り容量を測定する:

    CIRC_SPACE(head_index, tail_index, buffer_size);

    これは、アイテムを挿入できるバッファ内の空き容量[1]を返します。

  2. バッファ内の最大連続即時空き領域を測定する:

    CIRC_SPACE_TO_END(head_index, tail_index, buffer_size);

    バッファ[1]にアイテムを即座に挿入できる連続する空きスペースの量を返します。

  3. バッファの占有量を測定する：

    CIRC_CNT(head_index, tail_index, buffer_size);

    バッファ[2]に現在格納されているアイテムの数を返します。

  4. 非巻き戻しの占有量を測定する：

    CIRC_CNT_TO_END(head_index, tail_index, buffer_size);

    バッファから巻き戻しせずに抽出できる連続するアイテム[2]の数を返します。

これらのマクロは通常、0からbuffer_size-1の間の値を返しますが、

  1. CIRC_SPACE*()はプロデューサーで使用することを意図しています。プロデューサーにとっては、ヘッドインデックスを制御しているため下限値を返しますが、コンシューマーが別のCPUでバッファを消費している可能性があり、テールインデックスを動かしているため、

    コンシューマーにとっては、プロデューサーが空間を消費している可能性があるため上限値を示します。

  2. CIRC_CNT*()はコンシューマーで使用することを意図しています。コンシューマーにとっては、テールインデックスを制御しているため下限値を返しますが、プロデューサーが別のCPUでバッファを埋めている可能性があり、ヘッドインデックスを動かしているため、

    プロデューサーにとっては、コンシューマーがバッファを空にしている可能性があるため上限値を示します。

  3. サードパーティにとって、プロデューサーとコンシューマーがインデックスに書いたデータがどの順序で見えるかは保証されません。これらは独立しており、異なるCPUで行われる可能性があるため、このような状況では結果は単なる推測であり、負の値になる可能性もあります。

環状バッファとメモリーバリアーを併用する¶

環状バッファとメモリーバリアーを併用することで、以下のような必要性を回避できます：

  1. 両端へのアクセスを1つのロックで制御する必要があり、バッファを同時に埋めたり空にしたりできるようにする；および

  2. アトミックカウンタ操作を使用する。

この操作には2つの側面があります：バッファを埋めるプロデューサーと、バッファを空にするコンシューマーです。同時に1つのものだけがバッファを埋めるべきであり、1つのものだけがバッファを空にするべきですが、両方の側面は同時に動作できます。

プロデューサー¶

プロデューサーは以下のように見えます：

spin_lock(&producer_lock);

unsigned long head = buffer->head;
/* The spin_unlock() and next spin_lock() provide needed ordering. */
unsigned long tail = READ_ONCE(buffer->tail);

if (CIRC_SPACE(head, tail, buffer->size) >= 1) {
        /* insert one item into the buffer */
        struct item *item = buffer[head];

        produce_item(item);

        smp_store_release(buffer->head,
                          (head + 1) & (buffer->size - 1));

        /* wake_up() will make sure that the head is committed before
         * waking anyone up */
        wake_up(consumer);
}

spin_unlock(&producer_lock);

これはCPUに新しいアイテムの内容がヘッドインデックスがコンシューマーに利用可能になる前に書き込まれなければならないと指示し、その後、コンシューマーが目覚める前にヘッドインデックスの更新がCPUに指示されるようにします。

wake_up()関数は、実際に何かが目覚めた場合を除き、バリアを保証しないことに注意してください。したがって、順序を保証するためにこれに依存することはできません。ただし、配列には常に1つの要素が空の状態で残ります。そのため、プロダクターは現在コンシューマーが読み込んでいる要素を破壊する可能性を防ぐため、少なくとも2つの要素を生成する必要があります。したがって、コンシューマーの連続する呼び出し間でのアンロック・ロックペアは、コンシューマーが特定の要素を空にしたことを示すインデックスの読み取りと、プロダクターが同じ要素に書いたデータの間の必要な順序を提供します。

コンシューマー¶

コンシューマーは以下のように見えます:

spin_lock(&consumer_lock);

/* Read index before reading contents at that index. */
unsigned long head = smp_load_acquire(buffer->head);
unsigned long tail = buffer->tail;

if (CIRC_CNT(head, tail, buffer->size) >= 1) {

        /* extract one item from the buffer */
        struct item *item = buffer[tail];

        consume_item(item);

        /* Finish reading descriptor before incrementing tail. */
        smp_store_release(buffer->tail,
                          (tail + 1) & (buffer->size - 1));
}

spin_unlock(&consumer_lock);

これにより、CPUはインデックスが最新であることを確認した上で新しいアイテムを読み込むよう指示され、その後、CPUがアイテムを読み終わるのを待ってから新しいテールポインタを書き込むことになります。これによりアイテムが削除されます。

インデックスの読み取りにはREAD_ONCE()とsmp_load_acquire()が使用されていることに注意してください。これによりコンパイラがキャッシュされた値を破棄したり再読み込みしたりしないようにします。インデックスが一度しか使用されないことを保証できる場合、これは厳密には必要ありません。smp_load_acquire()はさらにCPUに、その後のメモリ参照と順序を強制します。同様に、両方のアルゴリズムでsmp_store_release()が使用され、スレッドのインデックスを書き込みます。これは、並行して読み取れるものに書き込んでいることを記録し、コンパイラがストアを破壊しないようにし、以前のアクセスとの順序を強制します。
