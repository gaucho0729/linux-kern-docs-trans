メモリホットプラグ¶

メモリホットプラグイベント通知¶

ホットプラグイベントは通知キューに送信されます。

次の6種類の通知が定義されています。 include/linux/memory.h:

MEM_GOING_ONLINE

新しいメモリが利用可能になる前に生成され、サブシステムがメモリを処理できるように準備するためです。この時点ではページアロケータは新しいメモリから割り当てを行うことができません。

MEM_CANCEL_ONLINE

MEM_GOING_ONLINEが失敗した場合に生成されます。

MEM_ONLINE

メモリが正常にオンラインにされたときに生成されます。コールバックは新しいメモリからページを割り当てることができます。

MEM_GOING_OFFLINE

メモリをオフラインにするプロセスを開始するためのイベントです。この時点でメモリからの割り当てはできなくなりましたが、オフラインにするメモリの一部はまだ使用中です。コールバックはサブシステムが認識しているメモリを指定されたメモリブロックから解放できます。

MEM_CANCEL_OFFLINE

MEM_GOING_OFFLINEが失敗した場合に生成されます。メモリブロックが再び利用可能になります。

MEM_OFFLINE

メモリがオフライン化された後に生成されます。

コールバックルーチンを登録するには次の関数を呼び出します:

hotplug_memory_notifier(callback_func, priority)

優先度が高いコールバック関数は、優先度が低いものよりも先に呼び出されます。

コールバック関数は次のプロトタイプを持つ必要があります:

int callback_func(
  struct notifier_block *self, unsigned long action, void *arg);

コールバック関数の最初の引数(self)は、通知チェーンのブロックポインタで、この関数自身を指しています。第二引数(action)は上記のイベントタイプのいずれかです。第三引数(arg)はstruct memory_notifyポインタを渡します:

struct memory_notify {
        unsigned long start_pfn;
        unsigned long nr_pages;
        int status_change_nid_normal;
        int status_change_nid_high;
        int status_change_nid;
}

  • start_pfnはオンライン/オフラインメモリの開始PFNです。

  • nr_pagesはオンライン/オフラインメモリのページ数です。

  • status_change_nid_normalはnodemaskのN_NORMAL_MEMORYが設定/クリアされるノードIDです（-1の場合はnodemaskのステータスは変更されません）。

  • status_change_nid_highはnodemaskのN_HIGH_MEMORYが設定/クリアされるノードIDです（-1の場合はnodemaskのステータスは変更されません）。

  • status_change_nidはnodemaskのN_MEMORYが設定/クリアされるノードIDです（-1の場合はnodemaskのステータスは変更されません）。これはメモリレスノードがメモリをオンラインで取得し、ノードがすべてのメモリを失うことを意味します。

    status_changed_nid*が0以上の場合、コールバックは必要に応じてノード構造体を作成/破棄する必要があります。

コールバックルーチンは次の値のいずれかを返します: NOTIFY_DONE, NOTIFY_OK, NOTIFY_BAD, NOTIFY_STOP（定義は include/linux/notifier.h

NOTIFY_DONEおよびNOTIFY_OKは後続処理に影響を与えません。

NOTIFY_BADは、MEM_GOING_ONLINE、MEM_GOING_OFFLINE、MEM_ONLINE、またはMEM_OFFLINEアクションに対してホットプラグをキャンセルする応答として使用されます。これにより、通知キューの処理が停止されます。

NOTIFY_STOPは、通知キューの処理を停止します。

ロックの内部構造¶

メモリブロックデバイス（つまり通常のRAM）を使用してメモリを追加/削除する際、device_hotplug_lockを保持する必要があります:

  • オンライン/オフラインリクエスト（例：sysfs経由）に対して同期を取る。これにより、メモリブロックデバイスはメモリが完全に追加された後からユーザー空間からアクセス可能（.online/.state属性）となる。メモリを削除する際には、誰もクリティカルセクション内にいないことが保証される。

  • CPUホットプラグや類似操作（例：ACPIやPPCに関連）に対して同期を取る。

特に、メモリ追加時にデバイスホットプラグロックを使用してロックインバージョンを回避するが、ユーザー空間が予想以上に早くそのメモリをオンライン化しようとした場合に発生する可能性がある。

  • device_online()はまずdevice_lock()を取得し、その後mem_hotplug_lockを取得する。

  • add_memory_resource()はまずmem_hotplug_lockを取得し、その後device_lock()を取得する（デバイス作成中にbus_add_device()で行われる）。

デバイスがdevice_lock()を取得する前からユーザー空間に見えるため、ロックインバージョンが発生する可能性がある。

メモリのオンライン/オフライン操作はdevice_online()/device_offline()を通じて行うべきである。これによりsysfs経由の操作と正しく同期される。online_typeを保護するなど、device_hotplug_lockを保持することを推奨する。

メモリの追加/削除/オンライン/オフラインや、異質/デバイスメモリの追加/削除を行う際には、メモリホットプラグ操作をシリアル化するためにmem_hotplug_lockを書き込みモードで常に保持するべきである（例：グローバル/ゾーン変数へのアクセス）。

さらに、mem_hot,plug_lock（device_hotplug_lockとは異なり）は読み取りモードで使用することで、get_online_mems/put_online_memsの実装が非常に効率的になるため、メモリが消失するのをコードが防ぐことができる。
