padata並列実行メカニズム¶

日付

2020年5月

padataは、カーネルが複数のCPU上でジョブを並列に実行できるようにするメカニズムであり、必要に応じて順序を保持しながらジョブを分散処理できます。

IPsecのために最初に開発され、大量のパケットを再配列せずに暗号化および復号処理を行う必要があるため、現在はpadataのシリアル化されたジョブサポートの唯一の利用者です。

padataはまた、スレッド間でロードバランスを図りながらスレッド間で調整しながらジョブを均等に分割して実行するマルチスレッドジョブもサポートしています。

シリアル化されたジョブの実行¶

初期化¶

padataを用いてシリアル化されたジョブを実行するための最初のステップは、ジョブの実行方法を全体的に制御するためのpadata_instance構造体を設定することです:

#include <linux/padata.h>

struct padata_instance *padata_alloc(const char *name);

‘name’は単にインスタンスを識別します。

次に、padata_shellを割り当ててpadataの初期化を完了します:

struct padata_shell *padata_alloc_shell(struct padata_instance *pinst);

padata_shellは、ジョブをpadataに送信するために使用され、複数のこのようなジョブを独立してシリアル化するためのものです。padata_instanceは、1つまたは複数のpadata_shellと関連付けられることができ、それぞれが別個のジョブ系列を許可します。

cpumaskの変更¶

ジョブを実行するCPUは、2つの方法で変更できます: プログラム的に padata_set_cpumask() またはsysfs経由で。前者は次のように定義されています:

int padata_set_cpumask(struct padata_instance *pinst, int cpumask_type,
                       cpumask_var_t cpumask);

ここでcpumask_typeはPADATA_CPU_PARALLELまたはPADATA_CPU_SERIALのいずれかです。parallel cpumaskは、このインスタンスに送信されたジョブを並列に実行するためのプロセッサを記述し、serial cpumaskはシリアル化コールバックプロセッサとして使用可能なプロセッサを定義します。cpumaskは新しいcpumaskを指定します。

インスタンスのcpumask用のsysfsファイルがある場合があります。たとえば、pcryptは/sys/kernel/pcrypt/<instance-name>にあります。インスタンスのディレクトリ内には、parallel_cpumaskとserial_cpumaskという2つのファイルがあり、ビットマスクをファイルにエコーバックすることで、どちらのcpumaskも変更できます。たとえば:

echo f > /sys/kernel/pcrypt/pencrypt/parallel_cpumask

これらのファイルのいずれかを読み込むと、ユーザーが提供したcpumaskが表示され、これは‘usable’ cpumaskとは異なる場合があります。

Padataは内部で2組のcpumasksを保持しており、ユーザーが提供したcpumasksと「利用可能な」cpumasksです。(各ペアは並列とシリアルのcpumaskから成り立っています。) ユーザーが提供したcpumasksはインスタンス割当時にすべての可能なCPUをデフォルトとしており、上記のように変更可能です。利用可能なcpumasksは常にユーザーが提供したcpumasksのサブセットであり、ユーザーが提供したマスク内のオンラインCPUのみを含みます。これらがpadataが実際に使用するcpumasksです。したがって、padataにオフラインCPUを含むcpumaskを提供しても問題ありません。ユーザーが提供したcpumask内のオフラインCPUがオンラインになった場合、padataはそのCPUを使用します。

CPUマスクの変更はコストのかかる操作であるため、頻繁に行うべきではありません。

ジョブの実行¶

実際にpadataインスタンスに作業を送信するには、padata_priv構造体を作成する必要があります。これは1つのジョブを表します:

struct padata_priv {
    /* Other stuff here... */
    void                    (*parallel)(struct padata_priv *padata);
    void                    (*serial)(struct padata_priv *padata);
};

この構造体はおそらく、実行する作業に特化したより大きな構造体の中に埋め込まれます。ほとんどのフィールドはpadata専用ですが、初期化時に構造体をゼロクリアする必要があります。また、parallel()とserial()関数を提供する必要があります。これらの関数は、後ほど見るように作業の実行中に呼び出されます。

ジョブの送信は以下の通り行われます:

int padata_do_parallel(struct padata_shell *ps,
                       struct padata_priv *padata, int *cb_cpu);

psとpadata構造体は上記のように設定する必要があります。cb_cpuはジョブが完了した際の最終コールバックに使用する推奨CPUを指し、現在のインスタンスのCPUマスク内に含まれていなければ、cb_cpuポインタは実際に選ばれたCPUを指すように更新されます。返却値は padata_do_parallel() 成功時はゼロとなり、ジョブが進行中であることを示します。-EBUSYはインスタンスのCPUマスクを別の場所で操作していることを示し、-EINVALはcb_cpuがシリアルcpumaskに含まれていない、または並列またはシリアルcpumasksにオンラインCPUが存在しない、または停止中のインスタンスを示します。

各ジョブは、 padata_do_parallel() に送信され、それぞれ1つのCPUで上記のparallel()関数の呼び出しに渡されます。複数のジョブを送信することで真の並列性が達成されます。parallel()関数はソフトウェア割込みが無効になっている状態で実行されるため、スリープできません。parallel()関数はpadata_priv構造体のポインタを単一のパラメータとして受け取り、実際の作業に関する情報はおそらく container_of() を用いて包含する構造体を検索して取得します。

parallel()は戻り値を持たないことに注意してください。padataサブシステムは、parallel()がこの時点でジョブの責任を引き受けることを想定しています。この呼び出し中にジョブが完了する必要はありませんが、parallel()が未処理の作業を残した場合、その作業が完了する前に新しいジョブを呼び出す準備が必要です。

ジョブのシリアル化¶

ジョブが完了した場合、parallel()（または実際に作業を終了する関数）は、以下の関数を呼び出してpadataにその事実を通知する必要があります：

void padata_do_serial(struct padata_priv *padata);

将来のどこかの時点で、 padata_do_serial() が、padata_priv構造体内のserial()関数を呼び出します。この呼び出しは、初期のparallel()呼び出しで指定されたCPU上で行われます。 padata_do_parallel()この呼び出しも、ローカルソフトウェア割込みが無効になっている状態で実行されます。注意点として、この呼び出しは、padataコードがジョブを提出された順番に完了させるために慎重に遅延されることがあります。

破壊¶

padataインスタンスのクリーンアップは、割当順に逆順で対応する2つのfree関数を呼び出すことで予測可能です：

void padata_free_shell(struct padata_shell *ps);
void padata_free(struct padata_instance *pinst);

ユーザーは、上記のいずれかを呼び出す前に、すべての未処理ジョブが完了していることを保証する責任があります。

マルチスレッドジョブの実行¶

マルチスレッドジョブはメインスレッドとゼロ個以上のアシスタントスレッドを持ち、メインスレッドがジョブに参加した後、すべてのアシスタントスレッドが完了するのを待機します。padataはジョブを「チャンク」と呼ばれる単位に分割し、チャンクはスレッドが1回のスレッド関数呼び出しで完了するジョブの一部です。

マルチスレッドジョブを実行するにはユーザーが行うべきことは3つあります。まず、padata_mt_job構造体を定義してジョブを説明します（インターフェースセクションで説明します）。これはスレッド関数へのポインタを含み、padataがスレッドにジョブチャンクを割り当てたときに呼び出します。次に、スレッド関数を定義します。これは3つの引数を受け取り、 start, end, and arg、ここで最初の2つはスレッドが処理する範囲を指定し、最後のものはジョブの共有状態へのポインタ（必要に応じて）です。共有状態を準備します。これは通常メインスレッドのスタック上に割り当てられます。最後に、 padata_do_multithreaded()を呼び出します。ジョブが完了するとこの関数は戻ります。

インターフェース¶

struct padata_priv¶

1つのジョブを表します

定義

struct padata_priv {
  struct list_head        list;
  struct parallel_data    *pd;
  int cb_cpu;
  unsigned int            seq_nr;
  int info;
  void (*parallel)(struct padata_priv *padata);
  void (*serial)(struct padata_priv *padata);
};

メンバ

list

リストエントリで、padataリストに接続するために使用します。

pd

内部制御構造体へのポインタです。

cb_cpu

シリアル化用コールバックCPU

seq_nr

並列処理されたデータオブジェクトのシーケンス番号

info

並列からシリアル関数に情報を渡すために使用します。

parallel

並列実行関数

serial

シリアル完了関数

struct parallel_data¶

内部制御構造体、使用中のCPUマスクに依存するすべての要素をカバー。

定義

struct parallel_data {
  struct padata_shell             *ps;
  struct padata_list              __percpu *reorder_list;
  struct padata_serial_queue      __percpu *squeue;
  atomic_t refcnt;
  unsigned int                    seq_nr;
  unsigned int                    processed;
  int cpu;
  struct padata_cpumask           cpumask;
  struct work_struct              reorder_work;
  spinlock_t lock;
};

メンバ

ps

padata_shellオブジェクト。

reorder_list

パーセルCPU再配置リスト。

squeue

シリアル化用に使用されるパーセルCPU padataキュー。

refcnt

このparallel_dataに参照を保持しているオブジェクトの数。

seq_nr

並列処理されたデータオブジェクトのシーケンス番号

processed

すでに処理されたオブジェクトの数。

cpu

次に処理するCPU。

cpumask

並列およびシリアルワーカーで使用中のCPUマスク。

reorder_work

再配置用ワーク構造体。

lock

再配置ロック。

struct padata_shell¶

Wrapper around struct parallel_data、その目的は、RCUを用いて下位の制御構造体を飛ばし的に置き換えることを可能にする。

定義

struct padata_shell {
  struct padata_instance          *pinst;
  struct parallel_data __rcu      *pd;
  struct parallel_data            *opd;
  struct list_head                list;
};

メンバ

pinst

padatインスタンス。

pd

飛ばし的に置き換え可能な実際のparallel_data構造体。

opd

padata_replaceで解放される古いpdへのポインタ。

list

padata_instanceリスト内のリストエントリ。

struct padata_mt_job¶

1つのマルチスレッドジョブを表す。

定義

struct padata_mt_job {
  void (*thread_fn)(unsigned long start, unsigned long end, void *arg);
  void *fn_arg;
  unsigned long           start;
  unsigned long           size;
  unsigned long           align;
  unsigned long           min_chunk;
  int max_threads;
};

メンバ

thread_fn

padataスレッドが処理する各作業チャンクに対して呼ばれる。

fn_arg

スレッド関数の引数。

start

ジョブの開始位置（単位はジョブ固有）。

size

このノードの作業サイズ（単位はジョブ固有）。

align

スレッド関数に渡される範囲はこの境界に沿って配置され、ジョブの開始と終了を除く例外を除く。

min_chunk

ジョブ固有単位での最小チャンクサイズ。クライアントが1つのワーカースレッドが一度に処理すべき適切な作業量を伝達するためのもの。

max_threads

ジョブに使用する最大スレッド数、実際の数はタスクサイズと最小チャンクサイズに応じて少なくなる可能性がある。

struct padata_instance¶

全体的な制御構造体。

定義

struct padata_instance {
  struct hlist_node               cpu_online_node;

メンバ

cpu_online_node

CPUオンラインコールバック用のリンク。

cpu_dead_node

CPUオフラインコールバック用のリンク。

parallel_wq

並列作業用ワークキュー。

serial_wq

シリアル作業用ワークキュー。

pslist

このインスタンスにアタッチされているpadata_shellオブジェクトの一覧。

cpumask

並列およびシリアル作業用にユーザーが指定したcpumasks。

kobj

padataインスタンスのカーネルオブジェクト。

lock

padataインスタンスのロック。

flags

padataフラグ。

int padata_do_parallel(struct padata_shell *ps, struct padata_priv *padata, int *cb_cpu)¶

padata並列化関数

パラメータ

struct padata_shell *ps

padatashell

struct padata_priv *padata

並列化されるオブジェクト

int *cb_cpu

シリアル化コールバック関数が実行されるCPUへのポインタ。serial cpumaskの pinst (つまりcpumask.cbcpu)にない場合、この関数はフォールバックCPUを選択し、見つからない場合は-EINVALを返します。

説明

並列化コールバック関数はBH（Bottom Half）がオフの状態で実行されます。

注意

padata_do_parallelで並列化されるすべてのオブジェクトは、padata_do_serialによって見なされる必要があります。

戻り値

成功時は0、エラー時は負のエラーコード。
