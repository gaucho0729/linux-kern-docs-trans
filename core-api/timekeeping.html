ktime accessors¶

デバイスドライバーは現在の時刻を読み取るために ktime_get() linux/timekeeping.hで宣言された多くの関連関数を使用できます。特定の用途にどちらも適切であれば、短い名前のアクセッサを使用することが推奨されます。

基本的なktime_tベースのインターフェース¶

推奨される最もシンプルな形式は、不透明なktime_tを返します。異なるクロック参照に対応する変種もあります：

ktime_t ktime_get(void)¶

CLOCK_MONOTONIC

信頼性の高いタイムスタンプや短い時間間隔の正確な測定に有用です。システム起動時に開始し、スリープ中に停止します。

ktime_t ktime_get_boottime(void)¶

CLOCK_BOOTTIME

例え ktime_get()スリープ中でも停止しないです。これは、スリープ操作で他のマシンと同期する必要のあるキーパス時刻などに使用できます。

ktime_t ktime_get_real(void)¶

CLOCK_REALTIME

UNIXエポック（1970年からのUTC時刻）を基準にした時間値を返します。gettimeofday()のユーザー空間と同様です。再起動後にタイムスタンプを維持する必要がある場合に使用しますが、内部用途では避けてください（リップ秒更新やNTP調整、settimeofday()操作により時刻が逆戻りする可能性があります）。

ktime_t ktime_get_clocktai(void)¶

CLOCK_TAI

例え ktime_get_real()UTCではなく国際原子時（TAI）を参照します。リップ秒更新によるジャンプを防ぐため、これはカーネルではほとんど使用されません。

ktime_t ktime_get_raw(void)¶

CLOCK_MONOTONIC_RAW

例え ktime_get()ハードウェアクロックソースの速度に一致し、クロックドリフトへの（NTP）調整を行わないです。これはカーネルではほとんど必要ありません。

ナノ秒、timespec64、および秒の出力¶

上記のすべてに対して、ユーザーが要求する形式に応じて時間値を返す変種があります：

u64 ktime_get_ns(void)¶
u64 ktime_get_boottime_ns(void)¶
u64 ktime_get_real_ns(void)¶
u64 ktime_get_clocktai_ns(void)¶
u64 ktime_get_raw_ns(void)¶

通常のktime_get関数と同様ですが、それぞれの時刻参照におけるu64のナノ秒数を返します。これは一部の呼び出し元にとってより便利な場合があります。

void ktime_get_ts64(struct timespec64*)¶
void ktime_get_boottime_ts64(struct timespec64*)¶
void ktime_get_real_ts64(struct timespec64*)¶
void ktime_get_clocktai_ts64(struct timespec64*)¶
void ktime_get_raw_ts64(struct timespec64*)¶

同上ですが、時間値を'struct timespec64'として返します。これは秒とナノ秒に分離しているため、時間の表示や外部インターフェースへの渡し時に余分な割り算を避けることができます。

time64_t ktime_get_seconds(void)¶
time64_t ktime_get_boottime_seconds(void)¶
time64_t ktime_get_real_seconds(void)¶
time64_t ktime_get_clocktai_seconds(void)¶
time64_t ktime_get_raw_seconds(void)¶

時刻の粗い粒度バージョンをスカラーのtime64_tとして返します。これによりクロックハードウェアへのアクセスを回避し、最後のタイマートックの完全な秒数にセカンドを四捨五入して取得します。

粗い粒度と高速なnsアクセス¶

より専用なケースのためにいくつかの追加バリアントがあります:

ktime_t ktime_get_coarse(void)¶
ktime_t ktime_get_coarse_boottime(void)¶
ktime_t ktime_get_coarse_real(void)¶
ktime_t ktime_get_coarse_clocktai(void)¶
u64 ktime_get_coarse_ns(void)¶
u64 ktime_get_coarse_boottime_ns(void)¶
u64 ktime_get_coarse_real_ns(void)¶
u64 ktime_get_coarse_clocktai_ns(void)¶
void ktime_get_coarse_ts64(struct timespec64*)¶
void ktime_get_coarse_boottime_ts64(struct timespec64*)¶
void ktime_get_coarse_real_ts64(struct timespec64*)¶
void ktime_get_coarse_clocktai_ts64(struct timespec64*)¶

これらは非粗いバージョンより速く、精度は低く、ユーザー空間のCLOCK_MONOTONIC_COARSEおよびCLOCK_REALTIME_COARSEと対応し、ユーザー空間では利用できないboottime/tai/raw timebaseを含む同等のインターフェースです。

ここでの時刻は最後のタイマートックに対応し、CONFIG_HZ=100の場合最大で10ms前になる可能性があります（jiffies変数の読み取りと同様）。高速パスで呼び出され、秒単位の精度を期待しながらjiffiesを使用するのが難しい場合（例：inodeタイムスタンプ）にのみ有用です。ハードウェアクロックへのアクセスをスキップすることで、現代の信頼性の高いサイクルカウンターを持つマシンでは約100CPUサイクルを節約し、古いハードウェアでは最大数マイクロ秒の節約が可能です。

u64 ktime_get_mono_fast_ns(void)¶
u64 ktime_get_raw_fast_ns(void)¶
u64 ktime_get_boot_fast_ns(void)¶
u64 ktime_get_real_fast_ns(void)¶

これらのバリアントは、非マスク可能割込み（NMI）中のタイムキーパー更新中やクロックソースがオフになっているスリープ開始時など、あらゆるコンテキストから呼び出すことができます。トレースやデバッグコード、マシンチェックレポートなどに有用ですが、ほとんどのドライバでは呼び出さないべきです。時間は特定の条件でジャンプすることが許可されています。

非推奨の時間インターフェース¶

古いカーネルは別のインターフェースを使用していましたが、これらは現在フェーズアウトされていますが、ポートされているサードパーティドライバで見られる可能性があります。特に、'struct timeval'または'struct timespec'を返すすべてのインターフェースは、32ビットアーキテクチャでは2038年にtv_secメンバがオーバーフローするため、置き換えられています。これらは推奨される置き換えです:

void ktime_get_ts(struct timespec*)¶

Use ktime_get() または ktime_get_ts64() を呼び出してください。

void do_gettimeofday(struct timeval*)¶
void getnstimeofday(struct timespec*)¶
void getnstimeofday64(struct timespec64*)¶
void ktime_get_real_ts(struct timespec*)¶

ktime_get_real_ts64() 直接の置き換えですが、monotonic time（ktime_get_ts64()）および/またはktime_tベースのインターフェース（ktime_get()/ktime_get_real()).

struct timespec current_kernel_time(void)¶
struct timespec64 current_kernel_time64(void)¶
struct timespec get_monotonic_coarse(void)¶
struct timespec64 get_monotonic_coarse64(void)¶

これらは置き換えられています ktime_get_coarse_real_ts64() および ktime_get_coarse_ts64()ただし、粗粒度の時間が必要なコードは、単純な 'jiffies' を代わりに使用できます。一方で、一部のドライバーは現在、より高い解像度のアクセッサを望む場合があります。

struct timespec getrawmonotonic(void)¶
struct timespec64 getrawmonotonic64(void)¶
struct timespec timekeeping_clocktai(void)¶
struct timespec64 timekeeping_clocktai64(void)¶
struct timespec get_monotonic_boottime(void)¶
struct timespec64 get_monotonic_boottime64(void)¶

これらは置き換えられています ktime_get_raw()/ktime_get_raw_ts64(), ktime_get_clocktai()/ktime_get_clocktai_ts64() および ktime_get_boottime()/ktime_get_boottime_ts64()ただし、ユーザーにとってクロックソースの選択が重要でない場合、変換してみてください。 ktime_get()/ktime_get_ts64() 一貫性を保つために代わりに
