DMA属性¶

このドキュメントでは、linux/dma-mapping.h で定義されたDMA属性のセマンティクスについて説明します。

DMA_ATTR_WEAK_ORDERING¶

DMA_ATTR_WEAK_ORDERING は、マッピングへの読み込みと書き込みが弱い順序性を持つことを指定します。つまり、読み込みと書き込みがお互いを通過する可能性があります。

DMA_ATTR_WEAK_ORDERING の実装はプラットフォームごとにオプションであるため、実装されていないプラットフォームでは属性を無視し、デフォルト動作を示します。

DMA_ATTR_WRITE_COMBINE¶

DMA_ATTR_WRITE_COMBINE は、マッピングへの書き込みがバッファリングされることでパフォーマンスを向上させることが可能です。

DMA_ATTR_WRITE_COMBINE の実装はプラットフォームごとにオプションであるため、実装されていないプラットフォームでは属性を無視し、デフォルト動作を示します。

DMA_ATTR_NO_KERNEL_MAPPING¶

DMA_ATTR_NO_KERNEL_MAPPING は、割り当てられたバッファにカーネル仮想マッピングを作成しないようにプラットフォームに指示します。一部のアーキテクチャではこのようなマッピングの作成は非自明な作業であり、非常に限られたリソース（カーネル仮想アドレス空間やDMA一貫アドレス空間など）を消費します。この属性で割り当てられたバッファは、ユーザー空間に渡すには dma_mmap_attrs().dma_alloc_attr() で返されるポインタを間接参照しないことを保証しており、このAPIを用いることで、そのポインタをクッキーとして扱い、 dma_mmap_attrs() に渡す必要があります。dma_free_attrs() にも同様にこの属性を設定することを確認してください。

DMA_ATTR_NO_KERNEL_MAPPING の実装はプラットフォームごとにオプションであるため、実装されていないプラットフォームでは属性を無視し、デフォルト動作を示します。

DMA_ATTR_SKIP_CPU_SYNC¶

dma_map_{single,page,sg}関数ファミリは、デフォルトでは指定されたバッファをCPUドメインからデバイスドメインへ転送します。一部の高度な用途では、複数のデバイス間でバッファを共有する必要がある場合があります。これは、各デバイスごとにマッピングを個別に作成する必要があります。通常、dma_map_{single,page,sg}関数を複数回呼び出して、各デバイスのポインタを指定することで実行されます。最初の呼び出しでは、CPUキャッシュが指定された領域で同期され（通常はキャッシュがフラッシュまたは無効化される）、次の呼び出しでは他のデバイスに対して同じキャッシュ同期操作が行われます。CPUキャッシュの同期は特に大容量のバッファでは時間がかかるため、可能な限り避けることを強く推奨します。DMA_ATTR_SKIP_CPU_SYNC属性は、バッファがすでにデバイスドメインに転送されていると仮定してCPUキャッシュの同期をスキップするためのプラットフォームコードの属性です。この属性はdma_unmap_{single,page,sg}関数ファミリにも使用でき、マッピングを解放後にバッファがデバイスドメインに残るよう強制します。注意深く使用してください。

DMA_ATTR_FORCE_CONTIGUOUS¶

デフォルトではDMAマッピングサブシステムは、dma_alloc_attrs()関数で割り当てられたバッファを個々のページから構成し、デバイスDMAアドレス空間で連続するチャンクとしてマッピング可能であれば組み立てることができます。この属性を指定すると、割り当てられたバッファが物理メモリ上でも連続性を保つよう強制されます。

DMA_ATTR_ALLOC_SINGLE_PAGES¶

DMAマッピングサブシステムに、メモリの割り当て方法でTLB効率を高める試みは時間の無駄であるとヒントを出します（つまり、より大きなページでマッピングを構築する試みは行わない）。以下の条件に該当する場合はこの属性を指定してください：

  • このメモリへのアクセスがTLBのスラッシングを引き起こさないとわかっている場合です。アクセスが順序的であるか、それらが順序的でないものの、多くの物理ページにまたがるアドレスを往復する可能性が低いとわかっている場合です。

  • このメモリへのアクセスでTLBミスのペナルティが十分小さく、実質的な影響を及ぼさないとわかっている場合です。暗号化や圧縮などの重い操作を行っている場合はこのような状況が発生する可能性があります。

  • DMAマッピングは基本的に一時的なものです。マッピングが短いライフタイムを持つと予想される場合、大容量ページを使用する代わりに、割当を最適化する（大容量ページを避ける）ことで、わずかなパフォーマンスの向上を得るよりも有益かもしれません。

このヒントを設定しても、巨大ページが取得されないことを保証するわけではありませんが、それほど積極的に取得しようとしないことを意味します。

注意

現在、DMA_ATTR_ALLOC_SINGLE_PAGESはARMプラットフォームでのみ実装されており、ARM64のパッチは近々投稿される予定です。

DMA_ATTR_NO_WARN¶

DMAマッピングサブシステムに割当失敗のレポートを抑制するように指示します（__GFP_NOWARNと同様です）。

一部のアーキテクチャでは、割当失敗はシステムログにエラーメッセージとして報告されます。これにより問題の特定やデバッグが可能ですが、失敗を処理するドライバ（例：後で再試行）はエラーメッセージに影響を受けず、再試行メカニズムの実装に応じて、実際には問題にならないエラーメッセージをシステムログに大量に投稿する可能性があります。

したがって、割当失敗が問題にならない呼び出しでは、ドライバがこれらのエラーメッセージを回避し、ログに影響を与えないようにする方法を提供します。

注意

現在、DMA_ATTR_NO_WARNはPowerPCでのみ実装されています。

DMA_ATTR_PRIVILEGED¶

リモートプロセッサやGPUなどの高度なペリフェラルデバイスは、DMAバッファに特権モード（スーパーバイザ）と非特権モード（ユーザー）の両方でアクセスします。この属性は、DMAマッピングサブシステムに、バッファが特権レベルで完全にアクセス可能であることを示し（理想的には、低特権レベルではアクセス不可または読み取り専用であることを想定します）。

DMA_ATTR_OVERWRITE¶

DMAマッピングサブシステムに、デバイスがマッピングされたサイズ全体を上書きすると予想されるため、呼び出し元は以前のバッファの内容を保持する必要がないことをヒントとして伝えます。これにより、バウンスバッファリングの実装がDMA_FROM_DEVICE転送を最適化できます。
