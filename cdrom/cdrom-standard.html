はじめに¶

Linuxは、おそらくサポートしているハードウェアデバイスの種類が最も豊富なUnix系のオペレーティングシステムです。この理由はおそらく以下の通りです

  • Linuxが現在サポートしている多くのプラットフォーム（i386-PC、Sparc Sunsなど）向けに利用可能なハードウェアデバイスのリストが非常に大きいこと

  • オペレーティングシステムのオープンな設計により、誰でもLinux用のドライバーを書くことができるからです

  • ドライバーを書く方法の例として、豊富なソースコードが存在しています

Linuxのオープン性と、利用可能なハードウェアの多様性により、Linuxは多くのハードウェアデバイスをサポートできるようになりました。しかし、このオープン性が多くの異なるデバイスをサポート可能にした一方で、各デバイスドライバーの動作が大きく異なってしまうという問題も生じています。特にCD-ROMデバイスでは、特定のドライブがコールにどのように反応するかという動作が、デバイスドライバーによって大きく異なります 標準 ioctl() Linux CD-ROMドライバーの作成者たちは、ドライバーの動作が完全に一貫しないことを避けるため、既存のドライバーを理解し、コピーした上で変更して新しいデバイスドライバーを作成しました。しかし、この慣習は、すべてのLinux CD-ROMドライバーにおいて一貫した動作を保つことができませんでした

このドキュメントは、Linux用のさまざまなCD-ROMデバイスドライバーで一貫した動作を確立するための取り組みについて説明しています。また、このドキュメントではさまざまな ioctl()および低レベルのCD-ROMデバイスドライバーがそれらをどのように実装すべきかについても定義しています。現在（Linux 2.1x 開発用カーネルを含む）IDE/ATAPIおよびSCSIを含むいくつかの低レベルのCD-ROMデバイスドライバーがこの一貫したインターフェースを使用しています。

CD-ROMが開発された当初、CD-ROMドライブとコンピュータ間のインターフェースは標準で指定されていませんでした。その結果、さまざまなCD-ROMインターフェースが開発されました。一部は独自の特許設計（ソニー、ミツミ、パナソニック、フィリップス）を採用しており、他のメーカーは既存の電気的インターフェースを採用しつつ機能を変更（クリエイティブラボ/サウンドブローラー、テアック、ファンアイ）したり、既存の電気的インターフェースの1つまたは複数にドライブを適応させ（アゼック、サンヨー、ファンアイ、バーテロス、ロンシャイン、オプティクスストレージおよびほとんどの NoName メーカー). 新しいドライブが独自のインターフェースやコマンドセット、フロー制御スキームを使用する場合、別途ドライバを書くか、既存のドライバを拡張する必要がありました。歴史的にCD-ROMのサポートは、これらの異なるインターフェースに対応してきました。現代では、ほぼすべての新しいCD-ROMドライブがIDE/ATAPIまたはSCSIであり、メーカーが新しいインターフェースを開発する可能性は極めて低いです。古い特許インターフェース用のドライブを探すのも難しくなってきています。

1.3.70の時代に、既存のソフトウェアインターフェースを確認したとき、 cdrom.hファイルでは、不規則なコマンドとデータ形式のセットに見えました。 1多くのソフトウェアインターフェースの機能は、特定のドライブの能力を補うために、 ad hoc の方法で追加されていました。より重要なのは、ほとんどの異なるドライバでコマンドの動作が異なっていたことです：例えば、一部のドライバではドライブがトレイを閉じる動作をします。 標準 ドライブがトレイを閉じる動作をします。 open() ドライブのトレイが開いているときに呼び出されるが、他のドライブはそうではない。一部のドライバーはデバイスを開くとドアをロックし、不整合なファイルシステムを防ぐためだが、他はロックしない。ソフトウェアによるドライブの排他を許可するためだ。間違いなく、さまざまなドライブの機能は異なり、たとえ2つのドライブが同じ機能を持っていたとしても、ドライバーの動作は通常異なる。

この構造体には、CD-ROMデバイスの低レベルドライバに関する情報が含まれています。この構造体は論理的にデバイスのメジャーナンバーに接続されています（ただし、一部のドライバではメジャーナンバーが異なる場合があります。IDEドライバの例が挙げられます）。

に移されます。この関数は cdrom_open()の逆論理を実装し、その後デバイス依存 release() ルーチンを呼び出します。使用カウントがゼロになった場合、割り当てられたバッファは sync_dev(dev) および invalidate_buffers(dev).

int cdrom_ioctl(struct inode *ip, struct file *fp,
                unsigned int cmd, unsigned long arg)

でフラッシュされます。 ioctl この関数はCD-ROMデバイスのすべての標準 ioctl() を統一的に処理します。異なる呼び出しは以下の3つのカテゴリに分類されます： audio_ioctl()デバイス操作で直接実装可能な呼び出し、呼び出しを経由して処理される呼び出し、そして残りのデバイス依存とみなされる呼び出し。一般的に、負の戻り値はエラーを示します。
