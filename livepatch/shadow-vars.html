シャドウ変数¶

Shadow variables は、livepatch モジュールが既存のデータ構造に追加の「シャドウ」データを関連付けるための単純な方法です。シャドウデータは親データ構造とは別に割り当てられ、親データ構造は変更されません。このドキュメントで説明するシャドウ変数 API は、シャドウ変数を親データ構造と関連付けるための割り当て/削除を行います。

実装では、親オブジェクトへのポインタとシャドウデータの数値識別子を関連付けるグローバルな内核ハッシュテーブルが導入されています。数値識別子は、シャドウ変数のバージョン、クラス、タイプなどに使用可能な単純な列挙です。具体的には、親ポインタがハッシュテーブルのキーとなり、数値IDはハッシュテーブルのクエリをフィルタリングします。複数のシャドウ変数が同じ親オブジェクトに接続される場合がありますが、数値識別子によって区別されます。

1. API の概要¶

(livepatch/shadow.c の完全な API 使用ドキュメントを参照してください。)

ハッシュテーブルはすべてのシャドウ変数を参照します。これらの参照は <obj, id> ペアで保存および取得されます。

  • klp_shadow 変数データ構造は、トラッキングメタデータとシャドウデータを同時にカプセル化しています:

    • メタデータ

      • obj - 親オブジェクトへのポインタ

      • id - データ識別子

    • data[] - シャドウデータの格納領域

klp_shadow_alloc() および klp_shadow_get_or_alloc() はデフォルトで変数をゼロイニングします。非ゼロ値が必要な場合、カスタムコンストラクタ関数を呼び出すことも可能です。呼び出し元は必要な排他制御を提供する必要があります。

コンストラクタは klp_shadow_lock スピンロックの下で呼び出されます。これは、新しい変数が割り当てられたときに一度だけ実行できる操作を実行するためのものです。

  • klp_shadow_get() - <obj, id> ペアを検索してシャドウ変数データポインタを取得する

  • klp_shadow_alloc() - <obj, id> ペアを検索して新しいシャドウ変数を割り当てる

    • 存在する場合

      • WARN して NULL を返す

    • <obj, id> が既に存在しない場合

      • 新しいシャドウ変数を割り当てる

      • カスタムコンストラクタとデータを指定して変数を初期化する

      • <obj, id> をグローバルハッシュテーブルに追加する

  • klp_shadow_get_or_alloc() - 既存のシャドウ変数を取得するか、新しいものを割り当てる

    • 存在する場合

      • 既存のシャドウ変数を返す

    • <obj, id> が既に存在しない場合

      • 新しいシャドウ変数を割り当てる

      • カスタムコンストラクタとデータを指定して変数を初期化する

      • <obj, id> ペアをグローバルハッシュテーブルに追加する

  • klp_shadow_free() - <obj, id> シャドウ変数を分離して解放する

    • 見つかった場合

      • 定義されている場合、デストラクタ関数を呼び出す

      • シャドウ変数を解放する

  • klp_shadow_free_all() - <, id>のシャドウ変数を分離して解放 - <, id>の参照をグローバルハッシュテーブルから検索してすべて削除, id>の参照をグローバルハッシュテーブルから検索してすべて削除, id>の参照をグローバルハッシュテーブルから検索してすべて削除

    • 見つかった場合

      • 定義されている場合、デストラクタ関数を呼び出す

      • シャドウ変数を解放する

2. 使用例¶

(例として、samples/livepatch/に含まれるshadow variable livepatchモジュールを参照してください。完全な動作例をご覧ください。)

以下の使用例では、commit 1d147bfa6429（「mac80211: AP powersave TX vs. wakeup raceの修正」）を考慮してください。このコミットでは、net/mac80211/sta_info.h にスピンロックを追加しました。 struct sta_info各使用例は、この修正のスタンドアロンなlivepatch実装とみなせます。

親のライフサイクルに合わせる¶

親データ構造が頻繁に作成・破棄される場合、シャドウ変数のライフサイクルを同じ割り当て・解放関数に合わせるのが最も簡単です。この場合、親データ構造は通常、割り当てられ、初期化され、その後ある方法で登録されます。シャドウ変数の割り当てと設定は親の初期化の一部とみなされ、親が「動作開始」する前に（つまり、この<obj, id>ペアのシャドウ変数get-APIリクエストが行われる前）に完了する必要があります。

commit 1d147bfa6429の場合、親sta_info構造体が割り当てられたときに、ps_lockポインタのシャドウコピーを割り当て、その後初期化します。

#define PS_LOCK 1
struct sta_info *sta_info_alloc(struct ieee80211_sub_if_data *sdata,
                                const u8 *addr, gfp_t gfp)
{
      struct sta_info *sta;
      spinlock_t *ps_lock;

      /* Parent structure is created */
      sta = kzalloc(sizeof(*sta) + hw->sta_data_size, gfp);

      /* Attach a corresponding shadow variable, then initialize it */
      ps_lock = klp_shadow_alloc(sta, PS_LOCK, sizeof(*ps_lock), gfp,
                                 NULL, NULL);
      if (!ps_lock)
              goto shadow_fail;
      spin_lock_init(ps_lock);
      ...

ps_lockが必要な場合、特定の struct sta_info::

void ieee80211_sta_ps_deliver_wakeup(struct sta_info *sta)
{
      spinlock_t *ps_lock;

      /* sync with ieee80211_tx_h_unicast_ps_buf */
      ps_lock = klp_shadow_get(sta, PS_LOCK);
      if (ps_lock)
              spin_lock(ps_lock);
      ...

親sta_info構造体が解放されるとき、まずシャドウ変数を解放します。

void sta_info_free(struct ieee80211_local *local, struct sta_info *sta)
{
      klp_shadow_free(sta, PS_LOCK, NULL);
      kfree(sta);
      ...

進行中の親オブジェクト¶

シャドウ変数を親オブジェクトと同時に割り当てるのが不適切または不可能な場合、またはlivepatch修正がシャドウ変数を親オブジェクトの一部のインスタンスにのみ適用する必要がある場合があります。このような場合、klp_shadow_get_or_alloc()関数呼び出しを使用して、既に進行中の親オブジェクトにシャドウ変数をアタッチできます。

commit 1d147bfa6429の場合、シャドウスピンロックを割り当てる良い場所は ieee80211_sta_ps_deliver_wakeup() 内です。

int ps_lock_shadow_ctor(void *obj, void *shadow_data, void *ctor_data)
{
      spinlock_t *lock = shadow_data;

      spin_lock_init(lock);
      return 0;
}

#define PS_LOCK 1
void ieee80211_sta_ps_deliver_wakeup(struct sta_info *sta)
{
      spinlock_t *ps_lock;

      /* sync with ieee80211_tx_h_unicast_ps_buf */
      ps_lock = klp_shadow_get_or_alloc(sta, PS_LOCK,
                      sizeof(*ps_lock), GFP_ATOMIC,
                      ps_lock_shadow_ctor, NULL);

      if (ps_lock)
              spin_lock(ps_lock);
      ...

この使用法では、必要に応じてシャドウ変数を作成し、それ以外の場合は既に作成された <obj, id> ペア用の変数を使用します。

前の使用例と同様に、シャドウスピンロックはクリーンアップが必要です。シャドウ変数は親オブジェクトが解放される直前に、またはシャドウ変数自体がもはや必要でなくなったときに解放できます。

その他の使用例¶

シャドウ変数は、データ構造が新規のlivepatchコードによって割り当てられたことを示すフラグとしても使用できます。この場合、シャドウ変数が保持するデータ値は重要ではなく、その存在が親オブジェクトの処理方法を示します。
