LP5521/LP5523/LP55231/LP5562/LP8501共通ドライバ¶

著者: Milo(Woogyom) Kim <milo.kim@ti.com>

説明¶

LP5521、LP5523/55231、LP5562およびLP8501は以下の共通機能を持っています。

I2Cデバイス経由のレジスタアクセス デバイス初期化/初期化解除 多くの出力チャンネル用のLEDクラスデバイスの作成 ユーザースペースインターフェース用のデバイス属性 レッドパターンを実行するためのプログラムメモリ

LP55xx共通ドライバーはエクスポートされた関数を使用してこれらの機能を提供します。

lp55xx_init_device() / lp55xx_deinit_device() lp55xx_register_leds() / lp55xx_unregister_leds() lp55xx_register_sysfs() / lp55xx_unregister_sysfs()

(ドライバ構造データ)

lp55xx共通ドライバーでは2つの異なるデータ構造が使用されます。

  • lp55xx_led

    LED電流、チャンネルインデックスなどの複数出力LEDチャンネルを制御します。

  • lp55xx_chip

    I2Cやプラットフォームデータなどの一般的なチップ制御

例えば、LP5521は最大3つのLEDチャンネルを持ち、LP5523/55231は9つの出力チャンネルを持ちます：

lp55xx_chip for LP5521 ... lp55xx_led #1
                           lp55xx_led #2
                           lp55xx_led #3

lp55xx_chip for LP5523 ... lp55xx_led #1
                           lp55xx_led #2
                                 .
                                 .
                           lp55xx_led #9

(チップ依存コード)

デバイス固有の設定をサポートするために、特別な構造体「lpxx_device_config」が使用されます。

  • 最大チャンネル数

  • リセットコマンド、チップ有効化コマンド

  • チップ固有の初期化

  • 明るさ制御レジスタアクセス

  • LED出力電流の設定

  • パターンを実行するためのプログラムメモリアドレスアクセス

  • 追加のデバイス固有属性

(ファームウェアインターフェース)

LP55xxファミリーデバイスは、さまざまなLEDパターンを実行するための内部プログラムメモリを持っています。

このパターンデータはユーザーランドにファイルとして保存されるか、I2C経由でメモリにHEXバイト文字列として書き込まれます。

LP55xx共通ドライバーはファームウェアインターフェースをサポートしています。

LP55xxチップは3つのプログラムエンジンを持っています。

パターンをロードして実行するためのプログラミング手順は以下の通りです。

  1. エンジン番号（1/2/3）を選択

  2. ロードモードに変更

  3. 選択された領域にパターンデータを書き込む

  4. 実行モードに変更

LP55xx共通ドライバーは以下の簡単なインターフェースを提供します。

select_engine:

プログラムを実行するためのエンジンを選択

run_engine:

ファームウェアインターフェース経由でロードされたプログラムを開始

firmware:

プログラムデータをロード

LP5523の場合、追加で「enginex_leds」というコマンドが必要です。これは各エンジン番号ごとにLED出力（複数）を選択するためのものです。詳細は「leds-lp5523.txt」を参照してください。

たとえば、LP5521のエンジン#1で点滅パターンを実行する場合:

echo 1 > /sys/bus/i2c/devices/xxxx/select_engine
echo 1 > /sys/class/firmware/lp5521/loading
echo "4000600040FF6000" > /sys/class/firmware/lp5521/data
echo 0 > /sys/class/firmware/lp5521/loading
echo 1 > /sys/bus/i2c/devices/xxxx/run_engine

たとえば、LP55231のエンジン#3で点滅パターンを実行する場合:

2つのLEDがパターン出力チャネルとして設定されています:

echo 3 > /sys/bus/i2c/devices/xxxx/select_engine
echo 1 > /sys/class/firmware/lp55231/loading
echo "9d0740ff7e0040007e00a0010000" > /sys/class/firmware/lp55231/data
echo 0 > /sys/class/firmware/lp55231/loading
echo "000001100" > /sys/bus/i2c/devices/xxxx/engine3_leds
echo 1 > /sys/bus/i2c/devices/xxxx/run_engine

エンジン#2と#3で点滅パターンを同時に実行するには:

for idx in 2 3
do
echo $idx > /sys/class/leds/red/device/select_engine
sleep 0.1
echo 1 > /sys/class/firmware/lp5521/loading
echo "4000600040FF6000" > /sys/class/firmware/lp5521/data
echo 0 > /sys/class/firmware/lp5521/loading
done
echo 1 > /sys/class/leds/red/device/run_engine

LP5523のもう一つの例です。

フルLEDストリングは'engine2_leds'で選択されます:

echo 2 > /sys/bus/i2c/devices/xxxx/select_engine
echo 1 > /sys/class/firmware/lp5523/loading
echo "9d80400004ff05ff437f0000" > /sys/class/firmware/lp5523/data
echo 0 > /sys/class/firmware/lp5523/loading
echo "111111111" > /sys/bus/i2c/devices/xxxx/engine2_leds
echo 1 > /sys/bus/i2c/devices/xxxx/run_engine

'loading'が0に設定された直後に登録されたコールバックが呼び出されます。コールバック内で選択されたエンジンがロードされ、メモリが更新されます。プログラミングされたパターンを実行するには、'run_engine'属性を有効にする必要があります。

LP8501のパターンシーケンスはLP5523と似ています。

しかしパターンデータは特定されています。

例1) エンジン1を使用:

echo 1 > /sys/bus/i2c/devices/xxxx/select_engine
echo 1 > /sys/class/firmware/lp8501/loading
echo "9d0140ff7e0040007e00a001c000" > /sys/class/firmware/lp8501/data
echo 0 > /sys/class/firmware/lp8501/loading
echo 1 > /sys/bus/i2c/devices/xxxx/run_engine

例2) エンジン2と3を同時に使用:

echo 2 > /sys/bus/i2c/devices/xxxx/select_engine
sleep 1
echo 1 > /sys/class/firmware/lp8501/loading
echo "9d0140ff7e0040007e00a001c000" > /sys/class/firmware/lp8501/data
echo 0 > /sys/class/firmware/lp8501/loading
sleep 1
echo 3 > /sys/bus/i2c/devices/xxxx/select_engine
sleep 1
echo 1 > /sys/class/firmware/lp8501/loading
echo "9d0340ff7e0040007e00a001c000" > /sys/class/firmware/lp8501/data
echo 0 > /sys/class/firmware/lp8501/loading
sleep 1
echo 1 > /sys/class/leds/d1/device/run_engine

( 'run_engine' および 'firmware_cb' )

プログラムデータの実行シーケンスは共通しています。

しかし各デバイスには独自のコマンド用レジスタアドレスがあります。

これをサポートするため、'run_engine' および 'firmware_cb' は各ドライバで設定可能です。

run_engine:

選択されたエンジンを制御

firmware_cb:

ファームウェアのロードが完了した後のコールバック関数。

ファームウェアのロードおよびプログラムメモリの更新に特化したチップ固有のコマンド。

( 事前定義されたパターンデータ )

ファームウェアインターフェースなしで、LP55xxドライバはLEDパターンをロードする別の方法を提供します。それは'predefined'パターンです。

事前定義されたパターンはプラットフォームデータで定義され、必要に応じてsysfs経由でロードします。

事前定義されたパターン概念を使用するには、'patterns' および 'num_patterns' を設定する必要があります。

事前定義されたパターンデータの例:

/* mode_1: blinking data */
static const u8 mode_1[] = {
              0x40, 0x00, 0x60, 0x00, 0x40, 0xFF, 0x60, 0x00,
              };

/* mode_2: always on */
static const u8 mode_2[] = { 0x40, 0xFF, };

struct lp55xx_predef_pattern board_led_patterns[] = {
      {
              .r = mode_1,
              .size_r = ARRAY_SIZE(mode_1),
      },
      {
              .b = mode_2,
              .size_b = ARRAY_SIZE(mode_2),
      },
}

struct lp55xx_platform_data lp5562_pdata = {
...
      .patterns      = board_led_patterns,
      .num_patterns  = ARRAY_SIZE(board_led_patterns),
};

その後、mode_1 および mode_2 はsysfs経由で実行できます:

echo 1 > /sys/bus/i2c/devices/xxxx/led_pattern    # red blinking LED pattern
echo 2 > /sys/bus/i2c/devices/xxxx/led_pattern    # blue LED always on

パターンの実行を停止するには:

echo 0 > /sys/bus/i2c/devices/xxxx/led_pattern
