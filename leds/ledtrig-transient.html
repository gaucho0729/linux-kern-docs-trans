LED一時トリガー¶

現在、leds timer trigger はワンショットタイマーをアクティブ化するインターフェースを持っていません。現在のサポートは、LEDがON状態になる時間とOFF状態になる時間を指定する2つのタイマーセットを許可しています。delay_on値はLEDがON状態を維持する時間、delay_off値はOFF状態を維持する時間を指定します。ONとOFFのサイクルはトリガーが無効化されるまで繰り返されます。ワンタイムアクティベーションの仕様はなく、一度ONまたはOFF状態を維持した後、元の状態に永久に戻る機能は実装できません。

ワンショットタイマーインターフェースがなければ、ユーザースペースでもタイマートリガーを使用して状態を保持するタイマーセットを指定できますが、ユーザースペースアプリケーションがクラッシュしたり終了したままトリガーを無効化しなかった場合、ハードウェアはその状態を永久的に維持します。

Transient triggerはワンショットタイマーのアクティベーションニーズを解決します。transient triggerは他のledsトリガーと同様に有効化および無効化できます。

LEDクラスデバイスドライバーが登録される際、サポートするすべてのledsトリガーとデフォルトのトリガーを指定できます。登録時にデフォルトのトリガーのアクティベーションルーチンが呼び出されます。LEDクラスデバイスの登録中にLEDの状態は変化しません。

ドライバーがアンレジストレーションされる際、現在アクティブなトリガーのデアクティベーションルーチンが呼び出され、LEDの状態がLED_OFFに変更されます。

ドライバーのスリープ状態ではLEDの状態がLED_OFFに変更され、リザーブでは状態を変更しません。スリープとリザーブの動作が現在有効なトリガーと明示的な相互作用をしないことに注意してください。ドライバーがスリープ状態にある間、LEDの状態変更は一時停止されます。ドライバーがスリープ状態に入った時点でアクティブなタイマーコンテナは継続して動作しますが、LEDの状態を実際に変更することはできません。ドライバーが再起動されると、トリガーは再び動作を開始します。

LEDの状態変更はbrightnessという一般的なledクラスデバイスプロパティを使用して制御されます。ユーザースペースからbrightnessを0に設定するecho 0 > brightnessコマンドは、現在のトリガーを無効化します。

一時的なトリガーは標準の登録および解除インターフェースを使用します。トリガーの登録中に、このトリガーをデフォルトとして指定した各LEDクラスデバイスに対して、トリガーのアクティベーションルーチンが呼び出されます。登録中にLEDの状態は変化しませんが、他のトリガーがアクティブな場合を除き、LEDの状態はLED_OFFに変更されます。

トリガーの解除中にLEDの状態がLED_OFFに変更されます。

一時的なトリガーのアクティベーションルーチンはLEDの状態を変更しません。プロパティを生成し初期化を行います。一時的なトリガーのデアクティベーションルーチンは、クリーンアップとプロパティの削除を行う前に、アクティブなタイマをキャンセルします。LEDの状態を非一時的な状態に戻します。ドライバがスリープ状態になると、一時的な状態に関係なくLEDの状態はLED_OFFに変更されます。

一時的なトリガーは、このトリガーをサポートするLEDクラスデバイスからユーザー空間から有効/無効にできます。以下に示すように：

echo transient > trigger
echo none > trigger
ノート:

新しいプロパティ「トリガー状態」を追加して状態を制御します。

このトリガーは3つのプロパティ、activate、state、durationをエクスポートします。一時的なトリガーがアクティブになるとこれらのプロパティはデフォルト値に設定されます。

  • durationはミリ秒単位でタイマ値を設定します。初期値は0です。

  • activateはdurationで指定されたタイマを必要に応じてアクティブ化および非アクティブ化します。初期値およびデフォルト値は0です。これにより、トリガーのアクティブ化後にdurationを設定できます。

  • stateはユーザーが指定した持続時間を指定して一時的な状態を保持するためのプロパティです。

    activate

    • ワンショットタイマのアクティブ化メカニズム。アクティブ時に1、非アクティブ時に0。一時的なトリガーが有効になると初期値はゼロとなり、durationを設定できるようにします。

      activate状態は指定された持続時間を持つタイマが動作中を示し、非アクティブ状態はアクティブなタイマが動作していないことを示します。

    duration

    • ワンショットタイマ値。activateが設定されると、duration値がタイマを一度だけ動作させるために使用されます。この値はユーザーがecho new_value > durationで設定しない限り、トリガーによって変更されません。

    状態

    • 一時的な状態を保持します。値は0または1の2つの値を持ち、0はLED_OFFに、1はLED_FULLにマッピングされます。指定された状態はワンショットタイマの期間だけ保持され、その後、一時的な状態の逆の非一時的な状態に切り替わります。state = LED_FULLの場合、タイマが終了するとLED_OFFに戻ります。state = LED_OFFの場合、タイマが終了するとLED_FULLに戻ります。注意点として、現在のLED状態は指定された状態への変更前にチェックされません。ドライバは、brightness_set()インターフェースでLEDのデフォルト状態を定義した結果、これらの値を反転してマッピングする可能性があります。

タイマが終了すると、アクティブ状態が非アクティブ状態に戻り、durationは設定値のまま保持されます。今後のアクティブ設定時に使用されます。これにより、ユーザーアプリが一度設定した時間を指定してタイマを実行できるようになります。タイマが終了すると、一時的な状態の逆の非一時的な状態に戻ります：

echo 1 > activate

durationが0でない場合、タイマースタート = duration

echo 0 > activate

現在実行中のタイマをキャンセルします。

echo n > duration

次のアクティブ設定時に使用するタイマ値を保存します。現在実行中のタイマがある場合、指定された時間だけ継続します。

echo 0 > duration

次のアクティブ設定時に使用するタイマ値を保存します。現在実行中のタイマがある場合、指定された時間だけ継続します。

echo 1 > state

指定されたdurationの期間、一時的な状態LED_FULLを保持するように設定します。

echo 0 > state

指定されたdurationの期間、一時的な状態LED_OFFを保持するように設定します。

サポートされていない機能¶

  • タイマアクティベーションはワンショットであり、タイマの延長や短縮はサポートされていません。

例¶

ユースケース1:

echo transient > trigger
echo n > duration
echo 1 > state

必要に応じて以下のステップを繰り返します：

echo 1 > activate - start timer = duration to run once
echo 1 > activate - start timer = duration to run once
echo none > trigger

このトリガーは以下のユースケースに使用することを目的としています：

  • ユーザー空間アプリがアクティビティインジケーターとしてLEDを使用する場合。

  • ユーザー空間アプリがウォッチドッグインジケーターとしてLEDを使用する場合 - アプリが生きている間はLEDを点灯させ、アプリが終了すると自動的に消灯します。

  • LEDの状態を一時的に制御する必要があるユーザー空間アプリが使用する場合。
