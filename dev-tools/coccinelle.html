Coccinelle¶

Coccinelle はパターンマッチングとテキスト変換を行うツールであり、カーネル開発において多くの用途があり、複雑な、ツリー全体を対象としたパッチの適用や問題のあるプログラミングパターンの検出などに利用されます。

Coccinelle の取得¶

カーネルに含まれるセマンティックパッチは、Coccinelle バージョン 1.0.0-rc11 以降で提供される機能とオプションを使用しています。以前のバージョンを使用すると、Coccinelle ファイルや coccicheck で使用されているオプション名が更新されているため、失敗します。

Coccinelle は多くのディストリビューションのパッケージマネージャーで利用可能です。例:

  • Debian

  • Fedora

  • Ubuntu

  • OpenSUSE

  • Arch Linux

  • NetBSD

  • FreeBSD

一部のディストリビューションパッケージは非推奨であり、Coccinelle ホームページで最新バージョンを取得することをお勧めします。 http://coccinelle.lip6.fr/

または、Github から:

https://github.com/coccinelle/coccinelle

取得後、以下のコマンドを実行してください:

./autogen
./configure
make

通常のユーザーとして、インストールには以下のコマンドを使用してください:

sudo make install

ソースからビルドするための詳細なインストール手順は以下にあります:

https://github.com/coccinelle/coccinelle/blob/master/install.txt

Linux Kernel での Coccinelle の使用¶

カーネルのトップレベル Makefile には Coccinelle 特有のターゲットが定義されています。このターゲットは coccicheck と名付けられ、 coccicheck フロントエンドを呼び出します。 scripts directory.

4つの基本的なモードが定義されています: patch, report, context, and org。MODE 変数を設定することで使用するモードを指定します。 MODE=<mode>.

  • patch 修正提案が可能な場合は、修正提案を行います。

  • report 以下の形式でリストを生成します: file:line:column-column: メッセージ

  • context 差分スタイルで興味のある行とそのコンテキストを強調します。興味のある行は -.

  • org Emacs の Org モード形式でレポートを生成します。

すべてのセマンティックパッチがすべてのモードを実装しているわけではありません。Coccinelle の簡単な使用のために、デフォルトモードは「レポート」です。

他の2つのモードはこれらのモードの一部の組み合わせを提供します。

  • chain 上記の順序で前のモードを試行し、成功するまで続けます。

  • rep+ctxt レポートモードとコンテキストモードを順に実行します。これは後述する C オプション（ファイル単位でコードをチェックする機能）とともに使用する必要があります。

例¶

すべてのセマンティックパッチに対してレポートを作成するには、以下のコマンドを実行してください:

make coccicheck MODE=report

パッチを生成するには、以下のコマンドを実行してください:

make coccicheck MODE=patch

coccicheckターゲットは、サブディレクトリ内のすべてのセマンティックパッチを適用します。 scripts/coccinelle Linuxカーネル全体に適用されます。

各セマンティックパッチに対して、コミットメッセージが提案されます。これは、セマンティックパッチで検出される問題の説明を含み、Coccinelleへの参照も含まれます。

静的コード解析器と同様に、Coccinelleは偽陽性を生成することがあります。したがって、レポートは慎重に確認し、パッチをレビューする必要があります。

詳細なメッセージを有効にするには、V=変数を設定します。例えば：

make coccicheck MODE=report V=1

Coccinelleの並列化¶

デフォルトでは、coccicheckは可能な限り並列に実行しようとします。並列度を変更するには、J=変数を設定します。例えば、4つのCPUで実行する場合：

make coccicheck MODE=report J=4

Coccinelle 1.0.2以降、CoccinelleはOcaml parmapを使用して並列化を行います。このサポートが検出された場合、parmapによる並列化の恩恵を受けることができます。

parmapが有効な場合、coccicheckは動的負荷分散を実現するために、 --chunksize 1 引数を使用します。これにより、スレッドに順次作業を割り当てることで、一部のスレッドのみが大部分の作業を処理する状況を回避します。動的負荷分散では、スレッドが早期に完了した場合でも、さらに作業を割り当て続けます。

parmapが有効な場合、Coccinelleでエラーが発生した場合、このエラー値が逆に伝播し、 make coccicheck コマンドの返却値がこの返却値をキャプチャします。

単一のセマンティックパッチを使用してCoccinelleを使用する¶

オプションのmake変数COCCIを使用して、単一のセマンティックパッチを検査できます。その場合、変数は適用するセマンティックパッチの名前で初期化する必要があります。

例えば：

make coccicheck COCCI=<my_SP.cocci> MODE=patch

または:

make coccicheck COCCI=<my_SP.cocci> MODE=report

Coccinelleが処理するファイルの制御¶

デフォルトでは、すべてのカーネルソースツリーが検査されます。

特定のディレクトリにCoccinelleを適用するには、 M= を使用できます。例えば、drivers/net/wireless/を検査するには次のように書きます：

make coccicheck M=drivers/net/wireless/

ディレクトリベースではなく、ファイルベースでCoccinelleを適用する場合、makefileはC変数を使用して処理するファイルを選択します。この変数は、全体のカーネル、特定のディレクトリ、または単一のファイルに対してスクリプトを実行するために使用できます。

例えば、drivers/bluetooth/bfusb.cを検査するには、C変数に値1を渡して、makeがコンパイルが必要と判断するファイルを検査します：

make C=1 CHECK=scripts/coccicheck drivers/bluetooth/bfusb.o

C変数に値2を渡すと、コンパイルが必要かどうかに関係なくファイルを検査します：

make C=2 CHECK=scripts/coccicheck drivers/bluetooth/bfusb.o

これらのファイルベースでのモードでは、セマンティックパッチに関する情報は表示されず、コミットメッセージも提案されません。

scripts/coccinelleに含まれるすべてのセマンティックパッチがデフォルトで実行されます。COCCI変数を使用することで、前のセクションで示したように単一のセマンティックパッチのみを適用することも可能です。

「レポート」モードがデフォルトです。MODE変数を使用して他のモードを選択できます。

Coccinelle SmPLパッチのデバッグ¶

coccicheckを使用するのが最適です。これにより、spatchコマンドラインでコンパイル時に使用するオプションと一致するインクルードオプションが提供されます。V=1を使用することでこれらのオプションを確認できます。その後、手動でデバッグオプションを追加してCoccinelleを実行することも可能です。

代替案として、SmPLパッチに対してCoccinelleを実行する際、stderrをstderrにリダイレクトするように指定することでデバッグできます。デフォルトではstderrは/dev/nullにリダイレクトされています。stderrをキャプチャしたい場合は、coccicheckに以下のオプションを指定できます。 DEBUG_FILE="file.txt" 例えば：

rm -f cocci.err
make coccicheck COCCI=scripts/coccinelle/free/kfree.cocci MODE=report DEBUG_FILE=cocci.err
cat cocci.err

SPFLAGSを使用してデバッグフラグを追加できます。デバッグ中に–profile –show-tryingをSPFLAGSに追加したい場合があります。例えば、以下のように使用できます：

rm -f err.log
export COCCI=scripts/coccinelle/misc/irqf_oneshot.cocci
make coccicheck DEBUG_FILE="err.log" MODE=report SPFLAGS="--profile --show-trying" M=./drivers/mfd/arizona-irq.c

err.logにはプロファイリング情報が記録され、Coccinelleが作業を進めるにつれてstdoutには進捗情報が表示されます。

DEBUG_FILEのサポートはcoccinelle >= 1.0.2を使用している場合にのみ利用可能です。

.cocciconfigサポート¶

Coccinelleは、spatchを起動するたびに使用するデフォルトのCoccinelleオプションとして.cocciconfigを読み込みます。.cocciconfigの変数の優先順位は以下の通りです：

  • 現在のユーザーのホームディレクトリが最初に処理されます

  • spatchを呼び出すディレクトリが次に処理されます

  • –dirオプションで指定されたディレクトリが最後に処理されます（使用されている場合）

coccicheckはmakeを通じて実行されるため、自然にカーネル本体のディレクトリから実行されます。そのため、.cocciconfigを読み込む際には上の2番目のルールが適用されます。 make coccicheck.

make coccicheck また、M=ターゲットの使用もサポートしています。M=ターゲットを指定しない場合、全体のカーネルをターゲットにするものとみなされます。カーネルのcoccicheckスクリプトには以下の内容があります：

if [ "$KBUILD_EXTMOD" = "" ] ; then
    OPTIONS="--dir $srctree $COCCIINCLUDE"
else
    OPTIONS="--dir $KBUILD_EXTMOD $COCCIINCLUDE"
fi

明示的なM=ターゲットが使用されている場合、KBUILD_EXTMODが設定されます。どちらの場合もspatch –dir引数が使用されるため、M=が使用されているかどうかに関わらず3番目のルールが適用されます。M=が使用されている場合、ターゲットディレクトリに独自の.cocciconfigファイルがある可能性があります。M=がcoccicheckに渡されない場合、ターゲットディレクトリはspatchを呼び出したディレクトリと同一です。

カーネルのcoccicheckターゲットを使用しない場合、.cocciconfigの読み込みに上の優先順位ロジックを維持してください。カーネルのcoccicheckターゲットを使用する場合、SPFLAGSを使用してカーネルの.coccicheck設定を上書きしてください。

Linux用のLinux専用.cocciconfigで、Linux用の合理的なデフォルトオプションを組み合わせてCoccinelleをサポートしています。これにより、gitがcoccigrepを介してクエリを実行できるようにヒントを出します。 git grep 200秒のタイムアウトは、現時点では十分であると考えられます。

coccinelleが.cocciconfigを読み込む際に取得するオプションは、システム上で実行されるspatchプロセスの引数として表示されません。Coccinelleが使用するオプションを確認するには、以下を実行してください：

spatch --print-options-only

SPFLAGSを使用して、自分の好みのインデックスオプションを上書きできます。競合するオプションがある場合、Coccinelleは最後に渡されたオプションを優先します。idutilsを使用するには、.cocciconfigを活用することが可能です。ただし、Coccinelleが優先順位を考慮するため、カーネルが自身の.cocciconfigを保持している現在、idutilsを使用する場合はSPFLAGSを活用する必要があります。詳細については、下記の「追加フラグ」セクションを参照してください。

追加フラグ¶

SPFLAGS変数を通じてspatchに追加フラグを渡すことができます。これは、Coccinelleがオプションが競合している場合でも最後に渡されたフラグを優先するためです。

make SPFLAGS=--use-glimpse coccicheck

Coccinelleはidutilsもサポートしていますが、coccinelle >= 1.0.6が必要です。IDファイルが指定されていない場合、Coccinelleはカーネルのトップレベルにある.id-utils.indexファイルをIDデータベースファイルとみなします。Coccinelleはスクリプトscripts/idutils_index.shを提供しており、これによりデータベースが作成されます：

mkid -i C --output .id-utils.index

別のデータベースファイル名をもつ場合、この名前でシンボリックリンクを張ることも可能です。

make SPFLAGS=--use-idutils coccicheck

代替として、データベースファイル名を明示的に指定することもできます。例えば：

make SPFLAGS="--use-idutils /full-path/to/ID" coccicheck

参照 spatch --help spatchオプションについて詳しく知るにはこちら。

注意: 空文字（null byte）は文字列の一部とみなされ、検索対象となる。 --use-glimpse および --use-idutils オプションはコードのインデックス化に外部ツールを必要とします。したがって、これらはデフォルトではアクティブではありません。ただし、これらのツールのいずれかでコードをインデックス化し、使用するcocciファイルに応じて、spatchはコードベース全体をより迅速に処理できるかもしれません。

SmPLパッチ固有のオプション¶

SmPLパッチは、Coccinelleに渡されるオプションに独自の要件を持つ場合があります。SmPLパッチ固有のオプションは、SmPLパッチの先頭に指定することで提供できます。例えば：

// Options: --no-includes --include-headers

SmPLパッチのCoccinelle要件¶

Coccinelleの機能が追加されることで、より高度なSmPLパッチが新しいバージョンのCoccinelleを必要とする場合があります。SmPLパッチがCoccinelleの最小バージョンを指定する場合、以下のように指定できます。例えば、Coccinelle >= 1.0.5を必要とする場合：

// Requires: 1.0.5

新しいセマンティックパッチの提案¶

新しいセマンティックパッチはカーネル開発者によって提案および送信できます。明確さのため、サブディレクトリに整理して提出してください。 scripts/coccinelle/.

Detailed description of the report mode¶

report 以下の形式でリストを生成します:

file:line:column-column: message

例¶

Running:

make coccicheck MODE=report COCCI=scripts/coccinelle/api/err_cast.cocci

will execute the following part of the SmPL script:

<smpl>
@r depends on !context && !patch && (org || report)@
expression x;
position p;
@@

  ERR_PTR@p(PTR_ERR(x))

@script:python depends on report@
p << r.p;
x << r.x;
@@

msg="ERR_CAST can be used with %s" % (x)
coccilib.report.print_report(p[0], msg)
</smpl>

This SmPL excerpt generates entries on the standard output, as illustrated below:

/home/user/linux/crypto/ctr.c:188:9-16: ERR_CAST can be used with alg
/home/user/linux/crypto/authenc.c:619:9-16: ERR_CAST can be used with auth
/home/user/linux/crypto/xts.c:227:9-16: ERR_CAST can be used with alg

Detailed description of the patch mode¶

When the patch mode is available, it proposes a fix for each problem identified.

例¶

Running:

make coccicheck MODE=patch COCCI=scripts/coccinelle/api/err_cast.cocci

will execute the following part of the SmPL script:

<smpl>
@ depends on !context && patch && !org && !report @
expression x;
@@

- ERR_PTR(PTR_ERR(x))
+ ERR_CAST(x)
</smpl>

This SmPL excerpt generates patch hunks on the standard output, as illustrated below:

diff -u -p a/crypto/ctr.c b/crypto/ctr.c
--- a/crypto/ctr.c 2010-05-26 10:49:38.000000000 +0200
+++ b/crypto/ctr.c 2010-06-03 23:44:49.000000000 +0200
@@ -185,7 +185,7 @@ static struct crypto_instance *crypto_ct
    alg = crypto_attr_alg(tb[1], CRYPTO_ALG_TYPE_CIPHER,
                              CRYPTO_ALG_TYPE_MASK);
    if (IS_ERR(alg))
-           return ERR_PTR(PTR_ERR(alg));
+           return ERR_CAST(alg);

    /* Block size must be >= 4 bytes. */
    err = -EINVAL;

Detailed description of the context mode¶

context highlights lines of interest and their context in a diff-like style.

注意: The diff-like output generated is NOT an applicable patch. The intent of the context mode is to highlight the important lines (annotated with minus, -) and gives some surrounding context lines around. This output can be used with the diff mode of Emacs to review the code.

例¶

Running:

make coccicheck MODE=context COCCI=scripts/coccinelle/api/err_cast.cocci

will execute the following part of the SmPL script:

<smpl>
@ depends on context && !patch && !org && !report@
expression x;
@@

* ERR_PTR(PTR_ERR(x))
</smpl>

This SmPL excerpt generates diff hunks on the standard output, as illustrated below:

diff -u -p /home/user/linux/crypto/ctr.c /tmp/nothing
--- /home/user/linux/crypto/ctr.c   2010-05-26 10:49:38.000000000 +0200
+++ /tmp/nothing
@@ -185,7 +185,6 @@ static struct crypto_instance *crypto_ct
    alg = crypto_attr_alg(tb[1], CRYPTO_ALG_TYPE_CIPHER,
                              CRYPTO_ALG_TYPE_MASK);
    if (IS_ERR(alg))
-           return ERR_PTR(PTR_ERR(alg));

    /* Block size must be >= 4 bytes. */
    err = -EINVAL;

Detailed description of the org mode¶

org Emacs の Org モード形式でレポートを生成します。

例¶

Running:

make coccicheck MODE=org COCCI=scripts/coccinelle/api/err_cast.cocci

will execute the following part of the SmPL script:

<smpl>
@r depends on !context && !patch && (org || report)@
expression x;
position p;
@@

  ERR_PTR@p(PTR_ERR(x))

@script:python depends on org@
p << r.p;
x << r.x;
@@

msg="ERR_CAST can be used with %s" % (x)
msg_safe=msg.replace("[","@(").replace("]",")")
coccilib.org.print_todo(p[0], msg_safe)
</smpl>

This SmPL excerpt generates Org entries on the standard output, as illustrated below:

* TODO [[view:/home/user/linux/crypto/ctr.c::face=ovl-face1::linb=188::colb=9::cole=16][ERR_CAST can be used with alg]]
* TODO [[view:/home/user/linux/crypto/authenc.c::face=ovl-face1::linb=619::colb=9::cole=16][ERR_CAST can be used with auth]]
* TODO [[view:/home/user/linux/crypto/xts.c::face=ovl-face1::linb=227::colb=9::cole=16][ERR_CAST can be used with alg]]
