Debugging kernel and modules via gdb¶

kgdbというカーネルデバッガー、QEMUやJTAGベースのハードウェアインターフェースなどのハイパーバイザは、gdbを使用してLinuxカーネルとそのモジュールを実行時においてデバッグできます。gdbにはPython用の強力なスクリプティングインターフェースが含まれています。カーネルは、典型的なカーネルデバッグステップを簡略化するヘルパスクリプトのコレクションを提供しています。これは、これらのスクリプトを有効化し使用する方法についての短いチュートリアルです。対象はQEMU/KVM仮想マシンに焦点を当てていますが、例は他のgdbスタブにも適用可能です。

要件¶

  • gdb 7.2以上（推奨: 7.4以上）で、Pythonサポートが有効になっている必要があります（通常、ディストリビューションではこれが既に有効になっています）

設定¶

  • QEMU/KVM仮想マシン用の仮想Linuxマシンを作成してください（詳細はwww.linux-kvm.orgおよびwww.qemu.orgをご覧ください）。クロス開発の場合は、 https://landley.net/aboriginal/bin マシンイメージとツールチェーンのプールを保持しており、開始に役立ちます。

  • CONFIG_GDB_SCRIPTSを有効にしてカーネルをビルドしてください。ただし、CONFIG_DEBUG_INFO_REDUCEDは無効にしてください。アーキテクチャがCONFIG_FRAME_POINTERをサポートする場合、それを有効にしてください。

  • ゲストにそのカーネルをインストールし、必要に応じてKASLRを無効にするためにカーネルコマンドラインに「nokaslr」を追加してください。代替として、QEMUは-kerneL、-append、-initrdコマンドラインスイッチを使用してカーネルを直接起動できます。これはモジュールに依存しない場合にのみ一般的に有用です。QEMUドキュメンテーションでこのモードの詳細をご覧ください。この場合、アーキテクチャがKASLRをサポートする場合、CONFIG_RANDOMIZE_BASEを無効にしてカーネルをビルドしてください。

  • QEMU/KVMのgdbスタブを有効にするには、以下のいずれかを行います

    • VM起動時にQEMUコマンドラインに「-s」を追加して

    または

    • 実行中にQEMUモニタコンソールから「gdbserver」を実行して

  • cd /path/to/linux-build

  • gdb vmlinuxでgdbを起動します

    一部のディストリビューションでは、gdbスクリプトの自動ロードを特定の安全なディレクトリに制限している場合があります。gdbがvmlinux-gdb.pyのロードを拒否する場合、以下を ~/.gdbinit に追加してください

    add-auto-load-safe-path /path/to/linux-build

    to ~/.gdbinit。詳しくはgdbのヘルプをご覧ください。

  • 起動したゲストに接続します：

    (gdb) target remote :1234

Linuxが提供するgdbヘルパの使用例¶

  • モジュール（およびメインカーネル）のシンボルをロードします：

    (gdb) lx-symbols
loading vmlinux
scanning for modules in /home/user/linux/build
loading @0xffffffffa0020000: /home/user/linux/build/net/netfilter/xt_tcpudp.ko
loading @0xffffffffa0016000: /home/user/linux/build/net/netfilter/xt_pkttype.ko
loading @0xffffffffa0002000: /home/user/linux/build/net/netfilter/xt_limit.ko
loading @0xffffffffa00ca000: /home/user/linux/build/net/packet/af_packet.ko
loading @0xffffffffa003c000: /home/user/linux/build/fs/fuse/fuse.ko
...
loading @0xffffffffa0000000: /home/user/linux/build/drivers/ata/ata_generic.ko

  • まだロードされていないモジュール関数にブレイクポイントを設定します。例：

    (gdb) b btrfs_init_sysfs
Function "btrfs_init_sysfs" not defined.
Make breakpoint pending on future shared library load? (y or [n]) y
Breakpoint 1 (btrfs_init_sysfs) pending.

  • ターゲットを続行します：

    (gdb) c

  • ターゲットでモジュールをロードし、シンボルのロードとブレイクポイントのヒットを確認します：

    loading @0xffffffffa0034000: /home/user/linux/build/lib/libcrc32c.ko
loading @0xffffffffa0050000: /home/user/linux/build/lib/lzo/lzo_compress.ko
loading @0xffffffffa006e000: /home/user/linux/build/lib/zlib_deflate/zlib_deflate.ko
loading @0xffffffffa01b1000: /home/user/linux/build/fs/btrfs/btrfs.ko

36              btrfs_kset = kset_create_and_add("btrfs", NULL, fs_kobj);

  • ターゲットカーネルのログバッファをダンプします：

    (gdb) lx-dmesg
[     0.000000] Initializing cgroup subsys cpuset
[     0.000000] Initializing cgroup subsys cpu
[     0.000000] Linux version 3.8.0-rc4-dbg+ (...

[     0.000000] BIOS-e820: [mem 0x0000000000000000-0x000000000009fbff] usable
[     0.000000] BIOS-e820: [mem 0x000000000009fc00-0x000000000009ffff] reserved
....

  • 現在のタスク構造体のフィールドを確認します：

    (gdb) p $lx_current().pid
$1 = 4998
(gdb) p $lx_current().comm
$2 = "modprobe\000\000\000\000\000\000\000"

  • 現在のCPUまたは指定されたCPU用のper-cpu関数を使用します：

    (gdb) p $lx_per_cpu("runqueues").nr_running
$3 = 1
(gdb) p $lx_per_cpu("runqueues", 2).nr_running
$4 = 0

  • container_ofヘルパを使用してhrtimersを詳しく調べます：

    (gdb) set $next = $lx_per_cpu("hrtimer_bases").clock_base[0].active.next
(gdb) p *$container_of($next, "struct hrtimer", "node")

コマンドと関数の一覧¶

コマンドや便利機能の数は時間とともに進化していくかもしれませんが、これは初期バージョンのスナップショットです:

(gdb) apropos lx
function lx_current -- Return current task
function lx_module -- Find module by name and return the module variable
function lx_per_cpu -- Return per-cpu variable
function lx_task_by_pid -- Find Linux task by PID and return the task_struct variable
function lx_thread_info -- Calculate Linux thread_info from task variable
lx-dmesg -- Print Linux kernel log buffer
lx-lsmod -- List currently loaded modules
lx-symbols -- (Re-)load symbols of Linux kernel and currently loaded modules

コマンドについては「help <command-name>」、便利機能については「help function <function-name>」と入力することで、詳細なヘルプを取得できます。
