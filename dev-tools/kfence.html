Kernel Electric-Fence (KFENCE)¶

Kernel Electric-Fence (KFENCE) は、低負荷でサンプリングベースのメモリ安全性エラー検出ツールです。KFENCE は、ヒープの範囲外アクセス、使用後解放（use-after-free）、無効な解放（invalid-free）などのエラーを検出します。

KFENCE は本番環境でのカーネルで有効化されるように設計されており、パフォーマンスの負荷はほぼゼロです。KASAN と比較すると、KFENCE はパフォーマンスを精度に交換しています。KFENCE の設計の主な動機は、十分な総稼働時間があれば、本番環境で通常は実行されないコードパスのバグを検出できる点です。ツールを大規模なマシン群に展開することで、短時間で十分な総稼働時間を達成できます。

使い方¶

KFENCE を有効化するには、カーネルを以下のように構成します:

CONFIG_KFENCE=y

KFENCE のサポートを有効化するがデフォルトでは無効にする場合（有効化するには値をゼロ以外に設定する）、カーネルを以下のように構成します: kfence.sample_interval to non-zero value), configure the kernel with:

CONFIG_KFENCE=y
CONFIG_KFENCE_SAMPLE_INTERVAL=0

KFENCE は、動作をカスタマイズするためのいくつかの設定オプションを提供します（詳しくは、 lib/Kconfig.kfence 詳しくは、以下を参照してください。

パフォーマンスの調整¶

最も重要なパラメータは KFENCE のサンプリング間隔で、カーネル起動パラメータ kfence.sample_interval ミリ秒で設定できます。サンプリング間隔は、ヒープ割当が KFENCE によって保護される頻度を決定します。デフォルト値は Kconfig オプション CONFIG_KFENCE_SAMPLE_INTERVAL. Setting kfence.sample_interval=0 KFENCE を無効化します。

KFENCE のメモリプールは固定サイズであり、プールが枯渇した場合、さらに KFENCE の割当は行われません。 CONFIG_KFENCE_NUM_OBJECTS (デフォルト 255) で、利用可能なガード対象オブジェクト数を制御できます。各オブジェクトは 2 ページを必要とし、1 つはオブジェクト自体、もう 1 つはガードページとして使用します。オブジェクトページはガードページと交互に配置され、すべてのオブジェクトページは 2 つのガードページで囲まれます。

KFENCE メモリプールに割り当てる総メモリ量は以下の式で計算できます:

( #objects + 1 ) * 2 * PAGE_SIZE

デフォルト設定を使用し、ページサイズが 4 KiB であると仮定すると、KFENCE メモリプールに 2 MiB を割り当てることになります。

注意: ヒューゲページをサポートするアーキテクチャでは、KFENCE はプールがヒューゲページを使用することを確保します。 PAGE_SIZE. これにより、追加のページテーブルが割り当てられます。

DebugFS インターフェース¶

いくつかのデバッグ情報はdebugfs経由で公開されています:

  • ファイル /sys/kernel/debug/kfence/stats リアルタイム統計情報を提供します。

  • ファイル /sys/kernel/debug/kfence/objects KFENCE経由で割り当てられたオブジェクトの一覧を提供し、既に解放されたが保護されているオブジェクトも含みます。

実装の詳細¶

ガード割り当てはサンプル間隔に基づいて設定されます。サンプル間隔が経過した後、メインアロケータ（SLABまたはSLUB）を通じた次の割り当てはKFENCEオブジェクトプールからガード割り当てを返します（割り当てサイズはPAGE_SIZEまでサポートされます）。この時点でタイマーコンテナがリセットされ、次の割り当ては間隔が経過後に設定されます。メインアロケータの高速パスを通じてKFENCE割り当てを「ゲート」する際にオーバーヘッドを回避するため、KFENCEは静的ブランチを静的キーインフラストラクチャを介して使用します。静的ブランチは切り替えられ、割り当てをKFENCEにリダイレクトします。

KFENCEオブジェクトはランダムに選択された左または右のページ境界に専用のページに配置されます。オブジェクトページの左と右のページは「ガードページ」として扱われ、属性が保護状態に変更され、アクセス試行時にページフォールトを発生させます。このようなページフォールトはKFENCEによって検出され、フォールトを優雅に処理するために不正アクセスを報告し、ページをアクセス可能状態にマークしてフォールトコードが（誤って）実行を継続できるようにします（set panic_on_warn をパニックに設定する代わりに）。

KFENCEは、オブジェクトのページ内でのメモリのバウンダリ外への書き込みを検出するために、パターンベースのレッドゾーンを採用しています。各オブジェクトページに対して、非オブジェクトメモリ全体にレッドゾーンが設定されます。典型的なアライメントでは、オブジェクトの未保護側にのみレッドゾーンが必要です。KFENCEはキャッシュの要求アライメントを尊重するため、特殊なアライメントによりオブジェクトの両側に保護されていないギャップが生じることがあり、これらすべてがレッドゾーンとして設定されます。

以下の図はページレイアウトを示しています：

---+-----------+-----------+-----------+-----------+-----------+---
   | xxxxxxxxx | O :       | xxxxxxxxx |       : O | xxxxxxxxx |
   | xxxxxxxxx | B :       | xxxxxxxxx |       : B | xxxxxxxxx |
   | x GUARD x | J : RED-  | x GUARD x | RED-  : J | x GUARD x |
   | xxxxxxxxx | E :  ZONE | xxxxxxxxx |  ZONE : E | xxxxxxxxx |
   | xxxxxxxxx | C :       | xxxxxxxxx |       : C | xxxxxxxxx |
   | xxxxxxxxx | T :       | xxxxxxxxx |       : T | xxxxxxxxx |
---+-----------+-----------+-----------+-----------+-----------+---

KFENCEオブジェクトの解放時に、オブジェクトのページが再び保護され、オブジェクトが解放済みとしてマークされます。その後のオブジェクトへのアクセスはエラーとなり、KFENCEは使用後の解放（use-after-free）アクセスを報告します。解放されたオブジェクトはKFENCEのフリー・リストの末尾に挿入されるため、最も最近解放されたオブジェクトの使用後の解放を検出する確率が高まります。

インターフェース¶

以下は、アロケーターやページ処理コードがKFENCEのアロケーションを設定および処理するために使用する関数の説明です。

bool is_kfence_address(const void *addr)¶

アドレスがKFENCEプールに属するかどうかを確認する

パラメータ

const void *addr

確認するアドレス

戻り値

アドレスがKFENCEオブジェクト範囲内かどうかによって真偽値が返されます。

説明

KFENCEオブジェクトは別個のページ範囲に存在し、通常のヒープオブジェクト（例: KFENCEオブジェクトはアロケータのフリー・リストに決して追加されない）と混在してはなりません。これを行わない場合、ヒープの破壊が発生するため、 is_kfence_address() オブジェクトが特定の処理を必要とするかどうかを確認するために使用する必要があります。

注意

この関数は高速パスで使用可能で、パフォーマンスに重大な影響を与えるため、今後の変更ではこの点を考慮する必要があります。例えば、別のロードを導入することを避け、KFENCE_POOL_SIZEを定数（カーネルへの即時パッチングサポートが追加されるまで）に維持する必要があります。

void kfence_shutdown_cache(struct kmem_cache *s)¶

KFENCEオブジェクト用のshutdown_cache()を処理する

パラメータ

struct kmem_cache *s

シャットダウンされるキャッシュ

説明

キャッシュをシャットダウンする前に、そのキャッシュから割り当てられたオブジェクトがまだ存在しないことを確認する必要があります。KFENCEオブジェクトはキャッシュから直接参照されないため、ここでの確認が必要です。

shutdown_cache()はSL*B内部の関数であり、kmem_cache_destroy()は割り当てられたオブジェクトがまだ存在する場合、エラーメッセージを出力してキャッシュの破壊を中止します。メモリがリークします。

KFENCEオブジェクト以外のオブジェクトが唯一存在する場合、全体のキャッシュをリークさせることなく、代わりに割当されたオブジェクトを「ゾンビ割当」として扱うことでより有用なデバッグ情報を提供します。この場合、オブジェクトは依然として使用または解放される可能性があります（これは優雅に処理されます）。ただし、使用はKFENCEエラーレポートを表示し、ユーザーがオブジェクトを使用している場所、元の割当場所、shutdown_cache()の呼び出し元をスタックトレースとともに含めます。

関連するツール¶

ユーザー空間では、同様のアプローチが GWP-ASanで採用されています。GWP-ASanもガードページとサンプリング戦略を用いて大規模なメモリ不安全なバグを検出します。KFENCEの設計はGWP-ASanに直接影響を受け、そのカーネル版として見なせます。また、サンプリングを用いないが同様なアプローチで、「KFENCE」という名前のインスピレーションを受けたものは、ユーザー空間の Electric Fence Malloc Debugger.

にも存在します。カーネル内では複数のツールがメモリアクセスエラーのデバッグに使用され、特にKASANはKFENCEが検出可能なすべてのバグクラスを検出できます。KASANはコンパイラインストルメンテーションに依存してより正確ですが、パフォーマンスコストが伴います。

KASANとKFENCEは補完的な関係にあり、異なるターゲット環境を対象としています。たとえば、テストケースや再現方法が存在する場合、KASANの方が優れたデバッグ支援ツールです。誤検出の可能性が低いため、KFENCEを用いたデバッグにはより多くの労力が必要です。ただし、大規模な展開でKASANを有効化できない場合、テストケースやファッジャーによってカバーされないコードパスでバグを発見するためKFENCEの利用が有益です。
