Sparse¶

Sparse は C プログラムのセマンティックチェックツールであり、カーネルコードのいくつかの潜在的な問題を検出するために使用できます。参照 https://lwn.net/Articles/689907/ sparse の概要についてはここを参照してください。このドキュメントには、カーネル固有の sparse の情報が含まれています。sparse に関する詳細情報（特に内部構造について）は、公式サイトで確認できます。 https://sparse.docs.kernel.org.

sparse を型チェックに使用する¶

「__bitwise」は型属性であり、このような処理を行わなければなりません：

typedef int __bitwise pm_request_t;

enum pm_request {
        PM_SUSPEND = (__force pm_request_t) 1,
        PM_RESUME = (__force pm_request_t) 2
};

これにより、PM_SUSPEND と PM_RESUME が「bitwise」整数になります（「__force」は sparse が bitwise 型へのキャストを警告するためのものです。ただし、この場合、実際に変換を強制したいので必要です）。また、enum 値はすべて同じ型なので、「enum pm_request」もその型になります。

gcc では、「__bitwise」や「__force」などの処理は不要になり、すべてが gcc にとって通常の整数のように見えます。

率直に言って、enum は必要ありません。上記のすべては、単一の特別な「int __bitwise」型にまとめられます。

したがって、より簡単な方法は次のとおりです：

typedef int __bitwise pm_request_t;

#define PM_SUSPEND ((__force pm_request_t) 1)
#define PM_RESUME ((__force pm_request_t) 2)

これにより、厳格な型チェックに必要なインフラストラクチャがすべて整っています。

補足として、定数整数「0」は特別な扱いを受けます。sparse が警告することなく、定数ゼロを bitwise 整数型として使用できます。これは、「bitwise」（名前の通り）が bitwise 型が混同されないように設計されているためです（little-endian と big-endian と cpu-endian など）。その場合、定数「0」は本当に特別です。

sparse をロックチェックに使用する¶

次のマクロは gcc では未定義ですが、sparse の実行中に定義され、sparse の「context」トレース機能（ロック適用用）を使用します。これらのアノテーションは、アノテーションされた関数のエントリとエクスイット時にロックが保持されているかを sparse に通知します。

「__must_hold」 - 指定されたロックが関数のエントリとエクスイット時に保持されています。

「__acquires」 - 指定されたロックが関数のエクスイット時に保持されていますが、エントリ時には保持されていません。

「__releases」 - 指定されたロックが関数のエントリ時に保持されていますが、エクスイット時には保持されていません。

関数がロックを保持せずにエントリとエクスイットし、関数内でバランスよくロックを取得・解放する場合、アノテーションは必要ありません。上記の3つのアノテーションは、sparse がコンテキストの不均衡を報告する可能性のある場合に使用します。

sparse の取得¶

最新のリリースバージョンの tarball は次の URL から取得できます： https://www.kernel.org/pub/software/devel/sparse/dist/

代替として、git を使って最新の開発バージョンの sparse のスナップショットを取得できます：

git://git.kernel.org/pub/scm/devel/sparse/sparse.git

取得したら、次を行います：

make
make install

通常ユーザーとして実行すると、~/bin ディレクトリに sparse をインストールします。

sparse の使用¶

「make C=1」を実行して、再コンパイルされるすべてのCファイルに対してsparseを実行するか、または「make C=2」を実行して、再コンパイルが必要かどうかに関わらずすべてのファイルに対してsparseを実行できます。後者はすでにビルド済みのツリー全体を確認するための高速な方法です。

オプションのmake変数CFはsparseに引数を渡すために使用できます。ビルドシステムは自動的に「-Wbitwise」をsparseに渡します。
