KUnitとは？¶

KUnitはLinuxカーネル用の軽量なユニットテストおよびモックフレームワークです。

KUnitはJUnit、Pythonのunittest.mock、およびC++用のGoogletest/Googlemockから強くインスピレーションを受けました。KUnitは、ユニットテストケースの定義、関連するテストケースをテストスイートにグループ化、テストの実行に共通のインフラストラクチャを提供、など、多くの機能を提供します。

KUnitはカーネルコンポーネントから構成され、ユニットテストを簡単に書くためのマクロセットを提供します。KUnitにテストが書かれている場合、カーネル起動時にビルドインで実行されるか、モジュールとしてビルドされた場合はロード時に実行されます。これらのテストは、カーネルログに結果を出力します。 TAP 形式。

これらのテスト（結果の読み込み）を簡単に実行するため、KUnitは提供します。 kunit_tool、User Mode Linuxのカーネルを構築し、実行し、テスト結果を解析します。 User Mode Linux カーネルを構築し、実行し、テスト結果を解析します。これにより、仮想マシンや別ハードウェアを必要とせずに開発中にKUnitテストを素早く実行できます。

なぜKUnit？¶

ユニットテストは、コードの単位を隔離してテストするためのものです。ユニットテストは最も細かい粒度のテストであり、コードのテスト対象となるコード内でのすべてのコードパスをテストできる必要があります。これはテスト対象のコードが非常に小さく、テストの制御範囲外のハードウェアなどの外部依存関係を持たない場合にのみ可能になります。

KUnitはカーネル内でのユニットテストに共通のフレームワークを提供します。

KUnitテストはほとんどのアーキテクチャで実行でき、ほとんどのテストはアーキテクチャに依存しません。すべてのビルトインKUnitテストはカーネル起動時に実行されます。代替として、KUnitとKUnitテストはモジュールとしてビルドされ、テストモジュールがロードされるときに実行されます。

注意

KUnitは、User Mode Linuxで仮想マシンや実際のハードウェアを必要とせずにテストを実行することもできます。User Mode LinuxはARMやx86のようなLinuxアーキテクチャで、カーネルをLinux実行ファイルとしてコンパイルします。KUnitは、UMLで使用するには、通常のアーキテクチャのようにビルドするか、 ARCH=um （他のアーキテクチャと同様に）、または kunit_tool.

KUnitは高速です。ビルド時間を除けば、呼び出しから完了までにKUnitは10〜20秒で数十のテストを実行できます。これは一部の人にとっては大きな違いには聞こえないかもしれませんが、このような高速で簡単に実行できるテストは、テスト方法やコードの書き方を根本的に変えることができます。リンス自身は、 Googleでのgitトークで述べました。:

「…多くの人がパフォーマンスとは同じことをより速く行うことであり、それは正しくありません。パフォーマンスとはそういうことではありません。何かを非常に速く、非常に正確に実行できると、人々はその使い方を変えていきます。」

この文脈ではリンスはブランチングとマージングについて話していましたが、この点はテストにも適用されます。テストが遅く、信頼性が低く、書くのが難しく、特殊なセットアップや特殊なハードウェアが必要な場合、テストを書く時間も実行する時間も大幅に長くなります。これによりテストが壊れやすくなり、多くのことをテストできず、テストが通った後で再実行されにくい状態になります。テストが本当に速い場合、常に実行します。変更を加えるたびに、誰かがコードを送るたびに、すべてのテストを実行します。なぜ他人がすべてのテストを正しく実行したかを信じる必要があるのでしょうか。あなたの環境で実行するのにかかる時間よりも短時間でテストを実行できるからです。
