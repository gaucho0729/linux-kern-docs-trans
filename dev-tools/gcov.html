Using gcov with the Linux kernel¶

gcovプロファイリングカーネルサポートは、GCCのカバレッジテストツールの使用を可能にします gcov Linuxカーネルと組み合わせて使用可能です。実行中のカーネルのカバレッジデータは、「gcov」デバッグファイルシステム（debugfs）ディレクトリ経由でgcov互換形式でエクスポートされます。特定のファイルのカバレッジデータを取得するには、カーネルビルドディレクトリに移動し、以下のオプションを使用してgcovを実行してください（root権限が必要）： -o option

# cd /tmp/linux-out
# gcov -o /sys/kernel/debug/gcov/tmp/linux-out/kernel spinlock.c

これは現在のディレクトリに実行回数を注釈として付与したソースコードファイルを生成します。さらに、lcovなどのグラフィカルなgcovフロントエンドを使用して、全体のカーネルのデータ収集を自動化し、HTML形式でカバレッジ概要を提供することも可能です。 lcov 可能用途:

デバッグ（この行が実際に到達しているか確認）

  • テスト改善（これらの行をカバーするためにはテストをどのように変更すべきか）

  • カーネル構成の最小化（関連するコードが実行されることもない場合、このオプションは必要か）

  • 準備

カーネルを以下のように構成してください：¶

全体のカーネルのカバレッジデータを取得するには：

CONFIG_DEBUG_FS=y
CONFIG_GCOV_KERNEL=y

注意：プロファイリングフラグでコンパイルされたカーネルは大幅にサイズが大きくなり、実行速度も遅くなります。また、CONFIG_GCOV_PROFILE_ALLはすべてのアーキテクチャでサポートされているとは限りません。

CONFIG_GCOV_PROFILE_ALL=y

プロファイリングデータはdebugfsがマウントされた後からアクセス可能になります：

特定のファイルまたはディレクトリのプロファイリングを有効にするには、対応するカーネルMakefileに以下の行を追加してください：

mount -t debugfs none /sys/kernel/debug

カスタマイズ¶

単一のファイル（例: main.o）の場合：

  • 特定のディレクトリ内のすべてのファイルの場合：

    GCOV_PROFILE_main.o := y

  • CONFIG_GCOV_PROFILE_ALLが指定された場合でもプロファイリング対象から除外するには：

    GCOV_PROFILE := y

このメカニズムは、メインカーネルイメージにリンクされているファイルまたはカーネルモジュールとしてコンパイルされたファイルのみをサポートします。

GCOV_PROFILE_main.o := n

および：

GCOV_PROFILE := n

gcovカーネルサポートはdebugfsに以下のファイルを生成します：

ファイル¶

すべてのgcov関連ファイルの親ディレクトリ。

/sys/kernel/debug/gcov

グローバルリセットファイル：このファイルに書き込むとすべてのカバレッジデータがゼロになります。

/sys/kernel/debug/gcov/reset

gcovツールが理解する実際のgcovデータファイル。このファイルに書き込むとファイルのカバレッジデータがゼロになります。

/sys/kernel/debug/gcov/path/to/compile/dir/file.gcda

gcovツールが必要とする静的データファイルへのシンボリックリンク。このファイルは、オプション

/sys/kernel/debug/gcov/path/to/compile/dir/file.gcno

でコンパイルする際、gccによって生成されます。 -ftest-coverage.

モジュール¶

カーネルモジュールには、モジュールアンロード時にのみ実行されるクリーンアップコードが含まれることがあります。gcovメカニズムは、アンロードされたモジュールに関連するデータのコピーを保持することで、このようなコードのカバレッジデータを収集する手段を提供します。このデータはdebugfsを通じて常に利用可能です。モジュールが再度ロードされると、関連するカバレッジカウンターが以前のインスタンスからのデータで初期化されます。

この動作は、gcov_persistカーネルパラメータを指定することで無効にすることができます：

gcov_persist=0

実行時において、ユーザーは未ロードされたモジュールのデータをデータファイルまたはグローバルリセットファイルに書き込むことで無視することもできます。

ビルド機とテスト機が分離されている¶

gcovのカーネルプロファイリングインフラストラクチャは、カーネルが同じマシンでビルドおよび実行される設定で即座に動作します。カーネルが別のマシンで実行される場合、gcovツールが使用される場所に応じて特別な準備が必要です。

  1. gcovはテスト機で実行される

    テスト機のgcovツールバージョンは、カーネルビルドに使用されるgccバージョンと互換性を保つ必要があります。また、ビルドからテスト機へ以下のファイルをコピーする必要があります：

    ソースツリーから：

    • すべてのCソースファイル＋ヘッダーファイル

    ビルドツリーから：

    • すべてのCソースファイル＋ヘッダーファイル

    • すべての.gcdaおよび.gcnoファイル

    • すべてのディレクトリへのリンク

    これらのファイルがテスト機においてビルド機と同じファイルシステムの場所に配置されることが重要です。パスコンポーネントがシンボリックリンクである場合、makeのCURDIR処理のため、実際のディレクトリを使用する必要があります。

  2. gcovはビルド機で実行される

    各テストケース後にテスト機からビルド機へ以下のファイルをコピーする必要があります：

    sysfs内のgcovディレクトリから：

    • すべての.gcdaファイル

    • すべての.gcnoファイルへのリンク

    これらのファイルはビルド機の任意の場所にコピーできます。gcovはそのディレクトリを指す-oオプションで呼び出す必要があります。

    ビルド機のディレクトリ構成の例：

    /tmp/linux:    kernel source tree
/tmp/out:      kernel build directory as specified by make O=
/tmp/coverage: location of the files copied from the test machine

[user@build] cd /tmp/out
[user@build] gcov -o /tmp/coverage/tmp/out/init main.c

コンパイラに関する注意¶

GCCとLLVMのgcovツールは必ずしも互換性があります。使用するには gcov GCC生成の.gcnoおよび.gcdaファイルと llvm-cov Clangで使用してください。

GCCとClangのgcov間のビルド差異はKconfigが処理します。検出されたツールチェーンに応じて適切なgcov形式を選択します。

トラブルシューティング¶

問題

リンカーステップ中にコンパイルが中断される

原因

メインカーネルにリンクされないソースファイルまたはカスタムリンカープロシージャーでリンクされるソースファイルにプロファイリングフラグが指定されている

解決策

影響を受けるソースファイルをプロファイリングから除外するために、対応するMakefileで GCOV_PROFILE := n または GCOV_PROFILE_basename.o := n を指定してください。

問題

sysfsからコピーされたファイルが空または不完全に表示される

原因

seq_fileの仕組みにより、cpやtarなどのツールがsysfsからファイルを正しくコピーできない場合があります。

解決策

Use cat を読み込む .gcda ファイルを cp -d リンクをコピーする。代わりに Appendix B に示されているメカニズムを使用してください。

Appendix A: gather_on_build.sh¶

ビルド機でカバレッジメタファイルを収集するためのサンプルスクリプト（6aを参照）：

#!/bin/bash

KSRC=$1
KOBJ=$2
DEST=$3

if [ -z "$KSRC" ] || [ -z "$KOBJ" ] || [ -z "$DEST" ]; then
  echo "Usage: $0 <ksrc directory> <kobj directory> <output.tar.gz>" >&2
  exit 1
fi

KSRC=$(cd $KSRC; printf "all:\n\t@echo \${CURDIR}\n" | make -f -)
KOBJ=$(cd $KOBJ; printf "all:\n\t@echo \${CURDIR}\n" | make -f -)

find $KSRC $KOBJ \( -name '*.gcno' -o -name '*.[ch]' -o -type l \) -a \
                 -perm /u+r,g+r | tar cfz $DEST -P -T -

if [ $? -eq 0 ] ; then
  echo "$DEST successfully created, copy to test system and unpack with:"
  echo "  tar xfz $DEST -P"
else
  echo "Could not create file $DEST"
fi

Appendix B: gather_on_test.sh¶

テスト機でカバレッジデータファイルを収集するためのサンプルスクリプト（6bを参照）：

#!/bin/bash -e

DEST=$1
GCDA=/sys/kernel/debug/gcov

if [ -z "$DEST" ] ; then
  echo "Usage: $0 <output.tar.gz>" >&2
  exit 1
fi

TEMPDIR=$(mktemp -d)
echo Collecting data..
find $GCDA -type d -exec mkdir -p $TEMPDIR/\{\} \;
find $GCDA -name '*.gcda' -exec sh -c 'cat < $0 > '$TEMPDIR'/$0' {} \;
find $GCDA -name '*.gcno' -exec sh -c 'cp -d $0 '$TEMPDIR'/$0' {} \;
tar czf $DEST -C $TEMPDIR sys
rm -rf $TEMPDIR

echo "$DEST successfully created, copy to build system and unpack with:"
echo "  tar xfz $DEST"
