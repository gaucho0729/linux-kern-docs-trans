シーケンスカウンタとシーケンシャルロック¶

はじめに¶

シーケンスカウンタは、ロックレスリーダー（読み取り専用の再試行ループ）とライタースタービングが発生しないリーダー-ライターコンシステンシメカニズムです。これは、まれにしか書かれないデータ（例：システム時間）に対して使用され、リーダーが一貫した情報セットを必要とし、情報が変化した場合に再試行する意欲がある場合に用いられます。

読み取り側クリティカルセクションの開始時にシーケンスカウントが偶数であり、終了時に同じシーケンスカウント値が再読まれる場合、データセットは一貫しています。このデータセット内のデータは、読み取り側クリティカルセクション内でコピーする必要があります。クリティカルセクションの開始と終了の間にシーケンスカウントが変化した場合、リーダーは再試行する必要があります。

ライターは、クリティカルセクションの開始と終了時にシーケンスカウントをインクリメントします。クリティカルセクションを開始した後、シーケントカウントは奇数になり、リーダーに更新が進行中であることを示します。クリティカルセクション終了時にシーケンスカウントは再び偶数に戻り、リーダーが進展できるようになります。

シーケンスカウンタの書き込み側クリティカルセクションは、読み取り側セクションによってプリエンプションまたは割り込まれてはなりません。それ以外の場合、リーダーはスピンロック状態でスケジューラータイク全体にわたって待機する必要があります。そのリーダーがリアルタイムスケジューリングクラスに属する場合、永遠にスピンし、カーネルはライブロックを発生させます。

保護されたデータにポインタが含まれている場合、このメカニズムは使用できません。ライターがリーダーが追跡しているポインタを無効化する可能性があるためです。

シーケンスカウンタ（seqcount_t)¶

これは素朴なカウントメカニズムであり、複数のライターに対する保護は提供していません。そのため、書き込み側クリティカルセクションは外部ロックによってシリアル化される必要があります。

書き込みシリアル化プリミティブが明示的にプリエンプションを無効にしない場合、書き込み側セクションに入る前にプリエンプションを明示的に無効にする必要があります。読み取りセクションがハードIRQまたはソフトIRQコンテキストから呼び出される場合、割り込みまたはボトムハーフもそれぞれ書き込みセクションに入る前に無効にする必要があります。

ライターサーバライズーションと非プリエンプションのシーケンスカウンタ要件を自動的に処理したい場合は、 シーケンシャルロック（seqlock_t） を呼び出してください。

初期化:

/* dynamic */
seqcount_t foo_seqcount;
seqcount_init(&foo_seqcount);

/* static */
static seqcount_t foo_seqcount = SEQCNT_ZERO(foo_seqcount);

/* C99 struct init */
struct {
        .seq   = SEQCNT_ZERO(foo.seq),
} foo;

書き込みパス:

/* Serialized context with disabled preemption */

write_seqcount_begin(&foo_seqcount);

/* ... [[write-side critical section]] ... */

write_seqcount_end(&foo_seqcount);

読み取りパス:

do {
        seq = read_seqcount_begin(&foo_seqcount);

        /* ... [[read-side critical section]] ... */

} while (read_seqcount_retry(&foo_seqcount, seq));

関連するロックを持つシーケンスカウンタ（seqcount_LOCKNAME_t)¶

議論されているように、 シーケンスカウンタ（seqcount_t）シーケンスカウンタの書込み側のクリティカルセクションはシリアル化され、非プリエンプティブでなければならない。このシーケンスカウンタの変種は、初期化時に書込み側のシリアル化に使用されるロックを関連付けることで、lockdepが書込み側のクリティカルセクションが適切にシリアル化されているかを検証できるようにします。

lockdepが無効化されている場合、またはストレージやランタイムのオーバーヘッドがない場合は、このロック関連付けはノーオペレーション（NOOP）です。lockdepが有効化されている場合、lock pointerはstruct seqcountに保存され、書込み側のクリティカルセクションの開始時にlockdepの「ロックが保持されている」アサーションが挿入され、適切に保護されているかを検証します。

プリエンプションを明示的に無効化しないロックタイプでは、書込み側の関数でプリエンプション保護が強制されます。

以下のシーケンスカウンタと関連付けられたロックが定義されています：

  • seqcount_spinlock_t

  • seqcount_raw_spinlock_t

  • seqcount_rwlock_t

  • seqcount_mutex_t

  • seqcount_ww_mutex_t

シーケンスカウンタの読み取りと書き込みAPIは、plain seqcount_tまたは上記のseqcount_LOCKNAME_tの変種のいずれかを引数として受け取ります。

初期化（「LOCKNAME」をサポートされているロックの1つに置き換えて）：

/* dynamic */
seqcount_LOCKNAME_t foo_seqcount;
seqcount_LOCKNAME_init(&foo_seqcount, &lock);

/* static */
static seqcount_LOCKNAME_t foo_seqcount =
        SEQCNT_LOCKNAME_ZERO(foo_seqcount, &lock);

/* C99 struct init */
struct {
        .seq   = SEQCNT_LOCKNAME_ZERO(foo.seq, &lock),
} foo;

書き込みパス：同様に シーケンスカウンタ（seqcount_t）、関連付けられた書き込みシリアル化ロックが取得されたコンテキストから実行されている場合。

読み取りパス：同様に シーケンスカウンタ（seqcount_t）.

ラッチシーケンスカウンタ（seqcount_latch_t)¶

ラッチシーケンスカウンタは、マルチバージョンコンカレンシー制御メカニズムであり、埋め込まれたseqcount_tカウンタの偶奇値を用いて保護データの2つのコピー間を切り替えることで、シーケンスカウンタの読み取りパスが自身の書込み側クリティカルセクションを安全に中断できるようにします。

読み取り側セクションがNMIハンドラから呼び出される可能性がある場合、書込み側セクションが読み取りによって中断されないことを保証できない場合はseqcount_latch_tを使用してください。

シーケンシャルロック（seqlock_t)¶

これは、前述のメカニズムに加え、 シーケンスカウンタ（seqcount_t） 書込み側のシリアル化と非プリエンプティブ性を実現する埋め込まれたスピニングロックを含みます。

読み取り側セクションがハードIRQまたはソフトIRQコンテキストから呼び出される場合、それぞれの割り込みまたはボトムハーフを無効化する書込み側関数の変種を使用してください。

初期化:

/* dynamic */
seqlock_t foo_seqlock;
seqlock_init(&foo_seqlock);

/* static */
static DEFINE_SEQLOCK(foo_seqlock);

/* C99 struct init */
struct {
        .seql   = __SEQLOCK_UNLOCKED(foo.seql)
} foo;

書き込みパス:

write_seqlock(&foo_seqlock);

/* ... [[write-side critical section]] ... */

write_sequnlock(&foo_seqlock);

読み取りパス、3つのカテゴリ：

  1. 通常のシーケンスリーダーは、ライターアクセスをブロックしないが、ライターが進行中である場合、シーケンス番号の変化を検知して再試行する必要がある。ライターはリーダーの進行を待つことなく：

    do {
        seq = read_seqbegin(&foo_seqlock);

        /* ... [[read-side critical section]] ... */

} while (read_seqretry(&foo_seqlock, seq));

  2. ロックングリーダーは、ライターまたは他のロックングリーダーが進行中である場合、待機する。進行中のロックングリーダーはライターのクリティカルセクションの進入をブロックする。このリーダーロックは排他ロックである。rwlock_tとは異なり、1つのロックングリーダーのみがこれを取得できる：

    read_seqlock_excl(&foo_seqlock);

/* ... [[read-side critical section]] ... */

read_sequnlock_excl(&foo_seqlock);

  3. 渡されたマーカーに応じて、条件付きロックレスリーダー（1の場合）またはロックリーダー（2の場合）を使用します。これにより、書き込みアクティビティの急激な増加時にロックレスリーダーのスターバーション（再試行ループの過剰）を回避できます。まず、ロックレスリーダーの試行を行います（マーカーを渡す）。その試行が失敗した場合（奇数のシーケンスカウンタが返され、次のイテレーションのマーカーとして使用されます）、ロックレスリーダーはフルなロックリーダーに変換され、再試行ループは必要ありません。

    /* marker; even initialization */
int seq = 0;
do {
        read_seqbegin_or_lock(&foo_seqlock, &seq);

        /* ... [[read-side critical section]] ... */

} while (need_seqretry(&foo_seqlock, seq));
done_seqretry(&foo_seqlock, seq);

パラメータ

説明

これは通常の一貫性保証ではなく、順序保証を提供するために使用できます。これは2つの連続するwmb()を1つのwmbに統合できるため、1つ安いです。

バリアンス周辺の書き込みはすべてアトミック（例: WRITE_ONCEを通じて）宣言する必要があります。a) 他のスレッドに書き込みが一括して見えるようにし、コンパイラの最適化を回避するため；b) どの書き込みがリーダーのクリティカルセクションに伝達されるべきかを文書化するためです。これは、バリアンスの前後にある書き込みがseq-writerのクリティカルセクション内に含まれていないため、リーダーが進行中の書き込みを認識する必要があるからです：

seqcount_t seq;
bool X = true, Y = false;

void read(void)
{
        bool x, y;

        do {
                int s = read_seqcount_begin(&seq);

                x = X; y = Y;

        } while (read_seqcount_retry(&seq, s));

        BUG_ON(!x && !y);
}

void write(void)
{
        WRITE_ONCE(Y, true);

        raw_write_seqcount_barrier(seq);

        WRITE_ONCE(X, false);
}

void raw_write_seqcount_latch(seqcount_latch_t *s)¶

ラッチリーダーを偶数/奇数コピーにリダイレクト

パラメータ

seqcount_latch_t *s

seqcount_latch_tへのポインタ

説明

ラッチ技術は、非原子的変更中にクエリを許可するマルチバージョンコンカレンシー制御手法です。クエリが変更を妨げることを保証できる場合（例：コンカレンシーがCPU間で厳密に制御されている場合）は、この技術は必要ありません。

伝統的なRCU/ロックレスデータ構造は原子的変更によってクエリが古い状態または新しい状態を観測することを保証しますが、ラッチは非原子的更新にも同様の保証を提供します。トレードオフはストレージコストの倍増です。データ構造全体の2つのコピーを維持する必要があります。

非常に単純に説明すると、まず1つのコピーを変更し、その後もう一つのコピーを変更します。これにより常に1つのコピーが安定した状態にあり、応答を提供できるようになります。

基本的な形式は以下の通りです：

struct latch_struct {
        seqcount_latch_t        seq;
        struct data_struct      data[2];
};

外部シリアル化されていると仮定される変更は以下の手順を実行します：

void latch_modify(struct latch_struct *latch, ...)
{
        smp_wmb();      // Ensure that the last data[1] update is visible
        latch->seq.sequence++;
        smp_wmb();      // Ensure that the seqcount update is visible

        modify(latch->data[0], ...);

        smp_wmb();      // Ensure that the data[0] update is visible
        latch->seq.sequence++;
        smp_wmb();      // Ensure that the seqcount update is visible

        modify(latch->data[1], ...);
}

クエリは以下の形式になります：

struct entry *latch_query(struct latch_struct *latch, ...)
{
        struct entry *entry;
        unsigned seq, idx;

        do {
                seq = raw_read_seqcount_latch(&latch->seq);

                idx = seq & 0x01;
                entry = data_query(latch->data[idx], ...);

        // This includes needed smp_rmb()
        } while (read_seqcount_latch_retry(&latch->seq, seq));

        return entry;
}

変更中にクエリは最初にdata[1]にリダイレクトされます。その後data[0]を変更します。変更が完了したらクエリをdata[0]に戻し、data[1]を変更できます。

注意2：

データが動的データ構造である場合、通常のRCUパターンを使用してデータ構造内のオブジェクトのライフタイムを管理する必要があります。

注意

非原子的変更不要という条件は、データが動的データ構造である場合の新しいエントリの公開を含みません。

イテレーションがdata[0]から開始され、変更シーケンス全体を欠くして中断される可能性があります。再開後に新しいエントリを観測するかもしれません。

説明

void read_seqbegin_or_lock(seqlock_t *lock, int *seq)¶

seqlock_t ロックレスまたはロックリーダーの開始

パラメータ

seqlock_t *lock

seqlock_tへのポインタ

int *seq

マーカーおよび戻り値パラメータ。渡された値が偶数の場合、リーダーは ロックレス seqlock_t リーダーとして read_seqbegin()渡された値が奇数の場合、リーダーは ロック リーダーとして read_seqlock_excl()この関数の最初の呼び出しにおいて、呼び出し元 grace periodsを尊重しなければなりませんし、 初期化し、偶数値を seq; このように、ロックレスの読み取りがまず試されるようになります。

説明

read_seqbegin_or_lock は、通常のロックレス seqlock_t 読み取りセクションをまず試すように設計された API です。奇数のカウンターが見つかった場合、ロックレス読み取りの試行は失敗し、次の読み取り反復では完全な seqlock_t ロックリーダーに変換されます。

これは、書き込み側のアクティビティが急激に増加した場合のロックレスリーダーの starvation（過剰な再試行ループ）を回避するために通常使用されます。

確認 シーケンスカウンタとシーケンシャルロック テンプレート例コードのため。

コンテキスト

seqlock_tの書き込みセクション、 または他の読み込みセクションがhardirqまたはsoftirqコンテキストから呼び出せる場合、この関数の_irqsaveまたは_bhバリアントを使用してください。

戻り値

遭遇したシーケンスカウンタ値は、 seq パラメータとしてオーバーロードされ、戻り値として使用されます。この戻り値は need_seqretry(). 読み取りセクションを再試行する必要がある場合、この戻り値も次の seq パラメータとして次の read_seqbegin_or_lock() 反復に渡す必要があります。
