ロックの教訓¶

レッスン1: スピンロック¶

ロックの最も基本的なプリミティブはスピンロックです:

static DEFINE_SPINLOCK(xxx_lock);

      unsigned long flags;

      spin_lock_irqsave(&xxx_lock, flags);
      ... critical section here ..
      spin_unlock_irqrestore(&xxx_lock, flags);

上記は常に安全です。これはローカルに割り込みを無効にしますが、スピンロック自体がグローバルなロックを保証するため、そのロックで保護されている領域内に複数の制御スレッドが存在しないことを保証します。UP環境でもこれで十分に機能するため、コードはUPとSMPの違いについて心配する必要がありません。スピンロックは両方の環境で正しく動作します。

注意！スピンロックのメモリへの影響については、以下で詳しく説明しています:

Documentation/memory-barriers.txt

  1. ACQUIRE操作。

  2. RELEASE操作。

上記は通常非常に簡単です（ほとんどの場合、1つのスピンロックで十分です - 複数のスピンロックを使用すると、ことさら複雑になり、場合によっては遅くなるため、通常は変数を操作する必要があるシーケンスだけに限って価値があります）。 知っている 分割する必要があります：確信がない場合は一切避けてください。

これはスピンロックに関する本当に難しい部分です：スピンロックを使用し始めると、以前に気づいていなかった領域にまで拡張される傾向があります。これは共有データ構造を正しく保護するためのスピンロックを確保しなければならないからです。 どこでも スピンロックは、他のコードとは完全に独立した場所（例えば、誰もが触らない内部ドライバデータ構造など）に最も簡単に追加できます。

注意！スピンロックは、あなたが また ロック自体を使ってCPU間でロックを実行する必要があります。これは、共有変数に触れるすべてのコードが使用するスピンロックについて合意しなければならないことを意味します。

レッスン2: レーダー-ライタースピンロック。¶

データアクセスが共有変数から主に読み取りを行うという自然なパターンを持つ場合、レーダー-ライターロック（rw_lock）版のスピンロックは時として役立ちます。それらは複数の読者を同じクリティカルセクションに同時に許可しますが、変数を変更する場合は排他的なライターロックを取得する必要があります。

注意！レーダー-ライターロックは、単純なスピンロックよりもより多くのアトミックなメモリ操作を必要とします。読者臨界区が長くない限り、スピンロックを使用する方が良いです。

これらのルーチンは上記と同じです:

rwlock_t xxx_lock = __RW_LOCK_UNLOCKED(xxx_lock);

     unsigned long flags;

     read_lock_irqsave(&xxx_lock, flags);
     .. critical section that only reads the info ...
     read_unlock_irqrestore(&xxx_lock, flags);

     write_lock_irqsave(&xxx_lock, flags);
     .. read and write exclusive access to the info ...
     write_unlock_irqrestore(&xxx_lock, flags);

上記のようなロックは、リンクリストなどの複雑なデータ構造に有用です、特にリスト自体を変更せずにエントリを検索する場合。読み取りロックは多数の並行読者を許可します。リストが に指定する必要があります。 リストが

また、読み取りロックを書き込みロックに「アップグレード」することはできません。そのため、いつでも変更が必要な場合（たとえ毎回行わないとしても）は、最初から書き込みロックを取得しなければなりません。

レッスン3: スピンロックの再考。¶

上記の単一スピンロックのプリミティブは、唯一の選択肢ではありません。これらは最も安全な方法であり、すべての状況で動作しますが、一部 なぜなら 安全なため、それらは比較的遅く、必要以上に遅いです。これは割込みを無効にする必要があるためです（x86では単一の命令ですが、コストが高く、他のアーキテクチャではさらに悪化します）。

複数のCPUでデータ構造を保護する必要がある場合、スピンロックを使用する際にはコスト効率の高いバージョンを使用できます。割込みハンドラでスピンロックが使用されないことを確認している場合、割込み用のバージョンを使用できます:

spin_lock(&lock);
...
spin_unlock(&lock);

(もちろん、同等の読み書きバージョンも含めて)。スピンロックは同じ種類の排他アクセスを保証し、はるかに高速です。これは、データが常に「プロセスコンテキスト」から操作される（つまり割込みが関与しない）ことを知っている場合に役立ちます。

割込みがスピンロックに関与する場合、これらのバージョンを使用してはいけない理由は、デッドロックが発生する可能性があるからです:

spin_lock(&lock);
...
        <- interrupt comes in:
                spin_lock(&lock);

割込みがすでにロックされた変数をロックしようとする場合。これは別のCPUで割込みが発生した場合に問題ありませんが、同じCPUでロックされている場合、ロックが明らかに解放されません（割込みがロックを待っているため、ロック保持者は割込みを処理するまで実行を中断されます）。

(これは、割込みバージョンのスピンロックがローカルな割込みのみを無効にする理由でもあります。他のCPUでの割込みでスピンロックを使用しても問題ありません。なぜなら、他のCPUでの割込みはロック保持中のCPUを中断しないからです。そのため、ロック保持者は継続して実行し、最終的にロックを解放します。)

参照情報:¶

動的初期化には、spin_lock_init()またはrwlock_init()を適切に使用してください:

spinlock_t xxx_lock;
rwlock_t xxx_rw_lock;

static int __init xxx_init(void)
{
     spin_lock_init(&xxx_lock);
     rwlock_init(&xxx_rw_lock);
     ...
}

module_init(xxx_init);

静的初期化には、DEFINE_SPINLOCK() / DEFINE_RWLOCK()または__SPIN_LOCK_UNLOCKED() / __RW_LOCK_UNLOCKED()を適切に使用してください。
