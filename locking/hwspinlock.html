ハードウェアスピンロックフレームワーク¶

はじめに¶

ハードウェアスピンロックモジュールは、異種プロセッサ間や単一の共有オペレーティングシステムを実行していないプロセッサ間での同期と相互排他的な処理にハードウェアの支援を提供します。

例えば、OMAP4はデュアルCortex-A9、デュアルCortex-M3、C64x+ DSPを搭載しており、それぞれが異なるオペレーティングシステムを実行しています（マスタープロセッサ（A9）は通常Linuxを、スレーブプロセッサ（M3とDSP）はRTOSの一種を実行しています）。

汎用的なhwspinlockフレームワークは、プラットフォームに依存しないドライバがhwspinlockデバイスを使用して、リモートプロセッサ間で共有されるデータ構造にアクセスできるようにします。これにより、他のメカニズムが存在しない場合でも同期と相互排他的な処理が実現できます。

これは、例えばプロセッサ間通信において必要です。OMAP4では、CPU重いマルチメディアタスクは、SyslinkというIPCサブシステムを通じてリモートM3および/またはC64x+スレーブプロセッサにオフロードされます。

メッセージベースの通信を高速化するためには、リモートプロセッサから到達したメッセージを適切なユーザープロセスに届けるための最小限のカーネルサポートが必要です。

この通信は、リモートプロセッサ間で共有されるシンプルなデータ構造に基づいており、アクセスはhwspinlockモジュールを用いて同期されています（リモートプロセッサが直接この共有データ構造に新しいメッセージを配置します）。

共通のhwspinlockインターフェースにより、汎用的なプラットフォームに依存しないドライバの実装が可能になります。

ユーザーAPI¶

struct hwspinlock *hwspin_lock_request(void);

hwspinlockを動的に割り当ててそのアドレスを返すか、利用されていないhwspinlockがない場合はNULLを返します。このAPIの利用者は、ロックのIDをリモートコアに伝達する必要があります。

プロセスコンテキストから呼び出されるべきです（スリープ可能）。

struct hwspinlock *hwspin_lock_request_specific(unsigned int id);

特定のhwspinlock IDを割り当ててそのアドレスを返すか、そのhwspinlockがすでに使用中である場合はNULLを返します。ボードコードは、特定のhwspinlock IDを予定された用途に割り当てるためにこの関数を呼び出します。

プロセスコンテキストから呼び出されるべきです（スリープ可能）。

int of_hwspin_lock_get_id(struct device_node *np, int index);

OF phandleベースの特定のロックのグローバルロックIDを取得します。この関数は、hwspinlockモジュールのDTユーザーが特定のhwspinlockのグローバルロックIDを取得し、通常のhwspin_lock_request_specific() APIでリクエストできるようにします。

成功時はロックID番号を返し、hwspinlockデバイスがまだコアに登録されていない場合は-EPROBE_DEFERを返し、その他のエラー値も返します。

プロセスコンテキストから呼び出されるべきです（スリープ可能）。

int hwspin_lock_free(struct hwspinlock *hwlock);

以前に割り当てられたhwspinlockを解放します。成功時は0を返し、失敗時は適切なエラーコード（例: hwspinlockがすでに解放されている場合の-EINVALなど）を返します。

プロセスコンテキストから呼び出されるべきです（スリープ可能）。

int hwspin_lock_timeout(struct hwspinlock *hwlock, unsigned int timeout);

以前に割り当てられたhwspinlockをタイムアウト制限（msecs単位）でロックします。hwspinlockがすでに取得されている場合、関数はビジー ループで待機しますが、タイムアウトが発生すると中断します。この関数が成功して返る場合、プリエンプションが無効化されるため、呼び出し元はスリープしてはいけません。また、ハードウェア インターコネクトのリモート コアのポーリングを最小限に抑えるため、hwspinlockをできるだけ早く解放することを推奨します。

成功時は0を返し、失敗時は適切なエラーコード（特にタイムアウトmsecs経過後にhwspinlockがまだビジーな場合の-ETIMEDOUTなど）を返します。この関数は決してスリープしません。

典型的な使用法¶

#include <linux/hwspinlock.h>
#include <linux/err.h>

int hwspinlock_example1(void)
{
        struct hwspinlock *hwlock;
        int ret;

        /* dynamically assign a hwspinlock */
        hwlock = hwspin_lock_request();
        if (!hwlock)
                ...

        id = hwspin_lock_get_id(hwlock);
        /* probably need to communicate id to a remote processor now */

        /* take the lock, spin for 1 sec if it's already taken */
        ret = hwspin_lock_timeout(hwlock, 1000);
        if (ret)
                ...

        /*
        * we took the lock, do our thing now, but do NOT sleep
        */

        /* release the lock */
        hwspin_unlock(hwlock);

        /* free the lock */
        ret = hwspin_lock_free(hwlock);
        if (ret)
                ...

        return ret;
}

int hwspinlock_example2(void)
{
        struct hwspinlock *hwlock;
        int ret;

        /*
        * assign a specific hwspinlock id - this should be called early
        * by board init code.
        */
        hwlock = hwspin_lock_request_specific(PREDEFINED_LOCK_ID);
        if (!hwlock)
                ...

        /* try to take it, but don't spin on it */
        ret = hwspin_trylock(hwlock);
        if (!ret) {
                pr_info("lock is already taken\n");
                return -EBUSY;
        }

        /*
        * we took the lock, do our thing now, but do NOT sleep
        */

        /* release the lock */
        hwspin_unlock(hwlock);

        /* free the lock */
        ret = hwspin_lock_free(hwlock);
        if (ret)
                ...

        return ret;
}

実装者向けAPI¶

int hwspin_lock_register(struct hwspinlock_device *bank, struct device *dev,
              const struct hwspinlock_ops *ops, int base_id, int num_locks);

プラットフォーム固有の実装から呼び出される必要があります。新しいhwspinlockデバイス（通常は多数のロックを含むバンク）を登録するためのものです。プロセスコンテキストから呼び出さなければなりません（この関数はスリープする可能性があります）。

成功時は0を返し、失敗時は適切なエラーコードを返します。

int hwspin_lock_unregister(struct hwspinlock_device *bank);

ベンダー固有の実装から呼び出される必要があります。hwspinlockデバイス（通常は多数のロックを含むバンク）をアンレジストするためのものです。

プロセスコンテキストから呼び出さなければなりません（この関数はスリープする可能性があります）。

成功時はhwspinlockのアドレスを返し、エラー（例: hwspinlockがまだ使用中の場合など）時はNULLを返します。

重要な構造体¶

struct hwspinlock_deviceは、通常ハードウェアロックのバンクを含むデバイスです。これはhwspinlock実装がhwspin_lock_register() APIを使用して登録します。

/**
* struct hwspinlock_device - a device which usually spans numerous hwspinlocks
* @dev: underlying device, will be used to invoke runtime PM api
* @ops: platform-specific hwspinlock handlers
* @base_id: id index of the first lock in this device
* @num_locks: number of locks in this device
* @lock: dynamically allocated array of 'struct hwspinlock'
*/
struct hwspinlock_device {
        struct device *dev;
        const struct hwspinlock_ops *ops;
        int base_id;
        int num_locks;
        struct hwspinlock lock[0];
};

struct hwspinlock_deviceは、ハードウェアロックを1つ表す各hwspinlock構造体を含む配列を含みます。

/**
* struct hwspinlock - this struct represents a single hwspinlock instance
* @bank: the hwspinlock_device structure which owns this lock
* @lock: initialized and used by hwspinlock core
* @priv: private data, owned by the underlying platform-specific hwspinlock drv
*/
struct hwspinlock {
        struct hwspinlock_device *bank;
        spinlock_t lock;
        void *priv;
};

ロックのバンクを登録する際には、hwspinlockドライバーはロックのprivメンバのみを設定する必要があります。他のメンバはhwspinlockコアによって設定および初期化されます。

実装コールバック¶

struct hwspinlock_opsには3つの可能なコールバックが定義されています：

struct hwspinlock_ops {
        int (*trylock)(struct hwspinlock *lock);
        void (*unlock)(struct hwspinlock *lock);
        void (*relax)(struct hwspinlock *lock);
};

最初の2つのコールバックは必須です：

->trylock()コールバックは、ロックを取得するための単一の試みを行い、失敗時は0、成功時は1を返す必要があります。このコールバックは ではありません スリープする可能性があります。

->unlock()コールバックはロックを解放します。常に成功し、同様にスリープする可能性があります。 ではありません スリープする可能性があります。

->relax()コールバックはオプションです。hwspinlockコアがロックのスピン中に呼び出され、ベースとなる実装が->trylock()の連続する呼び出し間で遅延を強制するために使用できます。同様にスリープする可能性があります。 ではありません スリープする可能性があります。
