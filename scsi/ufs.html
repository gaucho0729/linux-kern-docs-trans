ユニバーサルフラッシュストレージ¶

1. 概要¶

ユニバーサルフラッシュストレージ(UFS)はフラッシュデバイス用のストレージ仕様です。モバイル機器（スマートフォンやタブレットコンピュータなど）における埋め込み型および外付け型フラッシュメモリベースのストレージに共通のインターフェースを提供することを目的としています。この仕様はJEDEC Solid State Technology Associationによって定義されています。UFSはMIPI M-PHY物理層標準に基づいています。UFSはMIPI M-PHYを物理層として、MIPI Uniproをリンク層として使用します。

UFSの主な目標は以下の通りです：

  • 最適化されたパフォーマンス：

    UFSバージョン1.0および1.1における目標パフォーマンスは以下の通りです：

    • Gear1のサポートは必須です（レートA：1248Mbps、レートB：1457.6Mbps）

    • Gear2のサポートはオプションです（レートA：2496Mbps、レートB：2915.2Mbps）

    将来の標準バージョン、

    • Gear3（レートA：4992Mbps、レートB：5830.4Mbps）

  • 低消費電力

  • 高ランダムIOPsおよび低レイテンシー

2. UFSアーキテクチャ概要¶

UFSはSCSI SAM-5アーキテクチャモデルに基づく層型通信アーキテクチャを持っています。

UFS通信アーキテクチャは以下のレイヤーから構成されています、

2.1 アプリケーションレイヤー¶

アプリケーションレイヤーはUFSコマンドセットレイヤー（UCS）、タスクマネージャー、デバイスマネージャーから構成されています。UFSインターフェースはプロトコルに依存しない設計ですが、バージョン1.0および1.1ではSCSIをベースプロトコルとして選択しています。

UFSはSPC-4およびSBC-3で定義されたSCSIコマンドのサブセットをサポートしています。

  • UCS：

    UFS仕様でサポートされるSCSIコマンドを処理します。

  • タスクマネージャー：

    UFSで定義されたタスク管理機能を処理し、コマンドキュー制御に使用されます。

  • デバイスマネージャー：

    デバイスレベルの操作およびデバイス構成操作を処理します。デバイスレベル操作は主に電源管理操作およびインターコネクトレイヤーへのコマンドに関連し、デバイスレベル構成はデバイスの設定情報を変更および取得するためにクエリリクエストを処理します。

2.2 UFSトランスポートプロトコル（UTP）レイヤー¶

UTPレイヤーは上位レイヤーに対してサービスアクセスポイントを通じてサービスを提供します。UTPは上位レイヤーに対して3つのサービスアクセスポイントを定義しています。

  • UDM_SAP：デバイスマネージャー向けのサービスアクセスポイントで、デバイスレベル操作を実行するためにクエリリクエストを通じて行われます。

  • UTP_CMD_SAP：コマンドサービスアクセスポイントで、UCSを通じてコマンドを転送します。

  • UTP_TM_SAP：タスク管理サービスアクセスポイントで、タスクマネージャーを通じてタスク管理機能を転送します。

UTPはUFSプロトコル情報単位（UPIU）を通じてメッセージを転送します。

2.3 UFSインターコネクト（UIC）レイヤー¶

UICはUFSレイヤードアーキテクチャの最下層です。UFSホストとUFSデバイス間の接続を処理します。UICはMIPI UniProとMIPI M-PHYから構成されています。UICは上位レイヤーに対して2つのサービスアクセスポイントを提供します。

  • UIC_SAP: UFSホストとUFSデバイス間でUPIUを転送します。

  • UIO_SAP: Uniproレイヤーにコマンドを発行します。

3. UFSHCD概要¶

UFSホストコントローラードライバーはLinux SCSIフレームワークに基づいています。UFSHCDはSCSI MidlayerとPCIeベースのUFSホストコントローラー間のインターフェースとして機能する低レベルのデバイスドライバーです。

現在のUFSHCD実装は次の機能をサポートしています、

3.1 UFSコントローラー初期化¶

初期化モジュールはUFSホストコントローラーをアクティブな状態にし、UFSHCDとUFSデバイス間でコマンド/応答を転送できるように準備します。

3.2 UTP転送リクエスト¶

UFSHCDの転送リクエスト処理モジュールはSCSI MidlayerからSCSIコマンドを受信し、UPIUを形成してUFSHCDホストコントローラーに送信します。また、このモジュールはUFSHCDホストコントローラーからUPIU形式で受信した応答をデコードし、SCSI Midlayerにコマンドの状態を通知します。

3.3 UFSエラー処理¶

エラー処理モジュールはホストコントローラー致命的エラー、デバイス致命的エラー、およびUICインターコネクトレイヤー関連のエラーを処理します。

3.4 SCSIエラー処理¶

これはSCSI Midlayerに登録されたUFSHCD SCSIエラー処理ルーチンを通じて行われます。SCSI Midlayerが発行するエラー処理コマンドの例にはAbort task、Lun reset、host resetがあります。UFSHCDがこれらのタスクを実行するためのルーチンは、.eh_abort_handler、.eh_device_reset_handler、.eh_host_reset_handlerを通じてSCSI Midlayerに登録されます。

このバージョンのUFSHCDではクエリリクエストおよび電源管理機能は実装されていません。

4. BSGサポート¶

このトランスポートドライバーはUFSデバイスとUFSプロトコル情報単位（UPIU）を交換することをサポートします。通常、ユーザー空間ではufs_bsg.hを参照してstruct ufs_bsg_requestとstruct ufs_bsg_replyをrequest_upiuとreply_upiuとして割り当てます。これらのUPIUを埋める際にはJEDEC規格UFS2.1の第10.7節に従う必要があります。 Caveat emptor: ドライバーはさらに入力検証を行わず、UPIUをそのままデバイスに送信します。/dev/ufs-bsgにあるbsgデバイスを開き、適切なsg_io_v4を使用してSG_IOを送信してください：

io_hdr_v4.guard = 'Q';
io_hdr_v4.protocol = BSG_PROTOCOL_SCSI;
io_hdr_v4.subprotocol = BSG_SUB_PROTOCOL_SCSI_TRANSPORT;
io_hdr_v4.response = (__u64)reply_upiu;
io_hdr_v4.max_response_len = reply_len;
io_hdr_v4.request_len = request_len;
io_hdr_v4.request = (__u64)request_upiu;
if (dir == SG_DXFER_TO_DEV) {
        io_hdr_v4.dout_xfer_len = (uint32_t)byte_cnt;
        io_hdr_v4.dout_xferp = (uintptr_t)(__u64)buff;
} else {
        io_hdr_v4.din_xfer_len = (uint32_t)byte_cnt;
        io_hdr_v4.din_xferp = (uintptr_t)(__u64)buff;
}

ディスクリプタを読み書きする場合は、sg_io_v4の適切なxferpを使用してください。

https://github.com/westerndigitalcorporation/ufs-tool

ツールおよびそのサポートされている機能についてのより詳細な情報は、ツールのREADMEをご参照ください。
