2. バージョン履歴¶

  • 3.0 (2005年12月1日)

    • ドライバーをSCSIトランスポートクラスインフラストラクチャを使用して更新

    • adaptecからリリースされたドライバーバージョン2.0.15のサポートシーケンサーやコア修正を導入

  • 1.3.11 (2003年7月11日)

    • 複数のデッドロック問題を修正

    • 29320ALPおよび39320BのIDを追加

  • 1.3.10 (2003年6月3日)

    • SCB_TAGフィールドを16バイト境界に合わせる。これにより一部のPCI-33バスでのSCB破損を回避

    • Rev Bハードウェアでの非ゼロLUNを修正

    • 2.5.X SCSIプロシージャルFSインターフェースの変更に対応

    • 8bit WDTRメッセージでアシンクロ通信をネゴシエーションする際、ターゲットが我々がアシンクロであることを認識するため、オフセット0のSDTRを送信。これはQuantum Atlas 10Kのファームウェア欠陥への対応策

    • コントローラーのスリープと再開を実装

    • ドライバのアタッチ時にPCIエラー状態をクリアし、他のドライバのプローブによって以前にコントローラーを主張する前に行われたストレートなライトによってメモリマップドI/Oが無効になるのを防ぎます。

  • 1.3.9 (2003年5月22日)

    • コンパイラエラーを修正します。

    • 4GB境界を越えるセグメントのS/G分割を削除します。これはLinuxでは発生しないことが保証されています。

    • 2.5.Xカーネルで使用されるscsi_report_device_reset()のサポートを追加します。

    • 7901Bのサポートを追加します。

    • パケット化されたLUN Rev A回避策の処理を簡略化します。

    • 無視 Wide Residue メッセージの処理を修正・簡略化します。以前のコードでは、トランザクションデータ長が偶数だった場合に残差を報告できませんでした。

  • 1.3.8 (2003年4月29日)

    • コマンドラインインターフェースコードでアクセスされる型の修正を行います。

    • いくつかのファームウェアの最適化を行います。

    • "予期しないPKTバスフリー"エラーを修正します。

    • ホストにステータス不良のコマンドを通知するためのシーケンサーイニットを用います。通知をdeferする際には、未完了のセレクションがなくなるのを待つことで、ホストの中断時間を最小限に抑えます。

    • 2.2.X以前のサポートを削除します。

    • 新しい2.5.X割込みAPIのサポートを追加します。

    • ビッグエンディアンアーキテクチャのサポートを修正します。

  • 1.3.7 (2003年4月16日)

    • Use del_timer_sync() コントローラーシャットダウン時にタイムアウトが待機していないことを確認します。

    • 2.5.Xカーネル以前のバージョンでは、SCSI mallocプールのフラグメンテーションを避けるためにセグメントリストサイズを慎重に調整します。

    • /proc出力のチャネル表示を整理します。

    • add-single-device時にmid-layerデバイスリスト内の重複デバイスエントリを回避するワークアラウンドを実装します。

  • 1.3.6 (2003年3月28日)

    • ドメイン検証コードにおけるダブルフリーバグを修正します。

    • コントローラーシャットダウン時にfreeされたメモリへの参照を修正します。

    • SE→LVD変化時にバスをリセットします。これはトランシーバーをリセットするため必要です。

  • 1.3.5 (2003年3月24日)

    • いくつかのレジスタウィンドウモードのバグを修正します。

    • /procおよび診断表示でPPRフラグに読み込みストリーミングを含めます。

    • 2.5.XカーネルにおけるPCIホットプラグサポートを追加します。

    • RevAハードウェアのデフォルトプリコンパケーション値を修正します。

    • ドメイン検証スレッドシャットダウンを修正します。

    • H2A4におけるパケット化操作中のLEDの点滅を明るくするファームウェアワークアラウンドを追加します。

    • /procでのユーザー読み込みストリーミング設定の表示を修正します。

    • ドライバロックを簡略化し、mid-layerからのドライバエントリ時にio_request_lockを解放します。

    • コマンドラインパースを整理し、aiclibに大部分のコードを移動します。

3. コマンドラインオプション¶

警告

これらのドライバパラメータを誤って変更または追加するとシステムが動作しなくなる可能性があります。注意して使用してください。

/etc/modprobe.d/ディレクトリに.confファイルを配置し、以下の行を追加または編集してください options aic79xx aic79xx=[command[,command...]] オプションを指定する必要があります。形式は以下の通りです： command 以下のいずれかまたは複数を含みます

verbose
定義

ドライバの動作中に追加の情報メッセージを有効にします。

可能な値

このオプションはフラグです

デフォルト値

無効化されている場合です。

debug:[value]
定義

さまざまなデバッグ情報のレベルを有効にします。デバッグマスクのビット定義は、drivers/scsi/aic7xxx/aic79xx.h ファイルの「Debug」セクションに記載されています。

可能な値

0x0000 = デバッグなし、0xffff = 完全なデバッグ

デフォルト値

0x0000

no_reset
定義

初期プローブフェーズ中にバスをリセットしない

可能な値

このオプションはフラグです

デフォルト値

無効化されている場合です。

extended
定義

コントローラーで拡張変換を強制

可能な値

このオプションはフラグです

デフォルト値

無効化されている場合です。

periodic_otag
定義

順序タグを定期的に送信してタグの枯渇を防ぎます。一部の古いデバイスには必要です

可能な値

このオプションはフラグです

デフォルト値

無効化されている場合です。

reverse_scan
定義

SCSIバスを逆順でスキャンします（ターゲット15から開始）

可能な値

このオプションはフラグです

デフォルト値

無効化されている場合です。

global_tag_depth
定義

すべてのバス上のすべてのターゲットのグローバルタグ深度。このオプションはデフォルトのタグ深度を設定し、tag_infoオプションにより選択的に上書きできます。

可能な値

1 - 253

デフォルト値

32

tag_info:{{value[,value…]}[,{value[,value…]}…]}
定義

コントローラーごとにターゲットごとのタグキュー深度を設定します。コントローラーおよびターゲットを省略すると、デフォルトのタグ深度を維持します。

可能な値

1 - 253

デフォルト値

32

例:

tag_info:{{16,32,32,64,8,8,,32,32,32,32,32,32,32,32,32}

コントローラー0

  • ターゲット0にタグ深度16を指定

  • ターゲット3にタグ深度64を指定

  • ターゲット4および5にタグ深度8を指定

  • ターゲット6はデフォルトのまま

  • ターゲット1、2、7-15にタグ深度32を指定

他のターゲットはデフォルトの深度を維持します。

tag_info:{{},{32,,32}}

コントローラー1

  • ターゲット0および2にタグ深度32を指定

他のターゲットはデフォルトの深度を維持します。

rd_strm: {rd_strm_bitmask[,rd_strm_bitmask…]}
定義

ターゲットごとに読み込みストリーミングを有効にします。rd_strm_bitmaskは16ビットの16進数値で、各ビットがターゲットを表します。ターゲットのビットを'1'に設定すると、そのターゲットで読み込みストリーミングが有効になります。コントローラーを省略すると、デフォルトの読み込みストリーミング設定を維持します。

例:

rd_strm:{0x0041}

コントローラー0

  • ターゲット0および6で読み込みストリーミングを有効にします。

  • ターゲット1-5、7-15で読み込みストリーミングを無効にします。

他のターゲットはデフォルトの読み込みストリーミング設定を維持します。

rd_strm:{0x0023,,0xFFFF}

コントローラー0

  • ターゲット1、2、5で読み込みストリーミングを有効にします。

  • ターゲット3、4、6-15で読み込みストリーミングを無効にします。

コントローラー2

  • すべてのターゲットで読み込みストリーミングを有効にします。

他のターゲットはデフォルトの読み込みストリーミング設定を維持します。

可能な値

0x0000 - 0xffff

デフォルト値

0x0000

dv: {value[,value…]}
定義
コントローラーごとにドメイン検証ポリシーを設定します。

コントローラーを省略すると、デフォルトの読み込みストリーミング設定を維持します。

可能な値

< 0

シリアルEEPROMからの設定を使用

0

DVを無効化

> 0

DVを有効化
デフォルト値

DVシリアルEEPROMの設定

例:

dv:{-1,0,,1,1,0}

  • コントローラー0ではDVをデフォルトの設定にします

  • コントローラー1ではDVを無効にします

  • コントローラー2では設定をスキップします

  • コントローラー3および4ではDVを有効にします

  • コントローラー5ではDVを無効にします

seltime:[value]
定義

選択タイムアウト値を指定します

可能な値

0 = 256ms, 1 = 128ms, 2 = 64ms, 3 = 32ms

デフォルト値

0

precomp: {value[,value…]}
定義

各コントローラーごとにIOセルのプリコンパレンス値を設定します。コントローラーを省略すると、デフォルトのプリコンパレンス設定を維持します

可能な値

0 - 7

デフォルト値

チップのリビジョンにより異なります

例:

precomp:{0x1}

コントローラー0ではプリコンパレンス値を1に設定します

precomp:{1,,7}

  • コントローラー0ではプリコンパレンス値を1に設定します

  • コントローラー2ではプリコンパレンス値を8に設定します

slewrate: {value[,value…]}
定義

各コントローラーごとにIOセルのスルーレートを設定します。コントローラーを省略すると、デフォルトのスルーレート設定を維持します

可能な値

0 - 15

デフォルト値

チップのリビジョンにより異なります

例:

slewrate:{0x1}

  • コントローラー0ではスルーレートを1に設定します

slewrate :{1,,8}

  • コントローラー0ではスルーレートを1に設定します

  • コントローラー2ではスルーレートを8に設定します

amplitude: {value[,value…]}
定義

各コントローラーごとにIOセルの信号振幅を設定します。コントローラーを省略すると、デフォルトのリードストリーミング設定を維持します

可能な値

1 - 7

デフォルト値

チップのリビジョンにより異なります

例:

amplitude:{0x1}

コントローラー0では振幅を1に設定します

amplitude :{1,,7}

  • コントローラー0では振幅を1に設定します

  • コントローラー2では振幅を7に設定します

例:

options aic79xx aic79xx=verbose,rd_strm:{{0x0041}}

ドライバーの詳細出力を有効にし、コントローラー0のターゲット0および6のリードストリーミングをオンにします

4. 追加の注意事項¶

4.1. 知られている/未解決または注意事項の問題¶

  • SuSE Linux Enterprise 7では、LinuxカーネルのPCI割込みルーティングの問題によりドライバーが正しく動作しない可能性があります。SuSEに更新されたLinuxカーネルをご確認ください

4.2. 他社との互換性に関する問題¶

  • Adaptecは最新ファームウェアを搭載したUltra320ハードディスクのみをサポートしています。ハードディスクメーカーにご確認いただき、最新バージョンをご利用ください

4.3. オペレーティングシステムまたは技術の制限¶

  • PCIホットプラグは未検証であり、オペレーティングシステムが応答しなくなる可能性があります

  • 連続した0から始まらないLUNはシステム起動時に自動的にスキャンされない可能性があります。これはOSの制限です。Linuxベンダーに連絡し、非連続LUNの手動スキャン方法を確認してください

  • RedHatでのOSインストール中にドライバーアップデートディスク版のパッケージを使用すると、システムモジュールディレクトリにこのドライバーの2つのバージョンがインストールされる可能性があります。これにより/sbin/mkinitrdプログラムや他のRPMパッケージがシステムモジュールをインストールする際に問題が発生する可能性があります。システムが起動した後は、最新のRPMパッケージ版のドライバーをインストールすることをお勧めします。詳しくは http://www.adaptec.com.
