はじめに¶

BusLogic, Inc. は、MultiMaster ASIC 技術により、さまざまなバスアーキテクチャで共通のプログラミングインターフェースを提供する高性能 SCSI ホストアダプターを多数設計・製造しました。BusLogic は1996年2月に Mylex Corporation に買収されましたが、このドライバーがサポートする製品は BusLogic 名義で開発されたため、ソースコードおよびドキュメンテーションにはその名前が残されています。

このドライバーは現在の BusLogic MultiMaster ホストアダプター全機種をサポートし、今後の MultiMaster デザインにもほとんどまたは全く変更を加えないでサポートする予定です。最近では、BusLogic はコストが低く、ホストCPUに依存する FlashPoint ホストアダプターを導入しました。オンボードプロセッサを搭載していないにもかかわらず、FlashPoint ホストアダプターは非常に高性能で、コマンドレイテンシーも非常に低く抑えられています。BusLogic は最近、FlashPoint ドライバ開発者キットを私に提供しました。これは FlashPoint SCCB マネージャーのドキュメンテーションと、再配布可能なソースコードを含むものです。SCCB マネージャーはホストCPU上で動作し、MultiMaster ホストアダプターのファームウェアに相当する機能を実行するコードライブラリです。SCCB マネージャーを提供してくれたことにより、このドライバーは FlashPoint ホストアダプターにもサポートを追加しました。

Linux 用のこの完全に新しい BusLogic ドライバーを書く主な目的は、BusLogic SCSI ホストアダプターおよび現代の SCSI 外設機器が可能にする最大限のパフォーマンスを達成すること、そして高パフォーマンスなミッションクリティカルなアプリケーションに信頼性の高いドライバーを提供することです。すべての主要なパフォーマンス機能は Linux カーネルコマンドラインまたはモジュール初期化時に設定可能であり、個々のインストールがドライバーのパフォーマンスやエラー回復を特定のニーズに合わせて調整できるようにしています。

BusLogic SCSI ホストアダプターに関する Linux のサポート情報、このドライバーの最新リリースおよび BT-948/958/958D の最新ファームウェアについては、常に私の Linux ホームページ URL 「” で確認できます。http://sourceforge.net/projects/dandelion/”.

ドライバーの特徴¶

設定情報の報告とテスト¶

システム起動時にドライバーはホストアダプタのハードウェア構成について詳細に報告します。これは、各ターゲットデバイスと交渉した同期転送パラメータを含みます。各ターゲットデバイスごとにAutoSCSIの同期交渉、ワイド交渉、切断/再接続設定の状態、タグキューイングの状態が報告されます。すべてのターゲットデバイスで同じ設定が有効な場合、1つの単語または表現で表され、個別に異なる場合は各ターゲットデバイスごとに文字で表示されます。以下の例はこの報告形式を明確にするために示します。

同期交渉: Ultra

すべてのターゲットデバイスで同期交渉が有効になり、ホストアダプタは20.0 メガトランスファー/秒の交渉を試みます。

同期交渉: Fast

すべてのターゲットデバイスで同期交渉が有効になり、ホストアダプタは10.0 メガトランスファー/秒の交渉を試みます。

同期交渉: Slow

すべてのターゲットデバイスで同期交渉が有効になり、ホストアダプタは5.0 メガトランスファー/秒の交渉を試みます。

同期交渉: Disabled

同期交渉が無効になり、すべてのターゲットデバイスは非同期動作に制限されます。

同期交渉: UFSNUUU#UUUUUUUU

ターゲットデバイス0および4〜15はUltra速度で同期交渉が有効、ターゲットデバイス1はFast速度で同期交渉が有効、ターゲットデバイス2はSlow速度で同期交渉が有効、ターゲットデバイス3には許可されません。ホストアダプタのSCSI IDは「#」で表されます。

ワイド交渉、切断/再接続、タグキューイングの状態は「Enabled（有効）」、「Disabled（無効）」、または「Y」と「N」の文字列で報告されます。

パフォーマンス機能¶

BusLogic SCSI Host AdaptersはSCSI-2タグ付きキューイングを直接実装しており、ドライバーにタグ付きキューイングのサポートが組み込まれています。これにより、タグ付きキューイングをサポートするターゲットデバイスと通信できます。タグ付きキューイングは、各ターゲットデバイスまたは論理ユニットに対して複数の待機中のコマンドを発行できるため、I/O性能を大幅に向上させます。さらに、BusLogicの厳密なラウンドロビンモードがホストアダプタの性能を最適化し、スキャッタ/ギャザーI/OはLinux I/Oサブシステムが有効に利用できるセグメント数をサポートします。タグ付きキューイングの使用に関する各ターゲットデバイスごとの制御およびタグ付きキューイングのキュー深度の個別選択は、カーネルコマンットラインまたはモジュール初期化時に提供されるドライバーのオプションを通じて利用可能です。デフォルトでは、ホストアダプタの総キュー深度と、検出されたターゲットデバイスの数、タイプ、速度、機能に基づいてキュー深度が自動的に決定されます。また、ホストアダプタのファームウェアバージョンがタグ付きキューイングを正しく実装していないことが判明した場合、またはタグ付きキュー深度が1に設定されている場合、タグ付きキューイングは自動的に無効になります。ターゲットデバイスごとに切断/再接続が無効になっている場合も、タグ付きキューイングは無効になります。

信頼性機能¶

ドライバは幅広いエラー回復手順を実装しています。SCSIサブシステムの上位部分がタイムアウトしたコマンドを再初期化するよう要求した場合、SCSIサブシステムの推奨に従って、ホストアダプタのハードリセットとSCSIバスリセットの選択か、個々のターゲットデバイスにバスデバイスリセットメッセージを送信するかを判断します。エラー回復戦略は、各ターゲットデバイスごとにドライバオプションを通じて選択可能で、コマンドを再初期化するターゲットデバイスにバスデバイスリセットを送信することや、誤動作しているデバイスを妨害することを避けるためエラー回復を完全に抑制することも含まれます。バスデバイスリセットエラー回復戦略が選択され、バスデバイスリセットを送信しても正しく動作しない場合、次に再初期化されるコマンドはホストアダプタのハードリセットとSCSIバスリセットを強制します。他のデバイスによって引き起こされホストアダプタによって検出されたSCSIバスリセットも、ホストアダプタにソフトリセットを発行し再初期化することで処理されます。最後に、タグ付きキューイングが有効で、10分間隔で複数のコマンド再初期化が発生する場合、または運用開始後の10分以内にコマンド再初期化が発生した場合、そのターゲットデバイスのタグ付きキューイングは無効になります。これらのエラー回復オプションは、個々の異常なデバイスがシステム全体をロックアップまたはクラッシュさせるのを防ぎ、不適切に動作しているコンポーネントを除去後にクリーンなシャットダウンと再起動を可能にするため、全体のシステムの信頼性を向上させます。

PCI構成サポート¶

PCIシステムで、PCI BIOSサポートが有効なカーネルで実行されている場合、このドライバはPCI構成領域を調査し、システムBIOSが割り当てたI/Oポートアドレスを使用します。これにより、ISA互換I/Oポートアドレスはドライバによって無効になります。PCIシステムでは、ISA互換I/Oポートを完全に無効にするためにAutoSCSIユーティリティを使用することも推奨されます。BT-948/958/95、958DではISA互換I/Oポートがデフォルトで無効になっています。

/procファイルシステムサポート¶

ホストアダプタの構成情報と更新されたデータ転送およびエラー回復統計情報のコピーは、/proc/scsi/BusLogic/<N>インターフェースを通じて取得可能です。

共有割込みサポート¶

共有割込みをサポートするシステムでは、任意の数のBusLogicホストアダプタが同じ割込み要求チャネルを共有できます。

FlashPoint インストールノート¶

RAIDPlus サポート¶

FlashPoint ホストアダプターにはRAIDPlusが搭載されており、Mylexのブート可能なソフトウェアRAIDです。RAIDPlusはLinuxではサポートされておらず、今後もサポートする予定はありません。Linux 2.0のMDドライバーは結合（LINEAR）とストライピング（RAID-0）をサポートし、ミラーリング（RAID-1）、固定パリティ（RAID-4）、分散パリティ（RAID-5）は別途サポートされています。Linuxの組み込みRAIDサポートは一般的に柔軟性が高く、RAIDPlusよりパフォーマンスも優れているため、BusLogicドライバーにRAIDPlusサポートを含める動機は薄いです。

UltraSCSI転送の有効化¶

FlashPoint ホストアダプターは工場出荷設定で出荷され、これは保守的な設定でUltraSCSI速度のネゴシエーションを許可しません。これにより、これらのホストアダプターがUltraSCSI操作に不十分なケーブルや終端、または既存のSCSIデバイスがUltraSCSI速度の同期転送ネゴシエーションに適切に応答しないシステムにインストールされた場合でも問題が少なくなります。AutoSCSIを使用して「最適性能」設定をロードすることでUltraSCSI速度のネゴシエーションをすべてのデバイスで可能にしたり、個別にUltraSCSI速度を有効化したりできます。『最適性能』設定をロード後はSCAMを手動で無効化することをお勧めします。

BT-948/958/958D インストールノート¶

BT-948/958/958D PCI Ultra SCSI ホストアダプターは、Linuxをインストールする際にいくつかの状況で注意が必要な機能を備えています。

PCI I/Oポート割当¶

工場出荷時の設定に設定された場合、BT-948/958/958Dは、マザーボードのPCI BIOSで設定されたPCI I/Oポートの割り当てのみを認識します。BT-948/958/958Dは、以前のBusLogic SCSIホストアダプターが対応していたISA互換I/Oポートには応答しません。このドライバーはPCI I/Oポートの割り当てをサポートするため、この設定が推奨されます。ただし、特定の理由（例：Linuxディストリビューションがこのドライバーをブートカーネルにまだ使用していない場合など）で古いBusLogicドライバーを使用する必要がある場合、BusLogicはLegacy ISA互換I/Oポートを有効にするためのAutoSCSI設定オプションを提供しています。

この後方互換性オプションを有効にするには、システム起動時にCtrl-BでAutoSCSIユーティリティを起動し、「アダプタ設定」→「表示/変更設定」を選択した後、「ISA互換ポート」の設定を「無効」から「プライマリ」または「代替」に変更します。このドライバーがインストールされた後は、「ISA互換ポート」オプションを再び「無効」に戻す必要があります。古いBT-946C/956C/956CDもこの設定オプションを備えていますが、工場出荷時のデフォルト設定は「プライマリ」です。

PCIスロットのスキャン順序¶

複数のBusLogic PCIホストアダプターを搭載したシステムでは、BT-948/958/958DではPCIスロットのスキャン順序がBT-946C/956C/956CDと逆になる場合があります。SCSIディスクからブートするためには、ホストアダプターのBIOSとカーネルがどのディスクがブートデバイスかを一致させる必要があります。これは、BIOSとカーネルがPCIホストアダプターを同じ順序で認識していることを要します。マザーボードのPCI BIOSはPCIホストアダプターを列挙する標準的な方法を提供しており、Linuxカーネルでもこの方法を使用しています。一部のPCI BIOS実装では、バス番号とデバイス番号の増加順でPCIスロットを列挙しますが、他には逆の順序で列挙します。

残念ながら、マイクロソフトはWindows 95がPCI BIOSの列挙結果に関係なく、PCIスロットをバス番号とデバイス番号の増加順で常に列挙するように決定し、そのスキームをホストアダプタのBIOSがサポートしないとWindows 95の認証を取得できないとしました。そのため、BT-948/958/958Dの工場出荷時のデフォルト設定は、バス番号とデバイス番号の増加順でホストアダプタを列挙します。この機能を無効にするには、システム起動時にCtrl-Bを押してAutoSCSIユーティリティを起動し、「アダプタ設定」→「表示/変更設定」を選択し、Ctrl-F10を押した後、「バスとデバイス番号でPCIスキャン順序を使用する」オプションをOFFに変更してください。

このドライバーは、ホストアダプタのBIOSが列挙する順序と同じ順序でホストアダプタを認識するように、PCIスキャン順序オプションの設定を確認します。

UltraSCSI転送の有効化¶

BT-948/958/958Dは、UltraSCSI速度のネゴシエーションを許可しない「工場デフォルト」設定で出荷されます。これにより、これらのホストアダプタをUltraSCSI動作に不十分なケーブルや終端、または既存のSCSIデバイスがUltraSCSI速度の同期転送ネゴシエーションに適切に応答しないシステムにインストールした場合でも、問題が少なくなります。AutoSCSIを使用して「最適性能」設定をロードすることで、すべてのデバイスとUltraSCSI速度のネゴシエーションが可能になります。また、個別にUltraSCSI速度を有効化することも可能です。ただし、「最適性能」設定をロード後はSCAMを手動で無効化することをお勧めします。

ドライバーオプション¶

BusLogicドライバーのオプションは、Linuxカーネルコマンドラインまたはロード可能なカーネルモジュールインストール機能を通じて指定できます。複数のホストアダプタのドライバー設定は、オプション文字列をセミコロンで区切るか、コマンドラインに複数の「BusLogic=」文字列を指定することで指定できます。単一のホストアダプタの個別オプション設定はコンマで区切ります。プローブおよびデバッグオプションはすべてのホストアダプタに適用され、残りのオプションは選択したホストアダプタにのみ適用されます。

BusLogicドライバーのプローブオプションは以下の通りです：

IO:<integer>

「IO:」オプションは、ISA I/O アドレスを指定して、非PCI MultiMaster ホストアダプターの検出を試行します。どちらの「IO:」も「NoProbeISA」オプションが指定されていない場合、標準の BusLogic MultiMaster ISA I/O アドレス（0x330、0x334、0x230、0x234、0x130、および 0x134）が検出されます。複数の「IO:」オプションを指定することで、検出する I/O アドレスを正確に指定できますが、検出順序は常に標準リストに従います。

NoProbe

「NoProbe」オプションはすべての検出を無効化するため、BusLogic ホストアダプターは検出されません。

NoProbeISA

「NoProbeISA」オプションは標準の BusLogic ISA I/O アドレスの検出を無効化するため、検出されるのは PCI MultiMaster および FlashPoint ホストアダプターのみです。

NoProbePCI

「NoProbePCI」オプションは PCI コンフィギュレーションスペースの検出を無効化するため、検出されるのは ISA MultiMaster ホストアダプターのみです。また、ISA 互換 I/O ポートが「Primary」または「Alternate」に設定されている PCI MultiMaster ホストアダプターも検出されます。

NoSortPCI

「NoSortPCI」オプションは、PCI BIOS が提供する順序に従って PCI MultiMaster ホストアダプターを列挙します。AutoSCSI 「Use Bus And Device # For PCI Scanning Seq.」オプションの設定を無視します。

MultiMasterFirst

「MultiMasterFirst」オプションは、FlashPoint ホストアダプターの検出を MultiMaster ホストアダプターの検出よりも先に行います。デフォルトでは、FlashPoint および PCI MultiMaster ホストアダプターが同時に存在する場合、このドライバーは FlashPoint ホストアダプターを先に検出します。ただし、BIOS のプライマリディスクが最初の PCI MultiMaster ホストアダプターによって制御されている場合、MultiMaster ホストアダプターが先に検出されます。

FlashPointFirst

「FlashPointFirst」オプションは、MultiMaster ホストアダプターの検出を FlashPoint ホストアダプターの検出よりも先に行います。

BusLogic ドライバーのタグ付きキューイングオプションは、各ターゲットデバイスのキュー深度とタグ付きキューイングの許可を明示的に指定できます（ターゲットデバイスがタグ付きキューイングをサポートしている場合）。キュー深度は、ホストアダプターまたはターゲットデバイスに同時に実行される SCSI コマンドの数を示します。注意として、タグ付きキューイングを明示的に有効にすると問題が発生する可能性があるため、タグ付きキューイングの有効/無効オプションは、タグ付きキューイングを正しく実装していないターゲットデバイスで無効にするためのものとして提供されています。以下のオプションが利用可能です：

QueueDepth:<integer>

「QueueDepth:」または「QD:」オプションは、ターゲットデバイスのキュー深度を設定します。これは、タグ付きキューをサポートするすべてのターゲットデバイスおよびタグ付きキューをサポートしないデバイスの最大キュー深度を指定します。キュー深度オプションが指定されていない場合、ホストアダプターの総キュー深度と検出されたターゲットデバイスの数、タイプ、速度、能力に基づいて自動的に決定されます。ISAバウンスバッファを必要とするホストアダプターでは、DMAバウンスバッファメモリの過剰な事前割当てを避けるため、キュー深度はデフォルトでBusLogic_TaggedQueueDepthBBまたはBusLogic_UntaggedQueueDepthBBに設定されます。タグ付きキューをサポートしないターゲットデバイスは、BusLogic_UntaggedQueueDepthまたはBusLogic_UntaggedQueueDepthBBにキュー深度が設定されますが、指定されたキュー深度が低い場合を除きます。キュー深度が1の場合は、タグ付きキューが自動的に無効化されます。

QueueDepth:[<整数>,<整数>…]

「QueueDepth:[…]」または「QD:[…]」オプションは、各ターゲットデバイスごとにキュー深度を個別に指定します。<整数>が省略されている場合、対応するターゲットデバイスのキュー深度は自動的に選択されます。

TaggedQueuing:Default

「TaggedQueuing:Default」または「TQ:Default」オプションは、バスロジックホストアダプターのファームウェアバージョンに基づき、キュー深度が複数のコマンドをキューにできるかどうかに基づいてタグ付きキューを許可します。

TaggedQueuing:Enable

「TaggedQueuing:Enable」または「TQ:Enable」オプションは、このホストアダプター上のすべてのターゲットデバイスでタグ付きキューを有効にし、ホストアダプターのファームウェアバージョンに基づく制限を上書きします。

TaggedQue,Disable

「TaggedQueuing:Disable」または「TQ:Disable」オプションは、このホストアダプター上のすべてのターゲットデバイスでタグ付きキューを無効にします。

TaggedQueuing:<Target-Spec>

「TaggedQueuing:<Target-Spec>」または「TQ:<Target-Spec>」オプションは、各ターゲットデバイスごとにタグ付きキューを個別に制御します。<Target-Spec>は「Y」「N」「X」の文字列です。「Y」はタグ付きキューを有効、「N」は無効、「X」はファームウェアバージョンに基づくデフォルトを採用します。最初の文字はターゲットデバイス0、次の文字はターゲットデバイス1を指し、この文字列がすべてのターゲットデバイスをカバーしない場合、未指定の文字はすべて「X」とみなされます。

バスロジックドライバーのその他のオプションは以下の通りです：

BusSettleTime:<秒>

「BusSettleTime:」または「BST:」オプションは、バス安定時間（秒単位）を指定します。バス安定時間は、ホストアダプターのハードリセット（SCSIバスリセットを開始）とSCSIコマンドの実行の間に待機する時間を示します。指定がない場合は、BusLogic_DefaultBusSettleTimeがデフォルト値として使用されます。

InhibitTargetInquiry

「InhibitTargetInquiry」オプションは、マルチマスターホストアダプターでInquire Target DevicesまたはInquire Installed Devicesコマンドの実行を抑制します。これは、論理ユニットが0より大きいものにアドレス指定されたときに正しく応答しない古いターゲットデバイスと対応する場合に必要となることがあります。

BusLogicドライバのデバッグオプションは以下の通りです：

TraceProbe

「TraceProbe」オプションは、ホストアダプターのプローブをトレースします。

TraceHardwareReset

「TraceHardwareReset」オプションは、ホストアダプターのハードウェアリセットをトレースします。

TraceConfiguration

「TraceConfiguration」オプションは、ホストアダプターの設定をトレースします。

TraceErrors

「TraceErrors」オプションは、ターゲットデバイスからエラーを返すSCSIコマンドのトレースを有効にします。SCSIコマンドが失敗した場合、CDBおよびセンスデータがそれぞれ表示されます。

Debug

「Debug」オプションはすべてのデバッグオプションを有効にします。

以下の例は、最初のホストアダプターでターゲットデバイス1および2のキュー深度を7および15に、2番目のホストアダプターですべてのターゲットデバイスのキュー深度を31に、2番目のホストアダプターのバス安定時間を30秒に設定する方法を示しています。

Linuxカーネルコマンドライン：

linux BusLogic=QueueDepth:[,7,15];QueueDepth:31,BusSettleTime:30

LILO Linuxブートローダー（/etc/lilo.confにあります）：

append = "BusLogic=QueueDepth:[,7,15];QueueDepth:31,BusSettleTime:30"

INSMODロード可能なカーネルモジュールインストールツール：

insmod BusLogic.o \
    'BusLogic="QueueDepth:[,7,15];QueueDepth:31,BusSettleTime:30"'

注意

ドライバオプションにコンマが含まれる場合の正しくした処理を行うには、Module Utilities 2.1.71以降が必要です。

ドライバのインストール¶

このディストリビューションはLinuxカーネルバージョン2.0.35用に作成されましたが、2.0.4またはそれ以降の2.0シリーズのカーネルでも互換性があります。

新しいBusLogic SCSIドライバをインストールするには、以下のコマンドを使用できます（/usr/srcをあなたのLinuxカーネルソースツリーが保存されている場所に置き換えてください）：

cd /usr/src
tar -xvzf BusLogic-2.0.15.tar.gz
mv README.* LICENSE.* BusLogic.[ch] FlashPoint.c linux/drivers/scsi
patch -p0 < BusLogic.patch (only for 2.0.33 and below)
cd linux
make config
make zImage

その後、「arch/x86/boot/zImage」を標準のカーネルとしてインストールし、必要に応じてliloを実行し、再起動してください。
