SCSIメディアチェンジャードライバ用 README ファイル¶

SCSIメディアチェンジャー機器のドライバーです。/proc/scsi/scsiに「Type: Medium Changer」としてリストされています。

これは本物のJukebox（音楽ライブラリ）用のドライバーです。 リアル Jukeboxです。これは ではありません 一般的な小型CD-ROMチェンジャーと互換性がありますが、1スロットあたり1LUNのSCSIチェンジャーもしくはIDEドライブはサポートしていません。

ユーザーランドツールは以下の通り:

http://linux.bytesex.org/misc/changer.html

General Information¶

まずチェンジャーデバイスの仕組みについて説明します。チェンジャーは2（場合によってはより多く）のSCSI IDを持ちます。1つはロボットを制御するチェンジャーデバイス用、もう1つは実際にデータを読み書きするデバイス用です。後者は何でも良いです（MOD、CD-ROM、テープなど）。チェンジャーデバイスにとっては「気にする必要がない」ため、 のみ メディアを移動させるだけです。それ以外は何もしません。

SCSIチェンジャーモデルは、IDE-CDチェンジャーなどと比較して複雑ですが、ほぼすべてのケースを処理できます。4種類のチェンジャーエレメントをサポートしています:

メディアトランスポート

メディアを移動させる（つまりトランスポートアーム）デバイス。また「ピッカー」とも呼ばれます。

storage

メディアを保持できるスロット

インポート/エクスポート

上記と同じですが、外部からアクセス可能で、操作者（つまりあなた！）がメディアを挿入・抜き取れる仕組みです。有時「メイロスロット」とも呼ばれます。

データトランスファー

データを読み書きするデバイス（CD-ROM / テープ / その他ドライブ）です。

これらはすべて1つに限定されません。巨大なJukeboxは123台のCD-ROMスロット、5台のCD-ROMリーダー（したがって6つのSCSI ID: チェンジャーと各CD-ROM）および2つのトランスポートアームを持つこともあり、問題ありません。

実装方法¶

私はこのドライバーをNetBSD風のioctlインターフェースを持つキャラクターデバイスドライバーとして実装しました。NetBSDのヘッダーファイルと他のLinux SCSIデバイスドライバーの1つを起点にしました。インターフェースはNetBSDのソースコードと互換性があるため、BSD風のチェンジャードライバーをサポートするソフトウェア（誰か知っている？）があれば、このドライバーでも動作するはずです。

時間とともにいくつかのioctlが追加され、NetBSDのioctl APIではカバーされていなかったボリュームタグサポートなども含まれています。

現在の状態¶

複数のトランスポートアームをサポートする機能はまだ実装されていません（これまで誰もリクエストしていません…）。

私はGrundig製の35スロットCD-ROM Jukeboxでこのドライバーをテスト・使用しています。テープオートローダー（Exabyte、HP、DEC）でも動作するとの報告があります。一部の人はこのドライバーをAMANDAで使用しており、小規模（11スロット）および大規模（4MO、88スロット）マグネト光磁気Jukeboxでも問題なく動作します。おそらく他の多くのチェンジャーにも対応しており、ほとんどの人（ただしすべてではありません）は動作する場合にのみメールを送ってきます。 ではありません work…

私はデバイスリストを持っていません、ブラックリストもホワイトリストもありません。そのため、特定のデバイスがサポートされているかどうかを尋ねても意味がありません。理論上、SCSI-2メディア変換コマンドセットをサポートするすべての変換機器は、このドライバーで即座に動作するはずです。動作しない場合は、ドライバーまたは変換機器のファームウェアにバグがある可能性です。

使用方法¶

これはキャラクターデバイスで、主装置番号が86です。そのため、「mknod /dev/sch0 c 86 0」と入力して、ドライバー用の特殊ファイルを作成してください。

ドライバーが変換機器を見つけた場合、デバイスに関するメッセージを出力します（何も表示されない場合は「dmesg」を試してください）。/proc/devicesに表示されるはずです。表示されない場合…一部の変換機器では、デバイス用にID ? / LUN 0、ロボットメカニズム用にID ? / LUN 1を使用しますが、Linuxは ではありません デフォルトではLUN 0以外のLUNを検索しません。なぜなら、壊れたデバイスが多数あるからです。そのため、以下を試してください：

  1. echo "scsi add-single-device 0 0 ID 1" > /proc/scsi/scsi（IDはデバイスのSCSI-IDに置き換えてください）

  2. コマンドラインで「max_scsi_luns=1」でカーネルを起動してください（lilo.conf に append="max_scsi_luns=1" を追加することでうまくいくはずです）

問題が起きた場合は？¶

ドライバを insmod する際、「insmod debug=1」を指定すると詳細な出力が行われ、syslog に大量の情報が表示されます。カーネルを CONFIG_SCSI_CONSTANTS=y でコンパイルすると、エラーメッセージの品質が大幅に向上します。これにより、カーネルがエラーコードを人間が読める文字列に変換して表示するからです。

これらのメッセージは dmesg コマンドで表示できます（またはログファイルを確認してください）。ドライバに関する問題でメールでお問い合わせする際は、これらのメッセージを必ず添付してください。

insmod オプション¶

debug=0/1

デバッグメッセージを有効にします（上記参照、デフォルト: 0）。

verbose=0/1

詳細出力を有効にします（デフォルト: 1）。

init=0/1

モジュールロード時にチェンジャーにINITIALIZE ELEMENT STATUSコマンドを送信します（デフォルト: 1）。

timeout_init=<秒数>

INITIALIZE ELEMENT STATUSコマンドのタイムアウト（デフォルト: 3600）。

timeout_move=<秒数>

すべての他のコマンドのタイムアウト（デフォルト: 120）。

dt_id=<id1>,<id2>,…／dt_lun=<lun1>,<lun2>,…

これらはデータ転送要素のSCSI IDおよびLUNを指定するためのものです。ジューケボックスがこの情報を提供するため、通常は必要ありません。ただし、一部のデバイスでは…

vendor_firsts=, vendor_counts=, vendor_labels=

これらのinsmodオプションは、ドライバーにベンダー固有の要素タイプがあることを通知するために使用できます。グランディグなどはこのようにします。一部のジューケボックスには、新しく焼いたCDをラベルを付けるためのプリンタがあり、これは要素0xc000（タイプ5）としてアドレスされます。このようなベンダー固有の要素をドライバーに通知するには、このオプションを使用してください：

$ insmod ch                     \
        vendor_firsts=0xc000    \
        vendor_counts=1         \
        vendor_labels=printer

すべての3つのinsmodオプションは、最大4つのコンマ区切りの値を受け取ります。これにより、要素タイプ5〜8を設定できます。正しい値を特定するには、対象のデバイスのSCSI仕様が必要ですが、SCSI-2標準には含まれていません。
