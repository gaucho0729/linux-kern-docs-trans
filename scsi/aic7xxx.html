2. バージョン履歴¶

  • 7.0（2005年8月4日）

    • ドライバーをSCSIトランスポートクラスインフラストラクチャを使用して更新

    • 以前にリリースされたドライバーバージョンからのセクウェンサーやコアの修正をサポートしています。

  • 6.2.36（2003年6月3日）

    • PCIパリティエラーチェックを無効にするコードの修正

    • 無視 Wide Residue メッセージの処理を修正・簡略化します。以前のコードでは、トランザクションデータ長が偶数だった場合に残差を報告できませんでした。

    • 2.5.X EISAフレームワークのサポートを追加

    • 2.5.X SCSIプロシージャルFSインターフェースの変更に対応

    • ドメイン検証コマンドラインオプションのパース修正

    • 8bit WDTRメッセージでアシンクロ通信をネゴシエーションする際、ターゲットが我々がアシンクロであることを認識するため、オフセット0のSDTRを送信。これはQuantum Atlas 10Kのファームウェア欠陥への対応策

    • ドライバのアタッチ時にPCIエラー状態をクリアし、他のドライバのプローブによって以前にコントローラーを主張する前に行われたストレートなライトによってメモリマップドI/Oが無効になるのを防ぎます。

  • 6.2.35（2003年5月14日）

    • GCC 3.3コンパイラの警告の修正

    • EISAツインチャネルコントローラーでの動作修正

    • 2.5.Xのscsi_report_device_reset()のサポートを追加

  • 6.2.34（2003年5月5日）

    • 6.2.29で導入されたロックの再現問題を修正しました。これにより、io_request_lockと私たちのper-softcロック間のロック順序の逆転が発生する可能性がありました。これはRH9、SuSE、kernel.org 2.4.Xカーネルでのみ発生しました。

  • 6.2.33（2003年4月30日）

    • ユーザーに10回のエラーが報告された後、動的にPCIパリティエラー報告を無効にします。これらのエラーは、他のデバイスが不良パリティでPCIトランザクションを実行した結果です。ユーザーに問題が通知された後、エラーの継続的な報告はパフォーマンスを低下させるため、無効にします。

  • 6.2.32（2003年3月28日）

    • SCSI mallocプールのフラグメンテーションとSCSIミドルレイヤーのデッドロックを回避するため、動的にサイズを調整したS/Gリストを導入

  • 6.2.28（2003年1月20日）

    • ドメイン検証の修正

    • PCIパリティエラー検出を無効にする機能を追加

    • メモリマップI/Oのプローブを強化

  • 6.2.20（2002年11月7日）

    • ドメイン検証を追加

3. コマンドラインオプション¶

警告

これらのドライバパラメータを誤って変更または追加するとシステムが動作しなくなる可能性があります。注意して使用してください。

/etc/modprobe.dディレクトリに.confファイルを作成し、以下の行を追加または編集してください options aic7xxx aic7xxx=[command[,command...]] オプションを指定する必要があります。形式は以下の通りです： command 以下のいずれかまたは複数を含みます

verbose

定義

ドライバの動作中に追加の情報メッセージを有効にします。

可能な値

このオプションはフラグです

デフォルト値

無効化されている場合です。

debug:[value]

定義

さまざまなデバッグ情報の出力を有効にする

可能な値

0x0000 = デバッグなし、0xffff = 完全なデバッグ

デフォルト値

0x0000

no_probe

probe_eisa_vl

定義

EISA/VLBコントローラーのプローブを行わない。これはトグル機能です。ドライバーがデフォルトでEISA/VLBコントローラーをプローブしないようにコンパイルされている場合、"no_probe"を指定するとこのプローブを有効にします。逆にドライバーがデフォルトでEISA/VLBコントローラーをプローブするようにコンパイルされている場合、"no_probe"を指定するとこのプローブを無効にします。

可能な値

このオプションはトグル機能です

デフォルト値

EISA/VLBプローブはデフォルトで無効になっています

pci_parity

定義

PCIパリティエラーの検出をトグルします。多くのVIAチップセット搭載マザーボードでは、PCIバス上でPCIパリティが正しく生成されません。ハードウェアはこれらの「誤検出」パリティエラーと実際のパリティエラーを区別できません。この問題の症状は、ドライバーが以下のメッセージを連続して出力することです：

"scsi0:     Data Parity Error Detected during address or write data phase"

ドライバーが出力するメッセージ

可能な値

このオプションはトグル機能です

デフォルト値

PCIパリティエラーの報告を無効にします

no_reset

定義

初期プローブフェーズ中にバスをリセットしない

可能な値

このオプションはフラグです

デフォルト値

無効化されている場合です。

extended

定義

コントローラーで拡張変換を強制

可能な値

このオプションはフラグです

デフォルト値

無効化されている場合です。

periodic_otag

定義

順序タグを定期的に送信してタグの枯渇を防ぎます。一部の古いデバイスには必要です

可能な値

このオプションはフラグです

デフォルト値

無効化されている場合です。

reverse_scan

定義

SCSIバスを逆順でスキャンします（ターゲット15から開始）

可能な値

このオプションはフラグです

デフォルト値

無効化されている場合です。

global_tag_depth:[value]

定義

すべてのバス上のすべてのターゲットのグローバルタグ深度。このオプションはデフォルトのタグ深度を設定し、tag_infoオプションにより選択的に上書きできます。

可能な値

1 - 253

デフォルト値

32

tag_info:{{value[,value…]}[,{value[,value…]}…]}

定義

コントローラーごとにターゲットごとのタグキュー深度を設定します。コントローラーおよびターゲットを省略すると、デフォルトのタグ深度を維持します。

可能な値

1 - 253

デフォルト値

32

例:

tag_info:{{16,32,32,64,8,8,,32,32,32,32,32,32,32,32,32}

コントローラー0:

  • ターゲット0にタグ深度16を指定

  • ターゲット3にタグ深度64を指定

  • ターゲット4および5にタグ深度8を指定

  • ターゲット6はデフォルトのまま

  • ターゲット1、2、7-15にタグ深度32を指定

  • 他のターゲットはデフォルトの深度を維持します。

tag_info:{{},{32,,32}}

コントローラー1:

  • ターゲット0および2にタグ深度32を指定

  • 他のターゲットはデフォルトの深度を維持します。

seltime:[value]

定義

選択タイムアウト値を指定します

可能な値

0 = 256ms, 1 = 128ms, 2 = 64ms, 3 = 32ms

デフォルト値

0

dv: {value[,value…]}

定義

各コントローラーごとにドメイン検証ポリシーを設定します。コントローラーを省略することで、デフォルトの読み取りストリーミング設定を維持する場合があります。

可能な値

< 0

シリアルEEPROMからの設定を使用

0

DVを無効化

> 0

DVを有効化
デフォルト値

SCSI Select オプションがDV用に存在するコントローラーではSCSI-Select設定を有効にします。それ以外の場合は、U160速度をサポートするコントローラーではオン、他のすべてのコントローラータイプではオフにします。

例:

dv:{-1,0,,1,1,0}

  • コントローラー0ではDVをデフォルトの設定にします

  • コントローラー1ではDVを無効にします

  • コントローラー2では設定をスキップします

  • コントローラー3および4ではDVを有効にします

  • コントローラー5ではDVを無効にします

例:

options aic7xxx aic7xxx=verbose,no_probe,tag_info:{{},{,,10}},seltime:1

詳細なログ記録を有効にし、EISA/VLBプロービングを無効化し、コントローラー1/ターゲット2のタグ深度を10タグに設定します。
