Uprobe-tracer: Uprobeベースのイベントトレース¶

著者

Srikar Dronamraju

概要¶

Uprobeベースのトレースイベントはkprobeベースのトレースイベントと類似しています。この機能を有効にするには、カーネルをCONFIG_UPROBE_EVENTS=yでビルドしてください。

kprobe-eventトレーサーと同様に、この機能はcurrent_tracerを介して有効化する必要はありません。代わりに、/sys/kernel/debug/tracing/uprobe_eventsを通じてプローブポイントを追加し、/sys/kernel/debug/tracing/events/uprobes/<EVENT>/enableを通じて有効化します。

kprobe-eventトレーサーとは異なり、uprobeイベントインターフェースではユーザーがオブジェクト内のプローブポイントのオフセットを計算する必要があります。

代わりに、/sys/kernel/debug/tracing/dynamic_eventsを使用することもできます。このインターフェースは他の動的イベントにも統一的なアクセスを提供します。

uprobe_tracerの概要¶

p[:[GRP/]EVENT] PATH:OFFSET [FETCHARGS] : Set a uprobe
r[:[GRP/]EVENT] PATH:OFFSET [FETCHARGS] : Set a return uprobe (uretprobe)
p[:[GRP/]EVENT] PATH:OFFSET%return [FETCHARGS] : Set a return uprobe (uretprobe)
-:[GRP/]EVENT                           : Clear uprobe or uretprobe event

GRP           : Group name. If omitted, "uprobes" is the default value.
EVENT         : Event name. If omitted, the event name is generated based
                on PATH+OFFSET.
PATH          : Path to an executable or a library.
OFFSET        : Offset where the probe is inserted.
OFFSET%return : Offset where the return probe is inserted.

FETCHARGS     : Arguments. Each probe can have up to 128 args.
 %REG         : Fetch register REG
 @ADDR        : Fetch memory at ADDR (ADDR should be in userspace)
 @+OFFSET     : Fetch memory at OFFSET (OFFSET from same file as PATH)
 $stackN      : Fetch Nth entry of stack (N >= 0)
 $stack       : Fetch stack address.
 $retval      : Fetch return value.(\*1)
 $comm        : Fetch current task comm.
 +|-[u]OFFS(FETCHARG) : Fetch memory at FETCHARG +|- OFFS address.(\*2)(\*3)
 \IMM         : Store an immediate value to the argument.
 NAME=FETCHARG     : Set NAME as the argument name of FETCHARG.
 FETCHARG:TYPE     : Set TYPE as the type of FETCHARG. Currently, basic types
                     (u8/u16/u32/u64/s8/s16/s32/s64), hexadecimal types
                     (x8/x16/x32/x64), "string" and bitfield are supported.

(\*1) only for return probe.
(\*2) this is useful for fetching a field of data structures.
(\*3) Unlike kprobe event, "u" prefix will just be ignored, becuse uprobe
      events can access only user-space memory.

タイプ¶

fetch-argsには複数のタイプがサポートされています。Uprobeトレーサーは指定されたタイプに基づいてメモリをアクセスします。「s」および「u」のプレフィックスはそれぞれ符号付きと符号なしのタイプを示し、「x」プレフィックスは符号なしを意味します。トレースされた引数は「s」および「u」の場合は十進法、「x」の場合は十六進法で表示されます。型キャストを行わない場合、アーキテクチャ（例：x86-32はx3, x86-64はx64）に応じて「x32」または「x64」が使用されます。文字列型は特別な型で、ユーザー空間から「null-terminated」の文字列を取得します。ビットフィールドは別の特別な型で、3つのパラメータ（ビット幅、ビットオフセット、コンテナサイズ（通常は32））を取るため、構文は以下の通りです：

b<bit-width>@<bit-offset>/<container-size>

commについては、デフォルトの型は「string」であり、他の型は無効です。

イベントプロファイリング¶

イベントごとのプローブヒット数を確認するには、/sys/kernel/debug/tracing/uprobe_profileを参照してください。1列目はファイル名、2列目はイベント名、3列目はプローブヒット数です。

使用例¶

  • 新しいuprobeイベントとしてプローブを追加するには、uprobe_eventsに新しい定義を以下のように書き込みます（/bin/bashという実行ファイルのオフセット0x4245c0にuprobeを設定します）：

    echo 'p /bin/bash:0x4245c0' > /sys/kernel/debug/tracing/uprobe_events

  • 新しいuretprobeイベントとしてプローブを追加するには、

    echo 'r /bin/bash:0x4245c0' > /sys/kernel/debug/tracing/uprobe_events

  • 登録済みイベントを解除するには、

    echo '-:p_bash_0x4245c0' >> /sys/kernel/debug/tracing/uprobe_events

  • 登録されているイベントを表示するには、

    cat /sys/kernel/debug/tracing/uprobe_events

  • すべてのイベントをクリアするには、

    echo > /sys/kernel/debug/tracing/uprobe_events

以下は、プローブされたテキストアドレスでインストラクションポインタと%axレジスタをダンプする方法を示しています。/bin/zsh内のzfree関数をプローブします：

# cd /sys/kernel/debug/tracing/
# cat /proc/`pgrep zsh`/maps | grep /bin/zsh | grep r-xp
00400000-0048a000 r-xp 00000000 08:03 130904 /bin/zsh
# objdump -T /bin/zsh | grep -w zfree
0000000000446420 g    DF .text  0000000000000012  Base        zfree

0x46420は、0x00400000にロードされたオブジェクト/bin/zsh内のzfreeのオフセットです。したがって、uprobeのコマンドは以下の通りです：

# echo 'p:zfree_entry /bin/zsh:0x46420 %ip %ax' > uprobe_events

uretprobeの場合も同様に、

# echo 'r:zfree_exit /bin/zsh:0x46420 %ip %ax' >> uprobe_events

注意

ユーザーはオブジェクト内のプローブポイントのオフセットを明示的に計算する必要があります。

登録されているイベントを確認するには、uprobe_eventsファイルを確認してください。

# cat uprobe_events
p:uprobes/zfree_entry /bin/zsh:0x00046420 arg1=%ip arg2=%ax
r:uprobes/zfree_exit /bin/zsh:0x00046420 arg1=%ip arg2=%ax

イベントの形式は、ファイルevents/uprobes/zfree_entry/formatを参照してください。

# cat events/uprobes/zfree_entry/format
name: zfree_entry
ID: 922
format:
     field:unsigned short common_type;         offset:0;  size:2; signed:0;
     field:unsigned char common_flags;         offset:2;  size:1; signed:0;
     field:unsigned char common_preempt_count; offset:3;  size:1; signed:0;
     field:int common_pid;                     offset:4;  size:4; signed:1;
     field:int common_padding;                 offset:8;  size:4; signed:1;

     field:unsigned long __probe_ip;           offset:12; size:4; signed:0;
     field:u32 arg1;                           offset:16; size:4; signed:0;
     field:u32 arg2;                           offset:20; size:4; signed:0;

print fmt: "(%lx) arg1=%lx arg2=%lx", REC->__probe_ip, REC->arg1, REC->arg2

定義直後では、各イベントはデフォルトで無効になっています。これらのイベントをトレースするには、以下のように有効にする必要があります:

# echo 1 > events/uprobes/enable

トレースを開始し、ある程度の時間を待ってからトレースを停止してください。

# echo 1 > tracing_on
# sleep 20
# echo 0 > tracing_on

また、以下のようにイベントを無効化することもできます:

# echo 0 > events/uprobes/enable

トレースされた情報を以下から確認できます。

# cat trace
# tracer: nop
#
#           TASK-PID    CPU#    TIMESTAMP  FUNCTION
#              | |       |          |         |
             zsh-24842 [006] 258544.995456: zfree_entry: (0x446420) arg1=446420 arg2=79
             zsh-24842 [007] 258545.000270: zfree_exit:  (0x446540 <- 0x446420) arg1=446540 arg2=0
             zsh-24842 [002] 258545.043929: zfree_entry: (0x446420) arg1=446420 arg2=79
             zsh-24842 [004] 258547.046129: zfree_exit:  (0x446540 <- 0x446420) arg1=446540 arg2=0

出力結果は、pid 24842 に対して ip 0x446420 で uprobe がトリガーされ、ax レジスタの内容が 79 であることを示しています。また、ip 0x446540 で uretprobe がトリガーされ、対応する関数エントリが 0x446420 にあることを示しています。
