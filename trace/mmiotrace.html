カーネル内メモリマップI/Oトレース¶

ホームページおよびオプションのユーザースペースツールへのリンク:

https://nouveau.freedesktop.org/wiki/MmioTrace

MMIOトレースは2003年にインテルがFault Injection Test Harnessのために開発されました。2006年12月から2007年1月にかけて、インテルのコードを基にJeff Muizelaarが Nouveauプロジェクトを想定してMMIOアクセスのトレースを行うツールを作成しました。それ以来多くの人が貢献しています。

Mmiotraceは最初にNouveauプロジェクトを実際のユーザーとして、任意のメモリマッピングI/Oデバイスの逆コンピューティングを目的として構築されました。サポートされるアーキテクチャはx86とx86_64のみです。

Out-of-tree mmiotraceは当初、mainlineへの導入とftraceフレームワークのために修正されました。Pekka Paalanen <pq@iki.fi>.

カーネルを以下のように構成してください：¶

Mmiotrace機能はCONFIG_MMIOTRACEオプションでコンパイルされます。トレースはデフォルトで無効なので、この設定をyesにしても問題ありません。SMPシステムはサポートされていますが、複数のCPUがオンラインになるとトレースが信頼性低下しイベントを欠く可能性があるため、実行時の起動時にすべてのCPUを1つ除いてオフラインにします。CPUを手動で再起動することは可能ですが、イベントの喪失が発生しているかどうか自動検出する機能はありません。

使用法のクイックリファレンス¶

$ mount -t debugfs debugfs /sys/kernel/debug
$ echo mmiotrace > /sys/kernel/debug/tracing/current_tracer
$ cat /sys/kernel/debug/tracing/trace_pipe > mydump.txt &
Start X or whatever.
$ echo "X is up" > /sys/kernel/debug/tracing/trace_marker
$ echo nop > /sys/kernel/debug/tracing/current_tracer
Check for lost events.

使い方¶

debugfsが/sys/kernel/debugにマウントされているか確認してください。マウントされていない場合（root権限が必要）:

$ mount -t debugfs debugfs /sys/kernel/debug

トレースするドライバがロードされていないか確認してください。

mmiotraceを有効化（root権限が必要）:

$ echo mmiotrace > /sys/kernel/debug/tracing/current_tracer

トレースを開始して保存:

$ cat /sys/kernel/debug/tracing/trace_pipe > mydump.txt &

「cat」プロセスはバックグラウンドで実行（スリープ状態）を維持してください。

トレースしたいドライバをロードし使用してください。mmiotraceは、mmiotraceが有効な間、ioremappedされている領域へのMMIOアクセスのみをキャッチします。

トレース中にトレースにコメント（マーカー）を追加できます。$ echo "X is up" > /sys/kernel/debug/tracing/trace_marker これにより、巨大なトレースの中でもどのアクションに対応する部分かを確認しやすくなります。行った動作について説明的なマーカーを追加することをお勧めします。

mmiotraceを停止（root権限が必要）:

$ echo nop > /sys/kernel/debug/tracing/current_tracer

「cat」プロセスが終了します。終了しない場合は「fg」コマンドを実行し、Ctrl+Cを押して終了させます。

バッファが満杯になることでイベントが失われていないか確認してください。以下いずれか:

$ grep -i lost mydump.txt

これは正確に失われたイベント数を教えてくれます。または:

$ dmesg

カーネルログを確認し、「mmiotrace has lost events」の警告を探してください。イベントが失われた場合、トレースは不完全です。バッファを拡大して再度試してください。バッファのサイズを確認するには:

$ cat /sys/kernel/debug/tracing/buffer_size_kb

現在のバッファサイズを教えてくれます。この数値を約2倍にし、再度書き戻します。例えば:

$ echo 128000 > /sys/kernel/debug/tracing/buffer_size_kb

その後、最初から再実行してください。

ドライバプロジェクト（例：Nouveau）のトレースを行っている場合、結果を送信する前に以下の手順を行ってください。

$ lspci -vvv > lspci.txt
$ dmesg > dmesg.txt
$ tar zcf pciid-nick-mmiotrace.tar.gz mydump.txt lspci.txt dmesg.txt

その後、.tar.gzファイルを送信してください。トレースは大幅に圧縮されます。'pciid'と'nick'は、調査対象のハードウェアのPCI IDまたはモデル名、およびあなたのニックネームに置き換えてください。

Mmiotraceの動作方法¶

ハードウェアIOメモリへのアクセスは、PCIバスからアドレスをマッピングする際にioremap_*()関数のいずれかを呼び出すことで取得されます。MMIOTRACEは__ioremap()関数にハックされ、マッピングが作成されるたびに呼び出されます。マッピングはトレースログに記録されるイベントです。注意：ISA範囲のマッピングは常に存在するためキャッチされません。

MMIOアクセスはページフォールトを通じて記録されます。__ioremap()が返る直前にマッピングされたページは非存在状態に設定されます。ページへのアクセスはフォールトを引き起こします。フォールトハンドラはMMIOTRACEを呼び出してフォールトを処理します。MMIOTRACEはページを存在状態に設定し、シングルステッピングを実現するTFフラグを設定してフォールトハンドラを終了します。フォールトした指令が実行されデバッグトラップが発生します。ここでMMIOTRACEは再びページを非存在状態に設定します。指令はデコードされて読み取り/書き込みの種類、データ幅、読み込まれた値や書き込まれた値が取得され、トレースログに保存されます。

ページフォールトハンドラでページを存在状態に設定する操作はSMPマシンではレースコンディションがあります。シングルステッピング中に他のCPUがそのページで自由に実行されると、イベントが無視される可能性があります。トレース中に他のCPUを再起動するのは推奨されません。

トレースログ形式¶

raw logはテキスト形式で、grepやawkなどのツールで簡単にフィルタリング可能です。1レコードはログの1行です。レコードはキーワードで始まり、キーワードに応じた引数が続きます。引数はスペースで区切られ、または行末まで続きます。バージョン20070824のフォーマットは以下の通りです：

説明キーワード: スペース区切り引数¶

read event R width, timestamp, map id, physical, value, PC, PID write event W width, timestamp, map id, physical, value, PC, PID ioremap event MAP timestamp, map id, physical, virtual, length, PC, PID iounmap event UNMAP timestamp, map id, PC, PID marker MARK timestamp, text version VERSION the string "20070824" info for reader LSPCI lspci -vからの1行 PCI address map PCIDEV /proc/bus/pci/devicesデータのスペース区切り unk. opcode UNKNOWN timestamp, map id, physical, data, PC, PID

タイムスタンプは小数点を含む秒単位です。PhysicalはPCIバスアドレス、virtualはカーネル仮想アドレスです。Widthはバイト単位のデータ幅、valueはデータ値です。Map idは操作で使用したマッピングを識別する任意のID番号です。PCはプログラムカウンタ、PIDはプロセスIDです。PCは記録されていない場合ゼロです。PIDはユーザー空間メモリからのMMIOアクセスのトレースはまだサポートされていないため常にゼロです。

例えば、以下のawkフィルタは、物理アドレス範囲[0xfb73ce40, 0xfb800000]をターゲットとしたすべての32ビット書き込みを通過させます

$ awk '/W 4 / { adr=strtonum($5); if (adr >= 0xfb73ce40 &&
adr < 0xfb800000) print; }'

開発者向けツール¶

ユーザー空間のツールには以下のユーティリティが含まれます:

  • 数値のアドレスと値をハードウェアレジスタ名に置き換える

  • MMIOログの再実行、つまり記録された書き込みを再実行する
