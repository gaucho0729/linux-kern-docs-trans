Kprobesベースのイベントトレース¶

著者

Masami Hiramatsu

概要¶

これらのイベントはトレースポイントベースのイベントと類似しています。トレースポイントではなく、kprobe（kprobeおよびkretprobe）に基づいています。したがって、kprobeがプローブ可能なすべての関数（__kprobes/nokprobe_inlineアノテーションを持つ関数やNOKPROBE_SYMBOLでマーキングされた関数を除く）をプローブ可能です。トレースポイントベースのイベントとは異なり、この機能は動的に追加・削除可能です。

この機能を有効にするには、CONFIG_KPROBE_EVENTS=y でカーネルをビルドしてください。

イベントトレーサーと同様に、current_tracerを通じてアクティブ化する必要はありません。代わりに、/sys/kernel/debug/tracing/kprobe_events を介してプローブポイントを追加し、/sys/kernel/debug/tracing/events/kprobes/<EVENT>/enable を介して有効化してください。

kprobe_events ではなく、/sys/kernel/debug/tracing/dynamic_events を使用することも可能です。このインターフェースは、他の動的イベントにも統合的なアクセスを提供します。

kprobe_eventsの概要¶

 p[:[GRP/]EVENT] [MOD:]SYM[+offs]|MEMADDR [FETCHARGS]  : Set a probe
 r[MAXACTIVE][:[GRP/]EVENT] [MOD:]SYM[+0] [FETCHARGS]  : Set a return probe
 p:[GRP/]EVENT] [MOD:]SYM[+0]%return [FETCHARGS]       : Set a return probe
 -:[GRP/]EVENT                                         : Clear a probe

GRP            : Group name. If omitted, use "kprobes" for it.
EVENT          : Event name. If omitted, the event name is generated
                 based on SYM+offs or MEMADDR.
MOD            : Module name which has given SYM.
SYM[+offs]     : Symbol+offset where the probe is inserted.
SYM%return     : Return address of the symbol
MEMADDR        : Address where the probe is inserted.
MAXACTIVE      : Maximum number of instances of the specified function that
                 can be probed simultaneously, or 0 for the default value
                 as defined in Documentation/trace/kprobes.rst section 1.3.1.

FETCHARGS      : Arguments. Each probe can have up to 128 args.
 %REG          : Fetch register REG
 @ADDR         : Fetch memory at ADDR (ADDR should be in kernel)
 @SYM[+|-offs] : Fetch memory at SYM +|- offs (SYM should be a data symbol)
 $stackN       : Fetch Nth entry of stack (N >= 0)
 $stack        : Fetch stack address.
 $argN         : Fetch the Nth function argument. (N >= 1) (\*1)
 $retval       : Fetch return value.(\*2)
 $comm         : Fetch current task comm.
 +|-[u]OFFS(FETCHARG) : Fetch memory at FETCHARG +|- OFFS address.(\*3)(\*4)
 \IMM          : Store an immediate value to the argument.
 NAME=FETCHARG : Set NAME as the argument name of FETCHARG.
 FETCHARG:TYPE : Set TYPE as the type of FETCHARG. Currently, basic types
                 (u8/u16/u32/u64/s8/s16/s32/s64), hexadecimal types
                 (x8/x16/x32/x64), "string", "ustring" and bitfield
                 are supported.

 (\*1) only for the probe on function entry (offs == 0).
 (\*2) only for return probe.
 (\*3) this is useful for fetching a field of data structures.
 (\*4) "u" means user-space dereference. See :ref:`user_mem_access`.

タイプ¶

fetch-args には複数のタイプがサポートされています。kprobeトレーサーは指定されたタイプに基づいてメモリを参照します。プレフィックス「s」および「u」はそれぞれ符号付きと符号なしを表し、「x」プレフィックスは符号なしを意味します。トレースされた引数は「s」および「u」の場合は十進数、「x」の場合は十六進数で表示されます。型キャストを行わない場合、アーキテクチャ（例：x86-32はx32、x86-64はx64）に応じて「x32」または「x64」が使用されます。これらの値タイプは配列として使用可能です。配列データを記録するには、ベースタイプに「[N]」（Nは64未満の固定数）を追加します。例：「x16[4]」は4要素のx16（2バイトの十六進数）の配列を表します。注意点として、配列はメモリタイプのfetchargsに適用可能ですが、レジスタやスタックエントリなどには適用できません（例：「$stack1:x8[8]」は誤りですが、「+8($stack):x8[8]」は正しいです）。文字列タイプは特別なタイプで、カーネル空間から「NULL終端」の文字列を取得します。これは、文字列コンテナがページアウトされている場合、失敗してNULLを保存します。「ustring」タイプはユーザー空間用の文字列の代替です。詳しくは ユーザー記憶域アクセス をご覧ください。文字列配列タイプは他のタイプとは少し異なります。他のベースタイプでは「<base-type>[1]」は「<base-type>」と等価です（例：+0(%di):x32[1] は +0(%di):x32 と等価）。しかし、文字列[1] は文字列と等価ではありません。文字列タイプ自体は「char配列」を表しますが、文字列配列タイプは「char *配列」を表します。したがって、+0(%di):string[1] は +0(+0(%di)):string と等価です。ビットフィールドは別の特別なタイプで、3つのパラメータ（ビット幅、ビットオフセット、コンテナサイズ（通常は32））を取ります。構文は：

b<bit-width>@<bit-offset>/<container-size>

シンボル型(‘symbol’)は、u32またはu64型（BITS_PER_LONGに応じて）の別名であり、「symbol+offset」の形式で指定されたポインタを示します。$commの場合、デフォルトの型は「string」であり、他の型は無効です。

ユーザー記憶域アクセス¶

kprobeイベントはユーザー空間のメモリアクセスをサポートしています。その目的で、ユーザー空間のデリファレンス構文または‘ustring’型を使用できます。

ユーザー空間のデリファレンス構文は、ユーザー空間のデータ構造のフィールドにアクセスするためのものです。これは「u」プレフィックスをデリファレンス構文に追加することで実現します。たとえば、+u4(%si)は、レジスタ%siに格納されたアドレスから4オフセット分のメモリを読み込み、そのメモリがユーザー空間にあると期待します。文字列にも同様に使用できます（例: +u0(%si):stringは、レジスタ%siに格納されたアドレスから文字列を読み込みます）。‘ustring’はこのタスクを短縮した方法です。つまり、+0(%si):ustringは+u0(%si):stringと同等です。

kprobe-eventはユーザーメモリアクセス構文を提供しますが、透明に使用しません。これは、ユーザー空間のメモリに対して通常のデリファレンスや文字列型を使用すると失敗する可能性があり、一部のアーキテクチャでは常に失敗する場合があるためです。ユーザーはターゲットデータがカーネル空間かユーザー空間かを慎重に確認する必要があります。

プローブごとのイベントフィルタリング¶

プローブごとのフィルタリング機能により、各プローブに異なるフィルタを設定でき、トレースバッファに表示される引数を指定できます。kprobe_eventsでイベント名を‘p:’または‘r:’の直後に指定すると、tracing/events/kprobes/<EVENT>ディレクトリ下にイベントが追加され、そのディレクトリには‘id’、‘enable’、‘format’、‘filter’、‘trigger’が表示されます。

有効:

プローブを有効/無効にするには、1または0を書き込むことができます。

format:

このプローブイベントのフォーマットを表示します。

filter:

このイベントのフィルタリングルールを書き込むことができます。

id:

このプローブイベントのIDを表示します。

trigger:

イベントが発生した際に実行されるトリガーコマンドをインストールできます（詳細は イベントトレース, 第6節を参照）。

イベントプロファイリング¶

プローブのヒット数とミスヒット数を/sys/kernel/debug/tracing/kprobe_profileで確認できます。1列目はイベント名、2列目はプローブヒット数、3列目はプローブミスヒット数です。

カーネルブートパラメータ¶

カーネル起動時に「kprobe_event=」パラメータを使用して新しいkprobeイベントを追加して有効化できます。このパラメータはセミコロンで区切られたkprobeイベントを受け取り、フォーマットはkprobe_eventsと似ています。違いはプローブ定義パラメータがコンマで区切られている点です。例えば、以下のようにdo_sys_openでmyprobeイベントを追加できます

p:myprobe do_sys_open dfd=%ax filename=%dx flags=%cx mode=+4($stack)

以下のように記述してください（スペースをカンマに置き換えてください）

p:myprobe,do_sys_open,dfd=%ax,filename=%dx,flags=%cx,mode=+4($stack)

使用例¶

新しいイベントとしてプローブを追加するには、以下のようにkprobe_eventsに新しい定義を記述してください:

echo 'p:myprobe do_sys_open dfd=%ax filename=%dx flags=%cx mode=+4($stack)' > /sys/kernel/debug/tracing/kprobe_events

do_sys_open()関数の先頭にkprobeを設定し、「myprobe」イベントとして1番目の引数から4番目の引数を記録します。注意：関数引数がどのレジスタ/スタックエントリに割り当てられるかはアーキテクチャ固有のABIに依存します。ABIが不明な場合は、perf-toolsのprobeサブコマンド（tools/perf/配下にあります）を使用してください。この例のように、ユーザーは各引数により親しみやすい名前を選択できます。

echo 'r:myretprobe do_sys_open $retval' >> /sys/kernel/debug/tracing/kprobe_events

do_sys_open()関数の戻り先にkretprobeを設定し、「myretprobe」イベントとして戻り値を記録します。これらのイベントのフォーマットは、/sys/kernel/debug/tracing/events/kprobes/<EVENT>/formatから確認できます。

cat /sys/kernel/debug/tracing/events/kprobes/myprobe/format
name: myprobe
ID: 780
format:
        field:unsigned short common_type;       offset:0;       size:2; signed:0;
        field:unsigned char common_flags;       offset:2;       size:1; signed:0;
        field:unsigned char common_preempt_count;       offset:3; size:1;signed:0;
        field:int common_pid;   offset:4;       size:4; signed:1;

        field:unsigned long __probe_ip; offset:12;      size:4; signed:0;
        field:int __probe_nargs;        offset:16;      size:4; signed:1;
        field:unsigned long dfd;        offset:20;      size:4; signed:0;
        field:unsigned long filename;   offset:24;      size:4; signed:0;
        field:unsigned long flags;      offset:28;      size:4; signed:0;
        field:unsigned long mode;       offset:32;      size:4; signed:0;


print fmt: "(%lx) dfd=%lx filename=%lx flags=%lx mode=%lx", REC->__probe_ip,
REC->dfd, REC->filename, REC->flags, REC->mode

イベントが指定した式に合わせて4つの引数を持つことが確認できます。

echo > /sys/kernel/debug/tracing/kprobe_events

すべてのプローブポイントをクリアします。

または、

echo -:myprobe >> kprobe_events

特定のプローブポイントをクリアします。

定義直後では、各イベントはデフォルトで無効になっています。トレースを行うには、これを有効にする必要があります。

echo 1 > /sys/kernel/debug/tracing/events/kprobes/myprobe/enable
echo 1 > /sys/kernel/debug/tracing/events/kprobes/myretprobe/enable

以下のようにコマンドを実行して、間隔を指定してトレースを開始してください。

# echo 1 > tracing_on
Open something...
# echo 0 > tracing_on

トレースされた情報を以下から確認できます。

cat /sys/kernel/debug/tracing/trace
# tracer: nop
#
#           TASK-PID    CPU#    TIMESTAMP  FUNCTION
#              | |       |          |         |
           <...>-1447  [001] 1038282.286875: myprobe: (do_sys_open+0x0/0xd6) dfd=3 filename=7fffd1ec4440 flags=8000 mode=0
           <...>-1447  [001] 1038282.286878: myretprobe: (sys_openat+0xc/0xe <- do_sys_open) $retval=fffffffffffffffe
           <...>-1447  [001] 1038282.286885: myprobe: (do_sys_open+0x0/0xd6) dfd=ffffff9c filename=40413c flags=8000 mode=1b6
           <...>-1447  [001] 1038282.286915: myretprobe: (sys_open+0x1b/0x1d <- do_sys_open) $retval=3
           <...>-1447  [001] 1038282.286969: myprobe: (do_sys_open+0x0/0xd6) dfd=ffffff9c filename=4041c6 flags=98800 mode=10
           <...>-1447  [001] 1038282.286976: myretprobe: (sys_open+0x1b/0x1d <- do_sys_open) $retval=3

各行は、カーネルがイベントをヒットしたタイミングを示し、<- SYMBOLはカーネルがSYMBOLから戻ったことを表します（例：「sys_open+0x1b/0x1d <- do_sys_open」は、カーネルがdo_sys_openからsys_open+0x1bに戻ったことを示します）。
