ETMv4 sysfs Linuxドライバプログラミングリファレンス¶

著者

Mike Leach <mike.leach@linaro.org>

日付

2019年10月11日

既存のETMv4ドライバドキュメンテーションの補足。

sysfsファイルとディレクトリ¶

ルート: /sys/bus/coresight/devices/etm<N>

以下の段落では、sysfsファイルとそれらが影響を与えるETMv4レジスタ間の関連性について説明します。レジスタ名は「TRC」プレフィックスが省略されている点にご注意ください。

ファイル

mode (読み書き可能)

トレースレジスタ

{CONFIGR + その他のレジスタ}

備考

ビット選択でトレース機能を指定します。下記の「mode」セクションを参照してください。このビットは、要求された機能を有効にするためにトレース設定および他のレジスタの同等なプログラミングを引き起こします。

構文と例

echo bitfield > mode

32ビットまでのビットフィールドでトレース機能を設定します。

例

$> echo 0x012 > mode

ファイル

reset (書き込み専用)

トレースレジスタ

すべて

備考

すべてのプログラミングをトレースなし/論理が未設定にリセットします。

構文

echo 1 > reset

ファイル

enable_source (書き込み専用)

トレースレジスタ

PRGCTLR、すべてのハードウェアレジスタ。

備考

  • > 0 : ドライバに保持されている現在の値を使用してハードウェアをプログラミングし、トレースを有効にします。

  • = 0 : トレースハードウェアを無効にします。

構文

echo 1 > enable_source

ファイル

cpu (読み取り専用)

トレースレジスタ

なし。

備考

このETMが接続されているCPU ID。

例

$> cat cpu

$> 0

ファイル

addr_idx (読み書き可能)

トレースレジスタ

なし。

備考

アドレス比較器および範囲機能をインデックスする仮想レジスタ。範囲内のペアの最初のインデックスを設定します。

構文

echo idx > addr_idx

idx < nr_addr_cmp x 2 の場合

ファイル

addr_range (読み書き可能)

トレースレジスタ

ACVR[idx, idx+1], VIIECTLR

備考

addr_idxで選択された範囲のアドレスペア。オプションパラメータに基づいて含む/含まない、または省略された場合は現在の'mode'設定を使用します。制御レジスタで比較器範囲を選択します。インデックスが奇数値の場合エラーです。

依存

mode, addr_idx

構文

echo addr1 addr2 [exclude] > addr_range

addr1とaddr2が範囲を定義し、addr1 < addr2の場合

オプションで除外値:-

  • 0で含む

  • 1で除外します。

例

$> echo 0x0000 0x2000 0 > addr_range

注意: 任意のアドレスコンパレータをプログラミングする際、ドライバーはコンパレータにRANGE、SINGLE、START、STOPなどのタイプをタグ付けします。このタグが設定されると、同じsysfsファイル/タイプを使用してのみ値を変更できます。

したがって：

% echo 0 > addr_idx           ; select address comparator 0
% echo 0x1000 0x5000 0 > addr_range ; set address range on comparators 0, 1.
% echo 0x2000 > addr_start    ; error as comparator 0 is a range comparator
% echo 2 > addr_idx           ; select address comparator 2
% echo 0x2000 > addr_start    ; this is OK as comparator 2 is unused.
% echo 0x3000 > addr_stop     ; error as comparator 2 set as start address.
% echo 2 > addr_idx           ; select address comparator 3
% echo 0x3000 > addr_stop     ; this is OK

すべてのコンパレータ（および他のハードウェア）のプログラミングを解除するには、リセットパラメータを使用します：

% echo 1 > reset

「mode」sysfsパラメータ。¶

これはETMの全体的なトレースモードを設定するビットフィールド選択パラメータです。以下の表は、ドライバーソースファイルからの定義を用いて、これらのビットが表す機能を説明しています。多くの機能はオプションであり、ハードウェアでの実装に依存します。

以下にビット割当を示します：-

bit (0)：

ETM_MODE_EXCLUDE

description：

アドレス範囲を設定する際のインクルード/エクスクラード機能のデフォルト値です。範囲を除外するには1を設定します。modeパラメータが設定されると、現在インデックスされているアドレス範囲にこの値が適用されます。

bit (4)：

ETM_MODE_BB

description：

ハードウェアでブランチブロードキャストがサポートされている場合、これを有効にするために設定します[IDR0]。

bit (5)：

ETMv4_MODE_CYCACC

description：

ハードウェアでサイクル精度のトレースがサポートされている場合、これを有効にするために設定します[IDR0]。

bit (6)：

ETMv4_MODE_CTXID

description：

ハードウェアでコンテキストIDのトレースがサポートされている場合、これを有効にするために設定します[IDR2]。

bit (7)：

ETM_MODE_VMID

description：

ハードウェアで仮想マシンIDのトレースがサポートされている場合、これを有効にするために設定します[IDR2]。

bit (11)：

ETMv4_MODE_TIMESTAMP

description：

ハードウェアでタイムスタンプ生成がサポートされている場合、これを有効にするために設定します[IDR0]。

bit (12)：

ETM_MODE_RETURNSTACK

description：

ハードウェアでトレースリターンスタックの使用がサポートされている場合、これを有効にするために設定します[IDR0]。

bit (13-14)：

ETM_MODE_QELEM(val)

description：

'val'はETMが実装する場合のQELEMサポートレベルを決定します[IDR0]

bit (19)：

ETM_MODE_ATB_TRIGGER

description：

イベント制御レジスタ[EVENTCTLR1]のATBTRIGGERビットを有効にするために設定します。ハードウェアでサポートされている場合[IDR5]。

bit (20)：

ETM_MODE_LPOVERRIDE

description：

イベント制御レジスタ [EVENTCTLR1] の LPOVERRIDE ビットを有効にする設定です。IDR5 でサポートされている場合に適用されます。

ビット (21):

ETM_MODE_ISTALL_EN

description：

ストール制御レジスタ [STALLCTLR] の ISTALL ビットを有効にする設定です。

ビット (23):

ETM_MODE_INSTPRIO

description：

ストール制御レジスタ [STALLCTLR] の INSTPRIORITY ビットを有効にする設定です。IDR0 でサポートされている場合に適用されます。

ビット (24):

ETM_MODE_NOOVERFLOW

description：

ストール制御レジスタ [STALLCTLR] の NOOVERFLOW ビットを有効にする設定です。IDR3 でサポートされている場合に適用されます。

ビット (25):

ETM_MODE_TRACE_RESET

description：

ビューインスト制御レジスタ [VICTLR] の TRCRESET ビットを有効にする設定です。IDR3 でサポートされている場合に適用されます。

ビット (26):

ETM_MODE_TRACE_ERR

description：

ビューインスト制御レジスタ [VICTLR] の TRCCTRL ビットを有効にする設定です。

ビット (27):

ETM_MODE_VIEWINST_STARTSTOP

description：

ビューインスト制御レジスタ [VICTLR] のビューインスト開始/停止ロジックの初期状態値を設定します。

ビット (30):

ETM_MODE_EXCL_KERN

description：

デフォルトのトレース設定をカーネルモードのトレースを除外するようにします（注記 a を参照）。

ビット (31):

ETM_MODE_EXCL_USER

description：

デフォルトのトレース設定をユーザースペースのトレースを除外するようにします（注記 a を参照）。

注記 a) 起動時に ETM はアドレス範囲比較器 0 を使用して完全なアドレス空間をトレースするように設定されます。'mode' ビット 30 / 31 はこの設定を変更し、NS 状態におけるユーザースペース（EL0）またはカーネルスペース（EL1）のアドレス範囲比較器における EL 除外ビットを設定します。（デフォルト設定ではすべてのセキュア EL および NS EL2 が除外されます）

リセットパラメータが使用された後および/またはカスタムプログラミングが実施された後、これらのビットを使用するとアドレス比較器 0 の EL ビットが同じように設定されます。

注記 b) ビット 2-3、8-10、15-16、18、22 はデータトレースのみで動作する機能を制御します。A プロファイルのデータトレースは ETMv4 でアーキテクチャ的に禁止されているため、ここでは省略されています。可能であれば、ホモジェニアスなシステム内でコントロール可能な R または M プロファイルインフラストラクチャをサポートするカーネルがある場合に使用できます。

ビット 17、28-29 は未使用です。
