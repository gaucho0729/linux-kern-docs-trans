CoreSight エンベデッドクロストリガー（CTI & CTM）。¶

著者

Mike Leach <mike.leach@linaro.org>

日付

2019年11月

ハードウェアの説明¶

CoreSight Cross Trigger Interface (CTI) は、デバイス間でトリガー信号を入出力し、クロストリガー行列（CTM）を介して他のデバイスに接続するハードウェアデバイスです。このCTIは、番号付きチャネルを介してデバイス間でイベントを伝播させるためのインターフェースです。

e.g.:

0000000  in_trigs  :::::::
0 C   0----------->:     :             +======>(other CTI channel IO)
0  P  0<-----------:     :             v
0   U 0  out_trigs :     : Channels  *****      :::::::
0000000            : CTI :<=========>*CTM*<====>: CTI :---+
#######  in_trigs  :     : (id 0-3)  *****      :::::::   v
# ETM #----------->:     :                         ^   #######
#     #<-----------:     :                         +---# ETR #
####### out_trigs  :::::::                             #######

CTIドライバは、CTIをチャネルにトリガーを接続するプログラミングを可能にします。入力トリガーがアクティブになると、接続されたチャネルもアクティブになります。そのチャネルに接続された出力トリガーも同時にアクティブになります。アクティブなチャネルはCTMを介して他のCTIに伝播され、接続された出力トリガーをアクティブ化します（CTIチャネルゲートでフィルタリングされない限り）。

システムソフトウェアを用いてCTIのレジスタを直接プログラミングすることで、チャネルをアクティブ化することも可能です。

CTIはシステムによってCPUおよび/またはトレースデータパス上の他のCoreSightデバイスと関連付けられます。これらのデバイスが有効になると、接続されたCTIも自動的に有効になります。デフォルトでは電源投入時にCTIはトリガー/チャネルの接続がありませんので、システムに影響を与えることはありません（明示的にプログラミングされるまで）。

CTIとデバイス間のハードウェアトリガー接続は実装に依存します。ただし、CPU/ETMの組み合わせがv8アーキテクチャである場合、接続はアーキテクチャ的に定義された標準レイアウトになります。

ハードウェアトリガー信号は、CoreSight以外のデバイス（例：UART）に接続されたり、チップ外にハードウェアIOラインとして伝播されたりすることも可能です。

すべてのCTIデバイスはCTMに関連付けられています。多くのシステムでは1つの有効なCTM（1つのCTMまたは複数のCTMが相互に接続されている）が存在しますが、CTI+CTMのネットワークがCTMで相互に接続されていないシステムも可能です。このようなシステムでは、特定のCTMを介して接続されたCTIデバイスを関連付けるためCTMインデックスが宣言されます。

sysfsファイルとディレクトリ¶

CTIデバイスは既存のCoreSightバス上に他のCoreSightデバイスとともに表示されます:

>$ ls /sys/bus/coresight/devices
 cti_cpu0  cti_cpu2  cti_sys0  etm0  etm2  funnel0  replicator0  tmc_etr0
 cti_cpu1  cti_cpu3  cti_sys1  etm1  etm3  funnel1  tmc_etf0     tpiu0

以下の cti_cpu<N> 名前が付けられたCTIはCPUと、そのコアで使用されるETMに関連付けられます。The cti_sys<N> CTIは一般的なシステムインフラストラクチャCTIであり、他のCoreSightデバイスや、トリガー信号を生成または使用できる他のシステムハードウェアに関連付けられます。

>$ ls /sys/bus/coresight/devices/etm0/cti_cpu0
channels  ctmid  enable  nr_trigger_cons mgmt  power powered  regs
connections subsystem triggers0 triggers1  uevent
主要なファイル項目は次の通りです:-

  • enable: CTIを有効/無効にします。現在の状態を確認するために読み込みます。この項目が有効（1）として表示されている場合でも、 powered 無電源（0）として表示されている場合、有効化はデバイスが電源投入されたときに有効化を要求していることを示します。

  • ctmid 関連するCTM - システムに複数のCTI+CTMクラスタがあり、それらが相互に接続されていない場合にのみ関連します。

  • nr_trigger_cons 合計接続数 - triggers<N>ディレクトリをトリガーします。

  • powered CTIが現在電源が入っているかを確認するための読み込み。

サブディレクトリ:-

  • triggers<N>個々の接続のトリガーの一覧を含みます。

  • channelsチャネルAPIを含みます - CTIの主なプログラミングインターフェース。

  • regsraw programmable CTIレジスタへのアクセスを提供します。

  • mgmt標準のCoreSight管理レジスタ。

  • connections接続されたデバイスへのリンク CoreSight デバイス。リンク数は0から nr_trigger_cons。実際の数は nr_links このディレクトリで指定されます。

triggers<N>ディレクトリ¶

個々のトリガー接続情報。これはCoreSightおよび非CoreSight接続のトリガー信号を記述します。

各triggersディレクトリには、接続のトリガーを記述するパラメータのセットがあります。

  • name 接続の名前

  • in_signals この接続で使用される入力トリガー信号インデックス。

  • in_types 入力信号の機能タイプ。

  • out_signals この接続の出力トリガー信号。

  • out_types 出力信号の機能タイプ。

e.g:

>$ ls ./cti_cpu0/triggers0/
in_signals  in_types  name  out_signals  out_types
>$ cat ./cti_cpu0/triggers0/name
cpu0
>$ cat ./cti_cpu0/triggers0/out_signals
0-2
>$ cat ./cti_cpu0/triggers0/out_types
pe_edbgreq pe_dbgrestart pe_ctiirq
>$ cat ./cti_cpu0/triggers0/in_signals
0-1
>$ cat ./cti_cpu0/triggers0/in_types
pe_dbgtrigger pe_pmuirq

接続が「in」または「out」トリガーにゼロ信号を持つ場合、そのパラメータは省略されます。

チャネルAPIディレクトリ¶

この機能は、'regs'サブディレクトリ要素を直接操作する必要なく、トリガーをチャネルに接続する簡単な方法を提供します。

このAPIを提供するファイルは複数あります:

>$ ls ./cti_sys0/channels/
chan_clear         chan_inuse      chan_xtrigs_out     trigin_attach
chan_free          chan_pulse      chan_xtrigs_reset   trigin_detach
chan_gate_disable  chan_set        chan_xtrigs_sel     trigout_attach
chan_gate_enable   chan_xtrigs_in  trig_filter_enable  trigout_detach
trigout_filtered

これらの要素へのアクセスは主に次の形式をとります:

echo <chan> [<trigger>] > /<device_path>/<operation>

オプションの<trigger>はtrigXX_attach | detach操作にのみ必要です。

e.g.:

>$ echo 0 1 > ./cti_sys0/channels/trigout_attach
>$ echo 0 > ./cti_sys0/channels/chan_set

trigout(1)をchannel(0)に接続し、channel(0)をアクティブ化してcti_sys0.trigout(1)にセット状態を生成します。

API操作

  • trigin_attach, trigout_attachチャネルをトリガー信号に接続します。

  • trigin_detach, trigout_detachチャネルをトリガー信号から切断します。

  • chan_setチャネルを設定します - 設定状態はCTMを介して他の接続されたデバイスに伝播されます。

  • chan_clearチャネルをクリアします。

  • chan_pulseCoreSightクロックサイクルごとにチャネルを設定します。

  • chan_gate_enable書き込み操作によりCTIゲートがチャネルを他のデバイスに伝播（有効化）します。この操作にはチャネル番号を指定します。CTIゲートは電源投入時にすべてのチャネルにデフォルトで有効です。読み込みによりゲートで現在有効なチャネルの一覧を表示します。

  • chan_gate_disableチャネル番号を書き込み、そのチャネルのゲートを無効にします。

  • chan_inuse現在、任意の信号に接続されているチャネルを表示します。

  • chan_free接続されていない信号を持つチャネルを表示します。

  • chan_xtrigs_selチャネル番号を書き込み、表示するチャネルを選択します。読み込みにより選択されたチャネル番号を表示します。

  • chan_xtrigs_in選択されたビューチャネルに接続されている入力トリガーを表示します。

  • chan_xtrigs_out選択したビュー・チャンネルに接続されている出力トリガーを表示するには、読み込む必要があります。

  • trig_filter_enableデフォルトでは有効になっています。潜在的に危険な出力信号を設定できるようにするには無効にします。

  • trigout_filteredフィルタリングが有効になっている場合、設定が制限されるトリガー出力信号です。 trig_filter_enable 誤ってコアを停止する信号を防ぐなどの用途があります。 EDBGREQ 信号がコアを停止する場合、制限されます。

  • chan_xtrigs_reset1を書き込むことで、すべてのチャンネル／トリガーのプログラミングをクリアします。デバイスハードウェアをデフォルト状態に戻します。

以下に示す例では、入力トリガーインデックス1をチャンネル2に接続し、出力トリガーインデックス6を同じチャンネルに接続します。その後、適切なsysfs属性を使用して、チャンネル／トリガーの接続状態を確認します。

設定により、入力トリガー1かチャンネル2のいずれかがアクティブになると、トリガー出力6もアクティブになります。次にCTIを有効化し、ソフトウェア・チャネル制御を使用してチャンネル2をアクティブにします。これにより、レジスタ上のアクティブなチャネルと、レジスタ上のアクティブな信号を確認します。 choutstatus レジスタ上のアクティブなチャネルと、レジスタ上のアクティブな信号を確認します。最後にチャネルをクリアすることで、この状態は解除されます。 trigoutstatus レジスタ上のアクティブなチャネルと、レジスタ上のアクティブな信号を確認します。最後にチャネルをクリアすることで、この状態は解除されます。

e.g.:

.../cti_sys0/channels# echo 2 1 > trigin_attach
.../cti_sys0/channels# echo 2 6 > trigout_attach
.../cti_sys0/channels# cat chan_free
0-1,3
.../cti_sys0/channels# cat chan_inuse
2
.../cti_sys0/channels# echo 2 > chan_xtrigs_sel
.../cti_sys0/channels# cat chan_xtrigs_trigin
1
.../cti_sys0/channels# cat chan_xtrigs_trigout
6
.../cti_sys0/# echo 1 > enable
.../cti_sys0/channels# echo 2 > chan_set
.../cti_sys0/channels# cat ../regs/choutstatus
0x4
.../cti_sys0/channels# cat ../regs/trigoutstatus
0x40
.../cti_sys0/channels# echo 2 > chan_clear
.../cti_sys0/channels# cat ../regs/trigoutstatus
0x0
.../cti_sys0/channels# cat ../regs/choutstatus
0x0
