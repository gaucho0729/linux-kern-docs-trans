ブートタイムトレース¶

著者

Masami Hiramatsu <mhiramat@kernel.org>

概要¶

ブートタイムトレースは、デバイス初期化を含むブートプロセスをトレースし、ftraceのフル機能（イベントごとのフィルタとアクション、ヒストグラム、kprobeイベント、合成イベント、トレースインスタンスなど）を提供します。カーネルコマンドラインだけではこれらの複雑な機能を制御できませんので、この機能はbootconfigファイルでトレース機能のプログラミングを記述します。

ブートコンフィグのオプション¶

ブートコンフィグファイルでのブートタイムトレースの利用可能なオプション一覧 1. すべてのオプションは「ftrace.」または「kernel.」のプレフィックスの下にあります。最初に「kernel.」で始まるオプションについては、カーネルパラメータを参照してください 2.

Ftrace グローバルオプション¶

Ftrace グローバルオプションはブートコンフィグで「kernel.」のプレフィックスを持ち、これらはカーネルのレガシー コマンドラインの一部として渡されます。

kernel.tp_printk

printk バッファにもトレースイベントデータを出力します。

kernel.dump_on_oops [= MODE]

オッズ（Oops）発生時にftraceをダンプします。MODE = 1または省略した場合、すべてのCPUでトレースバッファをダンプします。MODE = 2の場合、オッズを引き起こしたCPUのバッファをダンプします。

kernel.traceoff_on_warning

WARN_ON()が発生した場合、トレースを停止します。

kernel.fgraph_max_depth = MAX_DEPTH

fgraphトレーサーの最大深さをMAX_DEPTHに設定します。

kernel.fgraph_filters = FILTER[, FILTER2…]

fgraphトレースの関数フィルタを追加します。

kernel.fgraph_notraces = FILTER[, FILTER2…]

fgraphトレース外の関数フィルタを追加します。

Ftrace パーフィンスタンスオプション¶

これらはグローバルなftraceノードを含む各インスタンスで使用できます。

ftrace.[instance.INSTANCE.]options = OPT1[, OPT2[…]]

指定されたftraceオプションを有効にします。

ftrace.[instance.INSTANCE.]tracing_on = 0|1

ブートタイムトレース開始時にこのインスタンスのトレースを有効/無効にします。（「traceon」イベントトリガーアクションで有効化することもできます）

ftrace.[instance.INSTANCE.]trace_clock = CLOCK

指定されたCLOCKをftraceのtrace_clockに設定します。

ftrace.[instance.INSTANCE.]buffer_size = SIZE

ftraceバッファサイズをSIZEに設定します。「KB」または「MB」をSIZEに使用できます。

ftrace.[instance.INSTANCE.]alloc_snapshot

スナップショットバッファを割り当てます。

ftrace.[instance.INSTANCE.]cpumask = CPUMASK

CPUMASKをトレースCPUマスクとして設定します。

ftrace.[instance.INSTANCE.]events = EVENT[, EVENT2[…]]

ブート時に指定されたイベントを有効にします。EVENTにはワイルドカードを使用できます。

ftrace.[instance.INSTANCE.]tracer = TRACER

TRACERをブート時の現在のトレーサーに設定します。（例: function）

ftrace.[instance.INSTANCE.]ftrace.filters

トレース関数フィルタルールの配列を取得します。

ftrace.[instance.INSTANCE.]ftrace.notraces

これは、非トレース関数フィルタールールの配列を取る。

Ftrace イベントごとのオプション¶

これらのオプションは、イベントごとのオプションを設定します。

ftrace.[instance.INSTANCE.]event.GROUP.EVENT.enable

GROUP:EVENTのトレースを有効にします。

ftrace.[instance.INSTANCE.]event.GROUP.EVENT.filter = FILTER

GROUP:EVENTにFILTERルールを設定します。

ftrace.[instance.INSTANCE.]event.GROUP.EVENT.actions = ACTION[, ACTION2[…]]

GROUP:EVENTにACTIONを設定します。

ftrace.[instance.INSTANCE.]event.kprobes.EVENT.probes = PROBE[, PROBE2[…]]

PROBEに基づいて新しいkprobeイベントを定義します。1つのイベントに複数のプローブを定義できますが、それらは同じタイプの引数を持つ必要があります。このオプションは、グループ名が「kprobes」のイベントにのみ利用可能です。

ftrace.[instance.INSTANCE.]event.synthetic.EVENT.fields = FIELD[, FIELD2[…]]

FIELDに基づいて新しい合成イベントを定義します。各フィールドは「type varname」の形式でなければなりません。

kprobeおよび合成イベントの定義はインスタンスノード下で記述できますが、他のインスタンスからも参照可能です。イベント名の競合に注意してください。

いつ開始するか¶

すべてのブートタイムトレースオプションは、 ftrace core_initcallの終わりに有効になります。これにより、postcore_initcall以降のイベントをトレースできます。ほとんどのサブシステムおよびアーキテクチャ依存ドライバは、これ以降に初期化されます（arch_initcallまたはsubsys_initcall）。したがって、ブートタイムトレースでそれらをトレースできます。core_initcallよりも前にトレースしたい場合は、以下のオプションを使用できます。 kernel。一部のオプションはinitcall処理よりも早く有効になります（例えば、 kernel.ftrace=function および kernel.trace_event はinitcallよりも前に開始します。）

例¶

例えば、各イベントにフィルタとアクションを追加し、kprobeイベントを定義し、ヒストグラムを持つ合成イベントを定義するには、以下のようにブート設定を記述します：

ftrace.event {
      task.task_newtask {
              filter = "pid < 128"
              enable
      }
      kprobes.vfs_read {
              probes = "vfs_read $arg1 $arg2"
              filter = "common_pid < 200"
              enable
      }
      synthetic.initcall_latency {
              fields = "unsigned long func", "u64 lat"
              actions = "hist:keys=func.sym,lat:vals=lat:sort=lat"
      }
      initcall.initcall_start {
              actions = "hist:keys=func:ts0=common_timestamp.usecs"
      }
      initcall.initcall_finish {
              actions = "hist:keys=func:lat=common_timestamp.usecs-$ts0:onmatch(initcall.initcall_start).initcall_latency(func,$lat)"
      }
}

また、ブートタイムトレースは「instance」ノードをサポートしており、複数のトレーサーを同時に実行できます。例えば、1つは「user_」で始まる関数をトレースし、他の1つは「kernel_」で始まる関数をトレースする場合、以下のようにブート設定を記述できます：

ftrace.instance {
      foo {
              tracer = "function"
              ftrace.filters = "user_*"
      }
      bar {
              tracer = "function"
              ftrace.filters = "kernel_*"
      }
}

instanceノードはイベントノードも受け入れるため、各インスタンスがイベントトレースをカスタマイズできます。

トリガーアクションとkprobesを使用すると、関数が呼ばれるときに関数グラフをトレースできます。例えば、以下はpci_proc_init()内のすべての関数呼び出しをトレースします：

ftrace {
      tracing_on = 0
      tracer = function_graph
      event.kprobes {
              start_event {
                      probes = "pci_proc_init"
                      actions = "traceon"
              }
              end_event {
                      probes = "pci_proc_init%return"
                      actions = "traceoff"
              }
      }
}

このブートタイムトレースは、ブート設定を通じてftraceカーネルパラメータをサポートしています。例えば、以下のカーネルパラメータ：

trace_options=sym-addr trace_event=initcall:* tp_printk trace_buf_size=1M ftrace=function ftrace_filter="vfs*"

これは以下のようにブート設定に記述できます：

kernel {
      trace_options = sym-addr
      trace_event = "initcall:*"
      tp_printk
      trace_buf_size = 1M
      ftrace = function
      ftrace_filter = "vfs*"
}

パラメータは「kernel」プレフィックスを使用し、「ftrace」ではなくなります。
