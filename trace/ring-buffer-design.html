ヘッド

  • リングバッファ内に新しい読み取りが発生する場所

プロデューサー

  • リングバッファに書き込むタスク（ライターと同じ）

  • プロデューサーと同じ

consumer

  • リングバッファから読み取るタスク（リーダーと同じ）

リーダー

  • コンシューマーと同じ

リーダーページ

  • リングバッファ外でリーダー専用に使用されるページ（ほぼすべて）

ヘッドページ

  • リーダーが次に使用するページへのポインタ

テールページ

  • 次に書き込むページへのポインタ

コミットページ

  • 最後に完了した非ネスト型書き込みのページへのポインタ

cmpxchg

  • ハードウェア支援型アトミックトランザクションで以下の動作を行う

    A = B if previous A == C

R = cmpxchg(A, C, B) is saying that we replace A with B if and only
    if current A is equal to C, and we put the old (current)
    A into R

R gets the previous A regardless if A is updated with B or not.

    更新が成功したかを確認するには、 R == C 比較が使用される

ジェネリックリングバッファ¶

リングバッファは上書きモードまたはプロデューサー/コンシューマーモードのいずれかで使用可能

プロデューサー/コンシューマーモードでは、プロデューサーがコンシューマーが解放する前にバッファを満たすと、プロデューサーは書き込みを停止する。これにより最近のイベントが失われる

上書きモードでは、プロデューサーがコンシューマーが解放する前にバッファを満たすと、プロデューサーは古いデータを上書きする。これにより最も古いイベントが失われる

複数のライターが同じパーセルCPUバッファで同時に書き込みを行うことはできないが、ライターは他のライターを中断できる。ただし、前のライターが再開するまで書き込みを終了しなければならない。これはアルゴリズムにとって非常に重要である。ライターは「スタック」のように動作する。割り込みの仕組みがこの動作を強制する:

writer1 start
   <preempted> writer2 start
       <preempted> writer3 start
                   writer3 finishes
               writer2 finishes
writer1 finishes

これはライターが割り込みによって中断され、割り込みが同時に書き込みを行うような状況に非常に近い

リーダーはいつでも発生するが、同時に複数のリーダーが実行されることはない。また、リーダーが他のリーダーを中断・割り込みすることはできない。リーダーはライターを中断・割り込みできないが、ライターが書き込みしている間でもバッファから読み取り/消費を行うことができる。ただし、読み取りを行うには別のプロセッサが必要である。リーダーは自身のプロセッサで読み取りを行い、ライターによって中断される可能性がある

ライターはリーダーを中断できるが、リーダーはライターを中断できない。ただし、ライターが書き込みしている間でもリーダーは別のプロセッサでバッファを読み取ることができる

リングバッファはリンクリストで結びつけられたページのリストから構成される

初期化時にリーダー専用のページがリーダー用に割り当てられる。これはリングバッファの一部ではない

head_page、tail_page、commit_pageはすべて同じページを指すように初期化されます。

リーダー ページは次のポインタがhead_pageを指し、前のポインタがhead_pageの前のページを指すように初期化されます。

リーダーは独自のページを使用します。起動時にこのページは割り当てられますが、リストに接続されていません。リーダーがバッファから読み込む場合、そのページが空である（起動時のように）場合、リーダーのページとhead_pageを交換します。古いリーダー ページはリング バッファに組み込まれ、head_pageは削除されます。挿入されたページ（古いリーダー ページ）の次のページが新しいhead_pageになります。

新しいページがリーダーに渡された後、リーダーはそのページに対して何をしても構いません（ライターがそのページを解放した後であれば）。

リーダー ページが交換される様子の例：この例ではバッファ内のhead_pageは表示されていません。これは交換を示すためのものです。

+------+
|reader|          RING BUFFER
|page  |
+------+
                +---+   +---+   +---+
                |   |-->|   |-->|   |
                |   |<--|   |<--|   |
                +---+   +---+   +---+
                 ^ |             ^ |
                 | +-------------+ |
                 +-----------------+


+------+
|reader|          RING BUFFER
|page  |-------------------+
+------+                   v
  |             +---+   +---+   +---+
  |             |   |-->|   |-->|   |
  |             |   |<--|   |<--|   |<-+
  |             +---+   +---+   +---+  |
  |              ^ |             ^ |   |
  |              | +-------------+ |   |
  |              +-----------------+   |
  +------------------------------------+

+------+
|reader|          RING BUFFER
|page  |-------------------+
+------+ <---------------+ v
  |  ^          +---+   +---+   +---+
  |  |          |   |-->|   |-->|   |
  |  |          |   |   |   |<--|   |<-+
  |  |          +---+   +---+   +---+  |
  |  |             |             ^ |   |
  |  |             +-------------+ |   |
  |  +-----------------------------+   |
  +------------------------------------+

+------+
|buffer|          RING BUFFER
|page  |-------------------+
+------+ <---------------+ v
  |  ^          +---+   +---+   +---+
  |  |          |   |   |   |-->|   |
  |  |  New     |   |   |   |<--|   |<-+
  |  | Reader   +---+   +---+   +---+  |
  |  |  page ----^                 |   |
  |  |                             |   |
  |  +-----------------------------+   |

リング バッファ内のデータがバッファ ページに保持されているデータよりも少ない場合、交換されるページがcommit_pageやtail_pageである可能性があります。

          reader page    commit page   tail page
              |              |             |
              v              |             |
             +---+           |             |
             |   |<----------+             |
             |   |<------------------------+
             |   |------+
             +---+      |
                        |
                        v
    +---+    +---+    +---+    +---+
<---|   |--->|   |--->|   |--->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

このケースもこのアルゴリズムでは依然として有効です。ライターがページを解放するとき、リーダー ページがリング バッファの次の位置を指しているため、そのページはリング バッファに直接組み込まれます。

主なポインタ：

リーダー ページ

  • リーダー専用のページで、リング バッファの一部ではありません（交換可能）

head_page

  • リーダー ページと交換されるリング バッファの次のページ

tail_page

  • 次の書き込みが行われるページ

commit_page

  • 最後に書き込みが完了したページ

commit_pageはライター スタックの外側のライターのみが更新します。他のライターが優先的に実行される場合でも、commit_pageは移動しません。

リング バッファにデータを書き込むと、リング バッファ内で位置が確保され、その位置がライターに返されます。ライターがその位置にデータを書き終わると、書き込みをコミットします。

このトランザクション中に別の書き込み（または読み込み）がいつでも行われることがあります。別の書き込みが発生した場合、それは前の書き込みが完了するまで終了する必要があります。

書き込み予約：

 Buffer page
+---------+
|written  |
+---------+  <--- given back to writer (current commit)
|reserved |
+---------+ <--- tail pointer
| empty   |
+---------+

書き込みコミット：

 Buffer page
+---------+
|written  |
+---------+
|written  |
+---------+  <--- next position for write (current commit)
| empty   |
+---------+

最初の予約の後に書き込みが発生した場合：

     Buffer page
    +---------+
    |written  |
    +---------+  <-- current commit
    |reserved |
    +---------+  <--- given back to second writer
    |reserved |
    +---------+ <--- tail pointer

After second writer commits::


     Buffer page
    +---------+
    |written  |
    +---------+  <--(last full commit)
    |reserved |
    +---------+
    |pending  |
    |commit   |
    +---------+ <--- tail pointer

When the first writer commits::

     Buffer page
    +---------+
    |written  |
    +---------+
    |written  |
    +---------+
    |written  |
    +---------+  <--(last full commit and tail pointer)

コミット ポインタは、他の書き込みを優先せずにコミットされた最後の書き込み位置を指します。他の書き込みを優先してコミットされた書き込みは、保留中のコミットとなり、すべての書き込みがコミットされるまで完全なコミットとはなりません。

コミットページは最後の完全なコミットを持つページを指します。テールページはコミット前の最後の書き込みを持つページを指します。

テールページは常にコミットページと同じかそれ以降の位置にあり、複数のページ先に位置する場合もあります。テールページがコミットページに追いつくと、以降の書き込みは行われません（リングバッファのモードに関係なく、オーバーライドモードとプロデューサー/コンシューマーモードのいずれも含む）。

ページの順序は以下の通りです：

head page
commit page
tail page

可能性のあるシナリオ：

                             tail page
  head page         commit page  |
      |                 |        |
      v                 v        v
    +---+    +---+    +---+    +---+
<---|   |--->|   |--->|   |--->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

特殊なケースとして、ヘッドページがコミットページおよびテールページのいずれかの後にある場合があります。これはコミット（およびテール）ページがリーダーページと交換された状態です。これはヘッドページが常にリングバッファの一部であるのに対し、リーダーページはそうではないためです。リングバッファ内で完全なページ未満がコミットされ、リーダーがページを交換する場合、コミットページが交換される可能性があります。

          reader page    commit page   tail page
              |              |             |
              v              |             |
             +---+           |             |
             |   |<----------+             |
             |   |<------------------------+
             |   |------+
             +---+      |
                        |
                        v
    +---+    +---+    +---+    +---+
<---|   |--->|   |--->|   |--->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+
                        ^
                        |
                    head page

この場合、テールとコミットがリングバッファに戻る際でもヘッドページは移動しません。

コミットページがまだそのページに存在している場合、リーダーはリングバッファにページを交換できません。読み込みが最後のコミット（実際のコミットで、保留中または予約されていないもの）に達した場合、読み込むべきデータはもうありません。バッファは次の完全なコミットが完了するまで空とみなされます。

テールページがヘッドページに達した場合、オーバーライドモードではヘッドページが1つ進み、プロデューサー/コンシューマーモードでは書き込みが失敗します。

オーバーライドモード：

            tail page
               |
               v
    +---+    +---+    +---+    +---+
<---|   |--->|   |--->|   |--->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+
                        ^
                        |
                    head page


            tail page
               |
               v
    +---+    +---+    +---+    +---+
<---|   |--->|   |--->|   |--->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+
                                 ^
                                 |
                             head page


                    tail page
                        |
                        v
    +---+    +---+    +---+    +---+
<---|   |--->|   |--->|   |--->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+
                                 ^
                                 |
                             head page

注意：リーダーページは依然として前のヘッドページを指しますが、交換が発生した際には最新のヘッドページを使用します。

リングバッファをロックレスにする:¶

ロックレスアルゴリズムの主な考え方は、ヘッドページポインタの移動とリーダーとのページ交換を組み合わせることです。状態フラグはページポインタ内に配置され、これを行うには各ページがメモリで4バイトアライメントされる必要があります。これにより、アドレスの2つの下位ビットをフラグとして使用できるようになり、アドレスの下位ビットは常にゼロになります。アドレスを取得するには、フラグをマスクするだけでよいです：

MASK = ~3

address & MASK

この2つのビットで保持されるフラグは以下の通りです：

HEADER

  • ポインタで示すページがヘッドページであることを示します。

UPDATE

  • ポインタで示すページがライターによって更新されており、以前または現在ヘッドページであったか、または今後ヘッドページになる可能性があることを示します。

          reader page
              |
              v
            +---+
            |   |------+
            +---+      |
                        |
                        v
    +---+    +---+    +---+    +---+
<---|   |--->|   |-H->|   |--->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

上記のポインタ「-H->」はHEADERフラグが設定されています。つまり、次のページがリーダーによってスワップされる次のページです。このポインタは次のページがヘッドページであることを示します。

テールページがヘッドポインタに達した場合、cmpxchgを使用してポインタをUPDATE状態に変更します：

            tail page
               |
               v
    +---+    +---+    +---+    +---+
<---|   |--->|   |-H->|   |--->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

            tail page
               |
               v
    +---+    +---+    +---+    +---+
<---|   |--->|   |-U->|   |--->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

「-U->」はUPDATE状態のポインタを表します。

リーダーへのアクセスには、リーダーを同期化するためのロックを取得する必要がありますが、ライターはリングバッファへの書き込みにロックを取得しません。これは、我々が単一のリーダーのみに注意を払えばよいこと、および書き込みは「スタック」形式で優先的に実行されることを意味します。

リーダーがリングバッファとページを交換しようとする際にはcmpxchgを使用します。ヘッドページのポインタのフラグビットにHEADERフラグが設定されていない場合、比較が失敗し、リーダーは新しいヘッドページを検索して再試行する必要があります。注意：UPDATEとHEADERフラグは同時に設定されることはありません。

リーダーは以下の手順でリーダーページを交換します：

+------+
|reader|          RING BUFFER
|page  |
+------+
                +---+    +---+    +---+
                |   |--->|   |--->|   |
                |   |<---|   |<---|   |
                +---+    +---+    +---+
                 ^ |               ^ |
                 | +---------------+ |
                 +-----H-------------+

リーダーはヘッドページの次のページにHEADERフラグを設定してリーダーページの次のポインタを設定します：

+------+
|reader|          RING BUFFER
|page  |-------H-----------+
+------+                   v
  |             +---+    +---+    +---+
  |             |   |--->|   |--->|   |
  |             |   |<---|   |<---|   |<-+
  |             +---+    +---+    +---+  |
  |              ^ |               ^ |   |
  |              | +---------------+ |   |
  |              +-----H-------------+   |
  +--------------------------------------+

以前のヘッドページのポインタをリーダーページのポインタに変更するcmpxchgを行います。新しいポインタにはHEADERフラグが設定されていません。この操作はヘッドページを原子的に進めるようにします：

+------+
|reader|          RING BUFFER
|page  |-------H-----------+
+------+                   v
  |  ^          +---+   +---+   +---+
  |  |          |   |-->|   |-->|   |
  |  |          |   |<--|   |<--|   |<-+
  |  |          +---+   +---+   +---+  |
  |  |             |             ^ |   |
  |  |             +-------------+ |   |
  |  +-----------------------------+   |
  +------------------------------------+

新しいヘッドページが設定された後、ヘッドページの前のポインタをリーダーページに更新します：

+------+
|reader|          RING BUFFER
|page  |-------H-----------+
+------+ <---------------+ v
  |  ^          +---+   +---+   +---+
  |  |          |   |-->|   |-->|   |
  |  |          |   |   |   |<--|   |<-+
  |  |          +---+   +---+   +---+  |
  |  |             |             ^ |   |
  |  |             +-------------+ |   |
  |  +-----------------------------+   |
  +------------------------------------+

+------+
|buffer|          RING BUFFER
|page  |-------H-----------+  <--- New head page
+------+ <---------------+ v
  |  ^          +---+   +---+   +---+
  |  |          |   |   |   |-->|   |
  |  |  New     |   |   |   |<--|   |<-+
  |  | Reader   +---+   +---+   +---+  |
  |  |  page ----^                 |   |
  |  |                             |   |
  |  +-----------------------------+   |
  +------------------------------------+

重要な点：リーダーページが前のポインタで指すページ（新しいヘッドページを指すもの）は、リーダーページ自身を指さないため、リングバッファには含まれません。次のポインタを介してリングバッファをトラバースする場合、常にリングバッファ内に留まりますが、前のポインタを介してトラバースする場合、そうとは限りません。

ページの前のポインタを調べることでリーダーページを特定できます。前のページの次のポインタが元のページを指していない場合、元のページはリーダーページです：

 +--------+
 | reader |  next   +----+
 |  page  |-------->|    |<====== (buffer page)
 +--------+         +----+
     |                | ^
     |                v | next
prev |              +----+
     +------------->|    |
                    +----+

ヘッドページが進む方法：

テールページがヘッドページに到達し、バッファがオーバーライドモードで動作しており、さらに書き込みが行われる場合、ライターがテールページを進める前にヘッドページを進める必要があります。ライターはcmpxchgを実行して、ヘッドページのポインタをHEADERフラグからUPDATEフラグに変換します。これにより、リーダーはバッファからヘッドページを交換できなくなり、ヘッドページを進めるのを停止します。

これにより、リーダーがライターに対して競合状態を生じることはありません。リーダーはスピンする必要があり、これがリーダーがライターを優先的に実行できない理由です：

            tail page
               |
               v
    +---+    +---+    +---+    +---+
<---|   |--->|   |-H->|   |--->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

            tail page
               |
               v
    +---+    +---+    +---+    +---+
<---|   |--->|   |-U->|   |--->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

次のページが新しいヘッドページになります：

           tail page
               |
               v
    +---+    +---+    +---+    +---+
<---|   |--->|   |-U->|   |-H->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

新しいヘッドページが設定された後、古いヘッドページのポインタをNORMALに戻すことができます:

           tail page
               |
               v
    +---+    +---+    +---+    +---+
<---|   |--->|   |--->|   |-H->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

ヘッドページが移動した後、テールページは今度は前進する可能性があります:

                    tail page
                        |
                        v
    +---+    +---+    +---+    +---+
<---|   |--->|   |--->|   |-H->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

上記は単純な更新です。より複雑なシナリオについて説明します。

前述した通り、十分な書き込みが最初の書き込みを妨害した場合、テールページはバッファを一周してコミットページと出会う可能性があります。このとき、書き込みをドロップする必要があります（通常はユーザーに警告を伴います）。ただし、コミットがリーダーページにまだ残っている場合、どうなりますか？コミットページはリングバッファの一部ではありません。テールページはこの状況を考慮する必要があります:

          reader page    commit page
              |              |
              v              |
             +---+           |
             |   |<----------+
             |   |
             |   |------+
             +---+      |
                        |
                        v
    +---+    +---+    +---+    +---+
<---|   |--->|   |-H->|   |--->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+
               ^
               |
           tail page

テールページが単にヘッドページを前進させても、リーダーページを離れる際のコミットが正しいページを指していない可能性があります。

この問題を解決するには、ヘッドページを前進させる前にコミットページがリーダーページにあるかをテストする必要があります。もしリーダーページにある場合、テールページがバッファを巻き上げたとみなされ、新しい書き込みをドロップする必要があります。

これはレースコンディションではありません。コミットページは外側のライター（プレエミットされたライター）のみが動かすため、ライターがテールページを動かしている間、コミットページは動かないからです。リーダーはリーダーページをスワップすることができません（リーダーページがコミットページとしても使われている場合）。リーダーは単にコミットがリーダーページから外れているかを確認するだけでよいです。コミットページがリーダーページを離れた後は、それ以降リーダーページに戻ることはなく、リーダーがバッファページ（コミットページでもある）と再度スワップしない限りです。

ネストされた書き込み¶

テールページを前進させる際には、ヘッドページが次のページである場合にまずヘッドページを前進させる必要があります。ヘッドページが次のページでない場合、テールページはcmpxchgで単に更新されます。

テールページを動かすのはライターのみです。この操作は原子的に行う必要があります（ネストされたライターを防ぐため）:

temp_page = tail_page
next_page = temp_page->next
cmpxchg(tail_page, temp_page, next_page)

上記は、テールページが予期するページを指している場合にのみテールページを更新します。失敗した場合、ネストされた書き込みがテールページを前進させたため、現在の書き込みはそれを押し上げる必要はありません:

           temp page
               |
               v
            tail page
               |
               v
    +---+    +---+    +---+    +---+
<---|   |--->|   |--->|   |--->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

ネストされたライターが入り、テールページを前進させます:

                    tail page (moved by nested writer)
            temp page   |
               |        |
               v        v
    +---+    +---+    +---+    +---+
<---|   |--->|   |--->|   |--->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

上記はcmpxchgで失敗しますが、テールページがすでに前進しているため、ライターは新しいテールページでストレージを再び確保しようと試みます。

しかし、ヘッドページの前進はやや複雑です:

            tail page
               |
               v
    +---+    +---+    +---+    +---+
<---|   |--->|   |-H->|   |--->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

ライターはヘッドページポインタをUPDATEに変換します:

            tail page
               |
               v
    +---+    +---+    +---+    +---+
<---|   |--->|   |-U->|   |--->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

しかし、ネストされたライターがここで優先的に実行した場合、次のページがヘッドページであることが確認されますが、それもまたネストされています。ライターはネストされていることを検出しますし、その情報を保存します。検出のポイントは、ヘッダーやノーマルポインタではなく、UPDATEフラグを確認することです。

ネストされたライターは新しいヘッドページポインタを設定します:

           tail page
               |
               v
    +---+    +---+    +---+    +---+
<---|   |--->|   |-U->|   |-H->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

ただし、UPDATEをノーマルに戻すことはしません。HEADからUPDATEにポインタを変換したライターだけが、それをノーマルに戻します:

                    tail page
                        |
                        v
    +---+    +---+    +---+    +---+
<---|   |--->|   |-U->|   |-H->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

ネストされたライターが完了した後、最外層のライターがUPDATEポインタをノーマルに戻します:

                    tail page
                        |
                        v
    +---+    +---+    +---+    +---+
<---|   |--->|   |--->|   |-H->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

複数のネストされた書き込みが入り、テールページが複数のページ分進んだ場合、状況はさらに複雑になります:

(first writer)

            tail page
               |
               v
    +---+    +---+    +---+    +---+
<---|   |--->|   |-H->|   |--->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

ライターはヘッドページポインタをUPDATEに変換します:

            tail page
               |
               v
    +---+    +---+    +---+    +---+
<---|   |--->|   |-U->|   |--->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

次のライターが入ると、UPDATEを確認し、新しいヘッドページを設定します:

(second writer)

           tail page
               |
               v
    +---+    +---+    +---+    +---+
<---|   |--->|   |-U->|   |-H->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

ネストされたライターはテールページを前へ進めるが、古いUPDATEページをノーマルに戻すことはしない。なぜなら、最外層のライターではないからです:

                    tail page
                        |
                        v
    +---+    +---+    +---+    +---+
<---|   |--->|   |-U->|   |-H->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

別のライターが優先的に実行し、テールページの次のページがヘッドページであることを確認します。それをHEADからUPDATEに変更します:

(third writer)

                    tail page
                        |
                        v
    +---+    +---+    +---+    +---+
<---|   |--->|   |-U->|   |-U->|   |--->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

ライターはヘッドページを前へ進めます:

(third writer)

                    tail page
                        |
                        v
    +---+    +---+    +---+    +---+
<---|   |--->|   |-U->|   |-U->|   |-H->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

しかし、第三のライターがHEADフラグをUPDATEに変更したため、それをノーマルに戻します:

(third writer)

                    tail page
                        |
                        v
    +---+    +---+    +---+    +---+
<---|   |--->|   |-U->|   |--->|   |-H->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

その後、テールページを進めて、第二のライターに戻ります:

(second writer)

                             tail page
                                 |
                                 v
    +---+    +---+    +---+    +---+
<---|   |--->|   |-U->|   |--->|   |-H->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

第二のライターはテールページを進めることが失敗し、すでに進んでいたため、再度試行して新しいテールページにデータを追加します。その後、第一のライターに戻ります:

(first writer)

                             tail page
                                 |
                                 v
    +---+    +---+    +---+    +---+
<---|   |--->|   |-U->|   |--->|   |-H->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

第一のライターは、自身がHEADページを更新している間にテールページが進んだかどうかを原子的に確認できません。そのため、HEADページを自身が考える新しいヘッドページに更新します:

(first writer)

                             tail page
                                 |
                                 v
    +---+    +---+    +---+    +---+
<---|   |--->|   |-U->|   |-H->|   |-H->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

cmpxchgがポインタの古い値を返すため、第一のライターはノーマルからHEADへのポインタ更新を成功と判断します。しかし、この状態では不十分です。テールページが以前の位置か、次のページかを確認する必要があります:

(first writer)

               A        B    tail page
               |        |        |
               v        v        v
    +---+    +---+    +---+    +---+
<---|   |--->|   |-U->|   |-H->|   |-H->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

テールページがAでもBでもなければ、ポインタをノーマルに戻す必要があります。ネストされたライターのみが懸念されるため、HEADページを設定した後だけチェックする必要があります:

(first writer)

               A        B    tail page
               |        |        |
               v        v        v
    +---+    +---+    +---+    +---+
<---|   |--->|   |-U->|   |--->|   |-H->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+

これでライターがヘッドページを更新できます。また、ヘッドページはUPDATE状態のまま、最外層のライターのみがノーマルに戻す必要があるため、リーダーが誤ったヘッドページを確認しないようにします:

(first writer)

               A        B    tail page
               |        |        |
               v        v        v
    +---+    +---+    +---+    +---+
<---|   |--->|   |--->|   |--->|   |-H->
--->|   |<---|   |<---|   |<---|   |<---
    +---+    +---+    +---+    +---+
