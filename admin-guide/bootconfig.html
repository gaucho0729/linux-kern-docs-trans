ブート構成¶

著者

Masami Hiramatsu <mhiramat@kernel.org>

概要¶

ブート構成は、現在のカーネルコマンドラインを拡張し、効率的にカーネルをブートする際に追加のキー値データをサポートします。これにより、管理者が構造化されたキーの設定ファイルを渡すことが可能になります。

構成ファイルの構文¶

ブート構成の構文は単純な構造化されたキー値です。各キーはドットで結ばれた単語からなり、キーと値は「.」で接続されます。 =値はセミコロン（;）または改行（\n）で終了しなければなりません。配列値の場合、配列項目はコンマ（,).

KEY[.WORD[...]] = VALUE[, VALUE2[...]][;]

）で区切ります。カーネルコマンドライン構文とは異なり、コンマと =.

の周辺にスペースを挟んでも問題ありません。各キーワードはアルファベット、数字、ハイフン（-）またはアンダースコア（_）のみを含む必要があります。値はセミコロン（;）、改行（\n）、コンマ（,）、ハッシュ（#）、閉じ括弧（}).

）などの区切り文字を除き、印刷可能な文字またはスペースのみを含みます。値にこれらの区切り文字を使用したい場合は、ダブルクォーテーション（"VALUE"）またはシングルクォーテーション（'VALUE'）で囲むことができます。注意点として、これらのクォーテーションはエスケープできません。

値を持たないキーまたは空の値を持つキーが存在することもあります。これらはキーが存在するかどうかを確認するために使用されます（ブーリアンのように）。

キー値構文¶

ブート構成ファイルの構文は、ユーザーが大括弧で部分的に同じキーワードをマージできるようにします。例えば：

foo.bar.baz = value1
foo.bar.qux.quux = value2

これらは以下のようにも記述できます：

foo.bar {
   baz = value1
   qux.quux = value2
}

さらに短く記述できます：

foo.bar { baz = value1; qux.quux = value2 }

どちらのスタイルでも、ブート時に解析する際、同じキーワードは自動的にマージされます。したがって、類似したツリーまたはキー値を追加できます。

同じキーの値¶

2つ以上の値または配列が同じキーを共有することは禁止されています。例えば：

foo = bar, baz
foo = qux  # !ERROR! we can not re-define same key

値を更新する場合は、上書き演算子 := を明示的に使用する必要があります。例えば：

foo = bar, baz
foo := qux

その後、 qux が foo キーに割り当てられます。これは、デフォルトのブート構成を解析することなく、一部のカスタムブート構成を追加してデフォルト値を上書きするのに役立ちます。

既存のキーに値を配列要素として追加する場合は、 += 演算子を使用できます。例えば：

foo = bar, baz
foo += qux

この場合、キー foo には bar, baz および qux.

が含まれます。さらに、親キーの下にサブキーと値が共存できます。例えば、以下の構成は許可されています：

foo = value1
foo.bar = value2
foo := value3 # This will update foo's value.

注意点として、構造化されたキーの下に直接の文字列値を指定するための構文はありません。そのため、大括弧の外側で定義する必要があります。例えば：

foo {
    bar = value1
    bar {
        baz = value2
        qux = value3
    }
}

また、キーの下にある値ノードの順序は固定されています。値とサブキーが存在する場合、値は常にキーの最初の子ノードになります。したがって、ユーザーがサブキーを最初に指定した場合、例えば：

foo.bar = value1
foo = value2

プログラム（および /proc/bootconfig）では以下のように表示されます：

foo = value2
foo.bar = value1

コメント¶

設定構文はシェルスクリプトスタイルのコメントを受け入れます。ハッシュ（"#"）で始まり改行（"\n"）まで続くコメントは無視されます。

# comment line
foo = value # value is set to foo.
bar = 1, # 1st element
      2, # 2nd element
      3  # 3rd element

これは以下のように解析されます：

foo = value
bar = 1, 2, 3

値と区切り記号（""）の間にコメントを置くことはできません。これは次の設定が構文エラーになります, または ;。これは次の設定が構文エラーになります

key = 1 # comment
      ,2

/proc/bootconfig¶

/proc/bootconfig は、ブート設定のユーザー空間インターフェースです。/proc/cmdline とは異なり、このファイルはキーバリュー形式のリストを表示します。各キーバリューペアは以下の形式で各行に表示されます：

KEY[.WORDS...] = "[VALUE]"[,"VALUE2"...]

ブート用にカーネルを設定する¶

ブート設定ファイルは initrd でロードされるため、以下のようないnitrd（initramfs）イメージファイルの末尾にパディング、サイズ、チェックサム、12バイトのマジックワードが追加されます。

[initrd][bootconfig][padding][size(le32)][checksum(le,32)][#BOOTCONFIG\n]

サイズとチェックサムのフィールドは符号なしの32ビットリトルエンディアン値です。

ブート設定が initrd イメージに追加される際、全体のファイルサイズは4バイト単位でアライメントされます。ギャップを埋めるために、NULL文字（\0)が追加されます。したがって、 size はブートconfigファイルの長さ＋パディングバイトです。

Linuxカーネルはinitrdイメージの最後の部分をメモリ内でデコードしてブート設定データを取得します。この「パッケージング」方法により、ブートローダーが正しいinitrdファイルサイズを渡す限り、ブートローダーおよびカーネルイメージ自体を変更または更新する必要がありません。もし偶然にもブートローダーがより長いサイズを渡すと、カーネルはブートconfigデータを見つけることができません。

この操作を行うため、Linuxカーネルはtools/bootconfig以下の「bootconfig」コマンドを提供し、管理者がinitrdイメージに設定ファイルを追加または削除できるようにします。以下のコマンドで構築できます：

# make -C tools/bootconfig

ブート設定ファイルをinitrdイメージに追加するには、以下のコマンドを実行してください（既存データは自動的に削除されます）：

# tools/bootconfig/bootconfig -a your-config /boot/initrd.img-X.Y.Z

イメージから設定を削除するには、以下のコマンドで -d オプションを使用してください：

# tools/bootconfig/bootconfig -d /boot/initrd.img-X.Y.Z

次に、通常のカーネルコマンドラインに「bootconfig」を追加して、カーネルにinitrdファイルの末尾にブートconfigを検索するように指示してください。

設定ファイルの制限¶

現在、最大の設定サイズは32KBで、合計のキーワード（キーバリュー エントリではない）は1024ノード以下でなければなりません。注意：これはエントリ数ではなくノード数です。1つのエントリは2ノード以上を消費するため、理論的には最大で512のキーバリュー ペアが可能です。キーワードが平均で3語含まれる場合、256のキーバリュー ペアが可能です。ほとんどの場合、設定項目の数は100エントリ以下で、8KB未満なので十分です。ノード数が1024を超えた場合、ファイルサイズが32KB未満でもパーサーがエラーを返します。（注意：この最大サイズはパディング ナル文字を含んでいません。）いずれにしても、bootconfigコマンドはinitrdイメージにboot configを追加する際にこれを検証するため、ブート前にユーザーが確認できます。

Bootconfig APIs¶

ユーザーはキーバリュー ペアを照会したりループ処理したりでき、ルート（プレフィックス）キーノードを検索し、そのノード以下のキーバリザーを取得することも可能です。

キーコンテキストを指定することで、直接値を照会できます。 xbc_find_value()ブートコンフィグに存在するキーや値を確認するには、以下のようにします。 xbc_for_each_key_value() キーバリュー ペアをループ処理するには、以下のようにします。注意：配列の値を取得するには、 xbc_array_for_each_value() 配列の値を取得するには、例えば以下のようにします：

vnode = NULL;
xbc_find_value("key.word", &vnode);
if (vnode && xbc_node_is_array(vnode))
   xbc_array_for_each_value(vnode, value) {
     printk("%s ", value);
   }

プレフィックス文字列を持つキーや値に焦点を当てたい場合、以下のようにします。 xbc_find_node() プレフィックス文字列でノードを検索し、そのノード以下のキーや値をループ処理するには、 xbc_node_for_each_key_value().

しかし、最も一般的な使い方は、プレフィックス以下の指定された値や配列を取得することです。以下に示します：

root = xbc_find_node("key.prefix");
value = xbc_node_find_value(root, "option", &vnode);
...
xbc_node_for_each_array_value(root, "array-option", value, anode) {
   ...
}

これは「key.prefix.option」の値と「key.prefix.array-option」の配列を取得します。

ロックは必要ありません。初期化後、設定は読み取り専用になります。変更が必要な場合は、すべてのデータとキーコンテキストをコピーする必要があります。
