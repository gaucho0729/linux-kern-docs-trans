デバイスホワイトリストコントローラー¶

1. 説明¶

デバイスファイルに対するopenおよびmknod制限を追跡し、強制するためのcgroupを実装します。デバイスcgroupは、各cgroupにデバイスアクセスホワイトリストを関連付けています。ホワイトリストエントリには4つのフィールドがあります。'type'は(all)、c(char)、またはb(block)のいずれかです。'all'はすべてのタイプおよびすべての主装置番号と補助装置番号に適用されます。主装置番号と補助装置番号は整数か*（すべて）です。アクセスはr（読み取り）、w（書き込み）、m（mknod）の組み合わせです。

ルートデバイスcgroupは初期状態で'all'にrwmを適用します。子デバイスcgroupは親からコピーを受け取り、管理者がホワイトリストからデバイスを削除したり新しいエントリを追加したりできます。子cgroupは親が拒否したデバイスアクセスを受けることはできません。

2. ユーザーインターフェース¶

エントリはdevices.allowを使用して追加し、devices.denyを使用して削除します。例えば：

echo 'c 1:3 mr' > /sys/fs/cgroup/1/devices.allow

cgroup 1が通常/dev/nullと呼ばれるデバイスを読み取りおよびmknodするのを許可します。実行：

echo a > /sys/fs/cgroup/1/devices.deny

はデフォルトの’a : rwm’エントリを削除します。実行：

echo a > /sys/fs/cgroup/1/devices.allow

は’a : rwm’エントリをホワイトリストに追加します。

3. セキュリティ¶

タスクはcgroup間で自身を移動できます。これは明らかに十分ではありませんが、ユーザーがこの機能に慣れるにつれて適切な制限方法を決定できます。CAP_SYS_ADMINを必要とする可能性があります。これは少なくともCAP_MKNODとは別のビットです。また、現在のcgroupの子孫でないcgroupへの移動を拒否する方法も考えられます。あるいは、rootを厳格に制限しようとしているため、CAP_MAC_ADMINを使用する可能性もあります。

ホワイトリストを変更するか、他のタスクを新しいcgroupに移動するにはCAP_SYS_ADMINが必要です。（再び、この点も変更する可能性があります）。

cgroupは親のcgroupよりも多くの権限を付与されません。

4. ヒエラルキー¶

デバイスcgroupは、cgroupが親のcgroupよりも多くのアクセス権限を持つことはないことを確認することで階層を維持します。常にcgroupのdevices.denyファイルにエントリを書き込むたびに、そのすべての子cgroupのホワイトリストからそのエントリを削除し、ローカルに設定されたホワイトリストエントリを再評価します。親のcgroupよりも多くのアクセス権を提供するローカルのホワイトリストエントリがある場合、そのエントリはホワイトリストから削除されます。

例:

  A
 / \
    B

group        behavior       exceptions
A            allow          "b 8:* rwm", "c 116:1 rw"
B            deny           "c 1:3 rwm", "c 116:2 rwm", "b 3:* rwm"

グループAでデバイスが拒否されている場合：

# echo "c 116:* r" > A/devices.deny

下位に伝播し、Bのエントリを再検証した後、ホワイトリストのエントリ「c 116:2 rwm」が削除されます：

group        whitelist entries                        denied devices
A            all                                      "b 8:* rwm", "c 116:* rw"
B            "c 1:3 rwm", "b 3:* rwm"                 all the rest

親の例外が変更され、ローカルの例外が許可されなくなった場合、それらは削除されます。

新しいホワイトリストエントリが伝播されないことに注意してください：

  A
 / \
    B

group        whitelist entries                        denied devices
A            "c 1:3 rwm", "c 1:5 r"                   all the rest
B            "c 1:3 rwm", "c 1:5 r"                   all the rest

追加 c *:3 rwm:

# echo "c *:3 rwm" >A/devices.allow

の結果：

group        whitelist entries                        denied devices
A            "c *:3 rwm", "c 1:5 r"                   all the rest
B            "c 1:3 rwm", "c 1:5 r"                   all the rest

ですが、今後Bに新しいエントリを追加することが可能になります：

# echo "c 2:3 rwm" >B/devices.allow
# echo "c 50:3 r" >B/devices.allow

あるいは：

# echo "c *:3 rwm" >B/devices.allow

device cgroups に子が存在する場合、devices.allow または devices.deny に 'a' を書き込むことですべてを許可または拒否する操作は可能ではなくなります。

4.1 Hierarchy (内部実装)¶

device cgroups は、ALLOW、DENY の動作と例外リストを用いて内部的に実装されており、以前のホワイトリストのみの実装との互換性を保つため、同じユーザーインターフェースを用いて内部状態を制御しています。デバイスへのアクセスを制限する例外の追加や削除は階層下に伝播され、それぞれの伝播された例外に対して、現在の親のアクセスルールに基づき有効なルールが再評価されます。
