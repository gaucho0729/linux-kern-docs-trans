ブロックIOコントローラー¶

概要¶

cgroupサブシステム「blkio」はブロックIOコントローラーを実装しています。ストレージ階層の葉ノードおよび中間ノードの両方で、比例帯域幅（proportional BW）、最大帯域幅（max BW）などのさまざまなIO制御ポリシーが必要なようです。計画は、blkioコントローラーにもcgroupベースの管理インターフェースを使用し、ユーザーのオプションに基づいて背景でIOポリシーを切り替えることです。

IO制御ポリシーの一つに制限ポリシー（throttling policy）があり、これはデバイスに上部IOレート制限を指定するために使用できます。このポリシーはジェネリックブロックレイヤーで実装されており、葉ノードだけでなく、デバイスマッパーなどの上位レベルの論理デバイスでも使用できます。

HOWTO¶

制限/上部制限ポリシー¶

  • ブロックIOコントローラーを有効にする:

    CONFIG_BLK_CGROUP=y

  • ブロックレイヤーでの制限を有効にする:

    CONFIG_BLK_DEV_THROTTLING=y

  • blkioコントローラーをマウントする（cgroups.txtを参照、なぜcgroupsが必要なのか？）:

    mount -t cgroup -o blkio none /sys/fs/cgroup/blkio

  • ルートグループの特定のデバイスに帯域幅レートを指定します。ポリシーの形式は「<major>:<minor> <bytes_per_second>」です:

    echo "8:16  1048576" > /sys/fs/cgroup/blkio/blkio.throttle.read_bps_device

    上記は、major/minor番号が8:16のデバイスにおいて、ルートグループの読み取り操作に1MB/秒の制限をかけます。

  • ddコマンドを実行してファイルを読み込み、レートが1MB/sに制限されているか確認します:

    # dd iflag=direct if=/mnt/common/zerofile of=/dev/null bs=4K count=1024
1024+0 records in
1024+0 records out
4194304 bytes (4.2 MB) copied, 4.0001 s, 1.0 MB/s

書き込み制限はblkio.throttle.write_bps_deviceファイルを使用して設定できます。

階層的なcgroups¶

制限は階層サポートを実装していますが、制限の階層サポートはcgroup側で「sane_behavior」が有効になっている場合にのみ有効になります。これは現在開発用オプションであり、公開されていません。

誰かが次のようないくつかのグループを階層に作成した場合:

   root
   /  \
test1 test2
   |
test3

「sane_behavior」で制限を行うと、階層を正しく処理します。制限ではすべての制限がサブツリー全体に適用され、すべての統計情報はそのcgroup内のタスクによって生成されたIOにローカルです。

cgroup側で「sane_behavior」が無効な場合、制限は実質的に同じレベルにあるすべてのグループを以下のようないくつかのグループとして扱います:

        pivot
     /  /   \  \
root  test1 test2  test3

さまざまなユーザーが見える設定オプション¶

CONFIG_BLK_CGROUP

  • ブロックIOコントローラー。

CONFIG_BFQ_CGROUP_DEBUG

  • デバッグ支援。このオプションが有効になっている場合、cgroupに追加の統計ファイルが表示されます。

CONFIG_BLK_DEV_THROTTLING

  • ブロックレイヤー内でブロックデバイスの制限を有効にする。

cgroupファイルの詳細¶

比例重みポリシーのファイル¶

  • blkio.weight

    • 各cgroupの重みを指定します。これは、デバイスごとのルールが指定されるまで、すべてのデバイスにおけるグループのデフォルト重みです。（blkio.weight_deviceを参照）現在、許可される重みの範囲は10から1000です。

  • blkio.weight_device

    • このインターフェースを使用して、各cgroupごとにデバイスごとのルールを指定できます。これらのルールは、blkio.weightで指定されたグループの重みのデフォルト値を上書きします。

      以下は形式です:

      # echo dev_maj:dev_minor weight > blkio.weight_device

      このcgroupで/dev/sdb (8:16)のweight=300を設定:

      # echo 8:16 300 > blkio.weight_device
# cat blkio.weight_device
dev     weight
8:16    300

      このcgroupで/dev/sda (8:0)のweight=500を設定:

      # echo 8:0 500 > blkio.weight_device
# cat blkio.weight_device
dev     weight
8:0     500
8:16    300

      このcgroupで/dev/sdaの特定のweightを削除:

      # echo 8:0 0 > blkio.weight_device
# cat blkio.weight_device
dev     weight
8:16    300
  • blkio.time

    • cgroupごとにデバイスごとのディスク時間（ミリ秒単位）を指定します。最初の2つのフィールドはデバイスの主番号と補助番号を、3番目のフィールドはグループに割り当てられたディスク時間（ミリ秒）を示します。

  • blkio.sectors

    • グループがディスクとやり取りするセクタ数を指定します。最初の2つのフィールドはデバイスの主番号と補助番号を、3番目のフィールドはグループがデバイスとやり取りするセクタ数を示します。

  • blkio.io_service_bytes

    • グループがディスクとやり取りするバイト数を指定します。これらは操作タイプ（読み取り/書き込み、同期/非同期）ごとにさらに分類されます。最初の2つのフィールドはデバイスの主番号と補助番号を、3番目のフィールドは操作タイプを、4番目のフィールドはバイト数を示します。

  • blkio.io_serviced

    • グループがディスクに対して実行するIO（bio）の数を指定します。これらは操作タイプ（読み取り/書き込み、同期/非同期）ごとにさらに分類されます。最初の2つのフィールドはデバイスの主番号と補助番号を、3番目のフィールドは操作タイプを、4番目のフィールドはIOの数を示します。

  • blkio.io_service_time

    • このcgroupが実行したIOのリクエスト送信から完了までの総時間を示します。ナノ秒単位で表示し、フラッシュデバイスでも意味のある値を提供します。キュー深度が1のデバイスではこの時間は実際のサービス時間に対応しますが、キュー深度が1より大きい場合、リクエストが順不同で処理されるため、この時間は複数のIOのサービス時間の合計を含む可能性があります。結果として、io_service_timeの合計が実際に経過した時間より大きくなることがあります。この時間は操作タイプ（読み取り/書き込み、同期/非同期）ごとにさらに分類されます。最初の2つのフィールドはデバイスの主番号と補助番号を、3番目のフィールドは操作タイプを、4番目のフィールドはio_service_time（ナノ秒単位）を示します。

  • blkio.io_wait_time

    • このcgroupのIOがスケジューラーのキューで待機している合計時間。これは累積したio_wait_timeの合計であり、全体の経過時間より大きい場合があります。これはcgroup全体の待機時間の測定ではなく、個々のIOのwait_timeを測定する指標です。キュー深度（queue_depth）が1より大きいデバイスでは、IOがデバイスに割り当てられた後でサービスを受けるまでの待機時間は含まれず、実際にサービスを受けるまでまでの時間（デバイスがリクエストを再順序化するため、タイムラグが生じる可能性があります）が計測されます。この時間はフラッシュデバイスでも意味のあるナノ秒単位で表示されます。この時間は読み込み/書き込み、同期/非同期の操作タイプごとにさらに分類されます。最初の2つのフィールドはデバイスの主装置番号とサブ装置番号を、3番目のフィールドは操作タイプを、4番目のフィールドはio_wait_time（ナノ秒単位）を示します。

  • blkio.io_merged

    • このcgroupに属するリクエストにマージされたbios/リクエストの総数。これは読み込み/書き込み、同期/非同期の操作タイプごとにさらに分類されます。

  • blkio.io_queued

    • このcgroupが任意の瞬間に待機中のリクエストの総数。これは読み込み/書き込み、同期/非同期の操作タイプごとにさらに分類されます。

  • blkio.avg_queue_size

    • CONFIG_BFQ_CGROUP_DEBUG=yのときのみデバッグ用。このcgroupが存在する間の平均キューのサイズ。キューのタイムスライスを取得するたびにキューのサイズをサンプリングします。

  • blkio.group_wait_time

    • CONFIG_BFQ_CGROUP_DEBUG=yのときのみデバッグ用。このcgroupがビジー状態になった（つまり0から1リクエスト待機に移行した）後で、そのキューのタイムスライスを取得するまでに待機した時間。これはio_wait_timeとは異なり、io_wait_timeはこのcgroup内の各IOがスケジューラーのキューで待機した時間の累積値です。ナノ秒単位で表示されます。この値を読み取る際、cgroupがタイムスライスを待っている状態にある場合、statは最後にタイムスライスを取得した時点までのgroup_wait_timeのみを報告し、現在の差分は含みません。

  • blkio.empty_time

    • CONFIG_BFQ_CGROUP_DEBUG=yの設定が有効な場合にのみデバッグ用の情報が表示されます。これは、cgroupがサービスを受けていない状態で待機している時間（待機時間）を表し、これはcgroup内のキューのアイドル時間は含みません。単位はナノ秒です。この値を読み取る際、cgroupが空状態にある場合、statは最後に待機要求があった時点までのempty_timeのみを報告し、現在のdeltaは含みません。

  • blkio.idle_time

    • CONFIG_BFQ_CGROUP_DEBUG=yの設定が有効な場合にのみデバッグ用の情報が表示されます。これは、I/Oスケジューラが他のキュー/サブグループからの要求よりも優先度の高い要求を待機するためにアイドルしている時間（アイドル時間）を表します。単位はナノ秒です。この値を読み取る際、cgroupがアイドル状態にある場合、statは最後のアイドル期間までのidle_timeのみを報告し、現在のdeltaは含みません。

  • blkio.dequeue

    • CONFIG_BFQ_CGROUP_DEBUG=yの設定が有効な場合にのみデバッグ用の情報が表示されます。これは、デバイスのサービスツリーからグループがデキューされた回数を示します。最初の2つのフィールドはデバイスの主機器番号とサブ機器番号を、3番目のフィールドは特定のデバイスからグループがデキューされた回数を表します。

  • blkio.*_recursive

    • 各種統計情報の再帰バージョンです。これらのファイルは非再帰バージョンと同じ情報を表示しますが、すべてのサブグループの統計情報を含みます。

制限/上限ポリシー用ファイル¶

  • blkio.throttle.read_bps_device

    • デバイスからの読み取りレートの上限を指定します。I/Oレートは秒あたりのバイト数で指定します。ルールはデバイスごとに設定されます。フォーマットは以下の通りです：

      echo "<major>:<minor>  <rate_bytes_per_second>" > /cgrp/blkio.throttle.read_bps_device
  • blkio.throttle.write_bps_device

    • デバイスへの書き込みレートの上限を指定します。I/Oレートは秒あたりのバイト数で指定します。ルールはデバイスごとに設定されます。フォーマットは以下の通りです：

      echo "<major>:<minor>  <rate_bytes_per_second>" > /cgrp/blkio.throttle.write_bps_device
  • blkio.throttle.read_iops_device

    • デバイスからの読み取りレートの上限を指定します。I/Oレートは秒あたりのI/O操作数で指定します。ルールはデバイスごとに設定されます。フォーマットは以下の通りです：

      echo "<major>:<minor>  <rate_io_per_second>" > /cgrp/blkio.throttle.read_iops_device
  • blkio.throttle.write_iops_device

    • デバイスへの書き込みレートの上限を指定します。I/Oレートは秒あたりのI/O操作数で指定します。ルールはデバイスごとに設定されます。フォーマットは以下の通りです：

      echo "<major>:<minor>  <rate_io_per_second>" > /cgrp/blkio.throttle.write_iops_device
注意：デバイスに対してBWとIOPSのルールを同時に指定した場合、I/Oは

両方の制約に従います。

  • blkio.throttle.io_serviced

    • グループがディスクに対して実行するIO（bio）の数を指定します。これらは操作タイプ（読み取り/書き込み、同期/非同期）ごとにさらに分類されます。最初の2つのフィールドはデバイスの主番号と補助番号を、3番目のフィールドは操作タイプを、4番目のフィールドはIOの数を示します。

  • blkio.throttle.io_service_bytes

    • グループがディスクとやり取りするバイト数を指定します。これらは操作タイプ（読み取り/書き込み、同期/非同期）ごとにさらに分類されます。最初の2つのフィールドはデバイスの主番号と補助番号を、3番目のフィールドは操作タイプを、4番目のフィールドはバイト数を示します。

各種ポリシーに共通するファイル¶

  • blkio.reset_stats

    • このファイルに整数を書き込むと、指定されたcgroupのすべての統計情報がリセットされます。
