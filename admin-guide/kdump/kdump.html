Kdump に関するドキュメンテーション - kexec を使用したクラッシュダンプ解決策¶

このドキュメントには概要、セットアップとインストール、および分析情報が含まれています。

概要¶

Kdump は、システムカーネルのメモリのダンプが必要な場合（例：システムがパニックになったときなど）に、kexec を使ってすぐにダンプ取得カーネルにブートします。システムカーネルのメモリイメージは再起動しても保持され、ダンプ取得カーネルからアクセス可能です。

cp や scp などの一般的なコマンドを使用して、メモリイメージをローカルディスクのダンプファイルにコピーしたり、ネットワークを介してリモートシステムにコピーしたりできます。

Kdump と kexec は現在、x86、x86_64、ppc64、ia64、s390x、arm および arm64 のアーキテクチャでサポートされています。

システムカーネルがブートする際、ダンプ取得カーネル用にメモリの小さなセクションを予約します。これにより、システムカーネルからの継続的なディレクトアクセス（DMA）がダンプ取得カーネルを破壊しないようにします。kexec -p コマンドは、この予約メモリにダンプ取得カーネルをロードします。

x86 マシンでは、カーネルがロードする場所に関係なく、最初の 640 KB の物理メモリが必要です。そのため、kexec はダンプ取得カーネルにブートする直前にこの領域をバックアップします。

同様に、PPC64 マシンでは、カーネルがロードする場所に関係なく、最初の 32 KB の物理メモリが必要です。また、64 KB ページサイズをサポートするため、kexec は最初の 64 KB メモリをバックアップします。

s390x では、kdump がトリガーされたときに、crashkernel レギオンが [0, crashkernel レギオンサイズ] と交換され、その後 kdump カーネルが [0, crashkernel レギオンサイズ] で実行されます。そのため、s390x ではリロケート可能なカーネルは必要ありません。

システムカーネルのコアイメージに関する必要なすべての情報は ELF 形式でエンコードされ、クラッシュ時に予約されたメモリ領域に保存されます。ELF ヘッダーの開始物理アドレスは elfcorehdr= ブートパラメータを通じてダンプ取得カーネルに渡されます。オプションで、elfcorehdr=[size[KMG]@]offset[KMG] の構文を使用して ELF ヘッダーのサイズも渡すことができます。

ダンプ取得カーネルを使用すると、/proc/vmcore を通じてメモリイメージにアクセスできます。これにより、cp や scp などのファイルコピーコマンドで ELF 形式のダンプファイルとして出力できます。さらに、GNU Debugger（GDB）や Crash ツールなどの分析ツールを使用してダンプファイルをデバッグできます。この方法により、ダンプページが正しく順序付けられます。

セットアップとインストール¶

kexec-tools をインストール¶

  1. root ユーザーとしてログインします。

  2. 次の URL から kexec-tools ユーザースペースパッケージをダウンロードします：

http://kernel.org/pub/linux/utils/kernel/kexec/kexec-tools.tar.gz

これは最新バージョンへのシンリンクです。

最新の kexec-tools git ツリーは次の URL で入手可能です：

  • git://git.kernel.org/pub/scm/utils/kernel/kexec/kexec-tools.git

  • http://www.kernel.org/pub/scm/utils/kernel/kexec/kexec-tools.git

gitwebインターフェースも利用可能です http://www.kernel.org/git/?p=utils/kernel/kexec/kexec-tools.git

kexec-toolsに関する詳しい情報は以下にあります http://horms.net/projects/kexec/

  1. 以下のコマンドを使用してtarballを展開してください:

    tar xvpzf kexec-tools.tar.gz

  2. 以下のコマンドを使用してkexec-toolsディレクトリに移動してください:

    cd kexec-tools-VERSION

  3. 以下のコマンドを使用してパッケージを構成してください:

    ./configure

  4. 以下のコマンドを使用してパッケージをコンパイルしてください:

    make

  5. 以下のコマンドを使用してパッケージをインストールしてください:

    make install

システムをビルドし、ダンプキャプチャカーネルをダンプします¶

Kdumpを使用する2つの方法があります。

  1. カーネルコアダンプをキャプチャするために、別途カスタムのダンプキャプチャカーネルをビルドしてください。

  2. または、システムカーネルバイナリ自体をダンプキャプチャカーネルとして使用し、別途のダンプキャプチャカーネルをビルドする必要はありません。これは、再配置可能なカーネルをサポートするアーキテクチャでのみ可能です。今日までに、i386、x86_64、ppc64、ia64、armおよびarm64アーキテクチャが再配置可能なカーネルをサポートしています。

再配置可能なカーネルをビルドすることは、ダンプをキャプチャするために2番目のカーネルをビルドする必要がないという点で有利です。ただし、同時に、自分のニーズに合ったカスタムダンプキャプチャカーネルをビルドしたい場合もあります。

システムおよびダンプキャプチャカーネルの設定項目として、kdumpサポートを有効にするために必要な設定は以下の通りです。

システムカーネルの設定オプション¶

  1. 「プロセッサタイプと機能」で「kexecシステムコール」を有効にしてください。

    CONFIG_KEXEC=y

  2. 「ファイルシステム」->「仮想ファイルシステム」で「sysfsファイルシステムサポート」を有効にしてください。これは通常デフォルトで有効になっています:

    CONFIG_SYSFS=y

    「Configure standard kernel features (for small systems)」が「General Setup」で有効になっていない場合、「sysfsファイルシステムサポート」は「仮想ファイルシステム」メニューに表示されない場合があります。その場合は、.configファイル自体を確認してsysfsが有効になっていることを確認してください、以下の通り:

    grep 'CONFIG_SYSFS' .config

  3. 「カーネルハッキング」で「カーネルにデバッグ情報でコンパイル」を有効にしてください。

    CONFIG_DEBUG_INFO=Y

    これにより、カーネルがデバッグシンボルでビルドされます。ダンプ解析ツールは、ダンプファイルを読み込んで解析するためにvmlinuxにデバッグシンボルが必要です。

ダンプキャプチャカーネルの設定オプション（アーキテクチャに依存しない）¶

  1. 「プロセッサタイプと機能」で「カーネルクラッシュダンプサポート」を有効にしてください。

    CONFIG_CRASH_DUMP=y

  2. 「ファイルシステム」->「仮想ファイルシステム」で「/proc/vmcoreサポート」を有効にしてください。

    CONFIG_PROC_VMCORE=y

    (CONFIG_PROC_VMCOREはCONFIG_CRASH_DUMPが選択されている場合にデフォルトで設定されます。)

ダンプキャプチャカーネルの設定オプション（アーキテクチャに依存する、i386およびx86_64）¶

  1. i386では、「プロセッサタイプと機能」で「ハイメモリサポート」を有効にしてください。

    CONFIG_HIGHMEM64G=y

    または:

    CONFIG_HIGHMEM4G

  2. i386およびx86_64では、「プロセッサタイプと機能」で「対称マルチプロセッシングサポート」を無効にしてください。

    CONFIG_SMP=n

    (CONFIG_SMP=yの場合は、ダンプキャプチャカーネルをロードする際のカーネルコマンドラインにmaxcpus=1を指定してください。詳しくは「ダンプキャプチャカーネルをロードする」セクションを参照してください。)

  3. ローカルなカーネルを構築・使用する場合、『Processor type and features』（プロセッサの種類と機能）の項目で『Build a relocatable kernel』（再配置可能なカーネルの構築）のサポートを有効化してください。

    CONFIG_RELOCATABLE=y

  4. 『Physical address where the kernel is loaded』（カーネルがロードされる物理アドレス）の項目に適切な値を設定してください（『Processor type and features』の下）。この項目は『kernel crash dumps』（カーネルクラッシュダンプ）が有効になっている場合にのみ表示されます。適切な値はカーネルが再配置可能かどうかによって異なります。

    再配置可能なカーネルを使用する場合、CONFIG_PHYSICAL_START=0x100000 を設定してください。これにより、カーネルが物理アドレス1MB（0x100000）で構築されますが、カーネルが再配置可能なため、メモリ領域にロードされる物理アドレスは任意です。kexec ブートローダーは、ダンプキャプチャ用カーネルがロードされるメモリ領域にカーネルをロードします。

    それ以外の場合は、『crashkernel=Y@X』というブートパラメータで予約されたメモリ領域の開始位置を指定してください。X はダンプキャプチャ用カーネルが使用するメモリ領域の開始位置を表し、一般的には16MB（0x1000000）です。したがって、CONFIG_PHYSICAL_START=0x1000000 を設定してください。

  5. カーネルとそのモジュールをビルドしてインストールしてください。ただし、ブートローダーの構成ファイルにこのカーネルを追加しないでください。

ダンプキャプチャ用カーネルの設定オプション（アーキテクチャ依存、ppc64）¶

  1. 『Kernel』（カーネル）オプションの下で『Build a kdump crash kernel』（kdump クラッシュカーネルの構築）のサポートを有効化してください。

    CONFIG_CRASH_DUMP=y

  2. 『Build a relocatable kernel』（再配置可能なカーネルの構築）のサポートを有効化してください。

    CONFIG_RELOCATABLE=y

カーネルとそのモジュールをビルドしてインストールしてください。

ダンプキャプチャ用カーネルの設定オプション（アーキテクチャ依存、ia64）¶

  • ia64 用のダンプキャプチャ用カーネルを構築するには、上記のアーキテクチャ非依存セクションで指定されたオプション以外に特別な設定は必要ありません。つまり、システムカーネルをダンプキャプチャ用カーネルとして使用することも可能です。

    クラッシュカーネル領域は、システムカーネルが実行時に自動的に配置できます。これはベースアドレスを 0 に指定するか、指定を省略することで実現されます。

    crashkernel=256M@0

    または:

    crashkernel=256M

    開始アドレスを指定した場合、カーネルの開始アドレスは64MB単位でアライメントされます。したがって、アライメントポイントよりも下の領域は無駄になります。

ダンプキャプチャ用カーネルの設定オプション（アーキテクチャ依存、arm）¶

  • 再配置可能なカーネルを使用する場合、『Boot』（ブート）オプションの下で『AUTO_ZRELADDR』のサポートを有効化してください。

    AUTO_ZRELADDR=y

ダンプキャプチャ用カーネルの設定オプション（アーキテクチャ依存、arm64）¶

  • 非VHEシステムでは、ダンプキャプチャ用カーネルのKVM（仮想化拡張）が有効化されません（設定されていても）。これは、CPUがpanic時にEL2にリセットされないためです。

拡張されたクラッシュカーネル構文¶

「crashkernel=size[@offset]」の構文はほとんどの設定で十分ですが、まれに予約メモリがシステムRAMの値に依存するようにする必要があります。これは、マシンからメモリが削除された後に起動不能になるのを防ぐために、カーネルコマンドラインを事前に設定するディストリビューター向けの用途がほとんどです。

構文は以下の通りです：

crashkernel=<range1>:<size1>[,<range2>:<size2>,...][@offset]
range=start-[end]

例:

crashkernel=512M-2G:64M,2G-:128M

これは意味します：

  1. RAMが512M未満の場合、何も予約しない（これは「救済」のケースです）

  2. RAMサイズが512Mから2G（exclusive）の間の場合、64Mを予約します

  3. RAMサイズが2G以上の場合、128Mを予約します

システムカーネルに起動します¶

  1. ブートローダー（grub、yaboot、liloなど）の設定ファイルを必要に応じて更新します。

  2. システムカーネルを「crashkernel=Y@X」というブートパラメータで起動します。ここでYはダンプキャプチャーカーネルに予約するメモリ量を、Xはこの予約メモリの開始アドレスを指定します。例えば、crashkernel=64M@16M」は、システムカーネルにメモリを16MB（物理アドレス0x01000000）から64MB予約するように指示します。

    x86およびx86_64では、「crashkernel=64M@16M”.

    ppc64では、「crashkernel=128M@32M”.

    ia64では、 256M@256M は一般的な値で通常動作します。領域はia64で自動的に配置される場合があります（上記のダンプキャプチャーカーネルの設定オプションの注意事項を参照）。sparse memoryを使用する場合は、GRANULE境界に四捨五入する必要があります。

    s390xでは通常「crashkernel=xxM」を使用します。xxの値はkdumpシステムのメモリ使用量に依存し、生産用システムのメモリサイズには依存しません。

    armでは「crashkernel=Y@X」の使用は不要です。Xが指定されていない場合、カーネルはRAMの最初の512MB内でダンプキャプチャーカーネルイメージを自動的に配置します。

    arm64では、「crashkernel=Y[@X]」を使用します。注意として、カーネルの開始アドレスXが明示的に指定された場合、2MiB（0x200000）にアライメントする必要があります。

ダンプキャプチャーカーネルをロードします¶

システムカーネルに起動した後、ダンプキャプチャーカーネルをロードする必要があります。

アーキテクチャとイメージの種類（再配置可能か否か）に応じて、未圧縮のvmlinuxまたは圧縮されたbzImage/vmlinuzのダンプキャプチャーカーネルをロードできます。以下に要約します。

i386およびx86_64の場合：

  • カーネルが再配置可能でない場合、vmlinuxを使用します。

  • カーネルが再配置可能な場合、bzImage/vmlinuzを使用します。

ppc64の場合：

  • vmlinuxを使用します

ia64の場合：

  • vmlinuxまたはvmlinuz.gzを使用します

s390xの場合：

  • imageまたはbzImageを使用します

armの場合：

  • zImageを使用します

arm64の場合：

  • vmlinuxまたはImageを使用します

未圧縮のvmlinuxイメージを使用する場合は、ダンプキャプチャーカーネルをロードするには次のコマンドを使用します：

kexec -p <dump-capture-kernel-vmlinux-image> \
--initrd=<initrd-for-dump-capture-kernel> --args-linux \
--append="root=<root-dev> <arch-specific-options>"

bzImage/vmlinuzを圧縮して使用している場合、ダンプキャプチャーカーネルをロードするには次のコマンドを使用してください:

kexec -p <dump-capture-kernel-bzImage> \
--initrd=<initrd-for-dump-capture-kernel> \
--append="root=<root-dev> <arch-specific-options>"

zImageを圧縮して使用している場合、ダンプキャプチャーカーネルをロードするには次のコマンドを使用してください:

kexec --type zImage -p <dump-capture-kernel-bzImage> \
--initrd=<initrd-for-dump-capture-kernel> \
--dtb=<dtb-for-dump-capture-kernel> \
--append="root=<root-dev> <arch-specific-options>"

圧縮されていないImageを使用している場合、ダンプキャプチャーカーネルをロードするには次のコマンドを使用してください:

kexec -p <dump-capture-kernel-Image> \
--initrd=<initrd-for-dump-capture-kernel> \
--append="root=<root-dev> <arch-specific-options>"

ia64では–args-linuxを指定する必要はありません。このオプションはこのアーキテクチャでは無効（no-op）となる予定ですが、現時点では指定しないでください

ダンプキャプチャーカーネルをロードする際のアーキテクチャ固有のコマンドラインオプションです。

i386、x86_64およびia64の場合:

「1 irqpoll maxcpus=1 reset_devices」

ppc64の場合：

「1 maxcpus=1 noirqdistrib reset_devices」

s390xの場合：

「1 maxcpus=1 cgroup_disable=memory」

armの場合：

「1 maxcpus=1 reset_devices」

arm64の場合：

「1 maxcpus=1 reset_devices」

ダンプキャプチャーカーネルをロードする際の注意点:

  • デフォルトではELFヘッダーはELF64形式で保存され、4GBを超えるメモリを持つシステムをサポートしています。i386ではkexecが物理メモリサイズが4GBを超えていないか自動的に確認し、そうでない場合はELF32を使用します。したがって、非PAEシステムでは常にELF32が使用されます。

    –elf32-core-headersオプションを使用するとELF32ヘッダーの生成を強制できます。これは現在GDBが32ビットシステムでELF64ヘッダーを持つvmcoreファイルを開けないため必要です。

  • 「irqpoll」ブートパラメータは、ダンプキャプチャーカーネルでのドライバ初期化失敗を共有割込みによるものから軽減します。

  • mountコマンドの出力で使用されるルートデバイス名に対応する形式で<root-dev>を指定してください。

  • ブートパラメータ「1」はネットワーク接続なしでダンプキャプチャーカーネルをシングルユーザーモードで起動します。ネットワーク接続が必要な場合は「3」を使用してください。

  • 通常、ダンプをキャプチャするためにSMPカーネルを起動する必要はありません。したがって、UPのダンプキャプチャーカーネルを構築するか、ダンプキャプチャーカーネルをロードする際にmaxcpus=1オプションを指定するのが一般的です。ただし、maxcpusは常に動作しますが、現在のアーキテクチャがサポートする場合、nr_cpusに置き換えることでメモリを節約できます（例: x86）。

  • マルチスレッドプログラム（例: makedumpfileの並列ダンプ機能）をダンプキャプチャーカーネルで使用する場合は、マルチCPUサポートを有効にしてください。そうでない場合、マルチスレッドプログラムのパフォーマンスが大幅に低下する可能性があります。マルチCPUサポートを有効にするには、SMPのダンプキャプチャーカーネルを起動し、maxcpus/nr_cpus、disable_cpu_apicid=[X]オプションを指定してください。

  • s390xでは、kdumpモードは2種類あります。ELFヘッダーがelfcorehdr=というカーネルパラメータで指定されている場合、kdumpカーネルは他のアーキテクチャと同様にそのヘッダーを使用します。elfcorehdr=パラメータが指定されていない場合、s390xのkdumpカーネルは動的にヘッダーを作成します。この2番目のモードの利点は、CPUやメモリホットプラグ時にkexec_load()でkdumpを再ロードする必要がないことです。

  • 多くのデバイスが接続されているs390xシステムでは、kdumpカーネルに"cio_ignore"というカーネルパラメータを使用することを推奨します。これにより、kdumpに関係のないデバイスのためのカーネルメモリの割り当てを防ぐことができます。SCSI/FCPデバイスを使用するシステムにも同様に適用されます。その場合、"allow_lun_scan" zfcpモジュールパラメータをゼロに設定した後、FCPデバイスをオンラインに設定してください。

カーネルパニック¶

以前に説明したようにdump-captureカーネルを正常にロードした後、システムがクラッシュをトリガーすると、システムはdump-captureカーネルに再起動します。トリガーポイントは以下の場所にあります panic()、die()、die_nmi()およびsysrqハンドラ（ALT-SysRq-c）です。

以下の条件でクラッシュトリガーが実行されます：

ハードロックアップが検出され、"NMI watchdog"が構成されている場合、システムはdump-captureカーネルに起動します（die_nmi()）。

die()が呼び出され、pidが0または1のスレッドであるか、または割込みコンテキスト内でdie()が呼び出された場合、またはdie()が呼び出され、panic_on_oopsが設定されている場合、システムはdump-captureカーネルに起動します。

powerpcシステムでは、ソフトリセットが生成されると、すべてのCPUがdie()を呼び出し、システムはdump-captureカーネルに起動します。

テスト目的でクラッシュをトリガーするには、"ALT-SysRq-c"、"echo c > /proc/sysrq-trigger"を使用するか、モジュールを書き込むことでpanicを強制できます。

ダンプファイルの出力¶

dump-captureカーネルが起動した後、以下のコマンドでダンプファイルを出力してください：

cp /proc/vmcore <dump-file>

解析¶

ダンプイメージを解析する前に、安定したカーネルに再起動してください。

コピーした/proc/vmcoreのダンプファイルを用いて、GDBで制限された解析が可能です。debug vmlinuxを-gオプションでビルドし、以下のコマンドを実行してください：

gdb vmlinux <dump-file>

プロセッサ0上のタスクのスタックトレース、レジスタ表示、メモリ表示は正常に動作します。

注意：GDBはx86で生成されたELF64形式のコアファイルを解析できません。最大4GBのメモリを持つシステムでは、dumpカーネルの–elf32-core-headersオプションを使用してELF32形式のヘッダーを生成できます。

また、Crashツールを使用してKdump形式のダンプファイルを解析することもできます。Crashツールは以下のURLから入手可能です：

https://github.com/crash-utility/crash

WARN()でKdumpをトリガーする¶

panic_on_warnというカーネルパラメータは、すべてのWARN()パスで呼び出されます。 panic() すべてのWARN()パスで呼び出されます。これにより、呼び出し時にkdumpが発生します。 panic() 呼び出し時にkdumpが発生します。ユーザーが実行時にもこの動作を指定したい場合、/proc/sys/kernel/panic_on_warnを1に設定することで同じ挙動を実現できます。

add_taint()でKdumpをトリガーする¶

panic_on_taintというカーネルパラメータは、ビットマスクの設定値がビットフラグの設定と一致する場合に条件付きで呼び出します。 panic() 内部から add_taint() このビットマスクで設定された値が、ビットフラグの設定と一致する場合に呼び出されます。 add_taint()これにより、呼び出し時にkdumpが発生します。 add_taint()->panic() 呼び出し時にkdumpが発生します。

define bttnobp
        set $tasks_off=((size_t)&((struct task_struct *)0)->tasks)
        set $pid_off=((size_t)&((struct task_struct *)0)->thread_group.next)
        set $init_t=&init_task
        set $next_t=(((char *)($init_t->tasks).next) - $tasks_off)
        set var $stacksize = sizeof(union thread_union)
        while ($next_t != $init_t)
                set $next_t=(struct task_struct *)$next_t
                printf "\npid %d; comm %s:\n", $next_t.pid, $next_t.comm
                printf "===================\n"
                set var $stackp = $next_t.thread.sp
                set var $stack_top = ($stackp & ~($stacksize - 1)) + $stacksize

                while ($stackp < $stack_top)
                        if (*($stackp) > _stext && *($stackp) < _sinittext)
                                info symbol *($stackp)
                        end
                        set $stackp += 4
                end
                set $next_th=(((char *)$next_t->thread_group.next) - $pid_off)
                while ($next_th != $next_t)
                        set $next_th=(struct task_struct *)$next_th
                        printf "\npid %d; comm %s:\n", $next_t.pid, $next_t.comm
                        printf "===================\n"
                        set var $stackp = $next_t.thread.sp
                        set var $stack_top = ($stackp & ~($stacksize - 1)) + stacksize

                        while ($stackp < $stack_top)
                                if (*($stackp) > _stext && *($stackp) < _sinittext)
                                        info symbol *($stackp)
                                end
                                set $stackp += 4
                        end
                        set $next_th=(((char *)$next_th->thread_group.next) - $pid_off)
                end
                set $next_t=(char *)($next_t->tasks.next) - $tasks_off
        end
end
document bttnobp
        dump all thread stack traces on a kernel compiled with !CONFIG_FRAME_POINTER
end

define btthreadstack
        set var $pid_task = $arg0

        printf "\npid %d; comm %s:\n", $pid_task.pid, $pid_task.comm
        printf "task struct: "
        print $pid_task
        printf "===================\n"
        set var $stackp = $pid_task.thread.sp
        set var $stacksize = sizeof(union thread_union)
        set var $stack_top = ($stackp & ~($stacksize - 1)) + $stacksize
        set var $stack_bot = ($stackp & ~($stacksize - 1))

        set $stackp = *((unsigned long *) $stackp)
        while (($stackp < $stack_top) && ($stackp > $stack_bot))
                set var $addr = *(((unsigned long *) $stackp) + 1)
                info symbol $addr
                set $stackp = *((unsigned long *) $stackp)
        end
end
document btthreadstack
         dump a thread stack using the given task structure pointer
end

define btpid

define dump_record
        set var $desc = $arg0
        set var $info = $arg1
        if ($argc > 2)
                set var $prev_flags = $arg2
        else
                set var $prev_flags = 0
        end

        set var $prefix = 1
        set var $newline = 1

        set var $begin = $desc->text_blk_lpos.begin % (1U << prb->text_data_ring.size_bits)
        set var $next = $desc->text_blk_lpos.next % (1U << prb->text_data_ring.size_bits)

        # handle data-less record
        if ($begin & 1)
                set var $text_len = 0
                set var $log = ""
        else
                # handle wrapping data block
                if ($begin > $next)
                        set var $begin = 0
                end

                # skip over descriptor id
                set var $begin = $begin + sizeof(long)

                # handle truncated message
                if ($next - $begin < $info->text_len)
                        set var $text_len = $next - $begin
                else
                        set var $text_len = $info->text_len
                end

                set var $log = &prb->text_data_ring.data[$begin]
        end

        # prev & LOG_CONT && !(info->flags & LOG_PREIX)
        if (($prev_flags & 8) && !($info->flags & 4))
                set var $prefix = 0
        end

        # info->flags & LOG_CONT
        if ($info->flags & 8)
                # (prev & LOG_CONT && !(prev & LOG_NEWLINE))
                if (($prev_flags & 8) && !($prev_flags & 2))
                        set var $prefix = 0
                end
                # (!(info->flags & LOG_NEWLINE))
                if (!($info->flags & 2))
                        set var $newline = 0
                end
        end

        if ($prefix)
                printf "[%5lu.%06lu] ", $info->ts_nsec / 1000000000, $info->ts_nsec % 1000000000
        end
        if ($text_len)
                eval "printf \"%%%d.%ds\", $log", $text_len, $text_len
        end
        if ($newline)
                printf "\n"
        end

        # handle dictionary data

        set var $dict = &$info->dev_info.subsystem[0]
        set var $dict_len = sizeof($info->dev_info.subsystem)
        if ($dict[0] != '\0')
                printf " SUBSYSTEM="
                set var $idx = 0
                while ($idx < $dict_len)
                        set var $c = $dict[$idx]
                        if ($c == '\0')
                                loop_break
                        else
                                if ($c < ' ' || $c >= 127 || $c == '\\')
                                        printf "\\x%02x", $c
                                else
                                        printf "%c", $c
                                end
                        end
                        set var $idx = $idx + 1
                end
                printf "\n"
        end

        set var $dict = &$info->dev_info.device[0]
        set var $dict_len = sizeof($info->dev_info.device)
        if ($dict[0] != '\0')
                printf " DEVICE="
                set var $idx = 0
                while ($idx < $dict_len)
                        set var $c = $dict[$idx]
                        if ($c == '\0')
                                loop_break
                        else
                                if ($c < ' ' || $c >= 127 || $c == '\\')
                                        printf "\\x%02x", $c
                                else
                                        printf "%c", $c
                                end
                        end
                        set var $idx = $idx + 1
                end
                printf "\n"
        end
end
document dump_record
        Dump a single record. The first parameter is the descriptor,
        the second parameter is the info, the third parameter is
        optional and specifies the previous record's flags, used for
        properly formatting continued lines.
end

define dmesg
        # definitions from kernel/printk/printk_ringbuffer.h
        set var $desc_committed = 1
        set var $desc_finalized = 2
        set var $desc_sv_bits = sizeof(long) * 8
        set var $desc_flags_shift = $desc_sv_bits - 2
        set var $desc_flags_mask = 3 << $desc_flags_shift
        set var $id_mask = ~$desc_flags_mask

        set var $desc_count = 1U << prb->desc_ring.count_bits
        set var $prev_flags = 0

        set var $id = prb->desc_ring.tail_id.counter
        set var $end_id = prb->desc_ring.head_id.counter

        while (1)
                set var $desc = &prb->desc_ring.descs[$id % $desc_count]
                set var $info = &prb->desc_ring.infos[$id % $desc_count]

                # skip non-committed record
                set var $state = 3 & ($desc->state_var.counter >> $desc_flags_shift)
                if ($state == $desc_committed || $state == $desc_finalized)
                        dump_record $desc $info $prev_flags
                        set var $prev_flags = $info->flags
                end

                set var $id = ($id + 1) & $id_mask
                if ($id == $end_id)
                        loop_break
                end
        end
end
document dmesg
        print the kernel ring buffer
end
