Ramoops oops/panic ロガー¶

Sergiu Iordache <sergiu@chromium.org>

更新日: 2021年2月10日

はじめに¶

Ramoops はシステムがクラッシュする前に RAM にログを書き込む oops/panic ロガーです。クラッシュ前に oops と panic を円環バッファにログとして記録します。Ramoops は再起動後にその領域の内容が生き残るよう、永続的な RAM を搭載したシステムが必要です。

Ramoops の概念¶

Ramoops は予め定義されたメモリ領域をダンプに使用します。このメモリ領域の開始位置、サイズ、タイプは以下の3つの変数で設定します:

  • mem_address 開始位置

  • mem_size サイズ。メモリサイズは2の累乗に丸められます。

  • mem_type メモリタイプを指定します（デフォルトは pgprot_writecombine）。

通常、 mem_type=0 のデフォルト値を使用します。これは pstore マッピングを pgprot_writecombine に設定するためです。 mem_type=1 を設定すると、 pgprot_noncachedを使用しようとしますが、これは一部のプラットフォームでのみ動作します。これは pstore がアトミック操作に依存しているためです。ARM では少なくとも pgprot_noncached がメモリを強く順序付けされたマッピングにしますが、強く順序付けされたメモリでのアトミック操作は実装依存であり、多くの ARM プラットフォーム（例: omaps）では動作しません。 mem_type=2 を設定すると、メモリ領域を通常のメモリとして扱います。これにより、キャッシュが有効になり、パフォーマンスが向上します。

メモリ領域は record_size のチャンク（2の累乗に丸められます）に分割され、各 kmesg ダンプは record_size の情報量を記録します。

kmsgダンプの保存対象を制限するには、 max_reason 値を設定します。これはinclude/linux/kmsg_dump.hの enum kmsg_dump_reasonで定義されています。例えば、OopsとPanicsの両方を保存するには、 max_reason を2（KMSG_DUMP_OOPS）に設定し、Panicsのみを保存するには、 max_reason を1（KMSG_DUMP_PANIC）に設定します。この値を0（KMSG_DUMP_UNDEF）に設定すると、理由フィルタリングは printk.always_kmsg_dump ブートパラメータで制御されます。未設定の場合はKMSG_DUMP_OOPS、設定されている場合はKMSG_DUMP_MAXになります。

モジュールはカウンターを使用して複数のダンプを記録しますが、再起動時にカウンターがリセットされるため、再起動後の新しいダンプは古いものに上書きされます。

Ramoops は永続メモリ領域のソフトウェア ECC 保護もサポートしています。ハードウェアリセットでマシンを再起動させる場合（例: ワッチドッグがトリガーされた場合）には特に役立ちます。このような場合、RAM が多少破損している可能性がありますが、通常は復元可能です。

パラメータの設定¶

Ramoops のパラメータを設定する方法はいくつかあります:

A. モジュールパラメータを使用します（変数名は前述の変数名と同じです）。デバッグのためには、起動時にメモリの一部を予約して、ramoops に使用する方法もあります。例えば、メモリが 128 MB を超えるマシンの場合、以下のカーネルコマンドラインで、カーネルに最初の 128 MB のメモリのみを使用し、ECC 保護された ramoops レギオンを 128 MB の境界に配置させます:

mem=128M ramoops.mem_address=0x8000000 ramoops.ecc=1

B. デバイスツリーのバインディングを使用します。詳しくは Documentation/devicetree/bindings/reserved-memory/ramoops.txt。

reserved-memory {
        #address-cells = <2>;
        #size-cells = <2>;
        ranges;

        ramoops@8f000000 {
                compatible = "ramoops";
                reg = <0 0x8f000000 0 0x100000>;
                record-size = <0x4000>;
                console-size = <0x4000>;
        };
};

C. プラットフォームデバイスを使用してプラットフォームデータを設定します。パラメータはこのプラットフォームデータを通じて設定できます。その例は以下の通りです:

#include <linux/pstore_ram.h>
[...]

static struct ramoops_platform_data ramoops_data = {
      .mem_size               = <...>,
      .mem_address            = <...>,
      .mem_type               = <...>,
      .record_size            = <...>,
      .max_reason             = <...>,
      .ecc                    = <...>,
};

static struct platform_device ramoops_dev = {
      .name = "ramoops",
      .dev = {
              .platform_data = &ramoops_data,
      },
};

[... inside a function ...]
int ret;

ret = platform_device_register(&ramoops_dev);
if (ret) {
      printk(KERN_ERR "unable to register platform device\n");
      return ret;
}

RAMメモリまたは周辺機器のメモリを指定できます。ただし、RAMを指定する場合、アーキテクチャコードの初期段階でmemblock_reserve()を呼び出してメモリを確保する必要があります。例えば:

#include <linux/memblock.h>

memblock_reserve(ramoops_data.mem_address, ramoops_data.mem_size);

データの読み取り¶

ダンプデータは pstore ファイルシステムから読み取れます。これらのファイルの形式は dmesg-ramoops-N、ここでNはメモリ内のレコード番号を表します。RAMから保存されたレコードを削除するには、対応するpstoreファイルをアンリンクするだけです。

永続的な関数トレース¶
