Unicodeのサポート¶

最終更新日: 2005-01-17, バージョン 1.4

このファイルはH. Peter Anvin <unicode@lanana.org> がLinux Assigned Names And Numbers Authority (LANANA)プロジェクトの一環として維持しています。現在のバージョンは以下のURLで確認できます:

http://www.lanana.org/docs/unicode/admin-guide/unicode.rst

はじめに¶

LinuxカーネルコードはUnicodeを使用して文字をフォントにマッピングするように再構築されました。Unicodeからフォントへのマッピングテーブルを1つダウンロードすることで、8ビット文字セットとUTF-8モードが指定されたフォントを使用するようになります。

これは8ビット文字テーブルのセマンティクスを微妙に変更します。4つの文字テーブルは現在次のようになります:

ESC ( B

GRAF_MAP

DEC VT100擬似グラフィックス

ESC ( 0

IBMPC_MAP

IBM コードページ 437

ESC ( U

ユーザー定義

ESC ( K

特に、ESC ( Uはもはや「直接フォントへ」ではなくなりました。フォントがIBMの文字セットとは完全に異なる可能性があるためです。これにより、ラテン1フォントをロードしていてもブロックグラフィックスの使用が可能になります。

これらのコードはISO 2022に似ていますが、コード自体やその使用方法はISO 2022と一致しません。Linuxでは2つの8ビットコード（G0とG1）を使用していますが、ISO 2022では4つの7ビットコード（G0-G3）があります。

Unicode標準/ISO 10646に従って、U+F000からU+F8FFの範囲がOS全体で使用するための予約領域として割り当てられています（Unicode標準ではこれを「Corporate Zone」と呼びますが、Linuxではこの表現が不正確なため、「Linux Zone」と呼んでいます）。U+F000は、1024文字または2048文字のフォントが必要な場合に直接マッピング領域を大きな2の累乗で開始できるようにするための開始点として選ばれました。これにより、U+E000からU+EFFFはEnd User Zoneとして残されます。

[v1.2]: Unicodeの範囲（U+F000からU+F7FF）は、翻訳テーブルを迂回してロードされたフォントに直接マッピングするようにハードコードされました。ユーザー定義のマップは現在、U+F000からU+F0FFにデフォルトとなり、以前の動作を模倣しています。実際にはこの範囲は短くなる可能性があります。たとえば、vgaconは256文字（U+F000..U+F0FF）または512文字（U+F000..U+F1FF）のフォントのみを処理できます。

Linux Zoneに割り当てられた実際の文字¶

さらに、Unicode 1.1.4に含まれていない以下の文字が定義されています。これらはDEC VTグラフィックスマップで使用されます。[v1.2] この使用は非推奨であり、もはや使用すべきではありません。下記を参照してください。

U+F800

DEC VTグラフィックス水平線スキャン1

U+F801

DEC VTグラフィックス水平線スキャン3

U+F803

DEC VTグラフィックス水平線スキャン7

U+F804

DEC VTグラフィックス水平線スキャン9

DEC VT220は6×10の文字マトリクスを使用しており、これらの文字はDEC VTグラフィック文字セットでなめらかな進行をしています。スキャンライン5はブロックグラフィック文字としても使用されるため、U+2500 FORMS LIGHT HORIZONTALとしてコード化されています。

[v1.3]: これらの文字はUnicode 3.2.0に公式に追加されました。追加位置はU+23BA、U+23BB、U+23BC、U+23BDです。Linuxは新しい値を使用しています。

[v1.2]: 以下の文字は、Unicodeに追加されにくいと考えられる一般的なキーボードシンボルを表しています。これは、メーカー固有のため非常に悪い設計の例です。

U+F810

キーボードシンボル フライングフラグ

U+F811

キーボードシンボル パウンドメニュー

U+F812

キーボードシンボル オープンアップル

U+F813

キーボードシンボル ソリッドアップル

クリンクン語サポート¶

1996年、Linuxは世界で初めて人工言語クリンクン語のサポートを追加しました。これはマーコックランドが『スター・トレック』テレビシリーズのために作成した言語です。このエンコーディングは後にConScript Unicode Registryによって採用され、Unicode Plane 1への採用提案（最終的に却下）されました。そのため、Linux/CSURプライベート割当としてLinuxゾーンに残っています。

このエンコーディングはクリンクン語研究所によって認可されています。詳しい情報は以下のリンクからご確認ください：

http://www.kli.org/

Linux CZの初期の文字は主にディンバツ/シンボル/フォームタイプであり、これは言語であるため、標準的なUnicodeの実装に合わせて16セル境界に配置しました。

注意

この範囲は現在ConScript Unicode Registryによって公式に管理されています。規範的な参照は以下のリンクにあります：

https://www.evertype.com/standards/csur/klingon.html

クリンクン語は26文字のアルファベットを持ち、10桁の位置価値記数法を用い、左から右へ、上から下へ書かれます。

クリンクン語アルファベットのいくつかのフォント形式が提案されていますが、シンボルのセットは一貫しており、実際の形状のみが異なるため、標準的なUnicodeの実装に従い、これらの違いはフォント変体とみなされます。

その他のフィクショナル・アーティフィシャル文字¶

クリンクンLinux Unicodeブロックの割り当て後、ジョン・カウーン <jcowan@reutershealth.com> とマイケル・エバーソン <everson@evertype.com> によってフィクショナル・アーティフィシャル文字の登録が設立されました。ConScript Unicode登録は以下のURLでアクセス可能です：

https://www.evertype.com/standards/csur/

使用される範囲はエンドユーザー・ゾーンの低域に位置するため、規範的に割り当てることはできませんが、フィクショナル文字をエンコードしたい人々は相互運用性の観点からこれらのコードを使用することをお勧めします。クリンクンについてはCSURがLinuxエンコーディングを採用しています。CSURの人々はテングワールとシルトをUnicodeプレーン1に追加するための活動を進めていますが、クリンクンのUnicodeプレーン1への追加は拒否され、上記のエンコーディングが公式に残っています。
