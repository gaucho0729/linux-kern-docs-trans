ABI非推奨シンボル¶

インターフェースをドキュメント化しています。これはまだカーネルに残っているが、今後いつか削除される予定になっているインターフェースです。

インターフェースの説明では、そのインターフェースが非推奨になった理由と、いつ削除される予定かを記載します。

/sys/bus/usb/devices/…/power/level

ファイルで定義されています sysfs-bus-usb

各USBデバイスディレクトリにはpower/levelという名前のファイルが含まれます。このファイルは、デバイスの電源レベル設定を保持しており、'on'または'auto'のいずれかです。

「on」は、デバイスがオートスリープを許可されないことを意味しますが、システムスリープ時の通常のスリープは引き続き許可されます。一方、「auto」は、ドライバの機能に応じて通常通りオートスリープとオートリザーブを実行することを意味します。

通常の使用では、デバイスは「auto」レベルに残しておくべきです。「on」レベルは管理用途に用意されています。デバイスをすぐにスリープさせたいが、I/Oリクエストに応じて再起動できるようにしたい場合は、power/autosuspendに「0」を書き込む必要があります。

適切なスリープおよび再起動ができないデバイスは「on」レベルに残しておくべきです。USB仕様ではデバイスがスリープ/再起動をサポートすることを要求していますが、多くのデバイスはこれをサポートしていません。実際には多くのデバイスがサポートしていないため、デフォルトではUSBコアはすべての非ハブデバイスを「on」レベルに初期化します。一部のドライバは、バインドされる際にこの設定を変更する場合があります。

このファイルは非推奨となり、2010年以降削除されます。代わりにpower/controlファイルを使用してください。これはまったく同じ動作を行います。

/sys/class以下に存在するシンボル¶

/sys/class/dax/

ファイルで定義されています sysfs-class-dax

デバイスDAXはファイルシステムDAX（CONFIG_FS_DAX）のデバイス中心の対応です。ファイルシステムを介さずにメモリ範囲を割り当ててマッピングできます。デバイスDAXは厳密で正確かつ予測可能な動作をします。具体的にはこのインターフェース:

  1. 設定時に行サイズ（pte、pmd、またはpud）に基づいて故障粒度を保証します。

  2. サポートされる故障シナリオを厳密に制限することで、決定的な動作を強制します。

以下の /sys/class/dax/ インターフェースはシステム内のすべてのdevice-daxインスタンスを列挙します。このABIは2020年後に廃止され、DAXバスインターフェース /sys/bus/dax/ に置き換えられます。device-daxインスタンスは /sys/bus/dax/devices/ 以下に存在します。

/sys/class/gpio/

ファイルで定義されています sysfs-gpio

Kconfigオプションとして、個々のGPIO信号はユーザー空間からアクセスできます。GPIOはユーザー空間に公開されるのは明示的な「export」操作によるものです。あるGPIOがカーネルコードで使用されていない場合、ユーザー空間がエクスポート（後でアンエクスポート）できます。カーネルコードは完全または部分的なアクセスを許可するためにエクスポートできます。

GPIOは、カーネル内で使用される整数0..INT_MAXの範囲で識別されます。詳しくはDocumentation/admin-guide/gpioを参照してください。

/sys/class/gpio
    /export ... asks the kernel to export a GPIO to userspace
    /unexport ... to return a GPIO to the kernel
    /gpioN ... for each exported GPIO #N OR
    /<LINE-NAME> ... for a properly named GPIO line
        /value ... always readable, writes fail for input GPIOs
        /direction ... r/w as: in, out (default low); write: high, low
        /edge ... r/w as: none, falling, rising, both
    /gpiochipN ... for each gpiochip; #N is its first GPIO
        /base ... (r/o) same as N
        /label ... (r/o) descriptive, not necessarily unique
        /ngpio ... (r/o) number of GPIOs; numbered N to N + (ngpio - 1)

このABIは非推奨となっており、2020年以降に削除されます。代替としてGPIOキャラクターデバイスが導入されています。

/sys/fs 以下のシンボル¶

/sys/fs/selinux/checkreqprot

ファイルで定義されています sysfs-selinux-checkreqprot

selinuxfs の "checkreqprot" ノードは、SELinux がユーザー空間が mmap/mprotect 呼び出しで要求した保護をチェックするように設定できます。これは legacy ユーザースペースや READ_IMPLIES_EXEC パーソナリティフラグへの互換性メカニズムでしたが、checkreqprot を 1 に設定すると、ポリシーアUTHORIZATION なしに実行可能マッピングを許可するためセキュリティが低下します。Linux v4.4 以降ではブート時に checkreqprot のデフォルト値が 0（実際の保護をチェック）に変更され、Android および Linux ディストリビューションでは初期化時に "0" を明示的に書き込みます。checkreqprot の設定を 1 にすることは 2021 年 6 月までサポートされ、その時点でカーネルは内部で checkreqprot を常に使用しなくなり、mmap/mprotect 呼び出しで実際に適用される保護を常にチェックします。checkreqprot selinuxfs ノードは後方互換性のために残るが、"0" の書き込みは無視され、"1" の書き込みは拒否されます。 /sys/fs/selinux/checkreqprot 初期化中に "0" を書き込むことで、checkreqprot の設定を 1 にすることは 2021 年 6 月までサポートされ、その時点でカーネルは内部で checkreqprot を常に使用しなくなり、mmap/mprotect 呼び出しで実際に適用される保護を常にチェックします。checkreqprot selinuxfs ノードは後方互換性のために残るが、"0" の書き込みは無視され、"1" の書き込みは拒否されます。

/sys/fs/selinux/disable

ファイルで定義されています sysfs-selinux-disable

selinuxfs の "disable" ノードは、ポリシーがカーネルにロードされる前に実行時において SELinux を無効にできます。このメカニズムで無効にすると、システムの再起動まで SELinux は無効のままです。

SELinux の無効化の推奨方法は "selinux=0" ブートパラメータですが、"disable" ノードは、カーネルコマンドラインを簡単に変更できない原始的なブートローダーを持つシステムで SELinux を無効にしやすくするため作成されました。残念ながら、SELinux を実行時において無効にできると、"__ro_after_init" フィーチャーを使用してカーネルの LSM ハックをセキュアにすることが困難になります。

幸いにも、SELinuxのランタイム無効化が必要な状況はもうないようです。デフォルトのKconfig設定ではこのselinuxfsノードが無効化されており、主要なディストリビューションの中ではフェデラタがのみランタイムでのSELinux無効化をサポートしています。フェデラタは現在、selinuxfsの「disable」ノードを削除中のため、このコードをカーネルから徐々に削除するプロセスを開始する予定です。

さらに詳しい情報は /sys/fs/selinux/disable CONFIG_SECURITY_SELINUX_DISABLE Kconfigオプションの下にあります。
