sysfs を通じて CPU テポロジー情報がエクスポートされる仕組み¶

sysfs経由でCPUトポロジー情報をエクスポートします。項目（属性）は、いくつかのアーキテクチャの/proc/cpuinfo出力と類似しています。これらは/sys/devices/system/cpu/cpuX/topology/に存在します。

physical_package_id:

cpuXの物理パッケージID。通常は物理ソケット番号に該当しますが、実際の値はアーキテクチャとプラットフォームに依存します。

die_id:

cpuXのCPUダイID。通常はハードウェアプラットフォームの識別子（カーネルのものではなく）です。実際の値はアーキテクチャとプラットフォームに依存します。

core_id:

cpuXのCPUコアID。通常はハードウェアプラットフォームの識別子（カーネルのものではなく）です。実際の値はアーキテクチャとプラットフォームに依存します。

book_id:

cpuXのブックID。通常はハードウェアプラットフォームの識別子（カーネルのものではなく）です。実際の値はアーキテクチャとプラットフォームに依存します。

drawer_id:

cpuXのドロワID。通常はハードウェアプラットフォームの識別子（カーネルのものではなく）です。実際の値はアーキテクチャとプラットフォームに依存します。

core_cpus:

同じコア内のCPUの内部カーネルマップ。（非推奨名: “thread_siblings”）

core_cpus_list:

同じコア内のCPUのヒューマンリーダブルなリスト。（非推奨名: “thread_siblings_list”）；

package_cpus:

同じphysical_package_idを共有するCPUの内部カーネルマップ。（非推奨名: “core_siblings”）

package_cpus_list:

同じphysical_package_idを共有するCPUのヒューマンリーダブルなリスト。（非推奨名: “core_siblings_list”）

die_cpus:

同じダイ内のCPUの内部カーネルマップ。

die_cpus_list:

同じダイ内のCPUのヒューマンリーダブルなリスト。

book_siblings:

同じbook_id内のcpuXのハードウェアスレッドの内部カーネルマップ。

book_siblings_list:

同じbook_id内のcpuXのハードウェアスレッドのヒューマンリーダブルなリスト。

drawer_siblings:

同じdrawer_id内のcpuXのハードウェアスレッドの内部カーネルマップ。

drawer_siblings_list:

同じdrawer_id内のcpuXのハードウェアスレッドのヒューマンリーダブルなリスト。

アーキテクチャに依存しない、drivers/base/topology.c、これらの属性をエクスポートします。ただし、bookおよびdrawer関連のsysfsファイルは、CONFIG_SCHED_BOOKおよびCONFIG_SCHED_DRAWERが選択されている場合にのみ作成されます。

CONFIG_SCHED_BOOKおよびCONFIG_SCHED_DRAWERは現在、s390でしか使用されておらず、CPUおよびキャッシュの階層を反映しています。

アーキテクチャがこの機能をサポートするには、include/asm-XXX/topology.hでこれらのマクロのいくつかを定義する必要があります。

#define topology_physical_package_id(cpu)
#define topology_die_id(cpu)
#define topology_core_id(cpu)
#define topology_book_id(cpu)
#define topology_drawer_id(cpu)
#define topology_sibling_cpumask(cpu)
#define topology_core_cpumask(cpu)
#define topology_die_cpumask(cpu)
#define topology_book_cpumask(cpu)
#define topology_drawer_cpumask(cpu)

の型 **_id macros はintです。の型 **_cpumask macros 通常のRCU読み込み側クリティカルセクションは、条件付きでスリープロックを取得することが許容されます（例として (const) struct cpumask *. 後者は適切な **_siblings sysfs属性（topology_sibling_cpumask()はthread_siblingsに対応しています）。

すべてのアーキテクチャで一貫性を保つため、include/linux/topology.hはinclude/asm-XXX/topology.hで定義されていない上記のマクロに対してデフォルトの定義を提供しています:

  1. topology_physical_package_id: -1

  2. topology_die_id: -1

  3. topology_core_id: 0

  4. topology_sibling_cpumask: 与えられたCPUのみ

  5. topology_core_cpumask: 与えられたCPUのみ

  6. topology_die_cpumask: 与えられたCPUのみ

booksをサポートしていないアーキテクチャ（CONFIG_SCHED_BOOK）では、topology_book_id()とtopology_book_cpumask()のデフォルト定義はありません。drawersをサポートしていないアーキテクチャ（CONFIG_SCHED_DRAWER）では、topology_drawer_id()とtopology_drawer_cpumask()のデフォルト定義もありません。

さらに、CPUのトポロジ情報は/sys/devices/system/cpu配下で提供され、以下のファイルを含みます。出力の内部ソースは括弧（「[]」）内に記載されています。

kernel_max:

カーネル構成で許可される最大のCPUインデックス。[NR_CPUS-1]

offline:

HOTPLUGGEDでオフにされたCPU（cpu-hotplug.txtを参照）またはカーネル構成で許可されるCPU数を超えたCPU。[~cpu_online_mask + cpus >= NR_CPUS]

online:

オンライン状態のCPUでスケジューリングが行われるCPU。[cpu_online_mask]

possible:

リソースが割り当てられており、存在する場合にオンライン状態にできるCPU。[cpu_possible_mask]

present:

システムに存在すると識別されたCPU。[cpu_present_mask]

上記の出力形式はcpulist_parse()と互換性があります（<linux/cpumask.h>を参照）。以下にいくつかの例を示します。

この例ではシステムに64つのCPUがありますが、cpus 32-63はkernel_maxを越えており、NR_CPUS構成オプションが32のため最大0..31まで制限されています。また、CPU 2と4-31はオンライン状態ではありませんが、どちらもpresentおよびpossibleであるためオンライン状態にできます:

kernel_max: 31
   offline: 2,4-31,32-63
    online: 0-1,3
  possible: 0-31
   present: 0-31

この例ではNR_CPUS構成オプションが128ですが、カーネルはpossible_cpus=144で起動しています。システムに4つのCPUがあり、cpu2が手動でオフラインにされ（オンライン状態にすることができる唯一のCPUです）:

kernel_max: 127
   offline: 2,4-127,128-143
    online: 0-1,3
  possible: 0-127
   present: 0-3

possible_cpus=NUM カーネル起動パラメータおよび各種cpumaskに関する詳細情報についてはcpu-hotplug.txtを参照してください。
