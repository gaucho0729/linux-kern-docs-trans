me ディスクレスシステム（たとえばXターミナルやプリンターサーバーなど）を使用するには、ルートファイルシステムがディスク以外のデバイス上に存在する必要があります。これはinitramfs（参照：Ramfs, rootfs and initramfs）やramdisk（参照：Ramfs, rootfs and initramfs）やNFS経由でマウントされたファイルシステムを使用する場合です。以下のテキストではNFSをルートファイルシステムとして使用する方法について説明します。このテキストの後半では、「クライアント」とはディスクレスシステムを、「サーバー」とはNFSサーバーを指します。Ramfs, rootfs and initramfs 初期 RAM ディスク (initrd) の使用) or a filesystem mounted via NFS. The following text describes on how to use NFS for the root filesystem. For the rest of this text ‘client’ means the diskless system, and ‘server’ means the NFS server.

nfsroot機能を有効にする¶

nfsrootを使用するには、カーネルの構成時にNFSクライアントサポートを内蔵として選択する必要があります。この選択が完了した後、nfsrootオプションが表示されるようになりますので、これをもって選択してください。

ネットワークオプションで、カーネルレベルの自動設定を有効にし、サポートする自動設定の種類も選択できます。DHCP、BOOTP、RARPのすべてを有効にすることは安全です。

カーネル コマンドライン¶

カーネルがブートローダー（以下参照）によってロードされた際には、どのルートfsデバイスを使用するかを指定する必要があります。nfsrootの場合は、サーバーの場所と、サーバー上のルートとしてマウントするディレクトリ名を指定する必要があります。以下にカーネル コマンドラインパラメータの例を示します：

root=/dev/nfs

これは擬似NFSデバイスを有効にするために必要です。注意点として、これは実際のデバイスではなく、カーネルにNFSを使用するように伝えるためのシンノミクスです。

nfsroot=[<server-ip>:]<root-dir>[,<nfs-options>]

もし nfsroot’パラメータがコマンドラインに指定されていない場合、デフォルトの `”/tftpboot/%s”`` が使用されます。

<server-ip> NFSサーバーのIPアドレスを指定します。

デフォルトのアドレスはipパラメータ（以下参照）によって決定されます。このパラメータは、IP自動設定とNFSに異なるサーバーを使用する場合に有効です。

<root-dir> サーバー上のルートとしてマウントするディレクトリ名です。

文字列に「%s」トークンがある場合、クライアントのIPアドレスのASCII表現に置き換えられます。

<nfs-options> 標準的なNFSオプションです。すべてのオプションはコンマで区切ります。

以下のデフォルトが使用されます：

port            = as given by server portmap daemon
rsize           = 4096
wsize           = 4096
timeo           = 7
retrans         = 3
acregmin        = 3
acregmax        = 60
acdirmin        = 30
acdirmax        = 60
flags           = hard, nointr, noposix, cto, ac
ip=<client-ip>:<server-ip>:<gw-ip>:<netmask>:<hostname>:<device>:<autoconf>:<dns0-ip>:<dns1-ip>:<ntp0-ip>

このパラメータは、カーネルがデバイスのIPアドレスをどのように設定するか、およびIPルーティングテーブルをどのように構成するかを指定します。元々はnfsaddrsと呼ばれていましたが、ブート時のIP設定はNFSに依存しないため、名前をipに変更し、古い名前を互換性のためのエイリアスとして残しました。

このパラメータがカーネルのコマンドラインに存在しない場合、すべてのフィールドは空とみなされ、以下に記載するデフォルト値が適用されます。一般的には、カーネルがオートコンフィギュレーションを使用してすべてを設定しようとするということです。

<autoconf>パラメータは、ipパラメータの値として単独で使用されることがあります（':'記号は含めません）。値が「ip=off」または「ip=none」の場合、オートコンフィギュレーションは行われません。それ以外の場合はオートコンフィギュレーションが行われます。最も一般的な使用方法は「ip=dhcp」です。

<client-ip> クライアントのIPアドレス。

デフォルト: オートコンフィギュレーションを使用して決定されます。

<server-ip> NFSサーバーのIPアドレス。

RARPを使用してクライアントアドレスを決定し、このパラメータが空でない場合、指定されたサーバーからのみ応答が受け入れられます。

NFSルート専用のパラメータです。つまり、NFSルートが動作していない場合、このパラメータが存在しなくてもオートコンフィギュレーションはトリガーされません。

値は/proc/net/pnpに「bootserver 」というプレフィックスを付けてエクスポートされます（以下参照）。

デフォルト: オートコンフィギュレーションサーバーのアドレスが使用されます。

<gw-ip> サーバーが異なるサブネットにある場合のゲートウェイのIPアドレス。

デフォルト: オートコンフィギュレーションを使用して決定されます。

<netmask> ローカルネットワークインターフェースのネットマスク。

指定されていない場合、クライアントのIPアドレスからクラスフルアドレッシングを前提にネットマスクが導出されます。

デフォルト: オートコンフィギュレーションを使用して決定されます。

<hostname> クライアントの名前。

「.」が含まれている場合、最初の「.」前の文字列をクライアントのホスト名として使用し、後の部分をNISドメイン名として使用します。オートコンフィギュレーションによって提供される可能性がありますが、存在しなくてもオートコンフィギュレーションをトリガーしません。指定された場合、DHCPを使用する際には、ユーザーが指定したホスト名（およびNISドメイン名が存在する場合）がDHCPリクエストに含まれます。これにより、クライアント用のDNSレコードが作成または更新される可能性があります。

デフォルト: クライアントのIPアドレスをASCII表記で使用します。

<device> 使用するネットワークデバイスの名前。

デフォルト: ホストに1つのデバイスしかない場合、そのデバイスが使用されます。それ以外の場合、オートコンフィギュレーションを使用してデバイスが決定されます。これは、すべてのデバイスからオートコンフィギュレーションリクエストを送信し、最初に応答を受け取ったデバイスを使用する方法です。

<autoconf> オートコンフィギュレーションに使用する方法。

複数の自動設定プロトコルを指定するオプションの場合、すべてのプロトコルを使用してリクエストが送信され、最初に応答するプロトコルが使用されます。

このオプションの値に関係なく、カーネルにコンパイルされている自動設定プロトコルのみが使用されます：

off or none: don't use autoconfiguration
              (do static IP assignment instead)
on or any:   use any protocol available in the kernel
             (default)
dhcp:        use DHCP
bootp:       use BOOTP
rarp:        use RARP
both:        use both BOOTP and RARP but not DHCP
             (old option kept for backwards compatibility)

dhcp を使用する場合、クライアント識別子は「ip=dhcp,client-id-type,client-id-value」という形式で使用できます。

デフォルト: 任意

<dns0-ip> プライマリネームサーバーのIPアドレス。

値は「nameserver 」というプレフィックスを付けて /proc/net/pnp にエクスポートされます（以下参照）。

デフォルト: 自動設定を使用しない場合は「なし」、自動設定を使用する場合は自動的に決定されます。

<dns1-ip> セカンダリネームサーバーのIPアドレス。

<dns0-ip> を参照してください。

<ntp0-ip> ネットワーク時刻プロトコル（NTP）サーバーのIPアドレス。

値は /proc/net/ipconfig/ntp_servers にエクスポートされますが、それ以外では使用されません（以下参照）。

デフォルト: 自動設定を使用しない場合は「なし」、自動設定を使用する場合は自動的に決定されます。

設定（手動または自動を問わず）が完了した後、以下の形式で2つのファイルが作成されます。設定後の値が空の場合、該当する行は省略されます：

  • /proc/net/pnp:

    #PROTO: <DHCP|BOOTP|RARP|MANUAL>（設定方法に応じて） domain <dns-domain>（自動設定の場合、DNSドメイン） nameserver <dns0-ip>（プライマリネームサーバーのIP） nameserver <dns1-ip>（セカンダリネームサーバーのIP） nameserver <dns2-ip>（テリチアリネームサーバーのIP） bootserver <server-ip>（NFSサーバーのIP）

  • /proc/net/ipconfig/ntp_servers:

    <ntp0-ip>（NTPサーバーのIP） <ntp1-ip>（NTPサーバーのIP） <ntp2-ip>（NTPサーバーのIP）

<dns-domain> および <dns2-ip>（/proc/net/pnp に記載）および <ntp1-ip> および <ntp2-ip>（/proc/net/ipconfig/ntp_servers に記載）は自動設定時に要求されます。これらは「ip=」というカーネルコマンドラインパラメータの一部として指定することはできません。

DNSリゾルバーが「domain」および「nameserver」オプションを認識するため、NFSルートファイルシステムを使用するシステムでは、/etc/resolv.conf がしばしば /proc/net/pnp にシンボリックリンクされています。

カーネルは、発見したNTPサーバーとシステム時間を同期しません。これはユーザー空間のプロセスの責任です（例：initrd/initramfs スクリプトで、/proc/net/ipconfig/ntp_servers に記載されたIPアドレスをNTPクライアントに渡して、実際のルートファイルシステムをNFSでマウントする前に実行する）。

nfsrootdebug

このパラメータは、起動時にカーネルログにデバッグメッセージを出力させ、管理者が正しいNFSマウントオプション、サーバーのアドレス、およびルートパスがNFSクライアントに正しく渡されていることを確認できるようにします。

rdinit=<実行可能ファイル>

システム初期化を開始するプログラムを含むファイルを指定するには、管理者はこのコマンドラインパラメータを使用できます。このパラメータのデフォルト値は「/init」です。指定されたファイルが存在し、カーネルがそれを実行できる場合、'nfsroot='を含むルートファイルシステム関連のカーネルコマンドラインパラメータは無視されます。

ブートローダー¶

カーネルをメモリに読み込むためには、さまざまな手段が利用可能です。これらは、さまざまな機能が利用可能であることに依存します：

  • syslinuxを使用してフロッピーディスクからブートする

    カーネルをビルドする際、syslinuxを使用したブート用フロッピーディスクを作成する簡単な方法は、zimageおよびbzimageイメージを使用したzdiskまたはbzdiskのmakeターゲットを使用することです。これらのターゲットは、FDARGSパラメータを受け入れ、カーネルのコマンドラインを設定するために使用できます。

    e.g:

    make bzdisk FDARGS="root=/dev/nfs"

    このコマンドを実行するユーザーは、フロッピードライブデバイスである/dev/fd0へのアクセスが必要です

    syslinuxに関する詳細情報、および事前にビルドされたカーネル用のブートディスクの作成方法については、以下を参照してください https://syslinux.zytor.com/

    注意

    以前は、ddを使用してカーネルを直接フロッピーディスクに書き込み、rdevを使用してブートデバイスを設定し、結果として得られたフロッピーディスクでブートする方法が可能でした。しかし、Linuxはこのブート方法をもはやサポートしていません。

  • isolinuxを使用してCD-ROMからブートする

    カーネルをビルドする際、isolinuxを使用したブート可能なCD-ROMを作成する簡単な方法は、bzimageイメージを使用したisoimageターゲットを使用することです。zdiskおよびbzdiskと同様に、このターゲットはFDARGSパラメータを受け入れ、カーネルのコマンドラインを設定するために使用できます。

    e.g:

    make isoimage FDARGS="root=/dev/nfs"

    結果として得られるisoイメージはarch/<ARCH>/boot/image.isoです。これはcdrecordなどのさまざまなツールを使用してCD-ROMに書き込むことができます。

    e.g:

    cdrecord dev=ATAPI:1,0,0 arch/x86/boot/image.iso

    isolinuxに関する詳細情報、および事前にビルドされたカーネル用のブートディスクの作成方法については、以下を参照してください https://syslinux.zytor.com/

  • LILOを使用する

    LILOを使用する場合、LILO構成ファイル内の'append='ディレクティブを使用して必要なすべてのコマンドラインパラメータを指定できます。

    ただし、'root='ディレクティブを使用するには、仮想のルートデバイスを作成する必要があります。LILOを実行後にこのデバイスは削除できます。

    e.g:

    mknod /dev/boot255 c 0 255

    LILOの設定方法については、そのドキュメンテーションを参照してください。

  • GRUBを使用する

    GRUBを使用する場合、カーネルパラメータはカーネル指定の後に単純に追加されます：kernel <kernel> <parameters>

  • loadlinを使用する

    loadlinは、ローカルのハードディスクをrootとしてマウントせずに、DOSコマンドプロンプトからLinuxを起動するために使用できます。このドキュメントの著者によるテストは十分に行われていませんが、一般的にはLILOの設定と同様にカーネルコマンドラインを設定することができると考えられます。

    追加の情報については、loadlinのドキュメンテーションを参照してください。

  • ブートROMを使用する

    これはおそらくディスクレスクライアントを起動する最も洗練された方法です。ブートROMを使用すると、カーネルはTFTPプロトコルを介してロードされます。このドキュメントの著者らは、ネットワーク経由でLinuxをブートするための商用ブートROMの存在を認識していません。ただし、netboot-nfsとetherbootという2つの無料のブートROMの実装があり、どちらもsunsite.unc.eduで入手可能で、どちらもディスクレスLinuxクライアントを起動するために必要なすべての機能を含んでいます。

  • pxelinuxを使用する

    pxelinuxは、多くの現代のネットワークカードに搭載されているPXEブートローダーを使用してLinuxを起動するために使用できます。

    pxelinuxを使用する場合、カーネルイメージは「kernel </tftpboot以下の相対パス>」で指定されます。nfsrootパラメータは、「append」行にそれらを追加することでカーネルに渡されます。pxelinuxと併用するシリアルコンソールの使用は一般的です、参照してください Linux シリアルコンソール 詳しくは

    isolinuxに関する詳細情報、および事前にビルドされたカーネル用のブートディスクの作成方法については、以下を参照してください https://syslinux.zytor.com/
