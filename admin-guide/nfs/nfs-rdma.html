NFS/RDMAの設定¶

著者

NetApp と Open Grid Computing (2008年5月29日)

警告

このドキュメントはおそらく非推奨です。

概要¶

このドキュメントは、Linux NFS/RDMA クライアントおよびサーバー用ソフトウェアのインストールと設定方法について説明しています。

NFS/RDMA クライアントは最初に Linux 2.6.24 で含まれ、NFS/RDMA サーバーは次のリリースである Linux 2.6.25 で含まれました。

テストでは、多くのワークロードにおいて優れたパフォーマンス結果（クライアントCPU使用量を最小限に抑えながら10Gbitのワイヤーバンド幅）を取得しており、コードはConnectathonテストスイートを通過し、InfinibandおよびiWARP RDMAアダプターの両方で動作します。

サポートを受ける方法¶

行き詰まった場合は、 nfs-rdma-devel@lists.sourceforge.net メールリストで質問を投稿できます。

インストール¶

これらの手順は、NFS/RDMA を使用するマシンを構築するためのステップバイステップのガイドです。

  • RDMAデバイスをインストールする

    drivers/infiniband/hw でサポートされるすべてのデバイスが使用可能です。

    テストは、MellanoxベースのIBカード、Ammasso AMS1100 iWARPアダプター、Chelsio cxgb3 iWARPアダプターを用いて行われました。

  • Linuxディストリビューションとツールをインストールする

    NFS/RDMA クライアントおよびサーバーを含む最初のカーネルリリースは、Linux 2.6.25 です。そのため、このリリース以降のLinuxカーネルと互換性のあるディストリビューションをインストールする必要があります。

    このドキュメントで説明する手順は、Red Hat の Fedora プロジェクトから提供されるディストリビューションとテストされています（http://fedora.redhat.com/).

  • クライアントに nfs-utils-1.1.2 またはそれ以降をインストールする

    mount.nfs コマンドを nfs-utils-1.1.2 またはそれ以降を使用することで NFS/RDMA マウントポイントを取得できます（nfs-utils-1.1.1 は NFS/RDMA マウントをサポートする最初の nfs-utils バージョンですが、いくつかの理由により nfs-utils-1.1.2 またはそれ以降の使用を推奨します）。使用している mount.nfs のバージョンを確認するには、以下を実行してください：

    $ /sbin/mount.nfs -V

    バージョンが 1.1.2 未満であるか、コマンドが存在しない場合は、最新版の nfs-utils をインストールする必要があります。

    最新のパッケージをダウンロードするには、以下から: https://www.kernel.org/pub/linux/utils/nfs

    パッケージを解凍し、インストール手順に従ってください。

    idmapper および gssd 実行ファイルが不要な場合（NFS/RDMA 有効なマウントコマンドを生成するためにこれらは必要ありません）、configure を実行する際これらの機能を無効にしてインストールプロセスを簡略化できます：

    $ ./configure --disable-gss --disable-nfsv4

    nfs-utils をビルドするには、tcp_wrappers パッケージをインストールしておく必要があります。詳細については、パッケージの README および INSTALL ファイルを参照してください。

    nfs-utilsパッケージをビルドした後、utils/mountディレクトリにmount.nfsというバイナリが存在します。このバイナリはNFS v2、v3、またはv4のマウントを開始するために使用できます。v4のマウントを開始するには、mount.nfs4という名前のバイナリを呼び出す必要があります。標準的な方法は、mount.nfs4というシンボリックリンクをmount.nfsに作成することです。

    このmount.nfsバイナリは以下の通り/sbin/mount.nfsにインストールする必要があります：

    $ sudo cp utils/mount/mount.nfs /sbin/mount.nfs

    この場所では、システムのmountコマンドがNFSマウントを自動的に呼び出します。

    注意

    mount.nfsおよびnfs-utils-1.1.2またはそれ以降は、NFSクライアントマシンのみに必要です。サーバーにはこの特定のバージョンのnfs-utilsは必要ありません。さらに、クライアントにはnfs-utils-1.1.2のmount.nfsコマンドのみが必要です。

  • NFS/RDMAをサポートするLinuxカーネルをインストールする

    NFS/RDMAクライアントとサーバーは、メインラインLinuxカーネルバージョン2.6.25以降に含まれています。この他にもさまざまなLinuxカーネルバージョンは以下の場所で入手できます： https://www.kernel.org/pub/linux/kernel/

    ソースコードをダウンロードし、適切な場所に配置してください。

  • RDMAスタックを構成する

    カーネル構成がRDMAサポートを有効にされていることを確認してください。デバイスドライバ -> InfiniBandサポートの下で、カーネル構成をInfiniBandサポートに更新してください（注意：オプション名は誤解を招く可能性があります。すべてのRDMAデバイス（IB、iWARPなど）のためにInfiniBandサポートを有効にする必要があります）。

    適切なIB HCAサポート（mlx4、mthca、ehca、ipathなど）またはiWARPアダプタサポート（amso、cxgb3など）を有効にしてください。

    InfiniBandを使用している場合は、IP-over-InfiniBandサポートを有効にしてください。

  • NFSクライアントとサーバーを構成する

    カーネル構成にもNFSファイルシステムサポートおよび/またはNFSサーバーサポートが有効になっている必要があります。これらと他のNFS関連の構成オプションは、ファイルシステム -> ネットワークファイルシステムの下で見つかります。

  • ビルド、インストール、再起動

    NFSとRDMAが有効になっている場合、NFS/RDMAコードは自動的に有効になります。NFS/RDMAクライアントとサーバーはSUNRPC_XPRT_RDMAという隠しの構成オプションで設定され、これはSUNRPCとINFINIBANDに依存します。SUNRPC_XPRT_RDMAの値は以下の通りです：

    1. SUNRPCまたはINFINIBANDがNの場合、NFS/RDMAクライアントとサーバーは構築されません

    2. SUNRPCとINFINIBANDがどちらもMまたはY（少なくとも1つがM）の場合、NFS/RDMAクライアントとサーバーはモジュールとして構築されます

    3. SUNRPCとINFINIBANDがどちらもYの場合、NFS/RDMAクライアントとサーバーはカーネルに組み込まれます

    したがって、上記の手順を実行し、NFSとRDMAを有効にしていない場合、NFS/RDMAクライアントとサーバーは構築されます。

    新しいカーネルを構築し、インストールして起動します。

RDMAおよびNFSの設定を確認します¶

NFS/RDMAソフトウェアを設定する前に、新しいカーネルをテストして正しく動作しているか確認することをお勧めします。特に、RDMAスタックが予期通り動作しているか、標準的なTCP/IPおよび/またはUDP/IPを介したNFSが正常に動作しているかを検証することをお勧めします。

  • RDMAの設定を確認します

    RDMAコンポーネントをモジュールとして構築した場合、この時点でロードしてください。たとえば、Mellanox Tavor/Sinai/Arbelカードを使用している場合:

    $ modprobe ib_mthca
$ modprobe ib_ipoib

    InfiniBandを使用している場合、ネットワーク上にサブネットマネージャー（SM）が動作していることを確認してください。IBスイッチに埋め込まれたSMがある場合はそれを使用してください。それ以外の場合は、OpenSMなどのSMをネットワーク内の端末ノードのいずれかで実行する必要があります。

    ネットワーク上にSMが動作している場合、以下の出力が表示されます:

    $ cat /sys/class/infiniband/driverX/ports/1/state
4: ACTIVE

    ここでdriverXはmthca0、ipath5、ehca3などです。

    InfiniBandソフトウェアスタックをさらにテストするには、IPoIBを使用します（これは2つのIBホストhost1とhost2が存在することを前提としています）:

    host1$ ip link set dev ib0 up
host1$ ip address add dev ib0 a.b.c.x
host2$ ip link set dev ib0 up
host2$ ip address add dev ib0 a.b.c.y
host1$ ping a.b.c.y
host2$ ping a.b.c.x

    他のデバイスタイプについては、適切な手順に従ってください。

  • NFSの設定を確認します

    上記で有効化したNFSコンポーネント（クライアントおよび/またはサーバー）を標準的なイーサネット経由でTCP/IPまたはUDP/IPを介して機能をテストしてください。

NFS/RDMAの設定¶

NFS/RDMAを構築するには、クライアントとして動作する機器とサーバーとして動作する機器の2台のマシンを使用することをお勧めします。

一括設定:¶

  • サーバー側のシステムで、/etc/exportsファイルを設定し、NFS/RDMAサーバーを起動します。

    以下の形式のエクスポートエントリがテスト済みです:

    /vol0   192.168.0.47(fsid=0,rw,async,insecure,no_root_squash)
/vol0   192.168.0.0/255.255.255.0(fsid=0,rw,async,insecure,no_root_squash)

    IPアドレスは、InfiniBand HCAのクライアントのIPoIBアドレスまたはRNICのクライアントのiWARPアドレスです。

    注意

    「insecure」オプションを使用する必要があります。なぜなら、NFS/RDMAクライアントは予約ポートを使用しないからです。

各マシンが起動するたびに:¶

  • RDMAドライバをロードし、設定します

    Mellanoxアダプターを使用するInfiniBandの場合:

    $ modprobe ib_mthca
$ modprobe ib_ipoib
$ ip li set dev ib0 up
$ ip addr add dev ib0 a.b.c.d

    注意

    クライアントとサーバーには一意のアドレスを使用してください！

  • NFSサーバーを起動します

    NFS/RDMAサーバーがモジュールとして構築されている場合（カーネル構成のCONFIG_SUNRPC_XPRT_RDMA=m）、RDMAトランスポートモジュールをロードします:

    $ modprobe svcrdma

    サーバーがどのように構築されたかに関係なく（モジュールまたは組み込み）、サーバーを起動します:

    $ /etc/init.d/nfs start

    または

    $ service nfs start

    サーバーにRDMAトランスポートを監聽するように指示します:

    $ echo rdma 20049 > /proc/fs/nfsd/portlist

  • クライアント側のシステムで

    NFS/RDMAクライアントがモジュールとして構築されている場合（カーネル構成のCONFIG_SUNRPC_XPRT_RDMA=m）、RDMAクライアントモジュールをロードします:

    $ modprobe xprtrdma.ko

    クライアントがどのように構築されたかに関係なく（モジュールまたは組み込み）、以下のコマンドを使用してNFS/RDMAサーバーをマウントします:

    $ mount -o rdma,port=20049 <IPoIB-server-name-or-address>:/<export> /mnt

    マウントがRDMAを使用しているか確認するには、「cat /proc/mounts」を実行し、指定されたマウントの「proto」フィールドを確認してください。

    おめでとうございます！NFS/RDMAを使用しています！
