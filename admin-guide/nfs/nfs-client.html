NFS クライアント¶

NFSクライアント¶

NFSバージョン2プロトコルは、RFC1094（1989年3月）で最初に記載されました。その後、NFSv3がRFC1813（1995年6月）で、NFSv4がRFC3530（2003年4月）でそれぞれ記載されました。

LinuxのNFSクライアントは現在、上記のすべてのバージョンをサポートしており、NFSv4のマイナーバージョン1のサポート追加作業が進行中です。

このドキュメントの目的は、システム管理者が設定可能なNFSクライアントの特異な機能について情報を提供することです。

nfs4_unique_idパラメータ¶

NFSv4では、クライアントがサーバーに自己を識別するためのユニークな文字列を必要とします。ファイルオープンやロック状態は、この識別子と関連付けられ、信頼性の高いNFSv4状態回復と透過的な状態移行をサポートするため、この識別子文字列はクライアントの再起動時に変更してはなりません。

他の介入がなければ、Linuxクライアントはローカルシステムのノード名を含む文字列を使用します。しかし、システム管理者はノード名が完全に限定されていないことや、クライアントシステムのライフタイム内に変化しないことを保証するための手間を取らないことがよくあります。ノード名には他の管理上の要件があり、nfs_client_id4文字列としての動作がうまくいかない場合があります。

nfs.nfs4_unique_idブートパラメータは、NFSクライアントがサーバーに自己を識別する際にシステムのノード名ではなく、代わりに使用するユニークな文字列を指定します。したがって、システムのノード名がユニークでない場合や変化した場合でも、nfs.nfs4_unique_idは変化せず、他のクライアントとの衝突を防ぎ、NFS再起動時の状態回復や透過的な状態移行時の状態喪失を防ぎます。

nfs4_unique_id文字列は通常UUIDですが、すべてのNFSクライアントでユニークとされるものであれば何でもかまいません。クライアントシステムがインストールされる際、システムのルートファイルシステムがインストール時にラベルに新しいUUIDを取得するのと同じように、nfs4_unique_id文字列はインストール時に選択されるべきです。

この文字列はクライアントのライフタイムを通じて固定しておくべきです。クライアントが正常にシャットダウンし、すべての未解決のNFSv4状態が期限切れになるように注意を払えば、変更は安全です。

この文字列はNFSクライアントのgrub.confに保存することも、PXEなどのネットワークブートファシリティを通じて提供することもできます。また、nfs.koモジュールパラメータとして指定することも可能です。ただし、コンテナで実行されているNFSクライアントにはサポートされていません。

DNS解決器¶

NFSv4は、特殊な「fs_locations」属性を介して、NFSクライアントを別のサーバーに移動したデータに参照させる機能を提供します。詳しくは RFC3530 第6節: ファイルシステムの移行と複製 および NFSv4における参照の実装ガイド.

fs_locations情報は、IPアドレスとパス、またはDNSホスト名とパスのいずれかの形式をとることができます。後者はNFSクライアントが新しいボリュームをマウントするためにはDNS検索が必要であり、そのためアップコールを介してユーザー空間がこのサービスを提供する必要があります。

ユーザーが通常の/var/lib/nfs/rpc_pipefsに'rpc_pipefs'ファイルシステムをマウントしていると仮定すると、アップコールは以下の手順で行われます:

  1. プロセスがdns_resolveキャッシュを確認し、有効なエントリが含まれているかを確認します。含まれていればそのエントリを返して終了します。

  2. 有効なエントリが存在しない場合、ヘルパースクリプト '/sbin/nfs_cache_getent'（'nfs.cache_getent' カーネル起動パラメータで変更可能）が実行され、2つの引数として「キャッシュ名「dns_resolve」および解決するホスト名が渡されます。

  3. 対応するIPアドレスを検索した後、ヘルパースクリプトは次のテキスト形式でrpc_pipefs擬似ファイル '/var/lib/nfs/rpc_pipefs/cache/dns_resolve/channel' に結果を書き込みます:

    「<IPアドレス> <ホスト名> <TTL>n」

    ここで<IPアドレス>は通常のIPv4（123.456.78.90）またはIPv6（ffee:ddcc:bbaa:9988:7766:5544:3322:1100, ffee::1100, …）形式で、<ホスト名>はヘルパースクリプトの第2引数と同一で、<TTL>はこのキャッシュエントリの「有効時間」（秒単位）です。

    注意

    <IPアドレス>が無効な場合（例：文字列「0」）、負のエントリが作成され、カーネルがホスト名に有効なDNS変換がないと扱います。

基本的なサンプル /sbin/nfs_cache_getent¶

#!/bin/bash
#
ttl=600
#
cut=/usr/bin/cut
getent=/usr/bin/getent
rpc_pipefs=/var/lib/nfs/rpc_pipefs
#
die()
{
    echo "Usage: $0 cache_name entry_name"
    exit 1
}

[ $# -lt 2 ] && die
cachename="$1"
cache_path=${rpc_pipefs}/cache/${cachename}/channel

case "${cachename}" in
    dns_resolve)
        name="$2"
        result="$(${getent} hosts ${name} | ${cut} -f1 -d\ )"
        [ -z "${result}" ] && result="0"
        ;;
    *)
        die
        ;;
esac
echo "${result} ${name} ${ttl}" >${cache_path}
