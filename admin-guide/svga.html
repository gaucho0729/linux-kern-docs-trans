ビデオモード選択サポート 2.13¶

著作権

© 1995–1999 Martin Mares, <mj@ucw.cz>

はじめに¶

この小さなドキュメントは、「ビデオモード選択」機能について説明しています。この機能により、ビデオBIOSがサポートするさまざまな特殊なビデオモードを使用できるようになります。BIOSの使用により、選択は起動時（カーネルの解圧が始まる前）に限定され、UEFI、kexecなどではなく、BIOSファームウェアで起動する80X86マシンでのみ動作します。

注意

焦っている人向けの短い紹介: 初めて使用するときは vga=ask を使用し、ビデオモードのプロンプトで入力してください。 scan ビデオモードのプロンプトで、使用したいモードを選択し、そのモードID（4桁の16進数）を覚えておき、その後 vga パラメータをこの数値（10進数に変換して）に設定してください。

使用するビデオモードは、カーネルパラメータで指定できます。このパラメータは、カーネルMakefile（SVGA_MODE=… 行）で指定するか、LILO（または使用しているその他のブートローダー）の「vga=…」オプションで指定するか、標準のLinuxユーティリティパッケージに含まれる「xrandr」ユーティリティで指定できます。このパラメータの使用可能な値は以下の通りです:

NORMAL_VGA - Standard 80x25 mode available on all display adapters.

EXTENDED_VGA - Standard 8-pixel font mode: 80x43 on EGA, 80x50 on VGA.

ASK_VGA - Display a video mode menu upon startup (see below).

0..35 - Menu item number (when you have used the menu to view the list of
   modes available on your adapter, you can specify the menu item you want
   to use). 0..9 correspond to "0".."9", 10..35 to "a".."z". Warning: the
   mode list displayed may vary as the kernel version changes, because the
   modes are listed in a "first detected -- first displayed" manner. It's
   better to use absolute mode numbers instead.

0x.... - Hexadecimal video mode ID (also displayed on the menu, see below
   for exact meaning of the ID). Warning: LILO doesn't support
   hexadecimal numbers -- you have to convert it to decimal manually.

メニュー¶

ASK_VGA モードは、起動時にカーネルがビデオモードのメニューを提示します。このとき、「RETURNキーを押すと利用可能なビデオモードが表示され、SPACEキーを押すか30秒待つと標準の80x25モードで起動します」というメッセージが表示されます。RETURNキーを押すとメニューに進み、SPACEキーを押すか30秒待つと標準の80x25モードで起動します。

メニューは以下のようになります:

Video adapter: <name-of-detected-video-adapter>
Mode:    COLSxROWS:
0  0F00  80x25
1  0F01  80x50
2  0F02  80x43
3  0F03  80x26
....
Enter mode number or ``scan``: <flashing-cursor-here>

<検出されたビデオアダプターの名前> はLinuxが検出したビデオアダプターを示します。これは一般的なアダプター名（MDA、CGA、HGC、EGA、VGA、VESA VGA [VESA準拠BIOSを持つVGA]）か、チップセット名（例: Trident）です。チップセットの直接検出はデフォルトで無効になっており、PCの設計が絶対に非現実的であるため信頼性がありません。

「0 0F00 80x25」は、メニュー項目（項目は「0」から「9」、「a」から「z」まで番号付け）の最初の項目がID=0x0f00の80x25モードを示します（モードIDの説明については次のセクションを参照してください）。

<カーソルがここに点滅しています> は、設定したい項目番号またはモードIDを入力し、RETURNキーを押すことを促しています。コンピュータが「未知のモードID」というエラーを表示する場合、そのモードを設定できないことを示しています。また、RETURNキーのみを押すと現在のモードが維持されます。

モード一覧には通常、いくつかの基本モードと一部のVESAモードが含まれています。チップセットが検出された場合、チップセット固有のモードも表示されることがあります（これらのモードは、同じカードに異なるBIOSが搭載されることがよくあり、モード番号はVGA BIOSに依存するため、あなたのマシンでは表示されない場合や使用できない場合があります）。

メニューに表示されるモードは一部の順序で並べられています：リストは標準モード（80x25および80x50）から始まり、その後「特殊」モード（80x28および80x43）、ローカルモード（ローカルモード機能が有効になっている場合）、VESAモード、最後に自動検出されたアダプター用のSVGAモードが続きます。

モード一覧が満足できない場合は（たとえば、あなたのカードがより多くの機能を備えていると考えている場合）、アイテム番号／モードIDの代わりに「scan」を入力してください。プログラムはBIOSにすべての可能なビデオモード番号を尋ね、それらをテストします。画面はしばらくフラッシュし、モニター内から不思議な音が聞こえ、その後、あなたのBIOSがサポートするすべての一致したビデオモードが表示されます（さらにいくつか ghost modes）。モニターが破損する可能性があると心配する場合は、この機能は使用しないでください。

スキャン後、モードの並び順はやや異なります：自動検出されたSVGAモードはまったく表示されず、スキャンによって明らかになった scan がすべてのVESAモードの前に表示されます。

モードID¶

ビデオ関連の複雑さのため、ここでのビデオモードIDもやや複雑です。ビデオモードIDは16ビットの数値で、通常は16進数表記（「0x」で始まる）で表されます。モードIDを知っている場合は、メニューに表示されていなくても、直接そのモードIDを入力して設定できます。

ID番号は以下の領域に分類されます：

0x0000 to 0x00ff - menu item references. 0x0000 is the first item. Don't use
     outside the menu as this can change from boot to boot (especially if you
     have used the ``scan`` feature).

0x0100 to 0x017f - standard BIOS modes. The ID is a BIOS video mode number
     (as presented to INT 10, function 00) increased by 0x0100.

0x0200 to 0x08ff - VESA BIOS modes. The ID is a VESA mode ID increased by
     0x0100. All VESA modes should be autodetected and shown on the menu.

0x0900 to 0x09ff - Video7 special modes. Set by calling INT 0x10, AX=0x6f05.
     (Usually 940=80x43, 941=132x25, 942=132x44, 943=80x60, 944=100x60,
     945=132x28 for the standard Video7 BIOS)

0x0f00 to 0x0fff - special modes (they are set by various tricks -- usually
     by modifying one of the standard modes). Currently available:
     0x0f00  standard 80x25, don't reset mode if already set (=FFFF)
     0x0f01  standard with 8-point font: 80x43 on EGA, 80x50 on VGA
     0x0f02  VGA 80x43 (VGA switched to 350 scanlines with a 8-point font)
     0x0f03  VGA 80x28 (standard VGA scans, but 14-point font)
     0x0f04  leave current video mode
     0x0f05  VGA 80x30 (480 scans, 16-point font)
     0x0f06  VGA 80x34 (480 scans, 14-point font)
     0x0f07  VGA 80x60 (480 scans, 8-point font)
     0x0f08  Graphics hack (see the VIDEO_GFX_HACK paragraph below)

0x1000 to 0x7fff - modes specified by resolution. The code has a "0xRRCC"
     form where RR is a number of rows and CC is a number of columns.
     E.g., 0x1950 corresponds to a 80x25 mode, 0x2b84 to 132x43 etc.
     This is the only fully portable way to refer to a non-standard mode,
     but it relies on the mode being found and displayed on the menu
     (remember that mode scanning is not done automatically).

0xff00 to 0xffff - aliases for backward compatibility:
     0xffff  equivalent to 0x0f00 (standard 80x25)
     0xfffe  equivalent to 0x0f01 (EGA 80x43 or VGA 80x50)

モードIDに0x8000を加えると、プログラムはモードパラメータに基づいて垂直表示タイミングを再計算しようとします。これは、特定のVGA BIOSのいくつかの邪魔なバグ（通常はS3チップセット搭載カードや古いCirrus Logic BIOSで使用される）を解消するために使用できます（主に表示終了時の余分なライン）。

オプション¶

arch/x86/boot/*のビルドオプションは、カーネルkconfigユーティリティとカーネル.configファイルによって選択されます。

VIDEO_GFX_HACK - 特殊ドライバーで後で使用するグラフィックモードの設定に特化した特殊なハックを含みます。これにより、_任意_のBIOSモード（グラフィックモードを含む）を設定でき、BIOS変数からではなく、特定のテキスト画面解像度を強制的に設定できます。専門知識があると確信しない限り使用しないでください。この設定を有効にするには、モード番号0x0f08を使用してください（上記の「モードID」セクションを参照）

まだ動作しない場合？¶

モード検出が正常に動作しない場合（例：モード一覧が正しくない、またはマシンがメニューを表示する代わりに停止するなど）、『オプション』項目に記載されているいくつかの設定オプションをオフに試してください。それでも失敗する場合は、カーネルパラメータを直接指定してビデオモードを設定した状態でカーネルを使用できます。

いずれの場合も、正確に何が起こるか、および設定の切り替えが不具合の挙動にどのように影響するかを記載したバグレポートを送ってください。

LinuxをM$-DOSから起動する場合、DOSツールを用いてビデオモードを設定することもできます。この場合、Linuxに0x0f04モード（「現在の設定を維持」）を指定する必要があります。なぜなら、非標準モードを使用しない場合でも、Linuxが自動的に80x25モードに切り替わるからです。

拡張モードを設定した場合、ディスプレイの下部にすでにスクロールされたテキストが含まれる余分な行がある場合は、VGA BIOSに「垂直表示終了設定の誤り」と呼ばれる一般的なビデオBIOSのバグが含まれています。モードIDに0x8000を加えることで問題が修正される可能性があります。残念ながら、この修正は手動で行う必要があります。自動検出メカニズムは利用できません。

履歴¶

1.0 (??-11月-95)

すべての古い設定.SでサポートされていたアダプターおよびCirrus Logic 54XXをサポートする最初のバージョン。一部の1.3.4?カーネルに含まれていたが、一部のマシンでの不安定性のため削除されました。

2.0 (28-1月-96)

再構築。Cirrus Logic 64XXのサポートを追加し、ほぼすべてがカスタマイズ可能となり、VESAサポートはより安定し、明示的なモード番号の指定が可能となり、「スキャン」機能が実装されました。

2.1 (30-1月-96)

VESAモードを0x200-0x3ffに移動。解像度に基づいたモード選択をサポート。いくつかのバグを修正。VESAモードはSVGA自動検出で提供されるモードよりも信頼性が高いことから、リストの前に表示。CLGD自動検出がより正確に動作。起動時に80x25がアクティブである必要がない。スキャンの修正。80x43（任意のVGA）を追加。コードの整理。

2.2 (1日-2月-96)

EGA 80x43の修正。VESAを0x200-0x4ffに拡張（非標準02XX VESAモードが動作）。表示終了のバグ回避処理をサポート。特殊モードを再番号化し、「再計算」フラグの追加を可能に。0xffffおよび0xfffeは実際のIDではなく、代替IDとして扱われるようになった。モード変更中にスクリーンの内容を保持。

2.3 (15-3月-96)

1.3.74カーネルとの互換性を向上。

2.4 (18-3月-96)

Hans Lermenによるパッチを追加し、一部のブートローダーでのメモリ上書き問題を修正。メモリ管理をこれらの変更に合わせて再構築。残念ながら、スクリーンの内容保持は一部のブートローダーでのみ動作するようになった。Tseng 132x60モードを追加。

2.5 (19-3月-96)

2.4で導入されたVESAモードスキャンのバグを修正しました。

2.6 (25-Mar-96)

一部のVESA BIOSエラーが報告されない – いくつかの破損したVESAコードを持つカード（例: ATI VGA）でのエラー報告を修正しました。

2.7 (09-Apr-96)

  • 0x100から0x7ffまでのすべてのVESAモードを受容しました。一部のカードでは非常に不思議なモード番号が使用されるためです。

  • Realtek VGAモードを追加しました（Gonzalo Tornaria氏の協力により）。

  • ハードウェアテストの順序をやや変更しました。ROMの内容に基づくテストを最初に行います。

  • 特殊なVideo7モードスイッチング機能のサポートを追加しました（Tom Vander Aa氏の協力により）。

  • 480スキャンラインモードを追加しました（特にノートブック向けに有用です。オリジナルバージョンは、hhanemaa、cs、ruuにより作成され、Jeff Chua氏により修正され、私により再構築されました）。 hhanemaa@cs.ruu.nl、Jeff Chua氏により修正され、私により再構築されました）。

  • スクリーンの保存/復元を修正しました。

2.8 (14-Apr-96)

  • 前のリリースはCONFIG_VIDEO_SVGAなしではコンパイルできませんでした。

  • モードスキャン時のテキストモードの認識を改善しました。

2.9 (12-May-96)

  • 0x80から0xffまでのVESAモードを無視しました（さらにVESA BIOSのバグがあります！）

2.10(11-Nov-96)

  • すべてをオプションにしました。

  • CONFIG_VIDEO_400_HACKスイッチを追加しました。

  • CONFIG_VIDEO_GFX_HACKスイッチを追加しました。

  • コードの整理を行いました。

2.11(03-May-97)

  • もう一度の整理を行いました。今度はドキュメンテーションも含めます。

  • SVGAアダプターの直接テストはデフォルトで無効にしました、 scan プロンプトラインで明示的に提供します。

  • 新しいプローブ機能の追加方法を説明するドキュメンテーションセクションを削除しました。ここではすべてのハードウェアプローブを廃止しようとしています。

2.12(25-May-98)

VESAフレームバッファグラフィックスのサポートを追加しました。

2.13(14-May-99)

小さなドキュメンテーションの修正を行いました。
