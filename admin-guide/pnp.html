概要¶

Plug and Playは、レガシーやその他の設定不可なデバイスの検出およびリソース設定を行うための手段を提供します。Linux Plug and Playレイヤーは、互換性のあるドライバーにこれらのサービスを提供します。

ユーザーインターフェース¶

Linux Plug and Playユーザーインターフェースは、Linux Plug and Playをサポートしていないレガシーおよびユーザーレベルのドライバー用にPnPデバイスをアクティベートする手段を提供します。このユーザーインターフェースはsysfsに統合されています。

標準のsysfsファイルに加えて、各デバイスのディレクトリに以下のファイルが作成されます： - id - サポートするEISA IDの一覧を表示 - options - 可能なリソース構成を表示 - resources - 現在割り当てられているリソースを表示し、リソースの変更を許可

デバイスのアクティベート¶

# echo "auto" > resources

これにより、自動リソース構成システムが呼び出され、デバイスがアクティベートされます

手動でのデバイスアクティベート¶

# echo "manual <depnum> <mode>" > resources

<depnum> - the configuration number
<mode> - static or dynamic
         static = for next boot
         dynamic = now

デバイスの無効化¶

# echo "disable" > resources

例:

フロッピーディスクコントローラーをアクティベートする必要があるとします。

  1. 正しいディレクトリに移動します。私の場合は/drivers/bus/pnp/devices/00:0f:です

    # cd /driver/bus/pnp/devices/00:0f
# cat name
PC standard floppy disk controller

  2. デバイスがすでにアクティブかどうかを確認します：

    # cat resources
DISABLED

  • 文字列「DISABLED」が表示されます。これはデバイスがアクティブでないことを意味します。

  1. デバイスの可能な構成を確認します（オプション）：

    # cat options
Dependent: 01 - Priority acceptable
    port 0x3f0-0x3f0, align 0x7, size 0x6, 16-bit address decoding
    port 0x3f7-0x3f7, align 0x0, size 0x1, 16-bit address decoding
    irq 6
    dma 2 8-bit compatible
Dependent: 02 - Priority acceptable
    port 0x370-0x370, align 0x7, size 0x6, 16-bit address decoding
    port 0x377-0x377, align 0x0, size 0x1, 16-bit address decoding
    irq 6
    dma 2 8-bit compatible

  2. 今すぐデバイスをアクティベートします：

    # echo "auto" > resources

  3. 最後にデバイスがアクティブかどうかを確認します：

    # cat resources
io 0x3f0-0x3f5
io 0x3f7-0x3f7
irq 6
dma 2

また、一連のカーネルパラメータもあります：

pnp_reserve_irq=irq1[,irq2] ....
pnp_reserve_dma=dma1[,dma2] ....
pnp_reserve_io=io1,size1[,io2,size2] ....
pnp_reserve_mem=mem1,size1[,mem2,size2] ....

統合Plug and Playレイヤー¶

すべてのPlug and Playドライバー、プロトコル、サービスは、Plug and Playレイヤーと呼ばれる中央の場所で統合されます。このレイヤーはPnPドライバーとPnPプロトコル間での情報交換を担当し、自動的に適切なプロトコルにコマンドを転送します。これにより、PnPドライバーの作成が大幅に簡単になります。

Plug and Playレイヤーから利用可能な機能は以下の通りです：

pnp_get_protocol

使用回数を1つ増やす

pnp_put_protocol

使用回数を1つ減らす

pnp_register_protocol

新しいPnPプロトコルを登録するための関数です

pnp_unregister_protocol

PnPプロトコルをPlug and Playレイヤーから削除するための関数です

pnp_register_driver

PnPドライバーをPlug and Playレイヤーに追加します

ドライバーモデル統合を含み、成功時は0を返し、失敗時は負のエラーナンバーを返します。.add()メソッドの呼び出し回数をカウントする必要がある場合は、それを把握できます

pnp_unregister_driver

PnPドライバーをPlug and Playレイヤーから削除します

Plug and Playプロトコル¶

このセクションには、PNPプロトコル開発者向けの情報が含まれています。

現在、コンピューティング界で利用可能なプロトコルは以下の通りです：

  • PNPBIOS:

    シリアルポートやパラレルポートなどのシステムデバイスに使用されます。

  • ISAPNP:

    ISAバスにおけるPNPサポートを提供します

  • ACPI:

    その多くの用途の中でも、ACPIはシステムレベルのデバイスに関する情報を提供します。

これはPNPBIOSの置き換えとして設計されています。現在はLinux Plug and Playでサポートされていませんが、近い将来に導入される予定です。

Linux PnPプロトコルの要件：1. プロトコルはEISA IDを使用しなければなりません 2. プロトコルはデバイスの現在の設定をPNPレイヤーに通知しなければなりません

  • リソースの設定機能は任意ですが、推奨されます。

以下のPNPプロトコル関連の関数があります：

pnp_add_device

この関数を使用してPNPデバイスをPNPレイヤーに追加します

pnp_dev構造体にすべての必要値が設定されている場合にのみこの関数を呼び出してください

pnp_init_device

この関数を使用してPNP構造体を初期化します

pnp_remove_device

この関数を使用してPlug and Playレイヤーからデバイスを削除します。デバイスがまだ使用中である場合、この関数は失敗します。自動的にデバイスと関連する構造体に使用されていたメモリを解放します

pnp_add_id

指定されたデバイスのサポートされるIDリストにEISA IDを追加します

さらに詳しい情報が必要な場合は、プロトコルのソースコードを参照してください。例えば/drivers/pnp/pnpbios/core.c

Linux Plug and Playドライバ¶

このセクションには、Linux PnPドライバ開発者向けの情報が含まれています。

新しい方法¶

  1. まずサポートされるEISA IDSの一覧を作成してください

    例:

    static const struct pnp_id pnp_dev_table[] = {
        /* Standard LPT Printer Port */
        {.id = "PNP0400", .driver_data = 0},
        /* ECP Printer Port */
        {.id = "PNP0401", .driver_data = 0},
        {.id = ""}
};

    関数部分（最後の4文字）においては、文字'X'をワイルドカードとして使用できます。

    例:

    /* Unknown PnP modems */
{       "PNPCXXX",              UNKNOWN_DEV     },

    サポートされるPNPカードIDは任意で定義できます。例：

    static const struct pnp_id pnp_card_table[] = {
        {       "ANYDEVS",              0       },
        {       "",                     0       }
};

  2. プローブおよびリムーブ関数は任意で定義できます。ドライバが既にリソースを検出する信頼できる方法（例：parport_pcドライバ）を持っている場合は、これらの関数を定義しない方がよいかもしれません。

    例:

    static int
serial_pnp_probe(struct pnp_dev * dev, const struct pnp_id *card_id, const
                struct pnp_id *dev_id)
{
. . .

    例:

    static void serial_pnp_remove(struct pnp_dev * dev)
{
. . .

    さらに詳しい情報が必要な場合は、/drivers/serial/8250_pnp.cを参照してください。

  3. ドライバ構造体を作成してください

    例:

    static struct pnp_driver serial_pnp_driver = {
        .name           = "serial",
        .card_id_table  = pnp_card_table,
        .id_table       = pnp_dev_table,
        .probe          = serial_pnp_probe,
        .remove         = serial_pnp_remove,
};

    • 名前とid_tableはNULLであってはなりません。

  4. ドライバを登録してください

    例:

    static int __init serial8250_pnp_init(void)
{
        return pnp_register_driver(&serial_pnp_driver);
}

古い方法¶

ISAPNPドライバの変換を容易にするため、一連の互換性関数が作成されました。これらは一時的な解決策としてのみ使用するべきです。

以下がその関数です：

struct pnp_dev *pnp_find_dev(struct pnp_card *card,
                             unsigned short vendor,
                             unsigned short function,
                             struct pnp_dev *from)
