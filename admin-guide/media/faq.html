4.3. よくある質問¶

注意

  1. デジタルTVでは、1つの物理チャネル内に異なるコンテンツが含まれることがあります。仕様ではこれをそれぞれ serviceと呼びます。これはテレビユーザーが「チャンネル」と呼ぶものです。そのため、混乱を避けるために、このFAQでは transponders を物理チャネルと呼び、 services を論理チャネルと呼びます。

  2. LinuxTVコミュニティは、メディアサブシステムに関する多くの情報を含むWikiページを維持しています。ここに答えが見つからない場合は、おそらくLinuxTVのWikiで有用な情報を得られる可能性が高いです。ホストされている場所は以下の通りです：

    https://www.linuxtv.org/wiki/

LinuxデジタルTVサポートに関する非常によくある質問

  1. 信号はチューニング後に数秒後に途絶えるように見えます。

    これはバグではなく、機能です。フロントエンドは大きな電力が必要で（結果として非常に熱くなるため）、使用されていない場合（つまりフロントエンドデバイスが閉じられた場合）は電源を切ります。 dvb-core module parameter dvb_shutdown_timeout はタイムアウトを変更するためのパラメータで、デフォルトは5秒です。タイムアウトを0に設定すると、この機能は無効になります。

  2. どうやってテレビを視聴できるのか？

    Linuxカーネルとともに、デジタルTV開発者はテスト用およびDVB APIの動作を示すために主に設計されたいくつかの簡単なユーティリティをサポートしています。これをDVB v5ツールと呼び、次のgitリポジトリにまとめられています： v4l-utils git repository:

    https://git.linuxtv.org/v4l-utils.git/

    さらに詳しい情報はLinuxTV Wikiで確認できます：

    https://www.linuxtv.org/wiki/index.php/DVBv5_Tools

    最初のステップは、送信されているサービスの一覧を取得することです。

    これはいくつかの既存のツールを使用して行います。たとえば、 dvbv5-scan tool

    https://www.linuxtv.org/wiki/index.php/Dvbv5-scan

    を使用できます。これについての詳細は次のURLで確認してください： w_scan 1 他にも、

    1

    https://www.linuxtv.org/wiki/index.php/W_scan

    などのアプリケーションは盲目的なスキャンを行い、可能なすべてのチャンネルを見つけることを試みますが、実行に時間がかかります。 kaffeine また、一部のアプリケーションは独自のコードでサービスをスキャンするため、外部アプリケーションを使用する必要はありません。

    このようなツールは、地域で利用可能なチャンネルトランスポンダーの一覧を含むファイルが必要です。そのため、LinuxTV開発者は、コミュニティからのパッチを受けて、デジタルTVチャンネルトランスポンダーのテーブルを維持しています。

    このリストは以下の場所にホストされています：

    https://git.linuxtv.org/dtv-scan-tables.git

    そして、いくつかのディストリビューションにパッケージされています。

    Kaffeineは一部の地上波基準に対して盲目的なスキャンのサポートがあります。また、DTVスキャンテーブルに依存していますが、内部にコピーを保持しており（ユーザーが要求すれば、最新バージョンをダウンロードすることもできます）。

    幸運な場合は、提供されたチャンネルトランスポンダーファイルの1つを使用するだけで済みます。そうでない場合は、インターネットでその情報を検索し、新しいファイルを作成する必要があります。いくつかのサイトには物理的なチャンネルリストが含まれています。ケーブルや衛星放送では、単一のチャンネルをチューニングする方法を知っているだけで、スキャンツールが他のチャンネルを識別できることが一般的です。一部の地域では、地上波放送にも同様に適用される場合があります。

    トランスポンダーファイルを取得したら、ツールなどを使ってサービスリストを生成する必要があります。 dvbv5-scan.

    現代のほとんどのデジタルテレビカードは、組み込みのハードウェアMPEGデコーダーを持っていません。そのため、アプリケーションがボードから提供されるMPEG-TSストリームを取得し、オーディオ、ビデオ、その他のデータに分割してデコードする必要があります。

  4. 正しい周波数で信号を受信できない

    それは多くの問題の可能性があります。私の個人的な経験では、テレビカードはテレビセットよりも強い信号を必要とし、ノイズに対してより敏感です。そのため、おそらくより良いアンテナやケーブルが必要かもしれません。ただし、ハードウェアやドライバの問題である可能性もあります。

    たとえば、Technotrend/Hauppauge DVB-Cカード は、よりもさらにシンプルなコードを生み出すため、のミリ秒単位のレイテンシーを回避できます。よって、ご活用ください。 アナログモジュールを使用している場合、module parameter adac=-1 (dvb-ttpci.o)を使用する必要があります。

    linuxtv.orgのFAQページを確認してください。そのページには貴重な情報が含まれているかもしれません：

    https://www.linuxtv.org/wiki/index.php/FAQ_%26_Troubleshooting

    それでも改善しない場合は、linux-media MLアーカイブを確認し、他のユーザーが同様の問題をハードウェアやデジタルテレビサービスプロバイダーで経験したかどうかを確認してください：

    https://lore.kernel.org/linux-media/

    どれも効かない場合は、linux-media MLにメールを送って、他の人が説明をしてくれるか確認してください。メールアドレスはlinux-media AT vger.kernel.orgです。

  5. dvb_netデバイスはまったくパケットを送ってきません

    実行 tcpdump on the dvb0_0 インターフェース。これによりインターフェースが混入モードに設定され、設定したPIDで構成されたパケットをすべて受け取るようになります。 dvbnet ツールで設定したIPアドレスとMACアドレスのパケットを確認してください。 ifconfig または ip addr.

    もし tcpdump 出力がない場合は、統計情報の ifconfig または netstat -ni 出力結果を確認してください。(注意: MACアドレスが間違っている場合、 dvb_net 入力が得られません。そのため、統計情報を確認する前に tcpdump を実行する必要があります。まったくパケットが届かない場合はPIDが間違っている可能性があります。エラーパケットが届いた場合は、PIDが間違っているか、ストリームがMPE標準(EN 301 192, http://www.etsi.org/)に準拠していない可能性があります。デバッグには例えば dvbsnoop を使用できます。

  6. 以下の dvb_net デバイスはまったくマルチキャストパケットを送ってきません

    ルートがマルチキャストアドレス範囲を含んでいるか確認してください。また、「逆ルート検証」が無効になっているか確認してください:

    $ "echo 0 > /proc/sys/net/ipv4/conf/dvb0/rp_filter"

  7. ロードが必要なモジュールはどれですか？

    柔軟性を高め、さまざまなハードウェアの組み合わせをサポートするために、メディアサブシステムはモジュール化されています。

    そのため、メインチップセット用のデジタルTVハードウェアモジュールに加えて、フロントエンドドライバとデジタルTVコアをロードする必要があります。ボードにリモコンが搭載されている場合、リモコンコアとリモコンテーブルもロードする必要があります。アナログTVをサポートしている場合も同様に、video4linuxのコアサポートをロードする必要があります。

    実際のモジュール名はLinuxカーネルのバージョンに依存しており、時間とともに変更されるため、メディアサポートの柔軟性を高めるために行われています。
