6.7. i.MXビデオキャプチャドライバー¶

6.7.1. はじめに¶

Freescaleのi.MX5/6には、画像フレームのキャプチャデバイスおよびディスプレイデバイス間での流れを処理する画像処理ユニット（IPU）が搭載されています。

画像キャプチャにおいて、IPUには以下の内部サブユニットが含まれています：

  • 画像DMAコントローラー（IDMAC）

  • カメラシリアルインターフェース（CSI）

  • 画像コンバーター（IC）

  • センサーマルチ-FIFOコントローラー（SMFC）

  • 画像ローテーター（IRT）

  • ビデオデインタレースまたは合成ブロック（VDIC）

IDMACは、画像フレームのメモリとの転送を担当するDMAコントローラーです。ビデオキャプチャおよびディスプレイパスにはそれぞれ専用のDMAチャネルが存在します。転送中、IDMACは垂直方向の画像反転、8x8ブロック転送（IRTの説明を参照）、同じカラースペース内でのピクセルコンポーネントの再配置（例：UYVYからYUYVへの変換）、パックド <-> プレーン変換を実行可能です。また、IDMACは、VDICが必要とするモーションコンパレンスを除いて、転送中に偶数行と奇数行を交互に織り交ぜることで簡単なデインタレースも行えます。

CSIは、パラレル、BT.656/1120、MIPI CSI-2バスを介してカメラセンサと直接インターフェースするバックエンドキャプチャユニットです。

ICはカラースペース変換、リサイズ（ダウンスケーリングおよびアップスケーリング）、水平方向の画像反転、90度および270度の回転操作を処理します。

IC内には、同時に変換処理を行う3つの独立した「タスク」があります：予処理エンコーディング、予処理ビューファインダー、ポスト処理です。各タスク内で変換処理はダウンサイズセクション、メインセクション（アップスケーリング、反転、カラースペース変換、グラフィックスプレーンの結合）、および回転セクションの3つのセクションに分割されます。

IPUはICタスク処理をタイムシェアリングします。タイムスライスの粒度は、ダウンサイズセクションでは8ピクセルのバースト、メイン処理セクションでは1画像ライン、回転セクションでは1画像フレームです。

SMFCは4つの独立したFIFOから構成され、それぞれが4つのIDMACチャネルを介してセンサからメモリへ直接キャプチャフレームを転送可能です。

IRTは90度および270度の画像回転処理を行います。この回転処理は8x8ピクセルブロック単位で行われ、IDMACが8x8ブロック転送およびブロック再配置を担当します。垂直方向の反転と連携して実行されます。

VDICはインターレースビデオをプログレッシブ形式に変換を担当し、低・中・高の動画補償モードをサポートしています。VDICから出力されるデインターレースフレームは、ICプリプロセスビューファインダータスクに送られ、さらに変換処理が行われます。また、VDICには2つの画像平面をアルファブレンドとカラーキーングで合成するコンビナが含まれています。

IPU内部のサブユニットに加えて、i.MXでビデオキャプチャに関与する外部のユニットも2つあります。

  • カメラセンサー用のMIPI CSI-2受信機で、MIPI CSI-2バスインターフェースをサポートします。これはSynopsys DesignWareコアです。

  • 複数のセンサーアクセスをCSIに送信するための2つのビデオマルチプレクサがあります。

詳細については、最新版のi.MX5/6リファレンスマニュアルを参照してください。 1 および 2.

6.7.2. 機能¶

このドライバーの主な機能には以下が含まれます：

  • メディアコントローラーAPIを介して、i.MXでサポートされているハードウェアビデオキャプチャパイプラインに対応する多数のパイプラインを設定できます。

  • 並列、BT.565、MIPI CSI-2インターフェースをサポートしています。

  • 複数のビデオキャプチャインターフェースで独立したエンティティを使用してパイプラインを設定することで、同時進行する独立したストリームを実現します。

  • ICタスクサブデバイスを使用したスケーリング、カラースペース変換、水平・垂直反転、画像回転をサポートしています。

  • 多くのピクセルフォーマットをサポートしています（RGB、パックドYUV、プランナーヤンUV、部分プランナーヤンUVなど）。

  • VDICサブデバイスは動画補償デインターレースをサポートし、低・中・高の動画補償モードが利用可能です。パイプラインはCSIからVDICサブデバイスにフレームを直接送信する機能を提供しており、今後はメモリバッファ経由でVDICにフレームを送信するためのoutput/mem2memデバイスもサポートされます。

  • フレームインターバルモニタ（FIM）が含まれており、ADV718xビデオデコーダーの垂直同期問題を修正できます。

6.7.3. トポロジー¶

以下にi.MX6Q SabreSDおよびi.MX6Q SabreAutoのメディアトポロジーを示します。次のセクションのエンティティ説明でこれらのダイアグラムを参照してください。

i.MX5/6のトポロジーは、IPUv3 CSIビデオマルチプレクサの上流部分で異なりますが、その下流のIPUv3トポロジーはすべてのi.MX5/6プラットフォームで共通しています。たとえば、MIPI CSI-2 OV5640センサーを使用するSabreSDはi.MX6 MIPI CSI-2受信機が必要ですが、SabreAutoは並列bt.656バスにADV7180デコーダーのみを搭載しているため、MIPI CSI-2受信機は不要でグラフに表示されていません。

6.7.4. エンティティ¶

6.7.5. imx6-mipi-csi2¶

これはMIPI CSI-2受信エンティティです。1つのシンクパッドを持ち、MIPI CSI-2ストリーム（通常はMIPI CSI-2カメラセンサーから）を受信します。4つのソースパッドを持ち、4つのMIPI CSI-2デマルチプル化された仮想チャネル出力に対応しています。複数のソースパッドを有効化することで、複数の仮想チャネルから独立してストリームを送信できます。

このエンティティは実際には2つのサブブロックから構成されています。1つはMIPI CSI-2コアで、これはSynopsys Designware MIPI CSI-2コアです。もう1つのサブブロックは「CSI-2 to IPU ガスケット」です。ガスケットは4つの仮想チャネルストリームをデマルチプルし、それぞれの仮想チャネルを含む4つの別個の並列バスを提供し、CSIsやビデオマルチプレクサに接続します。

i.MX6 solo/dual-liteでは、すべての4つの仮想チャネルバスが2つのビデオマルチプレクサに接続されます。CSI0とCSI1は、ビデオマルチプレクサによって選択された仮想チャネルからいずれも受信できます。

i.MX6 Quadでは、仮想チャネル0はビデオマルチプレクサによって選択され、IPU1-CSI0に接続されます。仮想チャネル1と2はそれぞれIPU1-CSI1とIPU2-CSI0にハードウェアで接続され、仮想チャネル3は再びビデオマルチプレクサによって選択され、IPU2-CSI1に接続されます。

6.7.6. ipuX_csiY_mux¶

これらはビデオマルチプレクサです。カメラセンサーの並列インターフェースまたはimx6-mipi-csi2エンティティからのMIPI CSI-2仮想チャネルから選択するため、2つ以上のシンクパッドを持ちます。1つのソースパッドを持ち、CSI（ipuX_csiYエンティティ）に接続します。

i.MX6 solo/dual-liteでは、2つのビデオマルチプレクサエンティティがあります。1つはIPU1-CSI0の前に配置され、並列センサーまたは4つのMIPI CSI-2仮想チャネル（合計5つのシンクパッド）を選択します。もう1つのマルチプレクサはIPU1-CSI1の前に配置され、同様に5つのシンクパッドで選択します。

i.MX6 Quadでは、2つのビデオマルチプレクサエンティティがあります。1つはIPU1-CSI0の前に配置され、並列センサーまたはMIPI CSI-2仮想チャネル0を選択します（2つのシンクパッド）。もう1つのマルチプレクサはIPU2-CSI1の前に配置され、並列センサーまたはMIPI CSI-2仮想チャネル3を選択します（2つのシンクパッド）。

6.7.7. ipuX_csiY¶

これらはCSIエンティティです。1つのシンクパッドを持ち、上記のようにビデオマルチプレクサまたはMIPI CSI-2仮想チャネルから受信します。

このエンティティは2つのソースパッドを持ちます。1番目のソースパッドは、ハードウェアリンクを介してipuX_vdicエンティティまたはipuX_ic_prpエンティティに直接接続でき、IDMACメモリバッファ転送を必要としません。

直接ソースパッドがipuX_ic_prpエンティティにルーティングされる場合、CSIからのフレームはICプリプロセスティングタスクの1つまたは両方によって処理されます。

直接ソースパッドがipuX_vdicエンティティにルーティングされる場合、VDICは「high motion」モードを使用してモーション補償付きデインターレースを実行します（ipuX_vdicエンティティの説明を参照）。

2番目のソースパッドはSMFCとIDMACチャネルを介してメモリバッファにビデオフレームを直接送信し、ICプリプロセスティングをバイパスします。このソースパッドはキャプチャデバイスノードにルーティングされ、ノード名は「ipuX_csiY capture」という形式になります。

注意：IDMACソースパッドはIDMACチャネルを使用するため、同じカラースペース内でピクセルの再配置がIDMACチャネルによって実行できます。たとえば、CSIシンクパッドがUYVYの順序で受信している場合、IDMACソースパッドに接続されたキャプチャデバイスはYUYVの順序でキャプチャできます。また、CSIシンクパッドがパックされたYUV形式を受信している場合、キャプチャデバイスはYUV420などのプランナーフォーマットをキャプチャできます。

IDMACソースパッドのIDMACチャネルは、モーション補償なしのシンプルなインターレースをサポートしています。ソースパッドのフィールドタイプがシーケンシャルトゥーボトムまたはボトムトゥートップの場合、かつリクエストされたキャプチャインターフェースのフィールドタイプがインターレース（t-b、b-t、または未指定インターレース）に設定されている場合に有効になります。キャプチャインターフェースはソースパッドのフィールド順序（ソースパッドがseq-btの場合、インターレースbt、ソースパッドがseq-tbの場合、インターレースtb）と同じフィールド順序を強制します。

ipuX_csiYによって生成されるイベントについては、参照:imx_api_ipuX_csiY.

6.7.8. ipuX_csiYにおけるクロッピング¶

CSIは受信するRAWセンサーフレームのクロッピングをサポートしています。これはipuX_csiYエンティティのシンクパッドで、クロップ選択サブデバイスAPIを使用して実装されます。

CSIは幅と高さの両方で固定の2分の1ダウンスケーリングを独立してサポートしています。これはipuX_csiYエンティティのシンクパッドで、コンポーズ選択サブデバイスAPIを使用して実装されます。

ipuX_csiYソースパッドの出力矩形はシンクパッドのコンポーズ矩形と同じです。したがって、ソースパッドの矩形は交渉できません。コンポーズ選択APIでシンクパッドで設定する必要があります（/2ダウンスケーリングを希望する場合。それ以外の場合、ソースパッドの矩形は入力矩形と等しくなります）。

クロッピングと/2ダウンスケーリングの例として、この例では1280x960の入力フレームを640x480にクロッピングし、その後幅高さの両方で/2ダウンスケーリングして320x240にします（ipu1_csi0がipu1_csi0_muxにリンクされていると仮定）：

media-ctl -V "'ipu1_csi0_mux':2[fmt:UYVY2X8/1280x960]"
media-ctl -V "'ipu1_csi0':0[crop:(0,0)/640x480]"
media-ctl -V "'ipu1_csi0':0[compose:(0,0)/320x240]"

6.7.9. ipuX_csiYにおけるフレームスキップ¶

CSIはフレームレートの減衰をフレームスキップを介してサポートしています。フレームレートの減衰は、シンクパッドとソースパッドのフレームインターバルを設定することで指定されます。ipuX_csiYエンティティは、CSIに最適なフレームスキップ設定を適用し、ソースパッドでの望ましいフレームレートを達成します。

以下の例では、想定される60Hzの入力フレームレートをIDMAC出力ソースパッドで半分に減らしています。

media-ctl -V "'ipu1_csi0':0[fmt:UYVY2X8/640x480@1/60]"
media-ctl -V "'ipu1_csi0':2[fmt:UYVY2X8/640x480@1/30]"

6.7.11. ipuX_vdic¶

VDICはモーション補償付きデインターレースを実行し、低・中・高の3つのモーション補償モードをサポートします。モードはV4L2_CID_DEINTERLACING_MODEメニュー制御で指定されます。VDICは2つのシンクパッドと1つのソースパッドを持ちます。

直接シンクパッドはipuX_csiYの直接パッドから入力を受け取ります。このリンクを使用するとVDICは高モーションモードのみで動作可能です。

IDMACシンクパッドがアクティブになると、出力またはmem2memデバイスノードから入力を受け取ります。このパイプラインでは、VDICは低・中モードでも動作可能です（これらのモードはメモリバッファからフレームを受信する必要があるため）。注意として、出力またはmem2memデバイスはまだ実装されていないため、このシンクパッドは現在リンクがありません。

ソースパッドはIC前処理エンティティipuX_ic_prpに接続されます。

6.7.12. ipuX_ic_prp¶

これはIC前処理エンティティです。データをシンクパッドから1つまたは2つのソースパッドにルーティングするルーターとして機能します。

このエンティティは1つのシンクパッドを持ち、シンクパッドはipuX_csiYの直接パッドまたはipuX_vdicから入力を受け取ります。

このエンティティは2つのソースパッドを持ちます。1つのソースパッドは前処理エンコードタスクエンティティ（ipuX_ic_prpenc）に、もう1つは前処理ビューファインダータスクエンティティ（ipuX_ic_prpvf）に接続されます。シンクパッドがipuX_csiYから入力を受けている場合、両方のソースパッドを同時にアクティブにできます。一方、シンクパッドがipuX_vdicから入力を受けている場合（VDICからのフレームは前処理ビューファインダータスクのみが処理可能）、みずから前処理ビューファインダータスクのソースパッドのみをアクティブにできます。

6.7.13. ipuX_ic_prpenc¶

これはIC前処理エンコードエンティティです。シンクパッドはipuX_ic_prpから、ソースパッドはキャプチャデバイスノードに接続されます。ノード名の形式は「ipuX_ic_prpenc capture」となります。

このエンティティはIC前処理エンコードタスクの操作を実行します：カラースペース変換、リサイズ（ダウンスケーリングとアップスケーリング）、水平および垂直反転、および90度/270度回転。反転および回転は標準的なV4L2コントロールを介して提供されます。

ipuX_csiY IDMACソースと同様に、このエンティティもモーション補償なしのシンプルなデインターレースおよびピクセルの再配置をサポートしています。

6.7.14. ipuX_ic_prpvf¶

これはIC前処理ビューイングエンティティです。ipuX_ic_prpから1つのシンクパッドを持ち、1つのソースパッドを持っています。ソースパッドはキャプチャデバイスノードにルーティングされ、ノード名は「ipuX_ic_prpvf capture」という形式になります。

このエンティティはipuX_ic_prpencと同様の動作をします。同じスケーリングアップおよびカラースペースコンバート（CSC）操作とフリップ/回転制御を備えています。ipuX_vdicからフレームを受信し、処理する場合、ipuX_ic_prpがipuX_vdicから受信している場合、ipuX_ic_prpvfでインターレース処理は使用できません。

ipuX_csiY IDMACソースと同様に、このエンティティはモーション補償なしのシンプルなインターレースをサポートしています。ただし、ipuX_vdicがパイプラインに含まれている場合（ipuX_ic_prpがipuX_vdicから受信している場合）、ipuX_ic_prpvfでインターレースを使用することはできません。なぜなら、ipuX_vdicはすでにモーション補償付きのデインターレースを実行しており、ipuX_vdicからのフィールドタイプ出力は「none（プログレッシブ）」のみであるためです。

6.7.15. キャプチャパイプライン¶

以下の内容は、パイプラインでサポートされるさまざまなユースケースを説明しています。

表示されているリンクにはバックエンドセンサー、ビデオMUX、またはmipi csi-2受信機リンクは含まれていません。これはセンサーインターフェースの種類（パラレルまたはmipi csi-2）に依存するため、これらのパイプラインは以下のようになります：

センサー -> ipuX_csiY_mux -> …

パラレルセンサーの場合、または：

センサー -> imx6-mipi-csi2 -> (ipuX_csiY_mux) -> …

mipi csi-2センサーの場合。imx6-mipi-csi2受信機は、mipi csi-2仮想チャネルに応じてビデオMUX（ipuX_csiY_mux）にルーティングする必要があるため、ipuX_csiY_muxは括弧内に表示されています。

6.7.16. 未処理ビデオキャプチャ¶

センサーからカメラデバイスインターフェースノードに直接フレームを送信し、変換なしでipuX_csiY IDMACソースパッドを通じて送信します：

-> ipuX_csiY:2 -> ipuX_csiY capture

6.7.17. IC直接変換¶

このパイプラインは、前処理エンコードエンティティを使用してCSIからICに直接フレームをルーティングし、スケーリングアップ（最大1024x1024解像度）、CSC、フリップ、および画像回転を実行します：

-> ipuX_csiY:1 -> 0:ipuX_ic_prp:1 -> 0:ipuX_ic_prpenc:1 -> ipuX_ic_prpenc capture

6.7.18. モーション補償デインターレース¶

このパイプラインはCSI直接パッドからVDICエンティティにフレームをルーティングし、モーション補償付きのデインターレース（高モーションモードのみ）、スケーリングアップ（最大1024x1024）、CSC、フリップ、および回転をサポートします：

-> ipuX_csiY:1 -> 0:ipuX_vdic:2 -> 0:ipuX_ic_prp:2 -> 0:ipuX_ic_prpvf:1 -> ipuX_ic_prpvf capture

6.7.19. 使用注意事項¶

V4L2アプリケーションとの後方互換性を確保し、ビデオデバイスノードからコントロールを取得するだけのV4L2アプリケーションをサポートするため、キャプチャデバイスインターフェースは現在のパイプライン内のアクティブなエンティティからコントロールを継承します。そのため、コントロールはサブデバイスから直接、またはアクティブなキャプチャデバイスインターフェースからアクセスできます。たとえば、FIMコントロールはipuX_csiYサブデバイスからも、またはアクティブなキャプチャデバイスインターフェースからも取得可能です。

以下の内容はSabre*リファレンスボードの特定の使用に関する注意点です：

6.7.20. i.MX6Q SabreLite with OV5642 and OV5640¶

このプラットフォームは、並列カメラインターフェースを備えたOmniVision OV5642モジュールと、MIPI CSI-2インターフェースを備えたOV5640モジュールが必要です。両方のモジュールはBoundary Devicesから入手可能です：

  • https://boundarydevices.com/product/nit6x_5mp

  • https://boundarydevices.com/product/nit6x_5mp_mipi

1つのカメラモジュールのみが利用可能な場合、デバイスツリーで他のセンサーノードを無効化できます。

OV5642モジュールはi.MX内部ビデオマッピングの並列バス入力からIPU1 CSI0に接続され、そのI2CバスはI2Cバス2に接続されています。

MIPI CSI-2 OV5640モジュールはi.MX内部のMIPI CSI-2レシーバーに接続され、レシーバーの4つの仮想チャネル出力は以下のようになります：vc0はIPU1 CSI0マッピングに、vc1はIPU1 CSI1に直接、vc2はIPU2 CSI0に直接、vc3はIPU2 CSI1マッピングに接続されます。OV5640はSabreLiteのI2Cバス2にも接続されているため、OV5642とOV5640は同じI2Cスレーブアドレスを共有してはなりません。

以下の基本的な例は、両センサー用の未処理ビデオキャプチャパイプラインを構成します。OV5642はipu1_csi0に、OV5640はMIPI CSI-2仮想チャネル1（imx6-mipi-csi2パッド2）で送信され、ipu1_csi1に接続されます。両センサーは640x480を出力し、OV5642はYUYV2X8、OV5640はUYVY2X8を出力します：

# Setup links for OV5642
media-ctl -l "'ov5642 1-0042':0 -> 'ipu1_csi0_mux':1[1]"
media-ctl -l "'ipu1_csi0_mux':2 -> 'ipu1_csi0':0[1]"
media-ctl -l "'ipu1_csi0':2 -> 'ipu1_csi0 capture':0[1]"
# Setup links for OV5640
media-ctl -l "'ov5640 1-0040':0 -> 'imx6-mipi-csi2':0[1]"
media-ctl -l "'imx6-mipi-csi2':2 -> 'ipu1_csi1':0[1]"
media-ctl -l "'ipu1_csi1':2 -> 'ipu1_csi1 capture':0[1]"
# Configure pads for OV5642 pipeline
media-ctl -V "'ov5642 1-0042':0 [fmt:YUYV2X8/640x480 field:none]"
media-ctl -V "'ipu1_csi0_mux':2 [fmt:YUYV2X8/640x480 field:none]"
media-ctl -V "'ipu1_csi0':2 [fmt:AYUV32/640x480 field:none]"
# Configure pads for OV5640 pipeline
media-ctl -V "'ov5640 1-0040':0 [fmt:UYVY2X8/640x480 field:none]"
media-ctl -V "'imx6-mipi-csi2':2 [fmt:UYVY2X8/640x480 field:none]"
media-ctl -V "'ipu1_csi1':2 [fmt:AYUV32/640x480 field:none]"

キャプチャデバイスノード「ipu1_csi0 capture」と「ipu1_csi1 capture」でそれぞれ独立してストリーミングを開始できます。v4l2-ctlツールを使用して、キャプチャデバイスノードでサポートされているYUVピクセルフォーマット（平面形式を含む）を選択できます。

6.7.21. i.MX6Q SabreAuto with ADV7180 decoder¶

i.MX6Q SabreAutoでは、内部ビデオマッピングの並列バス入力からIPU1 CSI0に接続されたオンボードのADV7180 SDデコーダーが搭載されています。

以下の例は、NTSC 720x480入力信号を使用してADV7180ビデオデコーダーからキャプチャするパイプラインを構成する方法を示しています。単純なインタウェイブ（変換なしで動的補正を含まない）を使用します。adv7180は順序的または交互のフィールド（NTSCではフィールドタイプ‘seq-bt’、または‘alternate’）を出力する必要があります：

# Setup links
media-ctl -l "'adv7180 3-0021':0 -> 'ipu1_csi0_mux':1[1]"
media-ctl -l "'ipu1_csi0_mux':2 -> 'ipu1_csi0':0[1]"
media-ctl -l "'ipu1_csi0':2 -> 'ipu1_csi0 capture':0[1]"
# Configure pads
media-ctl -V "'adv7180 3-0021':0 [fmt:UYVY2X8/720x480 field:seq-bt]"
media-ctl -V "'ipu1_csi0_mux':2 [fmt:UYVY2X8/720x480]"
media-ctl -V "'ipu1_csi0':2 [fmt:AYUV32/720x480]"
# Configure "ipu1_csi0 capture" interface (assumed at /dev/video4)
v4l2-ctl -d4 --set-fmt-video=field=interlaced_bt

ストリーミングは/dev/video4で開始できます。v4l2-ctlツールを使用して、/dev/video4上でのサポートされているYUVピクセルフォーマットを選択することも可能です。

この例では、ADV7180ビデオデコーダーからキャプチャするパイプラインを構成しており、PAL 720x576入力信号を想定しています。Motion Compensatedデインターレースを含む場合、adv7180はシーケンシャルまたは交替フィールド（PALでは'field type 'seq-tb'、または'alternate'）を出力する必要があります。

# Setup links
media-ctl -l "'adv7180 3-0021':0 -> 'ipu1_csi0_mux':1[1]"
media-ctl -l "'ipu1_csi0_mux':2 -> 'ipu1_csi0':0[1]"
media-ctl -l "'ipu1_csi0':1 -> 'ipu1_vdic':0[1]"
media-ctl -l "'ipu1_vdic':2 -> 'ipu1_ic_prp':0[1]"
media-ctl -l "'ipu1_ic_prp':2 -> 'ipu1_ic_prpvf':0[1]"
media-ctl -l "'ipu1_ic_prpvf':1 -> 'ipu1_ic_prpvf capture':0[1]"
# Configure pads
media-ctl -V "'adv7180 3-0021':0 [fmt:UYVY2X8/720x576 field:seq-tb]"
media-ctl -V "'ipu1_csi0_mux':2 [fmt:UYVY2X8/720x576]"
media-ctl -V "'ipu1_csi0':1 [fmt:AYUV32/720x576]"
media-ctl -V "'ipu1_vdic':2 [fmt:AYUV32/720x576 field:none]"
media-ctl -V "'ipu1_ic_prp':2 [fmt:AYUV32/720x576 field:none]"
media-ctl -V "'ipu1_ic_prpvf':1 [fmt:AYUV32/720x576 field:none]"
# Configure "ipu1_ic_prpvf capture" interface (assumed at /dev/video2)
v4l2-ctl -d2 --set-fmt-video=field=none

ストリーミングは/dev/video2で開始できます。v4l2-ctlツールを使用して、/dev/video2上でのサポートされているYUVピクセルフォーマットを選択することも可能です。

このプラットフォームは、J42コネクタ（Ain1）にComposite Videoアナログ入力をADV7180に受け入れます。

6.7.22. i.MX6DL SabreAutoとADV7180デコーダー¶

i.MX6DL SabreAutoでは、内部ビデオMUXのパラレルバス入力にオンボードのADV7180 SDデコーダーが接続されており、IPU1 CSI0に接続されています。

以下の例は、NTSC 720x480入力信号を使用してADV7180ビデオデコーダーからキャプチャするパイプラインを構成する方法を示しています。単純なインタウェイブ（変換なしで動的補正を含まない）を使用します。adv7180は順序的または交互のフィールド（NTSCではフィールドタイプ‘seq-bt’、または‘alternate’）を出力する必要があります：

# Setup links
media-ctl -l "'adv7180 4-0021':0 -> 'ipu1_csi0_mux':4[1]"
media-ctl -l "'ipu1_csi0_mux':5 -> 'ipu1_csi0':0[1]"
media-ctl -l "'ipu1_csi0':2 -> 'ipu1_csi0 capture':0[1]"
# Configure pads
media-ctl -V "'adv7180 4-0021':0 [fmt:UYVY2X8/720x480 field:seq-bt]"
media-ctl -V "'ipu1_csi0_mux':5 [fmt:UYVY2X8/720x480]"
media-ctl -V "'ipu1_csi0':2 [fmt:AYUV32/720x480]"
# Configure "ipu1_csi0 capture" interface (assumed at /dev/video0)
v4l2-ctl -d0 --set-fmt-video=field=interlaced_bt

ストリーミングは/dev/video0で開始できます。v4l2-ctlツールを使用して、キャプチャデバイスノード上のサポートされているピクセルフォーマットを選択することも可能です。

この例では、ADV7180ビデオデコーダーからキャプチャするパイプラインを構成しており、PAL 720x576入力信号を想定しています。Motion Compensatedデインターレースを含む場合、adv7180はシーケンシャルまたは交替フィールド（PALでは'field type 'seq-tb'、または'alternate'）を出力する必要があります。

# Setup links
media-ctl -l "'adv7180 4-0021':0 -> 'ipu1_csi0_mux':4[1]"
media-ctl -l "'ipu1_csi0_mux':5 -> 'ipu1_csi0':0[1]"
media-ctl -l "'ipu1_csi0':1 -> 'ipu1_vdic':0[1]"
media-ctl -l "'ipu1_vdic':2 -> 'ipu1_ic_prp':0[1]"
media-ctl -l "'ipu1_ic_prp':2 -> 'ipu1_ic_prpvf':0[1]"
media-ctl -l "'ipu1_ic_prpvf':1 -> 'ipu1_ic_prpvf capture':0[1]"
# Configure pads
media-ctl -V "'adv7180 4-0021':0 [fmt:UYVY2X8/720x576 field:seq-tb]"
media-ctl -V "'ipu1_csi0_mux':5 [fmt:UYVY2X8/720x576]"
media-ctl -V "'ipu1_csi0':1 [fmt:AYUV32/720x576]"
media-ctl -V "'ipu1_vdic':2 [fmt:AYUV32/720x576 field:none]"
media-ctl -V "'ipu1_ic_prp':2 [fmt:AYUV32/720x576 field:none]"
media-ctl -V "'ipu1_ic_prpvf':1 [fmt:AYUV32/720x576 field:none]"
# Configure "ipu1_ic_prpvf capture" interface (assumed at /dev/video2)
v4l2-ctl -d2 --set-fmt-video=field=none

ストリーミングは/dev/video2で開始できます。v4l2-ctlツールを使用して、/dev/video2上でのサポートされているYUVピクセルフォーマットを選択することも可能です。

このプラットフォームは、J42コネクタ（Ain1）にComposite Videoアナログ入力をADV7180に受け入れます。

6.7.23. i.MX6Q SabreSDとMIPI CSI-2 OV5640¶

i.MX6Q SabreLiteと同様に、i.MX6Q SabreSDはIPU1 CSI0に並列インターフェースOV5642モジュールとMIPI CSI-2 OV5640モジュールをサポートしています。OV5642はi2cバス1に接続され、OV5640はi2cバス2に接続されます。

SabreSDのデバイスツリーには、並列OV5642とMIPI CSI-2 OV5640のOFグラフが含まれていますが、この執筆時点ではMIPI CSI-2 OV5640のみがテストされており、OV5642ノードは現在無効になっています。OV5640モジュールはMIPIコネクタJ5に接続され、SabreSDボードに接続されるOV5640モジュールのNXP部番号はH120729です。

次の例では、OV5640からキャプチャする未処理ビデオキャプチャパイプラインを構成し、MIPI CSI-2仮想チャネル0で送信します：

# Setup links
media-ctl -l "'ov5640 1-003c':0 -> 'imx6-mipi-csi2':0[1]"
media-ctl -l "'imx6-mipi-csi2':1 -> 'ipu1_csi0_mux':0[1]"
media-ctl -l "'ipu1_csi0_mux':2 -> 'ipu1_csi0':0[1]"
media-ctl -l "'ipu1_csi0':2 -> 'ipu1_csi0 capture':0[1]"
# Configure pads
media-ctl -V "'ov5640 1-003c':0 [fmt:UYVY2X8/640x480]"
media-ctl -V "'imx6-mipi-csi2':1 [fmt:UYVY2X8/640x480]"
media-ctl -V "'ipu1_csi0_mux':0 [fmt:UYVY2X8/640x480]"
media-ctl -V "'ipu1_csi0':0 [fmt:AYUV32/640x480]"

ストリーミングは「ipu1_csi0 capture」ノードで開始できます。v4l2-ctlツールを使用して、キャプチャデバイスノード上のサポートされているピクセルフォーマットを選択することも可能です。

「ipu1_csi0 capture」に該当する/dev/videoノードを特定するには：

media-ctl -e "ipu1_csi0 capture"
/dev/video0

この場合、/dev/video0がストリーミング要素です。

v4l2-ctl経由でストリーミングを開始するには：

v4l2-ctl --stream-mmap -d /dev/video0

Gstreamer経由でストリーミングを開始し、コンテンツをディスプレイに送信するには：

gst-launch-1.0 v4l2src device=/dev/video0 ! kmssink

次の例では、OV5640からキャプチャする直接変換パイプラインを構成し、MIPI CSI-2仮想チャネル0で送信します。また、IC出力でのカラースペース変換とスケーリングも示しています。

# Setup links
media-ctl -l "'ov5640 1-003c':0 -> 'imx6-mipi-csi2':0[1]"
media-ctl -l "'imx6-mipi-csi2':1 -> 'ipu1_csi0_mux':0[1]"
media-ctl -l "'ipu1_csi0_mux':2 -> 'ipu1_csi0':0[1]"
media-ctl -l "'ipu1_csi0':1 -> 'ipu1_ic_prp':0[1]"
media-ctl -l "'ipu1_ic_prp':1 -> 'ipu1_ic_prpenc':0[1]"
media-ctl -l "'ipu1_ic_prpenc':1 -> 'ipu1_ic_prpenc capture':0[1]"
# Configure pads
media-ctl -V "'ov5640 1-003c':0 [fmt:UYVY2X8/640x480]"
media-ctl -V "'imx6-mipi-csi2':1 [fmt:UYVY2X8/640x480]"
media-ctl -V "'ipu1_csi0_mux':2 [fmt:UYVY2X8/640x480]"
media-ctl -V "'ipu1_csi0':1 [fmt:AYUV32/640x480]"
media-ctl -V "'ipu1_ic_prp':1 [fmt:AYUV32/640x480]"
media-ctl -V "'ipu1_ic_prpenc':1 [fmt:ARGB8888_1X32/800x600]"
# Set a format at the capture interface
v4l2-ctl -d /dev/video1 --set-fmt-video=pixelformat=RGB3

ストリーミングは「ipu1_ic_prpenc capture」ノードで開始できます。

「ipu1_ic_prpenc capture」に該当する/dev/videoノードを特定するには：

media-ctl -e "ipu1_ic_prpenc capture"
/dev/video1

この場合、/dev/video1がストリーミング要素です。

v4l2-ctl経由でストリーミングを開始するには：

v4l2-ctl --stream-mmap -d /dev/video1

Gstreamer経由でストリーミングを開始し、コンテンツをディスプレイに送信するには：

gst-launch-1.0 v4l2src device=/dev/video1 ! kmssink

6.7.24. 既知の問題¶

  1. キャプチャ解像度がICリザイ zerの限界である1024x1024に近い場合、90度または270度の回転制御を使用すると、平面ピクセルフォーマット（YUV420、YUV422p）と組み合わせてフレームキャプチャが失敗し、IDMACチャネルからのエンドオブフレーム割込みが発生しなくなることがあります。この問題を回避するには、90度または270度の回転が必要な場合は、低解像度と/orパックフォーマット（YUYV、RGB3など）を使用してください。
