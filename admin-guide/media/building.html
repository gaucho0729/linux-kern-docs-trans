2.1. Linuxカーネルの構成¶

カーネルのビルドオプションメニューにアクセスするには、以下のコマンドを使用します：

$ make menuconfig

選択したオプションをすべて選び、設定を保存して終了します

変更後の設定は以下のファイルに保存されます： .config ファイルは以下のようになります：

...
# CONFIG_RC_CORE is not set
# CONFIG_CEC_CORE is not set
CONFIG_MEDIA_SUPPORT=m
CONFIG_MEDIA_SUPPORT_FILTER=y
...

メディアサブシステムは、これらのメニュー構成オプションによって制御されます：

Device Drivers --->
    <M> Remote Controller support  --->
    [ ] HDMI CEC RC integration
    [ ] Enable CEC error injection support
    [*] HDMI CEC drivers  --->
    <*> Multimedia support  --->

以下の Remote Controller support このオプションはリモコンコントローラーのコアサポートを有効にします2.

以下の HDMI CEC RC integration このオプションはHDMI CECをLinuxと統合し、機械に直接接続されたリモコンコントローラーから送信されたデータをHDMI CEC経由で受信できるようにします

以下の HDMI CEC drivers このオプションは、HDMIインターフェースを介してCECコードを受信および/または送信するプラットフォームおよびUSBドライバを選択できます3.

最後のオプション（Multimedia support)はカメラ、オーディオ/ビデオキャプチャ機器、およびテレビのサポートを有効にします

メディアサブシステムのサポートは、メインカーネルと一緒にビルドするか、モジュールとしてビルドするかの選択肢があります。ほとんどの使用ケースでは、モジュールとしてビルドすることが推奨されます

注意

メニューを使用せず、カーネルは直接構成オプションを有効にするスクリプトを提供します。カーネルモジュールを使用してメディアサポートとリモコンサポートを有効にするには、以下のコマンドを使用できます：

$ scripts/config -m RC_CORE
$ scripts/config -m MEDIA_SUPPORT
2

Remote Controller support TVカードドライバを使用する場合、リモコンコントローラーのコアサポートに依存する可能性があるため、このオプションも有効にする必要があります

3

DRMサブシステムも、メディアHDMI CECサポートを使用するGPU用ドライバを提供していますので注意してください

これらのGPU固有のドライバは以下のメニューから選択されます： Graphics support メニュー、以下の項目下 Device Drivers.

GPUドライバがHDMI CECをサポートしている場合、メディアサブシステムでCECコアサポートが自動的に有効になります

2.1.1. メディア依存関係¶

クリーンな構成から上述のオプションを有効にしても、通常では十分ではありません。メディアサブシステムは、複数の他のLinuxコアサポートに依存して動作します

たとえば、ほとんどのメディアデバイスは、いくつかの周辺機器と通信するためにシリアル通信バスを使用します。このようなバスはI²C（Inter-Integrated Circuit）と呼ばれます。このようなハードウェアのサポートを構築するためには、I²Cバスのサポートを有効にする必要があります。メニュー経由で有効にするか、以下のようにコマンドで有効にすることができます:

./scripts/config -m I2C

別の例として、リモートコントローラーのコアは入力デバイスのサポートが必要であり、以下のように有効にすることができます:

./scripts/config -m INPUT

特定のドライバーを有効にするために必要な追加のサポート（例: PCIおよび/またはUSBのサポートなど）が必要な場合があります。

2.1.2. リモートコントローラーのサポートを有効にする¶

リモートコントローラーのメニューは、特定のデバイス用のドライバーを選択するためのものです。メニューの表示は以下のようになります:

--- Remote Controller support
<M>   Compile Remote Controller keymap modules
[*]   LIRC user interface
[*]     Support for eBPF programs attached to lirc devices
[*]   Remote controller decoders  --->
[*]   Remote Controller devices  --->

以下の Compile Remote Controller keymap modules オプションは、いくつかのポピュラーなリモートコントローラー用のキーマップを生成します。

以下の LIRC user interface オプションは、を使用する際、拡張機能を追加します lirc プログラムで、ユーザー空間がリモートコントローラーから素データを受信できるようにするAPIを有効にします。

以下の Support for eBPF programs attached to lirc devices オプションは、特殊なプログラム（eBPFと呼ばれる）を使用して、Linuxカーネルに追加のリモートコントローラーのデコード機能を追加できるようにします。

以下の Remote controller decoders オプションは、Linuxカーネルが認識するプロトコルを選択します。特定のデコードを無効にする必要がない限り、すべてのサブオプションを有効にすることをお勧めします。

以下の Remote Controller devices オプションは、デバイスをサポートするために必要なドライバーを選択できます。

同じ設定は、以下のスクリプト経由でも設定できます。たとえば、ITEリモートコントローラードライバー（Intel NUCおよび一部のASUS x86デスクトップで見られる）をサポートするには、以下のようにできます: script/config HDMI CECのサポートを有効にする

$ scripts/config -e INPUT
$ scripts/config -e ACPI
$ scripts/config -e MODULES
$ scripts/config -m RC_CORE
$ scripts/config -e RC_DEVICES
$ scripts/config -e RC_DECODERS
$ scripts/config -m IR_RC5_DECODER
$ scripts/config -m IR_ITE_CIR

2.1.3. HDMI CECのサポートは、ドライバーが必要なときに自動的に設定されます。したがって、グラフィックカードが必要な場合や既存のHDMIドライバーのいずれかを有効にすればよいです。¶

HDMI固有のドライバーは、以下のメニューで利用できます

HDMI固有のドライバーは、以下のメニューで利用できます HDMI CEC drivers メニュー4:

--- HDMI CEC drivers
< >   ChromeOS EC CEC driver
< >   Amlogic Meson AO CEC driver
< >   Amlogic Meson G12A AO CEC driver
< >   Generic GPIO-based CEC driver
< >   Samsung S5P CEC driver
< >   STMicroelectronics STiH4xx HDMI CEC driver
< >   STMicroelectronics STM32 HDMI CEC driver
< >   Tegra HDMI CEC driver
< >   SECO Boards HDMI CEC driver
[ ]     SECO Boards IR RC5 support
< >   Pulse Eight HDMI CEC
< >   RainShadow Tech HDMI CEC

上の内容は例です。実際のHDMIデバイスのオプションはシステムのアーキテクチャに依存し、新しいカーネルでは変化する場合があります。

2.1.4. メディアのサポートを有効にする¶

メディアメニューには、リモートコントローラーのメニューに比べて多くのオプションがあります。選択すると以下のオプションが表示されます:

--- Media support
[ ] Filter media drivers
[*] Autoselect ancillary drivers
    Media device types --->
    Media core support --->
    Video4Linux options --->
    Media controller options --->
    Digital TV options --->
    HDMI CEC options --->
    Media drivers --->
    Media ancillary drivers --->

特定のドライバーを構築する場合、または正確に何をするかわかっている場合を除き、I²Cの補助ドライバーを自動選択するため、オプションを有効にすることをお勧めします。 Autoselect ancillary drivers オプションを有効にすることをお勧めします。これにより、必要なI²C補助ドライバーが自動的に選択されます。

以下に記載する通り、メディアデバイスドライバーを選択する方法は2通りあります。

2.1.4.1. Filter media drivers メニュー¶

このメニューはPCおよびラップトップハードウェアの簡単な設定を目的としています。ユーザーが望むメディアドライバーの種類を指定できるようにすることで動作します:

[ ] Cameras and video grabbers
[ ] Analog TV
[ ] Digital TV
[ ] AM/FM radio receivers/transmitters
[ ] Software defined radio
[ ] Platform-specific devices
[ ] Test drivers

カメラやビデオキャプチャデバイスのサポートを追加するだけの場合は、最初のオプションを選択してください。複数のオプションを選択することも可能です。

このメニューのオプションを選択した後、構築システムは選択した機能をサポートする必要となるコアドライバーを自動的に選択します。

注意

ほとんどのテレビカードはハイブリッド型で、アナログテレビとデジタルテレビの両方をサポートしています。

ハイブリッドカードを使用している場合、 Analog TV および Digital TV メニューで有効にする必要があります。

このオプションを使用する場合、メディアサポートコア機能のデフォルト設定は基本的な機能を提供するのに十分ですが、必要に応じて追加の機能を手動で有効化できます。以下のサブメニューの設定を使用して、 Media support サブメニュー:

Media core support --->
Video4Linux options --->
Media controller options --->
Digital TV options --->
HDMI CEC options --->

望ましいフィルタを選択した後、フィルタリング条件に一致するドライバーは Media support->Media drivers サブメニューで表示されます。

2.1.4.2. Media Core Support フィルタリングなしのメニュー¶

フィルタリングなしのメニューを無効にすると、システムで利用可能な依存関係が満たされたすべてのドライバーが Filter media drivers メニューで表示されます。 Media drivers メニュー。

ただし、まず以下のメニューがドライバーに必要なコア機能をすべて含んでいるか確認してください。そうでなければ、対応するドライバーが表示されません。 Media Core Support メニュー。

2.1.5. 例¶

以下の表に記載されているボードのモジュールサポートを有効にするには、 この表モジュールメディアコアモジュールを使用して、 .config ファイルには以下のような行が含まれている必要があります:

CONFIG_MODULES=y

2.2. 新しいカーネルのビルドとインストール¶

一旦 .config ファイルに必要なものがすべて含まれていれば、ビルドには以下を実行するだけです make コマンド:

$ make

その後、新しいカーネルとそのモジュールをインストールします:

$ sudo make modules_install
$ sudo make install

2.3. メディアドライバとコアのみをビルドする場合¶

開発ツリーから新しい開発用カーネルを実行すると、通常はリスクがあります。これは、実験的な変更があり、それがバグを引き起こす可能性があるためです。そのため、新しいドライバのみをビルドする方法として、代替のツリーを使用する方法があります。

あります Linux Kernel backportsプロジェクト、安定したカーネルに対してコンパイルされる新しいドライバを含んでいます。

LinuxTV開発者たちはメディアサブシステムのメンテナンスを担当しており、最新のカーネルから毎日更新されるメディアドライバのみを含むバックポートツリーも維持しています。このようなツリーは以下から入手できます:

https://git.linuxtv.org/media_build.git/

注意すべきは、以下のツリーをテスト目的で使用する場合、相対的に安全であるものの、 media_build ランダムなカーネルで動作する（またはビルドされる）保証はありません。このツリーは、時間に余裕がある限り「ベストエフォート」の原則に基づいて維持されています。

このツリーに何か間違いを見つけた場合は、Linuxメディアサブシステムのメーリングリストにパッチを送信してください: media@vger.kernel.org、メールの件名に [PATCH media-build] media-build用の新しいパッチを送信する場合は、メールの件名に追加してください。

使用する前に、以下を実行してください:

$ ./build

注意

  1. ツリーが更新された場合、2回実行する必要があります。 media-build tree gets updated;

  2. 過去に異なるカーネルバージョン用にビルドした場合、 make distclean if you had built it in the past for a different Kernel version than the one you’re currently using;

  3. デフォルトでは、現在実行中のカーネルで定義されたメディア用の設定オプションを使用します。

異なるドライバーまたは設定オプションを選択するには、以下のコマンドを使用してください:

$ make menuconfig

その後、新しいドライバーをビルドしてインストールできます:

$ make && sudo make install

これにより、以前に使用していたメディアドライバーが上書きされます。
