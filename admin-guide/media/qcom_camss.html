6.15. Qualcomm Camera Subsystemドライバ¶

6.15.1. はじめに¶

このファイルは、drivers/media/platform/qcom/camss ディレクトリ下にある Qualcomm Camera Subsystem ドライバのドキュメンテーションを記述しています。

現在のドライババージョンは、Qualcomm MSM8916/APQ8016 および MSM8996/APQ8096 プロセッサに搭載されているカメラサブシステムをサポートしています。

このドライバは V4L2、Media controller および V4L2 subdev インターフェースを実装しており、カメラセンサーが V4L2 subdev インターフェースを介してカーネルで動作することをサポートしています。

このドライバは、Code Aurora に含まれる Qualcomm Camera Subsystem ドライバを参考に実装されています。 1 2.

6.15.2. Qualcomm Camera Subsystem ハードウェア¶

8x16 / 8x96 プロセッサに搭載され、このドライバがサポートするカメラサブシステムハードウェアは以下の通りです：

  • 2 / 3 個の CSIPHY モジュール。これらは CSI2 レシーバーの物理層を処理します。各 CSIPHY モジュールに別個のカメラセンサーを接続できます。

  • 2 / 4 個の CSID (CSI デコーダー) モジュール。これらは CSI2 レシーバーのプロトコル層およびアプリケーション層を処理します。CSID は CSIPHY のいずれかからデータストリームをデコードでき、各 CSID には TG (テストジェネレータ) ブロックが含まれており、テスト目的で人工的な入力データを生成できます。

  • ISPIF (ISP インターフェース) モジュール。CSID からのデータストリームを VFE の入力にルーティングします。

  • 1 / 2 個の VFE (ビデオフロントエンド) モジュール。画像処理ハードウェアブロックのパイプラインを含みます。VFE にはさまざまな入力インターフェースがあります。PIX (ピクセル) 入力インターフェースは画像処理パイプラインにデータを供給し、パイプラインの最後にはスケールおよびクロップモジュールが含まれます。3つの RDI (RAW ダンプインターフェース) 入力インターフェースは画像処理パイプラインをバイパスします。VFE にはさらに AXI バスインターフェースがあり、出力データをメモリに書き込みます。

6.15.3. サポートされる機能¶

現在のドライババージョンは以下の機能をサポートしています：

  • CSIPHY を経由したカメラセンサーからの入力；

  • CSID 内の TG によるテスト入力データの生成；

  • VFE の RDI インターフェース

    • 入力データのメモリへのRAWダンプ。

      サポートされるフォーマット：

      • YUYV/UYVY/YVYU/VYUY (パックされたYUV 4:2:2 - V4L2_PIX_FMT_YUYV / V4L2_PIX_FMT_UYVY / V4L2_PIX_FMT_YVYU / V4L2_PIX_FMT_VYUY)；

      • MIPI RAW8 (8bit ベイヤーRAW - V4L2_PIX_FMT_SRGGB8 / V4L2_PIX_FMT_SGRBG8 / V4L2_PIX_FMT_SGBRG8 / V4L2_PIX_FMT_SBGGR8)；

      • MIPI RAW10 (10bit パックされたベイヤーRAW - V4L2_PIX_FMT_SBGGR10P / V4L2_PIX_FMT_SGBRG10P / V4L2_PIX_FMT_SGRBG10P / V4L2_PIX_FMT_SRGGB10P / V4L2_PIX_FMT_Y10P)；

      • MIPI RAW12 (12bit パックされたベイヤーRAW - V4L2_PIX_FMT_SRGGB12P / V4L2_PIX_FMT_SGBRG12P / V4L2_PIX_FMT_SGRBG12P / V4L2_PIX_FMT_SRGGB12P)。

      • (8x96のみ) MIPI RAW14 (14bitパッケージ化Bayer RAW - V4L2_PIX_FMT_SRGGB14P / V4L2_PIX_FMT_SGBRG14P / V4L2_PIX_FMT_SGRBG14P / V4L2_PIX_FMT_SRGGB14P).

    • (8x96のみ) 入力データの形式変換。

      サポートされる入力形式:

      • MIPI RAW10 (10bitパッケージ化Bayer RAW - V4L2_PIX_FMT_SBGGR10P / V4L2_PIX_FMT_Y10P).

      サポートされる出力形式:

      • Plain16 RAW10 (10bitアンパッケージ化Bayer RAW - V4L2_PIX_FMT_SBGGR10 / V4L2_PIX_FMT_Y10).

  • VFEのPIXインターフェース

    • 入力データの形式変換。

      サポートされる入力形式:

      • YUYV/UYVY/YVYU/VYUY (パッケージ化YUV 4:2:2 - V4L2_PIX_FMT_YUYV / V4L2_PIX_FMT_UYVY / V4L2_PIX_FMT_YVYU / V4L2_PIX_FMT_VYUY).

      サポートされる出力形式:

      • NV12/NV21 (2平面YUV 4:2:0 - V4L2_PIX_FMT_NV12 / V4L2_PIX_FMT_NV21);

      • NV16/NV61 (2平面YUV 4:2:2 - V4L2_PIX_FMT_NV16 / V4L2_PIX_FMT_NV61).

      • (8x96のみ) YUYV/UYVY/YVYU/VYUY (パッケージ化YUV 4:2:2 - V4L2_PIX_FMT_YUYV / V4L2_PIX_FMT_UYVY / V4L2_PIX_FMT_YVYU / V4L2_PIX_FMT_VYUY).

    • スケーリングサポート。VFEエンコーダー スケールモジュールの設定で、最大16倍のダウンスケーリングが可能です。

    • クロッピングサポート。VFEエンコーダー クロッピングモジュールの設定。

  • 2つのデータ入力（8x96: 3つ）を同時かつ独立して使用可能 - カメラセンサーおよび/またはTGが使用可能です。

6.15.4. ドライバアーキテクチャと設計¶

ドライバはV4L2サブデバイスインターフェースを実装しています。モジュール間のハードウェアリンクをモデル化し、クリーンで論理的で使いやすいインターフェースを提供するため、ドライバは以下の通りV4L2サブデバイスに分割されています（8x16 / 8x96）:

  • 2 / 3 CSIPHYサブデバイス - 各CSIPHYは1つのサブデバイスで表されます;

  • 2 / 4 CSIDサブデバイス - 各CSIDは1つのサブデバイスで表されます;

  • 2 / 4 ISPIFサブデバイス - ISPIFはCSIDサブデバイスの数と同じ数のサブデバイスで表されます;

  • 4 / 8 VFEサブデバイス - 各入力インターフェース（3つのRDIと1つのPIX）に対応する数のサブデバイスで表されます。

ドライバをこのように分割する理由は以下の通りです:

  • CSIPHYおよびCSIDモジュールを個別のサブデバイスで表すことで、これらのモジュール間のハードウェアリンクをモデル化できます;

  • 各入力インターフェースに対応する個別のサブデバイスでVFEを表すことで、ハードウェアがサポートするように入力インターフェースを同時かつ独立して使用できます;

  • 複数のCSIDサブデバイスに相当するサブデバイスを用いてISPIFを表すことで、2つのカメラを同時に使用する際、線形のメディアコントローラーパイプラインを構築することが可能になります。これにより、パイプライン内での分岐を回避でき、それ以外の場合はa) ユーザースペースとb) メディアフレームワーク（例：電源のオン/オフ操作）が、単一のメディアエンティティにおけるシンクパッドからソースパッドへのデータフローに関する仮定を必要とします。

各VFEサブデバイスは、別個のビデオデバイスノードにリンクされています。

メディアコントローラーパイプライングラフは以下の通りです（接続された2台/3台のOV5645カメラセンサーを使用）：

6.15.5. ハードロックアップ検出器は、定期的に実行されるhrtimerによって生成される割込みでウォッチドッグタスクを起動します。ハードロックアップの検出には、「watchdog_thresh」（コンパイル時に初期化され、sysctlの同じ名前で設定可能）秒ごとにNMI perfイベントが生成されます。システム内のどのCPUもその間hrtimer割込みを受けていない場合、ハードロックアップ検出器（NMI perfイベントのハンドラ）がカーネル警告を生成するか、設定に応じてパニックを呼び出します。¶

現在サポートされている機能を実装するには、ハードウェアのランタイム設定（ストリーミング中に設定を更新）は必要ありません。各ハードウェアモジュールの完全な設定は、現在アクティブなメディアリンク、フォーマット、コントロール設定に基づいてSTREAMON ioctlをもとに適用されます。

VFE内のスケーラーモジュールの出力サイズは、「msm_vfe0_pix」エンティティのシンクパッドにおける実際のコンポジット選択矩形で設定されます。

VFE内のクロップモジュールのクロップ出力領域は、「msm_vfe0_pix」エンティティのソースパッドにおける実際のクロップ選択矩形で設定されます。
