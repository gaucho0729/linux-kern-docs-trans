6.14. フィリップスウェブカメラ（pwcドライバー）¶

このファイルには、フィリップスおよびOEMのWebカメラに関する追加情報が含まれています。メールアドレス: webcam@smcc.demon.nl 最終更新日: 2004-01-19 サイト: http://www.smcc.demon.nl/webcam/

フィリップスドライバのメインウェブページは上記のアドレスです。ここには多くの追加情報、よくある質問（FAQ）、バイナリプラグイン「PWCX」が含まれています。このプラグインには、高画質・高フレームレートの使用を可能にするデコンプレッサーの処理が含まれており、USBバスでの帯域幅の使用量も減少します（複数のカメラを同時に使用する際には特に役立ちます）。これらの処理はNDA（非開示契約）の下にあり、ソースコードとして配布されない可能性がありますが、使用は完全に任意です。

このコードはカーネルに組み込むか、モジュールとして構築できます。後者を推奨します（トラブルシューティングがはるかに簡単になるからです）。内蔵マイクはUSB Audioクラスを通じてサポートされています。

モジュールをロードする際、カメラのデフォルト設定をいくつか設定できます。一部のプログラムは特定の画像サイズや形式を必要としますが、ドライバで適切に設定する方法を知らない場合があります。オプションは以下の通りです:

size

sqcif、qsif、qcif、sif、cif、vgaのいずれかを指定します（それぞれ128x96、160x120、176x144、320x240、352x288、640x480の画像サイズ）。ただし、これらの解像度をサポートするカメラに限ります。

fps

望ましいフレームレートを指定します。4〜30の整数値を指定します。

fbufs

このパラメータは、カメラから取得するフレームを保存する内部バッファの数を指定します。画像を読み込むプロセスが少し遅かったり、一時的に忙しかったりする場合に役立ちます。ただし、遅いマシンではラグを引き起こす可能性があるため、慎重に選択してください。デフォルトは3で、これは十分な値です。2〜5の間で設定できます。

mbufs

これは1〜10の整数です。mmap()、VIDIOCCGMBUF、VIDIOCMCAPTUREなどに予約するバッファ数を指定します。デフォルトは2で、ほとんどのアプリケーションには十分です（ダブルバッファリング）

ツールでmmap()を使用してキャプチャを行っている際に、「Dumping frame…」というメッセージが多数表示される場合、ifの値を増やすことを検討してください。ただし、この設定は画像をバッファリングするわけではなく、プログラムが遅延しているときに少し余裕をもって動作させるためのものです。実際の効果を発揮させるには、マルチスレッドまたはフォークされたプログラムが必要です。

絶対最大値は10ですが、あまりに高い値を設定しないでください！各バッファは460KBのRAMを消費するため、メモリが十分でない限り4以上に設定するのは完全な無駄です。このメモリはopen()時にのみ割り当てられるため、カメラが使用されていないときは何も無駄にはなりません。

power_save

power_saveが有効（1に設定）になると、モジュールがclose()時にカメラをシャットダウンし、open()時に再起動を試みます。これにより電力消費を抑え、LEDを消灯させることができます。ただし、すべてのカメラがこの機能をサポートしているわけではありません（645および646は電力節約機能をまったく持ちません）。また一部のモデルでは動作しない場合があります（シャットダウンは行いますが、再起動しない）。この機能は実験的です。デフォルトでは無効になっています。

compression（プラグインでのみ有効）

このオプションを使用すると、カメラがUSBバスを通じて画像を圧縮する際の圧縮率を制御できます。パラメータを0〜3の間で設定できます：

0 = prefer uncompressed images; if the requested mode is not available
    in an uncompressed format, the driver will silently switch to low
    compression.
1 = low compression.
2 = medium compression.
3 = high compression.

高圧縮は帯域幅を節約しますが、不要なアーティファクトの発生を引き起こす可能性もあります。デフォルトは2（中程度の圧縮）です。どのモードで圧縮が必要かについては、ウェブサイトのFAQを参照してください。

645および646カメラとそれらをベースとしたOEMモデル（一部のみ）にはこの圧縮パラメータは適用されません。ほとんどのカメラはこのパラメータを尊重します。

leds

この設定には2つの整数が指定され、LEDの点灯/消灯時間（ミリ秒単位）を定義します。興味深いことに、カメラを使用中にLEDを点滅させることも可能です。これは：

leds=500,500

LEDを1秒ごとに点滅させます。しかし：

leds=0,0

LEDが常に点灯せず、静かな監視に適しています。

デフォルトでは、カメラが使用中にLEDは常時点灯し、使用が終了すると消灯します。

このパラメータはToUCamシリーズのカメラ（720、730、740、750）およびOEMモデルでのみ有効です。他のカメラではこのコマンドは無視され、LEDの制御はできません。

最後に：このパラメータはカメラデバイスを開く初めての際に初めて効果を発揮します。そのまではLEDは常に点灯します。

dev_hint

USBデバイスの長年の問題は、その動的性質です：カメラがどのデバイスに割り当てられるかは予測できません。これはモジュールのロード順序、ハブの設定、デバイスの挿抜順序、さらには月の満ち欠け（つまりランダムな場合もあります）に依存します。このオプションを使用すると、ドライバに特定のカメラが使用するべきビデオデバイスノード（/dev/videoX）をヒントを与えることができます。同じモデルのカメラを2台以上持っている場合にもこの機能は役立ちます。

カメラは、モデル番号（PCA645、PCVC750VCなど）のタイプと、オプションでシリアル番号（/sys/kernel/debug/usb/devicesに表示される）で指定されます。ヒントは以下の形式の文字列で構成されます：

[type[.serialnumber]:]node

角括弧はタイプとシリアル番号がどちらもオプションであることを意味しますが、シリアル番号を指定する場合はタイプを必ず指定しなければ意味がありません（実用上無意味です）。シリアル番号はタイプと「.」で区切り、ノード番号は「:」で区切り、それぞれが分離されます。

このやや謎めいた構文は、いくつかの例を挙げて説明するのがわかりやすいでしょう：

dev_hint=3,5              The first detected cam gets assigned
                          /dev/video3, the second /dev/video5. Any
                          other cameras will get the first free
                          available slot (see below).

dev_hint=645:1,680:2      The PCA645 camera will get /dev/video1,
                          and a PCVC680 /dev/video2.

dev_hint=645.0123:3,645.4567:0     The PCA645 camera with serialnumber
                                   0123 goes to /dev/video3, the same
                                   camera model with the 4567 serial
                                   gets /dev/video0.

dev_hint=750:1,4,5,6       The PCVC750 camera will get /dev/video1, the
                           next 3 Philips cams will use /dev/video4
                           through /dev/video6.

知っておくべきポイント：

  • シリアル番号は大文字小文字を区別し、リードゼロ（前導ゼロ）を含む完全な文字列で入力する必要があります（文字列として扱われます）。

  • デバイスノードがすでに使用されている場合、登録が失敗しウェブカメラが利用不可になります。

  • 最大で64台のビデオデバイスを扱えます。/devに十分なデバイスノードを用意しないと、番号を分散できません。/dev/video9の次は/dev/video10（/dev/videoAではありません）です。

  • カメラがどのdev_hintにもマッチしない場合、単に最初に空いているデバイスノードが割り当てられます（以前と同様です）。

trace

問題の検出をより効果的に行うために、モジュールが行う一部の呼び出しを「trace（トレース）」として有効化できます。これはカーネルログにデバッグレベルですべての項目を記録します。

trace変数はビットマスクです。各ビットは特定の機能を表します。トレースを有効にする場合は、下記の表でビット値を確認し、値を合計してtrace変数に指定してください。

たとえば、open()とread()関数をトレースするには、8 + 4 = 12を合計し、insmodまたはmodprobe時にtrace=12を指定します。初期化およびプローブのトレースをオフにする場合はtrace=0を指定します。traceのデフォルト値は35（0x23）です。

例:

# modprobe pwc size=cif fps=15 power_save=1

fbufs、mbufsおよびtraceパラメータはグローバルであり、すべての接続カメラに適用されます。各カメラは独自のバッファーセットを持ちます。

sizeおよびfpsはデバイスを開く際にデフォルト値を指定します。これは一部のツールがサイズを設定しない場合に備えたものです。open()後でもVideo4Linuxのioctl()コールを使用してこれらの設定を変更できます。デフォルトのデフォルト値はQCIFサイズで10fpsです。

圧縮パラメータはセミグローバルです。すべてのカメラの初期圧縮設定を指定しますが、VIDIOCPWCSCQUAL ioctl()コールを使用することで各カメラごとに設定可能です。

すべてのパラメータはオプションです。
