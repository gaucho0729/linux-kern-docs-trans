6.9. Intel Image Processing Unit 3 (IPU3) Imaging Unit (ImgU) ドライバ¶

著作権 © 2018 Intel Corporation

6.9.1. はじめに¶

このファイルは、drivers/media/pci/intel/ipu3 (CIO2) および drivers/staging/media/ipu3 (ImgU) に配置されている Intel IPU3（第3世代画像処理ユニット）イメージングユニットドライバーについて記載しています。

特定の Kaby Lake（および特定の Sky Lake）プラットフォーム（U/Y プロセッサライン）に搭載されている Intel IPU3 は、イメージングユニット（ImgU）と CIO2 デバイス（MIPI CSI2 受信機）の2つの部分から構成されています。

CIO2 デバイスはセンサーから受け取った RAW バイアーデータを、IPU3 が消費できる形式でフレームを出力します。CIO2 ドライバーは drivers/media/pci/intel/ipu3/ipu3-cio2* に配置されており、CONFIG_VIDEO_IPU3_CIO2 コンフィギュレーションオプションを通じて有効になります。

イメージングユニット（ImgU）は、IPU3 CIO2 デバイスでキャプチャされた画像の処理を担当します。ImgU ドライバーのソースコードは drivers/staging/media/ipu3 ディレクトリに配置されており、CONFIG_VIDEO_IPU3_IMGU コンフィギュレーションオプションを通じて有効になります。

2つのドライバーモジュールはそれぞれ ipu3_csi2 および ipu3_imgu と呼ばれます。

ドライバーは Kaby Lake プラットフォーム（U/Y プロセッサライン）でテストされています。

両方のドライバーは V4L2、メディアコントローラー、V4L2サブデバイスインターフェースを実装しています。IPU3 CIO2 ドライバーは、CIO2 MIPI CSI-2インターフェースに接続されたカメラセンサーを V4L2サブデバイスセンサードライバーを通じてサポートします。

6.9.2. CIO2¶

CIO2 は単一の V4L2サブデバイスとして表され、ユーザー空間に V4L2サブデバイスインターフェースを提供します。各 CSI-2 受信機にはビデオノードが割り当てられ、デバイス全体には単一のメディアコントローラーインターフェースが割り当てられます。

CIO2 には4つの独立したキャプチャチャネルがあり、それぞれが独自の MIPI CSI-2 受信機と DMA エンジンを持ちます。各チャネルは V4L2サブデバイスとしてモデル化され、ユーザー空間に V4L2サブデバイスノードとして露出され、2つのパッドを持ちます：

パッド

direction

用途

0

sink

MIPI CSI-2 入力（センサーサブデバイスに接続）

1

source

RAW ビデオキャプチャ（V4L2 ビデオインターフェースに接続）

V4L2 ビデオインターフェースは DMA エンジンをモデル化しており、ユーザー空間に V4L2 ビデオデバイスノードとして露出されます。

6.9.2.1. RAW バイアーフォーマットでのフレームキャプチャ¶

CIO2 MIPI CSI2 受信機は、CSI2 ポートに接続された RAW センサーから RAW バイアーフォーマットでフレームをキャプチャします。キャプチャされたフレームは ImgU ドライバーへの入力として使用されます。

IPU3 ImgU を用いた画像処理には raw2pnm 2, および yavta 3 というツールが必要です。これは IPU3 に特有の要件や機能に起因します。

– IPU3 CSI2レシーバーは、センサーからキャプチャしたフレームをIPU3固有のパックされたRAW Bayer形式で出力します。

– 複数のビデオノードを同時に動作させる必要があります。

ov5670センサーがCSI2ポート0に接続され、2592x1944の画像キャプチャを行う例を挙げます。

メディアコントローラーAPIを使用して、ov5670センサーをIPU3 CSI2レシーバーにパックされたRAW Bayer形式でフレームを送信するように設定します。

# This example assumes /dev/media0 as the CIO2 media device
export MDEV=/dev/media0

# and that ov5670 sensor is connected to i2c bus 10 with address 0x36
export SDEV=$(media-ctl -d $MDEV -e "ov5670 10-0036")

# Establish the link for the media devices using media-ctl [#f3]_
media-ctl -d $MDEV -l "ov5670:0 -> ipu3-csi2 0:0[1]"

# Set the format for the media devices
media-ctl -d $MDEV -V "ov5670:0 [fmt:SGRBG10/2592x1944]"
media-ctl -d $MDEV -V "ipu3-csi2 0:0 [fmt:SGRBG10/2592x1944]"
media-ctl -d $MDEV -V "ipu3-csi2 0:1 [fmt:SGRBG10/2592x1944]"

メディアパイプラインが設定されると、yavtaツールを使用して露出やゲインなどのセンサー固有の設定を指定できます。

e.g

yavta -w 0x009e0903 444 $SDEV
yavta -w 0x009e0913 1024 $SDEV
yavta -w 0x009e0911 2046 $SDEV

センサーの設定が完了したら、以下のようにフレームキャプチャを行います。

e.g

yavta --data-prefix -u -c10 -n5 -I -s2592x1944 --file=/tmp/frame-#.bin \
      -f IPU3_SGRBG10 $(media-ctl -d $MDEV -e "ipu3-cio2 0")

上記のコマンドにより、2592x1944解像度でsGRBG10形式のフレームを10枚キャプチャし、IPU3_SGRBG10形式で出力します。

キャプチャされたフレームは/tmp/frame-#.binファイルとして利用可能です。

6.9.3. ImgU¶

ImgUは2つのV4L2サブデバイスとして表され、それぞれユーザー空間に対してV4L2サブデバイスインターフェースを提供します。

各V4L2サブデバイスはパイプを表し、最大2ストリームをサポートします。これにより、連続ビューファインダー（CVF）やビデオ中のスナップショット（SDV）などの高度なカメラ機能をサポートします。

ImgUには2つの独立したパイプがあり、それぞれがユーザー空間にV4L2サブデバイスノードとして露出されるV4L2サブデバイスとしてモデル化されています。

各パイプには以下の目的で2つのシンクパッドと3つのソースパッドがあります：

パッド

direction

用途

0

sink

入力RAWビデオストリーム

1

sink

処理パラメータ

2

source

出力処理済みビデオストリーム

3

source

出力ビューファインダービデオストリーム

4

source

3A統計情報

各パッドは対応するV4L2ビデオインターフェースに接続され、ユーザー空間にV4L2ビデオデバイスノードとして露出されます。

6.9.3.1. デバイス操作¶

ImgUでは、入力ビデオノード（"ipu3-imgu 0/1":0、<エンティティ>:<パッド番号>形式）にバッファ（パックされたRAW Bayer形式）をキューイングすると、ImgUがバッファを処理し、YUV形式のビデオ出力と統計情報出力をそれぞれの出力ノードで生成します。ドライバは入力ビデオノードにバッファをキューイングする際、パラメータ、出力、統計情報ノードすべてにバッファが準備されている必要があります。

少なくとも入力、メイン出力、3A統計情報、ビューファインダービデオノードはすべて有効化する必要があります。

各ImgU V4L2サブデバイスには以下のビデオノードが含まれます。

6.9.3.2. 入力、出力、ビューファインダービデオノード¶

入力ビデオノードで受信したIPU3固有のパックされたRAW Bayer形式のフレームは、IPU3イメージングユニットで処理され、2つのビデオノードにそれぞれ異なる目的（メイン出力とビューファインダー出力）に向けた出力されます。

IPU3に特有のバエイヤ形式に関する詳細情報は以下にあります V4L2_PIX_FMT_IPU3_SBGGR10 (‘ip3b’), V4L2_PIX_FMT_IPU3_SGBRG10 (‘ip3g’), V4L2_PIX_FMT_IPU3_SGRBG10 (‘ip3G’), V4L2_PIX_FMT_IPU3_SRGGB10 (‘ip3r’).

このドライバーは、以下のドキュメントで定義された V4L2 ビデオキャプチャインターフェースをサポートしています インターフェース.

マルチプランナーアプリケーションプログラミングインターフェースのみがサポートされています。詳細情報は以下にあります シングルプレーンおよびマルチプレーンAPI.

6.9.3.3. パラメータビデオノード¶

パラメータビデオノードは、ImgUアルゴリズムが画像を処理する方法を設定するためのImgUアルゴリズムパラメータを受け取ります

IPU3に特有の処理パラメータに関する詳細情報は以下にあります V4L2_META_FMT_IPU3_PARAMS (‘ip3p’), V4L2_META_FMT_IPU3_3A (‘ip3s’).

6.9.3.4. 3A統計ビデオノード¶

3A統計ビデオノードは、ImgUドライバーが処理中のフレームの3A（オートフォーカス、オート露出、オートホワイトバランス）統計情報をユーザー空間アプリケーションに出力するために使用されます。ユーザー空間アプリケーションはこの統計データを使用して、ImgUの望ましいアルゴリズムパラメータを計算できます

6.9.4. Intel IPU3の設定¶

IPU3 ImgUパイプラインは、以下に定義されたメディアコントローラーを使用して設定できます 第 IV 章 - Media Controller API.

6.9.4.1. 実行モードとファームウェアバイナリの選択¶

ImgUはファームウェアに基づいて動作します。現在、ImgUファームウェアは2つのパイプラインを時間共有で実行し、単一の入力フレームデータを処理します。各パイプラインは「ビデオ」または「静止画」のいずれかのモードで動作します。「ビデオ」モードは通常ビデオフレームのキャプチャに使用され、「静止画」モードは静止画フレームのキャプチャに使用されます。ただし、システム負荷と電力消費を抑えるために静止画フレームをキャプチャしたい場合、「ビデオ」モードを選択することもできます。「静止画」モードでは、ImgUはより小さなBDS係数を使用し、より大きなバエイヤフレームを出力してYUV処理を進めるため、ビデオモードよりも高品質な画像を取得します。さらに、「静止画」モードではXNR3を用いてノイズ除去を行うため、ビデオモードよりもより多くの電力とメモリ帯域幅が必要になります。TNRは「ビデオ」モードで有効になり、「静止画」モードではバイパスされます。ImgUはデフォルトで「ビデオ」モードで動作しており、ユーザーはv4l2コントロールV4L2_CID_INTEL_IPU3_MODE（現在はdrivers/staging/media/ipu3/include/intel-ipu3.hに定義されています）を使用して実行モードを照会および設定できます。ユーザーにとって、「ビデオ」モードと「静止画」モードのバッファキューイングには違いがありません。必須入力ノードとメイン出力ノードを有効にしてバッファをキューイングする必要があります。統計情報とビューファインダーのキューはオプションです

現在の実行モードに応じてファームウェアバイナリが選択されます。ImgUダイナミックデバッグを有効にすると、「if_to_osys_striped」バイナリか「if_to_osys_primary_striped」バイナリを使用しているというログが表示されます。『VIDEO』モードでは「if_to_osys_striped」バイナリが選択され、『STILL』モードでは「if_to_osys_primary_striped」バイナリが選択されます。

6.9.4.2. RAW Bayer形式で画像を処理しています¶

6.9.4.2.1. ImgU V4L2 subdevを画像処理用に設定しています¶

ImgU V4L2 subdevはメディアコントローラーAPIで設定する必要があります。これにより、すべてのビデオノードが正しくセットアップされます。

『ipu3-imgu 0』subdevを例に挙げます。

media-ctl -d $MDEV -r
media-ctl -d $MDEV -l "ipu3-imgu 0 input":0 -> "ipu3-imgu 0":0[1]
media-ctl -d $MDEV -l "ipu3-imgu 0":2 -> "ipu3-imgu 0 output":0[1]
media-ctl -d $MDEV -l "ipu3-imgu 0":3 -> "ipu3-imgu 0 viewfinder":0[1]
media-ctl -d $MDEV -l "ipu3-imgu 0":4 -> "ipu3-imgu 0 3a stat":0[1]

対応するV4L2 subdevのパイプラインモードは、制御ID 0x009819a1を介して望む設定（例：ビデオモードには0、スタイリモードには1）に設定する必要があります。

yavta -w "0x009819A1 1" /dev/v4l-subdev7

ImgUパイプライン内の一部ハードウェアブロックは、クロッピングやスケーリングによってフレーム解像度を変更できます。このハードウェアブロックには、入力フィーダー（IF）、Bayerダウンスケーラー（BDS）、幾何学的歪み補正（GDC）が含まれます。また、フレーム解像度を変更できるブロックとしてYUVスケーラーもあり、これはセカンダリ出力にのみ適用されます。

RAW BayerフレームはこれらのImgUパイプラインハードウェアブロックを経て、最終的な処理後の画像がDDRメモリに出力されます。

入力フィーダー

入力フィーダーはセンサーからBayerフレームデータを取得し、フレームからラインやカラムのクロッピングを有効にした後、デバイスの内部ピクセルバッファにピクセルを保存します。これにより、後続のブロックが読み出すことができます。

Bayerダウンスケーラー

BayerダウンスケーラーはBayerドメインでの画像スケーリングを実行できます。各軸で1Xから1/4Xのダウンスケーリングを設定可能で、設定ステップは0.03125（1/32）です。

幾何学的歪み補正

幾何学的歪み補正は歪みの補正と画像フィルタリングを行います。追加のフィルタとエンベロープパディングピクセルが必要なので、GDCの入力解像度は出力解像度より大きくなければなりません。

YUVスケーラー

BDSと似たYUVスケーラーですが、主にYUVドメインでの画像ダウンスケーリングを実行します。1/12Xまでのダウンスケーリングをサポートしますが、メイン出力には適用できません。

ImgU V4L2 subdevは、上述のすべてのハードウェアブロックでサポートされる解像度を設定する必要があります。指定された入力解像度に対して、入力フィーダー、Bayerダウンスケーラー、GDCブロックはそれぞれのハードウェアブロックのアライメント要件に応じてサポートされる解像度で設定する必要があります。

ハードウェアブロックの出力解像度を、ハードウェア要件を満たしつつ最大のフィールドオブビューを保持するように賢く設定する必要があります。中間解像度は特定のツールを使用して生成できます。

https://github.com/intel/intel-ipu3-pipecfg

このツールは中間解像度を生成するために使用できます。詳細は以下のIPU3 ImgU設定テーブルを参照してください。

https://chromium.googlesource.com/chromiumos/overlays/board-overlays/+/master

baseboard-poppy/media-libs/cros-camera-hal-configs-poppy/files/gcss ディレクトリ内にある graph_settings_ov5670.xml を例として使用できます。

以下の手順は、画像処理用の ImgU パイプラインを準備します。

1. ImgU V4L2 subdev のデータ形式は、上記で取得した GDC の幅と高さを使用して、pad 0 で VIDIOC_SUBDEV_S_FMT を使用して設定する必要があります。

2. ImgU V4L2 subdev のクロッピングは、pad 0 で VIDIOC_SUBDEV_S_SELECTION を使用し、V4L2_SEL_TGT_CROP をターゲットとして、入力フィーダーの高さと幅を使用して設定する必要があります。

3. ImgU V4L2 subdev のコンポジットは、pad 0 で VIDIOC_SUBDEV_S_SELECTION を使用し、V4L2_SEL_TGT_COMPOSE をターゲットとして、BDS の高さと幅を使用して設定する必要があります。

ov5670 の例では、入力フレームの解像度が 2592x1944（これは ImgU subdev pad 0 に入力されます）の場合、入力フィーダー、BDS、GDC に対応する解像度はそれぞれ 2592x1944、2592x1944、2560x1920 です。

この手順を完了した後、受信した RAW Bayer フレームは、オープンソースアプリケーション v4l2n を使用して ImgU V4L2 subdev に以下のように入力できます。 2.

2592x1944 で撮影された画像の場合、 5 解像度が 2560x1920 で出力したい場合、viewfinder 解像度も 2560x1920 に設定するには、以下の v4l2n コマンドを使用できます。これにより、RAW Bayer フレームを処理し、メイン出力画像と viewfinder 出力のどちらにも望ましい結果を NV12 フォーマットで生成します。

v4l2n --pipe=4 --load=/tmp/frame-#.bin --open=/dev/video4
      --fmt=type:VIDEO_OUTPUT_MPLANE,width=2592,height=1944,pixelformat=0X47337069 \
      --reqbufs=type:VIDEO_OUTPUT_MPLANE,count:1 --pipe=1 \
      --output=/tmp/frames.out --open=/dev/video5 \
      --fmt=type:VIDEO_CAPTURE_MPLANE,width=2560,height=1920,pixelformat=NV12 \
      --reqbufs=type:VIDEO_CAPTURE_MPLANE,count:1 --pipe=2 \
      --output=/tmp/frames.vf --open=/dev/video6 \
      --fmt=type:VIDEO_CAPTURE_MPLANE,width=2560,height=1920,pixelformat=NV12 \
      --reqbufs=type:VIDEO_CAPTURE_MPLANE,count:1 --pipe=3 --open=/dev/video7 \
      --output=/tmp/frames.3A --fmt=type:META_CAPTURE,? \
      --reqbufs=count:1,type:META_CAPTURE --pipe=1,2,3,4 --stream=5

yavta を使用することもできます。 3 上記と同じことを行うコマンドは、

yavta --data-prefix -Bcapture-mplane -c10 -n5 -I -s2592x1944 \
      --file=frame-#.out-f NV12 /dev/video5 & \
yavta --data-prefix -Bcapture-mplane -c10 -n5 -I -s2592x1944 \
      --file=frame-#.vf -f NV12 /dev/video6 & \
yavta --data-prefix -Bmeta-capture -c10 -n5 -I \
      --file=frame-#.3a /dev/video7 & \
yavta --data-prefix -Boutput-mplane -c10 -n5 -I -s2592x1944 \
      --file=/tmp/frame-in.cio2 -f IPU3_SGRBG10 /dev/video4

ここで、/dev/video4、/dev/video5、/dev/video6、/dev/video7 はそれぞれ入力、出力、viewfinder、3A 統計のビデオノードを指します。

6.9.4.3. RAW Bayer 画像を YUV ドメインに変換する¶

上記の手順で処理された画像は、以下の通り YUV ドメインに変換できます。

6.9.4.3.1. メイン出力フレーム¶

raw2pnm -x2560 -y1920 -fNV12 /tmp/frames.out /tmp/frames.out.ppm

2560x1920 は出力解像度、NV12 はビデオフォーマットで、その後に入力フレームと出力 PNM ファイルが続きます。

6.9.4.3.2. viewfinder 出力フレーム¶

raw2pnm -x2560 -y1920 -fNV12 /tmp/frames.vf /tmp/frames.vf.ppm

2560x1920 は出力解像度、NV12 はビデオフォーマットで、その後に入力フレームと出力 PNM ファイルが続きます。

6.9.6. IPU3 パイプラインの概要¶

IPU3パイプラインには、それぞれが入力としてパラメータのセットを受ける画像処理ステージが複数あります。パイプラインの主要なステージは以下の通りです。

以下の表は上記のアルゴリズムについての説明を示しています。

名前

説明

光学ブラック補正

光学ブラック補正ブロックは、それぞれのピクセル値から事前に定義された値を減算し、画像品質を向上させます。定義は struct ipu3_uapi_obgrid_param.

線形化

このアルゴリズムブロックは、線形化パラメータを使用してセンサーの非線形性の影響を補正します。参照は struct ipu3_uapi_isp_lin_vmem_params.

SHD

レンズシャドウ補正は、光学レンズシャドウによるピクセル応答の空間的非均一性を補正するために使用されます。これは各ピクセルに対して異なるゲインを適用することで実現されます。ゲイン、ブラックレベルなどは struct ipu3_uapi_shd_config_static.

BNR

バエイヤノイズ除去ブロックは、バイラテラルフィルタを適用して画像ノイズを除去します。参照は struct ipu3_uapi_bnr_static_config 詳しくは以下をご参照ください。

ANR

Advanced Noise Reduction（ANR）は、バエイヤドメインでノイズ除去を行うブロックベースのアルゴリズムです。畳み込み行列などは struct ipu3_uapi_anr_config.

DM

デモサイシングは、RAWセンサーのバエイヤ形式データをRGB（赤、緑、青）形式に変換します。その後、ファームウェアによる次のストリーム処理のためにYチャネルの推定出力を追加します。構造体は struct ipu3_uapi_dm_config.

カラーブラック補正

カラーブラック補正アルゴリズムは、センサーサーフェース固有のカラースペースを標準の「sRGB」カラースペースに変換します。これは3×3行列を適用することで実現されます。定義は struct ipu3_uapi_ccm_mat_config.

ガンマ補正

ガンマ補正 struct ipu3_uapi_gamma_config は、各ピクセルごとにピクセルコンポーネントごとに適用される基本的な非線形トーンマッピング補正です。

CSC

カラースペース変換は、各ピクセルをRGBの主な表示からYUV（Y：明るさ、UV：輝度）の表示に変換します。これは3×3行列を適用することで実現されます。定義は struct ipu3_uapi_csc_mat_config

CDS

クロマダウンサンプリング CSCが実行された後、UV平面をYUV 4:2:0で各方向に2倍のファクターでダウンサンプリングするためにクロマダウンサンプリングが適用されます。4×2の設定可能なフィルタを使用します。 struct ipu3_uapi_cds_params.

CHNR

クロマノイズ除去 このブロックはクロマインスのピクセルのみを処理し、高周波ノイズをクリーンアップすることでノイズ除去を行います。参照は構造体 ipu3_uapi_yuvp1_chnr_config。

TCC

トータルカラーブラック補正は構造体 ipu3_uapi_yuvp2_tcc_static_config で定義されています。

XNR3

eXtreme Noise Reduction V3 は画像品質を改善するために使用されるノイズ除去アルゴリズムの第3版です。これはキャプチャされた画像の低周波ノイズを除去します。関連する構造体は以下の通りです、 struct ipu3_uapi_isp_xnr3_params ISPデータメモリ用 struct ipu3_uapi_isp_xnr3_vmem_params ベクターメモリ用。

TNR

テンポラルノイズ除去ブロックは、時間的に連続するフレームを比較してピクセル値の異常/ノイズを除去します。 struct ipu3_uapi_isp_tnr3_vmem_params および struct ipu3_uapi_isp_tnr3_params は、ISPベクタとデータメモリそれぞれに対して定義されています。

個々のアルゴリズムのACCパラメータは、 struct ipu3_uapi_acc_paramで定義されており、ユーザー空間が適用するように選択できます。struct ipu3_uapi_flagsが埋め込まれた struct ipu3_uapi_params 構造体において、ユーザー空間で無効に設定されたパラメータについては、ドライバは対応する構造体を無視し、その場合アルゴリズムの既存の設定が保持されます。
