6.17. Rockchip Image Signal Processor (rkisp1)¶

6.17.1. はじめに¶

このファイルは、RK3288およびRK3399 SoCに含まれるRockchip ISP1用ドライバのドキュメンテーションです。ドライバはdrivers/staging/media/rkisp1配下にあり、Media-Controller APIを使用しています。

6.17.2. トポロジー¶

ドライバには4つのビデオデバイスがあります：

  • rkisp1_mainpath: 高解像度で画像を取得するキャプチャデバイス。

  • rkisp1_selfpath: 画像を取得するキャプチャデバイス。

  • rkisp1_stats: ステータス情報を送信するメタデータキャプチャデバイス。

  • rkisp1_params: ユーザースペースからパラメータ設定を受信するメタデータ出力デバイス。

ドライバには3つのサブデバイスがあります：

  • rkisp1_resizer_mainpath: メインパスキャプチャデバイスのフレームをリサイズ・ダウンサンプリングするためのサブデバイス。

  • rkisp1_resizer_selfpath: セルフパスキャプチャデバイスのフレームをリサイズ・ダウンサンプリングするためのサブデバイス。

  • rkisp1_isp: センサに接続され、すべての画像処理（ISP）操作を担当するサブデバイス。

6.17.2.1. rkisp1_mainpath, rkisp1_selfpath - フレームキャプチャビデオノード¶

これらは mainpath および selfpath キャプチャデバイスでフレームをキャプチャします。これらはDMAエンジンで、フレームをメモリに書き込みます。セルフパスビデオデバイスはYUV/RGB形式のキャプチャが可能です。入力はYUV符号化ストリームで、RGBへの変換も可能です。セルフパスはバヤー形式のキャプチャはできません。メインパスはバヤーおよびYUV形式のキャプチャが可能ですが、RGB形式のキャプチャはできません。どちらのキャプチャビデオも V4L2_CAP_IO_MC capability.

6.17.2.2. rkisp1_resizer_mainpath, rkisp1_resizer_selfpath - リサイズサブデバイスノード¶

これらはメインパスおよびセルフパス用のリサイズエンティティです。これらはフレームを拡大・縮小し、YUVサンプリング（例：YUV4:2:2 → YUV4:2:0）を変更できます。また、シンクピンでのクロッピング機能も持ちます。リサイズエンティティはYUV:4:2:2形式（MEDIA_BUS_FMT_YUYV8_2X8）のみ処理可能です。メインパスキャプチャデバイスはバヤー形式のビデオキャプチャをサポートしており、その場合メインパスのリサイズは「バイパス」モードに設定され、フレームをそのまま転送します。

6.17.2.3. rkisp1_isp - 画像信号処理サブデバイスノード¶

これはISPエンティティです。シンクピン0にセンサに接続され、CSI-2プロトコルでフレームを受信します。CSI-2プロトコルの設定を担当します。シンクピン0（センサに接続）およびソースピン2（リサイズエンティティに接続）にクロッピング機能を持ちます。シンクピン0のクロッピングはセンサからの画像領域を定義し、ソースピン2のクロッピングは画像安定化（IS）の領域を定義します。

6.17.2.4. rkisp1_stats - 統計ビデオノード¶

統計ビデオノードは、rkisp1で処理されているフレームの3A（オートフォーカス、オートエキスポージャー、オートホワイトバランス）統計およびヒストグラム統計をユーザースペースアプリケーションに出力します。これらのデータを用いて、アプリケーションはrkisp_paramsノードを通じてドライバの再パラメータ化を行い、ビデオストリーム中の画像品質を向上させることができます。バッファ形式はstructで定義されています rkisp1_stat_buffer、ユーザースペースは V4L2_META_FMT_RK_ISP1_STAT_3A をデータフォーマットとして設定する必要があります。

6.17.2.5. rkisp1_params - パラメータビデオノード¶

rkisp1_paramsビデオノードは、ビデオストリーム中にハードウェアに適用されるパラメータをユーザースペースから受け取り、ブラックレベル、クロストーク補正などの値を動的に変更できるようにします。

バッファ形式はstructで定義されています rkisp1_params_cfg、ユーザースペースは 、V4L2_META_FMT_RK_ISP1_PARAMS をデータフォーマットとして設定する必要があります。

6.17.3. ビデオフレームのキャプチャ例¶

次の例では、'rkisp1_isp'のパッド0に接続されているセンサーはimx219です。

次のコマンドは、次元が900x800でプランナーフォーマットYUV 4:2:2のビデオをselfpathビデオノードからキャプチャするために使用できます。これはすべてのクロッピング機能を活用しています（以下の説明を参照してください）

# set the links
"media-ctl" "-d" "platform:rkisp1" "-r"
"media-ctl" "-d" "platform:rkisp1" "-l" "'imx219 4-0010':0 -> 'rkisp1_isp':0 [1]"
"media-ctl" "-d" "platform:rkisp1" "-l" "'rkisp1_isp':2 -> 'rkisp1_resizer_selfpath':0 [1]"
"media-ctl" "-d" "platform:rkisp1" "-l" "'rkisp1_isp':2 -> 'rkisp1_resizer_mainpath':0 [0]"

# set format for imx219 4-0010:0
"media-ctl" "-d" "platform:rkisp1" "--set-v4l2" '"imx219 4-0010":0 [fmt:SRGGB10_1X10/1640x1232]'

# set format for rkisp1_isp pads:
"media-ctl" "-d" "platform:rkisp1" "--set-v4l2" '"rkisp1_isp":0 [fmt:SRGGB10_1X10/1640x1232 crop: (0,0)/1600x1200]'
"media-ctl" "-d" "platform:rkisp1" "--set-v4l2" '"rkisp1_isp":2 [fmt:YUYV8_2X8/1600x1200 crop: (0,0)/1500x1100]'

# set format for rkisp1_resizer_selfpath pads:
"media-ctl" "-d" "platform:rkisp1" "--set-v4l2" '"rkisp1_resizer_selfpath":0 [fmt:YUYV8_2X8/1500x1100 crop: (300,400)/1400x1000]'
"media-ctl" "-d" "platform:rkisp1" "--set-v4l2" '"rkisp1_resizer_selfpath":1 [fmt:YUYV8_2X8/900x800]'

# set format for rkisp1_selfpath:
"v4l2-ctl" "-z" "platform:rkisp1" "-d" "rkisp1_selfpath" "-v" "width=900,height=800,"
"v4l2-ctl" "-z" "platform:rkisp1" "-d" "rkisp1_selfpath" "-v" "pixelformat=422P"

# start streaming:
v4l2-ctl "-z" "platform:rkisp1" "-d" "rkisp1_selfpath" "--stream-mmap" "--stream-count" "10"

上の例ではセンサーがバエイヤーフォーマットで設定されています： SRGGB10_1X10/1640x1232。rkisp1_isp:0パッドはセンサーと同じmbusフォーマットと寸法に設定する必要があります。それ以外の場合、ストリーミングは'EPIPE'エラーで失敗します。したがって、これも SRGGB10_1X10/1640x1232に設定されています。 (0,0)/1600x1200.

さらに、rkisp1_isp:0パッドはクロッピングを設定されています クロッピング寸法は自動的にISPソースパッドの形式に伝播されますrkisp1_isp:2 (0,0)/1500x1100.

。また、ISPソースパッドにもクロッピング操作が設定されています： リザイザーのシンクパッド rkisp1_resizer_selfpath は、リンクの他側のフォーマットと一致するように YUYV8_2X8/1500x1100 (300,400)/1400x1000 に設定する必要があります。さらにクロッピングが設定されています。

リザイザーのソースパッド、 rkisp1_resizer_selfpath:1 は、 YUYV8_2X8/900x800に設定されています。つまり、リザイザーは受信したフレームから最初に (300,400)/1400x100 のウィンドウをクロッピングし、その後このウィンドウを寸法 900x800.

にスケーリングします。注意点として、上の例ではstats-params制御ループを使用していません。そのためキャプチャフレームは3Aアルゴリズムを通過せず、品質が良くない可能性があり、暗く緑っぽく見えるかもしれません。

6.17.4. 量子化の設定¶
