ABI削除シンボル¶

/sys/bus配下のシンボル¶

/sys/bus/nd/devices/regionX/nfit/ecc_unit_size

ファイルで定義されています sysfs-bus-nfit

(RO) DIMMへの書き込み要求のサイズ。メモリコントローラーで読み込み-変更-書き込みサイクルを発生させない場合。

nfitドライバが初期化される際には、pmem範囲全体でARS（Address Range Scrub）操作が実行されます。このプロセスの一部として、指定されたアドレス範囲のARS能力を判定する必要があります。報告される能力の一つが「Clear Uncorrectable Error Range Length Unit Size」（参照：ACPI 6.2 第9.20.7.4節 Function Index 1 - Query ARS Capabilities）です。このプロパティは、NVDIMMがECC（Error Correcting Code）ブロックを維持するために読み込み-変更-書き込みサイクルを実行する境界を示します。

/sys/class以下に存在するシンボル¶

/sys/class/rfkill/rfkill[0-9]+/claim

ファイルで定義されています sysfs-class-rfkill

このファイルは、単一のrfkillインスタンスの制御権のみを取得する方法がなくなったため非推奨となりました。このファイルは2012年に削除予定でしたが、2016年に実際に削除されました。値：0: カーネルがイベントを処理

sysfsの下にあるシンボル¶

/sys/kernel/fadump_release_opalcore

ファイルで定義されています sysfs-kernel-fad,ump_release_opalcore

書き込み専用。システムがOPALベースのマシンで起動したときにsysfsファイルが利用可能となり、opalcoreの収集に使用されるメモリを解放するために使用されます。

/sys/kernel/uids/<uid>/cpu_shares

ファイルで定義されています sysfs-kernel-uids

以下の /sys/kernel/uids/<uid>/cpu_shares tunableはユーザーが許可されるCPU帯域幅を設定するために使用されます。これは比例値です。これは、2人のユーザーがログインしており、それぞれのsharesが等しい場合、同等のCPU帯域幅を獲得することを意味します。もう一つの例は、ユーザーAがshares=1024で、ユーザーBがshares=2048の場合、ユーザーBはユーザーAの2倍のCPU帯域幅を獲得することです。詳細については CFSスケジューラ

/sys/o2cb以下のシンボル¶

/sys/o2cbシンボリックリンク

ファイルで定義されています o2cb

これは、/sys/o2cbを /sys/fs/o2cbにリンクするシンボリックリンクです。新しいバージョンのocfs2-toolsが /sys/fs/o2cbを参照するようになった場合、このシンボリックリンクは削除されます。新しいソフトウェアはここを参照しないでください。代わりに /sys/fs/o2cbを参照してください。

ユーザー: ocfs2-tools。変更提案は ocfs2-devel@oss.oracle.com.

devfs¶

devfs

ファイルで定義されています devfs

devfsは数年間メンテナンスされておらず、修正不可能な競合条件を含み、カーネル内の命名ポリシーがLSBに反しており、udevを使用することで置き換えることができます。

fs/devfs/以下のファイル, include/linux/devfs_fs.hは、カーネルツリー全体の assorted devfs関数呼び出しとともに削除されました。

dv1394以下のシンボル¶

dv1394（a.k.a. 「OHCI-DV I/Oサポート」for FireWire）

ファイルで定義されています dv1394

/dev/dv1394/*はキャラクタデバイスファイルであり、それぞれのFireWireコントローラーおよびNTSCとPALに対応するためのもので、DVデータをread()で受信したりwrite()で送信したりすることができました。いくつかのioctl()は制御を可能にしました。この特殊なインターフェースは、機能的に同等でHDVをサポートし、新しいFireWireカーネルドライバ上でも透過的に動作するlibraw1394 + libiec61883によって代替されています。

ユーザー:

ffmpeg/libavformat（DV1394で構成される場合）

ip_queue¶

ip_queue

ファイルで定義されています ip_queue

ip_queueはnfnetlink_queueによって代替され、ユーザー空間により高度なキューイングメカニズムを提供します。ip_queueモジュールはすでに何年も前から廃止される予定とアナウンスされていました。

raw1394に関するシンボル¶

raw1394（FireWire用の「Raw IEEE1394 I/Oサポート」）

ファイルで定義されています raw1394

/dev/raw1394はFireWireバスへの低レベルアクセスを可能にするキャラクタデバイスファイルでしたが、デバイスセキュリティポリシーの実装が困難で、抽象化レベルが低いため、ユーザー空間クライアントがカーネルのieee1394コア機能を再実装する必要がありました。

代わりに/dev/fw*（firewire-coreの<linux/firewire-cdev.h> ABI）が導入されました。

ユーザー:

libraw1394（firewire-cdevにも対応し、ライブラリABIユーザーには透過的）

tcp_dma_copybreak sysctl¶

tcp_dma_copybreak sysctl

ファイルで定義されています net_dma

以前は、DMAコピーエンジンにオフロードされるソケット読み取りのサイズの下限（バイト単位）でしたが、CPUがDMA実行中にもかかわらずバッファにアクセスする可能性があるため、一貫性の問題から削除されました。

video1394（FireWire用の「OHCI-1394 Videoサポート」）¶

video1394（FireWire用の「OHCI-1394 Videoサポート」）

ファイルで定義されています video1394

/dev/video1394/*は、それぞれのFireWireコントローラー用のキャラクタデバイスファイルで、イソクロナスI/Oに使用されていました。これはraw1394のイソクロナスI/O機能の代替として追加され、初期バージョンではパフォーマンスの問題があったためです。video1394のユーザーは、video1394がデバイスの発見や設定に非同期I/Oを提供しないため、raw1394 + libraw1394を併用する必要がありました。

代わりに/dev/fw*（firewire-coreの<linux/firewire-cdev.h> ABI）が導入されました。

ユーザー:

libdc1394（firewire-cdevにも対応し、ライブラリABIユーザーには透過的）
