zram: 圧縮RAMベースのブロックデバイス¶

はじめに¶

zramモジュールは、/dev/zram<id> (<id> = 0, 1, …) という名前のRAMベースのブロックデバイスを生成します。これらのディスクに書かれたページはメモリ内に圧縮されて保存されます。これらのディスクは非常に高速なI/Oを可能とし、圧縮により十分なメモリ節約が可能です。使用例には/tmpストレージ、スワップディスクとしての利用、/var以下の各種キャッシュ、あるいはそれ以外の用途も含まれます。

個々のzramデバイスの統計情報は、/sys/block/zram<id>/ にあるsysfsノードを通じてエクスポートされます。

使い方¶

zramデバイスの構成および管理にはいくつかの方法があります：

  1. zramおよびzram_control sysfs属性を使用して

  2. util-linuxが提供するzramctlユーティリティを使用して、util-linux@vger.kernel.org).

このドキュメントでは、'手動' zram構成ステップのみを説明します。つまり、zramおよびzram_control sysfs属性に焦点を当てます。

zramctlについての詳細な情報が必要な場合は、util-linuxドキュメンテーション、zramctl manページ、または zramctl –helpをご参照ください。zramのメンテナはutil-linuxやzramctlの開発・メンテナンスを行っていません。質問等があれば、 util-linux@vger.kernel.org

zramの使用に必要な典型的なステップシーケンスを以下に示します。

警告¶

簡潔さのため、以下の例ではエラーチェックの部分を省略しています。ただし、エラー処理はユーザーの責任です。

zram sysfs属性はエラーの場合常に負の値を返します。可能な返却コードの一覧:

-EBUSY

デバイスが初期化された後は変更できない属性を変更しようとしたため。まずデバイスをリセットしてください。

-ENOMEM

zramはあなたの要件を満たすための十分なメモリを確保できませんでした。

-EINVAL

無効な入力が提供されました。

echoを使用する場合、返された値はechoユーティリティによって設定され、一般的なケースでは次のようになります:

echo 3 > /sys/block/zram0/max_comp_streams
if [ $? -ne 0 ]; then
        handle_error
fi

これで十分です。

1) モジュールをロード¶

modprobe zram num_devices=4

これにより4つのデバイスが作成されます: /dev/zram{0,1,2,3}

num_devicesパラメータはオプションで、zramに事前に作成するデバイスの数を指定します。デフォルト: 1。

2) 最大圧縮ストリーム数を設定¶

この属性に渡された値に関係なく、ZRAMは常に複数の圧縮ストリームを割り当てます（オンラインのCPUごとに1つずつ）これにより複数の同時圧縮操作が可能になります。一部のCPUがオフラインになると割り当てられたストリーム数は減少します。単一の圧縮ストリームモードは、UPシステムを実行しているか、オンラインのCPUが1つだけの場合を除いて廃止されました。

現在利用可能なストリーム数を確認するには:

cat /sys/block/zram0/max_comp_streams

3) 圧縮アルゴリズムを選択¶

comp_algorithmデバイス属性を使用することで、利用可能な圧縮アルゴリズムと現在選択されているアルゴリズム（括弧内に表示）を確認したり、選択されている圧縮アルゴリズムを変更したりできます（デバイスが初期化された後は、圧縮アルゴリズムの変更が不可能です）。

例:

#show supported compression algorithms
cat /sys/block/zram0/comp_algorithm
lzo [lz4]

#select lzo compression algorithm
echo lzo > /sys/block/zram0/comp_algorithm

現時点では、 comp_algorithm コンテンツは、カーネルがサポートするすべての圧縮アルゴリズムを必ずしも表示しません。このリストは主にデバイス設定を簡略化するためのものであり、リストにない圧縮アルゴリズムを指定して新しいデバイスを設定することも可能です。 comp_algorithmZRAMは内部的にCrypto APIを使用しており、一部のアルゴリズムがモジュールとして構築されている場合、/proc/cryptoや他の方法ですべてを一覧表示することはできません。ただし、この制限はカスタムな暗号化圧縮モジュール（S/WまたはH/W圧縮を実装）の利用を可能にする利点があります。

4) ディスクサイズの設定¶

sysfsノード「disksize」に値を書き込むことでディスクサイズを設定できます。値はバイト単位で指定するか、memサフィックスを使用することも可能です。例:

# Initialize /dev/zram0 with 50MB disksize
echo $((50*1024*1024)) > /sys/block/zram0/disksize

# Using mem suffixes
echo 256K > /sys/block/zram0/disksize
echo 512M > /sys/block/zram0/disksize
echo 1G > /sys/block/zram0/disksize

注意: メモリの2倍以上のzramを生成しても意味がありません。圧縮率が2:1を想定しているためです。zramは使用していないときにディスクサイズの約0.1%しか使用しないため、大きなzramは無駄です。

5) メモリ制限の設定: オプション¶

sysfsノード「mem_limit」に値を書き込むことでメモリ制限を設定できます。値はバイト単位で指定するか、memサフィックスを使用することも可能です。また、実行時にも値を変更できます。例:

# limit /dev/zram0 with 50MB memory
echo $((50*1024*1024)) > /sys/block/zram0/mem_limit

# Using mem suffixes
echo 256K > /sys/block/zram0/mem_limit
echo 512M > /sys/block/zram0/mem_limit
echo 1G > /sys/block/zram0/mem_limit

# To disable memory limit
echo 0 > /sys/block/zram0/mem_limit

6) アクティブ化¶

mkswap /dev/zram0
swapon /dev/zram0

mkfs.ext4 /dev/zram1
mount /dev/zram1 /tmp

7) zramデバイスの追加/削除¶

zramは動的（オンデマンド）でデバイスの追加と削除を可能にする制御インターフェースを提供しています。

新しい/dev/zramXデバイスを追加するには、hot_add属性に読み込み操作を行います。これにより、新しいデバイスのデバイスID（/dev/zram<id>を使用可能）が返されるか、エラーコードが返されます。

例:

cat /sys/class/zram-control/hot_add
1

既存の/dev/zramXデバイス（XはデバイスID）を削除するには以下のコマンドを実行します：

echo X > /sys/class/zram-control/hot_remove

ファイル /sys/block/zram<id>/stat

ブロックレイヤー統計情報を表します。読み取る ブロックレイヤー統計情報は /sys/block/<dev>/stat にあります 詳しくは以下をご参照ください。

ファイル /sys/block/zram<id>/io_stat

statファイルは、ブロックレイヤーでカウントされないデバイスのI/O統計を表します。したがって、zram<id>/statファイルには含まれません。これは1行のテキストで構成され、空白文字で区切られた以下の統計情報が含まれています：

failed_reads

failed_writes

invalid_io

notify_free

デバイスの使用シナリオに応じて、これは

スワップスロットの空き通知により解放されたページの数

REQ_OP_DISCARDリクエストにより解放されたページの数。前者は、スワップスロットが解放されるときにスワップブロックデバイスに送信され、これはこのディスクがスワップディスクとして使用されていることを示します。

スワップスロットの空き通知により解放されたページの数

  1. REQ_OP_DISCARDリクエストにより解放されたページの数。前者は、スワップスロットが解放されるときにスワップブロックデバイスに送信され、これはこのディスクがスワップディスクとして使用されていることを示します。

  2. REQ_OP_DISCARDリクエストにより解放されたページの数。前者は、スワップスロットが解放されるときにスワップブロックデバイスに送信され、これはこのディスクがスワップディスクとして使用されていることを示します。

後者は、discardオプションでマウントされたファイルシステムがデータブロックを破棄するたびに送信されます。

ファイル /sys/block/zram<id>/mm_stat

mm_statファイルは、デバイスのmm統計情報を表します。これは1行のテキストで構成され、空白文字で区切られた以下の統計情報が含まれています：

orig_data_size

このディスクに保存されている未圧縮データのサイズ。単位: バイト

compr_data_size

このディスクに保存されている圧縮データのサイズ

mem_used_total

このディスクに割り当てられたメモリの量。これはアロケータのフラグメンテーションとメタデータのオーバーヘッドを含むため、アロケータの空間効率はcompr_data_sizeとこの統計値を用いて計算できます。単位: バイト

mem_limit

ZRAMが圧縮データを保存するために使用できる最大メモリ量

mem_used_max

zramがデータを保存するために消費した最大メモリ量

same_pages

このディスクに書き込まれた同じ要素を含むページの数。このようなページにはメモリが割り当てられません。

pages_compacted

コンパクション中に解放されたページ数

huge_pages

圧縮不可能なページの数

ファイル /sys/block/zram<id>/bd_stat

bd_stat ファイルは、デバイスのバックイングデバイスの統計情報を表します。これは1行のテキストで構成され、空白文字で区切られた以下の統計情報が含まれています:

bd_count

バックイングデバイスに書かれたデータのサイズ。単位: 4Kバイト

bd_reads

バックイングデバイスからの読み込み回数。単位: 4Kバイト

bd_writes

バックイングデバイスへの書き込み回数。単位: 4Kバイト

9) 無効化¶

swapoff /dev/zram0
umount /dev/zram1

10) リセット¶

reset ノードに正の値を書き込むと:

echo 1 > /sys/block/zram0/reset
echo 1 > /sys/block/zram1/reset

指定されたデバイスに割り当てられたすべてのメモリを解放し、ディスクサイズをゼロに戻します。デバイスを再利用する前に、ディスクサイズを再度設定する必要があります。

オプション機能¶

writeback¶

CONFIG_ZRAM_WRITEBACK を有効にすると、zram はアイドル/圧縮不可能なページをメモリに保持せず、バックイングストレージに書き込むことができます。この機能を使用するには、管理者がバックイングデバイスを設定する必要があります。

echo /dev/sda5 > /sys/block/zramX/backing_dev

ディスクサイズの設定の前に設定する必要があります。現在はパーティションのみをサポートしています。管理者が圧縮不可能なページの書き戻しを使用したい場合は、以下のように設定できます。

echo huge > /sys/block/zramX/writeback

アイドルページの書き戻しを使用するには、まずユーザーが zram のページをアイドルとして宣言する必要があります:

echo all > /sys/block/zramX/idle

以降、zram 上のすべてのページはアイドルページになります。ブロックへのアクセスが要求されるまで、アイドルマークは削除されません。つまり、アクセス要求がない限り、これらのページは依然としてアイドルページのままです。

管理者は、適切なタイミングでこれらのアイドルページの書き戻しを要求できます:

echo idle > /sys/block/zramX/writeback

このコマンドにより、zram はメモリ内のアイドルページをストレージに書き戻します。

管理者が zram デバイス内の特定のページをバックイングデバイスに書き込む場合は、インターフェースにページインデックスを書き込むことができます。

echo "page_index=1251" > /sys/block/zramX/writeback

フラッシュデバイスで多数の書き込みIOがある場合、フラッシュの摩耗問題が発生する可能性があるため、管理者は書き込み制限を設計して、製品の寿命全体にわたるストレージの健康を保証する必要があります。

この懸念を解消するために、zram は「writeback_limit」機能をサポートしています。「writeback_limit_enable」のデフォルト値は 0 で、これにより書き戻しを制限しません。つまり、管理者が書き戻しの予算を適用したい場合は、以下のように writeback_limit_enable を有効化する必要があります:

$ echo 1 > /sys/block/zramX/writeback_limit_enable

writeback_limit_enable が設定されると、管理者が /sys/block/zramX/writeback_limit を介して予算を設定するまで、zram はすべての書き戻しを許可しません。

(管理者が writeback_limit_enable を有効にしない場合、/sys/block/zramX/writeback_limit を介して割り当てられた writeback_limit の値は意味を持ちません。)

管理者が 1 日あたり 400M の書き戻し制限を設定したい場合は、以下のように行うことができます:

$ MB_SHIFT=20
$ 4K_SHIFT=12
$ echo $((400<<MB_SHIFT>>4K_SHIFT)) > \
        /sys/block/zram0/writeback_limit.
$ echo 1 > /sys/block/zram0/writeback_limit_enable

管理者が予算が枯渇した後にも再度書き込みを許可したい場合、以下のように行うことができます：

$ echo $((400<<MB_SHIFT>>4K_SHIFT)) > \
        /sys/block/zram0/writeback_limit

管理者が最後に設定した以来の残りの書き戻し予算を確認したい場合：

$ cat /sys/block/zramX/writeback_limit

管理者が書き戻し制限を無効にする場合、以下のように行うことができます：

$ echo 0 > /sys/block/zramX/writeback_limit_enable

writeback_limitのカウントはzramをリセットするたびに（例：システム再起動、echo 1 > /sys/block/zramX/reset）リセットされます。したがって、zramをリセットするまでにどれだけ書き戻しが行われたかを次の設定時に追加の予算を割り当てるためにユーザーが管理する必要があります。

特定の期間における書き戻しカウントを測定したい場合、/sys/block/zram0/bd_statの3列目に確認できます。

メモリトラッキング¶

CONFIG_ZRAM_MEMORY_TRACKINGを有効にすると、ユーザーがzramブロックに関する情報を確認できます。これは*pagemapを用いてプロセスの冷たいページや圧縮不可能なページを特定するのに役立ちます。

この機能を有効にすると、/sys/kernel/debug/zram/zram0/block_stateからブロックの状態を確認できます。出力結果は以下の通りです：

300    75.033841 .wh.
301    63.806904 s...
302    63.806919 ..hi
最初の列

zramのブロックインデックス。

第二列

システム起動からのアクセス時間

第三列

ブロックの状態：

s:

同じページ

w:

バックストアに書き込まれたページ

h:

ヒープページ

i:

アイドルページ

上記の例の最初の行は、300番目のブロックが75.033841秒にアクセスされ、ブロックの状態がヒープページであるためバックストアに書き戻されていることを示しています。これはデバッグ機能であり、誰もこれに依存すべきではありません。
