セキュリティ関連のバグ¶

Linux カーネルの開発者たちはセキュリティを非常に真剣に扱います。そのため、セキュリティバグが発見された際には、それを迅速に修正し、公開するための情報を提供していただけますと幸いです。セキュリティバグについては、Linux カーネルセキュリティチームに報告してください。

お問い合わせ¶

Linux カーネルセキュリティチームは、メールで以下に連絡してください。security@kernel.org。これは、バグレポートの検証や修正の開発・公開を支援するセキュリティオフィサーのプライベートなリストです。既に修正策を持っている場合は、レポートに含めてください。これにより、処理が大幅に早まります。セキュリティチームは、関連するメンテナから追加の支援を受ける可能性もあります。

どのバグでも同様ですが、提供される情報が多ければ多いほど、診断・修正が容易になります。不明点がある場合は、以下の手順を確認してください。 バグの報告 エクスプロイットコードは非常に有用ですが、報告者から許可を得ない限り公開されません（既に公開されている場合は除きます）。

可能であれば、添付ファイルを避けた plain text のメールを送信してください。すべての詳細が添付ファイルに隠されている場合、複雑な問題について文脈を考慮した議論が困難になります。通常のパッチ送信（パッチを持っていなくても）のように考えましょう：問題と影響の説明、再現手順のリスト、そして提案された修正を plain text で記載してください。 通常のパッチ送信 (パッチを持っていなくても): 問題と影響の説明、再現手順のリスト、そして提案された修正を plain text で記載してください。

開示と制限付き情報¶

セキュリティリストは開示チャネルではありません。その場合は、以下の「調整」をご参照ください。

堅実な修正策が開発されたら、リリースプロセスが始まります。公開されているバグの修正は即座にリリースされます。

公開されていないバグの修正については、できるだけ早くリリースするのが我々の希望ですが、報告者または被害者からの要請により、リリースプロセス開始から7日間は延期されることがあります。ただし、バグの深刻さが理由でさらに時間がかかる場合、最大14日間の延長が認められることがあります。修正策の公開を延期する唯一の正当な理由は、QA（品質保証）や大規模な展開に必要なリリース調整のロジスティクスを考慮することです。

制限付き情報は、修正策の開発のために信頼できる個人と共有される場合がありますが、レポーターの許可なしに、修正策とともに公開されることや、他のどの開示チャネルにも掲載されることはありません。これは、元のバグレポートやフォローアップの議論（必要に応じて）、悪用方法、CVE情報やレポーターの身分など、含まれますが限らないものです。

言い換えれば、私たちの唯一の関心はバグの修正にあります。セキュリティリストに提出されたすべての情報や、レポートのフォローアップ議論は、制限が解除された後も永久に秘密保持されます。

調整¶

権限昇格を引き起こす可能性のある脆弱性など、敏感なバグの修正には、プライベートの<linux-distros>メーリングリストと調整する必要があります。これにより、アップストリームの修正が公開される際、ディストロベンダーが修正済みカーネルを迅速に配布できるよう準備を整えるためです。ディストロは提案されたパッチのテストに時間がかかるため、通常は少なくとも数日の制限期間を要求します。ベンダーのアップデート配布は火曜日から木曜日に好ましいです。必要に応じてセキュリティチームが調整を支援するか、レポーターが最初からlinux-distrosを含めるかを記載してください。この場合、linux-distrosウィキに記載されているように、メールの件名に『[vs]』を付けるのを忘れないでください: <linux-distros@vs.openwall.org>http://oss-security.openwall.org/wiki/mailing-lists/distros#how-to-use-the-lists>

CVEの割り当て¶

セキュリティチームは通常、CVEを割り当てることはありませんし、レポートや修正策にCVEを要求することもありません。これはプロセスを不必要に複雑にし、バグ処理を遅延させる可能性があるためです。レポーターが公表前にCVE識別子を割り当てることを希望する場合は、上記のプライベートlinux-distrosリストに連絡する必要があります。パッチが提供される前からCVE識別子がわかっている場合は、レポーターが同意する限り、コミットメッセージに記載することが望ましいです。

非開示合意¶

Linuxカーネルセキュリティチームは公式な機関ではありませんので、非開示合意を締結することができません。
