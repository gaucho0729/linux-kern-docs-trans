ブート時のRAIDアレイの自動検出¶

mdがカーネルに組み込まれている場合（モジュールとしてではなく）、タイプ0xfdのパーティションがスキャンされ、自動的にRAIDアレイにアセンブリされます。この自動検出はカーネルパラメータで抑制できます。 raid=noautodetectカーネル2.6.9以降では、タイプ0のスーパーブロックを持つドライブのみが自動検出され、ブート時に動作します。

カーネルパラメータ raid=partitionable (または raid=part) はすべての自動検出されたアレイがパーティション可能な状態でアセンブリされる事を意味します

ブート時の劣化/汚染アレイのアセンブリ¶

raid5またはraid6のアレイが同時に汚染（dirty）かつ劣化（degraded）している場合、検出不能なデータ破損が発生する可能性があります。これは、それが dirty パリティが信頼できないことを意味し、劣化しているということは、一部のデータブロックが欠落しており、パリティがないため信頼性のある再構築ができないことを意味します

このような理由で、mdは通常、このようなアレイの起動を拒否します。これは、システム管理者が可能なかさねを考慮しつつアレイを明示的に起動する必要があります。これは通常、以下のコマンドで行われます:

mdadm --assemble --force ....

このオプションは、アレイにルートファイルシステムが存在する場合、実質的に利用できません。このようなアレイからのブートをサポートするため、mdはモジュールパラメータをサポートしています start_dirty_degraded このパラメータを1に設定すると、チェックをバイパスし、汚染された劣化アレイを起動できるようになります

したがって、汚染された劣化raid5またはraid6のルートファイルシステムでブートするには、以下のコマンドを使用してください:

md-mod.start_dirty_degraded=1

スーパーブロック形式¶

mdドライバーはさまざまなスーパーブロック形式をサポートできます。現在、サポートしているスーパーブロック形式は以下の通りです 0.90.0 2.5開発シリーズで導入された形式です。 md-1 2.5開発シリーズで導入された形式です。

カーネルは使用されているスーパーブロック形式を自動検出します。

スーパーブロック形式 0 は遺産的な理由により他の形式とは異なり扱われます。これは元のスーパーブロック形式です。

一般的なルール - すべてのスーパーブロック形式に適用されます¶

配列は created すべてのデバイスに適切なスーパーブロックを書き込むことによって作成されます。

これは assembled これらのデバイスを特定のmd仮想デバイスに関連付けることによって実現されます。完全に組み立てられると、アクセス可能になります。

配列はユーザー空間のツールによって作成されるべきです。これによりすべてのデバイスにスーパーブロックが書き込まれ、通常は配列を uncleanアクティブにします。または一部のデバイスが欠落している状態で、カーネルのmdドライバが適切な冗長性（raid 1では複製、raid 4/5ではパリティ計算）を生成できるようにします。

配列が組み立てられると、最初にSET_ARRAY_INFO ioctlで初期化されます。これは特に、主バージョン番号とサブバージョン番号を含みます。主バージョン番号は使用されるスーパーブロック形式を指定し、サブバージョン番号は形式の処理を調整するために使用される可能性があります（例：スーパーブロックを各デバイスでどこに検索するかを示唆します）。

次に、ADD_NEW_DISK ioctlを使用して各デバイスが追加されます。これにより、追加するデバイスを特定する主バージョン番号とサブバージョン番号が提供されます。

配列はRUN_ARRAY ioctlで開始されます。

開始後、新しいデバイスを追加できます。これらには適切なスーパーブロックが書き込まれ、ADD_NEW_DISKに渡す必要があります。

故障したか、まだアクティブでないデバイスはHOT_REMOVE_DISKを使用して配列から分離できます。

format-0スーパーブロック配列およびスーパーブロックを持たない（非永続的）配列に適用される特定のルール¶

配列は created SET_ARRAY_INFO ioctlで配列（レベル、チャンクサイズなど）を記述することによって作成できます。これは major_version==0 および raid_disks != 0.

その後、未初期化のデバイスはADD_NEW_DISKで追加できます。ADD_NEW_DISKに渡す構造体にはデバイスの状態と配列内の役割を指定する必要があります。

RUN_ARRAYで開始後、未初期化のスパアはHOT_ADD_DISKで追加できます。

sysfs内のMDデバイス¶

mdデバイスはsysfs（/sys）に通常のブロックデバイスとして表示されます。例えば：

/sys/block/md0

Each md デバイスにはサブディレクトリ md が含まれ、これはデバイスに関するmd固有の情報です。

すべてのmdデバイスには以下の情報があります：

レベル

デバイスの raid levelを示すテキストファイル。例えばraid0、raid1、raid5、linear、multipath、faultyなど。まだraidレベルが設定されていない場合（配列がまだ組み立て中）、値は書き込まれた内容を反映します。これは上述の名前か、例えば 0, 5などの数値かもしれません。

raid_disks

完全に機能するアレイに含まれるデバイスの数を示す単純な数字を持つテキストファイルです。この値がまだわかっていない場合はファイルは空になります。アレイのサイズが変更されている場合は、新しいデバイス数が含まれます。一部のRAIDレベルでは、アレイがアクティブな状態でもこの値を設定することが可能です。これによりアレイの再構成が行われます。それ以外の場合は、アレイの構築中にのみ設定可能です。この属性の値を変更する際、アレイのサイズを小さくする可能性がある場合は許可されません。例えばRAID5でデバイス数を減らす際には、まずアレイサイズを設定してからデバイス数を減らす必要があります。 array_size 属性。

chunk_size

これは、 chunks のバイト数を示します。ストライピングを含むRAIDレベル（0、4、5、6、10）にのみ関係します。アレイのアドレス空間は論理的にチャンクに分割され、連続するチャンクは隣接するデバイスにストライプされます。サイズは少なくともPAGE_SIZE（4k）以上で、2の累乗である必要があります。アレイの構築中にのみ設定可能です

layout

以下の layout のためのレイアウトです。これは単純な数字であり、異なるRAIDレベルによって異なる解釈がされます。アレイの構築中にのみ書き込み可能です。

array_size

この属性は、アレイの利用可能なスペースを実際に結合されたデバイスの可用容量より小さく制限するのに使用できます。キロバイト単位の数字を設定し、その値が利用可能なサイズより小さい場合、アレイのサイズが設定されます。アレイの再構成（例：デバイスの追加）によってサイズは変更されません。'write'という単語を設定すると、アレイの有効なサイズが実際に利用可能なサイズに基づいて設定されます。 default を設定すると、アレイの有効なサイズが実際に利用可能なサイズに基づいて設定されます。 level, chunk_size および component_size.

この機能は、RAID4/5/6のデバイス数を減らす前にアレイのサイズを減らすために使用できます。また、外部メタデータ形式がこのような切り捨てを義務付ける場合にもサポートします。

reshape_position

これは、 none またはアレイのデバイス内のセクタ番号で、 reshape が到達できる範囲です。この値が設定されている場合、上記の3つの属性（raid_disks、chunk_size、layout）は古い値と新しい値の2つの値を持つ可能性があります。これらの値が異なる場合、属性の読み取りは以下のようになります：

new (old)

を返し、書き込みは new 値を適用し、 old を変更しません。

component_size

データ冗長性を持つアレイ（RAID0、ラインアレイ、故障アレイ、マルチパスを除く）では、すべてのコンポーネントが同じサイズでなければなりません（または少なくともすべてのコンポーネントがスペースを提供できるサイズが必要です）。これはアレイの幾何学的重要な部分です。セクタ単位で測定され、ここから読み取れます。この値に書き込むと、パーソナリティがサポートする場合（RAID1、RAID5、RAID6）かつコンポーネントドライブが十分大きい場合、アレイのサイズを変更することが可能です。

メタデータバージョン

これは、配列のメタデータを記録するために使用されている形式を示します。0.90（伝統的な形式）、1.0、1.1、1.2（さまざまな場所で使用される新しい形式）など、または none カーネルがメタデータを一切管理していないことを示します。代わりに、 external: ユーザー空間で設定された文字列が続く場合があります。これは、メタデータがユーザー空間のプログラムによって管理されていることを示します。デバイスの障害やその他のメタデータ更新が必要なイベントが発生すると、配列の活動はイベントが承認されるまで一時停止されます。

再同期開始

再同期を開始すべきポイントです。再同期が必要ない場合は、非常に大きな数（または none 2.6.30-rc1以降）。配列の作成時にデフォルトは0ですが、配列を「 clean で起動すると、この値ははるかに大きくなります。

new_dev

このファイルは読み取り専用で、書き込み可能です。書き込む値は主装置番号（major:minor）として、例えば8:0とします。これにより、そのデバイスが配列に接続され、利用可能であればmd/dev-XXX（デバイス名に応じて）に表示され、さらに構成が可能です。

安全モード遅延

md配列が特定の期間にわたって書き込み要求を受けていない場合、 cleanとマークされます。別の書き込み要求が到達すると、配列は dirty の前に書き込みを開始します。これは safe_modeの部分で、 certain period と呼ばれます。この値はこのファイルで秒数として設定され、デフォルトは200msec（0.200）です。0を書き込むと安全モードが無効になります。

配列状態

このファイルには、配列の現在の状態を示す単語が含まれています。多くの場合、状態は望ましい状態の単語を書き込むことで設定できますが、一部の状態は明示的に設定できない場合があり、一部の状態の変換は許可されていません。

Select/pollはこのファイルで動作します。アクティブ_IDLEとアクティブ（頻繁でほとんど意味のない変化）以外のすべての変化は通知されます。メタデータが外部で管理されている場合、アクティブ->アクティブ_IDLEの変化が報告されます。
