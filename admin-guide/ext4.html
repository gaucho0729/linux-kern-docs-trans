ext4 一般情報¶

Ext4 は ext3 ファイルシステムの進化版で、大容量のファイルシステム（64ビット）をサポートするための拡張性と信頼性の向上を実現しています。ディスク容量の増加と最新の機能要件に応じて設計されています。

メールリスト: linux-ext4@vger.kernel.org ウェブサイト: http://ext4.wiki.kernel.org

簡単な使用方法¶

注意: ext4 の開始にあたり詳細な情報を得るには、以下の URL にある ext4 ウィキサイトをご覧ください: http://ext4.wiki.kernel.org/index.php/Ext4_Howto

  • 最新版の e2fsprogs は以下の URL で入手可能です:

    https://www.kernel.org/pub/linux/kernel/people/tytso/e2fsprogs/

    または

    http://sourceforge.net/project/showfiles.php?group_id=2406

    または最新版の git リポジトリを以下から取得してください:

https://git.kernel.org/pub/scm/fs/ext2/e2fsprogs.git

  • ext4 ファイルシステムタイプを使用して新しいファイルシステムを作成:

    # mke2fs -t ext4 /dev/hda1

    既存の ext3 ファイルシステムを拡張属性をサポートするものに変更:

    # tune2fs -O extents /dev/hda1

    128バイトの inode で作成されたファイルシステムは、256バイトに変換して効率を向上させることができます:

    # tune2fs -I 256 /dev/hda1

  • マウント:

    # mount -t ext4 /dev/hda1 /wherever

  • 他のファイルシステムと比較する際には、複数のワークロードを試すことが重要です。しばしば、ワークロードパラメータの微妙な変更で、ファイルシステムの順位が大きく変わります。ext3 と比較する際には、ext4 はデフォルトで書き込みバリアを有効にし、ext3 はデフォルトで無効です。そのため、公平な比較を行うには、ext3 と ext4 の両方で '-o barriers=[0|1]' マウントオプションを明示的に指定することをお勧めします。ext3 のベンチマーク結果を最適化する際には、データジャーナリングモードを変更するのも有効です。'-o data=writeback' は一部のワークロードでは速く動作します。（ただし、data=writeback でマウントすると、不完全なシャットダウンの際に最近のファイルに古いデータが残る可能性があり、これはセキュリティ上のリスクとなる場合があります。）メタデータに重いワークロードでは、大容量のジャーナルでファイルシステムを構成するのも役立ちます。

機能¶

現在利用可能¶

  • 16TB を超えるファイルシステムの使用が可能（e2fsprogs のサポートはまだ未実装）

  • 拡張属性形式によりメタデータのオーバーヘッドが削減（RAM、IOアクセス、トランザクション）

  • 拡張属性形式は、磁気的な破損に対してマジック値によりより堅牢です

  • 木構造内の内部冗長性

  • 改善されたファイル割当（マルチブロック割当）

  • i_links_count[1] による32000サブディレクトリ制限の解除

  • mtime, atime, ctime, create time にナノ秒単位のタイムスタンプ

  • ディスク上の inode バージョンフィールド（NFSv4, Lustre）

  • uninit_bg 機能により e2fsck 時間が短縮

  • ジャーナルチェックサムにより堅牢性とパフォーマンスの向上

  • 永続的なファイルの事前割当て（例：ストリーミングメディア、データベースなど）

  • flex_bg機能によりビットマップとインノデテーブルをより大きな仮想グループにパックする機能

  • 大容量ファイルサポート

  • flex_bg機能を活用した大容量仮想ブロックグループによるインノデ割当て

  • 遅延割当て

  • 大容量ブロック（ページサイズまで）サポート

  • JBD2およびext4における効率的な新しい順序モード（バッファヘッドを使用せずに順序を強制するのを避ける）

  • 大文字小文字を区別しないファイル名検索

  • ファイルベースの暗号化サポート（fscrypt）

  • ファイルベースの検証サポート（fsverity）

[1] ブロックサイズが1KBのファイルシステムでは、ディレクトリハッシュツリーの最大深さが2に制限されるため、性能上の制限が生じる可能性があります。

大文字小文字を区別しないファイル名検索¶

大文字小文字を区別しないファイル名検索機能は、ディレクトリ単位で有効化可能です。これにより、同じファイルシステム内に大文字小文字を区別しないディレクトリと区別するディレクトリを混在させることができます。この機能は、空のディレクトリの+Fインノデ属性を反転することで有効化します。大文字小文字を区別しない文字列マッチ操作は、テキストがバイト列でどのようにエンコードされているかを知っている場合にのみ定義されます。そのため、大文字小文字を区別しないディレクトリを有効にするには、ファイルシステムがcasefold機能を備えている必要があります。この機能は、ファイルシステム全体で使用されるエンコードモデルを保存します。デフォルトでは、Unicode（この執筆時点ではバージョン12.1.0）の最新版がUTF-8形式で採用されます。比較アルゴリズムは、Unicodeで定義された正規化分解形式に文字列を正規化した後、バイト単位で比較する形で実装されます。

大文字小文字を区別しない機能はディスク上では名前を保持するため、ユーザー空間から提供されるファイル名はディスクに実際に書き込まれたものとバイト単位で一致します。カーネルが使用するUnicode正規化形式は内部表現であり、ユーザー空間やディスクには露出されません。ただし、大規模な大文字小文字を区別しないディレクトリで使用されるディスクハッシュは例外です。DX機能を持つディレクトリでは、ファイル名のcasefoldedバージョンを使用してハッシュを計算する必要があります。つまり、正規化形式の使用は、ディレクトリエントリが保存される場所に実際に影響を及ぼします。

ファイル名を不透明なバイト列としてではなく、エンコードされた文字列として見るよう変更する際、プログラムが無効な名前でファイルを作成しようとした場合の処理を考慮する必要があります。カーネル内のUnicodeサブシステムは、この場合の処理をファイルシステムに委譲しており、ファイルシステムは厳格モードを有効/無効にすることによってその動作を選択します。Ext4がこのような文字列に遭遇し、ファイルシステムが厳格モードを要求しなかった場合、システムはその文字列全体を不透明なバイト列として扱い、ユーザーがそのファイルに対して操作を行うことは可能ですが、大文字小文字を区別しない検索は機能しません。

オプション¶

ext4ファイルシステムをマウントする際、以下のオプションが受け付けられます: (*) == デフォルト

ro

ファイルシステムを読み取り専用でマウントします。注意点として、ext4は「読み取り専用」でマウントされてもジャーナルを再現（およびパーティションへの書き込み）します。ファイルシステムへの書き込みを防ぐには、「ro,noload」マウントオプションを使用できます。

journal_checksum

ジャーナルトランザクションのチェックサムを有効にします。これにより、e2fsckの復元コードおよびカーネルがカーネル内の破損を検出できます。これは互換性のある変更であり、古いカーネルでは無視されます。

journal_async_commit

コミットブロックはディスクリットに書かれる前にディスクリプタブロックの待機を必要としません。このオプションを有効にすると、古いカーネルがデバイスをマウントできなくなります。これは内部的に「journal_checksum」を有効にします。

journal_path=path, journal_dev=devnum

外部ジャーナルデバイスの主/サブデバイス番号が変更された場合、これらのオプションを使用して新しいジャーナルの場所を指定できます。ジャーナルデバイスは、devnumに格納された新しい主/サブデバイス番号、またはデバイスへのパスを通じて識別されます。

norecovery, noload

マウント時にジャーナルを読み込まないでください。注意点として、ファイルシステムがクリーンにアンマウントされなかった場合、ジャーナルの再現をスキップすると、ファイルシステムに不整合が生じ、それによりさまざまな問題が発生する可能性があります。

data=journal

すべてのデータがメインファイルシステムに書き込まれる前にジャーナルにコミットされます。このモードを有効にすると、遅延割当とO_DIRECTサポートが無効になります。

data=ordered (*)

すべてのデータがメタデータがジャーナルにコミットされる前に主なファイルシステムに直接書き出されます。

data=writeback

データの順序が保持されず、メタデータがジャーナルにコミットされた後でもデータがメインファイルシステムに書き込まれる可能性があります。

commit=nrsec (*)

この設定は、実行中のトランザクションの最大有効時間を「nrsec」秒に制限します。デフォルト値は5秒です。これは、電源が落ちた場合、最新の5秒間のメタデータの変更分を失うことになることを意味します（ジャーナリングによりファイルシステムは破損しません）。このデフォルト値（または低値）はパフォーマンスに悪影響を及ぼしますが、データの安全性に優れています。設定値を0にすると、デフォルト値（5秒）の状態と同様の効果があります。非常に大きな値を設定するとパフォーマンスが向上します。注意点として、遅延割当の影響により、電源障害時により古いデータも失われる可能性があるため、/proc/sys/vm/dirty_expire_centisecsに設定された時間経過後にそのデータの書き戻しが始まるためです。

barrier=<0|1(*)>, barrier(*), nobarrier

このオプションはjbdコードにおけるライトバリアーの使用を有効/無効にします。barrier=0は無効、barrier=1は有効です。また、バリアーをサポートするIOスタックが必要であり、jbdがバリアー書き込みでエラーを検出すると、警告とともに再度無効化します。ライトバリアーはディスク上のジャーナルコミットの正しい順序を強制し、揮発性ディスクのライトキャッシュの安全な使用を可能にしますが、パフォーマンスに若干のペナルティが生じます。ディスクがバッテリーでバックアップされている場合、バリアーを無効化することでパフォーマンスが改善されることがあります。マウントオプション「barrier」と「nobarrier」も使用してバリアーを有効/無効にでき、他のext4マウントオプションと整合性を保つためです。

inode_readahead_blks=n

このチューニングパラメータは、ext4のinodeテーブル読み取りアヘッドアルゴリズムがバッファキャッシュに事前に読み込むinodeテーブルブロックの最大数を制御します。デフォルト値は32ブロックです。

nouser_xattr

拡張ユーザー属性を無効にします。拡張属性に関する詳細情報はattr(5)マニュアルページをご参照ください。

noacl

このオプションはPOSIXアクセス制御リスト（ACL）のサポートを無効にします。ACLサポートがカーネル構成（CONFIG_EXT4_FS_POSIX_ACL）で有効になっている場合、マウント時にACLがデフォルトで有効になります。ACLに関する詳細情報はacl(5)マニュアルページをご参照ください。

bsddf (*)

「df」がBSDのように動作します。

minixdf

「df」がMinixのように動作します。

debug

追加のデバッグ情報がsyslogに送信されます。

abort

ext4_abort()の呼び出し効果をシミュレートしてデバッグ目的で使用します。これは通常、既にマウントされているファイルシステムを再マウントする際などに使用されます。

errors=remount-ro

エラー発生時にファイルシステムを読み取り専用で再マウントします。

errors=continue

ファイルシステムエラーでも継続して動作します。

errors=panic

エラー発生時にマシンをパニック状態にして停止します。（これらのマウントオプションはsuperblockで指定されたエラー動作を上書きします。superblockの設定はtune2fsを使用して行えます）

data_err=ignore(*)

ファイルデータバッファでエラーが発生した場合、エラー メッセージを出力します（順序モード）。

data_err=中止

ファイルデータバッファでエラーが発生した場合、ジャーナルを中止します（順序モード）。

grpid | bsdgroups

新しいオブジェクトは親のグループIDを取得します。

nogrpid (*) | sysvgroups

新しいオブジェクトは作成者のグループIDを取得します。

resgid=n

予約ブロックを使用できるグループID。

resuid=n

予約ブロックを使用できるユーザーID。

sb=

この場所に代替スーパーブロックを使用します。

quota, noquota, grpquota, usrquota

これらのオプションはファイルシステムによって無視されます。クォータツールがクォータを有効にするボリュームを認識するためにのみ使用されます。詳細については、quota-toolsパッケージのドキュメンテーションを参照してください（http://sourceforge.net/projects/linuxquota).

jqfmt=<quota type>, usrjquota=<file>, grpjquota=<file>

これらのオプションは、クォータに関するファイルシステムの詳細情報を提供し、ジャーナル再現中にクォータ情報を適切に更新できるようにします。これらは上記のクォータオプションを置き換えます。詳細については、quota-toolsパッケージのドキュメンテーションを参照してください（http://sourceforge.net/projects/linuxquota).

stripe=n

mballocが割り当てサイズとアライメントのために試みるファイルシステムブロック数。RAID5/6システムでは、データディスクの数 × RAID チャンクサイズ（ファイルシステムブロック単位）を設定してください。

delalloc (*)

ext4がブロック（s）を書き出す直前にブロック割り当てを延期します。これにより、ext4がより効率的に割り当て決定を行うことができます。

nodelalloc

遅延割り当てを無効にします。データがユーザー空間からページキャッシュにコピーされるときにブロックが割り当てられます。これは、write(2)システムコール経由で、または以前に未割り当てだったmmap’edページが初めて書き込まれるときに発生します。

max_batch_time=usec

ext4が同期的な書き込み操作と同時にバッチ処理でファイルシステム操作をまとめるために待つ最大時間を指定します。同期的な書き込み操作はコミットを強制し、I/O完了を待つため、コストが少なく、通過量を大幅に向上させるため、少量の時間を待って他のトランザクションが同期的な書き込みに乗り組めるか確認します。使用されるアルゴリズムはディスクの速度に応じて自動調整するように設計されており、トランザクションのコミットにかかる平均時間を測定して「コミット時間」と呼びます。トランザクションが実行されている時間がコミット時間より短い場合、ext4はコミット時間だけ待って他の操作がトランザクションに参加するか確認します。この最適化はmax_batch_timeを0に設定することで完全に無効化できます。

min_batch_time=マイクロ秒

このパラメータは、上記のコミット時間（commit time）を少なくともmin_batch_timeに設定します。デフォルトはゼロマイクロ秒です。このパラメータを増やすと、高速なディスクでのマルチスレッド・同期ワークロードの通過量が向上する可能性がありますが、レイテンシーが増加する代償があります。

journal_ioprio=優先度

kjournald2がコミット操作中に実行するI/O操作のI/O優先度（0〜7、0が最高優先度）を指定します。デフォルトは3で、デフォルトのI/O優先度よりやや高い優先度です。

auto_da_alloc(*), noauto_da_alloc

多くの破損したアプリケーションは、fd = open("foo.new")/write(fd,..)/close(fd)/ rename("foo.new", "foo")などのパターンで既存ファイルを置き換える際、fsync()を使用しません。あるいは、より悪い例ではfd = open("foo", O_TRUNC)/write(fd,..)/close(fd)です。auto_da_allocが有効な場合、ext4は置き換えによるリネームやトリミングパターンを検出し、次のジャーナルコミット時に遅延割当ブロックが割り当てられ、デフォルトのdata=orderedモードで新しいファイルのデータブロックがディスクに強制的に書き込まれるようします。これにより、ext3と同様の保証レベルが得られ、システムがクラッシュする前に遅延割当ブロックがディスクに強制されない場合の「ゼロ長さ」問題を回避します。

noinit_itable

バックグラウンドで未初期化の inode テーブルブロックを初期化しないでください。この機能はインストールCDによって使用され、インストールプロセスが可能な限り速く完了するようにするためのものです。inode テーブルの初期化プロセスは、ファイルシステムが再びマウント解除される次の機会まで延期されます。

init_itable=n

ラズィ inode テーブル初期化コードは、前のブロックグループの inode テーブルをゼロにしたのにかかったミリ秒数の n 倍の時間を待機します。これにより、ファイルシステムの inode テーブルが初期化される間、システムパフォーマンスへの影響を最小限に抑えます。

discard, nodiscard(*)

ext4 がブロックが解放されたときに下位ブロックデバイスに対して discard/TRIM コマンドを発行するかどうかを制御します。これは SSD デバイスやスパース/スリムプロビジョニングされた LUN に有効ですが、十分なテストが行われるまでデフォルトでは無効です。

nouid32

32 ビット UID および GID を無効にします。これは古いカーネルと互換性を取るためのオプションで、それらが16 ビットの値のみを保存し期待するためです。

block_validity(*), noblock_validity

これらのオプションは、ファイルシステムメタデータブロックを内部データ構造内で追跡するカーネル内での機能を有効または無効にします。これにより、マルチブロックアロケーターやその他のルーチンが、割当ビットマップの不具合や破損によってブロックがファイルシステムメタデータブロックと重複して割り当てられる問題を検出できます。

dioread_lock, dioread_nolock

ext4 が DIO レッドロックを使用するかどうかを制御します。dioread_nolock オプションが指定された場合、ext4 はバッファ書き込み前に未初期化のエクステントを割り当て、IO 完了後にエクステントを初期化します。このアプローチは inode ミューテックスを使用しないことで、高速ストレージでのスケーラビリティを向上させます。ただし、データジャーナリングと併用できませんし、カーネル警告とともに dioread_nolock オプションは無視されます。注意点として、dioread_nolock コードパスはエクステントベースのファイルにのみ使用されます。このオプションの制限により、デフォルトでは無効にしています（例: dioread_lock）。

max_dir_size_kb=n

このオプションは、ディレクトリのサイズを制限し、指定されたキロバイトを超えて拡張しようとすると ENOSPC エラーを発生させます。これはメモリ制約のある環境で、非常に大きなディレクトリがシステムパフォーマンスに深刻な影響を及ぼす場合や、さらにはメモリ不足キラーを引き起こす可能性があるため、有効です。（例: 512MB のメモリしかない場合、176MB のディレクトリがシステムの動作を大きく妨げる可能性があります。）

i_version

64 ビット inode バージョンサポートを有効にします。このオプションはデフォルトでは無効です。

dax

直接アクセス（ページキャッシュなし）を使用してください。ドキュメンテーション/filesystems/dax.txtを参照してください。このオプションはdata=journalと互換性がありません。

inlinecrypt

暗号化ファイルのコンテンツをblk-cryptoフレームワークを使用して暗号化/復号するようにします（ファイルシステムレイヤーの暗号化ではなく）。これによりインライン暗号化ハードウェアの使用が可能になります。ディスク上の形式は影響を受けません。詳細については インライン暗号化.

データモード¶

3つの異なるデータモードがあります:

  • writebackモード

    data=writebackモードではext4がデータのジャーナリングを行いません。このモードはXFS、JFS、ReiserFSのデフォルトモード（メタデータジャーナリング）と同様のジャーナリングレベルを提供します。クラッシュ＋復旧時に、クラッシュ前の短時間に書かれたファイルに不正確なデータが現れる可能性があります。このモードは通常、ext4のパフォーマンスにおいて最も良い結果をもたらします。

  • orderedモード

    data=orderedモードではext4がメタデータのみをジャーナリングしますが、データ変更に関連するメタデータ情報を論理的にデータブロックとともにトランザクションと呼ばれる単位にグループ化します。新しいメタデータをディスクに書き出す際には、関連するデータブロックが先に書き出されます。一般的にこのモードはwritebackモードよりやや遅く、journalモードより大幅に高速です。

  • journalモード

    data=journalモードはデータとメタデータの完全なジャーナリングを提供します。すべての新しいデータはまずジャーナルに書き込まれ、その後最終的な場所に移動します。クラッシュ発生時にジャーナルを再現することで、データとメタデータが一貫した状態に戻ります。このモードは、データの読み書きが同時にディスクに行われる場合を除き、最も遅いです。このモードを有効にすると、遅延割当とO_DIRECTサポートが無効になります。

/procエントリ¶

マウントされたext4ファイルシステムに関する情報は/proc/fs/ext4にあります。各マウントされたファイルシステムは、デバイス名に基づいて/proc/fs/ext4/<デバイス名>（例：/proc/fs/ext4/hdcや/proc/fs/ext4/dm-0）のディレクトリを持ちます。各デバイスディレクトリ内のファイルは以下の表に示します。

/proc/fs/ext4/<デバイス名>にあるファイル

mb_groups

マルチブロックアロケータのフリーブロックのバuddyキャッシュの詳細

/sysエントリ¶

マウントされたext4ファイルシステムに関する情報は/sys/fs/ext4にあります。各マウントされたファイルシステムは、デバイス名に基づいて/sys/fs/ext4/<デバイス名>（例：/sys/fs/ext4/hdcや/sys/fs/ext4/dm-0）のディレクトリを持ちます。各デバイスディレクトリ内のファイルは以下の表に示します。

/sys/fs/ext4/<デバイス名>にあるファイル:

(詳しくは Documentation/ABI/testing/sysfs-fs-ext4 を参照)

delayed_allocation_blocks

このファイルは読み取り専用で、ページキャッシュに保存されているが、ファイルシステムに割り当てられていないブロック数を表示しています。

inode_goal

インODE割当アルゴリズムが他のすべての割当アルゴリズムよりも優先して使用する目標インODEを制御するチューニングパラメータ（非ゼロの場合）。これはデバッグ用にのみ使用し、本番環境では0に設定する必要があります。

inode_readahead_blks

ext4のインノードテーブル読み進みアルゴリズムがバッファキャッシュに事前に読み込むインノードテーブルブロックの最大数を制御するチューニングパラメータ。

lifetime_write_kbytes

このファイルは読み取り専用で、ファイルシステムが作成後から書き込まれたデータのキロバイト数を表示します。

max_writeback_mb_bump

書き戻しコードが別のインODEに移行するまでに書き出すこと試みるメガバイトの最大数。

mb_group_prealloc

ストライプサイズがext4スーパーブロックに設定されていない場合、マルチブロックアロケータがこのチューニングパラメータの倍数にアロケーションリクエストを四捨五入します。

mb_max_inode_prealloc

インノードごとのext4_prealloc_spaceリストの最大長。

mb_max_to_scan

マルチブロックアロケータが最適なエクステントを検索する際の最大エクステント数。

mb_min_to_scan

マルチブロックアロケータが最適なエクステントを検索する際の最小エクステント数。

mb_order2_req

バッジキャッシュが使用されるリクエストの最小サイズ（2の累乗で指定）を制御するチューニングパラメータ。

mb_stats

マルチブロックアロケータがマウント解除時に収集する統計情報の有効/無効を制御します。1は統計情報を収集し、0は収集しません。

mb_stream_req

このチューニングパラメータより少ないブロック数を持つファイルは、ブロックグループ特有のプリアロケーションプールからブロックを割り当てられ、小ファイルが密集して配置されます。大ファイルはそれぞれ独自のプリアロケーションプールからブロックを割り当てられます。

session_write_kbytes

このファイルは読み取り専用で、マウント後からこのファイルシステムに書き込まれたデータのキロバイト数を表示しています。

reserved_clusters

これはRWファイルで、ファイルシステム内の予約されたクラスタ数を表します。特定の状況でコストのかかるzerooutや予期せぬENOSPC、データロスを防ぐために使用されます。デフォルトは2%または4096クラスタ、 whicheverが小さい方で、この値を変更できますが、ファイルシステム内のクラスタ数を超えてはなりません。マウント時に予約領域に十分なスペースがなければ、マウントは失敗しません。

Ioctls¶

Ext4はアプリケーションがext4固有の機能にアクセスできるようにするさまざまなioctlを実装しています。以下の表にこのioctlの一例を示します。このリストには本当にext4固有のioctl（EXT4_IOC_*)と、元々ext4固有だったが他のファイルシステムでもサポートされているioctl（FS_IOC_*).

Ext4 ioctls一覧

FS_IOC_GETFLAGS

インノードに関連する追加属性を取得します。ioctl引数はext4.hで説明されるビットフィールドの整数です。

FS_IOC_SETFLAGS

インノードに関連する追加属性を設定します。ioctl引数はext4.hで説明されるビットフィールドの整数です。

EXT4_IOC_GETVERSION, EXT4_IOC_GETVERSION_OLD

各インノードに保存されているi_generation番号を取得します。i_generation番号は通常、新しいインノードが作成されるときにのみ変更され、ネットワークファイルシステムで特に有用です。'_OLD'バージョンのioctlはFS_IOC_GETVERSIONのエイリアスです。

EXT4_IOC_SETVERSION, EXT4_IOC_SETVERSION_OLD

各インノードに保存されているi_generation番号を設定します。'_OLD'バージョンのioctlはFS_IOC_SETVERSIONのエイリアスです。

EXT4_IOC_GROUP_EXTEND

このioctlは、リサイズマウントオプションと同じ目的を持っています。ファイルシステムを最後に存在するブロックグループの終わりまでリサイズすることができ、さらにリサイズはresize2fsを使用して、オンラインまたはオフラインで行います。引数は、ファイルシステムの新しいブロック数を表す符号なしのlogn数を指します。

EXT4_IOC_MOVE_EXT

orig_fd（このioctlが指しているファイル記述子）からdonor_fd（move_extent構造体で指定されたファイル記述子）へブロックエクステントを移動します。その後、orig_fdとdonor_fdのinodeメタデータを交換します。これは特にオンラインデフラグメンテーションに有用で、割当先が移動したブロックをより効率的に連続エクステントに割り当てることができるためです。

EXT4_IOC_GROUP_ADD

既存または新しいグループ記述子ブロックに新しいグループ記述子を追加します。ext4_new_group_input構造体で新しいグループ記述子を定義し、このioctlの引数として渡します。これはEXT4_IOC_GROUP_EXTENDと組み合わせて使用され、ファイルシステムを最後に存在するブロックグループの終わりまでオンラインでリサイズするのに役立ちます。この2つのioctlはユーザー空間のオンラインリサイズツール（例：resize2fs）で使用されます。

EXT4_IOC_MIGRATE

このioctlはファイルシステム自体を操作します。ext3の間接ブロックマッピングinodeをext4のエクステントマッピングinodeに変換（移行）します。これは元のinodeの間接ブロックマッピングをたどり、連続ブロック範囲を一時inodeのext4エクステントに変換します。その後、inodeを交換します。このioctlはext3からext4への移行に役立つかもしれませんが、推奨されるのは新しいext4ファイルシステムを作成し、バックアップデータをコピーすることです。注意：このioctlはファイルシステムがエクステントをサポートしている必要があります。

EXT4_IOC_ALLOC_DA_BLKS

遅延割当ブロックをすべて割り当てることで、アプリケーションが期待するext3の動作を維持します。注意：これによりデータブロックの書き込みも開始されますが、今後この動作は変更される可能性があります。これは単純化のための実装です。

EXT4_IOC_RESIZE_FS

ファイルシステムを新しいサイズにリサイズします。リサイズ後のブロック数は64ビット整数の引数で指定します。カーネルがビットマップとinodeテーブルを割り当て、ユーザー空間のツールは新しいブロック数を単純に渡すだけです。

EXT4_IOC_SWAP_BOOT

指定されたインノデのi_blocksと関連する属性（i_blocks、i_size、i_flagsなど）を、インノデEXT4_BOOT_LOADER_INO（#5）と交換します。これは、通常、ファイルシステムのセキュアな部分にブートローダーを保存するために使用され、通常のユーザーが誤って変更できないようにするためのものです。以前のブートローダーのデータブロックは、指定されたインノデに関連付けられます。
