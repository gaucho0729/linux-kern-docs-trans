カーネルモジュール署名機能¶

概要¶

カーネルモジュール署名機能は、モジュールのインストール時に暗号化して署名し、ロード時にその署名を検証します。これにより、署名されていないモジュールや無効な鍵で署名されたモジュールのロードを禁止することで、カーネルのセキュリティを向上させます。モジュール署名により、悪意のあるモジュールをカーネルにロードするのをより困難にし、セキュリティが強化されます。モジュール署名の検証はカーネルが行うため、信頼できるユーザースペースの要素は必要ありません。

この機能はX.509 ITU-T標準証明書を使用して公開鍵を符号化します。署名自体はどの工業標準にも含まれていません。現在はRSA公開鍵暗号標準のみをサポートしています（ただし、プラグイン可能なため、他の標準も使用可能です）。使用可能なハッシュアルゴリズムはSHA-1、SHA-224、SHA-256、SHA-384、SHA-512（アルゴリズムは署名データ内の情報で選択されます）です。

モジュール署名の設定¶

モジュール署名機能を有効にするには、カーネル構成の ロード可能なモジュールサポートを有効にする セクションに移動し、以下のオプションを有効にします：

CONFIG_MODULE_SIG       "Module signature verification"

このオプションには複数の選択肢があります：

  1. モジュールが有効な署名を備えている必要がある (CONFIG_MODULE_SIG_FORCE)

    このオプションは、キーが不明な署名を持つモジュールや署名されていないモジュールに対してカーネルがどのように処理するかを指定します。

    このオプションがオフ（つまり「許容モード」）の場合、キーが利用できないモジュールや署名されていないモジュールは許可されますが、カーネルは「汚染（tainted）」とされ、関連するモジュールも「汚染」され、文字'Ｅ'で表示されます。

    このオプションがオン（つまり「制限モード」）の場合、カーネルが保有する公開鍵で検証可能な有効な署名を持つモジュールのみがロードされます。その他のモジュールはエラーを生成します。

    このオプションの設定に関係なく、署名ブロックが解析できない場合は、即座に拒否されます。

  2. すべてのモジュールを自動的に署名する (CONFIG_MODULE_SIG_ALL)

    このオプションがオンの場合、ビルドのmodules_installフェーズ中にモジュールが自動的に署名されます。オフの場合、手動で署名する必要があります：

    scripts/sign-file

  3. モジュールにどのハッシュアルゴリズムで署名するか

    インストールフェーズでモジュールに署名する際のハッシュアルゴリズムを選択します：

    CONFIG_MODULE_SIG_SHA1

    SHA-1でモジュールに署名

    CONFIG_MODULE_SIG_SHA224

    SHA-224でモジュールに署名

    CONFIG_MODULE_SIG_SHA256

    SHA-256でモジュールに署名

    CONFIG_MODULE_SIG_SHA384

    SHA-384でモジュールに署名

    CONFIG_MODULE_SIG_SHA512

    SHA-512でモジュールに署名

    ここに選択したアルゴリズムもカーネルに組み込まれる（モジュールではなく）ため、そのアルゴリズムで署名されたモジュールの署名を確認できるようにします。これにより、依存関係のループを引き起こすことなく、署名を検証できます。

  4. モジュール署名キーのファイル名またはPKCS#11 URI (CONFIG_MODULE_SIG_KEY)

    このオプションをデフォルト値以外に設定すると certs/signing_key.pem 署名キーの自動生成を無効にし、カーネルモジュールを指定したキーで署名できるようにします。提供された文字列は、秘密鍵と対応するX.509証明書をPEM形式で含むファイルを示すべきです。また、OpenSSL ENGINE_pkcs11が機能するシステムでは、RFC7512で定義されたPKCS#11 URIを指定することもできます。後者の場合、PKCS#11 URIは証明書と秘密鍵を参照する必要があります。

    PEMファイルに秘密鍵が暗号化されている場合、またはPKCS#11トークンがPINを必要とする場合、ビルド時に以下の KBUILD_SIGN_PIN 変数を介して提供できます。

  5. デフォルトのシステムキーリングに追加するX.509証明書 (CONFIG_SYSTEM_TRUSTED_KEYS)

    このオプションは、システムキーリングにデフォルトで含める追加証明書を含むPEM形式のファイルのファイル名に設定できます。

モジュール署名を有効にすると、署名を行うツールのためのカーネルビルドプロセスにOpenSSL開発パッケージへの依存関係が追加されます。

署名キーの生成¶

署名を生成および検証するために暗号化された鍵ペアが必要です。秘密鍵は署名を生成するために使用され、対応する公開鍵は署名を検証するために使用されます。秘密鍵はビルド中にのみ必要であり、ビルド後は削除または安全に保管できます。公開鍵はカーネルに組み込まれるため、モジュールがロードされるときに署名を検証できます。

通常の状況では、 CONFIG_MODULE_SIG_KEY がデフォルト値から変更されていない場合、カーネルビルドは、ファイル:

certs/signing_key.pem

に存在しない場合、opensslを使用して新しい鍵ペアを自動生成します。vmlinux（カーネルの公開部分）のビルド中に、公開鍵の部分はvmlinuxに組み込まれる必要があります。これは、以下の:

certs/x509.genkey

ファイル（存在しない場合でも生成されます）に記載されたパラメータを使用します。

自分のx509.genkeyファイルを提供することをお勧めします。

特に、x509.genkeyファイルでは、req_distinguished_nameセクションはデフォルト値から変更する必要があります:

[ req_distinguished_name ]
#O = Unspecified company
CN = Build time autogenerated kernel key
#emailAddress = unspecified.user@unspecified.company

生成されるRSA鍵のサイズは以下の通り設定できます:

[ req ]
default_bits = 4096

また、Linuxカーネルソースツリーのルートノードにあるx509.genkey鍵生成構成ファイルとopensslコマンドを使用して、手動で秘密鍵/公開鍵ファイルを生成することも可能です。以下は、秘密鍵/公開鍵ファイルを生成する例です:

openssl req -new -nodes -utf8 -sha256 -days 36500 -batch -x509 \
   -config x509.genkey -outform PEM -out kernel_key.pem \
   -keyout kernel_key.pem

生成されたkernel_key.pemファイルのフルパス名は、その後、 CONFIG_MODULE_SIG_KEY オプションで指定できます。このオプションで指定された証明書と秘密鍵が、自動生成されたキーペアの代わりに使用されます。

カーネル内の公開鍵¶

カーネルには、rootによって確認可能な公開鍵のリングが含まれており、これは「.builtin_trusted_keys」と呼ばれるキーリングに格納されています。確認するには以下のコマンドを使用します：

[root@deneb ~]# cat /proc/keys
...
223c7853 I------     1 perm 1f030000     0     0 keyring   .builtin_trusted_keys: 1
302d2d52 I------     1 perm 1f010000     0     0 asymmetri Fedora kernel signing key: d69a84e6bce3d216b979e9505b3e3ef9a7118079: X509.RSA a7118079 []
...

モジュール署名用に特別に生成された公開鍵に加え、追加の信頼できる証明書は、 CONFIG_SYSTEM_TRUSTED_KEYS 構成オプションで参照されるPEMエンコードされたファイルに提供できます。

さらに、アーキテクチャコードはハードウェアストアから公開鍵を取得し、それらを追加することも可能です（例：UEFIキーデータベースから）。

最後に、以下のコマンドを実行することで追加の公開鍵を追加できます：

keyctl padd asymmetric "" [.builtin_trusted_keys-ID] <[key-file]

e.g.:

keyctl padd asymmetric "" 0x223c7853 <my_public_key.x509

ただし、カーネルは、 .builtin_trusted_keys に鍵を追加する際に、 新しい鍵のX.509ラッパーが、その鍵が当時カーネル内にすでに存在している場合にのみ有効に署名されている必要があります。 .builtin_trusted_keys に追加される鍵のX.509ラッパーが、その鍵が当時カーネル内にすでに存在している場合にのみ有効に署名されている必要があります。

手動でのモジュール署名¶

モジュールを手動で署名するには、Linuxカーネルソースツリー内のscripts/sign-fileツールを使用します。このスクリプトには4つの引数が必要です：

  1. ハッシュアルゴリズム（例：sha256）

  2. 秘密鍵ファイル名またはPKCS#11 URI

  3. 公開鍵ファイル名

  4. 署名するカーネルモジュール

以下は、カーネルモジュールを署名する例です：

scripts/sign-file sha512 kernel-signkey.priv \
        kernel-signkey.x509 module.ko

使用されるハッシュアルゴリズムは構成されたものと一致する必要はありませんが、一致しない場合は、そのハッシュアルゴリズムがカーネルに組み込まれているか、またはそれ自体をロードせずにロード可能であることを確認してください。

秘密鍵がパスフレーズまたはPINコードを必要とする場合、$KBUILD_SIGN_PIN環境変数で提供できます。

署名済みモジュールとデバッグ情報の削除¶

署名済みモジュールは、デジタル署名をファイルの最後に単純に追加したものです。モジュールファイルの最後にある ~Module signature appended~. という文字列は署名が存在することを確認しますが、署名が有効であることを確認しません！

署名済みモジュールは、署名が定義されたELFコンテナの外にあるため非常に脆いです。したがって、署名が計算され添付された後では、削除できません。注意：署名時のデバッグ情報も含むすべてのモジュールが署名されたペイロードです。

署名済みモジュールのロード¶

モジュールはinsmod、modprobe、 init_module() または finit_module()でロードされ、署名されていないモジュールの場合と同様に処理が行われません。署名検証はすべてカーネル内で行われます。

無効な署名と署名されていないモジュール¶

もし CONFIG_MODULE_SIG_FORCE .sig_enforce=1が有効化されているか、カーネルコマンドラインにmodule.sig_enforce=1が指定されている場合、カーネルは公開鍵を持っている有効に署名されたモジュールのみをロードします。それ以外の場合は、署名されていないモジュールもロードします。カーネルが鍵を持っているが、署名が一致しないモジュールはロードを許可されません。

解析不能な署名を持つモジュールは拒否されます。

秘密鍵の管理/保護¶

秘密鍵はモジュールの署名に使用されるため、ウイルスやマルウェアが秘密鍵を使ってモジュールを署名し、オペレーティングシステムを侵害する可能性があります。秘密鍵は破壊するか、セキュアな場所に移動し、カーネルソースツリーのルートノードに保管しない必要があります。

複数のカーネル構成に同じ秘密鍵を使ってモジュールを署名する場合、モジュールのバージョン情報が十分に異なるようにする必要があります。これにより、別のカーネルにモジュールをロードするのを防ぎます。以下のいずれかを設定する必要があります： CONFIG_MODVERSIONS=y または、各構成に異なるカーネルリリース文字列を設定するために、変更してください EXTRAVERSION または CONFIG_LOCALVERSION.
