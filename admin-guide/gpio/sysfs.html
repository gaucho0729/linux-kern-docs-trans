GPIO Sysfs インターフェース（ユーザー空間用）¶

警告

このABIは非推奨となっており、ABIドキュメンテーションはDocumentation/ABI/obsolete/sysfs-gpioに移動しました。新しいユーザースペース消費者はキャラクターデバイスABIを使用する必要があります。この古いSysfs ABIは開発されません（新しい機能は追加されません）、ただ維持されるだけです。

新しいキャラクターデバイスABIの導入についてはtools/gpio/*にある例を参照してください。また、include/uapi/linux/gpio.hにあるユーザースペースヘッダーファイルも確認してください。

非推奨のSysfs ABI¶

「gpiolib」実装フレームワークを使用するプラットフォームでは、GPIOに対するユーザースペースインターフェースを構成する選択肢があります。これはデバッグfsインターフェースとは異なり、GPIOの方向と値の制御を提供するため、単にGPIOの状態を表示するだけではありません。さらに、デバッグサポートがなくても製造環境で存在する可能性があります。

システムの適切なハードウェアドキュメンテーションが与えられた場合、ユーザースペースは例えばGPIO #23がフラッシュメモリ内のブートローダーセグメントを保護するライト保護ラインを制御していることを知ることができます。システムアップグレード手順では、まずGPIOをインポートし、その後出力状態を変更し、コードを更新してからライト保護を再び有効にする必要があります。通常の使用ではGPIO #23は一切操作されず、カーネルはその存在を知る必要がありません。

適切なハードウェアドキュメンテーションに依存しますが、一部のシステムではユーザースペースGPIOを使用して標準カーネルが知らないシステム構成データを特定することができ、一部のタスクでは単純なユーザースペースGPIOドライバがシステムのすべての必要条件を満たす場合もあります。

適切なカーネルドライバを持つハードウェアをSYSFSで制御しないでください。詳しくは以下のドキュメンテーションを参照してください GPIOを使用するサブシステムドライバ カーネルのホイールをユーザースペースで再発明しないでください。本気で言っています。本当に。

Sysfsのパス¶

/sys/class/gpio/内のエントリは3種類あります:

  • GPIOをユーザースペース制御に導くためのコントロールインターフェース;

  • GPIO自体; そして

  • GPIOコントローラー（"gpio_chip"インスタンス）。

これは"device"シンボリックリンクなどの標準ファイルを除いて追加されます。

コントロールインターフェースは書き込み専用です:

/sys/class/gpio/

「export」…

ユーザースペースがカーネルにGPIOの制御をユーザースペースにエクスポートするよう依頼するには、このファイルにGPIO番号を書き込みます。

例: 「echo 19 > export」は、カーネルコードが要求していない場合でもGPIO #19の「gpio19」ノードを作成します。

「unexport」…

エクスポートをユーザースペースに戻す効果を逆転させます。

例: 「echo 19 > unexport」は、「export」ファイルを使用してエクスポートされた「gpio19」ノードを削除します。

GPIO信号は、/sys/class/gpio/gpio42/（GPIO #42の場合）などのパスを持ち、以下の読み書き可能な属性を持ちます:

/sys/class/gpio/gpioN/

「direction」…

「in」または「out」のいずれかを読み取ります。この値は通常書き込み可能です。「out」を書き込むと初期値として低電圧に初期化されます。ノイズのない動作を確保するため、「low」や「high」を書き込むことで、その初期値でGPIOを出力として設定できます。

この属性について注意してください が存在しない場合 カーネルがGPIOの方向変更をサポートしていない、またはカーネルコードがユーザースペースにこのGPIOの方向再構成を明示的に許可していない場合です。

「value」…

0（低電圧）または1（高電圧）を読み取ります。GPIOが出力として設定されている場合、この値を書き込むことができます。任意の非ゼロ値は高電圧として扱われます。

ピンが割り込み生成可能な割り込みピンとして設定可能で、かつ割り込みを生成するように設定されている場合（「edge」の説明を参照）、このファイルに対してpoll(2)を実行できます。poll(2)は割り込みがトリガーされたときに返します。poll(2)を使用する場合は、POLLPRIとPOLLERRイベントを設定してください。select(2)を使用する場合は、exceptfdsにファイル記述子を設定してください。poll(2)が返った後は、sysfsファイルの先頭にlseek(2)して新しい値を読み取るか、ファイルを閉じて再オープンして値を読み取る必要があります。

「edge」…

「none」、「rising」、「falling」、「both」のいずれかを読み取ります。これらの文字列を書き込むことで、「value」ファイルのpoll(2)が返る割り込みエッジを選択できます。

このファイルは、ピンが割り込み生成入力ピンとして設定可能である場合にのみ存在します。

「active_low」…

0（偽）または1（真）を読み取ります。非ゼロ値を書き込むと、読み取りおよび書き込みの際の値属性が反転します。既存および後のpoll(2)サポート設定は、「rising」および「falling」エッジの「edge」属性を通じてこの設定に従います。

GPIOコントローラーは、/sys/class/gpio/gpiochip42/（GPIO #42から開始するGPIOを実装するコントローラー）などのパスを持ち、以下の読み取り専用属性を持ちます:

/sys/class/gpio/gpiochipN/

「base」…

Nと同じで、このチップが管理する最初のGPIO

「label」…

診断用に提供されています（常に一意ではありません）

「ngpio」…

このチップが管理するGPIOの数（NからN + ngpio - 1）

ボードドキュメンテーションでは、GPIOがどの目的で使用されるかを記載することが一般的です。ただし、GPIO番号は常に安定しているわけではありません。daughter board（拡張ボード）のGPIOは、使用しているベースボードやスタックされている他のボードによって異なり得るため、このような場合ではgpiochipノード（回路図と併用して）を使用して、特定のシグナルに使用する正しいGPIO番号を特定する必要があります。

カーネルコードからのエクスポート¶

カーネルコードは、gpio_request()で既にリクエストされたGPIOのエクスポートを明示的に管理できます：

/* export the GPIO to userspace */
int gpiod_export(struct gpio_desc *desc, bool direction_may_change);

/* reverse gpio_export() */
void gpiod_unexport(struct gpio_desc *desc);

/* create a sysfs link to an exported GPIO node */
int gpiod_export_link(struct device *dev, const char *name,
              struct gpio_desc *desc);

カーネルドライバーがGPIOをリクエストした後、sysfsインターフェースで利用可能にするには gpiod_export()、ドライバーはシグナルの方向変更を制御できます。これにより、ユーザースペースコードが重要なシステム状態を誤って上書きしないようにします。

このような明示的なエクスポートはデバッグに役立ち（特定の実験をより容易にする）、またボードサポートパッケージの一部としてドキュメンテーションに適した常に利用可能なインターフェースを提供できます。

GPIOがエクスポートされた後、 gpiod_export_link() はsysfs内の他の場所からGPIOのsysfsノードへのシンボリックリンクを作成できます。ドライバーはこれを活用して、sysfs内での自身のデバイス配下に説明的な名前でインターフェースを提供できます。
