Smack¶

「あなたはよくできた、エレベーターを掃除することに決めたのね！」- ダークスターからのエレベーター

Smackは簡易マンドATORYアクセス制御カーネルです。Smackは、強制アクセス制御のためのカーネルベースの実装であり、その主な設計目標には簡潔さが含まれています。

SmackはLinuxにおける強制アクセス制御のスキームの一つにすぎません。強制アクセス制御に新しい方には、Smackを他のメカニズムと比較し、問題に最適なものを選ぶことをお勧めします。

Smackは以下の3つの主要なコンポーネントから構成されています：

  • カーネル

  • 基本的なユーティリティ（必須ではありませんが役立ちます）

  • 構成データ

SmackのカーネルコンポーネントはLinuxセキュリティモジュール（LSM）モジュールとして実装されています。netlabelを必要とし、拡張属性をサポートするファイルシステムで動作しますが、xattrサポートは厳密には必須ではありません。vanillaディストリビューションの下でもSmackカーネルを実行できます。

SmackカーネルはCIPSO IPオプションを使用します。一部のネットワーク構成はIPオプションに不耐性があり、Smackを使用するシステムへのアクセスを妨げる可能性があります。

SmackはTizenオペレーティングシステムで使用されています。詳しくは http://wiki.tizen.org をご覧ください。

Smackユーザースペースの現在のgitリポジトリは：

git://github.com/smack-team/smack.git

これはほとんどの現代ディストリビューションでビルドおよびインストールできます。smackutilには以下の5つのコマンドが含まれています：

chsmack:

Smack拡張属性値の表示または設定

smackctl:

Smackアクセスルールのロード

smackaccess:

ラベルが異なるプロセスとオブジェクト間のアクセスを報告

smackfs/load2およびsmackfs/cipso2インターフェースの導入により、この2つのコマンドは非推奨になりました。

smackload:

smackfs/loadに書き込むためのデータを適切にフォーマット

smackcipso:

smackfs/cipsoに書き込むためのデータを適切にフォーマット

Smackの意図に従い、構成データは最小限で厳密には必須ではありません。最も重要な構成ステップはsmackfs擬似ファイルシステムのマウントです。smackutilがインストールされている場合、起動スクリプトが自動でこれを処理しますが、手動でも可能です。

この行を /etc/fstab:

smackfs /sys/fs/smackfs smackfs defaults 0 0

以下の /sys/fs/smackfs ディレクトリはカーネルによって作成されます。

Smackはファイルシステムオブジェクトにラベルを保存するために拡張属性（xattrs）を使用します。これらの属性は拡張属性セキュリティネームスペースに保存されます。プロセスは CAP_MAC_ADMIN を必要とします。

Smackが使用する拡張属性は以下の通りです：

SMACK64

アクセス制御の決定に使用されます。新しいファイルシステムオブジェクトに割り当てられるラベルは、ほぼすべてのケースで作成プロセスのラベルになります。

SMACK64EXEC

この属性が設定されたプログラムファイルをexecするプロセスのSmackラベルは、この属性の値で実行されます。

SMACK64MMAP

この属性で指定されたSmackラベルのプロセスが許可されるアクセス以外のアクセスを許可しないようにします。これは共有ライブラリの非常に特定の使用ケースです。

SMACK64TRANSMUTE

値は「TRUE」のみ許可されます。この属性がディレクトリに設定されている場合、ディレクトリ内にオブジェクトが作成され、ディレクトリへの書き込みを許可するSmackルール（以下で説明）にtransmute（「t」モード）が含まれている場合、オブジェクトは作成プロセスのラベルではなく、ディレクトリのラベルを受け継ぎます。作成されるオブジェクトがディレクトリである場合、SMACK64TRANSMUTE属性も設定されます。

SMACK64IPIN

この属性はソケットのファイルディスクリプタにのみ存在します。この属性のSmackラベルを使用して、このソケットに届くパケットのアクセス制御を行います。

SMACK64IPOUT

この属性はソケットのファイルディスクリプタにのみ存在します。この属性のSmackラベルを使用して、このソケットから送信されるパケットのアクセス制御を行います。

ファイルにSmackラベルを設定する方法は複数あります：

# attr -S -s SMACK64 -V "value" path
# chsmack -a value path

プロセスは現在実行中のSmackラベルを読み取ることで確認できます /proc/self/attr/current。 CAP_MAC_ADMIN ラベルを持つプロセスは

に書き込むことでプロセスのSmackラベルを設定できます。 /sys/fs/smackfs.

access

後方互換性のために提供されています。access2インターフェースが推奨され、代わりに使用すべきです。このインターフェースは、指定されたSmackラベルを持つ主体が、指定されたSmackラベルを持つオブジェクトに対して特定のアクセスを有するかを報告します。このファイルに固定形式のアクセスルールを書き込み、次の読み込みでアクセスが許可されるかどうかを示します。テキストは「1」（アクセス許可）または「0」（拒否）のいずれかになります。

access2

このインターフェースは、指定されたSmackラベルを持つ主体が、指定されたSmackラベルを持つオブジェクトに対して特定のアクセスを有するかを報告します。このファイルに長形式のアクセスルールを書き込み、次の読み込みでアクセスが許可されるかどうかを示します。テキストは「1」（アクセス許可）または「0」（拒否）のいずれかになります。

ambient

これはラベルが付けられていないネットワークパケットに適用されるSmackラベルを含みます。

change-rule

このインターフェースは、既存のアクセス制御ルールの編集を許可します。書き込み時に受け入れる形式は:

"%s %s %s %s"

ここで、最初の文字列はサブジェクトラベル、2番目はオブジェクトラベル、3番目は許可するアクセス、4番目は拒否するアクセスです。アクセス文字列には「rwxat-」という文字のみを含むことができます。指定されたサブジェクトとオブジェクトのルールが既に存在する場合、3番目の文字列で許可を有効にし、4番目の文字列で許可を無効にします。そのようなルールが存在しない場合は、3番目と4番目の文字列で指定されたアクセスをもとに新しいルールが作成されます。

cipso

後方互換性のために提供されています。cipso2インターフェースが推奨され、代わりに使用するべきです。このインターフェースは、特定のCIPSOヘッダーをSmackラベルに割り当てることを許可します。書き込み時に受け入れる形式は:

"%24s%4d%4d"["%4d"]...

最初の文字列は固定のSmackラベルです。最初の数字は使用するレベル、2番目の数字はカテゴリ数、その後ろの数字はカテゴリです:

"level-3-cats-5-19          3   2   5  19"
cipso2

このインターフェースは、特定のCIPSOヘッダーをSmackラベルに割り当てることを許可します。書き込み時に受け入れる形式は:

"%s%4d%4d"["%4d"]...

最初の文字列は長いSmackラベルです。最初の数字は使用するレベル、2番目の数字はカテゴリ数、その後ろの数字はカテゴリです:

"level-3-cats-5-19   3   2   5  19"
direct

これは、ネットワークパケットにおけるSmack直接ラベル表現に使用されるCIPSOレベルを指定します。

doi

これは、ネットワークパケットで使用されるCIPSOドメインの解釈を指定します。

ipv6host

このインターフェースは、特定のIPv6インターネットアドレスを単一ラベルホストとして扱うことを許可します。単一ラベルホストへのパケット送信は、ホストラベルにSmack書き込みアクセスを持つプロセスに限定されます。すべての単一ラベルホストからの受信パケットは指定されたラベルが割り当てられます。書き込み時に受け入れる形式は:

"%h:%h:%h:%h:%h:%h:%h:%h label" or
"%h:%h:%h:%h:%h:%h:%h:%h/%d label".

「::」アドレスのショートカットはサポートされていません。ラベルが「-DELETE」の場合、一致したエントリが削除されます。

load

後方互換性のために提供されています。load2インターフェースが推奨され、代わりに使用するべきです。このインターフェースは、システム定義のルールに加えてアクセス制御ルールを指定することを許可します。書き込み時に受け入れる形式は:

"%24s%24s%5s"

ここで、最初の文字列はサブジェクトラベル、2番目はオブジェクトラベル、3番目は要求されるアクセスです。アクセス文字列には「rwxat-」という文字のみを含め、許可されるアクセス種類を指定します。「-」は許可されない権限のプレースホルダーです。文字列「r-x–」は読み取りと実行アクセスを指定します。ラベルは最大23文字までに制限されます。

load2

このインターフェースは、システムで定義されたルールに加えてアクセス制御ルールを指定できるようにします。書き込み時に受け入れる形式は以下の通りです。

"%s %s %s"

ここで最初の文字列はサブジェクトラベル、2番目の文字列はオブジェクトラベル、3番目の文字列は要求されたアクセスです。アクセス文字列には「rwxat-」という文字のみを含めることができ、どの種類のアクセスが許可されるかを指定します。「-」は許可されていない権限を表すプレースホルダーです。文字列「r-x–」は読み取りと実行アクセスを指定します。

load-self

後方互換性のために提供されています。load-self2インターフェースが推奨されており、代わりに使用するべきです。このインターフェースはプロセス固有のアクセス制御ルールを定義できます。これらのルールはアクセスが本来許可される場合にのみ参照され、プロセスに追加の制限を提供することを目的としています。フォーマットはloadインターフェースと同じです。

load-self2

このインターフェースはプロセス固有のアクセス制御ルールを定義できます。これらのルールはアクセスが本来許可される場合にのみ参照され、プロセスに追加の制限を提供することを目的としています。フォーマットはload2インターフェースと同じです。

logging

これはSmackのロギング状態を含みます。

mapped

これはネットワークパケットにおけるSmackマップラベル表現に使用されるCIPSOレベルを含みます。

netlabel

このインターフェースは特定のインターネットアドレスを単一ラベルホストとして扱うことができます。CIPSOヘッダーなしで単一ラベルホストにパケットが送信されますが、ホストラベルに対してSmackの書き込みアクセスを持つプロセスからのみ可能です。単一ラベルホストから受信したすべてのパケットには指定されたラベルが割り当てられます。書き込み時に受け入れる形式は以下の通りです。

"%d.%d.%d.%d label" or "%d.%d.%d.%d/%d label".

指定されたラベルが「-CIPSO」の場合、アドレスはCIPSOヘッダーをサポートするホストとして扱われます。

onlycap

これはCAP_MAC_ADMINが必要とするラベルを含みます。 CAP_MAC_OVERRIDE 有効にするにはこのファイルに望むラベルをスペースで区切って書き込みます。ファイルが空の場合、ラベルに関係なくこれらの能力が有効です。

ptrace

現在のptraceポリシーを定義するために使用されます

0 - デフォルト:

これはSmackアクセス制御ルールに依存するポリシーです。 PTRACE_READ サブジェクトがオブジェクトに対して読み取りアクセスを持つ必要があります。 PTRACE_ATTACH 読み取り・書き込みアクセスが必要です。

1 - 正確:

これは制限をかけるポリシーです。 PTRACE_ATTACHアタッチはサブジェクトとオブジェクトのラベルが等しい場合にのみ許可されます。 PTRACE_READ 影響を受けません。revoke-subjectで上書き可能です。 CAP_SYS_PTRACE.

このポリシーは「正確」のポリシーと同じ挙動ですが、revoke-subjectで上書きすることはできません。 CAP_SYS_PTRACE.

revoke-subject

ここにSmackラベルを記述すると、その主体ラベルを持つすべてのアクセスルールのアクセス権が「-」になります。

unconfined

カーネルが CONFIG_SECURITY_SMACK_BRINGUP プロセスが CAP_MAC_ADMIN このインターフェースにラベルを書き込むことができます。その後、そのラベルに関連するアクセスはログに記録され、それ以外の制限がない場合にのみ許可されます。注意してください。これは危険で、システムの適切なラベリングを破壊する可能性があります。本番環境では決して使用すべきではありません。

このインターフェースには、プロセスが書き込むことで移行可能なラベルの一覧が含まれています。 /proc/self/attr/current. 通常、プロセスは自身のラベルを任意の合法的な値に変更できますが、その際には CAP_MAC_ADMIN. このインターフェースは、 CAP_MAC_ADMIN を持たないプロセスが、事前に定義されたリスト内のラベルのいずれかに自身のラベルを再ラベル化できるようにします。 CAP_MAC_ADMIN を持たないプロセスは、ラベルを変更できるのは一度だけです。変更を行うと、このリストはクリアされます。値は、ファイルにスペースで区切った望ましいラベルを書き込むことで設定され、"-"を書き込むことでクリアされます。

強制アクセス制御¶

コンピュータシステムは、機械で使用する人々やサービス間で情報が共有される方法を制限するため、さまざまなスキームを採用しています。これらのスキームの一部は、プログラムやユーザーがデータにアクセスできる他のプログラムやユーザーを決定できるようにします。このようなスキームは、ユーザーの裁量でアクセス制御が指定されるため、任意アクセス制御メカニズムと呼ばれます。他のスキームでは、ユーザーまたはプログラムが何にアクセスできるかの決定はユーザーまたはプログラムに委ねられません。このようなスキームは、データにアクセスできるユーザーまたはプログラムの選択肢がないため、強制アクセス制御メカニズムと呼ばれます。

ベル＆ラパドゥラ¶

1980年代半ばから20世紀末にかけて、強制アクセス制御（MAC）は、米国国防省の紙の文書のマークに関する政策を数学的に記述したベル＆ラパドゥラセキュリティモデルと非常に密接に関連していました。この形式のMACは、カピタルベルトウェイとスカンディナビアのスーパーコンピュータセンター内で一定の支持を得ましたが、一般的なニーズに対応していないとしばしば指摘されていました。

ドメイン型強制¶

20世紀末頃に、ドメイン型強制実行（Domain Type Enforcement: DTE）が広く利用されるようになりました。このスキームでは、ユーザー、プログラム、データを相互に保護されるドメインに分類し、それぞれが他からアクセスを制限されます。このスキームは、一般的なLinuxディストリビューションの一部として広く導入されてきましたが、このスキームを維持するための管理負荷や、セキュアなドメインマッピングを提供するための全体システムに対する詳細な理解が必要なため、大多数のケースでは無効化されたり、限定的な用途にしか使われていません。

Smack¶

Smackは、以前のスキームの欠点を回避しつつ、有用な強制アクセス制御（Mandatory Access Control: MAC）を提供するためのメカニズムです。ベル＆ラパドゥラモデルの制限は、システムやその目的に応じたアクセス制御を実現することで解消されています。ドメイン型強制実行の複雑さを回避するために、既存のアクセスモードを基にアクセス制御を定義しています。

Smack用語¶

Smackについて話す際の専門用語は、他のMACシステムに詳しい人にとっては馴染みやすく、初心者でもそれほど難しくありません。ただし、以下の4つの用語は特定の意味で使用され、特に重要です：

サブジェクト：

サブジェクトとは、コンピュータシステムにおける能動的な実体です。Smackでは、タスクがサブジェクトであり、これは実行の基本単位です。

オブジェクト：

オブジェクトとは、コンピュータシステムにおける被動的な実体です。Smackでは、すべての種類のファイル、IPC（プロセス間通信）、タスクがオブジェクトとして扱えます。

アクセス：

サブジェクトがオブジェクトから情報を取得するか、情報をオブジェクトに書き込む試みはすべてアクセスとみなされます。

ラベル：

サブジェクトまたはオブジェクトの強制アクセス制御の特性を識別するデータです。

これらの定義はセキュリティコミュニティでの伝統的な使用法と一致しています。また、Linuxの用語として以下のような用語もよく登場します：

キャパビリティ：

キャパビリティを保有するタスクは、特定のキャパビリティによって定義されるシステムセキュリティポリシーの一部を違反する許可を得ています。1つ以上のキャパビリティを保有するタスクは特権タスクであり、キャパビリティを保有しないタスクは非特権タスクです。

特権：

システムセキュリティポリシーを違反する許可を持つタスクは特権を持っています。本書の執筆時点では、タスクが特権を持つのは、キャパビリティを保有しているか、または有効ユーザーがrootである場合です。

Smackの基礎¶

SmackはLinuxシステムの拡張です。サブジェクトがどのオブジェクトにアクセスできるかを、サブジェクトとオブジェクトそれぞれに付与されたラベルに基づいて追加の制限を課します。

ラベル¶

SmackのラベルはASCII文字列です。最大255文字までですが、23文字以内に抑えることを推奨します。特殊文字（アルファベットや数字以外）を含む1文字のラベルは、Smack開発チームの使用に予約されています。Smackのラベルは構造化されておらず、ケースセンシティブであり、それに対して行われる操作は等価性の比較のみです。Smackのラベルには印刷不可能な文字、『/』（スラッシュ）、『\』（バックスラッシュ）、『'』（クォート）、『"』（ダブルクォート）は含まれません。また、ラベルは『-』で始めることが出来ません。これは特別なオプションに予約されています。

いくつかの予め定義されたラベルがあります:

_       Pronounced "floor", a single underscore character.
^       Pronounced "hat", a single circumflex character.
*       Pronounced "star", a single asterisk character.
?       Pronounced "huh", a single question mark character.
@       Pronounced "web", a single at sign character.

Smackシステム上のすべてのタスクにラベルが割り当てられます。プロセスのSmackラベルは通常、システム初期化メカニズムによって割り当てられます。

アクセス規則¶

SmackはLinuxの伝統的なアクセスモードを使用します。これらのモードは読み取り、実行、書き込み、および場合によっては追加です。アクセスモードが明確でないケースには以下があります:

シグナル:

シグナルとは、サブジェクトタスクからオブジェクトタスクへの書き込み操作です。

インターネットドメインIPC:

パケットの送信は、ソースタスクから宛先タスクへの書き込み操作とみなされます。

Smackは、サブジェクトに付与されたラベルと、アクセスしようとしているオブジェクトに付与されたラベルに基づいてアクセスを制限します。強制されるルールは以下の順序で行われます:

  1. タスクが「*」というラベルを付与されている場合、すべてのアクセス要求は拒否されます。

  2. タスクが「^」というラベルを付与されている場合、読み取りまたは実行アクセス要求は許可されます。

  3. オブジェクトが「_」というラベルを付与されている場合、読み取りまたは実行アクセス要求は許可されます。

  4. オブジェクトが「*」というラベルを付与されている場合、すべてのアクセス要求は許可されます。

  5. タスクが同じラベルを持つオブジェクトに対してアクセスを要求する場合、すべてのアクセス要求は許可されます。

  6. ロードされたルールセットで明示的に定義されたアクセス要求は許可されます。

  7. それ以外のアクセスは拒否されます。

Smack アクセス規則¶

Smackによる隔離により、アクセス分離は簡単です。限定的なアクセスが望まれるオブジェクトとサブジェクトのラベル間の例は多くあります。例えば、機密情報のスパイモデルでは、高度に機密なプロジェクトに取り組む科学者が低機密の文書を読み取ることができ、彼女が書いたものは「生まれた」時点で高度に機密とされるケースがあります。このようなスキームをサポートするために、Smackはラベル間のアクセスを許可するためのルールを指定するメカニズムを含んでいます。

アクセスルールの形式¶

アクセスルールの形式は以下の通りです：

subject-label object-label access

ここでsubject-labelはタスクのSmackラベル、object-labelはアクセスされるオブジェクトのSmackラベル、accessは許可されるアクセス種類を指定する文字列です。アクセス指定文字はアクセスモードを記述する文字を探します：

a: 追加アクセスを許可します。r: 読み取りアクセスを許可します。w: 書き込みアクセスを許可します。x: 実行アクセスを許可します。t: ルールが変換を要求します。b: ルールがブリングアップのために報告されるべきです。

指定文字の-uppercase値も許可されています。アクセスモードの指定は順序に関係ありません。受け入れ可能なルールの例は以下の通りです：

TopSecret Secret  rx
Secret    Unclass R
Manager   Game    x
User      HR      w
Snap      Crackle rwxatb
New       Old     rRrRr
Closed    Off     -

受け入れられないルールの例は以下の通りです：

Top Secret Secret     rx
Ace        Ace        r
Odd        spells     waxbeans

ラベルにはスペースは許可されません。サブジェクトが常に同じラベルを持つファイルにアクセスできるため、そのケースにルールを指定する必要はありません。アクセス指定には有効な文字（rwxatbRWXATB）とダッシュ（‘-’）のみが許可されます。ダッシュはプレースホルダーであり、「a-r」は「ar」と同じです。単独のダッシュはアクセスを許可しないことを指定します。

アクセスルールの適用¶

Linuxの開発者は新しい種類のものをほとんど定義しません。通常は他のシステムからスキームや概念を導入します。他のシステムはほとんどがUnixの変種です。Unixには多くの魅力的な特徴がありますが、アクセス制御モデルの整合性はその一つではありません。Smackは、基盤となるメカニズムの精神に沿いながら、合理的にアクセスを統一的に扱 striveします。

ファイルシステムオブジェクト（ファイル、ディレクトリ、名前付きパイプ、シンボリックリンク、デバイスなど）は、モードビットアクセスに使用されるアクセス権限と密接に一致するアクセス権限が必要です。ファイルを読み込み用に開くには、ファイルへの読み取りアクセスが必要です。ディレクトリを検索するには実行アクセスが必要です。書き込みアクセスでファイルを作成するには、含むディレクトリに読み取りと書き込みアクセスが必要です。ファイルを削除するには、ファイルおよび含むディレクトリに読み取りと書き込みアクセスが必要です。ユーザーが含むディレクトリに読み取りアクセスがあるが、異なるラベルが付けられたファイルにアクセスできない場合、ファイルが存在することを確認できるが属性は確認できないことがあります。これは、ファイル名がディレクトリ内のデータであり、ファイル自体の一部ではないためです。

ディレクトリが変換（SMACK64TRANSMUTE=TRUE）されている場合、プロセスがそのディレクトリにオブジェクトを作成できるアクセスルールに「t」アクセスが含まれている場合、新規オブジェクトに割り当てられるラベルはディレクトリのラベルになります。作成プロセスのラベルではありません。これにより、ラベルが異なる2つのプロセスがすべてのファイルへのアクセスを許可せずにデータを共有するのをはるかに容易にします。

IPCオブジェクト（メッセージキュー、セマフォームセット、メモリセグメントなど）はフラットな名前空間に存在し、アクセス要求は対象のオブジェクトと一致する必要があります。

プロセスオブジェクトはシステム上のタスクを反映し、それらにアクセスするためのSmackラベルは、タスクが自身のアクセス試行で使用するSmackラベルと同じです。kill()システムコールを介して信号を送信する行為は、送信者から受信者への書き込み操作です。プロセスのデバッグには読み取りと書き込みが必要です。新しいタスクの作成は内部操作であり、2つのSmackラベルが同一のタスクを生成し、アクセスチェックは必要ありません。

ソケットはプロセスに添付されたデータ構造であり、1つのプロセスから別のプロセズにパケットを送信するには、送信者が受信者への書き込みアクセスを必要とします。受信者は送信者への読み取りアクセスを必要としません。

アクセスルールの設定¶

/etc/smack/accessesという設定ファイルには、システム起動時に設定されるルールが含まれています。その内容は特別なファイル/sys/fs/smackfs/load2に書き込まれます。いつでもルールを追加でき、即座に有効になります。任意の主語と対象のラベルのペアには1つのルールのみが存在し、最新に指定されたルールが以前の指定を上書きします。

タスク属性¶

プロセスのSmackラベルは/proc/<pid>/attr/currentから読み取ることができます。プロセスは自身のSmackラベルを/proc/self/attr/currentから読み取ることができます。権限のあるプロセスは/proc/self/attr/currentに書き込むことで自身のSmackラベルを変更できますが、他のプロセスのラベルは変更できません。

ファイル属性¶

ファイルシステムオブジェクトのSmackラベルは、ファイルにSMACK64という拡張属性として保存されます。この属性はセキュリティ名前空間に属します。この属性を変更できるのは権限を持つプロセスだけです。

権限¶

CAP_MAC_OVERRIDEまたはCAP_MAC_ADMINを持つプロセスは権限を持ちます。CAP_MAC_OVERRIDEは、それ以外に拒否されるオブジェクトへのアクセスを許可します。CAP_MAC_ADMINは、プロセスがSmackデータ（ルールや属性を含む）を変更できる権限を提供します。

Smackネットワーキング¶

前述した通り、Smackはネットワークプロトコルの送信時にアクセス制御を強制します。Smackプロセスが送信するすべてのパケットはSmackラベルでタグ付けされます。これはIPパケットのヘッダーにCIPSOタグを追加することで実現されます。受信する各パケットはCIPSOタグを含む必要があります。タグがなければネットワークのambientラベルが仮定されます。パケットが配信される前に、パケットのラベルを持つ主体が受信プロセスに書き込みアクセスを持つかを確認し、アクセスがない場合はパケットが破棄されます。

CIPSO構成¶

通常、CIPSO構成を指定する必要はありません。システムが使用するデフォルト値はすべての内部ケースを処理します。Smackは管理介入なしに、使用しているSmackラベルに一致するCIPSOラベル値を自動的に組み立てます。システムに到達するラベルのないパケットはambientラベルが割り当てられます。

Smackは、CIPSOをサポートする非Smackシステムからのパケットが到達する場合に構成が必要です。通常はTrusted Solarisシステムですが、他の少数派のシステムも存在します。CIPSOは各パケットに3つの重要な値を提供します。ドメインオブインタープリテーション（DOI）、レベル、カテゴリセットです。DOIは互換性のあるラベルスキームを使用するシステムグループを識別するためのもので、Smackシステムで指定されたDOIはリモートシステムのDOIと一致しなければパケットが破棄されます。DOIはデフォルトで3です。値は/sys/fs/smackfs/doiから読み取り、/sys/fs/smackfs/doiに書き込むことで変更できます。

ラベルとカテゴリセットは/etc/smack/cipsoで定義されたSmackラベルにマッピングされます。

Smack/CIPSOマッピングの形式は以下の通りです：

smack level [category [category]*]

Smackは、レベルまたはカテゴリセットが特定の方法で関連していることを期待せず、それらに基づいてアクセスを仮定または割り当てることもありません。いくつかのマッピングの例:

TopSecret 7
TS:A,B    7 1 2
SecBDE    5 2 4 6
RAFTERS   7 12 26

Smackラベルには「:」および「,」という文字が許可されていますが、特別な意味は持ちません。

SmackラベルをCIPSO値にマッピングする仕組みは、/sys/fs/smackfs/cipso2に書き込むことで定義されます。

明示的なマッピングに加えて、Smackは直接CIPSOマッピングもサポートしています。パケットに渡されるカテゴリセットが実際にはSmackラベルの符号化であることを示すため、1つのCIPSOレベルが使用されます。デフォルトではレベル250が使用され、値は/sys/fs/smackfs/directから読み取ることができ、/sys/fs/smackfs/directに書き込むことで変更可能です。

ソケット属性¶

ソケットに関連する属性は2つあります。これらの属性は特権を持つタスクのみが設定可能ですが、任意のタスクが自身のソケットに対して読み取ることができます。

SMACK64IPIN:

タスクオブジェクトのSmackラベル。ポリシーエンフォースメントを行う特権プログラムがこの値をスター・ラベルに設定できます。

SMACK64IPOUT:

出力パケットとともに送信されるSmackラベル。特権プログラムが他のタスクと通信を希望するラベルにこれを設定できます。

Smack Netlabel例外¶

ラベルを付与したアプリケーションが外部のラベルのない世界と通信する必要がある場合があります。そのために、/sys/fs/smackfs/netlabelという特別なファイルに例外を追加できます。

@IP1       LABEL1 or
@IP2/MASK  LABEL2

これは、LABEL1に書き込みアクセスがある場合に@IP1へのラベルのないアクセスを許可し、LABEL2に書き込みアクセスがある場合に@IP2/MASKサブネットへのアクセスを許可することを意味します。

/sys/fs/smackfs/netlabelファイル内のエントリは、クラスレスIPv4ルーティングと同様に、最も長いマスクを優先してマッチングされます。

特別なラベル「@」とオプション「-CIPSO」を使用できます:

@      means Internet, any application with any label has access to it
-CIPSO means standard CIPSO networking

CIPSOの概念を理解していない場合や使用しない予定の場合、以下のようにできます:

echo 127.0.0.1 -CIPSO > /sys/fs/smackfs/netlabel
echo 0.0.0.0/0 @      > /sys/fs/smackfs/netlabel

192.168.0.0/16ローカルネットワークでCIPSOを使用し、ラベルのないインターネットアクセスも必要である場合、以下のように設定できます:

echo 127.0.0.1      -CIPSO > /sys/fs/smackfs/netlabel
echo 192.168.0.0/16 -CIPSO > /sys/fs/smackfs/netlabel
echo 0.0.0.0/0      @      > /sys/fs/smackfs/netlabel

Smack用のアプリケーションの作成¶

Smackシステムで動作するアプリケーションは大きく3種類に分類されます。アプリケーションがSmackとどのように相互作用するかが、Smack環境で正しく動作するために必要な処理を決定します。

Smackを無視するアプリケーション¶

ほとんどのアプリケーションはSmackの特有な性質に全く関心を持ちません。プログラムの実行がプロセスに関連するSmackラベルに影響を与えないため、心配されるのはプロセスがプログラムに実行アクセスを持つかどうかです。

Smackに関連するアプリケーション¶

Smackについて教えることで改善できるプログラムもありますが、それら自身はセキュリティに関する決定を行いません。ls(1)というユーティリティはそのようなプログラムの例です。

Smack Enforcing Applications¶

これらはSmackについて知っているだけでなく、システムポリシーの実施に参加する特別なプログラムです。ほとんどの場合、これらはユーザーセッションを設定するプログラムです。ネットワークサービスも含まれており、さまざまなラベルで実行されているプロセスに情報を提供します。

File System Interfaces¶

Smackは拡張属性を使用してファイルシステムオブジェクトにラベルを保持します。ファイル、ディレクトリ、またはその他のファイルシステムオブジェクトのSmackラベルはgetxattr(2)を使用して取得できます：

len = getxattr("/", "security.SMACK64", value, sizeof (value));

rootディレクトリのSmackラベルをvalueに設定します。特権プロセスはsetxattr(2)を使用してファイルシステムオブジェクトのSmackラベルを設定できます：

len = strlen("Rubble");
rc = setxattr("/foo", "security.SMACK64", "Rubble", len, 0);

プログラムが適切な権限を持っている場合、/fooのSmackラベルを「Rubble」と設定します。

Socket Interfaces¶

ソケット属性はfgetxattr(2)を使用して読み取れます。

特権プロセスはfsetxattr(2)を使用して出力パケットのSmackラベルを設定できます：

len = strlen("Rubble");
rc = fsetxattr(fd, "security.SMACK64IPOUT", "Rubble", len, 0);

プログラムが適切な権限を持っている場合、ソケットから出るパケットのSmackラベルを「Rubble」と設定します：

rc = fsetxattr(fd, "security.SMACK64IPIN, "*", strlen("*"), 0);

プログラムが適切な権限を持っている場合、入力パケットがチェックされるオブジェクトラベルとして「*」を設定します。

Administration¶

Smackはいくつかのマウントオプションをサポートしています：

smackfsdef=label:

Smackラベル拡張属性を持たないファイルに割り当てるラベルを指定します。

smackfsroot=label:

Smack拡張属性を持たないファイルシステムのルートに割り当てるラベルを指定します。

smackfshat=label:

ファイルシステムに設定されたすべてのラベルに読み取りアクセスが必要なラベルを指定します。まだ実施されていません。

smackfsfloor=label:

ファイルシステムに設定されたすべてのラベルが読み取りアクセスが必要なラベルを指定します。まだ実施されていません。

smackfstransmute=label:

smackfsrootと完全に同じ動作ですが、マウントのルートにtransmuteフラグも設定します。

これらのマウントオプションはすべてのファイルシステムタイプに適用されます。

Smack auditing¶

セキュリティイベントのSmack監査を行いたい場合は、カーネル構成にCONFIG_AUDITを設定する必要があります。デフォルトではすべての拒否イベントが監査されます。/sys/fs/smackfs/loggingファイルに1文字を書き込むことでこの挙動を変更できます：

0 : no logging
1 : log denied (default)
2 : log accepted
3 : log denied & accepted

イベントは「key=value」のペアとしてログに記録され、各イベントには少なくとも主語、対象、要求された権限、アクション、イベントをトリガーしたカーネル関数が含まれます。イベントの種類によっては他のペアも含まれます。

Bringup Mode¶

ブリングアップモードは、アプリケーションの構成やシステムのブリングアップを容易にするログ機能を提供します。これらの機能を有効にするには、カーネルをCONFIG_SECURITY_SMACK_BRINGUPで構成してください。ブリングアップモードが有効な場合、アクセスが成功した理由が「b」アクセスモードでマーキングされたルールである場合、そのアクセスがログに記録されます。プロセスに新しいラベルが導入された場合、積極的にルールを追加できるよう「b」でマーキングします。このログ機能により、どのルールが実際にそのラベルに対して使用されているかを追跡できます。

ブリングアップモードのもう一つの機能は「unconfined（制限なし）」オプションです。ラベルを/sys/fs/smackfs/unconfinedに書き込むと、そのラベルを持つサブジェクトが任意のオブジェクトにアクセスでき、そのラベルを持つオブジェクトはすべてのサブジェクトにアクセス可能になります。ラベルがunconfinedであるためアクセスが許可された場合、そのアクセスがログに記録されます。この機能は危険です。ポリシーが強制されている場合に比べて、ファイルやディレクトリが本来アクセスできない場所に作成される可能性があるからです。
