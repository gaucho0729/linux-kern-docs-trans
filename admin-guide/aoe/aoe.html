はじめに¶

ATA over Ethernet は、LAN 上でブロックストレージに簡単なアクセスを提供するネットワークプロトコルです。

http://support.coraid.com/documents/AoEr11.txt

2.6 および 3.x カーネル用の EtherDrive (R) HOWTO は…にあります。

http://support.coraid.com/support/linux/EtherDrive-2.6-HOWTO.html

多くのヒントがあります！特に、仮想メモリの推奨チューニングについてはご確認ください：

http://support.coraid.com/support/linux/EtherDrive-2.6-HOWTO-5.html#ss5.19

aoetools は、このドライバーと連携して動作するユーザーランドのプログラムです。aoetools は sourceforge にあります。

http://aoetools.sourceforge.net/

この Documentation/admin-guide/aoe ディレクトリ内のスクリプトは、ドライバーの使用方法を記述する目的で用意されており、aoetools をインストールした場合は不要です。

デバイスノードの作成¶

udev を使用するユーザーは、ブロックデバイスノードが自動的に作成されるので見つけることができますが、すべての必要なデバイスノードを作成するには、このディレクトリ内の udev.txt に記載されている udev 設定ルールを使用してください。

udev-install.sh スクリプトがあります。このスクリプトは、これらのルールをシステムにインストールする方法を示しています。

また、/etc/modprobe.d/aoe.conf を編集して、必要に応じて aoe モジュールをロードする方法を示すオートロードスクリプトもあります。ただし、AoE 探索には数秒かかるため、aoe モジュールのプリロードの方がオートロードよりも好ましいです。最初の実行時に AoE デバイスが見つからないが、その後に表示される場合、混乱する可能性があります。

デバイスノードの使用¶

「cat /dev/etherd/err」は、エラー診断出力（再送されたパケットなど）を待機するブロックです。

「echo eth2 eth4 > /dev/etherd/interfaces」は、aoe ドライバーに ATA over Ethernet 通信を eth2 および eth4 に限定するように指示します。信頼できないネットワークからの AoE 通信はセキュリティ上の理由で無視する必要があります。以下の aoe_iflist ドライバーオプションも参照してください。

「echo > /dev/etherd/discover」は、ドライバーに利用可能な AoE デバイスを確認するように指示します。

今後、これらのキャラクターデバイスは消失し、sysfs 対応で置き換えられる可能性があります。aoetools のコマンドを使用することで、ユーザーはこれらの実装詳細から保護されます。

ブロックデバイスは次のようになります：

e{shelf}.{slot}
e{shelf}.{slot}p{part}

…「e0.2」は、最初のシェルフ（シェルフアドレスゼロ）の左から3番目のスロット（スロット2）を指します。これは全体のディスクです。そのディスクの最初のパーティションは「e0.2p1」になります。

sysfs の使用¶

/sys/block にある各 aoe ブロックデバイスは、state、mac、netif という追加の属性を持っています。state 属性は、デバイスが I/O に準備ができているときに「up」、検出されたが使用不可能な場合に「down」になります。「down,closewait」状態は、デバイスがまだ開いており、閉じられるまで再起動できないことを示します。

mac属性は、リモートAoEデバイスのイーサネットアドレスを表します。netif属性は、ローカルホストでリモートAoEデバイスと通信するネットワークインターフェースを示します。

このディレクトリには、この情報を便利な形式で整形するスクリプトが含まれています。aoetoolsを使用しているユーザーは、aoe-statコマンドを使用してください：

root@makki root# sh Documentation/admin-guide/aoe/status.sh
   e10.0            eth3              up
   e10.1            eth3              up
   e10.2            eth3              up
   e10.3            eth3              up
   e10.4            eth3              up
   e10.5            eth3              up
   e10.6            eth3              up
   e10.7            eth3              up
   e10.8            eth3              up
   e10.9            eth3              up
    e4.0            eth1              up
    e4.1            eth1              up
    e4.2            eth1              up
    e4.3            eth1              up
    e4.4            eth1              up
    e4.5            eth1              up
    e4.6            eth1              up
    e4.7            eth1              up
    e4.8            eth1              up
    e4.9            eth1              up

AoEトラフィックを指定されたホワイトスペースで区切られたネットワークインターフェースに限定するには、/sys/module/aoe/parameters/aoe_iflist（または以下で説明するドライバーオプションの方がより優れています）を使用してください。古いキャラクターデバイスとは異なり、sysfsエントリは読み取りだけでなく書き込みも可能です。

許可インターフェースの一覧を設定した後、ディスカバリーをトリガーすることが役立ちます。aoetoolsパッケージにはこの目的でaoe-discoverスクリプトが含まれています。また、上記で説明した/dev/etherd/discoverの特別なファイルを直接使用することもできます。

ドライバーオプション¶

組み込みのAoEドライバーにはブートオプションがあり、それに応じたモジュールパラメータaoe_iflistもあります。このオプションが指定されていない場合、すべてのネットワークインターフェースがATA over Ethernetのために使用される可能性があります。モジュールパラメータの使用例は次のとおりです：

modprobe aoe_iflist="eth1 eth3"

aoe_deadsecsモジュールパラメータは、ドライバーがAoEデバイスがAoEコマンドに応答するのを待つ最大秒数を決定します。aoe_deadsecs秒経過後にAoEデバイスは「ダウン」とみなされます。テスト目的でゼロを指定することも可能で、これによりaoeドライバーがAoEコマンドを永遠に試行し続けます。

aoe_maxoutモジュットパラメータのデフォルト値は128です。これは、一度にAoEターゲットに送信される未応答パケットの最大数を表します。

aoe_dyndevsモジュールパラメータのデフォルト値は1で、ドライバーが発見したAoEターゲットにブロックデバイスのマイナーデバイス番号を発見順に割り当てます。動的マイナーデバイス番号を使用する場合、AoEシェルフおよびスロットアドレスのより広範な範囲をサポートできます。udevを使用しているユーザーはマイナーデバイス番号について考える必要がありません。aoe_dyndevs=0を指定することで、aoetools内のaoe-mkshelfスクリプトを使用して静的マイナーデバイス番号スキームでデバイスノードを事前に作成できます。
