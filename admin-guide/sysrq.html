Linux Magic System Request Key Hacks¶

sysrq.cに関するドキュメンテーション

マジック・システム・リクエスト・キーとは何ですか？¶

カーネルが何をしていたとしても、完全にロックアップしていない限り、カーネルが応答する‘マジック’なキーボードショートカットです。

マジック・システム・リクエスト・キーを有効にするにはどうすればよいですか？¶

カーネルを構成する際、‘Magic SysRq key (CONFIG_MAGIC_SYSRQ)’に‘yes’を選択する必要があります。SysRqがコンパイルされているカーネルを実行している場合、/proc/sys/kernel/sysrqはSysRqキー経由で呼び出せる機能を制御します。このファイルのデフォルト値はCONFIG_MAGIC_SYSRQ_DEFAULT_ENABLEの設定によって決まり、そのデフォルト値は1です。/proc/sys/kernel/sysrqの可能な値の一覧は以下の通りです：

  • 0 - sysrqを完全に無効化

  • 1 - sysrqのすべての機能を有効化

  • ＞1 - 允許されるsysrq機能のビットマスク（詳細な機能説明は下記を参照）：

      2 =   0x2 - enable control of console logging level
  4 =   0x4 - enable control of keyboard (SAK, unraw)
  8 =   0x8 - enable debugging dumps of processes etc.
 16 =  0x10 - enable sync command
 32 =  0x20 - enable remount read-only
 64 =  0x40 - enable signalling of processes (term, kill, oom-kill)
128 =  0x80 - allow reboot/poweroff
256 = 0x100 - allow nicing of all RT tasks

以下のコマンドでこのファイルの値を設定できます：

echo "number" >/proc/sys/kernel/sysrq

数値は10進数でも、0xで始まる16進数でも記述できます。CONFIG_MAGIC_SYSRQ_DEFAULT_ENABLEは常に16進数で記述する必要があります。

値の /proc/sys/kernel/sysrq キーボード経由での呼び出しにのみ影響します。任意の操作の呼び出しは /proc/sysrq-trigger 管理者権限を持つユーザーによって常に許可されます。

マジック・システム・リクエスト・キーを使用するにはどうすればよいですか？¶

x86の場合

キーボードショートカットを押します ALT-SysRq-<command key>.

注意

一部のキーボードには‘SysRq’ラベルのキーがありません。‘SysRq’キーは‘Print Screen’キーとしても知られています。また、一部のキーボードでは同時に多くのキーを押すことができないため、以下の操作を試してみてください： Alt押して、 SysRqリリースします。 SysRq押して、 <command key>すべてを解放してください。

SPARCの場合

押してください ALT-STOP-<command key>、私はそう思っています。

シリアルコンソール（PCスタイルの標準シリアルポートのみ）

送信してください BREAK、その後5秒以内にコマンドキーを送信してください。送信 BREAK 2回送信すると、通常のBREAKとして解釈されます。

PowerPCの場合

押してください ALT - Print Screen (または F13) - <command key>. Print Screen (または F13) - <command key> これで十分かもしれません。

他の

他のアーキテクチャのキーボードショートカットをご存知であれば、教えていただけますと、このセクションに追加できます。

すべての

/proc/sysrq-trigger に文字を書き込みます。例:

echo t > /proc/sysrq-trigger

以下の <command key> 大文字小文字を区別します。

では、これらはどのように利用できるでしょうか？¶

Xサーバーやsvgalibプログラムがクラッシュしたときにunraw(r)は非常に便利です。

SAK(k)（Secure Access Key）は、コンソールにtrojanプログラムが存在しないことを確認したいときに便利です。ログイン時にパスワードを盗まれる可能性のあるtrojanプログラムをすべて終了させ、ログインプロンプトがinitからのものであることを確認できます。

重要です。

本来の形では、c2準拠システムのSAKとは異なり、誤解しないでください。

他者が「システム注意キー」としてこの機能を役立つと感じているようです。これは、コンソールの切り替えができないプログラムを終了したい場合に役立ちます。(例: X や svgalib プログラムなど。)

reboot(b) 電源を切る際に使用すると便利で、これは「リセット」ボタンを押すのと同等です。

crash(c) システムが停止しているときに手動でクラッシュダンプをトリガーできます。ただし、ダンプメカニズムが利用できない場合は、単にクラッシュを引き起こすだけです。

sync(s) 外部媒体を抜き取る前や、優雅なシャットダウンを提供しないレスキューシェルを使用した後などに便利です。これにより、データが安全にディスクに書き込まれます。注意: 「OK」と「Done」が画面に表示されるまで、同期が完了していません。

umount(u) ファイルシステムを正しくアンマウントした状態としてマークできます。稼働中のシステムから見ると、これらは読み取り専用で再マウントされます。再マウントが完了するのは、「OK」と「Done」が画面に表示されるまでです。

ログレベル 0-9 カーネルメッセージが大量に表示されるコンソールのときに役立ちます。選択することで 0 最も緊急なみに限ってのみコンソールに届くようになります。(syslogd/klogd が動作している場合は、それでもログに記録されます。)

term(e) および kill(i) 異常なプロセスが殺せない場合に役立ちます。特に、そのプロセスが他のプロセスを生成している場合にも有効です。

「ただ解凍 it(j)」は、FIFREEZE ioctl によって凍結した(おそらく root で)ファイルシステムによりシステムが応答しなくなった場合に役立ちます。

時折、SysRq を使用した後で「詰まってしまう」ことがあります。どうすればいいですか？¶

私にも同じことが起きます。私は、キーボードの両側でシフト、Alt、コントロールをタップし、無効な sysrq シーケンスをもう一度入力することで問題を解決しました。(例: alt-sysrq-z)。別の仮想コンソールに切り替えました。ALT+Fn) に戻るのも有効です。

SysRq を押したが、何もないように見える。問題はどこにある？¶

一部のキーボードでは、SysRq に割り当てられているキーコードが事前に定義された値 99 と異なります(参照: KEY_SYSRQ の include/uapi/linux/input-event-codes.h)、または SysRq キー自体を持っていない場合があります。その場合、 showkey -s を実行して適切なスキャンコードシーケンスを見つけ、 setkeycodes <sequence> 99 を実行してこのシーケンスを通常の SysRq コードにマッピングします。(例: setkeycodes e05b 99)。このコマンドをブートスクリプトに組み込むのが最善です。ちなみに、10 秒間何も入力しないことで、 showkey を終了できます。

SysRQ キーファンクションをモジュールに追加するにはどうすればいい？¶

テーブルに基本的な機能を登録するには、まずヘッダーファイル include/linux/sysrq.hをインクルードする必要があります。これにより、必要なすべての定義が提供されます。次に、 sysrq_key_op 構造体を作成し、A) 使用するキーハンドラ関数、B) SysRQがヘルプを表示するときに表示されるhelp_msg文字列、C) ハンドラが呼ばれる直前に表示されるaction_msg文字列を設定します。ハンドラは'sysrq.h'に定義されたプロトタイプに準拠する必要があります。

構造体が作成された後で、 sysrq_key_op カーネル関数を呼び出すことができます。 register_sysrq_key(int key, const struct sysrq_key_op *op_p); これは、'op_p' によって指される操作を 'key' テーブルのキーに登録します。 op_p そのテーブルの 'key' テーブルキーに登録しますが、そのスロットが空欄の場合にのみ。 unregister_sysrq_key(int key, const struct sysrq_key_op *op_p)モジュールのアンロード時に、関数を呼び出す必要があります。これは、'op_p' によって指されるキーオペレーションを 'key' テーブルの 'key' スロットから削除しますが、そのスロットに現在登録されている場合に限り行われます。これは、登録後でスロットが上書きされた場合を考慮したものです。

Magic SysRQ システムは、キー操作をキーオペレーション検索テーブルに登録することで動作します。このキーテーブルは 'drivers/tty/sysrq.c' に定義されており、コンパイル時にいくつかの操作が登録されていますが、変更可能なテーブルであり、インターフェースとして2つの関数がエクスポートされています。

register_sysrq_key and unregister_sysrq_key.

もちろん、テーブルに無効なポインタを残さないでください。つまり、register_sysrq_key() を呼び出したモジュールが終了する際には、unregister_sysrq_key() を呼び出して sysrq キーテーブルの使用したエントリをクリーンアップする必要があります。テーブル内の NULL ポインタは常に安全です。:)

handle_sysrq 関数内で handle_sysrq 関数を呼び出す必要がある場合は、ロック内（中断ハンドラ内であるため、スリープはできません）で動作していることを理解する必要がありますので、代わりに __handle_sysrq_nolock を呼び出してください。

SysRq キーを押したときにコンソールにみつばのみが表示されるのはなぜですか？¶

SysRq の出力は、他のコンソール出力と同じコンソールログレベル制御に従います。これは、ディストロのカーネルで一般的な 'quiet' モードで起動した場合、実際のコンソールに表示されない可能性があるためです。ただし、dmesg バッファに表示され、dmesg コマンドや、 /proc/kmsgの消費者にアクセス可能です。特定の例外として、sysrq コマンドのヘッダーラインは、現在のログレベルが最大であるかのようにすべてのコンソール消費者に渡されます。みつばのみが出力される場合、ほぼ確実にカーネルのログレベルが低すぎる可能性があります。コンソールチャネルで出力を確認したい場合は、 alt-sysrq-8 または:

echo 8 > /proc/sysrq-trigger

を使用してコンソールログレベルを一時的に上げる必要があります。sysrq コマンドをトリガーした後は、ログレベルを通常に戻すことを忘れないでください。
