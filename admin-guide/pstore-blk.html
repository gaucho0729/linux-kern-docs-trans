pstore ブロック oops/panic ロガー¶

はじめに¶

pstore block (pstore/blk) は、システムがクラッシュする前にブロックデバイスと非ブロックデバイスにログを書き込む oops/panic ロガーです。pstore ファイルシステムをマウントすることでこれらのログファイルを取得できます:

mount -t pstore pstore /sys/fs/pstore

pstore block の概念¶

pstore/blk は、pstore/blk の設定を効率的に構成する方法を提供しており、すべての設定はユーザー向けの設定とドライバ向けの設定の2つの部分に分かれています。

ユーザー向けの設定は pstore/blk の動作を決定します（例: pmsg_size、kmsg_size など）。これらはすべて Kconfig とモジュールパラメータをサポートしますが、モジュールパラメータは Kconfig より優先されます。

ドライバ向けの設定はすべてブロックデバイスと非ブロックデバイスに関するもので、ブロックデバイスの total_size や読み書き操作などが含まれます。

ユーザー向けの設定¶

すべての設定は Kconfig とモジュールパラメータをサポートしますが、モジュールパラメータは Kconfig より優先されます。

モジュールパラメータの例:

pstore_blk.blkdev=179:7 pstore_blk.kmsg_size=64

各設定の詳細は興味があるかもしれません。

blkdev¶

使用するブロックデバイス。ほとんどの場合、ブロックデバイスのパーティションです。pstore/blk では必須であり、MTD デバイスにも使用されます。

ブロックデバイスには以下の変種が受け入れられます:

  1. <hex_major><hex_minor> は16進数で表されるデバイス番号です（先頭の 0x は不要。例: b302）。

  2. /dev/<disk_name> はディスクのデバイス番号を表します。

  3. /dev/<disk_name><decimal> はディスクのデバイス番号にパーティション番号を加えたデバイス番号を表します。

  4. /dev/<disk_name>p<decimal> - 上記と同じ形式で、パーティションのディスク名が数字で終わる場合に使用します。

  5. PARTUUID=00112233-4455-6677-8899-AABBCCDDEEFF は、パーティションテーブルが提供する場合のパーティションの一意IDを表します。UUID は EFI/GPT UUID か、MSDOS パーティション用の SSSSSSSS-PP 形式（SSSSSSSS はゼロ埋めされた32ビット「NTディスクサインチャレ」、PP はゼロ埋めされた1ベースのパーティション番号）を指す場合もあります。

  6. PARTUUID=<UUID>/PARTNROFF=<int> は、既知の一意IDを持つパーティションに関連するパーティションを選択します。

  7. <major>:<minor> はコロンで区切られたデバイスの主番号とサブ番号です。

MTD デバイスには以下の変種が受け入れられます:

  1. <device name> MTD デバイス名。「pstore」が推奨されます。

  2. <device number> MTD デバイス番号。

kmsg_size¶

oops/panic フロントエンドのチャンクサイズ（KB）。 MUST 4 の倍数でなければなりません。oops/panic ログに興味がない場合はオプションです。

oops/panic front-endは、他のpstore front-endを除き、残りのスペースに応じて複数のチャンクが存在します。

pstore/blkはoops/panicチャンクに1つずつログを出力し、空きチャンクがなくなった場合、常に最も古いチャンクを上書きします。

pmsg_size¶

pmsg front-endのチャンクサイズ（KB）。これは MUST 4の倍数でなければなりません。pmsgログに興味がない場合はオプションです。

oops/panic front-endとは異なり、pmsg front-endには常に1つのチャンクのみがあります。

Pmsgはユーザー空間からアクセス可能なpstoreオブジェクトです。書き込みは /dev/pmsg0 に追加され、再起動時に /sys/fs/pstore/pmsg-pstore-blk-0.

console_size¶

console front-endのチャンクサイズ（KB）。これは MUST 4の倍数でなければなりません。consoleログに興味がない場合はオプションです。

pmsg front-endと同様に、console front-endにも常に1つのチャンクのみがあります。

すべてのコンソールログがチャンクに追加されます。再起動時に /sys/fs/pstore/console-pstore-blk-0.

ftrace_size¶

ftrace front-endのチャンクサイズ（KB）。これは MUST 4の倍数でなければなりません。consoleログに興味がない場合はオプションです。

oops front-endと同様に、CPUプロセッサ数に応じて複数のチャンクが存在します。各チャンクサイズはftrace_size / processors_countに等しくなります。

すべてのftraceログがチャンクに追加されます。再起動時に統合され、 /sys/fs/pstore/ftrace-pstore-blk-0.

max_reason¶

kmsgダンプの保存対象を制限するには、 max_reason 値を設定します。これはinclude/linux/kmsg_dump.hの enum kmsg_dump_reasonで定義されています。例えば、OopsとPanicsの両方を保存するには、 max_reason を2（KMSG_DUMP_OOPS）に設定し、Panicsのみを保存するには、 max_reason を1（KMSG_DUMP_PANIC）に設定します。この値を0（KMSG_DUMP_UNDEF）に設定すると、理由フィルタリングは printk.always_kmsg_dump ブートパラメータで制御されます。未設定の場合はKMSG_DUMP_OOPS、設定されている場合はKMSG_DUMP_MAXになります。

ドライバの設定¶

ブロックデバイスドライバのみがこれらの設定に興味を持ちます。ブロックデバイスドライバは register_pstore_blk を介してpstore/blkに登録します。

非ブロックデバイスドライバは register_pstore_device with struct pstore_device_info を介してpstore/blkに登録します。

圧縮とヘッダー¶

ブロックデバイスは圧縮せずにオプスデータを保存するのに十分なサイズです。実際にはデータ圧縮を推奨していません。pstore/blk はオプス/パニックデータの最初の行に情報を挿入するためです。たとえば：

Panic: Total 16 times

これは、最初の起動以降で16回目のオプス|パニックを意味します。時折、最初の起動以降のオプス|パニックの発生回数はシステムの安定性を判断するために重要です。

次の行は pstore ファイルシステムによって挿入されます。たとえば：

Oops#2 Part1

これは、最後の起動で2回目のオプスを意味します。

データの読み取り¶

ダンプデータは pstore ファイルシステムから読み取れます。これらのファイルの形式は dmesg-pstore-blk-[N] オプス/パニックフロントエンド用に pmsg-pstore-blk-0 pmsg フロントエンドなど。ダンプファイルのタイムスタンプはトリガー時間を記録します。ブロックデバイスから保存された記録を削除するには、対応する pstore ファイルをアンリンクするだけです。

パニック読み書きAPIでの注意点¶

パニック状態では、カーネルが長時間動作しなくなるため、タスクのスケジューリングが行われず、ほとんどのカーネルリソースが利用できなくなります。これは、単一コアコンピュータで動作する単一スレッドのプログラムに似ています。

以下の点は、パニック読み書きAPIで特に注意が必要です：

  1. 可能であれば 禁止です メモリを割り当てることはできません。メモリが必要な場合は、ブロックドライバーが初期化している間に割り当ててください。パニックを待つのではなく。

  2. ポーリングでなければなりません、 禁止です 割り込み駆動です。タスクのスケジューリングは行われません。ブロックドライバーは書き込みが成功するまで遅延をかけてください。ただし、スリープしてはいけません。

  3. 可能であれば 禁止です ロックを取得することはできません。他のタスクも共有リソースもないため、すべてのロックを破壊しても安全です。

  4. CPUのみで転送してください。DMAを使用する場合は、DMAがロックを保持しないことを確認してください。

  5. レジスタを直接制御してください。Linuxカーネルリソースを使用するのではなく、レジスタを直接制御してください。パニックが発生するのを待つ代わりに、初期化中にI/Oマップを行ってください。

  6. 必要に応じてブロックデバイスとコントローラーをリセットしてください。パニック発生時のブロックデバイスとコントローラーの状態が不明な場合は、停止してリセットするのも安全です。

pstore/blk は psblk_blkdev_info() をサポートしており、これは linux/pstore_blk.h、ブロックデバイスの使用に関する情報を取得できます。たとえば、デバイス番号、セクタ数、全体のディスクの開始セクタなどです。
