システムスリープ状態¶

著者

スリープ状態は、ユーザー空間コードの実行が不可能で、全体的なシステム活動が大幅に低下する、システム全体のグローバルな低消費電力状態です。

サポート可能なスリープ状態¶

Linux カーネルは、プラットフォームの設定と機能に応じて、最大で4つのシステムスリープ状態（ヒーブレーションを含む）をサポートできます。また、システムスリープの変体として最大3つの種類をサポートします。サポート可能なスリープ状態は以下に示します。

スリープ（S2IまたはS2Idle）¶

これは、ユーザー空間を凍結し、時刻保持を停止し、すべてのI/Oデバイスを低消費電力状態（作業状態よりも低い消費電力の状態）に置くことで、より多くの電力を節約できる汎用的なソフトウェアのみのスリープ変体です。これにより、プロセッサが最も深いアイドル状態で動作できるようになり、システム全体の電力消費を削減します。

この状態では、バンド内割込みによってシステムが復帰します。理論上、作業状態で割込みを発生させることができるすべてのデバイスが、S2Idleの復帰デバイスとして設定できます。

この状態は、 standby または suspend-to-RAMをサポートしていないプラットフォームでも使用可能です。また、より深いシステムスリープ変体と併用することで、再起動遅延を減らすことができます。常にサポートされるのは、 CONFIG_SUSPEND kernel configuration option is set.

スタンバイ¶

この状態は、中程度ですが現実的な電力節約が可能で、作業状態に戻る際の移行が比較的簡単です。どの作業状態も失われません（システムコアロジックは電力を維持しています）。そのため、システムは簡単に中断した場所に戻ることができます。

ユーザー空間を凍結し、時刻保持を停止し、すべてのI/Oデバイスを低消費電力状態に置くのは、 スリープ（S2IまたはS2Idle） の場合と同じですが、非起動CPUをオフラインにし、移行時にすべての低レベルシステム機能を停止します。このため、 スリープ（S2IまたはS2Idle）よりもより多くの電力を節約できるかもしれませんが、再起動遅延は一般的にその状態よりも長くなります。

この状態でシステムを起動できるデバイスのセットは、通常、 スリープ（S2IまたはS2Idle） よりも少なくなります。適切なwakeup機能の設定には、プラットフォームに依存する場合があります。

この状態は、 CONFIG_SUSPEND カーネルの設定オプションが設定され、プラットフォームがコアシステムスリープサブシステムにサポートを登録している場合、この状態はACPIベースのシステムではACPIで定義されたS1システム状態にマッピングされます。

Suspend-to-RAM（STRまたはS2RAMとも呼ばれる）¶

この状態（STRまたはS2RAMとも呼ばれる）は、サポートされている場合、システム内のすべてのものが低電力状態に移行され、メモリを除いて、メモリはコンテンツを保持するためにセルフリフレッシュモードに置かれるため、大幅な電力節約が可能です。システムの起動時に実行されるすべてのステップは、S2RAMへの移行時にも同様に実行されます。 standby 追加の操作はプラットフォームの機能に応じて行われることがあります。特に、ACPIベースのシステムでは、S2RAMへの移行の最後のステップとして、カーネルがプラットフォームファームウェア（BIOS）に制御を渡します。これにより、カーネルが直接制御していない低レベルのコンポーネントの電源がオフになることが通常あります。

デバイスおよびCPUの状態はメモリに保存され保持されます。すべてのデバイスがスリープ状態に移行され、低電力状態に置かれます。多くの場合、S2RAMへの移行時にすべてのペリフェラルバスが電源を失うため、デバイスはON状態への復帰を処理できる必要があります。

ACPIベースのシステムでは、S2RAMにはプラットフォームファームウェアに最低限のブートストラピングコードが存在してシステムを再開する必要があります。これは他のプラットフォームでも同様に適用される場合があります。

S2RAMからシステムを再開できるデバイスのセットは、通常、〜に比べて減少しています。 スリープ（S2IまたはS2Idle） および standby よりも少なくなります。適切なwakeup機能の設定には、プラットフォームに依存する場合があります。

S2RAMは、〜が設定されていて、プラットフォームがコアシステムスリープサブシステムにサポートを登録している場合にサポートされます。 CONFIG_SUSPEND カーネルの設定オプションが設定され、プラットフォームがコアシステムスリープサブシステムにサポートを登録している場合、ACPIベースのシステムではこの状態はACPIで定義されたS3システム状態にマッピングされます。

ヒーバート（スリープトディスクまたはSTDとも呼ばれる）¶

この状態（スリープトディスクまたはSTDとも呼ばれる）は、システムスリープの低レベルプラットフォームサポートがなくても最大の電力節約が可能で、システムを再開するための低レベルのコードがCPUアーキテクチャに存在する必要があります。

ヒーバートは、システムスリープのどの変異種とも大きく異なります。ヒーバート状態に移行するには3つのシステム状態変化が必要で、再開には2つのシステム状態変化が必要です。

まず、ヒbernationがトリガーされる際、カーネルはシステム全体の活動を停止し、メモリのスナップショット画像を作成して永続ストレージに書き込みます。次に、スナップショット画像を保存できる状態にシステムが移行し、画像が書き出され、最後に電源をほぼすべてのハードウェアコンポーネントから切断した低消費電力状態に移行します（メモリを含むが、限定されたウェイクアップデバイスを除く）。

スナップショット画像が書き出された後、システムは特別な低消費電力状態（例：ACPI S4）に移行するか、または自身の電源を切るかのいずれかを選択します。電源を切る状態は最小限の電力消費を実現し、このメカニズムがどのシステムでも動作するようにします。しかし、特別な低消費電力状態に移行すると、キーボードのキーを押すなど、追加のシステムウェイクアップ手段が利用可能になります。

ウェイクアップ後、プラットフォームファームウェアがブートローダーを実行し、カーネルの新しいインスタンスを起動します（システムの構成により、直接ブートローダーに制御が移る場合もありますが、いずれにしても新しいカーネルインスタンスが起動します）。この新しいカーネルインスタンス（以下、 restore kernelと呼ばれます）は永続ストレージに保存されたhibernation画像を検索し、見つかった場合はメモリにロードします。次に、システム全体の活動を停止し、復元カーネルが画像の内容で自身を上書きし、画像に保存された元のカーネル内の特別なトリップモールエリア（以下、 image kernelと呼ばれます）にジャンプします。このエリアには、特別なアーキテクチャ固有の低レベルコードが必要です。最後に、画像カーネルがシステムをhibernation前の状態に戻し、ユーザー空間の実行を再開します。

hibernationは、 CONFIG_HIBERNATION カーネルの設定オプションが設定されている場合にサポートされます。ただし、このオプションは、指定されたCPUアーキテクチャがシステム再開用の低レベルコードを含んでいる場合にのみ設定可能です。

基本 sysfs システムスリープおよびhibernationのインターフェース¶

電源管理サブシステムは、ユーザー空間に統一された sysfs インターフェースを提供し、どの下位システムアーキテクチャやプラットフォームでもシステムスリープを実行可能にします。このインターフェースは、 /sys/power/ ディレクトリに位置しています（ sysfs が /sysにマウントされていると仮定）

state

このファイルには、カーネルがサポートするスリープ状態を表す文字列の一覧が含まれています。このファイルにこれらの文字列のいずれかを書き込むと、カーネルがその文字列で表されるスリープ状態への移行を開始します。

特に、「disk」、「freeze」および「standby」の文字列は、 hibernationを表します, スリープ（S2IまたはS2Idle） および standby スリープ状態それぞれに対応します。"mem"文字列は、下記のファイルの内容に従って解釈されます。 mem_sleep ファイル

カーネルがどのシステムスリープ状態もサポートしない場合、このファイルは存在しません。

mem_sleep

このファイルには、サポートされているシステムスリープの変異を表す文字列の一覧が含まれており、ユーザー空間が上記のファイルの"mem"文字列に関連付ける変異を選択できるようにします。 state ファイル

このファイルに存在する可能性のある文字列は"s2idle"、"shallow"、"deep"です。"s2idle"文字列は常に スリープ（S2IまたはS2Idle） 慣例により、"shallow"および"deep"は standby および suspend-to-RAMそれぞれを表します。

このファイルに上記の文字列のいずれかを書き込むと、その文字列が表すシステムスリープの変異が上記のファイルの"mem"文字列に関連付けられます。 state 上記のファイルの"mem"文字列に関連付けられている変異を表す文字列が state ファイルに表示されます。

カーネルがシステムスリープをサポートしない場合、このファイルは存在しません。

disk

このファイルは、ハイブリッドスリープ（Suspend-to-Disk）の動作モードを制御します。具体的には、カーネルにハイブリッドイメージを作成した後に実行すべき動作を指定します。

このファイルから読み取ると、サポートされているオプションの一覧がエンコードされた形式で返されます。

platform

システムを特別な低電力状態（例：ACPI S4）に移行し、追加の wakeup オプションを有効化し、 wakeup 後にプラットフォームファームウェアが簡略化された初期化パスを取る可能性を提供します。

プラットフォームがハイブリッドイメージを作成した後にシステムをスリープ状態に移行する特別なメカニズムを提供している場合にのみ利用可能です（例：ACPI をサポートするプラットフォーム）。

shutdown

システムを電源を切る。

reboot

システムを再起動する（主に診断に使用されます）。

suspend

ハイブリッドシステムスリープ。上記のファイルで選択されたスリープ状態にシステムを移行します。 mem_sleep システムがその状態から成功裏に wakeup した場合、ハイブリッドイメージを破棄して継続します。それ以外の場合は、イメージを使用してシステムの以前の状態を復元します。

システムスリープがサポートされている場合にのみ利用可能です。

test_resume

診断操作。システムがハイブリッドから wakeup したかのようにイメージをロードし、現在実行中のカーネルインスタンスが復元カーネルであるかのように処理し、その後、フルシステムの再開を実行します。

上記の文字列のうちの1つをこのファイルに書き込むと、その文字列が表すオプションが選択されます。

現在選択されているオプションは角括弧で表示され、ハイブリッドがこのファイルに書き込まれてイメージが作成・保存された後にそのオプションが実行されることを意味します。 disk に（木の下から葉に向かって） /sys/power/state.

カーネルがハイブリッドをサポートしない場合、このファイルは存在しません。

image_size

このファイルは休止画像のサイズを制御します。

非負の整数を表す文字列を書き込むことで、画像サイズのベストエフォートの上限として使用されるバイト単位の値を設定できます。休止コアはその数を超えないようにする努力をしますが、それが不可能な場合でも休止画像が作成され、可能な限り小さなサイズになります。特に、「0」をこのファイルに書き込むと休止画像のサイズが最小になります。

読み込むと現在の画像サイズの上限が返されます。これはデフォルトでは利用可能なRAMサイズの約2/5に設定されています。

pm_trace

このファイルは、再起動を跨いでRTCメモリに最後の休止または再開イベントポイントを保存する「PM trace（パワーマネジメントトレース）」メカニズムを制御します。これにより、システム休止または再開中に発生するデバイスドライバの障害によるハードロックアップや再起動のデバッグがより効果的になります。

このファイルに「1」が含まれている場合、各休止/再開イベントポイントのフィンガープリントがRTCメモリに保存されます（実際のRTC情報は上書きされます）。これにより、システムクラッシュが発生した後でも生存し、後でクラッシュの原因となったドライバを特定できます。

デフォルトでは「0」が含まれており、ゼロでない整数を表す文字列を書き込むことで「1」に変更できます。

上記により、システムが状態に入る方法は2通りあります。 スリープ（S2IまたはS2Idle） 1つ目の方法は、直接「freeze」を /sys/power/stateファイルに書き込むことです。2つ目の方法は、「s2idle」を /sys/power/mem_sleep そして「mem」を書き込む /sys/power/state。同様に、システムがこの状態に入る方法は2通りあります（その場合、制御ファイルに書き込む文字列は「standby」または「shallow」と「mem」のいずれかです）ただし、この状態がプラットフォームでサポートされている場合に限り、システムがこの状態に入る方法は1通りだけです standby 状態（その場合、制御ファイルに書き込む文字列は「standby」または「shallow」と「mem」のいずれかです）ただし、この状態がプラットフォームでサポートされている場合に限り、システムがこの状態に入る方法は1通りだけです suspend-to-RAM 状態（「deep」を書き込む /sys/power/mem_sleep および「mem」を書き込む /sys/power/state).

デフォルトのスリープモードの種類（つまり、設定を一切変更せずに使用する場合のもの）は、 /sys/power/mem_sleep) 通常のシステムで「ディープ」（ほとんどのサポートしているシステムで suspend-to-RAM) または「s2idle」ですが、カーネルコマンドラインのパラメーターの値によって上書きされることがあります。 mem_sleep_default パラメーターの値によって上書きされることがあります。一部のACPIをサポートするシステムでは、ACPIテーブルに含まれる情報によって、原則的にサポートされています。 suspend-to-RAM は原則的にサポートされています。
