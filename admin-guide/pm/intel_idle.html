General Information¶

intel_idle intel_idle ドライバーは、 CPU idle time management subsystem in the Linux kernel (CPUIdle). It is the default CPU idle time management driver for the Nehalem and later generations of Intel processors, but the level of support for a particular processor model in it depends on whether or not it recognizes that processor model and may also depend on information coming from the platform firmware. [To understand intel_idle it is necessary to know how CPUIdle works in general, so this is the time to get familiar with CPUアイドル時間管理 if you have not done that yet.]

intel_idle は MWAIT instruction to inform the processor that the logical CPU executing it is idle and so it may be possible to put some of the processor’s functional blocks into low-power states. That instruction takes two arguments (passed in the EAX および ECX registers of the target CPU), the first of which, referred to as a hint, can be used by the processor to determine what can be done (for details refer to Intel Software Developer’s Manual 1). Accordingly, intel_idle refuses to work with processors in which the support for the MWAIT instruction has been disabled (for example, via the platform firmware configuration menu) or which do not support that instruction at all.

intel_idle is not modular, so it cannot be unloaded, which means that the only way to pass early-configuration-time parameters to it is via the kernel command line.

Enumeration of Idle States¶

Each MWAIT hint value is interpreted by the processor as a license to reconfigure itself in a certain way in order to save energy. The processor configurations (with reduced power draw) resulting from that are referred to as C-states (in the ACPI terminology) or idle states. The list of meaningful MWAIT hint values and idle states (i.e. low-power configurations of the processor) corresponding to them depends on the processor model and it may also depend on the configuration of the platform.

In order to create a list of available idle states required by the CPUIdle subsystem (see アイドル状態の表現 の CPUアイドル時間管理), intel_idle can use two sources of information: static tables of idle states for different processor models included in the driver itself and the ACPI tables of the system. The former are always used if the processor model at hand is recognized by intel_idle and the latter are used if that is required for the given processor model (which is the case for all server processor models recognized by intel_idle) またはプロセッサモデルが認識されていない場合。[ドライバーがそのプロセッサモデルを認識するものとしてACPIテーブルを使用できるようにするモジュールパラメータがあります; 詳細は に記載されています。.]

アイドル状態のコアおよびパッケージレベル¶

プロセッサが MWAIT 命令をサポートしている場合、通常、少なくとも2段階のアイドル状態（またはC状態）があります。1段階は「コアC状態」と呼ばれ、プロセッサ内の個々のコアをカバーし、もう1段階は「パッケージC状態」と呼ばれ、全体のプロセッサパッケージをカバーし、システムの他のコンポーネント（GPU、メモリコントローラー、I/Oホストなど）も含むことがあります。

一部の MWAIT ヒント値はプロセッサにコアC状態のみを使用させます（特に、 MWAIT ヒント値に対応する C1 アイドル状態ではこのようにしますが、ほとんどのヒント値はプロセッサにターゲットコア（つまり、論理CPUが MWAIT ヒント値で実行されているコア）を特定のコアC状態に移行させ、その後（可能であれば）より深いレベルの特定のパッケージC状態に移行させることができます。たとえば、 MWAIT ヒント値が表す C3 アイドル状態はプロセッサにターゲットコアを「コア C3」（または CC3）という低消費電力状態に移行させます。 MWAIT これは、そのコア内のすべての論理CPU（SMTスレッド）が C3 ヒント値（またはより深いアイドル状態を表すヒント値）で実行された場合に発生します。さらに、ほとんどの場合、プロセッサに全体のパッケージ（GPUやメモリコントローラーなどの非CPUコンポーネントを含む可能性がある）を「パッケージ C3」（または PC3」という低消費電力状態に移行させる許可を与えます。これは、すべてのコアが CC3 状態に移行し、（可能性がある場合）追加の条件が満たされたときに発生します（たとえば、GPUが PC3をカバーしている場合、GPUに特定の低消費電力状態が求められることがあります）。 PC3 を到達可能にするためには。

パッケージC状態への移行条件が満たされている場合、プロセッサがコアC状態のみを使用するには簡単な方法がありませんので、論理CPUが MWAIT コアレベルのみのヒント値で実行されていない（たとえば、 C1の場合）場合は、常にプロセッサがパッケージC状態に移行する可能性があると想定しなければなりません。[これはなぜなら、"内部"アイドル状態テーブルのほとんどの MWAIT ヒント値に対応する退出遅延およびターゲットリザディENCY値がパッケージC状態の特性を反映しているからです。] パッケージC状態を使用することが全く望ましくない場合、どちらか一方の方法を採用できます。 intel_idle の"内部"アイドル状態テーブル内の PM QoS …または…、 max_cstate モジュールパラメータの intel_idle 記載されている 上記 コアレベルのみを許可する範囲に制限する必要があります MWAIT ヒント値（例として C1).
