Linuxカーネルリリース5.x <http://kernel.org/>¶

これはLinuxバージョン5のリリースノートです。よく読みましょう。これらはこのリリースの概要を説明し、カーネルのインストール方法や何かがうまくいかない場合の対処法を説明しています。

Linuxとは何ですか？¶

LinuxはUnixオペレーティングシステムのクローンで、リンス・トーラルズがネットワーク上のハッカーたちの協力によりから scratch で書いたものです。POSIXおよびSingle UNIX Specificationの準拠を目指しています。

現代の完全なUnixに期待されるすべての機能を備えており、真のマルチタスク、仮想メモリ、共有ライブラリ、デマンドロード、共有コピオンライターエクセクティブ、適切なメモリ管理、IPv4およびIPv6を含むマルチスタックネットワーキングなどが含まれます。

GNU一般公衆許諾/licenses v2に基づいて配布されています - 詳細については同梱の COPYING ファイルを参照してください。

どのハードウェアで動作しますか？¶

もともとは32ビットx86ベースのPC（386またはそれ以上）向けに開発されましたが、現在は（少なくとも）コンパク・アルファAXP、Sun SPARCおよびUltraSPARC、モトローラ68000、PowerPC、PowerPC64、ARM、日立SuperH、Cell、IBM S/390、MIPS、HP PA-RISC、インテルIA-64、DEC VAX、AMD x86-64 Xtensa、ARCアーキテクチャでも動作します。

Linuxは、ページングされたメモリ管理ユニット（PMMU）とGNU Cコンパイラ（gcc）（GNUコンパイラコレクション、GCCの一部）の移植が可能であれば、ほとんどの汎用32ビットまたは64ビットアーキテクチャに簡単に移植可能です。PMMUを持たないアーキテクチャにも移植されていますが、その場合機能は明らかに制限されます。Linuxは自身にも移植されています。現在、カーネルをユーザー空間アプリケーションとして実行できます。これはUserMode Linux（UML）と呼ばれます。

ドキュメンテーション¶

  • インターネット上の電子形式および書籍で、Linux固有のものも含めて一般UNIXに関する情報も豊富にあります。Linux FTPサイトのドキュメンテーションサブディレクトリにあるLDP（Linuxドキュメンテーションプロジェクト）の書籍を確認することをお勧めします。このREADMEはシステムに関するドキュメンテーションの目的ではありません。より優れた情報源があります。

  • Documentation/サブディレクトリにはさまざまなREADMEファイルがあります。これらは通常、いくつかのドライバのためのカーネル固有のインストール手順を含みます。Please read the カーネルをコンパイルするための最小限の要件 ファイルを読みましょう。これは、カーネルのアップグレードによって生じる問題に関する情報を含んでいます。

カーネルソースのインストール¶

  • フルソースをインストールする場合は、カーネルのtarballを権限があるディレクトリ（例：ホームディレクトリ）に配置し、展開してください：

    xz -cd linux-5.x.tar.xz | tar xvf -

    「X」を最新のカーネルのバージョン番号に置き換えてください。

    「/usr/src/linux」エリアは使用しないでください！ このエリアには、ライブラリヘッダーファイルによって使用される（通常は不完全な）カーネルヘッダーファイルが含まれており、これらはライブラリと一致する必要があります。カーネルの最新版（kernel-du-jour）によって誤って変更されないようにしてください。

  • 5.xリリース間でのアップグレードはパッチ適用によって可能です。パッチはxz形式で配布されています。パッチ適用でインストールする場合、すべての新しいパッチファイルを取得し、カーネルソースのトップレベルディレクトリ（linux-5.x）に移動して、以下のコマンドを実行してください：

    xz -cd ../patch-5.x.xz | patch -p1

    現在のソースツリーのバージョン「x」より大きいすべてのバージョンに「x」を置き換えてください、 in_order、そして問題ありません。バックアップファイル（some-file-name~ または some-file-name.orig）を削除することを検討し、失敗したパッチ（some-file-name# または some-file-name.rej）がないことを確認してください。ある場合は、あなたまたは私どちらかが間違いを犯した可能性があります。

    5.xカーネルのパッチとは異なり、5.x.yカーネル（-stableカーネルとも呼ばれる）のパッチはインクリメンタルではなく、ベースとなる5.xカーネルに直接適用されます。たとえば、ベースカーネルが5.0で5.0.3パッチを適用したい場合、まず5.0.1と5.0.2のパッチを適用しないでください。同様に、カーネルバージョン5.0.2で5.0.3にジャンプしたい場合、まず5.0.2のパッチを逆適用（patch -R）してから5.0.3のパッチを適用してください。 before 5.0.3パッチを適用してください。このについての詳細は Linuxカーネルへのパッチ適用.

    代替として、スクリプトpatch-kernelを使用してこのプロセスを自動化できます。このスクリプトは現在のカーネルバージョンを判定し、見つかったすべてのパッチを適用します：

    linux/scripts/patch-kernel linux

    上のコマンドの最初の引数はカーネルソースの場所です。パッチは現在のディレクトリから適用されますが、第二引数として別のディレクトリを指定することも可能です。

  • 古い.oファイルや依存関係が残っていないことを確認してください：

    cd linux
make mrproper

    これでソースが正しくインストールされているはずです。

ソフトウェア要件¶

5.xカーネルのコンパイルおよび実行には、さまざまなソフトウェアパッケージの最新バージョンが必要です。参照してください カーネルをコンパイルするための最小限の要件 必要な最小バージョン番号とこれらのパッケージの更新方法。極めて古いバージョンを使用すると、構築または運用中に明らかに問題が発生した場合でも、間接的なエラーが発生し、非常に困難に解決することがあります。そのため、明確な問題が発生したときにパッケージを更新するだけでは十分ではありません。

カーネルのビルドディレクトリ¶

カーネルをコンパイルする際、すべての出力ファイルはデフォルトではカーネルソースコードと同様に保存されます。オプションを使用することで、 make O=output/dir 出力ファイル（.config を含む）の代替保存場所を指定できます。例:

kernel source code: /usr/src/linux-5.x
build directory:    /home/name/build/kernel

カーネルを構成し、ビルドするには以下のコマンドを使用してください：

cd /usr/src/linux-5.x
make O=/home/name/build/kernel menuconfig
make O=/home/name/build/kernel
sudo make O=/home/name/build/kernel modules_install install

注意： O=output/dir オプションを使用する場合、make のすべての呼び出しでこのオプションを指定する必要があります。

カーネルの構成¶

カーネルのマイナーバージョンをアップグレードする場合でも、このステップをスキップしないでください。各リリースで新しい構成オプションが追加されるため、構成ファイルが想定通りに設定されていない場合、予期せぬ問題が発生する可能性があります。既存の構成を新しいバージョンに最小限の作業で移行する場合は、 make oldconfigを使用して、新たに出現した質問にのみ答えるようにします。

  • 新しいカーネルで再起動して、楽しんでください。

何かがうまくいかない場合¶

  • カーネルのバグによる問題が発生した場合は、ファイル MAINTAINERS を確認し、問題が発生しているカーネルの部分に関連する特定の人物が記載されているかご確認ください。記載されていない場合は、私（torvalds@linux-foundation.org) にメールでご連絡いただくのが二番目に良い方法です。また、関連するメーリングリストやニュースグループにも送信するかもしれません。
