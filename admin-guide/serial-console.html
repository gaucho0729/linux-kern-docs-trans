Linux シリアルコンソール¶

シリアルポートをコンソールとして使用するには、カーネルにサポートを組み込む必要があります（デフォルトでは組み込まれていません）。PCスタイルのシリアルポートでは、メニュー項目の隣にある設定オプション:

キャラクターデバイス ‣ シリアルドライバ ‣ 8250/16550 および互換シリアルサポート ‣ 8250/16550 および互換シリアルポートでのコンソール

シリアルサポートはカーネルに組み込む必要があります。モジュールとして組み込むのはできません。

コンソール出力に複数のデバイスを指定できます。新しいカーネルコマンドラインオプションを定義して、使用するデバイス（複数可）を指定できます。

このオプションの形式は:

console=device,options

device:         tty0 for the foreground virtual console
                ttyX for any other virtual console
                ttySx for a serial port
                lp0 for the first parallel port
                ttyUSB0 for the first USB serial device

options:        depend on the driver. For the serial port this
                defines the baudrate/parity/bits/flow control of
                the port, in the format BBBBPNF, where BBBB is the
                speed, P is parity (n/o/e), N is number of bits,
                and F is flow control ('r' for RTS). Default is
                9600n8. The maximum baudrate is 115200.

カーネルコマンドラインに複数の console= オプションを指定できます。出力はすべてのデバイスに表示されます。最後のデバイスがオープン時に使用されます /dev/console。たとえば:

console=ttyS1,9600 console=tty0

は、オープン時に /dev/console が現在の前景仮想コンソールを取得し、カーネルメッセージが VGA コンソールと 2 番目のシリアルポート（ttyS1 または COM2）の両方に 9600 ボーレートで表示されるようにします。

シリアル、ビデオの各デバイスタイプごとに1つのコンソールのみを定義できます。

コンソールデバイスを指定しなかった場合、システムコンソールとして動作可能な最初のデバイスが使用されます。現在、システムはまず VGA カードを検索し、その後シリアルポートを検索します。したがって、VGA カードがシステムにない場合、最初のシリアルポートが自動的にコンソールになります。

使用するには新しいデバイスを作成する必要があります /dev/console。公式の /dev/console は現在キャラクターデバイス 5,1 です。

(ネットワークデバイスもコンソールとして使用できます。その情報については Documentation/networking/netconsole.rst を参照してください。)

以下は、 /dev/ttyS1 (COM2) をコンソールとして使用する例です。必要に応じてサンプル値を置き換えてください。

  1. 作成 /dev/console (実際のコンソール) と /dev/tty0 (マスタービジコンソール):

    cd /dev
rm -f console tty0
mknod -m 622 console c 5 1
mknod -m 622 tty0 c 4 0

  2. LILO もシリアルデバイスから入力を受け付けることができます。これは非常に有用なオプションです。LILO にシリアルポートを使用させるには、lilo.conf（グローバルセクション）で:

    serial  = 1,9600n8 (ttyS1, 9600 bd, no parity, 8 bits)

  3. 新しいカーネルのカーネルフラグに合わせて調整してください。再度 lilo.conf（カーネルセクション）で:

    append = "console=ttyS1,9600"

  4. システムが起動後にログインできるように、シリアルポートで getty が動作するようにしてください。これは、 /etc/inittab (getty の正確な構文はシステムに依存します):

    S1:23:respawn:/sbin/getty -L ttyS1 9600 vt100

  5. init と /etc/ioctl.save

    Sysvinit は、シリアルコンソールを使用する際には、 /etcに配置された /etc/ioctl.saveというファイルに stty 設定を記憶します。シリアルコンソールを初めて使用する前にこのファイルを削除してください。そうしないと init がバウドレートを 38400（仮想コンソールのバウドレート）に設定してしまう可能性があります。

  6. /dev/console および X プログラムが仮想コンソールとやりとりする場合、通常 /dev/consoleを開きます。新しい /dev/console デバイス、そしてあなたのコンソールはバーチャルコンソールではありません。一部のプログラムが失敗する原因になります。これらはVTインターフェースにアクセスしたいプログラムで、使用 /dev/console instead of /dev/tty0します。その一部は以下の通りです。

    Xfree86, svgalib, gpm, SVGATextMode

    ただし、現代のバージョンではこれらのプログラムは修正されています。

    注意点として、指定オプション（または console= オプション（または console=/dev/tty0), /dev/console は同じです。その場合でもすべての機能は正常に動作します。 /dev/tty0。その場合でもすべての機能は正常に動作します。
