SRBDS — 特殊レジスタバッファデータサンプリング¶

SRBDS は、MDS（Microarchitectural Data Sampling）技術を用いて特殊レジスタアクセスから返される値を推測できるハードウェアの脆弱性です。 MDS — マイクロアーキテクチャデータサンプリング 特殊レジスタアクセスとは、オフコアレジスタへのアクセスを指します。インテルの評価によると、プライバシーを期待するセキュリティ上の特殊レジスタ読み込みは RDRAND、RDSEED および SGX EGETKEY です。

RDRAND、RDSEED および EGETKEY 指令が使用される場合、データは特殊レジスタメカニズムを通じてコアに移動し、これは MDS 攻撃に脆弱です。

影響を受けるプロセッサ¶

RDRAND および/または RDSEED を実装するコアモデル（デスクトップ、モバイル、Xeon-E3）は影響を受ける可能性があります。

Family_Model とステッピングが以下のリストにあるプロセッサは SRBDS に影響されます。ただし、インテル TSX が利用可能ながら未有効な状態で MDS_NO をエクスポートするプロセッサは、TSX_CTRL_MSR を使用してソフトウェアが TSX を有効にした場合にのみ影響を受けるため、そのクラスは影響を受ける可能性があります。

関連するCVE¶

以下の CVE エントリはこの SRBDS 問題に関連しています:

CVE-2020-0543

SRBDS

特殊レジスタバッファデータサンプリング

攻撃シナリオ¶

非特権ユーザーは、MDS 技術を用いて他のコアまたはスレッドの RDRAND および RDSEED の実行結果から値を抽出できます。

対策メカニズム¶

インテルは、RDRAND、RDSEED および EGETKEY 指令を修正したマイクロコードアップデートを公開し、秘密の特殊レジスタデータが他の論理プロセッサにアクセスされる前に共有ステージングバッファで上書きします。

RDRAND、RDSEED または EGETKEY 指令の実行中、他の論理プロセッサからのオフコアアクセスは、特殊レジスタ読み込みが完了し、共有ステージングバッファ内の秘密データが上書きされるまで遅延されます。

パフォーマンスには以下の3つの影響があります:

  1. RDRAND、RDSEED、または EGETKEY 指令のレイテンシーが高くなります。

  2. 複数の論理プロセッサで RDRAND を同時に実行すると、シリアル化され、最大 RDRAND バンド幅が全体的に低下します。

  3. RDRAND、RDSEED または EGETKEY の実行は、コアキャッシュにヒットしない論理プロセッサのメモリアクセスを遅延させ、伝統的なロックされたキャッシュライン分割アクセスに類似した影響があります。

マイクロコード更新により、RDRANDおよびRDSEED命令の実行がIntel Software Guard Extensions (Intel SGX) エンクロース外で行われる場合に、MITIGATIONを無効化するオプトアウトメカニズム（RNGDS_MITG_DIS）が提供されます。このオプトアウトメカニズムでMITIGATIONを無効化した論理プロセッサでは、RDRANDおよびRDSEEDの実行時間が長くなることはなく、同一論理プロセッサのメモリアクセス性能に影響を与えません。このオプトアウトメカニズムはIntel SGXエンクロース（エンクロース内のRDRANDまたはRDSEEDの実行、およびEGETKEY実行を含む）に影響を与えません。

IA32_MCU_OPT_CTRL MSRの定義¶

この問題に対するMITIGATIONに加えて、Intelは新しいスレッドスコープのIA32_MCU_OPT_CTRL MSR（アドレス0x123）を追加しました。このMSRおよびRNGDS_MITG_DIS（ビット0）の存在はCPUID.(EAX=07H,ECX=0).EDX[SRBDS_CTRL = 9]==1で列挙されます。このMSRはマイクロコード更新を通じて導入されました。

論理プロセッサのIA32_MCU_OPT_CTRL[0]（RNGDS_MITG_DIS）を1に設定すると、その論理プロセッサ上でIntel SGXエンクロース外で実行されるRDRANDおよびRDSEEDのMITIGATIONを無効化します。特定の論理プロセッサでのMITIGATIONのオプトアウトは、他の論理プロセッサのRDRANDおよびRDSEEDのMITIGATIONに影響を与えません。

Intel SGXエンクロース内では、RNGDS_MITG_DSの値に関係なくMITIGATIONが適用されます。

カーネルコマンドラインでの緩和制御¶

カーネルコマンドラインは、起動時にSRBDS MITIGATIONを制御するためのオプション「srbds=」を提供します。このオプションは以下の通りです。

off

このオプションは、影響を受けるプラットフォームにおけるRDRANDおよびRDSEEDのSRBDS MITIGATIONを無効にします。

SRBDSシステム情報¶

Linuxカーネルはsysfsを通じて脆弱性ステータス情報を提供します。SRBDSについては、以下のsysfsファイルからアクセスできます：/sys/devices/system/cpu/vulnerabilities/srbds

このファイルに含まれる可能性のある値は以下の通りです：

影響なし

プロセッサは脆弱性がない

脆弱

プロセッサは脆弱性があり、MITIGATIONが無効化されている

脆弱性あり：マイクロコード未搭載

プロセッサは脆弱性があり、マイクロコードにMITIGATIONが搭載されていない

MITIGATION：マイクロコード

プロセッサは脆弱性があり、MITIGATIONが有効になっている

MITIGATION：TSX無効

このシステムがTSX無効で起動した場合、TSXが有効になっているときにのみプロセッサは脆弱性がある

不明：ハイパーザー状態に依存

仮想ゲストプロセッサで影響を受けており、ホストプロセッサがMITIGATIONを適用しているか脆弱性があるかを確認できない

SRBDSデフォルトMITIGATION

SRBDSデフォルトMITIGATION¶

この新しいマイクロコードは、RDRANDおよびRDSEEDの実行中にプロセッサのアクセスをシリアル化し、共有バッファが再利用のために解放される前に上書きされるように保証します。RDRANDおよびRDSEEDの緩和を無効にするには、「srbds=off」カーネル コマンドラインを使用してください。
