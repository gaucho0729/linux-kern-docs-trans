MDS — マイクロアーキテクチャデータサンプリング¶

マイクロアーキテクチャデータサンプリングは、CPU内部のさまざまなバッファに存在するデータに非特権の推測アクセスを許可するハードウェアの脆弱性です。

影響を受けるプロセッサ¶

この脆弱性は幅広いインテルプロセッサに影響を及ぼします。以下のプロセッサには影響はありません：

  • AMD、Centaur、およびその他の非インテルベンダーのプロセッサ

  • CPUファミリが6未満の古いプロセッサモデル

  • 一部のAtomプロセッサ（Bonnell、Saltwell、Goldmont、GoldmontPlus）

  • IA32_ARCH_CAPABILITIES MSRのARCH_CAP_MDS_NOビットが設定されているIntelプロセッサ

sysfs内のMDS脆弱性ファイルからプロセッサが影響を受けるかどうかを確認できます。参照してください MDSシステム情報.

すべてのプロセッサがすべてのMDSの変異種に影響されるわけではありませんが、緩和策はすべて同じため、カーネルはそれらを1つの脆弱性として扱います。

問題¶

ストア、ロード、L1リフィル操作を行う際、プロセッサは一時的なマイクロアーキテクチャ構造（バッファ）にデータを書き込みます。このバッファ内のデータは最適化のためにロード操作に転送されることがあります。

特定の条件下では、ロード操作によって引き起こされるエラー/アシストにより、ロードメモリアドレスとは関係のないデータがバッファから推測的に転送されることがあります。ロード操作はエラーまたはアシストを引き起こし、その結果は破棄されるため、転送されたデータは不正確なプログラム実行や状態変化を引き起こしません。しかし、悪意のある操作がこの推測データを漏洩ゲッタに転送することで、キャッシュサイドチャネル攻撃により値を推測できる可能性があります。

バッファはハイパースレッド間で共有される可能性があるため、ハイパースレッド横の攻撃が可能です。

より深い技術情報はMDS特有のx86アーキテクチャセクションで確認できます： マイクロアーキテクチャデータサンプリング（MDS）の緩和策.

攻撃シナリオ¶

MDS脆弱性への攻撃は、ホストまたはゲスト上で実行される悪意のある非特権ユーザー空間アプリケーションから行われる可能性があります。悪意のあるゲストOSも同様に攻撃を実行できます。

他の推測ベースの脆弱性とは異なり、MDS脆弱性は攻撃者がメモリターゲットアドレスを制御できません。その結果、攻撃は純粋にサンプリングベースとなりますが、TLBleed攻撃のようにサンプルを後処理して成功することが示されています。

ウェブブラウザ¶

ウェブブラウザを通じた攻撃が可能かどうかは不明です。JavaScriptを介した悪用は非常に可能性が低いとされていますが、Webassemblyなどの他の広く利用されているウェブ技術もまた、悪用される可能性があるとされています。

MDSシステム情報¶

Linuxカーネルは、システムの現在のMDS（Microarchitectural Data Sampling）状態を列挙するためのsysfsインターフェースを提供しています。これは、システムが脆弱かどうか、およびどの対策が有効かを示します。関連するsysfsファイルは以下の通りです：

/sys/devices/system/cpu/vulnerabilities/mds

このファイルの可能な値は次の通りです。

「影響を受けない」

プロセッサは脆弱性がありません

「脆弱（Vulnerable）」

プロセッサは脆弱ですが、対策が有効になっていません

「脆弱: CPUバッファのクリアを試みたが、マイクロコードが未更新（Vulnerable: Clear CPU buffers attempted, no microcode）」

プロセッサは脆弱ですが、マイクロコードが更新されていません。

対策は最大限の努力に基づいて有効になっています。参照： 「ベストエフォート対策モード（Best effort mitigation mode）」

「対策: CPUバッファのクリア（Mitigation: Clear CPU buffers）」

プロセッサは脆弱ですが、CPUバッファクリア対策が有効になっています。

プロセッサが脆弱な場合、以下の情報が上記情報に追加されます：

「SMT脆弱（SMT vulnerable）」

SMTが有効化されています

「SMT対策済み（SMT mitigated）」

SMTが有効かつ対策済み

「SMT無効（SMT disabled）」

SMTが無効化されています

「SMTホスト状態不明（SMT Host state unknown）」

カーネルが仮想マシン（VM）で動作しており、ホストのSMT状態が不明

「ベストエフォート対策モード（Best effort mitigation mode）」¶

プロセッサが脆弱な場合、CPUIDを通じてマイクロコードベースの対策メカニズムが宣伝されていない場合、カーネルはベストエフォート対策モードを選択します。このモードでは、CPUバッファをクリアする指令を実行しますが、その結果が確実にバッファをクリアするとは限りません。

これは、ホストがマイクロコード更新を適用しているが、ハイパーバイザがゲストにCPUIDを露出するまで更新されていない仮想化シナリオに対応するためです。ホストが更新されたマイクロコードを搭載している場合、保護が有効になります。そうでない場合、無駄なCPUサイクルが発生します。

mds sysfsファイル内の状態はこの状況を反映しています。

対策メカニズム¶

カーネルは影響を受けたCPUと、必要なマイクロコードの存在を検出します。

CPUが影響を受けている場合、マイクロコードが利用可能であれば、カーネルはデフォルトで対策を有効にします。この対策は起動時にカーネルコマンドラインオプションで制御可能です。参照： カーネルコマンドラインでの緩和制御.

「CPUバッファクリア（CPU buffer clearing）」¶

MDSの対策では、ユーザー空間に戻るときやゲストに入るときに影響を受けたCPUバッファをクリアします。

SMTが有効な場合、MSBDSのみに影響を受けているCPUではアイドル時の遷移時にバッファをクリアします。これは、他のMDSの変異種がクロスハイパースレッド攻撃に対して保護できないためです。

MSBDSのみに影響を受けているCPUでは、ユーザー空間、ゲスト、アイドル遷移の対策が十分であり、SMTは影響を受けません。

仮想化対策¶

ホストからゲストへの移行における保護は、CPUのL1TF脆弱性に依存します:

  • CPUはL1TFに影響されます:

    L1Dフラッシュの緩和が有効化され、最新のマイクロコードが利用可能な場合、L1Dフラッシュの緩和が自動的にゲスト移行を保護します。

    L1Dフラッシュの緩和が無効化されている場合、ホストのMDS緩和が有効化されているときにMDS緩和が明示的に呼び出されます。

    L1TFおよび仮想化に関する詳細については、以下を参照してください: L1TF — L1 Terminal Fault.

  • CPUはL1TFに影響されません:

    ホストのMDS緩和が有効化されている場合、ゲストに入る前にCPUバッファがフラッシュされます。

XEON PHIに関する特定の考慮事項¶

XEON PHIプロセッサファミリーはMSBDSに影響を受け、アイドル状態に入る際にハイパースレッド間で悪用される可能性があります。一部のXEON PHIバリエーションはユーザー空間（リング3）でMWAITを使用を許可しており、これは悪意のあるユーザー空間からの潜在的な攻撃ベクトルを開きます。この曝露は、カーネルコマンドラインで'ring3mwait=disable'というオプションを指定することで無効化できます。

XEON PHIは他のMDS変異種に影響されず、MSBDSはCPUがアイドル状態に入る前に緩和されています。XEON PHIはL1TFにも影響されないため、完全な保護のためSMTの無効化は必要ありません。

SMT制御¶

MSBDSを除くすべてのMDS変異種はハイパースレッド間で攻撃される可能性があります。つまり、MFBDSまたはMLPDSに影響されるCPUでは、完全な保護のためSMTを無効化する必要があります。これはほとんどの影響を受けたCPUに該当し、例外はXEON PHIです。参照: XEON PHIに関する特定の考慮事項.

SMTの無効化はパフォーマンスに大きな影響を与える可能性がありますが、影響の程度はワークロードの種類により異なります。

L1TF緩和ドキュメンテーションの関連する章を参照してください: L1TF — L1 Terminal Fault.

カーネルコマンドラインでの緩和制御¶

カーネルコマンドラインは起動時にオプション「mds=」を使用してMDS緩和を制御できます。このオプションの有効な引数は:

full

CPUが脆弱な場合、MDS脆弱性に対応するすべての緩和を有効化し、ユーザー空間への移行および仮想マシンへの移行時にCPUバッファをクリアします。SMTが有効化されている場合、アイドル移行も保護されます。

これは自動的にSMTを無効化しません。

full,nosmt

mds=fullと同じで、脆弱なCPUではSMTが無効化されています。これは完全な緩和です。

off

MDS緩和を完全に無効化します。

このオプションを指定しない場合、"mds=full"と同等です。TAA（TSX Asynchronous Abort）とMDSの両方に影響を受けるプロセッサでは、"mds=off"のみを指定して"tsx_async_abort=off"を併せて指定しないと、同じ緩和措置が両方の脆弱性に適用されるため、効果がありません。

緩和策選択ガイド¶

1. 信頼できるユーザースペース¶

すべてのユーザースペースアプリケーションが信頼できるソースから提供され、外部から供給された不信頼できるコードを実行しない場合、この緩和措置は無効化できます。

2. 信頼できるゲストを持つバーチャル化¶

信頼できるユーザースペースとの比較において同様の考慮事項が適用されます。

3. 信頼できないゲストを持つバーチャル化¶

保護はL1TFの緩和措置の状態に依存します。参照してください 仮想化対策.

MDSの緩和措置が有効化され、SMTが無効化されている場合、ゲストからホストへの攻撃およびゲストからゲストへの攻撃が防止されます。

デフォルトの緩和策¶

脆弱なプロセッサに対するカーネルのデフォルト緩和策は以下の通りです：

  • CPUバッファクリアリングを有効にする

カーネルはデフォルトでSMTの無効化を強制しません。これにより、不信頼できるコードを実行している場合、SMTシステムが脆弱になります。L1TFと同じ論理が適用されます。参照してください L1TF — L1 Terminal Fault.
