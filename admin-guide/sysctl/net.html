1. /proc/sys/net/core - ネットワークコアオプション¶

bpf_jit_enable¶

これはBPFジャストインタイム（JIT）コンパイラを有効にする設定です。BPFは柔軟で効率的なインフラストラクチャであり、さまざまなハックポイントでバイナリコードを実行できます。ネットワーク（例：XDP、tc）、トレース（例：kprobes、uprobes、tracepoints）、セキュリティ（例：seccomp）などのLinuxカーネルサブシステムで使用されています。LLVMにはBPFバックエンドがあり、制限されたCコードをBPF命令のシーケンスにコンパイルできます。bpf(2)を通じてプログラムをロードし、カーネル内の検証器を通過した後、JITはこれらのBPFプローグレットをネイティブCPU命令に変換します。JITには2つの種類があり、新しいeBPF JITは以下のアーキテクチャでサポートされています：

  • x86_64

  • x86_32

  • arm64

  • arm32

  • ppc64

  • sparc64

  • mips64

  • s390x

  • riscv64

  • riscv32

そして古いcBPF JITは以下のアーキテクチャでサポートされています：

  • mips

  • ppc

  • sparc

eBPF JITはcBPF JITのサブセットであり、カーネルがcBPF命令をeBPF命令に変換し、その後JITコンパイルを透明に実行します。古いcBPF JITはtcpdumpフィルターやseccompルールなどにのみ変換可能ですが、bpf(2)を通じてロードされたeBPFプログラムには対応していません。

値：

  • 0 - JITを無効化（デフォルト値）

  • 1 - JITを有効化

  • 2 - JITを有効化し、コンパイラにカーネルログにトレースを出力させる

bpf_jit_harden¶

これはBPF JITコンパイラの強化を有効にする設定です。サポートされているのはeBPF JITバックエンドです。強化はパフォーマンスを犠牲にしますが、JITスプレッドのリスクを軽減できます。

値：

  • 0 - JIT強化を無効化（デフォルト値）

  • 1 - 特権ユーザーのみにJIT強化を有効化

  • 2 - 全てのユーザーにJIT強化を有効化

bpf_jit_kallsyms¶

BPF JITコンパイラが有効な場合、コンパイルされたイメージはカーネルにとって未知のアドレスであり、トレースや/proc/kallsymsには表示されません。この設定により、これらのアドレスをエクスポートでき、デバッグやトレースに利用できます。bpf_jit_hardenが有効な場合、この機能は無効になります。

値：

  • 0 - JIT kallsymsエクスポートを無効化（デフォルト値）

  • 1 - 特権ユーザーのみにJIT kallsymsエクスポートを有効化

bpf_jit_limit¶

これはBPF JITコンパイラのメモリ割当にグローバルな制限を課す設定で、非特権ユーザーのJITリクエストを制限します。bpf_jit_limitはバイト単位のグローバル制限値を表します。

dev_weight¶

NAPI割込みでカーネルが処理可能な最大パケット数で、CPUごとの変数です。LROまたはGRO_HWをサポートするドライバでは、ハードウェアのアグリゲートパケットはこの文脈で1つのパケットとしてカウントされます。

デフォルト: 64

dev_weight_rx_bias¶

RPS（例: RFS、aRFS）処理が、ドライバの登録済みNAPIポール関数と競合しています。このパラメータは、RXソフトIRQサイクル中にRPSベースのパケット処理に使用されるネットデバイス予算の割合を制御します。また、ネットワークスタックのRX/TX側における非対称CPU需要に応じて現在のdev_weightを調整するためのものです。（dev_weight_tx_biasを参照）CPUごとに有効であり、dev_weightに基づいて計算され、乗算（dev_weight * dev_weight_rx_bias）によって決定されます。

デフォルト: 1

dev_weight_tx_bias¶

TXソフトIRQサイクル中に処理可能な最大パケット数をスケールします。CPUごとに有効であり、現在のdev_weightを非対称なネットワークスタック処理需要に応じてスケール可能にします。TXソフトIRQ処理がCPUを食い尽くすのを避けるため、注意が必要です。

dev_weight（dev_weight * dev_weight_tx_bias）に基づいて計算されます。

デフォルト: 1

default_qdisc¶

ネットワークデバイスに使用するデフォルトのキューイングディスパッチ（qdisc）。これはpfifo_fastをオーバーライドして代替のディスパッチを指定するためのものです。デフォルトのキューイングディスパッチは追加パラメータなしで作成されるため、設定なしで動作するキューイングディスパッチ（例: ストーナグ・フェアキュー（sfq）、CoDel（codel）、フェアキューCoDel（fq_codel）など）に最適です。Hierarchical Token BucketやDeficit Round Robinなどの設定が必要なキューイングディスパッチは使用しないでください。物理的なマルチキューインターフェースは依然としてmqをルートqdiscとして使用し、その葉はこのデフォルトを使用します。仮想デバイス（例: loやveth）はこの設定を無視し、デフォルトではnoqueueを使用します。

デフォルト: pfifo_fast

busy_read¶

ソケット読み取り時の低レイテンシーなビジー_POLLタイムアウト。(CONFIG_NET_RX_BUSY_POLLが必要) デバイスキューでのパケット待機にかかる時間（マイクロ秒単位）。これはSO_BUSY_POLLソケットオプションのデフォルト値を設定します。個別にソケットごとにSO_BUSY_POLLオプションを設定することでオーバーライド可能です（推奨方法）。sysctlを介してグローバルに有効化する必要がある場合は、50が推奨されます。

電力消費量が増加します。

デフォルト: 0（オフ）

busy_poll¶

pollおよびselect用の低遅延で忙しいポールタイムアウト。(CONFIG_NET_RX_BUSY_POLLが必要) イベントを待つための忙しいループの概算時間（マイクロ秒）。推奨値はポールするソケットの数に依存します。複数のソケットの場合50、複数百の場合は100。それ以上の場合epollを使用することを検討してください。注意: SO_BUSY_POLLが設定されたソケットのみ忙しいポールが行われるため、これらのソケットに選択的にSO_BUSY_POLLを設定するか、sysctl.net.busy_readをグローバルに設定してください。

電力消費量が増加します。

デフォルト: 0（オフ）

rmem_default¶

ソケット受信バッファのデフォルト設定（バイト数）。

rmem_max¶

受信ソケットバッファの最大サイズ（バイト数）。

tstamp_allow_data¶

プロセスが送信タイムスタンプを元パケットコンテンツとともに受信できるようにします。無効の場合、非特権プロセスからの送信タイムスタンプリクエストは、socketオプションSOF_TIMESTAMPING_OPT_TSONLYが設定されていない限り無視されます。

デフォルト: 1 (有効)

wmem_default¶

ソケット送信バッファのデフォルト設定（バイト数）。

wmem_max¶

送信ソケットバッファの最大サイズ（バイト数）。

message_burst and message_cost¶

これらのパラメータはネットワーキングコードからカーネルログに書き込まれる警告メッセージを制限するために使用されます。DoS攻撃を防ぐため、メッセージコストが高いほど書き込まれるメッセージ数が減少します。メッセージバーストはメッセージがドロップされるタイミングを制御します。デフォルト設定では5秒ごとに1つの警告メッセージが制限されます。

warnings¶

このsysctlは現在使用されません。

これはネットワーク上の問題（重複アドレスや不良チェックサムなど）により発生するネットワークスタックからのコンソールメッセージを制御するために使用されていました。

これらのメッセージは現在KERN_DEBUGレベルで出力され、動的デバッグ機能により有効化および制御できます。

netdev_budget¶

1つのNAPIポール（poll）サイクルで全インターフェースから取得するパケットの最大数。1つのポールサイクルではポールが登録されたインターフェースがラウンドロビン方式でスキャンされ、netdev_budget_usecsマイクロ秒を超えるとポールサイクルが終了します（netdev_budgetが枯渇していない場合でも）。

netdev_budget_usecs¶

1つのNAPIポールサイクルにおけるマイクロ秒の最大数。ポールサイクル中にnetdev_budget_usecsが経過するか、処理されたパケット数がnetdev_budgetに達するとポールが終了します。

netdev_max_backlog¶

インターフェースがカーネルが処理できるよりも速くパケットを受信した場合、INPUT側にキューイングされるパケットの最大数。

netdev_rss_key¶

RSS (Receive Side Scaling)を有効化したドライバは、ランダムに生成された40バイトのホストキーを使用します。一部のユーザースペースは、ドライバがethtool -xをサポートしていない場合でも、このキーの内容を取得する必要があります。

myhost:~# cat /proc/sys/net/core/netdev_rss_key
84:50:f4:00:a8:15:d1:a7:e9:7f:1d:60:35:c7:47:25:42:97:74:ca:56:bb:b6:a1:d8: ... (52 bytes total)

どのドライバもnetdev_rss_key_fill()関数を呼び出していない場合、ファイルにはヌルバイトが含まれます。

注意:

/proc/sys/net/core/netdev_rss_keyには52バイトのキーが含まれていますが、ほとんどのドライバはそのうちの40バイトのみを使用します。

myhost:~# ethtool -x eth0
RX flow hash indirection table for eth0 with 8 RX ring(s):
    0:    0     1     2     3     4     5     6     7
RSS hash key:
84:50:f4:00:a8:15:d1:a7:e9:7f:1d:60:35:c7:47:25:42:97:74:ca:56:bb:b6:a1:d8:43:e3:c9:0c:fd:17:55:c2:3a:4d:69:ed:f1:42:89

netdev_tstamp_prequeue¶

0に設定されている場合、RPS処理後にターゲットCPUがパケットを処理するタイミングでRXパケットのタイムスタンプをサンプリングできます。タイムスタンプに若干の遅延が生じる可能性がありますが、複数のCPUで負荷を分散できるようになります。

1に設定されている場合（デフォルト）、タイムスタンプはキューイングの前にできるだけ早くサンプリングされます。

optmem_max¶

ソケットごとの許可される補助バッファの最大サイズ。補助データは、cmsghdr構造体のシーケンスと添付データで構成されます。

fb_tunnels_only_for_init_net¶

フォールバックトンネル（tunl0、gre0、gretap0、erspan0、sit0、ip6tnl0、ip6gre0など）が自動的に作成されるかどうかを制御します。3つの可能性があります（a）値=0：モジュールのロード時にすべてのネットネームスペースでフォールバックトンネルが作成されます（後方互換性のある動作）。（b）値=1：[kcmd値:initns] フォールバックトンネルはinit_netネームスペースのみで作成され、他のネットネームスペースには存在しません。（c）値=2：[kcmd値:none] どのネットネームスペースでもモジュールのロード時にフォールバックトンネルが作成されません。これらのモジュールがビルトインの場合、ブート後で値を2に設定しても意味がありません。このデフォルトを変更するには、カーネルコマンドラインオプションを使用できます。詳細は カーネルのコマンドラインパラメータ をご参照ください。

フォールバックトンネルを作成しないことで、ユーザースペースが必要なものだけを自由に作成できるようになり、冗長なデバイスの作成を避けることができます。

デフォルト : 0（後方互換性のため）

devconf_inherit_init_net¶

新しいネットネームスペースが/init_netの現在の設定をすべて継承するかどうかを制御します。デフォルトでは、IPv4は/init_netの現在の設定を継承し、IPv6はすべての設定をデフォルト値に戻します。

1に設定されている場合、IPv4とIPv6の設定はどちらも/init_netの現在の設定から継承されます。2に設定されている場合、どちらもデフォルト値に戻されます。3に設定されている場合、どちらもこの新しいネットネームスペースが作成されたネットネームスペースの現在の設定から継承されます。

デフォルト : 0（後方互換性のため）

2. /proc/sys/net/unix - Unixドメインソケットのパラメータ¶

このディレクトリにはただ1つのファイルしかありません。unix_dgram_qlenは、Unixドメインソケットのバッファにキューイングされるデータグラムの最大数を制限します。PF_UNIXフラグが指定されていない限り、効果を発揮しません。

4. Appletalk¶

Appletalkがロードされている場合、/proc/sys/net/appletalkディレクトリはAppletalkの設定データを保持します。設定可能なパラメータは以下の通りです。

aarp-expiry-time¶

ARPエントリを期限切れまで保持する時間。古いホストを削除するために使用されます。

aarp-resolve-time¶

Appletalkアドレスを解決するために費やす時間。

aarp-retransmit-limit¶

クエリを再送する回数の上限。失敗するまで再送する回数です。

aarp-tick-time¶

期限切れの確認が行われる頻度を制御します。

/proc/net/appletalkディレクトリは、マシン上のアクティブなAppletalkソケットの一覧を保持しています。

フィールドはDDPタイプ、ローカルアドレス（ネットワーク:ノード形式）、リモートアドレス、送信待ちキューのサイズ、受信キューのサイズ（アプリケーションが読み込む待機中のバイト数）、ステータス、およびソケットを所有するUIDを示します。

/proc/net/atalk_ifaceはAppletalkで設定されたすべてのインターフェースの一覧を表示します。インターフェース名、Appletalkアドレス、そのアドレスのネットワーク範囲（またはフェーズ1ネットワークのネットワーク番号）、およびインターフェースのステータスが表示されます。

/proc/net/atalk_routeは各既知のネットワークルートを一覧表示します。ルートが指すターゲット（ネットワーク）、ルーター（直接接続の場合もあり）、ルートフラグ、および使用するデバイスが表示されます。

5. TIPC¶

tipc_rmem¶

TIPCプロトコルは、tcp_rmemと同様に受信メモリの調整可能なパラメータを導入しました。これは最小値、デフォルト値、最大値の3つの整数（トリプレット）で表されます。

# cat /proc/sys/net/tipc/tipc_rmem
4252725 34021800        68043600
#

最大値はCONN_OVERLOAD_LIMITに設定され、デフォルト値と最小値はその同じ値をスケーリング（シフト）したものです。注意点として、最小値は現時点では意味のある用途がありませんが、tcp_rmemなどのようにトリプレットを保持しています。

named_timeout¶

TIPC名テーブルの更新は、クラスター内でトランザクション処理なしに非同期的に配布されるため、さまざまな競合状態が発生する可能性がある。その一つ例として、あるノードから送信され、別のノードで受信された名前削除が、第三のノードから送信された名前公開と重なって受信される可能性がある。この場合、競合する更新が正しい順序で送信されたにもかかわらず、タイムアウトがゼロでない場合、失敗したトポロジ更新は遅延キューに置かれる。別のイベントがエラーをクリアするか、タイムアウトが発生するまで、キューから取り出される。値の単位はミリ秒である。
