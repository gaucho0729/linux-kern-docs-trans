このファイルには、/proc/sys/fs/にあるsysctlファイルに関するドキュメンテーションが含まれており、Linuxカーネルバージョン 2.2に適用されます。

このディレクトリ内のファイルは、Linuxカーネルの操作におけるさまざまな一般的な設定を調整および監視するために使用できます。一部のファイルはシステムを破壊する可能性があるため、実際の調整を行う前にドキュメンテーションとソースコードを確認することをお勧めします。

aio-nr & aio-max-nr¶

aio-nr は io_setup システムコールで指定されたイベント数の現在の合計値を表し、すべてのアクティブな aio コンテキストに対して計算されます。aio-nr が aio-max-nr に達した場合、io_setup は EAGAIN で失敗します。注意点として、aio-max-nr を上げてもカーネルデータ構造の事前割当てやサイズ変更は行われません。

dentry-state¶

linux/include/linux/dcache.h から:

struct dentry_stat_t dentry_stat {
      int nr_dentry;
      int nr_unused;
      int age_limit;         /* age in seconds */
      int want_pages;        /* pages requested by system */
      int nr_negative;       /* # of unused negative dentries */
      int dummy;             /* Reserved for future use */
};

Dentries は動的に割当てられ、解放されます。

nr_dentry は割当てられた dentries（アクティブ + 未使用）の総数を示し、nr_unused は LRU リストに保存されているが現時点で使用されていない dentries の数を表します。

Age_limit はメモリが不足しているときに shrink_dcache_pages() が呼び出され、dcache がまだ剪定されていない場合に、dcache エントリが再利用可能になるまでの秒数を示します。

nr_negativeは、使用されていないが負のdentry（ファイルにマッピングされていない）の数を示します。これらは、ユーザーが提供する非存在ファイルの拒否を速やかに処理するために役立ちます。

dquot-max & dquot-nr¶

ファイルdquot-maxは、キャッシュされたディスククォータエントリの最大数を示します。

ファイルdquot-nrは、割り当てられたディスククォータエントリの数と空きディスククォータエントリの数を示します。

空きキャッシュディスククォータが非常に少なく、同時システムユーザー数が非常に多い場合、制限を上げることを検討してください。

file-max & file-nr¶

file-maxの値は、Linuxカーネルが割り当て可能なファイルハンドルの最大数を示します。ファイルハンドルが不足するエラーが多数発生する場合は、この制限を上げることを検討してください。

歴史的にカーネルはファイルハンドルを動的に割り当てることができましたが、解放することはできませんでした。file-nrの3つの値は、割り当てられたファイルハンドル数、割り当てられたが使用されていないファイルハンドル数、および最大ファイルハンドル数を示します。Linux 2.6では常に空きファイルハンドル数が0として報告されます。これはエラーではなく、割り当てられたファイルハンドル数が使用されている数と一致していることを意味します。

file-maxを超えるファイルディスクリプタの割り当て試行はprintkで報告されます。"VFS: file-max limit <number> reached"を確認してください。

nr_open¶

これはプロセスが割り当て可能なファイルハンドルの最大数を示します。デフォルト値は1024*1024（1048576）で、ほとんどのマシンで十分です。実際の制限はRLIMIT_NOFILEリソース制限に依存します。

inode-max, inode-nr & inode-state¶

ファイルハンドル同様に、カーネルはinode構造体を動的に割り当てますが、まだ解放することはできません。

inode-maxの値は、inodeハンドラの最大数を示します。file-maxの値の3〜4倍にする必要があります。stdin、stdout、ネットワークソケットなどもinode構造体を必要するためです。inodeが定期的に不足する場合は、この値を増やす必要があります。

inode-nrファイルにはinode-stateの最初の2項目が含まれているため、このファイルには移動します…

inode-stateには3つの実際の数値と4つのダミーが含まれます。実際の数値は出現順にnr_inodes、nr_free_inodes、preshrinkです。

nr_inodesはシステムが割り当てたinodeの数を示し、inode-maxよりやや多くなることがあります。Linuxはページ単位でinodeを割り当てるためです。

Nr_free_inodesは空きインノードの数を表し、nr_inodesがinode-maxを超えた場合にシステムがインノード一覧を剪定する代わりに新たなインノードを割り当てる必要があるときにpreshrinkがゼロでない。

overflowgid & overflowuid¶

一部のファイルシステムは16ビットのUIDとGIDのみをサポートしていますが、LinuxではUIDとGIDは32ビットです。これらのファイルシステムが書き込み可能にマウントされた場合、65535を超えるUIDやGIDはディスクに書き込まれる前に固定値に変換されます。

これらのsysctlは固定UIDとGIDの値を変更できます。デフォルトは65534です。

pipe-user-pages-hard¶

非特権ユーザーがパイプに割り当てられる最大のページ数です。この制限に達した後は、使用量が制限を超えないまで新たなパイプの割り当てが制限されます。値を0に設定すると制限が解除され、これがデフォルトの設定です。

pipe-user-pages-soft¶

非特権ユーザーがパイプに割り当てられる最大のページ数で、パイプのサイズが単一のページに制限されるまでに到達した後は、このユーザーの新たなパイプは単一ページのサイズに制限されます。これにより総記憶使用量を制限します。fcntl()でサイズを増やす試みは使用量が制限を超えないまで拒否されます。デフォルト値は最大1024のパイプをデフォルトサイズで割り当てられます。値を0に設定すると制限が解除されます。

protected_fifos¶

この保護の目的は、攻撃者が制御するFIFOへの意図せぬ書き込みを防ぐことです。これは、通常ファイルを作成する予定のプログラムがFIFOを処理する際のリスクです。

値を"0"に設定すると、FIFOへの書き込みは制限されません。

値を"1"に設定すると、世界書き込み可能で所有権が自分のものではないディレクトリ内のFIFOに対してO_CREATでのオープンを許可しません。ただし、ディレクトリの所有者である場合を除きます。

値を"2"に設定すると、グループ書き込み可能なステッキディレクトリにも同様の制限が適用されます。

この保護はOpenwallの制限に基づいています。

protected_hardlinks¶

長年のセキュリティ問題の一つは、ハードリンクを用いた時間のチェックと使用の競合（time-of-check-time-of-use race）です。これは/tmpなどの世界書き込み可能なディレクトリでよく見られます。この脆弱性の一般的な悪用方法は、ハードリンクをたどる際の権限境界を越えることです（例：ルートプロセスが他のユーザーが作成したハードリンクをたどる）。また、分離されたパーティションがないシステムでは、管理者が脆弱なsetuid/setgidファイルをアップグレードするのを防ぐことができ、特殊ファイルへのリンクを防ぐことができます。

値を"0"に設定すると、ハードリンクの作成は制限されません。

値を"1"に設定すると、ユーザーがソースファイルを所有していない、または読み書きアクセス権を持っていない場合、ハードリンクの作成が禁止されます。

この保護は、Openwallおよびgrsecurityにおける制限に基づいています。

protected_regular¶

この保護はprotected_fifosに似ていますが、予期されるファイルを作成するプログラムが、攻撃者が制御する通常ファイルへの書き込みを回避します。

「0」に設定されている場合、通常ファイルへの書き込みは制限がありません。

「1」に設定されている場合、世界書き込み可能でsticky属性を持つディレクトリ内に、所有権を持っていない通常ファイルに対してO_CREATオープンを許可しません。ただし、ディレクトリの所有者によって所有されている場合は除きます。

値を"2"に設定すると、グループ書き込み可能なステッキディレクトリにも同様の制限が適用されます。

protected_symlinks¶

長年にわたって存在するセキュリティ問題の一つは、/tmpなどの世界書き込み可能なディレクトリでよく見られるシンボリックリンク（symlink）ベースの「時間の確認時と使用時の競合（TOCTOU）」です。この脆弱性の一般的な悪用方法は、指定されたシンボリックリンクをたどる際に権限境界を越えることです（つまり、ルートプロセスが他のユーザーのシンボリックリンクをたどる場合）。過去数十年にわたる数百の例（不完全なリスト）については、以下をご覧ください： https://cve.mitre.org/cgi-bin/cvekey.cgi?keyword=/tmp

「0」に設定されている場合、シンボリックリンクのたどる動作は制限がありません。

「1」に設定されている場合、sticky属性を持つ世界書き込み可能なディレクトリの外側で、またはシンボリックリンクとフォロワーのuidが一致する場合、またはディレクトリの所有者とシンボリックリンクの所有者が一致する場合に限り、シンボリックリンクをたどることができます。

この保護は、Openwallおよびgrsecurityにおける制限に基づいています。

suid_dumpable:¶

この値は、setuidまたは他の保護/汚染されたバイナリのコアダンプモードを照会および設定するために使用できます。モードは以下の通りです。

0

(default)

伝統的な動作。権限レベルを変更したプロセスまたは実行専用のプロセスはダンプされません。

1

(debug)

可能な限りすべてのプロセスがコアダンプされます。コアダンプは現在のユーザーが所有し、セキュリティが適用されません。これはシステムのデバッグ状況にのみ使用するためのものです。Ptraceはチェックされません。これは、通常のユーザーが権限を持つプロセスのメモリ内容を確認できるため、セキュリティがありません。

2

(suidsafe)

通常ダンプされないバイナリでもダンプされるが、これは「core_pattern」カーネルsysctlがパイプハンドラまたは完全なパスに設定されている場合に限ります。（この制限の詳細については、CVE-2006-2451を参照してください。）管理者が通常の環境で問題をデバッグしている場合、コアダンプパイプハンドラがあり、権限を持つコアダンプを適切に扱うか、または特定のディレクトリでコアダンプをキャッチする場合にこのモードが適切です。パイプハンドラまたは完全なパスが設定されていない場合、syslogに正しい設定がないことを警告するメッセージが発生します。

super-max & super-nr¶

これらの数値は、スーパーブロックの最大数を制御し、これによりカーネルがマウントできるファイルシステムの最大数を決定します。super-maxの値よりも多くのファイルシステムをマウントする必要がある場合のみ、super-maxを増やす必要があります。

aio-nr & aio-max-nr¶

aio-nrは、システム全体で現在の非同期IOリクエストの数を示します。aio-max-nrは、aio-nrが成長できる最大値を変更するためのパラメータです。

mount-max¶

これは、マウントネームスペース内に存在できるマウントの最大数を示します。

2. /proc/sys/fs/binfmt_misc¶

/proc/sys/fs/binfmt_misc内のファイルのドキュメンテーションは Linux における miscellaneous Binary Formats（binfmt_misc）のカーネルサポート.

3. /proc/sys/fs/mqueue - POSIXメッセージキューのファイルシステム¶

「mqueue」ファイルシステムは、POSIXメッセージキューAPI（POSIX 1003.1-2001版のシステムインターフェース仕様におけるMSGタグで記述）を実装するユーザースペースライブラリの作成に必要なカーネル機能を提供します。

「mqueue」ファイルシステムには、ファイルシステムが使用するリソース量を決定/設定するための値が含まれています。

/proc/sys/fs/mqueue/queues_maxは、システムに許可されるメッセージキューの最大数を設定/取得する読み書き可能なファイルです。

/proc/sys/fs/mqueue/msg_maxは、キュー内のメッセージ数の最大値を設定/取得する読み書き可能なファイルです。実際には、mq_open呼び出しで設定される別の（ユーザー）制限値の限界値として機能します。このキューの属性はmsg_maxよりも小さくまたは等しくなければなりません。

/proc/sys/fs/mqueue/msgsize_maxは、メッセージサイズの最大値を設定/取得する読み書き可能なファイルです（これは各メッセージキューが作成時に設定される属性です）。

/proc/sys/fs/mqueue/msg_defaultは、mq_open(2)のattrパラメータがNULLの場合にキュー内のメッセージ数のデフォルト値を設定/取得する読み書き可能なファイルです。msg_maxを超える場合、デフォルト値はmsg_maxに初期化されます。

/proc/sys/fs/mqueue/msgsize_defaultは、mq_open(2)のattrパラメータがNULLの場合にメッセージサイズのデフォルト値を設定/取得する読み書き可能なファイルです。msgsize_maxを超える場合、デフォルト値はmsgsize_maxに初期化されます。

4. /proc/sys/fs/epoll - epollインターフェースの設定オプション¶

このディレクトリには、epoll(7)インターフェースの設定オプションが含まれています。

max_user_watches¶

すべてのepollファイルディスクリプタは、イベントの準備状態を監視するファイルを複数保存できます。これらの監視対象ファイルのそれぞれは「ウォッチ」と呼ばれます。この設定オプションは、各ユーザーが許可される最大の「ウォッチ」数を指定します。各「ウォッチ」は、32ビットカーネルでは約90バイト、64ビットカーネルでは約160バイトのメモリを消費します。max_user_watchesの現在のデフォルト値は、利用可能な低メモリの1/32であり、これは「ウォッチ」あたりのバイト数で割られています。
