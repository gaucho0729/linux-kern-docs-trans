はじめに¶

メモリホットプラグの目的¶

メモリホットプラグはユーザーがメモリ量を増減できるようにします。一般的に、2つの目的があります。

  1. メモリ量を変更するため。これは容量オンデマンドなどの機能を許可するためです。

  2. 物理的にDIMMやNUMAノードをインストール/削除するため。これはDIMM/NUMAノードを交換し、消費電力を削減するなどです。

(A)は高度に仮想化された環境で必要で、(B)はメモリ電力管理をサポートするハードウェアで必要です。

Linuxのメモリホットプラグは両方の目的に設計されています。

メモリホットプラグのフェーズ¶

メモリホットプラグには2つのフェーズがあります：

  1. 物理メモリホットプラグフェーズ

  2. 論理メモリホットプラグフェーズ。

最初のフェーズはハードウェア/ファームウェアと通信し、ホットプラグされたメモリの環境を作成または削除します。基本的に、このフェーズは目的(B)に必要ですが、高度に仮想化された環境間での通信にも適しています。

メモリがホットプラグされた場合、カーネルは新しいメモリを認識し、新しいメモリ管理テーブルを作成し、新しいメモリの操作用のsysfsファイルを作成します。

ファームウェアが新しいメモリのOSへの接続を通知するサポートがある場合、このフェーズは自動的にトリガーされます。ACPIはこのイベントを通知できます。そうでない場合は、システム管理者による「プローブ」操作が使用されます。(参照 物理メモリホットアドフェーズ).

論理メモリホットプラグフェーズは、ユーザーがメモリの状態を有効/無効に変更します。ユーザーの視点からのメモリ量はこのフェーズによって変更されます。メモリ範囲が有効な場合、カーネルはその範囲内のすべてのメモリを空きページとして扱います。

このドキュメントでは、このフェーズをオンライン/オフラインとして説明します。

論理メモリホットプラグフェーズは、システム管理者がsysfsファイルに書き込みを行うことでトリガーされます。ホットアドドのケースでは、手動で物理ホットプラグフェーズの後に実行する必要があります。(ただし、メモリホットプラグ用のudevのホットプラグスクリプトを書く場合、これらのフェーズはスムーズに実行できます。)

メモリオンライン/オフライン操作の単位¶

メモリホットプラグはSPARSEMEMメモリモデルを使用し、メモリを同じサイズのチャンクに分割することが可能です。これらのチャンクは「セクション」と呼ばれます。メモリセクションのサイズはアーキテクチャに依存します。例えば、Powerは16MiB、ia64は1GiBを使用します。

メモリセクションは「メモリブロック」と呼ばれるチャンクに組み合わされます。メモリブロックのサイズはアーキテクチャに依存し、メモリのオンライン/オフライン操作が行われる論理単位を表します。デフォルトではメモリセクションのサイズと同じですが、アーキテクチャが別に指定する場合は異なります。(参照 メモリホットプラグ用のsysfsファイル.)

メモリブロックのサイズ（バイト単位）を確認するには、このファイルを読み込んでください：

/sys/devices/system/memory/block_size_bytes

カーネルの設定¶

メモリホットプラグ機能を使用するには、カーネルが以下のコンフィグオプションでコンパイルされる必要があります。

  • すべてのメモリホットプラグについて：

    • メモリモデル -> スパースメモリ (CONFIG_SPARSEMEM)

    • メモリホットアドドを許可する (CONFIG_MEMORY_HOTPLUG)

  • メモリの削除を有効にするには、以下の設定も必要です：

    • メモリホットリムーブを許可する (CONFIG_MEMORY_HOTREMOVE)

    • ページ移動 (CONFIG_MIGRATION)

  • ACPIメモリホットプラグについては、以下の設定も必要です：

    • メモリホットプラグ（ACPIサポートメニュー下） (CONFIG_ACPI_HOTPLUG_MEMORY)

    • このオプションはカーネルモジュールとして利用可能です。

  • 関連する設定として、あなたのボックスがACPIを介してNUMAノードホットプラグ機能を持っている場合、このオプションも必要です。

    • ACPI0004、PNP0A05およびPNP0A06コンテナドライバ（ACPIサポートメニュー下） (CONFIG_ACPI_CONTAINER).

    このオプションもカーネルモジュールとして利用可能です。

メモリホットプラグ用のsysfsファイル¶

すべてのメモリブロックはsysfsにデバイス情報が含まれています。各メモリブロックは /sys/devices/system/memory として記述されます：

/sys/devices/system/memory/memoryXXX

ここでXXXはメモリブロックIDです。

sysfsディレクトリでカバーされるメモリブロックについて。この範囲内にすべてのメモリセクションが存在し、メモリホールが存在しないことが期待されます。現在はメモリホールの有無を確認する方法はなく、その存在はメモリブロックのホットプラグ機能に影響を与えないことが想定されます。

例えば、1GiBのメモリブロックサイズを想定します。メモリが0x100000000から始まるデバイスは /sys/device/system/memory/memory4:

(0x100000000 / 1Gib = 4)

このデバイスはアドレス範囲[0x100000000 … 0x140000000)をカバーします。

各メモリブロックごとに以下の5つのファイルが確認できます：

  • /sys/devices/system/memory/memoryXXX/phys_index

  • /sys/devices/system/memory/memoryXXX/phys_device

  • /sys/devices/system/memory/memoryXXX/state

  • /sys/devices/system/memory/memoryXXX/removable

  • /sys/devices/system/memory/memoryXXX/valid_zones

phys_index

読み取り専用で、メモリブロックIDを含み、XXXと同じです。

state

読み取り/書き込み

  • 読み取り時に、メモリのオンライン/オフライン状態を含みます。

  • 書き込み時に、ユーザーは「online_kernel」、

「online_movable」、「online」、「offline」コマンドを指定でき、ブロック内のすべてのセクションに対して実行されます。

phys_device

読み取り専用: s390x でのみ使用されるレガシーアクセスで、カバーされたストレージの増分を公開します。

removable

読み取り専用: メモリブロックが除去可能かどうかを示す整数値を含みます。値が 1 の場合、メモリブロックは除去可能です。値が 0 の場合、除去できません。メモリブロックは、ブロック内のすべてのセクションが除去可能な場合にのみ除去可能です。

valid_zones

読み取り専用: このメモリブロックがオンライン可能なゾーンを表示します。

最初の列はデフォルトのゾーンを示します。

「memory6/valid_zones: Normal Movable」は、このメモリブロックがデフォルトでは ZONE_NORMAL にオンライン可能で、online_movable により ZONE_MOVABLE にオンライン可能です。

「memory7/valid_zones: Movable Normal」は、このメモリブロックがデフォルトでは ZONE_MOVABLE にオンライン可能で、online_kernel により ZONE_NORMAL にオンライン可能です。

注意

これらのディレクトリ/ファイルは物理メモリホットプラグフェーズ後に出現します。

CONFIG_NUMA が有効の場合、memoryXXX/ ディレクトリは以下のディレクトリ内のシンボリックリンク経由でアクセス可能です。 /sys/devices/system/node/node* ディレクトリ。

例:

/sys/devices/system/node/node0/memory9 -> ../../memory/memory9

バックリンクも作成されます:

/sys/devices/system/memory/memory9/node0 -> ../../node/node0

物理メモリホットアドフェーズ¶

ハードウェア(ファームウェア)のサポート¶

x86_64/ia64 プラットフォームでは ACPI を用いたメモリホットプラグがサポートされています。

一般的に、メモリホットプラグをサポートするファームウェア（ACPI）は _HID 「PNP0C80」のメモリクラスオブジェクトを定義します。PNP0C80 に通知が送信されると、Linux の ACPI ハンドラがシステムにメモリをホットアドドし、ホットプラグ udev スクリプトを呼び出します。これは自動的に実行されます。

ただし、メモリホットプラグ用のスクリプトは現在の generic udev パッケージに含まれていません。手動で作成するか、手動でメモリをオンライン/オフラインにしなければなりません。詳しくは メモリをオンラインにする方法 および メモリをオフラインにする方法.

ファームウェアが NUMA ノードホットプラグをサポートし、_HID 「ACPI0004」、「PNP0A05」、または「PNP0A06」を定義している場合、通知が送信され、ACPI ハンドラがこれらのオブジェクトに定義されたすべてのホットプラグコードを呼び出します。メモリデバイスが検出されると、メモリホットプラグコードが呼び出されます。

手動でメモリホットアドイベントを通知¶

一部のアーキテクチャでは、ファームウェアがメモリホットプラグイベントをカーネルに通知しない場合があります。そのため、カーネルに明示的に通知するための「プローブインターフェース」がサポートされています。このインターフェースは CONFIG_ARCH_MEMORY_PROBE に依存し、ホットプラグがサポートされている powerpc、sh、x86 で構成可能です（x86 では ACPI 通知で処理されるべきです）。

プローブインターフェースは以下の場所にあります:

/sys/devices/system/memory/probe

新しいメモリの物理アドレスをカーネルに通知するには、以下のコマンドを使用します:

% echo start_address_of_new_memory > /sys/devices/system/memory/probe

その後、[start_address_of_new_memory, start_address_of_new_memory + memory_block_size] のメモリ範囲がホットアドドされます。この場合、ホットプラグスクリプトは呼び出されません（現在の実装では）。手動でメモリをオンラインにする必要があります。詳しくは メモリをオンラインにする方法.

論理メモリホットアドフェーズ¶

メモリの状態¶

メモリブロックのオンライン/オフライン状態を確認するには、'state' ファイルを読みます:

% cat /sys/device/system/memory/memoryXXX/state

  • メモリブロックがオンラインの場合、'online' と読みます。

  • メモリブロックがオフラインの場合、'offline' と読みます。

メモリをオンラインにする方法¶

メモリがホットアドドされる際、カーネルは 'auto_online_blocks' ファイルで読み取れるポリシーに基づき、そのメモリブロックをオンラインにするかどうかを決定します:

% cat /sys/devices/system/memory/auto_online_blocks

デフォルトは CONFIG_MEMORY_HOTPLUG_DEFAULT_ONLINE カーネル設定オプションに依存します。このオプションが無効の場合、デフォルトは 'offline' となり、新たに追加されたメモリは利用可能な状態ではなく、手動で 'online' する必要があります。自動オンライン化を要求するには、'auto_online_blocks' ファイルに 'online' を書き込みます:

% echo online > /sys/devices/system/memory/auto_online_blocks

これはグローバルなポリシーを設定し、その後にホットアドドされるすべてのメモリブロックに影響を与えます。現在オフラインのブロックはその状態を維持します。特定の状況では、一部のメモリブロックが追加されてもオンライン化に失敗する可能性があります。ユーザー空間のツールは、その 'state' ファイル (/sys/devices/system/memory/memoryXXX/state) を確認し、手動でオンライン化を試みることができます。

自動オンライン化が要求されなかった、失敗した、またはメモリブロックがオフラインにされた場合、個々のブロックの状態を変更するには、'state' ファイルに書き込みます:

% echo online > /sys/devices/system/memory/memoryXXX/state

このオンライン化はターゲットメモリブロックの ZONE 型を変更しません。メモリブロックがどのゾーンにも属していない場合、適切なカーネルゾーン（通常は ZONE_NORMAL）が使用されます。movable_node カーネルコマンドラインオプションが指定されている場合は ZONE_MOVABLE が使用されます。

ZONE_MOVABLE に明示的に関連付けるには:

% echo online_movable > /sys/devices/system/memory/memoryXXX/state

注意

現在の制限: このメモリブロックは ZONE_MOVABLE に隣接している必要があります

または、カーネルゾーン（通常は ZONE_NORMAL）を明示的に要求するには:

% echo online_kernel > /sys/devices/system/memory/memoryXXX/state

注意

現在の制限: このメモリブロックは ZONE_NORMAL に隣接している必要があります

明示的なゾーンオンライン化は失敗する可能性があります（例: レンジが既存の不適合ゾーン内にある場合）。

これにより、メモリブロック XXX の状態は 'online' となり、利用可能なメモリ量が増加します。

今後変更される可能性があります。

論理メモリの削除¶

メモリオフラインとZONE_MOVABLE¶

メモリオフライン化はメモリオンライン化より複雑です。メモリオフライン化はメモリブロック全体を未使用にする必要があるため、メモリブロックに解放できないメモリが含まれている場合、オフライン化に失敗する可能性があります。

一般的に、メモリオフライン化には2つの技術があります。

  1. メモリブロック内のすべてのメモリを回収し、解放します。

  2. メモリブロック内のすべてのページを移動します。

現在の実装では、Linuxのメモリオフライン処理は方法(2)を使用しており、メモリブロック内のすべてのページをページ移動によって解放しています。ただし、すべてのページが移動可能ではありません。現在のLinuxでは、移動可能なページは匿名ページとページキャッシュのみです。移動によってメモリブロックをオフラインにするためには、カーネルがそのメモリブロックに移動可能なページのみが含まれていることを保証する必要があります。

現在、移動可能なページを含むメモリブロックを作成するためのブートオプションがサポートされています。"kernelcore="または"movablecore="というブートオプションを指定することで、ZONE_MOVABLE…これは移動可能なページのみが使用されるゾーンです…を生成できます。(参照) カーネルのコマンドラインパラメータ)

システムが起動時に"TOTAL"のメモリ量を有する場合、このブートオプションは以下のようにZONE_MOVABLEを生成します。

  1. kernelcore=YYYYというブートオプションを使用すると、移動可能なページ（オフライン用）以外のメモリサイズ（オフライン用外）はYYYY、移動可能なページ（オフライン用）のメモリサイズはTOTAL-YYYYになります。

  2. movablecore=ZZZZというブートオプションを使用すると、移動可能なページ（オフライン用）以外のメモリサイズ（オフライン用外）はTOTAL - ZZZZ、移動可能なページ（オフライン用）のメモリサイズはZZZZになります。

注意

残念ながら、どのメモリブロックがZONE_MOVABLEに属しているかを示す情報はありません。これはTBDです。

メモリをオフラインにする方法¶

同じsysfsインターフェースを使用してメモリブロックをオフラインにすることができます。

% echo offline > /sys/devices/system/memory/memoryXXX/state

オフラインが成功した場合、メモリブロックの状態が"offline"に変更されます。失敗した場合、カーネルはエラー(core)（例: -EBUSY）を返します。メモリブロックがZONE_MOVABLEに属さない場合でもオフラインを試みることができます。そのメモリブロックに"unmovable"メモリが含まれていない場合、成功します。

ZONE_MOVABLEに属するメモリブロックは簡単にオフラインにできるとみなされます。ただし、忙しい状態などでは-EBUSYを返す可能性があります。-EBUSYによりオフラインに失敗した場合でも、再試行することでオフラインに成功する可能性があります（または失敗する可能性があります）。（例: あるページがカーネル内部呼び出しによって参照され、すぐに解放される場合）

考慮点:

メモリホットプラグの設計方向は、メモリオフラインの可能性を高め、どのような状況でもメモリの外付けを保証することです。しかし、さらなる作業が必要です。特定の状況で-EBUSYを返すことはユーザーが再試行を決定するのを可能にし、良いかもしれません。現在、メモリオフラインコードは120秒のタイムアウトで一定回数の再試行を行います。

ロックの内部構造¶

メモリブロックデバイス（つまり通常のRAM）を使用してメモリを追加/削除する際、device_hotplug_lockを保持する必要があります:

  • オンライン/オフラインリクエスト（例：sysfs経由）に対して同期を取る。これにより、メモリブロックデバイスはメモリが完全に追加された後からユーザー空間からアクセス可能（.online/.state属性）となる。メモリを削除する際には、誰もクリティカルセクション内にいないことが保証される。

  • CPUホットプラグや類似操作（例：ACPIやPPCに関連）に対して同期を取る。

特に、メモリ追加時にデバイスホットプラグロックを使用してロックインバージョンを回避するが、ユーザー空間が予想以上に早くそのメモリをオンライン化しようとした場合に発生する可能性がある。

  • device_online()はまずdevice_lock()を取得し、その後mem_hotplug_lockを取得する。

  • add_memory_resource()はまずmem_hotplug_lockを取得し、その後device_lock()を取得する（デバイス作成中にbus_add_device()で行われる）。

デバイスがdevice_lock()を取得する前からユーザー空間に見えるため、ロックインバージョンが発生する可能性がある。

メモリのオンライン/オフライン操作はdevice_online()/device_offline()を通じて行うべきである。これによりsysfs経由の操作と正しく同期される。online_typeを保護するなど、device_hotplug_lockを保持することを推奨する。

メモリの追加/削除/オンライン/オフラインや、異質/デバイスメモリの追加/削除を行う際には、メモリホットプラグ操作をシリアル化するためにmem_hotplug_lockを書き込みモードで常に保持するべきである（例：グローバル/ゾーン変数へのアクセス）。

さらに、mem_hot,plug_lock（device_hotplug_lockとは異なり）は読み取りモードで使用することで、get_online_mems/put_online_memsの実装が非常に効率的になるため、メモリが消失するのをコードが防ぐことができる。
