Kernel Samepage Merging¶

概要¶

KSMはメモリ節約の重複データの削除機能で、CONFIG_KSM=yで有効化され、Linuxカーネルに2.6.32から導入されました。参照 mm/ksm.c その実装については、および http://lwn.net/Articles/306704/ および https://lwn.net/Articles/330589/

KSMは元々KVM（その際はKernel Shared Memoryと呼ばれていました）で使用されるために開発され、複数の仮想マシンを物理メモリに収めることを目的としていました（それらの間で共有されるデータを共有することで）。しかし、同じデータを多数生成するアプリケーションにとっても有用です。

KSMデーモンksmdは、アプリケーションが登録したユーザー領域を定期的にスキャンし、同一のコンテンツを持つページを1つの読み取り専用ページに置き換えることでメモリを節約します（プロセスが後でコンテンツを更新したい場合、自動的にコピーされます）。KSMデーモンが1回のスキャンで処理するページ数やスキャン間隔は、 sysfs インターフェース

KSMは匿名（プライベート）ページのみをマージし、ページキャッシュ（ファイル）ページは決してマージしません。KSMのマージされたページは元々カーネルメモリにロックされていましたが、現在は他のユーザーページと同様にスワップアウト可能です（ただし、スワップイン時に共有が破綻します：ksmdは再度その識別情報を再発見しマージしなければなりません）。

madvise を使用した KSM の制御¶

KSMはアプリケーションがmadvise(2)システムコールを使用して、マージの候補とみなされるアドレス空間のみを処理します：

int madvise(addr, length, MADV_MERGEABLE)

アプリケーションは

int madvise(addr, length, MADV_UNMERGEABLE)

を呼び出してそのアドバイスをキャンセルし、非共有ページに戻すことができます：その結果、KSMはその範囲内でマージしたページを解除します。注意：この解除コールは突然利用可能なメモリより多くを必要とすることがあり、EAGAINで失敗する可能性もありますが、より可能性が高いのはOut-Of-Memoryキラーコンピュータが起動することです。

KSMが実行中のカーネルに設定されていない場合、madviseのMADV_MERGEABLEおよびMADV_UNMERGEABLEはEINVALで失敗します。実行中のカーネルがCONFIG_KSM=yで構築されている場合、これらのコールは通常成功します：KSMデーモンが現在実行されていなくても、MADV_MERGEABLEはデーモンが起動した際にその範囲を登録します；範囲にKSMが実際にマージできるページが含まれていない場合でも、MADV_UNMERGEABLEがMADV_MERGEABLEでない範囲に適用された場合でもです。

メモリ領域が少なくとも1つの新しいMADV_MERGEABLEまたはMADV_UNMERGEABLE領域に分割する必要がある場合、プロセスがメモリ制限を超える可能性があるため、madviseはENOMEMを返すことがあります vm.max_map_count (参照： /proc/sys/vm/に関するドキュメンテーション).

他のmadviseコールと同様に、これらはユーザーのアドレス空間のマップ済み領域で使用することを意図しています。指定された範囲に未マップのギャップが含まれている場合、ENOMEMを報告します（ interveningのマップ済み領域を処理しているにもかかわらず）。内部構造に十分なメモリがなければEAGAINで失敗する可能性があります。

アプリケーションはMADV_MERGEABLEを使用する際は注意深く、利益が得られる領域に限定して使用すべきです。KSMのスキャンは大量の処理能力を消費する可能性があり、そのため一部のインストールではKSMを無効にする場合があります。

KSMデーモンのsysfsインターフェース¶

KSMデーモンは、以下に記載のsysfsファイルによって制御されます /sys/kernel/mm/ksm/, すべてのユーザーが読み取れるが、書き込みはrootだけが可能:

pages_to_scan

ksmdがスキャンを開始する前のスキャンページ数。例: echo 100 > /sys/kernel/mm/ksm/pages_to_scan.

デフォルト: 100 (デモンストレーション目的で選ばれた値)

sleep_millisecs

ksmdが次のスキャンまで待つミリ秒数。例: echo 20 > /sys/kernel/mm/ksm/sleep_millisecs

デフォルト: 20 (デモンストレーション目的で選ばれた値)

merge_across_nodes

異なるNUMAノードのページをマージ可能かどうかを指定します。0に設定すると、同じNUMAノードのメモリ領域に物理的に存在するページのみをマージします。これにより共有ページのアクセス遅延が低減されます。多数のノードがあり、NUMA距離が大きいシステムでは0の設定がメリットがあります。メモリ使用量を最小化する必要がある小規模システムでは、1（デフォルト）の設定によるより多くの共有がメリットになります。システムのパフォーマンスを各設定で比較してから使用するかどうかを決定することをお勧めします。 merge_across_nodes システムにksm共有ページが存在しないときにのみ設定を変更できます。まずrun 2でページをアンメージャーし、その後1に変更して再マージします。 merge_across_nodes, 新しい設定に応じて再マージします。

デフォルト: 1（以前のリリースと同様にノード間をマージする設定）

run

  • 0に設定するとksmdの実行を停止しますが、マージされたページは保持されます、

  • 1に設定するとksmdを実行します。例: echo 1 > /sys/kernel/mm/ksm/run,

  • 2に設定するとksmdを停止し、現在マージされているすべてのページをアンメージャーしますが、次回実行のためにマージ可能領域は登録されます。

デフォルト: 0（CONFIG_SYSFSが無効化されていない場合を除き、KSMを有効化するには1に変更する必要があります）

use_zero_pages

空ページ（つまりゼロのみを含む割り当てられたページ）が特別に扱されるかどうかを指定します。この値が1に設定されている場合、空ページは通常の処理とは異なり、カーネルのゼロページとマージされます。これは、カラーディゼロページを持つアーキテクチャにおいて、ワークロードに応じてパフォーマンスを向上させる可能性があります。この設定を有効にする際には注意が必要です。なぜなら、特定のワークロードではKSMのパフォーマンスが低下する可能性があるからです。例えば、マージ候補のページのチェックサムが空ページのチェックサムと一致する場合があります。この設定はいつでも変更可能です。ただし、変更後にはその時点以降にマージされたページにのみ効きます。

デフォルト: 0（以前のリリースにおける通常のKSM動作）

max_page_sharing

各KSMページに許可される最大共有数です。これにより、仮想メモリ操作における仮想マッピングのトラバーサルに伴う高遅延を防ぐ重複除去の制限を強制します。最小値は2です。なぜなら、新たに作成されたKSMページは少なくとも2つの共有者を持つからです。この値が高いほどKSMがメモリを迅速にマージし、重複除去率も高くなりますが、最悪の仮想マッピングトラバーサルの遅延が増加します。トラバーサルを遅くすると、スワップ、コンパクション、NUMAバランス、ページ移動中に発生する特定の仮想メモリ操作のレイテンシーが高くなり、それらの操作を呼び出した側の応答性が低下します。これらの仮想メモリ操作に伴うトラバーサルに影響されないタスクのスケジューラー遅延は、このパラメータに影響されません。なぜなら、これらのトラバーサルは常にスケジューラーに優しいからです。

stable_node_chains_prune_millisecs

KSMがデッドアップルimitに達したページのメタデータをチェックする頻度を指定します。ミリ秒値が小さいほど、KSMメタデータの解放が低レイテンシーで行われますが、ksmdがスキャン中に使用するCPUリソースが増加します。KSMページが1つも達していない場合は、これは無効です。 max_page_sharing まだ。

KSMとMADV_MERGEABLEの有効性は以下に示されます /sys/kernel/mm/ksm/:

pages_shared

共有されているページ数

pages_sharing

さらに多くのサイトが共有しているため、保存された量

pages_unshared

一意のページですが、繰り返しマージを試みている数

pages_volatile

木に配置するには早すぎるほど変化するページ数

full_scans

すべてのマージ可能な領域がスキャンされた回数

stable_node_chains

達した max_page_sharing 制限

stable_node_dups

重複したKSMページ数

高い比率の pages_sharing に（木の下から葉に向かって） pages_shared 良い共有を示しますが、比率が高い pages_unshared に（木の下から葉に向かって） pages_sharing 無駄な努力を示します。 pages_volatile いくつかの異なる活動を含んでいます。ただし、その比率が高い場合も、madvise MADV_MERGEABLEの不適切な使用を示します。

最大可能 pages_sharing/pages_shared 比率は制限されます max_page_sharing チューニング可能な。比率を増やすには max_page_sharing それに応じて増やす必要があります。
