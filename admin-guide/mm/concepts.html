概念概要¶

Linuxにおけるメモリ管理は、年々進化し、MMUを持たないマイクロコントローラーからスーパーコンピュータまで幅広いシステムをサポートするための機能をどんどん追加した複雑なシステムです。MMUを持たないシステムにおけるメモリ管理は nommu と呼ばれ、確実に専用のドキュメントが書かれるべきです（ hopefully いつか書かれるでしょう）。ただし、一部の概念は同じですが、ここではMMUが利用可能で、CPUが仮想アドレスを物理アドレスに変換できると仮定します。

仮想メモリの基礎¶

コンピュータシステムにおける物理メモリは限られたリソースであり、メモリホットプラグをサポートするシステムであっても、インストール可能なメモリ量にはハードウェアの制限があります。物理メモリは連続している必要はなく、複数のアドレス範囲としてアクセス可能である場合もあります。さらに、異なるCPUアーキテクチャや、同じアーキテクチャでも実装方法によっては、これらのアドレス範囲の定義が異なります。

このような複雑さを避けるため、仮想メモリという概念が開発されました。

仮想メモリはアプリケーションソフトウェアから物理メモリの詳細を抽象化し、必要な情報のみを物理メモリに保つ（_demand paging_）ことや、プロセス間でのデータの保護と制御された共有を提供します。

仮想メモリでは、すべてのメモリアクセスが仮想アドレスを使用します。CPUが命令をデコードし、システムメモリから読み取り（または書き込み）を行う際、その命令に含まれる 仮想 アドレスを、 物理 アドレスに変換します。この物理アドレスはメモリコントローラーが理解できる形式です。

物理システムメモリはページフレーム（またはページ）に分割され、各ページのサイズはアーキテクチャに依存します。一部のアーキテクチャでは複数のページサイズから選択可能で、この選択はカーネルビルド時に適切なカーネル構成オプションを設定することで行います。

各物理メモリページは1つまたは複数の仮想ページとしてマッピングできます。これらのマッピングはページテーブルによって記述され、プログラムで使用される仮想アドレスを物理メモリアドレスに変換します。ページテーブルは階層的に構成されています。

階層構造の最下層にあるテーブルには、ソフトウェアが実際に使用するページの物理アドレスが記録されています。より上位のテーブルには、下位レベルのページに属する物理アドレスが含まれています。トップレベルのページテーブルへのポインタはレジスタに格納されており、CPUがアドレス変換を行う際にはこのレジスタを使用してトップレベルのページテーブルにアクセスします。仮想アドレスの高位ビットはトップレベルのページテーブルのエントリをインデックスとして使用し、そのエントリを用いて次のレベルの階層にアクセスします。次のビットはそのレベルのページテーブルのインデックスとして使用され、仮想アドレスの最下位ビットは実際に使用されるページ内のオフセットを定義します。

大ページ（Huge Pages）¶

アドレス変換には複数のメモリアクセスが必要であり、メモリアクセスはCPUの速度に比べて遅くなります。アドレス変換に貴重なプロセッササイクルを費やすのを避けるため、CPUはこのような変換をキャッシュするTranslation Lookaside Buffer（TLB）と呼ばれるメモリを維持しています。通常TLBは限られたリソースであり、大容量のメモリワークセットを持つアプリケーションではTLBミスによりパフォーマンス低下が発生します。

多くの現代のCPUアーキテクチャでは、ページテーブルの上位レベルでメモリページを直接マッピングすることが可能です。例えば、x86では第二および第三レベルのページテーブルのエントリを使用して2Mおよび1Gページのマッピングが可能です。Linuxではこのようなページは hugeと呼ばれます。hugeページの使用によりTLBへの負担が大幅に軽減され、TLBヒット率が向上し、結果として全体のシステムパフォーマンスが向上します。

Linuxでは物理メモリをhugeページでマッピングするための2つのメカニズムがあります。最初のメカニズムは HugeTLBファイルシステム、またはhugetlbfsです。これはRAMをバックイングストアとして使用する仮想ファイルシステムであり、このファイルシステムで作成されたファイルのデータはメモリに格納され、hugeページを用いてマッピングされます。hugetlbfsについては HugeTLB Pages.

Another, more recent, mechanism that enables use of the huge pages is called Transparent HugePages, or THP. Unlike the hugetlbfs that requires users and/or system administrators to configure what parts of the system memory should and can be mapped by the huge pages, THP manages such mappings transparently to the user and hence the name. See Transparent Hugepage Support for more details about THP.

ゾーン（Zones）¶

ハードウェアは、さまざまな物理メモリ範囲のアクセスに制限を課すことがあります。一部のデバイスではDMAがすべてのアドレス可能なメモリに実行できない場合があり、他には物理メモリのサイズが仮想メモリの最大アドレス可能なサイズを超えるため、メモリの一部にアクセスするには特別な処理が必要です。Linuxはメモリページを ゾーン として、その使用可能性に応じてグループ化します。たとえば、ZONE_DMAはデバイスがDMAで使用できるメモリを含み、ZONE_HIGHMEMはカーネルのアドレス空間に永続的にマッピングされないメモリを含み、ZONE_NORMALは通常のアドレス指定が可能なページを含みます。

メモリゾーンの実際のレイアウトはハードウェアに依存しており、すべてのアーキテクチャがすべてのゾーンを定義するわけではなく、DMAの要件はプラットフォームによって異なります。

ノード（Nodes）¶

多くのマルチプロセッサマシンはNUMA（Non-Uniform Memory Access）システムです。このようなシステムでは、プロセッサからの距離に応じてアクセス遅延が異なるメモリバンクが配置されており、各バンクは node ノードと呼ばれ、Linuxは各ノードに対して独立したメモリ管理サブシステムを構築します。ノードには独自のゾーン、空きページと使用中のページのリスト、さまざまな統計カウンタが含まれます。NUMAについての詳細は NUMAとは何ですか？ および NUMA Memory Policy.

ページキャッシュ（Page cache）¶

物理メモリは揮発性を持ち、データをメモリに読み込む一般的なケースはファイルから読み取ることです。ファイルを読み取るたびに、データはページキャッシュに格納されます。 page cache その後の読み取りにおける高コストなディスクアクセスを避けるためです。同様に、ファイルに書き込む場合、データはページキャッシュに配置され、最終的にバックストレージデバイスに移されます。書き込まれたページは dirty Linuxが他の用途のために再利用する場合、デバイス上のファイル内容を更新されたデータと同期させることを確実にします。

匿名メモリ（Anonymous Memory）¶

以下の anonymous memory または anonymous mappings ファイルシステムによってサポートされていないメモリを表します。このようなマッピングは、プログラムのスタックとヒープの暗黙的な作成、またはmmap(2)システムコールの明示的な呼び出しによって生成されます。通常、匿名マッピングは、プログラムがアクセスできる仮想メモリ領域を定義します。読み取りアクセスは、ゼロで埋められた特別な物理ページを参照するページテーブルエントリの作成を引き起こします。プログラムが書き込みを行うと、書き込まれたデータを保持する通常の物理ページが割り当てられます。ページは汚染（dirty）マークされ、カーネルが再利用を決定した場合、汚染されたページがスワップアウトされます。

回収（Reclaim）¶

システムの寿命を通じて、物理ページはさまざまな種類のデータを保存するために使用されます。これはカーネルの内部データ構造、デバイスドライバーが使用するDMA可能なバッファ、ファイルシステムから読み込まれたデータ、ユーザー空間プロセスが割り当てたメモリなどです。

ページの使用目的によって、Linuxのメモリ管理が異なる処理を行います。いつでも解放可能なページは、例えばハードディスク上のデータをキャッシュしている場合や、ハードディスクにスワップアウト可能な場合など、データが他に存在するため、 reclaimableと呼ばれます。reclaimableなページの主なカテゴリはページキャッシュと匿名メモリです。

ほとんどの場合、内部カーネルデータを保持し、DMAバッファとして使用されるページは再利用が不可能で、ユーザーが解放するまでピン止めされます。このようなページは unreclaimableと呼ばれます。ただし、特定の状況では、カーネルデータ構造を占有しているページでも回収可能です。例えば、ファイルシステムメタデータのインメモリキャッシュはストレージデバイスから再読み込み可能なので、システムがメモリ圧力にさらされたときにメインメモリから削除可能です。

reclaimableな物理メモリページを解放し、再利用するプロセスは（驚き！） reclaimと呼ばれます。Linuxはシステムの状態に応じて、非同期または同期的にページを回収します。システムが負荷が少ない状態では、ほとんどのメモリが空き状態で、割り当て要求はすぐに空きページの供給から満たされます。負荷が増加すると空きページの量が減少し、ある閾値（high watermark）に達すると割り当て要求が kswapd デーモンを起動します。デーモンは非同期にメモリページをスキャンし、データが他に存在する場合はそのページを解放するか、バックストレージデバイスにエビクトします（汚れたページを思い出してください）。メモリ使用量がさらに増加し、もう一つの閾値（min watermark）に達すると割り当てが direct reclaimをトリガーします。この場合、割り当てが完了するまで十分なメモリページが回収されるまで待機します。

コンパクション（Compaction）¶

システムが稼働するにつれてタスクがメモリを割り当てたり解放したりし、メモリがフラグメンテーションします。仮想メモリでは散らばった物理ページを virtually contiguous な範囲として提示できますが、時として大規模な物理的に連続したメモリ領域の割り当てが必要です。このような必要性は、例えばデバイスドライバーがDMA用に大容量バッファを必要とする場合や、THPがヒューゲンページを割り当てる場合などに生じます。メモリ compaction フラグメンテーション問題を解決します。このメカニズムは、メモリゾーンの下部にある占有されているページを、ゾーンの上部にある空きページに移動させます。コンパクションスキャンが完了すると、空きページがゾーンの開始部に集約され、物理的に連続した大規模な領域の割り当てが可能になります。

reclaimと同様に、コンパクションはデーモンでの非同期処理として発生する可能性があり、メモリ割り当てリクエストの結果として同期処理として実行される場合があります。 kcompactd daemon or synchronously as a result of a memory allocation request.

OOMキラー（OOM killer）¶

負荷がかかるマシンでは、メモリが枯渇し、カーネルが十分なメモリを回収できなくなる可能性があります。システムの残りの部分を保護するため、カーネルは OOMキラー（OOM killer）.

以下の OOMキラー（OOM killer） システム全体の健康を考慮して、特定のタスクを犠牲にすることを選択します。選ばれたタスクは終了後に十分なメモリを解放できるようにするために終了させられます。
