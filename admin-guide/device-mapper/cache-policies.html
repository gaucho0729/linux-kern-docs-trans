ポリシーの作成に関するガイドライン¶

トランザクショナリティを排除することを心がけてください。コアは、移動中のものについて尋ねることを避けるように注意しています。これは面倒ですが、ポリシーを書くことをより簡単にするためです。

マッピングはポリシーに構築時にロードされます。

ターゲットによってマッピングされたすべてのbioはポリシーに参照されます。ポリシーは単純なHITまたはMISSを返すか、または移動を発行できます。

現在、ポリシーがバックグラウンド作業を発行する方法はありません。たとえば、直ちに追い出される可能性のある汚れたブロックの書き戻しを開始するなどです。

bioをマッピングしているため、リクエストではなくbioが原因でポリシーが誤解を受けることがあります。このため、コアターゲットはポリシーに対して定期的なティックを発行します。ポリシーは、ティックごとにブロックの状態（例：HITカウント）を更新する回数を1回に制限することが推奨されます。コアはbioが完了するのを監視してティックを行い、ioスケジューラーがioを実行したタイミングを確認しています。

提供されたキャッシュ代替ポリシーの概要¶

multiqueue (mq)¶

このポリシーは現在、smq（以下参照）の別名です。

以下のチューニングパラメータは受け付けますが、影響はありません：

'sequential_threshold <#nr_sequential_ios>'
'random_threshold <#nr_random_ios>'
'read_promote_adjustment <value>'
'write_promote_adjustment <value>'
'discard_promote_adjustment <value>'

確率的マルチキュー (smq)¶

このポリシーはデフォルトです。

確率的マルチキュー (smq) ポリシーは、マルチキュー (mq) ポリシーのいくつかの問題に対処します。

smq ポリシー（mq と比較）は、メモリ使用量が少なく、パフォーマンスが向上し、変化するワークロードに対して適応性が高くなるという約束を提供します。smq はまた、複雑なチューニングパラメータを持っていません。

ユーザーは、キャッシュターゲットを使用しているDMテーブルを適切に再ロードすることで、「mq」から「smq」に簡単に切り替えることができます。これにより、mq ポリシーのすべてのヒントが削除されます。また、smq がキャッシュすべき元デバイスのホットスポットを再計算するまで、キャッシュのパフォーマンスがやや低下する可能性があります。

メモリ使用量¶

mq ポリシーは多くのメモリを使用しました。64ビットマシンでは、キャッシュブロックごとに88バイトを使用しました。

smq はポインタではなく28ビットのインデックスを使用してデータ構造を実装します。各ブロックに明示的なHITカウントを保存しません。また、プリキャッシュではなく「ホットスポット」キューを使用します。これにより、エントリ数の4分の1しか使用されず、各ホットスポットブロックは単一のキャッシュブロックよりも広範な領域をカバーします。

これらすべてにより、smq はキャッシュブロックあたり約25バイトを使用します。まだ多くのメモリを使用しますが、大幅な改善です。

レベルバランス¶

mqはヒットカウント(~ln(ヒットカウント))に基づいて、マルチキュー構造のさまざまなレベルにエントリを配置していました。これにより、下位レベルには通常多くのエントリが、上位レベルには極めて少ないエントリが配置されていました。このようなアンバランスなレベル構造は、マルチキューの効果を低下させました。

smqはヒットカウントを保持せず、代わりに上位レベルの最も最近使用されていないエントリとヒットエントリを交換します。全体的な順序はこの確率的なプロセスの副次的な結果です。このスキームにより、各マルチキューレベルに占有するエントリ数を決定できるため、より良い昇格/降格の決定が可能になります。

適応性: mqポリシーは各キャッシュブロックに対してヒットカウントを保持していました。別のブロックがキャッシュに昇格するには、そのヒットカウントがキャッシュ内の現在の最低ヒットカウントを上回る必要があります。これにより、キャッシュが変化するIOパターンに適応するのに時間がかかることがありました。

smqはヒットカウントを保持しないため、この問題の多くは解消されます。さらに、ホットスポットキューのパフォーマンスを追跡しており、これをもとにブロックの昇格対象を決定します。ホットスポットキューのパフォーマンスが悪ければ、レベル間でのエントリの移動が速くなるため、新しいIOパターンに迅速に適応できます。

パフォーマンス¶

smqのテストでは、mqに比べて大幅に優れたパフォーマンスが確認されました。

cleaner¶

cleanerはキャッシュ内のすべての汚染ブロックを書き戻し、キャッシュを廃止します。

例¶

テーブルの構文は以下の通りです:

cache <metadata dev> <cache dev> <origin dev> <block size>
<#feature_args> [<feature arg>]*
<policy> <#policy_args> [<policy arg>]*

dmsetupコマンドを使用してメッセージを送信する構文は以下の通りです:

dmsetup message <mapped device> 0 sequential_threshold 1024
dmsetup message <mapped device> 0 random_threshold 8

dmsetupを使用する場合:

dmsetup create blah --table "0 268435456 cache /dev/sdb /dev/sdc \
    /dev/sdd 512 0 mq 4 sequential_threshold 1024 random_threshold 8"
creates a 128GB large mapped device named 'blah' with the
sequential threshold set to 1024 and the random_threshold set to 8.
