dm-zoned¶

dm-zonedデバイスマッパーのターゲットは、ZBCおよびZAC準拠のゾーンブロックデバイスを、書き込みパターン制約なしの通常のブロックデバイスとして公開します。これにより、ホストマネージドゾーンブロックデバイスのシーケンシャル書き込み制約をユーザー（ファイルシステムやローカルブロックデバイスアクセスを行うアプリケーション）から隠蔽し、ホスト認識ゾーンブロックデバイスにおける過剰なランダム書き込みによるデバイス側のパフォーマンス低下を軽減するドライブマネージドゾーンブロックデバイスを実装します。

ゾーンブロックデバイスのモデルとその制約についての詳細な説明は、SCSIデバイスについては以下のリンクを参照してください：

https://www.t10.org/drafts.htm#ZBC_Family

ATAデバイスについては以下のリンクを参照してください：

http://www.t13.org/Documents/UploadedDocuments/docs2015/di537r05-Zoned_Device_ATA_Command_Set_ZAC.pdf

dm-zonedの実装はシンプルで、システムオーバーヘッド（CPUおよびメモリ使用量、ストレージ容量の喪失）を最小限に抑えます。10TBのホストマネージドディスクで256MBのゾーンを持つ場合、dm-zonedのメモリ使用量はディスクごとに最大4.5MBに抑えられ、メタデータの保存および回収操作に内部で少なくとも5ゾーンが使用されます。

dm-zonedターゲットデバイスは、以下のdmzadmユーティリティを使用してフォーマットおよびチェックされます：

https://github.com/hgst/dm-zoned-tools

アルゴリズム¶

dm-zonedは、ゾーンブロックデバイスのシーケンシャルゾーンへの非シーケンシャル書き込みアクセスを処理するディスク上のバッファリングスキームを実装しています。通常のゾーンはキャッシュおよび内部メタデータの保存に使用され、また通常のブロックデバイスとゾーンブロックデバイスを併用することも可能です。その場合、通常のブロックデバイスはゾーンブロックデバイスのゾーンと同サイズの論理ゾーンに分割され、ゾーンブロックデバイスのゾーンの前に配置され、通常のゾーンと同様に処理されます。

デバイスのゾーンは2つのタイプに分類されます：

1) メタデータゾーン：メタデータを保存するために使用される通常のゾーンです。メタデータゾーンはユーザーに利用可能な容量として報告されません。

2) データゾーン：すべての残りのゾーンで、ユーザーデータを専用に保存するシーケンシャルゾーンが圧倒的に多く含まれます。デバイスの通常ゾーンはユーザーのランダムな書き込みをバッファリングするためにも使用され得ます。これらのゾーンに保存されたデータは通常ゾーンに直接マッピングされるかもしれませんが、後でシーケンシャルゾーンに移動され、通常ゾーンが再利用されるためのランダムな書き込みのバッファリングに使用されます。

dm-zonedは、後方のゾーンブロックデバイスの物理セクタサイズに関係なく、論理デバイスのセクタサイズを4096バイトに固定します。これにより、有効ブロック（書き込まれたブロック）を管理するためのメタデータ量を削減できます。

ディスク上のメタデータ形式は以下の通りです：

1) 最初の従来型ゾーンの最初のブロックには、メタデータブロックのディスク上の量と位置を記述するサーパー・ブロックが含まれています。

2) サーパー・ブロックの後には、論理デバイスブロックのマッピングを記述するブロックセットが使用されます。このマッピングはブロックのチャンク単位で行われ、チャンクサイズはゾーンブロックデバイスのサイズに等しくなります。マッピングテーブルはチャンク番号でインデックスされ、各マッピングエントリはデータを格納しているデバイスのゾーン番号を示します。各マッピングエントリは、ランダムな変更をバッファリングするために使用される従来型ゾーンのゾーン番号を示すこともできます。

3) マッピングテーブルの後には、データゾーン内のブロックの有効性を示すビットマップを格納するブロックセットが続きます。有効ブロックとは、書かれたが破棄されていないブロックを指します。バッファードデータチャンクの場合、ブロックは常にそのチャンクをマッピングしているデータゾーンまたはチャンクのバッファゾーン内でのみ有効です。

論理チャンクが従来型ゾーンにマッピングされている場合、すべての書き込み操作はゾーンに直接書き込むことで処理されます。マッピングゾーンが連続ゾーンである場合、論理チャンク内の書き込みオフセットが連続データゾーン内の書き込みポインタオフセットと一致している場合（つまり、書き込みがゾーンの書き込みポインタにアライメントされている場合）にのみ直接処理されます。その他の場合、バッファゾーンを介して間接的に処理されます。その場合、未使用の従来型ゾーンが割り当てられ、チャンクに割り当てられます。チャンクのバッファゾーンにブロックを書き込むと、そのチャンクをマッピングしている連続ゾーン内の同じブロックが自動的に無効になります。連続ゾーン内のすべてのブロックが無効になると、ゾーンは解放され、チャンクのバッファゾーンが主なマッピングゾーンとなり、通常のブロックデバイスと同様のネイティブランダム書き込み性能が得られます。

読み込み操作はビットマップから提供されるブロックの有効性情報に基づいて処理されます。有効ブロックは、チャンクをマッピングしている連続ゾーンから読み込まれます。チャンクがバッファードの場合、バッファゾーンから読み込まれます。アクセスされたチャンクにマッピングがなければ、またはアクセスされたブロックが無効な場合、読み込みバッファがゼロクリアされ、読み込み操作が終了します。

ある程度時間が経つと、利用可能な伝統的なゾーンが限られているため、すべてのゾーンがチャンクやバッファ順次ゾーンのマッピングに使われた場合、未バッファリングされたチャンクへの未整列の書き込みが不可能になる可能性があります。このような状況を避けるため、回収プロセスが定期的に使用されている伝統的なゾーンをスキャンし、バッファゾーンの有効ブロックを空き順次ゾーンにコピーすることで、最も最近使用されていないゾーンを回収しようとします。コピーが完了すると、チャンクマッピングが順次ゾーンを指すように更新され、バッファゾーンは再利用可能な状態になります。

メタデータ保護¶

急な電源オフやシステムクラッシュによるメタデータの破損を防ぐために、2セットのメタデータゾーンが使用されます。1セットはプライマリセットと呼ばれ、主なメタデータ領域として使用され、もう1セットはセカンダリセットと呼ばれ、ステージングエリアとして使用されます。変更されたメタデータはまずセカンダリセットに書き込まれ、その後、セカンダリセット内のスーパーブロックを更新することで検証されます。生成カウンタがこのセットに最新のメタデータが含まれていることを示します。この操作が完了すると、プライマリメタデータセットでメタデータブロックの更新が行われます。これにより、常にどちらか一方のセットが一貫性を保つようになります（すべての変更がコミットされるか、まったくコミットされない）。フラッシュ操作はコミットポイントとして使用されます。フラッシュリクエストを受信した際には、メタデータの変更活動が一時的に停止されます（インカムBIO処理および回収プロセスの双方）。すべての汚染されたメタデータブロックがステージングされ、更新されます。その後、通常の操作が再開されます。これにより、メタデータのフラッシュは書き込みおよび破棄リクエストを一時的に遅延させるだけです。メタデータのフラッシュが実行されている間でも、読み取りリクエストは並行して処理可能です。

通常のデバイスとゾーンブロックデバイスを併用する場合、ゾーンブロックデバイスの開始位置にゾーンビットマップを含まない第3のメタデータが書き込まれます。このメタデータは生成カウンタが「0」であり、通常の操作中には更新されません。これは識別目的にのみ使用されます。1番目のメタデータと2番目のメタデータは通常のブロックデバイスの開始位置に配置されます。

使い方¶

ゾーンブロックデバイスはまずdmzadmツールを使用してフォーマットする必要があります。これにより、デバイスのゾーン構成が分析され、メタデータセットの配置場所が決定され、メタデータセットが初期化されます。

例:

dmzadm --format /dev/sdxx

2つのドライブを使用する場合、両方のデバイスを指定する必要があります。通常のブロックデバイスを最初のデバイスとして指定してください。

例:

dmzadm --format /dev/sdxx /dev/sdyy

フォーマット済みデバイス（複数可）はdmzadmユーティリティでも起動できます。

例:

dmzadm --start /dev/sdxx /dev/sdyy

ゾーンの内部レイアウトおよび現在の使用状況に関する情報は、dmsetupからのステータスコールバックで取得できます:

例:

dmsetup status /dev/dm-X

1行を返します

0 <size> zoned <nr_zones> ゾーン <nr_unmap_rnd>/<nr_rnd> ランダム <nr_unmap_seq>/<nr_seq> 連続

<nr_zones> はゾーンの総数、<nr_unmap_rnd> は未マッピング（つまり空き）のランダムゾーンの数、<nr_rnd> は総ランダムゾーン数、<nr_unmap_seq> は未マッピングの連続ゾーン数、<nr_seq> は総連続ゾーン数です。

通常、空きランダムゾーンが50％未満になるとリカレントプロセスが自動的に開始されます。この閾値に達する前に手動でリカレントプロセスを開始するには、‘dmsetup message’関数を使用できます:

例:

dmsetup message /dev/dm-X 0 reclaim

リカレントプロセスを開始し、ランダムゾーンが連続ゾーンに移動します。
