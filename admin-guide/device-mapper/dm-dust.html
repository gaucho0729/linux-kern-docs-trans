dm-dust¶

このターゲットは、不良セクタが任意の場所に存在する挙動をエミュレートし、任意のタイミングでエミュレーションの失敗を有効化する機能を備えています。

このターゲットは線形ターゲットと同様の挙動をします。特定のタイミングでユーザーがメッセージを送信することで、特定のブロックでの読み込み失敗を開始し、ハードディスクドライブの不良セクタの挙動をエミュレートします。

失敗挙動が有効になっている場合（つまり、「dmsetup status」の出力が「fail_read_on_bad_block」と表示されている場合）、不良セクタリスト内のブロックの読み込みはEIO（入出力エラー）で失敗します。

不良セクタリスト内のブロックへの書き込みは以下の結果になります：

  1. ブロックを不良セクタリストから削除します。

  2. 書き込みが正常に完了します。

これは、不良セクタを持つドライブの「リマップされたセクタ」の挙動をエミュレートします。

通常、不良セクタに遭遇するドライブは、未知のタイミングや場所でさらに多くの不良セクタに遭遇します。dm-dustでは、ユーザーは「addbadblock」と「removebadblock」メッセージを使用して任意の場所に不良セクタを追加し、「enable」と「disable」メッセージを使用して、設定された「不良セクタ」が不良として扱われるかバイパスされるかの状態を制御できます。これにより、不良セクタが現始める「失敗」イベントをシミュレートする前にテストデータとメタデータを事前に書き込むことが可能です。

テーブルパラメータ¶

<device_path> <offset> <blksz>

必須パラメータ：
<device_path>：

ブロックデバイスへのパス。

<offset>：

device_pathの開始位置からのデータ領域オフセット

<blksz>：

ブロックサイズ（バイト単位）

(最小512、最大1073741824、2の累乗でなければなりません)

使用方法¶

まず、使用するデバイスのサイズ（512バイトセクタ単位）を確認します：

$ sudo blockdev --getsz /dev/vdb1
33552384

dm-dustデバイスを作成します（512バイトブロックサイズのデバイスの場合）：

$ sudo dmsetup create dust1 --table '0 33552384 dust /dev/vdb1 0 512'

(4096バイトブロックサイズのデバイスの場合)

$ sudo dmsetup create dust1 --table '0 33552384 dust /dev/vdb1 0 4096'

読み込み挙動のステータスを確認します（「bypass」はすべてのI/Oが下位デバイスに透過されるを示し、「verbose」は不良セクタの追加・削除・リマップが詳細にログ出力されるを示します）：

$ sudo dmsetup status dust1
0 33552384 dust 252:17 bypass verbose

$ sudo dd if=/dev/mapper/dust1 of=/dev/null bs=512 count=128 iflag=direct
128+0 records in
128+0 records out

$ sudo dd if=/dev/zero of=/dev/mapper/dust1 bs=512 count=128 oflag=direct
128+0 records in
128+0 records out

不良セクタの追加と削除¶

いつでも（つまりデバイスが「不良セクタ」エミュレーションが有効か無効かに関わらず）、addbadblockとremovebadblockメッセージを使用して不良セクタを追加または削除できます：

$ sudo dmsetup message dust1 0 addbadblock 60
kernel: device-mapper: dust: badblock added at block 60

$ sudo dmsetup message dust1 0 addbadblock 67
kernel: device-mapper: dust: badblock added at block 67

$ sudo dmsetup message dust1 0 addbadblock 72
kernel: device-mapper: dust: badblock added at block 72

これらの不良セクタは不良セクタリストに保存されます。デバイスがバイパスモードの間、読み込みと書き込みは成功します：

$ sudo dmsetup status dust1
0 33552384 dust 252:17 bypass

ブロック読み込み失敗の有効化¶

「不良セクタでの読み込み失敗」の挙動を有効にするには、enableメッセージを送信します：

$ sudo dmsetup message dust1 0 enable
kernel: device-mapper: dust: enabling read failures on bad sectors

$ sudo dmsetup status dust1
0 33552384 dust 252:17 fail_read_on_bad_block

「fail read on bad block」モードでデバイスを設定した場合、ブロックの読み取りを試みると「入出力エラー」が発生します:

$ sudo dd if=/dev/mapper/dust1 of=/dev/null bs=512 count=1 skip=67 iflag=direct
dd: error reading '/dev/mapper/dust1': Input/output error
0+0 records in
0+0 records out
0 bytes copied, 0.00040651 s, 0.0 kB/s

…また、不良ブロックへの書き込みはそのブロックを一覧から削除し、ハードディスクドライブの「remap」動作を模倣します:

$ sudo dd if=/dev/zero of=/dev/mapper/dust1 bs=512 count=128 oflag=direct
128+0 records in
128+0 records out

kernel: device-mapper: dust: block 60 removed from badblocklist by write
kernel: device-mapper: dust: block 67 removed from badblocklist by write
kernel: device-mapper: dust: block 72 removed from badblocklist by write
kernel: device-mapper: dust: block 87 removed from badblocklist by write

不良ブロックの追加/削除エラー処理¶

既に一覧に存在する不良ブロックを追加しようとすると、「無効な引数」エラーが発生し、以下の助言メッセージも表示されます:

$ sudo dmsetup message dust1 0 addbadblock 88
device-mapper: message ioctl on dust1  failed: Invalid argument
kernel: device-mapper: dust: block 88 already in badblocklist

一覧に存在しない不良ブロックを削除しようとすると、「無効な引数」エラーが発生し、以下の助言メッセージも表示されます:

$ sudo dmsetup message dust1 0 removebadblock 87
device-mapper: message ioctl on dust1  failed: Invalid argument
kernel: device-mapper: dust: block 87 not found in badblocklist

不良ブロック一覧内の不良ブロック数をカウントする¶

デバイスに設定された不良ブロック数をカウントするには、以下のメッセージコマンドを実行してください:

$ sudo dmsetup message dust1 0 countbadblocks

デバイスに現在設定されている不良ブロック数が表示されるメッセージが表示されます:

countbadblocks: 895 badblock(s) found

特定の不良ブロックの照会¶

特定のブロックが不良ブロック一覧に含まれているか確認するには、以下のメッセージコマンドを実行してください:

$ sudo dmsetup message dust1 0 queryblock 72

ブロックが一覧にある場合、以下のメッセージが表示されます:

dust_query_block: block 72 found in badblocklist

ブロックが一覧にない場合、以下のメッセージが表示されます:

dust_query_block: block 72 not found in badblocklist

「queryblock」メッセージコマンドは「有効」および「無効」の両方のモードで動作し、デバイスにI/Oを送信することなく、または「有効化」せずにブロックが「不良」と扱われるかを検証できます。

不良ブロック一覧のクリア¶

個別に「removebadblock」メッセージコマンドを実行する必要なく、不良ブロック一覧をクリアするには、以下のメッセージコマンドを実行してください:

$ sudo dmsetup message dust1 0 clearbadblocks

不良ブロック一覧をクリアした後、以下のメッセージが表示されます:

dust_clear_badblocks: badblocks cleared

クリアする不良ブロックがなかった場合、以下のメッセージが表示されます:

dust_clear_badblocks: no badblocks found

不良ブロック一覧の表示¶

不良ブロック一覧内のすべての不良ブロックを表示するには（例としてブロック1と2が不良ブロック一覧にあるデバイスを使用）、以下のメッセージコマンドを実行してください:

$ sudo dmsetup message dust1 0 listbadblocks
1
2

不良ブロック一覧に不良ブロックがなければ、コマンドは出力なしで実行されます:

$ sudo dmsetup message dust1 0 listbadblocks

メッセージコマンド一覧¶

以下は、dustデバイスに送信可能なメッセージの一覧です:

ブロックに対する操作（<blknum>という引数が必要）:

addbadblock <blknum>
queryblock <blknum>
removebadblock <blknum>

…ここで<blknum>はデバイスの範囲内のブロック番号（デバイスのブロックサイズに応じたものです）です。

単一引数メッセージコマンド:

countbadblocks
clearbadblocks
listbadblocks
disable
enable
quiet

デバイスの除去¶

完了したら、「dmsetup remove」コマンドでデバイスを除去してください:

$ sudo dmsetup remove dust1

静かなモード¶

多数の不良ブロックがあるテスト実行では、不良ブロックの追加・削除・「remap」に関する過剰なログ出力を回避したい場合があります。これは以下のメッセージを介して「静かなモード」を有効化することで実現できます:

$ sudo dmsetup message dust1 0 quiet

これは、追加/削除/削除された操作によってログメッセージを抑制します。ただし、「countbadblocks」または「queryblock」メッセージコマンドからのログメッセージは、静粛モードでも表示されます。

静粛モードの状態は、「dmsetup status」を実行することで確認できます：

$ sudo dmsetup status dust1
0 33552384 dust 252:17 fail_read_on_bad_block quiet

静粛モードを無効にするには、「quiet」メッセージを再度送信してください：

$ sudo dmsetup message dust1 0 quiet

$ sudo dmsetup status dust1
0 33552384 dust 252:17 fail_read_on_bad_block verbose

（「verbose」が存在することにより、通常のログ出力が行われます。）

「なぜしないの…？」¶

scsi_debug には、「medium error（中程度のエラー）」モードがあり、指定されたセクター（セクター 0x1234、ソースコードでハードコード済み）での読み取りを失敗させることが可能です。ただし、永続的なストレージとして RAM を使用するため、潜在的なデバイスサイズが大幅に減少します。

dm-flakey は、指定された時間周波数で全ブロック位置からの I/O を失敗させ、特定の時刻ではなく、時間の周期に基づいて動作します。

ハードディスクドライブで不良セクターが発生した場合、デバイスはそのセクターの読み取りを失敗させ、通常 EIO（「I/O エラー」）または ENODATA（「データが利用できません」）というエラー コードを返します。ただし、セクターへの書き込みは成功する可能性があり、デバイス コントローラーがそのセクターの読み取りエラーを再び経験しなくなった後（またはセクターの再配置後）に、セクターが読み取り可能になることがあります。ただし、今後デバイスで発生する不良セクターは、異なる、予測できない場所に現れる可能性があります。

このターゲットは、大容量のストレージデバイス（少なくとも数十ギガバイト、システムメモリを占有しません）を基盤として、特定のセクター位置および特定の時間に不良セクターの挙動を再現するデバイスを提供することを目指しています。
