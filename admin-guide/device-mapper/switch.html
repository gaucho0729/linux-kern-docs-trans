dm-switch (スイッチングデバイスマッパーターゲット)¶

device-mapper switch targetは、固定サイズのI/O領域を固定のパスセットに任意にマッピングするデバイスをサポートします。特定の領域に使用されるパスは、ターゲットにメッセージを送ることで動的に切り替えることができます。

多数の固定サイズのアドレス領域があり、dm-stripeなどのコンパクトな表現が可能でない場合、このターゲットは下位ブロックデバイスへのI/Oを効率的にマッピングします。

背景¶

Dell EqualLogicや他の一部のiSCSIストレージアレイは、分散型フレームレスアーキテクチャを使用しています。このアーキテクチャでは、ストレージグループは複数の独立したコントローラー、ディスクストレージ、ネットワークアダプターを持つ「メンバー」と呼ばれるストレージアレイで構成されます。LUNが作成されると、そのデータは複数のメンバーに分散されます。この分散の詳細は、このストレージシステムに接続されたイニシエーターには隠蔽されます。ストレージグループは、使用しているメンバー数に関係なく単一のターゲット発見ポートを提供します。iSCSIセッションが作成されると、各セッションは単一のメンバーのethポートに接続されます。LUNへのデータは任意のiSCSIセッション経由で送信でき、アクセスされるブロックが別のメンバーに保存されている場合、I/Oは必要に応じて転送されます。この転送はイニシエーターには見えません。ストレージレイアウトは動的であり、必要に応じてディスクに保存されているブロックをメンバー間で移動させることも可能です。

このアーキテクチャにより、ストレージグループとイニシエーターの管理・設定が簡素化されます。マルチパス設定では、ホストとターゲットの両方で複数のネットワークインターフェースを使用した複数のiSC�セッションを設定し、ネットワーク帯域幅の増加を活用できます。イニシエーターは、すべてのパスをラウンドロビンアルゴリズムで使用してI/Oを送信し、ストレージアレイメンバーが必要に応じて転送するようにすることができますが、データを正しいメンバーに直接送信することでパフォーマンスが向上します。

既存のdevice-mapperテーブルは、デバイスの異なる領域を異なるターゲットにマッピングできますが、このアーキテクチャではLUNが数十MB単位のアドレス領域に分散されるため、結果として得られるテーブルは100万以上のエントリを持つ可能性があり、メモリを大幅に消費します。

このdevice-mapper switch targetを使用することで、2層のデバイス階層を構築できます。

上位階層 - I/Oを送信すべきアレイメンバーを決定。下位階層 - 特定のメンバーへのパス間での負荷分散を実行。

下位階層は、各メンバーごとに1つのdm multipathデバイスを含みます。これらの各multipathデバイスは、1つの優先度グループ内の配列メンバーへの直接的なパスのセットを含み、既存のパスセレクターを活用してこれらのパス間でロードバランシングを行います。また、フェールオーバーのための他の配列メンバーへのパスを含む非推奨優先度グループも構築します。

上位階層は、1つのdm-switchデバイスを含みます。このデバイスはビットマップを使用してI/Oの位置を検索し、適切な下位階層デバイスを選択してI/Oをルーティングします。ビットマップを使用することで、16メンバーのグループ内の各アドレス範囲に対して4ビットを使用できます（これは私たちにとって非常に大きな値です）。これは、dmテーブルのBツリーが達成できるよりも密度の高い表現です。

構築パラメータ¶

<num_paths> <region_size> <num_optional_args> [<optional_args>…] [<dev_path> <offset>]+
<num_paths>

I/Oを分散するためのパスの数。

<region_size>

領域内の512バイトセクタ数。各領域は利用可能なパスのいずれかにリダイレクトできます。

<num_optional_args>

オプション引数の数。現在、オプション引数はサポートされていないため、この値はゼロでなければなりません。

<dev_path>

特定のパスへのデバイスを表すブロックデバイス。

<offset>

特定の<dev_path>上のデータの開始位置のオフセット（512バイトセクタ単位）。この数値は、リクエストを特定のパスに転送する際のセクタ番号に加算されます。通常はゼロです。

メッセージ¶

set_region_mappings <index>:<path_nr> [<index>]:<path_nr> [<index>]:<path_nr>…

領域テーブルを修正し、どの領域がどのパスにリダイレクトされるかを指定します。

<index>

領域番号（領域サイズは構築パラメータで指定されます）。インデックスが省略された場合、次の領域（前のインデックス＋1）が使用されます。16進数で表します（0xなどのプレフィックスは不要です）。

<path_nr>

0 … (<num_paths> - 1)の範囲にあるパス番号。16進数で表します（0xなどのプレフィックスは不要です）。

R<n>,<m>

このパラメータは繰り返しパターンを素早くロードするためのものです。<n>および<m>は16進数の数です。最後の<n>マッピングが次の<m>スロットに繰り返されます。

Status¶

ステータスラインは報告されません。

例¶

同じサイズのボリュームvg1/switch0 vg1/switch1 vg1/switch2を仮定します。

64KBの領域サイズを持つswitchデバイスを作成します:

dmsetup create switch --table "0 `blockdev --getsz /dev/vg1/switch0`
    switch 3 128 0 /dev/vg1/switch0 0 /dev/vg1/switch1 0 /dev/vg1/switch2 0"

最初の7項目をswitch0、switch1、switch2、switch0、switch1、switch2、switch1にマッピングします:

dmsetup message switch 0 set_region_mappings 0:0 :1 :2 :0 :1 :2 :1

繰り返しマッピングを設定します。このコマンド:

dmsetup message switch 0 set_region_mappings 1000:1 :2 R2,10

は以下のコマンドと同等です：

dmsetup message switch 0 set_region_mappings 1000:1 :2 :1 :2 :1 :2 :1 :2 \
    :1 :2 :1 :2 :1 :2 :1 :2 :1 :2
