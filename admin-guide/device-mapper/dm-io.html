dm-io¶

Dm-ioは同期I/Oおよび非同期I/Oのサービスを提供します。3つのタイプのI/Oサービスが利用可能で、それぞれが同期版と非同期版を持っています。

ユーザーはio_region構造体を設定して、I/Oの希望する位置を記述する必要があります。各io_regionはブロックデバイスと、領域の開始セクタおよびサイズを示します:

struct io_region {
   struct block_device *bdev;
   sector_t sector;
   sector_t count;
};

Dm-ioは1つのio_regionから読み取るか、複数のio_regionに書き込むことができます。複数の領域への書き込みはio_region構造体の配列で指定します。

最初のI/Oサービスタイプは、I/Oのデータバッファとしてメモリページのリストを取る仕様です。また、最初のページ内のオフセットも指定します:

struct page_list {
   struct page_list *next;
   struct page *page;
};

int dm_io_sync(unsigned int num_regions, struct io_region *where, int rw,
               struct page_list *pl, unsigned int offset,
               unsigned long *error_bits);
int dm_io_async(unsigned int num_regions, struct io_region *where, int rw,
                struct page_list *pl, unsigned int offset,
                io_notify_fn fn, void *context);

2番目のI/Oサービスタイプは、I/Oのデータバッファとしてbioベクターの配列を取る仕様です。呼び出し元が事前に組み上げたbioを持ち、その一部を異なるデバイスに割り当てたい場合に便利です:

int dm_io_sync_bvec(unsigned int num_regions, struct io_region *where,
                    int rw, struct bio_vec *bvec,
                    unsigned long *error_bits);
int dm_io_async_bvec(unsigned int num_regions, struct io_region *where,
                     int rw, struct bio_vec *bvec,
                     io_notify_fn fn, void *context);

3番目のI/Oサービスタイプは、I/Oのデータバッファとしてvmallocで確保されたメモリバッファへのポインタを取る仕様です。呼び出し元が大規模な領域へのI/Oを実行したいが、多数の個別メモリページを確保したくない場合に便利です:

int dm_io_sync_vm(unsigned int num_regions, struct io_region *where, int rw,
                  void *data, unsigned long *error_bits);
int dm_io_async_vm(unsigned int num_regions, struct io_region *where, int rw,
                   void *data, io_notify_fn fn, void *context);

非同期I/Oサービスを呼び出す際には、完了コールバックルーチンの名前と、I/O用のコンテキストデータへのポインタを指定する必要があります:

typedef void (*io_notify_fn)(unsigned long error, void *context);

このコールバックの「error」パラメータおよびすべての同期版の「*error」パラメータは、ビットセット（単純なエラー値ではなく）です。複数の領域への書き込みの場合、このビットセットによりdm-ioが各個別領域の成功・失敗を示すことができます。 *error パラメータはすべての同期版で、ビットセット（単純なエラー値ではなく）です。複数の領域への書き込みの場合、このビットセットによりdm-ioが各個別領域の成功・失敗を示すことができます。

どのdm-ioサービスを使用する前に、ユーザーはdm_io_get()を呼び出し、同時にI/Oを実行するメモリページ数を指定する必要があります。dm-ioはメモリプールを再調整して、I/O実行時の不要な待機を避けるために十分なページが常に利用可能になるようにします。

dm-ioサービスを使用が終了した後は、dm_io_put()を呼び出し、dm_io_get()呼び出し時に指定した同じ数のページを指定します。
