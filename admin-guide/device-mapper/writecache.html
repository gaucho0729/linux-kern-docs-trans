ライトキャッシュターゲット¶

Writecache target は、永続メモリまたはSSD上に書き込みをキャッシュします。読み込みは通常のRAMのページキャッシュでキャッシュされるため、読み込みをキャッシュしません。

デバイスが構築される際、最初のセクタはゼロに設定されているか、以前の呼び出しで有効なスーパーブロックを含んでいる必要があります。

コンストラクタパラメータ:

  1. キャッシュデバイスのタイプ - 「p」または「s」

    • p - 永続メモリ

    • s - SSD

  2. キャッシュされる下位デバイス

  3. キャッシュデバイス

  4. ブロックサイズ（4096が推奨されます；最大ブロックサイズはページサイズです）

  5. オプションパラメータの数（引数を持つパラメータは2つとカウントされます）

    start_sector n（デフォルト: 0）

    キャッシュデバイスの開始位置からの512バイトセクタのオフセット

    high_watermark n（デフォルト: 50）

    使用ブロック数がこのウォーターマークに達したときに書き戻しを開始します

    low_watermark x（デフォルト: 45）

    使用ブロック数がこのウォーターマークを下回ったときに書き戻しを停止します

    writeback_jobs n（デフォルト: 無制）

    書き戻し中のブロック数を制限します。この値を設定すると書き戻しのスループットは低下しますが、読み取りリクエストのレイテンシーが改善される可能性があります

    autocommit_blocks n（デフォルト: pmem では 64、ssd では 65536）

    アプリケーションがFLUSHリクエストを発行せずにこのブロック数を書き込んだ場合、ブロックは自動的にコミットされます

    autocommit_time ms（デフォルト: 1000）

    ミリ秒単位の自動コミット時間。この時間経過しFLUSHリクエストが受信されなければデータが自動的にコミットされます

    fua（デフォルトでは有効）

    永続メモリ専用 - 永続メモリから下位デバイスへデータを書く際にはFUAフラグを使用します

    nofua

    永続メモリ専用 - データを戻す際にはFUAフラグを使わず、その後FLUSHリクエストを送信します

    • 一部の下位デバイスではfuaが効果的ですが、一部ではnofuaが効果的です。ユーザーはテストを行う必要があります

ステータス: 1. エラーインジケーター - エラーがない場合は0、エラーがある場合はエラーナンバー 2. ブロック数 3. 空きブロック数 4. 書き戻中のブロック数

メッセージ:
flush

キャッシュデバイスをフラッシュします。キャッシュデバイスがエラーなしでフラッシュされた場合にメッセージが成功します

flush_on_suspend

次のスリープ時にキャッシュデバイスをフラッシュします。キャッシュデバイスを削除する際にはこのメッセージを使用してください。適切な手順は以下の通りです:

  1. 「flush_on_suspend」メッセージを送信します

  2. 下位デバイスにマッピングするラインアライメントのターゲットを持つ非アクティブテーブルをロードします

  3. デバイスをスリープ状態にします

  4. ステータスを確認し、エラーがないことを検証します

  5. デバイスを再開し、線形目標を使用するようにしてください

  6. キャッシュデバイスは現在非アクティブであり、削除できます
