EFI ブート ステブ¶

x86およびARMプラットフォームでは、カーネルのzImage/bzImageがPE/COFF画像として偽装され、EFIファームウェアロー�ーダーがそれをEFI実行ファイルとしてロードするように説得できます。bzImageヘッダーを変更するコードと、ファームウェアローダーがジャンプするEFI固有のエントリポイントは、合わせて「EFIブートスタブ」として知られ、arch/x86/boot/header.Sおよびarch/x86/boot/compressed/eboot.cにそれぞれ実装されています。ARMの場合、EFIスタブはarch/arm/boot/compressed/efi-header.Sおよびarch/arm/boot/compressed/efi-stub.cに実装されています。複数のアーキテクチャで共有されるEFIスタブコードはdrivers/firmware/efi/libstubにあります。

arm64では圧縮されたカーネルのサポートがありませんので、Image自体がPE/COFF画像として偽装され、EFIスタブはカーネルにリンクされています。arm64のEFIスタブはarch/arm64/kernel/efi-entry.Sおよびdrivers/firmware/efi/libstub/arm64-stub.cにあります。

EFIブートスタブを使用することで、grubやeliloなどの従来のEFIブートローダーを使わずにLinuxカーネルを起動することが可能です。EFIブートスタブはブートローダーの役割を果たすため、ある意味では IS ブートローダーです。

EFIブートスタブはCONFIG_EFI_STUBというカーネルオプションで有効になります。

bzImage.efiのインストール方法¶

arch/x86/boot/bzImageに存在するbzImageはEFIシステムパーティション（ESP）にコピーし、拡張子「.efi」でリネームする必要があります。拡張子がないとEFIファームウェアローダーが実行を拒否します。通常のLinuxファイルシステムからbzImage.efiを実行することはできませんが、EFIファームウェアはそれらのファイルシステムをサポートしていません。ARMの場合、arch/arm/boot/zImageをシステムパーティションにコピーし、リネームする必要がない場合があります。同様にarm64では、arch/arm64/boot/Imageをコピーするだけでよい場合があります。

EFIシェルからカーネルパラメータを渡す方法¶

bzImage.efiの後にカーネルの引数を渡すことができます。例えば：

fs0:> bzImage.efi console=ttyS0 root=/dev/sda4

「initrd=」オプション¶

ほとんどのブートローダーと同様に、EFIスタブは「initrd=」オプションを使用して複数のinitrdファイルを指定できます。これはEFIスタブ固有のコマンドラインパラメータであり、それ以外のパラメータはカーネル起動時に渡されます。

initrdファイルへのパスはESPの開始位置からの絶対パスでなければなりません。相対パスは機能しません。また、パスはEFIスタイルのパスであり、ディレクトリ要素はバックスラッシュ（\）で区切る必要があります。例えば、以下のディレクトリレイアウトがある場合：

fs0:>
      Kernels\
                      bzImage.efi
                      initrd-large.img

      Ramdisks\
                      initrd-small.img
                      initrd-medium.img

現在の作業ディレクトリが fs0:Kernels の場合、initrd-large.img ファイルを使用して起動するには、以下のコマンドを使用する必要があります。

fs0:\Kernels> bzImage.efi initrd=\Kernels\initrd-large.img

bzImage.efi に相対パスで指定できる点に注意してください。これは、実行しているイメージが EFI シェルによって解釈されるためで、EFI シェルは相対パスを理解しているからです。一方、コマンドラインの他の部分は bzImage.efi に渡されます。

「dtb=」オプション¶

ARM および arm64 アーキテクチャでは、カーネルにデバイスツリーを提供する必要があります。通常、ファームウェアは EFI CONFIGURATION TABLE を介してデバイスツリーを提供します。ただし、「dtb=」コマンドラインオプションを使用して、ファームウェアが提供するデバイスツリーを上書きするか、ファームウェアが提供できない場合にデバイスツリーを提供できます。

注意: ファームウェアは、カーネルの起動前にデバイスツリーにランタイムの設定情報を追加します。dtb= を使用してデバイスツリーを上書きすると、ファームウェアが提供するランタイムデータが失われる可能性があります。dtb= オプションは、デバッグツールとして使用するか、EFI CONFIGURATION TABLE にデバイスツリーが提供されていない場合の最終手段としてのみ使用すべきです。

「dtb=」は、上記で説明した「initrd=」オプションと同じ方法で処理されます。
