2.1. このガイドについて¶

このガイドでは、PCI Express Port Busドライバーの基本的な動作について説明し、サービスドライバーがPCI Express Port Busドライバーに登録/解除を行う方法についての情報を提供します。

2.2. PCI Express Port Busドライバーとは何ですか？¶

PCI Express Portは論理的なPCI-PCIブリッジ構造です。PCI Express Portには2つのタイプがあります：Root PortとSwitch Port。Root PortはPCI Express Root ComplexからPCI Expressリンクを開始し、Switch PortはPCI Expressリンクを内部の論理PCIバスに接続します。Switch Portのセカンダリバスがスイッチの内部ルーティングロジックを表すため、これをスイッチのアップストリームポートと呼びます。スイッチのダウンストリームポートは、スイッチの内部ルーティングバスからPCI Expressスイッチのダウンストリームリンクを表すバスにブリッジします。

PCI Express Portはポートタイプに応じて最大4つの異なる機能（このドキュメントではサービスと呼ばれます）を提供します。PCI Express Portのサービスには、ネイティブホットプラグサポート（HP）、電源管理イベントサポート（PME）、高度なエラー報告サポート（AER）、仮想チャネルサポート（VC）が含まれます。これらのサービスは単一の複合ドライバーによって処理されるか、対応するサービスドライバーによって個別に処理されます。

2.3. なぜPCI Express Port Busドライバーを使用するのでしょうか？¶

既存のLinuxカーネルでは、物理デバイスは単一のドライバーによって処理されます。PCI Express Portは複数の異なるサービスを持つPCI-PCIブリッジデバイスです。複数のサービスを簡潔かつシンプルに処理するため、各サービスに専用のソフトウェアサービスドライバーが割り当てられます。この場合、複数のサービスドライバーが単一のPCI-PCIブリッジデバイスを競合して使用します。たとえば、PCI Express Root Portのネイティブホットプラグサービスドライバーが最初にロードされると、そのRoot Portを占有します。これにより、カーネルはそのRoot Port用の他のサービスドライバーをロードしません。つまり、現在のドライバーモデルでは、複数のサービスドライバーが同時にPCI-PCIブリッジデバイス上で動作することはできません。

複数のサービスドライバーが同時に動作するようにするには、PCI Express Port Busドライバーを使用する必要があります。これはすべての populated PCI Express Port を管理し、必要なサービスリクエストを対応するサービスドライバーに配信します。PCI Express Port Busドライバーを使用する主な利点は以下の通りです：

  • 複数のサービスドライバーがPCI-PCIブリッジポートデバイス上で同時に実行されるように許可する。

  • 独立した段階的アプローチで実装されたサービスドライバーを許可する。

  • 1つのサービスドライバーが複数のPCI-PCIブリッジポートデバイス上で実行されるように許可する。

  • PCI-PCIブリッジポートデバイスのリソースを要求されたサービスドライバーに管理・配分する。

2.4. PCI Expressポートバスドライバーとサービスドライバーの設定¶

2.4.1. PCI Expressポートバスドライバーのサポートをカーネルに含める¶

PCI Expressポートバスドライバーの含め方は、カーネル構成にPCI Expressサポートが含まれているかどうかに依存する。カーネルがPCI Expressサポートを有効にした場合、カーネルが自動的にPCI Expressポートバスドライバーをカーネルドライバーとして含める。

2.4.2. サービスドライバーのサポートを有効にする¶

PCIデバイスドライバーはLinuxデバイスドライバーモデルに基づいて実装される。すべてのサービスドライバーはPCIデバイスドライバーである。上記のように、カーネルがPCI Expressポートバスドライバーをロードした後は、どのサービスドライバーもロードできない。PCI Expressポートバスドライバーモデルを満たすには、既存のサービスドライバーに最小限の変更を加える必要があり、既存のサービスドライバーの機能に影響を与えない。

サービスドライバーは、以下の2つのAPIを使用してPCI Expressポートバスドライバーにサービスを登録する必要がある（セクション5.2.1および5.2.2を参照）。サービスドライバーは、これらのAPIを呼び出す前に、ヘッダーファイル/include/linux/pcieport_if.hに含まれるpcie_port_service_driverデータ構造体を初期化する必要がある。これを実施しないと、識別子の不一致が発生し、PCI Expressポートバスドライバーがサービスドライバーをロードできなくなる。

2.4.2.1. pcie_port_service_register¶

int pcie_port_service_register(struct pcie_port_service_driver *new)

このAPIはLinuxドライバーモデルのpci_register_driver APIを置き換える。サービスドライバーは常にモジュール初期化時にpcie_port_service_registerを呼び出すべきである。注意点として、サービスドライバーがロードされた後、pci_enable_device(dev)やpci_set_master(dev)などの呼び出しは不要である。これらの呼び出しはPCIポートバスドライバーによって自動的に実行される。

2.4.2.2. pcie_port_service_unregister¶

void pcie_port_service_unregister(struct pcie_port_service_driver *new)

pcie_port_service_unregisterはLinuxドライバーモデルのpci_unregister_driverを置き換える。サービスドライバーはモジュール終了時に常にこのAPIを呼び出す。

2.4.2.3. サンプルコード¶

以下はポートサービスドライバーのデータ構造体を初期化するためのサービスドライバーのサンプルコードです。

static struct pcie_port_service_id service_id[] = { {
  .vendor = PCI_ANY_ID,
  .device = PCI_ANY_ID,
  .port_type = PCIE_RC_PORT,
  .service_type = PCIE_PORT_SERVICE_AER,
  }, { /* end: all zeroes */ }
};

static struct pcie_port_service_driver root_aerdrv = {
  .name               = (char *)device_name,
  .id_table   = &service_id[0],

  .probe              = aerdrv_load,
  .remove             = aerdrv_unload,

  .suspend    = aerdrv_suspend,
  .resume             = aerdrv_resume,
};

サービスドライバーの登録・解除に関するサンプルコードです。

static int __init aerdrv_service_init(void)
{
  int retval = 0;

  retval = pcie_port_service_register(&root_aerdrv);
  if (!retval) {
    /*
    * FIX ME
    */
  }
  return retval;
}

static void __exit aerdrv_service_exit(void)
{
  pcie_port_service_unregister(&root_aerdrv);
}

module_init(aerdrv_service_init);
module_exit(aerdrv_service_exit);

2.5. 資源競合の可能性¶

すべてのPCI-PCI Bridge Portデバイスのサービスドライバーが同時に実行可能であるため、以下にいくつかの可能なリソース競合とその解決策をリストします。

2.5.1. MSIおよびMSI-Xベクターリソース¶

デバイスでMSIまたはMSI-X割込みが有効になると、それらが無効化されるまでそのモードが維持されます。同一のPCI-PCI Bridgeポートのサービスドライバーは同じ物理デバイスを共有するため、個々のサービスドライバーがMSI/MSI-Xモードを有効または無効にすると予測不能な挙動を引き起こす可能性があります。

このような状況を避けるため、すべてのサービスドライバーが自身のデバイスで割込みモードを切り替えることは許可されません。PCI Expressポートバスドライバーが割込みモードを決定し、サービスドライバーには透明である必要があります。サービスドライバーは、struct pcie_deviceのfield irqに割り当てられたベクタIRQのみを把握する必要があります。これはPCI Expressポートバスドライバーが各サービスドライバーをスキャンする際に渡されます。サービスドライバーは(struct pcie_device*)dev->irqを使用してrequest_irq/free_irqを呼び出す必要があります。さらに、割込みモードはstruct pcie_deviceのfield interrupt_modeに保存されています。

2.5.2. PCIメモリ/IOマップド領域¶

PCI Express電源管理(PME)、高度なエラー報告(AER)、ホットプラグ(HP)、仮想チャネル(VC)のサービスドライバーは、PCI ExpressポートのPCI構成空間にアクセスします。すべてのケースにおいて、アクセスされるレジスタは互いに独立しています。このパッチは、すべてのサービスドライバーが適切に動作し、他のサービスドライバーの構成設定を上書きしないと仮定しています。

2.5.3. PCI構成レジスタ¶

各サービスドライバーは、自身のキャパビリティ構造体上でPCI構成操作を実行します。ただし、PCI Expressキャパビリティ構造体では、ルート制御レジスタとデバイス制御レジスタがPMEとAER間で共有されます。このパッチは、すべてのサービスドライバーが適切に動作し、他のサービスドライバーの構成設定を上書きしないと仮定しています。
