4.1. このガイドについて¶

このガイドでは、メッセージ符号化割込み（MSI）の基本的な概念、MSIを伝統的な割込みメカニズムよりも使用する利点、ドライバをMSIまたはMSI-Xに変更する方法、そしてデバイスがMSIをサポートしない場合の基本的な診断方法について説明します。

4.2. MSIとは何ですか？¶

メッセージ符号化割込みは、デバイスが特殊なアドレスに書き込みを行うことで、CPUが割込みを受信する仕組みです。

MSI機能は最初にPCI 2.2で指定され、その後PCI 3.0で各割込みを個別にマスク可能に拡張されました。MSI-X機能もPCI 3.0で導入され、MSIより多くの割込みをサポートし、割込みを個別に設定可能にしています。

デバイスはMSIとMSI-Xの両方をサポートする場合がありますが、一度に有効にするのはどちらか一方です。

4.3. なぜMSIを使用するのですか？¶

MSIを使用することで伝統的なピンベース割込みよりも優位性が得られる理由は3つあります。

ピンベースのPCI割込みはしばしば複数のデバイスで共有されます。このため、カーネルは各割込みハンドラを呼び出す必要があり、全体的なシステム性能が低下します。MSIは共有されないため、このような問題は発生しません。

デバイスがメモリにデータを書き込み、その後ピンベース割込みを発生させる場合、割込みがデータがすべてメモリに到達する前に到達する可能性があります（これはPCI-PCIブリッジの後ろにあるデバイスではより可能性が高い）。すべてのデータがメモリに到達することを確認するため、割込みハンドラは割込みを発生させたデバイスのレジスタを読み込む必要があります。PCIトランザクションの順序ルールにより、レジスタから値が返される前にすべてのデータがメモリに到達しなければなりません。MSIを使用することでこの問題を回避できます。割込みを生成する書き込みがデータ書き込みを通過できないため、割込みが発生する時点でドライバはすべてのデータがメモリに到達していることを知ります。

PCIデバイスは、ファンクションごとにピンベースの割り込みを1つしかサポートできません。ドライバーは通常、デバイスに何が起きたかを照会する必要がありますが、これにより一般的なケースでの割り込み処理が遅くなります。MSIを用いることで、デバイスはより多くの割り込みをサポートでき、それぞれの割り込みを異なる目的に特化させることができます。ある設計では、まれな条件（例えばエラー）に専用の割り込みを割り当てることで、ドライバーが通常の割り込み処理を効率的に処理できるようになります。他の設計例としては、ネットワークカードの各パケットキューまたはストレージコントローラーの各ポートに割り込みを割り当てる方法があります。

4.4. MSIの使用方法¶

PCIデバイスはピンベースの割り込みで初期化されます。デバイスドライバーはデバイスをMSIまたはMSI-Xに設定する必要があります。すべてのマシンがMSIを正しくサポートしているわけではなく、そのようなマシンでは以下のAPIが失敗し、デバイスは引き続きピンベースの割り込みを使用します。

4.4.1. MSIのカーネルサポートを含める¶

MSIまたはMSI-Xをサポートするには、カーネルがCONFIG_PCI_MSIオプションが有効になっている必要があります。このオプションは一部のアーキテクチャのみで利用でき、他のオプションも設定されている必要があります。たとえば、x86ではX86_UP_APICまたはSMPを有効にする必要があります。

4.4.2. MSIの使用¶

ドライバーはPCIレイヤーにMSIの機能を設定するようリクエストするだけで、ほとんどがすでに処理されています。

MSIまたはMSI-Xの割り込みベクターを自動的に使用するには、次の関数を使用してください：

int pci_alloc_irq_vectors(struct pci_dev *dev, unsigned int min_vecs,
              unsigned int max_vecs, unsigned int flags);

これはPCIデバイスに最大max_vecs個の割り込みベクターを割り当てます。返す値は割り当てられたベクター数または負のエラーコードです。デバイスが最小ベクター数を要求している場合、ドライバーはmin_vecs引数をその制限に設定し、PCIコアが最小数を満たせない場合に-ENOSPCを返します。

flags引数はデバイスおよびドライバーが使用できる割り込みタイプを指定します（PCI_IRQ_LEGACY、PCI_IRQ_MSI、PCI_IRQ_MSIX）。また、すべての割り込みタイプを要求するための簡易な省略形（PCI_IRQ_ALL_TYPES）も利用可能です。PCI_IRQ_AFFINITYフラグが設定されている場合、pci_alloc_irq_vectors()はCPUの可用性に応じて割り込みを分散します。

LinuxのIRQ番号を取得するために、 request_irq() および free_irq() およびベクターを使用するには、次の関数を使用してください：

int pci_irq_vector(struct pci_dev *dev, unsigned int nr);

割り当てられたリソースはデバイスを削除する前に次の関数で解放する必要があります：

void pci_free_irq_vectors(struct pci_dev *dev);

デバイスがMSI-XとMSIの両方をサポートしている場合、このAPIはMSI-X機能を優先して使用します。MSI-Xは1〜2048の中断をサポートしており、逆にMSIは最大32の中断（2の累乗である必要があります）に制限されています。さらに、MSIの中断ベクターは連続的に割り当てなければならないため、システムがMSI-Xに比べてMSI用に割り当てられるベクター数が少ない可能性があります。一部のプラットフォームでは、MSIの中断は同じCPUセットにのみターゲットとされ、MSI-Xの中断は異なるCPUにターゲットとされることがあります。

MSI-XやMSIをサポートしていないデバイスでは、単一のレガシIRQベクターにフォールバックします。

MSIまたはMSI-Xの中断の典型的な使用法は、デバイスがサポートする最大数のベクターを割り当てるものです。nvecがデバイスがサポートする数より大きい場合、自動的にサポート限界に制限されるため、事前にベクター数を照会する必要はありません:

nvec = pci_alloc_irq_vectors(pdev, 1, nvec, PCI_IRQ_ALL_TYPES)
if (nvec < 0)
        goto out_err;

ドライバーが変動するMSI中断数を扱うことができない場合、pci_alloc_irq_vectors()関数に「min_vecs」と「max_vecs」として同じ数を渡すことで特定の数の中断を要求できます:

ret = pci_alloc_irq_vectors(pdev, nvec, nvec, PCI_IRQ_ALL_TYPES);
if (ret < 0)
        goto out_err;

上記のリクエストタイプの典型的な例は、デバイスの単一MSIモードを有効にする場合です。これは「min_vecs」と「max_vecs」ととして2つの1を渡すことで実現できます:

ret = pci_alloc_irq_vectors(pdev, 1, 1, PCI_IRQ_ALL_TYPES);
if (ret < 0)
        goto out_err;

一部のデバイスはレガシライン中断をサポートしていない場合があり、その場合はドライバーがMSIまたはMSI-Xのみを許可するように指定できます:

nvec = pci_alloc_irq_vectors(pdev, 1, nvec, PCI_IRQ_MSI | PCI_IRQ_MSIX);
if (nvec < 0)
        goto out_err;

4.4.3. レガシAPI¶

以下の古いAPIは新規コードでは使用すべきではありません:

pci_enable_msi()              /* deprecated */
pci_disable_msi()             /* deprecated */
pci_enable_msix_range()       /* deprecated */
pci_enable_msix_exact()       /* deprecated */
pci_disable_msix()            /* deprecated */

さらに、サポートされるMSIまたはMSI-Xベクター数を提供するAPIもあります: pci_msi_vec_count() および pci_msix_vec_count(). 一般的には、pci_alloc_irq_vectors()がベクター数を自動的に制限するため、これらのAPIは避けるべきです。ベクター数のカウントが必要な特別な用途がある場合、その決定を再検討し、MSIおよびMSI-Xを透明に処理するpci_nr_irq_vectors()ヘルパー関数を追加する可能性があります。

4.4.4. MSIを使用する際の考慮点¶

4.4.4.1. スピンロック¶

ほとんどのデバイスドライバは、割込みハンドラで取得されるデバイスごとのスピンロックを備えています。ピンベースの割込みや単一のMSIを使用する場合、割込みを無効化する必要はありません（Linuxは同じ割込みが再入らないことを保証しています）。デバイスが複数の割込みを使用する場合、ロックを保持している間は割込みを無効化する必要があります。デバイスが異なる割込みを送信した場合、ドライバはスピンロックを再帰的に取得しようとしてデッドロックします。このようなデッドロックは、ローカル割込みを無効化してロックを取得するspin_lock_irqsave()またはspin_lock_irq()を使用することで回避できます（参照 Unreliable Guide To Locking).

4.4.5. デバイスがMSI/MSI-Xを有効にしているかを確認する方法¶

「lspci -v」（root権限で実行）を使用すると、いくつかのデバイスが「MSI」「Message Signalled Interrupts（メッセージ符号化割込み）」または「MSI-X」の機能を持つことが表示されることがあります。これらの機能それぞれには「Enable」フラグがあり、その後に「+」（有効）または「-」（無効）が続きます。

4.5. MSIの特殊な挙動¶

いくつかのPCIチップセットやデバイスはMSIをサポートしないことがわかっています。PCIスタックはMSIを無効にするための3つの方法を提供しています：

  1. グローバルに

  2. 特定のブリッジの下にあるすべてのデバイスに対して

  3. 単一のデバイスに対して

4.5.1. MSIをグローバルに無効化する¶

一部のホストチップセットはMSIを正しくサポートしていません。幸運にもメーカーがこの問題を認識しており、ACPI FADTテーブルに記載している場合があります。その場合、Linuxは自動的にMSIを無効化します。一部のボードではこの情報がテーブルに含まれていないため、私たちは自力で検出する必要があります。これらの完全なリストはdrivers/pci/quirks.cファイル内のquirk_disable_all_msi()関数の近くにあります。

MSIに問題があるボードの場合、カーネルのコマンドラインにpci=nomsiを指定してすべてのデバイスでMSIを無効化できます。問題を報告する際には、 linux-pci@vger.kernel.org に、完全な「lspci -v」の出力を添えて、カーネルにクイアックを追加できるようにしてください。

4.5.2. ブリッジの下でMSIを無効化する¶

一部のPCIブリッジは、バス間でMSIを適切にルーティングできません。その場合、ブリッジの下にあるすべてのデバイスでMSIを無効化する必要があります。

一部のブリッジは、PCIコンフィギュレーションスペース内のいくつかのビットを変更することでMSIを有効にすることができます（特にハイパーコンピュートチップセットのようなnVidia nForceやServerworks HT2000など）。ホストチップセットと同様に、Linuxはこれらをほぼすべて認識しており、可能であれば自動的にMSIを有効にします。Linuxに登録されていないブリッジの場合、ご存知の方法でコンフィギュレーションスペースでMSIを有効にして、以下のコマンドでそのブリッジでMSIを有効にすることができます：

echo 1 > /sys/bus/pci/devices/$bridge/msi_bus

ここで$bridgeは有効にしたブリッジのPCIアドレス（例：0000:00:0e.0）です。

MSIを無効にするには、0をechoしてください。この値を変更する際は注意が必要です。これは、このブリッジ以下のすべてのデバイスの割込み処理を破損させる可能性があるからです。

4.5.3. 特定のデバイスでのMSI無効化¶

一部のデバイスではMSIの実装に不具合があります。通常は個々のデバイスドライバで処理されますが、まれにクイック（quirk）で対処する必要があります。一部のドライバではMSIの使用を無効にするオプションがあります。これはドライバ開発者にとって便利な一時的な対処法ですが、ベストプラクティスではありません。ドライバの模倣には適していません。

4.5.4. デバイスでのMSI無効化の原因を特定する¶

上記の3つのセクションから、特定のデバイスでMSIが有効でない理由はいくつかあります。まず、dmesgを詳しく確認し、自分のマシンでMSIが有効になっているかを確認してください。また、.configを確認し、CONFIG_PCI_MSIが有効になっているかを確認してください。

次に、'lspci -t' コマンドでデバイス上のブリッジの一覧を取得できます。読み込む /sys/bus/pci/devices/*/msi_bus ファイルを確認することで、MSIが有効（1）か無効（0）かを確認できます。PCIルートとデバイスの間に位置するブリッジのmsi_busファイルに0が見つかった場合、MSIが無効化されている可能性があります。

デバイスドライバがMSIをサポートしているか確認することも重要です。たとえば、pci_alloc_irq_vectors()関数にPCI_IRQ_MSIまたはPCI_IRQ_MSIXフラグが含まれているか確認してください。
