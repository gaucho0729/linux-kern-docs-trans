9.4. PCIテスト機能¶

著者

Kishon Vijay Abraham I <kishon@ti.com>

従来は、標準的なPCIカード（イーサネットPCIカードやUSB PCIカード、SATA PCIカードなど）を用いてPCI RC（Root Complex）が常に検証されていました。しかし、LinuxカーネルにEP-coreが追加されることで、EPモードで動作するPCIコントローラーをテストデバイスとして構成することが可能になりました。

PCIエンドポイントテストデバイスは、ソフトウェアで定義された仮想デバイスであり、エンドポイント機能のテストに使用され、他のPCIエンドポイントデバイスのサンプルドライバとして機能します（EPフレームワークを使用するため）。

PCIエンドポイントテストデバイスには以下のレジスタがあります:

  1. PCI_ENDPOINT_TEST_MAGIC

  2. PCI_ENDPOINT_TEST_COMMAND

  3. PCI_ENDPOINT_TEST_STATUS

  4. PCI_ENDPOINT_TEST_SRC_ADDR

  5. PCI_ENDPOINT_TEST_DST_ADDR

  6. PCI_ENDPOINT_TEST_SIZE

  7. PCI_ENDPOINT_TEST_CHECKSUM

  8. PCI_ENDPOINT_TEST_IRQ_TYPE

  9. PCI_ENDPOINT_TEST_IRQ_NUMBER

  • PCI_ENDPOINT_TEST_MAGIC

このレジスタはBAR0のテストに使用されます。既知のパターンをMAGICレジスタに書き込み、読み戻すことでBAR0の検証を行います。

  • PCI_ENDPOINT_TEST_COMMAND

このレジスタはホストドライバがエンドポイントデバイスに実行すべき機能を示すために使用されます。

ビットフィールド

説明

ビット0

レガシーリークを発生させる

ビット1

MSIリークを発生させる

ビット2

MSI-Xリークを発生させる

ビット3

読み込みコマンド（RCバッファからデータを読み込む）

ビット4

書き込みコマンド（RCバッファにデータを書き込む）

ビット5

コピー コマンド（1つのRCバッファから別のRCバッファにデータをコピー）

  • PCI_ENDPOINT_TEST_STATUS

このレジスタはPCIエンドポイントデバイスの状態を反映しています。

ビットフィールド

説明

ビット0

読み込み成功

ビット1

読み込み失敗

ビット2

書き込み成功

ビット3

書き込み失敗

ビット4

コピー成功

ビット5

コピー失敗

ビット6

リークが発生した

ビット7

ソースアドレスが無効

ビット8

宛先アドレスが無効です

  • PCI_ENDPOINT_TEST_SRC_ADDR

このレジスタはコピー/読み取りコマンド用のソースアドレス（RCバッファアドレス）を含みます。

  • PCI_ENDPOINT_TEST_DST_ADDR

このレジスタはコピー/書き込みコマンド用の宛先アドレス（RCバッファアドレス）を含みます。

  • PCI_ENDPOINT_TEST_IRQ_TYPE

このレジスタは、読み取り/書き込み/コピーおよび割込みを発生させる（Legacy/MSI）コマンドでトリガーされる割込みタイプ（Legacy/MSI）を含みます。

可能なタイプ:

Legacy

0

MSI

1

MSI-X

2

  • PCI_ENDPOINT_TEST_IRQ_NUMBER

このレジスタはトリガーされたID割込みを含みます

許容される値:

Legacy

0

MSI

[1 .. 32]

MSI-X

[1 .. 2048]
