メッセージダイジェストアルゴリズムの定義¶

これらのデータ構造は、crypto_register_ahash()、crypto_register_shash()、crypto_unregister_ahash() および crypto_unregister_shash() を通じて管理されるモジュール型メッセージダイジェストアルゴリズムの実装を定義しています。

struct hash_alg_common¶

メッセージダイジェストのプロパティを定義します

定義

struct hash_alg_common {
  unsigned int digestsize;
  unsigned int statesize;
  struct crypto_alg base;
};

メンバ

digestsize

変換結果のサイズ。このサイズのバッファが、final および finup に呼び出される際、結果のハッシュを保存するために必要です。さまざまな事前定義されたサイズについては、git grep _DIGEST_SIZE include/crypto を使用して include/crypto/ を検索してください。 final および finup calls, so they can store the resulting hash into it. For various predefined sizes, search include/crypto/ using git grep _DIGEST_SIZE include/crypto.

statesize

変換の部分状態用のブロックサイズ。このサイズのバッファが、export 関数に渡される必要があります。なぜなら、このバッファに変換の部分状態を保存するからです。一方、import は export function as it will save the partial state of the transformation into it. On the other side, the import このサイズのバッファから状態を読み込む関数です。

base

暗号アルゴリズムのデータ構造の開始。crypto_algの共通データ構造はすべての暗号に共通する情報を含みます。hash_alg_commonデータ構造は現在、ハッシュ固有の情報を追加しています。

struct ahash_alg¶

非同期メッセージディジェストの定義

定義

struct ahash_alg {
  int (*init)(struct ahash_request *req);
  int (*update)(struct ahash_request *req);
  int (*final)(struct ahash_request *req);
  int (*finup)(struct ahash_request *req);
  int (*digest)(struct ahash_request *req);
  int (*export)(struct ahash_request *req, void *out);
  int (*import)(struct ahash_request *req, const void *in);
  int (*setkey)(struct crypto_ahash *tfm, const u8 *key, unsigned int keylen);
  int (*init_tfm)(struct crypto_ahash *tfm);
  void (*exit_tfm)(struct crypto_ahash *tfm);
  struct hash_alg_common halg;
};

メンバ

init

[必須] 変換コンテキストを初期化します。これはHASH変換の開始時に状態を初期化するためのものです。この処理では内部構造体が埋め込まれ、変換全体の期間にわたって使用されます。この時点ではデータ処理は行われません。ドライバ実装コードはreq->resultを使用してはなりません。

update

[必須] ドライバーにデータをプッシュします。この関数は上位レイヤーからブロック単位のデータをドライバーにプッシュし、ドライバーがハードウェアに適宜渡すようにします。この関数はHASH変換を終了して最終メッセージディジェストを計算してはなりません。この関数は変換コンテキストを変更してはなりません（この関数は同じ変換オブジェクトと並行して呼び出される可能性があるため）。データ処理はこの時点ですynchronous [SHASH] または asynchronous [AHASH] で行われます。ドライバはreq->resultを使用してはなりません。

final

[必須] ドライバーから結果を取得します。この関数は変換を終了し、ドライバーから結果ハッシュを取得して上位レイヤーに戻します。この時点ではデータ処理は行われません（ハードウェアが変換を完了させる必要がある場合を除く）。

finup

[オプション] 組み合わせ 更新 および final．この関数は、順番に実行される呼び出しを組み合わせたものです。 更新 および final 呼び出しが順番に実行される。一部のハードウェアは 更新 および final 別に、このコールバックは、このようなハードウェアが少なくともIPsecで使用可能になるように追加されました。データ処理はこの時点で同期的に[SHASH]または非同期的に[AHASH]行われます。

digest

組み合わせ init および 更新 および finalこの関数は、一連の操作全体として動作します。 init, 更新 および final 順に実行されるように設計されています。これは、 finupハードウェアが連続的な処理を実行できない場合のために追加されました。ただし、ハードウェアは一回の実行で全体の変換を完了する必要があります。 finupデータ処理はこの時点で同期的に[SHASH]または非同期的に[AHASH]行われます。

export

変換の部分的な状態をエクスポートします。この関数は、進行中の変換の全体の状態を提供されたデータブロックにダンプし、後で再び読み込むことができます。 import これは、特定の量のデータを処理した後に変換の部分的な結果を保存し、後で複数回再利用する場合に役立ちます。この時点でデータ処理は行われません。ドライバはreq->resultを使用してはなりません。

import

変換の部分的な状態をインポートします。この関数は、提供されたデータブロックから進行中の変換の全体の状態を読み込み、その後の変換を継続します。この時点でデータ処理は行われません。ドライバはreq->resultを使用してはなりません。

setkey

ハッシュアルゴリズムで使用されるオプションの鍵を設定します。この関数は、上位レイヤーからハッシュアルゴリズムに使用されるオプションの鍵をドライバに渡すためのものです。この関数は、変換コンテキストに鍵を保存するか、またはハードウェアに直接プログラミングするかを選択できます。前者の場合、変換オブジェクトの存在期間中に.setkey()が複数回呼ばれる可能性があるため、適切なタイミングでハードウェアに鍵をプログラミングする必要があります。すべてのハッシュアルゴリズムがこの関数を実装するわけではありません。これは鍵付きメッセージダイジェストにのみ必要です。SHAx/MDx/CRCxはこの関数を実装しません。HMAC(MDx)/HMAC(SHAx)/CMAC(AES)はこの関数を実装します。この関数は、他のどの関数よりも前に呼ばなければなりません。 init, 更新, final, finup, digest が呼ばれます。この時点でデータ処理は行われません。

init_tfm

暗号化変換オブジェクトを初期化します。この関数は、変換コンテキストが割り当てられた直後にのみ1回呼び出されます。暗号化ハードウェアに特別な要件がある場合、この関数はその要件を確認し、ソフトウェアのフォールバックを実装する必要があります。

exit_tfm

暗号化変換オブジェクトをデイジニライズします。これは init_tfmの対応処理で、に設定されたさまざまな変更を解除します init_tfm.

halg

参照 struct hash_alg_common
