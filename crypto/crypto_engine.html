暗号エンジン¶

概要¶

CE API は暗号化キュー管理インターフェースです。

要件¶

your_tfm_ctx という transform コンテキストの開始位置に crypto_engine 構造体を配置する必要があります。

struct your_tfm_ctx {
        struct crypto_engine engine;
        ...
};

エンジンは crypto_async_request の形式で非同期リクエストのみを管理します。その下位リクエストタイプは把握できず、transform 構造体のみにアクセス可能です。container_of を使ってコンテキストにアクセスすることはできません。さらに、エンジンは your という構造体について何も知らないため、既知のメンバが開始位置に配置されていることをエンジンは前提としています。struct your_tfm_ctx「」 struct crypto_engine のメンバが開始位置に配置されていることをエンジンは前提としています。

操作の順序¶

struct crypto_engine を取得するには、 crypto_engine_alloc_init()で初期化します。 crypto_engine_start()処理が終わったら、 crypto_engine_stop() でエンジンを停止し、 crypto_engine_exit().

でエンジンを破棄する必要があります。リクエストを転送する前に、enginectx コンテキストを以下の関数で埋めることを義務付けられます：

  • prepare_crypt_hardwareすべての準備関数が呼び出される前に行う必要があります。

  • unprepare_crypt_hardwareすべての解除関数が呼び出された後に呼び出す必要があります。

  • prepare_cipher_request/prepare_hash_requestそれぞれのリクエストが実行される前に呼び出されます。必要な処理や準備作業があればここで行います。

  • unprepare_cipher_request/unprepare_hash_requestそれぞれのリクエストが処理された後に呼び出されます。準備関数で行った処理をクリーンアップ/元に戻します。

  • cipher_one_request/hash_one_request現在のリクエストを処理します。

これらの関数は、受信したリクエストに関連する crypto_async_request 構造体にアクセスします。元のリクエストを取得するには、以下の関数を使用します：

container_of(areq, struct yourrequesttype_request, base);

ドライバが crypto_request を受信した際には、以下の関数のいずれかを使ってエンジンに転送する必要があります：

  • crypto_transfer_aead_request_to_engine()

  • crypto_transfer_akcipher_request_to_engine()

  • crypto_transfer_hash_request_to_engine()

  • crypto_transfer_skcipher_request_to_engine()

リクエスト処理終了後に、以下の関数のいずれかを呼び出す必要があります：

  • crypto_finalize_aead_request()

  • crypto_finalize_akcipher_request()

  • crypto_finalize_hash_request()

  • crypto_finalize_skcipher_request()
