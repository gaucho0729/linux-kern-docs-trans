認証付き暗号化（AEAD）アルゴリズムの定義¶

AEAD 暗号 API は、タイプ CRYPTO_ALG_TYPE_AEAD（/proc/crypto で「aead」としてリストされている）の暗号タイプと併用されます。

この種の暗号化の代表的な例は GCM と CCM です。ただし、カーネルはこれらの他にも AEAD 暗号をサポートしており、以下に示す暗号文字列で定義されています:

authenc（鍵付きメッセージハッシュ、ブロック暗号）

例: authenc（hmac（sha256）, cbc（aes））

対称鍵暗号操作用に提供された例コードはここでも適用されます。もちろんすべての skcipher シンボルは the に交換する必要があります aead 次のセクションで説明するpendants（対応する項目）に適用されます。さらに、AEAD操作では、暗号化または復号操作を行う前に、関連データメモリのポインタを設定するためにaead_request_set_ad関数を使用する必要があります。暗号化の場合、関連データメモリは暗号化操作中に埋められます。復号の場合、関連データメモリには復号データの整合性を確認するために使用されるデータが含まれている必要があります。非同期ブロック暗号操作との違いとして、呼び出し元はcrypto_aead_decryptの-EBADMSGエラーを明示的に確認する必要があります。このエラーは認証エラーを示し、つまりメッセージの整合性の破損を意味します。要するに、この-EBADMSGエラー コードは、標準的なブロックチェインモードよりもAEAD暗号が持つ主要な利点です。

メモリ構造:

ソースscatterlistには、関連データ || 平文または暗号文の連結が必要です。

宛先scatterlistは同じレイアウトですが、暗号化（resp. 復号）中に平文（resp. 暗号文）は認証タグのサイズ分成長（resp. 減少）します。

インプレースの暗号化/復号は、ソースと宛先の両方に同じscatterlistポインタを使用することで有効になります。

オフプレースの場合でも、関連データ用に宛先に空間を確保する必要があります（実際に書き込まれません）。これにより、インプレースとオフプレースのケースがより一貫しています。また、「宛先」関連データは「ソース」関連データとアリアス（同一のメモリ領域）を許可します。

他のscatterlist暗号APIと同様に、使用中のscatterlist内のゼロ長さのscatterlist要素は許可されません。したがって、関連データがない場合、最初の要素は平文/暗号文を指さなければなりません。

IPsecの要件を満たすために、rfc4106、rfc4309、rfc4543、およびrfc7539esp暗号には特別な仕様が適用されます。これらの暗号では、関連データバッファの最終の‘ivsize’バイトにIVの二重のコピーを含める必要があります。これは、関連データバッファに渡されたコピーとは別に必要です。 aead_request_set_crypt()これらの2つのIVコピーは異なってはなりません。同一アルゴリズムの異なる実装では、この場合の挙動が異なる可能性があります。注意点として、アルゴリズムが実際にIVを関連データとして扱わない場合もありますが、それでも aead_request_set_ad() に渡される長さには含まれるべきです。

int crypto_aead_decrypt(struct aead_request *req)¶

暗号文を復号化する

パラメータ

struct aead_request *req

暗号操作に必要なすべての情報を保持するaead_requestハンドルへの参照

説明

aead_requestハンドルを使用して暗号文データを復号化します。このデータ構造とデータの埋め方については、aead_request_*関数で説明します。

重要な注意点 呼び出し元は、暗号文をタグの後に連結する必要があります。

認証データ/タグは、crypto_aead_setauthsize呼び出しで定義されたサイズでなければなりません。

戻り値

0を返します（暗号化操作が成功した場合）；-EBADMSG：AEAD

暗号化操作は復号処理中にデータの認証を行います。したがって、暗号文の認証に失敗した場合（つまり、暗号文または関連データの整合性が破られた場合）、このエラーを返します。エラーが発生した場合、< 0を返します。

非同期AEADリクエストハンドル¶

aead_requestデータ構造には、AEAD暗号化操作に必要なすべてのポインタが含まれています。これは暗号ハンドル（複数のaead_requestインスタンスで使用可能）、平文と暗号文へのポインタ、非同期コールバック関数などです。これは、aead_request_* API呼び出しに使用されるハンドルとして、crypto_aead_* API呼び出しの暗号ハンドルと同様の役割を果たします。
