ブロック暗号アルゴリズムの定義¶

これらのデータ構造は、crypto_register_alg() および crypto_unregister_alg() を通じて管理されるモジュール型暗号アルゴリズムの実装を定義します。

struct cipher_alg¶

単一ブロック対称暗号の定義

定義

struct cipher_alg {
  unsigned int cia_min_keysize;
  unsigned int cia_max_keysize;
  int (*cia_setkey)(struct crypto_tfm *tfm, const u8 *key, unsigned int keylen);
  void (*cia_encrypt)(struct crypto_tfm *tfm, u8 *dst, const u8 *src);
  void (*cia_decrypt)(struct crypto_tfm *tfm, u8 *dst, const u8 *src);
};

メンバ

cia_min_keysize

変換にサポートされる最小の鍵サイズ。これは、この変換アルゴリズムがサポートする最小の鍵長です。これはハードウェア固有ではなく、事前に定義された値のいずれかに設定しなければなりません。このフィールドの可能な値は、git grep 「_MIN_KEY_SIZE」 include/crypto/ を参照してください

cia_max_keysize

変換にサポートされる最大の鍵サイズ。これは、この変換アルゴリズムがサポートする最大の鍵長です。これはハードウェア固有ではなく、事前に定義された値のいずれかに設定しなければなりません。このフィールドの可能な値は、git grep 「_MAX_KEY_SIZE」 include/crypto/ を参照してください

cia_setkey

変換の鍵を設定します。この関数は、供給された鍵をハードウェアにプログラミングするか、変換コンテキストに鍵を保存して後でプログラミングするためのものです。注意として、この関数は変換コンテキストを変更します。この関数は変換オブジェクトが存在する間、複数回呼び出される可能性があるため、鍵がハードウェアに正しく再プログラミングされるようにする必要があります。この関数はまた、鍵長の有効性を確認する責任も持ちます。

cia_encrypt

1ブロックのデータを暗号化します。この関数は、1ブロックのデータを暗号化するために使用され、これは cra_blocksize これは常にフルサイズで動作します。 cra_blocksize 小さいサイズのブロックを暗号化することはできません。したがって、提供されたバッファも少なくとも cra_blocksize サイズでなければなりません。入力と出力のバッファは常に cra_alignmaskに合わせていない場合、crypto APIはバッファを再配置します。再配置とは、新しいバッファを割り当て、データを新しいバッファにコピーし、処理を新しいバッファで行い、その後データを元のバッファに戻し、最後に新しいバッファを解放するプロセスです。 cra_alignmaskソフトウェアのフォールバックがcra_init呼び出しで設定されている場合、この関数はアルゴリズムがすべての鍵サイズをサポートしない場合、フォールバックを使用する可能性があります。 鍵が変換コンテキストに保存されている場合、この関数でハードウェアに再プログラミングされる可能性があります。 この関数は変換コンテキストを変更してはなりません。なぜなら、この関数は同じ変換オブジェクトと並行して呼び出される可能性があるからです。

cia_decrypt

特定のブロックを復号化します。これはcia_encryptの逆操作であり、条件は完全に同じです。 cia_encrypt、および条件は完全に同じです。

説明

すべてのフィールドは必須であり、入力が必要です。

struct compress_alg {

対称鍵暗号API¶

対称鍵暗号APIは、/proc/cryptoにリストされている「skcipher」として表示されるCRYPTO_ALG_TYPE_SKCIPHER型の暗号と併用されます。

非同期暗号操作では、暗号リクエストの関数呼び出しは操作完了前に即座に返ります。暗号リクエストは別スレッドとしてスケジューラによってCPUをロードバランシングします。カーネル暗号APIがリクエスト完了を呼び出し元に通知するためには、呼び出し元がコールバック関数を提供する必要があります。この関数はリクエスト完了時に暗号ハンドルとともに呼び出されます。

非同期操作をサポートするためには、暗号ハンドル以外の情報もカーネル暗号APIに提供する必要があります。その情報はskcipher_requestデータ構造体に記述することで提供されます。

対称鍵暗号APIにおいて、状態はtfm暗号ハンドルで維持されます。1つのtfmは複数の呼び出しや並列処理で使用可能です。非同期ブロック暗号呼び出しでは、呼び出し元だけが使用するコンテキストデータを、暗号リクエストに使用されるIVとともにリクエストデータ構造体で参照できます。このような状態情報の維持は、暗号ドライバ実装者にとって重要です。なぜなら、暗号処理完了時にコールバック関数を呼び出す際、複数の処理を並列で呼び出した場合、終了した処理に関する情報が必要になるからです。この状態情報はカーネル暗号APIでは使用されません。

単一ブロック暗号API¶

単一ブロック暗号APIは、/proc/cryptoにリストされている「cipher」として表示されるCRYPTO_ALG_TYPE_CIPHER型の暗号に使用されます。

単一ブロック暗号API呼び出しを使用すると、基本的な暗号プリミティブ操作を実装できます。これらの暗号プリミティブは、ブロックチェーン操作やIV処理を含みません。

この単一ブロック暗号APIの目的は、1ブロックずつ暗号操作を実行するテンプレートやその他の概念の実装をサポートすることです。テンプレートは、暗号プリミティブをブロック単位で呼び出し、これらの暗号操作の入力または出力データを処理します。

int crypto_cipher_setkey(struct crypto_cipher *tfm, const u8 *key, unsigned int keylen)¶

暗号の鍵を設定します

パラメータ

暗号ハンドル

const u8 *key

鍵を保持するバッファ

unsigned int keylen

鍵の長さ（バイト数）

説明

呼び出し元が提供した鍵が、暗号ハンドルで参照される単一ブロック暗号に設定されます

注意、鍵の長さは暗号タイプを決定します。多くのブロック暗号は、鍵サイズに応じて異なる暗号モードを実装しています。例えばAES-128 vs AES-192 vs AES-256など。AES暗号ハンドルに16バイトの鍵を提供すると、AES-128が実行されます。

戻り値

鍵の設定が成功した場合は0；エラーが発生した場合は<0
