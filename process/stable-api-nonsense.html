Linuxカーネルドライバインターフェース¶

(すべての質問に答え、さらに詳しい情報も)

Greg Kroah-Hartman <greg@kroah.com>

これは、なぜLinuxが バイナリーカーネルインターフェースや安定したカーネルインターフェースを持っていない.

注意

この記事は、カーネル内部のインターフェースについて説明しています カーネル内部 インターフェースであり、カーネルとユーザー空間のインターフェースではありません。

カーネルとユーザー空間のインターフェースは、アプリケーションプログラムが使用するシステムコールインターフェースです。このインターフェースは 非常に 時間とともに安定しており、壊れることはありません。以前の0.9系カーネルで作成された古いプログラムも、最新の2.6系カーネルで依然として正常に動作します。ユーザーとアプリケーションプログラマが信頼できるのはこのインターフェースです。

実行要約¶

あなたは安定したカーネルインターフェースを望んでいると思っていても、実際には望んでいないことに気づいていません。望んでいるのは安定して動作するドライバであり、それが得られるのはドライバがメインのカーネルツリーに含まれている場合だけです。ドライバがメインのカーネルツリーに含まれていると、多くの他のメリットも得られ、それがLinuxを強力で安定し、成熟したオペレーティングシステムに成長させた理由です。

はじめに¶

カーネル内部のインターフェースが変化することを気にする必要があるのは、少数のドライバを開発したい人だけです。世界の大多数の人々は、このインターフェースに気づいていないし、気にする必要もありません。

まず、私は any クローズドソース、ヒドンソース、バイナリーブロブ、ソースラッパー、またはGPLライセンスでソースコードを公開していないカーネルドライバを記述する他の用語についての法的問題は扱いません。法的質問がある場合は弁護士に相談してください。私はプログラマであり、技術的な問題についてのみ説明します（法的問題を軽視しているわけではありません。実際には存在し、常に注意が必要です）。

したがって、ここでの主なトピックはバイナリーカーネルインターフェースと安定したカーネルソースインターフェースです。これらはお互いに依存していますが、まずはバイナリーアプローチについて説明しておきます。

バイナリーカーネルインターフェース¶

カーネルに安定したカーネルソースインターフェースがあったと仮定すると、バイナリーアクセスインターフェースも自然に発生すると思いませんか？違います。以下のLinuxカーネルに関する事実を考慮してください：

  • 使用するCコンパイラのバージョンによって、カーネルのデータ構造に含まれる構造体のアライメントが異なり、関数の実装方法も異なる場合があります（関数をインラインで展開するかしないかなど）。個々の関数の構成はそれほど重要ではありませんが、データ構造のパディングの違いは非常に重要です。

  • カーネルのビルドオプションを選択する方法によって、カーネルが前提とするさまざまな要素が異なります：

    • 異なる構造体には異なるフィールドが含まれる場合があります

    • 一部の関数はまったく実装されない場合があります（例：非SMPビルドでは一部のロックがコンパイル時に無視されるなど）。

    • ビルドオプションによって、カーネル内のメモリのアライメント方法が異なります。

  • Linuxはさまざまなプロセッサアーキテクチャで動作します。あるアーキテクチャで作成されたバイナリドライバが、別のアーキテクチャで正しく動作する可能性はほぼありません。

これらの問題の多くは、特定のカーネル構成でモジュールをコンパイルすることで解決できます。カーネルがビルドされた際の同じCコンパイラを使用すれば十分です。特定のLinuxディストリビューションの特定バージョン用のモジュールを提供する場合にこれで十分ですが、これを複数のLinuxディストリビューションとそのサポートバージョンごとに繰り返すと、すぐにさまざまなビルドオプションの組み合わせが発生します。さらに、各Linuxディストリビューションのリリースには複数のカーネルが含まれており、それぞれが異なるハードウェア（プロセッサタイプやオプション）に最適化されています。そのため、単一のリリースでも複数のモジュールバージョンを用意する必要があります。

信じてください、このようなリリースをサポートしようとすると時間が経つにつれて精神的に追い詰められることになります。私は長期間前からこの現実を学んできました…

安定したカーネルソースインターフェース¶

Linuxカーネルドライバをメインのカーネルツリーにない状態で長期間維持しようとする人々にとっては、この話題ははるかに「不安定」です。

Linuxカーネルの開発は常に高速で継続しており、停止することはありません。そのため、カーネル開発者は現在のインターフェースにバグを見つけたり、より効率的な方法を模索したりします。そうした場合、現在のインターフェースを改善して修正します。この修正を行う際には、関数名が変化したり、構造体が拡大・縮小したり、関数パラメータが再設計されることがあります。このような変更が発生した場合、カーネル内でのこのインターフェースのすべての使用箇所を同時に修正することで、すべてが正常に動作し続けるようにしています。

このような変更の具体例として、内蔵USBインターフェースはこのサブシステムのライフサイクルを通じて少なくとも3回の再設計を経ています。これらの再設計は、以下のいくつかの問題を解決するために行われました：

  • データストリームの同期型モデルから非同期型モデルへの変更。これにより、複数のドライバの複雑さが軽減され、すべてのUSBドライバのスループットが向上し、現在はほぼすべてのUSBデバイスが最大速度で動作できるようになりました。

  • USBドライバがUSBコアからデータパケットを割り当てる方法が変更され、すべてのドライバがUSBコアにより多くの情報を提供する必要があるようになりました。これにより、いくつかのドキュメントされたデッドロック問題が修正されました。

これは、クローズドソースのオペレーティングシステムが時間とともに古いUSBインターフェースを維持せざるを得なかったことと大きく異なります。これにより、新規開発者があえて古いインターフェースを使用して不適切な方法で操作を行い、オペレーティングシステムの安定性に悪影響を及ぼす可能性があります。

これらのケースにおいても、すべての開発者がこれらの変更が重要であり、実施すべきものであると合意しました。実施に際しては、比較的少ない苦労で済みました。もしLinuxが安定したソースインターフェースを維持する必要があった場合、新しいインターフェースが作成され、古いインターフェースは維持される必要があり、USB開発者に追加の作業を課すことになります。しかし、すべてのLinuxのUSB開発者は自分の時間を使って作業を行っているため、無償で追加の作業を求めるのは現実的ではありません。

Linuxにおいてもセキュリティの問題は非常に重要です。セキュリティ上の問題が発覚した場合、その修正は非常に短時間で行われます。このような修正により、内部のカーネルインターフェースが再設計されることが何度かあり、セキュリティ問題が再発しないように対策を講じています。このような変更が行われた場合、そのインターフェースを使用しているすべてのドライバも同時に修正され、セキュリティ問題が修正され今後再発しないことを保証しています。内部インターフェースが変更できない場合、このようなセキュリティ問題を修正し、再発を防ぐことは不可能です。

カーネルインターフェースは時間とともに整理されます。現在のインターフェースを使用していない場合、そのインターフェースは削除されます。これにより、カーネルが可能な限り小さく保たれ、すべての潜在的なインターフェースが可能な限りテストされるようになります（未使用のインターフェースは妥当性をテストするのがほぼ不可能です）。

行うべきこと¶

したがって、メインカーネルツリーに含まれていないLinuxカーネルドライバを扱う開発者として、どのような対応を取るべきでしょうか？各カーネルバージョンごとに各ディストリビューション向けにバイナリドライバをリリースするというのは地獄のような作業であり、常に変化するカーネルインターフェースに追いつくのも大変な仕事です。

簡単です。あなたのドライバをメインカーネルツリーに組み込んでください（ここで話しているのはGPL互換ライセンスで公開されるドライバです。あなたのコードがこのカテゴリに該当しない場合、ラッキーなことに、あなたは自分で頑張らないといけません、ライセンスの対象外なコードを扱っている場合）。ドライバがツリーに含まれている場合、カーネルインターフェースが変更されたとしても、その変更を実施した開発者がドライバを修正してくれます。これにより、あなたのドライバが常にビルド可能であり、時間とともに動作を維持できるようになります。あなたの努力を極めて少ない状態で実現できます。

あなたのドライバがメインカーネルツリーに含まれることの非常に良い副作用は以下の通りです：

  • ドライバの品質が向上し、元の開発者にとってのメンテナンスコストが低下します。

  • 他の開発者があなたのドライバに機能を追加します。

  • 他の人があなたのドライバのバグを発見して修正します。

  • 他の人があなたのドライバのチューニングの余地を発見します。

  • 外部インターフェースの変更が求められる場合、他の人があなたのドライバを更新します。

  • ドライバはすべてのLinuxディストリビューションに自動的に配布されます。ディストリビューションに追加してもらう必要はありません。

Linuxは他のオペレーティングシステムよりも多く異なるデバイスを標準でサポートし、さらに多くのプロセッサアーキテクチャでこれらのデバイスをサポートするため、この確立された開発モデルは何かしら正しいことをやっているはずだ:)
