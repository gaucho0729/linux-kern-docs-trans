カーネルをコンパイルするための最小限の要件¶

はじめに¶

このドキュメントは、4.x カーネルを動作させるために必要なソフトウェアの最小限のレベルの一覧を提供することを目的としています。

このドキュメントは、私が2.0.x カーネル用に作成した「Changes」ファイルに基づいており、そのファイルと同じ貢献者（Jared Mauch、Axel Boldt、Alessandro Sigala、そしてネットワーク全体にわたる無数のユーザー）に名誉を負っています。

現在の最小限の要件¶

アップグレードを実施する前に 少なくとも これらのソフトウェアのバージョンを確認してください。バグに遭遇したと誤って考える前に、現在のバージョンが分からない場合は推奨されるコマンドで確認できます。

また、このリストはすでに機能的にLinuxカーネルを実行していることを前提としています。すべてのツールが必要なわけではありませんし、たとえばPCカードハードウェアを持っていない場合、pcmciautilsに気にする必要はありません。

カーネルのコンパイル¶

GCC¶

gccのバージョン要件は、コンピュータ内のCPUのタイプによって異なります

Clang/LLVM (オプション)¶

clangおよびLLVMユーティリティの最新公式リリース（ releases.llvm.org）はカーネルの構築にサポートされています。古いリリースは動作保証されておらず、古いバージョンをサポートするためにカーネルからワークアラウンドを削除する可能性があります。追加のドキュメントについては Clang/LLVMでLinuxをビルドする.

make¶

カーネルを構築するには、GNU make 3.81以降が必要です

binutils¶

カーネルを構築には、binutils 2.23以降が必要です

pkg-config¶

4.18以降のビルドシステムは、インストール済みのkconfigツールの確認や'make {g,x}config'でのフラグ設定の決定にpkg-configを必要とします。以前はpkg-configを使用していましたが、検証やドキュメント化されていませんでした

flex¶

Linux 4.16以降、ビルドシステムはビルド中にレキシカルアナライザを生成します。これにはflex 2.5.35以降が必要です

bison¶

Linux 4.16以降、ビルドシステムはビルド中にパーサーを生成します。これにはbison 2.0以降が必要です

perl¶

perl 5と以下のモジュールが必要です Getopt::Long, Getopt::Std, File::Basename, and File::Find カーネルを構築するために

BC¶

3.10バージョン以上のカーネルをビルドするにはbcが必要です

OpenSSL¶

モジュール署名および外部証明書の処理にはOpenSSLプログラムと暗号ライブラリを使用し、鍵の生成と署名生成を行います

モジュール署名が有効な場合、3.7バージョン以上のカーネルをビルドするにはopensslが必要です。また4.3バージョン以上のカーネルをビルドするにはopenssl開発パッケージも必要です

システムユーティリティ¶

アーキテクチャ変更¶

DevFSはudev（https://www.kernel.org/pub/linux/utils/kernel/hotplug/)

32ビットUIDサポートが実装されました。楽しんでください！

Linuxドキュメンテーションの関数については、ソースコード内の定義に近い位置に特別フォーマットされたコメントでインラインドキュメンテーションへ移行しています。これらのコメントはDocumentation/ディレクトリ内のReSTファイルと組み合わせることで、PostScript、HTML、LaTex、ePUB、PDFなどの形式に変換可能な豊富なドキュメンテーションを作成できます。ReST形式から任意の形式に変換するにはSphinxが必要です

Util-linux¶

新しいutil-linuxは fdisk 大容量ディスクへのサポート、マウント用の新オプション、サポートするパーティションタイプの認識、2.4カーネル対応のfdformat、などの機能を提供しています。アップグレードすることをお勧めします

Ksymoops¶

想定外のことが起こりカーネルがoops（異常終了）した場合、ksymoopsツールでデコードする必要がありますが、ほとんどの場合必要ありません。カーネルを CONFIG_KALLSYMS ビルドすることで読みやすいダンプを生成でき、ksymoopsよりも優れた出力結果が得られます。ただし、何らかの理由で CONFIG_KALLSYMS でビルドされていない場合で、そのオプションで Oops を再現・再構築する手段がない場合は、ksymoopsでもその Oops をデコードできます

Mkinitrd¶

ファイルツリーのレイアウト変更により /lib/modules mkinitrdのアップグレードも必要です

E2fsprogs¶

最新版の e2fsprogs fsckとdebugfsのいくつかのバグを修正しています。明らかにアップグレードすることをお勧めします

JFSutils¶

以下の jfsutils パッケージにはファイルシステムのユーティリティが含まれています。利用可能なユーティリティは以下の通りです：

  • fsck.jfs - トランザクションログの再実行を開始し、JFS形式のパーティションをチェックおよび修復します

  • mkfs.jfs - JFS形式のパーティションを作成します

  • このパッケージには他のファイルシステムユーティリティも含まれています

Reiserfsprogs¶

reiserfs-3.6.x（Linuxカーネル2.4.x）にはreiserfsprogsパッケージを使用してください。これは統合パッケージで、 mkreiserfs, resize_reiserfs, debugreiserfs および reiserfsckの作動するバージョンを含んでいます。これらのユーティリティはi386およびalphaプラットフォームの両方で動作します

Xfsprogs¶

最新版の xfsprogs 含む mkfs.xfs, xfs_db内のコールバック数を示し、 xfs_repair XFSファイルシステム用のユーティリティ（他にもあります）です。アーキテクチャに依存せず、2.0.0以降のバージョンであれば、このXFSカーネルコード（2.6.0以降が推奨されます）と正しく動作します（一部の重要な改善が含まれるため）。

PCMCIAutils¶

PCMCIAutilsは、システム起動時にPCMCIAソケットを適切に設定し、カーネルがモジュール化されておりホットプラグサブシステムが使用されている場合、16ビットPCMCIAデバイス用の適切なモジュールをロードします。 pcmcia-cs置き換えています。システム起動時にPCMCIAソケットを正しく設定し、カーネルがモジュール化されておりホットプラグサブシステムが使用されている場合、16ビットPCMCIAデバイス用の適切なモジュールをロードします。

Quota-tools¶

新しいバージョン2のクォータ形式を使用するには、32ビットのuidとgidのサポートが必要です。Quota-toolsのバージョン3.07以降はこのサポートを備えています。上記の表から推奨バージョンまたは新しいバージョンを使用してください。

Intel IA32マイクロコード¶

Intel IA32マイクロコードの更新を可能にするドライバが追加されました。これは通常の（misc）キャラクタデバイスとしてアクセス可能です。udevを使用していない場合は、以下の手順が必要かもしれません：

mkdir /dev/cpu
mknod /dev/cpu/microcode c 10 184
chmod 0644 /dev/cpu/microcode

root権限で実行する必要があります。また、この機能を活用するには、ユーザー空間のmicrocode_ctlユーティリティを取得することもおすすめします。

udev¶

udev は、ユーザースペースのアプリケーションで、 /dev を動的にのみ実際に存在するデバイスのエントリで埋め込みます。 udev devfsの基本的な機能を置き換えていますが、デバイスの永続的なデバイス名の割り当てを可能にしています。

FUSE¶

libfuse 2.4.0以降が必要です。絶対最低バージョンは2.3.0ですが、マウントオプション direct_io および kernel_cache は動作しません。

ネットワーキング¶

一般的な変更点¶

高度なネットワーク設定が必要な場合は、ip-route2からネットワークツールを使用することを検討してください。

パケットフィルタ / NAT¶

パケットフィルタリングおよびNATコードは、以前の2.4.xカーネルシリーズ（iptables）と同じツールを使用します。2.2.xスタイルのipchainsや2.0.xスタイルのipfwadmへの後方互換性モジュールも含まれています。

PPP¶

PPPドライバは、マルチリンクをサポートし、多様なメディアレイヤー上で動作できるように再構築されました。PPPを使用する場合は、pppdを少なくとも2.4.0以上にアップグレードしてください。

udevを使用していない場合、/dev/pppというデバイスファイルが必要です。これを生成するには、以下をroot権限で実行してください：

mknod /dev/ppp c 108 0

root権限で実行してください。

NFS-utils¶

古い（2.4および以前）カーネルでは、NFSサーバーがNFS経由でファイルにアクセスできるクライアントについて情報を把握する必要があります。この情報は、クライアントがファイルシステムをマウントするときに mountd で提供されるか、 exportfs でシステム起動時に提供されます。exportfsは、アクティブなクライアントの情報を /var/lib/nfs/rmtab.

から取得します。このアプローチは非常に脆弱で、rmtabが正しいことを依存しており、常に正確に保つのは難しいです（特にフェールオーバーを実装する場合）。システムが正常に動作している場合でも、 rmtab は古いエントリが多数残り、それらが削除されないため問題があります。

現代のカーネルでは、未知のホストからのリクエストを受け取ったときにmountdに通知するオプションがあります。これにより、mountdがカーネルに適切なエクスポート情報を提供できるようになり、カーネルとmountdの依存関係が解除されます。 rmtab これにより、カーネルは現在アクティブなクライアントについてのみ情報を必要とします。

この新しい機能を有効にするには、以下の手順を実行する必要があります。

mount -t nfsd nfsd /proc/fs/nfsd

exportfsまたはmountdを実行する前に、インターネット全体からのアクセスをブロックするファイアウォールを設定することをお勧めします（可能であれば）。

mcelog¶

x86カーネルでは、mcelogユーティリティが必要です。マシンチェックイベントを処理し、ログに記録するためには、 CONFIG_X86_MCE が有効になっている必要があります。マシンチェックイベントはCPUが報告するエラーです。処理することをお勧めします。
