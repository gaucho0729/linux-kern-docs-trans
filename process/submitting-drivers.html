Linux Kernel用ドライバの提出¶

このドキュメントは、さまざまなカーネルツリーにデバイスドライバを提出する方法を説明することを目的としています。ビデオカードドライバに興味がある場合は、XFree86 (https://www.xfree86.org/) および/または X.Org (https://x.org/)に報告してください。

注意

このドキュメントは古くなり、近年ほとんどメンテナンスされていません。更新するか、あるいはむしろ削除する方が良いでしょう。ここに書かれている内容は、他の開発ドキュメントにすでに含まれています。

ああ、そしてXFree86への変更の提出は本当に推奨しないよ:)

また、 パッチの送信: コードをカーネルに取り込むためのエッセンシャルガイド ドキュメントに記載されています。

デバイス番号の割り当て¶

ブロックデバイスおよびキャラクターデバイスのメジャーナンバーとマイナーナンバーは、Linuxの割り当て名と番号の権限機関（現在はTorben Mathiasen）によって割り当てられます。サイトは https://www.lanana.org/。これは、主流のカーネルに提出されないデバイスの番号の割り当てにも関与しています。参照してください Linux で割り当てられたデバイス（4.x 以降のバージョン） を参照してください。

割り当てられた番号を使わない場合、ドライバが提出されると、以前に顧客に配布した値とは異なる割り当てられた番号が割り当てられます。

ドライバをどのツリーに提出するか¶

Linux 2.0:

このカーネルツリーには新しいドライバの受け入れは行われません。

Linux 2.2:

このカーネルツリーには新しいドライバの受け入れは行われません。

Linux 2.4:

コードエリアに一般的なメンテナがいる場合は、カーネルファイル内のMAINTAINERSでリストされているメンテナに提出してください。メンテナから返信が得られなかったり、適切なメンテナが見つからない場合は、Willy Tarreau <w@1wt.eu>.

Linux 2.6 以降:

2.4と同じルールが適用されますが、APIの変更を追跡するにはlinux-kernelをフォローしてください。Linux 2.6+の提出の最終的な連絡先はAndrew Mortonです。

受理の基準¶

ライセンス:

コードはGNU一般公共ライセンスの下で私たちに公開される必要があります。BSDなどの他のコミュニティにも役立つ場合は複数のライセンスで公開することも可能です。GPL以外のライセンスを選択する場合は、カバーレターにライセンス選択の理由を記載してください。受け入れ可能なライセンスについては include/linux/module.h を参照してください。

著作権:

著作権者はGPLの使用に同意する必要があります。提出者と著作権者が同じ人物または法人であることが望ましいです。異なる場合は、GPLの使用を許可した人物または法人の名前を記載してください（著作権者の意図を確認する必要がある場合に備えて）。

インターフェース:

ドライバーが既存のインターフェースを使用し、同クラスの他のドライバーと同じように動作する場合、不要な新しいインターフェースを導入するよりも大幅に採用されやすくなります。LinuxとNTドライバーで共通のAPIを実装する必要がある場合は、ユーザー空間で実装してください。

コード:

Linuxのコードフォーマットスタイルを使用してください。詳しくは Linux Kernelのコーディングスタイルに記載されています。コードの一部が他のフォーマットが必要な場合（例：Windowsドライバーツールキットと共有する必要がある場合など）、それらを明確に分離し、その事実を記載してください。

移植性:

ポインタは常に32ビットではありません。すべてのコンピュータがリトルエンディアンではありません。すべてのユーザーが浮動小数点をサポートしているわけではありません。x86アセンブリをドライバー内でインラインで使用する際は慎重に検討してください。純粋なx86ドライバーは一般的ではありません。x86ハードウェアのみを使用する場合、移植性のテストは困難ですが、コードが簡単に移植可能になるようにするには簡単です。

明確性:

誰でもドライバーを修正できるようにする必要があります。これにより、あなたはパッチを受け取ることができ、バグレポートを受け取る必要がありません。ハードウェアの動作を意図的に複雑化したドライバーは、bitbucketに捨てられます。

PMサポート:

Linuxは多くのポータブル機器やデスクトップシステムで使用されているため、ドライバーはこのようなシステムで使用される可能性が高く、そのため基本的な電源管理をサポートする必要があります。システム全体のスリープと再起動の際の.suspendと.resumeメソッドを実装する必要があります。ドライバーがスリープと再起動を正しく処理しているか確認してください。確認できない場合は、少なくとも.resumeメソッドを-ENOSYS（"関数未実装"）エラーを返すように定義してください。また、ドライバーが何も処理していないときに消費電力を最小限に抑えるようにしてください。ドライバーのテスト手順については デバイスドライバでのスリープおよび再開サポートのテスト を参照してください。ドライバーに関連する電源管理の問題についての比較的完全な概要については デバイス電源管理の基礎.

制御:

一般的に、ドライバーの著者が積極的にメンテナンスを行っている場合、パッチは彼らにリダイレクトされます（極めて明確で確認の必要がない場合を除く）。ドライバーの連絡先および更新ポイントとしてあなたがなりたい場合は、コメント欄にその旨を明記し、MAINTAINERSファイルにドライバーのエントリを追加することをお勧めします。

採択を決定しない基準¶

ベンダー:

ハードウェアベンダーとしてドライバを維持することは、多くの場合良いことです。他の人がすでにツリーに安定したドライバを提供している場合、『我々がベンダーである』という理由で自分のドライバが選ばれるとは期待しないでください。理想的には、既存のドライバ作成者と協力して、完璧な単一のドライバを作成してください。

著者:

ドライバがどの大規模なLinux企業が書いたものであれ、あなたが書いたものであれ、違いはありません。誰もカーネルツリーに特別なアクセス権はありません。あなたにそう言っている人は、真実を語っていません。
