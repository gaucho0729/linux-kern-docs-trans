clang-format¶

clang-format C/C++/…コードをルールとヒューリスティクスに従ってフォーマットするツールです。他のツールと同様に完璧ではありませんし、すべてのケースをカバーするわけではありませんが、十分に役立つほどです。

clang-format いくつかの目的で使用できます:

  • コードブロックをカーネルスタイルに素早くフォーマットします。コードを移動する際や並べ替え・ソートする際に特に役立ちます。参照 clangformatreformat.

  • メンテナンス中のファイル、レビュー中のパッチ、差分などにスタイルの誤り、スペルミス、改善点を特定します。参照 clangformatreview.

  • コーディングスタイルのルールに従うのを助けるツールです。特に、カーネル開発に慣れていない人や、複数のプロジェクトで異なるスタイルを同時に扱っている人にとって有用です。

その構成ファイルは .clang-format カーネルツリーのルートにあります。その中に含まれるルールは、最も一般的なカーネルコーディングスタイルを近似しようと試みています。また、 Linux Kernelのコーディングスタイル 可能な限り従います。すべてのカーネルが同じスタイルを採用しているわけではありませんので、特定のサブシステムやフォルダに合わせてデフォルトを調整したい場合があります。そのために、別の .clang-format サブフォルダに別のファイルを書くことで、デフォルトを上書きできます。

このツール自体は、長い間、主要なLinuxディストリビューションのリポジトリに含まれています。以下を検索してください: clang-format あなたのリポジトリ内で。それ以外の場合、事前にビルドされたLLVM/clangバイナリをダウンロードするか、以下のソースコードからビルドできます:

https://releases.llvm.org/download.html

このツールについての詳細情報は以下をご参照ください:

https://clang.llvm.org/docs/ClangFormat.html

https://clang.llvm.org/docs/ClangFormatStyleOptions.html

ファイルとパッチのコーディングスタイルのレビュー¶

ツールをインラインモードで実行すると、コードスタイルの誤り、スペルミス、改善点を全体のサブシステム、フォルダ、または個別のファイル全体でレビューできます。

これを実行するには、以下のように実行できます:

# Make sure your working directory is clean!
clang-format -i kernel/*.[ch]

その後、git diffを見てください。

このようなdiffの行数を数えることは、構成ファイル内のスタイルオプションを改善/調整するのに役立ち、新しい clang-format 機能/バージョンをテストするのに役立ちます。

clang-format 統一diffを読み込むこともサポートしているため、パッチやgit diffを簡単にレビューできます。ドキュメンテーションは以下をご参照ください:

https://clang.llvm.org/docs/ClangFormat.html#script-for-patch-reformatting

特定のファイルの一部をフォーマットしないようにするには、以下のように実行できます: clang-format ファイルの一部をフォーマットしないようにするには、以下のように実行できます:

int formatted_code;
// clang-format off
    void    unformatted_code  ;
// clang-format on
void formatted_code_again;

コードブロックの再フォーマット¶

テキストエディタと統合することで、1回のキーボード操作で任意のコードブロック（選択範囲）を再フォーマットできます。これはコードを移動する際や、深くインデントされた複雑なコード、マルチラインマクロ（バックスラッシュの整列含む）など、特定の状況で特に役立ちます。

ツールが最適な結果を出さなかった場合でも、その後で調整は可能です。ただし、最初の近似値として非常に有用です。

多くのポピュラーなテキストエディタとの統合が可能です。vim、emacs、BBEdit、Visual Studioなど一部のエディタではビルトインでサポートがあります。インストール手順については、以下のセクションを参照してください：

https://clang.llvm.org/docs/ClangFormat.html

Atom、Eclipse、Sublime Text、Visual Studio Code、XCodeなどのエディタやIDEでは、即時利用可能なプラグインが見つかるでしょう。

この用途では、セカンダリ .clang-format を用いることを検討してください。いくつかのオプションを調整するためには、 clangformatextra.

サポートが不足しています¶

clang-format カーネルコードでよく見られるいくつかの機能に対するサポートが不足しています。これらは覚えやすく、ツールを定期的に使用するようになれば、すぐに回避または無視するようになります。

特に、以下の非常に一般的な項目を確認してください：

  • 1行ブロックの整列 #defines, e.g.:

    #define TRACING_MAP_BITS_DEFAULT       11
#define TRACING_MAP_BITS_MAX           17
#define TRACING_MAP_BITS_MIN           7

    vs.:

    #define TRACING_MAP_BITS_DEFAULT 11
#define TRACING_MAP_BITS_MAX 17
#define TRACING_MAP_BITS_MIN 7

  • 指定された初期化子の整列、例：

    static const struct file_operations uprobe_events_ops = {
        .owner          = THIS_MODULE,
        .open           = probes_open,
        .read           = seq_read,
        .llseek         = seq_lseek,
        .release        = seq_release,
        .write          = probes_write,
};

    vs.:

    static const struct file_operations uprobe_events_ops = {
        .owner = THIS_MODULE,
        .open = probes_open,
        .read = seq_read,
        .llseek = seq_lseek,
        .release = seq_release,
        .write = probes_write,
};

追加機能/オプション¶

スタイルオプションの一部は、出力結果と現在のコードの差異を最小限に抑えるため、設定ファイルではデフォルトで無効になっています。言い換えれば、差異をできるだけ小さくし、全体のファイルスタイルのレビュー、差分やパッチの確認を容易にするためです。

他のケース（例：特定のサブシステム/フォルダ/ファイル）では、カーネルスタイルが異なり、これらのオプションを有効にすることで、その場所のスタイルに近づける場合もあります。

例えば：

  • 割当の整列（AlignConsecutiveAssignments).

  • 宣言の整列（AlignConsecutiveDeclarations).

  • コメント内のテキストの再配置（ReflowComments).

  • ソート #includes (SortIncludes).

これらは通常、全体のファイルのフォーマットよりもブロックの再フォーマットに有用です。必要に応じて別の .clang-format ファイルを作成し、エディタ/IDEからそのファイルを使用することを検討してください。
