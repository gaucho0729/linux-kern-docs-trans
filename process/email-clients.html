Linux用メールクライアント情報¶

Git¶

最近では、ほとんどの開発者は git send-email 通常のメールクライアントではなく、このマニュアルページは非常に詳しいです。受信側では、メンテナは git am パッチを適用するために使用します。

が初めての方は、 git 最初のパッチを自分自身に送信してください。すべてのヘッダーを含むrawテキストとして保存し、 git am raw_email.txt を実行し、 git logで変更履歴を確認してください。それらが正常に動作する場合は、適切なメールリストにパッチを送信してください。

一般的な設定¶

Linuxカーネルのパッチは、メールで送信され、できればメール本文内にインラインテキストとして送信するのが望ましいです。一部のメンテナは添付ファイルを受け入れますが、その場合は添付ファイルのコンテンツタイプが text/plainである必要があります。ただし、添付ファイルは一般的に不推奨です。パッチの一部を引用する際の作業が難しくなるためです。

また、パッチや他のメールにもかかわらず、メール本文に plain text を使用することをお勧めします。 https://useplaintext.email は、お好みのメールクライアントを設定する方法や、まだお好みがなければ推奨されるメールクライアントの一覧を提供するのに役立ちます。

Linuxカーネルのパッチ用に使用されるメールクライアントは、パッチテキストを変更せずに送信する必要があります。たとえば、タブやスペースを削除したり変更したりしないようにしてください。行の先頭や末尾でも同様です。

パッチを format=flowedで送信しないでください。これは予期せぬ不要な改行を引き起こす可能性があります。

メールクライアントに自動的なワードラップをさせないでください。これによりパッチが破損する可能性もあります。

メールクライアントはテキストの文字セットエンコーディングを変更してはいけません。メールで送信されるパッチはASCIIまたはUTF-8エンコーディングのみを使用する必要があります。メールクライアントをUTF-8エンコーディングでメールを送信するように設定すると、いくつかの文字セットの問題を回避できます。

メールクライアントは「References:」または「In-Reply-To:」ヘッダーを生成し、維持して、メールスレッドが破損しないようにしてください。

コピー＆ペースト（または切り取り＆貼り付け）は、タブがスペースに変換されるため、通常パッチには機能しません。xclipboard、xclip、xcutselなどを使用する場合、動作する可能性がありますが、自分でテストするか、コピー＆ペーストを避けるのが最善です。

パッチを含むメールにPGP/GPG署名を使用しないでください。これは多くのスクリプトを破壊します（これは修正可能であるべきです）。

Linuxメールリストにパッチを送信する前に、自分自身にパッチを送信し、受信したメッセージを保存し、'patch'で正常に適用できるか確認することをお勧めします。

Kmail (GUI)¶

一部のユーザーはKmailをパッチ送信に成功しています。

HTMLでの作成をしないデフォルト設定は適切です。HTMLを有効にしないでください。

メールを編集する際には、オプションで"自動改行"をチェック解除してください。唯一のデメリットは、メール本文で入力したテキストが自動改行されず、パッチの前までに手動で改行する必要があります。これを回避する最も簡単な方法は、自動改行を有効にしてメールを編集し、下書きとして保存することです。下書きから再度開くと、自動改行が強制的に適用され、"自動改行"をチェック解除しても既存の改行が維持されます。

メールの下部に、一般的なパッチ区切り記号を挿入する前に、3本のハイフン（---).

その後、 メッセージ メニュー項目から選択 ファイル挿入 を選択し、パッチを選択してください。追加のメリットとして、メッセージ作成ツールバーのメニューをカスタマイズし、 ファイル挿入 アイコンがあります。

作成ウィンドウを十分に広くして、行が折り返さないようにしてください。KMail 1.13.5（KDE 4.5.4）以降では、作成ウィンドウで行が折り返されている場合、メールを送信する際に自動的に文字列の折り返しが行われます。オプションメニューで文字列の折り返しを無効にしても不十分です。したがって、あなたのパッチが非常に長い行を持っている場合、メールを送信する前に作成ウィンドウを非常に広くする必要があります。参照: https://bugs.kde.org/show_bug.cgi?id=174034

添付ファイルをGPGで署名して送信することは安全ですが、パッチの場合はインラインテキストの使用を推奨します。インラインテキストで挿入されたパッチをGPGで署名すると、7ビット符号化から抽出するのが困難になります。

インラインテキストとしてではなく、添付ファイルとしてパッチを送信する必要がある場合は、添付ファイルを右クリックして、 プロパティ、 自動表示を推奨 を選択して、添付ファイルをインライン表示にして読みやすさを向上させます。

インラインテキストとして送信されたパッチを保存する場合、メッセージリストパネルからパッチを含むメールを選択し、右クリックして をクリックしてを選択してください。メールが適切に作成されている場合、変更せずに全体をパッチとして使用できます。メールはユーザー専用で読み書き可能ですが、他の場所にコピーする場合はchmodでグループおよび世界読み取り可能に設定する必要があります。

Mutt (TUI)¶

多くのLinux開発者が使用していますので、動作は比較的安定しています。 muttそのため、動作は比較的安定しています。

Muttにはエディタが含まれていないため、使用するエディタは自動で改行しないように設定する必要があります。ほとんどのエディタには、ファイルの内容を変更せずに挿入するオプションがあります。 ファイル挿入 ファイルの内容を変更せずに挿入するオプションがあります。

使用するには vim Muttで以下のようにします：

set editor="vi"

xclipを使用する場合、以下のようにコマンドを入力してください：

:set paste

中ボタンまたはシフト＋インサートの前に、以下を使用してください：

:r filename

パッチをインラインで含める場合は、以下を使用してください。(a)ttachは不要です。 set paste.

また、以下を使用してパッチを生成することもできます： git format-patch その後、Muttを使用して送信してください：

$ mutt -H 0001-some-bug-fix.patch

設定オプション:

デフォルト設定で動作します。ただし、以下の設定をすることをお勧めします： send_charset に変更してください：

set send_charset="us-ascii:utf-8"

Muttは高度にカスタマイズ可能です。Gmail経由でパッチを送信するための最小限の設定は以下の通りです：

# .muttrc
# ================  IMAP ====================
set imap_user = 'yourusername@gmail.com'
set imap_pass = 'yourpassword'
set spoolfile = imaps://imap.gmail.com/INBOX
set folder = imaps://imap.gmail.com/
set record="imaps://imap.gmail.com/[Gmail]/Sent Mail"
set postponed="imaps://imap.gmail.com/[Gmail]/Drafts"
set mbox="imaps://imap.gmail.com/[Gmail]/All Mail"

# ================  SMTP  ====================
set smtp_url = "smtp://username@smtp.gmail.com:587/"
set smtp_pass = $imap_pass
set ssl_force_tls = yes # Require encrypted connection

# ================  Composition  ====================
set editor = `echo \$EDITOR`
set edit_headers = yes  # See the headers when editing
set charset = UTF-8     # value of $LANG; also fallback for send_charset
# Sender, email address, and sign-off line must match
unset use_domain        # because joe@localhost is just embarrassing
set realname = "YOUR NAME"
set from = "username@gmail.com"
set use_from = yes

Muttのドキュメントにはさらに多くの情報があります：

https://gitlab.com/muttmua/mutt/-/wikis/UseCases/Gmail

http://www.mutt.org/doc/manual/

Sylpheed (GUI)¶

  • インラインテキスト（または添付ファイル）の使用には適しています。

  • 外部エディタの使用を許可しています。

  • 大容量のフォルダでは遅くなります。

  • 非SSL接続ではTLS SMTP認証を行いません。

  • 作成ウィンドウには役立つルーラーバーがあります。

  • アドレス帳にアドレスを追加する際、表示名を正しく理解しません。

Thunderbird (GUI)¶

ThunderbirdはOutlookのクローンですが、テキストを変形させるのが好きですが、うまく振る舞うように強制する方法があります。

  • 外部エディタの使用を許可する: Thunderbirdとパッチの扱いには、『外部エディタ』拡張機能を使用してお気に入りの $EDITOR を読み込み/パッチを本文にマージするのに最適です。これを実行するには、拡張機能をダウンロードしてインストールし、次に『 表示‣ツールバー‣カスタマイズ… 』でその機能用のボタンを追加し、最後に『 作成 』ダイアログ内でクリックします。

    注意: 「外部エディタ」は、エディタがフォークしない必要があります。言い換えれば、エディタが閉じる前に戻らないようにする必要があります。追加のフラグを渡すか、エディタの設定を変更する必要があるかもしれません。特にgvimを使用している場合、gvimに-fオプションを渡す必要があります。バイナリがインストールされている場合、 /usr/bin/gvim -f (バイナリがインストールされている場合、 /usr/bin)をテキストエディタフィールドに 外部エディタ の設定に記載してください。他のエディタを使用している場合は、そのマニュアルを参照してこの操作方法を確認してください。

内部エディタを制御するには、次を行ってください:

  • Thunderbirdの設定を編集し、特定のエディタを使用しないように設定してください。『 format=flowed編集‣設定‣詳細‣設定エディタ 』に移動して、Thunderbirdのレジストリエディタを表示します。 表示‣メッセージ本文として‣純粋テキスト

  • Set mailnews.send_plaintext_flowed に（木の下から葉に向かって） false

  • Set mailnews.wraplength from 72 に（木の下から葉に向かって） 0

  • 表示‣文字エンコーディング‣ユニコード（UTF-8）

  • TkRat (GUI)

動作します。『ファイルの挿入…』または外部エディタを使用してください。¶

Gmail (Web GUI)

パッチの送信には動作しません。¶

Gmailウェブクライアントはタブをスペースに自動的に変換します。

同時に、78文字ごとにCRLFスタイルの改行で行を折り返しますが、タブをスペースに変換する問題は外部エディタで解決できます。

もう一つの問題は、Gmailが非ASCII文字を含むメッセージをbase64エンコードしてしまうことです。これはヨーロッパの名前などにも含まれます。

Gmail web client converts tabs to spaces automatically.
