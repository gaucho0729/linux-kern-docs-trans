Linuxカーネルライセンス規則¶

The Linux Kernel is provided under the terms of the GNU General Public License version 2 only (GPL-2.0), as provided in LICENSES/preferred/GPL-2.0, with an explicit syscall exception described in LICENSES/exceptions/Linux-syscall-note, as described in the COPYING file.

This documentation file provides a description of how each source file should be annotated to make its license clear and unambiguous. It doesn’t replace the Kernel’s license.

The license described in the COPYING file applies to the kernel source as a whole, though individual source files can have a different license which is required to be compatible with the GPL-2.0:

GPL-1.0+  :  GNU General Public License v1.0 or later
GPL-2.0+  :  GNU General Public License v2.0 or later
LGPL-2.0  :  GNU Library General Public License v2 only
LGPL-2.0+ :  GNU Library General Public License v2 or later
LGPL-2.1  :  GNU Lesser General Public License v2.1 only
LGPL-2.1+ :  GNU Lesser General Public License v2.1 or later

Aside from that, individual files can be provided under a dual license, e.g. one of the compatible GPL variants and alternatively under a permissive license like BSD, MIT etc.

The User-space API (UAPI) header files, which describe the interface of user-space programs to the kernel are a special case. According to the note in the kernel COPYING file, the syscall interface is a clear boundary, which does not extend the GPL requirements to any software which uses it to communicate with the kernel. Because the UAPI headers must be includable into any source files which create an executable running on the Linux kernel, the exception must be documented by a special license expression.

The common way of expressing the license of a source file is to add the matching boilerplate text into the top comment of the file. Due to formatting, typos etc. these "boilerplates" are hard to validate for tools which are used in the context of license compliance.

An alternative to boilerplate text is the use of Software Package Data Exchange (SPDX) license identifiers in each source file. SPDX license identifiers are machine parsable and precise shorthands for the license under which the content of the file is contributed. SPDX license identifiers are managed by the SPDX Workgroup at the Linux Foundation and have been agreed on by partners throughout the industry, tool vendors, and legal teams. For further information see https://spdx.org/

The Linux kernel requires the precise SPDX identifier in all source files. The valid identifiers used in the kernel are explained in the section License identifiers and have been retrieved from the official SPDX license list at https://spdx.org/licenses/ along with the license texts.

License identifier syntax¶

  1. Placement:

    カーネルファイルにSPDXライセンス識別子を追加する際は、コメントを含むことができるファイルの最初の可能な行に追加する必要があります。ほとんどのファイルでは最初の行が該当しますが、スクリプトで最初の行に「#!PATH_TO_INTERPRETER」が必要な場合は、そのスクリプトではSPDX識別子を2行目に記載します。


  1. スタイル:

    SPDXライセンス識別子はコメントとして追加します。コメントスタイルはファイルタイプによって異なります:

    C source: // SPDX-License-Identifier: <SPDX License Expression>
C header: /* SPDX-License-Identifier: <SPDX License Expression> */
ASM:      /* SPDX-License-Identifier: <SPDX License Expression> */
scripts:  # SPDX-License-Identifier: <SPDX License Expression>
.rst:     .. SPDX-License-Identifier: <SPDX License Expression>
.dts{i}:  // SPDX-License-Identifier: <SPDX License Expression>

    特定のツールが標準のコメントスタイルを処理できない場合、ツールが受け入れる適切なコメントメカニズムを使用する必要があります。これはCヘッダーファイルで「/* */」スタイルのコメントを使用する理由です。生成された.ldsファイルで「ld」がC++スタイルのコメントを解析できずビルドが中断される問題がありました。これはすでに修正されていますが、古いアセンブリツールはC++スタイルのコメントを処理できません。


  1. 構文:

    SPDXライセンス表現は、SPDXライセンスリストに記載されているSPDX短縮形ライセンス識別子、またはライセンス例外が適用される場合に2つのSPDX短縮形ライセンス識別子を「WITH」で区切った組み合わせです。複数のライセンスが適用される場合、表現はサブ表現を「AND」「OR」で区切り、括弧「(」「)」で囲みます。

    「or later」オプションを持つ[L]GPLなどのライセンスの識別子は、「+」で「or later」オプションを示します。

    // SPDX-License-Identifier: GPL-2.0+
// SPDX-License-Identifier: LGPL-2.1+

    ライセンスに修正が必要な場合は「WITH」を使用します。たとえば、LinuxカーネルのUAPIファイルでは次の表現を使用します:

    // SPDX-License-Identifier: GPL-2.0 WITH Linux-syscall-note
// SPDX-License-Identifier: GPL-2.0+ WITH Linux-syscall-note

    カーネルで使用される「WITH」例外の他の例は以下の通りです:

    // SPDX-License-Identifier: GPL-2.0 WITH mif-exception
// SPDX-License-Identifier: GPL-2.0+ WITH GCC-exception-2.0

    例外は特定のライセンス識別子と組み合わせてのみ使用可能です。有効なライセンス識別子は例外テキストファイルのタグに記載されています。詳細は以下の項目を参照してください 例外 第 License identifiers.

    ファイルが二重ライセンスで1つのライセンスのみを選択する場合、「OR」を使用します。たとえば、一部のdtsiファイルは二重ライセンスで利用可能です:

    // SPDX-License-Identifier: GPL-2.0 OR BSD-3-Clause

    カーネルの二重ライセンスファイルにおけるライセンス表現の例:

    // SPDX-License-Identifier: GPL-2.0 OR MIT
// SPDX-License-Identifier: GPL-2.0 OR BSD-2-Clause
// SPDX-License-Identifier: GPL-2.0 OR Apache-2.0
// SPDX-License-Identifier: GPL-2.0 OR MPL-1.1
// SPDX-License-Identifier: (GPL-2.0 WITH Linux-syscall-note) OR MIT
// SPDX-License-Identifier: GPL-1.0+ OR BSD-3-Clause OR OpenSSL

    ファイルに複数のライセンスがあり、すべての利用条件が適用される場合、「AND」を使用します。たとえば、他のプロジェクトからコードを継承し、カーネルに含める許可を得たが、元のライセンス条件を維持する場合:

    // SPDX-License-Identifier: (GPL-2.0 WITH Linux-syscall-note) AND MIT

    どちらのライセンス条件にも準拠する必要がある例は以下の通りです:

    // SPDX-License-Identifier: GPL-1.0+ AND LGPL-2.1+

License identifiers¶

現在使用中のライセンスおよびカーネルに追加されるコードのライセンスは以下の通りです:

  1. 推奨ライセンス:

    可能な限りこれらのライセンスを使用すべきです。これらは完全に互換性があり、広く使用されていることがわかっています。これらのライセンスは以下ディレクトリから入手できます:

    LICENSES/preferred/

    カーネルソースツリー内。

    このディレクトリ内のファイルには、完全なライセンステキストと メタタグが含まれています。ファイル名は、ソースファイルで使用するライセンスに使用するSPDXライセンス識別子と同一です。

    例:

    LICENSES/preferred/GPL-2.0

    GPLバージョン2のライセンステキストと必要なメタタグを含んでいます:

    LICENSES/preferred/MIT

    MITライセンステキストと必要なメタタグを含んでいます

    メタタグ:

    次のメタタグはライセンスファイルに必ず含まれるべきです:

    • 有効なライセンス識別子:

      プロジェクト内でこの特定のライセンステキストを参照する際に有効なライセンス識別子を1行または複数行で宣言する必要があります。通常は単一の有効な識別子ですが、'or later'オプションを持つライセンスの場合、2つの識別子が有効です。

    • SPDX-URL:

      このライセンスに関する追加情報を含むSPDXページのURLです。

    • 使用ガイドライン:

      自由形式の使用に関するアドバイステキストです。テキストには、SPDXライセンス識別子をソースファイルに記載する際の正しい例を含める必要があります。その例は License identifier syntax ガイドライン

    • License-Text:

      このタグ以降のすべてのテキストは、元のライセンステキストとして扱われます

    ファイル形式の例:

    Valid-License-Identifier: GPL-2.0
Valid-License-Identifier: GPL-2.0+
SPDX-URL: https://spdx.org/licenses/GPL-2.0.html
Usage-Guide:
  To use this license in source code, put one of the following SPDX
  tag/value pairs into a comment according to the placement
  guidelines in the licensing rules documentation.
  For 'GNU General Public License (GPL) version 2 only' use:
    SPDX-License-Identifier: GPL-2.0
  For 'GNU General Public License (GPL) version 2 or any later version' use:
    SPDX-License-Identifier: GPL-2.0+
License-Text:
  Full license text

    SPDX-License-Identifier: MIT
SPDX-URL: https://spdx.org/licenses/MIT.html
Usage-Guide:
  To use this license in source code, put the following SPDX
  tag/value pair into a comment according to the placement
  guidelines in the licensing rules documentation.
    SPDX-License-Identifier: MIT
License-Text:
  Full license text

  1. 非推奨ライセンス:

    これらのライセンスは既存のコードや他のプロジェクトからインポートしたコードのみに使用すべきです。これらのライセンスは以下ディレクトリから入手できます:

    LICENSES/deprecated/

    カーネルソースツリー内。

    このディレクトリ内のファイルには、完全なライセンステキストと メタタグが含まれています。ファイル名は、ソースファイルで使用するライセンスに使用するSPDXライセンス識別子と同一です。

    例:

    LICENSES/deprecated/ISC

    インターネットシステムズコンソーシアムのライセンステキストと必要なメタタグを含んでいます:

    LICENSES/deprecated/GPL-1.0

    GPLバージョン1のライセンステキストと必要なメタタグを含んでいます。

    メタタグ:

    「その他の」ライセンスのメタタグ要件は、 推奨ライセンス.

    ファイル形式の例:

    Valid-License-Identifier: ISC
SPDX-URL: https://spdx.org/licenses/ISC.html
Usage-Guide:
  Usage of this license in the kernel for new code is discouraged
  and it should solely be used for importing code from an already
  existing project.
  To use this license in source code, put the following SPDX
  tag/value pair into a comment according to the placement
  guidelines in the licensing rules documentation.
    SPDX-License-Identifier: ISC
License-Text:
  Full license text

  1. 二重ライセンスのみ

    これらのライセンスは、好ましいライセンスに加えて他のライセンスでコードを二重ライセンスする場合にのみ使用すべきです。これらのライセンスは以下ディレクトリから入手できます:

    LICENSES/dual/

    カーネルソースツリー内。

    このディレクトリ内のファイルには、完全なライセンステキストと メタタグが含まれています。ファイル名は、ソースファイルで使用するライセンスに使用するSPDXライセンス識別子と同一です。

    例:

    LICENSES/dual/MPL-1.1

    モジラパブリックライセンスバージョン1.1のライセンステキストと必要なメタタグを含んでいます:

    LICENSES/dual/Apache-2.0

    アパッチライセンスバージョン2.0のライセンステキストと必要なメタタグを含んでいます。

    メタタグ:

    「その他の」ライセンスのメタタグ要件は、 推奨ライセンス.

    ファイル形式の例:

    Valid-License-Identifier: MPL-1.1
SPDX-URL: https://spdx.org/licenses/MPL-1.1.html
Usage-Guide:
  Do NOT use. The MPL-1.1 is not GPL2 compatible. It may only be used for
  dual-licensed files where the other license is GPL2 compatible.
  If you end up using this it MUST be used together with a GPL2 compatible
  license using "OR".
  To use the Mozilla Public License version 1.1 put the following SPDX
  tag/value pair into a comment according to the placement guidelines in
  the licensing rules documentation:
SPDX-License-Identifier: MPL-1.1
License-Text:
  Full license text

  1. 例外:

    一部のライセンスは例外によって修正され、元のライセンスにない特定の権利を付与できます。これらの例外は以下ディレクトリから入手できます:

    LICENSES/exceptions/

    カーネルソースツリー内。このディレクトリ内のファイルには、完全な例外テキストと必要な 例外メタタグ.

    例:

    LICENSES/exceptions/Linux-syscall-note

    Linuxシステムコール例外を含み、LinuxカーネルのCOPYINGファイルで記載されているように、UAPIヘッダーファイルに使用されます。例: /* SPDX-License-Identifier: GPL-2.0 WITH Linux-syscall-note */:

    LICENSES/exceptions/GCC-exception-2.0

    GCCの「リンク例外」を含んでおり、この例外を付与したファイルのコンパイル済みバージョンと、ライセンスに関係なく任意のバイナリをリンクするのを許可します。これは、GPLと互換性のないソースコードから実行可能ファイルを生成するために必要です。

    例外メタタグ:

    以下のメタタグは例外ファイルに必ず存在する必要があります：

    • SPDX-Exception-Identifier:

      SPDXライセンス識別子と併用可能な例外識別子

    • SPDX-URL:

      SPDXライセンスに関する追加情報が記載されているSPDXページのURL

    • SPDX-Licenses:

      この例外が適用可能なSPDXライセンス識別子の一覧（コンマで区切ります）

    • 使用ガイドライン:

      使用上のアドバイスとしての自由形式のテキスト。テキストの後には、ソースファイルに記載すべきSPDXライセンス識別子の正しい例を含む必要があります（参照： License identifier syntax ガイドライン

    • Exception-Text:

      このタグの後のすべてのテキストは、元の例外テキストとして扱われます

    ファイル形式の例:

    SPDX-Exception-Identifier: Linux-syscall-note
SPDX-URL: https://spdx.org/licenses/Linux-syscall-note.html
SPDX-Licenses: GPL-2.0, GPL-2.0+, GPL-1.0+, LGPL-2.0, LGPL-2.0+, LGPL-2.1, LGPL-2.1+
Usage-Guidance:
  This exception is used together with one of the above SPDX-Licenses
  to mark user-space API (uapi) header files so they can be included
  into non GPL compliant user-space application code.
  To use this exception add it with the keyword WITH to one of the
  identifiers in the SPDX-Licenses tag:
    SPDX-License-Identifier: <SPDX-License> WITH Linux-syscall-note
Exception-Text:
  Full exception text

    SPDX-Exception-Identifier: GCC-exception-2.0
SPDX-URL: https://spdx.org/licenses/GCC-exception-2.0.html
SPDX-Licenses: GPL-2.0, GPL-2.0+
Usage-Guidance:
  The "GCC Runtime Library exception 2.0" is used together with one
  of the above SPDX-Licenses for code imported from the GCC runtime
  library.
  To use this exception add it with the keyword WITH to one of the
  identifiers in the SPDX-Licenses tag:
    SPDX-License-Identifier: <SPDX-License> WITH GCC-exception-2.0
Exception-Text:
  Full exception text

すべてのSPDXライセンス識別子および例外には、LICENSESサブディレクトリに該当するファイルが存在する必要があります。これはツールによる検証（例：checkpatch.pl）を可能にし、ソースから即座にライセンスを読み取って抽出できるようにするためのものです。これは、FSFE REUSEイニシアチブなどのFOSS団体が推奨しています。 FSFE REUSEイニシアチブ.

MODULE_LICENSE¶

ロード可能なカーネルモジュールにもMODULE_LICENSE()タグが必要です。このタグは、適切なソースコードライセンス情報（SPDX-License-Identifier）の代替ではなく、また、ソースコードが提供されるライセンスを表現または決定するためのものでもありません。

このタグの唯一の目的は、カーネルモジュールローダーおよびユーザー空間ツールが、モジュールがフリーソフトウェアか専有ソフトウェアかを判断するための十分な情報を提供することです。

MODULE_LICENSE()で有効なライセンス文字列は以下の通りです：

「GPL」

モジュールはGPLバージョン2でライセンスされています。これはGPL-2.0-onlyとGPL-2.0-or-laterの区別を示すものではありません。正確なライセンス情報は、対応するソースファイル内のライセンス情報によってのみ決定されます。

「GPL v2」

「GPL」と同じ意味です。これは歴史的な理由により存在しています。

「GPL and additional rights」

モジュールソースがGPL v2の変体とMITライセンスで二重ライセンスされていることを示す歴史的な表現です。新規コードでは使用しないでください。

「Dual MIT/GPL」

モジュールがGPL v2の変体またはMITライセンスの選択肢で二重ライセンスされていることを正しく表現する方法です。

「Dual BSD/GPL」

このモジュールは、GPL v2の変体またはBSDライセンスの選択肢の下で二重ライセンスされています。BSDライセンスの正確な変体は、対応するソースファイル内のライセンス情報によってのみ決定できます。

「Dual MPL/GPL」

このモジュールは、GPL v2の変体またはMozilla Public License (MPL)の選択肢の下で二重ライセンスされています。MPLライセンスの正確な変体は、対応するソースファイル内のライセンス情報によってのみ決定できます。

「Proprietary」

このモジュールは専用ライセンスの下にあります。この文字列は専有権を持つ第三者モジュールのみに使用され、カーネルツリーにソースコードが含まれるモジュールには使用できません。このタグが付けられたモジュールはロード時にカーネルを「P」フラグで汚染し、カーネルモジュールロー�ーダーは EXPORT_SYMBOL_GPL() でエクスポートされたシンボルに対してこのようなモジュールをリンク拒否します。
