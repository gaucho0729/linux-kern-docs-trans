Linux -stableリリースについて知りたいすべての情報¶

「-stable」ツリーに受け入れられるパッチの種類に関するルールは以下の通りです：

  • 明確に正しいことかつテスト済みである必要があります。

  • コンテキストを含めて100行以上にはなりません。

  • 1つの問題のみを修正する必要があります。

  • 人々に不快感を与える実際のバグを修正する必要があります（「これは問題になるかもしれない…」というようなものではありません）。

  • ビルドエラーを引き起こす問題、またはオプス（oops）、ハング、データ腐敗、実際のセキュリティ問題、または「これは良くない」と思われる問題を修正する必要があります。要するに、何か重要な問題を修正する必要があります。

  • 配布版カーネルのユーザーが報告した深刻な問題も、パフォーマンスやインタラクティビティに影響を与える重要な問題を修正する場合、考慮されることがあります。これらの修正は明らかでなく、レギレッションのリスクが高いため、配布版カーネルメンテナがのみ送信し、バグチケットへのリンクとユーザーに見える影響の追加情報が含まれる必要があります。

  • 新しいデバイスIDとキュークは受け入れられます。

  • 理論的なレースコンディションの問題は受け入れられません（ただし、レースが悪用される仕組みの説明が提供される場合は除きます）。

  • スペル修正やホワイトスペースのクリーンアップなどの「トリビアル」な修正を含んではなりません。

  • 以下のルールに従う必要があります パッチの送信: コードをカーネルに取り込むためのエッセンシャルガイド ルール。

  • この修正または同等の修正がすでにリンウスのツリー（アップストリーム）に存在している必要があります。

パッチを「-stable」ツリーに送信する手順¶

  • セキュリティパッチは「-stable」レビュープロセス（単独では）で処理されませんが、以下の手順に従う必要があります セキュリティ関連のバグ.

すべての他の送信については、以下のいずれかの手順を選択してください¶

オプション1¶

パッチを自動的に安定版ツリーに含めるには、署名エリアに

Cc: stable@vger.kernel.org

を追加してください。パッチがマージされると、著者やサブシステムメンテナが何もしなくても安定版ツリーに適用されます。

オプション2¶

パッチがリンウスのツリーにマージされた後、 stable@vger.kernel.org にメールを送信してください。メールにはパッチの件名、コミットID、適用すべき理由、および適用したいカーネルバージョンを含めてください。

オプション3¶

上記のルールに従っていることを確認した後、 stable@vger.kernel.orgに送信してください。アップストリームのコミットIDと適用したいカーネルバージョンをサブミッションのチェンジログに記載する必要があります。

オプション1 通常のRCU読み込み側クリティカルセクションは、条件付きでスリープロックを取得することが許容されます（例として 強く 推奨されるのは、最も簡単で一般的な方法です。 オプション2 および オプション3 パッチが公開されたgitツリーに適用されるときに価値がないと判断された場合（例：さらにレギレッションテストが必要な場合など）には、より有用です。 オプション3 パッチが古いカーネルに適用する際に特別な処理が必要な場合（例：APIが変更されている場合など）には特に有用です。

以下の通り注意してください オプション3、パッチがオリジナルのアップストリームパッチから逸脱している場合（例：バックポーティングが必要だったためなど）は、パッチの説明でこれを明確かつ正当化して記載する必要があります。

アップストリームのコミットIDは、コミットテキストの上に別行で指定する必要があります。以下のように記載してください：

commit <sha1> upstream.

さらに、一部のパッチは オプション1 を介して送信された場合、追加のパッチ前提条件を持つ場合があります。これはサインオフエリアで以下の形式で指定できます：

Cc: <stable@vger.kernel.org> # 3.3.x: a1f84a3: sched: Check for idle
Cc: <stable@vger.kernel.org> # 3.3.x: 1b9508f: sched: Rate-limit newidle
Cc: <stable@vger.kernel.org> # 3.3.x: fd21073: sched: Fix affinity logic
Cc: <stable@vger.kernel.org> # 3.3.x
Signed-off-by: Ingo Molnar <mingo@elte.hu>

タグの順序は次の意味を持ちます：

git cherry-pick a1f84a3
git cherry-pick 1b9508f
git cherry-pick fd21073
git cherry-pick <this commit>

また、一部のパッチはカーネルバージョンの前提条件を持つ場合があります。これはサインオフエリアで以下の形式で指定できます：

Cc: <stable@vger.kernel.org> # 3.3.x

タグの意味は次の通りです：

git cherry-pick <this commit>

指定されたバージョンから始まる各「-stable」ツリーについて。

送信後

  • 送信者は、パッチがキューに受け入れられるとACKを、拒否された場合はNAKを受信します。この応答は、開発者のスケジュールにより数日かかることがあります。

  • 受け入れられた場合、パッチは-stableキューに追加され、他の開発者および関連するサブシステムメンテナによってレビューされます。

レビュー・サイクル¶

  • -stableメンテナがレビュー・サイクルを決定した場合、パッチはレビュー委員会に送信され、パッチに影響を与える領域のメンテナ（送信者がその領域のメンテナでない場合）およびlinux-kernelメーリングリストにCCされます。

  • レビュー・コミッティは、パッチをACKまたはNAKするための48時間の期限があります。

  • コミッティのメンバーによってパッチが拒否され、またはlinux-kernelのメンバーがパッチに異議を唱え、メンテナやメンバーが気づいていなかった問題を指摘した場合、パッチはキューから削除されます。

  • レビュー・サイクル終了後、ACKされたパッチは最新の-stableリリースに追加され、新しい-stableリリースが行われます。

  • セキュリティパッチは、セキュリティカーネルチームから直接-stableツリーに受け入れられ、通常のレビュー・サイクルを経ることなく処理されます。詳細についてはカーネルセキュリティチームにご確認ください。

ツリー¶

  • 完了済みバージョンおよび進行中のバージョンのパッチキューは次の場所にあります：

    https://git.kernel.org/pub/scm/linux/kernel/git/stable/stable-queue.git

  • すべての安定版カーネルの確定されたタグ付きリリースは、各バージョンごとに別個のブランチにあります：

    https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git

  • すべての安定版カーネルバージョンのリリース候補は次の場所にあります：

    https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux-stable-rc.git/

    警告

    -stable-rc ツリーは、stable-queue ツリーのタイムスタンプのスナップショットであり、頻繁に変更されるため、よく再ベースされます。テスト目的（例: CIシステムで消費される）にのみ使用するべきです。
