MHI (モデム・ホストインターフェース)¶

このドキュメントはMHIプロトコルに関する情報を提供しています。

概要¶

MHIはQualcomm Innovation Center, Inc.が開発したプロトコルです。ホストプロセッサが高速なペリフェラルバスや共有メモリを介してモジュールデバイスを制御および通信するためのもので、MHIはあらゆるペリフェラルバスに簡単に適応可能ですが、主にPCIeベースのデバイスで使用されます。MHIは物理的なバス上で論理チャネルを提供し、IPデータパケット、モジュール制御メッセージ、診断などのモジュールプロトコルを少なくとも1つの論理チャネルを介して転送します。また、MHIプロトコルはデータ確認機能を提供し、1つまたは複数の論理チャネルを介してモジュールの電源状態を管理します。

MHI内部構造¶

MMIO¶

MMIO (Memory mapped IO)は、ペリフェラルバス（例：PCIe）によってホストメモリ空間にマッピングされるデバイスハードウェア内のレジスタ群です。以下の主要なMMIOレジスタ領域のコンポーネントがあります：

MHI制御レジスタ: MHI設定レジスタへのアクセス

MHI BHIレジスタ: BHI (Boot Host Interface)レジスタは、MHI初期化前のデバイスへのファームウェアダウンロードにホストが使用します。

チャネルドアベル配列: ホストがデバイスに新しい作業があることを通知するためのチャネルドアベル（DB）レジスタを使用します。

イベントドアベル配列: イベントコンテキスト配列に関連し、ホストがデバイスに新しいイベントが利用可能になったことを通知するためのイベントドアベル（DB）レジスタを使用します。

デバッグレジスタ: デバイスがパフォーマンス、機能性、安定性などのデバッグ情報をホストに公開するためのレジスタとカウンターの集合です。

データ構造¶

MHIが使用するすべてのデータ構造はホストシステムメモリに存在し、デバイスは物理インターフェースを通じてそれらにアクセスします。ホストシステムメモリ領域のMHIデータ構造およびデータバッファはデバイスにマッピングされます。

チャネルコンテキスト配列: すべてのチャネル設定はチャネルコンテキストデータ配列に整理されています。

トランスファーリング: ホストがチャネルに作業項目をスケジュールするためのもので、トランスファーデスクリプタ（TD）を要素とする環状キューとして組織されています。

イベントコンテキスト配列: すべてのイベント設定はイベントコンテキストデータ配列に整理されています。

イベントリング: デバイスが完了および状態変化メッセージをホストに送信するために使用されます。

コマンドコンテキスト配列: すべてのコマンド設定はコマンドコンテキストデータ配列に整理されています。

コマンドリング: ホストがデバイスにMHIコマンドを送信するために使用されます。コマンドリングは、コマンドデスクリプタ（CD）を円環キューとして組織されています。

チャネル¶

MHIチャネルは、ホストとデバイス間の論理的な単方向データパイプです。MHIにおけるチャネルの概念はUSBのエンドポイントに類似しています。MHIは最大256チャネルをサポートしていますが、特定のデバイス実装では最大数より少ない数をサポートする場合があります。

2つの単方向チャネルとそれらに関連する転送リングは、双方向データパイプを形成し、上位プロトコルがアプリケーションデータパケット（IPパケット、モデム制御メッセージ、診断メッセージなど）を転送するために使用できます。各チャネルは単一の転送リングに関連付けられます。

転送リング¶

ホストとデバイス間の転送はチャネルによって組織され、トランスファーデスクリプタ（TD）で定義されます。TDは転送リングを通じて管理され、デバイスとホスト間の各チャネルごとにホストメモリに存在します。TDは1つまたは複数のリング要素（または転送ブロック）から構成されます：

[Read Pointer (RP)] ----------->[Ring Element] } TD
[Write Pointer (WP)]-           [Ring Element]
                     -          [Ring Element]
                      --------->[Ring Element]
                                [Ring Element]

転送リングの基本的な使用方法は以下の通りです：

  • ホストが転送リングのメモリを割り当てます。

  • ホストが対応するチャネルコンテキスト内のベースポインタ、読み込みポインタ、書き込みポインタを設定します。

  • 読み込みポインタ（RP）が書き込みポインタ（WP）と等しい場合、リングは空とみなされます。

  • 書き込みポインタ（WP）＋1が読み込みポインタ（RP）と等しい場合、リングは満杯とみなされます。

  • 読み込みポインタ（RP）は、デバイスが次に処理すべき要素を示します。

  • ホストが新しいバッファを送信する場合、ホストはリング要素にバッファ情報を更新し、書き込みポインタ（WP）を次の要素にインクリメントし、関連するチャネルDBを通知します。

イベントリング¶

デバイスからホストへのイベントはイベントリングで組織され、イベントデスクリプタ（ED）で定義されます。イベントリングは、デバイスがデータ転送完了ステータス、コマンド完了ステータス、ステート変化などのイベントをホストに報告するために使用されます。イベントリングはホストメモリに存在するEDの配列です。EDは1つまたは複数のリング要素（または転送ブロック）から構成されます：

[Read Pointer (RP)] ----------->[Ring Element] } ED
[Write Pointer (WP)]-           [Ring Element]
                     -          [Ring Element]
                      --------->[Ring Element]
                                [Ring Element]

イベントリングの基本的な使用方法は以下の通りです：

  • ホストがイベントリングのメモリを割り当てます。

  • ホストが対応するチャネルコンテキスト内のベースポインタ、読み込みポインタ、書き込みポインタを設定します。

  • ホストとデバイスはともにローカルのRP、WPのコピーを持ちます。

  • 書き込みポインタ（WP）＋1が読み込みポインタ（RP）と等しい場合、リングは空（処理すべきイベントがない）とみなされます。

  • 読み込みポインタ（RP）が書き込みポインタ（WP）と等しい場合、リングはイベントで満杯とみなされます。

  • デバイスが新しいイベントを送信する必要がある場合、デバイスはRPで指されるEDを更新し、読み込みポインタ（RP）を次の要素にインクリメントし、割り込みをトリガーします。

リング要素¶

リング要素は、ホストとデバイス間で単一のデータブロックを転送するために使用されるデータ構造です。転送リング要素タイプは、単一のバッファポインタ、バッファのサイズ、および追加の制御情報を含みます。他のリング要素タイプは、制御およびステータス情報のみを含む場合があります。単一バッファ操作では、リングディスクリプタは単一の要素で構成されます。大容量のマルチバッファ操作（スキャッターアンドギャッターなど）では、要素をチェーンすることでより長いディスクリプタを形成できます。

MHI操作¶

MHI状態¶

MHI_STATE_RESET¶

MHIは電源投入またはハードウェアリセット後にリセット状態になります。ホストはデバイスのMMIOレジスタ領域にアクセスすることはできません。

MHI_STATE_READY¶

MHIは初期化のために準備されています。ホストはMMIOレジスタをプログラミングしてMHI初期化を開始できます。

MHI_STATE_M0¶

MHIはデバイスで動作中です。ホストはチャネル開始コマンドを発行してチャネルを開始できます。

MHI_STATE_M1¶

デバイスが物理インターフェースで事前に設定された時間内に不活性を検出すると、MHI操作は一時停止されます。

MHI_STATE_M2¶

MHIは低電力状態にあります。MHI操作は一時停止され、デバイスはより低い電力モードに移行できます。

MHI_STATE_M3¶

ホストがMHI操作を停止した場合、この状態になります。ホストがMHI操作を一時停止したときにこの状態になります。

MHI初期化¶

システムが起動した後、デバイスは物理インターフェースを介して列挙されます。PCIeの場合、デバイスは列挙され、デバイスのMMIOレジスタ領域にBAR-0が割り当てられます。デバイスのMHIを初期化するには、ホストは以下の操作を行います：

  • イベント、チャネルおよびコマンド配列用のMHIコンテキストを割り当てます。

  • コンテキスト配列を初期化し、割り込みを準備します。

  • デバイスがREADY状態になるのを待機します。

  • MHI MMIOレジスタをプログラミングし、デバイスをMHI_M0状態に設定します。

  • デバイスがM0状態になるのを待機します。

MHIデータ転送¶

ホストがデバイスにデータを転送するためにMHIデータ転送を開始します。ホストがデバイスにデータを転送するために実行する操作の順序は以下の通りです：

  • ホストはTD（トランスファーディスクリプタ）にバッファ情報を準備します。

  • ホストは対応するチャネルトランスファーリングのWP（Write Pointer）をインクリメントします。

  • ホストはチャネルDB（ドアベルレジスタ）をリングします。

  • デバイスがTDを処理するために起動します。

  • デバイスは処理したTDに対してED（イベントディスクリプタ）を更新して完了イベントを生成します。

  • デバイスは対応するイベントリングのRP（Read Pointer）をインクリメントします。

  • デバイスはホストを起動するためにIRQ（割り込み要求）をトリガーします。

  • ホストが起動し、完了イベントを確認するためイベントリングを確認します。

  • ホストは、対応するイベントリングのWPを更新し、データ転送が成功したことを示します。
