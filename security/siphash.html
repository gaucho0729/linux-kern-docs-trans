SipHash - 短い入力のPRF¶

著者

ジャスン・A・ドネンフェルドによって書かれました <jason@zx2c4.com>

SipHashは暗号的に安全なPRF – キー付きハッシュ関数 – であり、短い入力に対して非常に高性能なので、その名前もそれに由来しています。これは暗号学者のDaniel J. BernsteinとJean-Philippe Aumassonによって設計されました。これは以下の用途の一部として代替として意図されています: jhash, md5_transform, sha1_transform、など。

SipHashはランダムに生成された数値で埋められた秘密鍵と、入力バッファまたは複数の入力整数のいずれかを受け取ります。これにより、ランダムと区別がつかない整数が生成されます。この整数をセキュアなシーケンス番号、セキュアなクッキー、またはハッシュテーブルでの使用にマスクして使用できます。

鍵の生成¶

鍵は常に暗号的に安全なランダム数のソースから生成する必要があります。get_random_bytesまたはget_random_onceを使用して、以下のように:

siphash_key_t key;
get_random_bytes(&key, sizeof(key));

ここから鍵を導出していない場合は、間違っています。

関数の使用方法¶

関数には2つの変体があり、1つは整数のリストを受け取り、もう1つはバッファを受け取ります:

u64 siphash(const void *data, size_t len, const siphash_key_t *key);

そして:

u64 siphash_1u64(u64, const siphash_key_t *key);
u64 siphash_2u64(u64, u64, const siphash_key_t *key);
u64 siphash_3u64(u64, u64, u64, const siphash_key_t *key);
u64 siphash_4u64(u64, u64, u64, u64, const siphash_key_t *key);
u64 siphash_1u32(u32, const siphash_key_t *key);
u64 siphash_2u32(u32, u32, const siphash_key_t *key);
u64 siphash_3u32(u32, u32, u32, const siphash_key_t *key);
u64 siphash_4u32(u32, u32, u32, u32, const siphash_key_t *key);

ジェネリックなsiphash関数に定長のデータを渡すと、コンパイル時に定数畳み込みが行われ、最適化された関数の1つが自動的に選択されます。

ハッシュテーブルキー関数の使用方法:

struct some_hashtable {
        DECLARE_HASHTABLE(hashtable, 8);
        siphash_key_t key;
};

void init_hashtable(struct some_hashtable *table)
{
        get_random_bytes(&table->key, sizeof(table->key));
}

static inline hlist_head *some_hashtable_bucket(struct some_hashtable *table, struct interesting_input *input)
{
        return &table->hashtable[siphash(input, sizeof(*input), &table->key) & (HASH_SIZE(table->hashtable) - 1)];
}

返されたハッシュバケットに対して通常通りにイテレーションできます。

セキュリティ¶

SipHashは128ビットの鍵により非常に高いセキュリティマージンを持っています。鍵が秘密保持されている限り、攻撃者が関数の出力を推測することはできません。これは2^128の出力が非常に多いからです。

LinuxはSipHashの「2-4」変体を実装しています。

構造体渡しの注意点¶

XuY関数は通常、十分なサイズを持たないため、代わりに事前に埋められた構造体をsiphashに渡すのが望ましいです。このような場合、構造体にパディングの空きがないことを常に確認する必要があります。最も簡単な方法は、構造体のメンバをサイズの降順に並べ、サイズを取得する際にはoffsetendof()を使用することです。パフォーマンスの観点から、可能であれば構造体を右境界にアライメントするのも良いでしょう。以下に例を示します:

const struct {
        struct in6_addr saddr;
        u32 counter;
        u16 dport;
} __aligned(SIPHASH_ALIGNMENT) combined = {
        .saddr = *(struct in6_addr *)saddr,
        .counter = counter,
        .dport = dport
};
u64 h = siphash(&combined, offsetofend(typeof(combined), dport), &secret);

HalfSipHash - SipHashの不安全な若き従弟¶

著者

ジャスン・A・ドネンフェルドによって書かれました <jason@zx2c4.com>

SipHashがあなたの要件に十分速くない場合、HalfSipHashという恐ろしいが潜在的に有用な可能性を検討する価値があるかもしれません。HalfSipHashはSipHashのラウンド数を「2-4」から「1-3」に減らし、さらに恐ろしいことに64ビットの鍵（32ビットの出力）を使用するため、SipHashの128ビット鍵よりもブルートフォースで簡単に攻撃可能な設計となっています。ただし、この特性は一部の高性能なユーザーにのみ適用される可能性があります jhash ユーザー。

注意！

HalfSipHashは決してハッシュテーブルのキー関数としてのみ使用し、かつカーネル外に出力が伝送されることを絶対に確認できる場合に限り使用してください。これはハッシュテーブルの洪水によるサービス妨害攻撃を緩和する手段として、やや役立つ程度の用途にしかありません jhash ハッシュテーブルの洪水によるサービス妨害攻撃を緩和する手段として、やや役立つ程度の用途にしかありません

パフォーマンス¶

HalfSipHash は JenkinsHash に対して大体 3 倍遅いです。多くの置き換えでは、ハッシュテーブルの検索がボトルネックでないため、これは問題にならないでしょう。全体的に見れば、HalfSipHash のセキュリティと DoS 耐性のためにこのような犠牲を払うのは良い選択です。
