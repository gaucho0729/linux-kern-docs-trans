信頼された暗号化されたキー¶

信頼性あり暗号化されたキーは、既存のカーネルキーリングサービスに新たに追加された2つのキー種別です。これら2つの新しい種別はどちらも可変長の対称鍵であり、すべてのキーはカーネル内で生成され、ユーザー空間では暗号化されたバイナリブロブのみが表示され、保存され、ロードされます。信頼性ありキーはより高いセキュリティのために信頼されたプラットフォームモジュール（TPM）チップの利用を必要としますが、暗号化されたキーはあらゆるシステムで使用可能です。すべてのユーザー空間のブロブは読みやすさのため16進文字列で表示され、整合性検証が行われます。

信頼性ありキーはTPMを用いてキーの生成および封印を行います。キーはTPM内の2048ビットRSA鍵で封印され、指定されたPCR（整合性測定）値にオプションで封印され、PCRsとブロブ整合性検証が一致した場合にのみTPMによって封印を解除されます。ロードされた信頼性ありキーは新しい（将来の）PCR値で更新可能なので、カーネルやinitramfsが更新されるたびにキーを簡単に新しいPCR値に移行できます。同じキーは異なるPCR値ごとに複数の保存されたブロブを持つことができるので、複数のブートを簡単にサポートできます。

TPM 1.2¶

デフォルトでは信頼性ありキーはSRK（システムリーダー鍵）の下で封印され、デフォルトの認証値（20のゼロ）が使用されます。これはtakeownership時にtrousersユーティリティで設定可能です：『tpm_takeownership -u -z』。

TPM 2.0¶

ユーザーはまずストレージキーを作成し、永続化する必要があります。これにより、再起動後でもキーが利用可能です。以下のコマンドで実行できます。

IBM TSS 2スタックを使用する場合:

#> tsscreateprimary -hi o -st
Handle 80000000
#> tssevictcontrol -hi o -ho 80000000 -hp 81000001

Intel TSS 2スタックを使用する場合:

#> tpm2_createprimary --hierarchy o -G rsa2048 -c key.ctxt
[...]
#> tpm2_evictcontrol -c key.ctxt 0x81000001
persistentHandle: 0x81000001

使用方法:

keyctl add trusted name "new keylen [options]" ring
keyctl add trusted name "load hex_blob [pcrlock=pcrnum]" ring
keyctl update key "update [options]"
keyctl print keyid

options:
   keyhandle=    ascii hex value of sealing key
                   TPM 1.2: default 0x40000000 (SRK)
                   TPM 2.0: no default; must be passed every time
   keyauth=      ascii hex auth for sealing key default 0x00...i
                 (40 ascii zeros)
   blobauth=     ascii hex auth for sealed data default 0x00...
                 (40 ascii zeros)
   pcrinfo=      ascii hex of PCR_INFO or PCR_INFO_LONG (no default)
   pcrlock=      pcr number to be extended to "lock" blob
   migratable=   0|1 indicating permission to reseal to new PCR values,
                 default 1 (resealing allowed)
   hash=         hash algorithm name as a string. For TPM 1.x the only
                 allowed value is sha1. For TPM 2.x the allowed values
                 are sha1, sha256, sha384, sha512 and sm3-256.
   policydigest= digest for the authorization policy. must be calculated
                 with the same hash algorithm as specified by the 'hash='
                 option.
   policyhandle= handle to an authorization policy session that defines the
                 same policy and with the same hash algorithm as was used to
                 seal the key.

『keyctl print』はTPM_STORED_DATA形式の暗号化キーの16進文字列コピーを返します。新しいキーの長さは常にバイト単位で指定されます。信頼性ありキーは32〜128バイト（256〜1024ビット）で、上限は2048ビットSRK（RSA）鍵長に収まるように構造やパディングを含むためです。

暗号化キーはTPMに依存せず、AESを用いるため処理が速くなります。新しいキーはカーネルが生成するランダム数から作成され、指定された『マスターキー』で暗号化・復号されます。『マスターキー』は信頼性ありキーまたはユーザー鍵のいずれかです。暗号化キーの主な欠点は、信頼性ありキーに根拠がない場合、ユーザー鍵で暗号化されているだけなのでセキュリティが低くなることです。そのため、マスターユーザー鍵はできるだけ安全にロードする必要があります。できればブート初期段階でロードするのが望ましいです。

暗号化されたキーの復号化された部分には、単純な対称鍵かより複雑な構造のいずれかが含まれます。より複雑な構造の形式はアプリケーション固有であり、'format'で識別されます。

使用方法:

keyctl add encrypted name "new [format] key-type:master-key-name keylen"
    ring
keyctl add encrypted name "load hex_blob" ring
keyctl update keyid "update key-type:master-key-name"

以下では:

format:= 'default | ecryptfs | enc32'
key-type:= 'trusted' | 'user'

信頼されたキーの最初の利用者はEVMで、起動時にファイルメタデータのHMAC保護に高品質な対称鍵が必要です。信頼されたキーの使用により、EVMの鍵がユーザー層の問題で侵害されていないことを強く保証し、特定の起動PCR値に封印することで起動やオフライン攻撃から保護します。上記の信頼されたキー「kmk」を使用して暗号化されたキー「evm」を作成し、保存します:

オプション1: 'format'を省略:

$ keyctl add encrypted evm "new trusted:kmk 32" @u
159771175

オプション2: 'format'を明示的に'default'として定義:

$ keyctl add encrypted evm "new default trusted:kmk 32" @u
159771175

ディスクやファイルの暗号化など、信頼されたおよび暗号化されたキーの他の用途も予想されています。特に新しい形式'ecryptfs'が定義され、暗号化されたキーを使用してeCryptfsファイルシステムをマウントするためのものです。詳細については、ファイル Documentation/security/keys/ecryptfs.rst.

また、32バイトのペイロードサイズをサポートするための新しい形式'enc32'が定義されました。これは一時的にnvdimmセキュリティに使用されますが、32バイトのペイロードを必要とする他の用途にも拡張される可能性があります。
