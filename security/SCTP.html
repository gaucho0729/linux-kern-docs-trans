SCTP¶

SCTP LSM サポート¶

セキュリティ ハイクス¶

セキュリティ モジュールのサポートにあたり、3つのSCTP特有のハイクスが実装されています:

security_sctp_assoc_request()
security_sctp_bind_connect()
security_sctp_sk_clone()

さらに、以下のセキュリティ ハイクスが利用されています:

security_inet_conn_established()

これらのハイクスの使用方法は、以下のセクションで説明し、『SCTP SELinux サポート』章で説明されているSELinuxの実装についても記載しています。 SCTP SELinux サポート 章。

security_sctp_assoc_request()¶

関連付け INIT パケットの @ep および @chunk->skb をセキュリティ モジュールに渡します。成功時は0を、失敗時はエラーを返します。

@ep - pointer to sctp endpoint structure.
@skb - pointer to skbuff of association packet.

security_sctp_bind_connect()¶

セキュリティ モジュールに1つ以上のIPv4/IPv6アドレスを渡し、以下の @optname に基づいて、バインドまたはコネクトサービスを実行するための検証を行います。成功時は0を、失敗時はエラーを返します。

  @sk      - Pointer to sock structure.
  @optname - Name of the option to validate.
  @address - One or more ipv4 / ipv6 addresses.
  @addrlen - The total length of address(s). This is calculated on each
             ipv4 or ipv6 address using sizeof(struct sockaddr_in) or
             sizeof(struct sockaddr_in6).

------------------------------------------------------------------
|                     BIND Type Checks                           |
|       @optname             |         @address contains         |
|----------------------------|-----------------------------------|
| SCTP_SOCKOPT_BINDX_ADD     | One or more ipv4 / ipv6 addresses |
| SCTP_PRIMARY_ADDR          | Single ipv4 or ipv6 address       |
| SCTP_SET_PEER_PRIMARY_ADDR | Single ipv4 or ipv6 address       |
------------------------------------------------------------------

------------------------------------------------------------------
|                   CONNECT Type Checks                          |
|       @optname             |         @address contains         |
|----------------------------|-----------------------------------|
| SCTP_SOCKOPT_CONNECTX      | One or more ipv4 / ipv6 addresses |
| SCTP_PARAM_ADD_IP          | One or more ipv4 / ipv6 addresses |
| SCTP_SENDMSG_CONNECT       | Single ipv4 or ipv6 address       |
| SCTP_PARAM_SET_PRIMARY     | Single ipv4 or ipv6 address       |
------------------------------------------------------------------

以下の @optname 項目の概要は以下の通りです:

SCTP_SOCKOPT_BINDX_ADD - Allows additional bind addresses to be
                         associated after (optionally) calling
                         bind(3).
                         sctp_bindx(3) adds a set of bind
                         addresses on a socket.

SCTP_SOCKOPT_CONNECTX - Allows the allocation of multiple
                        addresses for reaching a peer
                        (multi-homed).
                        sctp_connectx(3) initiates a connection
                        on an SCTP socket using multiple
                        destination addresses.

SCTP_SENDMSG_CONNECT  - Initiate a connection that is generated by a
                        sendmsg(2) or sctp_sendmsg(3) on a new asociation.

SCTP_PRIMARY_ADDR     - Set local primary address.

SCTP_SET_PEER_PRIMARY_ADDR - Request peer sets address as
                             association primary.

SCTP_PARAM_ADD_IP          - These are used when Dynamic Address
SCTP_PARAM_SET_PRIMARY     - Reconfiguration is enabled as explained below.

ダイナミック アドレス再構成をサポートするには、両端点で以下のパラメータを有効にする必要があります（または適切な setsockopt(2)):

/proc/sys/net/sctp/addip_enable
/proc/sys/net/sctp/addip_noauth_enable

その後、以下の _PARAM_が、対応する @optnameが存在する場合、

      @optname                      ASCONF Parameter
     ----------                    ------------------
SCTP_SOCKOPT_BINDX_ADD     ->   SCTP_PARAM_ADD_IP
SCTP_SET_PEER_PRIMARY_ADDR ->   SCTP_PARAM_SET_PRIMARY

security_sctp_sk_clone()¶

新しいソケットが作成されるたびに呼び出されます。 accept(2)（つまり、TCPスタイルのソケット）またはソケットが「剥がされる」場合（例：ユーザースペースが sctp_peeloff(3).

@ep - pointer to current sctp endpoint structure.
@sk - pointer to current sock structure.
@sk - pointer to new sock structure.

security_inet_conn_established()¶

COOKIE ACKが受信されるときに呼び出されます:

@sk  - pointer to sock structure.
@skb - pointer to skbuff of the COOKIE ACK packet.

ポリシーステートメント¶

次のクラスと権限によりSCTPをサポートするための機能がカーネル内で利用可能です：

class sctp_socket inherits socket { node_bind }

次のポリシーキャパビリティが有効になっている場合、

policycap extended_socket_class;

SELinux SCTPサポートは、 name_connect 特定のポートタイプへの接続に必要な権限を追加し、 association 以下のセクションで説明される権限を追加します。

ユーザー空間ツールが更新されている場合、SCTPは以下のステートメントをサポートします： portcon 次の例のように表示されます：

portcon sctp 1024-1036 system_u:object_r:sctp_ports_t:s0

SCTP ペアラベル¶

SCTPソケットには1つのペアラベルのみが割り当てられます。これは最初のアソシエーションの確立時に割り当てられ、このソケット上の追加のアソシエーションでは、パケットのペアラベルがソケットのペアラベルと比較され、異なる場合にのみ、 association 権限が検証されます。これは、ソケットのペア sidと受信パケットのペア sidを比較して、アソシエーションが許可されるか拒否されるかを決定します。

ノート：

  1. ペアラベルが有効でない場合、ペアコンテキストは常に SECINITSID_UNLABELED (unlabeled_t （参照ポリシー）に設定されます。

  2. SCTPは単一のソケットでエンドポイントごとに複数のトランスポートアドレス（マルチホーム）をサポートできるため、ポリシーやNetLabelを用いて各アドレスに対して異なるペアラベルを設定することが可能です。ソケットのペアラベルは最初のアソシエーションのトランスポートアドレスによって決定されるため、すべてのペアラベルが一貫していることを推奨します。

  3. getpeercon(3)はユーザー空間でソケットのペアコンテキストを取得するために使用できます。

  4. NetLabelを使用する際には、特定のインターフェースにラベルが割り当てられ、そのインターフェースがダウンした場合、NetLabelサービスがエントリを削除します。そのため、ネットワーク起動スクリプトで netlabelctl(8)を呼び出して必要なラベルを設定してください（詳細は netlabel-config(8)のヘルパースクリプトを参照してください）。

  5. NetLabel SCTPペアラベルルールについては、以下の「netlabel」タグの投稿で説明されています： https://www.paul-moore.com/blog/t.

  6. CIPSOはIPv4アドレスのみにサポートされます： socket(AF_INET, ...) CALIPSO は IPv6 アドレス指定でのみサポートされています: socket(AF_INET6, ...)

    CIPSO/CALIPSO のテスト時に以下の点にご注意ください:

    1. SCTP パケットが無効なラベルのため届けられなかった場合、CIPSO は ICMP パケットを送信します。

    2. CALIPSO は ICMP パケットを送信せず、静かに破棄します。

  7. RFC 3554 に準拠していないため、IPSEC はサポートされていません - ユーザースペースでの sctp/ipsec サポートは実装されていません（racoon(8) または ipsec_pluto(8))、ただしカーネルは SCTP/IPSEC をサポートしています。
