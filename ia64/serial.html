シリアルデバイス¶

シリアルデバイスの命名規則¶

2.6.10以降、ia64プラットフォームにおけるシリアルデバイスはACPIとPCIの列挙順に基づいて名前が付けられます。ACPIネームスペース内の最初のデバイス（存在する場合）は/dev/ttyS0、2番目は/dev/ttyS1、というように順番に割り当てられ、PCIデバイスはACPIデバイスの後に連続して/dev/ttyS0から開始して名前が付けられます。

2.6.10以前は、このルールにはいくつかの混乱を招く例外がありました：

  • 一部のマシン（主にHP製）のファームウェアはHCDPテーブル[1]を提供し、カーネルにシリアルコンソールとして使用可能なデバイス情報を伝えます。ユーザーが「console=ttyS0」を指定した場合、またはEFI ConOutパスにUARTデバイスのみが含まれる場合、カーネルはHCDPで記述されたデバイスを/dev/ttyS0として登録します。

  • HCDPが存在しない場合、伝統的なCOMポートアドレス（I/Oポート0x3f8および0x2f8）にUARTが存在すると仮定し、カーネルはそれらを/dev/ttyS0および/dev/ttyS1として登録します。

追加のACPIまたはPCIデバイスは、/dev/ttyS0の後に発見順に順次登録されます。

HCDPがある場合、デバイス名はEFIの設定や「console=」引数によって変化します。HCDPがない場合、デバイス名は変化しませんが、実際には存在しないデバイスを登録してしまう可能性があります。

例えば、HP rx1600の単一のビルインシリアルポート（ACPIネームスペースで記述）とMP[2]（PCIデバイス）を持つマシンでは、以下のポートがあります：

コンソール選択¶

EFIはコンソールデバイスの情報を把握していますが、カーネルにそれらの位置を正確に伝えるには十分ではありません。DIG64 HCDPテーブル[1]はシリアルコンソールデバイスの位置を伝えますが、すべてのファームウェアが提供するわけではありません。また、EFIは複数のコンソールを同時にサポートしており、カーネルに「プライマリ」のコンソールを指定する情報は提供しません。

では、Linuxにどのコンソールデバイスを使用させるかを指定する方法はありますか？

  • ファームウェアがHCDPを提供する場合、EFIに単一のデバイス（UARTまたはVGAカード）をコンソールとして指定するだけで、カーネルに何も指定しなくても自動的にEFIコンソールを使用します。

    (これは2.6.6以降に限ります。それ以前のバージョンでは「console=ttyS0」を指定しないとシリアルコンソールが得られませんでした。)

  • HCDPがない場合、LinuxはVGAコンソールをデフォルトとして使用します。ただし「console=」引数を指定すればその設定を上書きできます。

注意: シリアルコンソールデバイスが/dev/ttyS0であると仮定しないでください。ttyS1、ttyS2などになる可能性があります。/etc/inittab（getty用）および/etc/securetty（rootログインを許可するため）に適切なエントリがあることを確認してください。

早期シリアルコンソール¶

カーネルがシリアルコンソールを使用できるのは、デバイスの位置を把握した後です。通常はドライバーがシリアルデバイスをすべて列挙するタイミングで発生しますが、カーネルの起動後数分以上かかることがあります。

2.6.10以降のカーネルには「early uart」と呼ばれるドライバーがあり、起動プロセスの初期段階で動作します。ユーザーが「console=uart,io,0x3f8」などの引数を指定するか、EFIコンソールパスにUARTデバイスのみが含まれておりファームウェアがHCDPを提供する場合、カーネルが自動的にこのドライバーを使用します。

シリアルコンソールの問題のトラブルシューティング¶

eliloが「Uncompressing Linux… done」と表示した後、カーネルの出力がない場合:

  • 「console=ttyS0」と指定しましたが、LinuxがttyS0に割り当てているデバイスを変更しました。1つのEFIコンソールデバイス[3]を設定し、「console=」オプションを削除してください。

  • EFIコンソールパスにVGAデバイスとUARTが両方含まれています。EFIおよびeliloは両方を使用しますが、LinuxはデフォルトでVGAを使用します。EFIコンソールパスからVGAデバイスを削除してください[3]。

  • 複数のUARTがEFIコンソールデバイスとして選択されています。EFIおよびeliloはすべての選択されたデバイスを使用しますが、Linuxは1つだけ使用します。EFIコンソールパスに1つのUARTのみを指定してください[3]。

  • HP MPポート[2]に接続されていますが、EFIコンソールデバイスとして非MP UARTを選択しています。EFIはMPをコンソールデバイスとして使用します（明示的に選択しなくても）。コンソールケーブルを非MP UARTに接続するか、EFIコンソールパス[3]をMP UARTに変更してください。

「Uncompressing Linux… done」と開始のカーネル出力の間に60秒以上の長時間の待機:

  • 早期コンソールがないのは「console=ttyS<n>」を使用したためです。ファームウェアがHCDPを提供する場合、「console=」オプションを削除してください。

  • HCDPがない場合、カーネルはドライバーがシリアルデバイスを検出するまでコンソールの位置を把握できません。使用する場合は「console=uart,io,0x3f8」（または機種に応じた適切なアドレス）を指定してください。

カーネルおよびinitスクリプトの出力は正常ですが、「login:」プロンプトがない:

  • コンソールtty用のgettyエントリを/etc/inittabに追加してください。コンソールがttyS<n>であることを示す「Adding console on ttyS<n>」メッセージを探してください。

「login:」プロンプトがあるが、rootとしてログインできない:

  • コンソールtty用のエントリを/etc/securettyに追加してください。

2.6.17以降でACPIシリアルデバイスが見つからない:

  • CONFIG_PNP と CONFIG_PNPACPI を有効にしてください。2.6.17 以前では ACPI シリアルデバイスは 8250_acpi によって検出されていました。2.6.17 からは 8250_pnp と CONFIG_PNPACPI の組み合わせが 8250_acpi の代わりに使用されるようになりました。

[1]

http://www.dig64.org/specifications/agreement この表はもともと「HCDP（Headless Console/Debug Port）」として定義されていました。現在のバージョンは「PCDP（Primary Console and Debug Port Devices）」として定義されています。

[2]

HP MP（マネジメントプロセッサ）は複数の UART を提供する PCI デバイスです。そのうちの 1 つがコンソールとしてよく使用され、EFI Boot Manager はこれを「Acpi(HWP0002,700)/Pci(…)/Uart」として識別します。外部接続は通常 25ピンコネクタで、特別なdongleがこれを3つの9ピンコネクタに変換し、そのうちの1つに「コンソール」とラベルが付けられます。

[3]

EFI コンソールデバイスの設定は EFI Boot Manager の「ブートオプションメンテナンス」メニューで行います。このメニューを使用するにはブートセッションを中断する必要があり、コンソール設定を変更した後は機器を再起動する必要があります。
