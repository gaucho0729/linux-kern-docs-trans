Ioctl ナンバー¶

1999年10月19日

マイケル・エリザベス・チャスタイン <mec@shout.net>

カーネルに新しいioctlを追加する場合、<linux/ioctl.h>で定義されている_IOマクロを使用すべきです：

_IO

an

パラメータを持たないioctl

_IOW

an

書き込みパラメータを持つioctl (copy_from_user)

_IOR

an

読み込みパラメータを持つioctl (copy_to_user)

_IOWR

an

書き込みと読み込みの両方を持つioctl。

「書き込み」と「読み込み」はユーザーの観点からのもので、システムコールの「write」と「read」と同じです。たとえば、SET_FOO ioctlは_IOWを使用しますが、カーネルは実際にはユーザー空間からデータを読み取ります。GET_FOO ioctlは_IORを使用しますが、カーネルは実際にはユーザー空間にデータを書き込みます。

_IO、_IOW、_IOR、または_IOWRの最初の引数は、以下の表にある識別文字または数字から選ぶことができます。多くのドライバが他のドライバと部分的に同じ文字を使用しているためです。

新しいデバイス用のドライバを書いている場合で、文字が必要な場合は、拡張可能なスペースを確保するため、32〜256のioctlコマンドを持つ未使用のブロックを選んでください。このファイルをパッチしてこのファイルにパッチを適用し、Linus Torvaldsにパッチを送信することでブロックを登録できます。または、<mec>にメールを送って、私がブロックを登録します。mec@shout.net>

_IO、_IOW、_IOR、または_IOWRの第二引数は、ioctl同士を区別するためのシーケンス番号です。_IOW、_IOR、または_IOWRの第三引数は、カーネルに渡すデータまたはカーネルから出力するデータの型（例: 'int' や 'struct foo'）です。注意！第三引数としてsizeof(arg)を使用しないでください。これにより、ioctlがsize_t型の引数を渡すと誤解されます。

一部のデバイスでは、メジャーナンバーを識別子として使用しています。これは一意であれば問題ありません。一部のデバイスはまったく異なる規則に従っていません。

この規則に従うことは良いです：

  1. ioctlをグローバルに一意に保つことで、エラー検出が容易になります。プログラムが正しいデバイスでioctlを呼び出さない場合、エラーが発生する代わりに予期せぬ動作が起こらないようにします。

  2. straceのビルド手順は、_IO、_IOW、_IOR、または_IOWRで定義されたioctl番号を自動的に検出します。

  3. straceは、番号が一意であれば、その番号を有用な名前にデコードできます。

  4. この規則でioctl番号を定義している場合、ioctlの検索がgrepでより簡単にできます。

  5. この規則に従う場合、ドライバコードはユーザー空間とカーネル空間のパラメータをコピーするための汎用コードを使用できます。

この表は、Linux/x86でユーザーランドから見えるioctlの一覧です。2.6.31までのほとんどのドライバを含んでいますが、いくつかは抜けている可能性があります。非X86アーキテクチャやdrivers/staging/からのioctlはリストアップされていません。
