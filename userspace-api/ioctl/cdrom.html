以下に示す情報は、カーネルソースコードの読み込みから得られたものです。時間とともに修正される可能性があります。

一般:

指定がない限り、すべてのioctl呼び出しは成功時は0を、エラー時はerrnoに適切な値を設定して-1を返します。（一部のioctlは非負のデータ値を返します。）

指定がない限り、すべてのioctl呼び出しはデータのコピーに失敗した場合、ユーザーアドレス空間へのコピーに失敗した際に-1を返し、errnoにEFAULTを設定します。

個々のドライバーはここに記載されていないエラーコードを返す場合があります。

指定がない限り、すべてのデータ構造体と定数は<linux/cdrom.h>で定義されています。

CDROMPLAYMSF

オーディオを再生 (MSF)

(struct cdrom_msf)

usage:

struct cdrom_msf msf;

ioctl(fd, CDROMPLAYMSF, &msf);
入力:

cdrom_msf構造体、音楽を再生するセグメントを記述します

出力:

none

エラー戻り値:

  • ENOSYS CDドライブがオーディオ機能を備えていない

  • MSFは分-秒-フレームを表します

  • LBAは論理ブロックアドレスを表します

  • セグメントは開始時間と終了時間を記述します。時間は分:秒:フレームで表され、フレームは1/75秒です。

CDROMREADRAW

rawモードでデータを読み込み（2352バイト）

(struct cdrom_read)

usage:

union {

  struct cdrom_msf msf;               /* input */
  char buffer[CD_FRAMESIZE_RAW];      /* return */
} arg;
ioctl(fd, CDROMREADRAW, &arg);
入力:

cdrom_msf構造体、読み込むアドレスを示します

開始値のみが重要です

出力:

ユーザーが提供したアドレスにデータが書き込まれます

エラー戻り値:

  • EINVAL address less than 0, or msf less than 0:2:0

  • ENOMEM メモリ不足

注:

  • 2.6.8.1以降、<linux/cdrom.h>のコメントによると、このioctlはcdrom_read構造体を受け入れるが、実際のソースコードはcdrom_msf構造体を読み込み、同じアドレスにデータバッファを書き込む。

  • MSF値は以下の式によりLBA値に変換される：

    lba = (((m * CD_SECS) + s) * CD_FRAMES + f) - CD_MSF_OFFSET;

CDROM_GET_MCN

「ユニバーサル製品コード（UPC）」を取得（存在する場合）

(struct cdrom_mcn)

ioctl(fd, CDROM_GET_MCN, &mcn);
入力:

none

出力:

（UPC）。この番号は、製品のバーコードに通常表示される番号を反映する必要があります。残念ながら、このような番号をディスクに記録しているディスクは少なく、それらのフォーマットすら異なる場合があります。

注:

  • ソースコードコメントは以下の通り：

    The following function is implemented, although very few
audio discs give Universal Product Code information, which
should just be the Medium Catalog Number on the box.  Note,
that the way the code is written on the CD is /not/ uniform
across all discs!

    Ok, this is where problems start.  The current interface for
the CDROM_DISC_STATUS ioctl is flawed.  It makes the false
assumption that CDs are all CDS_DATA_1 or all CDS_AUDIO, etc.
Unfortunately, while this is often the case, it is also
very common for CDs to have some tracks with data, and some
tracks with audio.      Just because I feel like it, I declare
the following to be the best way to cope.  If the CD has
ANY data tracks on it, it will be returned as a data CD.
If it has any XA tracks, I will return it as that.      Now I
could simplify this interface by combining these returns with
the above, but this more clearly demonstrates the problem
with the current interface.  Too bad this wasn't designed
to use bitmasks...             -Erik

Well, now we have the option CDS_MIXED: a mixed-type CD.
User level programmers might feel the ioctl is not very
useful.
                ---david

CDROM_LOCKDOOR

ドアをロックまたはアンロック

usage:

int lock;

ioctl(fd, CDROM_LOCKDOOR, lock);
入力:

ドアロックフラグ、1=ロック、0=アンロック

出力:

none

エラー戻り:

  • EDRIVE_CANT_DO_THIS

    ドアロック機能がサポートされていません

  • EBUSY

    複数のユーザーがドライブを開いておりCAP_SYS_ADMINを取得していない場合のアンロック試行

注:

2.6.8.1以降、ロックフラグはグローバルロックとなり、すべてのCDドライブが一緒にロックまたはアンロックされます。これはおそらくバグです。

EDRIVE_CANT_DO_THISは<linux/cdrom.h>で定義されており、現在（2.6.8.1）ではEOPNOTSUPPと同じです

ioctlの戻り値は現在のデバイスキャパビリティフラグです。CDC_CLOSE_TRAY、CDC_OPEN_TRAYなど参照してください

CDROMAUDIOBUFSIZ

オーディオバッファサイズを設定

usage:

int arg;

ioctl(fd, CDROMAUDIOBUFSIZ, val);
入力:

新しいオーディオバッファサイズ

出力:

ioctlの返戻値は新しいオーディオバッファサイズであり、エラーの場合は-1です。

エラー戻り値:

  • ENOSYS このドライバーではサポートされていません。

注:

すべてのドライバーではサポートされていません。

DVD_READ_STRUCT 読み込み構造体

usage:

dvd_struct s;

ioctl(fd, DVD_READ_STRUCT, &s);
入力:

dvd_struct構造体、含まれる情報は以下の通り:

type

必要な情報を指定し、DVD_STRUCT_PHYSICAL、DVD_STRUCT_COPYRIGHT、DVD_STRUCT_DISCKEY、DVD_STRUCT_BCA、DVD_STRUCT_MANUFACT のいずれかを指定します。

physical.layer_num

望むレイヤー、インデックスは0から

copyright.layer_num

望むレイヤー、インデックスは0から

disckey.agid
出力:

dvd_struct構造体、含まれる情報は以下の通り:

物理

タイプが DVD_STRUCT_PHYSICAL の場合

copyright

タイプが DVD_STRUCT_COPYRIGHT の場合

disckey.value

タイプが DVD_STRUCT_DISCKEY の場合

bca.{len,value}

タイプが DVD_STRUCT_BCA の場合

manufact.{len,valu}

タイプが DVD_STRUCT_MANUFACT の場合
エラー戻り:

  • EINVAL physical.layer_num がレイヤー数を超えています

  • EIO ドライブから無効な応答を受信しました

DVD_WRITE_STRUCT 書き込み構造体

2.6.8.1以降、実装されていない

dvd_authinfo ai;

入力:

dvd_authinfo構造体。詳しくは <linux/cdrom.h> を参照してください。

出力:

dvd_authinfo構造体。

CDROM_SEND_PACKET

ドライブにパケットを送信

usage:

struct cdrom_generic_command cgc;

ioctl(fd, CDROM_SEND_PACKET, &cgc);
入力:

送信するパケットを含む cdrom_generic_command 構造体

出力:

none

結果を含む cdrom_generic_command 構造体

エラー戻り値:

  • EIO

    コマンドが失敗しました。

  • EPERM

    操作が許可されていません。これは、読み取り専用で開いたドライブに書き込みコマンドを実行しようとした場合、または CAP_SYS_RAWIO が要求されるコマンドの場合です。

  • EINVAL

    cgc.data_direction が設定されていません

CDROM_NEXT_WRITABLE

long next;

ioctl(fd, CDROM_NEXT_WRITABLE, &next);
入力:

none

CDROM_LAST_WRITTEN

ディスク上の最後に書き込まれたブロックを取得

usage:

long last;

入力:

none

出力:
