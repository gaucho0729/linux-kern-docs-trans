新しい特権のないフラグ¶

execve システムコールは、新たに開始されたプログラムに親プロセスが持っていなかった権限を付与する可能性があります。setuid/setgid プログラムやファイルキャパビリティなど、最も明らかな例があります。親プロセスがこれらの権限を取得することを防ぐため、カーネルとユーザーコードは、子プロセスを侵害する可能性のある操作を親プロセスが行わないように注意する必要があります。例えば：

  • ダイナミックローダーは処理します LD_* プログラムがsetuidモードで実行されている場合、環境変数の扱いが異なります。

  • 非特権プロセスはchrootを使用できず、これはプロセスがch拡張を継承した場合に置き換えられることを許可するからです。 /etc/passwd プロセスがchrootを継承した場合、そのプロセスの観点からchrootが置き換えられることを許可します。

  • execコードにはptraceに対する特別な処理が含まれています。

これらはすべて一時的な修正です。The no_new_privs bit（Linux 3.5以降）は、プロセスがexecveを呼び出すことなく、実行環境を変更する際に安全にするための新しい汎用的なメカニズムです。任意のタスクが設定できます。 no_new_privsbitが設定されると、fork、clone、execveを跨っても継承され、解除することはできません。With no_new_privs が設定されていると、 execve() execve呼び出しをしなければ実行できなかった操作を行う権限を付与しないという約束があります。例えば、setuidとsetgid bitはuidやgidを変更しなくなり、ファイルの_capabilitiesは許可セットに追加されず、LSMsはexecve後に制約を緩和しません。

設定する no_new_privsにエクスポートするには、次のようにします：

prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0);

ただし、LSMsはexecの制約を厳格化しない可能性があります no_new_privs モードです。(これは、一般的なサービス起動プログラムを設定して no_new_privs デーモンを実行する前に設定すると、LSMベースのサンドボックスングに干渉する可能性があります。)
