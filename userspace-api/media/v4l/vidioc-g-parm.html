7.37. ioctl VIDIOC_G_PARM, VIDIOC_S_PARM¶

7.37.1. 名前¶

VIDIOC_G_PARM - VIDIOC_S_PARM - ストリーミングパラメータの取得または設定

7.37.2. 概要¶

VIDIOC_G_PARM¶

int ioctl(int fd, VIDIOC_G_PARM, v4l2_streamparm *argp)

VIDIOC_S_PARM¶

int ioctl(int fd, VIDIOC_S_PARM, v4l2_streamparm *argp)

7.37.3. 引数¶

fd

返されるファイル記述子 open().

argp

struct mem_ctl_info v4l2_streamparm.

7.37.4. 説明¶

アプリケーションは異なるフレーム間隔を要求できます。キャプチャまたは出力デバイスは、可能であれば要求されたフレーム間隔に対応するよう再構成されます。オプションでドライバは、要求されたフレーム間隔を達成するためにフレームをスキップしたり繰り返したりする場合があります。

ステートフルエンコーダー（参照 メモリ対メモリ ステートフル ビデオ エンコーダー インターフェース) では、通常、符号化されたビデオストリームに埋め込まれるフレーム間隔を表します。

フレーム間隔を変更してもフォーマットは変更されません。一方で、フォーマットを変更するとフレーム間隔が変わる可能性があります。

さらに、これらのioctlは、ドライバが読み書きモードで内部的に使用するバッファ数を確認するために使用できます。影響については、以下のセクションを参照してください。 read() function.

ストリーミングパラメータを取得および設定するには、アプリケーションはioctlを呼び出します。 VIDIOC_G_PARM および VIDIOC_S_PARM ioctlをそれぞれ呼び出します。これらは、構造体へのポインタを引数として受け取ります。 v4l2_streamparm これは、入力および出力デバイス用の個別パラメータを保持するユニオンを含みます。

struct v4l2_fract

timeperframe

これは、ドライバがキャプチャする連続するフレーム間の望ましい期間（秒単位）です。

これはビデオソース（例：センサー）がビデオフレームを生成する速度を設定します。速度が固定されている場合、ドライバは要求されたフレームレートを達成するためにフレームをスキップしたり繰り返したりする場合があります。

ステートフルエンコーダー（参照 メモリ対メモリ ステートフル ビデオ エンコーダー インターフェース) では、通常、符号化されたビデオストリームに埋め込まれるフレーム間隔を表します。

アプリケーションはここに望ましいフレーム期間を保存し、ドライバは実際のフレーム期間を返します。

ビデオ標準（ビデオ入力の切り替えによっても暗に含む）を変更すると、このパラメータがノーマルフレーム期間にリセットされることがあります。手動でリセットする場合は、このフィールドをゼロに設定するだけでよいです。

ドライバはこの機能をサポートする場合、必ずこのフィールドを設定する必要があります。 V4L2_CAP_TIMEPERFRAME フラグを含めます。以下のようにします： capability フィールドによって保護されています。

__u32

extendedmode

カスタム（ドライバ固有）ストリーミングパラメータ。使用しない場合は、アプリケーションおよびドライバはこのフィールドをゼロに設定する必要があります。このフィールドを使用するアプリケーションは、ドライバ名とバージョンを確認する必要があります、参照 キャパビリティの照会.

V4L2_CAP_TIMEPERFRAME

0x1000

フレーム期間は、 timeperframe フィールドによって保護されています。
キャプチャパラメータフラグ¶

V4L2_MODE_HIGHQUALITY

0x0001

高品質イメージングモード。高品質モードは静止画撮影アプリケーションに適しています。目的は、ハードウェアが提供できる最高の画像品質を取得することです。ドライバ開発者がどのようにこれを達成するかは定義されていません。ハードウェアやドライバ開発者の創造性に依存します。高品質モードは通常の動画キャプチャモードとは異なるモードです。高品質モードでは：

  • ドライバーは、動画キャプチャよりも高い解像度をキャプチャできる可能性があります。

  • ドライバーは、動画キャプチャより少ないピクセル形式をサポートする可能性があります（例：真色）。

  • ドライバーは、複数の連続するフィールドまたはフレームをキャプチャし、算術的に組み合わせて色エッジのアーティファクトを除去し、ビデオデータのノイズを減らす可能性があります。

  • ドライバーは、スキャナーのようにスライスで画像をキャプチャし、それにより通常では可能でないより大きなフォーマットの画像を処理できる可能性があります。

  • 画像キャプチャ操作は、動画キャプチャよりも大幅に遅くなる可能性があります。

  • 画像内の動く物体は過度な運動ぼけを持つ可能性があります。

  • キャプチャは、この read() 呼び出し時にkdumpが発生します。

7.37.5. 戻り値¶

成功した場合、0 が返されます。エラーの場合、-1 が返され、変数が適切に設定されます。 errno 一般的なエラーコードは、 汎用エラーコード 章。
