7.3. ioctl VIDIOC_CREATE_BUFS¶

7.3.1. 名前¶

VIDIOC_CREATE_BUFS - メモリマップまたはユーザーポインタまたはDMAバッファI/O用のバッファを生成

7.3.2. 概要¶

VIDIOC_CREATE_BUFS¶

int ioctl(int fd, VIDIOC_CREATE_BUFS, struct v4l2_create_buffers *argp)

7.3.3. 引数¶

fd

返されるファイル記述子 open().

argp

struct mem_ctl_info v4l2_create_buffers.

7.3.4. 説明¶

このioctlは、バッファを生成するために使用されます メモリマップ または ユーザーポインタ または DMAバッファ I/O。必要な制御が求められる場合、このioctlは既存のioctlの代替または補完として使用できます。このioctlは複数回呼び出され、異なるサイズのバッファを生成できます ioctl VIDIOC_REQBUFS ioctl

デバイスバッファを割り当てるには、structの関連するフィールドを初期化する必要があります v4l2_create_buffers 構造体を参照します。 count フィールドに要求されたバッファ数を設定し、 memory フィールドに要求されたI/Oメソッドを指定し、 reserved 配列をゼロに初期化する必要があります

以下の format フィールドにバッファが処理可能な画像形式を指定します。アプリケーションはこのstructを埋め込む必要があります v4l2_format。通常は、 VIDIOC_TRY_FMT または VIDIOC_G_FMT ioctlを使用して、要求された形式がドライバでサポートされていることを確認します。形式の type フィールドに基づき、単一プランナーフォーマットの場合は要求されたバッファサイズ、マルチプランナー形式の場合は各プランナーのサイズが、割り当てられたバッファに使用されます。ドライバは、ハードウェアがサポートしないサイズ（通常はサイズが小さすぎる場合）に対してエラーを返す可能性があります

このioctlで生成されたバッファは、 format.pix.sizeimage フィールド（またはその他のフォーマットタイプの対応するフィールド）で定義された最小サイズを持ちます。通常、 format.pix.sizeimage フィールドが指定された形式の最小要件よりも小さい場合、ドライバーが通常この操作を許可しないためエラーが返されます。逆に大きい場合は、値はそのまま使用されます。言い換えれば、ドライバーが要求されたサイズを拒否する可能性がありますが、受け入れられた場合は変更せずに使用します。

ioctlコマンドがこの構造体へのポインタを引数として呼ばれた場合、ドライバーは要求されたバッファ数までの割当を試み、実際に割当たった数と開始インデックスをこの構造体のフィールドに保存します。 count 2.5開発シリーズで導入された形式です。 index それぞれのフィールドに保存します。戻り値時に count 実際に割当たった数は要求された数より小さくなる場合があります。

成功した場合、0 が返されます。エラーの場合、-1 が返され、変数が適切に設定されます。 errno 一般的なエラーコードは、 汎用エラーコード 章。

ENOMEM
