7.24. ioctl VIDIOC_G_CROP, VIDIOC_S_CROP¶

7.24.1. 名前¶

VIDIOC_G_CROP - VIDIOC_S_CROP - 現在のクロッピング矩形を取得または設定する

7.24.2. 概要¶

VIDIOC_G_CROP¶

int ioctl(int fd, VIDIOC_G_CROP, struct v4l2_crop *argp)

VIDIOC_S_CROP¶

int ioctl(int fd, VIDIOC_S_CROP, const struct v4l2_crop *argp)

7.24.3. 引数¶

fd

返されるファイル記述子 open().

argp

struct mem_ctl_info v4l2_crop.

7.24.4. 説明¶

クロッピング矩形のサイズと位置を照会するには、アプリケーションは type フィールドを設定します。 v4l2_crop 該当するバッファ（ストリーム）タイプに構造体を設定し、この構造体へのポインタを用いて ioctl を呼び出す VIDIOC_G_CROP ioctl を呼び出す。ドライバーは構造体の残りの部分を埋めたり、クロッピングがサポートされていない場合にエラーコードを返したりします EINVAL エラーコードを返したりします

クロッピング矩形を変更するには、アプリケーションは type および struct v4l2_rect ioctlを設定します。ドライバは構造体 c v4l2_crop 構造体を初期化し、この構造体へのポインタを用いて ioctl を呼び出す VIDIOC_S_CROP この構造体へのポインタでioctlを実行します。

ドライバーはまず、要求された寸法をハードウェアの制限と比較し、キャプチャ/出力ウィンドウで指定される境界に基づいて、水平および垂直オフセット、幅および高さの最も近い値に調整します。特に、ドライバーはクロッピング矩形の垂直オフセットをフレームラインのモジュロ2に丸めなければなりません。これにより、フィールド順序が混同されることを防ぎます。

ドライバーは、現在の水平方向および垂直方向のスケーリングファクターを維持しながら、スケーリングプロセスの逆の矩形（データの方向によってソースまたはターゲットとなる）を可能な限り近いサイズに調整します。

最後に、ドライバーはハードウェアに実際のクロッピングおよび画像パラメータを設定します。 VIDIOC_S_CROP これは読み取り専用のioctlであり、実際のパラメータを返しません。パラメータを照会するには、アプリケーションが VIDIOC_G_CROP および ioctl VIDIOC_G_FMT, VIDIOC_S_FMT, VIDIOC_TRY_FMTを呼び出す必要があります。パラメータが不適切な場合、アプリケーションはクロッピングまたは画像パラメータを修正し、満足できるパラメータが交渉されるまでサイクルを繰り返します。

クロッピングがサポートされていない場合、パラメータは変更されず、 VIDIOC_S_CROP 返す EINVAL エラー コードに設定します。

type v4l2_crop¶
struct v4l2_crop¶

__u32

type

および以下の注記。 V4L2_BUF_TYPE_VIDEO_CAPTURE, V4L2_BUF_TYPE_VIDEO_CAPTURE_MPLANE, V4L2_BUF_TYPE_VIDEO_OUTPUT, V4L2_BUF_TYPE_VIDEO_OUTPUT_MPLANE および V4L2_BUF_TYPE_VIDEO_OVERLAYのみ v4l2_buf_type キャプチャまたは出力が可能な領域を定義し、水平および垂直ブランク領域を含む可能性があります。クロッピング矩形はこれらの制限を超えてはなりません。幅と高さはピクセル単位で定義され、ドライバ開発者はアナログドメインの座標系の原点と単位を選択する自由があります。

struct v4l2_rect

c

クロッピング矩形。これはstruct v4l2_cropcap bounds が使用されます。

注意

残念なことに、マルチプレーンバッファタイプ（V4L2_BUF_TYPE_VIDEO_CAPTURE_MPLANE および V4L2_BUF_TYPE_VIDEO_OUTPUT_MPLANE) においてこのAPIは、フィールドの入力方法について誤って作成されてしまいました。一部のドライバはバッファタイプのみを受け入れ、他のドライバはマルチプレーンバッファタイプ以外（つまり、 v4l2_crop type のないバッファタイプのみ）を受け入れていました。 _MPLANE バッファタイプのみを受け入れていました。一部のドライバはバッファタイプのみを受け入れ、他のドライバはマルチプレーンバッファタイプ以外（つまり、 _MPLANE のないバッファタイプのみ）を受け入れていました。

カーネル4.13以降では、両方のバッファタイプが許可されます。

7.24.5. 戻り値¶

成功した場合、0 が返されます。エラーの場合、-1 が返され、変数が適切に設定されます。 errno 一般的なエラーコードは、 汎用エラーコード 章。

ENODATA

この入力または出力ではクロッピングがサポートされていません。
