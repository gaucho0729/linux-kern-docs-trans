4.5.2. メモリ対メモリ ステートフル ビデオ エンコーダー インターフェース¶

ステートフルビデオエンコーダーは、ディスプレイ順に並んだRAWビデオフレームを入力として、それをバイナリストリームにエンコードします。このエンコーダーは、バイナリストリームの完全なチャンク（メタデータ、ヘッダなどすべてを含む）を生成し、結果として得られるバイナリストリームはクライアントによる追加の後処理が不要です。

このインターフェースをサポートするためにドライバ内でソフトウェアによるストリーム処理、ヘッダ生成などを実行することは強く推奨されません。このような操作が必要な場合は、ステートレスビデオエンコーダーインターフェース（開発中）の使用を強く推奨します。

4.5.2.7. エンコードパラメータの変更¶

エンコード中に各パラメータを変更できるかどうかはエンコーダー固有であり、V4L2コントロールインターフェースの標準的なセマンティクスに従います。クライアントはエンコード中にコントロールを設定しようとし、操作が-EBUSYエラー コードで失敗した場合、 CAPTURE キューを停止する必要があります。これを実行するには、以下の手順に従うことができます。 シーケンスと同様です 既にキューイング/エンコードされたフレームを失わないようにするための手順を実行します。

  3. 形式をデコーダーに設定する OUTPUT キューは、そのキューに利用可能な形式の一覧を変更しません。 CAPTURE キュー。フォーマットを設定する試みは、 OUTPUT 形式を設定しようとすると、デコーダーが要求された形式をサポートされている形式に調整します。 CAPTURE エンコーダーが要求された OUTPUT 形式をサポートされている形式に調整します。

  5. バッファがどのキューにも割り当てられている間、クライアントは OUTPUT または CAPTURE キューで形式を変更してはいけません。 CAPTURE キュー。ドライバーは、このような形式変更の試みに対して-EBUSYエラーコードを返します。
