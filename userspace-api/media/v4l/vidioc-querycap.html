7.48. ioctl VIDIOC_QUERYCAP¶

7.48.1. 名前¶

VIDIOC_QUERYCAP - デバイスの機能を照会する

7.48.2. 概要¶

VIDIOC_QUERYCAP¶

int ioctl(int fd, VIDIOC_QUERYCAP, struct v4l2_capability *argp)

7.48.3. 引数¶

fd

返されるファイル記述子 open().

argp

struct mem_ctl_info v4l2_capability.

7.48.4. 説明¶

すべてのV4L2デバイスは以下のioctlをサポートしています。 VIDIOC_QUERYCAP ioctl. これは、この仕様と互換性のあるカーネルデバイスを特定し、ドライバーおよびハードウェアの機能に関する情報を取得するために使用されます。ioctlは、struct v4l2_capabilityへのポインタを引数として受け取り、ドライバーがこの仕様と互換性がない場合、ioctlは v4l2_capability struct v4l2_capabilityを返します。 EINVAL エラー コードに設定します。

type v4l2_capability¶
struct v4l2_capability¶

__u8

driver[16]

ドライバー名。一意のNULL終端ASCII文字列です。例: "bttv"。ドライバー固有のアプリケーションは、この情報を使用してドライバーの識別を確認できます。また、既知のバグの回避やエラーレポートでのドライバーの特定にも有用です。

固定サイズの配列に文字列を保存することは悪い実装ですが、ここでは避けられません。ドライバーおよびアプリケーションは、配列の終端を超えて読み書きしないように注意し、文字列が正しくNULL終端されていることを確認する必要があります。

__u8

card[32]

デバイス名。NULL終端UTF-8文字列です。例: "Yoyodyne TV/FM"。1つのドライバーが異なるブランドやモデルのビデオハードウェアをサポートする場合があります。この情報はユーザー向けで、例として利用可能なデバイスの一覧メニューに表示されます。同じブランドの複数のTVカードが同じドライバーでサポートされる場合、この名前はキャラクターデバイスファイル名と組み合わせて（例: "platform:vivid-000"）曖昧さを避ける必要があります。 /dev/video2のいずれかを使用します。 bus_info 文字列を組み合わせることで曖昧さを避けることができます。

__u8

bus_info[32]

システム内のデバイスの場所。NULL終端ASCII文字列です。例: "PCI:0000:05:06.0"。この情報はユーザー向けで、複数の同一デバイスを区別するためのものです。このような情報が利用できない場合は、ドライバーが制御するデバイスの数を単純にカウントする必要があります（例: "platform:vivid-000"）。bus_infoはPCIボードの場合"PCI:"、PCI Expressボードの場合"PCIe:"、USBデバイスの場合"usb-"、I2Cデバイスの場合"I2C:"、ISAデバイスの場合"ISA:"、並列ポートデバイスの場合"parport"、プラットフォームデバイスの場合"platform:"で始める必要があります。

__u32

version

ドライバーのバージョン番号。

カーネル3.1以降、報告されるバージョン番号はV4L2サブシステムが提供し、カーネルのバージョン番号スキームに従います。ただし、例として安定版や配布版がカーネルのV4L2スタックを新しいバージョンから使用する場合、常に同じバージョン番号を返すとは限りません。

バージョン番号は以下のマクロを使用してフォーマットされます。 KERNEL_VERSION() マクロ。例えば、メディアスタックがカーネル4.14に同梱されたV4L2バージョンに対応する場合、以下のようになります:

#define KERNEL_VERSION(a,b,c) (((a) << 16) + ((b) << 8) + (c))

__u32 version = KERNEL_VERSION(4, 14, 0);

printf ("Version: %u.%u.%u\\n",

(version >> 16) & 0xFF, (version >> 8) & 0xFF, version & 0xFF);

__u32

capabilities

物理デバイス全体の利用可能な機能を参照してください デバイス機能フラグ同じ物理デバイスが/devに複数のデバイスをエクスポートできます（例: /dev/videoX、/dev/vbiY、/dev/radioZなど）。The capabilities フィールドには、複数のV4L2デバイスがユーザー空間にエクスポートされる際のすべての機能を結合した集合を含める必要があります。すべてのこれらのデバイスでは、 capabilities フィールドが同じ機能セットを返します。これにより、アプリケーションは通常ビデオデバイスを開くだけで、ビデオ、VBIおよび/またはラジオのサポートがあるかどうかを確認できます。

__u32

device_caps

開いたデバイスの機能、参照 デバイス機能フラグ。特定のデバイスノードの利用可能な機能を含める必要があります。例えば、 device_caps ラジオデバイスの場合は、このフィールドにはラジオ関連の機能のみが含まれ、ビデオやVBIの機能は含まれません。このフィールドは、 capabilities フィールドが V4L2_CAP_DEVICE_CAPS 機能を含む場合にのみ設定されます。のみ capabilities フィールドが V4L2_CAP_DEVICE_CAPS 機能を持つことができます。 device_caps は決して設定されません V4L2_CAP_DEVICE_CAPS.

__u32

reserved[3]

今後の拡張用に予約されています。ドライバはこの配列をゼロに設定しなければなりません。

デバイスがシングルプランナーアプリケーションプログラミングインターフェース（API）をサポートしていることを示します。 ビデオキャプチャ インターフェースの構造体とioctlsを借用しています。

V4L2_CAP_VIDEO_CAPTURE_MPLANE

0x00001000

デバイスが マルチプランアピ を通じて ビデオキャプチャ インターフェースの構造体とioctlsを借用しています。

V4L2_CAP_VIDEO_OUTPUT

0x00000002

デバイスがシングルプランナーアプリケーションプログラミングインターフェース（API）をサポートしていることを示します。 ビデオ出力 インターフェースの構造体とioctlsを借用しています。

V4L2_CAP_VIDEO_OUTPUT_MPLANE

0x00002000

デバイスが マルチプランアピ を通じて ビデオ出力 インターフェースの構造体とioctlsを借用しています。

V4L2_CAP_VIDEO_M2M

0x00008000

シングルプランナーアプリケーションプログラミングインターフェース（API）をサポートしています。

V4L2_CAP_VIDEO_M2M_MPLANE

0x00004000

デバイスが マルチプランアピ ビデオメモリ対メモリインターフェースを通じてサポートしています。

V4L2_CAP_VIDEO_OVERLAY

0x00000004

デバイスが Video Overlay インターフェース。ビデオオーバーレイデバイスは通常、グラフィックカードのビデオメモリに直接キャプチャ画像を保存し、ハードウェアによるクロッピングとスケーリングを行います。

V4L2_CAP_VBI_CAPTURE

0x00000010

デバイスが Raw VBI Capture インターフェース。テレックステとクローズドキャプションデータを提供します。

V4L2_CAP_VBI_OUTPUT

0x00000020

デバイスが Raw VBI Output インターフェースの構造体とioctlsを借用しています。

V4L2_CAP_SLICED_VBI_CAPTURE

0x00000040

デバイスが Sliced VBI Capture インターフェースの構造体とioctlsを借用しています。

V4L2_CAP_SLICED_VBI_OUTPUT

0x00000080

デバイスが Sliced VBI Output インターフェースの構造体とioctlsを借用しています。

V4L2_CAP_RDS_CAPTURE

0x00000100

デバイスが RDS キャプチャインターフェース。

V4L2_CAP_VIDEO_OUTPUT_OVERLAY

0x00000200

デバイスが Video Output Overlay (OSD)インターフェース。これは、 Video Overlay インターフェースとは異なり、ビデオ出力デバイスの二次機能であり、出力ビデオ信号に画像をオーバーレイします。ドライバがこのフラグを設定する場合、必ず V4L2_CAP_VIDEO_OVERLAY フラグをクリアしなければなりません。逆もしかりです。 1

V4L2_CAP_HW_FREQ_SEEK

0x00000400

デバイスが ioctl VIDIOC_S_HW_FREQ_SEEK ハードウェア周波数検索用のioctl。

V4L2_CAP_RDS_OUTPUT

0x00000800

デバイスが RDS 出力インターフェース。

V4L2_CAP_TUNER

0x00010000

デバイスにRF変調されたビデオ信号を受信するためのチューナーが搭載されています。チューナーのプログラミングに関する詳細情報については、 チューナーとモジュレータ.

V4L2_CAP_AUDIO

0x00020000

デバイスにオーディオ入力または出力があります。オーディオ録音または再生をサポートしているかどうかは、PCMまたは圧縮形式のいずれかかもしれません。PCMオーディオサポートはALSAまたはOSSインターフェースとして実装しなければなりません。オーディオ入出力に関する詳細情報については、 オーディオ入出力.

V4L2_CAP_RADIO

0x00040000

これはラジオ受信機です。

V4L2_CAP_MODULATOR

0x00080000

デバイスにRF変調されたビデオ/オーディオ信号を送信するためのモジュレータが搭載されています。モジュレータのプログラミングに関する詳細情報については、 チューナーとモジュレータ.

V4L2_CAP_SDR_CAPTURE

0x00100000

デバイスが SDR Capture インターフェースの構造体とioctlsを借用しています。

V4L2_CAP_EXT_PIX_FORMAT

0x00200000

デバイスが構造体 v4l2_pix_format 拡張フィールドをサポートしています。

V4L2_CAP_SDR_OUTPUT

0x00400000

デバイスが SDR Output インターフェースの構造体とioctlsを借用しています。

V4L2_CAP_META_CAPTURE

0x00800000

デバイスが メタデータインターフェース キャプチャインターフェース。

V4L2_CAP_READWRITE

0x01000000

デバイスが read() および/または write() I/Oメソッド。

V4L2_CAP_ASYNCIO

0x02000000

デバイスが 非同期 I/Oメソッド。

V4L2_CAP_STREAMING

0x04000000

デバイスが ストリーミング I/Oメソッド。

V4L2_CAP_META_OUTPUT

0x08000000

デバイスが メタデータインターフェース 出力インターフェース。

V4L2_CAP_TOUCH

0x10000000

これはタッチデバイスです。

V4L2_CAP_IO_MC

0x20000000

ユーザー空間から見た入力および/または出力は1つだけです。入力/出力にどのI/Oエンティティがルーテッドされるかを含むすべてのビデオトポロジー構成は、Media Controllerを介してユーザー空間によって設定されます。参照 第 IV 章 - Media Controller API.

V4L2_CAP_DEVICE_CAPS

0x80000000

ドライバーがフィールドを埋めます device_caps フィールド。この機能は常にフィールドにのみ現れます capabilities フィールドであり、決してフィールドには現れません device_caps フィールドによって保護されています。

7.48.5. 戻り値¶

成功した場合、0 が返されます。エラーの場合、-1 が返され、変数が適切に設定されます。 errno 一般的なエラーコードは、 汎用エラーコード 章。
