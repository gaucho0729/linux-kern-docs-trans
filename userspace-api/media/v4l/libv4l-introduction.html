5.1. はじめに¶

libv4l は、video4linux2 デバイスの上に薄い抽象化レイヤーを提供するライブラリのコレクションです。この（薄い）レイヤーの目的は、アプリケーション開発者が同じクラスのさまざまなデバイスをサポートする際、それぞれのデバイスに別個のコードを書くことなく、簡単に実装できるようにすることです。

libv4l の使用例は v4l2grab.

libv4l は 3 つの異なるライブラリから構成されています:

5.1.1. libv4lconvert¶

libv4lconvert は、V4L2 ドライバで見られる複数のピクセルフォーマットを、いくつかの一般的な RGB および YUY フォーマットに変換するライブラリです。

現在、以下の V4L2 ドライバフォーマットを処理できます: V4L2_PIX_FMT_BGR24, V4L2_PIX_FMT_HM12, V4L2_PIX_FMT_JPEG, V4L2_PIX_FMT_MJPEG, V4L2_PIX_FMT_MR97310A, V4L2_PIX_FMT_OV511, V4L2_PIX_FMT_OV518, V4L2_PIX_FMT_PAC207, V4L2_PIX_FMT_PJPG, V4L2_PIX_FMT_RGB24, V4L2_PIX_FMT_SBGGR8, V4L2_PIX_FMT_SGBRG8, V4L2_PIX_FMT_SGRBG8, V4L2_PIX_FMT_SN9C10X, V4L2_PIX_FMT_SN9C20X_I420, V4L2_PIX_FMT_SPCA501, V4L2_PIX_FMT_SPCA505, V4L2_PIX_FMT_SPCA508, V4L2_PIX_FMT_SPCA561, V4L2_PIX_FMT_SQ905C, V4L2_PIX_FMT_SRGGB8, V4L2_PIX_FMT_Y41P, V4L2_PIX_FMT_YUV420, V4L2_PIX_FMT_UYVY, V4L2_PIX_FMT_YVU410, and V4L2_PIX_FMT_YVYU.

後述のように、libv4lconvert はビデオ処理機能を追加し、ウェブカメラのビデオ品質を向上させるようになりました。ビデオ処理は 2 つの部分に分かれています: libv4lconvert/control と libv4lconvert/processing。

control 部分は、libv4lconvert/processing で提供されるビデオ処理機能を制御するためのコントロールを提供します。これらのコントロールは、永続的な共有メモリオブジェクトを使用してアプリケーション全体で保存されます（再起動まで有効）。

libv4lconvert/processing は実際のビデオ処理機能を提供します。

5.1.2. libv4l1¶

このライブラリは、v4l1 アプリケーションを v4l2 デバイスと簡単に動作させるための関数を提供します。これらの関数は通常の open/close/etc と同様に動作しますが、v4l1 ドライバの場合は呼び出しを透過的に処理し、v4l2 ドライバでは v4l1 API の完全なエミュレーションを行います。

これらの関数は古い V4L1 API のエミュレーションであるため、新規アプリケーションには使用すべきではありません。

5.1.3. libv4l2¶

このライブラリはすべての現代的な V4L2 アプリケーションで使用すべきです。

このライブラリは V4L2 open/ioctl/close/poll メソッドの呼び出しハンドルを提供します。デバイスの素出力ではなく、libv4lconvert を使用してより多くのビデオフォーマットを提供し、画像品質を向上させるように呼び出しを強化します。

ほとんどの場合、libv4l2 は v4l2 ドライバに直接呼び出しを渡しますが、 VIDIOC_TRY_FMT, VIDIOC_G_FMT, VIDIOC_S_FMT, VIDIOC_ENUM_FRAMESIZES および VIDIOC_ENUM_FRAMEINTERVALS フォーマットをエミュレートするため V4L2_PIX_FMT_BGR24, V4L2_PIX_FMT_RGB24, V4L2_PIX_FMT_YUV420, and V4L2_PIX_FMT_YVU410、ドライバにない場合 VIDIOC_ENUM_FMT ハードウェアでサポートされているフォーマットを継続して列挙し、libv4lが提供するエミュレートされたフォーマットを最後に追加しています。

5.1.3.1. Libv4lデバイス制御関数¶

libv4lが一般的なファイル操作メソッドを提供しています。

これらの関数はgccの関数と同様に動作します dup() およびV4L2関数 open(), close(), ioctl(), read(), mmap() および munmap():

int v4l2_open(const char *ファイル, int oflag, ...)¶

operates like the open() function.

int v4l2_close(int fd)¶

operates like the close() function.

int v4l2_dup(int fd)¶

operates like the libc dup() function, duplicating a file handler.

int v4l2_ioctl(int fd, unsigned long int リクエスト, ...)¶

operates like the ioctl() function.

int v4l2_read(int fd, void *バッファ, size_t n)¶

operates like the read() function.

void v4l2_mmap(void *start, size_t length, int prot, int フラグ, int fd, int64_t オフセット);¶

operates like the munmap() function.

int v4l2_munmap(void *_start, size_t length);¶

operates like the munmap() function.

これらの関数は追加の制御を提供します:

int v4l2_fd_open(int fd, int v4l2_flags)¶

v4l2libを通じて既に開かれたfdをさらに使用可能にし、必要に応じてlibv4l2のデフォルト動作を変更するための引数を使用します。現在、 v4l2_flags 、フォーマット変換を無効にするために v4l2_flags can be V4L2_DISABLE_CONVERSIONを指定できます。

int v4l2_set_control(int fd, int cid, int 値)¶

この関数は0〜65535の値を受け取り、その範囲を指定されたv4l制御IDの実際の範囲にスケーリングし、cidが存在しロックされていない場合にそのcidをスケーリング後の値に設定します。

int v4l2_get_control(int fd, int cid)¶

この関数は0〜65535の値を返します。指定されたv4l制御IDの実際の範囲にスケーリングされた値です。cidが存在しない、アクセスができない、またはエラーが発生した場合、0が返されます。

5.1.4. v4l1compat.so ラッパーライブラリ¶

このライブラリは、 open(), close(), ioctl(), mmap() および munmap() 操作の呼び出しをインターセプトし、libv4lの対応する関数にリダイレクトします。これにより、V4L2 APIを介してV4L1呼び出しをエミュレートすることも可能です。 LD_PRELOAD=/usr/lib/v4l1compat.soIt also emulates V4L1 calls via V4L2 API.

これにより、libv4lを使用していない古いバイナリアプリケーションの使用が可能になります。
