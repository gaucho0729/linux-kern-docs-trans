2.1. シングルプランナー形式構造体¶

type v4l2_pix_format¶
struct v4l2_pix_format¶

__u32

width

画像の幅（ピクセル数）。

__u32

height

画像の高さ（ピクセル数）。もし field が次のいずれかの場合は V4L2_FIELD_TOP, V4L2_FIELD_BOTTOM または V4L2_FIELD_ALTERNATE その場合、高さはフィールドの行数を指し、それ以外の場合はフレームの行数を指します（インターレース形式では、これはフィールド高さの2倍です）。

アプリケーションはこれらのフィールドを画像サイズを要求するために設定し、ドライバーは最も近い可能な値を返します。プランナーフォーマットの場合、 width および height 最大の平面に適用されます。誤解を避けるため、ドライバーは、すべての小さな平面のスケールファクターの倍数に丸めた値を返す必要があります。たとえば、画像形式がYUV 4:2:0の場合、 width および height 2の倍数でなければなりません。

ストリーム内に解像度情報がエンコードされている圧縮形式の場合、stateful mem2memデコーダーに供給される際、フィールドをゼロに設定してデコーダーに正しい値を検出させることが可能です。詳細については メモリ間ステートフルビデオデコーダーインターフェース およびフォーマットの説明を参照してください。

stateful mem2memエンコーダーのCAPTURE側で使用される圧縮形式の場合、フィールドはゼロでなければなりません。エンコーダー自身がOUTPUT側に基づいて符号化サイズを内部で計算するためです。詳細については メモリ対メモリ ステートフル ビデオ エンコーダー インターフェース およびフォーマットの説明を参照してください。

__u32

pixelformat

ピクセルフォーマットまたは圧縮タイプをアプリケーションが設定します。これはリトルエンディアン 4文字コード。V4L2は標準RGBフォーマットを RGB形式、YUVフォーマットを YUV形式、および予約コードを 予約された画像形式

__u32

field

フィールド順序、列挙型から選ぶ v4l2_field。ビデオ画像は通常インターレースです。アプリケーションは、上または下のフィールドのみをキャプチャまたは出力する、またはインターレースまたはシーケンシャルに1つのバッファに保存する、または別個のバッファで交互に保存するなど、フィールドを指定できます。ドライバーは選択されたフィールド順序を返します。フィールドに関する詳細については フィールド順序.

__u32

bytesperline

隣接する2行の左端ピクセル間のバイト単位の距離。

アプリケーションおよびドライバーは、各行の末尾にパディングバイトを要求するためにこのフィールドを設定できます。ただし、ドライバーはアプリケーションが指定した値を無視して、 width ピクセルあたりのバイト数の何倍か、またはハードウェアが必要とするより大きな値を返します。これにより、アプリケーションはこのフィールドをゼロに設定するだけで十分なデフォルト値を得られます。

ビデオハードウェアがパディングバイトにアクセスできるため、これらはアクセス可能なメモリに存在しなければなりません。画像の最後の行の後のパディングバイトがシステムページ境界を越える場合を考慮してください。入力デバイスはパディングバイトを書き込むかもしれませんが、値は未定義です。出力デバイスはパディングバイトの内容を無視します。

画像形式がプランナーフォーマットの場合、 bytesperline 値は最初の平面に適用され、同じ係数で width 他の平面用のフィールドです。例えばYUV 4:2:0画像のCbおよびCr平面は、Y平面に比べて各行の後にパディングバイトが半分になります。誤解を避けるため、ドライバーはこの値を bytesperline スケールファクターの倍数に丸めた値に設定する必要があります。

圧縮形式の場合、 bytesperline この値は意味がありません。アプリケーションおよびドライバーはこの場合、この値を0に設定する必要があります。

__u32

sizeimage

完全な画像を保持するバッファのバイト数、ドライバーが設定します。通常は bytesperline 倍 heightです。画像が可変長圧縮データで構成されている場合、これはコーデックが最悪の圧縮シナリオをサポートするために必要なバイト数です。

ドライバーが非圧縮画像の値を設定します。

可変長圧縮データでフラグが設定されている場合、クライアントは sizeimage フィールドを設定できます V4L2_FMT_FLAG_COMPRESSED に ioctl VIDIOC_ENUM_FMTただし、ドライバーはこれを無視して自身で値を設定するか、アライメント要件や最小/最大サイズ要件に基づいて提供された値を変更する可能性があります。クライアントがドライバーに任せる場合は、sizeimage を 0 に設定する必要があります。

__u32

colorspace

画像カラースペース、列挙型 v4l2_colorspaceから選択します。この情報は pixelformat を補完し、キャプチャストリームにはドライバーが設定し、出力ストリームにはアプリケーションが設定する必要があります。参照 カラースペース。アプリケーションがフラグ V4L2_PIX_FMT_FLAG_SET_CSC を設定した場合、アプリケーションはキャプチャストリームに対してキャプチャされた画像データの特定のカラースペースを要求するためこのフィールドを設定できます。ドライバーが要求された変換を処理できない場合、別のサポートされているカラースペースを返します。ドライバーはカラースペース変換をサポートしていることを、対応する構造体 v4l2_fmtdesc のフラグV4L2_FMT_FLAG_CSC_COLORSPACEを設定することにより示します。参照 画像フォーマット記述フラグ.

__u32

priv

このフィールドは、構造体 v4l2_pix_formatの残りのフィールドが有効かどうかを示します。設定されて V4L2_PIX_FMT_PRIV_MAGICの場合、拡張フィールドが正しく初期化されていることを示します。他の値に設定されている場合、拡張フィールドに未定義の値が含まれていることを示します。

拡張フィールドを使用したいアプリケーションは、まずデバイスから機能を確認するために V4L2_CAP_EXT_PIX_FORMAT という機能を照会する必要があります。この機能が設定されていない場合、拡張フィールドはサポートされておらず、拡張フィールドを使用すると未定義の結果になる可能性があります。

拡張フィールドを使用するには、アプリケーションは priv フィールドに渡して V4L2_PIX_FMT_PRIV_MAGICを設定し、すべての拡張フィールドを初期化し、構造体の未使用バイトをゼロにします v4l2_format raw_data フィールドによって保護されています。

When the priv が設定されていない場合、ドライバーはすべての拡張フィールドがゼロに設定されているかのように動作する必要があります。返却時にドライバーは V4L2_PIX_FMT_PRIV_MAGIC を設定し、すべての拡張フィールドを適切な値に設定する必要があります。 priv フィールドに渡して V4L2_PIX_FMT_PRIV_MAGIC アプリケーションがフラグ

flags

Flags set by the application or driver, see 形式フラグ.

形式フラグ¶

V4L2_PIX_FMT_FLAG_PREMUL_ALPHA

0x00000001

カラービューワーはアルファチャネル値で事前に乗算されます。たとえば、透明度50%のライトブルーのピクセルがRGBA値(128, 192, 255, 128)で表される場合、事前に乗算されたカラービューワーではRGBA値(64, 96, 128, 128)で表されます

V4L2_PIX_FMT_FLAG_SET_CSC

0x00000002

アプリケーションが設定します。これはキャプチャ専用で、出力ストリームでは無視されます。設定されている場合、デバイスに受信したカラースペースから要求されたカラースペース値へのカラースペース変換を要求します。カラーメトリックフィールド（colorspace, xfer_func, ycbcr_enc, hsv_enc または quantization) が設定されていれば、 *_DEFAULTのカラーメトリック設定は受信したまま変更されません。したがって、量子化を変更するには、 quantization フィールドをデフォルト値以外の値（V4L2_QUANTIZATION_FULL_RANGE または V4L2_QUANTIZATION_LIM_RANGE) に設定し、すべての他のカラーメトリックフィールドを *_DEFAULT.

ハードウェアが現在のピクセル形式でサポートする変換を確認するには、 画像フォーマット記述フラグ.
