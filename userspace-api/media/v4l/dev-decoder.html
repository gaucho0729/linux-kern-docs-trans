4.5.1. メモリ間ステートフルビデオデコーダーインターフェース¶

ステートフルビデオデコーダーは、バイトストリーム（例： Annex-B H.264/HEVCストリーム、raw VP8/9ストリーム）の完全なチャンクを処理し、表示順にrawビデオフレームにデコードします。デコーダーは、これらのバッファを処理するためにクライアントから追加の情報を受け取る必要はありません。

このインターフェースをサポートするためにドライバー内でストリームのソフトウェアパースや処理を行うことは強く推奨されません。このような操作が必要な場合は、ステートレスビデオデコーダーインターフェース（開発中）の使用を強く推奨します。

4.5.1.1. このドキュメントで使用する慣例と記法¶

  1. このドキュメントで明記されていない限り、一般的なV4L2 APIルールが適用されます。

  2. 「must」「may」「should」などの語の意味は、 RFC 2119.

  3. 「optional」でないステップはすべて必須です。

  4. VIDIOC_G_EXT_CTRLS() および VIDIOC_S_EXT_CTRLS() ～と交換可能である VIDIOC_G_CTRL() および VIDIOC_S_CTRL()、ただし明記されていない限りは。

  5. シングルプランアピ（参照 シングルプレーンおよびマルチプレーンAPI）および適用可能な構造体は、デコーダーの機能に応じて、および一般的なV4L2ガイドラインに従って、マルチプランアピと交換可能である、ただし明記されていない限りは。

  6. i = [a..b]: aからbまでの整数の列、つまりi = [0..2]: i = 0, 1, 2。

  7. 与えられた OUTPUT バッファAの場合、A’はバッファAを処理した結果のデータを含む CAPTURE キュー上のバッファを表します。

CAPTURE

出力バッファキュー；デコーダーではデコードされたフレームを含むバッファキュー、エンコーダーでは符号化されたバイトストリームを含むバッファキュー； V4L2_BUF_TYPE_VIDEO_CAPTURE または V4L2_BUF_TYPE_VIDEO_CAPTURE_MPLANE；データはハードウェアから CAPTURE バッファ

符号化高さ

与えられた符号化解像度に対応する高さ。

符号化解像度

符号化幅

与えられた符号化解像度に対応する幅。

表示順

DPB

デコードピクチャーバッファ；H.264/HEVCにおける、後続のデコードステップで参照可能なデコード済みのRAWフレームを保存するバッファ。

IDR

線形ブロック変換（例：H.264、VP8、VP9）に基づく画像・動画圧縮形式における処理単位。コードック固有ですが、一般的なコードックではサイズが16x16サンプル（ピクセル）です。

OUTPUT

未圧縮形式で、RAWピクセルデータ（例：YUV、RGB形式）を含みます。

再開ポイント

デコードを開始/再開できるバイナリストリーム内のポイント。以前の状態データが存在しない場合でもデコード可能。例：キーフレーム（VP8/VP9）やSPS/PPS/IDRシーケンス（H.264/HEVC）。新しいストリームのデコード開始またはシーク後の再開に必要です。

ソース高さ

ソース解像度

エンコーダーに供給されるソースフレームの解像度（可視解像度の境界までさらにトリミングされる）。エンコーダー専用の情報です。

4.5.1.12. コミットポイント¶

形式の設定とバッファの割り当ては、デコーダーの動作に変化をもたらします

  1. 形式をデコーダーに設定する OUTPUT キューは、サポートされている/広告されているフォーマットのセットを変更する可能性があります。 CAPTURE キュー。特に重要な点は、 CAPTURE フォーマットがリセットされる可能性があり、クライアントは以前に設定されたフォーマットが保持されるとは信頼してはいけません。

  2. キュー上のフォーマットを列挙する際には常にのみ返します。 CAPTURE キューは常に現在の...をサポートするフォーマットのみを返します。 OUTPUT 形式。

  3. 形式をデコーダーに設定する CAPTURE キューは、そのキューに利用可能な形式の一覧を変更しません。 OUTPUT キュー。現在選択されている形式でサポートされていない形式を設定しようとすると CAPTURE 形式を設定しようとすると、デコーダーが要求された形式をサポートされている形式に調整します。 OUTPUT 形式をサポートされている形式に調整します。 CAPTURE 形式をサポートされている形式に調整します。

  4. キュー上のフォーマットを列挙する際には常にのみ返します。 OUTPUT キューは常にサポートされている符号化形式の完全なセットを返します。現在の CAPTURE 形式。

  5. バッファがどのキューにも割り当てられている間、クライアントは OUTPUT または CAPTURE キューで形式を変更してはいけません。 OUTPUT キュー。ドライバーは、このような形式変更の試みに対して-EBUSYエラーコードを返します。

要約すると、形式と割当の設定は常にキューから始める必要があります。 OUTPUT キューと OUTPUT キューは、サポートされる形式のセットを統括するマスターです。 CAPTURE キュー。
