6.1. V4LとV4L2の違い¶

Video For Linux APIはLinux 2.1で最初に導入され、以前にドライバ開発者によって独立して開発されていたテレビやラジオ関連のインターフェースを統合・置き換えるために導入されました。Linux 2.5から大幅に改善されたV4L2 APIがV4L APIの代わりに採用され、旧V4Lコールはカーネルからサポートが削除されました。ただしライブラリは Libv4l Userspace Library V4L APIシステムコールをV4L2に変換する機能をサポートしています。

6.1.1. デバイスのオープンとクローズ¶

互換性のため、V4L2ビデオキャプチャ、オーバーレイ、ラジオおよびRAW VBIキャプチャデバイスのキャラクターデバイスファイル名はV4Lで使用されていたものと変わりません。これらは インターフェース および以下の V4Lデバイスタイプ、名前および番号.

テレックステッドデバイス（マイノル範囲192-223）はV4L2で削除され、現在は存在しません。純粋なテレックステッドを処理するハードウェアはもうありません。代わりにRAWまたはスライスされたVBIが使用されます。

V4L videodev モジュールは、ロード順に応じてドライバにマイノル番号を自動的に割り当てます。デバイスタイプに応じて登録されます。V4L2ドライバはデフォルトで同じ番号でデバイスを登録することを推奨しますが、システム管理者はドライバモジュールオプションを使用して任意のマイノル番号を割り当てることができます。メジャーデバイス番号は81のままです。

6.1.9.1. 読み取りメソッドを使用して画像をキャプチャする¶

V4L または V4L2 デバイスから画像を読み込む際の read() 関数を使用する際の本質的な違いはありませんが、V4L2 ドライバはこの I/O メソッドをサポートする必要はありません。アプリケーションは ioctl VIDIOC_QUERYCAP ioctl を使用してこの関数が利用可能かどうかを確認できます。すべての V4L2 デバイスはアプリケーションとデータをやり取りする際、 select() および poll() 関数の終わりを注釈する必要があります。

をサポートしなければなりません。画像形式とサイズを選択するため、V4L は VIDIOCSPICT および VIDIOCSWIN ioctls を提供します。V4L2 は一般的なデータ形式のネゴシエーション ioctls を使用します VIDIOC_G_FMT および VIDIOC_S_FMT. これらはstructへのポインタを取るようになりました v4l2_format を引数として、ここで構造体 v4l2_pix_format が指定されています。 pix の fmt ユニオンが使用されます。

V4L2 の読み取りインターフェースについての詳細情報は 読み書き.

6.1.9.2. メモリマッピングを使用して画像をキャプチャする¶

アプリケーションは V4L デバイスから画像を読み込むためにデバイスメモリ内のバッファをマッピングするか、またはより頻繁に DMA が可能なシステムメモリに割り当てられたバッファをアドレス空間にマッピングすることで読み込むことができます。これにより、読み取りメソッドのデータコピーのオーバーヘッドを回避できます。V4L2 もメモリマッピングをサポートしており、いくつかの違いがあります。

V4L

V4L2

画像形式はバッファを割り当てる前に選択する必要があります。このためには VIDIOC_S_FMT ioctl を使用します。形式が選択されていない場合、ドライバは最後に使用された形式、おそらく他のアプリケーションが要求した形式を使用する場合があります。

アプリケーションはバッファの数を変更できません。これはドライバに組み込まれており、ドライバモジュールをロードする際にモジュールオプションで変更可能な場合を除きます。

以下の ioctl VIDIOC_REQBUFS ioctl で希望するバッファ数を割り当てます。これは初期化シーケンスで必要なステップです。

ドライバはすべてのバッファを1つの連続したメモリ範囲としてマッピングします。このため、 VIDIOCGMBUF ioctl はバッファ数、各バッファの開始位置からのオフセット、および全体のメモリ使用量を照会することができ、これらは mmap() function.

バッファが個別にマッピングされます。各バッファのオフセットとサイズは ioctl. マルチプレーンAPIでは、structの一部のプレーン固有メンバが ioctl.

以下の VIDIOCMCAPTURE ioctl でバッファをキャプチャ用に準備します。これにより、このバッファの画像形式も決定されます。ioctl はすぐに返却され、最終的にエラーを含む形で EAGAIN ビデオ信号が検出されなかった場合のエラー コード。ドライバが複数のバッファをサポートする場合、アプリケーションはioctlを複数回呼び出すことができ、複数のキャプチャリクエストを待機状態にできます。

以下の VIDIOCSYNC ioctlは特定のバッファが埋められるまで実行を一時停止します。

ドライバは受信キューと送信キューを保持します。 ioctl VIDIOC_QBUF, VIDIOC_DQBUF 空のバッファを受信キューに追加し、埋められたバッファは送信キューからioctlで取得します。 VIDIOC_DQBUF 埋められたバッファが利用可能になるのを待機するには、この関数を、1つ以上のバッファをキューに追加した後で1回呼び出す必要があります。 select() または poll() が使用できます。 ioctl VIDIOC_STREAMON, VIDIOC_STREAMOFF キャプチャを開始するには、1つ以上のバッファをキューに追加した後でioctlを1回呼び出す必要があります。その対応する VIDIOC_STREAMOFF はキャプチャを停止し、両方のキューからすべてのバッファを取得します。アプリケーションは、信号状態がわかっている場合、この ioctl VIDIOC_ENUMINPUT ioctl.

メモリマッピングについての詳細な説明と例については、 ストリーミングI/O（メモリマッピング）.
