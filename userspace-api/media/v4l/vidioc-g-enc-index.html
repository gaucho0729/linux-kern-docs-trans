7.28. ioctl VIDIOC_G_ENC_INDEX (エンコーディングインデックスを取得するためのコマンド)¶

7.28.1. 名前¶

VIDIOC_G_ENC_INDEX - 圧縮ビデオストリームに関するメタデータを取得

7.28.2. 概要¶

VIDIOC_G_ENC_INDEX¶

int ioctl(int fd, VIDIOC_G_ENC_INDEX, struct v4l2_enc_idx *argp)

7.28.3. 引数¶

fd

返されるファイル記述子 open().

argp

struct mem_ctl_info v4l2_enc_idx.

7.28.4. 説明¶

以下の VIDIOC_G_ENC_INDEX ioctlは、現在ドライバーから読み取っている同じアプリケーションまたは別のアプリケーションが使用する圧縮ビデオストリームに関するメタデータを提供します。これは、デコードせずにストリームへのランダムアクセスに役立ちます。

データを読み込むには、アプリケーションは VIDIOC_G_ENC_INDEX structへのポインタを渡して v4l2_enc_idx. 成功した場合、ドライバーは entry 配列を埋め、 entries フィールドに書き込んだ要素数を格納し、 entries_cap フィールドによって保護されています。

配列の各要素は2つの要素からなり、 entry 配列は1つのピクチャに関するメタデータを含みます。 VIDIOC_G_ENC_INDEX 呼び出しはドライバーバッファから最大 V4L2_ENC_IDX_ENTRIES エントリを読み込み、このバッファは最大 entries_cap エントリを保持できます。この数値は V4L2_ENC_IDX_ENTRIESよりも低くても高くてもよいですが、ゼロにはできません。アプリケーションがメタデータを十分に読み取れなかった場合、最も古いエントリが失われます。バッファが空であったり、キャプチャ/エンコードが進行していない場合、 entries ゼロになります。

現在、このioctlはMPEG-2プログラムストリームおよびビデオ要素ストリームにのみ定義されています。

type v4l2_enc_idx¶
struct v4l2_enc_idx¶

__u32

entries

ドライバーが entry 配列を表しています。

__u32

entries_cap

に保存したエントリ数。ドライバーがバッファリングできるエントリ数。ゼロより大きい必要があります。

__u32

reserved[4]

今後の拡張用に予約されています。ドライバは配列をゼロに設定する必要があります。

struct v4l2_enc_idx_entry

entry[V4L2_ENC_IDX_ENTRIES]

圧縮ビデオストリームに関するメタデータ。配列の各要素は、その offset.
type v4l2_enc_idx_entry¶
struct v4l2_enc_idx_entry¶

__u64

offset

圧縮ビデオストリームの開始位置からこのピクチャの開始位置までのバイト数。これは PESパケットヘッダー として定義されています ISO 13818-1 または ピクチャヘッダー として定義されています ISO 13818-2です。エンコーダーが停止した場合、ドライバーはオフセットをゼロにリセットします。

__u64

pts

33ビットの プレゼンテーションタイムスタンプ が、 ISO 13818-1.

__u32

length

このピクチャのバイト数。

__u32

flags

このピクチャの符号化タイプを含むフラグ、詳しくは インデックスエントリフラグ.

__u32

reserved[2]

今後の拡張用に予約されています。ドライバは配列をゼロに設定する必要があります。
インデックスエントリフラグ¶

V4L2_ENC_IDX_FRAME_I

0x00

これはイントラ符号化されたピクチャです。

V4L2_ENC_IDX_FRAME_P

0x01

これは予測符号化されたピクチャです。

V4L2_ENC_IDX_FRAME_B

0x02

これは双方向予測符号化されたピクチャです。

V4L2_ENC_IDX_FRAME_MASK

0x0F

AND このマスクをフラグフィールドと論理積を取ることで、ピクチャの符号化タイプを取得できます。

7.28.5. 戻り値¶

成功した場合、0 が返されます。エラーの場合、-1 が返され、変数が適切に設定されます。 errno 一般的なエラーコードは、 汎用エラーコード 章。
