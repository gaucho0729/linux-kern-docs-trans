7.8. ioctl VIDIOC_DQEVENT¶

7.8.1. 名前¶

VIDIOC_DQEVENT - イベントをキューから取り出す

7.8.2. 概要¶

VIDIOC_DQEVENT¶

int ioctl(int fd, VIDIOC_DQEVENT, struct v4l2_event *argp)

7.8.3. 引数¶

fd

返されるファイル記述子 open().

argp

struct mem_ctl_info v4l2_event.

7.8.4. 説明¶

ビデオデバイスからイベントをキューから取り出す。このioctlには入力は必要ありません。すべての構造体のフィールドは v4l2_event ドライバによって埋められます。ファイルハンドルは、アプリケーションがselectシステムコールなどを使って取得できる例外も受信します。

イベントの種類¶

V4L2_EVENT_ALL

0

すべてのイベント。V4L2_EVENT_ALL は VIDIOC_UNSUBSCRIBE_EVENT で一度にすべてのイベントをアンサブスクライブする場合にのみ有効です。

V4L2_EVENT_VSYNC

1

このイベントは垂直同期時にトリガーされます。このイベントには構造体 v4l2_event_vsync が関連付けられています。

V4L2_EVENT_EOS

2

このイベントはストリームの終わりにトリガーされます。これは通常、MPEGデコーダーと併用して、MPEGストリームの最後がデコードされたときにアプリケーションに報告するために使用されます。

V4L2_EVENT_CTRL

3

このイベントは id が受信したい制御IDと一致する必要があります。制御の値が変更された場合、ボタン制御が押された場合、または制御のフラグが変更された場合にこのイベントがトリガーされます。このイベントには構造体 v4l2_event_ctrl が関連付けられています。この構造体は、構造体 v4l2_queryctrl および struct v4l2_control.

が呼び出しによって生成された場合、イベントは VIDIOC_S_CTRL または VIDIOC_S_EXT_CTRLS呼び出したioctl関数のファイルハンドルに送信されます。これにより、不快なフィードバックループを防ぎます。あなたが ではありません イベントを取得したい場合は、 します このイベントタイプは、内部に収容できるよりも多くのイベントが発生した場合でも情報が失われることを保証します。その場合、構造体 V4L2_EVENT_SUB_FL_ALLOW_FEEDBACK フラグを設定します。

V4L2_EVENT_FRAME_SYNC

4

フレームの受信が開始された直ちにトリガーされます。このイベントには構造体 v4l2_event_frame_sync が関連付けられています。

バッファアンダーランの場合、ハードウェアが停止する必要があるため、このイベントを生成できなくなる可能性があります。そのような場合、 frame_sequence 構造体のフィールド v4l2_event_frame_sync インクリメントされません。これにより、2つの連続するフレームのシーケンス番号の間にn倍のフレームインターバルが生じます。

V4L2_EVENT_SOURCE_CHANGE

5

ビデオデバイスが実行時においてソースパラメータの変更を検出するとこのイベントがトリガーされます。これはビデオデコーダーによって実行時の解像度変更がトリガーされるか、入力コネクタでフォーマット変更が発生した場合を含みます。このイベントは、 id が使用されるビデオデバイスノードの入力インデックス（またはサブデバイスノードのpadインデックス）からイベントを受信したい場合に一致する必要があります。

このイベントには構造体 v4l2_event_src_change が関連付けられています。 changes ビットフィールドはサブスクライブされたpadで変更された項目を示します。アプリケーションがイベントをデキューする前に複数のイベントが発生した場合、変更内容はすべてのイベントのOR値としてまとめられます。

V4L2_EVENT_MOTION_DET

6

1つ以上の領域のモーション検出状態が変更されたときにトリガーされます。このイベントには構造体 v4l2_event_motion_det が関連付けられています。

V4L2_EVENT_PRIVATE_START

0x08000000

ドライバ専用イベントのベースイベント番号です。

コントロール変更¶

V4L2_EVENT_CTRL_CH_VALUE

0x0001

この制御イベントは制御値が変更されたためトリガーされました。特殊なケース：変動制御はこのイベントを生成しません。制御が V4L2_CTRL_FLAG_EXECUTE_ON_WRITE フラグが設定されている場合、その値に関係なくこのイベントが送信されます。

V4L2_EVENT_CTRL_CH_FLAGS

0x0002

この制御イベントは、制御フラグが変更されたためトリガーされました。

V4L2_EVENT_CTRL_CH_RANGE

0x0004

この制御イベントは、制御の最小値、最大値、ステップまたはデフォルト値が変更されたためトリガーされました。
ソース変更¶

V4L2_EVENT_SRC_CH_RESOLUTION

0x0001

入力で解像度の変更が検出されたときにこのイベントがトリガーされます。これは入力コネクタまたはビデオデコーダーから発生する可能性があります。アプリケーションは新しい解像度（存在する場合）を照会する必要があります（信号が失われている可能性もあります）。

ステートフルデコーダーについては、以下のガイドラインを参照してください メモリ間ステートフルビデオデコーダーインターフェースビデオキャプチャデバイスは、新しいタイミングを取得するために以下の方法を使用する必要があります ビデオレシーバーが見ているDVタイミングを検出するには以下のioctlを使用します。 または VIDIOC_QUERYSTD.

重要です。: 新しいビデオタイミングが古いものと同一に見える場合でも、このイベントの受信はビデオ信号に問題があったことを示し、ストリーミングを停止して再開する必要があります（VIDIOC_STREAMOFF 続きは VIDIOC_STREAMON)。理由は、多くのビデオキャプチャデバイスが一時的な信号喪失から回復できないためで、ハードウェアがビデオ信号に同期するためにはストリーミングI/Oを再開する必要があります。

7.8.5. 戻り値¶

成功した場合、0 が返されます。エラーの場合、-1 が返され、変数が適切に設定されます。 errno 一般的なエラーコードは、 汎用エラーコード 章。
