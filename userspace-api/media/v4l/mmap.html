3.2. ストリーミングI/O（メモリマッピング）¶

入出力デバイスは、ioctlが設定されているときにこのI/Oメソッドをサポートします。 V4L2_CAP_STREAMING フラグを含めます。以下のようにします： capabilities 構造体の v4l2_capability は ioctl VIDIOC_QUERYCAP ストリーミングメソッドは2種類あり、メモリマッピングのフラーバーがサポートされているかを確認するにはアプリケーションが ioctl VIDIOC_REQBUFS ioctlを呼び出し、メモリタイプを V4L2_MEMORY_MMAP.

ストリーミングは、アプリケーションとドライバー間でバッファへのポインタのみをやり取りするI/Oメソッドです。データ自体はコピーされません。メモリマッピングは主にデバイスメモリ内のバッファをアプリケーションのアドレス空間にマッピングすることを目的としています。デバイスメモリはたとえばグラフィックカードのビデオメモリで、ビデオキャプチャ拡張機能が搭載されている場合があります。しかし、長期間にわたって利用可能な最も効率的なI/Oメソッドであるため、多くの他のドライバもストリーミングをサポートしており、DMA可能なメインメモリにバッファを割り当てています。

ドライバは複数のバッファセットをサポートできます。各セットは一意のバッファタイプ値で識別され、セットは独立しており、各セットは異なる種類のデータを保持できます。同時に異なるセットにアクセスするには異なるファイルディスクリプタを使用しなければなりません。 1

デバイスバッファを割り当てるにはアプリケーションが ioctl VIDIOC_REQBUFS ioctlで望ましいバッファ数とバッファタイプを指定します。たとえば V4L2_BUF_TYPE_VIDEO_CAPTURE。このioctlは、バッファがまだマッピングされていない場合にバッファ数を変更したり、割り当てられたメモリを解放したりすることもできます。

アプリケーションがバッファにアクセスする前に、アプリケーションのアドレス空間にマッピングする必要があります。そのために mmap() 関数を使用します。デバイスメモリ内のバッファの位置は ioctl. マルチプレーンAPIでは、structの一部のプレーン固有メンバが ioctlで確認できます。シングル・プランナーAPIの場合、 m.offset および length が構造体 v4l2_buffer に返され、その6番目と2番目のパラメータとして mmap() 関数に渡されます。マルチ・プランナーAPIを使用する場合、構造体 v4l2_buffer には構造体 v4l2_plane の配列を含み、それぞれが独自の m.offset および lengthを持ちます。マルチ・プランナーAPIを使用する場合、すべてのバッファのすべてのプランは個別にマッピングする必要がありますので、 mmap() への呼び出し回数はバッファ数に各バッファのプラン数をかけた数に等しくなければなりません。オフセットと長さの値は変更してはなりません。記憶してください、バッファは物理メモリに割り当てられており、仮想メモリとは異なりディスクにスワップされる可能性があります。アプリケーションはできるだけ早く munmap() function.

3.2.1. 例: シングル・プランナーAPIでのバッファマッピング¶

struct v4l2_requestbuffers reqbuf;
struct {
    void *start;
    size_t length;
} *buffers;
unsigned int i;

memset(&reqbuf, 0, sizeof(reqbuf));
reqbuf.type = V4L2_BUF_TYPE_VIDEO_CAPTURE;
reqbuf.memory = V4L2_MEMORY_MMAP;
reqbuf.count = 20;

if (-1 == ioctl (fd, VIDIOC_REQBUFS, &reqbuf)) {
    if (errno == EINVAL)
        printf("Video capturing or mmap-streaming is not supported\\n");
    else
        perror("VIDIOC_REQBUFS");

    exit(EXIT_FAILURE);
}

/* We want at least five buffers. */

if (reqbuf.count < 5) {
    /* You may need to free the buffers here. */
    printf("Not enough buffer memory\\n");
    exit(EXIT_FAILURE);
}

buffers = calloc(reqbuf.count, sizeof(*buffers));
assert(buffers != NULL);

for (i = 0; i < reqbuf.count; i++) {
    struct v4l2_buffer buffer;

    memset(&buffer, 0, sizeof(buffer));
    buffer.type = reqbuf.type;
    buffer.memory = V4L2_MEMORY_MMAP;
    buffer.index = i;

    if (-1 == ioctl (fd, VIDIOC_QUERYBUF, &buffer)) {
        perror("VIDIOC_QUERYBUF");
        exit(EXIT_FAILURE);
    }

    buffers[i].length = buffer.length; /* remember for munmap() */

    buffers[i].start = mmap(NULL, buffer.length,
                PROT_READ | PROT_WRITE, /* recommended */
                MAP_SHARED,             /* recommended */
                fd, buffer.m.offset);

    if (MAP_FAILED == buffers[i].start) {
        /* If you do not exit here you should unmap() and free()
           the buffers mapped so far. */
        perror("mmap");
        exit(EXIT_FAILURE);
    }
}

/* Cleanup. */

for (i = 0; i < reqbuf.count; i++)
    munmap(buffers[i].start, buffers[i].length);

3.2.2. 例: マルチ・プランナーAPIでのバッファマッピング¶

struct v4l2_requestbuffers reqbuf;
/* Our current format uses 3 planes per buffer */
#define FMT_NUM_PLANES = 3

struct {
    void *start[FMT_NUM_PLANES];
    size_t length[FMT_NUM_PLANES];
} *buffers;
unsigned int i, j;

memset(&reqbuf, 0, sizeof(reqbuf));
reqbuf.type = V4L2_BUF_TYPE_VIDEO_CAPTURE_MPLANE;
reqbuf.memory = V4L2_MEMORY_MMAP;
reqbuf.count = 20;

if (ioctl(fd, VIDIOC_REQBUFS, &reqbuf) < 0) {
    if (errno == EINVAL)
        printf("Video capturing or mmap-streaming is not supported\\n");
    else
        perror("VIDIOC_REQBUFS");

    exit(EXIT_FAILURE);
}

/* We want at least five buffers. */

if (reqbuf.count < 5) {
    /* You may need to free the buffers here. */
    printf("Not enough buffer memory\\n");
    exit(EXIT_FAILURE);
}

buffers = calloc(reqbuf.count, sizeof(*buffers));
assert(buffers != NULL);

for (i = 0; i < reqbuf.count; i++) {
    struct v4l2_buffer buffer;
    struct v4l2_plane planes[FMT_NUM_PLANES];

    memset(&buffer, 0, sizeof(buffer));
    buffer.type = reqbuf.type;
    buffer.memory = V4L2_MEMORY_MMAP;
    buffer.index = i;
    /* length in struct v4l2_buffer in multi-planar API stores the size
     * of planes array. */
    buffer.length = FMT_NUM_PLANES;
    buffer.m.planes = planes;

    if (ioctl(fd, VIDIOC_QUERYBUF, &buffer) < 0) {
        perror("VIDIOC_QUERYBUF");
        exit(EXIT_FAILURE);
    }

    /* Every plane has to be mapped separately */
    for (j = 0; j < FMT_NUM_PLANES; j++) {
        buffers[i].length[j] = buffer.m.planes[j].length; /* remember for munmap() */

        buffers[i].start[j] = mmap(NULL, buffer.m.planes[j].length,
                 PROT_READ | PROT_WRITE, /* recommended */
                 MAP_SHARED,             /* recommended */
                 fd, buffer.m.planes[j].m.offset);

        if (MAP_FAILED == buffers[i].start[j]) {
            /* If you do not exit here you should unmap() and free()
               the buffers and planes mapped so far. */
            perror("mmap");
            exit(EXIT_FAILURE);
        }
    }
}

/* Cleanup. */

for (i = 0; i < reqbuf.count; i++)
    for (j = 0; j < FMT_NUM_PLANES; j++)
        munmap(buffers[i].start[j], buffers[i].length[j]);

概念的にはストリーミングドライバーは2つのバッファキュー、入力キューと出力キューを保持します。これらは同期的なキャプチャまたは出力操作をビデオクロックに依存させることなく、ランダムなディスクやネットワークの遅延や他のプロセスによる中断にさらされるアプリケーションと分離し、データロスの確率を減らします。キューはFIFO（First In First Out）構造で組織され、入力FIFOにエンキューされた順序でバッファが出力され、出力FIFOからデキューされた順序でキャプチャされます。

ドライバーは常に一定数のバッファがエンキューされている状態で動作する必要がありますが、アプリケーションが事前にエンキューまたはデキューして処理できるバッファ数には制限はありません。また、エンキュー順序はデキュー順序と異なることも可能で、ドライバーは fill enqueued empty のバッファを任意の順序で処理できます。 2 バッファ（struct v4l2_buffer index）のインデックス番号はここでは役割を果たしません。ただ単にバッファを識別するためのものです。

初期状態ではすべてのマッピングされたバッファはデキュー状態で、ドライバーによってアクセスできません。キャプチャアプリケーションではまずすべてのマッピングされたバッファをエンキューし、その後キャプチャを開始して読み込みループに入ります。ここでアプリケーションは満たされたバッファがデキュー可能になるのを待機し、データが不要になったらバッファを再エンキューします。出力アプリケーションはバッファを満たしてエンキューし、十分なバッファが積まれたら出力処理を開始します。 VIDIOC_STREAMONwrite loopでは、アプリケーションが空きバッファがなくなると、空きバッファがデキュー可能になるのを待つ必要があります。

バッファをエンキューおよびデキューする際にはアプリケーションは VIVIOC_QBUF および VIDIOC_DQBUF ioctlを使用します。バッファのマッピング状態、エンキュー状態、満タン状態や空き状態はいつでも ioctl. マルチプレーンAPIでは、structの一部のプレーン固有メンバが ioctlを使用して確認できます。アプリケーションの実行を1つまたは複数のバッファがデキュー可能になるまで一時停止する2つの方法があります。デフォルトでは VIDIOC_DQBUF 出力キューにバッファがなければブロックします。flagが与えられた場合、 O_NONBLOCK 関数に与えられた場合、 open() 関数の場合、 VIDIOC_DQBUF エラー コードとともに即座に返します。 EAGAIN バッファが利用不可の場合のエラーコードです。The select() または poll() 関数は常に利用可能です。

キャプチャまたは出力アプリケーションを開始・停止するには VIDIOC_STREAMON および VIDIOC_STREAMOFF ioctl.

メモリマッピングI/Oを実装するドライバーは VIDIOC_REQBUFS, VIDIOC_QUERYBUF, VIDIOC_QBUF, VIDIOC_DQBUF, VIDIOC_STREAMON および VIDIOC_STREAMOFF ioctlに加えて、 mmap(), munmap(), select() および poll() function. 3
