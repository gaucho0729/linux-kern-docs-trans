7.6. ioctl VIDIOC_DBG_G_REGISTER, VIDIOC_DBG_S_REGISTER¶

7.6.1. 名前¶

VIDIOC_DBG_G_REGISTER - VIDIOC_DBG_S_REGISTER - ハードウェアレジスタの読み書き

7.6.2. 概要¶

VIDIOC_DBG_G_REGISTER¶

int ioctl(int fd, VIDIOC_DBG_G_REGISTER, struct v4l2_dbg_register *argp)

VIDIOC_DBG_S_REGISTER¶

int ioctl(int fd, VIDIOC_DBG_S_REGISTER, const struct v4l2_dbg_register *argp)

7.6.3. 引数¶

fd

返されるファイル記述子 open().

argp

struct mem_ctl_info v4l2_dbg_register.

7.6.4. 説明¶

注意

これはインターフェースであり、今後変更される可能性があります。 実験的API要素 インターフェースであり、今後変更される可能性があります。

ドライバのデバッグ目的でこれらのioctlはテストアプリケーションがハードウェアレジスタを直接アクセスできるようにします。通常のアプリケーションはこれらを使用してはいけません。

レジスタの書き込みや読み込みさえもシステムセキュリティや安定性を脅かしハードウェアを破損させる可能性があるため、これらのioctlはスーパーユーザーの特権が必要です。さらにLinuxカーネルはこれらのioctlを有効にするオプションでコンパイルする必要があります。 CONFIG_VIDEO_ADV_DEBUG option to enable these ioctls.

レジスタを書き込むにはアプリケーションはstructのすべてのフィールドを初期化する必要があります v4l2_dbg_register except for size を埋めます VIDIOC_DBG_S_REGISTER この構造体へのポインタで初期化する必要があります。The match.type および match.addr または match.name フィールドはTVカード上のチップを選択し、 reg フィールドはレジスタ番号を指定し、 val フィールドはレジスタに書き込む値を指定します。

レジスタを読み込むにはアプリケーションは match.type, match.addr または match.name および reg フィールドを初期化し、 VIDIOC_DBG_G_REGISTER この構造体へのポインタで呼び出します。成功した場合ドライバーはレジスタ値を val フィールドに保存し、値のサイズ（バイト単位）を size.

が呼ばれるとき、modprobeは match.type 通常のRCU読み込み側クリティカルセクションは、条件付きでスリープロックを取得することが許容されます（例として V4L2_CHIP_MATCH_BRIDGE, match.addr TVカード上のn番目のサブデバイスでないチップを選択します。ゼロは常にホストチップ（PCIまたはUSBバスに接続されたチップ）を選択します。チップの存在確認には ioctl VIDIOC_DBG_G_CHIP_INFO ioctl.

が呼ばれるとき、modprobeは match.type 通常のRCU読み込み側クリティカルセクションは、条件付きでスリープロックを取得することが許容されます（例として V4L2_CHIP_MATCH_SUBDEV, match.addr n番目のサブデバイスを選択します。

これらのioctlはオプションです。すべてのドライバーがサポートしているとは限りません。ただしドライバーがこれらのioctlをサポートする場合、 ioctl VIDIOC_DBG_G_CHIP_INFOをサポートする必要があります。逆にこれらをサポートしない場合でも VIDIOC_DBG_G_CHIP_INFO をサポートする可能性があります。

VIDIOC_DBG_G_REGISTER および VIDIOC_DBG_S_REGISTER Linux 2.6.21で導入されましたが、カーネル2.6.29ではここで説明するAPIに変更されました。

これらのioctlを直接呼び出すよりもv4l2-dbgユーティリティの使用を推奨します。LinuxTV v4l-dvbリポジトリから入手可能です。参照してください https://linuxtv.org/repo/ アクセス方法については以下を参照してください。
