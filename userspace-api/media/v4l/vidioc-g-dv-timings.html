7.26. ioctl VIDIOC_G_DV_TIMINGS, VIDIOC_S_DV_TIMINGS¶

7.26.1. 名前¶

VIDIOC_G_DV_TIMINGS - VIDIOC_S_DV_TIMINGS - VIDIOC_SUBDEV_G_DV_TIMINGS - VIDIOC_SUBDEV_S_DV_TIMINGS - 入力または出力のDVタイミングを取得または設定します

7.26.2. 概要¶

VIDIOC_G_DV_TIMINGS¶

int ioctl(int fd, VIDIOC_G_DV_TIMINGS, struct v4l2_dv_timings *argp)

VIDIOC_S_DV_TIMINGS¶

int ioctl(int fd, VIDIOC_S_DV_TIMINGS, struct v4l2_dv_timings *argp)

VIDIOC_SUBDEV_G_DV_TIMINGS¶

int ioctl(int fd, VIDIOC_SUBDEV_G_DV_TIMINGS, struct v4l2_dv_timings *argp)

VIDIOC_SUBDEV_S_DV_TIMINGS¶

int ioctl(int fd, VIDIOC_SUBDEV_S_DV_TIMINGS, struct v4l2_dv_timings *argp)

7.26.3. 引数¶

fd

返されるファイル記述子 open().

argp

struct mem_ctl_info v4l2_dv_timings.

7.26.4. 説明¶

入力または出力のDVタイミングを設定するには、アプリケーションはioctlを使用します。 VIDIOC_S_DV_TIMINGS 現在のタイミングを取得するには、アプリケーションはioctlを使用します。 VIDIOC_G_DV_TIMINGS 詳細なタイミング情報はstruct v4l2_bt_timings構造体を使用して埋められます。 v4l2_dv_timingsこれらのioctlはstruct v4l2_bt_timings構造体へのポインタを引数として受け取ります。 v4l2_dv_timings ioctlがサポートされていないか、タイミング値が正しくない場合、ドライバは EINVAL エラー コードに設定します。

呼び出し VIDIOC_SUBDEV_S_DV_TIMINGS 読み取り専用モードで登録されたサブデバイスのioctlは許可されません。エラーが返され、errno変数が -EPERM.

以下の linux/v4l2-dv-timings.h ヘッダーは、 CEA-861-E および VESA DMT 標準に準拠していない場合。現在の入力または出力がDVタイミングをサポートしていない場合（例： ioctl VIDIOC_ENUMINPUT が V4L2_IN_CAP_DV_TIMINGS フラグを設定していない場合）、 ENODATA error code is returned.

7.26.5. 戻り値¶

成功した場合、0 が返されます。エラーの場合、-1 が返され、変数が適切に設定されます。 errno 一般的なエラーコードは、 汎用エラーコード 章。

EINVAL

このioctlはサポートされていない、または VIDIOC_S_DV_TIMINGS パラメータが不適切です。

ENODATA

この入力または出力にはデジタルビデオタイミングがサポートされていません。

EBUSY

デバイスがビジー状態で、タイミングの変更ができないです。

EPERM

VIDIOC_SUBDEV_S_DV_TIMINGS 読み取り専用サブデバイスでioctlが呼び出されました。

DV BT Timing flags¶

フラグ

説明

V4L2_DV_FL_REDUCED_BLANKING

CVT/GTF固有: タイミングは減らした消去（CVT）または「セカンドGTF」曲線（GTF）を使用します。どちらの場合も水平および/または垂直消去インターバルが短縮され、同じ帯域幅でより高い解像度を実現できます。これは読み取り専用フラグであり、アプリケーションは設定してはなりません。

V4L2_DV_FL_CAN_REDUCE_FPS

CEA-861固有: 6の倍数のフレームレートを持つCEA-861フォーマットに設定されます。これらのフォーマットは、NTSCやPAL-Mなどの60Hzベースの標準（フレームレート29.97fps）との互換性を確保するために、1/1.001の速度でオプションで再生できます。送信機がこのような周波数を生成できない場合、フラグもクリアされます。これは読み取り専用フラグであり、アプリケーションは設定してはなりません。

V4L2_DV_FL_REDUCED_FPS

CEA-861固有: 以下のフラグが設定されているビデオ送信機またはビデオ受信機にのみ有効です。 V4L2_DV_FL_CAN_DETECT_REDUCED_FPS 設定されている場合にのみ有効です。それ以外の場合はこのフラグはクリアされます。また、以下のフラグが設定されているフォーマットにのみ有効です。 V4L2_DV_FL_CAN_REDUCE_FPS 他のフォーマットではドライバーがこのフラグをクリアします。

アプリケーションが送信機に対してこのフラグを設定すると、送信機の設定に使用されるピクセルクロックが1.001で割られてNTSCフレームレートとの互換性が確保されます。送信機がこのような周波数を生成できない場合、フラグはクリアされます。

ビデオ受信機がフォーマットが減らしたフレームレートを使用していると検出すると、アプリケーションにこの状況を通知するためにこのフラグを設定します。

V4L2_DV_FL_HALF_LINE

インターレースフォーマット固有: セットされている場合、フィールド1（奇数フィールド）の垂直フロントパッジが1半ライン長くなり、フィールド2（偶数フィールド）の垂直バックパッジが1半ライン短くなります。これにより、各フィールドが正確に同じ数の半ラインを持つようになります。半ラインが検出可能か使用可能かはハードウェアに依存します。

V4L2_DV_FL_IS_CE_VIDEO

設定されている場合、これはコンシューマー電子機器（CE）ビデオフォーマットです。このようなフォーマットは、R’G’B’符号化が使用されている場合、デフォルトでR’G’B’値が制限範囲（16-235）を使用する点で、他のフォーマット（一般的にITフォーマットと呼ばれる）とは異なります。CEA-861で定義されたすべてのフォーマットは、640x480p59.94フォーマットを除き、CEフォーマットです。

V4L2_DV_FL_FIRST_FIELD_EXTRA_LINE

SMPTE-125Mなどの一部のフォーマットでは、奇数の総高さを持つインターレース信号が使用されます。このようなフォーマットでは、このフラグが設定されている場合、最初のフィールドに追加のラインが含まれます。それ以外の場合は、2番目のフィールドに含まれます。

V4L2_DV_FL_HAS_PICTURE_ASPECT

設定されている場合、画像のアスペクト比（picture_aspect）フィールドは有効です。それ以外の場合は、ピクセルが正方形であると仮定し、画像のアスペクト比は幅対高度比と同じとします。

V4L2_DV_FL_HAS_CEA861_VIC

設定されている場合、cea861_vicフィールドは有効であり、CEA-861標準に従うビデオ識別コードを含みます。

V4L2_DV_FL_HAS_HDMI_VIC

設定されている場合、hdmi_vicフィールドは有効であり、HDMI標準（HDMIベンダー固有のInfoFrame）に従うビデオ識別コードを含みます。

V4L2_DV_FL_CAN_DETECT_REDUCED_FPS

CEA-861固有：このフラグはビデオ受信機に対してのみ有効で、送信機ではクリアされます。設定されている場合、ハードウェアは通常のフレームレートと1000/1001で減速されたフレームレートの違いを検出できます。例：60Hz vs 59.94Hz、30Hz vs 29.97Hz、24Hz vs 23.976Hzなど。
