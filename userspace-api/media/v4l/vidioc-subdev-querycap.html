7.62. ioctl VIDIOC_SUBDEV_QUERYCAP¶

7.62.1. 名前¶

VIDIOC_SUBDEV_QUERYCAP - サブデバイスの機能を照会する

7.62.2. 概要¶

VIDIOC_SUBDEV_QUERYCAP¶

int ioctl(int fd, VIDIOC_SUBDEV_QUERYCAP, struct v4l2_subdev_capability *argp)

7.62.3. 引数¶

fd

返されるファイル記述子 open().

argp

struct mem_ctl_info v4l2_subdev_capability.

7.62.4. 説明¶

すべての V4L2 サブデバイスは次の機能をサポートしています VIDIOC_SUBDEV_QUERYCAP ioctl. これは、この仕様と互換性のあるカーネルデバイスを特定し、ドライバーおよびハードウェアの機能に関する情報を取得するために使用されます。ioctlは、struct v4l2_capabilityへのポインタを引数として受け取り、ドライバーがこの仕様と互換性がない場合、ioctlは v4l2_subdev_capability ドライバがこの仕様と互換性がない場合、ioctl は ENOTTY エラー コードに設定します。

type v4l2_subdev_capability¶
struct v4l2_subdev_capability¶

__u32

version

ドライバーのバージョン番号。

報告されるバージョンは、カーネルのバージョン番号スキーマに従って V4L2 サブシステムによって提供されます。ただし、安定版や配布版に修正されたカーネルが新しいカーネルの V4L2 スタックを使用している場合など、カーネルのバージョンと常に一致するとは限りません。

バージョン番号は以下のマクロを使用してフォーマットされます。 KERNEL_VERSION() マクロ:

#define KERNEL_VERSION(a,b,c) (((a) << 16) + ((b) << 8) + (c))

__u32 version = KERNEL_VERSION(0, 8, 1);

printf ("Version: %u.%u.%u\\n",

(version >> 16) & 0xFF, (version >> 8) & 0xFF, version & 0xFF);

__u32

capabilities

開いたデバイスのサブデバイス機能、参照 サブデバイス機能フラグ.

__u32

reserved[14]

今後の拡張用に予約されています。V4L2 コアが 0 に設定します。
サブデバイス機能フラグ¶

V4L2_SUBDEV_CAP_RO_SUBDEV

0x00000001

サブデバイスのデバイスノードは読み取り専用モードで登録されます。サブデバイスの ioctls によるデバイス状態の変更アクセスは制限されます。読み取り専用サブデバイスに適用される制限の説明については、各サブデバイス ioctls のドキュメンテーションを参照してください。

7.62.5. 戻り値¶

成功した場合、0 が返されます。エラーの場合、-1 が返され、変数が適切に設定されます。 errno 一般的なエラーコードは、 汎用エラーコード 章。

ENOTTY

そのデバイスノードは V4L2 サブデバイスではありません。
