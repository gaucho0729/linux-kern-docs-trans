4.4. Video Output Overlay Interface¶

On-Screen Display (OSD)と呼ばれる

一部のビデオ出力デバイスは、出力ビデオ信号にフレームバッファ画像をオーバーレイできます。アプリケーションはこのインターフェースを使用してこのようなオーバーレイを設定でき、このインターフェースは Video Overlay インターフェースの構造体とioctlsを借用しています。

OSD機能は、 ビデオ出力 function.

注意

の同じキャラクタースペシャルファイルを通じてアクセスできます。 /dev/video このようなデバイスのデフォルト機能はビデオキャプチャまたは出力です。OSD機能は、 VIDIOC_S_FMT ioctl.

4.4.1. キャパビリティの照会¶

インターフェースを呼び出した後からのみ利用可能です。 Video Output Overlay インターフェースをサポートするデバイスは、 V4L2_CAP_VIDEO_OUTPUT_OVERLAY フラグを含めます。以下のようにします： capabilities 構造体の v4l2_capability は ioctl VIDIOC_QUERYCAP ioctl.

4.4.2. フレームバッファ¶

インターフェースとは異なり、フレームバッファは通常TVカードで実装され、グラフィックカードではありません。Linuxではフレームバッファデバイスとしてアクセス可能で、（ Video Overlay ）です。V4L2デバイスが与えられた場合、アプリケーションは/dev/fbNioctlを呼び出して対応するフレームバッファデバイスを検索できます。このioctlは、フレームバッファの物理アドレスを含む情報の他に、 VIDIOC_G_FBUF の場所を返します。フレームバッファデバイスのioctl base 構造体の v4l2_framebufferは、 FBIOGET_FSCREENINFO ioctlおよび構造体 smem_start 構造体の fb_fix_screeninfoの部分で、 FBIOGET_FSCREENINFO が fb_fix_screeninfo で定義されています。 linux/fb.h ヘッダーファイルに含まれています。

フレームバッファの幅と高さは現在のビデオ標準に依存します。V4L2ドライバは、すべてのアプリケーションがフレームバッファデバイスを閉じるまで、ビデオ標準の変更（またはフレームバッファサイズ変更を示す他のioctl）を拒否するため、 EBUSY エラーコードを返します。

4.4.2.1. 例: OSD用フレームバッファデバイスの検索¶

#include <linux/fb.h>

struct v4l2_framebuffer fbuf;
unsigned int i;
int fb_fd;

if (-1 == ioctl(fd, VIDIOC_G_FBUF, &fbuf)) {
    perror("VIDIOC_G_FBUF");
    exit(EXIT_FAILURE);
}

for (i = 0; i < 30; i++) {
    char dev_name[16];
    struct fb_fix_screeninfo si;

    snprintf(dev_name, sizeof(dev_name), "/dev/fb%u", i);

    fb_fd = open(dev_name, O_RDWR);
    if (-1 == fb_fd) {
        switch (errno) {
        case ENOENT: /* no such file */
        case ENXIO:  /* no driver */
            continue;

        default:
            perror("open");
            exit(EXIT_FAILURE);
        }
    }

    if (0 == ioctl(fb_fd, FBIOGET_FSCREENINFO, &si)) {
        if (si.smem_start == (unsigned long)fbuf.base)
            break;
    } else {
        /* Apparently not a framebuffer device. */
    }

    close(fb_fd);
    fb_fd = -1;
}

/* fb_fd is the file descriptor of the framebuffer device
   for the video output overlay, or -1 if no device was found. */

4.4.3. オーバーレイウィンドウとスケーリング¶

オーバーレイはソースとターゲットの矩形によって制御されます。ソース矩形はフレームバッファ画像の一部をオーバーレイする範囲を選び、ターゲット矩形は出力ビデオ信号で画像が表示される領域を示します。ドライバはスケーリングや矩形の任意のサイズ・位置をサポートする場合もあります。さらに、ドライバは Video Overlay インターフェースの構造体とioctlsを借用しています。

インターフェースで定義されたクリッピング/ブレンドメソッドのいずれか（またはそれらのいずれも）をサポートする場合があります。 v4l2_window 構造体 type フィールドを設定します。 v4l2_format に（木の下から葉に向かって） V4L2_BUF_TYPE_VIDEO_OUTPUT_OVERLAY を初期化し、 VIDIOC_G_FMT は、ソース矩形のサイズ、フレームバッファ内の位置、およびオーバーレイに使用するクリッピング/ブレンドメソッドを定義します。現在のパラメータを取得するには、アプリケーションは v4l2_window ioctlを設定します。ドライバは構造体 winサブ構造体に名前

を指定して、その内容を返します。以前にプログラムされたクリッピングリストやビットマップは取得できません。 type フィールドを設定します。 v4l2_format に（木の下から葉に向かって） V4L2_BUF_TYPE_VIDEO_OUTPUT_OVERLAYソース矩形をプログラムするには、アプリケーションは win を設定し、サブ構造体を初期化して VIDIOC_S_FMT ioctlを呼び出します。ドライバはハードウェアの制限に応じてパラメータを調整し、実際のパラメータを VIDIOC_G_FMT と同様に返します。同様に VIDIOC_S_FMTand wakes up processes waiting on the timerfd. While iterating the VIDIOC_TRY_FMT ioctlはドライバの機能を確認するためのもので、ドライバの状態を実際に変更することなく使用できます。ただし、 VIDIOC_S_FMT とは異なり、オーバーレイが有効になってからでも動作します。

インターフェースで定義されたクリッピング/ブレンドメソッドのいずれか（またはそれらのいずれも）をサポートする場合があります。 v4l2_crop ターゲット矩形のサイズと位置を定義します。オーバーレイのスケーリングファクターは、構造体に指定された幅と高さから推定されます。 v4l2_window および struct v4l2_cropクロッピングAPIは、 ビデオ出力 および Video Output Overlay デバイスに対して同様に適用され、 ビデオキャプチャ および Video Overlay デバイスに対して適用され、データフローの方向を逆にしているだけです。詳細については 画像のトリミング、挿入およびスケーリング – CROP API.

4.4.4. オーバーレイの有効化¶

V4L2 ioctを用いてオーバーレイを有効にするか無効にする機能はありません。ただし、ドライバーのフレームバッファインターフェースは、可能であれば FBIOBLANK ioctl.
