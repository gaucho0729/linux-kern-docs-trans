7.30. ioctl VIDIOC_G_FBUF, VIDIOC_S_FBUF¶

7.30.1. 名前¶

VIDIOC_G_FBUF - VIDIOC_S_FBUF - フレームバッファオーバーレイパラメータの取得または設定

7.30.2. 概要¶

VIDIOC_G_FBUF¶

int ioctl(int fd, VIDIOC_G_FBUF, struct v4l2_framebuffer *argp)

VIDIOC_S_FBUF¶

int ioctl(int fd, VIDIOC_S_FBUF, const struct v4l2_framebuffer *argp)

7.30.3. 引数¶

fd

返されるファイル記述子 open().

argp

struct mem_ctl_info v4l2_framebuffer.

7.30.4. 説明¶

アプリケーションは次の機能を使用して VIDIOC_G_FBUF および VIDIOC_S_FBUF ioctlでフレームバッファパラメータを取得および設定するための Video Overlay または Video Output Overlay (OSD). オーバーレイの種類はデバイスの種類（キャプチャまたは出力デバイス）によって示され、ioctlで確認できます。 ioctl VIDIOC_QUERYCAP ioctl。1つの /dev/videoN デバイスは両方のオーバーレイをサポートしてはいけません。

V4L2 APIは破壊的および非破壊的オーバーレイを区別します。破壊的オーバーレイは、キャプチャされたビデオ画像をグラフィックカードのビデオメモリにコピーします。非破壊的オーバーレイは、ビデオ画像をVGA信号に合成するか、グラフィックをビデオ信号に合成します。 ビデオ出力オーバーレイ これらは常に非破壊的です。

現在のパラメータを取得するには、アプリケーションは VIDIOC_G_FBUF ioctlを呼び出し、struct v4l2_framebufferへのポインタを渡します。 v4l2_framebuffer 構造体のすべてのフィールドを埋めます。オーバーレイがサポートされていない場合、EINVALエラー コードを返します。

パラメータを設定するには、アプリケーションは Video Output Overlaystruct v4l2_framebufferを初期化する必要があります。 flags フィールドを設定します。 v4l2_framebufferフレームバッファはTVカードで実装されているため、他のすべてのパラメータはドライバーによって決定されます。アプリケーションが VIDIOC_S_FBUF struct v4l2_framebufferへのポインタを渡すと、ドライバーがオーバーレイを準備し、 VIDIOC_G_FBUF フレームバッファパラメータを返します。エラー コードを返す場合もあります。

パラメータを設定するには、アプリケーションは 非破壊的ビデオオーバーレイstruct v4l2_framebufferを初期化する必要があります。 flags field, the fmt サブ構造体を呼び出し、 VIDIOC_S_FBUFドライバーがオーバーレイを準備し、フレームバッファパラメータを返します。 VIDIOC_G_FBUF フレームバッファパラメータを返します。エラー コードを返す場合もあります。

非破壊的ビデオオーバーレイの場合、 破壊的ビデオオーバーレイ アプリケーションはさらにベースアドレスを提供する必要があります。 base DMAをランダムなメモリ位置に設定すると、システムセキュリティや安定性、ハードウェアの破損を引き起こす可能性があるため、破壊的ビデオオーバーレイのパラメータを設定できるのはスーパーユーザーだけです。

__u32

bytesperline

隣接する2行の左端ピクセル間のバイト単位の距離。

このフィールドは 非破壊的ビデオオーバーレイ.

For 破壊的ビデオオーバーレイ アプリケーションおよびドライバはこのフィールドを設定して各ライン末尾にパディングバイトを要求できます。ただしドライバは要求値を無視し、 width timesバイト毎ピクセルまたはハードウェアが要するより大きい値を返す可能性があります。これはアプリケーションがこのフィールドをゼロに設定することで適切なデフォルトを取得できるということを意味します。

For ビデオ出力オーバーレイ ドライバは有効な値を返す必要があります。

ビデオハードウェアがパディングバイトにアクセスできるため、これらはアクセス可能なメモリに存在する必要があります。例えば画像の最後のライン後のパディングバイトがシステムページ境界を越える場合を想定してください。キャプチャデバイスはパディングバイトを書き込むかもしれませんが、その値は未定義です。出力デバイスはパディングバイトの内容を無視します。

画像形式がプランナーフォーマットの場合、 bytesperline 値は最初の平面に適用され、同じ係数で width 他の平面用のフィールドです。例えばYUV 4:2:0画像のCbおよびCr平面は、Y平面に比べて各行の後にパディングバイトが半分になります。誤解を避けるため、ドライバーはこの値を bytesperline スケールファクターの倍数に丸めた値に設定する必要があります。

__u32

sizeimage

このフィールドは 非破壊的ビデオオーバーレイ。 破壊的ビデオオーバーレイ アプリケーションはこのフィールドを初期化する必要があります。 ビデオ出力オーバーレイ ドライバーは有効な形式を返す必要があります。

Together with base によりドライバがアクセス可能なフレームバッファメモリが定義されます。

フレームバッファ機能フラグ¶

V4L2_FBUF_CAP_EXTERNOVERLAY

0x0001

デバイスは非破壊オーバーレイをサポートしています。ドライバがこのフラグをクリアすると、破壊オーバーレイのみがサポートされます。現時点では破壊的および非破壊的なオーバーレイをサポートするドライバは存在していません。実際にはビデオ出力オーバーレイは常に非破壊的です。

V4L2_FBUF_CAP_CHROMAKEY

0x0002

デバイスはクロマキーにより画像をクリッピングする機能をサポートしています。つまり、後述の色を持つピクセルのみをVGAまたはビデオ信号のピクセルに置き換えます。クロマキーは破壊的オーバーレイには意味がありません。

V4L2_FBUF_CAP_LIST_CLIPPING

0x0004

デバイスはクリップ矩形のリストを使用してクリッピングをサポートしています。

V4L2_FBUF_CAP_BITMAP_CLIPPING

0x0008

デバイスはビットマスクを使用してクリッピングをサポートしています。

V4L2_FBUF_CAP_LOCAL_ALPHA

0x0010

デバイスはフレームバッファまたはVGA信号のアルファチャネルを使用してクリッピング/ブレンドをサポートしています。アルファブレンドは破壊的オーバーレイには意味がありません。

V4L2_FBUF_CAP_GLOBAL_ALPHA

0x0020

デバイスはグローバルアルファ値を使用したアルファブレンドをサポートしています。アルファブレンドは破壊的オーバーレイには意味がありません。

V4L2_FBUF_CAP_LOCAL_INV_ALPHA

0x0040

デバイスはフレームバッファまたはVGA信号の逆アルファチャネルを使用してクリッピング/ブレンドをサポートしています。アルファブレンドは破壊的オーバーレイには意味がありません。

V4L2_FBUF_CAP_SRC_CHROMAKEY

0x0080

デバイスはソースクロマキーをサポートしています。クロマキー色を持つビデオピクセルはフレームバッファピクセルに置き換えられ、これはちょうど逆の動作です。 V4L2_FBUF_CAP_CHROMAKEY

V4L2_FBUF_FLAG_LOCAL_ALPHA

0x0008

フレームバッファのアルファチャネルを使用して、フレームバッファピクセルをビデオ画像とクリップまたはブレンドします。ブレンド関数は: output = フレームバッファピクセル * アルファ + ビデオピクセル * (1 - アルファ)です。実際のアルファ深度はフレームバッファピクセル形式によって異なります。

V4L2_FBUF_FLAG_GLOBAL_ALPHA

0x0010

グローバルアルファ値を使用してフレームバッファをビデオ画像とブレンドします。ブレンド関数は: output = (フレームバッファピクセル * アルファ + ビデオピクセル * (255 - アルファ)) / 255です。アルファ値は global_alpha 構造体の v4l2_window ioctlコマンドを参照してください。 VIDIOC_S_FMT リストのクリップ矩形またはビットマップを使用したクリッピングを有効にするフラグはありません。これらの方法は Video Overlay Interface および Video Output Overlay Interface.

V4L2_FBUF_FLAG_LOCAL_INV_ALPHA

0x0020

例え V4L2_FBUF_FLAG_LOCAL_ALPHA、フレームバッファのアルファチャネルを使用してフレームバッファピクセルをビデオ画像とクリップまたはブレンドしますが、逆転したアルファ値を使用します。ブレンド関数は: output = フレームバッファピクセル * (1 - アルファ) + ビデオピクセル * アルファです。実際のアルファ深度はフレームバッファピクセル形式によって異なります。

V4L2_FBUF_FLAG_SRC_CHROMAKEY

0x0040

ソースチロマキーを使用します。ソースチロマキー色は chromakey 構造体の v4l2_window ioctlコマンドを参照してください。 VIDIOC_S_FMT リストのクリップ矩形またはビットマップを使用したクリッピングを有効にするフラグはありません。これらの方法は Video Overlay Interface および Video Output Overlay Interface。両方のチロマキーは互いに排他的であり、同じ chromakey 構造体の v4l2_window が使用されています。

7.30.5. 戻り値¶

成功した場合、0 が返されます。エラーの場合、-1 が返され、変数が適切に設定されます。 errno 一般的なエラーコードは、 汎用エラーコード 章。

EPERM

VIDIOC_S_FBUF 破壊的オーバーレイのパラメータを交渉するためには特権ユーザーのみが呼び出せます。

EINVAL

以下の VIDIOC_S_FBUF パラメータは不適切です。
