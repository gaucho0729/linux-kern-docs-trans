1.27. 画像のトリミング、挿入およびスケーリング – CROP API¶

注意

CROP APIは、より新しい SELECTION APIによってほぼ置き換えられています。ほとんどの場合、新しいAPIを優先すべきですが、ピクセルアスペクト比の検出は VIDIOC_CROPCAP で実装され、SELECTION APIには同等の機能がありません。詳しくは 旧来のトリミングAPIとの比較 を参照してください。

一部のビデオキャプチャデバイスは、画像の一部をサンプリングし、任意のサイズに縮小または拡大する機能を持っています。このような機能をトリミングおよびスケーリングと呼びます。また、一部のビデオ出力デバイスは、画像を任意のスキャンラインと水平オフセットに挿入する機能を持っています。

アプリケーションは、以下のAPIを使用してビデオ信号から領域を選択し、デフォルトの領域およびハードウェアの制限を照会できます。

注意

名前とは異なり、 VIDIOC_CROPCAP, VIDIOC_G_CROP および VIDIOC_S_CROP ioctlは入力デバイスにも適用されます。

スケーリングにはソースとターゲットが必要です。ビデオキャプチャまたはオーバーレイデバイスでは、ソースはビデオ信号で、 cropping ioctlsは実際にサンプリングされる領域を決定します。ターゲットはアプリケーションが読み込む画像またはグラフィックスクリーンにオーバーレイされる画像です。そのサイズ（オーバーレイの場合は位置も）は VIDIOC_G_FMT および VIDIOC_S_FMT ioctls.

で交渉されます。ビデオ出力デバイスでは、ソースはアプリケーションから渡される画像で、そのサイズは再び VIDIOC_G_FMT および VIDIOC_S_FMT ioctl、または圧縮ビデオストリームにエンコードされています。ターゲットはビデオ信号で、 cropping ioctlsは画像が挿入される領域を決定します。

デバイスがスケーリングをサポートしない場合や VIDIOC_G_CROP および VIDIOC_S_CROP ioctlをサポートしない場合でも、ソースとターゲットの矩形は定義されます。そのサイズ（位置が必要な場合は）はこの場合固定されます。

注意

CROPまたはSELECTION APIをサポートするすべてのキャプチャおよび出力デバイスは、同時に VIDIOC_CROPCAP ioctl.

1.27.1. トリミング構造体¶

キャプチャデバイスでは、サンプリング可能な領域の左上角の座標、幅、高さは bounds 構造体の v4l2_cropcap は VIDIOC_CROPCAP サブ構造体によって指定されます。幅広いハードウェアをサポートするため、この仕様では原点や単位を定義していません。ただし、ドライバでは慣例として、水平同期パルスの先頭エッジ（0H、参照 図4.1. 行同期）を基準に未スケーリングのサンプルを水平方向に数えるべきです。垂直方向ではITU-Rのライン番号を用います（参照 525ライン および 625ライン)、ドライバーが両方のフィールドをキャプチャできる場合、2倍になります。

ソース矩形（実際にサンプリングされる領域）の左上角、幅、高さは、struct によって指定されます。 v4l2_crop struct と同じ座標系を使用します。 v4l2_cropcap. アプリケーションは を使用して、 VIDIOC_G_CROP および VIDIOC_S_CROP ioctls を使用してこの矩形を取得および設定できます。この矩形はキャプチャ境界内に完全に含まれなければなりません。ドライバーはハードウェアの制限に応じて、要求されたサイズおよび/または位置をさらに調整する場合があります。

各キャプチャデバイスは、 によって指定されるデフォルトのソース矩形を持ちます。 defrect struct のサブ構造体。 v4l2_cropcapこの矩形の中心は、ビデオ信号のアクティブな画像領域の中心と一致し、ドライバーのライターが完全な画像とみなす範囲をカバーする必要があります。ドライバーは、ドライバーが最初にロードされるときにソース矩形をデフォルトに戻す必要がありますが、その後は行いません。

出力デバイスの場合、これらの構造体と ioctls は適切に使用され、 target ビデオ信号に画像が挿入される矩形を定義します。

1.27.2. スケーリング調整¶

ビデオハードウェアは、さまざまなクロッピング、挿入、スケーリングの制限を持つ場合があります。スケーリングはアップまたはダウンのみをサポートする場合、または離散的なスケーリングファクターのみをサポートする場合、または水平方向と垂直方向で異なるスケーリング能力を持つ場合もあります。また、スケーリングをまったくサポートしない場合もあります。同時に、struct v4l2_crop 矩形はアライメントが必要であり、ソースとターゲットの矩形は任意の上限と下限のサイズ制限を持つ場合があります。特に最大 width および height 構造体 v4l2_crop は struct の領域より小さくなる場合があります。 v4l2_cropcap. bounds 領域です。したがって、通常どおり、ドライバーは要求されたパラメータを調整し、実際に選択された値を返す必要があります。

アプリケーションは、特定の画像サイズやビデオ信号内の特定の領域を好む場合、ソースまたはターゲットの矩形をまず変更できます。ドライバーがハードウェアの制限を満たすために両方を調整する必要がある場合、最後に要求された矩形が優先されます。ドライバーは、逆の矩形を調整することを好むべきです。The VIDIOC_TRY_FMT ioctl はドライバーの状態を変更しないので、要求された矩形のみを調整します。

ビデオキャプチャデバイスのスケーリングが1:1または2:1の比率に制限されており、ターゲット画像サイズが16 × 16ピクセルの倍数である場合、ソースのクロッピング矩形はデフォルト値（この例では上限値も同じ640 × 40, 0, 0のオフセット）が設定されています。アプリケーションが300 × 225ピクセルの画像サイズを要求し、ビデオが「フルピクチャー」から縮小されるものと想定している場合、ドライバは最も近い304 × 224ピクセルの画像サイズを設定し、要求サイズに最も近いクロッピング矩形608 × 224（224 × 2:1は400ピクセルの制限を超えるため）を選択します。オフセット0, 0は依然として有効なため変更されません。アプリケーションが報告したデフォルトのクロッピング矩形を基に、別のオフセットを提案するのは簡単です。 VIDIOC_CROPCAP アプリケーションが元のリクエストに近いオリジナルのアスペクト比の領域をカバーするように強く要求する場合、608 × 456ピクセルのクロッピング矩形を要求します。現在のスケーリングファクターによりクロッピングは640 × 384に制限されるため、ドライバはクロッピングサイズを608 × 384に設定し、画像サイズを最も近い304 × 192に調整します。

ソースとターゲットの矩形はデバイスの閉じたり開いたりするたびに変更されず、デバイスへのデータのパイピングが特別な準備なしで動作するようにします。高度なアプリケーションはI/Oを開始する前にパラメータが適切であることを確認する必要があります。

1.27.3. 例¶

次の2つの例ではビデオキャプチャデバイスが仮定されています；他のデバイスタイプの場合には変更してください。

注意

例: クロッピングパラメータのリセット V4L2_BUF_TYPE_VIDEO_CAPTURE 例: 簡単なダウンスケーリング

1.27.4. 例: 出力領域の選択¶

struct v4l2_cropcap cropcap;
struct v4l2_crop crop;

memset (&cropcap, 0, sizeof (cropcap));
cropcap.type = V4L2_BUF_TYPE_VIDEO_CAPTURE;

if (-1 == ioctl (fd, VIDIOC_CROPCAP, &cropcap)) {
    perror ("VIDIOC_CROPCAP");
    exit (EXIT_FAILURE);
}

memset (&crop, 0, sizeof (crop));
crop.type = V4L2_BUF_TYPE_VIDEO_CAPTURE;
crop.c = cropcap.defrect;

/* Ignore if cropping is not supported (EINVAL). */

if (-1 == ioctl (fd, VIDIOC_S_CROP, &crop)
    && errno != EINVAL) {
    perror ("VIDIOC_S_CROP");
    exit (EXIT_FAILURE);
}

1.27.6. 例: 現在のスケーリングファクターおよびピクセルアスペクト¶

注意

この例はビデオキャプチャデバイスを前提としています。

struct v4l2_cropcap cropcap;
struct v4l2_crop crop;

memset (&cropcap, 0, sizeof (cropcap));
cropcap.type = V4L2_BUF_TYPE_VIDEO_OUTPUT;

if (-1 == ioctl (fd, VIDIOC_CROPCAP;, &cropcap)) {
    perror ("VIDIOC_CROPCAP");
    exit (EXIT_FAILURE);
}

memset (&crop, 0, sizeof (crop));

crop.type = V4L2_BUF_TYPE_VIDEO_OUTPUT;
crop.c = cropcap.defrect;

/* Scale the width and height to 50 % of their original size
   and center the output. */

crop.c.width /= 2;
crop.c.height /= 2;
crop.c.left += crop.c.width / 2;
crop.c.top += crop.c.height / 2;

/* Ignore if cropping is not supported (EINVAL). */

if (-1 == ioctl (fd, VIDIOC_S_CROP, &crop)
    && errno != EINVAL) {
    perror ("VIDIOC_S_CROP");
    exit (EXIT_FAILURE);
}

1.27.7. ストリーミングパラメータ¶

注意

1.26.5. 例

struct v4l2_cropcap cropcap;
struct v4l2_crop crop;
struct v4l2_format format;
double hscale, vscale;
double aspect;
int dwidth, dheight;

memset (&cropcap, 0, sizeof (cropcap));
cropcap.type = V4L2_BUF_TYPE_VIDEO_CAPTURE;

if (-1 == ioctl (fd, VIDIOC_CROPCAP, &cropcap)) {
    perror ("VIDIOC_CROPCAP");
    exit (EXIT_FAILURE);
}

memset (&crop, 0, sizeof (crop));
crop.type = V4L2_BUF_TYPE_VIDEO_CAPTURE;

if (-1 == ioctl (fd, VIDIOC_G_CROP, &crop)) {
    if (errno != EINVAL) {
        perror ("VIDIOC_G_CROP");
        exit (EXIT_FAILURE);
    }

    /* Cropping not supported. */
    crop.c = cropcap.defrect;
}

memset (&format, 0, sizeof (format));
format.fmt.type = V4L2_BUF_TYPE_VIDEO_CAPTURE;

if (-1 == ioctl (fd, VIDIOC_G_FMT, &format)) {
    perror ("VIDIOC_G_FMT");
    exit (EXIT_FAILURE);
}

/* The scaling applied by the driver. */

hscale = format.fmt.pix.width / (double) crop.c.width;
vscale = format.fmt.pix.height / (double) crop.c.height;

aspect = cropcap.pixelaspect.numerator /
     (double) cropcap.pixelaspect.denominator;
aspect = aspect * hscale / vscale;

/* Devices following ITU-R BT.601 do not capture
   square pixels. For playback on a computer monitor
   we should scale the images to this size. */

dwidth = format.fmt.pix.width / aspect;
dheight = format.fmt.pix.height;
