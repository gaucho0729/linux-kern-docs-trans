7.46. ioctl VIDIOC_QBUF, VIDIOC_DQBUF¶

7.46.1. 名前¶

VIDIOC_QBUF - VIDIOC_DQBUF - ドライバとバッファを交換する

成功した場合、0 が返されます。エラーの場合、-1 が返され、変数が適切に設定されます。 errno 一般的なエラーコードは、 汎用エラーコード 章。

EAGAIN

Non-blocking I/Oは以下を使用して選択されています。 O_NONBLOCK 出力キューにバッファがなかった場合。

EINVAL

バッファ type サポートされていません、または index バッファが範囲外、またはまだバッファが割り当てられていない、または userptr または length が無効です、または V4L2_BUF_FLAG_REQUEST_FD フラグが設定されていたが、指定された request_fd が無効でした、または m.fd 無効なDMABUFファイル記述子でした。

EIO

VIDIOC_DQBUF 内部エラーにより失敗しました。また、信号喪失などの一時的な問題を示す可能性もあります。

注意

エラーを返したにもかかわらず、ドライバーが(空の)バッファをデキューする可能性があり、場合によってはキャプチャを停止するかもしれません。ただし、このようなバッファを再利用する場合、安全性が保証されない可能性があります。その詳細（例： index)も返されない可能性があります。ドライバーは、回復可能なエラーを示すために V4L2_BUF_FLAG_ERROR 0を返すことで、エラーを示すことが推奨されます。その場合、アプリケーションはバッファを安全に再利用し、ストリーミングを継続できるはずです。

EPIPE

VIDIOC_DQBUF mem2memコーデックの空のキャプチャキューの場合、特定のバッファがすでにデキューされている場合にこのエラーを返します。 V4L2_BUF_FLAG_LAST すでにデキューされており、新しいバッファが利用可能になることはない場合です。

EBADR

以下の V4L2_BUF_FLAG_REQUEST_FD フラグが設定されていたにもかかわらず、デバイスが指定されたバッファタイプのリクエストをサポートしていない場合、または V4L2_BUF_FLAG_REQUEST_FD フラグが設定されていないにもかかわらず、デバイスがバッファがリクエストの一部であることを要求している場合です。

EBUSY

最初のバッファはリクエストを通じてキューイングされたにもかかわらず、アプリケーションがそれを直接キューイングしようとしたり、逆にリクエストを通じてキューイングする代わりに直接キューイングしようとしたりする場合（両方のAPIを混在させることは許可されていません）。
