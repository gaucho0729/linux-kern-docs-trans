7.47. ioctl. マルチプレーンAPIでは、structの一部のプレーン固有メンバが¶

7.47.1. 名前¶

VIDIOC_QUERYBUF - バッファの状態を照会する

7.47.2. 概要¶

VIDIOC_QUERYBUF¶

int ioctl(int fd, VIDIOC_QUERYBUF, struct v4l2_buffer *argp)

7.47.3. 引数¶

fd

返されるファイル記述子 open().

argp

struct mem_ctl_info v4l2_buffer.

7.47.4. 説明¶

このioctlは以下のI/Oメソッドの一部です。 ストリーミング I/Oメソッド。バッファが割り当てられた後、いつでもバッファの状態を照会するために使用できます ioctl VIDIOC_REQBUFS ioctl.

アプリケーションは type フィールドを設定します。 v4l2_buffer 以前にstructで使用したと同じバッファタイプ v4l2_format type および struct v4l2_requestbuffers type内のコールバック数を示し、 index field. 有効なインデックス番号はゼロから、ioctl DMX_REQBUFSで割り当てられたバッファ数にまで範囲をもつ。 ioctl VIDIOC_REQBUFS (struct v4l2_requestbuffers count)から1を引いた値。The reserved および reserved2 フィールドを0に設定する必要があります。マルチプランナーファイルを使用する場合、 マルチプランアピand wakes up processes waiting on the timerfd. While iterating the m.planes フィールドには、ユーザー空間のポインタで構造体配列を指す必要があります v4l2_plane 2.5開発シリーズで導入された形式です。 length フィールドには、その配列の要素数を設定する必要があります。呼び出し後 ioctl. マルチプレーンAPIでは、structの一部のプレーン固有メンバが この構造体のポインタを渡すと、ドライバがエラー コードを返すか、構造体の残り部分を埋めるかします。

～において、クエリは flags フィールドの V4L2_BUF_FLAG_MAPPED, V4L2_BUF_FLAG_PREPARED, V4L2_BUF_FLAG_QUEUED および V4L2_BUF_FLAG_DONE フラグは有効です。The memory フィールドは現在のI/Oメソッドに設定されます。シングルプランアピの場合、the m.offset バッファのデバイスメモリからのオフセットを含み、the length フィールドにはそのサイズを含みます。マルチプランアピの場合、fields m.mem_offset および length の m.planes 配列要素が使用され、the length 構造体の v4l2_buffer 配列要素の数に設定されます。ドライバは残りのフィールドとフラグを設定するかどうかは自由です。これらはこの文脈では意味を持ちません。

構造体 v4l2_buffer 構造体は以下に指定されています。 バッファ.

成功した場合、0 が返されます。エラーの場合、-1 が返され、変数が適切に設定されます。 errno 一般的なエラーコードは、 汎用エラーコード 章。
