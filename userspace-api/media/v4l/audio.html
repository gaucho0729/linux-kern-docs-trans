1.5. オーディオ入出力¶

オーディオ入力と出力はデバイスの物理的なコネクタです。ビデオキャプチャデバイスは入力を持ち、出力デバイスは出力を持ち、それぞれゼロまたはそれ以上の数があります。ラジオデバイスはオーディオ入力または出力を持ちません。それらは正確に1つのチューナーを持ち、これは実際には 通常のRCU読み込み側クリティカルセクションは、条件付きでスリープロックを取得することが許容されます（例として オーディオソースですが、このAPIはチューナーをビデオ入力または出力と関連付けるだけであり、ラジオデバイスはこれらを持ちません。 1 テレビカード上のコネクタで受信したオーディオ信号をサウンドカードにループバックするものは、オーディオ出力とみなされません。

オーディオとビデオの入出力は関連しています。ビデオソースを選択すると同時にオーディオソースも選択されます。これはビデオとオーディオソースがチューナーである場合に最も明確です。さらにオーディオコネクタは1つのビデオ入力または出力と複数組み合わせることができます。2つのコンポジットビデオ入力と2つのオーディオ入力があると仮定すると、最大で4つの有効な組み合わせがあります。ビデオとオーディオコネクタの関係は audioset 該当する構造体のフィールド v4l2_input またはstruct v4l2_outputで定義されています。ここで各ビットはゼロから始まるインデックス番号を1つのオーディオ入力または出力に表します。

利用可能な入力と出力の数と属性を学ぶには、アプリケーションは ioctl VIDIOC_ENUMAUDIO および VIDIOC_ENUMAUDOUT ioctlでそれらを列挙できます。struct v4l2_audio は ioctl VIDIOC_ENUMAUDIO ioctlによって返されるものも含め、現在のオーディオ入力が照会される際の信号状態情報を含みます。

以下の VIDIOC_G_AUDIO および VIDIOC_G_AUDOUT ioctlは現在のオーディオ入力と出力をそれぞれ報告します。

注意

注意してください。これらと異なり、 VIDIOC_G_INPUT および VIDIOC_G_OUTPUT これらのioctlは構造体として ioctl VIDIOC_ENUMAUDIO および VIDIOC_ENUMAUDOUT を返しますが、単にインデックス番号だけではありません。

オーディオ入力の選択とそのプロパティの変更にはアプリケーションは VIDIOC_S_AUDIO ioctlを呼び出します。オーディオ出力（現在は変更可能なプロパティを持たない）を選択するにはアプリケーションは VIDIOC_S_AUDOUT ioctl.

ドライバは、デバイスが複数の選択可能なオーディオ入力を持つ場合、すべてのオーディオ入力ioctlを実装しなければなりません。デバイスが複数の選択可能なオーディオ出力を持つ場合、すべてのオーディオ出力ioctlを実装しなければなりません。デバイスにオーディオ入力または出力が存在する場合、ドライバはstruct V4L2_CAP_AUDIO のフラグを設定しなければなりません。 v4l2_capability は ioctl VIDIOC_QUERYCAP ioctl.

1.5.1. 例: 現在のオーディオ入力に関する情報¶

struct v4l2_audio audio;

memset(&audio, 0, sizeof(audio));

if (-1 == ioctl(fd, VIDIOC_G_AUDIO, &audio)) {
    perror("VIDIOC_G_AUDIO");
    exit(EXIT_FAILURE);
}

printf("Current input: %s\\n", audio.name);

1.5.2. 例: 1番目のオーディオ入力への切り替え¶

struct v4l2_audio audio;

memset(&audio, 0, sizeof(audio)); /* clear audio.mode, audio.reserved */

audio.index = 0;

if (-1 == ioctl(fd, VIDIOC_S_AUDIO, &audio)) {
    perror("VIDIOC_S_AUDIO");
    exit(EXIT_FAILURE);
}

実際にstruct v4l2_audio には tuner のようなフィールドを持つべきです。 v4l2_inputこれによりAPIがより一貫性を持ち、複数のチューナーを持つラジオデバイスを許可します。
