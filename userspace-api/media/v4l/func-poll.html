7.67. V4L2 poll()¶

7.67.1. 名前¶

v4l2-poll - ファイルディスクリプタでイベントが発生するのを待機します

7.67.2. 概要¶

#include <sys/poll.h>
int poll(struct pollfd *ufds, unsigned int nfds, int タイムアウト)¶

7.67.3. 引数¶

7.67.4. 説明¶

With the poll() 関数アプリケーションは、ドライバーがデータをキャプチャしたか、または出力用データを受け入れる準備ができているまで実行を一時停止します

ストリーミングI/Oが交渉された場合、この関数はキャプチャデバイスがバッファを満たした後、ioctlを介してデキューできるまで待機します VIDIOC_DQBUF 出力デバイスの場合、この関数はデバイスが新しいバッファを受け入れる準備ができているまで待機します VIDIOC_QBUF ioctlを介してディスプレイ用にキューイングされるまで待機します。バッファがすでにドライバーの送出キューにある場合（キャプチャ）または受信キューが満たされていない場合（ディスプレイ）には、関数は即座に返します

成功した場合 poll() 選択されたファイルディスクリプタの数を返します（つまり、フィールドがゼロでないファイルディスクリプタについて）。CECデバイスは、 revents 対応する struct pollfd 構造体のフィールドがゼロでない場合。キャプチャデバイスは POLLIN および POLLRDNORM フィールドにフラグを設定します revents フィールドを設定します。出力デバイスは POLLOUT および POLLWRNORM flags. タイムアウトした場合ゼロを返し、失敗した場合は-1を返し、変数は適切に設定されます。 errno 関数を呼び出していなかった場合、 VIDIOC_STREAMON 、そして poll() 関数が成功しますが、フィールドを設定します。 POLLERR フラグを含めます。以下のようにします： revents フィールド。アプリケーションが関数を呼び出しました場合 VIDIOC_STREAMON キャプチャデバイスの場合ですが、まだ呼び出していません VIDIOC_QBUFand wakes up processes waiting on the timerfd. While iterating the poll() 関数が成功し、フィールドを設定します POLLERR フラグを含めます。以下のようにします： revents フィールドを設定します。出力デバイスの場合、この同じ状況は poll() 成功することになりますが、フィールドを設定します POLLOUT および POLLWRNORM フィールドにフラグを設定します revents フィールドによって保護されています。

イベントが発生した場合（参照） ioctl VIDIOC_DQEVENT場合、 POLLPRI will be set in the revents フィールドと poll() will return.

When use of the read() function has been negotiated and the driver does not capture yet, the poll() function starts capturing. When that fails it returns a POLLERR as above. Otherwise it waits until data has been captured and can be read. When the driver captures continuously (as opposed to, for example, still images) the function may return immediately.

When use of the write() function has been negotiated and the driver does not stream yet, the poll() function starts streaming. When that fails it returns a POLLERR as above. Otherwise it waits until the driver is ready for a non-blocking write() 呼び出し時にkdumpが発生します。

If the caller is only interested in events (just POLLPRI is set in the events field), then poll() will ではありません start streaming if the driver does not stream yet. This makes it possible to just poll for events and not for buffers.

All drivers implementing the read() または write() function or streaming I/O must also support the poll() function.

詳細については、 poll() マニュアルページ。

7.67.5. 戻り値¶

成功した場合、 poll() 非ゼロのフィールドを持つ構造体の数を返します。呼び出しがタイムアウトした場合はゼロを返します。エラーの場合、-1を返し、 revents エラーの場合、-1を返し、 errno 変数が適切に設定されています:

EBADF

1つ以上の ufds メンバーが無効なファイル記述子を指定しています。

EBUSY

The driver does not support multiple read or write streams and the device is already in use.

EFAULT

ufds 参照しているメモリ領域がアクセスできません。

EINTR

呼び出しがシグナルによって中断されました。

EINVAL
