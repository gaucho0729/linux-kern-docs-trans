1.26.3. 設定¶

アプリケーションは次の機能を使用して セレクションAPI ビデオ信号またはバッファ内の領域を選択し、デフォルト設定やハードウェアの制限を照会できます。

ビデオハードウェアにはさまざまなクロッピング、コンポジング、スケーリングの制限がある場合があります。スケーリングはアップまたはダウンのみをサポートする場合、または離散的なスケーリングファクターのみをサポートする場合、あるいは水平方向と垂直方向で異なるスケーリング能力を持つ場合があります。また、スケーリングをまったくサポートしない場合もあります。同時に、クロッピング/コンポジング矩形は整列する必要があります。ソースとシンクの両方にも任意の上界と下界のサイズ制限があります。したがって、通常通り、ドライバは要求されたパラメータを調整し、実際に選択された値を返す必要があります。アプリケーションは制約フラグを使用して四捨五入の挙動を制御できます。 制約フラグ.

1.26.3.1. ビデオキャプチャの設定¶

図を参照してください クロッピングおよびコンポジングのターゲット ビデオキャプチャデバイスで利用可能な選択ターゲットの例を参照してください。クロッピングターゲットをコンポジングターゲットの前に設定することをお勧めします。

サンプル可能な領域の左上コーナーの座標範囲、幅、高さは次のターゲットによって指定されます。 V4L2_SEL_TGT_CROP_BOUNDS ターゲット。ドライバ開発者には、左上コーナーを位置 (0, 0) に設定することをお勧めします。 (0,0)。矩形の座標はピクセルで表されます。

実際にサンプルされる領域であるソース矩形の左上コーナー、幅、高さは次のターゲットによって指定されます。 V4L2_SEL_TGT_CROP ターゲット。これは次のターゲットと同じ座標系を使用します。 V4L2_SEL_TGT_CROP_BOUNDS。アクティブなクロッピング領域はキャプチャ境界内に完全に含まれていなければなりません。ドライバはハードウェアの制限に応じて、要求されたサイズおよび/または位置をさらに調整できます。

各キャプチャデバイスは、 によって指定されるデフォルトのソース矩形を持ちます。 V4L2_SEL_TGT_CROP_DEFAULT ターゲット。この矩形はドライバライターが完全な画像と見なす範囲をカバーしなければなりません。ドライバはドライバが最初にロードされるときにアクティブなクロッピング矩形をデフォルト値に設定しなければなりませんが、それ以降は設定しないでください。

コンポジングターゲットはメモリバッファを指します。コンポジング座標の制限は次の関数を使用して取得します。 V4L2_SEL_TGT_COMPOSE_BOUNDS。すべての座標はピクセルで表されます。矩形の左上コーナーは位置 (0, 0) に配置しなければなりません。 (0,0)。幅と高さは次の関数で設定された画像サイズと一致します。 VIDIOC_S_FMT.

ハードウェアによって画像が挿入されるバッファの一部は次のターゲットによって制御されます。 V4L2_SEL_TGT_COMPOSE ターゲット。矩形の座標は、境界矩形と同じ座標系で表されます。合成矩形は境界矩形内に完全に含まれなければなりません。ドライバーは合成矩形を境界限界に合わせて調整する必要があります。さらに、ドライバーはハードウェアの制限に応じて他の調整を行うこともできます。アプリケーションは、四捨五入の挙動を制御するための 制約フラグ.

キャプチャデバイスの場合、デフォルトの合成矩形は V4L2_SEL_TGT_COMPOSE_DEFAULTで取得されます。通常、これは境界矩形と等しいです。

ハードウェアによって変更されるバッファの一部は V4L2_SEL_TGT_COMPOSE_PADDEDで定義されます。これは V4L2_SEL_TGT_COMPOSE で定義されたすべてのピクセルに加えて、挿入プロセス中にハードウェアによって変更されたすべてのパディングデータを含みます。この矩形の外側にあるすべてのピクセルは eisa_driver_registerから戻るときにEISAデバイスが検出されることを期待しないでください。なぜなら、バスがまだプローブされていない可能性が高いからです。実際には、ほとんどの場合（バスルートドライバーがブートプロセスの後半になってから動作するため）このことが起こります。残念ながら、ほとんどのドライバーは自らプローブを行い、プローブルーティンを終了するときに全体のマシンを探索していると期待しています。 ハードウェアによって変更されません。パディング領域内にあるがアクティブ領域外にあるピクセルの内容は未定義です。アプリケーションはパディング矩形とアクティブ矩形を使用して、ゴミピクセルの位置を検出し、必要に応じて削除できます。

1.26.3.2. ビデオ出力の設定¶

出力デバイスの場合、ターゲットとioctlはビデオキャプチャの場合と同様に使用されます。 合成 矩形とは、画像をビデオ信号に挿入する操作を指します。クロッピング矩形とは、メモリバッファを指します。合成ターゲットをクロッピングターゲットの設定よりも先に設定することをお勧めします。

クロッピングターゲットとは、ビデオ信号またはグラフィカルスクリーンに挿入する画像を含むメモリバッファを指します。クロッピング座標の限界は V4L2_SEL_TGT_CROP_BOUNDSで取得されます。すべての座標はピクセル単位で表されます。左上隅は常にポイント (0,0)です。幅と高さは VIDIOC_S_FMT ioctl.

で指定された画像サイズに等しいです。ソース矩形の左上隅、幅、高さ（ハードウェアが画像データを処理する領域）は V4L2_SEL_TGT_CROPで指定されます。その座標は境界矩形と同じ座標系で表されます。アクティブクロッピング領域はクロップ境界内に完全に含まれなければなりません。ドライバーはハードウェアの制限に応じて、要求されたサイズと/または位置をさらに調整する場合があります。

出力デバイスの場合、デフォルトのクロッピング矩形は V4L2_SEL_TGT_CROP_DEFAULTで取得されます。通常、これは境界矩形と等しいです。

で取得されます。ハードウェアが画像をビデオ信号またはグラフィックディスプレイに挿入する領域は V4L2_SEL_TGT_COMPOSE ターゲットによって制御されます。矩形の座標はピクセル単位で表されます。合成矩形は境界矩形内に完全に含まれなければなりません。ドライバーは領域を境界限界に合わせて調整する必要があります。さらに、ドライバーはハードウェアの制限に応じて他の調整を行うこともできます。

デバイスにはデフォルトの合成矩形があり、これはターゲットによって与えられます。 V4L2_SEL_TGT_COMPOSE_DEFAULT ターゲット。この矩形はドライバの作成者が完全な画像と見なす範囲をカバーする必要があります。ドライバ開発者には、左上隅を位置 (0,0)に設定することをお勧めします。ドライバが最初にロードされるときに、アクティブな合成矩形をデフォルトのものに設定する必要があります。

デバイスはメモリバッファからの画像以外のビデオ信号に追加のコンテンツを導入する場合があります。これは画像周辺の境界線を含みます。ただし、このようなパディングされた領域はドライバ依存の機能であり、このドキュメントではカバーしていません。ドライバ開発者には、パディングされた矩形をアクティブな矩形と等しく保つことが推奨されます。パディングされたターゲットは次の識別子でアクセスされます。 V4L2_SEL_TGT_COMPOSE_PADDED 識別子です。これはメモリバッファからのすべてのピクセルを含む必要があります。 V4L2_SEL_TGT_COMPOSE ターゲットでは存在しない。

1.26.3.3. スケーリング制御¶

アプリケーションは、矩形の幅と高さを比較することによりスケーリングが行われているかを検出できます。 V4L2_SEL_TGT_CROP および V4L2_SEL_TGT_COMPOSE ターゲットによって取得した矩形。これらの値が等しくない場合、スケーリングが適用されます。アプリケーションはこれらの値を使用してスケーリング比率を計算できます。
