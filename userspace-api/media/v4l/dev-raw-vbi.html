4.6. Raw VBI Data Interface¶

VBIはVertical Blanking Intervalの略で、アナログビデオ信号のライン列の間にあるギャップを指します。VBI期間中は画像情報が送信されず、陰極管テレビの電子ビームが画面の上部に戻る間に一時的に空きます。オシロスコープで確認すると、垂直同期パルスとASK変調された短いデータパケットが見られます 1 ビデオ信号に載せており、これはテレテキストやクローズドキャプションなどのサービスの送信です。

このインターフェースタイプの対象は、ビデオ信号からサンプリングされた生のVBIデータ、または出力用に信号に追加されるデータです。データ形式は圧縮されていないビデオ画像に似ており、ライン数 × 1ラインあたりのサンプル数をVBI画像と呼びます

従来はV4L2 VBIデバイスは、主装置番号81で、補助装置番号224〜255のキャラクタデバイス専用ファイルを通じてアクセスされていました /dev/vbi および /dev/vbi0 に（木の下から葉に向かって） /dev/vbi31 は通常、好ましいVBIデバイスへのシンボリックリンクです。この規約は入力デバイスおよび出力デバイスの両方に適用されます /dev/vbi を検索する際の問題を解決するため、VBIキャプチャおよび出力は、下記のデバイス機能として利用可能です

。これらのデバイスを使用して生のVBIデータをキャプチャまたは出力するには、アプリケーションはioctlを呼び出す必要があります /dev/video。アクセスするには、 VIDIOC_S_FMT ioctl。アクセスするには、 /dev/vbi、生のVBIキャプチャまたは出力はデフォルトのデバイス機能です

4.6.1. キャパビリティの照会¶

raw VBIキャプチャまたは出力APIをサポートするデバイスは、それぞれioctlにフラグを設定します。 V4L2_CAP_VBI_CAPTURE または V4L2_CAP_VBI_OUTPUT フラグをそれぞれioctlに設定します。 capabilities 構造体の v4l2_capability は ioctl VIDIOC_QUERYCAP ioctlで、読み書き、ストリーミング、または非同期I/Oの少なくとも1つの方法をサポートしなければなりません。VBIデバイスにはチューナーやモデュレータが含まれる場合もありますし、含まれない場合もあります。

4.6.2. 補助機能¶

VBIデバイスは ビデオ入力または出力, チューナーまたはモジュレータ, and controls 必要に応じてioctlをサポートしなければなりません。 ビデオ標準 ioctlsはVBIデバイスをプログラミングするための重要な情報を提供するため、サポートしなければなりません。

4.6.3. Raw VBIフォーマットのネゴシエーション¶

Raw VBIのサンプリング能力は、特にサンプリング周波数に変化があります。データを正しく解釈するため、V4L2はサンプリングパラメータを照会するioctlを指定しています。さらに、柔軟性を確保するため、アプリケーションは異なるパラメータを提案することもできます。

通常、これらのパラメータは ではありません 時間にリセットされます。これによりUnixツールチェーンやデバイスのプログラミングを行い、それを通常のファイルのように読み取るための許可が得られます。よく書かれたV4L2アプリケーションは、クロッピングやスケーリングを含む実際の要求を満たすことを保証します。 open() Unixツールチェーンを許可し、デバイスをプログラミングしてからプレーンファイルのように読み取るのを可能にするための時間です。よく書かれたV4L2アプリケーションは、常に要求したパラメータを実際に得ていることを確認し、適切なパラメータを要求してから実際に取得したパラメータが適切であるかを確認する必要があります。

現在のraw VBIキャプチャパラメータを照会するには、アプリケーションはこの構造体へのポインタを用いてioctlを設定します。 type フィールドを設定します。 v4l2_format に（木の下から葉に向かって） V4L2_BUF_TYPE_VBI_CAPTURE または V4L2_BUF_TYPE_VBI_OUTPUTの結果を変更し、 VIDIOC_G_FMT ioctlをポインタでこの構造体に指して呼び出します。ドライバはこの構造体を v4l2_vbi_format vbi 構造体の fmt ユニオンに記入します。

異なるパラメータを要求するには、アプリケーションは上記のように type フィールドを設定します。 v4l2_format を設定し、構造体 v4l2_vbi_format vbi 構造体の fmt ユニオンのすべてのフィールドを初期化するか、あるいはより良い方法として VIDIOC_G_FMTの結果を変更し、 VIDIOC_S_FMT ioctlを設定します。ドライバはエラーを返します。 EINVAL パラメータが曖昧な場合にのみエラー コードを返し、それ以外の場合はハードウェアの能力に応じてパラメータを調整し、実際のパラメータを返します。ドライバがこの時点でリソースを割り当てると、エラー コードを返して、返されたパラメータが有効であるが、必要なリソースが現在利用不可であることを示すことがあります。たとえば、キャプチャするビデオおよびVBI領域が重なったり、ドライバが複数のオープンをサポートしており他のプロセスがVBIキャプチャまたは出力要求を行っている場合など、このような状況が発生する可能性があります。いずれにしても、アプリケーションは他のリソース割り当てポイントが返す可能性のある EBUSY エラー コードを想定する必要があります。たとえば、ビデオおよびVBI領域が重なったり、ドライバが複数のオープンをサポートしており他のプロセスがVBIキャプチャまたは出力要求を行っている場合など、このような状況が発生する可能性があります。いずれにしても、アプリケーションは他のリソース割り当てポイントが返す可能性のある EBUSYエラー コードを想定する必要があります。たとえば、ビデオおよびVBI領域が重なったり、ドライバが複数のオープンをサポートしており他のプロセスがVBIキャプチャまたは出力要求を行っている場合など、このような状況が発生する可能性があります。いずれにしても、アプリケーションは他のリソース割り当てポイントが返す可能性のある ioctl VIDIOC_STREAMON, VIDIOC_STREAMOFF ioctl および最初の read() , write() および select() 呼び出されます。

4.6.4. VBI画像の読み書き¶

フィールド番号と同期を保ち、実装を容易にするため、1回に渡される最小のデータ単位は、メモリに直後に続く2つのVBI画像フィールドからなる1フレームです。

フレームの総サイズは以下の通り計算されます：

(count[0] + count[1]) * samples_per_line * sample size in bytes

サンプルサイズは常に1バイトである可能性が高く、アプリケーションは他のドライバーと正しく動作させるためにフィールドを確認する必要があります。 sample_format フィールドを確認することで、他のドライバーと正しく動作させることができます。
