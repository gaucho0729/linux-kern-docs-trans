1.10. 拡張コントロールAPI¶

1.10.1. はじめに¶

元の制御メカニズムはユーザー設定（明るさ、彩度など）のために設計されていましたが、その後、より複雑なドライバAPIの実装に非常に有用なモデルとして使われるようになりました。各ドライバがこの大規模なAPIの一部を実装するだけで十分なためです。

MPEGエンコーディングAPIがこの拡張制御メカニズムの設計と実装を推進しました。MPEG標準は非常に大きく、現在サポートしているハードウェアMPEGエンコーダーはそれぞれこの標準の一部を実装しています。さらに、動画をMPEGストリームにエンコードする際のパラメータはMPEGエンコーディングチップ固有であり、MPEG標準は結果となるMPEGストリームのフォーマットを定義するだけで、動画が実際にそのフォーマットにエンコードされる方法は規定していません。

残念なことに、元の制御APIはこれらの新しい用途に必要な機能が不足しており、結果として（あまりにも元々の名前が適切でなかった）拡張制御APIへと拡張されました。

MPEGエンコーディングAPIが最初に拡張制御APIを使用したにもかかわらず、現在ではカメラ制御やFM放送機制御などの他の拡張制御クラスも存在します。拡張制御APIおよびすべての拡張制御クラスについては以下のテキストで説明します。

1.10.2. 拡張制御API¶

3つの新しいioctlが利用可能です： VIDIOC_G_EXT_CTRLS, VIDIOC_S_EXT_CTRLS および VIDIOC_TRY_EXT_CTRLS. これらのioctlは制御配列を処理します（対照的に、 VIDIOC_G_CTRL および VIDIOC_S_CTRL は単一の制御を処理します）。これは、複数の制御を一度に原子的に変更する必要があるためです。

新しいioctlのそれぞれは、 v4l2_ext_controls構造体へのポインタを期待します。この構造体には制御配列へのポインタ、その配列内の制御数、および制御クラスが含まれます。制御クラスは、類似した制御を単一のクラスにグループ化するために使われます。たとえば、制御クラス V4L2_CTRL_CLASS_USER はすべてのユーザー制御（つまり、旧 VIDIOC_S_CTRL ioctlで設定可能なすべての制御）を含みます。制御クラス V4L2_CTRL_CLASS_MPEG はすべてのMPEGエンコーディングに関連する制御などを含みます。

制御配列内のすべての制御は指定された制御クラスに属する必要があります。これが満たされない場合、エラーが返されます。

空の制御配列（count == 0）を使って指定された制御クラスがサポートされているかを確認することも可能です。

制御配列は v4l2_ext_control 構造体配列です。構造体 v4l2_ext_control は構造体 v4l2_controlと非常に似ていますが、64ビット値やポインタを渡すことができる点が異なります。

構造体 v4l2_ext_control ポインタをサポートしており、現在はN次元配列や構造体などの複合型を持つ制御を実装することが可能になりました。このような複合型の制御を使用するには、 V4L2_CTRL_FLAG_NEXT_COMPOUND 制御を列挙する際、実際にこのような複合型の制御を表示するためには指定が必要です。言い換えれば、これらの複合型の制御はプログラム的にしか使用すべきではありません。

このような複合型の制御は、ioctlが追加されることで、それまでには得られなかったより多くの情報を提供することが可能となりました。特に、このioctlは、この制御が複数の要素を持つ場合、N次元配列の次元数を返します。 VIDIOC_QUERYCTRL 、そして VIDIOC_QUERY_EXT_CTRL 制御の柔軟性により、設定しようとしている制御がドライバでサポートされているか、また有効な値の範囲を確認する必要があります。そのため、

  2. のメニューインデックスの一部がサポートされていない可能性があります（ V4L2_CTRL_TYPE_MENU はエラーを返します）。サポートされているMPEG音声ビットレートの一覧は良い例です。一部のドライバは1つまたは2つのビットレートのみをサポートし、他のドライバは幅広い範囲をサポートしています。VIDIOC_QUERYMENU 拡張制御の列挙

1.10.3. 拡張制御を列挙する推奨方法は、¶

と組み合わせて ioctls VIDIOC_QUERYCTRL、VIDIOC_QUERY_EXT_CTRL および VIDIOC_QUERYMENU を使用することです。 V4L2_CTRL_FLAG_NEXT_CTRL flag:

struct v4l2_queryctrl qctrl;

qctrl.id = V4L2_CTRL_FLAG_NEXT_CTRL;
while (0 == ioctl (fd, VIDIOC_QUERYCTRL, &qctrl)) {
    /* ... */
    qctrl.id |= V4L2_CTRL_FLAG_NEXT_CTRL;
}

初期の制御IDは0と V4L2_CTRL_FLAG_NEXT_CTRL フラグとは関係ありません。 VIDIOC_QUERYCTRL ioctlは指定されたIDよりも大きい制御を返します。そのような制御が見つからない場合はエラーが返されます。

特定の制御クラス内のすべての制御を取得したい場合は、初期の qctrl.id 値を制御クラスに設定し、別のチェックを追加して、別の制御クラスの制御が見つかったときにループを終了するようにします：

qctrl.id = V4L2_CTRL_CLASS_MPEG | V4L2_CTRL_FLAG_NEXT_CTRL;
while (0 == ioctl(fd, VIDIOC_QUERYCTRL, &qctrl)) {
    if (V4L2_CTRL_ID2CLASS(qctrl.id) != V4L2_CTRL_CLASS_MPEG)
        break;
    /* ... */
    qctrl.id |= V4L2_CTRL_FLAG_NEXT_CTRL;
}

32ビットの qctrl.id 値は3つのビット範囲に分かれています：上位4ビットはフラグ（例： V4L2_CTRL_FLAG_NEXT_CTRL）で使用され、実際のIDには含まれません。残りの28ビットが制御IDを構成し、そのうち上位12ビットが制御クラスを、下位16ビットが制御クラス内の制御を示します。これらの下位16ビットは常にゼロでないことが保証されています。0x1000以上はドライバ固有の制御に予約されています。マクロ V4L2_CTRL_ID2CLASS(id) は制御IDから制御クラスIDを返します。

ドライバが拡張制御をサポートしていない場合、 VIDIOC_QUERYCTRL は V4L2_CTRL_FLAG_NEXT_CTRLと組み合わせて使用すると失敗します。その場合、古い方法で制御を列挙する必要があります（ 例: 全てのコントロールを一覧表示するを参照）。サポートされている場合は、すべての制御を含むドライバ固有の制御も列挙されます。

1.10.4. 制御パネルの作成¶

グラフィカルなユーザーインターフェースでユーザーがさまざまなコントロールを選択できるコントロールパネルを作成することが可能です。基本的に、上記の方法を使用してすべてのコントロールを反復処理する必要があります。各コントロールクラスは、型のコントロールで開始します V4L2_CTRL_TYPE_CTRL_CLASS. VIDIOC_QUERYCTRL このコントロールクラスの名前を返します。これはコントロールパネル内のタブページのタイトルとして使用できます。

structのflagsフィールド v4l2_queryctrl コントロールの動作に関するヒントも含まれています。詳しくは ioctls VIDIOC_QUERYCTRL、VIDIOC_QUERY_EXT_CTRL および VIDIOC_QUERYMENU ドキュメンテーションをご確認ください。
