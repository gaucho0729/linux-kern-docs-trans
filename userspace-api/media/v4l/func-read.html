7.68. V4L2 read()¶

7.68.1. 名前¶

v4l2-read - V4L2デバイスからデータを読み込む

7.68.2. 概要¶

#include <unistd.h>
ssize_t 読み取り(int fd, void *buf, size_t コピーする文字数)¶

7.68.3. 引数¶

fd

返されるファイル記述子 open().

buf

埋めるバッファ

count

読み込むバイト数の最大値

7.68.4. 説明¶

read() 最大で読み込む試みを行う count ファイルディスクリプタからバイトを読み込む fd バッファの開始位置から bufバッファ内のデータのレイアウトについては、関連するデバイスインターフェースセクションで説明されています。詳しくは##を参照してください。もし count がゼロであれば、 read() ゼロを返し、他の結果は持ちません。もし count はより大きい SSIZE_MAX、結果は未定義です。どの場合でも count 値をそれぞれ read() 呼び出しは、最大で1フレーム（2フィールド分）のデータを提供します。

デフォルトでは read() データが利用可能になるまでブロックします。データが利用可能になるまで O_NONBLOCK 関数に与えられた場合、 open() 関数は、データが利用可能でない場合、すぐにエラー コードを返します。 EAGAIN エラー コードを返します。関数は常に select() または poll() 関数は常に実行を一時停止してデータが利用可能になるまで待機できます。すべてのサポートするドライバーは read() 関数もサポートする必要があります。 select() および poll().

ドライバーは、単一または複数のバッファを使用して読み込み機能を実装し、内部バッファが満たされたときに最も古いまたは最も新しいフレームを破棄することで、読み込み機能をさまざまな方法で実装できます。

read() バッファが満たされている間の「スナップショット」を返しません。単一のバッファを使用する場合、アプリケーションがバッファを読み始めるまでドライバーはキャプチャを停止します。これにより、垂直ブランク期間のみが読み込みに利用可能となり、またはキャプチャレートがビデオ標準の名義フレームレートを下回る必要があります。

の挙動は read() アクティブなピクチャーペリオドまたは上部と下部フィールドを分離する垂直ブランク中に呼び出された場合、破棄ポリシーに依存します。最も古いフレームを破棄するドライバーは、内部バッファに継続的にキャプチャを行い、以前に読み取らなかったフレームを上書きし、呼び出し時の受信フレームを返します。 read() 完了した時点ですぐに返します。

最も新しいフレームを破棄するドライバーは、次の呼び出しが行われるまでキャプチャを停止します。 read() 呼び出し。受信中のフレームは read() 時間に破棄され、次のフレームを返します。これにより、キャプチャレートが名義フレームレートの半分またはそれ以下になることが再び示されます。このモデルの例は、bttvドライバーのビデオ読み込みモードで、DMAがユーザー メモリに送信されるときに呼び出されます。 read() 呼び出され、DMAが完了したときに戻ります。

複数バッファモデルでは、ドライバーは内部バッファのリングを維持し、次の空きバッファに自動的に進みます。これにより、アプリケーションがバッファを十分に速く空にできる場合、連続的なキャプチャが可能になります。また、ドライバーが空きバッファがなくなるまで待機する場合の挙動も破棄ポリシーに依存します。

アプリケーションは、ドライバーが内部で使用するバッファ数を取得および設定できます。 VIDIOC_G_PARM および VIDIOC_S_PARM ioctlを介して。ただし、これはオプションです。破棄ポリシーは報告されず、変更できません。最小要件については インターフェース.

7.68.5. 戻り値¶

成功した場合、読み取ったバイト数が返されます。この数値が要求されたバイト数よりも小さかったり、1フレーム分のデータ量よりも小さかったとしてもエラーではありません。これは例えば、 read() シグナルによって中断された場合など、このような状況が発生する可能性があります。エラーの場合、-1が返され、 errno 変数が適切に設定されます。このような場合、次の読み取りは新しいフレームの開始位置から開始されます。可能なエラーコードは次の通りです:

EAGAIN

ノンブロッキングI/OがO_NONBLOCKを使用して選択され、即時に読み取れるデータがありませんでした。

EBADF

fd 有効なファイル記述子ではありません、または読み取り用に開いていません、またはプロセスが最大のファイル数を開いている場合です。

EBUSY

ドライバーが複数の読み取りストリームをサポートしておらず、デバイスがすでに使用中です。

EFAULT

buf 参照しているメモリ領域がアクセスできません。

EINTR

データが読み取られる前にシグナルによって呼び出しが中断されました。

EIO

I/Oエラー。これはハードウェアの問題や、リモートデバイス（USBカメラなど）との通信失敗を示します。

EINVAL

以下の read() このドライバーではサポートされていません、このデバイスではサポートされていません、または一般的にこの種のデバイスではサポートされていません。
