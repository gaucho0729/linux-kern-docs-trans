3.6. バッファ¶

バッファは、アプリケーションとドライバがストリーミングI/Oメソッドのいずれかを使用してやり取りするデータを保持します。マルチプレーンAPIでは、データはプレーン（画像のチャンネル）として保持され、バッファ構造体はこれらのプレーンを含むコンテナとして機能します。バッファ（プレーン）へのポインタのみがやり取りされ、データ自体はコピーされません。これらのポインタは、タイムスタンプやフィールドパリティなどのメタ情報とともにstructに格納されます v4l2_buffer、ioctl VIDIOC_QUERYBUFの引数として ioctl. マルチプレーンAPIでは、structの一部のプレーン固有メンバが, VIDIOC_QBUF および VIDIOC_DQBUF structの一部のプレーン固有メンバが v4l2_buffer各プレーンのポインタとサイズなどは、structに格納されます v4l2_plane その代わりに、structは各プレーン構造体の配列を保持しています v4l2_buffer 配列を含みます

デキューされたビデオバッファにはタイムスタンプが付与されます。ドライバーがタイムスタンプを取得するフレームのどの部分で、どのクロックを使用するかを決定します。マスクのフラグをご参照ください V4L2_BUF_FLAG_TIMESTAMP_MASK および V4L2_BUF_FLAG_TSTAMP_SRC_MASK の バッファ フラグこれらのフラグは、ビデオストリーム全体の間、すべてのバッファにおいて常に有効で一定です。これらのフラグの変更は、副作用として発生する可能性があります VIDIOC_S_INPUT または VIDIOC_S_OUTPUT しかし。The V4L2_BUF_FLAG_TIMESTAMP_COPY ただし、メモリ間デバイスなどで使用されるタイムスタンプ型はこのルールの例外です。タイムスタンプソースフラグは、OUTPUTビデオバッファからCAPTUREビデオバッファへコピーされます。

3.6.1. フォーマット、コントロール、バッファ間の相互作用¶

V4L2はバッファのサイズやバッファ内データのレイアウト方法に影響を与えるパラメータを公開しています。これらのパラメータはフォーマットとコントロールの両方を通じて公開されます。一つの例は、 V4L2_CID_ROTATE ピクセルがバッファ内でどのように保存される方向を変更し、選択されたフォーマットに末尾のパディングが含まれる場合のバッファサイズを制御するコントロールの一例です。

バッファの内容を解釈するために必要な情報（例えば、ピクセルフォーマット、ラインストライド、タイリング方向、または回転）は、このセクションの後半で「バッファレイアウト」として一括して呼ばれます。

バッファレイアウトを変更できるコントロールは、 V4L2_CTRL_FLAG_MODIFY_LAYOUT フラグを設定します。

フォーマットの変更またはバッファサイズやレイアウトに影響を与えるコントロールを行うには、ストリームを停止する必要があります。ストリームがアクティブな状態でこのような変更を試行すると、ioctlがフォーマットまたはコントロールを設定する際、エラーコードを返す必要があります。 EBUSY その場合、ドライバはさらに V4L2_CTRL_FLAG_GRABBED フラグを設定する必要があります。ストリームがアクティブな状態でそのコントロールを呼び出す際には、 VIDIOC_QUERYCTRL() または VIDIOC_QUERY_EXT_CTRL() ioctlが呼び出す際には、

注意

以下の VIDIOC_S_SELECTION() ハードウェアに応じて（例えばデバイスにスケーラーが含まれていない場合など）、選択矩形に加えてフォーマットを変更することがあります。同様に、 VIDIOC_S_INPUT(), VIDIOC_S_OUTPUT(), VIDIOC_S_STD() および VIDIOC_S_DV_TIMINGS() ioctlsは、フォーマットおよび選択矩形の形式も変更可能です。これらのioctlsがバッファサイズやレイアウトの変更を引き起こす場合、ドライバはこの節で説明するすべての場合において、同様に処理する必要があります。 VIDIOC_S_FMT() ioctl

バッファレイアウトにのみ影響を与えるコントロールは、ストリームが停止している間いつでも変更可能です。これらはバッファサイズに影響を与えないため、バッファ割当と同期させるための特別な処理は必要ありません。ストリームが停止した後、フラグはクリアされます。 V4L2_CTRL_FLAG_GRABBED flag

バッファサイズに影響を与えるフォーマットおよびコントロールはバッファ割当と相互作用します。これを扱う最も簡単な方法は、ドライバが常にこれらのフォーマットまたはコントロールを変更する際にはバッファを再割当する必要があることです。 VIDIOC_STREAMOFF() その場合、このような変更を行うには、ストリームが実行中であればまずvideo streamを停止するための VIDIOC_REQBUFS() ioctlを使用し、バッファをすべて解放するための V4L2_CTRL_FLAG_GRABBED ioctlを使用します。すべてのバッファを解放した後、コントロール用のフラグがクリアされます。その後、フォーマットまたはコントロールを変更し、バッファを再割当してストリームを再開する必要があります。典型的なioctlシーケンスは

  1. VIDIOC_STREAMOFF

  2. VIDIOC_REQBUFS(0)

  3. VIDIOC_S_EXT_CTRLS

  4. VIDIOC_S_FMT

  5. VIDIOC_REQBUFS(n)

  6. VIDIOC_QBUF

  7. VIDIOC_STREAMON

第二の呼び出しでは VIDIOC_REQBUFS() 新しいフォーマットと制御値を考慮してバッファサイズを計算します。アプリケーションは必要に応じて、ioctlを呼び出してサイズを取得することもできます。 VIDIOC_G_FMT() ioctlを呼び出すことができます。

注意

APIは制御（3.）とフォーマット（4.）の変更順序を強制しません。デバイスや使用ケースによって、フォーマットと制御の設定順序が異なり、場合によっては交互に設定されることもあります。たとえば、ある制御が異なるピクセルフォーマットで異なる動作をする場合、その場合はまずフォーマットを設定する必要があります。

バッファ再割当が必要な場合、バッファが割当てられている間、バッファサイズに影響を与えるフォーマットまたは制御を変更する試みは、フォーマットまたは制御設定のioctlがエラーを返す原因になります。 EBUSY エラーを返します。 VIDIOC_QBUF() ioctlがエラーを返します。 EINVAL エラーを返します。

バッファ再割当はコストのかかる操作です。そのコストを回避するため、ドライバは（推奨される）フォーマットまたは制御を変更してバッファが割当てられている状態でも許可できます。その場合、フォーマットと制御を変更するための典型的なioctlシーケンスは

  1. VIDIOC_STREAMOFF

  2. VIDIOC_S_EXT_CTRLS

  3. VIDIOC_S_FMT

  4. VIDIOC_QBUF

  5. VIDIOC_STREAMON

このシーケンスが正しく動作するには、キューイングされたバッファが新しいフォーマットまたは制御に十分なサイズである必要があります。ドライバは、フォーマット変更（ ENOSPC error in response to format change (VIDIOC_S_FMT()) or control changes (VIDIOC_S_CTRL() または VIDIOC_S_EXT_CTRLS()) if buffers too small for the new format are currently queued. As a simplification, drivers are allowed to return a EBUSY error from these ioctls if any buffer is currently queued, without checking the queued buffers sizes.

Additionally, drivers shall return a EINVAL error from the VIDIOC_QBUF() ioctl if the buffer being queued is too small for the current format or controls. Together, these requirements ensure that queued buffers will always be large enough for the configured format and controls.

Userspace applications can query the buffer size required for a given format and controls by first setting the desired control values and then trying the desired format. The VIDIOC_TRY_FMT() ioctl will return the required buffer size.

  1. VIDIOC_S_EXT_CTRLS(x)

  2. VIDIOC_TRY_FMT()

  3. VIDIOC_S_EXT_CTRLS(y)

  4. VIDIOC_TRY_FMT()

以下の VIDIOC_CREATE_BUFS() ioctl can then be used to allocate buffers based on the queried sizes (for instance by allocating a set of buffers large enough for all the desired formats and controls, or by allocating separate set of appropriately sized buffers for each use case).
