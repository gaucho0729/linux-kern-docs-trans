1.9. ユーザー制御¶

デバイスは通常、明るさ、彩度など、ユーザーが設定可能な制御項目を持ち、これらはグラフィカルユーザーインターフェースでユーザーに提示されます。ただし、異なるデバイスは提供可能な制御項目が異なり、また可能な値の範囲やデフォルト値もデバイスによって異なります。制御ioctlは、これらの制御項目に関する情報を提供し、どのデバイスとも正しく動作するユーザーインターフェースを作成するメカニズムを提供します。

すべての制御はID値を使用してアクセスされます。V4L2は特定の目的にいくつかのIDを定義しています。ドライバーは、さらに独自のカスタム制御を実装することも可能です。 V4L2_CID_PRIVATE_BASE 1 およびより高い値を使用します。事前に定義された制御IDは、 V4L2_CID_というプレフィックスを持ち、 制御IDでリストされています。IDは制御の属性を照会する際や、現在の値を取得または設定する際に使用されます。

アプリケーションは制御の目的についての仮定をせずにユーザーに表示すべきです。各制御にはユーザーが理解できる名前文字列が付与されます。目的が非直感的である場合、ドライバー開発者はユーザーマニュアル、ユーザーインターフェースプラグイン、またはドライバースペシフィックパネルアプリケーションを提供すべきです。事前に定義されたIDは、プログラム的にいくつかの制御を変更するために導入されました。例えば、チャンネルスイッチ中にデバイスをミュートするなどです。

ドライバーは、現在のビデオ入力または出力、チューナーまたはモジュレータ、オーディオ入力または出力の切り替え後に異なる制御を列挙できます。異なるとは、他の境界値、別のデフォルト値および現在値、ステップサイズ、または他のメニュー項目を意味します。特定の カスタム IDを持つ制御も名前やタイプを変更できます。

デバイスの現在の設定に該当しない制御（例えば、現在のビデオ入力には適用されない）の場合、ドライバーは V4L2_CTRL_FLAG_INACTIVE フラグを設定します。

制御値はグローバルに保存され、切り替え時に変化しません（報告された範囲内に留まる場合を除く）。また、デバイスが開かれる/閉じられるとき、チューナーのラジオ周波数が変更されるとき、または一般的にアプリケーションの要求がない限り変化しません。

V4L2は制御値が変化したときにアプリケーションを通知するイベントメカニズムを指定しています（参照： ioctl VIDIOC_SUBSCRIBE_EVENT, VIDIOC_UNSUBSCRIBE_EVENT, イベント V4L2_EVENT_CTRL）

すべての制御はマシンのエンディアンネスを使用します。

1.9.2. 例: 全てのコントロールを一覧表示する¶

struct v4l2_queryctrl queryctrl;
struct v4l2_querymenu querymenu;

static void enumerate_menu(__u32 id)
{
    printf("  Menu items:\\n");

    memset(&querymenu, 0, sizeof(querymenu));
    querymenu.id = id;

    for (querymenu.index = queryctrl.minimum;
         querymenu.index <= queryctrl.maximum;
         querymenu.index++) {
        if (0 == ioctl(fd, VIDIOC_QUERYMENU, &querymenu)) {
            printf("  %s\\n", querymenu.name);
        }
    }
}

memset(&queryctrl, 0, sizeof(queryctrl));

queryctrl.id = V4L2_CTRL_FLAG_NEXT_CTRL;
while (0 == ioctl(fd, VIDIOC_QUERYCTRL, &queryctrl)) {
    if (!(queryctrl.flags & V4L2_CTRL_FLAG_DISABLED)) {
        printf("Control %s\\n", queryctrl.name);

        if (queryctrl.type == V4L2_CTRL_TYPE_MENU)
            enumerate_menu(queryctrl.id);
    }

    queryctrl.id |= V4L2_CTRL_FLAG_NEXT_CTRL;
}
if (errno != EINVAL) {
    perror("VIDIOC_QUERYCTRL");
    exit(EXIT_FAILURE);
}

memset(&queryctrl, 0, sizeof(queryctrl));

        printf("V4L2_CID_BRIGHTNESS is not supportedn");

} else if (queryctrl.flags & V4L2_CTRL_FLAG_DISABLED) {
    printf("V4L2_CID_BRIGHTNESS is not supportedn");

    control.id = V4L2_CID_BRIGHTNESS;
    control.value = queryctrl.default_value;

    if (-1 == ioctl(fd, VIDIOC_S_CTRL, &control)) {

memset(&control, 0, sizeof(control));
control.id = V4L2_CID_CONTRAST;

if (0 == ioctl(fd, VIDIOC_G_CTRL, &control)) {
    control.value += 1;

    /* The driver may clamp the value or return ERANGE, ignored here */

The use of V4L2_CID_PRIVATE_BASE は問題です。異なるドライバーが同じ V4L2_CID_PRIVATE_BASE IDで異なるコントロールを表す。これにより、そのIDを持つコントロールの意味がドライバー依存であるため、このようなコントロールをプログラムで設定するのが困難になります。この問題を解決するためにドライバーは一意のIDを使用し、 V4L2_CID_PRIVATE_BASE IDはカーネルによってこれらの一意なIDにマッピングされます。これらを V4L2_CID_PRIVATE_BASE 実際のIDへのエイリアスとしてこれらのIDを考慮してください。

多くのアプリケーションは今日でもまだ V4L2_CID_PRIVATE_BASE IDを使用するのではなく ioctls VIDIOC_QUERYCTRL、VIDIOC_QUERY_EXT_CTRL および VIDIOC_QUERYMENU これは、そのコア内のすべての論理CPU（SMTスレッド）が V4L2_CTRL_FLAG_NEXT_CTRL すべてのIDを列挙するフラグを使用するため、サポートは V4L2_CID_PRIVATE_BASE まだ存在しています。
