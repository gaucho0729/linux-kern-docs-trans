7.7. ioctl VIDIOC_DECODER_CMD, VIDIOC_TRY_DECODER_CMD¶

7.7.1. 名前¶

VIDIOC_DECODER_CMD - VIDIOC_TRY_DECODER_CMD - デコーダー コマンドを実行する

7.7.2. 概要¶

VIDIOC_DECODER_CMD¶

int ioctl(int fd, VIDIOC_DECODER_CMD, struct v4l2_decoder_cmd *argp)

VIDIOC_TRY_DECODER_CMD¶

int ioctl(int fd, VIDIOC_TRY_DECODER_CMD, struct v4l2_decoder_cmd *argp)

7.7.3. 引数¶

fd

返されるファイル記述子 open().

argp

構造体へのポインタ v4l2_decoder_cmd.

7.7.4. 説明¶

これらの ioctl は、オーディオ/ビデオ（通常は MPEG-）デコーダーを制御します。 VIDIOC_DECODER_CMD デコーダーにコマンドを送信します。 VIDIOC_TRY_DECODER_CMD 実際に実行せずにコマンドを試すことができます。コマンドを送信するには、アプリケーションはこの構造体のすべてのフィールドを初期化する必要があります。 v4l2_decoder_cmd を埋めます VIDIOC_DECODER_CMD または VIDIOC_TRY_DECODER_CMD この構造体へのポインタを指定する必要があります。

以下の cmd フィールドにはコマンドコードを含める必要があります。一部のコマンドでは、 flags フィールドで追加の情報を使用します。

A write() または ioctl VIDIOC_STREAMON, VIDIOC_STREAMOFF デコーダーがまだ起動していない場合、暗黙の START コマンドを送信します。これは mem2mem デコーダーの両方のキューにも適用されます。

A close() または VIDIOC_STREAMOFF ストリーミングファイル記述子の呼び出しは、デコーダーに暗黙の即時 STOP コマンドを送信し、すべてのバッファデータを破棄します。これは mem2mem デコーダーの両方のキューにも適用されます。

原則として、これらの ioctl はオプションであり、すべてのドライバーがサポートするとは限りません。Linux 3.3 で導入されました。ただし、stateful mem2mem デコーダーでは必須です（詳しくは以下のドキュメントを参照してください）。 メモリ間ステートフルビデオデコーダーインターフェース).

Decoder Commands¶

V4L2_DEC_CMD_START

0

デコーダーを起動します。デコーダーがすでに動作中または一時停止している場合、このコマンドは再生速度を変更するだけです。つまり、 V4L2_DEC_CMD_START デコーダーが一時停止していた場合、 ではありません デコーダーを再開します。これを実行するには、明示的に V4L2_DEC_CMD_RESUME 呼び出す必要があります。このコマンドには1つのフラグがあります： V4L2_DEC_CMD_START_MUTE_AUDIO設定されている場合、非標準速度で再生する際、オーディオがミュートされます。

デバイスが以下を実装している場合、 メモリ間ステートフルビデオデコーダーインターフェースドレインシーケンスが以下コマンドで開始された場合、 V4L2_DEC_CMD_STOP コマンドを実行する前に、ドレインシーケンスを完了させる必要があります。ドレインシーケンスが進行中である場合にコマンドを実行しようとすると、エラー コードが発生します。このコマンドは、デコーダーが自身で明示的に停止を開始した場合にも、デコーダーを再起動するために使用できます。 EBUSY エラー コード。デコーダーが自身で明示的に停止を開始した場合、デコーダーを再起動するためにこのコマンドを使用することもできます。 V4L2_DEC_CMD_STOP 明示的に呼び出されます。参照してください メモリ間ステートフルビデオデコーダーインターフェース 詳細についてはこちら。

V4L2_DEC_CMD_STOP

1

デコーダーを停止します。デコーダーがすでに停止している場合、このコマンドは何もしません。このコマンドには2つのフラグがあります：flagが設定されている場合、デコーダーが停止した後、画像を黒に設定します。それ以外の場合、最後の画像が繰り返されます。flagが設定されている場合、デコーダーは即座に停止します（値を無視して）、それ以外の場合、デコーディングを続け、timestamp >= pts または内部バッファから待機中のデータがすべてデコードされるまで続きます。 V4L2_DEC_CMD_STOP_TO_BLACK それ以外の場合、デコーディングを続け、timestamp >= pts または内部バッファから待機中のデータがすべてデコードされるまで続きます。 V4L2_DEC_CMD_STOP_IMMEDIATELY それ以外の場合、デコーディングを続け、timestamp >= pts または内部バッファから待機中のデータがすべてデコードされるまで続きます。 pts それ以外の場合、デコーディングを続け、timestamp >= pts または内部バッファから待機中のデータがすべてデコードされるまで続きます。

デバイスが以下を実装している場合、 メモリ間ステートフルビデオデコーダーインターフェースこのコマンドは、ドキュメントに記載されているようにドレインシーケンスを開始します。 メモリ間ステートフルビデオデコーダーインターフェースこの場合、フラグや他の引数は受け付けられません。シーケンスが完了するまでコマンドを再度呼び出すと、エラーが発生します。 EBUSY エラー コードに設定します。

V4L2_DEC_CMD_PAUSE

2

デコーダーを一時停止します。デコーダーがまだ起動していない場合、ドライバーはエラー コードを返します。 EPERM デコーダーがすでに一時停止している場合は、このコマンドは何もしません。このコマンドには1つのフラグがあり、フラグが設定されている場合、一時停止状態でデコーダーの出力が黒に設定されます。 V4L2_DEC_CMD_PAUSE_TO_BLACK フラグが設定されている場合、一時停止状態でデコーダーの出力が黒に設定されます。

V4L2_DEC_CMD_RESUME

3

PAUSE コマンド後にデコードを再開します。デコーダーがまだ起動していない場合、ドライバーはエラー コードを返します。 EPERM デコーダーがすでに動作している場合は、このコマンドは何もしません。このコマンドにはフラグは定義されていません。

V4L2_DEC_CMD_FLUSH

4

保持されているキャプチャ バッファをすべてフラッシュします。これはステートレス デコーダーでのみ有効です。アプリケーションがストリームの終わりに到達し、最後の出力バッファがフラグを設定した場合にこのコマンドが通常使用されます。 V4L2_BUF_FLAG_M2M_HOLD_CAPTURE_BUF このフラグが設定されているため、最後にデコードされたフレームを含むキャプチャ バッファのデキューイングが防がれます。そのため、このコマンドは最後のデコードフレームを明示的にフラッシュするために使用できます。保持されているキャプチャ バッファがない場合、このコマンドは何もしません。

7.7.5. 戻り値¶

成功した場合、0 が返されます。エラーの場合、-1 が返され、変数が適切に設定されます。 errno 一般的なエラーコードは、 汎用エラーコード 章。

EBUSY

デバイスが実装するドレインシーケンスは メモリ間ステートフルビデオデコーダーインターフェース まだ進行中です。シーケンスが完了するまで、他のデコーダー コマンドを実行することはできません。

EINVAL
