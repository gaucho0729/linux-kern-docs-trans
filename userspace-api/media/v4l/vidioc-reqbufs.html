7.52. ioctl VIDIOC_REQBUFS¶

7.52.1. 名前¶

VIDIOC_REQBUFS - メモリマッピング、ユーザポインタI/O、DMAバッファI/Oを開始

7.52.2. 概要¶

VIDIOC_REQBUFS¶

int ioctl(int fd, VIDIOC_REQBUFS, struct v4l2_requestbuffers *argp)

7.52.3. 引数¶

fd

返されるファイル記述子 open().

argp

struct mem_ctl_info v4l2_requestbuffers.

7.52.4. 説明¶

このioctlは、 メモリマップ, ユーザーポインタ または DMABUF に基づいたI/Oを開始するために使用されます。メモリマッピングされたバッファはデバイスメモリに配置され、アプリケーションのアドレス空間にマッピングされる前にこのioctlで割り当てられなければなりません。ユーザバッファはアプリケーション自身が割り当て、このioctlはドライバをユーザポインタI/Oモードに切り替えるためのものであり、内部構造の設定も行います。同様に、DMABUFバッファはアプリケーションがデバイスドライバを通じて割り当て、このioctlはドライバをDMABUF I/Oモードに切り替えるだけです。直接的な割り当ては行いません。

デバイスバッファを割当てるには、アプリケーションはstructのすべてのフィールドを初期化します。 v4l2_requestbuffers structure. They set the type フィールドにそれぞれのストリームまたはバッファタイプを設定し、 count フィールドに希望するバッファ数を設定し、 memory は要求されたI/Oメソッドに設定し、 reserved 配列はゼロに初期化する必要があります。この構造体へのポインタでioctlを呼び出すと、ドライバは要求されたバッファ数を割り当てようとし、実際に割り当てられた数は count フィールドに格納されます。ドライバが空きメモリが不足した場合、この数は要求数より小さく、場合によってはゼロになることがあります。一方で、ドライバが正しく動作するためにより多くのバッファが必要な場合、この数はより大きい値になることもあります。たとえば、ビデオ出力は少なくとも2つのバッファを必要とし、1つは表示中で、もう1つはアプリケーションが埋め込む必要があります。

I/Oメソッドがサポートされていない場合、ioctlは EINVAL エラー コードに設定します。

アプリケーションは、 ioctl VIDIOC_REQBUFS を返して、バッファ数を変更するために再度呼び出されます。注意点として、DMABUF経由でバッファがまだマッピングされているか、エクスポートされている場合、 ioctl VIDIOC_REQBUFS は V4L2_BUF_CAP_SUPPORTS_ORPHANED_BUFS キャパビリティが設定されている場合にのみ成功します。そうでない場合、 ioctl VIDIOC_REQBUFS は EBUSY エラーコードを返します。もし V4L2_BUF_CAP_SUPPORTS_ORPHANED_BUFS が設定されている場合、これらのバッファはorphans（孤児）となり、マッピングが解除されるか、エクスポートされたDMABUF fdsが閉じるときに解放されます。値がゼロの場合は、すべてのバッファが解放またはorphansされ、進行中のDMAを中止または終了した後、明示的な count が行われます。 VIDIOC_STREAMOFF.

type v4l2_requestbuffers¶
struct v4l2_requestbuffers¶

__u32

count

要求または割り当てられたバッファ数

__u32

type

ストリームまたはバッファのタイプ、これは構造体 v4l2_format type のフィールドと同じです。詳しくは v4l2_buf_type を参照してください。

__u32

memory

アプリケーションがこのフィールドを V4L2_MEMORY_MMAP, V4L2_MEMORY_DMABUF または V4L2_MEMORY_USERPTRのみ v4l2_memory.

__u32

capabilities

ドライバによって設定されます。0の場合、ドライバがキャパビリティをサポートしていないことを意味します。その場合、わかっているのはドライバが確実にサポートしている V4L2_MEMORY_MMAP および 可能性がある 他の v4l2_memory タイプ。これ以外のキャパビリティはサポートしません。

キャパビリティを最小限の副作用で照会したい場合は、このioctlを count を0に設定し、 memory 設定に設定する V4L2_MEMORY_MMAP および type をバッファタイプに設定して呼び出すことができます。これにより、以前に割り当てられたバッファはすべて解放されるため、これは通常アプリケーションの開始時に実行されます。

__u32

reserved[1]

今後の拡張用のプレースホルダーです。ドライバーやアプリケーションは、配列をゼロに設定しなければなりません
V4L2 バッファキャパビリティフラグ¶

V4L2_BUF_CAP_SUPPORTS_MMAP

0x00000001

このバッファタイプは V4L2_MEMORY_MMAP ストリーミングモードをサポートしています。

V4L2_BUF_CAP_SUPPORTS_USERPTR

0x00000002

このバッファタイプは V4L2_MEMORY_USERPTR ストリーミングモードをサポートしています。

V4L2_BUF_CAP_SUPPORTS_DMABUF

0x00000004

このバッファタイプは V4L2_MEMORY_DMABUF ストリーミングモードをサポートしています。

V4L2_BUF_CAP_SUPPORTS_REQUESTS

0x00000008

このバッファタイプは リクエスト.

V4L2_BUF_CAP_SUPPORTS_ORPHANED_BUFS

0x00000010

をサポートしています。カーネルは ioctl VIDIOC_REQBUFS バッファがまだDMABUF経由でマップされているか、エクスポートされている間は、これらの孤立したバッファはマップ解除されるか、エクスポートされたDMABUF fdsが閉じられるときに解放されます。

V4L2_BUF_CAP_SUPPORTS_M2M_HOLD_CAPTURE_BUF

0x00000020

ステートレスデコーダー専用の有効範囲です。設定されている場合、ユーザー空間はキャプチャバッファの返却をOUTPUTタイムスタンプの変化まで待機させるフラグを設定できます。 V4L2_BUF_FLAG_M2M_HOLD_CAPTURE_BUF flagを設定することで、キャプチャバッファの返却をOUTPUTタイムスタンプが変化するまで待機させることができます。

V4L2_BUF_CAP_SUPPORTS_MMAP_CACHE_HINTS

0x00000040

この機能はドライバが設定し、キューがキャッシュおよびメモリ管理ヒントをサポートすることを示します。ただし、キューがストリーミングI/Oに使用される場合にのみ有効です。 メモリマッピング 参照 V4L2_BUF_FLAG_NO_CACHE_INVALIDATE および V4L2_BUF_FLAG_NO_CACHE_CLEAN.

7.52.5. 戻り値¶

成功した場合、0 が返されます。エラーの場合、-1 が返され、変数が適切に設定されます。 errno 一般的なエラーコードは、 汎用エラーコード 章。

EINVAL

バッファータイプ（type フィールド) または要求されたI/Oメソッド (memory) はサポートされていません。
