4.9. ioctlはサポートされる周波数範囲を報告します。¶

ラジオデータシステム（RDS）は、ラジオ番組の聴こえない音声サブキャリア上に、ステーション名や交通情報などの補助情報としてバイナリ形式で送信します。このインターフェースは、RDS情報を受信および/または送信できるデバイスを対象としています。

詳細については、コアRDS標準を参照してください IEC 62106 およびRBDS標準 NRSC-4-B.

注意

米国で使用されるRBDS標準はRDS標準とほぼ同じです。RDSデコーダー/エンコーダーはRBDSも処理可能です。ただし一部のフィールドの意味がやや異なります。詳細はRBDS標準を参照してください。

RBDS標準はMMBS（Modified Mobile Search）のサポートも規定しています。これは非公式な形式で、現在は廃止されているようです。RDSインターフェースはこの形式をサポートしていません。MMBSのサポート（または一般的にいわれる「Eブロック」）が必要な場合は、linux-mediaメーリングリストにご連絡ください： https://linuxtv.org/lists.php.

4.9.1. キャパビリティの照会¶

RDSキャプチャAPIをサポートするデバイスは、 V4L2_CAP_RDS_CAPTURE フラグを含めます。以下のようにします： capabilities 構造体の v4l2_capability は ioctl VIDIOC_QUERYCAP ioctlを設定します。RDSをサポートするチューナーは、 V4L2_TUNER_CAP_RDS フラグを含めます。以下のようにします： capability 構造体の v4l2_tunerを設定します。ドライバーがデータを解釈せずにRDSブロックを単に転送する場合、 V4L2_TUNER_CAP_RDS_BLOCK_IO フラグを設定する必要があります。詳しくは、 RDSデータの読み込みをご参照ください。今後の用途に備えて、フラグ V4L2_TUNER_CAP_RDS_CONTROLS も定義されています。しかし、この機能を持つラジオチューナー用ドライバーはまだ存在しないため、このようなドライバーを開発する予定がある場合は、linux-mediaメーリングリストでご相談ください： https://linuxtv.org/lists.php.

RDS信号の有無は、 rxsubchans 構造体の v4l2_tunerを確認することで検出できます。RDSデータが検出された場合、 V4L2_TUNER_SUB_RDS が設定されます。

RDS出力APIをサポートするデバイスは、 V4L2_CAP_RDS_OUTPUT フラグを含めます。以下のようにします： capabilities 構造体の v4l2_capability は ioctl VIDIOC_QUERYCAP ioctlを設定します。RDSをサポートするモジュレーターは、 V4L2_TUNER_CAP_RDS フラグを含めます。以下のようにします： capability 構造体の v4l2_modulatorを設定します。RDS送信を有効にするには、 V4L2_TUNER_SUB_RDS ビットを txsubchans 構造体の v4l2_modulatorを設定します。ドライバーがデータを解釈せずにRDSブロックを単に転送する場合、 V4L2_TUNER_CAP_RDS_BLOCK_IO フラグを設定する必要があります。チューナーがプログラム識別コードやラジオテキストなどのRDSエンティティを処理できる場合、 V4L2_TUNER_CAP_RDS_CONTROLS フラグを設定してください。詳しくは、 RDSデータの書き込み および FM送信機制御リファレンス.

4.9.2. RDSデータの読み込み¶

RDSデータは、 read() 関数でラジオデバイスから読み取れます。データは3バイトごとにパックされています。

4.9.3. RDSデータの書き込み¶
