7.58. ioctl VIDIOC_SUBDEV_G_CROP, VIDIOC_SUBDEV_S_CROP¶

7.58.1. 名前¶

VIDIOC_SUBDEV_G_CROP - VIDIOC_SUBDEV_S_CROP - subdev pad 上のクロップ矩形を取得または設定します

7.58.2. 概要¶

VIDIOC_SUBDEV_G_CROP¶

int ioctl(int fd, VIDIOC_SUBDEV_G_CROP, struct v4l2_subdev_crop *argp)

VIDIOC_SUBDEV_S_CROP¶

int ioctl(int fd, VIDIOC_SUBDEV_S_CROP, const struct v4l2_subdev_crop *argp)

7.58.3. 引数¶

fd

返されるファイル記述子 open().

argp

struct mem_ctl_info v4l2_subdev_crop.

7.58.4. 説明¶

注意

これはインターフェースであり、今後変更される可能性があります。 非推奨のAPI要素 インターフェースであり、今後削除される可能性があります。これは 選択 API によって置き換えられています.

現在のクロップ矩形を取得するには、アプリケーションは pad フィールドを設定します。 v4l2_subdev_crop メディア API および which フィールドに渡して V4L2_SUBDEV_FORMAT_ACTIVEで報告された望ましい pad ナンバーを設定します。その後、アプリケーションは VIDIOC_SUBDEV_G_CROP ioctl にこの構造体へのポインタを渡します。ドライバーはこの構造体の rect フィールドに値を設定するか、入力引数が無効な場合や、指定された pad でクロッピングがサポートされていない場合、エラー コードを返します EINVAL クロップ矩形を変更するには、アプリケーションは

デバイスの能力を照会するには、アプリケーションは which に（木の下から葉に向かって） V4L2_SUBDEV_FORMAT_TRYを設定します。設定された場合、ドライバーはデバイスに 'try' クロップ矩形を適用せず、アクティブなクロップ矩形と同様に変換し、サブデバイス ファイルハンドルに保存します。これにより、同じサブデバイスを照会する 2 つのアプリケーションはお互いに干渉しません

サブデバイス デバイスノードが読み取り専用モードで登録されている場合、 VIDIOC_SUBDEV_S_CROP 呼び出しは、 which フィールドがドライバによって V4L2_SUBDEV_FORMAT_TRYが有効な場合にのみ有効です。それ以外の場合、エラーが返され、errno 変数が -EPERM.

7.58.5. 戻り値¶

成功した場合、0 が返されます。エラーの場合、-1 が返され、変数が適切に設定されます。 errno 一般的なエラーコードは、 汎用エラーコード 章。

EBUSY

pad が現在 busy なため、クロップ矩形を変更できません。これは、pad 上にアクティブなビデオストリームがあるなどの原因で発生します。ioctl は、問題を修正するための別のアクションを実行せずに再試行してはなりません。このエラーは、 VIDIOC_SUBDEV_S_CROP

EINVAL

構造体 v4l2_subdev_crop pad 存在しないパッドを参照している場合、 which フィールドが存在しないフォーマットを参照している場合、または指定されたサブデバイス pad でクロッピングがサポートされていない場合にのみ返されます

EPERM

以下の VIDIOC_SUBDEV_S_CROP ioctl が読み取り専用サブデバイス上で呼び出され、 which フィールドがドライバによって V4L2_SUBDEV_FORMAT_ACTIVE.
