3. メディアグラフ要素を表すための型とフラグ¶

Media entity functions¶

MEDIA_ENT_F_UNKNOWN および MEDIA_ENT_F_V4L2_SUBDEV_UNKNOWN

不明なエンティティ。これは一般的にドライバーがエンティティを正しく初期化しなかったことを示し、これはカーネルのバグです

MEDIA_ENT_F_IO_V4L

データストリーミングの入力および/または出力エンティティ。

MEDIA_ENT_F_IO_VBI

V4L VBIストリーミングの入力または出力エンティティ

MEDIA_ENT_F_IO_SWRADIO

V4Lソフトウェアデジタルラジオ（SDR）ストリーミングの入力または出力エンティティ

MEDIA_ENT_F_IO_DTV

DVBデジタルTVストリーミングの入力または出力エンティティ

MEDIA_ENT_F_DTV_DEMOD

デジタルTVデモデューラー・エンティティ。

MEDIA_ENT_F_TS_DEMUX

MPEGトランスポートストリームデマルチプレクサ・エンティティ。ハードウェアまたはLinux DVBサブシステムによるカーネル空間での実装が可能です

MEDIA_ENT_F_DTV_CA

デジタルTVコンディショナル・アクセス・モジュール（CAM）エンティティ

MEDIA_ENT_F_DTV_NET_DECAP

デジタルTVネットワークULE/MLEデセパケーション・エンティティ。ハードウェアまたはカーネル空間での実装が可能です

MEDIA_ENT_F_CONN_RF

ラジオ周波数（RF）信号用のコネクタ。

MEDIA_ENT_F_CONN_SVIDEO

S-Video信号用のコネクタ。

MEDIA_ENT_F_CONN_COMPOSITE

RGBコンポジット信号用のコネクタ。

MEDIA_ENT_F_CAM_SENSOR

カメラビデオセンサー・エンティティ。

MEDIA_ENT_F_FLASH

フラッシュ制御エンティティ。

MEDIA_ENT_F_LENS

レンズ制御エンティティ。

MEDIA_ENT_F_ATV_DECODER

アナログビデオデコーダー。ビデオデコーダーの基本機能は、放送、DVDプレイヤー、カメラ、ビデオテープレコーダーなど幅広いソースから送信されるNTSC、PAL、SECAM、またはHD形式のアナログビデオを受信し、ストリームを明るさ（ルミナント）と色（クロマインス）の成分に分離して、適切なタイミング信号とともにあるデジタルビデオ標準形式で出力することです。

MEDIA_ENT_F_TUNER

デジタルTV、アナログTV、ラジオおよび/またはソフトウェアラジオチューナー。これはPLLチューニング段階を含み、ラジオ周波数（RF）信号を中間周波数（IF）に変換します。現代のチューナーは内部にIF-PLLデコーダーを備えており、音声およびビデオの処理が可能です。しかし古いモデルではこれらの段階は別個のエンティティで実装されています。

MEDIA_ENT_F_IF_VID_DECODER

IF-PLLビデオデコーダー。PLLから受信したIFをデコードし、アナログTVビデオ信号を出力します。これは非常に古いアナログチューナー（例：Philips MK3設計）に見られ、すべてtda9887（または互換性のある類似チップ、例：tda9885）を含んでいます。これらのデバイスはチューナーPLLとは異なるI2Cアドレスを使用します。

MEDIA_ENT_F_IF_AUD_DECODER

IF-PLL音声デコーダー。PLLから受信したIFをデコードし、アナログTV音声信号を出力します。これは非常に古いアナログハードウェア（例：Micronas msp3400、Philips tda9840、tda985xなど）に見られ、これらのデバイスはチューナーPLLとは異なるI2Cアドレスを使用し、IF-PLLビデオデコーダーとともに制御する必要があります。

MEDIA_ENT_F_AUDIO_CAPTURE

オーディオキャプチャ機能エンティティ。

MEDIA_ENT_F_AUDIO_PLAYBACK

オーディオプレイバック機能エンティティ。

MEDIA_ENT_F_AUDIO_MIXER

オーディオミキサー機能エンティティ。

MEDIA_ENT_F_PROC_VIDEO_COMPOSER

ビデオコンポーザー（ブレンドャー）。ビデオコンポジットを実行可能なエンティティは、少なくとも2つのシンクパッドと1つのソースパッドを備え、入力ビデオフレームを出力ビデオフレームに合成します。合成はアルファブレンド、カラーキー、ラスターオペレーション（ROP）、ステッチング、またはその他の方法で実行できます。

MEDIA_ENT_F_PROC_VIDEO_PIXEL_FORMATTER

ビデオピクセルフォーマッター。ピクセルフォーマットを実行可能なエンティティは、少なくとも1つのシンクパッドと1つのソースパッドを備えます。読み込みピクセルフォーマッターはメモリからピクセルを読み込み、アンパッキング、クロッピング、カラーキー、アルファ乗算、ピクセル符号化変換の一部を実行します。書き込みピクセルフォーマッターはドットフィルタリング、ピクセル符号化変換、パッキングの一部を実行し、メモリにピクセルを書き込みます。

MEDIA_ENT_F_PROC_VIDEO_PIXEL_ENC_CONV

ビデオピクセル符号化変換。ピクセル符号化変換を実行可能なエンティティは、少なくとも1つのシンクパッドと1つのソースパッドを備え、シンクパッドで受信したピクセルの符号化をソースパッドで異なる符号化に変換します。ピクセル符号化変換にはRGBとHSV、RGBとYUV、CFA（バエイ）とRGBの変換などが含まれますが、これらに限定されません。

MEDIA_ENT_F_PROC_VIDEO_LUT

ビデオリファレンステーブル。ビデオリファレンステーブル処理を実行可能なエンティティは1つのシンクパッドと1つのソースパッドを備えます。このエンティティはシンクパッドで受信したピクセルの値を内部テーブルから参照し、ソースパッドで出力します。参照処理は各コンポーネントを別々に実行するか、多次元テーブル参照として組み合わせて実行できます。

MEDIA_ENT_F_PROC_VIDEO_SCALER

ビデオスケーラー。ビデオスケーリングを実行可能なエンティティは、少なくとも1つのシンクパッドと1つのソースパッドを備え、シンクパッドで受信したビデオフレームをソースパッドで異なる解像度にスケーリングします。サポートされるスケーリング比率の範囲はエンティティ固有であり、水平方向と垂直方向で異なり得ます（特に1方向のみサポートされる場合もあります）。ビニングとサブサンプリング（場合によってはスキップとも呼ばれます）はスケーリングとして扱われます。

MEDIA_ENT_F_PROC_VIDEO_STATISTICS

ビデオ統計計算（ヒストグラム、3Aなど）。統計計算を実行可能なエンティティは1つのシンクパッドと1つのソースパッドを備えます。このエンティティはシンクパッドで受信したフレームの統計を計算し、ソースパッドで統計データを出力します。

MEDIA_ENT_F_PROC_VIDEO_ENCODER

ビデオ（MPEG、HEVC、VPxなど）エンコーダー。ビデオフレームを圧縮可能なエンティティです。1つのシンクパッドと少なくとも1つのソースパッドを備えます。

MEDIA_ENT_F_PROC_VIDEO_DECODER

ビデオ（MPEG、HEVC、VPxなど）デコーダー。圧縮ビデオストリームを未圧縮ビデオフレームに復号可能なエンティティです。1つのシンクパッドと少なくとも1つのソースパッドを備えます。

MEDIA_ENT_F_VID_MUX

ビデオ多重器。多重機能を持つエンティティは、少なくとも2つのシンクパッドと1つのソースパッドを備え、アクティブなシンクパッドから受信したビデオフレーム（複数可能）をソースパッドに転送しなければならない。

MEDIA_ENT_F_VID_IF_BRIDGE

ビデオインターフェースブリッジ。ビデオインターフェースブリッジエンティティは、少なくとも1つのシンクパッドと1つのソースパッドを備え、入力ビデオバス（HDMI、eDP、MIPI CSI-2など）からのビデオフレームをシンクパッドで受信し、出力ビデオバス（eDP、MIPI CSI-2、並列など）のソースパッドに送出する。

MEDIA_ENT_F_DV_DECODER

デジタルビデオデコーダー。ビデオデコーダーの基本機能は、幅広いソースから受信したデジタルビデオを、適切なタイミング信号とともに特定のデジタルビデオ標準形式に変換して出力することである。

MEDIA_ENT_F_DV_ENCODER

デジタルビデオエンコーダー。ビデオエンコーダーの基本機能は、適切なタイミング信号とともに特定のデジタルビデオ標準形式（通常は並列ビデオバスと同期信号）からデジタルビデオを受信し、HDMIやDisplayPortなどのデジタルビデオ出力コネクタに送出することである。

Media pad flags¶

MEDIA_PAD_FL_SINK

エンティティに対しての入力ピン。入力ピンはデータを吸収し、リンクのターゲットとなる。

MEDIA_PAD_FL_SOURCE

エンティティに対しての出力ピン。出力ピンはデータを供給し、リンクの出発点となる。

MEDIA_PAD_FL_MUST_CONNECT

このフラグが設定されており、ピンが他のピンにリンクされている場合、少なくとも1つのリンクが有効でなければエンティティがストリーミングを実行できずます。このフラグが設定されていない場合でも、一時的な理由（例：デバイスの設定に依存）により、ピンが有効なリンクを必要とする場合があります。フラグの absence は、常に有効なリンクがないことを意味しません。

ただ一つの MEDIA_PAD_FL_SINK および MEDIA_PAD_FL_SOURCE すべてのピンに対して設定する必要があります。

Media link flags¶

MEDIA_LNK_FL_ENABLED

リンクが有効であり、メディアデータの転送に使用できます。2つ以上のリンクがシンクピンにターゲットとしている場合、同時に有効なリンクは1つだけです。

MEDIA_LNK_FL_IMMUTABLE

リンクの有効状態は実行時において変更できません。変更不可能なリンクは常に有効です。

MEDIA_LNK_FL_DYNAMIC

リンクの有効状態はストリーミング中に変更可能です。このフラグはドライバによって設定され、アプリケーションでは読み取り専用です。

MEDIA_LNK_FL_LINK_TYPE

これはリンクのタイプを定義するビットマスクです。現在、2種類のリンクがサポートされています：

MEDIA_LNK_FL_DATA_LINK 2つのピン間のリンクの場合

MEDIA_LNK_FL_INTERFACE_LINK インターフェースとエンティティ間のリンクの場合
