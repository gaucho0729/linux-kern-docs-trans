5.1. イベント¶

OMAP 3 ISP ドライバは、CCDC および統計（AEWB、AF およびヒストグラム）サブデバイスで V4L2 イベントインターフェースをサポートしています。

CCDC サブデバイスは HS_VS インターナルで V4L2_EVENT_FRAME_SYNC 型のイベントを生成し、フレーム開始を通知します。以前のドライババージョンではこの目的で V4L2_EVENT_OMAP3ISP_HS_VS を使用していました。このイベントは、CCDC モジュールでフレームの最初のラインの受信が始まるタイミングで正確にトリガーされます。このイベントは CCDC サブデバイスでサブスクライブ可能です。

(並列インターフェースを使用する場合、VS シグナルの極性の正しい設定に注意する必要があります。シリアルレシーバーを使用する場合は自動的に正しい設定になります。)

各統計サブデバイスはイベントを生成できます。ユーザー空間アプリケーションが VIDIOC_OMAP3ISP_STAT_REQ IOCTL を使用して統計バッファをデキューするたびにイベントが生成されます。利用可能なイベントは以下の通りです：

  • V4L2_EVENT_OMAP3ISP_AEWB

  • V4L2_EVENT_OMAP3ISP_AF

  • V4L2_EVENT_OMAP3ISP_HIST

これらの IOCTL で使用されるイベントデータの型は struct omap3isp_stat_event_status です。統計計算にエラーが発生した場合でも通常のイベントが生成されますが、関連する統計バッファは存在しません。この場合、omap3isp_stat_event_status.buf_err がゼロ以外の値に設定されます。

5.2. プライベート IOCTL¶

OMAP 3 ISP ドライバは、可能な限り標準 V4L2 IOCTL とコントロールをサポートしています。しかし、ISP が提供する多くの機能（ガンマテーブルや統計収集の設定など）は標準 IOCTL の範囲外です。

一般的に、ハードウェア依存機能を含む各ブロックの設定にはプライベート IOCTL が用意されています。

サポートされるプライベート IOCTL は以下の通りです：

  • VIDIOC_OMAP3ISP_CCDC_CFG

  • VIDIOC_OMAP3ISP_PRV_CFG

  • VIDIOC_OMAP3ISP_AEWB_CFG

  • VIDIOC_OMAP3ISP_HIST_CFG

  • VIDIOC_OMAP3ISP_AF_CFG

  • VIDIOC_OMAP3ISP_STAT_REQ

  • VIDIOC_OMAP3ISP_STAT_EN

これらの IOCTL で使用されるパラメータ構造体は include/linux/omap3isp.h に記述されています。ISP 自体の特定のブロックに関する詳細な機能は技術参照マニュアル（TRM）に記載されています — 本文末に記載されています。

これらのプライベート IOCTL を使用せずに ISP ドライバを使用することは可能です。ただし、この方法では最適な画像品質を得ることはできません。AEWB、AF およびヒストグラムモジュールは、適切なプライベート IOCTL を使用して設定しないと使用できません。

5.3. CCDC およびプレビューブロック IOCTL¶

VIDIOC_OMAP3ISP_CCDC_CFG と VIDIOC_OMAP3ISP_PRV_CFG は、CCDC ブロックとプレビュー ブロックの機能を設定し、有効化・無効化するための IOCTL です。どちらの IOCTL も、それぞれのブロックで複数の機能を制御します。VIDIOC_OMAP3ISP_CCDC_CFG は、struct omap3isp_ccdc_update_config へのポインタを引数として受け取ります。同様に、VIDIOC_OMAP3ISP_PRV_CFG は、struct omap3isp_prev_update_config へのポインタを受け取ります。これらの構造体の定義は以下のドキュメントに記載されています。 1.

構造体の update フィールドは、特定の機能の設定を更新するかどうかを示し、flag フィールドは機能を有効化するか無効化するかを示します。

update および flag ビットマスクは、以下の値を受けることができます。CCDC およびプレビュー ブロックのそれぞれの個別の機能は、flag（無効化または有効化、構造体の flag フィールドの一部）と、その機能の構成データへのポインタと関連付けられています。

VIDIOC_OMAP3ISP_CCDC_CFG の update および flag フィールドの有効な値は以下の通りです。複数の機能を同じ IOCTL 呼び出しで設定するには、値を OR で組み合わせることができます。

  • OMAP3ISP_CCDC_ALAW

  • OMAP3ISP_CCDC_LPF

  • OMAP3ISP_CCDC_BLCLAMP

  • OMAP3ISP_CCDC_BCOMP

  • OMAP3ISP_CCDC_FPC

  • OMAP3ISP_CCDC_CULL

  • OMAP3ISP_CCDC_CONFIG_LSC

  • OMAP3ISP_CCDC_TBL_LSC

VIDIOC_OMAP3ISP_PRV_CFG に対応する値は以下の通りです：

  • OMAP3ISP_PREV_LUMAENH

  • OMAP3ISP_PREV_INVALAW

  • OMAP3ISP_PREV_HRZ_MED

  • OMAP3ISP_PREV_CFA

  • OMAP3ISP_PREV_CHROMA_SUPP

  • OMAP3ISP_PREV_WB

  • OMAP3ISP_PREV_BLKADJ

  • OMAP3ISP_PREV_RGB2RGB

  • OMAP3ISP_PREV_COLOR_CONV

  • OMAP3ISP_PREV_YC_LIMIT

  • OMAP3ISP_PREV_DEFECT_COR

  • OMAP3ISP_PREV_GAMMABYPASS

  • OMAP3ISP_PREV_DRK_FRM_CAPTURE

  • OMAP3ISP_PREV_DRK_FRM_SUBTRACT

  • OMAP3ISP_PREV_LENS_SHADING

  • OMAP3ISP_PREV_NF

  • OMAP3ISP_PREV_GAMMA

機能を有効化する際には、関連する構成ポインタは NULL であってはなりません。機能を無効化する際には、構成ポインタは無視されます。

5.4. 統計ブロック IOCTL¶

統計サブデバイスは、他のサブデバイスよりも動的な設定オプションを提供しています。パイプラインがストリーミング状態にあるときに、有効化・無効化・再設定が可能です。

統計ブロックは常に CCDC から入力画像データを取得します（ヒストグラムメモリの読み取りは実装されていません）。ユーザーは、統計サブデバイスノードを使用してプライベート IOCTL を介して統計データを取得できます。

AEWB、AF およびヒストグラムサブデバイスが提供するプライベート IOCTL は、ISP ハードウェアが提供するレジスタレベルインターフェースと密接に関連しています。ドライバ実装に特有の要素については、次に説明します。

5.5. VIDIOC_OMAP3ISP_STAT_EN¶

このプライベートIOCTLは統計モジュールの有効/無効を制御します。このリクエストがストリーミング開始前に行われた場合、パイプラインがストリーミングを開始した時点で効果を発揮します。パイプラインがすでにストリーミングしている場合、CCDCがアイドル状態になった時点で効果を発揮します。

5.6. VIDIOC_OMAP3ISP_AEWB_CFG, VIDIOC_OMAP3ISP_HIST_CFG および VIDIOC_OMAP3ISP_AF_CFG¶

これらのIOCTLはモジュールの設定に使用されます。ユーザーアプリケーションはハードウェアに関する深い知識を必要とします。ほとんどのフィールドの説明はOMAPのTRMsに記載されています。以下のすべての設定用プライベートIOCTLに共通する2つのフィールドについて説明します。これらはTRMに記載されていないため、理解を深めるために説明します。

omap3isp_[h3a_af/h3a_aewb/hist]_config.buf_size:

モジュールは内部でバッファを処理します。モジュールのデータ出力に必要なバッファサイズは、リクエストされた設定に依存します。ドライバーはストリーミング中に再設定をサポートしていますが、既に内部で割り当てられたよりも大きなバッファサイズを必要とする再設定はサポートしていません。この場合、-EBUSYを返します。このような状態を避けるため、モジュールを無効化/再設定/有効化するか、モジュールが無効な状態で最初の設定時に必要なバッファサイズをリクエストしてください。

内部バッファサイズの割り当ては、リクエストされた設定の最小バッファサイズとbuf_sizeフィールドの値を考慮します。buf_sizeフィールドが[最小値、最大値]の範囲外の場合、その値は範囲内にクリップされます。ドライバーは最大値を選択し、修正後のbuf_size値をユーザーアプリケーションに書き戻します。

omap3isp_[h3a_af/h3a_aewb/hist]_config.config_counter:

設定がリクエストされた時点とは同期して効果を発揮しないため、ドライバーはこの情報を追跡する方法を提供する必要があります。設定リクエスト後、ユーザー空間アプリケーションに返されるconfig_counterは、そのリクエストに固有の値です。ユーザーアプリケーションがバッファ利用可能イベントを受信した後、または新しいバッファがリクエストされたときに、このconfig_counterはバッファデータと設定をマッチングするために使用されます。

5.7. VIDIOC_OMAP3ISP_STAT_REQ¶

内部バッファキュー内の最も古いデータをユーザー空間に送信し、その後そのバッファを破棄します。フィールドomap3isp_stat_data.frame_numberはビデオバッファのfield_countフィールドと一致します。
