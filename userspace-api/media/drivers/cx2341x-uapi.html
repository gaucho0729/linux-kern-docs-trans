1. cx2341xドライバー¶

1.1. 非圧縮ファイル形式¶

cx23416は（cx23415も読み取れる）RAW YUV出力を行うことができます。YUVフレームの形式はこのチップ固有でHM12と呼ばれます。「HM」は「Hauppauge Macroblock」を指しますが、より正確には「Conexant Macroblock」が適切です。

形式はYUV 4:2:0で、1ピクセルあたり1Yバイト、4ピクセルあたり1Uおよび1Vバイトを使用します。

データは2つのマクロブロックプレーンに符号化され、1つ目のプレーンにはY値、2つ目のプレーンにはUVマクロブロックが含まれます。

Yプレーンは左から右、上から下に16x16ピクセルのブロックに分割され、それぞれ順に1行ずつ送信されます。

したがって、最初の16バイトは左上ブロックの1行目、次の16バイトは左上ブロックの2行目などです。このブロックを送信した後、右隣のブロックの1行目を送信し、同様に続きます。

UVプレーンは左から右、上から下に16x8のUV値のブロックに分割され、それぞれ順に1行ずつ送信されます。

したがって、最初の16バイトは左上ブロックの1行目で、8つのUV値ペア（合計16バイト）を含みます。次の16バイトは左上ブロックの8つのUVペアの2行目などです。このブロックを送信した後、右隣のブロックの1行目を送信し、同様に続きます。

以下のコードはHM12を別個のY、U、Vプレーンに変換する例です。このコードは720x576（PAL）ピクセルのフレームを前提としています。

フレームの幅は常に720ピクセルであり、実際の指定幅に関係なく変わりません。

高さが32ラインの倍数でない場合、キャプチャされた動画は最後のマクロブロックが欠落し、使用不可になります。したがって高さは32ラインの倍数でなければなりません。

1.1.1. RAW形式 C例¶

#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static unsigned char frame[576*720*3/2];
static unsigned char framey[576*720];
static unsigned char frameu[576*720 / 4];
static unsigned char framev[576*720 / 4];

static void de_macro_y(unsigned char* dst, unsigned char *src, int dstride, int w, int h)
{
unsigned int y, x, i;

// descramble Y plane
// dstride = 720 = w
// The Y plane is divided into blocks of 16x16 pixels
// Each block in transmitted in turn, line-by-line.
for (y = 0; y < h; y += 16) {
        for (x = 0; x < w; x += 16) {
        for (i = 0; i < 16; i++) {
                memcpy(dst + x + (y + i) * dstride, src, 16);
                src += 16;
        }
        }
}
}

static void de_macro_uv(unsigned char *dstu, unsigned char *dstv, unsigned char *src, int dstride, int w, int h)
{
unsigned int y, x, i;

// descramble U/V plane
// dstride = 720 / 2 = w
// The U/V values are interlaced (UVUV...).
// Again, the UV plane is divided into blocks of 16x16 UV values.
// Each block in transmitted in turn, line-by-line.
for (y = 0; y < h; y += 16) {
        for (x = 0; x < w; x += 8) {
        for (i = 0; i < 16; i++) {
                int idx = x + (y + i) * dstride;

                dstu[idx+0] = src[0];  dstv[idx+0] = src[1];
                dstu[idx+1] = src[2];  dstv[idx+1] = src[3];
                dstu[idx+2] = src[4];  dstv[idx+2] = src[5];
                dstu[idx+3] = src[6];  dstv[idx+3] = src[7];
                dstu[idx+4] = src[8];  dstv[idx+4] = src[9];
                dstu[idx+5] = src[10]; dstv[idx+5] = src[11];
                dstu[idx+6] = src[12]; dstv[idx+6] = src[13];
                dstu[idx+7] = src[14]; dstv[idx+7] = src[15];
                src += 16;
        }
        }
}
}

/*************************************************************************/
int main(int argc, char **argv)
{
FILE *fin;
int i;

if (argc == 1) fin = stdin;
else fin = fopen(argv[1], "r");

if (fin == NULL) {
        fprintf(stderr, "cannot open input\n");
        exit(-1);
}
while (fread(frame, sizeof(frame), 1, fin) == 1) {
        de_macro_y(framey, frame, 720, 720, 576);
        de_macro_uv(frameu, framev, frame + 720 * 576, 720 / 2, 720 / 2, 576 / 2);
        fwrite(framey, sizeof(framey), 1, stdout);
        fwrite(framev, sizeof(framev), 1, stdout);
        fwrite(frameu, sizeof(frameu), 1, stdout);
}
fclose(fin);
return 0;
}

1.2. 埋め込まれたV4L2_MPEG_STREAM_VBI_FMT_IVTV VBIデータの形式¶

著者: Hans Verkuil <hverkuil@xs4all.nl>

このセクションでは、MPEG-2プログラムストリームに埋め込まれたVBIデータのV4L2_MPEG_STREAM_VBI_FMT_IVTV形式について説明します。この形式は、ivtvドライバ（Conexant cx23415/6チップ用ドライバ）の一部のハードウェア制限により規定されており、特にVBIデータの最大サイズが影響しています。cx23415を介してMPEGストリームを再生する際には、長すぎるデータは切り捨てられます。

この形式の利点は、非常にコンパクトであり、すべてのラインのVBIデータを収容しつつ最大許容サイズ内に収めることが可能です。

VBIデータのストリームIDは0xBDです。埋め込まれたデータの最大サイズは4 + 43 * 36バイトで、これは4バイトのヘッダーと2 * 18本のVBIライン（各ラインが1バイトのヘッダーと42バイトのペイロードを含む）です。この制限を超えるデータはcx23415/6ファームウェアによって切り捨てられます。VBIラインのデータに加えて、キャプチャされたラインを指定するビットマスク用の36ビットと、このデータパッケージがV4L2_MPEG_STREAM_VBI_FMT_IVTV形式のVBIデータを含むことを示す4バイトのマジックコインが必要です。すべてのラインが使用される場合、ビットマスクはもう収まらなくなります。この問題を解決するために2つの異なるマジックナンバーが導入されました。

‘itv0’: このマジックナンバーの後に2つの符号なし長整数が続きます。最初の符号なし長整数のビット0-17は、最初のフィールドのどのラインがキャプチャされるかを示します。最初の符号なし長整数のビット18-31と、2番目の符号なし長整数のビット0-3は、2番目のフィールドの情報を表します。

‘ITV0’: このマジックナンバーはすべてのVBIラインがキャプチャされるものと仮定しており、つまりビットマスクが0xffffffffと0xfであることを暗黙的に意味します。

これらのマジックコイン（および‘itv0’の場合の8バイトビットマスク）の後、キャプチャされたVBIラインが始まります。

各ラインごとに、最初のバイトの最下位4ビットにデータタイプが含まれます。可能な値は以下の表に示されています。ペイロードはその次の42バイトにあります。

可能なデータタイプの一覧:

#define IVTV_SLICED_TYPE_TELETEXT       0x1     // Teletext (uses lines 6-22 for PAL)
#define IVTV_SLICED_TYPE_CC             0x4     // Closed Captions (line 21 NTSC)
#define IVTV_SLICED_TYPE_WSS            0x5     // Wide Screen Signal (line 23 PAL)
#define IVTV_SLICED_TYPE_VPS            0x7     // Video Programming System (PAL) (line 16)
