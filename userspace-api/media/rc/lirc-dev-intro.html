6.1. はじめに¶

LIRC は Linux インフラレッドリモコンを指します。LIRC デバイスインターフェースは、ユーザー空間とカーネル空間間で素の IR およびデコードされたスキャンコードデータを双方向に転送するインターフェースです。本質的に、これは chardev（/dev/lircX、X = 0, 1, 2, …）であり、いくつかの標準的な struct file_operations が定義されています。素の IR およびデコードされたスキャンコードの転送に関しては、read、write、ioctl などの fops が基本となります。

LIRC デバイスに BPF プログラムをアタッチして、素の IR をスキャンコードにデコードすることも可能です。

ドライバが LIRC で登録された際の dmesg 出力例:

$ dmesg |grep lirc_dev
rc rc0: lirc_dev: driver mceusb registered at minor = 0, raw IR receiver, raw IR transmitter

キャラクタデバイスとして表示されるべきものです:

$ ls -l /dev/lirc*
crw-rw---- 1 root root 248, 0 Jul 2 22:20 /dev/lirc0

注意として、パッケージ v4l-utils には LIRC デバイスを操作するためのツールが含まれています:

  • ir-ctl: 素の IR を受信・送信し、LIRC デバイスの機能を照会できます。

  • ir-keytable: キーマップをロードし、IR カーネルプロトコルを設定できます。BPF IR デコーダーをロードし、IR デコードをテストできます。一部の BPF IR デコーダーも提供されています。

6.2. LIRC モード¶

LIRC は、以下の表に示すように、IR コードの受信および送信に使用可能ないくつかのモードをサポートしています。

LIRC_MODE_SCANCODE

このモードは送信および受信の両方に使用されます。

NECプロトコルでは、「ボタン保持」を「同じボタンを繰り返し押し」で区別する方法がありません。RC-5およびRC-6プロトコルにはトグルビットがあります。ボタンを離した後、再び押した場合、トグルビットが反転します。トグルビットが設定されている場合、 LIRC_SCANCODE_FLAG_TOGGLE が設定される前。

6.3. BPFベースの赤外線（IR）デコーダー¶

カーネルは一般的な 赤外線（IR）プロトコル、ただしサポートされていないプロトコルは多くあります。これらのプロトコルをサポートするには、BPFプログラムをロードしてデコードを行うことが可能です。ただし、これはRAW IRを読み取えるLIRCデバイスでのみ可能です。

まず、 bpf(2) syscallで、 BPF_LOAD_PROG 引数で、タイプ BPF_PROG_TYPE_LIRC_MODE2。LIRCデバイスにアタッチされると、このプログラムはLIRCデバイスの各パルス、スペース、タイムアウトイベントに対して呼び出されます。BPFプログラムのコンテキストは、符号なし整数へのポインタであり、 LIRC_MODE_MODE2 値です。プログラムがスキャンコードをデコードした場合、BPF関数を使用してサブミットできます。 bpf_rc_keydown() または bpf_rc_repeat()マウスやポインタの移動は bpf_rc_pointer_rel().

取得した後、 BPF_PROG_TYPE_LIRC_MODE2 BPFプログラムをLIRCデバイスにアタッチするには、 bpf(2) syscallを使用します。ターゲットはLIRCデバイスのファイルディスクリプタでなければなりません。アタッチタイプは BPF_LIRC_MODE2。1つのLIRCデバイスに同時にアタッチできるBPFプログラムは最大64個です。
