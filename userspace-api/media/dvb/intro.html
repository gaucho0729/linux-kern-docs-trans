1. はじめに¶

1.1. 知っておくべきこと¶

このドキュメントの読者には、デジタルビデオ放送（デジタルTV）分野の知識が必要であり、MPEG2仕様ISO/IEC 13818（いわゆるITU-T H.222）の第1部に精通している必要があります。つまり、プログラム/トランスポートストリーム（PS/TS）とは何か、パケット化された要素ストリーム（PES）やIフレームとは何かを理解している必要があります。

さまざまなデジタルTV標準ドキュメントは以下のURLからダウンロード可能です：

  • ヨーロッパの標準（DVB）： http://www.dvb.org および/または http://www.etsi.org.

  • アメリカの標準（ATSC）： https://www.atsc.org/standards/

  • 日本の標準（ISDB）： http://www.dibeg.org/

また、Linuxデバイスへのアクセス方法やioctlコールの使用方法を理解する必要があります。これにはCまたはC++の知識も含まれます。

1.2. 履歴¶

1999年末にConvergenceで使用した最初のデジタルTVカード用APIは、フレームグリッパーカード用に主に開発されたVideo4Linux APIの拡張版でした。そのため、デジタルTVカードやその新機能（MPEGストリームの録画や複数のセクションおよびPESデータストリームの同時フィルタリングなど）にはあまり適切ではありませんでした。

2000年初頭、NokiaからデジタルTV用新しいLinux標準APIの提案がConvergenceに届けられました。オープン標準に基づいた端末の開発へのコミットメントとして、NokiaとConvergenceはすべてのLinux開発者に公開し、 https://linuxtv.org 2000年9月に公開しました。Siemens/Hauppauge DVB PCIカード用のLinuxドライバーを提供することで、ConvergenceはLinuxデジタルTV APIの最初の実装を提供しました。Convergenceは初期のLinuxデジタルTV APIのメンテナでした。

現在、このAPIはLinuxTVコミュニティ（つまり、このドキュメントを読んでいるあなた）によって維持されています。LinuxデジタルTV APIは、カーネル内のサブシステムコアの改善とともに常にレビューされ、改善されています。

1.3. 概要¶

デジタルTVカードまたはセットトップボックス（STB）は通常、以下の主なハードウェアコンポーネントから構成されます：

チューナーとデジタルTVデモデューラーからなるフロントエンド

ここで、衛星アンテナや直接のケーブルから到達する素子信号は、フロントエンドがMPEGトランスポートストリーム（TS）に下変換および変調されます。衛星フロントエンドの場合、これは衛星機器制御（SEC）機能を含み、LNB偏光、マルチフィードスイッチ、パラボラスロータの制御が可能です。

条件付きアクセス（CA）ハードウェア（CIアダプターおよびスマートカードスロット）

完全なTSはCAハードウェアを通じて処理されます。ユーザーがアクセスできるプログラム（スマートカードによって制御される）はリアルタイムでデコードされ、TSに再挿入されます。

注意

すべてのデジタルTVハードウェアが条件付きアクセスハードウェアを備えているわけではありません。

入力するデジタルTV MPEG-TSストリームをフィルタリングするデマルチプレクサ

デマルチプレクサはTSをオーディオやビデオストリームなどの構成要素に分離します。通常は複数のオーディオおよびビデオストリームを含み、このプロバイダーの他のストリームにも含まれるプログラムに関する情報を含むデータストリームも含まれます。

オーディオおよびビデオデコーダ

デマルチプレクサの主なターゲットはオーディオおよびビデオデコーダです。デコード後、これらは未圧縮のオーディオおよびビデオをコンピュータ画面またはテレビジョンに送信します。

注意

現代のハードウェアでは通常、別個のデコーダハードウェアがありません。このような機能は主にメインCPU、システムのグラフィックアダプター、またはSoC（システムオンチップ）統合回路に内蔵された信号処理ハードウェアによって提供されます。

特定の用途（例：データのみの利用、例として「衛星経由インターネット」）では必要ない場合もあります。

1.4. LinuxデジタルTVデバイス¶

LinuxデジタルTV APIは、現在のところビデオ、オーディオ、フロントエンド、デマルチプレクサ、CA（条件付きアクセス）およびIP-over-DVBネットワーク用の6つのUnixスタイルのキャラクターデバイスを通じてこれらのハードウェアコンポーネントを制御します。ビデオおよびオーディオデバイスはMPEG2デコーダハードウェアを制御し、フロントエンドデバイスはチューナーおよびデジタルTVデモジュレータを制御します。デマルチプレクサデバイスはハードウェアのPESおよびセクションフィルタの制御を提供します。ハードウェアがフィルタリングをサポートしない場合、ソフトウェアで実装できます。最後に、CAデバイスはハードウェアのすべての条件付きアクセス機能を制御します。このデバイスを通じてアプリケーションに提供されるCA機能の数や方法は、プラットフォームごとのセキュリティ要件に依存します。

すべてのデバイスは /dev ツリーの下にあります。 /dev/dvb。個々のデバイスは以下の通りです：

  • /dev/dvb/adapterN/audioM,

  • /dev/dvb/adapterN/videoM,

  • /dev/dvb/adapterN/frontendM,

  • /dev/dvb/adapterN/netM,

  • /dev/dvb/adapterN/demuxM,

  • /dev/dvb/adapterN/dvrM,

  • /dev/dvb/adapterN/caM,

オプションを指定する必要があります。形式は以下の通りです： N はシステム内のデジタルTVカードを0から始めて列挙し、 M は各アダプター内の各デバイスタイプを0から始めて列挙します。以降の議論ではこの「/dev/dvb/adapterN/」は省略します。

すべてのデバイスのデータ構造および関数呼び出しについての詳細は次の章で説明します。

1.5. APIインクルードファイル¶

各デジタルTV機器には対応するインクルードファイルが存在します。デジタルTV APIのインクルードファイルは、アプリケーションのソースコードに部分的なパスを指定してインクルードする必要があります。例:

#include <linux/dvb/ca.h>

#include <linux/dvb/dmx.h>

#include <linux/dvb/frontend.h>

#include <linux/dvb/net.h>

アプリケーションが異なるAPIバージョンをサポートできるようにするため、追加のインクルードファイル linux/dvb/version.h が存在し、この定数を定義しています。このドキュメントは以下を説明しています DVB_API_VERSION. このドキュメントは以下を説明しています DVB_API_VERSION 5.10.
