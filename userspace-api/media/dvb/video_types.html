6.2.1.1. video_format_t¶

以下の video_format_t 定義されたデータ型

typedef enum {
    VIDEO_FORMAT_4_3,     /* Select 4:3 format */
    VIDEO_FORMAT_16_9,    /* Select 16:9 format. */
    VIDEO_FORMAT_221_1    /* 2.21:1 */
} video_format_t;

VIDEO_SET_FORMAT関数（??）でドライバーに出力ハードウェア（例: TV）のアスペクト比を伝えるために使用されます。また、VIDEO_GET_STATUS（??）で返されるvideo_status（??）およびVIDEO_GET_EVENT（??）で返されるvideo_event（??）というデータ構造にも使用され、現在のビデオストリームの表示形式を報告します。

6.2.1.2. video_displayformat_t¶

ビデオストリームの表示形式と表示ハードウェアの表示形式が異なる場合、アプリケーションは画像のクロッピングの処理方法を指定する必要があります。これはVIDEO_SET_DISPLAY_FORMATコール（??）を使用して行え、以下の引数を受け取ります。

typedef enum {
    VIDEO_PAN_SCAN,       /* use pan and scan format */
    VIDEO_LETTER_BOX,     /* use letterbox format */
    VIDEO_CENTER_CUT_OUT  /* use center cut out format */
} video_displayformat_t;

引数として。

6.2.1.3. video_stream_source_t¶

ビデオストリームのソースはVIDEO_SELECT_SOURCEコールで設定され、内部（デマルチプレクサ）または外部（ユーザー書き込み）のソースに応じて以下の値を取ることができます。

typedef enum {
    VIDEO_SOURCE_DEMUX, /* Select the demux as the main source */
    VIDEO_SOURCE_MEMORY /* If this source is selected, the stream
                   comes from the user through the write
                   system call */
} video_stream_source_t;

VIDEO_SOURCE_DEMUXはデマルチプレクサ（フロントエンドまたはDVRデバイスからの入力）をビデオストリームのソースとして選択します。VIDEO_SOURCE_MEMORYが選択された場合、ストリームはアプリケーションから通過してきます。 write() システムコールで読み取ることができます。

6.2.1.4. video_play_state_t¶

VIDEO_GET_STATUSコールが返す可能性のある値は、ビデオ再生の状態を表します。

typedef enum {
    VIDEO_STOPPED, /* Video is stopped */
    VIDEO_PLAYING, /* Video is currently playing */
    VIDEO_FREEZED  /* Video is freezed */
} video_play_state_t;
type video_command¶

6.2.1.5. struct video_command¶

アプリケーションが使用する前に構造体をゼロに初期化する必要があります。これにより、今後の拡張が安全に行えます。

struct video_command {
    __u32 cmd;
    __u32 flags;
    union {
        struct {
            __u64 pts;
        } stop;

        struct {
            /* 0 or 1000 specifies normal speed,
               1 specifies forward single stepping,
               -1 specifies backward single stepping,
               >>1: playback at speed/1000 of the normal speed,
               <-1: reverse playback at (-speed/1000) of the normal speed. */
            __s32 speed;
            __u32 format;
        } play;

        struct {
            __u32 data[16];
        } raw;
    };
};

type video_status¶

6.2.1.8. struct video_status¶

VIDEO_GET_STATUSコールは、再生操作のさまざまな状態を示す以下の構造体を返します。

struct video_status {
    int                   video_blank;   /* blank video on freeze? */
    video_play_state_t    play_state;    /* current state of playback */
    video_stream_source_t stream_source; /* current source (demux/memory) */
    video_format_t        video_format;  /* current aspect ratio of stream */
    video_displayformat_t display_format;/* selected cropping mode */
};

video_blankが設定されている場合、チャンネルが変更されたり再生が停止されたりするとビデオが消えます。それ以外の場合は、最後の画像が表示されます。play_stateはビデオが現在凍結、停止、または再生中であるかを示します。stream_sourceはビデオストリームの選択されたソースを示し、デマルチプレクサまたはメモリから来る可能性があります。video_formatは現在再生中のビデオストリームのアスペクト比（4:3または16:9のいずれか）を示します。最後に、display_formatはソースビデオ形式が出力デバイスの形式と異なる場合の選択されたクロッピングモードを示します。

6.2.1.10. video capabilities¶

VIDEO_GET_CAPABILITIESコールは、ハードウェアの機能に応じて設定されたビットをもつ無符号整数を返します。

/* bit definitions for capabilities: */
/* can the hardware decode MPEG1 and/or MPEG2? */
#define VIDEO_CAP_MPEG1   1
#define VIDEO_CAP_MPEG2   2
/* can you send a system and/or program stream to video device?
   (you still have to open the video and the audio device but only
    send the stream to the video device) */
#define VIDEO_CAP_SYS     4
#define VIDEO_CAP_PROG    8
/* can the driver also handle SPU, NAVI and CSS encoded data?
   (CSS API is not present yet) */
#define VIDEO_CAP_SPU    16
#define VIDEO_CAP_NAVI   32
#define VIDEO_CAP_CSS    64
