2.4.1. デジタルTVフロントエンドオープン¶

2.4.1.1. 名前¶

fe-open - フロントエンドデバイスを開く

2.4.1.2. 概要¶

#include <fcntl.h>
int open(const char *device_name, int フラグ)¶

2.4.1.3. 引数¶

device_name

開くデバイス。

flags

オープンフラグ。アクセスは次のいずれかで可能です O_RDWR または O_RDONLY.

複数のオープンは次のフラグで許可されます O_RDONLY. このモードでは、クエリおよび読み取り用のioctlのみが許可されます。

1つのオープンのみが許可されます O_RDWR. このモードでは、すべてのioctlが許可されます。

When the O_NONBLOCK フラグが指定された場合、システムコールはデータが利用不可またはデバイスドライバーが一時的にビジーな場合、エラーコードを返す可能性があります EAGAIN このシステムコールは、指定されたフロントエンドデバイスをオープンします (

他のフラグは効果がありません。

2.4.1.4. 説明¶

) 以降の使用のためにオープンします。/dev/dvb/adapter?/frontend?成功したオープン後に行う最初のことは、frontend_typeを取得することです。 ioctl FE_GET_INFO.

デバイスは読み取り専用モードでオープンでき、これによりデバイスのステータスや統計情報の監視のみが可能ですが、読み取り/書き込みモードでは、さまざまな用途が可能になります（例: チューニング操作の実行）。

複数のフロントエンドが存在するシステムでは、通常、複数のデバイスが読み取り/書き込みモードで同時にオープンすることはできません。読み取り/書き込みモードでフロントエンドデバイスがオープンされている間、他のオープン()コールが読み取り/書き込みモードで実行されると、非ブロッキングモードかブロッキングモードかによって失敗するかブロックするか異なります。ブロッキングモードでオープンされたフロントエンドデバイスは、後でfcntlシステムコールのF_SETFLコマンドを使用して非ブロッキングモードに変更できます（逆も可能です）。これは標準的なシステムコールであり、Linuxのfcntlマニュアルページで記述されています。オープン()コールが成功した場合、デバイスは指定されたモードで使用可能になります。これは、対応するハードウェアが電源が入っていることを意味し、他のフロントエンドが電源を切られた可能性があることを示します。

2.4.1.5. 戻り値¶

成功した場合 open() 新しいファイル記述子を返します。エラーの場合、-1が返され、 errno 変数が適切に設定されます。

可能性のあるエラーコードは次の通りです。

成功した場合、0が返され、 ca_slot_info ca_capsが埋められます。

エラーの場合、-1が返され、 errno 変数が適切に設定されます。

EPERM

呼び出し元がデバイスにアクセスする権限がありません。

EBUSY

デバイスドライバーがすでに使用中です。

EMFILE

プロセスが最大のファイル数を開いているためです。

ENFILE

システム全体でオープンされているファイル数の制限に達しました。

一般的なエラーコードは「CA_GET_SLOT_INFO」セクションで説明されています。 汎用エラーコード 章。
