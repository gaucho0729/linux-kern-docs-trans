4.3. ハイレベルCI API¶

注意

このドキュメンテーションは古くなったものです。

このドキュメントは、Linux DVB APIに準拠したハイレベルCI APIについて説明しています。

ハイレベルCIアプローチでは、ほぼ任意のアーキテクチャを持つ新しいカードもこのスタイルで実装可能であり、switch文内の定義はどのカードにも簡単に適応できるため、追加のioctlは必要ありません。

デメリットはドライバ/ハードウェアが残りの処理を管理しなければならないことです。アプリケーションプログラマにとっては、Linux DVB APIに定義されたCI ioctlsを介して配列を送受信するだけです。この機能のためにAPIは変更されていません。

4.3.1. なぜ別のCIインターフェースが必要なのか？¶

これは最もよく質問される質問の一つです。良い質問ですね。厳密にはこれは新しいインターフェースではありません。

CIインターフェースはDVB APIのca.hで以下のように定義されています：

typedef struct ca_slot_info {
        int num;               /* slot number */

        int type;              /* CA interface this slot supports */
#define CA_CI            1     /* CI high level interface */
#define CA_CI_LINK       2     /* CI link layer level interface */
#define CA_CI_PHYS       4     /* CI physical layer level interface */
#define CA_DESCR         8     /* built-in descrambler */
#define CA_SC          128     /* simple smart card interface */

        unsigned int flags;
#define CA_CI_MODULE_PRESENT 1 /* module (or card) inserted */
#define CA_CI_MODULE_READY   2
} ca_slot_info_t;

このCIインターフェースはハイレベルCIインターフェースに従っており、ほとんどのアプリケーションでは実装されていません。そのためこの分野が再検討されています。

このCIインターフェースは、他のカテゴリに属するすべてのCIベースデバイスをサポートしようとする点で大きく異なります。

これは、アプリケーション層でのみEN50221スタイルのタグを処理し、セッション管理はアプリケーションで行う必要はありません。ドライバ/ハードウェアがすべての処理を行います。

このインターフェースは純粋にEN50221インターフェースであり、APDUを交換します。これは、アプリケーションとドライバ間の通信においてセッション管理、リンクレイヤー、トランスポートレイヤーが存在しないことを意味します。これ以上はありません。ドライバ/ハードウェアがすべての処理を行います。

このハイレベルCIインターフェースでは、通常のioctlsでインターフェースを定義できます。

これらのすべてのioctlsはハイレベルCIインターフェースにも有効です

#define CA_RESET _IO(‘o’, 128) #define CA_GET_CAP _IOR(‘o’, 129, ca_caps_t) #define CA_GET_SLOT_INFO _IOR(‘o’, 130, ca_slot_info_t) #define CA_GET_DESCR_INFO _IOR(‘o’, 131, ca_descr_info_t) #define CA_GET_MSG _IOR(‘o’, 132, ca_msg_t) #define CA_SEND_MSG _IOW(‘o’, 133, ca_msg_t) #define CA_SET_DESCR _IOW(‘o’, 134, ca_descr_t)

デバイスを照会すると、以下のように情報を提供します：

CA_GET_SLOT_INFO
----------------------------
Command = [info]
APP: Number=[1]
APP: Type=[1]
APP: flags=[1]
APP: CI High level interface
APP: CA/CI Module Present

CA_GET_CAP
----------------------------
Command = [caps]
APP: Slots=[1]
APP: Type=[1]
APP: Descrambler keys=[16]
APP: Type=[1]

CA_SEND_MSG
----------------------------
Descriptors(Program Level)=[ 09 06 06 04 05 50 ff f1]
Found CA descriptor @ program level

(20) ES type=[2] ES pid=[201]  ES length =[0 (0x0)]
(25) ES type=[4] ES pid=[301]  ES length =[0 (0x0)]
ca_message length is 25 (0x19) bytes
EN50221 CA MSG=[ 9f 80 32 19 03 01 2d d1 f0 08 01 09 06 06 04 05 50 ff f1 02 e0 c9 00 00 04 e1 2d 00 00]

ドライバではAPIからすべてのioctlsが実装されていないため、APIでは実装できないハードウェアの他の機能はCA_GET_MSGとCA_SEND_MSG ioctlsを使用して実現されます。他のハードウェアとの互換性を維持するためにEN50221スタイルのラッパーが使用されます。

/* a message to/from a CI-CAM */
typedef struct ca_msg {
        unsigned int index;
        unsigned int type;
        unsigned int length;
        unsigned char msg[256];
} ca_msg_t;

データの流れは以下のようになります,

     App (User)
     -----
     parse
       |
       |
       v
     en50221 APDU (package)
--------------------------------------
|      |                             | High Level CI driver
|      |                             |
|      v                             |
|    en50221 APDU (unpackage)        |
|      |                             |
|      |                             |
|      v                             |
|    sanity checks                   |
|      |                             |
|      |                             |
|      v                             |
|    do (H/W dep)                    |
--------------------------------------
       |    Hardware
       |
       v

High Level CIインターフェースはEN50221 DVB標準を採用しており、標準を採用することで将来への耐性が確保されます。
