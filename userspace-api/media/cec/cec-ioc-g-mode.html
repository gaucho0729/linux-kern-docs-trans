2.10. ioctls CEC_G_MODE および CEC_S_MODE¶

CEC_G_MODE, CEC_S_MODE - 排他的にCECアダプターを使用するための取得または設定

2.10.1. 概要¶

CEC_G_MODE¶

int ioctl(int fd, CEC_G_MODE, __u32 *argp)

CEC_S_MODE¶

int ioctl(int fd, CEC_S_MODE, __u32 *argp)

2.10.2. 引数¶

fd

返されるファイル記述子 open().

argp

CECモードへのポインタ。

2.10.3. 説明¶

デフォルトでは、任意のファイルハンドルが ioctls CEC_RECEIVEおよびCEC_TRANSMITを使用できますが、アプリケーション同士が競合しないようにするため、CECアダプターへの排他アクセスを取得する必要があります。このioctlはファイルハンドルを送信者および/または受信者モードに設定し、選択されたモードによって排他性が決まります。送信者はメッセージを開始するファイルハンドルであり、他のCECデバイスにコマンドを送信します。受信者はCECアダプターに送信されたメッセージを受信し、処理します。同じファイルハンドルが送信者と受信者双方の役割を担うことも、または2つの異なるファイルハンドルがそれぞれ役割を担うこともできます。CECメッセージが受信された場合、CECフレームワークがどのように処理するかを決定します。メッセージが以前に送信されたメッセージへの応答である場合、応答はそのメッセージを待っているファイルハンドルに送信されます。また、フレームワークがそのメッセージを処理します。

メッセージが応答でない場合、CECフレームワークがまず処理します。受信者がいない場合、メッセージは無視され、フレームワークが処理できなかった場合は、送信者にフィーチャーアボートが送信されます。受信者がいる場合、メッセージは受信者に渡され、受信者が

利用可能な送信者モードは以下の通りです：

送信者モード¶

CEC_MODE_NO_INITIATOR

0x0

送信者ではありません。つまり、CECメッセージを送信したり、CECアダプターの変更を実行したりできません。

CEC_MODE_INITIATOR

0x1

送信者（デバイスが開かれた際のデフォルト）であり、CECメッセージを送信したり、CECアダプターの変更を実行したりできます（排他的な送信者がいる場合を除く）

CEC_MODE_EXCL_INITIATOR

0x2

これは排他起動者であり、このファイル記述子はCECメッセージを送信し、CECアダプターの設定を変更できる唯一のものです。他のユーザーがすでに排他起動者である場合、起動者になる試みはエラー コードを返します。 EBUSY エラー コード エラー。

フォロワー モード¶

CEC_MODE_NO_FOLLOWER

0x00

フォロワーではありません（デバイスが開かれた際のデフォルト状態）。

CEC_MODE_FOLLOWER

0x10

フォロワーであり、CECメッセージを受信します（排他フォロワーが存在する場合は除く）。以下の条件がある場合、フォロワーになることはできません CEC_CAP_TRANSMIT が設定されていないか、もしくは CEC_MODE_NO_INITIATOR が指定された場合、その場合は EINVAL エラー コードが返されます。

CEC_MODE_EXCL_FOLLOWER

0x20

これは排他的フォロワーであり、このファイル記述子だけがCECメッセージを受信して処理します。他の誰かがすでに排他的フォロワーである場合、フォロワーになる試みは EBUSY エラー コードを返します。 CEC_CAP_TRANSMIT が設定されていないか、もしくは CEC_MODE_NO_INITIATOR が指定された場合、その場合は EINVAL エラー コードが返されます。

CEC_MODE_EXCL_FOLLOWER_PASSTHRU

0x30

これは排他的フォロワーであり、このファイル記述子だけがCECメッセージを受信して処理します。さらに、CECデバイスを透過モードに設定し、排他的フォロワーがほとんどのコアメッセージを処理できるようにします（CECフレームワークに依存せず）。他の誰かがすでに排他的フォロワーである場合、フォロワーになる試みは EBUSY エラー コードを返します。 CEC_CAP_TRANSMIT が設定されていないか、もしくは CEC_MODE_NO_INITIATOR が指定された場合、その場合は EINVAL エラー コードが返されます。

受信者がいない場合、任意のCECファイルハンドルが¶

CEC_MSG_GET_CEC_VERSION

コアは、設定されたCECバージョンを返します ioctl CEC_ADAP_S_LOG_ADDRS、パススルー モードの場合は除きます。パススルー モードではコアは処理を行わず、このメッセージはフォロワーによって処理されます

コアは、設定されたベンダーIDを返します ioctl CEC_ADAP_S_LOG_ADDRS、パススルー モードの場合は除きます。パススルー モードではコアは処理を行わず、このメッセージはフォロワーによって処理されます

CEC_MSG_ABORT

コアは、仕様に従って「機能拒否」メッセージを返します。ただし、パススルー モードの場合は除きます。パススルー モードではコアは処理を行わず、このメッセージはフォロワーによって処理されます

CEC_MSG_GIVE_PHYSICAL_ADDR

コアは現在の物理アドレスを報告します。ただし、パススルー モードの場合は除きます。パススルー モードではコアは処理を行わず、このメッセージはフォロワーによって処理されます

CEC_MSG_GIVE_OSD_NAME

コアは現在のOSD名を報告します。ただし、パススルー モードの場合は除きます。パススルー モードではコアは処理を行わず、このメッセージはフォロワーによって処理されます ioctl CEC_ADAP_S_LOG_ADDRS、パススルー モードの場合は除きます。パススルー モードではコアは処理を行わず、このメッセージはフォロワーによって処理されます

CEC_MSG_GIVE_FEATURES

CECバージョンが2.0未満の場合、コアは処理を行いません。それ以外の場合、設定された現在の機能を報告します ioctl CEC_ADAP_S_LOG_ADDRS、パススルー モードの場合は除きます。パススルー モードではコアは処理を行いません（すべてのCECバージョンにおいて）し、このメッセージはフォロワーによって処理されます

CEC_MSG_USER_CONTROL_PRESSED

もし CEC_CAP_RC が設定されており、 CEC_LOG_ADDRS_FL_ALLOW_RC_PASSTHRU が設定されている場合、リモコンキーの押下を生成します。このメッセージは常にフォロワーに転送されます

CEC_MSG_USER_CONTROL_RELEASED

もし CEC_CAP_RC が設定されており、 CEC_LOG_ADDRS_FL_ALLOW_RC_PASSTHRU が設定されている場合、リモコンキーの解放を生成します。このメッセージは常にフォロワーに転送されます

CEC_MSG_REPORT_PHYSICAL_ADDR

CECフレームワークは報告された物理アドレスを記録し、その後フォロワーにメッセージを転送します
