2.6. ioctls CEC_ADAP_G_LOG_ADDRS and CEC_ADAP_S_LOG_ADDRS¶

2.6.1. 名前¶

CEC_ADAP_G_LOG_ADDRS, CEC_ADAP_S_LOG_ADDRS - 論理アドレスの取得または設定

2.6.2. 概要¶

CEC_ADAP_G_LOG_ADDRS¶

int ioctl(int fd, CEC_ADAP_G_LOG_ADDRS, struct cec_log_addrs *argp)

CEC_ADAP_S_LOG_ADDRS¶

int ioctl(int fd, CEC_ADAP_S_LOG_ADDRS, struct cec_log_addrs *argp)

2.6.3. 引数¶

fd

返されるファイル記述子 open().

argp

struct mem_ctl_info cec_log_addrs.

2.6.4. 説明¶

現在のCEC論理アドレスを照会するには、アプリケーションはioctl CEC_ADAP_G_LOG_ADDRSを呼び出します ioctl CEC_ADAP_G_LOG_ADDRS structへのポインタを渡して cec_log_addrs ドライバが論理アドレスを保存する場所です

新しい論理アドレスを設定するには、アプリケーションはstruct cec_log_addrs を埋めます ioctl CEC_ADAP_S_LOG_ADDRS このstructへのポインタを渡して。The ioctl CEC_ADAP_S_LOG_ADDRS は、 CEC_CAP_LOG_ADDRS が設定されている場合（ ENOTTY エラーコードが返されます）。The ioctl CEC_ADAP_S_LOG_ADDRS は、起動機モードのファイル記述子によってのみ呼び出せます（参照 ioctls CEC_G_MODE および CEC_S_MODE）の場合、 EBUSY エラーコードが返されます

既存の論理アドレスをクリアするには、 num_log_addrs を0に設定します。その場合、他のすべてのフィールドは無視されます。アダプターは未設定状態に移行し、 cec_version, vendor_id および osd_name すべてのフィールドはデフォルト値（CECバージョン2.0、ベンダーアイデンティティなし、空のOSD名）に戻されます

物理アドレスが有効な場合（参照 ioctl CEC_ADAP_S_PHYS_ADDR）の場合、このioctlはすべての要求された論理アドレスが取得されるまでブロックします。ファイル記述子が非ブロッキングモードの場合、論理アドレスの取得を待たず、代わりに0を返します

A CEC_EVENT_STATE_CHANGE 論理アドレスが取得またはクリアされたときにこのイベントが送信されます

論理アドレスタイプがすでに定義されている場合にこのioctlを呼び出すと、 ioctl CEC_ADAP_S_LOG_ADDRS エラーが返されます EBUSY.

type cec_log_addrs¶
struct cec_log_addrs¶

__u8

log_addr[CEC_MAX_LOG_ADDRS]

実際に取得された論理アドレスです。ドライバが設定します。論理アドレスが取得できなかった場合、 CEC_LOG_ADDR_INVALID。このアダプターがUnregisteredの場合、 log_addr[0] は0xfに設定され、他のすべてが CEC_LOG_ADDR_INVALID.

__u16

log_addr_mask

このアダプターが取得したすべての論理アドレスのビットマスクです。このアダプターがUnregisteredの場合、 log_addr_mask はビット15を設定し、他のすべてのビットをクリアします。このアダプターがまったく設定されていない場合、 log_addr_mask は0に設定されます。ドライバが設定します

__u8

cec_version

このアダプターが使用するCECバージョンです。参照 CEC Versions。メッセージを実装するために使用されます。注意として、 CEC_MSG_CEC_VERSION および CEC_MSG_REPORT_FEATURES メッセージ。注意として、 CEC_OP_CEC_VERSION_1_3A はCECフレームワークによって許可されません

__u8

num_log_addrs

設定する論理アドレスの数。最大で available_log_addrs 返却される ioctl CEC_ADAP_G_CAPSこの構造体のすべての配列は、インデックス available_log_addrs-1までしか埋められず、それ以降の配列要素は無視されます。CEC 2.0標準では最大2つの論理アドレスが許容されていますが、一部のハードウェアではより多くのサポートがあります。 CEC_MAX_LOG_ADDRS これは4です。ドライバーは実際に取得可能な論理アドレス数を返しますが、これは要求された数より少ない場合があります。このフィールドを0に設定すると、CECアダプターはすべての取得した論理アドレスをクリアし、他のすべてのフィールドは無視されます。

__u32

vendor_id

ベンダーIDは特定のベンダーまたはエンティティを識別する24ビットの数です。このIDに基づいて、ベンダー固有のコマンドが定義されることがあります。ベンダーIDを設定したくない場合は、 CEC_VENDOR_ID_NONE.

__u32

flags

フラグ。参照 struct cec_log_addrsのフラグ 利用可能なフラグの一覧を参照してください。

char

osd_name[15]

On-Screen Display名は、 CEC_MSG_SET_OSD_NAME メッセージ。

__u8

primary_device_type[CEC_MAX_LOG_ADDRS]

各論理アドレスのプライマリデバイスタイプ。参照 CEC プライマリデバイスタイプ 可能なタイプを参照してください。

__u8

log_addr_type[CEC_MAX_LOG_ADDRS]

論理アドレスタイプ。参照: CEC 論理アドレスタイプ 可能なタイプについては。ドライバーは、実際に宣言した論理アドレスタイプでこれを更新します（例：fallback する必要がある場合、 CEC_LOG_ADDR_TYPE_UNREGISTERED).

__u8

all_device_types[CEC_MAX_LOG_ADDRS]

CEC 2.0 特有の：すべてのデバイスタイプのビットマスク。参照: CEC すべてのデバイスタイプ フラグこれはCEC 2.0で使用されます。 CEC_MSG_REPORT_FEATURES メッセージです。CEC 1.4の場合、このフィールドを0に残すか、CEC 2.0ガイドラインに従って入力することで、CECフレームワークにデバイスの種類に関するより多くの情報を提供できます。ただし、フレームワークはCECメッセージでこれを直接使用しません。

__u8

features[CEC_MAX_LOG_ADDRS][12]

各論理アドレスの機能です。これはCEC 2.0で使用されます。 CEC_MSG_REPORT_FEATURES メッセージです。12バイトはRCプロファイルとデバイス機能を含みます。CEC 1.4の場合、このフィールドをすべて0に残すか、CEC 2.0ガイドラインに従って入力することで、CECフレームワークにデバイスの種類に関するより多くの情報を提供できます。ただし、フレームワークはCECメッセージでこれを直接使用しません。
struct cec_log_addrsのフラグ¶

CEC_LOG_ADDRS_FL_ALLOW_UNREG_FALLBACK

1

デフォルトでは、要求されたタイプの論理アドレスが確保できない場合、未設定状態に戻ります。このフラグが設定されている場合、未登録論理アドレスにフォールバックします。注意点として、未登録論理アドレスが明示的に要求された場合、このフラグは効果を持ちません。

CEC_LOG_ADDRS_FL_ALLOW_RC_PASSTHRU

2

デフォルトでは、 CEC_MSG_USER_CONTROL_PRESSED および CEC_MSG_USER_CONTROL_RELEASED メッセージはフォロワー（存在すれば）にのみ転送されます。このフラグが設定されている場合、これらのメッセージはリモートコントロール入力サブシステムにも転送され、キーボード入力として表示されます。この機能は明示的に有効にする必要があります。CECをパスワード入力などに使用する場合、この機能を有効にしない方が望ましいです。

CEC_LOG_ADDRS_FL_CDC_ONLY

4

このフラグが設定されている場合、デバイスはCDC-Onlyです。CDC-Only CECデバイスは、CDCメッセージのみを処理できるCECデバイスです。

他のすべてのメッセージは無視されます。

2.6.5. 戻り値¶

成功した場合、0 が返されます。エラーの場合、-1 が返され、変数が適切に設定されます。 errno 一般的なエラーコードは、 汎用エラーコード 章。

以下の ioctl CEC_ADAP_S_LOG_ADDRS 次のエラーコードを返すことができます：

ENOTTY

以下の CEC_CAP_LOG_ADDRS キャピャビリティが設定されていないため、このioctlはサポートされていません。

EBUSY

CECアダプターが現在自己設定中であるか、すでに設定されており、 num_log_addrs がゼロでない、または別のファイルハンドルが排他的フォロワーまたはイニシエーターモードである、またはファイルハンドルがモード CEC_MODE_NO_INITIATOR.

EINVAL

structの内容 cec_log_addrs が無効な場合。
