OpenCAPI（Open Coherent Accelerator Processor Interface）¶

OpenCAPIはプロセッサとアクセラレータ間のインターフェースです。低遅延かつ高帯域幅を実現することを目指しています。仕様は OpenCAPI Consortium.

によって開発されています。アクセラレータ（FPGA、ASICなど）がホストメモリをバーチャルアドレスを用いてコヒーレントにアクセスできるようにし、OpenCAPIデバイスは自身のメモリをホストからもアクセス可能にします。

LinuxではOpenCAPIは「ocxl」として知られており、IBMのCAPIインターフェース（powerpc用ドライバ）の「cxl」という名前を避けるため、オープンでプロセッサに依存しない進化版として名付けられています。

ハイレベルな概観¶

OpenCAPIは物理リンク上に実装されるデータリンク層（DL）とトランザクション層（TL）を定義しています。DLとTLを実装したプロセッサやデバイスはメモリ共有を開始できます。

+-----------+                         +-------------+
|           |                         |             |
|           |                         | Accelerated |
| Processor |                         |  Function   |
|           |  +--------+             |    Unit     |  +--------+
|           |--| Memory |             |    (AFU)    |--| Memory |
|           |  +--------+             |             |  +--------+
+-----------+                         +-------------+
     |                                       |
+-----------+                         +-------------+
|    TL     |                         |    TLX      |
+-----------+                         +-------------+
     |                                       |
+-----------+                         +-------------+
|    DL     |                         |    DLX      |
+-----------+                         +-------------+
     |                                       |
     |                   PHY                 |
     +---------------------------------------+

デバイスの発見¶

OpenCAPIはデバイス上に実装されたPCIに似た構成空間を用います。そのためホストは構成空間を照会することでAFU（アクセラレータ機能ユニット）を発見できます。

LinuxにおけるOpenCAPIデバイスはPCIデバイスと同様に扱われます（いくつかの例外を除く）。ファームウェアはハードウェアをPCIリンクのように抽象化する必要があります。多くの既存のPCIインフラストラクチャが再利用されています：デバイスは標準的なPCI列挙中にスキャンされ、BARが割り当てられます。そのため「lspci」というコマンドを用いて利用可能なデバイスを確認できます。

構成空間は物理アダプター上に存在するAFU（複数可能）の情報を定義します。例えばその名前、サポートするメモリコンテキスト数、MMIO領域のサイズなどです。

MMIO¶

OpenCAPIは各AFUに対して2つのMMIO領域を定義しています：

  • 全体にわたるレジスタを含むグローバルMMIO領域。

  • 各コンテキストごとに固定サイズのペラプロセスMMIO領域。

AFU割込み¶

OpenCAPIはAFUがホストプロセスに割込みを送信する機能を備えています。これはトランザクション層で定義された「intrp_req」を通じて行われ、64ビットのオブジェクトハンドルで割込みを定義します。

ドライバはプロセスが割込みを割り当てて64ビットのオブジェクトハンドルを取得でき、AFUに渡すことができます。

キャラクタデバイス¶

ドライバは物理デバイス上の各AFUに対して1つのキャラクタデバイスを作成します。物理デバイスは複数の機能を持ち、各機能が複数のAFUを持つ場合があります。ただし現在のところ、テストは1つのAFUをエクスポートするデバイスに限定されています。

キャラクタデバイスは/dev/ocxl/に存在し、名前は/dev/ocxl/<AFU名>.<ロケーション>.<インデックス>の形式になります。

where <AFU name> は、AFU のコンフィギュレーションスペースに記録されている最大20文字の名前です。<location> はドライバによって追加され、システムに同一のOpenCAPIデバイスが複数インスタンス存在する場合にデバイスを区別するのに役立ちます。<index> も、デバイスが同一のAFUを複数搭載している極めて稀なケースにおいてAFUを区別するのに使用されます。

Sysfs クラス¶

AFUを表すデバイスに対してocxl クラスが追加されます。/sys/class/ocxl を参照してください。レイアウトの詳細は Documentation/ABI/testing/sysfs-class-ocxl に記載されています。

ユーザーAPI¶

open¶

AFUのコンフィギュレーションスペースに記録された定義に基づき、AFUは複数のメモリコンテキストと作業を行うことが可能であり、その場合、関連するキャラクターデバイスは異なるプロセスによって複数回オープンされることがあります。

ioctl¶

OCXL_IOCTL_ATTACH:

呼び出し元プロセスのメモリコンテキストをAFUにアタッチし、AFUがそのメモリにアクセスできるようにします。

OCXL_IOCTL_IRQ_ALLOC:

AFU割込みを割り当て、識別子を返します。

OCXL_IOCTL_IRQ_FREE:

以前に割り当てたAFU割込みを解放します。

OCXL_IOCTL_IRQ_SET_FD:

イベントfdをAFU割込みに関連付けることで、ユーザープロセスがAFUが割込みを送信したときに通知されるようにします。

OCXL_IOCTL_GET_METADATA:

カードから設定情報（MMIO領域のサイズ、AFUバージョン、現在のコンテキストのPASIDなど）を取得します。

OCXL_IOCTL_ENABLE_P9_WAIT:

AFUがユーザー空間のスレッドが実行している'wait'を起こすことを許可します。ユーザー空間に情報を返してAFUの設定を可能にします。注意：これはPOWER9でのみ利用可能です。

OCXL_IOCTL_GET_FEATURES:

ユーザー空間からOpenCAPIに影響を与えるCPUの機能を報告します。

mmap¶

プロセスはAFUとのやり取りのためにプロセスごとのMMIO領域をmmapできます。
