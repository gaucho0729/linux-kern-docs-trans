Human Interface Devicesのお手入れガイド¶

はじめに¶

通常の入力タイプのHIDデバイスに加えて、USBはヒューマンインターフェースデバイスプロトコルを、人間インターフェースではないが類似した通信ニーズを持つものにも使用しています。この例として特に重要なのは、電源デバイス（特に中断不能電源）と高級モニターのモニター制御です。

これらの多様な要件をサポートするため、Linux USBシステムはHIDイベントを2つの別々のインターフェースに提供しています：* 入力サブシステム（HIDイベントをキーボード、マウス、ジョイストickなどの通常の入力デバイスインターフェースおよび正規化されたイベントインターフェースに変換）と、 はじめに * hiddevインターフェース（比較的素のHIDイベントを提供）

デバイスによって生成されるHIDイベントのデータフローは以下のようになります：

usb.c ---> hid-core.c  ----> hid-input.c ----> [keyboard/mouse/joystick/event]
                        |
                        |
                         --> hiddev.c ----> POWER / MONITOR CONTROL

さらに、USB以外のサブシステム（他のサブシステム）も入力サブシステムにイベントを提供する可能性がありますが、これらはhidデバイスインターフェースに影響を与えません。

HIDデバイスインターフェースの使用方法¶

hiddevインターフェースは通常のUSBメジャーデバイスを使用するキャラクターデバイスインターフェースで、マイノル番号は96から111までです。そのため、以下のコマンドが必要です：

mknod /dev/usb/hiddev0 c 180 96
mknod /dev/usb/hiddev1 c 180 97
mknod /dev/usb/hiddev2 c 180 98
mknod /dev/usb/hiddev3 c 180 99
mknod /dev/usb/hiddev4 c 180 100
mknod /dev/usb/hiddev5 c 180 101
mknod /dev/usb/hiddev6 c 180 102
mknod /dev/usb/hiddev7 c 180 103
mknod /dev/usb/hiddev8 c 180 104
mknod /dev/usb/hiddev9 c 180 105
mknod /dev/usb/hiddev10 c 180 106
mknod /dev/usb/hiddev11 c 180 107
mknod /dev/usb/hiddev12 c 180 108
mknod /dev/usb/hiddev13 c 180 109
mknod /dev/usb/hiddev14 c 180 110
mknod /dev/usb/hiddev15 c 180 111

したがって、hiddev準拠のユーザー空間プログラムをデバイスの正しいインターフェースに指定すれば、すべてが正常に動作します。

もちろん、hiddev準拠のユーザー空間プログラムを持っている前提で話しています。プログラムを書く必要がある場合は、続きを読みましょう。

HIDDEV API¶

この説明は、以下のHID仕様と併せて読むと理解が深まります： https://www.usb.org、そして便利にリンクされています http://www.linux-usb.org.

hiddev APIはread()インターフェースと、一連のioctl()コールを使用します。

HIDデバイスは、ホストコンピュータとデータを交換する際、データバンドルとしての「レポート」を使用します。各レポートは「フィールド」に分割され、それぞれが1つまたは複数の「ユース」を持つことができます。hid-coreでは、これらのユースそれぞれに32ビット符号付き値が割り当てられます。

read():¶

これはイベントインターフェースです。HIDデバイスの状態が変化すると、割り込み転送を介してレポートが送信され、そのレポートには変化した値が含まれます。hid-core.cモジュールはレポートを解析し、hiddev.cにレポート内で変化した個々のユースを返します。基本モードでは、hiddevはこれらの個々のユース変化をstruct hiddev_eventを介して読み取り者に提供します：

struct hiddev_event {
    unsigned hid;
    signed int value;
};

ステータスが変更された HID 使用識別子と、変更後の値を含みます。構造体の定義は <linux/hiddev.h> 内に記述されており、他の有用な #defines と構造体も含まれています。HID 使用識別子は HID 使用ページを 16 ビットの上位にシフトしたものを、使用コードと OR したものです。read() 関数の挙動は、以下の HIDIOCSFLAG ioctl を使用して変更可能です。

ioctl():¶

これは制御インターフェースです。いくつかの制御項目があります：

HIDIOCGVERSION

  • int (読み取り)

hiddev ドライバからバージョンコードを取得します。

HIDIOCAPPLICATION

  • (なし)

この ioctl 呼び出しは、hid デバイスに関連する HID アプリケーション使用を取得します。ioctl() の第 3 引数は取得するアプリケーションインデックスを指定します。これはデバイスが複数のアプリケーションコレクションを持つ場合に役立ちます。インデックスが無効な場合（デバイスが持つアプリケーションコレクション数を超える場合）、ioctl は -1 を返します。事前にデバイスが持つアプリケーションコレクション数は、hiddev_devinfo 構造体の num_applications フィールドから確認できます。

HIDIOCGCOLLECTIONINFO

  • struct hiddev_collection_info (読み取り/書き込み)

これは上記の情報のサブセットを返します。アプリケーションコレクションだけでなく、デバイスが持つすべてのコレクションを提供し、コレクションが階層でどのレベルにあるかを返します。ユーザーは index フィールドを返すインデックスに設定した hiddev_collection_info 構造体を渡します。ioctl は他のフィールドを埋めます。インデックスが最後のコレクションインデックスより大きい場合、ioctl は -1 を返し、errno を -EINVAL に設定します。

HIDIOCGDEVINFO

  • struct hiddev_devinfo (読み取り)

デバイスを記述する hiddev_devinfo 構造体を取得します。

HIDIOCGSTRING

  • struct hiddev_string_descriptor (読み取り/書き込み)

デバイスから文字列デスクリプターを取得します。呼び出し元は「index」フィールドを埋めて、返すべきデスクリプターを指定します。

HIDIOCINITREPORT

  • (なし)

カーネルにデバイスからすべての入力および機能レポート値を取得するよう指示します。この時点で、すべての使用構造体にデバイスの現在値が含まれており、デバイスが変化するたびに維持されます。注意点として、この ioctl の使用は一般的には必要ありません。後続のカーネルでは、接続時にデバイスからレポートを自動的に初期化するためです。

HIDIOCGNAME

  • string (可変長)

デバイス名を取得します

HIDIOCGREPORT

  • struct hiddev_report_info (書き込み)

カーネルにデバイスから機能または入力レポートを取得するよう指示し、使用構造体を選択的に更新します（INITREPORTとは対照的です）。

HIDIOCSREPORT

  • struct hiddev_report_info (書き込み)

カーネルにデバイスにレポートを送信するよう指示します。このレポートは、HIDIOCSUSAGEコール（下記参照）を通じてユーザーが個々の使用値をレポートに記入し、その後デバイスに完全なレポートを送信する前に埋め込むことができます。

HIDIOCGREPORTINFO

  • struct hiddev_report_info (読み取り/書き込み)

ユーザーがhiddev_report_info構造体を埋め込みます。レポートはタイプ（入力、出力または機能）とIDで検索されるため、ユーザーがこれらのフィールドを埋め込む必要があります。IDは絶対値（デバイスが報告する実際のレポートID）か、相対値（HID_REPORT_ID_FIRSTで最初のレポート、および（HID_REPORT_ID_NEXT | report_id）でreport_idの次のレポート）のいずれかです。レポートIDに関する事前情報がない場合、このioctlを正しく使用するには、上記の相対IDを用いて有効なIDを列挙する必要があります。ioctlは次のIDが存在しない場合に非ゼロを返します。実際のレポートIDは返されたhiddev_report_info構造体に記録されます。

HIDIOCGFIELDINFO

  • struct hiddev_field_info (読み取り/書き込み)

hiddev_field_info構造体にレポートに関連するフィールド情報を返します。ユーザーはこの構造体にreport_idとreport_typeを埋め込む必要があります（上記と同様）。field_indexも埋め込む必要があります。これは、以前のHIDIOCGREPORTINFOコールから返されたmaxfield-1までの数値である必要があります。

HIDIOCGUCODE

  • struct hiddev_usage_ref (読み取り/書き込み)

hiddev_usage_ref構造体に使用コードを返します。この構造体にレポートタイプ、レポートID、フィールドインデックス、およびフィールド内のインデックスがすでに埋め込まれている前提で。

HIDIOCGUSAGE

  • struct hiddev_usage_ref (読み取り/書き込み)

hiddev_usage_ref構造体に使用値を返します。取得する使用を上記のように指定するか、ユーザーがreport_typeフィールドを埋め込み、report_idをHID_REPORT_ID_UNKNOWNに指定することもできます。この場合、使用が見つかった場合、hiddev_usage_refにレポートおよびフィールド情報が埋め込まれます。

HIDIOCSUSAGE

  • struct hiddev_usage_ref (書き込み)

出力レポート内の使用値を設定します。ユーザーは上記のようにhiddev_usage_ref構造体を埋め込み、さらにvalueフィールドを埋め込みます。

HIDIOGCOLLECTIONINDEX

  • struct hiddev_usage_ref (書き込み)

この使用に関連するコレクションインデックスを返します。これは、コレクション階層での位置を示します。

HIDIOCGFLAG

  • int (読み取り)

HIDIOCSFLAG

  • int (書き込み)

これらの操作は、上記のread()呼び出しに影響を与えるモードフラグをそれぞれ検査し、置き換えます。フラグは以下の通りです:

HIDDEV_FLAG_UREF

  • read()呼び出しは現在、struct hiddev_usage_refをstruct hiddev_eventの代わりに返します。これはより大きな構造体ですが、デバイスのレポートに同じ使用コードを持つ複数の使用項目がある場合、このような曖昧さを解消するためのモードです。

HIDDEV_FLAG_REPORT

  • このフラグはHIDDEV_FLAG_UREFと併用する必要があります。このフラグが設定されている場合、デバイスがレポートを送信すると、read()にstruct hiddev_usage_refが返され、report_typeとreport_idが埋め込まれますが、field_indexはFIELD_INDEX_NONEに設定されます。これはデバイスがレポートを送信した際の追加の通知として機能します。
