HIDセンサーフレームワーク¶

HIDセンサーフレームワークは、センサーハブに接続されたセンサードライバーを実装するために必要なインターフェースを提供します。センサーハブはHIDデバイスであり、HID 1.12センサーアクセスの使用テーブルに準拠したレポート記述子を提供します。

HID 1.12「HIDセンサーアクセス」仕様からの説明: 「センサー用のHID使用の標準化は、センサーハードウェアベンダーがUSB境界で一貫したプラグアンドプレイインターフェースを提供することを許可（義務としない）します。これにより、一部のオペレーティングシステムがベンダー間で再利用可能な共通デバイスドライバーを組み込むことができ、ベンダー自身がドライバーを提供する必要がなくなる可能性があります。」

この仕様は、センサーの種類や個々のデータフィールドを記述する多くの使用IDを定義しています。各センサーは変動する数のデータフィールドを持つことができます。フィールドの長さと順序はレポート記述子で指定されます。例えば、レポート記述子の一部は以下のようになります:

   INPUT(1)[INPUT]
 ..
    Field(2)
      Physical(0020.0073)
      Usage(1)
        0020.045f
      Logical Minimum(-32767)
      Logical Maximum(32767)
      Report Size(8)
      Report Count(1)
      Report Offset(16)
      Flags(Variable Absolute)
..
..

レポートは「センサーページ（0x20）」に加速度計3D（0x73）が含まれていることを示しています。この加速度計3Dにはいくつかのフィールドがあります。例えば、フィールド2は運動強度（0x045f）で、論理最小値は-32767、論理最大値は3,2767です。フィールドの順序と各フィールドの長さは、入力イベントのRAWデータがこの形式を使用するため重要です。

ハードロックアップ検出器は、定期的に実行されるhrtimerによって生成される割込みでウォッチドッグタスクを起動します。ハードロックアップの検出には、「watchdog_thresh」（コンパイル時に初期化され、sysctlの同じ名前で設定可能）秒ごとにNMI perfイベントが生成されます。システム内のどのCPUもその間hrtimer割込みを受けていない場合、ハードロックアップ検出器（NMI perfイベントのハンドラ）がカーネル警告を生成するか、設定に応じてパニックを呼び出します。¶

この仕様は、データフィールドのセットが異なるさまざまな種類のセンサーを定義しています。異なるセンサー間で共通の入力イベントをユーザー空間アプリケーションに送信するのは困難です。例えば、加速度計はX、Y、Zデータを送信し、環境光センサーは照度データを送信します。そのため、実装には2つの部分があります:

  • コアHIDドライバー

  • 個別センサープロセッシング部分（センサードライバー）

コアドライバー¶

コアドライバーは（hid-sensor-hub）をHIDドライバーとして登録します。レポート記述子を解析し、すべてのセンサーを識別します。HID-SENSOR-xxxx（xxxxは仕様からの使用ID）という名前のMFDデバイスを追加します。

例:

HID-SENSOR-200073は3D加速度計ドライバーに登録されます。

したがって、この名前を持つドライバーが挿入されると、その関数のプローブルーチンが呼び出されます。したがって、加速度計処理ドライバーはこの名前で登録し、3D加速度計が検出された場合にプローブされます。

コアドライバーは、処理ドライバーが使用IDごとに登録し、イベントを取得するために使用できるAPIセットを提供します。また、入力/フィーチャー/出力レポートを取得および設定するパース関数も提供します。

個別センサープロセッシング部分（センサードライバー）¶

処理ドライバーは、コアドライバーが提供するインターフェースを使用してレポートを解析し、フィールドのインデックスやイベントを取得できます。このドライバーはIIOインターフェースを使用して、特定のセンサーの標準ABIを定義したインターフェースを活用できます。

コアドライバーインターフェース¶

コールバック構造:

Each processing driver can use this structure to set some callbacks.
      int (*suspend)(..): Callback when HID suspend is received
      int (*resume)(..): Callback when HID resume is received
      int (*capture_sample)(..): Capture a sample for one of its data fields
      int (*send_event)(..): One complete event is received which can have
                             multiple data fields.

登録関数:

int sensor_hub_register_callback(struct hid_sensor_hub_device *hsdev,
                      u32 usage_id,
                      struct hid_sensor_hub_callbacks *usage_callback):

使用IDに対してコールバックを登録します。コールバック関数はスリープを許可されません:

int sensor_hub_remove_callback(struct hid_sensor_hub_device *hsdev,
                      u32 usage_id):

使用IDに対してコールバックを削除します。

パース関数:

int sensor_hub_input_get_attribute_info(struct hid_sensor_hub_device *hsdev,
                      u8 type,
                      u32 usage_id, u32 attr_usage_id,
                      struct hid_sensor_hub_attribute_info *info);

処理ドライバーは、レポート記述子内で特定のフィールドを検索し、存在する場合、必要な情報を保存して個別にフィールドを設定または取得できるようにします。これらのインデックスにより、毎回検索する必要がなく、フィールドインデックスを取得して設定や取得できます。

フィーチャーレポートの設定:

int sensor_hub_set_feature(struct hid_sensor_hub_device *hsdev, u32 report_id,
                      u32 field_index, s32 value);

このインターフェースは、フィーチャーレポート内のフィールドの値を設定するために使用されます。例えば、report_intervalというフィールドがあり、sensor_hub_input_get_attribute_infoの呼び出しで解析されている場合、その個別フィールドを直接設定できます:

int sensor_hub_get_feature(struct hid_sensor_hub_device *hsdev, u32 report_id,
                      u32 field_index, s32 *value);

このインターフェースは、入力レポート内のフィールドの値を取得するために使用されます。例えば、report_intervalというフィールドがあり、sensor_hub_input_get_attribute_infoの呼び出しで解析されている場合、その個別フィールド値を直接取得できます:

int sensor_hub_input_attr_get_raw_value(struct hid_sensor_hub_device *hsdev,
                      u32 usage_id,
                      u32 attr_usage_id, u32 report_id);

入力レポートを通じて特定のフィールド値を取得するために使用されます。例えば加速度計がX軸の値を取得したい場合、X軸の使用IDを指定してこの関数を呼び出せます。HIDセンサーはイベントを提供するため、どのフィールドもポーリングする必要はありません。新しいサンプルが発生した場合、コアドライバーは登録されたコールバック関数を呼び出してサンプルを処理します。

HID カスタムおよび汎用センサー¶

HIDセンサー仕様では2つの特別なセンサー使用タイプが定義されています。これらは標準的なセンサーを表さないため、Linux IIOタイプインターフェースで定義することはできません。これらのセンサーの目的は、機能拡張を行うことや、センサーが通信するデータを暗号化する方法を提供することです。データとその封筒形式の間のマッピングが分からなければ、アプリケーションやドライバーはセンサーが通信するデータを特定するのが困難です。これにより、ベンダーがアプリケーションを提供するなど、異なるユースケースが可能になります。一般的なユースケースには、他のセンサーのデバッグや、キーボードの接続/切断やラップトップの開閉などのイベントの提供があります。

アプリケーションがこれらのセンサーを活用できるように、ここではsysfs属性グループ、属性およびmiscデバイスインターフェースを通じてエクスポートされています。

sysfs上での表現の例:

.
│   ├──  enable_sensor
│   │   ├── feature-0-200316
│   │   │   ├── feature-0-200316-maximum
│   │   │   ├── feature-0-200316-minimum
│   │   │   ├── feature-0-200316-name
│   │   │   ├── feature-0-200316-size
│   │   │   ├── feature-0-200316-unit-expo
│   │   │   ├── feature-0-200316-units
│   │   │   ├── feature-0-200316-value
│   │   ├── feature-1-200201
│   │   │   ├── feature-1-200201-maximum
│   │   │   ├── feature-1-200201-minimum
│   │   │   ├── feature-1-200201-name
│   │   │   ├── feature-1-200201-size
│   │   │   ├── feature-1-200201-unit-expo
│   │   │   ├── feature-1-200201-units
│   │   │   ├── feature-1-200201-value
│   │   ├── input-0-200201
│   │   │   ├── input-0-200201-maximum
│   │   │   ├── input-0-200201-minimum
│   │   │   ├── input-0-200201-name
│   │   │   ├── input-0-200201-size
│   │   │   ├── input-0-200201-unit-expo
│   │   │   ├── input-0-200201-units
│   │   │   ├── input-0-200201-value
│   │   ├── input-1-200202
│   │   │   ├── input-1-200202-maximum
│   │   │   ├── input-1-200202-minimum
│   │   │   ├── input-1-200202-name
│   │   │   ├── input-1-200202-size
│   │   │   ├── input-1-200202-unit-expo

│   │   │   ├── input-1-200202-value

ここには、4つのフィールド、2つの機能、2つの入力を持つカスタムセンサーがあります。各フィールドは属性のセットで表されます。"value"以外のすべてのフィールドは読み取り専用です。"value"フィールドは読み書き可能なフィールドです。

例:

/sys/bus/platform/devices/HID-SENSOR-2000e1.6.auto/feature-0-200316$ grep -r . *
feature-0-200316-maximum:6
feature-0-200316-minimum:0
feature-0-200316-name:property-reporting-state
feature-0-200316-size:1
feature-0-200316-unit-expo:0
feature-0-200316-units:25
feature-0-200316-value:1

このようなセンサーを有効にする方法は？¶

デフォルトではセンサーは電源をオフにできます。sysfs属性の"enable"を使用して有効化できます:

$ echo 1 > enable_sensor

有効化され電源がオンになると、HIDレポートを使用してセンサーが値を報告します。これらのレポートはmiscデバイスインターフェースを介してFIFO順にプッシュされます:

/dev$ tree | grep HID-SENSOR-2000e1.6.auto
│   │   │   ├── 10:53 -> ../HID-SENSOR-2000e1.6.auto
│   ├──  HID-SENSOR-2000e1.6.auto

各レポートはヘッダーにより前導される可変長です。このヘッダーは32ビットの使用ID、64ビットのタイムスタンプ、および32ビットのrawデータ長フィールドから構成されます。
