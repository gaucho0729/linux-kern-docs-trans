CFS帯域制御¶

[ このドキュメントは、SCHED_NORMAL 用の CPU バンド幅制御についてのみ説明しています。

SCHED_RT のケースは、以下に説明されています。 リアルタイムグループスケジューリング ]

CFS バンド幅制御は、CONFIG_FAIR_GROUP_SCHED の拡張機能であり、グループまたは階層に最大 CPU バンド幅を指定することが可能です。

グループのバンド幅は、クォータとペリオドを指定して設定されます。各ペリオド（マイクロ秒単位）内で、タスクグループに最大でクォータマイクロ秒の CPU 時間が割り当てられます。このクォータは、cgroup で実行可能になったスレッドごとに、各 CPU の run queues にスライスとして割り当てられます。クォータがすべて割り当てられると、追加のクォータ要求はスレッドを制限（スロットリング）します。スロットリングされたスレッドは、次のペリオドでクォータが補充されるまで実行されません。

グループの未割当クォータはグローバルに追跡され、各ペリオド境界で cfs_quota 単位に戻されます。スレッドがこのバンド幅を消費すると、需要に応じて CPU ローカルの「シロ」に転送されます。各更新で転送されるクォータ量は調整可能で、「スライス」として説明されます。

管理¶

クォータとペリオドは、cgroupfs を通じて cpu サブシステム内で管理されます。

cpu.cfs_quota_us: 1 ペリオド内の利用可能な実行時間の合計（マイクロ秒） cpu.cfs_period_us: ペリオドの長さ（マイクロ秒） cpu.stat: 制限統計をエクスポートします [以下で詳しく説明します]

デフォルト値は以下の通りです：

cpu.cfs_period_us=100ms
cpu.cfs_quota=-1

cpu.cfs_quota_us に -1 を設定すると、グループにバンド幅制限が適用されていないことになります。このようなグループは、制限されていないバンド幅グループと呼ばれます。これは、CFS の伝統的なワークコンサービング動作を表します。

任意の（有効な）正の値を設定すると、指定されたバンド幅制限が適用されます。クォータまたはペリオドの最小値は 1ms です。また、ペリオドの最大長は 1s です。バンド幅制限を階層的に使用する場合、追加の制限があります。詳しくは以下で説明します。

任意の負の値を cpu.cfs_quota_us に設定すると、バンド幅制限が解除され、グループが制限されていない状態に戻ります。

グループのバンド幅指定を更新すると、制限状態にある場合でも制限が解除されます。

システム全体の設定¶

効率を高めるため、グローバルプールとCPUローカルの「シロッコ」間でランタイムがバッチ処理形式で転送されます。これにより、大規模システムにおけるグローバルな会計負荷が大幅に軽減されます。このような更新が必要な際、各回に転送される量は「スライス」として記述されます。

これはprocfsを介して調整可能です:

/proc/sys/kernel/sched_cfs_bandwidth_slice_us (default=5ms)

スライス値を大きくすると転送オーバーヘッドが減少しますが、小さな値はより細かい消費量の制御を可能にします。

統計¶

グループの帯域幅統計は、cpu.statの3つのフィールドを通じてエクスポートされます。

cpu.stat:

  • nr_periods: 通過した実施間隔の数。

  • nr_throttled: グループが制限/制限された回数。

  • throttled_time: グループのエンティティが制限された合計時間（ナノ秒単位）。

このインターフェースは読み取り専用です。

階層的な考慮事項¶

インターフェースは、個々のエンティティの帯域幅が常に達成可能であることを強制します。つまり：max(c_i) <= C。ただし、集約されたケースにおけるオーバーサブスクリプションは明示的に許可され、階層内でワークコンサービング semantics を実現します:

例: Sum (c_i) は C を超える可能性があります

[ここで C は親の帯域幅、c_i はその子孫です]

グループが制限されるのは以下の2つの方法があります:

  1. 1つの期間内で自身のクォータを完全に消費する

  2. 親のクォータが期間内で完全に消費される

上記b)の場合、子孫がまだランタイムを残している場合でも、親のランタイムが更新されるまで使用を許可されません。

CFS帯域幅クォータの注意点¶

スライスがCPUに割り当てられると期限切れません。ただし、そのCPU上のすべてのスレッドが実行不可能になった場合、スライスのほぼすべて（1msを除く）がグローバルプールに戻されます。これはコンパイル時にmin_cfs_rq_runtime変数で設定され、グローバルロックへの競合を防ぐパフォーマンスチューニングです。

CPUローカルのスライスが期限切れることはないため、いくつかの特殊なケースが生じます。これらを理解しておく必要があります。

cgroup CPU制限アプリケーションでは、CPU制限がかかるため、この点は比較的無関係です。それらは自然に各期間にクォータの全量と各CPUローカルスライスの全量を消費するため、nr_periodsはnr_throttledとほぼ等しく、cpuacct.usageは各期間にcfs_quota_usとほぼ同じ速度で増加することが期待されます。

高スレッド化かつCPUバウンドでないアプリケーションにおいて、この非期限のニュアンスにより、タスクグループが各CPUで使用していないスライス分のクォータ制限を一時的に超えることが可能になります（通常は1つのCPUあたり最大1msまたはmin_cfs_rq_runtimeで定義された値）。このわずかなバーストは、以前の期間においてクォータが割り当てられていたが完全に使用されなかった、または返却されなかった場合にのみ適用されます。このバースト量はコア間で転送されません。その結果、このメカニズムは依然としてタスクグループのクォータ平均使用量を厳密に制限しますが、単一の期間よりも長い時間窓を考慮します。また、このメカニズムにより、各CPUあたりのバースト能力は最大1msに制限されます。これにより、高コア数マシンにおいてクォータ制限が小さい高スレッドアプリケーションのユーザー体験がより良く、予測可能になります。また、CPU使用量がクォータ未満の状態で同時に実行されるアプリケーションのスロットリングの傾向を排除します。別の言い方をすれば、スライスの未使用部分を期間を超えて有効にすることで、CPUローカルのシロが完全なスライス分のCPU時間を使わない場合にクォータを無駄に期限切れさせる可能性を減らしています。

CPUバウンドと非CPUバウンド・インタラクティブアプリケーションの相互作用も考慮する必要があります、特に単一コア使用率が100%に達した場合。これらのアプリケーションにそれぞれ半分のCPUコアを割り当て、同じCPU上でスケジューリングされた場合、理論上非CPUバウンドアプリケーションが特定の期間で1ms分の追加クォータを使用する可能性があり、これによりCPUバウンドアプリケーションがその分だけクォータを完全に使用できなくなることがあります。このような場合、CFSアルゴリズム（sched-design-CFS.rstを参照）がどちらのアプリケーションを実行するかを決定します。両方のアプリケーションは実行可能であり、残りのクォータを持つためです。この実行時間の差は、次の期間にインタラクティブアプリケーションがアイドル状態になることで補われます。

例¶

  1. グループを1つのCPU分の実行時間に制限する:

    If period is 250ms and quota is also 250ms, the group will get
1 CPU worth of runtime every 250ms.

# echo 250000 > cpu.cfs_quota_us /* quota = 250ms */
# echo 250000 > cpu.cfs_period_us /* period = 250ms */

  2. マルチCPUマシンでグループを2つのCPU分の実行時間に制限する

    500msの周期と1000msのクォータで、グループは500msごとに2つのCPU分の実行時間を取得できます:

    # echo 1000000 > cpu.cfs_quota_us /* quota = 1000ms */
# echo 500000 > cpu.cfs_period_us /* period = 500ms */

The larger period here allows for increased burst capacity.

  3. グループを1つのCPUの20%に制限する。

    50msの周期で、10msのクォータは1つのCPUの20%に相当します:

    # echo 10000 > cpu.cfs_quota_us /* quota = 10ms */
# echo 50000 > cpu.cfs_period_us /* period = 50ms */

    ここでは小さな周期を使用することで、バースト容量を犠牲にした代わりに一貫したレイテンシー応答を確保しています。
