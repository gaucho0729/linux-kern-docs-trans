S390 デバッグ機能¶

ファイル:

  • arch/s390/kernel/debug.c

  • arch/s390/include/asm/debug.h

説明:¶

この機能の目的は、ログレコードをメモリ内で効率的に保存できるカーネルデバッグログ記録APIを提供することです。各コンポーネント（例：デバイスドライバ）が個別のデバッグログを持つことで、生産環境でのシステムクラッシュ後にデバッグログを検証し、クラッシュの原因を分析することが可能になります。

システムがまだ動作しているが、一部のサブコンポーネント（dbfを使用している）のみが失敗した場合、Linux debugfsファイルシステムを介してライブシステムでデバッグログを確認できます。

このデバッグ機能は、カーネルおよびドライバ開発においても非常に有用です。

設計:¶

カーネルコンポーネント（例：デバイスドライバ）は、関数呼び出し debug_register(). この関数は呼び出し元のデバッグログを初期化します。各デバッグログには複数のデバッグエリアがあり、同時に1つのエリアのみが有効です。各デバッグエリアはメモリ内の連続するページから構成され、イベントや例外呼び出しが行われた際にデバッグエントリ（ログレコード）が記録されます。

イベント呼び出しは、アクティブなデバッグエリアに指定されたデバッグエントリを書き込み、アクティブなエリアのログポインタを更新します。アクティブなデバッグエリアの終端に達した場合、リングバッファのように巻き戻して、アクティブなエリアの先頭に次のデバッグエントリを書き込みます。

例外呼び出しは、指定されたデバッグエントリをログに書き込み、次のデバッグエリアに切り替えます。これにより、現在のエリアで巻き戻し発生時に例外の発生原因を記録するレコードが上書きされることを防ぎます。

デバッグエリア自体もリングバッファ形式で順序付けられています。最後のデバッグエリアで例外が発生した場合、次のデバッグエントリは最初のエリアから再び書き込まれます。

イベントおよび例外呼び出しには4つのバージョンがあります：rawデータ用、テキスト用、数値（unsigned intおよびlong）用、sprintf形式の文字列用のそれぞれです。

各デバッグエントリには以下のデータが含まれます：

  • タイムスタンプ

  • 呼び出しタスクのCPU番号

  • デバッグエントリのレベル（0…6）

  • 呼び出し元への戻り先アドレス

  • エントリが例外かどうかを示すフラグ

デバッグログは、debugfsファイルシステム内のエントリを通じてライブシステムで確認できます。上位ディレクトリ「s390dbf」には、それぞれ登録されたコンポーネントに対応するディレクトリがあり、コンポーネント名と同様の名前が付けられます。debugfsは通常、 /sys/kernel/debug にマウントされるため、debug機能はこのパスを通じてアクセスできます /sys/kernel/debug/s390dbf.

ディレクトリの内容は、デバッグログに対するさまざまなビューを表すファイルです。各コンポーネントは、関数を通じてビューを登録することで、使用するビューを決定できます。 debug_register_view()hex/asciiおよびsprintfデータ用の事前定義されたビューが提供されています。他のビューも定義可能です。ビューの内容は、対応するdebugfsファイルを読み込むだけで確認できます。

すべてのデバッグログには実際のデバッグレベル（0〜6の範囲）があります。デフォルトのレベルは3です。イベントおよび例外関数にはパラメータがあります。 level レベルが実際のレベル以下であるデバッグエントリのみログに記録されます。これは、イベントを記録する際、高優先度のログエントリには低レベル値、低優先度のエントリには高レベル値を割り当てる必要があります。実際のデバッグレベルは、debugfsファイルシステムを介して、debugfsファイルに数値文字列「x」を書き込むことで変更できます。 level debugfsファイルに「-」を書き込むことでデバッグを完全に無効化できます。 level debugfsファイル。

例:

> echo "-" > /sys/kernel/debug/s390dbf/dasd/level

すべてのデバッグログのデバッグ機能をグローバルに無効化することも可能です。2つのsysctlパラメータを介して動作を変更できます。 /proc/sys/s390dbf:

現在、2つのトリガーがあり、これらはデバッグ機能をグローバルに停止します。最初の可能性はsysctlを使用することです。 debug_active 設定値が1の場合、デバッグ機能が有効になります。設定値が0の場合、デバッグ機能が無効になります。 debug_active sysctl。設定値が0の場合、デバッグ機能が無効になります。

2番目のデバッグ機能停止トリガーはカーネルoopsです。これにより、oops以前のデバッグ情報の上書きが防がれます。oops後には、1をパイプしてデバッグ機能を再有効化できます。ただし、oopsが発生したカーネルを本番環境で使用することは推奨されません。 /proc/sys/s390dbf/debug_activedebugfsファイル。

デバッグ機能の無効化を禁止したい場合は、sysctlを使用できます。設定値を0に設定すると、デバッグ機能の無効化が不可能になります。デバッグ機能がすでに無効化されている場合、その状態は維持されます。 debug_stoppable sysctl。設定値を0に設定すると、デバッグ機能の無効化が不可能になります。デバッグ機能がすでに無効化されている場合、その状態は維持されます。 debug_stoppable debugfsファイル。

事前定義されたビュー:¶

extern struct debug_view debug_hex_ascii_view;

extern struct debug_view debug_sprintf_view;

例¶

/*
 * hex_ascii-view Example
 */

#include <linux/init.h>
#include <asm/debug.h>

static debug_info_t *debug_info;

static int init(void)
{
    /* register 4 debug areas with one page each and 4 byte data field */

    debug_info = debug_register("test", 1, 4, 4 );
    debug_register_view(debug_info, &debug_hex_ascii_view);

    debug_text_event(debug_info, 4 , "one ");
    debug_int_exception(debug_info, 4, 4711);
    debug_event(debug_info, 3, &debug_info, 4);

    return 0;
}

static void cleanup(void)
{
    debug_unregister(debug_info);
}

module_init(init);
module_exit(cleanup);

/*
 * sprintf-view Example
 */

#include <linux/init.h>
#include <asm/debug.h>

static debug_info_t *debug_info;

static int init(void)
{
    /* register 4 debug areas with one page each and data field for */
    /* format string pointer + 2 varargs (= 3 * sizeof(long))       */

    debug_info = debug_register("test", 1, 4, sizeof(long) * 3);
    debug_register_view(debug_info, &debug_sprintf_view);

    debug_sprintf_event(debug_info, 2 , "first event in %s:%i\n",__FILE__,__LINE__);
    debug_sprintf_exception(debug_info, 1, "pointer to debug info: %p\n",&debug_info);

    return 0;
}

static void cleanup(void)
{
    debug_unregister(debug_info);
}

module_init(init);
module_exit(cleanup);

デバッグレベルの変更¶

例:

> cat /sys/kernel/debug/s390dbf/dasd/level
3
> echo "5" > /sys/kernel/debug/s390dbf/dasd/level
> cat /sys/kernel/debug/s390dbf/dasd/level
5

デバッグエリアのフラッシュ¶

デバッグエリアは、debugfsファイル「flush」に希望するエリアの番号（0…n）をパイプ処理することでフラッシュできます。'-'を指定するとすべてのデバッグエリアがフラッシュされます。

例:

  1. デバッグエリア0をフラッシュ:

    > echo "0" > /sys/kernel/debug/s390dbf/dasd/flush

  2. すべてのデバッグエリアをフラッシュ:

    > echo "-" > /sys/kernel/debug/s390dbf/dasd/flush

デバッグエリアのサイズ変更¶

デバッグエリアのサイズは、debugfsファイル「pages」にページ数をパイプ処理することで変更できます。リサイズリクエストはデバッグエリアのフラッシュも行います。

例:

debug機能「dasd」のデバッグエリアに4ページを設定:

> echo "4" > /sys/kernel/debug/s390dbf/dasd/pages

デバッグ機能の停止¶

例:

  1. 停止が許可されているか確認:

    > cat /proc/sys/s390dbf/debug_stoppable

  2. デバッグ機能を停止:

    > echo 0 > /proc/sys/s390dbf/debug_active

crashインターフェース¶

以下の crash v5.1.0以降のツールには、すべてのデバッグログを表示するかファイルシステムにエクスポートする組み込みコマンドがあります。 s390dbf これにより、ライブシステム上でデバッグログを調査し、システムクラッシュ後のメモリダンプでもデバッグログを確認できます。

rawメモリの調査¶

ライブシステム上でデバッグログを調査し、システムクラッシュ後のデバッグログを確認する最後の可能性は、VMやサービス要素でrawメモリを確認することです。デバッグログのアンカーは debug_area_first システムマップ内のシンボルを参照します。その後、debug.hで定義されたデータ構造の正しいポインタに従い、メモリ内のデバッグエリアを検索する必要があります。通常、デバッグ機能を使用するモジュールは、デバッグログへのポインタを示すグローバル変数をもつため、このポインタに従うことでメモリ内のデバッグログを検索することが可能です。

この方法では、データフィールドの長さとして「16 * x + 4」バイト（x = 0..n）を使用することをお勧めします。 debug_register() データフィールドを適切にフォーマットして表示するためには、この設定が必要です。

事前定義されたビュー¶

2つの事前定義されたビューがあります：hex_ascii と sprintf。hex_ascii ビューは、データフィールドを16進数とASCII表現で表示します（例： 45 43 4b 44 | ECKD).

sprintf ビューは、sprintf 関数が行うようにデバッグエントリをフォーマットします。sprintf イベント/例外関数は、デバッグエントリにフォーマット文字列へのポインタ（サイズ = sizeof(long)）を書き込み、各可変長引数（vararg）に対してlong値を記録します。したがって、フォーマット文字列と2つの可変長引数を持つデバッグエントリの場合、データ領域には（3 * sizeof(long)）バイトの領域を確保する必要があります。 debug_register() function.

重要:

sprintf イベント関数で「%s」を使用することは危険です。デバッグ機能が存在する間、渡された文字列のメモリが確保されている場合に限り「%s」を使用できます。これはパフォーマンスの観点から、デバッグ機能に文字列へのポインタのみが保存されるためです。その後文字列が解放された場合、デバッグ機能を検査する際にOOPSが発生します。これはすでに解放されたメモリを参照するためです。

ノート:

sprintf ビューを使用する際は、sprintf イベントおよび例外関数以外のイベント/例外関数を使用しないでください。

hex_ascii および sprintf ビューのフォーマットは以下の通りです：

  • エリア数

  • タイムスタンプ（1970年1月1日00:00:00協定世界時(UTC)からの秒数とマイクロ秒数でフォーマット済み）

  • デバッグエントリのレベル

  • 例外フラグ (* = 例外)

  • 呼び出しタスクのCPU番号

  • 呼び出し元への戻り先アドレス

  • データフィールド

hex_ascii ビューの典型的な行は以下のようになります（最初の行は説明用であり、'cating' ビューを表示する際には表示されません）：

area  time           level exception cpu caller    data (hex + ascii)
--------------------------------------------------------------------------
00    00964419409:440690 1 -         00  88023fe

ビューの定義¶

ビューは「debug_view」構造体で指定されます。デバッグfsファイルを読み書きするためのコールバック関数が定義されています：

struct debug_view {
      char name[DEBUG_MAX_PROCF_LEN];
      debug_prolog_proc_t* prolog_proc;
      debug_header_proc_t* header_proc;
      debug_format_proc_t* format_proc;
      debug_input_proc_t*  input_proc;
      void*                private_data;
};

where:

typedef int (debug_header_proc_t) (debug_info_t* id,
                                   struct debug_view* view,
                                   int area,
                                   debug_entry_t* entry,
                                   char* out_buf);

typedef int (debug_format_proc_t) (debug_info_t* id,
                                   struct debug_view* view, char* out_buf,
                                   const char* in_buf);
typedef int (debug_prolog_proc_t) (debug_info_t* id,
                                   struct debug_view* view,
                                   char* out_buf);
typedef int (debug_input_proc_t) (debug_info_t* id,
                                  struct debug_view* view,
                                  struct file* file, const char* user_buf,
                                  size_t in_buf_size, loff_t* offset);

「private_data」メンバは、ビュー固有のデータへのポインタとして使用できます。これはデバッグ機能自体では使用されません。

デバッグfsファイルを読み込む際の出力は以下のようになります：

"prolog_proc output"

"header_proc output 1"  "format_proc output 1"
"header_proc output 2"  "format_proc output 2"
"header_proc output 3"  "format_proc output 3"
...

debugfsからビューが読み取られる際、Debug Featureはプロローグの書き込みのために‘prolog_proc’を1回呼び出します。その後、既存のデバッグエントリごとに‘header_proc’と‘format_proc’が呼び出されます。

input_procは、ビューに書き込まれる際に機能を実装するために使用できます（例： echo "0" > /sys/kernel/debug/s390dbf/dasd/level).

header_procにはデフォルト関数を使用できます debug_dflt_header_fn() debug.hで定義されており、予定されたビューと同じヘッダー出力結果を生成します。例:

00 00964419409:440761 2 - 00 88023ec

コールバック関数の使用方法を確認するには、デフォルトビューの実装を確認してください！

例:

#include <asm/debug.h>

#define UNKNOWNSTR "data: %08x"

const char* messages[] =
{"This error...........\n",
 "That error...........\n",
 "Problem..............\n",
 "Something went wrong.\n",
 "Everything ok........\n",
 NULL
};

static int debug_test_format_fn(
   debug_info_t *id, struct debug_view *view,
   char *out_buf, const char *in_buf
)
{
  int i, rc = 0;

  if (id->buf_size >= 4) {
     int msg_nr = *((int*)in_buf);
     if (msg_nr < sizeof(messages) / sizeof(char*) - 1)
        rc += sprintf(out_buf, "%s", messages[msg_nr]);
     else
        rc += sprintf(out_buf, UNKNOWNSTR, msg_nr);
  }
  return rc;
}

struct debug_view debug_test_view = {
  "myview",                 /* name of view */
  NULL,                     /* no prolog */
  &debug_dflt_header_fn,    /* default header for each entry */
  &debug_test_format_fn,    /* our own format function */
  NULL,                     /* no input function */
  NULL                      /* no private data */
};
