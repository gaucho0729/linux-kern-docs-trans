z/VM モニターレコードへの読み取りアクセス用 Linux API¶

日付: 2004年11月26日

著者: Gerald Schaefer (geraldsc@de.ibm.com)

説明¶

この項目は、ユーザー空間から利用可能で、z/VM モニターレコードの読み取りアクセスを可能にする新しい Linux API を提供します。 *MONITOR z/VM のシステムサービス。

ユーザー要件¶

この API にアクセスしたい z/VM ゲストは、IUCV 接続をサービスに許可するため、設定が必要です。 *MONITOR サービス、つまり、IUCV が必要です。 *MONITOR ユーザーエントリに IUCV ステートメントが必要です。使用するモニターディスカッションセグメント（DCSS）が制限されている場合（おそらくそうですが）、NAMESAVE <DCSS NAME> ステートメントも必要です。この項目は IUCV デバイスドライバーを使用して z/VM サービスにアクセスしますので、IUCV サポートを持つカーネルが必要です。また、z/VM のバージョン 4.4 または 5.1 が必要です。

モニターディスカッションセグメント（DCSS）をロードできる2つのオプションがあります（例では DCSS が144 MB から152 MB まで開始および終了していると仮定しています）。モニターディスカッションセグメントの場所を照会するには、Class E 特権 CP コマンド Q NSS MAP を使用します（BEGPAG と ENDPAG の値は 4K ページ単位で提供されます）。

関連情報: 「CP コマンドおよびユーティリティリファレンス」(SC24-6081-00) で DEF STOR および Q NSS MAP コマンドについて、また 「Saved Segments プランニングおよび管理」(SC24-6116-00) で DCSS について詳しく説明しています。

1番目のオプション:¶

CP コマンド DEF STOR CONFIG を使用して、DCSS のアドレス範囲周辺にゲスト仮想ストレージ内の「メモリの穴」を定義できます。

例: DEF STOR CONFIG 0.140M 200M.200M

これにより、2つのストレージブロックが定義されます。1つ目は0MB から開始し、140MB のサイズ、2つ目は200MB から開始し、200MB のサイズで、合計ストレージは340MB になります。注意: 最初のブロックは常に0MB から開始し、64MB 以上である必要があります。

2番目のオプション:¶

ゲスト仮想ストレージは DCSS の開始アドレスよりも下に終了し、parmfile に「mem=」カーネルパラメータを指定し、DCSS の終了アドレスよりも大きい値を設定する必要があります。

例:

DEF STOR 140M

これにより、ゲストのストレージサイズは140MB になります。parmfile に「mem=160M」パラメータが追加されます。

ユーザーインターフェース¶

キャラクターデバイスは、「monreader」という名前のカーネルモジュールとして実装されており、modprobe コマンドでロードできます。または、カーネルに組み込むこともできます。オプションのモジュール（またはカーネル）パラメータとして、「mondcss」があり、モニターディスカッションセグメント（DCSS）の名前を指定します。モジュールがカーネルに組み込まれている場合、parmfile に「monreader.mondcss=<DCSS NAME>」というカーネルパラメータを指定できます。

指定されていない場合、DCSSのデフォルト名は「MONDCSS」です。既に他のユーザーがサービス（例：Performance Toolkit）に接続されている場合、モニタ用DCSSはすでに定義されており、同じDCSSを使用する必要があります。 *MONITOR CPコマンド Q MONITOR（Class E権限）は、すでに定義されているモニタ用DCSSの名前と、接続されているユーザーを表示します。サービスに関する詳細については、「z/VM Performance」（SC24-6109-00）を参照してください。 *MONITOR z/VMにモニタ用DCSSがまだない場合、作成方法を確認してください。DCSSを定義および保存するにはClass E権限が必要です。

例:¶

modprobe monreader mondcss=MYDCSS

このコマンドはモジュールをロードし、DCSS名を「MYDCSS」に設定します。

ノート:¶

このAPIは、サービスを制御するインターフェースを提供していません。例えば、収集するデータを指定するなど。 *MONITOR これはCPコマンド MONITOR（Class E権限）で実行できます。詳しくは「CPコマンドおよびユーティリティリファレンス」を参照してください。

udevで管理されるデバイスノード:¶

モジュールをロードした後、キャラクタデバイスが作成され、デバイスノード/<udevディレクトリ>/monreaderも同時に作成されます。

udevをサポートしていない場合のデバイスノード:¶

お使いのディストリビューションがudevをサポートしていない場合、デバイスノードが自動的に作成されず、モジュールをロードした後で手動で作成する必要があります。そのため、デバイスの主装置番号と補助装置番号を把握する必要があります。これらの番号は/sys/class/misc/monreader/devにあります。

cat /sys/class/misc/monreader/devを実行すると、<主装置番号>:<補助装置番号>という形式で出力されます。デバイスノードはmknodコマンドで作成可能です。mknod <name> c <主装置番号> <補助装置番号>と入力してください。ここで<name>は作成するデバイスノードの名前です。

例:¶

# modprobe monreader
# cat /sys/class/misc/monreader/dev
10:63
# mknod /dev/monreader c 10 63

このコマンドはデフォルトのモニタDCSS（MONDCSS）でモジュールをロードし、デバイスノードを生成します。

ファイル操作:¶

サポートされるファイル操作はopen、release、read、pollです。読み込みには2つの代替方法があります：ポーリングを併用したノンブロッキング読み込み、またはポーリングなしのブロッキング読み込み。IOCTLはサポートされていません。

読み込み:¶

デバイスから読み取る際には、12バイトのモニタ制御要素（MCE）が提供され、その後に1つまたは複数の連続するモニタ記録のセット（CMSユーティリティのMONWRITE出力と同様ですが、4K制御ブロックは除く）が続きます。MCEには、次の記録セットの種類（サンプル/イベントデータ）、含まれるモニタドメイン、およびモニタDCSS内の記録セットの開始アドレスと終了アドレスに関する情報が含まれます。開始アドレスと終了アドレスは、記録セットのサイズを決定するために使用でき、終了アドレスはデータの最後のバイトのアドレスを示します。開始アドレスは、「フレーム終端」記録（ドメイン1、記録13）を正しく処理するために必要であり、4Kページ（フレーム）境界に対する記録開始オフセットを決定するために使用できます。

「z/VM Performance」ドキュメントの「付録A:」 *MONITORを参照してください。モニタ制御要素のレイアウトについては、以下に記載されています（z/VM 5.1）： https://www.vm.ibm.com/pubs/mon510/index.html

monreaderデバイスから提供されるデータストリームのレイアウトは以下の通りです：

...
<0 byte read>
<first MCE>              \
<first set of records>    |
...                       |- data set
<last MCE>                |
<last set of records>    /
<0 byte read>
...

1つのデータセット内に複数のMCEと対応する記録セットの組み合わせが存在する可能性があり、各データセットの終わりは0バイト読み込みで成功した読み込みが示されます（返却値0）。未完成のデータは、完全なセットが成功して読み込まれるまで無効とみなされるため、データ処理を行う前に常に完全なセットをバッファに読み込む必要があります。

データセットの最大サイズはモニタDCSSのサイズに達するため、バッファを十分に設計するか、動的メモリ割り当てを使用してください。モニタDCSSのサイズはモジュールをロード後にsyslogに表示されます。また、(Class E特権) CPコマンド Q NSS MAP を使用して、すべてのセグメントとその情報の一覧を確認することもできます。

他の多くのキャラクタデバイスと同様に、エラー状態は読み込んだバイト数が負の値を返すことで示されます。この場合、errno変数がエラー状態を示します：

EIO:

応答失敗、読み込んだデータが無効であり、アプリケーションは最後の成功した読み込み（0サイズ）以降に読み込んだデータを破棄する必要があります。

EFAULT:

copy_to_userが失敗しました、読み込んだデータが無効であり、アプリケーションは最後の成功した読み込み（0サイズ）以降に読み込んだデータを破棄する必要があります。

EAGAIN:

非ブロッキング読み込み中にデータが利用できない場合に発生します。データが欠落しているわけではなく、ただ単に再度試してみるか、非ブロッキング読み込みにはポーリングを使用してください。

EOVERFLOW:

メッセージ制限が達成されました。最後の成功した読み取り以降に0サイズで読み取ったデータは有効ですが、その後のレコードが欠落している可能性があります。

最後のケース（EOVERFLOW）ではデータが欠落している可能性があります。最初の2つのケース（EIO、EFAULT）ではデータが確実に欠落しています。その後のデータの読み込みを継続するか、アプリケーションが終了するかはアプリケーション側の判断になります。

オープン:¶

キャラクタデバイスを開く際には1ユーザーのみが許可されています。既に使用中の場合、オープン関数は負の値を返してエラー（errnoがEBUSYに設定）となり、失敗します。IUCV接続が確立できない場合にもオープン関数は失敗します。この場合、errnoはEIOに設定され、syslogにIPUSER SEVERコードを含むエラーメッセージが表示されます。IPUSER SEVERコードについては『z/VM Performance』の付録Aに記載されています。 *MONITOR デバイスがオープンされた直後からインカムメッセージが受け付けられ、メッセージ制限にカウントされます。つまり、デバイスを開くだけで読み取らなかった場合、最終的に『メッセージ制限が達成されました』（EOVERFLOWエラー コード）のエラーが発生します。

ノート:¶

デバイスがオープンされた直後からインカムメッセージが受け付けられ、メッセージ制限にカウントされます。つまり、デバイスを開くだけで読み取らなかった場合、最終的に『メッセージ制限が達成されました』（EOVERFLOWエラー コード）のエラーが発生します。
