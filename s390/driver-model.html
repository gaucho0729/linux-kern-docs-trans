S/390ドライバモデルインターフェース¶

1. CCWデバイス¶

ccwでアドレス指定可能なすべてのデバイスは「CCWデバイス」と呼ばれます。実際にはccwで駆動されていない場合でも、このように呼ばれます。

すべてのCCWデバイスはサブチャネルを通じてアクセスされます。これはdevices/以下の構造体に反映されています。

devices/
   - system/
   - css0/
         - 0.0.0000/0.0.0815/
         - 0.0.0001/0.0.4711/
         - 0.0.0002/
         - 0.1.0000/0.1.1234/
         ...
         - defunct/

この例では、デバイス0815はサブチャネルセット0のサブチャネル0を通じてアクセスされ、デバイス4711はサブチャネルセット0のサブチャネル1を通じてアクセスされます。サブチャネル2は非I/Oサブチャネルです。デバイス1234はサブチャネルセット1のサブチャネル0を通じてアクセスされます。

「defunct」と名付けられたサブチャネルは、システム上の実際のサブチャネルを表していません。これは、他のCCWデバイスが以前のサブチャネルで動作を開始した際に、切断されたCCWデバイスが移動される仮想のサブチャネルです。それらのCCWデバイスが再びそのサブチャネルで動作を開始した場合、適切なサブチャネルに再び移動されます。

CCWデバイスはバスID（例: 0.0.4711）を通じてアドレス指定する必要があります。このデバイスはbus/ccw/devices/の下にあります。

すべてのCCWデバイスはsysfsを通じていくつかのデータをエクスポートします。

cutype:

制御ユニットのタイプ／モデル。

devtype:

デバイスのタイプ／モデル（必要に応じて）。

availability:

切断されたデバイスの場合、'good'または'boxed'、'no path'または'no device'のいずれかです。

online:

デバイスをオンラインおよびオフラインに設定するインターフェースです。デバイスが切断されている特別な場合（1.2節のnotify関数を参照）、オンラインに0をパイプすると強制的にデバイスを削除します。

デバイスドライバーは、各デバイスごとのデータとインターフェースをエクスポートするエントリを追加できます。

サブチャネルごとにデータがエクスポートされる場合もあります（bus/css/devices/を参照）：

chpids:

デバイスが接続されているchpids。

pimpampom:

インストールされたパス、利用可能なパス、運用中のパスのマスク。

さらにデータがある場合もあります。たとえばブロックデバイスの場合。

1.1 CCWデバイスの起動¶

これはいくつかのステップで行われます。

  1. 各ドライバーは、パラメータを指定できる1つまたは複数のパラメータインターフェースを提供できます。これらのインターフェースもドライバーの責任です。

  2. a.が実行された後、必要に応じて、デバイスは最後に‘online’インターフェースを通じて起動されます。

1.2 CCWデバイス用ドライバーの作成¶

The basic struct ccw_device および struct ccw_driver データ構造体はinclude/asm/ccwdev.hにあります：

struct ccw_device {
      spinlock_t *ccwlock;
      struct ccw_device_private *private;
      struct ccw_device_id id;

      struct ccw_driver *drv;
      struct device dev;
      int online;

      void (*handler) (struct ccw_device *dev, unsigned long intparm,
                       struct irb *irb);
};

struct ccw_driver {
      struct module *owner;
      struct ccw_device_id *ids;
      int (*probe) (struct ccw_device *);
      int (*remove) (struct ccw_device *);
      int (*set_online) (struct ccw_device *);
      int (*set_offline) (struct ccw_device *);
      int (*notify) (struct ccw_device *, int);
      struct device_driver driver;
      char *name;
};

‘private’フィールドには内部I/O操作に必要なデータのみが含まれており、デバイスドライバーには利用できません。

各ドライバーは、関心のあるCUタイプ／モデルおよび／またはデバイスタイプ／モデルをMODULE_DEVICE_TABLEに宣言する必要があります。この情報は後でstruct ccw_device_idフィールドに見つかります：

struct ccw_device_id {
      __u16   match_flags;

      __u16   cu_type;
      __u16   dev_type;
      __u8    cu_model;
      __u8    dev_model;

      unsigned long driver_info;
};

ccw_driver に含まれる関数は、以下の方法で使用する必要があります:

probe:

この関数は、ドライバが関心を持つ各デバイスに対してデバイスレイヤーが呼び出します。ドライバは、dev->driver_data に配置するプライベート構造体を割り当て、属性（必要に応じて）を作成する必要があります。また、割り込みハンドラ（以下参照）もここで設定する必要があります。

int (*probe) (struct ccw_device *cdev);
パラメータ:
cdev

  • プローブされるデバイス。

remove:

この関数は、ドライバ、デバイス、またはモジュールが削除されるときにデバイスレイヤーが呼び出します。ドライバはここでクリーンアップを行う必要があります。

int (*remove) (struct ccw_device *cdev);
パラメータ:
cdev

  • 削除されるデバイス。

set_online:

この関数は、共通I/Oレイヤーがデバイスを‘online’属性を通じてアクティブ化するときに呼び出されます。ドライバはここで最終的にデバイスを設定し、アクティブ化する必要があります。

int (*set_online) (struct ccw_device *);
パラメータ:
cdev

  • アクティブ化されるデバイス。共通レイヤーがデバイスがすでにオンラインでないことを確認しています。

set_offline: この関数は、共通I/Oレイヤーがデバイスを

‘online’属性を通じて非アクティブ化するときに呼び出されます。ドライバはデバイスをシャットダウンする必要がありますが、プライベートデータの解放は行わないでください。

int (*set_offline) (struct ccw_device *);
パラメータ:
cdev
  • 非アクティブ化されるデバイス。共通レイヤーが

    デバイスがオンラインであることを確認しています。

notify:

この関数は、共通I/Oレイヤーがデバイスの一部の状態変化を通知するときに呼び出されます。

ドライバに通知されるのは以下の通りです:

  • オンライン状態で、デバイスが接続解除（CIO_GONE）または最後のパスが失われた（CIO_NO_PATH）。ドライバは !0 を返してデバイスを保持する必要があります。返却コードが 0 の場合、通常通りデバイスが削除されます（notify ファンクションが登録されていない場合でも同様）。ドライバがデバイスを保持したい場合、デバイスは接続解除状態に移されます。

  • 接続解除状態で、デバイスが再び運用可能になった（CIO_OPER）。共通I/Oレイヤーはデバイス番号とデバイス/CUの組み合わせを検証し、それが同じデバイスであることを確認します。異なる場合、古いデバイスは削除され、新しいデバイスが登録されます。notify ファンクションの返却コードにより、ドライバがデバイスを再登録したいかどうかを示します：!0 で保持、0 でデバイスを削除して再登録します。

int (*notify) (struct ccw_device *, int);
パラメータ:
cdev

  • 状態が変化したデバイス。

イベント

  • 発生したイベント。これは CIO_GONE、CIO_NO_PATH または CIO_OPER のいずれかです。

notify ファンクションの handler フィールドの struct ccw_device このフィールドは、デバイスの割込みハンドラに設定される予定です。複数のハンドラを用いるドライバ（例：複数サブチャネルデバイス）をサポートするため、これはccw_deviceのメンバであり、ccw_driverではありません。ハンドラは、ドライバが呼ばれる前にset_online()処理中に共通レイヤーに登録され、ドライバが呼ばれた後にset_offline()処理中に解除されます。また、登録後／解除前には、パスグループのグループ化または解散（必要に応じて）が行われます。

void (*handler) (struct ccw_device *dev, unsigned long intparm, struct irb *irb);
パラメータ: dev - ハンドラが呼ばれるデバイス
intparm - デバイスドライバが割込みが関連するI/Oを識別するためのintparm

または割込みを非依頼型として認識するためのパラメータ

irb - 割込み応答ブロックで、集約された

ステータスを含みます。

デバイスドライバは共通ccw_deviceレイヤーから呼び出され、irbパラメータから割込みに関する情報を取得できます。

1.3 ccwgroupデバイス¶

ccwgroupメカニズムは、lcsやctcなどの複数のccwデバイスからなるデバイスを処理するために設計されています。

ccwドライバは「group」属性を提供します。ccwデバイスのバスIDをこの属性にパイプすると、これらのccwデバイス（可能であれば）からなるccwgroupデバイスが作成されます。このccwgroupデバイスは通常のccwデバイスと同様にオンラインまたはオフラインに設定できます。

各ccwgroupデバイスはまた、「ungroup」属性を提供してデバイスを再び破壊します（オフライン時のみ）。これは汎用的なccwgroupメカニズムであり（ドライバは通常の除去ルーチンを実装する以外に何の処理も必要ありません）。

ccwgroupデバイスのメンバーであるccwデバイスは、デバイス構造体のdriver_dataにccwgroupデバイスへのポインタを保持します。ドライバはこのフィールドを触ってはいけません。プライベートデータとしてccwgroupデバイスのdriver_dataを使用すべきです。

ccwgroupドライバを実装するには、include/asm/ccwgroup.hを参照してください。ほとんどのドライバはccwgroupとccwの両方を実装する必要があります。

2. チャネルパス¶

チャネルパスは、サブチャネル同様にチャネルサブシステムルート（css0）下に表示され、「chp0.<chpid>」と呼ばれます。ドライバはなく、どのバスにも属しません。注意してください。2.4の/proc/chpidsとは異なり、チャネルパスオブジェクトは物理的な状態ではなく論理的な状態のみを反映します。これは機械サポートの欠如により物理的な状態を一貫して追跡できなかったためです（実際には気にする必要もありません）。

status

  • オンラインまたはオフラインの状態を表します。'on'または'off'をパイプで渡すことで、chpidが論理的にオンライン/オフラインになります。オンラインのchpidに対して'on'をパイプすると、chpidが接続しているすべてのデバイスに対してパスの再検出が行われます。これにより、ユーザーがオンラインであることを知っているチャネルパスを強制的に再利用できるようになり、マシンがまだ機械チェックを行っていない場合でも、カーネルがそのチャネルパスを使用できるようになります。

type

  • チャネルパスの物理的なタイプ。

共有

  • チャネルパスが共有されているかどうか。

cmg

  • チャネル測定グループ。

3. システムデバイス¶

3.1 xpram¶

xpramはdevices/system/下に'xpram'として表示されます。

3.2 cpus¶

各CPUに対して、devices/system/cpu/下にディレクトリが作成されます。各CPUには'online'という属性があり、0または1の値を取ることができます。

4. その他のデバイス¶

4.1 Netiucv¶

netiucvドライバーは、bus/iucv/drivers/netiucv下に'connection'という属性を作成します。この属性にパイプを送ると、指定されたホストに対して新しいnetiucv接続が作成されます。

netiucv接続は、devices/iucv/下に「netiucv<ifnum>」として表示されます。インターフェース番号は、'connection'属性を通じて定義された接続に順番に割り当てられます。

user

  • 接続先のパートナーを示します。

バッファ

  • 最大バッファサイズ。これをパイプで送ることでバッファサイズを変更できます。
