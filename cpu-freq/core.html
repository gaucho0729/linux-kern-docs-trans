CPUFreqコアとCPUFreq通知者の一般説明¶

著者:

  • Dominik Brodowski <linux@brodo.de>

  • David Kimdon <dwhedon@debian.org>

  • Rafael J. Wysocki <rafael.j.wysocki@intel.com>

1. 一般情報¶

CPUFreqコアコードはdrivers/cpufreq/cpufreq.cに配置されています。このcpufreqコードは、CPUFreqアーキテクチャドライバ（実際に周波数変更を行うコード）および「通知者」に標準化されたインターフェースを提供します。通知者は、ポリシー変更（例：ACPIなどの熱管理モジュール）やすべての周波数変更（例：タイミングコード）を通知される必要があるデバイスドライバやカーネルの他の部分です。また、この場所でカーネルの「定数」loops_per_jiffyも周波数変更時に更新されます。

cpufreqポリシーの参照カウントはcpufreq_cpu_getとcpufreq_cpu_putで行われ、cpufreqドライバがコアに正しく登録され、cpufreq_put_cpuが呼ばれるまでアンロードされないことを保証します。これにより、使用中のcpufreqポリシーが解放されることを防ぎます。

2. CPUFreq通知者¶

CPUFreq通知者は標準的なカーネル通知インターフェースに準拠しています。詳細はlinux/include/linux/notifier.hをご参照ください。

2つの異なるCPUFreq通知者があります - ポリシーノティフィケーションとトランジションノティフィケーション。

2.1 CPUFreqポリシーノティフィケーション¶

新しいポリシーが作成されたり、削除されたりするときに通知されます。

フェーズは、通知関数の第2引数で指定され、ポリシーが最初に作成される場合はCPUFREQ_CREATE_POLICY、削除される場合はCPUFREQ_REMOVE_POLICYです。

第3引数、a void *pointerは、min、max（新しいポリシーの下限と上限の周波数（kHz）を含む）などの値を持つstruct cpufreq_policyを指します。

2.2 CPUFreqトランジション通知者¶

ポリシー内の各オンラインCPUに対して、CPUfreqドライバがCPUコアの周波数を切り替えるたびに通知されます（この変更には外部的な影響がありません）。

第2引数はフェーズを指定し、CPUFREQ_PRECHANGEまたはCPUFREQ_POSTCHANGEです。

第3引数は、以下の値を持つstruct cpufreq_freqsです：

CPU

影響を受けるCPUの番号

古い

古い周波数

new

新しい周波数

フラグ

cpufreqドライバのフラグ

3. Operating Performance Point（OPP）によるCPUFreqテーブル生成¶

OPPについての詳細は、 Operating Performance Points (OPP) ライブラリ

dev_pm_opp_init_cpufreq_table -

この関数は、OPPレイヤーの内部情報をcpufreqに提供しやすい形式に変換する即時利用可能な変換ルーチンを提供します。

警告

割り込みコンテキストでこの関数を使用しないでください。

例:

soc_pm_init()
{
       /* Do things */
       r = dev_pm_opp_init_cpufreq_table(dev, &freq_table);
       if (!r)
               policy->freq_table = freq_table;
       /* Do other things */
}

注意

この関数は、CONFIG_CPU_FREQとCONFIG_PM_OPPの両方が有効になっている場合にのみ利用可能です。

dev_pm_opp_free_cpufreq_table

dev_pm_opp_init_cpufreq_tableで割り当てられたテーブルを解放します。
