新しいCPUFreqプロセッサドライバの実装方法¶

著者:

  • Dominik Brodowski <linux@brodo.de>

  • Rafael J. Wysocki <rafael.j.wysocki@intel.com>

  • Viresh Kumar <viresh.kumar@linaro.org>

1. 何をすべきですか？¶

つまり、新しいCPU / チップセットを手に入れてデータシートがあり、このCPU / チップセットのcpufreqサポートを追加したいと考えていますか？素晴らしいです。必要なことについてのヒントを以下に示します：

1.1 初期化¶

まず、__initcallレベル7 (module_init()) またはそれ以降の関数で、このカーネルが正しいCPUと正しいチップセット上で動作しているかを確認してください。そうであれば、cpufreq_register_driver() を使用してCPUfreqコアにstruct cpufreq_driverを登録します。

このstruct cpufreq_driverには何を含める必要がありますか？

.name - このドライバーの名前。

.init - ポリシーごとの初期化関数へのポインタ。

.verify - 「検証」関数へのポインタ。

.setpolicy _or_ .fast_switch _or_ .target _or_ .target_index - 以下で違いを説明します。

オプションで

.flags - cpufreqコアへのヒント。

.driver_data - cpufreqドライバー固有のデータ。

.resolve_freq - ターゲット周波数に最も適した周波数を返しますが、周波数を変更しません。

.get_intermediate および target_intermediate - CPU周波数を変更する際の安定した周波数への切り替えに使用します。

.get - 現在のCPUの周波数を返します。

.bios_limit - CPUのハードウェア/BIOS最大周波数制限を返します。

.exit - CPU_POST_DEADフェーズでCPUホットプラグプロセス中に呼ばれるポリシーごとのクリーンアップ関数へのポインタ。

.stop_cpu - CPU_DOWN_PREPAREフェーズでCPUホットプラグプロセス中に呼ばれるポリシーごとの停止関数へのポインタ。

.suspend - インタラクティブが停止された後に呼ばれるポリシーごとのスリープ関数へのポインタ。

.resume - インタラクティブが再開される前に呼ばれるポリシーごとの再開関数へのポインタ。

.ready - ポリシーが完全に初期化された後に呼ばれるポリシーごとの準備完了関数へのポインタ。

.attr - sysfsに値をエクスポートするためのNULL終端の「struct freq_attr」リストへのポインタ。

.boost_enabled - 有効にするとブースト周波数が有効になります。

.set_boost - ブースト周波数を有効/無効にするためのポリシーごとの関数へのポインタ。

1.2 パーコア初期化¶

新しいCPUがデバイスモデルに登録されたとき、またはcpufreqドライバーが自身を登録した後、cpufreqドライバーがCPUにポリシーが存在しなかった場合、cpufreq_driver.init関数が呼ばれます。注意点として、.init() および .exit() ルーチンはポリシーごとに1回だけ呼ばれます。CPUを管理する各CPUごとに呼ばれるわけではありません。引数として struct cpufreq_policy *policy が渡されます。では、今後何をすべきですか？

必要に応じて、CPUのCPUfreqサポートを有効にしてください。

その後、ドライバーは以下の値を入力する必要があります：

policy->cpuinfo.min_freq および policy->cpuinfo.max_freq

このCPUがサポートする最小および最大周波数（kHz）

policy->cpuinfo.transition_latency

このCPUが2つの周波数間を切り替えるのにかかる時間（ナノ秒）（適切な場合、CPUFREQ_ETERNALを指定してください）

policy->cur

このCPUの現在の動作周波数（適切な場合）

policy->min, policy->max, policy->policy および、必要に応じて policy->governor

はこのCPUの「デフォルトポリシー」を含める必要があります。数秒後に cpufreq_driver.verify が呼び出され、cpufreq_driver.setpolicy または cpufreq_driver.target/target_index がこれらの値とともに呼び出されます。

policy->cpus

(オンライン + オフライン)のCPUのマスクを更新し、このCPUとともにDVFSを行うCPU（つまり、クロック/電圧ラインを共有するCPU）を指定してください。

これらの値（cpuinfo.min[max]_freq, policy->min[max]）を設定する際には、周波数テーブルヘルパが役立ちます。セクション2で詳しく説明しています。

1.3 verify¶

ユーザーが新しいポリシー（「policy,governor,min,max」からなる）を設定しようと決定した場合、このポリシーは互換性のある値を修正するために検証する必要があります。これらの値を検証するには、cpufreq_verify_within_limits(struct cpufreq_policy *policy, unsigned int min_freq, unsigned int max_freq) 関数が役立ちます。セクション2で周波数テーブルヘルパについて詳しく説明しています。

少なくとも1つの有効な周波数（または動作範囲）が policy->min と policy->max の間に存在することを確認してください。必要に応じて policy->max をまず増やし、それが解決しない場合に限り policy->min を減らしてください。

1.4 target または target_index または setpolicy または fast_switch？¶

ほとんどの cpufreq ドライバーまたはCPU周波数スケーリングアルゴリズムは、CPU周波数を事前に定義された固定値にのみ設定できます。このような場合、->target()、->target_index()、または ->fast_switch() コールバックを使用してください。

一部の cpufreq 対応プロセッサは、自身で特定の範囲内で周波数を切り替えることができます。このような場合は、->setpolicy() コールバックを使用してください。

1.5. target/target_index¶

target_index 呼び出しには2つの引数があります： struct cpufreq_policy *policy, and unsigned int 公開された周波数テーブルへのインデックス。

CPUfreq ドライバーはここに呼び出されると新しい周波数を設定する必要があります。実際の周波数は freq_table[index].frequency で決定されます。

エラー発生時に常に以前の周波数（つまり policy->restore_freq）に戻す必要があります。以前に中間周波数に切り替えたとしても例外ではありません。

廃止¶

target 呼び出しには3つの引数があります： struct cpufreq_policy *policy, unsigned int target_frequency, unsigned int relation.

CPUfreqドライバは、ここで呼ばれたときに新しい周波数を設定する必要があります。実際の周波数は以下のルールを使用して決定する必要があります：

  • target_freqに近づける必要があります

  • policy->min <= new_freq <= policy->max (これは有効でなければなりません!!!)

  • relation==CPUFREQ_REL_Lの場合、target_freq以上または等しい新しい周波数を選択する必要があります。（「Lは最低値ですが、それ以下は不可」）

  • relation==CPUFREQ_REL_Hの場合、target_freq以下または等しい新しい周波数を選択する必要があります。（「Hは最高値ですが、それ以上は不可」）

ここでも周波数テーブルヘルパーが役立つ可能性があります - 詳細はセクション2を参照してください。

1.6. fast_switch¶

この関数はスケジューラのコンテキストから周波数の切り替えに使用されます。すべてのドライバがこれを実装する必要はありません。このコールバック内でスリープすることは許可されていません。このコールバックは、切り替えを可能な限り高速に実行するため、高度に最適化する必要があります。

この関数には2つの引数があります： struct cpufreq_policy *policy および unsigned int target_frequency.

1.7 setpolicy¶

setpolicyコールはのみを引数として受け取ります。 struct cpufreq_policy *policy in-processorまたはin-chipsetのダイナミック周波数切り替えの下限をpolicy->minに、上限をpolicy->maxに設定する必要があります。-サポートされている場合- policy->policyがCPUFREQ_POLICY_PERFORMANCEの場合、パフォーマンス志向の設定を選択し、CPUFREQ_POLICY_POWERSAVEの場合、電力節約志向の設定を選択する必要があります。drivers/cpufreq/longrun.cの参照実装も確認してください

1.8 get_intermediate and target_intermediate¶

target_index()とCPUFREQ_ASYNC_NOTIFICATIONが設定されていないドライバーのみ適用されます。

get_intermediateはプラットフォームが切り替えることを希望する安定した中間周波数を返す必要があります。target_intermediate()は、indexに対応する周波数にジャンプする前にCPUをその周波数に設定する必要があります。コアが通知を送信するため、ドライバーはtarget_intermediate()またはtarget_index()で通知を処理する必要はありません。

ドライバーは、特定のターゲット周波数に対して中間周波数への切り替えを行いたくない場合、get_intermediate()から'0'を返すことができます。その場合、コアは直接->target_index()を呼び出します。

注意: ->target_index()は、失敗した場合、コアがその通知を送信するため、policy->restore_freqに戻す必要があります。

2. 周波数テーブルヘルパー¶

ほとんどのcpufreqプロセッサは特定の周波数にのみ設定可能であるため、"周波数テーブル"にいくつかの機能を含めることで、プロセッサドライバの一部の作業を支援することができる。このような"周波数テーブル"は、"driver_data"にドライバ固有の値、"frequency"に対応する周波数、およびフラグを設定したstruct cpufreq_frequency_tableの配列で構成される。テーブルの最後には、周波数をCPUFREQ_TABLE_ENDに設定したcpufreq_frequency_tableエントリを追加する必要がある。また、テーブル内の特定のエントリをスキップする場合は、周波数をCPUFREQ_ENTRY_INVALIDに設定する。エントリは特定の順序でなくてもよいが、順序が整っているとcpufreqコアがDVFSをより速く実行するため、検索が速くなる。

cpufreqテーブルは、ポリシーがpolicy->freq_tableフィールドに有効なポインタを含んでいる場合、コアが自動的に検証する。

cpufreq_frequency_table_verify()は、少なくともpolicy->minとpolicy->maxの間に有効な周波数が存在し、他のすべての条件が満たされていることを保証する。これは->verify呼び出しに役立つ。

cpufreq_frequency_table_target()は->target段階に該当する周波数テーブルのヘルパー関数である。この関数に値を渡すだけで、CPUが設定すべき周波数を含む周波数テーブルエントリを返す。

以下のマクロはcpufreq_frequency_tableをイテレータとして使用できる。

cpufreq_for_each_entry(pos, table) - 周波数テーブルのすべてのエントリをイテレートする。

cpufreq_for_each_valid_entry(pos, table) - 無効な周波数（CPUFREQ_ENTRY_INVALID）を除いたすべてのエントリをイテレートする。引数"pos" - ループカーソル、"table" - イテレートしたい周波数テーブル cpufreq_frequency_table * as a loop cursor and "table" - the cpufreq_frequency_table * you want to iterate over.

例:

struct cpufreq_frequency_table *pos, *driver_freq_table;

cpufreq_for_each_entry(pos, driver_freq_table) {
        /* Do something with pos */
        pos->frequency = ...
}

driver_freq_table内のposの位置を扱う必要がある場合は、ポインタを減算しないでください（コストが高いため）。代わりに、cpufreq_for_each_entry_idx()とcpufreq_for_each_valid_entry_idx()マクロを使用してください。
