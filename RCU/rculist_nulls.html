RCU hlist_nullsを使用したリストとオブジェクトの保護¶

このセクションでは、SLAB_TYPESAFE_BY_RCUの割当を使用して、読み込みが主なリンクリストとオブジェクトを保護するためのhlist_nullsの使用方法について説明します。

基本事項については以下を参照してください。 RCUを用いた読み込みが主なリンクリストの保護

「nulls」の使用¶

特殊なマーカー（'nulls'と呼ばれる）を使用する方法は、以下の問題を解決するための便利な方法です：

SLAB_TYPESAFE_BY_RCU kmem_cacheで割当されたオブジェクトを管理する典型的なRCUリンクリストは、以下のアルゴリズムを使用できます：

1) ロックアルゴリズム¶

rcu_read_lock()
begin:
obj = lockless_lookup(key);
if (obj) {
  if (!try_get_ref(obj)) // might fail for free objects
    goto begin;
  /*
  * Because a writer could delete object, and a writer could
  * reuse these object before the RCU grace period, we
  * must check key after getting the reference on object
  */
  if (obj->key != key) { // not the object we expected
    put_ref(obj);
    goto begin;
  }
}
rcu_read_unlock();

lockless_lookup(key)は伝統的なものを使用できませんので注意してください。 hlist_for_each_entry_rcu() ただし、追加のメモリバリア（smp_rmb()）を含むバージョンを使用してください。

lockless_lookup(key)
{
  struct hlist_node *node, *next;
  for (pos = rcu_dereference((head)->first);
      pos && ({ next = pos->next; smp_rmb(); prefetch(next); 1; }) &&
      ({ tpos = hlist_entry(pos, typeof(*tpos), member); 1; });
      pos = rcu_dereference(next))
    if (obj->key == key)
      return obj;
  return NULL;
}

また、伝統的なものは以下の通りです： hlist_for_each_entry_rcu() smp_rmb()を欠いているため、以下の通りです：

struct hlist_node *node;
for (pos = rcu_dereference((head)->first);
      pos && ({ prefetch(pos->next); 1; }) &&
      ({ tpos = hlist_entry(pos, typeof(*tpos), member); 1; });
      pos = rcu_dereference(pos->next))
 if (obj->key == key)
   return obj;
return NULL;

Corey Minyard氏の言葉を引用します：

"If the object is moved from one list to another list in-between the
time the hash is calculated and the next field is accessed, and the
object has moved to the end of a new list, the traversal will not
complete properly on the list it should have, since the object will
be on the end of the new list and there's not a way to tell it's on a
new list and restart the list traversal. I think that this can be
solved by pre-fetching the "next" field (with proper barriers) before
checking the key."

2) インサートアルゴリズム¶

読者に新しい‘obj->obj_next’値や以前の‘obj->key’値を読み取らせない必要があります。そうしないと、アイテムがチェーンから削除され、別のチェーンに挿入される可能性があります。新しいチェーンが移動前から空だった場合、‘next’ポインタはNULLになり、locklessリーダーは元のチェーンの次のアイテムを読み逃がす可能性があります。

/*
* Please note that new inserts are done at the head of list,
* not in the middle or end.
*/
obj = kmem_cache_alloc(...);
lock_chain(); // typically a spin_lock()
obj->key = key;
/*
* we need to make sure obj->key is updated before obj->next
* or obj->refcnt
*/
smp_wmb();
atomic_set(&obj->refcnt, 1);
hlist_add_head_rcu(&obj->obj_node, list);
unlock_chain(); // typically a spin_unlock()

3) リムーブアルゴリズム¶

特別なことは何もありません。標準のRCU hlist削除を使用できます。ただし、SLAB_TYPESAFE_BY_RCUのおかげで、削除されたオブジェクトはRCU grace period終了前にもっとも高速に再利用される可能性があるため、注意してください。

if (put_last_reference_on(obj) {
  lock_chain(); // typically a spin_lock()
  hlist_del_init_rcu(&obj->obj_node);
  unlock_chain(); // typically a spin_unlock()
  kmem_cache_free(cachep, obj);
}

余分なsmp_rmb()の回避¶

hlist_nullsを使用することで、lockless_lookup()内の追加のsmp_rmb()とinsert関数内の追加のsmp_wmb()を回避できます。

たとえば、ハッシュテーブルの各スロットの‘nulls’終端マーカーとしてスロット番号を保存することを選択した場合、検索がチェーンの終端に達したときに最終的な‘nulls’値を確認することで、競合状態（あるライターがオブジェクトを削除し、または別のチェーンに移動した）を検出できます。最終的な‘nulls’値がスロット番号でない場合、検索を再開する必要があります。オブジェクトが同じチェーンに移動した場合、リーダーは気にする必要はありません：最終的にはリストを再スキャンしても問題ありません。

1) ロックアルゴリズム¶

head = &table[slot];
rcu_read_lock();
begin:
hlist_nulls_for_each_entry_rcu(obj, node, head, member) {
  if (obj->key == key) {
    if (!try_get_ref(obj)) // might fail for free objects
      goto begin;
    if (obj->key != key) { // not the object we expected
      put_ref(obj);
      goto begin;
    }
  goto out;
}
/*
* if the nulls value we got at the end of this lookup is
* not the expected one, we must restart lookup.
* We probably met an item that was moved to another chain.
*/
if (get_nulls_value(node) != slot)
goto begin;
obj = NULL;

out:
rcu_read_unlock();

2) インサート関数¶

/*
* Please note that new inserts are done at the head of list,
* not in the middle or end.
*/
obj = kmem_cache_alloc(cachep);
lock_chain(); // typically a spin_lock()
obj->key = key;
/*
* changes to obj->key must be visible before refcnt one
*/
smp_wmb();
atomic_set(&obj->refcnt, 1);
/*
* insert obj in RCU way (readers might be traversing chain)
*/
hlist_nulls_add_head_rcu(&obj->obj_node, list);
unlock_chain(); // typically a spin_unlock()
