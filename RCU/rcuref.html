RCUで保護されるリスト/配列要素の参照カウント設計¶

percpu-ref フィーチャーは、参照カウントとRCUを組み合わせる場合の最初の選択肢となる可能性があります。詳細については、include/linux/percpu-refcount.h を参照してください。ただし、percpu-refがメモリを過剰に消費するという極めて特殊なケースでは、以下の説明を参照してください。

伝統的なリーダー/ライタースピンロックまたはセマフォで保護されたリストの要素に対する参照カウントは、シンプルです：

コード例 A:

1.                                      2.
add()                                   search_and_reference()
{                                       {
    alloc_object                            read_lock(&list_lock);
    ...                                     search_for_element
    atomic_set(&el->rc, 1);                 atomic_inc(&el->rc);
    write_lock(&list_lock);                  ...
    add_element                             read_unlock(&list_lock);
    ...                                     ...
    write_unlock(&list_lock);          }
}

3.                                      4.
release_referenced()                    delete()
{                                       {
    ...                                     write_lock(&list_lock);
    if(atomic_dec_and_test(&el->rc))        ...
        kfree(el);
    ...                                     remove_element
}                                           write_unlock(&list_lock);
                                            ...
                                            if (atomic_dec_and_test(&el->rc))
                                                kfree(el);
                                            ...
                                        }

このリスト/配列がRCUを使用してロックフリー化され、add()とdelete()内のwrite_lock()をspin_lock()に、search_and_reference()内のread_lock()を rcu_read_lock()、search_and_reference()内のatomic_inc()がすでにリスト/配列から削除された要素を参照している可能性があります。このような場合、以下のようにatomic_inc_not_zero()を使用してください：

コード例 B:

1.                                      2.
add()                                   search_and_reference()
{                                       {
    alloc_object                            rcu_read_lock();
    ...                                     search_for_element
    atomic_set(&el->rc, 1);                 if (!atomic_inc_not_zero(&el->rc)) {
    spin_lock(&list_lock);                      rcu_read_unlock();
                                                return FAIL;
    add_element                             }
    ...                                     ...
    spin_unlock(&list_lock);                rcu_read_unlock();
}                                       }
3.                                      4.
release_referenced()                    delete()
{                                       {
    ...                                     spin_lock(&list_lock);
    if (atomic_dec_and_test(&el->rc))       ...
        call_rcu(&el->head, el_free);       remove_element
    ...                                     spin_unlock(&list_lock);
}                                           ...
                                            if (atomic_dec_and_test(&el->rc))
                                                call_rcu(&el->head, el_free);
                                            ...
                                        }

時折、更新（書込み）ストリーム内で要素への参照を取得する必要があります。このような場合、atomic_inc_not_zero()は過剰な処理になる可能性があり、更新側のスピンロックを保持しているため、atomic_inc()を使用する方が適切です。

search_and_reference()のコードパス内で「FAIL」を扱うのは常に便利ではありません。このような場合、atomic_dec_and_test()をdelete()からel_free()に移動するようにしてください：

コード例 C:

1.                                      2.
add()                                   search_and_reference()
{                                       {
    alloc_object                            rcu_read_lock();
    ...                                     search_for_element
    atomic_set(&el->rc, 1);                 atomic_inc(&el->rc);
    spin_lock(&list_lock);                  ...

    add_element                             rcu_read_unlock();
    ...                                 }
    spin_unlock(&list_lock);            4.
}                                       delete()
3.                                      {
release_referenced()                        spin_lock(&list_lock);
{                                           ...
    ...                                     remove_element
    if (atomic_dec_and_test(&el->rc))       spin_unlock(&list_lock);
        kfree(el);                          ...
    ...                                     call_rcu(&el->head, el_free);
}                                           ...
5.                                      }
void el_free(struct rcu_head *rhp)
{
    release_referenced();
}

重要なのは、add()で追加された初期参照は、削除後も grace period（猶予期間）が経過するまで削除されません。これにより、search_and_reference()がこの要素を検出できず、el->rcの値は増加しません。したがって、el->rcがゼロになると、この要素を参照しようとする読者はいないため、要素は安全に解放できます。これにより、読者がこの要素を見つけた場合でも、参照カウンタの値を確認することなく参照を取得できることが保証されます。

コード例 Cに示すRCUベースのパターンは、コード例 Bのパターンと比較して、同時にdelete()が呼び出された場合でもsearch_and_reference()が特定のオブジェクトを検出すればそのオブジェクトへの参照を取得できるという明確な利点があります。同様に、コード例 BとCはコード例 Aと比較して、delete()呼び出しを待機させることなく、search_and_reference()の呼び出しをいくらでも行うことができ、その結果を削除する処理が行われるたびに、最終的に kfree()これは現代のコンピュータシステム、すら小さなシステムでも通常問題にはなりません。

delete()が待機できる場合、 synchronize_rcu() delete()から呼び出せ、以下のようにel_free()をdeleteに統合できます。

4.
delete()
{
    spin_lock(&list_lock);
    ...
    remove_element
    spin_unlock(&list_lock);
    ...
    synchronize_rcu();
    if (atomic_dec_and_test(&el->rc))
        kfree(el);
    ...
}

カーネルにおける追加の例として、リストCのパターンはstruct pidの参照カウントで使用され、リストBのパターンはstruct posix_aclで使用されています。
