Lockdep-RCU スラッシュ¶

Lockdep-RCU は 2010 年初頭に Linux カーネルに追加されました（http://lwn.net/Articles/371986/）。この機能は、RCU API の一般的な誤使用を検出します。特に、RCU 保護されたポインタに適切な保護を施さずにアクセスするような誤使用を検出します。このような誤使用が検出された場合、lockdep-RCU スラットが発生します。 rcu_dereference() lockdep-RCU スラットの通常の原因は、RCU 保護されたデータ構造にアクセスする際に、RCU レッドサイドクリティカルセクションの正しい種類を保持していないか、または更新側の正しいロックを保持していないことです。この問題は重大な場合があり、ランダムなメモリ上書きやさらに深刻な問題を引き起こす可能性があります。ただし、誤検出（ファルスポジティブ）も起こる可能性があり、それが現実世界のものです。

この形式は、通常の RCU レッドサイドクリティカルセクション内である必要がありますが、「他の情報」リスト上の情報はそれとは異なります。代わりに、3 つのロックを保持しており、そのうち 1 つは RCU に関連する可能性があります。このロックが本当にこの参照を保護している場合、修正方法は RCU に通知することです。たとえば、__cfq_exit_single_io_context() を cfq_exit_queue() から取得した struct request_queue "q" を引数として受け取るよう変更することで、rcu_dereference_protected を以下のように呼び出すことが可能になります：

if (rcu_dereference(ioc->ioc_data) == cic) {

この変更により、このコードが RCU レッドサイドクリティカルセクション内で呼び出された場合、または ->queue_lock を保持している場合でも lockdep-RCU スラットが発生しなくなります。特に、この修正により上記の lockdep-RCU スラットが抑制されることになります（上記リストの #2 を参照）。

if (rcu_dereference_protected(ioc->ioc_data,
                              lockdep_is_held(&q->queue_lock)) == cic) {

この変更により、このコードが RCU レッドサイドクリティカルセクション内で呼び出された場合、または ->queue_lock を保持している場合でも lockdep-RC, スラットが発生しなくなります。特に、この修正により上記の lockdep-RCU スラットが抑制されることになります（上記リストの #2 を参照）。

一方で、実際にRCU read-side critical sectionを必要とする可能性もあります。この場合、critical sectionは、 rcu_dereference()から返された値の使用にわたって、または少なくとも参照カウントがインクリメントされるか、そのような処理が行われるまで、カバーする必要があります。このような状況を処理するための方法として、 rcu_read_lock() および rcu_read_unlock() 以下のようになります:

rcu_read_lock();
if (rcu_dereference(ioc->ioc_data) == cic) {
        spin_lock(&ioc->lock);
        rcu_assign_pointer(ioc->ioc_data, NULL);
        spin_unlock(&ioc->lock);
}
rcu_read_unlock();

を追加する方法があります。この変更により、 rcu_dereference() は常にRCU read-side critical section内にあり、これにより再度上記のlockdep-RCU splatが抑制されることになります。

ただし、この特定のケースでは、実際にから返されたポインタを解釈しているわけではありません。 rcu_dereference()代わりに、そのポインタはcicポインタと比較されるだけで、これにより、 rcu_dereference() は rcu_access_pointer() 以下のようになります:

if (rcu_access_pointer(ioc->ioc_data) == cic) {

で呼び出すことが法的に許可されているため、この変更により上記のlockdep-RCU splatも抑制されることになります。 rcu_access_pointer() 保護なしで
