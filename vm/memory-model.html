物理メモリモデル¶

システム内の物理メモリは、さまざまな方法でアドレス指定されることがあります。最も単純なケースは、物理メモリがアドレス0から始まり、最大アドレスまでの連続した範囲をカバーする場合です。ただし、この範囲にはCPUがアクセスできない小さな穴がある場合もあり、その場合は完全に分離したアドレスに複数の連続した範囲が存在する可能性があります。また、NUMA（Non-Uniform Memory Access）を考慮しないと、さまざまなCPUに接続されたメモリバンクが存在する可能性があります。

Linuxはこの多様性を、FLATMEM、DISCONTIGMEM、SPARSEMEMの3つのメモリモデルのいずれかを用いて抽象化しています。各アーキテクチャはサポートするメモリモデル、デフォルトのメモリモデル、およびデフォルトを手動で上書き可能かどうかを定義します。

注意

この執筆時点ではDISCONTIGMEMは非推奨とされていますが、いくつかのアーキテクチャでまだ使用されています。

すべてのメモリモデルは、struct pageを1つまたは複数の配列に配置して、物理ページフレームの状態を追跡します。

選択されたメモリモデルに関係なく、物理ページフレーム番号（PFN）と対応する struct page.

の間には1対1のマッピングが存在します。 pfn_to_page() および page_to_pfn() 各メモリモデルは、 struct page PFNへの変換を可能にするアシスタント関数を定義します。

FLATMEM¶

最も単純なメモリモデルはFLATMEMです。このモデルは、連続的またはほぼ連続的な物理メモリを持つ非NUMAシステムに適しています。

FLATMEMメモリモデルでは、全体の物理メモリをマッピングする mem_map グローバルな配列が存在します。ほとんどのアーキテクチャでは、穴（未使用領域）もこの mem_map 配列にエントリとして含まれています。ただし、 struct page 穴に対応する

オブジェクトは完全に初期化されることはありません。 mem_map 配列を割り当てるには、アーキテクチャ固有の設定コードが free_area_init() 関数を呼び出す必要があります。ただし、 memblock_free_all() ページアロケータにすべてのメモリを渡す。

あるアーキテクチャが可能であれば CONFIG_ARCH_HAS_HOLES_MEMORYMODEL オプションが有効であれば、そのメモリの一部を解放できる可能性があります。 mem_map 配列は実際の物理ページをカバーしない場合があります。その場合、アーキテクチャ固有の pfn_valid() 実装では、その配列内のホールを考慮する必要があります。 mem_map 考慮する必要があります。
