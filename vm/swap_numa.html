スワップデバイスをNUMAノードに自動的にバインドする¶

システムに複数のスワップデバイスがあり、スワップデバイスがノード情報を保持している場合、この情報を活用してget_swap_pages()でどのスワップデバイスを使用するかを決定し、パフォーマンスを向上させることができます。

この機能の使い方¶

スワップデバイスには優先順位があり、使用順序を決定します。自動バインディングを活用するには、スワップデバイスの優先順位設定を手動で行う必要はありません。たとえば、2ノードのマシンでスワップデバイスswapAとswapBがあり、swapAがノード0に、swapBがノード1に接続されているとします。これらを有効にするには以下のようにします：

# swapon /dev/swapA
# swapon /dev/swapB

この場合、ノード0はswapAを先に、swapBを次に使用し、ノード1はswapBを先に、swapAを次に使用します。注意点として、スワップデバイスを有効にする順序は重要ではありません。

4ノードのマシンにおけるより複雑な例。6つのスワップデバイスを有効にする場合、swapAとswapBがノード0に、swapCがノード1に、swapDとswapEがノード2に、swapFがノード3に接続されています。これらを有効にする方法は上の例と同様です：

# swapon /dev/swapA
# swapon /dev/swapB
# swapon /dev/swapC
# swapon /dev/swapD
# swapon /dev/swapE
# swapon /dev/swapF

この場合、ノード0は以下の順序で使用します：

swapA/swapB -> swapC -> swapD -> swapE -> swapF

swapAとswapBは他のスワップデバイスよりもラウンドロビン方式で使用されます。

ノード1は以下の順序で使用します：

swapC -> swapA -> swapB -> swapD -> swapE -> swapF

ノード2は以下の順序で使用します：

swapD/swapE -> swapA -> swapB -> swapC -> swapF

同様に、swapDとswapEは他のスワップデバイスよりもラウンドロビン方式で使用されます。

ノード3は以下の順序で使用します：

swapF -> swapA -> swapB -> swapC -> swapD -> swapE

実装詳細¶

現在のコードでは、優先度に基づくリストswap_avail_listを使用してどのスワップデバイスを使用するかを決定します。複数のスワップデバイスが同じ優先度を持つ場合、ラウンドロビン方式で使用されます。この変更では、単一のグローバルなswap_avail_listを、各NUMAノードごとに別々のリストに置き換えています。つまり、各NUMAノードが自身の優先度に基づくスワップデバイスのリストを参照します。スワップデバイスの優先度は、該当するノードのswap_avail_listで上昇させることができます。

現在のスワップデバイスの優先度は、ユーザーが0以上を設定するか、システムが-1から下へ順に選ぶかによって決まります。swap_avail_list内の優先度値は、plistが低から高に並んでいるため、スワップデバイスの優先度の負数となっています。新しいポリシーは優先度が0以上のケースのセマンティクスは変更せず、以前の-1から下へ順に選ぶ方式が-2から下へ順に選ぶ方式に変わり、-1は優先度として予約されます。そのため、複数のスワップデバイスが同じノードに接続されている場合、そのノードのplistではすべて-1の優先度に設定され、他のスワップデバイスよりもラウンドロビン方式で使用されます。
