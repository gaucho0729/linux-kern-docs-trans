ハイメモリとは何ですか？¶

物理メモリのサイズが仮想メモリの最大サイズに近づいたりそれを超えたりする場合、カーネルがすべての物理メモリを常にマップ保持することが不可能になります。このため、カーネルはアクセスしたい物理メモリの一部に一時的なマッピングを開始する必要があります。

永久的なマッピングがカバーしない物理メモリの部分を「highmem」と呼びます。この境界線はアーキテクチャに依存した制約があります。

i386アーキテクチャでは、カーネルをすべてのプロセスの仮想メモリ空間にマップすることで、カーネルのエントリ/エクスイット時のTLB無効化コストを全額支払う必要がありません。これにより、i386では4GiBの仮想メモリ空間をユーザー空間とカーネル空間に分割する必要があります。

このアプローチを採用するアーキテクチャでは、一般的な分割は3:1で、ユーザー空間に3GiB、カーネル空間に上位1GiBを割り当てます：

+--------+ 0xffffffff
| Kernel |
+--------+ 0xc0000000
|        |
| User   |
|        |
+--------+ 0x00000000

これにより、カーネルが一度にマップできる物理メモリは最大1GiBですが、他の用途（包括的に残りの物理メモリにアクセスするための一時マッピングなど）に仮想アドレス空間が必要なため、実際の直接マップは通常約896MiB程度になります。

mmコンテキストタグ付きTLBを持つ他のアーキテクチャでは、別個のカーネルとユーザーのマップが可能です。しかし、一部のハードウェア（例：一部のARM）では、mmコンテキストタグを使用する際の仮想空間が制限されます。

一時的な仮想マッピング¶

カーネルには複数の方法で一時的なマッピングを作成する仕組みがあります：

  • vmap(). 複数の物理ページを連続した仮想空間に長時間のマッピングを作成するために使用できます。アンマップする際にはグローバルな同期が必要です。

  • kmap(). 単一のページに短時間のマッピングを許可します。グローバルな同期が必要ですが、ある程度の平均化が可能です。ネストして使用する際にはデッドロックの可能性があり、新規コードでは推奨されません。

  • kmap_atomic(). 単一のページに非常に短時間のマッピングを許可します。マッピングは発行したCPUに限定されるためパフォーマンスが良好ですが、発行タスクはマッピングを完了するまでそのCPUに留まらなければなりません。他のタスクがマッピングを置き換える可能性があるためです。

    割込みコンテキストでもkmap_atomic()を使用できます。これはスリープを伴わないため、呼び出し元はkunmap_atomic()が呼ばれるまでスリープしない必要があります。

    kmap_atomic()関数が失敗しないと想定されるかもしれません。

kmap_atomicの使用¶

kmap_atomic()を使用するタイミングと場所は明確です。コードがhigh memoryからページを割り当てた場合（例：pagecacheに格納されたページ）に使用されます。APIには2つの関数があり、以下のように使用できます：

/* Find the page of interest. */
struct page *page = find_get_page(mapping, offset);

/* Gain access to the contents of that page. */
void *vaddr = kmap_atomic(page);

/* Do something to the contents of that page. */
memset(vaddr, 0, PAGE_SIZE);

/* Unmap that page. */
kunmap_atomic(vaddr);

kunmap_atomic()呼び出しは、kmap_atomic()呼び出しの結果を使用します。引数ではありません。

1つのページから別のページにコピーする必要がある場合、kmap_atomic呼び出しは厳密にネストして使用する必要があります。例えば：

vaddr1 = kmap_atomic(page1);
vaddr2 = kmap_atomic(page2);

memcpy(vaddr1, vaddr2, PAGE_SIZE);

kunmap_atomic(vaddr2);
kunmap_atomic(vaddr1);

一時的なマッピングのコスト¶

一時的なマッピングの作成には高いコストがかかります。アーキテクチャはカーネルのページテーブル、データTLBおよび/またはMMUのレジスタを操作する必要があります。

CONFIG_HIGHMEMが設定されていない場合、カーネルはページ構造体のアドレスをページコンテンツへのポインタに変換するための簡単な算術操作だけでマッピングを試みます。このような場合、アンマップ操作は空操作となる可能性があります。

CONFIG_MMUが設定されていない場合、一時的なマッピングやhighmemは存在しません。このような場合、算術的なアプローチが使用されます。

i386 PAE¶

i386アーキテクチャは、特定の状況下で32ビットのマシンに最大64GiBのRAMを挿入することを許可します。これはいくつかの影響を及ぼします：

  • Linuxはシステム内の各ページに対してpage-frame構造体を必要とし、pageframeは永続的なマッピングに存在する必要があります。つまり：

  • 最大で896M / sizeof(struct page)のpage-frameを有できます。struct pageが32バイトの場合、これは約112Gのページに相当します。しかし、カーネルはそのメモリにページフレーム以外にもデータを保存する必要があります…

  • PAEはページテーブルを大きくするため、TLBフィルやその他の処理でより多くのデータをアクセスする必要があり、システムの速度が遅くなります。一方で、PAEはより多くのPTEビットを持ち、NXやPATなどの高度な機能を提供できます。

一般的な推奨は、32ビットマシンでは8GiB以上は使用しないことです。ただし、あなたのワークロードに合わせてより多くのメモリを使用する可能性もありますが、基本的に自分で責任を取る必要があります。カーネル開発者があなたの環境が崩れても気にするとは限りません。
