ページテーブルロックの分割¶

元々、mm->page_table_lock スピンロックは mm_struct のすべてのページテーブルを保護していました。しかし、このアプローチはマルチスレッドアプリケーションにおけるページフォールトのスケーラビリティに悪影響を及ぼし、ロックの競合が高いためです。スケーラビリティを改善するために、split page table lock が導入されました。

split page table lock を使用すると、各テーブルごとに別個のロックを用いてテーブルへのアクセスをシリアル化します。現在は PTE および PMD テーブルに split lock を適用しており、より上位のテーブルへのアクセスは mm->page_table_lock で保護されています。

テーブルのロック/アンロックやその他のアクセッサ関数のヘルパー関数があります:

  • pte_offset_map_lock()

    pte をマップし、PTE テーブルロックを取得し、取得したロックのポインタを返します;

  • pte_unmap_unlock()

    PTE テーブルをアンロックし、アンマップします;

  • pte_alloc_map_lock()

    PTE テーブルを必要に応じて割当し、ロックを取得します。割当に失敗した場合は NULL を返します;

  • pte_lockptr()

    PTE テーブルロックのポインタを返します;

  • pmd_lock()

    PMD テーブルロックを取得し、取得したロックのポインタを返します;

  • pmd_lockptr()

    PMD テーブルロックのポインタを返します;

PTE テーブル用の split page table lock は、CONFIG_SPLIT_PTLOCK_CPUS（通常は 4）が NR_CPUS 以下の場合、コンパイルタイムに有効になります。split lock が無効の場合、すべてのテーブルは mm->page_table_lock で保護されます。

PMD テーブル用の split page table lock は、PTE テーブル用が有効で、アーキテクチャがサポートしている場合に有効になります（以下参照）。

Hugetlb と split page table lock¶

Hugetlb は複数のページサイズをサポートします。split lock は PMD レベルのみに使用し、PUD には使用しません。

Hugetlb 専用のヘルパー関数:

  • huge_pte_lock()

    PMD_SIZE ページ用の pmd split lock を取得し、それ以外は mm->page_table_lock を使用します;

  • huge_pte_lockptr()

    テーブルロックのポインタを返します;

アーキテクチャによる split page table lock のサポート¶

PTE split page table lock の特別な有効化は必要ありません。必要な処理は pgtable_pte_page_ctor() と pgtable_pte_page_dtor() によって行われ、PTE テーブルの割当/解放時にこれらを呼び出す必要があります。

アーキテクチャがページテーブルの割当に slab allocator を使用しないようにしてください。slab は page->slab_cache を使用してページを管理します。このフィールドは page->ptl と共有しているストレージを使用します。

PMD split lock は、ページテーブルレベルが 2 つ以上ある場合にのみ意味があります。

PMD split lock の有効化には、PMD テーブルの割当時に pgtable_pmd_page_ctor() を呼び出し、解放時に pgtable_pmd_page_dtor() を呼び出す必要があります。

割当は通常 pmd_alloc_one() で行われ、解放は pmd_free() と pmd_free_tlb() で行われます。ただし、すべての PMD テーブルの割当/解放パスをカバーしてください。例として X86_PAE では pgd_alloc() でいくつかの PMD を事前に割当てる必要があります。

すべての設定が完了した場合、CONFIG_ARCH_ENABLE_SPLIT_PMD_PTLOCKを設定できます。

注意: pgtable_pte_page_ctor()およびpgtable_pmd_page_ctor()は失敗する可能性があるため、適切に処理する必要があります。

page->ptl¶

page->ptlは、split page table lockにアクセスするために使用され、'page'はテーブルを含むstruct pageです。これはpage->privateといくつかの他のフィールドと共有されたメモリ領域を使用しています。

struct pageのサイズを増やさずに最適なパフォーマンスを維持するため、以下のようなトリックを使用します:

  • spinlock_tがlongに収まる場合、page->ptrをspinlockとして使用し、間接的なアクセスを回避してキャッシュラインを節約できます。

  • spinlock_tのサイズがlongより大きい場合、page->ptlをspinlock_tへのポインタとして使用し、動的に割り当てます。これによりDEBUG_SPINLOCKまたはDEBUG_LOCK_ALLOCが有効なsplit lockの使用が可能ですが、間接的なアクセスにより1つのキャッシュライン分のコストが発生します;

PTEテーブル用にpgtable_pte_page_ctor()で、PMDテーブル用にpgtable_pmd_page_ctor()でspinlock_tが割り当てられます。

page->ptlを直接アクセスしないでください。適切なヘルパーを使用してください。
