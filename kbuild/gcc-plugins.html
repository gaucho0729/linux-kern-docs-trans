GCCプラグインインフラストラクチャ¶

はじめに¶

GCCプラグインは、コンパイラに追加の機能を提供するロード可能なモジュールです 1。ランタイムインストゥレーションや静的解析に有用です。コンパイル時にコールバックを介して分析・変更・追加コードの生成が可能です 2、GIMPLE 3、IPA 4 およびRTLパス 5.

カーネルのGCCプラグインインフラストラクチャは、ツリー外モジュールのビルド、クロスコンパイル、別ディレクトリでのビルドをサポートしています。プラグインソースファイルはC++コンパイラでコンパイル可能でなければなりません

現在、GCCプラグインインフラストラクチャは一部のアーキテクチャのみをサポートしています。『select HAVE_GCC_PLUGINS』をgrepして、どのアーキテクチャがGCCプラグインをサポートしているか確認してください

このインフラストラクチャはgrsecurityから移植されました 6 およびPaX 7.

ファイル¶

($(src)/scripts/gcc-plugins)

これはGCCプラグインのディレクトリです

($(src)/scripts/gcc-plugins/gcc-common.h)

これはGCCプラグイン用の互換性ヘッダーファイルです。個々のgccヘッダーではなく常にこのヘッダーをインクルードする必要があります

($(src)/scripts/gcc-plugins/gcc-generate-gimple-pass.h, $(src)/scripts/gcc-plugins/gcc-generate-ipa-pass.h, $(src)/scripts/gcc-plugins/gcc-generate-simple_ipa-pass.h, $(src)/scripts/gcc-plugins/gcc-generate-rtl-pass.h)

これらのヘッダーはGIMPLE、SIMPLE_IPA、IPA、RTLパスの登録構造体を自動生成します。手動で構造体を作成するのではなく、これらのヘッダーを使用するべきです

使い方¶

使用するgccバージョンに応じてgccプラグインヘッダーをインストールする必要があります。たとえばUbuntuではgcc-10の場合:

apt-get install gcc-10-plugin-dev

、Fedoraの場合:

dnf install gcc-plugin-devel

カーネル構成でGCCプラグインインフラストラクチャと使用したいプラグイン（いくつか）を有効にします:

CONFIG_GCC_PLUGINS=y
CONFIG_GCC_PLUGIN_CYC_COMPLEXITY=y
CONFIG_GCC_PLUGIN_LATENT_ENTROPY=y
...

プラグイン（いくつか）を含む最小ツールセットをコンパイルするには:

make scripts

、またはカーネルmakeを実行して、サイクル的複雑度GCCプラグインで全体をコンパイルするだけでも可能です

4. 新しいGCCプラグインを追加する方法¶

GCCプラグインはscripts/gcc-plugins/にあります。プラグインソースファイルはscripts/gcc-plugins/直下に配置する必要があります。サブディレクトリの作成はサポートされていません。scripts/gcc-plugins/Makefile、scripts/Makefile.gcc-pluginsおよび関連するKconfigファイルに追加する必要があります。cyc_complexity_plugin.c（CONFIG_GCC_PLUGIN_CYC_COMPLEXITY）のGCCプラグインを参照してください
