再現可能なビルド¶

同じソースコードとツールのセットでビルドを行うことが再現可能であることは一般的に望ましいです。つまり、出力は常に完全に同じになります。これにより、バイナリ配布版や埋め込みシステムのビルドインフラストラクチャが改ざんされていないことを確認できます。また、ソースコードやツールの変更が結果となるバイナリに影響を与えないことを確認するのもより簡単になります。

以下の Reproducible Builds プロジェクト この一般的なトピックについての詳細情報があります。このドキュメントでは、カーネルのビルドが再現不可能になるさまざまな理由と、それらを回避する方法について説明しています。

タイムスタンプ¶

カーネルはタイムスタンプを3つの場所に埋め込んでいます：

  • 公開されるバージョン文字列 uname() および含まれる /proc/version

  • 埋め込まれたinitramfs内のファイルタイムスタンプ

  • 有効化された場合、 CONFIG_IKHEADERSカーネルまたは対応するモジュールに埋め込まれたカーネルヘッダのファイルタイムスタンプは、 /sys/kernel/kheaders.tar.xz

デフォルトではタイムスタンプは現在の時間であり、 kheaders さまざまなファイルの変更時刻。これを上書きするには、 KBUILD_BUILD_TIMESTAMP 変数を使用する必要があります。git コミットからビルドしている場合、そのコミット日付を使用できます。

カーネルは ではありません 使用する __DATE__ および __TIME__ マクロ、およびそれらが使用される場合に警告を出力します。外部コードを組み込む場合、それらを使用している場合は、対応するタイムスタンプを上書きするために SOURCE_DATE_EPOCH 環境変数に表示されます。

ユーザー、ホスト¶

カーネルはビルド時のユーザー名とホスト名を /proc/version. These must be overridden using the KBUILD_BUILD_USER and KBUILD_BUILD_HOST variables. If you are building from a git commit, you could use its committer address.

Absolute filenames¶

When the kernel is built out-of-tree, debug information may include absolute filenames for the source files. This must be overridden by including the -fdebug-prefix-map option in the KCFLAGS 変数を介して提供できます。

Depending on the compiler used, the __FILE__ macro may also expand to an absolute filename in an out-of-tree build. Kbuild automatically uses the -fmacro-prefix-map option to prevent this, if it is supported.

再現可能なビルドウェブサイトには、これらに関するさらに詳しい情報があります prefix-mapオプション.

ソースパッケージ内の生成されたファイル¶

一部のプログラムのビルドプロセスは、サブディレクトリ内の tools/ サブディレクトリでは完全にツリー外ビルドをサポートしていません。これにより、後続のソースパッケージビルドで生成されたファイルが含まれる可能性があります。You should ensure the source tree is pristine by running make rpm-pkg 生成されたファイルを含む可能性があります。ソースツリーが純粋であることを確認するために、ビルド前の実行を推奨します。 make mrproper または git clean -d -f -x ソースパッケージをビルドする前に実行してください。

モジュール署名¶

有効にすると、 CONFIG_MODULE_SIG_ALLデフォルトでは、各ビルドごとに一時的なキーを生成するため、モジュールが再現不可能になります。ただし、ソースに署名キーを含めることで、モジュールの署名目的が達成されなくなる可能性があります。

この問題に対する一つのアプローチは、ビルドプロセスを分割して、再現不可能な部分をソースとして扱うことです：

  1. 永続的な署名キーを生成します。このキーの証明書をカーネルソースに追加します。

  2. 以下の CONFIG_SYSTEM_TRUSTED_KEYS 署名キーの証明書を含めるためのシンボルを設定し、 CONFIG_MODULE_SIG_KEY 空文字列に設定し、 CONFIG_MODULE_SIG_ALLを無効化します。カーネルとモジュールをビルドします。

  3. モジュールの分離署名を作成し、それをソースとして公開します。

  4. モジュール署名を付属する第二のビルドを実行します。これにより、モジュールを再ビルドするか、ステップ2の出力を使用できます。

構造ランダム化¶

有効にすると、 CONFIG_GCC_PLUGIN_RANDSTRUCTランダムシードを事前に生成する必要があります。 scripts/gcc-plugins/randomize_layout_seed.h 再ビルド時に同じ値が使用されるようにします。

デバッグ情報の競合¶

これは再現不可能性の問題ではなく、生成されたファイルが 過剰に 再現可能すぎるためです。

再現可能なビルドに必要なすべての変数を設定した後、vDSOのデバッグ情報は異なるカーネルバージョンでも同一になる可能性があります。これにより、異なるカーネルバージョン用のデバッグ情報パッケージ間でファイルの競合が発生する可能性があります。

これを回避するには、任意の文字列の「salt」を含めてvDSOを異なるカーネルバージョンごとに変更できます。これはKconfigシンボルで指定されます。 CONFIG_BUILD_SALT.
