Kconfigマクロ言語¶

概念¶

基本的なアイデアはMakeからインスピレーションを受けました。Makeを観察すると、1つの中に2つの言語が含まれているように見えます。1つはターゲットとプリリクエストからなる依存関係グラフを記述する言語で、もう1つはテキスト置換を行うマクロ言語です。

2つの言語段階には明確な区別があります。例えば、以下のようにmakefileを記述できます：

APP := foo
SRC := foo.c
CC := gcc

$(APP): $(SRC)
        $(CC) -o $(APP) $(SRC)

マクロ言語は変数参照を展開した形式に置き換え、以下のようにソースファイルが入力されたかのように扱います：

foo: foo.c
        gcc -o foo foo.c

その後、Makeは依存関係グラフを分析し、更新が必要なターゲットを決定します。

Kconfigではこのアイデアはほぼ同じです。以下のようにKconfigファイルを記述できます：

CC := gcc

config CC_HAS_FOO
        def_bool $(shell, $(srctree)/scripts/gcc-check-foo.sh $(CC))

Kconfigのマクロ言語はソースファイルを以下の中間形式に処理します：

config CC_HAS_FOO
        def_bool y

その後、Kconfigはkconfig-language.rstで説明されているように、シンボル間の依存関係を解決する評価段階に移ります。

変数¶

Makeと同様に、Kconfigの変数はマクロ変数として機能します。マクロ変数は「in place」で展開され、テキスト文字列に変換され、さらに展開されます。変数の値を取得するには、変数名を $( ) で囲みます。括弧は単一文字の変数名でも必要で、$Xは構文エラーです。{ } 形式（例: ${CC}）はサポートされません。

変数には2種類あります：単純展開変数と再帰展開変数。

単純展開変数は := 割り当て演算子で定義されます。その右辺はKconfigファイルから行を読み込む際に即座に展開されます。

再帰展開変数は = 割り当て演算子で定義されます。右辺は変数の値としてそのまま保存され、展開は一切行われません。代わりに変数が使用される際に展開されます。

もう一つの割り当て演算子があります； += は変数にテキストを追加するために使用されます。左辺が単純変数として元から定義されていた場合、右辺は即座に展開されます。それ以外の場合は評価が遅延されます。

変数参照は以下の形式のようにパラメータを受け取ることができます：

$(name,arg1,arg2,arg3)

パラメータ化された参照を関数と見なせます。(より正確には、以下に記載されている「組み込み関数」と対比して「ユーザー定義関数」です。)

関数が使用される際には、その関数が異なるパラメータを渡すことで異なるように展開されるため、有用な関数は使用時に拡張する必要があります。したがって、ユーザー定義関数は = 代入演算子を使って定義されます。パラメータは、$(1)、$(2) などを使って関数本体の定義内で参照されます。

実際、再帰的に展開される変数とユーザー定義関数は内部的には同じです。(つまり、「変数」は「引数がゼロの関数」です。) 「変数」という広義の意味で言うと、それは「ユーザー定義関数」も含みます。

組み込み関数¶

Make と同様に、Kconfig もいくつかの組み込み関数を提供しています。すべての関数は特定の数の引数を取る必要があります。

Make では、すべての組み込み関数は少なくとも 1 つの引数を取る必要があります。Kconfig では組み込み関数にゼロ個の引数を許可しており、$(fileno)、$(lineno) のようなものがそれに該当します。これらを「組み込み変数」と見なしてもよいですが、最終的には呼び出す方法の違いに過ぎません。ここでは「組み込み関数」として、ネイティブでサポートされる機能を指します。

Kconfig は現在、以下の組み込み関数をサポートしています。

  • $(shell,command)

「shell」関数は単一の引数を受け取り、その引数をサブシェルに展開して実行します。コマンドの標準出力は関数の値として読み込まれ、返されます。出力のすべての改行はスペースに置き換えられ、末尾の改行は削除されます。標準エラーは返されず、プログラムの終了ステータスも返されません。

  • $(info,text)

「info」関数は単一の引数を受け取り、それを標準出力に印刷します。この関数は空文字列に評価されます。

  • $(warning-if,condition,text)

「warning-if」関数は 2 つの引数を受け取ります。条件部が「y」の場合、テキスト部が標準エラー出力に送られます。テキストには現在の Kconfig ファイル名と現在の行番号が先頭に付加されます。

  • $(error-if,condition,text)

「error-if」関数は「warning-if」関数と似ていますが、条件部が「y」の場合には即座に解析を終了します。

  • $(filename)

「filename」は引数を取らず、$(filename) は解析されているファイル名に展開されます。

  • $(lineno)

「lineno」は引数を取らず、$(lineno) は解析されている行番号に展開されます。

Make と Kconfig¶

Kconfig は Make に似たマクロ言語を採用していますが、関数呼び出しの構文はやや異なります。

Make での関数呼び出しは次のようになります：

$(func-name arg1,arg2,arg3)

関数名と最初の引数は少なくとも1つの空白で区切られます。その後、最初の引数の前導空白はトリムされますが、他の引数の空白は保持されます。最初のパラメータにスペースを開始するには、ある種のトリックが必要です。たとえば、「info」関数で「hello」を表示したい場合は、以下のように記述できます:

empty :=
space := $(empty) $(empty)
$(info $(space)$(space)hello)

Kconfigはコンマのみを区切り文字として使用し、関数呼び出しではすべての空白を保持します。一部の人々は、各コンマ区切りの後にスペースを追加するのが好みます:

$(func-name, arg1, arg2, arg3)

この場合、「func-name」は「 arg1」、「 arg2」、「 arg3」を受け取ります。前導スペースの存在は関数によって重要になることがあります。Makeの場合も同様です。たとえば、$(subst .c, .o, $(sources))は典型的な間違いで、「.c」が「 .o」に置き換えられます。

Makeでは、ユーザー定義関数は組み込み関数「call」を使用して参照されます。以下のように記述します:

$(call my-func,arg1,arg2,arg3)

Kconfigはユーザー定義関数と組み込み関数を同じ方法で呼び出します。'call'の省略により構文が短くなります。

Makeでは一部の関数はコンマを引数区切りではなく、文字列として扱います。たとえば、$(shell echo hello, world)は「echo hello, world」というコマンドを実行します。同様に、$(info hello, world)は「hello, world」を標準出力に表示します。これは_役立つ不一致_と表現できます。

Kconfigでは、$( )コンテキストで出現するコンマは常に区切り文字として扱われます。これは以下の意味を持ちます:

$(shell, echo hello, world)

これはエラーです。'shell'関数が1つのパラメータしか受け取れないにもかかわらず、2つのパラメータを渡しています。引数内にコンマを渡すには、以下のトリックを使用できます:

comma := ,
$(shell, echo hello$(comma) world)

注意事項¶

変数（または関数）はトークンをまたがって展開できません。したがって、複数のトークンからなる式の短縮として変数を使用することはできません。以下の例は動作します:

RANGE_MIN := 1
RANGE_MAX := 3

config FOO
        int "foo"
        range $(RANGE_MIN) $(RANGE_MAX)

しかし、以下の例は動作しません:

RANGES := 1 3

config FOO
        int "foo"
        range $(RANGES)

Kconfigでは変数はどのキーワードにも展開できません。以下の例は動作しません:

MY_TYPE := tristate

config FOO
        $(MY_TYPE) "foo"
        default y

設計上明らかですが、$(shell command)はテキスト置換フェーズで展開されます。シンボルを'shell'関数に渡すことはできません。

以下の例は予想通りに動作しません:

config ENDIAN_FLAG
        string
        default "-mbig-endian" if CPU_BIG_ENDIAN
        default "-mlittle-endian" if CPU_LITTLE_ENDIAN

config CC_HAS_ENDIAN_FLAG
        def_bool $(shell $(srctree)/scripts/gcc-check-flag ENDIAN_FLAG)

代わりに、以下のようすることで、任意の関数呼び出しを静的に展開できます:

config CC_HAS_ENDIAN_FLAG
        bool
        default $(shell $(srctree)/scripts/gcc-check-flag -mbig-endian) if CPU_BIG_ENDIAN
        default $(shell $(srctree)/scripts/gcc-check-flag -mlittle-endian) if CPU_LITTLE_ENDIAN
