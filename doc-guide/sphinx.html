はじめに¶

Linuxカーネルは Sphinx を用いて、 reStructuredText ファイルから見やすいドキュメンテーションを生成します。 Documentation. HTMLまたはPDF形式でドキュメンテーションをビルドするには、 make htmldocs または make pdfdocs. 生成されたドキュメンテーションは Documentation/output.

reStructuredTextファイルには、ソースファイルから構造化されたドキュメンテーションコメント（kernel-docコメント）を含めるディレクティブが含まれている場合があります。通常、これらは関数や型、コードの設計について説明するために使用されます。kernel-docコメントは特別な構造とフォーマットを持っていますが、それらはreStructuredTextとして扱われることも含まれます。

最後に、Documentation/ディレクトリ内に数千ものプレーンテキストのドキュメンテーションファイルが散在しています。 Documentation. 一部は時間とともにreStructuredTextに変換される可能性がありますが、大部分はプレーンテキストのまま残るでしょう。

Sphinxのインストール¶

現在、Documentation/ディレクトリ内のファイルで使用されているreStructuredTextのマークアップは、 Sphinx バージョン1.3以上でビルドすることを意図しています。

Sphinxの要件を確認するスクリプトがあります。参照してください Sphinxの依存関係の確認 を参照してください。

ほとんどのディストリビューションにはSphinxが含まれていますが、ツールチェーンは脆弱で、機械の他のPythonパッケージをアップグレードするなどした際にドキュメントのビルドが破綻するケースがよくあります。

その回避策として、ディストリビューションに同梱されているバージョンとは異なるバージョンを使用することをお勧めします。そのためには、仮想環境内でSphinxをインストールすることをお勧めします。 virtualenv-3 または virtualenvあなたのディストリビューションがPython 3をパッケージングする方法に応じて、

注意

  1. Sphinxバージョン1.5未満は、Pythonのdocutilsバージョン0.13.1以降と正しく動作しません。そのため、それらのバージョンを使用する場合は、 pip install 'docutils==0.12'.

  2. RTDテーマを使用してhtml出力することをお勧めします。Sphinxのバージョンに応じて、別途インストールする必要があります。 pip install sphinx_rtd_theme.

  3. 一部のReSTページには数式が含まれています。Sphinxの仕様上、これらの式はLaTeX記法で記述されています。これらを評価するには、texliveにamdfontsとamsmathをインストールする必要があります。

要約すると、Sphinxバージョン1.7.9をインストールする場合は、以下の手順を行ってください：

$ virtualenv sphinx_1.7.9
$ . sphinx_1.7.9/bin/activate
(sphinx_1.7.9) $ pip install -r Documentation/sphinx/requirements.txt

実行した後 . sphinx_1.7.9/bin/activate、プロンプトが変更され、新しい環境を使用していることを示します。新しいシェルを開く場合は、再度このコマンドを実行して、ドキュメントのビルド前に仮想環境に戻る必要があります。

画像出力¶

カーネルドキュメントビルドシステムには、グラフビズとSVG形式の画像を処理する拡張機能が含まれており、(参照) 図と画像).

動作させるには、GraphVizとImageMagickの両方のパッケージをインストールする必要があります。これらのパッケージがインストールされていない場合でも、ビルドシステムはドキュメンテーションを構築しますが、出力には画像が含まれません。

PDFおよびLaTeXのビルド¶

このようなビルドは現在、Sphinxバージョン1.4以降でのみサポートされています。

PDFおよびLaTeX出力には、さらに XeLaTeX バージョン3.14159265が必要です。

ディストリビューションによっては、必要な機能の最小セットを提供する一連の texlive パッケージをインストールする必要があります。 XeLaTeX 動作させるために必要なものです。

Sphinxの依存関係の確認¶

Sphinxの依存関係を自動的にチェックするスクリプトがあります。このスクリプトがあなたのディストリビューションを認識できる場合、そのディストリビューション用のインストールコマンドラインオプションのヒントも表示します:

$ ./scripts/sphinx-pre-install
Checking if the needed tools for Fedora release 26 (Twenty Six) are available
Warning: better to also install "texlive-luatex85".
You should run:

        sudo dnf install -y texlive-luatex85
        /usr/bin/virtualenv sphinx_1.7.9
        . sphinx_1.7.9/bin/activate
        pip install -r Documentation/sphinx/requirements.txt

Can't build as 1 mandatory dependency is missing at ./scripts/sphinx-pre-install line 468.

デフォルトでは、htmlとPDFの両方の要件をチェックし、画像、数式、LaTeXビルドの要件も含み、仮想Python環境が使用されるものと仮定します。htmlビルドに必要なものは必須とされ、それ以外はオプションとされます。

2つのオプションパラメータをサポートしています:

--no-pdf

PDFのチェックを無効にする;

--no-virtualenv

Sphinx用のOSパッケージングを使用する代わりに、Python仮想環境を使用する。

Sphinxのビルド¶

ドキュメンテーションを生成する通常の方法は、 make htmldocs または make pdfdocsを実行することです。他のフォーマットも利用可能です。詳しくは、 make helpのドキュメンテーションセクションをご覧ください。生成されたドキュメンテーションは、 Documentation/output.

以下のフォーマット固有のサブディレクトリに配置されます。ドキュメンテーションを生成するには、Sphinx（sphinx-build）がインストールされている必要があります。より美しく表示するためには、Read the Docs Sphinxテーマ（sphinx_rtd_theme）が使用されます（利用可能であれば）。PDF出力にはさらに、 XeLaTeX および convert(1) からImageMagick（https://www.imagemagick.org）が必要です。これらはすべて広く利用されており、ディストリビューションにパッケージされています。

Sphinxに追加のオプションを渡すには、 SPHINXOPTS make変数を使用できます。例えば、 make SPHINXOPTS=-v htmldocs を指定してより詳細な出力を得ることができます。

生成されたドキュメンテーションを削除するには、 make cleandocs.

ドキュメンテーションの作成¶

を実行してください。新しいドキュメンテーションを追加するには、以下のように簡単です:

  1. 新しい .rst ファイルを Documentation.

  2. の下のどこかに追加してください。 Sphinxのメイン の Documentation/index.rst.

TOCツリーから参照してください。これは、シンプルなドキュメンテーション（例えば今読んでいるこのドキュメンテーション）には十分ですが、より大きなドキュメントではサブディレクトリ（既存のものを使うことも）を作成することを推奨します。例えば、グラフィックスサブシステムのドキュメンテーションは、 Documentation/gpuの下にあり、複数の .rst ファイルに分割され、メインインデックスから参照される別個の index.rst （独自の toctree を持つ）があります。

詳しくは、 Sphinx および reStructuredText のドキュメンテーションをご覧ください。特に、Sphinxの reStructuredText Primer はreStructuredTextの始め方として良い場所です。また、いくつかの Sphinx固有のマーキアップ構文もあります。.

カーネルドキュメンテーションに関する特定のガイドライン¶

以下に、カーネルドキュメンテーションに関する特定のガイドラインを示します:

  • reStructuredTextのマーキアップを過度に使用しないでください。シンプルに保つことが重要です。基本的にドキュメンテーションはプレーンテキストで、フォーマットの整合性を保つことで他の形式に変換可能なようにしてください。

  • 既存のドキュメンテーションをreStructuredTextに変換する際には、フォーマットの変更を最小限に抑えましょう。

  • ドキュメンテーションの変換時には、フォーマットだけでなく、コンテンツも更新してください。

  • ヘッダーデコレーションの順序に厳密に従ってください:

    1. = ドキュメントタイトルには上線を使用します:

      ==============
Document title
==============

    2. = 章には上線を使用します:

      Chapters
========

    3. - 節には上線を使用します:

      Section
-------

    4. ~ サブセクションには上線を使用します:

      Subsection
~~~~~~~~~~

    RSTではセクションタイトルの装飾スタイルの順序に明確な規則はありません（「セクションタイトルの装飾スタイルの数や順序を固定するのではなく、出現順に従う」という仕様）。ただし、階層の高いセクションで統一的な装飾を維持することで、ドキュメントの読みやすさが向上します。

  • 固定幅テキストブロック（コード例、ケース例など）を挿入する際には、 :: シンタックスハイライトが不要な内容、特に短いスニペットには、 .. code-block:: <language> シンタックスハイライトが有効な長いコードブロックには、

Cドメイン¶

以下の Sphinx C Domain (name c)はC APIのドキュメンテーションに適しています。例えば関数プロトタイプ:

.. c:function:: int ioctl( int fd, int request )

カーネルドキュメンテーションのCドメインには追加機能があります。例えば、関数の参照名を一般的な名前（例: rename ）に変更できます。 open または ioctl:

.. c:function:: int ioctl( int fd, int request )
   :name: VIDIOC_LOG_STATUS

func-name（例: ioctl）は出力に残りますが、ref-nameは ioctl に（木の下から葉に向かって） VIDIOC_LOG_STATUSから VIDIOC_LOG_STATUS.

以下の flat-table は二段階リストで、 list-table に似ていますが、いくつかの追加機能があります:

  • column-span: role cspan でセルを追加の列に拡張できます。

  • row-span: role rspan でセルを追加の行に拡張できます。

  • テーブル行の右端のセルを、そのテーブル行の右側に存在しないセルをカバーするように自動的にスパンします。オプションで :fill-cells: この動作は以下のように変更可能です auto span に（木の下から葉に向かって） auto fill、最後のセルをスパンするのではなく、空のセルを自動的に挿入します。

オプション:

  • :header-rows: [int] ヘッダー行の数

  • :stub-columns: [int] ストブ列の数

  • :widths: [[int] [int] … ] 列の幅

  • :fill-cells: 、自動的に欠損しているセルをスパンするのではなく、欠損しているセルを挿入します

役割:

  • :cspan: [int] 追加の列 (morecols)

  • :rspan: [int] 追加の行 (morerows)

以下にこのマークアップの使用方法を示します。ステージドリストの最初のレベルは table-row。その中には table-row この中には、セルのリストのみが許可されています table-row。例外は comments ( .. ) および targets (例: ある参照先への参照) :ref:`last row <last row>` / last row).

     - head col 2
     - head col 3
     - head col 4

     - field 1.2 with autospan

Cross-referencing¶

ドキュメンテーションページ間でのクロスリファレンスは、Documentation フォルダからファイルへのパスを渡すことで実現できます。たとえば、このページへのクロスリファレンス（.rst 拡張子は任意です）は以下のようにします：

See Documentation/doc-guide/sphinx.rst.

相対パスを使用する場合は、Sphinxのディレクティブを使用する必要があります。 doc 同じディレクトリからこのページを参照する場合は、以下のようにします：

See :doc:`sphinx`.

カーネルドックの関数や型へのクロスリファレンスに関する情報については、 kernel-docコメントの作成.

図と画像¶

画像を追加する場合は、次のディレクティブを使用する必要があります。 kernel-figure および kernel-image スケーラブルな画像形式（SVG）を使用して図を挿入する場合は、SVG画像の例):

.. kernel-figure::  svg_image.svg
   :alt:    simple SVG image

   SVG image example

カーネルの図（および画像）ディレクティブは、 DOT 形式のファイルをサポートしています。詳しくは、

  • DOT: http://graphviz.org/pdf/dotguide.pdf

  • Graphviz: http://www.graphviz.org/content/dot-language

簡単な例（DOTのHello World例):

.. kernel-figure::  hello.dot
   :alt:    hello world

   DOT's hello world example

埋め込み レンダリング Graphvizなどのマークアップ（または言語）をサポートしています。この機能は、 DOT ディレクティブによって提供されています。 kernel-render ディレクティブです。

.. kernel-render:: DOT
   :alt: foobar digraph
   :caption: Embedded **DOT** (Graphviz) code

   digraph foo {
    "bar" -> "baz";
   }

レンダリングされる結果はインストールされているツールによって異なります。Graphvizがインストールされている場合、ベクター画像が表示されます。インストールされていない場合は、raw markupが literal-block (埋め込まれたDOT（Graphviz）コード).

以下の レンダリング ディレクティブは、 figure ディレクティブに存在するすべてのオプションを備えています。さらにオプション caption. caption が指定されている場合、 figure ノードが挿入されます。指定されていない場合は、 image ノードが挿入されます。参照したい場合は、 caption が必要です（埋め込まれたSVGマークアップ).

埋め込まれた SVG:

.. kernel-render:: SVG
   :caption: Embedded **SVG** markup
   :alt: so-nw-arrow

   <?xml version="1.0" encoding="UTF-8"?>
   <svg xmlns="http://www.w3.org/2000/svg" version="1.1" ...>
      ...
   </svg>
