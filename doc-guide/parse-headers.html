uAPIヘッダーファイルの含める¶

場合によっては、ユーザー空間APIを説明するためや、コードとドキュメンテーション間のクロスリファレンスを生成するため、ヘッダーファイルとC言語の例コードを含めることが役立ちます。ユーザー空間APIファイルのクロスリファレンスを追加するには、Sphinxがドキュメンテーションに記述されていないシンボルを検出すると警告を生成するという追加の利点があります。これにより、uAPIドキュメンテーションがカーネルの変更と同期を取るようになります。 parse_headers.pl このようなクロスリファレンスを生成するための方法を提供しています。ドキュメンテーションのビルド中にMakefileを通じて呼び出す必要があります。詳しくは Documentation/userspace-api/media/Makefile カーネルツリー内で使用方法の例をご覧ください。

parse_headers.pl¶

NAME¶

parse_headers.pl - Cファイルを解析し、関数、構造体、列挙型、定義を識別してSphinxの本にクロスリファレンスを生成します。

SYNOPSIS¶

parse_headers.pl [<オプション>] <Cファイル> <出力ファイル> [<例外ファイル>]

<オプション>は –debug、–help、または –usage のいずれかです。

OPTIONS¶

–debug

スクリプトをデバッグモードに設定します。

–usage

簡潔なヘルプメッセージを表示して終了します。

–help

詳細なヘルプメッセージを表示して終了します。

DESCRIPTION¶

Cヘッダーやソースファイル（C_FILE）を、..parsed-literalブロックでインクルードされるReStructured Textに変換し、APIを説明するドキュメンテーションファイルとのクロスリファレンスを生成します。オプションでEXCEPTIONS_FILEを指定して、特定の要素を無視するか、非デフォルトの参照にリンクするように指定できます。

出力は（OUT_FILE）に書き込まれます。

定義、関数、構造体、typedef、列挙型および列挙シンボルを識別し、すべてのクロスリファレンスを生成できます。また、Linux ioctlを指定するための#defineも区別できます。

EXCEPTIONS_FILEには2種類のステートメントが含まれます: 無視 または replace.

無視タグの構文は:

無視 type 名前

以下の 無視 が、特定の 名前 タイプのシンボルに対してクロスリファレンスを生成しないことを意味します。 type.

置き換えタグの構文は:

replace type 名前 new_value

以下の replace が、特定の 名前 タイプのシンボルに対してクロスリファレンスを生成しないことを意味します。 typeに対してクロスリファレンスを生成しますが、デフォルトの置き換えルールではなく new_value.

を使用します。どちらのステートメントでも type は次のいずれかです:

ioctl

無視または置き換えステートメントは、ioctl定義のように:

#define VIDIOC_DBG_S_REGISTER _IOW(‘V’, 79, struct v4l2_dbg_register)

define

無視または置き換えステートメントは、C_FILE内の他の#defineにも適用されます。

typedef

無視または置き換えステートメントは、C_FILE内のtypedefステートメントにも適用されます。

struct

無視または置き換えステートメントは、C_FILE内の構造体ステートメントの名前にも適用されます。

enum

ignore または replace ステートメントは、C_FILE 内の enum ステートメントの名前に対して適用されます。

symbol

ignore または replace ステートメントは、C_FILE 内の enum 値の名前に対して適用されます。

replace ステートメントの場合、 new_value タイプに対して :c:type: への参照が自動的に使用されます。 typedef, enum および struct タイプに対して :ref: が使用されます。 ioctl, define および symbol タイプの参照タイプは、replace ステートメント内で明示的に定義することも可能です。

例¶

ignore define _VIDEODEV2_H

C_FILE 内の #define _VIDEODEV2_H を無視します。

ignore symbol PRIVATE

次の構造体の場合:

enum foo { BAR1, BAR2, PRIVATE };

PRIVATE に対してクロス参照を生成しません。 PRIVATE.

replace symbol BAR1 :c:type:`foo` replace symbol BAR2 :c:type:`foo`

次の構造体の場合:

enum foo { BAR1, BAR2, PRIVATE };

BAR1 および BAR2 の enum シンボルが、C ドメイン内の foo シンボルにクロス参照されるようになります。
