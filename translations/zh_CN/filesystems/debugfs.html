DebugFS

デバッグfs¶

Debugfsは、ユーザー空間から情報を取得するための内核開発者向けの簡単な方法です。procとは異なり、procはプロセスに関する情報のみを提供します。sysfsとは異なり、厳格な「1つのファイルに1つの値」のルールを持ちません。debugfsにはルールがまったくありませんので、開発者はここに望む情報を自由に配置できます。debugfsファイルシステムは安定したABIインターフェースとして利用できません。理論的には、debugfsがファイルをエクスポートする際には制約がありませんが、[1]実際には常にそう簡単ではありません。debugfsインターフェースも、必要に応じて設計し、インターフェースを変更しないようにすることが望ましいです。

debugfsは通常、以下のコマンドでインストールされます:

mount -t debugfs none /sys/kernel/debug

（または同等の/etc/fstab行）。debugfsのルートディレクトリはデフォルトでrootユーザーのみがアクセス可能です。ファイルツリーへのアクセスを変更するには、「uid」「gid」「mode」マウントオプションを使用してください。注意点として、debugfs APIはGPLプロトコルに従ってモジュールにエクスポートされます。

debugfsを使用するコードは<linux/debugfs.h>を含める必要があります。その後、少なくとも1つのディレクトリを作成してdebugfsファイルを保存します:

struct dentry *debugfs_create_dir(const char *name, struct dentry *parent);

成功した場合、この呼び出しは指定された親ディレクトリ下にnameという名前のディレクトリを作成します。parentパラメータが空の場合、debugfsのルートディレクトリに作成されます。ディレクトリ作成成功時に返される値は、dentry構造体へのポインタです。このdentry構造体のポインタは、ディレクトリ内にファイルを作成（および最終的にクリーンアップ）するために使用できます。ERR_PTR（-ERROR）の返却値はエラーを示し、ERR_PTR（-ENODEV）が返却された場合は、カーネルがdebugfsをサポートしていないため、以下の関数はすべて無効です。

debugfsディレクトリ内にファイルを作成する最も一般的な方法は:

struct dentry *debugfs_create_file(const char *name, umode_t mode,
                                   struct dentry *parent, void *data,
                                   const struct file_operations *fops);

ここで、nameは作成するファイルの名前、modeはファイルに与えるアクセス権、parentはファイルを保存するディレクトリへのポインタ、dataは生成されたinode構造体のi_privateフィールドに格納されるデータ、fopsはファイル操作関数のセットで、具体的なファイル操作の動作を実装します。少なくともread（）および/またはwrite（）操作は提供する必要があります。他の操作は必要に応じて追加できます。同様に、返却値は作成されたファイルのdentryポインタであり、エラーの場合はERR_PTR（-ERROR）が返却され、システムがdebugfsをサポートしていない場合はERR_PTR（-ENODEV）が返却されます。初期サイズのファイルを作成するには、以下の関数を使用できます:

struct dentry *debugfs_create_file_size(const char *name, umode_t mode,
                            struct dentry *parent, void *data,
                            const struct file_operations *fops,
                            loff_t file_size);

file_sizeは初期ファイルサイズです。他のパラメータはdebugfs_create_file関数と同様です。

多くの場合、複数のファイル操作を手動で作成する必要はありません。単純なケースでは、debugfsコードが多くの補助関数を提供しています。単一の整数値を含むファイルは以下のいずれかを使用して作成できます:

void debugfs_create_u8(const char *name, umode_t mode,
                       struct dentry *parent, u8 *value);
void debugfs_create_u16(const char *name, umode_t mode,
                        struct dentry *parent, u16 *value);
struct dentry *debugfs_create_u32(const char *name, umode_t mode,
                                  struct dentry *parent, u32 *value);
void debugfs_create_u64(const char *name, umode_t mode,
                        struct dentry *parent, u64 *value);

これらのファイルは指定された値を読み書きできます。読み書きをサポートしないファイルの場合は、modeパラメータのビットを必要に応じて設定してください。これらのファイルの値は十進法で表示され、十六進法を使用する場合は以下の関数を使用できます:

void debugfs_create_x8(const char *name, umode_t mode,
                       struct dentry *parent, u8 *value);
void debugfs_create_x16(const char *name, umode_t mode,
                        struct dentry *parent, u16 *value);
void debugfs_create_x32(const char *name, umode_t mode,
                        struct dentry *parent, u32 *value);
void debugfs_create_x64(const char *name, umode_t mode,
                        struct dentry *parent, u64 *value);

这些功能只有在开发人员知道导出值的大小的时候才有用。某些数据类型在不同的架构上 有不同的宽度，这样会使情况变得有些复杂。在这种特殊情况下可以使用以下函数:

void debugfs_create_size_t(const char *name, umode_t mode,
                           struct dentry *parent, size_t *value);

予想通り、この関数はsize_t型の変数を表すdebugfsファイルを作成します。

同样地，也有导出无符号长整型变量的函数，分别以十进制和十六进制表示如下:

struct dentry *debugfs_create_ulong(const char *name, umode_t mode,
                                    struct dentry *parent,
                                    unsigned long *value);
void debugfs_create_xul(const char *name, umode_t mode,
                        struct dentry *parent, unsigned long *value);

ブール値は以下の方法でdebugfsに配置できます:

struct dentry *debugfs_create_bool(const char *name, umode_t mode,
                                   struct dentry *parent, bool *value);

读取结果文件将产生Y（对于非零值）或N，后跟换行符写入的时候，它只接受大写或小写 值或1或0。任何其他输入将被忽略。

同様に、atomic_t型の値もdebugfsに配置できます:

void debugfs_create_atomic_t(const char *name, umode_t mode,
                             struct dentry *parent, atomic_t *value)

このファイルを読み込むとatomic_t値が取得でき、このファイルに書き込むとatomic_t値を設定できます。

另一个选择是通过以下结构体和函数导出一个任意二进制数据块:

struct debugfs_blob_wrapper {
    void *data;
    unsigned long size;
};

struct dentry *debugfs_create_blob(const char *name, umode_t mode,
                                   struct dentry *parent,
                                   struct debugfs_blob_wrapper *blob);

このファイルを読み込むと、ポインタが指すdebugfs_blob_wrapper構造体のデータが返されます。一部のドライバでは、「blobs」を用いて複数行の静的フォーマットテキストを返す簡単な方法として使用しています。この関数はバイナリ情報をエクスポートするためのものですが、マスターブランチにはこのようなコードは見られません。注意点として、debugfs_create_blob（）コマンドで作成されたすべてのファイルは読み取り専用です。

debugfsにレジスタブロックをダンプする場合は、以下の関数を使用できます。開発中にこのような操作を行うことがよくありますが、このようなデバッグコードはマスターブランチにアップロードされることがほとんどありません:

struct debugfs_reg32 {
    char *name;
    unsigned long offset;
};

struct debugfs_regset32 {
    struct debugfs_reg32 *regs;
    int nregs;
    void __iomem *base;
};

struct dentry *debugfs_create_regset32(const char *name, umode_t mode,
                                 struct dentry *parent,
                                 struct debugfs_regset32 *regset);

void debugfs_print_regs32(struct seq_file *s, struct debugfs_reg32 *regs,
                     int nregs, void __iomem *base, char *prefix);

「base」パラメータは0になる可能性がありますが、reg32配列を構築するには__stringifyを使用する必要があります。実際には、多くのレジスタ名（マクロ）はレジスタブロックのベースアドレスからのバイトオフセットです。

debugfsにu32配列をダンプする場合は、以下の関数を使用してファイルを作成できます:

void debugfs_create_u32_array(const char *name, umode_t mode,
                   struct dentry *parent,
                   u32 *array, u32 elements);

「array」パラメータはデータを提供し、「elements」パラメータは配列内の要素数です。注意点として、配列作成後は配列サイズを変更できません。

デバイスに関連するseq_fileを作成するための関数があります:

struct dentry *debugfs_create_devm_seqfile(struct device *dev,
                             const char *name,
                             struct dentry *parent,
                             int (*read_fn)(struct seq_file *s,
                                     void *data));

「dev」パラメータはdebugfsファイルに関連するデバイスで、「read_fn」はseq_fileの内容を印刷するときにコールバックされる関数ポインタです。

还有一些其他的面向目录的函数:

struct dentry *debugfs_rename(struct dentry *old_dir,
                              struct dentry *old_dentry,
                              struct dentry *new_dir,
                              const char *new_name);

struct dentry *debugfs_create_symlink(const char *name,
                                      struct dentry *parent,
                                      const char *target);

调用debugfs_rename()既存のdebugfsファイルをリネームし、必要に応じてディレクトリを切り替えることができます。new_nameは関数呼び出し前に存在してはいけません。返却値はold_dentryで、更新された情報を含みます。シンボリックリンクはdebugfs_create_symlink（）で作成できます。

すべてのdebugfsユーザーが考慮すべき点は:

debugfsは自動的に作成したディレクトリをクリーンアップしません。モジュールがdebugfsディレクトリを明示的に削除せずにアンロードされると、多くのワイルドポインタが残り、システムの不安定性を引き起こします。したがって、すべてのdebugfsユーザー（モジュールとしてビルド可能なユーザーを含む）は、モジュールアンロード時に作成したすべてのファイルとディレクトリを削除する準備をしなければなりません。ファイルは以下の方法で削除できます:

void debugfs_remove(struct dentry *dentry);

dentry値はNULLまたはエラー値である場合、ファイルは削除されません。

以前は、カーネル開発者がdebugfsを使用する際には、作成したすべてのdentryポインタを記録し、最終的にすべてのファイルをクリーンアップする必要がありました。しかし、現在ではdebugfsユーザーは以下の関数を呼び出して、以前に作成したファイルを再帰的にクリーンアップできます:

void debugfs_remove_recursive(struct dentry *dentry);

上記の関数にトップレベルディレクトリのdentryを渡すと、そのディレクトリ以下のすべての階層が削除されます。
