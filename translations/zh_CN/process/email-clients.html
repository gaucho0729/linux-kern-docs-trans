Linuxメールクライアント設定情報¶

Git¶

现在大多数开发人员使用 git send-email 而不是常规的电子邮件客户端。这方面 的手册非常好。在接收端，维护人员使用 git am 加载补丁。

如果你是 git 新手，那么把你的第一个补丁发送给你自己。将其保存为包含所有 标题的原始文本。运行 git am raw_email.txt ，然后使用 git log 查看更 改日志。如果工作正常，再将补丁发送到相应的邮件列表。

普通配置¶

Linux内核のパッチはメールで提出されるが、パッチをメール本文の埋め込みテキストとして送信するのが望ましい。一部のメンテナは添付ファイルを受け取るが、添付ファイルの内容形式は"text/plain"でなければならない。しかし、添付ファイルは推奨されていない。なぜなら、コメントの過程でパッチの参照部分が扱いにくくなるからである。

Linux内核のパッチを送信するメールクライアントは、パッチを送信する際、テキストの原始的な状態を維持するべきである。例えば、タブやスペースを変更したり削除したりしてはならない。また、各行の先頭や末尾でも同様である。

"format=flowed"モードでパッチを送信しないでほしい。これは予期せぬ有害な改行を引き起こす可能性がある。

不要让你的邮件客户端进行自动换行。这样也会破坏你的补丁。

メールクライアントはテキストの文字コードを変更してはならない。送信するパッチはASCIIまたはUTF-8のエンコーディングでなければならない。UTF-8でメールを送信することで、文字コードの問題を回避できる。

メールクライアントは"References:"または"In-Reply-To:"ヘッダーを形成し維持すべきである。これにより、メールのトピックが中断されない。

コピー＆ペースト（または切り取り＆貼り付け）は通常、パッチには使えない。なぜなら、タブがスペースに変換されるからである。xclipboard、xclip、xcutselを使うことは可能だが、テストするか、使用を避けるのが望ましい。

PGP/GPG署名付きのメールにパッチを含めないでほしい。これにより多くのスクリプトがパッチを読み取れず適用できない。この問題は修正可能である。

内核メールリストにパッチを送信する前に、自分宛てにパッチを送信してみる。受信したメールを保存し、"patch"コマンドで適用して成功すれば、内核メールリストに送信する。

一些邮件客户端提示¶

Linux内核にパッチを送信するためのMUA（メールユーザーエージェント）の設定に関する詳細なヒントを以下に示す。これらはすべてのソフトウェアパッケージの設定を網羅しているわけではない。

説明： TUI = テキストベースのユーザーインターフェース GUI = グラフィカルユーザーインターフェース

Alpine (TUI)¶

設定オプション： "Sending Preferences"セクションで：

  • "Do Not Send Flowed Text"を有効にする

  • "Strip Whitespace Before Sending"を無効にする

メールを書く際、パッチが表示される場所にカーソルを置き、CTRL-Rを押すことで指定されたパッチファイルをメール本文に埋め込む。

Evolution (GUI)¶

一些开发者成功的使用它发送补丁

メールオプションで"Preformat"を選択

フォーマット→ヘッダー→プレフォーマット（Ctrl-7）またはツールバーから

然后使用：

挿入→テキストファイル…（Alt-n x）でパッチファイルを挿入。

また、"diff -Nru old.c new.c | xclip"を実行し、"Preformat"を選択した後、中ボタンで貼り付けることも可能。

Kmail (GUI)¶

一些开发者成功的使用它发送补丁。

HTML形式のデフォルト設定は適切である。HTMLを有効にしない。

当书写一封邮件的时候，在选项下面不要选择自动换行。唯一的缺点就是你在邮件中输入的任何文本 都不会被自动换行，因此你必须在发送补丁之前手动换行。最简单的方法就是启用自动换行来书写邮件， 然后把它保存为草稿。一旦你在草稿中再次打开它，它已经全部自动换行了，那么你的邮件虽然没有 选择自动换行，但是还不会失去已有的自动换行。

在邮件的底部，插入补丁之前，放上常用的补丁定界符：三个连字号(—)。

次に"Message"メニュー項目で"Insert File"を選択し、パッチファイルを選択する。また、メールクライアントのツールバーに"insert file"アイコンを追加するオプションもある。

GPGで添付ファイルをマークしても安全だが、内嵌テキストのパッチにはGPGを避けるのが望ましい。GPGから7ビット符号化で抽出すると、内嵌テキストの署名パッチが複雑になる。

パッチを添付ファイルとして送信する場合は、添付ファイルを右クリックし、プロパティを選択して"Suggest automatic display"をチェック。これにより、読者に内嵌添付ファイルが見やすくなる。

内嵌テキストのパッチを保存する際、メールリストパネルからパッチを含むメールを選択し、右クリックして"save as"を選択。正しい形式で構成されたメールであれば、変更していない状態で保存できる。メールを独自のウィンドウで表示している場合、保存オプションは存在しない。これはkmailのbugzillaに報告されたバグで、修正される予定である。メールはユーザー専用の読み取り権限で保存されるため、他の場所にコピーする場合は、グループや全体の読み取り権限に変更する必要がある。

Lotus Notes (GUI)¶

不要使用它。

Mutt (TUI)¶

多くのLinux開発者はmuttクライアントを使用しており、その動作は非常に良好である。

muttは編集器を標準で備えていないため、どの編集器を使用しても自動改行を有効にしないべきである。ほとんどの編集器は"insert file"オプションを備えており、ファイルの内容を変更することなく挿入できる。

vimをmuttの編集器として使用する場合：

set editor="vi"

xclipを使用する場合は、:set pasteを入力し、中ボタンまたはShift-Insertで貼り付け、または:r filenameを実行する。

パッチを内嵌テキストとして送信する場合、(a)ttachは"set paste"を含まない場合にうまく動作する。

你可以通过 git format-patch パッチを生成し、muttで送信する：

$ mutt -H 0001-some-bug-fix.patch

設定オプション： デフォルト設定で動作するのが望ましい。しかし、"send_charset"を"us-ascii::utf-8"に設定しておくと良い。

muttは高度にカスタマイズ可能である。以下はmuttをGmail経由でパッチを送信するための最小限の設定例：

# .muttrc
# ================  IMAP ====================
set imap_user = 'yourusername@gmail.com'
set imap_pass = 'yourpassword'
set spoolfile = imaps://imap.gmail.com/INBOX
set folder = imaps://imap.gmail.com/
set record="imaps://imap.gmail.com/[Gmail]/Sent Mail"
set postponed="imaps://imap.gmail.com/[Gmail]/Drafts"
set mbox="imaps://imap.gmail.com/[Gmail]/All Mail"

# ================  SMTP  ====================
set smtp_url = "smtp://username@smtp.gmail.com:587/"
set smtp_pass = $imap_pass
set ssl_force_tls = yes # Require encrypted connection

# ================  Composition  ====================
set editor = `echo \$EDITOR`
set edit_headers = yes  # See the headers when editing
set charset = UTF-8     # value of $LANG; also fallback for send_charset
# Sender, email address, and sign-off line must match
unset use_domain        # because joe@localhost is just embarrassing
set realname = "YOUR NAME"
set from = "username@gmail.com"
set use_from = yes

muttのドキュメントにはさらに詳しい情報がある：

http://dev.mutt.org/trac/wiki/UseCases/Gmail

http://dev.mutt.org/doc/manual.html

Pine (TUI)¶

Pineは以前、スペース削減の問題があったが、これらは現在修正されている。

可能であれば、alpine（Pineの後継者）を使用することを推奨する。

設定オプション： 最新バージョンではフローテキストを削除する必要がある。"no-strip-whitespace-before-send"オプションも必要である。

Sylpheed (GUI)¶

  • 内嵌文本可以很好的工作（或者使用附件）。

  • 允许使用外部的编辑器。

  • 对于目录较多时非常慢。

  • SSL接続でない場合、TLS SMTP認証が使用できない。

  • 作成ウィンドウには有用なruler barがある。

  • 给地址本中添加地址就不会正确的了解显示名。

Thunderbird (GUI)¶

デフォルトではthunderbirdがテキストを破損させるが、いくつかの方法でこれを改善できる。

  • ユーザーアカウント設定の「作成とアドレス指定」セクションでは、「HTML形式でメッセージを編集」の選択を避けてください。

  • Thunderbirdの設定を編集し、改行を防ぐようにしてください：user_pref("mailnews.wraplength", 0);

  • Thunderbirdの設定を編集し、「format=flowed」形式の使用を無効にしてください：user_pref("mailnews.send_plaintext_flowed", false);

  • Thunderbirdを事前にフォーマットモードに設定してください。HTML形式がデフォルトで設定されている場合、タイトルバーのドロップダウンメニューから「Preformat」を選択するだけで簡単です。テキスト形式がデフォルトの場合、一時的にHTML形式に変更して新しいメッセージを書いた後、再びテキスト形式に戻す必要があります（それ以外に改行が発生します）。実行方法は、送信アイコンにShiftキーを押し、HTML形式に変更した後、タイトルバーのドロップダウンメニューから「Preformat」を選択してください。

  • 外部エディタを使用可能にする：Thunderbirdにパッチを適用する最も簡単な方法は、「外部エディタ」拡張機能をインストールし、お気に入りの$EDITORを使用してテキストにパッチを読み込むかマージする方法です。実行方法は、拡張機能をダウンロードしてインストールし、次に「表示→ツールバー→カスタマイズ…」をクリックしてキーを設定し、メッセージを書く際にはそのキーをクリックするだけです。

動作します。『ファイルの挿入…』または外部エディタを使用してください。¶

使用可能です。『ファイルの挿入…』または外部エディタを使用してください。

パッチの送信には動作しません。¶

不要使用它发送补丁。

Gmailウェブクライアントはタブをスペースに自動的に変換します。

虽然制表符转换为空格问题可以被外部编辑器解决，同时它还会使用回车换行把每行拆分为78个字符。

別の問題として、GmailはASCII文字以外の文字をbase64エンコードに変換します。これにより、ヨーロッパ人の名前のように見えます。
