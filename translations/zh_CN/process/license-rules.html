Linuxカーネルライセンス規則¶

Linux内核はLICENSES/preferred/GPL-2.0で提供されるGNU一般公共ライセンスバージョン2（GPL-2.0）の条項に基づき提供され、LICENSES/exceptions/Linux-syscall-noteで例外的に記載されたシステムコール（例：COPYINGファイルに記載されているもの）が明示されています。

此文档文件提供了如何对每个源文件进行注释以使其许可证清晰明确的说明。 它不会取代内核的许可证。

内核ソースコード全体はCOPYINGファイルで記載されているライセンスに適用されますが、個々のソースファイルはGPL-2.0と互換可能な異なるライセンスを適用することがあります:

GPL-1.0+ : GNU通用公共许可证v1.0或更高版本
GPL-2.0+ : GNU通用公共许可证v2.0或更高版本
LGPL-2.0 : 仅限GNU库通用公共许可证v2
LGPL-2.0+: GNU 库通用公共许可证v2或更高版本
LGPL-2.1 : 仅限GNU宽通用公共许可证v2.1
LGPL-2.1+: GNU宽通用公共许可证v2.1或更高版本

さらに、個々のファイルは二重ライセンスの下で提供されることがあります。例えば、GPLの変体やBSD、MITなどのライセンスが含まれます。

ユーザー空間API（UAPI）ヘッダーファイルは、ユーザー空間プログラムとカーネルのインターフェースを記述しており、これは特別なケースです。内核のCOPYINGファイルに記載されている注記によると、システムコールインターフェースは明確な境界であり、これを使用してカーネルと通信するソフトウェアにGPLの要件を拡張しません。UAPIヘッダーファイルはLinux内核上で実行される実行ファイルのソースコードに必ず含まれるため、この例外は特別なライセンス記述で明記する必要があります。

表达源文件许可证的常用方法是将匹配的样板文本添加到文件的顶部注释中。由于 格式，拼写错误等，这些“样板”很难通过那些在上下文中使用的验证许可证合规性 的工具。

テンプレートテキストの代替方法として、各ソースファイルにソフトウェアパッケージデータ交換（SPDX）ライセンス識別子を使用することも可能です。SPDXライセンス識別子は機械が解析可能な形式であり、ファイル内容のライセンスを正確に表します。SPDXライセンス識別子はLinux FoundationのSPDXワーキンググループが管理しており、業界全体、ツールベンダー、法務チームなどから広く合意されています。詳細については https://spdx.org/

Linux内核はすべてのソースファイルに正確なSPDX識別子を必要とします。内核で使用される有効な識別子は 许可标识符 一节中进行了解释，并且已可以在 https://spdx.org/licenses/ の公式SPDXライセンス一覧から取得され、ライセンス本文も添付されています。

许可标识符语法¶

1.安置:

   カーネルファイル内のSPDXライセンス識別子は、コメントを含むことができるファイルの最初の行に追加する必要があります。ほとんどのファイルではこれは最初の行ですが、最初の行に’#!PATH_TO_INTERPRETER’が必要なスクリプトを除きます。このようなスクリプトではSPDX識別子は第二行に配置されます。

SPDX識別子は第二行に配置されます。


  1. 风格:

    SPDXライセンス識別子はコメントとして追加されます。コメントのスタイルはファイルタイプによって異なります:

    C source: // SPDX-License-Identifier: <SPDX License Expression>
C header: /* SPDX-License-Identifier: <SPDX License Expression> */
ASM:      /* SPDX-License-Identifier: <SPDX License Expression> */
scripts:  # SPDX-License-Identifier: <SPDX License Expression>
.rst:     .. SPDX-License-Identifier: <SPDX License Expression>
.dts{i}:  // SPDX-License-Identifier: <SPDX License Expression>

    特定のツールが標準のコメントスタイルを処理できない場合、ツールが受け入れる対応するコメントメカニズムを使用する必要があります。これはCヘッダーファイルで「/**/」スタイルのコメントを使用する理由です。過去には生成された.ldsファイルを使用する際、'ld'がC++コメントを解析できずビルドが破損する問題がありました。この問題はすでに修正されていますが、依然として古いアセンブリツールがC++スタイルのコメントを処理できない場合があります。


  1. 句法:

    <SPDXライセンス表現>はSPDXライセンスリスト内のSPDX短形式ライセンス識別子であり、ライセンス例外が適用される場合、「WITH」で区切られた2つのSPDX短形式ライセンス識別子の組み合わせです。複数のライセンスが適用される場合、表現は論理演算子「AND」「OR」でサブ表現を区切り、「（」、「）」で括られます。

    「またはより高い」オプションを持つ[L]GPLなどのライセンスの識別子は「+」を用いて「またはより高い」オプションを表します。:

    // SPDX-License-Identifier: GPL-2.0+
// SPDX-License-Identifier: LGPL-2.1+

    修正が必要なライセンスがある場合は「WITH」を使用します。例えば、linuxカーネルUAPIファイルは以下の表現を使用します:

    // SPDX-License-Identifier: GPL-2.0 WITH Linux-syscall-note
// SPDX-License-Identifier: GPL-2.0+ WITH Linux-syscall-note

    カーネル内で「WITH」例外が適用される他の例は以下の通りです:

    // SPDX-License-Identifier: GPL-2.0 WITH mif-exception
// SPDX-License-Identifier: GPL-2.0+ WITH GCC-exception-2.0

    例外只能与特定的许可证标识符一起使用。有效的许可证标识符列在异常文本文件 的标记中。有关详细信息，请参阅 许可标识符 一章中的 例外 。

    二重ライセンスでかつどちらか一方のライセンスのみ選択される場合、「OR」を使用します。例えば、一部のdtsiファイルは二重ライセンス下で利用可能です:

    // SPDX-License-Identifier: GPL-2.0 OR BSD-3-Clause

    内核中双许可文件中许可表达式的示例:

    // SPDX-License-Identifier: GPL-2.0 OR MIT
// SPDX-License-Identifier: GPL-2.0 OR BSD-2-Clause
// SPDX-License-Identifier: GPL-2.0 OR Apache-2.0
// SPDX-License-Identifier: GPL-2.0 OR MPL-1.1
// SPDX-License-Identifier: (GPL-2.0 WITH Linux-syscall-note) OR MIT
// SPDX-License-Identifier: GPL-1.0+ OR BSD-3-Clause OR OpenSSL

    複数のライセンスが適用され、そのすべての条項がファイルの使用に適用される場合、「AND」を使用します。例えば、コードが他のプロジェクトから継承されており、すでにカーネルに含める許可が与えられていたが、元のライセンス条項を保持する必要がある場合:

    // SPDX-License-Identifier: (GPL-2.0 WITH Linux-syscall-note) AND MIT

    另一个需要遵守两套许可条款的例子是:

    // SPDX-License-Identifier: GPL-1.0+ AND LGPL-2.1+

许可标识符¶

当前使用的许可证以及添加到内核的代码许可证可以分解为：

  1. 优先许可:

    应尽可能使用这些许可证，因为它们已知完全兼容并广泛使用。这些许可证在内核 目录:

    LICENSES/preferred/

    此目录中的文件包含完整的许可证文本和 元标记 ファイル名はSPDXライセンス識別子と一致し、これはソースファイルに適用されるライセンスです。

    例如:

    LICENSES/preferred/GPL-2.0

    GPLv2ライセンステキストと必要なメタタグを含みます:

    LICENSES/preferred/MIT

    MITライセンス本文と必要なメタタグを含む

    元标记:

    许可证文件中必须包含以下元标记：

    • 有効なライセンス識別子:

      一行或多行, 声明那些许可标识符在项目内有效, 以引用此特定许可的文本。通

    常这是一个有效的标识符，但是例如对于带有’或更高’选项的许可证，两个标识 符都有效。

    • SPDX-URL:

      ライセンスに関する追加情報を含むSPDXページのURL。

    • 使用ガイドライン:

      推奨される自由形式のテキストを使用してください。このテキストにはSPDXライセンス識別子の正しい例を含める必要があります。なぜなら、これらは 许可标识符语法 指南放入源文件中。

    • License-Text:

      此标记之后的所有文本都被视为原始许可文本

    文件格式示例:

    Valid-License-Identifier: GPL-2.0
Valid-License-Identifier: GPL-2.0+
SPDX-URL: https://spdx.org/licenses/GPL-2.0.html
Usage-Guide:
  To use this license in source code, put one of the following SPDX
  tag/value pairs into a comment according to the placement
  guidelines in the licensing rules documentation.
  For 'GNU General Public License (GPL) version 2 only' use:
    SPDX-License-Identifier: GPL-2.0
  For 'GNU General Public License (GPL) version 2 or any later version' use:
    SPDX-License-Identifier: GPL-2.0+
License-Text:
  Full license text

    SPDX-License-Identifier: MIT
SPDX-URL: https://spdx.org/licenses/MIT.html
Usage-Guide:
  To use this license in source code, put the following SPDX
  tag/value pair into a comment according to the placement
  guidelines in the licensing rules documentation.
    SPDX-License-Identifier: MIT
License-Text:
  Full license text

  1. 不推荐的许可证:

    这些许可证只应用于现有代码或从其他项目导入代码。这些许可证在内核目录:

    LICENSES/other/

    此目录中的文件包含完整的许可证文本和 元标记 ファイル名はSPDXライセンス識別子と一致し、これはソースファイルに適用されるライセンスです。

    例如:

    LICENSES/other/ISC

    包含国际系统联合许可文本和所需的元标签:

    LICENSES/other/ZLib

    ZLIBライセンス本文と必要なメタタグを含む

    元标签:

    “其他”许可证的元标签要求与 优先许可 的要求相同。

    文件格式示例:

    Valid-License-Identifier: ISC
SPDX-URL: https://spdx.org/licenses/ISC.html
Usage-Guide:
  Usage of this license in the kernel for new code is discouraged
  and it should solely be used for importing code from an already
  existing project.
  To use this license in source code, put the following SPDX
  tag/value pair into a comment according to the placement
  guidelines in the licensing rules documentation.
    SPDX-License-Identifier: ISC
License-Text:
  Full license text

  1. 例外:

    某些许可证可以修改，并允许原始许可证不具有的某些例外权利。这些例外在 内核目录:

    LICENSES/exceptions/

    此目录中的文件包含完整的例外文本和所需的 例外元标记 。

    例如:

    LICENSES/exceptions/Linux-syscall-note

    Linux内核のCOPYINGファイルで記録されているLinuxシステムコール例外を含む。このファイルはUAPIヘッダーファイルに使用される。例えば:

    LICENSES/exceptions/GCC-exception-2.0

    GCCの「リンク例外」を含む。これは、この例外が付与されたファイルのコンパイルバージョンと、ライセンスにかかわらずどのバイナリファイルともリンクを許可する。これはGPL互換でないソースコードから実行可能なバイナリファイルを生成するために必要な。

    例外元标记:

    以下元标记必须在例外文件中可用：

    • SPDX-Exception-Identifier:

      SPDXライセンス識別子と共に使用可能な例外識別子。

    • SPDX-URL:

      例外に関する追加情報を含むSPDXページのURL。

    • SPDX-Licenses:

      例外が利用可能なSPDXライセンス識別子の一覧（カンマで区切る）。

    • 使用ガイドライン:

      推奨される自由形式のテキストを使用してください。テキストの後にはSPDXライセンス識別子の正しい例を追加する必要があります。なぜなら、これらは 许可标识符语法 指南放入源文件中。

    • Exception-Text:

      此标记之后的所有文本都被视为原始异常文本

    文件格式示例:

    SPDX-Exception-Identifier: Linux-syscall-note
SPDX-URL: https://spdx.org/licenses/Linux-syscall-note.html
SPDX-Licenses: GPL-2.0, GPL-2.0+, GPL-1.0+, LGPL-2.0, LGPL-2.0+, LGPL-2.1, LGPL-2.1+
Usage-Guidance:
  This exception is used together with one of the above SPDX-Licenses
  to mark user-space API (uapi) header files so they can be included
  into non GPL compliant user-space application code.
  To use this exception add it with the keyword WITH to one of the
  identifiers in the SPDX-Licenses tag:
    SPDX-License-Identifier: <SPDX-License> WITH Linux-syscall-note
Exception-Text:
  Full exception text

    SPDX-Exception-Identifier: GCC-exception-2.0
SPDX-URL: https://spdx.org/licenses/GCC-exception-2.0.html
SPDX-Licenses: GPL-2.0, GPL-2.0+
Usage-Guidance:
  The "GCC Runtime Library exception 2.0" is used together with one
  of the above SPDX-Licenses for code imported from the GCC runtime
  library.
  To use this exception add it with the keyword WITH to one of the
  identifiers in the SPDX-Licenses tag:
    SPDX-License-Identifier: <SPDX-License> WITH GCC-exception-2.0
Exception-Text:
  Full exception text

すべてのSPDXライセンス識別子および例外はLICENSESサブディレクトリに該当するファイルを持たなければなりません。これはツールの検証（例: checkpatch.pl）を許可し、ソースからライセンスを読み取って抽出する準備を整えるために必要なため、これはさまざまなFOSS組織が推奨しています。 FSFE REUSEイニシアチブ.

模块许可¶

ロード可能なカーネルモジュールにはMODULE_LICENSE（）メタタグが必要です。このメタタグは正しいソースコードライセンス情報（SPDX-License-Identifier）を代替するものではなく、またモジュールのソースコードの正確なライセンスを示すまたは決定するものではありません。

此标记的唯一目的是提供足够的信息，该模块是否是自由软件或者是内核模块加 载器和用户空间工具的专有模块。

MODULE_LICENSE（）の有効なライセンス文字列は:

「GPL」

このモジュールはGPLバージョン2に基づいてライセンスされています。これはGPL-2.0やGPL-2.0-or-laterなどの違いを示すものではありません。正確なライセンス情報は、対応するソースファイル内のライセンス情報によってのみ決定されます。

「GPL v2」

「GPL」と同じです。これは歴史的な理由により存在しています。

「GPL and additional rights」

モジュールソースがGPL v2変体とMITライセンスで二重ライセンスされていた歴史的な変体を表します。新規コードでは使用しないでください。

「Dual MIT/GPL」

モジュールソースがGPL v2変体またはMITライセンスを選択して二重ライセンスされている正しい表現方法です。

「Dual BSD/GPL」

このモジュールはGPL v2変体またはBSDライセンスを選択して二重ライセンスされています。BSDライセンスの正確な変体は、対応するソースファイル内のライセンス情報によってのみ決定されます。

「Dual MPL/GPL」

このモジュールはGPL v2変体またはMozilla Public License（MPL）を選択して二重ライセンスされています。MPLライセンスの正確な変体は、対応するソースファイル内のライセンス情報によってのみ決定されます。

「Proprietary」

このモジュールは専有ライセンスに基づいています。この文字列は専有の第三者モジュールにのみ使用し、カーネルツリーにソースコードを持つモジュールには使用できません。このようにマークされたモジュールはロード時に'P'タグでカーネルを汚染し、カーネルモジュールローダーはこれらのモジュールをEXPORT_SYMBOL_GPL（）でエクスポートされたシンボルにリンクしないでください。
