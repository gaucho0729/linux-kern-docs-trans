導入¶

Linux カーネルは Sphinx ドキュメントをファイルから生成する際に使用します reStructuredText が含まれているフォルダから Documentation. HTML または PDF 形式のドキュメントを生成するには、コマンドを使用してください make htmldocs o make pdfdocs. 生成されたドキュメントはフォルダに表示されます Documentation/output.

reStructuredText ファイルには、ドキュメントコメントや kernel-doc 型のコメントをソースファイルから含めるためのディレクティブが含まれています。通常、これらのコメントは関数や型、コードのアーキテクチャを説明するために使用されます。kernel-doc 型のコメントは特別な構造とフォーマットを持ちますが、それ以外は reStructuredText と同様に処理されます。

さらに、フォルダにはテキスト形式のドキュメントが数千あります。これらの中には、時間とともに reStructuredText 形式に変換されるものもありますが、大半はテキスト形式のまま残ります。 DocumentationDocumentation/ フォルダ内のファイルに使用される ReST マークアップは、バージョン 1.3 またはそれ以降の Sphinx で処理されるように設計されています。

画像の生成¶

カーネルドキュメンテーションの生成メカニズムには、Graphviz および SVG 形式の画像を処理できる拡張機能が含まれています（詳しくは 図と画像).

この機能を有効にするには、Graphviz と ImageMagick の両方をインストールする必要があります。これらのパッケージがインストールされていない場合でも、ドキュメンテーション生成システムは動作しますが、結果には画像が含まれません。

Sphinxドキュメンテーションの生成¶

HTML または PDF 形式でドキュメンテーションを生成するには、それぞれのコマンドを実行します make htmldocs o make pdfdocs. 他のフォーマットでもドキュメンテーションを生成できます。詳細については、コマンドを実行してください make help. 生成されたドキュメンテーションは以下のようなサブフォルダにあります Documentation/output.

もちろん、ドキュメンテーションを生成するには、Sphinx (sphinx-build) をインストールする必要があります。Se disponibile, il tema Read the Docs Sphinx で使用され、より読みやすい HTML ドキュメンテーションを取得できます。PDF 形式のドキュメンテーションには、 XeLaTeX` e di ``convert(1) ImageMagick で利用可能（https://www.imagemagick.org). 通常、これらのパッケージはすべて Linux ディストリビューションで利用可能で、パッケージ化されています。

Sphinxに追加のオプションを渡すには、make変数を使用してください SPHINXOPTS. Sphinxが生成中により詳細な出力を行うようにするには、次のコマンドを使用してください make SPHINXOPTS=-v htmldocs.

生成されたドキュメントを削除するには、次のコマンドを使用してください make cleandocs.

ドキュメンテーションの作成¶

新しいドキュメントを追加するのは簡単です:

  1. ファイルを追加してください .rst サブディレクトリ内に Documentation

  2. インデックスに参照を追加してください (Sphinxのメイン) in Documentation/index.rst.

これは、シンプルなドキュメント（現在読んでいるドキュメントなど）には十分ですが、より複雑なドキュメントには、専用のサブディレクトリを作成すること（既存のサブディレクトリを使用することも可）が推奨されます。例えば、グラフィックサブシステムはサブディレクトリ Documentation/gpu; このドキュメントは複数のファイルに分割されており、 .rst およびインデックス index.rst (con un toctree 専用の) がメインインデックスで参照されています。

以下のドキュメントを参照してください Sphinx e reStructuredText 詳細な情報については以下のドキュメントを参照してください。特に、 reStructuredTextの入門マニュアル Sphinxは良い出発点です。さらに、いくつかの Sphinx用の特定のビルダー.

カーネルドキュメントのガイドライン¶

このセクションでは、カーネルドキュメントに関するいくつかのガイドラインを紹介します:

  • reStructuredTextの構文を過度に使用しないでください。ドキュメントはシンプルにしてください。ほとんどのドキュメントは、複数の形式への変換が可能な最小限の構造を持つシンプルなテキストにしてください。

  • reStructuredText形式に変換する際には、オリジナルの構造をできるだけ忠実に保つようにしてください。

  • ドキュメントを変換する際には、フォーマットの修正にとどまらず、コンテンツを更新してください。

  • 見出しレベルの装飾は以下の通りにしてください:

    1. = ドキュメントタイトルには上線を追加してください:

      ======
Titolo
======

    2. = 章には

      Capitoli
========

    3. - 節には

      Sezioni
-------

    4. ~ サブセクションには

      Sottosezioni
~~~~~~~~~~~~

    RSTは特定の順序を強制しません (装飾の数や順序を固定するのではなく、使用する順序は見つかった順序になります) ただし、主要なレベルの統一性があると、ドキュメントの読みやすさが向上します。

  • 固定フォントサイズのテキストブロック（例：コード例、ユースケースなど）を挿入するには、 :: 構文の強調が不要な場合、特に小さなフラグメントには .. code-block:: <language> 構文の強調が役立つ長いブロックには、コードをテキスト中に挿入する短いコードには `` を使用してください。

Cドメイン¶

The Sphinx Cドメイン C（denominato c）はC APIのドキュメンテーションに適しています。たとえば、関数のプロトタイプ：

.. c:function:: int ioctl( int fd, int request )

kernel-docのCドメインには追加機能があります。たとえば、よく使われる名前の関数に新しい参照名を割り当てることができます open o ioctl:

.. c:function:: int ioctl( int fd, int request )
   :name: VIDIOC_LOG_STATUS

関数名（たとえばioctl）はテキストに残りますが、参照名は ioctl a VIDIOC_LOG_STATUSから変わります。インデックスの項目も VIDIOC_LOG_STATUS.

関数については、参照を生成するために c:func: を使用する必要はありません。Sphinxのいくつかのマジックな拡張機能により、ドキュメンテーション生成システムが自動的に funzione() への参照をクロスリファレンスに変換します。ドキュメンテーションに c:func: が見つかった場合は、削除してください。

リスト形式のテーブル¶

リスト形式のテーブル（リストテーブル）を使用することをお勧めします。リスト形式のテーブルはリストのリストです。ASCIIアートに比べてテキスト形式のファイルでは読みにくいかもしれませんが、作成や編集が簡単で、変更の影響範囲が内容の変更に限定されるため利点があります。

リスト形式のテーブル flat-table はリストのリストと似ていますが、 list-table に追加機能を持っています：

  • column-span: 列スパンの役割 cspan セルが次の列にわたって拡張できます

  • raw-span: 行スパンの役割 rspan セルが次の行にわたって拡張できます

  • auto-span: 最右のセルが右にわたって拡張されます（セルが不足しているため）。オプション :fill-cells: でこの挙動を auto-span から auto-fillに変更できます。これは空のセルを自動的に挿入するためです。

オプション：

  • :header-rows: [int] ヘッダー行数

  • :stub-columns: [int] スタブ列数

  • :widths: [[int] [int] … ] 列幅

  • :fill-cells: 空のセルを自動的に生成する代わりに、不足しているセルを拡張します。

役割：

  • :cspan: [int] 次の列（morecols)

  • :rspan: [int] 次の行（morerows)

次の例はこのマーカーの使用方法を示しています。リストのリストの最初のレベルは 行です。リスト形式のテーブルでは、 行 に含まれるセルのリストのみを挿入できます。例外は 行 コメント )と ( .. リンク です。 (たとえば、参照先として :ref:`last row <last row>` / last row)

.. flat-table:: table title
   :widths: 2 1 1 3

   * - head col 1
     - head col 2
     - head col 3
     - head col 4

   * - column 1
     - field 1.1
     - field 1.2 with autospan

   * - column 2
     - field 2.1
     - :rspan:`1` :cspan:`1` field 2.2 - 3.3

   * .. _`it last row`:

     - column 3

以下のように表示されます：

table title¶

head col 1

head col 2

head col 3

head col 4

column 1

field 1.1

field 1.2 は auto span で

column 2

field 2.1

field 2.2 - 3.3

column 3

図と画像¶

画像を追加する場合は、ディレクティブを使用してください kernel-figure e kernel-image. たとえば、SVG形式の画像の図を挿入するには：

.. kernel-figure::  ../../../doc-guide/svg_image.svg
   :alt:    una semplice immagine SVG

   Una semplice immagine SVG

コアのディレクティブは、図や画像の形式をサポートしています DOT, 詳細については

  • DOT: http://graphviz.org/pdf/dotguide.pdf

  • Graphviz: http://www.graphviz.org/content/dot-language

小さな例（DOT例):

.. kernel-figure::  ../../../doc-guide/hello.dot
   :alt:    ciao mondo

   Esempio DOT

ディレクティブを通じて kernel-render 特定のコードを追加できます。たとえば、次の形式で DOT Graphvizの形式：

.. kernel-render:: DOT
   :alt: foobar digraph
   :caption: Codice **DOT** (Graphviz) integrato

   digraph foo {
    "bar" -> "baz";
   }

表示はインストールされたプログラムに依存します。Graphvizがインストールされている場合、ベクター画像が表示されます。それ以外の場合、rawコードはテキストブロックとして表示されます テキストブロック (統合されたDOT（Graphviz）コード).

ディレクティブ レンダリング ディレクティブのすべてのオプションを備えています figure、オプションの追加で caption。もし caption 値がある場合、ノード figure 追加されます。それ以外の場合、ノードが追加されます image。オプション caption 参照を追加する場合は必要です（SVGコードを統合).

コードの記述には SVG:

.. kernel-render:: SVG
   :caption: Integrare codice **SVG**
   :alt: so-nw-arrow

   <?xml version="1.0" encoding="UTF-8"?>
   <svg xmlns="http://www.w3.org/2000/svg" version="1.1" ...>
      ...
   </svg>
