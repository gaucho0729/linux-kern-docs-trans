Linuxカーネルのライセンスに関するルール¶

Linux Kernelは、GNU General Public License（GPL-2.0）の第2版の条件に基づいてリリースされています。このライセンスのコピーはLICENSES/preferred/GPL-2.0ファイルに含まれており、システムコールに関する例外はLICENSES/exceptions/Linux-syscall-noteに記載されています。これらすべての内容は COPYING ファイルに記載されています。 GNU General Public License (GPL-2.0)、このライセンスのコピーはLICENSES/preferred/GPL-2.0ファイルに含まれており、システムコールに関する例外はLICENSES/exceptions/Linux-syscall-noteに記載されています。これらすべての内容は COPYING ファイルに記載されています。

このドキュメントでは、各ソースファイルが明確かつ曖昧でないようライセンスされる方法について説明しています。これはLinux Kernelのライセンスを代替するものではありません。

COPYINGファイルに記載されているライセンスは、Linux Kernelのソースコード全体に適用されるため、個々のソースファイルは異なるライセンスを持つことができますが、これらはGPL-2.0と互換性がある必要があります：

GPL-1.0+  :  GNU General Public License v1.0 o successiva
GPL-2.0+  :  GNU General Public License v2.0 o successiva
LGPL-2.0  :  GNU Library General Public License v2
LGPL-2.0+ :  GNU Library General Public License v2 o successiva
LGPL-2.1  :  GNU Lesser General Public License v2.1
LGPL-2.1+ :  GNU Lesser General Public License v2.1 o successiva

この他に、個々のファイルはBSDやMITなどの許容ライセンスとGPLの互換バリアントを組み合わせた二重ライセンスで提供されることがあります。

ユーザー空間（UAPI）向けのAPIヘッダーファイルは、プログラムが使用するインターフェースを記述しており、特別なケースです。COPYINGファイルの注記によると、システムコールはGPLの制約の明確な境界であり、それ以降のプログラムの制約は適用されません。UAPIヘッダーファイルはLinux Kernel上で実行可能な任意のプログラムのソースコードにインクルードされる必要があるため、この例外は明記された特別条項で認められています。

ソースファイルのライセンスを示す最も一般的な方法は、ファイルの先頭に該当するライセンスのテキストブロックをコメントとして追加することです。ただし、フォーマットや誤字脱字などの理由により、ライセンス検証ツールでこれらのテキストブロックを特定するのが困難です。

テキストブロックの代わりに、ライセンス識別子を使用する方法もあります。 Software Package Data Exchange (SPDX)を各ソースファイルに追加します。SPDXライセンス識別子は機械が解析可能で、ファイルがどのライセンスで提供されているかを示す正確な略称です。SPDXライセンス識別子はLinux FoundationのSPDXワーキンググループによって管理され、産業界の企業、ツール開発者、法務チーム間で合意されています。詳細については https://spdx.org/

Linuxカーネルは、すべてのソースファイルに正確なSPDX識別子を必要とします。有効な識別子については、以下のセクションで説明します。 ライセンス識別子 SPDXライセンスリストの公式リストからコピーされた有効な識別子と、それぞれのテキストは以下の通り示されています。 https://spdx.org/licenses/.

ライセンス識別子の構文¶

  1. 位置付け:

    SPDXライセンス識別子は、コメントを含むファイルの可能な最初の行に配置する必要があります。ほとんどのファイルでは最初の行ですが、'#!PATH_TO_INTERPRETER'を最初の行として要求するスクリプトは例外です。このようなスクリプトでは、SPDX識別子は2行目に配置されます。


  1. スタイル:

    SPDXライセンス識別子はコメントとして追加されます。コメントのスタイルはファイルの種類により異なります:

    sorgenti C:       // SPDX-License-Identifier: <SPDX License Expression>
intestazioni C:   /* SPDX-License-Identifier: <SPDX License Expression> */
ASM:      /* SPDX-License-Identifier: <SPDX License Expression> */
scripts:  # SPDX-License-Identifier: <SPDX License Expression>
.rst:     .. SPDX-License-Identifier: <SPDX License Expression>
.dts{i}:  // SPDX-License-Identifier: <SPDX License Expression>

    特定のプログラムが主なコメントスタイルを処理できない場合、そのプログラムが受け入れるメカニズムを使用する必要があります。これはCヘッダーファイルで「/* */」が使われている理由です。我々は「ld」がC++コメントを.ldファイルで解析できなかったことに気づきました。この問題は現在修正されていますが、古いプログラムがC++コメントスタイルを処理できない場合があります。


  1. 構文:

    <SPDXライセンス表現>は、SPDXライセンスリストに記載されているライセンス識別子を用いるか、例外的なケースでは「WITH」で2つのSPDX識別子を結合します。複数のライセンスを使用する場合、表現は「AND」「OR」というキーワードで区切られた括弧「(」「）」で囲まれたサブ表現で構成されます。

    LGPLなどの「o successive」オプションを採用するライセンスの識別子は、最後に「+」記号を追加して「o successive」を示します。

    // SPDX-License-Identifier: GPL-2.0+
// SPDX-License-Identifier: LGPL-2.1+

    ライセンスの変更が必要な場合は「WITH」を使用します。たとえば、LinuxカーネルのUAPIは以下の表現を使用します:

    // SPDX-License-Identifier: GPL-2.0 WITH Linux-syscall-note
// SPDX-License-Identifier: GPL-2.0+ WITH Linux-syscall-note

    カーネル内で「WITH」を使用する他の例は以下の通りです:

    // SPDX-License-Identifier: GPL-2.0 WITH mif-exception
// SPDX-License-Identifier: GPL-2.0+ WITH GCC-exception-2.0

    例外はライセンス識別子と組み合わせてのみ使用可能です。承認されたライセンス識別子は、対応する例外ファイルに記載されています。詳細については、以下の 例外 章の ライセンス識別子

    「OR」キーワードは、二重ライセンスを使用する場合にのみ使用し、その中から1つのライセンスを選択する必要があります。たとえば、いくつかのdtsiファイルは二重ライセンスで利用可能です:

    // SPDX-License-Identifier: GPL-2.0 OR BSD-3-Clause

    二重ライセンスでライセンスされたファイルの表現例は以下の通りです:

    // SPDX-License-Identifier: GPL-2.0 OR MIT
// SPDX-License-Identifier: GPL-2.0 OR BSD-2-Clause
// SPDX-License-Identifier: GPL-2.0 OR Apache-2.0
// SPDX-License-Identifier: GPL-2.0 OR MPL-1.1
// SPDX-License-Identifier: (GPL-2.0 WITH Linux-syscall-note) OR MIT
// SPDX-License-Identifier: GPL-1.0+ OR BSD-3-Clause OR OpenSSL

    複数のライセンス条項が1つのファイルに適用される場合、ANDキーワードを使用すべきです。たとえば、コードが他のプロジェクトから取り込まれ、そのプロジェクトがカーネルに追加する許可を与えていますが、元のライセンス条項が変更されずに残る場合:

    // SPDX-License-Identifier: (GPL-2.0 WITH Linux-syscall-note) AND MIT

    以下は、両方のライセンス条項を尊重する必要があるもう一つの例です:

    // SPDX-License-Identifier: GPL-1.0+ AND LGPL-2.1+

ライセンス識別子¶

現在使用中のライセンスおよびカーネルに追加されたライセンスは、以下のように分類できます:

  1. 推奨ライセンス:

    可能な限り、ここに示すライセンスを使用すべきです。これらは完全に互換性があり、非常に一般的なライセンスです。カーネルのソースコード内、以下ディレクトリにあります:

    LICENSES/preferred/

    このディレクトリ内のファイルには、ライセンス条文の全文と、 メタタグが含まれています。このファイル名は、SPDXライセンス識別子として使用される名称であり、ソースコードファイルにも使用する必要があります。

    例：

    LICENSES/preferred/GPL-2.0

    これは、GPLライセンスの2番目のバージョンの条文と必要なメタタグを含んでいます:

    LICENSES/preferred/MIT

    これは、MITライセンスの条文と必要なメタタグを含んでいます。

    メタタグ:

    ライセンスファイルには以下のメタタグが含まれるべきです:

    • 有効なライセンス識別子:

      ライセンス識別子を1行または複数行で宣言し、プロジェクト内でそのライセンスを参照する際の有効な識別子を示します。通常は1つの有効な識別子ですが、'or later'オプションを許可するライセンスの場合は2つの有効な識別子があります。

    • SPDX-URL:

      SPDXページのURLで、ライセンスに関する追加情報を提供しています。

    • 使用ガイドライン:

      自由形式のテキストでユーザーにヒントを提供します。テキストには、ソースコードファイル内でSPDXライセンス識別子を使用する方法の例を含め、以下のガイドラインに準拠する必要があります: ライセンス識別子の構文.

    • License-Text:

      このラベルの後のすべてのテキストは、もともとのライセンス条文の一部として扱われます。

    例：

    Valid-License-Identifier: GPL-2.0
Valid-License-Identifier: GPL-2.0+
SPDX-URL: https://spdx.org/licenses/GPL-2.0.html
Usage-Guide:
  To use this license in source code, put one of the following SPDX
  tag/value pairs into a comment according to the placement
  guidelines in the licensing rules documentation.
  For 'GNU General Public License (GPL) version 2 only' use:
    SPDX-License-Identifier: GPL-2.0
  For 'GNU General Public License (GPL) version 2 or any later version' use:
    SPDX-License-Identifier: GPL-2.0+
License-Text:
  Full license text

    SPDX-License-Identifier: MIT
SPDX-URL: https://spdx.org/licenses/MIT.html
Usage-Guide:
  To use this license in source code, put the following SPDX
  tag/value pair into a comment according to the placement
  guidelines in the licensing rules documentation.
    SPDX-License-Identifier: MIT
License-Text:
  Full license text

  1. 非推奨ライセンス:

    この種のライセンスは、既存のコードや他のプロジェクトからコードを取り込む場合にのみ使用すべきです。ライセンスはカーネルのソースコード内の以下ディレクトリにあります:

    LICENSES/deprecated/

    このディレクトリ内のファイルには、ライセンス条文の全文と、 メタタグが含まれています。このファイル名は、SPDXライセンス識別子として使用される名称であり、ソースコードファイルにも使用する必要があります。

    例：

    LICENSES/deprecated/ISC

    これは、インターネットシステムコンソーシアムのライセンスとそのメタタグを含んでいます:

    LICENSES/deprecated/GPL-1.0

    これは、GPLライセンスのバージョン1とそのメタタグを含んでいます。

    メタタグ:

    'その他の'（'other'）ライセンスに必要なメタタグは、'推奨ライセンス'に使用されるものと同じです。 推奨ライセンス.

    ファイル形式の例:

    Valid-License-Identifier: ISC
SPDX-URL: https://spdx.org/licenses/ISC.html
Usage-Guide:
  Usage of this license in the kernel for new code is discouraged
  and it should solely be used for importing code from an already
  existing project.
  To use this license in source code, put the following SPDX
  tag/value pair into a comment according to the placement
  guidelines in the licensing rules documentation.
    SPDX-License-Identifier: ISC
License-Text:
  Full license text

  1. 二重ライセンス専用

    これらのライセンスは、通常のライセンスと組み合わせて使用されるコードにのみ使用すべきです。これらのライセンスは、カーネルのソースコード内の以下ディレクトリにあります:

    LICENSES/dual

    このフォルダ内のファイルは、それぞれのライセンスの完全なテキストとその識別子を含んでいます。 メタタグファイル名は、ソースファイルで使用すべきSPDXライセンス識別子と同一です。

    例：

    LICENSES/dual/MPL-1.1

    このファイルは、ライセンスのバージョン1.1のテキストを含んでいます Mozilla Public License および必要なメタタグ:

    LICENSES/dual/Apache-2.0

    このファイルは、Apacheライセンスのバージョン2.0のテキストと必要なメタタグを含んでいます。

    メタタグ:

    「その他」（「その他」）ライセンスの要件は、 推奨ライセンス.

    ファイル形式の例:

    Valid-License-Identifier: MPL-1.1
SPDX-URL: https://spdx.org/licenses/MPL-1.1.html
Usage-Guide:
  Do NOT use. The MPL-1.1 is not GPL2 compatible. It may only be used for
  dual-licensed files where the other license is GPL2 compatible.
  If you end up using this it MUST be used together with a GPL2 compatible
  license using "OR".
  To use the Mozilla Public License version 1.1 put the following SPDX
  tag/value pair into a comment according to the placement guidelines in
  the licensing rules documentation:
SPDX-License-Identifier: MPL-1.1
License-Text:
  Full license text

  1. 例外:

    いくつかのライセンスは、追加の権利を提供する例外によって修正されることがあります。これらの例外は、カーネルのソースコードの以下のフォルダにあります:

    LICENSES/exceptions/

    このフォルダ内のファイルは、例外の完全なテキストと 例外用メタタグ.

    例：

    LICENSES/exceptions/Linux-syscall-note

    Linuxシステムコールの例外の説明を含んでおり、LinuxカーネルのCOPYINGファイルで文書化されています。これはUAPIヘッダーファイルに使用され、たとえば /* SPDX-License-Identifier: GPL-2.0 WITH Linux-syscall-note */ のようにします:

    LICENSES/exceptions/GCC-exception-2.0

    リンク例外は、どのバイナリでも、そのライセンスに関係なく、この例外でマークされたソースコードのコンパイルとリンクを許可します。これは、GPLと互換性のないソースコードから実行可能ファイルを作成するために必要です。

    例外用メタタグ:

    例外を含むファイルには、次のメタタグが必要です:

    • SPDX-Exception-Identifier:

      SPDXライセンス識別子と組み合わせて使用可能な例外識別子。

    • SPDX-URL:

      この例外に関する追加情報が含まれるSPDXページのURL。

    • SPDX-Licenses:

      SPDXライセンス識別子のコンマで区切ったリストで、この例外と併用可能なライセンスです。

    • 使用ガイドライン:

      自由形式のテキストでユーザーにヒントを提供します。テキストには、ソースコードファイル内でSPDXライセンス識別子を使用する方法の例を含め、以下のガイドラインに準拠する必要があります: ライセンス識別子の構文.

    • Exception-Text:

      このラベルの後のすべてのテキストは、もともとのライセンス条文の一部として扱われます。

    例：

    SPDX-Exception-Identifier: Linux-syscall-note
SPDX-URL: https://spdx.org/licenses/Linux-syscall-note.html
SPDX-Licenses: GPL-2.0, GPL-2.0+, GPL-1.0+, LGPL-2.0, LGPL-2.0+, LGPL-2.1, LGPL-2.1+
Usage-Guidance:
  This exception is used together with one of the above SPDX-Licenses
  to mark user-space API (uapi) header files so they can be included
  into non GPL compliant user-space application code.
  To use this exception add it with the keyword WITH to one of the
  identifiers in the SPDX-Licenses tag:
    SPDX-License-Identifier: <SPDX-License> WITH Linux-syscall-note
Exception-Text:
  Full exception text

    SPDX-Exception-Identifier: GCC-exception-2.0
SPDX-URL: https://spdx.org/licenses/GCC-exception-2.0.html
SPDX-Licenses: GPL-2.0, GPL-2.0+
Usage-Guidance:
  The "GCC Runtime Library exception 2.0" is used together with one
  of the above SPDX-Licenses for code imported from the GCC runtime
  library.
  To use this exception add it with the keyword WITH to one of the
  identifiers in the SPDX-Licenses tag:
    SPDX-License-Identifier: <SPDX-License> WITH GCC-exception-2.0
Exception-Text:
  Full exception text

すべてのSPDXライセンス識別子および例外には、LICENSESサブフォルダにファイルが必要です。これは、ツールが検証（例：checkpatch.pl）を実行し、ライセンスを読み取り、ソースコードから権利を抽出できるようにするためです。これは、FSFE REUSEなどの複数のFOSS組織が推奨しています。FSFE REUSE 初期化.

MODULE_LICENSE¶

カーネルモジュールにはMODULE_LICENSE()ラベルが必要です。このラベルは、ソースコードのライセンス情報（SPDX-License-Identifier）を置き換えるものではなく、正確なライセンスを示す情報も提供しません。

このラベルの唯一の目的は、カーネルモジュールローダーやユーザー空間ツールに、モジュールがフリーソフトウェアか専有ソフトウェアかを理解させるための十分な情報を提供することです。

MODULE_LICENSE() に有効なライセンス文字列は以下の通りです:

「GPL」

このモジュールは GPL バージョン 2 でライセンスされています。これは GPL’2.0-only と GPL-2.0-or-later の区別をしません。正確なライセンスは、対応するソースファイルを読むことでのみ確認できます。

「GPL v2」

「GPL」と同じ意味です。これは歴史的な理由により存在しています。

「GPL and additional rights」

これは歴史的な理由により存在する変体で、モジュールのソースコードが GPL v2 の変体と MIT ライセンスの下で公開されることを示します。新しいコードにはこの文字列は使用しないでください。

「Dual MIT/GPL」

このモジュールは、GPL v2 の変体か MIT ライセンスのいずれかを選択する二重ライセンスで公開されています。この表現は正しい方法です。

「Dual BSD/GPL」

このモジュールは、GPL v2 の変体か BSD ライセンスのいずれかを選択する二重ライセンスで公開されています。BSD ライセンスの正確な変体は、対応するソースファイルを読むことでのみ確認できます。

「Dual MPL/GPL」

このモジュールは、GPL v2 の変体か Mozilla Public License (MPL) のいずれかを選択する二重ライセンスで公開されています。MPL ライセンスの正確な変体は、対応するソースファイルを読むことでのみ確認できます。

「Proprietary」

このモジュールは専有ライセンスで公開されています。この文字列は第三者の専有モジュール専用であり、カーネルソース内のモジュールには使用できません。このラベルが付けられたモジュールはカーネルを汚染しており、'P' フラグが割り当てられます。ロード時に、カーネルのモジュールロー�ーダーは EXPORT_SYMBOL_GPL() でエクスポートされたシンボルとのリンクを拒否します。
