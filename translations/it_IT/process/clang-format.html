clang-format¶

clang-format C/C++/…などのコードを、ルールと推論法のグループに従ってフォーマットするためのツールです。すべてのツール同様、完璧ではありませんし、すべてのケースをカバーするわけではありませんが、実用上十分に優れています。

clang-format さまざまな目的で使用できます:

  • カーネルのスタイルに従ってコードブロックを素早くフォーマットするのに特に役立ちます。コードを移動し、並べ替える際には特に有用です。参照 it_clangformatreformat.

  • 保持しているファイル、レビューしている変更内容、差分などにスタイルのエラー、誤字脱字、改善点を特定します。参照 it_clangformatreview.

  • コードスタイルに従うのを助けるツールで、特に新規参加者や複数のプロジェクトで異なるスタイルのコードを同時に作業する人々にとって有用です。

その設定ファイルは .clang-format カーネルのソースコードのメインフォルダにあります。そのファイルに記述されたルールは、カーネルのコードスタイルを近似しようとしています。また、できるだけ Linuxカーネル用コードスタイル. すべてのカーネルが同じスタイルを採用しているわけではありませんので、特定のサブシステムやフォルダ用に基本ルールを調整するかもしれません。これを実行するには、別のファイルに記述して上書きできます .clang-format in una sottocartella.

このツールはすでに多くのポピュラーなLinuxディストリビューションに長期間含まれています。自分のリポジトリで clang-format を検索してください。それ以外の場合は、LLVM/clangのプレコンパイル済みバイナリをダウンロードするか、ソースコードから生成できます:

http://releases.llvm.org/download.html

以下に詳しい情報があります:

https://clang.llvm.org/docs/ClangFormat.html

https://clang.llvm.org/docs/ClangFormatStyleOptions.html

ファイルと変更内容のコードスタイルをレビューする¶

このプログラムを実行することで、サブシステム全体、フォルダ、または個々のファイルをスタイルのエラー、誤字脱字、改善点を探してレビューできます。

これを実行するには、以下のようなコマンドを実行できます:

# Make sure your working directory is clean!
clang-format -i kernel/*.[ch]

その後、 git diff.

このdiffの行を確認することで、設定ファイルのスタイルオプションを改善・調整するのに役立ちます。また、新しい機能やバージョンを確認するのにも役立ちます。 clang-format.

clang-format このツールは複数のdiffを統合的に読み込むことができますので、変更内容を簡単にレビューし、 git diffのドキュメントは以下のURLにあります:

https://clang.llvm.org/docs/ClangFormat.html#script-for-patch-reformatting

特定の部分を clang-format がフォーマットしないようにするには、コード中に以下のように記述できます:

int formatted_code;
// clang-format off
    void    unformatted_code  ;
// clang-format on
void formatted_code_again;

ただし、常に clang-formatと同期させるのは魅力的ですが、特に新規ファイルやメンテナの場合、他の人が異なるバージョンの clang-format あるいはまったく使いません。したがって、カーネルコードでこれらのマーカーを使用するのを控えるべきです。少なくとも、それが広く利用されるようになるまで clang-format まで待つのがよいでしょう。

コードブロックの整形¶

エディタのプラグインを使用することで、キーボードショートカット1つでコードブロック（選択範囲）を整形できます。これは特に、複雑なコードを再整理する際や、マルチラインマクロ（およびそれらの「バー」の整列）などに非常に役立ちます。

このツールがうまく機能しなかった場合の修正はいつでも可能です。ただし、最初の近似値として、非常に有用です。

このプログラムは多くの人気のあるエディタと統合可能です。vim、emacs、BBEdit、Visual Studioなどは直接サポートしています。以下のリンク先でインストール手順をご確認ください：

https://clang.llvm.org/docs/ClangFormat.html

Atom、Eclipse、Sublime Text、Visual Studio Code、XCodeなどのエディタやIDEでは、使用可能なプラグインが見つかるはずです。

この用途にあたっては、2番目の .clang-format を自分のオプションでカスタマイズできます。参照してください it_clangformatextra.

サポートされていない機能¶

clang-format カーネルコードでよく見られるいくつかの機能はサポートされていません。これらは覚えやすく、定期的に使用するようになれば、すぐに問題を回避または無視する方法を学ぶことができます。

特に、よく見られるものは以下の通りです：

  • のアライメント #define 1行で表示する場合、例えば：

    #define TRACING_MAP_BITS_DEFAULT       11
#define TRACING_MAP_BITS_MAX           17
#define TRACING_MAP_BITS_MIN           7

    対して：

    #define TRACING_MAP_BITS_DEFAULT 11
#define TRACING_MAP_BITS_MAX 17
#define TRACING_MAP_BITS_MIN 7

  • 初期値のアライメント、例えば：

    static const struct file_operations uprobe_events_ops = {
        .owner          = THIS_MODULE,
        .open           = probes_open,
        .read           = seq_read,
        .llseek         = seq_lseek,
        .release        = seq_release,
        .write          = probes_write,
};

    対して：

    static const struct file_operations uprobe_events_ops = {
        .owner = THIS_MODULE,
        .open = probes_open,
        .read = seq_read,
        .llseek = seq_lseek,
        .release = seq_release,
        .write = probes_write,
};

機能と追加オプション¶

現在のコードとプログラムの出力との違いを最小限に抑えるため、いくつかのスタイルオプションや機能は基本設定では無効になっています。言い換えれば、差分を最小限に抑え、ファイルや差分、変更のレビューを簡略化することを目的としています。

他の場合（特定のサブシステム/フォルダ/ファイルなど）では、カーネルのスタイルが異なり、これらのオプションの一部を有効にすることで、より良い結果が得られる可能性があります。

例えば：

  • 割り当てのアライメント（AlignConsecutiveAssignments).

  • 宣言のアライメント（AlignConsecutiveDeclarations).

  • コメント内のテキストの再配置（ReflowComments).

  • を並べる #include (SortIncludes).

ファイル全体ではなく、通常は個々のブロックの整形に役立ちます。代わりに、別のファイル .clang-format を作成してエディタ/IDEで使用することもできます。
