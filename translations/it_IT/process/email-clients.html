Linux用メールソフトに関する情報¶

Git¶

現在、ほとんどの開発者は git send-email 古典的なメールクライアントの代わりに使用しています。manページは十分に良いです。受信側では、メンテナは git am パッチを適用するために使用しています。

もしあなたが新しいユーザーであれば git パッチを自分自身に送信してください。すべてのヘッダーを含むテキストとして保存し、その後、コマンドを実行してください。 git am messaggio-formato-testo.txt 結果をレビューしてください。 git log。すべてが正常に動作したら、適切なディスカッションリストにパッチを送信できます。

オプションの概要¶

カーネルのパッチはメールで送信され、できればメッセージ本文として送信するのが望ましいです。一部のメンテナは添付ファイルを受け入れますが、その場合は添付ファイルの content-type 設定する必要があります。 text/plain。ただし、通常は添付ファイルは好まれません。なぜなら、レビューの過程でパッチの一部を引用するのが難しくなるからです。

Linuxカーネルのパッチを送信するために使用されるメールクライアントは、変更せずに送信する必要があります。たとえば、タブやスペースを変更したり削除したりしてはいけません。行の先頭や末尾にも同様です。

パッチを送信しないでください。 format=flowed。これは、予期せぬ改行が発生する可能性があります。

あなたのメールクライアントが自動的に改行しないようにしてください。これによりパッチが破損する可能性があります。

メールクライアントはテキストの文字コードを変更してはいけません。メールで送信するパッチはASCIIまたはUTF-8でエンコードする必要があります。UTF-8で送信するように設定すれば、文字コードの問題を防げます。

メールクライアントは「References」または「In-Reply-To:」ヘッダーを生成し、保持する必要があります。これにより、議論が中断されません。

通常、コピー＆ペースト（または切り取り＆貼り付け）はパッチには機能しません。タブがスペースに変換されるためです。xclipboard、xclip、xcutselなどを使用すれば機能するかもしれませんが、確認したほうが良いです。あるいは、コピー＆ペーストを使わないほうが良いでしょう。

パッチを含むメッセージにPGP/GPG署名を使用しないでください。これにより、一部のパッチを読み込んだり適用したりするスクリプトの正常な動作が妨げられます（これは修正可能ですが）。

Linuxのディスカッションリストにパッチを送信する前に、自分自身にパッチを送信して、受け取ったメッセージを保存し、ソースコードに成功して適用するのも良い考えです。

メールクライアント（MUA）に関するヒント¶

ここでは、Linuxカーネルのパッチを編集・送信するためのメールクライアント（MUA）の設定方法についてのヒントを紹介します。ただし、これらは完全な設定の要約とはみなしません。

解説:

  • TUI = テキストベースのユーザーインターフェース（text-based user interface)

  • GUI = グラフィカルユーザーインターフェース（graphical user interface)

Kmail (GUI)¶

一部の人々はこの方法でパッチを送信するのを成功させています。

HTMLメッセージ作成を無効にする基本設定は正しいです。有効にしてはいけません。

メッセージを書いている際、オプションメニューから「自動改行」の選択を解除してください。その唯一のデメリットは、メッセージ内で他の文字を入力すると自動的に改行されなくなることです。この問題を回避する最も簡単な方法は、オプションを有効にしてメッセージを書いた後、下書きとして保存することです。下書きからメッセージを開くと、改行がメッセージの一部として含まれるため、「自動改行」を無効にしても何も失いません。

メッセージの終わり、パッチを挿入する直前に、パッチの区切り記号を追加してください：3本の破線（---).

今度は、メニューから メッセージを選択し、 テキストファイルを挿入… 自分のパッチを選んでください。追加の解決策として、ツールバーをカスタマイズして、アイコンを追加することで テキストファイルを挿入….

作業ウィンドウを十分に広げて改行を避けてください。これはKmail 1.13.5（KDE 4.5.4）において、送信時に画面で次の行にわたる行に対して自動的に改行が追加されるためです。自動改行を無効にするだけでは不十分です。そのため、パッチに非常に長い行が含まれる場合、作業ウィンドウを広げて改行を防ぐ必要があります。参照： https://bugs.kde.org/show_bug.cgi?id=174034

添付ファイルにGPGによる署名をかけることもできますが、パッチの場合はメッセージ本文に直接追加する方が望ましいため、GPG署名は使用しないでください。メッセージ本文に埋め込まれたパッチは7ビット符号化された形式で抽出するのが困難になります。

どうしてもパッチを添付ファイルとして送信する必要がある場合は、添付ファイルを右クリックして、 プロパティを選び、 自動表示を推奨する を有効にして、添付ファイルがメッセージの一部として表示されるようにしてください。

パッチを含むメッセージを保存するには、メッセージを選択して右クリックし、 保存するを選択してください。メッセージが十分に準備されていれば、編集なしに完全に使用可能です。メッセージはユーザー専用の読み書き許可で保存されます。他のグループや全世界に公開する場合は、 chmod chmod

Mutt (TUI)¶

Lotus Notesのコメントを参照してください。 mutt多くのLinux開発者は

を使用するため、十分に動作するはずです。 Muttには独自のエディタがありませんので、どのエディタも自動的に改行を追加しないように設定する必要があります。多くのエディタには ファイルを挿入

というオプションがあり、ファイルの内容を変更せずに挿入します。 vim をエディタとして使用するには、

set editor="vi"

パッチをメッセージに挿入する際にはxclipを使用する場合、以下のコマンドを実行してください：

:set paste

中央クリックまたはShift+Insertキーを押す前に行ってください。あるいは以下のコマンドを使用してください：

:r filename

(a)llegaは set paste

なしで十分に機能します。 git format-patch でパッチを生成し、Muttで送信してください：

$ mutt -H 0001-some-bug-fix.patch

設定オプション:

基本設定ではすべて動作します。ただし、以下の設定を確認することをお勧めします： send_charset:

set send_charset="us-ascii:utf-8"

Muttは非常にカスタマイズ可能です。以下に、Gmailを使用してパッチを送信するために必要な最小限の設定を示します。

# .muttrc
# ================  IMAP ====================
set imap_user = 'yourusername@gmail.com'
set imap_pass = 'yourpassword'
set spoolfile = imaps://imap.gmail.com/INBOX
set folder = imaps://imap.gmail.com/
set record="imaps://imap.gmail.com/[Gmail]/Sent Mail"
set postponed="imaps://imap.gmail.com/[Gmail]/Drafts"
set mbox="imaps://imap.gmail.com/[Gmail]/All Mail"

# ================  SMTP  ====================
set smtp_url = "smtp://username@smtp.gmail.com:587/"
set smtp_pass = $imap_pass
set ssl_force_tls = yes # Require encrypted connection

# ================  Composition  ====================
set editor = `echo \$EDITOR`
set edit_headers = yes  # See the headers when editing
set charset = UTF-8     # value of $LANG; also fallback for send_charset
# Sender, email address, and sign-off line must match
unset use_domain        # because joe@localhost is just embarrassing
set realname = "YOUR NAME"
set from = "username@gmail.com"
set use_from = yes

パッチを送信するには動作しません。

ウェブベースのGmailは自動的にタブをスペースに変換します。

同時に、78文字ごとに改行を追加します。ただし、スペースとタブの変換問題は外部エディタを使用することで解決できます。

Gmailは、ASCII文字以外を含むすべてのメッセージでBase64エンコーディングを使用しているため、別の問題があります。これはヨーロッパの名前などにも含まれます。
