故障注入機能インフラストラクチャ¶

参照: drivers/md/md-faulty.c および "every_nth" モジュールオプション（scsi_debug）

利用可能な故障注入機能¶

  • failslab

    slab割当失敗を注入します。(kmalloc(), kmem_cache_alloc(), …)

  • fail_page_alloc

    ページ割当失敗を注入します。(alloc_pages(), get_free_pages(), …)

  • fail_usercopy

    ユーザーメモリアクセス関数の失敗を注入します。(copy_from_user(), get_user(), …)

  • fail_futex

    futexデッドロックおよびuaddr故障エラーを注入します。

  • fail_make_request

    設定された /sys/block/<device>/make-it-fail または /sys/block/<device>/<partition>/make-it-fail により許可されたデバイスでディスクIOエラーを注入します。(submit_bio_noacct())

  • fail_mmc_request

    debugfsエントリを /sys/kernel/debug/mmc0/fail_mmc_request 以下に設定することで、MMCデータエラーを注入します

  • fail_function

    ALLOW_ERROR_INJECTION()マクロで指定された特定の関数にエラーリターンを注入します。debugfsエントリを /sys/kernel/debug/fail_function 以下に設定します。ブートオプションはサポートされていません。

  • NVMe故障注入

    debugfsエントリを /sys/kernel/debug/nvme*/fault_inject 以下に設定することで、NVMeステータスコードとリトライフラグを注入します。デフォルトのステータスコードは NVME_SC_INVALID_OPCODE でリトライなしです。ステータスコードとリトライフラグはdebugfs経由で設定可能です。

故障注入機能の動作を設定¶

debugfsエントリ¶

fault-inject-debugfs カーネルモジュールは、故障注入機能の実時間設定に必要なdebugfsエントリを提供します。

  • /sys/kernel/debug/fail*/probability:

    失敗注入の確率（％）

    形式: <percent>

    注意: 100回に1回の失敗率は一部のテストケースでは非常に高いエラーレートです。このようなテストケースでは、probability=100 を設定し、/sys/kernel/debug/fail*/interval を設定することを検討してください。

  • /sys/kernel/debug/fail*/interval:

    should_fail() の呼び出しで、他のテストがすべて通過した場合の失敗間隔を指定します。

    注意: interval>1 でこの機能を有効にすると、probability=100 を設定することを検討してください。

  • /sys/kernel/debug/fail*/times:

    失敗が発生する最大回数を指定します。-1 は「制限なし」を意味します。

  • /sys/kernel/debug/fail*/space:

    初期のリソース「予算」を指定します。should_fail(,size) の各呼び出しで「size」分減算されます。space がゼロになるまで失敗注入が抑制されます。

  • /sys/kernel/debug/fail*/verbose

    形式: { 0 | 1 | 2 }

    失敗を挿入する際のメッセージの詳細度を指定します。'0'はメッセージを表示しません;'1'は各失敗ごとに1行のログを表示します;'2'はコールトレースも表示します--故障挿入によって明らかになった問題のデバッグに役立ちます。

  • /sys/kernel/debug/fail*/task-filter:

    形式: { ‘Y’ | ‘N’ }

    ‘N’はプロセスによるフィルタリングを無効にします（デフォルト）。任意の正数は、/proc/<pid>/make-it-fail==1 で指定されたプロセスにのみ失敗を制限します。

  • /sys/kernel/debug/fail*/require-start, /sys/kernel/debug/fail*/require-end, /sys/kernel/debug/fail*/reject-start, /sys/kernel/debug/fail*/reject-end:

    スタックトレースのウォーク中にテストされる仮想アドレスの範囲を指定します。失敗が挿入されるのは、ウォークされたスタックトレース内の呼び出し元が要求範囲に含まれており、拒否範囲に含まれていない場合です。デフォルトの要求範囲は [0,ULONG_MAX)（仮想アドレス空間全体）です。デフォルトの拒否範囲は [0,0) です。

  • /sys/kernel/debug/fail*/stacktrace-depth:

    検索中にスタックトレースのウォークで最大で検索する深度を指定します。[require-start,require-end) または [reject-start,reject-end) の範囲内で呼び出し元を検索する際の最大深度です。

  • /sys/kernel/debug/fail_page_alloc/ignore-gfp-highmem:

    形式: { ‘Y’ | ‘N’ }

    デフォルトは ‘N’ です。'Y' に設定すると、highmem/user アロケーションへの失敗挿入を行いません。

  • /sys/kernel/debug/failslab/ignore-gfp-wait:

  • /sys/kernel/debug/fail_page_alloc/ignore-gfp-wait:

    形式: { ‘Y’ | ‘N’ }

    デフォルトは ‘N’ です。'Y' に設定すると、非スリープアロケーション（GFP_ATOMIC アロケーション）のみに失敗を挿入します。

  • /sys/kernel/debug/fail_page_alloc/min-order:

    失敗を挿入するための最小のページアロケーションオーダーを指定します。

  • /sys/kernel/debug/fail_futex/ignore-private:

    形式: { ‘Y’ | ‘N’ }

    デフォルトは ‘N’ です。'Y' に設定すると、プライベート（アドレス空間）ファutex処理では失敗挿入を無効にします。

  • /sys/kernel/debug/fail_function/inject:

    形式: { ‘function-name’ | ‘!function-name’ | ‘’ }

    エラーレポート挿入の対象となる関数名を指定します。関数名の先頭に '!' が付いている場合は、指定された関数を挿入リストから削除します。何も指定しない場合は（''）挿入リストをクリアします。

  • /sys/kernel/debug/fail_function/injectable:

    (読み取り専用) エラーレポート挿入可能な関数と、指定可能なエラータイプを表示します。エラータイプは以下のいずれかです; - NULL: retval は 0 でなければなりません。- ERRNO: retval は -1 から -MAX_ERRNO (-4096) でなければなりません。- ERR_NULL: retval は 0 または -1 から -MAX_ERRNO (-4096) でなければなりません。

  • /sys/kernel/debug/fail_function/<functiuon-name>/retval:

    指定された関数に挿入する「エラー」リターン値を指定します。これはユーザーが新しい挿入エントリを指定したときに作成されます。

ブートオプション¶

debugfsが利用できない状態（早期ブート時）で障害を注入する場合、以下のブートオプションを使用してください:

failslab=
fail_page_alloc=
fail_usercopy=
fail_make_request=
fail_futex=
mmc_core.fail_request=<interval>,<probability>,<space>,<times>

プロシージャー項目¶

  • /proc/<pid>/fail-nth, /proc/self/task/<tid>/fail-nth:

    このファイルに整数Nを書き込むと、タスク内のN番目の呼び出しが失敗します。このファイルから読み取ると整数値が返されます。値が'0'の場合は、このファイルへの以前の書き込みによる障害が注入済みです。正の整数Nの場合は、まだ障害が注入されていません。このファイルは、slab、futexなどすべての障害タイプを有効にします。この設定は、確率、間隔、回数などの他の一般的なdebugfs設定よりも優先されます。ただし、個別機能設定（例: fail_futex/ignore-private）はこの設定よりも優先されます。

    この機能は、単一のシステムコールにおける障害の系統的なテストに使用することを意図しています。以下に例を示します。

新しい障害注入機能の追加方法¶

  • #include <linux/fault-inject.h>

  • 障害属性を定義する

    DECLARE_FAULT_ATTR(name);

    詳細については、fault-inject.h内のstruct fault_attrの定義を参照してください。

  • 障害属性の設定方法を提供する

  • ブートオプション

    ブート時に障害注入機能を有効にする必要がある場合、ブートオプションを用いて設定できます。以下に補助関数を示します:

    setup_fault_attr(attr, str);

  • debugfsエントリ

    failslab, fail_page_alloc, fail_usercopy, および fail_make_request はこの方法を使用しています。補助関数:

    fault_create_debugfs_attr(name, parent, attr);

  • モジュールパラメータ

    障害注入機能のスコープが単一のカーネルモジュールに限定されている場合、モジュールパラメータを用いて障害属性を設定するのが望ましいです。

  • 失敗を挿入するハックを追加する

    should_fail() が true を返す場合、クライアントコードは障害を注入する必要があります:

    should_fail(attr, size);

アプリケーション例¶

  • モジュールの初期化/終了コードにslab割当失敗を注入する:

    #!/bin/bash

FAILTYPE=failslab
echo Y > /sys/kernel/debug/$FAILTYPE/task-filter
echo 10 > /sys/kernel/debug/$FAILTYPE/probability
echo 100 > /sys/kernel/debug/$FAILTYPE/interval
echo -1 > /sys/kernel/debug/$FAILTYPE/times
echo 0 > /sys/kernel/debug/$FAILTYPE/space
echo 2 > /sys/kernel/debug/$FAILTYPE/verbose
echo 1 > /sys/kernel/debug/$FAILTYPE/ignore-gfp-wait

faulty_system()
{
    bash -c "echo 1 > /proc/self/make-it-fail && exec $*"
}

if [ $# -eq 0 ]
then
    echo "Usage: $0 modulename [ modulename ... ]"
    exit 1
fi

for m in $*
do
    echo inserting $m...
    faulty_system modprobe $m

    echo removing $m...
    faulty_system modprobe -r $m
done

  • 特定のモジュールにのみページ割当失敗を注入する:

    #!/bin/bash

FAILTYPE=fail_page_alloc
module=$1

if [ -z $module ]
then
    echo "Usage: $0 <modulename>"
    exit 1
fi

modprobe $module

if [ ! -d /sys/module/$module/sections ]
then
    echo Module $module is not loaded
    exit 1
fi

cat /sys/module/$module/sections/.text > /sys/kernel/debug/$FAILTYPE/require-start
cat /sys/module/$module/sections/.data > /sys/kernel/debug/$FAILTYPE/require-end

echo N > /sys/kernel/debug/$FAILTYPE/task-filter
echo 10 > /sys/kernel/debug/$FAILTYPE/probability
echo 100 > /sys/kernel/debug/$FAILTYPE/interval
echo -1 > /sys/kernel/debug/$FAILTYPE/times
echo 0 > /sys/kernel/debug/$FAILTYPE/space
echo 2 > /sys/kernel/debug/$FAILTYPE/verbose
echo 1 > /sys/kernel/debug/$FAILTYPE/ignore-gfp-wait
echo 1 > /sys/kernel/debug/$FAILTYPE/ignore-gfp-highmem
echo 10 > /sys/kernel/debug/$FAILTYPE/stacktrace-depth

trap "echo 0 > /sys/kernel/debug/$FAILTYPE/probability" SIGINT SIGTERM EXIT

echo "Injecting errors into the module $module... (interrupt to stop)"
sleep 1000000

  • btrfsマウント時にopen_ctreeエラーを注入する:

    #!/bin/bash

rm -f testfile.img
dd if=/dev/zero of=testfile.img bs=1M seek=1000 count=1
DEVICE=$(losetup --show -f testfile.img)
mkfs.btrfs -f $DEVICE
mkdir -p tmpmnt

FAILTYPE=fail_function
FAILFUNC=open_ctree
echo $FAILFUNC > /sys/kernel/debug/$FAILTYPE/inject
echo -12 > /sys/kernel/debug/$FAILTYPE/$FAILFUNC/retval
echo N > /sys/kernel/debug/$FAILTYPE/task-filter
echo 100 > /sys/kernel/debug/$FAILTYPE/probability
echo 0 > /sys/kernel/debug/$FAILTYPE/interval
echo -1 > /sys/kernel/debug/$FAILTYPE/times
echo 0 > /sys/kernel/debug/$FAILTYPE/space
echo 1 > /sys/kernel/debug/$FAILTYPE/verbose

mount -t btrfs $DEVICE tmpmnt
if [ $? -ne 0 ]
then
    echo "SUCCESS!"
else
    echo "FAILED!"
    umount tmpmnt
fi

echo > /sys/kernel/debug/$FAILTYPE/inject

rmdir tmpmnt
losetup -d $DEVICE
rm testfile.img

failslabまたはfail_page_allocを用いてコマンドを実行するためのツール¶

上述のタスクを簡単に実行するため、tools/testing/fault-injection/failcmd.sh を使用できます。詳細については、「./tools/testing/fault-injection/failcmd.sh –help」を実行してください。以下に例を示します。

例:

「make -C tools/testing/selftests/ run_tests」コマンドを実行し、slab割当失敗を注入する:

# ./tools/testing/fault-injection/failcmd.sh \
        -- make -C tools/testing/selftests/ run_tests

上記と同じ内容ですが、デフォルトで1回までの失敗ではなく最大100回の失敗を指定:

# ./tools/testing/fault-injection/failcmd.sh --times=100 \
        -- make -C tools/testing/selftests/ run_tests

上記と同じ内容ですが、slab割当失敗ではなくページ割当失敗を注入:

# env FAILCMD_TYPE=fail_page_alloc \
        ./tools/testing/fault-injection/failcmd.sh --times=100 \
        -- make -C tools/testing/selftests/ run_tests

fail-nthを用いた系統的な障害¶

以下のコードは、socketpair()システムコールにおける0番目、1番目、2番目など、各能力に対して系統的にエラーを発生させます:

#include <sys/types.h>
#include <sys/stat.h>
#include <sys/socket.h>
#include <sys/syscall.h>
#include <fcntl.h>
#include <unistd.h>
#include <string.h>
#include <stdlib.h>
#include <stdio.h>
#include <errno.h>

int main()
{
      int i, err, res, fail_nth, fds[2];
      char buf[128];

      system("echo N > /sys/kernel/debug/failslab/ignore-gfp-wait");
      sprintf(buf, "/proc/self/task/%ld/fail-nth", syscall(SYS_gettid));
      fail_nth = open(buf, O_RDWR);
      for (i = 1;; i++) {
              sprintf(buf, "%d", i);
              write(fail_nth, buf, strlen(buf));
              res = socketpair(AF_LOCAL, SOCK_STREAM, 0, fds);
              err = errno;
              pread(fail_nth, buf, sizeof(buf), 0);
              if (res == 0) {
                      close(fds[0]);
                      close(fds[1]);
              }
              printf("%d-th fault %c: res=%d/%d\n", i, atoi(buf) ? 'N' : 'Y',
                      res, err);
              if (atoi(buf))
                      break;
      }
      return 0;
}
