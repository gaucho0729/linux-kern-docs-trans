ターゲットサポートユーザースペースI/O¶

ユーザースペースI/O¶

LIOがSCSIコマンドとデータをユーザースペースに渡して処理するための共有メモリインターフェースを定義します。これにより、カーネル内でのサポートが難しいバックエンドも可能になります。

UIOフレームワークを使用して、デバイス作成やインテロスペクションの大部分の作業を行います

ringのレイアウトについては.hファイルを参照してください。コマンドリングは定義されていますが、データ領域の詳細は含まれていません。コマンドエントリ内のオフセット値は、mmapされた領域内の他の場所を指します。データバッファにはコマンドリングの外に別な領域が用意されています。これにより、バッファの割当を動的に変更したり、ページフリップや他の割当技術を採用しても、コマンドリングのレイアウトを変更せずに最大の柔軟性が得られます

セキュリティ: ユーザープロセスは悪意を持つと仮定する必要があります。意図的にコマンドリングプロトコルを破壊する方法はありますが、他の問題を防ぐため、共有メモリ領域のみを読み込む必要があります data 共有メモリ領域から読み込む必要があります。オフセットやサイズではなく。これはコマンドリングエントリおよびメモックスにも適用されます。このための追加コードには「UAM」コメントが含まれる場合があります

リング設計¶

mmapされた領域は3つの部分に分かれています：1) メモックス（struct tcmu_mailbox、下記）；2) コマンドリング；3) コマンドリングを超えたすべての領域（データ）

メモックスは、共有メモリ領域の開始位置からのコマンドリングのオフセットと、コマンドリングのサイズをユーザースペースに伝えます

カーネルは、リングにstruct tcmu_cmd_entryを配置し、mailbox->cmd_headを更新して、UIOの割込みメカニズムを通じてユーザースペースにSCSIコマンドを渡します

tcmu_cmd_entryはヘッダーを含みます。ヘッダータイプがPADの場合、ユーザースペースはhdr->lengthバイト（cmdr_sizeでmod）をスキップして次のcmd_entryを検索します

それ以外の場合、エントリはmmapされた領域内のcdbとデータバッファのオフセットを含みます。後者はiov配列を通じてアクセス可能です。iovアドレスも共有領域内のオフセットです

ユーザースペースがコマンドの処理を完了した場合、entry->rsp.scsi_statusを設定し、必要に応じてrsp.sense_bufferを埋めます。さらにmailbox->cmd_tailを古いcmd_tailにhdr->lengthを加えた値（cmdr_sizeでmod）に設定します。cmd_tailがcmd_headと等しくない場合、次のパケットを同じように処理し続けます
