バスを問わないデバイスアクセス¶

著者

Matthew Wilcox

著者

Alan Cox

はじめに¶

Linuxは、すべてのバスとデバイスを横断してIOを実行するためのAPIを提供し、デバイスドライバがバスの種類に依存せず記述できるようにしています。

メモリマッピングIO¶

デバイスへのアクセスの取得¶

最も広くサポートされているIO形式はメモリマッピングIOです。つまり、CPUのアドレス空間の一部がメモリへのアクセスではなく、デバイスへのアクセスとして解釈されます。一部のアーキテクチャではデバイスが固定アドレスに配置されることが定義されていますが、ほとんどのアーキテクチャではデバイスの発見方法を持っています。PCIバスのウォークはこのようなスキームの良い例です。このドキュメントではこのようなアドレスを取得する方法は扱いませんが、すでにアドレスを持っているものと仮定しています。物理アドレスはunsigned long型です。

このアドレスを直接使用すべきではありません。代わりに、以下で説明するアクセッサ関数に渡すのに適したアドレスを取得するには、呼び出す必要があります ioremap()デバイスにアクセスするための適切なアドレスが返されます。

デバイスの使用が終了した後（たとえば、モジュールの終了ルーチンで）、iounmap()を呼び出してアドレス空間をカーネルに戻してください。ほとんどのアーキテクチャでは、iounmap()を呼び出すたびに新しいアドレス空間を割り当てます。 ioremap()iounmap()を呼び出さない限り、アドレス空間が不足する可能性があります。

デバイスへのアクセス¶

ドライバーが主に使用するインターフェースの一部は、デバイス上のメモリマップされたレジスタの読み書きです。Linuxは、8ビット、16ビット、32ビット、64ビットの量を読み書きするインターフェースを提供しています。これは歴史的な理由により、byte、word、long、quadアクセスと呼ばれます。読み取りと書き込みのアクセスはサポートされていますが、プリフェッチのサポートは今のところありません。

関数はreadb()、readw()、readl()、readq()、readb_relaxed()、readw_relaxed()、readl_relaxed()、readq_relaxed()、writeb()、writew()、writel()、writeq()と呼ばれます。

一部のデバイス（たとえば、フレームバッファ）は、8バイトごとにではなく、より大きな転送を希望しています。このようなデバイスには、memcpy_toio()、memcpy_fromio()、memset_io()関数が提供されています。IOアドレスに対してmemsetまたはmemcpyを使用しないでください。これらはデータを順序通りにコピーする保証はありません。

読み取りと書き込み関数は順序を保つように定義されています。つまり、コンパイラがI/Oシーケンスを再配置することは許可されていません。順序がコンパイラの最適化で許可される場合、__readb()や関連する関数を使用して緩い順序を示すことができます。この機能は慎重に使用してください。

各機能はお互いに同期しており、順序付けられていると定義されていますが、デバイスが接続されているバス自体は非同期性を持つことがあります。特に、多くの著者はPCIバスの書き込みが非同期的にポストされるという点で混乱をしています。ドライバ開発者は、特定のケースで書き込みが確実に実行されていることを確認するため、同じデバイスから読み込みを行う必要があります。このような性質はAPIを通じてドライバ開発者に隠すことはできません。一部のケースでは、デバイスのリセットなどにより読み込みが失敗する可能性があるため、そのような場合にconfig spaceから読み込みを行う必要があります。

以下は、ドライバが書き込みの効果が表示される前に実行を継続する前に確保したい場合の書き込みフラッシュの例です：

static inline void
qla1280_disable_intrs(struct scsi_qla_host *ha)
{
    struct device_reg *reg;

    reg = ha->iobase;
    /* disable risc and host interrupts */
    WRT_REG_WORD(&reg->ictrl, 0);
    /*
     * The following read will ensure that the above write
     * has been received by the device before we return from this
     * function.
     */
    RD_REG_WORD(&reg->ictrl);
    ha->flags.ints_enabled = 0;
}

PCIの順序ルールは、バスからの未完了のDMA書き込みがすべて完了した後にPIO読み込み応答が到達することを保証しています。これは、一部のデバイスではreadb()呼び出しの結果がドライバにDMAトランザクションが完了したことを示すためです。しかし多くの場合、ドライバはデバイスが行った前のDMA書き込みとは関係のない次のreadb()呼び出しを示したいことがあります。このようなケースではreadb_relaxed()を使用できますが、一部のプラットフォームのみが緩和されたセマンティクスを尊重します。緩和された読み込み関数は、サポートするプラットフォームでは大幅なパフォーマンス向上をもたらします。qla2xxxドライバはreadX_relaxed()の使用例を提供しています。多くの場合、ドライバのreadX()呼び出しの大部分はreadX_rel,axed()呼び出しに安全に変換できます。なぜなら、DMA完了を示すまたは依存するケースは少数であるからです。

ポート・スペースのアクセス¶

ポート・スペースの説明¶

一般的にサポートされる他のIO形式の一つにポート・スペースがあります。これは通常のメモリアドレス空間とは別なアドレス範囲です。これらのアドレスへのアクセスは、メモリマップアドレスへのアクセスほど速くありませんし、またアドレス空間もより小さい可能性があります。

メモリマップIOとは異なり、ポート・スペースへのアクセスには準備が必要ありません。

ポート・スペースへのアクセス¶

このスペースへのアクセスは、8ビット、16ビット、32ビットアクセス（バイト、ワード、ロング）を提供する関数セットを通じて行われます。これらの関数はinb(), inw(), inl(), outb(), outw(), outl()です。

これらの関数には一部の変種が提供されています。一部のデバイスではポートへのアクセスを遅くする必要があります。この機能は、 _p 関数の終わりまで。memcpyの同等物もあります。ins()およびouts()関数は、指定されたポートにバイト、ワード、ロングをコピーします。

公開関数¶

phys_addr_t virt_to_phys(volatile void *アドレス)¶

仮想アドレスを物理アドレスにマッピングする

パラメータ

volatile void *address

再マッピングするアドレス

返された物理アドレスは、指定されたメモリアドレスの物理（CPU）マッピングです。この関数は、直接マッピングまたはkmallocで割り当てられたアドレスに対してのみ有効です。

この関数はDMA転送のバスマッピングを提供しません。ほぼすべての想定されるケースでは、デバイスドライバーはこの関数を使用すべきではありません。

void *phys_to_virt(phys_addr_t アドレス)¶

物理アドレスを仮想アドレスにマッピングする

パラメータ

phys_addr_t address

再マッピングするアドレス

返された仮想アドレスは、指定されたメモリアドレスの現在のCPUマッピングです。この関数は、カーネルマッピングを持つアドレスに対してのみ有効です。

この関数はDMA転送のバスマッピングを処理しません。ほぼすべての想定されるケースでは、デバイスドライバーはこの関数を使用すべきではありません。

void __iomem *ioremap(resource_size_t オフセット, unsigned long size)¶

バスメモリをCPU空間にマッピングする

パラメータ

resource_size_t offset

メモリのバスアドレス

unsigned long size

マッピングするリソースのサイズ

説明

ioremapは、バスメモリをCPUがreadb/readw/readl/writeb/writew/writel関数および他のmmioヘルパーを介してアクセス可能にするプラットフォーム固有の操作シーケンスを実行します。返されたアドレスは、仮想アドレスとして直接使用できるとは限りません。

マッピングしようとしている領域がPCI BARである場合は、以下を確認してください pci_iomap().

void iosubmit_cmds512(void __iomem *dst, const void *src, size_t コピーする文字数)¶

512ビット単位で単一のMMIO位置にデータをコピー

パラメータ

void __iomem *dst

MMIO空間の宛先（512ビットアライメントが必要）

const void *src

source

size_t count

送信する512ビットの量

説明

カーネル空間からMMIO空間へデータを512ビット単位で送信します。アクセス順序は保証されず、その後のメモリバリアも実行されません。

警告: プラットフォームでCPU指令がサポートされていることを確認していない限り、このヘルパーを使用しないでください。

void __iomem *pci_iomap_range(struct pci_dev *dev, int bar, unsigned long オフセット, unsigned long maxlen)¶

PCI BARに対して仮想マッピングクッキーを作成する

パラメータ

struct pci_dev *dev

BARを所有するPCIデバイス

int bar

BAR番号

unsigned long offset

指定されたオフセット位置のBAR内のメモリをマッピングする

unsigned long maxlen

マッピングするメモリの最大長

説明

この関数を使用すると、デバイスのBARに__iomemアドレスが割り当てられます。ioread*()およびiowrite*()関数を使用してアクセスできます。これらの関数はMMIOまたはPIOアドレス空間かどうかを隠蔽し、正しい方法で期待通りの動作を行います。

maxlen マッピングする最大長を指定します。オフセットからBARの終わりまで全体をアクセスしたい場合は、 0 ここに記載しています。

maxlen マッピングする最大長を指定します。オフセットからBARの終わりまで全体をアクセスしたい場合は、 0 ここに記載しています。
