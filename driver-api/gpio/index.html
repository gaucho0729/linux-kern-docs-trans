struct gpio_irq_chip¶

GPIO割込み制御器

定義

struct gpio_irq_chip {
  struct irq_chip *chip;
  struct irq_domain *domain;
  const struct irq_domain_ops *domain_ops;
#ifdef CONFIG_IRQ_DOMAIN_HIERARCHY;
  struct fwnode_handle *fwnode;
  struct irq_domain *parent_domain;
  int (*child_to_parent_hwirq)(struct gpio_chip *gc,unsigned int child_hwirq,unsigned int child_type,unsigned int *parent_hwirq, unsigned int *parent_type);
  void *(*populate_parent_alloc_arg)(struct gpio_chip *gc,unsigned int parent_hwirq, unsigned int parent_type);
  unsigned int (*child_offset_to_irq)(struct gpio_chip *gc, unsigned int pin);
  struct irq_domain_ops child_irq_domain_ops;
#endif;
  irq_flow_handler_t handler;
  unsigned int default_type;
  struct lock_class_key *lock_key;
  struct lock_class_key *request_key;
  irq_flow_handler_t parent_handler;
  void *parent_handler_data;
  unsigned int num_parents;
  unsigned int *parents;
  unsigned int *map;
  bool threaded;
  int (*init_hw)(struct gpio_chip *gc);
  void (*init_valid_mask)(struct gpio_chip *gc,unsigned long *valid_mask, unsigned int ngpios);
  unsigned long *valid_mask;
  unsigned int first;
  void (*irq_enable)(struct irq_data *data);
  void (*irq_disable)(struct irq_data *data);
  void (*irq_unmask)(struct irq_data *data);
  void (*irq_mask)(struct irq_data *data);
  ANDROID_KABI_RESERVE(1);
  ANDROID_KABI_RESERVE(2);
};

メンバ

chip

GPIO IRQチップの実装はGPIOドライバによって提供されます。

domain

割込み翻訳ドメイン；GPIO hwirq番号とLinux IRQ番号のマッピングを担当します。

domain_ops

このIRQチップの割込みドメイン操作のテーブル。

fwnode

このgpiochip/irqchipに対応するファームウェアノードで、階層的なirqdomainサポートが必要です。

parent_domain

NULLでない場合、このGPIO割込み制御器のIRQドメインの親として設定され、階層的な割込みドメインを構築します。この存在により、階層的な割込みサポートが有効になります。

child_to_parent_hwirq

このコールバックは、階層的な割込みチップで子ハードウェアIRQオフセットを親ハードウェアIRQオフセットに変換します。子ハードウェアIRQはGPIOインデックス0..ngpio-1に対応します（ngpioフィールドを参照してください） struct gpio_chip）および対応する親ハードウェアIRQとタイプ（IRQ_TYPE_*など）はドライバによって返されます。ドライバはオフセットや検索テーブル、またはこのチップに最適な方法を使用してこの値を計算できます。ドライバで変換に成功した場合は0を返します。

一部のハードウェアIRQ範囲に親HWIRQが対応しない場合、-EINVALを返しますが、同時に以下のフィールドを埋め込むことも確認してください valid_mask および need_valid_mask これらのGPIOラインを翻訳不可にします。

populate_parent_alloc_arg

このオプションコールバックは、親のIRQドメイン用の特定の構造体を割り当てて初期化します。このコールバックが指定されていない場合、 gpiochip_populate_parent_fwspec_twocell が使用されます。4セルの変体名 gpiochip_populate_parent_fwspec_fourcell も利用可能です。

child_offset_to_irq

このオプションコールバックは、GPIOチップ上の子のGPIOラインオフセットをGPIO to_irq()コールバック用のIRQ番号に変換します。このコールバックが指定されていない場合、ラインオフセットを返すデフォルトコールバックが提供されます。

child_irq_domain_ops

このGPIO IRQチップで使用されるIRQドメイン操作。操作が指定されていない場合、デフォルトのコールバックが使用されてIRQ階層が設定されます。一部のドライバでは独自のtranslate関数を提供する必要があります。

handler

GPIO IRQ用のIRQハンドラ（通常は事前に定義されたIRQコア関数）はGPIOドライバによって提供されます。

default_type

GPIOドライバ初期化時に適用されるデフォルトのIRQトリガー型、GPIOドライバによって提供されます。

lock_key

各GPIO IRQチップのlockdepクラス（IRQロック用）

request_key

各GPIO IRQチップのlockdepクラス（IRQリクエスト用）

parent_handler

GPIOチップの親割込みの割込みハンドラ。親割込みがネストされている場合、NULLになる可能性がある。

parent_handler_data

親割込みのハンドラに関連付けられたデータ。

num_parents

GPIOチップの割込み親の数。

parents

GPIOチップの割込み親の一覧。このリストはドライバが所有しているため、コアはこのリストを参照するだけで変更しない。

map

GPIOチップの各ラインの割込み親の一覧。

threaded

割込み処理がネストされたスレッドを使用する場合にTrue。

init_hw

IRQチップが追加される前にハードウェアを初期化するオプションのルーチン。特定のドライバがIRQ関連レジスタをクリアして不意のイベントを回避したい場合に非常に役立つ。

init_valid_mask

初期化用のオプションルーチン valid_maskすべてのGPIOラインが有効な割込みである必要がない場合に使用。一部のラインが割込みを発生させられない場合があり、このルーチンが定義されている場合は「valid_mask」にビットマスクを渡され、0..(ngpios-1)のngpiosビットを「1」に設定して有効とみなす。コールバックは使用できない割込みに対応するビットを「0」に直接設定できる。

valid_mask

もし NULL チップのIRQドメインに含める有効なGPIOのビットマスク。

first

静的IRQ割当に必要。設定されている場合、irq_domain_add_simple()は初期化時にすべてのIRQを割り当ててマッピングする。

irq_enable

古いirq_chip irq_enableコールバックを保存

irq_disable

古いirq_chip irq_disableコールバックを保存

irq_unmask

古いirq_chip irq_unmaskコールバックを保存

irq_mask

古いirq_chip irq_maskコールバックを保存

GPIOコントローラーを抽象化

定義

struct gpio_chip {
  const char              *label;
  struct gpio_device      *gpiodev;
  struct device           *parent;
  struct module           *owner;
  int (*request)(struct gpio_chip *gc, unsigned int offset);
  void (*free)(struct gpio_chip *gc, unsigned int offset);
  int (*get_direction)(struct gpio_chip *gc, unsigned int offset);
  int (*direction_input)(struct gpio_chip *gc, unsigned int offset);
  int (*direction_output)(struct gpio_chip *gc, unsigned int offset, int value);
  int (*get)(struct gpio_chip *gc, unsigned int offset);
  int (*get_multiple)(struct gpio_chip *gc,unsigned long *mask, unsigned long *bits);
  void (*set)(struct gpio_chip *gc, unsigned int offset, int value);
  void (*set_multiple)(struct gpio_chip *gc,unsigned long *mask, unsigned long *bits);
  int (*set_config)(struct gpio_chip *gc,unsigned int offset, unsigned long config);
  int (*to_irq)(struct gpio_chip *gc, unsigned int offset);
  void (*dbg_show)(struct seq_file *s, struct gpio_chip *gc);
  int (*init_valid_mask)(struct gpio_chip *gc,unsigned long *valid_mask, unsigned int ngpios);
  int (*add_pin_ranges)(struct gpio_chip *gc);
  int base;
  u16 ngpio;
  const char              *const *names;
  bool can_sleep;
#if IS_ENABLED(CONFIG_GPIO_GENERIC);
  unsigned long (*read_reg)(void __iomem *reg);
  void (*write_reg)(void __iomem *reg, unsigned long data);
  bool be_bits;
  void __iomem *reg_dat;
  void __iomem *reg_set;
  void __iomem *reg_clr;
  void __iomem *reg_dir_out;
  void __iomem *reg_dir_in;
  bool bgpio_dir_unreadable;
  int bgpio_bits;
  spinlock_t bgpio_lock;
  unsigned long bgpio_data;
  unsigned long bgpio_dir;
#endif ;
#ifdef CONFIG_GPIOLIB_IRQCHIP;
  struct gpio_irq_chip irq;
#endif ;
  unsigned long *valid_mask;
#if defined(CONFIG_OF_GPIO);
  struct device_node *of_node;
  unsigned int of_gpio_n_cells;
  int (*of_xlate)(struct gpio_chip *gc, const struct of_phandle_args *gpiospec, u32 *flags);
#endif ;
  ANDROID_KABI_RESERVE(1);
  ANDROID_KABI_RESERVE(2);
};

メンバ

label

GPIOデバイスの機能名、例えば部品番号やSoC IPブロックの名前。

gpiodev

内部状態を保持する、オパケな構造体

parent

GPIOを提供するオプションの親デバイス

owner

アクティブなGPIOをエクスポートするモジュールの除去を防ぐ

request

チップ固有のアクティベーション処理用のオプションフック、例えばモジュール電源やクロックの有効化；スリープ可能

free

チップ固有のデアクティベーション処理用のオプションフック、例えばモジュール電源やクロックの無効化；スリープ可能

get_direction

信号「offset」の方向を返す、0=出力、1=入力（GPIO_LINE_DIRECTION_OUT / GPIO_LINE_DIRECTION_INと同じ）、または負のエラー。入力専用または出力専用のGPIOチップでも常にこの関数を実装することを推奨する。

direction_input

信号「offset」を入力として設定、またはエラーを返す。入力専用または出力専用のGPIOチップでは省略可能。

direction_output

信号「offset」を出力として設定、またはエラーを返す。入力専用または出力専用のGPIOチップでは省略可能。

get

信号「offset」の値を返す、0=ロー、1=ハイ、または負のエラー

get_multiple

「mask」で定義された複数のシグナルの値を読み込み、「bits」に保存し、成功時は0を、エラー時は負のエラーコードを返します

set

シグナル「offset」の出力値を設定します

set_multiple

「mask」で定義された複数のシグナルの出力値を設定します

set_config

さまざまな設定をサポートするオプションのハンドラ。generic pinconfと同じパックされた設定フォーマットを使用します

to_irq

非静的なgpio_to_irq()マッピングをサポートするオプションのハンドラ；実装はスリープしないでください

dbg_show

デバッグ用のdebugfsに内容を表示するオプションのルーチン；この項目を省略した場合デフォルトのコードが使用されますが、カスタムコードで追加の状態（例えばプルアップ/プルダウン設定など）を表示できます

init_valid_mask

初期化用のオプションルーチン valid_maskすべてのGPIOが有効でない場合に使用します

add_pin_ranges

ピン範囲を初期化するオプションのルーチン；GPIO機能を提供するピンの特殊なマッピングが必要な場合に使用します。GPIOチップの追加後に、IRQチップの追加前に呼ばれます

base

このチップで処理する最初のGPIO番号を指定します；登録時に負数の場合、動的ID割当を要求します。非推奨：非負数を指定してチップのベースオフセットを固定することは非推奨です。すべてのケースでgpiolibがチップベースを選択できるように、-1をベースとして渡してください。長期的には静的なGPIO番号空間を廃止したいです

ngpio

このコントローラーで処理するGPIOの数；最後のGPIOは（base + ngpio - 1）です

names

設定されている場合、このチップのGPIOの代替名として使用する文字列の配列を指定します。配列の任意のエントリはGPIOに代替名がない場合NULLにすることができますが、配列は ngpio 項目数分の長さです。名前には無符号整数を表す単一のprintkフォーマット指定子を含めることができます。これは実際にGPIO番号に置き換えられます

can_sleep

get()/set()メソッドがスリープする場合、このフラグを設定しなければなりません。これらはI2CまたはSPI経由でGPIOエクスパンドャーチップにアクセスする際にはスリープしなければなりません。このチップがIRQをサポートする場合、これらのIRQはスレッド化する必要があります。チップアクセスがスリープする可能性があるため（例：IRQステータスレジスタの読み出し時）

read_reg

汎用GPIO用の読み込み関数

write_reg

汎用GPIO用の書き込み関数

be_bits

汎用GPIOがビッグエンディアンのビット順序（ビット31がライン0、ビット30がライン1…ビット0がライン31）を表す場合、このフラグは汎用GPIOコアによってtrueに設定されます。これは内部管理用です

reg_dat

汎用GPIO用のデータ（入力）レジスタ

reg_set

汎用GPIO用の出力設定レジスタ（出力＝ハイ）

reg_clr

汎用GPIO用の出力クリアレジスタ（出力＝ロー）

reg_dir_out

汎用GPIO用の方向出力設定レジスタ

reg_dir_in

汎用GPIO用の方向入力設定レジスタ

bgpio_dir_unreadable

方向レジスタ（複数）は読み込めず、出力の内部状態トラッキングに依存する必要があります

bgpio_bits

汎用GPIO用に使用されるレジスタビット数、つまり<register width> * 8

bgpio_lock

チップ->bgpio_dataをロックするために使用されます。また、シャドウレジスタと実際のデータレジスタの書き込みを統合するために必要です。

bgpio_data

汎用GPIO用に安全にビットをクリア/設定するためのシャドウデータレジスタ。

bgpio_dir

汎用GPIO用に安全に方向をクリア/設定するためのシャドウ方向レジスタ。このワードの「1」はラインが出力として設定されていることを意味します。

irq

割り込みチップ機能をGPIOチップと統合します。ほとんどの実用的なケースでIRQの処理に使用できます。

valid_mask

もし NULL チップから使用可能なGPIOのビットマスクを保持します。

of_node

このGPIOコントローラーを表すデバイスツリーのノードへのポインタ。

of_gpio_n_cells

GPIO指定子を形成するために使用されるセルの数。

of_xlate

デバイスツリーのGPIO指定子をチップ相対のGPIO番号とフラグに変換するためのコールバック。

説明

gpio_chipはプラットフォームがさまざまなGPIOソースを抽象化し、共通のプログラミングインターフェースを通じてアクセスできるようにします。例として、SoCコントローラー、FPGA、マルチファンクションチップ、専用GPIO拡張チップなどが挙げられます。

各チップが制御する信号数で、メソッド呼び出しで「offset」値として0..(ngpio - 1)の範囲で識別されます。これらの信号がgpio_get_value(gpio)などの呼び出しで参照される際、オフセットはgpio番号から base 減算して計算されます。
