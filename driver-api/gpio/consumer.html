GPIOディスクリプタ消費者インターフェース¶

このドキュメントでは、GPIOフレームワークの消費者インターフェースについて説明します。注意点として、ここでは新しいディスクリプタベースのインターフェースについて説明しています。古い整数ベースのGPIOインターフェースについての説明はgpio-legacy.txtをご参照ください。

GPIO消費者のガイドライン¶

標準的なGPIOコールを使用せずに動作できないドライバーは、KconfigエントリでGPIOLIBまたはselect GPIOLIBに依存する必要があります。ドライバーがGPIOを取得・使用するための関数は、次のファイルをインクルードすることで利用可能です：

#include <linux/gpio/consumer.h>

GPIOLIBが無効の場合、ヘッダーファイルにはすべての関数に対する静的インラインスタブが用意されています。これらのスタブが呼び出されると警告が発生します。これらのスタブは以下の2つのユースケースで使用されます：

  • 簡単なコンパイルカバレッジ（例：COMPILE_TEST） - 現在のプラットフォームがGPIOLIBを有効化または選択していないとしても、システムを実行しないので問題ありません。

  • 本当にオプションのGPIOLIBサポート - あるコンパイル時設定で特定のシステムでGPIOを使用しないが、他のコンパイル時設定では使用する場合。この場合、消費者はこれらの関数を呼び出さないことを確認しなければなりません。それ以外の場合、コンソール警告が表示され、ユーザーに威圧感を与える可能性があります。

ディスクリプタベースのGPIOインターフェースで使用するすべての関数は、 gpiod_の部分で、 gpio_ prefixは古いインターフェース用です。カーネル内の他の関数はこれらのprefixを使用してはなりません。古い関数の使用は強く推奨されません。新しいコードでは<linux/gpio/consumer.h>とディスクリプタのみを使用する必要があります。

GPIOの取得と解放¶

ディスクリプタベースのインターフェースでは、GPIOは不透明で偽造不可能なハンドラで識別され、これは特定の関数呼び出しを通じて取得する必要があります。 gpiod_get() 多くの他のカーネルサブシステムと同様に、 gpiod_get() はGPIOを用いるデバイスと、リクエストされたGPIOが果たすべき機能を引数として受け取ります：

struct gpio_desc *gpiod_get(struct device *dev, const char *con_id,
                            enum gpiod_flags flags)

複数のGPIOを組み合わせて機能を実装する場合（例：数字を表示する単純なLEDデバイス）、追加のインデックス引数を指定できます：

struct gpio_desc *gpiod_get_index(struct device *dev,
                                  const char *con_id, unsigned int idx,
                                  enum gpiod_flags flags)

DeviceTreeの場合のcon_idパラメータについての詳細な説明は GPIOマッピング

フラグパラメータは、GPIOの方向と初期値をオプションで指定するために使用されます。値は以下の通りです：

  • GPIOD_ASISまたは0でGPIOを一切初期化しない。方向は後で専用の関数を使用して設定する必要があります。

  • GPIOD_INでGPIOを入力として初期化する。

  • GPIOD_OUT_LOW は、GPIO を出力として初期化し、値が 0 になるようにします。

  • GPIOD_OUT_HIGH は、GPIO を出力として初期化し、値が 1 になるようにします。

  • GPIOD_OUT_LOW_OPEN_DRAIN は GPIOD_OUT_LOW と同様ですが、オープンドレイン方式で電気的に使用されるように強制します。

  • GPIOD_OUT_HIGH_OPEN_DRAIN は GPIOD_OUT_HIGH と同様ですが、オープンドレイン方式で電気的に使用されるように強制します。

最後の 2 つのフラグは、オープンドレインが必須となる使用ケース（例: I2C）で使用されます。マッピング（board.txt を参照）でラインがすでにオープンドレインとして設定されていない場合、オープンドレインが強制的に適用され、使用ケースに合わせてボード設定を更新する必要があるという警告が表示されます。

これらの関数は、有効な GPIO デスクリプターか、IS_ERR() で確認可能なエラーコードを返します（NULL ポインタを返すことはありません）。GPIO がデバイス/機能/インデックスの組み合わせに割り当てられていない場合にのみ -ENOENT を返します。他のエラーコードは、GPIO が割り当てられているが取得中にエラーが発生した場合に使用されます。これは、オプションの GPIO パラメータで、GPIO の存在とエラーの区別を明確にするためのものです。オプションの GPIO パラメータの一般的なパターンでは、 gpiod_get_optional() および gpiod_get_index_optional() これらの関数を使用できます。GPIO が要求された機能に割り当てられていない場合、これらの関数は -ENOENT ではなく NULL を返します：

struct gpio_desc *gpiod_get_optional(struct device *dev,
                                     const char *con_id,
                                     enum gpiod_flags flags)

struct gpio_desc *gpiod_get_index_optional(struct device *dev,
                                           const char *con_id,
                                           unsigned int index,
                                           enum gpiod_flags flags)

gpio_get*_optional() 関数（およびそのマネージドバリアント）は、gpiolib API の他の部分とは異なり、gpiolib のサポートが無効になっている場合でも NULL を返します。これはドライバ開発者にとって便利で、-ENOSYS の返却コードを特別な処理する必要がありません。システム統合者は、必要に応じて gpiolib を有効にする必要があります。

複数の GPIO を使用する関数では、1 回の呼び出しですべての GPIO を取得できます：

struct gpio_descs *gpiod_get_array(struct device *dev,
                                   const char *con_id,
                                   enum gpiod_flags flags)

この関数は struct gpio_descs を返し、これはデスクリプターの配列を含みます。また、gpiolib のプライベート構造体へのポインタも含み、これを get/set 配列関数に渡すことで、I/O プロセスの処理を高速化する可能性があります：

struct gpio_descs {
        struct gpio_array *info;
        unsigned int ndescs;
        struct gpio_desc *desc[];
}

次の関数は、要求された機能に GPIO が割り当てられていない場合、-ENOENT ではなく NULL を返します：

struct gpio_descs *gpiod_get_array_optional(struct device *dev,
                                            const char *con_id,
                                            enum gpiod_flags flags)

これらの関数のデバイス管理バリアントも定義されています：

struct gpio_desc *devm_gpiod_get(struct device *dev, const char *con_id,
                                 enum gpiod_flags flags)

struct gpio_desc *devm_gpiod_get_index(struct device *dev,
                                       const char *con_id,
                                       unsigned int idx,
                                       enum gpiod_flags flags)

struct gpio_desc *devm_gpiod_get_optional(struct device *dev,
                                          const char *con_id,
                                          enum gpiod_flags flags)

struct gpio_desc *devm_gpiod_get_index_optional(struct device *dev,
                                                const char *con_id,
                                                unsigned int index,
                                                enum gpiod_flags flags)

struct gpio_descs *devm_gpiod_get_array(struct device *dev,
                                        const char *con_id,
                                        enum gpiod_flags flags)

struct gpio_descs *devm_gpiod_get_array_optional(struct device *dev,
                                                 const char *con_id,
                                                 enum gpiod_flags flags)

GPIO デスクリプターは、以下の関数を使用して破棄できます： gpiod_put() 関数：

void gpiod_put(struct gpio_desc *desc)

GPIO の配列に対しては、この関数を使用できます：

void gpiod_put_array(struct gpio_descs *descs)

これらの関数を呼び出した後は、デスクリプターを使用してはいけません。また、配列で取得したデスクリプターを個別に解放する（ gpiod_put()) することも許可されていません。 gpiod_get_array().

デバイス管理バリアントは、予想通り：

void devm_gpiod_put(struct device *dev, struct gpio_desc *desc)

void devm_gpiod_put_array(struct device *dev, struct gpio_descs *descs)

GPIO の使用¶

方向の設定¶

ドライバーがGPIOを扱う最初のステップは、その方向を設定することです。gpiod_get*()に方向設定フラグが渡されていない場合、gpiod_direction_*()関数のいずれかを呼び出すことで方向を設定します:

int gpiod_direction_input(struct gpio_desc *desc)
int gpiod_direction_output(struct gpio_desc *desc, int value)

戻り値は成功時はゼロ、エラー時は負のエラー番号となります。チェックする必要があります。なぜなら、get/set呼び出しはエラーを返しませんし、誤設定が発生する可能性があるからです。通常はタスクコンテキストからこれらの呼び出しを実行する必要があります。ただし、スピンロック安全なGPIOについては、タスクが有効化される前でも早めのボード初期化の一部として使用することが可能です。

出力GPIOの場合、提供された値が初期出力値になります。これにより、システム起動時の信号のグルチングを回避できます。

ドライバーはGPIOの現在の方向を照会することもできます:

int gpiod_get_direction(const struct gpio_desc *desc)

この関数は、出力の場合は0、入力の場合は1を返します。エラーの場合はエラーコードを返します。

GPIOにはデフォルトの方向がありませんので、 方向を設定せずにGPIOを使用することは不正であり、未定義の動作を引き起こします！

スピンロック安全なGPIOアクセス¶

ほとんどのGPIOコントローラーはメモリ読み書き命令でアクセスできます。これらはスリープを必要とせず、ハード（非スレッド）IRQハンドラ内や類似コンテキストから安全に実行できます。

アトミックコンテキストからGPIOをアクセスするには、次の呼び出しを使用します:

int gpiod_get_value(const struct gpio_desc *desc);
void gpiod_set_value(struct gpio_desc *desc, int value);

値は論理値で、ゼロはロー、ゼロ以外はハイを表します。出力ピンの値を読み込む際、返される値はピンに実際に現れる値です。ただし、オープンドレイン信号や出力遅延などの問題により、指定された出力値と一致しない場合があります。

get/set呼び出しはエラーを返しません。なぜなら、「無効なGPIO」はgpiod_direction_*()からすでに報告済みだからです。ただし、すべてのプラットフォームが出力ピンの値を読み込むことができるわけではありません。読み込めないプラットフォームでは常にゼロを返す必要があります。また、スリープせずに安全にアクセスできないGPIO（以下参照）に対してこれらの呼び出しを行うことはエラーです。

スリープ可能なGPIOアクセス¶

一部のGPIOコントローラーはI2CやSPIなどのメッセージベースのバスでアクセスする必要があります。これらのGPIO値を読み書きするコマンドは、キューの先頭に到達してコマンドを送信し、応答を受信するのを待つ必要があります。これはスリープを必要とし、IRQハンドラ内では実行できません。

このタイプのGPIOをサポートするプラットフォームは、次の呼び出しで他のGPIOと区別します:

int gpiod_cansleep(const struct gpio_desc *desc)

このようなGPIOをアクセスするため、異なるアクセッサが定義されています:

int gpiod_get_value_cansleep(const struct gpio_desc *desc)
void gpiod_set_value_cansleep(struct gpio_desc *desc, int value)

このようなGPIOにアクセスするには、スリープする可能性のあるコンテキストが必要です（例えばスレッド化されたIRQハンドラ）、そしてこれらのアクセッサは、cansleep()名前接尾辞を含まないスピンロック安全なアクセッサではなく、代わりに使用する必要があります。

これらのアクセッサがスリープする可能性があること、およびハードIRQハンドラからアクセスできないGPIOにも動作することを除けば、これらの呼び出しはスピンロック安全な呼び出しと同様の動作を行います。

アクティブローおよびオープンドレインのセマンティクス¶

消費者が物理的なラインレベルに気を配る必要がないため、すべてのgpiod_set_value_xxx()またはgpiod_set_array_value_xxx()関数は、 論理的な valueを操作します。これにより、アクティブローのプロパティを考慮し、GPIOがアクティブローに設定されている場合、物理的なラインレベルを駆動する前に渡された値を処理します。

オープンドレインまたはオープンソース出力ラインについても同様です：これらは出力が高（オープンドレイン）または低（オープンソース）になるように積極的に駆動しません。代わりに、出力がハイインピーダンス値に切り替わるだけです。消費者はこれに気を配る必要はありません。（詳細についてはドライバーテキストのオープンドレインセクションを参照してください。）

これにより、すべてのgpiod_set_(array)_value_xxx()関数は、パラメータ「value」を「アサートされた」（「1」）または「デアサートされた」（「0」）として解釈します。物理的なラインレベルはこれに応じて駆動されます。

例として、特定のGPIOのアクティブロープロパティが設定されている場合、gpiod_set_(array)_value_xxx()が「アサートされた」（「1」）を渡すと、物理的なラインレベルは低くなります。

まとめると：

Function (example)                 line property          physical line
gpiod_set_raw_value(desc, 0);      don't care             low
gpiod_set_raw_value(desc, 1);      don't care             high
gpiod_set_value(desc, 0);          default (active high)  low
gpiod_set_value(desc, 1);          default (active high)  high
gpiod_set_value(desc, 0);          active low             high
gpiod_set_value(desc, 1);          active low             low
gpiod_set_value(desc, 0);          open drain             low
gpiod_set_value(desc, 1);          open drain             high impedance
gpiod_set_value(desc, 0);          open source            high impedance
gpiod_set_value(desc, 1);          open source            high

set_raw/get_raw関数を使用することでこれらのセマンティクスを上書きすることは可能ですが、システムに依存しないドライバなどはできるだけ避けるべきです。これらは物理的なラインレベルに気を配る必要がなく、論理的な値に焦点を当てるべきです。

raw GPIO値のアクセス¶

GPIOラインの論理状態を管理する必要がある消費者が存在します。つまり、デバイスが実際に受信する値を、GPIOラインとの間にあるものに関係なく、気にする必要がない場合です。

以下の関数呼び出しは、GPIOのアクティブローまたはオープンドレインのプロパティを無視し、rawライン値を操作します：

int gpiod_get_raw_value(const struct gpio_desc *desc)
void gpiod_set_raw_value(struct gpio_desc *desc, int value)
int gpiod_get_raw_value_cansleep(const struct gpio_desc *desc)
void gpiod_set_raw_value_cansleep(struct gpio_desc *desc, int value)
int gpiod_direction_output_raw(struct gpio_desc *desc, int value)

GPIOのアクティブロー状態は以下の関数呼び出しを使用して照会できます：

int gpiod_is_active_low(const struct gpio_desc *desc)

これらの関数は、物理的なラインレベルやオープンドレインセマンティクスに気を配る必要がないため、極力控えるべきです。

単一の関数呼び出しで複数のGPIOをアクセス¶

以下の関数は、GPIO配列の値を取得または設定します：

int gpiod_get_array_value(unsigned int array_size,
                          struct gpio_desc **desc_array,
                          struct gpio_array *array_info,
                          unsigned long *value_bitmap);
int gpiod_get_raw_array_value(unsigned int array_size,
                              struct gpio_desc **desc_array,
                              struct gpio_array *array_info,
                              unsigned long *value_bitmap);
int gpiod_get_array_value_cansleep(unsigned int array_size,
                                   struct gpio_desc **desc_array,
                                   struct gpio_array *array_info,
                                   unsigned long *value_bitmap);
int gpiod_get_raw_array_value_cansleep(unsigned int array_size,
                                   struct gpio_desc **desc_array,
                                   struct gpio_array *array_info,
                                   unsigned long *value_bitmap);

int gpiod_set_array_value(unsigned int array_size,
                          struct gpio_desc **desc_array,
                          struct gpio_array *array_info,
                          unsigned long *value_bitmap)
int gpiod_set_raw_array_value(unsigned int array_size,
                              struct gpio_desc **desc_array,
                              struct gpio_array *array_info,
                              unsigned long *value_bitmap)
int gpiod_set_array_value_cansleep(unsigned int array_size,
                                   struct gpio_desc **desc_array,
                                   struct gpio_array *array_info,
                                   unsigned long *value_bitmap)
int gpiod_set_raw_array_value_cansleep(unsigned int array_size,
                                       struct gpio_desc **desc_array,
                                       struct gpio_array *array_info,
                                       unsigned long *value_bitmap)

配列は任意のGPIOのセットにすることができます。関数は、対応するチップドライバーがサポートする場合、同じバンクまたはチップに属するGPIOを同時にアクセスしようとします。その場合、大幅なパフォーマンス向上が期待できます。同時にアクセスできない場合は、GPIOが順番にアクセスされます。

関数は3つの引数を取ります:

  • array_size - 配列の要素数

  • desc_array - GPIO記述子の配列

  • array_info - 取得可能なオプション情報 gpiod_get_array()

  • value_bitmap - GPIOの値を保存するビットマップ（取得時）または

    GPIOに割り当てる値のビットマップ（設定時）

ディスクリプタ配列は次の方法で取得できます gpiod_get_array() 関数またはその変体を使用することで、その関数が返す記述子のグループが望ましいGPIOのグループと一致する場合、それらのGPIOは、struct gpio_descsが返す構造体を使用して簡単にアクセスできます。 gpiod_get_array():

struct gpio_descs *my_gpio_descs = gpiod_get_array(...);
gpiod_set_array_value(my_gpio_descs->ndescs, my_gpio_descs->desc,
                      my_gpio_descs->info, my_gpio_value_bitmap);

また、完全に任意の記述子の配列にアクセスすることも可能です。記述子は、任意の組み合わせを使用して取得できます。 gpiod_get() および gpiod_get_array()その後、配列の記述子を手動で設定する必要があります。その場合、array_infoはNULLに設定する必要があります。

最適な性能を達成するため、同一チップに属するGPIOはデスクリプタの配列内で連続している必要があります。

さらに高い性能が得られる場合があります。デスクリプタの配列インデックスが単一チップのハードウェアピン番号と一致する場合です。get/set配列関数に渡された配列が、 gpiod_get_array() and array_info関連付けられた配列情報も渡されると、関数は高速ビットマップ処理パスを採用し、value_bitmap引数を該当する.chipの.get/set_multiple()コールバックに直接渡します。これにより、GPIOバンクをデータI/Oポートとして利用することが可能で、性能への影響が最小限に抑えられます。

返却値は gpiod_get_array_value() and its variantsは成功時に0、エラー時に負の値を返します。～との違いに注意してください。 gpiod_get_value()成功時に0または1を返しますが、GPIO値を伝達します。配列関数を使用すると、GPIO値はvalue_arrayに格納されるため、返却値として渡されません。

GPIOが割り当てられたIRQ¶

GPIOラインはIRQとしてよく使用されます。特定のGPIOに対応するIRQ番号を取得するには、次の呼び出しを使用します：

int gpiod_to_irq(const struct gpio_desc *desc)

マッピングができない場合（特にそのGPIOがIRQとして使用できない可能性が高い場合）、IRQ番号か負のerrnoコードを返します。GPIOが入力として設定されていない場合に使用することは未チェックのエラーです gpiod_direction_input()、または元々から取得したIRQ番号を使用しないこと gpiod_to_irq(). gpiod_to_irq() スリープは許可されていません。

Non-error values returned from gpiod_to_irq() can be passed to request_irq() または free_irq(). They will often be stored into IRQ resources for platform devices, by the board-specific initialization code. Note that IRQ trigger options are part of the IRQ interface, e.g. IRQF_TRIGGER_FALLING, as are system wakeup capabilities.

GPIOs and ACPI¶

On ACPI systems, GPIOs are described by GpioIo()/GpioInt() resources listed by the _CRS configuration objects of devices. Those resources do not provide connection IDs (names) for GPIOs, so it is necessary to use an additional mechanism for this purpose.

Systems compliant with ACPI 5.1 or newer may provide a _DSD configuration object which, among other things, may be used to provide connection IDs for specific GPIOs described by the GpioIo()/GpioInt() resources in _CRS. If that is the case, it will be handled by the GPIO subsystem automatically. However, if the _DSD is not present, the mappings between GpioIo()/GpioInt() resources and GPIO connection IDs need to be provided by device drivers.

For details refer to _DSD デバイスプロパティ（GPIO関連）

Interacting With the Legacy GPIO Subsystem¶

Many kernel subsystems still handle GPIOs using the legacy integer-based interface. Although it is strongly encouraged to upgrade them to the safer descriptor-based API, the following two functions allow you to convert a GPIO descriptor into the GPIO integer namespace and vice-versa:

int desc_to_gpio(const struct gpio_desc *desc)
struct gpio_desc *gpio_to_desc(unsigned gpio)

The GPIO number returned by desc_to_gpio() can be safely used as long as the GPIO descriptor has not been freed. All the same, a GPIO number passed to gpio_to_desc() must have been properly acquired, and usage of the returned GPIO descriptor is only possible after the GPIO number has been released.

Freeing a GPIO obtained by one API with the other API is forbidden and an unchecked error.
