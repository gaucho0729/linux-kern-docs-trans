バッファ¶

  • struct iio_buffer — 一般的なバッファ構造

  • iio_validate_scan_mask_onehot() — 選択されたチャンネルがちょうど1つであることを検証します

  • iio_buffer_get() — バッファへの参照を取得します

  • iio_buffer_put() — バッファへの参照を解放します

Industrial I/Oコアは、トリガー源に基づいた連続データキャプチャの方法を提供します。複数のデータチャンネルは、 /dev/iio:deviceX キャラクターデバイスノードから一度に読み取ることができ、CPU負荷を減らします。

IIOバッファ sysfsインターフェース¶

IIOバッファは、以下にアトリビュートディレクトリが関連付けられています。 /sys/bus/iio/iio:deviceX/buffer/*. 既存の属性の一例は以下の通りです:

  • length, バッファが保存できるデータサンプルの総数（容量）

  • enable, バッファキャプチャを有効化します

IIOバッファの設定¶

バッファに配置されたチャンネル読み取りに関連するメタ情報はスキャン要素と呼ばれます。スキャン要素を構成する重要なビットは、以下にユーザー空間アプリケーションに公開されます。 /sys/bus/iio/iio:deviceX/scan_elements/* ディレクトリ。このファイルには以下の形式の属性が含まれています:

  • enable, チャンネルを有効にするために使用されます。その属性が非 ゼロの場合、トリガーされたキャプチャにはこのチャンネルのデータサンプルが含まれます

  • type, バッファ内のスキャン要素データの保存方法を記述し、ユーザー空間から読み取る形式を示します。形式は [be|le]:[s|u]bits/storagebitsXrepeat[>>shift] です。* be または le, ビッグエンディアンまたはリトルエンディアンを指定します。* s または u, 符号付き（2の補数）か符号なしを指定します。* ビット, 有効なデータビット数を指定します。* storagebits, バッファ内で占有するビット数（パディング後）を指定します。* シフト, 指定された場合、不要なビットをマスクする前に適用するシフト量を指定します。* repeat, ビット/ストレージビットの繰り返し数を指定します。repeat要素が0または1の場合、repeat値は省略されます。

例として、3軸加速度計のドライバで、データが2つの8ビットレジスタに保存される場合があります。

  7   6   5   4   3   2   1   0
+---+---+---+---+---+---+---+---+
|D3 |D2 |D1 |D0 | X | X | X | X | (LOW byte, address 0x06)
+---+---+---+---+---+---+---+---+

  7   6   5   4   3   2   1   0
+---+---+---+---+---+---+---+---+
|D11|D10|D9 |D8 |D7 |D6 |D5 |D4 | (HIGH byte, address 0x07)
+---+---+---+---+---+---+---+---+

各軸には以下のスキャン要素タイプがあります:

$ cat /sys/bus/iio/devices/iio:device0/scan_elements/in_accel_y_type
le:s12/16>>4

ユーザー空間アプリケーションは、バッファから読み取ったデータサンプルを、2バイトのリトルエンディアン符号付きデータと解釈します。これは12ビットの有効データをマスクする前に4ビット右シフトが必要です。

バッファサポートを実装するには、iio_chan_spec定義で以下のフィールドを初期化する必要があります:

struct iio_chan_spec {
/* other members */
        int scan_index
        struct {
                char sign;
                u8 realbits;
                u8 storagebits;
                u8 shift;
                u8 repeat;
                enum iio_endian endianness;
               } scan_type;
       };

上記の加速度計を実装するドライバには、以下のチャンネル定義があります:

struct iio_chan_spec accel_channels[] = {
        {
                .type = IIO_ACCEL,
                .modified = 1,
                .channel2 = IIO_MOD_X,
                /* other stuff here */
                .scan_index = 0,
                .scan_type = {
                        .sign = 's',
                        .realbits = 12,
                        .storagebits = 16,
                        .shift = 4,
                        .endianness = IIO_LE,
                },
        }
        /* similar for Y (with channel2 = IIO_MOD_Y, scan_index = 1)
         * and Z (with channel2 = IIO_MOD_Z, scan_index = 2) axis
         */
 }

ここでは scan_index 、有効化されたチャンネルがバッファ内で配置される順序を定義します。低い scan_index のインデックスを持つチャンネルは、高いインデックスを持つチャンネルよりも前に配置されます。各チャンネルは一意の scan_index.

設定 scan_index to -1は、特定のチャンネルがバッファーキャプチャをサポートしていないことを示すために使用できます。この場合、scan_elementsディレクトリにチャンネルに関するエントリが作成されません。

int iio_push_to_buffers_with_timestamp(struct iio_dev *indio_dev, void *data, int64_t timestamp)¶

データとタイムスタンプをバッファに送信

パラメータ

struct iio_dev *indio_dev

デバイス用のiio_dev構造体。

void *data

サンプルデータ

int64_t timestamp

サンプルデータのタイムスタンプ

説明

IIOデバイスのバッファにデータをプッシュします。タイムスタンプが有効になっているデバイスの場合、この関数は提供されたタイムスタンプをサンプルデータバッファの最後の要素として保存し、その後デバイスのバッファにプッシュします。サンプルデータバッファは追加のタイムスタンプを保持できるサイズ（通常はindio->scan_bytesバイト）でなければなりません。

成功時は0を返し、エラーの場合は負のエラーコードを返します。
