コア要素¶

Industrial I/O コアは、さまざまな種類の埋め込みセンサー用ドライバを書くための統一されたフレームワークと、ユーザー空間アプリケーションがセンサーを操作するための標準インターフェースを提供します。実装は以下の場所にあります drivers/iio/industrialio-*

Industrial I/O デバイス¶

  • struct iio_dev - 工業用I/Oデバイス

  • iio_device_alloc() - 割り当て iio_dev ドライバから

  • iio_device_free() - 解放 iio_dev ドライバから

  • iio_device_register() - IIOサブシステムにデバイスを登録

  • iio_device_unregister() - IIOサブシステムからデバイスを登録解除

IIOデバイスは通常、1つのハードウェアセンサーに該当し、ドライバがデバイスを処理するために必要なすべての情報を提供します。まずはIIOデバイスに組み込まれた機能を見て、その後でドライバがIIOデバイスをどのように利用するかを示します。

ユーザー空間アプリケーションがIIOドライバとやり取りする方法は2通りあります。

  1. /sys/bus/iio/iio:deviceX/、これはハードウェアセンサーを表し、同じチップのデータチャネルをグループ化しています。

  2. /dev/iio:deviceX、バッファードデータ転送とイベント情報の取得に使用されるキャラクターデバイスノードインターフェース。

典型的なIIOドライバは、自身を I2C または SPI ドライバとして登録し、probeとremoveという2つのルーチンを作成します。

probe時:

  1. を呼び出して、MMIOまたはIOポート範囲を利用可能にします。これを実施しないと、ドライバの再ロードができない状態になります。 iio_device_alloc()、IIOデバイスのメモリを割り当てます。

  2. IIOデバイスのフィールドをドライバ固有の情報（例：デバイス名、デバイスチャネル）で初期化します。

  3. を呼び出して、MMIOまたはIOポート範囲を利用可能にします。これを実施しないと、ドライバの再ロードができない状態になります。 iio_device_register()、デバイスをIIOコアに登録します。この呼び出し後、デバイスはユーザー空間アプリケーションからのリクエストを受け入れるようになります。

remove時、probeで割り当てたリソースを逆の順序で解放します:

  1. iio_device_unregister()、IIOコアからデバイスを登録解除します。

  2. iio_device_free()、IIOデバイスのメモリを解放します。

IIOデバイス sysfsインターフェース¶

属性はsysfsファイルで、チップ情報の公開やアプリケーションがさまざまな設定パラメータを設定できるようにします。インデックスXを持つデバイスの属性は、/sys/bus/iio/iio:deviceX/ ディレクトリにあります。一般的な属性は以下の通り:

  • name、物理チップの説明。

  • dev、が関連付けられている主:補助ペアを表示します /dev/iio:deviceX ノード。

  • sampling_frequency_available、デバイスの利用可能な離散的なサンプリング周波数値のセット。

  • IIOデバイスの利用可能な標準属性は、Linuxカーネルソースの Documentation/ABI/testing/sysfs-bus-iio ファイルで説明されています。

IIOデバイスチャネル¶

struct iio_chan_spec - 単一チャネルの仕様

IIOデバイスチャネルはデータチャネルの表現です。IIOデバイスは1つまたは複数のチャネルを持つことができます。例えば:

  • 温度計センサーは温度測定を表す1つのチャネルを持ちます。

  • 可視光と赤外線領域の測定を示す2つのチャネルを持つ光センサー。

  • 加速度計はX、Y、Z軸の加速度を表す最大3つのチャネルを持つことができます。

IIOチャンネルは次の通り記述されます struct iio_chan_spec. 上記の例にある温度センサーのサーモメータードライバーは、そのチャンネルを次の通り記述する必要があります:

static const struct iio_chan_spec temp_channel[] = {
     {
         .type = IIO_TEMP,
         .info_mask_separate = BIT(IIO_CHAN_INFO_PROCESSED),
     },
};

ユーザー空間に公開されるチャンネルsysfs属性はビットマスク形式で指定されます。共有情報に応じて、属性は次のマスクのいずれかに設定されます:

  • info_mask_separate, 属性はこのチャンネルに特有です

  • info_mask_shared_by_type, 同じタイプのすべてのチャンネルで共有されます

  • info_mask_shared_by_dir, 同じ方向のすべてのチャンネルで共有されます

  • info_mask_shared_by_all, すべてのチャンネルで共有されます

チャンネルタイプごとに複数のデータチャンネルがある場合、区別する方法は2通りあります:

  • set .modified の iio_chan_spec を1に設定します。modifierは次の通り指定されます .channel2 の同じ iio_chan_spec 構造体のフィールドで、チャンネルの物理的に一意な特徴（方向やスペクトル応答など）を示します。例えば、光センサーは赤外線光用と赤外線および可視光用の2つのチャンネルを持つことができます。

  • set .indexed の iio_chan_spec を1に設定します。この場合、チャンネルは単にインデックスで指定される別のインスタンスです .channel フィールドによって保護されています。

チャンネルのmodifierを活用する方法は次の通りです:

static const struct iio_chan_spec light_channels[] = {
        {
                .type = IIO_INTENSITY,
                .modified = 1,
                .channel2 = IIO_MOD_LIGHT_IR,
                .info_mask_separate = BIT(IIO_CHAN_INFO_RAW),
                .info_mask_shared = BIT(IIO_CHAN_INFO_SAMP_FREQ),
        },
        {
                .type = IIO_INTENSITY,
                .modified = 1,
                .channel2 = IIO_MOD_LIGHT_BOTH,
                .info_mask_separate = BIT(IIO_CHAN_INFO_RAW),
                .info_mask_shared = BIT(IIO_CHAN_INFO_SAMP_FREQ),
        },
        {
                .type = IIO_LIGHT,
                .info_mask_separate = BIT(IIO_CHAN_INFO_PROCESSED),
                .info_mask_shared = BIT(IIO_CHAN_INFO_SAMP_FREQ),
        },
   }

このチャンネルの定義は、素データ取得用に2つの別々のsysfsファイルを生成します:

  • /sys/bus/iio/iio:deviceX/in_intensity_ir_raw

  • /sys/bus/iio/iio:deviceX/in_intensity_both_raw

処理済みデータ用の1つのファイル:

  • /sys/bus/iio/iio:deviceX/in_illuminance_input

およびサンプリング周波数用の共有sysfsファイル:

  • /sys/bus/iio/iio:deviceX/sampling_frequency.

チャンネルのインデックスを活用する方法は次の通りです:

static const struct iio_chan_spec light_channels[] = {
        {
                .type = IIO_VOLTAGE,
                .indexed = 1,
                .channel = 0,
                .info_mask_separate = BIT(IIO_CHAN_INFO_RAW),
        },
        {
                .type = IIO_VOLTAGE,
                .indexed = 1,
                .channel = 1,
                .info_mask_separate = BIT(IIO_CHAN_INFO_RAW),
        },
}

これにより、素データ取得用に2つの別々の属性ファイルが生成されます:

  • /sys/bus/iio/devices/iio:deviceX/in_voltage0_raw, チャンネル0の電圧測定を表します。

  • /sys/bus/iio/devices/iio:deviceX/in_voltage1_raw, チャンネル1の電圧測定を表します。

struct iio_enum¶

列挙型チャンネル情報属性

定義

struct iio_enum {
  const char * const *items;
  unsigned int num_items;
  int (*set)(struct iio_dev *, const struct iio_chan_spec *, unsigned int);
  int (*get)(struct iio_dev *, const struct iio_chan_spec *);
};

メンバ

items

文字列の配列

num_items

項目配列の長さ

set

コールバック関数を設定します。NULLを指定することもできます。

get

コールバック関数を取得します。NULLを指定することもできます。

説明

iio_enum構造体は、エナムスタイルのチャネル属性を実装するために使用できます。エナムスタイルの属性とは、一連の文字列が符号なし整数値にマッピングされる属性を指します。IIOエナムヘルパーコードは、値と文字列のマッピングを処理し、「_available」ファイルを生成して、すべての利用可能な項目の一覧を提供します。属性が更新されるときにsetコールバックが呼ばれます。最後のパラメータは、新たにアクティブになった項目のインデックスです。getコールバックは現在アクティブな項目を照会するために使用され、そのインデックスを返す必要があります。

struct iio_chan_spec {
  enum iio_chan_type      type;

  const struct iio_chan_spec_ext_info *ext_info;

};

メンバ

type

このチャネルが測定する測定タイプ

channel

チャネルに割り当てる希望する番号

channel2

差動チャネルに2番目の番号がある場合、ここに指定します。modifiedが設定されている場合は、ここに指定された値が修正値になります。

address

ドライバ固有の識別子

scan_index

バッファから読み取る際のスキャンでの順序を示す単調インデックス

scan_type

スキャンタイプを記述する構造体

scan_type.sign

符号付き（'s'）または符号なし（'u'）を指定します

scan_type.realbits

有効なデータビット数

scan_type.storagebits

リアルビット + パディング

scan_type.shift

リアルビットをマスクする前にこの値で右シフトします。

scan_type.repeat

リアル/ストレージビットの繰り返し回数。繰り返し要素が1より大きい場合、sysfsのtype要素には繰り返し値が表示されます。それ以外の場合、繰り返し回数は省略されます。

scan_type.endianness

リトルエンディアンまたはビッグエンディアン

info_mask_separate

このチャネルに特有の情報がエクスポートされるべきものです。

info_mask_separate_available

このチャネルに特有の利用可能情報がエクスポートされるべきものです。

info_mask_shared_by_type

同じタイプのすべてのチャネルで共有される情報がエクスポートされるべきものです。

info_mask_shared_by_type_available

同じタイプのすべてのチャネルで共有される利用可能情報がエクスポートされるべきものです。

info_mask_shared_by_dir

同じ方向のすべてのチャネルで共有される情報がエクスポートされるべきものです。

info_mask_shared_by_dir_available

同じ方向のすべてのチャネルで共有される利用可能情報がエクスポートされるべきものです。

info_mask_shared_by_all

すべてのチャネルで共有される情報がエクスポートされるべきものです。

info_mask_shared_by_all_available

すべてのチャネルで共有される利用可能情報がエクスポートされるべきものです。

event_spec

このチャネルに登録するべきイベントの配列。

num_event_specs

event_spec配列のサイズ。

ext_info

このチャネルの拡張情報属性の配列。配列はNULL終端され、最後の要素のnameフィールドはNULLに設定する必要があります。

extend_name

チャネル属性に説明的な名前を付けることを許可します。これはmodifierとは異なり、コードなどの影響はありません。

datasheet_name

チャネルの内核マッピングに使用される名前。データシートでチャネルが最初に参照される名前（例: IND）または最も近い複合名（例: IND-INC）に該当する必要があります。

modified

このチャネルにmodifierが適用されますか。modifierの種類はチャネルタイプに依存します。modifierはchannel2で設定されます。例: 軸方向のセンサーについてのx軸に関するIIO_MOD_Xなど。

indexed

チャネルが数値インデックスを持つことを指定します。指定しない場合、sysfs属性ではチャネルインデックス番号が抑制されますが、イベントコードでは抑制されません。

output

出力チャネル

differential

差分チャネル

メンバ

event_attrs

イベント制御属性

attrs

汎用デバイス属性

read_raw

デバイスから値を要求するための関数。maskはどの値を指定するかを示します。注意: 0は対象のチャネルの読み取りを意味します。返却値はデバイスが返す値のタイプを指定します。valとval2には返却値を構成する要素が格納されます。

read_raw_multi

デバイスから値を返す関数。maskはどの値を指定します。ノート: 0は対象のチャンネルの読み取りを意味します。返却値はデバイスが返す値のタイプを指定します。valsポインタは返却値を構成する要素を含みます。max_lenはvalsポインタが含める最大要素数を指定します。val_lenはvals内の有効な要素数を返します。

read_avail

デバイスから利用可能な値を返す関数。maskはどの値を指定します。ノート: 0は対象のチャンネルの利用可能な値を意味します。返却値はvalsにIIO_AVAIL_LISTかIIO_AVAIL_RANGEが返されるかを指定します。valsのタイプはtypeに、valsの数はlengthに返却されます。範囲の場合、常にmin、step、maxの3つのvalsが返されます。リストの場合、すべての可能な値が列挙されます。

write_raw

デバイスに値を書き込む関数。パラメータはread_rawと同じです。

write_raw_get_fmt

期待される形式/精度を照会するコールバック関数。ドライバが設定しなければ、write_rawはIIO_VAL_INT_PLUS_MICROを返します。

read_event_config

イベントが有効かどうかを確認します。

write_event_config

イベントが有効かどうかを設定します。

read_event_value

イベントに関連する設定値を読み取ります。

write_event_value

イベントの設定値を書き込みます。

validate_trigger

現在のトリガーが変更されるときにトリガーを検証する関数。

update_scan_mode

チャンネルが変更されたときにデバイスとスキャンバッファを設定する関数

debugfs_reg_access

チャンネル指定子インデックスを取得する関数ポインタ。#iio-cellsが0より大きい場合、ドライバはカスタムのof_xlate関数を提供し、 args 登録済みのIIOチャンネル配列内の適切なインデックスを返します。

hwfifo_set_watermark

現在のハードウェアFIFOウォーターマークレベルを設定する関数ポインタ; ハードウェアFIFOの動作詳細についてはDocumentation/ABI/testing/sysfs-bus-iioのhwfifo_*エントリを参照してください

hwfifo_flush_to_buffer

ハードウェアFIFOに蓄積されたサンプルをデバイスバッファにフラッシュする関数ポインタ。ドライバはcountサンプル以上をフラッシュしてはなりません。関数はフラッシュされたサンプル数を返し、0はフラッシュされなかった場合、負の整数はエラーが発生した場合に返します。
