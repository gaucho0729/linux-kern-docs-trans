Intel(R) Management Engine (ME) クライアントバスAPI¶

理由¶

MEIキャラクターデバイスは、専用アプリケーションがIntelのMEに含まれる多数のFWアプライアンスとユーザースペースでデータを送受信するのに役立ちます。ただし、一部のME機能では既存のソフトウェアスタックを活用し、既存のカーネルサブシステムを通じて公開する方が適切です。

カーネルデバイスドライバモデルにシームレスに統合するため、MEIドライバ上にカーネル仮想バス抽象化を追加します。これにより、MEI機能に対するLinuxカーネルドライバを、それぞれのサブシステムに属するスタンドアロンエンティティとして実装できます。既存のデバイスドライバは、MEI CLバスレイヤーを既存のコードに追加することで再利用される可能性があります。

MEI クライアントバスAPI¶

MEIクライアントドライバの実装は、他のバスベースドデバイスドライバと非常に似ています。ドライバは、 struct mei_cl_driver structure defined in include/linux/mei_cl_bus.c

struct mei_cl_driver {
        struct device_driver driver;
        const char *name;

        const struct mei_cl_device_id *id_table;

        int (*probe)(struct mei_cl_device *dev, const struct mei_cl_id *id);
        int (*remove)(struct mei_cl_device *dev);
};

に定義された include/linux/mod_devicetable.h mei_cl_device_id構造体は、ドライバがデバイス名にバインドするのに使われます。

struct mei_cl_device_id {
        char name[MEI_CL_NAME_SIZE];
        uuid_le uuid;
        __u8    version;
        kernel_ulong_t driver_info;
};

実際にMEクライアントバスにドライバを登録するには、 mei_cl_add_driver() APIを呼び出さなければなりません。これは通常、モジュール初期化時に行われます。

ドライバが登録されデバイスにバインドされると、ドライバはこのバスでのI/Oを試みる通常です。これは mei_cl_send() および mei_cl_recv() 関数を通じて行う必要があります。詳細情報は API: セクションでより詳細に説明します。

例¶

理論的な例として、MEが「contact」NFC IPを搭載していると仮定してみましょう。このデバイスのドライバーアクセス初期化および終了ルーチンは以下のようになります:

#define CONTACT_DRIVER_NAME "contact"

static struct mei_cl_device_id contact_mei_cl_tbl[] = {
        { CONTACT_DRIVER_NAME, },

        /* required last entry */
        { }
};
MODULE_DEVICE_TABLE(mei_cl, contact_mei_cl_tbl);

static struct mei_cl_driver contact_driver = {
        .id_table = contact_mei_tbl,
        .name = CONTACT_DRIVER_NAME,

        .probe = contact_probe,
        .remove = contact_remove,
};

static int contact_init(void)
{
        int r;

        r = mei_cl_driver_register(&contact_driver);
        if (r) {
                pr_err(CONTACT_DRIVER_NAME ": driver registration failed\n");
                return r;
        }

        return 0;
}

static void __exit contact_exit(void)
{
        mei_cl_driver_unregister(&contact_driver);
}

module_init(contact_init);
module_exit(contact_exit);

そして、ドライバーの簡略化されたprobeルーチンは以下のようになります:

int contact_probe(struct mei_cl_device *dev, struct mei_cl_device_id *id)
{
        [...]
        mei_cldev_enable(dev);

        mei_cldev_register_rx_cb(dev, contact_rx_cb);

        return 0;
}

probeルーチンでは、まずドライバーがMEIデバイスを有効にして、受信ハンドラを登録します。これはスレッド化されたIRQハンドラの登録に近い処理です。ハンドラの実装では通常 mei_cldev_recv() を呼び出し、その後受信データを処理します。

#define MAX_PAYLOAD 128
#define HDR_SIZE 4
static void conntact_rx_cb(struct mei_cl_device *cldev)
{
        struct contact *c = mei_cldev_get_drvdata(cldev);
        unsigned char payload[MAX_PAYLOAD];
        ssize_t payload_sz;

        payload_sz = mei_cldev_recv(cldev, payload,  MAX_PAYLOAD)
        if (reply_size < HDR_SIZE) {
                return;
        }

        c->process_rx(payload);

}
