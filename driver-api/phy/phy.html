PHYサブシステム¶

著者

Kishon Vijay Abraham I <kishon@ti.com>

このドキュメントでは、ジェネリックPHYフレームワークと提供されるAPI、および使用方法について説明します。

はじめに¶

PHY PHYは物理層の略です。デバイスを物理媒体に接続するためのインターフェースとして使用され、たとえばUSBコントローラーはPHYを用いてシリアル化、デシリアル化、符号化、デコードなどの機能を提供し、必要なデータ伝送速度を取得します。注意点として、一部のUSBコントローラーはPHY機能を内蔵しており、他は外部PHYを使用しています。その他のPHYを使用する外設機器には無線LAN、イーサネット、SATAなどが含まれます。

このフレームワークの目的は、Linuxカーネル内に散らばっているPHYドライバをdrivers/phyに集約し、コードの再利用性を高め、保守性を改善することです。

このフレームワークは、PHY機能がコントローラー内に内蔵されていない外部PHYを使用するデバイスに対してのみ有効です。

PHYプロバイダーの登録/解除¶

PHYプロバイダーとは、1つ以上のPHYインスタンスを実装するエンティティを指します。単一のPHYインスタンスのみを実装するシンプルなケースでは、フレームワークがof_xlateの実装を提供するof_phy_simple_xlateを使用します。複数のインスタンスを実装する場合は、自前のof_xlate実装を提供する必要があります。of_xlateはdtブートケースでのみ使用されます。

#define of_phy_provider_register(dev, xlate)    \
        __of_phy_provider_register((dev), NULL, THIS_MODULE, (xlate))

#define devm_of_phy_provider_register(dev, xlate)       \
        __devm_of_phy_provider_register((dev), NULL, THIS_MODULE,
                                        (xlate))

of_phy_provider_registerとdevm_of_phy_provider_registerマクロを使用してPHYプロバイダーを登録できます。dtブートケースでは、すべてのPHYプロバイダーが上記の2つのマクロのいずれかを使用して登録する必要があります。

PHYプロバイダーに関連するデバイスツリーのノードは、通常、各PHYを表す複数の子ノードを含みます。一部のバインディングではコンテキストや拡張性を考慮して子ノードを追加のレベルにネストする場合があり、その場合はlow levelの_of_phy_provider_register_full()とdevm_of_phy_provider_register_full()マクロを使用してノードを上書きできます。

#define of_phy_provider_register_full(dev, children, xlate) \
        __of_phy_provider_register(dev, children, THIS_MODULE, xlate)

#define devm_of_phy_provider_register_full(dev, children, xlate) \
        __devm_of_phy_provider_register_full(dev, children,
                                             THIS_MODULE, xlate)

void devm_of_phy_provider_unregister(struct device *dev,
        struct phy_provider *phy_provider);
void of_phy_provider_unregister(struct phy_provider *phy_provider);

devm_of_phy_provider_unregisterとof_phy_provider_unregisterを使用してPHYをアンレジストできます。

PHYの作成¶

PHYドライバは他の外設コントローラーが利用できるようにPHYを作成する必要があります。PHYフレームワークはこれに2つのAPIを提供します。

struct phy *phy_create(struct device *dev, struct device_node *node,
                       const struct phy_ops *ops);
struct phy *devm_phy_create(struct device *dev,
                            struct device_node *node,
                            const struct phy_ops *ops);

PHYドライバは、デバイスポインタとphy_opsを渡して上記の2つのAPIのいずれかを使用してPHYを作成できます。phy_opsは初期化、終了、電源ON、電源OFFなどのPHY操作を実行するための関数ポインタのセットです。

PHYのプライベートデータ（phy_ops内）を参照するには、PHYプロバイダードライバがPHYを作成した後、phy_set_drvdata()を使用し、phy_ops内でphy_get_drvdata()を使用してプライベートデータを取得できます。

  1. PHYへの参照の取得

コントローラーがPHYを使用する前に、まずPHYへの参照を取得する必要があります。このフレームワークは、PHYへの参照を取得するための以下のAPIを提供しています。

struct phy *phy_get(struct device *dev, const char *string);
struct phy *phy_optional_get(struct device *dev, const char *string);
struct phy *devm_phy_get(struct device *dev, const char *string);
struct phy *devm_phy_optional_get(struct device *dev,
                                  const char *string);
struct phy *devm_of_phy_get_by_index(struct device *dev,
                                     struct device_node *np,
                                     int index);

phy_get、phy_optional_get、devm_phy_get、devm_phy_optional_getを使用してPHYを取得できます。dtブートの場合は、文字列引数にdtデータ内のPHY名を、非dtブートの場合はPHYのラベルを指定します。devm_phy_getは成功したPHY取得時にdevresを用いてデバイスとPHYを関連付けます。ドライバのアンロード時にdevresデータのリリース関数が呼び出され、devresデータが解放されます。PHYがオプションである場合、phy_optional_getとdevm_phy_optional_getを使用します。これらの関数はPHYが見つからない場合でも-ENODEVを返さず、NULLを返します。一部の汎用ドライバ（例：ehci）は複数のPHYを使用するため、このようなドライバでは名前による参照は意味を持ちません。その場合は、インデックスに基づいてPHY参照を取得するためのdevm_of_phy_get_by_indexを使用します。

NULLは有効なPHY参照です。すべてのPHY消費者呼び出しはNULL参照に対してNOPになります。つまり、リリース呼び出し、phy_init()とphy_exit()呼び出し、phy_power_on()とphy_power_off()呼び出しはすべてNULL参照に対してNOPになります。NULL参照はオプションのPHYデバイスを処理するデバイスで役立ちます。

PHYへの参照の解放¶

コントローラーがもはやPHYを必要としなくなった場合、上記セクションのAPIを使用して取得したPHY参照を解放する必要があります。PHYフレームワークはPHY参照を解放するための2つのAPIを提供しています。

void phy_put(struct phy *phy);
void devm_phy_put(struct device *dev, struct phy *phy);

これらのAPIはすべてPHY参照を解放するために使用され、devm_phy_putはこのPHYに関連するdevresを破壊します。

PHYの破壊¶

PHYを作成したドライバがアンロードされる際には、以下の2つのAPIのいずれかを使用して作成したPHYを破壊する必要があります。

void phy_destroy(struct phy *phy);
void devm_phy_destroy(struct device *dev, struct phy *phy);

これらのAPIはすべてPHYを破壊し、devm_phy_destroyはこのPHYに関連するdevresを破壊します。

PM Runtime¶

このサブシステムはpmランタイムが有効です。したがって、PHYを作成する際には、このサブシステムで作成されたPHYデバイスのpm_runtime_enableが呼び出され、PHYを破壊する際にはpm_runtime_disableが呼び出されます。注意点として、このサブシステムで作成されるPHYデバイスは、phy_create（PHYプロバイダーデバイス）を呼び出したデバイスの子になります。

このサブシステムによって作成されたphy_deviceのpm_runtime_get_syncは、親子関係のため、PHYプロバイダーデバイスのpm_runtime_get_syncを呼び出します。また、phy_power_onとphy_power_offはそれぞれphy_pm_runtime_get_syncとphy_pm_runtime_putを実行します。PM操作を行うためには、phy_pm_runtime_get、phy_pm_runtime_get_sync、phy_pm_runtime_put、phy_pm_runtime_put_sync、phy_pm_runtime_allow、phy_pm_runtime_forbidなどのエクスポートされたAPIが提供されています。

PHYマッピング¶

DeviceTreeの助けを借りずにPHYへの参照を取得するためには、フレームワークはclkdevに類似したlookupを提供しており、clk構造体をデバイスにバインドできます。既にstruct phyへのハンドルが存在する場合、ランタイム時にlookupを行うことができます。

フレームワークは、lookupの登録および解除に以下のAPIを提供しています:

int phy_create_lookup(struct phy *phy, const char *con_id,
                      const char *dev_id);
void phy_remove_lookup(struct phy *phy, const char *con_id,
                       const char *dev_id);
