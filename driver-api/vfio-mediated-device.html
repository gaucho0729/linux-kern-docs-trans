仮想ファンクションI/O（VFIO）中継デバイス[1]¶

DMAデバイスを仮想化するユースケースの数は増加しています。以前は、このようなデバイスを仮想化するには、開発者が独自のマネジメントインターフェースとAPIを作成し、ユーザー空間ソフトウェアと統合する必要がありました。ユーザー空間ソフトウェアとの統合を簡素化するために、私たちは共通の要件と統一されたマネジメントインターフェースを特定しました。

VFIOドライバフレームワークは、直接デバイスへのアクセスを統一したAPIで提供します。これは、セキュアでIOMMU保護された環境においてユーザー空間に直接デバイスアクセスを提供するIOMMU/デバイスに依存しないフレームワークです。このフレームワークはGPU、ネットワークアダプター、コンピュートアクセラレータなどの複数のデバイスで使用されます。直接デバイスアクセスにより、仮想マシンやユーザー空間アプリケーションが物理デバイスに直接アクセスできます。このフレームワークはmediatedデバイスにも再利用されます。

mediatedコアドライバは、さまざまなデバイスのドライバが使用できるmediatedデバイス管理の共通インターフェースを提供します。このモジュールは、以下の操作を実行するための汎用インターフェースを提供します:

  • mediatedデバイスの作成と破棄

  • mediatedバスドライバにmediatedデバイスを追加し、削除する

  • IOMMUグループにmediatedデバイスを追加し、削除する

mediatedコアドライバは、バスドライバを登録するインターフェースも提供します。例えば、mediated VFIO mdevドライバはmediatedデバイス用に設計されており、VFIO APIをサポートします。mediatedバスドライバは、VFIOグループにmediatedデバイスを追加し、削除します。

登録インターフェース¶

mediatedコアドライバは、以下の種類の登録インターフェースを提供します:

  • mediatedバスドライバの登録インターフェース

  • 物理デバイスドライバインターフェース

mediatedバスドライバの登録インターフェース¶

mediatedバスドライバの登録インターフェースは、mediatedデバイスのドライバを表す以下の構造を提供します:

/*
 * struct mdev_driver [2] - Mediated device's driver
 * @name: driver name
 * @probe: called when new device created
 * @remove: called when device removed
 * @driver: device driver structure
 */
struct mdev_driver {
        const char *name;
        int  (*probe)  (struct device *dev);
        void (*remove) (struct device *dev);
        struct device_driver    driver;
};

mdev用の中間バスドライバーは、コアドライバーに自身を登録および解除する際の関数呼び出しでこの構造体を使用する必要があります。

  • 登録:

    extern int  mdev_register_driver(struct mdev_driver *drv,
                               struct module *owner);

  • 解除:

    extern void mdev_unregister_driver(struct mdev_driver *drv);

中間バスドライバーは、デバイスがドライバーにバインドされるときに中間デバイスをVFIOグループに追加し、デバイスがドライバーからバインドされるときに中間デバイスをVFIOから削除する責任があります。

物理デバイスドライバインターフェース¶

物理デバイスドライバインターフェースは、物理デバイスに関連する作業を管理するAPIを定義するmdev_parent_ops[3]構造体を提供します。

mdev_parent_ops構造体に含まれる構造体は以下の通りです:

  • dev_attr_groups: 親デバイスの属性

  • mdev_attr_groups: 中間デバイスの属性

  • supported_config: サポートされる構成を定義する属性

mdev_parent_ops構造体に含まれる関数は以下の通りです:

  • create: 中間デバイス用にドライバーで基本リソースを割り当てる

  • remove: 中間デバイスが破棄されるときにドライバーでリソースを解放する

(注意: mdev-coreはmdev親デバイス、mdevタイプ、または他のカテゴリごとにcreate/removeコールバックの暗黙のシリアル化を提供しません。ベンダーのドライバーはこの点において完全に非同期であるか、自前のリソース保護を提供する必要があります。)

mdev_parent_ops構造体に含まれるコールバックは以下の通りです:

  • open: 中間デバイスのオープンコールバック

  • close: 中間デバイスのクローズコールバック

  • ioctl: 中間デバイスのioctlコールバック

  • read: 読み取りエミュレーションコールバック

  • write: 書き込みエミュレーションコールバック

  • mmap: mmapエミュレーションコールバック

ドライバーはmdev_coreドライバーに自身を登録する際の関数呼び出しでmdev_parent_ops構造体を使用する必要があります:

extern int  mdev_register_device(struct device *dev,
                                 const struct mdev_parent_ops *ops);

ただし、ドライバーがmdev_coreドライバーから自身を解除する際の関数呼び出しではmdev_parent_ops構造体は必要ありません:

extern void mdev_unregister_device(struct device *dev);

中継デバイス管理インターフェース（sysfs経由）¶

sysfsを通じた管理インターフェースにより、libvirtなどのユーザースペースソフトウェアはハードウェアに依存しない形で中間デバイスを照会および設定できます。この管理インターフェースは、以下の機能をサポートする物理デバイスドライバの下層に柔軟性を提供します:

  • 中間デバイスのホットプラグ

  • 単一の仮想マシン内の複数の中間デバイス

  • 異なる物理デバイスからの複数の中間デバイス

mdev_busクラスディレクトリ内のリンク¶

/sys/class/mdev_bus/ディレクトリには、mdevコアドライバーに登録されたデバイスへのリンクが含まれています。

各物理デバイスのsysfsにおけるディレクトリとファイル¶

|- [parent physical device]
|--- Vendor-specific-attributes [optional]
|--- [mdev_supported_types]
|     |--- [<type-id>]
|     |   |--- create
|     |   |--- name
|     |   |--- available_instances
|     |   |--- device_api
|     |   |--- description
|     |   |--- [devices]
|     |--- [<type-id>]
|     |   |--- create
|     |   |--- name
|     |   |--- available_instances
|     |   |--- device_api
|     |   |--- description
|     |   |--- [devices]
|     |--- [<type-id>]
|          |--- create
|          |--- name
|          |--- available_instances
|          |--- device_api
|          |--- description
|          |--- [devices]

  • [mdev_supported_types]

    現在サポートされている中間デバイスの種類とその詳細一覧。

    [<type-id>], device_api, および available_instances は、ベンダードライバーが提供すべき必須属性です。

  • [<type-id>]

    [<type-id>] の名前は、ベンダードライバーが提供する文字列にデバイスドライバ文字列をプレフィックスとして追加することで作成されます。この名前の形式は以下の通りです。

    sprintf(buf, "%s-%s", dev_driver_string(parent->dev), group->name);

    (または mdev_parent_dev(mdev) を使用してコア mdev コードの外側で親デバイスに到達する方法)

  • device_api

    この属性は、作成されているデバイスAPIを示すべきです。例えば、PCIデバイスの場合には「vfio-pci」を示します。

  • available_instances

    この属性は、<type-id> 型のデバイスが作成可能な数を示すべきです。

  • [device]

    このディレクトリには、<type-id> 型のデバイスが作成されたリンクが含まれています。

  • 名前

    この属性は人間が読める名前を示すべきです。これはオプション属性です。

  • 説明

    この属性は、種類の簡潔な特徴/説明を示すべきです。これはオプション属性です。

各 mdev デバイスの sysfs におけるディレクトリとファイル¶

|- [parent phy device]
|--- [$MDEV_UUID]
       |--- remove
       |--- mdev_type {link to its type}
       |--- vendor-specific-attributes [optional]

  • remove (読み取り専用)

'remove' ファイルに '1' を書き込むと mdev デバイスが破壊されます。ベンダードライバーがそのデバイスをアクティブにしており、ホットアンプラグをサポートしていない場合、remove() コールバックが失敗する可能性があります。

例:

# echo 1 > /sys/bus/mdev/devices/$mdev_UUID/remove

中間デバイスのホットプラグ¶

中間デバイスは実行時にも作成および割り当てが可能です。中間デバイスのホットプラグ手順は、PCIデバイスのホットプラグ手順と同様です。

中継デバイス用の翻訳API¶

VFIOドライバーでユーザー pfn をホスト pfn に変換するためのAPIは以下の通り提供されます:

extern int vfio_pin_pages(struct device *dev, unsigned long *user_pfn,
                          int npage, int prot, unsigned long *phys_pfn);

extern int vfio_unpin_pages(struct device *dev, unsigned long *user_pfn,
                            int npage);

これらの関数は、struct vfio_iommu_driver_ops[4] の pin_pages および unpin_pages コールバックを使用してバックエンド IOMMU モジュールに呼び出されます。現在、これらのコールバックは TYPE1 IOMMU モジュールでサポートされています。PPC64 sPAPR モジュールなどの他の IOMMU バックエンドモジュールでこれらを有効にするには、これらの2つのコールバック関数を提供する必要があります。

サンプルコードの使用¶

samples/vfio-mdev/ ディレクトリ内の mtty.c は、中間デバイスフレームワークの使用方法を示すサンプルドライバプログラムです。

サンプルドライバは、PCIカードを介してシリアルポートをシミュレートするmdevデバイスを作成します。

  1. mtty.ko モジュールをビルドしてロードします。

    このステップにより、ダミーデバイス /sys/devices/virtual/mtty/mtty/ が作成されます

    このデバイスディレクトリ内のsysfsのファイルは以下のようになります:

    # tree /sys/devices/virtual/mtty/mtty/
   /sys/devices/virtual/mtty/mtty/
   |-- mdev_supported_types
   |   |-- mtty-1
   |   |   |-- available_instances
   |   |   |-- create
   |   |   |-- device_api
   |   |   |-- devices
   |   |   `-- name
   |   `-- mtty-2
   |       |-- available_instances
   |       |-- create
   |       |-- device_api
   |       |-- devices
   |       `-- name
   |-- mtty_dev
   |   `-- sample_mtty_dev
   |-- power
   |   |-- autosuspend_delay_ms
   |   |-- control
   |   |-- runtime_active_time
   |   |-- runtime_status
   |   `-- runtime_suspended_time
   |-- subsystem -> ../../../../class/mtty
   `-- uevent

  2. 前のステップで作成したダミーデバイスを使用して中間デバイスを作成します:

    # echo "83b8f4f2-509f-382f-3c1e-e6bfe0fa1001" >    \
         /sys/devices/virtual/mtty/mtty/mdev_supported_types/mtty-2/create

  3. qemu-kvm にパラメータを追加します:

    -device vfio-pci,\
 sysfsdev=/sys/bus/mdev/devices/83b8f4f2-509f-382f-3c1e-e6bfe0fa1001

  4. 仮想マシンを起動します。

    ホストにハードウェアがなく、Linuxゲスト仮想マシンでは、デバイスは以下のようになります:

    # lspci -s 00:05.0 -xxvv
00:05.0 Serial controller: Device 4348:3253 (rev 10) (prog-if 02 [16550])
        Subsystem: Device 4348:3253
        Physical Slot: 5
        Control: I/O+ Mem- BusMaster- SpecCycle- MemWINV- VGASnoop- ParErr-
Stepping- SERR- FastB2B- DisINTx-
        Status: Cap- 66MHz- UDF- FastB2B- ParErr- DEVSEL=medium >TAbort-
<TAbort- <MAbort- >SERR- <PERR- INTx-
        Interrupt: pin A routed to IRQ 10
        Region 0: I/O ports at c150 [size=8]
        Region 1: I/O ports at c158 [size=8]
        Kernel driver in use: serial
00: 48 43 53 32 01 00 00 02 10 02 00 07 00 00 00 00
10: 51 c1 00 00 59 c1 00 00 00 00 00 00 00 00 00 00
20: 00 00 00 00 00 00 00 00 00 00 00 00 48 43 53 32
30: 00 00 00 00 00 00 00 00 00 00 00 00 0a 01 00 00

In the Linux guest VM, dmesg output for the device is as follows:

serial 0000:00:05.0: PCI INT A -> Link[LNKA] -> GSI 10 (level, high) -> IRQ 10
0000:00:05.0: ttyS1 at I/O 0xc150 (irq = 10) is a 16550A
0000:00:05.0: ttyS2 at I/O 0xc158 (irq = 10) is a 16550A

  5. Linuxゲスト仮想マシンでシリアルポートを確認します:

    # setserial -g /dev/ttyS*
/dev/ttyS0, UART: 16550A, Port: 0x03f8, IRQ: 4
/dev/ttyS1, UART: 16550A, Port: 0xc150, IRQ: 10

  6. minicom や任意のテルミナルエミュレータプログラムを使用して、ハードウェアフロー制御を無効にした状態で /dev/ttyS1 または /dev/ttyS2 のポートを開きます。

  7. minicom テルミナルにデータを入力するか、テルミナルエミュレータプログラムにデータを送信し、データを読み取ります。

    ホストの mtty ドライバーからデータがループバックされます。

  8. 作成した mediated device を破壊してください:

    # echo 1 > /sys/bus/mdev/devices/83b8f4f2-509f-382f-3c1e-e6bfe0fa1001/remove
