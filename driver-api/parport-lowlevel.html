parportサブシステムは parport (コアポート共有コード), および実際にポートアクセスを行うさまざまな低レベルドライバー。各低レベルドライバーは特定のポートスタイル（PC、Amigaなど）を処理します。

デバイスドライバー開発者向けのparportインターフェースは、グローバル関数とポート関数に分けることができます。

グローバル関数は、主にデバイスドライバーとparportサブシステム間での通信に使用され、利用可能なポートの一覧を取得し、ポートを排他的に使用するための取得、などを行います。また、以下のような関数も含まれます。 generic IEEE 1284準拠のアーキテクチャで動作する標準的な操作を行う関数です。

ポート関数は低レベルドライバーによって提供されますが、コアparportモジュールは一部の関数を汎用的に提供しています。 defaults 一部のルーチンについては。ポート関数は3つのグループに分類されます：SPP、EPP、ECP。

SPP（Standard Parallel Port）関数は、いわゆる SPP レジスタ：データ、ステータス、コントロール。ハードウェアには実際にこのようなレジスタが存在しない可能性がありますが、PCには存在し、このインターフェースは一般的なPC実装に基づいています。他の低レベルドライバーは、ほとんどの機能をエミュレートできるかもしれません。

IEEE 1284 EPPモードでの読み書きにはEPP（Enhanced Parallel Port）機能が提供され、ECP（Extended Capabilities Port）機能はIEEE 1284 ECPモードで使用されます。(BECPについてはどうですか？誰が気にするのでしょうか？)

EPPおよび/またはECP転送のハードウェア支援は利用可能かもしれませんが、利用されない場合もあります。ハードウェアが使われない場合は、ソフトウェアで駆動されます。IEEE 1284を僅かにサポートする外付け機器に対応するため、'fudge factors'を調整する低レベルドライバ専用の関数が提供されています。

グローバル関数¶

parport_register_driver - parportにデバイスドライバを登録する¶

SYNOPSIS¶

#include <linux/parport.h>

struct parport_driver {
        const char *name;
        void (*attach) (struct parport *);
        void (*detach) (struct parport *);
        struct parport_driver *next;
};
int parport_register_driver (struct parport_driver *driver);

DESCRIPTION¶

パラレルポートが検出されたときに通知を受けたい場合は、parport_register_driverを呼び出す必要があります。ドライバは即座にすでに検出されたすべてのポートと、低レベルドライバがロードされるたびに新しいポートについて通知されます。

A struct parport_driver ドライバのテキスト名を含み、新しいポートを処理する関数ポインタと、低レベルドライバのアンロードによりポートがなくなった場合の処理を行う関数ポインタを持ちます。ポートは使用されていない場合（つまり、そのポートにデバイスが登録されていない場合）のみ切断されます。

の可視部分 struct parport * attatch/detachに渡される引数は以下の通りです:

struct parport
{
        struct parport *next; /* next parport in list */
        const char *name;     /* port's name */
        unsigned int modes;   /* bitfield of hardware modes */
        struct parport_device_info probe_info;
                        /* IEEE1284 info */
        int number;           /* parport index */
        struct parport_operations *ops;
        ...
};

構造体には他のメンバも存在しますが、それらは触ってはいけません。

以下の modes メンバは基盤となるハードウェアの機能を要約しており、フラグをビットごとにORで組み合わせたものです:

PARPORT_MODE_PCSPP

IBM PCレジスタが利用可能で、データ、コントロール、ステータスレジスタに作用する関数はハードウェアに直接書き込む可能性があります。

PARPORT_MODE_TRISTATE

データドライバがオフにされ、データラインが逆方向（外付け機器からホストへの転送）で使用されることが可能になります。

PARPORT_MODE_COMPAT

ハードウェアが互換モード（プリンタ）転送をサポートしており、compat_write_blockが利用可能です。

PARPORT_MODE_EPP

ハードウェアがEPP転送をサポートしています。

PARPORT_MODE_ECP

ハードウェアがECP転送をサポートしています。

PARPORT_MODE_DMA

ハードウェアがDMAをサポートしており、ISA DMA可能メモリ（kmallocでGFP_DMAフラグを使用して割り当てたメモリ）を低レベルドライバに渡すことでDMAを活用できるかもしれません。

の他にもフラグが存在する可能性があります modes 同様に適用されます。

の内容は modes アドバイザリです。たとえば、ハードウェアがDMAをサポートしていて、PARPORT_MODE_DMAが modesに含まれている場合でも、DMAが常に利用されるとは限りません。同様に、ECP転送をサポートするハードウェアでも必ず使用されるとは限りません。

戻り値¶

成功時はゼロ、エラーの場合はエラーコード。

エラー¶

なし。(失敗する可能性がある？なぜintを返すのか？)

例¶

static void lp_attach (struct parport *port)
{
        ...
        private = kmalloc (...);
        dev[count++] = parport_register_device (...);
        ...
}

static void lp_detach (struct parport *port)
{
        ...
}

static struct parport_driver lp_driver = {
        "lp",
        lp_attach,
        lp_detach,
        NULL /* always put NULL here */
};

int lp_init (void)
{
        ...
        if (parport_register_driver (&lp_driver)) {
                /* Failed; nothing we can do. */
                return -EIO;
        }
        ...
}

parport_unregister_driver - parportにこのドライバを忘れさせる¶

SYNOPSIS¶

#include <linux/parport.h>

struct parport_driver {
        const char *name;
        void (*attach) (struct parport *);
        void (*detach) (struct parport *);
        struct parport_driver *next;
};
void parport_unregister_driver (struct parport_driver *driver);

DESCRIPTION¶

このコマンドは、parportに新しいポートやポートが消失したことをデバイスドライバに通知しないようにします。そのドライバに属する登録済みデバイスはアンレジストされません。各デバイスに対してparport_unregister_deviceを使用する必要があります。

例¶

void cleanup_module (void)
{
        ...
        /* Stop notifications. */
        parport_unregister_driver (&lp_driver);

        /* Unregister devices. */
        for (i = 0; i < NUM_DEVS; i++)
                parport_unregister_device (dev[i]);
        ...
}

parport_enumerate - 平行ポートの一覧を取得する(DEPRECATED)¶

SYNOPSIS¶

#include <linux/parport.h>

このマシンの有効な平行ポートの一覧から最初のポートを取得します。次の平行ポートは、 struct parport *next の要素 struct parport * が返されます。もし next がNULLの場合、リストにはさらに平行ポートがありません。リスト内のポート数はPARPORT_MAXを超えないです。

戻り値¶

A struct parport * マシンの有効な平行ポートを記述する、または存在しない場合はNULLです。

エラー¶

この関数は、使用可能な平行ポートがないことを示すためにNULLを返すことができます。

例¶

int detect_device (void)
{
        struct parport *port;

        for (port = parport_enumerate ();
        port != NULL;
        port = port->next) {
                /* Try to detect a device on the port... */
                ...
        }
        }

        ...
}

ノート¶

parport_enumerateは非推奨となりました。代わりにparport_register_driverを使用してください。

parport_register_device - ポートを使用するように登録する¶

SYNOPSIS¶

#include <linux/parport.h>

typedef int (*preempt_func) (void *handle);
typedef void (*wakeup_func) (void *handle);
typedef int (*irq_func) (int irq, void *handle, struct pt_regs *);

struct pardevice *parport_register_device(struct parport *port,
                                          const char *name,
                                          preempt_func preempt,
                                          wakeup_func wakeup,
                                          irq_func irq,
                                          int flags,
                                          void *handle);

DESCRIPTION¶

この関数を使用して、平行ポートにデバイスドライバを登録します(port)

の(name) 引数は/procファイルシステムに表示されるデバイスの名前です。この文字列は、デバイスの寿命全体（parport_unregister_deviceが呼ばれるまで）有効でなければなりません。

この関数は、あなたのドライバに3つのコールバックを登録します： preempt, wakeup および irq. これらはすべてNULLに設定して、コールバックを望まないことを示すことができます。

When the preempt 関数が呼ばれるのは、他のドライバが平行ポートを使用したいからです。 preempt 平行ポートがまだ解放できない場合、関数はゼロ以外の値を返す必要があります。ゼロを返すと、ポートは他のドライバに奪われ、使用前に再取得する必要があります。

以下の wakeup 関数は、他のドライバがポートを解放した後で、他のドライバがまだ取得していないときに呼ばれます。この関数内で平行ポートを取得できます（その場合、取得は確実に成功します） wakeup 、または必要なければ選ばないことができます。

ドライバが取得した平行ポートで割込みが発生した場合、 irq 関数が呼ばれます。(共有割込みについて何か書くべきです。)

以下の handle はドライバ固有のデータへのポインタであり、コールバック関数に渡されます。

flags は次のフラグのビットごとの組み合わせであるかもしれません：

フラグ

意味

PARPORT_DEV_EXCL

デバイスはまったく並列ポートを共有できません。絶対に必要のない限り使用しないでください。

typedefは実際に定義されていません。関数プロトタイプを読みやすくするためだけに表示されています。

返されたデバイスの可視部分 struct pardevice は:

struct pardevice {
        struct parport *port;   /* Associated port */
        void *private;          /* Device driver's 'handle' */
        ...
};

戻り値¶

A struct pardevice *: 一時的に登録された並列ポートデバイスへのハンドルで、parport_claim、parport_releaseなどに使用できます。

エラー¶

NULLが返される場合、そのポートにデバイスを登録する際に問題が発生しました。

例¶

static int preempt (void *handle)
{
        if (busy_right_now)
                return 1;

        must_reclaim_port = 1;
        return 0;
}

static void wakeup (void *handle)
{
        struct toaster *private = handle;
        struct pardevice *dev = private->dev;
        if (!dev) return; /* avoid races */

        if (want_port)
                parport_claim (dev);
}

static int toaster_detect (struct toaster *private, struct parport *port)
{
        private->dev = parport_register_device (port, "toaster", preempt,
                                                wakeup, NULL, 0,
                                                private);
        if (!private->dev)
                /* Couldn't register with parport. */
                return -EIO;

        must_reclaim_port = 0;
        busy_right_now = 1;
        parport_claim_or_block (private->dev);
        ...
        /* Don't need the port while the toaster warms up. */
        busy_right_now = 0;
        ...
        busy_right_now = 1;
        if (must_reclaim_port) {
                parport_claim_or_block (private->dev);
                must_reclaim_port = 0;
        }
        ...
}

parport_claim, parport_claim_or_block - デバイスのために並列ポートを占有する¶

SYNOPSIS¶

#include <linux/parport.h>

int parport_claim (struct pardevice *dev);
int parport_claim_or_block (struct pardevice *dev);

DESCRIPTION¶

これらの関数は、 dev 登録されています parport_claim ブロックしませんが、 parport_claim_or_block ブロックする場合があります。（ブロック可能か、中断可能かを説明してください。）

すでに占有しているポートを再び占有しようとしないでください。

戻り値¶

返値がゼロの場合、ポートが成功裏に占有され、呼び出し元が並列ポートの占有権を持ちます。

もし parport_claim_or_block 成功して返す前にブロックする場合、返値は正数になります。

エラー¶

-EAGAIN

ポートが一時的に利用不可ですが、再度占有する試みは成功する可能性があります。

parport_find_class - クラスでデバイスを検索します¶

SYNOPSIS¶

#include <linux/parport.h>

typedef enum {
        PARPORT_CLASS_LEGACY = 0,       /* Non-IEEE1284 device */
        PARPORT_CLASS_PRINTER,
        PARPORT_CLASS_MODEM,
        PARPORT_CLASS_NET,
        PARPORT_CLASS_HDC,              /* Hard disk controller */
        PARPORT_CLASS_PCMCIA,
        PARPORT_CLASS_MEDIA,            /* Multimedia device */
        PARPORT_CLASS_FDC,              /* Floppy disk controller */
        PARPORT_CLASS_PORTS,
        PARPORT_CLASS_SCANNER,
        PARPORT_CLASS_DIGCAM,
        PARPORT_CLASS_OTHER,            /* Anything else */
        PARPORT_CLASS_UNSPEC,           /* No CLS field in ID */

parport_set_timeout - 不活性タイムアウトを設定する¶

SYNOPSIS¶

#include <linux/parport.h>

long parport_set_timeout (struct pardevice *dev, long inactivity);

DESCRIPTION¶

登録されたデバイスの不活性タイムアウト（ジーフィーズ単位）を設定します。以前のタイムアウト値が返されます。

戻り値¶

以前のタイムアウト値（ジーフィーズ単位）。

ノート¶

ポート->ops関数の一部は、外設機の遅延により時間がかかることがあります。外設機が応答しなくなった場合、ジーフィーズ経過後にタイムアウトが発生し、ブロッキング関数が返ります。 inactivity ジーフィーズ経過後にタイムアウトが発生し、ブロッキング関数が返ります。

0ジーフィーズのタイムアウトは特別なケースです。関数はブロッキングせずにできるだけ処理を行い、ハードウェアを未知の状態にしない必要があります。たとえば、割込みハンドラ内でポート操作を行う場合、0ジーフィーズのタイムアウトを使用すべきです。

登録されたデバイスに対して設定されたタイムアウトは、再度設定するまでその値のままです。
