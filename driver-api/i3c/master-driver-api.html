void i3c_bus_maintenance_lock(struct i3c_bus *bus)¶

バスのメンテナンス操作のためにバスをロックします

パラメータ

struct i3c_bus *bus

ロックを取得するI3Cバス

説明

この関数はバスロックを取得し、バス上で他の操作が行われないようにします。これは、スレーブイベントの有効/無効化、DAAの再実行、デバイスの動的アドレス変更、マスターシップの放棄など、すべての種類のバスメンテナンス操作に必要です。

このようなロックの目的は、ドライバーやコアロジックがI3Cデバイス情報に依存するのを防ぐためです。その情報が裏で変更される可能性があるからです。

void i3c_bus_normaluse_lock(struct i3c_bus *bus)¶

通常の操作のためにバスをロックします

パラメータ

struct i3c_bus *bus

ロックを取得するI3Cバス

説明

これはメンテナンス操作ではないすべての操作に使用されます（メンテナンス操作の一例は i3c_bus_maintenance_lock() をご参照ください）。基本的にすべてのI3Cデバイスとの通信は通常の操作です（HDR、SDR転送、またはバス状態やI3C動的アドレスを変更しないCCCコマンド）。

このロックは通常の操作のシリアル化を保証しません。つまり、I3Cマスターに渡された転送要求は並列に送信され得、I3Cマスタードライバーは自身でロックを使用して、異なる通信が混在しないように、またはエンジンがビジーなときに出力/入力キューへのアクセスを行わないようにしなければなりません。

int i3c_master_bus_init(struct i3c_master_controller *マスター)¶

I3Cバスの初期化

パラメータ

struct i3c_master_controller *master

バスを初期化しているメインマスタ

説明

この関数は、I3C仕様で記述されているすべての初期化ステップを実行します：

  1. I2Cデバイスをマスタにアタッチし、マスタが内部デバイステーブルを適切に埋めるようにします

  2. を呼び出して、MMIOまたはIOポート範囲を利用可能にします。これを実施しないと、ドライバの再ロードができない状態になります。 i3c_master_controller_ops->bus_init() マスターファームウェアの初期化メソッド。通常はバスモード（純粋バスまたは混合高速/低速バス）が選択される場所です

  3. バス上のすべてのデバイスにダイナミックアドレスをリセットします。これは、バスが以前に他のユーザー（たとえばブートローダー）によって設定されていた場合に特に重要です

  4. すべてのスレーブイベントを無効にします。

  5. init_dyn_addrでI3Cデバイスのアドレススロットを予約します。また、デバイスがstatic_addrを持つ場合、FWがリクエストしたダイナミックアドレスをSETDASAで事前に割り当てて、対応する静的に定義されたI3Cデバイスをマスタにアタッチします。

  6. 残りのすべてのI3Cデバイスに動的アドレスを割り当てるため、DAA（Dynamic Address Assignment）を行います

この操作が完了すると、すべてのI3CおよびI2Cデバイスが使用可能になります

戻り値

成功した場合は0、エラーの場合は負のエラーコードを返します。

enum i3c_bus_mode¶

定数

I3C_BUS_MODE_PURE

struct i3c_bus {
  struct i3c_dev_desc *cur_master;

メンバ

cur_master

現在バスを制御しているI3Cマスターデバイス。I3Cはマルチマスターバスであるため、時間とともに変化する可能性があります。マスターデバイスがフレームを送信する前にバス所有権を要求する必要があるかどうかを通知するために使用されます

id

バスID。フレームワークがバスを登録する際に割り当てられます

addrslots

スロットごとに2ビットのビットマップでアドレス状態をエンコードし、DAA（動的アドレス割り当て）手続きを容易にするためのアドレス状態マスク（参照 enum i3c_addr_slot_status)

mode

バスモード（参照 enum i3c_bus_mode)

scl_rate

I3CモードおよびI2CモードにおけるSCL信号の周波数

scl_rate.i3c

I3C SDR/プライベート転送時のクロック信号の最大周波数

scl_rate.i2c

I2C転送時のクロック信号の最大レート

devs

バスに接続されているすべてのI3C/I2Cデバイスを含む2つのリスト

devs.i3c

バスに接続されI3Cマスタに成功裏に接続されたI3Cデバイスを表すデバイス記述子のリスト

devs.i2c

バスに接続されI3Cマスタに成功裏に接続されたI2Cデバイスを表すデバイス記述子のリスト

lock

バスの読み取り/書き込みロック。このロックは、バス全体および接続デバイスに影響を与える操作を保護するために必要です。たとえば、スレーブに動的アドレスを解除（RSTDAA CCC）を要求する際には、これらのデバイスにI3Cフレームを送信しようとする他の操作が行われないことを保証する必要があります。注意点として、このロックはデバイス間の並行性を保護するものではありません。複数のドライバが同じマスタを通じて異なるI3C/I2Cフレームを並行して送信できる場合があります。フレームが実際に順番に送信され、交差しないことを保証するのはマスタの責任です

説明

I3Cバスは、I3Cマスタを通じて暗黙的に記述されるのではなく、マルチマスタ機能に対応するため独自のオブジェクトで表現されます。これにより、複数のマスタが1つのバスを共有できるようになります。各マスタは必要に応じてバスの所有権を要求します

メンバ

bus_init

I3Cバスの初期化を担当するハンドラ。少なくともmaster_set_info()を呼び出しバスモードを設定する必要があります。コントローラー固有の初期化もここに記述できます。このメソッドは必須です

bus_cleanup

を実行したすべての処理をクリーンアップします i3c_master_controller_ops->bus_init()。このメソッドはオプションです

attach_i3c_dev

I3Cデバイスがバスに接続されたたびに呼び出されます。これはDAAの後や、ファームウェアで静的に宣言されたデバイスの場合（その場合は静的アドレスのみを持ち動的アドレスは0）にも発生します。この関数が呼び出される際、デバイス情報はまだ取得されていません。これはI3Cデバイスにマスターマネージャー固有のデータをアタッチするのに適した場所です。このメソッドはオプションです

reattach_i3c_dev

I3Cデバイスのアドレスが変更されたたびに呼び出されます。これはデバイスが電源を切ってアドレスを失った場合、または静的アドレスを持つデバイスがSETDASAで動的アドレスが割り当てられた場合にも発生します。このメソッドはオプションです

detach_i3c_dev

I3Cデバイスがバスから切断されたときに呼び出されます。通常はマスターデバイスが登録解除されたときに発生します。このメソッドはオプションです

do_daa

DAA（動的アドレス割り当て）手順を行います。この手順ではENTDAA CCCコマンドを送信し、DAAで発見したすべてのデバイスを追加します i3c_master_add_i3c_dev_locked()を追加します i3c_master_add_i3c_dev_locked() 次にコントローラーに接続または再接続されます。このメソッドは必須です。

supports_ccc_cmd

CCCコマンドがサポートされている場合trueを返す必要があります。それ以外はfalseを返します。このメソッドは任意ですが、提供されない場合コアはすべてのCCCコマンドをサポートしていると仮定します。

send_ccc_cmd

CCCコマンドを送信します。このメソッドは必須です。

priv_xfers

1つまたは複数のプライベートI3C SDR転送を行います。このメソッドは必須です。

attach_i2c_dev

I2Cデバイスがバスに接続されるたびに呼び出されます。これはI2Cデバイスにマスターコントローラー固有のデータを接続するのに適した場所です。このメソッドは任意です。

detach_i2c_dev

I2Cデバイスがバスから分離されるときに呼び出されます。通常はマスターデバイスが登録解除されるときに発生します。このメソッドは任意です。

i2c_xfers

1つまたは複数のI2C転送を行います。注意点として、i3c転送とは異なり、コアは転送に添付されたバッファがDMA安全であることを保証しません。ドライバがDMA安全なバッファを使用したい場合は、 i2c_get_dma_safe_msg_buf() および i2c_put_dma_safe_msg_buf() I2Cフレームワークが提供するヘルパを使用すべきです。このメソッドは必須です。

request_ibi

I3CデバイスにIBIハンドラをアタッチします。これはIBIハンドラの定義とIBI（最大ペイロード長および予約されたスロット数）の制約を定義することを意味します。一部のコントローラーは通常のデバイスよりも少ないIBI対応デバイスをサポートするため、このメソッドは-EBUSY 追加のIBI登録にスペースがなくなった場合に呼び出されます。このメソッドは任意です。

free_ibi

以前に->request_ibi()でリクエストしたIBIを解放します。IBIは->disable_irq() 呼び出す前に無効化されていなければなりません。このメソッドは->request_ibiがNULLでない場合にのみ必須です。

enable_ibi

IBIを有効化します。->request_ibi()が呼び出された後に->enable_ibi()が呼び出される場合にのみ有効です。コントローラーはまずコントローラー側でIBIを有効化する必要があります（例：ハードウェアIRQをアンマスク）その後、IBIフラグを設定したENEC CCCコマンドをI3Cデバイスに送信します。このメソッドは->request_ibiがNULLでない場合にのみ必須です。

disable_ibi

IBIを無効化します。まずIBIフラグを設定したDISEC CCCコマンドを送信し、その後コントローラー側でハードウェアIRQを無効化します。このメソッドは->request_ibiがNULLでない場合にのみ必須です。

recycle_ibi_slot

IBIスロットを再利用します。IBIハンドラによってIBIが処理されるたびに呼び出されます。IBIスロットはIBIスロットプールに戻して、コントローラーが今後のIBIのために再利用できるようにします。このメソッドは->request_ibiがNULLでない場合にのみ必須です。
