NTB ドライバ¶

NTB（Non-Transparent Bridge）は、2台以上のコンピュータの別個のメモリシステムを同じPCI-Expressファブリックに接続するPCI-Expressブリッジチップの一種です。既存のNTBハードウェアは、ドアベルレジスタやメモリ翻訳ウインドウといった共通機能をサポートしており、スクラッチパッドやメッセージレジスタといった非共通機能もサポートしています。スクラッチパッドレジスタは、デバイスの両側からアクセス可能な読み書き可能なレジスタで、ペアが固定アドレスで少量の情報を交換できるようにします。メッセージレジスタも同様の目的で利用可能です。さらに、情報が他のペアによって上書きされないことを保証する特別なステータスビットが提供されています。ドアベルレジスタは、ペアが割り込みイベントを送信する方法を提供します。メモリウインドウは、ペアメモリへの翻訳された読み書きアクセスを可能にします。

NTB コアドライバ (ntb)¶

NTBコアドライバは、共通機能をラッピングしたAPIを定義しており、NTB機能に興味のあるクライアントがハードウェアドライバでサポートされるNTBデバイスを発見できるようにします。ここでの「クライアント」とは、NTB APIを使用する上位レイヤーのコンポーネントを指します。「ドライバ」または「ハードウェアドライバ」という用語は、特定のベンダーおよびモデルのNTBハードウェア用のドライバを指します。

NTB クライアントドライバ¶

NTBクライアントドライバはNTBコアドライバに登録する必要があります。登録後、NTBハードウェアまたはハードウェアドライバが挿入・除去されるたびに、クライアントのプローブおよびリムーブ関数が適切に呼び出されます。登録はLinuxデバイスフレームワークを使用するため、PCIドライバを書いたことのある人には馴染みやすいでしょう。

NTBクライアントドライバの典型的な実装¶

NTBの主な目的は、少なくとも2つのシステム間で一部のメモリを共有することです。そのため、スクラッチパッド/メッセージレジスタなどのNTBデバイス機能は、適切なメモリウインドウ初期化に主に使用されます。通常、NTB APIは2種類のメモリウインドウインターフェースをサポートしています：ローカルNTBポートで設定されるインバウンド翻訳と、ペアのNTBポートでペアが設定するアウトバウンド翻訳。最初のタイプは次の図に示されています。

Inbound translation:

Memory:              Local NTB Port:      Peer NTB Port:      Peer MMIO:
 ____________
| dma-mapped |-ntb_mw_set_trans(addr)  |
| memory     |        _v____________   |   ______________
| (addr)     |<======| MW xlat addr |<====| MW base addr |<== memory-mapped IO
|------------|       |--------------|  |  |--------------|

最初のタイプのメモリウインドウ初期化の典型的なシナリオは以下の通りです：1) メモリ領域を割り当てる、2) 翻訳されたアドレスをNTB設定に設定する、3) 何か手段でペアーデバイスに初期化が行われたことを通知する、4) ペアーデバイスが対応するアウトバウンドメモリウインドウをマッピングして共有メモリ領域にアクセスできるようにする。

2番目のインターフェースタイプは、共有ウィンドウがピアデバイスによって初期化される場合を示しており、図に描かれています:

Outbound translation:

Memory:        Local NTB Port:    Peer NTB Port:      Peer MMIO:
 ____________                      ______________
| dma-mapped |                |   | MW base addr |<== memory-mapped IO
| memory     |                |   |--------------|
| (addr)     |<===================| MW xlat addr |<-ntb_peer_mw_set_trans(addr)
|------------|                |   |--------------|

2番目のインターフェースタイプの初期化の典型的なシナリオは、1) メモリ領域を割り当て、2) そのアドレスをピアデバイスに転送、3) ピアデバイスがそのアドレスをNTB設定に設定、4) ピアデバイスが送出用メモリウィンドウをマッピングして共有メモリ領域にアクセス可能にするというものです。

説明されたシナリオは、1つのポータブルアルゴリズムとして組み合わせることができます。

ローカルデバイス:

  1. 共有ウィンドウ用のメモリを割り当てる

  2. 割り当てた領域の変換アドレスでメモリウィンドウを初期化（ローカルメモリウィンドウ初期化がサポートされていない場合、失敗する可能性あり）

  3. 変換アドレスとメモリウィンドウインデックスをピアデバイスに送信

ピアデバイス:

  1. 他のデバイスによって割り当てられたメモリ領域の取得アドレスでメモリウィンドウを初期化（ピアメモリウィンドウ初期化がサポートされていない場合、失敗する可能性あり）

  2. 送出用メモリウィンドウをマッピング

このシナリオに従って、NTBメモリウィンドウAPIは以下のように使用できます:

ローカルデバイス:

  1. ntb_mw_count(pidx) - 指定されたポートインデックスのローカルデバイスとピアデバイス間で割り当て可能なメモリ範囲の数を取得

  2. ntb_get_align(pidx, midx) - 共有メモリ領域のアライメントとサイズに制限を取得（これによりメモリを適切に割り当てられます）

  3. 2)で取得した制限に従って物理的に連続したメモリ領域を割り当てる

  4. ntb_mw_set_trans(pidx, midx) - 指定されたインデックスのメモリウィンドウの変換アドレスをピアデバイスに設定を試みる（ローカル変換アドレス設定がサポートされていない場合、失敗する可能性あり）

  5. scratchpadやメッセージレジスタなどを使って、変換ベースアドレス（通常はメモリウィンドウ番号とともに）をピアデバイスに送信

ピアデバイス:

  1. ntb_peer_mw_set_trans(pidx, midx) - 他のデバイス（pidxに関連）から取得した変換アドレスを指定されたメモリウィンドウに設定を試みる（取得アドレスが最大可能アドレスを超えるか、適切にアライメントされていない場合など、失敗する可能性あり）

  2. ntb_peer_mw_get_addr(widx) - 共有メモリにアクセスするためのメモリウィンドウのMMIOアドレスを取得

また、ntb_mw_count(pidx)は、ポートインデックス-pidxのピアデバイスのntb_peer_mw_count()と同様の値を返す必要があります。

NTBトランスポートクライアント（ntb_transport）とNTBネットデバイス（ntb_netdev）¶

NTBの主なクライアントはTransportクライアントで、NTB Netdevと併用されます。これらのドライバーは協働して、ntbを介してペアに論理的なリンクを確立し、ネットワークデータのパケットを交換する論理的なリンクを構築します。Transportクライアントはペアに論理的なリンクを確立し、メッセージやデータの交換に使用するキュー・ペアを生成します。NTB Netdevは、Transportキュー・ペアを使用してイーサネットデバイスを生成します。ネットワークデータはソケットバッファとTransportキュー・ペアバッファの間でコピーされます。TransportクライアントはNetdev以外にも用途があるかもしれませんが、現在は他のアプリケーションがまだ開発されていません。

NTB Ping Pongテストクライアント (ntb_pingpong)¶

Ping Pongテストクライアントは、NTBハードウェアのドアベルおよびスクラッチパッドレジスタを動作確認するデモンストレーションとして、またシンプルなNTBクライアントの例として機能します。Ping Pongは起動時にリンクを確立し、NTBリンクが起動するのを待つ後、NTBのドアベルスクラッチパッドレジスタの読み書きを行います。ペア同士はドアベルビットのビットマスクを使用して相互に割り込みを行い、各ラウンドごとにビットマスクを1シフトすることで、複数のドアベルビットと割り込みベクタの動作をテストします。Ping Pongドライバーはまた、最初のローカルスクラッチパッドを読み取り、各ラウンドでその値に1を加えたものを最初のペアスクラッチパッドに書き込み、その後ペアドアベルレジスタに書き込みます。

モジュールパラメータ:

  • unsafe - 一部のハードウェアではスクラッチパッドおよびドアベルレジスタに既知の問題があります。

    デフォルトではPing Pongはこのようなハードウェアを動作確認しようとしません。リスクを理解した上で、unsafe=1を設定することでこの動作を上書きできます。

  • delay_ms - ドアベル割り込みイベントの受信と次のラウンドのペアドアベルレジスタの設定の間の遅延を指定します。

    割り込みイベントと次のラウンドのペアドアベルレジスタの設定の間の遅延を指定します。

  • init_db - 新しいラウンドの開始に使用するドアベルビットを指定します。新しい

    ドアベルビットが範囲外にシフトされた後、シリーズが開始されます。

  • dyndbg - このモジュールをロードする際にはdyndbg=+pを指定することを推奨し、

    コンソールでデバッグ出力を確認してください。

NTB Tool Test Client (ntb_tool)¶

このツールは主にNTBハードウェアおよびドライバのデバッグに使用され、debugfsを通じてNTBドアベルの読み取り、設定、クリア、およびスクラッチパッドの読み書きにアクセスを提供します。

現在、このモジュールにはパラメータがありません。

デバッグファイル:

  • debugfs/ntb_tool/hw/

    ツールで検出された各NTBデバイスごとにdebugfsにディレクトリが作成され、このディレクトリは hw も参照してください。

  • hw/db

    このファイルは、ローカルドアベルを読み込み、設定、クリアするためのものです。すべての操作がすべてのハードウェアでサポートされるとは限りません。ドアベルを読み込むには、ファイルを読み込みます。ドアベルを設定するには、書き込み s 設定するビットを記述した後ろに続きます（例: echo ‘s 0x0101’ > db)。ドアベルをクリアするには、書き込み c クリアするビットを記述した後ろに続きます。

  • hw/mask

    このファイルは、ローカルドアベルマスクを読み込み、設定、クリアするためのものです。参照 db 詳しくは以下をご参照ください。

  • hw/peer_db

    このファイルは、ピアドアベルを読み込み、設定、クリアするためのものです。参照 db 詳しくは以下をご参照ください。

  • hw/peer_mask

    このファイルは、ピアドアベルマスクを読み込み、設定、クリアするためのものです。参照 db 詳しくは以下をご参照ください。

  • hw/spad

    このファイルは、ローカルスクラッチパッドを読み込み、書き込みます。すべてのスクラッチパッドの値を読み込むには、ファイルを読み込みます。値を書き込むには、スクラッチパッド番号と値のペアを連続して記述します（例: echo ‘4 0x123 7 0xabc’ > spad # スクラッチパッドを設定するには 4 および 7 に（木の下から葉に向かって） 0x123 および 0xabcそれぞれに対応します。

  • hw/peer_spad

    このファイルは、ピアスクラッチパッドを読み込み、書き込みます。参照 spad 詳しくは以下をご参照ください。

NTB MSIテストクライアント（ntb_msi_test）¶

MSIテストクライアントは、NTBメモリウィンドウを介してMSI割り込みを送信する機能を提供するMSIライブラリのテストとデバッグに使用されます。テストクライアントはdebugfsファイルシステムを通じて操作されます:

  • debugfs/ntb_tool/hw/

    ツールで検出された各NTBデバイスごとにdebugfsにディレクトリが作成され、このディレクトリは hw も参照してください。

  • hw/port

    このファイルは、ローカルポート番号を記述します

  • hw/irq*_occurrences

    各割り込みに対して1つのoccurrencesファイルが存在し、読み込まれるとその割り込みがトリガーされた回数が返されます。

  • hw/peer*/port

    このファイルは、各ピアのポート番号を記述します

  • hw/peer*/count

    このファイルは、各ピアでトリガー可能な割り込みの数を記述します

  • hw/peer*/trigger

    割り込み番号（countで指定された値以下の任意の数）を書き込むと、指定されたピアで割り込みがトリガーされます。そのピアの割り込みのoccurrencesファイルはインクリメントされるべきです。

NTB ハードウェアドライバ¶

NTBハードウェアドライバーは、NTBコアドライバーにデバイスを登録する必要があります。登録後、クライアントのプローブおよびリモート解除関数が呼び出されます。

NTBインテルハードウェアドライバー（ntb_hw_intel）¶

インテルハードウェアドライバーは、XeonおよびAtom CPUでのNTBをサポートします。

モジュールパラメータ:

  • b2b_mw_idx

    ピアNTBをメモリウィンドウを介してアクセスする場合、このメモリウィンドウを使用してピアNTBにアクセスします。値がゼロまたは正数の場合は、最初のmw idxから開始し、負数の場合は最後のmw idxから開始します。両側はここに同じ値を設定しなければなりません！デフォルト値は -1.

  • b2b_mw_share

    ピアNTBをメモリウィンドウを介してアクセスし、メモリウィンドウが十分大きい場合でも、クライアントがメモリウィンドウの後半をピアへのアドレス変換に使用できるようにします。

  • xeon_b2b_usd_bar2_addr64

    XeonハードウェアでB2Bトポロジーを使用する場合、リンクの上流側にあるBAR2のウィンドウに、NTBデバイス間のバス上にこの64ビットアドレスを使用してください。

  • xeon_b2b_usd_bar4_addr64 - 参照 xeon_b2b_bar2_addr64.

  • xeon_b2b_usd_bar5_addr32 - 参照 xeon_b2b_bar2_addr64.

  • xeon_b2b_usd_bar5_addr32 - 参照 xeon_b2b_bar2_addr64.

  • xeon_b2b_dsd_bar2_addr64 - 参照 xeon_b2b_bar2_addr64.

  • xeon_b2b_dsd_bar4_addr64 - 参照 xeon_b2b_bar2_addr64.

  • xeon_b2b_dsd_bar4_addr32 - 参照 xeon_b2b_bar2_addr64.

  • xeon_b2b_dsd_bar5_addr32 - 参照 xeon_b2b_bar2_addr64.
