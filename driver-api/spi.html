シリアルペリフェラルインターフェース（SPI）¶

SPIは「シリアルペリフェラルインターフェース」と呼ばれ、埋め込みシステムで広く使用されるシンプルで効率的なインターフェースです。基本的にはマルチプレクサードシフターレジスタで構成されており、3本の信号線が時計（SCK、通常1〜20 MHzの範囲）、"マスター出力、スレーブ入力"（MOSI）データライン、"マスター入力、スレーブ出力"（MISO）データラインを保持します。SPIはフルダイクスプロトコルであり、MOSIラインに1ビットずつシフトするたびに、MISOラインで対応するビットがシフトされます。これらのビットはシステムメモリとのやり取り中にさまざまなサイズのワードに組み立てられます。追加のチップセレクトラインは通常アクティブロー（nCS）で、各ペリフェラルには通常4つの信号が使用され、場合によっては割り込み信号も含まれます。

ここに記載されているSPIバスの機能は、SPIバスとデバイスを宣言し、標準的なLinuxドライバーモデルに従って管理し、入出力操作を実行する汎用インターフェースを提供します。現在は、LinuxがSPIペリフェラルと通信し、自身でそのようなペリフェラルを実装しない"マスター側"インターフェースのみがサポートされています。（SPIスレーブを実装するインターフェースは必然的に異なる構造になります。）

プログラミングインターフェースは、2種類のドライバーと2種類のデバイスを中心に構成されています。"コントローラードライバー"はコントローラーハードウェアを抽象化し、GPIOピンのセットから複雑な双方向DMAエンジンに接続されたFIFOペアまで幅広く対応します（SPIシフターレジスタの他側で最大のスループットを実現）。このようなドライバーは、バス（通常はプラットフォームバス）とSPIの間を橋渡しし、デバイスのSPI側を struct spi_masterこのマスターの子として表される struct spi_device として生成され、 struct spi_board_info ボード固有の初期化コードから提供されるデスクリプタによって作成されます。 struct spi_driver は"プロトコルドライバー"と呼ばれ、通常のドライバーモデル呼び出しを用いて spi_device にバインドされます。

(i) トランスファーがメッセージの最後でない場合、このフラグはメッセージの途中でチップセレクトを一時的に無効にするために使用されます。このようにチップセレクトをトグルすることで、チップコマンドを終了させる必要があり、1つのspi_messageで複数のチップトランザクションをまとめて実行できます。

すべてのspi_deviceへのメッセージはFIFO順で処理されるが、メッセージが異なるデバイスに順番違いで送られる可能性がある。一部のデバイスは優先度が高く、または「ハード」なアクセス時間要件があるため、このようなことが起こる。

転送中に何らかのエラーが検出された場合、メッセージ全体の処理は中止され、デバイスは選択解除される。関連するメッセージ完了コールバックが戻るまで、そのデバイスにキューイングされた他のspi_messageは処理されない。(このルールはすべての同期転送呼び出しにも適用される。これらはこのコアの非同期プリミティブをラッパーとしている。)

戻り値

成功時はゼロ、失敗時は負のエラーコードを返します。

パラメータ

データを交換するデバイス

コンテキスト

説明

このコールはスリープ可能のコンテキストからしか使用できない。スリープは中断不可であり、タイムアウトもない。低オーバーヘッドのコントローラードライバはDMAを直接メッセージバッファに読み込むことができる。

SPIデバイスのチップ選択はメッセージ実行中はアクティブであり、その後は通常メッセージ間で無効になる。一部の頻繁に使用されるデバイスのドライバは、次のメッセージが同じチップに送られる可能性を考慮してチップ選択を維持し、チップ選択のコストを最小化したいかもしれない。(これにより電力消費が増加する可能性がある。)
