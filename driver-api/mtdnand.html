MTD NANDドライバプログラミングインターフェース¶

著者

Thomas Gleixner

はじめに¶

汎用NANDドライバは、ほぼすべてのNANDおよびAG-ANDベースのチップをサポートし、Memory Technology Devices (MTD)サブシステムに接続します。

このドキュメンテーションは、NANDデバイス用にボードドライバやファイルシステムドライバを実装したい開発者向けに提供されています。

既知のバグと仮定¶

なし。

ドキュメンテーションヒント¶

関数と構造体のドキュメンテーションは自動生成されています。各関数と構造体メンバには[XXX]識別子で短い説明が付与されています。以下の章ではこれらの識別子の意味を説明します。

関数識別子 [XXX]¶

関数は[XXX]識別子で短いコメントにマークされています。識別子は関数の使用方法とスコープを説明します。以下の識別子が使用されます：

  • [MTDインターフェース]

    これらの関数はMTDカーネルAPIへのインターフェースを提供し、置き換え不可能でハードウェアに依存しない機能を提供します。

  • [NANDインターフェース]

    これらの関数はエクスポートされ、NANDカーネルAPIへのインターフェースを提供します。

  • [GENERIC]

    汎用関数は置き換え不可能で、ハードウェアに依存しない機能を提供します。

  • [DEFAULT]

    デフォルト関数はハードウェア関連の機能を提供し、ほとんどの実装に適しています。ボードドライバが必要に応じてこれらの関数を置き換えることができます。これらの関数はNANDチップ記述構造体内のポインタ経由で呼び出されます。ボードドライバはnand_scan()を呼び出す前に置き換えたい関数を設定できます。nand_scan()への入力時に関数ポインタがNULLの場合、検出されたチップタイプに適したデフォルト関数がポインタに設定されます。

構造体メンバ識別子 [XXX]¶

構造体メンバは[XXX]識別子でコメントにマークされています。識別子はメンバの使用方法とスコープを説明します。以下の識別子が使用されます：

  • [INTERN]

    これらのメンバはNANDドライバの内部使用のみに限られ、変更してはなりません。ほとんどの値はnand_scan()で評価されるチップ幾何情報から計算されます。

  • [REPLACEABLE]

    置き換え可能なメンバはハードウェア関連の機能を保持し、ボードドライバが提供できます。ボードドライバはnand_scan()を呼び出す前に置き換えたい関数を設定できます。nand_scan()への入力時に関数ポインタがNULLの場合、検出されたチップタイプに適したデフォルト関数がポインタに設定されます。

  • [BOARDSPECIFIC]

    ボード固有のメンバーはハードウェア関連の情報を保持しており、この情報はボードドライバによって提供される必要があります。ボードドライバはnand_scan()を呼び出す前に、関数ポインタとデータフィールドを設定する必要があります。

  • [オプション]

    オプションのメンバーはボードドライバに関連する情報を保持できます。汎用NANDドライバコードはこの情報を使用しません。

基本的なボードドライバ¶

ほとんどのボードでは、基本的な関数を提供し、nandチップ記述構造体の一部としてボードに依存する情報を埋め込むだけで十分です。

基本的な定義¶

少なくともnand_chip構造体とioremapされたチップアドレスのストレージを提供する必要があります。nand_chip構造体はkmallocを使用して動的に割り当てることも、静的に割り当てることもできます。NANDチップ構造体はMTD構造体を埋め込んでおり、これはMTDサブシステムに登録されます。nand_to_mtd()というヘルパ関数を使用して、nand_chipポインタからMTD構造体のポインタを抽出できます。

kmallocベースの例

static struct mtd_info *board_mtd;
static void __iomem *baseaddr;

静的例

static struct nand_chip board_chip;
static void __iomem *baseaddr;

パーティションの定義¶

デバイスをパーティションに分割したい場合は、ボードに適したパーティションスキーマを定義してください。

#define NUM_PARTITIONS 2
static struct mtd_partition partition_info[] = {
    { .name = "Flash partition 1",
      .offset =  0,
      .size =    8 * 1024 * 1024 },
    { .name = "Flash partition 2",
      .offset =  MTDPART_OFS_NEXT,
      .size =    MTDPART_SIZ_FULL },
};

ハードウェア制御関数¶

ハードウェア制御関数はNANDチップ（複数）の制御ピンへのアクセスを提供します。GPIOピンまたはアドレスラインを使用してアクセスできます。アドレスラインを使用する場合、タイミング要件が満たされていることを確認してください。

GPIOベースの例

static void board_hwcontrol(struct mtd_info *mtd, int cmd)
{
    switch(cmd){
        case NAND_CTL_SETCLE: /* Set CLE pin high */ break;
        case NAND_CTL_CLRCLE: /* Set CLE pin low */ break;
        case NAND_CTL_SETALE: /* Set ALE pin high */ break;
        case NAND_CTL_CLRALE: /* Set ALE pin low */ break;
        case NAND_CTL_SETNCE: /* Set nCE pin low */ break;
        case NAND_CTL_CLRNCE: /* Set nCE pin high */ break;
    }
}

アドレスラインベースの例。 nCEピンはチップセレクトデコーダーによって駆動されていると仮定しています。

static void board_hwcontrol(struct mtd_info *mtd, int cmd)
{
    struct nand_chip *this = mtd_to_nand(mtd);
    switch(cmd){
        case NAND_CTL_SETCLE: this->legacy.IO_ADDR_W |= CLE_ADRR_BIT;  break;
        case NAND_CTL_CLRCLE: this->legacy.IO_ADDR_W &= ~CLE_ADRR_BIT; break;
        case NAND_CTL_SETALE: this->legacy.IO_ADDR_W |= ALE_ADRR_BIT;  break;
        case NAND_CTL_CLRALE: this->legacy.IO_ADDR_W &= ~ALE_ADRR_BIT; break;
    }
}

デバイス準備関数¶

ハードウェアインターフェースがNANDチップの準備/ビジー（R/B）ピンをGPIOやその他のアクセス可能なI/Oピンに接続している場合、この関数はピンの状態を読み戻します。この関数には引数がなく、デバイスがビジー（R/Bピンがロー）の場合に0を、デバイスが準備完了（R/Bピンがハイ）の場合に1を返す必要があります。ハードウェアインターフェースが準備/ビジーピンへのアクセスを提供しない場合は、この関数は定義されず、関数ポインタthis->legacy.dev_readyはNULLに設定する必要があります。

初期化関数¶

初期化関数はメモリを割り当てて、すべてのボード固有のパラメータと関数ポインタを設定します。すべての設定が完了したらnand_scan()が呼び出されます。この関数はチップの検出と識別を試みます。チップが見つかった場合、すべての内部データフィールドがそれに応じて初期化されます。構造体（たち）は最初にゼロクリアされてから、デバイスに関する必要な情報を埋め込む必要があります。

static int __init board_init (void)
{
    struct nand_chip *this;
    int err = 0;

    /* Allocate memory for MTD device structure and private data */
    this = kzalloc(sizeof(struct nand_chip), GFP_KERNEL);
    if (!this) {
        printk ("Unable to allocate NAND MTD device structure.\n");
        err = -ENOMEM;
        goto out;
    }

    board_mtd = nand_to_mtd(this);

    /* map physical address */
    baseaddr = ioremap(CHIP_PHYSICAL_ADDRESS, 1024);
    if (!baseaddr) {
        printk("Ioremap to access NAND chip failed\n");
        err = -EIO;
        goto out_mtd;
    }

    /* Set address of NAND IO lines */
    this->legacy.IO_ADDR_R = baseaddr;
    this->legacy.IO_ADDR_W = baseaddr;
    /* Reference hardware control function */
    this->hwcontrol = board_hwcontrol;
    /* Set command delay time, see datasheet for correct value */
    this->legacy.chip_delay = CHIP_DEPENDEND_COMMAND_DELAY;
    /* Assign the device ready function, if available */
    this->legacy.dev_ready = board_dev_ready;
    this->eccmode = NAND_ECC_SOFT;

    /* Scan to find existence of the device */
    if (nand_scan (this, 1)) {
        err = -ENXIO;
        goto out_ior;
    }

    add_mtd_partitions(board_mtd, partition_info, NUM_PARTITIONS);
    goto out;

out_ior:
    iounmap(baseaddr);
out_mtd:
    kfree (this);
out:
    return err;
}
module_init(board_init);

終了関数¶

終了関数は、ドライバーがモジュールとしてコンパイルされる場合にのみ必要です。これはチップドライバーが保持するすべてのリソースを解放し、MTDレイヤー内のパーティションを登録解除します。

#ifdef MODULE
static void __exit board_cleanup (void)
{
    /* Unregister device */
    WARN_ON(mtd_device_unregister(board_mtd));
    /* Release resources */
    nand_cleanup(mtd_to_nand(board_mtd));

    /* unmap physical address */
    iounmap(baseaddr);

    /* Free the MTD device structure */
    kfree (mtd_to_nand(board_mtd));
}
module_exit(board_cleanup);
#endif

高度なボードドライバ機能¶

この章ではNANDドライバーの高度な機能について説明します。ボードドライバーで上書き可能な関数の一覧については、nand_chip構造体のドキュメンテーションを参照してください。

複数チップ制御¶

NANDドライバーはチップアレイを制御できます。そのため、ボードドライバーは独自のselect_chip関数を提供する必要があります。この関数は要求されたチップを(選択/非選択)します。nand_chip構造体の関数ポインタはnand_scan()を呼び出す前に設定する必要があります。nand_scan()のmaxchipパラメータはスキャンするチップの最大数を定義します。select_chip関数が要求されたチップ数を処理できるようにしてください。

NANDドライバーはチップを1つの仮想チップに結合し、MTDレイヤーに提供します。

注意: ドライバーは等しいサイズのチップを持つ線形チップアレイのみを処理できます。バス幅を拡張する並列アレイのサポートはありません。

GPIOベースの例

static void board_select_chip (struct mtd_info *mtd, int chip)
{
    /* Deselect all chips, set all nCE pins high */
    GPIO(BOARD_NAND_NCE) |= 0xff;
    if (chip >= 0)
        GPIO(BOARD_NAND_NCE) &= ~ (1 << chip);
}

アドレスラインベースの例。 nCEピンがアドレスデコーダに接続されていると仮定します。

static void board_select_chip (struct mtd_info *mtd, int chip)
{
    struct nand_chip *this = mtd_to_nand(mtd);

    /* Deselect all chips */
    this->legacy.IO_ADDR_R &= ~BOARD_NAND_ADDR_MASK;
    this->legacy.IO_ADDR_W &= ~BOARD_NAND_ADDR_MASK;
    switch (chip) {
    case 0:
        this->legacy.IO_ADDR_R |= BOARD_NAND_ADDR_CHIP0;
        this->legacy.IO_ADDR_W |= BOARD_NAND_ADDR_CHIP0;
        break;
    ....
    case n:
        this->legacy.IO_ADDR_R |= BOARD_NAND_ADDR_CHIPn;
        this->legacy.IO_ADDR_W |= BOARD_NAND_ADDR_CHIPn;
        break;
    }
}

ハードウェアECCサポート¶

関数と定数¶

NANDドライバーは3種類のハードウェアECCをサポートしています。

  • NAND_ECC_HW3_256

    ハードウェアECCジェネレータが256バイトごとに3バイトのECCを提供します。

  • NAND_ECC_HW3_512

    ハードウェアECCジェネレータが512バイトごとに3バイトのECCを提供します。

  • NAND_ECC_HW6_512

    ハードウェアECCジェネレータが512バイトごとに6バイトのECCを提供します。

  • NAND_ECC_HW8_512

    ハードウェアECCジェネレータが512バイトごとに8バイトのECCを提供します。

ハードウェアジェネレータが異なる機能を持つ場合、nand_base.cの適切な場所に追加してください。

ボードドライバーは以下の関数を提供する必要があります:

  • enable_hwecc

    この関数はチップへの読み書き前に呼び出されます。この関数でハードウェアジェネレータをリセットまたは初期化してください。この関数は読み書き操作を区別する引数を渡して呼び出されます。

  • calculate_ecc

    この関数はチップからの読み書き後に呼び出されます。ハードウェアからECCをバッファに転送してください。オプションNAND_HWECC_SYNDROMEが設定されている場合、この関数は書き込み時にのみ呼び出されます。下記を参照してください。

  • correct_data

    ECCエラーが発生した場合、この関数はエラー検出および訂正のために呼び出されます。エラーが訂正可能な場合は1または2を返し、訂正不可能な場合は-1を返します。ハードウェアジェネレータがnand_eccソフトウェアジェネレータのデフォルトアルゴリズムと一致する場合、nand_eccが提供する訂正関数を使用してください。重複したコードを実装するのではなく、この関数を用いてください。

ハードウェアECCとsyndrome計算¶

多くのハードウェアECC実装はリード・ソロモン符号を使用し、読み込み時にエラーsyndromeを計算します。このsyndromeは、一般的なリード・ソロモンsyndromeに変換した後、ジェネリックリード・ソロモンライブラリ内のエラー訂正コードを呼び出す必要があります。

ECCバイトはデータバイトの直後に配置する必要があります。これによりsyndromeジェネレータが動作します。これはソフトウェアECCで一般的に使用されるレイアウトとは逆です。データとオフバンド領域の分離はもはや不可能です。nandドライバコードはこのレイアウトを処理し、残りのオフバンド領域の空きバイトはオートプレースメントコードで管理されます。この場合、一致するオフバンドレイアウトを提供してください。実装例はrts_from4.cおよびdiskonchip.cを参照してください。このような場合、ECCレイアウトが不良ブロックマーカーの位置と干渉するため、フラッシュメモリ上に不良ブロックテーブルを使用する必要があります。詳細は不良ブロックテーブルサポートを参照してください。

不良ブロックテーブルサポート¶

ほとんどのNANDチップは、予定された位置に不良ブロックをマークします。これらのブロックは、不良ブロック情報が失われるのを防ぐため、一切の条件で削除してはいけません。ブロックがアクセスされるたびに、不良ブロックマークを確認するには、ブロック内の最初のページのスパレーエリアを読み込む必要があります。これは時間がかかるため、不良ブロックテーブルを使用します。

nandドライバはさまざまな種類の不良ブロックテーブルをサポートしています。

  • デバイスごと

    不良ブロックテーブルはデバイス内のすべての不良ブロック情報を含み、複数のチップを含む場合もあります。

  • チップごと

    チップごとに不良ブロックテーブルが使用され、そのチップの不良ブロック情報を含みます。

  • 固定オフセット

    不良ブロックテーブルはチップ（デバイス）内の固定オフセット位置に配置されます。これはさまざまなDiskOnChipデバイスに適用されます。

  • 自動配置

    不良ブロックテーブルはチップ（デバイス）の終わりまたは開始位置に自動的に配置および検出されます。

  • ミラーテーブル

    不良ブロックテーブルはチップ（デバイス）内でミラーリングされ、不良ブロックテーブルの更新時にデータロスを防ぎます。

nand_scan()はnand_default_bbt()関数を呼び出します。nand_default_bbt()は、nand_scan()で取得したチップ情報に応じて適切なデフォルトの不良ブロックテーブル記述子を選択します。

標準的なポリシーは、デバイスの不良ブロックをスキャンし、RAMベースの不良ブロックテーブルを構築することです。これにより、フラッシュチップ自体の不良ブロック情報を常に確認するよりも高速なアクセスが可能になります。

フラッシュベースのテーブル¶

不良ブロックテーブルをフラッシュメモリに保持することが望ましいか、あるいは必要となる場合があります。AG-ANDチップでは必須です。なぜなら、これらのチップは工場でマーキングされた不良ブロックを持っていないからです。代わりに工場でマーキングされた良ブロックを持っています。ブロックが再利用されるために削除される際、マーカーパターンは消去されます。したがって、パターンをチップに戻す前に電源が落ちた場合、このブロックは失われて不良ブロックに追加されます。そのため、チップを最初に検出する際、良ブロックをスキャンし、それらのブロックを削除する前に不良ブロックテーブルにこの情報を保存します。

テーブルが保存されているブロックは、メモリの不良ブロックテーブルで不良ブロックとしてマークされるため、誤ってアクセスされることを防ぎます。不良ブロックテーブル管理関数はこの保護を回避できます。

フラッシュベースの不良ブロックテーブルのサポートを有効にする最も簡単な方法は、nand_scan()を呼び出す前にnand_chip構造体のbbt_optionフィールドでNAND_BBT_USE_FLASHオプションを設定することです。AG-ANDチップではこれがデフォルトで行われます。これにより、NANDドライバのデフォルトのフラッシュベースの不良ブロックテーブル機能が有効になります。デフォルトの不良ブロックテーブルオプションは以下の通りです。

  • チップごとに不良ブロックテーブルを保存する

  • ブロックあたり2ビットを使用する

  • チップの終わりに自動的に配置する

  • バージョン番号を持つミラーテーブルを使用する

  • チップの終わりに4ブロックを予約する

ユーザー定義のテーブル¶

ユーザー定義のテーブルは、nand_bbt_descr構造体を埋め込み、nand_chip構造体のbbt_tdメンバにポインタを保存してnand_scan()を呼び出すことで作成されます。ミラーテーブルが必要な場合は、2番目の構造体を作成し、nand_chip構造体のbbt_mdメンバにポインタを保存する必要があります。bbt_mdメンバがNULLに設定されている場合、メインテーブルのみが使用され、ミラーテーブルのスキャンは行われません。

nand_bbt_descr構造体で最も重要なフィールドはoptionsフィールドです。optionsはテーブルの大部分のプロパティを定義します。optionsを定義する際は、rawnand.hから予備定義された定数を使用してください。

  • ブロックあたりのビット数

    サポートされるビット数は1ビット、2ビット、4ビット、8ビットです。

  • チップごとのテーブル

    定数NAND_BBT_PERCHIPを設定すると、チップアレイ内の各チップごとに不良ブロックテーブルが管理されます。このオプションを設定しない場合、デバイスごとに不良ブロックテーブルが使用されます。

  • テーブルの位置は絶対値です

    定数NAND_BBT_ABSPAGEを使用し、bad block tableが開始する絶対ページ番号をpagesフィールドで定義してください。チップごとに不良ブロックテーブルを設定し、マルチチップアレイを使用する場合、チップアレイ内の各チップごとに開始ページ番号を指定する必要があります。注意: テーブル識別パターンのスキャンは行われませんので、pattern、veroffs、offs、lenフィールドは未初期化のままにできます。

  • テーブルの位置は自動的に検出されます

    テーブルはチップ（デバイス）の最初または最後の良品ブロックに配置できます。NAND_BBT_LASTBLOCKを設定すると、不良ブロックテーブルをチップ（デバイス）の末尾に配置します。不良ブロックテーブルは、不良ブロックテーブルを保持するブロックの最初のページのスパアエリアに保存されたパターンによって識別されます。patternフィールドにパターンへのポインタを保存してください。さらに、パターンの長さをlenフィールドに、スパアエリア内のオフセットをnand_bbt_descr構造体のoffsメンバに指定する必要があります。ミラーリングされた不良ブロックテーブルには異なるパターンが必須です。

  • テーブルの作成

    NAND_BBT_CREATEオプションを設定して、スキャン時にテーブルが見つからない場合にテーブル作成を有効にしてください。通常は新しいチップが検出された際にのみ実行されます。

  • テーブルの書き込みサポート

    NAND_BBT_WRITEオプションを設定して、テーブルの書き込みサポートを有効にしてください。これにより、摩耗によりブロックが不良とマークされる必要がある場合に不良ブロックテーブルを更新できます。MTDインターフェース関数block_markbadは、不良ブロックテーブルの更新関数を呼び出します。書き込みサポートが有効な場合、テーブルはFLASH上に更新されます。

    注意: 書き込みサポートは、バージョン管理を持つミラーリングテーブルに対してのみ有効にしてください。

  • テーブルバージョン管理

    NAND_BBT_VERSIONオプションを設定して、テーブルバージョン管理を有効にしてください。書き込みサポートを持つミラーリングテーブルにはこの機能を有効にするのが強く推奨されます。これにより、不良ブロックテーブル情報の喪失リスクは、1つの摩耗したブロックに関する情報の喪失に限定されます。バージョンはデバイスのスパアエリア内の4連続バイトに保存されます。バージョン番号の位置は、不良ブロックテーブル記述子のveroffsメンバで定義されます。

  • 書き込み時にブロックの内容を保存する

    不良ブロックテーブルを保持するブロックに他の有用な情報が含まれている場合、NAND_BBT_SAVECONTENTオプションを設定してください。不良ブロックテーブルが書き込まれる際、全体のブロックが読み込まれ、不良ブロックテーブルが更新され、ブロックが削除され、すべての情報が再び書き込まれます。このオプションが設定されていない場合、不良ブロックテーブルのみが書き込まれ、ブロック内の他のすべての情報は無視され削除されます。

  • 予約ブロック数

    自動配置を行うためには、不良ブロックテーブルの保存に使用するブロックを予約する必要があります。予約ブロック数は、不良ブロックテーブルの説明構造体のmaxblocksメンバで定義されます。ミラーテーブルに4ブロックを予約するというのは、合理的な数です。これにより、不良ブロックテーブル識別パターンのスキャン対象となるブロック数も制限されます。

スパアエリア（自動配置）¶

NANDドライバーは、ファイルシステムデータのスパアエリアへの配置方法にいくつかの選択肢を提供します。

  • ファイルシステムドライバーによる配置

  • 自動配置

デフォルトの配置関数は自動配置です。NANDドライバーは、さまざまなチップタイプに対応するデフォルトの配置スキーマを内蔵しています。ハードウェアのECC機能によりデフォルトの配置が合わない場合、ボードドライバーが独自の配置スキーマを提供できます。

ファイルシステムドライバーは、デフォルトの配置スキーマではなく独自の配置スキーマを使用できます。

配置スキーマはnand_oobinfo構造体で定義されます

struct nand_oobinfo {
    int useecc;
    int eccbytes;
    int eccpos[24];
    int oobfree[8][2];
};

  • useecc

    useeccメンバはECCおよび配置機能を制御します。ヘッダーファイルinclude/mtd/mtd-abi.hにはECCおよび配置を選択するための定数が含まれています。MTD_NANDECC_OFFはECCを完全にオフにします。これはテストや診断用にのみ提供されており、推奨されません。MTD_NANDECC_PLACEは呼び出し元が定義した配置を選び、MTD_NANDECC_AUTOPLACEは自動配置を選択します。

  • eccbytes

    eccbytesメンバは、ページあたりのECCバイト数を定義します。

  • eccpos

    eccpos配列は、スパアエリア内のECCコードの配置位置をバイトオフセットで保持します。

  • oobfree

    oobfree配列は、スパアエリア内で自動配置に使用可能な領域を定義します。情報は{オフセット、サイズ}の形式で提供されます。オフセットは利用可能な領域の開始位置、サイズはバイト単位の長さを表します。複数の領域を定義できます。リストは{0, 0}のエントリで終了します。

ファイルシステムドライバーによる配置¶

呼び出し元の関数は、eccの配置を定義するnand_oobinfo構造体へのポインタを提供します。書き込みの際には、データバッファに加えて、スパレーエリアバッファを提供する必要があります。スパレーエリアバッファのサイズは（ページ数）×（スパレーエリアのサイズ）です。読み取りの際には、バッファサイズは（ページ数）×（スパレーエリアのサイズ＋（ページあたりのeccステップ数）×sizeof(int)）です。ドライバは、各タプルのeccチェック結果をスパレーエリアバッファに保存します。保存順序は以下の通りです。

<spare data page 0><ecc result 0>...<ecc result n>

...

<spare data page n><ecc result 0>...<ecc result n>

これはYAFFS1で使用されるレガシーモードです。

スパレーエリアバッファがNULLの場合、nand_oobinfo構造体に指定されたスキーマに従ってのみeccの配置が行われます。

自動配置¶

自動配置は、組み込みのデフォルト設定を用いてeccバイトをスパレーエリアに配置します。ファイルシステムデータをスパレーエリアに保存・読み込む必要がある場合、呼び出し元の関数はバッファを提供する必要があります。各ページあたりのバッファサイズはnand_oobinfo構造体のoobfree配列で決定されます。

スパレーエリアバッファがNULLの場合、組み込みのデフォルトスキーマに従ってのみeccの配置が行われます。

ファイルシステムサポート¶

NANDドライバーはMTDインターフェースを介してファイルシステムに必要なすべての機能を提供します。

ファイルシステムはNANDの特徴や制限を理解する必要があります。NANDフラッシュの主な制限は、ページに好きなだけ書き込むことができないことです。ページに連続して書き込む際、再び削除するまでに許可される書き込み回数はメーカーの仕様により1〜3回までです。これはスパアエリアにも同様に適用されます。

そのため、NANDを意識したファイルシステムは、ページサイズのチャンクで書き込むか、または小さな書き込みを一時保存する書き込みバッファを保持する必要があります。利用可能なNANDを意識したファイルシステム: JFFS2, YAFFS。

ファイルシステムデータをスパアエリアに保存する際の使用方法は、以前の章で説明したスパアエリア配置機能によって制御されます。

ツール¶

MTDプロジェクトはNANDフラッシュを扱うためのいくつかの便利なツールを提供しています。

  • flasherase, flasheraseall: FLASHパーティションの削除とフォーマット

  • nandwrite: NAND FLASHにファイルシステムイメージを書き込む

  • nanddump: NAND FLASHパーティションの内容をダンプする

これらのツールはNANDの制限を認識しています。エラーの原因がNANDを意識していないアクセスメソッドによるものである場合は、これらのツールを使用してください。

データバッファと関連するECCおよびOOBデータがすべて0xffパターンであるかを確認し、その領域が消去されてプログラミング可能であることを示します。bitflips_thresholdは、領域が消去されていないとみなすための最大ビットフリップ数を指定します。

成功した場合、渡されたバッファが0xffで埋まり、ビットフリップ数がbitflips_threshold以下である正の数を返します。しきい値を超えた場合、-ERROR_CODEを返します。

2/ エラーページにおけるビットフリップを確認する際には、

ペイロードデータだけでなく、関連するECCデータも確認する必要があります。なぜなら、ユーザーがほぼすべてのビットを1に設定し、一部を0に設定している場合があるからです。このような場合、チャンクを削除済みと見なすべきではなく、ECCバイトの確認によりこのような状況を防ぐことができます。
