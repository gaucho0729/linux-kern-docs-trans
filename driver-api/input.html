close

最後のユーザーが呼び出すときにこのメソッドが呼ばれます input_close_device().

デバイスに送信されるイベント（例：EV_LEDやEV_SND）のハンドラ。デバイスは要求された動作（LEDを点灯、音を鳴らすなど）を実行する必要があります。この呼び出しは event_lock スリープしてはなりません

grab

デバイスがキャプチャされている（EVIOCGRAB ioctlによる）入力ハンドル。ハンドルがデバイスをキャプチャすると、すべての入力イベントの唯一の受信者になります

このスピンロックは、入力コアがデバイスの新しいイベントを受信・処理する際（ input_event()）に取得されます。デバイスが入力コアに登録された後、デバイスのパラメータ（キーマップやabsmin、absmax、absfuzzなど）にアクセス・変更するコードはこのロックを取得しなければなりません

open()、close()、flush()メソッドの呼び出しを順序付けます

users

このデバイスを開いたユーザー（入力ハンドル）の数を保存します。これは input_open_device() および input_close_device() が、最初のユーザーがデバイスを開くときにのみdev->open()が呼ばれるように、最後のユーザーがデバイスを閉じるときにのみdev->close()が呼ばれるようにします

going_away

登録解除中のデバイスをマークし、input_open_device*()が-ENODEVで失敗させます

dev

ドライバモデルにおけるこのデバイスのビュー

h_list

このデバイスに関連する入力ハンドルのリスト。リストにアクセスする際はdev->mutexを保持しなければなりません

node

input_dev_listにデバイスを配置するために使用されます

num_vals

現在のフレームにキューイングされた値の数

max_vals

フレームにキューイングされた最大値

vals

現在のフレームにキューイングされた値の配列

devres_managed

devresフレームワークで管理されており、明示的なアンレジストレーションや解放が必要ないことを示します

timestamp

input_set_timestampによって設定されたタイムスタンプを保存する領域

struct input_handler¶

入力デバイスのインターフェースの一つを実装します

定義

struct input_handler {
  void *private;
  void (*event)(struct input_handle *handle, unsigned int type, unsigned int code, int value);
  void (*events)(struct input_handle *handle, const struct input_value *vals, unsigned int count);
  bool (*filter)(struct input_handle *handle, unsigned int type, unsigned int code, int value);
  bool (*match)(struct input_handler *handler, struct input_dev *dev);
  int (*connect)(struct input_handler *handler, struct input_dev *dev, const struct input_device_id *id);
  void (*disconnect)(struct input_handle *handle);
  void (*start)(struct input_handle *handle);
  bool legacy_minors;
  int minor;
  const char *name;
  const struct input_device_id *id_table;
  struct list_head        h_list;
  struct list_head        node;
  ANDROID_KABI_RESERVE(1);
};

メンバ

private

ドライバ固有のデータ

event

イベントハンドラ。このメソッドは入力コアが割り込みを無効にしてdev->event_lockスピンロックを保持した状態で呼び出され、したがってスリープしてはなりません

events

イベントシーケンスハンドラ。このメソッドは入力コアが割り込みを無効にしてdev->event_lockスピンロックを保持した状態で呼び出され、したがってスリープしてはなりません

filter

同様に イベント; 通常のイベントハンドラと「フィルタ」を分離します

match

デバイスのIDとハンドラのid_tableを比較して、デバイスとハンドラの間で細かいマッチングを行うために呼ばれます

connect

ハンドラを入力デバイスにアタッチするときに呼ばれます

disconnect

ハンドラを入力デバイスから切断します

start

指定されたハンドルに対応するハンドラの処理を開始します。この関数は、connect()メソッドの直後にinput coreによって呼び出され、またデバイスを「取得」したプロセスがそれを解放した際にも呼び出されます

legacy_minors

設定に設定する true レガシー・マイナーレンジを使用するドライバによって使用されます

minor

このドライバが提供できるデバイス用の32個のレガシー・マイナーの範囲の開始位置

name

/proc/bus/input/handlersに表示されるハンドラの名前

id_table

このドライバが処理できるinput_device_idsのテーブルへのポインタ

h_list

ハンドラに関連するinputハンドルのリスト

node

input_handler_listにドライバを登録するためのポインタ

説明

入力ハンドラは入力デバイスにアタッチされ、入力ハンドルを作成します。任意の入力デバイスに同時に複数のハンドラがアタッチされている可能性があります。すべてのハンドラは、デバイスが生成する入力イベントのコピーを受け取ります

同じ構造体が入力フィルタの実装にも使用されます。入力コアはフィルタを優先的に実行し、フィルタのfilter()メソッドがイベントをフィルタリングすべきと返した場合、通常のハンドラにイベントを渡しません true Note that input core serializes calls to connect() and disconnect() methods.

input coreはconnect()とdisconnect()メソッドの呼び出しをシリアル化します

struct input_dev *devm_input_allocate_device(struct デバイス *dev)¶

管理された入力デバイスを割り当てます

パラメータ

struct device *dev

作成される入力デバイスを所有するデバイス

説明

準備された struct input_dev または NULL.

管理された入力デバイスは明示的にアンレジストレーションや解放する必要がありません。オーナーデバイスがドライバからバインド解除（またはバインディング失敗）されるときに自動的に処理されます。管理された入力デバイスが割り当てられると、通常の入力デバイスと同様に設定・登録できます。devm_input_device_[un]register()の特殊な変体は存在せず、通常の関数は管理されたデバイスと非管理デバイスの両方で動作します。ただし、ほとんどの場合、管理された入力デバイスは明示的にアンレジストレーションや解放する必要はありません。

注意

オーナーデバイスは入力デバイスの親として設定され、ユーザーはこれを上書きしないでください。

void input_free_device(struct input_dev *dev)¶

input_dev構造体が占めるメモリを解放します

パラメータ

struct input_dev *dev

解放する入力デバイス

説明

この関数は、以下の場合にのみ使用してください input_register_device() まだ呼び出されていないか、呼び出しが失敗した場合。デバイスが登録された後は input_unregister_device() を使用し、最後の参照が解除されるまでメモリが解放されません。

struct key_entry {

type
