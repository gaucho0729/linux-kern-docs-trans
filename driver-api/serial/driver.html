ローレベルシリアルAPI¶

このドキュメントは、新しいシリアルドライバのいくつかの側面についての簡単な概要を目的としています。完全ではありません。ご質問があれば、以下にご相談ください <rmk@arm.linux.org.uk>

参照実装はamba-pl011.cに含まれています。

ローカットシリアルハードウェアドライバ¶

ローカットシリアルハードウェアドライバは、コアシリアルドライバにポート情報（uart_portで定義）と制御メソッド（uart_opsで定義）を提供する責任があります。また、ポートの割り込み処理を担当し、コンソールサポートを提供することも含まれます。

コンソールサポート¶

シリアルコアはいくつかのヘルパーファンクションを提供します。これは正しいポート構造（uart_get_consoleを通じて）を特定し、コマンドライン引数をデコード（uart_parse_options）する機能を含みます。

また、uart_console_writeというヘルパーファンクションがあり、1文字ずつ書き込みを行い、改行をCRLFシーケンスに変換します。ドライバ開発者はこの関数を使用することを推奨します。

ロック¶

ローカットハードウェアドライバは、port->lockを使用して必要なロックを担当する責任があります。ただし、いくつかの例外があります（uart_opsのリストで後述します）。

2つのロックがあります。ポートごとのスピンロックと、全体のセマフォ。

コアドライバの観点から、port->lockは以下のデータをロックします：

port->mctrl
port->icount
port->state->xmit.head (circ_buf->head)
port->state->xmit.tail (circ_buf->tail)

ローカットドライバはこのロックを追加のロック提供のために自由に使用できます。

port_semセマフォは、ポートが不適切なタイミングで追加/削除/再構成されるのを防ぐために使用されます。v2.6.27以降、このセマフォはtty_port構造体の「mutex」メンバとなり、一般的に「ポートミューテックス」と呼ばれます。

uart_ops¶

uart_ops構造体は、シリアルコアとハードウェア固有ドライバ間の主なインターフェースです。これはハードウェアを制御するためのすべてのメソッドを含みます。

tx_empty(port)

この関数は、'port'で指定されたポートの送信FIFOおよびシフターが空かどうかをテストします。空であればTIOCSER_TEMTを返し、そうでなければ0を返します。ポートがこの操作をサポートしない場合はTIOCSER_TEMTを返します。

ロック：なし。

割り込み：呼び出し元依存。

この呼び出しはスリープしてはいけません

set_mctrl(port, mctrl)

この関数は、'port'で指定されたポートのモデム制御ラインをmctrlで指定された状態に設定します。mctrlの関連ビットは以下の通りです：

  • TIOCM_RTS RTS信号。

  • TIOCM_DTR DTR信号。

  • TIOCM_OUT1 OUT1信号。

  • TIOCM_OUT2 OUT2信号。

  • TIOCM_LOOP ポートをループバックモードに設定します。

適切なビットが設定されている場合、シグナルはアクティブに駆動されるべきです。ビットがクリアされている場合、シグナルはインアクティブに駆動されるべきです。

ロック: port->lock が取得されています。

割り込み: ローカルで無効化されています。

この呼び出しはスリープしてはいけません

get_mctrl(port)

モデム制御入力の現在の状態を返します。出力の状態は返すべきではありません。コアがその状態を追跡しているためです。状態情報には以下の項目を含めるべきです：

  • DCD シグナルの TIOCM_CAR 状態

  • CTS シグナルの TIOCM_CTS 状態

  • DSR シグナルの TIOCM_DSR 状態

  • RI シグナルの TIOCM_RI 状態

シグナルが現在アクティブに駆動されている場合、ビットが設定されます。ポートが CTS、DCD、または DSR をサポートしない場合、ドライバーはシグナルが常にアクティブであることを示すべきです。RI が利用できない場合、シグナルはアクティブと表示されません。

ロック: port->lock が取得されています。

割り込み: ローカルで無効化されています。

この呼び出しはスリープしてはいけません

stop_tx(port)

キャラクターの送信を停止します。これは CTS ラインがインアクティブになったり、tty レイヤーが XOFF 文字により送信を停止したいと通知した場合に起きます。

ドライバーはできるだけ早くキャラクターの送信を停止すべきです。

ロック: port->lock が取得されています。

割り込み: ローカルで無効化されています。

この呼び出しはスリープしてはいけません

start_tx(port)

キャラクターの送信を開始します。

ロック: port->lock が取得されています。

割り込み: ローカルで無効化されています。

この呼び出しはスリープしてはいけません

throttle(port)

ラインディスパッチの入力バッファがほぼ満杯に近いことをシリアルドライバーに通知し、シリアルポートにキャラクターを送信しないように信号を出すべきです。これはハードウェアによるフロー制御が有効になっている場合にのみ呼び出されます。

ロック: .unthrottle() と tty レイヤーによる termios 変更とシリアル化されています。

unthrottle(port)

シリアルポートにキャラクターを送信しても入力バッファがオーバーフローする心配がないことをシリアルドライバーに通知します。

これはハードウェアによるフロー制御が有効になっている場合にのみ呼び出されます。

ロック: .throttle() と tty レイヤーによる termios 変更とシリアル化されています。

send_xchar(port,ch)

ポートが停止していても高優先度のキャラクターを送信します。これは XON/XOFF フロー制御と tcflow() の実装に使用されます。シリアルドライバーがこの関数を実装しない場合、tty コアはキャラクターを環状バッファに追加してから start_tx() / stop_tx() を呼び出してデータをフラッシュします。

ch == ‘0’ (__DISABLED_CHAR) の場合、送信しないでください。

ロック：なし。

割り込み：呼び出し元依存。

stop_rx(port)

キャラクターの受信を停止します。ポートが閉じる過程にあります。

ロック: port->lock が取得されています。

割り込み: ローカルで無効化されています。

この呼び出しはスリープしてはいけません

enable_ms(port)

モデムステータス割り込みを有効にします。

このメソッドは複数回呼び出される可能性があります。シャットダウンメソッドが呼び出される際にはモデムステータス割り込みを無効化する必要があります。

ロック: port->lock が取得されています。

割り込み: ローカルで無効化されています。

この呼び出しはスリープしてはいけません

break_ctl(port,ctl)

ブレイク信号の送信を制御します。ctl がゼロでない場合、ブレイク信号を送信する必要があります。別のゼロ ctl で呼び出された際には信号を終了する必要があります。

ロック: 呼び出し元がtty_port->mutexを保持しています

startup(port)

割込みリソースを取得し、低レベルドライバ状態を初期化します。受信のためにポートを有効化します。RTSおよびDTRのアクティブ化は行いません（別個のset_mctrl呼び出しで行われます）

このメソッドは、ポートが最初に開かれたときにのみ呼び出されます

ロック: port_semが取得されています

割込み: グローバルに無効化されています

shutdown(port)

ポートを無効化し、有効な場合のブレイク条件を解除し、割込みリソースを解放します。RTSおよびDTRの無効化は行いません（すでにset_mctrl呼び出しで行われています）

ドライバは、この呼び出しが完了した後、port->stateにアクセスしてはいけません

このメソッドは、このポートの利用者がいなくなったときにのみ呼び出されます

ロック: port_semが取得されています

割り込み：呼び出し元依存。

flush_buffer(port)

書き込みバッファをクリアし、DMA状態をリセットし、進行中のDMA転送を停止します

ポート->state->xmitリングバッファがクリアされたときに呼び出されます

ロック: port->lock が取得されています。

割り込み: ローカルで無効化されています。

この呼び出しはスリープしてはいけません

set_termios(port,termios,oldtermios)

ポートパラメータ（ワード長、パリティ、ストップビットなど）を変更します。read_status_maskとignore_status_maskを更新し、受信したいイベントタイプを指定します。関連するtermios->c_cflagビットは以下の通りです：

CSIZE

  • ワード長

CSTOPB

  • 2ストップビット

PARENB

  • パリティ有効

PARODD

  • 奇数パリティ（PARENBが有効な場合）

CREAD

  • 文字の受信を有効化（未設定の場合でもポートからの文字は受信しますが破棄します）

CRTSCTS

  • 設定されている場合、CTSステータス変化の報告を有効化します

CLOCAL

  • 未設定の場合、モデムステータス変化の報告を有効化します

関連するtermios->c_iflagビットは以下の通りです：

INPCK

  • フレームエラーおよびパリティエラーイベントをTTYレイヤーに伝達します

BRKINT / PARMRK

  • これら両方とも、ブレイクイベントをTTYレイヤーに伝達します

IGNPAR

  • パリティおよびフレーミングエラーを無視します

IGNBRK

  • ブレイクエラーを無視します。IGNPARも設定されている場合、オーバーランエラーも無視します

iflagビットの相互作用は以下の通りです（パリティエラーを例にします）：

パリティエラー

INPCK

IGNPAR

n/a

0

n/a

キャラクターが受信され、TTY_NORMALとしてマークされました

なし

1

n/a

キャラクターが受信され、TTY_NORMALとしてマークされました

はい

1

0

キャラクターが受信され、TTY_PARITYとしてマークされました

はい

1

1

キャラクターが破棄されました

ハードウェアが「ソフト」フロー制御をサポートする場合、他のフラグ（例: xon/xoff キャラクター）を使用できます。

ロック: 呼び出し元がtty_port->mutexを保持しています

割り込み：呼び出し元依存。

この呼び出しはスリープしてはいけません

set_ldisc(port,termios)

ディスシプリン変更の通知。参照: ロックロノミコン.

ロック: 呼び出し元がtty_port->mutexを保持しています

pm(port,state,oldstate)

指定されたポートに対して、電源管理関連のアクティビティを実行します。Stateは新しい状態（uart_pm_stateのenumで定義）を、oldstateは以前の状態を示します。

この関数は、リソースを取得するために使用すべきではありません。

この関数は、ポートが最初に開かれたときおよび最終的に閉じられたときに呼び出されます（システムコンソールとしても使用される場合を除く）。CONFIG_PMが設定されていなくても発生します。

ロック：なし。

割り込み：呼び出し元依存。

type(port)

指定されたポートを説明する文字列定数へのポインタを返します。NULLを返す場合、'unknown'という文字列が代入されます。

ロック：なし。

割り込み：呼び出し元依存。

release_port(port)

ポートが現在使用しているメモリおよびIO領域のリソースを解放します。

ロック：なし。

割り込み：呼び出し元依存。

request_port(port)

ポートが必要とするメモリおよびIO領域のリソースを要求します。失敗した場合、この関数が返る際にはリソースを登録せず、-EBUSYを返す必要があります。

ロック：なし。

割り込み：呼び出し元依存。

config_port(port,type)

ポートに必要な自動設定ステップを実行します。 type 必要な設定のビットマスクを含みます。UART_CONFIG_TYPEはポートが検出および識別を必要とすることを示します。port->typeは検出されたタイプに設定するか、ポートが検出されなかった場合はPORT_UNKNOWNに設定する必要があります。

UART_CONFIG_IRQは割込み信号の自動設定を示し、標準のカーネル自動プローブ技術を使用して検出する必要があります。ポートが内部的に割込みをハードワイヤードしているプラットフォーム（例: システムオンチップ実装）では必要ありません。

ロック：なし。

割り込み：呼び出し元依存。

verify_port(port,serinfo)

serinfoに含まれる新しいシリアルポート情報がこのポートタイプに適しているかを確認します。

ロック：なし。

割り込み：呼び出し元依存。

ioctl(port,cmd,arg)

ポート固有のIOCTLを実行します。IOCTLコマンドは<asm/ioctl.h>に記載されている標準番号システムを使用して定義する必要があります。

ロック：なし。

割り込み：呼び出し元依存。

poll_init(port)

kgdbによって呼び出され、poll_put_char()およびpoll_get_char()をサポートするための最小限のハードウェア初期化を実行します。->startup()とは異なり、割込みを要求すべきではありません。

ロック: tty_mutexおよびtty_port->mutexが取得されています。

割込み: なし。

poll_put_char(port,ch)

kgdbによって呼び出され、シリアルポートに1つのキャラクターを直接書き込みます。TX FIFOにスペースがあるまでブロックする必要があります。

ロック：なし。

割り込み：呼び出し元依存。

この呼び出しはスリープしてはいけません

poll_get_char(port)

kgdbから直接シリアルポートから1文字を読み取るために呼ばれる。データが利用可能であればそれを返し、そうでない場合は即座にNO_POLL_CHARを返す必要があります。

ロック：なし。

割り込み：呼び出し元依存。

この呼び出しはスリープしてはいけません

その他の関数¶

uart_update_timeout(port,cflag,baud)

バイト数、パリティ、ストップビット、ボーレートに基づいてFIFOドレインタイムアウト、port->timeoutを更新します。

ロック: 呼び出し元がport->lockを取得することを期待しています

割り込み: なし

uart_get_baud_rate(port,termios,old,min,max)

指定されたtermiosに応じた数値ボーレートを返します。特殊な38400ボーレートの「kludge（不完全な補正）」を考慮します。B0ボーレートは9600ボーレートにマッピングされます。

ボーレートがmin..maxの範囲外の場合、oldがNULLでない場合は元のボーレートを試します。その結果もmin..maxの制約を超える場合、9600ボーレートを返します。termiosは使用中のボーレートに更新されます。

注意: min..maxは常に9600ボーレートを選択可能である必要があります。

ロック: 呼び出し元依存

割り込み: なし

uart_get_divisor(port,baud)

指定されたボーレートに応じたディバイザー（baud_base / baud）を適切に四捨五入して返します。

38400ボーレートかつカスタムディバイザーが選択された場合、カスタムディバイザーを返します。

ロック: 呼び出し元依存

割り込み: なし

uart_match_port(port1,port2)

このユーティリティ関数は、2つのuart_port構造体が同じポートを表しているかどうかを判定するために使用できます。

ロック: なし

割り込み: なし

uart_write_wakeup(port)

送信バッファ内の文字数がしきい値を下回ったときにドライバがこの関数を呼び出すことを期待しています。

ロック: port->lockを保持しておく必要があります

割り込み: なし

uart_register_driver(drv)

UARTドライバをコアドライバに登録します。これによりTTYレイヤーに登録し、ポートごとの状態をコアドライバで初期化します

drv->portはNULLでなければならず、この呼び出し成功後にuart_add_one_portでポートごとの構造体を登録する必要があります

ロック: なし

割り込み: 有効

uart_unregister_driver()

コアドライバからドライバのすべての参照を削除します。低レベルドライバは、すべてのポートを uart_remove_one_port() 登録した場合に、 uart_add_one_port().

ロック: なし

割り込み: 有効

uart_suspend_port()

uart_resume_port()

uart_add_one_port()

uart_remove_one_port()

その他の注意事項¶

今後はuart_portから「未使用」のエントリを削除し、低レベルドライバが独自のuart_portをコアに登録できるようにする予定です。これにより、ドライバがuart_portを構造体ポインタとして使用できるようになり、以下のようになります：

struct my_port {
        struct uart_port        port;
        int                     my_stuff;
};

モデム制御ラインのGPIO経由¶

モデム制御ラインをGPIO経由で設定/取得するための補助関数が提供されています。

mctrl_gpio_init(port, idx):

デバイスツリーから{cts,rts,…}-gpiosを取得し（存在すれば）、リクエストして方向を設定などを行い、割り当てられた構造体を返します。 devm_* 関数が使用されるため、mctrl_gpio_free()を呼び出す必要はありません。この関数は割り込みハンドリングを設定するため、ドライバでGPIO入力ラインの変更を処理しないようにしてください。

mctrl_gpio_free(dev, gpios):

mctrl_gpio_init()でリクエストされたGPIOを解放します。 devm_* devm_*関数が使用されるため、通常はこの関数を呼び出す必要はありません。

mctrl_gpio_to_gpiod(gpios, gidx)

この関数は、モデムラインインデックスに関連するgpio_desc構造体を返します。

mctrl_gpio_set(gpios, mctrl):

この関数は、mctrlの状態に応じてgpiosを設定します。

mctrl_gpio_get(gpios, mctrl):

この関数は、gpiosの値に基づいてmctrlを更新します。

mctrl_gpio_enable_ms(gpios):

irqを有効にし、msラインの変更を処理します。

mctrl_gpio_disable_ms(gpios):

irqを無効にし、msラインの変更の処理を停止します。
