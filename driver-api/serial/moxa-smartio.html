1. はじめに¶

Smartio/Industio/UPCIファミリーのLinuxドライバは、以下のマルチポートボードをサポートしています。

  • 2ポートマルチポートボード

    CP-102U, CP-102UL, CP-102UF CP-132U-I, CP-132UL, CP-132, CP-132I, CP132S, CP-132IS, CI-132, CI-132I, CI-132IS, (C102H, C102HI, C102HIS, C102P, CP-102, CP-102S)

  • 4ポートマルチポートボード

    CP-104EL, CP-104UL, CP-104JU, CP-134U, CP-134U-I, C104H/PCI, C104HS/PCI, CP-114, CP-114I, CP-114S, CP-114IS, CP-114UL, C104H, C104HS, CI-104J, CI-104JS, CI-134, CI-134I, CI-134IS, (C114HI, CT-114I, C104P), POS-104UL, CB-114, CB-134I

  • 8ポートマルチポートボード

    CP-118EL, CP-168EL, CP-118U, CP-168U, C168H/PCI, C168H, C168HS, (C168P), CB-108

このドライバおよびインストール手順はLinux Kernel 2.4.xおよび2.6.xに基づいて開発されました。Intel x86ハードウェアプラットフォームをサポートしています。互換性を維持するため、このバージョンはRedHat、Mandrake、FedoraおよびS.u.S.E Linuxでも適切にテストされています。ただし、互換性の問題が発生した場合は、Moxaにご連絡ください。 サポート@moxa.com.tw.

デバイスドライバに加えて、このバージョンでは有用なユーティリティも提供されています。以下がその例です。

  • msdiag

    インストール済みのMoxa Smartio/Industioボードを表示する診断プログラム

  • msmon

    データカウントおよびラインステータス信号を観察するモニタプログラム

  • msterm シリアルポートのテストに役立つシンプルなターミナルプログラム

    ports.

  • io-irq.exe

    ISAボードの設定用の構成プログラム。注意: このプログラムはDOS環境下でのみ実行可能です。

すべてのドライバおよびユーティリティは、GNU General Public Licenseに基づきソースコード形式で公開されています。詳細については、各ソースコードファイルのGNU General Public Licenseに関するアナウンスメントを参照してください。

2. システム要件¶

  • ハードウェアプラットフォーム: Intel x86マシン

  • カーネルバージョン: 2.4.xまたは2.6.x

  • gccバージョン 2.72以上

  • 最大4つのボードを組み合わせてインストール可能

3. インストール¶

3.1 ハードウェアインストール¶

スマートio/インダストリオファミリーのマルチポートボードには、ISAとPCIの2種類のバスがあります。

ISAボード¶

このドライバをインストールする前に、CAPアドレス、I/Oアドレス、割込みベクターおよびIRQを設定する必要があります。さらに進む前に、ユーザーマニュアルのハードウェアインストール手順を参照してください。ISAボードが適切に設定された後、JP1の状態がオープンになっていることを確認してください。

PCI/UPCIボード¶

他のISAデバイスとのIRQ競合を避けるために、BIOSでIRQの使用を調整する必要があります。インストール前にユーザーマニュアルのハードウェアインストール手順を参照してください。

PCI IRQ共有¶

同じマルチポートボード内の各ポートは同じIRQを共有します。最大4台のモクサスマートio/インダストリオPCIファミリーのマルチポートボードを1つのシステムにインストールし、同じIRQを共有できます。

3.2 ドライバファイル¶

ドライバファイルはftp、CD-ROM、フロッピーディスクから取得できます。いずれにしても、まずドライバファイル「mxser.tgz」を指定されたディレクトリ（例：/moxa）にコピーしてください。以下に実行コマンドを示します：

# cd /
# mkdir moxa
# cd /moxa
# tar xvf /dev/fd0

または:

# cd /
# mkdir moxa
# cd /moxa
# cp /mnt/cdrom/<driver directory>/mxser.tgz .
# tar xvfz mxser.tgz

3.3 デバイスの命名規則¶

/moxa/mxserディレクトリにすべてのドライバおよびユーティリティファイルが含まれています。インストール手順は使用するモデルによって異なります。モジュールドライバを使用する場合は3.4を参照し、静的ドライバを使用する場合は3.5を参照してください。

ダイヤルインおよびコールアウトポート¶

このドライバは伝統的なシリアルデバイスの特性を維持しています。各シリアルポートには2つの特別なファイル名があります。1つはダイヤルインポートで「ttyMxx」と名付けられ、コールアウトポートの命名規則は「cumxx」です。

2枚以上のボードをインストールした場合のデバイス命名¶

スマートio/インダストリオマルチポートボードの命名規則は以下の通りです。

ボード番号

ダイヤルインポート

コールアウトポート

1番目のボード

ttyM0 - ttyM7

cum0 - cum7

2番目のボード

ttyM8 - ttyM15

cum8 - cum15

3番目のボード

ttyM16 - ttyM23

cum16 - cum23

4番目のボード

ttyM24 - ttyM31

cum24 - cum31

注意

カーネル2.6以上では、cumデバイスは非推奨となりました。そのため、ttyM*デバイスを使用してください。

ボードの順序¶

このドライバはドライバのパラメータに従ってISAボードをアクティブにします。すべての指定されたISAボードがアクティブになった後、PCIボードがシステム内で自動的にインストールされます。したがって、ボード番号はISAボードのCAPアドレスによって順序付けられます。PCIボードの順序はISAボードの後に配置され、C168H/PCIボードはC104H/PCIボードよりも優先されます。

3.4 モジュールドライバの設定¶

モジュールドライバはインストールの最も簡単な方法です。静的ドライバのインストールを希望する場合は、この段落をスキップしてください。

————- モクサドライバの使用準備 ——————–

3.4.1 正しいメジャーナンバーを持つttyデバイスの作成¶

MOXAドライバを使用する前に、システムにドライバのメジャーナンバーで作成されたttyデバイスが存在している必要があります。この手順を簡略化するために、シェルスクリプト「msmknod」を提供しています。この手順は一度実行すればよいですが、以下の条件に該当する場合は再度行う必要があります。

  1. ドライバのメジャーナンバーを変更した場合。詳しくは「3.7」節をご参照ください。

  2. インストール済みのMOXAボードの総数が変更された場合。たとえばMOXAボードを追加または削除した場合です。

  3. tty名を変更したい場合。この場合はシェルスクリプト「msmknod」を変更する必要があります。

手順は以下の通りです。

# cd /moxa/mxser/driver
# ./msmknod

このシェルスクリプトは、ダイヤルインデバイスとコールアウトデバイスのメジャーナンバーを指定してttyデバイスを作成します。また、インストール済みのMOXAボードの総数を指定する必要があります。ダイヤルインデバイスとコールアウトデバイスのデフォルトのメジャーナンバーはそれぞれ30、35です。他の番号に変更する場合は、「3.7」節を参照してください。msmknodは、同じデバイス名を占有している特殊ファイルを削除します。

3.4.2 MOXAドライバおよびユーティリティのビルド¶

MOXAドライバおよびユーティリティを使用する前に、すべてのソースコードをコンパイルする必要があります。この手順は一度実行すればよいですが、ソースコードを変更した場合は再度コンパイルする必要があります。たとえば、ドライバのメジャーナンバーを変更した場合（詳しくは「3.7」節を参照）、この手順を再度行う必要があります。

「Makefile」を/moxa/mxserに見つけてください。次に実行してください

# make clean; make install

..note:

For Red Hat 9, Red Hat Enterprise Linux AS3/ES3/WS3 & Fedora Core1:
# make clean; make installsp1

For Red Hat Enterprise Linux AS4/ES4/WS4:
# make clean; make installsp2

ドライバファイル「mxser.o」およびユーティリティは、それぞれシステムディレクトリに適切にコンパイルされコピーされます。

————- MOXAドライバのロード——————–

3.4.3 MOXAドライバのロード¶

# modprobe mxser <argument>

モジュールドライバーをアクティブ化します。必要に応じて「lsmod」を実行して「mxser」がアクティブ化されているか確認してください。MOXAボードがISAボードの場合、<argument>が必要です。詳しくは「3.4.5」節をご参照ください。

————- ブート時にMOXAドライバをロード—————–

3.4.4 mxserドライバのロード¶

上記の説明では、「modprobe mxser」を実行してこのドライバをアクティブ化し、「rmmod mxser」を実行して削除することができます。

ただし、手動での操作を省くためにブート時の設定を行うのが望ましいです。ブート時の設定はrcファイルによって実現できます。この手順を簡略化するために、「moxa/mxser/driver」配下に「rc.mxser」ファイルを提供しています。

ISAボードを使用する場合は、「modprobe …」コマンドを変更して引数を追加する必要があります（詳しくは「3.4.5」節を参照）。rc.mxserを変更した後、手動で「/moxa/mxser/driver/rc.mxser」を実行して変更内容が正しいか確認してください。エラーが発生した場合は再度変更してください。変更が完了した場合は、以下の手順に進んでください。

rcファイルの設定に必要なコマンドを実行してください:

# cd /moxa/mxser/driver
# cp ./rc.mxser /etc/rc.d
# cd /etc/rc.d

「rc.serial」が存在するか確認してください。もし「rc.serial」が存在しない場合は、viで作成し、「chmod 755 rc.serial」を実行して権限を変更してください。

最後の行に「/etc/rc.d/rc.mxser」を追加してください。

再起動し、「lsmod」コマンドでmoxa.oが起動しているか確認してください。

3.4.5. CAPアドレスの指定¶

システム内にSmartio/Industio ISAボードを駆動する場合、mxser.oを起動する際に該当ボードのCAPアドレスを指定するパラメータを追加する必要があります。パラメータの形式は以下の通りです:

modprobe mxser ioaddr=0x???,0x???,0x???,0x???
                       |  |  |    |
                       |  |  |    +- 4th ISA board
                       |  |  +------ 3rd ISA board
                       |  +------------ 2nd ISA board
                       +-------------------1st ISA board

3.5 Linux kernel 2.4.xおよび2.6.x用の静的ドライバ設定¶

注意:

静的ドライバを使用するには、linux kernel sourceパッケージをインストールする必要があります。

3.5.1 カーネル内の組み込みドライバをバックアップ¶

# cd /usr/src/linux/drivers/char
# mv mxser.c mxser.c.old

For Red Hat 7.x user, you need to create link:
# cd /usr/src
# ln -s linux-2.4 linux

3.5.2 リンクの作成¶

# cd /usr/src/linux/drivers/char
# ln -s /moxa/mxser/driver/mxser.c mxser.c

3.5.3 ISAボード用のCAPアドレスリストを追加¶

PCIボードのユーザーはこのステップをスキップしてください。

モジュールモードでは、ISAボードのCAPアドレスはパラメータで指定されます。静的ドライバ設定では、ドライバのソースコード内でアドレスを割り当てなければなりません。ISAボードをインストールしない場合は、次のセクションに進んでください。ドライバソースコードを変更する手順は以下の通りです。

  1. 実行:

    # cd /moxa/mxser/driver
# vi mxser.c

  2. 以下の配列mxserBoardCAP[]を見つけます:

    static int mxserBoardCAP[] = {0x00, 0x00, 0x00, 0x00};

  3. viを使用してこの配列内のアドレスを変更してください。例えば、CAPアドレス0x280と0x180を持つ2つのISAボードを1番目と2番目に割り当てる場合、ソースコードを以下のように変更してください:

    static int mxserBoardCAP[] = {0x280, 0x180, 0x00, 0x00};

3.5.4 カーネル設定¶

カーネルを構成してください:

# cd /usr/src/linux
# make menuconfig

メニュー駆動のシステムに移動します。[Character devices][Non-standard serial port support]を選択し、「[*]」で組み込みドライバ（[M]ではなく）の「Moxa SmartIO support」ドライバを有効にしてください。その後、[Exit]を選択してこのプログラムを終了してください。

3.5.5 カーネルの再構築¶

以下の手順はLinuxカーネルの再構築に関する参考情報です。

適切な詳細については、Linuxドキュメントを参照してください:

  1. 以下のコマンドを実行してください:

    cd /usr/src/linux
make clean              # take a few minutes
make dep                # take a few minutes
make bzImage            # take probably 10-20 minutes
make install            # copy boot image to correct position

  1. ブートカーネル（vmlinuz）が正しい位置にあることを確認してください。

  2. 「lilo」ユーティリティを使用する場合、/etc/lilo.confの「image」項目がvmlinuzのパスを指定しているか確認してください。そうでない場合、誤った（または古い）ブートカーネルイメージ（vmlinuz）をロードしてしまいます。/etc/lilo.confを確認した後、「lilo」を実行してください。

「make bzImage」の結果がエラーとなった場合、Linux設定のセットアップに戻る必要があります。/usr/src/linuxディレクトリで「make menuconfig」を実行してください。

3.6 カスタム設定¶

このドライバーは既にデフォルトの設定を提供していますが、デバイス名やメジャーナンバーを変更することも可能です。これらのパラメータを変更する方法は以下の通りです。

  1. デバイス名の変更

    デフォルトの命名規則ではなく、他のデバイス名を使用したい場合は、シェルスクリプト「msmknod」内の内部コードを編集するだけで済みます。まず、「msmknod」をviで開き、「ttyM」と「cum」を含む各行を見つけ、ご希望のデバイス名に変更してください。「msmknod」は次回実行時に指定したデバイス名を生成します。

  2. メジャーナンバーの変更

    メジャーナンバー30および35がすでに使用されている場合、このドライバーで2つの空きメジャーナンバーを選択する必要があります。メジャーナンバーを変更するには以下の3つの手順があります。

3.6.1 空きメジャーナンバーの確認¶

/proc/devicesで、システム内に使用されているメジャーナンバーを確認できます。空きメジャーナンバーを2つ選択してください。例: 40, 45。

3.6.2 特殊ファイルの作成¶

/moxa/mxser/driver/msmknodを実行し、指定したメジャーナンバーで特殊ファイルを作成します。

3.6.3 新しいメジャーナンバーでドライバーを編集¶

viで/moxa/mxser/driver/mxser.cを開き、「MXSERMAJOR」を含む行を見つけ、以下のように内容を変更してください：

      #define         MXSERMAJOR              40
      #define         MXSERCUMAJOR            45

3.6.4 Run "make clean; make install" in /moxa/mxser/driver.

3.7 ドライバーのインストール確認¶

ドライバーがアクティブになった際の最新状態ログを確認するには、/var/log/messagesを参照してください。

4. ユーティリティ¶

このドライバーには3つのユーティリティが含まれています。msdiag、msmon、mstermです。これら3つのユーティリティはソースコード形式でリリースされており、実行可能なファイルにコンパイルして/usr/binにコピーする必要があります。

これらのユーティリティを使用する前に、ドライバーをロードしてください（3.4および3.5を参照）し、「msmknod」ユーティリティを実行したことを確認してください。

msdiag - 診断¶

このユーティリティは、ドライバーがシステム内で検出するモクサ スマートイオ/インダストイオ ボードの情報を表示する機能を提供します。

msmon - ポートモニタリング¶

このユーティリティは、すべてのモクサ ポートのアクティビティを素早く確認できるようにします。モニタリングを開始した時点からの各ポートの受信/送信（Rx/Tx）文字数を簡単に把握できます。

Rx/Tx通過量は、インターバルベース（例: 最近5秒）および平均ベース（モニタリング開始時からの累積）で報告されます。＜HOME＞キーですべてのポートのカウントをリセットし、＜+＞＜-＞（プラス/マイナス）キーで表示時間インターバルを変更できます。モニタリング中のポートを＜ENTER＞キーで選択すると、そのポートの通信パラメータ、信号状態、入出力キューを確認できます。

msterm - テルミナルエミュレーション¶

このユーティリティは、すべてのttyポート（特にMOXAポート）のデータ送受信機能を提供します。単純なアプリケーションのテストに非常に役立ちます。たとえば、ポートに接続されたモデムにATコマンドを送信するか、ログイン目的のターミナルとして使用できます。注意点として、これはフルスクリーン操作を処理しない単純なターミナルエミュレーションです。

5. Setserial¶

サポートされているSetserialパラメータは以下の通りです。

uart

UARTタイプを設定（16450–>FIFOを無効化、16550A–>FIFOを有効化）

close_delay

ポートを閉じる際、DTRが低電圧で保持される時間（1/100秒単位）を設定します。

closing_wait

ポートを閉じる際、受信機を無効化する前にデータが完全に排泄されるのを待つ時間（1/100秒単位）を設定します。

spd_hi

アプリケーションが38.4kbを要求した場合、57.6kbを使用します。

spd_vhi

アプリケーションが38.4kbを要求した場合、115.2kbを使用します。

spd_shi

アプリケーションが38.4kbを要求した場合、230.4kbを使用します。

spd_warp

アプリケーションが38.4kbを要求した場合、460.8kbを使用します。

spd_normal

アプリケーションが38.4kbを要求した場合、38.4kbを使用します。

spd_cust

アプリケーションが38.4kbを要求した場合、カスタムディビジョンを使用して速度を設定します。

除数

このオプションでカスタムディビジョンを設定します。

baud_base

このオプションでベースボーダー速度を設定します。

6. トラブルシューティング¶

ブートタイムのエラーメッセージと解決策はできるだけ明確に記載されています。すべての解決策が失敗した場合は、技術サポートチームにご連絡ください。

エラーメッセージ:

4枚以上のMOXA Smartio/Industioファミリーボードが検出されました。5番目以降のボードは無視されます。

解決策: この問題を回避するため、5番目以降のボードを差し抜いてください。MOXAドライバは最大4枚のボードをサポートしています。

エラーメッセージ:

Request_irq失敗、IRQ(?)が他のデバイスと競合している可能性があります。

解決策: 他のPCIまたはISAデバイスが割り込みを占有しています。原因が不明な場合は、/proc/interruptsを確認して空き割り込みを検索し、MOXAボードに別の空き割り込みを設定してください。

エラーメッセージ:

ボード #: C1xxシリーズ（CAP=xxx）の割り込み番号が無効です。

解決策: 同一マルチポートボード内のポートは同じ割り込み番号を共有します。MOXAボードごとに1つの割り込み番号（ゼロ以外）を設定してください。

エラーメッセージ:

MOXA ISAボード（CAP=xxx）に割り込みベクターが設定されていません。

解決策: MOXA ISAボードには割り込みベクターが必要です。ユーザーマニュアルの「ハードウェアインストール」章を参照し、割り込みベクターを設定してください。

エラーメッセージ:

MOXA Smartio/Industioファミリードライバのインストールに失敗しました！

解決策: MOXAドライバのロードに失敗しました。主装置番号が他のデバイスと競合している可能性があります。前のセクション3.7を参照し、MOXAドライバに空き主装置番号を設定してください。

エラーメッセージ:

MOXA Smartio/Industioファミリーコールアウトドライバーのインストールに失敗しました！

解決策：Moxaコールアウトドライバーのロードに失敗しました。コールアウトデバイスのメジャーナンバーが他のデバイスと競合している可能性があります。前のセクション3.7を参照し、Moxaドライバー用の空きコールアウトデバイスメジャーナンバーを変更してください。
