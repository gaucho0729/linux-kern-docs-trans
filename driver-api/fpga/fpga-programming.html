FPGAプログラミング用のカーネル内API¶

概要¶

FPGAプログラミング用のカーネル内APIは、FPGAマネージャー、ブリッジ、リージョンからなるAPIの組み合わせです。FPGAプログラミングをトリガーする実際の関数は fpga_region_program_fpga().

fpga_region_program_fpga() FPGAマネージャーおよびブリッジが提供する機能を使用します。実行内容は以下の通りです

  • リージョンのミューテックスをロックします

  • リージョンのFPGAマネージャーのミューテックスをロックします

  • メソッドが指定されている場合、FPGAブリッジの一覧を構築します

  • ブリッジを無効化します

  • 渡された情報を使ってFPGAをプログラミングします fpga_region->info.

  • ブリッジを再有効化します

  • ロックを解放します

以下の struct fpga_image_info プログラミングするFPGAイメージを指定します。これは fpga_image_info_alloc() と解放されます fpga_image_info_free()

リージョンを使用してFPGAをプログラミングする方法¶

FPGAリージョンドライバがプローブされた際、FPGAマネージャードライバへのポインタが渡され、どのマネージャーを使用するかを知るようになります。リージョンは、プログラミング中に制御するブリッジの一覧を持つか、またはその一覧を生成する関数へのポインタを持っています。以下は次のステップのサンプルコードです:

#include <linux/fpga/fpga-mgr.h>
#include <linux/fpga/fpga-region.h>

struct fpga_image_info *info;
int ret;

/*
 * First, alloc the struct with information about the FPGA image to
 * program.
 */
info = fpga_image_info_alloc(dev);
if (!info)
        return -ENOMEM;

/* Set flags as needed, such as: */
info->flags = FPGA_MGR_PARTIAL_RECONFIG;

/*
 * Indicate where the FPGA image is. This is pseudo-code; you're
 * going to use one of these three.
 */
if (image is in a scatter gather table) {

        info->sgt = [your scatter gather table]

} else if (image is in a buffer) {

        info->buf = [your image buffer]
        info->count = [image buffer size]

} else if (image is in a firmware file) {

        info->firmware_name = devm_kstrdup(dev, firmware_name,
                                           GFP_KERNEL);

}

/* Add info to region and do the programming */
region->info = info;
ret = fpga_region_program_fpga(region);

/* Deallocate the image info if you're done with it */
region->info = NULL;
fpga_image_info_free(info);

if (ret)
        return ret;

/* Now enumerate whatever hardware has appeared in the FPGA. */

FPGAプログラミング用API¶

  • fpga_region_program_fpga() — FPGAをプログラミングする

  • fpga_image_info() — プログラミングするFPGAイメージを指定する

  • fpga_image_info_alloc() — FPGAイメージ情報構造体を割り当てる

  • fpga_image_info_free() — FPGAイメージ情報構造体を解放する

int fpga_region_program_fpga(struct fpga_region *領域)¶

FPGAをプログラミングする

パラメータ

struct fpga_region *region

FPGAリージョン

説明

fpgaイメージ情報（region->info）を使用してFPGAをプログラミングします。リージョンにget_bridges関数がある場合、プログラミングが成功した場合はブリッジの排他的な参照を保持します。これは、呼び出し元が安全と判断するまでリージョンの再プログラミングを防ぐためのものです。呼び出し元は、リージョンの再プログラミングを試行する前に、 fpga_bridges_put() を呼び出す必要があります。

成功時は0を、負のエラーコードを返します。

FPGAマネージャーフラグ

以下のフラグが使用されます fpga_image_info->flags フィールド

FPGA_MGR_PARTIAL_RECONFIG: サポートされている場合、部分的なリコンフィギュレーションを実行する

FPGA_MGR_EXTERNAL_CONFIG: Linuxの起動前にFPGAがすでに設定済み

FPGA_MGR_ENCRYPTED_BITSTREAM: ビットストリームが暗号化されていることを示す

FPGA_MGR_BITSTREAM_LSB_FIRST: SPIビットストリームビット順序はLSBファースト

FPGA_MGR_COMPRESSED_BITSTREAM: FPGAビットストリームは圧縮されている

struct fpga_image_info¶

FPGAイメージ固有の情報

定義

struct fpga_image_info {
  u32 flags;
  u32 enable_timeout_us;
  u32 disable_timeout_us;
  u32 config_complete_timeout_us;
  char *firmware_name;
  struct sg_table *sgt;
  const char *buf;
  size_t count;
  int region_id;
  struct device *dev;
#ifdef CONFIG_OF;
  struct device_node *overlay;
#endif;
};

メンバ

flags

上記の論理フラグ

enable_timeout_us

ブリッジを通じたトラフィックを有効にする最大時間（マイクロ秒）

disable_timeout_us

ブリッジを通じたトラフィックを無効にする最大時間（マイクロ秒）

config_complete_timeout_us

write_complete操作でFPGAが運用状態に移行するまでの最大時間

firmware_name

FPGAイメージファームウェアファイルの名前

sgt

FPGAイメージを含むスキャッタ/ガーナーテーブル

buf

FPGAイメージを含む連続バッファ

count

バッファのサイズ

region_id

ターゲット領域のID

dev

このデバイスを所有するデバイス

overlay

デバイスツリー・オーバーレイ
