FPGA Manager¶

概要¶

FPGAマネージャーのコアは、イメージでFPGAをプログラミングするための関数セットをエクスポートします。このAPIはメーカーに依存しません。すべてのメーカー固有の仕様は、低レベルドライバに隠蔽されており、このドライバはコアにオペレーションのセットを登録します。FPGAイメージデータ自体はメーカー固有ですが、我々の目的では単なるバイナリデータと見なします。FPGAマネージャーのコアはこれを解析しません。

プログラミングするFPGAイメージはスキャッターガatherリスト、単一の連続バッファ、またはファームウェアファイルのいずれかで提供できます。カーネルメモリの連続割り当てを避けるべきであるため、ユーザーは可能であればスキャッターガatherリストを使用することを推奨します。

イメージのプログラミングに関する詳細は構造体（struct fpga_image_info）に記述されています。この構造体には、FPGAイメージへのポインタや、イメージ固有の詳細（フルリコンフィギュレーション用か部分リコンフィギュレーション用かなど）などのパラメータが含まれます。

新しいFPGAデバイスをサポートする方法¶

もう一つのFPGAマネージャーを追加するには、特定のオペレーションを実装するドライバを書きます。プローブ関数は、 fpga_mgr_register()、例えば：

static const struct fpga_manager_ops socfpga_fpga_ops = {
        .write_init = socfpga_fpga_ops_configure_init,
        .write = socfpga_fpga_ops_configure_write,
        .write_complete = socfpga_fpga_ops_configure_complete,
        .state = socfpga_fpga_ops_state,
};

static int socfpga_fpga_probe(struct platform_device *pdev)
{
        struct device *dev = &pdev->dev;
        struct socfpga_fpga_priv *priv;
        struct fpga_manager *mgr;
        int ret;

        priv = devm_kzalloc(dev, sizeof(*priv), GFP_KERNEL);
        if (!priv)
                return -ENOMEM;

        /*
         * do ioremaps, get interrupts, etc. and save
         * them in priv
         */

        mgr = devm_fpga_mgr_create(dev, "Altera SOCFPGA FPGA Manager",
                                   &socfpga_fpga_ops, priv);
        if (!mgr)
                return -ENOMEM;

        platform_set_drvdata(pdev, mgr);

        return fpga_mgr_register(mgr);
}

static int socfpga_fpga_remove(struct platform_device *pdev)
{
        struct fpga_manager *mgr = platform_get_drvdata(pdev);

        fpga_mgr_unregister(mgr);

        return 0;
}

これらのオペレーションは、この特定のFPGAのプログラミングシーケンスに必要なデバイス固有のレジスタ書き込みを実装します。成功時は0を返し、エラー時は負のエラーコードを返します。

プログラミングシーケンスは以下の通りです：

  1. .write_init

  2. .write または .write_sg（1回または複数回呼び出される可能性あり）

  3. .write_complete

.write_init関数はFPGAをイメージデータの受信準備にします。.write_initに渡されるバッファは最大で.initial_header_sizeバイトの長さです。全体のビットストリームが即座に利用できない場合、コアコードは少なくともこの量をバッファリングした後で開始します。

.write関数はバッファをFPGAに書き込みます。このバッファはFPGAイメージ全体を含む場合もあれば、イメージの小さなチャンクを含む場合もあります。後者の場合、この関数は連続するチャンクごとに複数回呼び出されます。このインターフェースはPIOを用いるドライバに適しています。

.write_sgバージョンは.writeと同様の動作ですが、入力はsg_tableスキャッターガatherリストになります。このインターフェースはDMAを用いるドライバに適しています。

.write_complete関数はすべてのイメージが書き込まれた後、FPGAを運用モードに移行するために呼び出されます。

オペレーションには.state関数が含まれており、これはFPGAの現在の状態を判定し、型 enum fpga_mgr_statesのコードを返します。これにより状態の変化は起こりません。

新しいFPGAマネージャードライバを実装するためのAPI¶

  • fpga_mgr_states — fpga_manager->状態.

  • struct fpga_manager — FPGAマネージャー構造体

  • struct fpga_manager_ops — 低レベルFPGAマネージャードライバオペレーション

  • devm_fpga_mgr_create() — マネージャ構造体を割り当ておよび初期化

  • fpga_mgr_register() — FPGAマネージャを登録

  • fpga_mgr_unregister() — FPGAマネージャをアンレジスト

enum fpga_mgr_states¶

fpgaフレームワークの状態

定数

FPGA_MGR_STATE_UNKNOWN

状態を特定できません

FPGA_MGR_STATE_POWER_OFF

FPGAの電源がオフ

FPGA_MGR_STATE_POWER_UP

FPGAが電源がオンと報告

FPGA_MGR_STATE_RESET

FPGAがリセット状態

FPGA_MGR_STATE_FIRMWARE_REQ

ファームウェアリクエスト中

FPGA_MGR_STATE_FIRMWARE_REQ_ERR

ファームウェアリクエスト失敗

FPGA_MGR_STATE_WRITE_INIT

FPGAをプログラミング準備

FPGA_MGR_STATE_WRITE_INIT_ERR

WRITE_INITステージでのエラー

FPGA_MGR_STATE_WRITE

イメージをFPGAに書き込み中

FPGA_MGR_STATE_WRITE_ERR

FPGA書き込み中のエラー

FPGA_MGR_STATE_WRITE_COMPLETE

プログラミング後のステップ実行中

FPGA_MGR_STATE_WRITE_COMPLETE_ERR

WRITE_COMPLETEステージでのエラー

FPGA_MGR_STATE_OPERATING

FPGAがプログラミング完了し運用中

struct fpga_manager¶

FPGAマネージャ構造体

定義

struct fpga_manager {
  const char *name;
  struct device dev;
  struct mutex ref_mutex;
  enum fpga_mgr_states state;
  struct fpga_compat_id *compat_id;
  const struct fpga_manager_ops *mops;
  void *priv;
};

メンバ

name

低レベルFPGAマネージャの名前

dev

FPGAマネージャデバイス

ref_mutex

FPGAマネージャへの参照を1つだけ許可

state

FPGAマネージャの状態

compat_id

互換性確認用のFPGAマネージャID

mops

FPGAマネージャ操作構造体へのポインタ

priv

低レベルドライバのプライベートデータ

struct fpga_manager_ops¶

低レベルFPGAマネージャドライバ用の操作

定義

struct fpga_manager_ops {
  size_t initial_header_size;
  enum fpga_mgr_states (*state)(struct fpga_manager *mgr);
  u64 (*status)(struct fpga_manager *mgr);
  int (*write_init)(struct fpga_manager *mgr,struct fpga_image_info *info, const char *buf, size_t count);
  int (*write)(struct fpga_manager *mgr, const char *buf, size_t count);
  int (*write_sg)(struct fpga_manager *mgr, struct sg_table *sgt);
  int (*write_complete)(struct fpga_manager *mgr, struct fpga_image_info *info);
  void (*fpga_remove)(struct fpga_manager *mgr);
  const struct attribute_group **groups;
};

メンバ

initial_header_size

write_initに渡すべき最大バイト数

state

FPGAの状態を表すenum値を返す

status

FPGAの状態を返す（再構成エラー コードを含む）

write_init

FPGAを構成データの受信に準備

write

FPGAにcountバイトの構成データを書き込む

write_sg

FPGAに構成データのスキャッターリストを書き込む

write_complete

書き込みが完了後にFPGAを運用状態に設定

fpga_remove

オプション: ドライバの除去中にFPGAを特定の状態に設定

groups

オプションの属性グループ

説明

fpga_manager_opsは特定のFPGAマネージャドライバで実装される低レベル関数です。オプションの関数は呼び出される前にNULLかどうかテストされるため、省略しても問題ありません。

struct fpga_manager *devm_fpga_mgr_create(struct デバイス *dev, const char *名前, const struct fpga_manager_ops *mops, void *priv)¶

マネージド FPGA マネージャ構造体を生成および初期化

パラメータ

struct device *dev

pdevからFPGAマネージャデバイス

const char *name

FPGAマネージャ名

const struct fpga_manager_ops *mops

FPGAマネージャ操作構造体へのポインタ

void *priv

FPGAマネージャプライベートデータ

説明

この関数は、FPGAマネージャドライバのprobe関数で使用することを意図しています。マネージャドライバがmanager structを生成した後 devm_fpga_mgr_create()、それを fpga_mgr_register()で登録する必要があります。マネージャドライバのremove関数では fpga_mgr_unregister()を呼び出す必要があります。この関数で割り当てられたmanager structは、ドライバの解除時に自動的に解放されます。これは、 fpga_mgr_register()、構造体は依然としてクリーンアップされます

戻り値

ポインタ struct fpga_manager またはNULL
