はじめに¶

プロトコル vs バス¶

かつては、Small Computer Systems Interface（SCSI）は、ディスクドライブ、テープドライブ、モデム、プリンタ、スキャナ、光学ドライブ、テスト機器、医療機器など幅広い外設機器をホストコンピュータに接続するための並列I/Oバスとデータプロトコルを定義していました。

古い並列（ファスト/ワイド/ウルトラ）SCSIバスはほぼ使用されなくなりましたが、SCSIコマンドセットはUSB、SATA、SAS、ファイバー・チャネル、ファイアワイヤ、ATAPIデバイスに接続されたストレージデバイスの通信に今なお幅広く使用されています。

以下の SCSIプロトコル ビッグエンディアンのピアツーピアパケットベースのプロトコルです。SCSIコマンドは6、10、12、または16バイトの長さで、しばしば関連するデータペイロードが続きます。

SCSIコマンドはほぼどの種類のバスでも転送可能で、USB、SATA、SAS、ファイバー・チャネル、ファイアワイヤ、ATAPIデバイスに接続されたストレージデバイスのデフォルトプロトコルです。SCSIパケットはインフィニバンドでもよくやり取りされます。 I2O, TCP/IP (iSCSI), すら パラレルポート.

Linux SCSIサブシステムの設計¶

SCSIサブシステムは上層、中間層、下層の3層設計を採用しています。SCSIサブシステムに関与するすべての操作（ディスクからセクタを読み取るなど）は、3つのレベルそれぞれで1つのドライバを使用します：上層ドライバ、下層ドライバ、SCSI中間層。

SCSI上層はユーザー空間とカーネル間のインターフェースを提供し、I/Oおよびioctl()のためのブロックデバイスとキャラクターデバイスノードを提供します。SCSI下層には特定のハードウェアデバイス用のドライバが含まれます。

中間層はネットワークルーティング層（例：IPv4スタック）に類似しており、上層の/devノードと下層の対応するデバイス間でパケットベースのデータプロトコルをルーティングします。コマンドキューの管理、エラー処理、電源管理機能を提供し、ioctl()リクエストに応答します。

void fc_remote_port_delete(struct fc_rport *rport)¶

FCトランスポートにリモートポートがもはや存在しないことを通知します。

パラメータ

struct fc_rport *rport

もはや存在しないリモートポート

説明

LLDDは、リモートポートがトポロジに含まれなくなったことをトランスポートに通知するためにこのルーチンを呼び出します。注意：ポートがトポロジから外れても、fc_hostで表示されるリモートポートとして残る場合があります。これは2つの条件で行われます：

  1. ポートがSCSIターゲットだった場合、その削除を「ブロッキング」して遅延します。これにより、ポートが一時的に消失しても、SCSIデバイスツリーに影響を与えることなく再出現できます。ブロッキング期間中はポートは依然として存在します。

  2. ポートがSCSIターゲットで、予想以上に長時間消失した場合、ポートとそれに接続されたSCSIデバイスツリーを削除します。ただし、ポートが再び存在する場合に備えて、そのポートに割り当てられたターゲットIDは半永続的に維持したいです。ポート構造体は（情報は極めて簡略化されているものの）残り、ターゲットIDバインディングも維持されます。

リモートポートがFCPターゲットでない場合、完全に破壊され、割り当てられることもなくなります。これはfc_remote_portクラスのデバイスも含めてです。

リモートポートがFCP Targetである場合、ポートは一時的にブロックされた状態に置かれます。Linuxデバイスドライバ（LLDD）の観点では、rportはもはや存在しなくなります。SCSI midlayerの観点では、SCSIターゲットは存在しますが、その上のすべてのsdevはさらにI/Oがブロックされます。以下が期待されます。

リモートポートがdev_loss_tmoタイムアウト内に返信しない場合（LLDDが fc_remote_port_add()を呼び出すことで信号を送信）、SCSIターゲットは削除され、すべての待機中のI/Oが終了し、そのSCSIデバイスが削除されます。ポート構造体はNot Presentとマークされ、一部がクリアされ、リモートポートがSCSIターゲットIDバインディングに関連して再出現した場合にそのポートを識別するための情報のみが残ります。有効なバインディングが存在する限りポートは維持されます（例：ユーザーがバインディングタイプを変更するか、SCSIホストをロード解除するまで）。

リモートポートがdev_loss_tmo値内に返信し、ターゲットIDバインディングタイプに一致した場合、ポート構造体は再利用されます。もはやSCSIターゲットでなくなった場合、ターゲットは破壊されます。SCSIターゲットのままの場合は、ターゲットがアンブロックされ（I/O再開が許可される）、スキャンが実行されすべてのLUNが検出されるようにします。

通常のプロセスコンテキストからのみ呼び出されます。割り込みから呼び出すことはできません。

シリアルアタッチメントSCSI (SAS) トランスポートクラス¶

ファイル drivers/scsi/scsi_transport_sas.c は、シリアルアタッチメントSCSI（SATAの変種で大規模なハイエンドシステム向け）のトランスポート属性を定義します。

SASトランスポートクラスは、SAS HBAの処理に共通のコードを含み、ドライバーモデルにおけるSASトポロジーの近似表現、およびこれらのトポロジーと管理インターフェースをユーザー空間に公開するためのsysfs属性を提供します。

基本的なSCSIコアオブジェクトに加えて、このトランスポートクラスは2つの追加の中間オブジェクトを導入します：struct sas_phy で表される SAS PHY は SAS HBA または Expander 上の「送出」PHY を表し、struct sas_rphy で表される SAS remote PHY は SAS Expander またはエンドデバイス上の「受信」PHY を表します。注意点として、これは純粋なソフトウェアの概念であり、PHY と remote PHY のハードウェアは全く同じです。

このコードでは SAS ポートという概念は存在しません。ユーザーは port_identifier 属性をもとに、どの PHY がワイドポートを形成するかを確認できます。これはポート内のすべての PHY で同じ値になります。

ホストバスアダプターートランスポートタイプ¶

多くの現代のデバイスコントローラーは、さまざまな種類の物理的な接続を通じてデバイスと通信するために、SCSIコマンドセットをプロトコルとして使用しています。

SCSI言語では、SCSIコマンドを運ぶことができるバスは「トランスポート」と呼ばれ、そのようなバスに接続するコントローラーは「ホストバスアダプター」（HBA）と呼ばれます。

デバッグトランスポート¶

drivers/scsi/scsi_debug.cというファイルは、可変数のディスク（またはディスクのようなデバイス）が接続されたホストアダプタをシミュレートします（共有RAMを共有）。異常な状況が見つかった場合、カーネルをpanicさせながら、ブロックが混ざらないように多数のチェックを行います。

より現実的になるため、シミュレートされたデバイスはSASディスクのトランスポート属性を持ちます。

ドキュメンテーションについては http://sg.danny.cz/sg/sdebug26.html
