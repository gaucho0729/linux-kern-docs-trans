高速同期シリアルインターフェース (HSI)¶

はじめに¶

高速同期インターフェース (HSI) は、アプリケーションプロセッサとベースバンドチップセット間のダイレベル接続を最適化したフルダブルスレッド、低遅延プロトコルです。このインターフェースは2003年にMIPIアライアンスによって規定され、それ以降複数のベンダーによって実装されています。

HSIインターフェースは、複数のチャネル（通常は8チャネル）を介したフルダブルスレッド通信をサポートし、最大200 Mbit/sの速度に達成可能です。

シリアルプロトコルはDATAとFLAGという2つの信号を組み合わせたデータおよびクロック信号と、フロー制御用の追加のREADY信号を使用します。また、スタンバイモードからチップを再起動するためのWAKE信号も使用可能です。これらの信号は、アプリケーションダイからセルラー・ダイへの信号にはAC、逆方向にはCAという接頭辞が付与されます。

+------------+                                 +---------------+
|  Cellular  |                                 |  Application  |
|    Die     |                                 |      Die      |
|            | - - - - - - CAWAKE - - - - - - >|               |
|           T|------------ CADATA ------------>|R              |
|           X|------------ CAFLAG ------------>|X              |
|            |<----------- ACREADY ------------|               |
|            |                                 |               |
|            |                                 |               |
|            |< - - - - -  ACWAKE - - - - - - -|               |
|           R|<----------- ACDATA -------------|T              |
|           X|<----------- ACFLAG -------------|X              |
|            |------------ CAREADY ----------->|               |
|            |                                 |               |
|            |                                 |               |
+------------+                                 +---------------+

LinuxにおけるHSIサブシステム¶

Linuxカーネルでは、HSIデバイスにhsiサブシステムを使用するように設計されています。hsiサブシステムは、HSIコントローラーのドライバを含み、マルチポートコントローラーのサポートも提供し、HSIポートの使用に必要な汎用APIを提供します。

また、HSIクライアントドライバも含まれており、これらは汎用APIを活用してHSIインターフェースで使用されるプロトコルを実装します。これらのクライアントドライバは、任意の数のチャネルを使用可能です。

hsi-charデバイス¶

各ポートは自動的に汎用クライアントドライバであるhsi_charを登録し、ユーザースペースでHSIポートを表すキャラクターデバイスを提供します。これはユーザースペースからHSIを介して通信するための手段です。ユーザースペースは次のioctlコマンドを使用してhsi_charデバイスを設定できます：

HSC_RESET

HSIポートをフラッシュ

HSC_SET_PM

クライアントの有効化または無効化

HSC_SEND_BREAK

ブレイク送信

HSC_SET_RX

RX設定の設定

HSC_GET_RX

RX設定の取得

HSC_SET_TX

TX設定の設定

HSC_GET_TX

TX設定の取得

struct hsi_channel¶

hsiクライアントが使用するチャネルリソース

定義

struct hsi_channel {
  unsigned int    id;
  const char      *name;
};

メンバ

id

チャネル番号

name

チャネル名

struct hsi_config¶

RX/TX HSIモジュールの設定

定義

struct hsi_config {
  unsigned int            mode;
  struct hsi_channel      *channels;
  unsigned int            num_channels;
  unsigned int            num_hw_channels;
  unsigned int            speed;
  union {
    unsigned int    flow;
    unsigned int    arb_mode;
  };
};

メンバ

mode

ビット送信モード（STREAMまたはFRAME）

channels

クライアントが使用するチャネルリソース

num_channels

チャネルリソースの数

num_hw_channels

トランシーバーが設定されているチャネル数 [1..16]

speed

最大ビット送信速度 (Kbit/s)

{unnamed_union}

匿名

flow

RXフロー種別（SYNCHRONIZEDまたはPIPELINE）

arb_mode

TXフレームの仲裁モード（ラウンドロビン、優先度）

struct hsi_msg¶

HSIメッセージ記述子

定義

struct hsi_msg {
  struct list_head        link;
  struct hsi_client       *cl;
  struct sg_table         sgt;
  void *context;
  void (*complete)(struct hsi_msg *msg);
  void (*destructor)(struct hsi_msg *msg);
  int status;
  unsigned int            actual_len;
  unsigned int            channel;
  unsigned int            ttype:1;
  unsigned int            break_frame:1;
};

メンバ

link

現在の記述子所有者が自由に使用可能

cl

転送を実行するHSIデバイスクライアント

sgt

スキャッタリスト配列の先頭

context

転送に関連するクライアントコンテキストデータ

complete

転送完了時のコールバック

destructor

フラッシュ時にリソースを解放するデストラクタ

status

完了時の転送状態

actual_len

完了時の実際に転送されたデータ長

channel

メッセージをTX/RXするチャネル

ttype

転送タイプ（設定されている場合はTX、それ以外はRX）

break_frame

trueの場合HSIがブレイクフレームを送受信。リクエストではデータバッファは無視される

HSIポートデバイス

定義

struct hsi_port {
  struct device                   device;
  struct hsi_config               tx_cfg;
  struct hsi_config               rx_cfg;
  unsigned int                    num;
  unsigned int                    shared:1;
  int claimed;
  struct mutex                    lock;
  int (*async)(struct hsi_msg *msg);
  int (*setup)(struct hsi_client *cl);
  int (*flush)(struct hsi_client *cl);
  int (*start_tx)(struct hsi_client *cl);
  int (*stop_tx)(struct hsi_client *cl);
  int (*release)(struct hsi_client *cl);
  struct blocking_notifier_head   n_head;
};

メンバ

device

デバイスのドライバーモデル表現

tx_cfg

現在のTXパス設定

rx_cfg

現在のRXパス設定

num

ポート番号

shared

ポートが複数のクライアントで共有可能であることを示すフラグ

claimed

ポートを主張しているクライアントの参照カウント

lock

ポート主張をシリアル化する

async

非同期転送コールバック

setup

HSIクライアント設定を設定するコールバック

flush

ハードウェア状態をクリーンアップし、すべての待機中の転送を破棄するコールバック

start_tx

クライアントがデータをTXしたいことを通知するコールバック

stop_tx

クライアントがもはやデータをTXしないことを通知するコールバック

release

クライアントがもはやポートを使用しないことを通知するコールバック

n_head

クライアントにポートイベントを通知するノティファイチェーン

int hsi_async(struct hsi_client *cl, struct hsi_msg *msg)¶

HSI転送をコントローラーに送信します。

パラメータ

struct hsi_client *cl

転送を送信するHSIクライアント

struct hsi_msg *msg

コントローラーに渡されるHSI転送

説明

HSIメッセージは事前に channel、ttype、complete、destructor フィールドを設定しておく必要があります。nents > 0 の場合、クライアントは scatterlists をバッファへの書き込みまたは読み取りを指すように初期化する必要があります。

HSIコントローラーはクライアントから事前に割り当てられたバッファに依存し、自身でバッファを割り当てません。

HSIメッセージの転送が完了した後、HSIコントローラーはステータスと actual_len フィールドを更新した HSIメッセージとともに complete コールバックを呼び出します。complete コールバックは hsi_async から戻る前に呼び出されることがあります。

失敗時は -errno を返し、成功時は 0 を返します。

int hsi_event(struct hsi_port *port, unsigned long イベント)¶

ポートイベントをクライアントに通知する

パラメータ

struct hsi_port *port

イベントが発生したポート

unsigned long event

イベントの種類

説明

クライアントはウェイクラインの動作について気にする必要はありません。ただし、HSIハードウェアプロトコルにおけるレースコンディションのため、ウェイクラインの変化を通知する必要があります。これにより、ワークアラウンドの実装が可能になります。

イベント: HSI_EVENT_START_RX - インカムウェイクラインがハイ HSI_EVENT_STOP_RX - インカムウェイクラインがダウン

エラー時に-errnoを返し、成功時は0を返します。

int hsi_get_channel_id_by_name(struct hsi_client *cl, char *名前)¶
