エラー検出と訂正 (EDAC) デバイス¶

EDACサブシステムで使用される主要な概念¶

いくつかの注意が必要なことが明らかでないことがあります。たとえば ソケット、*ソケットセット, バンク, 行, チップセレクト行, チャネル, など…

これらの用語は、人々が思うほど意味しないことがあり（信じられない！）、議論の共通の基盤を作成するため、用語とその定義が確立されます。

  • メモリデバイス

メモリスティックに搭載された個々のDRAMチップです。これらのデバイスは通常、4ビットおよび8ビット（x4、x8）を出力します。複数のチップを並列にグループ化することで、メモリコントローラーが期待するビット数が得られます。通常は72ビットで、これにより64ビットのデータに加えて8ビットのECCデータを提供します。

  • メモリスティック

複数のメモリデバイスを並列で集約したプリント基板です。通常、これは過剰なエラーが発生した場合に交換されるフィールド交換ユニット（FRU）であり、最も一般的にはDIMM（Dual Inline Memory Module）と呼ばれます。

  • メモリソケット

マザーボード上の物理的なコネクタで、1つのメモリスティックを受容します。いくつかのデータシートでは「スロット」とも呼ばれます。

  • チャネル

メモリコントローラーのチャネルは、複数のDIMMと通信を担当します。各チャネルは独立した制御（コマンド）とデータバスを持ち、独立して使用するか、他のチャネルとグループ化して使用できます。

  • ブランチ

これは通常、フルバッファードDIMMメモリコントローラーの最高階層です。通常、このブランチには2つのチャネルが含まれます。同じブランチにある2つのチャネルは、単一モードまたはロックステップモードで使用できます。ロックステップモードが有効になると、キャッシュラインが倍になりますが、一般的にパフォーマンスのペナルティが生じます。また、エラーが発生した際に単一のメモリスティックを指すことはできません。なぜなら、エラー訂正コードは1つのDIMMではなく2つのDIMMを使用して計算されるからです。そのため、単一モードよりも多くのエラーを訂正できます。

  • シングルチャネル

メモリコントローラーがアクセスするデータは1つのDIMMに含まれます。たとえば、データが64ビット幅の場合、データはCPUに64ビットの並列アクセスで流されます。通常、SDR、DDR、DDR2、DDR3メモリで使用されます。FB-DIMMとRAMBUSはチャネルに関する異なる概念を使用するため、この概念は適用されません。

  • ダブルチャネル

メモリコントローラーがアクセスするデータサイズは、2つのDIMMにインタレースされ、同時にアクセスされます。たとえば、DIMMが64ビット幅（ECCを含むと72ビット）の場合、データはCPUに128ビットの並列アクセスで流されます。

  • チップセレクト行

これは、DRAMレーベルを選択してアクセスするためのDRAMレーベルの名前です。シングルチャネルでは64ビット、デュアルチャネルでは128ビットのチップセレクト行が一般的です。一部のDIMMタイプではメモリバッファが存在するため、メモリコントローラーから直接アクセスを隠すことができるため、メモリコントローラーでは見えない可能性があります。

  • シングルレーベルスタック

シングルレーベルスタックは1つのチップセレクト行を持つメモリです。マザーボードは通常、メモリスタックに2つのチップセレクトピンを駆動します。シングルレーベルスタックはこれらの行のうち1つしか使用しません。もう1つは未使用になります。

  • ダブルレーベルスタック

ダブルレーベルスタックは、異なるメモリデバイスのセットをアクセスする2つのチップセレクト行を持ちます。2つの行は同時にアクセスできません。

  • ダブルサイドスタック

非推奨の用語, 詳細は ダブルレーベルスタック.

ダブルサイドスタックは、異なるメモリデバイスのセットをアクセスする2つのチップセレクト行を持ちます。2つの行は同時にアクセスできません。「ダブルサイド」はメモリスタックの両サイドにデバイスが搭載されているかどうかに関係なく、独立した用語です。

  • ソケットセット

単一のメモリアクセスに必要なすべてのメモリスタック、またはチップセレクト行でカバーされるすべてのメモリスタック。1つのソケットセットは2つのチップセレクト行を持ち、ダブルサイドスタックが使用される場合、これらはチップセレクト行を占有します。

  • バンク

チップセレクト行とソケットセットを区別する必要がある場合、この用語は曖昧であるため避けられています。

メモリコントローラー¶

EDACコアの大部分はメモリコントローラーのエラー検出に焦点を当てています。The edac_mc_alloc()。これは内部的にstruct mem_ctl_info を用いてメモリコントローラーを記述し、EDACドライバにとっては不透明な構造体です。EDACコアだけがこの構造体にアクセスできます。

enum 検出されたエラーの種類¶

検出されたエラーの種類

定数

HW_EVENT_ERR_CORRECTED

訂正可能エラー - ECCで訂正されたエラーが検出されたことを示します

HW_EVENT_ERR_UNCORRECTED

訂正不可能エラー - ECCで訂正できないエラーですが、致命的ではありません（未使用のメモリ領域にあるか、メモリコントローラーが操作を再試行することで回復できるなど）

HW_EVENT_ERR_DEFERRED

遅延エラー - 訂正不可能なエラーで、緊急性がありません。これはハードウェアのデータ汚染により、システムが汚染されたデータを消費するまで動作を継続できる場合があります。予防的措置も取られることがあります（ページのオフライン化など）

HW_EVENT_ERR_FATAL

致命的なエラー - 回復不能なエラーです。

HW_EVENT_ERR_INFO

情報 - CPER仕様ではエラーの4番目のタイプとして情報ログが定義されています。

EDACブロック¶

EDACサブシステムは、ハードウェアの他の部分でのエラーを報告するための汎用的なメカニズムを提供します edac_device_alloc_ctl_info() function.

構造体 edac_dev_sysfs_block_attribute, edac_device_block, edac_device_instance および edac_device_ctl_info sysfs上に汎用的または抽象的な'edac_device'表現を提供します

この構造体群と、それらのAPIを実装するコードは、標準的なメモリやPCIでないEDACタイプのデバイス（例：

  • CPUキャッシュ（L1およびL2）

  • DMAエンジン

  • コアCPUスイッチ

  • ファブリックスイッチユニット

  • PCIeインターフェースコントローラー

  • その他、エラーを監視可能なEDAC/ECCタイプのデバイスなど）を登録します

2段階の階層構造をサポートします

例えば、キャッシュはL1、L2、L3レベルで構成され、各CPUコアが独自のL1キャッシュを持ち、L2およびL3キャッシュを共有する場合があります。このような場合、以下のsysfsノードで表現できます：

/sys/devices/system/edac/..

pci/            <existing pci directory (if available)>
mc/             <existing memory device directory>
cpu/cpu0/..     <L1 and L2 block directory>
        /L1-cache/ce_count
                 /ue_count
        /L2-cache/ce_count
                 /ue_count
cpu/cpu1/..     <L1 and L2 block directory>
        /L1-cache/ce_count
                 /ue_count
        /L2-cache/ce_count
                 /ue_count
...

the L1 and L2 directories would be "edac_device_block's"
