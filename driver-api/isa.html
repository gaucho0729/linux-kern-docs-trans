ISAドライバ¶

以下のテキストは、Rene Herman氏が作成したISAバスドライバの初期コミットのコミットメッセージから適応したものです。

最近の「isaドライバがplatformデバイスを使用する」議論において、ALSAのISAドライバがハードウェアが見つからない場合にドライバのロード（デバイス登録の段階）を失敗させるオプションがなかった問題が指摘されました。これはprobe()エラーがドライバモデルを通じて上位に伝達されないためです。この議論の中で、私は別個のISAバスが最適であると考え、Russell King氏も同意し、このバスは実際のデバイス検出に.match()メソッドを使用できると提案しました。

添付ファイルはこれを実現しています。この古い非一般的な検出可能なISAハードウェアについては、ドライバ自体が検出を行うため、platform_busとは異なり、isa_busもドライバに.match()を配布します。

もう一つの違いとして、これらのデバイスはドライバがそれらを駆動したいと考えるため、ドライバモデル内に存在します。つまり、すべてのデバイス作成処理は内部に統合されています。

この提供する使用モデルは良いですし、Takashi Iwai氏とJaroslav Kysela氏からALSA側で承認されています。ALSAドライバのmodule_initは（旧ISA専用ドライバの場合）以下のようになります：

static int __init alsa_card_foo_init(void)
{
        return isa_register_driver(&snd_foo_isa_driver, SNDRV_CARDS);
}

static void __exit alsa_card_foo_exit(void)
{
        isa_unregister_driver(&snd_foo_isa_driver);
}

他のバスモデルと同様の使用モデルを提供しており、ALSA ISAドライバから多くの重複した初期化コードを削除しています。

渡されるisa_driver構造体は通常のドライバ構造体で、struct device_driverを埋め込み、通常のprobe/remove/shutdown/suspend/resumeコールバック、および指定された.matchコールバックを含みます。

「SNDRV_CARDS」が渡されるのは、unsigned int ndevパラメータで、作成するデバイス数と、それらのメソッドを呼び出すためのものです。

platform_driverコールバックはplatform_deviceパラメータで呼び出され、isa_driverコールバックは struct device *dev, unsigned int id ペア直接で呼び出されます。バス内でのデバイス作成が完全に内部化されているため、isa_devを渡すことでリークを防ぐため、渡す必要はありません。IDはそれ以外に常に必要なもので、 struct device いずれにしても、コールバック内のコードもより読みやすくしています。

この追加の .match() コールバックにより、ISA ドライバはすべてのオプションを備えています。ALSA が古い非ロード動作を維持したい場合、古い .probe を .match にすべて移し、すべてが存在していると確認された後にのみ登録するようにするだけで済みます。常にロードする動作を維持したい場合（変更後しばらくはプラットフォームデバイスの動作を誤って実行していたように）、.match() を提供せず、以前と同様に .probe() ですべてを行うだけで済みます。

Takashi Iwai がすでに提案したように、より合理的なバスのモデルに近づけるためには、後続のバインドが成功する可能性があるときにロードしたい場合、.match() で前提条件（ユーザーがカードを有効にしたいか、ポート/IRQ/DMA 値が渡されているかの確認など）を処理し、.probe() で残りの処理を行うことで、最も良いモデルになります。

コードへ…

このモジュールは、isa_register_driver() と isa_unregister_driver() の2つの関数をエクスポートしています。

isa_register_driver() は struct device_driver を登録し、その後渡された ndev をループしてデバイスを作成し登録します。これにより、バスのマッチメソッドが呼び出されます。これは以下の通りです：

int isa_bus_match(struct device *dev, struct device_driver *driver)
{
        struct isa_driver *isa_driver = to_isa_driver(driver);

        if (dev->platform_data == isa_driver) {
                if (!isa_driver->match ||
                        isa_driver->match(dev, to_isa_dev(dev)->id))
                        return 1;
                dev->platform_data = NULL;
        }
        return 0;
}

まず、このデバイスがドライバのデバイスであるかを確認するために、デバイスの platform_data ポインタがこのドライバを指しているかをチェックします。プラットフォームデバイスは文字列を比較しますが、すべてが内部で処理されるため、isa_register_driver() は dev->platform_data を isa_driver ポインタとして再利用しています。platform_data が利用可能かどうかは信頼できますが、そうでない場合でも、isa_driver ポインタを private struct isa_dev に移すのは当然の対応です。

次に、ドライバが .match を提供していない場合、マッチングを行います。提供している場合は、ドライバの match() メソッドが呼び出され、マッチングを決定します。

もしマッチングが成功した場合 ではありません マッチングが成功した場合、dev->platform_data はリセットされ、isa_register_driver() がこれを検知してデバイスを再登録します。

すべての処理中にエラーが発生した場合、またはどのデバイスにもマッチしなかった場合、すべての操作がロールバックされ、エラーまたは -ENODEV が返されます。

isa_unregister_driver() は、マッチしたデバイスとドライバ自体を登録を解除します。

module_isa_driver は、モジュール初期化/終了処理で特別な処理を行わない ISA ドライバ用のヘルパーマクロです。これにより多くのテンプレートコードを省略できます。各モジュールはこのマクロを1回だけ使用でき、呼び出すことで module_init と module_exit を置き換えます。

max_num_isa_devは、ISAデバイスのアドレス範囲を基に、I/Oポートアドレス空間に登録可能なISAデバイスの最大数を決定するマクロです。
