I2CおよびSMBusサブシステム¶

I2C（または装飾的なフォントを使わない場合、「I2C」）は「Inter-IC」バスの略称で、低データレート通信に十分な場面で広く使用されるシンプルなバスプロトコルです。また、これはライセンス商標でもあるため、一部のベンダーは別の名称（例：「Two-Wire Interface（TWI）」）で同じバスを呼んでいます。I2CはSCL（クロック）とSDA（データ）の2つの信号で動作し、基板の実装面積を節約し、シグナル品質の問題を最小限に抑えます。ほとんどのI2Cデバイスは7ビットアドレスを使用し、最大400kHzのバス速度が一般的ですが、高速拡張（3.4 MHz）はまだ広く利用されていません。I2Cはマルチマスターバスであり、オープンドレイン信号を用いてマスターデバイス間の仲裁、ハンドシェイク、および遅いクライアントからのクロック同期を行います。

LinuxのI2Cプログラミングインターフェースは、バスのマスターサイドとスレーブサイドの相互作用をサポートしています。インターフェースは2種類のドライバーと2種類のデバイスを軸に構成されており、I2C「アダプタドライバー」はコントローラーハードウェアを抽象化し、物理デバイス（例：PCIデバイスやplatform_device）にバインドして、 struct i2c_adapter 管理する各I2Cバスセグメントを表します。各I2Cバスセグメントには、 struct i2c_clientで表されるI2Cデバイスが存在します。これらのデバイスは、 struct i2c_driverにバインドされ、標準的なLinuxドライバーモデルに従う必要があります。さまざまなI2Cプロトコル操作を行う関数が用意されており、現在のところすべての関数はタスクコンテキストからのみ利用可能です。

システム管理バス（SMBus）はI2Cの姉妹プロトコルです。ほとんどのSMBusシステムはI2C準拠しています。SMBusでは電気的制約が厳しく、特定のプロトコルメッセージやイディオムを標準化しています。I2CをサポートするコントローラーはSMBus操作をほぼすべてサポートしますが、SMBusコントローラーはI2Cコントローラーがサポートするすべてのプロトコルオプションをサポートしません。さまざまなSMBusプロトコル操作を行う関数があり、I2Cプリミティブを使用するか、i2c_adapterデバイスにSMBusコマンドを発行して実行します。

callbackに渡されるi2c_client構造体は、実際のi2c_clientではありません。i2c_smbus_read_byte_dataなどの関数を呼び出すために十分に初期化されています。それ以外の処理は行わないでください。特に、dev_dbgなどの関数を呼び出すことは禁止されています detect i2c_client構造体は実際のi2c_clientではありません。i2c_smbus_read_byte_dataなどの関数を呼び出すために十分に初期化されています。それ以外の処理は行わないでください。特に、dev_dbgなどの関数を呼び出すことは禁止されています

struct i2c_algorithm¶

I2C転送メソッドを表す

定義

struct i2c_algorithm {
  int (*master_xfer)(struct i2c_adapter *adap, struct i2c_msg *msgs, int num);
  int (*master_xfer_atomic)(struct i2c_adapter *adap, struct i2c_msg *msgs, int num);
  int (*smbus_xfer)(struct i2c_adapter *adap, u16 addr,unsigned short flags, char read_write, u8 command, int size, union i2c_smbus_data *data);
  int (*smbus_xfer_atomic)(struct i2c_adapter *adap, u16 addr,unsigned short flags, char read_write, u8 command, int size, union i2c_smbus_data *data);
  u32 (*functionality)(struct i2c_adapter *adap);
#if IS_ENABLED(CONFIG_I2C_SLAVE);
  int (*reg_slave)(struct i2c_client *client);
  int (*unreg_slave)(struct i2c_client *client);
#endif;
};

メンバ

master_xfer

msgs配列で定義された指定されたI2Cアダプターに、numメッセージをアダプター経由で転送可能な一連のI2Cトランザクションを実行します。

master_xfer_atomic

同じく master_xfer。ただし、アトミックコンテキストのみを使用するため、シャットダウン前にPMICなどに非常に遅くアクセスできます。オプションです。

smbus_xfer

指定されたI2CアダプターにSMBusトランザクションを実行します。この関数が存在しない場合、バスレイヤーはSMBus呼び出しをI2Cトランザクションに変換しようとします。

smbus_xfer_atomic

同じく smbus_xfer。ただし、アトミックコンテキストのみを使用するため、シャットダウン前にPMICなどに非常に遅くアクセスできます。オプションです。

functionality

このアルゴリズム/アダプターのペアがサポートするフラグを、 I2C_FUNC_* フラグを確認します。

reg_slave

指定されたクライアントをこのアダプターのI2Cスレーブモードに登録する

unreg_slave

指定されたクライアントをこのアダプターのI2Cスレーブモードから登録を解除する

説明

以下の構造体は、新しいバスドライバーを実装したい人向けです:i2c_algorithmは、同じバスアルゴリズム（例:ビットバッキングやPCF8584など）でアドレス指定可能なハードウェアソリューションのインターフェースです。

return codesから master_xfer{_atomic} フィールドは、転送中に発生したエラーコードの種類を示すべきです。これは、カーネルドキュメンテーションファイルの『I2C/SMBUS Fault Codes』で記載されています。 I2C/SMBUS フォールトコード.

複合メッセージに関する注意: 一部のI2Cコントローラーは、1回の転送あたりに1つのメッセージのみを送信でき、複合メッセージまたは「書き込み後に読み込み」と呼ばれる機能をサポートしています。これは（通常）小さな書き込みメッセージの後に読み込みメッセージが続く形式で、EEPROMなどのレジスタベースのデバイスにアクセスするためのものです。このモードをサポートするフラグがあります。これによりmax_num_msg = 2となり、複合メッセージモード固有の制限をmax_comb_*_lenでチェックします。ハードウェア実装の違いにより、一部のコントローラーは「書き込み後に何でも」やその他の変種を実行できます。これをサポートするため、「書き込み後に読み込み」は「書き込み最初」や「読み込み第二」などの小さなビットに分解され、必要に応じて組み合わせられます。

s32 i2c_smbus_read_i2c_block_data_or_emulated(const struct i2c_client *クライアント, u8 コマンド, u8 length, u8 *値)¶

ブロック読み込みまたはエミュレート

パラメータ

const struct i2c_client *client

スレーブデバイスへのハンドル

u8 command

スレーブが解釈するバイト

u8 length

データブロックのサイズ。SMBusは最大I2C_SMBUS_BLOCK_MAXバイトを許可します

u8 *values

データが読み込まれるバイト配列。スレーブから返されるデータを保持できるだけのサイズ。SMBusは最大I2C_SMBUS_BLOCK_MAXバイトを許可します

説明

アダプターがサポートしている場合、SMBusの「ブロック読み込み」プロトコルを実行します。ブロック読み込みがサポートされていない場合は、利用可能なワードまたはバイト読み込みプロトコルを使用してエミュレートします。

この関数でアクセスされるI2Cスレーブデバイスのアドレスは、線形領域にマッピングされる必要があります。これにより、ブロック読み込みとバイト読み込みの効果が同じになります。この関数を使用する前に、I2Cスレーブがブロック転送をバイト転送と交換するサポートがあるか確認してください。

struct i2c_client *i2c_new_smbus_alert_device(struct i2c_adapter *アダプタ, struct i2c_smbus_alert_setup *設定)¶

ターゲットアダプター

説明
