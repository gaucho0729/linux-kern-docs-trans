BTT - ブロック翻訳テーブル¶

1. はじめに¶

永続メモリベースのストレージは、バイト（正確にはキャッシュライン）単位でのIO操作が可能です。しかし、このようなストレージを伝統的なブロックデバイスとして公開したいケースは多いです。永続メモリ用のブロックドライバーはまさにこの目的を果たします。ただし、これらはアトミック性の保証を提供しません。伝統的なSSDは、キャパシタに蓄えたエネルギーを活用して、フライト中のブロック書き込みを完了するなど、ハードウェアレベルで破損セクタの保護を提供します。しかし、永続メモリにはこのような特権はありません。書き込みが進行中で電源が落ちた場合、ブロックには古いデータと新しいデータの混在が発生します。アプリケーションはこのような状況を想定していない可能性があります。

ブロック翻訳テーブル（BTT）は、永続メモリデバイスにおいてアトミックなセクタ更新セマンティクスを提供します。これにより、セクタ書き込みが破損しないことを前提にしているアプリケーションも引き続き正常に動作できます。BTTはスタックされたブロックデバイスとして現れ、そのメタデータ用に基盤となるストレージの一部を確保します。その中心には、ボリューム内のすべてのブロックを再マッピングする間接テーブルがあり、非常にシンプルなファイルシステムのようにしか機能しません。

2. 静的レイアウト¶

BTTが配置可能な基盤となるストレージは、何の制限もありません。ただし、BTTは利用可能な空間を最大512 GiBのチャンクに分割します。このチャンクを「アレナ」と呼びます。

各アレナはメタデータレイアウトにおいて同じ構造を持ち、アレナ内の参照はすべて内部に限定されます（ただし、次のアレナを指す1つのフィールドを除く）。以下の図は「ディスク上のメタデータレイアウト」を示しています。

3. 操作理論¶

a. BTT マップ¶

マップは、LBAを内部ブロックにマッピングするシンプルな検索/間接テーブルです。各マップエントリは32ビットです。2つの最上位ビットは特別なフラグで、残りは内部ブロック番号を形成します。

ビット

説明

31 - 30

エラーおよびゼロフラグ - 以下の用途で使用されます：

== ==  ====================================================
31 30  Description
== ==  ====================================================
0  0   Initial state. Reads return zeroes; Premap = Postmap
0  1   Zero state: Reads return zeroes
1  0   Error state: Reads fail; Writes clear 'E' bit
1  1   Normal Block – has valid postmap
== ==  ====================================================

29 - 0

内部の'postmap'ブロックへのマッピング

以降で使用される用語のいくつか：

外部LBA

上位レイヤーに見えるLBA

ABA

アレナブロックアドレス - アレナ内のブロックオフセット/番号

Premap ABA

外部LBAの範囲チェックによって決定されたアレナ内のブロックオフセット

Postmap ABA

マップからの間接によって得られた「データブロック」領域内のブロック番号

nfree

任意の時点で維持される空きブロックの数。これはアレナに同時に行われる書き込み操作の最大数です。

たとえば、BTTを追加した後、1024GBのディスクが表示されます。外部LBAの読み取りが768GBで行われ、これは第二の領域に属します。この領域が提供する512GBのブロックのうち、このブロックは256GBに位置しています。したがって、プレマップABAは256GBです。次にマップを参照し、ブロック「X」（256GB）がブロック「Y」（例として「64」）にマッピングされていることを確認します。したがって、ポストマップABAは64になります。

b. BTT フロッグ¶

BTTは、すべての書き込みを「割当書き込み」として実行することによりセクタの原子性を提供します。つまり、すべての書き込みは「空きブロック」に実行されます。空きブロックの一覧はBTTフロッグとして維持されます。「フロッグ」は「free list（空きリスト）」と「log（ログ）」を組み合わせた語です。フロッグには'nfree'個のエントリがあり、エントリには以下の項目が含まれます。

lba

書き込まれているプレマップABA

old_map

この書き込みが完了した後、このブロックは空きブロックになります。この古いポストマップABA

new_map

新しいポストマップABA。マップはこのlba->ポストマップABAのマッピングを反映するために更新されますが、復元が必要な場合に備えてここにログします。

seq

このフロッグエントリの2つのセクションのうち、有効/最新のものを示すシーケンス番号です。通常の運用では01->10->11->01（2進数）と循環し、00は初期化されていない状態を示します。

lba’

代替lbaエントリ

old_map’

代替古いポストマップエントリ

new_map’

代替新しいポストマップエントリ

seq’

代替シーケンス番号。

上記の各フィールドは32ビットで、1つのエントリは32バイトになります。エントリはキャッシュラインの共有やアリアスを避けるため64バイトにパディングされます。フロッグの更新では、エントリを書き込む際、以下の手順で実行されます：a. シーケンス番号に基づいてエントリの「古い」セクションを上書き b. 「新しい」セクションを書き込み、シーケンス番号を最後に書き込みます。

c. ランの概念¶

「nfree」は、アリーナが同時に処理できるIO数を示しますが、「nlanes」はBTTデバイス全体が処理できるIO数です：

nlanes = min(nfree, num_cpus)

ラン番号はIOの開始時に取得され、IOの実行中、すべてのディスク上のデータ構造およびメモリ内のデータ構造にインデックスとして使用されます。CPUが最大の可用ラン数より多い場合、ランはスピンロックで保護されます。

d. メモリ内のデータ構造：読み取りトラッキングテーブル（RTT）¶

2つのスレッドが存在するケースを考えてみましょう。一方は読み込み、もう一方は書き込みを行います。書き込みスレッドが空きブロックを取得して新しいIOを実行している間に、（遅い）読み込みスレッドがまだそのブロックから読み出している状態が発生する可能性があります。つまり、読み込みスレッドがマップエントリを確認し、対応するブロックを読み出している状態です。一方、書き込みスレッドが同じ外部LBAに書き込みを開始し、書き込み完了後にその外部LBAのマップを新しいポストマップABAに更新します。この時点で、読み込みスレッドがまだ読み出している内部のポストマップブロックが空きブロックリストに挿入されています。同じLBAに対して別の書き込みが発生した場合、その空きブロックを取得して書き込みを開始すると、読み込みスレッドが不正確なデータを読み取る可能性があります。このような問題を防ぐためにRTT（Read-Through Table）を導入します。

RTTは、アリーナごとの単純なテーブルで、'nfree'個のエントリを持ちます。すべての読み込みスレッドは、読み出しているポストマップABAをrtt[lane_number]に挿入し、読み出し完了後にそのエントリをクリアします。すべての書き込みスレッドは、空きブロックを取得した後、RTTにその存在を確認します。RTTにポストマップ空きブロックが存在している場合、読み込みスレッドがRTTエントリをクリアするのを待ってから書き込みを開始します。

e. メモリ内データ構造: マップロック¶

2つの書き込みスレッドが同じLBAに書き込みを行うケースを考えてみましょう。以下のステップ順序に競合が発生する可能性があります:

free[lane] = map[premap_aba]
map[premap_aba] = postmap_aba

両方のスレッドがそれぞれのfree[lane]に同じ古い、解放されたpostmap_abaを更新する可能性があります。これにより、空きエントリが失われる一方で、2つのレーンに別の空きエントリが複製されるため、レイアウトが不一致になります。

この問題を解決するためには、アリーナごとの単一のマップロックを取得する必要があるかもしれませんが、競合が発生しすぎる可能性があるため、代わりに(nfree)個のマップロックを配列として使用します。この配列は、premap_aba modulo nfreeに基づいてインデックス付けされます。

f. Flogからの復元¶

起動時にBTT flogを解析して空きブロックリストを作成します。すべてのエントリを走査し、各レーンの2つの可能な「セクション」の中でもっとも最近のものを常に確認します（シーケンス番号に基づく）。復元ルール/ステップはシンプルです:

  • map[log_entry.lba]を読み込みます。

  • log_entry.newがマップエントリと一致する場合、log_entry.oldは空きブロックです。

  • log_entry.newがマップエントリと一致しない場合、log_entry.newは空きブロックです。（このケースは電源オフ/不安全なシャットダウンによってのみ発生します）

g. 要約 - 読み込みと書き込みフロー¶

読み込み:

  1. 外部LBAをアリーナ番号＋pre-map ABAに変換します。

  2. レーンを取得し（レーンロックを取得します）

  3. マップを読み込み、このpre-map ABAに対応するエントリを取得します

  4. RTT[lane]にpost-map ABAを入力します

  5. マップ内のTRIMフラグが設定されている場合、ゼロを返してIOを終了し、ステップ8に移動します

  6. マップ内のERRORフラグが設定されている場合、EIOでIOを終了します（ステップ8に移動）

  7. このブロックからデータを読み込みます

  8. RTT[lane]からpost-map ABAエントリを削除します

  9. レーン（およびlane_lock）を解放します

書き込み:

  1. 外部LBAをアリーナ番号＋pre-map ABAに変換します

  2. レーンを取得し（レーンロックを取得します）

  3. レーンをメモリ内の空きリストのインデックスとして使用し、新しいブロック、次のフラグインデックス、次のシーケンス番号を取得します

  4. RTTをスキャンし、空きブロックが存在するか確認します。存在する場合はスピン/待機します

  5. この空きブロックにデータを書き込みます

  6. マップからこのpre-map ABAに対応する既存のpost-map ABAエントリを読み込みます

  7. フラグエントリを書き込みます: [premap_aba / 旧postmap_aba / 新postmap_aba / seq_num]

  8. マップに新しいpost-map ABAを書き込みます

  9. 古いpost-mapエントリを空きリストに書き込みます

  10. 次のシーケンス番号を計算し、空きリストエントリに書き込みます

  11. レーン（およびlane_lock）を解放します

4. エラー処理¶

情報ブロックのチェックサムが一致しない（復元も失敗する）場合、アリーナはエラー状態になります。以下の条件が発生した場合、エラーとみなされます:

  • 情報ブロックのチェックサムが一致しない（復元も失敗する）

  • すべての内部空きブロックが、マップされたブロックと空きブロック（BTTフラグから）の合計で一意かつ完全にアドレス指定されていない

  • フラグから空きリストを再構築すると、欠落/重複/不可能なエントリが判明する

  • マップエントリが範囲外にある

これらのエラー条件のいずれかが発生した場合、情報ブロック内のフラグを使用してアリーナを読み取り専用状態にします

5. 使い方¶

BTTはlibnvdimmサブシステム（pmem、またはblkモード）で露出される任意のディスク（名前空間）に設定できます。このような名前空間を設定する最も簡単な方法は、'ndctl'ユーティリティを使用することです [1]:

例えば、4kセクタサイズでBTTを設定するndctlコマンドラインは以下の通りです:

ndctl create-namespace -f -e namespace0.0 -m sector -l 4k

より多くのオプションについては、ndctl create-namespace –helpを参照してください

[1]: https://github.com/pmem/ndctl
