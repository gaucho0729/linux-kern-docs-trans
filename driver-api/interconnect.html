汎用システムインターコネクトサブシステム¶

はじめに¶

このフレームワークは、SoC上のインターコネクトの設定を制御するための標準的なカーネルインターフェースを提供することを目的としています。これらの設定は、複数の接続されたデバイスまたは機能ブロック間の通信用量、レイテンシー、優先度などであり、動的に制御することで省電力化や最大性能を実現できます。

インターコネクトバスは、さまざまなドライバから受け取った要求に応じてデータパスで設定可能なハードウェアです。インターコネクトバスの例として、チップセット内のさまざまなコンポーネントまたは機能ブロック間のインターコネクトがあります。SoC上には複数のインターコネクトがあり、これらは多段階構造を持つ場合があります。

以下に、現実世界のSoCインターコネクトバストポロジーの簡略図を示します。

用語¶

インターコネクトプロバイダーはインターコネクトハードウェアのソフトウェア定義です。上記の図におけるインターコネクトプロバイダーはM NoC、S NoC、C NoC、P NoCおよびMem NoCです。

インターコネクトノードはインターコネクトハードウェアポートのソフトウェア定義です。各インターコネクトプロバイダーは複数のインターコネクトノードから構成され、他のSoCコンポーネントや他のインターコネクトプロバイダーに接続されています。CPUがメモリに接続するポイントはインターコネクトノードと呼ばれ、これはMem NoCインターコネクトプロバイダーに属します。

インターコネクトエンドポイントはパスの最初または最後の要素です。すべてのエンドポイントはノードですが、すべてのノードがエンドポイントであるわけではありません。

インターコネクトパスは、ソースノードから宛先ノードへ到達するための経路上にあるすべてのノードを含む、2つのエンドポイント間のすべての要素です。これには複数のマスターマイスターペアが含まれる場合があります。

インターコネクトコンシューマーは、プロバイダーが提供するデータパスを活用するエンティティです。コンシューマーは、通信用量、レイテンシー、優先度などの要求をプロバイダーに送信します。通常、コンシューマーはデバイスドライバであり、自身のニーズに基づいて要求を送信します。コンシューマーの例として、さまざまなフォーマットや画像サイズをサポートするビデオデコーダーがあります。

インターコネクトプロバイダー¶

インターコネクトプロバイダーは、インターコネクトバスハードウェアを初期化および構成するためのメソッドを実装するエンティティです。インターコネクトプロバイダードライバはインターコネクトプロバイダーコアに登録する必要があります。

struct icc_provider¶

複数のインターコネクト制御を提供する可能性のあるインターコネクトプロバイダー（コントローラー）エンティティ

定義

struct icc_provider {
  struct list_head        provider_list;
  struct list_head        nodes;
  int (*set)(struct icc_node *src, struct icc_node *dst);
  int (*aggregate)(struct icc_node *node, u32 tag, u32 avg_bw, u32 peak_bw, u32 *agg_avg, u32 *agg_peak);
  void (*pre_aggregate)(struct icc_node *node);
  int (*get_bw)(struct icc_node *node, u32 *avg, u32 *peak);
  struct icc_node* (*xlate)(struct of_phandle_args *spec, void *data);
  struct icc_node_data* (*xlate_extended)(struct of_phandle_args *spec, void *data);
  struct device           *dev;
  int users;
  bool inter_set;
  void *data;
};

メンバ

provider_list

登録済みインターコネクトプロバイダーの一覧

nodes

インターコネクトプロバイダーのノードの内部リスト

set

デバイス固有の設定操作関数へのポインタ

aggregate

デバイス固有の集約操作関数へのポインタ

pre_aggregate

デバイス固有の関数へのポインタ（集約開始前に呼び出される、オプション）

get_bw

デバイス固有の現在の帯域幅を取得する関数へのポインタ

xlate

プロバイダー固有のコールバック（phandle引数からノードをマッピングするための）

xlate_extended

ベンダー固有のコールバック（phandle引数からノードデータをマッピングするための）

dev

このインターコネクトプロバイダーに所属するデバイス

users

アクティブなユーザーのカウント

inter_set

インターコネクトプロバイダー間のペアが設定されるかどうか set

data

プライベートデータへのポインタ

struct icc_node¶

インターコネクトトポロジーに含まれるエンティティ

定義

struct icc_node {
  int id;
  const char              *name;
  struct icc_node         **links;
  size_t num_links;
  struct icc_provider     *provider;
  struct list_head        node_list;
  struct list_head        search_list;
  struct icc_node         *reverse;
  u8 is_traversed:1;
  struct hlist_head       req_list;
  u32 avg_bw;
  u32 peak_bw;
  u32 init_avg;
  u32 init_peak;
  void *data;
};

メンバ

id

プラットフォーム固有のノードID

name

debugfsで使用されるノード名

links

トラバーサル時に次の目的地を指すターゲットの一覧

num_links

他のインターコネクトノードへのリンク数

provider

このノードのインターコネクトプロバイダーを指す

node_list

親プロバイダーの「nodes」リスト内のリストエントリ

search_list

ノードグラフを歩く際使用するリスト

reverse

ノードグラフを歩く際の前のノードへのポインタ

is_traversed

ノードグラフを歩く際使用するフラグ

req_list

このノードに関連するQoS制約リクエストの一覧

avg_bw

すべての消費者からの平均帯域幅リクエストの集約値

peak_bw

すべての消費者からのピーク帯域幅リクエストの集約値

init_avg

初期化中にハードウェアから読み取った平均帯域幅値

init_peak

初期化中にハードウェアから読み取ったピーク帯域幅値

data

プライベートデータへのポインタ

インターコネクトコンシューマー¶

インターコネクト消費者は、エンドポイント間のパスを取得し、これらのインターコネクトパスの帯域幅/レイテンシー/QoS要件を設定するためにインターコネクトAPIを使用するクライアントです。これらのインターフェースは現在ドキュメント化されていません。

インターコネクトデバッグfsインターフェース¶

いくつかのサブシステムと同様に、インターコネクトはデバッグとintrospection用のファイルを作成します。debugfs内のファイルはABIとみなされないため、アプリケーションソフトウェアはカーネルバージョン間でのフォーマットの変更に依存すべきではありません。

/sys/kernel/debug/interconnect/interconnect_summary:

システム内のすべてのインターコネクトノードとその集約帯域幅リクエストを表示します。各ノードの下にインデントして、各デバイスからの帯域幅リクエストを表示します。

/sys/kernel/debug/interconnect/interconnect_graph:

graphviz dot形式でインターコネクトグラフを表示します。これはシステム内のすべてのインターコネクトノードとリンクを表示し、同じプロバイダーからのノードをサブグラフとしてグループ化します。この形式は人間が読みやすく、dotを経由して多くのグラフィカル形式のダイアグラムを生成できます。

$ cat /sys/kernel/debug/interconnect/interconnect_graph | \
        dot -Tsvg > interconnect_graph.svg
