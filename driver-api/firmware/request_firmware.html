request_firmware API¶

通常、ファームウェアをロードしてからデバイスにロードする必要があります。以下に典型的なファームウェアのワークフローを示します：

if(request_firmware(&fw_entry, $FIRMWARE, device) == 0)
       copy_fw_to_device(fw_entry->data, fw_entry->size);
release_firmware(fw_entry);

非同期ファームウェアリクエスト¶

非同期ファームウェアリクエストは、ドライバコードがファームウェアやエラーの返却を待つ必要がないようにします。ファームウェアやエラーが見つかったときにドライバを通知するための関数コールバックが提供されます。 request_firmware_nowait() アトミックコンテキストでは呼び出すことができません。

再起動時の特別な最適化¶

一部のデバイスでは、システム再起動時にファームウェアを保持できるようにする最適化が実装されています。このような最適化を使用する場合、ドライバー開発者は再起動後のスリープからの復帰時にファームウェアが依然として利用可能であることを保証しなければなりません。これは、 firmware_request_cache() ファームウェアをロードするリクエストではなく、

int firmware_request_cache(struct デバイス *デバイス, const char *名前)¶

スリープ時にファームウェアをキャッシュして再起動時に使用可能にする

ファームウェアをキャッシュする必要のあるデバイス

説明

一部のデバイスでは、システム再起動時にファームウェアをロードする必要がないようにする最適化が実装されています。この最適化は、スリープからの復帰時にファームウェアが依然として存在することを必要とする場合があります。このような状況でファームウェアが復帰時に存在することを保証するには、このルーチンを使用できます。このアシスタントは、 request_firmware_into_buf() または request_firmware_nowait() uevent が設定されていない場合。

request firmware API はドライバの使用を想定しています¶

API コールが返るたびにファームウェアを処理し、その後ファームウェアを解放する必要があります。たとえば、 request_firmware() を呼び出し、返した場合、ドライバーは fw_entry->{data,size} にファームウェアイメージがアクセス可能になります。何か問題が起きた場合 request_firmware() 非ゼロを返し、fw_entry が NULL に設定されます。ドライバーがファームウェアの処理を終えたら、release_firmware(fw_entry) を呼び出してファームウェアイメージと関連するリソースを解放できます。
