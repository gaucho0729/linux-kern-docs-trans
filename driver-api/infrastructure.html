struct device_link *device_link_add(struct デバイス *consumer, struct デバイス *supplier, u32 フラグ)¶

2つのデバイス間のリンクを作成します。

パラメータ

struct device *consumer

リンクのコンシューマー端。

struct device *supplier

リンクのサプライヤー端。

u32 flags

リンクフラグ。

説明

呼び出し元はリンク作成とランタイムPMの適切な同期を担当します。まず、DL_FLAG_PM_RUNTIMEフラグを設定すると、ランタイムPMフレームワークがリンクを考慮するようになります。次に、DL_FLAG_RPM_ACTIVEフラグを追加して設定すると、サプライヤーデバイスがリンク作成時にアクティブなメタステートに強制され、参照カウントされます。DL_FLAG_PM_RUNTIMEが設定されていない場合、DL_FLAG_RPM_ACTIVEは無視されます。

DL_FLAG_STATELESSが設定されている場合、 フラグこの関数の呼び出し元は、この関数が返すリンクを直接、以下のいずれかを用いて解放する必要があります。 device_link_del() または device_link_remove().

ただし、このフラグが設定されていない場合、この関数の呼び出し元はリンクの管理を完全にドライバーコアに委譲しており、返値はリンクが存在するかどうかを確認するためのものに限られます。その場合、DL_FLAG_AUTOREMOVE_CONSUMERとDL_FLAG_AUTOREMOVE_SUPPLIERデバイスリンクフラグを用いて、ドライバーコアにリンクが安全に削除できるタイミングを示すことができます。つまり、DL_FLAG_AUTOREMOVE_CONSUMERまたはDL_FLAG_AUTOREMOVE_SUPPLIERを設定することで、コンシューマードライバーまたはサプライヤードライバーがデバイスからアンバインドされた後、リンクが使用されなくなることをドライバーコアに通知します。どのフラグも設定されていない場合、リンクは、リンクを指すデバイス（コンシューマーやサプライヤーのいずれか）が登録解除されるまで維持されます。 フラグ が設定されている場合、ドライバーコアにそのリンクが使用されなくなる（この関数の呼び出し元によって）ことを通知します。つまり、コンシューマードライバーまたはサプライヤードライバーがデバイスからアンバインドされた後、リンクを削除できると示します。どのフラグも設定されていない場合、リンクは、リンクを指すデバイス（コンシューマーやサプライヤーのいずれか）が登録解除されるまで維持されます。

また、DL_FLAG_STATELESS、DL_FLAG_AUTOREMOVE_CONSUMER、DL_FLAG_AUTOREMOVE_SUPPLIERが設定されていない場合（つまり、永続的な管理デバイスリンクが追加されている場合）、DL_FLAG_AUTOPROBE_CONSUMERフラグを使用して、ドライバコアにサプライヤデバイスにドライバをバインディングした後、コンシューマドライバを自動的に検出するよう要求できます。 フラグ DL_FLAG_STATELESSとDL_FLAG_AUTOREMOVE_CONSUMER、DL_FLAG_AUTOREMOVE_SUPPLIER、DL_FLAG_AUTOPROBE_CONSUMERのうちの1つを同時に設定する組み合わせは無効であり、NULLが事前に返されます。ただし、この関数が呼び出されるときに既に指定されたペア間でデバイスリンクが存在する場合、その既存のリンクが返されます（リンクのフラグはその後変更される可能性があります）。この関数の呼び出し元は、リンクが新たに作成されたかのように扱う必要があります（特に、DL_FLAG_STATELESSが渡されていた場合）。

DL_FLAG_STATELESSとDL_FLAG_AUTOREMOVE_CONSUMER、DL_FLAG_AUTOREMOVE_SUPPLIER、DL_FLAG_AUTOPROBE_CONSUMERのうちの1つを同時に設定する組み合わせは無効であり、NULLが事前に返されます。ただし、この関数が呼び出されるときに既に指定されたペア間でデバイスリンクが存在する場合、その既存のリンクが返されます（リンクのフラグはその後変更される可能性があります）。この関数の呼び出し元は、リンクが新たに作成されたかのように扱う必要があります（特に、DL_FLAG_STATELESSが渡されていた場合）。 フラグ at the same time is invalid and will cause NULL to be returned upfront. However, if a device link between the given consumer および supplier pair exists already when this function is called for them, the existing link will be returned regardless of its current type and status (the link’s flags may be modified then). The caller of this function is then expected to treat the link as though it has just been created, so (in particular) if DL_FLAG_STATELESS was passed in フラグ、リンクはもはや必要なくなったときに明示的に解放する必要があります（上記のように述べられています）。

リンクの作成には、dpm_list と devices_kset リストの再並び替えという副作用があります。これは、消費者デバイスとそのすべての依存デバイスをこれらのリストの先頭に移動するためのものです（この関数が呼び出されたときに登録されていないデバイスにはこの現象は起こりません）。

この関数が呼び出される際、サプライヤー・デバイスが登録されている必要があります。登録されていない場合、NULLが返されます。消費者・デバイスは登録されていなくても構いません。

すべての「システム」サブシステムは、サブシステム名を表す/sys/devices/system/<name>のルートデバイスを持ちます。このルートデバイスはサブシステム全体にわたる属性を持つことができます。すべての登録デバイスはこの単一のルートデバイスの下に配置され、サブシステム名に単純な番号を付けて名前が付けられます。登録デバイスは明示的に名前が付けられず、デバイスの「id」のみが設定されます。
