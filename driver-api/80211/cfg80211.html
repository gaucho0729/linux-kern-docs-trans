cfg80213サブシステム¶

cfg80211はLinuxにおける802.11デバイスの設定用APIです。ユーザースペースとドライバを橋渡しし、802.11に関連するユーティリティ機能を提供します。cfg80211は、すべての現代的な無線ドライバがnl80211を通じて一貫したAPIを提供できるように、直接または間接的にmac80211を介して使用しなければなりません。後方互換性のため、cfg80211はユーザースペースにワイヤレス拡張機能を提供しますが、ドライバには完全に隠します。

さらに、cfg80211には規制に基づく周波数帯域の使用制限を強制するコードが含まれています。

デバイス登録¶

ドライバがcfg80211を使用するためには、ハードウェアデバイスをcfg80211に登録する必要があります。これは以下のハードウェア能力構造体を通じて行われます。

各デバイスの基本構造は「wiphy」であり、各インスタンスはシステムに接続された物理的な無線デバイスを表します。このようなwiphyには、ゼロ個、1個、または複数の仮想インターフェースが関連付けられ得ますが、ネットワークインターフェースの ieee80211_ptr ポインタが struct wireless_dev を指すことで識別されます。この構造体は通常ネットワークインターフェースのプライベートデータ領域に埋め込まれています。ドライバは仮想インターフェースの即時作成または破壊をオプションで許可できますが、少なくとも1つまたは作成可能なインターフェースが存在しないと無線デバイスは役に立ちません。

各wiphy構造体にはデバイスの能力情報が含まれており、またドライバが提供する各種操作へのポインタも保持しています。ここでの定義と構造体はこれらの能力を詳細に説明しています。

ドライバがインターフェースとそのタイプの組み合わせが許可されているかを確認するためにこの関数を呼び出すことができます。

アクションと設定¶

各無線デバイスおよび仮想インターフェースは、ユーザー空間から呼び出される設定操作とその他のアクションを提供します。これらのアクションは操作構造体で記述され、各操作が使用するパラメータは別途説明されます。

また、一部の操作は非同期であり、ドライバが呼び出す必要のある関数を通じてステータス情報を取得します。

スキャンおよびBSSリストの処理と関連する機能は別の章で説明します。

struct cfg80211_pmksa¶

PMKセキュリティアソシエーション

定義

struct cfg80211_pmksa {
  const u8 *bssid;
  const u8 *pmkid;
  const u8 *pmk;
  size_t pmk_len;
  const u8 *ssid;
  size_t ssid_len;
  const u8 *cache_id;
  u32 pmk_lifetime;
  u8 pmk_reauth_threshold;
};

メンバ

bssid

APのBSSID（may be NULL).

pmkid

PMKSAを参照する識別子。

pmk

PMKSAが識別されるPMK。 pmkid。これはFILS STAによる鍵導出に使用されます。それ以外の場合、 NULL.

pmk_len

長さの pmk。長さは pmk 生成に使用されるハッシュアルゴリズムによって異なります。

ssid

FILSキャッシュ識別子を使用してPMKSAが有効なESSを指定するSSID（may be NULL).

ssid_len

長さの ssid オクテット単位で。

cache_id

2オクテットキャッシュ識別子でFILS APがPMKSAのスコープを識別します。これはのみ有効です。 ssid_len がゼロでない場合（may be NULL).

pmk_lifetime

PMKSAの最大有効時間（秒）（dot11RSNAConfigPMKLifetime）または指定されていない場合の0。設定されたPMKSAは、有効期限が切れた後はPMKSAキャッシュに使用してはいけません。このPMKから導出されたすべての鍵は有効期限が切れた時点で無効になります。つまり、このPMKを使用して接続している場合、接続は切断する必要があります。

pmk_reauth_threshold

再認証のしきい値時間（PMK有効時間のパーセンテージ、dot11RSNAConfigPMKReauthThreshold）または指定されていない場合の0。ドライバは、このしきい値を超えて新しいBSSに再アソシエーションする際、このPMKSAを使用してキャッシュするのではなく、現在のPMKが期限切れになる前に新しいPMKを生成するために完全な認証をトリガーする必要があります。

説明

この構造体はPMKSAキャッシュのためにset/del_pmksa()メソッドに渡されます。

スキャンとBSSリストの処理¶

スキャンプロセス自体は比較的簡単ですが、cfg80211は多くの補助機能を提供しています。スキャンを開始するには、スキャン定義を指定してスキャン操作を呼び出します。このスキャン定義にはスキャンするチャンネルと、プローブリクエストを送信するSSID（ワイルドカードを含む場合も可）が含まれます。プローブリクエストにSSIDを指定しない場合、パッシブスキャンとみなされます。さらに、スキャンリクエストにはプローブリクエストに追加する情報要素（IE）が含まれる場合があります。IEは正しく形成され、ドライバがwiphy構造体で広告した最大長を超えないことが保証されています。

スキャンでBSSが見つかった場合、cfg80211に通知する必要があります。なぜなら、cfg80211がBSSリストを維持する責任があるからです。ドライバはリストを自分で維持してはいけません。この通知には、さまざまな関数が存在します。

ドライバがBSSリストを保持しないので、BSSを検索してその情報をcfg80211が保持するBSS構造から取得する機能もあります。BSSリストはユーザー空間にも提供されます。

RFkill統合¶

cfg80211におけるRFkill統合は、ドライバに対してほぼ見えません。cfg80211は、認識している無線デバイスごとに自動的にrfkillインスタンスを登録します。ソフトキルは接続を切断し、すべてのインターフェースをオフにすることに翻訳され、ドライバはすべてのインターフェースがオフになったときにデバイスをオフにする必要があります。

ただし、デバイスがハードRFkillラインを備えている場合、cfg80211を介してrfkillサブシステムと相互作用する必要があります。これを行うには、ここに記載されているいくつかのヘルパ関数を使用できます。
