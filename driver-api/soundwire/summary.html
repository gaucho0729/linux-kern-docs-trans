SoundWireサブシステムの概要¶

SoundWireは、2015年にMIPIアライアンスによって採択された新しいインターフェースです。SoundWireは、オーディオ関連のデータを転送するために使用されます。SoundWireインターフェースは、モバイルやモバイルインスピレーションを持つシステムにおけるオーディオデバイスの統合を最適化しています。

SoundWireは、データ線とクロック線を持つ2ピンのマルチドロップインターフェースです。低コストで効率的かつ高性能なシステムの開発を促進します。SoundWireインターフェースの主要な特徴には次のようなものがあります：

  1. 単一の2ピンインターフェースを介して、すべてのペイロードデータチャネル、制御情報、セットアップコマンドを転送します。

  2. DDR（デュアルデータレート）データ伝送を用いることで、クロック周波数を低減し、結果として電力消費を抑えることができます。

  3. クロックスケーリングとオプションの複数データレーンを採用し、データレートの幅広い柔軟性を提供してシステム要件に合わせます。

  4. デバイス状態のモニタリングを含み、マスターへの割込みスタイルのアラートを提供します。

SoundWireプロトコルは最大11つのスレーブインターフェースをサポートします。すべてのインターフェースは共通のバス（データ線とクロック線を含む）を共有します。各スレーブは最大14つのデータポートをサポートでき、そのうち13ポートはオーディオ転送用です。データポート0はバULKコントロール情報の転送用で、オーディオデータポート（1〜14）は送信または受信モードで最大8チャネルをサポートします（通常は固定方向ですが、仕様により方向変更が可能です）。帯域幅制限（約19.2〜24.576Mbits/s）により、11×13×8チャネルの同時送信はできません。

以下の図は、SoundWireマスターと2つのスレーブデバイス間の接続例を示しています。

+---------------+                                       +---------------+
|               |                       Clock Signal    |               |
|    Master     |-------+-------------------------------|    Slave      |
|   Interface   |       |               Data Signal     |  Interface 1  |
|               |-------|-------+-----------------------|               |
+---------------+       |       |                       +---------------+
                        |       |
                        |       |
                        |       |
                     +--+-------+--+
                     |             |
                     |   Slave     |
                     | Interface 2 |
                     |             |
                     +-------------+

用語¶

MIPI SoundWire仕様では、「デバイス」という用語はマスターまたはスレーブインターフェースを指しますが、これはやや混乱を招く可能性があります。このサマリーおよびコードでは、「インターフェース」という用語はハードウェアのみを指します。Linuxデバイスモデルに従い、バスに接続された各スレーブインターフェースを特定のドライバーによって管理するデバイスとしてマッピングします。Linux SoundWireサブシステムは、サードパーティベンダーが実装定義の機能を有効化できるAPIを提供し、一般的な設定・構成タスクはバスによって処理されるフレームワークを提供します。

バス：SoundWire Linuxバスを実装し、SoundWireプロトコルを処理します。MIPIで定義されたすべてのスレーブレジスタをプログラムします。SoundWireマスターを表します。システム内には複数のバスインスタンスが存在する可能性があります。

スレーブ: SoundWireスレーブデバイスとして登録されます(Linuxデバイス)。複数のスレーブデバイスが1つのバスインスタンスに登録できます。

スレーブドライバー: スレーブデバイスを制御するドライバーです。MIPIで指定されたレジスタはバスが直接制御し(マスタードライバー/インターフェースを通じて送信されます)。任意の実装定義スレーブレジスタはスレーブドライバーが制御します。実際には、スレーブドライバーはregmapに依存し、直接レジスタアクセスを要求しないことが期待されます。

プログラミングインターフェース(SoundWireマスターアクセスドライバー)¶

SoundWireバスはSoundWireマスターアクセスの実装とSoundWireスレーブデバイスのプログラミングインターフェースをサポートします。すべてのコードはSoC設計者および3rdパーティベンダーが一般的に使用する「sdw」プレフィックスを使用します。

各SoundWireマスターアクセスインターフェースはバスに登録する必要があります。バスは標準的なマスターミピプロパティを読み込むAPIを実装し、マスタードライバーが独自の機能を実装するためのマスターオプスのコールバックも提供します。DTサポートは現在実装されていませんが、機能を有効化するためのAPIを用いれば簡単に追加できます。 device_property_ API。

マスターアクセスインターフェースとマスターアクセスインターフェース機能はボードファイル、DTまたはACPIに基づいて登録されます。

SoundWireバスの登録に使用するバスAPIは以下の通りです:

int sdw_bus_master_add(struct sdw_bus *bus,
                        struct device *parent,
                        struct fwnode_handle)
{
        sdw_master_device_add(bus, parent, fwnode);

        mutex_init(&bus->lock);
        INIT_LIST_HEAD(&bus->slaves);

        /* Check ACPI for Slave devices */
        sdw_acpi_find_slaves(bus);

        /* Check DT for Slave devices */
        sdw_of_find_slaves(bus);

        return 0;
}

これによりマスターデバイス用のsdw_busオブジェクトが初期化されます。「sdw_master_ops」と「sdw_master_port_ops」コールバック関数がバスに提供されます。

「sdw_master_ops」はバスがハードウェア固有の方法でバスを制御するために使用されます。バス制御機能（バス上のSoundWire読み書きメッセージの送信、クロック周波数の設定およびストリーム同期ポイント（SSP）の設定など）を含みます。「sdw_master_ops」構造体はマスターハードウェアの詳細をバスから抽象化します。

「sdw_master_port_ops」はバスがマスターアクセスインターフェースポートのポートパラメータを設定するために使用されます。MIPI仕様ではマスターアクセスインターフェースポートのレジスタマップが定義されていないため、バスは「sdw_master_port_ops」コールバック関数を呼び出してポート操作（ポート準備、ポートトランスポートパラメータ設定、ポート有効/無効）を行います。マスタードライバーの実装はこれによりハードウェア固有の設定を実行できます。

プログラミングインターフェース(SoundWireスレーブドライバー)¶

MIPI仕様では、各Slaveインターフェースが一意の48ビットの識別子を公開する必要があります。この識別子は6つの読み取り専用dev_idレジスタに格納され、dev_id識別子にはベンダーおよび部品情報が含まれ、同一部品を区別するためのフィールドも含まれます。追加のクラスフィールドは現在使用されていません。Slaveドライバは特定のベンダーおよび部品識別子のために記述され、バスはこれらの2つのIDに基づいてSlaveデバイスを列挙します。Slaveデバイスとドライバの一致はこれらの2つのIDに基づいて行われます。デバイスとドライバIDの一致が成功した場合、バスがSlaveドライバのプローブを呼び出します。マスターデバイスとSlaveデバイス間には親子関係が強制されます（論理的な表現は物理的な接続性と一致しています）。

マスターデバイスとSlaveデバイスの依存関係情報はプラットフォームデータ、ボードファイル、ACPI、またはDTに保存されています。MIPIソフトウェア仕様では、複数のマスターアクセスを持つコントローラー用に追加のlink_idパラメータが定義されています。dev_idレジスタはリンクスコープ内で一意であり、link_idはコントローラーのスコープ内で一意です。dev_idとlink_idはシステムレベルでは必ずしも一意ではありませんが、親子情報は曖昧さを避けるために使用されます。

static const struct sdw_device_id slave_id[] = {
        SDW_SLAVE_ENTRY(0x025d, 0x700, 0),
        {},
};
MODULE_DEVICE_TABLE(sdw, slave_id);

static struct sdw_driver slave_sdw_driver = {
        .driver = {
                   .name = "slave_xxx",
                   .pm = &slave_runtime_pm,
                   },
        .probe = slave_sdw_probe,
        .remove = slave_sdw_remove,
        .ops = &slave_slave_ops,
        .id_table = slave_id,
};

機能については、バスは標準的なSlave MIPIプロパティを読み取るためのAPIを実装し、Slaveドライバが独自の機能を実装するためのSlave opsにおけるコールバックも提供します。バスはSlaveレジスタをプログラミングし、バスの再構成を制御するためにSlaveの機能セットを知る必要があります。
