SoundWireにおけるオーディオストリーム¶

オーディオストリームは、論理的または仮想的な接続であり、

  1. システムメモリバッファ（複数可）とコーデック（複数可）の間で作成されます。

  2. DSPメモリバッファ（複数可）とコーデック（複数可）の間で作成されます。

  3. FIFO（複数可）とコーデック（複数可）の間で作成されます。

  4. コーデック（複数可）とコーデック（複数可）の間で作成されます。

データリンクを介してDMA（複数可）チャネルによって駆動されます。オーディオストリームは1つまたは複数のチャネルのデータを含みます。ストリーム内のすべてのチャネルは、同じサンプリングレートと同じサンプルサイズを備える必要があります。

SoundWireインターフェースを使用して、2つのチャネル（左と右）を持つストリームが開かれると仮定します。以下は、SoundWireにおけるストリームの表現方法です。

メモリ内のストリームサンプル（システムメモリ、DSPメモリまたはFIFOs）

-------------------------
| L | R | L | R | L | R |
-------------------------

例1: LとRチャンネルを持つステレオストリームはマスターからスレーブへ再生されます。マスターとスレーブはどちらも単一ポートを使用しています。

+---------------+                    Clock Signal  +---------------+
|    Master     +----------------------------------+     Slave     |
|   Interface   |                                  |   Interface   |
|               |                                  |       1       |
|               |                     Data Signal  |               |
|    L  +  R    +----------------------------------+    L  +  R    |
|     (Data)    |     Data Direction               |     (Data)    |
+---------------+  +----------------------->       +---------------+

例2: LとRチャンネルを持つステレオストリームはスレーブからマスターへキャプチャされます。マスターとスレーブはどちらも単一ポートを使用しています。

+---------------+                    Clock Signal  +---------------+
|    Master     +----------------------------------+     Slave     |
|   Interface   |                                  |   Interface   |
|               |                                  |       1       |
|               |                     Data Signal  |               |
|    L  +  R    +----------------------------------+    L  +  R    |
|     (Data)    |     Data Direction               |     (Data)    |
+---------------+  <-----------------------+       +---------------+

例3: LとRチャンネルを持つステレオストリームはマスターによって再生されます。LチャンネルとRチャンネルはそれぞれ異なるスレーブによって受信されます。マスターと両スレーブは単一ポートを使用しています。

+---------------+                    Clock Signal  +---------------+
|    Master     +---------+------------------------+     Slave     |
|   Interface   |         |                        |   Interface   |
|               |         |                        |       1       |
|               |         |           Data Signal  |               |
|    L  +  R    +---+------------------------------+       L       |
|     (Data)    |   |     |    Data Direction      |     (Data)    |
+---------------+   |     |   +------------->      +---------------+
                    |     |
                    |     |
                    |     |                        +---------------+
                    |     +----------------------> |     Slave     |
                    |                              |   Interface   |
                    |                              |       2       |
                    |                              |               |
                    +----------------------------> |       R       |
                                                   |     (Data)    |
                                                   +---------------+

例4: LとRチャンネルを持つステレオストリームはマスターによって再生されます。LチャンネルとRチャンネルはそれぞれ異なるスレーブによって受信されます。マスターと両スレーブはL+Rを処理する単一ポートを使用しています。各スレーブデバイスは静的設定または動的オリエンテーションに基づいてローカルでL+Rデータを処理し、1つまたは複数のスピーカーを駆動することがあります。

+---------------+                    Clock Signal  +---------------+
|    Master     +---------+------------------------+     Slave     |
|   Interface   |         |                        |   Interface   |
|               |         |                        |       1       |
|               |         |           Data Signal  |               |
|    L  +  R    +---+------------------------------+     L + R     |
|     (Data)    |   |     |    Data Direction      |     (Data)    |
+---------------+   |     |   +------------->      +---------------+
                    |     |
                    |     |
                    |     |                        +---------------+
                    |     +----------------------> |     Slave     |
                    |                              |   Interface   |
                    |                              |       2       |
                    |                              |               |
                    +----------------------------> |     L + R     |
                                                   |     (Data)    |
                                                   +---------------+

例5: LとRチャンネルを持つステレオストリームはマスターの2つのポートによって再生され、スレーブインターフェースの単一ポートのみで受信されます。

+--------------------+
|                    |
|     +--------------+                             +----------------+
|     |             ||                             |                |
|     |  Data Port  ||  L Channel                  |                |
|     |      1      |------------+                 |                |
|     |  L Channel  ||           |                 +-----+----+     |
|     |   (Data)    ||           |   L + R Channel ||    Data |     |
| Master  +----------+           | +---+---------> ||    Port |     |
| Interface          |           |                 ||     1   |     |
|     +--------------+           |                 ||         |     |
|     |             ||           |                 +----------+     |
|     |  Data Port  |------------+                 |                |
|     |      2      ||  R Channel                  |     Slave      |
|     |  R Channel  ||                             |   Interface    |
|     |   (Data)    ||                             |       1        |
|     +--------------+         Clock Signal        |     L  +  R    |
|                    +---------------------------> |      (Data)    |
+--------------------+                             |                |
                                                   +----------------+

例6: LとRチャンネルを持つステレオストリームは2つのマスターによってそれぞれ1チャンネルずつ再生され、2つのスレーブによってそれぞれ1チャンネルずつ受信されます。両マスターと両スレーブは単一ポートを使用しています。

+---------------+                    Clock Signal  +---------------+
|    Master     +----------------------------------+     Slave     |
|   Interface   |                                  |   Interface   |
|       1       |                                  |       1       |
|               |                     Data Signal  |               |
|       L       +----------------------------------+       L       |
|     (Data)    |     Data Direction               |     (Data)    |
+---------------+  +----------------------->       +---------------+

+---------------+                    Clock Signal  +---------------+
|    Master     +----------------------------------+     Slave     |
|   Interface   |                                  |   Interface   |
|       2       |                                  |       2       |
|               |                     Data Signal  |               |
|       R       +----------------------------------+       R       |
|     (Data)    |     Data Direction               |     (Data)    |
+---------------+  +----------------------->       +---------------+

例7: LとRチャンネルを持つステレオストリームは2つのマスターによってそれぞれ両チャンネルを再生され、各スレーブはL+Rを受信します。これは例4と同じアプリケーションですが、スレーブが別個のリンクに配置されている点が異なります。

+---------------+                    Clock Signal  +---------------+
|    Master     +----------------------------------+     Slave     |
|   Interface   |                                  |   Interface   |
|       1       |                                  |       1       |
|               |                     Data Signal  |               |
|     L + R     +----------------------------------+     L + R     |
|     (Data)    |     Data Direction               |     (Data)    |
+---------------+  +----------------------->       +---------------+

+---------------+                    Clock Signal  +---------------+
|    Master     +----------------------------------+     Slave     |
|   Interface   |                                  |   Interface   |
|       2       |                                  |       2       |
|               |                     Data Signal  |               |
|     L + R     +----------------------------------+     L + R     |
|     (Data)    |     Data Direction               |     (Data)    |
+---------------+  +----------------------->       +---------------+

例8: 4チャンネルのストリームは2つのマスターによってそれぞれ2チャンネルずつ再生され、各スレーブは2チャンネルを受信します。

+---------------+                    Clock Signal  +---------------+
|    Master     +----------------------------------+     Slave     |
|   Interface   |                                  |   Interface   |
|       1       |                                  |       1       |
|               |                     Data Signal  |               |
|    L1 + R1    +----------------------------------+    L1 + R1    |
|     (Data)    |     Data Direction               |     (Data)    |
+---------------+  +----------------------->       +---------------+

+---------------+                    Clock Signal  +---------------+
|    Master     +----------------------------------+     Slave     |
|   Interface   |                                  |   Interface   |
|       2       |                                  |       2       |
|               |                     Data Signal  |               |
|     L2 + R2   +----------------------------------+    L2 + R2    |
|     (Data)    |     Data Direction               |     (Data)    |
+---------------+  +----------------------->       +---------------+

注意1: 上記のようなマルチリンクの場合、ロックを行うにはグローバルロックを取得し、その後バスインスタンスごとにロックを行います。ただし、この場合、呼び出し元フレームワーク(ASoC DPCM)がカードのストリーム操作を常にシリアル化することを保証しているため、レースコンディションが発生せず、グローバルロックは必要ありません。

ノート2: スレーブデバイスは、特定のストリーム（例4）でリンクに送信されるすべてのチャンネルを受信するように設定される場合があります。または、データのサブセットのみを受信するように設定される場合もあります（例3）。スレーブデバイスの設定は、SoundWireサブシステムAPIではなく、snd_soc_dai_set_tdm_slot() APIによって行われます。プラットフォームまたはマシンドライバは、どのスロットが使用されるかを通常設定します。例4では、すべてのデバイスが同じスロットを使用しますが、例3ではスレーブデバイス1は例えばスロット0、スレーブデバイス2はスロット1を使用します。

ノート3: 複数のシンクポートは、SoundWireフレーム内の同じビットスロットで同じ情報を抽出できますが、複数のソースポートは異なるビットスロット設定で構成される必要があります。これはI2S/PCM TDMの使用における同じ制限です。

SoundWire ストリーム管理フロー¶

ストリーム定義¶

  1. 現在のストリーム: これは、準備、有効化、無効化、解除などの操作が行われるストリームとみなされます。

  2. アクティブストリーム: これは、現在のストリーム以外のバスで既にアクティブなストリームとみなされます。バス上には複数のアクティブストリームがある場合があります。

SoundWireバスは、SoundWireバス上でレンダリングまたはキャプチャされる各ストリームの操作を管理します。このセクションでは、バス上で割り当てられたり解放されたりした各オーディオストリームに対するバス操作について説明します。以下は、バスが各オーディオストリームに保持するストリーム状態です。

SoundWire ストリーム状態¶

以下にSoundWireストリーム状態と状態遷移ダイアグラムを示します。

+-----------+     +------------+     +----------+     +----------+
| ALLOCATED +---->| CONFIGURED +---->| PREPARED +---->| ENABLED  |
|   STATE   |     |    STATE   |     |  STATE   |     |  STATE   |
+-----------+     +------------+     +---+--+---+     +----+-----+
                                         ^  ^              ^
                                         |  |              |
                                       __|  |___________   |
                                      |                 |  |
                                      v                 |  v
         +----------+           +-----+------+        +-+--+-----+
         | RELEASED |<----------+ DEPREPARED |<-------+ DISABLED |
         |  STATE   |           |   STATE    |        |  STATE   |
         +----------+           +------------+        +----------+

ノート: 状態間の遷移 SDW_STREAM_ENABLED および SDW_STREAM_DISABLED は、ALSA/ASoCレベルでINFO_PAUSEフラグがサポートされている場合にのみ関連します。同様に、 SDW_DISABLED_STATE および SDW_PREPARED_STATE の間の遷移はINFO_RESUMEフラグに依存します。

ノート2: フレームワークは基本的な状態遷移チェックを実装していますが、特定のプラットフォームでDISABLEDからENABLEDへの遷移が有効かどうかなどのチェックは行いません。このようなテストはALSA/ASoCレベルで追加する必要があります。

ストリーム状態操作¶

以下は、ストリーム状態遷移の一部としてバスがマスターやスレーブに実行する操作について説明します。

SDW_STREAM_ALLOCATED¶

ストリームの割当状態。これはストリームの初期状態です。この状態に入る前の操作:

  1. ストリームのランタイムが割り当てられます。このストリームランタイムは、ストリームに対するすべての操作の参照として使用されます。

  2. ストリームの実行時情報の保持に必要なリソースは割り当てられ、初期化されます。これは、ストリームタイプ（PCM/PDM）やパラメータ、ストリームに関連するマスターアンドスレーブインターフェース、ストリーム状態などのすべてのストリーム関連情報を保持します。

上記のすべての操作が成功した後、ストリーム状態は SDW_STREAM_ALLOCATED.

バスは、ストリームを割り当てるための以下のAPIを実装しており、1つのストリームごとに1回呼び出されます。ASoC DPCMフレームワークでは、このストリーム状態が.startup()操作とリンクされています。

int sdw_alloc_stream(char * stream_name);

SoundWireコアは、通常、ダイリンク.startup()コールバック中に呼び出されるsdw_startup_stream()というヘルパーファンクションを提供します。このファンクションは、ストリームに接続されているすべてのDAIのストリームポインタを割り当て、ストリームの割り当てと設定を行います。

SDW_STREAM_CONFIGURED¶

ストリームの設定状態。この状態に入る前の実行操作:

  1. SDW_STREAM_ALLOCATED状態で割り当てられたストリーム情報のリソースはここに更新されます。これは、ストリームパラメータ、現在のストリームに関連するマスターアンドスレーブの実行時情報などが含まれます。

  2. 現在のストリームに関連するすべてのマスターアンドスレーブは、バスにポート情報を提供します。これは、マスターアンドスレーブが現在のストリームに割り当てたポート番号と、チャネルマスクを含みます。

上記のすべての操作が成功した後、ストリーム状態は SDW_STREAM_CONFIGURED.

バスは、CONFIG状態用の以下のAPIを実装しており、ストリームに関連するそれぞれのマスターアンドスレーブによって1回呼び出されます。これらのAPIは、それぞれのマスターアンドスレーブによって1回のみ呼び出されます。ASoC DPCMフレームワークでは、このストリーム状態は.hw_params()操作とリンクされています。

int sdw_stream_add_master(struct sdw_bus * bus,
              struct sdw_stream_config * stream_config,
              struct sdw_ports_config * ports_config,
              struct sdw_stream_runtime * stream);

int sdw_stream_add_slave(struct sdw_slave * slave,
              struct sdw_stream_config * stream_config,
              struct sdw_ports_config * ports_config,
              struct sdw_stream_runtime * stream);

SDW_STREAM_PREPARED¶

ストリームの準備状態。この状態に入る前の実行操作:

  1. リザーブ操作の場合は、ステップ1とステップ2は省略され、バス帯域幅が既知です。

  2. 帯域幅、フレーム形状、クロック周波数などのバスパラメータは、現在のストリームおよびバス上の既にアクティブなストリーム（複数可能）に基づいて計算されます。現在のストリームをバス上に適切に配置するため、再計算が必要です。

  3. フレーム形状とクロック周波数に基づいて、すべてのマスターアンドスレーブのポートのトランスポートおよびポートパラメータが現在のストリームおよび既にアクティブなストリームに対して計算されます。

  4. 計算されたバスおよびトランスポートパラメータは、マスターアンドスレーブのレジスタにプログラミングされます。バンクレジスタのプログラミングは、現在使用されていない代替バンク（bank）で行われます。既にアクティブなストリームのポートは、代替バンク（bank）で有効化されます。これは、既にアクティブなストリームの動作を妨げないためです。

  5. すべての値がプログラミングされた後、バスは代替バンクへのスイッチを開始し、すべての新しい値が効力を発揮します。

  6. 現在のストリームのマスターおよびスレーブのポートは、PrepareCtrlレジスタをプログラミングすることで準備されます。

上記のすべての操作が成功した後、ストリーム状態は SDW_STREAM_PREPARED.

バスはPREPARE状態用の以下のAPIを実装しており、ストリームごとに1回呼び出さなければなりません。ASoC DPCMフレームワークでは、このストリーム状態は.prepare()操作にリンクされています。.trigger()操作が必ずしも.follow()するとは限らないため、直接的な遷移が許可されます。 SDW_STREAM_PREPARED に（木の下から葉に向かって） SDW_STREAM_DEPREPARED が許可されます。

int sdw_prepare_stream(struct sdw_stream_runtime * stream);

SDW_STREAM_ENABLED¶

ストリームの有効状態。この状態に移行するとデータポートが有効になります。この状態に入る前の操作:

  1. SDW_STREAM_PREPARED状態で計算されたすべての値は代替バンク（現在使用されていないバンク）にプログラミングされます。これにはすでにアクティブなストリームのプログラミングも含まれます。

  2. 現在のストリームのすべてのマスターおよびスレーブポートは、代替バンク（現在使用されていないバンク）にChannelEnレジスタをプログラミングすることで有効になります。

  3. すべての値がプログラミングされた後、バスは代替バンクへのスイッチを開始し、すべての新しい値が効力を発揮し、現在のストリームに関連するポートが有効になります。

上記のすべての操作が成功した後、ストリーム状態は SDW_STREAM_ENABLED.

バスはENABLE状態用の以下のAPIを実装しており、ストリームごとに1回呼び出さなければなりません。ASo, C DPCMフレームワークでは、このストリーム状態は.trigger()開始操作にリンクされています。

int sdw_enable_stream(struct sdw_stream_runtime * stream);

SDW_STREAM_DISABLED¶

ストリームの無効状態。この状態から退出するとデータポートが無効になります。この状態に入る前の操作:

  1. 現在のストリームのすべてのマスターおよびスレーブポートは、代替バンク（現在使用されていないバンク）にChannelEnレジスタをプログラミングすることで無効になります。

  2. バスおよびアクティブなストリームの現在の設定はすべて代替バンク（現在使用されていないバンク）にプログラミングされます。

  3. すべての値がプログラミングされた後、バスは代替バンクへのスイッチを開始し、すべての新しい値が効力を発揮し、現在のストリームに関連するポートが無効になります。

上記のすべての操作が成功した後、ストリーム状態は SDW_STREAM_DISABLED.

バスはDISABLED状態用の以下のAPIを実装しており、ストリームごとに1回呼び出さなければなりません。ASoC DPCMフレームワークでは、このストリーム状態は.trigger()停止操作にリンクされています。

INFO_PAUSEフラグがサポートされている場合、直接的な遷移が可能です SDW_STREAM_ENABLED が許可されます。

ASoCが.prepare()コールバックを使用して再開操作を行う場合、ストリームは SDW_STREAM_DISABLED に（木の下から葉に向かって） SDW_STREAM_PREPAREDに遷移できます。すべての必要な設定が復元されますが、バンド幅とビット割当の更新は行いません。

int sdw_disable_stream(struct sdw_stream_runtime * stream);

SDW_STREAM_DEPREPARED¶

ストリームのデプレッパード状態。この状態に入る前の操作:

  1. 現在のストリームに関連するマスターやスレーブのポートすべてが、PrepareCtrlレジスタをプログラミングすることでデプレッパード状態になります。

  2. 現在のストリームのペイロード帯域幅は、バスの総帯域幅要件から減少し、バンクスイッチなどの実行によって新しいパラメータが計算・適用されることで、総帯域幅要件が減少します。

上記のすべての操作が成功した後、ストリーム状態は SDW_STREAM_DEPREPARED.

バスはDEPREPARED状態用に以下のAPIを実装しており、ストリームごとに1回呼び出す必要があります。ALSA/ASoCでは「デプレッパード」という概念は存在せず、このストリーム状態をALSA/ASoCの操作にマッピングする際は実装に依存します。

INFO_PAUSEフラグがサポートされている場合、ストリーム状態は.hw_free()操作と関連付けられ、TRIGGER_STOPではストリームがデプレッパードされません。

他の実装では、TRIGGER_STOP時に SDW_STREAM_DEPREPARED 状態に遷移する場合があります。遷移が必要な場合は、 SDW_STREAM_PREPARED 状態です。

int sdw_deprepare_stream(struct sdw_stream_runtime * stream);

SDW_STREAM_RELEASED¶

ストリームのリリース状態。この状態に入る前の操作:

  1. 現在のストリームに関連するすべてのマスターやスレーブのポートのリソースを解放します。

  2. 現在のストリームに関連するマスターやスレーブのランタイムリソースを解放します。

  3. 現在のストリームに関連するストリームランタイムリソースを解放します。

上記のすべての操作が成功した後、ストリーム状態は SDW_STREAM_RELEASED.

バスはRELEASE状態用に以下のAPIを実装しており、ストリームに関連するすべてのマスターやスレーブが呼び出す必要があります。ASoC DPCMフレームワークでは、このストリーム状態は.hw_free()操作と関連付けられます。

int sdw_stream_remove_master(struct sdw_bus * bus,
              struct sdw_stream_runtime * stream);
int sdw_stream_remove_slave(struct sdw_slave * slave,
              struct sdw_stream_runtime * stream);

.shutdown() ASoC DPCM操作では、ALOCATED状態で割り当てられたストリームを解放するためにバスAPIを呼び出します。

.shutdown()では、ストリーム状態を保持するデータ構造が解放されます。

void sdw_release_stream(struct sdw_stream_runtime * stream);

SoundWireコアは、通常dailink .shutdown()コールバック中に呼び出されるsdw_shutdown_stream()ヘルパー関数を提供しており、すべてのDAISに接続されたストリームのストリームポインタをクリアし、ストリーム用に割り当てられたメモリを解放します。

サポートされていません¶

  1. 単一のポートで複数のチャネルをサポートする場合、2つのストリーム間やストリーム間で使用することはできません。たとえば、4チャネルを持つポートは、理論上SoundWireでは2つの独立したステレオストリームを処理可能ですが、実際には使用できません。
