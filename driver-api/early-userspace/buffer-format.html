initramfs バッファ形式¶

Al Viro, H. Peter Anvin

最終修正日: 2002-01-13

カーネル2.5.x以降では、古い「初期ramdisk」プロトコルは新しい「初期ramfs」(initramfs)プロトコルで置き換えられたり補完されたりします。initramfsの内容はinitrdプロトコルで使用される同じメモリバッファプロトコルを使用しますが、内容は異なります。initramfsバッファにはアーカイブが含まれており、これはramfsファイルシステムに展開されます。このドキュメントではinitramfsバッファ形式の形式について詳述します。

initramfsバッファ形式は「newc」または「crc」CPIO形式に基づいており、cpio(1)ユーティリティで作成できます。CPIOアーカイブはgzip(1)を使用して圧縮可能です。したがって、initramfsバッファの有効なバージョンの一つは単一の.cpio.gzファイルです。

initramfsバッファの完全な形式は以下の文法で定義されています。ここで:

*       is used to indicate "0 or more occurrences of"
(|)     indicates alternatives
+       indicates concatenation
GZIP()  indicates the gzip(1) of the operand
ALGN(n) means padding with null bytes to an n-byte boundary

initramfs  := ("\0" | cpio_archive | cpio_gzip_archive)*

cpio_gzip_archive := GZIP(cpio_archive)

cpio_archive := cpio_file* + (<nothing> | cpio_trailer)

cpio_file := ALGN(4) + cpio_header + filename + "\0" + ALGN(4) + data

cpio_trailer := ALGN(4) + cpio_header + "TRAILER!!!\0" + ALGN(4)

人間の言葉で説明すると、initramfsバッファには圧縮および/または未圧縮のCPIOアーカイブ（「newc」または「crc」形式）のコレクションが含まれており、メンバーの間にゼロバイト（パディング用）を任意の量追加できます。

CPIOの「TRAILER!!!」エントリ（アーカイブ終端）はオプションですが、無視されません。ハードリンクの処理については下記を参照してください。

CPIOヘッダの構造は以下の通りです（すべてのフィールドは左にゼロを補ってフィールドの全幅に満たす16進数のASCII文字列で表されます。たとえば、整数4780はASCII文字列「000012ac」として表されます）:

c_modeフィールドは、Linuxのstat(2)で返すst_modeの内容と一致し、ファイルタイプとファイルパーミッションをエンコードする。

正規ファイルやシンボリックリンクでないファイルのc_filesizeはゼロでなければならない。

c_chksumフィールドには、データフィールド内のすべてのバイトを合計した32ビットの符号なし和が含まれる。cpio(1)ではこれを「crc」と呼ぶが、これは明らかに誤り（サイクルレジディスタンシー検査は異なるより強力な整合性検査である）が、このアルゴリズムが使用されている。

ファイル名が「TRAILER!!!」の場合、これは実際のアーカイブの終わりを示すマーカーである。アーカイブの終わりを示すマーカーのc_filesizeはゼロでなければならない。

ハードリンクの処理¶

非ディレクトリでc_nlink > 1のファイルが見られた場合、(c_maj,c_min,c_ino)のタプルがタプルバッファで検索される。見つからない場合はタプルバッファに登録し通常のエントリを作成する。見つかった場合は、ファイルの二重コピーではなくハードリンクを作成する。ファイルの二重コピーを含める必要はない（ただし許可されている）。ファイルの内容を含まない場合は、c_filesizeフィールドをゼロに設定してデータセクションがないことを示す。データが存在する場合は、前のファイルインスタンスが上書きされる。これにより、データを保持するファイルインスタンスがシーケンスのどこでも出現可能になる（GNU cpioは、ファイルの最後のインスタンスにのみデータを付けると報告されている）。

シンボリックリンクのc_filesizeはゼロであってはならない。

「TRAILER!!!」のアーカイブ終わりマーカーが見られた場合、タプルバッファがリセットされる。これにより、独立して生成されたアーカイブを連結できる。

異なるソースからのファイルデータを組み合わせる（(c_maj,c_min,c_ino)フィールドを再生成せずに）には、以下のいずれかの技術を用いることができる：

  1. 異なるファイルデータソースを「TRAILER!!!」のアーカイブ終わりマーカーで区切る、または

  2. すべての非ディレクトリエントリでc_nlink == 1を確保する。
