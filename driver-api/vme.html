VMEデバイスドライバ¶

ドライバ登録¶

Linux Kernel内の他のサブシステムと同様に、VMEデバイスドライバーはVMEサブシステムに登録されます。これは通常、デバイスの初期化ルーチンから呼び出されます。これは以下の呼び出しを通じて実現されます。 vme_register_driver().

構造体タイプのポインタ struct vme_driver 登録関数に提供する必要があります。これに加えて、ドライバーがサポートできる最大のデバイス数も指定する必要があります。

少なくとも、’.name’、’.match’、’.probe’要素を正しく設定する必要があります。 struct vme_driver ’.name’要素は、デバイスドライバーの名前を保持する文字列へのポインタです。

’.match’関数は、ドライバーに登録するべきVMEデバイスを制御します。デバイスがスキャンされるべき場合は1を、そうでない場合は0を返す必要があります。この例のマッチ関数（vme_user.cから）は、スキャンされるデバイスの数を1に制限します：

#define USER_BUS_MAX    1
...
static int vme_user_match(struct vme_dev *vdev)
{
        if (vdev->id.num >= USER_BUS_MAX)
                return 0;
        return 1;
}

’.probe’要素には、プローブルーティンへのポインタを含める必要があります。プローブルーティンには struct vme_dev ポインタを引数として渡す。

ここで、'num' フィールドはこの特定のドライバの順序付いたデバイスIDを指します。ブリッジ番号（またはバス番号）は dev->bridge->num を使ってアクセスできます。

VMEコアからドライバをアンレジストするための関数も提供されています。 vme_unregister_driver() 通常はデバイスドライバのエクスイットルーティンから呼び出されるべきです。

リソース管理¶

ドライバがVMEコアに登録されると、登録時に指定された回数だけマッチルーティンが呼び出されます。マッチが成功した場合、ゼロ以外の値を返す必要があります。ゼロを返すと失敗とみなされます。すべての成功したマッチに対して、対応するドライバのプローブルーティンが呼び出されます。プローブルーテイニングはデバイス構造体へのポインタを渡され、このポインタは保存しておく必要があります。これはVMEリソースを要求するために必要です。

ドライバは1つまたは複数のマスターウィンドウ（vme_master_request()）、スレーブウィンドウ（vme_slave_request()）および/またはDMAチャネル（vme_dma_request())。デバイスドライバーが特定のウィンドウまたはDMAチャネルを要求するのではなく（これは他のドライバーによって使用される可能性がある）、APIはドライバーの必要な属性に基づいてリソースを割り当てます。スレーブウィンドウでは、これらの属性は'aspace'でアクセスが必要なVMEアドレス空間と'cycle'で必要なVMEバスサイクルタイプに分割されます。マスターウィンドウはさらに'width'でデータ転送幅を指定する属性を追加します。これらの属性はビットマスクとして定義され、1つのウィンドウに対して属性の任意の組み合わせを要求できます。コアは要件を満たすウィンドウを割り当て、vme_resource型のポインタを返します。このポインタは割り当てられたリソースを識別するために使用します。DMAコントローラーでは、転送の潜在的な方向をルート属性で提供する必要があります。これは通常VME-to-MEMおよび/またはMEM-to-VMEですが、一部のハードウェアではVME-to-VMEやMEM-to-MEMの転送やテストパターン生成もサポートします。要件に合致する未割り当てのウィンドウが見つからない場合、NULLポインタが返されます。

不要になった後でウィンドウの割り当てを解放する関数も提供されています。これらは（vme_master_free(), vme_slave_free() および vme_dma_free())に、リソース割り当て時に提供されたポインタを渡す必要があります。

マスターウインドウ¶

マスターウィンドウはローカルプロセッサからVMEバスへのアクセスを提供します。利用可能なウィンドウ数とアクセスモードは基盤となるチップセットに依存します。ウィンドウは使用する前に設定する必要があります。

マスターウィンドウの設定¶

マスターウィンドウが割り当てられた後 vme_master_set() を用いて設定でき、 vme_master_get() で現在の設定を取得できます。アドレス空間、転送幅、サイクルタイプはリソース管理で説明したとおりですが、一部のオプションは排他的です。たとえば、1つのアドレス空間のみを指定できます。

マスターウィンドウのアクセス¶

を返す関数です。 vme_master_read() を用いて読み取りができ、 vme_master_write() で設定されたマスターウィンドウに書き込みできます。

単純な読み取りと書き込みに加え、 vme_master_rmw() を用いて読み取り-変更-書き込みトランザクションを実行できます。VMEウィンドウの一部はさらにユーザー空間メモリにマッピングできます。 vme_master_mmap().

スレーブウインドウ¶

スレーブウィンドウはVMEバス上のデバイスにローカルメモリのマッピングされた部分へのアクセスを提供します。利用可能なウィンドウ数とアクセスモードは基盤となるチップセットに依存します。ウィンドウは使用する前に設定する必要があります。

スレーブウィンドウの設定¶

スレーブウィンドウが割り当てられた後 vme_slave_set() を用いて設定でき、 vme_slave_get() 現在の設定を取得する。

アドレス空間、転送幅およびサイクルタイプはリソース管理で説明した内容と同様ですが、一部のオプションは排他的です。たとえば、1つのアドレス空間のみを指定できます。

スレーブウィンドウバッファの割当¶

ユーザーがバッファを割当てるための関数が提供されています（vme_alloc_consistent()）および解放（vme_free_consistent()）連続バッファを提供します。これらの関数は必ず使用する必要はなく、他の方法でもバッファを割当てることが可能です。ただし、連続であり、VMEブリッジからアクセス可能であることを確認する必要があります。

スレーブウィンドウアクセス¶

スレーブウィンドウはローカルメモリをVMEバスにマッピングし、標準的なメモリアクセス方法を使用する必要があります。

DMAチャネル¶

VME DMA転送はリンクリストDMA転送を実行する機能を提供します。APIはDMAリストという概念を導入しています。各DMAリストはDMAコントローラーに渡すことができるリンクリストです。複数のリストは作成、拡張、実行、再利用、破壊が可能です。

リスト管理¶

を返す関数です。 vme_new_dma_list() 作成および削除のために提供されています。 vme_dma_list_free() DMAリストの削除のために提供されています。リストの実行はリストを自動的に破壊しないので、繰り返しのタスクにリストを再利用できるようにします。

リストの構築¶

リストに項目を追加するには vme_dma_list_add() （この関数を呼び出す前に、ソースと宛先属性を作成する必要があります。これは「転送属性」セクションで説明されています。）

注意

DMAリストに項目が追加されるまで、転送のソースと宛先の詳細な属性はチェックされません。DMAチャネルのリクエストは、コントローラーがデータを転送する方向を純粋に確認します。結果として、この呼び出しがエラーを返す可能性があります。たとえば、ソースまたは宛先がサポートされていないVMEアドレス空間にある場合です。

転送属性¶

ソースと宛先の属性は、リストに項目を追加する操作とは別に処理されます。これは、各タイプのソースと宛先に必要な属性が多様なためです。PCI、VME、パターンのソースと宛先（適切な場合）の属性を作成する関数があります：

  • PCIソースまたは宛先： vme_dma_pci_attribute()

  • VMEソースまたは宛先： vme_dma_vme_attribute()

  • パターンソース： vme_dma_pattern_attribute()

を返す関数です。 vme_dma_free_attribute() 属性を解放するために使用する必要があります。

リストの実行¶

を返す関数です。 vme_dma_list_exec() リストを実行のためにキューイングし、リストが実行された後に返します。

割込み¶

VME APIは、特定のVMEレベルとステータスIDの組み合わせにコールバックをアタッチおよびデタッチする機能、および特定のVMEレベルとステータスIDを持つVME割込みを生成する機能を提供します。

割込みハンドラのアタッチ¶

を返す関数です。 vme_irq_request() 割込みハンドラをアタッチおよびデタッチするために使用できます。 vme_irq_free() 特定のVMEレベルとステータスIDの組み合わせを解放するための機能です。任意の組み合わせは1つのコールバック関数にのみ割り当てられます。voidポインタパラメータが提供され、その値がコールバック関数に渡されます。このポインタの使用はユーザー定義です。コールバック関数のパラメータは以下の通りです。コールバック関数を記述する際には注意が必要です。コールバック関数は割込みコンテキストで実行されます。

void callback(int level, int statid, void *priv);

割込み生成¶

を返す関数です。 vme_irq_generate() 指定されたVMEレベルとVMEステータスIDでVME割込みを生成できます。

ロケーションモニタ¶

VME APIはロケーションモニタの設定に以下の機能を提供します。

ロケーションモニタ管理¶

を返す関数です。 vme_lm_request() ロケーションモニタのブロックの使用を要求し、 vme_lm_free() 必要なくなった後でそれらを解放するための機能が提供されます。各ブロックは隣接するロケーションを監視する複数のロケーションモニタを提供できます。関数 vme_lm_count() 提供されるロケーション数を確認するために使用できます。

ロケーションモニタ設定¶

ロケーションモニタのブロックが割り当てられた後、関数 vme_lm_set() ロケーションモニタのロケーションとモードを設定するための機能が提供されます。関数 vme_lm_get() 既存の設定を取得するために使用できます。

ロケーションモニタ使用¶

を返す関数です。 vme_lm_attach() コールバックのアタッチを可能にし、 vme_lm_detach() 各ロケーションモニタロケーションからonを分離できます。各ロケーションモニタは複数の隣接ロケーションを監視できます。コールバック関数は以下の通り宣言されます。

void callback(void *data);

スロット検出¶

を返す関数です。 vme_slot_num() 提供されたブリッジのスロットIDを返します。

バス検出¶

を返す関数です。 vme_bus_num() 提供されたブリッジのバスIDを返します。

struct vme_dev¶

VMEデバイスを表す構造体

定義

struct vme_dev {
  int num;
  struct vme_bridge *bridge;
  struct device dev;
  struct list_head drv_list;
  struct list_head bridge_list;
};

メンバ

num

デバイス番号

bridge

このデバイスが属するブリッジデバイスへのポインタ

dev

内部デバイス構造

drv_list

ドライバごとのデバイス一覧

bridge_list

ブリッジごとのデバイス一覧

struct vme_driver¶

VMEドライバを表す構造体

定義

struct vme_driver {
  const char *name;
  int (*match)(struct vme_dev *);
  int (*probe)(struct vme_dev *);
  int (*remove)(struct vme_dev *);
  struct device_driver driver;
  struct list_head devices;
};

メンバ

name

ドライバ名、VMEドライバの中で一意でなければなりません。通常はモジュール名と同じです。

match

プローブが実行されるかどうかを判定するためのコールバック

probe

デバイスバインディング用のコールバック、新しいデバイスが検出されたときに呼び出されます。

remove

デバイス削除時に呼び出されるコールバック

driver

下位の汎用デバイスドライバ構造体

devices

このドライバに関連するVMEデバイス一覧（struct vme_dev）
