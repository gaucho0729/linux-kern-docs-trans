汎用カウンタインターフェース¶

はじめに¶

カウンタデバイスは多様な産業分野に広く存在しており、これらのデバイスの ubiquity により、共通のインターフェースと標準的な相互作用・露出が求められます。このドライバAPIは、既存のカウンタデバイスドライバ間で見られる重複コードの問題を解決するために、ジェネリックカウンタインターフェースを導入し、ドライバが共通のコンポーネントと機能をサポート・露出できるようにします。

理論¶

カウンタデバイスは設計が大きく異なりますが、四象限エンコーダーカウンタであれカウントデバイスであれ、すべてのカウンタデバイスはコアなコンポーネントセットを備えています。このコアなコンポーネントセットが、ジェネリックカウンタインターフェースの本質を形成しています。

カウンタには3つのコアなコンポーネントがあります:

  • シグナル: カウンタが評価するデータストリーム。

  • シナプス: シグナルと評価トリガー、カウントとの関連付け。

  • カウント: 関連付けられたシナプスの効果の蓄積。

SIGNAL¶

シグナルはデータストリームを表します。これはカウンタがカウントデータを決定するために評価する入力データです。例えば、回転エンコーダーの四象限信号出力ラインなど。すべてのカウンタデバイスがユーザーにシグナルデータへのアクセスを提供するわけではなく、ドライバでは露出がオプションです。

シグナルデータがユーザーにアクセス可能である場合、ジェネリックカウンタインターフェースは以下のシグナル値を提供します:

  • SIGNAL_LOW: シグナルラインが低電圧状態です。

  • SIGNAL_HIGH: シグナルラインが高電圧状態です。

シグナルは1つまたは複数のカウントに関連付けられます。

SYNAPSE¶

シナプスはシグナルとカウントの関連付けを表します。シグナルデータはそれぞれのカウントデータに影響を与え、シナプスはこの関係を表します。

シナプスアクションモードは、シグナルデータの条件を指定し、対応するカウントのカウント機能評価をトリガーしてカウントデータを更新します。ジェネリックカウンタインターフェースは以下のアクションモードを提供します:

  • None: シグナルがカウント機能をトリガーしません。パルス-方向カウント機能モードでは、このシグナルは方向として評価されます。

  • Rising Edge: 低電圧状態から高電圧状態への遷移。

  • Falling Edge: 高電圧状態から低電圧状態への遷移。

  • Both Edges: 任意の状態遷移。

カウンターとは、関連する入力信号の状態をそれぞれのカウント関数によって評価した結果として生成されるカウントデータと関連する入力信号の集合を指します。ジェネリック・カウンターインターフェースの文脈において、カウンターは、それぞれのカウントに関連する信号の集合を伴うカウントから構成されます。そのシナプスインスタンスは、関連するカウントのカウント関数更新条件を表します。

シナプスは、1つのシグナルを1つのカウントに関連付けます。

カウント¶

カウントは、接続されたシナプスの影響の蓄積を表します。つまり、シグナルの集合のカウントデータを指します。ジェネリック・カウンターインターフェースは、カウントデータを自然数として表現します。

カウントは、カウントデータの更新動作を表すカウント関数モードを持っています。ジェネリック・カウンターインターフェースは、以下の可用カウント関数モードを提供します：

  • インクリメント: 積算されたカウントが増加します。

  • デクリメント: 積算されたカウントが減少します。

  • パルス方向: シグナルAの立ち上がりエッジがそれぞれのカウントを更新します。入力レベルのシグナルBが方向を決定します。

  • クォーダチュア: クォーダチュア符号化シグナルのペアを評価し、位置と方向を決定します。以下のクォーダチュアモードが利用可能です：

    • x1 A: 方向が前進の場合、クォーダチュアペアシグナルAの立ち上がりエッジがそれぞれのカウントを更新します。方向が後退の場合、クォーダチュアペアシグナルAの立ち下がりエッジがそれぞれのカウントを更新します。クォーダチュア符号化が方向を決定します。

    • x1 B: 方向が前進の場合、クォーダチュアペアシグナルBの立ち上がりエッジがそれぞれのカウントを更新します。方向が後退の場合、クォーダチュアペアシグナルBの立ち下がりエッジがそれぞれのカウントを更新します。クォーダチュア符号化が方向を決定します。

    • x2 A: クォーダチュアペアシグナルAの任意の状態変化がそれぞれのカウントを更新します。クォーダチュア符号化が方向を決定します。

    • x2 B: クォーダチュアペアシグナルBの任意の状態変化がそれぞれのカウントを更新します。クォーダチュア符号化が方向を決定します。

    • x4: クォーダチュアペアシグナルのいずれかの状態変化がそれぞれのカウントを更新します。クォーダチュア符号化が方向を決定します。

カウントは、1つ以上の関連するシナプスの集合を持っています。

パラダイム¶

最も基本的なカウンター機器は、シナプスを介して1つのシグナルと1つのカウントを関連付けることで表現されます。例えば、ソース入力ラインの立ち上がりエッジのカウントを蓄積する単純なカウンター機器を考えてみましょう：

        Count                Synapse        Signal
        -----                -------        ------
+---------------------+
| Data: Count         |    Rising Edge     ________
| Function: Increase  |  <-------------   / Source \
|                     |                  ____________
+---------------------+

この例では、Signalはパルス電圧を持つソース入力ラインであり、Countは繰り返しインクリメントされる持続的なカウント値です。Signalはシナプスを介してそれぞれのCountに関連付けられます。シナプスで指定されたSignalデータ条件によって増加関数がトリガーされます。この場合、電圧入力ラインの立ち上がりエッジ条件です。要約すると、カウンター機器の存在と動作はそれぞれCount、Signal、シナプスコンポーネントによって適切に表現されています。立ち上がりエッジ条件が累積カウントデータの増加関数をトリガーします。

カウンター機器は単一のSignalに限定されません。実際、理論上は複数のSignalが単一のCountに関連付けられることがあります。例えば、クォーダチュアエンコーダーのカウンター機器は、2つの入力ラインの状態に基づいて位置を追跡できます。

           Count                 Synapse     Signal
           -----                 -------     ------
+-------------------------+
| Data: Position          |    Both Edges     ___
| Function: Quadrature x4 |  <------------   / A \
|                         |                 _______
|                         |
|                         |    Both Edges     ___
|                         |  <------------   / B \
|                         |                 _______
+-------------------------+

この例では、2つのSignal（クォーダチュアエンコーダーのラインAとB）が単一のCountに関連付けられています。AまたはBのいずれかで立ち上がりまたは下降エッジが発生すると、「クォーダチュアx4」関数がトリガーされ、移動方向を決定し、それぞれの位置データを更新します。「クォーダチュアx4」関数は、クォーダチュアエンコーダーのカウンター機器のハードウェアで実装されている可能性があります。Count、Signal、シナプスはこのハードウェアの動作と機能を表現しています。

同じCountに関連付けられたSignalは、異なるシナプスアクションモード条件を持つことがあります。例えば、クォーダチュアモードで動作しないパルス・ディレクションモードのクォーダチュアエンコーダーのカウンター機器は、1つの入力ラインを移動用、もう1つの入力ラインを方向用に割り当てることがあります。

           Count                   Synapse      Signal
           -----                   -------      ------
+---------------------------+
| Data: Position            |    Rising Edge     ___
| Function: Pulse-Direction |  <-------------   / A \ (Movement)
|                           |                  _______
|                           |
|                           |       None         ___
|                           |  <-------------   / B \ (Direction)
|                           |                  _______
+---------------------------+

Signal Aのみが「パルス・ディレクション」更新関数をトリガーしますが、Signal Bの瞬時的な状態は方向を把握するために必要であり、位置データを適切に更新するために重要です。結局、両方のSignalは2つのシナプスを介して同じCountに関連付けられていますが、1つのシナプスのみがアクティブなアクションモード条件を持ち、カウント関数をトリガーし、もう1つは「なし」条件アクションモードに設定されており、そのSignalの状態評価の可用性を示しています。

Signal、Synapse、Countは抽象的な表現であり、物理的なソースと密接に関連する必要はありません。これにより、カウンターユーザーは物理的なコンポーネント（入力ラインが差動か単端かなど）のニュアンスから距離を置き、データとプロセスが表す核心的な概念（例えば、クォーダチュアエンコーディングデータから解釈される位置）に集中できます。

ユーザースペースインターフェース¶

ジェネリックカウンターインターフェースによって複数のsysfs属性が生成され、/sys/bus/counter/devices/counterXディレクトリに存在します（counterXはそれぞれのカウンターデバイスを指します）。詳細な情報についてはDocumentation/ABI/testing/sysfs-bus-counterを参照してください。

これらのsysfs属性を通じて、プログラムやスクリプトはそれぞれのカウンターデバイスのジェネリックカウンターのカウント、シグナル、シナプスと対話できます。

ドライバAPI¶

ドライバ開発者は、include/linux/counter.hヘッダーファイルをインクルードすることでジェネリックカウンターインターフェースをコード内で利用できます。このヘッダーファイルにはカウンターデバイスを定義するための主要なデータ構造、関数プロトタイプ、マクロが含まれています。

struct signal_enum_ext¶

シグナルエナム拡張属性

定義

struct counter_signal_enum_ext {
  const char * const *items;
  size_t num_items;
  int (*get)(struct counter_device *counter, struct counter_signal *signal, size_t *item);
  int (*set)(struct counter_device *counter, struct counter_signal *signal, size_t item);
};

メンバ

items

文字列の配列

num_items

に指定されたアイテム数 items

get

取得コールバック関数；NULLを指定することも可能です

set

設定コールバック関数；NULLを指定することも可能です

説明

counter_signal_enum_ext構造体は、列挙型スタイルのSignal拡張属性を実装するために使用できます。列挙型スタイルの属性とは、文字列の集合が符号なし整数値にマッピングされている属性のことです。汎用的なカウンターシグナル列挙型拡張ヘルパーコードは、値と文字列のマッピング処理を担うほか、「_available」ファイルを生成して、すべての利用可能な項目の一覧を保持します。getコールバックは現在アクティブな項目を照会するために使用され、'item'パラメータを通じて該当項目の配列内のインデックスが返されます。setコールバックは属性が更新されたときに呼び出され、'item'パラメータには該当項目の配列内の新しいアクティブ項目のインデックスが含まれます。

struct counter_ops {
  int (*signal_read)(struct counter_device *counter,struct counter_signal *signal, enum counter_signal_value *val);
  int (*count_read)(struct counter_device *counter, struct counter_count *count, unsigned long *val);
  int (*count_write)(struct counter_device *counter, struct counter_count *count, unsigned long val);
  int (*function_get)(struct counter_device *counter, struct counter_count *count, size_t *function);
  int (*function_set)(struct counter_device *counter, struct counter_count *count, size_t function);
  int (*action_get)(struct counter_device *counter,struct counter_count *count, struct counter_synapse *synapse, size_t *action);
  int (*action_set)(struct counter_device *counter,struct counter_count *count, struct counter_synapse *synapse, size_t action);
};

メンバ

signal_read

オプションのシグナル属性読み取りコールバック。対応するシグナルの読み取り値は「val」パラメータを通じて返されます。

count_read

オプションのカウント属性読み取りコールバック。対応するカウントの読み取り値は「val」パラメータを通じて返されます。

count_write

オプションのカウント属性書き込みコールバック。対応するカウントの書き込み値は「val」パラメータを通じて渡されます。

function_get

現在のカウント機能モードを取得する関数。成功時は0を、エラー時は負のエラーコードを返します。対応するカウントの返却された機能モードのインデックスは「function」パラメータを通じて返されます。

function_set

カウント機能モードを設定する関数。「function」は対応するカウントのfunctions_list配列から要求された機能モードのインデックスです。

action_get

現在のアクションモードを取得する関数。成功時は0を、エラー時は負のエラーコードを返します。対応するシンパゼスの返却されたアクションモードのインデックスは「action」パラメータを通じて返されます。

action_set

アクションモードを設定する関数。「action」は対応するシンパゼスのactions_list配列から要求されたアクションモードのインデックスです。

カウンターデバイスをサポートするには、ドライバはまずcounter_signal構造体を介して利用可能なカウンタースイグナルを割り当てなければなりません。これらのスイグナルは配列として保存し、カウンターデバイス構造体のsignals配列メンバに設定してから、カウンターがシステムに登録される必要があります。

カウンターカウントはcounter_count構造体を介して割り当てられ、それぞれのカウンタースイグナルの関連付け（シナプス）はcounter_synapse構造体を介して行われます。関連するcounter_synapse構造体は配列として保存し、それぞれのcounter_count構造体のsynapses配列メンバに設定します。これらのcounter_count構造体は、カウンターがシステムに登録される前に、割り当てられたcounter_device構造体のcounts配列メンバに設定します。

ドライバのコールバックは、counter_ops構造体を介してcounter_device構造体に提供される必要があります。これにより、デバイスと通信し、各種のスイグナルおよびカウントの読み書き、およびシナプスおよびカウントの「アクションモード」および「機能モード」の設定・取得が可能になります。

定義されたcounter_device構造体は、counter_register関数に渡してシステムに登録され、counter_unregister関数に渡して登録を解除します。同様に、デバイスメモリ管理での登録が必要な場合は、devm_counter_registerおよびdevm_counter_unregister関数を使用できます。

補助機能やデータ用の拡張sysfs属性は、定義されたcounter_device_ext、counter_count_ext、counter_signal_ext構造体を渡すことで作成できます。この場合、counter_device_ext構造体は、それぞれのカウンターデバイスのグローバル/汎用的な露出と設定に使用され、counter_count_extおよびcounter_signal_ext構造体は、特定のカウントまたはスイグナルの補助的な露出と設定が可能です。

拡張タイプを決定するには、スコープの問題です。

  • スイグナル拡張は、特定のスイグナルに関する情報/制御を露出する属性です。このような属性は、sysfs内のスイグナルディレクトリ下に存在します。

    たとえば、スイグナルにインバート機能がある場合、スイグナル拡張として「invert」という名前の属性を作成して、その機能を切り替えることができます: /sys/bus/counter/devices/counterX/signalY/invert

  • カウント拡張は、特定のカウントに関する情報/制御を露出する属性です。このような属性は、sysfs内のカウントディレクトリ下に存在します。

    たとえば、カウントの更新を一時停止/再開したい場合、"enable"という名前のカウント拡張機能を使用して切り替えることができます。例: /sys/bus/counter/devices/counterX/countY/enable

  • デバイス拡張機能は、特定のカウントまたはシグナルに特化しない情報を公開・制御する属性です。ここにグローバルな機能やその他の雑多な機能を配置します。

    たとえば、デバイスに過熱センサーがある場合、"error_overtemp"という名前のデバイス拡張機能を使用してチップの過熱を報告できます。例: /sys/bus/counter/devices/counterX/error_overtemp

アーキテクチャ¶

ジェネリックカウンターインターフェースのカウンターモジュールがロードされる際、counter_init関数が呼び出され、"counter"という名前のバスタイプがシステムに登録されます。その後、モジュールがアンロードされる際、counter_exit関数が呼び出され、"counter"という名前のバスタイプがシステムから登録解除されます。

カウンター機器はcounter_register関数を通じてシステムに登録され、後でcounter_unregister関数を通じて削除されます。counter_register関数はカウンター機器に一意のIDを割り当て、対応するsysfsディレクトリを作成します。ここでXは指定された一意のIDです:

/sys/bus/counter/devices/counterX

counterXディレクトリ内にsysfs属性が作成され、カウンター機器のカウント、シグナル、シナプスに関する機能、設定、データ、および機器自体のオプションや情報を公開します。

各シグナルには、関連するsysfs属性を格納するディレクトリが作成され、Yはそれぞれのシグナルの一意のIDです:

/sys/bus/counter/devices/counterX/signalY

同様に、各カウントには、関連するsysfs属性を格納するディレクトリが作成され、Yはそれぞれのカウントの一意のIDです:

/sys/bus/counter/devices/counterX/countY

ジェネリックカウンターインターフェースの利用可能なsysfs属性についてのより詳細な説明は、Documentation/ABI/testing/sysfs-bus-counterファイルを参照してください。

カウンターデバイスに関連するシグナルおよびカウントは、counter_register関数によってシステムに登録されます。signal_read/signal_writeドライバコールバックはそれぞれのシグナル属性に関連付けられ、count_read/count_writeおよびfunction_get/function_setドライバコールバックはそれぞれのカウント属性に関連付けられます。同様に、action_get/action_setドライバコールバックもそれぞれのシナプス属性に関連付けられます。ドライバコールバックが未定義の場合は、関連する属性の読み書き許可が無効になります。

同様に、定義されたcounter_device_ext、counter_count_ext、counter_signal_ext構造体が渡されるたびに、拡張sysfs属性が作成されます。
