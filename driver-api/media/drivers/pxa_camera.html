8.1.8. PXA-Camera ホストドライバー¶

著者: Robert Jarzmik <robert.jarzmik@free.fr>

8.1.8.1. 制約¶

  1. YUV422P形式の画像サイズ 全てのYUV422P画像は幅×高さが16の倍数である必要があります。これはDMA制約により、8バイトの倍数のみを転送するためです。

8.1.8.2. グローバルなビデオワークフロー¶

  1. QCI停止 初期状態ではQCIインターフェースは停止しています。バッファがキューイングされる（pxa_videobuf_ops->buf_queue）と、QCIが開始されます。

  2. QCI開始 QCIが開始されている間でも、キャプチャを停止せずに新たなバッファをキューイングできます。新しいバッファはDMAチェーンの末尾に「追加」され、1フレームずつスムーズにキャプチャされます。

    QCIインターフェースでバッファが満たされると、「完了（DONE）」と判定され、アクティブなバッファリストから削除されます。その後、ユーザー空間アプリケーションによって再キューイングまたはデキューイングが可能です。

    最後のバッファが満たされると、QCIインターフェースは停止します。

  3. キャプチャのグローバルな有限状態機械のスキーマ

+----+                             +---+  +----+
| DQ |                             | Q |  | DQ |
|    v                             |   v  |    v
+-----------+                     +------------------------+
|   STOP    |                     | Wait for capture start |
+-----------+         Q           +------------------------+
+-> | QCI: stop | ------------------> | QCI: run               | <------------+
|   | DMA: stop |                     | DMA: stop              |              |
|   +-----------+             +-----> +------------------------+              |
|                            /                            |                   |
|                           /             +---+  +----+   |                   |
|capture list empty        /              | Q |  | DQ |   | QCI Irq EOF       |
|                         /               |   v  |    v   v                   |
|   +--------------------+             +----------------------+               |
|   | DMA hotlink missed |             |    Capture running   |               |
|   +--------------------+             +----------------------+               |
|   | QCI: run           |     +-----> | QCI: run             | <-+           |
|   | DMA: stop          |    /        | DMA: run             |   |           |
|   +--------------------+   /         +----------------------+   | Other     |
|     ^                     /DMA still            |               | channels  |
|     | capture list       /  running             | DMA Irq End   | not       |
|     | not empty         /                       |               | finished  |
|     |                  /                        v               | yet       |
|   +----------------------+           +----------------------+   |           |
|   |  Videobuf released   |           |  Channel completed   |   |           |
|   +----------------------+           +----------------------+   |           |
+-- | QCI: run             |           | QCI: run             | --+           |
| DMA: run             |           | DMA: run             |               |
+----------------------+           +----------------------+               |
        ^                      /           |                           |
        |          no overrun /            | overrun                   |
        |                    /             v                           |
+--------------------+         /   +----------------------+               |
|  Frame completed   |        /    |     Frame overran    |               |
+--------------------+ <-----+     +----------------------+ restart frame |
| QCI: run           |             | QCI: stop            | --------------+
| DMA: run           |             | DMA: stop            |
+--------------------+             +----------------------+

Legend: - each box is a FSM state
        - each arrow is the condition to transition to another state
        - an arrow with a comment is a mandatory transition (no condition)
        - arrow "Q" means : a buffer was enqueued
        - arrow "DQ" means : a buffer was dequeued
        - "QCI: stop" means the QCI interface is not enabled
        - "DMA: stop" means all 3 DMA channels are stopped
        - "DMA: run" means at least 1 DMA channel is still running

8.1.8.3. DMA 使用¶

  1. DMAフロー

    • 最初のバッファがキャプチャ用にキューイングされたとき QCIは開始されますが、データ転送は開始されません。「フレーム終了（End Of Frame）」割込みが発生すると、IRQハンドラがDMAチェーンを開始します。

    • 1つのビデオバッファのキャプチャ DMAチェーンがビデオバッファのRAMページにデータを転送を開始します。すべてのページが転送されると、「ENDINTR」状態でDMA IRQが発生します。

    • 1つのビデオバッファの完了 DMA IRQハンドラがビデオバッファを「完了（DONE）」と判定し、アクティブな実行キューから削除します。同時に、次のビデオバッファ（存在すれば）がDMAで転送されます。

    • 最後のビデオバッファの完了 最後のビデオバッファのDMA IRQで、QCIが停止します。

  2. DMA準備済みバッファはこの構造を持ちます

+------------+-----+---------------+-----------------+
| desc-sg[0] | ... | desc-sg[last] | finisher/linker |
+------------+-----+---------------+-----------------+

この構造はdma->sg_cpuによって指されます。ディスクリプタは以下のよう使用されます：

  • desc-sg[i]: i番目のディスクリプタ、i番目のsg要素をビデオバッファスキャッターガatherに転送します

  • フィニッシャー: ddadr=DADDR_STOP、dcmd=ENDIRQEN

  • リンカー：ddadr=次のビデオバッファのdesc-sg[0]、dcmd=0

次のスキーマでは、d0=desc-sg[0] .. dN=desc-sg[N]とし、「f」はフィニッシャー、「l」はリンカーを表します。典型的な実行チェーンは以下の通り：

    Videobuffer 1         Videobuffer 2
+---------+----+---+  +----+----+----+---+
| d0 | .. | dN | l |  | d0 | .. | dN | f |
+---------+----+-|-+  ^----+----+----+---+
                 |    |
                 +----+

チェインが完了すると、チェインは以下のようになります：

    Videobuffer 1         Videobuffer 2         Videobuffer 3
+---------+----+---+  +----+----+----+---+  +----+----+----+---+
| d0 | .. | dN | l |  | d0 | .. | dN | l |  | d0 | .. | dN | f |
+---------+----+-|-+  ^----+----+----+-|-+  ^----+----+----+---+
                 |    |                |    |
                 +----+                +----+
                                      new_link

  1. DMAホットチェインのタイムスライス問題

DMAチェインはDMAが実行中に行われるため、DMAが1つのビデオバッファから次のものへジャンプする間にリンクが行われる可能性があります。このスキーマでは、以下のシーケンスが発生した場合問題になります：

  • DMAチェインはビデオバッファ1 + ビデオバッファ2

  • pxa_videobuf_queue()がビデオバッファ3をキューイングするために呼び出されます

  • DMAコントローラーがビデオバッファ2を終了し、DMAが停止します

 =>
    Videobuffer 1         Videobuffer 2
+---------+----+---+  +----+----+----+---+
| d0 | .. | dN | l |  | d0 | .. | dN | f |
+---------+----+-|-+  ^----+----+----+-^-+
                 |    |                |
                 +----+                +-- DMA DDADR loads DDADR_STOP

  • pxa_dma_add_tail_buf()が呼び出され、ビデオバッファ2の「フィニッシャー」がビデオバッファ3への「リンカー」に置き換えられます（新しいリンカーの作成）

  • pxa_videobuf_queue()が終了します

  • DMA IRQハンドラが呼び出され、ビデオバッファ2の終了が処理されます

  • Videobuffer3のキャプチャがDMAチェーンにスケジュールされていません（停止しているため！！！）

    Videobuffer 1         Videobuffer 2         Videobuffer 3
+---------+----+---+  +----+----+----+---+  +----+----+----+---+
| d0 | .. | dN | l |  | d0 | .. | dN | l |  | d0 | .. | dN | f |
+---------+----+-|-+  ^----+----+----+-|-+  ^----+----+----+---+
                 |    |                |    |
                 +----+                +----+
                                      new_link
                                     DMA DDADR still is DDADR_STOP

  • pxa_camera_check_link_miss()が呼び出されます。これはDMAが完了し、バッファがpcdev->captureリストにまだ存在しているかを確認します。その場合、キャプチャが再開され、Videobuffer3がDMAチェーンにスケジュールされます。

  • DMA IRQハンドラが終了します

注意

pxa_camera_check_link_miss()がDDADR()の値を読み取った直後にDMAが停止した場合、DMAがバッファを処理し終えるときにDMA IRQハンドラが再び呼び出されることが保証されます。これにより、Videobuffer3が再スケジュールされます。
