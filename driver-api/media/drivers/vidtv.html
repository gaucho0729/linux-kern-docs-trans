8.2.3. vidtv: バーチャルデジタルTVドライバー¶

Author: Daniel W. S. Almeida <dwlsalmeida@gmail.com>, 2020年6月。

8.2.3.1. 背景¶

Vidtvは、ドライバーライターが参考にするテンプレートとしての役割を果たす仮想DVBドライバーであり、既存のメディアDVB APIの検証を行うことで、ユーザースペースアプリケーションの開発者にも支援を提供します。

現在、vidtvには以下のコンポーネントが含まれています：

  • 仮想チューナードライバーは、選択された周波数が特定の配信システムの有効周波数テーブルから遠すぎる場合、悪い信号品質を報告します。

  • 仮想デモッドライバーは、チューナーから返す仮想信号品質を連続的に確認し、CNRレベルに応じて信号ロックを失ったり再取得したりするデバイスをシミュレートします。

  • 仮想ブリッジドライバーは、仮想チューナーおよびデモッドライバーをモジュールとしてロードし、デマルチプレクサの論理を実装する責任があります。このモジュールは初期化時にシミュレーションの挙動を決定するパラメータを受け取ります。

  • 有効なMPEGトランスポートストリームをエンコードするコードがあり、これはブリッジドライバーに渡されます。この仮想ストリームにはハードコードされたコンテンツが含まれており、現在は単一のオーディオのみのチャンネルが存在します。このチャンネルにはSMPTE 302mで符号化されたサインウェーブが含まれています。このエンコーダーが選ばれた理由は、PCMオーディオデータをMPEGトランスポートストリームにエンコードする最も簡単な方法だからです。

8.2.3.2. vidtvのビルド¶

vidtvはテストドライバーであり、 ではありません カーネルをコンパイルする際、デフォルトで有効になります。

vidtvのコンパイルを有効にするには、

  • Enable DVB_TEST_DRIVERS、ならば

  • Enable DVB_VIDTV

モジュールとしてコンパイルされた場合、以下の.koファイルが生成されます：

  • dvb_vidtv_tuner.ko

  • dvb_vidtv_demod.ko

  • dvb_vidtv_bridge.ko

8.2.3.3. vidtvの実行¶

モジュールとしてコンパイルされた場合、以下を実行します：

modprobe vidtv

これで完了です！ブリッジドライバーは自身の初期化中にチューナーおよびデモッドライバーを初期化します。

デフォルトでは以下の周波数を受信します：

  • DVB-T/T2/C用：474 MHz

  • DVB-S/S2用：11,362 GHz

衛星システムでは、ドライバーはKuバンドの周波数範囲（10.7 GHzから12.75 GHz）を持つユニバーサル拡張LNBfをシミュレートします。

vidtvにコマンドライン引数をオプションで定義できます。

8.2.3.4. vidtvのコマンドライン引数¶

以下はvidtvに渡せるすべての引数の一覧です：

drop_tslock_prob_on_low_snr

信号品質が悪い場合にTSロックを失う確率。この確率は、信号品質が悪いときに仮想デモッドライバーがステータス0を返すように使用されます。

recover_tslock_prob_on_good_snr:

信号が改善した際にTSロックを回復する確率。この確率は、フェイクデモデューラードライバーが信号品質が改善した場合に0x1fのステータスを最終的に返すために使用されます。

mock_power_up_delay_msec

電源投入遅延をシミュレートします。デフォルト: 0。

mock_tune_delay_msec

チューニング遅延をシミュレートします。デフォルト 0。

vidtv_valid_dvb_t_freqs

シミュレートする有効なDVB-T周波数（Hz単位）。

vidtv_valid_dvb_c_freqs

シミュレートする有効なDVB-C周波数（Hz単位）。

vidtv_valid_dvb_s_freqs

Kuバンドでシミュレートする有効なDVB-S/S2周波数（kHz単位）。

max_frequency_shift_hz,

チャンネルチューニング時の許容される最大周波数シフト（Hz単位）。

si_period_msec

SIパケットを送信する間隔。デフォルト: 40ms。

pcr_period_msec

PCRパケットを送信する間隔。デフォルト: 40ms。

mux_rate_kbytes_sec

必要に応じてTSヌルパケットを挿入してこのビットレートを維持しようとします。デフォルト: 4096。

pcr_pid,

すべてのチャンネル用のPCR PID。デフォルト: 0x200。

mux_buf_sz_pkts,

MUXバッファのサイズ（188バイト単位で指定）。

8.2.3.5. vidtv内部構造¶

カーネルモジュールは以下のようになっています:

vidtv_tuner.[ch]

フェイクチューナーDVBドライバーの実装。

vidtv_demod.[ch]

フェイクデモデューラーDVBドライバーの実装。

vidtv_bridge.[ch]

ブリッジドライバーの実装。

MPEG関連のコードは以下のようになっています:

vidtv_ts.[ch]

MPEG TSパケット（TSヘッダ、アダプテーションフィールド、PCRパケット、NULLパケットなど）を処理するコード。

vidtv_psi.[ch]

これはPSIジェネレータです。PSIパケットはMPEGトランスポートストリームに関する一般的な情報を含み、ユーザー空間アプリケーションがトランスポートストリームの情報を取得し、最終的に（ダミー）チャンネルにチューニングするためには必要です。

ジェネレータが別ファイルで実装されているため、メディアサブシステムの他の場所でも再利用可能です。

現在、vidtvはPAT、PMT、SDT、NIT、EITの5つのPSIテーブルを処理できます。

PATおよびPMTの仕様は ISO 13818-1: Systems、SDT、NIT、EITの仕様は以下の通りです ETSI EN 300 468: DVBシステムにおけるサービス情報（SI）の仕様.

必須ではありませんが、デバッグ時のPSIテーブルの確認にTSファイルを使用すると便利です。Vidtvはこのファイルに含まれるPSI構造を再現しようと試みています: TS1Globo.ts.

ストリームの構造を可視化するには、 DVBInspector.

vidtv_pes.[ch]

エンコーダーのデータをMPEG TSパケットに変換するPES論理を実装しています。これらはその後TS多重化処理に供され、最終的にユーザー空間に届けられます。

vidtv_encoder.h

Vidtvエンコーダーのインターフェースです。新しいエンコーダーはこのドライバでこのファイルの関数を実装することで追加できます。

vidtv_s302m.[ch]

PCMオーディオデータを生成されたMPEG Transport Streamに挿入するためのS302Mエンコーダーを実装しています。関連する仕様は以下に掲載されています SMPTE 302M-2007: テレビ - AES3データのMPEG-2 Transport Streamへのマッピング.

生成されたMPEG Elementary Streamは、S302M登録記述子を添えてプライベートストリームで送信されます。

これによりユーザー空間にオーディオ信号を渡し、メディアソフトウェアでデコード・再生が可能になります。ffmpegにおける対応デコーダーは「libavcodec/s302m.c」にあり、実験的です。

vidtv_channel.[ch]

「チャンネル」の抽象化を実装しています。

Vidtvが起動すると、ハードコードされたいくつかのチャンネルが作成されます:

  1. これらのサービスはSDTを構成するために連結されます。

  2. これらのプログラムはPATを構成するために連結されます

  3. これらのイベントはEITを構成するために連結されます

  4. PAT内の各プログラムに対応するPMTセクションが作成されます

  5. チャンネルのPMTセクションにはそのストリームが割り当てられます

  6. すべてのストリームは、ループで対応するエンコーダーからTSパケットを生成し、これらは多重化処理によって交差され、ブリッジに届けられます。

vidtv_mux.[ch]

MPEG TS多重化処理を実装しており、ffmpegの「libavcodec/mpegtsenc.c」に準拠しています

多重化処理は以下の責任を担います:

  1. 最後の反復からの経過時間を記録する。

  2. エンコーダーを polling して「elapsed_time」分のデータを取得する。

  3. 必要に応じてPSIおよび/またはPCRパケットを挿入する。

  4. 選択されたビットレートを維持するため、NULLパケットでストリームを埋める。

  5. 生成されたTSパケットをブリッジドライバに届ける。

8.2.3.6.2. dvb-scanを使用する¶

チャンネルにチューニングし、PSIテーブルを読み取るには、dvb-scanを使用できます。

そのためには、スキャンファイルと呼ばれる設定ファイルを提供する必要があります。以下は例です:

[Channel]
FREQUENCY = 474000000
MODULATION = QAM/AUTO
SYMBOL_RATE = 6940000
INNER_FEC = AUTO
DELIVERY_SYSTEM = DVBC/ANNEX_A

注意

パラメータは、テストしているビデオ標準に依存します。

注意

Vidtvは仮想ドライバであり、スキャンファイル内の情報の多くを検証しません。DVB-T/DVB-T2の場合、'FREQUENCY'と'DELIVERY_SYSTEM'を指定するだけで十分ですが、DVB-S/DVB-Cの場合には'SYMBOL_RATE'も指定する必要があります。

スキャンテーブルをオンラインで参照できます: dvb-scan-tables.

8.2.3.7. vidtvでまだ改善できる点¶

8.2.3.7.1. 追加 debugfs integration¶

フロントエンドドライバは.read_statusコールを通じてDVBv5の統計情報を提供しますが、ユーザー空間にデバッグfsを介して追加の統計情報を提供する機能は役立ちます。debugfsはデバッグ目的に設計されたシンプルで使いやすいRAMベースのファイルシステムです。

この論理はフロントエンドドライバを汚染しないように別ファイルで実装されるべきです。これらの統計情報はドライバ固有であり、テスト中に有用です。

Sianoドライバは、debugfsを使用してドライバ固有の統計情報をユーザー空間に伝達するドライバの例であり、参照用として使用できます。

利便性のために、Kconfigオプションを通じてさらに有効化および無効化する必要があります。

8.2.3.7.2. ビデオをテストする方法を追加する¶

現在、vidtvはPCMオーディオのみをエンコードできます。MPEG-2ビデオエンコードのシンプルなバージョンを実装してビデオもテストできるようにするといいでしょう。最初に確認すべき場所は ISO 13818-2: 情報技術 — 動画および関連するオーディオ情報の一般的な符号化 — 第2部: 動画、これはMPEGトランスポートストリームにおける圧縮ビデオの符号化をカバーしています。

これはオプションでVideo4Linux2テストパターンジェネレータ（v4l2-tpg）を使用する場合があり、その位置は:

drivers/media/common/v4l2-tpg/

8.2.3.7.3. ホワイトノイズのシミュレーションを追加する¶

vidtvチューナーには、選択した周波数が有効な周波数テーブルから遠すぎるかどうかを識別するコードがあります。現時点では、このためチューナーが悪質な信号品質を報告し、デモデュレータが最終的に信号のロックを失う可能性があります。

信号品質が悪いときにノイズをシミュレートするには:

  • TSパケットをランダムにドロップする。これは連続カウンタが更新されてもパケットがデマルチケーターに渡されない場合、連続エラーをトリガーします。

  • エラー統計を適切に更新する（例: BERなど）。

  • 符号化されたデータ内の一部のノイズをシミュレートする。

struct vidtv_channel¶

「チャンネル」の抽象化

定義

struct vidtv_channel {
  char *name;
  u16 transport_stream_id;
  struct vidtv_psi_table_sdt_service *service;
  u16 program_num;
  struct vidtv_psi_table_pat_program *program;
  struct vidtv_psi_table_pmt_stream *streams;
  struct vidtv_encoder *encoders;
  struct vidtv_psi_table_eit_event *events;
  struct vidtv_channel *next;
};

メンバ

name

チャンネルの名前

transport_stream_id

TSを識別するための番号で、任意に選択されます。

service

単一のサービス。SDTに連結されます。

program_num

PAT、PMT、SDTの間のリンク。

program

単一のプログラムで、1つまたは複数のストリームに関連付けられます。PATに連結されます。

streams

「プログラム」のPMTセクションを埋めるストリームループ

encoders

エンコーダーのループ。各ストリームに1つのエンコーダーが必要です。

events

オプションのイベント情報。これはEITにフィードされます。

next

このチャンネルをオプションでチェーンします。

説明

vidtvが起動する際には、ハードコードされたチャンネルが作成されます。これらのサービスはSDTを埋め込むために連結され、これらの番組はPATを埋め込むために連結されます。PAT内の各番組に対してPMTセクションが作成されます。チャンネルごとのPMTセクションはそのストリームに割り当てられます。各ストリームは対応するエンコーダーにポールされTSパケットを生成します。これらのパケットはmuxによってインターレースされる可能性があり、その後ブリッジに配信されます
