8.1.1. bttvドライバ¶

8.1.1.1. bttvとサウンド ミニハウトゥー¶

bt848/849/878/879ベースのボードは多く存在します。ビデオの動作を実現するのは通常大変ではありません。なぜなら、これはbt8xxチップが完全に処理するからです。このチップはすべてのボードで共通しています。しかし、サウンドの処理は各ボードでやや異なる方法で行われます。

グリッパーボードを正しく処理するには、btt,ttv-cards.cに存在するtvcards[]配列が各ボードに必要な情報を保持しています。サウンドは正しいエントリが使用されている場合にのみ動作します（ビデオでは通常違いはありません）。bttvドライバはカーネルログに表示され、使用しているカードタイプを示します。例えば以下のように表示されます：

bttv0: model: BT848(Hauppauge old) [autodetected]

この情報が正しいか確認してください。正しいボードタイプをinsmod引数として渡す必要があります、 insmod bttv card=2 たとえば。ファイル BTTVカード一覧 はカード用の有効な引数の一覧を保持しています。

そのリストにあなたのカードが含まれていない場合、新しいエントリがまだリストされていない可能性があるため、ソースコードを確認してみてください。あなたのカード用のエントリがなければ、既存のエントリのうちどれかが動作するかどうかを試してみる必要があります（単なる試行錯誤です…）。

一部のボードには、ステレオデコードやその他の便利な機能を実行するためのサウンド用の追加プロセッサが搭載されています。たとえばHauppaugeではmsp34xxチップが使用されています。ボードにこのようなチップがある場合、サウンドを動作させるために補助モジュールをロードする必要があるかもしれません。 msp3400 サウンドが動作しない場合は、チップに該当するモジュールが存在しない可能性があります。不運ですね。新しいモジュールを書く必要があります。ただし、まずはvideo4linuxメールリストアーカイブを確認することをおすすめします…

もちろん、スピーカーをキャプチャボードに直接接続していない限り、正しくインストールされたサウンドカードが必要です。ヒント：ミキサー設定も確認してください。たとえばALSAではデフォルトですべてミュートされています。

8.1.1.1.1. サウンドの詳細な仕組み¶

それでも動作しない場合は、ドライバのカスタマイズが必要かもしれません。以下に自己完結型の説明を示します。

bt8xxチップには32の汎用ピンと、これらのピンを制御するレジスタがあります。そのうちの1つは出力有効レジスタ（BT848_GPIO_OUT_EN）で、bt848チップによってアクティブに駆動されるピンを指定します。もう1つはデータレジスタ（BT848_GPIO_DATA）で、これらのピンのステータスを取得/設定可能です。入力と出力の両方で使用できます。

ほとんどのキャプチャボードメーカーは、これらのピンを外部チップのサウンドルーティング制御に使用しています。ただし、すべてのボードは多少異なります。一部のメーカーでは、これらのピンはリモコン受信チップを駆動するためにも使用されています。一部のボードではGPIOピンではなく、I2CバスをMUXチップに接続するために使用しています。

上記のように、各既知のボードに対応する必要情報を保持する配列があります。基本的に、自分のボード用に新しい行を作成する必要があります。重要なフィールドはこれら2つです。

struct tvcard
{
      [ ... ]
      u32 gpiomask;
      u32 audiomux[6]; /* Tuner, Radio, external, internal, mute, stereo */
};

gpiomaskは、オーディオMUXチップを制御するピンを指定します。出力有効レジスタ（BT848_GPIO_OUT_EN)の対応するビットは、これらのピンがbt848チップによって駆動する必要があるため、設定されます。

以下の audiomux[] 配列は、さまざまな入力（つまり、チューナー/ミュート/…などにどのピンがハイ/ローになるか）のデータ値を保持します。これはデータレジスタ（BT848_GPIO_DATA)に書き込まれてオーディオMUXを切り替えます。

行うべきことは、gpiomaskとaudiomux配列の正しい値を特定することです。Windowsとカード用ドライバーがインストールされている場合、Windowsドライバーが使用するレジスタ値を確認するのも役立ちます。このような作業を行うためのツールは、 http://btwincap.sourceforge.net/download.html.

You might also dig around in the *.ini files of the Windows applications. You can have a look at the board to see which of the gpio pins are connected at all and then start trial-and-error …

バージョン0.7.41から、bttvはgpioデバッグを容易にするinsmodオプションをいくつか追加しました:

bttv_gpio=0/1

gpioデバッグメッセージを有効/無効にする

gpiomask=n

gpiomask値を設定

audiomux=i,j,…

audiomux配列の値を設定

audioall=a

audiomux配列の値を設定（配列要素すべてに同じ値を設定し、特定の値の影響を確認するのに便利）。

以下のようになります: bttv_gpio=1 look like this:

bttv0: gpio: en=00000027, out=00000024 in=00ffffd8 [audio: off]

en  =   output _en_able register (BT848_GPIO_OUT_EN)
out =   _out_put bits of the data register (BT848_GPIO_DATA),
        i.e. BT848_GPIO_DATA & BT848_GPIO_OUT_EN
in  =   _in_put bits of the data register,
        i.e. BT848_GPIO_DATA & ~BT848_GPIO_OUT_EN
