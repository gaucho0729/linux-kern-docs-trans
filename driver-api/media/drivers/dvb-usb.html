8.2.1. dvb-usbフレームワークのコンセプト¶

注意

  1. このドキュメントは古くなりました。最新情報はDVB Wikiで確認してください https://linuxtv.org/wiki https://www.linuxtv.org/wiki/index.php/DVB_USB

  2. 非推奨: 新しいDVB USBドライバーはdvb-usb-v2フレームワークを使用すべきです。

2005年3月に、新しいTwinhan USB2.0 DVB-Tデバイスを入手しました。彼らは仕様書とファームウェアを提供してくれました。

ドライバーをdibusbに組み込むことにかなり興味がありました（もちろんいくつかの特殊な処理は必要です）。しかし、いくつかの仕様を読み、USBの通信を監視した結果、dibusbドライバーはその後完全に混乱してしまいます。そのため、異なるアプローチを取ることにしました：dvb-usbフレームワークを活用した方法です。

フレームワークは汎用的な機能（主にカーネルAPIの呼び出し）を提供します。例えば：

  • トランスポートストリームURBの処理とdvb-demux-feed-controlとの連携（バーストおよびアイソクロナスがサポートされています）

  • DVB-APIへのデバイス登録

  • I2Cアダプタの登録（必要に応じて）

  • リモコン/入力デバイスの処理

  • ファームウェアのリクエストとロード（現在はCypress USBコントローラー専用です）

  • 複数のドライバーで共有可能な他の機能/メソッド（バーストコントロールコマンドなどの機能）

  • TODO: I2Cチャンカー。レジスタアクセスのデバイス固有のチャンクを、レジスタ長と複数書き込み/読み込み可能な値数に応じて生成します。

特定のDVB USBデバイスのソースコードはバス経由でのデバイス通信を担当します。DVB-API機能との接続は、静的デバイス記述（struct dvb_usb_device）で割り当てられたコールバックを介して行われます。

例としてdrivers/media/usb/dvb-usb/vp7045*を参照してください。

目標は、すべてのUSBデバイス（dibusb、cinergyT2、おそらくttusb；flexcop-usbは既に汎用flexcopデバイスから恩恵を受けています）がdvb-usb-libを使用することです。

8.2.1.2. 使い方¶

8.2.1.2.1. ファームウェア¶

ほとんどのUSBドライバは、デバイスにファームウェアをダウンロードしてから動作します。

DVB-USBドライバのWikiページを確認し、ご使用のデバイスに必要なファームウェアを確認してください：

https://linuxtv.org/wiki/index.php/DVB_USB

8.2.1.2.2. コンパイル¶

ドライバがLinuxカーネルに含まれているため、お好みの設定環境でドライバーを有効にすることで十分です。ドライバをモジュールとしてコンパイルすることをお勧めします。ホットプラグで残りの作業を行います。

dvb-kernelを使用する場合は、build-2.6ディレクトリに移動し、'make'を実行した後、'insmod.sh load'を実行してください。

8.2.1.2.3. ドライバのロード¶

ホットプラグは、デバイスを接続した際にドライバを自動的にロードします。

デバッグ出力を有効にする場合は、手動でドライバをロードし、dvb-kernel cvsリポジトリ内から実行する必要があります。

まず、利用可能なデバッグレベルを確認してください：

# modinfo dvb-usb
# modinfo dvb-usb-vp7045

etc.

modprobe dvb-usb debug=<level>
modprobe dvb-usb-vp7045 debug=<level>
etc.

これでうまくいくはずです。

ドライバが正常にロードされ、ファームウェアファイルが正しい場所にあり、デバイスが接続されている場合、『電源』LEDが点灯するはずです。

この時点で、DVB対応アプリケーションを起動できるはずです。私は(t|s)zap、mplayer、dvbscanで基本的な動作をテストしています。VDR-xineは長期的なテストシナリオとして使用しています。

8.2.1.3. 既知の問題とバグ¶

  • DVBアプリケーションを実行中にUSBデバイスを外すと、システムが異常終了する可能性があります。

8.2.1.3.2. USB1.1 バンド幅制限¶

現在サポートされているデバイスの多くはUSB1.1であり、USB2.0ハブに接続すると最大で約5〜6 MBit/sの帯域幅しかありません。これはDVB-Tチャンネルのトランスポートストリーム（約16 MBit/s）を受信するには十分ではありません。通常、テレビ視聴（HDTVは除く）だけであれば問題ありませんが、同じ周波数で別のチャンネルを録画しながら視聴することはできません。これはすべてのUSB1.1 DVB-Tデバイスに当てはまります。

デバイスの重い使用によってTSが歪むというバグは完全に解消されました。私が使用していたすべてのdvb-usb-devices（Twinhan、Kworld、DiBcom）はVDRで正常に動作しており、時には録画しながら別のチャンネルを視聴することもできました。
