3. リモートコントローラーデバイス¶

3.1. リモートコントローラー コア¶

リモートコントローラー コアは、リモートコントローラーのキーボード入力やマウスイベントの受信・送信に必要なインフラストラクチャを実装しています。

リモートコントローラーでキーが押されたたびにスキャンコードが生成されます。また、ほとんどのハードウェアでは、キーを数十ミリ秒以上押し続けると繰り返しのキーイベントが生成されます。これは、Linux上で通常のキーボードやマウスが内部的に処理する仕組みと類似しています。1したがって、リモートコントローラー コアはLinuxのinput/evdevインターフェース上に実装されています。

1

主な違いは、キーボードイベントではキーボードコントローラーがキー押下とキーリリースそれぞれに対してイベントを生成するのに対し、赤外線ベースのリモートコントローラーではキーリリースイベントは存在せず、代わりにキー繰り返しを示す追加のコードが生成される点です。

ただし、ほとんどのリモートコントローラーは赤外線（IR）を用いて信号を送信します。赤外線信号をモジュレーションするための複数のプロトコルが存在するため、コアの重要な一部は、ドライバとコアシステムを、送信機が使用する赤外線プロトコルに対応させる調整を行います。

赤外線送信は、キャリアを使用して赤外線エミッタを点滅させることで行われます。キャリアはIR送信機のハードウェアによってオンまたはオフに切り替えられます。キャリアがオンになると、 パルスと呼ばれます。キャリアがオフになると、 スペース.

と呼ばれます。つまり、典型的なIR送信は、それぞれの所定の持続時間を持つ パルス および スペース イベントのシーケンスとして見ることができます。

キャリアパラメータ（周波数、デューティー比）および パルス および スペース イベント間のインターバルはプロトコルによって異なります。例えば、NECプロトコルでは38kHzのキャリアを用い、送信は9msの パルス と4.5msのスペースで開始します。その後、16ビットのスキャンコードを送信します。これは8ビットのアドレス（通常は特定のリモートコントローラーごとに固定値）と8ビットのコードから構成され、ビット「1」は560µs パルス の後で1690µs スペース でモジュレーションされ、ビット「0」は560µs パルス の後で560µs スペース.

でモジュレーションされます。受信側では、低域通過フィルタを用いて受信信号を パルス/スペース イベントのシーケンスに変換できます。これにより、受信側はキャリア周波数の実際のパラメータに興味を持たず、すべてのイベントの受信時間のみを測定する必要があります。したがって、シンプルなIR受信機ハードウェアは、これらのイベントのタイミングをカーネルに提供します。このような受信機を持つハードウェアのドライバは、 パルス/スペース として定義されています。 RC_DRIVER_IR_RAW、として定義されています。 rc_driver_type2他のハードウェアは、シーケンスをデコードしてスキャンコードをカーネルに返すマイクロコントローラーが搭載されています。 パルス/スペース シーケンスをデコードし、スキャンコードをカーネルに返します。このような受信機は RC_DRIVER_SCANCODE.

2

RCコアは、受信機を搭載せずにIRエミッタのみを備えたデバイスもサポートしています。現在、このようなすべてのデバイスはraw TXモードでのみ動作します。このようなハードウェアは RC_DRIVER_IR_RAW_TX.

RCコアがイベントを受信する際、 RC_DRIVER_IR_RAW IR受信機から生成されたイベントを受信すると、IRプロトコルをデコードして対応するスキャンコードを取得する必要があります。RCコアがサポートするプロトコルは、enumで定義されています。 rc_proto.

RCコードがスキャンコードを受信する際（直接、またはドライバのタイプ RC_DRIVER_SCANCODE、またはIRデコーダ経由で受信した場合）、Linuxの入力イベントコードに変換する必要があります。これはマッピングテーブルを介して行われます。

カーネルは、ほとんどのメディアデバイスでマッピングテーブルをサポートしています。また、sysfsノードを介してランタイムにテーブルをロードすることもサポートしています。詳しくは、 RCユーザースペースAPI 詳細についてはこちら。
