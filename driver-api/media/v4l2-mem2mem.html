1.21. V4L2 メモリ対メモリ機能およびデータ構造¶

struct v4l2_m2m_ops¶

mem-to-memデバイスドライバコールバック

定義

struct v4l2_m2m_ops {
  void (*device_run)(void *priv);
  int (*job_ready)(void *priv);
  void (*job_abort)(void *priv);
};

メンバ

device_run

必須。このコールバック内で実際に作業（トランザクション）を開始します。作業はこのコールバックが返る前に終了する必要はなく（通常はそうなります）。作業が終了した後、 v4l2_m2m_job_finish() または v4l2_m2m_buf_done_and_job_finish() が呼び出される必要があります。

job_ready

オプション。ドライバがまだ完全な作業を準備できていない場合（つまり、トランザクションを完了するのにスリープが必要な場合）、0を返す必要があります。提供されていない場合は、ドライバが1つのソースバッファと1つの宛先バッファだけで1つの完全なトランザクションを実行できるとみなされます。このメソッドはスリープしてはいけません。

job_abort

オプション。ドライバに現在実行中のトランザクションをできるだけ速く中止するように通知します（つまり、デバイスを安全に停止できるタイミングで）。トランザクションがその時点で完了しない場合でも、即座に中止する必要があります。ドライバが必要なステップを実行した後、 v4l2_m2m_job_finish() または v4l2_m2m_buf_done_and_job_finish() が呼び出されるようにします。この関数は、デバイスが停止できる状態になるのを待つ必要はなく（通常はそうしません）。

struct v4l2_m2m_ctx¶

メモリ対メモリコンテキスト構造体

定義

struct v4l2_m2m_ctx {
  struct mutex                    *q_lock;
  bool new_frame;
  bool is_draining;
  struct vb2_v4l2_buffer          *last_src_buf;
  bool next_buf_last;
  bool has_stopped;
  struct v4l2_m2m_dev             *m2m_dev;
  struct v4l2_m2m_queue_ctx       cap_q_ctx;
  struct v4l2_m2m_queue_ctx       out_q_ctx;
  struct list_head                queue;
  unsigned long                   job_flags;
  wait_queue_head_t finished;
  void *priv;
};

メンバ

q_lock

struct mutex lock

new_frame

device_runコールバックで有効。trueの場合は新しいフレームの開始、falseの場合は既存フレームの新しいスライスを示します。V4L2_BUF_CAP_SUPPORTS_M2M_HOLD_CAPTURE_BUFが設定されている場合を除き、常にtrueです。

is_draining

デバイスがドレインフェーズにあることを示します

last_src_buf

ドレインの最後のソースバッファを示します

next_buf_last

次のキャプチャキューのバッファに「最後」のフラグを設定します

has_stopped

デバイスが停止されていることを示します

m2m_dev

M2Mコンテキストを処理するための内部データを指すオパケポインタ

cap_q_ctx

キャプチャ（出力からメモリ）キューコンテキスト

out_q_ctx

出力（入力からメモリ）キューコンテキスト

queue

メモリ対メモリコンテキストの一覧

job_flags

ジョブキューのフラグ。v4l2-mem2mem.c内部で使用されます: TRANS_QUEUED, TRANS_RUNNING および TRANS_ABORT.

finished

ジョブキューが完了したことを通知するための待機キュー

priv

インスタンスプライベートデータ

説明

メモリ対メモリコンテキストはファイルハンドルに固有であり、デバイスなどには固有ではありません。

void v4l2_m2m_try_schedule(struct v4l2_m2m_ctx *m2m_ctx)¶

インスタンスがpending job queueに追加可能か確認し、可能であれば追加する

パラメータ

struct v4l2_m2m_ctx *m2m_ctx

構造体で指定されたインスタンスに割り当てられたm2mコンテキスト v4l2_m2m_ctx

説明

インスタンスが実行可能にするためには以下の3つの基本的な条件を満たす必要があります：1)少なくとも1つのソースバッファがキューに追加されている、2)少なくとも1つの宛先バッファがキューに追加されている、3)ストリーミングが有効になっている

キューがバッファリングされている場合（例：デコーダハードウェアリングバッファでストリームオフを行う前にドレインが必要な場合）、そのキュー上でのv4l2バッファなしでのスケジューリングを許可する

追加のカスタム要件も存在する場合があります。その場合はドライバがv4l2_m2m_opsのjob_readyコールバックを提供し、インスタンスが準備完了である場合に1を返す必要があります。例として、1つのトランザクションあたり複数のsrc/dstバッファを必要とするインスタンスが挙げられます

void v4l2_m2m_job_finish(struct v4l2_m2m_dev *m2m_dev, struct v4l2_m2m_ctx *m2m_ctx)¶

ジョブが完了したことをフレームワークに通知し、クリーンアップを実行する

パラメータ

struct v4l2_m2m_dev *m2m_dev

M2Mコンテキストを処理するための内部データを指すオパケポインタ

struct v4l2_m2m_ctx *m2m_ctx

構造体で指定されたインスタンスに割り当てられたm2mコンテキスト v4l2_m2m_ctx

説明

ドライバがデバイスを解放するために呼び出されます。デバイスが他のインスタンスの制御を許可する状態に到達した後、できるだけ早く呼び出す必要があります

この関数は、 v4l2_m2m_ops->device_run コールバックがドライバで呼び出された後だけ呼び出す必要があります。再帰を防ぐため、 v4l2_m2m_ops->device_run コールバックから直接呼び出すべきではありません

void v4l2_m2m_buf_done_and_job_finish(struct v4l2_m2m_dev *m2m_dev, struct v4l2_m2m_ctx *m2m_ctx, enum vb2_buffer_state 状態)¶

ソース/宛先バッファとその状態を返し、ジョブが完了したことをフレームワークに通知してクリーンアップを実行する

パラメータ

struct v4l2_m2m_dev *m2m_dev

M2Mコンテキストを処理するための内部データを指すオパケポインタ

struct v4l2_m2m_ctx *m2m_ctx

構造体で指定されたインスタンスに割り当てられたm2mコンテキスト v4l2_m2m_ctx

enum vb2_buffer_state state

v4l2_m2m_buf_done()に渡されるvb2バッファの状態

説明

V4L2_BUF_CAP_SUPPORTS_M2M_HOLD_CAPTURE_BUFを設定するドライバは、保持されたバッファを考慮するためにこの関数を使用する必要があります。他のドライバにはオプションです

この関数はソースバッファを準備リストから削除し、指定された状態で返します。宛先バッファについては、'held'としてマークされていない限り同様の処理を行います。'held'の場合、バッファは準備リストに残されます

その後、ジョブが完了します（job_finish()を参照）

これにより、単一のキャプチャバッファを埋める複数の出力バッファを使用できます。これは、複数の例としてH.264スライスが単一のデコードフレームに貢献する無状態デコーダで通常使用されます

ドライバのmmap()関数から呼び出されます。videobufferに対して両方のキューのmmap()をシームレスに処理し、通常のキューごとのオフセットと正しいvideobufキューのポインタを受け取ります。videobufの外側で、あるキューからのバッファに予定されたオフセットを加え、それをvideobufに戻す前に減算することで区別します。修正されたオフセットはドライバ（そしてアプリケーション）のみが受け取ります。

void v4l2_m2m_buf_copy_metadata(const struct vb2_v4l2_buffer *out_vb, struct vb2_v4l2_buffer *cap_vb, bool copy_frame_flags)¶

出力バッファからキャプチャバッファにバッファメタデータをコピーします

パラメータ

const struct vb2_v4l2_buffer *out_vb

メタデータのソースとなる出力バッファ

struct vb2_v4l2_buffer *cap_vb

メタデータを受信するキャプチャバッファ

bool copy_frame_flags

KEY/B/PFRAMEフラグもコピーします

説明

このアシスタント関数は、タイムスタンプ、タイムコード（TIMECODEバッファフラグが設定されている場合）、フィールド、およびTIMECODE、KEYFRAME、BFRAME、PFRAME、TSTAMP_SRC_MASKフラグを、 out_vb に（木の下から葉に向かって） cap_vb.

もし copy_frame_flags falseの場合、KEYFRAME、BFRAME、PFRAMEフラグはコピーされません。これは、このビットを明示的に設定するエンコーダーで通常必要です。
