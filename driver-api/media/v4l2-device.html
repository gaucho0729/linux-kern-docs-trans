1.5. V4L2デバイスインスタンス¶

各デバイスインスタンスは、 struct v4l2_device. 非常に単純なデバイスはこの構造体を割り当てることで十分ですが、ほとんどの場合、この構造体をより大きな構造体の内部に埋め込むことになります。

デバイスインスタンスを登録するには、以下の関数を呼び出さなければなりません：

v4l2_device_register (dev, v4l2_dev).

登録により、 v4l2_device 構造体が初期化されます。dev->driver_dataフィールドが NULLの場合、このフィールドが v4l2_dev 引数。

にリンクされます。メディアデバイスフレームワークと統合したいドライバは、dev->driver_dataを手動で設定して、 struct v4l2_device を指すドライバ固有のデバイス構造体を指定する必要があります。これは、V4L2デバイスインスタンスを登録する前に dev_set_drvdata() を呼び出すことで実現されます。また、 struct v4l2_device フィールドを適切に初期化・登録された media_device インスタンスを生成する必要があります。

もし v4l2_devが空の場合は、dev（ドライバ名の後にバスIDを追加した値）から導出された値に設定されます。呼び出す前に設定した場合は、変更されません。devが v4l2_device_register() の場合、 NULLを呼び出す前に grace periodsを尊重しなければなりませんし、 設定 v4l2_devを設定する必要があります。 v4l2_device_register().

使用できます v4l2_device_set_name() を呼び出すことで、ドライバ名とドライバグローバルのatomic_tインスタンスに基づいて名前を設定します。これにより、 ivtv0, ivtv1などの名前が生成されます。名前が数字で終わる場合、ハイフンが挿入されます： cx18-0, cx18-1などの形式になります。この関数はインスタンス番号を返します。

最初の dev 引数は通常、 struct device のポインタです。 pci_dev, usb_interface または platform_deviceはまれに NULLになることがあります。ISAデバイスや、1つのデバイスが複数のPCIデバイスを生成する場合など、特定の親と関連付けることができないケースがあります。 v4l2_dev を提供することもできます。

サブデバイスがイベントを通知するために呼び出すコールバックを設定することも可能です。サブデバイスがこの設定を必要とするかどうかは、サブデバイスに依存します。サブデバイスがサポートする通知は、 notify() のヘッダーファイルで定義する必要があります。 include/media/subdevice.h.

V4L2デバイスは以下の関数を呼び出すことで登録を解除されます：

v4l2_device_unregister() (v4l2_dev).

がdev->driver_dataフィールドに指している場合、 v4l2_devにリセットされます。 NULL。登録解除により、すべてのサブデバイスも自動的にデバイスから登録解除されます。

ホットプラグ可能なデバイス（例：USBデバイス）がある場合、切断が発生すると親デバイスが無効になります。 v4l2_device がその親デバイスを指しているため、親がなくなったことを示すためにもこのポインタをクリアする必要があります。これを実行するには、以下の関数を呼び出します：

v4l2_device_disconnect() (v4l2_dev).

これは ではありません サブデバイスを登録解除しないため、サブデバイスの登録解除を行うには依然として v4l2_device_unregister() 関数を呼び出す必要があります。ドライバがホットプラグ可能でない場合は、この関数を呼び出す必要はありません。 v4l2_device_disconnect().

特定のドライバによって登録されたすべてのデバイスを反復処理する必要がある場合があります。これは複数のデバイスドライバが同じハードウェアを使用する場合に通常発生します。例えば、ivtvfbドライバはframebufferドライバであり、ivtvハードウェアを使用します。ALSAドライバも同様です。

すべての登録済みデバイスを反復処理するには、以下の手順を実行します：

static int callback(struct device *dev, void *p)
{
        struct v4l2_device *v4l2_dev = dev_get_drvdata(dev);

        /* test if this device was inited */
        if (v4l2_dev == NULL)
                return 0;
        ...
        return 0;
}

int iterate(void *p)
{
        struct device_driver *drv;
        int err;

        /* Find driver 'ivtv' on the PCI bus.
        pci_bus_type is a global. For USB buses use usb_bus_type. */
        drv = driver_find("ivtv", &pci_bus_type);
        /* iterate over all ivtv device instances */
        err = driver_for_each_device(drv, NULL, p, callback);
        put_driver(drv);
        return err;
}

デバイスインスタンスの連続カウンターを保持する必要がある場合があります。これは、デバイスインスタンスをモジュールオプション配列のインデックスにマッピングするために一般的に使用されます。

推奨されるアプローチは以下の通りです。

static atomic_t drv_instance = ATOMIC_INIT(0);

static int drv_probe(struct pci_dev *pdev, const struct pci_device_id *pci_id)
{
        ...
        state->instance = atomic_inc_return(&drv_instance) - 1;
}

複数のデバイスノードがある場合、アンレジストレアできるタイミングを把握するのは難しいです。 v4l2_device ホットプラグ可能なデバイスに対して。この目的のために v4l2_device 参照カウントのサポートがあります。参照カウントは、 video_register_device() 呼ばれるたびに増加し、そのデバイスノードが解放されるたびに減少します。参照カウントがゼロになると、 v4l2_device release()コールバックが呼ばれます。ここで最終的なクリーンアップを実行できます。

他のデバイスノード（例: ALSA）が作成される場合、以下のコールバックを呼び出すことで参照カウントを手動で増減できます：

v4l2_device_get() (v4l2_dev).

または:

v4l2_device_put() (v4l2_dev).

初期参照カウントが1であるため、 v4l2_device_put() の disconnect() コールバック（USBデバイスの場合）または remove() コールバック（例: PCIデバイスの場合）、それ以外の場合参照カウントはゼロにならないままです。

1.5.1. v4l2_device関数とデータ構造体¶

struct v4l2_device¶

V4L2デバイスドライバー用のメイン構造体

定義

struct v4l2_device {
  struct device *dev;
  struct media_device *mdev;
  struct list_head subdevs;
  spinlock_t lock;
  char name[V4L2_DEVICE_NAME_SIZE];
  void (*notify)(struct v4l2_subdev *sd, unsigned int notification, void *arg);
  struct v4l2_ctrl_handler *ctrl_handler;
  struct v4l2_prio_state prio;
  struct kref ref;
  void (*release)(struct v4l2_device *v4l2_dev);
};

メンバ

dev

ポインタ struct device.

mdev

ポインタ struct media_device、NULLになる場合があります。

subdevs

登録されたサブデバイスを追跡するために使用されます

lock

この構造体をロックする; この構造体がより大きな構造体に埋め込まれている場合、ドライバーでも使用できます。

name

一意のデバイス名、デフォルトではドライバ名 + バスID

notify

一部のサブデバイスから呼び出される通知操作。

ctrl_handler

コントロールハンドラ。 NULL.

prio

デバイスの優先度状態

ref

この構造体への参照を追跡してください。

release

参照カウントがゼロになると呼ばれる解放関数。

説明

各V4L2デバイスのインスタンスは、スタンドアロンまたはより大きな構造体に埋め込まれた形でv4l2_device構造体を作成する必要があります。

これはサブデバイスへの簡単なアクセスを提供し（v4l2-subdev.hを参照）、基本的なV4L2デバイスレベルのサポートを提供します。

注意

  1. dev->driver_data この構造体を指します。

  2. dev かもしれません NULL 親デバイスがない場合

指定されたビットマスクとグループIDが一致するすべてのサブデバイスに対して指定された操作を呼び出します

パラメータ

v4l2_dev

struct v4l2_device 反復処理するサブデバイスを所有する

grpmsk

チェックするビットマスク struct v4l2_subdevgrp_id グループIDを一致させる。すべてのグループを一致させるには0を使用してください。

o

要素の名前 struct v4l2_subdev_ops 含まれる f。それぞれの要素は、操作関数のセットをグループ化します

f

条件に一致する場合に呼び出される操作関数 cond 一致します。操作関数は、各要素に基づいてグループごとに定義されています struct v4l2_subdev_ops.

args...

引数を表します f.

説明

エラーは無視してください。

注意

サブデバイスは、サブデバイスリストを走査している間には追加または削除できません。
