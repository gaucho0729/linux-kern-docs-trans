2.3. デジタルテレビ デマルチ kABI¶

2.3.1. デジタルTVデマルチプル¶

カーネルのデジタルTVデマルチプルkABIは、低レベルかつハードウェア固有のドライバをハードウェアに依存しないデマルチプルレイヤーに登録するドライバ内部のインターフェースを定義します。これはデジタルTVデバイスドライバの開発者だけに興味がある内容です。このkABIのヘッダーファイルは demux.h および、以下に配置されています include/media.

システム内の各デマルチプルに対してデマルチプルkABIを実装する必要があります。これはデマルチプルのTSソースを選択し、デマルチプルリソースを管理するために使用されます。デマルチプルクライアントがデマルチプルkABIを通じてリソースを割り当てると、そのリソースのkABIポインタを取得します。

各デマルチプルはDVBフロントエンドまたはメモリからTS入力を受けることができます。これはこのデマルチプルkABIを通じて設定されます。複数のフロントエンドを持つシステムでは、このkABIを使用してDVBフロントエンドの1つをデマルチプルのTSソースとして選択できます（ハードウェアプラットフォームで固定されている場合は除きます）。

デマルチプルkABIはデマルチプルとの接続に関連するフロントエンドの制御を行います。他のフロントエンドパラメータ（チューニングなど）の設定には、デジタルTVフロントエンドkABIが使用されます。

デマルチプル抽象インターフェースを実装する関数は静的またはモジュールプライベートとして定義され、デマルチプルコアに登録して外部からアクセス可能にする必要があります。struct内のすべての関数を実装する必要はありません。 dmx_demuxたとえば、デマルチプルインターフェースはセクションフィルタリングをサポートするかもしれませんが、PESフィルタリングはサポートしない場合があります。kABIクライアントは、関数ポインタの値を確認してから関数を呼び出す必要があります。値が NULL の場合、関数が利用不可であることを意味します。

デマルチプルAPIの関数が共有データを変更する場合、更新のロストやレースコンディションの問題を防ぐ必要があります。たとえば、ミューテックスでコードの一部を保護するなどします。

ボトムハーフコンテキストから呼び出される関数はスリープしてはいけません。たとえば、メモリ割り当てを GFP_ATOMIC を使用せずに実行しても、スワップが必要な場合、カーネルスレッドがスリープされる可能性があります。Linuxカーネルはネットワークデバイスインターフェースの関数をボトムハーフコンテキストから呼び出します。したがって、ネットワークデバイスコードからデマルチプルkABI関数が呼び出される場合、その関数はスリープしてはいけません。

2.3.2. デマルチプルコールバックAPI¶

このカーネル空間APIは、フィルタリングされたデータをデマルチプルクライアントに提供するコールバック関数を含みます。他のDVB kABIとは異なり、これらの関数はクライアントが提供し、デマルチプルコードから呼び出されます。

この抽象インターフェースの関数ポインタは、他のデマルクAPIと同様に構造体にパッケージ化されません。これは、コールバック関数がそれぞれ独立して登録され使用されるためです。例として、APIクライアントがTSパケットの受信に複数のコールバック関数を提供し、PESパケットやセクションにはコールバック関数を提供しないことも可能です。

コールバックAPIを実装する関数は再入可能である必要はありません。デマルクドライバがこれらの関数を呼び出すとき、ドライバは元の呼び出しの戻り値が返るまで、関数を再度呼び出すことはできません。ハードウェア割込みによってコールバックがトリガーされる場合、コールバック関数を直接割込みから呼び出すのではなく、Linuxのボトムハーフメカニズムを使用するかタスクレットを起動することをお勧めします。

このメカニズムは dmx_ts_cb() および dmx_section_cb() コールバックによって実装されます。

この関数コールバックプロトタイプはデマルクAPIのクライアントが提供し、デマルクコードから呼び出されます。この関数は、start_filtering()関数でTSフィードのフィルタリングが有効化された場合にのみ呼び出されます。 dmx_demuxフィルタ設定に一致するすべてのTSパケットは環状バッファにコピーされます。フィルタリングされたTSパケットはこのコールバック関数を使用してクライアントに配信されます。この関数は、 buffer1 および buffer2 コールバックパラメータが環状バッファ内のアドレスを指していることが期待されます。ただし、他の実装方法も可能です。呼び出し元は、パラメータが指すメモリを解放しないでください。 buffer1 および buffer2 パラメータが指すアドレス。

この関数が呼ばれた場合、 buffer1 パラメータは通常、環状バッファ内の未配信TSパケットの最初のアドレスを指します。 buffer2 bufferパラメータは通常NULLですが、受信したTSパケットが環状バッファの最後のアドレスを越えて「ラップ」してバッファの先頭に戻った場合を除きます。後者の場合、 buffer1 パラメータは環状バッファ内のアドレスを含み、 buffer2 パラメータは環状バッファの先頭アドレスを含みます。この関数で配信されるバイト数（つまり、 buffer1_length + buffer2_length）は通常、set()関数で指定されたcallback_lengthパラメータの値に等しくなります。ただし、callback_lengthバイトのTSデータを受信する前にタイムアウトが発生した場合、未配信のパケットはすぐにこの関数を呼び出してクライアントに配信されます。タイムアウト時間はTS Feed APIのset()関数で制御されます。

TSレベルの前向き誤り訂正（FEC）で修正できないエラーが含まれるTSパケットが受信された場合、TSパケットヘッダーのTransport_error_indicatorフラグを設定する必要があります。エラーはより上位のプロトコルで修正される可能性があるため、TSパケットは破棄しないでください。呼び出し元がコールバック処理が遅い場合、環状バッファが満杯になる可能性があります。このような場合、デマルクドライバーはバッファが満杯の間受信したTSパケットを破棄し、-EOVERFLOWを返します。

  • 成功の場合は0、

  • -EOVERFLOW、バッファオーバーフローの場合は。

リソースを allocate_section_feed、割り当てられたフィルタも含む。セクションフィードでの進行中のフィルタリングは、この関数を呼び出す前に停止しておく必要があります。 demux 関数のパラメータにはデマルチパッケージングAPIとインスタンスデータへのポインタが含まれます。The feed 関数パラメータには、TSフィードAPIとインスタンスデータへのポインタが含まれます。成功時は0を、不正なパラメータの場合は-EINVALを返します。

add_frontend

デマルクとフロントエンド間の接続を登録します。つまり、デマルクがconnect_frontendを呼び出して指定されたフロントエンドをTSソースとして使用できるようにするという意味です。 connect_frontend この関数のクライアントは、フロントエンド構造体に動的または静的メモリを確保し、そのフィールドを初期化した後でこの関数を呼び出す必要があります。この関数は通常ドライバ初期化中に呼び出されます。呼び出し元は、remove_frontendを成功して呼び出すまで、フロントエンド構造体のメモリを解放してはなりません。 remove_frontendの部分で、 demux 関数のパラメータにはデマルチパッケージングAPIとインスタンスデータへのポインタが含まれます。The frontend 関数のパラメータには、フロントエンドインスタンスデータへのポインタが含まれています。成功時は0を返し、パラメータが不正な場合に-EINVALを返します。

remove_frontend

指定されたフロントエンドが、add_frontend関数呼び出しによって登録され、 add_frontend、このデマルクによってTSソースとして接続できなくなりました。この関数は、フロントエンドドライバーまたはデマルクドライバーがシステムから削除されたときに呼び出す必要があります。フロントエンドが使用中の場合、関数は-EBUSYを返して失敗します。この関数を成功して呼び出した後、callerは、以前に動的に割り当てられたfrontend構造体のメモリを解放できます。この操作の前 add_frontend の demux 関数のパラメータにはデマルチパッケージングAPIとインスタンスデータへのポインタが含まれます。The frontend 関数のパラメータには、フロントエンドインスタンスデータへのポインタが含まれています。成功時は0を返し、フロントエンドが見つからない場合に-ENODEVを返し、パラメータが不正な場合に-EINVALを返します。

get_frontends

このデマルクに登録されたフロントエンドのAPIを提供します。この呼び出しによって取得したどのフロントエンドも、 connect_frontendのパラメータとして使用できます。インクルードファイル demux.h には、次のマクロが含まれています。 DMX_FE_ENTRY() ジェネリック型 struct の要素を list_head struct dmx_frontend この関数呼び出しによって取得した要素のメモリを解放してはならない。**demux* 関数パラメータには、demux APIとインスタンスデータへのポインタが含まれる。リストヘッド構造体ポインタをfront-endインターフェースのリストとして返すか、空リストの場合はNULLを返す。

connect_frontend

front-endのTS出力とdemuxの入力を接続する。demuxは、demuxに登録されたfront-endのみに接続可能である。関数 add_frontendでfront-endが登録されている場合にのみ接続可能である。HWプラットフォームの機能によっては、複数のdemuxが同じfront-endに接続可能かどうかが異なる。使用しない場合は、front-endは disconnect_frontendの部分で、 demux 関数のパラメータにはデマルチパッケージングAPIとインスタンスデータへのポインタが含まれます。The frontend 関数のパラメータには、フロントエンドインスタンスデータへのポインタが含まれています。成功時は0を返し、パラメータが不正な場合に-EINVALを返します。

disconnect_frontend

demuxと以前に接続されたfront-endを切断する。関数 connect_frontend 呼び出しによって接続されたdemuxとfront-endを切断する。関数 demux パラメータには、demux APIとインスタンスデータへのポインタが含まれる。成功時は0を、パラメータが不正な場合は-EINVALを返す。

get_pes_pids

DMX_PES_AUDIO0、DMX_PES_VIDEO0、DMX_PES_TELETEXT0、DMX_PES_SUBTITLE0およびDMX_PES_PCR0のPIDを取得する。関数 demux 関数のパラメータにはデマルチパッケージングAPIとインスタンスデータへのポインタが含まれます。The pids パラメータには、PIDを格納するための5つのu16要素の配列が含まれる。成功時は0を、パラメータが不正な場合は-EINVALを返す。
