7. カメラセンサードライバーの作成¶

7.1. CSI-2¶

MIPI CSI-2に関する記述を参照してください MIPI CSI-2.

7.2. クロックの処理¶

カメラセンサーはPLLと複数のディバイザーを含む内部クロックツリーを持ち、ドライバーがハードウェア固有のパラメータ（外部クロック周波数とリンク周波数）に基づいてクロックツリーを構成します。これらの2つのパラメータは一般的にシステムファームウェアから取得され、他の周波数は一切使用しないでください。

クロック周波数が非常に重要である理由は、クロック信号がSoCから出力され、多くの場合特定の周波数がシステムで使用されるように設計されているためです。他の周波数を使用すると他の部分に有害な影響を及ぼす可能性があるため、ユーザーが設定可能なのは事前に決められた周波数のみです。

7.3. フレームサイズ¶

カメラセンサーが生成するフレームサイズの設定には2つの異なる方法があります。

7.3.1. 自由に設定可能なカメラセンサードライバー¶

自由に設定可能なカメラセンサードライバーは、デバイスの内部処理パイプラインを1つまたは複数のサブデバイスとして公開し、それぞれ異なるクロッピングおよびスケーリング設定を提供します。デバイスの出力サイズは、デバイスのピクセル配列サイズから一連のクロッピングおよびスケーリング操作の結果です。

このようなドライバーの例はsmiappドライバー（drivers/media/i2c/smiappを参照）です。

7.3.2. レジスタ一覧ベースのドライバー¶

レジスタ一覧ベースのドライバーは、ユーザーの要求に基づいてデバイスを制御するのではなく、ハードウェアレベルで独立した複数のパラメータを組み合わせたいくつかのプリセット設定に限定されます。ドライバーがこのような設定を選択する方法は、デバイスの内部パイプラインの最後のソースパッドで設定されたフォーマットに基づきます。

ほとんどのセンサードライバーはこの方法で実装されています（例: drivers/media/i2c/imx319.cを参照）。

7.4. フレームインターバルの設定¶

フレームインターバルの可能性を得る方法およびフレームインターバルの設定には2つの異なる方法があります。どちらを実装するかはデバイスの種類に依存します。

7.4.1. RAWカメラセンサー¶

フレームインターバルは、複数のカメラセンサー実装固有のパラメータの設定結果であり、高レベルのパラメータ（フレームインターバル）ではなく、現代のRAWカメラセンサーではこれらのパラメータがほぼすべて同じ傾向があります。

フレームインターバルは以下の式で計算されます:

frame interval = (analogue crop width + horizontal blanking) *
                 (analogue crop height + vertical blanking) / pixel rate

この式はバスに依存せず、カメラセンサー以外にも幅広いデバイスにおける素データのタイミングパラメータに適用可能です。アナログトリミング機能を持たないデバイスは、ソース画像のフルサイズ、つまりピクセル配列サイズを使用します。

水平および垂直のブランキングは、 V4L2_CID_HBLANK および V4L2_CID_VBLANKそれぞれで指定されます。これらの制御の単位はラインです。ピクセルレートは、 V4L2_CID_PIXEL_RATE 同じサブデバイス内で指定されます。その制御の単位はHzです。

レジスタリストベースのドライバーは、目的のために読み取り専用のサブデバイスノードを実装する必要があります。レジスタリストベースでないデバイスは、デバイスの内部処理パイプラインを設定するためにこれらを使用します。

線形パイプラインの最初のエンティティはピクセル配列です。ピクセル配列の後に他のエンティティが続く場合があり、これはビニング、スキップ、スケーリング、デジタルトリミングの設定を可能にするためです。 選択肢: トリミング、スケーリング、コンポジション.

7.4.2. USBカメラなどデバイス¶

USBビデオクラスハードウェアおよび多くの類似の高レベルインターフェースをネイティブで提供するカメラは、ファームウェアまたはハードウェアレベルでフレームインターバル（またはフレームレート）の概念を一般的に使用します。これは、素データカメラが実装する低レベルの制御が、uAPI（またはkAPI）でこれらのデバイスのフレームインターバルを制御できないことを意味します。

7.5. 電源管理¶

常にランタイムPMを使用してデバイスの電源状態を管理してください。カメラセンサードライバーはこの点で特別ではありません。それらは、それ以外に制御するデバイスの電源状態を責任をもって制御する必要があります。一般的に、レジスタがアクセスされるときやストリーミング中にデバイスは電源がオンになっている必要があります。

既存のカメラセンサードライバーは、古い v4l2_subdev_core_ops->s_power()コールバックをブリッジまたはISPドライバーで使用して電源状態を管理することがあります。これはしかし、 非推奨です。ISPまたはブリッジドライバーからs_powerを呼び出す必要があると感じた場合、代わりに使用しているセンサードライバーにランタイムPMのサポートを追加してください。新規ドライバーはs_powerを使用すべきではありません。

例として、以下のリンクを参照してください。 drivers/media/i2c/ov8856.c および drivers/media/i2c/smiapp/smiapp-core.c。これらの2つのドライバーは、ACPIおよびDTベースのシステムの両方で動作します。

7.5.1. 制御フレームワーク¶

v4l2_ctrl_handler_setup() 関数は、デバイスのランタイムPM runtime_resume コールバック内で使用できません。なぜなら、デバイスの電源状態を把握する方法がないからです。これは、デバイスの電源状態が電源状態の変化後にのみ変更されるためです。電源状態の変化後にデバイスの電源状態を取得するために、 s_ctrl コールバックを使用できます:

int pm_runtime_get_if_in_use(struct デバイス *dev);¶

関数が電源カウントを取得できたか、またはランタイムPMが無効化されていた場合、関数はゼロ以外の値を返します。どちらの場合でも、ドライバはデバイスにアクセスすることができるかもしれません。
