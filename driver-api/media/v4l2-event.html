1.12. V4L2イベント¶

V4L2イベントは、ユーザー空間にイベントを通知するための汎用的な方法を提供します。ドライバは v4l2_fh を使用して、V4L2イベントをサポートする必要があります。

イベントはファイルハンドルごとにサブスクライブされます。イベントの仕様は、 type を含み、オプションで特定のオブジェクトと関連付けられます。そのオブジェクトは id フィールドを通じて識別されます。使用されていない場合、 id は0です。したがって、イベントは (type, id) のタプルで一意に識別されます。

以下の v4l2_fh 構造体には、その subscribed フィールドによって保護されています。

にサブスクライブされたイベントの一覧があります。 v4l2_subscribed_event ユーザーがイベントをサブスクライブすると、 v4l2_fh.subscribedに構造体が追加され、サブスクライブされたすべてのイベントに対応する構造体が作成されます。

Each v4l2_subscribed_event 構造体は、 v4l2_kevent リングバッファで終了し、そのサイズは呼び出し元の v4l2_event_subscribe()によって指定されます。このリングバッファは、ドライバが生成したすべてのイベントを保存するために使用されます。

したがって、すべての (type, ID) イベントタプルには、それぞれ独自の v4l2_kevent リングバッファがあります。これにより、ドライバが短時間に同じタイプの多数のイベントを生成しても、他のタイプのイベントが上書きされることを防ぎます。

ただし、1つのタイプのイベントがリングバッファのサイズより多く生成された場合、最も古いイベントは破棄され、新しいイベントが追加されます。 v4l2_kevent 構造体は、

以下の v4l2_kevent のリストにリンクされ、 available 構造体の v4l2_fh リストに接続されるため、 ioctl VIDIOC_DQEVENT が最初にデキューするイベントを識別できます。

最後に、イベントサブスクライブが特定のオブジェクト（例: V4L2コントロール）に関連付けられている場合、そのオブジェクトもそのイベントを生成できるようにする必要があります。したがって、 node フィールドは、 v4l2_subscribed_event 構造体をそのようなオブジェクトのリストにリンクするために使用できます。

まとめると、

  • struct v4l2_fh には、 subscribed イベントのリストと、 available イベントのリストがあります。

  • struct v4l2_subscribed_event には、その特定のタイプの挙動中のイベント（待機中）を保持するリングバッファがあります。

  • もし struct v4l2_subscribed_event が特定のオブジェクトに関連付けられている場合、そのオブジェクトには、 struct v4l2_subscribed_event の内部リストがあります。これにより、イベントがどのオブジェクトに関連付けられているかを把握できます。

さらに、内部の struct v4l2_subscribed_event には merge() および replace() コールバック関数をドライバが設定できます。これらのコールバック関数は、新しいイベントが発生し、かつリングバッファに容量がなくなったときに呼び出されます。

以下の replace() コールバック関数は、このイベントタイプのリングバッファのサイズが1である場合（つまり、リングバッファに1つのイベントのみ保存可能）に、古いイベントのペイロードを新しいイベントのペイロードに置き換え、関連するデータを統合します。

以下の merge() コールバック関数は、リングバッファのサイズが1より大きい場合に、最も古いイベントのペイロードを2番目に古いイベントのペイロードに統合します。

このように、状態情報は失われず、その状態に至るまでの途中のステップ情報は保持されます。

これらのコールバックの良い例はv4l2-event.cにあります。 replace/merge コントロールイベントのコールバックです。 ctrls_replace() および ctrls_merge() これらのコールバックは割込みコンテキストから呼び出されるため、高速でなければならないです。
