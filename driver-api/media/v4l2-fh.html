1.6. V4L2 File handlers¶

struct v4l2_fh V4L2フレームワークで使用されるファイルハンドル固有のデータを簡単に保持する方法を提供します。

注意

新しいドライバーは使用する必要があります struct v4l2_fh 優先度処理も実装するために使用されるため、ioctl VIDIOC_G_PRIORITY, VIDIOC_S_PRIORITY).

V4L2フレームワーク内で使用されるかどうかを確認するために、ユーザーは v4l2_fh (ドライバーではなく)V4L2フレームワーク内で、ドライバーが v4l2_fh ポインタとして使用しているかをテストする file->private_data ->flags. このビットは、 V4L2_FL_USES_V4L2_FH ビットを video_deviceがドライバーの独自のファイルハンドル構造体の一部として割り当てられたときに設定されます。 v4l2_fh_init() polling間隔（ms）。0の場合はpollingを無効にします。

struct v4l2_fh がドライバーの file->private_data 関数内で設定される場合、 open() が割り当てられます。

多くの場合、 struct v4l2_fh はより大きな構造体に埋め込まれます。その場合、以下の関数を呼び出してください:

  1. v4l2_fh_init() および v4l2_fh_add() の open()

  2. v4l2_fh_del() および v4l2_fh_exit() の release()

ドライバーはcontainer_ofマクロを使用して、自身のファイルハンドル構造体を抽出できます。

例:

struct my_fh {
        int blah;
        struct v4l2_fh fh;
};

...

int my_open(struct file *file)
{
        struct my_fh *my_fh;
        struct video_device *vfd;
        int ret;

        ...

        my_fh = kzalloc(sizeof(*my_fh), GFP_KERNEL);

        ...

        v4l2_fh_init(&my_fh->fh, vfd);

        ...

        file->private_data = &my_fh->fh;
        v4l2_fh_add(&my_fh->fh);
        return 0;
}

int my_release(struct file *file)
{
        struct v4l2_fh *fh = file->private_data;
        struct my_fh *my_fh = container_of(fh, struct my_fh, fh);

        ...
        v4l2_fh_del(&my_fh->fh);
        v4l2_fh_exit(&my_fh->fh);
        kfree(my_fh);
        return 0;
}

以下は、使用される v4l2_fh 関数の短い説明です:

v4l2_fh_init (fh, vdev)

  • ファイルハンドルを初期化します。この MUST ドライバーの v4l2_file_operations->open()ハンドラ内で実行する必要があります。

v4l2_fh_add (fh)

  • Add a v4l2_fh に（木の下から葉に向かって） video_device ファイルハンドルリストに追加します。ファイルハンドルが完全に初期化された後で呼び出す必要があります。

v4l2_fh_del (fh)

  • ファイルハンドルを video_deviceから関連付けを解除します。ファイルハンドルの終了関数を呼び出すことができます。

v4l2_fh_exit (fh)

  • ファイルハンドルを初期化を解除します。初期化を解除した後、 v4l2_fh メモリを解放できます。

もし struct v4l2_fh 埋め込まれていない場合、これらの補助関数を使用できます:

v4l2_fh_open (struct file *filp)

  • これは、 struct v4l2_fhを割り当て、初期化し、 struct video_device に関連付けたファイル構造体に追加します。

v4l2_fh_release (struct file *filp)

  • これを、 struct video_device に関連付けたファイル構造体から削除し、初期化を解除して解放します。 v4l2_fh これらの2つの関数は、v4l2_file_operationの

opsに組み込むことができます。 open() および release() 複数のドライバーは、最初のファイルハンドルが開かれたときと最後のファイルハンドルが閉じたときに処理を行う必要があります。そのため、2つの補助関数が追加されました:

関連付けられたデバイスノードの唯一のオープンファイルハンドルかどうかを確認するための v4l2_fh 構造体が唯一のオープンファイルハンドルかどうかを確認します:

v4l2_fh_is_singular (fh)

  • ファイルハンドルが唯一のオープンファイルハンドルである場合、1を返します。それ以外の場合は0を返します。

v4l2_fh_is_singular_file (struct file *filp)

  • 同じですが、filp->private_dataをv4l2_fh_is_singularに渡して呼び出します。
