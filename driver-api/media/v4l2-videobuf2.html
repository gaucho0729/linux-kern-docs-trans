1.15. V4L2 videobuf2関数とデータ構造¶

enum vb2_memory¶

ユーザー空間でバッファが見えるようにするためのメモリモデルのタイプ。

定数

VB2_MEMORY_UNKNOWN

バッファのステータスが不明か、またはユーザー空間でまだ使用されていない。

VB2_MEMORY_MMAP

カーネルによってバッファが割り当てられ、mmap() ioctlを通じてメモリマップされます。このモデルは、ユーザーがread()またはwrite()システムコールを介してバッファを使用する場合にも使用されます。

VB2_MEMORY_USERPTR

ユーザー空間で割り当てられ、mmap() ioctlを通じてメモリマップされています。

VB2_MEMORY_DMABUF

DMAバッファを介してユーザー空間に渡されます。

struct vb2_mem_ops¶

メモリ管理/メモリアロケータ操作。

定義

struct vb2_mem_ops {
  void *(*alloc)(struct device *dev, unsigned long attrs,unsigned long size,enum dma_data_direction dma_dir, gfp_t gfp_flags);
  void (*put)(void *buf_priv);
  struct dma_buf *(*get_dmabuf)(void *buf_priv, unsigned long flags);
  void *(*get_userptr)(struct device *dev, unsigned long vaddr,unsigned long size, enum dma_data_direction dma_dir);
  void (*put_userptr)(void *buf_priv);
  void (*prepare)(void *buf_priv);
  void (*finish)(void *buf_priv);
  void *(*attach_dmabuf)(struct device *dev,struct dma_buf *dbuf,unsigned long size, enum dma_data_direction dma_dir);
  void (*detach_dmabuf)(void *buf_priv);
  int (*map_dmabuf)(void *buf_priv);
  void (*unmap_dmabuf)(void *buf_priv);
  void *(*vaddr)(void *buf_priv);
  void *(*cookie)(void *buf_priv);
  unsigned int    (*num_users)(void *buf_priv);
  int (*mmap)(void *buf_priv, struct vm_area_struct *vma);
};

メンバ

alloc

ビデオメモリを割り当て、オプションでアロケータのプライベートデータも割り当て、失敗時はERR_PTR()を返し、成功時はアロケータのプライベートデータへのポインタを返します。返されたプライベート構造体は、この構造体内の他の操作の引数として渡されます。また、この操作に渡されるgfp_flagsは、vb2_queueのgfp_flagsフィールドから取得されます。この関数のsize引数は buf_priv 他の操作の引数として渡されます。さらに、アロケート時に使用するgfp_flagsもこの操作に渡されます。これらのフラグはvb2_queueのgfp_flagsフィールドから取得されます。この関数のsize引数は page aligned.

put

アロケータにこのバッファがもはや使用されないことを通知します。通常、このバッファが他のユーザーによって使用されていない場合、アロケータがバッファを解放します。引数は、allocコールバックから以前に返されたアロケータのプライベートなバッファ構造体です。 buf_priv 引数は、アロケータのプライベートなバッファ構造体です。

get_dmabuf

ハードウェア操作用にユーザー空間のメモリを取得します。DMABUFメモリタイプで使用されます。

get_userptr

ハードウェア操作用にユーザー空間のメモリを取得します。USERPTRメモリタイプで使用されます。vaddrは、USERPTRタイプのビデオバッファをキューイングする際にvideobufレイヤーに渡されるアドレスです。成功時はバッファに関連するアロケータのプライベートなバッファ構造体を返し、失敗時はERR_PTR()を返します。返されたプライベート構造体は、この構造体内の他の操作の引数として渡されます。 buf_priv 引数として他の操作に渡されます。

put_userptr

USERPTRバッファがもはや使用されないことをアロケータに通知します。

prepare

ユーザー空間からドライバにバッファが渡されるたびに呼び出されます。キャッシュ同期に使用されるオプションの関数です。

finish

ドライバからユーザー空間にバッファが戻されるたびに呼び出されます。オプションの関数です。

attach_dmabuf

共有 struct dma_buf ハードウェア操作用にアタッチします。DMABUFメモリタイプで使用されます。devは割り当てデバイス、dbufは共有dma_bufです。失敗時はERR_PTR()を返し、成功時はアロケータのプライベートなバッファ構造体を返します。この構造体は、以降のバッファアクセスに使用されます。

detach_dmabuf

バッファのエクスポーターに、現在のDMABUFバッファがもはや使用されないことを通知します。 buf_priv 引数は、attach_dmabufコールバックから以前に返されたアロケータのプライベートなバッファ構造体です。

map_dmabuf

dmabufへのアクセス要求; このドライバーがdmabufを使用することをdmabufのアロケータに通知します。

unmap_dmabuf

dmabufのアクセス制御を解放します - これ以降このドライバーはdmabufを使用しないため、アロケータに通知します。

vaddr

指定されたプライベート構造体に関連するメモリバッファのカーネル仮想アドレスを返します。該当するマッピングが存在しない場合はNULLを返します。

cookie

指定されたプライベート構造体に関連するメモリバッファのアロケータ固有のクッキーを返します。利用不可の場合はNULLを返します。

num_users

メモリバッファの現在のユーザー数を返します。videobufレイヤー（または実際にそのバッファを使用しているドライバー）が唯一のユーザーである場合は1を返します。

mmap

指定された仮想メモリ領域下で、指定されたメモリバッファのユーザー空間マッピングを設定します。

説明

これらの操作は、videobuf2コアがサポートする各ストリーミングI/Oメソッドのメモリ管理/メモリアロケータを実装するためにvideobuf2コアが使用します。

注意

  1. USERPTRタイプに必要な操作: get_userptr, put_userptr。

  2. MMAPタイプに必要な操作: alloc, put, num_users, mmap。

  3. 読み書きアクセスタイプに必要な操作: alloc, put, num_users, vaddr。

  4. DMABUFタイプに必要な操作: attach_dmabuf, detach_dmabuf, map_dmabuf, unmap_dmabuf。

struct vb2_plane¶

プレーン情報。

定義

struct vb2_plane {
  void *mem_priv;
  struct dma_buf          *dbuf;
  unsigned int            dbuf_mapped;
  unsigned int            bytesused;
  unsigned int            length;
  unsigned int            min_length;
  union {
    unsigned int    offset;
    unsigned long   userptr;
    int fd;
  } m;
  unsigned int            data_offset;
};

メンバ

mem_priv

このプレーンに関連するプライベートデータ。

dbuf

dma_buf - 共有バッファオブジェクト。

dbuf_mapped

dbufがマップされているかどうかを示すフラグ

bytesused

プレーン内のデータが占めるバイト数（ペイロード）。

length

このプレーンのサイズ（ペイロードではない）バイト数。

min_length

このプレーンの最小必要サイズ（ペイロードではない）バイト数。 length 常に大きく等于 min_length.

m

memtype固有データを含むユニオン。

m.offset

関連するメモリが struct vb2_buffer 通常のRCU読み込み側クリティカルセクションは、条件付きでスリープロックを取得することが許容されます（例として VB2_MEMORY_MMAP、このプレーンのデバイスメモリの開始位置からのオフセットに等しい（または、ビデオノードのmmap()呼び出しに渡すべき「クッキー」）です。

m.userptr

メモリが VB2_MEMORY_USERPTR、このプレーンを指すユーザー空間ポインタです。

m.fd

メモリが VB2_MEMORY_DMABUF、このプレーンに関連するユーザー空間ファイル記述子です。

data_offset

データの開始位置までのプレーン内のオフセット；通常は0ですが、データの前にヘッダがある場合はその値になります。

説明

すべてのフィールドをカバーするための十分な情報が含まれるべきです。 struct v4l2_plane videodev2.hで定義されています。

enum vb2_buffer_state¶

現在のビデオバッファ状態。

定数

VB2_BUF_STATE_DEQUEUED

ユーザー空間制御下のバッファ。

VB2_BUF_STATE_IN_REQUEST

メディアリクエストにキューイングされたバッファ。

VB2_BUF_STATE_PREPARING

videobufでバッファが準備中です。

VB2_BUF_STATE_QUEUED

videobufでバッファがキューイングされていますが、ドライバにはまだありません。

VB2_BUF_STATE_ACTIVE

ドライバでバッファがキューイングされており、ハードウェア操作で使用される可能性があります。

VB2_BUF_STATE_DONE

ドライバからvideobufへバッファが返却されましたが、ユーザー空間へまだデキューイングされていません。

VB2_BUF_STATE_ERROR

上記と同じですが、バッファの操作がエラーで終了しており、ユーザー空間へデキューイングされるときにエラーが報告されます。

struct vb2_ops¶

ドライバ固有のコールバックです。

定義

struct vb2_ops {
  int (*queue_setup)(struct vb2_queue *q,unsigned int *num_buffers, unsigned int *num_planes, unsigned int sizes[], struct device *alloc_devs[]);
  void (*wait_prepare)(struct vb2_queue *q);
  void (*wait_finish)(struct vb2_queue *q);
  int (*buf_out_validate)(struct vb2_buffer *vb);
  int (*buf_init)(struct vb2_buffer *vb);
  int (*buf_prepare)(struct vb2_buffer *vb);
  void (*buf_finish)(struct vb2_buffer *vb);
  void (*buf_cleanup)(struct vb2_buffer *vb);
  int (*start_streaming)(struct vb2_queue *q, unsigned int count);
  void (*stop_streaming)(struct vb2_queue *q);
  void (*buf_queue)(struct vb2_buffer *vb);
  void (*buf_request_complete)(struct vb2_buffer *vb);
};

メンバ

queue_setup

VIDIOC_REQBUFS() および VIDIOC_CREATE_BUFS() ハンドラからメモリ割当の前に呼び出されます。この関数は最大2回呼び出されることがあります：元のバッファ数が割当可能でなければ、実際に割当えたバッファ数で2回目の呼び出しを行い、その数が問題ないか確認します。ドライバは *num_buffers に必要なバッファ数、*num_planes に必要なプレーン数、sizes[] 配列に各プレーンのサイズを設定し、alloc_devs[] 配列にオプションで各プレーンのアロケータ固有のデバイスを指定します。VIDIOC_REQBUFS() から呼び出された場合、*num_planes == 0 であり、ドライバは現在のフォーマットを使用してプレーンサイズを決定し、*num_buffers は割当われるバッファの総数です。VIDIOC_CREATE_BUFS() から呼び出された場合、*num_planes != 0 であり、これはリクエストされたプレーン数を表し、sizes[] にはリクエストされたプレーンサイズが含まれます。この場合、*num_buffers は q->num_buffers に加えて割当られます。どちらかの *num_planes またはリクエストされたサイズが無効な場合、コールバックは -EINVAL.

wait_prepare

vb2関数呼び出し中に取得したロックを解放します。これはioctlが新しいバッファの到着を待つ必要がある前に呼び出されます。ブロッキングアクセスタイプのデッドロックを避けるために必要です。

wait_finish

前のコールバックで解放したすべてのロックを再取得します。新しいバッファの到着を待っている間にスリープした後、操作を続行するために必要です。

buf_out_validate

出力バッファが準備されたり、リクエストにキューイングされたときに呼び出されます。ドライバはユーザー空間から提供された情報を検証するためにこれを使用できます。これはOUTPUTキューの場合にのみ必要です。

buf_init

バッファが割り当てられた後（MMAPの場合）または新しいUSERPTRバッファが取得した後呼び出されます。ドライバーは追加のバッファ関連の初期化を行うことができます。初期化失敗（返り値 != 0）はキューの設定を成功させるのを防ぎます。オプション。

buf_prepare

ユーザー空間からバッファがキューイングされるたびに呼び出されます（VIDIOC_PREPARE_BUF() ioctlからも）。ドライバーはこのコールバックで各ハードウェア操作前に必要な初期化を行うことができます。この時点でバッファはCPUに同期されているため、ドライバーはアクセスまたは変更可能です。VIDIOC_CREATE_BUFS()をサポートするドライバーはバッファサイズの検証も行う必要があります。エラーが返された場合、ドライバーはバッファをキューイングしません。オプション。

buf_finish

ユーザー空間に戻すバッファのデキューイングの前に行われます。バッファはCPUに同期されているため、ドライバーは内容をアクセスまたは変更可能です。ユーザー空間がバッファにアクセスする前に必要な操作を行うことができます。オプション。バッファの状態は以下のいずれかです： DONE および ERROR ストリーミングが進行中に発生し、 PREPARED キューがキャンセルされ、すべての待機中のバッファがデフォルトに戻る状態です。 DEQUEUED 状態です。通常は状態が VB2_BUF_STATE_DONEの場合のみ処理が必要です。その他の場合はバッファの内容は無視されます。

buf_cleanup

バッファが解放される前に一度呼び出されます。ドライバーは追加のクリーンアップを行うことができます。オプション。

start_streaming

「ストリーミング」状態に入るときに一度呼び出されます。ドライバーは buf_queue コールバックを start_streaming が呼ばれる前に、ドライバーはcountパラメータで既にキューイングされたバッファ数を受け取ります。ハードウェアが失敗した場合、エラーを返すことができます。その場合、すでにドライバーに渡されたすべてのバッファは buf_queue コールバックでドライバーが呼び出すことで返却されます。 vb2_buffer_done() with VB2_BUF_STATE_QUEUEDを設定します。もしその値がゼロでなければ、 vb2_queue->min_buffers_neededはユーザー空間が少なくともその数のバッファをキューイングした後まで呼ばられません。 start_streaming が呼ばれる前にユーザー空間が少なくともその数のバッファをキューイングした後まで呼ばられません。

stop_streaming

「ストリーミング」状態を無効にするときに呼び出されます。ドライバーはDMAトランザクションを停止するか、完了を待ってから、すべてのバッファを buf_queue コールバックで取得したバッファを呼び出すことで返却します。 vb2_buffer_done() のいずれかで VB2_BUF_STATE_DONE または VB2_BUF_STATE_ERRORを使用できます。 vb2_wait_for_all_buffers() ファンクション

buf_queue

バッファvbをドライバーに渡します。ドライバーはこのバッファでハードウェア操作を開始できます。ドライバーはこのバッファを返却するために vb2_buffer_done() 関数を呼び出します。これはVIDIOC_STREAMON() ioctlを呼び出した後常に呼ばれます。ユーザーがVIDIOC_STREAMON()を呼び出す前にバッファをキューイングした場合、このコールバックが start_streaming コールバックよりも先に呼ばれる可能性があります。

buf_request_complete

キューに登録されていないが、キューされたリクエストに関連付けられているバッファがキャンセルされました。ドライバーは、リクエストに関連するオブジェクトを完了としてマークする必要があります。リクエストがサポートされている場合に必須です。

説明

これらの操作は、明示的に記載されていない限り、割り込みコンテキストから呼び出されません。

定義

struct vb2_queue {
  unsigned int                    type;
  unsigned int                    io_modes;
  struct device                   *dev;
  unsigned long                   dma_attrs;
  unsigned int                    bidirectional:1;
  unsigned int                    fileio_read_once:1;
  unsigned int                    fileio_write_immediately:1;
  unsigned int                    allow_zero_bytesused:1;
  unsigned int               quirk_poll_must_check_waiting_for_buffers:1;
  unsigned int                    supports_requests:1;
  unsigned int                    requires_requests:1;
  unsigned int                    uses_qbuf:1;
  unsigned int                    uses_requests:1;
  unsigned int                    allow_cache_hints:1;
  struct mutex                    *lock;
  void *owner;
  const struct vb2_ops            *ops;
  const struct vb2_mem_ops        *mem_ops;
  const struct vb2_buf_ops        *buf_ops;
  void *drv_priv;
  u32 subsystem_flags;
  unsigned int                    buf_struct_size;
  u32 timestamp_flags;
  gfp_t gfp_flags;
  u32 min_buffers_needed;
  struct device                   *alloc_devs[VB2_MAX_PLANES];
};

メンバ

type

vb2-coreコールラーが定義するコンテンツを持つプライベートなバッファタイプです。たとえば、V4L2の場合、これは enum v4l2_buf_type.

io_modes

サポートされるIOメソッド（参照 enum vb2_io_modes).

dev

デバイスをデフォルトの割当コンテキストとして使用します。ドライバーが alloc_devs 配列を表しています。

dma_attrs

DMA属性を指定します。

bidirectional

このフラグが設定されている場合、このキューのバッファのDMA方向は DMA_BIDIRECTIONAL 方向に上書きされます。ハードウェア（ファームウェア）が読み込み用にマップされたバッファに書き込む（DMA_TO_DEVICE）場合や、書き込み用にマップされたバッファから読み込む（DMA_FROM_DEVICE）場合に役立ちます。DMAマッピングが双方向でないにもかかわらず、ハードウェア（ファームウェア）が逆方向でバッファにアクセスしようとした場合、IOMMU保護違反が発生する可能性があります。

fileio_read_once

最初のバッファを読み終わってからEOFを報告する

fileio_write_immediately

各write()呼び出し後にバッファをキューに登録する

allow_zero_bytesused

bytesused == 0をドライバーに渡すことを許可する

quirk_poll_must_check_waiting_for_buffers

戻り値 EPOLLERR QBUFが呼び出されていない場合のpoll時。これはvb1のイディオムで、vb2でも採用されています。

supports_requests

このキューはRequest APIをサポートしています。

requires_requests

このキューはRequest APIを必要とします。このフラグが1に設定されている場合、supports_requestsも1に設定する必要があります。

uses_qbuf

このキューにqbufが直接使用されました。最初の呼び出し時に1に設定し、キューがキャンセルされたときに0に設定します。この値が1の場合、リクエストからバッファをキューすることはできません。

uses_requests

このキューでリクエストが使用されています。最初のリクエストがキューされたときに1に設定し、キューがキャンセルされたときに0に設定します。この値が1の場合、直接バッファをキューすることはできません。

allow_cache_hints

このフラグが設定されている場合、ユーザー空間は->prepare()または->finish()でのキャッシュフラッシュ/無効化をスキップするためにキャッシュ管理ヒントを渡すことができます。

lock
