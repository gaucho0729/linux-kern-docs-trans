1.22. V4L2 async kAPI¶

enum v4l2_async_match_type¶

非同期サブデバイスロジックの種類で、マッチを特定するために使用される

定数

V4L2_ASYNC_MATCH_CUSTOM

マッチは次のロジックを使用します struct v4l2_async_subdev.match ops

V4L2_ASYNC_MATCH_DEVNAME

マッチはデバイス名を使用します

V4L2_ASYNC_MATCH_I2C

マッチはI2CアダプタIDとアドレスを確認します

V4L2_ASYNC_MATCH_FWNODE

マッチはファームウェアノードを使用します

説明

この列挙型は、非同期サブデバイスロジックが非同期デバイスをマッチングするためのアルゴリズムを定義するために使用されます。

struct v4l2_async_subdev¶

ブリッジが認識するサブデバイスの記述子

定義

struct v4l2_async_subdev {
  enum v4l2_async_match_type match_type;
  union {
    struct fwnode_handle *fwnode;
    const char *device_name;
    struct {
      int adapter_id;
      unsigned short address;
    } i2c;
    struct {
      bool (*match)(struct device *dev, struct v4l2_async_subdev *sd);
      void *priv;
    } custom;
  } match;
  struct list_head list;
  struct list_head asd_list;
};

メンバ

match_type

使用されるマッチの種類

match

各バスタイプのマッチングデータセットのユニオン

match.fwnode

ポインタ struct fwnode_handle マッチング対象。次の条件で使用されます match_type 通常のRCU読み込み側クリティカルセクションは、条件付きでスリープロックを取得することが許容されます（例として V4L2_ASYNC_MATCH_FWNODE.

match.device_name

マッチング対象のデバイス名を含む文字列。次の条件で使用されます match_type 通常のRCU読み込み側クリティカルセクションは、条件付きでスリープロックを取得することが許容されます（例として V4L2_ASYNC_MATCH_DEVNAME.

match.i2c

マッチング対象のI2Cパラメータを含む埋め込まれた構造体。両方 match.i2c.adapter_id および match.i2c.address マッチングする必要があります。使用する場合 match_type 通常のRCU読み込み側クリティカルセクションは、条件付きでスリープロックを取得することが許容されます（例として V4L2_ASYNC_MATCH_I2C.

match.i2c.adapter_id

マッチングするI2CアダプタID。使用する場合 match_type 通常のRCU読み込み側クリティカルセクションは、条件付きでスリープロックを取得することが許容されます（例として V4L2_ASYNC_MATCH_I2C.

match.i2c.address

マッチングするI2Cアドレス。使用する場合 match_type 通常のRCU読み込み側クリティカルセクションは、条件付きでスリープロックを取得することが許容されます（例として V4L2_ASYNC_MATCH_I2C.

match.custom

ドライバ固有のマッチング基準。使用する場合 match_type 通常のRCU読み込み側クリティカルセクションは、条件付きでスリープロックを取得することが許容されます（例として V4L2_ASYNC_MATCH_CUSTOM.

match.custom.match

使用するドライバ固有のマッチング関数 V4L2_ASYNC_MATCH_CUSTOM.

match.custom.priv

使用するドライバ固有のプライベート構造体（マッチングパラメータを含む） V4L2_ASYNC_MATCH_CUSTOM.

list

オブジェクトをリンクするための struct v4l2_async_subdev プローブ待機中のオブジェクトを notifier->waiting リストに結びつけるための

asd_list

オブジェクトをマスターノティフィケーションに追加するための struct v4l2_async_subdev オブジェクトをマスターノティフィケーションに追加するための asd_list

説明

この構造体がドライバ固有の構造体のメンバとして使用される場合、ドライバ固有の構造体は struct v4l2_async_subdev 最初のメンバとして含む必要があります。
