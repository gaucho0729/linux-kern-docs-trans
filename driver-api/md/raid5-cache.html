RAID 4/5/6キャッシュ¶

RAID 4/5/6 には、通常の RAID ディスク以外にデータキャッシュ用の追加ディスクを含む場合があります。キャッシュディスクの役割は RAID ディスクと変わりません。キャッシュディスクは RAID ディスクにデータをキャッシュします。キャッシュはライトスルー（4.4 以降サポート）またはライトバック（4.10 以降サポート）モードで構成可能です。mdadm（3.4 以降サポート）には「–write-journal」オプションが追加され、キャッシュ付きアレイの作成が可能です。詳細は mdadm マニュアルをご参照ください。デフォルトでは（RAID アレイ起動時）、キャッシュはライトスルーモードで動作します。ユーザーは以下のようにモードを切り替えることができます:

echo "write-back" > /sys/block/md0/md/journal_mode

ライトスルーモードに戻すには以下を実行してください:

echo "write-through" > /sys/block/md0/md/journal_mode

両モードにおいて、アレイへのすべての書き込みはキャッシュディスクに最初にヒットします。これはキャッシュディスクが高速で持続可能である必要があることを意味します。

ライトスルーモード¶

このモードは主に「ライトホール」問題を解決します。RAID 4/5/6 アレイにおいて、不正なシャットダウンにより一部のストライプのデータが一貫していない状態になる可能性があります（例：データとパリティが一致しない）。その理由は、ストライプ書き込みは複数の RAID ディスクを関与するため、不正なシャットダウン前にすべての RAID ディスクに書き込まれていない可能性があるからです。データが不一致なアレイは「デグレード」と呼ばれます。MD はアレイを再同期して正常な状態に戻そうとしますが、再同期が完了する前であれば、システムのクラッシュにより RAID アレイ内の実データの破損の可能性が生じます。この問題を「ライトホール」と呼びます。

ライトスルー キャッシュは、すべてのデータをキャッシュディスクに一時保存します。データがキャッシュディスクに安全に保存された後、RAID ディスクにフラッシュされます。この二段階書き込みにより、不正なシャットダウン後でも MD が正しいデータを復元できるため、アレイがデグレード状態であっても「ライトホール」を閉じることができます。

ライトスルー モードでは、MD は RAID ディスクにデータが安全に保存された後に上位レイヤー（通常はファイルシステム）に I/O 完了を報告します。そのため、キャッシュディスクの故障でもデータロスが発生しません。もちろん、キャッシュディスクの故障は再び「ライトホール」のリスクにさらします。

ライトスルー モードでは、キャッシュディスクの容量は大きくなくてもよいです。数百メガバイト程度で十分です。

ライトバックモード¶

write-backモードは「write hole」問題も解決します。なぜなら、すべての書き込みデータがキャッシュディスクに一時保存されるからです。ただし、「write-back」キャッシュの主な目的は書き込み速度を向上させることです。ストライプのすべてのRAIDディスクに書き込みが及ぶ場合、これを「フルストライプ書き込み」と呼びます。フルストライプ書き込みでない場合、MDは新しいパリティを計算する前に古いデータを読み込む必要があります。このような同期読み込みは書き込みスループットに悪影響を与えます。連続的な書き込みであっても、同時に処理されない場合、このオーバーヘッドに影響を受けます。write-backキャッシュはデータを一時保存し、データがフルストライプ書き込みになるまで待機した後、RAIDディスクに一括して書き込みます。これによりオーバーヘッドを完全に回避できるため、一部のワークロードには非常に役立ちます。連続書き込み後にfsyncを実行する典型的なワークロードが例です。

write-backモードでは、MDはデータがキャッシュディスクに到達した直後に上位レイヤー（通常はファイルシステム）にIO完了を報告します。データは特定の条件が満たされた後、RAIDディスクにフラッシュされます。そのため、キャッシュディスクの障害はデータロスを引き起こします。

write-backモードでは、MDはメモリにもデータをキャッシュします。メモリキャッシュにはキャッシュディスクに保存された同じデータが含まれるため、電源喪失でもデータロスは発生しません。メモリキャッシュのサイズは配列のパフォーマンスに影響を与えます。サイズは大きいほど推奨されます。ユーザーは以下のようにサイズを設定できます:

echo "2048" > /sys/block/md0/md/stripe_cache_size

キャッシュディスクが小さすぎると、ワークロードによって書き込みの集約効率が低下する可能性があります。write-backモードでは、少なくとも数ギガバイトのサイズを持つキャッシュディスクを使用することを推奨します。

実装¶

write-throughとwrite-backキャッシュは同じディスクフォーマットを使用します。キャッシュディスクは単純なwrite logとして構成されます。このlogは「メタデータ」と「データ」のペアから構成され、メタデータはデータを記述し、復元識別に使用するチェックサムとシーケンスIDも含みます。データはIOデータやパリティデータを含み、データはチェックサムも含みます。チェックサムはデータの前にメタデータに保存され、これはMDがメタデータとデータの順序に気を配らずに自由に書き込めるための最適化です。MDスーパーブロックには、logヘッドの有効なメタデータを指すフィールドがあります。

logの実装は非常にシンプルです。難しいのは、MDがキャッシュディスクとRAIDディスクにデータを書き込む順序です。具体的には、write-throughモードでは、MDはIOデータのパリティを計算し、IOデータとパリティをlogに書き込みます。その後、logにデータとパリティが安定した後、RAIDディスクにデータとパリティを書き込み、最後にIOが完了します。読み込みは通常通りRAIDディスクから行われます。

書き戻しモードでは、MDがIOデータをログに書き込み、IO完了を報告します。その時点でデータはメモリに完全にキャッシュされ、これは読み取りがメモリキャッシュを参照することを意味します。特定の条件が満たされた場合、MDはデータをRAIDディスクにフラッシュします。MDはデータのパリティを計算し、ログにパリティを書き込みます。この処理が完了後、MDはデータとパリティをRAIDディスクに書き込み、その後メモリキャッシュを解放します。フラッシュ条件は、ストライプがフルストライプ書き込みになる、空きキャッシュディスク領域が低くなる、または空きインカーネルメモリキャッシュ領域が低くなるなどが考えられます。

不正なシャットダウン後、MDは回復処理を行います。MDはログからすべてのメタデータとデータを読み込みます。シーケンスIDとチェックサムにより、破損したメタデータやデータを検出します。MDがデータと有効なパリティ（RAID4/5では1つ、RAID6では2つ）を持つストライプを見つけた場合、MDはデータとパリティをRAIDディスクに書き込みます。パリティが不完全な場合、またはデータの一部が破損している場合、それらは破棄されます。MDは有効なデータを読み込み、通常通りRAIDディスクに書き込みます。
