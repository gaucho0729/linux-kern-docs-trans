s390チャネルデバイスドライバの作成¶

著者

Cornelia Huck

はじめに¶

このドキュメントでは、s390ベースのチャネル接続I/Oデバイスを駆動するデバイスドライバが利用できるインターフェースについて説明します。ハードウェアとのやり取りや、一般的なドライバコアとのやり取りに必要なインターフェースが含まれます。これらのインターフェースはs390の一般的なI/Oレイヤーによって提供されます。

このドキュメントでは、s390チャネルI/Oアーキテクチャに関連する技術用語に精通していることを前提としています。このアーキテクチャについての説明は、「z/Architecture: Principles of Operation」、IBM出版物番号SA22-7832を参照してください。

s390システム上のほとんどのI/Oデバイスは、ここに説明するチャネルI/Oメカニズムを通じて駆動されることが一般的ですが、diagインターフェースなどの他の方法もあります。これらは本ドキュメントの範囲外です。

s390の一般的なI/Oレイヤーは、厳密にはI/Oデバイスとみなされないデバイスにもアクセスを提供します。これらも含めて説明しますが、本ドキュメントの焦点ではありません。

さらなる情報は、カーネルソースの以下の場所にあります S/390ドライバモデルインターフェース.

cssバス¶

cssバスには、システム上の利用可能なサブチャネルが含まれています。これらはいくつかのカテゴリに分類されます：

  • 標準I/Oサブチャネル、システムで使用します。これらはccwバス上の子デバイスを持ち、以下で説明します。

  • vfio-ccwドライバにバインドされたI/Oサブチャネル。詳しくは vfio-ccw: 基本的なインフラストラクチャ.

  • メッセージサブチャネル。現在のLinuxドライバは存在しません。

  • CHSCサブチャネル（最大1つ）。chscサブチャネルドライバを使用して、非同期のchscコマンドを送信できます。

  • eADMサブチャネル。ストレージクラスメモリとの通信に使用します。

ccwバス¶

ccwバスは、s390システムに利用可能なデバイスの大部分を含みます。チャネルコマンドワード（ccw）という基本的なコマンド構造に名付けられ、ccwバスはいわゆるチャネル接続デバイスを含みます。これらはI/Oサブチャネルを通じてアドレス指定され、cssバス上に表示されます。チャネル接続デバイスのドライバは、サブチャネルを直接操作することなく、ccwバス上のI/Oデバイス（ccwデバイス）を通じて操作します。

チャネル接続デバイス用のI/O機能¶

一部のハードウェア構造は、一般的なI/Oレイヤーおよびデバイスドライバで使用するためにC構造に変換されています。ハードウェア構造に関する詳細情報については、「Principles of Operation」を参照してください。

struct irb¶

割込み応答ブロック

定義

struct irb {
  union scsw scsw;
  union {
    struct esw0 esw0;
    struct esw1 esw1;
    struct esw2 esw2;
    struct esw3 esw3;
    struct esw_eadm eadm;
  } esw;
  __u8 ecw[32];
};

メンバ

scsw

サブチャネルステータスワード

esw

拡張ステータスワード

ecw

拡張制御ワード

説明

割込みが発生した際にデバイスドライバーに渡されるirb。求められた割込みの場合、共通I/Oレイヤーはすでにフィールドが有効かどうかを確認しており、フィールドが無効である場合でも常に 0。ユニットチェックが発生した場合、 ecw センスデータを含可能（デバイスが同時センスをサポートしない場合、共通I/Oレイヤーが自身でセンスデータを取得するため、デバイスドライバーが基本的なセンスを実行する必要はありません）。求められていない割込みの場合、irbは変更せずに渡されます（センスデータが必要な場合は除く）。

ccwデバイス¶

チャネルI/Oを開始したいデバイスはccwバスに接続する必要があります。ドライバコアとの相互作用は共通I/Oレイヤーを通じて行われ、ccwデバイスとccwデバイスドライバーの抽象概念を提供します。

チャネルI/Oを開始または終了する関数はすべてccwデバイス構造に作用します。デバイスドライバーはこれらの関数をバイパスしてはなりません。

チャネル測定機能¶

チャネル測定機能は、チャネルサブシステムが各チャネル接続デバイスに対して提供する測定データを収集するための手段を提供します。

ccwgroupバス¶

ccwgroupバスにはユーザーが作成した人工デバイスのみが含まれます。多くのネットワークデバイス（例：qeth）は実際には複数のccwデバイス（qethの場合、読み取り、書き込み、データチャネルなど）で構成されています。ccwgroupバスは、これらのccwデバイスをslaveデバイスとして含むメタデバイスを作成するメカニズムを提供します。
