NVMEM サブシステム¶

Srinivas Kandagatla <srinivas.kandagatla@linaro.org>

このドキュメントではNVMEMフレームワークと提供されるAPI、およびその使用方法について説明します。

1. はじめに¶

NVMEM 非揮発性メモリ層の略称です。eeprom、efusesなどの非揮発性メモリからSoCやデバイス固有の設定情報を取得するために使用されます。

このフレームワークが存在する前は、eepromなどのNVMEMドライバがdrivers/miscに配置されており、sysfsファイルの登録や、内核ユーザーがドライバが駆動するデバイスの内容にアクセスできるようにするためのコードをほぼ同じコードを複数のドライバで繰り返し実装していました。

これは、他の内核ユーザーにとっても問題でした。なぜなら、各ドライバで使用する解決策が大きく異なり、抽象化の漏れがかなり発生していたからです。

このフレームワークはこれらの問題を解決することを目的としています。また、消費者デバイスがNVMEMから必要なデータ（MACアドレス、SoC/リビジョンID、部品番号など）を取得できるようにするDT（Device Tree）表現も導入しています。このフレームワークはregmapに基づいており、regmapで利用可能な大部分の抽象化を複数のバスタイプで再利用できます。

NVMEMプロバイダー¶

NVMEMプロバイダーとは、非揮発性メモリを初期化し、読み書きするメソッドを実装したエンティティを指します。

2. NVMEM プロバイダーの登録/解除¶

NVMEMプロバイダーは、nvmem_register()に関連するnvmem構成情報を提供することでNVMEMコアに登録できます。登録成功時にコアは有効なnvmem_deviceポインタを返します。

nvmem_unregister(nvmem)は以前に登録されたプロバイダーをアンレジストします。

例えば、シンプルなqfpromケース:

static struct nvmem_config econfig = {
      .name = "qfprom",
      .owner = THIS_MODULE,
};

static int qfprom_probe(struct platform_device *pdev)
{
      ...
      econfig.dev = &pdev->dev;
      nvmem = nvmem_register(&econfig);
      ...
}

NVMEMプロバイダーは必ずregmapを関連付けている必要があります。 struct device. これを実施しないとnvmem_register()からエラー コードが返されます。

ボードファイルのユーザーはnvmem_cell_table構造体を使用してnvmemセルを定義し、登録できます:

static struct nvmem_cell_info foo_nvmem_cells[] = {
      {
              .name           = "macaddr",
              .offset         = 0x7f00,
              .bytes          = ETH_ALEN,
      }
};

static struct nvmem_cell_table foo_nvmem_cell_table = {
      .nvmem_name             = "i2c-eeprom",
      .cells                  = foo_nvmem_cells,
      .ncells                 = ARRAY_SIZE(foo_nvmem_cells),
};

nvmem_add_cell_table(&foo_nvmem_cell_table);

さらに、機械コードからnvmemセルの検索エントリを生成し、nvmemフレームワークに登録することも可能です（以下例をご参照ください）:

static struct nvmem_cell_lookup foo_nvmem_lookup = {
      .nvmem_name             = "i2c-eeprom",
      .cell_name              = "macaddr",
      .dev_id                 = "foo_mac.0",
      .con_id                 = "mac-address",
};

nvmem_add_cell_lookups(&foo_nvmem_lookup, 1);

NVMEM消費者¶

NVMEMプロバイダーを使用してNVMEMから読み書きを行うエンティティを指します。

3. NVMEMセルベースの消費者API¶

NVMEMセルはNVMEM内のデータエントリ/フィールドです。NVMEMフレームワークはNVMEMセルの読み書きに3つのAPIを提供します:

struct nvmem_cell *nvmem_cell_get(struct device *dev, const char *name);
struct nvmem_cell *devm_nvmem_cell_get(struct device *dev, const char *name);

void nvmem_cell_put(struct nvmem_cell *cell);
void devm_nvmem_cell_put(struct device *dev, struct nvmem_cell *cell);

void *nvmem_cell_read(struct nvmem_cell *cell, ssize_t *len);
int nvmem_cell_write(struct nvmem_cell *cell, void *buf, ssize_t len);

*nvmem_cell_get() APIは指定されたIDに基づいてnvmemセルへの参照を取得し、nvmem_cell_read/write()はセルの読み書きを行います。セルの使用が終了した後、消費者は *nvmem_cell_put() を呼び出してセルの割当メモリをすべて解放する必要があります。

4. 直接NVMEMデバイスベースの消費者API¶

一部のケースでは、NVMEMを直接読み書きする必要があります。このような消費者のために、NVMEMフレームワークは以下のAPIを提供しています:

struct nvmem_device *nvmem_device_get(struct device *dev, const char *name);
struct nvmem_device *devm_nvmem_device_get(struct device *dev,
                                         const char *name);
struct nvmem_device *nvmem_device_find(void *data,
                      int (*match)(struct device *dev, const void *data));
void nvmem_device_put(struct nvmem_device *nvmem);
int nvmem_device_read(struct nvmem_device *nvmem, unsigned int offset,
                    size_t bytes, void *buf);
int nvmem_device_write(struct nvmem_device *nvmem, unsigned int offset,
                     size_t bytes, void *buf);
int nvmem_device_cell_read(struct nvmem_device *nvmem,
                         struct nvmem_cell_info *info, void *buf);
int nvmem_device_cell_write(struct nvmem_device *nvmem,
                          struct nvmem_cell_info *info, void *buf);

消費者がNVMEMを直接読み書きする前に、nvmem_controllerを取得する必要があります。これは以下の *nvmem_device_get() APIから取得します。

これらのAPIとcellベースのAPIの違いは、これらのAPIが常にnvmem_deviceをパラメータとして受け取る点です。

5. NVMEMへの参照の解放¶

消費者がもはやNVMEMを必要としなくなった場合、上記のセクションで説明したAPIを使用して取得したNVMEMの参照を解放する必要があります。NVMEMフレームワークは、NVMEMの参照を解放するための2つのAPIを提供しています:

void nvmem_cell_put(struct nvmem_cell *cell);
void devm_nvmem_cell_put(struct device *dev, struct nvmem_cell *cell);
void nvmem_device_put(struct nvmem_device *nvmem);
void devm_nvmem_device_put(struct device *dev, struct nvmem_device *nvmem);

これらのAPIはすべてNVMEMの参照を解放するために使用され、devm_nvmem_cell_putおよびdevm_nvmem_device_putはこのNVMEMに関連するdevresを破壊します。

ユーザースペース¶

6. ユーザースペースバイナリインターフェース¶

ユーザースペースは、以下の場所に配置されているraw NVMEMファイルを読み書きできます:

/sys/bus/nvmem/devices/*/nvmem

例:

hexdump /sys/bus/nvmem/devices/qfprom0/nvmem

0000000 0000 0000 0000 0000 0000 0000 0000 0000
*
00000a0 db10 2240 0000 e000 0c00 0c00 0000 0c00
0000000 0000 0000 0000 0000 0000 0000 0000 0000
...
*
0001000
