LinuxカーネルSLIMbusサポート¶

概要¶

SLIMbusとは？¶

SLIMbus（Serial Low Power Interchip Media Bus）は、MIPI（Mobile Industry Processor Interface）アライアンスが開発した仕様です。このバスはマスターマスター/スレーブ構成を採用しており、クロックとデータの2線でマルチドロップ実装されています。

現在、SLIMbusはSoC（システム・オン・チップ）のアプリケーションプロセッサと周辺コンポーネント（通常はコーデック）のインターフェースとして使用されています。SLIMbusはタイム・ディビジョン・マルチプレクシングを用いて複数のデータチャネルとコントロールチャネルをサポートしています。

コントロールチャネルは、バス管理、設定、ステータス更新などのさまざまな制御機能に使用されます。これらのメッセージはユニキャスト（例：デバイス固有値の読み書き）またはマルチキャスト（例：データチャネルの再構成シーケンスはすべてのデバイスに送信されるブロードキャストメッセージ）のいずれかです。

データチャネルは2つのSLIMbusデバイス間でのデータ転送に使用され、データチャネルはデバイス上の専用ポートを使用します。

ハードウェアの説明：¶

SLIMbus仕様では、デバイスの機能に応じてさまざまな種類のデバイス分類が定義されています。マネージャー・デバイスは列挙、設定、ダイナミック・チャネル・割り当てを担当し、すべてのバスには1つのアクティブなマネージャーが存在します。

ジェネリック・デバイスはアプリケーション機能を提供するデバイス（例：コーデック）です。

フレーマー・デバイスはバスのクロック制御を担当し、フレーム同期およびフレーミング情報をバス上に送信します。

各SLIMbusコンポーネントは物理層のモニタリングに使用されるインターフェース・デバイスを持っています。

通常、各SoCにはSLIMbusコンポーネントが含まれており、1つのマネージャー・デバイス、1つのフレーマー・デバイス、1つのジェネリック・デバイス（データチャネルサポート用）、1つのインターフェース・デバイスを持っています。外部周辺SLIMbusコンポーネントは通常、1つのジェネリック・デバイス（機能/データチャネルサポート用）と関連するインターフェース・デバイスを持っています。ジェネリック・デバイスのレジスタは「値要素」としてマッピングされ、SLIMbusコントロールチャネルを介して制御/ステータス情報を交換するための読み書きが可能です。同一のバス上に複数のフレーマー・デバイスがある場合、マネージャー・デバイスがアクティブなフレーマーを選択します。

仕様上、SLIMbusは現在の周波数および帯域幅要件に基づいて「クロック・ギア」を使用して電源管理を行います。クロック・ギアは10種類あり、各ギアは前のギアの2倍の周波数に変更されます。

各デバイスには6バイトの列挙アドレスがあり、マネージャーはデバイスがバス上に存在することを報告した後、各デバイスに1バイトの論理アドレスを割り当てます。

ソフトウェアの説明：¶

SLIMbusドライバーには2つのタイプがあります:

slim_controllerはSLIMbusの「コントローラー」を表し、このドライバーはSoC（マネージャーデバイス、レイヤーの監視とエラー報告を行う関連インターフェースデバイス、デフォルトフレーマーデバイス）が必要とする作業を実装する必要があります。

slim_deviceはSLIMbusの「汎用デバイス/コンポーネント」を表し、slim_driverはこのslim_device用のドライバーを実装する必要があります。

ドライバへのデバイス通知:¶

SLIMbusデバイスは存在を報告するメカニズムを持っています。このため、フレームワークは、対応するデバイスがバス上で存在を報告したときにドライバがバインドできるようにします。ただし、ドライバが対応するSLIMbusデバイスを有効化する（例：電源をオンにしたり、リセット状態から抜けたり）ために最初にプローブする必要がある場合があります。その動作をサポートするため、フレームワークはドライバが最初にプローブすることを許可しています（例：標準のDeviceTree互換性フィールドを使用）。これにより、ドライバがデバイスが機能している（つまり、存在を報告している）ときにいつかを把握する必要があります。そのために、デバイスが存在を報告し、コントローラーによって論理アドレスが割り当てられたときにdevice_upコールバックが使用されます。

同様に、SLIMbusデバイスはダウンしたときに「存在していない」と報告します。デバイスが存在していないと報告し、コントローラーによって論理アドレス割り当てが無効化されたときに、device_downコールバックがドライバに通知します。

また、「boot_device」という通知は、コントローラーがバスをリセットしたときにslim_driverに通知します。この通知により、ドライバはバスがリセットされた後にデバイスが機能するように必要な手順を実行できます。

SLIMbusデバイスの状態

定数

SLIMbusデバイスが存在していないか、まだ報告されていない状態です。

struct slim_device {

e_addr

ctrl

status

SLIMbusデバイスの状態

laddr

このデバイスの1バイトの論理アドレス

is_laddr_valid

laddrが有効かどうかを示します

stream_list

このデバイス上のストリーム一覧

stream_list_lock

ストリーム一覧を保護するロック

説明

SLIMbusデバイスがコントローラーに登録されると返されるクライアント/デバイスハンドルです。この構造体へのポインタは、クライアントドライバがハンドルとして使用します。

struct slim_driver¶

SLIMbusの「汎用デバイス」（スレーブ）ドライバ（SPIのspi_deviceに類似）

定義

struct slim_driver {
  int (*probe)(struct slim_device *sl);
  void (*remove)(struct slim_device *sl);
  void (*shutdown)(struct slim_device *sl);
  int (*device_status)(struct slim_device *sl, enum slim_device_status s);
  struct device_driver            driver;
  const struct slim_device_id     *id_table;
};

メンバ

probe

このドライバをSLIMbusデバイスにバインドします。

remove

このドライバをSLIMbusデバイスからアンバインドします。

shutdown

電源オフ/停止時の標準シャットダウンコールバック

device_status

このコールバックは、以下の条件に該当したときに呼び出されます - デバイスが存在を報告しladdrが割り当てられた場合 - デバイスが存在を報告しなくなったか、バスが停止した場合。

driver

SLIMbusデバイスドライバーは、この構造体のnameとownerフィールドを初期化する必要があります。

id_table

このドライバーがサポートするSLIMbusデバイスの一覧

struct slim_val_inf¶

Slimbus値または情報要素

定義

struct slim_val_inf {
  u16 start_offset;
  u8 num_bytes;
  u8 *rbuf;
  const u8                *wbuf;
  struct completion      *comp;
};

メンバ

start_offset

情報/値要素マップにおける開始オフセットを指定します。

num_bytes

最大16まで。これにより、メッセージがSLIMbus仕様のスライスサイズに収まるようになります。

rbuf

値を読み取るバッファ

wbuf

書き込むバッファ

comp

非同期操作の完了処理。TIDがトランザクションに必要となる場合（例: REQUEST操作）にのみ有効です。他のトランザクションはすべて同期処理です。

struct slim_stream_config¶

SLIMbusストリームの設定。オーディオドライバーからhw_paramsまたはprepareコールで行われ、レート、チャネル数などの必要な情報をすべて持っています。チャネルとポートは1対1でマッピングされます。

定義

struct slim_stream_config {
  unsigned int rate;
  unsigned int bps;
  unsigned int ch_count;
  unsigned int *chs;
  unsigned long port_mask;
  int direction;
};

メンバ

rate

データレート

bps

データサンプルあたりのビット数

ch_count

チャネル数

chs

チャネル番号の一覧へのポインタ

port_mask

このストリームで使用するポートのマスク

direction

ストリームの方向、SNDRV_PCM_STREAM_PLAYBACKまたはSNDRV_PCM_STREAM_CAPTURE。

module_slim_driver¶

module_slim_driver (__slim_driver)

SLIMbusドライバーの登録に使用する補助マクロ

パラメータ

__slim_driver

slimbus_driver構造体

説明

モジュールの初期化/終了時に特別な処理を行わないSLIMbusドライバー用の補助マクロ。これにより多くのボイラープレートが省略されます。各モジュールはこのマクロを一度だけ使用し、呼び出すことで置き換えられます。 module_init() および module_exit()

struct slim_framer¶

SLIMbusフレーマーを表します。すべてのコントローラーは複数のフレーマーを持つ可能性があります。バスのクロックを担当するアクティブなフレーマーがあり、マネージャーはフレーマーの切り替えを担当します。

定義

struct slim_framer {
  struct device           dev;
  struct slim_eaddr       e_addr;
  int rootfreq;
  int superfreq;
};

メンバ

dev

デバイスのドライバーモデル表現

e_addr

フレーマーの列挙アドレス。

rootfreq

フレーマーが動作できるルート周波数。これはバスが動作可能な最大周波数（'クロックギア10'）です。

superfreq

ルート周波数あたりのスーパーフレーム。すべてのフレームは6144ビットです。

struct slim_msg_txn¶

コントローラーが送信するメッセージ。この構造体にはパケットヘッダー、ペイロード、および埋め込むバッファ（必要に応じて）が含まれます。

定義

struct slim_msg_txn {
  u8 rl;
  u8 mt;
  u8 mc;
  u8 dt;
  u16 ec;
  u8 tid;
  u8 la;
  struct slim_val_inf     *msg;
  struct completion      *comp;
};

メンバ

rl

ヘッダーフィールド。残り長さ。

mt

ヘッダーフィールド。メッセージタイプ。

mc

ヘッダーフィールド。LSBはタイプmtのメッセージコードです。

dt

ヘッダーフィールド。宛先タイプ。

ec

要素コード。要素アクセスAPIに使用されます。

tid

トランザクションID。応答を期待するメッセージに使用されます。（読み取り操作に関連するメッセージコードに適用されます）

la

このメッセージが送られるデバイスの論理アドレス。（宛先タイプがブロードキャストの場合は使用されません。）

msg

読み書きされる要素アクセスメッセージ

comp

読み書きが同期処理の場合の完了処理。tidベースのトランザクションで内部的に使用されます。

enum slim_clk_state¶

定数

SLIM_CLK_ACTIVE

SLIMbusクロックが有効です。

SLIM_CLK_ENTERING_PAUSE

SLIMbusクロックの停止シーケンスがバス上に送信されています。成功した場合、状態はSLIM_CLK_PAUSEDに変更されます。失敗した場合、状態はSLIM_CLK_ACTIVEに戻ります

SLIM_CLK_PAUSED

SLIMbusコントローラークロックが停止しました。

説明

現在のクロック状態を保持しています。

struct slim_sched¶

定義

struct slim_sched {
  enum slim_clk_state     clk_state;
  struct completion       pause_comp;
  struct mutex            m_reconf;
};

メンバ

clk_state

コントローラーのクロック状態 enum slim_clk_state

pause_comp

クロック停止シーケンスの完了を通知します。クライアントがコントローラーがクロック停止中にSLIMbusトランザクションを呼び出す場合に役立ちます

m_reconf

このミューテックスは、現在のリコンフィギュレーション（データチャネルスケジューリング、メッセージ帯域幅予約）が完了するまで保持されます。このミューテックスが保持されている間、メッセージAPIはバス上で同時に使用可能です。リコンフィギュレーションが進行中でもエレメンタルアクセスメッセージはバス上に送信できるためです

ストリームを無効にするためのコントローラー固有の処理を実装する関数ポインタ

「マネージャーデバイス」はデバイス管理、帯域幅割当、チャネル設定、チャネルごとのポート関連付けを担当します。デバイス管理とは、デバイスの列挙（レポート-プレゼンント、レポート-アブセント）に基づく論理アドレスの割り当て/削除です。帯域幅割当は、バス上のアクティブなチャネルやSLIMbusデバイスからのメッセージ帯域幅リクエストに基づいてマネージャーが動的に実行します。現在の帯域幅使用状況に基づき、マネージャーはバスの動作周波数（クロックギアのステップで1から10、各ギアが前のギアよりも2倍の周波数を表す）を選択します。マネージャーはまた、低電力モード（クロックパーズと呼ばれる）への移行（および退出）を担当します。複数のフレーマーがバス上にある場合、特定のユースケースで特定のフレーマーを使用して以前のフレーマーの電源を維持しないようにする必要がある場合は、フレーマーの手渡しも行います

コントローラーはマネージャーデバイスの役割を果たし、「インターフェースデバイス」も担当します。インターフェースデバイスはバスの監視を行い、同期喪失やデータスロット衝突などの情報を報告します

wakeup

クロックパーズからコントローラーを再起動するためのコントローラー固有の処理を実装する関数ポインタ。フレームワークはこの関数を呼び出してコントローラーをクロックパーズから抜け出します

クロック一時停止:¶

SLIMバスは、バスが低電力モードに入る前に、バス上のすべてのアクティブなデバイスに再構成シーケンス（クロック一時停止と呼ばれる）をブロードキャストする必要があります。コントローラーは低電力モードに入るときにこのシーケンスを使用し、対応するクロックおよび/または電源ラインをオフにして電力消費を節約します。クロック一時停止を終了するには、フレーマーデバイスを起動するか、データラインをトグルします。

クロック一時停止API:¶

int slim_ctrl_clk_pause(struct slim_controller *ctrl, bool wakeup, u8 再開)¶

コントローラーがクロック一時停止に入る/出るときに呼ばれる。

パラメータ

struct slim_controller *ctrl

バスを一時停止または再開するリクエストを送信するコントローラー

bool wakeup

クロック一時停止からこのコントローラーを再開する。

u8 restart

クロック一時停止用の再開時間値（仕様に従う）。コントローラーを再開する際にはこの値は使用されません。

説明

SLIMバス仕様では、このシーケンスを使用してバスのクロックをオフにします。シーケンスには、バス上のすべてのデバイスに3つのブロードキャストメッセージ（再構成シーケンス）を送信する必要があります。クロック一時停止を終了するには、コントローラーがアクティブなフレーマーデバイスを起動します。このAPIはwakeupが偽の場合、クロック一時停止再構成シーケンスを実行します。wakeupが真の場合、コントローラーのwakeupが呼ばれます。クロック一時停止に入る際には、メッセージのトランザクションが待機中である場合、-EBUSYが返されます。

メッセージング:¶

フレームワークはSLIMバスデバイスと制御情報を交換するためのregmapおよび読み込み/書き込みAPIをサポートしています。APIは同期または非同期で使用できます。メッセージングAPIについての詳細情報は、ヘッダーファイル<linux/slimbus.h>に記載されています。
