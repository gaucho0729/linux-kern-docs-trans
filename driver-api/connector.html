カーネルコンネクタ¶

カーネルコネクタ - 新しい netlink 基盤のユーザースペース <-> カーネルスペース向けの使いやすい通信モジュール。

コネクタドライバは、netlink 基盤のネットワークを用いてさまざまなエージェントを接続するのを容易にします。コールバック関数と識別子を登録する必要があります。ドライバが適切な識別子を持つ特殊な netlink メッセージを受信すると、対応するコールバックが呼び出されます。

ユーザースペースの観点から見ると、これは非常に簡単です：

  • socket();

  • bind();

  • send();

  • recv();

しかし、カーネルスペースがこのような接続のフルパワーを活用する場合、ドライバ開発者は特殊なソケットを作成し、 struct sk_buff ハンドリングなどについて理解しておく必要があります。コネクタドライバは、カーネルスペースのエージェントが netlink 基盤のネットワークを用いてプロセス間通信を大幅に容易にするためのインターフェースを提供します：

int cn_add_callback(struct cb_id *id, char *name, void (*callback) (struct cn_msg *, struct netlink_skb_parms *));
void cn_netlink_send_mult(struct cn_msg *msg, u16 len, u32 portid, u32 __group, int gfp_mask);
void cn_netlink_send(struct cn_msg *msg, u32 portid, u32 __group, int gfp_mask);

struct cb_id
{
      __u32                   idx;
      __u32                   val;
};

idx と val は一意の識別子であり、カーネル内での使用のために connector.h ヘッダーファイルに登録する必要があります。 void (*callback) (void *) は、上記の idx.val を含むメッセージがコネクタコアによって受信されたときに呼び出されるコールバック関数です。この関数の引数は、 struct cn_msg *:

struct cn_msg
{
      struct cb_id            id;

      __u32                   seq;
      __u32                   ack;

      __u16                   len;    /* Length of the following data */
      __u16                   flags;
      __u8                    data[0];
};

コネクタインターフェース¶

int cn_add_callback(struct cb_id *id, const char *名前, void (*コールバック)(struct cn_msg*, struct netlink_skb_parms*))¶

新しいコールバックをコネクタコアに登録します。

パラメータ

struct cb_id *id

一意のコネクタのユーザ識別子です。カーネル内での合法的な使用のために connector.h に登録する必要があります。

const char *name

コネクタのコールバックシンボリック名。

void (*callback)(struct cn_msg *, struct netlink_skb_parms *)

コネクタのコールバック。パラメータは cn_msg および送信者の資格情報

void cn_del_callback(struct cb_id *id)¶

新しいコールバックをコネクタコアから解除します。

パラメータ

struct cb_id *id

一意のコネクタのユーザ識別子。

int cn_netlink_send_mult(struct cn_msg *msg, u16 len, u32 portid, u32 group, gfp_t gfp_mask)¶

指定されたグループにメッセージを送信します。

パラメータ

struct cn_msg *msg

メッセージヘッダ（添付データ付き）。

u16 len

送信する msg の数。

u32 portid

宛先ポート。非ゼロの場合、メッセージは指定されたポートに送信され、このポートは元の送信者に設定されるべきです。

u32 group

宛先グループ。もし portid および group がゼロであれば、登録されたすべてのコネクタユーザを通して適切なグループが検索され、ID が同じユーザーに割り当てられたグループにメッセージが届けられます。 msg. group ゼロでなければ、指定されたグループにメッセージが届けられます。

gfp_t gfp_mask

GFP マスク。

説明

ソフトIRQ コンテキストから安全に呼び出せますが、強いメモリ圧力下では静かに失敗する可能性があります。

指定されたグループにリスナーがいない場合 -ESRCH 返却可能です。

int cn_netlink_send(struct cn_msg *msg, u32 portid, u32 group, gfp_t gfp_mask)¶

指定されたグループにメッセージを送信します。

パラメータ

struct cn_msg *msg

メッセージヘッダ（添付データ付き）。

u32 portid

宛先ポート。非ゼロの場合、メッセージは指定されたポートに送信され、このポートは元の送信者に設定されるべきです。

u32 group

宛先グループ。もし portid および group がゼロであれば、登録されたすべてのコネクタユーザを通して適切なグループが検索され、ID が同じユーザーに割り当てられたグループにメッセージが届けられます。 msg. group ゼロでなければ、指定されたグループにメッセージが届けられます。

gfp_t gfp_mask

GFP マスク。

説明

ソフトIRQ コンテキストから安全に呼び出せますが、強いメモリ圧力下では静かに失敗する可能性があります。

指定されたグループにリスナーがいない場合 -ESRCH 返却可能です。

注意:

新しいコールバックユーザーを登録する際、コンネクタコアはそのユーザーにID.idxと等しいnetlinkグループを割り当てます。

プロトコルの説明¶

現在のフレームワークは固定ヘッダーを持つトランスポート層を提供しています。このようなヘッダーを使用する推奨プロトコルは以下の通りです。

msg->seqとmsg->ackはメッセージの系譜を決定するために使用されます。誰かがメッセージを送信する際には、ローカルで一意なシーケンスとランダムなアサーション番号を使用します。シーケンス番号はnlmsghdr->nlmsg_seqにもコピーされることがあります。

シーケンス番号は各メッセージ送信ごとにインクリメントされます。

メッセージに応答を期待する場合、受信メッセージのシーケンス番号は元のメッセージと同じでなければなりません。また、アサーション番号はその番号＋1でなければなりません。

受信メッセージのシーケンス番号が期待しているものと一致しない場合、それは新しいメッセージです。シーケンス番号が一致するが、アサーション番号が元のメッセージのシーケンス番号＋1でない場合も新しいメッセージとみなされます。

明らかに、プロトコルヘッダーには上記のIDが含まれています。

コンネクタは、選択したIDがオンまたはオフ（登録または解除）になったときに通知を提供します。これは、カーネルドライバーまたはユーザー空間プロセスがコンネクタドライバーに特別なコマンドを送ることで実現され、その際、id={-1, -1}で自身を登録します。

この使用例は、cn_test.cモジュールに見られます。このモジュールは、通知を要求しメッセージを送信するためにコンネクタを使用しています。

信頼性¶

Netlink自体は信頼性のあるプロトコルではありません。つまり、メモリ圧力やプロセスの受信キューのオーバーフローによりメッセージが失われる可能性があるため、呼び出し元はその準備をしなければなりません。そのため、struct cn_msg [メインコンネクタのメッセージヘッダー]にはu32 seqとu32 ackフィールドが含まれています。

ユーザー空間の使用方法¶

2.6.14には新しいnetlinkソケット実装があり、デフォルトではnetlinkグループ1以外にデータを送信することができません。したがって、netlinkソケット（例：コンネクタを使用）で異なるグループ番号を使用する場合、ユーザー空間アプリケーションはそのグループにまずサブスクライブする必要があります。これは以下の擬似コードで実現できます：

s = socket(PF_NETLINK, SOCK_DGRAM, NETLINK_CONNECTOR);

l_local.nl_family = AF_NETLINK;
l_local.nl_groups = 12345;
l_local.nl_pid = 0;

if (bind(s, (struct sockaddr *)&l_local, sizeof(struct sockaddr_nl)) == -1) {
      perror("bind");
      close(s);
      return -1;
}

{
      int on = l_local.nl_groups;
      setsockopt(s, 270, 1, &on, sizeof(on));
}

上記の270はSOL_NETLINK、1はNETLINK_ADD_MEMBERSHIPソケットオプションです。マルチキャストサブスクライブを解除するには、NETLINK_DROP_MEMBERSHIPパラメータ（0で定義）を使用した上記のソケットオプションを呼び出します。

2.6.14のnetlinkコードでは、最大グループ番号（netlink_kernel_create()時に使用される）以下のグループのみを選択可能です。コネクタの場合、CN_NETLINK_USERS + 0xfが使用されるため、グループ番号12345を使用したい場合はCN_NETLINK_USERSをその数値に増やす必要があります。追加で0xf番のグループ番号は非カーネルユーザーに割り当てられます。

この制限により、グループ0xffffffffは現在動作しません。そのため、コネクタのグループ通知の追加/削除が行えません。ただし、私が知る限りはcn_test.cテストモジュールのみがこのグループを使用していました。

netlink関連の作業はまだ進行中であるため、2.6.15の期間に変更がある可能性があります。その場合、ドキュメンテーションはそれに合わせて更新されます。

コードサンプル¶

コネクタテストモジュールおよびユーザー空間のサンプルコードはsamples/connector/にあります。このコードをビルドするには、CONFIG_CONNECTORとCONFIG_SAMPLESを有効にしてください。
