0. はじめに¶

更新日: 2008年1月2日

著作権 (c) 2008 Intel Corporation

汎用的な熱管理 Sysfs は、熱ゾーンデバイス（センサー）および熱冷却デバイス（ファン、プロセッサ…）が熱管理ソリューションに登録し、その一部となるためのインターフェースを提供します。

  • [0-*] 0から始まる任意の正数を表します

  • [1-*] 1から始まる任意の正数を表します

1. 熱 Sysfs ドライバ インターフェース関数¶

1.1 熱ゾーンデバイス インターフェース¶

struct thermal_zone_device
*thermal_zone_device_register(char *type,
                              int trips, int mask, void *devdata,
                              struct thermal_zone_device_ops *ops,
                              const struct thermal_zone_params *tzp,
                              int passive_delay, int polling_delay))

このインターフェース関数は、/sys/class/thermal フォルダに新しい熱ゾーンデバイス（センサー）を追加し、 thermal_zone[0-*]同時に登録されたすべての熱冷却デバイスにバインドしようとします。

type:

熱ゾーンのタイプ。

トリップポイント:

この熱ゾーンがサポートするトリップポイントの総数。

イベントマスク:

ビット列: ‘n’番目のビットが設定されている場合、トリップポイント ‘n’ は書き込み可能です。

devdata:

デバイスのプライベートデータ

ops:

熱ゾーンデバイスのコールバック。

.bind:

熱ゾーンデバイスを熱冷却デバイスとバインドします。

.unbind:

熱ゾーンデバイスと熱冷却デバイスのバインドを解除します。

.get_temp:

熱ゾーンの現在温度を取得します。

.set_trips:

トリップポイントのウィンドウを設定します。現在温度が更新されるたびに、現在温度の直下と直上のトリップポイントが検出されます。

.get_mode:

熱ゾーンの現在のモード（有効/無効）を取得します。

  • 「有効」は、カーネルの熱管理が有効であることを意味します。

  • 「無効」は、トリップポイントでのカーネル熱ドライバの動作を停止し、ユーザー アプリケーションが熱管理を担当できるようにします。

.set_mode:

熱ゾーンのモード（有効/無効）を設定します。

.get_trip_type:

特定のトリップポイントのタイプを取得します。

.get_trip_temp:

特定のトリップポイントが発火する温度を取得します。

.set_emul_temp:

デバッグ用に異なる閾値温度ポイントをシミュレートするためのエミュレーション温度を設定します。

tzp:

サーモアルゾーンプラットフォームパラメータ。

passive_delay:

パッシブクーリングを実行する際のポール間の待機ミリ秒数。

polling_delay:

トリップポイントが跨がったかを確認する際のポール間の待機ミリ秒数（割り込み駆動システムでは0を指定します）。

void thermal_zone_device_unregister(struct thermal_zone_device *tz)

このインターフェース関数はサーモアルゾーンデバイスを削除します。/sys/class/thermalフォルダから該当するエントリを削除し、使用しているサーモクーリングデバイスをアンバインドします。

struct thermal_zone_device
*thermal_zone_of_sensor_register(struct device *dev, int sensor_id,
                     void *data,
                     const struct thermal_zone_of_device_ops *ops)

このインターフェースはDTサーモアルゾーンに新しいセンサーを追加します。この関数はデバイスツリーに記述されたサーモアルゾーンリストを検索し、dev->of_nodeで指すセンサーデバイスを温度プロバイダーとして参照するゾーンを探します。センサーノードを参照するゾーンに対して、センサーをDTサーモアルゾーンデバイスに追加します。

このインターフェースのパラメータは以下の通りです：

dev:

dev->of_nodeに有効なノードポインタを含むセンサーのデバイスノード。

sensor_id:

センサーIPが複数のセンサーを有する場合のセンサー識別子。

data:

プライベートポインタ（呼び出し元が所有）で、温度読み取りが必要なときに呼び出し元に返されます。

ops:

struct thermal_zone_of_device_ops *.

get_temp

センサー温度を読み取るための関数ポインタ。これはセンサードライバから提供される必須コールバックです。

set_trips

温度ウィンドウを設定するための関数ポインタ。このウィンドウを離れるとドライバはthermal_zone_device_updateを介してサーモコアに通知しなければなりません。

get_trend

センサー温度トレンドを読み取るための関数ポインタ。

set_emul_temp

センサーのエミュレーション温度を設定するための関数ポインタ。

サーモアルゾーン温度はthermal_zone_of_device_opsのget_temp()関数ポインタから提供されます。呼び出されると、プライベートポインタ@dataが戻されます。

失敗した場合はエラーポインタを返し、成功した場合は有効なサーモアルゾーンデバイスハンドルを返します。呼び出し元はIS_ERR()で結果を確認します。

void thermal_zone_of_sensor_unregister(struct device *dev,
                                       struct thermal_zone_device *tzd)

このインターフェースはthermal_zone_of_sensor_register()で成功して追加されたセンサーをDTサーモアルゾーンから登録を解除します。この関数はthermal_zone_of_sensor_register()インターフェースで登録されたサーモアルゾーンデバイスからセンサーのコールバックとプライベートデータを削除します。また、.get_temp()とget_trend()のサーモアルゾーンデバイスコールバックを削除してゾーンを無効化します。

struct thermal_zone_device
*devm_thermal_zone_of_sensor_register(struct device *dev,
                      int sensor_id,
                      void *data,
                      const struct thermal_zone_of_device_ops *ops)

このインターフェースはthermal_zone_of_sensor_register()のリソース管理バージョンです。

セクション1.1.3で説明されているthermal_zone_of_sensor_register()のすべての詳細はここにも適用されます。

このインターフェースを使用してセンサーを登録するメリットは、エラー処理パスやドライバのアンバインディング中にthermal_zone_of_sensor_unregister()を明示的に呼び出す必要がないことです。これはドライバリソースマネージャーが自動的に処理します。

void devm_thermal_zone_of_sensor_unregister(struct device *dev,
                                struct thermal_zone_device *tzd)

このインターフェースはthermal_zone_of_sensor_unregister()のリソース管理バージョンです。セクション1.1.4で説明されているthermal_zone_of_sensor_unregister()のすべての詳細はここにも適用されます。通常この関数は呼び出さず、リソース管理コードがリソースを解放することを保証します。

int thermal_zone_get_slope(struct thermal_zone_device *tz)

このインターフェースはサーモアルゾーンデバイスのスロープ属性値を読み取るためのものです。これはプラットフォームドライバが温度計算に利用できるかもしれません。

int thermal_zone_get_offset(struct thermal_zone_device *tz)

このインターフェースはサーモアルゾーンデバイスのオフセット属性値を読み取るためのものです。これはプラットフォームドライバが温度計算に利用できるかもしれません。

1.2 サーモアル冷却デバイスインターフェース¶

struct thermal_cooling_device
*thermal_cooling_device_register(char *name,
                void *devdata, struct thermal_cooling_device_ops *)

このインターフェース関数は、/sys/class/thermal/フォルダに新しいサーモアル冷却デバイス（ファン/プロセッサ/…）をcooling_device[0-*]として追加します。 cooling_device[0-*]。同時に登録されたすべてのサーモアルゾーンデバイスに自身をバインドしようとします。

name:

冷却デバイス名。

devdata:

デバイスプライベートデータ。

ops:

サーモアル冷却デバイスコールバック。

.get_max_state:

冷却デバイスの最大スロットステートを取得します。

.get_cur_state:

冷却デバイスの現在のリクエストスロットステートを取得します。

.set_cur_state:

冷却デバイスの現在のスロットステートを設定します。

void thermal_cooling_device_unregister(struct thermal_cooling_device *cdev)

このインターフェース関数はサーモアル冷却デバイスを削除します。/sys/class/thermal/フォルダから対応するエントリを削除し、すべての使用しているサーモアルゾーンデバイスから自身をアンバインドします。

1.3 サーモアルゾーンデバイスとサーモアル冷却デバイスのバインディングインターフェース¶

int thermal_zone_bind_cooling_device(struct thermal_zone_device *tz,
        int trip, struct thermal_cooling_device *cdev,
        unsigned long upper, unsigned long lower, unsigned int weight);

このインターフェース関数はサーモアル冷却デバイスを特定のトリップポイントにバインドします。

この関数は通常サーモアルゾーンデバイスの.bindコールバック内で呼び出されます。

tz:

サーモアルゾーンデバイス

cdev:

サーモアル冷却デバイス

trip:

冷却デバイスが関連付けられているこのサーモアルゾーンのトリップポイントを指定します。

upper:

このトリップポイントの最大冷却ステート。THERMAL_NO_LIMITは上限がなく、冷却デバイスがmax_stateで動作可能を意味します。

lower:

このトリップポイントで使用可能な最小冷却ステート。THERMAL_NO_LIMITは下限がなく、冷却ステート0で動作可能を意味します。

weight:

この冷却デバイスがこのサーマルゾーンに与える影響。詳しくは下記1.4.1をご参照ください。

int thermal_zone_unbind_cooling_device(struct thermal_zone_device *tz,
                        int trip, struct thermal_cooling_device *cdev);

このインターフェース関数は、サーマルゾーンデバイスの特定のトリップポイントから冷却デバイスをアンバインドします。この関数は通常、サーマルゾーンデバイスの.unbindコールバックで呼び出されます。

tz:

サーモアルゾーンデバイス

cdev:

サーモアル冷却デバイス

trip:

冷却デバイスが関連付けられているこのサーモアルゾーンのトリップポイントを指定します。

1.4 サーマルゾーンパラメータ¶

struct thermal_bind_params

この構造体は、特定のトリップポイントでゾーンと冷却デバイスをバインドするために使用される以下のパラメータを定義します。

.cdev:

冷却デバイスのポインタ

.weight:

特定の冷却デバイスがこのゾーンに与える「影響」を表します。これは他の冷却デバイスと比較しての相対値です。例えば、すべての冷却デバイスが重み1を持つ場合、すべてのデバイスが同じように貢献します。パーセンテージを使用することも可能ですが、必須ではありません。重みが0の場合は、すべての冷却デバイスが重み0を持つ場合を除き、この冷却デバイスがこのゾーンの冷却に貢献しません。すべての重みが0の場合、すべてのデバイスが同じように貢献します。

.trip_mask:

これは、このサーマルゾーンとcdevが特定のトリップポイントでバインドされる関係を示すビットマスクです。nthビットが設定されている場合、cdevとサーマルゾーンはトリップポイントnでバインドされます。

.binding_limits:

これは冷却状態の制限を表す配列です。必ず2 * thermal_zone.number_of_trip_pointsの数を有する必要があります。これは<lower-state upper-state>の状態制限を含むタプルの配列で、バインディング時に各トリップポイントに1つの状態制限タプルが関連付けられます。NULLポインタはすべてのトリップポイントで<THERMAL_NO_LIMITS THERMAL_NO_LIMITS>を表します。これらの制限はcdevをトリップポイントにバインドする際に使用されます。

.match:

このコールバック関数は、プラットフォームデータに従って「tzとcdev」がバインドされるべきかどうかを成功(0)で返します。

struct thermal_zone_params

この構造体はサーマルゾーンのプラットフォームレベルパラメータを定義します。各サーマルゾーンのこのデータはプラットフォームレイヤーから提供されるべきです。これはオプション機能で、一部のプラットフォームはこのデータを提供しないこともできます。

.governor_name:

このゾーンで使用されるサーマルガバネーターの名前

.no_hwmon:

サーマルとhwmon sysfsインターフェースが必要かどうかを示すブール値。no_hwmon == falseの場合はhwmon sysfsインターフェースが作成され、no_hwmon == trueの場合は何も行われません。thermal_zone_paramsがNULLの場合、hwmonインターフェースが作成されます（後方互換性のため）。

.num_tbps:

このゾーンのthermal_bind_paramsエントリ数

.tbp:

thermal_bind_paramsエントリ

2. sysfs属性構造体¶

RO

読み取り専用値

WO

書き込み専用値

RW

読み取り/書き込み値

Thermal sysfs属性は/sys/class/thermal以下に表示されます。hwmon sysfs I/F拡張機能は、hwmonがコンパイル済みまたはモジュールとして構築されている場合、/sys/class/hwmon以下に利用可能です。

Thermal zoneデバイスのsys I/Fは、登録されると同時に作成されます：

/sys/class/thermal/thermal_zone[0-*]:
  |---type:                   Type of the thermal zone
  |---temp:                   Current temperature
  |---mode:                   Working mode of the thermal zone
  |---policy:                 Thermal governor used for this zone
  |---available_policies:     Available thermal governors for this zone
  |---trip_point_[0-*]_temp:  Trip point temperature
  |---trip_point_[0-*]_type:  Trip point type
  |---trip_point_[0-*]_hyst:  Hysteresis value for this trip point
  |---emul_temp:              Emulated temperature set node
  |---sustainable_power:      Sustainable dissipatable power
  |---k_po:                   Proportional term during temperature overshoot
  |---k_pu:                   Proportional term during temperature undershoot
  |---k_i:                    PID's integral term in the power allocator gov
  |---k_d:                    PID's derivative term in the power allocator
  |---integral_cutoff:        Offset above which errors are accumulated
  |---slope:                  Slope constant applied as linear extrapolation
  |---offset:                 Offset constant applied as linear extrapolation

Thermal coolingデバイスのsys I/Fは、登録されると同時に作成されます：

/sys/class/thermal/cooling_device[0-*]:
  |---type:                   Type of the cooling device(processor/fan/...)
  |---max_state:              Maximum cooling state of the cooling device
  |---cur_state:              Current cooling state of the cooling device
  |---stats:                  Directory containing cooling device's statistics
  |---stats/reset:            Writing any value resets the statistics
  |---stats/time_in_state_ms: Time (msec) spent in various cooling states
  |---stats/total_trans:      Total number of times cooling state is changed
  |---stats/trans_table:      Cooing state transition table

次に続く2つの動的属性はペアで作成/削除されます。これらはthermal zoneと関連するcoolingデバイス間の関係を表します。thermal_zone_bind_cooling_device/thermal_zone_unbind_cooling_deviceの各成功実行ごとに作成/削除されます。

/sys/class/thermal/thermal_zone[0-*]:
  |---cdev[0-*]:              [0-*]th cooling device in current thermal zone
  |---cdev[0-*]_trip_point:   Trip point that cdev[0-*] is associated with
  |---cdev[0-*]_weight:       Influence of the cooling device in
                              this thermal zone

Thermal zoneデバイスのsysfs I/Fとcoolingデバイスのsysfs I/Fに加え、汎用thermalドライバーは各thermal zoneデバイスの_type_ごとにhwmon sysfs I/Fを生成します。例えば、汎用thermalドライバーはACPI thermal zoneを登録するごとに1つのhwmonクラスデバイスを登録し、関連するhwmon sysfs I/Fを構築します。

/sys/class/hwmon/hwmon[0-*]:
  |---name:                   The type of the thermal zone devices
  |---temp[1-*]_input:        The current temperature of thermal zone [1-*]
  |---temp[1-*]_critical:     The critical trip point of thermal zone [1-*]

お読みください sysfsファイルの命名規則とデータフォーマット標準 フィールドを参照してください。

Thermal zone属性¶

type

thermal zoneタイプを表す文字列。これはthermal zoneドライバーが登録時に提供します。例: "acpitz"はACPI thermalデバイスを示します。hwmon sys属性と整合性を保つため、短い小文字の文字列で、スペースやハイフンを含まない必要があります。RO、必須

temp

thermal zone（センサー）が報告する現在の温度。単位: ミリデグリーセルシウス RO、必須

mode

[enabled, disabled]のいずれかの予定値。このファイルは現在のthermal zoneを管理しているアルゴリズムの情報を提供します。デフォルトのカーネルベースのアルゴリズムかユーザー空間アプリケーションかを示します。

enabled

カーネルthermal管理を有効化します。

無効化されている場合です。

トリップポイントに対するカーネルthermal zoneドライバーの動作を防ぎ、ユーザーアプリケーションがthermal管理を完全に担当できるようにします。

RW、オプション

policy

特定のゾーン用に使用されるさまざまなthermal governorの一つ。

RW、必須

available_policies

特定のゾーンで使用可能なthermal governorの一覧。

RO、必須

trip_point_[0-*]_temp

トリップポイントが発火する温度以上。

単位: ミリデグリーセルシウス

RO、オプション

trip_point_[0-*]_type

トリップポイントのタイプを示す文字列。

critical、hot、passive、 active[0-*] ACPI thermal zoneの場合。

RO、オプション

trip_point_[0-*]_hyst

トリップポイントのヒステリシス値。整数で表されます。単位: セルシウス RW、オプション

cdev[0-*]

thermal coolingデバイスノードのsysfsリンク。冷却デバイスのスロットリング制御を表すsys I/Fが存在します。

RO、オプション

cdev[0-*]_trip_point

この熱域におけるトリップポイントで、 cdev[0-*] 関連付けられています。-1は冷却デバイスがどのトリップポイントとも関連付けられていないことを意味します。

RO、オプション

cdev[0-*]_weight

この熱域における影響度は cdev[0-*] 他の冷却デバイスと比較して相対的な値です。たとえば、他のデバイスの2倍の重みを持つ冷却デバイスは、熱域の冷却効果が2倍になります。

RW、オプション

passive

この属性は、ネイティブの熱ドライバが被動冷却ポリシーをサポートしない熱域にのみ存在します。デフォルトはゼロで、温度（ミリデグリーアンジル）を設定することで、熱域に被動的なトリップポイントを有効化できます。有効化は1秒間隔でポーリングによって行われます。

単位: ミリデグリーアンジル・セラス

有効な値: 0（無効）または1000より大きい

RW、オプション

emul_temp

熱域（センサー）におけるエミュレート温度の設定インターフェースです。この温度を設定した後、登録されている場合はプラットフォームエミュレーション関数にこの温度を渡すか、ローカルにキャッシュします。これは、異なる温度しきい値とその関連する冷却アクションをデバッグする際に役立ちます。このノードは書き込み専用であり、このノードに0を書き込むとエミュレーションを無効にします。単位: ミリデグリーアンジル・セラス

WO、オプション

警告:

生産用システムでこのオプションを有効にする際は注意が必要です。ユーザー空間は、このsysfsノードに低温度値を大量に書き込むだけで熱制御ポリシーを簡単に無効にできます。

sustainable_power

熱域が持つ持続的な消費電力の推定値で、電力配分ガバナーモードで使用されます。詳細については パワーアロケータ ゴ vernor ツナブル

単位: ミリワット

RW、オプション

k_po

電力配分ガバナーのPID制御における比例項で、温度過剰（現在の温度が「目標温度」トリップポイントを上回る状態）時の制御に使用されます。詳細については パワーアロケータ ゴ vernor ツナブル

RW、オプション

k_pu

電力配分ガバナーのPID制御における比例項で、温度不足（現在の温度が「目標温度」トリップポイントを下回る状態）時の制御に使用されます。詳細については パワーアロケータ ゴ vernor ツナブル

RW、オプション

k_i

電力配分ガバナーのPID制御における積分項で、長期的なドリフトを補償するために使用されます。詳細については パワーアロケータ ゴ vernor ツナブル

RW、オプション

k_d

電力配分ガバナーのPID制御における微分項で、詳細については パワーアロケータ ゴ vernor ツナブル

RW、オプション

integral_cutoff

3. 簡単な実装¶

ACPIの熱帯域（thermal zone）は、critical（危険）、hot（高温）、passive（省エネ）、active（アクティブ）などの複数のトリップポイントをサポートすることがあります。ACPIの熱帯域がcritical、passive、active[0]およびactive[1]を同時にサポートする場合、その熱帯域は4つのトリップポイントを含むthermal_zone_device（thermal_zone1）として登録されます。この熱帯域には1つのプロセッサと1つのファンがあり、これらはどちらもthermal_cooling_deviceとして登録され、熱帯域の冷却効果は同等とみなされます。

プロセッサが_PSLメソッドにリストされ、ファンが_AL0メソッドにリストされている場合、sys I/F構造体は以下のように構築されます：

/sys/class/thermal:
 |thermal_zone1:
   |---type:                   acpitz
   |---temp:                   37000
   |---mode:                   enabled
   |---policy:                 step_wise
   |---available_policies:     step_wise fair_share
   |---trip_point_0_temp:      100000
   |---trip_point_0_type:      critical
   |---trip_point_1_temp:      80000
   |---trip_point_1_type:      passive
   |---trip_point_2_temp:      70000
   |---trip_point_2_type:      active0
   |---trip_point_3_temp:      60000
   |---trip_point_3_type:      active1
   |---cdev0:                  --->/sys/class/thermal/cooling_device0
   |---cdev0_trip_point:       1       /* cdev0 can be used for passive */
   |---cdev0_weight:           1024
   |---cdev1:                  --->/sys/class/thermal/cooling_device3
   |---cdev1_trip_point:       2       /* cdev1 can be used for active[0]*/
   |---cdev1_weight:           1024

 |cooling_device0:
   |---type:                   Processor
   |---max_state:              8
   |---cur_state:              0

 |cooling_device3:
   |---type:                   Fan
   |---max_state:              2
   |---cur_state:              0

/sys/class/hwmon:
 |hwmon0:
   |---name:                   acpitz
   |---temp1_input:            37000
   |---temp1_crit:             100000

4. シンボルエクスポートAPI¶

4.1. get_tz_trend¶

この関数は熱帯域の傾向（温度変化率）を返します。理想的には、熱センサードライバがこのコールバックを実装すべきですが、実装されていない場合、熱フレームワークは前回の温度値と現在の温度値を比較して傾向を計算します。

4.2. get_thermal_instance¶

この関数は、指定された{thermal_zone, cooling_device, trip_point}の組み合わせに対応するthermal_instanceを返します。該当するインスタンスが存在しない場合はNULLを返します。

4.3. thermal_notify_framework¶

この関数はセンサー・ドライバからのトリップイベントを処理します。設定されたポリシーより冷却デバイスの制限を開始します。CRITICALおよびHOTのトリップポイントでは対応するドライバに通知し、ACTIVEおよびPASSIVEのトリップポイントでは実際に制限を行います。制限ポリシーは設定されたプラットフォームデータに基づいており、プラットフォームデータが提供されていない場合はstep_wise制限ポリシーを使用します。

4.4. thermal_cdev_update¶

この関数は冷却デバイスの状態を設定するための仲裁者として機能し、可能な限り冷却デバイスを最も深い冷却状態に設定します。

5. thermal_emergency_poweroff¶

クリティカルなトリップ温度が発生した場合、熱フレームワークはorderly_poweroff()を呼び出してシステムを順序よくシャットダウンします。orderly_poweroff()がシステムのシャットダウンに失敗した場合、システムが不望な高温で動作し続ける危険があります。この高リスクな状況を軽減するため、事前に設定された秒数後にwork queueを起動し、kernel_power_off()関数を使用して緊急シャットダウンを開始します。kernel_power_off()が失敗した場合、最悪の場合emergency_restart()が呼び出されます。

orderly_poweroff()が適切に実行されるよう、遅延時間を慎重に設定する必要があります。orderly_poweroff()が失敗した場合、遅延時間が経過後に緊急シャットダウンが自動的に実行され、システムが停止します。

遅延時間を0に設定すると緊急シャットダウンがサポートされません。したがって、緊急シャットダウンがトリガーされるためには、ゼロ以外の正の値を慎重に設定する必要があります。
