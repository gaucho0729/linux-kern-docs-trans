パワーアロケータ ゴ vernor ツナブル¶

トリップポイント¶

ゲーバーは以下の2つの被動的なトリップポイントと最適に動作します:

  1. 「スイッチオン」トリップポイント: ゲーバー制御ループが動作を開始する温度以上。これは熱域の最初の被動的なトリップポイントです。

  2. 「目標温度」トリップポイント: これはゲーバーが制御する目標温度です。この値は「スイッチオン」トリップポイントよりも高く設定する必要があります。これは熱域の最後の被動的なトリップポイントです。

PID制御器¶

パワーアロケーターゲーバーは温度を制御入力として、電力を制御出力として機能する比例積分微分制御器（PID制御器）を実装しています:

P_max = k_p * e + k_i * err_integral + k_d * diff_err + sustainable_power

オプションを指定する必要があります。形式は以下の通りです：

  • e = desired_temperature - current_temperature

  • err_integralは以前の誤差の合計です

  • diff_err = e - previous_error

これは下記の図に示されているものと似ています:

                                    k_d
                                     |
current_temp                         |
     |                               v
     |              +----------+   +---+
     |       +----->| diff_err |-->| X |------+
     |       |      +----------+   +---+      |
     |       |                                |      tdp        actor
     |       |                      k_i       |       |  get_requested_power()
     |       |                       |        |       |        |     |
     |       |                       |        |       |        |     | ...
     v       |                       v        v       v        v     v
   +---+     |      +-------+      +---+    +---+   +---+   +----------+
   | S |-----+----->| sum e |----->| X |--->| S |-->| S |-->|power     |
   +---+     |      +-------+      +---+    +---+   +---+   |allocation|

持続可能な電力¶

熱域を登録する際には、持続可能な発熱可能な電力（mW）の推定値を提供する必要があります。これは目標温度で持続的に発熱可能な電力の推定値です。これは目標温度での最大持続電力の割当に使用される最大持続電力です。実際の持続電力は環境条件などの要因により変化します。閉ループ制御器はこれらの変動を適切に対処します。 sustainable_power したがって単なる推定値であり、熱上昇の積極性を調整するためにチューニング可能です。参考として、4インチスマートフォンの持続電力は通常2000mW、10インチタブレットでは約4500mW（画面サイズにより異なります）です。

デバイスツリーを使用している場合は、thermal-zoneのプロパティとして追加してください。例えば:

thermal-zones {
        soc_thermal {
                polling-delay = <1000>;
                polling-delay-passive = <100>;
                sustainable-power = <2500>;
                ...

代わりに、熱域がプラットフォームコードから登録される場合は、 thermal_zone_params を渡してください。 sustainable_powerが指定されていない場合、 thermal_zone_params 以前に渡されていた場合は、以下のような処理で十分です:

static const struct thermal_zone_params tz_params = {
        .sustainable_power = 3500,
};

そして、 tz_params を thermal_zone_device_register()

k_po と k_pu¶

パワーアロケーターティーマルゲーバーのPID制御器の実装により、2つの比例項定数の設定が可能です: k_po および k_pu. k_po は温度過剰期間（現在温度が「目標温度」トリップポイントを上回るとき）の比例項定数です。逆に、 k_pu は温度不足期間（現在温度が「目標温度」トリップポイントを下回るとき）の比例項定数です。

これらの制御は、システムの許容される熱的「勾配」を設定するための主なメカニズムとして意図されています。例えば、低い値は、利用可能な容量が低温で上限に設定される代償として、より遅い勾配を提供します。 k_pu 一方で、高い値は、温度が低い間、ガバナが非常に高い出力を許可し、温度の過剰上昇を引き起こす可能性があります。 k_pu switch_on_temp

この値は、温度が k_pu は:

2 * sustainable_power / (desired_temperature - switch_on_temp)

switch_on_temp のとき、制御器の比例項の出力は2 * switch_on_temp sustainable_powerのデフォルト値は k_po は:

sustainable_power / (desired_temperature - switch_on_temp)

PID制御式における比例項およびフィードフォワード値に注目すると以下のようになります：

P_max = k_p * e + sustainable_power

比例項は、目標温度と現在温度の差に比例します。現在温度が目標温度と一致する場合、比例項はゼロとなり、 P_max = sustainable_power. つまり、システムは定常負荷下で熱平衡状態で動作する必要があります。 sustainable_power これは単なる推定値であり、このような閉ループ制御が採用される理由です。

展開 k_pu すると、

P_max = 2 * sustainable_power * (T_set - T) / (T_set - T_on) +
    sustainable_power

where:

  • T_set は目標温度を表します

  • T は現在の温度を表します

  • T_on はスイッチオン温度を表します

現在の温度がスイッチオン温度となった場合、上記の式は以下のようになります：

P_max = 2 * sustainable_power * (T_set - T_on) / (T_set - T_on) +
    sustainable_power = 2 * sustainable_power + sustainable_power =
    3 * sustainable_power

したがって、比例項のみで電力は 3 * から線形に減少します sustainable_power に（木の下から葉に向かって） sustainable_power スイッチオン温度から目標温度まで温度が上昇するとき

k_i および integral_cutoff¶

k_i PIDループの積分項定数を設定します。この項は、PID制御器が長期的なオフセットや出力制御の量子化性を補正するために使用されます: 冷却装置はガバナが要求する正確な電力の設定ができないためです。温度誤差が integral_cutoff以下の場合、エラーが積分項に蓄積されます。この項はその後、 k_i に乗算され、制御器の出力に加算されます。通常、 k_i は低く設定されます（1または2）で、 integral_cutoff は0になります。

k_d¶

k_d はPIDループの導出項定数を設定します。デフォルト値（0）を維持することをお勧めします。

冷却装置電力API¶

このガバナで制御される冷却装置は、その cooling_device_opsに追加の"power" APIを提供する必要があります。これは3つの操作からなります:

  1. int get_requested_power(struct thermal_cooling_device *cdev,
                        struct thermal_zone_device *tz, u32 *power);
@cdev:

以下の struct thermal_cooling_device ポインタ

@tz:

現在動作しているサーマルゾーン

@power:

計算された電力を保存するポインタ

get_requested_power() デバイスがミリワット単位で要求する電力を計算し、@powerに保存します。成功時は0を、失敗時は-E*を返す必要があります。これは現在、電力配分ガバナが各冷却装置に与える電力量を計算するために使用されています。

  1. int state2power(struct thermal_cooling_device *cdev, struct
                thermal_zone_device *tz, unsigned long state,
                u32 *power);
@cdev:

以下の struct thermal_cooling_device ポインタ

@tz:

現在動作しているサーマルゾーン

@state:

冷却デバイスの状態

@power:

同等の電力値を保存するポインタ

@stateの冷却デバイス状態をミリワット単位の電力消費量に変換し、@powerに保存します。成功時は0を、失敗時は-E*を返します。これは現在、サーマルコアがアクターが消費できる最大電力を計算するために使用されています。

  1. int power2state(struct thermal_cooling_device *cdev, u32 power,
                unsigned long *state);
@cdev:

以下の struct thermal_cooling_device ポインタ

@power:

ミリワット単位の電力

@state:

結果の状態を保存するポインタ

デバイスが@power mW以下の電力を消費する状態を計算し、@stateに保存します。成功時は0を、失敗時は-E*を返します。これは現在、サーマルコアがパワーアロケータガバナが設定した電力を状態に変換するために使用されており、この変換は外部要因に依存するため関数として実装されています。外部要因が変化する可能性があるため、現在の状況に応じた最適な変換を実行する必要があります。

冷却デバイスの重み¶

重みは冷却デバイス間の電力配分を偏らせるメカニズムです。これは異なる冷却デバイスの相対的な電力効率を表します。高い電力効率を示すには高い重みを割り当てます。重みは相対的であり、すべての冷却デバイスが重み1を持つ場合、それらは同等とみなされます。これは異質なシステムで、同じ種類の計算を実行するが効率が異なる2つの冷却デバイスがある場合に特に有用です。例えば、2種類のプロセッサを持つシステムです。

サーマルゾーンがプラットフォームコードを使用して登録されている場合、 thermal_zone_device_register() (つまり、プラットフォームコード)、重みはサーマルゾーンの thermal_bind_parametersに含まれて渡されます。プラットフォームがデバイスツリーを使用して登録されている場合、各マップの contribution プロパティとして渡されます。 cooling-maps ノード。

電力アロケータガバナの制限¶

電力アロケータガバナのPID制御器は定期的なティックがある場合に最適に動作します。ドライバがthermal_zone_device_update()を（または最終的にガバナの関数を呼び出す何かを）繰り返し呼び出す場合、ガバナの応答は不十分になります。これはこのガバナに特有ではなく、ステップワイズ制御も同様に、中断などにより通常のサーマルフレームワークティックより早くthrottle()を呼び出すと過剰に反応してしまいます。 thermal_zone_device_update() (または最終的にガバナの throttle() 関数を呼び出す何か)を繰り返し呼び出すと、ガバナの応答が不十分になります。注意してください。これはこのガバナに特有ではなく、ステップワイズ制御も同様に、中断などにより通常のサーマルフレームワークティックより早くthrottle()を呼び出すと過剰に反応してしまいます。
