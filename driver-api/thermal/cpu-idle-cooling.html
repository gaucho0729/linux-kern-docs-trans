CPUアイドル冷却¶

状況:¶

特定の状況においてSoCがクリティカル温度限界に達し、温度制御周辺の温度を安定化できなくなることがあります。SoCが温度を安定化する必要がある場合、カーネルはクーリングデバイスに作用して消費電力を軽減できます。クリティカル温度に達した場合、温度を低下させるための決定が必要となり、その結果、パフォーマンスに影響が出ます。

もう一つの状況は、ダイナミックリークをクロックゲートによって最小限に抑えた後でも、シリコン温度が継続的に上昇し続けることです。このランナウェイ現象は静的リークによって継続されることがあります。解決策は、コンポーネントを電源を切ることで、ダイナミックリークと静的リークを減らし、コンポーネントを冷却できるようにすることです。

最後に挙げるとても重要なのは、システムが特定の電力予算を要求する場合でも、OPP密度の関係で、要求された電力予算より低いOPPを選ばざるを得ず、CPUを過剰に使用せずにパフォーマンスを失うことになります。言い換えれば、1つのOPPでは要求された電力予算より少ない電力でCPUを過剰に使用せず、次のOPPでは電力予算を超えることになります。もし中間のOPPがあれば使用できたでしょう。

解決策:¶

特定の期間において静的リークとダイナミックリークを制御された期間内で除去できる場合、SoCの温度は低下します。アイドル状態の期間やアイドルサイクルのインジェクション期間を調整することで、電力予算を調整して温度を軽減できます。

Operating Performance Point（OPP）密度はcpufreqの制御精度に大きな影響を与えます。しかし、異なるベンダー間ではOPP密度が多様で、一部のベンダーではOPP間の電力ギャップが大きいため、熱制御時のパフォーマンス損失や他のシナリオでの電力損失が生じます。

特定のOPPにおいて、すべてのCPUが同じクラスタに属するものと仮定し、クラスタアイドル状態のターゲットリザーニングよりも長い期間アイドルサイクルをインジェクションすると、その期間に静的リークとダイナミックリークを低下させることができます（この状態に入るためのエネルギーを除く）。したがって、アイドルサイクルによる持続可能な電力はOPPの持続可能な電力と線形関係にあり、以下の係数で計算できます：

Power(IdleCycle) = Coef x Power(OPP)

アイドルインジェクション:¶

アイドルインジェクションの基本的な概念は、制御サイクルごとに指定された時間だけCPUをアイドル状態に強制することです。これはcpufreqに加えてCPUの電力消費と発熱を制御する別の方法を提供します。理想的には、同じクラスタに属するすべてのCPUがアイドルサイクルを同期してインジェクトすれば、クラスタは最小の電力消費で電源オフ状態に達し、静的漏れ電流をほぼゼロに抑えることができます。ただし、これらのアイドルサイクルのインジェクションは、CPUが深睡眠状態から目覚める必要があるため、追加の遅延を生じます。

私たちはパフォーマンスへの影響が受け入れられる範囲内で、固定されたアイドルインジェクションの時間と固定された遅延を採用しています。緩和の強度は、アイドルインジェクションのデューティーサイクルを調整することで増減させることができます。

^
|
|
|-------                         -------
|_______|_______________________|_______|___________

<------>
  idle  <---------------------->
               running

 <----------------------------->
         duty cycle 25%

冷却デバイスの実装はデューティーサイクルのパーセンテージに応じて状態数を決定します。緩和が行われていない場合、冷却デバイスの状態はゼロとなり、デューティーサイクルは0%になります。

緩和が開始されると、ガバナーポリシーに応じて初期状態が選択されます。固定されたアイドル時間とデューティーサイクル（つまり冷却デバイスの状態）を基に、稼働時間は計算できます。

ガバナーは冷却デバイスの状態を変更し、デューティーサイクルを調整します。この変化によって冷却効果が調整されます。

^
|
|
|-------                 -------
|_______|_______________|_______|___________

<------>
  idle  <-------------->
           running

 <--------------------->
     duty cycle 33%


^
|
|
|-------         -------
|_______|_______|_______|___________

<------>
  idle  <------>
         running

 <------------->
  duty cycle 50%

アイドルインジェクションの時間値は以下の制約に合致する必要があります：

  • 緩和が開始される際の許容できる遅延よりも小さく、または等しい必要があります。これはプラットフォーム依存であり、ユーザー体験、反応性とパフォーマンスのトレードオフに依存します。この値は明示的に指定する必要があります。

  • 望む熱対策のアイドル状態の目標滞在時間よりも大きい必要があります。そうでなければ、より多くのエネルギーを消費してしまいます。

電力に関する考慮事項¶

熱トリップポイントに達した場合、特定の温度に対して指定された電力を維持する必要がありますが、この時点で消費する電力は：

Power = Capacitance x Voltage^2 x Frequency x Utilisation

…これは維持可能な電力（またはシステム設定に何か間違いがある）よりも大きいです。『容量』と『利用率』は固定値であり、『電圧』と『周波数』は OPP を変更したくないため、人工的に固定されています。『容量』と『利用率』を単一の項にまとめると『動的電力係数（Cdyn）』となります。上記を簡略化すると：

Pdyn = Cdyn x Voltage^2 x Frequency

電力配分ガバナは、デバイスツリーで定義された持続可能な電力を目標として、私たちに電力を somehow 減らすように求めます。したがって、アイドルインジェクションメカニズムを用いることで、特定のOPPでフル電力で動作する時間とアイドル時間の平均電力（Ptarget）を求めることが目的です。これは以下の式で表されます：

P(opp)target = ((Trunning x (P(opp)running) + (Tidle x P(opp)idle)) /
                       (Trunning + Tidle)

 ...

Tidle = Trunning x ((P(opp)running / P(opp)target) - 1)

この時点でCPUの実行期間を知ることができれば、必要なアイドルインジェクションを算出できます。あるいは、アイドルインジェクションの時間 duration を持っている場合、以下の式で実行期間を計算できます：

Trunning = Tidle / ((P(opp)running / P(opp)target) - 1)

実際には、実行電力が目標電力よりも小さい場合、負の時間値が発生します。したがって、この式は電力削減に限定され、実行電力が目標電力よりも大きいようにするためには、より高いOPPが必要です。

ただし、このデモンストレーションでは以下の3つの要素を無視しています：

  • 静的リークはここでは定義されていません。この値を式に導入することは可能ですが、SoCベンダーから値を取得するのが困難なため、ほとんどの場合ゼロと仮定しています。

  • アイドル状態のウェイクアップラットENCY（エントリーやエクスイットラットENCY）は考慮されていません。厳密なアイドルインジェクション計算を行うためには、この値を式に加える必要があります。

  • インジェクションされたアイドル時間は、アイドル状態のターゲットリジデンシー以上でなければなりません。それ以外の場合、エネルギー消費が増加し、潜在的に緩和効果を逆転させる可能性があります。

したがって、最終的な方程式は次の通りです：

Trunning = (Tidle - Twakeup ) x
               (((P(opp)dyn + P(opp)static ) - P(opp)target) / P(opp)target )
