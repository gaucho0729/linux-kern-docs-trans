USBバルクストリーム¶

背景¶

バーストエンドポイントストリームは、USB 3.0仕様で導入されました。ストリームは、デバイスドライバーがバーストエンドポイントをオーバーロードし、複数の転送を一度にキューイングできるようにします。

ストリームは、Universal Serial Bus 3.0仕様書のセクション4.4.6.4および8.12.1.4に定義されています。 https://www.usb.org/developers/docs/ USB接続SCSIプロトコル（USB Attached SCSI Protocol）は、複数のSCSIコマンドをキューイングするためにストリームを使用します。これはT10ウェブサイト（https://t10.org/).

デバイス側の影響¶

バッファがストリームリングにキューイングされた後、デバイスは（別のエンドポイントでのオフバンドメカニズムを通じて）そのストリームIDのデータが準備完了であることを通知されます。その後、デバイスはホストにどの「ストリーム」を開始したいかを伝えます。ホストはデバイスが要求しなくてもストリームでの転送を開始できますが、デバイスはその転送を拒否する場合があります。デバイスはいつでもストリーム間を切り替えることができます。

ドライバの影響¶

int usb_alloc_streams(struct usb_interface *interface,
              struct usb_host_endpoint **eps, unsigned int num_eps,
              unsigned int num_streams, gfp_t mem_flags);

デバイスドライバーは、ホストコントローラードライバーにメモリを割り当ててもらうためにこのAPIを呼び出します。これにより、ドライバーは最大num_streamsのストリームIDを使用できます。ドライバーは、同様のストリームIDで設定する必要のあるusb_host_endpointsの配列を渡す必要があります。これは、UASPドライバーが双方向コマンドシーケンスで使用されるバーストINおよびOUTエンドポイントに同じストリームIDを使用できるようにするためです。

返却値は、エンドポイントがストリームをサポートしていないか、またはxHCIドライバがメモリ不足となった場合のエラー条件、またはホストコントローラーがこのエンドポイントに割り当てたストリーム数です。xHCIホストコントローラーハードウェアはサポート可能なストリームIDの数を宣言し、SuperSpeedデバイスの各バーストエンドポイントはサポート可能なストリームIDの数を示します。したがって、ドライバーは要求したよりも少ないストリームIDが割り当てられた場合でも対応できる必要があります。

エンドポイントにURBがキューイングされている場合は、この関数を呼び出さないでください。また、2ストリーム未満を要求してこの関数を呼び出すことはできません。

同じエンドポイントに対してこのAPIを呼び出すことは1回だけ許可されます。 usb_free_streams()これはxHCIホストコントローラードライバの簡略化であり、今後変更される可能性があります。

使用する新しいストリームIDの選択¶

ストリームID 0は予約されており、デバイスとの通信には使用しないでください。もし usb_alloc_streams() がNという値を返す場合、ストリーム1からNを使用できます。特定のストリームにURBをキューイングするには、urb->stream_idの値を設定してください。エンドポイントがストリームをサポートしない場合、エラーが返されます。

xHCIドライバが二次ストリームIDをサポートする場合、次のストリームIDを選択するための新しいAPIが追加される必要があります。

クリーンアップ¶

ドライバーがストリームを使用してデバイスと通信を停止したい場合、以下を呼び出す必要があります:

void usb_free_streams(struct usb_interface *interface,
              struct usb_host_endpoint **eps, unsigned int num_eps,
              gfp_t mem_flags);

ドライバーがインターフェースを解放するとき、すべてのストリームIDが解放されます。これにより、ストリームをサポートしないドライバーでもエンドポイントを使用できるようになります。
