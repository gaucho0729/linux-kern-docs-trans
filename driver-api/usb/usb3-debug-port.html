USB3デバッグポート¶

著者

ルーバアロウ <baolu.lu@linux.intel.com>

日付

2017年3月

一般的な¶

これはx86システムにおけるUSB3デバッグポートの使用方法に関するHOWTOです。

USB3デバッグポートに基づくすべてのカーネルデバッグ機能を使用する前に、以下の手順を実施する必要があります：

1) check whether any USB3 debug port is available in
   your system;
2) check which port is used for debugging purposes;
3) have a USB 3.0 super-speed A-to-A debugging cable.

はじめに¶

xHCIホストコントローラーが提供するオプションながら独立した機能であるxHCIデバッグ機能（DbC）について、xHCI仕様書のセクション7.6で説明されています。

DbCが初期化され有効になると、デバッグポート（通常は最初のUSB3スーパースピードポート）を通じてデバッグデバイスが提供されます。このデバッグデバイスはUSBフレームワークと完全に互換性があり、デバッグ対象（デバッグ対象システム）とデバッグホスト間で非常に高性能なフル duplexシリアルリンクを提供します。

EARLY PRINTK¶

DbCは早期のprintkメッセージのログ記録に設計されています。この機能の一つの用途はカーネルデバッグです。たとえば、通常のコンソールコードが初期化される前に機械が非常に早期にクラッシュした場合などです。他の用途には、フルブロウンprintkコンソールドライバーやklogdではなく、よりシンプルでロックフリーなログ記録が含まれます。

デバッグ対象システムでは、CONFIG_EARLY_PRINTK_USB_XDBCを有効にしてデバッグ用カーネルをカスタマイズする必要があります。また、以下のカーネル起動パラメータを追加してください：

"earlyprintk=xdbc"

システムに複数のxHCIコントローラーがある場合、このカーネルパラメータにホストコントローラーインデックスを追加できます。このインデックスは0から始まります。

現在の設計ではDbCのランタイムスリープ/再開をサポートしていません。その結果、以下のカーネル起動パラメータを追加してUSBサブシステムのランタイム電源管理を無効にすることをお勧めします：

"usbcore.autosuspend=-1"

デバッグ対象を開始する前に、デバッグホスト上のUSBポート（ルートポートまたは任意の外部ハブのポート）にデバッグポートを接続する必要があります。これらの2つのポートを接続するケーブルはUSB 3.0スーパースピードのA-to-Aデバッグケーブルを使用する必要があります。

デバッグ対象の早期起動中にDbCが検出され初期化されます。初期化後、デバッグホストはデバッグ対象内のデバッグデバイスを列挙できるようになります。その後、デバッグホストはデバッグデバイスをusb_debugドライバーモジュールと結合し、/dev/ttyUSBデバイスを生成します。

デバッグデバイスの列挙がスムーズに行われた場合、デバッグホストで以下のカーネルメッセージを確認できます：

# tail -f /var/log/kern.log
[ 1815.983374] usb 4-3: new SuperSpeed USB device number 4 using xhci_hcd
[ 1815.999595] usb 4-3: LPM exit latency is zeroed, disabling LPM.
[ 1815.999899] usb 4-3: New USB device found, idVendor=1d6b, idProduct=0004
[ 1815.999902] usb 4-3: New USB device strings: Mfr=1, Product=2, SerialNumber=3
[ 1815.999903] usb 4-3: Product: Remote GDB
[ 1815.999904] usb 4-3: Manufacturer: Linux
[ 1815.999905] usb 4-3: SerialNumber: 0001
[ 1816.000240] usb_debug 4-3:1.0: xhci_dbc converter detected
[ 1816.000360] usb 4-3: xhci_dbc converter now attached to ttyUSB0

minicomなどの通信プログラムを使用してメッセージを読み込み表示できます。以下の簡単なbashスクリプトは、設定の健全性を確認するのに役立ちます。

===== start of bash scripts =============
#!/bin/bash

while true ; do
        while [ ! -d /sys/class/tty/ttyUSB0 ] ; do
                :
        done
cat /dev/ttyUSB0
done
===== end of bash scripts ===============

シリアルTTY¶

DbCのサポートがxHCIドライバに追加されました。ランタイムでDbCが提供するデバッグデバイスを使用できます。

この機能を使用するには、カーネルがUSB_XHCI_DBGCAPをサポートするように設定されていることを確認してください。xHCIデバイスノードのsysfs属性を使用してDbCを有効または無効にします。デフォルトではDbCは無効です:

root@target:/sys/bus/pci/devices/0000:00:14.0# cat dbc
disabled

以下のコマンドでDbCを有効にしてください:

root@target:/sys/bus/pci/devices/0000:00:14.0# echo enable > dbc

いつでもDbCの状態を確認できます:

root@target:/sys/bus/pci/devices/0000:00:14.0# cat dbc
enabled

デバッグターゲットをUSB 3.0 super-speed A-to-Aデバッグケーブルでデバッグホストに接続してください。デバッグターゲット上に/dev/ttyDBC0が作成され、以下のようなカーネルメッセージが表示されます:

root@target: tail -f /var/log/kern.log
[  182.730103] xhci_hcd 0000:00:14.0: DbC connected
[  191.169420] xhci_hcd 0000:00:14.0: DbC configured
[  191.169597] xhci_hcd 0000:00:14.0: DbC now attached to /dev/ttyDBC0

これにより、DbCの状態は以下のようになりました:

root@target:/sys/bus/pci/devices/0000:00:14.0# cat dbc
configured

デバッグホストでは、デバッグデバイスが認識されました。以下のようなカーネルメッセージが表示されます:

root@host: tail -f /var/log/kern.log
[   79.454780] usb 2-2.1: new SuperSpeed USB device number 3 using xhci_hcd
[   79.475003] usb 2-2.1: LPM exit latency is zeroed, disabling LPM.
[   79.475389] usb 2-2.1: New USB device found, idVendor=1d6b, idProduct=0010
[   79.475390] usb 2-2.1: New USB device strings: Mfr=1, Product=2, SerialNumber=3
[   79.475391] usb 2-2.1: Product: Linux USB Debug Target
[   79.475392] usb 2-2.1: Manufacturer: Linux Foundation
[   79.475393] usb 2-2.1: SerialNumber: 0001

デバッグデバイスは現在動作しています。ホストとターゲット間で通信やデバッグを行うための任意のプログラムを使用できます。
