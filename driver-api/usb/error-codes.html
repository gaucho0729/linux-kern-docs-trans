USBエラーコード¶

改訂版

2004年10月21日

これは、usbcoreから返される可能性のあるすべてのエラーコード（およびその解釈）に関するドキュメントです。

一部はホストコントローラードライバー（HCD）によって返されますが、デバイスドライバーはusbcoreを通じてのみ確認できます。原則として、すべてのHCDは転送速度に依存する動作を除き、特定のエラーの報告方法を除いて同じように動作する必要があります。

エラーコードは usb_submit_urb()¶

USBに特有でない:

0

URBの送信は正常に行われました

-ENOMEM

内部構造の割当にメモリが不足しています

USBに特有な:

-EBUSY

URBはすでにアクティブです。

-ENODEV

指定されたUSBデバイスまたはバスは存在しません

-ENOENT

指定されたインターフェースまたはエンドポイントが存在しないか、有効になっていません

-ENXIO

ホストコントローラードライバーがこの種のURBのキュー処理をサポートしていません。（ホストコントローラーのバグとして扱います。）

-EINVAL

  1. 無効な転送タイプが指定されました（またはサポートされていません）

  2. 無効なまたはサポートされていない定期的な転送間隔

  3. ISO: 転送間隔を変更しようとした

  4. ISO: number_of_packets は < 0 です

  5. その他のさまざまなケース

-EXDEV

ISO: URB_ISO_ASAP 指定されておらず、URBがスケジュールされるすべてのフレームがすでに期限切れになっています

-EFBIG

ホストコントローラードライバーがその数のISOフレームをスケジュールできません

-EPIPE

URBに指定されたパイプタイプがエンドポイントの実際のタイプと一致しません

-EMSGSIZE

  1. エンドポイントのmaxpacketサイズがゼロです；現在のインターフェースのアリトセッティングでは使用できません

  2. ISOパケットがエンドポイントのmaxpacketサイズより大きい

  3. 要求されたデータ転送長が無効です：負数またはホストコントローラーでは大きすぎます

-ENOSPC

このリクエストにより、定期的な転送（割込み、イソクロナス）に予約されたUSB帯域幅が過剰に使用されます

-ESHUTDOWN

デバイスまたはホストコントローラーが、問題を回避できないため無効化されました

-EPERM

送信が失敗しました because urb->reject が設定されていない場合、

-EHOSTUNREACH

URBがデバイスがスリープしているため拒否されました

-ENOEXEC

コントロールURBにはセットアップパケットが含まれていません

エラーコードは in urb->status または in iso_frame_desc[n].status (ISOの場合)¶

USBデバイスドライバーは、完了ハンドラでのみURBステータス値をテストできます。これは、HCDが1つのCPUでこれらの値を更新する一方で、デバイスドライバーが別のCPUでそれらをテストする可能性があるためです。

転送の実際長はエラーが報告された場合でも正の値になることがあります。これは、転送が複数のパケットを含むため、1つまたは複数のパケットがエラーが発生する前に終了する可能性があるからです。

イソクロナスURBの場合、URBステータス値がゼロでないのは、URBがアンリーフされた、デバイスが除去された、ホストコントローラーが無効化された、または転送された長さが要求された長さより小さく、 URB_SHORT_NOT_OK フラグが設定されている場合です。イソクロナスURBの完了ハンドラは、 urb->status がゼロに設定されている場合のみ確認できます, -ENOENT, -ECONNRESET, -ESHUTDOWN（sleepable RCU）が導入されました。 -EREMOTEIO個々のフレーム記述子ステータスフィールドは、より多くのステータスコードを報告する場合があります。

0

転送が正常に完了しました

-ENOENT

URBは同期的にアンリーナされました usb_unlink_urb()

-EINPROGRESS

URBがまだ待機中で、結果がまだありません（ドライバーがこのステータスを確認した場合は、バグである可能性があります）

-EPROTO 1, 2

  1. ビットストUFFエラー

  2. 規定されたバスターンアラウンド時間内に応答パケットが受信されませんでした

  3. 不明なUSBエラー

-EILSEQ 1, 2

  1. CRC不一致

  2. 規定されたバスターンアラウンド時間内に応答パケットが受信されませんでした

  3. 不明なUSBエラー

注意：制御器ハードウェアは通常、a)、b)、c)のケースを区別しないため、ドライバーはプロトコルエラー、応答の失敗（デバイス切断が原因となることがよくあります）、または他の障害のいずれかを特定できません。

-ETIME 2

規定されたバスターンアラウンド時間内に応答パケットが受信されませんでした。このエラーは代わりに -EPROTO または -EILSEQ.

-ETIMEDOUT

同期的なUSBメッセージ関数は、転送が完了する前にタイムアウトが発生し、HCから他のエラーが報告されなかったことを示すためにこのコードを使用します。

-EPIPE 2

エンドポイントが停止しました。非制御エンドポイントの場合、このステータスを usb_clear_halt().

-ECOMM

IN転送中に、ホスト制御器がエンドポイントからデータを受信する速度よりもシステムメモリに書き込む速度が遅かったため

-ENOSR

OUT転送中に、ホスト制御器がUSBデータレートに追いつくためにシステムメモリからデータを取得する速度が遅すぎたため

-EOVERFLOW 1

エンドポイントが返したデータ量は、エンドポイントの最大パケットサイズまたは残りバッファサイズのいずれかを上回りました。「バーバー」。

-EREMOTEIO

エンドポイントから読み取ったデータが指定されたバッファを満たしていませんでしたので、 URB_SHORT_NOT_OK が設定されました urb->transfer_flags.

-ENODEV

デバイスが接続解除されました。通常、他のエラーの連続が続きます（ハブドライバーがデバイス接続解除イベントを即座に検出しないからです）。

-EXDEV

ISO転送が部分的に完了しました（のみ設定されます iso_frame_desc[n].status、ではなく urb->status)

-EINVAL

ISOの混乱が発生した場合: ログオフして家に帰ってください

-ECONNRESET

URBは非同期的にアンリーナされました usb_unlink_urb()

-ESHUTDOWN

デバイスまたはホスト制御器が、物理的な切断などの問題により無効化されました。
1(1,2,3)

エラーコードのような -EPROTO, -EILSEQ および -EOVERFLOW は、不良なデバイス（ファームウェアを含む）やケーブルなどのハードウェア問題を示すことが一般的です。

2(1,2,3,4)

これは、ホスト制御器が使用するさまざまな種類のホスト制御器が、デバイス切断により転送が失敗したことを示すためのいくつかのコードの一つです。ハブドライバーが切断処理を開始する間、デバイスは各リクエストに対してこのような障害レポートを受信する可能性があります。
