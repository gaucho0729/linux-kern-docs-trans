USB Type-C アルタナティブモードドライバー用API¶

はじめに¶

Alternate modeは、USB Type-CおよびUSB Power Delivery仕様で定義されたVendor Defined Messages (VDM)を用いてパートナーと通信します。この通信はSVID（StandardまたはVendor ID）固有であり、つまり各Alternate modeごとに固有であるため、すべてのAlternate modeにはカスタムドライバが必要です。

USB Type-Cバスは、SVIDおよびモード番号を用いてドライバを発見されたパートナーのAlternate modeにバインドできます。

USB Type-C Connector Class ポートがサポートするすべてのAlternate modeに対してデバイスを提供し、パートナーがサポートするすべてのAlternate modeに対して個別のデバイスを提供します。Alternate modeのドライバはパートナーのAlternate modeデバイスにバインドされ、ポートのAlternate modeデバイスはポートドライバによって処理される必要があります。

新しいパートナーAlternate modeデバイスが登録されると、そのデバイスは、パートナーが接続されているポートのAlternate modeデバイスにリンクされ、SVIDおよびモードが一致するものになります。ポートドライバとAlternate modeドライバ間の通信は同じAPIを用いて行われます。

ポートAlternate modeデバイスはパートナーとAlternate modeドライバの間のプロキシとして機能するため、ポートドライバはAlternate modeドライバからSVID固有のコマンドをパートナーに転送し、パートナーからAlternate modeドライバに転送するだけでよいです。ポートドライバはSVID固有の通信を直接行う必要はなく、ポートAlternate modeデバイスに対して操作コールバックを提供する必要があります。Alternate modeドライバも同様にパートナーAlternate modeデバイスに対してコールバックを提供する必要があります。

使用方法:¶

一般¶

デフォルトではAlternate modeドライバがモードへの移行を担当します。また、モードへの移行の決定をユーザー空間に委譲することも可能です（Documentation/ABI/testing/sysfs-class-typecを参照）。ポートドライバは独自にどのモードも開始すべきではありません。

->vdm 操作コールバックベクターの中で最も重要なコールバックです。これはパートナーからAlternate modeドライバへ、およびポートドライバの場合は逆にAlternate modeドライバからパートナーへSVID固有のコマンドを届けるために使用されます。ドライバ間でのSVID固有のコマンドの送信は typec_altmode_vdm().

パートナーとのSVID固有コマンドによる通信でピンの再構成が必要な場合、Alternate modeドライバはバスに通知する必要があります typec_altmode_notify()ドライバーは、交渉されたSVID固有のピン構成値を関数にパラメータとして渡します。バスドライバーはその後、その値をMUXの状態値として使用してコネクタのMUXを設定します。

注意: SVID固有のピン構成値は常に TYPEC_STATE_MODALUSB Type-C仕様ではコネクタに2つのデフォルト状態を定義しています: TYPEC_STATE_USB および TYPEC_STATE_SAFEこれらの値はバスが状態の最初の可能性として予約しています。代替モードが起動する際、バスはコネクタを TYPEC_STATE_SAFE EnterまたはExit ModeコマンドをUSB Type-C仕様で送信する前に、またモードが終了した後もコネクタを TYPEC_STATE_USB に戻します。

SVID固有のピン構成値の作業定義の例は以下のようになります:

enum {
    ALTMODEX_CONF_A = TYPEC_STATE_MODAL,
    ALTMODEX_CONF_B,
    ...
};

補助マクロ TYPEC_MODAL_STATE() を使用することもできます:

#define ALTMODEX_CONF_A = TYPEC_MODAL_STATE(0);
#define ALTMODEX_CONF_B = TYPEC_MODAL_STATE(1);

ケーブルプラグ代替モード¶

代替モードドライバーはケーブルプラグの代替モードデバイスとは関係ありません。パートナーの代替モードデバイスにのみ関係します。代替モードがサポートする、または必要とする場合、ケーブルがSOP Primeメッセージに応答し、オプションでSOP Double Primeメッセージにも応答する場合、その代替モードのドライバーはケーブルプラグの代替モードにハンドルを要求して typec_altmode_get_plug()を使用し、その制御を引き継ぐ必要があります。

struct typec_altmode_ops¶

代替モード固有の操作ベクター

定義

struct typec_altmode_ops {
  int (*enter)(struct typec_altmode *altmode, u32 *vdo);
  int (*exit)(struct typec_altmode *altmode);
  void (*attention)(struct typec_altmode *altmode, u32 vdo);
  int (*vdm)(struct typec_altmode *altmode, const u32 hdr, const u32 *vdo, int cnt);
  int (*notify)(struct typec_altmode *altmode, unsigned long conf, void *data);
  int (*activate)(struct typec_altmode *altmode, int activate);
  ANDROID_KABI_RESERVE(1);
};

enter

Enter Modeコマンドで実行する操作

exit

Exit Modeコマンドで実行する操作

attention

Attentionコマンドのコールバック

vdm

SVID固有のコマンドのコールバック

notify

プラットフォームと代替モード間の通信チャネル

activate

Enter/Exit Mode用のユーザー コールバック

この関数の主な目的は、代替モードドライバーがパートナーと交渉したピン構成を伝えることです。この情報はMUXの設定などに使用されます。逆方向への通信も可能です、低レベルのデバイスドライバーは代替モードドライバーに通知を送信することもできます。実際の通信はすべてのSVIDごとに異なります。
