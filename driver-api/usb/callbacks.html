USBコアコールバック¶

usbcoreが実行するコールバックは何か？¶

ドライバの構造体で定義されたコールバックと、ドライバが送信するURBの完了ハンドラを通じて、usbcoreはドライバに呼び出されます。前者のみがこのドキュメントの範囲内です。これら2種類のコールバックは完全に独立しています。完了コールバックに関する情報は以下に記載されています。 USBリクエストブロック (URB).

ドライバの構造体で定義されたコールバックは以下の通りです。

  1. ホットプラグコールバック:

  • @probe:

    ドライバがデバイスの特定のインターフェースを管理することを希望しているかどうかを確認するために呼び出されます。

  • @disconnect:

    インターフェースがアクセスできなくなった場合、通常はそのデバイスが切断された（または切断中）か、ドライバモジュールがアンロードされているときに呼び出されます。

  1. usbfsを通じた特殊なバックドア:

  • @ioctl:

    ユーザー空間とusbfsファイルシステムを通じて通信したいドライバに使用されます。これにより、デバイスはファイルシステム内の他の場所に表示されなくても、ユーザー空間に情報を公開する方法を提供できます。

  1. 電源管理（PM）コールバック:

  • @suspend:

    デバイスがサスペンドされるときに呼び出されます。

  • @resume:

    デバイスが再開されるときに呼び出されます。

  • @reset_resume:

    サスペンドされたデバイスが再起動された代わりにリセットされたときに呼び出されます。

  1. デバイスレベルの操作:

  • @pre_reset:

    デバイスがリセットされる直前に呼び出されます。

  • @post_reset:

    デバイスがリセットされた後に呼び出されます。

IOCTLインターフェース（2）は非常に良い理由がある場合にのみ使用すべきです。現在はSysfsが推奨されています。PMコールバックについては別途説明しています。 USBの電源管理.

コールバックの呼び出し規約¶

すべてのコールバックは相互に排他的です。他のUSBコールバックとのロックは必要ありません。すべてのコールバックはタスクコンテキストから呼び出されます。スリープは可能です。ただし、すべてのスリープは時間の小さな固定上限を保つ必要があります。特に、ユーザー空間に呼び出しを行い結果を待つことはできません。

ホットプラグコールバック¶

これらのコールバックは、ドライバとインターフェースを関連付けたり、解除したりするためのものです。ドライバのインターフェースへの結合は排他的です。

probe()コールバック¶

int (*probe) (struct usb_interface *intf,
              const struct usb_device_id *id);

インターフェースの受け入れまたは拒否を行います。デバイスを受け入れる場合は0を返し、そうでない場合は-ENODEVまたは-ENXIOを返してください。初期化中に本物のエラーが発生し、ドライバがインターフェースを受け入れることができなくなった場合のみ、他のエラーコードを使用してください。usbcoreの機能であるusb_set_intfdata()を活用してインターフェースにデータ構造を関連付けることを強く推奨します。これにより、特定のインターフェースと関連付ける内部状態や識別情報を明確にできます。デバイスはスリープ状態にされず、呼び出されたインターフェースおよびデバイスのエンドポイント0へのIO操作が可能です。初期化が長時間かからない場合は、ここでデバイスの初期化を行うのが良いです。

disconnect()コールバック¶

void (*disconnect) (struct usb_interface *intf);

このコールバックはインターフェースとの接続を切断する信号です。このコールバックから戻った後は、デバイスへのIO操作を一切行うことはできません。また、他のドライバがインターフェースにバインドされている場合に干渉する操作（例: パワー管理操作など）を行うこともできません。物理的な切断により呼び出された場合は、usbcoreがすべてのURBを終了します。注意点として、この場合disconnectは物理的な切断後ある程度時間が経ってから呼び出されるため、ドライバはコールバック前にもIOが失敗する可能性に備える必要があります。

デバイスレベルのコールバック¶

pre_reset¶

int (*pre_reset)(struct usb_interface *intf);

ドライバまたはユーザー空間が引数として渡されたインターフェースを含むデバイスのリセットをトリガーしています。IO操作を停止し、すべての待機中のURBが完了するのを待って、復元するために必要なデバイスの状態を保存してください。post_resetメソッドが呼ばれるまで、新たなURBの送信は行えません。

ここでメモリを割り当てる場合は、アトミックコンテキストである場合はGFP_ATOMICを使用してください。

post_reset¶

int (*post_reset)(struct usb_interface *intf);

リセットが完了しました。保存したデバイスの状態を復元し、デバイスの使用を再開してください。

ここでメモリを割り当てる場合は、アトミックコンテキストである場合はGFP_ATOMICを使用してください。

コールシーケンス¶

ドライバにバインドされていないインターフェースについては、probe以外のコールバックは呼び出されません。

インターフェースがドライバにバインドされている場合、probeは呼び出されません。したがって、probeが成功した後、同じインターフェースに対する再度のprobeが行われる前にdisconnectが呼び出されます。

ドライバがインターフェースにバインドされた後、pre_resetとpost_resetの間を除いてdisconnectがいつでも呼び出せます。pre_resetは常にpost_resetに続いて呼び出されます。リセットが失敗した場合やデバイスが抜き込まれた場合でも、この順序は変わりません。

suspendは常にresume、reset_resume、またはdisconnectのいずれかで続きます。
