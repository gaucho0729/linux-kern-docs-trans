基本的な概念または「URBとは何か？」¶

新しいドライバの基本的な考え方はメッセージ送信です。このメッセージ自体はUSBリクエストブロック（URB）と呼ばれます。

  • URBは、USBトランザクションを実行し、データや状態を戻すために必要なすべての関連情報を含みます。

  • URBの実行は本質的に非同期操作であり、つまり、 usb_submit_urb() 呼び出しは、要求されたアクションを成功裏にキューイングした後すぐに返されます。

  • 1つのURBのトランスファーは、 usb_unlink_urb() いつでもキャンセル可能です。

  • 各URBには完了ハンドラがあり、アクションが成功裏に完了またはキャンセルされた後に呼び出されます。URBはまた、完了ハンドラに情報を渡すためのコンテキストポインタも含みます。

  • デバイスの各エンドポイントは論理的にリクエストのキューをサポートしており、そのキューを埋めることで、ドライバが他の完了処理を処理している間でも、USBハードウェアがエンドポイントにデータを転送し続けることができます。これによりUSB帯域幅の使用効率が最大化され、周期的なトランスファーモードを使用する際のデータのシームレスなストリーミングをサポートします。

URB構造体¶

いくつかのフィールドは struct urb は:

struct urb
{
// (IN) device and pipe specify the endpoint queue
      struct usb_device *dev;         // pointer to associated USB device
      unsigned int pipe;              // endpoint information

      unsigned int transfer_flags;    // URB_ISO_ASAP, URB_SHORT_NOT_OK, etc.

// (IN) all urbs need completion routines
      void *context;                  // context for completion routine
      usb_complete_t complete;        // pointer to completion routine

// (OUT) status after each completion
      int status;                     // returned status

// (IN) buffer used for data transfers
      void *transfer_buffer;          // associated data buffer
      u32 transfer_buffer_length;     // data buffer length
      int number_of_packets;          // size of iso_frame_desc

// (OUT) sometimes only part of CTRL/BULK/INTR transfer_buffer is used
      u32 actual_length;              // actual data buffer length

// (IN) setup stage for CTRL (pass a struct usb_ctrlrequest)
      unsigned char *setup_packet;    // setup packet (control only)

// Only for PERIODIC transfers (ISO, INTERRUPT)
  // (IN/OUT) start_frame is set unless URB_ISO_ASAP isn't set
      int start_frame;                // start frame
      int interval;                   // polling interval

  // ISO only: packets are only "best effort"; each can have errors
      int error_count;                // number of errors
      struct usb_iso_packet_descriptor iso_frame_desc[0];
};

ドライバは、claimしたインターフェースの適切なエンドポイント記述子から値を使用して「パイプ」値を生成する必要があります。

URBを取得する方法¶

URBは、 usb_alloc_urb():

struct urb *usb_alloc_urb(int isoframes, int mem_flags)

を呼び出すことで割り当てられます。返値は割り当てられたURBへのポインタで、割り当てに失敗した場合は0です。isoframesパラメータはスケジュールするイソクロナストランスファーフレーム数を指定します。CTRL/BULK/INTの場合、0を使用してください。mem_flagsパラメータは標準のメモリ割り当てフラグを保持し、コードがブロックするかどうかなどの制御が可能です。

URBを解放するには、 usb_free_urb():

void usb_free_urb(struct urb *urb)

サブミットしたがまだ完了コールバックで返されていないURBを解放することも可能です。使用が終わると自動的に解放されます。

記入が必要な項目は？¶

トランザクションの種類によっては、 linux/usb.h でインライン関数が定義されており、初期化を簡略化します。例えば、 usb_fill_control_urb(), usb_fill_bulk_urb() および usb_fill_int_urb()。一般的には、USBデバイスポインタ、パイプ（通常はusb.hから取得）、トランスファーバッファ、希望するトランスファー長、完了ハンドラ、およびそのコンテキストが必要です。既存のドライバを確認してその使い方をご確認ください。

フラグ:

  • ISOでは2つの起動動作があります：指定されたstart_frameかASAPです。

  • ASAPを設定するには URB_ISO_ASAP transfer_flagsに設定します。

短いパケットを許容しない場合、設定してください URB_SHORT_NOT_OK transfer_flagsに設定します。

URBを送信する方法は？¶

単に呼び出すだけで usb_submit_urb():

int usb_submit_urb(struct urb *urb, int mem_flags)

以下の mem_flags パラメータ、例えば GFP_ATOMIC、メモリの割り当てを制御し、メモリが不足しているときに下位レベルがブロックするかどうかを指定します。

すぐに返します。ステータス0（要求がキューに追加されました）か、いくつかのエラーコードのいずれかで、通常は以下の原因によって発生します：

  • メモリ不足（-ENOMEM)

  • 接続されていないデバイス（-ENODEV)

  • 停止したエンドポイント（-EPIPE)

  • キューに待機中のISO転送が多すぎる（-EAGAIN)

  • リクエストされたISOフレームが多すぎる（-EFBIG)

  • 無効なINTインターバル（-EINVAL)

  • INTに複数のパケット（-EINVAL)

送信後、 urb->status 通常のRCU読み込み側クリティカルセクションは、条件付きでスリープロックを取得することが許容されます（例として -EINPROGRESS；ただし、完成コールバック以外ではその値を確認しないでください。

イソクロナスエンドポイントでは、あなたの完成ハンドラは（再）URBを同じエンドポイントにmulti-bufferingを使用して送信し、 URB_ISO_ASAP フラグを指定して、連続的なISOストリーミングを得るために必須です。

すでに実行中のURBをキャンセルする方法は？¶

すでに送信したがまだドライバに返されていないURBをキャンセルするには2つの方法があります。非同期キャンセルの場合は、 usb_unlink_urb():

int usb_unlink_urb(struct urb *urb)

を呼び出します。これにより、URBは内部リストから削除され、すべての割り当てられたハードウェアディスクリプタが解放されます。ステータスはアンリンクを反映します。注意点として、 usb_unlink_urb() が返るまでURBは通常完了していませんので、完成ハンドラが呼び出されるのを待つ必要があります。

URBを同期してキャンセルするには、 usb_kill_urb():

void usb_kill_urb(struct urb *urb)

を呼び出します。これにより、 usb_unlink_urb() が行うすべての処理を行い、さらにURBが返され、完成ハンドラが終了した後まで待機します。また、URBを一時的に使用不可にマークするため、完成ハンドラや誰かがURBを再送信しようとすると、 -EPERM エラーが発生します。したがって、 usb_kill_urb() が返るとき、URBは完全にアイドル状態になっています。

ライフタイムの問題があります。URBはいつでも完了する可能性があり、完成ハンドラがURBを解放する場合があります。このとき usb_unlink_urb() または usb_kill_urb() が実行中であれば、メモリアクセス違反が発生します。ドライバはこれを避ける責任があり、通常はロックが必要で、URBがまだ使用中である間、解放されないようにします。

一方で、usb_unlink_urbが完成ハンドラを呼び出す可能性があるため、ハンドラはusb_unlink_urbが呼び出されているときにロックを取得してはいけません。この問題の一般的な解決策は、ロックを保持しながらURBの参照カウントをインクリメントし、その後ロックを解放してusb_unlink_urbまたはusb_kill_urbを呼び出し、最後に参照カウントをデクリメントすることです。参照カウントをインクリメントするには:c:func`usb_get_urb`を呼び出します：

struct urb *usb_get_urb(struct urb *urb)

（返却値は引数と同じなので無視してください）参照カウントを減らすために呼び出してください usb_free_urb()URBがコンプリーションハンドラによって解放される危険がない場合、これらは必要ありません

コンプリーションハンドラについてどうですか？¶

ハンドラは以下の型です

typedef void (*usb_complete_t)(struct urb *)

つまり、コンプリーション呼び出しを引き起こしたURBを取得します。コンプリーションハンドラでは、 urb->status USBエラーを検出するために確認してください。コンテキストパラメータがURBに含まれているため、コンプリーションハンドラに情報を渡すことができます

注意してください。エラー（またはアンリーナー）が報告されても、データが転送された可能性があります。これはUSB転送がパケット化されているためで、1KByteのバッファを転送するのに16パケットが必要で、そのうち10パケットが成功した可能性があるからです

警告

コンプリーションハンドラ内でスリープしないでください

これらは通常、アトミックコンテキストで呼び出されます

現在のカーネルではコンプリーションハンドラがローカル割込みを無効にして実行されますが、今後この仕様が変更されるため、コンプリーションハンドラ内でローカルIRQが常に無効であると仮定しないでください

イソクロナス（ISO）転送はどのように行いますか？¶

バーチャル転送とは異なり、ISOでは以下のフィールドを設定する必要があります urb->interval 送金の頻度を指定する必要があります。通常は1フレームごとに送金します（高速デバイスでは1マイクロフレームごとに送金します）。実際に使用される間隔は、指定した値以下の2の累乗になります。You can use the usb_fill_int_urb() マクロでほとんどのISO送信フィールドを埋めることができます。

ISO送信では、さらに usb_iso_packet_descriptor 構造体を、URBの末尾で usb_alloc_urb()が、各送信パケットごとに割り当てられます。

以下の usb_submit_urb() コールは、実装された間隔値を、指定された間隔値以下の値に変更します。If urb->interval スケジューリングが使用される場合、 URB_ISO_ASAP も更新されます。 urb->start_frame 各エントリに対して、このフレームのデータオフセット（ベースはtransfer_buffer）と、書き込む/読み込む予定の長さを指定する必要があります。完了後、actual_lengthには実際に送信された長さが、statusにはこのフレームのISO送信結果ステータスが格納されます。フレームごとに変化する長さを指定することも可能です（例：オーディオ同期/適応送信速度）。また、長さ0を指定することで1つ以上のフレームを省略（ストリピング）することもできます。

スケジューリングでは、自分の希望する開始フレームまたは

を選択できます。前述した通り、常に少なくとも1つのURBをキューに保持し、完了後に後続のURBを再送信（re-submit）し続けると、USB帯域幅の利用状況が許す限り、スムーズなISOストリーミングが得られます。 URB_ISO_ASAPAs explained earlier, if you always keep at least one URB queued and your completion keeps (re)submitting a later URB, you’ll get smooth ISO streaming (if usb bandwidth utilization allows).

自分の開始フレームを指定する場合、現在のフレームより複数のフレーム前を設定してください。ISOデータを他のイベントストリームと同期する場合、このモデルが役立つかもしれません。

割込み（INT）転送の開始方法は？¶

割込み転送は、イソクロナス転送と同様に周期的であり、2の累乗（1、2、4など）の単位で発生します。単位はフルスピードおよびローローテーションデバイスではフレーム、ハイスピードデバイスではマイクロフレームです。以下にマクロを使用してINT転送フィールドを埋めることができます。 usb_fill_int_urb() マクロを使用してINT転送フィールドを埋めます。

以下の usb_submit_urb() コールは、実装された間隔値を、指定された間隔値以下の値に変更します。If urb->interval リクエストされたインターバル値以下の実装されたインターバル値に設定します。

Linux 2.6では、以前のバージョンとは異なり、割込みURBが完了時に自動的に再開されません。完了ハンドラが呼ばれるときに終了します。他のURBと同様です。割込みURBを再開したい場合は、完了ハンドラで明示的に再送信する必要があります。
