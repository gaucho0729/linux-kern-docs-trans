DMAテストガイド¶

Andy Shevchenko <andriy.shevchenko@linux.intel.com>

この小さなドキュメントは、dmatestモジュールを使用してDMAドライバをテストする方法を紹介しています。

注意

テストスイートは、DMA_MEMCPY（メモリ間）、DMA_MEMSET（定数からメモリまたはメモリ間、エミュレート時）、DMA_XOR、DMA_PQの少なくとも1つの機能を持つチャンネルでのみ動作します。

注意

関連する質問がある場合は、公式メールリストを使用してください dmaengine@vger.kernel.org.

パート1 - テストモジュールのビルド方法¶

メニュー構成には、以下のパスで見つけることができるオプションがあります：

デバイスドライバ -> DMAエンジンサポート -> DMAテストクライアント

構成ファイルでは、CONFIG_DMATEST というオプションが存在します。dmatestはモジュールとしてビルドするかカーネル内に組み込むことができます。以下ではそのケースを検討します。

パート2 - dmatestがモジュールとしてビルドされている場合¶

使用例：

% modprobe dmatest timeout=2000 iterations=1 channel=dma0chan0 run=1

…または：

% modprobe dmatest
% echo 2000 > /sys/module/dmatest/parameters/timeout
% echo 1 > /sys/module/dmatest/parameters/iterations
% echo dma0chan0 > /sys/module/dmatest/parameters/channel
% echo 1 > /sys/module/dmatest/parameters/run

…またはカーネルコマンドラインで：

dmatest.timeout=2000 dmatest.iterations=1 dmatest.channel=dma0chan0 dmatest.run=1

マルチチャンネルテストの使用例（5.0カーネルで導入）：

% modprobe dmatest
% echo 2000 > /sys/module/dmatest/parameters/timeout
% echo 1 > /sys/module/dmatest/parameters/iterations
% echo dma0chan0 > /sys/module/dmatest/parameters/channel
% echo dma0chan1 > /sys/module/dmatest/parameters/channel
% echo dma0chan2 > /sys/module/dmatest/parameters/channel
% echo 1 > /sys/module/dmatest/parameters/run

注意

5.0カーネル以降、単一チャンネルまたはマルチチャンネルのいずれの場合も、チャンネルパラメータ（複数ある場合はすべて）を他のすべてのパラメータの後に設定する必要があります。そのタイミングで、スレッドに使用される既存のパラメータ値が取得されます。他のすべてのパラメータは共有されます。したがって、他のパラメータを変更した後で追加のチャンネルを指定した場合、すべてのスレッドに使用される（共有）パラメータは新しい値を使用します。チャンネルが指定された後、各スレッドは待機状態になります。すべてのスレッドは「run」パラメータが1に設定されたときに実行を開始します。

ヒント

利用可能なチャンネルの一覧は、次のコマンドを実行することで確認できます：

% ls -1 /sys/class/dma/

開始後、"dmatest: dma0chan0を使用して1スレッドを追加しました"というメッセージが表示されます。その特定のチャンネル用のスレッドが作成され、待機状態になります。待機中のスレッドは「run」が1に設定されたときに実行されます。

新しいテストを実行しても、進行中のテストは停止しません。

以下のコマンドでテストの状態を確認できます。

% cat /sys/module/dmatest/parameters/run

テスト完了を待つには、ユーザー空間で「run」をfalseになるまでポーリングするか、「wait」パラメータを使用してください。モジュールロード時に「wait=1」を指定すると、モジュール初期化がテスト実行完了まで待機します。/sys/module/dmatest/parameters/wait を読み込むと、実行中のテストが完了するのを待ってから戻ります。たとえば、以下のスクリプトは42テストが完了するのを待ってから終了します。注意点として、「iterations」が「infinite」に設定されている場合、待機は無効になります。

例:

% modprobe dmatest run=1 iterations=42 wait=1
% modprobe -r dmatest

…または：

% modprobe dmatest run=1 iterations=42
% cat /sys/module/dmatest/parameters/wait
% modprobe -r dmatest

パート3 - カーネル内に組み込まれた場合¶

カーネルコマンドラインに供給されるモジュールパラメータは、最初に実行されるテストに使用されます。ユーザーが制御を取得した後、同じまたは異なるパラメータでテストを再実行できます。詳細については、上記のセクションを参照してください。 パート2 - dmatestがモジュールとしてビルドされている場合.

どちらの場合も、モジュールパラメータはテストケースの実際の値として使用されます。いつでも実行時において、以下のコマンドを実行することで確認できます。

% grep -H . /sys/module/dmatest/parameters/*

パート4 - テスト結果の収集¶

テスト結果は、カーネルログバッファに以下のような形式で出力されます:

"dmatest: result <channel>: <test id>: '<error msg>' with src_off=<val> dst_off=<val> len=<val> (<err code>)"

出力例:

% dmesg | tail -n 1
dmatest: result dma0chan0-copy0: #1: No errors with src_off=0x7bf dst_off=0x8ad len=0x3fea (0)

メッセージ形式は、さまざまなエラー種別の間で統一されています。括弧内の数字は追加情報（例: エラーコード、エラーカウンタ、ステータスなど）を表します。テストスレッドは、完了時に実行したテスト数、失敗したテスト数、結果コードを示すサマリーラインを出力します。

例:

% dmesg | tail -n 1
dmatest: dma0chan0-copy0: summary 1 test, 0 failures 1000 iops 100000 KB/s (0)

データミスマッチエラーの詳細情報も出力されますが、上記の形式には従いません。

パート5 - チャネル割当の処理¶

チャネルの割当¶

チャネルはテスト実行開始前に設定する必要はありません。チャネルを設定せずにテストを実行すると、利用可能なすべてのチャネルがテスト対象になります。

例:

% echo 1 > /sys/module/dmatest/parameters/run
dmatest: No channels configured, continue with any

チャネルは「channel」パラメータを使用して登録されます。チャネル名で要求すると、チャネルが登録され、テストリストに待機中のスレッドが追加されます。

例:

% echo dma0chan2 > /sys/module/dmatest/parameters/channel
dmatest: Added 1 threads using dma0chan2

上記の例を繰り返すことで、さらに多くのチャネルを追加できます。チャネルパラメータを読み込むと、最後に成功して追加されたチャネル名が返されます。

例:

% echo dma0chan1 > /sys/module/dmatest/parameters/channel
dmatest: Added 1 threads using dma0chan1
% echo dma0chan2 > /sys/module/dmatest/parameters/channel
dmatest: Added 1 threads using dma0chan2
% cat /sys/module/dmatest/parameters/channel
dma0chan2

チャネルを要求するもう一つの方法は、空文字列でチャネルを要求することです。これにより、テスト可能なすべてのチャネルを要求できます:

例:

% echo "" > /sys/module/dmatest/parameters/channel
dmatest: Added 1 threads using dma0chan0
dmatest: Added 1 threads using dma0chan3
dmatest: Added 1 threads using dma0chan4
dmatest: Added 1 threads using dma0chan5
dmatest: Added 1 threads using dma0chan6
dmatest: Added 1 threads using dma0chan7
dmatest: Added 1 threads using dma0chan8

テスト設定のどの時点ででも、「test_list」パラメータを読み込むと、現在待機中のテストの一覧が表示されます。

例:

% cat /sys/module/dmatest/parameters/test_list
dmatest: 1 threads using dma0chan0
dmatest: 1 threads using dma0chan3
dmatest: 1 threads using dma0chan4
dmatest: 1 threads using dma0chan5
dmatest: 1 threads using dma0chan6
dmatest: 1 threads using dma0chan7
dmatest: 1 threads using dma0chan8

注意: チャネル設定は各テスト実行ごとに再度行う必要があります。チャネル設定は次のテスト実行に引き継がれません。

チャネルの解放¶

チャネルを解放するには、runを0に設定します。

例:

% echo dma0chan1 > /sys/module/dmatest/parameters/channel
dmatest: Added 1 threads using dma0chan1
% cat /sys/class/dma/dma0chan1/in_use
1
% echo 0 > /sys/module/dmatest/parameters/run
% cat /sys/class/dma/dma0chan1/in_use
0

以前のテスト実行で割当されたチャネルは、成功したテスト実行後に新しいチャネルが要求されるたびに自動的に解放されます。
