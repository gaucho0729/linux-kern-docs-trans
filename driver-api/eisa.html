EISAバスサポート¶

著者

Marc Zyngier <maz@wild-wind.fr.eu.org>

このドキュメントは、EISAドライバを新しいEISA/sysfs APIに移植する際のランダムなノートを集めたものです。

バージョン2.5.59から、EISAバスはPCIやUSBなどより主流なバスとほぼ同等の地位を与えられています。これはsysfsを通じて、バス、デバイス、ドライバを管理するための十分な抽象化が可能になったためです。

新しいAPIは使いやすくはありますが、既存のドライバを新しいインフラストラクチャに移植するのは簡単ではありません（主に検出コードがISAカードのプローブにも使用されるため）。さらに、ほとんどのEISAドライバはLinuxで最も古いドライバの一つなので、想像する通り、ここ数年でいくつかの古びたコードが蓄積しています。

EISAインフラストラクチャは3つの部分から構成されています：

  • バスコードは一般的なコードの大部分を実装しており、EISAコードが動作するすべてのアーキテクチャで共有されます。バスプローブ（バス上のEISAカードの検出）、I/Oリソースの割当、sysfsを通じた複雑なネーミング、ドライバが登録できるインターフェースを提供します。

  • バスルートドライバはバスハードウェアと一般的なバスコードの間の接着剤を実装します。バスを実装するデバイスの検出と、その後のバスコードによるプローブに必要な設定を行います。これはx86でのI/O領域の確保のような単純なものから、hppaのEISAコードのような複雑な処理まで幅広いです。これは「新しい」プラットフォームでEISAを動作させるために実装すべき部分です。

  • ドライバはバスに管理するデバイスの一覧を提供し、デバイスが指示されたときにプローブや解放を行う必要があるコールバックを実装します。

以下に示すすべての関数／構造体は<linux/eisa.h>に存在し、これには<linux/device.h>に強く依存しています。

バスルートドライバ¶

int eisa_root_register (struct eisa_root_device *root);

eisa_root_register関数は、デバイスをEISAバスのルートとして宣言するために使用されます。eisa_root_device構造体はこのデバイスへの参照と、プローブのためのいくつかのパラメータを保持しています：

struct eisa_root_device {
        struct device   *dev;    /* Pointer to bridge device */
        struct resource *res;
        unsigned long    bus_base_addr;
        int              slots;  /* Max slot number */
        int              force_probe; /* Probe even when no slot 0 */
        u64              dma_mask; /* from bridge device */
        int              bus_nr; /* Set by eisa_root_register */
        struct resource  eisa_root_res; /* ditto */
};

node

eisa_root_registerの内部用途に使用

dev

ルートデバイスへのポインタ

res

ルートデバイスI/Oリソース

bus_base_addr

このバス上のスロット0のアドレス

slots

プローブする最大スロット番号

force_probe

スロット0が空（EISAマザーボードがない）でもプローブする

dma_mask

デフォルトDMAマスク。通常はブリッジデバイスのdma_maskです。

bus_nr

一意のバスID、eisa_root_registerによって設定

ドライバ¶

int eisa_driver_register (struct eisa_driver *edrv);
void eisa_driver_unregister (struct eisa_driver *edrv);

十分でしょうか？

struct eisa_device_id {
        char sig[EISA_SIG_LEN];
        unsigned long driver_data;
};

struct eisa_driver {
        const struct eisa_device_id *id_table;
        struct device_driver         driver;
};

id_table

NULLで終端されたEISA ID文字列の配列、その後に空文字列が続きます。各文字列はオプションでドライバ依存の値（driver_data）とペアになります。

ドライバ

一般的なドライバー、例えば以下のように記述されているもの デバイスドライバ．.name、.probe および .remove メンバーのみが必須です。

例として、3c59x ドライバーがあります：

static struct eisa_device_id vortex_eisa_ids[] = {
        { "TCM5920", EISA_3C592_OFFSET },
        { "TCM5970", EISA_3C597_OFFSET },
        { "" }
};

static struct eisa_driver vortex_eisa_driver = {
        .id_table = vortex_eisa_ids,
        .driver   = {
                .name    = "3c59x",
                .probe   = vortex_eisa_probe,
                .remove  = vortex_eisa_remove
        }
};

デバイス¶

sysfs フレームワークは、デバイスの検出および除去時に .probe および .remove 関数を呼び出します（注意として、.remove 関数はドライバーがモジュールとして構築されている場合にのみ呼び出されます）。

両方の関数には、'struct device’へのポインタが渡されます。これは以下の 'struct eisa_device' にカプセル化されています：

struct eisa_device {
        struct eisa_device_id id;
        int                   slot;
        int                   state;
        unsigned long         base_addr;
        struct resource       res[EISA_MAX_RESOURCES];
        u64                   dma_mask;
        struct device         dev; /* generic device */
};

id

デバイスから読み取った EISA ID。id.driver_data は、一致するドライバーの EISA ID から設定されます。

スロット

デバイスが検出されたスロット番号

状態

デバイスの状態を示すフラグのセット。現在のフラグは EISA_CONFIG_ENABLED および EISA_CONFIG_FORCED です。

res

このデバイスに割り当てられた4つの256バイトのI/O領域のセット

dma_mask

DMA マスクは親デバイスから設定されます。

dev

汎用デバイス（参照 基本的なデバイス構造)

‘struct eisa_device’ を ‘struct device’ から ‘to_eisa_device’ マクロを使用して取得できます。

その他の情報¶

void eisa_set_drvdata (struct eisa_device *edev, void *data);

デバイスの driver_data レギスタにデータを格納します。

void *eisa_get_drvdata (struct eisa_device *edev):

デバイスのdriver_data領域に以前に保存されていたポインタを取得します。

int eisa_get_region_index (void *addr);

指定されたアドレスの領域番号（0 <= x < EISA_MAX_RESOURCES）を返します。

カーネルパラメータ¶

eisa_bus.enable_dev

ファームウェアがカードを無効として設定していても有効にするコンマで区切られたスロットリストです。ドライバーはこのような状態でもデバイスを正しく初期化できる必要があります。

eisa_bus.disable_dev

ファームウェアがカードを有効として設定していても無効にするコンマで区切られたスロットリストです。ドライバーはこのようなデバイスを処理しません。

virtual_root.force_probe

EISAスロットをプローブするコードを強制的に実行します（EISA準拠のマザーボードが見つからない場合でも）。デフォルトでは0（強制しない）ですが、CONFIG_ALPHA_JENSENまたはCONFIG_EISA_VLB_PRIMINGが設定されている場合に1（強制プローブ）に設定します。

ランダムなノート¶

EISAドライバーを新しいAPIに変換するには主に コード（プローブがコアEISAコードに移動したため）を削除します。残念ながら、ほとんどのドライバーはISAとEISAで共通のプローブルーティンを使用しています。EISAコードを除去する際には他のバスに影響を及ぼさないよう注意が必要です… あなた

はできません eisa_driver_registerから戻るときにEISAデバイスが検出されることを期待しないでください。なぜなら、バスがまだプローブされていない可能性が高いからです。実際には、ほとんどの場合（バスルートドライバーがブートプロセスの後半になってから動作するため）このことが起こります。残念ながら、ほとんどのドライバーは自らプローブを行い、プローブルーティンを終了するときに全体のマシンを探索していると期待しています。 プローブルーティンを終了するときに全体のマシンを探索していると期待しています。

たとえば、お気に入りのEISA SCSIカードを「hotplug」モデルに切り替えることは、「正しいこと」(tm)です。
