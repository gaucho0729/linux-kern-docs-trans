HD-Audio DP-MST 対応¶

DP MSTオーディオをサポートするため、HD Audio HDMI コーデックドライバーは仮想ピンと動的PCM割当を導入しました。

仮想ピンはper_pinの拡張です。DP MSTと従来の最大の違いは、DP MSTがデバイスエントリを導入している点です。各ピンは複数のデバイスエントリを含むことができ、各デバイスエントリはピンとして動作します。

各ピンが複数のデバイスエントリを含み、各コーデックが複数のピンを含むため、per_pinごとに1つのPCMを使用すると多くのPCMが必要になります。新しい解決策は、少数のPCMを生成し、動的にPCMをper_pinにバインドすることです。ドライバーはspec->dyn_pcm_assignフラグを使用して新しい解決策を有効にするかどうかを示します。

PCM¶

追加予定

ピンの初期化¶

各ピンは複数のデバイスエントリ（仮想ピン）を持つことができます。Intelプラットフォームでは、デバイスエントリ数は動的に変更されます。DP MSTハブが接続されている場合、DP MSTモードになり、デバイスエントリ数は3になります。それ以外の場合はデバイスエントリ数は1になります。

実装を簡略化するため、起動時にDP MSTモードに関係なくすべてのデバイスエントリを初期化します。

接続リスト¶

DP MSTは接続リストコードを再利用します。同じピンのデバイスエントリが同じ接続リストを持つため、コードを再利用可能です。

これは、デバイスエントリの設定なしにデバイスエントリ接続リストを取得することを意味します。

ジャック¶

前提:

  • MSTはdyn_pcm_assignでなければならず、Intelシナリオではacompです。

  • NON-MSTはdyn_pcm_assignであるかどうかは任意で、acompまたは!acompである可能性があります。

したがって、以下のシナリオがあります:

  1. MST (&& dyn_pcm_assign && acomp)

  2. NON-MST && dyn_pcm_assign && acomp

  3. NON-MST && !dyn_pcm_assign && !acomp

以下の議論ではMSTとNON-MSTの違いを無視します。これはジャック処理にあまり影響しないからです。

ドライバはhdmi_spec内のstruct hdmi_pcm pcm[]配列を使用し、snd_jackはhdmi_pcmのメンバです。各ピンにはstruct hdmi_pcm * pcmポインタが1つずつ割り当てられます。

!dyn_pcm_assignの場合、per_pin->pcmはspec->pcm[n]に静的に割り当てられます。

dyn_pcm_assignの場合、モニターがホットプラグされたときにper_pin->pcmがspec->pcm[n]に割り当てられます。

ジャックの構築¶

  • dyn_pcm_assign

    hda_jackを使用せず、spec->pcm_rec[pcm_idx].jackにsnd_jackを直接使用します。

  • !dyn_pcm_assign

    hda_jackを使用し、spec->pcm_rec[pcm_idx].jack = jack->jackに静的に割り当てます。

非依頼イベントの有効化¶

!acompの場合、非依頼イベントを有効化します。

モニターのホットプラグイベント処理¶

  • acomp

    pin_eld_notify() -> check_presence_and_report() -> hdmi_present_sense() -> sync_eld_via_acomp().

    直接使用 snd_jack_report() dyn_pcm_assignと!dyn_pcm_assignの両方でspec->pcm_rec[pcm_idx].jackに使用します

  • !acomp

    hdmi_unsol_event() → hdmi_intrinsic_event() → check_presence_and_report() → hdmi_present_sense() → hdmi_prepsent_sense_via_verbs()

    直接使用 snd_jack_report() spec->pcm_rec[pcm_idx].jack における dyn_pcm_assign に対して。hda_jack メカニズムを使用してジャックイベントを処理する。
