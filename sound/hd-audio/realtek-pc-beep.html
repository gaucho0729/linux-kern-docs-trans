Realtek PC ビープ隠しレジスタ¶

このファイルは「PC Beep隠しレジスタ」について記述しており、特定のRealtek HDAコーデックに存在し、MUXと透過ミキサーを制御してピン間でオーディオをルーティングできるが、HDAウィジェットとして露出されていない機能を提供します。私のDell XPS 13 9350のマシンでは、これらの隠しルートは、出力パスにミキサー・ウィジェットを持たないコーデック向けに柔軟なPC Beep出力を可能にする設計であると考えられます。なぜ、ドキュメントされていないベンダー・レジスタにミキサーを隠す方が、単純にウィジェットとして露出するよりも簡単なのか、私には分かりません。

レジスタの説明¶

このレジスタは、NID 20hの処理係数0x36を介してアクセスされます。以下の説明にないビットは、私のマシンでは明確な影響を及ぼしません:

MSB                           LSB
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
| |h|S|L|         | B |R|       | Known bits
+=+=+=+=+=+=+=+=+=+=+=+=+=+=+=+=+
|0|0|1|1|  0x7  |0|0x0|1|  0x7  | Reset value
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
1Ah入力選択 (B): 2ビット

ゼロのとき、NID 01hで「Beep生成」コマンドを実行した場合の内部ビープジェネレータ（または外部PCBEEPピン）からのPC Beepラインを1Ahピンノードに露出します。ゼロでないとき、ヘッドホンジャック（または一部のマシンではラインイン）入力が代わりに露出されます。PC Beepが選択された場合、1Ahブースト制御は効果を持ちません。

1Ahループバックを左（L）で増幅: 1ビット

hビットとSビットで指定された出力にミキシングする前に、1Ahの左チャンネルを増幅します。他のウィジェットに露出される1Ahのレベルには影響しません。

1Ahループバックを右（R）で増幅: 1ビット

hビットとSビットで指定された出力にミキシングする前に、1Ahの右チャンネルを増幅します。他のウィジェットに露出される1Ahのレベルには影響しません。

1Ahを21hにループバック [アクティブロー] (h): 1ビット

ゼロのとき、1Ah（LおよびRビットに応じて増幅される可能性あり）を21h（私の機器のヘッドホンジャック）に混ぜます。混ぜた信号は21hのミュート設定を尊重します。

1Ahを14hにループバック (S): 1ビット

1のとき、1Ah（LおよびRビットに応じて増幅される可能性あり）を14h（私の機器の内部スピーカー）に混ぜます。混ぜた信号は 14hのミュート設定を無視し、14hが出力として設定されているときに常に表示されます。 1Ah入力選択 (DIVはNID 01hで設定されたPCビープディバイダー):

パス図¶

1Ahを21h/14hにループバック:

<Beep generator>   <PCBEEP pin>    <Headphone jack>
        |                |                |
        +--DIV--+--!DIV--+       {1Ah boost control}
                |                         |
                +--(b == 0)--+--(b != 0)--+
                             |
             >1Ah (Beep/Headphone Mic/Line In)<

すべてのRealtek HDAコーデックは、ノードID 20hを持つベンダー定義ウィジェットを持ち、さまざまなコーデック機能を制御するレジスタバンクへのアクセスを提供します。レジスタは標準的なHDA処理係数コマンド（Set/Get Coefficient Index、Set/Get Processing Coefficient）を通じて読み書きされます。このノードは公開データシートのコマンド一覧で「Realtek Vendor Registers」として名付けられており、それ以外は完全にドキュメントされていません。

     <1Ah (Beep/Headphone Mic/Line In)>
                     |
              {amplify if L/R}
                     |
        +-----!h-----+-----S-----+
        |                        |
{21h mute control}               |
        |                        |
>21h (Headphone)<     >14h (Internal Speaker)<

背景¶

1Ahを21h/14hにループバック:

Realtekのコミットで名前がつけられているこのレジスタは、係数0x36で露出しており、注目すべき点があります。他の多くのレジスタとは異なり、詳細なアンプのパラメータを制御するものであるが、HDA仕様の範囲外であるため、このレジスタはオーディオルーティングを制御しており、標準的なHDAミキサーおよびセレクタ・ウィジェットで定義することができた可能性があります。

具体的には、ノードID（NID）1Ahの入力ピン・ウィジェットの2つのソース間で選択します。このウィジェットの信号は、オーディオジャック（私のラップトップであるDell XPS 13 9350ではヘッドホンジャックですが、Realtekのコミットコメントによると、一部のマシンではラインインの可能性があります）から来るか、PCビープラインから来るかのどちらかです（PCビープライン自体は、コードックの内部ビープジェネレータと外部PCBEEPピンの間で多重化されており、ビープジェネレータがNID 01hでビーブル語を介して有効化されているかどうかに応じて異なります）。さらに、この信号は21hおよび/または14hの出力ピンに（オプションで増幅しながら）ミキシングすることもできます。

このレジスタのリセット値は0x3717で、これは1AhのPCビープを増幅してヘッドホンとスピーカーの両方にミキシングします。HDA仕様は「[ベンダー定義のビープ入力ピン] 接続はリンク・リセット（ のみ RST#)がアサートされている間も維持される）と述べていますが、このレジスタを無視することはできません。なぜなら、1Ahが通常公開する入力や、PCBEEPトレースがシールドされておらず筐体ノイズを拾っている場合（私のマシンでは両方の条件が成立しています）に影響を与えるからです。

残念なことに、このレジスタの設定を間違える方法はたくさんあります。Linuxはすでにほとんどの間違いを経験したようです。例えば、S3スリープ後にレジスタがリセットされるため、既存のコードから見るとすべてのベンダー・レジスタでこの現象が起きているわけではないことが分かっており、冷起動時の挙動改善に役立つ修正が行われていますが、スリープ後に続くことはありません。他の修正では1Ah入力がPCビープから切り替わったものの、ループバック経路を両方無効化できていません。私のマシンでは、ヘッドホン入力が増幅され、ヘッドホン出力にループバックしてしまいます。この出力ピンはまったく同じです！予想通り、これはヘッドホンノイズを引き起こし、そのノイズの特性は1Ahのブースト制御で制御されます。（オンラインでXPS 13のヘッドホンノイズを修正する方法として「Headphone Mic Boost」を変更する手順を目にしたことがある場合は、これがその理由です。）

ここに掲載されている情報は、ALC256コーデックの動作をブラックボックス逆工学によって取得したものであり、正確性が保証されていません。この情報はおそらくALC255、ALC257、ALC235、ALC236などのコーデックにも適用される可能性があります。これらのコーデックはALC256と類似した設計で、すべてが同一の初期化関数を共有しているからです。(既存の修正情報から推測すると、ALC225やALC285などの他のコーデックもこのレジスタを備えていると考えられます) patch_realtek.cただし、これらのコーデックに関する具体的なデータ（例: ノードID、ビット位置、ピンマッピングなど）はここに記載した内容と異なる可能性があります。
