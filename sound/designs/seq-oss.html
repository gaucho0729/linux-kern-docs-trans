ALSA 上の OSS シーケンサエミュレーション¶

著作権 (c) 1998,1999 by Takashi Iwai

ver.0.1.8; 1999年11月16日

説明¶

このディレクトリには、ALSA上でのOSSシーケンサーエミュレーションドライバが含まれています。このプログラムはまだ開発段階にあることに注意してください。

これはOSSシーケンサーエミュレーションを提供し、以下のようなデバイス経由でアクセス可能になります。 /dev/sequencer および /dev/music 適切なALSAシーケンサーが準備されている場合、OSSを使用するほとんどのアプリケーションが動作します。

このドライバによってエミュレートされる機能は以下の通りです：

  • 通常のシーケンサーやMIDIイベント：

    これらはALSAシーケンサーイベントに変換され、対応するポートに送信されます。

  • タイマーイベント：

    タイマーコントロールはioctlで選択できません。コントロールレートはHZに関係なく常に100に固定されます。つまり、Alphaシステムでも1/100秒が1tickになります。ベースレートとテンポは /dev/music.

  • パッチロード：

    パッチロードはシンセドライバのコールバックによって実現されるため、シンセドライバがサポートしているかどうかに依存します。

  • I/O制御：

    ほとんどの制御は受け入れられます。一部の制御はシンセドライバに依存し、元のOSSにも依存します。

さらに、以下の高度な機能が利用可能です：

  • より優れたキュー機構：

    イベントは処理前にキューに格納されます。

  • 複数のアプリケーション：

    2つ以上のアプリケーションを同時に実行できます（OSSシーケンサーでも！）。ただし、各MIDIデバイスは排他的に使用されます。つまり、あるアプリケーションがMIDIデバイスを開いた後、他のアプリケーションは使用できません。シンセデバイスにはこのような制限はありません。

  • リアルタイムイベント処理：

    イベントはout of bound ioctlを使用せずにリアルタイムで処理できます。リアルタイムモードに切り替えるにはABSTIME 0イベントを送信してください。その後のイベントはキューを介さずにリアルタイムで処理されます。リアルタイムモードをオフにするにはRELTIME 0イベントを送信してください。

  • /proc インターフェース:

    アプリケーションおよびデバイスの状態は以下のように表示できます。 /proc/asound/seq/oss いつでも確認できます。後続のバージョンでは、設定は以下のように変更されます。 /proc インターフェースも利用可能になります。

インストール¶

シーケンサーサポート（--with-sequencer=yes)とOSSエミュレーション（--with-oss=yes)オプションでコンフィギュアスクリプトを実行してください。モジュール snd-seq-oss.o が作成されます。あなたのサウンドカードのシンセモジュールがOSSエミュレーションをサポートしている場合（現時点ではEmu8000ドライバのみ）、このモジュールが自動的にロードされます。そうでない場合は、このモジュールを手動でロードする必要があります。

最初に、このモジュールはすでにシーケンサに接続されているすべてのMIDIポートをスキャンします。その後は、ALSAシーケンサのアラートメカニズムによってポートの作成・削除を監視します。

利用可能なシンセおよびMIDIデバイスはprocインターフェースで確認できます。実行してください。 cat /proc/asound/seq/oss、デバイスを確認してください。たとえば、AWE64カードを使用している場合、以下のような表示になります：

OSS sequencer emulation version 0.1.8
ALSA client number 63
ALSA receiver port 0

Number of applications: 0

Number of synth devices: 1
synth 0: [EMU8000]
  type 0x1 : subtype 0x20 : voices 32
  capabilties : ioctl enabled / load_patch enabled

Number of MIDI devices: 3
midi 0: [Emu8000 Port-0] ALSA port 65:0
  capability write / opened none

midi 1: [Emu8000 Port-1] ALSA port 65:1
  capability write / opened none

midi 2: [0: MPU-401 (UART)] ALSA port 64:0
  capability read/write / opened none

デバイス番号は元のOSSドライバーの情報とは異なる場合がありますので注意してください。 /proc/asound/oss-devices 元のOSSドライバーのそれらの情報。リストに記載されているデバイス番号を使用してください /proc/asound/seq/oss OSSシーケンサーエミュレーションで再生してください。

シンセサイザーデバイスの使用方法¶

お気に入りのプログラムを実行してください。私はplaymidi-2.4、awemidi-0.4.3、gmod-3.1、xmp-1.1.5をテストしました。sfxloadなどのツールでサンプルをロードできます /dev/sequencer 、sfxloadなどのツールでも可能です。

低レベルドライバーがシンセサイザデバイスへの複数アクセスをサポートしている場合（例：Emu8000ドライバー）、2つ以上のアプリケーションが同時に実行できます。

MIDI デバイスの使用方法¶

これまでにMIDI出力のみがテストされています。MIDI入力はまったく確認されていませんが、おそらく動作するでしょう。リストに記載されているデバイス番号を使用してください。 /proc/asound/seq/oss。これらの番号は、リスト内のものとは大きく異なります /proc/asound/oss-devices.

モジュールオプション¶

以下のモジュールオプションが利用可能です：

maxqlen

読み込み/書き込みキューの最大長を指定します。このキューはOSSシーケンサー専用で、ALSAシーケンサーのキュー長とは独立しています。デフォルト値は1024です。

seq_oss_debug

デバッグレベルを指定します。ゼロ（＝デバッグメッセージなし）または正の整数を受け取ります。デフォルト値は0です。

キュー機構¶

OSSシーケンサーエミュレーションはALSAプライオリティキューを使用します。 /dev/sequencer からのイベントはキューに処理され、モジュールオプションで指定されたキューに配置されます。

からのすべてのイベントは開始時に解析されます。 /dev/sequencer タイミングイベントもこの時点で解析されるため、イベントがリアルタイムで処理される可能性があります。イベントABSTIME 0を送信するとリアルタイムモードに切り替えられ、イベントRELTIME 0を送信するとオフになります。リアルタイムモードではすべてのイベントが即座に配信されます。

キューされたイベントは、ALSAシーケンサーディスパッチャによってスケジュールされた時間に応じて対応するALSAシーケンサーポートに配信されます。

書き込みキューが満杯の場合、ブロッキングモードでは一定量（デフォルトでは半分）が空になるまでプロセスが待機します。また、書き込みタイミングの同期も実装されています。

MIDIデバイスからの入力やエコーバックイベントは読み取りFIFOキューに保存されます。アプリケーションがブロッキングモードで読み取る場合、プロセスが目覚めます。 /dev/sequencer OSSシンセサイザデバイスを登録するには、snd_seq_oss_synth_register()関数を使用してください：

シンセサイザーデバイスへのインターフェース¶

登録¶

引数

int snd_seq_oss_synth_register(char *name, int type, int subtype, int nvoices,
        snd_seq_oss_callback_t *oper, void *private_data)

はioctl用に適切なsynth_info構造体を作成するために使用されます。返却値はこのデバイスのインデックス番号です。このインデックス番号はアンレジスタ時に記憶しておく必要があります。登録に失敗した場合、-errnoが返却されます。 name, type, subtype および nvoices を

でこのデバイスを解放するには、snd_seq_oss_synth_unregister()関数を呼び出してください：

int snd_seq_oss_synth_unregister(int index)

で、 index は登録関数から返却されたインデックス番号です。

コールバック¶

OSSシンセサイザデバイスはサンプルのダウンロードやサンプルリセットなどのioctl機能を備えています。OSSエミュレーションでは、これらの特殊な機能はコールバックによって実現されます。登録引数operはこれらのコールバックを指定するために使用されます。以下のコールバック関数は必ず定義する必要があります：

snd_seq_oss_callback_t:
 int (*open)(snd_seq_oss_arg_t *p, void *closure);
 int (*close)(snd_seq_oss_arg_t *p);
 int (*ioctl)(snd_seq_oss_arg_t *p, unsigned int cmd, unsigned long arg);
 int (*load_patch)(snd_seq_oss_arg_t *p, int format, const char *buf, int offs, int count);
 int (*reset)(snd_seq_oss_arg_t *p);

例外を除いて open および close コールバックはNULLを許可されます。

各コールバック関数は、引数の型を最初の引数として受け取ります。 snd_seq_oss_arg_t 最初の3つのフィールド、

struct snd_seq_oss_arg_t {
    int app_index;
    int file_mode;
    int seq_mode;
    snd_seq_addr_t addr;
    void *private_data;
    int event_passing;
};

はOSSシーケンサーによって初期化されます。 app_index, file_mode および seq_mode はアプリケーションがOSSシーケンサーを開く際に一意のインデックスを表します。 app_index はファイル操作モードを示すビットフラグです。意味については file_mode を参照してください。 seq_oss.h はシーケンサ操作モードです。現在のバージョンでは、 seq_mode のみが有効です。 SND_OSSSEQ_MODE_SYNTH が使用されます。

次の2つのフィールド、 addr および private_dataはシンセドライバーがオープンコールバックで必ず埋める必要があります。 addr はこのデバイスに割り当てられたALSAシーケンサポートのアドレスを含みます。ドライバーがメモリを割り当てた場合、 private_dataはクローズコールバックで自身で解放する必要があります。

最後のフィールド、 event_passingはノートオン/オフイベントの翻訳方法を示します。 PROCESS_EVENTS モードでは、ノート255は速度変化とみなされ、キーピレスチャーアクセントイベントはポートに渡されます。 PASS_EVENTS モードでは、すべてのノートオン/オフイベントが変更せずにポートに渡されます。 PROCESS_KEYPRESS モードでは、128以上のノートはキーピレスチャーアクセントイベントとみなされます（主にEmu8000ドライバー用）。

オープンコールバック¶

以下の open はアプリケーションがOSSシーケンサーでこのデバイスを開くたびに呼び出されます。これはNULLであってはなりません。通常、オープンコールバックは以下の手順を実行します：

  1. プライベートデータレコードを割り当てます。

  2. ALSAシーケンサポートを作成します。

  3. 新しいポートアドレスを arg->addr.

  4. に設定します。 arg->private_data.

このシンセポートのport_infoの型ビットフラグには TYPE_MIDI_GENERIC ビットを含んではなりません。代わりに TYPE_SPECIFIC を使用する必要があります。また、 CAP_SUBSCRIPTION ビットも含んではなりません。これは他の通常のMIDIデバイスと区別するためです。オープン処理が成功した場合は0を、失敗した場合は-errnoを返します。

IOCTLコールバック¶

以下の ioctl はシーケンサーがデバイス固有のIOCTLを受信した際に呼び出されます。以下の2つのIOCTLはこのコールバックで処理する必要があります：

IOCTL_SEQ_RESET_SAMPLES

メモリ内のすべてのサンプルをリセット – 0を返します

IOCTL_SYNTH_MEMAVL

利用可能なメモリサイズを返します

FM_4OP_ENABLE

通常は無視されます

その他のIOCTLはシーケンサー内部で処理され、低レベルドライバーに渡されません。

ロードパッチコールバック¶

以下の load_patch callbackはサンプルダウンロードに使用されます。このcallbackはユーザー空間のデータを読み取り、各デバイスに転送する必要があります。成功した場合は0を返し、失敗した場合は-errnoを返します。format引数はpatch_infoレコード内のパッチキーです。bufはpatch_infoレコードが格納されているユーザー空間のポインタです。offsは無視できます。countはこのサンプルデータの総データサイズです。

クローズコールバック¶

以下の close このデバイスがアプリケーションによって閉じられるときに呼ばれます。openコールバックで割り当てられたプライベートデータは、closeコールバックで解放する必要があります。ALSAポートの削除もここで行う必要があります。このコールバックはNULLであってはなりません。

リセットコールバック¶

以下の reset シーケンサーデバイスがリセットまたはアプリケーションによって閉じられるときに呼ばれます。このコールバックは関連するポートのサウンドをすぐにオフにし、ポートの状態を初期化する必要があります。このコールバックが未定義の場合、OSS seqはポートにイベントを送信します。 HEARTBEAT ポートにイベントを送信します。

イベント¶

ほとんどのイベントはシーケンサーによって処理され、適切なALSAシーケンサーイベントに翻訳されるため、各シンセデバイスはALSAシーケンサーポートのinput_eventコールバックを通じて受信します。以下のALSAイベントはドライバで実装する必要があります：

ALSAイベント

オリジナルのOSSイベント

ノートオン

SEQ_NOTEON, MIDI_NOTEON

注意

SEQ_NOTEOFF, MIDI_NOTEOFF

キープレス

MIDI_KEY_PRESSURE

チャンプレス

SEQ_AFTERTOUCH, MIDI_CHN_PRESSURE

PGMCHANGE

SEQ_PGMCHANGE, MIDI_PGM_CHANGE

ピッチベンド

SEQ_CONTROLLER(CTRL_PITCH_BENDER), MIDI_PITCH_BEND

コントローラー

MIDI_CTL_CHANGE, SEQ_BALANCE (with CTL_PAN)

CONTROL14

SEQ_CONTROLLER

REGPARAM

SEQ_CONTROLLER(CTRL_PITCH_BENDER_RANGE)

SYSEX

SEQ_SYSEX

これらの動作の多くは、Emu8000 lowlevelドライバに含まれるMIDIエミュレーションドライバによって実現できます。今後のリリースではこのモジュールは独立します。

一部のOSSイベント（SEQ_PRIVATE および SEQ_VOLUME イベント）はイベントタイプSND_SEQ_OSS_PRIVATEとして渡されます。OSSシーケンサーはこれらのイベントを8バイトのパケットとして変更せずに渡します。lowlevelドライバはこれらのイベントを適切に処理する必要があります。

MIDI デバイスへのインターフェース¶

OSSエミュレーションはALSA MIDIシーケンサーポートの作成と削除をALSAシーケンサーからのアナウンスを受けて自動的に検出するため、MIDIデバイスはシンセデバイスのように明示的に登録する必要がありません。ただし、ALSAシーケンサーに登録されるMIDIポート_infoにはグループ名 SND_SEQ_GROUP_DEVICE と能力ビット CAP_READ または CAP_WRITEを含める必要があります。また、サブスクリプション能力、 CAP_SUBS_READ または CAP_SUBS_WRITEも定義する必要があります。これらの条件を満たさない場合、ポートはOSSシーケンサーMIDIデバイスとして登録されません。

MIDIデバイス経由のイベントはOSSシーケンサーによって解析され、対応するALSAシーケンサーイベントに変換されます。MIDIシーケンサーからの入力もOSSシーケンサーによってMIDIバイトイベントに変換されます。これはseq_midiモジュールの逆の動作です。
