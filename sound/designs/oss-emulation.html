カーネル OSS-エミュレーションに関する注意点¶

2004年1月22日、Takashi Iwai <tiwai@suse.de>

モジュール¶

ALSAはカーネル上で強力なOSSエミュレーションを提供します。PCM、ミキサーおよびシーケンサデバイスのOSSエミュレーションは、snd-pcm-oss、snd-mixer-oss、snd-seq-ossという拡張カーネルモジュールとして実装されています。OSS PCM、ミキサーまたはシーケンサデバイスにアクセスする必要がある場合は、対応するモジュールをロードする必要があります。

これらのモジュールは、対応するサービスが呼び出されるときに自動的にロードされます。エイリアスは sound-service-x-yで定義され、ここでxとyはカード番号とマイナーユニット番号です。通常、ユーザーがこれらのエイリアスを手動で定義する必要はありません。

OSSモジュールの自動ロードに必要なステップは、カードエイリアスを /etc/modprobe.d/alsa.conf、例えば：

alias sound-slot-0 snd-emu10k1

に定義することです。第二カードについては、 sound-slot-1 も定義してください。注意点として、エイリアス名をターゲット名として使用することはできません（つまり、 alias sound-slot-0 snd-card-0 は古いmodutilsと同様に動作しなくなりました）。

現在利用可能なOSS構成は、/proc/asound/oss/sndstatに表示されます。これは、商用OSSドライバで利用可能な/dev/sndstatと同じ構文を使用しています。ALSAでは、/dev/sndstatをこのプロシージャーファイルにシンリンクできます。

このプロシージャーファイルに表示されるデバイスは、対応するOSSエミュレーションモジュールがロードされた後だけ表示されます。"NOT ENABLED IN CONFIG"が表示されても心配する必要はありません。

デバイスマッピング¶

ALSAがサポートするOSSデバイスファイルは以下の通りです：

PCM:
        /dev/dspX
        /dev/adspX

Mixer:
        /dev/mixerX

MIDI:
        /dev/midi0X
        /dev/amidi0X

Sequencer:
        /dev/sequencer
        /dev/sequencer2 (aka /dev/music)

ここでXは0から7までのカード番号です。

(注意：一部のディストリビューションでは、/dev/midi0や/dev/midi1などのデバイスファイルが存在します。これらはOSSではなく、tclmidi（完全に異なるもの）用のものです。)

実際のOSSとは異なり、ALSAは割り当てられたデバイスファイル以上を使用できません。たとえば、最初のカードは/dev/dsp1や/dev/dsp2を使用できませんが、/dev/dsp0と/dev/adsp0のみを使用できます。

上記のように、PCMとMIDIには2つのデバイスがある場合があります。通常、ALSAの最初のPCMデバイス（hw:0,0 ）は/dev/dspにマッピングされ、第二のデバイス（hw:0,1）は/dev/adsp（利用可能であれば）にマッピングされます。MIDIの場合、/dev/midiと/dev/amidiにそれぞれマッピングされます。

このデバイスマッピングは、snd-pcm-ossとsnd-rawmidiのモジュールオプションを介して変更できます。PCMの場合、snd-pcm-ossには以下のオプションが利用可能です：

dsp_map

/dev/dspXに割り当てられるPCMデバイス番号（デフォルト=0）

adsp_map

/dev/adspXに割り当てられるPCMデバイス番号（デフォルト=1）

たとえば、第三のPCMデバイス（hw:0,2）を/dev/adsp0にマッピングするには、以下のように定義してください：

options snd-pcm-oss adsp_map=2

オプションは配列を取るため、第二カードを設定する場合は、コンマで区切った2つのエントリを指定してください。たとえば、第二カードの第三PCMデバイスを/dev/adsp1にマッピングするには、以下のように定義してください：

options snd-pcm-oss adsp_map=0,2

MIDIデバイスのマッピングを変更するには、snd-rawmidiには以下のオプションが利用可能です:

midi_map

/dev/midi0Xに割り当てられるMIDIデバイス番号（デフォルト＝0）

amidi_map

/dev/amidi0Xに割り当てられるMIDIデバイス番号（デフォルト＝1）

たとえば、1番目のカードの3番目のMIDIデバイスを/dev/midi00に割り当てたい場合、以下のように定義します:

options snd-rawmidi midi_map=2

PCM モード¶

デフォルトでは、ALSAは所謂プラグインレイヤーを使用してOSS PCMをエミュレートし、カードがネイティブにサポートしていない場合にサンプル形式、レート、またはチャンネルを自動的に変換しようとします。これにより、quakeやwineなどの一部のアプリケーションで問題が発生することがあります、特にMMAPモードのみでカードを使用している場合です。

このような場合、アプリケーションごとにPCMの挙動を変更するには、procファイルにコマンドを書き込むことができます。各PCMストリームに対してprocファイルが存在します、 /proc/asound/cardX/pcmY[cp]/oss、ここでXはカード番号（ゼロベース）、YはPCMデバイス番号（ゼロベース）、 p は再生用で、 c は録音用です。注意点として、このprocファイルはsnd-pcm-ossモジュールがロードされた後のみ存在します。

コマンドシーケンスの構文は以下の通りです:

app_name fragments fragment_size [options]

app_name はアプリケーション名（優先度が高い）またはパスを含まない名前です。 fragments はフラグメント数を指定するか、指定がない場合はゼロです。 fragment_size はフラグメントサイズ（バイト）を指定するか、指定がない場合はゼロです。 options はオプションパラメータです。以下のオプションが利用可能です:

無効化

アプリケーションはこのチャンネル用のpcmデバイスを開こうとするが、使用しない。

direct

プラグインを使用しない

block

ブロックオープンモードを強制的に使用

ノンブロック

ノンブロックオープンモードを強制的に使用

partial-frag

部分的なフラグメントも書き込む（再生専用に影響）

サイレントを無効化

前方のサイレントを埋めないことでクリックを防ぐ

以下の disable オプションは、アプリケーションがハードウェア自体が両方向をサポートしているにもかかわらず、一方のストリーム方向（再生または録音）のみを正しく処理していない場合に役立ちます。この direct オプションは、上記のように自動変換をバイパスし、MMAPアプリケーションに有用です。たとえば、quakeでプラグインなしで最初のPCMデバイスを再生するには、以下のようのようにechoコマンドでコマンドを送ります:

% echo "quake 0 0 direct" > /proc/asound/card0/pcm0p/oss

quakeが再生のみを必要とする場合、以下の2番目のコマンドを追加してドライバにこの方向のみが割り当てられることを通知できます:

% echo "quake 0 0 disable" > /proc/asound/card0/pcm0c/oss

procファイルのパーミッションはsndモジュールのオプションによって決まります。デフォルトではrootとして設定されているため、上記のコマンドを送るにはスーパーユーザーになる必要があります。

ブロックおよびノンブロックオプションはデバイスファイルを開く挙動を変更するために使用されます。

デフォルトでは、ALSAはオリジナルのOSSドライバと同様の動作をします、つまり、ビジーなときにファイルをブロックしません。この場合、-EBUSYエラーが返されます。

このブロッキング動作は、snd-pcm-ossのnonblock_openモジュールオプションを通じてグローバルに変更できます。OSSデバイスのブロッキングモードをデフォルトとして使用するには、以下のように定義してください：

options snd-pcm-oss nonblock_open=0

以下の partial-frag および no-silence 最近、コマンドが追加されました。どちらのコマンドも最適化用にのみ使用されます。前者のコマンドは、フラグメントが満たされたときにのみ書き込み転送を呼び出すように指定します。後者は自動的に静かなデータを先に書き込まないように停止します。どちらもデフォルトでは無効です。

現在の設定を確認するには、procファイルを読み込むことができます。読み込んだデータを再びprocファイルに送信することで、現在の設定を保存できます

% cat /proc/asound/card0/pcm0p/oss > /somewhere/oss-cfg

そして、以下のように復元できます

% cat /somewhere/oss-cfg > /proc/asound/card0/pcm0p/oss

また、現在の設定をすべてクリアするには、以下のようにコマンドを送信してください： erase 以下のようにコマンドを送信してください：

% echo "erase" > /proc/asound/card0/pcm0p/oss

ミキサー要素¶

ALSAは完全に異なるミキサーインターフェースを持つため、OSSミキサーのエミュレーションは相対的に複雑です。ALSAは、名前文字列に基づいて複数の異なるALSA（ミキサー）制御からミキサー要素を構築します。たとえば、ボリューム要素SOUND_MIXER_PCMは、再生方向用の「PCM再生ボリューム」および「PCM再生スイッチ」制御と、キャプチャディレクトリ（存在する場合）用の「PCMキャプチャボリューム」および「PCMキャプチャスイッチ」制御から構成されます。OSSのPCMボリュームが変更されると、すべての上記ボリュームおよびスイッチ制御が自動的に調整されます。

これらのミキサー要素の現在の割当は、/proc/asound/cardX/oss_mixerというプロシージャーファイルに記録されており、以下のような形式になります。

VOLUME "Master" 0
BASS "" 0
TREBLE "" 0
SYNTH "" 0
PCM "PCM" 0
...

1列目はOSSボリューム要素、2列目は対応するALSAコントロールのベース文字列、3列目はコントロールインデックスです。文字列が空欄の場合、対応するOSSコントロールが利用不可であることを意味します。

割当を変更するには、このプロシージャーファイルに設定を書き込むことができます。例えば、「Wave Playback」をPCMボリュームにマッピングする場合、以下のコマンドを送信します。

% echo 'VOLUME "Wave Playback" 0' > /proc/asound/card0/oss_mixer

コマンドはプロシージャーファイルに記載されているとおりです。1行ごとに1つのボリュームを変更できます。最後の例では、PCMボリュームが変更されると「Wave Playback Volume」と「Wave Playback Switch」の両方が影響を受けます。

PCMプロシージャーファイルの場合と同様に、プロシージャーファイルのパーミッションはsndモジュールのオプションに依存します。上記のコマンドを送信するにはスーパーユーザーが必要になる可能性があります。

PCMプロシージャーファイルの場合と同様に、全体のファイルイメージを読み書きすることで現在のミキサー設定を保存および復元できます。

デュプレックスストリーム¶

単一のデバイスファイルを再生および録音に使用する場合、OSS APIは各方向でフォーマット、サンプルレート、チャンネル数を異なる設定を提供していません。そのため、

io_handle = open("device", O_RDWR)

各方向で値が同じである必要があります。

2方向で異なる値を使用する場合は、両方の

input_handle = open("device", O_RDONLY)
output_handle = open("device", O_WRONLY)

を使用して、対応するハンドルの値を設定してください。

非対応機能¶

ICE1712ドライバーのMMAP¶

ICE1712は非標準の形式、インターレーブされた10チャンネル24bit（32bitにパック）形式のみをサポートしています。そのため、OSSでの従来の形式（モノラルまたは2チャンネル、8bitまたは16bit）ではバッファをMMAPすることはできません。
