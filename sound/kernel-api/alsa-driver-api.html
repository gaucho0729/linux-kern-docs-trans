int snd_card_free_when_closed(struct snd_card *card)¶

Disconnect the card, free it later eventually

パラメータ

struct snd_card *card

soundcard structure

説明

ACPIテーブル内のオブジェクトとは異なり、 snd_card_free(), this function doesn’t try to release the card resource immediately, but tries to disconnect at first. When the card is still in use, the function returns before freeing the resources. The card resources will be freed when the refcount gets to zero.

dmaengineベースのPCMの設定データ

定義

struct snd_dmaengine_pcm_config {
  int (*prepare_slave_config)(struct snd_pcm_substream *substream,struct snd_pcm_hw_params *params, struct dma_slave_config *slave_config);
  struct dma_chan *(*compat_request_channel)(struct snd_soc_pcm_runtime *rtd, struct snd_pcm_substream *substream);
  int (*process)(struct snd_pcm_substream *substream,int channel, unsigned long hwoff, void *buf, unsigned long bytes);
  dma_filter_fn compat_filter_fn;

メンバ

prepare_slave_config

PCMサブストリームのDMA slave_configを埋めるためのコールバック。PCMドライバのhwparamsコールバックから呼び出されます。

compat_request_channel

devicetreeを使用しないプラットフォームでDMAチャネルを要求するためのコールバック

process

ユーザー空間と双方向に転送されるサンプルの処理を適用するために使用されるコールバックです。

compat_filter_fn

デバイスツリーを使用しないプラットフォームでチャンネルを要求する際のフィルターファンクションとして使用されます。フィルターパラメータはDAIのDMAデータになります。

dma_dev

設定されている場合、このデバイスではなくDAIデバイスではなくDMAチャンネルを要求します。

chan_names

設定されている場合、登録時にこれらのカスタムDMAチャンネル名を要求します。

pcm_hardware

PCMに使用するsnd_pcm_hardware構造体です。

prealloc_buffer_size

事前に割り当てられたオーディオバッファのサイズです。

注意

両方compat_request_channelとcompat_filter_fnが設定されている場合、compat_request_channelがチャンネルを要求し、compat_filter_fnは無視されます。それ以外の場合、dma_request_channelを使用してチャンネルを要求し、compat_filter_fnをフィルターファンクションとして使用します。

const char *flavour

カードがその同僚の中でも差別化するフレーバー「差別化要素」。

説明

Intelのマシンドライバーは多くの異なるデバイスで使用されることがありますが、ユーザー空間では差別化が難しいです。これはマシンドライバーが通常自身の名前をカードの短い名前として使用し、カードの長い名前を空白にすることによるものです。このようなデバイスを区別し、デバイス固有の構成設定が欠如しているためのバグを修正するため、この機能によりDMI情報がサウンドカードの長い名前として使用されることが可能です。フォーマットは「ベンダー-製品-バージョン-ボード」（ここではキャラクター「-」が異なるDMIフィールドを区切る役割を果たします）です。これにより、ユーザー空間がデバイス固有のUse Case Manager (UCM)構成をカードにロードできるようになります。

可能となるカードの長い名前例: DellInc.-XPS139343-01-0310JH ASUSTeKCOMPUTERINC.-T100TA-1.0-T100TA Circuitco-MinnowboardMaxD0PLATFORM-D0-MinnowBoardMAX

この機能は、カードの長い名前をフレーバーとして利用して追加の差別化を提供することもサポートしています。例えば「ベンダー-製品-バージョン-ボード-フレーバー」の形式です。

カードの長い名には数字とアルファベットの文字といくつかのセパレータ文字のみを保持します。これはユーザー空間のUCMがカードの長い名前をカードの構成ディレクトリ名として使用するためで、AudoConfはスペースなどの特殊文字をサポートできないためです。

成功時は0を返し、それ以外は負のエラーコードを返します。
