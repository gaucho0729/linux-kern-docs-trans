Audiophile USB 仕様と正しい使用方法¶

このセクションは、デバイスの機能と制限についての重要な事実を思い出させてくれます。

デバイスには4つのオーディオインターフェースと2つのMIDIポートがあります：

  • アナログステレオ入力 (Ai)

    • このポートは、ラインレベルのオーディオ入力2ペア（1/4” TS と RCA）をサポートしています

    • 1/4” TS (ジャック) コネクタが接続されている場合、RCA コネクタは無効になります

  • アナログステレオ出力 (Ao)

  • デジタルステレオ入力 (Di)

  • デジタルステレオ出力 (Do)

  • MIDI イン (Mi)

  • MIDI アウト (Mo)

内部DAC/ADCは以下の特徴を持っています：

  • サンプル深度は16ビットまたは24ビット

  • サンプルレートは8kHzから96kHzまで

  • 2つのインターフェースは同時に異なるサンプル深度を使用できません

さらに、Audiophile USB のドキュメンテーションには以下の警告があります：

ビット深度を切り替える前に、すべてのオーディオアプリケーションを終了してください

USB 1.1 の帯域幅制限により、選択したオーディオモードによって同時に有効化できるインターフェースの数は制限されています：

  • 16ビット/48kHz ==> 4チャネル入力 + 4チャネル出力

    • Ai+Ao+Di+Do

  • 24ビット/48kHz ==> 4チャネル入力 + 2チャネル出力、または 2チャネル入力 + 4チャネル出力

    • Ai+Ao+Do または Ai+Di+Ao または Ai+Di+Do または Di+Ao+Do

  • 24ビット/96kHz ==> 2チャネル入力 _or_ 2チャネル出力（半二重のみ）

    • Ai または Ao または Di または Do

デジタルインターフェースに関する重要な事実：¶

  • Do ポートは、周辺音声符号化された AC-3 および DTS パススルーを追加でサポートしていますが、Linux 環境でのテストは行っていません

    • この設定では、Doインターフェースのみを有効にすることができます。

  • オーディオデジタルストリームの録音以外にも、Diポートを有効にする方法は、デバイスを外部のサンプルクロックに同期させる手段の一つです。

    • その結果、Diポートを有効にする際には、アクティブなデジタルソースが接続されている場合に限り有効にする必要があります。

    • デジタルソースが接続されていない状態でDiを有効にすると、同期エラー（例えば、奇数のサンプルレートで音が再生される場合など）が発生する可能性があります。

ALSAにおけるAudiophile USB MIDIサポート¶

以下のモジュールがロードされると、Audiophile USB MIDIポートが自動的にサポートされます：

  • snd-usb-audio

  • snd-seq-midi

追加の設定は必要ありません。

ALSAにおけるAudiophile USBオーディオサポート¶

Audiophile USBデバイスのオーディオ機能はsnd-usb-audioモジュールによって処理されます。このモジュールは、デバイス固有のパラメータを用いた「高度な」モードで動作するか、デバイス固有のパラメータを呼ばずにデフォルトモードで動作します。 device_setup.

デフォルトAlsaドライバモード¶

snd-usb-audioドライバのデフォルト動作は、起動時にデバイスの機能を一覧表示し、アプリケーションの要件に応じて必要なモードを自動的にアクティブ化します。例えば、ユーザーが24bit-depthモードで録音し、その後すぐに16bit-depthモードに切り替える場合、snd-usb-audioモジュールはデバイスを即座に再構成します。

このアプローチの利点は、ドライバがユーザーのニーズに応じてサンプルレート/ビット深度を自動的に切り替えることです。しかし、Windowsでこのデバイスを使用しているユーザーは、この動作が意図されていないことを知っています。Windowsでは、アプリケーションを終了した後でm-audioコントロールパネルを使用してデバイスの動作モードを切り替える必要があります。したがって、次のセクションで説明するように、このデフォルトAlsaドライバモードはデバイスの誤設定を引き起こす可能性があります。

まずはデフォルトAlsaドライバモードに戻りましょう。この場合、AudiophileインターフェースはALSA PCMデバイスに以下のようにマッピングされます（デバイスのインデックスが1であると仮定します）：

  • hw:1,0は再生時にAo、キャプチャ時にDi

  • hw:1,1は再生時にDo、キャプチャ時にAi

  • hw:1,2はAC3/DTSパストスルーモードでの再生時にDo

このモードでは、デバイスはビッグエンディアンバイトエンコーディングを使用し、サポートされるオーディオ形式は16bit深度モードでS16_BE、24bit深度モードでS24_3BEです。

例外はhw:1,2ポートで、これはリトルエンディアン準拠（S16_LEをサポートするとされる）と報告されていますが、実際にはS16_BEストリームのみを処理します。これはカーネル2.6.23以降で修正され、現在hw:1,2インターフェースはこのデフォルトドライバモードでビッグエンディアンとして報告されています。

例:

  • AoポートにS24_3BEエンコードされたRAWファイルを再生する:

    % aplay -D hw:1,0 -c2 -t raw -r48000 -fS24_3BE test.raw

  • AiポートからS24_3BEエンコードされたRAWファイルを録音する:

    % arecord -D hw:1,1 -c2  -t raw -r48000 -fS24_3BE test.raw

  • DoポートにS16_BEエンコードされたRAWファイルを再生する:

    % aplay -D hw:1,1 -c2 -t raw -r48000 -fS16_BE test.raw

  • DoポートにAC3サンプルファイルを再生する:

    % aplay -D hw:1,2 --channels=6 ac3_S16_BE_encoded_file.raw

デフォルトのAlsaドライバモードで問題がなければ、以下の章はスキップできます。

高度なモジュール設定¶

上記のハードウェア制約により、Alsaドライバのデフォルトモードでのデバイス初期化はデバイスの破損状態を引き起こす可能性があります。例えば、Aiインターフェースからキャプチャされた音声が歪んでいる（過度な高音量ゲインで増幅されたような）という問題があります。

snd-usb-audioモジュールには、新しいモジュールパラメータが追加されました。 device_setup (このパラメータはカーネルバージョン2.6.17で導入されました)

Audiophile USBの作動モードの初期化¶

Audiophile USBデバイスに関して、この値はユーザーに以下を指定可能にします:

  • サンプルビット深度

  • サンプルレート

  • Diポートの使用有無

初期化時に device_setup=0x00、snd-usb-audioモジュールはパラメータを省略した場合と同じ挙動をします（上記の「デフォルトAlsaドライバモード」参照）

他のモードについては以下のサブセクションで説明します。

16ビットモード¶

サポートされているモードは以下の通りです:

  • device_setup=0x01

    • Diが無効な16ビット48kHzモード

    • Ai,Ao,Doは同時に使用可能です

    • hw:1,0はキャプチャモードでは利用不可です

    • hw:1,2は利用不可です

  • device_setup=0x11

    • Diが有効な16ビット48kHzモード

    • Ai,Ao,Di,Doは同時に使用可能です

    • hw:1,0はキャプチャモードで利用可能です

    • hw:1,2は利用不可です

これらのモードではデバイスが16ビットモードのみで動作します。カーネル2.6.23以前では、デバイスがビッグエンディアンと報告されていましたが実際はリトルエンディアンでした。そのためファイルを再生するには以下のようでした:

% aplay -D hw:1,1 -c2 -t raw -r48000 -fS16_BE test_S16_LE.raw

ここで「test_S16_LE.raw」は実際にはリトルエンディアンのサンプルファイルでした。

Hakan Lennestal（このモードでのデバイスのリトルエンディアン性を発見した人物）により修正がコミットされました（カーネル2.6.23で導入予定）。Alsaは現在リトルエンディアンインターフェースを報告します。そのためファイルを再生するには以下のようにします:

% aplay -D hw:1,1 -c2 -t raw -r48000 -fS16_LE test_S16_LE.raw

24ビットモード¶

サポートされているモードは以下の通りです:

  • device_setup=0x09

    • Diが無効な24ビット48kHzモード

    • Ai,Ao,Doは同時に使用可能です

    • hw:1,0はキャプチャモードでは利用不可です

    • hw:1,2は利用不可です

  • device_setup=0x19

    • Diが有効な24ビット48kHzモード

    • Ai,Ao,Di,Doから3ポートを同時に使用可能です

    • hw:1,0はキャプチャモードで利用可能で、Diにアクティブなデジタルソースを接続する必要があります

    • hw:1,2は利用不可です

  • device_setup=0x0D または 0x10

    • 24ビット96kHzモード

    • このモードではDiがデフォルトで有効ですが、アクティブなソースに接続する必要はありません

    • Ai,Ao,Di,Doから1ポートのみを同時に使用可能です

    • hw:1,0はキャプチャモードで利用可能です

    • hw:1,2は利用不可です

これらのモードではデバイスがビッグエンディアン準拠となっています（詳細は上記の「デフォルトAlsaドライバモード」を参照し、aplayコマンドの例を確認してください）

AC3とDTSパストスルーモード¶

ハカン・レンネスタル氏のご協力により、このモードが動作することを示すレポートを入手しました。

  • device_setup=0x03

    • Doポートのみが有効な16ビット48kHzモード

    • AC3とDTSパストスルー

    • この設定ではDoポートがpcmデバイスhw:1,0にマッピングされています

このモードでAC3/DTS符号化された.wavファイルを再生するためのコマンドライン:

% aplay -D hw:1,0 --channels=6 ac3_S16_LE_encoded_file.raw

使用方法 device_setup パラメータ¶

パラメータは以下のように指定できます:

  • デバイスを手動でプローブする場合（root権限が必要）:

    # modprobe -r snd-usb-audio
# modprobe snd-usb-audio index=1 device_setup=0x09

  • もしくは、モジュール設定ファイル（通常は/etc/modprobe.d/ディレクトリ内の.confファイル）でモジュールオプションを設定する際:

    alias snd-card-1 snd-usb-audio
options snd-usb-audio index=1 device_setup=0x09

デバイスの初期化に関する注意¶

  • デバイスの正しい初期化には、デバイス起動前にdevice_setupをモジュールに指定する必要があります。手動プローブ方法を使用する場合は、初期化後にデバイスを電源投入してください。

  • この手順を無視するとデバイスの不正な設定が発生します。その場合、デバイスをオフにしてsnd-usb-audioモジュールをアンプローブし、正しいdevice_setupパラメータで再プローブした後、デバイスを再度オンにしてください。

  • デバイスを有効なモードで正しく初期化し、その後他のモード（別のサンプル深度を持つ場合も）に切り替える場合は、以下の手順も実施してください:

    • まずデバイスをオフにします

    • snd-usb-audioモジュールをデレジストレーションします（modprobe -r）

    • device_setupパラメータを変更するには、device_setupオプションを変更してください /etc/modprobe.d/*.conf

    • デバイスをオンにします

  • この最後の問題に対する回避策はカーネル2.6.23で導入されていますが、デバイス初期化の「安定性」を保証するには十分でない可能性があります。

技術的な詳細情報（ハッカー向け）¶

このセクションは、デバイスの内部構造やAlsaがどのようにサポートしているかを理解したいハッカー向けです。

オーディオフィル USBの device_setup 構造体¶

オーディオフィル USBのdevice_setupマジックナンバーを理解したい場合は、バイナリ計算の基本的な知識が必要です。ただし、パラメータを使用するには必要ありませんので、このセクションはスキップできます。

device_setupは1バイトの長さであり、構造は以下の通りです:

+---+---+---+---+---+---+---+---+
| b7| b6| b5| b4| b3| b2| b1| b0|
+---+---+---+---+---+---+---+---+
| 0 | 0 | 0 | Di|24B|96K|DTS|SET|
+---+---+---+---+---+---+---+---+

以下では:

  • b0は SET ビット

    • device_setupが初期化されている場合は必ず設定する必要があります

  • b1は DTS ビット

    • デジタル出力でDTS/AC3が使用されている場合にのみ設定されます

    • この設定はテストされていません

  • b2はレート選択フラグです

    • 設定されている場合 1 レート範囲は48.1〜96kHzです

    • それ以外の場合、サンプリング周波数範囲は8〜48kHzです

  • b3はビット深度選択フラグです

    • 設定されている場合 1 サンプルは24ビットです

    • それ以外の場合、16ビットです

    • b2がb3を意味する点に注意してください。96kHzモードは24ビットサンプル専用です。

  • b4はデジタル入力フラグです。

    • 設定されている場合 1 デバイスはアクティブなデジタルソースが接続されていると仮定しています。

    • ポートにソースが見られない場合はDiを有効にしないでください（これにより同期問題が発生します）。

    • b4はb2によって意味される（同時に有効なポートが1つしかないので同期エラーは発生しません）。

  • b5からb7は今後の使用のために予約されており、設定する必要があります。 0

    • b7、b6、b4それぞれに対応するAo、Do、Aiになる可能性があります。

注意:

  • device_setupに渡す値をチェックする仕組みはありません。

    • たとえば0x05（16ビット96kHz）を選択すると、b2がb3を意味するため、0x09に戻るが、/var/log/messagesには警告が表示されません。

  • USBバスの制限によるハードウェア制約はチェックされません。

    • b2を選択すると、すべてのインターフェースが24ビット/96kHzに準備されるが、同時に使用できるのは1つだけです。

このデバイスのUSB実装詳細¶

ドライバーハッキングに興味がない場合は、このセクションを無視してもかまいません。

このセクションではデバイスの内部構造について説明し、WindowsとLinuxドライバのusb-snoopingによって得たデータを要約しています。

M-Audio Audiophile USBは7つのUSBインターフェースを持っています：「USBインターフェース」：

  • USBインターフェース nb.0

  • USBインターフェース nb.1

    • オーディオ制御機能

  • USBインターフェース nb.2

    • アナログ出力

  • USBインターフェース nb.3

    • デジタル出力

  • USBインターフェース nb.4

    • アナログ入力

  • USBインターフェース nb.5

    • デジタル入力

  • USBインターフェース nb.6

    • MIDIMANのクイックに準拠したMIDIインターフェース

各インターフェースは5つのAltSetting（AltSet 1,2,3,4,5）を持ちますが、以下の例外があります：

  • インターフェース3（デジタル出力）はAlset nb.6が追加されています

  • インターフェース5（デジタル入力）はAlset nb.3と5を持ちません

AltSettingの機能についての簡単な説明は以下の通りです：

  • AltSetting 1は以下の通りです：

    • 24ビット深度、48.1〜96kHzサンプリングモード

    • 適応再生（AoとDo）、同期キャプチャ（Ai）、または非同期キャプチャ（Di）

  • AltSetting 2は以下の通りです：

    • 24ビット深度、8〜48kHzサンプリングモード

    • 非同期キャプチャと再生（Ao,Ai,Do,Di）

  • AltSetting 3は以下の通りです：

    • 24ビット深度、8〜48kHzサンプリングモード

    • 同期キャプチャ（Ai）と適応再生（Ao,Do）

  • AltSettings 4 は以下の設定に対応します

    • 16ビット深度、8〜48kHzのサンプリングモード

    • 非同期キャプチャと再生（Ao,Ai,Do,Di）

  • AltSettings 5 は以下の設定に対応します

    • 16ビット深度、8〜48kHzのサンプリングモード

    • 同期キャプチャ（Ai）と適応再生（Ao,Do）

  • AltSettings 6 は以下の設定に対応します

    • 16ビット深度、8〜48kHzのサンプリングモード

    • 同期再生（Do）、オーディオ形式タイプIII IEC1937_AC-3

デバイスの正しい初期化を確保するため、ドライバー grace periodsを尊重しなければなりませんし、 知っている デバイスがどのように使用されるか:

  • DTSを選択した場合、インターフェース2とAltSet nb.6のみを登録する必要があります

  • 96KHzの場合、各インターフェースのAltSet nb.1のみを選択する必要があります

  • サンプルが24ビット/48kHzを使用している場合、デジタル入力が接続されている場合はAltSet 2を使用し、デジタル入力が接続されていない場合はAltSet nb.3のみを使用する必要があります

  • サンプルが16ビット/48kHzを使用している場合、デジタル入力が接続されている場合はAltSet 4を使用し、デジタル入力が接続されていない場合はAltSet nb.5のみを使用する必要があります

snd-usb-audioモジュールにdevice_setupをパラメータとして指定した場合、parse_audio_endpoints関数はクイック（quirk）を呼び出して audiophile_skip_setting_quirk ドライバーにdevice_setupと一致しないAltSettingsが登録されないようにするため

オーディオフィル・USBとジャックのサポート¶

このセクションでは、オーディオフィル・USBデバイスのジャックでのサポートについて説明します

Jackdでデバイスを使用する際の2つの主な問題があります:

  • 24ビットモードでのビッグエンディアンデバイスのサポート

  • 4入力/4出力チャンネルのサポート

Jackdでの直接サポート¶

Jackは最近のバージョン（Andreas Steinmetz氏の最初のビッグエンディアンパッチのおかげ）でビッグエンディアンデバイスをサポートしています。このサポートがjackdに組み込まれた正確な時期は私には覚えていませんが、jackdバージョン0.103.0ではほぼ問題ありません（16ビットビッグエンディアンデバイスにわずかなバグが影響していますが、上記の段落を丁寧に読まれたため、現在はカーネル>= 2.6.23を使用しており、16ビットデバイスはリトルエンディアンになっています ;-））。

再生用Aoと録音用Aiを使用するためには、以下のコマンドでjackdを実行できます:

% jackd -R -dalsa -Phw:1,0 -r48000 -p128 -n2 -D -Chw:1,1

Alsa plughwを使用する¶

最近のJackdがインストールされていない場合、Alsaを使用して downgrade できます plug コンバーター。

例えば、以下はAoで2つの再生チャンネル、Aiから2つのキャプチャチャンネルでJackを実行する方法です:

% jackd -R -dalsa -dplughw:1 -r48000 -p256 -n2 -D -Cplughw:1,1
しかし、以下の警告メッセージが表示される可能性があります:

ALSAソフトウェア「plug」レイヤーを使用しているように見えます。これは「default」ALSAデバイスを使用している可能性があります。これは効率が低下しています。ハードウェアデバイスを使用する代わりにplugレイヤーを使用するのではなく、別のデバイスを使用することを検討してください。

ジャックでの2つの入力および/または出力インターフェースの取得¶

ご覧の通り、ジャックサーバーをこのように起動すると、1つのステレオ入力（DiまたはAi）と1つのステレオ出力（AoまたはDo）のみが有効になります。

これは以下の制限によります:

  • ジャックは一度に1つのキャプチャデバイスと1つの再生デバイスのみを開くことができます

  • Audiophile USBは2台（または3台）のAlsaデバイスとして認識されます: hw:1,0, hw:1,1（オプションでhw:1,2）

JackでAi+Diおよび/またはAo+Doのサポートを得たい場合は、Alsaデバイスを1つの論理的な「複合」デバイスに統合する必要があります。

試してみたい場合は、このページの情報を確認することをお勧めします: http://www.sound-man.co.uk/linuxaudio/ice1712multi.html これは別のデバイス（ice1712）に関連していますが、Audiophile USBに合わせて調整可能です。

Jackdで複数のAudiophile USBインターフェースを有効にするには、以下が必要です:

  • JackdのバージョンにMMAP_COMPLEXパッチが適用されていることを確認（ice1712ページを参照）

  • （おそらく）alsa-lib/src/pcm/pcm_multi.cファイルのパッチ適用（ice1712ページを参照）

  • .asoundrcファイルで複数デバイス（hw:1,0とhw:1,1の組み合わせ）を定義する

  • このデバイスでjackdを起動する

現在この設定でテストに成功していません。このような設定で成功した場合は、メールでお知らせください。
