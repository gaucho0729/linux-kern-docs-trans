ダイナミックPCM¶

説明¶

Dynamic PCM は、ALSA PCM デバイスが PCM ストリームの実行中にデジタル的にさまざまなデジタルエンドポイントにオーディオをルーティングできるようにします。例: PCM0 は I2S DAI0、I2S DAI1、または PDM DAI2 にデジタルオーディオをルーティングできます。これは、複数の ALSA PCM を公開し、複数の DAI にルーティング可能な SoC DSP ドライバで特に役立ちます。

DPCM の実行時ルーティングは、ASoC コードックドライバでアナログ信号がルーティングされるのと同じように、ALSA ミキサー設定によって決定されます。DPCM は DSP 内部のオーディオパスを表す DAPM グラフを使用し、ミキサー設定に基づいて各 ALSA PCM が使用するパスを決定します。

DPCM は、既存のコンポーネントコードック、プラットフォーム、DAI ドライバーを再利用し、変更は不要です。

SoC ベースの DSP を搭載した電話オーディオシステム¶

以下の電話オーディオサブシステムを考慮してください。このドキュメント内のすべての例で使用します :-

| Front End PCMs    |  SoC DSP  | Back End DAIs | Audio devices |

                    *************
PCM0 <------------> *           * <----DAI0-----> Codec Headset
                    *           *
PCM1 <------------> *           * <----DAI1-----> Codec Speakers
                    *   DSP     *
PCM2 <------------> *           * <----DAI2-----> MODEM
                    *           *
PCM3 <------------> *           * <----DAI3-----> BT
                    *           *
                    *           * <----DAI4-----> DMIC
                    *           *
                    *           * <----DAI5-----> FM
                    *************

このダイアグラムは、シンプルなスマートフォンオーディオサブシステムを示しています。Bluetooth、FM デジタルラジオ、スピーカー、ヘッドセットジャック、デジタルマイク、セルラーモデムをサポートしています。このサウンドカードは 4 つの DSP フロントエンド（FE）ALSA PCM デバイスを露出し、6 つのバックエンド（BE）DAI をサポートします。各 FE PCM は、任意の BE DAI にデジタル的にオーディオデータをルーティングできます。FE PCM デバイスは、複数の BE DAI にオーディオをルーティングすることもできます。

例 - DAI0 から DAI1 への DPCM プレイバックの切り替え¶

オーディオがヘッドセットに再生されています。しばらくしてユーザーがヘッドセットを外した後もオーディオはスピーカーで再生されます。

PCM0 でのヘッドセットへのプレイバックは以下のようになります :-

                    *************
PCM0 <============> *           * <====DAI0=====> Codec Headset
                    *           *
PCM1 <------------> *           * <----DAI1-----> Codec Speakers
                    *   DSP     *
PCM2 <------------> *           * <----DAI2-----> MODEM
                    *           *
PCM3 <------------> *           * <----DAI3-----> BT
                    *           *
                    *           * <----DAI4-----> DMIC
                    *           *
                    *           * <----DAI5-----> FM
                    *************

ユーザーがジャックからヘッドセットを外したため、スピーカーを使用する必要があります :-

                    *************
PCM0 <============> *           * <----DAI0-----> Codec Headset
                    *           *
PCM1 <------------> *           * <====DAI1=====> Codec Speakers
                    *   DSP     *
PCM2 <------------> *           * <----DAI2-----> MODEM
                    *           *
PCM3 <------------> *           * <----DAI3-----> BT
                    *           *
                    *           * <----DAI4-----> DMIC
                    *           *
                    *           * <----DAI5-----> FM
                    *************

オーディオドライバーは以下のよう処理します :-

  1. マシンドライバーがジャックの除去イベントを受信します。

  2. マシンドライバーまたはオーディオ HAL がヘッドセットパスを無効化します。

  3. パスが無効になったため、ヘッドセット用の DAI0 で PCM トリガー（停止）、hw_free()、shutdown() 操作を実行します。

  4. マシンドライバーまたはオーディオ HAL がスピーカーパスを有効化します。

  5. パスが有効になったため、スピーカー用の DAI1 で PCM 操作（startup()、hw_params()、prepare()、trigger(start)）を実行します。

この例では、マシンドライバーまたはユーザースペースオーディオ HAL がルーティングを変更し、DPCM が DAI PCM 操作を管理してリンクを上げ下げします。オーディオ再生はこの移行中に停止しません。

DPCM マシンドライバー¶

DPCM を有効化した ASoC マシンドライバーは、通常のマシンドライバーと同様ですが、以下のような追加の作業が必要です :-

  1. FE と BE DAI リンクを定義する。

  2. FE/BE PCM 操作を定義する。

  3. ウィジェットグラフの接続を定義する。

FE と BE DAI リンク¶

| Front End PCMs    |  SoC DSP  | Back End DAIs | Audio devices |

                    *************
PCM0 <------------> *           * <----DAI0-----> Codec Headset
                    *           *
PCM1 <------------> *           * <----DAI1-----> Codec Speakers
                    *   DSP     *
PCM2 <------------> *           * <----DAI2-----> MODEM
                    *           *
PCM3 <------------> *           * <----DAI3-----> BT
                    *           *
                    *           * <----DAI4-----> DMIC
                    *           *
                    *           * <----DAI5-----> FM
                    *************

上記の例では、4つのFE DAIリンクと6つのBE DAIリンクを定義する必要があります。FE DAIリンクは以下のようになります :-

static struct snd_soc_dai_link machine_dais[] = {
      {
              .name = "PCM0 System",
              .stream_name = "System Playback",
              .cpu_dai_name = "System Pin",
              .platform_name = "dsp-audio",
              .codec_name = "snd-soc-dummy",
              .codec_dai_name = "snd-soc-dummy-dai",
              .dynamic = 1,
              .trigger = {SND_SOC_DPCM_TRIGGER_POST, SND_SOC_DPCM_TRIGGER_POST},
              .dpcm_playback = 1,
      },
      .....< other FE and BE DAI links here >
};

このFE DAIリンクは、通常のDAIリンクとほぼ同じですが、DAIリンクをDPCM FEに設定し、 dynamic = 1フラグでサポートされるFEストリーム方向も設定する必要があります。また、各FEごとのトリガー呼び出しの順序を指定するオプションもあります。これにより、ASoCコアがDSPを他のコンポーネントよりも前にまたは後にトリガーできるようになり、一部のDSPではDAI/DSPの開始および停止シーケンスの順序に強い制約があるためです。 dpcm_playback および dpcm_capture 上記のFE DAIは、BEが動的でランタイム設定に応じて変化するため、コーデックとコードDAIをダミーデバイスに設定しています。

BE DAIは以下のようになります :-

このBE DAIリンクはDAI0をコーデック（この場合RT5460 AIF1）に接続し、

static struct snd_soc_dai_link machine_dais[] = {
      .....< FE DAI links here >
      {
              .name = "Codec Headset",
              .cpu_dai_name = "ssp-dai.0",
              .platform_name = "snd-soc-dummy",
              .no_pcm = 1,
              .codec_name = "rt5640.0-001c",
              .codec_dai_name = "rt5640-aif1",
              .ignore_suspend = 1,
              .ignore_pmdown_time = 1,
              .be_hw_params_fixup = hswult_ssp0_fixup,
              .ops = &haswell_ops,
              .dpcm_playback = 1,
              .dpcm_capture = 1,
      },
      .....< other BE DAI links here >
};

フラグでBEであることを示し、サポートされるストリーム方向のフラグを no_pcm で設定します。BEには、スリープやPMダウンタイムを無視するフラグも設定されており、ホストレスモードで動作させることができます。ホストCPUがデータを転送しない状態（例：Bluetooth電話通話）で動作します :- dpcm_playback および dpcm_capture 上記。

これにより、ホストCPUがスリープ状態でも、DSP、MODEM DAI、BT DAIが動作し続けることができます。

                    *************
PCM0 <------------> *           * <----DAI0-----> Codec Headset
                    *           *
PCM1 <------------> *           * <----DAI1-----> Codec Speakers
                    *   DSP     *
PCM2 <------------> *           * <====DAI2=====> MODEM
                    *           *
PCM3 <------------> *           * <====DAI3=====> BT
                    *           *
                    *           * <----DAI4-----> DMIC
                    *           *
                    *           * <----DAI5-----> FM
                    *************

BE DAIリンクは、コーデックが外部で管理されるデバイスである場合、コーデックをダミーデバイスに設定することもできます。

同様に、CPU DAIがDSPファームウェアで管理される場合、BE DAIはCPU DAIをダミーデバイスに設定することもできます。

FE/BE PCM操作

上記のBEは、いくつかのPCM操作と¶

コールバックをエクスポートします。fixupコールバックは、マシンドライバがFE hwパラメータに基づいてDAIを（再）設定する際に使用されます。つまり、DSPはFEからBEへSRCまたはASRCを実行する可能性があります。 fixup 例えば、DSPはFE hwパラメータをすべて48kHz、16bit、ステレオで固定してDAI0を動作させます。これにより、DAI0のマシンドライバでFE hwパラメータを固定しなければ、DAIが望ましい設定で動作しない可能性があります。

他のPCM操作は通常のDAIリンクと同じです。必要に応じて使用してください。

static int dai0_fixup(struct snd_soc_pcm_runtime *rtd,
                      struct snd_pcm_hw_params *params)
{
      struct snd_interval *rate = hw_param_interval(params,
                      SNDRV_PCM_HW_PARAM_RATE);
      struct snd_interval *channels = hw_param_interval(params,
                                              SNDRV_PCM_HW_PARAM_CHANNELS);

      /* The DSP will convert the FE rate to 48k, stereo */
      rate->min = rate->max = 48000;
      channels->min = channels->max = 2;

      /* set DAI0 to 16 bit */
      params_set_format(params, SNDRV_PCM_FORMAT_S16_LE);
      return 0;
}

ウィジェットグラフ接続

BE DAIリンクは通常、ASoC DAPMコアが初期化時にグラフに接続します。ただし、BEコーデックまたはBE DAIがダミーの場合は、ドライバで明示的に設定する必要があります :-¶

DPCM DSPドライバの作成

/* BE for codec Headset -  DAI0 is dummy and managed by DSP FW */
{"DAI0 CODEC IN", NULL, "AIF1 Capture"},
{"AIF1 Playback", NULL, "DAI0 CODEC OUT"},

DPCM DSPドライバは、標準のプラットフォームクラスASoCドライバとコードッククラスドライバの要素を組み合わせたものに見えます。DSPプラットフォームドライバは以下のものを実装する必要があります :-¶

Front End PCM DAI - つまり、struct snd_soc_dai_driver。

  1. DAAPMグラフでFE DAIからBEへのDSPオーディオルーティングを示す。

  2. DSPグラフからのDAPMウィジェット。

  3. DAPMウィジェットからDSPグラフ

  4. ゲインやルーティングなどに使用するミキサー

  5. DMAの設定。

  6. BE AIFウィジェット。

項目6はDSPの外側でオーディオをルーティングするために重要です。BEごとにそれぞれのストリーム方向に対してAIFを定義する必要があります。例えばBE DAI0の上記では以下のようにします:-

SND_SOC_DAPM_AIF_IN("DAI0 RX", NULL, 0, SND_SOC_NOPM, 0, 0),
SND_SOC_DAPM_AIF_OUT("DAI0 TX", NULL, 0, SND_SOC_NOPM, 0, 0),

BE AIFはDSPグラフを他のコンポーネントドライバ（例：コーデックグラフ）のグラフに接続するために使用されます。

ホストレスPCMストリーム¶

ホストレスPCMストリームとは、ホストCPUを経由せずにルーティングされるストリームです。電話機からモジュールへの通話がその例です。

                    *************
PCM0 <------------> *           * <----DAI0-----> Codec Headset
                    *           *
PCM1 <------------> *           * <====DAI1=====> Codec Speakers/Mic
                    *   DSP     *
PCM2 <------------> *           * <====DAI2=====> MODEM
                    *           *
PCM3 <------------> *           * <----DAI3-----> BT
                    *           *
                    *           * <----DAI4-----> DMIC
                    *           *
                    *           * <----DAI5-----> FM
                    *************

この場合、PCMデータはDSPを経由してルーティングされます。この使用ケースではホストCPUは制御のみを行い、ストリームの実行中にスリープ状態にすることができます。

ホストはホストレスリンクを以下のように制御できます:-

  1. リンクをCODEC <-> CODECスタイルのリンクとして設定する。この場合、リンクの有効/無効はDAPMグラフの状態によって制御されます。通常これはDAI間のパスを接続または切断するためにミキサー制御を用いることを意味します。

  2. ホストレスFE。このFEはDAPMグラフ上のBE DAIリンクに仮想的な接続を持ち、制御は通常のPCM操作としてFEによって行われます。この方法はDAIリンクに対するより多くの制御を提供しますが、リンクを制御するためのユーザー空間コードが大幅に必要になります。CODEC<->CODECを用いることを推奨します。ただしハードウェアでPCM操作のより細かいシーケンシングが必要な場合は例外です。

CODEC <-> CODEC リンク¶

このDAIリンクはDAPMがDAPMグラフ内で有効なパスを検出するときに有効になります。マシンドライバはDAIリンクに追加のパラメータを設定します。つまり、

static const struct snd_soc_pcm_stream dai_params = {
      .formats = SNDRV_PCM_FMTBIT_S32_LE,
      .rate_min = 8000,
      .rate_max = 8000,
      .channels_min = 2,
      .channels_max = 2,
};

static struct snd_soc_dai_link dais[] = {
      < ... more DAI links above ... >
      {
              .name = "MODEM",
              .stream_name = "MODEM",
              .cpu_dai_name = "dai2",
              .codec_dai_name = "modem-aif1",
              .codec_name = "modem",
              .dai_fmt = SND_SOC_DAIFMT_I2S | SND_SOC_DAIFMT_NB_NF
                              | SND_SOC_DAIFMT_CBM_CFM,
              .params = &dai_params,
      }
      < ... more DAI links here ... >

これらのパラメータはDAPMが有効なパスを検出するとDAI hw_params()を設定するために使用され、その後PCM操作を呼び出してリンクを開始します。DAPMはパスがもはや有効でなくなったときにDAIを無効にする適切なPCM操作を呼び出します。

ホストレスFE¶

DAIリンク（複数可）はPCMデータを読み書きしないFEによって有効になります。これは新しいFEを両DAIリンクに仮想パスで接続した構造になります。DAIリンクはFE PCMが開始されるときに開始され、FE PCMが停止するときに停止します。注意点として、この構成ではFE PCMはデータを読み書きできません。
