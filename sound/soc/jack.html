ASoC ジャック検出¶

ALSA はユーザー空間に物理ジャックを表現するための標準 API を提供しており、カーネル側の実装は include/sound/jack.h に記載されています。ASoC はこの API の拡張版を提供し、2つの追加機能を備えています:

  • 複数のジャック検出メソッドが1つのユーザー可視のジャックで同時に動作するようにします。埋め込みシステムでは、単一のジャックに複数の検出メソッドが存在し、それぞれ異なるハードウェアで処理されることが一般的です。

  • DAPM との統合により、検出されたジャック状態に基づき DAPM エンドポイントを自動的に更新できます（例: ヘッドホンが接続されていない場合、ヘッドホン出力をオフにする）。

これはジャックを3つの要素に分けて動作させることで実現されます：ジャック自体は struct snd_soc_jack で表され、DAPM エンドポイントを更新するための snd_soc_jack_pins のセット、およびジャックレポートメカニズムを提供するコードブロック。

たとえば、システムはステレオヘッドセットジャックを備え、ヘッドホン用とマイクロフォン用の2つのレポートメカニズムを持つ場合があります。一部のシステムではヘッドホンが接続されている間スピーカー出力が使用できないため、ジャック状態が変化するたびにスピーカーとヘッドホンの両方を更新する必要があります。

ジャック - struct snd_soc_jack¶

これはシステム上の物理ジャックを表し、ユーザー空間に見えるものです。ジャック自体は完全に被動的であり、マシンドライバによって設定され、ジャック検出メソッドによって更新されます。

ジャックはマシンドライバが snd_soc_jack_new() を呼び出すことで作成されます。

snd_soc_jack_pin¶

これはジャックの状態に応じて更新される DAPM ピンを表し、ジャックのサポートする一部のステータスビットに基づいています。各 snd_soc_jack はゼロ個以上のこれらを備え、自動的に更新されます。これらはマシンドライバによって作成され、jack と関連付けられます。 snd_soc_jack_add_pins()エンドポイントのステータスは必要に応じてジャックステータスの逆になるように設定できます（例: ジャックでマイクロフォンが接続されていない場合、内蔵マイクロフォンを有効にする）。

ジャック検出方法¶

実際のジャック検出は、システムの入力状態を監視し、ジャックを更新するために snd_soc_jack_report() を呼び出すコードによって行われます。 snd_soc_jack_report()特定のビットのサブセットを更新するように指定します。ジャック検出コードはマシンドライバによって設定され、ジャックの更新設定とジャック接続時に報告すべき項目を指定します。

これは通常 GPIO の状態に基づいて行われます。このハンドラは snd_soc_jack_add_gpio() 関数で提供されます。他にも方法が利用可能で、たとえば CODEC に統合されている場合があります。CODEC に統合されたジャック検出の例は WM8350 ドライバで確認できます。

ジャックには複数の検出メカニズムを持つ場合がありますが、少なくとも1つは必要でなければ役立ちません。

マシンドライバ¶

これらはすべて機械ドライバーがシステムハードウェアに応じてつながり、機械ドライバーはsnd_soc_jackと更新するピンの一覧を設定した後、そのジャックの現在の状態に基づいて1つまたは複数のジャック検出メカニズムを設定します。
