ポータブルデバイス用ダイナミックオーディオ電源管理¶

説明¶

ダイナミックオーディオ電源管理（DAPM）は、ポータブルLinuxデバイスがオーディオサブシステム内で常に最小限の電力を消費できるように設計されています。これは他のカーネル電源管理（PM）と独立しており、他のPMシステムと簡単に共存可能です。

DAPMはすべてのユーザー空間アプリケーションにとって完全に透過的です。すべての電源スイッチングはASoCコア内で行われるため、ユーザー空間アプリケーションにはコード変更や再コンパイルは必要ありません。DAPMは、デバイス内のオーディオストリーム（キャプチャ/プレイバック）の活動やオーディオミキサー設定に基づいて電源スイッチングの決定を行います。

DAPMは全体のマシンをカバーしており、オーディオサブシステム全体の電源制御を含みます。これは内部コーデック電源ブロックとマシンレベルの電源システムも含まれます。

DAPMには4つの電源ドメインがあります

コーデックバイアスドメイン

VREF、VMID（コアコーデックおよびオーディオ電源）

通常はコーデックプローブ/リムーブおよびスリープ/リザーブ時に制御されますが、サイドトーンなど電源が不要な場合、ストリームタイムに設定することも可能です。

プラットフォーム/マシンドメイン

物理的に接続された入力および出力

プラットフォーム/マシンおよびユーザー操作に依存し、マシンドライバーによって設定され、非同期イベント（例：ホストポートの挿入時）に応じて反応します。

パスドメイン

オーディオサブシステムの信号パス

ユーザーがミキサーおよびMUX設定を変更するときに自動的に設定されます。例：alsamixer、amixer。

ストリームドメイン

DACおよびADC。

ストリームのプレイバック/キャプチャが開始・停止されるときに有効/無効になります。例：aplay、arecord。

すべてのDAPM電源スイッチングの決定は、マシン全体のオーディオルーティングマップを参照して自動的に行われます。このマップは各マシン固有であり、すべてのオーディオコンポーネント（内部コーデックコンポーネントを含む）間の接続を表します。すべての電源に影響を与えるオーディオコンポーネントはここではウィジェットと呼ばれます。

DAPMウィジェット¶

オーディオDAPMウィジェットはいくつかのタイプに分類されます：-

ミキサー

複数のアナログ信号を単一のアナログ信号にまとめます。

MUX

複数の入力の中から1つだけ出力するアナログスイッチ。

PGA

プログラマブルゲインアンプまたは減衰ウィジェット。

ADC

アナログからデジタルへのコンバーター

DAC

デジタルからアナログへのコンバーター

スイッチ

アナログスイッチ

入力

コーデック入力ピン

出力

コーデック出力ピン

ヘッドホン

ヘッドホン（オプションでジャック）

マイク

マイク（オプションでジャック）

ライン

ライン入力/出力（オプションでジャック）

スピーカー

スピーカー

サプライ

他のウィジェットに使用される電源またはクロックサプライウィジェット。

レギュレータ

オーディオコンポーネントに電源を供給する外部レギュレータ。

クロック

オーディオコンポーネントにクロックを供給する外部クロック。

AIF IN

オーディオインターフェース入力（TDMスロットマスク付き）。

AIF OUT

オーディオインターフェース出力（TDMスロットマスク付き）。

Siggen

信号生成器。

DAI IN

デジタルオーディオインターフェース入力。

DAI OUT

デジタルオーディオインターフェース出力。

DAI リンク

2つのDAI構造体間のDAIリンク

Pre

特殊なPREウィジェット（他のすべてのウィジェットよりも先に実行）

Post

特殊なPOSTウィジェット（他のすべてのウィジェットよりも後に実行）

バッファ

DSP内のウィジェット間オーディオデータバッファ。

スケジューラ

DSP内部スケジューラ（コンポーネント/パイプライン処理のスケジューリング）。

効果

オーディオ処理効果を実行するウィジェット。

SRC

DSPまたはCODEC内のサンプルレートコンバーター

ASRC

DSPまたはCODEC内のアシンクロナスサンプルレートコンバーター

エンコーダー

1形式（通常PCM）から別の通常より圧縮された形式へのオーディオデータの符号化を行うウィジェット。

デコーダー

圧縮形式から非圧縮形式（例：PCM）へのオーディオデータの復号を行うウィジェット。

(ウィジェットは include/sound/soc-dapm.h で定義されています)

ウィジェットは、コンポーネントドライバータイプのいずれかを使用してサウンドカードに追加できます。soc-dapm.h に定義されたユーティリティマクロを使用して、コーデックおよびマシンDAPMウィジェットのウィジェットリストを簡単に構築できます。

ほとんどのウィジェットには名前、レジスタ、シフト、インバートがあります。一部のウィジェットにはストリーム名とkcontrols用の追加パラメータがあります。

ストリームドメインウィジェット¶

ストリームウィジェットはストリーム電源ドメインに関連し、ADC（アナログからデジタル変換器）、DAC（デジタルからアナログ変換器）、AIF IN、AIF OUTのみで構成されます。

ストリームウィジェットの形式は以下の通りです：

SND_SOC_DAPM_DAC(name, stream name, reg, shift, invert),
SND_SOC_DAPM_AIF_IN(name, stream, slot, reg, shift, invert)

注意：ストリーム名は、あなたのコーデック snd_soc_codec_dai における対応するストリーム名と一致する必要があります。

例：ハイファイ再生およびキャプチャ用のストリームウィジェット

SND_SOC_DAPM_DAC("HiFi DAC", "HiFi Playback", REG, 3, 1),
SND_SOC_DAPM_ADC("HiFi ADC", "HiFi Capture", REG, 2, 1),

例：AIF用のストリームウィジェット

SND_SOC_DAPM_AIF_IN("AIF1RX", "AIF1 Playback", 0, SND_SOC_NOPM, 0, 0),
SND_SOC_DAPM_AIF_OUT("AIF1TX", "AIF1 Capture", 0, SND_SOC_NOPM, 0, 0),

パスドメインウィジェット¶

パスドメインウィジェットは、オーディオサブシステム内のオーディオ信号またはオーディオパスを制御または影響を与える機能を持っています。以下の形式です：

SND_SOC_DAPM_PGA(name, reg, shift, invert, controls, num_controls)

任意のウィジェットkcontrolsは、controlsとnum_controlsメンバを使用して設定できます。

例：ミキサー・ウィジェット（kcontrolsは最初に宣言されます）

/* Output Mixer */
static const snd_kcontrol_new_t wm8731_output_mixer_controls[] = {
SOC_DAPM_SINGLE("Line Bypass Switch", WM8731_APANA, 3, 1, 0),
SOC_DAPM_SINGLE("Mic Sidetone Switch", WM8731_APANA, 5, 1, 0),
SOC_DAPM_SINGLE("HiFi Playback Switch", WM8731_APANA, 4, 1, 0),
};

SND_SOC_DAPM_MIXER("Output Mixer", WM8731_PWR, 4, 1, wm8731_output_mixer_controls,
      ARRAY_SIZE(wm8731_output_mixer_controls)),

ミキサー要素がミキサー・ウィジェットの名前で前接しない場合、SND_SOC_DAPM_MIXER_NAMED_CTLを使用できます。パラメータはSND_SOC_DAPM_MIXERと同じです。

マシンドメイン・ウィジェット¶

マシン・ウィジェットは、コードック・ウィジェットとは異なり、コードックのレジスタビットと関連付けられていません。マシン・ウィジェットは、独立して電源を供給できるマシン音声コンポーネント（コードックやDSP以外）ごとに割り当てられます。例:

  • スピーカー・アンプ

  • マイクロホン・バイアス

  • ジャックコネクタ

マシン・ウィジェットにはオプションのコールバックを設定できます。

例: 外部マイクロホン用のジャックコネクタ・ウィジェットで、マイクロホンが挿さったときにマイクロホン・バイアスを有効にする場合:-:

static int spitz_mic_bias(struct snd_soc_dapm_widget* w, int event)
{
      gpio_set_value(SPITZ_GPIO_MIC_BIAS, SND_SOC_DAPM_EVENT_ON(event));
      return 0;
}

SND_SOC_DAPM_MIC("Mic Jack", spitz_mic_bias),

コードック（BIAS）ドメイン¶

コードック・バイアス電源ドメインにはウィジェットが存在せず、コードックのDAPMイベントハンドラによって処理されます。このハンドラは、コードックの電源状態がストリームイベントやカーネルPMイベントに関連して変化したときに呼び出されます。

仮想ウィジェット¶

コードックまたはマシン音声マップに存在するが、ソフトウェア電源制御に該当するウィジェットが存在しない場合があります。その場合は、仮想ウィジェット（制御ビットを持たないウィジェット）を作成する必要があります。例:

SND_SOC_DAPM_MIXER("AC97 Mixer", SND_SOC_DAPM_NOPM, 0, 0, NULL, 0),

これは、ソフトウェアで複数の信号パスを統合するために使用できます。

すべてのウィジェットが定義された後、DAPMサブシステムに個別に追加するために、次の関数呼び出しを使用できます。 snd_soc_dapm_new_control().

コードック/DSPウィジェットの相互接続¶

ウィジェットは、コードック、プラットフォーム、マシン内でオーディオパス（相互接続と呼ばれます）によって接続されます。各相互接続を定義する必要がありますが、ウィジェット間のすべてのオーディオパスのマップを作成するために必要です。

これは、コードックまたはDSP（およびマシン音声システムの回路図）のダイアグラムで最も簡単です。これは、ウィジェットをオーディオ信号パスを通じて結合する必要があるためです。

例: WM8731出力ミキサー（wm8731.c）

WM8731出力ミキサーには3つの入力（ソース）があります

  1. ラインバイパス入力

  2. DAC（HiFi再生）

  3. マイクロホンサイドトーン入力

この例の各入力には、kcontrolが関連付けられています（上記の例で定義されています）し、kcontrol名を通じて出力ミキサーに接続されています。これにより、音声信号の宛先ウィジェットをソースウィジェットと接続できます。

/* output mixer */
{"Output Mixer", "Line Bypass Switch", "Line Input"},
{"Output Mixer", "HiFi Playback Switch", "DAC"},
{"Output Mixer", "Mic Sidetone Switch", "Mic Bias"},

したがって、次のようになります:-

  • 宛先ウィジェット <=== パス名 <=== ソースウィジェット、または

  • シンク、パス、ソース、または

  • Output Mixer は「via the」 DAC で接続されています HiFi Playback Switch.

ウィジェット間のパス名が存在しない場合（例: 直接接続）は、パス名にNULLを渡します。

相互接続は次の関数呼び出しで作成されます:-

snd_soc_dapm_connect_input(codec, sink, path, source);

最後に、snd_soc_dapm_new_widgets(codec)は、すべてのウィジェットおよび接続がコアに登録された後に呼び出さなければなりません。これにより、コアがコーデックおよびマシンをスキャンし、内部DAPM状態が機械の物理的な状態と一致するようにします。

マシンウィジェット接続¶

マシンウィジェット接続は、コーデックのそれと同様の方法で作成され、直接コーデックピンをマシンレベルのウィジェットに接続します。

例：スピーカーオートのコーデックピンを内部スピーカーに接続します。

/* ext speaker connected to codec pins LOUT2, ROUT2  */
{"Ext Spk", NULL , "ROUT2"},
{"Ext Spk", NULL , "LOUT2"},

これにより、DAPMは接続（および使用中）されているピンとNC（未接続）のピンをそれぞれオン/オフするようになります。

エンドポイントウィジェット¶

エンドポイントは、機械内のオーディオ信号の開始または終点（ウィジェット）であり、コーデックを含みます。例：

  • ヘッドホンジャック

  • 内部スピーカー

  • 内部マイク

  • マイクジャック

  • コーデックピン

エンドポイントはDAPMグラフに追加され、電力消費を抑えるためにその使用状況が判定されます。例：NCのコーデックピンはオフにされ、未接続のジャックもオフにできます。

DAPMウィジェットイベント¶

一部のウィジェットは、PMイベントでDAPMコアに興味を登録できます。例：アンプを備えたスピーカーは、スピーカーが使用されるときにのみアンプを電源を入れるためにウィジェットを登録します。

/* turn speaker amplifier on/off depending on use */
static int corgi_amp_event(struct snd_soc_dapm_widget *w, int event)
{
      gpio_set_value(CORGI_GPIO_APM_ON, SND_SOC_DAPM_EVENT_ON(event));
      return 0;
}

/* corgi machine dapm widgets */
static const struct snd_soc_dapm_widget wm8731_dapm_widgets =
      SND_SOC_DAPM_SPK("Ext Spk", corgi_amp_event);

すべてのイベントをサポートする他のウィジェットについては、soc-dapm.hをご参照ください。

イベントタイプ¶

イベントウィジェットがサポートするイベントタイプは以下の通りです。

/* dapm event types */
#define SND_SOC_DAPM_PRE_PMU  0x1     /* before widget power up */
#define SND_SOC_DAPM_POST_PMU 0x2             /* after widget power up */
#define SND_SOC_DAPM_PRE_PMD  0x4     /* before widget power down */
#define SND_SOC_DAPM_POST_PMD 0x8             /* after widget power down */
#define SND_SOC_DAPM_PRE_REG  0x10    /* before audio path setup */
#define SND_SOC_DAPM_POST_REG 0x20    /* after audio path setup */
