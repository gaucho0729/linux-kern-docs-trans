Advanced Linux Sound Architecture - ドライバ設定ガイド¶

カーネルの設定¶

ALSAのサポートを有効にするには、少なくともプライマリサウンドカードのサポートを含むカーネルをビルドする必要があります（CONFIG_SOUND）。ALSAはOSSをエミュレートできるため、OSSモジュールのいずれかを選択する必要はありません。

「OSS APIエミュレーション」（CONFIG_SND_OSSEMUL）を有効にし、OSSミキサーおよびPCMのサポートも有効にすると、ALSAでOSSアプリケーションを実行できます。

SB Live!などのカードでWaveTable機能をサポートする場合は、「Sequencerサポート」（CONFIG_SND_SEQUENCER).

）を有効にします。ALSAのデバッグメッセージをより詳細にするには、「Verbose printk」および「Debug」オプションを有効にします。メモリリークの検出には「Debug memory」も有効にしてください。「Debug detection」はカードの検出を確認するチェックを追加します。

すべてのALSA ISAドライバがLinux isapnp API（カードがISA PnPをサポートする場合）をサポートしていることにご注意ください。isapnptoolsでカードを設定する必要はありません。

モジュールパラメータ¶

ユーザーはオプションとともにモジュールをロードできます。モジュールが複数のカードをサポートし、同じタイプのカードが複数ある場合、オプションにコンマで区切った複数の値を指定できます。

Module snd¶

コアALSAモジュール。すべてのALSAカードドライバがこのモジュールを使用します。以下のオプションはグローバルな効果を持ちます。

major

サウンドドライバのメジャーバージョン番号; デフォルト: 116

cards_limit

自動ロード時のカードインデックスの上限 (1-8); デフォルト: 1; 複数のカードを自動ロードする場合、このオプションを snd-card-X アリヤスとともに指定してください。

slots

指定されたドライバ用のスロットインデックスを確保します; このオプションは複数の文字列を受け取ります。詳しくは Module Autoloading Support セクションをご参照ください。

debug

デバッグメッセージのレベルを指定します; (0 = デバッグ出力無効, 1 = 通常のデバッグメッセージ, 2 = 詳細なデバッグメッセージ); このオプションは CONFIG_SND_DEBUG=y。このオプションは sysfs の /sys/modules/snd/parameters/debug ファイルを介して動的に変更できます。

Module snd-pcm-oss¶

PCM OSS エミュレーションモジュール。このモジュールはデバイスのマッピングを変更するオプションを受け取ります。

dsp_map

1番目のOSSデバイスに割り当てられるPCMデバイス番号のマッピング; デフォルト: 0

adsp_map

2番目のOSSデバイスに割り当てられるPCMデバイス番号のマッピング; デフォルト: 1

nonblock_open

ビジーなPCMデバイスを開くのをブロックしない; デフォルト: 1

たとえば、 dsp_map=2の場合、/dev/dsp はカード #0 の PCM #2 にマッピングされます。同様に、 adsp_map=0の場合、/dev/adsp はカード #0 の PCM #0 にマッピングされます。2番目以降のカードを変更する場合、コンマで区切ってこのオプションを指定します、たとえば dsp_map=0,1.

nonblock_open optionはPCMデバイスを開く動作の挙動を変更します。このオプションがゼロでない場合、忙しいOSS PCMデバイスを開こうとしてもブロックされず、すぐにEAGAINで返します（O_NONBLOCKフラグと同様の動作）。

上位サウンドカードモジュールの共通パラメータ¶

上位レベルのサウンドカードモジュールは以下のオプションをサポートします。

index

サウンドカードのインデックス (スロット番号); 値: 0から31までの数値または負数; 非負数の場合そのインデックス番号を割り当て、負数の場合許可されるインデックス番号のビットマスクと解釈し、最初の空きインデックスを割り当てます; デフォルト: -1

id

カードID (識別子または名前); 最大15文字まで; デフォルト: カードタイプ; この名前のディレクトリが/proc/asound/下に作成され、カードに関する情報を含みます; このIDはインデックス番号の代わりにカードを特定するために使用できます

enable

カードを有効にする; デフォルト: 有効 (PCIおよびISA PnPカード)

モジュール snd-adlib¶

AdLib FMカード用のモジュール。

port

OPLチップのポート番号

このモジュールは複数のカードをサポートしていますが、自動プローブをサポートしていませんのでポート番号を明示的に指定する必要があります。実際のAdLib FMカードでは0x388を使用します。注意: このカードはPCMサポートやミキサーを持たず、FM合成のみをサポートします。

確認してください sbiload alsa-toolsパッケージから提供されているものを使用し、モジュールをロードした後、割り当てられたALSAシーケンサポート番号を確認してください sbiload -l.

例の出力:

Port     Client name                       Port name
64:0     OPL2 FM synth                     OPL2 FM Port

ロードしてください std.sb および drums.sb 同様に提供されているパッチも sbiload:

sbiload -p 64:0 std.sb drums.sb

OPL3をドライブする場合、このドライバを使用する代わりに std.o3 および drums.o3 を使用してください。カードから音声を出力させるには、 aplaymidi から alsa-utils:

aplaymidi -p 64:0 foo.mid

モジュール snd-au8810, snd-au8820, snd-au8830¶

Aureal Vortex、Vortex2およびAdvantageデバイス用モジュール。

pcifix

PCIのワークアラウンドを制御；0 = すべてのワークアラウンドを無効、1 = AurealカードのPCIレイテンシーを0xffに強制、2 = VIA KT133 AGPブリッジでのダミーリクエストの効率的な処理に向けたExtend PCI#2 Internal Masterを強制、3 = 上記両方を強制、255 = 必要な設定を自動検出（デフォルト）

このモジュールはすべてのADB PCMチャンネル、ac97ミキサー、SPDIF、ハードウェアEQ、mpu401、ゲームポートをサポートします。A3Dおよびwavetableのサポートはまだ開発中です。開発および逆コンピレーション作業は https://savannah.nongnu.org/projects/openvortex/ SPDIF出力にはAC97コーデック出力のコピーが含まれています。ただし、 spdif pcmデバイスを使用すると、rawデータの透過が可能です。ハードウェアEQおよびSPDIFはVortex2およびAdvantageにのみ存在します。

注意: 一部のALSAミキサーアプリケーションはSPDIFサンプリングレート制御を正しく処理しない場合があります。このような問題が発生した場合は、別のALSA準拠ミキサー（alsamixerが動作します）を試してください。

モジュール snd-azt1605¶

Aztech AZT1605チップセットベースのAztech Sound Galaxyサウンドカード用モジュール。

port

ベースのポート番号（0x220,0x240,0x260,0x280）

wss_port

WSSのポート番号（0x530,0x604,0xe80,0xf40）

irq

WSSのIRQ番号（7,9,10,11）

dma1

WSS再生用DMA番号（0,1,3）

dma2

WSSキャプチャ用DMA番号（0,1）、-1 = 無効（デフォルト）

mpu_port

MPU-401 UARTのポート番号（0x300,0x330）、-1 = 無効（デフォルト）

mpu_irq

MPU-401 UARTのIRQ番号（3,5,7,9）、-1 = 無効（デフォルト）

fm_port

OPL3のポート番号（0x388）、-1 = 無効（デフォルト）

このモジュールは複数のカードをサポートしますが、自動プローブはサポートしていません： port, wss_port, irq および dma1 指定する必要があります。他の値はオプションです。

port ベースアドレスジャンパ（0x220または0x240）またはカードのEEPROMに保存された値と一致する必要があります（EEPROMと「CONFIG MODE」ジャンパが「EEPROM SETTING」に設定されているカードの場合）。他の値は上記のオプションから自由に選択できます。

もし dma2 が指定され、かつ dma1と異なる場合、カードはフル duplexモードで動作します。ただし、 dma1=3、のみ dma2=0 が有効でなければ、キャプチャを有効にする唯一の方法であり、キャプチャ可能なチャンネルは0と1のみです。

汎用設定は port=0x220 wss_port=0x530 irq=10 dma1=1 dma2=0 mpu_port=0x330 mpu_irq=9 fm_port=0x388.

選んだIRQおよびDMAチャンネルは、BIOSでレガシISA用に確保する必要があります。

power_save および power_save_controller オプションはパワーセーブモードに関連します。詳細はpowersave.rstを参照してください。

注意2：出力にクリック音が聞こえる場合は、モジュールオプション position_fix=1 または 2. position_fix=1 を指定すると、DMAポインタとしてSD_LPIBレジスタの値をFIFOサイズ補正なしで使用します。 position_fix=2 を指定すると、ドライバはSD_LPIBレジスタの代わりにポジションバッファを使用します。（通常SD_LPIBレジスタの方がポジションバッファより正確です。）

position_fix=3 はVIAデバイス専用です。キャプチャストリームのポジションはLPIBとPOSBUFの両方から確認されます。 position_fix=4 は再生にLPIB、録音にPOSBUFを使用する組み合わせモードです。

注意：ロード時に多くの azx_get_response timeout メッセージが表示される場合、割込み（例：ACPI割込みルーティング）の問題が考えられます。オプションのように pci=noacpiで起動してみてください。また、 single_cmd=1 モジュールオプションを試すこともできます。これにより、HDAコントローラーとコーデック間の通信方法をCORB/RIRBではなく単一の即時コマンドに切り替えます。基本的に単一コマンドモードはBIOS専用で、非依頼イベントも得られません。ただし、少なくとも割込みとは独立して動作します。これは最終手段であり、できるだけ避けるべきです…

MORE NOTES ON azx_get_response timeout PROBLEMS: 一部のハードウェアでは、適切なprobe_maskオプションを追加して azx_get_response timeout 上記の問題ではなく、この現象は非存在または非動作のコーデックスロット（おそらくモデムに関連する）へのアクセスがHDオーディオバス経由の通信を停止させることで発生します。コーデックスロットが調査される様子を確認するには、 CONFIG_SND_DEBUG_VERBOSEを有効にすると、またはコーデックプロシージャーファイルのファイル名からも確認できます。その後、probe_maskオプションを使用して調査するスロットを制限してください。例えば、 probe_mask=1 は1番目のスロットのみを調査し、 probe_mask=4 は3番目のスロットのみを調査します。

AC97 Quirkオプション¶

ac97_quirkオプションは、on-board AC’97コントローラー（例：snd-intel8x0）のドライバで特定のデバイスに対するワークアラウンドを有効化/上書きします。一部のハードウェアでは、マスターやヘッドホン、サウンドの出力ピンがバージョンによって混同されて入れ替わっているためです（AC’97仕様のバージョン違いによる混乱から）。

ドライバは既知の問題のあるデバイスの自動検出を提供しますが、一部は未知または誤って検出される可能性があります。その場合、このオプションで正しい値を指定してください。

以下の文字列は受け付けられます：

デフォルト

デフォルトの設定を上書きしないでください

none

quirkを無効化してください

hp_only

マスターコントロールとヘッドホンコントロールを1つのコントロールとしてバインドしてください

swap_hp

ヘッドホンコントロールとマスターコントロールを交換してください

swap_surround

マスターコントロールとサウンドコントロールを交換してください

ad_sharing

AD1985の場合、OMSビットをオンにしてヘッドホンを使用してください

alc_jack

ALC65xの場合、ジャックセンスモードをオンにしてください

inv_eapd

逆転したEAPDの実装

mute_led

EAPDビットをバインドしてミュートLEDのオン/オフを制御してください

後方互換性のために、-1、0、…などの対応する整数値も受け入れられます

例えば、もし Master ボリューム制御はあなたのデバイスには効果がありませんが、 Headphone 効果がある場合は、ac97_quirk=hp_only モジュールオプションを渡してください

Module Autoloading Support¶

ALSAドライバはモジュールアリアスを定義することで自動的に要求に応じてロードできます。文字列 snd-card-%1 ALSAネイティブデバイスでは、 %i 0〜7のサウンドカード番号です

OSSサービス用のALSAドライバを自動ロードするには、文字列を定義してください sound-slot-%i オプションを指定する必要があります。形式は以下の通りです： %i これはOSS用のスロット番号で、ALSAのカードインデックスに対応します。通常、この値を同じカードモジュールとして定義してください

単一のemu10k1カードの例は以下の通りです：

----- /etc/modprobe.d/alsa.conf
alias snd-card-0 snd-emu10k1
alias sound-slot-0 snd-emu10k1
----- /etc/modprobe.d/alsa.conf

自動ロード可能なサウンドカードの数はモジュールオプションに依存します cards_limit sndモジュールのオプションです。デフォルトでは1に設定されています。複数のカードを自動ロードするには、そのオプションでサウンドカードの数を指定してください

複数のカードが利用可能な場合、各カードのインデックス番号をモジュールオプションで指定することをお勧めします。カードの順序を一貫して保持するためです

2つのサウンドカードの例は以下の通りです：

----- /etc/modprobe.d/alsa.conf
# ALSA portion
options snd cards_limit=2
alias snd-card-0 snd-interwave
alias snd-card-1 snd-ens1371
options snd-interwave index=0
options snd-ens1371 index=1
# OSS/Free portion
alias sound-slot-0 snd-interwave
alias sound-slot-1 snd-ens1371
----- /etc/modprobe.d/alsa.conf

この例では、interwaveカードは常に最初のカード（インデックス0）としてロードされ、ens1371は2番目のカード（インデックス1）としてロードされます

代替（新しい）方法として、スロット割り当てを固定するには、 slots sndモジュールのオプションを使用します。上記の場合、以下のように指定してください：

options snd slots=snd-interwave,snd-ens1371

その後、最初のスロット（#0）はsnd-interwaveドライバに割り当てられ、2番目のスロット（#1）はsnd-ens1371に割り当てられます。スロットオプションを使用する場合、各ドライバのインデックスオプションは省略できます（ただし、競合しない限り同時に使用することも可能です）

スロットオプションは、ホットプラグインによる可能性のあるスロット競合を回避するために特に有用です。例えば、上記の例では、最初の2つのスロットがすでに予約されています。snd-interwaveまたはsnd-ens1371がsnd-usb-audioなどの他のドライバよりも前にロードされる場合、そのドライバは3番目以降のスロットに割り当てられます。

モジュール名に'!'が付与されている場合、その名前を除くすべてのモジュールにスロットが割り当てられます。例えば、 slots=!snd-pcsp snd-pcspを除くすべてのモジュールに1番目のスロットを予約します。

ALSA PCMデバイスからOSSデバイスへのマッピング¶

/dev/snd/pcmC0D0[c|p]  -> /dev/audio0 (/dev/audio) -> minor 4
/dev/snd/pcmC0D0[c|p]  -> /dev/dsp0 (/dev/dsp)     -> minor 3
/dev/snd/pcmC0D1[c|p]  -> /dev/adsp0 (/dev/adsp)   -> minor 12
/dev/snd/pcmC1D0[c|p]  -> /dev/audio1              -> minor 4+16 = 20
/dev/snd/pcmC1D0[c|p]  -> /dev/dsp1                -> minor 3+16 = 19
/dev/snd/pcmC1D1[c|p]  -> /dev/adsp1               -> minor 12+16 = 28
/dev/snd/pcmC2D0[c|p]  -> /dev/audio2              -> minor 4+32 = 36
/dev/snd/pcmC2D0[c|p]  -> /dev/dsp2                -> minor 3+32 = 39
/dev/snd/pcmC2D1[c|p]  -> /dev/adsp2               -> minor 12+32 = 44

最初の数字は /dev/snd/pcmC{X}D{Y}[c|p] 式で表される音声カード番号で、2番目の数字はデバイス番号を表します。ALSAデバイスは、それぞれキャプチャと再生を示す方向を示すサフィックスを持っています。 c または p キャプチャと再生を示す方向を示すサフィックスを持っています。

snd-pcm-ossモジュールのモジュールオプションによって、上記のデバイスマッピングは変化する可能性があることにご注意ください。

早期バッファ割り当て¶

一部のドライバ（例：hdsp）は大容量の連続バッファを必要とします。しかし、ドライバモジュールが実際にロードされる際には、メモリの断片化によりこのような領域を見つけるのが遅くなることがあります。事前にsnd-page-allocモジュールをロードし、そのプロシージャーファイルにコマンドを書き込むことでPCMバッファを予約できます。例えば、早朝のブートステージで以下のようにします： /etc/init.d/*.local スクリプト。

プロシージャーファイル /proc/drivers/snd-page-alloc を読み込むと、現在のページ割当の使用状況が表示されます。書き込み時には、snd-page-alloc ドライバに以下のコマンドを送信できます：

  • add VENDOR DEVICE MASK SIZE BUFFERS

VENDOR および DEVICE は PCI ベンダーおよびデバイス ID です。整数値を指定し、16進数の場合は 0x プレフィックスが必要です。MASK は PCI DMA マスクを指定します。制限がない場合は 0 を指定してください。SIZE は各バッファの割当サイズを指定します。KB または MB は k および m のサフィックスで指定可能です。最大値は 16MB です。BUFFERS は割当バッファ数を指定します。0 より大きくなければなりません。最大値は 4 です。

  • 削除

すべての未使用の事前に割り当てられたバッファを削除します。
