最終確認日: 2007年10月5日

はじめに¶

ワッチドッグタイマ（WDT）は、ソフトウェアの障害が発生した場合にコンピュータシステムをリセットするハードウェア回路です。おそらくすでにご存知のことでしょう。

通常、ユーザー空間のデーモンは、/dev/watchdogという特殊なデバイスファイルを通じて、カーネルのワッチドッグドライバに定期的に「ユーザー空間が生きている」と通知します。このような通知が発生すると、ドライバはハードウェアのワッチドッグに状態が正常であることを伝え、システムをリセットするまで少し待機するよう指示します。ユーザー空間が失敗した場合（RAMエラー、カーネルのバグなど）、通知が停止し、タイムアウトが発生した後、ハードウェアのワッチドッグがシステムをリセットして再起動を引き起こします。

Linux ワッチドッグAPIは、適当な構成であり、異なるドライバがその一部を異なる、時には互換性のない方法で実装しています。このファイルは、既存の使用方法を記述し、今後のドライバ開発者に参考として利用できるよう試みています。

最もシンプルなAPI¶

すべてのドライバが基本的な動作モードをサポートしており、/dev/watchdogが開かれた時点でワッチドッグがアクティブになり、指定された時間内にワッチドッグに「ping」されない場合にシステムが再起動します。この時間はタイムアウトまたはマージンと呼ばれます。ワッチドッグにpingする最も簡単な方法は、デバイスにデータを書き込むことです。したがって、非常にシンプルなワッチドッグデーモンは次のソースファイルのように見えます：samples/watchdog/watchdog-simple.cを参照してください。

より高度なドライバは、書き込みを行う前にHTTPサーバーがまだ応答しているかを確認するなど、このような処理が可能です。

デバイスが閉じられた場合、ワッチドッグは無効になります（「マジッククローズ」機能がサポートされている場合を除く）。これは常に良いアイデアではありません。なぜなら、ワッチドッグデーモンにバグがあり、システムがクラッシュした場合、再起動が行われないからです。このため、一部のドライバが「クローズ時にウォッチドッグシャットダウンを無効化」する設定オプション、CONFIG_WATCHDOG_NOWAYOUTをサポートしています。この設定をカーネルのコンパイル時にYに設定すると、ワッチドッグを一度起動した後は無効にする方法がありません。したがって、ワッチドッグデーモンがクラッシュした場合、タイムアウトが発生した後にシステムが再起動します。ワッチドッグデバイスは通常、nowayoutモジュールパラメータをサポートして、このオプションをランタイムで制御できます。

マジッククローズ機能¶

ドライバーが「Magic Close」をサポートしている場合、ファイルを閉じる直前に/dev/watchdogに特定のマジック文字‘V’を送信しない限り、ドライバーはウォッチドッグを無効にはしません。ユーザー空間のデーモンがこの特殊な文字を送信せずにファイルを閉じる場合、ドライバーはデーモン（および一般的なユーザー空間）が終了したと判断し、ウォッチドッグを無効にする前にpingを停止します。このため、ウォッチドッグが十分な時間内に再オープンされない場合、再起動が発生します。

ioctl API¶

すべての準拠ドライバーはioctl APIをサポートしています。

ioctlを使用したウォッチドッグのping

ioctlインターフェースを持つすべてのドライバーは少なくとも1つのioctl、KEEPALIVEをサポートしています。このioctlはウォッチドッグデバイスへの書き込みと同じ動作をしますので、上のプログラムのメインループは以下のようになります：

while (1) {
        ioctl(fd, WDIOC_KEEPALIVE, 0);
        sleep(10);
}

ioctlへの引数は無視されます。

タイムアウトの設定と取得¶

一部のドライバーでは、SETTIMEOUT ioctlを使用してウォッチドッグタイムアウトをリアルタイムで変更できます。これらのドライバーはオプションフィールドにWDIOF_SETTIMEOUTフラグを設定しています。引数は秒単位のタイムアウトを表す整数です。ドライバーは同じ変数に実際に使用されたタイムアウトを返しますが、ハードウェアの制限により、求めたタイムアウトと異なる場合があります：

int timeout = 45;
ioctl(fd, WDIOC_SETTIMEOUT, &timeout);
printf("The timeout was set to %d seconds\n", timeout);

この例では、デバイスのタイムアウトの粒度が分単位の場合、「タイムアウトを60秒に設定しました」と表示される可能性があります。

Linux 2.4.18カーネルから、GETTIMEOUT ioctlを使用して現在のタイムアウトを照会できます：

ioctl(fd, WDIOC_GETTIMEOUT, &timeout);
printf("The timeout was is %d seconds\n", timeout);

プリタイムアウト¶

一部のウォッチドッグタイマーでは、システムをリセットする実際の時間よりも前にトリガーを起動できるように設定できます。これはNMI、割込み、または他のメカニズムで実現できます。これにより、Linuxがリセットする前に有用な情報を記録できます（例：パニック情報やカーネルコアダンプ）：

pretimeout = 10;
ioctl(fd, WDIOC_SETPRETIMEOUT, &pretimeout);

プリタイムアウトは、タイムアウトが起動する時間よりも前の秒数を表します。これはプリタイムアウトまでの秒数ではありません。例えば、タイムアウトを60秒に設定し、プリタイムアウトを10秒に設定した場合、プリタイムアウトは50秒後に起動します。プリタイムアウトをゼロに設定すると無効になります。

プリタイムアウトを取得するためのget関数もあります：

ioctl(fd, WDIOC_GETPRETIMEOUT, &timeout);
printf("The pretimeout was is %d seconds\n", timeout);

すべてのウォッチドッグドライバーがプリタイムアウトをサポートするわけではありません。

再起動までの秒数を取得する¶

一部のウォッチドッグドライバーでは、システムが再起動するまでの残り時間を報告できます。WDIOC_GETTIMELEFTは、再起動までの秒数を返すioctlです：

ioctl(fd, WDIOC_GETTIMELEFT, &timeleft);
printf("The timeout was is %d seconds\n", timeleft);

環境モニタリング¶

すべてのウォッチドッグドライバーは、システムに関するより多くの情報を返す必要があります。一部は温度、ファン、電源レベルのモニタリングを行い、一部はシステムの最後の再起動の原因を教えてくれます。GETSUPPORT ioctlを使用して、デバイスが何ができるかを確認できます:

struct watchdog_info ident;
ioctl(fd, WDIOC_GETSUPPORT, &ident);

ident構造体で返されるフィールドは以下の通りです:

identity

ウォッチドッグドライバーを特定する文字列

firmware_version

カードにファームウェアバージョンが存在する場合、そのバージョン

オプション

デバイスがサポートする機能を記述するフラグ

オプションフィールドには以下のビットが設定可能で、GET_STATUSおよびGET_BOOT_STATUS ioctlsが返す情報の種類を示します。

WDIOF_OVERHEAT

CPUの過熱によるリセット

ウォッチドッグによって熱限界を超えたため、マシンが最後に再起動されました:

WDIOF_FANFAULT

ファンの故障

ウォッチドッグカードでモニタリングされているシステムファンが故障しました

WDIOF_EXTERN1

外部リレーリレー1

外部モニタリングリレーやソース1がトリガーされました。現実世界のアプリケーション向けに設計されたコントローラーには、リセットをトリガーする外部モニタリングピンが含まれます。

WDIOF_EXTERN2

外部リレーリレー2

外部モニタリングリレーやソース2がトリガーされました

WDIOF_POWERUNDER

電源不良/電源故障

マシンが電圧不足の状態を示しています

WDIOF_CARDRESET

カードが以前にCPUをリセットしました

最後の再起動はウォッチドッグカードによって引き起こされました

WDIOF_POWEROVER

電圧過多

マシンが電圧過多の状態を示しています。注意：一方が不足し、もう一方が過多の場合、両方のビットが設定されることがあります（これは少し不思議に感じるかもしれませんが、論理的に正しいです）。

WDIOF_KEEPALIVEPING

keep alive pingの応答

ウォッチドッグは最後にクエリされた後、keep alive pingを検知しました。

WDIOF_SETTIMEOUT

タイムアウトの設定/取得が可能です

ウォッチドッグは予備タイムアウトを実行できます。

WDIOF_PRETIMEOUT

予備タイムアウト（秒単位）、取得/設定可能

オプションフィールドに任意のビットが設定されているドライバーでは、GETSTATUSおよびGETBOOTSTATUS ioctlsを使用して現在の状態や最後の再起動時の状態を確認できます:

int flags;
ioctl(fd, WDIOC_GETSTATUS, &flags);

or

ioctl(fd, WDIOC_GETBOOTSTATUS, &flags);

注意：すべてのデバイスがこれらの2つのコールをサポートしているわけではありません。一部のデバイスはGETBOOTSTATUSコールのみをサポートしています。

一部のドライバーはGETTEMP ioctlを使用して温度を測定できます。返される値は華氏度で示されます:

int temperature;
ioctl(fd, WDIOC_GETTEMP, &temperature);

最後に、SETOPTIONS ioctl を使用して、カードの動作のいくつかの側面を制御できます:

int options = 0;
ioctl(fd, WDIOC_SETOPTIONS, &options);

利用可能なオプションは以下の通りです:

WDIOS_DISABLECARD

ウォッチドッグタイマをオフにします

WDIOS_ENABLECARD

ウォッチドッグタイマをオンにします

WDIOS_TEMPPANIC

温度トリップ時にカーネルパニックを発生させます
