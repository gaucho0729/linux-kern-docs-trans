Linux ワッチドッグタイマーパワーマネジメントガイド¶

最終確認日: 2013年2月12日

Wim Van Sebroeck <wim@iguana.be>

はじめに¶

このドキュメントでは、ウォッチドッグタイマードライバまたはデバイスについて説明していません。また、ユーザー空間がウォッチドッグタイマーアクセラレータと通信するために使用できるAPIについても説明していません。この情報が必要な場合は、次のファイルを参照してください: Linux ワッチドッグドライバAPI .

このドキュメントでは何を説明していますか？ウォッチドッグタイマードライバがウォッチドッグタイマードライバフレームワークを使用する場合に使用できるAPIについて説明しています。このフレームワークは、ユーザー空間とのインターフェースをすべて提供し、同じコードを毎回再実装する必要がありません。これにより、ウォッチドッグタイマードライバは、ウォッチドッグタイマーコントロールに必要なさまざまなルーチン（操作）のみを提供する必要があります。

API¶

ウォッチドッグタイマードライバがウォッチドッグタイマードライバコアを使用する場合、#include <linux/watchdog.h> を必須です（ウォッチドッグデバイスドライバを書く際にはこれを行わなければなりません）。このインクルードファイルには、以下の登録/解除ルーチンが含まれています:

extern int watchdog_register_device(struct watchdog_device *);
extern void watchdog_unregister_device(struct watchdog_device *);

watchdog_register_device ルーチンはウォッチドッグタイマーデバイスを登録します。このルーチンのパラメータは、watchdog_device構造体へのポインタです。このルーチンは成功時はゼロを返し、失敗時は負のerrnoコードを返します。

watchdog_unregister_device ルーチンは登録済みのウォッチドッグタイマーデバイスを解除します。このルーチンのパラメータは、登録済みのwatchdog_device構造体へのポインタです。

ウォッチドッグサブシステムには、ブートプロセス中に希望するタイミングでウォッチドッグを登録できるようにする登録遅延メカニズムが含まれています。

ウォッチドッグデバイス構造体は以下のように見えます:

struct watchdog_device {
      int id;
      struct device *parent;
      const struct attribute_group **groups;
      const struct watchdog_info *info;
      const struct watchdog_ops *ops;
      const struct watchdog_governor *gov;
      unsigned int bootstatus;
      unsigned int timeout;
      unsigned int pretimeout;
      unsigned int min_timeout;
      unsigned int max_timeout;
      unsigned int min_hw_heartbeat_ms;
      unsigned int max_hw_heartbeat_ms;
      struct notifier_block reboot_nb;
      struct notifier_block restart_nb;
      void *driver_data;
      struct watchdog_core_data *wd_data;
      unsigned long status;
      struct list_head deferred;
};

これは以下のフィールドを含みます：

  • id: watchdog_register_device によって設定されます。id 0 は特殊です。/dev/watchdog0 cdev (動的メジャーマイナー0) と古い /dev/watchdog miscdev の両方を持っています。id は watchdog_register_device を呼び出すときに自動的に設定されます。

  • parent: watchdog_register_device を呼び出す前に、これを親デバイス（または NULL）に設定してください。

  • groups: ワッチドッグデバイスを作成するときに作成するsysfs属性グループのリスト。

  • info: watchdog_info 構造体へのポインタ。この構造体は、ウォッチドッグタイマーコンポーネントに関する追加情報を提供します。(一意の名前など)

  • ops: ワッチドッグがサポートするウォッチドッグ操作のリストへのポインタ。

  • gov: 指定されたウォッチドッグデバイスのプリタイムアウトガバナーへのポインタまたは NULL。

  • タイムアウト: ウォッチドッグタイマのタイムアウト値（秒単位）。WDOG_ACTIVEが設定されている場合、ユーザー空間がハートビートリクエストを送信しなかった場合、システムが再起動するまでの時間です。

  • プリタイムアウト: ウォッチドッグタイマのプリタイムアウト値（秒単位）。

  • min_timeout: ウォッチドッグタイマの最小タイムアウト値（秒単位）。設定されている場合、'timeout'の最小設定可能な値です。

  • max_timeout: ウォッチドッグタイマの最大タイムアウト値（秒単の単位）。ユーザー空間から見た値で、設定されている場合、'timeout'の最大設定可能な値です。max_hw_heartbeat_msがゼロでない場合は使用されません。

  • min_hw_heartbeat_ms: ハートビート間の最小時間のハードウェア制限（ミリ秒単位）。この値は通常ゼロです。ハードウェアが低いインターバルを許容できない場合のみ指定します。

  • max_hw_heartbeat_ms: 最大ハードウェアハートビート（ミリ秒単位）。設定されている場合、'timeout'がmax_hw_heartbeat_msより大きい場合、インフラストラクチャがウォッチドッグドライバにハートビートを送信します（WDOG_ACTIVEが設定されていてユーザー空間が' timeout'秒以上ハートビートを送信しなかった場合を除く）。ドライバがstop関数を実装していない場合、この値を設定する必要があります。

  • reboot_nb: 再起動通知用に登録された通知ブロック（内部使用専用）。ドライバがwatchdog_stop_on_rebootを呼び出す場合、ウォッチドッグコアがこのような通知でウォッチドッグを停止します。

  • restart_nb: マシン再起動用に登録された通知ブロック（内部使用専用）。ウォッチドッグがマシン再起動を可能にする場合、ops->restartを定義する必要があります。優先度はwatchdog_set_restart_priorityで変更可能です。

  • bootstatus: デバイスの起動後の状態（ウォッチドッグWDIOF_*状態ビットで報告されます）。

  • driver_data: ドライバ固有データへのポインタ。このデータはwatchdog_set_drvdataとwatchdog_get_drvdataルーチンのみでアクセスする必要があります。

  • wd_data: ウォッチドッグコアの内部データへのポインタ。

  • status: このフィールドには、デバイスの状態に関する追加情報が含まれます（例: ウォッチドッグタイマが動作中/アクティブか、nowayoutビットが設定されているかなど）。

  • deferred: wtd_deferred_reg_listに登録されるエントリで、早期初期化されたウォッチドッグを登録するために使用されます。

ウォッチドッグ操作のリストは次のようになります:

struct watchdog_ops {
      struct module *owner;
      /* mandatory operations */
      int (*start)(struct watchdog_device *);
      /* optional operations */
      int (*stop)(struct watchdog_device *);
      int (*ping)(struct watchdog_device *);
      unsigned int (*status)(struct watchdog_device *);
      int (*set_timeout)(struct watchdog_device *, unsigned int);
      int (*set_pretimeout)(struct watchdog_device *, unsigned int);
      unsigned int (*get_timeleft)(struct watchdog_device *);
      int (*restart)(struct watchdog_device *);
      long (*ioctl)(struct watchdog_device *, unsigned int, unsigned long);
};

ウォッチドッグタイマドライバの操作のモジュール所有者を最初に定義することが重要です。このモジュール所有者は、ウォッチドッグがアクティブなときにモジュールをロックするために使用されます。（これにより、モジュールをアンロードする際、/dev/watchdogがまだオープンしている場合でもシステムクラッシュを防ぎます）

一部の操作は必須で、一部はオプションです。必須操作は以下の通りです。

  • start: これはウォッチドッグタイマーデバイスを開始するルーチンへのポインタです。このルーチンはウォッチドッグタイマーデバイス構造体へのポインタをパラメータとして必要とし、成功時はゼロを返し、失敗時は負のerrnoコードを返します。

すべてのウォッチドッグタイマーハードウェアが同じ機能をサポートしているわけではありません。そのため、すべての他のルーチン/操作はオプションです。それらはサポートされている場合にのみ提供する必要があります。オプションのルーチン/操作は以下の通りです。

  • stop: このルーチンによりウォッチドッグタイマーデバイスが停止されます。

    このルーチンはウォッチドッグタイマーデバイス構造体へのポインタをパラメータとして必要とし、成功時はゼロを返し、失敗時は負のerrnoコードを返します。一部のウォッチドッグタイマーハードウェアは起動のみ可能で停止できません。このようなハードウェアをサポートするドライバはstopルーチンを実装する必要がありません。

    ドライバにstop関数がなければ、ウォッチドッグコアはWDOG_HW_RUNNINGを設定し、ウォッチドッグデバイスが閉じられた後、ドライバのkeepalive ping関数を呼び出します。

    ウォッチドッグドライバがstop関数を実装していない場合、max_hw_heartbeat_msを設定しなければなりません。

  • ping: これはウォッチドッグタイマーハードウェアにkeepalive pingを送るルーチンです。

    このルーチンはウォッチドッグタイマーデバイス構造体へのポインタをパラメータとして必要とし、成功時はゼロを返し、失敗時は負のerrnoコードを返します。

    この機能を個別にサポートしないハードウェアは、start関数を使用してウォッチドッグタイマーハードウェアを再起動します。ウォッチドッグタイマードライバコアも同様に、keepalive pingを送るにはping操作（利用可能場合）またはstart操作（ping操作が利用不可の場合）を使用します。

    (注意: WDIOC_KEEPALIVE ioctlコールは、ウォッチドッグの情報構造体のoptionフィールドにWDIOF_KEEPALIVEPINGビットが設定されている場合にのみ有効です。)

  • status: これはウォッチドッグタイマーデバイスの状態を確認するルーチンです。デバイスの状態はウォッチドッグ WDIOF_* 状態フラグ/ビットで報告されます。

    WDIOF_MAGICCLOSEおよびWDIOF_KEEPALIVEPINGはウォッチドッグコアによって報告されます。ドライバからこれらのビットを報告する必要はありません。また、ドライバがstatus関数を提供しない場合、ウォッチドッグコアはstruct watchdog_deviceのbootstatus変数に含まれる状態ビットを報告します。

  • set_timeout: このルーチンはウォッチドッグタイマーデバイスのタイムアウト時間を確認し変更します。成功時は0を返し、"パラメータが範囲外"の場合は-EINVAL、"ウォッチドッグに値を書き込めない"の場合は-EIOを返します。成功時はこのルーチンがウォッチドッグデバイスのタイムアウト値を実際のタイムアウト値（リクエストされた値とは異なる可能性がある）に設定する必要があります（ウォッチドッグが必ずしも1秒単位の解像度を持つとは限らないため）。

    max_hw_heartbeat_msを実装するドライバは、ハードウェアウォッチドッグのハートビートをtimeoutとmax_hw_heartbeat_msの最小値に設定します。これらのドライバは、timeout値をリクエストされたタイムアウト値（max_hw_heartbeat_msより大きい場合）に設定するか、実際のタイムアウト値に設定します。（注意: ワッチドッグの情報構造体のoptionsフィールドにWDIOF_SETTIMEOUTを設定する必要があります）。

    ウォッチドッグドライバがwatchdog_device.timeoutの設定以外に動作を必要としない場合、このコールバックは省略可能です。

    set_timeoutが提供されていないが、WDIOF_SETTIMEOUTが設定されている場合、ウォッチドッグインフラストラクチャは内部的にウォッチドッグデバイスのタイムアウト値をリクエストされた値に更新します。

    pretimeout機能が使用されている場合（WDIOF_PRETIMEOUT）、set_timeoutはpretimeoutが有効かどうかを確認し、タイマを適切に設定する必要があります。コアでは競合条件を避けてこれを実行できないため、ドライバの責任です。

  • set_pretimeout: このルーチンはウォッチドッグのpretimeout値を確認および変更します。すべてのウォッチドッグがpretimeout通知をサポートするわけではないため、これはオプションです。タイムアウト値は絶対時間ではなく、実際のタイムアウトが発生するまでの秒数です。成功時は0を返し、"パラメータが範囲外"の場合は-EINVAL、"ウォッチドッグに値を書き込めない"の場合は-EIOを返します。値が0の場合はpretimeout通知を無効にします。

    （注意: ワッチドッグの情報構造体のoptionsフィールドにWDIOF_PRETIMEOUTを設定する必要があります）。

    ウォッチドッグドライバがwatchdog_device.pretimeoutの設定以外に動作を必要としない場合、このコールバックは省略可能です。つまり、set_pretimeoutが提供されていないがWDIOF_PRETIMEOUTが設定されている場合、ウォッチドッグインフラストラクチャは内部的にウォッチドッグデバイスのpretimeout値をリクエストされた値に更新します。

  • get_timeleft: このルーチンはリセットまでの残り時間を返します。

  • restart: このルーチンはマシンを再起動します。成功時は0を返し、失敗時は負のエラー番号を返します。

  • ioctl: このルーチンが存在する場合、内部のioctlコールハンドリングを行う前にこのルーチンが最初に呼び出されます。サポートされていないコマンドの場合、このルーチンは-ENOIOCTLCMDを返すべきです。ioctlコールに渡されるパラメータは watchdog_device、cmd および arg です。

ステータスビットは（望ましくは）set_bit および clear_bit などのビット操作関数で設定すべきです。定義されたステータスビットは以下の通りです：

  • WDOG_ACTIVE: このステータスビットは、ユーザーの視点からウォッチドッグタイマーデバイスがアクティブかどうかを示します。このフラグが設定されている間、ユーザー空間はドライバにハートビートリクエストを送信する必要があります。

  • WDOG_NO_WAY_OUT: このビットはウォッチドッグのnowayout設定を保存します。このビットが設定されている場合、ウォッチドッグタイマーコンテナは停止できません。

  • WDOG_HW_RUNNING: ハードウェアウォッチドッグが動作している場合、ウォッチドッグドライバがこのビットを設定します。このビットはウォッチドッグタイマーハードウェアが停止できない場合に設定する必要があります。また、ウォッチドッグデバイスがオープンされる前にも、起動後にウォッチドッグタイマが動作している場合に設定されることがあります。このビットが設定されている場合、ウォッチドッグインフラストラクチャはWDOG_ACTIVEが設定されていない間、ウォッチドッグハードウェアにkeepaliveリクエストを送信します。注意：このビットが設定された状態でウォッチドッグタイマーデバイスを登録すると、/dev/watchdogを開く際にはstart操作をスキップし、keepaliveリクエストを代わりに送信します。

    ウォッチドッグタイマーデバイスを登録する前にWDOG_NO_WAY_OUTステータスビットを設定するには、以下のいずれかを使用できます：

    • watchdog_device構造体で静的に設定し、

      .status = WATCHDOG_NOWAYOUT_INIT_STATUS,

      (これはCONFIG_WATCHDOG_NOWAYOUTと同じ値を設定します) または、

    • 次のヘルパ関数を使用します：

      static inline void watchdog_set_nowayout(struct watchdog_device *wdd,
                                         int nowayout)
注意:

WatchDog Timer Driver Coreはmagic close機能とnowayout機能をサポートしています。magic close機能を使用するには、ウォッチドッグのinfo構造体のoptionsフィールドにWDIOF_MAGICCLOSEビットを設定する必要があります。

nowayout機能はmagic close機能を上書きします。

ドライバ固有データを取得または設定するには、次の2つのヘルパ関数を使用すべきです：

static inline void watchdog_set_drvdata(struct watchdog_device *wdd,
                                        void *data)
static inline void *watchdog_get_drvdata(struct watchdog_device *wdd)

watchdog_set_drvdata関数はドライバ固有データを追加できます。この関数の引数は、ドライバ固有データを追加したいウォッチドッグデバイスと、データそのもののポインタです。

watchdog_get_drvdata関数はドライバ固有データを取得できます。この関数の引数は、データを取得したいウォッチドッグデバイスです。関数はドライバ固有データへのポインタを返します。

タイムアウトフィールドを初期化するには、次の関数を使用できます：

extern int watchdog_init_timeout(struct watchdog_device *wdd,
                                 unsigned int timeout_parm,
                                 struct device *dev);

watchdog_init_timeout関数は、モジュールのタイムアウトパラメータを使用してタイムアウトフィールドを初期化するか、デバイスツリーからtimeout-secプロパティを取得して初期化できます（モジュールタイムアウトパラメータが無効な場合）。ベストプラクティスとして、watchdog_deviceのタイムアウト値にデフォルトタイムアウト値を設定し、その後この関数を使用してユーザーが好むタイムアウト値を設定することをお勧めします。この関数は成功時にゼロを返し、失敗時には負のエラー番号を返します。

再起動時にウォッチドッグを無効にするには、ユーザーは次のヘルパーファンクションを呼び出す必要があります：

static inline void watchdog_stop_on_reboot(struct watchdog_device *wdd);

ウォッチドッグをアンレジストレーション時に無効にするには、ユーザーは次のヘルパーファンクションを呼び出す必要があります。注意点として、nowayoutフラグが設定されていない場合にのみウォッチドッグが停止します。

static inline void watchdog_stop_on_unregister(struct watchdog_device *wdd);

再起動ハンドラの優先度を変更するには、次のヘルパーファンクションを使用する必要があります：

void watchdog_set_restart_priority(struct watchdog_device *wdd, int priority);

ユーザーは次のガイドラインに従って優先度を設定する必要があります：

  • 0: 最終手段として呼び出されるべきで、再起動機能が限定されています

  • 128: デフォルトの再起動ハンドラ、他のハンドラが利用できない場合や再起動でシステム全体を再起動できる場合に使用します

  • 255: 最高優先度、他のすべての再起動ハンドラを優先します

プリタイムアウト通知を発生させるには、次の関数を使用する必要があります：

void watchdog_notify_pretimeout(struct watchdog_device *wdd)

この関数は割込みコンテキストで呼び出すことができます。ウォッチドッグプリタイムアウトガバネッサーフレームワーク（kbuild CONFIG_WATCHDOG_PRETIMEOUT_GOVシンボル）が有効な場合、ウォッチドッグデバイスに事前に割り当てられたプリタイムアウトガバネーターによってアクションが実行されます。ウォッチドッグプリタイムアウトガバネッサーフレームワークが有効でない場合、watchdog_notify_pretimeout()はカーネルログバッファに通知メッセージを出力します。

ウォッチドッグの最後に知られたハードウェアキープアライブ時間を設定するには、次の関数を使用する必要があります：

int watchdog_set_last_hw_keepalive(struct watchdog_device *wdd,
                                   unsigned int last_ping_ms)

この関数はウォッチドッグの登録直後にすぐに呼び出す必要があります。これは最後に発生したハードウェアハートビートを現在時刻よりlast_ping_ms前に設定します。ウォッチドッグがprobeが呼ばれるときにすでに動作している場合にのみこの関数を呼び出す必要があります。ウォッチドッグは最後のpingからmin_hw_heartbeat_ms時間が経過した後にのみpingできます。
