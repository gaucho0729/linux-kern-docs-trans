旧ワッチドッグドライバをワッチドッグフレームワークに移行する方法¶

by Wolfram Sang <wsa@kernel.org>

ウォッチドッグフレームワークがカーネルに導入される前は、すべてのドライバーが独自にAPIを実装していました。現在ではフレームワークが共通部品を分離し、それらのドライバーはフレームワークのユーザーとして軽量化されています。このドキュメントではこの作業の手順を説明し、必要なステップや注意すべき点を記載しています。

file_operations構造体を削除する¶

旧ドライバーはopen()やwrite()などの操作用に独自のfile_operationsを定義していました。これらは現在フレームワークが処理し、必要に応じてドライバーを呼び出します。したがって、一般的には「file_operations」構造体と関連する関数は不要となり、わずかなドライバースペシフィックな詳細を他の関数に移す必要があります。以下に関数と必要なアクションの概要を示します：

  • open: リソース管理（ファイルオープンチェック、マジッククローズの準備など）はすべて削除可能です。デバイス固有の処理はドライバースペシフィックなstart関数に移す必要があります。一部のドライバーではstart関数がping関数としても使用されることがあります。その場合、start/stopのバランス（クロックなど）が必要な場合は、別途start関数を再構築する方が良いでしょう。

  • close: openと同様の注意点が適用されます。

  • write: すべての動作はフレームワークが処理するため、削除可能です。つまり、write時のpingとマジック文字（'V'）の処理もフレームワークが担当します。

  • ioctl: ドライバーはIOCTLインターフェースに拡張を加えることが許可されていますが、最も一般的な機能はフレームワークが処理し、ドライバーの支援によって実現されます：

    WDIOC_GETSUPPORT:

    ドライバーから必須のwatchdog_info構造体を返します

    WDIOC_GETSTATUS:

    status-callbackが定義されている必要があります。それ以外は0を返します

    WDIOC_GETBOOTSTATUS:

    bootstatusメンバが適切に設定されている必要があります。さらにサポートがない場合は0にしてください！

    WDIOC_SETOPTIONS:

    特別な準備は必要ありません

    WDIOC_KEEPALIVE:

    必要であればwatchdog_infoのオプションにWDIOF_KEEPALIVEPINGを設定してください

    WDIOC_SETTIMEOUT:

    watchdog_infoのオプションにWDIOF_SETTIMEOUTを設定し、set_timeout-callbackを定義する必要があります。コアはmin_timeoutとmax_timeoutが設定されている場合、制限チェックも行います。すべてオプションです。

    WDIOC_GETTIMEOUT:

    特別な準備は必要ありません

    WDIOC_GETTIMELEFT:

    get_timeleft() callbackを定義する必要があります。それ以外はEOPNOTSUPPを返します

    他のIOCTLはioctl-callbackを使用して処理できます。注意点として、これは主に旧ドライバの移植に使用することを目的としており、新しいドライバではプライベートなIOCTLを新たに作成すべきではありません。プライベートなIOCTLは優先的に処理されます。callbackが-ENOIOCTLCMDを返す場合、フレームワークのIOCTLも試行されます。他のエラーはユーザーに直接返されます。

例としての変換:

-static const struct file_operations s3c2410wdt_fops = {
-       .owner          = THIS_MODULE,
-       .llseek         = no_llseek,
-       .write          = s3c2410wdt_write,
-       .unlocked_ioctl = s3c2410wdt_ioctl,
-       .open           = s3c2410wdt_open,
-       .release        = s3c2410wdt_release,
-};

デバイス固有の処理を行う関数を確認し、後でリファクタリングのために残しておきます。それ以外のコードは削除してください。

miscdeviceを削除する¶

file_operationsがなくなったため、'struct miscdevice'も削除できます。フレームワークはwatchdog_dev_register()が呼ばれた際に自動的に作成します。watchdog_register_device()によって呼び出されます：

-static struct miscdevice s3c2410wdt_miscdev = {
-       .minor          = WATCHDOG_MINOR,
-       .name           = "watchdog",
-       .fops           = &s3c2410wdt_fops,
-};

非推奨のインクルードと定義を削除する¶

簡略化により、いくつかの定義はおそらく使用されなくなりました。それらを削除してください。インクルードも同様に削除可能です。例えば：

- #include <linux/fs.h>
- #include <linux/miscdevice.h> (if MODULE_ALIAS_MISCDEV is not used)
- #include <linux/uaccess.h> (if no custom IOCTLs are used)

watchdog操作を追加する¶

すべての可能コールバックは'struct watchdog_ops'に定義されています。このディレクトリ内の'watchdog-kernel-api.txt'で詳しく説明されています。 start() ownerは必ず設定する必要がありますが、それ以外はオプションです。古いドライバで対応する関数は簡単に見つけることができます。注意点として、これらの関数に渡されるパラメータとしてwatchdog_deviceへのポインタが渡されるため、関数ヘッダを変更する必要があります。他の変更は必要ないでしょう。ここでは単純にハードウェアへの直接アクセスが行われるためです。上記のステップで残ったデバイス固有のコードは、これらのコールバックにリファクタリングする必要があります。

ここに簡単な例:

+static struct watchdog_ops s3c2410wdt_ops = {
+       .owner = THIS_MODULE,
+       .start = s3c2410wdt_start,
+       .stop = s3c2410wdt_stop,
+       .ping = s3c2410wdt_keepalive,
+       .set_timeout = s3c2410wdt_set_heartbeat,
+};

典型的な関数ヘッダの変更例は以下の通り:

-static void s3c2410wdt_keepalive(void)
+static int s3c2410wdt_keepalive(struct watchdog_device *wdd)
 {
...
+
+       return 0;
 }

...

-       s3c2410wdt_keepalive();
+       s3c2410wdt_keepalive(&s3c2410_wdd);

watchdogデバイスを追加する¶

今後、'struct watchdog_device'を作成し、フレームワークに必要な情報を埋め込む必要があります。この構造体についても、このディレクトリ内の'watchdog-kernel-api.txt'で詳しく説明されています。必須のwatchdog_info構造体と新たに作成したwatchdog_opsを渡します。多くの古いドライバでは、bootstatusやtimeoutなどの情報に静的変数を使用していましたが、これらはwatchdog_deviceのメンバに変換する必要があります。注意点として、timeout値はunsigned intです。一部のドライバではsigned intを使用しているため、こちらも変換する必要があります。

ここに簡単なwatchdogデバイスの例:

+static struct watchdog_device s3c2410_wdd = {
+       .info = &s3c2410_wdt_ident,
+       .ops = &s3c2410wdt_ops,
+};

「nowayout」機能の処理¶

いくつかのドライバではnowayoutを静的に使用しており、モジュールパラメータが存在せず、CONFIG_WATCHDOG_NOWAYOUTによって機能が有効かどうかが決まります。この処理は、watchdog_deviceのstatus変数を以下のように初期化することで変換する必要があります：

.status = WATCHDOG_NOWAYOUT_INIT_STATUS,

ほとんどのドライバーは、nowayoutのランタイム設定を許可しており、通常はモジュールパラメータを追加することで実現されます。この変換は次のようになります：

watchdog_set_nowayout(&s3c2410_wdd, nowayout);

モジュールパラメータ自体は残しておき、nowayoutに関連する他のすべての処理は削除できます。これはopen()、close()、またはwrite()などの関数内にコードが含まれている可能性があります。

ウォッチドッグデバイスを登録する¶

misc_register(&miscdev)をwatchdog_register_device(&watchdog_dev)に置き換えてください。返却値の確認と、エラーが発生した場合のメッセージが依然として適切であることを確認してください。また、アンレジストレーションのケースも変換してください：

-       ret = misc_register(&s3c2410wdt_miscdev);
+       ret = watchdog_register_device(&s3c2410_wdd);

...

-       misc_deregister(&s3c2410wdt_miscdev);
+       watchdog_unregister_device(&s3c2410_wdd);

Kconfigエントリを更新する¶

ドライバーのエントリは現在、WATCHDOG_COREを選択する必要があります：

  • select WATCHDOG_CORE
