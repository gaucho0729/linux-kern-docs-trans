バックライトサポート¶

バックライトコアはバックライトドライバの実装をサポートしています。

バックライトドライバは、 devm_backlight_device_register()を使用してドライバを登録します。バックライトドライバのプロパティ（タイプやmax_brightnessなど）を指定する必要があります。コアが明るさや電源状態などの変化を検出するとupdate_status()操作が呼び出されます。バックライトドライバはこの操作を実装し、明るさを調整するために使用します。

バックライトコアは以下のsysfs属性を提供しています：

- brightness         R/W, set the requested brightness level
- actual_brightness  RO, the brightness level used by the HW
- max_brightness     RO, the maximum  brightness level supported

sysfs-class-backlightのドキュメンテーションを参照してください。

sysfsインターフェースを使用してバックライトを調整できます。また、バックライトドライバはホットキーまたはプラットフォームやファームウェア固有の方法でバックライトを調整することもサポートできます。

HWが明るさのすべてのレベルをサポートしない場合、get_brightness()操作を実装する必要があります。これにより、ユーザー空間から実際の明るさレベルをactual_brightness属性経由でアクセスできます。

バックライトが変化すると、actual_brightness属性に接続されたueventを通じてユーザー空間に報告されます。プラットフォーム固有の方法（例：ホットキーによる明るさ調整）で明るさが設定された場合、ドライバはバックライトコアに明るさが変化したことを通知する必要があります。 backlight_force_update().

バックライトドライバコアはfbdevから通知を受け取り、イベントがFB_EVENT_BLANKで、FBIOBLANK ioctrlの値がバックライト状態に変化をもたらす場合、update_status()操作が呼び出されます。

struct backlight_ops¶

バックライト操作

定義

struct backlight_ops {
  unsigned int options;
#define BL_CORE_SUSPENDRESUME   (1 << 0);
  int (*update_status)(struct backlight_device *);
  int (*get_brightness)(struct backlight_device *);
  int (*check_fb)(struct backlight_device *bd, struct fb_info *info);
};

メンバ

options

コアから操作が呼び出される方法を設定します。

optionsパラメータはコアの動作を調整します。BL_CORE_SUSPENDRESUMEを設定すると、スリープと再起動時にupdate_status()操作が呼び出されます。

update_status

プロパティが変更されたときに呼び出される操作。

バックライトドライバに一部のプロパティが変更されたことを通知します。update_status操作はupdate_lockによって保護されています。

バックライトドライバは以下を使用する必要があります。 backlight_is_blank() 表示がblankedされているかを確認し、それに応じて明るさを設定する必要があります。update_status()は、どのプロパティも変更されたときに呼び出されます。

戻り値:

成功時は0、エラーが発生した場合は負のエラーコードを返します。

get_brightness

現在のバックライト明るさを返します。

ドライバはこれをハードウェアからの読み戻しとして実装する可能性があります。この操作はオプションであり、実装されていない場合は現在の明るさプロパティの値が使用されます。

戻り値:

明るさは0または正の数値でなければなりません。失敗した場合は負のエラーコードを返します。

check_fb

フレームバッファデバイスを確認します。

指定されたフレームバッファデバイスがこのバックライトにバインドされているかを確認します。この操作はオプションであり、実装されていない場合はfbdevが常にバックライトにバインドされていると仮定されます。

戻り値:

infoがNULLか、fbdevがバックライトにバインドされている場合にtrueを返します。一致しない場合はfalseを返します。

説明

バックライトデバイスが登録されるときにバックライト操作が指定されます。

struct backlight_properties¶

backlight properties

定義

struct backlight_properties {
  int brightness;
  int max_brightness;
  int power;
  int fb_blank;
  enum backlight_type type;
  unsigned int state;
#define BL_CORE_SUSPENDED       (1 << 0)        ;
#define BL_CORE_FBBLANK         (1 << 1)        ;
  enum backlight_scale scale;
};

メンバ

brightness

ユーザーが要求する現在の明るさ。

バックライトコアは、明るさをsysfs属性経由で設定する際、範囲を(0からmax_brightness)に保ちます。/sys/class/backlight/<backlight>/brightness。

この値は、backlight_propertiesに設定され、 devm_backlight_device_register() デフォルトの明るさ値を設定します。

max_brightness

最大明るさ値。

この値は、backlight_propertiesに設定され、 devm_backlight_device_register() ドライバが登録後で変更してはなりません。

power

現在の電源モード。

ユーザー空間は、sysfs属性を介して電源モードを設定できます。電源プロパティが更新されるとき、update_status()が呼び出されます。

可能な値は: (0: 全ての電源ON, 1〜3: 省電力モード; 4: 全ての電源オフ)、FB_BLANK_XXXを参照してください。

バックライトデバイスが有効化されるとき べき乗 FB_BLANK_UNBLANKに設定されます。バックライトデバイスが無効化されるとき べき乗 FB_BLANK_POWERDOWNに設定されます。

fb_blank

FBIOBLANK ioctlから取得した電源状態。

FBIOBLANK ioctlが呼び出されるとき fb_blank blankパラメータに設定され、update_status()操作が呼び出されます。

バックライトデバイスが有効化されるとき fb_blank FB_BLANK_UNBLANKに設定されます。バックライトデバイスが無効化されるとき fb_blank FB_BLANK_POWERDOWNに設定されます。

バックライトドライバはこのプロパティを使用すべきではありません。これはstate & BL_CORE_FBLANKによって置き換えられています（ただし、ほとんどのドライバは backlight_is_blank() blank状態を取得するための推奨手段です）。

fb_blankは非推奨となり、削除されます。

type

サポートされるバックライトのタイプ。

バックライトタイプは、ユーザー空間がバックライトタイプに基づいて適切なポリシー決定を行うことを可能にする。

この値は、backlight_propertiesに設定され、 devm_backlight_device_register().

state

バックライトコアの状態。

状態はビットマスクです。表示が消灯すると予想される場合、BL_CORE_FBBLANKが設定され、ドライバーが停止している場合、BL_CORE_SUSPENDEDが設定されます。

バックライトドライバーは、update_status()操作でこの状態プロパティを読み取るのではなく、 backlight_is_blank() update_status()操作を使用すべきです。

状態はコアによって維持され、ドライバーはこれを変更してはなりません。

scale

明るさスケールのタイプ。

説明

この構造体はバックライトのすべてのプロパティを定義します。

struct backlight_device¶

バックライトデバイスデータ

定義

struct backlight_device {
  struct backlight_properties props;
  struct mutex update_lock;
  struct mutex ops_lock;
  const struct backlight_ops *ops;
  struct notifier_block fb_notif;
  struct list_head entry;
  struct device dev;
  bool fb_bl_on[FB_MAX];
  int use_count;
};

メンバ

props

バックライトプロパティ

update_lock

update_status()操作を呼び出す際のロック。

update_lockは内部のバックライトロックで、update_status()操作へのアクセスをシリアル化します。バックライトコアはupdate_status()操作を呼び出す際、このupdate_lockを保持します。バックライトドライバーはupdate_lockを使用してはなりません。

ops_lock

バックライト_opsに関連するすべての操作を囲むロック。

ops_lockは内部のバックライトロックで、opsポインタを保護し、opsへのすべてのアクセスと操作が呼び出される際の排他制御に使用されます。バックライトドライバーはops_lockを使用してはなりません。

ops

バックライト操作へのポインタ。

opsがNULLの場合、このデバイスを登録したドライバーがアンロードされており、class_get_devdata()がそのドライバーの本体を指している場合も無効です。

fb_notif

フレームバッファ通知ブロック

entry

すべての登録済みバックライトデバイスのリストエントリ

dev

親デバイス。

fb_bl_on

個々のfbdevの状態。

複数のfbdevが1つのバックライトデバイスを共有する場合があります。fb_bl_onは個々のfbdevの状態を記録します。

use_count

fb_bl_onの使用回数。

説明

バックライトデバイスに必要なすべてのデータを保持する構造体。
