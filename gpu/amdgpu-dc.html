drm/amd/display - Display Core (DC)¶

placeholder - サポートされているプラットフォームの一般的な説明、DC とは何かなど

他のオペレーティングシステムと部分的に共有されているため、ディスプレイコアドライバーは2つの部分に分割されています。

  1. Display Core (DC) OSに依存しないコンポーネントを含みます。ハードウェアプログラミングやリソース管理などはここで処理されます。

  2. Display Manager (DM) OSに依存するコンポーネントを含みます。amdgpuベースドライバとDRMへのハックはここに実装されています。

残念ながら、このパッケージは頻繁にDCと呼ばれるため、文脈を考慮すれば明確であるべきです。

CONFIG_DRM_AMD_DC が有効な場合、サポートされているASICに対してDCがデフォルトで初期化されます。強制的に無効にするには、カーネルコマンドラインに amdgpu.dc=0 を設定します。 amdgpu.dc=0 同様に、サポートされていないASICで強制的に有効にするには、amdgpu.dc=1 を設定します。 DCがロードされているかを確認するには、dmesgで以下のエントリを検索してください：.

AMDgpu Display Manager

Display Core initialized with <version number here>

割込み¶

DMはベースドライバーが提供するIRQ管理の上層に追加の管理レイヤーを提供します。これは今後のTODOとしてクリーンアップ可能です。

ベースドライバーはDRMとのIRQソース登録、ベースドライバーのIRQテーブルへのハンドラ登録、およびハンドラコールバックを提供します amdgpu_irq_handler()、DRMが割込み時に呼び出します。この汎用ハンドラはIRQテーブルを検索し、対応する amdgpu_irq_src_funcs.process ハンドラを呼び出します。

DMが提供する上層のものは、上半分と下半分の割込み処理用に特化した2つのIRQテーブルで、下半分はワーキューを実装しています：

  • amdgpu_display_manager.irq_handler_list_high_tab

  • amdgpu_display_manager.irq_handler_list_low_tab

これらはベースドライバーのIRQテーブルを上書きし、DMが提供するハンドラでその影響が現れます。 amdgpu_irq_src_funcs.process。これらはすべてDMの汎用ハンドラに設定されています、 amdgpu_dm_irq_handler()、これはDMのIRQテーブルを検索します。ただし、ベースドライバーがこのハンドラを認識するためには、DMがベースドライバーにIRQを登録する必要があります。dce110_register_irq_handlers()とdcn10_register_irq_handlers()を参照してください。

DCのハードウェア割込みトグルをベースドライバーに公開するため、DMは amdgpu_irq_src_funcs.set ハンドラを実装します。ベースドライバーはこれを amdgpu_irq_update() 有効または無効にするために呼び出します。

int amdgpu_dm_atomic_check(struct drm_device *dev, struct drm_atomic_state *状態)¶

AMDgpu DMのアトミックチェック実装。

パラメータ

struct drm_device *dev

DRMデバイス

struct drm_atomic_state *state

コミットするアトミック状態

説明

指定されたアトミック状態がDCでハードウェアにプログラミング可能かを検証します。これは、 struct dc_state 新しいハードウェア状態を反映したDC状態を構築し、DCにプログラミング可能かを確認します。既存のDC状態を変更しないことが重要です。そうしないと、アトミックチェックが予期せずにハードウェア変更をコミットする可能性があります。

DC状態を検証する際、正しいロックを取得することが重要です。あるCRTCでストリームを追加/削除/更新し、別のCRTCでフラップしている場合、グローバルロックを取得することで、すべてのフラップ完了までDRMの同期イベントで待機するよう保証できます。

DMはすべてのCRTCsの状態に影響するコネクタを追加します。これは必要に見えるかもしれません。これはDCストリーム作成にDCシンクが必要で、DRMコネクタ状態に結びついているためです。この処理を整理するのは可能ですが非自明です。今後のTODO項目かもしれません。

戻り値

-検証に失敗した場合のエラーコード。
