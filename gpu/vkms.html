drm/vkms Virtual Kernel Modesetting¶

VKMS は KMS ドライバーのソフトウェアのみのモデルで、テストやヘッドレスマシンでの X（または類似の）の実行に有用です。VKMS はハードウェア表示機能を必要とせずに仮想ディスプレイを実現し、DRM API テストで GPU を解放することを目的としています。

  • vaddr_src と vaddr_dst をアルファ値を使ってブレンドする代わりに、上書きするのではなく blend().

  • XRGB プレーン形式のクリアードアルファ値を確認するための igt テストを追加します。

  • 完全不透明および完全透明（中間値はハードウェア固有の丸めモードに影響される）の極端なアルファ値を確認するための igt テストを追加します。

ランタイム設定¶

vkms インスタンスを再構成するためにはモジュールを再ロードせずにできるようにしたいです。使用例/テストケース:

  • ホットプラグ/ホットリムーブコネクタを即時で実行（コンポジタの DP MST ハンドリングをテストするため）。

  • プレーン/CRtc/コネクタの設定（複数のコネクタをサポートするためにはまずコードが必要です）。

  • 出力設定の変更: スクリーンの挿抜、EDIDの変更、リフレッシュレートの変更を許可。

現在の提案された解決策は、vkms の設定を configfs で公開することです。すべての既存モジュールオプションも configfs でサポートする必要があります。

プレーン機能追加¶

多くのプレーン機能を追加サポートできます:

  • カーソル以外のリアルオーバーレイプレーン。

  • すべてのプレーンでフルアルファブレンド。

  • 回転、スケーリング。

  • 追加のバッファ形式、特に動画用の YUV 形式（NV12 など）。低/高 bpp RGB 形式も興味深いです。

  • 非同期更新（現在はカーソルプレーンのみで legacy カーソル API で可能）。

これらすべてに対して igt テストカバレッジをレビューし、すべての関連する igt テストケースが vkms で動作することを確認します。

Writebackサポート¶

現在 vkms は各フレームごとに CRC を計算します。追加のプレーン機能を実装したら、合成フレーム全体を書き戻し、以下のように公開できます:

  • Writeback コネクタ。ハードウェアの writeback サポートがない場合にコンポジタのテストに有用です。

  • v4l デバイスとして。特殊な vkms コンフィギュレーションでのコンポジタのデバッグに有用で、開発者が実際に何が起きているかを確認できます。

Primeバッファ共有¶

すでに vgem があり、レンダリングのテスト用の gem ドライバーで、vkms がモード設定側のテストに使われるのと同様です。vkms にバッファ共有サポートを追加することで、これらを一緒にテストし、同期や他の多くの機能をテストできます。また、この機能により、コンポジタが SoC チップで正しく動作するかをテストできます。表示とレンダリングはしばしば 2 つのドライバーで分離されるためです。

出力機能¶

  • 可変リフレッシュレート/FreeSyncのサポート。これはおそらくprimeバッファ共有のサポートが必要で、テスト時にレンダリングをシミュレートするためにvgemフェンスを使用できるようにする必要があります。また、EDIDを指定するためのサポートも必要です。

  • リンク状態のサポートを追加し、例えばDisplayPortリンクが破損した場合にコンポジターがランタイムフォールバックを検証できるようにします。

  • すべてのホットプラグ処理は「ランタイム設定」セクションに記載されています。

eBPFを用いたアトミックチェック¶

アトミックドライバーにはユーザースペースに明示的に露出されていない多くの制限があります。ユーザースペースはアトミックIOCTLを通じて、可能であればTEST_ONLYフラグを使用してこれらの制限を確認できます。これらの制限すべてに対してカスタマイズ可能なコードを追加しようとすると、コンポジターをテストするための作業は無駄に終わります。代わりに、eBPFをサポートしてアトミック状態の任意の検証を可能にし、さまざまな制限を実装するライブラリを提供するのも一つの方法です。

この機能にはプレーンコンポジティング、複数の出力など、いくつかの機能がすでに有効にしておく必要があります。
