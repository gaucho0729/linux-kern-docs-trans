VGAアービトラー¶

グラフィックデバイスはI/Oまたはメモリ空間の範囲を通じてアクセスされます。ほとんどの現代のデバイスはこのような範囲の再配置を許容しますが、一部の「レガシー」VGAデバイスはPCIバス上に実装されると、ISAバス時代と同様の「ハードデコード済み」アドレスが使用されることが一般的です。詳細については、「PCIバスバインディング IEEE Std 1275-1994標準の起動（初期化設定）ファームウェアリビジョン2.1」セクション7「レガシーデバイス」を参照してください。

Xサーバー内のリソースアクセス制御（RAC）モジュール[0]は、複数のレガシーデバイスが同じマシンに存在する場合、レガシーVGA仲裁タスク（他のバス管理タスクも含む）を処理するために存在しました。しかし、これらのデバイスが異なるユーザースペースクライアント（例：並列で動作する2つのサーバー）によってアクセスしようとした場合、アドレス割り当てが衝突します。さらに、理想的にはユーザースペースアプリケーションとしてのXサーバーはバスリソースを制御する役割を担うべきではありません。したがって、Xサーバーの外側で仲裁スキームを実装し、これらのリソースの共有を制御する必要があります。このドキュメントでは、Linuxカーネル用に実装されたVGA仲裁の動作について説明します。

vgaarbカーネル/ユーザースペースABI¶

vgaarbはLinuxカーネルのモジュールです。初期ロード時にすべてのPCIデバイスをスキャンし、VGAデバイスを仲裁処理に追加します。その後、仲裁器はVGAレガシーインストラクションの各デバイスにおけるデコードの有無を有効/無効にします。仲裁器を使用したくない/必要ないデバイスは、明示的に呼び出すことで指定できます。 vga_set_legacy_decoding().

カーネルはクライアントに対してキャラクタデバイスインターフェース（/dev/vga_arbiter）をエクスポートします。このインターフェースのセマンティクスは以下の通りです：

open

アービターユーザーインスタンスを開きます。デフォルトでは、システムのデフォルトVGAデバイスに接続されます。

close

ユーザーアイテントスインスタンスを閉じます。ユーザーアクションで取得したロックを解放します。

読み取り

ターゲットの状態を示す文字列を返します。例：

「<card_ID>,decodes=<io_state>,owns=<io,mem,io+mem,none>,locks=<io_state> (ic,mc)」

IO状態文字列は{io,mem,io+mem,none}の形式で、mcおよびicはそれぞれメモリとIOロックカウント（デバッグ/診断用のみ）です。「decodes」はカードが現在デコードしている内容、「owns」は現在有効な内容、「locks」はこのカードでロックされている内容を示します。カードが挿されている場合でない場合は、card_IDに「invalid」が返され、新しいカードがターゲットに指定されるまで、すべてのコマンドに-ENODEVエラーが返されます。

書き込み

アービターにコマンドを書き込みます。コマンド一覧：

target <card_ID>

ターゲットをカード<card_ID>に切り替えます（以下を参照）

lock <io_state>

ターゲットにロックを取得します（「none」は無効なio_stateです）

trylock <io_state>

ターゲットにブロッキングしないロックを取得 (失敗した場合、EBUSYを返す)

io_stateをアンロック

ターゲットのロックを解放

すべてをアンロック

このユーザーが保持しているターゲットのすべてのロックを解放 (未実装です)

io_stateをデコード

カードのレガシーデコード属性を設定

poll

任意のカードで変更があった場合のイベント (ターゲットに限らない)

card_IDの形式は「PCI:domain:bus:dev.fn」です。これを「default」に設定すると、システムのデフォルトカードに戻ります (TODO: 未実装です)。現在はPCIのみがサポートされていますが、今後ユーザー空間APIが他のバスタイプをサポートする可能性があります (現在のカーネル実装ではサポートされていません)

ロックに関する注意点:

ドライバーは、どのユーザーがどのカードにどのロックを保持しているかを追跡します。これはカーネルのそれと同様のスタッキングをサポートしています。この実装はやや複雑ですが、ユーザー空間の問題に耐えられるようにし、プロセスが終了した際に適切にクリーンアップできるようにします。現在、1つのユーザー (ファイルディスクリプタインスタンス) に対して同時に16枚のカードのロックを発行できます。

デバイスがホット-{un,}plugされた場合、pci_notify()というフックがあり、システムに追加/削除されたことを通知し、自動的にarbiterに追加/削除されます。

DRM、vgacon、その他のドライバーが使用できるように、カーネル内にarbiterのAPIがあります。

VGAリソースの取得とロック

パラメータ

struct pci_dev *pdev

VGAカードのPCIデバイスまたはシステムデフォルトのNULL

unsigned int rsrc

取得およびロックするリソースのビットマスク

int interruptible

割込みによってブロッキングは可能でしょうか？

説明

この関数は指定されたカードのVGAリソースを取得し、それらのリソースをロックします。リソースが「通常」（非レガシ）の場合、アービトラーはそのリソースタイプのレガシデコードを行っているかを確認します。行っている場合、ロックは「レガシリソースロック」に変換されます。

アービトラーは、競合する可能性のあるすべてのVGAカードを検索し、それらのIOおよび/またはメモリアクセスを無効化（必要に応じてP2PブリッジのVGAフォワーディングも含む）します。これにより、リクエストされたリソースを使用できるようになります。その後、カードがこれらのリソースをロックしているとマークされ、IOおよび/またはメモリアクセスが有効化されます（必要に応じて親P2PブリッジのVGAフォワーディングも含む）。

ある競合するカードがすでにリクエストされたリソースの1つをロックしている場合、この関数はブロッキングします（異なるバスセグメントのリソースも含むため、P2PブリッジはVGAメモリとIOを区別しないと推測されます）。ユーザー空間インターフェースでこのブロッキングを割込み信号で中断可能かどうかを指定できます。

割込み時間やアトミックコンテキストでは呼び出せません。カードがすでにリソースを所有している場合、関数は成功します。ネストされた呼び出しはサポートされています（リソースごとのカウンターが維持されます）

成功した場合、次のコマンドでVGAリソースを再解放します vga_put().

成功時は 0、失敗時は負のエラーコードを返します

成功時は0、失敗時は-1

libpciaccess¶

VGA仲裁キャラクターデバイスを使用するため、libpciaccessライブラリ内にAPIが実装されました。システム内の各デバイスに該当するstruct pci_deviceに1つのフィールドが追加されました：

/* the type of resource decoded by the device */
int vgaarb_rsrc;

さらに、pci_systemに以下のフィールドが追加されました：

int vgaarb_fd;
int vga_count;
struct pci_device *vga_target;
struct pci_device *vga_default_dev;

vga_countは、仲裁されているカードの数を追跡するために使用され、たとえば1枚のカードしかない場合、完全に仲裁を回避できます。

以下の関数は、指定されたカードに対してVGAリソースを取得し、それらのリソースをロックします。リソースが「通常」（レガシーでない）場合、アービターはまずその種類のリソースに対してカードがレガシーデコードを行っているかを確認します。確認結果が肯定的であれば、ロックは「レガシーリソースロック」に変換されます。アービターはまず、競合する可能性のあるすべてのVGAカードを検出し、そのIOやメモリアクセスを無効化し、必要に応じてP2PブリッジのVGAフォワーディングも無効化します。これにより、リクエストされたリソースを使用できるようにします。その後、カードがこれらのリソースをロックしているとマークされ、カードのIOおよび/またはメモリアクセスが有効化されます（必要に応じて親P2PブリッジのVGAフォワーディングも有効化されます）。vga_arb_lock()の場合、競合するカードがすでに必要なリソースのいずれか（または異なるバスセグメントのリソース、P2_PFブリッジがVGAメモリとIOを区別しないことから）をロックしている場合、関数はブロックします。カードがすでにリソースを所有している場合は、関数は成功します。vga_arb_trylock()は、ブロック代わりに(-EBUSY)を返します。ネストされた呼び出しはサポートされており（リソースごとのカウンタが維持されます）。

このクライアントのターゲットデバイスを設定します。

int  pci_device_vgaarb_set_target   (struct pci_device *dev);

たとえば、x86で同じバス上の2つのデバイスが異なるリソースをロックしようとしても、どちらも成功します（ロックされます）。異なるバス上のデバイスが異なるリソースをロックしようとしても、最初に試したデバイスだけが成功します。

int  pci_device_vgaarb_lock         (void);
int  pci_device_vgaarb_trylock      (void);

デバイスのリソースをアンロックします。

int  pci_device_vgaarb_unlock       (void);

カードがレガシービジーログIO、レガシービジーログメモリ、両方、またはどちらもデコードしないかをアービトラータに通知します。すべてのカードはデフォルトで両方をデコードしますが、カードドライバー (例: fbdev) がレガシーデコードを無効にした場合、アービトラータに通知してカードをアービトラシオンプロセスから除外し、いつでも割り込みを安全に取得できるようにします。

int  pci_device_vgaarb_decodes      (int new_vgaarb_rsrc);

アービターのデバイスに接続し、構造体を割り当てます

int  pci_device_vgaarb_init         (void);

接続を閉じます

void pci_device_vgaarb_fini         (void);
