drm/amdgpu AMDgpuドライバー¶

drm/amdgpuドライバーは、Graphics Core Next (GCN)アーキテクチャに基づくすべてのAMD Radeon GPUをサポートしています。

モジュールパラメータ¶

amdgpuドライバーがサポートするモジュールパラメータは以下の通りです：

vramlimit (int)

テスト用にVRAMの総容量(MiB)を制限します。デフォルトは0（フルVRAMを使用）です。

vis_vramlimit (int)

テスト用にCPUが見えるVRAMの容量(MiB)を制限します。デフォルトは0（フルCPU見えるVRAMを使用）です。

gartsize (uint)

テスト用にGARTのサイズ(MiB)を制限します（32、64など）。デフォルトは-1（asicに依存）です。

gttsize (int)

テスト用にGTTドメインのサイズ(MiB)を制限します。デフォルトは-1（VRAMが3GB < VRAM < 3/4 RAMの場合はVRAMサイズ、それ以外は3/4 RAMサイズ）です。

moverate (int)

最大バッファ移動レート(MB/s)を設定します。デフォルトは-1（8 MB/s）です。

benchmark (int)

ベンチマークを実行します。デフォルトは0（ベンチマークをスキップ）です。

test (int)

BO GTT->VRAMおよびVRAM->GTT GPUコピーのテストを実行します。デフォルトは0（テストをスキップ、テストを実行するには1を設定）です。

audio (int)

HDMI/DPAudioを設定します。非DCディスプレイ処理にのみ影響します。デフォルトは-1（有効）、0を設定すると無効になります。

disp_priority (int)

ディスプレイ優先度（1 = 通常、2 = 高）を設定します。非DCディスプレイ処理にのみ影響します。デフォルトは0（自動）です。

hw_i2c (int)

hw i2cエンジンを有効にします。非DCディスプレイ処理にのみ影響します。デフォルトは0（無効）です。

pcie_gen2 (int)

PCIE Gen2/3モードを無効にします（0 = 無効、1 = 有効）。デフォルトは-1（自動、有効）です。

msi (int)

メッセージ符号化割り込み（MSI）機能を無効にします（1 = 有効、0 = 無効）。デフォルトは-1（自動、有効）です。

lockup_timeout (string)

GPUスケジューラーのタイムアウト値をミリ秒単位で設定します。

フォーマットは[Non-Compute]または[GFX,Compute,SDMA,Video]のいずれかです。1つまたは複数の値を指定できます。0や負の値は無効とされ、デフォルトのタイムアウト値に調整されます。

  • 1つの値を指定した場合、すべての非コンピュートジョブに適用されます。

  • 複数の値を指定した場合、最初の値はGFX用、2番目の値はCompute用、3番目と4番目の値はSDMAとVideo用になります。

デフォルト（lockup_timeout設定なし）では、すべての非コンピュートジョブ（GFX、SDMA、Video）のタイムアウトは10000ミリ秒です。コンピュートジョブにはタイムアウトが強制されません。

dpm (int)

ダイナミックパワーマネジメント設定を上書きします（0 = 無効、1 = 有効、2 = vega20用sw smuドライバーを有効）。デフォルトは-1（自動）です。

fw_load_type (int)

デバッグ用に異なるファームウェアロードタイプを設定します（0 = ディレクト、1 = SMU、2 = PSP）。デフォルトは-1（自動）です。

aspm (int)

ASPMを無効にする（1 = 有効、0 = 無効）。デフォルトは-1（自動で有効）。

runpm (int)

PX/HGラップトップのdGPUにおける実行時電源管理制御のオーバーライド。amdgpuドライバーは、dGPUがアイドル状態にあるときに動的に電源をオフにできます。デフォルトは-1（自動で有効）。値を0に設定するとこの機能を無効にします。

ip_block_mask (uint)

GPUで有効にするIPブロックをオーバーライドします。各GPUはgfx、ディスプレイ、ビデオなどからなるIPブロックのコレクションです。このパラメータを使用して特定のブロックを無効にできます。注意：IPブロックには固定されたインデックスは存在しません。一部のアシックではIPが存在しない場合や、複数のインスタンスを含む場合があり、アシックによって順序が異なります。アシック上のIP一覧はドライバーログの出力で確認してください。デフォルトは0xffffffff（デバイス全体のブロックを有効）。

bapm (int)

双方向アプリケーション電源管理（BAPM）を動的にCPUとGPU間でTDPを共有するために使用します。値を0に設定すると無効になります。デフォルトは-1（自動で有効）。

deep_color (int)

Deep Colorサポートを有効にするには1を設定します。非DCディスプレイ処理にのみ影響します。デフォルトは0（無効）。

vm_size (int)

GPUのクライアントごとの仮想アドレス空間のサイズをギガバイト単位でオーバーライドします。デフォルトは-1（各アシックごとに自動）。

vm_fragment_size (int)

VMフラグメントサイズをビット単位でオーバーライドします（4、5など。4 = 64K、9 = 2M）。デフォルトは-1（各アシックごとに自動）。

vm_block_size (int)

VMページテーブルサイズをビット単位でオーバーライドします（デフォルトはvm_sizeとハードウェア設定に依存）。デフォルトは-1（各アシックごとに自動）。

vm_fault_stop (int)

デバッグ用にVMエラーで停止します（0 = 一切しない、1 = 最初のエラーで停止、2 = すべてで停止）。デフォルトは0（停止しない）。

vm_debug (int)

VM処理のデバッグ（0 = 無効、1 = 有効）。デフォルトは0（無効）。

vm_update_mode (int)

VM更新モードをオーバーライドします。CPUを使用してVMを更新します（0 = 一切しない、1 = グラフィックスのみ、2 = コンピュートのみ、3 = 両方）。デフォルトは-1（大BAR（LB）システムではコンピュートVMテーブルのみCPUで更新、それ以外は0、一切しない）。

exp_hw_support (int)

実験的なハードウェアサポートを有効にする（1 = 有効）。デフォルトは0（無効）。

dc (int)

ディスプレイコアドライバーをデバッグ用に有効/無効にする（1 = 有効、0 = 無効）。デフォルトは-1（各アシックごとに自動）。

sched_jobs (int)

ソフトウェアキューでサポートされる最大ジョブ数をオーバーライドします。デフォルトは32。

sched_hw_submission (int)

最大ハードウェアサブミッション数をオーバーライドします。デフォルトは2。

ppfeaturemask (hexint)

電源機能を上書きして有効化します。drivers/gpu/drm/amd/include/amd_shared.h にある PP_FEATURE_MASK の enum を参照してください。デフォルトは現在の安定した電源機能のセットです。

forcelongtraining (uint)

再起動時に長時間のメモリトレーニングを強制します。デフォルトはゼロで、再起動時の短時間トレーニングを示します。

pcie_gen_cap (uint)

PCIE 世代速度キャパビリティを上書きします。drivers/gpu/drm/amd/include/amd_pcie.h にある CAIL フラグを参照してください。デフォルトは 0（各 ASIC ごとに自動）です。

pcie_lane_cap (uint)

PCIE レーンキャパビリティを上書きします。drivers/gpu/drm/amd/include/amd_pcie.h にある CAIL フラグを参照してください。デフォルトは 0（各 ASIC ごとに自動）です。

cg_mask (uint)

GPU で有効化されているクロックゲート機能を上書きします（0 = クロックゲートを無効化）。drivers/gpu/drm/amd/include/amd_shared.h にある AMD_CG_SUPPORT フラグを参照してください。デフォルトは 0xffffffff（すべて有効）です。

pg_mask (uint)

GPU で有効化されている電力ゲート機能を上書きします（0 = 電力ゲートを無効化）。drivers/gpu/drm/amd/include/amd_shared.h にある AMD_PG_SUPPORT フラグを参照してください。デフォルトは 0xffffffff（すべて有効）です。

sdma_phase_quantum (uint)

SDMA コンテキストスイッチフェーズクォータニムを上書きします（GPU クロックサイクル x 1K、0 = 変更なし）。デフォルトは 32 です。

disable_cu (charp)

CU（コンピュートユニット）を無効化します（se.sh.cu,… の形式で設定）。デフォルトは NULL です。

virtual_display (charp)

仮想ディスプレイ機能を有効化します。この機能はヘッドレスボードや仮想環境で仮想ディスプレイハードウェアを提供します。xxxx:xx:xx.x,x;xxxx:xx:xx.x,x の形式で設定します（デバイスの PCI アドレスと公開する CRTCs の数）。デフォルトは NULL です。

job_hang_limit (int)

ジョブがハングした時間を許容する時間設定。デフォルトは 0 です。

lbpw (int)

負荷分散パーウォット（LBPW）を有効にする（1 = 有効、0 = 無効）。デフォルトは -1（自動、有効）です。

gpu_recovery (int)

GPU 回復メカニズムを有効にする（1 = 有効、0 = 無効）。デフォルトは -1（自動、SRIOV 以外は無効）です。

emu_mode (int)

エミュレーションモードを有効にする（エミュレータで実行する場合のみ必要）。デフォルトは 0（無効）です。

ras_enable (int)

GPU で RAS 機能を有効にする（0 = 無効、1 = 有効、-1 = 自動（デフォルト））

ras_mask (uint)

有効にする RAS 機能のマスク（デフォルト 0xffffffff）。ras_enable == 1 の場合にのみ有効です。drivers/gpu/drm/amd/amdgpu/amdgpu_ras.h にあるフラグを参照してください。

si_support (int)

SIサポートドライバを設定します。このパラメータはCONFIG_DRM_AMDGPU_SIを設定した後で有効になります。SIアシックの場合、ラデオンドライバーが有効になっている場合、値を0に設定するとラデオンドライバーを使用し、値を1に設定するとAMDGPUドライバーを使用します。デフォルトではラデオンドライバーが利用可能であれば使用し、利用不可な場合はAMDGPUドライバーを使用します。

cik_support (int)

CIKサポートドライバを設定します。このパラメータはCONFIG_DRM_AMDGPU_CIKを設定した後で有効になります。CIKアシックの場合、ラデオンドライバーが有効になっている場合、値を0に設定するとラデオンドライバーを使用し、値を1に設定するとAMDGPUドライバーを使用します。デフォルトではラデオンドライバーが利用可能であれば使用し、利用不可な場合はAMDGPUドライバーを使用します。

smu_memory_pool_size (uint)

SMUデバッグ用途にGTTを確保するために使用します。値を0に設定すると無効になります。実際のサイズは値×256MiBです。例: 0x1 = 256Mバイト、0x2 = 512Mバイト、0x4 = 1Gバイト、0x8 = 2Gバイト。デフォルトは0（無効）です。

async_gfx_ring (int)

異なる優先度または同等の優先度で設定可能なgfxリングを有効にするためのパラメータです。

mcbp (int)

ミッドコマンドバッファプリエンプションを有効にするためのパラメータです。（0 = 無効（デフォルト）、1 = 有効）

discovery (int)

ドライバーがVRAMの上部にあるIPディスカバリー表からハードウェアIP情報を取得できるようにします。（-1 = 自動（デフォルト）、0 = 無効、1 = 有効）

mes (int)

マイクロエンジンスケジューラを有効にするパラメータです。これはgfx、sdma、compute用の新しいハードウェアスケジューリングエンジンです。（0 = 無効（デフォルト）、1 = 有効）

noretry (int)

GPUメモリコントローラーのリトライエラーを無効にするパラメータです。（0 = リトライ有効、1 = リトライ無効、-1 自動（デフォルト））

force_asic_type (int)

すべてのサポートGPUに対してアシックタイプを指定するための非負の値です。

sched_policy (int)

スケジューリングポリシーを設定します。デフォルトはHWS（ハードウェアスケジューリング）でのオーバーサブスクリプションです。値を1に設定するとオーバーサブスクリプションを無効にし、値を2に設定するとHWSを無効にしてキューをHQDに静的に割り当てます。

hws_max_conc_proc (int)

HWSが同時にスケジュールできるプロセスの最大数です。最大値はHWSに割り当てられたVMIDの数であり、これもデフォルト値です。

cwsr_enable (int)

CWSR（コンピュートウェーブストアアンドレジューム）はGPUがコンピュートウェーブの途中でシェーダー実行をプリエンプションできるようにします。デフォルトではこの機能を有効にしています（値1）。値を0に設定すると無効になります。

max_num_of_queues_per_device (int)

デバイスごとの最大キュー数です。有効な設定範囲は1から4096です。デフォルトは4096です。

send_sigterm (int)

未処理例外が発生した際にHSAプロセスにSIGTERMを送信します。デフォルトではSIGTERMを送信せず、dmesgにエラーを出力します。値を1に設定するとSIGTERMを送信します。

debug_largebar (int)

debug_largebarを1に設定すると、非大容量バーシステムでも大容量バー機能をシミュレートできます。これにより、ROCmアプリケーションに報告されるVRAMサイズが可視サイズ（通常256MB）に制限されます。デフォルト値は0で、無効です。

ignore_crat (int)

KFD初期化時にCRATテーブルを無視します。デフォルトでは、KFDはACPI CRATテーブルを使用してAMD APUsに関する情報を取得します。このオプションは、CRATテーブルが破損しているシステムでのワークアラウンドとして機能できます。

デフォルトは自動（asicタイプ、iommu_v2、cratテーブルに応じてCRATを使用するかどうかを決定）

halt_if_hws_hang (int)

HWSハングが検出された場合に停止します。デフォルト値0はハング時の停止を無効とします。設定1でハング時の停止を有効にします。

hws_gws_support(bool)

ファームウェアバージョンのチェックに関係なく、HWSがGWSバリアをサポートしていると仮定します。デフォルト値: false（MEC2ファームウェアバージョンのチェックに依存）

queue_preemption_timeout_ms (int)

キューのプリエンプションタイムアウト（1 = 最小値、9000 = デフォルト）

debug_evictions(bool)

エヴィクションの原因を特定するのに役立つ追加のデバッグメッセージを有効にします

no_system_mem_limit(bool)

システムメモリ制限を無効化し、複数プロセスの共有メモリをサポートします

dcfeaturemask (uint)

表示機能の有効化を上書きします。drivers/gpu/drm/amd/include/amd_shared.hのDC_FEATURE_MASK enumを参照してください。デフォルトは現在の安定した表示機能のセットです。

dcdebugmask (uint)

表示機能の有効化を上書きします。drivers/gpu/drm/amd/include/amd_shared.hのDC_DEBUG_MASK enumを参照してください。

abmlevel (uint)

DC有効なハードウェアで使用されるデフォルトのABM（アダプティブバックライトマネジメント）レベルを上書きします。DMCUがサポートされロードされている必要があります。有効なレベルは0-4です。値0はABMをデフォルトで無効にします。値1-4はABMアルゴリズムによる最大許容明るさの減少を制御し、1は最小の減少、4は最大の減少を表します。

デフォルトは0、または無効です。ユーザースペースは起動後にこのレベルを上書きできます。

tmz (int)

信頼されたメモリゾーン（TMZ）は、メモリに書き込まれたり読み出されたりするデータを保護する方法です。

デフォルト値: 0（オフ）。TODO: 完了するまでautoに変更します。

reset_method (int)

GPUリセット方法（-1 = 自動（デフォルト）、0 = 伝統的、1 = mode0、2 = mode1、3 = mode2、4 = baco）

bad_page_threshold (int)

不良ページ閾値は、RAS ECCによって検出された不良ページの閾値を指定します。ECCによって検出された不良ページの合計が閾値を超えるとGPUが不良状態に移行し、ユーザーの追加の確認のために残します。

コアドライバインフラストラクチャ¶

このセクションではコアドライバインフラストラクチャについて説明します。

メモリドメイン¶

AMDGPU_GEM_DOMAIN_CPU GPUにアクセスできないシステムメモリ。このプール内のメモリは、必要に応じてディスクにスワップされる可能性があります。

AMDGPU_GEM_DOMAIN_GTT GPUがアクセス可能なシステムメモリで、gartを通じてGPUの仮想アドレス空間にマッピングされます。gartメモリは非連続のシステムメモリページを線形化し、GPUが線形化された形式でシステムメモリにアクセスできるようにします。

AMDGPU_GEM_DOMAIN_VRAM ローカルなビデオメモリ。APUの場合、BIOSによって切り出されたメモリです。

AMDGPU_GEM_DOMAIN_GDS シャドウスレッド間でデータを共有するために使用されるグローバルなオンチップデータストレージ。

AMDGPU_GEM_DOMAIN_GWS グローバルなウェーブ同期、デバイス上のすべてのウェーブの実行を同期するために使用されます。

AMDGPU_GEM_DOMAIN_OA 3Dまたはコンピュートエンジンがデータを追加する際に使用される順序付きアペンド。

バッファオブジェクト¶

バッファオブジェクトを操作するインターフェースを定義します。 amdgpu_bo バッファオブジェクトはドライバー（VRAM、システムメモリなど）が使用するメモリを表します。ドライバーはユーザー空間にDRM/GEM APIを提供し、これらはインターフェースを使用してバッファオブジェクトを生成・削除・設定します。これらはカーネルのTTMメモリマネージャーによって管理されます。また、gfx、uvdなど、カーネルクライアントも内部でこれらのインターフェースを使用してGPUに使用されるカーネル管理アロケーションを行います。

MMU Notifier¶

一貫性のあるuserptrの処理には、プロセスのページテーブルの更新をドライバに通知するMMU通知レジスタを登録します。

誰かがページテーブルを無効化しようとすると、そのページに関するすべての操作が完了するまで更新をブロックし、読み取り専用でない場合はそのページをアクセス済みとし、汚染（dirty）としてマークします。

関連するuserptrを使用した新しいコマンドの送信は、すべてのページテーブル無効化が完了し、再び一貫性のあるプロセスアドレス空間が見られるまで遅延されます。

AMDGPU バーチャルメモリ¶

GPUVMは古いアシックスのレガシーアルゴリズムに似ていますが、GPU全体にわたる単一のグローバルgartテーブルではなく、常に複数のVMページテーブルが有効になっています。VMページテーブルにはVRAMページとシステムメモリページの混在が可能で、システムメモリページはスヌープ（キャッシュされたシステムページ）または非スヌープ（非キャッシュされたシステムページ）としてマッピングできます。各VMにはIDが割り当てられ、各VMIDにはページテーブルが関連付けられます。コマンドバッファを実行する際、カーネルはリングにそのコマンドバッファに使用するVMIDを指定します。VMIDはコマンドが送信されるたびに動的に割り当てられます。ユーザースペースドライバーは独自のアドレス空間を維持し、カーネルはコマンドバッファを送信しVMIDが割り当てられた際にページテーブルを設定します。Cayman/Trinityは一度に最大8つのアクティブなVMをサポートし、SIは16個をサポートします。

割込み処理¶

GPUハードウェア内で生成される割込みリクエストは、amdgpu IRQハンドラに渡され、そのハンドラが割込みのソースと種類を検出し、対応するハンドラを割り当てます。割込み処理にkernel関数の呼び出しが必要で、処理がスリープする可能性がある場合は、workハンドラに処理を委譲します。

モジュールパラメータでMSI機能が無効になっていない場合、MSIサポートが有効になります。

他のドライバによって駆動されるGPU割込みソースについては、IRQドメインサポートが使用され（仮想IRQとハードウェアIRQのマッピングが行われます）。

これはホットプラグイベントのワークハンドラ（すべてのASIC）。ホットプラグ割込みがあった場合、IRQハンドラからこのワークがスケジュールされます。このワークはコネクタテーブルを走査し、各コネクタに対してホットプラグハンドラを呼び出します。その後、DRMホットプラグイベントを送信してユーザー空間を通知します。

IPブロック¶

AMDGPU XGMIサポート¶

AMDGPU XGMIサポート

XGMIは、複数のGPUカードを均一なメモリ空間に結合する高速インターコネクトで、このメモリ空間は共通のハービーIDと個々のノードIDで構成され、どちらも64ビットの数値です。

ファイルxgmi_device_idには、GPUデバイスごとの一意のIDが含まれており、/sys/class/drm/card${cardno}/device/ディレクトリに保存されます。

デバイスディレクトリ内にサブディレクトリ「xgmi_hive_info」が作成され、ハービーIDとノードリストが含まれます。

ハービーIDは以下の場所に保存されています：

/sys/class/drm/card${cardno}/device/xgmi_hive_info/xgmi_hive_id

ノード情報は以下の数値付きディレクトリに保存されています：

/sys/class/drm/card${cardno}/device/xgmi_hive_info/node${nodeno}/xgmi_device_id

各デバイスは、自身のxgmi_hive_infoディレクトリを持ち、ノードサブディレクトリの鏡像セットが含まれます。

XGMIメモリ空間は、各ノードの2の累乗にパディングされたVRAM領域を連続的に追加することで構築されます。

AMDGPU RASサポート¶

AMDGPU RASインターフェースはsysfs（情報取得用）とdebugfs（エラーインジェクション用）経由で公開されます。

RAS debugfs/sysfs制御およびエラーインジェクションインターフェース¶

struct ras_debug_ifを受け取るためのインターフェースで、2つのメンバを持ちます。

最初のメンバ：ras_debug_if::headまたはras_debug_if::inject。

headは、制御対象となるIPブロックを示します。

headには4つのメンバがあり、それらはblock、type、sub_block_index、nameです。block：制御対象のIP。type：有効/無効/インジェクトされるエラーの種類。sub_block_index：一部のIPにはサブコンポーネントがあり、例えばGFX、sDMAなど。name：IPの名前。

injectにはheadより2つのメンバが追加され、それらはaddress、valueです。名前の通り、inject操作はaddressにvalueを書き込みます。

第二のメンバ: struct ras_debug_if::op。これは3種類の操作を持っています。

  • 0: ブロックのRASを無効化する。::headをデータとして使用する。

  • 1: ブロックのRASを有効化する。::headをデータとして使用する。

  • 2: ブロックにエラーを注入する。::injectをデータとして使用する。

インターフェースの使用方法は？

プログラム

コードにstruct ras_debug_ifをコピーし、初期化します。この構造体を制御ノードに書き込みます。

シェル

echo op block [error [sub_block address value]] > .../ras/ras_ctrl

パラメータ:

op: 無効化、有効化、エラー注入

無効化: ブロックのみが必要 有効化: ブロックとエラーが必要 エラー注入: エラー、アドレス、値が必要

ブロック: umc, sdma, gfx, ………

ras_block_string[]を参照してください。

エラー: ue, ce

ue: 複数の訂正不能エラー ce: 単一の訂正可能エラー

sub_block:

サブブロックインデックス。サブブロックがない場合は0を渡します。

bashコマンドの例:

echo inject umc ue 0x0 0x0 0x0 > /sys/kernel/debug/dri/0/ras/ras_ctrl
echo inject umc ce 0 0 0 > /sys/kernel/debug/dri/0/ras/ras_ctrl
echo disable umc > /sys/kernel/debug/dri/0/ras/ras_ctrl

結果を確認する方法は？

無効化/有効化の場合、/sys/class/drm/card[0/1/2…]/device/ras/featuresにRAS機能を確認してください。

エラー注入の場合、/sys/class/drm/card[0/1/2…]/device/ras/[gfx/sdma/…]_err_countに該当するエラー数を確認してください。

注意

操作はサポートされているブロックのみ許可されます。ras_maskを確認してください: /sys/module/amdgpu/parameters/ras_mask。特定のASICでRASをサポートするブロックを確認できます。

RAS: 不可逆エラー時の再起動動作¶

通常、訂正不能エラーが発生した場合、ドライバーはGPUをリセットして回復します。ただし、回復不能なエラーが発生した場合、ドライバーはそのイベントでシステムを自動的に再起動するインターフェースを提供します。

debugfsに以下のファイルがこのインターフェースを提供します: /sys/kernel/debug/dri/[0/1/2…]/ras/auto_reboot

使用方法:

echo true > .../ras/auto_reboot

RASエラー数sysfsインターフェース¶

ユーザーは、/sys/class/drm/card[0/1/2…]/device/ras/[gfx/sdma/…]_err_countを通じてGPUの各IPブロックのエラー数を読み取ることができます。

複数行出力され、訂正不能（ue）および訂正可能（ce）のエラー数を報告します。

1行のフォーマットは以下の通りです、

[ce|ue]: カウント

例:

ue: 0
ce: 1

RAS EEPROM debugfsインターフェース¶

一部のボードには、vramでECCエラーを経験した不良ページの一覧を永続的に保存するEEPROMが含まれています。このインターフェースは、テスト後のエラー注入をリセットする方法を提供します。

使用方法:

echo 1 > ../ras/ras_eeprom_reset

RAS VRAM不良ページsysfsインターフェース¶

ユーザーは、/sys/class/drm/card[0/1/2…]/device/ras/gpu_vram_bad_pagesを通じてGPUのvramの不良ページを読み取ることができます。

複数行出力され、各行が1つのGPUページを表します。

1行のフォーマットは以下の通りです、gpu pfn : gpu page size : flags

gpu pfnおよびgpu page sizeは16進形式で表示されます。flagsは以下の文字のいずれかです、

R: 保留中、このGPUページは使用不可です。

P: 保留待ち、このGPUページは不良とマークされており、次のpage_reserveウィンドウで保留されます。

F: 保留できません。このGPUページは特定の理由により保留できません。

例:

0x00000001 : 0x00001000 : R
0x00000002 : 0x00001000 : P

GPU sysfs パワー状態インターフェース¶

GPUの電源制御はsysfsファイル経由で公開されています。

power_dpm_state¶

power_dpm_stateファイルはレガシーインターフェースであり、後方互換性のためにのみ提供されています。amdgpuドライバーは特定の電源関連パラメータの調整にsysfs APIを提供しており、この機能はpower_dpm_stateファイルを用いて実行されます。このファイルは以下の引数を受け取ります:

  • バッテリー

  • バランス

  • パフォーマンス

バッテリー

古いGPUではvbiosがバッテリー運用用の特別な電源状態を提供していました。バッテリーを選択するとこの状態に切り替わります。新しいGPUではこの機能が提供されなくなり、このオプションは無効です。

バランス

古いGPUではvbiosがバランス運用用の特別な電源状態を提供していました。バランスを選択するとこの状態に切り替わります。新しいGPUではこの機能が提供されなくなり、このオプションは無効です。

パフォーマンス

古いGPUではvbiosがパフォーマンス運用用の特別な電源状態を提供していました。パフォーマンスを選択するとこの状態に切り替わります。新しいGPUではこの機能が提供されなくなり、このオプションは無効です。

power_dpm_force_performance_level¶

amdgpuドライバーは特定の電源関連パラメータの調整にsysfs APIを提供しており、この機能はpower_dpm_force_performance_levelファイルを用いて実行されます。このファイルは以下の引数を受け取ります:

  • auto

  • low

  • high

  • 手動

  • profile_standard

  • profile_min_sclk

  • profile_min_mclk

  • profile_peak

auto

「auto」を選択すると、ドライバーが現在の条件に基づいて最適な電源プロファイルを選択します。

low

「low」を選択すると、クロックが最低電源状態に強制されます。

high

「high」を選択すると、クロックが最高電源状態に強制されます。

手動

手動モードが選択された場合、ユーザーはsysfsファイルpp_dpm_mclk、pp_dpm_sclk、pp_dpm_pcieを通じて各クロックドメインごとの有効な電力状態を手動で調整でき、pp_power_profile_mode sysfsファイルを通じて電力状態の遷移ヒューリスティクスを調整できます。

profile_standard profile_min_sclk profile_min_mclk profile_peak

プロファイリングモードが選択された場合、クロックゲートと電力ゲートが無効となり、クロックがさまざまなプロファイリングケースに応じて設定されます。特定のワークロードをプロファイリングする際、クロックや電力ゲートによるクロック変動が結果に影響を与えないようにする場合はこのモードを推奨します。profile_standardはアシックごとに異なる固定クロックレベルを設定します。profile_min_sclkはsclkを最低レベルに固定します。profile_min_mclkはmclkを最低レベルに固定します。profile_peakはすべてのクロック（mclk、sclk、pcie）を最高レベルに設定します。

pp_table¶

amdgpuドライバは新しいパワープレイテーブルをアップロードするためのsysfs APIを提供しています。この機能はpp_tableファイルを使用します。ファイルを読み込むと現在のパワープレイテーブルがダンプされ、ファイルに書き込むと新しいパワープレイテーブルをアップロードし、そのテーブルを使用してパワープレイを再初期化しようとします。

pp_od_clk_voltage¶

amdgpuドライバは、パワーステート内の各パワーレベルにおけるクロックと電圧を調整するためのsysfs APIを提供しています。この機能はpp_od_clk_voltageファイルを使用します。

実際のメモリコントローラークロックレートが公開されるため、DRAMの有効メモリクロックではありません。これを変換するには以下の式を使用してください：

クロック変換（MHz）：

HBM：有効メモリクロック = メモリコントローラークロック × 1

G5：有効メモリクロック = メモリコントローラークロック × 1

G6：有効メモリクロック = メモリコントローラークロック × 2

DRAMデータレート（MT/s）：

HBM：有効メモリクロック × 2 = データレート

G5：有効メモリクロック × 4 = データレート

G6：有効メモリクロック × 8 = データレート

帯域幅（MB/s）：

データレート × VRAMビット幅 / 8 = メモリ帯域幅

いくつかの例：

RX460のG5：

メモリコントローラークロック = 1750 MHz

有効メモリクロック = 1750 MHz × 1 = 1750 MHz

データレート = 1750 × 4 = 7000 MT/s

メモリ帯域幅 = 7000 × 128ビット / 8 = 112000 MB/s

RX5700のG6：

メモリコントローラークロック = 875 MHz

有効メモリクロック = 875 MHz × 2 = 1750 MHz

データレート = 1750 × 8 = 14000 MT/s

メモリ帯域幅 = 14000 × 256ビット / 8 = 448000 MB/s

< ベガ10および以前のアシック >

ファイルを読み込むと表示される内容：

  • OD_SCLKでラベル付けされたエンジンクロックレベルと電圧の一覧

  • OD_MCLKでラベル付けされたメモリクロックレベルと電圧の一覧

  • sclk、mclk、および電圧の有効な範囲一覧でラベル付けされたOD_RANGE

これらの設定を手動で調整するには、まずpower_dpm_force_performance_levelを使用して「manual」を選択します。各レベルの新しい値を設定するには、ファイルに「s/m level clock voltage」という文字列を含む文字列を書き込みます。例: 「s 1 500 820」はsclkレベル1を500 MHzで820 mVに更新します。「m 0 350 810」はmclkレベル0を350 MHzで810 mVに更新します。必要なすべての状態を編集した後は、ファイルに「c」（コミット）を書き込みます。デフォルトの電源レベルに戻す場合は、ファイルに「r」（リセット）を書き込みます。

<Vega20以降のASIC向け>

ファイルを読み込むと表示される内容：

  • エンジンクロックの最小値と最大値をラベル付けしたOD_SCLK

  • メモリクロックの最大値をラベル付けしたOD_MCLK

  • 3つの<周波数、電圧>ポイントでラベル付けされたOD_VDDC_CURVE。これらはsclk電圧曲線を校正するために使用できます。

  • sclk、mclk、および電圧曲線ポイントの有効な範囲一覧でラベル付けされたOD_RANGE

これらの設定を手動で調整するには:

  • まずpower_dpm_force_performance_levelを使用して「manual」を選択します

  • クロック周波数の設定では、ファイルに「s/m index clock」という文字列を含む文字列を書き込み、新しい値を入力します。インデックスは最小クロックを設定する場合は0、最大クロックを設定する場合は1になります。例: 「s 0 500」は最小sclkを500 MHzに更新します。「m 1 800」は最大mclkを800 MHzに更新します。

    sclk電圧曲線では、ファイルに「vc point clock voltage」という文字列を含む文字列を書き込み、新しい値を入力します。ポイントは0、1、2でインデックスされます。例: 「vc 0 300 600」はポイント1を300 MHzで600 mVに更新します。「vc 2 1000 1000」はポイント3を1000 MHzで1000 mVに更新します。

  • 必要なすべての状態を編集した後は、ファイルに「c」（コミット）を書き込みます

  • デフォルトの電源レベルに戻す場合は、ファイルに「r」（リセット）を書き込みます

pp_dpm_*¶

amdgpuドライバーは、特定の電源状態における有効な電源レベルを調整するためのsysfs APIを提供しています。このためにはpp_dpm_sclk、pp_dpm_mclk、pp_dpm_socclk、pp_dpm_fclk、pp_dpm_dcefclk、pp_dpm_pcieのファイルが使用されます。

pp_dpm_socclkおよびpp_dpm_dcefclkインターフェースはVega10以降のASIC向けにのみ利用可能です。pp_dpm_fclkインターフェースはVega20以降のASIC向けにのみ利用可能です。

ファイルを読み込むと、電源状態内の有効な電源レベルとそれらのレベルのクロック情報が表示されます。

これらの状態を手動で調整するには、まず power_dpm_force_performance_level を使用して manual を選択します。次に、各レベルに新しい値を入力するため、"echo xx xx xx > pp_dpm_sclk/mclk/pcie" という文字列を入力します。例:

echo "4 5 6" > pp_dpm_sclk

これにより、sclk レベル 4、5、6 が有効になります。

注意: dcefclk の最大 DPM レベルへの変更は現在サポートされていません

pp_power_profile_mode¶

amdgpu ドライバーは、電源状態での電源レベル間の切り替えに関するヒューリスティクスを調整するための sysfs API を提供しています。このファイルは pp_power_profile_mode を使用します。

このファイルを読み込むと、すべての予定された電源プロファイルとそのプロファイルに関連するヒューリスティクスの設定の一覧が表示されます。

プロファイルを選択するか、カスタムプロファイルを作成するには、まず power_dpm_force_performance_level を使用して manual を選択します。予定されたプロファイルの番号を pp_power_profile_mode に書き込むと、そのヒューリスティクスが有効になります。カスタムのヒューリスティクスセットを作成するには、カスタムプロファイルの番号を先頭にし、各ヒューリスティクスパラメータの設定を含む文字列をファイルに書き込みます。アシックファミリによってヒューリスティクスパラメータは異なります。

*_busy_percent¶

amdgpu ドライバーは、GPU のビジー状態をパーセンテージで読み取るための sysfs API を提供しています。このファイルは gpu_busy_percent を使用します。SMU ファームウェアは、IP コアの集約アクティビティレベルに基づいて負荷のパーセンテージを計算します。

amdgpu ドライバーは、VRAM のビジー状態をパーセンテージで読み取るための sysfs API を提供しています。このファイルは mem_busy_percent を使用します。SMU ファームウェアは、IP コアの集約アクティビティレベルに基づいて負荷のパーセンテージを計算します。

gpu_metrics¶

amdgpu ドライバーは、現在の GPU メトリクスデータを取得するための sysfs API を提供しています。このファイルは gpu_metrics を使用します。ファイルを読み込むと、現在のすべての GPU メトリクスデータがダンプされます。

これらのデータには温度、周波数、エンジン利用率、電力消費、スロットラー状態、ファン速度、CPU コア統計情報（APU 限定）が含まれます。これにより、すべてのセンサーの同時スナップショットが得られます。

GPU プロダクト情報¶

特定のカードでは sysfs を介して GPU の情報を取得できます

product_name¶

amdgpu ドライバーは、デバイスのプロダクト名を報告するための sysfs API を提供しています。このファイルは serial_number を使用し、FRU から取得したプロダクト名を返します。注意: これは特定のサーバー用カードのみで利用可能です

product_number¶

amdgpu ドライバーは、デバイスのプロダクト名を報告するための sysfs API を提供しています。このファイルは serial_number を使用し、FRU から取得したプロダクト名を返します。注意: これは特定のサーバー用カードのみで利用可能です

serial_number¶

amdgpuドライバは、デバイスのシリアル番号を報告するためのsysfs APIを提供します。serial_numberファイルはこの目的で使用され、FRUから取得したシリアル番号を返します。注意: この機能は特定のサーバー用カードにのみ利用可能です

unique_id¶

amdgpuドライバは、GPUに一意のIDを提供するためのsysfs APIを提供します。unique_idファイルはこの目的で使用されます。これにより、マシンごとに一貫して保持されるユニークIDが提供されます

注意: この機能はGFX9以降のデバイスでのみ動作します。非対応のASIC(GFX8および以前)ではこのファイルは存在しません

GPUメモリ使用状況情報¶

さまざまなメモリ使用状況はsysfs経由でアクセス可能です

mem_info_vram_total¶

amdgpuドライバは、デバイス上の現在の総VRAM量を報告するためのsysfs APIを提供します。mem_info_vram_totalファイルはこの目的で使用され、VRAMの総容量（バイト単位）を返します

mem_info_vram_used¶

amdgpuドライバは、デバイス上の現在の総VRAM量を報告するためのsysfs APIを提供します。mem_info_vram_usedファイルはこの目的で使用され、現在使用中のVRAMの総量（バイト単位）を返します

mem_info_vis_vram_total¶

amdgpuドライバは、デバイス上の現在の可視VRAM総量を報告するためのsysfs APIを提供します。mem_info_vis_vram_totalファイルはこの目的で使用され、可視VRAMの総容量（バイト単位）を返します

mem_info_vis_vram_used¶

amdgpuドライバは、現在の可視VRAM使用量を報告するためのsysfs APIを提供します。mem_info_vis_vram_usedファイルはこの目的で使用され、現在使用中の可視VRAMの総量（バイト単位）を返します

mem_info_gtt_total¶

amdgpuドライバは、GTTの現在の総サイズを報告するためのsysfs APIを提供します。mem_info_gtt_totalファイルはこの目的で使用され、GTTブロックの総サイズ（バイト単位）を返します

mem_info_gtt_used¶

amdgpuドライバは、現在のGTT使用量を報告するためのsysfs APIを提供します。mem_info_gtt_usedファイルはこの目的で使用され、GTTブロックの現在の使用量（バイト単位）を返します

PCIe使用状況情報¶

pcie_bw¶

amdgpuドライバは、GPUがPCIe経由で最後の1秒間に受信および送信したデータ量を推定するためのsysfs APIを提供します。pcie_bwファイルはこの目的で使用され、パフォーマンスカウンタが受信および送信メッセージ数をカウントし、その値を返します。最大ペイロードサイズ（mps）も返します。注意: 各パケットのサイズを簡単に取得することはできませんので、PCIe帯域幅の使用量を迅速に推定するため、最大ペイロードサイズ（mps）を出力しています

pcie_replay_count¶

amdgpuドライバーは、PCIe再送信（NAK）の総数を報告するためのsysfs APIを提供しています。pcie_replay_countというファイルはこの目的で使用され、生成されたNAKと受信したNAKの合計を返します。
