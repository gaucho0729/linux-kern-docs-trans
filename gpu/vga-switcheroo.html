VGAスイッチーロー¶

vga_switcherooは、ラップトップのハイブリッドグラフィックス用のLinuxのサブシステムです。これらは2つのタイプに分類されます:

  • muxed: マルチプレクサチップを使用してGPU間で出力を切り替えるデュアルGPU。

  • muxless: デュアルGPUですが、出力に接続されているのは1つのGPUのみです。もう一方のGPUはレンダリングをオフロードするためのもので、結果はPCIe経由でフレームバッファにコピーされます。LinuxではDRI PRIMEでこの機能をサポートしています。

ハイブリッドグラフィックスは2000年代後半に登場し、初期はすべてmuxedの設計でした。新しいラップトップではコストのためmuxlessのアーキテクチャに移行しています。ただし、MacBook Proはmuxを引き続き使用しています。muxは多様な機能を持ち、一部はパネルのみを切り替え、他は外部ディスプレイも切り替え可能です。また、一部はすべてのディスプレイピンを一度に切り替え、他はDDCラインのみを切り替えることができます。(EDIDプローブを_inactive GPUに許可するため) さらに、muxはディスクリートGPUの電源をオフにするためにも使用されます。

DRMドライバーはGPUをvga_switcherooに登録し、それ以降はクライアントと呼ばれます。muxはハンドラと呼ばれます。muxlessのマシンでは、ディスクリートGPUの電源状態を制御するハンドラも登録されます。->switchtoコールバックは明確な理由でノーオペです。ディスクリートGPUにはHDAコントローラーが搭載され、HDMI/DPのオーディオ信号を処理します。これもクライアントとして登録され、vga_switcherooがディスクリートGPUの電源状態を変更時のスリープ/再起動順序を適切に管理できます。結果として最大で3つのクライアントが存在します: 2つのvgaクライアント(GPU)と1つのオーディオクライアント(ディスクリートGPU上)。コードは2つのGPU以上をサポートする準備ができています。

現在出力が切り替えられているGPUはvga_switcherooではアクティブクライアントと呼ばれ、使用されていないGPUはインアクティブクライアントです。インアクティブクライアントのDRMドライバーがロードされると、パネルのEDIDをプローブできず、VBIOSに表示モードを提供する必要があります。VBIOSのモードが不正確だったり、VBIOSが存在しない場合(これはMacBook Proでよく見られます)、ハンドラがこの機能をサポートする場合、クライアントはDDCラインを一時的に自身に切り替えることができます。出力全体を切り替えるのではなくDDCラインのみを切り替えることで、不要な画面のちらみを防ぎます。

使用モード¶

手動スイッチングと手動電源制御¶

この使用方法では、ファイル /sys/kernel/debug/vgaswitcheroo/switch を読み込むことで現在の vga_switcheroo 状態を取得でき、このファイルに書き込むことで状態を変更できます。このファイルは、2つのGPUドライバと1つのハンドラが vga_switcheroo に登録された時点で表示されます。以下のコマンドが理解されます:

  • OFF: 使用していないデバイスを電源を切ります。

  • ON: 使用していないデバイスを電源を付けます。

  • IGD: 統合グラフィックスデバイスに切り替えます。統合GPUを必要に応じて電源を付けて、ディスクリートGPUを電源を切ります。前提条件として、ユーザー空間プロセス（例: Xorg、alsactl）がGPUまたはオーディオクライアントのデバイスファイルを開いていない必要があります。スイッチが失敗した場合、ユーザーは lsof(8) または fuser(1) を /dev/dri/ および /dev/snd/controlC1 に対して実行して、スイッチを妨げるプロセスを特定できます。

  • DIS: ディスクリートグラフィックスデバイスに切り替えます。

  • DIGD: 統合グラフィックスデバイズへの遅延スイッチです。最後のユーザー空間プロセスがGPUおよびオーディオクライアントのデバイスファイルを閉じた時点でスイッチを行います。

  • DDIS: ディスクリートグラフィックスデバイスへの遅延スイッチです。

  • MIGD: マルチプレクサのみのスイッチで統合グラフィックスデバイスに切り替えます。コンソールのリマップやGPUの電源状態の変更を行いません。統合GPUが現在オフの場合、画面が黒くなります。オンの場合、VRAMに保存されている内容が表示されます。いずれの場合も、ユーザーは盲目的にコマンドを入力して戻す必要があります。

  • MDIS: マルチプレクサのみのスイッチでディスクリートグラフィックスデバイスに切り替えます。

GPUの電源状態がドライバのランタイムPMによって制御されている場合、ONおよびOFFコマンドは無効です（次のセクションを参照）。

マルチプレクサなしのマシンでは、IGD/DIS、DIGD/DDISおよびMIGD/MDISコマンドは使用しないでください。

ドライバ電源制御¶

この使用方法では、ディスクリートGPUはドライバのランタイムPMの判断で自動的に電源をオン/オフします。マルチプレクサ付きマシンでは、ユーザーはdebugfsインターフェースを通じてマルチプレクサの状態を依然として影響を与えることができますが、ディスクリートGPUのONおよびOFFコマンドは無効になります。

このモードはNvidia HybridPower/OptimusおよびATI PowerXpressのデフォルトです。カーネルコマンドラインに nouveau.runpm=0、radeon.runpm=0 または amdgpu.runpm=0 を指定すると無効になります。

GPUがスリープ状態になった後、ハンドラを呼び出してGPUの電源を切る必要があります。同様に、GPUが再開する前に電源を復元する必要があります。これは、 vga_switcheroo_init_domain_pm_ops()によって実現され、GPUのスリープ/再開関数にハンドラの必要な呼び出しを追加します。

オーディオデバイスが再開した後、GPUを起動する必要があります。これは、PCIのクイックが呼び出すことで実現されます。 device_link_add() GPUへの依存関係を宣言します。これにより、オーディオデバイスが使用されている間とその間ずっとGPUがアクティブなまま維持されます。

MUX機種では、MUXが最初にディスクリートGPUに切り替えられている場合、起動後にGPUが電源を切られた際にユーザーは黒い画面に陥ります。回避策として、ランタイムスリープ時にMUXを統合GPUに強制的に切り替えます、参照。 https://bugs.freedesktop.org/show_bug.cgi?id=75917

struct vga_switcheroo_handler¶

ハンドラコールバック

定義

struct vga_switcheroo_handler {
  int (*init)(void);
  int (*switchto)(enum vga_switcheroo_client_id id);
  int (*switch_ddc)(enum vga_switcheroo_client_id id);
  int (*power_state)(enum vga_switcheroo_client_id id, enum vga_switcheroo_state state);
  enum vga_switcheroo_client_id (*get_client_id)(struct pci_dev *pdev);
};

メンバ

init

ハンドラの初期化。任意。vga_switcherooが有効になったときに呼び出されます（つまり、2つのVGAクライアントが登録されたとき）。ハンドラがVGAクライアントの存在に依存する遅延初期化を行うことができます。現在はradeonおよびamdgpuドライバのみがこの機能を使用しています。返却値は無視されます。

switchto

指定されたクライアントに出力スイッチを切り替える。必須。muxlessマシンではこれは無効です。0を返すと成功、それ以外は失敗（その場合、スイッチは中止されます）

switch_ddc

指定されたクライアントにDDCラインを切り替える。任意。成功時は前のDDC所有者を返し、失敗時は負の整数を返す

power_state

指定されたクライアントの電源を切るか復元する。任意。返却値は無視されます

get_client_id

指定されたPCIデバイスが統合型かディスクリート型GPUかを判定する。必須

説明

ハンドラコールバック。多重器自体。The switchto および get_client_id メソッドは必須で、他のすべてはNULLに設定可能です。

クライアントコールバック

定義

struct vga_switcheroo_client_ops {

メンバ

カードのスリープ/再開に相当する処理を行う。必須。これはディスクリートGPUの電源を切るのではなく、ハンドラの責任です

reprobe

出力のポーリング。任意。GPUを wakeup し、出力スイッチをそのデバイスに切り替えた後呼び出されます

can_switch

デバイスが今すぐスイッチ可能かどうかを判定する。必須。クライアントはユーザー空間プロセスがそのデバイスファイルを開いている場合、falseを返す必要があります

gpu_bound

GPUがバインドされたときにクライアントIDをオーディオクライアントに通知する

説明

クライアントコールバック。クライアントはGPUまたはGPU上のオーディオデバイスのいずれかです。The set_gpu_state および can_switch メソッドは必須で、 reprobe NULLに設定可能です。オーディオクライアントの場合、The reprobe memberは偽です。一方で、 gpu_bound はオーディオクライアント専用で、GPUクライアントには使用されません。

ハンドラ¶

apple-gmuxハンドラ¶

gmuxは、MacBook Proに内蔵されたマイクロコントローラーで、デュアルGPUをサポートしており、A Lattice XP2 はプレレタインモデルに搭載され、 Renesas R4F2113 はレタインモデルに搭載されています。

(MacPro6,1 2013もgmuxを搭載していますが、なぜ搭載されているのかは不明です。このモデルはデュアルGPUを搭載していますが、内蔵ディスプレイは搭載されていません。)

gmuxは南橋のLPCバスに接続されており、マイクロコントローラーによってI/Oポートのアクセス方法が異なります。プレレタイン用のgmuxにアクセスするドライバ関数はinfixed _pio_、レタイン用のgmuxにアクセスするドライバ関数もinfixed _index_.

gmuxはさらに南橋のGPIOピンに接続されており、ACPI GPEをトリガーすることができました。MBP5 2008/09ではNvidia MCP79のGPIOピン22、その後のモデルではIntel PCHのGPIOピン6を使用します。GPEは単に割込みが発生したことを示すもので、実際に発生したイベントの種類はgmuxレジスタを読み取ることで識別されます。

グラフィックスmux¶

プレレタインモデルでは、両GPUのLVDS出力がgmuxに接続され、そのうちのいずれかをパネルに接続します。gmuxの特徴的な機能の一つは、スイッチ時に出力のブランキングインターバルを長くすることで、GPUの同期を図るためのものです。これにより、ユーザーには感知できないフラッカーフリースイッチが可能になります（US 8,687,007 B2).

レタインモデルでは、gmux自体ではなく、gmuxによって制御される別のチップがMUXングを担当します。このチップは三つのソースから供給され、 NXP CBTL06142, TI HD3SS212 または Pericom PI3VDP12412のいずれかです。パネルはLVDSではなくeDPで駆動されるため、レタイン解像度に必要なピクセルクロックはLVDSの限界を超えるためです。

プレレタインモデルはパネルのDDCピンを個別にスイッチ可能です。これは TI SN74LV4066A によって処理され、gmuxによって制御されます。これにより、アクティブでないGPUがパネルのEDIDをプローブできます。レタインモデルではこの機能がありません。eDPMUX用のチップはAUXチャネルを個別にスイッチできないため（リンクされたデータシートを参照、Pericomは可能ですが使用されていません）。しかし、レタインパネルはDPCDにNO_AUX_HANDSHAKE_LINK_TRAININGビットが設定されており、アクティブでないGPUがAUXハンドシェークをスキップし、アクティブGPUによって事前に校正されたリンクパラメータで出力を設定できます。

外部DPポートは、最初の2世代のユニボディMacBook Proモデル（MBP5 2008/09とMBP6 2010）でのみ完全にスイッチ可能です。これは NXP CBTL06141 によって実現され、gmuxによって制御されます。これはレタイン用のeDPMUXの前身であり、違いは2.7 Gbit/s対応と5.4 Gbit/s対応のサポートです。

次のMacBook Pro世代では、外部DPポートが組み合わせたDP/Thunderboltポートに置き換えられ、GPU間の切り替えが可能になったものの、ディスクリートGPUまたはThunderboltコントローラーへの接続のみが可能となりました。興味深いことに、フルポートはもう切り替えができないものの、AUXおよびHPDは依然として切り替えが可能で、 NXP CBTL03062 (プレレタインのMBP8 2011およびMBP9 2012)または2つの TI TS3DS10224 (レタインの場合)はgmuxの制御下で動作します。統合GPUはメインリンクが欠如しているため、外部ディスプレイは幻想のように見えるため、リンクトレーニングに失敗します。

gmuxはすべてのディスプレイコネクタのHPD信号を受信し、ホットプラグ時に割り込みを送信します。外部ポートの切り替えができない世代では、ディスクリートGPUが起動され、新たに接続されたディスプレイを駆動します。これらの世代でAUXの切り替え機能は、統合GPUがディスクリートGPUが休止している間、ポートをスキャンすることでホットプラグ検出の信頼性を向上させる可能性がありますが、現時点ではこの機能は使用されていません。

外部ポートの切り替えポリシーは、完全な切り替えが可能な世代では、IGD / DISコマンドがvga_switcherooに送信される際にポートとパネルが一緒に切り替えられます。したがって、統合GPUでバッテリー電力で例としてビデオプロジェクターを駆動することが可能です。ユーザーはより高いパフォーマンスが必要な場合、ディスクリートGPUに手動で切り替えることができます。

すべての新しい世代では、外部ポートはディスクリートGPUのみで駆動されます。パネルが統合GPUに切り替えられている状態でディスプレイを接続すると、 両方を組み合わせます GPUが最大性能で使用されます。電力消費を抑えるため、ユーザーは手動でディスクリートGPUに切り替えることができ、統合GPUを停止します。

gmuxの起動時の初期切り替え状態はEFI変数 gpu-power-prefs-fa4ce28d-b62f-4c99-9cc3-6815686e30f9 (5番目のバイト、1 = IGD、0 = DIS)でユーザー設定可能です。この設定に基づき、EFIファームウェアはgmuxにパネルおよび外部DPコネクタの切り替えを指示し、選択されたGPU用のフレームバッファを割り当てます。

電源制御¶

gmuxはディスクリートGPUの電源を切る機能を持ち、コア電圧、VRAM、PCIeの電源ラインの正しい順序で電源をオフにし、再起動する自動管理を行います。

バックライト制御¶

単GPUのMacBookではバックライトのPWM信号はGPUが生成します。一方、双GPUのMacBook ProではどちらのGPUもエネルギー節約のために停止されるため、PWM信号はgmuxによって制御される別途のバックライトドライバが必要です。最も古い世代のMBP5 2008/09は TI LP8543 バックライトドライバを使用します。すべての新しいモデルは TI LP8545.
