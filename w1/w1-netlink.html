コネクタを介したユーザースペース通信プロトコル¶

メッセージの種類¶

w1コアとユーザースペース間で送信されるメッセージの種類は3つあります：

  1. イベント。自動またはリクエストによる検索で新しいマスターデバイスまたはスレーブデバイスが検出されるたびに生成されます。

  2. ユーザースペースコマンド。

  3. ユーザースペースコマンドへの応答。

プロトコル¶

[struct cn_msg] - connector header.
      Its length field is equal to size of the attached data
[struct w1_netlink_msg] - w1 netlink header.
      __u8 type       - message type.
                      W1_LIST_MASTERS
                              list current bus masters
                      W1_SLAVE_ADD/W1_SLAVE_REMOVE
                              slave add/remove events
                      W1_MASTER_ADD/W1_MASTER_REMOVE
                              master add/remove events
                      W1_MASTER_CMD
                              userspace command for bus master
                              device (search/alarm search)
                      W1_SLAVE_CMD
                              userspace command for slave device
                              (read/write/touch)
      __u8 status     - error indication from kernel
      __u16 len       - size of data attached to this header data
      union {
              __u8 id[8];                      - slave unique device id
              struct w1_mst {
                      __u32           id;      - master's id
                      __u32           res;     - reserved
              } mst;
      } id;

[struct w1_netlink_cmd] - command for given master or slave device.
      __u8 cmd        - command opcode.
                      W1_CMD_READ     - read command
                      W1_CMD_WRITE    - write command
                      W1_CMD_SEARCH   - search command
                      W1_CMD_ALARM_SEARCH - alarm search command
                      W1_CMD_TOUCH    - touch command
                              (write and sample data back to userspace)
                      W1_CMD_RESET    - send bus reset
                      W1_CMD_SLAVE_ADD        - add slave to kernel list
                      W1_CMD_SLAVE_REMOVE     - remove slave from kernel list
                      W1_CMD_LIST_SLAVES      - get slaves list from kernel
      __u8 res        - reserved
      __u16 len       - length of data for this command
              For read command data must be allocated like for write command
      __u8 data[0]    - data for this command

各コンネクタメッセージには、ゼロ個以上の添付されたw1_netlink_cmdメッセージを含む1つ以上のw1_netlink_msgが含まれます。

イベントメッセージの場合、w1_netlink_cmdの埋め込まれた構造体は存在せず、コンネクタヘッダーとw1_netlink_msg構造体のみが含まれます。この際、「len」フィールドはゼロに設定され、タイプ（イベントタイプの1つ）とID（8バイトのスレーブ固有ID（ホスト順）またはマスターID（バスマスターデバイスがw1コアに追加されたときに割り当てられる））が設定されます。

現在、ユーザースペースコマンドへの応答は読み取りコマンドリクエストに対してのみ生成されます。1つのw1_netlink_cmd読み取りリクエストごとに1つの応答が生成され、応答送信時に結合されません。典型的な応答メッセージは以下のようになります：

[cn_msg][w1_netlink_msg][w1_netlink_cmd]
cn_msg.len = sizeof(struct w1_netlink_msg) +
           sizeof(struct w1_netlink_cmd) +
           cmd->len;
w1_netlink_msg.len = sizeof(struct w1_netlink_cmd) + cmd->len;
w1_netlink_cmd.len = cmd->len;

W1_LIST_MASTERSへの応答は、すべての登録済みマスターデバイスIDを含むメッセージをユーザースペースに送信する必要があります。フォーマットは以下の通りです：

cn_msg (CN_W1_IDX.CN_W1_VAL as id, len is equal to sizeof(struct
w1_netlink_msg) plus number of masters multiplied by 4)
w1_netlink_msg (type: W1_LIST_MASTERS, len is equal to
        number of masters multiplied by 4 (u32 size))
id0 ... idN

各メッセージの最大サイズは4KBです。したがって、マスターデバイスの数がこのサイズを超える場合、複数のメッセージに分割されます。

W1検索およびアラーム検索コマンド。

リクエスト：

[cn_msg]
  [w1_netlink_msg type = W1_MASTER_CMD
      id is equal to the bus master id to use for searching]
  [w1_netlink_cmd cmd = W1_CMD_SEARCH or W1_CMD_ALARM_SEARCH]

応答：

[cn_msg, ack = 1 and increasing, 0 means the last message,
      seq is equal to the request seq]
[w1_netlink_msg type = W1_MASTER_CMD]
[w1_netlink_cmd cmd = W1_CMD_SEARCH or W1_CMD_ALARM_SEARCH
      len is equal to number of IDs multiplied by 8]
[64bit-id0 ... 64bit-idN]

各ヘッダー内の長さは、その背後にあるデータのサイズに対応します。したがって、w1_netlink_cmd->len = N * 8; となります。ここでNはこのメッセージ内のIDの数です。ゼロでも可能です。

w1_netlink_msg->len = sizeof(struct w1_netlink_cmd) + N * 8;
cn_msg->len = sizeof(struct w1_netlink_msg) +
            sizeof(struct w1_netlink_cmd) +
            N*8;

W1リセットコマンド：

[cn_msg]
  [w1_netlink_msg type = W1_MASTER_CMD
      id is equal to the bus master id to use for searching]
  [w1_netlink_cmd cmd = W1_CMD_RESET]

コマンド状態応答¶

コマンド（ルート、マスター、スレーブ、またはw1_netlink_cmd構造体を含むか含まない）はすべてw1コアによって「確認」されます。応答の形式はリクエストメッセージと同じですが、長さパラメータはユーザーが要求したデータを考慮しません。つまり、読み取り/書き込み/タッチIOリクエストはデータを含まないため、w1_netlink_cmd.lenはゼロとなり、w1_netlink_msg.lenはw1_netlink_cmd構造体のサイズとなり、cn_msg.lenはsizeof(struct w1_netlink_msg) と sizeof(struct w1_netlink_cmd) の合計になります。マスターまたはルートコマンド（w1_netlink_cmdが添付されていない）に対する応答は、cn_msgとw1_netlink_msg構造体のみを含みます。

w1_netlink_msg.statusフィールドには、正のエラーコード（例：EINVAL）または成功時のゼロが設定されます。

すべての構造体の他のフィールドは、リクエストメッセージ内の同じパラメータを反映します（長さについては上記のように例外があります）。

w1_netlink_msg内に埋め込まれたすべてのw1_netlink_cmdに対してステータス応答が生成されます。w1_netlink_cmd構造体が存在しない場合、w1_netlink_msgに対して応答が生成されます。

すべてのw1_netlink_cmdコマンド構造体がw1_netlink_msgごとに処理されます。エラーがあっても、長さの不一致による割込みのみがメッセージ処理を中断します。

新しいコマンドが受信された際のw1コアの操作手順¶

新しいメッセージ(w1_netlink_msg)が受信されると、w1コアはw1_netlink_msg.typeフィールドに基づいてマスターまたはスレーブリクエストであるかを検出します。その後、対応するマスターまたはスレーブデバイスを検索します。見つかった場合、マスターデバイス（リクエストされたデバイスまたはスレーブデバイスが見つかった場所のデバイス）をロックします。スレーブコマンドがリクエストされた場合、指定されたデバイスを選択するためのリセット/セレクト手順を開始します。

その後、w1_netlink_msgに記載されたすべての操作を順次実行します。コマンドが応答を必要とする場合（例：読み取りコマンド）、コマンド実行完了時に応答を送信します。

すべてのコマンド(w1_netlink_cmd)が処理されると、マスターデバイスがアンロックされ、次のw1_netlink_msgヘッダー処理が開始されます。

コネクタ [1] に関する特定のドキュメンテーション¶

各コネクタメッセージには「address」として2つのu32フィールドが含まれます。w1はinclude/linux/connector.hヘッダーで定義されたCN_W1_IDXとCN_W1_VALを使用します。各メッセージにはシーケンス番号とアッケナント番号も含まれます。イベントメッセージのシーケンス番号は、このマスターを介して送信される各イベントメッセージごとに適切なバスマスターのシーケンス番号を増加させたものであり、ユーザースペースリクエストのシーケンス番号はユーザースペースアプリケーションによって設定されます。応答のシーケンス番号はリクエストのものと同一であり、アッケナント番号はseq+1に設定されます。
