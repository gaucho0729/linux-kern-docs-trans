カーネルドライバー w1_therm¶

サポートされているチップ:

  • Maxim ds18*20ベースの温度センサー。

  • Maxim ds1825ベースの温度センサー。

  • GXCAS GC20MH01温度センサー。

著者: Evgeniy Polyakov <johnpol@2ka.mipt.ru>

説明¶

w1_thermはds18*20、ds28ea00、GX20MH01デバイスの基本的な温度変換を提供します。

サポートされるファミリーコード:

W1_THERM_DS18S20

0x10

W1_THERM_DS1822

0x22

W1_THERM_DS18B20

0x28

W1_THERM_DS1825

0x3B

W1_THERM_DS28EA00

0x42

サポートはsysfsエントリを通じて提供されます w1_slave。各オープンおよび読み取りシーケンスは温度変換を開始し、その後2行のASCII出力を行います。1行目には読み取った9バイトの16進数と計算されたCRC値、およびCRCが一致したかどうかのYES/NOが表示されます。CRCが一致した場合、返された値が保持されます。2行目には保持された値とt=以降のミリデグリーセンチグラードの温度が表示されます。

代わりに、温度は temperature sysfsを介して読み取ることができます。これはミリデグリーセンチグラードの温度のみを返します。

バス上のすべてのデバイスを一括で読み取るには、w1_bus_masterレベルのエントリに書き込むことで、 trigger に（木の下から葉に向かって） therm_bulk_read convertコマンドをバス上のすべてのデバイスに送信します。バス上にパラサイト電源デバイスが検出され（モジュールで強力なプルアップが有効になっている場合）、パラサイト電源デバイスが長時間の変換に必要であるため、ラインを高電位に駆動します。読み取り therm_bulk_read は、一括変換が待機中でない場合0を、少なくとも1つのセンサーが変換中である場合-1を、変換が完了したが少なくとも1つのセンサーの値がまだ読み取れていない場合1を返します。結果の温度は、各デバイスの temperature エントリを読み取ることでアクセスできます。変換が進行中である場合、空の値を返す可能性があります。注意点として、一括読み取りが送信されても1つのセンサーがすぐに読み取られない場合、このデバイスの次の temperature へのアクセスは、一括読み取りコマンド発行時の温度を返します（現在の温度ではありません）。

必要に応じて強力なプルアップが適用されます。

conv_time は現在の変換時間（読み取り）を取得し、調整（書き込み）します。温度変換時間はデバイスタイプと現在の解像度に依存します。デフォルトの変換時間はドライバーがデバイスデータシートに基づいて設定します。多くの元のデバイスのクローンの変換時間はデータシート仕様からずれています。選択肢は3つあります：1）ミリ秒単位で正しい変換時間を手動で設定して conv_timeに書き込みます；2）変換時間を自動測定して設定するには 1 に（木の下から葉に向かって） conv_timeに書き込みます；3） features を使用して変換完了のポーリングを有効にします。選択肢2、3はパラサイト電源モードでは使用できません。デフォルトの変換時間に戻すには 0 に（木の下から葉に向かって） conv_time.

解像度値（ビット数）を書き込むと w1_slave センサーの精度が次の読み取りで変更されます。許容される解像度はセンサーによって定義されています。センサーが電源を再起動すると解像度がリセットされます。

現在の解像度をEEPROMに保存するには、 0 に（木の下から葉に向かって） w1_slaveを書き込みます。EEPROMの書き込み回数は限られているため（>50k回）、このコマンドは慎重に使用してください。

代替として、各デバイスの専用の resolution エントリを使用して解像度を読み取ったり書き込んだりできます（センサーがサポートしている場合）。

一部の非正規のDS18B20チップは12ビットモードに固定されているため、実際の解像度はチップから読み取って確認します。

注意：解像度を変更すると、変換時間はデフォルトに戻ります。

書き込み専用のsysfsエントリ eeprom はEEPROM操作の代替手段です。書き込み save でデバイスのRAMをEEPROMに保存し、書き込み restore でEEPROMデータをデバイスのRAMに復元します。

ext_power エントリは各デバイスの電源状態を確認できます。読み込み 0 がパラサイト電源デバイスかどうかを示し、 1 が外部電源デバイスかどうかを示します。

Sysfs alarms TH（温度上限）およびTL（温度下限）アラームを読み取りまたは書き込み可能です。値はスペースで区切って指定し、デバイスの範囲内（通常-55℃〜125℃）に収める必要があります。値は8ビットレジスタに保存されるため整数で指定します。最小値は自動的にTLに設定されます。設定後はマスターレベルでアラームを検索できます。

モジュールパラメータstrong_pullupは0に設定して強力なプルアップを無効化、1に設定して自動検出を有効化、2に設定して強力なプルアップを強制的に有効化できます。自動検出の場合は、ドライバが「電源供給を読み取る」コマンドを使用してバス上にパラサイト電源デバイスがあるか確認します。確認結果に応じてマスターデバイスの強力なプルアップを有効化します。このコマンドでパラサイトデバイスの検出に失敗した場合（例：一部のDS18S20では確認されている）、強力なプルアップを強制的に有効化できます。

強力なプルアップが有効な場合、変換中にマスターデバイスの強力なプルアップが駆動されます（マスタードライバが強力なプルアップをサポートしている場合）またはプルアップ抵抗にフォールバックします。DS18B20温度センサー仕様では最大電流消費が1.5mAであり、5kΩのプルアップ抵抗は十分でないことが記載されています。強力なプルアップは追加の電流を供給するために設計されています。

DS28EA00は1ワイヤーバス上でチップの物理的な位置を特定するシーケンス検出アルゴリズムを実装するための追加の2つのピンを提供します。この機能により、バスの順序に関する事前知識がなくてもチップの位置を特定できます。sysfsを通じてサポートされています。 w1_seqこのファイルには、バス上のデバイスインデックスを表す整数値が1行に記録されます。インデックスは0から始まります。

features sysfsエントリは、デバイスごとのオプションドライバ設定を制御します。寄生モードでの電力不足、ラインノイズ、または十分な変換時間がない場合、変換失敗が発生する可能性があります。元のDS18B20および一部のクローンは無効な変換の検出をサポートしています。書き込みビットマスク 1 に（木の下から葉に向かって） features 変換成功の確認を有効にするため。変換後、scratchpadメモリのバイト6が0xCで温度が85.00（電源投入値）または127.94（電力不足）を読み取った場合、ドライバは変換エラーを返します。ビットマスク 2 変換完了のポーリング（通常電源のみ）を有効にする。変換開始後にバス上で読み取りサイクルを生成します。寄生電源モードではこの機能は利用できません。機能ビットマスクはORで組み合わせられます。詳細はDocumentation/ABI/testing/sysfs-driver-w1_thermを参照してください。

GX20MH01デバイスはDS18*20と同様にファミリ番号0x28を共有します。一般的にDS18B20と互換性があります。追加されたのは最低2ビットです。-5, 2-6 Configレジスタ内の温度ビット；ConfigレジスタのR2ビットにより13ビットおよび14ビットの解像度が有効になります。デバイスは14ビット解像度モードで電源がオンされます。データシートに記載されている変換時間は低いため、増やす必要があります。デバイスはドライバ機能をサポートしています。 1 および 2.
