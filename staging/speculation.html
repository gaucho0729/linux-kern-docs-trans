スペキュレーション¶

このドキュメントでは、推測の潜在的な影響と、一般的なAPIを用いて不望な影響を汎用的に軽減する方法について説明します。

パフォーマンス向上と平均レイテンシーの最小化を目的として、多くの現代のCPUはブランチ予測などの推測実行技術を採用しています。これにより、後段で無効化される作業が行われることもあります。

通常、推測実行はアーキテクチャの状態（レジスタの内容など）から観測することはできません。ただし、一部のケースでは、キャッシュなどのマイクロアーキテクチャの状態への影響を観測でき、これにより機密情報が抽出されるサイドチャネルが形成されることがあります。

例えば、ブランチ予測がある場合、推測的に実行されるコードが境界チェックを無視する可能性があります。以下のコードを考えてみましょう：

int load_array(int *array, unsigned int index)
{
        if (index >= MAX_ARRAY_ELEMS)
                return 0;
        else
                return array[index];
}

arm64では、このようなコードがアセンブリ命令列にコンパイルされることがあります：

      CMP     <index>, #MAX_ARRAY_ELEMS
      B.LT    less
      MOV     <returnval>, #0
      RET
less:
      LDR     <returnval>, [<array>, <index>]
      RET

CPUが条件分岐を誤って予測し、推測的にarray[index]をロードする可能性があります（index >= MAX_ARRAY_ELEMSであっても）。この値は後で破棄されるものの、推測的なロードがマイクロアーキテクチャの状態に影響を与える可能性があります。

複数の依存するメモリアクセスを含むより複雑なシーケンスでは、機密情報が漏洩する可能性があります。以下のコードを考えてみましょう（前記の例を拡張したもの）：

int load_dependent_arrays(int *arr1, int *arr2, int index)
{
        int val1, val2,

        val1 = load_array(arr1, index);
        val2 = load_array(arr2, val1);

        return val2;
}

推測の下で、最初のload_array()呼び出しはバウンド外のアドレスの値を返す可能性があり、2番目の呼び出しはこの値に依存したマイクロアーキテクチャの状態に影響を与えます。これにより、任意の読み取りのプリミティブが提供される可能性があります。

スペキュレーション側チャネルの緩和¶

カーネルは、推測に基づくサイドチャネルの影響を受けるアーキテクチャに対して、境界チェックを推測条件でも尊重する汎用APIを提供しています。

<linux/nospec.h>に含まれるarray_index_nospec()というアシスタント関数は、サイドチャネルを通じた情報漏洩を防ぐために使用できます。

array_index_nospec(index, size)の呼び出しは、CPUの推測条件に関係なく、[0, size)の範囲に制限されたクリーン化されたインデックス値を返します。

これは、前述のload_array()例を保護するために使用できます：

int load_array(int *array, unsigned int index)
{
        if (index >= MAX_ARRAY_ELEMS)
                return 0;
        else {
                index = array_index_nospec(index, MAX_ARRAY_ELEMS);
                return array[index];
        }
}
