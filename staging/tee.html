TEEサブシステム¶

このドキュメントでは、LinuxにおけるTEEサブシステムについて説明します。

TEE（Trusted Execution Environment）は、あるセキュアな環境で実行される信頼できるOSであり、例えばARM CPUのTrustZoneや、別個のセキュアコプロセッサなどがあります。TEEドライバーは、TEEと通信するために必要な詳細を処理します。

このサブシステムは以下の処理を行います:

  • TEEドライバーの登録

  • LinuxとTEE間の共有メモリの管理

  • TEEに対する汎用APIの提供

TEE インターフェース¶

include/uapi/linux/tee.hはTEEに対する汎用インターフェースを定義します。

ユーザー空間（クライアント）は、/dev/tee[0-9]*または/dev/teepriv[0-9]*を開くことでドライバーに接続します。

  • TEE_IOC_SHM_ALLOCは共有メモリを割り当て、ユーザー空間がmmapできるファイル記述子を返します。ユーザー空間がファイル記述子を必要なくなった場合、それを閉じるべきです。共有メモリが不要になった場合は、munmap()でアンマップし、メモリの再利用を許可する必要があります。

  • TEE_IOC_VERSIONは、このドライバーが処理するTEEとその機能をユーザー空間に通知します。

  • TEE_IOC_OPEN_SESSIONは信頼アプリケーションへの新しいセッションを開きます。

  • TEE_IOC_INVOKEは信頼アプリケーション内の関数を呼び出します。

  • TEE_IOC_CANCELは進行中のTEE_IOC_OPEN_SESSIONまたはTEE_IOC_INVOKEをキャンセルする可能性があります。

  • TEE_IOC_CLOSE_SESSIONは信頼アプリケーションへのセッションを閉じます。

クライアントには通常クライアントとsupplicantという2つのクラスがあります。後者はTEEがLinux内のリソースにアクセスするための補助プロセスであり、たとえばファイルシステムアクセスなどです。通常クライアントは/dev/tee[0-9]*を開き、supplicantは/dev/teepriv[0-9]を開きます。

クライアントとTEE間の多くの通信はドライバーには透明です。ドライバーの主な役割は、クライアントからのリクエストを受信し、TEEに転送し、結果を返すことです。supplicantの場合、通信は逆方向になります。TEEがsupplicantにリクエストを送り、それから結果を返します。

TEE カーネルインターフェース¶

カーネルはTEEバスインフラストラクチャを提供し、信頼アプリケーションはユニバーサルユニーク識別子（UUID）で識別されるデバイスとして表されます。クライアントドライバーはサポートするデバイスUUIDの一覧を登録します。

TEEバスインフラストラクチャが登録するAPIは以下の通りです：

match():

クライアントドライバーのUUIDテーブルを走査し、デバイスUUIDに一致するものを検索します。一致が見つかった場合、この特定のデバイスはクライアントドライバーが登録した対応するprobe APIを通じてプローブされます。このプロセスは、デバイスまたはクライアントドライバーがTEEバスに登録されるたびに発生します。

uevent():

TEEバスに新しいデバイスが登録されるたびにユーザースペース（udev）に通知し、モジュール化されたクライアントドライバーの自動ロードを実現します。

TEEバスデバイスの列挙は、基盤となるTEE実装に依存するため、TEEドライバが対応する実装を提供できるように開放されています。

その後、TEEクライアントドライバは、include/linux/tee_drv.hに記載されたAPIを通じて、一致した信頼アプリケーションと通信できます。

TEEクライアントドライバの例¶

TEEクライアントドライバが信頼アプリケーションと通信する必要がある場合、UUID: ac6a4085-0e82-4c33-bf98-8eb8e118b6c2を持つ信頼アプリケーションを想定すると、ドライバ登録のスニペットは以下のようになります：

static const struct tee_client_device_id client_id_table[] = {
        {UUID_INIT(0xac6a4085, 0x0e82, 0x4c33,
                   0xbf, 0x98, 0x8e, 0xb8, 0xe1, 0x18, 0xb6, 0xc2)},
        {}
};

MODULE_DEVICE_TABLE(tee, client_id_table);

static struct tee_client_driver client_driver = {
        .id_table       = client_id_table,
        .driver         = {
                .name           = DRIVER_NAME,
                .bus            = &tee_bus_type,
                .probe          = client_probe,
                .remove         = client_remove,
        },
};

static int __init client_init(void)
{
        return driver_register(&client_driver.driver);
}

static void __exit client_exit(void)
{
        driver_unregister(&client_driver.driver);
}

module_init(client_init);
module_exit(client_exit);

OP-TEE ドライバー¶

OP-TEEドライバはOP-TEEベースのTEEを処理します。現在はARM TrustZoneベースのOP-TEEソリューションのみがサポートされています。

OP-TEEとの最低レベルの通信はARM SMC Calling Convention（SMCCC）に基づいています。これはOP-TEEのSMCインターフェースの基礎であり、ドライバが内部的に使用するインターフェースです。その上にOP-TEEメッセージプロトコルが積み重なっています。

OP-TEE SMCインターフェースはSMCCCに必要な基本機能を提供し、OP-TEE固有の追加機能も提供します。特に注目すべき関数は以下の通りです：

  • OPTEE_SMC_FUNCID_CALLS_UID（SMCCCの一部）はバージョン情報を返し、その後TEE_IOC_VERSIONで返されます。

  • OPTEE_SMC_CALL_GET_OS_UUIDは特定のOP-TEE実装を返し、たとえばTrustZoneベースのOP-TEEと別セキュアコプロセッサ上で実行されるOP-TEEを区別します。

  • OPTEE_SMC_CALL_WITH_ARGはOP-TEEメッセージプロトコルを駆動します。

  • OPTEE_SMC_GET_SHM_CONFIGはドライバとOP-TEEがLinuxとOP-TEE間で共有メモリとして使用するメモリ範囲を合意します。

GlobalPlatform TEEクライアントAPIは一般的なTEE APIの上に実装されています。

OP-TEEアーキテクチャ内のさまざまなコンポーネント間の関係の図：

   User space                  Kernel                   Secure world
   ~~~~~~~~~~                  ~~~~~~                   ~~~~~~~~~~~~
+--------+                                             +-------------+
| Client |                                             | Trusted     |
+--------+                                             | Application |
   /\                                                  +-------------+
   || +----------+                                           /\
   || |tee-      |                                           ||
   || |supplicant|                                           \/
   || +----------+                                     +-------------+
   \/      /\                                          | TEE Internal|
+-------+  ||                                          | API         |
+ TEE   |  ||            +--------+--------+           +-------------+
| Client|  ||            | TEE    | OP-TEE |           | OP-TEE      |
| API   |  \/            | subsys | driver |           | Trusted OS  |
+-------+----------------+----+-------+----+-----------+-------------+
|      Generic TEE API        |       |     OP-TEE MSG               |
|      IOCTL (TEE_IOC_*)      |       |     SMCCC (OPTEE_SMC_CALL_*) |
+-----------------------------+       +------------------------------+

RPC（リモートプロシージャコール）はセキュアワールドからカーネルドライバまたはtee-supplicantへのリクエストです。RPCはOPTEE_SMC_CALL_WITH_ARGから特定のSMCCC戻り値範囲で識別されます。カーネル宛てのRPCメッセージはカーネルドライバによって処理され、他のRPCメッセージはドライバの関与を除いて共有メモリバッファの表現形式を切り替えることでtee-supplicantに転送されます。

OP-TEEデバイス列挙¶

OP-TEEはデバイス列挙をサポートするためにdrivers/tee/optee/device.cという仮想の信頼アプリケーションを提供します。言い換えれば、OP-TEEドライバはこのアプリケーションを呼び出して、TEEバスに登録可能な信頼アプリケーションの一覧を取得します。

AMD-TEE ドライバー¶

AMD-TEEドライバーは、AMDのTEE環境と通信を処理します。TEE環境はAMD Secure Processorによって提供されます。

AMD Secure Processor（以前はPlatform Security ProcessorまたはPSPと呼ばれていました）は、ARM TrustZone技術を搭載した専用プロセッサであり、第三者の信頼アプリケーションを実行可能にするソフトウェアベースの信頼実行環境（TEE）を備えています。この機能は現在、APUのみで有効化されています。

以下の図は、AMD-TEEの概要を示しています。

                                            |
   x86                                      |
                                            |
User space            (Kernel space)        |    AMD Secure Processor (PSP)
~~~~~~~~~~            ~~~~~~~~~~~~~~        |    ~~~~~~~~~~~~~~~~~~~~~~~~~~
                                            |
+--------+                                  |       +-------------+
| Client |                                  |       | Trusted     |
+--------+                                  |       | Application |
    /\                                      |       +-------------+
    ||                                      |             /\
    ||                                      |             ||
    ||                                      |             \/
    ||                                      |         +----------+
    ||                                      |         |   TEE    |
    ||                                      |         | Internal |
    \/                                      |         |   API    |
+---------+           +-----------+---------+         +----------+
| TEE     |           | TEE       | AMD-TEE |         | AMD-TEE  |
| Client  |           | subsystem | driver  |         | Trusted  |
| API     |           |           |         |         |   OS     |
+---------+-----------+----+------+---------+---------+----------+
|   Generic TEE API        |      | ASP     |      Mailbox       |
|   IOCTL (TEE_IOC_*)      |      | driver  | Register Protocol  |
+--------------------------+      +---------+--------------------+

x86レベルで最も低い位置にあるAMD Secure Processor（ASP）ドライバーは、CPUをPSPメモリーメールボックスレジスタを使用してPSPにコマンドを送信します。コマンドバッファの形式はASPドライバーには非透明です。ASPドライバーの役割は、セキュアプロセッサにコマンドを送信し、結果をAMD-TEEドライバーに返すことです。AMD-TEEドライバーとAMD Secure Processorドライバー間のインターフェースは[6]に記載されています。

AMD-TEEドライバーは、TEEでの処理に必要なコマンニバッファのペイロードをパッケージ化します。異なるTEEコマンドのコマンドバッファ形式は[7]に記載されています。

AMD-TEE信頼OSがサポートするTEEコマンドは以下の通りです。

  • TEE_CMD_ID_LOAD_TA - 信頼アプリケーション（TA）バイナリを

    TEE環境にロードします。

  • TEE_CMD_ID_UNLOAD_TA - TAバイナリをTEE環境からアンロードします。

  • TEE_CMD_ID_OPEN_SESSION - ロード済みのTAとのセッションを開きます。

  • TEE_CMD_ID_CLOSE_SESSION - ロード済みのTAとのセッションを閉じます

  • TEE_CMD_ID_INVOKE_CMD - ロード済みのTAでコマンドを実行します

  • TEE_CMD_ID_MAP_SHARED_MEM - シェアードメモリをマップします

  • TEE_CMD_ID_UNMAP_SHARED_MEM - シェアードメモリをアンマップします

AMD-TEE信頼OSはAMD Secure Processor上で動作するファームウェアです。

AMD-TEEドライバはTEEサブシステムに自身を登録し、以下のドライバ関数コールバックを実装します:

  • get_version - ドライバの実装IDと機能を返します。

  • open - ドライバのコンテキストデータ構造を設定します。

  • release - ドライバリソースを解放します。

  • open_session - TAバイナリをロードし、ロードされたTAとのセッションを開きます。

  • close_session - ロードされたTAとのセッションを閉じて、それをアンロードします。

  • invoke_func - ロードされたTAを使用してコマンドを実行します。

cancel_req ドライバコールバックはAMD-TEEでサポートされていません。

GlobalPlatform TEE Client API [5]は、ユーザー空間（クライアント）がAMDのTEEと通信するために使用できます。AMDのTEEは、TAとのロード、セッションのオープン、コマンドの実行、セッションのクロージングに安全な環境を提供します。
