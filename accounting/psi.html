PSI - Pressure Stall Information¶

日付

2018年4月

著者

Johannes Weiner <hannes@cmpxchg.org>

CPU、メモリ、またはI/Oデバイスが競合状態にある場合、ワークロードはレイテンシのピーク、スループットの低下、およびOOMキルのリスクに直面します。

このような競合状態を正確に測定できない場合、ユーザーはハードウェアリソースを過度に過剰割当し、頻繁に過剰割当による障害に直面するリスクを負うか、安全策を取ってリソースを過度に利用しない選択を余儀なくされます。

psi機能は、リソース不足によって引き起こされる障害と、複雑なワークロードやシステム全体に与える時間的影響を特定・定量します。

リソース不足による生産性の低下を正確に測定することで、ユーザーはハードウェアに合わせたワークロードのサイズを設定したり、ワークロードの需要に応じてハードウェアをプロビジョニングしたりできます。

psiはリアルタイムでこの情報を集約するため、負荷軽減、他のシステムやデータセンターへのジョブの移動、低優先度や再起動可能なバッチジョブの戦略的な停止や終了などの技術を用いてシステムを動的に管理できます。

これにより、ワークロードの健康を犠牲にすることなくハードウェアの利用率を最大化し、OOMキルなどの重大な障害を回避できます。

プレッシャーインターフェース¶

各リソースのプレッシャー情報は、/proc/pressure/ディレクトリ内のcpu、memory、ioファイルを通じてエクスポートされます。

CPUのフォーマットは以下の通りです：

some avg10=0.00 avg60=0.00 avg300=0.00 total=0

memoryおよびIOについては以下のようにします：

some avg10=0.00 avg60=0.00 avg300=0.00 total=0
full avg10=0.00 avg60=0.00 avg300=0.00 total=0

「some」行は、少なくとも一部のタスクが特定のリソースで停止している時間割合を示します。

「full」行は、すべての非アイドルタスクが特定のリソースで同時に停止している時間割合を示します。この状態では実際のCPUサイクルが無駄になり、長時間この状態にいるワークロードはスワップアウトとみなされます。これはパフォーマンスに重大な影響を与え、一部のタスクが停止しているがCPUが生産的な作業を行っている状態と区別する必要があります。したがって、このスタール状態のサブセットに費やす時間は別途追跡され、「full」の平均値としてエクスポートされます。

比率（％）は10秒、60秒、300秒のウィンドウで最近のトレンドを追跡し、短期的な出来事や中長期的なトレンドの洞察を提供します。総絶対停止時間（マイクロ秒単位）も追跡されエクスポートされ、遅延のピークを検出するための機能や、カスタム時間フレームでのトレンドの平均を計算するための機能を可能にします。

プレッシャーしきい値のモニタリング¶

ユーザーはトリガーを登録し、リソースの圧力が特定のしきい値を超えたときにpoll()を使用して通知されるようにできます。

トリガーは特定の時間窓における累積停止時間の最大値を記述します。例えば、500msの時間窓内で合計100msの停止時間を達成すると、ウェイクアップイベントが生成されます。

トリガーを登録するには、/proc/pressure/以下のpsiインターフェースファイルを開き、監視するリソースを指定して、望ましいしきい値と時間窓を書き込みます。開いたファイル記述子はselect()、poll()、epoll()を使用してトリガーイベントを待機するために使用します。以下のような形式が使用されます：

<some|full> <stall amount in us> <time window in us>

例えば、/proc/pressure/memoryに「some 150000 1000000」と書き込むと、1秒の時間窓内で部分的なメモリ停止時間を測定し、150msのしきい値が追加されます。同様に、/proc/pressure/ioに「full 50000 1000000」と書き込むと、1秒の時間窓内で完全なIO停止時間を測定し、50msのしきい値が追加されます。

トリガーは複数のpsiメトリックに設定でき、同じpsiメトリックに対して複数のトリガーを指定することも可能です。ただし、各トリガーに対して個別のファイル記述子が必要であり、同じpsiインターフェースファイルを開く場合でも、各トリガーに対して個別のopen()システムコールを実行する必要があります。既にpsiトリガーが存在するファイル記述子に書き込みを行うとEBUSYエラーが発生します。

システムが監視対象のpsiメトリックの停止状態に入ったときにのみモニタが有効になり、停止状態から抜けたときに無効になります。システムが停止状態にある間、トラッキングウィンドウごとに10回の割合でpsi信号の増加を監視します。

カーネルは500msから10秒までのウィンドウサイズを受容しており、そのため最小監視更新間隔は50ms、最大は1秒です。最小限の制限は過度なポーリングを防ぐため、最大限の制限は監視が不要になる可能性が高く、psiの平均値を使用する場合に設定されています。

有効になると、少なくとも1つのトラッキングウィンドウの期間はアクティブのままにされ、システムが停止状態の入出を繰り返す際の繰り返しの有効化/無効化を防ぎます。

ユーザー空間への通知はトラッキングウィンドウごとに1回ずつ制限されます。

ファイル記述子が閉じられると、トリガーは登録を解除されます。

ユーザー空間モニタリングの使用例¶

#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <poll.h>
#include <string.h>
#include <unistd.h>

/*
 * Monitor memory partial stall with 1s tracking window size
 * and 150ms threshold.
 */
int main() {
      const char trig[] = "some 150000 1000000";
      struct pollfd fds;
      int n;

      fds.fd = open("/proc/pressure/memory", O_RDWR | O_NONBLOCK);
      if (fds.fd < 0) {
              printf("/proc/pressure/memory open error: %s\n",
                      strerror(errno));
              return 1;
      }
      fds.events = POLLPRI;

      if (write(fds.fd, trig, strlen(trig) + 1) < 0) {
              printf("/proc/pressure/memory write error: %s\n",
                      strerror(errno));
              return 1;
      }

      printf("waiting for events...\n");
      while (1) {
              n = poll(&fds, 1, -1);
              if (n < 0) {
                      printf("poll error: %s\n", strerror(errno));
                      return 1;
              }
              if (fds.revents & POLLERR) {
                      printf("got POLLERR, event source is gone\n");
                      return 0;
              }
              if (fds.revents & POLLPRI) {
                      printf("event triggered!\n");
              } else {
                      printf("unknown event received: 0x%x\n", fds.revents);
                      return 1;
              }
      }

      return 0;
}

Cgroup2インターフェース¶

CONFIG_CGROUP=yのカーネルとcgroup2ファイルシステムがマウントされているシステムでは、cgroupにグループ化されたタスクについてもpressure stall情報が追跡されます。cgroupfsマウントポイント内の各サブディレクトリには、cpu.pressure、memory.pressure、io.pressureファイルが含まれており、フォーマットは/proc/pressure/ファイルと同じです。

per-cgroupのpsiモニタは、システム全体のそれらと同じように指定および使用できます。
