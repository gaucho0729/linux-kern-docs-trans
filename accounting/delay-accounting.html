Delay accounting¶

タスクは、あるカーネルリソースが利用可能になるのを待つときに実行中に遅延を経験します。たとえば、実行可能なタスクは、空きCPUを待つことがあります。

タスクごとの遅延アカウント機能は、タスクが

  1. CPUを待つ（実行可能状態になっている間）

  2. タスクによって開始された同期ブロックI/Oの完了

  3. ページのスワップイン

  4. メモリの回収

などの遅延を測定し、taskstatsインターフェースを通じてユーザースペースにこれらの統計情報を提供します。

このような遅延は、タスクのCPU優先度、I/O優先度、RSS制限値を適切に設定するためのフィードバックとなります。重要なタスクにおける長時間の遅延は、その対応する優先度を上げるきっかけとなることがあります。

この機能は、taskstatsインターフェースを通じて、スレッドグループ（伝統的なUnixプロセスに対応）に属するすべてのタスク（またはスレッド）の遅延統計を集約して提供します。これはカーネルがより効率的に実行できる一般的な集約です。

ユーザースペースユーティリティ（特にリソース管理アプリケーション）は、遅延統計を任意のグループに集約することもできます。この機能を有効にするために、タスクの遅延統計はそのライフタイム中および終了時にも利用可能です。これにより、継続的で完全なモニタリングが可能になります。

インターフェース¶

遅延アカウントは、このディレクトリ内の別ドキュメントで詳細に説明されているtaskstatsインターフェースを使用します。taskstatsは、pidごとおよびtgidごとの統計情報をユーザースペースに一般的なデータ構造として返します。遅延アカウント機能はこの構造の特定のフィールドを埋め込みます。詳しくは

include/linux/taskstats.h

をご参照ください。これは、遅延アカウントに関連するフィールドの説明であり、通常、CPU、同期ブロックI/O、スワップイン、メモリ回収などの累積遅延を返すカウンタの形式になります。

タスクの特定のカウンタ（例：cpu_delay_total）の2つの連続した読み取り値の差を取ることで、タスクがその間の対応するリソースを待つ間に経験した遅延を算出できます。

タスクが終了する際、タスクごとの統計情報を含むレコードがコマンドを必要とせずにユーザースペースに送信されます。それがスレッドグループの最後の終了タスクである場合、tgidごとの統計情報も送信されます。詳細はtaskstatsインターフェースの説明をご参照ください。

tools/accountingディレクトリにあるgetdelays.cユーザースペースユーティリティは、簡単なコマンドを実行し、対応する遅延統計情報を表示します。また、taskstatsインターフェースの使用例としても機能します。

使い方¶

カーネルをコンパイルするには:

CONFIG_TASK_DELAY_ACCT=y
CONFIG_TASKSTATS=y

ブートアップ時にディレイアカウントングがデフォルトで有効になっています。無効にするには、以下をカーネルのブートオプションに追加してください:

nodelayacct

カーネルのブートオプションに。以下の指示はこの操作が行われていないことを前提としています。

システムがブートアップした後は、getdelays.cに似たユーティリティを使用して、特定のタスクまたはタスクグループ（tgid）が経験するディレイにアクセスできます。このユーティリティは、指定されたコマンットを実行し、対応するディレイを確認することもできます。

getdelaysコマンドの一般的な形式:

getdelays [-t tgid] [-p pid] [-c cmd...]

pid 10のブートから経過したディレイを取得:

# ./getdelays -p 10
(output similar to next case)

tgid 5を持つすべてのpidのブートから経過したディレイの合計を取得:

# ./getdelays -t 5


CPU     count   real total      virtual total   delay total
        7876    92005750        100000000       24001500
IO      count   delay total
        0       0
SWAP    count   delay total
        0       0
RECLAIM count   delay total
        0       0

指定されたシンプルなコマンドを実行中に観測されたディレイを取得:

# ./getdelays -c ls /

bin   data1  data3  data5  dev  home  media  opt   root  srv        sys  usr
boot  data2  data4  data6  etc  lib   mnt    proc  sbin  subdomain  tmp  var


CPU   count   real total      virtual total   delay total
      6       4000250         4000000         0
IO    count   delay total
      0       0
SWAP  count   delay total
      0       0
RECLAIM       count   delay total
      0       0
