Uacce について¶

Uacce（統合/ユーザースペースアクセスを目的としたアクセラレータフレームワーク）は、アクセラレータとプロセス間で共有仮想アドレス（SVA）を提供することを目的としています。これにより、アクセラレータがメインCPUの任意のデータ構造にアクセスできるようになります。これはCPUとI/Oデバイス間のデータ共有とは異なり、データ内容だけでなくアドレスそのものを共有するためです。統合アドレスにより、ハードウェアとプロセスのユーザースペースが通信時に同じ仮想アドレスを共有できます。Uacceはハードウェアアクセラレータを異質プロセッサとして扱い、IOMMUは同じCPUページテーブルを使用するため、VAからPAへの変換も同じになります。

|                          |     |                          |
|  User application (CPU)  |     |   Hardware Accelerator   |
|__________________________|     |__________________________|

             |                                 |
             | va                              | va
             V                                 V
         __________                        __________
        |          |                      |          |
        |   MMU    |                      |  IOMMU   |
        |__________|                      |__________|
             |                                 |
             |                                 |
             V pa                              V pa
         _______________________________________
        |                                       |
        |              Memory                   |
        |_______________________________________|

アーキテクチャ¶

Uacceはカーネルモジュールであり、IOMMUおよびアドレス共有を担当します。ユーザードライバーやライブラリはWarpDriveとして呼ばれます。

IOMMU SVA APIを基盤としたuacceデバイスは、PASIDを持たないアドレス空間も含めて複数のアドレス空間にアクセスできます。

通信には仮想概念であるキューが使用されます。これはFIFOのようなインターフェースを提供し、アプリケーションと関与するすべてのハードウェア間で統一されたアドレス空間を維持します。

どのように動作するのか¶

UacceはmmapとIOMMUを使用して機能を実現します。

Uacceは登録されたすべてのデバイスに対してキャラクタデバイス（chrdev）を作成します。ユーザーアプリケーションがchrdevを開くと新しいキューが作成され、ファイルディスクリプタはキューのユーザーハンドルとして使用されます。アクセラレータデバイスはUacceオブジェクトとして表現され、ユーザースペースにchrdevとしてエクスポートされます。ユーザーアプリケーションはioctl（制御パス）または共有メモリ（データパス）を通じてハードウェアと通信します。

ハードウェアへの制御パスはファイル操作を通じて、データパスはキューFdのmmap領域を通じて行われます。

キューのファイルアドレス空間:

 /**
 * enum uacce_qfrt: qfrt type
 * @UACCE_QFRT_MMIO: device mmio region
 * @UACCE_QFRT_DUS: device user share region
 */
enum uacce_qfrt {
        UACCE_QFRT_MMIO = 0,
        UACCE_QFRT_DUS = 1,
};

すべての領域はオプションであり、デバイスタイプによって異なります。各領域は一度しかマッピングできません。複数回マッピングすると-EEXISTが返されます。

デバイスmmio領域はハードウェアのmmio領域にマッピングされ、ドアベルやその他のハードウェアへの通知に一般的に使用されます。データチャネルとしては十分ではありません。

デバイスユーザーシェア領域は、ユーザープロセスとデバイス間でデータバッファを共有するために使用されます。

Uacce レジスタAPI¶

レジスタAPIはuacce.hに定義されています。

struct uacce_interface {
  char name[UACCE_MAX_NAME_SIZE];
  unsigned int flags;
  const struct uacce_ops *ops;
};

IOMMUの機能に応じて、uacce_interfaceフラグは以下のようになります:

/**
 * UACCE Device flags:
 * UACCE_DEV_SVA: Shared Virtual Addresses
 *              Support PASID
 *              Support device page faults (PCI PRI or SMMU Stall)
 */
#define UACCE_DEV_SVA               BIT(0)

struct uacce_device *uacce_alloc(struct device *parent,
                                 struct uacce_interface *interface);
int uacce_register(struct uacce_device *uacce);
void uacce_remove(struct uacce_device *uacce);

uacce_registerの結果は以下の通りです:

  1. uacceモジュールがコンパイルされていない場合、ERR_PTR(-ENODEV)

  2. 望ましいフラグで成功

  3. 交渉されたフラグで成功、例えば

uacce_interface.flags = UACCE_DEV_SVA ですが uacce->flags = ~UACCE_DEV_SVA

そのため、ユーザードライバーは返却値だけでなく、交渉されたuacce->flagsも確認する必要があります。

ユーザー・ドライバ¶

キュー・ファイルのmmap領域は、通信プロトコルをラップするユーザー・ドライバが必要です。Uacceは、ユーザー・ドライバが正しいアクセラレータを一致させるためにsysfsにいくつかの属性を提供します。詳細はDocumentation/ABI/testing/sysfs-driver-uacceをご参照ください。
