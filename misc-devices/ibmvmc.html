IBM ビジュー管理チャネルカーネルドライバ (IBMVMC)¶

著者

Dave Engebretsen <engebret@us.ibm.com>, Adam Reznechek <adreznec@linux.vnet.ibm.com>, Steven Royer <seroyer@linux.vnet.ibm.com>, Bryant G. Ly <bryantly@linux.vnet.ibm.com>,

はじめに¶

注意: このドキュメントを理解するには仮想化技術に関する知識が必要です。

参考になるドキュメントとして以下のものが挙げられます:

https://openpowerfoundation.org/wp-content/uploads/2016/05/LoPAPR_DRAFT_v11_24March2016_cmt1.pdf

Virtual Management Channel (VMC) は、ハイパーバイザと管理パーティション間のインターフェースを提供する論理デバイスです。このインターフェースはメッセージ passing インターフェースに似ています。この管理パーティションは、ハードウェア管理コンソール (HMC) を使用するシステムの代替として意図されています。

IBMが開発した主要なハードウェア管理ソリューションは、ハードウェア管理コンソール (HMC) と呼ばれるアプライアンスサーバーに依存しています。これは外部のタワーやラックマウントされたパーソナルコンピュータとしてパッケージ化されています。Power Systems環境では、1つのHMCが複数のPOWERプロセッサベースのシステムを管理できます。

管理アプリケーション¶

管理パーティションには、システム管理者がコマンドラインインターフェース (CLI) または表記状態転送アプリケーション (REST API) を使用してシステムのパーティション設定を構成できるアプリケーションが存在します。

管理アプリケーションは、PowerVMで仮想化されたPOWER8または新しいプロセッサベースのサーバー上のLinux論理パーティションで実行されます。従来はHMCが必要だったシステム構成、メンテナンス、制御機能は、HMCとハイパーバイザ間のインターフェースと既存のオペレーティングシステムメソッドを組み合わせて管理アプリケーションで実装できます。このツールはHMCが実装する機能のサブセットを提供し、基本的なパーティション設定を可能にします。管理アプリケーションコンポーネントがサポートするHMCとハイパーバイザ間のメッセージは、以下のVMCインターフェースを介してハイパーバイザに送信されます。

VMCは管理パーティションが基本的なパーティション機能を提供できるようにします:

  • 論理パーティション設定

  • 個々のパーティションの起動および停止アクション

  • パーティション状態の表示

  • 仮想イーサネットの管理

  • 仮想ストレージの管理

  • 基本的なシステム管理

Virtual Management Channel (VMC)¶

仮想管理チャネル (VMC) は、管理アプリケーションとハイパーバイザ間で通信するための論理デバイスとして定義されています。これは仮想化管理ソフトウェアを実行するためのパイプを基本的に作成します。このデバイスは、指定された管理パーティションに仮想デバイスとして提示されます。

この通信デバイスは、コマンド/応答キュー（CRQ）およびリモート直接メモリアクセス（RDMA）インターフェースを使用しています。プロトコルメッセージの送受信を行う前に、ハイパーバイザーおよび管理パーティション側のチャネルが動作していることを確認するため、3-way handshakeが定義されています。

このドライバーはさらにトランスポートイベント用のCRQも利用しています。ハイパーバイザーがペアーパーティションのいずれかが異常終了したか、または一方がH_FREE_CRQを呼び出してCRQを閉じたことを検出するとCRQメッセージが送信されます。VMCデバイスには、2つの新しいCRQメッセージクラスが導入されています。VMC管理メッセージは、VMCを使用する各パーティションがパートナーに対して機能を通知するために使用され、HMCインターフェースメッセージは管理パーティションとハイパーバイザー間でHMCメッセージを実際にやり取りするために使用されます。ほとんどのHMCメッセージはCRQバッファのサイズを大幅に超えるため、各HMCインターフェースCRQメッセージ送信前にHMCメッセージデータの仮想DMA（RMDA）が実行されます。RDMA操作は常に管理パーティションが実行し、ハイパーバイザーはメッセージデータの移動を直接引き起こしません。

用語¶

RDMA

リモート直接メモリアクセスは、サーバーからクライアントまたはパートナーパーティションへのDMA転送を指します。DMAは、メモリへの物理I/Oおよびメモリ間の移動操作を含む操作を指します。

CRQ

コマンド/応答キューは、パートナーパーティション間で通信を行うための機能です。ハイパーバイザーからパーティションへシグナルされるトランスポートイベントもこのキューで報告されます。

管理パーティション VMC ドライバインターフェースの例¶

このセクションでは、デバイスドライバーを使用してVMCデバイスにインターフェースする管理アプリケーションの実装例を示します。このドライバーは、たとえば/dev/ibmvmcという新しいデバイスを提供し、オープン、クローズ、読み込み、書き込み、ioctl操作をVMCデバイスに対して行うインターフェースを提供します。

VMCインターフェースの初期化¶

デバイスドライバーは、ドライバーがロードされるときにVMCを初期化する責任があります。まず、CRQを生成し初期化します。次に、VMCの能力の交換が行われ、管理パーティションとハイパーサー双方に存在するコードバージョンとリソース数を示します。最後に、ハイパーサーは管理パーティションに初期のVMCバッファプールの作成を依頼し、各可能なHMC接続ごとに1つのバッファを用意します。これは管理アプリケーションセッションの初期化に使用されます。この初期化シーケンスが完了する前は、デバイスはopen()呼び出しに対してEBUSYを返します。すべてのopen()失敗に対してはEIOが返されます。

Management Partition            Hypervisor
                CRQ INIT
---------------------------------------->
           CRQ INIT COMPLETE
<----------------------------------------
              CAPABILITIES
---------------------------------------->
         CAPABILITIES RESPONSE
<----------------------------------------
      ADD BUFFER (HMC IDX=0,1,..)         _
<----------------------------------------  |
          ADD BUFFER RESPONSE              | - Perform # HMCs Iterations
----------------------------------------> -

VMC Interface Open¶

基本的なVMCチャネルが初期化された後、HMCセッションレベルの接続が確立できます。アプリケーション層はVMCデバイスに対してopen()を実行し、そのデバイスに対してioctl()を実行して、このセッションのHMC ID（32バイトのデータ）を指定します。VMCデバイスが無効な状態にある場合、ioctl()に対してEIOが返されます。ドライバーはこのHMC IDに対して新しいHMCセッション値（1〜255の範囲）とHMCインデックス値（インデックス0から254まで）を生成します。次に、ドライバーはHMC IDをハイパーサーにRDMAで送信し、VMCを介してセッションを確立するためのインターフェースオープンメッセージをハイパーサーに送信します。ハイパーサーがこの情報を受信した後、新しいHMC接続用の初期バッファプールを管理パーティションに種をまくためにAdd Bufferメッセージを送信します。最後に、ハイパーサーはインターフェースオープン応答メッセージを送信し、通常のランタイムメッセージングの準備ができていることを示します。以下の図はこのVMCフローを示します。

Management Partition             Hypervisor
              RDMA HMC ID
---------------------------------------->
            Interface Open
---------------------------------------->
              Add Buffer                  _
<----------------------------------------  |
          Add Buffer Response              | - Perform N Iterations
----------------------------------------> -
        Interface Open Response
<----------------------------------------

VMC Interface Runtime¶

通常の実行中、管理アプリケーションとハイパーバイザはSignal VMCメッセージとRDMA操作を介してHMCメッセージを交換します。管理アプリケーションがハイパーバイザにデータを送信する際は、VMCデバイスに対してwrite()を実行し、ドライバーがRDMA操作によりデータをハイパーバイザに転送した後、Signalメッセージを送信します。ハイパーバイザがVMCデバイスバッファを提供していない場合、または現在バッファが利用できない場合、write()はEBUSYを返します。他のエラー（例：無効なデバイス状態）については、write()がEIOを返します。ハイパーバイザが管理アプリケーションにメッセージを送信する際は、データをVMCバッファに格納し、管理パーティション内のVMCドライバーにSignalメッセージを送信します。ドライバーがバッファをパーティションにRDMA操作で転送し、VMCデバイスのread()を介して適切な管理アプリケーションにデータを転送します。read()リクエストはバッファが利用できない場合、ブロックされます。管理アプリケーションは、VMCデバイスが読み込み用データを準備するのを待つためにselect()を使用できます。

Management Partition             Hypervisor
                MSG RDMA
---------------------------------------->
                SIGNAL MSG
---------------------------------------->
                SIGNAL MSG
<----------------------------------------
                MSG RDMA
<----------------------------------------

VMCインターフェースの終了¶

アプリケーションレイヤーがデバイスに対してclose()を実行すると、管理パーティションがHMCセッションレベルの接続を閉じます。この操作により、ハイパーバイザにInterface Closeメッセージが送信され、セッションが終了します。デバイスドライバーは、このHMC接続用に割り当てられたバッファのストレージを解放する必要があります。

Management Partition             Hypervisor
             INTERFACE CLOSE
---------------------------------------->
        INTERFACE CLOSE RESPONSE
<----------------------------------------
