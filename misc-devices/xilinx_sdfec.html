Xilinx SD-FEC ドライバ¶

概要¶

このドライバーは、Zynq Ultrascale+™ RFSoCs用のSD-FEC統合ブロックをサポートしています。

SD-FECコアの機能についての詳細な説明は、 SD-FEC製品ガイド (PG256)

このドライバーがサポートする機能は次の通りです：

  • 統合ブロックの設定および状態情報の取得

  • LDPC符号の設定

  • トーチューデコードの設定

  • エラーのモニタリング

SD-FECドライバーの欠点、既知の問題、および制限は次の通りです：

  • ドライバーのインスタンスごとに同時にオープンできるファイルハンドラは1つだけです

  • SD-FEC統合ブロックのリセットはこのドライバーによって制御されません

  • 共有LDPCコードテーブルの巻き戻しをサポートしていません

デバイスツリーのエントリは次の通りです： linux-xlnx/Documentation/devicetree/bindings/misc/xlnx,sd-fec.txt

動作モード¶

ドライバーはSD-FECコアと2つの動作モードで動作します：

  • ランタイム構成

  • プログラマブル論理（PL）初期化

ランタイム構成¶

ランタイム構成では、ドライバーの役割はソフトウェアアプリケーションが次の操作を実行できるようにすることです：

  • トーチューデコードまたはLDPCエンコード・デコードの設定パラメータをロード

  • SD-FECコアをアクティブ化

  • SD-FECコアのエラーをモニタリング

  • SD-FECコアの状態および設定情報を取得

プログラマブル論理（PL）初期化¶

PL初期化では、サポートロジックがトーチューデコードまたはLDPCエンコード・デコードの設定パラメータをロードします。ドライバーの役割は、ソフトウェアアプリケーションが次の操作を実行できるようにすることです：

  • SD-FECコアをアクティブ化

  • SD-FECコアのエラーをモニタリング

  • SD-FECコアの状態および設定情報を取得

ドライバの構造¶

ドライバーは、 probe および remove 操作が提供されるプラットフォームデバイスを定義します。

  • プローブ: デバイスツリーのエントリをもとに設定レジスタを更新し、コアの現在のアクティブ状態（例: コアがバイパスされているか、コアが起動されているか）を判定します。

ドライバーは、ユーザー アプリケーションインターフェースを提供するために次のドライバーファイル操作を定義しています：

  • オープン: 1つのSD-FECインスタンスに対して同時にオープンできるファイル記述子は1つだけです

  • リリース: 現在のファイル記述子が閉じた後、他のファイル記述子がオープンできるようにします

  • ポール: SD-FECエラーイベントをモニタリングする方法を提供します

  • アンロックド_イオコントロール: アプリケーションがSD-FECコアを構成できるioctlコマンドを提供します

    • XSDFEC_START_DEV

    • XSDFEC_STOP_DEV

    • XSDFEC_GET_STATUS

    • XSDFEC_SET_IRQ

    • XSDFEC_SET_TURBO

    • XSDFEC_ADD_LDPC_CODE_PARAMS

    • XSDFEC_GET_CONFIG

    • XSDFEC_SET_ORDER

    • XSDFEC_SET_BYPASS

    • XSDFEC_IS_ACTIVE

    • XSDFEC_CLEAR_STATS

    • XSDFEC_SET_DEFAULT_CONFIG

ドライバの使用方法¶

概要¶

ドライバーを開いた後、ユーザーはSD-FECコアを構成およびアクティブ化するための操作とドライバーの構成を確認する必要があります。以下の手順を実行する必要があります：

  • 構成の確認

  • すでに望ましい設定にされている場合は、オーダーを設定してください

  • SD-FECコアの設定に応じて、またはSD-FECがPL初期化用に設定されていない場合に、Turboデコード、LPDCエンコードまたはデコードパラメータを設定してください

  • すでに有効になっていない場合は、割り込みを有効にしてください

  • 必要に応じてSD-FECコアをバイパスしてください

  • すでに起動していない場合は、SD-FECコアを起動してください

  • SD-FECコアの状態を取得してください

  • 割り込みを監視してください

  • SD-FECコアを停止してください

割り込みを監視している場合、重大なエラーが検出された場合はリセットが必要なため、ドライバーはデフォルト設定をロードする必要があります

構成の確認¶

ioctlを使用してSD-FECコアの設定を確認してください XSDFEC_GET_CONFIG.

オーダーを設定¶

オーダーの設定は、ブロックの入力から出力への順序がどのように変化するかを決定します

オーダーの設定はioctlを使用して行います XSDFEC_SET_ORDER

以下の制限条件を満たす必要があります

  • 以下の state structのメンバ xsdfec_status ioctlによって埋め込まれます XSDFEC_GET_STATUS SD-FECコアが起動していないことを示します

LDPCコードを追加¶

以下の手順は、LDPCコードをSD-FECコアに追加する方法を示しています

  • 自動生成されたパラメータを使用して、 struct xsdfec_ldpc_params 望ましいLDPCコード用に埋め込んでください

  • LPDCパラメータおよび構造体内のパラメータのSC、QA、LAテーブルオフセットを設定してください struct xsdfec_ldpc_params

  • 構造体内の望ましいCode Id値を設定してください struct xsdfec_ldpc_params

  • ioctlを使用してLPDCコードパラメータを追加してください XSDFEC_ADD_LDPC_CODE_PARAMS

  • 適用されたLPDCコードパラメータに対しては、関数 xsdfec_calculate_shared_ldpc_table_entry_size() を呼び出して共有LPDCコードテーブルのサイズを計算してください。これにより、ユーザーが共有テーブルの使用状況を把握し、次のLDPCコードパラメータのテーブルオフセットを選択する際に未使用のテーブル領域を選べるようにします

  • 各LDPCコードパラメータに対して繰り返してください

以下の制限条件を満たす必要があります

  • 以下の code のメンバーです struct xsdfec_config ioctlによって埋め込まれます XSDFEC_GET_CONFIG SD-FECコアがLDPCとして設定されていることを示します

  • 以下の code_wr_protect の struct xsdfec_config ioctlによって埋め込まれます XSDFEC_GET_CONFIG 書き込み保護が有効になっていないことを示します

  • 以下の state structのメンバ xsdfec_status ioctlによって埋め込まれます XSDFEC_GET_STATUS SD-FECコアが起動していないことを示します

Turboデコードを設定¶

Turboデコードパラメータの設定はioctlを使用して行います XSDFEC_SET_TURBO 自動生成されたパラメータを使用して、 struct xsdfec_turbo 望ましいTurboコード用に埋め込んでください

Turboデコードの追加は以下の制限条件を満たす必要があります

  • 以下の code のメンバーです struct xsdfec_config ioctlによって埋め込まれます XSDFEC_GET_CONFIG SD-FECコアがTURBOとして設定されていることを示します

  • 以下の state structのメンバ xsdfec_status ioctlによって埋め込まれます XSDFEC_GET_STATUS SD-FECコアが起動していないことを示します

割り込みを有効化¶

割り込みの有効化または無効化はioctlを使用して行います XSDFEC_SET_IRQ。パラメータとして渡されたメンバの struct xsdfec_irqioctlは、さまざまな割り込みカテゴリの設定とクリアに使用されます。割り込みカテゴリの制御は以下の通りです。

  • enable_isr を制御します tlast interrupts

  • enable_ecc_isr ECC割り込みを制御します

もし code のメンバーです struct xsdfec_config ioctlによって埋め込まれます XSDFEC_GET_CONFIG SD-FECコアがTURBOとして構成されている場合、ECCエラーの有効化は必要ありません。

SD-FECをバイパスする¶

SD-FECのバイパスはioctlを使用して行います XSDFEC_SET_BYPASS

以下の制限条件を満たす必要があります。

  • 以下の state のメンバーです struct xsdfec_status ioctlによって埋め込まれます XSDFEC_GET_STATUS SD-FECコアが起動していないことを示します

SD-FECコアを起動する¶

ioctlを使用してSD-FECコアを起動します XSDFEC_START_DEV

SD-FECステータスを取得する¶

ioctlを使用してデバイスのSD-FECステータスを取得します XSDFEC_GET_STATUS、これはを埋めます struct xsdfec_status

割り込みのモニタリング¶

  • pollシステムコールを使用して割り込みをモニタリングします。pollシステムコールは割り込みが発生するのを待機し、割り込みが発生しなければタイムアウトします。

  • pollの返戻 revents がステータスおよび/またはステートが更新されたかどうかを示します

    • POLLPRI 重大なエラーを示し、ユーザーはを使用して確認する必要があります XSDFEC_GET_STATUS および XSDFEC_GET_STATS を確認するため

    • POLLRDNORM 重大でないエラーが発生したことを示し、ユーザーはを使用して確認する必要があります XSDFEC_GET_STATS を確認するため

  • ioctlを使用してステータスを取得する XSDFEC_GET_STATS

    • 重大なエラーの場合、 isr_err_count または uecc_count のメンバーです struct xsdfec_stats がゼロでないことを示します

    • 重大でないエラーの場合、 cecc_count のメンバーです struct xsdfec_stats がゼロでないことを示します

  • ioctlを使用してステートを取得する XSDFEC_GET_STATUS

    • 重大なエラーの場合、 state の xsdfec_status がリセットが必要であることを示します

  • ステータスをクリアする XSDFEC_CLEAR_STATS

リセットが必要な重大なエラーが検出された場合、アプリケーションはioctlを呼び出してリセット後、ioctlを呼び出す必要はありません XSDFEC_SET_DEFAULT_CONFIG、リセット後、ioctlを呼び出す必要はありません XSDFEC_STOP_DEV

注意: pollシステムコールを使用すると、ビジー・ルーティングを防ぐことができます XSDFEC_GET_STATS および XSDFEC_GET_STATUS

SD-FECコアを停止する¶

ioctlを使用してデバイスを停止します XSDFEC_STOP_DEV

デフォルト設定を設定する¶

ioctlを使用してデフォルト設定をロードします XSDFEC_SET_DEFAULT_CONFIG ドライバを復元するため

制限¶

ユーザーはSD-FECデバイスファイルハンドラを複製してはいけません。たとえば、fork()やdup()でSD-FECファイルハンドラを作成したプロセスを複製してはいけません。

enum xsdfec_axis_word_include¶

ワード構成

XSDFEC_FIXED_VALUE
