AArch64 Linuxにおけるメモリレイアウト¶

著者: Catalin Marinas <catalin.marinas@arm.com>

このドキュメントでは、AArch64 Linuxカーネルで使用される仮想メモリレイアウトについて説明します。このアーキテクチャでは、4KBページサイズで最大4段階の翻訳テーブル、64KBページサイズで最大3段階の翻訳テーブルを使用できます。

AArch64 Linuxでは、4KBページ構成で3段階または4段階の翻訳テーブルを使用し、ユーザーおよびカーネルそれぞれで39ビット（512GB）または48ビット（256TB）の仮想アドレスをサポートします。64KBページサイズでは2段階の翻訳テーブルを使用し、42ビット（4TB）の仮想アドレスをサポートしますが、メモリレイアウトは同じです。

ARMv8.2は大規模仮想アドレス空間のオプションサポートを追加しました。これは64KBページサイズで実行している場合にのみ利用可能です。この機能により、翻訳テーブルの1段階における記述子数が拡張されます。

ユーザーアドレスではビット63:48が0に設定され、カーネルアドレスでは同じビットが1に設定されます。TTBRxの選択は仮想アドレスのビット63によって決まります。swapper_pg_dirにはカーネル（グローバル）マッピングのみが含まれ、user pgdにはユーザー（非グローバル）マッピングのみが含まれます。swapper_pg_dirのアドレスはTTBR1に書き込まれますが、TTBR0には書き込まれません。

KVMをVirtualization Host Extensionsなしで使用する場合、ハイパーザーはEL2で線形マッピングからの固定（およびランダムな）オフセットでカーネルページをマッピングします。詳細はkern_hyp_vaマクロとkvm_update_va_mask関数を参照してください。MMIOデバイス（例: GICv2）はHYP idmapページの近くにマッピングされ、ARM64_SPECTRE_V3Aが有効な特定のCPUではベクタも同様にマッピングされます。

KVMをVirtualization Host Extensionsで使用する場合、追加のマッピングは作成されません。ホストカーネルがEL2で直接実行されるためです。

カーネルにおける52ビットVAサポート¶

ARMv8.2-LVAオプション機能が存在し、64KBページサイズで実行している場合、ユーザー空間およびカーネルアドレスの両方に52ビットのアドレス空間を使用できます。ただし、52ビットをサポートするカーネルバイナリは、ハードウェア機能が存在しない場合でも早期起動時に48ビットに戻す必要があります。

このフォールバックメカニズムにより、カーネルの.textセクションはより高いアドレスに配置される必要があり、これにより48/52ビットの仮想アドレス（VA）に依存しないことになる。カサーン（kasan）シャドウ領域は全体のカーネルVA空間の一部に過ぎないため、48/52ビットの両方においてカサーンシャドウの終端も高い半分の領域に配置しなければならない。（48ビットから52ビットへの切り替えでは、カサーンシャドウの終端は~0ULに依存し、不変であり、開始アドレスは下位アドレスへ「拡張」する）

phys_to_virtおよびvirt_to_physの最適化のために、PAGE_OFFSETは常に0xFFF0000000000000（52ビット対応）に固定される。これにより、追加の変数読み込みが不要になる。physvirtオフセットとvmemmapオフセットは早期起動時に計算され、この論理を実現する。

単一のバイナリが48ビットと52ビットの両方のVA空間をサポートする必要があるため、VMEMMAPは52ビットのVAに十分なサイズを確保し、さらに固定のPAGE_OFFSETを収容するための十分なサイズを確保しなければならない。

カーネル内のほとんどのコードはVA_BITSを考慮する必要はなく、VAサイズを知る必要があるコードでは以下のように変数が定義される：

VA_BITS定数は 最大値 仮想アドレス空間のサイズ

VA_BITS_MIN定数は 最小値 仮想アドレス空間のサイズ

vabits_actual変数は 実際の値 仮想アドレス空間のサイズ

最大値と最小値は、バッファが十分なサイズになるようにしたり、最悪の場合でもアドレスが十分近い位置に配置されるようにするのに役立つ。

52ビットユーザー空間VA¶

ARMv8.0のVA空間最大サイズが48ビットであるソフトウェアとの互換性を維持するため、カーネルはデフォルトでは48ビット範囲からユーザー空間に仮想アドレスを返す。

ソフトウェアはmmapヒントパラメータを48ビットより大きい値に指定することで、52ビット空間からのVAを受け取るよう「オプイン」できる。

例:

maybe_high_address = mmap(~0UL, size, prot, flags,...);

また、以下のカーネル構成オプションを有効にすることで、デバッグ用のカーネルをビルドして52ビット空間からのアドレスを返すことも可能である：

CONFIG_EXPERT=y && CONFIG_ARM64_FORCE_52BIT=y

このオプションはデバッグアプリケーション用にのみ意図されており、本番環境で使用すべきではありません。
