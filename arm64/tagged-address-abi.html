AArch64 TAGGED ADDRESS ABI¶

著者: Vincenzo Frascino <vincenzo.frascino@arm.com>

Catalin Marinas <catalin.marinas@arm.com>

日付: 2019年8月21日

このドキュメントでは、AArch64 Linuxにおけるタグ付きアドレスABIの使用方法とセマンティクスについて説明します。

1. はじめに¶

AArch64では、 TCR_EL1.TBI0 ビットがデフォルトで設定されており、ユーザー空間（EL0）が非ゼロの上位バイトを持つ64ビットポインタを通じてメモリアクセスを実行できるようにしています。このドキュメントでは、ユーザー空間が特定のタグ付きポインタをカーネルシステムコールに渡すことを可能にするシステムコールABIの緩和について説明します。

2. AArch64 タグ付きアドレスABI¶

このドキュメントにおけるカーネルシステムコールインターフェースの観点から、「有効なタグ付きポインタ」は、ユーザープロセスアドレス空間内のアドレスを参照し、以下のいずれかの方法で取得された可能性のある非ゼロの上位バイトを持つポインタです：

  • mmap() システムコールにおいて、次のいずれかが成立する場合：

    • フラグが MAP_ANONYMOUS ビットが設定されているか、

    • ファイル記述子が通常のファイル（ memfd_create()) か、 /dev/zero

  • brk() システムコール（つまり、プロセス作成時のプログラムブレイクの初期位置と現在の位置の間のヒープ領域）

  • プロセス作成時にカーネルによってマッピングされたメモリ（ mmap() 上記と同じ制限が適用される（例：データ、BSS、スタックなど）。

AArch64 タグ付きアドレスABIは、ユーザーアドレスがカーネルによってどのように使用されるかに応じて、2段階の緩和があります：

  1. カーネルによってアクセスされないが、アドレス空間管理に使用されるユーザーアドレス（例： mprotect(), madvise()）。この文脈での有効なタグ付きポインタの使用は、以下の例外を除いて許可されています：

    • brk(), mmap() 2.5開発シリーズで導入された形式です。 new_address 引数として mremap() これらのアリアスする可能性があるため、既存の

      ユーザーのアドレスと衝突する可能性があります。

      注意: この挙動はv5.6で変更され、以前のカーネルが有効なタグ付きポインタを誤って受け入れる可能性があります。 brk(), mmap() および mremap() システムコールの

    • 以下の range.start, start および dst 引数としての UFFDIO_* ioctl()``s used on a file descriptor obtained from ``userfaultfd()、ファイルディスクリプタから読み取った後に得られるエラーアドレスはタグが付けられず、タグ無知なプログラムを混乱させる可能性があります。

      注意: この挙動はv5.14で変更され、以前のカーネルが有効なタグ付きポインタを誤って受け入れる可能性があります。

  2. カーネルがアクセスするユーザーのアドレス（例 write()）。このABIの緩和はデフォルトで無効になっており、アプリケーションスレッドは明示的に有効にする必要があります prctl() 以下のようになります:

    • PR_SET_TAGGED_ADDR_CTRL：呼び出しスレッドのAArch64タグ付きアドレスABIを有効にするか無効にするかを指定します。

      以下の (unsigned int) arg2 引数は使用される制御モードを記述するビットマスクです：

      • PR_TAGGED_ADDR_ENABLE：AArch64タグ付きアドレスABIを有効にする。デフォルト状態は無効です。

      引数 arg3, arg4, and arg5 は0でなければなりません。

    • PR_GET_TAGGED_ADDR_CTRL：呼び出しスレッドのAArch64タグ付きアドレスABIの状態を取得します。

      引数 arg2, arg3, arg4, and arg5 は0でなければなりません。

    上記のABIプロパティはスレッドスコープであり、clone()とfork()で継承され、exec()でクリアされます。

    呼び出し prctl(PR_SET_TAGGED_ADDR_CTRL, PR_TAGGED_ADDR_ENABLE, 0, 0, 0) が返します -EINVAL AArch64 Tagged Address ABIがグローバルに無効化されている場合、 sysctl abi.tagged_addr_disabled=1デフォルトの sysctl abi.tagged_addr_disabled 設定は0です。

AArch64 Tagged Address ABIがスレッドで有効になっている場合、以下の動作が保証されています：

  • セクション3で記載されている例外を除き、すべてのシステムコールは有効なタグ付きポインタを受容できます。

  • 無効なタグ付きポインタに対しては、システムコールの動作は未定義です。エラー コードの返却、(致命的な)シグナルの発生、またはその他の失敗モードのいずれかが発生する可能性があります。

  • 有効なタグ付きポインタに対するシステムコールの動作は、対応する未タグ付けポインタに対する動作と同じです。

AArch64におけるタグ付きポインタの意味の定義は、 AArch64 Linuxにおけるタグ付き仮想アドレス.

3. AArch64 Tagged Address ABI例外¶

以下のシステムコールパラメータは、ABIの緩和に関係なく未タグ付けでなければなりません：

  • prctl() カーネルがアクセスするための直接または間接的に引数として渡されるユーザー データへのポインタを除く。

  • ioctl() カーネルがアクセスするための直接または間接的に引数として渡されるユーザー データへのポインタを除く。

  • shmat() および shmdt().

ゼロ以外のタグ付きポインタを使用する試みは、エラー コードの返却、(致命的な)シグナルの発生、またはその他の失敗モードのいずれかを引き起こす可能性があります。

4. 正しい使用例¶

#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/mman.h>
#include <sys/prctl.h>

#define PR_SET_TAGGED_ADDR_CTRL      55
#define PR_TAGGED_ADDR_ENABLE        (1UL << 0)

#define TAG_SHIFT            56

int main(void)
{
     int tbi_enabled = 0;
     unsigned long tag = 0;
     char *ptr;

     /* check/enable the tagged address ABI */
     if (!prctl(PR_SET_TAGGED_ADDR_CTRL, PR_TAGGED_ADDR_ENABLE, 0, 0, 0))
             tbi_enabled = 1;

     /* memory allocation */
     ptr = mmap(NULL, sysconf(_SC_PAGE_SIZE), PROT_READ | PROT_WRITE,
                MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
     if (ptr == MAP_FAILED)
             return 1;

     /* set a non-zero tag if the ABI is available */
     if (tbi_enabled)
             tag = rand() & 0xff;
     ptr = (char *)((unsigned long)ptr | (tag << TAG_SHIFT));

     /* memory access to a tagged address */
     strcpy(ptr, "tagged pointer\n");

     /* syscall with a tagged pointer */
     write(1, ptr, strlen(ptr));

     return 0;
}
