ARM64 CPU機能レジスタ¶

著者: Suzuki K Poulose <suzuki.poulose@arm.com>

このファイルは、AArch64 CPU ID/機能レジスタをユーザースペースにエクスポートするABIの仕様を説明しています。このABIの利用可能性はHWCAPsのHWCAP_CPUIDを通じてアドバタイズされます。

1. 動機¶

ARMアーキテクチャは、CPU/システムの機能を記述する一連の機能レジスタを定義しています。これらのシステムレジスタへのアクセスはEL0から制限されており、アプリケーションが実行時においてより良い決定を行うためにこの情報を抽出する信頼できる方法は存在しません。HWCAPsを通じてアプリケーションに利用可能な情報は限られており、その使用にはいくつかの問題があります。

  1. HWCAPsの変更にはユーザースペース（例: libc）の更新が必要となり、新しい変更がディストリビューションに反映されるまでに時間がかかることがあります。レジスタを公開することで、アプリケーションはツールチェーンの更新なしに情報を取得できます。

  2. HWCAPsへのアクセスは、たとえばlibc以前やldが起動時初期化される際など、制限されることがあります。

  3. HWCAPsは非ブール情報の効果的な表現が困難です。アーキテクチャはIDレジスタで機能を表す標準的な形式を定義しており、これは明確に定義されており、すべての有効なアーキテクチャ変種を表現可能です。

2. 要件¶

  1. 安全性:

    アプリケーションはインフラストラクチャが提供する情報をもとにシステム全体で安全に実行できる必要があります。特に異質なCPUを持つシステムでは、インフラストラクチャはシステム内のすべての利用可能なCPUで安全な値をエクスポートします。

    たとえば、少なくとも1つのCPUがCRC32指令を実装していない場合、他のCPUが実装している場合でもCRC32が実装されていないと報告する必要があります。それ以外に、CRC32をサポートしていないCPUにスケジュールされたアプリケーションがクラッシュする可能性があります。

  2. セキュリティ:

    アプリケーションはユーザースペースでの通常動作に関連する情報のみを受信できる必要があります。そのため、一部のフィールドはマスクされ（つまり、非表示にされ）、その値は機能が「サポートされていない」と示されます。可視的な機能の一覧については第4節を参照してください。また、カーネルはサポートしている内容に基づいてフィールドを操作する場合があります。たとえば、カーネルがFPをサポートしていない場合、FPが利用不可（CPUが提供しているにもかかわらず）と示される可能性があります。

  3. 実装定義の機能

    インフラストラクチャはARMv8-Aアーキテクチャに基づき、実装定義されたレジスタを公開しません。

  4. CPU識別:

    MIDR_EL1はプロセッサを特定するのに役立つように公開されています。異質なシステムでは、これはgetcpu()と同様にレース条件を引き起こす可能性があります（プロセスがレジスタ値を使用するまでに別のCPUに移動する可能性があるため）。CPUアフィニティが設定されていない限り、その値が現在実行中のプロセッサを反映しているとは限りません。この制約により、REVIDRは公開されていません。REVIDRはMIDRと組み合わせて意味を持つためです。代わりに、MIDR_EL1とREVIDR_EL1はsysfs経由で公開され、以下に示します:

    /sys/devices/system/cpu/cpu$ID/regs/identification/
                                              \- midr
                                              \- revidr

3. 実装¶

インフラストラクチャは「MRS」命令のエミュレーションに基づいて構築されています。アプリケーションから制限されたシステムレジスタにアクセスすると例外が発生し、SIGILLがプロセスに送信されます。インフラストラクチャは例外ハンドラに接続され、サポートされているシステムレジスタ空間に属する場合にその操作をエミュレートします。

インフラストラクチャがエミュレートするシステムレジスタ空間は以下の通りです:

Op0=3, Op1=0, CRn=0, CRm=0,4,5,6,7

(ARMv8 ARM DDI 0487A.hの「非デバッグシステムレジスタアクセス用のシステム命令符号化」表C5-6を参照してください。)

インフラストラクチャが返す値には以下のルールが適用されます:

  1. 「IMPLEMENTATION DEFINED（実装定義）」フィールドの値は0に設定されます。

  2. 予約済みフィールドの値はアーキテクチャで定義された予約値で埋められます。

  3. 「表示可能（visible）」フィールドの値は、特定の機能のシステム全体で安全な値を保持します（MIDR_EL1を除く、セクション4を参照）。

  4. 他のフィールド（つまり表示不可能なフィールド）は、アーキテクチャで定義されたようにして機能が欠如していることを示します。

#include <asm/hwcap.h>
#include <stdio.h>
#include <sys/auxv.h>

#define get_cpu_ftr(id) ({                                    \
              unsigned long __val;                            \
              asm("mrs %0, "#id : "=r" (__val));              \
              printf("%-20s: 0x%016lx\n", #id, __val);        \
      })

int main(void)
{

      if (!(getauxval(AT_HWCAP) & HWCAP_CPUID)) {
              fputs("CPUID registers unavailable\n", stderr);
              return 1;
      }

      get_cpu_ftr(ID_AA64ISAR0_EL1);
      get_cpu_ftr(ID_AA64ISAR1_EL1);
      get_cpu_ftr(ID_AA64MMFR0_EL1);
      get_cpu_ftr(ID_AA64MMFR1_EL1);
      get_cpu_ftr(ID_AA64PFR0_EL1);
      get_cpu_ftr(ID_AA64PFR1_EL1);
      get_cpu_ftr(ID_AA64DFR0_EL1);
      get_cpu_ftr(ID_AA64DFR1_EL1);

      get_cpu_ftr(MIDR_EL1);
      get_cpu_ftr(MPIDR_EL1);
      get_cpu_ftr(REVIDR_EL1);

#if 0
      /* Unexposed register access causes SIGILL */
      get_cpu_ftr(ID_MMFR0_EL1);
#endif

      return 0;
}
