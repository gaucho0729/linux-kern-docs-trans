ARM64 ELF hwcaps¶

このドキュメントは、arm64 ELF hwcaps の使用方法とセマンティクスについて説明します。

1. はじめに¶

一部のハードウェアやソフトウェア機能は、特定のCPU実装や/および特定のカーネル構成でのみ利用可能であり、EL0でのユーザースペースコードによるアーキテクチャの発見メカニズムが利用できない場合があります。カーネルは、これらの機能の存在をユーザースペースにauxiliary vector内のフラグ群（hwcaps）を通じて公開します。

ユーザースペースソフトウェアは、auxiliary vectorのAT_HWCAPまたはAT_HWCAP2エントリを取得し、関連するフラグが設定されているかをテストすることで機能を検証できます。例えば：

bool floating_point_is_present(void)
{
        unsigned long hwcaps = getauxval(AT_HWCAP);
        if (hwcaps & HWCAP_FP)
                return true;

        return false;
}

hwcapで記述される機能に依存するソフトウェアは、機能が存在することを確認するために関連するhwcapフラグをチェックする必要があります。

他の手段で機能をプローブすることは信頼性がありません。機能が利用できない場合、その機能を使用しようとすると予測不能な挙動が発生する可能性があり、SIGILLなどの信頼できるインジケーターが得られない場合があります。

2. hwcapsの解釈¶

ほとんどのhwcapsは、EL0でのユーザースペースコードがアクセスできないアーキテクチャIDレジスタで記述される機能の存在を示す目的で設計されています。これらのhwcapsはIDレジスタのフィールドに基づいて定義されており、ARM Architecture Reference Manual（ARM ARM）におけるこれらのフィールドの定義を参照して解釈する必要があります。

このようなhwcapsは以下の形式で説明されます：

Functionality implied by idreg.field == val.

このようなhwcapsは、idreg.fieldがvalの値を持つときにARM ARMで定義される機能の存在を示しますが、idreg.fieldが正確にvalに等しいことを示すわけではありません。また、idreg.fieldの他の値によって引き起こされる機能の欠如を示すわけではありません。

他のhwcapsはIDレジスタだけでは記述できない機能の存在を示す場合があります。これらはIDレジスタへの参照を必要とせず、他のドキュメントを参照する可能性があります。

4. 使用されていない AT_HWCAP ビット¶

ユーザー空間との相互運用性のために、AT_HWCAP のビット62およびビット63は常に0として返されることが保証されています。
