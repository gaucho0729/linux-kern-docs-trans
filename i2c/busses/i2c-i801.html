モジュールパラメータ¶

  • disable_features (ビットベクター)

デバイスが通常サポートする機能を無効化します。この機能により、ドライバーやハードウェアのバグを回避することが可能です。ビット値:

0x01

SMBus PECの無効化

0x02

ブロックバッファの無効化

0x08

I2Cブロック読み取り機能の無効化

0x10

割込みを使用しない

0x20

SMBusホスト通知の無効化

説明¶

ICH（正式名称は82801AA）、ICH0（82801AB）、ICH2（82801BA）、ICH3（82801CA/CAM）および後のデバイス（PCH）は、インテルの「810」チップセット（セレロンベースのPC用）、「810E」チップセット（ピューリアムベースのPC用）、「815E」チップセット、その他のチップセットに含まれるインテルのチップです。

ICHチップは、少なくとも2つの論理的なPCIデバイスに含まれる7つの別個のPCI機能を持っています。lspciの出力は以下のようになります:

00:1e.0 PCI bridge: Intel Corporation: Unknown device 2418 (rev 01)
00:1f.0 ISA bridge: Intel Corporation: Unknown device 2410 (rev 01)
00:1f.1 IDE interface: Intel Corporation: Unknown device 2411 (rev 01)
00:1f.2 USB Controller: Intel Corporation: Unknown device 2412 (rev 01)
00:1f.3 Unknown class [0c05]: Intel Corporation: Unknown device 2413 (rev 01)

SMBusコントローラーはデバイス1fの機能3です。クラス0c05はSMBusシリアルコントローラーです。

ICHチップは、少なくともSMBusコントローラーではインテルのPIIX4チップと非常に似ています。

プロセスコールサポート¶

82801EB（ICH5）以降のチップではブロックプロセスコールがサポートされています。

I2Cブロック読み取りサポート¶

82801EB（ICH5）以降のチップではI2Cブロック読み取りがサポートされています。

SMBus 2.0サポート¶

82801DB（ICH4）以降のチップではいくつかのSMBus 2.0機能がサポートされています。

割込みサポート¶

PCI割込みサポートは82801EB（ICH5）以降のチップでサポートされています。

隠されたICH SMBus¶

システムにインテルICH南橋が搭載されているにもかかわらず、lspciで00:1f.3にSMBusデバイスが表示されず、BIOSで有効化する方法も見つからない場合は、BIOSコードによって隠されている可能性があります。AsusはP4Bマザーボードで最初にこの処理を行ったことで知られており、その後多くのボードでも同様の処理が行われています。一部のベンダーのマシンにも影響が出ることがあります。

まず試すべきは「i2c-scmi」ACPIドライバーです。SMBusが意図的に非表示になっている可能性があり、これはACPIによって駆動されるためです。もし「i2c-scmi」ドライバーが動作すれば、以後は「i2c-i801」ドライバーを無視し、ICH SMBusを非表示にしようとしないでください。たとえ「i2c-scmi」が動作しなくても、ACPIコードがSMBusを使用していないことを確認してください。まず「fan」および「thermal」ドライバーをロードし、/sys/class/thermalを確認してください。もし「acpitz」というタイプのサーモアルゾーンが見つかったら、ACPIがSMBusを使用している可能性があり、安全のため非表示にしないほうがよいでしょう。ACPIがSMBusを使用していないことを確実に確認した後で、非表示を解除してください。

SMBusを非表示解除するには、カーネルがPCIデバイスを列挙する前にPCIレジスタの値を変更する必要があります。これはdrivers/pci/quirks.cで行われ、すべての影響を受けるボードがリストに記載されている必要があります（関数asus_hides_smbus_hostbridgeを参照）。SMBusデバイスが見つからない場合、SMBusに何か興味深いものがあると推測する場合は（例: ハードウェアモニタリングチップ）、自分のボードをリストに追加する必要があります。

マザーボードはホストブリッジPCIデバイスのサブベンダーIDとサブデバイスIDによって識別されます。以下で自分のIDを取得してください。 lspci -n -v -s 00:00.0:

00:00.0 Class 0600: 8086:2570 (rev 02)
        Subsystem: 1043:80f2
        Flags: bus master, fast devsel, latency 0
        Memory at fc000000 (32-bit, prefetchable) [size=32M]
        Capabilities: [e4] #09 [2106]
        Capabilities: [a0] AGP version 3.0

ここではホストブリッジIDが2570（82865G/PE/P）、サブベンダーIDが1043（Asus）、サブデバイスIDが80f2（P4P800-X）です。ブリッジIDとサブベンダーIDのシンボリック名はinclude/linux/pci_ids.hで確認できます。次にdrivers/pci/quirks.cの適切な場所に自分のサブデバイスID用のcaseを追加してください。その後、非表示にしたSMBusが他のデバイスと競合していないことを十分にテストしてください。

動作し、有用（SMBusに利用可能なチップがある）かつ安全に見える場合は、カーネルへのパッチ提出を検討してください。

注意: lm_sensors 2.10.2以降には、unhide_ICH_SMBusというスクリプトがprog/hotplugに含まれており、fakephpドライバーを使用してカーネルをパッチングせずにSMBusを一時的に非表示解除できます。自分の隠されたICH SMBusに興味深いデバイスがあるかどうかを確認したい場合に非常に便利です。

lm_sensorsプロジェクトは、このドライバーの初期開発においてテキサスインSTRUMENTSの支援を心から感謝します。

lm_sensorsプロジェクトは、このドライバーのSMBus 2.0 / ICH4機能開発においてインテルの支援を心から感謝します。
