ユーザー空間でのI2Cデバイスドライバの実装¶

通常、I2Cデバイスはカーネルドライバによって制御されます。ただし、/devインターフェースを通じてアダプター上のすべてのデバイスにアクセスすることも可能です。このためにはモジュールi2c-devをロードする必要があります。

各登録されたI2Cアダプターには0から始まる番号が割り当てられます。/sys/class/i2c-dev/を確認することでどのアダプターにどの番号が割り当てられているかを確認できます。あるいは、「i2cdetect -l」を実行することで、システムに存在するすべてのI2Cアダプターの一覧を取得できます。i2cdetectはi2c-toolsパッケージに含まれます。

I2Cデバイスファイルは、主装置番号89で、サブ装置番号は上記の説明に基づいて割り当てられた番号に対応します。これらは「i2c-%d」（i2c-0、i2c-1、…、i2c-10、…）と呼ばなければなりません。すべての256つのサブ装置番号はI2C用に予約されています。

Cの例¶

では、CプログラムからI2Cアダプターにアクセスしたいとします。まず、次の2つのヘッダーファイルをインクルードする必要があります：

#include <linux/i2c-dev.h>
#include <i2c/smbus.h>

次に、アクセスしたいアダプターを決定する必要があります。このためには、/sys/class/i2c-dev/を確認するか、「i2cdetect -l」を実行してください。アダプター番号は多少動的に割り当てられるため、予測することはできません。1回の起動ごとに変化する可能性もあります。

次に、デバイスファイルを開きます。以下のように実行します：

int file;
int adapter_nr = 2; /* probably dynamically determined */
char filename[20];

snprintf(filename, 19, "/dev/i2c-%d", adapter_nr);
file = open(filename, O_RDWR);
if (file < 0) {
  /* ERROR HANDLING; you can check errno to see what went wrong */
  exit(1);
}

デバイスを開いたら、通信したいデバイスアドレスを指定する必要があります：

int addr = 0x40; /* The I2C address */

if (ioctl(file, I2C_SLAVE, addr) < 0) {
  /* ERROR HANDLING; you can check errno to see what went wrong */
  exit(1);
}

これで準備が整いました。これより、SMBusコマンドやプレーンI2Cを用いてデバイスと通信できます。デバイスがSMBusコマンドをサポートする場合は、それらを優先的に使用してください。以下に両方の例を示します：

__u8 reg = 0x10; /* Device register to access */
__s32 res;
char buf[10];

/* Using SMBus commands */
res = i2c_smbus_read_word_data(file, reg);
if (res < 0) {
  /* ERROR HANDLING: I2C transaction failed */
} else {
  /* res contains the read word */
}

/*
 * Using I2C Write, equivalent of
 * i2c_smbus_write_word_data(file, reg, 0x6543)
 */
buf[0] = reg;
buf[1] = 0x43;
buf[2] = 0x65;
if (write(file, buf, 3) != 3) {
  /* ERROR HANDLING: I2C transaction failed */
}

/* Using I2C Read, equivalent of i2c_smbus_read_byte(file) */
if (read(file, buf, 1) != 1) {
  /* ERROR HANDLING: I2C transaction failed */
} else {
  /* buf[0] contains the read byte */
}

注意：read()およびwrite()コールによって実現可能なI2CおよびSMBusプロトコルのサブセットに限定されます。特に、読み取りと書き込みメッセージを同じトランザクション内で混在させる「結合トランザクション」はサポートされていません。そのため、このインターフェースはユーザー空間のプログラムでほぼ使われません。

重要：インライン関数の使用により、 が プログラムをコンパイルする際には「-O」またはその変種を指定する必要があります！

インターフェースの完全な説明¶

次のIOCTLが定義されています：

ioctl(file, I2C_SLAVE, long addr)

スレーブアドレスを変更します。引数の7ビット下位がアドレスとして使用されます（10ビットアドレスの場合は10ビット下位が使用されます）。

ioctl(file, I2C_TENBIT, long select)

selectが0でない場合、10ビットアドレスを選択し、0の場合、通常の7ビットアドレスを選択します。デフォルトは0です。このリクエストはアダプターがI2C_FUNC_10BIT_ADDRをサポートしている場合にのみ有効です。

ioctl(file, I2C_PEC, long select)

selectが0でない場合、SMBus PEC（パケットエラー検出）の生成および検証を有効にし、0の場合には無効にします。デフォルトは0です。SMBusトランザクションでのみ使用されます。このリクエストはアダプターがI2C_FUNC_SMBUS_PECをサポートしている場合にのみ効果を発揮します。サポートしていない場合でも安全です。ただ単に効果がありません。

ioctl(file, I2C_FUNCS, unsigned long *funcs)

アダプターの機能を取得し、それを設定します *funcs.

ioctl(file, I2C_RDWR, struct i2c_rdwr_ioctl_data *msgset)

途中でストップを挟まない複合的な読み書きトランザクションを行います。アダプターがI2C_FUNC_I2Cをサポートしている場合にのみ有効です。引数は以下のポインタです:

struct i2c_rdwr_ioctl_data {
  struct i2c_msg *msgs;  /* ptr to array of simple messages */
  int nmsgs;             /* number of messages to exchange */
}

msgs[]自身はデータバッファへのポインタを含みます。関数は、メッセージごとにI2C_M_RDフラグが設定されているかどうかに応じて、そのバッファにデータを書き込むか読み込むかを行います。slaveアドレスおよび10ビットアドレスモードの使用を各メッセージで設定する必要があります。これは上記のioctlで設定した値を上書きします。

ioctl(file, I2C_SMBUS, struct i2c_smbus_ioctl_data *args)

可能であれば、以下の説明されたメソッドを使用してください。直接のioctlを発行するのではなく i2c_smbus_* メソッドを提供しています。

read(2)およびwrite(2)コールを使用することで、通常のI2Cトランザクションを行えます。アドレスバイトを渡す必要はありません。代わりに、デバイスにアクセスする前にioctl I2C_SLAVEでアドレスを設定してください。

SMBusレベルのトランザクション（詳細はドキュメントファイルsmbus-protocolを参照）は以下の関数を通じて行えます:

__s32 i2c_smbus_write_quick(int file, __u8 value);
__s32 i2c_smbus_read_byte(int file);
__s32 i2c_smbus_write_byte(int file, __u8 value);
__s32 i2c_smbus_read_byte_data(int file, __u8 command);
__s32 i2c_smbus_write_byte_data(int file, __u8 command, __u8 value);
__s32 i2c_smbus_read_word_data(int file, __u8 command);
__s32 i2c_smbus_write_word_data(int file, __u8 command, __u16 value);
__s32 i2c_smbus_process_call(int file, __u8 command, __u16 value);
__s32 i2c_smbus_block_process_call(int file, __u8 command, __u8 length,
                                   __u8 *values);
__s32 i2c_smbus_read_block_data(int file, __u8 command, __u8 *values);
__s32 i2c_smbus_write_block_data(int file, __u8 command, __u8 length,
                                 __u8 *values);

すべてのトランザクションは失敗時に-1を返します。errnoを読み込むことで発生した原因を確認できます。'write'トランザクションは成功時に0を、'read'トランザクションは読み取った値を返します（read_blockを除く）。ブロックバッファは32バイト以上必要ありません。

上記の関数はlibi2cライブラリにリンクすることで利用可能です。これはi2c-toolsプロジェクトで提供されています。参照: https://git.kernel.org/pub/scm/utils/i2c-tools/i2c-tools.git/.

実装詳細¶

関心のある方のために、I2Cを/devインターフェースで使用する際のカーネル内のコードフローを以下に示します:

  1. プログラムは/dev/i2c-Nを開き、上記の「C例」セクションに記載されているようにioctl()を呼び出します。

  2. これらのopen()およびioctl()呼び出しはi2c-devカーネルドライバによって処理されます。詳しくはi2c-dev.c:i2cdev_open()およびi2c-dev.c:i2cdev_ioctl()を参照してください。i2c-devはユーザー空間からプログラミング可能な汎用的なI2Cチップドライバとみなせます。

  3. 一部のioctl()呼び出しは管理タスク用であり、i2c-devが直接処理します。例としてI2C_SLAVE（アクセスしたいデバイスのアドレスを設定）やI2C_PEC（今後のトランザクションにおけるSMBusエラー検出を有効/無効にします）があります。

  4. i2c-devは、他のioctl()呼び出しを内核内の関数呼び出しに変換します。例としてI2C_FUNCSがあり、これはi2c.h:i2c_get_functionality()を使用してI2Cアダプタの機能を照会し、I2C_SMBUSはi2c-core-smbus.cでSMBusトランザクションを実行します。i2c_smbus_xfer().

    i2c-devドライバーは、ユーザースペースから渡されるすべてのパラメータの正当性を確認します。この後、ユーザースペース経由の呼び出しと内核のI2Cチップドライバーによる直接呼び出しには違いがありません。これは、I2Cバスドライバーがユーザースペースからのアクセスをサポートするために特別な処理を実装する必要がないことを意味します。

  5. これらのi2c.h関数は、実際のI2Cバスドライバーの実装をラッパーとして提供します。各アダプタは、これらの標準的な呼び出しを実装するコールバック関数を宣言しなければなりません。i2c.h:i2c_get_functionality()はi2c_adapter.algo->functionality()を呼び出し、i2c-core-smb,us.c:i2c_smbus_xfer() adapter.algo->smbus_xfer()が実装されている場合はそれを呼び、そうでない場合はi2c-core-smbus.c:i2c_smbus_xfer_emulated()を呼び出します。これは順にi2c_adapter.algo->master_xfer()を呼び出します。

I2Cバスドライバーがこれらのリクエストを処理した後、実行は呼び出しチェーンを上へ戻り、ほぼ処理は行われません。ただし、i2c-devは返却データ（あった場合）をioct()呼び出しに適した形式でパッケージングします。
