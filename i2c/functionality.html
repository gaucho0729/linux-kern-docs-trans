I2C/SMBus Functionality¶

はじめに¶

すべてのI2CまたはSMBusアダプタがI2C仕様のすべてを実装しているわけではないため、クライアントはアダプタに接続するオプションが与えられたときに必要な機能がすべて実装されているとは信頼できません。クライアントはアダプタが必要な機能を備えているかを確認する方法が必要です。

機能定数¶

最新の機能定数一覧については、<uapi/linux/i2c.h>をご確認ください！

I2C_FUNC_I2C

純粋なI2Cレベルのコマンド（純粋なSMBusアダプタは通常これらを実行できません）

I2C_FUNC_10BIT_ADDR

10ビットアドレス拡張を処理します

I2C_FUNC_PROTOCOL_MANGLING

I2C_M_IGNORE_NAK、I2C_M_REV_DIR_ADDR、I2C_M_NO_RD_ACKフラグについて把握しています（これらはI2Cプロトコルを変更します！）

I2C_FUNC_NOSTART

繰り返しスタートシーケンスをスキップできます

I2C_FUNC_SMBUS_QUICK

SMBusのwrite_quickコマンドを処理します

I2C_FUNC_SMBUS_READ_BYTE

SMBusのread_byteコマンドを処理します

I2C_FUNC_SMBUS_WRITE_BYTE

SMBusのwrite_byteコマンドを処理します

I2C_FUNC_SMBUS_READ_BYTE_DATA

SMBusのread_byte_dataコマンドを処理します

I2C_FUNC_SMBUS_WRITE_BYTE_DATA

SMBusのwrite_byte_dataコマンドを処理します

I2C_FUNC_SMBUS_READ_WORD_DATA

SMBusのread_word_dataコマンドを処理します

I2C_FUNC_SMBUS_WRITE_WORD_DATA

SMBusのwrite_byte_dataコマンドを処理します

I2C_FUNC_SMBUS_PROC_CALL

SMBusのprocess_callコマンドを処理します

I2C_FUNC_SMBUS_READ_BLOCK_DATA

SMBusのread_block_dataコマンドを処理します

I2C_FUNC_SMBUS_WRITE_BLOCK_DATA

SMBusのwrite_block_dataコマンドを処理します

I2C_FUNC_SMBUS_READ_I2C_BLOCK

SMBusのread_i2c_block_dataコマンドを処理します

I2C_FUNC_SMBUS_WRITE_I2C_BLOCK

SMBusのwrite_i2c_block_dataコマンドを処理します

上記のフラグのいくつかの組み合わせは、ご利便のため定義されています：

I2C_FUNC_SMBUS_BYTE

SMBusのread_byteおよびwrite_byteコマンドを処理します

I2C_FUNC_SMBUS_BYTE_DATA

SMBusのread_byte_dataおよびwrite_byte_dataコマンドを処理します

I2C_FUNC_SMBUS_WORD_DATA

SMBus read_word_data および write_word_data コマンドを処理します

I2C_FUNC_SMBUS_BLOCK_DATA

SMBus read_block_data および write_block_data コマンドを処理します

I2C_FUNC_SMBUS_I2C_BLOCK

SMBus read_i2c_block_data および write_i2c_block_data コマンドを処理します

I2C_FUNC_SMBUS_EMUL

実際の I2C アダプタでエミュレート可能なすべての SMBus コマンドを処理します（透過的エミュレーションレイヤーを使用）

カーネルバージョン3.5以前では、I2C_FUNC_NOSTART は I2C_FUNC_PROTOCOL_MANGLING の一部として実装されていました。

アダプタ実装¶

新しいアダプタドライバを作成する際には、関数コールバックを実装する必要があります functionality典型的な実装例は以下の通りです。

典型的なSMBus専用アダプタは、サポートするSMBusトランザクションをすべてリストアップします。この例はi2c-piix4ドライバからのものです:

static u32 piix4_func(struct i2c_adapter *adapter)
{
      return I2C_FUNC_SMBUS_QUICK | I2C_FUNC_SMBUS_BYTE |
             I2C_FUNC_SMBUS_BYTE_DATA | I2C_FUNC_SMBUS_WORD_DATA |
             I2C_FUNC_SMBUS_BLOCK_DATA;
}

典型的なフルI2Cアダプタは以下のようになります（i2c-pxaドライバからの例）:

static u32 i2c_pxa_functionality(struct i2c_adapter *adap)
{
      return I2C_FUNC_I2C | I2C_FUNC_SMBUS_EMUL;
}

I2C_FUNC_SMBUS_EMUL は、i2c-coreがI2Cアダプタ上でI2C_FUNC_I2Cを使用してエミュレート可能なSMBusトランザクション（I2Cブロックトランザクションを含む）をすべて含みます。目的は、クライアントドライバがSMBus機能をサポートしているかを確認できるようにすることです。アダプタがハードウェアで実装しているか、i2c-coreがソフトウェアでエミュレートしているかはクライアントドライバには関係ありません。

クライアントの確認¶

クライアントがアダプタに接続しようとする前、またはアダプタにサポートするデバイスが存在するかテストする前に、必要な機能が存在するか確認する必要があります。典型的な方法は（lm75ドライバからの例）:

static int lm75_detect(...)
{
      (...)
      if (!i2c_check_functionality(adapter, I2C_FUNC_SMBUS_BYTE_DATA |
                                   I2C_FUNC_SMBUS_WORD_DATA))
              goto exit;
      (...)
}

ここでは、lm75ドライバがアダプタがSMBusバイトデータトランザクションとSMBusワードデータトランザクションの両方を実行できるかを確認しています。実行できない場合、このアダプタではドライバが動作しないため、以降の処理は不要です。上記の確認が成功した場合、ドライバは以下の関数を呼び出すことができます: i2c_smbus_read_byte_data(), i2c_smbus_write_byte_data(), i2c_smbus_read_word_data() および i2c_smbus_write_word_data()一般的なルールとして、i2c_check_functionality() でテストする機能定数は、ドライバが呼び出している i2c_smbus_* 関数と完全に一致する必要があります。

上記の確認は、アダプタがハードウェアで機能を実装しているか、i2c-coreがソフトウェアでエミュレートしているかを示すものではありません。クライアントドライバはこれに気を配る必要がありません。i2c-coreがI2Cアダプタ上でSMBusトランザクションを透過的に実装するためです。

/dev を通じた確認¶

ユーザー空間のプログラムからアダプターにアクセスしようとする場合、/devインターフェースを使用する必要があります。もちろん、必要な機能がサポートされているか確認する必要があります。これはI2C_FUNCS ioctlを使用して行います。以下に、i2cdetectプログラムから改変した例を示します：

int file;
if (file = open("/dev/i2c-0", O_RDWR) < 0) {
      /* Some kind of error handling */
      exit(1);
}
if (ioctl(file, I2C_FUNCS, &funcs) < 0) {
      /* Some kind of error handling */
      exit(1);
}
if (!(funcs & I2C_FUNC_SMBUS_QUICK)) {
      /* Oops, the needed functionality (SMBus write_quick function) is
         not available! */
      exit(1);
}
/* Now it is safe to use the SMBus write_quick command */
