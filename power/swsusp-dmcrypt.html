dm-crypt と swsusp の併用方法¶

著者: Andreas Steinmetz <ast@domdv.de>

前提条件: dm-crypt の仕組みを理解している必要があります。理解していない場合は、以下のウェブページを参照してください: http://www.saout.de/misc/dm-crypt/ あなたは読みました スワップスリープ を理解しています。実際に読みました 初期 RAM ディスク (initrd) の使用 initrd の仕組みを理解しています。initrd を作成するか、編集する方法を知っています。

システムが正しく設定されているので、ディスクは暗号化されています。ただし、swap デバイスとブートパーティションは暗号化されていません。ブートパーティションには、暗号化設定や緊急復旧用のミニシステムが含まれている可能性があります。現在の暗号化設定をすでに含む initrd を持っているかもしれません。

この時点で、swap も暗号化したいです。ただし、swsusp を使ってスリープを続ける機能も維持したいです。しかし、これは、再開前にパスフレーズを入力するか、pcmcia フラッシュディスクやUSBメモリなどの外部デバイスから鍵を読み込む必要があることを意味します。そのため、initrd を用意し、dm-crypt を設定した後、暗号化された swap デバイスから再開を依頼する必要があります。

最も重要なのは、swap デバイスがinitrdおよび実行中のシステムの両方で常に同じ major/minor を保持することです。これを実現する最も簡単な方法は、dmsetup を使ってこの swap デバイスを最初に設定することです。これにより、常に以下のようになります:

brw-------  1 root root 254, 0 Jul 28 13:37 /dev/mapper/swap0

次に、カーネルを /dev/mapper/swap0 をデフォルトの再開パーティションとして使用するように設定してください。これにより、カーネルの .config ファイルには以下が含まれます:

CONFIG_PM_STD_PARTITION="/dev/mapper/swap0"

ブートローダーを新しく作成または編集した initrd を使用するように準備してください。lilo の場合、最も簡単な設定は以下の行のように見えます:

image=/boot/vmlinuz
initrd=/boot/initrd.gz
label=linux
append="root=/dev/ram0 init=/linuxrc rw"

最後に、initrd を作成または編集する必要があります。仮に pcmcia フラッシュディスクから dm-crypt の設定を読み込む initrd を作成する場合、カードは挿入時に /dev/hde1 に配置された ext2 ファイルシステムでフォーマットされています。このカードには、少なくとも「swapkey」という名前のファイルに保存された暗号化された swap 設定が含まれています。initrd の /etc/fstab には以下のようないくつかの設定が含まれています:

/dev/hda1   /mnt    ext3      ro                            0 0
none        /proc   proc      defaults,noatime,nodiratime   0 0
none        /sys    sysfs     defaults,noatime,nodiratime   0 0

/dev/hda1 には、暗号化されていないミニシステムが含まれており、これにより pcmcia フラッシュディスクから設定を読みながらすべての暗号化デバイスを設定します。以下に、暗号化された swap から再開を可能にする initrd の /linuxrc が続きます。再開が失敗した場合でも、/dev/hda1 上のミニシステムで起動を継続します:

#!/bin/sh
PATH=/sbin:/bin:/usr/sbin:/usr/bin
mount /proc
mount /sys
mapped=0
noresume=`grep -c noresume /proc/cmdline`
if [ "$*" != "" ]
then
  noresume=1
fi
dmesg -n 1
/sbin/cardmgr -q
for i in 1 2 3 4 5 6 7 8 9 0
do
  if [ -f /proc/ide/hde/media ]
  then
    usleep 500000
    mount -t ext2 -o ro /dev/hde1 /mnt
    if [ -f /mnt/swapkey ]
    then
      dmsetup create swap0 /mnt/swapkey > /dev/null 2>&1 && mapped=1
    fi
    umount /mnt
    break
  fi
  usleep 500000
done
killproc /sbin/cardmgr
dmesg -n 6
if [ $mapped = 1 ]
then
  if [ $noresume != 0 ]
  then
    mkswap /dev/mapper/swap0 > /dev/null 2>&1
  fi
  echo 254:0 > /sys/power/resume
  dmsetup remove swap0
fi
umount /sys
mount /mnt
umount /proc
cd /mnt
pivot_root . mnt
mount /proc
umount -l /mnt
umount /proc
exec chroot . /sbin/init $* < dev/console > dev/console 2>&1

上記の不思議なループについては気にしないでください。busyboxのmshはletステートメントを認識していません。では、スクリプト内で何が起きているのか説明します。まず、再開を試みるかどうかを決定する必要があります。起動パラメータに「noresume」や初期化用のパラメータ「single」や「emergency」が指定されている場合は再開しません。

次に、PCMCIAフラッシュディスクから取得した設定データをもとにdmcryptを設定する必要があります。設定成功した場合は、再開をしない場合はスワップデバイスをリセットする必要があります。「echo 254:0 > /sys/power/resume」の行は、最初のデバイスマッパーのデバイスから再開を試みます。注意点として、再開するかどうかに関わらず、/sys/power/resumeにデバイスを設定しておくことが重要です。後続のスリープ処理が失敗する可能性があります。再開が開始すると、スクリプトの実行はここで終了します。

再開しない場合は、単に暗号化されたスワップデバイスを削除し、/dev/hda1上のminiシステムに全体の暗号化設定を任せます（ご自身で好みに合わせて調整してください）。

その後に続くのは、ルートファイルシステムを変更し、そこから起動を継続するというよく知られたプロセスです。私は起動を継続する前にinitrdをアンマウントするのが好みですが、ご自身で調整してください。
