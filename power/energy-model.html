デバイスのエネルギー計算モデル¶

1. 概要¶

エネルギー計算モデル（EM）フレームワークは、デバイスのパフォーマンスレベルごとの消費電力を知るドライバと、その情報をもとにエネルギー意識の決定を行うカーネルサブシステムの間のインターフェースとして機能します。

デバイスの消費電力に関する情報の出所はプラットフォームによって大きく異なります。一部のケースではdevicetreeデータを用いて推定することが可能ですが、他のケースではファームウェアがより正確な情報を持ち、さらにはユーザースペースが最適な位置にあることもあります。各クライアントサブシステムがそれぞれの情報源に対応する実装を繰り返すのを防ぐため、EMフレームワークは抽象化レイヤーとして介入し、カーネル内での電力コストテーブルのフォーマットを標準化することで、冗長な作業を回避します。

以下の図は、EMフレームワークに電力コスト情報を提供するドライバ（ここではアームアーキテクチャに特化していますが、他のアーキテクチャにも適用可能）と、その情報を読み取るクライアントの例を示しています。

| Thermal (IPA) |  | Scheduler (EAS) |  |     Other     |
+---------------+  +-----------------+  +---------------+
        |                   | em_cpu_energy()   |
        |                   | em_cpu_get()      |

                  |         |         |
                  v         v         v
                 +---------------------+

                 |     Framework       |

         +----------+       |       +---------+

 | Device Tree  |   |   Firmware    |  |      ?       |

CPUデバイスの場合、EMフレームワークはシステム内の「パフォーマンスドメイン」ごとに電力コストテーブルを管理します。パフォーマンスドメインとは、パフォーマンスが一緒にスケーリングされるCPUのグループです。一般的にパフォーマンスドメインはCPUFreqポリシーと1対1で対応しており、パフォーマンスドメイン内のすべてのCPUは同一のマイクロアーキテクチャを備つなければなりません。異なるパフォーマンスドメインのCPUは異なるマイクロアーキテクチャを持つことができます。

2. コアAPI¶

2.1 コンフィグオプション¶

EMフレームワークを使用するにはCONFIG_ENERGY_MODELを有効にする必要があります。

2.2 パフォーマンスドメインの登録¶

ドライバは以下のAPIを呼び出してEMフレームワークにパフォーマンスドメインを登録する必要があります。

int em_dev_register_perf_domain(struct device *dev, unsigned int nr_states,
              struct em_data_callback *cb, cpumask_t *cpus);

ドライバは、各パフォーマンスステートごとに<周波数、電力>のタプルを返すコールバック関数を提供しなければなりません。ドライバが提供するコールバック関数は、必要な手段で任意の場所（DT、ファームウェアなど）からデータを取得できます。CPUデバイスの場合、パフォーマンスドメインに属するCPUをcpumaskで指定する必要があります。その他のデバイスでは最後の引数をNULLに設定しなければなりません。セクション3を参照してください。また、kernel/power/energy_model.cを参照するとこのAPIについてさらに詳しいドキュメンテーションが得られます。

2.3 パフォーマンスドメインへのアクセス¶

エネルギー計算モデルへのアクセスを提供するAPI関数は2つあります：CPU IDを引数として受け取るem_cpu_get()関数と、デバイスポインタを引数として受け取るem_pd_get()関数です。使用するインターフェースに応じてサブシステムごとに異なりますが、CPUデバイスの場合は両関数が同じパフォーマンスドメインを返します。

CPUのエネルギー計算モデルに興味のあるサブシステムはem_cpu_get()APIを使用して取得できます。エネルギー計算モデルのテーブルはパフォーマンスドメインが作成される際に一度割り当てられ、メモリに保持され変更されません。

パフォーマンスドメインの消費エネルギーはem_cpu_energy()APIを使用して推定できます。CPUデバイスの場合、この推定はschedutil CPUfreqガバナーモードが使用されていると仮定して行われます。現在は他のデバイスタイプにはこの計算が提供されていません。

上記のAPIについての詳細はinclude/linux/energy_model.hをご参照ください。

3. 例ドライバ¶

このセクションでは、(仮想の)‘foo’プロトコルを使用してエネルギー計算モデルフレームワークにパフォーマンスドメインを登録するシンプルなCPUFreqドライバの例を示します。ドライバはEMフレームワークに提供するest_power()関数を実装しています：

-> drivers/cpufreq/foo_cpufreq.c

01    static int est_power(unsigned long *mW, unsigned long *KHz,
02                    struct device *dev)
03    {
04            long freq, power;
05
06            /* Use the 'foo' protocol to ceil the frequency */
07            freq = foo_get_freq_ceil(dev, *KHz);
08            if (freq < 0);
09                    return freq;
10
11            /* Estimate the power cost for the dev at the relevant freq. */
12            power = foo_estimate_power(dev, freq);
13            if (power < 0);
14                    return power;
15
16            /* Return the values to the EM framework */
17            *mW = power;
18            *KHz = freq;
19
20            return 0;
21    }
22
23    static int foo_cpufreq_init(struct cpufreq_policy *policy)
24    {
25            struct em_data_callback em_cb = EM_DATA_CB(est_power);
26            struct device *cpu_dev;
27            int nr_opp, ret;
28
29            cpu_dev = get_cpu_device(cpumask_first(policy->cpus));
30
31            /* Do the actual CPUFreq init work ... */
32            ret = do_foo_cpufreq_init(policy);
33            if (ret)
34                    return ret;
35
36            /* Find the number of OPPs for this policy */
37            nr_opp = foo_get_nr_opp(policy);
38
39            /* And register the new performance domain */
40            em_dev_register_perf_domain(cpu_dev, nr_opp, &em_cb, policy->cpus);
41
42            return 0;
43    }
