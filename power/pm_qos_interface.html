PM Quality Of Service インターフェース¶

このインターフェースは、ドライバ、サブシステム、ユーザースペースアプリケーションがパラメータの1つに対してパフォーマンスの期待値を登録できるカーネルモードとユーザーモードのインターフェースを提供します。

2つの異なるPM QoSフレームワークが利用可能です：

  • CPUレイテンシQoS。

  • デバイスごとのPM QoSフレームワークは、デバイスごとのレイテンシ制約とPM QoSフラグを管理するためのAPIを提供します。

PM QoSフレームワークで使用されるレイテンシ単位はマイクロ秒（usec）です。

1. PM QoSフレームワーク¶

CPUレイテンシQoSのリクエストのグローバルなリストと、集計された（有効な）ターゲット値が維持されます。リストの変更またはリスト要素の変更により、集計されたターゲット値が更新されます。CPUレイテンシQoSでは、集計されたターゲット値はリスト要素に保持されているターゲット値の最小値です。

注意：集計されたターゲット値はアトミック変数として実装されており、集計値の読み取りにはロックメカニズムが不要です。

カーネル空間からこのインターフェースを使用するには簡単です：

void cpu_latency_qos_add_request(handle, target_value)：

CPUレイテンシQoSリストにターゲット値を持つ要素を挿入します。このリストが変更されると、新しいターゲット値が再計算され、ターゲット値が変更された場合にのみ登録された通知コールバックが呼び出されます。PM QoSのクライアントは、PM QoS API関数で今後の使用のために返されたhandleを保存する必要があります。

void cpu_latency_qos_update_request(handle, new_target_value)：

handleで指されるリスト要素を新しいターゲット値に更新し、新しい集計ターゲットを再計算します。ターゲット値が変更された場合、通知ツリーを呼び出します。

void cpu_latency_qos_remove_request(handle)：

要素を削除します。削除後、集計ターゲットを更新し、ターゲット値が変更された場合に通知ツリーを呼び出します。

int cpu_latency_qos_limit()：

CPUレイテンシQoSの集計値を返します。

int cpu_latency_qos_request_active(handle)：

リクエストがまだアクティブであるかを返します（つまり、CPUレイテンシQoSリストから削除されていないか）。

int cpu_latency_qos_add_notifier(notifier)：

CPUレイテンシQoSに通知コールバック関数を追加します。CPUレイテンシQoSの集計値が変更されたときにコールバックが呼び出されます。

int cpu_latency_qos_remove_notifier(notifier)：

CPUレイテンシQoSから通知コールバック関数を削除します。

ユーザースペースから：

インフラストラクチャはCPUレイテンシQoS用に/dev/cpu_dma_latencyという1つのデバイスノードを公開します。

プロセスのみがPM QoSのリクエストを登録できます。プロセスの自動クリーンアップを提供するため、インターフェースはプロセスがパラメータリクエストを以下のように登録する必要があります。

CPUレイテンシQoSのデフォルトPM QoSターゲットを登録するには、プロセスは/dev/cpu_dma_latencyを開く必要があります。

デバイスノードが保持されている限り、そのプロセスはパラメータに登録されたリクエストを持っています。

リクエストされたターゲット値を変更するには、プロセスはオープンされたデバイスノードにs32値を書き込む必要があります。代替として、10文字長の形式（例: "0x12345678"）で値を16進文字列として書き込むこともできます。これはcpu_latency_qos_update_request()呼び出しに翻訳されます。

ターゲット値のユーザーモードリクエストを削除するには、単にデバイスノードを閉じるだけで十分です。

2. デバイスごとのPM QoSレイテンシとフラグフレームワーク¶

各デバイスに対しては、PM QoSリクエストの3つのリストがあります。そのうち2つは、再起動レイテンシとアクティブステートレイテンシ許容値（マイクロ秒単位）の集計ターゲットとともに維持され、3番目のリストはPM QoSフラグ用です。値はリクエストリストの変更に応じて更新されます。

再起動レイテンシとアクティブステートレイテンシ許容値のターゲット値は、パラメータリスト要素に保持されているリクエスト値の最小値です。PM QoSフラグの集計値は、すべてのリスト要素の値をビットごとのORで集約します。現在は1つのデバイスPM QoSフラグが定義されています: PM_QOS_FLAG_NO_POWER_OFF。

注意: 集計ターゲット値は、読み取り時にロックメカニズムを必要としないように実装されています。

カーネルモードでのこのインターフェースの使用方法は以下の通りです:

int dev_pm_qos_add_request(device, handle, type, value):

指定されたデバイスのリストに要素を挿入します。このリストの変更により、新しいターゲットが再計算され、ターゲット値が変更された場合にのみ登録された通知を呼び出します。dev_pm_qosのクライアントは、他のdev_pm_qos API関数で今後の使用のためにハンドルを保存する必要があります。

int dev_pm_qos_update_request(handle, new_value):

ハンドルで指されるリスト要素を新しいターゲット値に更新し、新しい集計ターゲットを再計算します。ターゲット値が変更された場合、通知ツリーを呼び出します。

int dev_pm_qos_remove_request(handle):

要素を削除します。削除後、集計ターゲットを更新し、リクエストの削除によりターゲット値が変更された場合に通知ツリーを呼び出します。

s32 dev_pm_qos_read_value(device, type):

指定されたデバイスの制約リストの集計値を返します。

列挙型 pm_qos_flags_status dev_pm_qos_flags(device, mask)

指定されたデバイスのPM QoSフラグを指定されたフラグマスクと比較します。戻り値の意味は以下の通りです。

PM_QOS_FLAGS_ALL:

マスク内のすべてのフラグが設定されています

PM_QOS_FLAGS_SOME:

マスク内の一部のフラグが設定されています

PM_QOS_FLAGS_NONE:

マスク内のフラグがすべて未設定です

PM_QOS_FLAGS_UNDEFINED:

デバイスのPM QoS構造が初期化されていないか、リクエストリストが空です。

int dev_pm_qos_add_ancestor_request(dev, handle, type, value)

指定されたデバイスの直系の先祖デバイス（power.ignore_childrenフラグが未設定の場合）またはpower.set_latency_toleranceコールバックポインタがNULLでない場合（DEV_PM_QOS_LATENCY_TOLERANCEリクエストの場合）にPM QoSリクエストを追加します。

int dev_pm_qos_expose_latency_limit(device, value)

デバイスのPM QoS再起動遅延制約リストにリクエストを追加し、デバイスのpowerディレクトリ下にsysfs属性pm_qos_resume_latency_usを生成してユーザー空間がそのリクエストを操作できるようにします。

void dev_pm_qos_hide_latency_limit(device)

dev_pm_qos_expose_latency_limit()で追加されたリクエストをデバイスのPM QoS再起動遅延制約リストから削除し、デバイスのpowerディレクトリ下のsysfs属性pm_qos_resume_latency_usを削除します。

int dev_pm_qos_expose_flags(device, value)

デバイスのPM QoSフラグリストにリクエストを追加し、デバイスのpowerディレクトリ下にsysfs属性pm_qos_no_power_offを生成してユーザー空間がPM_QOS_FLAG_NO_POWER_OFFフラグの値を変更できるようにします。

void dev_pm_qos_hide_flags(device)

dev_pm_qos_expose_flags()で追加されたリクエストをデバイスのPM QoSフラグリストから削除し、デバイスのpowerディレクトリ下のsysfs属性pm_qos_no_power_offを削除します。

通知メカニズム:

デバイスごとのPM QoSフレームワークにはデバイスごとの通知木があります。

int dev_pm_qos_add_notifier(device, notifier, type):

デバイスに特定のリクエストタイプに対する通知コールバック関数を追加します。

デバイスの制約リストの集約値が変更されたときにコールバックが呼ばれます。

int dev_pm_qos_remove_notifier(device, notifier, type):

デバイスの通知コールバック関数を削除します。

アクティブステート遅延許容¶

このデバイスのPM QoSタイプは、ハードウェアが即座にエネルギー節約モードに切り替わるシステムをサポートするために使用されます。このようなシステムでは、ハードウェアが選択した運用モードが過度にエネルギー節約を目的としている場合、ソフトウェアに過剰なレイテンシが発生し、プロトコルの要件やターゲットフレームまたはサンプリングレートなどの制約を満たせなくなる可能性があります。

特定のデバイスにソフトウェアがレイテンシ許容制御メカニズムを有する場合、そのデバイスのdev_pm_info構造体の.set_latency_toleranceコールバックを埋め込む必要があります。このコールバックが指す関数は、ハードウェアに有効な要件値を伝達するための処理を実装する必要があります。

デバイスの有効なレイテンシ許容値が変化した場合、その.set_latency_tolerance()コールバックが実行され、有効な値が渡されます。この値が負数である場合（つまり、デバイスのレイテンシ許容要件リストが空であることを意味する）、コールバックは、利用可能な場合にその下位ハードウェアのレイテンシ許容制御メカニズムを自動モードに切り替える必要があります。また、この値がPM_QOS_LATENCY_ANYであり、ハードウェアが特別な「要件なし」設定をサポートする場合、コールバックはその設定を使用する必要があります。これにより、ソフトウェアがデバイスのレイテンシ許容値を、デバイスの電源状態変化（例：D3coldからD0への移行中など）に応じてハードウェアが自動的に更新しないように防止できます。

.set_latency_tolerance()がデバイスに存在する場合、そのデバイスの電源ディレクトリにsysfs属性pm_qos_latency_tolerance_usが存在します。これにより、ユーザー空間はデバイスのレイテンシ許容要件を指定できます。この属性に「any」と書くと「要件なし、ハードウェアがレイテンシ許容を制御しない」となり、『auto』と書くと、デバイスの要件リストに他の要件がなければハードウェアを自動モードに切り替えることができます。

カーネルコードは、上述の関数とDEV_PM_QOS_LATENCY_TOLERANCEデバイスPM QoSタイプを組み合わせて、デバイスのレイテンシ許容要件を追加、削除、更新できます。
