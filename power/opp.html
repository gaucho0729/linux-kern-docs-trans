Operating Performance Points (OPP) ライブラリ¶

  1. 2009-2010 Nishanth Menon <nm@ti.com>, Texas Instruments Incorporated

1. はじめに¶

1.1 Operating Performance Point (OPP) とは？¶

現代の複雑なSoC（システムオンチップ）は、複数のサブモジュールが協働して動作しています。運用中のシステムで多様な使用ケースが発生する中、SoC内のすべてのモジュールが常に最高性能の周波数で動作する必要はありません。このような状況をサポートするため、SoC内のサブモジュールはドメインに分類され、一部のドメインは低電圧・低周波数で動作し、他のドメインは高電圧・高周波数のペアで動作できるようにします。

デバイスが各ドメインごとにサポートする周波数と電圧の組み合わせを表す離散的なタプルの集合を、Operating Performance Points（OPP）と呼びます。

例として、

MPUデバイスが以下の機能をサポートしているとします：{300MHz で最小電圧 1V}、{800MHz で最小電圧 1.2V}、{1GHz で最小電圧 1.3V}

これらを次の {Hz, uV} のタプルとして3つのOPPに表すことができます：

  • {300000000, 1000000}

  • {800000000, 1200000}

  • {1000000000, 1300000}

1.2 Operating Performance Points ライブラリ¶

OPP ライブラリは、OPP情報を整理・照会するためのヘルパ関数のセットを提供します。このライブラリは drivers/opp/ ディレクトリに配置され、ヘッダーファイルは include/linux/pm_opp.h にあります。OPP ライブラリは、電源管理のメニュー構成（menuconfig）から CONFIG_PM_OPP を有効化することで利用可能です。OPP ライブラリは CONFIG_PM に依存しており、Texas Instruments の OMAP フレームワークなどのSoCでは、cpufreq が不要で特定のOPPでオプションで起動できる場合があります。

OPP ライブラリの典型的な使用方法は以下の通りです：

(users)        -> registers a set of default OPPs              -> (library)
SoC framework  -> modifies on required cases certain OPPs      -> OPP layer
               -> queries to search/retrieve information       ->

OPPレイヤーは、各ドメインが一意のデバイスポインタで表されることを期待しています。SoCフレームワークは、各デバイスに対して初期のOPPリストをOPPレイヤーに登録します。このリストは通常5程度の最小限の数で、フレームワークがシステムでデフォルトで安全に有効化できると期待されるOPPの集合です。

OPPの利用可能性に関する注意¶

システムが運用を進める中で、SoCフレームワークは、さまざまな外部要因に基づいて各デバイスごとに特定のOPPを有効にするか無効にするかを選択することがあります。例として、熱管理やその他の例外状況など、SoCフレームワークが高周波数OPPを無効にして安全に運用を継続し、必要に応じて再有効化できるまで待つ場合があります。

OPP libraryはこの概念を実装で実現します。以下の操作関数は、利用可能なOPPのみに対して動作します: opp_find_freq_{ceil, floor}, dev_pm_opp_get_voltage, dev_pm_opp_get_freq, dev_pm_opp_get_opp_count

dev_pm_opp_find_freq_exactは、その後dev_pm_opp_enable/disable関数でOPPを有効/無効にし、必要なときにOPPを有効にするために使用されるOPPポインタを検索するために使用されます。

警告: OPP libraryをユーザーする場合は、dev_pm_opp_enable/disable関数がデバイスに対して呼び出される場合、またはこれらの関数をトリガーする正確なメカニズム、またはcpufreqなどの他の依存サブシステムへの通知メカニズムは、OPP libraryを使用するSoC固有のフレームワークの裁量に委ねられます。同様に、これらの操作の際にはcpufreqテーブルを再取得する際の注意が必要です。

2. 初期OPPリスト登録¶

SoC実装は、dev_pm_opp_add関数を繰り返し呼び出して、デバイスごとにOPPを追加します。SoCフレームワークはOPPエントリを最適に登録することが期待され、典型的な数は5未満です。OPPを登録して生成されたリストは、OPP libraryがデバイスの動作中を通じて管理します。その後、SoCフレームワークはdev_pm_opp_enable/disable関数を使用してOPPの可用性を動的に制御できます。

dev_pm_opp_add

特定のデバイスポインタで表されるドメインに新しいOPPを追加します。このOPPは周波数と電圧で定義されます。追加後、OPPは利用可能とみなされ、その可用性の制御はdev_pm_opp_enable/disable関数で行います。OPP libraryは内部的にopp構造体でこの情報を保存・管理します。この関数は、SoCの使用環境に応じて最適なリストを定義するためにSoCフレームワークが使用できます。

警告:

割り込みコンテキストでこの関数を使用しないでください。

例:

soc_pm_init()
{
       /* Do things */
       r = dev_pm_opp_add(mpu_dev, 1000000, 900000);
       if (!r) {
               pr_err("%s: unable to register mpu opp(%d)\n", r);
               goto no_cpufreq;
       }
       /* Do cpufreq things */
no_cpufreq:
       /* Do remaining things */
}

3. OPP検索関数¶

cpufreqなどの高レベルフレームワークは周波数で動作します。周波数を対応するOPPに戻すため、OPP libraryは内部的に管理しているOPPリストを検索するための便利な関数を提供します。これらの検索関数は、一致するOPPポインタを返します（一致しなければエラーを返します）。これらのエラーはIS_ERR()などの標準エラーチェックで処理され、呼び出し元で適切なアクションが行われます。

これらの関数の呼び出し元は、OPPを使用後にdev_pm_opp_put()を呼び出す必要があります。呼び出さない場合、OPPのメモリが解放されず、メモリリークを引き起こします。

dev_pm_opp_find_freq_exact

特定の周波数に基づいてOPPを検索します 正確な一致 周波数と利用可能性。この関数は、デフォルトでは利用できないOPPを有効にするために特に役立ちます。例: SoCフレームワークが、より高い周波数が利用可能である状況を検出した場合、この関数を使用してOPPを検索し、dev_pm_opp_enableを呼び出して実際に利用可能にします:

opp = dev_pm_opp_find_freq_exact(dev, 1000000000, false);
dev_pm_opp_put(opp);
/* dont operate on the pointer.. just do a sanity check.. */
if (IS_ERR(opp)) {
       pr_err("frequency not disabled!\n");
       /* trigger appropriate actions.. */
} else {
       dev_pm_opp_enable(dev,1000000000);
}
ノート:

これは、利用不可能なOPPを対象とする唯一の検索関数です。

dev_pm_opp_find_freq_floor

指定された周波数以下の利用可能なOPPを検索します。この関数は、より低いマッチを検索する場合や、周波数の降順でOPP情報を処理する場合に役立ちます。例: デバイスの最高OPPを検索する場合: at most the provided frequency. This function is useful while searching for a lesser match OR operating on OPP information in the order of decreasing frequency. Example: To find the highest opp for a device:

freq = ULONG_MAX;
opp = dev_pm_opp_find_freq_floor(dev, &freq);
dev_pm_opp_put(opp);
dev_pm_opp_find_freq_ceil

指定された周波数以下の利用可能なOPPを検索します。この関数は、より低いマッチを検索する場合や、周波数の降順でOPP情報を処理する場合に役立ちます。例: デバイスの最高OPPを検索する場合: at least the provided frequency. This function is useful while searching for a higher match OR operating on OPP information in the order of increasing frequency. Example 1: To find the lowest opp for a device:

freq = 0;
opp = dev_pm_opp_find_freq_ceil(dev, &freq);
dev_pm_opp_put(opp);

Example 2: A simplified implementation of a SoC cpufreq_driver->target:

soc_cpufreq_target(..)
{
       /* Do stuff like policy checks etc. */
       /* Find the best frequency match for the req */
       opp = dev_pm_opp_find_freq_ceil(dev, &freq);
       dev_pm_opp_put(opp);
       if (!IS_ERR(opp))
               soc_switch_to_freq_voltage(freq);
       else
               /* do something when we can't satisfy the req */
       /* do other stuff */
}

4. OPP Availability Control Functions¶

OPPライブラリに登録されたデフォルトのOPPリストは、すべての可能性をカバーするとは限りません。OPPライブラリは、OPPリスト内でOPPの利用可能性を変更するための関数セットを提供します。これにより、SoCフレームワークは、どのセットのOPPが操作可能かについて、細かい動的な制御を行うことができます。これらの関数は、 temporarily remove an OPP in conditions such as thermal considerations (e.g. don’t use OPPx until the temperature drops).

警告:

Do not use these functions in interrupt context.

dev_pm_opp_enable

Make a OPP available for operation. Example: Let's say that 1GHz OPP is to be made available only if the SoC temperature is lower than a certain threshold. The SoC framework implementation might choose to do something as follows:

if (cur_temp < temp_low_thresh) {
       /* Enable 1GHz if it was disabled */
       opp = dev_pm_opp_find_freq_exact(dev, 1000000000, false);
       dev_pm_opp_put(opp);
       /* just error check */
       if (!IS_ERR(opp))
               ret = dev_pm_opp_enable(dev, 1000000000);
       else
               goto try_something_else;
}
dev_pm_opp_disable

Make an OPP to be not available for operation Example: Let's say that 1GHz OPP is to be disabled if the temperature exceeds a threshold value. The SoC framework implementation might choose to do something as follows:

if (cur_temp > temp_high_thresh) {
       /* Disable 1GHz if it was enabled */
       opp = dev_pm_opp_find_freq_exact(dev, 1000000000, true);
       dev_pm_opp_put(opp);
       /* just error check */
       if (!IS_ERR(opp))
               ret = dev_pm_opp_disable(dev, 1000000000);
       else
               goto try_something_else;
}

5. OPP Data Retrieval Functions¶

Since OPP library abstracts away the OPP information, a set of functions to pull information from the OPP structure is necessary. Once an OPP pointer is retrieved using the search functions, the following functions can be used by SoC framework to retrieve the information represented inside the OPP layer.

dev_pm_opp_get_voltage

oppポインタで表される電圧を取得します。例：cpufreqが異なる周波数に遷移する際、SoCフレームワークは、電圧を提供するPower Managementチップのレギュレータフレームワークを使用して、oppポインタで表される電圧を設定する必要があります:

soc_switch_to_freq_voltage(freq)
{
       /* do things */
       opp = dev_pm_opp_find_freq_ceil(dev, &freq);
       v = dev_pm_opp_get_voltage(opp);
       dev_pm_opp_put(opp);
       if (v)
               regulator_set_voltage(.., v);
       /* do other things */
}
dev_pm_opp_get_freq

oppポインタで表される周波数を取得します。例：SoCフレームワークがいくつかのヘルパ関数を使用する場合、oppポインタを渡すことで追加のパラメータを省略し、データパラメータを処理するのに役立ちます:

soc_cpufreq_target(..)
{
       /* do things.. */
        max_freq = ULONG_MAX;
        max_opp = dev_pm_opp_find_freq_floor(dev,&max_freq);
        requested_opp = dev_pm_opp_find_freq_ceil(dev,&freq);
        if (!IS_ERR(max_opp) && !IS_ERR(requested_opp))
               r = soc_test_validity(max_opp, requested_opp);
        dev_pm_opp_put(max_opp);
        dev_pm_opp_put(requested_opp);
       /* do other things */
}
soc_test_validity(..)
{
        if(dev_pm_opp_get_voltage(max_opp) < dev_pm_opp_get_voltage(requested_opp))
                return -EINVAL;
        if(dev_pm_opp_get_freq(max_opp) < dev_pm_opp_get_freq(requested_opp))
                return -EINVAL;
       /* do things.. */
}
dev_pm_opp_get_opp_count

デバイスの利用可能なOPPの数を取得します。例：SoC内のコプロセッサがテーブル形式で利用可能な周波数を知る必要がある場合、メインプロセッサは以下のようない通知を行います:

soc_notify_coproc_available_frequencies()
{
       /* Do things */
       num_available = dev_pm_opp_get_opp_count(dev);
       speeds = kzalloc(sizeof(u32) * num_available, GFP_KERNEL);
       /* populate the table in increasing order */
       freq = 0;
       while (!IS_ERR(opp = dev_pm_opp_find_freq_ceil(dev, &freq))) {
               speeds[i] = freq;
               freq++;
               i++;
               dev_pm_opp_put(opp);
       }

       soc_notify_coproc(AVAILABLE_FREQs, speeds, num_available);
       /* Do other things */
}

6. データ構造¶

通常、SoCには複数の電圧ドメインがあり、これらは変化します。各ドメインはデバイスポインタで表されます。OPPとの関係は以下のようになります:

SoC
 |- device 1
 |    |- opp 1 (availability, freq, voltage)
 |    |- opp 2 ..
 ...  ...
 |    `- opp n ..
 |- device 2
 ...
 `- device m

OPPライブラリは、SoCフレームワークが populate し、上述の関数群がアクセスする内部リストを保持しています。ただし、実際のOPPおよびドメインを表す構造体はOPPライブラリ内部にあり、システム間で再利用可能な適切な抽象化を可能にするためです。

struct dev_pm_opp

OPPライブラリの内部データ構造で、OPPを表します。周波数、電圧、利用可能性情報に加え、OPPライブラリが動作するために必要な内部の記録情報も含みます。この構造体へのポインタは、SoCフレームワークなどのユーザーに返され、OPPレイヤーとのやり取りにおけるOPPの識別子として使用されます。

警告:

struct dev_pm_oppポインタはユーザーが解析したり変更したりしてはいけません。例えば、dev_pm_opp_addによってデフォルト値が設定されるが、dev_pm_opp_enable/disable関数によってOPPの利用可能性を変更できます。

struct device

これはOPPレイヤーにドメインを識別するために使用されます。デバイスの性質および実装は、OPPライブラリのユーザー（例：SoCフレームワーク）に委譲されます。

全体的に、簡略化した視点では、データ構造の操作は以下のようになります:

Initialization / modification:
            +-----+        /- dev_pm_opp_enable
dev_pm_opp_add --> | opp | <-------
  |         +-----+        \- dev_pm_opp_disable
  \-------> domain_info(device)

Search functions:
             /-- dev_pm_opp_find_freq_ceil  ---\   +-----+
domain_info<---- dev_pm_opp_find_freq_exact -----> | opp |
             \-- dev_pm_opp_find_freq_floor ---/   +-----+

Retrieval functions:
+-----+     /- dev_pm_opp_get_voltage
| opp | <---
+-----+     \- dev_pm_opp_get_freq

domain_info <- dev_pm_opp_get_opp_count
