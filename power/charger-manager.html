チャージャーマネージャー¶

  1. 2011 MyungJoo Ham <myungjoo.ham@samsung.com>, GPL

充電管理は、スリープ状態（suspend-to-RAM）中に温度監視が必要な場合や、各バッテリーに複数の充電器が接続されており、ユーザーランドが複数の充電器の集約情報を確認したい場合に、カーネル内でのバッテリー充電管理を提供します。

充電管理はplatform_driverで実装され、power-supply-classエントリを有します。充電管理のインスタンス（充電管理で作成されたplatform-device）は、独立したバッテリーと充電器を表します。システム内に複数の独立したバッテリーと充電器が存在する場合、システムは複数の充電管理インスタンスを必要とする場合があります。

1. はじめに¶

充電管理がサポートする機能:

  • 複数の充電器のサポート（例: USB、AC、太陽光パネルを備えたデバイス）

    システムは複数の充電器（または電源）を有する場合があり、それらの一部が同時にアクティブになる可能性があります。各充電器は独自のpower-supply-classを持ち、各power-supply-classはバッテリー状態に関する異なる情報を提供できます。このフレームワークは複数の情報源から充電関連情報を統合し、単一のpower-supply-classとして結合情報を表示します。

  • スリープ状態（suspend-to-RAM）時のポーリングサポート（suspend_againコールバックを含む）

    バッテリーが充電中でシステムがスリープ状態にある場合、バッテリーの健康状態を監視するために周囲温度やバッテリー温度を確認する必要があります。これを実現するには、システムを定期的に目覚めさせる方法があります。ただし、このような方法はバッテリーの健康状態やタスクの監視、スリープ状態を維持すべきユーザープロセスのための不要なデバイスの目覚めを引き起こし、結果として不要な電力消費と充電プロセスの遅延を招きます。さらに、このようなピーク電力消費は充電中に充電器を停止させる可能性があり（外部電源入力 < デバイス電力消費）、充電時間を長くし、バッテリーの寿命にも影響を与えます。

    充電管理はplatform_suspend_opsのsuspend_againコールバックとして使用可能な「cm_suspend_again」関数を提供します。プラットフォームがcm_suspend_again以外のタスクを必要とする場合、独自のsuspend_againコールバックを実装し、その中でcm_suspend_againを呼び出すことができます。通常、プラットフォームは充電管理で使用されるデバイスを再起動およびスリープさせる必要があります。

  • 早すぎる満充電イベントの処理サポート

    フルバッテリーイベントから「fullbatt_vchkdrop_ms」経過後に電圧が「fullbatt_vchkdrop_uV」以上低下した場合、フレームワークは充電を再開します。このチェックは、ウェイクアップ時間を設定し、suspend_againを使用してスリープ中に実行されます。

  • uevent-notifyのサポート

    充電関連イベントでは、デバイスはUEVENTを通じてユーザーに通知を送信します。

2. 再スリープに関連するグローバル充電管理データ¶

再スリープモニタリング（in-suspendモニタリング）をサポートする充電管理マネージャーを設定するには、ユーザーはsetup_charger_manager("charger_global_desc *"で構造体を提供する必要があります。struct charger_global_desc *)。このin-suspendモニタリング用のcharger_global_descデータは名前の通りグローバルです。したがって、複数のバッテリーがある場合でも、ユーザーは一度提供するだけで済みます。複数のバッテリーがある場合、複数の充電管理マネージャーインスタンスは同じcharger_global_descを共有し、すべてのインスタンスのin-suspendモニタリングを管理します。

ユーザーは以下の3つのエントリをすべて提供する必要があります struct charger_global_desc in-suspendモニタリングを有効にするために正しく設定する必要があります:

char *rtc_name;

システムをスリープから再起動するためのrtc（例："rtc0"）の名前。rtcのアラーム割込み（AIE）がスリープからシステムを再起動できる必要があります。充電管理マネージャーはアラーム値を保存・復元し、充電管理マネージャーがアラームよりも早く起動する場合、以前に定義されたアラームを使用します。これにより、充電管理マネージャーが以前に定義されたアラームと干渉しないようにします。

bool (*rtc_only_wakeup)(void);

このコールバックは、CMにスリープからの再起動が"rtc"のアラームのみによって引き起こされたかどうかを通知する必要があります。他のウェイクアップソースが起動した場合はfalseを返し、"rtc"が唯一のウェイクアップ理由である場合はtrueを返します。

bool assume_timer_stops_in_suspend;

trueの場合、充電管理マネージャーはスリープ中にタイマ（CMはjiffiesをタイマとして使用）が停止すると想定します。その後、CMはスリープ時間とアラーム長を同じものとします。

3. 再スリープのセットアップ方法¶

充電管理マネージャーは関数"extern bool cm_suspend_again(void)"を提供します。cm_suspend_againが呼び出されると、すべてのバッテリーを監視します。システムのplatform_suspend_opsのsuspend_opsコールバックは、cm_suspend_again関数を呼び出して、充電管理マネージャーが再スリープを希望しているかどうかを確認します。他のデバイスやタスクが再スリープ機能を使用していない場合、platform_suspend_opsはcm_suspend_againを直接参照してsuspend_againコールバックを実行できます。

cm_suspend_again() は、システムが Charger Manager によって目覚め、ポーリング（スリープ中のモニタリング）の結果が「normal」の場合、true を返します（「再度スリープを希望する」を意味します）。

4. Charger-Manager データ（struct charger_desc）¶

他のバッテリーとは独立して充電されるバッテリーごとに（複数のバッテリーが単一の充電器で充電される場合、それらは1つの独立したバッテリーとしてカウントされます）Charger Manager のインスタンスがアタッチされます。以下の

struct charger_desc の要素:

char *psy_name;

バッテリーの電源供給クラス名。psy_name が NULL の場合、デフォルトは「battery」です。ユーザーは「/sys/class/power_supply/[psy_name]/」にアクセスできます。

enum polling_modes polling_mode;
CM_POLL_DISABLE:

このバッテリーをポーリングしない。

CM_POLL_ALWAYS:

このバッテリーを常にポーリングする。

CM_POLL_EXTERNAL_POWER_ONLY:

外部電源が接続されている場合にのみこのバッテリーをポーリングする。

CM_POLL_CHARGING_ONLY:

このバッテリーが充電されている場合にのみポーリングする。

unsigned int fullbatt_vchkdrop_ms; / unsigned int fullbatt_vchkdrop_uV;

両方がゼロでない場合、Charger Manager はバッテリーが満充電された後、fullbatt_vchkdrop_ms でバッテリー電圧の降下を確認します。電圧降下が fullbatt_vchkdrop_uV を超える場合、Charger Manager は充電器を無効化・有効化することでバッテリーを再充電します。電圧降下条件のみで再充電を実装する必要があります（遅延条件は不要）が、燃料ゲージや充電器デバイス/チップからのハードウェア割込みで実装する必要があります。

unsigned int fullbatt_uV;

指定値がゼロでない場合、バッテリーが充電されていないかつバッテリー電圧が fullbatt_uV 以上である場合、Charger Manager はバッテリーが満充電（容量＝100）とみなします。

unsigned int polling_interval_ms;

ポーリングの必要間隔（ミリ秒）。Charger Manager はこのバッテリーを polling_interval_ms ごとに、またはより頻繁にポーリングします。

enum data_source battery_present;
CM_BATTERY_PRESENT:

バッテリーが存在すると仮定します。

CM_NO_BATTERY:

バッテリーが存在しないと仮定します。

CM_FUEL_GAUGE:

バッテリーの存在情報を燃料ゲージから取得します。

CM_CHARGER_STAT:

充電器からバッテリーの存在情報を取得します。

char **psy_charger_stat;

NULL で終了する配列で、充電器の電源供給クラス名を保持します。各電源供給クラスは、「PRESENT」（バッテリー_present が「CM_CHARGER_STAT」の場合）、「ONLINE」（外部電源が接続されているかを示す）、および「STATUS」（バッテリーが「FULL」か否か、または「FULL」、「充電中」、「放電中」、「充電していない」を示す）を提供する必要があります。

int num_charger_regulators; /* struct regulator_bulk_data *charger_regulators; */

充電機器をレギュレータフレームワークのバッチ処理用形式で表すレギュレータ。

char *psy_fuel_gauge;

燃料ゲージの電源供給クラス名。

int (*temperature_out_of_range)(int *mC); /* bool measure_battery_temp; */

このコールバック関数は、温度が充電に安全かどうかを0で返し、過熱している場合は正数、過冷している場合は負数を返します。変数mCは、温度を千分の1度単位で表し、measure_battery_tempの値に応じて温度源がバッテリーか周囲温度かを示します。

5. 充電機器のイベントをCharger-Managerに通知: cm_notify_event()¶

充電機器のイベントをCharger Managerに通知する必要がある場合、イベントをトリガーする充電デバイスドライバーはcm_notify_event(psy, type, msg)を呼び出して対応するCharger Managerに通知します。この関数では、psyは充電ドライバーのpower_supplyポインタであり、Charger-Managerと関連付けられています。パラメータ「type」はIRQのtypeと同じ(enum cm_event_types)で、イベントメッセージ「msg」はオプションであり、「UNDESCRIBED」または「OTHERS」のイベントタイプの場合にのみ有効です。

6. その他の考慮事項¶

バッテリーが抜かれた、充電機器が抜かれた、充電機器が挿した、DCIN過電圧/過電圧、充電停止などの充電機器に影響を与えるイベントでは、システムがウェイクアップするよう設定する必要があります。少なくとも以下の条件でスリープからシステムをウェイクアップする必要があります：a) 充電ON/OFF b) 外部電源IN/OUT c) バッテリーIN/OUT（充電中）

通常はPMICをウェイクアップソースとして設定することで実現されます。
