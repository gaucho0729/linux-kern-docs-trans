レギュレータ消費者ドライバインターフェース¶

このテキストは消費者デバイスドライバ用のレギュレータインターフェースについて説明しています。使用されている用語についての説明はoverview.txtをご参照ください。

1. 消費者レギュレータアクセス (静的および動的ドライバ)¶

消費者ドライバは、レギュレータへのアクセスを取得するために次の関数を呼び出します。

regulator = regulator_get(dev, "Vcc");

消費者は自身の struct device ポインタと電源供給IDを渡します。コアは機種固有の検索テーブルを参照して正しいレギュレータを検索します。検索が成功した場合、この関数はこの消費者を供給するstruct regulatorへのポインタを返します。

レギュレータを解放するには、消費者ドライバは次の関数を呼び出す必要があります。

regulator_put(regulator);

消費者は1つ以上のレギュレータから供給されることがあります。例えば、コーデック消費者はアナログおよびデジタルの電源供給を持つ場合があります。

digital = regulator_get(dev, "Vcc");  /* digital core */
analog = regulator_get(dev, "Avdd");  /* analog */

レギュレータアクセス関数 regulator_get() および regulator_put() は通常、デバイスドライバのprobe()およびremove()関数で呼び出されます。

2. レギュレータ出力の有効化と無効化 (静的および動的ドライバ)¶

消費者は次の関数を呼び出して自身の電源供給を有効化できます:

int regulator_enable(regulator);
ノート:

レギュレータが有効化されている可能性があります。これは消費者がレギュレータを共有しているか、またはブートローダーやカーネルボード初期化コードによってすでに有効化されている場合です。

消費者は次の関数を呼び出してレギュレータが有効化されているかを確認できます:

int regulator_is_enabled(regulator);

レギュレータが有効化されている場合、ゼロより大きい値を返します。

消費者は必要なくなったときに次の関数を呼び出して電源供給を無効化できます:

int regulator_disable(regulator);
ノート:

他の消費者と共有されている場合、この関数は供給を無効化しない可能性があります。レギュレータは有効化参照カウントがゼロになるまで無効化されません。

緊急時の場合は次の関数を呼び出してレギュレータを強制的に無効化できます:

int regulator_force_disable(regulator);
ノート:

これによりレギュレータ出力が即座に強制的にシャットダウンされ、すべての消費者が電源をオフにされます。

3. レギュレータ電圧制御およびステータス (動的ドライバ)¶

一部の消費者ドライバは、システムの動作ポイントに合わせて供給電圧を動的に変更する必要があります。例えば、CPUfreqドライバは周波数に合わせて電圧をスケーリングして電力を節約し、SDドライバは正しいカード電圧を選択する必要があります。

消費者は次の関数を呼び出して供給電圧を制御できます:

int regulator_set_voltage(regulator, min_uV, max_uV);

ここでmin_uVとmax_uVはマイクロボルト単位での最小および最大許容電圧です。

注意: この関数はレギュレータが有効化されているか無効化されているかに関わらず呼び出すことができます。有効化されている場合、電圧は即座に変更されますが、無効化されている場合は電圧設定が変更され、次回レギュレータが有効化されるときに物理的に電圧が設定されます。

レギュレータが設定した電圧出力は次の関数を呼び出して確認できます:

int regulator_get_voltage(regulator);
ノート:

get_voltage()は、レギュレータが有効か無効かに関わらず設定された出力電圧を返します。ただし、レギュレータの出力状態を確認するために使用すべきではありません。ただし、is_enabled()と併用することで、レギュレータの物理的な出力電圧を確認できます。

4. レギュレータ電流制限制御・状態（ダイナミックドライバ）¶

一部の消費者ドライバは、システムの動作点に合わせて供給電流制限を動的に変更する必要があります。例えば、LCDバックライトドライバはバックライトの明るさを変えるために電流制限を変更し、USBドライバは電源供給時に500mAの制限を設定したい場合があります。

消費者は以下の関数を呼び出して、供給電流制限を制御できます。

int regulator_set_current_limit(regulator, min_uA, max_uA);

min_uAとmax_uAはマイクロアンペア単位での最小および最大の許容電流制限です。

ノート:

この関数はレギュレータが有効か無効かに関わらず呼び出せます。有効な状態で呼び出された場合、電流制限は即座に変更され、無効な状態で呼び出された場合は、電流制限の設定が変更され、次にレギュレータが有効になったときに物理的に設定されます。

レギュレータの電流制限は以下の関数を呼び出して確認できます。

int regulator_get_current_limit(regulator);
ノート:

get_current_limit()は、レギュレータが有効か無効かに関わらず電流制限を返しますが、レギュレータの電流負荷を確認するために使用すべきではありません。

5. レギュレータ動作モード制御・状態（ダイナミックドライバ）¶

一部の消費者は、自身の供給レギュレータの動作モードを変更してシステムの消費電力をさらに節約できます。例えば、消費者ドライバがアイドル状態になり、その後電流消費量が減少する場合があります。

レギュレータの動作モードは間接的にもしくは直接的に変更できます。

間接的な動作モード制御¶

消費者ドライバは、以下の関数を呼び出して供給レギュレータの動作モードの変更を要求できます。

int regulator_set_load(struct regulator *regulator, int load_uA);

これにより、コアがレギュレータ（すべての消費者を基に）の総負荷を再計算し、必要かつ許可された場合に現在の負荷に最適な動作モードに変更します。

load_uA値は消費者のデータシートから確認できます。例えば、多くのデータシートには特定の状況における最大電流消費量を示す表が含まれています。

ほとんどの消費者は間接的な動作モード制御を使用します。なぜなら、レギュレータの知識や他の消費者と共有されているかを把握していないからです。

直接的な動作モード制御¶

カスタムまたは密接に結合されたドライバは、自身の動作点に応じてレギュレータの動作モードを直接制御したい場合があります。これは以下の関数を呼び出すことで実現できます。

int regulator_set_mode(struct regulator *regulator, unsigned int mode);
unsigned int regulator_get_mode(struct regulator *regulator);

直接モードは、消費者が 知っている 調節器についてであり、他の消費者と共有していない。

6. 調節器イベント¶

調節器は外部イベントを消費者に通知できます。イベントは調節器のストレスや故障状態において、消費者が受信できる可能性があります。

消費者は調節器イベントに関心を登録するには、以下のように呼び出します：

int regulator_register_notifier(struct regulator *regulator,
                                struct notifier_block *nb);

消費者は調節器イベントの関心を解除するには、以下のように呼び出します：

int regulator_unregister_notifier(struct regulator *regulator,
                                  struct notifier_block *nb);

調節器は、その関心を持つ消費者にイベントを送信するために、カーネルの notifier フレームワークを使用します。

7. 調節器の直接レジスタアクセス¶

一部の電源管理ハードウェアまたはファームウェアは、カーネルの関与なしに、レギュレータへの低レベルハードウェアアクセスが必要に設計されています。このようなデバイスの例は次のとおりです：

  • I2Cを介して供給電圧を変更し、所望の出力クロックレートを達成するための電圧制御振子と制御ロジックを備えたクロックソース

  • 過熱状態において、任意のI2Cトランザクションを実行してシステムの電源を切る機能を持つ熱管理ファームウェア

このようなデバイス/ファームウェアを設定するには、レギュレータのI2Cアドレスや、さまざまなレギュレータレジスタのアドレスなど、さまざまなパラメータを設定する必要があります。レギュレータフレームワークは、これらの詳細を照会するための以下のヘルパーを提供しています。

I2Cアドレスや転送速度などのバス固有の詳細は、regmapフレームワークによって処理されます。レギュレータのregmap（サポートされている場合）を取得するには、以下を使用します：

struct regmap *regulator_get_regmap(struct regulator *regulator);

レギュレータの電圧選択レジスタのハードウェアレジスタオフセットとビットマスクを取得するには、以下を使用します：

int regulator_get_hardware_vsel_register(struct regulator *regulator,
                                         unsigned *vsel_reg,
                                         unsigned *vsel_mask);

レギュレータフレームワークの電圧選択コード（regulator_list_voltageで使用される）を、直接電圧選択レジスタに書き込むことができるハードウェア固有の電圧選択値に変換するには、以下を使用します：

int regulator_list_hardware_vsel(struct regulator *regulator,
                                 unsigned selector);
