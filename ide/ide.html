Enhanced IDEドライブに関する情報¶

hdparmユーティリティは、動作中のシステムでさまざまなIDE機能を制御できます。これは別途パッケージ化されています。人気のあるLinux FTPサイトで探してください。

重要です。

不具合のあるIDEチップセットはデータを破損させる可能性があります!!

CMD640およびRZ1000インターフェースのPCIバージョンは、PCI BIOSサポートが構成されている場合、起動時に自動的に検出されます。

LinuxはRZ1000の「prefetch」（「readahead」）モードを無効化し、ハードウェアの設計上の欠陥によりデータ破損を防ぎます。

CMD640では、「IRQアンマスキング」（hdparm -u1）が「prefetch」モードが有効になっているドライブで無効化されます。もし「prefetch」が無効化されている（hdparm -p8）場合、「IRQアンマスキング」を再利用できます。

CMD640では、「32bit I/O」（hdparm -c1）が「prefetch」モードが無効になっているドライブで無効化されます。もし「prefetch」が有効化されている（hdparm -p9）場合、「32bit I/O」を再利用できます。

CMD640は一部のVesa Local Bus（VLB）カードでも使用され、 禁止です Linuxによって自動的に検出されます。このようなインターフェースで安全かつ信頼性の高い運用を行うためには、 MUST 「cmd640.probe_vlb」カーネルオプションを使用してください。

「serialize」オプションの使用は不要です。

よくある間違い¶

  • 40ワイヤーIDEケーブルはDMAモードでudma2までデータを転送できますが、それ以上はできません。

  • 可能であれば、同じケーブルに接続するデバイスは別チャンネルに接続してください。通常はディスクが1番目、CD-ROMが2番目です。

  • 同じケーブルに複数のデバイスを接続する場合、それらがサポートするデータ転送モードに注意してください。

  • さらに良い方法は、同じケーブルに同じベンダーおよびデバイスタイプを使用することです。

これはhd.cから進化した複数IDEインターフェースドライバーです¶

デフォルトでは1つまたは複数のIRQ（通常は14および15）で最大9つのIDEインターフェースをサポートします。ATA-6仕様ではインターフェースごとに最大2つのドライブが可能です：

Primary:    ide0, port 0x1f0; major=3;  hda is minor=0; hdb is minor=64
Secondary:  ide1, port 0x170; major=22; hdc is minor=0; hdd is minor=64
Tertiary:   ide2, port 0x1e8; major=33; hde is minor=0; hdf is minor=64
Quaternary: ide3, port 0x168; major=34; hdg is minor=0; hdh is minor=64
fifth..     ide4, usually PCI, probed
sixth..     ide5, usually PCI, probed

インターフェースide0よりも後のインターフェースに接続されたデバイスにアクセスするには、/devに該当するデバイスファイルが存在することを確認してください。なければ、/dev/MAKEDEVを使用してそのエントリを生成してください。

このドライバーは、ほとんどのIDEインターフェース（すべてのPCIインターフェースを含む）を自動的に検出します。それに接続されたドライブ/幾何学、およびインターフェースが使用するIRQライン（通常はide0/ide1用の14、15）も検出します。

必要に応じて、複数のインターフェースが単一のIRQを共有することが可能ですが、これはややパフォーマンス低下を伴います。これは、別個のカードであれ単一のVLBカードであれ、いずれも可能です。IDEドライバーは自動的にこれを検出・処理します。ただし、これはあなたのハードウェアに有害である可能性もありますが、必ずしもそうではありません。2つ以上のカードが同じIRQを駆動すると、バスドライバーがお互いに破壊される可能性がありますが、実際にはこのような状況はめったに起こりません。注意が必要です。疑問がある場合は、やめたほうがいいでしょう！

ドライブは通常、自動プローブやCMOS/BIOSデータの確認によって検出されます。極端な状況では、fdiskの「見かけの幾何学」をカーネルの「コマンドライン」に指定することで、LILOを介して指定可能です。このような行の形式は以下の通りです：

ide_core.chs=[interface_number.device_number]:cyls,heads,sects

または:

ide_core.cdrom=[interface_number.device_number]

例:

ide_core.chs=1.0:1050,32,64  ide_core.cdrom=1.1

成功した自動プローブの結果は、物理的な幾何学/IRQの指定を上書きすることがありますが、「元の」幾何学はパーティションングの目的（fdisk）のために「論理的」幾何学として保持されることがあります。

ブート時の自動プローブがドライブを誤って認識した場合（例：hd.cで動作するがide.cでは動作しない）、各ドライブに対してコマンドラインオプションを指定することで、ハードウェアのプローブ/識別シーケンスをスキップできます。例えば：

ide_core.noprobe=0.1

または:

ide_core.chs=1.0:768,16,32
ide_core.noprobe=1.0

1つのIDEデバイスがインターフェースに接続されている場合、ジャンパを「single」または「master」に設定する必要があります。 ではありません 「slave」。多くのユーザーがこの要件を満たしていないためにCD-ROMで問題を経験しています。そのため、ドライバーは現在両方のユニットをプローブしますが、ジャンパを正しく設定した場合に成功する可能性が高いです。

Scott Snyder氏他による支援により、ドライバーはNEC-260やMITSUMIのトリプル/クォーターレコードドライブなどのATAPI CD-ROMドライブをサポートします。このようなドライブは起動時にハードディスクと同様に識別されます。

何か理由でCD-ROMドライブが ではありません 起動時に検出された場合、LILOを介してカーネルコマンのパラメータを指定することで、プローブをより厳しく行うことができます。例えば：

ide_core.cdrom=1.0      /* "master" on second interface (hdc) */

または:

ide_core.cdrom=1.1      /* "slave" on second interface (hdd) */

例えば、GW2000システムでは、プライマリインターフェース（/dev/hda）にハードディスクがあり、セカンダリインターフェース（/dev/hdc）にIDE CD-ROMドライブが接続されている場合があります。CD-ROMドライブにCDをマウントするには、以下のようなコマンドを使用します：

ln -sf /dev/hdc /dev/cdrom
mkdir /mnt/cdrom
mount /dev/cdrom /mnt/cdrom -t iso9660 -o ro

上記のすべての手順を実施した後、mountが動作せず、ドライバー（dmesg）から status=0xffというエラーが表示された場合、これはドライバーがハードウェアに読み込みを試みても応答がないことを意味します。以下のいずれかが原因である可能性があります：

  • ハードウェアが破損しています。

  • デバイスの正しいアドレスを使用していないか、ドライブのジャンパ設定が誤っています。上記の構成手順を再確認してください。

  • IDEコントローラーは、正常に動作する前に非標準の初期化シーケンスが必要な場合があります。このような場合、コントローラー専用のMS-DOSドライバが別途用意されることが一般的です。サウンドカードのIDEインターフェースはこのカテゴリに属します。このような設定は、まずMS-DOSを起動し、適切なドライバをロードした後、電源を切らずにLinuxを温起動（warm-boot）することで動作させることが可能です。これはMS-DOSのautoexecファイルでloadlinを使用して自動化できます。

タイムアウトエラーが常に発生する場合は、ドライブからの割込みがホストに届いていない可能性があります。ハードウェアジャンパの設定を確認し、ドライバが期待する設定と一致しているか確認してください（上記の設定手順を参照）。PCIシステムを使用している場合は、BIOS設定も確認してください。BIOSがIRQ 15を無効にしているシステムの報告がありました。

カーネルは、CD-ROMがデフォルトのブロックサイズ1024でマウントされている場合、そのディスクからバイナリを直接実行できます。

この情報に関するフィードバックは、maintainerに送ってください。そのアドレスはlinux/MAINTAINERSに記載されています。

IDEドライバはモジュール化されています。高レベルのディスク/CD-ROM/テープ/フロッピードライバは常にロード可能なモジュールとしてコンパイルできます。チップセットドライバはカーネルに組み込む必要があります。コアコード（ide.c）はチップセットサポートが不要な場合にロード可能なモジュールとしてコンパイルできます。

ide.cをkmodと組み合わせてモジュールとして使用する場合、以下の内容を追加してください。

alias block-major-3 ide-probe

/etc/modprobe.d/配下の構成ファイルに。

ide.cをモジュールとして使用する場合、insmodで「options=」キーワードを使用してドライバにコマンドラインパラメータを渡せます。ただし、'、'は'；'に置き換えてください。

カーネルコマンドラインにおけるideドライバパラメータの要約¶

レガシIDE VLBホストドライバ（ali14xx/dtc2278/ht6560b/qd65xx/umc8672）を使用する場合、明示的にプローブを有効にする必要があります。つまり、ALI M14xxチップセット（ali14xxホストドライバ）のプローブを有効にするには、以下のbootオプションを使用してください。

  • ali14xxドライバがカーネルに組み込まれている場合、「ali14xx.probe」bootオプション

  • ali14xxドライバがモジュールとしてコンパイルされている場合、「probe」モジュールパラメータ（「modprobe ali14xx probe」）

レガシCMD640ホストドライバ（cmd640）を使用する場合、VLB版チップセットのプローブを有効にするには「probe_vlb」カーネルパラメータを使用してください（PCI版は自動検出されます）。

ide-4drivesドライバにも「probe」カーネルパラメータを使用してください（IDE汎用チップセットで1ポートに4台のドライブをサポートするため）

AmigaでIDEダブラーのサポートを有効にするには、gayleホストドライバー（ドライバーが組み込まれている場合は「gayle.doubler」）に「doubler」カーネルパラメータを使用します。

ケーブル検出を無視するように強制するには（これは短い40ワイヤーのケーブルを使用している場合にのみ必要ですが、そうでない場合はバグとして報告してください）、「ignore_cable」カーネルパラメータを使用します：

  • IDEが組み込まれている場合、「ide_core.ignore_cable=[インターフェース番号]」ブートオプション（例：「ide_core.ignore_cable=1」で「ide1」のケーブル検出を無視する）を使用します。

  • IDEがモジュールとしてコンパイルされている場合、「ignore_cable=[インターフェース番号]」モジュールパラメータ（ide_coreモジュール用）を使用します。

ide_coreの他のカーネルパラメータは以下の通りです：

  • 「nodma=[インターフェース番号.デバイス番号]」でデバイスのDMAを禁止します。

  • 「noflush=[インターフェース番号.デバイス番号]」でフラッシュリクエストを無効にします。

  • 「nohpa=[インターフェース番号.デバイス番号]」でホスト保護エリアを無効にします。

  • 「noprobe=[インターフェース番号.デバイス番号]」でプローブをスキップします。

  • 「nowerr=[インターフェース番号.デバイス番号]」でWRERR_STATビットを無視します。

  • 「cdrom=[インターフェース番号.デバイス番号]」でデバイスをCD-ROMとして強制します。

  • 「chs=[インターフェース番号.デバイス番号]」でデバイスをディスクとして強制します（CHS方式を使用）。

用語集¶

IDE

統合ドライブ電子（IDE）とは、各ドライブに内蔵されたコントローラーが搭載されていることを意味します。そのため、「IDEインターフェースカード」は「コントローラーカード」ではありません。

ATA

AT（旧IBM 286コンピュータ）アタッチメントインターフェースは、ハードディスクをPCに接続するための草案アメリカンナショナルスタンダードです。これは「IDE」の公式名称です。

最新の標準では、ベンダー固有の「拡張IDE（EIDE）」実装から進化したATA-6仕様の拡張機能が定義されています。

ide-cdドライバは、IDEインターフェースに接続されたATAPI 1.2からATAPI 2.6準拠のCD-ROMドライブすべてで動作します。注意点として、一部のCD-ROMメーカー（ミツミ、ソニー、クリエイティブ、Aztech、ゴールドスターなど）がATAPI準拠ドライブと独自インターフェースを備えたドライブを同時に製造しているため、独自インターフェースを採用しているドライブではこのドライバは動作しません（ただし他のCD-ROMドライバの一つは動作する可能性があります）。また、パラレルポートに接続されたATAPIドライブには対応していません。さらに、少なくとも1台のドライブ（CyCDROM CR520ie）はIDEポートに接続されていますがATAPI準拠ではありません。このようなドライブにはこのドライバは動作しません（ただしaztcdドライバをご参照ください）。

ATAパケットインターフェースは、SCSIプロトコルに似た新しいドライブ制御プロトコルで、ATA2標準が制定された同時期に作成されました。ATAPIは現在、CDROM、TAPE、FLOPPY（ZIPまたはLS120/240）デバイス、取り外し可能なR/Wカートリッジ、および大容量ハードディスクドライブの制御に使用されています。
