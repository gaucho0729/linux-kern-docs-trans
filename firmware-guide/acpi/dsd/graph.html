グラフ¶

_DSD¶

_DSD (デバイス固有データ) [7] は、ACPI仕様書に明記されていないハードウェア機能に関する情報を伝達するための予定された ACPI デバイス構成オブジェクトであり、[1][6] に記載されている。グラフに関連する _DSD の拡張には、プロパティ [4] と階層データ拡張 [5] の 2 つがある。プロパティ拡張は一般的なキー値ペアを提供し、階層データ拡張は他のノードへの参照を持つノードをサポートし、木構造を形成する。この木構造のノードには、プロパティ拡張で定義されたプロパティが含まれる可能性がある。2 つの拡張は、各ノードにゼロ個以上のプロパティ（キー値ペア）を持つ木構造を提供する。

このデータ構造は、include/linux/fwnode.h に定義された device_* および fwnode_* 関数を使用して実行時にも参照可能である。

ファイウェノードは、ファイウェアタイプに依存しない一般的なファイウェアノードオブジェクトを表す。ACPI では、ファイウェノードは _DSD 階層データ拡張オブジェクトであり、デバイスの _D、SD オブジェクトはファイウェノードで表される。

このデータ構造は、ACPI テーブル内の他の場所でハードリファレンスを用いてデバイス自体への参照と階層データ拡張配列のインデックスを各深さごとに指定して参照可能である。

ポートとエンドポイント¶

ポートとエンドポイントの概念は、Devicetree [3] におけるそれらと非常に類似している。ポートはデバイス内のインターフェースを表し、エンドポイントはそのインターフェースへの接続を表す。

すべてのポートノードは、階層データ拡張木構造内のデバイスの「_DSD」ノード下に配置される。各ポートノードに関連するデータ拡張は、キーとして「port」で始まり、「@」文字を続けてポート番号を表す必要がある。参照する対象オブジェクトは「PRTX」と呼ばなければならない。ここで「X」はポート番号である。このようなパッケージの例は以下の通り:

Package() { "port@4", "PRT4" }

さらに、エンドポイントはポートノード下に配置される。エンドポイントノードの階層データ拡張キーは「endpoint」で始まり、「@」文字を続けてエンドポイント番号を表す必要がある。参照する対象オブジェクトは「EPXY」と呼ばなければならない。ここで「X」はポート番号で、「Y」はエンドポイント番号である。このようなパッケージの例は以下の通り:

Package() { "endpoint@0", "EP40" }

各ポートノードは、「port」というプロパティ拡張キーを含み、その値はポート番号です。エンドポイントは同様に「reg」というプロパティ拡張キーで番号付けられ、その値はエンドポイント番号です。ポート番号はデバイス内で一意でなければなりません。エンドのポイント番号はポート内で一意でなければなりません。デバイスオブジェクトが単一のポートのみを持つ場合、そのポート番号はゼロでなければなりません。同様に、ポートが単一のエンドポイントのみを持つ場合、そのエンドポイント番号はゼロでなければなりません。

エンドポイント参照は、「remote-endpoint」というプロパティ名を持つプロパティ拡張とともに、同じパッケージ内の参照を使用します。このような参照は、リモートデバイス参照、デバイス内のポートデータ拡張参照の最初のパッケージエントリ、そしてポート内のエンドポイントデータ拡張参照の最初のパッケージエントリから構成されます。個々の参照は以下のようになります：

Package() { device, "port@X", "endpoint@Y" }

上記の例では、「X」はポート番号、「Y」はエンドポイント番号です。

エンドポイントへの参照は常に両方向で行われる必要があります。つまり、リモートエンドポイントおよび参照されたリモートエンドポイントノードから戻る参照です。

このような例は以下に示します：

Scope (\_SB.PCI0.I2C2)
{
    Device (CAM0)
    {
        Name (_DSD, Package () {
            ToUUID("daffd814-6eba-4d8c-8a91-bc9bbf4aa301"),
            Package () {
                Package () { "compatible", Package () { "nokia,smia" } },
            },
            ToUUID("dbb8e3e6-5886-4ba6-8795-1319f52a966b"),
            Package () {
                Package () { "port@0", "PRT0" },
            }
        })
        Name (PRT0, Package() {
            ToUUID("daffd814-6eba-4d8c-8a91-bc9bbf4aa301"),
            Package () {
                Package () { "reg", 0 },
            },
            ToUUID("dbb8e3e6-5886-4ba6-8795-1319f52a966b"),
            Package () {
                Package () { "endpoint@0", "EP00" },
            }
        })
        Name (EP00, Package() {
            ToUUID("daffd814-6eba-4d8c-8a91-bc9bbf4aa301"),
            Package () {
                Package () { "reg", 0 },
                Package () { "remote-endpoint", Package() { \_SB.PCI0.ISP, "port@4", "endpoint@0" } },
            }
        })
    }
}

Scope (\_SB.PCI0)
{
    Device (ISP)
    {
        Name (_DSD, Package () {
            ToUUID("dbb8e3e6-5886-4ba6-8795-1319f52a966b"),
            Package () {
                Package () { "port@4", "PRT4" },
            }
        })

        Name (PRT4, Package() {
            ToUUID("daffd814-6eba-4d8c-8a91-bc9bbf4aa301"),
            Package () {
                Package () { "reg", 4 }, /* CSI-2 port number */
            },
            ToUUID("dbb8e3e6-5886-4ba6-8795-1319f52a966b"),
            Package () {
                Package () { "endpoint@0", "EP40" },
            }
        })

        Name (EP40, Package() {
            ToUUID("daffd814-6eba-4d8c-8a91-bc9bbf4aa301"),
            Package () {
                Package () { "reg", 0 },
                Package () { "remote-endpoint", Package () { \_SB.PCI0.I2C2.CAM0, "port@0", "endpoint@0" } },
            }
        })
    }
}

ここでは、「CAM0」デバイスのポート0が「ISP」デバイスのポート4に接続され、逆も同様です。
