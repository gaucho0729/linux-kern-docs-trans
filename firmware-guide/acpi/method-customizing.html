Linux ACPI カスタム制御メソッド ガイド¶

著者

Zhang Rui <Zhang Rui <.zhang@intel.com>

Linuxは、実行時にACPI制御メソッドをカスタマイズすることをサポートしています。

ユーザーはこれを以下のように利用できます：

  1. 既存のメソッドを上書きして、正しく動作しない場合やデバッグ目的の場合など。

  2. 欠落しているメソッド（例: _OFF、_ON、_STA、_INI など）を作成するために、完全に新しいメソッドを挿入します。

このような場合、DSDT全体を上書きする代わりに、単一の制御メソッドを動的にインストールする方がはるかに簡単です。カーネルの再構築や再起動が不要で、テスト結果を数分で得られます。

注意

  • ACPI METHODのみが上書き可能です。他のオブジェクトタイプ（例: 「Device」、「OperationRegion」など）は認識されません。スコープ演算子内に宣言されたメソッドもサポートされません。

  • 同じACPI制御メソッドは複数回上書き可能です。Linux/カーネルが使用するのは常に最新のものです。

  • ACPIデバッグオブジェクトの出力（Store (AAAA, Debug)）を取得するには、以下を実行してください：

    echo 1 > /sys/module/acpi/parameters/aml_debug_output

1. 既存のメソッドを上書きする¶

  1. ACPIテーブルをACPI sysfs I/F経由で取得します。例: DSDTを取得するには、「cat /sys/firmware/acpi/tables/DSDT > /tmp/dsdt.dat」を実行します。

  2. 「iasl -d dsdt.dat」を実行してテーブルをディスアセンブルします。

  3. メソッドのASLコードを再作成し、新しいファイルに保存します。

  4. 新しいファイル（psr.asl）をACPIテーブル形式にパッケージ化します。カスタマイズされた _SB._AC._PSR メソッドの例は以下の通りです：

    DefinitionBlock ("", "SSDT", 1, "", "", 0x20080715)
{
   Method (\_SB_.AC._PSR, 0, NotSerialized)
   {
      Store ("In AC _PSR", Debug)
      Return (ACON)
   }
}

    ACPI名前空間内のメソッドのフルパス名を使用する必要があります。

  5. ファイルをアセンブルしてメソッドのAMLコードを生成します。例: 「iasl -vw 6084 psr.asl」（psr.amlが生成結果として作成されます）。「-vw 6084」パラメータがiASLコンパイラでサポートされていない場合は、新しいバージョンを試してください。

  6. debugfsをマウントします。「mount -t debugfs none /sys/kernel/debug」

  7. debugfs経由で旧メソッドを上書きします。「cat /tmp/psr.aml > /sys/kernel/debug/acpi/custom_method」を実行します。

2. 新しいメソッドを挿入する¶

既存のメソッドを上書きするよりも簡単です。挿入したいメソッドのASLコードを作成し、セクション1のステップc)〜g)に従うだけです。

3. 変更を元に戻す¶

現在、新しく挿入したメソッドの「undo」操作はサポートされていません。つまり、現在はメソッドを削除することはできません。上書きしたメソッドの場合、変更を元に戻すには、セクション1のステップc)でメソッドのオリジナルASLコードのコピーを保存し、再びステップc)〜g)を実行してオリジナルのメソッドで上書きしてください。

注意

複数のカスタムACPIメソッドが実行されるカーネルを使用できますが、各デバッグfsへの個別書き込みは単一のメソッドの上書きを実装します。つまり、複数のACPIメソッドを挿入/上書きする場合、ステップc)〜g)を複数回繰り返す必要があります。

注意

rootがこのドライバーを不正に利用して任意のメモリを変更し、追加の権限を取得できる可能性があります。rootの権限が制限されている場合（例えば起動後に追加モジュールのロードが許可されていない場合など）を考慮してください。
