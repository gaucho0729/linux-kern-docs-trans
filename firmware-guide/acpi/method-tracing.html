要約¶

このドキュメントでは、メソッドトレーシングファシリティの機能とインターフェースについて説明します。

機能と使用例¶

ACPICAはメソッドトレーシング機能を提供しており、現在この機能を2つの関数で実装しています。

ログ減算機能¶

ACPICAサブシステムは、CONFIG_ACPI_DEBUGが有効になっている場合にデバッグ出力を提供します。ACPI_DEBUG_PRINT()マクロを介して配置されたデバッグメッセージは、コンポーネントレベル（デバッグレイヤー、/sys/module/acpi/parameters/debug_layerで設定）とタイプレベル（デバッグレベル、/sys/module/acpi/parameters/debug_levelで設定）の2レベルで減算可能です。

しかし、特定のレイヤー/レベルが制御メソッド評価に適用される場合、デバッグ出力の量がカーネルログバッファに収められすぎる可能性があります。そのため、制御メソッド評価が開始されたときにのみ特定のデバッグレイヤー/レベル（通常はより詳細な）ログを有効にし、評価が停止したときに詳細なログを無効にするというアイデアが導入されました。

以下のコマンド例は「ログ減算」機能の使用方法を示します：

  1. 制御メソッドが評価されているときに、一致するデバッグレイヤー/レベルのログをフィルタリングする：

    # cd /sys/module/acpi/parameters
# echo "0xXXXXXXXX" > trace_debug_layer
# echo "0xYYYYYYYY" > trace_debug_level
# echo "enable" > trace_state

  2. 指定された制御メソッドが評価されているときに、一致するデバッグレイヤー/レベルのログをフィルタリングする：

    # cd /sys/module/acpi/parameters
# echo "0xXXXXXXXX" > trace_debug_layer
# echo "0xYYYYYYYY" > trace_debug_level
# echo "\PPPP.AAAA.TTTT.HHHH" > trace_method_name
# echo "method" > /sys/module/acpi/parameters/trace_state

  3. 指定された制御メソッドが初めて評価されているときに、一致するデバッグレイヤー/レベルのログをフィルタリングする：

    # cd /sys/module/acpi/parameters
# echo "0xXXXXXXXX" > trace_debug_layer
# echo "0xYYYYYYYY" > trace_debug_level
# echo "\PPPP.AAAA.TTTT.HHHH" > trace_method_name
# echo "method-once" > /sys/module/acpi/parameters/trace_state
以下では:
0xXXXXXXXX/0xYYYYYYYY

「 ACPIデバッグ出力 可能なデバッグレイヤー/レベルマスク値の例。

PPPP.AAAA.TTTT.HHHH

ACPIネームスペース内で見つかる制御メソッドのフルパス。これは制御メソッド評価のエントリである必要はありません。

AMLトレーサー¶

メソッドトレーシングファシリティは、AMLインタプリタが制御メソッドまたはAMLオペコードを実行するときに「トレースポイント」に特別なログエントリを追加します。注意：ログエントリのフォーマットは変更される可能性があります。

開発者はこれらの特別なログエントリを使用してAMLの解釈を追跡でき、これにより問題のデバッグやパフォーマンスチューニングを支援できます。注意：「AMLトレーサー」ログはACPI_DEBUG_PRINT()マクロで実装されているため、「AMLトレーサー」ログを有効にするにはCONFIG_ACPI_DEBUGも有効にする必要があります。

以下のコマンド例は「AMLトレーサー」機能の使用方法を示します：

  1. 制御メソッドが評価されているときに、メソッドの開始/停止に関する「AMLトレーサー」ログをフィルタリングする：

    # cd /sys/module/acpi/parameters
# echo "0x80" > trace_debug_layer
# echo "0x10" > trace_debug_level
# echo "enable" > trace_state

  2. 指定された制御メソッドが評価されているときに、「AML tracer」のメソッド開始/停止をフィルタリングします。

    # cd /sys/module/acpi/parameters
# echo "0x80" > trace_debug_layer
# echo "0x10" > trace_debug_level
# echo "\PPPP.AAAA.TTTT.HHHH" > trace_method_name
# echo "method" > trace_state

  3. 指定された制御メソッドが初めて評価されているときに、「AML tracer」のメソッド/オペコード開始/停止ログをフィルタリングします。

    # cd /sys/module/acpi/parameters
# echo "0x80" > trace_debug_layer
# echo "0x10" > trace_debug_level
# echo "\PPPP.AAAA.TTTT.HHHH" > trace_method_name
# echo "method-once" > trace_state

  4. 指定された制御メソッドが評価されているときに、「AML tracer」のメソッド/オペコード開始/停止をフィルタリングします。

    # cd /sys/module/acpi/parameters
# echo "0x80" > trace_debug_layer
# echo "0x10" > trace_debug_level
# echo "\PPPP.AAAA.TTTT.HHHH" > trace_method_name
# echo "opcode" > trace_state

  5. 指定された制御メソッドが初めて評価されているときに、「AML tracer」のメソッド/オペコード開始/停止をフィルタリングします。

    # cd /sys/module/acpi/parameters
# echo "0x80" > trace_debug_layer
# echo "0x10" > trace_debug_level
# echo "\PPPP.AAAA.TTTT.HHHH" > trace_method_name
# echo "opcode-opcode" > trace_state

上記のメソッドトレース機能に関連するモジュールパラメータは、ブートパラメータとして使用できます。たとえば、

acpi.trace_debug_layer=0x80 acpi.trace_debug_level=0x10 \
acpi.trace_method_name=\_SB.LID0._LID acpi.trace_state=opcode-once

インターフェースの説明¶

すべてのメソッドトレース機能は、/sys/module/acpi/parameters/でアクセス可能なACPIモジュールパラメータを通じて設定できます。

trace_method_name

ユーザーがトレースしたいAMLメソッドのフルパス。

フルパスには名前のセグメントに末尾の「_」は含めず、「"」を用いて絶対パスを形成することが可能です。

trace_debug_layer

トレース機能が有効になっているときに一時的に使用されるdebug_layer。

デフォルトではACPI_EXECUTER (0x80)を使用し、これはすべての「AML tracer」ログに使用されるdebug_layerです。

trace_debug_level

トレース機能が有効になっているときに一時的に使用されるdebug_level。

デフォルトではACPI_LV_TRACE_POINT (0x10)を使用し、これはすべての「AML tracer」ログに使用されるdebug_levelです。

trace_state

トレース機能の状態。

ユーザーは以下のコマンドを実行することでこのデバッグトレース機能を有効/無効にできます。

# echo string > /sys/module/acpi/parameters/trace_state

「string」は以下のいずれかでなければなりません:

「disable」

メソッドトレース機能を無効にします。

「有効化」

メソッドトレース機能を有効にします。

トレース_debug_layer/trace_debug_levelに一致するACPICAのデバッグメッセージは、任意のメソッド実行中にログ出力されます。

「method」

メソッドトレース機能を有効にします。

トレース_debug_layer/trace_debug_levelに一致するACPICAのデバッグメッセージは、トレース_method_nameのメソッド実行中にログ出力されます。

「method-once」

メソッドトレース機能を有効にします。

トレース_debug_layer/trace_debug_levelに一致するACPICAのデバッグメッセージは、トレース_method_nameのメソッド実行中に一度だけログ出力されます。

「opcode」

メソッドトレース機能を有効にします。

トレース_debug_layer/trace_debug_levelに一致するACPICAのデバッグメッセージは、トレース_method_nameのメソッド/オペコード実行中にログ出力されます。

「opcode-once」

メソッドトレース機能を有効にします。

トレース_debug_layer/trace_debug_levelに一致するACPICAのデバッグメッセージは、トレース_method_nameのメソッド/オペコード実行中に一度だけログ出力されます。

「enable」と他の機能有効化オプションの違いは以下の通りです。

  1. 「enable」が指定された場合、trace_debug_layer/trace_debug_levelがすべての制御メソッド評価に適用されるため、trace_stateを「enable」に設定した後、trace_method_nameはNULLにリセットされます。

  2. 「method/opcode」が指定された場合、trace_stateをこれらのオプションに設定する際、trace_method_nameがNULLである場合、trace_debug_layer/trace_debug_levelがすべての制御メソッド評価に適用されます。
