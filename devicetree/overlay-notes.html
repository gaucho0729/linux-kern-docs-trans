Device Treeオーバーレイに関する注意点¶

このドキュメントは、drivers/of/overlay.c に実装された内蔵デバイスツリー・オーバーレイ機能の実装について説明し、『How overlays work』と併せて読むべき補足ドキュメントです Device Treeダイナミックリゾルバに関する注意点[1]

『How overlays work』¶

デバイスツリーのオーバーレイの目的は、カーネルのライブツリーを変更し、その変更がカーネルの状態に反映されるようにすることです。カーネルは主にデバイスを扱うため、新たに生成されたデバイスノードがアクティブなデバイスを表す場合は、そのノードを生成する必要があります。逆にデバイスノードが無効化されたり完全に削除された場合は、影響を受けるデバイスは登録解除されるべきです。

foo ボードのベースツリーが以下のようになっている例を考えてみましょう:

---- foo.dts ---------------------------------------------------------------
    /* FOO platform */
    /dts-v1/;
    / {
            compatible = "corp,foo";

            /* shared resources */
            res: res {
            };

            /* On chip peripherals */
            ocp: ocp {
                    /* peripherals that are always instantiated */
                    peripheral1 { ... };
            };
    };
---- foo.dts ---------------------------------------------------------------

オーバーレイ bar.dts は、

---- bar.dts - overlay target location by label ----------------------------
    /dts-v1/;
    /plugin/;
    &ocp {
            /* bar peripheral */
            bar {
                    compatible = "corp,bar";
                    ... /* various properties and child nodes */
            };
    };
---- bar.dts ---------------------------------------------------------------

ロードされ（[1] に記載された方法で解決されると）、foo+bar.dts に変換されます:

---- foo+bar.dts -----------------------------------------------------------
    /* FOO platform + bar peripheral */
    / {
            compatible = "corp,foo";

            /* shared resources */
            res: res {
            };

            /* On chip peripherals */
            ocp: ocp {
                    /* peripherals that are always instantiated */
                    peripheral1 { ... };

                    /* bar peripheral */
                    bar {
                            compatible = "corp,bar";
                            ... /* various properties and child nodes */
                    };
            };
    };
---- foo+bar.dts -----------------------------------------------------------

このオーバーレイにより、新しいデバイスノード（bar）が生成され、bar プラットフォームデバイスが登録されます。マッチするデバイスドライバがロードされると、予期通りにデバイスが生成されます。

ベースDTが -@ オプションでコンパイルされていない場合、『&ocp』ラベルはオーバーレイノードをベースDTの正しい場所に解決できません。この場合、ターゲットパスを指定できます。ラベルによるターゲットパス構文が優先されるのは、オーバーレイをベースDT内のラベルがどこにあるかに関係なく適用できるためです。

上記の bar.dts 例をターゲットパス構文に変更したものは以下の通り:

---- bar.dts - overlay target location by explicit path --------------------
    /dts-v1/;
    /plugin/;
    &{/ocp} {
            /* bar peripheral */
            bar {
                    compatible = "corp,bar";
                    ... /* various properties and child nodes */
            }
    };
---- bar.dts ---------------------------------------------------------------

オーバーレイ内蔵API¶

このAPIは非常に使いやすく設計されています。

  1. of_overlay_fdt_apply() を呼び出してオーバーレイ変更セットを生成・適用します。返り値はエラーか、このオーバーレイを識別するクッキーになります。

  2. of_overlay_remove() を呼び出して、以前 of_overlay_fdt_apply() で生成したオーバーレイ変更セットを削除・クリーンアップします。他のオーバーレイによってスタックされた変更セットは削除できません。

さらに、すべてのオーバーレイを一度に削除するには、of_overlay_remove_all() を呼び出します。これにより、正しい順序ですべてのオーバーレイが削除されます。

また、オーバーレイ操作時に呼び出される通知レジスタを登録するオプションもあります。詳細は of_overlay_notifier_register/unregister および enum of_overlay_notify_action を参照してください。

通知コールバックは、OF_OVERLAY_POST_REMOVE に該当するノードを受信した後は、デバイスツリーノードまたはそのコンテンツへのポインタを保存すべきではありません。
