JSON SchemaでDeviceTreeバインディングを書く¶

Devicetreeバインディングはjson-schemaの語彙を使用して記述されます。スキーマファイルはJSONと互換性のあるYAMLのサブセットで記述されます。YAMLがJSONよりも人間が読みやすく、コメントのサポート（'#'で前につける）などの利点があるため、YAMLが使用されています。

スキーマの内容¶

各スキーマドキュメントは、トップレベルのプロパティで定義される構造化されたjson-schemaです。通常、1つのバインディングが1ファイルに定義されています。トップレベルのjson-schemaプロパティとして使用されるものは以下の通りです：

$id

json-schemaのユニークな識別子文字列。この文字列は有効なURIでなければなりません（通常はバインディングのファイル名とパスを含みます）。DTスキーマの場合、このURIは"で始まる必要があります。http://devicetree.org/schemas/URLは、スキーマ内の「$ref」プロパティで指定された他のファイルへの参照を構築するために使用されます。「$ref」値が先頭に「/」を含む場合、ホスト名が先頭に追加されます。「$ref」値が相対パスまたはファイル名のみの場合、現在のスキーマファイルの「$id」値のホスト名とパスコンポーネントが先頭に追加されます。ローカルファイルにもURLが使用されますが、その場所に実際にファイルが存在しない可能性があります。

$schema

このスキーマファイルが準拠しているメタスキーマを示します。

title

バインディングスキーマの内容を1行で説明します。

maintainers

DT固有のプロパティ。このバインディングのメンテナーメールアドレス（複数可）を含むリスト。

説明

オプション。このバインディングに関する詳細情報を含むマルチラインテキストブロック。デバイスの機能、準拠する規格、データシートへのリンクなど、詳細情報を記載する。

選択

オプション。ノードをマッチングするためのJSONスキーマ。'select'が指定されていない場合、ノードは可能な互換文字列値またはノード名とマッチングされる。ほとんどのバインディングでは'select'は必要ない。

allOf

オプション。他のスキーマを含めるリスト。このバインディングが準拠する他のスキーマを含めるために使用される。I2CやSPIコントローラーなどの特定のデバイスクラスのスキーマを含める場合にも使用される。

プロパティ

バインディングのDTプロパティを定義するサブスキーマの集合。プロパティが既知の共通プロパティ（例: 'interrupts'）か、バインディング/ベンダー固有のプロパティかによって、正確なスキーマ構文が異なる。

プロパティは、その下に子プロパティを定義した子DTノードを定義することができる。

プロパティセクションの詳細については、「プロパティスキーマ」セクションを参照。

patternProperties

オプション。'properties'と同様だが、名前は正規表現を使用する。

必須

「properties」セクションから常に存在するDTプロパティの一覧。

例

オプション。バインディングを実装する1つまたは複数のDTS ハンクの一覧。注意: YAMLでは先頭のタブは許可されていないため、代わりにスペースを使用する必要があります。

他の記載がない限り、すべてのプロパティは必須です。

プロパティ スキーマ¶

スキーマの「properties」セクションには、バインディング用のすべてのDTプロパティが含まれます。各プロパティには、そのプロパティに適用されるjson-schemaの語彙を使用した制約が含まれています。プロパティ スキーマはDTファイルの検証に使用されます。

一般的なプロパティについては、一般的なバインディング スキーマでカバーされていない追加の制約のみを定義する必要があります。有効な値の数や有効な可能性のある値などです。

ベンダー固有のプロパティには通常、より詳細なスキーマが必要です。ブール型のプロパティを除き、schemas/types.yaml内の型への参照を持つ必要があります。「description」プロパティは常に必要です。

Devicetree スキーマは、dtcで生成されるYAMLエンコードされたDTデータと正確には一致しません。これらはよりコンパクトで、多数のボイラープレートを避けるために簡略化されています。ツールはスキーマファイルを処理して、検証用の最終スキーマを生成します。現在、ツールが実行する変換は2つです。

json-schemaにおける配列のデフォルトは、可変サイズで明示的に定義されたよりも多くの項目を許可することです。これは'minItems'、'maxItems'、'additionalItems'を定義することで制限できます。ただし、Devicetree スキーマではほとんどの場合固定サイズが望ましいため、'items'リスト内の項目数に基づいてこれらのプロパティが追加されます。

YAML Devicetree形式では、単一の値が存在する場合でも、すべての文字列値を配列として、スカラー値を行列として扱います（グループの定義のため）。スキーマ内の単一のエントリはこのエンコーディングに合わせて固定されます。

テスト¶

依存関係¶

DTスキーマプロジェクトをインストールする必要があります。DTスキーマバインディングドキュメントを検証し、DTスキーマを使用してDTSファイルを検証するためです。DTスキーマプロジェクトはpipを使用してインストールできます：

pip3 install git+https://github.com/devicetree-org/dt-schema.git@master

複数の実行可能ファイル（dt-doc-validate、dt-mk-schema、dt-validate）がインストールされます。これらがPATHに含まれていることを確認してください（デフォルトでは~/.local/bin）。

dctもYAML出力サポートを有効にしてビルドする必要があります。これには、ホストシステムにlibyamlおよびそのヘッダーファイルをインストールする必要があります。一部のディストリビューションでは開発パッケージをインストールする必要があります、たとえば：

Debian:

apt-get install libyaml-dev

Fedora:

dnf -y install libyaml-devel

チェックの実行¶

DTスキーマバインディングドキュメントは、メタスキーマ（スキーマのスキーマ）を使用して検証する必要があります。これにより、これらが有効なJSON-Schemaおよび有効なバインディングスキーマであることを確認できます。 dt_binding_check ターゲット:

make dt_binding_check

DTソースファイルの検証を行うには、 dtbs_check ターゲット:

make dtbs_check

注意してください dtbs_check エラーのあるバインディングスキーマファイルはスキップされます。エラーのあるバインディングスキーマファイルのすべての検証エラーを取得するには、 dt_binding_check 使用する必要があります。

両方を1つのコマンットで実行できます:

make dt_binding_check dtbs_check

また、単一のスキーマファイルでチェックを実行することも可能です。変数を特定のスキーマファイルに設定する必要があります。 DT_SCHEMA_FILES 変数を特定のスキーマファイルに設定する必要があります。

make dt_binding_check DT_SCHEMA_FILES=Documentation/devicetree/bindings/trivial-devices.yaml
make dtbs_check DT_SCHEMA_FILES=Documentation/devicetree/bindings/trivial-devices.yaml
