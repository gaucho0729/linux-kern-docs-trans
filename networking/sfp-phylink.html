phylink¶

概要¶

phylinkは、ホットプラグ可能なネットワーキングモジュールを直接MACに接続し、ホットプラグイベント時にアダプターを再初期化せずにサポートするメカニズムです。

phylinkは現在、従来のphylibベースの設定、固定リンク設定、SFP（Small Formfactor Pluggable）モジュールをサポートしています。

運用モード¶

phylinkは、ファームウェアの設定に応じていくつかの運用モードを持っています。

  1. PHYモード

    PHYモードでは、phylibを使用してPHYから現在のリンク設定を読み取り、MACドライバに渡します。MACドライバは、リンクでネゴシエーションを有効にせずに指定されたモードを正確に設定する必要があります。

  2. 固定モード

    MACドライバの観点から、固定モードはPHYモードと同様です。

  3. インバンドモード

    インバンドモードは802.3z、SGMII、類似のインターフェースモードで使用され、インバンドのネゴシエーションやコントロールワードがserdesチャネルを介して送信されることを期待しています。

例えば、これは以下の意味になります:

&eth {
  phy = <&phy>;
  phy-mode = "sgmii";
};

インバンドSGMIIサインアリティングを使用しません。PHYは、その mac_config() 関数に渡された設定を正確に従う必要があります。リンクは、 mac_link_up() および mac_link_down() 関数の終わりを注釈する必要があります。

&eth {
  managed = "in-band-status";
  phy = <&phy>;
  phy-mode = "sgmii";
};

インバンドモードを使用し、PHYのネゴシエーション結果がSGMIIコントロールワードを通じてMACに渡され、MACがコントロールワードを確認することを期待しています。このため、 mac_link_up() および mac_link_down() 関数はMAC側のリンクを強制的にアップダウンさせない必要があります。

sfp/phylinkへのネットワークドライバー変換の概要ガイド¶

このガイドでは、ネットワークドライバをphylibからsfp/phylinkサポートに変換する方法を簡潔に説明します。このドキュメンテーションの改善にパッチを送信してください。

  1. オプションで、ネットワークドライバのphylib更新関数をリンクダウンとリンクアップの2つの部分に分割できます。これは別個の準備コミットとして実施できます。

    このような準備の古い例はgitコミットfc548b991fb0にあります。ただし、この場合は3つの部分に分割しており、リンクアップ部分ではリンク設定に基づいてMACを設定するようになっています。詳しくは mac_link_up() を参照してください。

  2. 置き換える:

    select FIXED_PHY
select PHYLIB

    以下のように変更してください：

    select PHYLINK

    ドライバのKconfigセクション内の

  3. 追加する:

    #include <linux/phylink.h>

    ドライバのヘッダーファイルリストに

  4. 追加する:

    struct phylink *phylink;
struct phylink_config phylink_config;

    ドライバのプライベートデータ構造体に追加します。ここではドライバのプライベートデータポインタを priv と呼び、プライベートデータ構造体を struct foo_priv.

  5. 以下の関数を置き換えてください:

    オリジナル関数

    置き換え関数

    phy_start(phydev)

    phylink_start(priv->phylink)

    phy_stop(phydev)

    phylink_stop(priv->phylink)

    phy_mii_ioctl(phydev, ifr, cmd)

    phylink_mii_ioctl(priv->phylink, ifr, cmd)

    phy_ethtool_get_wol(phydev, wol)

    phylink_ethtool_get_wol(priv->phylink, wol)

    phy_ethtool_set_wol(phydev, wol)

    phylink_ethtool_set_wol(priv->phylink, wol)

    phy_disconnect(phydev)

    phylink_disconnect_phy(priv->phylink)

    注意: これらの関数の一部は rtnl ロックの下で呼び出さなければならず、呼び出しが行われていない場合に警告を出します。通常はこの条件が満たされていますが、ドライバのスリープ/再開処理から呼び出される場合を除きます。

  6. ksettings の get/set メソッドを以下に置き換えてください:

    static int foo_ethtool_set_link_ksettings(struct net_device *dev,
                                          const struct ethtool_link_ksettings *cmd)
{
        struct foo_priv *priv = netdev_priv(dev);

        return phylink_ethtool_ksettings_set(priv->phylink, cmd);
}

static int foo_ethtool_get_link_ksettings(struct net_device *dev,
                                          struct ethtool_link_ksettings *cmd)
{
        struct foo_priv *priv = netdev_priv(dev);

        return phylink_ethtool_ksettings_get(priv->phylink, cmd);
}

  7. 以下の呼び出しを置き換えてください:

    phy_dev = of_phy_connect(dev, node, link_func, flags, phy_interface);

    および関連するコードを以下の呼び出しに置き換えてください:

    err = phylink_of_phy_connect(priv->phylink, node, flags);

    ほとんどの場合、 flags ゼロにすることができます。これらは DT ノードに PHY が指定されている場合、この関数呼び出し内の of_phy_attach() に渡されるフラグです node.

    node ネットワーク PHY プロパティ、固定リンクプロパティを含む DT ノードであり、sfp プロパティも含みます

    固定リンクの設定は削除すべきです。phylink が内部で処理します。

    of_phy_connect() にはリンク更新用の関数ポインタが渡されていましたが、これは以下の (8) に記載する MAC 更新の別の形式に置き換えられています。

    PHY のサポート/広告の操作は、以下の (8) に記載する validate コールバックに基づいて phylink 内で行われます。

    ドライバはもはや phy_interfaceを保存する必要がありません。また、 phy_interface は速度、duplex などと同様に動的プロパティになります。

    最後に、MAC ドライバはもはや PHY に直接アクセスしなくなります。これは phylink モデルにおいて PHY が動的であるためです。

  8. Add a struct phylink_mac_ops ドライバにインスタンスを渡すことで、関数ポインタのテーブルを実装し、これらの関数を実装する必要があります。古いリンク更新関数は of_phy_connect() に置き換えられ、3つのメソッドになります: mac_link_up(), mac_link_down(), and mac_config()。ステップ1が実行された場合、その時点で機能が分割されています。

    インバンドネゴシエーションが使用されている場合、 mac_link_up() および mac_link_down() インバンドネゴシエーションが完了しないようにしないでください。これらの関数はインバンドリンクステートが変化したときに呼び出されるため、リンクが上がらない可能性があります。

    以下の validate() メソッドは、提供されたサポートマスクをマスクし、 state->advertising サポートされる ethtool リンクモードと組み合わせます。これらは新しい ethtool リンクモードであるため、ビットマスク操作を使用しなければなりません。例は drivers/net/ethernet/marvell/mvneta.c を参照してください。

    以下の mac_link_state() メソッドは MAC からリンクステートを読み取り、MAC が現在使用している設定を報告します。これはインバンドネゴシエーションメソッド（例: 1000base-X および SGMII）において特に重要です。

    以下の mac_link_up() メソッドは、リンクがアップになったことをMACに通知するために使用されます。この呼び出しには、参照用のネゴシエーションモードとインターフェースが含まれ、最終的なリンクパラメータ（速度、双方向通信、フロー制御/パウーズ有効化設定）も提供されます。これらの設定は、MACとPCSが密接に統合されていない場合、または設定がインバンドネゴシエーションから来ない場合にMACを構成するために使用する必要があります。

    以下の mac_config() メソッドは、MACに要求された状態を更新するために使用され、MAC構成の変更時にリンクを不要にダウンさせることを避ける必要があります。これは、関数が状態を変更し、MAC構成を変更する必要が絶対にない限りリンクをダウンさせないことを意味します。このような処理の例は、 mvneta_mac_config() drivers/net/ethernet/marvell/mvneta.c

    これらのメソッドに関する詳細情報については、以下のインラインドキュメンテーションを参照してください。 struct phylink_mac_ops.

  9. PHY用のof_parse_phandle()呼び出し、固定リンク用のof_phy_register_fixed_link()呼び出しなど、プローブ関数から削除し、以下のものを使用してください：

    struct phylink *phylink;
priv->phylink_config.dev = &dev.dev;
priv->phylink_config.type = PHYLINK_NETDEV;

phylink = phylink_create(&priv->phylink_config, node, phy_mode, &phylink_ops);
if (IS_ERR(phylink)) {
        err = PTR_ERR(phylink);
        fail probe;
}

priv->phylink = phylink;

    また、プローブ失敗パスや除去パスにおいて適切にphylinkを破壊するには、以下の関数を呼び出してください：

    phylink_destroy(priv->phylink);

  10. MACリンクステート割込みをphylink経由で転送するには、以下の方法を使用してください：

    phylink_mac_change(priv->phylink, link_is_up);

    オプションを指定する必要があります。形式は以下の通りです： link_is_up リンクが現在アップしている場合はtrue、それ以外はfalseです。MACがこれらの割込みを提供できない場合、以下の設定を行ってください： priv->phylink_config.pcs_poll = true; ステップ9で説明されています。

  11. ドライバが以下の関数を呼び出さないことを確認してください：

    netif_carrier_on()
netif_carrier_off()

これらはphylinkがリンクステートを追跡するのを妨げ、phylinkが以下のメソッド経由での呼び出しを省略する原因になります。 mac_link_up() および mac_link_down() メソッド

ネットワークドライバは、スリープ/再開パスを通じて以下の関数を呼び出す必要があります。 phylink_stop() および phylink_start() これにより、適切な struct phylink_mac_ops メソッドが必要なときに呼び出されるようになります。

SFPキャビネットに関するDTの記述については、カーネルソースツリー内のバインディングドキュメンテーションを参照してください。 Documentation/devicetree/bindings/net/sff,sfp.txt
