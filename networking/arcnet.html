ドライバのインストール¶

ドライバをインストールするために必要なのは以下の手順だけです：

make config
        (be sure to choose ARCnet in the network devices
        and at least one chipset driver.)
make clean
make zImage

現在のカーネルに ARCnet ドライバをアップグレードしてこの ARCnet パッケージを取得した場合、まず linux/drivers/net ディレクトリ内の arcnet.c を上書きしてください。

新しい Linux カーネルで再起動時に ARCnet のメッセージが表示されれば、ドライバが正しくインストールされていることを確認できます。

4 種類のチップセットオプションがあります：

  1. 標準 ARCnet COM90xx チップセット。

これは通常の ARCnet カードで、おそらくあなたが持っているものです。このチップセットドライバは、カードの位置を指定されない場合でも自動プローブします。コマンドラインで以下のオプションを使用します：

com90xx=[<io>[,<irq>[,<shmem>]]][,<name>] | <name>

チップセットサポートをモジュールとしてロードする場合、オプションは以下の通りです：

io=<io> irq=<irq> shmem=<shmem> device=<name>

自動プローブを無効にするには、カーネルコマンドラインに「com90xx=」を指定してください。カードの位置を指定せず自動プローブを許可するには、「com90xx=<name>」を指定してください。

  1. ARCnet COM20020 チップセット。

これは SMC が製造する新しいチップセットで、プロミスカスモード（パケットスニーフィング）や追加の診断情報などのサポートがあります。残念ながら、これらのカードの自動プローブには合理的な方法がありません。必須として I/O アドレスをカーネルコマンドラインで指定する必要があります。

コマンドラインオプションは以下の通りです：

com20020=<io>[,<irq>[,<node_ID>[,backplane[,CKP[,timeout]]]]][,name]

チップセットサポートをモジュールとしてロードする場合、オプションは以下の通りです：

io=<io> irq=<irq> node=<node_ID> backplane=<backplane> clock=<CKP>
timeout=<timeout> device=<name>

COM20020 チップセットは、DIP スイッチで設定されているデフォルトのノード ID をソフトウェアで上書きして設定できます。COM20020 のデータシートを持っていない場合、他の 3 種類のオプションが何を指すか分からない場合は、それらはあなたにとって関係ありません。無視してください。

  1. ARCnet COM90xx チップセットを I/O マップモードで使用する場合。

これは通常のARCnetカードにも動作しますが、共有メモリを使用していません。上記のドライバよりも性能は劣りますが、共有メモリをサポートしないカードを持っている場合、または（不思議なことに）マシン内にARCnetカードが多数あるために共有メモリスロットが不足している場合に使用できます。カーネルコマンドラインにI/Oアドレスを指定しないと、ドライバがカードを検出できなくなります。

コマンドラインオプションは以下の通りです：

com90io=<io>[,<irq>][,<name>]
チップセットサポートをモジュールとしてロードする場合、オプションは以下の通りです：

io=<io> irq=<irq> device=<name>

  1. ARCnet RIM I カード。

これらはCOM90xxチップで、_完全に_メモリマップされています。これらのサポートはテストされていません。もし持っている場合は、成功報告を著者にメールで送ってください。すべてのオプションを指定する必要があります（デバイス名を除く）。コマンドラインオプション:

arcrimi=<shmem>,<irq>,<node_ID>[,<name>]

チップセットサポートをモジュールとしてロードする場合、オプションは以下の通りです：

shmem=<shmem> irq=<irq> node=<node_ID> device=<name>

ロード可能なモジュールサポート¶

Linuxを構築・再構築する際、『Generic ARCnetサポート』に尋ねられたら「m」を選択し、ARCnetチップセットのサポートをロード可能なモジュールとして使用したい場合は、それに応じて「m」を選択してください。『Generic ARCnetサポート』には「y」を選択し、チップセットサポートには「m」を選択することも可能です。

make config
make clean
make zImage
make modules

ロード可能なモジュールを使用している場合、insmodでモジュールをロードする必要があります。また、コマンドラインでカードのさまざまな特性を指定できます。（最近のドライバでは自動プローブが大幅に信頼性が向上し、モジュールとして動作するため、ほとんどの場合これを使用しなくても済みます。）

例:

cd /usr/src/linux/modules
insmod arcnet.o
insmod com90xx.o
insmod com20020.o io=0x2e0 device=eth1

ドライバの使用方法¶

ARCnet COM90xxサポートをカーネルに組み込んで構築した場合、起動時にカードを自動で検出します。異なるチップセットドライバをカーネルに組み込んで使用する場合は、上記のようにカーネルコマンドラインに必要なオプションを指定する必要があります。

NET-2-HOWTOとETHERNET-HOWTOを読みましょう。これらはこのドライバを取得した場所で入手可能です。ARCnetを、（場合によっては逆に）Ethernetカードを進化させたものと考えてください。

ついでに、HOWTO内のすべての「eth0」への参照を「arc0」に変更してください。ARCnetは「真の」Ethernetではありませんし、デバイス名は異なります。

1台のコンピュータでの複数のカード¶

Linuxはこれに対応していますが、私は忙しくてARCnetドライバはこの点でやや劣化しています。COM90xxサポートがカーネルに組み込まれている場合、すべてのインストール済みカードを自動検出しようとします。

他のチップセットをサポートするカーネルに組み込まれている場合、カーネルコマンドラインでオプションを繰り返すことができます。例えば:

LILO: linux com20020=0x2e0 com20020=0x380 com90io=0x260

チップセットサポートがロード可能なモジュールとして組み込まれている場合、次のような操作が必要です:

insmod -o arc0 com90xx
insmod -o arc1 com20020 io=0x2e0
insmod -o arc2 com90xx

ARCnetドライバは今後、名前を自動的に整理します。

…と動作させるにはどうすればよいですか？¶

NFS:

linux→linuxの設定は問題ないはずです。Ethernetカードを使用しているかのように見せかけましょう。oak.oakland.edu:/simtel/msdos/nfsには、良いDOSクライアントがいくつかあります。また、SOSSというDOSベースのNFSサーバーもあります。これはLinuxのように完全にマルチタスクをサポートしていません（実際にはマルチタスクをまったくサポートしていません）が、必要なものが何か分からないかもしれません。

AmiTCP（および他のソフトウェアも含む）を使用する場合、Amigaのnfstabに以下のオプションを設定する必要があります：MD 1024 MR 1024 MW 1024（Christian Gottschling <ferksy@indigo.tng.oche.de> による）

これらの設定は、最大NFSデータ/読み取り/書き込みブロックサイズを指している可能性があります。なぜAmigaのデフォルト設定が機能しなかったのか理由はわかりません。詳しい情報があれば、私に教えてください。

DOS:

arcether.comというフリーソフトウェアを使用している場合、私のウェブページからドライバーパッチをインストールすることを検討してください。これはPC/TCPの処理を助け、arcetherが初期化中にタイムアウトしてしまった場合でもロードできるようにします。実際、386+で使用する場合はパッチを本当に必要とします。

Windows:

DOSを参照してください :) Trumpet WinsockはNovellまたはArcetherクライアントとどちらでも問題なく動作します。ただし、winpktをロードすることを忘れないでください。

LAN ManagerおよびWindows for Workgroups:

これらのソフトウェアはインターネット標準と互換性のないプロトコルを使用します。ネットワーク上の他のすべてのデバイスに混乱を及ぼすように、カードがEthernetであるかのように装います。

ただし、LinuxのARCnetドライバーバージョン2.00以上は「arc0e」デバイスを通じてこのプロトコルをサポートしています。詳しくは「マルチプロトコルサポート」セクションを参照してください。

Linux用のフリーソフトウェアSambaサーバーおよびクライアントを使用することで、TCP/IPベースのWfWgまたはLan Managerネットワークと非常にスムーズにインターフェースできます。

Windows 95:

Win95には、LANMANスタイルのネットワークドライバ（NDIS）またはNovellドライバ（ODI）を使用してARCnetパケットを処理するためのツールが含まれています。ODIを使用する場合、Linuxでは「arc0」デバイスを使用する必要があります。NDIを使用する場合は「arc0e」デバイスを試してください。arc0eが必要な場合は、あなたは完全に馬鹿です、または両方のエンカプスレーションタイプを組み合わせたハイブリッドネットワークを構築する必要があります。詳しくは下記の「マルチプロトコルサポート」セクションをご参照ください。

OS/2:

Warp ConnectでSMCのARCnetドライバを使用すると動作するという情報がありました。この場合、「arc0e」インターフェースを使用する必要があります。SMCドライバーが「通常の」Warpボーナスパックに含まれるTCP/IP機能と動作するようになった場合、私に教えてください。

ftp.microsoft.comも「Lan Manager for OS/2」クライアントというフリーソフトウェアを提供しており、WfWgと同じプロトコルを使用するはずです。ただし、Warpでのインストールには失敗しました。結果があれば、私にメールで教えてください。

NetBSD/AmiTCP:

これらは、インターネット標準のARCnetプロトコル（RFC1051）の古いバージョンを使用しており、Linuxドライバv2.10 ALPHA以降のarc0sデバイスで動作するLinuxドライバと互換性があります。（下記の「マルチプロトコルARCnet」を参照してください。）** NetBSDの新しいバージョンは明らかにRFC1201をサポートしているようです。

マルチプロトコルARCnetの使用¶

ARCnetドライバv2.10 ALPHAは、それぞれの「仮想ネットワークデバイス」で動作する3つのプロトコルをサポートしています：

arc0

RFC1201プロトコルは、ノベルのTRXNETドライバと100%互換性がある公式のインターネット標準です。ARCnetドライバのバージョン1.00はこのプロトコルのみをサポートしていました。arc0は3つのプロトコルの中で最も高速（何故か）で、RFC1201の「パケット分割」操作をサポートしているため、より大きなパケットを使用できます。特定の理由で他のプロトコルを使用する必要がない限り、このプロトコルを使用することを強くお勧めします。

arc0e

「イーサネットエミネーション」は、実際にはイーサネットパケットに似たパケットをARCnet経由で送信します。6バイトのハードウェアアドレスを含むため、イーサネットパケットと類似しています。このプロトコルは、WfWgやLANMANに含まれるMicrosoftのNDIS ARCnetドライバと互換性があります。MTU（493）がTCP/IPが「必要とする」MTU（576）よりも小さいため、一部のネットワーク操作が正しく動作しない可能性があります。しかし、LinuxのTCP/IPレイヤーはほとんどの場合、TCP/IPパケットを自動的に分割してサイズを調整することで問題を補償します。arc0eはarc0よりもわずかに遅く動作します（おそらくはMTUの小ささが原因です）。

arc0s

「シンプル」なRFC1051プロトコルは、新しい標準と完全に互換性がない「以前の」インターネット標準です。しかし、一部のソフトウェア（NetBSDやAmiTCPを含む）は今もこの古い標準のみをサポートしています。RFC1051はRFC1201のパケット分割をサポートせず、MTU（507）がインターネットの「要件」より小さいため、問題が発生する可能性があります。また、arc0eと同様の理由でRFC1201に比べて約25%遅く動作します。

arc0sのサポートはTomasz Motylewskiによって提供され、私は多少修正を加えました。バグはおそらく私の責任です。

必要なければarc0eとarc0sをドライバに組み込む必要はありません。これによりメモリを節約でき、最近のLinuxカーネルで「NFS-root」などの機能を使用する際の混乱を避けることができます。

arc0eとarc0sデバイスは、arc0デバイスを初めてifconfigで設定した際に自動的に作成されます。ただし、実際にそれらを使用するには、必要な他の仮想デバイスもifconfigで設定する必要があります。ネットワークを設定する方法はいくつかあります:

  1. 単一プロトコル。

    これはネットワークを設定する最も簡単な方法です。2つの利用可能なプロトコルのうち、どちらか1つだけを使用します。上記のように、arc0のみを使用するのが良いですが、他のソフトウェア（例: WfWgなど、arc0eのみで動作するソフトウェアがある場合）がある場合は除きます。

    arc0のみが必要な場合は、以下のコマンドで開始できます:

    ifconfig arc0 MY.IP.ADD.RESS
route add MY.IP.ADD.RESS arc0
route add -net SUB.NET.ADD.RESS arc0
[add other local routes here]

    arc0e（かつ、arc0eのみ）が必要な場合は、少し異なります:

    ifconfig arc0 MY.IP.ADD.RESS
ifconfig arc0e MY.IP.ADD.RESS
route add MY.IP.ADD.RESS arc0e
route add -net SUB.NET.ADD.RESS arc0e

    arc0sはarc0eと同様の方法で動作します。

  2. 同じワイヤー上に複数のプロトコルを使用する。

    ここからが本番です。試してみるだけでも、一部の異常な状態を許容する必要があります。以下は I が行ったことです。:) 注意点として、私の家庭ネットワークにはarc0sは含まれていません。NetBSDやAmiTCPのコンピュータを持っていないため、arc0sは限定的なテストの際にのみ使用しています。

    私の家庭ネットワークには3台のコンピュータがあります。2台はLinuxのマシン（RFC1201プロトコルを好む、上記の理由により）、1台はLinuxを実行できないが、無料のMicrosoft LANMANクライアントを実行するXTです。

    さらに悪いことに、1台のLinuxマシン（freedom）にはモデムがあり、インターネットプロバイダーへのルーターとして機能しています。もう1台のLinuxマシン（insight）には独自のIPアドレスがあり、freedomをデフォルトゲートウェイとして使用する必要があります。XT（patience）は独自のインターネットIPアドレスを持っていないため、RFC1597で定義された「プライベートサブネット」にIPアドレスを割り当てました。

    まずは、insightとfreedomだけのシンプルなネットワークを想定します。insightは以下が必要です:

    • RFC1201（arc0）プロトコルでfreedomと通信する必要があります。なぜなら、私はこのプロトコルをより好んでおり、速度も速いからです。

    • インターネットゲートウェイとしてfreedomを使用する必要があります。

    これは比較的簡単です。insightを以下のように設定してください:

    ifconfig arc0 insight
route add insight arc0
route add freedom arc0  /* I would use the subnet here (like I said
                                to in "single protocol" above),
                                but the rest of the subnet
                                unfortunately lies across the PPP
                                link on freedom, which confuses
                                things. */
route add default gw freedom

    freedomは以下のように設定されます:

    ifconfig arc0 freedom
route add freedom arc0
route add insight arc0
/* and default gateway is configured by pppd */

    素晴らしい、今やinsightはarc0経由でfreedomに直接通信し、インターネット経由でパケットを送信しています。上記の手順が分からない場合は、このセクションを読むのをやめてください。なぜなら、その後はさらに複雑になるからです。

    では、patienceをネットワークに追加するにはどうすればよいでしょうか？LANMANクライアントを使用するため、arc0eデバイスが必要です。patienceはinsightとfreedomの両方と通信でき、インターネットへのゲートウェイとしてfreedomを使用する必要があります。（patienceは「プライベートIPアドレス」を持ち、インターネットでは動作しませんが、これは問題ありません。私はこのサブネットのためにfreedomでLinux IPマスカレードを設定しました）

    忍耐（必要に迫られている；私のプロバイダーから別のIPアドレスは取得していない）は、自由と洞察とは異なるサブネット上のIPアドレスを持ち、自由をインターネットゲートウェイとして使用する必要があります。さらに悪いことに、LANMANを含むほとんどのDOSネットワークソフトウェアは、ネットマスクと「デフォルトゲートウェイ」に完全に依存した非合理的なネットワークスキーマを持っています。これにより、自由や洞察に到達する際、忍耐はデフォルトゲートウェイを通じて送信することになります。自由と洞察（arc0eデバイスのおかげで）は直接送信を理解できるにもかかわらずです。

    その代わりに、自由にプライベートサブネット上の追加IPアドレス（別名「ゲートキーパー」）を割り当てます。これは忍耐と同じプライベートサブネット上にあります。次に、ゲートキーパーを忍耐のデフォルトゲートウェイとして定義します。

    自由の設定（上記のコマンドに加えて）:

    ifconfig arc0e gatekeeper
route add gatekeeper arc0e
route add patience arc0e

    この方法で、自由は忍耐のすべてのパケットをarc0e経由で送信し、プライベートサブネット上のゲートキーパーとしてIPアドレスを提供します。洞察やインターネットと通信する際には、「自由」のインターネット用IPアドレスを使用します。

    洞察にarc0eデバイスを設定していないことにご注意ください。これは動作しますが、実際には必要ありません。また、私のプライベートサブネットから洞察に別の特別なIPアドレスを割り当てる必要があります。しかし、洞察と忍耐がどちらも自由をデフォルトゲートウェイとしているため、すでに相互に通信可能です。

    最初にこのような設定をしたのは幸運でした（咳咳）。これはインサイトをDOSモードに起動するときに非常に便利です。その際、ノベルのODIプロトコルスタックが動作し、これはRFC1201 ARCnetにのみ対応します。このモードでは、ノベルスタックがマイクロソフトのイーサネットエンカプスと互換性がないため、インサイトが忍耐と直接通信することは不可能です。自由や忍耐の設定を変更せずに、インサイト（今やDOSモードのまま）のデフォルトゲートウェイを自由に設定するだけで、二つのホスト間で通常は通信できない状態でも「自動的に」転送されます。

    図解が好きな方のために、私は同じ物理的なARCnetワイヤー上に2つの「仮想サブネット」を作成しました。このようなイメージで考えてください:

        [RFC1201 NETWORK]                   [ETHER-ENCAP NETWORK]
(registered Internet subnet)           (RFC1597 private subnet)

                       (IP Masquerade)
    /---------------\         *            /---------------\
    |               |         *            |               |
    |               +-Freedom-*-Gatekeeper-+               |
    |               |    |    *            |               |
    \-------+-------/    |    *            \-------+-------/
            |            |                         |
         Insight         |                      Patience
                     (Internet)

メールであなたの設定を説明してください。できればドライバーバージョン、カーネルバージョン、ARCnetカードモデル、CPUタイプ、ネットワーク上のシステム数、使用中のソフトウェアリストを含めて、以下のアドレスに送ってください:

apenwarr@worldvisions.ca

私は受信したすべてのメッセージに対して（場合によっては自動化された）返信を送信します。私のメールアドレスは不思議な感じ（また、通常、さまざまな場所を経て私に届くため、転送されることが多い）なので、合理的な時間内に返信がない場合は、再度送信してください。

これは機能しない: 今後どうすればよいですか？¶

上記と同じ手順を実行するほか、ifconfigおよびrouteコマンドの出力結果、および関連するログエントリ（つまり、「arcnet:」で始まり、最後の再起動以降に表示されたすべての項目）をメールに含めてください。

自分で問題を解決しようとしたい場合は（問題の詳細をまず私にメールで報告することを強くお勧めします）、いくつかのデバッグレベルを試してみることを検討してください。D_DURINGまたはそれ以上の重いテストを行う場合は、まずklogdデーモンを終了させるのが非常に良い考えです。D_DURINGは各パケット送受信ごとに4〜5行の情報を表示します。D_TX、D_RX、D_SKBはパケットが送信または受信されるたびに実際に表示するため、明らかに情報量が大きいです。

v2.40 ALPHA以降、自動プローブルーチンが大幅に変更されました。特に、カードが見つからない理由を教えてくれるようになるのは、D_INIT_REASONSデバッグフラグを有効にした場合に限られます。

ドライバが動作している状態で、arcdumpシェルスクリプト（私から入手可能またはARCnetパッケージに含まれている場合）をroot権限で実行することで、いつでもarcnetバッファの内容を確認できます。この情報を理解するには、関連するRFCドキュメントを取得することをお勧めします（一部はarcnet.cの上部に記載されています）。arcdumpはカードが0xD0000に配置されていると仮定しています。配置位置が異なる場合は、スクリプトを編集してください。

バッファ0と1は受信用、バッファ2と3は送信用に使用されます。ピンポンバッファは両方向で実装されています。

デバッグレベルにD_DURINGが含まれており、SLOW_XMIT_COPYを定義していなければ、カードがリセットされるたびに（ifconfig upを実行するか、Linuxがドライバが破損していると判断した場合に限って発生します）バッファが0x42という定数に初期化されます。送信中にバッファの未使用部分も0x42にクリアされます。これは、パケットによって使用されているバイトを特定しやすくするためです。

カーネルを再コンパイルすることなくデバッグレベルを変更するには、以下を実行してください：

ifconfig arc0 down metric 1xxx
/etc/rc.d/rc.inet1

ここで「xxx」は希望するデバッグレベルです。たとえば、「metric 1015」はデバッグレベル15に設定します。現在のデフォルトはデバッグレベル7です。

デバッグレベルは（v1.90 ALPHAから）複数のデバッグフラグの二進法的な組み合わせで表されます。そのため、デバッグレベル7は実際には1+2+4（D_NORMAL+D_EXTRA+D_INIT）を意味します。D_DURINGを含めるには、この値に16を加えてデバッグレベル23にします。

その意味が分からなければ、おそらく知りたくないでしょう。問題があれば私にメールで連絡してください。
