1. 説明¶

TUN/TAPはユーザー空間のプログラムがパケットを受信および送信できるようにする機能を提供します。これは物理メディアからではなく、ユーザー空間のプログラムからパケットを受信し、物理メディアを通じてではなく、ユーザー空間のプログラムにパケットを書き出すことで、単純なポイントツーポイントまたはイーサネットデバイスと見なせます。

ドライバを使用するには、プログラムが/dev/net/tunを開き、対応するioctl()を実行してカーネルにネットワークデバイスを登録する必要があります。ネットワークデバイスは、選択したオプションによってtunXXまたはtapXXとして表示されます。プログラムがファイルディスクリプタを閉じると、ネットワークデバイスおよびすべての関連するルートが削除されます。

選択したデバイスの種類によって、ユーザー空間のプログラムはIPパケット（tun）を読み書きするか、イーサネットフレーム（tap）を読み書きする必要があります。使用するものは、ioctl()で指定されたフラグによって決まります。

パッケージから http://vtun.sourceforge.net/tun にはtunおよびtapデバイスの使用方法を示す2つの簡単な例が含まれています。どちらのプログラムも2つのネットワークインターフェース間のブリッジとして動作します。br_select.c - selectシステムコールを基にしたブリッジ。br_sigio.c - 非同期IOとSIGIOシグナルを基にしたブリッジ。ただし、最も良い例はVTunです http://vtun.sourceforge.net :))

2. 設定¶

デバイスノードを作成:

mkdir /dev/net (if it doesn't exist already)
mknod /dev/net/tun c 10 200

パーミッションを設定:

e.g. chmod 0666 /dev/net/tun

非rootユーザーがデバイスにアクセスできるようにしても問題ありません。なぜなら、ネットワークデバイスを作成するか、または所有権がユーザー自身でないネットワークデバイスに接続するにはCAP_NET_ADMINが必須だからです。非特権ユーザーにデバイスの所有権を付与して永続的なデバイスを作成する場合は、/dev/net/tunデバイスがそのユーザーに利用可能である必要があります。

ドライバモジュールの自動ロード

カーネルモジュールロー�ーダー - モジュール自動ロードサポートがカーネルに有効になっていることを確認してください。カーネルは最初のアクセス時にそれをロードする必要があります。

モジュールを手動で挿入:

modprobe tun

後者の方法で行う場合は、必要に応じて毎回モジュールをロードする必要があります。前者の方法で行うと、/dev/net/tunを開くときに自動的にロードされます。

3. プログラムインターフェース¶

3.1 ネットワークデバイスの割り当て¶

char *dev はデバイス名の形式文字列（例: "tun%d"）でなければなりませんが（私が見る限り）、これは有効なネットワークデバイス名のいずれでも構いません。注意点として、文字列ポインタは実際のデバイス名（例: "tun0"）に上書きされます：

#include <linux/if.h>
#include <linux/if_tun.h>

int tun_alloc(char *dev)
{
    struct ifreq ifr;
    int fd, err;

    if( (fd = open("/dev/net/tun", O_RDWR)) < 0 )
       return tun_alloc_old(dev);

    memset(&ifr, 0, sizeof(ifr));

    /* Flags: IFF_TUN   - TUN device (no Ethernet headers)
     *        IFF_TAP   - TAP device
     *
     *        IFF_NO_PI - Do not provide packet information
     */
    ifr.ifr_flags = IFF_TUN;
    if( *dev )
       strncpy(ifr.ifr_name, dev, IFNAMSIZ);

    if( (err = ioctl(fd, TUNSETIFF, (void *) &ifr)) < 0 ){
       close(fd);
       return err;
    }
    strcpy(dev, ifr.ifr_name);
    return fd;
}

3.2 フレーム形式¶

IFF_NO_PIフラグが設定されていない場合、各フレーム形式は:

Flags [2 bytes]
Proto [2 bytes]
Raw protocol(IP, IPv6, etc) frame.

3.3 マルチキュー tuntap インターフェース¶

Linuxカーネル3.8以降では、複数のファイルディスクリプタ（キュー）を用いてパケットの送受信を並列化できるマルチキューtuntapがサポートされています。デバイス割当は以前と同様で、ユーザーが複数のキューを作成したい場合は、TUNSETIFFを同じデバイス名で複数回呼び出し、IFF_MULTI_QUEUEフラグを指定する必要があります。

char *dev deviceはデバイス名、queuesは作成するキューの数を表し、fdsは作成されたファイルディスクリプタ（キュー）を呼び出し元に返します。各ファイルディスクリプタはキューインターフェースとしてユーザー空間からアクセス可能になります。

#include <linux/if.h>
#include <linux/if_tun.h>

int tun_alloc_mq(char *dev, int queues, int *fds)
{
    struct ifreq ifr;
    int fd, err, i;

    if (!dev)
        return -1;

    memset(&ifr, 0, sizeof(ifr));
    /* Flags: IFF_TUN   - TUN device (no Ethernet headers)
     *        IFF_TAP   - TAP device
     *
     *        IFF_NO_PI - Do not provide packet information
     *        IFF_MULTI_QUEUE - Create a queue of multiqueue device
     */
    ifr.ifr_flags = IFF_TAP | IFF_NO_PI | IFF_MULTI_QUEUE;
    strcpy(ifr.ifr_name, dev);

    for (i = 0; i < queues; i++) {
        if ((fd = open("/dev/net/tun", O_RDWR)) < 0)
           goto err;
        err = ioctl(fd, TUNSETIFF, (void *)&ifr);
        if (err) {
           close(fd);
           goto err;
        }
        fds[i] = fd;
    }

    return 0;
err:
    for (--i; i >= 0; i--)
        close(fds[i]);
    return err;
}

新しいioctl(TUNSETQUEUE)が導入され、キューの有効化/無効化を可能にしました。IFF_DETACH_QUEUEフラグで呼び出すとキューが無効化され、IFF_ATTACH_QUEUEフラグで呼び出すと有効化されます。TUNSETIFFで作成されたキューはデフォルトで有効化されます。

fdは有効化または無効化したいファイルディスクリプタ（キュー）で、enableがtrueの場合は有効化、falseの場合は無効化します:

#include <linux/if.h>
#include <linux/if_tun.h>

int tun_set_queue(int fd, int enable)
{
    struct ifreq ifr;

    memset(&ifr, 0, sizeof(ifr));

    if (enable)
       ifr.ifr_flags = IFF_ATTACH_QUEUE;
    else
       ifr.ifr_flags = IFF_DETACH_QUEUE;

    return ioctl(fd, TUNSETQUEUE, (void *)&ifr);
}

ユニバーサル TUN/TAP デバイスドライバ FAQ¶

  1. TUN/TAPドライバがサポートするプラットフォームはどれですか？

現在、以下の3つのUnix系OSでドライバが実装されています:

  • Linuxカーネル 2.2.x、2.4.x

  • FreeBSD 3.x、4.x、5.x

  • Solaris 2.6、7.0、8.0

  1. TUN/TAPドライバはどのような用途で使われますか？

上記のように、TUN/TAPドライバの主な目的はトンネリングです。VTun（http://vtun.sourceforge.net).

TUN/TAPを用いた別の興味深いアプリケーションはpipsecd（http://perso.enst.fr/~beyssac/pipsec/）で、FreeS/WANとは異なり完全なカーネルルーティングをサポートするユーザー空間でのIPsec実装です。

  1. 仮想ネットワークデバイスは実際にどのように動作しますか？

仮想ネットワークデバイスは、物理メディアからパケットを受信する代わりにユーザー空間のアプリケーションから受信し、物理メディア経由で送信する代わりにユーザー空間のアプリケーションに送信するシンプルなポイントツーポイントまたはイーサネットデバイスと見なせます。

tap0にIPv6を設定した場合、カーネルがtap0にIPv6パケットを送信すると、アプリケーション（例：VTun）に渡されます。アプリケーションはそのパケットを暗号化・圧縮し、TCPまたはUDPを介して他端に送信します。他端のアプリケーションは受信したデータを復号・解圧して、TAPデバイスにパケットを書き込み、カーネルはそのパケットが実際の物理デバイスから来たものとして処理します。

  1. TUNドライバとTAPドライバの違いは何ですか？

TUNはIPフレームを処理し、TAPはイーサネットフレームを処理します。

これは、TUNを使用する際にはIPパケットを読み書きし、TAPを使用する際にはイーサネットフレームを処理する必要がありますことを意味します。

  1. BPFとTUN/TAPドライバーの違いは何ですか？

BPFは高度なパケットフィルタです。既存のネットワークインターフェースに接続できます。仮想ネットワークインターフェースを提供しません。TUN/TAPドライバーは仮想ネットワークインターフェースを提供し、このインターフェースにBPFを接続することが可能です。

  1. TAPドライバーはカーネルのイーサネットブリッジングをサポートしていますか？

はい。LinuxとFreeBSDのドライバーはイーサネットブリッジングをサポートしています。
