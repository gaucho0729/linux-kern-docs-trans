radiotapヘッダの使用方法¶

radiotap includeファイルへのポインタ¶

radiotapヘッダは可変長で拡張可能であり、必要な情報は以下のドキュメントから得られます。

./include/net/ieee80211_radiotap.h

このドキュメントでは概要を説明し、一部の特殊なケースについて注意喚起しています。

ヘッダーの構造¶

ヘッダの先頭には固定部分があり、u32のビットマップが含まれており、各ビットに対応する引数が存在するかどうかを定義しています。したがって、ieee80211_radiotap_headerのit_presentメンバのb0ビットが設定されている場合、引数インデックス0（IEEE80211_RADIOTAP_TSFT）のヘッダが引数領域に存在することを意味します。

< 8-byte ieee80211_radiotap_header >
[ <possible argument bitmap extensions ... > ]
[ <argument> ... ]

現在は13の引数インデックスが定義されていますが、u32のit_presentメンバにスペースが不足した場合、b31ビットが設定されていると次のu32ビットマップが続くことを示し（上記の「可能な引数ビットマップ拡張…」参照）、引数の開始位置は毎回4バイトずつ進みます。

it_lenメンバの__le16は、ieee80211_radiotap_headerとその後の引数が占めるバイト数の合計を設定します。

引数の要件¶

固定部分の後には、it_presentメンバの対応するビットが設定されている各引数インデックスの引数が続きます。

  • すべての引数はリトルエンディアンで保存されています！

  • 特定の引数インデックスの引数ペイロードは固定長です。したがって、IEEE80211_RADIOTAP_TSFTが存在する場合、常に8バイトの引数が存在します。すべての引数サイズの詳細な分解については、./include/net/ieee80211_radiotap.hのコメントを参照してください。

  • 引数は引数サイズの境界にアライメントされ、パディングで調整されます。u16の引数はすでに境界にない場合、次のu16境界から開始する必要があります。u32は次のu32境界、といった具合です。

  • 「アライメント」はieee80211_radiotap_headerの開始位置（つまり、radiotapヘッダの最初のバイト）に対して相対的です。最初のバイトの絶対的なアライメントは定義されていません。したがって、radiotapヘッダが例えばアドレス0x00000003から始まっても、アライメント処理では最初のバイトを0と扱います。

  • 固定のradiotapヘッダーや引数領域においてマルチバイトエンティティの絶対アライメントが保証されないという点は、これらのマルチバイトエンティティにアクセスする際に特別な回避策を講じる必要があることを意味します。Blackfinなどの一部のアーキテクチャでは、奇数アドレスを指すu16ポインタのデリファレンスを試みる行為を処理できません。その代わりに、アーキテクチャが要求する場合にデリファレンスを行うため、カーネルAPIのget_unaligned()を使用する必要があります。

  • 特定の引数インデックスに対応する引数は複数の型が組み合わさったものになることがあります。例えばIEEE80211_RADIOTAP_CHANNELは、合計長さ4の2つのu16からなるペイロードを持つ引数を持っています。このような場合、u16を扱うためのパディングルールが適用され、4バイト単位のエンティティを扱うのではなく、u16を扱うルールが適用されます。

有効なradiotapヘッダーの例¶

0x00, 0x00, // <-- radiotap version + pad byte
0x0b, 0x00, // <- radiotap header length
0x04, 0x0c, 0x00, 0x00, // <-- bitmap
0x6c, // <-- rate (in 500kHz units)
0x0c, //<-- tx power
0x01 //<-- antenna

Radiotapパーサーの使用方法¶

radiotap構造体を解析する必要がある場合は、net/wireless/radiotap.cに存在するradiotapパーサーを使用することで作業を大幅に簡略化できます。プロトタイプはinclude/net/cfg80211.hで利用可能です。使用方法は以下の通りです：

#include <net/cfg80211.h>

/* buf points to the start of the radiotap header part */

int MyFunction(u8 * buf, int buflen)
{
        int pkt_rate_100kHz = 0, antenna = 0, pwr = 0;
        struct ieee80211_radiotap_iterator iterator;
        int ret = ieee80211_radiotap_iterator_init(&iterator, buf, buflen);

        while (!ret) {

                ret = ieee80211_radiotap_iterator_next(&iterator);

                if (ret)
                        continue;

                /* see if this argument is something we can use */

                switch (iterator.this_arg_index) {
                /*
                * You must take care when dereferencing iterator.this_arg
                * for multibyte types... the pointer is not aligned.  Use
                * get_unaligned((type *)iterator.this_arg) to dereference
                * iterator.this_arg for type "type" safely on all arches.
                */
                case IEEE80211_RADIOTAP_RATE:
                        /* radiotap "rate" u8 is in
                        * 500kbps units, eg, 0x02=1Mbps
                        */
                        pkt_rate_100kHz = (*iterator.this_arg) * 5;
                        break;

                case IEEE80211_RADIOTAP_ANTENNA:
                        /* radiotap uses 0 for 1st ant */
                        antenna = *iterator.this_arg);
                        break;

                case IEEE80211_RADIOTAP_DBM_TX_POWER:
                        pwr = *iterator.this_arg;
                        break;

                default:
                        break;
                }
        }  /* while more rt headers */

        if (ret != -ENOENT)
                return TXRX_DROP;

        /* discard the radiotap header part */
        buf += iterator.max_length;
        buflen -= iterator.max_length;

        ...

}
