はじめに:¶

このモジュールは、ディスクログが失敗した場合やシリアルコンソールが実用的でない場合に、UDP を使ってカーネルの printk メッセージをログとして送信し、デバッグを可能にします。

この機能は、組み込みモードまたはモジュールとして使用できます。組み込みモードでは、ネットワークインターフェースカード（NIC）が初期化された後すぐに netconsole が初期化され、指定されたインターフェースが可能な限り早急に起動します。これにより、初期のカーネルパニックのキャプチャはできませんが、ほとんどのブートプロセスをキャプチャできます。

送信者と受信者の設定:¶

netconsole は、以下の形式の文字列構成パラメータ「netconsole」を受け取ります：

netconsole=[+][src-port]@[src-ip]/[<dev>],[tgt-port]@<tgt-ip>/[tgt-macaddr]

  where
       +             if present, enable extended console support
       src-port      source for UDP packets (defaults to 6665)
       src-ip        source IP to use (interface address)
       dev           network interface (eth0)
       tgt-port      port for logging agent (6666)
       tgt-ip        IP address for logging agent
       tgt-macaddr   ethernet MAC address for logging agent (broadcast)

例:

linux netconsole=4444@10.0.0.1/eth1,9353@10.0.0.2/12:34:56:78:9a:bc

または:

insmod netconsole netconsole=@/,@10.0.0.2/

IPv6 を使用する場合：

insmod netconsole netconsole=@/,@fd00:1:2:3::1/

また、複数のリモートエージェントにログを送信する場合、セミコロンで複数のエージェントのパラメータを区切り、全体を「クォート」で囲むことで指定できます：

modprobe netconsole netconsole="@/,@10.0.0.2/;@/eth1,6892@10.0.0.3/"

組み込みの netconsole は、TCP スタックが初期化された後すぐに起動し、指定されたデバイスを指定されたアドレスで起動を試みます。

リモートホストは、カーネルメッセージを受信するためのいくつかのオプションがあります。例えば：

  1. syslogd

  2. netcat

    BSD 基盤の netcat バージョン（例: Fedora、openSUSE、Ubuntu）を使用するディストリビューションでは、-p オプションを使わず、リスニングポートを明示的に指定する必要があります：

        nc -u -l -p <port>' / 'nc -u -l <port>

or::

    netcat -u -l -p <port>' / 'netcat -u -l <port>

  3. socat

socat udp-recv:<port> -

動的再構成:¶

動的再構成性は netconsole に有用な機能で、configfs 基盤のユーザー空間インターフェースから、実行時においてリモートログ目標を動的に追加、削除、またはパラメータを再構成することが可能です。[注意: ブート時またはモジュールオプションで指定・作成された netconsole ターゲットのパラメータは、このインターフェースを通じて露出されず、動的に変更することはできません。]

この機能を含めるには、netconsole モジュール（または netconsole が組み込まれているカーネル）をビルドする際、CONFIG_NETCONSOLE_DYNAMIC を選択してください。

以下にいくつかの例を示します（configfs が /sys/kernel/config にマウントされている場合）。

リモートログ目標を追加するには（ターゲット名は任意）：

cd /sys/kernel/config/netconsole/
mkdir target1

新たに作成されたターゲットは、上記で述べたようにデフォルトのパラメータ値を持ち、デフォルトでは無効になっています。これらは、以下の説明のようにパラメータを設定した後、'enabled' 属性に '1' を書き込むことで有効化する必要があります。

ターゲットを削除するには：

rmdir /sys/kernel/config/netconsole/othertarget/

インターフェースは netconsole ターゲットの以下のパラメータをユーザー空間に公開します：

enabled

このターゲットは現在有効ですか？

(読み取り/書き込み)

extended

拡張モードが有効化されています

(読み取り/書き込み)

dev_name

ローカルネットワークインターフェース名

(読み取り/書き込み)

ローカルポート

使用するソースUDPポート

(読み取り/書き込み)

リモートポート

リモートエージェントのUDPポート

(読み取り/書き込み)

ローカルIP

使用するソースIPアドレス

(読み取り/書き込み)

リモートIP

リモートエージェントのIPアドレス

(読み取り/書き込み)

(読み取り専用)

ローカルMAC

(読み取り専用)

リモートMAC

リモートエージェントのMACアドレス

(読み取り/書き込み)

「有効」属性は、ターゲットのパラメータを更新するかどうかを制御するために使用されます。無効化されたターゲット（つまり、「有効」が0の場合）のパラメータのみを変更できます。

ターゲットのパラメータを更新するには:

cat enabled                            # check if enabled is 1
echo 0 > enabled                       # disable the target (if required)
echo eth2 > dev_name                   # set local interface
echo 10.0.0.4 > remote_ip              # update some parameter
echo cb:a9:87:65:43:21 > remote_mac    # update more parameters
echo 1 > enabled                       # enable target again

ローカルインターフェースを動的に更新することもできます。これは、netconsoleがロード/初期化されたときに存在しなかった新しいインターフェースを使用したい場合に特に役立ちます。

拡張コンソール:¶

「+」が構成行の前に付いているか、または「extended」構成ファイルが1に設定されている場合、拡張コンソールサポートが有効になります。例示的なブートパラメータは次のとおりです:

linux netconsole=+4444@10.0.0.1/eth1,9353@10.0.0.2/12:34:56:78:9a:bc

ログメッセージは、次の形式の拡張メタデータヘッダーで送信されます。これは/dev/kmsgと同じ形式です:

<level>,<sequnum>,<timestamp>,<contflag>;<message text>

メッセージテキスト内の非印刷文字は「xff」表記でエスケープされます。メッセージにオプションの辞書が含まれる場合、バイトリテールニューラインがデリミタとして使用されます。

メッセージが特定のバイト数（現在は1000）に収まらない場合、netconsoleはメッセージを複数のフラグメントに分割します。これらのフラグメントは「ncfrag」ヘッダー場を追加して送信されます:

ncfrag=<byte-offset>/<total-bytes>

例えば、非常に小さなチャンクサイズを仮定すると、メッセージ「the first chunk, the 2nd chunk.」は次のようになります:

6,416,1758426,-,ncfrag=0/31;the first chunk,
6,416,1758426,-,ncfrag=16/31; the 2nd chunk.

その他の注意点:¶

警告

デフォルトのターゲットイーサネット設定は、ブロードキャストイーサネットアドレスを使用してパケットを送信します。これにより、同じイーサネットセグメントにある他のシステムへの負荷が増加する可能性があります。

ヒント

一部のLANスイッチがイーサネットブロードキャストを抑制するように設定されている場合、netconsoleに渡す構成パラメータでリモートエージェントのMACアドレスを明示的に指定することをお勧めします。

ヒント

例えば、10.0.0.2のMACアドレスを確認するには、次のコマンドを使用できます:

ping -c 1 10.0.0.2 ; /sbin/arp -n | grep 10.0.0.2

ヒント

リモートログエージェントが送信元とは別のLANサブネットにある場合、デフォルトゲートウェイのMACアドレス（/sbin/route -nを使用して確認できます）をリモートMACアドレスとして指定することをお勧めします。

注意

ネットワークデバイス（上記例ではeth1）は他のネットワークトラフィックを実行できます。netconsoleは侵入的ではありません。カーネルメッセージのボリュームが高いため、他のトラフィックにわずかな遅延を引き起こす可能性がありますが、他の影響はないと考えられます。

注意

リモートログインエージェントが送信元からのすべてのメッセージを受信または印刷していない場合、送信元で「console_loglevel」パラメータを設定してコンソールにのみ高優先度のメッセージを送信するように設定している可能性があります。これを実行時に行うには以下のコマンドを使用できます:

dmesg -n 8

または、起動時にカーネルコマンドラインで「debug」を指定して、すべてのカーネルメッセージをコンソールに送信することもできます。このパラメータには「loglevel」カーネル起動オプションを使用して特定の値を設定することも可能です。dmesg(8)のmanページを参照してください。 カーネルのコマンドラインパラメータ 詳しくは以下をご参照ください。

Netconsoleは、最も深刻なカーネルのバグを記録できるように、可能な限り即時性を重視して設計されています。IRQコンテキストからも動作し、パケットを送信中に割込みを有効にしていません。これらの特殊なニーズにより、設定はより自動化できません。基本的な制限として、IPネットワーク、UDPパケット、イーサネットデバイスのみがサポートされます。
