SB100デバイスドライバ¶

sb1000は、General Instrument（NextLevelとしても知られる）SURFboard1000内部ケーブルモデムボード用のモジュールネットワークデバイスドライバーです。これはISAカードであり、ケーブルテレビ会社がケーブルモデム接続を提供するために使用されます。これは1方向のダウンストリーム専用ケーブルモデムであり、アップストリームネットリンクは通常の電話モデムで提供されます。

このドライバーはFranco Venturi氏によって書かれました <fventuri@mediaone.net>. この素晴らしいコードには、大変感謝すべきです！

必要なツール¶

このデバイスのサポートは現在、標準のLinuxカーネルに含まれています。ドライバーのソースコードファイルはdrivers/net/sb1000.cです。これに加えて必要なのは：

  1. 「cmconfig」プログラム。これは「ifconfig」を補完してケーブルモデムおよびネットワークインターフェース（通常「cm0」と呼ばれる）を設定するユーティリティです；

  2. いくつかのPPPスクリプトで、/etc/pppに配置されており、ケーブルモデム経由での接続を簡単にします。

    これらのユーティリティは以下から取得できます：

    http://www.jacksonville.net/~fventuri/

    Francoのオリジナルソースコード配布ファイル.tar.gz内にあります。sb1000ドライバーのサポートは以下にあります：

    • http://web.archive.org/web/%2E/http://home.adelphia.net/~siglercm/sb1000.html

    • http://web.archive.org/web/%2E/http://linuxpower.cx/~cable/

    これらのユーティリティとともに。

  3. 標準のisapnpツール。これらはSB1000カードを起動時（またはその後手動で）設定するために必要です。これはPnPカードです。

    これらのツールがLinuxディストリビューションの標準でインストールされていない場合、以下から取得できます：

    http://www.roestock.demon.co.uk/isapnptools/

    またはLinuxディストリビューションバイナリCDまたはそのウェブサイトを確認してください。isapnp、pnpdump、または/etc/isapnp.confに関するサポートが必要な場合は、以下にアクセスしてください：

    http://www.roestock.demon.co.uk/isapnptools/isapnpfaq.html

ドライバーの使用方法¶

SB1000カードを動作させるには、以下の手順を実行してください：

  1. 実行 make config（sleepable RCU）が導入されました。 make menuconfig（sleepable RCU）が導入されました。 make xconfigどちらか好きな方を、トップカーネルツリーのディレクトリに移動してカーネル構成を設定してください。必ず「Prompt for development drivers」に「Y」を選び、「sb1000ドライバー」に「M」を選び、TCP/IPおよびPPPネットワークサポートを得るために標準的なネットワーキング質問すべてに「Y」または「M」を選びます。

  2. BEFORE カーネルをビルドする前に、drivers/net/sb1000.cを編集してください。READ_DATA_PORTの値をisapnpがPnPカードにアクセスするI/Oアドレスに再定義してください。これは/etc/isapnp.confのREADPORTの値またはpnpdumpの出力で与えられます。

  3. カーネルとモジュールを通常通りビルドしてインストールしてください。

  4. 新しいカーネルを通常の手順に従って起動してください。

  5. 新しいSB1000 PnPカードを設定するには、「pnpdump」の出力をファイルにキャプチャし、このファイルを編集して、すべてのPnPカードの正しいI/Oポート、IRQ、DMA設定を設定してください。設定が互いに衝突しないように確認してください。その後、「isapnp」コマンドを新しい設定ファイルを入力として実行してこの設定をテストしてください。エラーを確認し、必要に応じて修正してください。(余談ですが、私はSB1000カードにI/Oポート0x110と0x310、IRQ 11を使用しており、これらは私の環境ではうまく動作します。状況により異なります。) 最後に、完了した設定ファイルを/etc/isapnp.confに保存し、再起動時に正しく設定されるようにしてください。

  6. Francoのサイトや上記の他の参照先から元ファイルsb1000-1.1.2.tar.gzをダウンロードしてください。root権限で、一時ディレクトリに解凍し、以下の操作を行ってください。 make cmconfig を呼び出し、その後 install -c cmconfig /usr/local/sbin実行しないでください make install これはすべてのユーティリティがビルド済みでインストール準備ができていることを期待しているため、単にcmconfigだけをインストールするためのものではありません。

  7. root権限で、Francoのtarファイル内のppp/サブディレクトリにあるすべてのファイルを/etc/pppにコピーしてください。既に存在するファイルを上書きしないように注意してください。その後、 ppp@gi-on を編集し、ケーブルモデムの正しいログイン名、電話番号、および周波数を設定してください。また、pap-secretsを編集して、ログイン名とパスワード、および必要なサイト固有の情報を指定してください。

  8. /etc/ppp/firewallを編集し、古い2.0.xカーネルのipfwadmコマンドではなくipchainsを使用するようにしてください。ipfwadmコマンドをipchainsコマンのに変換するユーティリティがあります:

    http://users.dhp.com/~whisper/ipfwadm2ipchains/

    また、ファイアウォールスクリプトを変更して、異なるファイアウォールスキームを実装することも検討してください。

  9. PPP接続をスクリプト /etc/ppp/ppp@gi-onで開始してください。この操作を行うにはroot権限が必要です。このような頻繁に使用するコマンドは、sudoなどのユーティリティを使用してroot権限で実行することをお勧めします。接続に成功すると、ケーブルモデムインターフェースがアップになり、コンソールにドライバメッセージが表示されます:

    cm0: sb1000 at (0x110,0x310), csn 1, S/N 0x2a0d16d8, IRQ 11.
sb1000.c:v1.1.2 6/01/98 (fventuri@mediaone.net)

    「ifconfig」コマンドで、2つの新しいインターフェース、ppp0とcm0が表示されることを確認してください。

    「cmconfig cm0」コマンドで、ケーブルモデムインターフェースに関する情報を取得できます。

  10. 例えば、以下のサイト経由でpingを試してください。 ping -c 5 www.yahoo.comパケットが受信されるはずです。

  11. サイト名（例：www.yahoo.com）がIPアドレス（例：204.71.200.67）に解決できない場合は、/etc/resolv.confファイルに構文エラーがないことと、正しい名前解決サーバーのIPアドレスが含まれていることを確認してください。それでも解決しない場合は、以下のコマンドを試してみてください: ping -c 5 204.71.200.67 ネットワークが動作しているが、DNS解決が問題の原因である可能性があるため、確認してください。

  12. 問題が解決しない場合は、上記のサポートWebサイトにアクセスし、その場所にある情報を読みましょう。

一般的な問題¶

  1. パケットはppp0インターフェースから出ますが、cm0インターフェースから戻ってきません。私は接続されているように見えますが、数値のIPアドレスにすらpingできません。(これはDebianシステムでデフォルトのブート時の設定スクリプトのため、主に発生します。)

解決策

rootとして echo 0 > /proc/sys/net/ipv4/conf/cm0/rp_filter ppp0インターフェースと同じIPアドレスを共有できるようにします。このコマンドはおそらく/etc/ppp/cablemodemスクリプトに追加すべきです right*between 「/sbin/ifconfig」と「/sbin/cmconfig」コマンドの間に配置してください。/proc/sys/net/ipv4/conf/ppp0/rp_filterにも同様の処理が必要かもしれません。もし各再起動時に/proc/sys/net/ipv4/conf/default/rp_filterにこの処理を行っていれば、すべてのインターフェースが同じIPアドレスを共有できます。

  1. 実行時に「unresolved symbol」のエラーメッセージが表示されます insmod sb1000.o.

解決策

おそらく非対応のカーネルソースツリーと/usr/include/linuxおよび/usr/include/asmヘッダーファイルを使用しています。これらのディレクトリに正しいバージョンのヘッダーファイルをインストールし、その後カーネルを再構築して再インストールしてください。

  1. isapnpが実行されるとエラーが報告され、SB1000カードが動作しません。

解決策

isapnpの後続バージョンでは、SB1000カードの2つのI/Oアドレスを割り当てる行に「(CHECK)」オプションが問題を引き起こしています。これは最初にRH 6.0で発生しました。SB1000のI/Oアドレスに「(CHECK)」を削除してください。他のハードウェアと競合しないことを確認した上で、isapnpを再実行してください。

  1. 実行できません /etc/ppp/ppp@gi-on ファイル。

解決策

rootとして実行してください chmod ug+x /etc/ppp/ppp@gi-on.

  1. ファイアウォールスクリプトが動作しません(2.2.x以降のカーネルで)

解決策

上記のipfwadm2ipchainsスクリプトを使用して、/etc/ppp/firewallスクリプトを非推奨のipfwadmコマンドからipchainsに変換してください。

  1. 以下の通り tons /var/kern.log、/var/messages、および/または/var/syslogファイルにファイアウォールのdenyメッセージが大量に表示され、/varパーティションが満杯になっています！！！

解決策

まず、ISPにDoS(サービス拒否)および/またはポートスキャン(UDP接続試行)攻撃を受けていることを伝えましょう！denyメッセージを確認して攻撃の種類と発信元を特定してください。次に、/etc/ppp/cablemodemを編集し、「,nobroadcast」オプションを「cmconfig」コマンドに有効にしてください(その行をコメント解除)。broadcastインターフェース(IPアドレスxxx.yyy.zzz.255など)でこれらの拒否パケットを受信しない場合は、誰かが特定のマシンを攻撃している可能性があります。注意してください…。

  1. 動作は問題ないようですが、時間が経つとコンピュータがフリーズしてしまいます（特にケーブルモデムを通じた長時間のダウンロード中に起こりやすいです）！

解決策

ドライバーに短い遅延を追加することでSURFboardを「遅く」する必要があります。あなたのPCがSB1000の転送速度に追いつかない可能性があるためです。これを実行するには、Francoのsb1000-1.1.2.tar.gzアーカイブをダウンロードし、手動でsb1000.oをビルドしてインストールするのが良いでしょう。'Makefile'を編集し、'SB1000_DELAY'の定義を探してください。'CFLAGS'行をアンコメント（デフォルトの行をコメントアウト）し、'-DSB1000_DELAY=60'のように60マイクロ秒に遅延を設定して試してください。その後、 make rootとして実行してください make install を実行して試してください。それでも動作しない場合やドライバーをいじるのが好きな場合は、他の数字を試してみてください。ただし、遅延が高いほどドライバーが遅くなり（ドライバーがアクティブに使用される際にはPC全体も遅くなるため）、注意が必要です。このヒントはEd Daiga氏に感謝します。
