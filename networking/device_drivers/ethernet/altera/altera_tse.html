Altera Triple-Speed Ethernet MACドライバ¶

著作権 © 2008-2014 Altera Corporation

これは、SGDMAおよびMSGDMAソフトDMA IPコンポーネントを使用したAltera Triple-Speed Ethernet (TSE) コントローラー用のドライバです。このドライバはプラットフォームバスを使用してコンポーネントリソースを取得します。このドライバをテストした設計は、Cyclone(R) V SOC FPGAボード、Cyclone(R) V FPGAボードで構築され、ARMおよびNIOSプロセッサホストで個別にテストされました。予想される使用ケースは、埋め込みシステムと外部のペア間での簡単な通信で、埋め込みシステムのステータスや簡単な設定のやり取りです。

詳細についてはwww.altera.comおよびwww.rocketboards.orgをご覧ください。ドライバのサポートフォーラムはwww.rocketboards.orgにあり、このドライバをテストした設計も同サイトに掲載されています。また、このドライバのメンテナはMAINTAINERSに記載されています。

Triple-Speed Ethernet、SGDMA、MSGDMAコンポーネントはすべてソフトIPコンポーネントであり、Altera Quartusツールチェーンを使用してFPGAに組み立てて構築できます。このドライバをテストした設計はQuartus 13.1および14.0で構築されました。sopc2dtsツールはドライバのデバイスツリーを作成するために使用され、rocketboards.orgで確認できます。

ドライバのプローブ関数はデバイスツリーを検査し、Triple-Speed EthernetインスタンスがSGDMAまたはMSGDMAコンポーネントを使用しているかを判定します。プローブ関数はその後、それぞれの構成に対応するDMAルーチンをインストールし、初期化、送信/受信設定、割込みハンドリングのプリミティブをセットアップします。

SGDMAコンポーネントは、今後1〜2年以内にMSGDMAコンポーネントに置き換えられることになっています（2014年初頭の執筆時点）。既存の設計およびリファレンスとしてSGDMAのサポートは含まれています。開発者が独自のソフトDMA論理とドライバサポートを実装したい場合に備えており、新しい設計ではSGDMAを使用すべきではありません。

SGDMAは1回の送信または受信操作のみをサポートしており、MSGDMAソフトIPに比べてパフォーマンスが劣ります。詳しくはwww.altera.comをご覧ください。

SGDMAまたはMSGDMAでのスキャッターガather DMAは現在サポートされていません。スキャッターガather DMAは今後のメンテナンスアップデートでこのドライバに追加される予定です。

ジャンボフレームは現在はサポートされていません。

ドライバはPHY操作を10/100Mbpsに制限しており、1Gbpsでの完全なテストはまだ行われていません。このサポートは今後のメンテナンスアップデートで追加される予定です。

1. カーネル設定¶

カーネル設定オプションはALTERA_TSEです：

デバイスドライバ —> ネットワークデバイスサポート —> イーサネットドライバサポート —> Altera Triple-Speed Ethernet MACサポート (ALTERA_TSE)

2. ドライバパラメータ一覧¶

  • debug: メッセージレベル (0: 出力なし、16: 全て);

  • dma_rx_num: RXリストのディスクリプタ数 (デフォルトは64);

  • dma_tx_num: TXリストのディスクリプタ数 (デフォルトは6,4);

3. コマンドラインオプション¶

ドライバパラメータはコマンドライン引数で渡すことも可能です。

altera_tse=dma_rx_num:128,dma_tx_num:512

4. ドライバ情報および注意点¶

4.1. 送信プロセス¶

ドライバの送信ルーチンがカーネルから呼び出される際、下位のDMA送信ルーチン (SGDMAまたはMSGDMA) を呼び出して送信ディスクリプタを設定し、送信操作を開始します。送信が完了すると、送信DMAロジックが割り込みを生成します。ドライバは割り込みハンドリングチェーンのコンテキストで送信完了を処理し、送信および要求された送信操作の追跡に必要なリソースを再利用します。

4.2. 受信プロセス¶

ドライバは初期化時に受信バッファを受信DMAロジックにポストします。受信バッファは、下位のDMAロジック (MSGDMAは受信バッファをキューイング可能ですが、SGDMAはSGDMA受信ロジックにキューイングできません) に応じてキューイングされる場合があります。パケットが受信されると、DMAロジックが割り込みを生成します。ドライバはDMA受信ロジックのステータスを取得し、受信完了を再集約するまで割り込みを処理します。

4.3. 割り込み軽減¶

ドライバは受信操作においてNAPIを用いてDMA割り込みの数を軽減可能です。送信操作における割り込み軽減はまだサポートされていませんが、今後のメンテナンスリリースで追加される予定です。

4.4) Ethtoolサポート¶

Ethtoolはサポートされています。ドライバ統計情報や内部エラーは「ethtool -S ethX」コマンドで取得可能です。レジスタのダンプなども可能です。

4.5) PHYサポート¶

ドライバはPALと互換性があり、PHYおよびGPHYデバイスと動作可能です。

5. デバッグ情報¶

ドライバは内部統計情報、デバッグ情報、MAC および DMA レジスタなど、デバッグ情報をエクスポートします。

ユーザーは ethtool のサポートを使用して統計情報を取得できます。たとえば、ethtool -S ethX を使用して（統計カウンタを表示）または ethtool -d ethX を使用して MAC レジスタを確認できます。

開発者は「debug」モジュールパラメータを使用してさらに詳細なデバッグ情報を取得することもできます。

6. 統計情報サポート¶

コントローラーおよびドライバは、IEEE 標準で定義された統計情報、RFC で定義された統計情報、ドライバまたは Altera で定義された統計情報をサポートしています。これらの統計情報の標準定義を含む4つの仕様は以下の通りです。

  • IEEE 802.3-2012 - IEEE Ethernet 標準

  • RFC 2863 は以下に記載 http://www.rfc-editor.org/rfc/rfc2863.txt.

  • RFC 2819 は以下に記載 http://www.rfc-editor.org/rfc/rfc2819.txt.

  • Altera Triple Speed Ethernet User Guide は以下に記載 http://www.altera.com

TSE およびデバイスドライバでサポートされる統計情報は以下の通りです。

「tx_packets」は IEEE 802.3-2012、セクション 5.2.2.1.2 で定義される aFramesTransmittedOK と同等です。この統計情報は、成功裏に送信されたフレームのカウントを示します。

「rx_packets」は IEEE 802.3-2012、セクション 5.2.2.1.5 で定義される aFramesReceivedOK と同等です。この統計情報は、成功裏に受信されたフレームのカウントを示します。これは CRC エラー、長さエラー、またはアライメントエラーなどのエラーパケットを含みません。

「rx_crc_errors」は IEEE 802.3-2012、セクション 5.2.2.1.6 で定義される aFrameCheckSequenceErrors と同等です。この統計情報は、フレームが受信される際の CRC テストに失敗した、整数バイト長のフレームのカウントを示します。

「rx_align_errors」は IEEE 802.3-2012、セクション 5.2.2.1.7 で定義される aAlignmentErrors と同等です。この統計情報は、フレームが受信される際の CRC テストに失敗した、整数バイト長でないフレームのカウントを示します。

「tx_bytes」は IEEE 802.3-2012、セクション 5.2.2.1.8 で定義される aOctetsTransmittedOK と同等です。この統計情報は、インターフェースから成功裏に送信されたデータおよびパディングバイトのカウントを示します。

「rx_bytes」は IEEE 802.3-2012、セクション 5.2.2.1.14 で定義される aOctetsReceivedOK と同等です。この統計情報は、コントローラーによって成功裏に受信されたデータおよびパディングバイトのカウントを示します。

「tx_pause」は、IEEE 802.3-2012、第30章3.4.2節に定義された「aPAUSEMACCtrlFramesTransmitted」と同等です。この統計は、ネットワークコントローラーから送信されたPAUSEフレームの数をカウントします。

「rx_pause」は、IEEE 802.3-2012、第30章3.4.3節に定義された「aPAUSEMACCtrlFramesReceived」と同等です。この統計は、ネットワークコントローラーに到達したPAUSEフレームの数をカウントします。

「rx_errors」は、RFC 2863に定義された「ifInErrors」と同等です。この統計は、パケットにエラーが含まれており、上位プロトコルに届けられなかったパケットの数をカウントします。

「tx_errors」は、RFC 2863に定義された「ifOutErrors」と同等です。この統計は、エラーにより送信できなかったパケットの数をカウントします。

「rx_unicast」は、RFC 2863に定義された「ifInUcastPkts」と同等です。この統計は、ブロードキャストアドレスやマルチキャストグループに宛てられていないパケットの数をカウントします。

「rx_multicast」は、RFC 2863に定義された「ifInMulticastPkts」と同等です。この統計は、マルチキャストアドレスグループに宛てられたパケットの数をカウントします。

「rx_broadcast」は、RFC 2863に定義された「ifInBroadcastPkts」と同等です。この統計は、ブロードキャストアドレスに宛てられたパケットの数をカウントします。

「tx_discards」は、RFC 2863に定義された「ifOutDiscards」と同等です。この統計は、エラーが検出されなかったにもかかわらず送信されなかった出力パケットの数を表します。内部バッファスペースを確保するなどの理由で発生する場合があります。

「tx_unicast」は、RFC 2863に定義された「ifOutUcastPkts」と同等です。この統計は、マルチキャストグループやブロードキャストアドレスに宛てられていないパケットの数をカウントします。

「tx_multicast」は、RFC 2863に定義された「ifOutMulticastPkts」と同等です。この統計は、マルチキャストグループに宛てられたパケットの数をカウントします。

「tx_broadcast」は、RFC 2863に定義された「ifOutBroadcastPkts」と同等です。この統計は、ブロードキャストアドレスに宛てられたパケットの数をカウントします。

「ether_drops」は、RFC 2819に定義された「etherStatsDropEvents」と同等です。この統計は、内部コントローラーのリソース不足によりドロップされたパケットの数をカウントします。

「rx_total_bytes」は、RFC 2819に定義された「etherStatsOctets」と同等です。この統計は、コントローラーに到達した全バイト数（エラーおよびドロップされたパケットを含む）をカウントします。

「rx_total_packets」はRFC 2819で定義されたetherStatsPktsに相当します。この統計情報は、コントローラーによって受信された全パケット数（エラー、破棄、ユニキャスト、マルチキャスト、ブロードキャストパケットを含む）をカウントします。

「rx_undersize」はRFC 2819で定義されたetherStatsUndersizePktsに相当します。この統計情報は、64バイト未満で正しく形成されたパケット数をカウントします。

「rx_oversize」はRFC 2819で定義されたetherStatsOversizePktsに相当します。この統計情報は、1518バイトを超える正しく形成されたパケット数をカウントします。

「rx_64_bytes」はRFC 2819で定義されたetherStatsPkts64Octetsに相当します。この統計情報は、64オクテット長さのパケット数をカウントします。

「rx_65_127_bytes」はRFC 2819で定義されたetherStatsPkts65to127Octetsに相当します。この統計情報は、65オクテットから127オクテットまでの長さのパケット数をカウントします。

「rx_128_255_bytes」はRFC 2819で定義されたetherStatsPkts128to255Octetsに相当します。この統計情報は、128オクテットから255オクテットまでの長さのパケット数をカウントします。

「rx_256_511_bytes」はRFC 2819で定義されたetherStatsPkts256to511Octetsに相当します。この統計情報は、256オクテットから511オクテットまでの長さのパケット数をカウントします。

「rx_512_1023_bytes」はRFC 2819で定義されたetherStatsPkts512to1023Octetsに相当します。この統計情報は、512オクテットから1023オクテットまでの長さのパケット数をカウントします。

「rx_1024_1518_bytes」はRFC 2819で定義されたetherStatsPkts1024to1518Octetsに相当します。この統計情報は、1024オクテットから1518オクテットまでの長さのパケット数をカウントします。

「rx_gte_1519_bytes」はAltera TSEの動作に特有の統計情報です。この統計情報は、frm_lengthレジスタで設定された最大フレーム長さまでの間、1519オクテット以上で受信した正常なフレームおよびエラーフレームの数をカウントします。詳細については、Altera TSE User Guideを参照してください。

「rx_jabbers」はRFC 2819で定義されたetherStatsJabbersに相当します。この統計情報は、1518オクテットを超える長さのパケット数をカウントし、そのうちCRCエラー（整数オクテット数の不良CRC）またはアライメントエラー（非整数オクテット数の不良CRC）を含みます。

「rx_runts」はRFC 2819で定義された「etherStatsFragments」と同等です。この統計値は、64オクテット未満の長さで、整数のオクテット数のCRCエラー（CRCエラー）または非整数のオクテット数のCRCエラー（アライメントエラー）を持つパケットの合計数を示します。
