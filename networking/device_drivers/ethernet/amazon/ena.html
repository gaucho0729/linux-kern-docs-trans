Linuxカーネルドライバー for Elastic Network Adapter (ENA) ファミリ¶

概要¶

ENAは、現代のCPU機能とシステムアーキテクチャを効率的に活用するためのネットワークインターフェースとして設計されています。

ENAデバイスは、最小限のメモリマップされたレジスタと拡張可能なコマンドセットを備えた軽量な管理インターフェースを提供し、管理キュー（Admin Queue）を通じて運用されます。

このドライバは幅広いENAデバイスをサポートし、リンク速度に依存しない（つまり10GbE、25GbE、40GbEなどすべてのリンク速度で同一のドライバが使用される）、交渉可能な拡張可能な機能セットを備えています。

一部のENAデバイスはSR-IOVをサポートしており、このドライバはSR-IOV物理ファンクション（PF）および仮想ファンクション（VF）デバイスの両方で使用されます。

ENAデバイスは、複数のTx/Rxキュー対（デバイスが管理キューを通じて最大数をアドバタイズ）を提供し、各Tx/Rxキュー対に専用のMSI-X割込みベクター、適応的な割込みモデレーション、CPUキャッシュライン最適化されたデータ配置により、高速で低オーバーヘッドのネットワークトラフィック処理を実現します。

ENAドライバはチェックサムオフロードやTCP送信セグメンテーションオフロード（TSO）などの業界標準のTCP/IPオフロード機能をサポートし、マルチコアスケーリング用の受信側スケーリング（RSS）もサポートしています。

ENAドライバおよび対応デバイスは、ウォッチドッグなどのヘルスモニタリングメカニズムを実装し、アプリケーションに透明な形でデバイスとドライバの回復を可能にし、デバッグログも提供します。

一部のENAデバイスは、マイクロ秒単位の遅延を削減するLow-latency Queue（LLQ）という動作モードをサポートしています。

管理インターフェース:¶

ENA管理インターフェースは以下の手段を通じて提供されます:

  • PCIe構成空間

  • デバイスレジスタ

  • 管理キュー（AQ）および管理完了キュー（ACQ）

  • 非同期イベント通知キュー（AENQ）

ENAデバイスのMMIOレジスタはドライバ初期化中にのみアクセスされ、その後の通常のデバイス運用には関与しません。

AQは管理コマンドの送信に使用され、結果/応答はACQを通じて非同期的に報告されます。

ENAは少数の管理コマンドを導入しており、ベンダー固有の拡張機能を含む余地があります。ほとんどの管理操作は汎用的なGet/Set機能コマンドでフレームされます。

次の管理者キュー コマンドがサポートされています:

  • I/O送信キューの作成

  • I/O完了キューの作成

  • I/O送信キューの破壊

  • I/O完了キューの破壊

  • 機能の取得

  • 機能の設定

  • AENQの構成

  • 統計情報の取得

サポートされているGet/Set機能プロパティの一覧はena_admin_defs.hを参照してください。

非同期イベント通知キュー(AENQ)は、ENAデバイスがACQで報告できないイベントをドライバーに送信するために使用される単方向キューです。AENQイベントはグループに分類され、各グループには複数のシンドロームが含まれることがあります。

イベントは以下の通りです:

グループ

シンドローム

リンク状態の変化

X

致命的なエラー

X

通知

トラフィックの停止

通知

トラフィックの再開

Keep-Alive

X

ACQおよびAENQは同じMSI-Xベクターを使用します。

Keep-Aliveはデバイスの健康状態を監視する特別なメカニズムです。ドライバーはウォッチドッグ(WD)ハンドラを維持しており、発火した場合、現在の状態と統計情報をログに記録した後、ENAデバイスおよびドライバーを再起動します。Keep-Aliveイベントはデバイスが毎秒送信します。ドライバーはKeep-Aliveイベントの受信時にWDを再アームします。Keep-Aliveイベントが欠落した場合、WDハンドラが発火します。

データパスインターフェース¶

I/O操作はTxおよびRx送信キュー(Tx SQおよびRx SQ)に基づいています。各SQには完了キュー(CQ)が関連付けられています。

SQおよびCQは連続した物理メモリ内のディスクリプタリングとして実装されます。

ENAドライバーはTx SQに対して2つのキュー操作モードをサポートしています:

  • 通常モード

    • このモードでは、Tx SQはホストのメモリに存在します。ENAデバイスはENA Txディスクリプタとパケットデータをホストメモリから取得します。

  • 低遅延キュー(LLQ)モードまたは「プッシュモード」。

    • このモードでは、ドライバーがトランスミットディスクリプタとパケットの最初の128バイトを直接ENAデバイスメモリ空間にプッシュします。パケットの残りのペイロードはデバイスが取得します。この操作モードでは、ドライバーは専用のPCIデバイスメモリBARを使用し、Write-Combine機能でマッピングします。

Rx SQは通常モードのみをサポートします。

注意: すべてのENAデバイスがLLQをサポートするわけではなく、この機能は初期化時にデバイスとネゴシエーションされます。

ENAデバイスがLLQモードをサポートしない場合、ドライバーは通常モードに戻ります。

ドライバーは、TxとRxの両方でマルチキューをサポートしています。これはさまざまな利点があります:

  • 特定のイーサネットインターフェースでのCPU/スレッド/プロセスの競合が減少します。

  • 完了時のキャッシュミス率が低下します。特に、sk_buff構造体を保持するデータキャッシュラインに対しては顕著です。

  • 受信パケットの処理におけるプロセスレベルの並列性が向上します。

  • パケットの処理をアプリケーションスレッドが実行されているCPUにリダイレクトすることで、データキャッシュヒット率が向上します。

  • ハードウェア割込みリダイレクト。

割込みモード¶

ドライバーは、TxとRxの両方向のキュー対（queue pair）ごとに単一のMSI-Xベクターを割り当てます。また、管理（ACQとAENQ）用に専用のMSI-Xベクターを追加で割り当てます。

管理割込みの登録は、Linuxカーネルがアダプターをプローブするときに実行され、アダプターが除去されるときに解除されます。I/Oキュー割込みの登録は、アダプターのLinuxインターフェースがオープンされるときに実行され、インターフェースがクローズされるときに解除されます。

管理割込みの名前は:

ena-mgmnt@pci:<PCI domain:bus:slot.function>

キュー対ごとに割込みの名前は:

<interface name>-Tx-Rx-<queue index>

ENAデバイスは自動マスクと自動クリアの割込みモードで動作します。つまり、MSI-Xがホストに配信されると、そのCauseビットが自動的にクリアされ、割込みがマスクされます。ドライバーはNAPI処理が完了後にマスクを解除します。

割込みの調整（Interrupt Moderation）¶

ENAドライバーおよびデバイスは従来モードまたは適応割込み調整モードで動作できます。

従来モードでは、ドライバーがデバイスに静的な割込み遅延値に基づいて割込みの投稿を遅延させます。割込み遅延値はethtool(8)で設定可能です。ドライバーがサポートするethtoolパラメータはtx-usecs、rx-usecsです。

適応割込み調整モードでは、ドライバーがトラフィックの性質に応じてNAPIサイクルごとに割込み遅延値を動的に更新します。

適応コールスティングはethtool(8)のadaptive_rx on|offパラメータで有効/無効にできます。

適応割込み調整（DIM）に関する詳細情報は、 Net DIM - ジェネリックネットワークダイナミック割込みモデレーション

RXコピーブレイク¶

rx_copybreakはデフォルトでENA_DEFAULT_RX_COPYBREAKに初期化され、SIOCETHTOOL ioctlのETHTOOL_STUNABLEコマンドで設定できます。

SKB¶

Rx処理でNAPIコンテキストを使用して受信フレーム用にドライバが割り当てたSKB（Socket Buffer）。割り当て方法はパケットのサイズに依存します。フレーム長がrx_copybreakより大きい場合、napi_get_frags()が使用され、それ以外はnetdev_alloc_skb_ip_align()が使用されます。この際、CPUがバッファの内容をSKBにコピーし、バッファが再利用されます。

統計¶

ユーザーはethtoolを使用してENAデバイスおよびドライバの統計情報を取得できます。ドライバはデバイスから定期的または拡張された統計情報（キューごとの統計情報も含む）を収集できます。

さらに、デバイスのリセット時にドライバはsyslogに統計情報をログ出力します。

MTU¶

ドライバはデバイスと協議した最大値を上限として任意に大きなMTUをサポートしています。MTUはSetFeatureコマンド（ENA_ADMIN_MTUプロパティ）を使用して設定されます。ユーザーはip(8)などの従来ツールを介してMTUを変更できます。

ステートレスオフロード¶

ENAドライバは以下のオフロードをサポートしています：

  • IPv4/IPv6におけるTSO（TCP Segmentation Offload）

  • ECN（Explicit Congestion Notification）をサポートしたTSO

  • IPv4ヘッダーチェックサムオフロード

  • IPv4/IPv6におけるTCP/UDPチェックサムオフロード

RSS（Receive Side Scaling）¶

  • ENAデバイスは柔軟なRxトラフィックのステアリングを可能にするRSSをサポートしています。

  • ToeplitzおよびCRC32ハッシュ関数がサポートされています。

  • ハッシュ関数の入力としてL2/L3/L4フィールドのさまざまな組み合わせを設定できます。

  • ドライバはAQ SetFeatureコマンド（ENA_ADMIN_RSS_HASH_FUNCTION、ENA_ADMIN_RSS_HASH_INPUTおよびENA_ADMIN_RSS_INDIRECTION_TABLE_CONFIGプロパティ）を使用してRSS設定を構成します。

  • NETIF_F_RXHASHフラグが設定されている場合、Rx CQディスクリプタに含まれる32ビットハッシュ結果が受信SKBに設定されます。

  • ユーザーはethtool(8)を使用してハッシュキー、ハッシュ関数、インデックステーブルを設定できます。

データパス¶

Tx¶

end_start_xmit()関数はスタックから呼び出されます。この関数は以下の処理を行います：

  • データバッファ（skb->dataおよびfrags）をマッピングします。

  • プッシュモードのドライバおよびデバイスの場合、プッシュバッファ（ena_buf）を設定します。

  • 残りのfrags用のENAバッファを準備します。

  • 空きreq_idリングから新しいリクエストIDを割り当てます。リクエストIDはTx情報内のパケットのインデックスです。これは無順序Tx完了処理に使用されます。

  • パケットをTxリングの適切な位置に追加します。

  • ena_com_prepare_tx()関数を呼び出します。これはENA通信層でena_bufをENAディスクリプタに変換し（必要に応じてメタENAディスクリプタを追加）ます。

    • この関数は、プッシュモードの場合、ENAディスクリプタおよびプッシュバッファをデバイスメモリ空間にコピーします。

  • ENAデバイスにドアベルを書き込みます。

  • ENAデバイスがパケットを送信完了した際、完了割込みが発生します。

  • 割込みハンドラがNAPIをスケジュールします。

  • ena_clean_tx_irq()関数が呼び出されます。この関数は、ENAによって生成された完了ディスクリプタを処理し、完了したパケットごとに1つの完了ディスクリプタを処理します。

    • 完了ディスクリプタからreq_idが取得され、req_idを通じてパケットのtx_infoが取得されます。データバッファがアンマップされ、req_idが空のreq_idリングに返されます。

    • 完了ディスクリプタが完了するか、予算が達成されるまで関数は実行されます。

Rx¶

  • ENAデバイスからパケットが受信される場合

  • 割込みハンドラがNAPIをスケジュールします。

  • ena_clean_rx_irq()関数が呼び出されます。この関数はENA通信層関数ena_rx_pkt()を呼び出し、新しい未処理パケットに使用されたディスクリプタ数を返します。新しいパケットが見つからない場合はゼロを返します。

  • その後、ena_clean_rx_irq()関数が呼び出されます。

  • ena_eth_rx_skb()はパケット長を確認します：

    • パケットが小さい場合（len < rx_copybreak）、ドライバは新しいパケット用のSKBを割り当て、パケットのペイロードをSKBデータバッファにコピーします。

      • このようにして、元のデータバッファはスタックに渡されず、今後のRxパケットのために再利用されます。

    • それ以外の場合、関数はRxバッファをアンマップし、新しいSKB構造体を割り当て、RxバッファをSKBフラグメントに接続します。

  • 新しいSKBは必要な情報（プロトコル、チェックサムのハードウェア検証結果など）を更新し、NAPIインターフェース関数napi_gro_receive()を通じてネットワークスタックに渡されます。
