1. Cirrus Logic LAN CS8900/CS8920 イーサネットアダプター¶

1.1. 製品概要¶

Cirrus Logic製のCS8900ベースのISAイーサネットアダプターはIEEE 802.3準拠しており、ISAバスコンピュータでの10 Mbpsイーサネットネットワークにおける半二重または全二重操作をサポートしています。これらのアダプターは16ビットISAまたはEISAバス拡張スロットでの運用を目的としており、10BaseTのみまたは3メディア構成（10BaseT、10Base2、および10Base-5またはファイバーネットワーク用のAUI）で利用可能です。

CS8920ベースのアダプターは、CS8900ベースのアダプターにPlug and Play（PnP）サポートとWakeup Frame認識機能を追加したものです。そのため、この2種類のアダプター間の設定手順には若干の違いがあります。詳しくは「アダプター設定」セクションを参照してください。

1.2. ドライバの説明¶

Linux用のCS8900/CS8920イーサネットアダプタードライバはLinux v2.3.48またはそれ以降のカーネルをサポートしており、カーネルに直接コンパイルして組み込むか、実行時にデバイスドライバモジュールとしてロードできます。

2. アダプタのインストールと設定¶

CS8900およびCS8920ベースのアダプタは、ボード内に搭載されたEEPROMに保存されたパラメータを使用して設定可能です。アダプタの設定をEEPROMで変更する場合は、DOSベースのCS8900/20 Setup Utilityを使用してください。

ドライバをモジュールとしてロードする場合、コマンドライン引数でアダプタの設定パラメータを指定して、EEPROMの設定を上書きしたり、EEPROMを使用しない場合のインターフェース設定を行うことが可能です。(CS8920ベースのアダプタはEEPROMを使用する必要があります。) 詳細は第3章「ドライバをモジュールとしてロード」を参照してください。

CS8900/20 Setup UtilityはDOSベースのアプリケーションであるため、ターゲットのLINUXシステムにインストールする前に、DOSベースのシステムでCS8900/20 Setup Utilityを使用してアダプタをインストール・設定する必要があります。(CS8900ベースのアダプタをインストールし、デフォルト設定で問題がない場合は不要です。)

2.1. CS8900ベースのアダプタ設定¶

Cirrus Logicから出荷されるCS8900ベースのアダプタは、以下の「デフォルト」設定で構成されています：

Operation Mode:      Memory Mode
IRQ:                 10
Base I/O Address:    300
Memory Base Address: D0000
Optimization:        DOS Client
Transmission Mode:   Half-duplex
BootProm:            None
Media Type:          Autodetect (3-media cards) or
                     10BASE-T (10BASE-T only adapter)

他のアダプタと競合する場合のみ、デフォルト設定を変更してください。アダプタの設定を変更するには、CS8900/20 Setup Utilityを実行してください。

2.2. CS8920ベースのアダプタ設定¶

Cirrus Logicから出荷されるCS8920ベースのアダプタは、プラグアンドプレイ(PnP)をサポートしています。しかし、cs89x0ドライバはPnPをサポートしていないため、CS8920アダプタはDOSベースのPCでインストールし、CS8900/20 Setup Utilityを実行してPnPを無効化し、アダプタを設定する必要があります。これを行わない場合、アダプタは動作せず、ドライバと通信が不可能になります。

****************************************************************
*                    CS8920-BASED ADAPTERS:                    *
*                                                              *
* CS8920-BASED ADAPTERS ARE PLUG and PLAY ENABLED BY DEFAULT.  *
* THE CS89X0 DRIVER DOES NOT SUPPORT PnP. THEREFORE, YOU MUST  *
* RUN THE CS8900/20 SETUP UTILITY TO DISABLE PnP SUPPORT AND   *
* TO ACTIVATE THE ADAPTER.                                     *
****************************************************************

3. ドライバをモジュールとしてロード¶

ドライバがロード可能なモジュールとしてコンパイルされている場合、'modprobe'コマンドでドライバモジュールをロードできます。多くのアダプタの設定パラメータは、ロードコマンドのコマンドライン引数として指定可能です。この機能により、EEPROMの設定を上書きしたり、EEPROMを使用しない場合のインターフェース設定を行うことが可能です。

例:

insmod cs89x0.o io=0x200 irq=0xA media=aui

この例では、モジュールをロードし、アダプターをIOポートベースアドレス200h、割込み10、AUIメディア接続を使用するように設定します。コマンドラインで利用可能な設定オプションは以下の通りです。

io=###               - specify IO address (200h-360h)
irq=##               - specify interrupt level
use_dma=1            - Enable DMA
dma=#                - specify dma channel (Driver is compiled to support
                       Rx DMA only)
dmasize=# (16 or 64) - DMA size 16K or 64K.  Default value is set to 16.
media=rj45           - specify media type
 or media=bnc
 or media=aui
 or media=auto
duplex=full          - specify forced half/full/autonegotiate duplex
 or duplex=half
 or duplex=auto
debug=#              - debug level (only available if the driver was compiled
                       for debugging)

注意：

  1. EEPROMが存在する場合、指定されたコマンドラインパラメータは、EEPROMに保存された対応する設定値を上書きします。

  2. 「io」パラメータはコマンドラインで必ず指定する必要があります。

  3. ドライバのハードウェアプローブルーチンは、cs89x0カードが書き込まれたアドレスに存在することを確認するまでI/O領域に書き込みを行いません。これはデバイスプローブに問題を引き起こす可能性があります。この挙動を回避するには、 io= モジュールパラメータに1を加えます。これはI/Oアドレスを実際に変更しないですが、ドライバにハードウェアを部分的に初期化してからカードを識別するように通知するフラグです。提供されたアドレスにcs89x0カードが存在しない場合にこの操作は危険です。

    例えば、IOベースアドレス0x300に配置されたアダプターをスキャンするには、IOアドレスを0x301に指定します。

  4. 「duplex=auto」パラメータはCS8920専用にサポートされています。

  5. EEPROMが存在しない場合の最小限のコマンドライン設定は以下の通りです。

    io irq media type (自動検出なし)

  6. 以下の追加パラメータはCS89XXのデフォルト値（EEPROMやコマンドライン引数が指定されていない場合の値）です。

    • DMAバースト = 有効

    • IOCHRDY有効 = 有効

    • UseSA = 有効

    • CS8900はコマンドラインで指定されていない場合、半二重通信モードにデフォルトします

    • CS8920はコマンドラインで指定されていない場合、自動交渉モードにデフォルトします

    • 他の設定パラメータはリセットデフォルトを使用します

    • dma_mode = 0

  7. ifconfigを使用してアダプターのイーサネットアドレスを設定できます。

  8. 多くのLinuxディストリビューションは「modprobe」コマンドを使用してモジュールをロードします。このプログラムは「/etc/conf.modules」ファイルを読み込み、ドライバモジュールがロードされる際に渡される設定情報を決定します。上記のすべての設定オプションは「/etc/conf.modules」ファイルに記述できます。

    例:

    > cat /etc/conf.modules
...
alias eth0 cs89x0
options cs89x0 io=0x0200 dma=5 use_dma=1
...

    この例では、このマシンのイーサネットドライバがcs89x0ドライバを使用することをモジュールシステムに通知しています。また、「modprobe」にドライバがロードされる際に「io」、「dma」、「use_dma」引数を渡すように求めています。

  9. Cirrusはcs89x0がISA DMAチャネル5、6、または7を使用することを推奨しています。他のDMAチャネルはおそらく動作しないでしょう。

  10. cs89x0は受信専用のDMAをサポートしています。DMAモードは大幅に効率的です。400MHz Celeronマシンに大容量のpingパケットを洪水攻撃すると、非DMAモードではCPU容量の82%を消費しますが、DMAモードでは45%にまで減少します。

  11. Linuxカーネルが組み込みのplug-and-playサポートでコンパイルされている場合、cs89x0カードに関する情報を確認するには以下のコマンドを使用できます。

    cat /proc/isapnp

  12. DMA動作中に異常な挙動やネットワークデータの破損が発生した場合は、PCのBIOSを使用してEISAバスクロックを遅くしてください。

  13. cs89x0ドライバがカーネルに直接組み込まれている（モジュールでない）場合、そのI/OアドレスはISAバスのプローブによって自動的に決定されます。IRQ番号、メディアオプションなどはカードのEEPROMから取得されます。

  14. cs89x0ドライバがカーネルに直接組み込まれている場合、DMAモードは「cs89x0_dma=N」という起動オプションをカーネルに提供することで選択できます。ここで「N」は希望するDMAチャンネル番号（5、6または7）です。

    カーネルの起動オプションはLILOコマンドラインで提供できます:

    LILO boot: linux cs89x0_dma=5

    または、/etc/lilo.confに配置することもできます:

    image=/boot/bzImage-2.3.48
  append="cs89x0_dma=5"
  label=linux
  root=/dev/hda5
  read-only

    このモードではDMA Rxバッファサイズは16 kbytesに固定されています。（64kモードは利用不可）。

4. ドライバのコンパイル¶

cs89x0ドライバはカーネルに直接組み込むか、ロード可能なデバイスドライバモジュールとしてコンパイルできます。

標準的な方法でドライバを構成し、カーネルをコンパイルしてください。

4.1. 受信DMAをサポートするドライバのコンパイル¶

DMAのコンパイル時オプションは2.3カーネルシリーズで削除されました。DMAサポートは今後ドライバに無条件で含まれるようになり、'use_dma=1'というモジュールオプションで有効になります。

5. テストとトラブルシューティング¶

5.1. 既知の欠陥と制限¶

このアーカイブに同梱されているRELEASE.TXTファイルを参照してください。ここに既知の欠陥、ドライバの制限、回避策の一覧が記載されています。

5.2. アダプターのテスト¶

アダプターがインストール・設定されると、CS8900/20 Setup Utilityの診断オプションを使用してアダプターおよびネットワーク接続の機能をテストできます。アダプターのハードウェア設定に応じて機能をテストするには「自己テスト」オプションを使用してください。アダプターが他のPCとイーサネット経由で通信できるかをテストするには「ネットワークテスト」オプションを使用してください。このPCもCS8900/20 Setup Utilityを実行しているCS8900/20ベースのアダプターを搭載している必要があります。

注意

Setup Utilityの診断はDOS専用のオペレーティングシステム環境で動作します。Windows 95、Windows NT、OS/2、または他のオペレーティングシステムのDOSまたはコマンドプロンプトセッションから診断を実行しないでください。

CS8900/20アダプターの診断テストを実行するには:

  1. PCでDOSを起動し、CS8900/20 Setup Utilityを起動してください。

  2. アダプターの現在の設定が表示されます。ENTERキーを押してメインメニューに移動してください。

  1. メインメニューから「診断」（ALT-G）を選択します。・「自己診断」を選択してアダプターの基本機能をテストします。・「ネットワークテスト」を選択してネットワーク接続とケーブルの状態をテストします。

5.2.1. 診断自己診断¶

診断自己診断は、ハードウェア設定時に割り当てられたシステムリソースに基づいてアダプターの基本機能およびISAバスを介した通信機能を確認します。以下のテストが実施されます：

  • IOレジスタ読み書きテスト

    IOレジスタ読み書きテストは、CS8900/20がIOモードでアクセス可能であることを確認し、IOベースアドレスが正しいことを確認します。

  • 共有メモリテスト

    共有メモリテストは、CS8900/20がメモリモードでアクセス可能であることを確認し、割り当てられたメモリアドレス範囲がシステム内の他のデバイスと競合していないことを確認します。

  • 割込みテスト

    割込みテストは、割り当てられたIRQ信号と競合がないことを確認します。

  • EEPROMテスト

    EEPROMテストは、EEPROMが読み出せることを確認します。

  • チップRAMテスト

    チップRAMテストは、CS8900/20内蔵の4Kメモリが正常に動作することを確認します。

  • 内部ループバックテスト

    内部ループバックテストは、アダプターの送信機と受信機が正常に動作することを確認します。このテストに失敗した場合は、アダプターのケーブルがネットワークに接続されているか確認してください（LEDの動作を確認するなど）。

  • ブートPROMテスト

    ブートPROMテストは、ブートPROMが存在し、読み出せることを確認します。失敗は、ハードウェアの問題またはブートPROMアドレス割り当ての競合によりブートPROMが正しく読み出せなかったことを示します。（このテストはアダプターがブートPROMオプションを使用するように設定されている場合にのみ適用されます。）

テスト項目の失敗は、ISAバス上の他のデバイスとシステムリソースの競合を示している可能性があります。この場合、失敗したシステムリソースに別の値を指定してアダプターを再設定するため、手動設定オプションを使用してください。

5.2.2. 診断ネットワークテスト¶

診断ネットワークテストは、同じネットワーク上の異なるPCにインストールされた2つのCS8900/20アダプター間でデータを転送することにより、動作するネットワーク接続を確認します。（注意：診断ネットワークテストはルーターを介した2つのノード間で実行しないでください。）

このテストには、2つのPCがそれぞれCS8900/20ベースのアダプターを搭載し、CS8900/20設定ユーティリティが動作している必要があります。1つのPCはレスポンダとして設定され、もう1つのPCはイニシエーターとして設定されます。イニシエーターを開始した後、イニシエーターはレスポンダにデータフレームを送信し、レスポンダがフレームをイニシエーターに返します。

起動機のディスプレイには、受信および送信されたフレームの総数が表示され、正常またはエラーで受信・送信されたフレーム数も表示されます。ユーザーは任意のタイミングでテストを終了できます。

診断ネットワークテストの設定方法:

  1. CS8900/20ベースのアダプターを搭載し、動作確認済みのネットワーク接続を備えたPCを応答機として選択します。CS8900/20設定ユーティリティを実行し、「診断 -> ネットワークテスト -> 応答機」を選択してメインメニューから実行します。ENTERキーを押して応答機を開始します。

  2. テスト対象のCS8900/20ベースのアダプターを搭載したPCに戻り、CS8900/20設定ユーティリティを起動します。

  3. メインメニューから「診断 -> ネットワークテスト -> 起動機」を選択し、ENTERキーを押してテストを開始します。

テストを起動機で任意のタイミングで停止できますが、応答機は継続して動作します。この方法により、追加のPCに移動して他のPCをテストする際、応答機を停止・起動せずに起動機を別のPCで実行できます。

5.3. アダプターのLEDの使用方法¶

2メディアおよび3メディアアダプターには、10Base-Tコネクタに近いボード後部に2つのLEDが表示されます。

リンク整合性LED: 緑色のLEDが「常時点灯」している場合、有効な10Base-T接続を示します。(10Base-2またはAUI接続では緑色LEDは無関係です。)

TX/RX LED: アダプターがデータを送信または受信するたびに黄色のLEDが一瞬明るくなります。(通常のネットワークでは黄色のLEDが「ちらつく」ように見えます。)

5.4. I/O競合の解決方法¶

2つ以上のアダプターが同じISAリソース（I/Oアドレス、メモリアドレスまたはIRQ）を使用するとI/O競合が発生します。CS8900/20ベースのアダプターをインストールまたは設定した後、I/O競合を検出する方法は以下の4通りあります:

  1. システムが正しく起動しない（または起動しない）。

  2. ドライバーがアダプターと通信できず、「アダプターが見つからない」というエラーメッセージを報告します。

  3. ネットワークに接続できず、またはドライバーがロードされません。

  4. アダプターをメモリモードで設定したにもかかわらず、ドライバーがロード時にI/Oモードを使用していると報告される場合、メモリアドレス競合の可能性があります。

I/O競合が発生した場合は、CS8900/20設定ユーティリティを実行し、診断自己テストを実施します。通常、競合しているISAリソースは自己テストに失敗します。その場合、競合しているリソースの選択肢を変更してアダプターを再設定し、再度診断を実行して他のI/O競合を確認します。

PCが起動しないなどの場合、アダプターを取り外して、別のPCにインストールしてCS8900/20 Setup Utilityを実行し、設定を再構成する必要があります。ターゲットシステムに再インストールした後、ドライバーを再度ロードする前に、新しい設定に競合がないか診断の自己テストを実施してください。

アダプターを手動で設定する際は、以下の表に示すようにISAシステムのリソース使用量を考慮してください。

-----------           --------                      ---      --------

   230-23F            Bus Mouse                      4       COM1
   270-27F            LPT3: third parallel port      5       LPT2
   2F0-2FF            COM2: second serial port       6       Floppy Disk controller
   320-32F            Fixed disk controller          7       LPT1
                                                       8       Real-time Clock

A000-BFFF     EGA Graphics Adapter

6. 技術サポート¶

6.2. 技術サポートへの連絡前の必要な情報¶

Cirrus Logicに技術サポートを依頼する前に、以下の情報のうち可能な限り提供してください。

1.) アダプターの種類（CRD8900、CDB8900、CDB8920など）

2.) アダプターの設定

  • IOベース、メモリベース、IOまたはメモリモードの有効化、IRQ、DMAチャネル

  • Plug and Playの有効/無効（CS8920ベースのアダプターのみ）

  • メディア自動検出または特定のメディアタイプ（どのタイプか）

3.) PCシステムの設定

  • Plug and Playシステム（はい/いいえ）

  • BIOS（メーカーとバージョン）

  • システムのメーカーとモデル

  • CPU（タイプと速度）

  • システムRAM

  • SCSIアダプター

4.) ソフトウェア

  • CS89XXドライバーおよびバージョン

  • ご使用のネットワークOSおよびバージョン

  • ご使用のシステムのOSバージョン

  • すべてのプロトコルサポートファイルのバージョン

5.) 表示されたエラーメッセージ

6.3 最新ドライババージョンの取得¶

最新のCS89XXドライバおよびサポートソフトウェアは、Cirrus LogicのWebサイトから取得できます。また、Cirrus Logic技術サポート（メールアドレス： ethernet@crystal.cirrus.com)に連絡し、自動ソフトウェア更新通知の登録を依頼することもできます。

Cirrus Logicは以下のWebページで最新のドライバおよび技術資料を公開しています。 http://www.cirrus.com https://www.cirrus.com

6.4 現在のメンテナ¶

2000年2月からこのドライバのメンテナンスはAndrew Mortonが担当しています。

6.5 カーネルモジュールパラメータ¶

cs89x0 EEPROMが存在しない埋め込み環境で使用するため、カーネル起動パラメータ cs89x0_media= が実装されています。使用方法は以下の通りです：

cs89x0_media=rj45    or
cs89x0_media=aui     or
cs89x0_media=bnc
