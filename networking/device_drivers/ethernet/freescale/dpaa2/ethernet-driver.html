DPAA2 Ethernetドライバ¶

このファイルはFreescale DPAA2 Ethernetドライバのドキュメンテーションを提供します。

サポートされているプラットフォーム¶

このドライバはFreescale DPAA2 SoC（例: LS2080A、LS2088A、LS1088A）のネットワークサポートを提供します。

アーキテクチャ概要¶

通常のNICとは異なり、DPAA2アーキテクチャではネットワークインターフェースを表す単一のハードウェアブロックは存在せず、複数の別個のハードウェアリソースがネットワーク機能を提供します：

  • ネットワークインターフェース

  • キュー、チャネル

  • バッファプール

  • MAC/PHY

すべてのハードウェアリソースはManagement Complex（MC）ポートを通じて割り当てられ、設定されます。MCはこれらのリソースをDPAA2オブジェクトとして抽象化し、それらを設定・制御するためのABIを提供します。キューなどの一部のハードウェアリソースはMCオブジェクトに対応せず、他のオブジェクトの内部リソースとして扱われます。

DPAA2アーキテクチャとそのオブジェクト抽象化についての詳細な説明については DPAA2 (Data Path Acceleration Architecture Gen2) 概要.

各Linux netデバイスはDatapath Network Interface（DPNI）オブジェクトに基づき、Buffer Pools（DPBPs）、I/Oポート（DPIOs）、Concentrators（DPCONs）を使用します。

DPNIはPHYに1対1で対応しないネットワークインターフェースです。DPBPはハードウェアバッファプールを表します。パケットI/OはDPCONオブジェクトのコンテキストで行われ、DPIOポートを通じてハードウェアリソースとやり取りします。

データパスI/O（DPIO）ポートはエンキューおよびデキューのサービス、データ利用可能通知、バッファプール管理を提供します。DPIOはすべてのDPAA2オブジェクト（および暗黙的にすべてのDPAA2カーネルドライバ）でデータフレームを処理するための共有リソースですが、トラフィック配分の目的でCPUにアフィンする必要があります。

フレームはハードウェアフレームキューを通じて送信および受信され、ハードウェアスケジューリングの目的でキューをチャネルにグループ化できます。イーサネットドライバはTXフレームをエグジットキューにエンキューし、送信が完了した後、CPUにTX確認フレームを送信します。

イングリットキューにフレームが利用可能になると、CPUにデータ利用可能通知が送信されます。通知はチャネルごとに発生するため、同じチャネル内の複数のキューにフレームが利用可能であっても、1つの通知のみが送信されます。チャネルが通知を発生させた後は、明示的に再起動する必要があります。

各ネットワークインターフェースは、複数のRx、Txおよび確認用キューをCPUにアフィン（割り当て）し、少なくとも1つのキューをサービスする各CPUに1つのチャネル（DPCON）を持ちます。DPCONは、コアのアフィンDPIOを通じて異なるCPUにイングレストラフィックを分散するために使用されます。

ハードウェアバッファプールの役割はイングレスフレームデータの保存です。各ネットワークインターフェースは、カーネルが割り当てたバッファで独自のバッファプールを所有しており、これを種子として初期化します。

DPNIはPHYから分離されています。DPNIはDPMACオブジェクトを通じてPHYに接続されたり、内部リンクを通じて他のDPNIに接続されたりしますが、接続はMCによって管理され、イーサネットドライバには完全に透明です。

ネットワークインターフェースの作成¶

MCバス上でプローブされた各DPNIオブジェクトに対してネットデバイスが作成されます。各DPNIはネットワークインターフェースの設定オプションおよび関連するハードウェアリソースを決定する複数のプロパティを持ちます。

DPNIオブジェクト（およびネットワークインターフェースに必要な他のDPAA2オブジェクト）は、MCバス上のコンテナに2つの方法のいずれかで追加できます：静的に、起動時にMCが解析するデータパスレイアウトバイナリファイル（DPL）を通じて；または、実行時においてDPAA2オブジェクトAPIを介して動的に作成します。

機能とオフロード¶

IPv4/6フレーム上のTCPおよびUDPにおけるハードウェアチェックサムオフロードがサポートされています。チェックサムオフロードは、ethtoolを通じてRXおよびTXごとに個別に構成可能です。

イングレスパスにおいてユニキャストおよびマルチキャストMACフィルタリングのハードウェアオフロードがサポートされ、常に有効にされています。

RXおよびTXパスの両方にスキャッターガatherフレームがサポートされています。TXではSGサポートはethtoolを通じて構成可能ですが、RXでは常に有効です。

DPAA2ハードウェアは最大10キロバイトのジャンボイーサフレームを処理できます。

イーサネットドライバは、トラフィックを送信元IP、宛先IP、IPプロトコル、L4送信ポート、L4受信ポートの5要素キーに基づいて配分する静的なフローハッシュスキームを定義しています。現在はユーザーの設定はサポートされていません。

ネットワークインターフェースのハードウェア固有の統計情報および一部の非標準ドライバ統計情報は、ethtool -Sオプションを通じて確認できます。
