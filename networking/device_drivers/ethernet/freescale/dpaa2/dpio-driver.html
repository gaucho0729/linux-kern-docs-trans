はじめに¶

DPAA2 DPIO (Data Path I/O) は、ネットワークインターフェースや他のアクセラレータとの間でフレームをエンキューおよびデキューするインターフェースを提供するハードウェアオブジェクトです。DPIOはネットワークインターフェースのハードウェアバッファプール管理も提供します。

このドキュメントはLinux DPIOドライバー、そのサブコンポーネント、およびAPIの概要を提供します。

参照 DPAA2 (Data Path Acceleration Architecture Gen2) 概要 LinuxにおけるDPAA2ドライバアーキテクチャの一般的な概要については、以下を参照してください。

ドライバ概要¶

DPIOドライバーはfsl-mcバスで検出されたDPIOオブジェクトにバインドされ、以下のサービスを提供します:

  1. 他のドライバ（例：イーサネットドライバ）がそれぞれのオブジェクトに対してフレームをエンキューおよびデキューできるようにします

  2. データがキューまたはチャネルに利用可能になったときにデータ利用通知用のコールバックをドライバに登録できるようにします

  3. ドライバがハードウェアバッファプールを管理できるようにします

Linux DPIOドライバーは3つの主要なコンポーネントから構成されています–

DPIOオブジェクトドライバー– fsl-mcドライバーでDPIOオブジェクトを管理します

DPIOサービス– 他のLinuxドライバにサービスAPIを提供します

QBmanポータルインターフェース– ポータルコマンドを送信し、応答を取得します:

DPIOオブジェクトドライバー (dpio-driver.c)¶

dpio-driverコンポーネントはfsl-mcバスに登録され、"dpio"タイプのオブジェクトを処理します。probe()の実装はDPIOの基本的な初期化を処理し、DPIO領域（QBman SWポータル）のマッピングと割込みの初期化、irqハンドラの登録を行います。dpio-driverはプローブされたDPIOをdpio-serviceに登録します。

DPIOサービス (dpio-service.c, dpaa2-io.h)¶

dpioサービスコンポーネントは、イーサネットドライバなどのDPAA2ドライバにキューイング、通知、バッファ管理サービスを提供します。システムでは通常、1つのCPUごとに1つのDPIOオブジェクトを割り当てて、すべてのCPUでキューイング操作が同時に実行できるようにします。

QBmanポータルインターフェース (qbman-portal.c)¶

qbman-portalコンポーネントは、以下のような操作のために低レベルのハードウェアビット操作を行うAPIを提供します:

  • Qmanソフトウェアポータルの初期化

  • ポータルコマンドの構築および送信

  • ポータル割込みの設定および処理

qbman-portal APIは他のドライバに公開されておらず、のみdpio-serviceで使用されます。

その他のファイル(dpaa2-fd.h, dpaa2-global.h)¶

フレーム記述子およびスキャッターギャッターの定義と、それらを操作するAPIはdpaa2-fd.hで定義されています。

デキュー結果構造体およびパースAPIはdpaa2-global.hで定義されています。
