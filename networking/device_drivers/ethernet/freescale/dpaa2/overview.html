このドキュメントは、Freescale DPAA2アーキテクチャとLinuxカーネルへの統合についての概要を提供します。

はじめに¶

DPAA2は、高速ネットワークパケット処理を目的としたハードウェアアーキテクチャです。DPAA2はイーサネットパケット処理、キュー管理、バッファ管理、自律的なL2スイッチング、仮想イーサネットブリッジング、アクセラレータ（例：暗号化）共有など、複雑なメカニズムを備えています。

DPAA2ハードウェアコンポーネントの一つであるマネジメントコンプレックス（MC）がDPAA2ハードウェアリソースを管理します。MCはソフトウェアドライバがDPAA2ハードウェアを操作するためのオブジェクトベースの抽象化を提供します。MCはキュー、バッファプール、ネットワークポートなどのDPAA2ハードウェアリソースを使用して、ネットワークインターフェース、L2スイッチ、アクセラレータインスタンスなどの機能オブジェクト/デバイスを作成します。MCはメモリマップI/Oコマンドインターフェース（MCポート）を提供し、DPAA2ソフトウェアドライバがDPAA2オブジェクトを操作するために使用します。

以下の図はDPAA2リソース管理アーキテクチャの概要を示しています。

MCは作成、発見、接続、設定、破壊などの操作を仲介します。データの高速パス操作（パケット送受信など）はMCを介さず、DPIOオブジェクト内のメモリマップ領域を直接使用して行われます。

DPAA2オブジェクトの概要¶

このセクションでは、いくつかの主要なDPAA2オブジェクトについての簡単な概要を説明します。ネットワークインターフェースを作成する際の関与するオブジェクトを示すシナリオが記載されています。

DPRC (Datapath Resource Container)¶

DPRCは、他のすべてのDPAA2オブジェクトを保持するコンテナオブジェクトです。以下の例図では、コンテナ内に5種類（DPMCP、DPIO、DPBP、DPNI、DPMAC）のオブジェクトが8個存在しています。

+---------------------------------------------------------+
| DPRC                                                    |
|                                                         |
|  +-------+  +-------+  +-------+  +-------+  +-------+  |
|  | DPMCP |  | DPIO  |  | DPBP  |  | DPNI  |  | DPMAC |  |
|  +-------+  +-------+  +-------+  +---+---+  +---+---+  |
|  | DPMCP |  | DPIO  |                                   |
|  +-------+  +-------+                                   |
|  | DPMCP |                                              |
|  +-------+                                              |
|                                                         |
+---------------------------------------------------------+

OSの観点から見ると、DPRCはPCIのようなプラグアンドプレイバスと同様の挙動をします。DPRCコマンドを使用して、DPRCのコンテンツを列挙し、存在するハードウェアオブジェクト（マッピング可能な領域や割込み含む）を発見できます。

DPRC.1 (bus)
   |
   +--+--------+-------+-------+-------+
      |        |       |       |       |
    DPMCP.1  DPIO.1  DPBP.1  DPNI.1  DPMAC.1
    DPMCP.2  DPIO.2
    DPMCP.3

ハードウェアオブジェクトは動的に作成および破壊可能で、DPRC内にオブジェクトをホットプラグ/アンプラグできる機能を提供します。

DPRCは、MCコマンドを送信するために使用できるマッピング可能なMMIO領域（MCポート）を持ち、ステータスイベント（ホットプラグなど）用の割込みを備えています。コンテナ内のすべてのオブジェクトは同じハードウェア「隔離コンテキスト」を共有します。これは、IOMMUに対して隔離の粒度がDPRC（コンテナ）レベルであり、個々のオブジェクトレベルではないことを意味します。

DPRCは、ファームウェアが起動時にMCに渡される設定ファイルを介して静的に定義され、オブジェクトで埋め込まれます。

DPAA2のイーサネットネットワークインターフェース用オブジェクト¶

通常のイーサネットNICは単一の塊で構成されています。NICデバイスはTX/RXキュー管理機構、設定機構、バッファ管理、物理ポート、割込みなどを含みます。DPAA2はより細かい粒度で複数のハードウェアオブジェクトを活用します。各オブジェクトは専用の機能を提供し、ソフトウェアはこれらのオブジェクトのグループを用いてイーサネットネットワークインターフェース機能を実現します。このアプローチにより、有限なハードウェアリソースの効率的な利用、柔軟性、パフォーマンスの向上が可能になります。

以下の図は、2つのCPUを持つシステムにおけるシンプルなネットワークインターフェース構成に必要なオブジェクトを示しています。

+---+---+ +---+---+
   CPU0     CPU1
+---+---+ +---+---+
    |         |
+---+---+ +---+---+
   DPIO     DPIO
+---+---+ +---+---+
    \     /
     \   /
      \ /
   +---+---+
      DPNI  --- DPBP,DPMCP
   +---+---+
       |
       |
   +---+---+
     DPMAC
   +---+---+
       |
   port/PHY

以下のオブジェクトについて説明します。各オブジェクトには簡潔な説明と、サポートする操作の概要、およびオブジェクトの主要リソース（MMIO領域とIRQ）の概要が記載されています。

DPMAC（データパス イーサネットMAC）¶

イーサネットMACを表し、イーサネットPHYに接続され、物理的なイーサネットフレームの送受信を可能にするハードウェアデバイスです。

  • MMIO領域：なし

  • IRQ：DPNIリンク変化

  • コマンド：リンクのアップ/ダウン設定、リンク設定、統計取得、IRQ設定、有効化、リセット

DPNI（データパス ネットワークインターフェース）：TX/RXキュー、ネットワークインターフェース設定、RXバッファプール設定機構を含みます。TX/RXキューはメモリ上にあり、キュー番号で識別されます。

  • MMIO領域：なし

  • IRQ：リンク状態

  • コマンド：ポート設定、オフロード設定、キュー設定、パース/分類設定、IRQ設定、有効化、リセット

DPIO（データパス I/O）¶

パケットのエンキューおよびデキュー操作とハードウェアバッファプール管理操作のインターフェースを提供します。DPAA2アーキテクチャは、キューへのアクセスメカニズム（DPIOオブジェクト）とキュー自体を分離しています。DPIOは、エンキュー/デキュー操作にMMIOインターフェースを提供します。エンキュー操作を行うには、DPIOのMMIO領域にデスクリプタを書き込み、その中にターゲットキュー番号を含める必要があります。通常、各CPUに1つのDPIOが割り当てられ、これによりすべてのCPUが同時にエンキュー/デキュー操作を実行できます。DPIOは、異なるDPAA2ドライバー間で共有されることが期待されます。

  • MMIO領域：キュー操作、バッファ管理

  • 割込み（IRQ）：データ利用可能、混雑通知、バッファプール枯渇

  • コマンド：割込み設定、有効化、リセット

DPBP（Datapath Buffer Pool）¶

ハードウェアバッファプールを表します。

  • MMIO領域：なし

  • 割込み（IRQ）：なし

  • コマンド：有効化、リセット

DPMCP（Datapath MC Portal）¶

MCコマンドポートを提供します。ドライバーがMCにオブジェクトを管理するためのコマンドを送信するために使用されます。

  • MMIO領域：MCコマンドポート

  • 割込み（IRQ）：コマンド完了

  • コマンド：割込み設定、有効化、リセット

オブジェクト接続¶

一部のオブジェクトには明示的な関係があり、設定が必要です：

  • DPNI <–> DPMAC

  • DPNI <–> DPNI

  • DPNI <–> L2-switch-port

    DPNIはDPMAC、他のDPNI、またはL2スイッチポートなどに接続される必要があります。DPNIの接続はDPRCコマンドを通じて行われます。

+-------+  +-------+
| DPNI  |  | DPMAC |
+---+---+  +---+---+
    |          |
    +==========+

  • DPNI <–> DPBP

    ネットワークインターフェースには「バッファプール」（DPBPオブジェクト）が必要であり、これは受信したイーサネットデータをコピーするメモリのポインタリストを提供します。イーサネットドライバーはネットワークインターフェースに関連するDPBPsを設定します。

割込み¶

DPAA2オブジェクトによって生成されるすべての割込みはメッセージ割込みです。ハードウェアレベルでは、デバイスによって生成されるメッセージ割込みは通常、3つのコンポーネントを持ちます– 1) ハードウェアバスで表現される偽装不能な「デバイスID」、2) アドレス、3) データ値です。

DPAA2デバイス/オブジェクトの場合、同じコンテナ/DPRC内のすべてのオブジェクトは同じ「デバイスID」を共有します。ARMベースのSoCでは、これはストリームIDと同じです。

DPAA2 Linuxドライバ概要¶

このセクションでは、DPAA2用のLinuxカーネルドライバの概要を説明します– 1) バスドライバと関連する「DPAA2インフラストラクチャ」ドライバ、および 2) 関数オブジェクトドライバ（イーサネットなど）です。

以前に説明したように、DPRC（DPAA2オブジェクトのコンテナ）は、他の種類のDPAA2オブジェクトを保持するコンテナです。これはプラグアンドプレイバスコントローラーと機能的に類似しています。DPRC内の各オブジェクトはLinuxの「デバイス」として扱われ、ドライバーにバインドされています。以下の図はネットワーキングシナリオにおけるLinuxドライバーと、それぞれのドライバーにバインドされているオブジェクトを示しています。各ドライバーについての簡単な説明を以下に示します。

        .              .     tx confirm> |   | dequeue>

各ドライバーについての簡単な説明は以下の通りです。

MC-busドライバー¶

MC-busドライバーはプラットフォームドライバーであり、ブートファームウェアから渡されたデバイスツリーのノード（compatible "fsl,qoriq-mc"）からプローブされます。これはDPAA2カーネルインフラストラクチャの起動を担当します。主な機能には以下の通りです。

  • kernelに"fsl-mc"という新しいバスタイプを登録し、バスコールバック（例: match/uevent/dev_groups）を実装すること

  • DPAA2ドライバーの登録およびデバイスの追加/削除用のAPIを実装すること

  • MSI IRQドメインを作成すること

  • 'device add'を実行して'root' DPRCを露出し、これによりroot DPRCがDPRCドライバーにバインドされるようにトリガーすること

MC-busデバイスツリーノードのバインディングは以下のドキュメンテーションを参照してください Documentation/devicetree/bindings/misc/fsl,qoriq-mc.txt。MC-busのsysfsバインディング/アンバインディングインターフェースは以下のドキュメンテーションを参照してください Documentation/ABI/testing/sysfs-bus-fsl-mc.

DPRCドライバー¶

DPRCドライバーはDPRCオブジェクトにバインドされ、バスインスタンスのランタイム管理を行います。DPRCの初期バススキャンを実行し、ホットプラグなどのコンテナイベントの割り込みを処理します。

アロケータ¶

DPMCPやDPBPなどのオブジェクトは汎用的で代替可能であり、他のドライバーに使用されるように設計されています。たとえば、DPAA2イーサネットドライバーは以下のものを必要とします。

  • DPMCPはMCコマンドを送信し、ネットワークインターフェースを構成するために使用されます

  • DPBPはネットワークバッファプールとして使用されます

アロケータドライバーはこれらの割り当て可能なオブジェクトタイプに登録し、バスがプローブされるときにこれらのオブジェクトはアロケータにバインドされます。アロケータは、他のDPAA2ドライバーが割り当て可能なオブジェクトプールを維持します。

DPIOドライバー¶

DPIOドライバーはDPIOオブジェクトにバインドされ、イーサネットドライバーなどの他のドライバーがそれぞれのオブジェクトに対してデータをエンキューおよびデキューできるようにするサービスを提供します。主なサービスには以下の通りです。

  • データ利用可能通知

  • ハードウェアキュー操作（データのエンキューおよびデキュー）

  • ハードウェアバッファプール管理

パケットを送信する際、イーサネットドライバーはデータをキューに配置し、DPIO APIを呼び出します。受信の際は、イーサネットドライバーがデータの可用性を通知するコールバックを登録します。パケットをキューから取り出すにはDPIO APIが使用されます。パフォーマンスを最適化するために通常は物理CPUごとに1つのDPIOオブジェクトが存在し、異なるCPUが同時にデータをキューイングおよびキュー アウトすることが可能です。

DPIOドライバーは、カーネル内にアクティブなすべてのDPAA2ドライバー（イーサネット、暗号化、圧縮など）の代行として動作します。

イーサネットドライバー¶

イーサネットドライバーはDPNIにバインドされ、DPAA2ネットワークインターフェースをネットワークスタックに接続するために必要なカーネルインターフェースを実装します。各DPNIはLinuxネットワークインターフェースに該当します。

MACドライバー¶

イーサネットPHYはチップ外のボード固有のコンポーネントであり、適切なPHYドライバーがmdioバスを介して管理します。MACドライバーはPHYドライバーとMC（マスターコントローラー）の間のプロキシとしての役割を果たします。これはMCコマンドをDPMACオブジェクトに通じて行われます。PHYドライバーがリンク変化を通知した場合、MACドライバーはDPMACコマンドを介してMCに通知します。ネットワークインターフェースがアップまたはダウンされる場合、MCはDPM、ACドライバーに割り込みを介して通知し、ドライバーは適切なアクションをとることができます。
