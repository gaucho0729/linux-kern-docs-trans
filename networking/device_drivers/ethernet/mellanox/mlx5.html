ドライバーとkconfigオプションの有効化¶

mlx5 coreはモジュール化されており、主要なmlx5 coreドライバ機能の多くはビルド時にコンパイル込み/外しを選択できます
カーネルのKconfigフラグを通じて選択できます。
基本機能、イーサネットネットデバイスのrx/txオフロード、およびXDPは、最も基本的なフラグで利用できます
CONFIG_MLX5_CORE=y/m および CONFIG_MLX5_CORE_EN=y。
高度な機能の一覧については下記をご参照ください。

CONFIG_MLX5_CORE=(y/m/n) (モジュール mlx5_core.ko)

カーネルの設定で CONFIG_MLX5_CORE=y/m を選択することでドライバを有効化できます
これにより、mlx5 ulpsがインターフェースするmlx5 coreドライバが提供されます (mlx5e, mlx5_ib)

CONFIG_MLX5_CORE_EN=(y/n)

このオプションを選択することで、標準のrx/txオフロードを含む基本的なイーサネットネットデバイスのサポートが可能になります
mlx5eはmlx5 ulpドライバであり、ネットデバイスカーネルインターフェースを提供します。選択された場合、mlx5eは
mlx5_core.koに組み込まれます

CONFIG_MLX5_EN_ARFS=(y/n)

ハードウェアアクセラレーションによる受信フローのステアリング (arfs) サポートとntupleフィルタリングを有効にします
https://community.mellanox.com/s/article/howto-configure-arfs-on-connectx-4

CONFIG_MLX5_EN_RXNFC=(y/n)

ethtoolによる受信ネットワークフロー分類を有効にし、ユーザー定義の
フロールールを介してethtool set/get_rxnfc APIを通じて、任意のrxキューにトラフィックを誘導する機能を提供します

CONFIG_MLX5_CORE_EN_DCB=(y/n):

有効にする データセンターブリッジング（DCB）サポート.

CONFIG_MLX5_MPFS=(y/n)

ConnectX NICでのイーサネットマルチ・フィジカルファンクションスイッチ（MPFS）サポート。
MPFsは次の条件で必要です マルチホスト 構成が有効になって、ユーザーが設定したユニキャストMACアドレスを要求するPFに渡すことを許可します
ユーザーが設定したユニキャストMACアドレスを要求するPFに渡す

CONFIG_MLX5_ESWITCH=(y/n)

ConnectX NICでのイーサネットSRIOV E-Switchサポート。E-Switchは内部SRIOVパケットのルーティングを提供します
および有効化されたVFsとPFのための2つの利用可能なモードでのスイッチング:
1) レガシSRIOVモード（L2 MAC VLANルーティングベース）.
2) スイッチデブモード（eswitchオフロード）.

CONFIG_MLX5_CORE_IPOIB=(y/n)

IPoIBオフロード＆加速サポート。
CONFIG_MLX5_CORE_ENが必要で、rdma用の高速化インターフェースを提供します
IPoIB ulp netdevice。

CONFIG_MLX5_FPGA=(y/n)

Mellanox Technologies製のInnovaファミリーネットワークカードのサポートを構築します
Innovaネットワークカードは、1枚の基板にConnectXチップとFPGAチップを搭載しています。
このオプションを選択すると、mlx5_coreドライバーはInnova FPGAコアを含み、
サンドボックス固有のクライアントドライバーの構築を許可します。

CONFIG_MLX5_EN_IPSEC=(y/n)

有効にする IPSec XFRM暗号化オフロードの加速.

CONFIG_MLX5_EN_TLS=(y/n)

TLS暗号化オフロードの加速。

CONFIG_MLX5_INFINIBAND=(y/n/m) (module mlx5_ib.ko)

低レベルのInfiniBand/RDMAおよび RoCE のサポート。

外部オプション ( 対応するmlx5機能が必要な場合に選択してください )

  • CONFIG_PTP_1588_CLOCK: 選択すると、mlx5 ptpサポートが有効になります

  • CONFIG_VXLAN: 選択すると、mlx5 vxlanサポートが有効になります。

  • CONFIG_MLXFW: 選択すると、mlx5ファームウェアフラッシュサポートが有効になります（devlinkおよびethtoolを介して）。

Devlink情報¶

devlink情報は、デバイス上の実行中のファームウェアバージョンと保存されたファームウェアバージョンを報告します。また、HCAボードタイプIDを表すデバイスPSIDも出力します。

ユーザー コマンドの例:

$ devlink dev info pci/0000:00:06.0
   pci/0000:00:06.0:
   driver mlx5_core
   versions:
      fixed:
         fw.psid MT_0000000009
      running:
         fw.version 16.26.0100
      stored:
         fw.version 16.26.0100

Devlinkパラメータ¶

flow_steering_mode: デバイスフローステアリングモード¶

フローステアリングモードパラメータはドライバーのフローステアリングモードを制御します。サポートされるモードは2つあります：1. ‘dmfs’ - デバイス管理型フローステアリング。2. ‘smfs’ - ソフトウェア/ドライバ管理型フローステアリング。

DMFSモードでは、HWステアリングエンティティがファームウェアを通じて作成および管理されます。SMFSモードでは、ドライバーがファームウェアの干渉なしにハードウェア直接にHWステアリングエンティティを作成および管理します。

SMFSモードは、デフォルトのDMFSモードと比較して高速で、より良いルール挿入率を提供します。

ユーザー コマンドの例:

  • SMFSフローステアリングモードを設定:

    $ devlink dev param set pci/0000:06:00.0 name flow_steering_mode value "smfs" cmode runtime

  • デバイスフローステアリングモードを読み取:

    $ devlink dev param show pci/0000:06:00.0 name flow_steering_mode
  pci/0000:06:00.0:
  name flow_steering_mode type driver-specific
  values:
     cmode runtime value smfs

enable_roce: RoCEの有効化状態¶

RoCEの有効化状態は、ドライバーがRoCEトラフィックをサポートするかどうかを制御します。RoCEが無効の場合、gidテーブルは存在せず、のみraw Ethernet QPがサポートされ、よく知られたUDP RoCEポート上のトラフィックはraw Ethernetトラフィックとして処理されます。

RoCEの有効化状態を変更するには、ユーザーがdriverinit cmode値を変更し、devlink reloadを実行する必要があります。

ユーザー コマンドの例:

  • RoCEを無効化:

    $ devlink dev param set pci/0000:06:00.0 name enable_roce value false cmode driverinit
$ devlink dev reload pci/0000:06:00.0

  • RoCEの有効化状態を読み取:

    $ devlink dev param show pci/0000:06:00.0 name enable_roce
  pci/0000:06:00.0:
  name enable_roce type generic
  values:
     cmode driverinit value true

Devlinkヘルスレポーター¶

tx reporter¶

tx reporterは、以下の2つのエラーケースの報告および回復を担当します：

  • TXタイムアウト

    カーネルのTXタイムアウト検出を報告します。失われた割り込みを検索して回復します。

  • TXエラー完了

    エラーTX完了を報告します。TXキューをフラッシュしてリセットすることで回復します。

tx reporterは、需要に基づく診断コールバックをサポートしており、その際、送信キューのリアルタイム情報を提供します。

ユーザー コマンドの例:

  • 送信キューの状態を診断:

    $ devlink health diagnose pci/0000:82:00.0 reporter tx

注意: このコマンドの出力はインターフェースがアップしている場合にのみ有効です。インターフェースがダウンしている場合、出力は空になります。

  • 送信エラーの数、成功した回復フローの数、自動回復が有効かどうか、および最後の回復からの優雅な期間を表示します。

    $ devlink health show pci/0000:82:00.0 reporter tx

rx reporter¶

rx reporterは、以下の2つのエラーシナリオの報告および回復を担当しています。

  • RXキューの初期化（ポピュレーション）タイムアウト

    リング初期化時にRXキューのディスクリプタポピュレーションはnapiコンテキストでIRQをトリガーして実行され、ディスクリプタの最小数を取得できなかった場合、タイムアウトが発生し、EQ（イベントキュー）をポーリングすることで回復可能になります。

  • エラーを報告したRX完了（割込みコンテキストでHWが報告）

    RX完了エラーを報告します。必要に応じて関連するキューをフラッシュし、リセットして回復します。

rx reporterは、オンデマンド診断コールバックもサポートしており、リアルタイムで受信キューの状態情報を提供します。

  • RXキューの状態を診断し、対応する完了キューを表示します。

    $ devlink health diagnose pci/0000:82:00.0 reporter rx

注意: このコマンドの出力はインターフェースがアップしている場合にのみ有効です。インターフェースがダウンしている場合、出力は空になります。

  • 送信エラーの数、成功した回復フローの数、自動回復が有効かどうか、および最後の回復からの優雅な期間を表示します。

    $ devlink health show pci/0000:82:00.0 reporter rx

fw reporter¶

fw reporterは診断およびダンプコールバックを実装しており、fwエラーの症状（fwシンドロームなど）を検出するとfwコアダンプをトリガーしてダンプバッファに保存します。ユーザーがいつでもfw reporter診断コマンドを実行して現在のfwステータスを確認できます。

ユーザー コマンドの例:

  • fwヘルスステータスを確認します。

    $ devlink health diagnose pci/0000:82:00.0 reporter fw

  • 既に保存されているFWコアダンプを読み込むか、新しいダンプをトリガーします。

    $ devlink health dump show pci/0000:82:00.0 reporter fw

注意: このコマンドはFWトレーサーの所有権を持つPFのみで実行可能です。他のPFまたは任意のVFで実行すると「Operation not permitted」が返されます。

fw fatal reporter¶

fw fatal reporterはダンプおよび回復コールバックを実装しており、CR領域ダンプと回復フローにより致命的なエラーの指示を追跡します。CR領域ダンプはvscインターフェースを使用し、FWコマンドインターフェースが機能しない場合でも有効です（これはほとんどのFW致命的エラーのケースです）。回復機能はドライバを再ロードし、必要に応じてFWリセットをトリガーする回復フローを実行します。

ユーザー コマンドの例:

  • FW回復フローを手動で実行します。

    $ devlink health recover pci/0000:82:00.0 reporter fw_fatal

  • 既に保存されているFW CR領域ダンプを読み込むか、新しいダンプをトリガーします。

    $ devlink health dump show pci/0000:82:00.1 reporter fw_fatal

注意: このコマンドはPFのみで実行可能です。

mlx5トレースポイント¶

mlx5ドライバは、カーネルトレースポイントインターフェースを使用してトレースポイントを提供し、トレッキングおよびデバッグに使用します（参照してください ftrace - 関数トレーサー).

サポートされるmlx5イベントの一覧は、/sys/kernel/debug/tracing/events/mlx5/ を確認してください

tcおよびeswitchオフロードトレースポイント:

  • mlx5e_configure_flower: flowerフィルターアクションおよびクッキーのオフロードをトレースします。

    $ echo mlx5:mlx5e_configure_flower >> /sys/kernel/debug/tracing/set_event
$ cat /sys/kernel/debug/tracing/trace
...
tc-6535  [019] ...1  2672.404466: mlx5e_configure_flower: cookie=0000000067874a55 actions= REDIRECT

  • mlx5e_delete_flower: flowerフィルターアクションおよびクッキーの削除がmlx5からトレースされる:

    $ echo mlx5:mlx5e_delete_flower >> /sys/kernel/debug/tracing/set_event
$ cat /sys/kernel/debug/tracing/trace
...
tc-6569  [010] .N.1  2686.379075: mlx5e_delete_flower: cookie=0000000067874a55 actions= NULL

  • mlx5e_stats_flower: flower統計リクエストがトレースされる:

    $ echo mlx5:mlx5e_stats_flower >> /sys/kernel/debug/tracing/set_event
$ cat /sys/kernel/debug/tracing/trace
...
tc-6546  [010] ...1  2679.704889: mlx5e_stats_flower: cookie=0000000060eb3d6a bytes=0 packets=0 lastused=4295560217

  • mlx5e_tc_update_neigh_used_value: tunnelルールネイバー更新値がmlx5にオフロードされトレースされる:

    $ echo mlx5:mlx5e_tc_update_neigh_used_value >> /sys/kernel/debug/tracing/set_event
$ cat /sys/kernel/debug/tracing/trace
...
kworker/u48:4-8806  [009] ...1 55117.882428: mlx5e_tc_update_neigh_used_value: netdev: ens1f0 IPv4: 1.1.1.10 IPv6: ::ffff:1.1.1.10 neigh_used=1

  • mlx5e_rep_neigh_update: ネイバー状態変更イベントによりスケジュールされたネイバー更新タスクがトレースされる:

    $ echo mlx5:mlx5e_rep_neigh_update >> /sys/kernel/debug/tracing/set_event
$ cat /sys/kernel/debug/tracing/trace
...
kworker/u48:7-2221  [009] ...1  1475.387435: mlx5e_rep_neigh_update: netdev: ens1f0 MAC: 24:8a:07:9a:17:9a IPv4: 1.1.1.10 IPv6: ::ffff:1.1.1.10 neigh_connected=1
