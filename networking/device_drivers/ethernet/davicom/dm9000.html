DM9000 ネットワークドライバー¶

2008年 Simtec Electronics が著作権を保有します

Ben Dooks <ben@simtec.co.uk> <ben-linux@fluff.org>

はじめに¶

このファイルは、drivers/net/dm9000.c および drivers/net/dm9000.h に含まれる DM9000 プラットフォームデバイスベースのネットワークドライバーの使用方法を説明しています。

このドライバーは、DM9000E（最初にサポートされたチップ）、DM9000A、DM9000B の3つの変種をサポートします。現在、Ben Dooks がこのドライバーをメンテナンスおよびテストしており、このドライバーに関するパッチには Ben Dooks を CC: する必要があります。

プラットフォームデバイスの定義¶

プラットフォームデバイスに接続されている最小限のリソースは以下の通りです：

  1. アドレスレジスタの物理アドレス

  2. データレジスタの物理アドレス

  3. デバイスの割込みピンが接続されているIRQライン

これらのリソースは、アドレス領域の順序が重要であるため、この順序で指定する必要があります（ドライバーはこれらをアドレス順にデータと期待しています）。

arch/arm/mach-s3c2410/mach-bast.c からの例は以下の通りです：

static struct resource bast_dm9k_resource[] = {
      [0] = {
              .start = S3C2410_CS5 + BAST_PA_DM9000,
              .end   = S3C2410_CS5 + BAST_PA_DM9000 + 3,
              .flags = IORESOURCE_MEM,
      },
      [1] = {
              .start = S3C2410_CS5 + BAST_PA_DM9000 + 0x40,
              .end   = S3C2410_CS5 + BAST_PA_DM9000 + 0x40 + 0x3f,
              .flags = IORESOURCE_MEM,
      },
      [2] = {
              .start = IRQ_DM9000,
              .end   = IRQ_DM9000,
              .flags = IORESOURCE_IRQ | IORESOURCE_IRQ_HIGHLEVEL,
      }
};

static struct platform_device bast_device_dm9k = {
      .name           = "dm9000",
      .id             = 0,
      .num_resources  = ARRAY_SIZE(bast_dm9k_resource),
      .resource       = bast_dm9k_resource,
};

bast_dm9k_resource[2].flags でIRQトリガーフラグを設定している点に注意してください。このフラグが存在しない場合、警告が生成されます。flags フィールドのトリガーは、 request_irq() IRQハンドラを登録する際に渡され、IRQが正しく設定されるようにします。

これはオプションの構成プラットフォームデータが提供されていない典型的なプラットフォームデバイスを示しています。次の例では同じリソースを使用していますが、追加のオプションプラットフォームデータを介して追加の構成データを渡しています：

static struct dm9000_plat_data bast_dm9k_platdata = {
      .flags          = DM9000_PLATF_16BITONLY,
};

static struct platform_device bast_device_dm9k = {
      .name           = "dm9000",
      .id             = 0,
      .num_resources  = ARRAY_SIZE(bast_dm9k_resource),
      .resource       = bast_dm9k_resource,
      .dev            = {
              .platform_data = &bast_dm9k_platdata,
      }
};

プラットフォームデータは include/linux/dm9000.h に定義されており、以下で説明します。

プラットフォームデータ¶

DM9000 用の追加プラットフォームデータは、デバイスへのIOバス幅、外部PHYが接続されているか、外部の構成EEPROMが利用可能かを記述できます。

プラットフォームデータの .flags フィールドのフラグは以下の通りです：

DM9000_PLATF_8BITONLY

IOは8bit操作で行う必要があります。

DM90,000_PLATF_16BITONLY

IOは16bit操作で行う必要があります。

DM9000_PLATF_32BITONLY

IOは32bit操作で行う必要があります。

DM9000_PLATF_EXT_PHY

チップは外部PHYに接続されています。

DM9000_PLATF_NO_EEPROM

ボードにEEPROMが存在しないか、ユーザーから隠すことを示すことができます。

DM9000_PLATF_SIMPLE_PHY

内部PHYを使用してより単純なPHYポーリングメソッドに切り替えます。これは定期的にMII PHYの状態を読み取ろうとしない方法です。詳細については、リンクステートポーリングに関するセクションを参照してください。

DM9000_FORCE_SIMPLE_PHY_POLLという設定シンボルおよびKconfigエントリ「Force simple NSR based PHY polling」により、このフラグをビルド時に強制的に有効にできます。

PHY Link state polling¶

ドライバーはリンク状態を追跡し、ネットワークコアにリンク（キャリア）の可用性を通知します。これはチップのバージョンや使用中のPHYによって異なり、いくつかの方法で管理されます。

内部PHYの場合、元の（現在のデフォルトでもある）方法は、チップに必要な割り込みサポートがある場合、ステータスが変化したときに、または2秒ごとに定期タイマーベースでMII状態を読み取ることです。

内部PHYのオーバーヘッドを減らすために、現在はDM9000_FORCE_SIMPLE_PHY_POLL設定またはDM9000_PLATF_SIMPLE_PHYプラットフォームデータオプションを使用して、高コストのMIIアクセスをせずにサマリ情報のみを読み取るオプションがあります。この方法は高速ですが、情報量が少ないです。

外部PHYを使用する場合、ドライバーは現在、リンク変化時の割り込み取得方法が存在しないため、MIIリンクステータスをポーリングする必要があります。

DM9000A / DM9000B¶

これらのチップはDM9000Eと機能的に類似しており、同じドライバーで簡単にサポートされます。特徴は以下の通りです：

  1. 内部PHYのステータス変化時の割り込み。これは、内部PHYを使用するこれらのデバイスで、定期的なPHYステータスポーリングが無効になることを意味します。

  2. TCP/UDPチェックサムオフローディング。これは現在ドライバーがサポートしていません。

ethtool¶

ドライバーは、ドライバーの状態情報、PHY状態、EEPROMへのアクセスにethtoolインターフェースをサポートしています。
