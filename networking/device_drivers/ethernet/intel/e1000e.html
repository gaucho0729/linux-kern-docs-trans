コマンドラインパラメータ¶

ドライバがモジュールとして構築されている場合、以下のオプションパラメータはmodprobeコマンドを使用してコマンドラインに入力することで使用されます。

modprobe e1000e [<option>=<VAL1>,<VAL2>,...]

このドライバがサポートするシステム内の各ネットワークポートには<VAL#>が必要です。値はファンクション順に各インスタンスに適用されます。例えば：

modprobe e1000e InterruptThrottleRate=16000,16000

この場合、システム内にe1000eがサポートするネットワークポートは2つあります。各パラメータのデフォルト値は一般的に推奨設定ですが、特に記載がない限りです。

注意：デスクリプターはデータバッファとその関連する属性を記述します。この情報はハードウェアによってアクセスされます。

InterruptThrottleRate¶

有効な範囲

0,1,3,4,100-100000

デフォルト値

3

インテラルスロー率は、各インテラルベクターが毎秒生成できるインテラル数を制御します。インテラルスロー率を増やすとレイテンシーは低下しますが、CPU利用率が増加します。ただし、一部の状況ではスループット向上にも貢献する可能性があります。

InterruptThrottleRateを100以上に設定すると、アダプターが1秒間に最大でその数の割り込みを送信するよう設定されます。これにより、システムの割り込み負荷が軽減され、重負荷時のCPU利用率が低下しますが、パケットの処理が遅くなるためレイテンシーが増加します。

以前のドライバのデフォルト動作は、インテラルスロー率が静的な8000という値を仮定していました。これはすべてのトラフィックタイプに対する良いフォールバック値でしたが、小パケット処理性能やレイテンシーに劣っていました。しかしハードウェアは毎秒より多くの小パケットを処理できるため、このための適応型インテラルモデレーションアルゴリズムが実装されました。

ドライバは2つの適応モード（設定1または3）を持ち、受信トラフィックの種類に基づいてインテラルスロー率値を動的に調整します。最後のタイムフレームで受信したトラフィックの種類を判定した後、そのトラフィックに適したインテラルスロー率に調整します。

このアルゴリズムは、インターバルごとに受信トラフィックを3つのクラスに分類します。「Bulk traffic（大容量トラフィック）」は通常サイズのパケットが多数含まれる場合、「Low latency（低レイテンシー）」は少量のトラフィックや小パケットが大幅に含まれる場合、「Lowest latency（最低レイテンシー）」はほぼすべて小パケットまたは極めて少ないトラフィックの場合です。

  • 0: オフ

    インテラルモデレーションをオフにし、小パケットレイテンシーを改善する可能性があります。ただし、この高いインテラルレートによるCPU利用率の増加のため、バッチ処理トラフィックには一般的に不適切です。

  • 1: ディナミックモード

    このモードは、インテラルベクターごとのインテラルを制御しながら非常に低いレイテンシーを維持しようとします。これは場合によっては追加のCPU利用率を引き起こす可能性があります。e1000eをレイテンシーに敏感な環境で展開する予定がある場合は、このパラメータを考慮する必要があります。

  • 3: ディナミックコンサービティブモード（デフォルト）

    動的コンサービティブモードでは、「Bulk traffic」に該当するトラフィックにはInterruptThrottleRate値を4000に設定します。一方、「Low latency」または「Lowest latency」に該当するトラフィックでは、InterruptThrottleRate値を段階的に20000に増加させます。このデフォルトモードはほとんどのアプリケーションに適しています。

  • 4: シンプルバランスモード

    簡略モードでは、割り込み率はTXとRXトラフィックの比率に基づきます。1秒あたりのバイトレートがほぼ同じ場合、割り込み率は2000にまで低下します。トラフィックが主に送信または受信の場合、割り込み率は8000に達する可能性があります。

  • 100-100000:

    InterruptThrottleRate を 100 以上に設定すると、アダプターが 1 秒あたり最大でその数の割込みを送信するよう設定されます。これにより、システムの割込み負荷が軽減され、重負荷時の CPU 使用率を低下させることができます。ただし、パケットが迅速に処理されないため、レイテンシーが増加します。

注意: InterruptThrottleRate は TxAbsIntDelay および RxAbsIntDelay パラメータよりも優先されます。つまり、受信および/または送信の絶対遅延を最小化しても、Interrupt Throttle Rate が許容する範囲を超えて割込みを生成するようにコントローラーを強制しません。

RxIntDelay¶

有効な範囲

0-65535（0=オフ）

デフォルト値

0

この値は受信インテラプトの生成を1.024マイクロ秒単位で遅らせます。適切に調整すれば、特定のネットワークトラフィックに対してCPU効率を向上させる可能性があります。この値を増やすとフレーム受信に追加のレイテンシーが発生し、TCPトラフィックのスループットが低下する可能性があります。システムが受信をドロップしている場合、この値が高すぎる可能性があり、ドライバが利用可能な受信ディスクリプタを枯渇してしまう原因となるかもしれません。

注意: RxIntDelay を 0 以外の値に設定した場合、特定のネットワーク状況でアダプターが停止（送信を停止）する可能性があります。このような場合、システムイベントログに NETDEV WATCHDOG メッセージが記録され、コントローラーが自動的にリセットされネットワーク接続が復元されます。ハングの可能性を排除するには、RxIntDelay を 0 に設定してください。

RxAbsIntDelay¶

有効な範囲

0-65535（0=オフ）

デフォルト値

8

この値は 1.024 マイクロ秒単位で、受信割込みが生成されるまでの遅延を制限します。設定された時間内に最初のパケットが受信された後に割込みが生成されるようにします。これは RxIntDelay が 0 でない場合にのみ役立ちます。適切な調整と RxIntDelay の組み合わせにより、特定のネットワーク状況でのトラフィックスループットが向上する可能性があります。

TxIntDelay¶

有効な範囲

0-65535（0=オフ）

デフォルト値

8

この値は送信割込みの生成を1.024マイクロ秒単位で遅延させます。適切に調整すれば、特定のネットワークトラフィックにおいてCPU効率を向上させることが可能です。システムが送信が失われていると報告している場合、この値が高すぎる可能性があり、ドライバが利用可能な送信ディスクリプタを枯渇させる原因となることがあります。

TxAbsIntDelay¶

有効な範囲

0-65535（0=オフ）

デフォルト値

32

この値は 1.024 マイクロ秒単位で、送信割込みが生成されるまでの遅延を制限します。これは TxIntDelay が 0 でない場合にのみ役立ちます。設定された時間内に最初のパケットがワイヤー上に送信された後に割込みが生成されるようにします。適切な調整と TxIntDelay の組み合わせにより、特定のネットワーク状況でのトラフィックスループットが向上する可能性があります。

copybreak¶

有効な範囲

0-xxxxxxx (0=オフ)

デフォルト値

256

ドライバーは、このサイズ以下のすべてのパケットを新しい受信バッファにコピーしてスタックに渡します。このパラメータは他のパラメータと異なり、すべてのドライバーインスタンスに単一の（1,1,1 などではなく）パラメータとして適用され、かつ /sys/module/e1000e/parameters/copybreak でランタイム中に利用可能です。

copybreak を使用するには、タイプ:

modprobe e1000e.ko copybreak=128

有効な範囲

0 (無効)

CrcStripping¶

有効な範囲

0,1

デフォルト値

1 (有効)

受信パケットからCRCを剥離してネットワークスタックに送信します。BMCが有効なマシンであっても、ドライバのロードまたは有効化後にIPMIトラフィックを受信できない場合があります。その場合はこの機能を無効にしてみてください。

WriteProtectNVM¶

有効な範囲

0,1

デフォルト値

1 (有効)

1に設定されている場合、ハードウェアがICHx NVM内のGbE領域へのすべての書き込み/消去サイクルを無視するように構成されます（NVMの誤った破壊を防ぐため）。この機能は、ドライバロード時にパラメータを0に設定することで無効にできます。

注意: NVMの書き込みを有効にする際にはパラメータをゼロに設定した状態で機器を電源を完全に切って再起動する必要があります。NVMがロックされている状態（ドライバロード時にパラメータが1に設定されている場合）では、電源サイクル以外でアンロックすることはできません。

追加の機能と設定¶

ジャンボフレーム¶

ジャンボフレームのサポートは、最大送信ユニット（MTU）をデフォルト値1500より大きい値に変更することで有効になります。

ifconfigコマンドを使用してMTUサイズを増やすことができます。例えば、<x>はインターフェース番号で、以下のコマンドを入力してください:

ifconfig eth<x> mtu 9000 up

代わりに、ipコマンドを使用することもできます:

ip link set mtu 9000 dev eth<x>
ip link set up dev eth<x>

この設定は再起動時に保持されません。設定変更を永続化するには、以下のファイルに'MTU=9000'を追加してください:

  • RHELの場合: /etc/sysconfig/network-scripts/ifcfg-eth<x>

  • SLESの場合: /etc/sysconfig/network/<config_file>

注意: ジャンボフレームの最大MTU設定は8996です。これは最大ジャンボフレームサイズ9018バイトに一致します。

注意: 10または100Mbpsでジャンボフレームを使用することはサポートされておらず、パフォーマンス低下やリンク喪失を引き起こす可能性があります。

注意: 以下のアダプタはジャンボフレームサイズのパケットを最大4088バイトまで制限します:

  • Intel(R) 82578DMギガビットネットワーク接続

  • Intel(R) 82577LMギガビットネットワーク接続

以下のアダプタはジャンボフレームをサポートしていません:

  • Intel(R) PRO/1000ギガビットサーバーアダプター

  • Intel(R) PRO/1000 PMネットワーク接続

  • Intel(R) 82562G 10/100ネットワーク接続

  • Intel(R) 82562G-2 10/100ネットワーク接続

  • Intel(R) 82562GT 10/100ネットワーク接続

  • Intel(R) 82562GT-2 10/100ネットワーク接続

  • Intel(R) 82562V 10/100ネットワーク接続

  • Intel(R) 82562V-2 10/100ネットワーク接続

  • Intel(R) 82566DCギガビットネットワーク接続

  • Intel(R) 82566DC-2 ギガビットネットワーク接続

  • Intel(R) 82566DM ギガビットネットワーク接続

  • Intel(R) 82566MC ギガビットネットワーク接続

  • Intel(R) 82566MM ギガビットネットワーク接続

  • Intel(R) 82567V-3 ギガビットネットワーク接続

  • Intel(R) 82577LC ギガビットネットワーク接続

  • Intel(R) 82578DC ギガビットネットワーク接続

注意: MACSecがシステムで有効になっている場合、82579ベースのネットワークデバイスではジャンボフレームの設定はできません。

ethtool¶

ドライバーはethtoolインターフェースを使用してドライバーの設定および診断、統計情報の表示を行います。この機能には最新のethtoolバージョンが必要です。ダウンロードはこちら:

https://www.kernel.org/pub/software/network/ethtool/

注意: 一部のデバイス（例: 82578）で有効/無効テストを検証する際は、ethtoolを使用する際、テスト間で数秒の間隔を設ける必要があります。

速度とフル デュプレックス設定¶

速度と双方向通信の設定に関する問題を解決する際には、銅ベースのアダプターとファイバーベースのアダプターを区別する必要があります。

デフォルトモードでは、銅ベースのIntel(R) エスネットワークアダプターはリンクパートナーと自動交渉を行い、最適な設定を決定します。アダプターが自動交渉でリンクパートナーとリンクを確立できない場合、アダプターとリンクパートナーの設定を同一に手動で設定する必要があります。これは、自動交済をサポートしていない古いスイッチや、特定の速度または双方向通信モードに強制されたスイッチとリンクを確立する場合にのみ必要です。リンクパートナーは選択した設定と一致する必要があります。1 Gbps以上の速度は強制できません。1 Gbps以上を手動で設定するには、自動交渉の広告設定を使用してください。

速度、双方向通信、自動交渉の広告設定はethtoolユーティリティを通じて設定されます。

注意: 速度と双方向通信の強制や自動交渉の広告設定の変更は、経験豊富なネットワーク管理者のみが行うべきです。スイッチの設定は常にアダプターの設定と一致する必要があります。アダプターのパフォーマンスが低下するか、アダプターが正常に動作しなくなる可能性があります。

ファイバーベースの接続を使用するIntel(R) エスネットワークアダプターは、リンクパートナーと自動交渉を行いません。これらのアダプターはフルダブルクォーテーションで動作し、ネイティブ速度のみで動作します。

Wake on LAN（WoL）の有効化¶

WoLはethtoolユーティリティを通じて設定されます。

システムの次のシャットダウンまたは再起動時にWoLが有効になります。このドライバーのバージョンでは、WoLを有効にするには、シャットダウンまたはシステムのスリープ前にe1000eドライバーをロードする必要があります。

注意: Wake on LANは以下のデバイスではポートAでのみサポートされています。- Intel(R) PRO/1000 PT Dual Port Network Connection - Intel(R) PRO/1000 PT Dual Port Server Connection - Intel(R) PRO/1000 PT Dual Port Server Adapter - Intel(R) PRO/1000 PF Dual Port Server Adapter - Intel(R) PRO/1000 PT Quad Port Server Adapter - Intel(R) Gigabit PT Quad Port Server ExpressModule
