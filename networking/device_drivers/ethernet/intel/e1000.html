コマンドラインパラメータ¶

各パラメータのデフォルト値は一般的に推奨設定ですが、特に記載がない限りそのままでよいです。

ノート：

AutoNeg、Duplex、Speedパラメータについての詳細情報は、このドキュメントの「スピードとダブルックスの設定」セクションをご参照ください。

InterruptThrottleRate、RxIntDelay、TxIntDelay、RxAbsIntDelay、TxAbsIntDelayパラメータについての詳細情報は、以下のアプリケーションノートをご参照ください： http://www.intel.com/design/network/applnots/ap450.htm

AutoNeg¶

(銅線接続のアダプターのみサポート)

有効な範囲

0x01-0x0F, 0x20-0x2F

デフォルト値

0x2F

このパラメータは、アダプターが広告するスピードとダブルックス設定を指定するビットマスクです。このパラメータを使用する場合、SpeedとDuplexパラメータは指定してはなりません。

ノート:

AutoNegパラメータについての詳細情報は、このリーディメの「スピードとダブルックス」セクションをご参照ください。

Duplex¶

(銅線接続のアダプターのみサポート)

有効な範囲

0-2 (0=自動交渉、1=半二重、2=全二重)

デフォルト値

0

データが流れる方向を指定します。1方向または2方向のいずれかです。両方のDuplexとリンクパートナーが自動交渉を設定している場合、ボードは正しい二重性を自動で検出します。リンクパートナーが強制されている場合（全二重または半二重）、Duplexは半二重にデフォルトします。

FlowControl¶

有効な範囲

0-3 (0=なし、1=受信のみ、2=送信のみ、3=受信&送信)

デフォルト値

EEPROMからフロー制御設定を読み込みます

このパラメータは、イーサネットPAUSEフレームの自動生成(Tx)と応答(Rx)を制御します。

InterruptThrottleRate¶

(インテル(R) 82542、82543または82544ベースのアダプターではサポートされていません)

有効な範囲

0,1,3,4,100-100000 (0=オフ、1=動的、3=動的コンサービティブ、4=簡易バランス)

デフォルト値

3

ドライバーは、受信パケットに対してアダプターが1秒間に生成する割り込みの数を制限できます。これは、アダプターが1秒間に生成する割り込みの最大数に基づいて値をアダプターに書き込みます。

InterruptThrottleRateを100以上に設定すると、アダプターが1秒間に最大でその数の割り込みを送信するよう設定されます。これにより、システムの割り込み負荷が軽減され、重負荷時のCPU利用率が低下しますが、パケットの処理が遅くなるためレイテンシーが増加します。

ドライバの以前のデフォルト動作は、静的なInterruptThrottleRate値を8000に設定し、すべてのトラフィックタイプに対する良いバックアップ値を提供していましたが、小パケットのパフォーマンスとレイテンシーに不十分でした。ハードウェアは1秒あたりに多くの小パケットを処理できるにもかかわらず、このため、適応的な割り込み制御アルゴリズムが実装されました。

7.3.x以降、ドライバはトラフィックの種類に応じてInterruptThrottleRate値を動的に調整する2つの適応モード（設定1または3）をサポートしています。過去のタイムフレームで受信したトラフィックの種類を判定した後、そのトラフィックに適したInterruptThrottleRate値に調整します。

このアルゴリズムは、インターバルごとに受信トラフィックを3つのクラスに分類します。「Bulk traffic（大容量トラフィック）」は通常サイズのパケットが多数含まれる場合、「Low latency（低レイテンシー）」は少量のトラフィックや小パケットが大幅に含まれる場合、「Lowest latency（最低レイテンシー）」はほぼすべて小パケットまたは極めて少ないトラフィックの場合です。

動的コンサービティブモードでは、「Bulk traffic」に該当するトラフィックにはInterruptThrottleRate値を4000に設定します。一方、「Low latency」または「Lowest latency」に該当するトラフィックでは、InterruptThrottleRate値を段階的に20000に増加させます。このデフォルトモードはほとんどのアプリケーションに適しています。

クラスターやグリッドコンピューティングなど、低レイテンシーが極めて重要な状況では、InterruptThrottleRateをモード1に設定することでさらにレイテンシーを低減できます。このモードはモード3と同様の動作をし、「Lowest latency」に該当するトラフィックではInterruptThrottleRate値を段階的に70000に増加させます。

簡略モードでは、割り込み率はTXとRXトラフィックの比率に基づきます。1秒あたりのバイトレートがほぼ同じ場合、割り込み率は2000にまで低下します。トラフィックが主に送信または受信の場合、割り込み率は8000に達する可能性があります。

InterruptThrottleRateを0に設定すると、割り込み制御が無効になり、小パケットのレイテンシーが改善される可能性がありますが、大容量トラフィックには一般的に不適です。

ノート:

InterruptThrottleRateはTxAbsIntDelayおよびRxAbsIntDelayパラメータよりも優先されます。つまり、受信および/または送信の絶対遅延を最小化しても、Interrupt Throttle Rateが許可する以上の割り込みをコントローラーに強制することはできません。

注意:

Intel(R) PRO/1000 CT Network Connection (コントローラー82547)を使用している場合、InterruptThrottleRateを75,000以上に設定すると、特定のネットワーク環境でアダプターが停止してしまい（送信を停止）、システムイベントログにNETDEV WATCHDOGメッセージが記録されます。また、コントローラーは自動的にリセットされ、ネットワーク接続が復元されます。この停止の可能性を排除するため、InterruptThrottleRateは75,000以上に設定せず、0に設定しないようにしてください。

ノート:

e1000がデフォルト設定でロードされ、複数のアダプターが同時に使用されている場合、CPU利用率が非線形に増加する可能性があります。全体的なスループットに影響を与えることなくCPU利用率を制限するためには、ドライバを以下の通りロードすることをお勧めします：

modprobe e1000 InterruptThrottleRate=3000,3000,3000

これは、ドライバの最初のインスタンス、2番目のインスタンス、3番目のインスタンスそれぞれに対してInterruptThrottleRateを3000インタラプト/秒に設定します。2000から3000インタラプト/秒の範囲はほとんどのシステムで動作し、良い初期値ですが、最適な値はプラットフォームに依存します。CPU利用率が問題でなければ、RX_POLLING (NAPI)とデフォルトのドライバ設定を使用してください。

RxDescriptors¶

有効な範囲

  • 82542および82543ベースのアダプターでは48-256、

  • 他のすべてのサポートされているアダプターでは48-4096

デフォルト値

256

この値はドライバが割り当てる受信バッファディスクリプタの数を指定します。この値を増やすと、ドライバがより多くの受信パケットをバッファリングできるようになりますが、システムメモリの使用量が増加します。

各ディスクリプタは16バイトです。各ディスクリプタに対して受信バッファも割り当てられ、MTU設定に応じて2048、4096、8192、または16384バイトのいずれかになります。最大MTUサイズは16110です。

ノート:

MTUはフレームサイズを指定します。ジャンボフレームの設定が必要です。システムリソースに応じて、より多くの受信ディスクリプタの要求が拒否される場合があります。その場合は、より少ない数を使用してください。

RxIntDelay¶

有効な範囲

0-65535（0=オフ）

デフォルト値

0

この値は受信インテラプトの生成を1.024マイクロ秒単位で遅らせます。適切に調整すれば、特定のネットワークトラフィックに対してCPU効率を向上させる可能性があります。この値を増やすとフレーム受信に追加のレイテンシーが発生し、TCPトラフィックのスループットが低下する可能性があります。システムが受信をドロップしている場合、この値が高すぎる可能性があり、ドライバが利用可能な受信ディスクリプタを枯渇してしまう原因となるかもしれません。

注意:

RxIntDelayを0以外の値に設定した場合、特定のネットワーク環境ではアダプターが停止して通信を停止する可能性があります。このような場合、システムイベントログにNETDEV WATCHDOGメッセージが記録されます。また、コントローラーが自動的にリセットされ、ネットワーク接続が復元されます。ハングの可能性を排除するためには、RxIntDelayを0に設定してください。

RxAbsIntDelay¶

(このパラメータは82540、82545以降のアダプターのみサポートしています。)

有効な範囲

0-65535（0=オフ）

デフォルト値

128

この値は1.024マイクロ秒単位で、受信割込みが生成されるまでの遅延を制限します。RxIntDelayが0でない場合にのみ有効で、初期パケットが設定された時間内に受信された後に割込みが生成されるようにします。適切な調整を行うことで、特定のネットワーク環境でのトラフィックスループットを向上させることが可能です。

速度¶

(このパラメータは銅線接続のアダプターのみサポートしています。)

有効な設定

0, 10, 100, 1000

デフォルト値

0（すべてのサポート速度で自動交渉）

Speedは、メガビット毎秒（Mbps）単位でライン速度を指定された値に強制します。このパラメータが指定されていないか、0に設定されており、リンクパートナーが自動交渉に設定されている場合、ボードは正しい速度を自動検出します。Speedを10または100に設定する場合は、_duplexも同時に設定する必要があります。

TxDescriptors¶

有効な範囲

  • 82542および82543ベースのアダプターでは48-256、

  • 他のすべてのサポートされているアダプターでは48-4096

デフォルト値

256

この値はドライバが割り当てた送信ディスクリプタの数です。この値を増やすことで、ドライバがより多くの送信をキューイングできるようになります。各ディスクリプタは16バイトです。

ノート:

システムリソースによっては、より多くの送信ディスクリプタの要求が拒否される場合があります。その場合は、低い数値を使用してください。

TxIntDelay¶

有効な範囲

0-65535（0=オフ）

デフォルト値

8

この値は送信割込みの生成を1.024マイクロ秒単位で遅延させます。適切に調整すれば、特定のネットワークトラフィックにおいてCPU効率を向上させることが可能です。システムが送信が失われていると報告している場合、この値が高すぎる可能性があり、ドライバが利用可能な送信ディスクリプタを枯渇させる原因となることがあります。

TxAbsIntDelay¶

(このパラメータは82540、82545以降のアダプターのみサポートしています。)

有効な範囲

0-65535（0=オフ）

デフォルト値

32

この値は1.024マイクロ秒単位で、送信割込みが生成されるまでの遅延を制限します。TxIntDelayが0でない場合にのみ有効で、初期パケットが設定された時間内にワイヤー上に送信された後に割込みが生成されるようにします。適切な調整を行うことで、特定のネットワーク環境でのトラフィックスループットを向上させることが可能です。

XsumRX¶

(このパラメータは82542ベースのアダプターではサポートされていません。)

有効な範囲

0-1

デフォルト値

1

値が「1」の場合は、ドライバが受信パケット（UDPおよびTCP）のIPチェックサムオフロードをアダプターのハードウェアに有効にする必要があります。

Copybreak¶

有効な範囲

0-xxxxxxx (0=オフ)

デフォルト値

256

使い方

modprobe e1000.ko copybreak=128

ドライバは、このサイズ以下のすべてのパケットを新しいRXバッファにコピーしてからスタック上へ渡します。

このパラメータは、他のパラメータとは異なり、すべてのドライバインスタンスに単一のパラメータとして適用され、/sys/module/e1000/parameters/copybreakでもランタイムに利用可能です。

SmartPowerDownEnable¶

有効な範囲

0-1

デフォルト値

0 (無効)

PHYが低消費電力状態でオフになることを許可します。ユーザーはサポートされているチップセットでこのパラメータを無効化できます。

速度とフル デュプレックス設定¶

速度と双方向通信の設定を制御するためには3つのキーワードを使用します。これらのキーワードはSpeed、Duplex、およびAutoNegです。

ボードがファイバーインターフェースを使用する場合、これらのキーワードは無視され、ファイバーインターフェースボードは常に1000 Mbpsフルダイレクトリンクで接続します。

銅ベースのボードでは、キーワードは以下のようになります：

  • デフォルトでは自動交渉が行われます。ボードはすべてのサポートされる速度と双方向通信の組み合わせを宣伝し、リンクパートナーが自動交渉を設定している場合、最高の共通速度と双方向通信モードで接続します。

  • Speed = 1000の場合、制限付き自動交渉が有効になり、1000 Mbpsのみが宣伝されます（1000BaseT仕様では自動交渉が必要です）。

  • Speed = 10または100の場合、SpeedとDuplexの両方を設定する必要があります。自動交渉は無効になり、AutoNegパラメータは無視されます。リンクパートナーにも強制的に設定する必要があります。

AutoNegパラメータは、自動交渉プロセスに対してより細かい制御が必要な場合に使用します。自動交渉中に宣伝される速度と双方向通信の組み合わせを指定したい場合に使用します。

追加の設定¶

ジャンボフレーム¶

ジャンボフレームのサポートは、MTUをデフォルトの1500より大きい値に変更することで有効になります。ifconfigコマンドを使用してMTUサイズを増やすことができます。例えば：

ifconfig eth<x> mtu 9000 up

この設定は再起動後に保持されません。永続的に設定するには、以下の行をファイル /etc/sysconfig/network-scripts/ifcfg-eth<x> に追加してください。

MTU=9000

この例はRed Hatディストリビューションに適用されます。他のディストリビューションでは設定ファイルの場所が異なります。

注意：

Jumbo frames環境ではスループット性能の劣化が観測される場合があります。このような状況が確認された場合は、アプリケーションのソケットバッファサイズを増やすことや、/proc/sys/net/ipv4/tcp_*memエントリの値を増やすことで改善される可能性があります。詳細については、特定のアプリケーションのマニュアルおよび/usr/src/linux*/Documentation/networking/ip-sysctl.txtを参照してください。

  • Jumbo Framesの最大MTU設定は16110です。これはJumbo Framesの最大サイズ16128に一致します。

  • 10または100MbpsでJumbo framesを使用することはサポートされておらず、パフォーマンス低下やリンクの喪失を引き起こす可能性があります。

  • Intel(R) 82542および82573V/EコントローラーベースのアダプターはJumbo Framesをサポートしていません。これらは以下の製品名に対応します：

    Intel(R) PRO/1000 Gigabit Server Adapter
Intel(R) PRO/1000 PM Network Connection

ethtool¶

ドライバーはethtoolインターフェースを使用してドライバーの設定と診断、統計情報の表示を行います。この機能にはethtoolバージョン1.6以降が必要です。

最新のethtoolは以下の場所から入手可能です https://www.kernel.org/pub/software/network/ethtool/

Wake on LAN（WoL）の有効化¶

WoLはethtoolユーティリティを通じて設定されます。

このドライバーバージョンでは、システムの次回シャットダウンまたは再起動時にWoLが有効になります。WoLを有効にするには、シャットダウンまたは再起動時にe1000ドライバをロードする必要があります。
