Marvell(Aquantia) AQtion Driver¶

aQuantia マルチギガビットPCI Expressファミリーエスカレート イーサネットアダプター

アダプターの特定¶

このリリースのドライバーは、AQC-100、AQC-107、AQC-108ベースのイーサネットアダプターと互換性があります。

SFP+デバイス（AQC-100ベースのアダプター用）¶

このリリースは、パッシブなダイレクトアタッチケーブル（DAC）およびSFP+/LC光学トランシーバーでテストされました。

設定¶

リンクメッセージの表示¶

ディストリビューションがシステムメッセージを制限している場合、リンクメッセージはコンソールに表示されません。ネットワークドライバーリンクメッセージをコンソールで確認するには、次のコマンドを入力してdmesgを8に設定してください：

dmesg -n 8

注意

この設定は再起動後に保持されません。

ジャンボフレーム¶

ドライバーはすべてのアダプターでジャンボフレームをサポートしています。ジャンボフレームのサポートを有効にするには、MTUをデフォルトの1500より大きい値に変更します。MTUの最大値は16000です。使用するには、 ip コマンドでMTUサイズを増やす。例：

ip link set mtu 16000 dev enp1s0

ethtool¶

ドライバーは、ドライバーの設定と診断、統計情報の表示にethtoolインターフェースを使用します。この機能には最新のethtoolバージョンが必要です。

NAPI¶

NAPI（Rxポーリングモード）はatlanticドライバーでサポートされています。

割込みコールスイーニングのサポート¶

ITRモード、TX/RXコールスイーニングタイミングは次のコマンドで確認できます：

ethtool -c <ethX>

および変更するには：

ethtool -C <ethX> tx-usecs <usecs> rx-usecs <usecs>

コールスイーニングを無効にするには：

ethtool -C <ethX> tx-usecs 0 rx-usecs 0 tx-max-frames 1 tx-max-frames 1

Wake on LANのサポート¶

マジックパケットによるWOLサポート：

ethtool -s <ethX> wol g

WOLを無効にするには：

ethtool -s <ethX> wol d

RXフロー規則（ntupleフィルタ）¶

以下の順序で適用される別個の規則がサポートされています:

  1. 16つのVLAN ID規則

  2. 16つのL2 EtherType規則

  3. 8つのL3/L4 5-Tuple規則

ドライバはethtoolインターフェースを介してntupleフィルタを設定します。 ethtool -N <device> <filter>.

RXフロー規則を有効にするか無効にするには:

ethtool -K ethX ntuple <on|off>

ntupleフィルタを無効にする場合、すべてのユーザーが設定したフィルタはドライバキャッシュおよびハードウェアからクリアされます。ntupleを再有効にする際には、すべての必要なフィルタを再追加する必要があります。

規則の固定順序により、フィルタの位置も固定されています:

  • 位置0〜15はVLAN IDフィルタ

  • 位置16〜31はL2 EtherTypeフィルタ

  • 位置32〜39はL3/L4 5-tupleフィルタ（IPv6の場合、位置32、36）

L3/L4 5-tuple（プロトコル、送信元および宛先IPアドレス、送信元および宛先TCP/UDP/SCTPポート）は8つのフィルタと比較されます。IPv4では最大8つの送信元および宛先アドレスを一致させることができます。IPv6では最大2つのアドレスペアをサポートできます。送信元および宛先ポートはTCP/UDP/SCTPパケットのみ比較されます。

パケットをキュー5に転送するフィルタを追加するには <-N|-U|--config-nfc|--config-ntuple> switch:

ethtool -N <ethX> flow-type udp4 src-ip 10.0.0.1 dst-ip 10.0.0.2 src-port 2000 dst-port 2001 action 5 <loc 32>

  • actionはキュー番号です。

  • locはルール番号です。

For flow-type ip4|udp4|tcp4|sctp4|ip6|udp6|tcp6|sctp6 loc番号は32〜39の範囲内で設定する必要があります。IPv4の場合 flow-type ip4|udp4|tcp4|sctp4|ip6|udp6|tcp6|sctp6 IPv4トラフィックには8つのルールを設定できます。IPv6トラフィックには2つのルールを設定できます。IPv6トラフィックのloc番号は32と36です。現在、IPv4とIPv6のフィルタを同時に使用することはできません。

IPv6フィルタトラフィックの例:

sudo ethtool -N <ethX> flow-type tcp6 src-ip 2001:db8:0:f101::1 dst-ip 2001:db8:0:f101::2 action 1 loc 32
sudo ethtool -N <ethX> flow-type ip6 src-ip 2001:db8:0:f101::2 dst-ip 2001:db8:0:f101::5 action -1 loc 36

IPv4フィルタトラフィックの例:

sudo ethtool -N <ethX> flow-type udp4 src-ip 10.0.0.4 dst-ip 10.0.0.7 src-port 2000 dst-port 2001 loc 32
sudo ethtool -N <ethX> flow-type tcp4 src-ip 10.0.0.3 dst-ip 10.0.0.9 src-port 2000 dst-port 2001 loc 33
sudo ethtool -N <ethX> flow-type ip4 src-ip 10.0.0.6 dst-ip 10.0.0.4 loc 34

actionを-1に設定すると、フィルタに一致するすべてのトラフィックが破棄されます。

actionの最大値は31です。

VLANフィルタ（VLAN ID）は16つのフィルタと比較されます。VLAN IDにはマスク0xF000を付与する必要があります。これはVLANフィルタとL2 Ethertypeフィルタ（UserPriority）を区別するためです。UserPriorityとVLAN IDは同じ「vlan」パラメータで渡されるためです。

VLAN 2001からのパケットをキュー5に転送するフィルタを追加するには:

ethtool -N <ethX> flow-type ip4 vlan 2001 m 0xF000 action 1 loc 0

L2 Ethertypeフィルタは、Ethertypeフィールドまたは802.1QのEthertypeおよびUser Priority（PCP）フィールドでパケットをフィルタリングできます。UserPriority（vlan）パラメータにはマスク0x1FFFを付与する必要があります。これはVLANフィルタとL2 Ethertypeフィルタ（UserPriority）を区別するためです。UserPriorityとVLAN IDは同じ「vlan」パラメータで渡されるためです。

優先度3のIP4パケットをキュー3にリダイレクトするフィルタを追加するには:

ethtool -N <ethX> flow-type ether proto 0x800 vlan 0x600 m 0x1FFF action 3 loc 16

現在のフィルタの一覧を確認するには:

ethtool <-u|-n|--show-nfc|--show-ntuple> <ethX>

テーブル自体からルールを削除できます。これは次のコマンドを使用して行います:

sudo ethtool <-N|-U|--config-nfc|--config-ntuple> <ethX> delete <loc>

  • locは削除するルール番号です。

Rx filtersは、フィルターテーブルをロードするインターフェースで、すべてのフローをキュー0にリダイレクトします。ただし、「action」を使用して代替のキューを指定した場合、フィルタ条件に一致するフローは適切なキューにリダイレクトされます。RX filtersはすべての2.6.30以降のカーネルでサポートされています。

UDP用RSS¶

現在、NICはフラグメント化されたIPパケットのRSSをサポートしていません。これにより、フラグメント化されたUDPトラフィックのRSS動作が正しくなりません。UDP用RSSを無効にするには、RX Flow L3/L4ルールを使用できます。

例:

ethtool -N eth0 flow-type udp4 action 0 loc 32

UDP GSOハードウェアオフロード¶

UDP GSOは、UDPヘッダーの割り当てをハードウェアにオフロードすることでUDP送信レートを向上させます。これには特別なユーザースペースソケットオプションが必要で、/kernel/tools/testing/selftests/net/で確認できます:

udpgso_bench_tx -u -4 -D 10.0.1.1 -s 6300 -S 100

100バイトサイズのUDPパケットを、単一の6300バイトのユーザーバッファから送信します。

UDP GSOは次の方法で設定されます:

ethtool -K eth0 tx-udp-segmentation on

プライベートフラグ（テスト用）¶

Atlanticドライバーはハードウェアのカスタム機能用のプライベートフラグをサポートしています:

$ ethtool --show-priv-flags ethX

Private flags for ethX:
DMASystemLoopback  : off
PKTSystemLoopback  : off
DMANetworkLoopback : off
PHYInternalLoopback: off
PHYExternalLoopback: off

例:

$ ethtool --set-priv-flags ethX DMASystemLoopback on

DMASystemLoopback: DMAホストループバック。PKTSystemLoopback: パケットバッファホストループバック。DMANetworkLoopback: DMAブロックのネットワーク側ループバック。PHYInternalLoopback: PHYの内部ループバック。PHYExternalLoopback: PHYの外部ループバック（ループバックイーサネットケーブルを使用）。

コマンドラインパラメータ¶

Atlanticドライバーで利用可能なコマンドラインパラメータは次の通りです:

aq_itr - インターポートスロットリングモード¶

許容値: 0, 1, 0xFFFF

デフォルト値: 0xFFFF

0

インターポートスロットリングを無効化します。

1

インターポートスロットリングを有効化し、指定されたTXおよびRXレートを使用します。

0xFFFF

自動スロットリングモード。ドライバーはリンク速度に基づいて最適なRXおよびTXインターポートスロットリング設定を選択します。

aq_itr_tx - TXインターポートスロットリングレート¶

許容値: 0 - 0x1FF

デフォルト値: 0

TX側のスロットリング（マイクロ秒単位）。アダプターは最大のインターポート遅延をこの値に設定します。最小のインターポート遅延はこの値の半分になります

aq_itr_rx - RXインターポートスロットリングレート¶

許容値: 0 - 0x1FF

デフォルト値: 0

RX側のスロットリング（マイクロ秒単位）。アダプターは最大のインターポート遅延をこの値に設定します。最小のインターポート遅延はこの値の半分になります

注意

ethtool -cを使用して実時間でITR設定を変更できます（以下を参照）

設定ファイルパラメータ¶

一部の微調整およびパフォーマンス最適化には、{source_dir}/aq_cfg.hファイルでいくつかのパラメータを変更できます。

AQ_CFG_RX_PAGEORDER¶

デフォルト値: 0

RXページオーバーライド。これは、各ディスクリプタに割り当てられるRXページ数（2の累乗の数）です。受信ディスクリプタのサイズは依然としてAQ_CFG_RX_FRAME_MAXで制限されます。

ページオーダーを増やすことで、ページの再利用がより効果的になります（IOMMUを有効にしたシステムでは実際の効果があります）。

AQ_CFG_RX_REFILL_THRES¶

デフォルト値: 32

RXリフィルしきい値。指定された空きディスクリプタ数が観測されるまで、RXパスは解放されたディスクリプタをリフィルしません。大きな値はページ再利用をより効果的にするかもしれませんが、パケットのドロップを引き起こす可能性もあります。

AQ_CFG_VECS_DEF¶

キューの数

有効範囲: 0 - 8（AQ_CFG_VECS_MAXまで）

デフォルト値: 8

この値は、システム上の利用可能なコア数によって制限されます。

AQ_CFG_IS_RSS_DEF¶

受信側スケーリングの有効/無効

この機能により、アダプターは複数のCPUコアに受信処理を分散させ、単一のCPUコアを過負荷から守ることができます。

有効値

0

無効化されている場合です。

1

enabled

デフォルト値: 1

AQ_CFG_NUM_RSS_QUEUES_DEF¶

受信側スケーリング用のキュー数

有効範囲: 0 - 8（AQ_CFG_VECS_DEFまで）

デフォルト値: AQ_CFG_VECS_DEF

AQ_CFG_IS_LRO_DEF¶

大規模受信オフロードの有効/無効

このオフロードにより、アダプターは複数のTCPセグメントを結合し、OSネットワークサブシステムに単一の結合された単位として通知します。

システムはエネルギー消費が少なくなりますが、パケット処理に遅延が生じます。

有効値

0

無効化されている場合です。

1

enabled

デフォルト値: 1

AQ_CFG_TX_CLEAN_BUDGET¶

1回のTX処理でクリーンアップする最大ディスクリプタ数。

デフォルト値: 256

aq_cfg.hファイルが変更された場合、ドライバを再ビルドする必要があります。
