このリリースでは¶

このファイルは、すべてのSynopsys(R) イーサネットコントローラー用のstmmac Linuxドライバーについて説明しています。

現在、このネットワークデバイスドライバーは、すべてのSTi埋め込みMAC/GMAC（7xxx/5xxx SoC）、SPEAr（arm）、Loongson1B（mips）およびXILINX XC2V3000 FF1152AMT0221 D1215994A VIRTEX FPGAボードをサポートしています。Synopsys Ethernet QoS 5.0 IPKもサポートされています。

DesignWare(R) Cores イーサネットMAC 10/100/1000 ユニバーサルバージョン3.70a（および以前のバージョン）およびDesignWare(R) Cores イーサネットQuality-of-Serviceバージョン4.0（および以降）が使用されています。また、DesignWare(R) Cores XGMAC - 10G イーサネットMACおよびDesignWare(R) Cores Enterprise MAC - 100G イーサネットMACも使用されています。

このドライバーは、プラットフォームバスとPCIの両方をサポートしています。

このドライバーは、以下のSynopsys(R) DesignWare(R) Cores イーサネットコントローラーおよび対応する最小バージョンと最大バージョンをサポートしています：

  • 送信元アドレス挿入 / 置換

  • エスイッチツールを使用したセルフトレステスト

カーネルの設定¶

カーネル設定オプションは CONFIG_STMMAC_ETH:

  • CONFIG_STMMAC_PLATFORM：はプラットフォームドライバを有効にするために使用されます。

  • CONFIG_STMMAC_PCI：はPCIドライバを有効にするために使用されます。

コマンドラインパラメータ¶

ドライバがモジュールとして構築されている場合、以下のオプションパラメータは、modprobeコマンドでコマンドラインに指定して使用されます（例：PCIモジュールの場合）：

modprobe stmmac_pci [<option>=<VAL1>,<VAL2>,...]

ドライバパラメータはコマンドライン引数で渡すことも可能です。

stmmaceth=watchdog:100,chain_mode=1

ドライバー情報と注意事項¶

送信プロセス¶

xmitメソッドは、カーネルがパケットを送信する必要があるときに呼び出されます。このメソッドはリング内の記述子を設定し、DMAエンジンにパケットが送信準備ができていることを通知します。

デフォルトでは、ドライバーは NETIF_F_SG フィールドのbitを設定し、 net_device 構造体のfeaturesフィールドのbitを設定し、スキャッターガather機能を有効化します。これは、チェックサムがハードウェアで実行可能なチップおよび設定では常に有効です。

コントローラーがパケットの送信を終えたら、タイマがスケジュールされ、送信リソースが解放されます。

受信プロセス¶

1つ以上のパケットが受信されると割り込みが発生します。割り込みはキューにされないため、ドライバーは受信プロセス中にリング内のすべての記述子をスキャンする必要があります。

これはNAPIに基づいています。そのため、割り込みハンドラは作業がある場合にのみ信号を送信し、その後終了します。その後、pollメソッドが将来の時点でスケジュールされます。

受信パケットはDMAによって、事前に割り当てられたソケットバッファのリストに保存され、memcpy（ゼロコピー）を避けるためです。

割り込み抑制¶

ドライバーは、3.50以前のチップでの受信においてNAPIを使用してDMA割り込みの数を抑制できます。新しいチップでは、HW RX Watchdogがこの抑制に使用されます。

抑制パラメータはethtoolを使用して調整できます。

WoL¶

GMAC、GMAC4/5およびXGMACコアで、マジックフレームおよびユニキャストフレームを通じたWake on LAN機能はサポートされています。

DMA記述子¶

ドライバーは通常の記述子と代替記述子の両方を処理します。代替記述子はDesignWare(R)コアのEthernet MAC Universalバージョン3.41a以降のみテストされています。

stmmacはDMA記述子を、ダブルバッファ（RING）モードおよびリンクリスト（CHAINED）モードの両方で動作させることができます。RINGモードでは各記述子が2つのデータバッファポインタを指し、CHAINEDモードでは1つのデータバッファポインタを指します。RINGモードがデフォルトです。

CHAINEDモードでは各記述子がリスト内の次の記述子へのポインタを持つため、記述子自体に明示的なリンクが形成されます。これに対してRINGモードでは明示的なリンクが不可能です。

拡張記述子¶

拡張記述子は、PTPパケットやTCP/UDP/ICMPをIP上に載せたEthernetペイロードに関する情報を提供します。これはGMAC Synopsys(R)チップで3.50以前のバージョンでは利用できません。プローブ時にドライバーがこれらを実際に使用できるかどうかを判断します。このサポートはPTPv2では必須であり、ハードウェアタイムスタンプと拡張ステータスを保存するために追加の記述子が使用されます。

ethtoolサポート¶

Ethtoolはサポートされています。たとえば、ドライバの統計情報（RMONを含む）や内部エラーは、以下のコマンドを使用して取得できます:

ethtool -S ethX

Ethtoolの自己診断もサポートされています。これにより、MACおよびPHYのループバックメカニズムを使用してハードウェアの初期チェックを行うことが可能です:

ethtool -t ethX

ジャンボフレームおよびセグメンテーションオフローディング¶

ジャンボフレームはGMACでサポートされておりテスト済みです。GSO（グラフィックセグメンテーションオフローディング）も追加されていますが、ソフトウェアで実行されます。LRO（リンクレイヤー統合）はサポートされていません。

TSOサポート¶

TSO（TCPセグメンテーションオフローディング）機能は、GMAC 4.x以上およびXGMACチップファミリでサポートされています。TCPプロトコルでパケットを送信する際、TCPスタックは、低レベルドライバ（stmmacの場合）に提供されるSKB（スクラブパケット）が最大フレーム長（IPヘッダ＋TCPヘッダ＋ペイロード≦1500バイト（MTUが1500に設定されている場合））に適合していることを保証します。これは、アプリケーションがTCPを使用して送信するパケットの長さ（ヘッダを加えた後）が1514バイトを超える場合、パケットが複数のTCPパケットに分割されるためです。データペイロードは分割され、ヘッダ（TCP/IPなど）が追加されます。この処理はソフトウェアによって行われます。

TSOが有効な場合、TCPスタックは最大フレーム長を気にせず、stmmacにSKBパケットをそのまま提供します。GMAC IPは、最大フレーム長に合わせてセグメンテーションを行う必要があります。

この機能はデバイスツリーを通じて有効化できます snps,tso エントリ。

エネルギー効率Ethernet（Energy Efficient Ethernet）¶

エネルギー効率Ethernet（EEE）は、IEEE 802.3 MACサブレイヤーおよび物理層ファミリを低消費電力アイドル（LPI）モードで動作させることを可能にします。EEEモードは、100Mbps、1000Mbps、1GbpsのIEEE 802.3 MAC操作をサポートします。

LPIモードは、データの送受信がないときに通信デバイスの一部機能をオフにすることで電力節約を実現します。リンクの両側のシステムは、低リンク利用率期間中に一部機能を無効化し電力を節約できます。MACはシステムがLPIモードに入るか退出するかを制御し、PHYにその情報を伝達します。

インターフェースが開かれた直後、ドライバはEEEがサポート可能かどうかを確認します。これはDMAハードウェア能力レジスタとPHYデバイスのMCDレジスタを確認することで行われます。

TX LPIモードに入るには、ドライバは送信が行われないときにLPIモードを有効化および無効化するソフトウェアタイマが必要です。

高精度時刻プロトコル（PTP）¶

ドライバはIEEE 1588-2002準拠の高精度時刻プロトコル（PTP）をサポートしており、ネットワーク通信などの技術を用いた測定・制御システムにおける時刻の正確な同期を可能にします。

IEEE 1588-2002のタイムスタンプ機能に加えて、新しいGMACコアは高度なタイムスタンプ機能をサポートしています。Kernelの設定時にIEEE 1588-2008を有効化できます。

SGMII/RGMIIサポート¶

新しいGMACデバイスはRGMII/SGMIIの管理方法を独自に提供します。この情報はハードウェア能力レジスタを確認することで実行時にも取得可能です。これにより、stmmacはPHYLIBを使用することなく自動交渉およびリンク状態の管理が可能になります。実際、ハードウェアはAN（自動交渉）を再実行し、フル/ハーフ duplexモードおよび速度を確認するための拡張レジスタのサブセットを提供します。これらのレジスタにより、自動交渉されたリンクパートナーの能力を確認することが可能です。

物理¶

ドライバーはPHYおよびGPHYデバイスと接続するための物理抽象層との互換性を有しています。

HWの機能¶

新しいチップから、HW機能レジスタが利用可能な場合、多くの設定は実行時に発見されます。たとえば、EEE、HW csum、PTP、拡張デスクリプタなどが実際に利用可能かどうかを理解するためです。このドライバーでは、HW機能レジスタからの情報がプラットフォームから渡された情報に置き換わる戦略を採用しています。

デバッグ情報¶

ドライバーは多くの情報をエクスポートします。たとえば内部統計情報、デバッグ情報、MACおよびDMAレジスタなどがあります。

必要な情報の種類によって、いくつかの方法で読み取ることができます。

たとえば、ユーザーはethtoolのサポートを使用して統計情報を取得できます。たとえば、以下のように: ethtool -S ethX (MMCがサポートされている場合、管理カウンタを表示) または MAC/DMAレジスタを確認できます。たとえば、以下のように: ethtool -d ethX

カーネルをコンパイルする際の CONFIG_DEBUG_FS ドライバーは以下のdebugfsエントリをエクスポートします:

  • descriptors_status: DMA TX/RXディスクリプタリングを表示するため

  • dma_cap: HW Capabilitiesを表示するため

開発者はまた、 debug module parameterを使用してさらに詳細なデバッグ情報を取得できます（詳しくは: NETIF Msg Levelを参照してください）。

サポート¶

サポートされているカーネルとサポートされているアダプターでリリースされたソースコードに問題が発覚した場合、該当する問題に関する特定の情報をメールで送信してください netdev@vger.kernel.org
