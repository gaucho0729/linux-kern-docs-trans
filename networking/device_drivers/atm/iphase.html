ATM (i)Chip IA Linuxドライバソース¶

最初に読みましょう

開始する前にこのファイルを読みましょう！

説明¶

これはInterphase PCI ATM (i)Chip IA Linux ドライバソースリリース用のREADMEファイルです。

このドライバの特徴および制限事項は以下の通りです：

  • 単一のVPI（VPI値が0）をサポートしています。

  • サーバーボード（制御メモリ512K）で4KのVC、クライアントボード（制御メモリ128K）で1KのVCをサポートしています。

  • UBR、ABRおよびCBRサービスカテゴリをサポートしています。

  • のみAAL5をサポートしています。

  • VCにおけるPCRの設定をサポートしています。

  • システム内の複数のアダプターをサポートしています。

  • すべてのInterphase ATM PCI (i)Chipアダプターカードの変種をサポートしています。x575（OC3、制御メモリ128K、512Kおよびパケットメモリ128K、512Kおよび1M）、x525（UTP25）およびx531（DS3およびE3）を含みます。参照 http://www.iphase.com/ 詳しくは以下をご参照ください。

  • のみx86プラットフォームをサポートしています。

  • SMPをサポートしています。

開始する前に¶

インストール¶

  1. システムへのアダプタのインストール

    システムにATMアダプタをインストールするには、以下の手順を実行してください。

    1. rootとしてログインしてください。

    2. システムをシャットダウンし、電源を切ってください。

    3. システム内に1つまたは複数のATMアダプタをインストールしてください。

    4. 各アダプタをATMスイッチのポートに接続してください。システム電源を投入した際にアダプタがスイッチに正しく接続されている場合、アダプタの前面パネルにある緑色の「リンク」LEDが点灯します。

    5. システムを電源投入し、起動してください。

  2. [ 削除済み ]

  3. ABRサポートを含むカーネルを再構築

    [ a. および b. 削除済み ]

    1. カーネルを再構成し、「make menuconfig」または「make xconfig」を通じてInterphase iaドライバを選択してください。

    2. カーネル、ロード可能なモジュールおよびatmツールを再構築してください。

    3. 新しい構築カーネルおよびモジュールをインストールし、再起動してください。

  4. iaドライバがモジュールとして構築されている場合、アダプタハードウェアドライバ（iaドライバ）をロードしてください

    1. rootとしてログインしてください。

    2. /lib/modules/<kernel-version>/atm ディレクトリに移動してください。

    3. 「insmod suni.o; insmod iphase.o」を実行してください。ドライバがシステムにロードされる間、アダプタの前面パネルにある黄色の「ステータス」LEDが点滅します。

    4. 「ia」ドライバが正常にロードされているかを確認するには、以下のコマンドを実行してください：

      cat /proc/atm/devices

      ドライバが正常にロードされている場合、コマンドの出力は以下の行に似ています：

      Itf Type    ESI/"MAC"addr AAL(TX,err,RX,err,drop) ...
0   ia      xxxxxxxxx  0 ( 0 0 0 0 0 )  5 ( 0 0 0 0 0 )

      また、ATMドライバに関するメッセージを確認するには、システムログファイル /var/log/messages を確認してください。

これらの設定はほとんどの環境で動作しますが、以下のコマンドを入力することで変更できます。

insmod <IA_DIR>/ia.o IA_RX_BUF=<RX_CNT> IA_RX_BUF_SZ=<RX_SIZE> \
        IA_TX_BUF=<TX_CNT> IA_TX_BUF_SZ=<TX_SIZE>

以下では:

  • RX_CNT = 受信バッファの数（1〜128）

  • RX_SIZE = 受信バッファのサイズ（48〜64K）

  • TX_CNT = 送信バッファの数（1〜128）

  • TX_SIZE = 送信バッファのサイズ（48〜64K）

  1. 送信および受信バッファのサイズは4の倍数でなければなりません。

  2. 送信および受信バッファに必要なメモリがアダプタのパケットメモリの総量以下になるように注意する必要があります。

5.2 iaデバッグトレースを有効にする

iaドライバがCONFIG_ATM_IA_DEBUGフラグでビルドされている場合、必要な場合にデバッグトレースを提供できます。IADebugFlagというビットマスク変数でトレースの出力を制御します。IADebugFlagのビットマップはiphase.hにあります。デバッグトレースを有効にするには、insmodコマンドラインオプションを使用します。たとえば、「insmod iphase.o IADebugFlag=0xffffffff」はドライバをロードしながらすべてのデバッグトレースを有効にします。

  1. ttcp_atmおよびPVCを使用したIaドライバのテスト

    PVCの設定では、テスト機器はバックトーバックで接続するか、スイッチを通じて接続できます。スイッチを通じて接続する場合、スイッチはPVC（複数可）に設定する必要があります。

    1. UBRテストの場合:

      データを受信するテスト機器で、以下を入力してください:

      ttcp_atm -r -a -s 0.100

      もう一方のテスト機器で、以下を入力してください:

      ttcp_atm -t -a -s 0.100 -n 10000

      「ttcp_atm -h」を実行して、ttcp_atmツールのオプションを表示します。

    2. ABRテストの場合:

      UBRテストと同じですが、追加のコマンドオプションがあります:

      -Pabr:max_pcr=<xxx>

      where:

      xxx = 最大ピークセルレート（170〜353207）

      このオプションは両方の機器で設定する必要があります。

    3. CBRテストの場合:

      UBRテストと同じですが、追加のコマンドオプションがあります:

      -Pcbr:max_pcr=<xxx>

      where:

      xxx = 最大ピークセルレート（170〜353207）

      このオプションは送信機器のみで設定できます。
