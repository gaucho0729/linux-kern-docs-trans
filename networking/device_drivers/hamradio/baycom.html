Linux用Baycomモデムドライバ¶

トーマス・M・セイラー, HB9JNX/AE4WA, <sailer@ife.ethz.ch>sailer@ife.ee.ethz.ch>

baycomモデムのドライバは、コードを共有しないため、個別のドライバに分割されました。ドライバおよびデバイス名も変更されています。

このドキュメントは、シンプルなBaycomスタイルのアマチュア無線モデム用のLinuxカーネルドライバについて説明しています。

以下のドライバが利用可能です：¶

baycom_ser_fdx:

このドライバは、フルダブルックスまたはハーフダブルックスでSER12モデムをサポートします。ボーレートはモジュールパラメータを通じて変更可能であり、シリアルポート上のほぼすべてのビットバングモデムをサポートします。デバイス名はbcsf0からbcsf3までです。これはSER12タイプのモデムに推奨されるドライバですが、動作しないデルタステータスビットを持つ破損したUARTクローンがある場合、baycom_ser_hdxを試すこともできます。 baud module parameter

baycom_ser_hdx:

これはSER12型モデム用の代替ドライバーです。半二重通信のみをサポートし、1200 baudのみをサポートします。そのデバイスはbcsh0からbcsh3と呼ばれます。baycom_ser_fdxドライバーがUARTで動作しない場合にのみこのドライバーを使用してください。

baycom_par:

このドライバーはpar96およびpicparモデムをサポートします。そのデバイスはbcp0からbcp3と呼ばれます。

baycom_epp:

このドライバーはEPPモデムをサポートします。そのデバイスはbce0からbce3と呼ばれます。このドライバーは進行中の開発です。

以下のモデムがサポートされています:

ser12

これは非常にシンプルな1200 baud AFSKモデムです。モデムは単なる変調器/復調器チップ（通常はTI TCM3105）のみで構成されており、コンピュータが受信ビットクロックを再生成し、HDLCプロトコルを処理します。モデムはシリアルポートに接続されるため、この名前が付けられています。シリアルポートは非同期シリアルポートとして使用されないため、シリアルポート用のカーネルドライバーを使用できません。このドライバーは標準シリアルハードウェア（8250、16450、16550）のみをサポートします。

par96

これは9600 baud FSKでG3RUH標準に準拠したモデムです。モデムはすべてのフィルタリングと受信クロックの再生成を行います。データはシフトレジスタを介してPCとやり取りされ、シフトレジスタは16ビットに満たされ、割り込みが送信されます。PCはその後、シフトレジスタを一気に空にします。このモデムはパラレルポートに接続されるため、この名前が付けられています。モデムはHDLCプロトコルの実装とスクランブラー多項式の処理をPCに委譲します。

picpar

これはHenning Rech氏（DF9IC）が設計したpar96モデムのリデザインです。このモデムはpar96とプロトコル互換ですが、低消費電力ICを3つのみ使用しており、パラレルポートから電源供給可能で追加の電源供給が不要です。さらに、キャリア検出回路を搭載しています。

EPP

これは拡張されたパラレルポートに接続する高速モデムアダプターです。

対象ユーザーは、高速ハブ（76.8kbit/s）を介して作業するユーザーです。

eppfpga

これはEPPアダプターのリデザインです。

上記のすべてのモデムは半二重通信のみをサポートしています。しかし、ドライバーはKISS（以下参照）をサポートするフルダイヤルコマンドを備えており、パケットを送信するたびに即座に送信を開始し、DCD（データキャリア検出）を気にせず送信します。つまり、チャネルに他のユーザーがいる場合でも送信を開始します。このコマンドはDAMAチャネルアクセスプロトコルの一部実装で必要です。

ドライバーのインターフェース¶

以前のドライバーとは異なり、これらはもはやキャラクターデバイスではなく、カーネルネットワークインターフェースとして動作します。インストールは簡単です。インストール後、bc{sf,sh,p,e}[0-3]という4つのインターフェースが利用可能です。ax25ユーティリティからsethdlcを使用してドライバーの状態を設定できます。ユーザー層のAX.25スタックを使用するユーザーは、net2kissユーティリティ（ax25ユーティリティパッケージにも含まれています）を使用してネットワークインターフェースのパケットを擬似tty上のKISSストリームに変換できます。また、WAMPES用のパッチも提供しており、カーネルネットワークインターフェースを直接接続可能です。

ドライバーの設定¶

ドライバーをカーネルに挿入するたびに、どのポートでどのモデムにアクセスするかを指定する必要があります。これはsetbaycomユーティリティで行えます。1つのモデムのみを使用する場合、insmodコマンドライン（または、 /etc/modprobe.d/*.conf).

例:

modprobe baycom_ser_fdx mode="ser12*" iobase=0x3f8 irq=4
sethdlc -i bcsf0 -p mode "ser12*" io 0x3f8 irq 4

両行は、最初のポートをser12モデムでドライブする設定です（DOSではCOM1）。modeパラメータの*はドライバーにソフトウェアDCDアルゴリズムを使用するよう指示します（以下参照）：

insmod baycom_par mode="picpar" iobase=0x378
sethdlc -i bcp0 -p mode "picpar" io 0x378

両行は、最初のポートをpicparモデムでドライブする設定です（DOSではLPT1）。(注：picparはハードウェアDCDを、par96はソフトウェアDCDを意味します）。

チャネルアクセスパラメータはsethdlc -aまたはkissparmsで設定可能です。注意点として、両ユーティリティは値の解釈がやや異なります。

ハードウェアDCDとソフトウェアDCDの違い¶

空中的衝突を避けるため、ドライバーはチャネルが忙しいかどうかを把握する必要があります。これはDCD回路/ソフトウェアの役割です。ドライバーは、ソフトウェアのDCDアルゴリズム（options=1）を使用するか、ハードウェアのDCD信号（options=0）を使用するかを選択できます。

ser12

ソフトウェアDCDを使用する場合、ラジオのスquelch（静音）は常に開けた状態にする必要があります。ソフトウェアDCDアルゴリズムを使用することを強く推奨します。なぜなら、これはほとんどのハードウェアスquelch回路よりもはるかに高速だからです。ただし、システムへの負荷がやや高くなるというデメリットがあります。

par96

このタイプのモデムにおけるソフトウェアDCDアルゴリズムはあまりにも弱いです。モデムは、ソフトウェアで合理的なDCDアルゴリズムを実装するための十分な情報を提供していません。したがって、あなたのラジオがPAR96モデムのDCD入力に信号を供給する場合、ハードウェアDCD回路の使用を推奨します。

picpar

picparモデムは組み込みのDCDハードウェアを備えており、これは強く推奨されます。

Linuxカーネルとの互換性¶

シリアルドライバーとbaycomシリアルドライバーは同じハードウェアリソースを競合します。もちろん、一度に1つのドライバーしかインターフェースにアクセスできません。シリアルドライバーは起動時に見つかったすべてのインターフェースにアクセスします。そのため、baycomドライバーはその後シリアルポートにアクセスできなくなります。したがって、シリアルドライバーが所有するポートを解放する必要があるかもしれません。その際、「setserial /dev/ttyS# uart none」というコマンドで、#はインターフェース番号を指定します。baycomドライバーは起動時にポートを予約しません（指定された場合は除く）。問題を解決するもう一つの方法は、すべてのドライバーをモジュールとしてコンパイルし、kmodがアプリケーションに応じて正しいドライバーをロードするようにすることです。

パラレルポートドライバー（baycom_par、baycom_epp）は現在、parportサブシステムを使用して、異なるクライアントドライバー間でポートを仲裁します。
