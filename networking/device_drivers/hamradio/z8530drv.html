1. ドライバの初期化¶

ドライバーを使用するには、以下の3つの手順を実行する必要があります:

  1. モジュールとしてコンパイルされている場合: モジュールをロードする

  2. ハードウェア、モデムおよびKISSパラメータの設定はsccinitを使用して行います

  3. 各チャネルをLinuxカーネルのAX.25に接続するには、「ifconfig」を使用します

2.4以下のバージョンとは異なり、このドライバーはリアルなネットワークデバイスドライバーです。xNOSを実行する代わりに私たちの優れたカーネルAX.25を使用する場合は、上記のサイトから入手可能な2.xバージョンを使用するか、AX.25-HOWTOを参照してネットワークデバイスドライバーでKISS TNCをエミュレートする方法を確認してください

1.1 モジュールのロード¶

(ドライバーをカーネルイメージの一部としてコンパイルする場合、

この章をスキップし、1.2に進んでください)

モジュールを使用する前に、以下のコマンドでロードする必要があります:

insmod scc.o

module-init-toolsに同梱されている「man insmod」を読みましょう

insmodを/etc/rc.d/rc.*のいずれかのファイルに含め、その後にsccinitの呼び出しを追加してください。これは/etc/z8530drv.confを読み込みます

1.2. /etc/z8530drv.conf¶

すべてのパラメータを設定するには、rc.*ファイルのいずれかから/sbin/sccinitを実行する必要があります。インターフェースを「ifconfig」で設定する前にこれを実行する必要があります。Sccinitは/etc/z8530drv.confを読み込み、ハードウェア、モデムおよびKISSパラメータを設定します。このパッケージに同梱されているサンプルファイルを自分の環境に合わせて変更してください

このファイルは2つの主要なセクションから構成されています

1.2.1 ハードウェアパラメータの設定¶

ハードウェア設定セクションでは、各Z8530に対して以下のパラメータを定義します

chip    1
data_a  0x300                   # data port A
ctrl_a  0x304                   # control port A
data_b  0x301                   # data port B
ctrl_b  0x305                   # control port B
irq     5                       # IRQ No. 5
pclock  4915200                 # clock
board   BAYCOM                  # hardware type
escc    no                      # enhanced SCC chip? (8580/85180/85280)
vector  0                       # latch for interrupt vector
special no                      # address of special function register
option  0                       # option to set via sfr
チップ

  • これはsccinitを少し簡単にプログラムするための区切り文字です。パラメータは効果を持ちません

data_a

  • このZ8530のデータポートAのアドレス（必須）

ctrl_a

  • このZ8530の制御ポートAのアドレス（必須）

data_b

  • このZ8530のデータポートBのアドレス（必須）

ctrl_b

  • このZ8530の制御ポートBのアドレス（必須）

irq

  • このチップに使用するIRQ。異なるチップは異なるIRQまたは同じIRQを使用できます。共有する場合は、1つのチップ定義内で指定する必要があります

pclock - Z8530のPCLKピンのクロック（オプション、4915200は

デフォルト値）、Hz（ヘルツ）で測定

ボード

  • ボードの「type（タイプ）」:

    SCC type

    値

    PA0HZP SCC カード

    PA0HZP

    EAGLE カード

    EAGLE

    PC100 カード

    PC100

    PRIMUS-PC (DG9BL) カード

    PRIMUS

    BayCom (U)SCC カード

    BAYCOM
escc

  • ESCCチップ（8580、85180、85280）のサポートが必要な場合は、この値を「yes（イエス）」に設定してください（オプション、デフォルトは「no（ノ）」）

vector

  • PA0HZP カードのベクター・ラッチ（いわゆる「intack ポート」）のアドレス。すべてのチップに対して1つのベクター・ラッチしか存在しません！（オプション、デフォルトは0）

特殊

  • 複数のカードで使用される特殊機能レジスタのアドレス。（オプション、デフォルトは0）

オプション - そのレジスタに書き込む値（オプション、デフォルトは0）

最大4つのチップ（8チャネル）を指定できます。これで足りない場合は、次の行を:

#define MAXSCC 4

より高い値に変更してください。

ユーティリティ「gencfg」¶

PE1CHLドライバーのDOS用パラメータのみ知っている場合は、gencfgを実行してください。正しいポートアドレスが生成されるはずです（願わくば）。そのパラメータは、netで「attach scc」コマンドを使用する際のパラメータと完全に同じですが、「init」文字列は含まれません。例:

gencfg 2 0x150 4 2 0 1 0x168 9 4915200

OptoSCC用のz8530drv.confのスケルトンを標準出力に表示します。

gencfg 2 0x300 2 4 5 -4 0 7 4915200 0x10

BAYCOM USCCカードにも同じ動作を行います。私の意見ではscc_config.hを編集する方がはるかに簡単です…

1.2.2 チャネルの設定¶

チャンネル定義は、各チャンネルごとに3つのサブセクションに分かれています:

scc0の例:

# DEVICE

device scc0     # the device for the following params

# MODEM / BUFFERS

speed 1200              # the default baudrate
clock dpll              # clock source:
                        #       dpll     = normal half duplex operation
                        #       external = MODEM provides own Rx/Tx clock
                        #       divider  = use full duplex divider if
                        #                  installed (1)
mode nrzi               # HDLC encoding mode
                        #       nrzi = 1k2 MODEM, G3RUH 9k6 MODEM
                        #       nrz  = DF9IC 9k6 MODEM
                        #
bufsize 384             # size of buffers. Note that this must include
                        # the AX.25 header, not only the data field!
                        # (optional, defaults to 384)

# KISS (Layer 1)

txdelay 36              # (see chapter 1.4)
persist 64
slot    8
tail    8
fulldup 0
wait    12
min     3
maxkey  7
idle    3
maxdef  120
group   0
txoff   off
softdcd on
slip    off

これらのセクション内での順序は重要ではありません。これらのセクション間の順序は重要です。モデムパラメータは最初に認識されたKISSパラメータで設定されます…

ボードを起動（またはinsmod）後に一度だけ初期化できます。その後、「mode（モード）」と「clock（クロック）」以外のすべてのパラメータはSccparamプログラムやKISSを通じて変更可能です。セキュリティホールを防ぐためです…

  1. このディバイダーは通常SCC-PBC（PA0HZP）に搭載されており、BayComでは存在しない場合があります。これはDPLL（デジタルPLL）の出力を送信クロックとしてフィードバックします。ディバイダーをインストールせずにこのモードを使用すると、通常はmaxkeyが期限切れになるまでトランシーバーをキー操作しますが、何も送信しません（役に立ちません）。

2. あなたの AX.25 ソフトウェアによるチャネルの接続¶

2.1 カーネル AX.25¶

AX.25デバイスを設定するには、単に以下を入力してください:

ifconfig scc0 44.128.1.1 hw ax25 dl0tha-7

これにより、IPアドレス44.128.20.107と呼称「dl0tha」を持つネットワークインターフェースが作成されます。IPアドレスを持っていない場合は（まだ持っていない場合）、44.128.0.0ネットワーク内の任意のIPアドレスを使用できます。axattachは必要ありません。axattach（slattachと同様）の目的は、TTYに接続されたKISSネットワークデバイスを作成することです。ax25-utilsのドキュメンテーションとAX.25-HOWTOを参照し、カーネルのAX.25設定パラメータを学ぶことが推奨されます。

2.2 NOS, NET および TFKISS¶

TTYドライバ（KISS TNCエミュレーションとも呼ばれる）が削除されたため、古い動作をエミュレートする必要があります。これらのプログラムを使用するコストとして、カーネルのAX.25をコンパイルする必要があります（実際に使用するかどうかに関係なく）。まず、/etc/ax25/axportsを設定します。例えば：

9k6     dl0tha-9  9600  255 4 9600 baud port (scc3)
axlink  dl0tha-15 38400 255 4 Link to NOS

sccデバイスを「ifconfig」で設定します：

ifconfig scc3 44.128.1.1 hw ax25 dl0tha-9

次に、擬似TTYにaxattachします：

axattach /dev/ptys0 axlink

そしてNOSを起動し、/dev/ptys0に接続します。問題は、DAMA制御されたチャネルでは、カーネルのAX.25経由でのみNOSに接続可能であるため、深刻な問題です。この問題を解決するには、「rxecho」を設定し、「9k6」から「axlink」への受信フレームをエコーし、「axlink」から「9k6」への送信フレームをエコーさせ、以下のように起動します：

rxecho

あるいは、z8530drv-utilsに同梱されている「kissbridge」を使用します：

ifconfig scc3 hw ax25 dl0tha-9
kissbridge scc3 /dev/ptys0

3.2 パラメータの設定¶

エミュレートされたKISS TNCのパラメータ設定はSCCドライバでも同様に行います。パラメータを変更するには、ax25-utilsパッケージの「kissparms」プログラムを使用するか、「sccparam」プログラムを使用します：

sccparam <device> <paramname> <decimal-|hexadecimal value>

以下のパラメータを変更できます：

param

12

以下のパラメータは次の意味を持ちます:

speed:

このチャネルのボーレート（bps）

例: sccparam /dev/scc3 speed 9600

txdelay:

送信機がキーイングされた後、最初のバイトが送信されるまでの遅延（10ms単位）。これはTNCでは「TXDELAY」と呼ばれます。0を指定すると、ドライバはCTS信号がアサートされるのを待つだけになります。これはMODEMおよび/または送信機にタイマーやその他の回路が存在し、送信機がデータを受け入れる準備ができたらCTSをアサートするものと仮定しています。このパラメータの通常の値は30〜36です。

例: sccparam /dev/scc0 txd 20

persist:

チャネルが空いているときに送信機がキーイングされる確率です。値は0〜255で、確率は（値+1）/256です。値は50〜60程度に設定し、チャネルがより重く使用される場合は下げてください。

例: sccparam /dev/scc2 persist 20

slottime:

チャネルのサンプリング間隔です。10ms単位で表されます。約200〜300ms（値20〜30）が適切な値です。

例: sccparam /dev/scc0 slot 20

tail:

パケットの最後のバイトがSCCに転送された後、送信機がキーイングされたままになる時間です。これはCRCやフラグがSCCから送出されるまで送信機をキーイングし続ける必要があるためです。この値は選択されたボーレートに依存します。いくつかの文字時間程度で十分です（例: 1200bpsで40ms（値4））。このパラメータの値は10ms単位です。

例: sccparam /dev/scc2 4

full:

フルダブルダイナミックモードのスイッチです。これは次の値のいずれかを指定できます:

0: インターフェースはCSMAモードで動作します（通常の

ハーフダブルダイナミックパケット無線機動作）

1: フルダブルダイナミックモード、つまり、受信されたキャリアを確認せずにいつでも送信機がキーイングされます。

送信するパケットがなくなったときにキーイングが解除されます。

2: 1と同じですが、送信するパケットがなくなった場合でも送信機がキーイングされます。

その場合、フラグが送信されるまでタイムアウト（パラメータ10）が発生するまで送信されます。

例: sccparam /dev/scc0 fulldup off

wait:

フレームが送信キューに並ぶ後、送信試行前の初期待機時間です。これはCSMAモードでの最初のスロットの長さに相当します。フルダブルダイナミックモードではパフォーマンスを最大化するために0に設定されます。このパラメータの値は10ms単位です。

例: sccparam /dev/scc1 wait 4

maxkey:

送信機がパケットを送信するためにキーを押し続ける最大時間を秒単位で指定します。これは忙しいCSMAチャネルで、大量のトラフィックを生成する際に「悪い評判をつける」ことを防ぐために役立ちます。指定された時間経過後は新しいフレームが開始されなくなり、代わりに指定された時間（パラメータmin）の間送信機がオフになります。その後、キーupの選択されたアルゴリズムが再び開始されます。値0または「off」はこの機能を無効化し、無限の送信時間を許可します。

例: sccparam /dev/scc0 maxk 20

min:

最大送信時間超過時に送信機がオフになる時間を秒単位で指定します。

例: sccparam /dev/scc3 min 10

idle:

このパラメータは、フルダプル2モードにおける最大アイドル時間を秒単位で指定します。この時間以内にフレームが送信されなかった場合、送信機がキーを下げるようになります。値0はフルダプルモード1と同じ結果をもたらします。このパラメータは無効化可能です。

例: sccparam /dev/scc2 idle off # 無限に送信

maxdefer

空きチャネルを待つ最大時間（秒単位）を指定します。このタイマーが切れた場合、送信機は即座にキーを押し始めます。他のユーザーとトラブルを起こすのが好きであれば、この値を非常に低く設定してください ;-)

例: sccparam /dev/scc0 maxdefer 240 # 2分

txoff:

このパラメータが0の場合はパケットの送信が有効になります。それ以外の場合は無効になります。

例: sccparam /dev/scc2 txoff on

group:

複数の周波数を同じバンドで使用する特別な無線機器を構築することが可能です。例えば複数の受信機と1つの送信機を接続し、送信機を周波数間でスイッチングするなどです。また、同じバンドで動作する複数の無線機を接続することも可能です。このような場合、複数の周波数で送信することは不可能、または良くない考えです。SCCドライバは「param <interface> group <x>」コマンドを使用して、異なるインターフェースの送信機をロックする方法を提供します。これはCSMAモード（パラメータfull = 0）で使用する必要があります。

<x>の値が0の場合はグループ制限を無効にし、制限されたグループを生成するには以下の計算式で<x>を算出します：<x>はいくつかのオクタール数の論理ANDです。

200

他のグループ内の送信機がすべてオフになっているときにのみこの送信機がキーを押し始めます。

100

他のグループ内のインターフェースのキャリア検出がすべてオフになっているときにのみこの送信機がキーを押し始めます。

0xx

異なるグループを定義するために使用できるバイト。インターフェースが同じグループに属しているのは、そのxx値の論理ANDがゼロでない場合です。

例:

2つのインターフェースがグループ201を使用する場合、送信機は同時にキーがかけません。

2つのインターフェースがグループ101を使用する場合、両チャンネルが同時に空いているときにのみ送信機がキーされます。グループ301の場合は、送信機が同時にキーされません。

設定する前に、octal数を十進数に変換してください。

例: (記述する)

softdcd:

実際のものではなく、ソフトウェアのdcdを使用してください… 非常に遅いスquelchには便利です。

例: sccparam /dev/scc0 soft on

4. 問題¶

BayCom USCCカードで送信問題が発生した場合は、8530のメーカーを確認してください。SGSチップはわずかに異なるタイミングを持っています。Zilogを試してください… 解決策として、データポートではなくレジスタ8に書き込むことがありますが、ESCCチップでは機能しません。 SIGH!

PTTが最大keyupタイマが期限切れまでロックされるという非常に一般的な問題があります。ほとんどの場合、ドライバーをCONFIG_SCC_DELAY（make configで設定）でコンパイルすることで問題が解決します。さらにヒントが必要な場合は、(擬似) FAQとz8530drv-utilsに同梱されているドキュメンテーションを参照してください。

386ベースのシステムでドライバーが動作しないという報告があります。(例: Amstrad) これらのシステムは偽のATバスタイミングを持ち、割込みに対する遅延を引き起こします。問題を確認するには、疑われるポートの出力結果をSccstatで確認してください。アンダーランとオーバーランが表示される場合、このようなシステムを使用している可能性があります。

受信データの処理遅延: これは以下の要素に依存します

  • カーネルのバージョン

  • カーネルプロファイリングがコンパイルされているか
