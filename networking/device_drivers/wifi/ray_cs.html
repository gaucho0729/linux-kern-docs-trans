Raylink 無線LANカード¶

1999年9月21日

著作権 © 1998 Corey Thomas (corey@world.std.com)

このファイルは、Linux用Raylink無線LANカードドライバのドキュメンテーションです。Raylink無線LANカードは、IEEE 802.11準拠の無線ネットワーク接続を1メガビット/秒および2メガビット/秒で提供するPCMCIAカードです。詳細については http://www.raytheon.com/micro/raylink/ を参照してください。このドライバは初期開発段階でありバグがあります。詳細については、このドキュメントの最後に記載されている既知のバグと制限を参照してください。このドライバは、WebGearのAviator 2.4およびAviator Pro無線LANカードにも動作します。

カーネル2.3.18以降では、ray_csドライバがLinuxカーネルソースに組み込まれています。ray_csの開発用ウェブページは http://web.ralinktech.com/ralink/Home/Support/Linux.html です。メールは corey@world.std.com

カーネルドライバはray_cs-1.62.tgzに基づいています

私のウェブページにあるドライバは、David Hindsのpcmciaパッケージに追加で使用するためのものです。すべてのコマンドラインパラメータはモジュールとしてコンパイルした場合に利用可能です。カーネルに組み込まれた場合、コマンドラインで利用可能なパラメータはessid=のみです。すべてのPCMCIAドライバのパラメータの処理方法が合意されるまではこの状態が変わります。組み込みドライバで非デフォルトパラメータを使用する必要がある場合は、/usr/src/linux/drivers/net/pcmcia/ray_cs.cで編集してください。module_paramを検索することですべてのパラメータを見つけることができます。

カードサービスに関する情報は以下にあります：

http://pcmcia-cs.sourceforge.net/

PCMCIAデバイスにはカードサービスユーザープログラムが必要です。カーネル版ドライバにはpcmcia-cs-3.1.1以上が必要です。

現在、ray_csはDavid Hindsのカードサービスパッケージに含まれていませんので、以下の特殊な手順が必要です。

/etc/pcmcia/config.optsファイルの最後に、source ./ray_cs.optsという行を追加してください。これにより、カードサービスが起動時にray_cs.optsファイルを読み込みます。/etc/pcmcia/ray_cs.optsファイルを作成し、以下の内容を記述してください。

#### start of /etc/pcmcia/ray_cs.opts ###################
# Configuration options for Raylink Wireless LAN PCMCIA card
device "ray_cs"
  class "network" module "misc/ray_cs"

card "RayLink PC Card WLAN Adapter"
  manfid 0x01a6, 0x0000
  bind "ray_cs"

module "misc/ray_cs" opts ""
#### end of /etc/pcmcia/ray_cs.opts #####################

異なるパラメータで既存のネットワークに接続する場合は、ネットワーク管理者に連絡して設定情報を取得し、/etc/pcmcia/ray_cs.optsを編集してください。空の引数の間に以下のパラメータを追加してください。

ray_csドライバで指定可能なパラメータ（ray_cs.optsに記載）：

bc

integer

0 = 通常モード（802.11タイミング）、1 = 旧型breezecomアクセスポイントとの動作を許可するため、インターフレームタイミングを遅くします。

beacon_period

integer

キロマイクロ秒単位のビーコン周期、

有効値 = ホップステイの整数倍でなければなりません

デフォルト = 256

country

integer

1 = USA（デフォルト）、2 = 欧州、3 = 日本、4 = 韓国、5 = スペイン、6 = フランス、7 = イスラエル、8 = オーストラリア

essid

文字列

ESS ID - 接続するネットワーク名

最大32文字の文字列、デフォルト値 = “ADHOC_ESSID”

hop_dwell

integer

ホップ滞在時間（キロマイクロ秒）

許可値 = 16,32,64,128（デフォルト）,256

irq_mask

integer

Linux標準の16ビット値、1ビット/IRQ

LSBはIRQ 0、ビット1はIRQ 1など。IRQの選択を制限するために使用。割込みの制御には/etc/pcmcia/config.optsが推奨される

net_type

integer

0（デフォルト）= アドホックネットワーク、1 = インフラストラクチャ

phy_addr

文字列

新しいMACアドレス（16進数）を含む文字列、xで始まる必要があります（例: x00008f123456）

psm

integer

0 = 連続的にアクティブ、1 = パワーランニングモード（現時点では役立ちません）

pc_debug

integer

(0-5) 大きな値はより詳細なログ出力になります。ray_debugを置き換えます

ray_debug

integer

pc_debugで置き換えられました

ray_mem_speed

integer

デフォルトは500

sniffer

integer

0 = サニーファーでない（デフォルト）、1 = tcpdumpや類似ツールでネットワークトラフィックを記録できるサニーファーですが、通常のネットワーク使用は許可されません

translate

integer

0 = 翻訳なし（フレームをカプセル化）、1 = 翻訳（RFC1042/802.1）

サニーファーモードについて詳しく:

tcpdumpは802.11ヘッダーを理解できないため、内容を解釈できませんが、ファイルに記録することは可能です。これはLinuxに見えない802.11低レベルプロトコルのデバッグにのみ有用です。ftp転送や類似の操作を行う場合はサニーファーモードは必要ありません。また、カードが上位に送らないパケットタイプがあるため、それらは常に見られません（ACK、RTS、CTS、プローブなど）。「showcap」という簡単なプログラムがray_csパッケージに含まれており、802.11ヘッダーを解析できます

既知の問題と未実装の機能

x86以外のアーキテクチャでは動作しません

SMPでは動作しません

フレームの再構成サポートはまだデバッグされておらず、実際には動作しません。私はネットワークがフラグメントを生成する設定に遭遇したことはありませんが、それでも修正する必要があります

ioctlサポートは不完全です。ハードウェアアドレスはifconfigで設定できません。異なるハードウェアアドレスが必要な場合は、ray_cs.optsのphy_addrパラメータを使用して設定できます。これにはカードの挿入が必要です
