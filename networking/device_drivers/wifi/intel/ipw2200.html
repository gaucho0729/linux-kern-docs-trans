0. 使用前の重要情報¶

重要通知 すべてのユーザーおよび配布者向け!!!!

Intelの無線LANアダプタは、地域ごとの規制機関の要件を満たすために設計・製造・テスト・品質検査されています。無線LANは一般的に無許可機器であり、レーダー、衛星、その他の許可済みおよび無許可機器とスペクトルを共有しています。そのため、干渉を避けるために動的に検出・回避・使用制限が必要な場合があります。多くの場合、Intelは製品の使用許可を得る前に、地域および地域規制機関の適合性を証明するテストデータを提供する必要があります。Intelの無線LANのEEPROM、ファームウェア、ソフトウェアドライバは、無線動作に影響を与えるパラメータを厳密に制御し、電磁適合性（EMC）を確保するように設計されています。これらのパラメータには、RF電力、スペクトル使用、チャネルスキャン、人体への露出などが含まれます。

これらの理由から、Intelは無線WLANアダプタに同梱されたバイナリ形式のソフトウェア（例：EEPROMおよびファームウェア）の操作を第三者による改変を許可しません。さらに、Intelの無線LANアダプタで使用する場合、不正な第三者によって改変されたパッチ、ユーティリティ、またはコード（オープンソースコードの変更を含む）を使用した場合、（i）製品の規制適合性を確保する責任はすべてのユーザーにあり、（ii）Intelは、変更後の製品に関連するいかなる問題にも責任を負いません（保証に関する主張や規制適合性の違反による問題を含む）、（iii）Intelは、このような変更後の製品に対して第三者へのサポートを提供または支援する義務を負いません。

注意: 許可機関は、無線LANアダプタをモジュールとみなすことが多く、そのため、アンテナやシステム構成がEMCおよび無線動作に適合していないことを証明するテストデータの提出とレビューによってシステムレベルの規制承認を条件としています。

1. はじめに¶

以下のセクションでは、Intel(R) PRO/Wireless 2915ABG Driver for Linux の使用方法について簡潔に説明します。

このドキュメンテーションは、ワイヤレス技術の理解や使用に関する包括的なマニュアルではなく、Linux 上で無線接続を開始するのに十分な情報を提供します。

ドライバのビルドおよびインストールに関する情報は、INSTALL ファイルをご参照ください。

1.1. 機能概要¶

現在のバージョン（1.1.2）でサポートされている機能は以下の通りです:

  • BSSモード（インフラストラクチャ、マネージド）

  • IBSSモード（アドホック）

  • WEP（OPENおよびSHARED KEYモード）

  • 802.1x EAP（wpa_supplicantおよびxsupplicant経由）

  • ワイヤレス拡張機能のサポート

  • BおよびGレートの完全なサポート（2200および2915）

  • Aレートの完全なサポート（2915のみ）

  • 送信電力制御

  • S状態のサポート（ACPIスリープ/再開）

以下の機能は現在有効ですが、公式にはサポートされていません:

  • WPA

  • ロング/ショートプリアンブルのサポート

  • モニターモード（RFMonとも呼ばれる）

公式サポートと有効化の区別は、特定の機能に対して行われた検証および相互運用性テストの量を反映しています。

1.2. コマンドラインパラメータ¶

Linuxカーネルで使用される多くのモジュール同様、Intel(R) PRO/Wireless 2915ABG Driver for Linux はモジュールパラメータとして構成オプションを提供します。モジュールパラメータを指定する最も一般的な方法はコマンドラインです。

一般的な形式は:

% modprobe ipw2200 parameter=value

サポートされているパラメータは以下の通りです:

接続

ドライバの自動スキャン・アソシエーション機能を無効にするには0に設定します。無効にすると、ドライバがネットワークをスキャンしてアソシエートするまで、ターゲットネットワークの設定（例: ネットワークSSIDの設定）が行われるのを待つ必要があります。デフォルトは0（自動アソシエーションを実行しない）

例: % modprobe ipw2200 associate=0

auto_create

アドホックネットワークの自動作成を無効にするには0に設定します。デフォルトは1です。

channel

アソシエーションに使用するチャネル番号。チャネルの設定方法として標準のワイヤレスツール（i.e. iwconfig eth1 channel 10)を使用するのが一般的ですが、デバッグの際にはこのパラメータを設定することがあります。チャネル0は「任意」を意味します

debug

デバッグビルドを使用している場合、この設定はデバッグ情報のログ出力量を制御します。詳細な使用方法については、「dvals」および「load」スクリプトを参照してください（dvalsおよびloadスクリプトは、SourceForgeプロジェクトから入手可能なipw2200開発スナップショットリリースに含まれています） http://ipw2200.sf.net)

led

実験的なLEDコードを有効にするために使用できます。0 = オフ、1 = オン。デフォルトは1です。

mode

アダプターのデフォルトモードを設定するために使用できます。0 = マネージド、1 = アドホック、2 = モニタ

1.3. ワイヤレス拡張機能プライベートメソッド¶

汎用ハードウェアを扱うインターフェースとして設計されているため、通常のワイヤレスツールインターフェースでは公開されていない機能があります。このような場合、ドライバがカスタムまたはプライベートメソッドを宣言できるようにする仕組みが提供されています。Intel(R) PRO/Wireless 2915ABG Linuxドライバは、さまざまな設定を構成するためにこれらのメソッドをいくつか定義しています。

プライベートワイヤレスメソッドを使用する一般的な形式は以下の通りです：

% iwpriv $IFNAME method parameters

ここで$IFNAMEは、デバイスが登録されているインターフェース名（通常はeth1、ネットワークインターフェース名マネージャー（ifrenameなど）によってカスタマイズ可能）です

サポートされているプライベートメソッドは以下の通りです：

get_mode

ドライバがサポートするIEEEモードを報告するために使用できます。例：

% iwpriv eth1 get_mode eth1 get_mode:802.11bg (6)

set_mode

ドライバがサポートするIEEEモードを構成するために使用できます。

使用方法:

% iwpriv eth1 set_mode {mode}

ここで{mode}は1〜7の範囲の数値です：

1

802.11a (2915専用)

2

802.11b

3

802.11ab (2915専用)

4

802.11g

5

802.11ag (2915専用)

6

802.11bg

7

802.11abg (2915専用)
get_preamble

プリアム長の設定を報告するために使用できます。

set_preamble

プリアム長の設定を変更するために使用できます：

使用方法:

% iwpriv eth1 set_preamble {mode}

ここで{mode}は以下のいずれかです：

1

ロングプリアムのみ

0

オート（接続状態に基づくロングまたはショート）

1.4. sysfsヘルパーファイル¶

Linuxカーネルは、オペレーティングシステムのさまざまなコンポーネントにアクセスするための擬似ファイルシステムを提供しています。Intel(R) PRO/Wireless 2915ABG Linuxドライバは、このメカニズムを通じていくつかの設定パラメータを公開しています。

sysfsのエントリは読み取りおよび/または書き込みをサポートできます。通常、catコマンドを使用してsysfsエントリの内容を照会でき、echoコマンドを使用して内容を設定できます。例えば：

% cat /sys/bus/pci/drivers/ipw2200/debug_level

ドライバのログ出力サブシステムの現在のデバッグレベルを報告します（ドライバが構築時にCONFIG_IPW2200_DEBUGが設定されていた場合のみ有効）。

デバッグレベルを設定するには：

% echo $VALUE > /sys/bus/pci/drivers/ipw2200/debug_level

このsysfsエントリでは$VALUEは数字になります。sysfsファイルへの入力は必ずしも数字である必要はありません。たとえば、hotplugで使用されるファームウェアロー�ーダーは、ユーザー空間からドライバへファームウェアイメージを転送するためにsysfsエントリを使用します。

Intel(R) PRO/Wireless 2915ABGドライバfor Linuxは、sysfsエントリを2つのレベルで公開します。ドライバレベルは、ドライバのすべてのインスタンス（複数のデバイスがインストールされている場合）に適用され、デバイスレベルは特定の単一インスタンスにのみ適用されます。

1.4.1 ドライバレベルのsysfs補助ファイル¶

ドライバレベルのファイルは、/sys/bus/pci/drivers/ipw2200/に確認してください。

debug_level

これは「debug」モジュールパラメータと同じグローバル制御を行います

1.4.2 デバイスレベルのsysfs補助ファイル¶

デバイスレベルのファイルは、以下に確認してください:

/sys/bus/pci/drivers/ipw2200/{PCI-ID}/

例:

/sys/bus/pci/drivers/ipw2200/0000:02:01.0

デバイスレベルのファイルは、/sys/bus/pci/drivers/ipw2200: に確認してください

2. アドホックネットワーキング¶

Ad-Hocネットワークでデバイスを使用する際は、ドライバーがネットワークを構築・参加・統合する際の手順と要件を理解することが役立ちます。

以下の説明は、Ad-Hocネットワークのメンバーとしてドライバーを使用する際の一貫した体験を提供するための十分な情報を提供することを目的としています。

2.1 Ad-Hocネットワークへの参加¶

Ad-Hocネットワークに接続する最も簡単な方法は、既存のネットワークに参加することです。

2.2 Ad-Hocネットワークの作成¶

Ad-Hocネットワークは、ワイヤレスツールの構文を使用して作成されます。

例: iwconfig eth1 mode ad-hoc essid testing channel 2

3. 無線ツールとの相互作用¶

3.1 iwconfig mode¶

アダプターのモードを設定する際、すべてのランタイムで設定されたパラメータが、モジュールがロードされた際の値に戻されます。これはチャネル、レート、ESSIDなども含みます。

3.2 iwconfig sens¶

「iwconfig ethX sens XX」コマンドは、iwconfigドキュメンテーションで説明されている信号感度閾値を設定するのではなく、連続して失われるビーコンの数を設定します。これは、ハンドオーバー（つまり、別のアクセスポイントへの移動）をトリガーするための値です。同時に、分離閾値を設定し、その値の3倍に設定します。

オープンソース開発プロジェクトの性質上、完全な検証プロセスを経ていない変更が頻繁に組み込まれます。これらの変更は開発スナップショットリリースに組み込まれます。

「開発」部分が0（例: 1.0.0、1.1.0など）のバージョンは、カーネルへの組み込みが可能となる安定版を示します。

「開発」部分が0以外（例: 1.0.1、1.1.5など）のバージョンは、テスト用および最先端ユーザー向けに提供される開発版を示します。開発リリースの安定性や機能は保証されていません。我々はすべてのスナップショットが適切に安定しているように努めていますが、リリース頻度が高く、リリースを迅速に提供したいという願望により、未知の異常が発生する可能性があります。
