IPvs-sysctl¶

/proc/sys/net/ipv4/vs/* 変数:¶

am_droprate - 整数

デフォルト 10

drop_rate 防御のモード3で使用される常にモードのドロップレートを設定します。

amemthresh - 整数

デフォルト 1024

利用可能なメモリのしきい値（ページ単位）を設定します。自動的な防御モードで使用され、利用可能なメモリが不足している場合、対応する戦略が有効になり、変数は自動的に2に設定されます。それ以外の場合は、戦略が無効になり、変数は1に設定されます。

backup_only - ブール値

  • 0 - 無効 (デフォルト)

  • 0以外 - 有効

設定されている場合、サーバーがバックアップモードにあるときにディレクターファンクションを無効化し、DR/TUNメソッドでのパケットループを回避します。

conn_reuse_mode - 整数

1 - デフォルト

ipvsがポート再利用を検出した接続をどのように処理するかを制御します。これはビットマップで、値は以下の通りです：

0: ポート再利用に対して特別な処理を無効化します。新しい接続は以前の接続を処理した同じ実際のサーバーに転送されます。

ビット1: 安全な場合に新しい接続の再スケジューリングを有効にします。つまり、expire_nodest_connが発生するたびに、TCPソケットでは接続がTIME_WAIT状態にあるときに有効になります（これはNATモードを使用している場合にのみ可能です）。

ビット2: ビット1に加えて、TCP接続ではFIN_WAIT状態にあるときに有効になります。これはDirect Routingモードでのロードバランサーが最後に見る状態です。このビットは非常に忙しいクラスターに新しい実際のサーバーを追加するのに役立ちます。

conntrack - ブール値

  • 0 - 無効 (デフォルト)

  • 0以外 - 有効

設定されている場合、IPVSで処理する接続の接続追跡エントリを維持します。

IPVSで処理する接続がステートフルファイアウォールルールでも処理される場合、この設定を有効にすべきです。つまり、接続追跡を使用するiptablesルールです。それ以外の場合は、パフォーマンスの最適化としてこの設定を無効にすることが推奨されます。

IPVS FTPアプリケーションモジュールで処理される接続は、この設定に関係なく接続追跡エントリを持ちます。

IPVSがCONFIG_IP_VS_NFCTでコンパイルされている場合にのみ利用可能です。

cache_bypass - ブール値

  • 0 - 無効 (デフォルト)

  • 0以外 - 有効

有効にされている場合、キャッシュサーバーが利用できない場合や宛先アドレスがローカルでない場合（iph->daddrがRTN_UNICAST）、パケットを元の宛先に直接転送します。これは透明なWebキャッシュクラスタで主に使用されます。

debug_level - 整数

  • 0 - 送信エラーのメッセージ（デフォルト）

  • 1 - 致命的でないエラーのメッセージ

  • 2 - 設定

  • 3 - 宛先ごみ

  • 4 - 削除エントリ

  • 5 - サービス検索

  • 6 - スケジューリング

  • 7 - 接続新規/期限切れ、検索および同期

  • 8 - 状態遷移

  • 9 - 宛先バインディング、テンプレートチェックおよびアプリケーション

  • 10 - IPVSパケット送信

  • 11 - IPVSパケット処理（ip_vs_in/ip_vs_out）

  • 12以上 - パケットトラバーサル

IPVSがCONFIG_IP_VS_DEBUGが有効になっている状態でコンパイルされている場合にのみ利用可能です。

高いデバッグレベルは低いレベルのメッセージを含むため、デバッグレベル2を設定するとレベル0、1、2のメッセージがすべて含まれます。したがって、レベルが高いほどログ出力はより冗長になります。

drop_entry - インテジャー

  • 0 - 無効 (デフォルト)

drop_entryの防御策は、接続ハッシュテーブル内のエントリをランダムに削除して、新規接続にメモリを確保するものです。現在のコードでは、このdrop_entryプロシージャは毎秒実行され、全体の1/32をランダムにスキャンして、SYN-RECV/SYNACK状態のエントリを削除します。これによりsyn-flooding攻撃に対して効果的です。

drop_entryの有効な値は0〜3で、0はこの戦略が常に無効であることを意味し、1と2は自動モード（利用可能なメモリが不足している場合、戦略が有効になり変数が自動的に2に設定され、それ以外は戦略が無効で変数が1に設定される）を表し、3は常に有効であることを意味します。

drop_packet - インテジャー

  • 0 - 無効 (デフォルト)

drop_packetの防御策は、リアルサーバーに転送する前に1/rateの割合でパケットをドロップします。rateが1の場合はすべての入力パケットをドロップします。

値の定義はdrop_entryと同じです。自動モードでは、rateは以下の式で決定されます：rate = amemthresh / (amemthresh - available_memory)（利用可能なメモリが利用可能なメモリ閾値より小さい場合）。モード3が設定されている場合、常に有効なモードのドロップ率は/proc/sys/net/ipv4/vs/am_droprateで制御されます。

expire_nodest_conn - ブール

  • 0 - 無効 (デフォルト)

  • 0以外 - 有効

デフォルト値は0で、ロードバランサーは宛先サーバーが利用不可な場合にパケットを静かにドロップします。ユーザー空間のモニタリングプログラムがサーバーを削除した（過負荷や誤検出のため）後、再度サーバーを追加した場合、接続は継続可能になります。

この機能が有効になっている場合、宛先サーバーが利用不可なパケットが到達した時点で接続を即座に期限切れとし、クライアントプログラムに接続が閉じたことを通知します。これは、宛先が利用不可な場合に接続をフラッシュする機能に相当します。

expire_quiescent_template - ブール

  • 0 - 無効 (デフォルト)

  • 0以外 - 有効

非ゼロ値が設定されている場合、ロードバランサーは宛先サーバーが静止状態になったときに永続的なテンプレートを期限切れとします。これは、ユーザーが宛先サーバーの重みを0に設定して静止状態にし、その後の通常の永続的な接続を別の宛先サーバーに送信したい場合に役立ちます。デフォルトでは、新しい永続的な接続は静止状態の宛先サーバーに許可されます。

この機能が有効になっている場合、ロードバランサーは、新しい接続をスケジュールするための永続性テンプレートを使用する際、宛先サーバーが静止状態である場合にそのテンプレートを期限切れとします。

ignore_tunneled - BOOLEAN

  • 0 - 無効 (デフォルト)

  • 0以外 - 有効

設定されている場合、ipvsは未認識のプロトコルを持つすべてのパケットに対してipvs_propertyを設定します。これにより、ipipなどのトンネルプロトコルをルーティングから除外でき、ipvsホストにトンネルされたパケットを再スケジュールするのを防ぐことができます（つまり、ipvsがリアルサーバーとしても動作している場合のループを防ぐことができます）。

nat_icmp_send - BOOLEAN

  • 0 - 無効 (デフォルト)

  • 0以外 - 有効

ロードバランサーがリアルサーバーからパケットを受信したが、接続エントリが存在しない場合、ICMPエラー メッセージ（ICMP_DEST_UNREACH）を送信するかどうかを制御します。

pmtu_disc - BOOLEAN

  • 0 - 無効

  • 0以外 - 有効（デフォルト）

デフォルトでは、PMTUを超えるDFパケットは、転送方法に関係なくFRAG_NEEDEDで拒否されます。TUNメソッドではこのフラグを無効にして、このようなパケットをフラグメント化できます。

secure_tcp - INTEGER

  • 0 - 無効 (デフォルト)

secure_tcpの防御策は、より複雑なTCP状態遷移テーブルを使用することです。VS/NATでは、3-wayハンドシェイクが完了するまでTCP ESTABLISHED状態に移行を遅らせます。

値の定義はdrop_entryおよびdrop_packetと同じです。

sync_threshold - 2つのINTEGERのベクター: sync_threshold, sync_period

デフォルト 3 50

接続が同期されるための閾値を設定します。これは、接続が同期されるための最小の受信パケット数です。接続の受信パケット数がsync_periodの剰余が閾値と等しいたびに接続が同期されます。閾値の範囲は0からsync_periodまでです。

sync_periodとsync_refresh_periodが0の場合、状態変更時のみまたはパケット数がsync_thresholdに達したときにのみ同期を送信します。

sync_refresh_period - UNSIGNED INTEGER

デフォルト 0

接続タイマーの報告された時間差が新しい同期メッセージをトリガーする秒数です。接続状態が最後の同期以来変化していない場合、指定された期間（または接続タイムアウトの半分、低い場合はその半分）内に同期メッセージを送信しないようにできます。

高トラフィックの通常接続で同期レートを減らすために役立ちます。さらに、sync_refresh_period/8の間隔でsync_retries回再試行します。

sync_retries - INTEGER

デフォルト 0

sync_refresh_period/8の間隔で同期再試行を定義します。同期メッセージの喪失を防ぐために役立ちます。sync_retriesの範囲は0から3です。

sync_qlen_max - UNSIGNED LONG

まだ送信されていないキューに待機中の同期メッセージのハード制限です。デフォルトではメモリページの1/32ですが、実際にはメッセージ数を表します。送信レートがキューイングレートより低い場合に、メモリの大規模割り当てを防ぐための保護機能です。

sync_sock_size - INTEGER

デフォルト 0

SNDBUF（マスターサーバー）またはRCVBUF（バックアップサーバー）のソケット制限の設定です。デフォルト値は0（システムデフォルトを保持）です。

sync_ports - INTEGER

デフォルト値は1

マスターサーバーとバックアップサーバーが同期トラフィックのために使用できるスレッド数です。各スレッドは単一のUDPポートを使用し、スレッド0はデフォルトポート8848を使用し、最後のスレッドは8848+sync_ports-1のポートを使用します。

snat_reroute - BOOLEAN

  • 0 - 無効

  • 0以外 - 有効（デフォルト）

有効にすると、realserversからSNATされたパケットのルートを再計算し、ディレクターから発信したかのようにルーティングします。無効の場合はディレクターによって転送されたかのようにルーティングします。

ポリシールーティングが有効な場合、ディレクターから発信したパケットのルートが、ディレクターによって転送されたパケットのルートと異なる可能性があります。

ポリシールーティングが無効な場合、再計算されたルートは常に元のルートと同じため、snat_rerouteを無効にして再計算を避ける最適化が可能です。

sync_persist_mode - INTEGER

デフォルト 0

永続性を使用する際の接続の同期を制御します

0: すべての接続タイプが同期されます

1: 接続タイプに応じて同期トラフィックを減らすように試みます。永続サービスでは通常接続の同期を避けて、永続テンプレートのみに同期します。この場合、TCPおよびSCTPではバックアップサーバーでsloppy_tcpおよびsloppy_sctpフラグを有効にする必要があります。非永続サービスではこの最適化は適用されず、モード0が前提です。

sync_version - INTEGER

デフォルト値は1

同期メッセージを送信する際の同期プロトコルのバージョンです。

0は元の同期プロトコル（バージョン0）を選択します。これは、元の同期プロトコルのみを理解するレガシーシステムに同期メッセージを送信する場合に使用します。

1は現在の同期プロトコル（バージョン1）を選択します。可能な限りこのバージョンを使用してください。

このsync_versionエントリを持つカーネルは、バージョン1とバージョン2の同期プロトコルのメッセージを受信できます。
