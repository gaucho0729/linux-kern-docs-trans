IP Sysctl¶

/proc/sys/net/ipv4/* 変数¶

ip_forward - ボールド

  • 0 - 無効 (デフォルト)

  • 0以外 - 有効

インターフェース間でパケットを転送します。

この変数は特殊で、変更によりすべての設定パラメータがデフォルト状態（ホストにはRFC1122、ルーターにはRFC1812）に戻されます。

ip_default_ttl - 整数

出力（転送されない）IPパケットのTTLフィールド（Time To Live）のデフォルト値。1から255の間で指定してください。デフォルト: 64（RFC1700が推奨しています）

ip_no_pmtu_disc - 整数

Path MTU Discoveryを無効にします。モード1で有効にして、フラグメンテーションが必要なICMPを受信した場合、この宛先のPMTUがmin_pmtu（下記参照）に設定されます。ローカルで生成されるフラグメントを回避するには、min_pmtuをシステム内の最小インターフェースMTUに手動で上げる必要があります。

モード2では、受信するPath MTU Discoveryメッセージは無視されます。出力フレームはモード1と同じように処理され、すべての作成されたソケットにIP_PMTUDISC_DONTを暗黙的に設定します。

モード3は強化されたPMTU検出モードです。カーネルは、ベースとなるプロトコルが単純なソケット検索以外で確認できる場合に限り、フラグメンテーションが必要なエラーのみを受け入れます。現在、PMTUイベントを処理するプロトコルはTCP、SCTP、DCCPです（これらはシーケンス番号やアソシエーションなどの確認を行います）。このモードはグローバルに有効にすべきではなく、TCP経路MTUがまだ動作する必要がある名前サーバーなどの名前空間を保護する目的でのみ使用する予定です。グローバルに有効にすると、他のプロトコルが破壊される可能性があります。

可能値: 0-3

デフォルト: FALSE

min_pmtu - 整数

デフォルト 552 - 最小で発見されたPath MTU

ip_forward_use_pmtu - ボールド

デフォルトでは、ルーターが不望なフラグメンテーションを引き起こす可能性があるため、プロトコルのPath MTUを信頼していません。ユーザー空間のソフトウェアが独自にPath MTUを発見し、カーネルがこの情報を尊重する必要がある場合のみ有効にします。通常はこのような状況ではありません。

デフォルト: 0 (無効)

可能な値:

  • 0 - 無効

  • 1 - 有効

fwmark_reflect - ボールド

カーネルが生成したIPv4応答パケット（ソケットに関連付けられていない場合、たとえばTCP RSTやICMPエコーレ ply）のfwmarkを制御します。未設定の場合、これらのパケットのfwmarkはゼロです。設定されている場合、応答先のパケットのfwmarkを取得します。

デフォルト: 0

fib_multipath_use_neigh - ボールド

多重ルートのnexthopを決定する際、既存の隣接エントリの状態を使用します。無効にすると、隣接情報が使われず、パケットが失敗したnexthopに送られる可能性があります。これはCONFIG_IP_ROUTE_MULTIPATHが有効なカーネルビルドでのみ有効です。

デフォルト: 0 (無効)

可能な値:

  • 0 - 無効

  • 1 - 有効

fib_multipath_hash_policy - INTEGER

多重ルートのハッシュポリシーを制御します。これはCONFIG_IP_ROUTE_MULTIPATHが有効なカーネルビルドでのみ有効です。

デフォルト: 0 (レイヤー3)

可能な値:

  • 0 - レイヤー3

  • 1 - レイヤー4

  • 2 - レイヤー3または内部レイヤー3（存在する場合）

fib_sync_mem - UNSIGNED INTEGER

fibエントリからの汚れたメモリがこの値を超えるとsynchronize_rcuが強制されます。

デフォルト: 512kB 最小: 64kB 最大: 64MB

ip_forward_update_priority - INTEGER

IPv4ヘッダーの「TOS」フィールドからSKBの優先度を更新するかどうかを制御します。新しいSKB優先度はrt_tos2priorityテーブルに基づいてTOSフィールドの値からマッピングされます（man tc-prioを参照）。

デフォルト: 1（優先度を更新）

可能な値:

  • 0 - 優先度を更新しない

  • 1 - 優先度を更新する

route/max_size - INTEGER

カーネルに許可される最大ルート数です。多くのインターフェースおよび/またはルートを使用する場合、この値を増やす必要があります。

Linuxカーネル3.6以降、IPv4ではrouteキャッシュが使用されなくなったため、この設定は非推奨となりました。

neigh/default/gc_thresh1 - INTEGER

保持するエントリの最小数です。この数より少ない場合、ガベージコレクターはエントリを削除しません。

デフォルト: 128

neigh/default/gc_thresh2 - INTEGER

ガベージコレクターがエントリの削除をより積極的に行うしきい値です。この数を超えた場合、5秒以上古いエントリが削除されます。

デフォルト: 512

neigh/default/gc_thresh3 - INTEGER

許可される非PERMANENTな隣接エントリの最大数です。多くのインターフェースを使用する場合や、多くの直接接続されたピアと通信する場合、この値を増やす必要があります。

デフォルト: 1024

neigh/default/unres_qlen_bytes - INTEGER

他のネットワークレイヤーが未解決アドレスのパケットをキューイングする際、各アドレスに使用可能な最大バイト数です。（Linux 3.3で追加）

負の値を設定しても意味がなく、エラーが返されます。

デフォルト: SK_WMEM_MAX, （net.core.wmem_defaultと同じ）

アーキテクチャやカーネルオプションによって正確な値は異なりますが、中程度のサイズのパケットを256個キューイングできるようにするには十分です。

neigh/default/unres_qlen - INTEGER

他のネットワークレイヤーが未解決アドレスのパケットをキューイングする際、各アドレスに許可される最大パケット数です。

(Linux 3.3で非推奨) : unres_qlen_bytesを使用してください。

Linux 3.3以前では、デフォルト値は3であり、これが予期せぬパケットロスを引き起こす可能性があります。現在のデフォルト値は、unres_qlen_bytesのデフォルト値とパケットの真のサイズに基づいて計算されます。

デフォルト: 101

mtu_expires - インテジャー

キャッシュされたPMTU情報の保持時間（秒単位）。

min_adv_mss - インテジャー

広告されたMSSは最初のホップルートMTUに依存しますが、この設定値以下にはなりません。

IP フラグメント化:

ipfrag_high_thresh - ロング インテジャー

IP フラグメントを再構築するために使用される最大メモリ量。

ipfrag_low_thresh - ロング インテジャー

(linux-4.17から非推奨) IP フラグメントを再構築するために使用される最大メモリ量。カーネルは不完全なフラグメントキューを削除してリソースを解放し始めますが、依然として新しいフラグメントを受け入れてデフラグメント化を行います。

ipfrag_time - インテジャー

IP フラグメントをメモリに保持する時間（秒単位）。

ipfrag_max_dist - インテジャー

ipfrag_max_distは非負の整数値であり、同じIP送信元アドレスを持つフラグメント間の最大の「不整合」を定義します。パケットの再配列は一般的ですが、特定のフラグメントキューが未完了のまま、あるIPアドレスから多数のフラグメントが到着した場合、そのキューに属するフラグメントのいくつかが失われている可能性があります。ipfrag_max_distが正の場合、フラグメントを再構築キューに追加する前に追加のチェックが行われます。特定のIPアドレスからipfrag_max_dist（またはそれ以上）のフラグメントが到着した場合、キューに属するフラグメントのいくつかが失われていると推定され、既存のフラグメントキューが破棄され、新しいキューが開始されます。ipfrag_max_distの値がゼロの場合はこのチェックが無効になります。

ipfrag_max_distに非常に小さな値（例: 1または2）を使用すると、通常のパケット再配列が発生する場合でもフラグメントキューが不要に破棄される可能性があり、アプリケーションのパフォーマンス低下を引き起こす可能性があります。一方で、非常に大きな値（例: 50000）を使用すると、異なるIPデータグラムから発生したIPフラグメントを誤って再構築する可能性が高くなり、データ腐敗の原因になることがあります。デフォルト: 64

INETピアストレージ¶

inet_peer_threshold - インテジャー

ストレージの概算サイズ。このしきい値以上になると、エントリが積極的に削除されます。このしきい値はエントリの有効時間とガベージコレクションの間隔も決定します。エントリが増えるほど、有効時間が短くなり、ガベージコレクションの間隔も短くなります。

inet_peer_minttl - インテジャー

エントリの最小タイム-to-live。再組み立て側でフラグメントのタイム-to-liveをカバーするには十分である必要があります。プールサイズがinet_peer_threshold未満の場合、この最小タイム-to-liveは保証されます。秒単位で測定されます。

inet_peer_maxttl - 整数

エントリの最大タイム-to-live。プール内のエントリ数が非常に少ない（つまりメモリ圧力がない）場合、未使用のエントリはこの期間経過後に期限切れになります。秒単位で測定されます。

TCP変数¶

somaxconn - 整数

ソケットlisten()のバックログ制限。ユーザー空間ではSOMAXCONNと呼ばれます。デフォルトは4096（linux-5.4以前では128）。tcp_max_syn_backlogも参照してください。

tcp_abort_on_overflow - ブール値

リスニングサービスが新しい接続を受け入れるのが遅すぎる場合、接続をリセットします。デフォルトはFALSEで、これは一時的なバーストによるオーバーフローの場合、接続が回復することを意味します。リスニングデーモンを高速化できると確認されている場合以外はこのオプションを有効にしないでください。このオプションを有効にするとサーバーのクライアントに悪影響を及ぼす可能性があります。

tcp_adv_win_scale - 整数

tcp_adv_win_scale > 0の場合は、バッファーオーバーヘッドをbytes/2^tcp_adv_win_scaleとしてカウントします（tcp_adv_win_scale <= 0の場合はbytes-bytes/2^(-tcp_adv_win_scale)）。

可能値は[-31, 31]を含む範囲です。

デフォルト: 1

tcp_allowed_congestion_control - 文字列

非特権プロセスが使用可能なコンゴスト制御の選択肢を表示/設定します。これはtcp_available_congestion_controlに記載されているリストのサブセットです。

デフォルトは「reno」で、デフォルト設定（tcp_congestion_control）と同じです。

tcp_app_win - 整数

アプリケーションバッファにmax(window/2^tcp_app_win, mss)の窓を予約します。値0は特殊で、何も予約しません。

デフォルト: 31

tcp_autocorking - ブール値

TCP自動コルキングを有効にします。アプリケーションが連続して小規模なwrite()/sendmsg()システムコールを実行する場合、これらの小規模な書き込みをできるだけ統合して、送信パケットの総数を減らします。これは、フローの前のパケットがQdiscキューまたはデバイス送信キューに待機している場合に実行されます。アプリケーションは、TCP_CORKを使用して最適な動作を実現できる場合、それを知っているときにソケットをアンコルキングできます。

デフォルト : 1

tcp_available_congestion_control - 文字列

登録されているコンゴスト制御の選択肢を表示します。より多くのコンゴスト制御アルゴリズムがモジュールとして利用可能ですが、ロードされていない場合があります。

tcp_base_mss - 整数

パケット化レイヤーのパスMTU検出（MTUプローブ）で使用されるsearch_lowの初期値。MTUプローブが有効な場合、これは接続の初期MSSです。

tcp_mtu_probe_floor - INTEGER

MTUプロービングが有効になっている場合、この値は接続のsearch_lowに使用される最小のMSSを制限します。

Default : 48

tcp_min_snd_mss - INTEGER

TCP SYNおよびSYNACKメッセージは通常、RFC 1122およびRFC 6691で説明されているADVMSSオプションを宣伝します。

このADVMSSオプションがtcp_min_snd_mssよりも小さい場合、静かにtcp_min_snd_mssに制限されます。

Default : 48 (セグメントあたり少なくとも8バイトのペイロードを確保します）

tcp_congestion_control - STRING

新しい接続に使用される渋滞制御アルゴリズムを設定します。アルゴリズム「reno」は常に利用可能ですが、カーネルの設定に応じて追加の選択肢が利用可能になる場合があります。デフォルト値はカーネルの設定に含まれます。受動的接続の場合、リスナーの渋滞制御選択肢が継承されます。

[see setsockopt(listenfd, SOL_TCP, TCP_CONGESTION, “name” …) ]

tcp_dsack - BOOLEAN

TCPが「複製」SACKを送信できるようにします。

tcp_early_retrans - INTEGER

テールロスプローブ（TLP）は、テールロスによって発生するRTOを高速復旧に変換します（draft-ietf-tcpm-rack）。TLPはRACKの正常な動作を必要とします（tcp_recoveryを参照）。

可能な値:

  • 0はTLPを無効にします

  • 3または4はTLPを有効にします

Default: 3

tcp_ecn - INTEGER

TCPによる明示的な渋滞通知（ECN）の使用を制御します。ECNは、TCP接続の両端がサポートを示している場合にのみ使用されます。この機能は、サポートするルーターがパケットをドロップする前に渋滞を信号として通知することで、渋滞による損失を回避するのに役立ちます。

可能な値は以下の通りです：

0

ECNを無効にします。開始も受け入れもしません。

1

入力接続がECNを要求した場合、ECNを有効にし、出力接続試行でもECNを要求します。

2

入力接続がECNを要求した場合、ECNを有効にしますが、出力接続試行ではECNを要求しません。

デフォルト: 2

tcp_ecn_fallback - BOOLEAN

カーネルがECN接続が不適切であると検出すると、非ECNへのフォールバックを有効にします。現在、この設定はRFC3168のセクション6.1.1.1からのフォールバックを実装していますが、今後はこの設定下で追加の検出メカニズムが実装される可能性を予留しています。tcp_ecnまたはルートごとの（または渋滞制御）ECN設定が無効になっている場合、この値は使用されません。

Default: 1 (フォールバックが有効)

tcp_fack - BOOLEAN

これはレガシーのオプションであり、現在は効果がありません。

tcp_fin_timeout - INTEGER

アプリケーションから参照されなくなった（orphansと呼ばれる）接続が、ローカル側で終了する前にFIN_WAIT_2状態でどのくらいの時間を維持するかを指定します。未orphansの接続では「受信専用」状態として完全に有効ですが、orphansの接続がFIN_WAIT_2状態で待機すると、リモート側が接続を閉じるのを永遠に待つ可能性があります。

参照: tcp_max_orphans

デフォルト: 60秒

tcp_frto - INTEGER

RFC5682で定義されたForward RTO-Recovery（F-RTO）を有効にします。F-RTOはTCP再送信タイムアウトの強化された復旧アルゴリズムであり、RTT（Round-Trip Time）が変動するネットワーク（例：無線ネットワーク）において特に効果的です。F-RTOは送信側でのみの変更であり、ペアのサポートを必要としません。

デフォルトでは非ゼロ値で有効です。0を設定するとF-RTOが無効になります。

tcp_fwmark_accept - BOOLEAN

設定されている場合、ソケットマーキングがされていないリスニングソケットに到達する接続は、受信SYNパケットのfwmarkを受信ソケットのマーキングに設定します。これにより、接続のすべてのパケット（最初のSYNACKから）がこのfwmarkで送信されます。リスニングソケットのマーキングは変更されません。すでにsetsockopt(SOL_SOCKET, SO_MARK, …)でfwmarkが設定されているリスニングソケットは影響を受けません。

デフォルト: 0

tcp_invalid_ratelimit - INTEGER

既存の接続宛てのTCPパケットが以下のいずれかの理由により無効である場合、重複確認応答（dupacks）の最大送信速度を制限します:

  1. ウィンドウ外のシーケンス番号、

  2. ウィンドウ外の確認番号、または

  3. PAWS（Protection Against Wrapped Sequence numbers）チェック失敗

これは、バグのあるまたは悪意のあるミドルウェアやMITM（Man-in-the-Middle）がTCPヘッダーフィールドを改変して、各エンドポイントが相手が無効なTCPセグメントを送っていると誤認させることで発生する単純な「ACKループ」型DoS攻撃を緩和するのに役立ちます。

0を設定すると、無効なセグメントに対するdupacksのレート制限が無効になります。それ以外の場合、この値はdupacksを送信する間隔（ミリ秒単位）を指定します。

デフォルト: 500（ミリ秒）。

tcp_keepalive_time - INTEGER

keepaliveが有効な場合、TCPがkeepaliveメッセージを送信する間隔を指定します。デフォルト: 2時間。

tcp_keepalive_probes - INTEGER

TCPが接続が切断されたと判断するまで送信するkeepaliveプローブの数を指定します。デフォルト値: 9。

tcp_keepalive_intvl - INTEGER

プローブが送信される頻度。tcp_keepalive_probes と乗算して、プローブが開始された後、応答を待たない接続を切断するまでの時間を示します。デフォルト値: 75秒（つまり、再試行の約11分後に接続が中断されます）。

tcp_l3mdev_accept - ブール値

子ソケットがL3マスターデバイスインデックスを継承できるようにします。このオプションを有効にすると、「グローバル」リスニングソケットがL3マスタードメイン（例: VRF）をまたがって動作し、接続されたソケットが発生したパケットのL3ドメインにバインドされるようになります。この設定は、カーネルがCONFIG_NET_L3_MASTER_DEVでコンパイルされた場合にのみ有効です。

デフォルト: 0 (無効)

tcp_low_latency - ブール値

これはレガシーのオプションであり、現在は効果がありません。

tcp_max_orphans - 整数

システムが保持する、ユーザーのファイルハンドルに接続されていないTCPソケットの最大数です。この数値を超えると、孤立した接続が即座にリセットされ、警告が表示されます。この制限は単純なDoS攻撃を防ぐためのものであり、この制限に依存したり、人工的に値を下げたりしないでください。ネットワーク条件がデフォルト値を超える必要がある場合は、インストールされたメモリを増やすなどしてこの値を上げ、ネットワークサービスをより積極的にリスニングおよび終了するようにチューニングしてください。再度お伝えしますが、各孤立した接続は最大で約64Kの非スワップメモリを消費します。

tcp_max_syn_backlog - 整数

受け取らなかったクライアントからのACKを持つ接続要求（SYN_RECV）の最大数です。

これは各リスナーごとの制限です。

低メモリマシンでは最小値は128で、マシンのメモリ量に比例して増加します。

サーバーが過負荷になると、この数値を増やすことを試してください。

また、/proc/sys/net/core/somaxconnも確認してください。SYN_RECVリクエストソケットは約304バイトのメモリを消費します。

tcp_max_tw_buckets - 整数

システムが同時に保持するタイムウェイトソケットの最大数です。この数値を超えるとタイムウェイトソケットが即座に破棄され、警告が表示されます。この制限は単純なDoS攻撃を防ぐためのものであり、この制限を人工的に下げてはいけません。ネットワーク条件がデフォルト値を超える必要がある場合は、インストールされたメモリを増やすなどしてこの値を上げてください。

tcp_mem - 3つの整数のベクター: min, pressure, max

min: このページ数未満の場合は、TCPはメモリの使用量について気にしません。

pressure: TCPが割り当てたメモリ量がこのページ数を超えると、TCPはメモリ使用量を制限し、メモリ圧力モードに入ります。メモリ使用量が「min」以下になるまでこのモードは続きます。

max: すべてのTCPソケットがキューイングするための許容ページ数です。

起動時に利用可能なメモリの量からデフォルト値が計算されます。

tcp_min_rtt_wlen - 整数

最小RTTを追跡するためのウィンドウ付き最小フィルターのウィンドウ長です。短いウィンドウは、フローが長くなる経路に移動した際に新しい（高い）最小RTTをより速く検出できるようにします（たとえば、トラフィック工学のため）。長いウィンドウは、一時的な混雑などのRTTの膨張に抵抗するフィルターになります。単位は秒です。

可能値: 0 - 86400 (1日)

デフォルト: 300

tcp_moderate_rcvbuf - ブール値

Default: 3

デフォルト: 300

tcp_retrans_collapse - ブール値

一部の破損したプリンタとの互換性を確保します。再送時により大きなパケットを送信して、特定のTCPスタックのバグを回避します

tcp_retries1 - 整数

この値は、未確認のRTO再送信が原因でTCPが何かが間違っていると判断するまでの時間を影響します。tcp_retries2の詳細については参照してください

RFC 1122は少なくとも3回の再送信を推奨しており、これがデフォルト値です

tcp_retries2 - 整数

この値は、RTO再送信が未確認の有効なTCP接続のタイムアウトを影響します。値Nを指定すると、初期RTOがTCP_RTO_MINである仮想的なTCP接続は、N回再送信した後、(N+1)番目のRTOで接続を切断します

デフォルト値15は仮想的なタイムアウト924.6秒を生成し、有効なタイムアウトの下限となります。TCPは仮想的なタイムアウトを超える最初のRTOで実際にタイムアウトします

RFC 1122はタイムアウトに少なくとも100秒を推奨しており、これは少なくとも8の値に対応します

tcp_rfc1337 - ブール値

設定されている場合、TCPスタックはRFC1337に準拠します。設定されていない場合、RFC準拠はされませんが、TCP TIME_WAITのアサassinを防ぎます

デフォルト: 0

tcp_rmem - 3つの整数のベクター: min, default, max

min: TCPソケットで使用される受信バッファの最小サイズ。これは中程度のメモリ圧力下でも各TCPソケットに保証されます

デフォルト: 4K

default: TCPソケットで使用される受信バッファの初期サイズ。この値は他のプロトコルが使用するnet.core.rmem_defaultを上書きします。デフォルト: 131072バイト。この値は初期ウィンドウサイズ65535を生成します

max: TCPソケットの自動選択された受信バッファの最大許容サイズ。この値はnet.core.rmem_maxを上書きしません。setsockopt()でSO_RCVBUFを設定すると、そのソケットの受信バッファサイズの自動チューニングが無効になり、この値は無視されます。デフォルト: ラムサイズに応じて131072バイトから6MBの間

tcp_sack - ブール値

選択的な確認応答（SACKS）を有効にします

tcp_comp_sack_delay_ns - LONG INTEGER

TCPは、SRTTの5%に基づくタイマーを使用してSACK送信数を減らそうとします。このsysctlで制限され、ナノ秒単位で設定されます。デフォルトは1msで、TSO自動サイズ設定の周期に基づいています。

デフォルト : 1,000,000 ns (1 ms)

tcp_comp_sack_slack_ns - LONG INTEGER

このsysctlは、SACK圧縮に使用されるタイマーのスラックを制御します。これにより、小規模なRTTフローに追加の時間を与え、システムオーバーヘッドを減らすためにタイマーアラームの割り込みを機会的に短縮できます。

デフォルト : 100,000 ns (100 us)

tcp_comp_sack_nr - INTEGER

圧縮可能なSACKの最大数。0に設定するとSACK圧縮が無効になります。

デフォルト : 44

tcp_slow_start_after_idle - BOOLEAN

設定されている場合、RFC2861の動作を行い、アイドル期間後に渋滞ウィンドウをタイムアウトします。アイドル期間は現在のRTOで定義されます。設定されていない場合、アイドル期間後に渋滞ウィンドウはタイムアウトしません。

デフォルト: 1

tcp_stdurg - BOOLEAN

TCPの緊急ポインタフィールドをホストの要件に準拠した解釈を使用します。ほとんどのホストは古いBSDの解釈を使用しているため、この機能を有効にするとLinuxがそれらと正しく通信できなくなる可能性があります。

デフォルト: FALSE

tcp_synack_retries - INTEGER

パッシブなTCP接続試行のSYNACK再送信回数。255を超えてはいけません。デフォルト値は5で、現在の初期RTO（1秒）に基づく最終的な再送信までの時間は31秒、最終的なタイムアウトは63秒後に発生します。

tcp_syncookies - INTEGER

カーネルがCONFIG_SYN_COOKIESでコンパイルされている場合のみ有効です。ソケットのSYNバックログキューがオーバーフローしたときにsyncookiesを送信します。これは一般的な「SYN洪水攻撃」を防ぐための機能です。デフォルト: 1

syncookiesはフォールバック機能です。高度な負荷を受けるサーバーの保護には使用しないでください。ログにSYN洪水の警告が表示されるが、調査の結果、合法的な接続の過負荷が原因である場合は、この警告が消えるまで他のパラメータを調整してください。参照: tcp_max_syn_backlog, tcp_synack_retries, tcp_abort_on_overflow。

syncookiesはTCPプロトコルを大幅に違反しており、TCP拡張機能の使用を許可しません。一部のサービス（例：SMTPリレーリング）の性能が大幅に低下する可能性があります。これはあなた自身には見えませんが、あなたのクライアントやリレーホストに影響を与えます。ログにSYN洪水の警告が表示されているにもかかわらず、実際に洪水が発生していない場合、あなたのサーバーが誤って構成されている可能性があります。

ネットワーク接続にsyncookiesが与える影響をテストしたい場合は、この設定を2に設定して、syncookiesの無条件生成を有効化できます。

tcp_fastopen - INTEGER

TCP Fast Open (RFC7413) を有効化し、初期SYNパケットでデータを送受信できるようにします。

クライアントのサポートはフラグ0x1（デフォルトで有効）により有効になり、クライアントはconnect()ではなくsendmsg()またはsendto()をMSG_FASTOPENフラグとともに使用してデータをSYNパケットで送信する必要があります。

サーバーのサポートはフラグ0x2（デフォルトで無効）により有効になり、すべてのリスナーに有効化するには別のフラグ（0x400）を設定するか、TCP_FASTOPENソケットオプションを使用して個別にリスナーを有効化します。オプション値はsyn-dataバックログの長さになります。

値（ビットマップ）は

0x1

(クライアント)

クライアントで初期SYNにデータを送信を有効にする。

0x2

(サーバー)

サーバーのサポートを有効にし、3-wayハンドシェイクが完了する前にSYNパケットに含まれるデータを受け入れてアプリケーションに渡すことができます。

0x4

(クライアント)

クッキーの有無に関係なく初期SYNにデータを送信し、クッキーオプションを必要としません。

0x200

(サーバー)

クッキーオプションが存在しなくてもSYNパケット内のデータを受け入れます。

0x400

(サーバー)

TCP_FASTOPENソケットオプションを明示的に設定しなくても、すべてのリスナーがFast Openをサポートするようデフォルトで有効にします。

デフォルト: 0x1

追加のクライアントまたはサーバー機能は、基本的なサポート（0x1および0x2）がそれぞれ有効になっている場合にのみ効果を持ちます。

tcp_fastopen_blackhole_timeout_sec - INTEGER

TFOファイアウォールブラックホール問題が発生した場合、アクティブなTCPソケットでFastopenを無効にする初期時間（秒単位）。この時間は、Fastopenが再有効化された直後にブラックホール問題が検出されるたびに指数関数的に増加し、ブラックホール問題が解消すると初期値に戻ります。0を設定するとブラックホール検出が無効になります。

デフォルトでは0（機能は無効）に設定されています。

tcp_fastopen_key - コンマで区切られた32桁の十六進数INTEGERリスト

リストにはプライマリキーとオプションのバックアップキーが含まれます。プライマリキーはクッキーの生成と検証に使用され、オプションのバックアップキーはクッキーの検証にのみ使用されます。バックアップキーの目的は、キーが回転される際のTFO検証を最大限にすることです。

カーネルがtcp_fastopen sysctlを0x400に設定している場合（上記参照）またはTCP_FASTOPEN setsockopt() optnameが設定されておりかつ以前にsysctlでキーが設定されていない場合、カーネルがランダムに選んだプライマリキーを構成できます。setsockopt()でTCP_FASTOPEN_KEY optnameを使用してキーを設定した場合、そのソケットごとのキーがsysctlで指定されたキーを上書きします。

キーは4つの8桁の16進数で構成され、'-'で区切られます。例: xxxxxxxx-xxxxxxxx-xxxxxxxx-xxxxxxxx。前導ゼロは省略可能です。プライマリキーとバックアップキーはコンマで区切ることで指定できます。1つのキーのみを指定した場合、それはプライマリキーとなり、以前に設定されていたバックアップキーは削除されます。

tcp_syn_retries - INTEGER

アクティブなTCP接続試行における初期SYNの再送信回数を指定します。127を越えるべきではありません。デフォルト値は6で、現在の初期RTO（1秒）に基づく最終的なタイムアウトは63秒後に発生します。これにより、アクティブなTCP接続試行の最終タイムアウトは127秒後に発生します。

tcp_timestamps - INTEGER

RFC1323で定義されたタイムスタンプを有効にします。

  • 0: 無効

  • 1: RFC1323で定義されたタイムスタンプを有効にし、接続ごとにランダムなオフセットを使用します。

  • 2: 1と同様ですが、ランダムなオフセットは使用しません。

デフォルト: 1

tcp_min_tso_segs - INTEGER

TSOフレームごとのセグメントの最小数を指定します。

Linux-3.12以降、TCPはフロー速度に応じてTSOフレームを自動的にサイズ調整します。特定の用途では、TCPが大きなTSOフレームを構築するように強制することも可能です。注意: TCPスタックは、利用可能なウィンドウが小さすぎる場合、TSOパケットを分割する可能性があります。

デフォルト: 2

tcp_pacing_ss_ratio - INTEGER

TCPスタックは現在の速度（current_rate = cwnd * mss / srtt）に比率を適用してsk->sk_pacing_rateを設定します。TCPがスロースタート状態にある場合、tcp_pacing_ss_ratioは速度を検出するために適用され、RTTごとにcwndを倍にする前提でプローブします。

デフォルト: 200

tcp_pacing_ca_ratio - INTEGER

TCPスタックは現在の速度（current_rate = cwnd * mss / srtt）に比率を適用してsk->sk_pacing_rateを設定します。TCPが渋滞回避フェーズにある場合、tcp_pacing_ca_ratioはより保守的なプローブを目的として適用されます。

デフォルト: 120

tcp_tso_win_divisor - INTEGER

これは、1つのTSOフレームがどの程度のコンカレントウィンドウを消費できるかを制御します。このパラメータの設定は、バースト性と大きなTSOフレームの構築のバランスを取る選択です。

Default: 3

tcp_tw_reuse - INTEGER

プロトコルの観点から安全である場合、TIME-WAITソケットを新しい接続に再利用します。

  • 0 - 無効

  • 1 - グローバル有効

  • 2 - ループバックトラフィックのみ有効

技術専門家のアドバイスやリクエストなしに変更すべきではありません。

デフォルト: 2

tcp_window_scaling - BOOLEAN

RFC1323で定義されたウィンドウスケーリングを有効にします。

tcp_wmem - 最小値、デフォルト値、最大値の3つのINTEGERのベクトル

min: TCPソケット用の送信バッファに確保されるメモリ量。各TCPソケットはその生成によりこのメモリを使用する権限を持ちます。

デフォルト: 4K

default: TCPソケットが使用する送信バッファの初期サイズ。この値は他のプロトコルが使用するnet.core.wmem_defaultとは異なります。

これは通常、net.core.wmem_defaultよりも小さくなります。

デフォルト: 16K

max: TCPソケット用の自動調整送信バッファに許可される最大メモリ量。この値はnet.core.wmem_maxを上書きしません。setsockopt()でSO_SNDBUFを指定すると、そのソケットの送信バッファサイズの自動調整が無効となり、この値は無視されます。

デフォルト: RAMサイズに応じて64Kから4MBの間

tcp_notsent_lowat - 符号なし整数

TCP_NOTSENT_LOWATソケットオプションにより、TCPソケットは送信待ちバイト数を制御できます。送信待ちバイト数が各ソケットの値を下回り、かつ送信キューが満たされていない場合、poll()/select()/epoll()はPOLLOUTイベントを報告します。sendmsg()は制限を超えた場合、新しいバッファを追加しません。

このグローバル変数は、TCP_NOTSENT_LOWATを使用していないソケットの送信待ちデータ量を制御します。これらのソケットでは、グローバル変数の変更は即座に効果を持ちます。

デフォルト: UINT_MAX (0xFFFFFFFF)

tcp_workaround_signed_windows - ブール値

設定されている場合、ウィンドウスケーリングオプションの受信がないことはリモートのTCPが破損しているとみなされ、ウィンドウを符号付き量として扱います。設定されていない場合、リモートのTCPが破損していないとみなします。

デフォルト: 0

tcp_thin_linear_timeouts - ブール値

薄いストリームに対して線形タイムアウトを動的にトリガーします。設定されている場合、タイムアウトによる再送時にストリームが薄い（飛ばし中のパケットが4未満）かどうかを確認します。ストリームが薄い限り、指数バックオフモードに入る前に最大6回の線形タイムアウトが行われます。これにより、非積極的な薄いストリームの再送遅延が改善されます。より詳しい情報については スリムストリームとTCP

デフォルト: 0

tcp_limit_output_bytes - 整数

TCPソケットごとのTCP小キュー制限を制御します。TCPバULK送信者は、損失通知を受けるまで飛ばし中のパケットを増やします。SNDBUF自動調整を使用すると、ローカルマシン（例: qdiscs、CPUバックログ、またはデバイス）に大量のパケットがキューイングされ、他のフローのレイテンシーに悪影響を及ぼす可能性があります。tcp_limit_output_bytesはqdiscやデバイス上のバイト数を制限し、人工的なRTT/cwndを減らし、バッファブルームを軽減します。

デフォルト: 1048576 (16 * 65536)

tcp_challenge_ack_limit - インテジャー

RFC 5961（Improving TCP’s Robustness to Blind In-Window Attacks）で推奨されているように、毎秒送信するChallenge ACKの数を制限します。デフォルト: 1000

tcp_rx_skb_cache - ブール

TCPソケットごとの1skbのキャッシュを制御します。これは一部のワークロードのパフォーマンス向上に役立つ可能性があります。ただし、多くのTCPソケットを持つシステムではメモリ使用量が増加するため、危険である可能性があります。

デフォルト: 0 (無効)

デフォルト: 4K

CIPSOv4変数¶

設定されている場合、CIPSOラベルマッピングキャッシュへの追加と検索が有効になります。設定されていない場合、追加は無視され、検索は常にヒットしません。ただし、設定の有無に関わらず、必要に応じてキャッシュは無効化されるため、このオプションをオンオフに切り替えることができます。キャッシュは常に「安全」に保たれます。

IP変数¶

ip_local_port_range - 2 整数

TCPおよびUDPがローカルポートを選択する際に使用するローカルポートの範囲を定義します。最初の数字は最初のローカルポート番号、2番目の数字は最後のローカルポート番号です。可能であれば、これらの数字は異なる奇偶性（1つは偶数、1つは奇数）を持つようにしてください。ip_unprivileged_port_start以上でなければなりません。デフォルト値はそれぞれ32768と60999です。

ip_local_reserved_ports - カンマで区切った範囲のリスト

既知の第三者アプリケーションに割り当てられるポートを指定します。これらのポートは自動ポート割当（例：connect()またはbind()でポート番号0を指定した場合）では使用されません。明示的なポート割当の挙動は変更されません。

入力および出力のフォーマットは、カンマで区切った範囲のリスト（例：「1,2-4,10-10」はポート1、2、3、4および10）です。ファイルに書き込むと、以前に予約されていたすべてのポートをクリアし、入力で指定されたリストに更新します。

ip_local_port_rangeとip_local_reserved_portsの設定は独立しており、どちらもカーネルが自動ポート割当で利用可能なポートを決定する際の考慮対象です。

現在のip_local_port_rangeにないポートを予約することもできます、例えば：

$ cat /proc/sys/net/ipv4/ip_local_port_range
32000       60999
$ cat /proc/sys/net/ipv4/ip_local_reserved_ports
8080,9148

これは冗長ですが、後でポート範囲が予約されたポートを含む値に変更される場合にこのような設定が役立ちます。

デフォルト: 空

ip_local_unbindable_ports - カンマで区切った範囲のリスト

直接bind()できないポートを指定します。

通常、カーネルの制御を超えた原因で無効なポート（例：シリアルコンソール、リモート電源管理、デバッグ用にNICによって奪われたポート）の使用をブロックするために使用します。

これらのポートを‘ip_local_reserved_ports’にリスト化することも検討してください。これにより自動バインディングを防ぐことができます。

デフォルト: 空

igmp_max_memberships - INTEGER

サブスクライブ可能なマルチキャストグループの最大数を変更します。デフォルト: 20

理論的な最大値は、1つのデータグラムにメンバーシップレポートを送信する必要があるため（つまり、レポートが複数のデータグラムにまたがってはならない）制限されます。

サポートされるグループ数 'M' は、65535バイトの単一データグラムに収められるグループレポートエントリの数によって制限されます。

M = 65536 - sizeof (ip ヘッダー)/(sizeof(Group record))

グループレコードは可変長で、最小12バイトです。そのため net.ipv4.igmp_max_memberships は以下の値を超えて設定すべきではありません：

(65536-24) / 12 = 5459

値 5459 は IP ヘッダーオプションが含まれないことを前提としています。実際にはこの数値は低くなる可能性があります。

rp_filter - INTEGER

  • 0 - ソース検証を行いません。

  • 1 - RFC3704で定義された厳格モード。各インバウンドパケットがFIBと照合され、インターフェースが最良の逆ルートでない場合、パケット検証が失敗します。デフォルトでは失敗したパケットは破棄されます。

  • 2 - RFC3704で定義された緩和モード。各インバウンドパケットの送信元アドレスもFIBと照合され、送信元アドレスがどのインターフェースも経由できない場合、パケット検証が失敗します。

RFC3704における現在の推奨実装は、IPスプーフィングによるDDoS攻撃を防ぐため厳格モードを有効にすることです。非対称ルーティングや複雑なルーティングを用いる場合は緩和モードが推奨されます。

{interface}でのソース検証には、conf/{all,interface}/rp_filterの最大値が使用されます。

デフォルト値は0です。一部のディストリビューションでは起動スクリプトで自動的に有効化されています。

  • 1 - 同じサブネット上の複数のネットワークインターフェースを有し、ARP応答はカーネルがARP’d IPをそのインターフェース経由でルーティングするかどうかに基づいて行われます（そのため、ソースベースルーティングを使用する必要があります）。言い換えれば、どのインターフェース（通常は1つ）がARPリクエストに応答するかを制御できます。

  • 0 - （デフォルト）カーネルは他のインターフェースのアドレスでもARPリクエストに応答できます。これは直感的ではあるものの、通信成功の可能性を高めるため通常有効です。LinuxではIPアドレスはホスト全体に所属し、特定のインターフェースには所属しません。ただし、ロードバランシングなどの複雑な設定ではこの挙動が問題になることがあります。

arp_announce - INTEGER

ARPリクエストで送信されるIPパケットのローカルソースIPアドレスの発言制限レベルを異なるレベルで定義します。

  • 0 - (デフォルト) 任意のインターフェースに設定されたローカルアドレスを使用します

  • 1 - 送信インターフェースのターゲットのサブネットに含まれないローカルアドレスは避けるように試みます。このモードは、このインターフェース経由で到達可能なターゲットホストがARPリクエストでソースIPアドレスを論理ネットワークに含める必要がある場合に役立ちます。リクエストを生成する際には、ターゲットIPを含むすべてのサブネットを確認し、そのサブネットに属するソースアドレスを保持します。そのようなサブネットがなければ、レベル2のルールに従ってソースアドレスを選択します。

  • 2 - ターゲットに対して最適なローカルアドレスを常に使用します。このモードではIPパケット内のソースアドレスを無視し、ターゲットホストとの通信に好ましいローカルアドレスを選択します。選択は、出力インターフェースのターゲットIPを含むすべてのサブネットのプライマリIPアドレスを検索して行われます。適切なローカルアドレスが見つからない場合は、出力インターフェースまたは他のすべてのインターフェースにある最初のローカルアドレスを選択します。

conf/{all,interface}/arp_announceの最大値が使用されます。

IPV6_V6ONLYソケットオプションのデフォルト値で、IPv6ソケットの使用をIPv6通信に限定します。

  • FALSE: IPv4マッピングアドレス機能を有効にする

  • TRUE: 有効

  • FALSE: 無効

デフォルト: TRUE

auto_flowlabels - INTEGER

パケットのフローハッシュに基づいてフローラベルを自動生成します。これにより、ルーターなどの中間デバイスが、等コスト多重ルーティングなどのメカニズムでパケットフローを識別できます（RFC 6438を参照）。

0

自動フローラベルは完全に無効

1

自動フローラベルはデフォルトで有効で、IPV6_AUTOFLOWLABELソケットオプションを使用してソケットごとに無効にできます

2

自動フローラベルは許可されており、IPV6_AUTOFLOWLABELソケットオプションを使用してソケットごとに有効にできます

3

自動フローラベルは有効で強制されており、ソケットオプションで無効にすることはできません

デフォルト: 1

flowlabel_state_ranges - BOOLEAN

フローラベル番号空間を2つの範囲に分割します。0-0x7FFFFはIPv6フロー管理ファシリティに予約され、0x80000-0xFFFFFはRFC6437で説明されているステートレスフローラベルに予約されています。

  • TRUE: 有効

  • FALSE: 無効

デフォルト: true

flowlabel_reflect - INTEGER

フローラベルの反射を制御します。これは、任意キャスト環境でのPath MTU Discoveryが等コスト多重ルーティングと併用されるために必要です。RFC 7690を参照してください： https://tools.ietf.org/html/draft-wang-6man-flow-label-reflection-01

これはビットマスクです。

  • 1: 既存フローに対して有効

    この設定により、tcp: spurious retransmissionを受信時にIPv6フローラベルを変更するなどの自動フローラベル変更が防止されます

  • 2: TCP RESETパケット（アクティブなリスナーなし）に対して有効。設定されている場合、閉じたポートのSYNパケットに対するRSTパケットは、受信したフローラベルを反映します。

  • 4: ICMPv6エコーレ plyメッセージの有効化。

デフォルト: 0

デフォルト: 0 (レイヤー3)

addip_enable - BOOLEAN

0: pfを無効化します。

rcvbuf_policy - 整数

受信バッファがソケットに割り当てられるか、アソシエーションに割り当てられるかを決定します。SCTPは、単一のソケットで複数のアソシエーションを作成する機能をサポートしています。この機能を使用すると、1つの停止したアソシエーションが大量のデータをバッファリングしてしまい、他のアソシエーションがデータを送信できなくなる可能性があります。これを回避するため、rcvbuf_policyをアソシエーションごとに受信バッファ空間を割り当てるように設定できます。これにより、説明されたブロッキングを防ぐことができます。

  • 1: 受信バッファ空間はアソシエーションごとに割り当てられます

  • 0: 受信バッファ空間はソケットごとに割り当てられます

デフォルト: 0

sndbuf_policy - 整数

上記のrcvbuf_policyと同様に、これは送信バッファ空間に適用されます。

  • 1: 送信バッファはアソシエーションごとに追跡されます

  • 0: 送信バッファはソケットごとに追跡されます。

デフォルト: 0

sctp_mem - 3つの整数（min、pressure、max）のベクター

すべてのSCTPソケットがキューイングに使用できるページ数。

min: このページ数以下の場合は、SCTPはメモリの使用量について気にしません。SCTPが割り当てたメモリ量がこの数を超えると、SCTPはメモリ使用量を調整し始めます。

pressure: この値はtcp_memのフォーマットに合わせて導入されました。

max: すべてのSCTPソケットがキューイングに使用できるページ数。

デフォルト値は起動時に利用可能なメモリ量に基づいて計算されます。

sctp_rmem - 3つの整数値を含むベクター: min, default, max

「min」のみが使用され、「default」と「max」は無視されます。

min: SCTPソケットが使用する受信バッファの最小サイズ。中程度のメモリ負荷下でも各SCTPソケット（アソシエーションごとではなく）に保証されます。

デフォルト: 4K

sctp_wmem - 3つの整数値を含むベクター: min, default, max

現在の設定では効果がありません。

addr_scope_policy - 整数

IPv4アドレススコープの制御 - draft-stewart-tsvwg-sctp-ipv4-00

  • 0 - IPv4アドレススコープを無効化

  • 1 - IPv4アドレススコープを有効化

  • 2 - draftに従うがIPv4プライベートアドレスを許可

  • 3 - draftに従うがIPv4リンクローカルアドレスを許可

デフォルト: 1
