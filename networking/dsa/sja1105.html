NXP SJA1105スイッチドライバー¶

概要¶

NXP SJA1105 は 6つのデバイスからなるファミリです:

  • SJA1105E: 1世代、TTEthernet なし

  • SJA1105T: 1世代、TTEthernet あり

  • SJA1105P: 2世代、TTEthernet なし、SGMII なし

  • SJA1105Q: 2世代、TTEthernet あり、SGMII なし

  • SJA1105R: 2世代、TTEthernet なし、SGMII あり

  • SJA1105S: 2世代、TTEthernet あり、SGMII あり

これらは SPIで管理される自動車用スイッチで、すべてのポートがギガビット対応であり、MII/RMII/RGMII をサポートし、1ポートにはオプションで SGMII もサポートします。

自動車用部品であるため、設定インターフェースはセットアンドフォゲット方式で設計されており、実行時における動的なやり取りは極めて最小限です。ソフトウェアで静的設定を組み、CRC とテーブルヘッダーを付けてパックし、SPI経由で送信する必要があります。

静的設定は複数の設定テーブルから成り、各テーブルは複数のエントリを含みます。一部の設定テーブルは実行時において（部分的に）再構成可能ですが、他のはできません。また、必須のテーブルとそうでないテーブルがあります:

ドライバーはプローブ時に静的設定を作成し、常にメモリに保持してハードウェア状態のシャドウとしています。ハードウェア設定を変更する必要がある場合、静的設定も更新されます。その変更された設定が動的再構成インターフェースを通じてスイッチに送信可能であれば送信し、そうでない場合はスイッチを再起動して更新された静的設定で再プログラミングします。

トラフィックサポート¶

スイッチはDSAタグのハードウェアサポートを持っていません。ただし、スイッチ制御用の「遅いプロトコル」（STPやPTPなど）を除き、これらのプロトコルについてはスイッチがリンクローカル宛先MACアドレス用の2つのプログラマブルフィルタを備えています。これらはBPDUsやPTPトラフィックをマスターネットデバイスにトラップし、STPおよび1588普通時計/境界時計機能をサポートするために使用されます。CPUにトラップされたフレームについては、ハードウェアがソースポートおよびスイッチID情報をフレームにエンコードします。

しかし、以下のように活用することで CONFIG_NET_DSA_TAG_8021Q （VLANに基づくソフトウェア定義のDSAタギング形式）により、特定の状況においてネットワークスタックを通じた一般的なトラフィック終端処理をサポートできます。

VLAN認識状態に応じて、スイッチで以下の運用モードが可能です：

  • モード1（VLAN無関係）：ポートがスタンドアロンのネットデバイスとして使用されている場合、またはブリッジにslaveされている場合（ vlan_filtering=0.

  • モード2（完全なVLAN認識）：ポートがブリッジにslaveされている場合（ vlan_filtering=1。ユーザーは bridge vlan コマンドを通じてすべてのVLAN範囲にアクセスできますが、スイッチネットデバイスを通じた一般的なトラフィック（STP、PTPなど以外）の終端処理はできません。他のパケットは依然としてユーザー空間でDSAマスターアクセスインターフェースを通じて処理可能です（ DSA_TAG_PROTO_NONE).

  • モード3（ベストエフォート VLAN認識）：ポートがブリッジにslaveされている場合（ vlan_filtering=1、およびその親スイッチのdevlinkプロパティ名 best_effort_vlan_filtering が true。この設定では、利用可能なVIDの範囲が縮小されます（0〜1023および3072〜4094）、利用可能なVIDの数も減少します（ポートあたり最大7つの非pvid VLAN）*、共有VLAN学習が行われます（FDB検索はDMACのみで行われ、VIDは考慮されません）。

SJA1105スイッチ1は、CPUへ向かう各ユーザーポートの各VLANに対して1つのリタグエントリを消費します。また、隣接スイッチのどのポートでも設定された非pvid VLANに興味がある場合、それらの各VLANについても1つのリタグエントリを消費します。

この場合、SJA1105スイッチ1は以下の通り合計11つのリタグエントリを消費します：

  • ユーザーポートにインストールされたVLAN 1と100のための8つのリタグエントリ（sw1p0 - sw1p3)

  • SJA1105スイッチ2のユーザーポートにインストールされたVLAN 100のための3つのリタグエントリ（sw2p0 - sw2p2）、これはそのスイッチにも興味があるポートがあるためです。VLAN 1はSJA1105スイッチ2のpvidであり、逆方向のリタグ処理は必要ありません。

SJA1105スイッチ2も11つのリタグエントリを消費しますが、以下のように整理されています：

  • ユーザーポートのブリッジVLANのために7つのリタグエントリ（sw2p0 - sw2p3).

  • SJA1105スイッチ1のユーザーポートにインストールされたVLAN 100のための4つのリタグエントリ（sw1p0 - sw1p3).

スイッチング機能¶

ドライバーは、ポートブリッジングにおけるL2フォワーディングルールのハードウェア設定をサポートしています。ポート間のフォワーディング、ブロードキャスト、フロッディングドメインは、2つの方法で制限可能です：L2フォワーディングレベル（1つのブリッジのポートを他のブリッジのポートから隔離）またはVLANポートメンバシップレベル（同じブリッジ内のポートを隔離）。ハードウェアが最終的に採用するフォワーディング決定は、これらの2つのルールセットの論理積です。

ハードウェアは内部でポートベースのVLAN（pvid）でトラフィックをすべてタグ付けするか、または802.1QタグからVLAN情報をデコードします。高度なVLAN分類はできません。VLANタグが割り当てられると、フレームはポートのメンバーシップルールと照合され、どのVLANにも一致しない場合はイングレスで破棄されます。この挙動は、スイッチポートがブリッジにslave（属している）状態で利用可能です。 vlan_filtering 1.

通常、ハードウェアはVLAN認識に関する設定はできませんが、スイッチが検索するTPID（タグプロトコルID）を変更することで、ブリッジのセマンティクスを vlan_filtering 0 維持できます（すべてのトラフィックを受信、タグありまたはタグなし）、したがってこのモードもサポートされています。

スイッチポートを複数のブリッジに分離するサポートがあります（例：2 + 2）、ただしすべてのブリッジが同一レベルのVLAN認識（どちらも vlan_filtering 0、またはどちらも1）を持つ必要があります。また、VLAN認識がスイッチレベルでグローバルであるための避けられない制限として、ブリッジが vlan_filtering 少なくとも1つのスイッチポートをslaveにした後、他の未ブリッジングされたポートはスタンドアロンのトラフィック終端のためにも利用できなくなります。

STPによるトポロジおよびループ検出はサポートされています。

L2 FDB（Forwarding Database）の操作（追加/削除/ダンプ）は、第一世代のデバイスでは現在可能です。FDBエントリのエイジング時間や、完全な静的管理（アドレス学習なし、未知トラフィックのフロodingなし）の有効化は、ドライバではまだ設定できません。

他のnetdeviceとのブリッジングについての特別なコメント（例を用いて説明）：

ボードにはeth0、eth1、 swp0@eth1, swp1@eth1, swp2@eth1, swp3@eth1スイッチポート（swp0-3）はbr0の下位に配置されています。eth0をswp0-3と通信可能な別のスイッチポートに変換したいという要望があります。

br0がvlan_filtering 0の場合、eth0をbr0に単純に追加することで目的の結果を得られます。br0がvlan_filtering 1の場合、swp0-3のDSAマスターとなるeth0とeth1をslaveにする新しいbr1インターフェースを作成する必要があります。これはこのモードでは、br0下位のスイッチポートが通常のトラフィックを処理できず、スイッチデバイス操作のコンディションとしてのみ使用されるためです。

オフロード¶

タイムアウェアスケジューリング¶

スイッチはIEEE 802.1Q-2018（以前は802.1Qbv）で指定されたスケジュール済みトラフィックの向上機能の変種をサポートしています。これにより、ネットワークスケジュール内でゲートオープンイベントと同様にインバンドで送信される優先トラフィックの決定的なレイテンシーを保証できます。

この機能はtc-taprio offload（'flags 2'）を通じて管理可能です。taprioのソフトウェア実装との違いは、後者はCPUから発生したトラフィックのみを整形可能で、自律的に転送されるフローは整形できない点です。

このデバイスには8つのトラフィッククラスがあり、VLAN PCPビット（VLANが存在しない場合はポートベースのデフォルトが使用されます）に基づいて受信フレームをそのうちの1つにマッピングします。前記セクションで説明したように、 vlan_filteringの値によって、スイッチがVLANとして認識するEtherTypeは通常の0x8100か、ドライバが内部で使用するカスタム値のいずれかになります。したがって、スタンドアロンモードまたはブリッジモードで使用する場合、スイッチは0x8100 EtherTypeを認識しないため、VLAN PCPを無視します。 vlan_filtering=0これらのモードでは、特定のTXキューへのインジェクションはDSAネットワークデバイスのみが行えるため、エグジット時にタグヘッダーのPCPフィールドを埋める必要があります。使用 vlan_filtering=1の場合は、逆の動作になります：オフロードされたフローはVLAN PCPに基づいてTXキューに誘導可能ですが、DSAネットワークデバイスはそれを行えません。VLAN認識が有効なハードウェアTXキューにフレームをインジェクトするには、DSAマスターポートにVLANサブインターフェースを作成し、0x8100 VLANタグをスイッチに送信し、VLAN PCPビットを適切に設定する必要があります。

管理トラフィック（DMAC 01-80-C2-xx-xx-xxまたは01-19-1B-xx-xx-xxを持つ）は特例です：スイッチは常に固定優先度で処理し、VLAN PCPビットを無視します。管理トラフィックのトラフィッククラスは現在、7（最高優先度）であり、ドライバでは設定できません。

出力ポートに500マイクロ秒のサイクルスケジュールを設定する例が以下に示されます swp5。管理トラフィック（クラス7）のトラフィッククラスゲートは100マイクロ秒開放され、他のすべてのトラフィッククラスのゲートは400マイクロ秒開放されます：

#!/bin/bash

set -e -u -o pipefail

NSEC_PER_SEC="1000000000"

gatemask() {
        local tc_list="$1"
        local mask=0

        for tc in ${tc_list}; do
                mask=$((${mask} | (1 << ${tc})))
        done

        printf "%02x" ${mask}
}

if ! systemctl is-active --quiet ptp4l; then
        echo "Please start the ptp4l service"
        exit
fi

now=$(phc_ctl /dev/ptp1 get | gawk '/clock time is/ { print $5; }')
# Phase-align the base time to the start of the next second.
sec=$(echo "${now}" | gawk -F. '{ print $1; }')
base_time="$(((${sec} + 1) * ${NSEC_PER_SEC}))"

tc qdisc add dev swp5 parent root handle 100 taprio \
        num_tc 8 \
        map 0 1 2 3 5 6 7 \
        queues 1@0 1@1 1@2 1@3 1@4 1@5 1@6 1@7 \
        base-time ${base_time} \
        sched-entry S $(gatemask 7) 100000 \
        sched-entry S $(gatemask "0 1 2 3 4 5 6") 400000 \
        flags 2

複数の出力ポートにtc-taprio offloadを適用することが可能です。ハードウェアの制限により、2つのポートで同時にゲートイベントがトリガーされることはありません。ドライバはスケジュールの整合性をこの制限と比較し、必要に応じてエラーを出力します。この制限を回避するためのスケジュール分析が必要ですが、これは本文書の範囲外です。

ルーティングアクション（リダイレクト、トラップ、ドロップ）¶

スイッチは、ユーザーが指定した一連の宛先ポートにパケットのフローベースのリダイレクトをオフロード可能です。内部的には、これは仮想リンク（TTEthernetの概念）を活用して実装されます。

ドライバーは仮想リンク用の2種類のキーをサポートしています:

  • VLANを認識する仮想リンク: これらは宛先MACアドレス、VLAN ID、VLAN PCPに基づいて一致します。

  • VLANを認識しない仮想リンク: これらは宛先MACアドレスのみに基づいて一致します。

ブリッジのVLAN認識状態（vlan_filtering）は、仮想リンクルールがインストールされている間は変更できません。

同じルール内で複数のアクションを組み合わせることができます。ルーティングアクションのみが要求される場合、ドライバーは「非クリティカル」仮想リンクを作成します。アクションリストにtc-gate（以下で詳しく説明）が含まれる場合、仮想リンクは「タイムクリティカル」になります（フレームバッファを予約されたメモリパーティションから取得など）。

サポートされる3つのルーティングアクションは「trap」、「drop」、「redirect」です。

例1: swp2で受信したDAが42:be:24:9b:76:20のフレームをCPUおよびswp3に送信します。このタイプのキー（DAのみ）は、ポートのVLAN認識状態がオフの場合に使用されます:

tc qdisc add dev swp2 clsact
tc filter add dev swp2 ingress flower skip_sw dst_mac 42:be:24:9b:76:20 \
        action mirred egress redirect dev swp3 \
        action trap

例2: swp2で受信したDAが42:be:24:9b:76:20、VIDが100、PCPが0のフレームを破棄します:

tc filter add dev swp2 ingress protocol 802.1Q flower skip_sw \
        dst_mac 42:be:24:9b:76:20 vlan_id 100 vlan_prio 0 action drop

タイムベースのイングレスポリシング¶

スイッチのTTEthernetハードウェア機能は、IEEE 802.1Q-2018（以前は802.1Qci）で規定されたPer-Stream Filtering and Policing（PSFP）条項に準拠して制限できます。これにより、最大1024のフロー（宛先MACアドレス、VLAN ID、VLAN PCPからなるタプルで識別）に対して厳密なタイミングベースのアドミッション制御が実行できます。予期せぬ受信ウィンドウ外で受信したパケットは破棄されます。

この機能はtc-gateアクションのオフロードを通じて管理できます。ルーティングアクションはTTEthernetの仮想リンク内でイントリニックであり（タイムクリティカルなトラフィックの明示的なルーティングを行い、FDB、フラッディングなどに依存しません）、tc-gateアクションはsja1105にオフロードを依頼する際には常に単独で現れません。少なくとも1つのリダイレクトまたはトラップアクションがその後に続きます。

例: tc-taprioスケジュールをtc-gateスケジュールとフェーズ同期させます（クロックは1588アプリケーションスタックによって同期され、このドキュメントの範囲外です）。送信者から届いたパケットは破棄されません。注意点として、受信ウィンドウは送信ウィンドウよりも大きく（この例ではさらに大幅に）、リンクのパケット伝播遅延を補償するために設定されています（この遅延は1588アプリケーションスタックによって決定されます）。

受信者（sja1105）:

tc qdisc add dev swp2 clsact
now=$(phc_ctl /dev/ptp1 get | awk '/clock time is/ {print $5}') && \
        sec=$(echo $now | awk -F. '{print $1}') && \
        base_time="$(((sec + 2) * 1000000000))" && \
        echo "base time ${base_time}"
tc filter add dev swp2 ingress flower skip_sw \
        dst_mac 42:be:24:9b:76:20 \
        action gate base-time ${base_time} \
        sched-entry OPEN  60000 -1 -1 \
        sched-entry CLOSE 40000 -1 -1 \
        action trap

送信者:

now=$(phc_ctl /dev/ptp0 get | awk '/clock time is/ {print $5}') && \
        sec=$(echo $now | awk -F. '{print $1}') && \
        base_time="$(((sec + 2) * 1000000000))" && \
        echo "base time ${base_time}"
tc qdisc add dev eno0 parent root taprio \
        num_tc 8 \
        map 0 1 2 3 4 5 6 7 \
        queues 1@0 1@1 1@2 1@3 1@4 1@5 1@6 1@7 \
        base-time ${base_time} \
        sched-entry S 01  50000 \
        sched-entry S 00  50000 \
        flags 2

イングレスゲート操作をスケジュールするエンジンは、tc-taprioオフロードにも使用される同じエンジンです。したがって、同一の200nsスロット内で2つのゲートアクション（tc-gateまたはtc-taprioゲート）が同時に発火しないという制限は依然として適用されます。

実用性を高めるため、フローブロックを介して複数のイングレスポートでタイムトリガーされた仮想リンクを共有することが可能です。この場合、同時に発火する制限は適用されません。なぜなら、システム全体で1つのスケジュールが共有された仮想リンクのスケジュールに統合されるからです。

tc qdisc add dev swp2 ingress_block 1 clsact
tc qdisc add dev swp3 ingress_block 1 clsact
tc filter add block 1 flower skip_sw dst_mac 42:be:24:9b:76:20 \
        action gate index 2 \
        base-time 0 \
        sched-entry OPEN 50000000 -1 -1 \
        sched-entry CLOSE 50000000 -1 -1 \
        action trap

各フローのハードウェア統計情報も利用可能です（"pkts"はドロップされたフレーム数をカウントし、タイミング違反、宛先ポート不足、MTU制限チェックによるドロップフレームの合計を示します）。バイトレベルのカウンターは利用できません。

デバイスツリーバインディングとボード設計¶

このセクションは参照します Documentation/devicetree/bindings/net/dsa/sja1105.txt および、いくつかの潜在的なスイッチの注意点を示すことを目的としています。

RMII PHYの役割とオフバンドシグナル¶

RMII仕様では、50 MHzクロック信号はMACによって駆動されるか、外部のオシレーターによって駆動される（PHYによって駆動されることは許容されていない）。しかし、この仕様は比較的緩いものであり、複数の方法でデバイスが仕様を逸脱している。一部のPHYは仕様に反する動作を行い、50 MHzクロックを自ら出力ピンで駆動する出力ピンを提供する場合がある。これは、ユーザーにとって役立つようにと試みた動作である。一方で、SJA1105は二進法でしか設定できない。RMII MAC役割で動作する際には、クロック信号を駆動しようとする。この動作を防ぐには、RMII PHY役割に設定する必要がある。しかし、これを行うと意図せぬ副作用が生じる。RMII仕様では、PHYはRXD[1:0]を介してバンド外の信号を送信できる。これは、フレームのプリアンブル前に送信される追加のコードワード（/J/および/K/）である。MACはRMII仕様でこのバンド外のシグナル機構を定義されていない。したがって、SJA1105ポートがPHY役割に設定され、クロック信号の多重駆動を防ぐために設定される場合、必然的にRMII PHY間の接続が生成される。SJA1105はPHYインターフェースを完全にエミュレートし、フレームプリアンブル前に/J/および/K/のシンボルを生成する。これは、実際のPHYが理解しないはずの信号である。したがって、PHYはSJA1105がPHYとして動作している場合に送信された追加シンボルを100Base-Txワイヤーに符号化する。ワイヤーの他端では、一部のリンクパートナーがこれらの追加シンボルを無視する一方、他のパートナーはこれらを認識して以降のすべてのイーサネットフレームを破棄してしまう。これは、一部のリンクパートナーではパケットロスに見えるが、他のパートナーでは見られない。要約すると、RMIIモードでSJA1105がPHYに接続されている場合、参照クロックを駆動させる必要がある。

RGMII固定リンクと内部遅延¶

バインディングドキュメントで述べたように、第2世代のデバイスにはMAC内に調整可能な遅延ラインが含まれており、これにより正しいRGMIIタイミングバジェットを確立できます。電源投入時にこれらの遅延ラインは、受信と送信クロックを73.8度から101.7度の位相差でシフトさせることができます。ただし、遅延ラインは安定した周波数を持つクロック信号にロックする必要があります。これは、古い周波数と新しい周波数のクロック間に少なくとも2マイクロ秒の静寂期間が必要ということを意味します。そうでない場合、ロックが失われてしまい、遅延ラインはリセット（電源を切って再起動）する必要があります。RGMIIでは、リンク速度に応じてクロック周波数が変化します（1000Mbpsで125MHz、100Mbpsで25MHz、10Mbpsで2.5MHz）。リンク速度はANプロセス中に変化する可能性があります。スイッチポートがRGMII固定リンクで接続され、リンクパートナーのリンクステートライフサイクルがLinuxの制御範囲外（例えば異なるSoC）である場合、遅延ラインは手動の干渉（スイッチポートのifdown/ifup）がない限りロックされていない（非アクティブ）ままです。要約すると、RGMIIモードでは、リンクパートナーがリンク速度を変更しないか、変更する場合はスイッチポートと連携して行う必要があります（実際には、固定リンクの両端が同じLinuxシステムの制御下にある必要があります）。なぜ固定リンクインターフェースがリンク速度を変更する必要があるのかというと、リセット時に100Mbpsモードで起動するイーサネットコントローラーがあり、そのドライバーはギガビットでの動作が必要な場合、速度とクロック周波数を変更する必要があります。

MDIOバスとPHY管理¶

SJA1105はMDIOバスを持っておらず、インバンドANも実行しません。したがって、スイッチデバイスからリンクステートの通知は届きません。ボードは、スイッチに接続されたPHYをシステム内に存在する他のMDIOバス（例: DSAマスターのMDIOバス）に接続する必要があります。リンクステート管理は、ドライバーがPHYでネゴシエートされた設定とMACリンク速度をSPIコマンドで手動で同期を取ることで行われます。
