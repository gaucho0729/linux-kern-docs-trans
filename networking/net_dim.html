前提条件¶

このドキュメントでは、読者がネットワークドライバーや一般的な割込みモデレーションに関する基本的な知識を持っていることを前提としています。

はじめに¶

動的割込みモデレーション（DIM）（ネットワーク分野では）は、チャネルの割込みモデレーション設定を変更してパケット処理を最適化するメカニズムを指します。このメカニズムには、システムから収集したランタイムデータを分析して、チャネルのモデレーションパラメータを変更するかどうかを決定するアルゴリズムが含まれます。Net DIM はこのようなメカニズムです。アルゴリズムの各反復において、データサンプルを分析し、前のサンプルと比較して必要に応じて割込みモデレーション設定の一部を変更するかどうかを決定します。データサンプルにはデータ帯域幅、パケット数、イベント数が含まれており、サンプル間の時間も測定されます。Net DIM は現在のデータと前のデータを比較し、調整された割込みモデレーション設定オブジェクトを返します。一部のケースではアルゴリズムが変更を実行しないこともあります。設定項目はイベント間の最小許容時間（マイクロ秒）と、イベントごとの望ましいパケット数の最大値です。Net DIM アルゴリズムは帯域幅の向上を割込みレートの削減よりも重要視しています。

Net DIMアルゴリズム¶

Net DIM アルゴリズムの各反復は以下の手順に従います：

  1. 新しいデータサンプルを計算します。

  2. それを前のサンプルと比較します。

  3. 決定を下します - 割込みモデレーション設定項目を提案します。

  4. 提案された設定を適用するスケジュールワーク関数を実行します。

最初の2つのステップはシンプルです。新しいデータと以前のデータの両方が、Net DIMに登録されたドライバーによって提供されます。以前のデータは、前の反復処理に提供された新しいデータを指します。比較ステップでは、新しいデータと以前のデータの差異を確認し、最後のステップの結果を決定します。帯域幅が増加した場合、ステップの結果は「改善（better）」と判定され、帯域幅が減少した場合、「悪化（worse）」と判定されます。帯域幅に変化がない場合は、パケットレートを同様に比較します。増加は「改善」、減少は「悪化」となります。パケットレートにも変化がない場合、割り込みレートを比較します。このアルゴリズムは割り込みレートを最小化することを目的としており、割り込みレートの増加は「悪化」、減少は「改善」とみなされます。ステップ#2では、誤った結果を避けるための最適化が行われています。差分が特定のパーセンテージ以上である場合にのみ、サンプル間の差を有効な差とみなします。また、Net DIMは自ら測定を行わないため、ドライバーが提供するデータが有効であると仮定しています。

ステップ#3は、ステップ#2の結果とアルゴリズムの内部状態を基に、推奨される設定を決定します。状態はアルゴリズムの「方向」を反映しており、左（モデレーションの削減）、右（モデレーションの増加）、または停止（静止）のいずれかを示します。もう一つの最適化として、停止を決定する回数が多ければ多いほど、アルゴリズムの反復間隔が長くなるように設定されます。これにより、計算オーバーヘッドを削減します。また、「最も左」または「最も右」の決定に「駐車」した後、アルゴリズムは他の方向へステップを踏んでこの決定を検証する可能性があります。これは「深いスリープ状態」に陥らないようにするためです。決定がなされると、事前に定義されたプロファイルから割り込みモデレーションの設定が選択されます。

最後のステップは、登録されたドライバーに推奨される設定を適用するように通知することです。これは、Net DIM APIによって定義され、登録されたドライバーが提供する作業関数をスケジュールすることで実現されます。

ご覧の通り、Net DIM自体はシステムと積極的にやり取りしません。誤ったデータが提供された場合、正しい決定を下すのが困難になり、作業関数が推奨された設定を適用しない場合、Net DIMは無用になります。ただし、この仕組みにより、登録されたドライバーにはある程度の裁量が与えられ、特定の条件では部分的なデータを提供したり、アルゴリズムの推奨を無視する可能性があります。

DIMへのネットワークデバイスの登録¶

Net DIM APIは主な関数を公開しています net_dim()この関数はNet DIMアルゴリズムのエントリポイントであり、ドライバーが割り込みのモジュレーションパラメータを変更すべきかどうかを確認するたびに呼び出す必要があります。ドライバーは次の2つのデータ構造を提供する必要があります： struct dim および struct dim_sample. struct dim 特定のオブジェクト（RXキュー、TXキュー、その他のキューなど）のDIMの状態を記述します。これには現在選択されているプロファイル、以前のデータサンプル、ドライバーが提供したコールバック関数などが含まれます。 struct dim_sample データサンプルを記述し、これを struct dim に保存されているデータサンプルと比較して、アルゴリズムの次のステップを決定します。サンプルにはドライバーが測定したバイト数、パケット数、割り込み数を含める必要があります。

ネットワークドライバーからNet DIMを使用するには、ドライバーがメインの net_dim() 関数を呼び出す必要があります。推奨される方法は net_dim() ごとに割り込みを呼び出すことです。Net DIMには組み込まれたモジュレーションがあり、特定の条件で反復をスキップする可能性があるため、 net_dim() の呼び出しもモジュレーションする必要はありません。上記のように、ドライバーは struct dim から net_dim() 型のオブジェクトを提供する必要があります。Net DIMを使用する各エンティティは、データ構造に struct dim を含め、これを主なNet DIM APIオブジェクトとして使用する必要があります。 struct dim_sample は最新のバイト数、パケット数、割り込み数を保持する必要があります。計算は行わず、素データを含めるだけでよいです。

以下の net_dim() 関数自体は何も返しません。代わりにNet DIMはドライバーが提供したコールバック関数に依存しており、アルゴリズムが割り込みモジュレーションパラメータを変更するときに呼び出されます。このコールバックはデータフローへのオーバーヘッドを加えないように、別スレッドでスケジュールされ実行されます。作業が完了した後、Net DIMアルゴリズムは次の反復に進むために適切な状態に設定する必要があります。

例¶

以下のコードはドライバーをNet DIMに登録する方法を示しています。実際の使用例は完全ではありませんが、使用法の概要を明確にするはずです。

#include <linux/dim.h>

/* Callback for net DIM to schedule on a decision to change moderation */
void my_driver_do_dim_work(struct work_struct *work)
{
      /* Get struct dim from struct work_struct */
      struct dim *dim = container_of(work, struct dim,
                                     work);
      /* Do interrupt moderation related stuff */
      ...

      /* Signal net DIM work is done and it should move to next iteration */
      dim->state = DIM_START_MEASURE;
}

/* My driver's interrupt handler */
int my_driver_handle_interrupt(struct my_driver_entity *my_entity, ...)
{
      ...
      /* A struct to hold current measured data */
      struct dim_sample dim_sample;
      ...
      /* Initiate data sample struct with current data */
      dim_update_sample(my_entity->events,
                        my_entity->packets,
                        my_entity->bytes,
                        &dim_sample);
      /* Call net DIM */
      net_dim(&my_entity->dim, dim_sample);
      ...
}

/* My entity's initialization function (my_entity was already allocated) */
int my_driver_init_my_entity(struct my_driver_entity *my_entity, ...)
{
      ...
      /* Initiate struct work_struct with my driver's callback function */
      INIT_WORK(&my_entity->dim.work, my_driver_do_dim_work);
      ...
}

動的割込みモデレーション（DIM）ライブラリAPI¶

struct dim_cq_moder¶

CQのモジュレーション値の構造体。DIMとその消費者間での通信に使用します。

定義

struct dim_cq_moder {
  u16 usec;
  u16 pkts;
  u16 comps;
  u8 cq_period_mode;
};

メンバ

usec

CQのタイマースケジュール（DIMによる推奨）

pkts

CQのパケットカウンタースケジュール（DIMによる推奨）

comps

完了カウンター

cq_period_mode

CQの期間カウントモード（CQE/EQEから取得）

struct dim_sample¶

DIMサンプルデータの構造体。DIMとその消費者間での通信に使用します。

定義

struct dim_sample {
  ktime_t time;
  u32 pkt_ctr;
  u32 byte_ctr;
  u16 event_ctr;
  u32 comp_ctr;
};

メンバ

time

サンプルタイムスタンプ

pkt_ctr

パケット数

byte_ctr

バイト数

event_ctr

イベント数

comp_ctr

現在の完了カウンター

struct dim_stats¶

DIMの統計情報の構造体。現在の測定されたレートを保持するために使用します。

定義

struct dim_stats {
  int ppms;
  int bpms;
  int epms;
  int cpms;
  int cpe_ratio;
};

メンバ

ppms

毎ミリ秒のパケット数

bpms

毎ミリ秒のバイト数

epms

毎ミリ秒のイベント数

cpms

毎ミリ秒の完了数

cpe_ratio

完了数とイベント数の比率

struct dim¶

動的割込み調整（DIM）のダイナミックな構造。特定のDIMインスタンスに関するすべての情報を保持します。

定義

struct dim {
  u8 state;
  struct dim_stats prev_stats;
  struct dim_sample start_sample;
  struct dim_sample measuring_sample;
  struct work_struct work;
  void *priv;
  u8 profile_ix;
  u8 mode;
  u8 tune_state;
  u8 steps_right;
  u8 steps_left;
  u8 tired;
};

メンバ

state

アルゴリズムの状態（以下を参照）

prev_stats

前回のイテレーションからの測定レート（比較用）

start_sample

現在のイテレーション開始時のサンプリングデータ

measuring_sample

A dim_sample 現在のイベントを更新するために使用されるデータ

work

実行すべき作業

priv

dimを指す構造体へのポインタ

profile_ix

現在のモジュレーションプロファイル

mode

CQ期間カウントモード

tune_state

アルゴリズム調整状態（以下を参照）

steps_right

高モジュレーションへのステップ数

steps_left

低モジュレーションへのステップ数

tired

パーキング深度カウンター

enum dim_cq_period_mode¶

CQ期間カウントモード

定数

DIM_CQ_PERIOD_MODE_START_FROM_EQE

EQEからカウントを開始

DIM_CQ_PERIOD_MODE_START_FROM_CQE

CQEからカウントを開始（タイマーリセットを意味）

DIM_CQ_PERIOD_NUM_MODES

モード数

enum dim_state¶

DIMアルゴリズム状態

定数

DIM_START_MEASURE

これは最初のイテレーションです（新しいプロファイルを適用した後も同様）

DIM_MEASURE_IN_PROGRESS

アルゴリズムはすでに進行中です - 作業を実行する必要があるか確認

DIM_APPLY_NEW_PROFILE

DIM消費者が現在プロファイルを適用中です - 測定不要

説明

アルゴリズムがイテレーションを開始する有効な状態にあるかどうかを決定します。

enum dim_tune_state¶

DIMアルゴリズム調整状態

定数

DIM_PARKING_ON_TOP

アルゴリズムがローカルなピークポイントを検出 - 明確な差異がある場合に終了

DIM_PARKING_TIRED

アルゴリズムが深いピークポイントを検出 - tired > 0の場合は終了しない

DIM_GOING_RIGHT

アルゴリズムが高モジュレーションレベルを試行中

DIM_GOING_LEFT

アルゴリズムが低モジュレーションレベルを試行中

説明

アルゴリズムが実行すべきアクションを決定します。

enum dim_stats_state¶

DIMアルゴリズム統計状態

定数

DIM_STATS_WORSE

現在のイテレーションは以前よりも性能が悪くなっています

DIM_STATS_SAME

現在のイテレーションは以前と同様の性能を示しています

DIM_STATS_BETTER

現在のイテレーションは以前よりも性能が向上しています

説明

現在のイテレーションの評価を決定します。

enum dim_step_result¶

DIMアルゴリズムステップ結果

定数

DIM_STEPPED

通常のステップを実行しました

DIM_TOO_TIRED

同じステップが複数回実行された場合 - 疲れた駐車場に移動する必要があります

DIM_ON_EDGE

最も左または右のプロファイルに移動しました

説明

これはステップの結果を説明しています

bool dim_on_top(struct dim *dim)¶

現在の状態が停止するのに適した場所かどうかを確認（トップ位置）

パラメータ

struct dim *dim

DIMコンテキスト

説明

現在のプロファイルが駐車場として適切かどうかを確認します。これによりDIMチェックの頻度が低下します（プロファイルを変更する必要がないと仮定するため）

void dim_turn(struct dim *dim)¶

プロファイルの方向を変更して移動

パラメータ

struct dim *dim

DIMコンテキスト

説明

右に移動していた場合は左に、左に移動していた場合は右に移動します。現在駐車中であれば何もしません

struct dim *dim

説明

void dim_park_tired(struct dim *dim)¶
