ジェネリックHDLCレイヤー¶

Krzysztof Halasa <khc@pm.waw.pl>

汎用HDLCレイヤーは現在、次のプロトコルをサポートしています:

  1. フレームレレー (ANSI、CCITT、CiscoおよびLMIなし)

    • 通常の（ルーテッド）インターフェースおよびイーサネットブリッジ（イーサネットデバイスエミュレーション）インターフェースは、単一のPVCを共有できます。

    • ARPサポート（カーネル内にはInARPサポートがありません - 一部の実験的なInARPユーザースペースデーモンが利用可能です： http://www.kernel.org/pub/linux/utils/net/hdlc/).

  2. raw HDLC - IP（IPv4）インターフェースまたはイーサネットデバイスエミュレーションのいずれか

  3. Cisco HDLC

  4. PPP

  5. X.25（X.25ルーティンを使用します。）

汎用HDLCはプロトコルドライバーのみです - 特定のハードウェアに使用する低レベルドライバーが必要です。

イーサネットデバイスエミュレーション（HDLCまたはフレームレレーPVCを使用）はIEEE 802.1Q（VLAN）および802.1D（イーサネットブリッジング）と互換性があります。

hdlc.oおよびハードウェアドライバーがロードされていることを確認してください。これにより、「hdlc」（hdlc0など）のネットワークデバイスが複数作成され、それぞれのWANポートに1つずつ作成されます。'sethdlc'ユーティリティが必要です。取得方法は以下の通り：

http://www.kernel.org/pub/linux/utils/net/hdlc/

sethdlc.cユーティリティをコンパイル：

gcc -O2 -Wall -o sethdlc sethdlc.c

あなたのカーネルに適した正しいバージョンのsethdlcを使用していることを確認してください。

sethdlcを使用して、物理インターフェース、クロックレート、使用するHDLCモード、およびフレームレレーを使用する場合の必要なPVCを追加してください。通常は以下のような設定を行います：

sethdlc hdlc0 clock int rate 128000
sethdlc hdlc0 cisco interval 10 timeout 25

または:

sethdlc hdlc0 rs232 clock ext
sethdlc hdlc0 fr lmi ansi
sethdlc hdlc0 create 99
ifconfig hdlc0 up
ifconfig pvc0 localIP pointopoint remoteIP

フレームレレーモードの場合、pvcデバイスを使用する前に、ifconfig master hdlcデバイス up（IPアドレスを割り当てることなく）してください。

インターフェースの設定：

  • v35 | rs232 | x21 | t1 | e1

    • カードがソフトウェア選択可能なインターフェースを持つ場合、指定されたポートの物理インターフェースを設定します。

    ループバック

    • ハードウェアループバックを有効化（テスト用のみ）

  • クロック ext

    • RXクロックとTXクロックの両方が外部

  • クロック インターフェース

    • RXクロックとTXクロックの両方が内部

  • クロック txint

    • RXクロックは外部、TXクロックは内部

  • クロック txfromrx

    • RXクロックは外部、TXクロックはRXクロックから導出

  • レート

    • bps単位でクロックレートを設定（「int」または「txint」クロックの場合のみ）

プロトコルの設定：

  • hdlc - raw HDLC（IPのみ）モードを設定

    nrz / nrzi / fm-mark / fm-space / manchester - 送信コードを設定

    no-parity / crc16 / crc16-pr0（初期ゼロを設定したCRC16） / crc32-itu

    crc16-itu（ITU-T多項式を使用したCRC16） / crc16-itu-pr0 - パリティを設定

  • hdlc-eth - HDLCを使用したイーサネットデバイスエミュレーション。パリティおよび符号化は上記と同じ。

  • cisco - Cisco HDLCモードを設定（IP、IPv6およびIPXをサポート）

    interval - keepaliveパケット間の秒数

    timeout - 最後にkeepaliveパケットを受信した後、リンクがダウンとみなすまでの秒数

    リンクがダウンとみなします

  • ppp - 同步PPPモードを設定

  • x25 - X.25モードを設定

  • fr - Frame Relayモード

    lmi ansi / ccitt / cisco / none - LMI（リンク管理）タイプ

    dce - Frame Relay DCE（ネットワーク）側のLMIを使用。デフォルトのDTE（ユーザー）側とは異なります。

    時計とは関係ありません！

    • t391 - リンク整合性検証ポーリングタイマ（秒単位）- ユーザー

    • t392 - ポーリング検証タイマ（秒単位）- ネットワーク

    • n391 - フルステータスポーリングカウンター - ユーザー

    • n392 - エラースレッショール - ユーザーとネットワーク共通

    • n393 - 監視イベントカウント - ユーザーとネットワーク共通

Frame-Relay専用:

  • create n | delete n - DLCI #nを持つPVCインターフェースを追加/削除。新規インターフェースはpvc0, pvc1などと名付けられます。

  • create ether n | delete ether n - イーサネットブリッジドフレーム用のデバイスを追加。デバイスはpvceth0, pvceth1などと名付けられます。

ボード固有の問題¶

n2.oおよびc101.oにはパラメータが必要です:

insmod n2 hw=io,irq,ram,ports[:io,irq,...]

例:

insmod n2 hw=0x300,10,0xD0000,01

または:

insmod c101 hw=irq,ram[:irq,...]

例:

insmod c101 hw=9,0xdc000

カーネルに組み込まれている場合、これらのドライバはカーネル（コマンドライン）パラメータが必要です:

n2.hw=io,irq,ram,ports:...

または:

c101.hw=irq,ram:...

N2、C101、またはPLX200SYNカードで問題がある場合、"private"コマンドを実行してポートのパケットディスクリプタリング（カーネルログに記録されます）:

sethdlc hdlc0 private

ハードウェアドライバは# define DEBUG_RINGSでビルドする必要があります。この情報は不具合報告に添付すると役立ちます。どうぞお気軽にお知らせください。

パッチやその他の情報はこちら: <http://www.kernel.org/pub/linux/utils/net/hdlc/>.
