Devlink Info¶

以下の devlink-info メカニズムは、デバイスドライバーがハードウェアおよびファームウェアの情報を標準的で拡張可能な形式で報告できるようにします。

このAPIの元となる動機は、 devlink-info APIの動機は二つありました。

  • ファームウェアの管理をベンダーに依存しない形で複数のマシン全体で自動化することを可能にします（参照 Devlink Flash);

  • 各コンポーネントのファームウェアバージョンを指定する（ethtoolのバージョン文字列とは異なります）。

devlink-info 複数のオブジェクトの報告をサポートしています。ドライバーバージョンの報告は一般的に推奨されません（ここでも、他のLinux APIでも同様です）。

上位レベルの情報オブジェクト一覧¶

名前

説明

driver

現在使用中のデバイスドライバーの名前、sysfsでも取得可能です。

serial_number

デバイスのシリアル番号。

これは通常、ASICのシリアル番号であり、デバイスのPCIコンフィギュレーションスペースにもよく見られます。 デバイスシリアル番号 capability.

シリアル番号は物理デバイスごとに一意でなければなりません。場合によってはデバイスのシリアル番号が48ビット（イーサネットMACアドレスの長さ）程度しかなく、PCI DSNは64ビット長いため、デバイスはシリアル番号に追加情報を埋め込むことがあります。たとえばポートIDやPCIインターフェースIDを2バイト分追加する場合があります。ドライバーはこのようなパディングやインターフェースIDを除去または正規化し、ハードウェアを一意に識別するシリアル番号のみを報告する必要があります。つまり、同じデバイスの2つのポートやマルチホストデバイスの2つのホストで報告されるシリアル番号は同一であるべきです。

board.serial_number

デバイスのボードシリアル番号。

これは通常、ボードのシリアル番号であり、PCI ビタル・プロダクト・データ (VPD).

fixed

フィールドアップデートができないコンポーネントのハードウェア識別子とバージョンのグループ。

このセクションのバージョンはデバイスの設計を特定します。たとえば、PCI VPDで報告されるコンポーネント識別子やボードバージョンです。データは devlink-info 最小限の論理的なコンポーネントに分割する必要があります。たとえば、PCI VPDはさまざまな情報を結合してPart Number文字列を形成するかもしれませんが、 devlink-info すべての部分を個別の項目として報告する必要があります。

このグループには、シリアル番号などの頻繁に変化する識別子は含まれてはいけません。参照 Devlink Flash その理由を理解してください。

running

現在実行中のソフトウェア/ファームウェアに関する情報のグループ。これらのバージョンは通常、再起動後にのみ更新され、場合によってはデバイスのリセット後に更新されます。

stored

デバイスフラッシュ内のソフトウェア/ファームウェアバージョンのグループ。

保存された値は、再起動が行われていない場合でもフラッシュの変更を反映する必要があります。デバイスが新しいソフトウェアをフラッシュした際にバージョンを更新できない場合、 stored バージョンを報告してはいけません。

各バージョンは、各バージョングループ内で最大1回しかレポートされません。フラッシュメモリに保存されたファームウェアコンポーネントは、 running および stored セクションに必ず表示される必要があります。デバイスがレポートを生成できる場合 stored バージョン（参照 Devlink Flash）。ソフトウェア/ファームウェアコンポーネントがディスクからロードされる場合（例： /lib/firmware）のみ、実行中のバージョンがカーネルAPI経由でレポートされるべきです。

汎用バージョン¶

ドライバーは、バージョン情報のエクスポートに次の汎用名を使用することが期待されています。既存のドライバ固有のバージョンと再利用可能な名前が存在しない場合、ドライバー開発者は既存のドライバ固有のバージョンを参照して再利用を試すべきです。最終手段として、コンポーネントが本当に一意である場合、ドライバ固有の名前を使用することは許可されていますが、これらはドライバ固有のファイルでドキュメント化する必要があります。

すべてのバージョンは、次の用語を試して使用すべきです：

一般的なバージョン接尾辞一覧¶

名前

説明

id, revision

設計およびリビジョンの識別子、主にハードウェアバージョンに使用されます。

api

コンポーネント間のAPIバージョン。API項目は通常、ユーザーにとって価値が限られ、ベンダーが他のバージョンから推測できるため、APIバージョンの追加は一般的にノイズとして推奨されません。

bundle_id

デバイスにフラッシュされたディストリビューションパッケージの識別子。これは、ファームウェアパッケージの属性であり、複数のバージョンをカバーしてファームウェアイメージの管理を容易にするためのものです（参照 Devlink Flash).

bundle_id は両方の running および stored バージョンに表示されるべきではありません。ただし、 bundle_id をカバーするコンポーネントのいずれかが変更され、バンドルからのバージョンと一致しなくなった場合

board.id¶

ボード設計の一意な識別子。

board.rev¶

ボード設計のリビジョン。

asic.id¶

ASIC設計の識別子。

asic.rev¶

ASIC設計のリビジョン/ステッピング。

board.manufacture¶

部品を製造した企業または工場の識別子。

fw¶

全体的なファームウェアバージョン、通常はfw.mgmt、fw.appなど複数のバージョンを表します。

fw.mgmt¶

制御ユニットのファームウェアバージョン。このファームウェアはハウスキーピングタスク、PHY制御などに責任を持ちますが、パケット単位のデータパス操作には関与しません。

fw.mgmt.api¶

ドライバーとファームウェア間のソフトウェアインターフェースのファームウェアインターフェース仕様バージョン。

fw.app¶

高速パケット処理を制御するデータパスマイクロコード。

fw.undi¶

UNDIソフトウェア、UEFIドライバ、ファームウェア、または両方を含mayする。

fw.ncsi¶

ネットワークコントローラー側帯インターフェースをサポート/処理するソフトウェアのバージョン。

fw.psid¶

ファームウェアパラメータセットの一意な識別子。これらは通常、製造時に定義された特定のボードのパラメータです。

fw.roce¶

RoCE管理を担当するRoCEファームウェアバージョン。

fw.bundle_id¶

ファームウェアバンドル全体の固有の識別子。
