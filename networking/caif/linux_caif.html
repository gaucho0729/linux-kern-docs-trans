はじめに¶

CAIFは、ST-Ericssonのセルラーモデムがモデムとホスト間の通信のために使用するMUXプロトコルです。ホストプロセスは仮想ATチャネルを開くことができ、GPRSデータ接続、ビデオチャネル、ユーティリティチャネルを起動できます。ユーティリティチャネルは、モデムとホスト間の汎用パイプです。

ST-Ericssonモデムは、モデムとホスト間の通信にいくつかのトランスポートをサポートしています。現在、LinuxではUARTとループバックが利用可能です。

アーキテクチャ¶

CAIFの実装は以下の通りに分かれています:

  • CAIFソケットレイヤーおよびGPRS IPインターフェース。

  • CAIFコアプロトコル実装

  • CAIFリンクレイヤー、NETデバイスとして実装されています。

ハードロックアップ検出器は、定期的に実行されるhrtimerによって生成される割込みでウォッチドッグタスクを起動します。ハードロックアップの検出には、「watchdog_thresh」（コンパイル時に初期化され、sysctlの同じ名前で設定可能）秒ごとにNMI perfイベントが生成されます。システム内のどのCPUもその間hrtimer割込みを受けていない場合、ハードロックアップ検出器（NMI perfイベントのハンドラ）がカーネル警告を生成するか、設定に応じてパニックを呼び出します。¶

CAIFコアプロトコルレイヤー¶

CAIFコアレイヤーは、ST-Ericssonが定義したCAIFプロトコルを実装します。このプロトコルスタックは、仕様で記述された各レイヤーを別個のレイヤーとして実装する階層型アーキテクチャで構成されています。このアーキテクチャは、「プロトコルレイヤー」および「プロトコルパケット」の設計パターンにインスピレーションを得ています。

CAIFの構造¶

コアCAIF実装には以下の要素があります:

  • CAIFのシンプルな実装。

  • レイヤードアーキテクチャ（Streamsスタイル）、CAIF仕様の各レイヤーは別個のcファイルで実装されています。

  • クライアントはPHYレイヤーを追加するために構成関数を呼び出す必要があります。

  • クライアントは、受信および送信関数を使用してCAIFペイロードを消費/生成するため、CAIFレイヤーを実装する必要があります。

  • クライアントはクライアントレイヤーを追加および接続するために構成関数を呼び出す必要があります。

  • CAIFパケット（cfpkt）を受信/送信する際、所有権は呼び出された関数に移されます（フレーミングレイヤーの受信関数を除く）。

レイヤードアーキテクチャ¶

CAIFプロトコルは2つの部分に分かれます：サポート関数とプロトコル実装。サポート関数には以下の要素があります:

  • CFPKT CAIFパケット。CAIFプロトコルパケットの実装。CAIFパケットは、作成、破壊、コンテンツの追加、プロトコルパケットへのヘッダーおよびトレーラーの追加/抽出を行う関数を持っています。

CAIFプロトコル実装には以下の要素があります:

  • CFCNFG CAIF構成レイヤー。CAIFプロトコルスタックを構成し、CAIFスタック上にリンクレイヤーおよびドライバインターフェースを追加するためのクライアントインターフェースを提供します。

  • CFCTRL CAIF制御レイヤー。列挙やチャネル設定などの制御メッセージの符号化・復号を行います。また、リクエストと応答メッセージのマッチングも行います。

  • CFSERVL ジェネラルCAIFサービスレイヤー機能；フロー制御およびリモートシャットダウンリクエストの処理を行います。

  • CFVEI CAIF VEIレイヤー。VEI（仮想外部インターフェース）上でのCAIF ATチャネルを処理します。このレイヤーはVEIフレームを符号化・復号化します。

  • CFDGML CAIFデータグラムレイヤー。CAIFデータグラムレイヤー（IPトラフィック）を処理し、データグラムフレームを符号化・復号化します。

  • CFMUX CAIFマルチプレクサレイヤー。複数の物理的なベアラーと複数のチャネル（VEI、データグラムなど）間の多重化を処理します。MUXは既存のCAIFチャネルと物理的なインスタンスを追跡し、Channel-IdとPhysical-IDに基づいて適切なインスタンスを選択します。

  • CFFRML CAIFフレーミングレイヤー。フレーミング（フレーム長とフレームチェックサム）を処理します。

  • CFSERL CAIFシリアルレイヤー。フレームをCAIFフレームに正しく長さを保って連結・分割します。

                | CFCNFG  |

|   AT    |     | Control |     | Datagram|

このレイヤードアプローチでは以下の「ルール」が適用されます。

  • すべてのレイヤーは同じ構造体「struct cflayer」を埋め込んでいます。

  • レイヤーは他のレイヤーのプライベートデータに依存しません。

  • レイヤーはポインタを設定して積み重ねられます。

    layer->up , layer->dn

  • データを上位に送信するには、各レイヤーは以下を行います：

    layer->up->receive(layer->up, packet);

  • データを下位に送信するには、各レイヤーは以下を行います：

    layer->dn->transmit(layer->dn, packet);

CAIFソケットとIPインターフェース¶

IPインターフェースおよびCAIFソケットAPIはCAIFコアプロトコルの上に実装されています。IPインターフェースおよびCAIFソケットはCAIFコアプロトコルスタックと同様に「struct cflayer」のインスタンスを持っています。ネットワークデバイスおよびソケットはCAIFスタックの他の部分と同様に「struct cflayer」で定義された「receive()」関数を実装します。このようにして、パケットの送受信は他のレイヤーと同様に処理されます。「dn->transmit()」関数が呼び出されてデータを送信します。

リンクレイヤーの設定¶

リンクレイヤーはLinuxネットワークデバイスとして実装されています（struct net_device）。ペイロードのハンドリングおよび登録は標準的なLinuxメカニズムを使用して行われます。

CAIFプロトコルは再送を実装せずに無損失リンクレイヤーに依存しています。これはパケットのドロップが起こってはならないことを意味します。そのため、物理インターフェースがすべてのCAIFチャネルに対してフロー停止を開始できるフロー制御メカニズムが実装されています。
