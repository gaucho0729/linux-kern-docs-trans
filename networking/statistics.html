インターフェース統計¶

概要¶

このドキュメントはLinuxネットワークインターフェース統計のガイドです。

Linuxにおけるインターフェース統計の主な3つの情報源は以下の通りです：

  • 標準インターフェース統計（に基づく） struct rtnl_link_stats64;

  • プロトコル固有の統計；および

  • ドライバ定義の統計（ethtool経由で利用可能）

標準インターフェース統計¶

標準統計にアクセスするための複数のインターフェースがあります。最も一般的なのは ip コマンドは iproute2:

$ ip -s -s link show dev ens4u1u1
6: ens4u1u1: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP mode DEFAULT group default qlen 1000
  link/ether 48:2a:e3:4c:b1:d1 brd ff:ff:ff:ff:ff:ff
  RX: bytes  packets  errors  dropped overrun mcast
  74327665117 69016965 0       0       0       0
  RX errors: length   crc     frame   fifo    missed
             0        0       0       0       0
  TX: bytes  packets  errors  dropped carrier collsns
  21405556176 44608960 0       0       0       0
  TX errors: aborted  fifo   window heartbeat transns
             0        0       0       0       128
  altname enp58s0u1u1

注意してください -s すべてのメンバを表示するには2回指定します struct rtnl_link_stats64. -s 詳細なエラーが表示されなくなるように1回指定します

ip JSON形式の出力をサポートしており、 -j オプションの下に隠されています。

プロトコル固有の統計¶

デバイスの設定に使用される一部のインターフェースは、関連する統計を報告することもできます。たとえば、パーズフレームを設定するために使用されるethtoolインターフェースは、対応するハードウェアカウンタを報告できます：

$ ethtool --include-statistics -a eth0
Pause parameters for eth0:
Autonegotiate:        on
RX:                   on
TX:                   on
Statistics:
  tx_pause_frames: 1
  rx_pause_frames: 1

ドライバ定義の統計¶

ドライバ定義のethtool統計は次のコマンドでダンプできます： ethtool -S $ifc, e.g.:

$ ethtool -S ens4u1u1
NIC statistics:
   tx_single_collisions: 0
   tx_multi_collisions: 0

uAPIs¶

procfs¶

履歴 /proc/net/dev テキストインターフェースは、インターフェースの一覧とその統計情報を取得できます。

このインターフェースは使用しているにもかかわらず、 struct rtnl_link_stats64 内部的に一部のフィールドを組み合わせています。

sysfs¶

sysfs内の各デバイスディレクトリには、 統計 ディレクトリ（例：/sys/class/net/lo/statistics/ )に、メンバーに対応するファイルが含まれています。このシンプルなインターフェースは、ツールにアクセスできない制約のある/埋め込まれた環境で特に便利です。しかし、複数の統計を読み込む際には非効率です。 struct rtnl_link_stats64.

内部的に全体をダンプして、 struct rtnl_link_stats64 アクセスされたファイルに対応する統計のみを報告します。

sysfsのファイルは以下に記載されています。 Documentation/ABI/testing/sysfs-class-net-statistics.

netlink¶

rtnetlink (NETLINK_ROUTE) is the preferred method of accessing struct rtnl_link_stats64 stats.

Statistics are reported both in the responses to link information requests (RTM_GETLINK) and statistic requests (RTM_GETSTATS, when IFLA_STATS_LINK_64 bit is set in the .filter_mask of the request).

ethtool¶

Ethtool IOCTL interface allows drivers to report implementation specific statistics. Historically it has also been used to report statistics for which other APIs did not exist, like per-device-queue statistics, or standard-based statistics (e.g. RFC 2863).

Statistics and their string identifiers are retrieved separately. Identifiers via ETHTOOL_GSTRINGS with string_set 設定に設定する ETH_SS_STATS, and values via ETHTOOL_GSTATS. User space should use ETHTOOL_GDRVINFO to retrieve the number of statistics (.n_stats).

ethtool-netlink¶

Ethtool netlink is a replacement for the older IOCTL interface.

Protocol-related statistics can be requested in get commands by setting the ETHTOOL_FLAG_STATS flag in ETHTOOL_A_HEADER_FLAGS. Currently statistics are supported in the following commands:

  • ETHTOOL_MSG_PAUSE_GET

debugfs¶

Some drivers expose extra statistics via debugfs.

struct rtnl_link_stats64¶

struct rtnl_link_stats64¶

The main device statistics structure.

定義

struct rtnl_link_stats64 {
  __u64 rx_packets;
  __u64 tx_packets;
  __u64 rx_bytes;
  __u64 tx_bytes;
  __u64 rx_errors;
  __u64 tx_errors;
  __u64 rx_dropped;
  __u64 tx_dropped;
  __u64 multicast;
  __u64 collisions;
  __u64 rx_length_errors;
  __u64 rx_over_errors;
  __u64 rx_crc_errors;
  __u64 rx_frame_errors;
  __u64 rx_fifo_errors;
  __u64 rx_missed_errors;
  __u64 tx_aborted_errors;
  __u64 tx_carrier_errors;
  __u64 tx_fifo_errors;
  __u64 tx_heartbeat_errors;
  __u64 tx_window_errors;
  __u64 rx_compressed;
  __u64 tx_compressed;
  __u64 rx_nohandler;
};

メンバ

rx_packets

Number of good packets received by the interface. For hardware interfaces counts all good packets received from the device by the host, including packets which host had to drop at various stages of processing (even in the driver).

tx_packets

Number of packets successfully transmitted. For hardware interfaces counts packets which host was able to successfully hand over to the device, which does not necessarily mean that packets had been successfully transmitted out of the device, only that device acknowledged it copied them out of host memory.

rx_bytes

Number of good received bytes, corresponding to rx_packets.

For IEEE 802.3 devices should count the length of Ethernet Frames excluding the FCS.

tx_bytes

Number of good transmitted bytes, corresponding to tx_packets.

For IEEE 802.3 devices should count the length of Ethernet Frames excluding the FCS.

rx_errors

Total number of bad packets received on this network device. This counter must include events counted by rx_length_errors, rx_crc_errors, rx_frame_errors and other errors not otherwise counted.

tx_errors

Total number of transmit problems. This counter must include events counter by tx_aborted_errors, tx_carrier_errors, tx_fifo_errors, tx_heartbeat_errors, tx_window_errors and other errors not otherwise counted.

rx_dropped

受信されたが処理されなかったパケット数（リソース不足やサポートされていないプロトコルなどにより）。ハードウェアインターフェースでは、このカウンターにはデバイスが別途カウントしているパケットドロップを含めないべきです。 rx_missed_errors (procfsがこの2つのカウンターを統合しているため)

tx_dropped

送信までの過程でドロップされたパケット数（リソース不足などにより）。

multicast

受信されたマルチキャストパケット数。ハードウェアインターフェースでは、この統計は通常デバイスレベルで計算されるため（ rx_packets)、ホストに到達しなかったパケットを含む可能性があります。

IEEE 802.3デバイスではこのカウンターは以下のようになる可能性があります：

  • 30.3.1.1.21 aMulticastFramesReceivedOK

collisions

パケット送信時の衝突数。

rx_length_errors

無効な長さによりドロップされたパケット数。これは「フレーム」エラーの一部で、 /proc/net/dev.

IEEE 802.3デバイスではこのカウンターは以下の属性の合計に等しくべきです：

  • 30.3.1.1.23 aInRangeLengthErrors

  • 30.3.1.1.24 aOutOfRangeLengthField

  • 30.3.1.1.25 aFrameTooLongErrors

rx_over_errors

受信FIFOオーバーフローイベントカウンター。

歴史的に発生したオーバーフローイベントのカウント。このようなイベントは受信ディスクリプターや割り込み経由で報告される可能性があり、ドロップパケットとは1対1に対応しない場合があります。

高速インターフェースでは、このカウンターはホストが提供するバッファに収まらなかったパケット数を示すことを推奨します（例：MTUより大きいパケットやリングの次のバッファがスキャッターテランスで利用不可な場合）。

「フレーム」エラーの一部で、 /proc/net/dev.

この統計は歴史的に rx_fifo_errors.

この統計はハードウェアイベントに該当し、ソフトウェアデバイスでは一般的に使用されません。

rx_crc_errors

CRCエラーにより受信されたパケット数。これは「フレーム」エラーの一部で、 /proc/net/dev.

IEEE 802.3デバイスではこのカウンターは以下のものと等しくべきです：

  • 30.3.1.1.6 aFrameCheckSequenceErrors

rx_frame_errors

受信フレームアライメントエラー。これは「フレーム」エラーの一部で、 /proc/net/dev.

IEEE 802.3デバイスではこのカウンターは以下のものと等しくべきです：

  • 30.3.1.1.7 aAlignmentErrors

rx_fifo_errors

受信FIFOエラーカウンター。

歴史的に発生したオーバーフローイベントのカウント。このようなイベントは受信ディスクリプターや割り込み経由で報告される可能性があり、ドロップパケットとは1対1に対応しない場合があります。

この統計は歴史的に rx_over_errors。高速インターフェースのドライバーでの使用は推奨されません。

この統計はソフトウェアデバイスで使用され、例としてソフトウェアパケットキューのオーバーフロー（可能）やシーケンシングエラー（GRE）をカウントします。

rx_missed_errors

ホストがパケットを欠損した回数。これは「drop」カウンタに統合されています。 /proc/net/dev.

デバイスがバッファスペースの不足によりパケットをドロップした回数をカウントします。これは通常、ホストインターフェースがネットワークインターフェースより遅く、またはホストが受信パケットレートに追いついていないことを示します。

この統計はハードウェアイベントに該当し、ソフトウェアデバイスでは使用されません。

tx_aborted_errors

「キャリア」エラーの集計に含まれる一部です。 /proc/net/devIEEE 802.3デバイスで半二重運用可能な場合、このカウンタは以下のものと同等でなければなりません：

  • 30.3.1.1.11 aFramesAbortedDueToXSColls

高速インターフェースでは、このカウンタを一般的なデバイス廃棄カウンタとして使用できます。

tx_carrier_errors

送信中にキャリアの喪失により発生したフレーム送信エラーの回数。これは「キャリア」エラーの集計に含まれる一部です。 /proc/net/dev.

IEEE 802.3デバイスではこのカウンターは以下のものと等しくべきです：

  • 30.3.1.1.13 aCarrierSenseErrors

tx_fifo_errors

デバイスのFIFOアンダーラン/アンダーフローにより発生したフレーム送信エラーの回数。この状態は、デバイスがフレームの送信を開始したが、送信機に十分な時間内にフレーム全体を届けられなかったときに発生します。これは「キャリア」エラーの集計に含まれる一部です。 /proc/net/dev.

tx_heartbeat_errors

古い半二重イーサネットにおけるハートビート/SQEテストエラーの回数。これは「キャリア」エラーの集計に含まれる一部です。 /proc/net/dev.

IEEE 802.3デバイスではおそらく以下のものと同等です：

  • 30.3.2.1.4 aSQETestErrors

tx_window_errors

遅延衝突（イーサネットでは最初の64B送信後）により発生したフレーム送信エラーの回数。これは「キャリア」エラーの集計に含まれる一部です。 /proc/net/dev.

IEEE 802.3デバイスではこのカウンターは以下のものと等しくべきです：

  • 30.3.1.1.10 aLateCollisions

rx_compressed

正しく受信された圧縮パケットの回数。このカウンタはパケット圧縮をサポートするインターフェース（例：CSLIP、PPP）でのみ意味を持ちます。

tx_compressed

送信された圧縮パケットの回数。このカウンタはパケット圧縮をサポートするインターフェース（例：CSLIP、PPP）でのみ意味を持ちます。

rx_nohandler

インターフェースで受信されたが、ネットワーキングスタックによりドロップされたパケットの回数。これはデバイスがパケット受信を指定されていない（例：ボンドのバックアップリンク）場合に発生します。

ドライバ作成者向けの注意事項¶

ドライバは、が一致するメンバを持つすべての統計を報告する必要があります。 struct rtnl_link_stats64 exclusively via .ndo_get_stats64. ethtoolまたはdebugfs経由でこのような標準的な統計を報告することは受け入れられません。

ドライバは、に可能な限り高い準拠を確保する必要があります。 struct rtnl_link_stats64注意として、詳細なエラーステータスは一般の rx_error / tx_error カウンタに追加する必要があります。

以下の .ndo_get_stats64 コールバックは、経由のアクセスにより眠ってはいけません。 /proc/net/dev. ドライバがデバイスから統計を取得する際にはleepする場合、定期的に非同期に実行し、最新のコピーをのみ返す必要があります。 .ndo_get_stats64. Ethtoolの割込みコールスティングインターフェースにより、必要に応じて統計の更新頻度を設定できます。

ethtool統計情報の取得は複数のシスカールを伴うプロセスであり、ドライバーはユーザー空間がそれらを読み込む際にレースコンディションを避けるため、統計情報の数を一定に保つことが推奨されます。

インターフェースのアップダウンなどの通常操作においても、統計情報は維持される必要があります。
