DNSリゾルバー・モジュール¶

概要¶

DNSリゾルバモジュールは、カーネルサービスがdns_resolverというキーテイプのキーを要求することでDNSクエリを実行する方法を提供します。これらのクエリは/sbin/request-keyを通じてユーザースペースにアップコールされます。

これらのルーチンは、dns.upcall、cifs.upcallおよびrequest-keyといったユーザースペースツールによってサポートされる必要があります。これは開発中であり、現在は完全な機能セットを提供していません。サポートしている機能には以下の通りです：

(*) dns_resolverキーテイプを実装してユーザースペースに連絡します。

サポートされていないAFSの機能には次の通りです：

(*) AFSDBリソースレコードのDNSクエリサポート。

このコードはCIFSファイルシステムから抽出されました。

コンパイル¶

このモジュールは、以下のカーネルのコンフィギュレーションオプションを有効にすることで有効になります：

CONFIG_DNS_RESOLVER     - tristate "DNS Resolver support"

設定¶

この機能を設定するには、/etc/request-key.confファイルを編集し、/sbin/request-keyがアップコールを適切に処理できるようにする必要があります。たとえば、基本的なdnameからIPv4/IPv6アドレスの解決を処理するには、以下の行を追加します：

#OP     TYPE            DESC    CO-INFO PROGRAM ARG1 ARG2 ARG3 ...
#====== ============    ======= ======= ==========================
create  dns_resolver    *       *       /usr/sbin/cifs.upcall %k

「foo」というクエリタイプのクエリを処理するには、より一般的な行の上に以下の行を追加します。最初にマッチする行が選ばれます：

create  dns_resolver    foo:*   *       /usr/sbin/dns.foo %k

使い方¶

この機能を活用するには、以下の関数のいずれかをモジュールで実装されている後、呼び出すことができます：

   #include <linux/dns_resolver.h>

::

   int dns_query(const char *type, const char *name, size_t namelen,
                const char *options, char **_result, time_t *_expiry);

This is the basic access function.  It looks for a cached DNS query and if
it doesn't find it, it upcalls to userspace to make a new DNS query, which
may then be cached.  The key description is constructed as a string of the
form::

           [<type>:]<name>

where <type> optionally specifies the particular upcall program to invoke,
and thus the type of query to do, and <name> specifies the string to be
looked up.  The default query type is a straight hostname to IP address
set lookup.

The name parameter is not required to be a NUL-terminated string, and its
length should be given by the namelen argument.

The options parameter may be NULL or it may be a set of options
appropriate to the query type.

The return value is a string appropriate to the query type.  For instance,
for the default query type it is just a list of comma-separated IPv4 and
IPv6 addresses.  The caller must free the result.

The length of the result string is returned on success, and a negative
error code is returned otherwise.  -EKEYREJECTED will be returned if the
DNS lookup failed.

If _expiry is non-NULL, the expiry time (TTL) of the result will be
returned also.

カーネルは内部のキーリングで検索したキーをキャッシュしています。このキャッシュは、CAP_SYS_ADMINの権限を持つプロセスがKEYCTL_KEYRING_CLEARをキーリングIDに対して使用することでクリアできます。

ユーザースペースからDNSキーを読み込む¶

dns_resolverタイプのキーはkeyctl_read()または「keyctl read/print/pipe」を使用してユーザースペースから読み込むことができます。

メカニズム¶

dnsresolverモジュールは「dns_resolver」と呼ばれるキーテイプを登録します。このタイプのキーは、ユーザースペースからDNS検索結果を転送およびキャッシュするために使用されます。

dns_query()が呼び出されると、request_key()を呼び出してローカルキーリングでキャッシュされたDNS結果を検索します。見つからない場合は、ユーザースペースにアップコールして新しい結果を取得します。

ユーザースペースへのアップコールはrequest_key()アップコールベクターを通じて行われ、/etc/request-key.conf内の設定行によって/sbin/request-keyが実行するプログラムを指定します。

アップコールハンドラープログラムはDNSをクエリし、keyctl_instantiate_key()ルーチンに渡すのに適した形式に結果を処理します。その後、dns_resolver_instantiate()にデータを渡します。この関数はデータ内のオプションを削除・処理し、残りの文字列をキーのペイロードとしてアタッチします。

アップコールハンドラプログラムは、抽出した結果から取得したすべてのレコードのうちで最も短いTTLを持つキーの有効期限を設定する必要があります。これにより、キーが保持するデータが期限切れしたときに、キーは破棄され再作成されます。

dns_query()は、キーに関連付けられた値のコピーを返します。エラーが発生した場合はエラーを返します。

See <ファイル：Key Request Service（キーリクエストサービス）> request-key関数についてさらに詳しい情報があります。

デバッグ¶

デバッグメッセージは、次のファイルに1を書き込むことで動的に有効にすることができます:

/sys/module/dnsresolver/parameters/debug
