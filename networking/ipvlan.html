IPVLANドライバーガイド¶

初期リリース:

Mahesh Bandewar <maheshb AT google.com>

1. はじめに:¶

これはmacvlanドライバと概念的に非常に似ていますが、slave間のmuxing/demuxingにL3を用いるという1つの主要な違いがあります。この性質により、マスターデバイスがslaveデバイスとL2を共有します。私はこのドライバを開発中にネットワーク名前空間と併用しており、それ以外の使用ケースがあるかは不明です。

2. ビルドとインストール:¶

ドライバをビルドするには、CONFIG_IPVLANの設定項目を選択してください。ドライバはカーネルに組み込む形で(CONFIG_IPVLAN=y)、またはモジュールとして(CONFIG_IPVLAN=m)ビルドできます。

3. 設定:¶

このドライバにはモジュールパラメータはなく、IProute2/ipユーティリティを使用して設定できます。

ip link add link <master> name <slave> type ipvlan [ mode MODE ] [ FLAGS ]
   where
     MODE: l3 (default) | l3s | l2
     FLAGS: bridge (default) | private | vepa

e.g.

  1. 以下のコマンドでeth0をマスターデバイスとしてL3ブリッジモードでIPvlanリンクを作成します:

    bash# ip link add link eth0 name ipvl0 type ipvlan

  2. このコマンドはL2ブリッジモードでIPvlanリンクを作成します:

    bash# ip link add link eth0 name ipvl0 type ipvlan mode l2 bridge

  3. このコマンドはL2プライベートモードでIPvlanデバイスを作成します:

    bash# ip link add link eth0 name ipvlan type ipvlan mode l2 private

  4. このコマンドはL2VEPAモードでIPvlanデバイスを作成します:

    bash# ip link add link eth0 name ipvlan type ipvlan mode l2 vepa

4. 操作モード:¶

IPvlanはL2とL3の2つの運用モードを持っています。あるマスターデバイスに対しては、どちらか一方のモードを選択し、そのマスターデバイスのすべてのslaveは同じ（選択された）モードで動作します。RXモードはほぼ同じですが、L3モードではslaveがマルチキャスト/ブロードキャストトラフィックを受信しません。L3モードはより制限的で、ルーティングは他の（ほぼ）デフォルト名前空間から制御されます。

4.1 L2モード:¶

このモードではTX処理はslaveデバイスに接続されたスタックインスタンスで行われ、パケットはマスターデバイスにスイッチされキューイングされて送信されます。このモードではslaveがマルチキャストおよびブロードキャスト（必要に応じて）をRX/TXします。

4.2 L3モード:¶

このモードではTX処理はslaveデバイスに接続されたスタックインスタンスでL3まで行われ、パケットはマスターデバイスのスタックインスタンスにスイッチされ、L2処理とルーティングが行われます。このモードではslaveがマルチキャスト/ブロードキャストトラフィックを受信したり送信したりしません。

4.3 L3Sモード:¶

これはL3モードと非常に似ていますが、iptables（conn-tracking）がこのモードで動作します。したがってL3-対称（L3s）です。これはややパフォーマンスが低下しますが、plain-L3モードではなくこのモードを選択しているのはconn-trackingが動作するためです。

5. モードフラグ:¶

現在、次のモードフラグが利用可能です

5.1 ブリッジ:¶

これはデフォルトのオプションです。このモードでIPvlanポートを構成する場合は、ユーザーはコマンドラインにこのオプションを追加するか、何も指定しないかを選択できます。これは、スレーブがマスターデバイスを通じて通信する以外にも、スレーブ同士で通信できる伝統的なモードです。

5.2 プライベート:¶

このオプションをコマンドラインに追加すると、ポートがプライベートモードになります。つまり、ポートはスレーブ間でのクロス通信を許可しません。

5.3 VEPA:¶

このオプションをコマンドラインに追加すると、ポートがVEPAモードになります。つまり、ポートは802.1Qbgで説明されているように、外部エンティティにスイッチング機能をオフロードします。注意: IPvlanのVEPAモードには制限があります。IPvlanはマスターデバイスのMACアドレスを使用するため、このモードで隣接するネイバー宛てのパケットは、送信元と宛先のMACアドレスが同じになります。これにより、スイッチ/ルーターがリダイレクトメッセージを送信します。

6. 何を選べばいいか（macvlan vs. ipvlan）¶

これらの2つのデバイスは多くの点で非常に似ていますが、特定のユースケースがどのデバイスを選ぶかを決定する場合があります。以下のいずれかの状況があなたのユースケースを定義する場合、ipvlanを使用することを検討してください。

  1. 外部スイッチ/ルーターに接続されたLinuxホストで、ポートごとに1つのMACアドレスのみを許可するポリシーが設定されています。

  2. マスターデバイス上で作成される仮想デバイスの数がMAC容量を超え、NICを混入モードにし、パフォーマンス低下が懸念される場合。

  3. スレーブデバイスが不正/信頼できないネットワークネームスペースに配置される場合、スレーブのL2層が変更/悪用される可能性があるため。

6. 例: 設定¶

+=============================================================+
|  Host: host1                                                |
|                                                             |
|   +----------------------+      +----------------------+    |
|   |   NS:ns0             |      |  NS:ns1              |    |
|   |                      |      |                      |    |
|   |                      |      |                      |    |
|   |        ipvl0         |      |         ipvl1        |    |
|   +----------#-----------+      +-----------#----------+    |
|              #                              #               |
|              ################################               |
|                              # eth0                         |
+==============================#==============================+

  1. 2つのネットワークネームスペースを設定 - ns0、ns1:

    ip netns add ns0
ip netns add ns1

  2. eth0（マスターデバイス）に2つのipvlanスレーブを設定:

    ip link add link eth0 ipvl0 type ipvlan mode l2
ip link add link eth0 ipvl1 type ipvlan mode l2

  3. スレーブをそれぞれのネットワークネームスペースに割り当て:

    ip link set dev ipvl0 netns ns0
ip link set dev ipvl1 netns ns1

  4. スレーブデバイスを構成するために、名前空間（ns0またはns1）に切り替えます

    • ns0の場合:

      (1) ip netns exec ns0 bash
(2) ip link set dev ipvl0 up
(3) ip link set dev lo up
(4) ip -4 addr add 127.0.0.1 dev lo
(5) ip -4 addr add $IPADDR dev ipvl0
(6) ip -4 route add default via $ROUTER dev ipvl0

    • ns1の場合:

      (1) ip netns exec ns1 bash
(2) ip link set dev ipvl1 up
(3) ip link set dev lo up
(4) ip -4 addr add 127.0.0.1 dev lo
(5) ip -4 addr add $IPADDR dev ipvl1
(6) ip -4 route add default via $ROUTER dev ipvl1
