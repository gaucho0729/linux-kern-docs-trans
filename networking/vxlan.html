仮想拡張ローカルエリアネットワーキングドキュメンテーション¶

VXLANプロトコルは、IEEE 802.1qにおける VLAN ID（4096）の制限を解決するためのトンネリングプロトコルとして設計されています。VXLANでは識別子のサイズが24ビット（16777216）に拡張されます。

VXLANはIETF RFC 7348で記述されており、複数のベンダーによって実装されています。このプロトコルはUDPを介して動作し、単一の宛先ポートを使用します。このドキュメントではLinuxカーネルのトンネルデバイスについて説明しており、Openvswitch用のVXLAN実装も別途存在します。

一般的なトンネルとは異なり、VXLANは1対Nのネットワークであり、単なるポイントツーポイントではありません。VXLANデバイスは、学習ブリッジと同様の方法で動的に他端点のIPアドレスを学習するか、静的に設定された転送エントリを使用して処理します。

VXLANの管理はGREとVLANの2つの近隣プロトコルと同様に行われます。VXLANの設定には、VXLANが最初にアップストリームにマージされたカーネルリリースに一致するiproute2のバージョンが必要です。

  1. vxlanデバイスの作成:

    # ip link add vxlan0 type vxlan id 42 group 239.1.1.1 dev eth1 dstport 4789

これは新しいデバイスvxlan0を作成します。このデバイスはeth1経由で multicast グループ 239.1.1.1 を使用し、転送テーブルにエントリがないトラフィックを処理します。宛先ポート番号はIANAが割り当てた4789に設定されます。LinuxのVXLAN実装はIANAが標準宛先ポート番号を選択する前から存在しており、後方互換性を維持するためにLinuxが選択した値をデフォルトで使用します。

  1. vxlanデバイスの削除:

    # ip link delete vxlan0

  2. vxlan情報の表示:

    # ip -d link show vxlan0

新しいブリッジコマンドを使用することで、vxlan転送テーブルの作成、削除、表示が可能です。

  1. 転送テーブルエントリの作成:

    # bridge fdb add to 00:17:42:8a:b4:05 dst 192.19.0.2 dev vxlan0

  2. 転送テーブルエントリの削除:

    # bridge fdb delete 00:17:42:8a:b4:05 dev vxlan0

  3. 転送テーブルの表示:

    # bridge fdb show dev vxlan0

以下のNIC機能は、UDPトンネル関連のオフロード（最も一般的にはVXLAN機能ですが、特定のエンカプスレーションプロトコルのサポートはNIC固有です）を示唆する可能性があります：

  • tx-udp_tnl-segmentation

  • tx-udp_tnl-csum-segmentation

    UDPエンカプスレーションフレームのTCPセグメンテーションオフロードを実行できる機能

  • rx-udp_tunnel-port-offload

    UDPエンカプスレーションフレームの受信側解析を実行し、NICがプロトコル認識型オフロード（例：内側フレームのチェックサム検証オフロード）を実行できるようにします（プロトコル無関係なオフロードをサポートしないNICには必要）

サポートしているデバイスについては rx-udp_tunnel-port-offload 現在のオフロードポートの一覧を確認するには ethtool:

$ ethtool --show-tunnels eth0
Tunnel information for eth0:
  UDP port table 0:
    Size: 4
    Types: vxlan
    No entries
  UDP port table 1:
    Size: 4
    Types: geneve, vxlan-gpe
    Entries (1):
        port 1230, vxlan-gpe
