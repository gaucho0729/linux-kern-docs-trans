NETIFメッセージレベル¶

ネットワークインターフェースメッセージレベル設定の設計。

履歴¶

ネットワークインターフェースのデバッグメッセージインターフェースの設計は、後方互換性を重視した設計と制約によって導かれてきました。現在の実装を理解し、古いドライバのソースコードと関連付けるために、歴史と進化を理解することが役立ちます。

Linuxの開始から、各ネットワークデバイスドライバには、デバッグメッセージレベルを制御するローカルの整数変数がありました。メッセージレベルは0から7までで、詳細度が単調に増加しました。

メッセージレベルは3を超えて明確に定義されていませんでしたが、常に指定されたレベルの±1以内で実装されていました。ドライバは成熟するにつれて、より詳細なレベルのメッセージを省略する傾向がありました。

  • 0 最小限のメッセージ、致命的なエラーのみの情報。

  • 1 標準的なメッセージ、初期化ステータス。実行時メッセージはなし

  • 2 特殊なメディア選択メッセージ、一般的にタイマードライバ。

  • 3 インターフェースの開始と停止、通常のステータスメッセージを含む

  • 4 TxとRxフレームエラーのメッセージ、異常なドライバ動作

  • 5 Txパケットキュー情報、割込みイベント。

  • 6 完了したTxパケットと受信したRxパケットのステータス

  • 7 TxとRxパケットの初期内容

初期にはこのメッセージレベル変数は各ドライバで一意の名前が使われていました（例：「lance_debug」）ので、カーネルシンボリックデバッガーが場所を特定し、設定を変更できるようにしました。カーネルモジュールが一般的になった後、変数は「debug」として一貫して名前を変えられ、モジュールパラメータとして設定可能になりました。

このアプローチはうまく機能しましたが、常に追加機能の需要がありました。年々、以下の機能が追加されてきました。

  • ioctl()呼び出しでレベルを変更する。

  • ドライバごとの設定ではなく、インターフェースごとのメッセージレベル設定。

  • 出力されるメッセージの種類に対するより選択的な制御。

netif_msgの推奨は、わずかな複雑度とコードサイズの増加でこれらの機能を追加します。

以下の点を推奨します。

  • ドライバごとの整数変数「debug」をモジュールパラメータとして保持し、デフォルトレベルを「1」に設定します。

  • インターフェースごとのプライベート変数「msg_enable」を追加します。この変数はレベルではなくビットマップであり、初期化は以下の通りです：

    1 << debug

    より正確には：

    debug < 0 ? 0 : 1 << min(sizeof(int)-1, debug)

    メッセージは以下のようになります：

    if (debug > 1)
     printk(MSG_DEBUG "%s: ...

    に変更してください：

    if (np->msg_enable & NETIF_MSG_LINK)
     printk(MSG_DEBUG "%s: ...
