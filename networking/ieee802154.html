IEEE 802.15.4開発者ガイド¶

はじめに¶

IEEE 802.15.4 ワークグループは、中間層（MAC）と物理層（PHY）の標準化に焦点を当てています。上位層には主に2つの選択肢があります:

  • ZigBee - ZigBee Alliance が提供する特許技術のプロトコル

  • 6LoWPAN - 低速の個人エリアネットワーク上でのIPv6ネットワーク

Linux-wpan の目標は、IEEE 802.15.4 および 6LoWPAN プロトコルの完全な実装を提供することです。IEEE 802.15.4 は、低速無線個人エリアネットワークを構築するためのプロトコルスタックです。

このスタックは3つの主要な部分から構成されています:

  • IEEE 802.15.4 層; ここでは、Berkeley ソケット API を使用し、一般的なLinuxネットワークスタックを用いてIEEE 802.15.4 データメッセージを転送し、netlink を通じた特別なプロトコルで設定/管理を行います

  • MAC - 共有チャネルへのアクセスを提供し、信頼性の高いデータ配信を実現します

  • PHY - デバイスドライバを表します

ソケットAPI¶

int sd = socket(PF_IEEE802154, SOCK_DGRAM, 0);

アドレスファミリ、ソケットアドレスなどは、include/net/af_ieee802154.h ヘッダーやユーザー空間パッケージ内の特別なヘッダーで定義されています（詳しくは https://linux-wpan.org/wpan-tools.html または git ツリーの https://github.com/linux-wpan/wpan-tools).

6LoWPAN Linux 実装¶

IEEE 802.15.4 標準は、MTU が127バイトと定義されており、セキュリティが有効な場合、無線リンクでのリンクスループットが250kbps以下の環境では、実際のMACペイロードは約80オクテットになります。6LoWPAN アダプテーションフォーマット[RFC4944]は、このような制約されたリンクを介してIPv6データグラムを転送するための仕様で、制限された帯域幅、メモリ、またはエネルギー資源を考慮しています。[RFC4944]は、無線センサネットワークなどのアプリケーションで予想されるリソース制約を考慮し、メッシュアドレスングヘッダーを導入してサブIPフォワーディングをサポートし、IPv6の最小MTU要件[RFC2460]をサポートするフラグメンテーションヘッダーを定義し、IPv6データグラムのステートレスヘッダーコンプレッション（LOWPAN_HC1 および LOWPAN_HC2）を定義して、IPv6およびUDPヘッダーを数バイトにまで圧縮します。

2011年9月に標準の更新[RFC6282]が公開され、HC1およびHC2の圧縮を非推奨にし、IPHC符号化フォーマットを定義しました。このLinux実装ではIPHC符号化フォーマットが使用されています。

6lowpanに関連するすべてのコードは、net/6lowpan/* および net/ieee802154/6lowpan/* ファイルにあります

6LoWPANインターフェースを設定するには、1. IEEE802.15.4インターフェースを追加し、チャネルとPAN IDを設定する；2. 6lowpanインターフェースをコマンドで追加する（例: # ip link add link wpan0 name lowpan0 type lowpan）；3. 'lowpan0'インターフェースを有効にする

ドライバ¶

Wi-Fiと同様に、IEEE 802.15.4を実装するデバイスにはいくつかの種類があります。1) 「HardMAC」。MACレイヤーはデバイス自体で実装され、デバイスは管理（例: MLME）およびデータAPIをエクスポートします。2) 「SoftMAC」または単にラジオ。このようなデバイスは、自動CRC計算や比較、自動ACK処理、アドレスマッチングなど、いくつかの種類のアクセラレーションを持つ無線トランシーバーです。

このようなデバイスは、Linuxカーネルに接続するための異なるアプローチが必要です。

HardMAC¶

include/net/ieee802154_netdev.hヘッダーファイルを参照してください。Linux net_deviceを実装し、.type = ARPHRD_IEEE802154を設定する必要があります。データはソケットファミリーコードを介してplain sk_buffsでやり取りされます。skb受信時にskb->cbには、struct ieee802154_mac_cbで説明されている追加情報が含まれている必要があります。パケット送信時にskb->cbはデバイスのheader_ops->create関数に追加データを提供します。注意点として、このデータは後で（ソケットコードがskbをqdiscにサブミットする際）上書きされる可能性があるため、後でこのcbから情報を取得する必要がある場合は、自分でskb->dataに情報を保存する必要があります。

MLMEインターフェースを接続するには、net_deviceのml_privフィールドにstruct ieee802154_mlme_opsインスタンスへのポインタを設定する必要があります。assoc_req、assoc_resp、disassoc_req、start_req、scan_reqはオプションです。他のすべてのフィールドは必須です。

SoftMAC¶

MACはIEEE 802.15.4 Linuxスタックの中間レイヤーです。現在はドライバの登録とスレーブインターフェースの管理インターフェースを提供しています。

注意: 現在はモニターデバイスタイプのみがサポートされています。これはネットワークスナイファー（例: WireShark）用のIEEE 802.15.4スタックインターフェースです。

このレイヤーは近日中に拡張される予定です。

include/net/mac802154.hヘッダーファイルとdrivers/net/ieee802154/ディレクトリ内のいくつかのドライバを参照してください。

フェイクドライバ¶

さらに、SoftMAC（fakelb - IEEE 802.15.4ループバックドライバ）インターフェースをシミュレートするドライバが利用可能です。このオプションは、実際のハードウェアを使用することなくスタックのテストとデバッグを可能にします。

デバイスドライバAPI¶

include/net/mac802154.hは以下の関数を定義しています:

struct ieee802154_dev *ieee802154_alloc_device(size_t priv_size, struct ieee802154_ops *ops)¶

IEEE 802.15.4互換デバイスの割当。

void ieee802154_free_device(struct ieee802154_dev *dev)¶

割当されたデバイスの解放。

int ieee802154_register_device(struct ieee802154_dev *dev)¶

PHYをシステムに登録します。

void ieee802154_unregister_device(struct ieee802154_dev *dev)¶

登録されたPHYの解放。

void ieee802154_rx_irqsafe(struct ieee802154_hw *hw, struct sk_buff *skb, u8 lqi)¶

ハードウェアデバイスから受信したskbにRFリンク品質インジケーター（LQI）が含まれていることを802.15.4モジュールに通知します。

void ieee802154_xmit_complete(struct ieee802154_hw *hw, struct sk_buff *skb, bool ifs_handling)¶

802.15.4モジュールに、skb内のフレームがハードウェアデバイスを通じて送信されているか、または送信される予定であることを通知する

IEEE 802.15.4操作構造体において、以下のコールバックを少なくとも実装する必要があります:

struct ieee802154_ops {
     ...
     int     (*start)(struct ieee802154_hw *hw);
     void    (*stop)(struct ieee802154_hw *hw);
     ...
     int     (*xmit_async)(struct ieee802154_hw *hw, struct sk_buff *skb);
     int     (*ed)(struct ieee802154_hw *hw, u8 *level);
     int     (*set_channel)(struct ieee802154_hw *hw, u8 page, u8 channel);
     ...
};
int start(struct ieee802154_hw *hw)¶

ハードウェアデバイスの初期化のために802.15.4モジュールが呼び出すハンドラ

void 停止(struct ieee802154_hw *hw)¶

ハードウェアデバイスのクリーンアップのために802.15.4モジュールが呼び出すハンドラ

int xmit_async(struct ieee802154_hw *hw, struct sk_buff *skb)¶

skb内のフレームがハードウェアデバイスを通じて送信されるたびに802.15.4モジュールが呼び出すハンドラ

int ed(struct ieee802154_hw *hw, u8 *レベル)¶

ハードウェアデバイスからのエネルギー検出のために802.15.4モジュールが呼び出すハンドラ

int set_channel(struct ieee802154_hw *hw, u8 page, u8 channel)¶

ハードウェアデバイスの特定のチャネルでリスニングするための無線機を設定する

さらに、IEEE 802.15.4デバイス操作構造体を埋める必要があります。
