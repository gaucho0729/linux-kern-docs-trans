XFRMデバイス - IPsec計算のオフロード¶

Shannon Nelson <shannon.nelson@oracle.com>

概要¶

IPsecはネットワークトラフィックのセキュリティ確保に有用ですが、計算コストが高いため、10Gbpsのリンクでもトラフィックやリンク設定によって1Gbps以下になることがあります。幸いなことに、NICがハードウェアベースのIPsecオフロードを提供するものがあり、これによりスループットが大幅に向上し、CPUの使用率が低下します。XFRMデバイスインターフェースは、NICドライバーがネットワークスタックにハードウェアオフロードへのアクセスを提供できるようにします。

オフロードへのユーザーランドアクセスは、libreswanやKAME/raccoonなどのシステムを通じて行われますが、iproute2の‘ip xfrm’コマンドセットは実験に役立ちます。例としてコマンドは以下のようになります：

ip x s add proto esp dst 14.0.0.70 src 14.0.0.52 spi 0x07 mode transport \
   reqid 0x07 replay-window 32 \
   aead 'rfc4106(gcm(aes))' 0x44434241343332312423222114131211f4f3f2f1 128 \
   sel src 14.0.0.52/24 dst 14.0.0.70/24 proto tcp \
   offload dev eth4 dir in

はい、それは醜いですが、シェルスクリプトと/or libreswanの役割です。

実装するコールバック¶

/* from include/linux/netdevice.h */
struct xfrmdev_ops {
      int     (*xdo_dev_state_add) (struct xfrm_state *x);
      void    (*xdo_dev_state_delete) (struct xfrm_state *x);
      void    (*xdo_dev_state_free) (struct xfrm_state *x);
      bool    (*xdo_dev_offload_ok) (struct sk_buff *skb,
                                     struct xfrm_state *x);
      void    (*xdo_dev_state_advance_esn) (struct xfrm_state *x);
};

IPsecオフロードを提供するNICドライバーは、ネットワークスタックのXFRMサブシステムにオフロードを提供するためにこれらのコールバックを実装する必要があります。さらに、NETIF_F_HW_ESPとNETIF_F_HW_ESP_TX_CSUMという機能フラグがオフロードの可用性を示します。

フロー¶

プローブタイムとcall to register_netdev()以前に、ドライバーはローカルデータ構造とXFRMコールバックを設定し、機能フラグを設定する必要があります。XFRMコードのリスナーがNETDEV_REGISTERでセットアップを完了します。

adapter->netdev->xfrmdev_ops = &ixgbe_xfrmdev_ops;
adapter->netdev->features |= NETIF_F_HW_ESP;
adapter->netdev->hw_enc_features |= NETIF_F_HW_ESP;

新しいSAが「offload」機能のリクエストとともに設定されると、ドライバーのxdo_dev_state_add()がオフロードされる新しいSAと、RxまたはTxの指示を提供されます。ドライバーは

  • オフロードにサポートされているアルゴリズムを確認する必要があります

  • SA情報（鍵、ソルト、ターゲットIP、プロトコルなど）を保存する

  • SAのハードウェアオフロードを有効にする

  • ステータス値を返す：

    0

    成功

    -EOPNETSUPP

    オフロードがサポートされていない、SW IPsecを使用してください

    その他

    リクエストを失敗させる

ドライバーはSAにoffload_handleを設定することもでき、これは高速パスオフロードリクエストにコンテキストを伝達するために使用される不透明なvoidポインタです：

xs->xso.offload_handle = context;

ネットワークスタックがオフロード設定済みのSAでIPsecパケットを準備する際には、まずskbと意図したオフロード状態を渡してxdo_dev_offload_ok()を呼び出し、ドライバーにオフロードが処理可能かどうかを尋ねます。これにより、パケット情報（IPv4またはIPv6、IPv4オプションなしなど）を確認し、オフロードがサポート可能かどうかをtrueまたはfalseで返します。

送信準備ができたら、ドライバーは送信パケットのオフロード情報（不透明コンテキストを含む）を確認し、パケット送信を適切に設定する必要があります：

xs = xfrm_input_state(skb);
context = xs->xso.offload_handle;
set up HW for send

スタックはすでにパケットデータに適切なIPsecヘッダーを挿入済みです。オフロードは暗号化を行い、ヘッダー値を修正するだけで十分です。

パケットが受信され、HWが復号をオフロードしたことを示した場合、ドライバーはそのデコードされたSAへの参照をパケットのskbに追加する必要があります。この時点でデータは復号済みですが、IPsecヘッダーはまだパケットデータに含まれており、後続のスタック処理でxfrm_input()で削除されます。

Rx skbに使用されたSAを検索し、保持する:

get spi, protocol, and destination IP from packet headers
xs = find xs from (spi, protocol, dest_IP)
xfrm_state_hold(xs);

skbに状態情報を保存する:

sp = secpath_set(skb);
if (!sp) return;
sp->xvec[sp->len++] = xs;
sp->olen++;

オフロードの成功および/またはエラー状態を示す:

xo = xfrm_offload(skb);
xo->flags = CRYPTO_DONE;
xo->status = crypto_status;

通常通りnapi_gro_receive()にパケットを渡す

ESNモードでは、xfrm_replay_advance_esn()からxdo_dev_state_advance_esn()が呼び出されます。ドライバーはパケットのシーケンス番号を確認し、必要に応じてHW ESNステートマシンを更新します。

SAがユーザーによって削除された場合、ドライバーはxdo_dev_state_delete()を呼び出してオフロードを無効化します。その後、すべての参照カウントが解除された後、ガベージコレクションルーチンからxdo_dev_state_free()が呼び出され、オフロード状態の残りのリソースがクリアされます。ドライバーがこれらのリソースをどのように使用するかは、特定のハードウェアの要件に依存します。

netdevがDOWN状態に設定されると、XFRMスタックのnetdevリスナーが残っているオフロードされた状態に対してxdo_dev_state_delete()とxdo_dev_state_free()を呼び出します。
