ストリームパーサー (strparser)¶

はじめに¶

ストリームパーサー (strparser) は、データストリーム上でのアプリケーション層プロトコルのメッセージを解析するユーティリティです。ストリームパーサーは、カーネル内の上位レイヤーと連携して、アプリケーション層メッセージのカーネルサポートを提供します。たとえば、カーネルコネクション多重化器 (KCM) は、BPF プログラムを使用してメッセージを解析するためにストリームパーサーを使用します。

strparser は、受信コールバックモードまたは一般モードのいずれかで動作します。

受信コールバックモードでは、TCP ソケットの data_ready コールバックから strparser が呼び出されます。メッセージはソケットで受信されるたびに解析され、配信されます。

一般モードでは、外部からのソースから skbs のシーケンスが strparser に供給されます。シーケンスが処理されるにつれてメッセージが解析され配信されます。このモードにより、strparser は任意のデータストリームに適用できます。

インターフェース¶

API にはコンテキスト構造体、コールバック関数のセット、ユーティリティ関数、および受信コールバックモード用の data_ready 関数が含まれます。コールバックには、解析を実行する parse_msg 関数（例: KCM の場合の BPF 解析）と、完全なメッセージが完了したときに呼ばれる rcv_msg 関数が含まれます。

関数¶

strp_init(struct strparser *strp, struct sock *sk,
        const struct strp_callbacks *cb)

ストリームパーサーを初期化するために呼び出されます。strp は上位レイヤーによって割り当てられた strparser 型の構造体で、sk は受信コールバックモードで使用する TCP ソケットを示します（一般モードでは NULL に設定されます）。コールバックはストリームパーサーによって呼び出されます（以下にコールバックの一覧が示されています）。

void strp_pause(struct strparser *strp)

ストリームパーサーを一時停止します。メッセージ解析は停止され、上位レイヤーに新しいメッセージが配信されません。

void strp_unpause(struct strparser *strp)

一時停止されたストリームパーサーを再開します。

void strp_stop(struct strparser *strp);

strp_stop はストリームパーサーの操作を完全に停止するために呼び出されます。これはストリームパーサーがエラーを検出する内部処理で呼び出されるほか、上位レイヤーから解析操作を停止するために呼び出されます。

void strp_done(struct strparser *strp);

strp_done はストリームパーサーインスタンスが保持するリソースを解放するために呼び出されます。これはストリームパーサーが停止した後で必ず呼び出さなければなりません。

int strp_process(struct strparser *strp, struct sk_buff *orig_skb,
                 unsigned int orig_offset, size_t orig_len,
                 size_t max_msg_size, long timeo)

一般モードでストリームパーサーが sk_buff を解析するために strp_process が呼び出されます。処理されたバイト数または負のエラーコードが返されます。注意点として、strp_process は sk_buff を消費しません。max_msg_size はストリームパーサーが解析する最大サイズで、timeo はメッセージの完了までのタイムアウトです。

void strp_data_ready(struct strparser *strp);

下位ソケットでstrparserが処理できるデータが準備された場合、上位レイヤーはstrp_tcp_data_readyを呼び出します。これは、ソケットに設定されたdata_readyコールバックから呼び出されるべきです。注意点として、最大メッセージサイズは受信ソケットバッファの制限であり、メッセージタイムアウトはソケットの受信タイムアウトです。

void strp_check_rcv(struct strparser *strp);

strp_check_rcvはソケット上の新しいメッセージを確認するために呼び出されます。これは通常、ストリームパーサーインスタンスの初期化時やstrp_unpauseの後に呼び出されます。

コールバック¶

コールバックは合計6つあります:

int (*parse_msg)(struct strparser *strp, struct sk_buff *skb);

parse_msgはストリーム内の次のメッセージの長さを決定するために呼び出されます。上位レイヤーはこの関数を実装する必要があります。これはsk_buffが次のアプリケーションレイヤーのメッセージのヘッダーを含んでいると解析する必要があります。

入力sk_buffのskb->cbはstruct strp_msgです。parse_msgではoffsetフィールドのみが重要で、メッセージがskb内で開始するオフセットを示します。

この関数の返却値は:

>0

正しく解析されたメッセージの長さを示します

0

メッセージを解析するためにさらにデータを受信する必要があります

-ESTRPIPE

現在のメッセージはカーネルによって処理されず、ユーザー空間にソケットの制御を戻します。ユーザー空間はメッセージを直接読み取る必要があります

他の< 0

解析エラー、同期が失われたと仮定してユーザー空間に制御を戻し、ストリームが復旧不可能であるためアプリケーションがTCPソケットを閉じる必要があります

エラーが返却された場合（返却値が0未満）でパーサーが受信コールバックモードにある場合、TCPソケットにエラーを設定し、それを起動します。parse_msgが-ESTRPIPEを返却し、ストリームパーサーが現在のメッセージのためにいくつかのバイトを読み取っていた場合、関連付けられたソケットに設定されるエラーはENODATAです。その場合、ストリームは復旧不可能です。

void (*lock)(struct strparser *strp)

ロックコールバックは、strparserが非同期操作（タイムアウトの処理など）を実行しているときにstrp構造体をロックするために呼び出されます。受信コールバックモードでは、関連するソケットのlock_sockをデフォルト関数として使用します。一般モードではコールバックを適切に設定する必要があります。

void (*unlock)(struct strparser *strp)

アンロックコールバックは、ロックコールバックで取得したロックを解放するために呼び出されます。受信コールバックモードでは、関連するソケットのrelease_sockをデフォルト関数として使用します。一般モードではコールバックを適切に設定する必要があります。

void (*rcv_msg)(struct strparser *strp, struct sk_buff *skb);

rcv_msgは完全なメッセージが受信されキューイングされたときに呼び出されます。呼び出し元はsk_buffを消費する必要があります。strp_pauseを呼び出して、rcv_msg内でさらにメッセージの受信を防ぐことができます（strp_pauseを参照）。このコールバックは必ず設定する必要があります。

入力skbのskb->cbはstruct strp_msgです。この構造体にはoffsetとfull_lenという2つのフィールドがあります。offsetはskb内でのメッセージの開始位置を、full_lenはメッセージの長さを表します。skb->len - offsetはfull_lenより大きい場合があります。これはstrparserがskbをトリムしないからです。

   int (*read_sock_done)(struct strparser *strp, int err);

read_sock_done is called when the stream parser is done reading
the TCP socket in receive callback mode. The stream parser may
read multiple messages in a loop and this function allows cleanup
to occur when exiting the loop. If the callback is not set (NULL
in strp_init) a default function is used.

::

   void (*abort_parser)(struct strparser *strp, int err);

This function is called when stream parser encounters an error
in parsing. The default function stops the stream parser and
sets the error in the socket if the parser is in receive callback
mode. The default function can be changed by setting the callback
to non-NULL in strp_init.

統計¶

各ストリームパーサーインスタンスにはさまざまなカウンタが保持されています。これらはstrp_stats構造体に格納されています。strp_aggr_statsは複数のストリームパーサーインスタンスの統計を累積するための便利な構造体です。save_strp_statsとaggregate_strp_statsは統計を保存および集約するための補助関数です。

メッセージのアセンブリ制限¶

ストリームパーサーは、メッセージの組み立てに消費されるリソースを制限するメカニズムを提供します。

新しいメッセージの組み立てが始まるときにタイマが設定されます。受信コールバックモードでは、関連するTCPソケットのrcvtimeからメッセージタイムアウトが取得されます。一般モードでは、strp_processにタイムアウトを引数として渡します。タイマが組み立て完了前に起動した場合、ストリームパーサーは中止され、受信コールバックモードではTCPソケットにETIMEDOUTエラーが設定されます。

受信コールバックモードでは、メッセージ長は関連するTCPソケットの受信バッファサイズに制限されます。parse_msgが返す長さがソケットバッファサイズを超える場合、ストリームパーサーはEMSGSIZEエラーをTCPソケットに設定して中止されます。注意として、ストリームパーサーを持つソケットの最大受信skbuffサイズは、TCPソケットのsk_rcvbufの2倍になります。

一般モードでは、メッセージ長制限はstrp_processへの引数として渡されます。
