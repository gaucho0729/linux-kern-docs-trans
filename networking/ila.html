識別子ロケーターアドレスング（ILA）¶

はじめに¶

Identifier-locator addressing (ILA) は IPv6 で使用される技術で、ネットワークノードの位置とアイデンティティを区別します。アドレスの一部はノードの変更不可能なアイデンティティを、もう一方はノードの動的な位置を示します。Identifier-locator addressing はネットワーク仮想化のオーバーレイネットワークの効率的な実装や、移動性などのユースケースの解決策として利用できます。

ILA は、カプセル化なしでオーバーレイネットワークを実装するための手段と見なせます。これは、パケットがネットワークを通過する際に宛先アドレスに対してネットワークアドレス変換（NAT）を実行することで達成されます。ネットワークに対しては、ILA 変換されたパケットは他の IPv6 パケットと変わりません。たとえば、トランスポートプロトコルが TCP の場合、ILA 変換されたパケットは単なる TCP/IPv6 パケットのように見えます。この利点は、ネットワークに対して ILA が透過的であるため、ECMP、RSS、GRO、GSO などのネットワーク最適化が自動的に動作することです。

ILA プロトコルは Internet-Draft draft-herbert-intarea-ila で記述されています。

ILA 用語¶

  • 識別子

    ネットワーク内のノードをその位置とは関係なく識別するための数値。ILA 識別子は 64 ビットの値です。

  • ロケータ

    物理ホストにルーティングされるネットワークプレフィックス。ロケータはアドレステッドノードのトポロジカルな位置を提供します。ILA ロケータは 64 ビットのプレフィックスです。

  • ILA マッピング

    ILA 識別子をロケータ（またはロケータとメタデータ）にマッピングするものです。ILA ドメインは、ドメイン内のすべての宛先に対するマッピングを含むデータベースを保持します。

  • SIR アドレス

    SIR プレフィックス（上位 64 ビット）と識別子（下位 64 ビット）からなる IPv6 アドレス。SIR アドレスはアプリケーションに表示され、アプリケーションがノードの位置とは関係なくアドレスティングする手段を提供します。

  • ILA アドレス

    ロケータ（上位 64 ビット）と識別子（下位 64 ビット）からなる IPv6 アドレス。ILA アドレスはアプリケーションには表示されません。

  • ILA ホスト

    送信または受信時に ILA 変換を実行できるエンドホストです。

  • ILA ルーター

    ILA 変換と変換されたパケットの転送を実行するネットワークノードです。

  • ILA フォワーディングキャッシュ

    マッピングの作業セットキャッシュのみを保持する ILA ルーターの一種です。

  • ILA ノード

    ILA 変換を実行できるネットワークノードです。これは ILA ルーター、ILA フォワーディングキャッシュ、または ILA ホストのいずれかです。

操作¶

ILA の基本的な操作は 2 つあります：

  • SIRアドレスをILAアドレスに変換します。これはILAオーバレイへのイングレス時に実行されます。

  • ILAアドレスをSIRアドレスに変換します。これはILAオーバレイからのエグレス時に実行されます。

ILAはネットワーク内のエンドホストまたは中間デバイスに展開可能であり、これらはそれぞれ「ILAホスト」と「ILAルーター」によって提供されます。これらの2つの展開ポイントの設定とデータパスは多少異なります。

以下の図は、ILAを介したパケットの流れを示すとともに、ILAホストとルーターも示しています。

 +--------+                                                +--------+
 | Host A +-+                                         +--->| Host B |
 |        | |              (2) ILA                   (')   |        |
 +--------+ |            ...addressed....           (   )  +--------+
            V  +---+--+  .  packet      .  +---+--+  (_)
(1) SIR     |  | ILA  |----->-------->---->| ILA  |   |   (3) SIR
 addressed  +->|router|  .              .  |router|->-+    addressed
 packet        +---+--+  .     IPv6     .  +---+--+        packet
                /        .    Network   .
               /         .              .   +--+-++--------+
 +--------+   /          .              .   |ILA ||  Host  |
 |  Host  +--+           .              .- -|host||        |
 |        |              .              .   +--+-++--------+
 +--------+              ................

トランスポートチェックサムの処理¶

ILAによってアドレスが変換される場合、変換後のアドレスを擬似ヘッダーに含むエンカプスレーションされたトランスポートチェックサムがワイヤー上では正しく表示されない可能性があります。これはNICのチェックサムオフロードなどの中間デバイスがチェックサムを処理する際に問題となります。この問題に対処するための3つのオプションがあります：

  • no action ワイヤー上でのチェックサムの不正確性を許容します。受信側がチェックサムを検証する前に、

    ILAからSIRアドレスへの変換が行われる必要があります。

  • トランスポートチェックサムの調整

    ILA変換が実行される際、パケットが解析され、トランスポート層のチェックサムが見つかった場合、変換後のアドレスに基づいて正しいチェックサムに調整されます。

  • チェックサムニュートラルマッピング

    アドレスが変換される際、チェックサムがカバーするパケットの他の部分で差異を補正できます。識別子の下位16ビットが使用されます。この方法は好まれますなぜなら、IPヘッダーを超えてパケットを解析する必要がなく、多くの場合調整は事前に計算されマッピングとともに保存できるからです。

チェックサムニュートラル調整は識別子の下位16ビットに影響を与えます。ILAからSIRアドレスへの変換がエグレス時に実行される際、下位ビットは元の値に戻され、識別子が元の送信時のように復元されます。

識別子の種類¶

ILAはさまざまな使用ケースに応じて異なる種類の識別子を定義しています。

定義された種類は以下の通りです：

0: インターフェース識別子

1: ローカルユニーク識別子

2: IPv4アドレス用仮想ネットワーク識別子

3: IPv6ユニキャストアドレス用仮想ネットワーク識別子

4: IPv6マルチキャストアドレス用仮想ネットワーク識別子

5: ローカル外アドレス識別子

現在のカーネルILAの実装では、ローカルユニーク識別子（LUID）のみがサポートされています。LUIDは汎用的な、フォーマットのない64ビットの識別子を提供します。

識別子の形式¶

カーネルのILAは、識別子のフォーマットに「Cビット」と「識別子タイプ」という2つのオプションフィールドをサポートしています。これらのフィールドの有無は構成によって決まります。

識別子タイプが存在する場合、それは識別子の3つの最高位ビットを占めます。可能な値は上記のリストに示されています。

Cビットが存在する場合、これはチェックサムニュートラルマッピングが行われたことを示します。CビットはILAアドレスにのみ設定され、SIRアドレスには設定されません。

最もシンプルなフォーマットでは識別子タイプ、Cビット、チェックサム調整値は存在しないため、識別子は非構造化の64ビット値とみなされます：

+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|                            Identifier                         |
+                                                               +
|                                                               |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+

チェックサムニュートラル調整はneutral-map-autoを設定することで常に存在するように構成できます。この場合、Cビットは存在しませんが、チェックサム調整値は低順位の16ビットに配置されます。識別子は依然として64ビットです：

+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|                            Identifier                         |
|                               +-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|                               |  Checksum-neutral adjustment  |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+

Cビットは、ILAアドレスにチェックサムニュートラルマッピングが適用されたことを明示的に示すために使用できます。フォーマットは以下の通りです：

+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|     |C|                    Identifier                         |
|     +-+                       +-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|                               |  Checksum-neutral adjustment  |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+

識別子タイプフィールドが存在する場合、識別子タイプを示します。存在しない場合は、マッピング構成に基づいてタイプが推論されます。チェックサムニュートラル調整は識別子タイプとともに自動的に使用され、以下の例のように示されています：

+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
| Type|                      Identifier                         |
+-+-+-+                         +-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|                               |  Checksum-neutral adjustment  |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+

識別子タイプとCビットが同時に存在する場合、識別子のフォーマットは以下のようになります：

+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
| Type|C|                    Identifier                         |
+-+-+-+-+                       +-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|                               |  Checksum-neutral adjustment  |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+

設定¶

ILAマッピングの構成には2つの方法があります。1つはLWTルートを使用する方法、もう1つはila_xlat（NFHOOK PREROUTING hookから呼び出されます）です。ila_xlatはILAホストの受信パスで使用することを目的としています。

XDPでILAルーターも実装されています。その説明は本ドキュメントの範囲外です。

ILA LWTルートの使用方法は以下の通りです：

ip route add DEST/128 encap ila LOC csum-mode MODE ident-type TYPE via ADDR

宛先（DEST）はSIRアドレス（ILAホストまたはイングレスILAルーター）かILAアドレス（エグレスILAルーター）のいずれかです。LOCは64ビットのロケーター（形式：W:X:Y:Z）で、宛先アドレスの上位64ビットを上書きします。チェックサムMODEは「no-action」、「adj-transport」、「neutral-map」、「neutral-map-auto」のいずれかです。neutral-mapが設定されている場合、Cビットが存在します。識別子TYPEは「luid」または「use-format」のいずれかです。use-formatの場合、識別子タイプフィールドが存在し、有効なタイプはそのフィールドから取得されます。

ila_xlatの使用方法は以下の通りです：

ip ila add loc_match MATCH loc LOC csum-mode MODE ident-type TYPE

MATCHは、翻訳を適用するために一致させる必要のある入力ロケータを示します。LOCは、宛先アドレスの上位64ビットを上書きするロケータです。MODEとTYPEは、上記と同じ意味を持ちます。

いくつかの例¶

# Configure an ILA route that uses checksum neutral mapping as well
# as type field. Note that the type field is set in the SIR address
# (the 2000 implies type is 1 which is LUID).
ip route add 3333:0:0:1:2000:0:1:87/128 encap ila 2001:0:87:0 \
     csum-mode neutral-map ident-type use-format

# Configure an ILA LWT route that uses auto checksum neutral mapping
# (no C-bit) and configure identifier type to be LUID so that the
# identifier type field will not be present.
ip route add 3333:0:0:1:2000:0:2:87/128 encap ila 2001:0:87:1 \
     csum-mode neutral-map-auto ident-type luid

ila_xlat configuration

# Configure an ILA to SIR mapping that matches a locator and overwrites
# it with a SIR address (3333:0:0:1 in this example). The C-bit and
# identifier field are used.
ip ila add loc_match 2001:0:119:0 loc 3333:0:0:1 \
    csum-mode neutral-map-auto ident-type use-format

# Configure an ILA to SIR mapping where checksum neutral is automatically
# set without the C-bit and the identifier type is configured to be LUID
# so that the identifier type field is not present.
ip ila add loc_match 2001:0:119:0 loc 3333:0:0:1 \
    csum-mode neutral-map-auto ident-type use-format
