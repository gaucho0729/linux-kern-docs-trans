Linux Phonetプロトコルファミリ¶

はじめに¶

Phonetは、ノキアのセルラーモデムがIPCおよびRPCのために使用するパケットプロトコルです。Linux Phonetソケットファミリを使用することで、Linuxホストプロセスはモデム、またはモデムに接続された他の外部デバイスとメッセージをやり取りできます。モデムはルーティングを担当します。

Phonetパケットは、デバイスによって異なり、以下のハードウェア接続を通じてやり取りできます：

  • USBとCDC Phonetインターフェース、

  • 赤外線、

  • Bluetooth、

  • RS232シリアルポート（専用の「FBUS」ラインディスカリンを備えた）、「

  • SSIバスと一部のTI OMAPプロセッサ。

パケット形式¶

Phonetパケットは以下の共通ヘッダを持ちます：

struct phonethdr {
  uint8_t  pn_media;  /* Media type (link-layer identifier) */
  uint8_t  pn_rdev;   /* Receiver device ID */
  uint8_t  pn_sdev;   /* Sender device ID */
  uint8_t  pn_res;    /* Resource ID or function */
  uint16_t pn_length; /* Big-endian message byte length (minus 6) */
  uint8_t  pn_robj;   /* Receiver object ID */
  uint8_t  pn_sobj;   /* Sender object ID */
};

Linuxでは、リンクレイヤーヘッダにはpn_mediaバイト（以下参照）が含まれます。次の7バイトはネットワークレイヤーヘッダの一部です。

デバイスIDは分割されており、6ビットの上位ビットがデバイスアドレスを構成し、2ビットの下位ビットは多重化に使用されます。また、8ビットのオブジェクト識別子も多重化に使用されます。このような性質から、Phonetは6ビットのアドレス空間と10ビットのトランスポートプロトコル（IP世界におけるポート番号に類似）を持つネットワークレイヤーとみなせます。

モデムは常にアドレス番号0を持ちます。他のすべてのデバイスはそれぞれ6ビットのアドレスを持ちます。

リンク層¶

Phonetリンクは常にポイントツーポイントリンクです。リンクレイヤーヘッダは1つのPhonetメディアタイプバイトで構成され、パケットが送信されるリンクをモデムの観点から一意に特定します。各Phonetネットワークデバイスは適切にメディアタイプバイトを先頭に追加し、設定する必要があります。便利なため、phonet_header_opsというリンクレイヤーヘッダ操作構造体が提供されています。これはネットワークデバイスのハードウェアアドレスに応じてメディアタイプを設定します。

Linux Phonetネットワークインターフェースは、イーサネットタイプ範囲外の専用リンクレイヤーパケットタイプ（ETH_P_PHONET）をサポートしています。これらはPhonetパケットのみを送受信できます。

仮想TUNトンネルドライバーもPhonetで使用できます。これはIFF_TUNモードで、IFF_NO_PIフラグを除いて使用します。この場合、リンクレイヤーヘッダがありませんので、Phonetメディアタイプバイトもありません。

Phonetインターフェースはパケットの再配列を許可されないため、これらには（デフォルト）Linux FIFO qdiscのみを使用する必要があります。

ネットワーク層¶

PhonetソケットアドレスファミリはPhonetパケットヘッダをマッピングします：

struct sockaddr_pn {
  sa_family_t spn_family;    /* AF_PHONET */
  uint8_t     spn_obj;       /* Object ID */
  uint8_t     spn_dev;       /* Device ID */
  uint8_t     spn_resource;  /* Resource or function */
  uint8_t     spn_zero[...]; /* Padding */
};

リソースフィールドは送受信時にのみ使用され、bind()およびgetsockname()では無視されます。

低レベルデータグラムプロトコル¶

アプリケーションは、PF_PHONETファミリのPhonetデータグラムソケットプロトコルを使用してPhonetメッセージを送信できます。各ソケットは、利用可能な2^10個のオブジェクトIDのうちの1つにバインドされ、他のピアとパケットを送受信できます。

struct sockaddr_pn addr = { .spn_family = AF_PHONET, };
ssize_t len;
socklen_t addrlen = sizeof(addr);
int fd;

fd = socket(PF_PHONET, SOCK_DGRAM, 0);
bind(fd, (struct sockaddr *)&addr, sizeof(addr));
/* ... */

sendto(fd, msg, msglen, 0, (struct sockaddr *)&addr, sizeof(addr));
len = recvfrom(fd, buf, sizeof(buf), 0,
               (struct sockaddr *)&addr, &addrlen);

このプロトコルはSOCK_DGRAMの接続なし semanticsを採用しています。ただし、connect()やgetpeername()はPhonetの使用例では役立たなさそうだったのでサポートされていません（必要であれば簡単に追加可能です）。

リソースサブスクリプション¶

Phonetデータグラムソケットは、以下の通り8ビットのPhonetリソースに任意の数サブスクライブできます：

uint32_t res = 0xXX;
ioctl(fd, SIOCPNADDRESOURCE, &res);

サブスクライブは、SIOCPNDELRESOURCE I/O制御リクエストを使用して同様にキャンセルされ、またはソケットが閉じるときにキャンセルされます。

注意：1つのリソースに対して同時に1つのみソケットがサブスクライブ可能です。複数のソケットが同時にサブスクライブされている場合、ioctl()はEBUSYを返します。

Phonet Pipeプロトコル¶

Phonetパイププロトコルは、端末間の渋滞制御を備えた単純な順序付きパケットプロトコルです。受動的なリスニングソケットパラダイムを使用します。リスニングソケットは一意の空きオブジェクトIDにバインドされ、各リスニングソケットはaccept()で取得したソケットごとに最大255同時接続を処理できます。

int lfd, cfd;

lfd = socket(PF_PHONET, SOCK_SEQPACKET, PN_PROTO_PIPE);
listen (lfd, INT_MAX);

/* ... */
cfd = accept(lfd, NULL, NULL);
for (;;)
{
  char buf[...];
  ssize_t len = read(cfd, buf, sizeof(buf));

  /* ... */

  write(cfd, msg, msglen);
}

通常、2つのエンドポイント間の接続は「第三者」アプリケーションによって確立されます。これは両エンドポイントが受動的であることを意味します。

Linuxカーネルバージョン2.6.39以降では、アクティブ側でconnect()を使用して2つのエンドポイントを直接接続することも可能です。これは新しいNokiaワイヤレスモデムAPIをサポートするためのものです（例：ST-Ericsson U8500プラットフォームのNokia Slim Modemなど）：

struct sockaddr_spn spn;
int fd;

fd = socket(PF_PHONET, SOCK_SEQPACKET, PN_PROTO_PIPE);
memset(&spn, 0, sizeof(spn));
spn.spn_family = AF_PHONET;
spn.spn_obj = ...;
spn.spn_dev = ...;
spn.spn_resource = 0xD9;
connect(fd, (struct sockaddr *)&spn, sizeof(spn));
/* normal I/O here ... */
close(fd);

パイププロトコルはSOL_PNPIPEレベルで2つのソケットオプションを提供します：

PNPIPE_ENCAPは1つの整数値(int)を受け取ります：

PNPIPE_ENCAP_NONE：

ソケットは通常通り動作します（デフォルト）。

PNPIPE_ENCAP_IP：

ソケットは仮想IPインターフェースのバックエンドとして使用されます。これはCAP_NET_ADMINの権限が必要です。NokiaモデムでのGPRSデータサポートはこの機能を使用できます。注意：このモードではpoll()やread()は信頼性がありません。

PNPIPE_IFINDEX

は読み取り専用の整数値です。これはPNPIPE_ENCAPで作成されたネットワークインターフェースのインデックスを含み、エンカプスレーションがオフの場合にはゼロです。

PNPIPE_HANDLE

は読み取り専用の整数値です。これはパイプの下位識別子（"パイプハンドル"）を含み、すでに接続済みまたは接続中であるソケットディスクリプタにのみ定義されます。
