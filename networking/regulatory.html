Linuxワイヤレス規制ドキュメンテーション¶

このドキュメントは、Linuxワイヤレス規制インフラストラクチャがどのように動作するかについての概要を説明しています。

最新情報はプロジェクトのウェブページで取得できます:

https://wireless.wiki.kernel.org/en/developers/Regulatory

ユーザー空間での規制ドメインの保持¶

規制ドメインの動的性質を考慮し、ユーザー空間に規制ドメインを保持し、ユーザー空間がカーネルに1つの規制ドメインをアップロードして、すべてのワイヤレスデバイスが従うべき中心的な規制ドメインを提供するフレームワークを提供しています。

規制ドメインをカーネルに渡す方法¶

規制ドメインが最初に設定されるとき、カーネルはすべての規制ルールを含むデータベースファイル(regulatory.db)を要求します。その後、そのデータベースを必要に応じて国ごとのルールを検索するために使用します。

規制ドメインをカーネルに渡す方法（旧CRDAソリューション）¶

ユーザー空間はnl80211経由でユーザー空間エージェントが構築した規制ドメインをカーネルに送信することで、規制ドメインを取得します。カーネルは予期される規制ドメインのみを尊重します。

この目的を達成するための現在利用可能なユーザー空間エージェントとしてCRDA（中央規制ドメインエージェント）があります。そのドキュメンテーションはこちら:

https://wireless.wiki.kernel.org/en/developers/Regulatory/CRDA

基本的に、カーネルは新しい規制ドメインが必要だとわかればudevイベントを送信します。特定のISO/IEC 3166 alpha2に対応する規制ドメインをトリガーするため、udevルールを設定できます。

以下は使用可能なudevルールの例です:

# 例ファイル、/etc/udev/rules.d/regulatory.rulesに配置するKERNEL==”regulatory*”, ACTION==”change”, SUBSYSTEM==”platform”, RUN+=”/sbin/crda”

alpha2は環境変数としてCOUNTRY変数の下で渡されます。

誰が規制ドメインを要求するのか？¶

  • ユーザー

ユーザーはiwを使用できます:

https://wireless.wiki.kernel.org/en/users/Documentation/iw

例:

# set regulatory domain to "Costa Rica"
iw reg set CR

これにより、カーネルに指定されたalpha2の規制ドメインを設定を依頼します。カーネルは、ユーザーが指定したalpha2に対応する規制ドメインを提供するようユーザー空間にueventを送信します。

  • 国情報要素用ワイヤレスサブシステム

カーネルはユーザー空間に新しい規制ドメインが必要であることを通知するueventを送信します。この機能の統合が進むにつれて詳細情報を追加します。

  • ドライバ

ドライバが特定の規制ドメインの設定が必要と判断した場合、ワイヤレスコアに通知できます。 regulatory_hint(). ドライバには2つの選択肢があります – 一つはalpha2を提供し、crdaがその国に対応する規制ドメインを提供するか、または内部のカスタム知識に基づいて独自の規制ドメインを構築し、ワイヤレスコアがそれを尊重できるようにするかです。

Most ドライバは、alpha2で規制ヒントを提供する最初のメカニズムに依存します。これらのドライバでは、カスタムEEPROM規制データに基づいてコンプライアンスを確認するための追加チェックが利用可能です。この追加チェックは、ドライバがreg_notifier()コールバックを登録することで利用できます。 struct wiphy このノティファイは、コアの規制ドメインが変更されたときに呼び出されます。ドライバはこれを利用して変更内容を確認し、変更を実施した主体（ドライバ、ユーザー、国IEなど）を検証し、内部EEPROMデータに基づいて許可する内容を決定できます。世界移動（ワールドローミング）を実現するデバイスドライバはこのコールバックを使用すべきです。ワールドローミングに関する詳細は、サポートが有効になったときにこのドキュメントに追加されます。

自身の規制ドメインを提供するデバイスドライバはコールバックを必要としません。なぜなら、登録されたチャンネルのみが許可されるためです。したがって 追加 チャンネルは有効化できません。

例コード - alpha2をヒントするドライバ:¶

この例はzd1211rwデバイスドライバから来ています。まず、デバイスのEEPROMの国/規制ドメイン値を特定のalpha2にマッピングするようにします。

static struct zd_reg_alpha2_map reg_alpha2_map[] = {
      { ZD_REGDOMAIN_FCC, "US" },
      { ZD_REGDOMAIN_IC, "CA" },
      { ZD_REGDOMAIN_ETSI, "DE" }, /* Generic ETSI, use most restrictive */
      { ZD_REGDOMAIN_JAPAN, "JP" },
      { ZD_REGDOMAIN_JAPAN_ADD, "JP" },
      { ZD_REGDOMAIN_SPAIN, "ES" },
      { ZD_REGDOMAIN_FRANCE, "FR" },

次に、EEPROMの読み込んだ値をalpha2にマッピングするルーチンを定義します。

static int zd_reg2alpha2(u8 regdomain, char *alpha2)
{
      unsigned int i;
      struct zd_reg_alpha2_map *reg_map;
              for (i = 0; i < ARRAY_SIZE(reg_alpha2_map); i++) {
                      reg_map = &reg_alpha2_map[i];
                      if (regdomain == reg_map->reg) {
                      alpha2[0] = reg_map->alpha2[0];
                      alpha2[1] = reg_map->alpha2[1];
                      return 0;
              }
      }
      return 1;
}

最後に、発見したalpha2をコアにヒントを出すことができます。ただし、wiphyを登録した後で行い、初期化中に実行する必要があります。

r = zd_reg2alpha2(mac->regdomain, alpha2);
if (!r)
        regulatory_hint(hw->wiphy, alpha2);

例コード - 内蔵規制ドメインを提供するドライバ:¶

[注意: このAPIは現在利用できません。必要に応じて追加可能です]

ドライバから取得可能な規制情報をもつ場合、あなた が必要 な場合、このAPIを使用して規制ドメイン構造体を構築し、ワイヤレスコアに渡すことができます。これを実行するには kmalloc() 規制ドメイン構造体を保持できるだけのサイズの構造体を作成し、その中にデータを埋め込む必要があります。最後に、構造体を含めて regulatory_hint() を呼び出します。

以下はスタックを使用した規制ドメインの簡単な例です。あなたの実装は異なります（EEPROMキャッシュを読み込むなど）。

規制ドメインの例キャッシュ:

struct ieee80211_regdomain mydriver_jp_regdom = {
      .n_reg_rules = 3,
      .alpha2 =  "JP",
      //.alpha2 =  "99", /* If I have no alpha2 to map it to */
      .reg_rules = {
              /* IEEE 802.11b/g, channels 1..14 */
              REG_RULE(2412-10, 2484+10, 40, 6, 20, 0),
              /* IEEE 802.11a, channels 34..48 */
              REG_RULE(5170-10, 5240+10, 40, 6, 20,
                      NL80211_RRF_NO_IR),
              /* IEEE 802.11a, channels 52..64 */
              REG_RULE(5260-10, 5320+10, 40, 6, 20,
                      NL80211_RRF_NO_IR|
                      NL80211_RRF_DFS),
      }
};

wiphyが登録された後、コードのどこかで以下の処理を行います:

struct ieee80211_regdomain *rd;
int size_of_regd;
int num_rules = mydriver_jp_regdom.n_reg_rules;
unsigned int i;

size_of_regd = sizeof(struct ieee80211_regdomain) +
        (num_rules * sizeof(struct ieee80211_reg_rule));

rd = kzalloc(size_of_regd, GFP_KERNEL);
if (!rd)
        return -ENOMEM;

memcpy(rd, &mydriver_jp_regdom, sizeof(struct ieee80211_regdomain));

for (i=0; i < num_rules; i++)
        memcpy(&rd->reg_rules[i],
               &mydriver_jp_regdom.reg_rules[i],
               sizeof(struct ieee80211_reg_rule));
regulatory_struct_hint(rd);
