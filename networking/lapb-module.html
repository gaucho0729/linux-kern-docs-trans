Linux LAPBモジュールインターフェース¶

バージョン 1.3

ジョナサン・ナイヤー 29.12.96

変更 (ヘンナー・アイゼン, 2000-10-29): data_indication() に int 型の戻り値を追加

LAPB モジュールは、Linux オペレーティングシステムのどの部分でも LAPB サービスを必要とする場合に使用できる別個にコンパイルされたモジュールです。このドキュメントでは、このモジュールのインターフェースと提供するサービスを定義します。この文脈での「モジュール」という用語は、LAPB モジュールが別個にロード可能なモジュールであることを意味するわけではありませんが、標準的な意味での「モジュール」を指します。

LAPB モジュールへのインターフェースには、モジュールへの関数、モジュールから重要な状態変化を示すコールバック、およびモジュールに関する情報を取得・設定する構造体が含まれます。

構造体¶

おそらく最も重要な構造体は、受信および送信データを保持する skbuff 構造体です。ただし、これは本ドキュメントの範囲外です。

LAPB 特有の構造体は LAPB 初期化構造体と LAPB パラメータ構造体です。これらは標準ヘッダーファイル <linux/lapb.h> に定義されます。ヘッダーファイル <net/lapb.h> は LAPB モジュール内部用であり、外部での使用はできません。

LAPB初期化構造体¶

この構造体は、lapb_register の呼び出し（以下参照）においてのみ使用されます。これは LAPB モジュールのサービスを必要とするデバイスドライバに関する情報を含みます:

struct lapb_register_struct {
        void (*connect_confirmation)(int token, int reason);
        void (*connect_indication)(int token, int reason);
        void (*disconnect_confirmation)(int token, int reason);
        void (*disconnect_indication)(int token, int reason);
        int  (*data_indication)(int token, struct sk_buff *skb);
        void (*data_transmit)(int token, struct sk_buff *skb);
};

この構造体の各メンバは、LAPB モジュールで特定のイベントが発生した際にデバイスドライバが呼び出す関数に対応します。詳細は以下で説明します。コールバックが不要 (!!) 場合は NULL を代わりに使用できます。

LAPBパラメータ構造体¶

この構造体は lapb_getparms および lapb_setparms 関数（以下参照）で使用されます。これらはデバイスドライバが特定の接続における LAPB 実装の運用パラメータを取得および設定できるようにします:

struct lapb_parms_struct {
        unsigned int t1;
        unsigned int t1timer;
        unsigned int t2;
        unsigned int t2timer;
        unsigned int n2;
        unsigned int n2count;
        unsigned int window;
        unsigned int state;
        unsigned int mode;
};

T1 および T2 はプロトコルタイミングパラメータで、100ms 単位で指定されます。N2 はリンクで失敗とみなされる前のリンク試行回数の最大値です。ウィンドウサイズは、リモート端が確認せずに送信できるデータパケットの最大数を表し、標準 LAPB リンクでは 1 〜 7、拡張 LAPB リンクでは 1 〜 127 が許容されます。

mode 変数は、現在 3 値を設定するために使用されるビットフィールドです。ビットフィールドの意味は以下の通り:

ビット

意味

0

LAPB 操作 (0=LAPB_STANDARD 1=LAPB_EXTENDED)

1

[SM]LP 操作 (0=LAPB_SLP 1=LAPB=MLP)

2

DTE/DCE 操作 (0=LAPB_DTE 1=LAPB_DCE)

3-31

予約済み、0でなければならない。

拡張LAPB操作は拡張シーケンス番号の使用を意味し、結果としてより大きなウィンドウサイズを許容します。デフォルトは標準LAPB操作です。MLP操作はSLP操作と同様ですが、LAPBで使用されるアドレスが操作モードを示すために異なります。デフォルトはシングルリンクプロシージャです。DCEとDTEの操作の違いは(i)コマンドおよび応答に使用されるアドレス、および(ii)DCEが接続されていない場合、T1ごとにDMを送信することです（ポールが設定されていない）。上記の定数名は大文字で、パブリックLAPBヘッダーファイルで定義されます。

関数¶

LAPBモジュールは複数の関数エントリポイントを提供します。

int lapb_register(void *token, struct lapb_register_struct);

LAPBモジュールを使用する前にこの関数を呼び出す必要があります。呼び出しが成功するとLAPB_OKが返されます。トークンはデバイスドライバーが生成する一意の識別子で、LAPBリンクのインスタンスを一意に識別します。これはLAPBモジュールのすべてのコールバックで返され、デバイスドライバーがLAPBモジュールに呼び出すすべての関数で使用されます。単一のデバイスドライバー内に複数のLAPBリンクがある場合、lapb_registerへの複数の呼び出しが必要です。lapb_register_structの形式は上記に記載されています。返却値は以下の通りです。

LAPB_OK

LAPBが正常に登録されました。

LAPB_BADTOKEN

トークンはすでに登録されています。

LAPB_NOMEM

メモリ不足

 
int lapb_unregister(void *token);

この関数はLAPBリンクに関連するすべてのリソースを解放します。現在のLAPBリンクはさらにメッセージを送信することなく放棄されます。この関数呼び出し後、トークンの値はLAPB関数のすべての呼び出しでもはや有効ではありません。有効な返却値は以下の通りです。

LAPB_OK

LAPBが正常に登録解除されました。

LAPB_BADTOKEN

無効または不明なLAPBトークン。

 
int lapb_getparms(void *token, struct lapb_parms_struct *parms);

デバイスドライバーが現在のLAPB変数の値を取得できます。lapb_parms_structは上記に記載されています。有効な返却値は以下の通りです。

LAPB_OK

LAPB_getparmsが正常に実行されました。

LAPB_BADTOKEN

無効または不明なLAPBトークン。

 
int lapb_setparms(void *token, struct lapb_parms_struct *parms);

デバイスドライバーが現在のLAPB変数の値を設定できます。lapb_parms_structは上記に記載されています。t1timer、t2timer、n2countの値は無視されます。また、接続中にモードビットを変更しても無視されます。エラーが発生した場合、どの値も変更されていません。有効な返却値は以下の通りです。

LAPB_OK

LAPB_getparmsが正常に実行されました。

LAPB_BADTOKEN

無効または不明なLAPBトークン。

LAPB_INVALUE

いずれかの値が許容範囲外でした。

 
int lapb_connect_request(void *token);

現在のパラメータ設定を使用して接続を開始します。有効な返却値は以下の通りです。

LAPB_OK

LAPBが接続を開始しています。

LAPB_BADTOKEN

無効または不明なLAPBトークン。

LAPB_CONNECTED

LAPBモジュールはすでに接続されています。

 
int lapb_disconnect_request(void *token);

接続を切断します。有効な返却値は以下の通りです。

LAPB_OK

LAPBが接続を切断しています。

LAPB_BADTOKEN

無効または不明なLAPBトークン。

LAPB_NOTCONNECTED

LAPBモジュールは接続されていません。

 
int lapb_data_request(void *token, struct sk_buff *skb);

リンク経由での送信のために、LAPBモジュールにデータをキューイングします。呼び出しが成功した場合、skbuffはLAPBモジュールの所有となり、デバイスドライバでは再利用できません。有効な戻り値は以下の通りです:

LAPB_OK

LAPBがデータを受け入れました。

LAPB_BADTOKEN

無効または不明なLAPBトークン。

LAPB_NOTCONNECTED

LAPBモジュールは接続されていません。

 
int lapb_data_received(void *token, struct sk_buff *skb);

デバイスから受信したデータをLAPBモジュールにキューイングします。LAPBモジュールに渡されるデータはskb->dataがLAPBデータの先頭を指している必要があります。呼び出しが成功した場合、skbuffはLAPBモジュットルの所有となり、デバイスドライバでは再利用できません。有効な戻り値は以下の通りです:

LAPB_OK

LAPBがデータを受け入れました。

LAPB_BADTOKEN

無効または不明なLAPBトークン。

コールバック¶

これらは、LAPBモジュールがイベント発生時に呼び出すためにデバイスドライバが提供するコールバック関数です。これらはlapb_register（上記参照）でlapb_register_struct（上記参照）構造体とともにLAPBモジュールに登録されます。

void (*connect_confirmation)(void *token, int reason);

LAPBモジュールがlapb_connect_request（上記参照）呼び出しによって要求された接続が確立した後に呼び出されます。理由は常にLAPB_OKです。

void (*connect_indication)(void *token, int reason);

LAPBモジュールがリモートシステムによってリンクが確立されたときに呼び出されます。理由は常にLAPB_OKです。

void (*disconnect_confirmation)(void *token, int reason);

デバイスドライバがlapb_disconnect_request（上記参照）呼び出しを行った後にイベントが発生したときにLAPBモジュールが呼び出します。理由は発生した事象を示します。すべてのケースにおいてLAPBリンクは終了とみなされます。理由の値は以下の通りです:

LAPB_OK

LAPBリンクが正常に終了しました。

LAPB_NOTCONNECTED

リモートシステムが接続されていませんでした。

LAPB_TIMEDOUT

リモートシステムからN2回の試行で応答が受信されませんでした。

 
void (*disconnect_indication)(void *token, int reason);

LAPBモジュールがリモートシステムによってリンクが終了されたか、他のイベントによってリンクが終了したときに呼び出されます。これはlapb_connect_request（上記参照）呼び出しに対応する応答として返される可能性があり、リモートシステムが要求を拒否した場合です。理由の値は以下の通りです:

LAPB_OK

リモートシステムによってLAPBリンクが正常に終了しました。

LAPB_REFUSED

リモートシステムが接続要求を拒否しました。

LAPB_NOTCONNECTED

リモートシステムが接続されていませんでした。

LAPB_TIMEDOUT

リモートシステムからN2回の試行で応答が受信されませんでした。

 
int (*data_indication)(void *token, struct sk_buff *skb);

LAPBモジュールがリモートシステムから受信したデータをプロトコルスタックの次のレイヤーに転送すべき場合に呼び出されます。このときskbuffはデバイスドライバの所有となり、LAPBモジュールはこれに対してさらなる処理を行いません。skb->dataポインタはLAPBヘッダの後のデータの最初のバイトを指します。

フレームが上位レイヤーに届く前にドロップされた場合、このメソッドはヘッダーファイルinclude/linux/netdevice.hで定義されたNET_RX_DROPを返す必要があります。

void (*data_transmit)(void *token, struct sk_buff *skb);

これは、デバイスドライバーがリモートシステムにデータを送信する際にLAPBモジュールが呼び出します。skbuffはデバイスドライバーの所有物となり、LAPBモジュールはこれに対してさらに処理を行いません。skb->dataポインタはLAPBヘッダーの最初のバイトを指しています。
