Linuxパケットジェネレーターガイド¶

CONFIG_NET_PKTGENを有効にして、pktgenをカーネル内またはモジュールとしてコンパイル・ビルドしてください。モジュールの使用が推奨されます; 必要に応じてmodprobe pktgenを実行してください。起動後、pktgenは各CPUにアフィニティを持つスレッドを生成します。監視および制御は/proc経由で行われます。適切なサンプルスクリプトを選択し、その設定を行うのが最も簡単です。

デュアルCPUの場合:

ps aux | grep pkt
root       129  0.3  0.0     0    0 ?        SW    2003 523:20 [kpktgend_0]
root       130  0.3  0.0     0    0 ?        SW    2003 509:50 [kpktgend_1]

監視および制御のためにpktgenは以下を生成します:

/proc/net/pktgen/pgctrl
/proc/net/pktgen/kpktgend_X
/proc/net/pktgen/ethX

最大性能を達成するためのNICのチューニング¶

デフォルトのNIC設定は（おそらく）pktgenの人工的な過負荷型ベンチマークには最適化されていません。これは通常の使用ケースを妨げる可能性があるためです。

NICのTXリングバッファを特定的に増やす:

# ethtool -G ethX tx 1024

大きなTXリングバッファはpktgenのパフォーマンス向上に寄与しますが、一般的なケースでは1) TXリングバッファがCPUのL1/L2キャッシュよりも大きくなる可能性があるため、2) NIC HWレイヤーでのキューイングが増える（バッファブルームに悪影響を及ぼす）ため、逆にパフォーマンスに悪影響を及ぼす可能性があります。

HW TXリング内のパケット/ディスクリプタが遅延を引き起こすと結論付けるのは控えましょう。ドライバはパフォーマンスの理由でリングバッファのクリーンアップを遅延させることが一般的であり、TXリングが停止しているパケットは単にクリーンアップを待っている可能性があります。

このクリーンアップの問題は特にドライバixgbe（Intel 82599チップ）の場合に顕著です。このドライバ（ixgbe）はTX+RXリングクリーンアップを統合しており、クリーンアップ間隔はethtool –coalesce設定のパラメータ「rx-usecs」に影響されます。

ixgbeでは例えば「30」を指定し、約33Kインタラプト/秒（1/30*10^6）を実現します:

# ethtool -C ethX rx-usecs 30

カーネルスレッド¶

pktgenは各CPUにアフィニティを持つスレッドを生成します。これは/proc/net/pktgen/kpktgend_Xというprocファイルで制御されます。

例: /proc/net/pktgen/kpktgend_0:

Running:
Stopped: eth4@0
Result: OK: add_device=eth4@0

最も重要なのはスレッドに割り当てられたデバイスです。

2つの基本的なスレッドコマンドは:

  • add_device DEVICE@NAME – 単一のデバイスを追加します

  • rem_device_all – すべての関連デバイスを削除します

スレッドにデバイスを追加する際、対応するprocファイルが作成され、このデバイスの設定に使用されます。そのため、デバイス名は一意である必要があります。

同一のデバイスを複数スレッドに追加するサポートのために、マルチキューNICで有用です。デバイス名の命名規則に「@」を追加します: デバイス@something

「@」の後の部分はなんでもよいですが、スレッド番号を使用するのが慣例です。

デバイスの設定¶

これは/procインターフェース経由で実行され、サンプルスクリプトで定義されたpgsetを用いることで最も簡単に実行できます。サンプルスクリプトから関数を使用するには、PGDEV環境変数を指定する必要があります。つまり：

export PGDEV=/proc/net/pktgen/eth4@0
source samples/pktgen/functions.sh

例:

pg_ctrl start           starts injection.
pg_ctrl stop            aborts injection. Also, ^C aborts generator.

pgset "clone_skb 1"     sets the number of copies of the same packet
pgset "clone_skb 0"     use single SKB for all transmits
pgset "burst 8"         uses xmit_more API to queue 8 copies of the same
                        packet and update HW tx queue tail pointer once.
                        "burst 1" is the default
pgset "pkt_size 9014"   sets packet size to 9014
pgset "frags 5"         packet will consist of 5 fragments
pgset "count 200000"    sets number of packets to send, set to zero
                        for continuous sends until explicitly stopped.

pgset "delay 5000"      adds delay to hard_start_xmit(). nanoseconds

pgset "dst 10.0.0.1"    sets IP destination address
                        (BEWARE! This generator is very aggressive!)

pgset "dst_min 10.0.0.1"            Same as dst
pgset "dst_max 10.0.0.254"          Set the maximum destination IP.
pgset "src_min 10.0.0.1"            Set the minimum (or only) source IP.
pgset "src_max 10.0.0.254"          Set the maximum source IP.
pgset "dst6 fec0::1"     IPV6 destination address
pgset "src6 fec0::2"     IPV6 source address
pgset "dstmac 00:00:00:00:00:00"    sets MAC destination address
pgset "srcmac 00:00:00:00:00:00"    sets MAC source address

pgset "queue_map_min 0" Sets the min value of tx queue interval
pgset "queue_map_max 7" Sets the max value of tx queue interval, for multiqueue devices
                        To select queue 1 of a given device,
                        use queue_map_min=1 and queue_map_max=1

pgset "src_mac_count 1" Sets the number of MACs we'll range through.
                        The 'minimum' MAC is what you set with srcmac.

pgset "dst_mac_count 1" Sets the number of MACs we'll range through.
                        The 'minimum' MAC is what you set with dstmac.

pgset "flag [name]"     Set a flag to determine behaviour.  Current flags
                        are: IPSRC_RND # IP source is random (between min/max)
                             IPDST_RND # IP destination is random
                             UDPSRC_RND, UDPDST_RND,
                             MACSRC_RND, MACDST_RND
                             TXSIZE_RND, IPV6,
                             MPLS_RND, VID_RND, SVID_RND
                             FLOW_SEQ,
                             QUEUE_MAP_RND # queue map random
                             QUEUE_MAP_CPU # queue map mirrors smp_processor_id()
                             UDPCSUM,
                             IPSEC # IPsec encapsulation (needs CONFIG_XFRM)
                             NODE_ALLOC # node specific memory allocation
                             NO_TIMESTAMP # disable timestamping
pgset 'flag ![name]'    Clear a flag to determine behaviour.
                        Note that you might need to use single quote in
                        interactive mode, so that your shell wouldn't expand
                        the specified flag as a history command.

pgset "spi [SPI_VALUE]" Set specific SA used to transform packet.

pgset "udp_src_min 9"   set UDP source port min, If < udp_src_max, then
                        cycle through the port range.

pgset "udp_src_max 9"   set UDP source port max.
pgset "udp_dst_min 9"   set UDP destination port min, If < udp_dst_max, then
                        cycle through the port range.
pgset "udp_dst_max 9"   set UDP destination port max.

pgset "mpls 0001000a,0002000a,0000000a" set MPLS labels (in this example
                                        outer label=16,middle label=32,
                                        inner label=0 (IPv4 NULL)) Note that
                                        there must be no spaces between the
                                        arguments. Leading zeros are required.
                                        Do not set the bottom of stack bit,
                                        that's done automatically. If you do
                                        set the bottom of stack bit, that
                                        indicates that you want to randomly
                                        generate that address and the flag
                                        MPLS_RND will be turned on. You
                                        can have any mix of random and fixed
                                        labels in the label stack.

pgset "mpls 0"           turn off mpls (or any invalid argument works too!)

pgset "vlan_id 77"       set VLAN ID 0-4095
pgset "vlan_p 3"         set priority bit 0-7 (default 0)
pgset "vlan_cfi 0"       set canonical format identifier 0-1 (default 0)

pgset "svlan_id 22"      set SVLAN ID 0-4095
pgset "svlan_p 3"        set priority bit 0-7 (default 0)
pgset "svlan_cfi 0"      set canonical format identifier 0-1 (default 0)

pgset "vlan_id 9999"     > 4095 remove vlan and svlan tags
pgset "svlan 9999"       > 4095 remove svlan tag


pgset "tos XX"           set former IPv4 TOS field (e.g. "tos 28" for AF11 no ECN, default 00)
pgset "traffic_class XX" set former IPv6 TRAFFIC CLASS (e.g. "traffic_class B8" for EF no ECN, default 00)

pgset "rate 300M"        set rate to 300 Mb/s
pgset "ratep 1000000"    set rate to 1Mpps

pgset "xmit_mode netif_receive"  RX inject into stack netif_receive_skb()
                                 Works with "burst" but not with "clone_skb".
                                 Default xmit_mode is "start_xmit".

サンプルスクリプト¶

pktgen用のチュートリアルスクリプトと補助ツールは、samples/pktgenディレクトリにあります。補助スクリプトparameters.shは、サンプルスクリプト全体で一貫してパラメータを解析するのを容易にします。

使用例とヘルプ：

./pktgen_sample01_simple.sh -i eth4 -m 00:1B:21:3C:9D:F8 -d 192.168.8.2

Usage::

./pktgen_sample01_simple.sh [-vx] -i ethX

-i : ($DEV)       output interface/device (required)
-s : ($PKT_SIZE)  packet size
-d : ($DEST_IP)   destination IP
-m : ($DST_MAC)   destination MAC-addr
-t : ($THREADS)   threads to start
-c : ($SKB_CLONE) SKB clones send before alloc new SKB
-b : ($BURST)     HW level bursting of SKBs
-v : ($VERBOSE)   verbose
-x : ($DEBUG)     debug

設定されるグローバル変数も一覧にしています。例えば、必須のインターフェース/デバイスパラメータ「-i」は変数$DEVを設定します。pktgen_sampleXXスクリプトをコピーし、必要に応じてカスタマイズしてください。

古いスクリプト：

pktgen.conf-1-2                  # 1 CPU 2 dev
pktgen.conf-1-1-rdos             # 1 CPU 1 dev w. route DoS
pktgen.conf-1-1-ip6              # 1 CPU 1 dev ipv6
pktgen.conf-1-1-ip6-rdos         # 1 CPU 1 dev ipv6  w. route DoS
pktgen.conf-1-1-flows            # 1 CPU 1 dev multiple flows.

割込みアフィニティ¶

特定のCPUにデバイスを追加する際、/proc/irq/XX/smp_affinityを割り当てることでTX割込みを同じCPUにバインドするのも良い方法です。これにより、skbsを解放する際のキャッシュの衝突が減少します。

さらに、デバイスフラグQUEUE_MAP_CPUを使用することで、SKBsのTXキューを実行中のスレッドのCPUにマッピングできます（smp_processor_id()から直接取得します）。

IPsecを有効にする¶

ESPエンカプスレーションを含むデフォルトのIPsec変換とトランスポートモードを有効にするには、単に以下のように設定します：

pgset "flag IPSEC"
pgset "flows 1"

既存のテストベッドスクリプトでAHタイプとトンネルモードを使用するのを壊さないため、"pgset spi SPI_VALUE"を用いて使用する変換モードを指定できます。
