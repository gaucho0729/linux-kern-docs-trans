CPU フィーチャ¶

Hollis Blanchard <hollis@austin.ibm.com> 5月2002年

このドキュメントでは、PPC Linuxカーネルで自己修正コードを含むシステムを用いて、コンパイル時選択を必要とせずにさまざまなPowerPC CPUをサポートする仕組みについて説明します。

起動プロセスの初期段階では、ppc32カーネルが現在のCPUタイプを検出し、それに応じた機能セットを選択します。例として、Altivecサポート、分離された指令・データキャッシュ、CPUがDOZEおよびNAPスリープモードをサポートするかどうかなどが挙げられます。

機能セットの検出は簡単です。プロセッサの一覧はarch/powerpc/kernel/cputable.cにあります。PVRレジスタはマスク処理され、リスト内の各値と比較されます。一致した場合、cur_cpu_specのcpu_featuresがこのプロセッサの機能ビットマスクに割り当てられ、__setup_cpu関数が呼び出されます。

Cコードでは'cur_cpu_spec[smp_processor_id()]->cpu_features'を特定の機能ビットでテストします。これはppc_setup_l2cr()など多くの場所で行われます。

アセンブリでcpufeaturesを実装するにはやや複雑です。パフォーマンスに影響を与える複数のパスがあり、配列インデックス、構造体参照、条件分岐を追加するとパフォーマンスが低下します。パフォーマンスのペナルティを回避しつつ、コンパイル時ではなく実行時でのCPU選択を可能にするため、未使用コードは'nop'命令で置き換えられます。この'nop'処理はCPU 0の機能に基づいて行われるため、非同一プロセッサを持つマルチプロセッサシステムでは動作しません（ただし、このようなシステムは他の問題を抱えている可能性が高いです）。

プロセッサタイプを検出した後、カーネルは不要なコードセクションを'nop'命令で上書きしてパッチします。cpufeaturesを使用するには、arch/powerpc/include/asm/cputable.hにある2つのマクロのみが必要です。head.Sのtransfer_to_handlerで確認できます。

#ifdef CONFIG_ALTIVEC
BEGIN_FTR_SECTION
        mfspr   r22,SPRN_VRSAVE         /* if G4, save vrsave register value */
        stw     r22,THREAD_VRSAVE(r23)
END_FTR_SECTION_IFSET(CPU_FTR_ALTIVEC)
#endif /* CONFIG_ALTIVEC */

CPU 0がAltivecをサポートする場合、コードは変更されません。サポートしない場合は、両方の命令が'nop'命令に置き換えられます。

END_FTR_SECTIONマクロには2つのより簡単な変種があります：END_FTR_SECTION_IFSETとEND_FTR_SECTION_IFCLR。これらはそれぞれcur_cpu_spec[0]->cpu_featuresのフラグが設定されているか、クリアされているかをテストします。これら2つのマクロはほとんどの場合で使用すべきです。

END_FTR_SECTIONマクロは、'__ftr_fixup' ELFセクションにこのコードに関する情報を保存することで実装されます。do_cpu_ftr_fixups（arch/powerpc/kernel/misc.S）が呼び出されると、__ftr_fixup内のレコードを反復処理し、必要な機能が存在しない場合、BEGIN_FTR_SECTIONからEND_FTR_SECTIONまでの各セクションに'nop'命令を連続して書き込みます。
