ハイパーコール操作コード (hcalls)¶

概要¶

64ビット Power Book3S プラットフォームでの仮想化は PAPR 指定書に基づいています 1 ゲストOSの実行環境と、ハイパーバイザとの特権操作における相互作用方法を記述しています

  • IBM PowerVM (PHYP): IBMの独自のハイパーバイザで、AIX、IBM-i、Linuxをサポートゲストとして提供（論理パーティションまたはLPARSと呼ばれる）します。これは完全なPAPR指定書をサポートしています。

  • Qemu/KVM: PPC64 Linuxホスト上で実行されるPPC64 Linuxゲストをサポートします。ただし、これはPAPR指定書のサブセットであるLoPAPRのみを実装しています。 2.

PPC64アーキテクチャでは、PAPRハイパーバイザ上で実行されるゲストカーネルは呼ばれます pSeriesゲスト. pseriesゲストはスーパーバイザーモード（HV=0）で実行され、ハイパーバイザ特権の操作が必要なときにハイパーバイザにハイパーコールを発行しなければなりません。 3 またはハイパーバイザで管理されるその他のサービスに対して。

したがって、ハイパーコール（hcall）は、pseriesゲストがハイパーバイザに特権操作を代行して実行するよう依頼する本質的なリクエストです。ゲストは必要な入力オペランドとともにハイパーコールを発行します。ハイパーバイザが特権操作を実行した後、ステータスコードと出力オペランドをゲストに返します。

HCALL ABI¶

pseriesゲストとPAPRハイパーバイザ間のhcallのABI仕様は、参照のセクション14.5.3に記載されています。 2. ハイパーバイザコンテキストへの切り替えはインストラクションを通じて行われます。 HVCS hcallのオペコードが設定されていることを期待しています。 r3 およびhcallの入力引数はレジスタで提供されます。 r4-r12. 値をメモリバッファを通じて渡す必要がある場合、そのバッファに保存されたデータはビッグエンディアンバイト順でなければなりません。

ハイパーバイザが‘HVCS’インストラクションを処理した後、制御がゲストに戻ると、hcallの戻り値は以下に利用可能です。 r3 および出力値はレジスタで返されます。 r4-r12. 入力引数の場合と同様に、メモリバッファに保存された出力値はビッグエンディアンバイト順でなければなりません。

PowerPCアーキテクチャコードは、以下のように名付けられた便利なラッパーを提供します。 plpar_hcall_xxx アーキテクチャ固有のヘッダで定義されています。 4 Linuxカーネルがpseriesゲストとして実行されているときにハイパーコールを発行するためのものです。

DRCおよびDRCインデックス¶

DR1                                  Guest
+--+        +------------+         +---------+
|  | <----> |            |         |  User   |
+--+  DRC1  |            |   DRC   |  Space  |
            |    PAPR    |  Index  +---------+
DR2         | Hypervisor |         |         |
+--+        |            | <-----> |  Kernel |
|  | <----> |            |  Hcall  |         |
+--+  DRC2  +------------+         +---------+

PAPRハイパーバイザの用語で、PCIデバイス、NVDIMMなど、LPARが動的リソース（DR）として使用可能な共有ハードウェアリソース。DRがLPARに割り当てられた場合、PHYPはLPARのアクセスを管理するためのデータ構造である動的リソース接続子（DRC）を作成します。LPARはDRCを不透明な32ビット数であるDRCインデックスで参照します。DRCインデックス値はデバイスツリーで提供され、DRに関連するデバイスツリーノードの属性として存在します。

HCALLリターン値¶

HCALLの処理後、ハイパーバイザは r3 HCALLの成功または失敗を示します。失敗した場合、エラーコードがエラーの原因を示します。これらのコードはアーキテクチャ固有のヘッダーファイルで定義およびドキュメント化されています 4.

一部のHCALLは長時間かかる可能性があり、完全に処理するために複数回実行される必要があります。このようなHCALLは通常、不透明な値 継続トークン 引数リスト内で受け取り、 H_CONTINUE ハイパーバイザがHCALLの処理をまだ完了していないことを示します。

このようなHCALLを実行するには、ゲストは 継続トークン == 0 初期呼び出しで設定し、その後のHCALLではハイパーバイザが返す 継続トークン の値を使用します。ハイパーバイザが非 H_CONTINUE のリターン値を返すまで繰り返します。

HCALLオペコード¶

以下はPHYPがサポートするHCALLの一例です。対応するオペコード値については、アーキテクチャ固有のヘッダーファイルをご参照ください 4:

H_SCM_READ_METADATA

入力: drcIndex, offset, buffer-address, numBytesToRead
出力: numBytesRead
リターン値: H_Success, H_Parameter, H_P2, H_P3, H_Hardware

NVDIMMのDRCインデックスを指定して、そのメタデータ領域から指定されたオフセット位置にNバイトを読み込み、提供されたバッファにコピーします。メタデータ領域はラベル情報、不良ブロック情報などの構成情報を格納しており、NVDIMMストレージ領域とは別領域に配置されるため、別なアクセスセマンティクスが提供されています。

H_SCM_WRITE_METADATA

入力: drcIndex, offset, data, numBytesToWrite
出力: なし
リターン値: H_Success, H_Parameter, H_P2, H_P4, H_Hardware

NVDIMMのDRCインデックスを指定して、指定されたオフセット位置から提供されたバッファからNバイトをメタデータ領域に書き込みます。

H_SCM_BIND_MEM

入力: drcIndex, startingScmBlockIndex, numScmBlocksToBind,
targetLogicalMemoryAddress, continue-token
出力: continue-token, targetLogicalMemoryAddress, numScmBlocksToBound
リターン値: H_Success, H_Parameter, H_P2, H_P3, H_P4, H_Overlap,
H_Too_Big, H_P5, H_Busy

NVDIMMのDRCインデックスを指定して、連続するSCMブロック範囲を (startingScmBlockIndex, startingScmBlockIndex+numScmBlocksToBind) ゲストにマッピングします。 targetLogicalMemoryAddress ゲスト物理アドレス空間内で。targetLogicalMemoryAddress == 0xFFFFFFFF_FFFFFFFFの場合は、ハイパーバイザがゲストにターゲットアドレスを割り当てます。ゲストがSCMブロックにアクティブなPTEエントリを持つ場合、HCALLが失敗する可能性があります。 targetLogicalMemoryAddress == 0xFFFFFFFF_FFFFFFFF then hypervisor assigns a target address to the guest. The HCALL can fail if the Guest has an active PTE entry to the SCM block being bound.

H_SCM_UNBIND_MEM | 入力: drcIndex, startingScmLogicalMemoryAddress, numScmBlocksToUnbind | 出力: numScmBlocksUnbound | 戻り値: H_Success, H_Parameter, H_P2, H_P3, H_In_Use, H_Overlap, | H_Busy, H_LongBusyOrder1mSec, H_LongBusyOrder10mSec

NVDIMMのDRCインデックスを指定して、 numScmBlocksToUnbind SCMブロックをゲスト物理アドレス空間から解除します。ゲストがSCMブロックにアクティブなPTEエントリを持つ場合、HCALLが失敗する可能性があります。 startingScmLogicalMemoryAddress from guest physical address space. The HCALL can fail if the Guest has an active PTE entry to the SCM block being unbound.

H_SCM_QUERY_BLOCK_MEM_BINDING

入力: drcIndex, scmBlockIndex
出力: Guest-Physical-Address
リターン値: H_Success, H_Parameter, H_P2, H_NotFound

DRCインデックスとSCMブロックインデックスを指定して、SCMブロックがマッピングされているゲスト物理アドレスを返します。

H_SCM_QUERY_LOGICAL_MEM_BINDING

入力: Guest-Physical-Address
出力: drcIndex, scmBlockIndex
リターン値: H_Success, H_Parameter, H_P2, H_NotFound

ゲスト物理アドレスを指定して、そのアドレスにマッピングされているDRCインデックスとSCMブロックを返します。

H_SCM_UNBIND_ALL

入力: scmTargetScope, drcIndex
出力: なし
リターン値: H_Success, H_Parameter, H_P2, H_P3, H_In_Use, H_Busy,
H_LongBusyOrder1mSec, H_LongBusyOrder10mSec

ターゲットスコープに応じて、すべてのNVDIMMに属するSCMブロックまたは特定のdrcIndexを持つNVDIMMに属するすべてのSCMブロックをLPARメモリから解除します。

H_SCM_HEALTH

Input: drcIndex
出力: health-bitmap (r4), health-bit-valid-bitmap (r5)
リターン値: H_Success, H_Parameter, H_Hardware

DRCインデックスを指定して、PMEMデバイスの予測的な故障情報と全体的な健康状態に関する情報を返します。health-bitmap内のアサートされたビットは、PMEMデバイスおよび健康状態の状態（以下表に記載）を示し、health-bit-valid-bitmapはhealth-bitmap内の有効なビットを示します。ビットは逆順で報告されます。例えば、0xC400000000000000という値はビット0、1、5が有効であることを示します。

H_SCM_PERFORMANCE_STATS

入力: drcIndex, resultBufferアドレス
出力: なし
リターン値: H_Success, H_Parameter, H_Unsupported, H_Hardware, H_Authority, H_Privilege

DRCインデックスを指定して、NVDIMMのパフォーマンス統計情報を収集し、resultBufferにコピーします。
