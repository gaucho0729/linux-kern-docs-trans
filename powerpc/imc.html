基本概要¶

IMC (In-Memory collection counters) は、ネストレベル（チップ上にあるがコア外）、コアレベル、スレッドレベルで大量のハードウェアパフォーマンスイベントを収集するハードウェアモニタリング機能です。

ネストPMUカウンターは、OCC（On-Chip Controller）複合体内で実行されるネストIMCマイクロコードによって処理されます。マイクロコードはカウンターのデータを収集し、ネストIMCカウンターのデータをメモリに移動します。

コアおよびスレッドレベルのIMC PMUカウンターはコア内で処理されます。コアレベルPMUカウンターはコアごとのIMCカウンターのデータを提供し、スレッドレベルPMUカウンターはCPUスレッドごとのIMCカウンターのデータを提供します。

OPALはIMCカタログからIMC PMUおよびサポートされるイベント情報を取り出し、デバイスツリーを通じてカーネルに渡します。イベント情報には以下の項目が含まれます:

  • イベント名

  • イベントオフセット

  • イベント説明

また、以下の項目も含まれる場合があります:

  • イベントスケール

  • イベント単位

一部のPMUでは、サポートされるすべてのイベントに共通のスケールと単位値が存在する場合があります。その場合、これらのイベントのスケールと単位プロパティはPMUから継承される必要があります。

メモリ内のイベントオフセットは、カウンターのデータが蓄積される場所です。

IMCカタログは以下にあります:

https://github.com/open-power/ima-catalog

カーネルはデバイスツリー内の imc-counters デバイスノードで、互換性フィールド ibm,opal-in-memory-countersが設定されています。デバイスツリーから、カーネルはPMUとそのイベント情報の解析を行い、PMUとその属性をカーネルに登録します。

IMCの使用例¶

# perf list
[...]
nest_mcs01/PM_MCS01_64B_RD_DISP_PORT01/            [Kernel PMU event]
nest_mcs01/PM_MCS01_64B_RD_DISP_PORT23/            [Kernel PMU event]
[...]
core_imc/CPM_0THRD_NON_IDLE_PCYC/                  [Kernel PMU event]
core_imc/CPM_1THRD_NON_IDLE_INST/                  [Kernel PMU event]
[...]
thread_imc/CPM_0THRD_NON_IDLE_PCYC/                [Kernel PMU event]
thread_imc/CPM_1THRD_NON_IDLE_INST/                [Kernel PMU event]

nest_mcs0/PM_MCS_DOWN_128B_DATA_XFER_MC0/のチップごとのデータを確認するには:

# ./perf stat -e "nest_mcs01/PM_MCS01_64B_WR_DISP_PORT01/" -a --per-socket

コア0の非アイドル指令を確認するには:

# ./perf stat -e "core_imc/CPM_NON_IDLE_INST/" -C 0 -I 1000

makeコマンドの非アイドル指令を確認するには:

# ./perf stat -e "thread_imc/CPM_NON_IDLE_PCYC/" make

IMCトレースモード¶

POWER9はIMCに対して蓄積モードとトレースモードの2つのモードをサポートしています。蓄積モードでは、イベントカウントがシステムメモリに蓄積されます。ハイパーコアは定期的にまたはリクエスト時にポストされたカウントを読み取ります。IMCトレースモードでは、64ビットトレースSCOM値がイベント情報で初期化されます。トレースSCOM内のCPMCxSELとCPMC_LOADはモニタリングするイベントとサンプリング期間を指定します。CPMCxSELのオーバーフローごとに、ハードウェアがプログラムカウンターとイベントカウントをメモリに指定されたLDBAR先に書き込みます。

LDBARは、64ビットのスレッドごとの特別用途レジスタであり、ハードウェアが積算モードまたはトレースモードで構成されているかを示すビットを持っています。

CPMC_LOADにはサンプリング時間の長さが含まれています。SAMPSELおよびCPMCxSELはカウントするイベントを決定します。BUFFERSIZEはメモリ範囲を示します。オーバーフローごとにハードウェアがプログラムカウンタとイベントカウントをスナップショットを取り、メモリを更新し、次のサンプリング時間用にCPMC_LOADの値を再ロードします。IMCハードウェアは例外をサポートしていないため、メモリバッファが終端に達した場合は静かに巻き戻します。

現在、トレースモードで監視されるイベントは固定でサイクルです。

トレースIMCの使用例¶

# perf list
[....]
trace_imc/trace_cycles/                            [Kernel PMU event]

トレース-IMCイベントでアプリケーション/プロセスを記録するには:

# perf record -e trace_imc/trace_cycles/ yes > /dev/null
[ perf record: Woken up 1 times to write data ]
[ perf record: Captured and wrote 0.012 MB perf.data (21 samples) ]

以下の perf.data 生成され、perf reportを使用して読み込むことができます。

IMCトレースモードのメリット¶

PMI（パフォーマンスモニタリング割込み）の割込み処理は回避されています。これはIMCトレースモードがプログラムカウンタをスナップショットを取り、メモリに更新するためです。これにより、オペレーティングシステムがPMI処理のオーバーヘッドなしでリアルタイムでの指令サンプリングを行う方法も提供されます。

パフォーマンスデータの取得には perf top トレース-IMCイベントを含む場合と含まない場合の両方で可能です。

PMI割込みのカウントは、 perf top トレース-IMCイベントを含まない場合に実行されるコマンドで行われます。

# grep PMI /proc/interrupts
PMI:          0          0          0          0   Performance monitoring interrupts
# ./perf top
...
# grep PMI /proc/interrupts
PMI:      39735       8710      17338      17801   Performance monitoring interrupts
# ./perf top -e trace_imc/trace_cycles/
...
# grep PMI /proc/interrupts
PMI:      39735       8710      17338      17801   Performance monitoring interrupts

つまり、トレース_imcを使用している場合、PMI割込みのカウントは増加しません。 trace_imc イベント。
