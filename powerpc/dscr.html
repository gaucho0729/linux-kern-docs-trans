DSCR (データストリーム制御レジスタ)¶

powerpcでDSCRレジスタは、ユーザーがプロセッサ内のデータストリームのプリフェッチを制御できるようにします。詳細な使用方法については、ISAドキュメントまたは関連マニュアルを参照してください。このドキュメントでは、DSCRを用いたプリフェッチ制御のためのカーネルサポート、関連するカーネルオブジェクト、機能、およびエクスポートされたユーザーインターフェースについて概説します。

  1. データ構造:

    1. thread_struct:

      dscr            /* Thread DSCR value */
dscr_inherit    /* Thread has changed default DSCR */

    2. PACA:

      dscr_default    /* per-CPU DSCR default value */

    3. sysfs.c:

      dscr_default    /* System DSCR default value */

  2. スケジューラの変更:

    スケジューラは、スレッドがdscr_inherit値をクリアしている場合（つまり、これまでデフォルトのDSCRを変更していない場合）、CPUごとのDSCRデフォルト値（CPUのPACA値に保存されている）をレジスタに書き込みます。dscr_inherit値が設定されている場合（デフォルトのDSCRを変更している場合）、スケジューラはthread struct内のdscrに含まれる変更後の値をレジスタに書き込み、CPUごとのデフォルトのPACAベースのDSCR値ではなく、この変更後の値を使用します。

    注意: スケジューラのプロセスコンテキストスイッチでは、システム全体のグローバルDSCR値は一切直接使用されません。

  3. SYSFSインターフェース:

    • グローバルDSCRデフォルト: /sys/devices/system/cpu/dscr_default

    • CPU固有のDSCRデフォルト: /sys/devices/system/cpu/cpuN/dscr

    sysfsでグローバルDSCRデフォルトを変更すると、すべてのCPU固有のDSCRデフォルトが直ちにPACA構造体内で更新されます。現在のプロセスがdscr_inheritをクリアしている場合、新しい値がすべてのCPUのDSCRレジスタに即座に書き込まれ、現在のスレッドのDSCR値も更新されます。

    sysfsでCPU固有のDSCRデフォルト値を変更すると、上記と同じ動作を行います。ただし、グローバルの場合とは異なり、この変更は特定のCPUに対してのみ適用されます。

  4. ユーザー空間での指示:

    DSCRレジスタは、この目的に用意された2つのSPR番号を用いてユーザー空間からアクセスできます。

    1. 問題状態SPR: 0x03 (非特権、POWER8のみ)

    2. 特権状態SPR: 0x11 (特権)

    ユーザー空間から特権SPR番号（0x11）を介してDSCRにアクセスすることは可能で、これはカーネル内で不正指令例外を発生させた後、エミュレートされるためです。mfsprおよびmtspr命令もエミュレートされます。

    ユーザー空間からユーザーレベルのSPR（0x03）を通じてDSCRにアクセスすると、最初にファシリティが利用不可例外が発生します。この例外ハンドラ内で、mfspr指令ベースの読み取り試行はエミュレートされ返却され、最初のmtspr指令ベースの書き込み試行は、次回以降（読み取りおよび書き込みのいずれも）にDSCRファシリティを有効化するためにFSCRレジスタにDSCRファシリティを設定します。

  5. 「dscr_inherit」についての詳細:

    スレッド構造体要素「dscr_inherit」は、該当スレッドが以下のいずれかの方法を用いてDSCR自体を変更したかを表します。この要素は、カーネルにおいてCPUデフォルトのDSCR値を使用するか、自身の変更後のDSCR値を使用するかを示します。

    1. mtspr指令（SPR番号0x03）

    2. mtspr指令（SPR番号0x11）

    3. ptraceインターフェース（ユーザーDSCR値を明示的に設定）

    このイベント以降に作成されるプロセスの子プロセスも、この同じ挙動を継承します。
