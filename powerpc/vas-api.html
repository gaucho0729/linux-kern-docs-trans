仮想アクセラレータスイッチボード (VAS) ユーザースペース API¶

はじめに¶

Power9プロセッサはバーチャルアクセラレータスイッチボード（VAS）を導入し、ユーザー空間とカーネルがハードウェアアクセラレータ（ネストアクセラレータ（NX）と呼ばれるコプロセッサ）と通信できるようにしています。NXユニットは、842圧縮、GZIP圧縮、暗号化などの1つまたは複数のハードウェアエンジンまたはコプロセッサタイプから構成されます。Power9では、ユーザー空間アプリケーションはハードウェアでZLIBおよびGZIP圧縮アルゴリズムをサポートするGZIP圧縮エンジンにのみアクセス可能となります。

NXと通信するには、カーネルがチャネルまたはウィンドウを確立し、その後カーネルの関与なしに直接リクエストを送信する必要があります。GZIPエンジンへのリクエストは、コプロセッサリクエストブロック（CRB）としてフォーマットされ、これらのCRBはCOPY/PASTE命令を使用してNXに送信され、エンジンのリクエストキューに関連するハードウェアアドレスにCRBがペーストされます。

GZIPエンジンは2つの優先度レベルのリクエストを提供しています：通常と高優先度。現在はユーザー空間から通常リクエストのみがサポートされています。

このドキュメントでは、カーネルと通信してチャネル/ウィンドウを設定し、直接NXアクセラレータに圧縮リクエストを送信できるようにするユーザースペースAPIについて説明します。

概要¶

GZIPエンジンへのアプリケーションアクセスは、VAS/NXデバイスドライバーによって実装された/dev/crypto/nx-gzipデバイスノードを通じて提供されます。アプリケーションは、/dev/crypto/nx-gzipデバイスを開いてファイルディスクリプタ（fd）を取得する必要があります。その後、このfdを使用してVAS_TX_WIN_OPEN ioctlを実行し、エンジンとの接続を確立します。これは、このプロセスに対してGZIPエンジンの送信ウィンドウが開かれたことを意味します。接続が確立されると、アプリケーションはmmap()システムコールを使用して、エンジンのリクエストキューのハードウェアアドレスをアプリケーションの仮想アドレス空間にマッピングする必要があります。

アプリケーションは、copy/paste命令を使用して1つまたは複数のリクエストをエンジンに送信できます。この場合、mmap()によって返された仮想アドレス（つまりpaste_address）にCRBをペーストします。ユーザー空間は、ファイルディスクリプタを閉じる（close(fd)）ことにより確立した接続または送信ウィンドウを閉じることができます。または、プロセスの終了時に自動的に閉じます。

アプリケーションは、同じウィンドウで複数のリクエストを送信したり、複数のウィンドウを確立したりできますが、各ファイルディスクリプタに対して1つのウィンドウのみが存在します。

次のセクションでは、個々のステップに関する追加の詳細情報と参照が提供されています。

NX-GZIPデバイスノード¶

システムには1つの/dev/crypto/nx-gzipノードがあり、これはシステム内のすべてのGZIPエンジンへのアクセスを提供します。/dev/crypto/nx-gzipに対して有効な操作は以下の通りです。

  • 読み取りと書き込みのためにデバイスを開きます。

  • VAS_TX_WIN_OPEN ioctlを実行します。

  • エンジンのリクエストキューをアプリケーションの仮想アドレス空間にmmap()して、コプロセッサエンジンのpaste_addressを取得します。

  • デバイスノードを閉じます。

このデバイスノードに対する他のファイル操作は未定義です。

コピーおよびペースト操作はハードウェアに直接送信され、このデバイスを通じて行われません。詳細についてはCOPY/PASTEドキュメントを参照してください。

システムには複数のNXコプロセッサエンジンのインスタンスがある場合があります（通常はP9チップごとに1つ）が、システム全体で1つの/dev/crypto/nx-gzipデバイスノードのみが存在します。nx-gzipデバイスノードを開くと、カーネルが適切なNXアクセラレータインスタンスの送信ウィンドウを開きます。実行中のユーザープロセスのCPUを特定し、そのCPUが属するチップに対応するNXインスタンスを決定します。

アプリケーションは以下の説明に従って、VAS_TX_WIN_OPEN ioctlのvas_idフィールドを使用して特定のNXコプロセッサインスタンスを選択できます。

ユーザー空間ライブラリlibnxzは以下にありますが、まだ開発中です：

https://github.com/abalib/power-gzip

インフレート/デフロート呼び出しを使用するアプリケーションは、libzではなくlibnxzとリンクし、NX GZIP圧縮を使用できます。これにより、コードの変更は必要ありません。

/dev/crypto/nx-gzipを開きます¶

nx-gzipデバイスは読み取りと書き込みのために開く必要があります。デバイスを開くには特別な権限は必要ありません。各ウィンドウは1つのファイルディスクリプタに対応するため、ユーザー空間プロセスが複数のウィンドウが必要な場合は、複数のopen呼び出しが必要です。

他の詳細（返却値、エラーコード、制限など）についてはopen(2)システムコールのmanページを参照してください。

VAS_TX_WIN_OPEN ioctl¶

NXコプロセッサエンジンと接続を確立するには、以下の通りVAS_TX_WIN_OPEN ioctlを使用してください。

struct vas_tx_win_open_attr {
        __u32   version;
        __s16   vas_id; /* specific instance of vas or -1
                                for default */
        __u16   reserved1;
        __u64   flags;  /* For future use */
        __u64   reserved2[6];
};
バージョン:

バージョンフィールドは現在1に設定する必要があります。

vas_id:

'-1'を渡すと、カーネルがプロセスに最適なNXインスタンスをベストエフォートで割り当てます。特定のVASインスタンスを選択するには、「利用可能なVASエンジンの発見」セクションを参照してください。

flags、reserved1およびreserved2[6]フィールドは今後の拡張用であり、0に設定する必要があります。

VAS_TX_WIN_OPEN ioctlの属性attrは以下の通り定義されています：

#define VAS_MAGIC 'v'
#define VAS_TX_WIN_OPEN _IOW(VAS_MAGIC, 1,
                                struct vas_tx_win_open_attr)

struct vas_tx_win_open_attr attr;
rc = ioctl(fd, VAS_TX_WIN_OPEN, &attr);

VAS_TX_WIN_OPEN ioctlは成功時に0を返します。エラーの場合、-1を返し、errno変数にエラーを示します。

エラー条件：

EINVAL

fdが有効なVASデバイスを参照していません。

EINVAL

無効なvas ID

EINVAL

バージョンが適切な値に設定されていません

EEXIST

指定された fd に対してウィンドウがすでに開かれています

ENOMEM

メモリが不足してウィンドウの割り当てができません

ENOSPC

システムにアクティブなウィンドウ（接続）が多すぎます

EINVAL

予約済みフィールドが 0 に設定されていません

詳細情報やエラーコード、制限事項については ioctl(2) マニュアルページを参照してください

mmap() NX-GZIP デバイス¶

NX-GZIP デバイス fd の mmap() システムコールは、アプリケーションが CRB をハードウェアエンジンにコピー/ペーストするための paste_address を返します

paste_addr = mmap(addr, size, prot, flags, fd, offset);

NX-GZIP デバイス fd における mmap() に関する制限は次の通りです:

  • サイズは PAGE_SIZE にする必要があります

  • オフセットパラメータは 0ULL にする必要があります

mmap(2) マニュアルページを参照してください。mmap(2) マニュアルページに記載されているエラー条件に加えて、以下のエラーコードのいずれかで失敗する場合があります:

EINVAL

fd が開いているウィンドウと関連付けられていない場合（つまり、VAS_TX_WIN_OPEN ioctl の成功した呼び出し後に mmap() が呼ばれていない場合）

EINVAL

オフセットフィールドが 0ULL になっていない場合

利用可能な VAS エンジンの検出¶

システム内の各利用可能な VAS インスタンスは、/proc/device-tree/vas@* または /proc/device-tree/xscom@*/vas@* のようなデバイスツリーのノードを持っています。チップまたは VAS インスタンスを特定し、このノード内の対応する ibm,vas-id プロパティ値を使用して特定の VAS インスタンスを選択してください

コピー/ペースト操作¶

アプリケーションは、CRB を NX に送信するためにコピー/ペースト命令を使用する必要があります。PowerISA のセクション 4.4 を参照してください: https://openpowerfoundation.org/?resource_lib=power-isa-version-3-0

CRB 指定と NX の使用¶

アプリケーションは、共処理機器にリクエストを送信する際、共処理機器リクエストブロック（CRB）を使用してフォーマットする必要があります。CRB の形式については NX-GZIP ユーザーマニュアルを参照し、ユーザー空間から NX を使用してリクエストを送信し、リクエストの状態を確認してください

NX フォールト処理¶

アプリケーションは NX にリクエストを送信し、共処理機器ステータスブロック（CSB）のフラグをポーリングしてステータスを待機します。NX は各リクエストの処理後に CSB にステータスを更新します。CSB の形式およびステータスフラグについては NX-GZIP ユーザーマニュアルを参照してください

NX が CSB アドレスまたは任意のリクエストバッファで翻訳エラー（NX ページフォールトと呼ばれる）を検出すると、CPU に割り込みを発生させ、フォールトを処理します。アプリケーションが無効なアドレスを渡すか、リクエストバッファがメモリに存在しない場合、ページフォールトが発生します。オペレーティングシステムは、以下のデータで CSB を更新してフォールトを処理します:

csb.flags = CSB_V;
csb.cc = CSB_CC_FAULT_ADDRESS;
csb.ce = CSB_CE_TERMINATION;
csb.address = fault_address;

アプリケーションが翻訳エラーを受信した場合、フォールトアドレスを持つページにアクセスまたは操作することで、このページがメモリに存在するようにします。その後、アプリケーションはこのリクエストを NX に再送信できます

OSが無効なCSBアドレスのためCSBを更新できなくなった場合、元のリクエストが送信された送信窓を開いたプロセスにSEGVシグナルを送信します。このシグナルは以下のsiginfo構造体と共に返されます:

siginfo.si_signo = SIGSEGV;
siginfo.si_errno = EFAULT;
siginfo.si_code = SEGV_MAPERR;
siginfo.si_addr = CSB adress;

マルチスレッドアプリケーションの場合、NX送信窓はすべてのスレッド間で共有可能です。たとえば、子スレッドが送信窓を開いた場合でも、他のスレッドはこの窓を使用してNXにリクエストを送信できます。CSBアドレスが有効である限り、OSのハンドリングエラーでもリクエストは成功します。NXリクエストに無効なCSBアドレスが含まれる場合、シグナルは窓を開いた子スレッドに送信されます。ただし、スレッドが窓を閉じることなく終了し、この窓を使用してリクエストを発行した場合、シグナルはスレッドグループリーダー (tgid) に送信されます。これらのシグナルはアプリケーションが無視するか処理するかをアプリケーションが決定します。

NX-GZIP ユーザーマニュアル: https://github.com/libnxz/power-gzip/blob/master/power_nx_gzip_um.pdf

シンプルな例¶

int use_nx_gzip()
{
        int rc, fd;
        void *addr;
        struct vas_setup_attr txattr;

        fd = open("/dev/crypto/nx-gzip", O_RDWR);
        if (fd < 0) {
                fprintf(stderr, "open nx-gzip failed\n");
                return -1;
        }
        memset(&txattr, 0, sizeof(txattr));
        txattr.version = 1;
        txattr.vas_id = -1
        rc = ioctl(fd, VAS_TX_WIN_OPEN,
                        (unsigned long)&txattr);
        if (rc < 0) {
                fprintf(stderr, "ioctl() n %d, error %d\n",
                                rc, errno);
                return rc;
        }
        addr = mmap(NULL, 4096, PROT_READ|PROT_WRITE,
                        MAP_SHARED, fd, 0ULL);
        if (addr == MAP_FAILED) {
                fprintf(stderr, "mmap() failed, errno %d\n",
                                errno);
                return -errno;
        }
        do {
                //Format CRB request with compression or
                //uncompression
                // Refer tests for vas_copy/vas_paste
                vas_copy((&crb, 0, 1);
                vas_paste(addr, 0, 1);
                // Poll on csb.flags with timeout
                // csb address is listed in CRB
        } while (true)
        close(fd) or window can be closed upon process exit
}
