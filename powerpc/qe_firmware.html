I - ファームウェア用ソフトウェアライセンス¶

各ファームウェアファイルには独自のソフトウェアライセンスが付属しています。特定のライセンスに関する情報は、ファームウェアとともに配布されるライセンステキストをご参照ください。

II - マイクロコードの利用可能性¶

ファームウェアファイルはさまざまなチャネルを通じて配布されています。一部は http://opensource.freescale.com他のファームウェアファイルについては、Freescaleの担当者またはお使いのオペレーティングシステムベンダーにご相談ください。

III - 説明と用語¶

このドキュメントでは、「microcode（マイクロコード）」という用語は、実際のQEマイクロコードを構成する32ビット整数のシーケンスを指します。

「firmware（ファームウェア）」という用語は、マイクロコードおよびその他のデータを含むバイナリーブロブを指します。

  1. マイクロコードの目的を記述します

  2. マイクロコードをアップロードする方法と場所を記述します

  3. さまざまなレジスタの値を指定します

  4. 特定のデバイスドライバーで使用する追加データを含みます

ファームウェアファイルは、ファームウェアのみを含むバイナリーファイルです。

IV - マイクロコードプログラミングの詳細¶

QEアーキテクチャでは、各RISCプロセッサに対してI-RAMに存在するマイクロコードは1つだけです。現在のマイクロコードを置き換えるには、まず完全なQEリセット（マイクロコードを無効にする）を行わなければなりません。

QEマイクロコードは以下の手順でアップロードされます：

  1. マイクロコードは、IRAM.IADDおよびIRAM.IDATAレジスタを使用して特定の場所にI-RAMに配置されます。

  2. CERCR.CIRビットは、ファームウェアが分割I-RAMを必要とするかどうかに応じて0または1に設定されます。分割I-RAMは、複数のRISCプロセッサを持つQEを搭載したSOC（例：8360）においてのみ意味があります。I-RAMを分割することで、各プロセッサが異なるマイクロコードを実行できるため、非対称マルチプロセッシング（AMP）システムを効果的に構築できます。

  3. TIBCRトラップレジスタは、マイクロコード内のトラップハンドラのアドレスで初期化されます。

  4. RSP.ECCRレジスタは、提供された値でプログラミングされます。

  5. 必要に応じて、仮想トラップおよび拡張モードデータを使用するデバイスドライバーはそれらを使用します。

仮想マイクロコードトラップ

これらの仮想トラップは、マイクロコード内の条件分岐です。これらはROMコードで導入された「soft」プロビジョナルであり、より高い柔軟性を実現し、ハードウェアトラップを節約するために導入されました。新しい機能が有効化されたり、RAMパッケージで問題が修正されている場合、これらを有効にする必要があります。このデータ構造は、マイクロコードにこれらの仮想トラップのうちどれが有効かを通知します。

V - ファームウェア構造レイアウト¶

ファーレスケールのQEマイクロコードは通常ヘッダーファイルとして提供されます。このヘッダーファイルには、マイクロコードのバイナリ自体を定義するマクロおよびマイクロコードをアップロードする際の他のデータが含まれています。これらのファイルの形式は他のコードへの簡単なインクルードには不向きであり、よりポータブルな形式が必要です。このセクションではその形式を定義しています。

ヘッダーファイルを配布する代わりに、マイクロコードおよび関連データはバイナリ・ブループリントに埋め込まれます。このブループリントはqe_upload_firmware()関数に渡され、関数はブループリントを解析し、マイクロコードをアップロードするために必要なすべての処理を行います。

すべての整数はビッグエンディアンです。qe_upload_firmware()関数のコメントを参照してください。最新の実装情報が記載されています。

この構造体はバージョン管理をサポートしており、構造体のバージョンは構造体自身に埋め込まれています。前後互換性を確保するため、すべてのバージョンの構造体は開始部に同じ「qe_header」構造体を使用する必要があります。

「header」（型: struct qe_header）:

「length」フィールドは、この構造体全体のサイズ（バイト単位）を表し、含まれるすべてのマイクロコードおよびCRC（存在する場合）を含むサイズを示します。

「magic」フィールドは、文字「Q」、「E」、「F」を含む3バイトの配列です。これはこの構造体がQEファームウェア構造体であることを示す識別子です。

「version」フィールドは、この構造体のバージョンを示す1バイトです。構造体のレイアウトが変更される必要がある場合（追加のマイクロコードタイプへの対応を含む）、バージョン番号も変更する必要があります。

「id」フィールドは、NULL終端文字列（印刷用に適した形式）であり、ファームウェアを識別します。

「count」フィールドは「microcode」構造体の数を示します。それぞれのRISCプロセッサには1つずつ「microcode」構造体が存在しなければならないため、このフィールドはこのSOCのRISCプロセッサの数を表しています。

‘soc’構造体には、マイクロコードを該当するSOC自身と一致させるために使用されるSOC番号およびリビジョンが含まれています。通常、マイクロコードロー�ーダーはこの構造体のデータとSOC番号およびリビジョンを比較し、一致した場合のみマイクロコードをアップロードする必要があります。ただし、このチェックはすべてのプラットフォームで行われません。

推奨されませんが、soc.modelフィールドに‘0’を指定することで、SOCの一致を完全にスキップできます。

‘model’フィールドは、実際のSOCと一致する16ビットの数値です。‘major’および‘minor’フィールドはそれぞれSOCのメジャーリビジョンおよびマイナーリビジョン番号を表します。

たとえば、8323、リビジョン1.0を一致させる場合:

soc.model = 8323
soc.major = 1
soc.minor = 0

‘padding’は構造体のアライメントに必要です。このフィールドは‘extended_modes’フィールドが64ビット境界にアライメントされるようにします。

‘extended_modes’は、デバイスドライバに影響を与える特別な機能を定義するビットフィールドです。各ビットはそれぞれドライバに特有の特殊な指示を持ち、このフィールドはQEライブラリに保存されており、qe_get_firmware_info()を呼び出すすべてのドライバに利用可能です。

‘vtraps’は、各仮想トラップに対応する仮想トラップ値を含む8ワードの配列です。‘extended_modes’と同様に、このフィールドはQEライブラリに保存されており、qe_get_firmware_info()を呼び出すすべてのドライバに利用可能です。

‘microcode’（型: struct qe_microcode）:

各RISCプロセッサに対して1つの‘microcode’構造体があります。最初の‘microcode’構造体は最初のRISCに、次は次のRISCに該当します。

‘id’フィールドは、この特定のマイクロコードを識別するためのNULL終端文字列であり、印刷用に適しています。

‘traps’は、16つのトラップそれぞれに対応するハードウェアトラップ値を含む16ワードの配列です。trap[i]が0の場合、そのトラップは無視されます（つまり、TIBCR[i]に書き込まれません）。全体の値はTIBCR[i]レジスタにそのまま書き込まれるため、必要に応じてENおよびT_IBPビットを設定してください。

‘eccr’はECCRレジスタにプログラミングする値です。

‘iram_offset’はマイクロコードを開始して書き込むIRAM内のオフセットです。

‘count’はマイクロコード内の32ビットワードの数です。

‘code_offset’は、この構造体の開始位置からマイクロコード自体が見つかるオフセット（バイト単位）です。最初のマイクロコードバイナリは‘microcode’配列の直後に配置される必要があります。

‘major’、‘minor’、‘revision’はそれぞれマイクロコードのメジャーバージョン、マイナーバージョン、リビジョン番号を表します。すべての値が0の場合、これらのフィールドは無視されます。

‘reserved’は構造のアライメントに必要です。‘microcode’が配列であるため、64ビットの‘extended_modes’フィールドは64ビット境界にアライメントする必要があります。これは‘microcode’のサイズが8バイトの倍数である場合にのみ起こるため、その条件を満たすために‘reserved’を追加します。

最後のマイクロコードの後に32ビットのCRCがあります。これはこのアルゴリズムを使用して計算できます。

u32 crc32(const u8 *p, unsigned int len)
{
      unsigned int i;
      u32 crc = 0;

      while (len--) {
         crc ^= *p++;
         for (i = 0; i < 8; i++)
                 crc = (crc >> 1) ^ ((crc & 1) ? 0xedb88320 : 0);
      }
      return crc;
}
