8.1. はじめに¶

このモジュールは、入力ドライバ開発者が各種serioデバイス（特にラップトップに搭載されているさまざまなタッチパッド）をテストする際の作業を簡略化することを目的としています。物理的なデバイスを手元に持つ必要なく、ユーザー空間の特権プログラムがカーネルのserioドライバと直接やりとりし、仮想serioポートを制御できるようにします。

8.2. 使用概要¶

userioカーネルモジュールとやりとりするには、アプリケーションで/dev/userioキャラクタデバイスを開くだけです。コマンドはデバイスに書き込むことで送信され、serioドライバから受信したデータは/dev/userioデバイスからそのまま読み取れます。デバイスとやりとりするための構造体やマクロは<linux/userio.h>および<linux/serio.h>に定義されています。

8.3. コマンド構造¶

コマンドを/dev/userioに送信するために使用される構造体は以下の通りです：

struct userio_cmd {
        __u8 type;
        __u8 data;
};

type 送信するコマンドのタイプを記述します。これは<linux/userio.h>で定義されたUSERIO_CMDマクロのいずれかです。 data コマンドに伴う引数です。コマンドに引数がない場合はこのフィールドは無視されますが、カーネルは無視します。コマンドを送信する際は構造体を直接キャラクタデバイスに書き込みます。送信したコマンドが無効な場合、キャラクタデバイスはエラーを返し、カーネルログにより詳細なエラーが表示されます。一度に1つのコマンドのみを送信可能です。初期のコマンド送信後にキャラクタデバイスに追加で書き込まれたデータは無視されます。

仮想serioポートを閉じるには、/dev/userioを閉じるだけです。

8.4. コマンド¶

8.4.1. USERIO_CMD_REGISTER¶

serioドライバにポートを登録し、データのやりとりを開始します。登録はポートタイプがUSERIO_CMD_SET_PORT_TYPEで設定された後のみ可能です。引数はありません。

8.4.2. USERIO_CMD_SET_PORT_TYPE¶

エミュレートするポートのタイプを設定します。ここで data 設定されるポートタイプです。<linux/serio.h>のマクロのいずれかです。例えば：SERIO_8042は通常のPS/2ポートを設定します。

8.4.3. USERIO_CMD_SEND_INTERRUPT¶

仮想serioポートを通じてserioドライバに割込みを送信します。ここで data 送信される割込みデータです。

8.5. ユーザースペースツール¶

userioユーザースペースツールは、i8042から得られる一部のデバッグ情報を用いてPS/2デバイスを記録し、/dev/userioでデバイスを再生できます。これらのツールの最新バージョンは以下から取得できます:

https://github.com/Lyude/ps2emu
