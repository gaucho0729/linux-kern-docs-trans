2. ゲームポートドライバのプログラミング¶

2.1. 基本的なクラシックなゲームポート¶

ゲームポートが inb()/outb() の機能しか提供しない場合、ジョイスティックドライバに登録するためのコードはシンプルです：

struct gameport gameport;

gameport.io = MY_IO_ADDRESS;
gameport_register_port(&gameport);

struct gameport は他のフィールドをすべて 0 に初期化してください。ゲームポートの汎用コードが残りの処理を行います。

ハードウェアが複数の io アドレスをサポートする場合、ドライバがハードウェアをどのアドレスでプログラミングするかを選べるなら、より非標準的なアドレスから開始するのが望ましいです。標準の 0x201 アドレスと衝突する可能性が小さくなります。

例として、ドライバが 0x200、0x208、0x210、0x218 のアドレスをサポートする場合、0x218 が最初の選択肢になります。

ゲームポートアドレスが ISA io スペースにマッピングされていない（0x1000 以上）場合、そのアドレスを使用し、ISA ミラーをマッピングしないでください。

また、ゲームポートが占める io スペース全体に対して request_region() を必ず呼び出してください。実際には1つの ioport しか使用されないものの、ゲームポートは通常 io スペース内で1〜16個のアドレスを占めます。

さらに、io が ISA スペースにマッピングされている場合、->open() コールバックでゲームポートを有効化することをお勧めします。これにより、実際に使用されるまで io スペースを占有しません。->close() コールバックで再度無効化してください。また、->open() コールバック内で io アドレスを選択できるため、他のゲームポートが既に使用しているアドレスでも失敗せずに動作します。

2.2. メモリマップされたゲームポート¶

ゲームポートが MMIO でアクセス可能である場合、この方法が推奨されます。なぜなら、この方法は高速で、毎秒の読み取り数がより多くなるからです。このようなゲームポートを登録するには、基本的な IO に比べて少し複雑ですが、それほど難しくありません：

struct gameport gameport;

void my_trigger(struct gameport *gameport)
{
        my_mmio = 0xff;
}

unsigned char my_read(struct gameport *gameport)
{
        return my_mmio;
}

gameport.read = my_read;
gameport.trigger = my_trigger;
gameport_register_port(&gameport);

2.3. コックドモードのゲームポート¶

軸の値を数値として報告できるゲームポートがあります。つまり、ドライバは古い方法で測定する必要がなく、ゲームポートにADCが内蔵されているためです。このようなコックドゲームポートを登録するには：

struct gameport gameport;

int my_cooked_read(struct gameport *gameport, int *axes, int *buttons)
{
        int i;

        for (i = 0; i < 4; i++)
                axes[i] = my_mmio[i];
        buttons[i] = my_mmio[4];
}

int my_open(struct gameport *gameport, int mode)
{
        return -(mode != GAMEPORT_MODE_COOKED);
}

gameport.cooked_read = my_cooked_read;
gameport.open = my_open;
gameport.fuzz = 8;
gameport_register_port(&gameport);

ここでの唯一の混乱点は fuzz 値です。これは ADC データ内のノイズ量を表し、実験によって最適値を決定します。理想的なゲームポートはこの値をゼロに設定できますが、一般的なものは 8 〜 32 の間です。アナログ処理や入力処理の fuzz 値の扱いについては analog.c と input.c を参照してください。fuzz 値はガウシアンフィルタのウィンドウサイズを決定し、データのノイズを除去します。

2.4. より複雑なゲームポート¶

Gameportsはrawモードおよびcookedモードの両方をサポートします。その場合、例1+2または例1+3を組み合わせて使用してください。Gameportsは内部キャリブレーションをサポートします - 以下を参照してください。また、lightning.cおよびanalog.cもその仕組みについて説明しています。ドライバが複数のgameportインスタンスを同時にサポートする場合、gameport構造体の->privateメンバにデータを指すようにしてください。

2.5. gameportの登録解除¶

シンプルな方法:

gameport_unregister_port(&gameport);

2.6. gameport構造体¶

注意

このセクションは古くなった。ここにあるいくつかのフィールドは、include/linux/gameport.hにあるものと一致していません。

struct gameport {

    void *private;

gameportドライバで自由に使用可能なプライベートポインタ。(ジョystickドライバではありません！)

int number;

gameportが登録されたときに割り当てられた番号。情報目的のみです。

int io;

rawモードで使用するI/Oアドレス。rawモードをサポートするgameportの場合、この値を設定するか、->read()を何らかの値に設定してください。

int speed;

gameportのrawモード読み取り速度（秒あたりの読み取り数で千単位）。

int fuzz;

gameportがcookedモードをサポートする場合、この値をデータ内のノイズ量を表す値に設定してください。参照: コックドモードのゲームポート.

void (*trigger)(struct gameport *);

トリガー。この関数はns558のワンショットをトリガーする必要があります。NULLに設定されている場合、outb(0xff, io)が使用されます。

unsigned char (*read)(struct gameport *);

ボタンとns558ワンショットビットを読み込む。NULLに設定されている場合、inb(io)が代わりに使用されます。

int (*cooked_read)(struct gameport *, int *axes, int *buttons);

gameportがcookedモードをサポートする場合、このポインタを加熱読取関数に設定してください。axes[0..3]にジョystickの軸4つの値を、buttons[0]に4ビットのボタン状態を設定してください。

int (*calibrate)(struct gameport *, int *axes, int *max);

ADCハードウェアのキャリブレーションを行う関数。呼び出される際、callerがaxes[0..3]を加熱データで事前に埋め、max[0..3]に各軸の予想最大値を事前に埋めます。calibrate()関数はADCハードウェアの感度を調整し、最大値が範囲内になるようにし、axes[]値を新しい感度に合わせて再計算するか、ハードウェアから再読み込みして有効な値にする必要があります。

int (*open)(struct gameport *, int mode);

open()は2つの目的を持っています。まず、ドライバがポートをrawモードまたはcookedモードで開くことができ、open()コールバックがサポートするモードを決定します。次に、リソースの割り当てがここで行われます。ポートもここで有効化できます。この呼び出し以前に、gameport構造体の他のフィールド（特にioメンバ）は有効である必要はありません。

void (*close)(struct gameport *);

close()はopen()で割り当てたリソースを解放し、gameportを無効化する可能性があります。

struct gameport_dev *dev;
struct gameport *next;

gameportレイヤー内で内部的に使用します。

};

楽しんでください！
