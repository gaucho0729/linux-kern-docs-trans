6.6. プログラミングインターフェース¶

著者

ラーグナル・ホイランド・エスピノーサ <ragnar@macula.net> - 7月1998年

6.6.1. はじめに¶

重要です。

このドキュメントは、非推奨の js インターフェースについて説明しています。新しいクライアントは、ジェネリックなイベント（evdev) インターフェースに切り替えることを推奨します。

1.0ドライバは、ジョystickドライバに対して新しいイベントベースのアプローチを使用しています。ユーザーのプログラムがジョystickの値をポーリングする代わりに、ジョystickドライバは現在の状態の変化のみを報告します。詳細については、joystickパッケージに含まれるjoystick-api.txt、joystick.h、jstest.cを参照してください。ジョystickデバイスはブロッキングモードまたはノンブロッキングモードのいずれかで使用でき、select()コールをサポートしています。

後方互換性のために、古い(v0.x)インターフェースはまだ含まれています。古いインターフェースを使用してジョystickドライバに呼び出しが行われると、古いインターフェースと互換性のある値が返されます。このインターフェースはまだ最大2軸に制限されており、使用するアプリケーションは通常2つのボタンのみをデコードしますが、ドライバは最大32個のボタンを提供します。

6.6.2. 初期化¶

通常のセマンティクスに従ってジョystickデバイスを開きます（つまり、openを使用します）。ドライバが変化をポーリングする代わりにイベントを報告するようになったため、open直後に一連の合成イベント(JS_EVENT_INIT)が発行され、それらを読み取ることでジョystickの初期状態を取得できます。

デフォルトでは、デバイスはブロッキングモードで開かれます:

int fd = open ("/dev/input/js0", O_RDONLY);

6.6.3. イベントの読み込み¶

struct js_event e;
read (fd, &e, sizeof(e));

js_eventは次のようになります:

struct js_event {
        __u32 time;     /* event timestamp in milliseconds */
        __s16 value;    /* value */
        __u8 type;      /* event type */
        __u8 number;    /* axis/button number */
};

読み取りが成功した場合、sizeof(e)が返されます。ただし、セクション3.1で説明したように、1回の読み取りで複数のイベントを読み取る場合はその分だけ返されます。

6.6.3.1. js_event.type¶

js_event.typeの可能な値は type は:

#define JS_EVENT_BUTTON         0x01    /* button pressed/released */
#define JS_EVENT_AXIS           0x02    /* joystick moved */
#define JS_EVENT_INIT           0x80    /* initial state of device */

上記のように、ドライバはオープン時に合成JS_EVENT_INIT ORされたイベントを発行します。つまり、INIT BUTTONイベントを発行している場合、現在のtype値は以下の通りです:

int type = JS_EVENT_BUTTON | JS_EVENT_INIT;     /* 0x81 */

合成イベントと実イベントを区別しない場合は、JS_EVENT_INITビットをオフにできます:

type &= ~JS_EVENT_INIT;                         /* 0x01 */

6.6.3.2. js_event.number¶

js_event.numberの値は number イベントを生成した軸またはボタンに対応します。注意点として、これらはそれぞれ別の番号付けを行います（つまり、軸0とボタン0の両方が存在します）。一般的に、

軸

番号

1番目の軸X

0

1番目の軸Y

1

2番目の軸X

2

2番目の軸Y

3

…といった具合です

ハットはジョystickの種類によって異なります。一部は8方向に動かせ、一部は4方向に動かせます。しかし、ドライバはハットを常に2つの独立した軸として報告します。ハードウェアが独立した移動を許可しない場合でもです。

6.6.3.3. js_event.value¶

軸の場合、 value は、-32767から+32767までの符号付き整数であり、ジョystickがその軸に沿った位置を表します。ジョystickが dead、またはその範囲を満たしていない場合、再校正を行う必要があります（たとえば、jscaleを使用して）。

ボタンの場合、 value 押下ボタンイベントの場合1、リリースボタンイベントの場合0です。

ただし、

if (js_event.type == JS_EVENT_BUTTON) {
        buttons_state ^= (1 << js_event.number);
}

JS_EVENT_INITイベントを個別に処理すればうまく動作しますが、

if ((js_event.type & ~JS_EVENT_INIT) == JS_EVENT_BUTTON) {
        if (js_event.value)
                buttons_state |= (1 << js_event.number);
        else
                buttons_state &= ~(1 << js_event.number);
}

ドライバとの同期を失うことがないためより安全です。最初のコード例ではJS_EVENT_INITイベントに個別のハンドラを書く必要があるため、この方法の方が短くなります。

6.6.3.4. js_event.time¶

イベントが生成された時間は js_event.timeに保存されています。これは過去のどこかの時点からのミリ秒単位の時間です。これにより、ダブルクリックの検出や、軸の移動とボタン押下が同時に発生したかの判定など、タスクが簡単になります。

6.6.4. 読み込み¶

ブロッキングモードでデバイスを開くと、読み込みがブロック（つまり、待機）し、イベントが生成されるまで永遠に待機します。永遠に待機できない場合（これは、確かに長い時間です）、2つの代替案があります。

  1. fdにデータが読み込まれるのを待つか、タイムアウトするまでselectを使用します。select(2)のmanページには良い例があります。

  2. ノンブロッキングモードでデバイスを開きます（O_NONBLOCK）

6.6.4.1. O_NONBLOCK¶

O_NONBLOCKモードで読み込みを行うとreadが-1を返す場合、必ずしも「実際の」エラーではありません（errno(3)を確認してください）。これは、ドライバのキューに待機中のイベントがいないことを意味するだけです。キュー内のすべてのイベントを読み取るべきです（つまり、-1を受けるまで）。

例えば、

while (1) {
        while (read (fd, &e, sizeof(e)) > 0) {
                process_event (e);
        }
        /* EAGAIN is returned when the queue is empty */
        if (errno != EAGAIN) {
                /* error */
        }
        /* do something interesting with processed events */
}

キューを空にする理由の一つは、キューが満杯になるとイベントを欠くことになり、古いイベントが上書きされるからです。

もう一つの理由は、すべての出来事を把握したいこと、および処理を後回しにしたくないことです。

キューが満杯になるのはなぜですか？それは、前述の通りキューを空にしていないから、または1回の読み込みから次の読み込みまでの時間が長すぎて、キューに保存できるイベントが多すぎるからです。高負荷のシステムでは、これらの読み込みをさらに多く生成する可能性があります。

読み込み間隔がキューを満杯にしてイベントを失うほど長くなると、ドライバーは起動モードに切り替え、次回読み込むときにJS_EVENT_INITという合成イベントが生成され、ジョイストックの実際の状態を通知します。

注意

バージョン1.2.8からは、キューが環状で64イベントを保持できるようになりました。JS_BUFF_SIZEをjoystick.hで増やしてドライバーを再コンパイルすることで、このサイズを拡張できます。

上記のコードでは、通常のread(2)機能を使って一度に複数のイベントを読み取ることもできます。そのためには、上記のreadを以下のように置き換える必要があります：

struct js_event mybuffer[0xff];
int i = read (fd, mybuffer, sizeof(mybuffer));

この場合、キューが空だった場合はreadが-1を返し、それ以外の場合はイベント数がi / sizeof(js_event)で表されます。また、バッファが満杯だった場合は、ドライバキューを空にするまでイベントを処理し続けるのが良いです。

6.6.5. IOCTL¶

ジョystickドライバは以下のioctl(2)操作を定義しています:

                        /* function                     3rd arg  */
#define JSIOCGAXES      /* get number of axes           char     */
#define JSIOCGBUTTONS   /* get number of buttons        char     */
#define JSIOCGVERSION   /* get driver version           int      */
#define JSIOCGNAME(len) /* get identifier string        char     */
#define JSIOCSCORR      /* set correction values        &js_corr */
#define JSIOCGCORR      /* get correction values        &js_corr */

たとえば、軸の数を読み取るには:

char number_of_axes;
ioctl (fd, JSIOCGAXES, &number_of_axes);

6.6.5.1. JSIOGCVERSION¶

JSIOGCVERSIONは、ランタイムで実行中のドライバが1.0以上でイベントインターフェースをサポートしているかを確認するための良い方法です。サポートされていない場合はIOCTLが失敗します。コンパイル時の判定にはJS_VERSIONシンボルをテストできます:

#ifdef JS_VERSION
#if JS_VERSION > 0xsomething

6.6.5.2. JSIOCGNAME¶

JSIOCGNAME(len)は、ジョystickの名前文字列を取得するための操作です。これは起動時に表示される名前と同じです。'len'引数はアプリケーションが名前を要求する際のバッファ長を指定し、名前が長すぎる場合にオーバーランを防ぐために使用されます:

char name[128];
if (ioctl(fd, JSIOCGNAME(sizeof(name)), name) < 0)
        strncpy(name, "Unknown", sizeof(name));
printf("Name: %s\n", name);

6.6.5.3. JSIOC[SG]CORR¶

JSIOC[SG]CORRの使用法についてはjscal.cを参照してください。これらは通常のプログラムでは必要ありませんが、jscalやkcmjoyなどのジョystick校正ソフトウェアでは必要です。これらのIOCTLとデータ型は安定したAPIの一部とは見なされず、ドライバの次のバージョンで予告なしに変更される可能性があります。

JSIOCSCORRとJSIOCGCORRの両方とも、&js_corrがすべての軸の情報を保持できるようにする必要があります。つまり、struct js_corr corr[MAX_AXIS];

struct js_corrは以下のようになります:

struct js_corr {
        __s32 coef[8];
        __u16 prec;
        __u16 type;
};

および type:

#define JS_CORR_NONE            0x00    /* returns raw values */
#define JS_CORR_BROKEN          0x01    /* broken line */

6.6.6. 後方互換性¶

0.xジョystickドライバAPIは非常に限られており、非推奨となっています。ただし、ドライバは後方互換性を提供しています。以下に簡単な概要を示します:

struct JS_DATA_TYPE js;
while (1) {
        if (read (fd, &js, JS_RETURN) != JS_RETURN) {
                /* error */
        }
        usleep (1000);
}

例から想像できるように、readは即座に実行され、ジョystickの現在の状態を返します:

struct JS_DATA_TYPE {
        int buttons;    /* immediate button state */
        int x;          /* immediate x axis value */
        int y;          /* immediate y axis value */
};

そしてJS_RETURNは定義されています:

#define JS_RETURN       sizeof(struct JS_DATA_TYPE)

ボタンの状態をテストするには、

first_button_state  = js.buttons & 1;
second_button_state = js.buttons & 2;

0.xドライバでは軸値の範囲が明示的に定義されていません（ただし、値は非負である必要があります）。1.2.8以上のドライバでは、値を報告する際の固定範囲が使用され、1が最小値、128が中心値、255が最大値となります。

v0.8.0.2ドライバも、/dev/djsXに「デジタルジョystick」（現在はこのドライバでは「マルチシステムジョystick」と呼ばれる）のインターフェースを提供していました。このドライバはそのインターフェースとの互換性を試みていません。
