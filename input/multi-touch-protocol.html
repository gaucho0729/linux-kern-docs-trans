3. マルチタッチ（MT）プロトコル¶

著作権

© 2009-2010 Henrik Rydberg <rydberg@euromail.se>

3.1. はじめに¶

新しいマルチタッチおよびマルチユーザー機器のすべての機能を活用するためには、複数の接触点（デバイス表面に直接接触しているオブジェクト）の詳細データを報告する仕組みが必要です。このドキュメントでは、カーネルドライバが任意の数の接触点に関する詳細情報を報告できるようにするマルチタッチ（MT）プロトコルについて説明します。

このプロトコルはハードウェアの機能に応じて2つのタイプに分かれます。匿名接触点（タイプA）を処理するデバイスでは、すべての接触点の素データを受信者に送信する方法が記述されています。識別可能な接触点（タイプB）を追跡できるデバイスでは、個々の接触点の更新情報をイベントスロット経由で送信する方法が記述されています。

注意

MTプロトコルのタイプAは非推奨であり、すべてのカーネルドライバはタイプBを使用するように変換されています。

3.2. プロトコルの使用方法¶

接触点の詳細情報はABS_MTイベントの別個のパケットとして順次送信されます。接触パケットの一部としてのみ認識されるのはABS_MTイベントです。これらのイベントは現在の単一タッチ（ST）アプリケーションでは無視されるため、既存のドライバ上でMTプロトコルをSTプロトコルの上に実装することが可能です。

タイプAデバイス用のドライバは、各パケットの終わりでinput_mt_sync()を呼び出すことで接触パケットを区切ります。これによりSYN_MT_REPORTイベントが生成され、受信者に現在の接触点のデータを受け入れて次のデータを待機するよう指示します。

タイプBデバイス用のドライバは、各パケットの開始時にスロットを引数として指定する input_mt_slot()を呼び出すことで接触パケットを区切ります。これによりABS_MT_SLOTイベントが生成され、受信者に指定されたスロットの更新を待機するよう指示します。

すべてのドライバはmulti-touch転送の終わりをinput_sync()関数を呼び出すことで示します。これにより受信者が最後のEV_SYN/SYN_REPORTからのイベントを処理し、新しいイベント/パケットの受け入れを準備するよう指示されます。

ステートレスなタイプAプロトコルとステートフルなタイプBスロットプロトコルの主な違いは、識別可能な接触点を用いることでユーザー空間に送信するデータ量を減らす点にあります。スロットプロトコルではABS_MT_TRACKING_IDを使用する必要があります。これはハードウェアから提供されるか、素データから計算されるものです。 5.

タイプAデバイスでは、カーネルドライバは現在の表面にあるすべての匿名接触点の任意の列挙を生成する必要があります。イベントストリームにおけるパケットの出現順序は重要ではありません。フィンガートラッキングやイベントフィルタリングはユーザー空間で処理されます。 3.

タイプBデバイスでは、カーネルドライバーはそれぞれの識別された接触に対してスロットを関連付け、そのスロットを使用して接触の変更を伝播させる必要があります。接触の作成、置き換え、破棄は、関連付けられたスロットのABS_MT_TRACKING_IDを変更することで実現されます。非負のトラッキングIDは接触を表し、値-1は未使用のスロットを示します。以前に存在しなかったトラッキングIDは新規とみなされ、もはや存在しないトラッキングIDは削除されたとみなされます。変更のみが伝播されるため、各初期化された接触の完全な状態は受信側に保持される必要があります。MTイベントを受信した際には、現在のスロットの適切な属性を単に更新するだけでよいです。

一部のデバイスはハードウェアが報告できるよりも多くの接触を識別および/または追跡します。このようなデバイスのドライバーは、ハードウェアが報告する各接触に対して1つのタイプBスロットを関連付ける必要があります。スロットに関連付けられた接触のIDが変化した場合、ドライバーはそのスロットを無効化するためにABS_MT_TRACKING_IDを変更する必要があります。ハードウェアが現在報告しているよりも多くの接触を追跡していることを信号で通知した場合、ドライバーはBTN_TOOL_*TAPイベントを使用してユーザー空間にその時点でハードウェアが追跡している接触の総数を通知する必要があります。ドライバーは、対応するBTN_TOOL_*TAPイベントを明示的に送信し、use_countをfalseに設定して呼び出すことでこれを実行する必要があります。 input_mt_report_pointer_emulation()ドライバーはハードウェアが報告できるスロット数だけを広告する必要があります。ユーザー空間は、ドライバーが報告できる総接触数がスロット数より多いことを検出するために、ABS_MT_SLOT軸のabsinfoで報告されたタイプBスロット数より大きい最大サポートBTN_TOOL_*TAPイベントを確認します。

ABS_MT_SLOT軸の最小値は0でなければなりません。

3.3. プロトコル例A¶

タイプAデバイスにおける2接触タッチの最小イベントシーケンスは以下のようになります:

ABS_MT_POSITION_X x[0]
ABS_MT_POSITION_Y y[0]
SYN_MT_REPORT
ABS_MT_POSITION_X x[1]
ABS_MT_POSITION_Y y[1]
SYN_MT_REPORT
SYN_REPORT

1つの接触を移動した後のシーケンスはまったく同じです。すべての現在の接触のrawデータは、すべての同期間でSYN_REPORTごとに送信されます。

最初の接触を上げた後のシーケンスは以下のようになります:

ABS_MT_POSITION_X x[1]
ABS_MT_POSITION_Y y[1]
SYN_MT_REPORT
SYN_REPORT

2番目の接触を上げた後のシーケンスは以下のようになります:

SYN_MT_REPORT
SYN_REPORT

ドライバーがBTN_TOUCHまたはABS_PRESSUREをABS_MTイベントに加えて報告している場合、最後のSYN_MT_REPORTイベントは省略できます。そうでない場合、入力コアは最後のSYN_REPORTを無視し、ユーザー空間にゼロ接触イベントが届かないことになります。

3.4. プロトコル例B¶

タイプBのデバイスにおける2点接触のための最小限のイベントシーケンスは以下のようになります:

ABS_MT_SLOT 0
ABS_MT_TRACKING_ID 45
ABS_MT_POSITION_X x[0]
ABS_MT_POSITION_Y y[0]
ABS_MT_SLOT 1
ABS_MT_TRACKING_ID 46
ABS_MT_POSITION_X x[1]
ABS_MT_POSITION_Y y[1]
SYN_REPORT

接触45をx方向に移動した後のシーケンスは以下の通りです:

ABS_MT_SLOT 0
ABS_MT_POSITION_X x[0]
SYN_REPORT

スロット0の接触を上げた後のシーケンスは以下の通りです:

ABS_MT_TRACKING_ID -1
SYN_REPORT

修正対象のスロットがすでに0であるため、ABS_MT_SLOTは省略されます。このメッセージにより、スロット0と接触45の関連付けが解除されるため、接触45が破棄され、スロット0が他の接触のために再利用可能になります。

最後に、2番目の接触を上げた後のシーケンスは以下の通りです:

ABS_MT_SLOT 1
ABS_MT_TRACKING_ID -1
SYN_REPORT

3.5. イベントの使用法¶

望ましいプロパティを持つABS_MTイベントのセットが定義されています。イベントはカテゴリに分類されており、部分的な実装を可能にしています。最小限のセットはABS_MT_POSITION_XとABS_MT_POSITION_Yからなり、複数の接触を追跡できます。デバイスがサポートする場合、ABS_MT_TOUCH_MAJORとABS_MT_WIDTH_MAJORを使用して、接触領域のサイズと近接する工具のサイズを提供できます。

TOUCHおよびWIDTHパラメータは幾何学的な意味を持ちます。窓を通して、誰かが指をガラスに軽く押し当てている様子を想像してください。あなたは2つの領域を確認します。1つは指が実際にガラスに触れている部分からなる内側の領域、もう1つは指の周囲で形成される外側の領域です。接触領域の中心(a)はABS_MT_POSITION_X/Yで、近接する指の中心(b)はABS_MT_TOOL_X/Yです。接触直径はABS_MT_TOUCH_MAJORで、指の直径はABS_MT_WIDTH_MAJORです。今度はその人がガラスに指を強く押し付けると、接触領域は拡大します。一般的に、ABS_MT_TOUCH_MAJOR / ABS_MT_WIDTH_MAJORという比率（常に1未満）は接触圧力に関連しています。圧力ベースのデバイスでは、ABS_MT_PRESSUREを使用して接触領域の圧力を提供できます。接触ホバーが可能なデバイスでは、ABS_MT_DISTANCEを使用して接触と表面の距離を示します。

     Linux MT                               Win8
    __________                     _______________________
   /          \                   |                       |
  /            \                  |                       |
 /     ____     \                 |                       |
/     /    \     \                |                       |
\     \  a  \     \               |       a               |
 \     \____/      \              |                       |
  \                 \             |                       |
   \        b        \            |           b           |
    \                 \           |                       |
     \                 \          |                       |
      \                 \         |                       |
       \                /         |                       |
        \              /          |                       |
         \            /           |                       |
          \__________/            |_______________________|

MAJORパラメータに加えて、接触および指の領域の楕円形状はMINORパラメータを追加することで記述できます。これにより、MAJORとMINORは楕円の主軸と副軸になります。接触楕円の向きはORIENTATIONパラメータで記述され、指の楕円の方向はベクトル(a - b)で示されます。

タイプAのデバイスでは、さらに接触形状の詳細を指定するためABS_MT_BLOB_IDを使用できます。

ABS_MT_TOOL_TYPEは、タッチしているツールが指かペンかそれ以外のものかを指定するために使用できます。最後に、ABS_MT_TRACKING_IDは、時間とともに特定された接触を追跡するために使用できます 5.

タイプBプロトコルでは、ABS_MT_TOOL_TYPEおよびABS_MT_TRACKING_IDは入力コアによって暗黙的に処理されるため、ドライバーは代わりに以下を呼び出す必要があります input_mt_report_slot_state().

3.6. イベントセマンティクス¶

ABS_MT_TOUCH_MAJOR

接触の主軸の長さを表します。長さは表面単位で指定する必要があります。表面がX×Y解像度を持つ場合、ABS_MT_TOUCH_MAJORの最大可能値は√(X²+Y²)（対角線）です 4.

ABS_MT_TOUCH_MINOR

接触の縦軸の長さを表面単位で表します。接触が円形の場合、このイベントは省略できます 4.

ABS_MT_WIDTH_MAJOR

近づいているツールの主軸の長さを表面単位で表します。これはツール自体のサイズを示すものと理解してください。接触と近づいているツールの向きは同じと仮定されます 4.

ABS_MT_WIDTH_MINOR

近づいているツールの縦軸の長さを表面単位で表します。円形の場合は省略してください 4.

上記の4つの値は、接触に関する追加情報を導き出すために使用できます。ABS_MT_TOUCH_MAJOR / ABS_MT_WIDTH_MAJORの比は圧力を表す概念を近似します。指や手のひらなど、手の各部分は異なる特徴的な幅を持っています

ABS_MT_PRESSURE

接触面での圧力を、任意の単位で表します。圧力に基づくデバイスや、空間的な信号強度分布を持つデバイスではTOUCHおよびWIDTHではなくこのイベントを使用できます

ABS_MT_DISTANCE

接触と表面との距離を表面単位で表します。距離がゼロの場合は接触が表面に触れていることを意味し、正の数は接触が表面の上をホバーしていることを示します

ABS_MT_ORIENTATION

タッチしている楕円の向きを表します。値はタッチ中心を時計回りに四分の一回転する符号付きの値として記述する必要があります。符号付きの値の範囲は任意ですが、表面のY軸（北）に合わせた楕円にはゼロを、楕円が左に傾いている場合は負の値、右に傾いている場合は正の値を返す必要があります。X軸の正方向に合わせた場合、範囲の最大値を、X軸の負方向に合わせた場合、範囲の-最大値を返す必要があります

タッチエリプスはデフォルトで対称です。真の360度の方向をサポートできるデバイスでは、報告された方向が最大値を超える必要があります。これは四分の一回転以上を示すためです。逆さにした指の場合は、最大値の2倍を返す必要があります。

タッチ領域が円形の場合、またはカーネルドライバーで情報が提供されていない場合は、方向は省略できます。デバイスが2つの軸を区別できるが、その間の値を一意に特定できない場合、部分的な方向サポートが可能です。その場合、ABS_MT_ORIENTATIONの範囲は[0, 1]になります。 4.

ABS_MT_POSITION_X

タッチしている楕円の中心の表面X座標。

ABS_MT_POSITION_Y

タッチしている楕円の中心の表面Y座標。

ABS_MT_TOOL_X

近づいているツールの中心の表面X座標。デバイスが意図したタッチポイントとツール自体を区別できない場合は省略します。

ABS_MT_TOOL_Y

近づいているツールの中心の表面Y座標。デバイスが意図したタッチポイントとツール自体を区別できない場合は省略します。

4つの座標値はタッチ位置とツール位置を分離するために使用できます。両方の座標が存在する場合、主なツール軸はタッチポイントに向かいます。 1それ以外の場合、ツール軸はタッチ軸と一致します。

ABS_MT_TOOL_TYPE

近づいているツールの種類。多くのカーネルドライバーは指やペンなどの異なるツールタイプを区別できません。その場合、イベントは省略する必要があります。現在のプロトコルは主にMT_TOOL_FINGER、MT_TOOL_PEN、MT_TOOL_PALMをサポートしています。 2。タイプBデバイスではこのイベントはinput coreによって処理されます。ドライバーは代わりに input_mt_report_slot_state()。接触のABS_MT_TOOL_TYPEは、デバイスに触れ続けている間でも時間とともに変化する可能性があります。ファームウェアが最初に出現したツールを特定できないためです。

ABS_MT_BLOB_ID

BLOB_IDは複数のパケットを一つの任意形状の接触にグループ化します。ポイントの順序はポリゴンを形成し、接触の形状を定義します。これはタイプAデバイス用の低レベルの匿名グループであり、高レベルのtrackingIDと混同しないでください。 5。ほとんどのタイプAデバイスはblob機能を持っていないため、ドライバーはこのイベントを安全に省略できます。

ABS_MT_TRACKING_ID

TRACKING_IDは接触のライフサイクル全体を通してその接触を識別します 5. TRACKING_IDの値の範囲は、長期間にわたって維持される接触を一意に識別できるように十分に大きく設定する必要があります。タイプBデバイスではこのイベントは入力コアによって処理されますが、ドライバーは代わりに input_mt_report_slot_state().

3.7. イベント計算¶

ハードウェアの多様性により、一部のデバイスはMTプロトコルによりよく適合します。マッピングを簡素化し統一するため、このセクションでは特定のイベントを計算するためのレシピを提供します。

矩形形状で接触を報告するデバイスでは符号化された方向を取得できません。XとYを接触矩形の辺の長さと仮定すると、可能な情報量を保持するための簡単な式は以下の通りです：

ABS_MT_TOUCH_MAJOR := max(X, Y)
ABS_MT_TOUCH_MINOR := min(X, Y)
ABS_MT_ORIENTATION := bool(X > Y)

ABS_MT_ORIENTATIONの範囲は[0, 1]に設定し、デバイスがY軸方向（0）とX軸方向（1）の指を区別できることを示します。

TとC座標を両方持つwin8デバイスでは、位置マッピングは以下の通りです：

ABS_MT_POSITION_X := T_X
ABS_MT_POSITION_Y := T_Y
ABS_MT_TOOL_X := C_X
ABS_MT_TOOL_Y := C_Y

残念ながら、接触楕円とツール楕円の両方を指定する情報が不足しているため、近似値に頼らざるを得ません。以前の使用と互換性がある単純なスキームは以下の通りです：

ABS_MT_TOUCH_MAJOR := min(X, Y)
ABS_MT_TOUCH_MINOR := <not used>
ABS_MT_ORIENTATION := <not used>
ABS_MT_WIDTH_MAJOR := min(X, Y) + distance(T, C)
ABS_MT_WIDTH_MINOR := min(X, Y)

理由：接触楕円の方向に関する情報がありませんので、内接円で近似します。ツール楕円はベクトル（T - C）に一致するため、距離（T, C）に応じて直径を増やす必要があります。最後に、タッチ直径をツールの厚さと等しく仮定し、上記の式に至ります。

3.9. ジェスチャー¶

ジェスチャーイベントの作成という特定の用途において、TOUCHおよびWIDTHパラメータは、例えば指の圧力を近似するか、人差し指と親指を区別するのに使用できます。MINORパラメータを追加することで、スワイプする指と指を向ける指を区別でき、ORIENTATIONを用いることで指の捻れを検出できます。
