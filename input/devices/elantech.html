9. Elantech Touchpad Driver¶

Copyright (C) 2007-2008 Arjan Opmeer <arjan@opmeer.net>

Steve Havelkaが提供したハードウェアバージョン1に関する追加情報

バージョン2（EeePC）のハードウェアサポートは、XandrosのWoodyから受け取ったパッチと、eeeuser.comフォーラムのStewieGriffinユーザーから転送された情報に基づいています

9.1. はじめに¶

現在、Linux用Elantechタッチパッドドライバーは4つの異なるハードウェアバージョンを認識しています（無遠慮な命名でバージョン1、バージョン2、バージョン3、バージョン4と呼ばれます）。バージョン1は「古い」ノートPCに搭載されており、パケットごとに4バイトを使用します。バージョン2はEeePCで導入され、パケットごとに6バイトを使用し、2本の指の位置やタッチ幅などの追加機能を提供します。ハードウェアバージョン3は6バイトごとにパケットを使用し（2本の指の場合は2つの6バイトパケットを連結）、最大3本の指の追跡を可能にします。ハードウェアバージョン4は6バイトごとにパケットを使用し、ステータスパケットと複数のヘッドまたは動きパケットを組み合わせることができます。ハードウェアバージョン4は最大5本の指の追跡をサポートします。

一部のハードウェアバージョン3およびバージョン4には、別個のパケット形式を使用するトラックポイントも搭載されています。これは6バイトごとにパケットを使用します。

ドライバーは両方のハードウェアバージョンをサポートしており、Xorg Synapticsタッチパッドドライバーおよびそのグラフィカルな設定ユーティリティと互換性があります。

トラックポイントが利用可能な場合、マウスボタンはタッチパッドまたはトラックポイントのいずれかに関連付けられます。xorgでタッチパッドを無効化する（TouchPadOff=0）と、タッチパッドに関連するボタンも同時に無効になります。

さらに、タッチパッドの動作は、内部レジスタの内容を調整することで変更できます。これらのレジスタは、ドライバーによって/sys/bus/serio/drivers/psmouse/serio?以下のsysfsエントリとして表現され、読み取りおよび書き込みが可能です。

現在、ハードウェアバージョン1のレジスタについてはある程度理解されています。ハードウェアバージョン2は一部の同じレジスタを使用しているように見えますが、レジスタ内のビットが同じ意味を持つか、意味が変化している可能性があるかどうかは不明です。

さらに、一部のレジスタ設定はタッチパッドが相対モードで動作している場合にのみ効果を発揮し、絶対モードでは効果がありません。Linux Elantechタッチパッドドライバーは常にハードウェアを絶対モードに設定するため、以下に記載されている情報はすべて即座に利用できません。しかし、Elantechに関する自由に利用可能なドキュメンテーションが存在しないので、情報の完全性を保つためここに提供しています。

9.2. 追加の設定¶

現在、Linux Elantech ポインティングデバイスドライバーは、/sys/bus/serio/drivers/psmouse/serio? に3つの追加の設定項目を提供しています。

  • debug

    デバッグレベルをONまたはOFFに切り替えます。

    このファイルに「0」をエコーバックすると、すべてのデバッグがOFFになります。

    現在、「1」を設定すると基本的なデバッグが有効になり、「2」を設定するとパケットデバッグが有効になります。ハードウェアバージョン1ではデフォルトでOFF、バージョン2ではデフォルトで「1」が設定されています。

    パケットデバッグをONにすると、ドライバーが受信したすべてのパケットを処理する前にsyslogにダンプします。注意が必要なのは、これにより大量のデータが生成される可能性があることです。

  • paritycheck

    パリティチェックをONまたはOFFに切り替えます。

    このファイルに「0」をエコーバックするとパリティチェックがOFFになります。非ゼロの値を設定するとONになります。ハードウェアバージョン1ではデフォルトでON、バージョン2ではデフォルトでOFFです。

    ハードウェアバージョン1では、各パケットの最後の3バイトに対してパリティビットを計算し、基本的なデータ整合性を検証します。ドライバーはこれらのビットをチェックし、破損したパケットは拒否します。この設定項目を使用することで、このチェックをバイパスできます。

    ハードウェアバージョン2ではパリティビットが提供されません。のみいくつかの基本的なデータ整合性チェックが可能です。現在、チェックはデフォルトで無効になっています。現在、チェックを有効にしても何も動作しません。

  • crc_enabled

    crc_enabledを0/1に設定します。この整合性チェックの公式な名前は「crc_enabled」ですが、実際には巡回冗長検出（cyclic redundancy check）ではありません。

    crc_enabledの状態に応じて、ハードウェアバージョン3および4で基本的なデータ整合性検証が行われます。ドライバーは破損したパケットを拒否します。この設定項目を使用することで、crc_enabledの状態を変更できます。

    crc_enabledの値を読み込むと現在の値が表示されます。このファイルに「0」または「1」をエコーバックすると、状態を「0」または「1」に設定します。

9.3. ハードウェアバージョンの区別¶

ハードウェアバージョンを検出するには、param[0].param[1].param[2]のバージョン番号を読みます：

4 bytes version: (after the arrow is the name given in the Dell-provided driver)
02.00.22 => EF013
02.06.00 => EF019

現実の環境では、00.01.64、01.00.21、02.00.00、02.00.04、02.00.06などのバージョンも存在します：

6 bytes:
02.00.30 => EF113
02.08.00 => EF023
02.08.XX => EF123
02.0B.00 => EF215
04.01.XX => Scroll_EF051
04.02.XX => EF051

現実の環境では、04.03.01、04.04.11などのバージョンも存在します。ほぼ違いはなく、EF113は圧力/幅を報告しないことと異なるデータ整合性チェックがあるだけです。

param[0] <= 01のバージョンはすべて4バイト/ファームウェア1とみなせます。02.08.00未満のバージョン（02.00.30を除く）は4バイト/ファームウェア2とみなせます。それ以上のバージョン（02.08.00以上）はすべて6バイトとみなせます。

9.4. ハードウェアバージョン 1¶

9.4.1. Registers¶

レジスタに16進数値をエコーバックすることで、その内容を変更できます。

例:

echo -n 0x16 > reg_10

  • reg_10:

    bit   7   6   5   4   3   2   1   0
      B   C   T   D   L   A   S   E

      E: 1 = enable smart edges unconditionally
      S: 1 = enable smart edges only when dragging
      A: 1 = absolute mode (needs 4 byte packets, see reg_11)
      L: 1 = enable drag lock (see reg_22)
      D: 1 = disable dynamic resolution
      T: 1 = disable tapping
      C: 1 = enable corner tap
      B: 1 = swap left and right button

  • reg_11:

    bit   7   6   5   4   3   2   1   0
      1   0   0   H   V   1   F   P

      P: 1 = enable parity checking for relative mode
      F: 1 = enable native 4 byte packet mode
      V: 1 = enable vertical scroll area
      H: 1 = enable horizontal scroll area

  • reg_20:

    single finger width?

  • reg_21:

    scroll area width (small: 0x40 ... wide: 0xff)

  • reg_22:

    drag lock time out (short: 0x14 ... long: 0xfe;
                    0xff = tap again to release)

  • reg_23:

    tap make timeout?

  • reg_24:

    tap release timeout?

  • reg_25:

    smart edge cursor speed (0x02 = slow, 0x03 = medium, 0x04 = fast)

  • reg_26:

    smart edge activation area width?

9.4.2. ネイティブリレーショナルモード4バイトパケット形式¶

バイト0:

bit   7   6   5   4   3   2   1   0
      c   c  p2  p1   1   M   R   L

      L, R, M = 1 when Left, Right, Middle mouse button pressed
         some models have M as byte 3 odd parity bit
      when parity checking is enabled (reg_11, P = 1):
         p1..p2 = byte 1 and 2 odd parity bit
      c = 1 when corner tap detected

バイト1:

bit   7   6   5   4   3   2   1   0
     dx7 dx6 dx5 dx4 dx3 dx2 dx1 dx0

      dx7..dx0 = x movement;   positive = right, negative = left
      byte 1 = 0xf0 when corner tap detected

バイト2:

bit   7   6   5   4   3   2   1   0
     dy7 dy6 dy5 dy4 dy3 dy2 dy1 dy0

      dy7..dy0 = y movement;   positive = up,    negative = down

バイト3:

parity checking enabled (reg_11, P = 1):

   bit   7   6   5   4   3   2   1   0
         w   h  n1  n0  ds3 ds2 ds1 ds0

         normally:
            ds3..ds0 = scroll wheel amount and direction
                       positive = down or left
                       negative = up or right
         when corner tap detected:
            ds0 = 1 when top right corner tapped
            ds1 = 1 when bottom right corner tapped
            ds2 = 1 when bottom left corner tapped
            ds3 = 1 when top left corner tapped
         n1..n0 = number of fingers on touchpad
            only models with firmware 2.x report this, models with
            firmware 1.x seem to map one, two and three finger taps
            directly to L, M and R mouse buttons
         h = 1 when horizontal scroll action
         w = 1 when wide finger touch?

otherwise (reg_11, P = 0):

   bit   7   6   5   4   3   2   1   0
        ds7 ds6 ds5 ds4 ds3 ds2 ds1 ds0

         ds7..ds0 = vertical scroll amount and direction
                    negative = up
                    positive = down

9.4.3. ネイティブアブソリュートモード4バイトパケット形式¶

EF013およびEF019はファームウェアのバグのため特殊な挙動があります（1本の指が接触している場合、最初の2つの位置レポートは無視する必要があります）。このカウントは、指の数が変化したときにリセットされます。

バイト0:

firmware version 1.x:

   bit   7   6   5   4   3   2   1   0
         D   U  p1  p2   1  p3   R   L

         L, R = 1 when Left, Right mouse button pressed
         p1..p3 = byte 1..3 odd parity bit
         D, U = 1 when rocker switch pressed Up, Down

firmware version 2.x:

   bit   7   6   5   4   3   2   1   0
        n1  n0  p2  p1   1  p3   R   L

         L, R = 1 when Left, Right mouse button pressed
         p1..p3 = byte 1..3 odd parity bit
         n1..n0 = number of fingers on touchpad

バイト1:

firmware version 1.x:

   bit   7   6   5   4   3   2   1   0
         f   0  th  tw  x9  x8  y9  y8

         tw = 1 when two finger touch
         th = 1 when three finger touch
         f  = 1 when finger touch

firmware version 2.x:

   bit   7   6   5   4   3   2   1   0
         .   .   .   .  x9  x8  y9  y8

バイト2:

bit   7   6   5   4   3   2   1   0
     x7  x6  x5  x4  x3  x2  x1  x0

      x9..x0 = absolute x value (horizontal)

バイト3:

bit   7   6   5   4   3   2   1   0
     y7  y6  y5  y4  y3  y2  y1  y0

      y9..y0 = absolute y value (vertical)

9.5. ハードウェアバージョン2¶

9.5.1. Registers¶

レジスタに16進数値をエコーバックすることで、その内容を変更できます。

例:

echo -n 0x56 > reg_10

  • reg_10:

    bit   7   6   5   4   3   2   1   0
      0   1   0   1   0   1   D   0

      D: 1 = enable drag and drop

  • reg_11:

    bit   7   6   5   4   3   2   1   0
      1   0   0   0   S   0   1   0

      S: 1 = enable vertical scroll

  • reg_21:

    unknown (0x00)

  • reg_22:

    drag and drop release time out (short: 0x70 ... long 0x7e;
                          0x7f = never i.e. tap again to release)

9.5.2. ネイティブアブソリュートモード6バイトパケット形式¶

9.5.2.1. パリティチェックおよびパケット再同期¶

パリティチェックは行われませんが、一部の整合性チェックは可能です。

例えばEF113の場合、

SA1= packet[0];
A1 = packet[1];
B1 = packet[2];
SB1= packet[3];
C1 = packet[4];
D1 = packet[5];
if( (((SA1 & 0x3C) != 0x3C) && ((SA1 & 0xC0) != 0x80)) || // check Byte 1
    (((SA1 & 0x0C) != 0x0C) && ((SA1 & 0xC0) == 0x80)) || // check Byte 1 (one finger pressed)
    (((SA1 & 0xC0) != 0x80) && (( A1 & 0xF0) != 0x00)) || // check Byte 2
    (((SB1 & 0x3E) != 0x38) && ((SA1 & 0xC0) != 0x80)) || // check Byte 4
    (((SB1 & 0x0E) != 0x08) && ((SA1 & 0xC0) == 0x80)) || // check Byte 4 (one finger pressed)
    (((SA1 & 0xC0) != 0x80) && (( C1 & 0xF0) != 0x00))  ) // check Byte 5
        // error detected

他のすべてのデバイスでは、ほんの数個の定数ビットがあります:

if( ((packet[0] & 0x0C) != 0x04) ||
    ((packet[3] & 0x0f) != 0x02) )
        // error detected

エラーが検出された場合、すべてのパケットが1つずらされ（パケット[0]は無視されます）。

9.5.2.2. 1本または3本指のタッチ¶

バイト0:

bit   7   6   5   4   3   2   1   0
      n1  n0  w3  w2   .   .   R   L

      L, R = 1 when Left, Right mouse button pressed
      n1..n0 = number of fingers on touchpad

バイト1:

bit   7   6   5   4   3   2   1   0
      p7  p6  p5  p4 x11 x10 x9  x8

バイト2:

bit   7   6   5   4   3   2   1   0
      x7  x6  x5  x4  x3  x2  x1  x0

      x11..x0 = absolute x value (horizontal)

バイト3:

bit   7   6   5   4   3   2   1   0
      n4  vf  w1  w0   .   .   .  b2

      n4 = set if more than 3 fingers (only in 3 fingers mode)
      vf = a kind of flag ? (only on EF123, 0 when finger is over one
           of the buttons, 1 otherwise)
      w3..w0 = width of the finger touch (not EF113)
      b2 (on EF113 only, 0 otherwise), b2.R.L indicates one button pressed:
             0 = none
             1 = Left
             2 = Right
             3 = Middle (Left and Right)
             4 = Forward
             5 = Back
             6 = Another one
             7 = Another one

バイト4:

bit   7   6   5   4   3   2   1   0
     p3  p1  p2  p0  y11 y10 y9  y8

      p7..p0 = pressure (not EF113)

バイト5:

bit   7   6   5   4   3   2   1   0
     y7  y6  y5  y4  y3  y2  y1  y0

      y11..y0 = absolute y value (vertical)

9.5.2.3. 2本指のタッチ¶

注意：2つの座標ペアは、2本の指の正確な座標ではなく、左下と右上座標のペアです。実際の指は、これらの2点で定義される正方形の他の対角線上に位置している可能性があります。

バイト0:

bit   7   6   5   4   3   2   1   0
     n1  n0  ay8 ax8  .   .   R   L

      L, R = 1 when Left, Right mouse button pressed
      n1..n0 = number of fingers on touchpad

バイト1:

bit   7   6   5   4   3   2   1   0
     ax7 ax6 ax5 ax4 ax3 ax2 ax1 ax0

      ax8..ax0 = lower-left finger absolute x value

バイト2:

bit   7   6   5   4   3   2   1   0
     ay7 ay6 ay5 ay4 ay3 ay2 ay1 ay0

      ay8..ay0 = lower-left finger absolute y value

バイト3:

bit   7   6   5   4   3   2   1   0
      .   .  by8 bx8  .   .   .   .

バイト4:

bit   7   6   5   4   3   2   1   0
     bx7 bx6 bx5 bx4 bx3 bx2 bx1 bx0

      bx8..bx0 = upper-right finger absolute x value

バイト5:

bit   7   6   5   4   3   2   1   0
     by7 by8 by5 by4 by3 by2 by1 by0

      by8..by0 = upper-right finger absolute y value

9.6. ハードウェアバージョン3¶

9.6.1. Registers¶

  • reg_10:

    bit   7   6   5   4   3   2   1   0
      0   0   0   0   R   F   T   A

      A: 1 = enable absolute tracking
      T: 1 = enable two finger mode auto correct
      F: 1 = disable ABS Position Filter
      R: 1 = enable real hardware resolution

9.6.2. ネイティブアブソリュートモード6バイトパケット形式¶

1本および3本指のタッチは同じ6バイトパケット形式を使用しますが、3本指のタッチでは3本の指の中心位置のみをレポートします。

ファームウェアは2本指のタッチに対して12バイトのデータを送信します。

デバウンスに関する注意：電源が不安定な場合や電気的な問題がある場合、または指の数が変化した場合、ファームウェアはドライバにハードウェアがデバウンス状態にあることを通知する「デバウンスパケット」を送信します。このデバウンスパケットのサインは以下の通りです:

byte 0: 0xc4
byte 1: 0xff
byte 2: 0xff
byte 3: 0x02
byte 4: 0xff
byte 5: 0xff

このようなパケットに遭遇した場合は無視します。

9.6.2.1. 1本または3本指のタッチ¶

バイト0:

bit   7   6   5   4   3   2   1   0

     L, R = 1 when Left, Right mouse button pressed
     n1..n0 = number of fingers on touchpad

バイト1:

     p7  p6  p5  p4 x11 x10  x9  x8

バイト2:

bit   7   6   5   4   3   2   1   0
     x7  x6  x5  x4  x3  x2  x1  x0

     x11..x0 = absolute x value (horizontal)

バイト3:

bit   7   6   5   4   3   2   1   0
      0   0  w1  w0   0   0   1   0

      w3..w0 = width of the finger touch

バイト4:

bit   7   6   5   4   3   2   1   0
     p3  p1  p2  p0  y11 y10 y9  y8

     p7..p0 = pressure

バイト5:

bit   7   6   5   4   3   2   1   0
     y7  y6  y5  y4  y3  y2  y1  y0

     y11..y0 = absolute y value (vertical)

9.6.2.2. 2本指のタッチ¶

2本指のタッチのパケット形式は同じですが、ハードウェアは2つの6バイトパケットを送信します。最初のパケットには1本目の指のデータ、2番目のパケットには2本目の指のデータが含まれます。したがって、2本指のタッチでは合計12バイトが送信されます。

9.7. ハードウェアバージョン4¶

9.7.1. Registers¶

  • reg_07:

    bit   7   6   5   4   3   2   1   0
      0   0   0   0   0   0   0   A

      A: 1 = enable absolute tracking

9.7.2. ネイティブアブソリュートモード6バイトパケット形式¶

v4ハードウェアは真のマルチタッチパッドであり、最大5本の指を追跡できます。残念ながら、PS/2の帯域幅が限られているため、パケット形式は複雑です。

指の数またはIDが変化した場合、ハードウェアはステータスパケットを送信して、タッチパッド上の指の数とIDを通知し、その後ヘッドパケットまたはモーションパケットを送信します。ヘッドパケットには指ID、絶対座標(x,y)、幅、圧力データが含まれます。モーションパケットには2本の指の位置変化データが含まれます。

たとえば、ステータスパケットがタッチパッドに2本の指があることを伝えたら、その後に2つのヘッドパケットが続くと予想できます。指の状態が変わらない場合、その後のパケットはモーションパケットとなり、指の位置のデルタ値のみを送信します。ステータスパケットを受信するまでこの状態が続きます。

1本指のタッチは例外です。ステータスパケットが1本の指があることを伝えたら、ハードウェアはその後にヘッドパケットのみを送信します。

     y11..y0 = absolute y value (vertical)

9.7.2.3. モーションパケット¶

バイト0:

bit   7   6   5   4   3   2   1   0
    id2 id1 id0   w   0   1   R   L

    L, R = 1 when Left, Right mouse button pressed
    id2..id0 = finger id
    w = 1 when delta overflows (> 127 or < -128), in this case
    firmware sends us (delta x / 5) and (delta y  / 5)

バイト1:

bit   7   6   5   4   3   2   1   0
     x7  x6  x5  x4  x3  x2  x1  x0

     x7..x0 = delta x (two's complement)

バイト2:

bit   7   6   5   4   3   2   1   0
     y7  y6  y5  y4  y3  y2  y1  y0

     y7..y0 = delta y (two's complement)

バイト3:

bit   7   6   5   4   3   2   1   0
    id2 id1 id0   1   0   0   1   0

    id2..id0 = finger id

バイト4:

bit   7   6   5   4   3   2   1   0
     x7  x6  x5  x4  x3  x2  x1  x0

     x7..x0 = delta x (two's complement)

バイト5:

bit   7   6   5   4   3   2   1   0
     y7  y6  y5  y4  y3  y2  y1  y0

     y7..y0 = delta y (two's complement)

     byte 0 ~ 2 for one finger
     byte 3 ~ 5 for another

9.8. トラックポイント（ハードウェアバージョン3および4用）¶

9.8.1. Registers¶

特別なレジスタは特定されていません。

9.8.2. ネイティブリレーモード6バイトパケット形式¶

9.8.2.1. ステータスパケット¶

バイト0:

bit   7   6   5   4   3   2   1   0
      0   0  sx  sy   0   M   R   L

バイト1:

bit   7   6   5   4   3   2   1   0
    ~sx   0   0   0   0   0   0   0

バイト2:

bit   7   6   5   4   3   2   1   0
    ~sy   0   0   0   0   0   0   0

バイト3:

bit   7   6   5   4   3   2   1   0
      0   0 ~sy ~sx   0   1   1   0

バイト4:

bit   7   6   5   4   3   2   1   0
     x7  x6  x5  x4  x3  x2  x1  x0

バイト5:

bit   7   6   5   4   3   2   1   0
     y7  y6  y5  y4  y3  y2  y1  y0


      x and y are written in two's complement spread
          over 9 bits with sx/sy the relative top bit and
          x7..x0 and y7..y0 the lower bits.
      ~sx is the inverse of sx, ~sy is the inverse of sy.
      The sign of y is opposite to what the input driver
          expects for a relative movement
