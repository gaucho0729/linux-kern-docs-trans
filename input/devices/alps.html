1. ALPS Touchpad Protocol¶

1.1. はじめに¶

現在、ALPS ツッチパッドドライバーは、ALPS ツッチパッドで使用されている7つのプロトコルバージョンをサポートしています。これらはバージョン1、2、3、4、5、6、7、8と呼ばれます。

2010年中頃以降、いくつかの新しいALPSツッチパッドがリリースされ、さまざまなノートPCやミニノートPCに統合されました。これらの新しいツッチパッドは、動作の違いが大きく、alps_model_data定義テーブル（各バージョンの特性を記述するテーブル）はもはや不十分です。設計選択肢として、alps_model_dataテーブルを再定義し、既存デバイスのリグレッションテストのリスクを負うか、新しいデバイスをalps_model_dataテーブルの外に隔離するかという選択肢がありました。後者の選択が採用されました。新しいツッチパッドのサインは「Rushmore」、「Pinnacle」、「Dolphin」と呼ばれ、alps.cコードで確認できます。このドキュメントでは、このグループのALPSツッチパッドを一般的に「new ALPSツッチパッド」と呼びます。

私たちはACPIインターフェースの_HID（ハードウェアID）/_CID（互換性ID）定義を用いて、異なるALPSバリアントを一意に識別する方法を試しましたが、1対1のマッピングにはなっていませんでした。実際には、_HIDと実際のハードウェアタイプの間にはm:nのマッピングがあるように見えました。

1.2. 検出¶

すべてのALPSツッチパッドは、「E6レポート」コマンドシーケンス（E8-E6-E6-E6-E9）に応答します。ボタンが押されていない場合、ALPSツッチパッドは00-00-0Aまたは00-00-64を応答します。最初のバイトのビット0〜2が1になる場合、いくつかのボタンが押されていることを示します。

「E6レポート」が成功した場合、ツッチパッドのモデルは「E7レポート」シーケンス（E8-E7-E7-E7-E9）を使用して識別されます。応答はモデル署名であり、alps_model_data_array内の既知のモデルと一致します。

バージョン3および4をサポートする古いツッチパッドでは、「E7レポート」モデル署名は常に73-02-64です。これらのバージョンを区別するには、「Enter Command Mode」シーケンスからの応答を確認する必要があります。

新しいALPSツッチパッドのE7署名は73-03-50または73-03-0Aですが、ECコマンドモード応答でより明確に区別されます。

1.3. コマンドモード¶

バージョン3および4のプロトコルは、16ビットアドレス空間内の1バイトデバイスレジスタを読み書きするためにコマンドモードを使用します。コマンドシーケンスEC-EC-EC-E9によりデバイスがコマンドモードに移行し、デバイスは88-07に続いて第3バイトを応答します。この第3バイトを確認することで、デバイスがバージョン3または4のプロトコルを使用しているかを判断できます。

コマンドモードから抜け出すには、タッチパッドにPSMOUSE_CMD_SETSTREAM (EA)を送信します。

コマンドモード中にいる場合、v3デバイスではEC、v4デバイスではF5という特定のコマンドを最初に送信することでレジスタアドレスを設定できます。その後、アドレスはニブル単位で送信され、各ニブルはオプションでデータを含むコマンドとしてエンコードされます。このエンコード方法はv3とv4プロトコルでやや異なります。

アドレスが設定されると、PSMOUSE_CMD_GETINFO (E9)を送信することでそのアドレスのレジスタを読み取れます。応答の最初の2バイトは読み取るレジスタのアドレスを、3番目のバイトはレジスタの値を示します。レジスタの書き込みは、アドレスの送信と同様のエンコード方式で値をニブル単位で送信します。

新しいALPSタッチパッドではECコマンドを使用してコマンドモードに入ります。新しいALPSタッチパッドの応答は大幅に異なり、動作の決定においてより重要です。このコードは元のalps_model_dataテーブルから分離され、alps_identify関数に移動されました。たとえば、「ドルフィン」タッチパッドにはEC応答の2番目のバイトによって2つのハードウェア初期化シーケンスがあるようです。

1.4. パケットフォーマット¶

以下の表では次の表記法を使用しています：

CAPITALS = stick, miniscules = touchpad

「?」はモデルによって意味が異なります。たとえばホイールの回転、追加ボタン、デュアルポイントのスタックボタンなどです。

1.5. PS/2パケットフォーマット¶

byte 0:  0    0 YSGN XSGN    1    M    R    L
byte 1: X7   X6   X5   X4   X3   X2   X1   X0
byte 2: Y7   Y6   Y5   Y4   Y3   Y2   Y1   Y0

デバイスはオーバーフロー状態を信号として送信しません。

トラックポイントが使用され、タッチパッドに指が乗っていないプロトコルバージョン2のデバイスでは、M R Lビットがポイントングストックとタッチパッドボタンの組み合わせ状態を信号として送信します。

1.6. ALPS絶対モード - プロトコルバージョン1¶

byte 0:  1    0    0    0    1   x9   x8   x7
byte 1:  0   x6   x5   x4   x3   x2   x1   x0
byte 2:  0    ?    ?    l    r    ?  fin  ges
byte 3:  0    ?    ?    ?    ?   y9   y8   y7
byte 4:  0   y6   y5   y4   y3   y2   y1   y0
byte 5:  0   z6   z5   z4   z3   z2   z1   z0

1.7. ALPS絶対モード - プロトコルバージョン2¶

byte 0:  1    ?    ?    ?    1  PSM  PSR  PSL
byte 1:  0   x6   x5   x4   x3   x2   x1   x0
byte 2:  0  x10   x9   x8   x7    ?  fin  ges
byte 3:  0   y9   y8   y7    1    M    R    L
byte 4:  0   y6   y5   y4   y3   y2   y1   y0
byte 5:  0   z6   z5   z4   z3   z2   z1   z0

プロトコルバージョン2のデュアルポイントデバイスはデュアルポイントストック用に標準のPS/2マウスパケットを送信します。M、R、Lビットはポイントングストックとタッチパッドボタンの組み合わせ状態を信号として送信しますが、デルルデュアルポイントデバイスではPSM、PSR、PSLビットでポイントングストックボタンを個別に報告します。

1.8. デュアルポイントデバイス – インタレーブパケットフォーマット¶

byte 0:    1    1    0    0    1    1    1    1
byte 1:    0   x6   x5   x4   x3   x2   x1   x0
byte 2:    0  x10   x9   x8   x7    0  fin  ges
byte 3:    0    0 YSGN XSGN    1    1    1    1
byte 4:   X7   X6   X5   X4   X3   X2   X1   X0
byte 5:   Y7   Y6   Y5   Y4   Y3   Y2   Y1   Y0
byte 6:    0   y9   y8   y7    1    m    r    l
byte 7:    0   y6   y5   y4   y3   y2   y1   y0
byte 8:    0   z6   z5   z4   z3   z2   z1   z0

インタレーブフォーマットを使用するデバイスは通常、デュアルポイントストック用に標準のPS/2マウスパケットとALPS絶対モードパケットを送信します。ストックとタッチパッドが同時に使用される場合にのみインタレーブパケットフォーマットに切り替えます。

1.9. ALPS絶対モード - プロトコルバージョン3¶

ALPSプロトコルバージョン3には3つの異なるパケット形式があります。最初の2つはタッチパッドイベントに関連し、3番目はトラックストックイベントに関連しています。

最初のタイプはタッチパッドの位置パケットです：

byte 0:    1    ?   x1   x0    1    1    1    1
byte 1:    0  x10   x9   x8   x7   x6   x5   x4
byte 2:    0  y10   y9   y8   y7   y6   y5   y4
byte 3:    0    M    R    L    1    m    r    l
byte 4:    0   mt   x3   x2   y3   y2   y1   y0
byte 5:    0   z6   z5   z4   z3   z2   z1   z0

一部のデバイスではトラックストックボタンがこのパケットで報告され、他のデバイスではトラックストックパケットで報告されます。

2番目のパケットタイプは、x軸とy軸を表すビットマップを含みます。ビットマップでは、特定の位置に指が乗っている場合、そのビットが設定されます。したがって、ビットマップパケットは低解像度のマルチタッチデータの取得に利用できますが、指の追跡はできません。このパケットはまた、接触点の数（下記の表におけるf1とf0）をエンコードしています：

byte 0:    1    1   x1   x0    1    1    1    1
byte 1:    0   x8   x7   x6   x5   x4   x3   x2
byte 2:    0   y7   y6   y5   y4   y3   y2   y1
byte 3:    0  y10   y9   y8    1    1    1    1
byte 4:    0  x14  x13  x12  x11  x10   x9   y0
byte 5:    0    1    ?    ?    ?    ?   f1   f0

このパケットは、mtビットが設定された位置パケットの後にのみ出現し、通常は2つ以上の接触がある場合にのみ出現します（ただし、まれに1つの接触しかない場合もあります）。

最終的なv3パケットタイプはトラックストックパケットです：

byte 0:    1    1   x7   y7    1    1    1    1
byte 1:    0   x6   x5   x4   x3   x2   x1   x0
byte 2:    0   y6   y5   y4   y3   y2   y1   y0
byte 3:    0    1   TP   SW    1    M    R    L
byte 4:    0   z6   z5   z4   z3   z2   z1   z0
byte 5:    0    0    1    1    1    1    1    1

TPはタップ処理が有効な場合のタップSW状態、またはプレス処理が有効な場合のプレス状態を表します。SWは4つのボタンが利用可能である場合のスクロールアップを表します。

1.10. ALPS絶対モード - プロトコルバージョン4¶

プロトコルバージョン4には8バイトのパケット形式があります：

byte 0:    1    ?   x1   x0    1    1    1    1
byte 1:    0  x10   x9   x8   x7   x6   x5   x4
byte 2:    0  y10   y9   y8   y7   y6   y5   y4
byte 3:    0    1   x3   x2   y3   y2   y1   y0
byte 4:    0    ?    ?    ?    1    ?    r    l
byte 5:    0   z6   z5   z4   z3   z2   z1   z0
byte 6:    bitmap data (described below)
byte 7:    bitmap data (described below)

最後の2バイトは部分的なビットマップパケットを表し、完全なビットマップパケットを構成するには3つのパケットが必要です。組み立てられると、6バイトのビットマップパケットは以下の形式になります：

byte 0:    0    1   x7   x6   x5   x4   x3   x2
byte 1:    0   x1   x0   y4   y3   y2   y1   y0
byte 2:    0    0    ?  x14  x13  x12  x11  x10
byte 3:    0   x9   x8   y9   y8   y7   y6   y5
byte 4:    0    0    0    0    0    0    0    0
byte 5:    0    0    0    0    0    0    0  y10

いくつか注意すべき点があります。

  1. ビットマップデータでは、バイト0のビット6がビットマップパケットの最初のフラグメントを識別する同期バイトとして機能します。

  2. ビットマップはv3のビットマップパケットと同じデータを表していますが、パケットレイアウトは異なります。

  3. v4プロトコルパケットには接触ポイントの数を表すカウントが含まれていません。接触ポイントの数はビットマップを分析することで導出する必要があります。

  4. 位置パケットとビットマップパケットの比率は3対1です。そのため、MT位置はST位置更新の毎3回にのみ更新され、接触ポイントの数も同様に毎3パケットごとに更新される必要があります。

これまでにトラックストック搭載のv4デバイスは確認されていません。

1.11. ALPS絶対モード - プロトコルバージョン5¶

これは基本的にプロトコルバージョン3ですが、パケットデコードの論理が異なります。alps_process_touchpad_packet_v3関数を呼び出し、専用のdecode_fields関数ポインタを使用してパケットを正しく解釈します。これはDolphinデバイスにのみ使用されているようです。

単一の接触の場合、6バイトのパケット形式は：

byte 0:    1    1    0    0    1    0    0    0
byte 1:    0   x6   x5   x4   x3   x2   x1   x0
byte 2:    0   y6   y5   y4   y3   y2   y1   y0
byte 3:    0    M    R    L    1    m    r    l
byte 4:   y10  y9   y8   y7  x10   x9   x8   x7
byte 5:    0   z6   z5   z4   z3   z2   z1   z0

MTの場合、形式は：

byte 0:    1    1    1    n3   1   n2   n1   x24
byte 1:    1   y7   y6    y5  y4   y3   y2    y1
byte 2:    ?   x2   x1   y12 y11  y10   y9    y8
byte 3:    0  x23  x22   x21 x20  x19  x18   x17
byte 4:    0   x9   x8    x7  x6   x5   x4    x3
byte 5:    0  x16  x15   x14 x13  x12  x11   x10

1.12. ALPS絶対モード - プロトコルバージョン6¶

トラックストックパケットの形式は次の通りです:

byte 0:    1    1    1    1    1    1    1    1
byte 1:    0   X6   X5   X4   X3   X2   X1   X0
byte 2:    0   Y6   Y5   Y4   Y3   Y2   Y1   Y0
byte 3:    ?   Y7   X7    ?    ?    M    R    L
byte 4:   Z7   Z6   Z5   Z4   Z3   Z2   Z1   Z0
byte 5:    0    1    1    1    1    1    1    1

タッチパッドパケットの形式は次の通りです:

byte 0:    1    1    1    1    1    1    1    1
byte 1:    0    0    0    0   x3   x2   x1   x0
byte 2:    0    0    0    0   y3   y2   y1   y0
byte 3:    ?   x7   x6   x5   x4    ?    r    l
byte 4:    ?   y7   y6   y5   y4    ?    ?    ?
byte 5:   z7   z6   z5   z4   z3   z2   z1   z0

(v6タッチパッドは中央ボタンを持ちません)

1.13. ALPS Absolute Mode - プロトコルバージョン7¶

トラックストックパケットの形式は次の通りです:

byte 0:    0    1    0    0    1    0    0    0
byte 1:    1    1    *    *    1    M    R    L
byte 2:   X7    1   X5   X4   X3   X2   X1   X0
byte 3:   Z6    1   Y6   X6    1   Y2   Y1   Y0
byte 4:   Y7    0   Y5   Y4   Y3    1    1    0
byte 5:  T&P    0   Z5   Z4   Z3   Z2   Z1   Z0

タッチパッドパケットの形式は次の通りです:

        packet-fmt     b7     b6     b5     b4     b3     b2     b1     b0
byte 0: TWO & MULTI     L      1      R      M      1   Y0-2   Y0-1   Y0-0
byte 0: NEW             L      1   X1-5      1      1   Y0-2   Y0-1   Y0-0
byte 1:             Y0-10   Y0-9   Y0-8   Y0-7   Y0-6   Y0-5   Y0-4   Y0-3
byte 2:             X0-11      1  X0-10   X0-9   X0-8   X0-7   X0-6   X0-5
byte 3:             X1-11      1   X0-4   X0-3      1   X0-2   X0-1   X0-0
byte 4: TWO         X1-10    TWO   X1-9   X1-8   X1-7   X1-6   X1-5   X1-4
byte 4: MULTI       X1-10    TWO   X1-9   X1-8   X1-7   X1-6   Y1-5      1
byte 4: NEW         X1-10    TWO   X1-9   X1-8   X1-7   X1-6      0      0
byte 5: TWO & NEW   Y1-10      0   Y1-9   Y1-8   Y1-7   Y1-6   Y1-5   Y1-4
byte 5: MULTI       Y1-10      0   Y1-9   Y1-8   Y1-7   Y1-6    F-1    F-0

L:         Left button
R / M:     Non-clickpads: Right / Middle button
           Clickpads: When > 2 fingers are down, and some fingers
           are in the button area, then the 2 coordinates reported
           are for fingers outside the button area and these report
           extra fingers being present in the right / left button
           area. Note these fingers are not added to the F field!
           so if a TWO packet is received and R = 1 then there are
           3 fingers down, etc.
TWO:       1: Two touches present, byte 0/4/5 are in TWO fmt
           0: If byte 4 bit 0 is 1, then byte 0/4/5 are in MULTI fmt
              otherwise byte 0 bit 4 must be set and byte 0/4/5 are
              in NEW fmt
F:         Number of fingers - 3, 0 means 3 fingers, 1 means 4 ...

1.14. ALPS Absolute Mode - プロトコルバージョン8¶

SS4 (73 03 14)およびSS5 (73 03 28)ハードウェアで使用されます。

パケットタイプはAPDフィールド（バイト3のビット4〜5）によって指定されます。

タッチパッドパケット（APD = 0x2）:

          b7   b6   b5   b4   b3   b2   b1   b0
byte 0:  SWM  SWR  SWL    1    1    0    0   X7
byte 1:    0   X6   X5   X4   X3   X2   X1   X0
byte 2:    0   Y6   Y5   Y4   Y3   Y2   Y1   Y0
byte 3:    0  T&P    1    0    1    0    0   Y7
byte 4:    0   Z6   Z5   Z4   Z3   Z2   Z1   Z0
byte 5:    0    0    0    0    0    0    0    0

SWM、SWR、SWL: 中央、右、左のボタン状態

タッチパッド1指パケット（APD = 0x0）:

          b7   b6   b5   b4   b3   b2   b1   b0
byte 0:  SWM  SWR  SWL    1    1   X2   X1   X0
byte 1:   X9   X8   X7    1   X6   X5   X4   X3
byte 2:    0  X11  X10  LFB   Y3   Y2   Y1   Y0
byte 3:   Y5   Y4    0    0    1 TAPF2 TAPF1 TAPF0
byte 4:  Zv7  Y11  Y10    1   Y9   Y8   Y7   Y6
byte 5:  Zv6  Zv5  Zv4    0  Zv3  Zv2  Zv1  Zv0

TAPF: ??? LFB: ???

タッチパッド2指パケット（APD = 0x1）:

          b7   b6   b5   b4   b3   b2   b1   b0
byte 0:  SWM  SWR  SWL    1    1  AX6  AX5  AX4
byte 1: AX11 AX10  AX9  AX8  AX7  AZ1  AY4  AZ0
byte 2: AY11 AY10  AY9  CONT AY8  AY7  AY6  AY5
byte 3:    0    0    0    1    1  BX6  BX5  BX4
byte 4: BX11 BX10  BX9  BX8  BX7  BZ1  BY4  BZ0
byte 5: BY11 BY10  BY9    0  BY8  BY7  BY5  BY5

CONT: 3または4指のパケットが続きます

タッチパッド3または4指パケット（APD = 0x3）:

          b7   b6   b5   b4   b3   b2   b1   b0
byte 0:  SWM  SWR  SWL    1    1  AX6  AX5  AX4
byte 1: AX11 AX10  AX9  AX8  AX7  AZ1  AY4  AZ0
byte 2: AY11 AY10  AY9  OVF  AY8  AY7  AY6  AY5
byte 3:    0    0    1    1    1  BX6  BX5  BX4
byte 4: BX11 BX10  BX9  BX8  BX7  BZ1  BY4  BZ0
byte 5: BY11 BY10  BY9    0  BY8  BY7  BY5  BY5
