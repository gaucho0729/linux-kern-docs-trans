10.1. はじめに¶

このドキュメントは、I-Force 2.0デバイスに力の効果を指定するプロトコルについて私が発見した情報を説明しています。この情報はImmerseから来ていません。そのため、このドキュメントに書かれている内容を信用しないでください。このドキュメントはプロトコルを理解するためのものです。これは参考書ではありません。コメントや訂正は歓迎します。お問い合わせはメールでお願いします: johann.deneux@gmail.com

警告

このドキュメントに書かれている内容に基づいてI-Forceデバイスにデータを送信した結果生じた損害や被害については、私は責任を負いません。

10.2. 事前注意事項¶

すべての値は16進数で、ビッグエンディアン（MSBが左側）でエンコードされています。注意してください、パケット内の値はリトルエンディアンでエンコードされています。役割が不明なバイトは???でマークされ、より深い検証が必要な情報は?でマークされます。

10.2.1. パケットの一般的な形式¶

デバイスがRS-232を介して通信する場合のパケットの形式です。

2B

OP

LEN

DATA

CS

CSはチェックサムです。これはすべてのバイトの排他的論理和（XOR）に等しいです。

USBを使用する場合:

OP

DATA

2B、LEN、CSフィールドは消失しています。おそらくUSBがフレームを処理し、データ腐敗は処理されるか無視されるためです。

まず、デバイスがコンピュータに送信する効果について説明します

10.3. デバイスの入力状態¶

このパケットは、各ボタンの状態と各軸の値を示すために使用されます:

OP= 01 for a joystick, 03 for a wheel
LEN= Varies from device to device
00 X-Axis lsb
01 X-Axis msb
02 Y-Axis lsb, or gas pedal for a wheel
03 Y-Axis msb, or brake pedal for a wheel
04 Throttle
05 Buttons
06 Lower 4 bits: Buttons
   Upper 4 bits: Hat
07 Rudder

10.4. デバイスの効果状態¶

OP= 02
LEN= Varies
00 ? Bit 1 (Value 2) is the value of the deadman switch
01 Bit 8 is set if the effect is playing. Bits 0 to 7 are the effect id.
02 ??
03 Address of parameter block changed (lsb)
04 Address of parameter block changed (msb)
05 Address of second parameter block changed (lsb)
... depending on the number of parameter blocks updated

10.4.1. 力の効果¶

OP=  01
LEN= 0e
00 Channel (when playing several effects at the same time, each must
            be assigned a channel)
01 Wave form
        Val 00 Constant
        Val 20 Square
        Val 21 Triangle
        Val 22 Sine
        Val 23 Sawtooth up
        Val 24 Sawtooth down
        Val 40 Spring (Force = f(pos))
        Val 41 Friction (Force = f(velocity)) and Inertia
               (Force = f(acceleration))


02 Axes affected and trigger
        Bits 4-7: Val 2 = effect along one axis. Byte 05 indicates direction
                Val 4 = X axis only. Byte 05 must contain 5a
                Val 8 = Y axis only. Byte 05 must contain b4
                Val c = X and Y axes. Bytes 05 must contain 60
        Bits 0-3: Val 0 = No trigger
                Val x+1 = Button x triggers the effect
        When the whole byte is 0, cancel the previously set trigger

03-04 Duration of effect (little endian encoding, in ms)

05 Direction of effect, if applicable. Else, see 02 for value to assign.

06-07 Minimum time between triggering.

08-09 Address of periodicity or magnitude parameters
0a-0b Address of attack and fade parameters, or ffff if none.
*or*
08-09 Address of interactive parameters for X-axis,
      or ffff if not applicable
0a-0b Address of interactive parameters for Y-axis,
      or ffff if not applicable

0c-0d Delay before execution of effect (little endian encoding, in ms)

10.4.2. 時間ベースのパラメータ¶

10.4.2.1. アタックとフェード¶

OP=  02
LEN= 08
00-01 Address where to store the parameters
02-03 Duration of attack (little endian encoding, in ms)
04 Level at end of attack. Signed byte.
05-06 Duration of fade.
07 Level at end of fade.

10.4.2.2. 強度¶

OP=  03
LEN= 03
00-01 Address
02 Level. Signed byte.

10.4.2.3. 周期性¶

OP=  04
LEN= 07
00-01 Address
02 Magnitude. Signed byte.
03 Offset. Signed byte.
04 Phase. Val 00 = 0 deg, Val 40 = 90 degs.
05-06 Period (little endian encoding, in ms)

10.4.3. インタラクティブなパラメータ¶

OP=  05
LEN= 0a
00-01 Address
02 Positive Coeff
03 Negative Coeff
04+05 Offset (center)
06+07 Dead band (Val 01F4 = 5000 (decimal))
08 Positive saturation (Val 0a = 1000 (decimal) Val 64 = 10000 (decimal))
09 Negative saturation

ここでのエンコードは少し不思議です: コエフィシエント（coeffs）は符号付き値です。最大値は64（10進数で100）、最小値は9cです。オフセットの最小値はFE0C、最大値は01F4です。デッドバンドの最小値は0、最大値は03E8です。

10.4.4. コントロール¶

OP=  41
LEN= 03
00 Channel
01 Start/Stop
        Val 00: Stop
        Val 01: Start and play once.
        Val 41: Start and play n times (See byte 02 below)
02 Number of iterations n.

10.4.5. 初期化¶

10.4.5.1. 機能の照会¶

OP=  ff
Query command. Length varies according to the query type.
The general format of this packet is:
ff 01 QUERY [INDEX] CHECKSUM
responses are of the same form:
FF LEN QUERY VALUE_QUERIED CHECKSUM2
where LEN = 1 + length(VALUE_QUERIED)
10.4.5.1.1. RAMサイズの照会¶
QUERY = 42 ('B'uffer size)

デバイスは同じパケットに加えて、メモリのサイズを含む2つの追加バイトを返信する必要があります: ff 03 42 03 e8 CS は、デバイスが1000バイトのRAMを有していることを意味します。

10.4.5.1.2. 効果の数の照会¶
QUERY = 4e ('N'umber of effects)

デバイスは同時に実行可能な効果の数（1バイト）を送信して応答する必要があります: ff 02 4e 14 CS は20効果を表します。

10.4.5.1.3. ベンダーID¶
QUERY = 4d ('M'anufacturer)

ベンダーIDを照会する（2バイト）

10.4.5.1.4. 製品ID¶
QUERY = 50 ('P'roduct)

製品IDを照会する（2バイト）

10.4.5.1.5. デバイスを開く¶
QUERY = 4f ('O'pen)

データが返されません。

10.4.5.1.6. デバイスを閉じる¶
QUERY = 43 ('C')lose

データが返されません。

10.4.5.1.7. 効果を照会する¶
QUERY = 45 ('E')

効果タイプを送信。サポートされている場合、ゼロ以外の値を返します（2バイト）

10.4.5.1.8. ファームウェア バージョン¶
QUERY = 56 ('V'ersion)

3バイトを送信 - メジャーバージョン、マイナーバージョン、サブマイナーバージョン

10.4.5.2. デバイスの初期化¶

10.4.5.2.1. 制御を設定¶

注意

デバイス依存で、モデルによって異なります！

OP=  40 <idx> <val> [<val>]
LEN= 2 or 3
00 Idx
   Idx 00 Set dead zone (0..2048)
   Idx 01 Ignore Deadman sensor (0..1)
   Idx 02 Enable comm watchdog (0..1)
   Idx 03 Set the strength of the spring (0..100)
   Idx 04 Enable or disable the spring (0/1)
   Idx 05 Set axis saturation threshold (0..2048)
10.4.5.2.2. 効果状態を設定¶
OP=  42 <val>
LEN= 1
00 State
   Bit 3 Pause force feedback
   Bit 2 Enable force feedback
   Bit 0 Stop all effects
10.4.5.2.3. 全体を設定¶
OP=  43 <val>
LEN= 1
00 Gain
   Val 00 = 0%
   Val 40 = 50%
   Val 80 = 100%

10.4.6. パラメータ メモリ¶

各デバイスは、効果のパラメータを保存するための一定量のメモリを持っています。RAMの量は異なります。私は200から1000バイトまでの値を確認しました。以下に、各パラメータセットに必要なメモリ量を示します：

  • 周期 : 0c

  • 強度 : 02

  • アタックとフェード : 0e

  • インタラクティブ : 08

10.5. 付録: プロトコルを学ぶ方法？¶

1. DirectX SDKに同梱されているフォースエディタを使用して効果を生成するか、Immersion Studioを使用してください（開発者セクションで無料で入手可能：www.immersion.com）。2. RS232またはUSB（ジョイストリック/ホイールを接続した場所に応じて）をソフトウェアで監視を開始します。私はfCoderからComPortSpyを使用しました（アルファ版！）。3. 効果を再生し、監視画面で何が起こるか確認してください。

ComPortSpyについて少し: 初見では、このソフトウェアは、うーん、まあ… バグっているように見えます。実際、データは数秒の遅延で表示されます。私自身は、効果を再生するたびに再起動します。無料（ビールが無料）でアルファ版であることを覚えておいてください！

10.6. URLS¶

確認 http://www.immerse.com Immersion Studio用、および http://www.fcoder.com ComPortSpy用。
