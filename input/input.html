1.1. アーキテクチャ¶

入力サブシステムは、Linuxですべての入力デバイスをサポートするためのドライバのコレクションで設計されています。ほとんどのドライバはdrivers/inputに配置されていますが、いくつかはdrivers/hidおよびdrivers/platformにあります。

入力サブシステムのコアは入力モジュールで、これに続いて他のすべての入力モジュールをロードする必要があります。これは、2つのモジュールグループ間の通信のための方法として機能します:

1.1.1. デバイスドライバー¶

これらのモジュールはハードウェア（たとえばUSB経由）と通信し、キーボード入力やマウスの動きなどのイベントを入力モジュールに提供します。

1.1.2. イベントハンドラ¶

これらのモジュールは入力コアからイベントを受け取り、必要に応じてさまざまなインターフェースを介して他の場所に転送します。たとえばキーボード入力はカーネルに、マウスの動きはGPMおよびXにシミュレートされたPS/2インターフェース経由で転送されます。

1.2. シンプルな使用方法¶

1つのUSBマウスと1つのUSBキーボードで構成される一般的な設定では、以下のモジュールをロードする必要があります（またはカーネルに組み込まれている必要があります）:

input
mousedev
usbcore
uhci_hcd or ohci_hcd or ehci_hcd
usbhid
hid_generic

これにより、USBキーボードはすぐに動作し、USBマウスは/dev/inputにmajor 13、minor 63のキャラクターデバイスとして利用可能になります:

crw-r--r--   1 root     root      13,  63 Mar 28 22:45 mice

このデバイスは通常システムによって自動的に作成されます。手動で作成するコマンドは以下の通りです:

cd /dev
mkdir input
mknod input/mice c 13 63

その後、GPM（テキストモードのマウスカット＆ペーストツール）とXFree86をこのデバイスに指定して使用する必要があります。GPMは以下のように呼び出されます:

gpm -t ps2 -m /dev/input/mice

そしてXでは:

Section "Pointer"
    Protocol    "ImPS/2"
    Device      "/dev/input/mice"
    ZAxisMapping 4 5
EndSection

以上の手順をすべて実行すると、USBマウスとキーボードを使用できるようになります。

1.3. 詳細な説明¶

1.3.1. イベントハンドラ¶

イベントハンドラは、デバイスから生成されたイベントを必要に応じてユーザースペースとカーネル内の消費者に配布します。

1.3.1.1. evdev¶

evdev は汎用的な入力イベントインターフェースで、カーネルで生成されたイベントをプログラムにタイムスタンプとともに直接渡します。イベントコードはすべてのアーキテクチャで同じであり、ハードウェアに依存しません。

これはユーザースペースがユーザー入力を受け取るための推奨インターフェースであり、すべてのクライアントがこれを使用することを推奨します。

参照 イベントインターフェース APIに関する注意点

デバイスは/dev/inputにあります:

crw-r--r--   1 root     root      13,  64 Apr  1 10:49 event0
crw-r--r--   1 root     root      13,  65 Apr  1 10:50 event1
crw-r--r--   1 root     root      13,  66 Apr  1 10:50 event2
crw-r--r--   1 root     root      13,  67 Apr  1 10:50 event3
...

2つのマイナー範囲があります：64から95は静的なレガシー範囲です。システム内の入力デバイスが32を超える場合、追加のevdevノードがマイナー256から作成されます。

1.3.1.2. keyboard¶

keyboard はカーネル内での入力ハンドラで、VTコードの一部です。キーボードのキーパスを消費し、VTコンソールのユーザー入力を処理します。

1.3.1.3. mousedev¶

mousedev はレガシーのマウス入力を利用するプログラムを動作させるためのハックです。マウスまたはデジタイザ/タブレットからのイベントを取得し、ユーザー空間にPS/2スタイル（/dev/psauxのように）のマウスデバイスを提供します。

/dev/input内のmousedevデバイス（上記のように表示されます）は:

crw-r--r--   1 root     root      13,  32 Mar 28 22:45 mouse0
crw-r--r--   1 root     root      13,  33 Mar 29 00:41 mouse1
crw-r--r--   1 root     root      13,  34 Mar 29 00:41 mouse2
crw-r--r--   1 root     root      13,  35 Apr  1 10:50 mouse3
...
...
crw-r--r--   1 root     root      13,  62 Apr  1 10:50 mouse30
crw-r--r--   1 root     root      13,  63 Apr  1 10:50 mice

Each mouse デバイスは1つのマウスまたはデジタイザに割り当てられ、最後のものは除く。 miceこの1文字のデバイスはすべてのマウスおよびデジタイザで共有され、マウスが接続されていない場合でもデバイスは存在します。これはホットプラグ可能なUSBマウスの使用に便利で、古いプログラムがホットプラグを処理しない場合でも、マウスが接続されていない状態でもデバイスを開けることができます。

カーネル構成のCONFIG_INPUT_MOUSEDEV_SCREEN_[XY]は、XFree86における画面のサイズ（ピクセル数）を表します。Xでデジタイザを使用したい場合、その移動が仮想PS/2マウス経由でXに送信されるため、スケーリングが必要なためです。マウスのみを使用する場合はこれらの値は使用されません。

Mousedevは、読み込むプログラムの希望に応じてPS/2、ImPS/2（Microsoft IntelliMouse）またはExplorerPS/2（IntelliMouse Explorer）プロトコルのいずれかを生成します。GPMとXはこれらいずれかに設定できます。USBマウスのホイールを使用するにはImPS/2、追加の（最大5つ）ボタンを使用するにはExplorerPS/2が必要です。

1.3.1.4. joydev¶

joydev v0.xおよびv1.xのLinuxジョystick APIを実装しています。参照 プログラミングインターフェース 詳しくは以下をご参照ください。

ジョystickが接続されるとすぐに、/dev/inputの以下の場所でアクセス可能です：

crw-r--r--   1 root     root      13,   0 Apr  1 10:50 js0
crw-r--r--   1 root     root      13,   1 Apr  1 10:50 js1
crw-r--r--   1 root     root      13,   2 Apr  1 10:50 js2
crw-r--r--   1 root     root      13,   3 Apr  1 10:50 js3
...

js31までのレガシーレンジに続き、ジョystickデバイスがさらに多い場合はマイナーデバイス番号256を超える追加のノードが作成されます。

1.3.2. デバイスドライバー¶

デバイスドライバはイベントを生成するモジュールです。

1.3.2.1. hid-generic¶

hid-generic 全体のドライバーライブラリの中で最大かつ最も複雑なドライバーです。すべてのHIDデバイスを処理しますが、HIDのUSB仕様が複雑で、デバイスの種類も非常に多いため、このような規模が必要です。

現在、USBマウス、ジョystick、ゲームパッド、ステアリングホイールキーボード、トラックボール、デジタイザを処理しています。

ただし、USBはモニター制御、スピーカー制御、UPS、LCDなど多くの用途でHIDも使用しています。

モニターおよびスピーカーの制御はhid/inputインターフェースに簡単に追加できるかもしれませんが、UPSやLCDについては意味がありません。このような用途にはhiddevインターフェースが設計されました。参照 Human Interface Devicesのお手入れガイド 詳しくはここを参照してください。

usbhidモジュールの使用は非常に簡単で、パラメータを指定せず自動的にすべてを検出します。HIDデバイスが挿入されると適切に検出されます。

ただし、デバイスの種類が多岐にわたるため、特定のデバイスがうまく動作しない場合があります。その場合はhid-core.cの冒頭に#define DEBUGを定義し、syslogトレースを送ってください。

1.3.2.2. usbmouse¶

埋め込みシステムや、HIDデスクリプタが破損したマウスや、usbhidを使用するのに適していない他の用途には、usbmouseドライバが利用できます。これはUSBマウス専用のドライバで、よりシンプルなHIDBPプロトコルを使用します。このため、マウスがこのシンプルなプロトコルをサポートしている必要があります。すべてのマウスがサポートしているわけではありません。特に強い理由がない限り、usbhidを使用してください。

1.3.2.3. usbkbd¶

usbmouseと同様に、簡略化されたHIDBPプロトコルでキーボードと通信します。サイズは小さく、特別なキーをサポートしていません。特別な理由がない場合は、usbhidを使用してください。

1.3.2.4. psmouse¶

PS/2プロトコルを使用したすべてのポインティングデバイス（SynapticsやALPSのタッチパッド、Intellimouse Explorerデバイス、LogitechのPS/2マウスなど）のドライバです。

1.3.2.5. atkbd¶

PS/2（AT）キーボード用のドライバです。

1.3.2.6. iforce¶

I-Forceのジョイスティックとホイール（USBおよびRS232経由）用のドライバです。Force Feedbackのサポートが含まれていますが、Immersion Corp.はこのプロトコルを商標権として扱い、詳細を公表していません。

1.4. 動作確認¶

キーボードでいくつかのキーを入力するだけで、キーボードが正常に動作し、カーネルのキーボードドライバに正しく接続されているか確認できます。

Doing a cat /dev/input/mouse0 (c, 13, 32)はマウスがエミュレートされているかを確認します。マウスを動かすと文字が表示されます。

You can test the joystick emulation with the jstest utility, available in the joystick package (see はじめに).

You can test the event devices with the evtest utility.

1.5. イベントインターフェース¶

You can use blocking and nonblocking reads, and also select() on the /dev/input/eventX devices, and you’ll always get a whole number of input events on a read. Their layout is:

struct input_event {
        struct timeval time;
        unsigned short type;
        unsigned short code;
        unsigned int value;
};

time タイムスタンプで、イベントが発生した時間です。タイプは例えばEV_REL（相対座標）やEV_KEY（キーの押下・解放）など。詳細はinclude/uapi/linux/input-event-codes.hを参照してください。

code イベントコードで、例えばREL_XやKEY_BACKSPACEなど。詳細はinclude/uapi/linux/input-event-codes.hを参照してください。

value イベントが持つ値で、EV_RELでは相対変化、EV_ABSでは絶対値（ジョイスティックなど）、EV_KEYでは0（解放）、1（押下）、2（自動繰り返し）が設定されます。

参照 入力イベントコード イベントコードに関する詳細情報についてはこちらを参照してください。
