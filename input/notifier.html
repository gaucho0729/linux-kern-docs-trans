3. キーボード通知¶

register_keyboard_notifier関数を使用することで、キーボードイベントに応答するコールバックを取得できます（詳しい情報はkbd_keycode()関数を参照してください）。渡される構造体はkeyboard_notifier_paramです。

  • ‘vc’は常に、キーボードイベントが適用されるVCを提供します;

  • ‘down’はキープレスイベントの場合1、キーリリースの場合0です;

  • ‘shift’は現在のモディファイア状態を表し、マスクビットのインデックスはKG_*です;

  • ‘value’はイベントの種類に依存します。

  • KBD_KEYCODEイベントは他のイベントよりも常に先に送信され、valueはキーコードです。

  • キーコードがkeysymにバインドされていない場合、KBD_UNBOUND_KEYCODEイベントが送信されます。valueはキーコードです。

  • キーコードからkeysymへの変換結果がUnicode文字だった場合、KBD_UNICODEイベントが送信されます。valueはUnicode値です。

  • キーコードからkeysymへの変換結果がUnicode文字でない場合、KBD_KEYSYMイベントが送信されます。valueはkeysymです。

  • 非Unicode keysymの処理の後にKBD_POST_KEYSYMイベントが送信されます。これにより、結果のLEDを確認できるなどします。

最後のイベントを除き、各イベント種別のコールバックはNOTIFY_STOPを返すことでイベントを「食べ」ることができます。通知ループが停止され、キーボードイベントが無視されます。

ざっくりとしたCコードスニペットでは、以下のようにします:

kbd_keycode(keycode) {
    ...
    params.value = keycode;
    if (notifier_call_chain(KBD_KEYCODE,&params) == NOTIFY_STOP)
        || !bound) {
            notifier_call_chain(KBD_UNBOUND_KEYCODE,&params);
            return;
    }

    if (unicode) {
            param.value = unicode;
            if (notifier_call_chain(KBD_UNICODE,&params) == NOTIFY_STOP)
                    return;
            emit unicode;
            return;
    }

    params.value = keysym;
    if (notifier_call_chain(KBD_KEYSYM,&params) == NOTIFY_STOP)
            return;
    apply keysym;
    notifier_call_chain(KBD_POST_KEYSYM,&params);
}

注意

この通知は通常、割込みコンテキストから呼び出されます。
