5.1. はじめに¶

このドキュメントは、Linux環境でのフォースフィードバックデバイスの使用方法を説明しています。目標は、これらのデバイスを単なる入力デバイスとして扱うのではなく、実際に力の効果をレンダリングできるようにすることです。このドキュメントはLinux入力インターフェースのフォースフィードバック部分のみを説明しています。このドキュメントを読む前に、joystick.txtとinput.txtを読みましょう。

5.2. ユーザーへの指示¶

フォースフィードバックを有効にするには、以下の手順を実施してください。

  1. カーネルがevdevと、あなたのデバイスをサポートするドライバで構成されている必要があります。

  2. evdevモジュールがロードされ、/dev/input/event*デバイスファイルが作成されていることを確認してください。

開始する前に、いくつかのデバイスが初期化フェーズで激しく振動することがあります。これは私の「AVB Top Shot Pegasus」で確認されています。この不快な挙動を停止するには、ジョイストickを極限まで動かしてください。いずれにしても、何かがうまくいかない場合にデバイスを壊さないために、常に手を置いたままにしておくべきです。

シリアル接続のiforceデバイスを使用している場合は、inputattachを起動する必要があります。詳細はjoystick.txtを参照してください。

5.2.1. 動作しますか？¶

ffttestというユーティリティを使用してドライバをテストできます:

% fftest /dev/input/eventXX

5.3. 開発者への指示¶

すべてのインタラクションはevent APIを使用して行われます。つまり、/dev/input/eventXXに対してioctl()とwrite()を使用できます。この情報は変更される可能性があります。

5.3.1. デバイスの機能を照合する¶

#include <linux/input.h>
#include <sys/ioctl.h>

#define BITS_TO_LONGS(x) \
        (((x) + 8 * sizeof (unsigned long) - 1) / (8 * sizeof (unsigned long)))
unsigned long features[BITS_TO_LONGS(FF_CNT)];
int ioctl(int file_descriptor, int request, unsigned long *features);

「request」はEVIOCGBIT(EV_FF, features配列のバイト数)でなければなりません

デバイスがサポートする機能を返します。featuresは以下のビットを持つビットフィールドです:

  • FF_CONSTANTは定常力の効果をレンダリングできます

  • FF_PERIODICは以下の波形を持つ周期的な効果をレンダリングできます:

    • FF_SQUAREは正方形波形

    • FF_TRIANGLEは三角波形

    • FF_SINEは正弦波形

    • FF_SAW_UPは上向きの锯齿波

    • FF_SAW_DOWNは下向きの锯齿波

    • FF_CUSTOMはカスタム波形

  • FF_RAMPはランプ効果をレンダリングできます

  • FF_SPRINGはスプリングの存在をシミュレートできます

  • FF_FRICTIONは摩擦をシミュレートできます

  • FF_DAMPERはダンパ効果をシミュレートできます

  • FF_RUMBLEは振動効果

  • FF_INERTIAは慣性をシミュレートできます

  • FF_GAINはゲインを調整できます

  • FF_AUTOCENTERは自動センターを調整できます

注意

  • ほとんどの場合、FF_PERIODICをFF_RUMBLEよりも使用すべきです。FF_RUMBLEをサポートするすべてのデバイスはFF_PERIODIC（正方形、三角形、正弦波）をサポートし、逆もしかりです。

  • 一時的にFF_CUSTOMの正確な構文は未定義ですが、まだどのドライバもサポートしていません。

int ioctl(int fd, EVIOCGEFFECTS, int *n);

デバイスがメモリに保持できるエフェクトの数を返します。

5.3.2. デバイスへのエフェクトのアップロード¶

#include <linux/input.h>
#include <sys/ioctl.h>

int ioctl(int file_descriptor, int request, struct ff_effect *effect);

「request」はEVIOCSFFでなければなりません。

「effect」はアップロードするエフェクトを記述する構造体を指します。エフェクトはアップロードされますが再生されません。effectの内容は変更可能です。特に、「id」フィールドはドライバが割り当てる一意のIDに設定されます。このデータは、一部の操作（エフェクトの削除、再生の制御）を行うために必要です。「id」フィールドはユーザーが-1に設定することで、ドライバに新しいエフェクトを割り当てるよう指示します。

エフェクトはファイル記述子に依存します。

ff_effect構造体の説明については<uapi/linux/input.h>を参照してください。また、shape.svgおよびinteractive.svgに含まれるいくつかのスケッチにも参考になるでしょう：

5.3.3. デバイスからエフェクトを削除する¶

int ioctl(int fd, EVIOCRMFF, effect.id);

デバイスのメモリに新たなエフェクトを確保します。注意点として、この操作はエフェクトが再生中であれば停止することも含まれます。

5.3.4. エフェクトの再生を制御する¶

再生の制御はwrite()で行われます。以下に例を示します：

 #include <linux/input.h>
 #include <unistd.h>

     struct input_event play;
     struct input_event stop;
     struct ff_effect effect;
     int fd;
...
     fd = open("/dev/input/eventXX", O_RDWR);
...
     /* Play three times */
     play.type = EV_FF;
     play.code = effect.id;
     play.value = 3;

     write(fd, (const void*) &play, sizeof(play));
...
     /* Stop an effect */
     stop.type = EV_FF;
     stop.code = effect.id;
     stop.value = 0;

     write(fd, (const void*) &stop, sizeof(stop));

5.3.5. ゲインの設定¶

すべてのデバイスが同じ強度を持つわけではありません。そのため、ユーザーはエフェクトの強さを調整するためのゲイン係数を設定する必要があります。この設定はドライバへのアクセスに関係なく永続的に保持されます。

/* Set the gain of the device
int gain;           /* between 0 and 100 */
struct input_event ie;      /* structure used to communicate with the driver */

ie.type = EV_FF;
ie.code = FF_GAIN;
ie.value = 0xFFFFUL * gain / 100;

if (write(fd, &ie, sizeof(ie)) == -1)
    perror("set gain");

5.3.6. オートセンターの有効化/無効化¶

オートセンター機能は私の意見ではエフェクトのレンダリングをかなり邪魔するため、ゲームの種類に応じて計算されるエフェクトとして扱うべきだと考えています。ただし、必要であれば有効化することも可能です。

int autocenter;             /* between 0 and 100 */
struct input_event ie;

ie.type = EV_FF;
ie.code = FF_AUTOCENTER;
ie.value = 0xFFFFUL * autocenter / 100;

if (write(fd, &ie, sizeof(ie)) == -1)
    perror("set auto-center");

値が0の場合は「オートセンターなし」を意味します。

5.3.7. エフェクトの動的更新¶

新しいエフェクトをアップロードするように処理しますが、idフィールドを-1に設定する代わりに、望むエフェクトidに設定します。通常、エフェクトは停止せず再開されません。ただし、デバイスの種類によってはすべてのパラメータを動的に更新できない場合があります。例えば、iforceデバイスではエフェクトの方向は更新できません。その場合、ドライバはエフェクトを停止し、アップロードし、再開します。

したがって、エフェクトが再生中に方向を動的に変更する際には、再開回数が1の場合でも再起動が問題にならない場合に限って推奨されます。

5.3.8. エフェクトの状態に関する情報¶

エフェクトの状態が変更されるたびにイベントが送信されます。イベントのフィールドの値と意味は以下の通りです：

struct input_event {
/* When the status of the effect changed */
        struct timeval time;

/* Set to EV_FF_STATUS */
        unsigned short type;

/* Contains the id of the effect */
        unsigned short code;

/* Indicates the status */
        unsigned int value;
};

FF_STATUS_STOPPED   The effect stopped playing
FF_STATUS_PLAYING   The effect started to play

  • 状態フィードバックはiforceドライバのみがサポートしています。本当に必要な理由がある場合は、 linux-joystick@atrey.karlin.mff.cuni.cz または anssi.hannula@gmail.com それのサポートが他のドライバーに統合されるように
