PXA25x LCDコントローラー用ドライバ¶

このドライバーは、モジュールとして使用する場合は options=<OPTIONS>、内蔵で使用する場合は video=pxafb:<OPTIONS> で、以下のオプションをサポートしています。

例:

modprobe pxafb options=vmem:2M,mode:640x480-8,passive

またはカーネル コマンドラインで:

video=pxafb:vmem:2M,mode:640x480-8,passive

vmem: VIDEO_MEM_SIZE

割り当てるビデオメモリの量（K や M でキロバイトまたはメガバイトを指定可能です）

mode:XRESxYRES[-BPP]

XRES == LCCR1_PPL + 1

YRES == LLCR2_LPP + 1

ディスプレイの解像度（ピクセル単位）

BPP == ビット深度。有効な値は 1, 2, 4, 8 および 16 です。

pixclock:PIXCLOCK

ピクセル時計（ピコ秒単位）

left:LEFT == LCCR1_BLW + 1

right:RIGHT == LCCR1_ELW + 1

hsynclen:HSYNC == LCCR1_HSW + 1

upper:UPPER == LCCR2_BFW

lower:LOWER == LCCR2_EFR

vsynclen:VSYNC == LCCR2_VSW + 1

ディスプレイのマージンおよび同期時間

color | mono => LCCR0_CMS

umm…

active | passive => LCCR0_PAS

アクティブ（TFT）またはパッシブ（STN）ディスプレイ

single | dual => LCCR0_SDS

シングルパネルまたはダブルパネルのパッシブディスプレイ

4pix | 8pix => LCCR0_DPD

4 ピクセルまたは 8 ピクセルのモノクロシングルパネルデータ

hsync:HSYNC, vsync:VSYNC

水平および垂直同期。0 => アクティブロー、1 => アクティブハイ

dpc:DPC

ダブルピクセル時計。1=>有効、0=>無効

outputen:POLARITY

出力有効極性。0 => アクティブロー、1 => アクティブハイ

pixclockpol:POLARITY

ピクセル時計極性 0 => 下降エッジ、1 => 上昇エッジ

PXA27x 以降のLCDコントローラーにおけるオーバーレイサポート¶

PXA27x 以降のプロセッサは、ベースフレームバッファの上に overlay1 および overlay2 をサポートしています（ベースの下にも可能）。パレットおよびパレットなしのRGB形式、およびYUV形式（overlay2 にのみ利用可能）をサポートしています。これらのオーバーレイには専用DMAチャネルがあり、フレームバッファと同様の動作を行います。

ただし、これらのオーバーレイフレームバッファと通常のフレームバッファにはいくつかの違いがあります。以下にまとめます:

  1. オーバーレイはベースフレームバッファ内の32ビットワードアライメント位置から開始可能で、これは(x, y)の開始位置を意味します。この情報はvar->nonstd（no）にエンコードされ、var->xoffset および var->yoffset はこのような用途には使用しません。

  2. オーバーレイフレームバッファは指定された ‘struct fb_var_screeninfo’ に従って動的に割り当てられ、割り当て量は以下の通り決定されます:

    var->xres_virtual * var->yres_virtual * bpp

    bpp = 16 – RGB565またはRGBT555の場合

    bpp = 24 – YUV444パック形式

    bpp = 24 – YUV444プランナ形式

    bpp = 16 – YUV422プランナ形式（1ピクセル = 1 Y + 1/2 Cb + 1/2 Cr）

    bpp = 12 – YUV420プランナ形式（1ピクセル = 1 Y + 1/4 Cb + 1/4 Cr）

    ノート:

    1. オーバーレイはx方向のパンニングをサポートしていないため、var->xres_virtualは常にvar->xresと等しくなります

    2. オーバーレイのライン長は32ビットワード境界に配置する必要があります。YUVプランナ形式では、ビット数が最小のコンポーネント（例: YUV420の場合、Crコンポーネントが2ビット）のライン長が16ピクセルの倍数になる必要があります

    3. 開始位置（XPOS）は32ビットワード境界に配置する必要があります。それ以外の場合はfb_check_var()が失敗します

    4. オーバーレイの矩形はベースプレーン内に収める必要があります。それ以外の場合は失敗します

    アプリケーションはオーバーレイフレームバッファを操作するための以下の手順に従う必要があります

    1. open(“/dev/fb[1-2]”, …)

    2. ioctl(fd, FBIOGET_VSCREENINFO, …)

    3. varを望ましいパラメータで修正:

      1. var->xresおよびvar->yres

      2. より多くのメモリが必要な場合はvar->yres_virtualを大きくしてください（通常はダブルバッファリング用）

      3. var->nonstdで開始位置(x, y)およびカラーフォーマットを指定します

      4. RGBモードを使用する場合はvar->{red, green, blue, transp}を設定してください

    4. ioctl(fd, FBIOPUT_VSCREENINFO, …)

    5. ioctl(fd, FBIOGET_FSCREENINFO, …)

    6. mmap

    7. …

  3. YUVプランナ形式はフレームバッファフレームワーク内でサポートされていません。アプリケーションはフレームバッファ内の各コンポーネントのオフセットと長さを管理する必要があります

  4. var->nonstdは開始位置(x, y)およびカラーフォーマットを渡すためのパラメータです。詳細なビットフィールドは以下の通り:

    31                23  20         10          0
 +-----------------+---+----------+----------+
 |  ... unused ... |FOR|   XPOS   |   YPOS   |
 +-----------------+---+----------+----------+

    カラーフォーマット – pxafb.hで定義されたOVERLAY_FORMAT_*

    • 0 – RGB

    • 1 – YUV444パック形式

    • 2 – YUV444プランナ形式

    • 3 – YUV422プランナ形式

    • 4 – YUR420プランナ形式

    XPOS – 開始位置（水平方向）

    YPOS – 開始位置（垂直方向）
