フレームバッファコンソール¶

フレームバッファコンソール（fbcon）は、その名前からもわかるように、フレームバッファデバイス上で動作するテキストコンソールです。VGAコンソールなどの標準テキストコンソールドライバと同様の機能を持ちつつ、フレームバッファのグラフィカルな性質に起因する追加機能も備えています。

x86アーキテクチャではフレームバッファコンソールはオプションであり、一部ではおもちゃとして扱われることもあります。他のアーキテクチャでは、テキストまたはグラフィカルな表示デバイスとして唯一の選択肢となることがあります。

fbconの特徴とは？fbconは高解像度、多様なフォントタイプ、表示回転、基本的なマルチヘッドなど、さまざまな機能をサポートしています。理論上は、グラフィックカードが提供する機能を活用した多色フォント、ブレンド、エイリアシング、あるいはその他の機能も可能です。

A. 設定¶

フレームバッファコンソールは、お好みのカーネル設定ツールを使用して有効化できます。設定は「Device Drivers->Graphics Support->Console display driver support->Framebuffer Console Support」の下にあります。'y'を選択して静的コンパイルするか、'm'を選択してモジュールとしてコンパイルするかを選んでください。モジュール名はfbconです。

fbconを有効化するには、少なくとも1つのフレームバッファドライバが必要です。そのためには、利用可能な多数のドライバの中から選択してください。x8,システムではほぼすべてのシステムがVGAカードを搭載しているため、vga16fbおよびvesafbは常に利用可能です。ただし、チップセット固有のドライバを使用すると、動的なビデオモードの変更などの機能が得られます。

ペンギンロゴを表示するには、「Graphics support->Bootup logo」で利用可能なロゴの中から選択してください。

また、少なくとも1つのコンパイルインフォントを選択する必要がありますが、何も選択しなければ、カーネル設定ツールが自動的に8x16フォントを選択します。

注意: フレームバッファを有効化したがフレームバッファコンソールを有効化していないという一般的なバグレポートがあります。ドライバによっては、画面が消えたり、乱れたりする可能性がありますが、システムは正常に起動します。グラフィックチップを変更しないドライバを使用している場合、VGAコンソールが依然として利用可能です。

B. ロード¶

可能性のあるシナリオ:

  1. ドライバとfbconが静的コンパイルされている

    通常、fbconは自動的にコンソールを引き継ぎます。ただし、vesafbは明示的にvga=というブートオプションパラメータで有効化する必要があります。

  2. ドライバが静的コンパイルされており、fbconがモジュールとしてコンパイルされている

    ドライバによっては、標準のコンソールが表示されるか、上記のように乱れた表示になることがあります。フレームバッファコンソールを取得するには、「modprobe fbcon」を実行してください。

  3. ドライバはモジュールとしてコンパイルされ、fbconは静的コンパイルされています

    標準のコンソールが表示されます。ドライバを「modprobe xxxfb」でロードすると、fbconがコンソールを自動的に取得します（fbcon=map:nオプションを使用する場合を除きます）。下記を参照してください。

  4. ドライバとfbconはどちらもモジュールとしてコンパイルされています。

    これらをロードする順序は問いません。どちらもロードされるとfbconがコンソールを取得します。

  1. ブートオプション

    フレームバッファコンソールには、動作を変更するためのいくつかのブートオプションがありますが、これらはまだよく分かっていません。

  1. fbcon=font:<name>

    使用する初期フォントを指定します。「name」には以下のコンパイル済みフォントのいずれかを指定できます: 10x18, 6x10, 6x8, 7x14, Acorn8x8, MINI4x6, PEARL8x8, ProFont6x11, SUN12x22, SUN8x16, TER16x32, VGA8x16, VGA8x8。

    注意: すべてのドライバが8で割り切れない幅のフォント（例: vga16fb）を処理できるわけではありません。

  2. fbcon=map:<0123>

    これは興味深いオプションです。どのドライバがどのコンソールにマッピングされるかを指定します。「0123」は64（利用可能なコンソール数）になるまで繰り返されます。上記の例では、012301230123…と展開され、マッピングは以下のようになります。

    tty | 1 2 3 4 5 6 7 8 9 ...
fb  | 0 1 2 3 0 1 2 3 0 ...

('cat /proc/fb' should tell you what the fb numbers are)

    有用な副作用として、ロードされたfbドライバ数より大きいマップ値を使用する場合があります。たとえば、fb0（1つのドライバのみ）が利用可能であれば、fbcon=map:1を指定するとfbconがコンソールを取得しないようにします。

    後でコンソールをフレームバッファデバイスにマッピングするには、「con2fbmap」ユーティリティを使用してください。

  3. fbcon=vc:<n1>-<n2>

    このオプションは、fbconが指定された範囲のコンソールのみを取得するようにします。「n1」と「n2」で指定された範囲外のコンソールは標準コンソールドライバで制御されます。

    注意: x86マシンでは標準コンソールはVGAコンソールであり、通常同じビデオカードに配置されます。したがって、VGAコンソールで制御されるコンソールは乱れた表示になります。

  4. fbcon=rotate:<n>

    このオプションはコンソール表示の向きを変更します。「n」には以下の値を指定できます:

    • 0 - 標準向き（0度）

    • 1 - 時計回り（90度）

    • 2 - 逆向き（180度）

    • 3 - 反時計回り（270度）

    角度はその後も「rotate」属性または「rotate_all」属性に同じ数字をエコーバックすることで変更できます。これらは/sys/class/graphics/fbconに存在する属性です:

    • rotate - 有効なコンソールの表示を回転

    • rotate_all - 全コンソールの表示を回転

    コンソールの回転機能は、カーネルにフレームバッファコンソール回転サポートがコンパイルされている場合にのみ利用可能です。

    注意: この機能は純粋にコンソールの回転に関するものであり、他のフレームバッファを使用するアプリケーションは通常の向きのままです。実際、背後で動作するfbドライバはコンソール回転を完全に無視しています。

  5. fbcon=margin:<color>

    このオプションはマージンの色を指定します。マージンは画面の右端と下端に残る、テキストに使用されない領域です。デフォルトではこの領域は黒色になります。「color」値は使用しているフレームバッファドライバに依存する整数値です。

  6. fbcon=nodefer

    カーネルにdeferred fbconオーバーテイクサポートがコンパイルされている場合、通常はファームウェア/ブートローダーが残したフレームバッファの内容は、コンソールにテキストが実際に出力されるまで保持されます。このオプションはfbconがfbdevデバイスに即座にバインドするようにします。

  7. fbcon=logo-pos:<location>

    可能な「location」は「center」（引用符なし）のみであり、指定された場合、ブートアップロゴはデフォルトの左上角からフレームバッファの中央へ移動します。複数のCPUにより複数のロゴが表示される場合、ロゴの集まり全体が中央へ移動します。

  8. fbcon=logo-count:<n>

    値「n」はブートアップロゴの数を上書きします。0はロゴの表示を無効化し、-1はデフォルト値（オンラインCPUの数）を指定します。

  1. アタッチ、デタッチ、アンロード

fbconのアタッチ、デタッチ、アンロード方法について説明する前に、依存関係の図示が理解を助けるかもしれません。

コンソールレイヤーは他のサブシステムと同様に、ハードウェアとインターフェースするドライバが必要です。したがって、VGAコンソールの場合:

console ---> VGA driver ---> hardware.

VGAドライバがアンロード可能であると仮定すると、まずVGAドライバをコンソールレイヤーからアンバインドする必要があります。VGAドライバはコンソールレイヤーにまだバインドされている場合、アンロードできません。(参照 コンソールドライバ の属性はすべてのケースで期待通り動作する必要があります（つまり、トルボPステートを無効に設定した場合でも常にそれらの使用を防ぐ必要があります）。

これはフレームバッファコンソール(fbcon)の場合より複雑です。なぜならfbconはコンソールとドライバの間の中間レイヤーだからです:

console ---> fbcon ---> fbdev drivers ---> hardware

fbdevドライバはfbconにバインドされている場合にアンロードできませんし、fbconはコンソールレイヤーにバインドされている場合にアンロードできません。

したがってfbdevドライバをアンロードするには、まずfbconをコンソールからアンバインドし、次にfbdevドライバをfbconからアンバインドする必要があります。幸いなことに、fbconをコンソールレイヤーからアンバインドするだけで、フレームバッファドライバもfbconから自動的にアンバインドされます。したがってfbdevドライバをfbconから明示的にアンバインドする必要はありません。

ではfbconをコンソールからアンバインドするにはどうすればよいのでしょうか？一部の答えは コンソールドライバまとめると:

バインドファイルにfbcon（framebuffer console driver）を表す値をエコーします。vtcon1がfbconを表すと仮定すると:

echo 1 > sys/class/vtconsole/vtcon1/bind - attach framebuffer console to
                                           console layer
echo 0 > sys/class/vtconsole/vtcon1/bind - detach framebuffer console from
                                           console layer

fbconがコンソールレイヤーから分離された場合、起動時のコンソールドライバ（通常はVGAテキストモード）が制御を引き継ぎます。いくつかのドライバ（rivafbとi810fb）は自動的にVGAテキストモードを復元しますが、それ以外のドライバではfbconを分離する前に、VGAテキストモードが正しく復元されるためにいくつかの追加手順が必要です。以下はそのような手順の一つです:

  1. vbetoolをダウンロードまたはインストールします。このユーティリティは現在のほとんどのディストリビューションに含まれており、通常はスリープ/再起動ツールの一部として提供されます。

  2. カーネル構成でCONFIG_FRAMEBUFFER_CONSOLEを'y'または'm'に設定し、お気に入りのフレームバッファドライバを1つ以上有効にします。

  3. テキストモードで起動し、rootとして以下のコマンドを実行します:

    vbetool vbestate save > <vga state file>

    上記のコマンドは、グラフィックハードウェアのレジスタ内容を<vga state file>に保存します。このステップは一度実行すれば再利用可能です。

  4. fbconがモジュールとしてコンパイルされている場合、fbconをロードするには以下を行います:

    modprobe fbcon

  5. 次にfbconを分離します:

    vbetool vbestate restore < <vga state file> && \
echo 0 > /sys/class/vtconsole/vtcon1/bind

  6. これでVGAモードに戻りました。fbconをモジュールとしてコンパイルしている場合、'rmmod fbcon'でアンロードできます。

  7. fbconを再接続するには:

    echo 1 > /sys/class/vtconsole/vtcon1/bind

8. fbconがバインド解除されると、システムに登録されているすべてのドライバも同時にバインド解除されます。これにより、fbconと個別フレームバッファドライバは任意にアンロードまたはロードできます。ドライバやfbconを再ロードすると自動的にコンソール、fbcon、ドライバがバインドされます。fbconをアンロードせずにすべてのドライバをアンロードすると、コンソールがfbconにバインドできなくなります。

vesafbユーザー向けの注意:¶

残念ながら、起動ラインにvga=xxxパラメータ（ハードウェアをグラフィックモードに設定）が含まれている場合、例えばvesafbをロードする際には、vgaconがロードされません。代わりに、vgaconはデフォルトの起動コンソールをdummyconに置き換え、fbconを分離した後には表示が得られません。マシンはまだ動作しているので、vesafbを再接続できます。ただし、vesafbを再接続するには以下のいずれかを行います:

バリエーション1:

  1. fbconを分離する前に以下を行います:

    vbetool vbemode save > <vesa state file> # do once for each vesafb mode,
                                         # the file can be reused

  2. ステップ5のようにfbconを分離します。

  3. fbconを接続します:

    vbetool vbestate restore < <vesa state file> && \
echo 1 > /sys/class/vtconsole/vtcon1/bind

バリエーション2:

  1. fbconを分離する前に以下を行います:

    echo <ID> > /sys/class/tty/console/bind

vbetool vbemode get

  2. モード番号をメモします

  1. ステップ5のようにfbconを分離します。

  2. fbconを接続します:

    vbetool vbemode set <mode number> && \
echo 1 > /sys/class/vtconsole/vtcon1/bind

サンプル:¶

ここにX86マシンでフレームバッファコンソールドライバをバインドまたはアンバインドするために使用できる2つのサンプルbashスクリプトがあります:

#!/bin/bash
# Unbind fbcon

# Change this to where your actual vgastate file is located
# Or Use VGASTATE=$1 to indicate the state file at runtime
VGASTATE=/tmp/vgastate

# path to vbetool
VBETOOL=/usr/local/bin


for (( i = 0; i < 16; i++))
do
  if test -x /sys/class/vtconsole/vtcon$i; then
      if [ `cat /sys/class/vtconsole/vtcon$i/name | grep -c "frame buffer"` \
           = 1 ]; then
          if test -x $VBETOOL/vbetool; then
             echo Unbinding vtcon$i
             $VBETOOL/vbetool vbestate restore < $VGASTATE
             echo 0 > /sys/class/vtconsole/vtcon$i/bind
          fi
      fi
  fi
done

#!/bin/bash
# Bind fbcon

for (( i = 0; i < 16; i++))
do
  if test -x /sys/class/vtconsole/vtcon$i; then
      if [ `cat /sys/class/vtconsole/vtcon$i/name | grep -c "frame buffer"` \
           = 1 ]; then
        echo Unbinding vtcon$i
        echo 1 > /sys/class/vtconsole/vtcon$i/bind
      fi
  fi
done
