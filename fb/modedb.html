modedbデフォルトビデオモードサポート¶

現在、すべてのフレームバッファデバイスドライバーが独自のビデオモードデータベースを持ち、これは混乱を招くだけでなく、リソースの浪費にもつながる。modedb の主な考え方は、

  • すべてのフレームバッファデバイスで利用可能な1つのプローブルーチンを持つこと

  • 標準的なビデオモード（XFree86 から取得）を含む1つの汎用的なビデオモードデータベース

  • 非標準的なモードを必要とするグラフィックハードウェア（例: amifb および Mac フレームバッファドライバー（macmodes.c を使用））用に独自のモードデータベースを提供する可能性

フレームバッファデバイスが video= オプションを認識しない場合、そのオプションをビデオモードオプションとみなすべきである。video= オプションにフレームバッファデバイスが指定されていない場合、fbmem はそのオプションをグローバルなビデオモードオプションとみなす。

有効なモード指定子（mode_option 引数）:

<xres>x<yres>[M][R][-<bpp>][@<refresh>][i][m][eDd]
<name>[-<bpp>][@<refresh>]

<xres>, <yres>, <bpp> および <refresh> は十進数、<name> は文字列である。角括弧内はオプションである。

mode_option 引数で 'M' を指定すると、タイミングは VESA(TM) 協調ビデオタイミングを使用して計算される。'R' を指定するとデジタルディスプレイ用に「減らしたブラッキング」計算が行われる。'i' を指定するとインターレースモードの計算が行われる。'm' を指定すると計算にマージンを加える（xres の 1.8%（8 ピクセル未満は切り捨て）、yres の 1.8%）。

サンプルの使い方: 1024x768M@60m - マージンを含む CVT タイミング

DRM ドライバーも出力の有効化/無効化を有効にするオプションを追加している:

'e' はディスプレイを強制的に有効にする（ディスプレイが接続されているかどうかの検出を上書き）。'D' はディスプレイを強制的に有効にし、デジタル出力を使う。これはアナログとデジタル信号を兼ね備える出力（例: HDMI および DVI-I）に特に有用である。他の出力では 'e' と同じ動作をする。'd' を指定すると出力が無効化される。

さらに、オプションがどの出力に適用されるかを指定することもできる。VGA 出力を強制的に有効にして特定のモードを駆動するには、次のように指定する:

video=VGA-1:1280x1024@60me

複数のポートに対してオプションを複数回指定することも可能である。例えば:

video=LVDS-1:d video=HDMI-1:D

オプションはモードの後にコンマを区切りとして指定することもできる。

サンプルの使い方: 720x480,rotate=180 - 720x480 モード、180 度回転

有効なオプションは:

- margin_top, margin_bottom, margin_left, margin_right (integer):
  Number of pixels in the margins, typically to deal with overscan on TVs
- reflect_x (boolean): Perform an axial symmetry on the X axis
- reflect_y (boolean): Perform an axial symmetry on the Y axis
- rotate (integer): Rotate the initial framebuffer by x
  degrees. Valid values are 0, 90, 180 and 270.
- panel_orientation, one of "normal", "upside_down", "left_side_up", or
  "right_side_up". For KMS drivers only, this sets the "panel orientation"
  property on the kms connector as hint for kms users.

VESA(TM) 協調ビデオタイミング（CVT）とは何か？¶

VESA(TM) ウェブサイトより:

「CVT の目的は、一貫した

コンピュータ表示製品（CRTを用いるものおよび他の表示技術を用いるもの）における標準形式、表示リフレッシュレート、タイミング仕様の連携されたセットを提供することを目的としています。CVTの意図は、ソースおよび表示メーカーが共通のツールセットを用いて、新しいタイミングを一貫して開発し、互換性を高めるための環境を整えることです。

これはVESA(TM)が承認した3番目のビデオタイミング標準です。最初の標準は「ディスクリートビデオタイミング（DVT）」で、VESA(TM)が承認した予め定義されたモードのコレクションです。2番目の標準は「ジェネラライズドタイミングフォーマラ（GTF）」で、ピクセルクロック、水平同期周波数、または垂直リフレッシュレートを指定することでタイミングを計算するアルゴリズムです。

GTFは主にCRT表示に設計されており、高いブランキング要件のためにピクセルクロックを意図的に増加させています。これは、高いデータレートを必要とするデジタル表示インターフェースでは、ピクセルクロックをできるだけ保持する必要があるため不適切です。また、GTFは表示のアスペクト比を考慮していません。

CVTはこれらの制限を解消しています。CRTを用いる場合、使用される式はGTFの導出式であり、いくつかの修正が加えられています。デジタル表示を用いる場合、「減らしたブランキング」計算式が使用されます。

フレームバッファサブシステムの観点からは、表示メーカーが新しいモードをリリースするたびにグローバルモードデータベースに新しい形式を追加する必要はありません。CVTを指定することで、ほとんどの場合、あるいはすべての新しいCRT表示に加えて、'減らしたブランキング'計算式を指定すればほとんどのフラットパネルにも適用可能です。（表示のCVT互換性はEDIDから確認可能です。EDIDバージョン1.3には追加の128バイトブロックがあり、追加のタイミング情報が格納されています。現在はこの追加ブロックをパースする機能はレイヤーにまだ実装されていません。）

CVTは新しい命名規則も導入しました（dmesg出力から確認できます）：

<pix>M<a>[-R]

where: pix = total amount of pixels in MB (xres x yres)
       M   = always present
       a   = aspect ratio (3 - 4:3; 4 - 5:4; 9 - 15:9, 16:9; A - 16:10)
      -R   = reduced blanking

      example:  .48M3-R - 800x600 with reduced blanking

注意：VESA(TM)は標準CVTタイミングの定義に制限があります：

  • アスペクト比は上記の値のいずれかに限られます

  • 許容されるリフレッシュレートは50、60、70、または85Hzに限られます

  • 減らしたブランキングを使用する場合、リフレッシュレートは60Hzでなければなりません

上記のいずれかを満たさない場合でも、カーネルは警告を出しますが、タイミング計算は依然として行われます。

適切なビデオモードを検索するには、以下を呼び出します：

int __init fb_find_mode(struct fb_var_screeninfo *var,
                        struct fb_info *info, const char *mode_option,
                        const struct fb_videomode *db, unsigned int dbsize,
                        const struct fb_videomode *default_mode,
                        unsigned int default_bpp)

db/dbsizeで非標準ビデオモードデータベースを指定するか、NULLを指定して標準ビデオモードデータベースを使用します。

fb_find_mode() 指定されたビデオモード（または一致する任意のモード、たとえば640x480のモードが複数ある場合など）を試します。失敗した場合はデフォルトモードを試し、それでも失敗した場合はすべてのモードを順に試します。

ブート時にビデオモードを指定するには、次のブートオプションを使用してください：

video=<driver>:<xres>x<yres>[-<bpp>][@refresh]

ここで<driver>は以下の表から選ぶ名前です。有効なデフォルトモードはdrivers/video/fbdev/core/modedb.cにあります。ドライバのドキュメンテーションを確認してください。さらに多くのモードがあるかもしれません：

Drivers that support modedb boot options
Boot Name     Cards Supported

amifb       - Amiga chipset frame buffer
aty128fb    - ATI Rage128 / Pro frame buffer
atyfb       - ATI Mach64 frame buffer
pm2fb       - Permedia 2/2V frame buffer
pm3fb       - Permedia 3 frame buffer
sstfb       - Voodoo 1/2 (SST1) chipset frame buffer
