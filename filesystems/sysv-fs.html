SystemV ファイルシステム¶

すべての以下のファイルシステムを実装しています

  • Xenix ファイルシステム、

  • SystemV/386 ファイルシステム、

  • Coherent ファイルシステム。

インストール方法:

  • カーネルの構成時に「System V および Coherent ファイルシステムサポート」の質問に「y」を答えてください。

  • ディスクまたはパーティションをマウントするには、以下のコマンドを使用してください:

    mount [-r] -t sysv device mountpoint

    ファイルシステムタイプ名:

    -t sysv
-t xenix
-t coherent

    は交換可能ですが、最後の2つは最終的に消えます。

現在の実装におけるバグ:

  • Coherent ファイルシステム:

    • 「free list interleave」n:m は現在無視されています。

    • ファイルシステム名とパック名のどちらもないファイルシステムのみが認識されます。(Coherent の「man mkfs」を参照してください。)

  • SystemV Release 2 ファイルシステム:

    スーパーブロックはブロック9、15、18のみを検索します。これはフロッピーディスクのトラック1の開始に相当します。ハードディスクでのサポートはまだありません。

これらのファイルシステムはそれほど大きく異なっていません。Minix FS との比較は以下の通りです:

  • Linux fdisk はパーティション情報を報告します

    • Minix FS 0x81 Linux/Minix

    • Xenix FS ??

    • SystemV FS ??

    • Coherent FS 0x08 AIX ブート可能

  • ブロックまたはゾーンのサイズ（ディスク上のデータ割当単位）

    • Minix FS 1024

    • Xenix FS 1024（512 ??）

    • SystemV FS 1024（512 および 2048）

    • Coherent FS 512

  • 一般的なレイアウト: すべてが1つのブートブロック、1つのスーパーブロック、インODEとディレクトリ/データの別領域を持ちます。SystemV Release 2 ファイルシステム（例: Microport）では、最初のトラックが予約され、すべてのブロック番号（スーパーブロックを含む）が1トラックずれています。

  • ディスク上の「short」（16ビットエンティティ）のバイト順:

    • Minix FS リトルエンディアン 0 1

    • Xenix FS リトルエンディアン 0 1

    • SystemV FS リトルエンディアン 0 1

    • Coherent FS リトルエンディアン 0 1

    もちろん、これはファイルシステムに影響するだけで、その上にあるファイルのデータには影響しません！

  • ディスク上の「long」（32ビットエンティティ）のバイト順:

    • Minix FS リトルエンディアン 0 1 2 3

    • Xenix FS リトルエンディアン 0 1 2 3

    • SystemV FS リトルエンディアン 0 1 2 3

    • Coherent FS PDP-11 2 3 0 1

    もちろん、これはファイルシステムに影響するだけで、その上にあるファイルのデータには影響しません！

  • ディスク上のインODE: 「short」、0 は存在しないことを意味し、ルートディレクトリの ino は:

    Minix FS

    1

    Xenix FS, SystemV FS, Coherent FS

    2

  • ファイルに対するハードリンクの最大数:

    Minix FS

    250

    Xenix FS

    ??

    SystemV FS

    ??

    Coherent FS

    >=10000

  • 空きインノードの管理:

    • Minix FS

      ビットマップ

    • Xenix FS, SystemV FS, Coherent FS

      スーパーブロック内に一定数の空きインノードをキャッシュしています。キャッシュが空になると、線形検索を使用して新しい空きインノードを検索します。

  • 空きブロックの管理:

    • Minix FS

      ビットマップ

    • Xenix FS, SystemV FS, Coherent FS

      空きブロックは「フリー リスト」として組織化されています。これはすべての空きブロックが次の空きブロックへのポインタを持つという誤解を招く表現ですが、実際には空きブロックは限定されたサイズのチャンクで組織化され、定期的に空きブロックが次のチャンクに関連する空きブロックへのポインタを持つことがあります。最初のブロックは次のチャンクのポインタを含み、このようにリストは「ブロック番号 0」でXenix FSおよびSystemV FSでは終了し、Coherent FSではブロックがゼロに初期化されます。

  • スーパーブロックの位置:

    Minix FS

    ブロック 1 = バイト 1024..2047

    Xenix FS

    ブロック 1 = バイト 1024..2047

    SystemV FS

    バイト 512..1023

    Coherent FS

    ブロック 1 = バイト 512..1023

  • スーパーブロックのレイアウト:

    • Minix FS:

      unsigned short s_ninodes;
unsigned short s_nzones;
unsigned short s_imap_blocks;
unsigned short s_zmap_blocks;
unsigned short s_firstdatazone;
unsigned short s_log_zone_size;
unsigned long s_max_size;
unsigned short s_magic;

    • Xenix FS, SystemV FS, Coherent FS:

      unsigned short s_firstdatazone;
unsigned long  s_nzones;
unsigned short s_fzone_count;
unsigned long  s_fzones[NICFREE];
unsigned short s_finode_count;
unsigned short s_finodes[NICINOD];
char           s_flock;
char           s_ilock;
char           s_modified;
char           s_rdonly;
unsigned long  s_time;
short          s_dinfo[4]; -- SystemV FS only
unsigned long  s_free_zones;
unsigned short s_free_inodes;
short          s_dinfo[4]; -- Xenix FS only
unsigned short s_interleave_m,s_interleave_n; -- Coherent FS only
char           s_fname[6];
char           s_fpack[6];

      それらは大きく異なります:

      Xenix FS:

      char           s_clean;
char           s_fill[371];
long           s_magic;
long           s_type;

      SystemV FS:

      long           s_fill[12 or 14];
long           s_state;
long           s_magic;
long           s_type;

      Coherent ファイルシステム:

      unsigned long  s_unique;

      Coherent FSはマジックを持ちません。

  • インノードのレイアウト:

    • Minix FS:

      unsigned short i_mode;
unsigned short i_uid;
unsigned long  i_size;
unsigned long  i_time;
unsigned char  i_gid;
unsigned char  i_nlinks;
unsigned short i_zone[7+1+1];

    • Xenix FS, SystemV FS, Coherent FS:

      unsigned short i_mode;
unsigned short i_nlink;
unsigned short i_uid;
unsigned short i_gid;
unsigned long  i_size;
unsigned char  i_zone[3*(10+1+1+1)];
unsigned long  i_atime;
unsigned long  i_mtime;
unsigned long  i_ctime;

  • 通常のファイルデータブロックは以下のように組織化されています

    • Minix FS:

      • 7つの直接ブロック

      • 1つの間接ブロック（ブロックへのポインタ）

      • 1つの二重間接ブロック（ブロックへのポインタへのポインタ）

    • Xenix FS, SystemV FS, Coherent FS:

      • 10つの直接ブロック

      • 1つの間接ブロック（ブロックへのポインタ）

      • 1つの二重間接ブロック（ブロックへのポインタへのポインタ）

      • 1つの三重間接ブロック（ブロックへのポインタへのポインタへのポインタ）

    Minix FS

    32

    32

    Xenix FS

    64

    16

    SystemV FS

    64

    16

    Coherent FS

    64

    8

  • ディスク上のディレクトリエントリ

    • Minix FS:

      unsigned short inode;
char name[14/30];

    • Xenix FS, SystemV FS, Coherent FS:

      unsigned short inode;
char name[14];

    Minix FS

    16/32

    64/32

    Xenix FS

    16

    64

    SystemV FS

    16

    64

    Coherent FS

    16

    32

  • ホストfsckが悲鳴を上げることなくシンボリックリンクを実装する方法:

    • Minix FS（通常）

    • Xenix FS（クルード）: chmod 1000で通常ファイルとして

    • SystemV FS ??

    • Coherent FS（クルード）: chmod 1000で通常ファイルとして

注記: 私たちはしばしば「ブロック」と言いますが、これはゾーン（割当単位）を指し、ディスクドライバーの「ブロック」の概念とは異なります。
