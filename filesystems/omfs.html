最適化MPEGファイルシステム（OMFS）¶

概要¶

OMFSはSonicBlueが開発したファイルシステムで、ReplayTV DVRおよびRio Karma MP3プレイヤーで使用されます。このファイルシステムはエクステントベースで構成され、ブロックサイズは2KBから8KBまで、ハッシュベースのディレクトリを採用しています。このファイルシステムドライバーは、これらのデバイスからディスクを読み書きするためのものです。

注意：このFSを自前のストリーミングメディアデバイス用の一般的なファイルシステムの代わりに使用することを推奨しません。ネイティブのLinuxファイルシステムの方が性能が優れている可能性があります。

詳細情報はこちら:

http://linux-karma.sf.net/

mkomfsやomfsckなどのユーティリティが含まれるomfsprogsは、以下から入手可能です:

https://bobcopeland.com/karma/

インストール手順はREADMEに記載されています。

オプション¶

OMFSは以下のマウントオプションをサポートしています:

uid=n

すべてのファイルを指定されたユーザーが所有する

gid=n

すべてのファイルを指定されたグループが所有する

umask=xxx

パーミッションのumaskをxxxに設定

fmask=xxx

ファイル用のumaskをxxxに設定

dmask=xxx

ディレクトリ用のumaskをxxxに設定

ディスクフォーマット¶

OMFSは「sysblock」と通常のデータブロックを区別しています。sysblockグループにはスーパーブロック情報、ファイルメタデータ、ディレクトリ構造、エクステントが含まれます。各sysblockには、sysblock全体のCRCを含むヘッダがあり、ディスク上の連続するブロックにミラーリングされる場合があります。sysblockのサイズはデータブロックより小さくても、同じ64ビットブロック番号でアドレス指定されるため、残りのスペースは無効とされます。

sysblockヘッダ情報:

struct omfs_header {
        __be64 h_self;                  /* FS block where this is located */
        __be32 h_body_size;             /* size of useful data after header */
        __be16 h_crc;                   /* crc-ccitt of body_size bytes */
        char h_fill1[2];
        u8 h_version;                   /* version, always 1 */
        char h_type;                    /* OMFS_INODE_X */
        u8 h_magic;                     /* OMFS_IMAGIC */
        u8 h_check_xor;                 /* XOR of header bytes before this */
        __be32 h_fill2;
};

ファイルとディレクトリはどちらもomfs_inodeで表されます:

struct omfs_inode {
        struct omfs_header i_head;      /* header */
        __be64 i_parent;                /* parent containing this inode */
        __be64 i_sibling;               /* next inode in hash bucket */
        __be64 i_ctime;                 /* ctime, in milliseconds */
        char i_fill1[35];
        char i_type;                    /* OMFS_[DIR,FILE] */
        __be32 i_fill2;
        char i_fill3[64];
        char i_name[OMFS_NAMELEN];      /* filename */
        __be64 i_size;                  /* size of file, in bytes */
};

OMFSのディレクトリは大規模なハッシュテーブルで実装されています。ファイル名はハッシュ化され、OMFS_DIR_STARTから始まるバケットリストに先頭に追加されます。検索にはファイル名をハッシュ化し、i_siblingポインタを順に辿る必要があります。空きバケットはすべて1のブロックポインタ（~0）で表されます。

ファイルはomfs_inode構造体に続き、OMFS_EXTENT_STARTから始まるエクステントテーブルで構成されます:

struct omfs_extent_entry {
        __be64 e_cluster;               /* start location of a set of blocks */
        __be64 e_blocks;                /* number of blocks after e_cluster */
};

struct omfs_extent {
        __be64 e_next;                  /* next extent table location */
        __be32 e_extent_count;          /* total # extents in this table */
        __be32 e_fill;
        struct omfs_extent_entry e_entry;       /* start of extent entries */
};

各エクステントにはブロックオフセットと割り当てられたブロック数が含まれます。各テーブルの最後のエクステントは、e_clusterを~0にし、e_blocksをテーブル内のブロック数の1の補数に設定したターミネーターです。

このテーブルがオーバーフローした場合、継続_inodeが作成され、e_nextで参照されます。これらはヘッダを持つものの、inode構造体の残りの部分は含まれていません。
