NFSv4.1サーバー実装¶

minorversion 1 のサーバー対応は、/proc/fs/nfsd/versions コントロールファイルを使用して制御可能です。このファイルを読み込む際の文字列出力には、「+4.1」または「-4.1」のいずれかが含まれます。

現在、minorversion 1 のサーバー対応はデフォルトで有効になっています。実行時においては、/proc/fs/nfsd/versions コントロールファイルに文字列「-4.1」を書き込むことで無効化可能です。このコントロールファイルを書き込むには、nfsd サービスを停止する必要があります。この作業には rpc.nfsd を使用可能です（参照: rpc.nfsd(8)）。

(警告: 旧バージョンのサーバーは「+4.1」と「-4.1」をそれぞれ「+4」と「-4」と解釈します。したがって、新旧のカーネルで動作するコードは、4.1 の有効/無効を明示的に制御する必要があります。 before 4.1 の有効/無効を制御する；rpc.nfsd はこれを正しく行います。)

nfsd における NFSv4 minorversion 1（NFSv4.1）の実装は RFC 5661 に基づいています。

NFSv4.1 の多くの新機能の中から、現在の実装は必須の NFSv4.1 セッションに焦点を当てています。これにより、「exactly once」セマンティクスや、各クライアントに割り当てられたリソースの制御および制限（スローイング）が改善されています。

以下の表は NFSv4.1 ドキュメントから抜粋したもので、minor version 1 において実装が必須（REQ）、選択肢（OPT）、および NFSv4.0 で実装してはならない（MNI）となる操作を示しています。最初の列は、Linux サーバー実装がまだサポートしていない操作を示しています。

識別されたオプション機能とその略称は以下の通りです：

  • pNFS Parallel NFS

  • FDELG File Delegations

  • DDELG Directory Delegations

以下の略称は Linux サーバー実装の状態を示します。

  • I 実装された NFSv4.1 操作。

  • NS サポートされていません。

  • NS* 未実装のオプション機能。

実装に関する注意:¶

SSV:

仕様では必須とされているが、実装例は確認されていないため一時的に無視する。サーバーはEXCHANGE_IDでNFS4ERR_ENCR_ALG_UNSUPPを返すが、これにより今後も対応可能である。

バックチャネルでのGSS:

理論上は必須だが、実装は限られている（特に現在のLinuxクライアントはこれを要求しない）。CREATE_SESSIONでNFS4ERR_ENCR_ALG_UNSUPPを返す。

DELEGPURGE:

CLAIM_DELEGATE_PREVおよび/またはCLAIM_DELEG_PREV_FHをサポートするサーバーのみ必須（これによりクライアントが再起動を越えたデリゲーションを維持できる）。そのため、現時点では実装不要である。

EXCHANGE_ID:

実装IDは無視される

CREATE_SESSION:

バックチャネル属性は無視される

SEQUENCE:

動的スロットテーブルの再交渉をサポートしていない（オプション）

非標準のコンパウンド制限:

セッションフォアチャネルRPCコンパウンドでca_maxrequestsizeリクエストとca_maxresponsesize応答を同時に要求する場合のサポートがないため、CREATE_SESSIONフォアチャネル交渉で約束した性能を満たせない可能性がある。

関連項目 http://wiki.linux-nfs.org/wiki/index.php/Server_4.0_and_4.1_issues.
