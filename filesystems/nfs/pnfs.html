pnfsにおける参照カウント¶

複数の関連するキャッシュがあります。レイアウトは複数のデバイスを参照でき、それぞれのデバイスは複数のデータサーバーを参照できます。各データサーバーは複数のデバイスによって参照され、各デバイスは複数のレイアウトによって参照されます。このような複雑な関係を整理するため、参照カウントが必要です。

struct pnfs_layout_hdr¶

ワイヤー上のコマンドLAYOUTGETはstruct pnfs_layout_segmentに対応し、通常は変数名lsegで参照されます。各nfs_inodeは、nfsi->layoutという構造体のpnfs_layout_hdr型のレイアウトセグメントのキャッシュを保持できます。

inodeが参照するヘッダーの参照を、LAYOUTGET、LAYOUTRETURN、LAYOUTCOMMITなどの Outstanding RPCコールおよび保持されている各lsegに対して保持します。

各ヘッダーは（空でない場合）struct nfs_client（cl_layouts）に関連するリストに追加されます。このリストに追加される際には参照カウントが増加しません。なぜなら、lsegがリストに保持しているため、レイアウトは保持されているからです。

deviceid_cache¶

lsegsはdevice idsを参照します。device idsはnfs_clientとレイアウトドライバータイプごとに解決されます。device idsはRCUキャッシュ（struct nfs4_deviceid_cache）に保持され、キャッシュ自体は各マウントごとに参照されます。各lsegが参照するentry（struct nfs4_deviceid）は、lsegの寿命にわたって保持されます。

RCUは、deviceidが基本的に「一度書き込み、複数読み込み」のデータ構造であるため使用されます。ハッシュリストのバケット数32はより適切な正当性が求められますが、複数のdeviceidを1つのファイルシステムに、複数のファイルシステムを1つのnfs_clientに持つ可能性があるため、現状では妥当です。

ハッシュコードはnfsdコードベースからコピーされています。ハッシュとこのアルゴリズムの変種についての議論は、以下にあります ここに記載しています。

data server cache¶

ファイルドライバーデバイスはデータサーバーを参照し、これらはモジュールレベルのキャッシュに保持されます。参照は、deviceidがそれを指している間保持されます。

lseg¶

lsegはNFS_LSEG_VALIDビットに対応する追加の参照を保持し、pnfs_layout_hdrのリストに保持します。pnfs_layout_hdrのリストから最後のlsegが削除されると、NFS_LAYOUT_DESTROYEDビットが設定され、新しいlsegの追加が防がれます。

layout drivers¶

PNFSは「レイアウトドライバ」と呼ばれるものを使用します。STDでは4つの基本レイアウトタイプが定義されています：「files（ファイル）」、「objects（オブジェクト）」、「blocks（ブロック）」、「flexfiles（フレキシブルファイル）」です。これらの各タイプには、共通の関数ベクターテーブルを持つレイアウトドライバがあり、nfs-clientのpnfs-coreによってこれらのレイアウトタイプを実装するために呼び出されます。

ファイルレイアウトドライバーのコードは fs/nfs/filelayout/.. ディレクトリにあります。ブロックレイアウトドライバーのコードは fs/nfs/blocklayout/.. ディレクトリにあります。フレックスファイルレイアウトドライバーのコードは fs/nfs/flexfilelayout/.. ディレクトリにあります。
