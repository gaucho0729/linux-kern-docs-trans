spufs¶

名前¶

spufs - SPU ファイルシステム

説明¶

SPU ファイルシステムは、Cell Broadband Engine アーキテクチャを実装した PowerPC マシンで使用され、Synergistic Processor Units (SPUs) にアクセスするために用いられます。

ファイルシステムは posix 共有メモリやメッセージキューに似た名前空間を提供します。ファイルシステムに書き込み権限を持つユーザーは、spufs ルートに SPU コンテキストを確立するために spu_create(2) を使用できます。

すべての SPU コンテキストは、予め定義されたファイルセットを含むディレクトリで表されます。これらのファイルは論理 SPU の状態を操作するために使用でき、ユーザーはファイルの権限を変更できますが、実際にファイルを追加または削除することはできません。

マウントオプション¶

uid=<uid>

マウントポイントを所有するユーザーを設定します。デフォルトは 0 (root) です。

gid=<gid>

マウントポイントを所有するグループを設定します。デフォルトは 0 (root) です。

ファイル¶

spufs のファイルは、read(2) や write(2) などの標準的なシステムコールとほぼ同じ挙動をしますが、通常のファイルシステムでサポートされる操作のサブセットのみをサポートしています。このリストはサポートされる操作と、それぞれの man ページでの挙動との違いを詳細に説明しています。

read(2) をサポートするすべてのファイルは readv(2) もサポートし、write(2) をサポートするすべてのファイルは writev(2) もサポートします。すべてのファイルは access(2) および stat(2) ファミリの操作をサポートしますが、struct stat の st_mode、st_nlink、st_uid および st_gid フィールドのみが信頼できる情報を持ちます。

chmod(2)/fchmod(2) および chown(2)/fchown(2) の操作をサポートしていますが、許可された操作と矛盾する権限（例: wbox ファイルへの読み取りアクセス）を付与することはできません。

現在のファイル一覧:

/mem

SPU のローカルストレージメモリの内容です。これは通常の共有メモリファイルのようにアクセスでき、SPU のアドレス空間にコードとデータを含みます。オープンした mem ファイルに対する可能な操作は:

read(2), pread(2), write(2), pwrite(2), lseek(2)

これらはドキュメントに記載されている通り動作しますが、seek(2)、write(2) および pwrite(2) はファイルの末尾を越えてサポートされません。ファイルサイズは SPU のローカルストレージのサイズであり、通常 256 バイトです。

mmap(2)

mem をプロセスアドレス空間にマッピングすると、プロセスアドレス空間内での SPU ローカルストレージにアクセスできます。ただし、MAP_SHARED でのみマッピングが許可されます。

/mbox

最初のSPUからCPUへの通信メールボックス。このファイルは読み取り専用であり、32ビット単位で読み取ることができます。このファイルは非ブロッキングモードでのみ使用でき、poll()関数でもブロックしません。オープンしたmboxファイルで可能な操作は:

read(2)

4未満の数値を要求した場合、read関数は-1を返し、errnoをEINVALに設定します。メールボックスにデータが存在しない場合、返却値が-1に設定され、errnoがEAGAINになります。データが正常に読み取られた場合、4バイトがデータバッファに格納され、値4が返されます。

/ibox

2番目のSPUからCPUへの通信メールボックス。これは1番目のメールボックスファイルと同様ですが、ブロッキングI/Oモードで読み取ることができ、poll関連のシステムコールを使用して待機できます。オープンしたiboxファイルで可能な操作は:

read(2)

4未満の数値を要求した場合、read関数は-1を返し、errnoをEINVALに設定します。メールボックスにデータが存在しない場合、ファイルディスクリプタがO_NONBLOCKでオープンされている場合、返却値が-1に設定され、errnoがEAGAINになります。

メールボックスにデータが存在しない場合、ファイルディスクリプタがO_NONBLOCKでオープンされていない場合、呼び出しはSPUが自身の割込みメールボックスチャンネルに書き込むのを待つまでブロックします。データが正常に読み取られた場合、4バイトがデータバッファに格納され、値4が返されます。

poll(2)

iboxファイルのpollは、読み込み可能なデータがあるたびに(POLLIN | POLLRDNORM)を返します。

/wbox

CPUからSPUへの通信メールボックス。これは書き込み専用であり、32ビット単位で書き込まれます。メールボックスが満杯の場合、write()はブロックし、poll関数を使用して空になるのを待つことができます。オープンしたwboxファイルで可能な操作は: write(2) 4未満の数値を要求した場合、write関数は-1を返し、errnoをEINVALに設定します。メールボックスに空きがなく、ファイルディスクリプタがO_NONBLOCKでオープンされている場合、返却値が-1に設定され、errnoがEAGAINになります。

メールボックスに空きがなく、ファイルディスクリプタがO_NONBLOCKでオープンされていない場合、呼び出しはSPUが自身のPPEメールボックスチャンネルから読み取るのを待つまでブロックします。データが正常に読み取られた場合、4バイトがデータバッファに格納され、値4が返されます。

poll(2)

iboxファイルのpollは、書き込み可能な空きがあるたびに(POLLOUT | POLLWRNORM)を返します。

/mbox_stat, /ibox_stat, /wbox_stat

現在のキューの長さを表す読み取り専用ファイル。つまり、mbox や ibox から読み取れる単語数、または wbox に書き込める単語数（ブロッキングせずに）を示します。これらのファイルは4バイト単位でしか読み取れず、ビッグエンディアンのバイナリ整数を返します。オープンしたファイルに対して可能な操作は以下の通りです。 *box_stat ファイルの可能な操作は以下の通りです：

read(2)

読み取り要求値が4バイト未満の場合、read は-1を返し、errno を EINVAL に設定します。それ以外の場合、データバッファに4バイトの値が設定され、mbox_stat または ibox_stat で読み取れる要素数（ブロッキングまたは EAGAIN を引き起こさない）が含まれます。

/npc, /decr, /decr_status, /spu_tag_mask, /event_mask, /srr0

SPU の内部レジスタ。表現は次の実行する命令の数値を示すASCII文字列です。これらはデバッグ用に読み取り/書き込みモードで使用できますが、プログラムの通常動作ではこれらに依存すべきではありません。なぜなら、npc 以外のレジスタへのアクセスにはSPUコンテキストの保存が必要で、非常に非効率だからです。

これらのファイルの内容は以下の通りです：

npc

次プログラムカウンタ

decr

SPU デクリメントャー

decr_status

デクリメントャー状態

spu_tag_mask

SPU DMA 用のMFCタグマスク

event_mask

SPU割込み用イベントマスク

srr0

割込み戻りアドレスレジスタ

オープンした npc、decr、decr_status、spu_tag_mask、event_mask または srr0 ファイルに対して可能な操作は以下の通りです：

read(2)

read 呼び出しに渡されたカウントがポインタ値の必要長さに加えて改行文字を含むよりも短い場合、同じファイルディスクリプタからの次の読み取りは文字列を完了するまで行われます。SPUタスクによってレジスタが変更されても関係ありません。文字列が完全に読み取られた後は、すべての次の読み取り操作はゼロバイトを返し、新しいファイルディスクリプタを開く必要があります。

write(2)

ファイルへの書き込み操作は、文字列に指定された値でレジスタを設定します。文字列は最初の非数値文字またはバッファの終わりまで解析され、同じファイルディスクリプタへの次の書き込みは前の設定を上書きします。

/fpcr

このファイルは、fpcr レジスタを4バイトのファイルとして提供します。fpcr ファイルに対する操作は以下の通りです。

read(2)

読み取り要求値が4バイト未満の場合、read は-1を返し、errno を EINVAL に設定します。それ以外の場合、データバッファに4バイトの値が設定され、fpcr レジスタの現在値が含まれます。

write(2)

4未満の値が要求された場合、writeは-1を返し、errnoをEINVALに設定します。それ以外の場合、データバッファから4バイトの値がコピーされ、fpcrレジスタの値が更新されます。

/signal1, /signal2

SPUの2つの信号通知チャネルです。これらは32ビットのワードを扱う読み書き可能なファイルです。これらのファイルに書き込むとSPUに割り込みが発生します。信号ファイルに書き込まれた値は、SPU経由のチャネル読み込みまたはホストユーザースペース経由のファイル読み込みで取得可能です。SPUが値を読み取った後は、ゼロにリセットされます。開いたsignal1またはsignal2ファイルで可能な操作は以下の通りです：

read(2)

4未満の値が要求された場合、readは-1を返し、errnoをEINVALに設定します。それ以外の場合、指定された信号通知レジスタの現在値を含む4バイトの値がデータバッファに格納されます。

write(2)

4未満の値が要求された場合、writeは-3を返し、errnoをEINVALに設定します。それ以外の場合、データバッファから4バイトの値がコピーされ、指定された信号通知レジスタの値が更新されます。信号通知レジスタは、signal1_typeまたはsignal2_typeファイルの内容に応じて、入力データで置き換えられるか、または旧値と入力データのビットごとのOR演算結果に更新されます。

/signal1_type, /signal2_type

これらの2つのファイルはsignal1およびsignal2通知ファイルの動作を変更します。これらは「1」または「0」を表す数値のASCII文字列を含みます。モード0（上書き）では、ハードウェアがsignalチャネルの内容を書き込まれたデータで上書きします。モード1（論理OR）では、ハードウェアが後に書き込まれたビットを累積します。開いたsignal1_typeまたはsignal2_typeファイルで可能な操作は以下の通りです：

read(2)

read呼び出しに渡されたcountが、桁数に加えて改行文字の長さよりも短い場合、同じファイルディスクリプタからの次のreadは文字列を完成させます。文字列が完全に読み取られた後は、すべての次のread操作はゼロバイトを返し、新しいファイルディスクリプタを開いて値を再度読み取る必要があります。

write(2)

ファイルへの書き込み操作は、文字列に指定された値でレジスタを設定します。文字列は最初の非数値文字またはバッファの終わりまで解析され、同じファイルディスクリプタへの次の書き込みは前の設定を上書きします。

例¶

/etc/fstabエントリ

none /spu spufs gid=spu 0 0
