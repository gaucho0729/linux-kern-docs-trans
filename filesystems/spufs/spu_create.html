spu_create¶

名前¶

spu_create - 新しい spu コンテキストの作成

概要¶

#include <sys/types.h>
#include <sys/spu.h>

int spu_create(const char *pathname, int flags, mode_t mode);

説明¶

spu_create システムコールは、PowerPCマシンでCell Broadband Engine Architectureを実装している場合に使用され、Synergistic Processor Units (SPUs)にアクセスするために用いられます。このコールは、pathnameに論理的なSPUコンテキストを新たに作成し、それに紐付くハンドルを返します。pathnameはspufsファイルシステムのマウントポイント内の既存でないディレクトリを指さなければなりません。spu_createが成功すると、pathnameにディレクトリが作成され、その中にファイルが生成されます。

返されたファイルハンドルはspu_run(2)またはclose()にのみ渡すことができます。その他の操作は定義されていません。close()が呼ばれた際には、spufs内の関連するディレクトリエントリが削除されます。このファイルディスクリプタまたはコンテキストディレクトリ内のファイルに最後のハンドルが閉じた場合、論理的なSPUコンテキストが破壊されます。

flagsパラメータは0か、以下の定数のビットごとの論理和の組み合わせを指定できます。

SPU_RAWIO

SPUの一部のハードウェアレジスタをユーザー空間にマッピングを許可します。このフラグはCAP_SYS_RAWIOの権限が必要です。詳しくはcapabilities(7)を参照してください。

modeパラメータはspufsで新規ディレクトリを作成する際のパーミッションを指定します。modeはユーザーのumask(2)値で修正され、ディレクトリおよびその中のファイルに適用されます。ファイルのパーミッションマスクにより、modeの一部がさらに除外されます。詳しくはstat(2)を参照してください。

戻り値¶

spu_createは新しいファイルディスクリプタを返します。エラー条件を示すために-1を返す場合があります。その際、errnoは以下のエラーコードのいずれかに設定されます。

エラー¶

EACCES

現在のユーザーがspufsマウントポイントに書き込みアクセス権を持っていない場合。

EEXIST 指定されたパス名に既にSPUコンテキストが存在しています。

EFAULT 現在のアドレス空間で有効な文字列ポインタではありません。

space.

EINVAL spufsマウントポイント内にパス名がディレクトリではありません。

ELOOP パス名を解決する際に見つかったシンボリックリンクが多すぎます。

EMFILE プロセスが最大オープンファイル数に達しています。

ENAMETOOLONG

パス名が長すぎます。

ENFILE システム全体でオープンファイル数の制限に達しています。

ENOENT パス名の一部が解決できませんでした。

ENOMEM カーネルがすべての必要なリソースを割り当てられませんでした。

ENOSPC 新しいコンテキストを作成するためのSPUリソースが不足しています

またはユーザー固有のSPUコンテキスト数の制限に達しています。

ENOSYS 現在のシステムではこの機能が提供されていません、なぜなら

ハードウェアがSPUを提供していないか、spufsモジュールがロードされていない場合です。

ENOTDIR

pathnameの一部がディレクトリではありません。

備考¶

spu_createはSPUに対するより抽象的なインターフェースを実装したライブラリから使用することを意図しており、通常のアプリケーションから使用すべきではありません。参照してください http://www.bsc.es/projects/deepcomputing/linuxoncell/ 推奨されるライブラリについては

ファイル¶

pathnameはspufsのマウントポイント以下の場所を指さなければなりません。慣例により、/spuにマウントされます。

準拠しています¶

この呼び出しはLinux固有であり、ppc64アーキテクチャのみで実装されています。このシステムコールを使用するプログラムは移植性がありません。
