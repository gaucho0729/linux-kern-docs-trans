spu_run¶

名前¶

spu_run - SPUコンテキストの実行

概要¶

#include <sys/spu.h>

int spu_run(int fd, unsigned int *npc, unsigned int *event);

説明¶

spu_runシステムコールは、PowerPCマシンでCell Broadband Engine Architectureを実装している場合に使用され、Synergistic Processor Units (SPUs)にアクセスします。spu_create(2)から返されたfdを使用して特定のSPUコンテキストを参照します。コンテキストが物理的なSPUにスケジュールされると、npcに渡されたインストラクションポインタから実行を開始します。

SPUコードの実行は同期的に行われ、spu_runはSPUが実行中である間は戻りません。メインCPUや他のSPUとSPUコードを並列に実行する必要がある場合は、まずpthread_create(3)などの関数を使用して新しい実行スレッドを生成する必要があります。

spu_runが戻るとき、SPUインストラクションポインタの現在値がnpcに書き戻されるため、ポインタを更新することなくspu_runを再度呼び出すことができます。

eventはNULLポインタか、spu_runが戻るときに埋められる拡張ステータスコードを指すことができます。これは次の定数のいずれかです：

SPE_EVENT_DMA_ALIGNMENT

DMAアライメントエラー

SPE_EVENT_SPE_DATA_SEGMENT

DMAセグメンテーションエラー

SPE_EVENT_SPE_DATA_STORAGE

DMAストレージエラー

event引数にNULLを渡した場合、これらのエラーは呼び出しプロセスにシグナルとして届けられます。

戻り値¶

spu_runはspu_statusレジスタの値を返すか、エラーを示す-1を返します。またerrnoを以下のエラーコードのいずれかに設定します。spu_statusレジスタの値にはステータスコードのビットマスクと、SPUのstop-and-signal命令から返された14ビットのコード（オプション）が含まれます。

0x02

SPUはstop-and-signalによって停止されました。

0x04

SPUはhaltによって停止されました。

0x08

SPUはチャネルを待機しています。

0x10

SPUはシングルステップモードです。

0x20

SPUが無効なインストラクションを実行しようとしました。

0x40

SPUが無効なチャネルにアクセスしようとしました。

0x3fff0000

この値でマスクされたビットには、stop-and-signalから返されたコードが含まれます。

常に下位8ビットのいずれかが設定されているか、spu_runからエラーコードが返されます。

エラー¶

EAGAINまたはEWOULDBLOCK

fdがノンブロッキングモードで、spu_runがブロックする可能性があります。

EBADF fdが有効なファイルディスクリプタではありません。

EFAULT npcが有効なポインタではありませんか、statusがNULLでも有効な

ポインタを参照します。

EINTR spu_runが進行中にシグナルが発生しました。この場合、npc値

必要に応じて新しいプログラムカウンタ値に更新されます。

EINVAL fdがspu_create(2)から返されたファイルディスクリプタではありません。

ENOMEM ページフォールトの処理に十分なメモリがありませんでした。

MFCのダイレクトメモリアクセスから来ています。

ENOSYS 現在のシステムではこの機能が提供されていません、なぜなら

ハードウェアがSPUを提供していないか、spufsモジュールがロードされていない場合です。

備考¶

spu_runは、SPUに対するより抽象的なインターフェースを実装したライブラリから使用することを目的としており、通常のアプリケーションから使用すべきではありません。参照してください http://www.bsc.es/projects/deepcomputing/linuxoncell/ 推奨されるライブラリについては

準拠しています¶

この呼び出しはLinux固有であり、ppc64アーキテクチャのみで実装されています。このシステムコールを使用するプログラムは移植性がありません。
