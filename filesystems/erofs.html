拡張読み取り専用ファイルシステム - EROFS¶

概要¶

EROFSファイルシステムはEnhanced Read-Only File Systemの略で、他の読み取り専用ファイルシステムとは異なり、柔軟性と拡張性を重視しつつ、シンプルで高性能な設計を目指しています。

以下のようなシナリオに最適なファイルシステムソリューションとして設計されています:

  • 読み取り専用ストレージメディアや、

  • 完全に信頼できる読み取り専用ソリューションの一部として、セキュリティなどの観点から公式のゴールデンイメージとビット単位で完全一致する必要があるため、変更不可である必要があります。また、

  • メタデータの削減と透過的ファイル圧縮により、端到端のパフォーマンスを保証しながらストレージ空間を節約したいというニーズに対応しています（特にメモリ制限のある埋め込みデバイス向けに、スマートフォンなど）。

EROFSの主な特徴は以下の通りです:

  • ディスク上のリトルエンディアン設計;

  • 現在は4KBブロックサイズ（nobh）で、最大16TBのアドレス空間をサポート;

  • メタデータとデータは設計上混在可能です;

  • 異なる要件に対応するための2つのインノードバージョン:

    インノードメタデータサイズ

    32バイト

    64バイト

    最大ファイルサイズ

    4 GB

    16 EB（最大ボリュームサイズによって制限）

    最大uids/gids

    65536

    4294967296

    ファイル変更時刻

    no

    はい（64 + 32ビットタイムスタンプ）

    最大ハードリンク数

    65536

    4294967296

    メタデータ予約

    4バイト

    14バイト

  • 拡張属性（xattrs）のサポート（オプション）;

  • すべてのファイルに対して拡張属性のインラインとデータの末尾インラインをサポート;

  • POSIX.1e ACLを拡張属性を使用してサポート;

  • 透過的ファイル圧縮のサポート（オプション）: 高性能を実現するためLZ4アルゴリズムを使用し、4KB固定サイズの出力圧縮を実施。

以下のgitツリーは、開発中のファイルシステムユーザースペースツール（例: フォーマットツールmkfs.erofs）を提供しています:

  • git://git.kernel.org/pub/scm/linux/kernel/git/xiang/erofs-utils.git

バグやパッチは歓迎します。ご協力をお願いいたします。以下のlinux-erofsメーリングリストに送信してください:

マウントオプション¶

(no)user_xattr

拡張ユーザー属性の設定。注意: CONFIG_EROFS_FS_XATTRが選択されている場合、xattrはデフォルトで有効になります。

(no)acl

POSIXアクセス制御リストの設定。注意: CONFIG_EROFS_FS_POSIX_ACLが選択されている場合、aclはデフォルトで有効になります。

cache_strategy=%s

今後キャッシュされた復元圧縮の戦略を選択:

無効化されている場合です。

インプレースI/O復元圧縮のみ;

読み込み予測

未完了の圧縮物理クラスターの最後の部分をキャッシュして以降の読み込みに備えます。残りの圧縮物理クラスターについては、インプレースI/Oによるデコンプレッションを実行し続けます;

readaround

未完了の圧縮物理クラスターの両端をキャッシュして以降の読み込みに備えます。残りの圧縮物理クラスターについては、インプレースI/Oによるデコンプレッションを実行し続けます。

dax={always,never}

直接アクセス（ページキャッシュなし）を使用します。Documentation/filesystems/dax.rst を参照してください。

dax

レガシーなオプションで、以下に該当します dax=always.

ディスク上の詳細¶

Summary¶

他の読み取り専用ファイルシステムとは異なり、EROFSボリュームはできるだけシンプルに設計されています:

                              |-> aligned with the block size
 ____________________________________________________________
| |SB| | ... | Metadata | ... | Data | Metadata | ... | Data |
|_|__|_|_____|__________|_____|______|__________|_____|______|
0 +1K

すべてのデータ領域はブロックサイズとアライメントし、メタデータ領域はそれとは異なる場合があります。すべてのメタデータは現在、2つの異なる空間（ビュー）で観察できます:

  1. インODEメタデータ空間

    有効なインODEは、固定値（32バイト）のインODEスロットとアライメントし、コンパクトなインODEサイズと一致するように設計されています。

    各インODEは以下の式で直接検索できます:

    inodeオフセット = meta_blkaddr × ブロックサイズ + 32 × nid

                                |-> aligned with 8B
                                    |-> followed closely
+ meta_blkaddr blocks                                      |-> another slot
_____________________________________________________________________
|  ...   | inode |  xattrs  | extents  | data inline | ... | inode ...
|________|_______|(optional)|(optional)|__(optional)_|_____|__________
        |-> aligned with the inode slot size
            .                   .
            .                         .
        .                              .
        .                                    .
    .                                         .
    .                                              .
.____________________________________________________|-> aligned with 4B
| xattr_ibody_header | shared xattrs | inline xattrs |
|____________________|_______________|_______________|
|->    12 bytes    <-|->x * 4 bytes<-|               .
                    .                .                 .
                .                      .                   .
        .                           .                     .
    ._______________________________.______________________.
    | id | id | id | id |  ... | id | ent | ... | ent| ... |
    |____|____|____|____|______|____|_____|_____|____|_____|
                                    |-> aligned with 4B
                                                |-> aligned with 4B

    インODEは32バイトまたは64バイトであり、すべてのインODEバージョンに共通するフィールドであるi_formatによって区別できます:

     __________________               __________________
|     i_format     |             |     i_format     |
|__________________|             |__________________|
|        ...       |             |        ...       |
|                  |             |                  |
|__________________| 32 bytes    |                  |
                                 |                  |
                                 |__________________| 64 bytes

    Xattrs、エクステント、データインラインはそれぞれ適切なアライメントを持つインODEに続き、異なるデータマッピングではオプションです。_現在_までに4つの有効なデータマッピングがサポートされています:

    0

    データインラインなしのフラットファイルデータ（エクステントなし）;

    1

    固定サイズの出力データ圧縮（非コンパクトなインデックス付き）;

    2

    データインライン付きのフラットファイルデータ（エクステントなし）;

    3

    固定サイズの出力データ圧縮（コンパクトなインデックス付き、v5.3以降）。

    オプションのXattrsのサイズはインODEヘッダのi_xattr_countで示されます。大容量のXattrsや複数のファイルで共有されるXattrsは、インラインでインODEの後に記録するのではなく、共有Xattrsメタデータに保存できます。

  2. 共有Xattrsメタデータ空間

    共有Xattrs空間は上記のインODE空間と同様で、特定のブロック（xattr_blkaddrで指定）から開始し、適切なアライメントで順番に整理されています。

    各共有Xattrsも以下の式で直接検索できます:

    xattrオフセット = xattr_blkaddr × ブロックサイズ + 4 × xattr_id

                        |-> aligned by  4 bytes
+ xattr_blkaddr blocks                     |-> aligned with 4 bytes
_________________________________________________________________________
|  ...   | xattr_entry |  xattr data | ... |  xattr_entry | xattr data  ...
|________|_____________|_____________|_____|______________|_______________

ディレクトリ¶

すべてのディレクトリは現在、コンパクトなディスク上の形式で整理されています。注意点として、各ディレクトリブロックはインデックス領域と名前領域に分割され、ランダムなファイル検索をサポートしています。すべてのディレクトリエントリは_厳密に_アルファベット順で記録され、改善されたプレフィックスバイナリ検索アルゴリズムをサポートしています（関連するソースコードを参照してください）。

                ___________________________
                /                           |
            /              ______________|________________
            /              /              | nameoff1       | nameoffN-1
____________.______________._______________v________________v__________
| dirent | dirent | ... | dirent | filename | filename | ... | filename |
|___.0___|____1___|_____|___N-1__|____0_____|____1_____|_____|___N-1____|
    \                           ^
    \                          |                           * could have
    \                         |                             trailing '\0'
        \________________________| nameoff0

                            Directory block

最初のファイル名のオフセット以外にも、nameoff0はこのブロック内のディレクトリエントリの総数を示しており、別なオンディスクフィールドを導入する必要がないためです。

圧縮機能¶

現在、EROFSは4KB固定サイズの出力透過ファイル圧縮をサポートしており、以下に示します:

        |---- Variant-Length Extent ----|-------- VLE --------|----- VLE -----
        clusterofs                      clusterofs            clusterofs
        |                               |                     |   logical data
_________v_______________________________v_____________________v_______________
... |    .        |             |        .    |             |  .          | ...
____|____.________|_____________|________.____|_____________|__.__________|____
    |-> cluster <-|-> cluster <-|-> cluster <-|-> cluster <-|-> cluster <-|
        size          size          size          size          size
        .                             .                .                   .
        .                       .               .                  .
            .                  .              .                .
    _______._____________._____________._____________._____________________
        ... |             |             |             | ... physical data
    _______|_____________|_____________|_____________|_____________________
            |-> cluster <-|-> cluster <-|-> cluster <-|
                size          size          size

現在、各オンディスク物理クラスタは最大で4KBの(un)圧縮データを含むことができます。各論理クラスタには、クラスタタイプや物理クラスタアドレスなどを記述する対応するオンディスクインデックスがあります。

詳細については、erofs_fs.h の「struct z_erofs_vle_decompressed_index」を参照してください。
