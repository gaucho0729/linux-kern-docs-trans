Fiemap Ioctl¶

fiemap ioctl は、ユーザー空間がファイルの領域マッピングを取得するための効率的な方法です。ブロック単位のマッピング（例: bmap）ではなく、fiemap は領域の一覧を返します。

リクエストの基本¶

fiemap リクエストは struct fiemap 内でエンコードされます:

struct fiemap {
      __u64   fm_start;        /* logical offset (inclusive) at
                                * which to start mapping (in) */
      __u64   fm_length;       /* logical length of mapping which
                                * userspace cares about (in) */
      __u32   fm_flags;        /* FIEMAP_FLAG_* flags for request (in/out) */
      __u32   fm_mapped_extents; /* number of extents that were
                                  * mapped (out) */
      __u32   fm_extent_count; /* size of fm_extents array (in) */
      __u32   fm_reserved;
      struct fiemap_extent fm_extents[0]; /* array of mapped extents (out) */
};

fm_start および fm_length は、プロセスがマッピングを取得したいファイルの論理的な範囲を指定します。返される領域はディスク上のものと一致します。つまり、最初に返される領域の論理的なオフセットは fm_start より前になる可能性があり、最後に返される領域の範囲は fm_length より後になる可能性があります。すべてのオフセットと長さはバイト単位です。

fm_flags にはマッピングの検索方法を変更するフラグを設定できます。カーネルが特定のフラグを理解できない場合、EBADR を返して fm_flags の内容にエラーを引き起こしたフラグのセットを示します。カーネルがすべてのフラグをサポートする場合、fm_flags の内容は変更されません。ユーザー空間は特定のフラグの拒否が操作に致命的かどうかを判断する必要があります。このスキーマは、今後 fiemap インターフェースが拡張されるのを可能にしつつ、旧ソフトウェアとの互換性を失わないように設計されています。

fm_extent_count は fm_extents[] 配列に返すことができる領域の数を指定します。fm_extent_count がゼロの場合、fm_extents[] 配列は無視されます（領域は返されません）し、fm_mapped_extents の数は fm_extents[] にファイルの現在のマッピングを保持するために必要な領域数を示します。注意: FIEMAP 呼び出しの間でファイルが変化する可能性があるため、これは制限されません。

fm_flags に設定できるフラグ:

FIEMAP_FLAG_SYNC

このフラグが設定されている場合、カーネルはマッピングする領域の前にファイルを同期します。

FIEMAP_FLAG_XATTR

このフラグが設定されている場合、返される領域は inode の拡張属性検索木を記述します。データ木ではなくします。

領域マッピング¶

ユーザー空間はfiemap構造体とともにfm_extents配列を確保する必要があります。fm_extents配列に含まれる要素数はfm_extent_countを通じて渡します。カーネルがマッピングするエクステントの数はfm_mapped_extentsで返されます。fiemap_extentsに確保された要素数が要求された範囲をマッピングするために必要な数より少ない場合、fm_extent[]配列にマッピング可能な最大のエクステント数がfm_mapped_extentsで返され、fm_mapped_extentsはfm_extent_countと等しくなります。この場合、配列の最後のエクステントは要求された範囲を完全にはカバーせず、FIEMAP_EXTENT_LASTフラグは設定されません（次のセクションでエクステントフラグについて詳しく説明します）。

各エクステントはfm_extentsで返されるfiemap_extent構造体で記述されます。

struct fiemap_extent {
        __u64       fe_logical;  /* logical offset in bytes for the start of
                            * the extent */
        __u64       fe_physical; /* physical offset in bytes for the start
                            * of the extent */
        __u64       fe_length;   /* length in bytes for the extent */
        __u64       fe_reserved64[2];
        __u32       fe_flags;    /* FIEMAP_EXTENT_* flags for this extent */
        __u32       fe_reserved[3];
};

すべてのオフセットと長さはバイト単位で、ディスク上のそれらと一致しています。論理オフセットが要求範囲の前より前から始まるか、論理長が要求範囲を越えることが有効です。FIEMAP_EXTENT_NOT_ALIGNEDが返されない限り、fe_logical、fe_physical、fe_lengthはファイルシステムのブロックサイズに合わせてアライメントされます。FIEMAP_EXTENT_MERGEDフラグが設定されたエクステントを除き、隣接するエクステントはマージされません。

fe_flagsフィールドにはエクステントの情報を示すフラグが含まれています。特殊なフラグであるFIEMAP_EXTENT_LASTはファイルの最後のエクステントに常に設定され、fiemapコールを実行するプロセスがさらにエクステントが存在しないことを検出できるようにします。これにより、ioctlを再度呼び出す必要がなくなります。

一部のフラグは意図的に曖昧にされ、他のより具体的なフラグが存在する場合に常に設定されます。これにより、特定のプロパティを検索するプログラムは、そのプロパティを示すすべての既存および将来のフラグを把握する必要がありません。

たとえば、FIEMAP_EXTENT_DATA_INLINEまたはFIEMAP_EXTENT_DATA_TAILが設定されている場合、FIEMAP_EXTENT_NOT_ALIGNEDも同時に設定されます。インラインまたはテールパッケージデータを検索するプログラムは特定のフラグに依存できます。非アライメントのエクステントを操作しようとはしないソフトウェアは、FIEMAP_EXTENT_NOT_ALIGNEDのみをチェックすればよく、すべての現在および将来のフラグを気にする必要がありません。注意点として、逆は成立しません。FIEMAP_EXTENT_NOT_ALIGNEDは単独で有効です。

FIEMAP_EXTENT_LAST

これはファイル内の一般的に最後の拡張領域です。この拡張領域を超えてマッピングを試みると、何も返されない可能性があります。一部の実装では、このフラグを設定して、ユーザーが照会した範囲（fiemap->fm_length）内の最後の拡張領域であることを示します。

FIEMAP_EXTENT_UNKNOWN

この拡張領域の位置は現在不明です。これはデータがアクセスできないボリュームに保存されているか、ファイルにストレージが割り当てられていない可能性を示しています。

FIEMAP_EXTENT_DELALLOC

これはFIEMAP_EXTENT_UNKNOWNを設定することもします。

遅延割当 - この拡張領域にはデータが存在しますが、物理的な位置がまだ割り当てられていません。

FIEMAP_EXTENT_ENCODED

この拡張領域は通常のファイルシステムブロックではなく、符号化されています（例: 暗号化または圧縮）。ブロックデバイスへのI/Oを通じてこの拡張領域のデータを読み込むと、未定義の結果になる可能性があります。

注意として、ファイルシステムの支援なしに、この拡張領域の位置に直接書き込みによってデータを更新しようとしたり、FIEMAPインターフェースで取得した情報を使ってマウント中のファイルシステムでデータにアクセスしたりすることはできません。 always 言い換えれば、ユーザーのアプリケーションはファイルシステムがマウントされていないときにのみ、ブロックデバイスへのI/Oを通じて拡張領域データを読み込むことができます。その際はFIEMAP_EXTENT_ENCODEDフラグがクリアされている必要があります。他の状況ではブロックデバイスを通じてファイルシステムへの読み書きは行わないでください。

FIEMAP_EXTENT_DATA_ENCRYPTED

これはFIEMAP_EXTENT_ENCODEDを設定することもします。この拡張領域のデータはファイルシステムによって暗号化されています。

FIEMAP_EXTENT_NOT_ALIGNED

拡張領域のオフセットと長さがブロックアライメントを保証されていない可能性があります。

FIEMAP_EXTENT_DATA_INLINE

これはFIEMAP_EXTENT_NOT_ALIGNEDを設定することもします。データはメタデータブロック内に配置されています。

FIEMAP_EXTENT_DATA_TAIL

これはFIEMAP_EXTENT_NOT_ALIGNEDを設定することもします。データは他のファイルのデータとともに1つのブロックに詰め込まれています。

FIEMAP_EXTENT_UNWRITTEN

未書込み拡張領域 - この拡張領域は割り当てられていますが、データが初期化されていません。これはファイルシステムを通じて読み込むとすべてゼロになるが、デバイスから直接読み込むと内容が未定義であることを示します。

FIEMAP_EXTENT_MERGED

ファイルが拡張領域をサポートしない場合（つまりブロックベースのアドレス指定方式を使用する場合）、このフラグが設定されます。個々のブロックごとに拡張領域をユーザー空間に返すことは極めて非効率であるため、カーネルは隣接するブロックをできるだけ多く「拡張領域」にマージしようとします。

VFS -> ファイルシステム実装¶

fiemapをサポートするファイルシステムは、inode_operations構造体に->fiemapコールバックを実装する必要があります。fs->fiemapコールは、サポートするfiemapフラグのセットを定義し、各発見したエクステントに対して補助関数を呼び出す責任があります:

struct inode_operations {
     ...

     int (*fiemap)(struct inode *, struct fiemap_extent_info *, u64 start,
                   u64 len);

->fiemapにはstruct fiemap_extent_infoが渡され、これはfiemapリクエストを説明します:

struct fiemap_extent_info {
      unsigned int fi_flags;          /* Flags as passed from user */
      unsigned int fi_extents_mapped; /* Number of mapped extents */
      unsigned int fi_extents_max;    /* Size of fiemap_extent array */
      struct fiemap_extent *fi_extents_start; /* Start of fiemap_extent array */
};

ファイルシステムはこの構造体を直接アクセスする必要はなく設計されています。ファイルシステムハンドラはシグナルに耐性を持ち、致命的なシグナルを受信した場合にEINTRを返す必要があります。

->fiemapコールバックの開始時にfiemap_prep()補助関数を介してフラグのチェックを行う必要があります:

int fiemap_prep(struct inode *inode, struct fiemap_extent_info *fieinfo,
                u64 start, u64 *len, u32 supported_flags);

struct fieinfoはioctl_fiemap()から受け取ったまま渡す必要があります。fsが理解するfiemapフラグのセットはfs_flagsを通じて渡します。fiemap_prep()が無効なユーザーフラグを検出すると、fieinfo->fi_flagsに悪い値を設定して-EBADRを返します。fsがfiemap_prep()から-EBADRを受けると、すぐにそのエラーをioctl_fiemap()に返す必要があります。また、範囲はサポートされる最大ファイルサイズと照合されます。

リクエスト範囲内の各エクステントに対して、ファイルシステムは補助関数fiemap_fill_next_extent()を呼び出す必要があります:

int fiemap_fill_next_extent(struct fiemap_extent_info *info, u64 logical,
                            u64 phys, u64 len, u32 flags, u32 dev);

fiemap_fill_next_extent()は、渡された値をfm_extents配列の次の空きエクステントに埋め込みます。呼び出し元のファイルシステムの特定フラグから一般的なエクステントフラグが自動的に設定されるため、ユーザー空間APIは破壊されません。

fiemap_fill_next_extent()は成功時に0を返し、ユーザーが提供したfm_extents配列が満杯になった場合は1を返します。エクステントをユーザーメモリにコピー中にエラーが発生した場合、-EFAULTが返されます。
