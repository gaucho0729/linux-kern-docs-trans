チェックサム¶

2012年上半期から、すべての主要なext4およびjbd2データ構造にメタデータチェックサムが追加されました。関連する機能フラグはmetadata_csumです。使用するチェックサムアルゴリズムはスーパーブロックで指定されていますが、2012年10月時点ではサポートされているアルゴリズムはcrc32cのみです。一部のデータ構造には32ビットのチェックサムを格納するためのスペースがなかったため、16ビットのみが保存されています。64bit機能を有効にするとデータ構造のサイズが増加し、多くのデータ構造で32ビットのチェックサムを格納できるようになります。ただし、既存の32ビットファイルシステムは64bitモードに拡張することはできません（少なくとも実験的なresize2fsパッチを適用しない限り）。

既存のファイルシステムは以下のコマンドを実行することでチェックサムを追加できます tune2fs -O metadata_csum 下位デバイスに対して。tune2fsがディレクトリブロックに十分な空き領域がなければ、チェックサムを追加するための再構築を実行するよう求めます e2fsck -D ディレクトリをチェックサム付きで再構築するためのコマンドを実行してください。この作業にはディレクトリファイルの空き領域を削除し、htreeインデックスを再バランスするという追加のメリットがあります。このステップを無視すると、ディレクトリはチェックサムで保護されません！

以下の表は、各チェックサムタイプに含まれるデータ要素を説明しています。チェックサム関数はスーパーブロックで指定されているもの（2013年10月時点ではcrc32c）で、特に記載がない限りそのままであります。

メタデータ

長さ

構成要素

スーパーブロック

__le32

チェックサムフィールドまでのスーパーブロック全体。UUIDはスーパーブロック内に含まれています。

MMP

__le32

UUID + チェックサムフィールドまでのMMPブロック全体

拡張属性

__le32

UUID + すべての拡張属性ブロック。チェックサムフィールドはゼロに設定されています。

ディレクトリエントリ

__le32

UUID + inode番号 + inode生成番号 + チェックサムフィールドを含む偽のエントリまでのディレクトリブロック

HTREEノード

__le32

UUID + inode番号 + inode生成番号 + すべての有効なエクステント + HTREEテール。チェックサムフィールドはゼロに設定されています。

エクステント

__le32

UUID + inode番号 + inode生成番号 + チェックサムフィールドまでのエクステントブロック全体

ビットマップ

__le32 or __le16

UUID + すべてのビットマップ。チェックサムはグループ記述子に保存され、グループ記述子サイズが32バイト（つまり^64bit）の場合には切り捨てられます

インODE

__le32

UUID + inode番号 + inode生成番号 + すべてのinode。チェックサムフィールドはゼロに設定されています。各inodeには独自のチェックサムがあります。

グループ記述子

__le16

metadata_csumの場合、UUID + グループ番号 + すべての記述子；gdt_csumの場合、crc16(UUID + グループ番号 + すべての記述子)。いずれの場合も、下位16ビットのみが保存されます。
