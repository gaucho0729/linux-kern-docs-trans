Amigaファイルシステムの概要¶

すべての Amiga ファイルシステムの種類が読み書き可能としてサポートされていません。現在の Amiga は、6 種類の異なるファイルシステムを認識しています:

DOS0

古いまたは元のファイルシステムで、ハードディスクにはあまり適しておらず、通常は使用されません。読み書き可能。

DOS1

元の高速ファイルシステム。読み書き可能。

DOS2

古い「国際的」ファイルシステム。国際的とは、アクセント（国際的）文字をファイル名に含めた場合でも大文字小文字を区別しないようにバグを修正したことを意味します。読み書き可能。

DOS3

「国際的」高速ファイルシステム。読み書き可能。

DOS4

元のディレクトリキャッシュを持つファイルシステム。ディレクトリキャッシュはフロッピーディスクのディレクトリアクセスを大幅に高速化しますが、ファイルの作成・削除には逆に遅くなります。ハードディスクではあまり意味がありません。読み取り専用。

DOS5

ディレクトリキャッシュを持つ高速ファイルシステム。読み取り専用。

上記のすべてのファイルシステムは、ブロックサイズが 512 バイトから 32K バイトまで可能です。サポートされるブロックサイズは 512 バイト、1024 バイト、2048 バイト、4096 バイトです。大きなブロックサイズはディスク空間の浪費を伴いますが、処理速度を大幅に向上させます。4K バイト以上では得られる恩恵がそれほど大きくないため、通常は不要です。

上記のファイルシステムに相当する muFS（マルチユーザー ファイルシステム）もサポートされています。

AFFS のマウントオプション¶

protect

このオプションが設定されている場合、保護ビットの変更が禁止されます。

setuid[=uid]

ファイルシステム内のすべてのファイルおよびディレクトリの所有者を uid または現在のユーザーの uid に設定します。

setgid[=gid]

gid に対して同様の動作を行います。

mode=mode

指定された（八進数）値にモードフラグを設定します。元のパーミッションを無視します。ディレクトリは、対応する r ビットが設定されている場合、x パーミッションが付与されます。これは、AmigaOS のほとんどのファイルが 600 にマッピングするため、役立ちます。

nofilenametruncate

ファイル名が標準の最大ファイル名長（30 文字）を超えた場合、エラーが返されます。

reserved=num

パーティションの開始位置に予約ブロックを num 個設定します。このオプションは必要ありません。デフォルトは 2 です。

root=block

ルートブロックのブロック番号を設定します。これは必要ありません。

bs=blksize

ブロックサイズを blksize に設定します。有効なブロックサイズは 512 バイト、1024 バイト、2048 バイト、4096 バイトです。root オプション同様、affs が自動的に判別できるため、通常必要ありません。

quiet

ファイルシステムは、許可されていないモード変更に対してエラーを返しません。

verbose

ファイルシステムがマウントされたときに、ボリューム名、ファイルシステムタイプ、ブロックサイズがsyslogに記録されます。

mufs

ファイルシステムは実際にはmuFSですが、自身をmuFSと識別していません。ファイルシステムがmuFSとして使用されているが、フォーマットされていない場合、このオプションが必要です。

prefix=path

AFFSパーティション上のシンボリックリンクの絶対パス名にはこのパスが先頭に付加されます。デフォルトは「/」です。(下記を参照してください。)

volume=name

AFFSパーティション上で絶対パスを持つシンボリックリンクが作成される際、nameがボリューム名として先頭に付加されます。デフォルトは空文字です。(下記を参照してください。)

ユーザー/グループおよび保護フラグの処理¶

Amiga → Linux:

Amigaの保護フラグRWEDRWEDHSPARWEDは以下のようになります:

  • Rはユーザー、グループ、その他に対してrにマッピングされます。ディレクトリではRはxを意味します。

  • Wはwにマッピングされます。

  • Eはxにマッピングされます。

  • Dは無視されます。

  • H、S、PはLinuxでは常に保持され、無視されます。

  • ファイルに書き込まれるときAはクリアされます。

ユーザーIDとグループIDが使用されます（set[gu]idがマウントオプションとして指定されていない場合）。ほとんどのAmigaファイルシステムは単ユーザーのシステムなので、rootが所有者になります。Amigaファイルシステムのルートディレクトリ（マウントポイント）は、実際にファイルシステムをマウントするユーザー（rootディレクトリにはuid/gidフィールドがありません）が所有者になります。

Linux → Amiga:

Linuxのrwxrwxrwxファイルモードは以下のようになります:

  • r権限はユーザー、グループ、その他に対してRを許可します。

  • w権限はユーザー、グループ、その他に対してWを許可します。

  • ユーザーのx権限は通常ファイルに対してEを許可します。

  • ユーザー、グループ、その他に対してDを許可します。

  • その他のフラグ（suid、sgidなど）は無視され、保持されません。

新たに作成されるファイルとディレクトリは現在のユーザーのユーザーIDとグループIDを取得し、umaskに応じたモードを取得します。

シンボリックリンク¶

AmigaとLinuxのファイルシステムは似ていますが、いくつかの違いがあります。そのうちの一つはシンボリックリンクに関係します。Linuxではファイルシステムにちょうど一つのルートディレクトリがありますが、Amigaでは各ファイルシステム（例えば、パーティション、フロッピーディスクなど）に別個のルートディレクトリがあります。Amigaではこれらのエントリを「ボリューム」と呼び、シンボリックな名前でアクセスできます。したがって、シンボリックリンクは別のボリュームを指すことができます。AFFSはボリューム名をディレクトリ名に変換し、prefixパス（prefixオプションを参照）を先頭に付加します。

例: すべてのAmigaパーティションを/amiga/<volume>（<volume>はボリューム名）の下にマウントし、すべてのAFFSパーティションをマウントする際には「prefix=/amiga/」というオプションを指定します。（それらは「User」「WB」「Graphics」などになる可能性があり、マウントポイントは/amiga/User、/amiga/WB、/amiga/Graphicsになります）。'User:sc/include/dos/dos.h'を参照するシンボリックリンクは、/amiga/User/sc/include/dos/dos.hに解決されます。

例¶

コマンドライン:

mount  Archive/Amiga/Workbench3.1.adf /mnt -t affs -o loop,verbose
mount  /dev/sda3 /Amiga -t affs

/etc/fstabエントリ:

/dev/sdb5   /amiga/Workbench    affs    noauto,user,exec,verbose 0 0

重要なお知らせ¶

Windows 95を起動する際（3.x、98、NTについては確認していません）、PCにAmigaハードディスクを接続している場合、Rigid Disk Block（RDB）のブロック0の0x00dc〜0x00dfバイトがゴミデータで上書きされ、RDBが無効になります。幸いなことにこの領域はRDBの未使用領域なので、チェックサムのみが一致しなくなるだけです。Linuxはこのゴミデータを無視してRDBを認識しますが、Amigaに再度接続する前にRDBを復元または修復する必要があります。Windowsを起動する前にRDBのバックアップを取ってください。

すでに損傷が発生している場合、以下のコマンドでRDBを修復できます（<disk>はデバイス名です）。

自己責任で実施してください:

dd if=/dev/<disk> of=rdb.tmp count=1
cp rdb.tmp rdb.fixed
dd if=/dev/zero of=rdb.fixed bs=1 seek=220 count=4
dd if=rdb.fixed of=/dev/<disk>

バグ、制限事項、注意点¶

多くの機能が予想通り動作しない可能性があります。すべてがテスト済みではありませんが、このファイルシステムを使用して何百MBものデータを読み書きしています。最新のバグ情報についてはfs/affs/Changesを参照してください。

デフォルトではファイル名が30文字にトリミングされます（警告なし）。'nofilenametruncate'マウントオプションでこの挙動を変更できます。

AFFSではファイル名マッチング時にケースを区別しませんが、Linuxのシェルではケースを区別します。例（/wbがAFFSマウントされたファイルシステムの場合）:

rm /wb/WRONGCASE

は/mnt/wrongcaseを削除しますが、

rm /wb/WR*

はシェルがファイル名をマッチングするため、削除されません。

ブロック割り当てはハードディスクパーティション用に設計されています。複数のプロセスが（小さな）ディスクettenに書き込む場合、ブロックが不格好な方法で割り当てられます（実際のAFFSもこれ以上改善していません）。空間が限られている場合でも同様です。

OFS（Old File System）上ではプログラムを実行できません。これは488バイトのブロックサイズによりメモリマップが不可能なためです。同様の理由で、このようなファイルシステムにイメージをループバックデバイス経由でマウントすることもできません。

RDBのルートブロック内のビットマップ有効フラグは、AFFSパーティションがマウントされている間にシステムがクラッシュした場合に正確でなくなる可能性があります。現在ではAmiga（ディスク検証ツール）や手動でなければガタがかったファイルシステムを修復する方法はありません（誰がそんなことをするでしょうか？）。今後は改善されるかもしれません。

システム起動時にaffsパーティションをマウントする場合、fsckにこのファイルシステムのチェックを実行しないように伝える必要があります（/etc/fstabの6番目のフィールドに「0」を設定してください）。

通常のPCまたはワークステーションでは、Amiga floppy controllerとの互換性の問題により、floppyディスクを読み込むことができません。
