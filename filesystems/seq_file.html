seq_fileインターフェース¶

著作権 2003 Jonathan Corbet <corbet@lwn.net>

このファイルは、LWN.netのドライバ移植シリーズから元々取り込まれています。 https://lwn.net/Articles/driver-porting/

デバイスドライバ（または他のカーネルコンポーネント）がシステム管理者やユーザーに情報を提供する方法は複数ありますが、仮想ファイルの作成は有用な技術の一つです。debugfs、/procなどに仮想ファイルを作成することで、特殊なユーティリティプログラムを使わずに人間が読みやすい出力が得られ、スクリプトライターにとっても作業が楽になります。このような仮想ファイルの利用は年々増えてきています。

仮想ファイルの作成を正しく行うのは常にちょっとした課題でした。文字列を返す仮想ファイルを作るのはそれほど難しくありませんが、出力が長くなると（1回の操作でアプリケーションが読み取るよりも長い場合）、複数の読み込み（およびシーク）を処理する際には、読者による仮想ファイル内の位置管理が重要になります。その位置は、出力行の中間であることが多く、カーネルはこれまでに複数の実装が誤って実装された歴史があります。

2.6カーネルには、Alexander Viroによって実装された関数セットがあり、仮想ファイルの作成者が正しい実装を行うことを容易にします。

seq_fileインターフェースは<linux/seq_file.h>で利用可能です。seq_fileには3つの側面があります。

  • 仮想ファイルの実装が提示するオブジェクトをステップで処理できるイテレータインターフェース。

  • 出力バッファなどの詳細を気にせずオブジェクトを出力形式に変換するためのユーティリティ関数。

  • 仮想ファイルのほとんどの操作を実装するための汎用的なfile_operationsセット。

ここでは、非常に単純な例を通じてseq_fileインターフェースを確認します。ロード可能なモジュールを作成し、/proc/sequenceというファイルを作成します。このファイルを読み込むと、1行ずつ増加する整数値が表示されます。シーケンスはユーザーが他のことに興味を持った時点で終了します。このファイルはシーク可能で、以下のような操作が可能です：

dd if=/proc/sequence of=out1 count=1
dd if=/proc/sequence skip=1 of=out2 count=1

出力ファイルout1とout2を結合して正しい結果を得られます。はい、これは完全に無駄なモジュールですが、メカニズムを示すために他の詳細に埋もれることなく説明しています。（このモジュールの完全なソースコードを確認したい場合は、 https://lwn.net/Articles/22359/).

非推奨のcreate_proc_entry¶

上記の記事ではcreate_proc_entryを使用していますが、これは3.10カーネルで削除されました。現在のバージョンでは以下の更新が必要です：

-   entry = create_proc_entry("sequence", 0, NULL);
-   if (entry)
-           entry->proc_fops = &ct_file_ops;
+   entry = proc_create("sequence", 0, NULL, &ct_file_ops);

イテレータインターフェース¶

seq_fileを用いて仮想ファイルを実装するモジュールは、セッション（ Roughly one read()システムコール）の間にデータの関心領域をステップで走査できるイテレータオブジェクトを実装しなければなりません。イテレータが特定の位置に移動できる場合（ファイルを実装するものと同様ですが、位置番号をシーケンスの位置にどのようにマッピングするかは任意）、イテレータはセッション中に一時的に存在するだけでよいです。イテレータが数値の位置を簡単に見つけることができないが、first/nextインターフェースとよく合う場合、イテレータはプライベートデータ領域に保存され、セッションごとに継続的に使用できます。

たとえば、テーブルからファイアウォールルールをフォーマットするseq_file実装は、位置Nをチェーン内のN番目のルールと解釈する単純なイテレータを提供できます。潜在的に変動するリンクリストのコンテンツを表示するseq_file実装は、リスト内のポインタを記録し、現在の位置が削除されるリスクがない限り、そのポインタを提供できます。

データジェネレータにとって最も意味のある方法で位置決めが行われるため、ジェネレータは仮想ファイル内のオフセットへの位置の変換について意識する必要はありません。ただし、ゼロの位置はファイルの開始を示すべきです。

/proc/sequenceイテレータは、次の数字のカウントをその位置として使用します。

イテレータが動作するためには4つの関数を実装しなければなりません。最初の関数は start()、セッションを開始し、位置を引数として受け取り、その位置から読み始めるイテレータを返します。posが start() に渡されるのは常にゼロ、または前回セッションで使用した最も最近のposです。

シンプルなシーケンス例では、 start() 関数は以下のようになります：

static void *ct_seq_start(struct seq_file *s, loff_t *pos)
{
        loff_t *spos = kmalloc(sizeof(loff_t), GFP_KERNEL);
        if (! spos)
                return NULL;
        *spos = *pos;
        return spos;
}

このイテレータのデータ構造全体は、現在の位置を保持する単一のloff_t値です。シーケンスイテレータには上限がありませんが、他のseq_file実装ではそうではありません。ほとんどの場合、 start() 関数は「ファイルの終わりを過ぎた」状態を確認し、必要に応じてNULLを返す必要があります。

static void ct_seq_stop(struct seq_file *s, void *v)
{
        kfree(v);
}

static int ct_seq_show(struct seq_file *s, void *v)
{
        loff_t *spos = v;
        seq_printf(s, "%lld\n", (long long)*spos);
        return 0;
}

すべてが正常であれば、show()関数はゼロを返します。通常の方法で負のエラーコードが返されると、何かがうまくいかなかったことを示します。このエラーコードはユーザー空間に戻されます。この関数はまたSEQ_SKIPを返すこともあり、これにより現在の項目はスキップされます。show()関数がSEQ_SKIPを返す前に出力を行っていた場合、その出力は無視されます。

seq_printf()については後で詳しく見ますが、まずはseq_operations構造体を作成してseq_fileイテレータの定義を完了します。この構造体には先ほど定義した4つの関数を含みます。

static const struct seq_operations ct_seq_ops = {
        .start = ct_seq_start,
        .next  = ct_seq_next,
        .stop  = ct_seq_stop,
        .show  = ct_seq_show
};

この構造体は、seq_fileコードと/procファイルを少しの間結びつけるために必要です。

seq_fileコードがイテレータ値を処理する際、この値は完全に不透明とみなされます。したがって、出力するデータをステップで進めるのに役立つ何でも良いです。カウンターが有用ですが、配列やリンクリストへの直接のポインタでも構いません。プログラマがイテレータ関数の呼び出し間で何かが起こる可能性を理解している限り、何でも可能です。 start() ただし、seq_fileコード（設計上）はイテレータ関数の呼び出し間でスリープしません。そのため、その間ロックを保持することは合理的です。seq_fileコードはイテレータがアクティブな間、他のロックを取得しません。 start() および stop()したがって、その間ロックを保持することは合理的です。seq_fileコードはイテレータがアクティブな間、他のロックを取得しません。

イテレータ値が返される際、 start() next()が次のnext()または stop() 呼び出しに確実に渡されることが保証されています。これにより、ロックなどのリソースを信頼性よく解放できます。ただし、 no イテレータがshow()に渡される保証はありませんが、実際にはそうすることが多いです。

フォーマットされた出力¶

seq_fileコードは、イテレータによって生成された出力の位置を管理し、ユーザーのバッファにその出力を渡します。ただし、この動作を行うには、出力がseq_fileコードに渡される必要があります。いくつかのユーティリティ関数がこのタスクを容易にするよう定義されています。

ほとんどのコードはseq_printf()を使用します。これは printk()にほぼ同じように動作しますが、seq_fileポインタを引数として必要とします。

直接の文字出力には、次の関数を使用できます：

seq_putc(struct seq_file *m, char c);
seq_puts(struct seq_file *m, const char *s);
seq_escape(struct seq_file *m, const char *s, const char *esc);

最初の2つの関数は、単一の文字と文字列を出力し、予想通りの動作を行います。 seq_escape() これはseq_puts()に似ていますが、文字列esc内の文字はすべて8進法で出力されます。

ファイル名の出力には、次の関数ペアもあります：

int seq_path(struct seq_file *m, const struct path *path,
             const char *esc);
int seq_path_root(struct seq_file *m, const struct path *path,
                  const struct path *root, const char *esc)

ここでpathは対象のファイルを示し、escは出力時にエスケープする文字の集合です。呼び出しは seq_path() 現在のプロセスのファイルシステムルートに対して相対的なパスを出力します。異なるルートを指定したい場合は、seq_path_root()関数で使用できます。パスがルートから到達できない場合、seq_path_root()はSEQ_SKIPを返します。

出力が複雑な関数は以下のチェックを行いたいかもしれません：

bool seq_has_overflowed(struct seq_file *m);

trueが返された場合、さらにseq_<output>の呼び出しを避ける必要があります。

seq_has_overflowedからtrueが返された場合、seq_fileバッファは破棄され、seq_show関数がより大きなバッファを確保して再試行します。

すべてを動作させる¶

これまでにseq_fileシステム内で出力を行うための便利な関数群を用意しましたが、ユーザーが実際に確認できるファイルに変換していません。カーネル内にファイルを作成するには、ファイル操作を実装するfile_operations構造体の作成が必要です。seq_fileインターフェースは多くの作業を自動化する既製の操作を提供しますが、仮想ファイルの作成者はopen()メソッドを実装する必要があります。open関数は多くの場合、例のモジュールのように単一行で実装されます：

static int ct_open(struct inode *inode, struct file *file)
{
        return seq_open(file, &ct_seq_ops);
}

ここで、 seq_open() は以前に作成したseq_operations構造体を用いて、仮想ファイルの反復処理をセットアップします。

openが成功した場合、 seq_open() はstruct seq_fileポインタをfile->private_dataに格納します。同じイテレータを複数のファイルで使用するアプリケーションでは、seq_file構造体のprivateフィールドに任意のポインタを格納できます。この値はイテレータ関数から後で取得できます。

また、 seq_open() というラッパー関数があります。この関数はゼロ埋めされたメモリブロックをkmallocで確保し、seq_file構造体のprivateフィールドにポインタを保存して成功時に0を返します。ブロックサイズは関数の第3引数で指定します（例：

static int ct_open(struct inode *inode, struct file *file)
{
        return seq_open_private(file, &ct_seq_ops,
                                sizeof(struct mystruct));
}

また、__seq_open_private()という変種関数もあります。機能的には同じですが、成功した場合、確保したメモリブロックのポインタを返して、さらに初期化が可能になります（例：

static int ct_open(struct inode *inode, struct file *file)
{
        struct mystruct *p =
                __seq_open_private(file, &ct_seq_ops, sizeof(*p));

        if (!p)
                return -ENOMEM;

        p->foo = bar; /* initialize my stuff */
                ...
        p->baz = true;

        return 0;
}

対応するclose関数としてseq_release_private()が利用でき、このopenで確保したメモリを解放します。

他の操作関心のあるread()、llseek()、release()はすべてseq_fileコードが実装します。したがって、仮想ファイルのfile_operations構造体は以下のようになります：

static const struct file_operations ct_file_ops = {
        .owner   = THIS_MODULE,
        .open    = ct_open,
        .read    = seq_read,
        .llseek  = seq_lseek,
        .release = seq_release
};

また、seq_release_private()はseq_fileのprivateフィールドの内容を kfree() に渡して構造体を解放します。

最終的なステップは/procファイル自体の作成です。例示コードでは、通常の方法で初期化コード内で行われています:

static int ct_init(void)
{
        struct proc_dir_entry *entry;

        proc_create("sequence", 0, NULL, &ct_file_ops);
        return 0;
}

module_init(ct_init);

それだけです。

seq_list¶

ファイルがリンクリストを走査する場合、これらのルーチンは役立つかもしれません:

struct list_head *seq_list_start(struct list_head *head,
                                 loff_t pos);
struct list_head *seq_list_start_head(struct list_head *head,
                                      loff_t pos);
struct list_head *seq_list_next(void *v, struct list_head *head,
                                loff_t *ppos);

これらのヘルパーはposをリスト内の位置として解釈し、それに応じて走査を行います。あなたの start() next()関数は、適切なlist_head構造体へのポインタを渡してこれらのヘルパーを呼び出すだけでよいです。 seq_list_* helpers with a pointer to the appropriate list_head structure.

さらに簡単なバージョン¶

非常にシンプルな仮想ファイルにはさらに簡単なインターフェースがあります。モジュールはshow()関数のみを定義すればよいです。この関数は仮想ファイルが含むすべての出力を生成する必要があります。ファイルのopen()メソッドは次のように呼び出します:

int single_open(struct file *file,
                int (*show)(struct seq_file *m, void *p),
                void *data);

出力が必要なとき、show()関数が1回呼び出されます。single_open()に渡されたデータ値はseq_file構造体のprivateフィールドにあります。single_open()を使用する際は、file_operations構造体でsingle_release()を使用するべきです。 seq_release() in the file_operations structure to avoid a memory leak.
