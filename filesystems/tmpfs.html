Tmpfs¶

Tmpfs は、すべてのファイルを仮想メモリに保持するファイルシステムです。

tmpfs に保存されているすべてのデータは一時的なものであり、ハードディスクにファイルが作成されることはありません。tmpfs のインスタンスをアンマウントすると、その中に保存されていたすべてのデータが失われます。

tmpfs はすべてのデータをカーネルの内部キャッシュに保持し、含まれるファイルに応じてサイズを拡大または縮小します。不要なページはスワップ領域にスワップアウトできます。最大サイズ制限は、'mount -o remount …' を使用してリアルタイムで調整可能です。

ramfs（tmpfs のテンプレート）と比較すると、スワップとサイズ制限のチェックが追加されています。また、RAM ディスク（/dev/ram*）は物理メモリに固定サイズのハードディスクをシミュレートし、通常のファイルシステムを上に構築する必要があります。RAM ディスクはスワップをサポートせず、サイズ変更もできません。

tmpfs は完全にページキャッシュとスワップ領域に存在するため、/proc/meminfo ではすべての tmpfs ページが「Shmem」と表示され、free(1) では「Shared」と表示されます。これらのカウンターには共有メモリ（shmem、ipcs(1) を参照）も含まれます。信頼性の高いカウント方法は df(1) と du(1) を使用することです。

tmpfs の主な用途は以下の通りです：

  1. カーネル内部マウントは常に存在し、すべてのユーザーには表示されません。これは共有匿名マッピングと SYSV 共有メモリに使用されます。

    このマウントは CONFIG_TMPFS に依存しません。CONFIG_TMPFS が設定されていない場合、ユーザーが見える tmpfs の部分は構築されません。ただし、内部メカニズムは常に存在します。

  2. glibc 2.2 以降は、POSIX 共有メモリ（shm_open、shm_unlink）のために tmpfs を /dev/shm にマウントする必要があります。/etc/fstab に以下の行を追加することでこれを実現できます：

    tmpfs   /dev/shm        tmpfs   defaults        0 0

    必要に応じて、tmpfs をマウントするディレクトリを作成してください。

    このマウントは SYSV 共有メモリには必要ありません。内部マウントがその用途に使用されます。（2.3 カーネルでは tmpfs の前身（shm fs）をマウントする必要がありました）

  3. 一部の人（含む私）は、/tmp と /var/tmp などに tmpfs をマウントし、大きなスワップパーティションを持つことが非常に便利だと考えています。現在、tmpfs ファイルのループマウントが動作するため、ほとんどのディストリビューションで提供される mkinitrd は tmpfs /tmp で成功するはずです。

  4. おそらく私は知らないことがさらに多くあるでしょう :-)

tmpfs にはサイズ設定用の3つのマウントオプションがあります：

size

この tmpfs インスタンスの割り当てられたバイト数の制限です。デフォルトではスワップを除いた物理 RAM の半分です。tmpfs インスタンスを過大に設定すると、OOM ハンドラがそのメモリを解放できず、マシンがデッドロックします。

nr_blocks

サイズと同じですが、PAGE_SIZEのブロック単位で計算されます。

nr_inodes

このインスタンスの最大インノード数を指定します。デフォルトは物理メモリページ数の半分ですが、highmemマシンではローメモリページ数と比較して低い方を採用します。

これらのパラメータは、k、m、gのサフィックスでキロ、メガ、ギガを指定でき、再マウント時に変更可能です。sizeパラメータには%サフィックスを指定して、物理メモリのそのパーセンテージに制限できます。sizeとnr_blocksが指定されていない場合のデフォルトはsize=50%です。

nr_blocks=0（またはsize=0）の場合、そのインスタンスのブロック制限はありません。nr_inodes=0の場合はインノード制限はありません。このようなオプションでマウントするのは一般的には不推奨ですが、多くのCPUが重い使用をすることのあるシステムではそのインスタンスのスケーラビリティを向上させます。

tmpfsには、NUMAメモリ割当ポリシーをすべてのファイルに設定するマウントオプションがあります（CONFIG_NUMAが有効の場合）。これは「mount -o remount …」でリアルタイムに調整可能です。

mpol=default

プロセスの割当ポリシーを使用します（set_mempolicy(2)を参照）

mpol=prefer:Node

指定されたNodeからメモリを割当てる傾向があります

mpol=bind:NodeList

メモリはNodeList内のノードのみから割当てられます

mpol=interleave

各ノードを順番にメモリを割当てる傾向があります

mpol=interleave:NodeList

NodeList内の各ノードを順番にメモリを割当てます

mpol=local

ローカルのノードからメモリを割当てる傾向があります

NodeListは、小数点を含むコンマ区切りの数値と範囲で指定します。範囲はハイフンで区切られた2つの小数点数で、範囲内の最小と最大のノード番号を表します。例: mpol=bind:0-3,5,7,9-15

有効なNodeListを持つメモリポリシーは、ファイル作成時に指定された通り保存されます。タスクがファイルシステム内でファイルを割当てる際、マウントオプションのメモリポリシーが適用され、NodeList（存在すれば）呼び出しタスクのcpuset制約によって変更されます[参照] CPUSETS] および以下のオプションフラグが適用されます。結果として得られたNodeListが空集合の場合、ファイルの有効なメモリポリシーは「default」ポリシーに戻ります。

NUMAメモリ割当ポリシーには、モードと併用可能なオプションフラグがあります。tmpfsをマウント時にこれらのフラグをモードの後に指定することで使用可能です。参照 NUMA Memory Policy すべての利用可能なメモリ割当ポリシーのモードフラグとそのメモリポリシーへの影響についてのリストです。

=static         is equivalent to        MPOL_F_STATIC_NODES
=relative       is equivalent to        MPOL_F_RELATIVE_NODES

たとえば、mpol=bind=static:NodeList は、MPOL_BIND | MPOL_F_STATIC_NODES の割当ポリシーに相当します。

tmpfs を mpol オプションでマウントしようとすると、実行中のカーネルが NUMA をサポートしていない場合、または nodelist にオンラインでないノードを指定している場合に失敗します。システムが tmpfs のマウントに依存しているが、たまに NUMA 機能を備わわないカーネル（安全な回復用カーネルなど）を実行する場合、またはオンラインノードが少ない場合がある場合は、自動マウントオプションから mpol オプションを省略することをお勧めします。tmpfs が MountPoint にすでにマウントされている場合、'mount -o remount,mpol=Policy:NodeList MountPoint' で後から追加できます。

初期のルートディレクトリを指定するには、以下のマウントオプションを使用できます：

mode

8進数で表したパーミッション

uid

ユーザーID

gid

グループID

これらのオプションは再マウントには影響しません。マウント済みのファイルシステムでは、chmod(1)、chown(1)、chgrp(1) でこれらのパラメータを変更できます。

tmpfs には、インODE番号が32ビットか64ビットかを選択するマウントオプションがあります：

inode64

64ビットインODE番号を使用する

inode32

32ビットインODE番号を使用する

32ビットカーネルでは inode32 は暗黙の設定であり、inode64 はマウント時に拒否されます。64ビットカーネルでは CONFIG_TMPFS_INODE64 がデフォルトになります。inode64 は、1つのデバイス内での複数ファイルのインODE番号が重複する可能性を防ぎますが、33ビットインODE番号に達した際に glibc が EOVERFLOW で失敗するリスクがあります。これは、32ビットアプリケーションが長期間稼働し、2GiB を超えるファイルを開くと EINVAL で失敗する非常に古いアプリケーションが tmpfs をアクセスする場合に発生します。

したがって、'mount -t tmpfs -o size=10G,nr_inodes=10k,mode=700 tmpfs /mytmpfs' は、/mytmpfs に 10GB の RAM/SWAP を 10240 の inode で割当可能で、root だけがアクセス可能な tmpfs インスタンスを提供します。
