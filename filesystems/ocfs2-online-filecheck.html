OCFS2ファイルシステム - オンラインファイルチェック¶

このドキュメントでは、OCFS2のオンラインファイルチェック機能について説明します。

はじめに¶

OCFS2は高可用性システムでよく使用されます。しかし、エラーが発生するとファイルシステムが読み取り専用に変換されることが一般的です。これは必要ない場合もあり、ファイルシステムを読み取り専用にすると他の実行中のプロセスにも影響を及ぼし、可用性が低下する可能性があります。そのため、mountオプション（errors=continue）が導入され、呼び出し元プロセスに-EIOエラーを返して処理を終了させることで、ファイルシステムの破壊を防ぎます。ファイルシステムは読み取り専用にされず、問題のあるファイルのインODE番号がカーネルログに報告されます。ユーザーはオンラインファイルチェック機能を使用してこのファイルを確認・修復できます。

範囲¶

この取り組みは、クラスターファイルシステムの日常運用を妨げる小さな問題を解決することを目的としています。初期は通常ファイルを対象にし、最終的にはファイルシステム内のすべてのファイル（システムファイルを含む）を対象にします。

ディレクトリとファイルのリンクが正しくない場合、ディレクトリインODEがエラーとして報告されます。

この機能は、ファイルシステムの他のコンポーネントへの依存関係を伴う大規模なチェックには不向きです。例えば、ファイルブロックのビットが設定されているかを確認するようなエラーの場合、オフラインfsckの使用が推奨されます。

このような操作/機能は自動化すべきではありません。ファイルシステムが修復試行前よりもさらに破損する可能性があるため、ユーザーの操作と同意のもとで実行する必要があります。

ユーザーインターフェース¶

OCFS2ファイルシステムにエラーが発生した場合、通常そのエラーを引き起こしたインODE番号が伴います。このインODE番号はファイルの確認・修復に使用されます。

各OCFS2ファイルシステムのマウントごとにsysfsディレクトリがあります:

/sys/fs/ocfs2/<devname>/filecheck

ここで、<devname>はすでにマウントされたOCFS2ボリュームデバイスの名前を示します。上のファイルはインODE番号を受け入れます。これにより、カーネル空間と通信し、チェックまたは修復するファイル（インODE番号）を指定できます。現在は3つの操作がサポートされており、インODEのチェック、インODEの修復、結果レコード履歴のサイズ設定です。

  1. <inode>を修復する前に発生した具体的なエラーを確認するには、以下を実行します:

    # echo "<inode>" > /sys/fs/ocfs2/<devname>/filecheck/check
# cat /sys/fs/ocfs2/<devname>/filecheck/check

出力は次のようになります:

INO         DONE    ERROR
39502               1       GENERATION

<INO> lists the inode numbers.
<DONE> indicates whether the operation has been finished.
<ERROR> says what kind of errors was found. For the detailed error numbers,
please refer to the file linux/fs/ocfs2/filecheck.h.

  1. このインODEを修復する場合は、以下を実行します:

    # echo "<inode>" > /sys/fs/ocfs2/<devname>/filecheck/fix
# cat /sys/fs/ocfs2/<devname>/filecheck/fix

出力は次のようになります::

INO         DONE    ERROR
39502               1       SUCCESS

今回は、<ERROR>列はこの修正が成功したかどうかを示しています。

3. 記録キャッシュはチェック/修正結果の履歴を保存するために使用されます。デフォルトのサイズは10で、10〜100の範囲内で調整可能です。サイズを調整するには以下のようにします：

# echo "<size>" > /sys/fs/ocfs2/<devname>/filecheck/set

不具合修正¶

inodeを受信すると、ファイルシステムはinodeとファイルメタデータを読み込みます。エラーが発生した場合、ファイルシステムはエラーを修正し、修正した問題をカーネルログに報告します。予防策として、最終的な修正を行う前にinodeのエラーをまず確認する必要があります。

inodeと結果の履歴は、最後に修正/チェックされた(N)個のinodeと、修正/チェックされた詳細なエラーが含まれる小さなリンクリストバッファに一時的に保持されます。これらの詳細なエラーはカーネルログに印刷されます。
