それは何ですか:¶

sysfsは、RAMベースのファイルシステムであり、初期的にはramfsに基づいています。これは、カーネルデータ構造、その属性、およびそれらの間のリンクをユーザー空間にエクスポートする手段を提供します。

sysfsは、kobjectインフラストラクチャに固有に結合されています。詳しくは kobjects、ksets、ktypesについてのすべての知識 kobjectインターフェースに関する情報をお読みください。

sysfs の使用¶

CONFIG_SYSFSが定義されている限り、sysfsは常にコンパイルされます。アクセスするには以下を行います:

mount -t sysfs sysfs /sys

ディレクトリ作成¶

システムに登録されたすべてのkobjectに対して、sysfs内にそのkobject用のディレクトリが作成されます。このディレクトリは、kobjectの親のサブディレクトリとして作成され、内部のオブジェクト階層をユーザー空間に表現します。sysfsのトップレベルディレクトリは、オブジェクト階層の共通の祖先を表し、つまりオブジェクトが属するサブシステムを示します。

Sysfsは、ディレクトリに関連するkernfs_nodeオブジェクトに、そのディレクトリを実装するkobjectへのポインタを内部的に保持しています。過去には、sysfsがファイルを開閉するたびにkobjectの参照カウントを直接操作するためにこのkobjectポインタを使用していました。現在のsysfs実装では、kobject参照カウントはsysfs_schedule_callback()関数のみが直接変更します。

属性¶

kobjectの属性は、ファイルシステム内の通常のファイルとしてエクスポートできます。SysfsはファイルI/O操作を、属性に定義されたメソッドにフォワーディングし、カーネル属性の読み書きを可能にします。

属性はASCIIテキストファイルでなければなりません。1ファイルに1つの値のみを含むのが望ましいですが、1ファイルに1つの値を含むのは効率的でない可能性があるため、同じ型の値の配列を表現するのは社会的に許容されます。

型の混在、複数行のデータ表現、データの複雑なフォーマットは強く非難されます。このような操作を行うと、公開的に恥をかかされる可能性があり、コードが突然再実装されることがあります。

属性定義は単純に:

struct attribute {
        char                    * name;
        struct module               *owner;
        umode_t                 mode;
};


int sysfs_create_file(struct kobject * kobj, const struct attribute * attr);
void sysfs_remove_file(struct kobject * kobj, const struct attribute * attr);

裸の属性は、属性値の読み書き手段を持たないため、サブシステムは特定のオブジェクトタイプに対して属性を追加・削除するための独自の属性構造とラッパー関数を定義することを推奨されます。

たとえば、ドライバモデルはstruct device_attributeを以下のように定義します:

struct device_attribute {
        struct attribute    attr;
        ssize_t (*show)(struct device *dev, struct device_attribute *attr,
                        char *buf);
        ssize_t (*store)(struct device *dev, struct device_attribute *attr,
                        const char *buf, size_t count);
};

int device_create_file(struct device *, const struct device_attribute *);
void device_remove_file(struct device *, const struct device_attribute *);

また、デバイス属性を定義するためのこのヘルパ関数も定義しています:

#define DEVICE_ATTR(_name, _mode, _show, _store) \
struct device_attribute dev_attr_##_name = __ATTR(_name, _mode, _show, _store)

たとえば、宣言:

static DEVICE_ATTR(foo, S_IWUSR | S_IRUGO, show_foo, store_foo);

は以下の操作に等価です:

static struct device_attribute dev_attr_foo = {
        .attr = {
                .name = "foo",
                .mode = S_IWUSR | S_IRUGO,
        },
        .show = show_foo,
        .store = store_foo,
};

include/linux/kernel.hに記載されている「OTHER_WRITABLE? 一般的には悪い考えとされています。」という注意書きを考慮すると、全員が書き込み可能なsysfsファイルを設定しようとすると失敗し、「Others」に対してROモードに戻るため、実行が失敗します。

一般的なケースでは、sysfs.hが属性の定義をより簡単にし、コードをコンパクトで読みやすくするための便利なマクロを提供しています。上記のケースは以下のように短縮できます:

static struct device_attribute dev_attr_foo = __ATTR_RW(foo);

あなたのラッパー関数を定義するためのヘルパ関数の一覧は以下の通りです:

__ATTR_RO(name):

デフォルトのname_showとモード0444を前提としています

__ATTR_WO(name):

name_storeのみを前提とし、モード0200（rootのみの書き込みアクセス）に制限されています

__ATTR_RO_MODE(name, mode):

より制限的なROアクセスの現在の使用例はEFI System Resource Table（drivers/firmware/efi/esrt.cを参照）に限られています

__ATTR_RW(name):

デフォルトのname_show、name_storeを前提とし、モードを0644に設定します

__ATTR_NULL:

名前をNULLに設定し、リストの終端を示すために使用されます（kernel/workqueue.cを参照）

サブシステム固有のコールバック¶

サブシステムが新しい属性タイプを定義する場合、その属性所有者のshowおよびstoreメソッドに読み書き呼び出しを転送するためのsysfs操作のセットを実装する必要があります:

struct sysfs_ops {
        ssize_t (*show)(struct kobject *, struct attribute *, char *);
        ssize_t (*store)(struct kobject *, struct attribute *, const char *, size_t);
};

[ サブシステムはすでにstruct kobj_typeをこのタイプの記述子として定義しておく必要があります。sysfs_opsポインタはここで保存されます。詳細はkobjectドキュメンテーションを参照してください。 ]

ファイルが読み込まれたり書き込まれたりする際、sysfsは該当するタイプのメソッドを呼び出します。このメソッドは、一般的なstruct kobjectとstruct attributeポインタを適切なポインタタイプに変換し、関連するメソッドを呼び出します。

以下に例を示します:

#define to_dev_attr(_attr) container_of(_attr, struct device_attribute, attr)

static ssize_t dev_attr_show(struct kobject *kobj, struct attribute *attr,
                            char *buf)
{
        struct device_attribute *dev_attr = to_dev_attr(attr);
        struct device *dev = kobj_to_dev(kobj);
        ssize_t ret = -EIO;

        if (dev_attr->show)
                ret = dev_attr->show(dev, dev_attr, buf);
        if (ret >= (ssize_t)PAGE_SIZE) {
                printk("dev_attr_show: %pS returned bad count\n",
                                dev_attr->show);
        }
        return ret;
}

属性データの読み込み/書き込み¶

属性を読み書きする際、show()またはstore()メソッドを属性宣言時に指定する必要があります。メソッドの型はデバイス属性で定義されたものと同様にシンプルであるべきです:

ssize_t (*show)(struct device *dev, struct device_attribute *attr, char *buf);
ssize_t (*store)(struct device *dev, struct device_attribute *attr,
                const char *buf, size_t count);

つまり、オブジェクト、属性、バッファのみをパラメータとして受け取る必要があります。

sysfsは PAGE_SIZEサイズのバッファを確保し、これをメソッドに渡します。sysfsは読み書きごとにメソッドを正確に1回呼び出します。これにより、メソッド実装に以下の挙動が強制されます:

  • read(2)の際、show()メソッドはバッファ全体を埋める必要があります。属性は単一の値または同様な値の配列のみをエクスポートするため、これはそれほどコストのかかる操作ではありません。

    これにより、ユーザー空間がファイル全体を任意に読み取り、シークを自由に行えるようになります。ユーザー空間がゼロにシーク戻したり、オフセット0でpread(2)を実行したりすると、show()メソッドが再び呼び出され、バッファが再び埋められます。

  • 書き込み(2)において、sysfsは最初の書き込み時にバッファ全体を渡す必要があります。sysfsはその後、このバッファ全体をstore()メソッドに渡します。ストア時にデータの後ろに終端のNULLが追加されます。これにより、以下の関数が安全に使用できます。 sysfs_streq() 安全に使用できます。

    sysfsファイルを書き込む際、ユーザースペースのプロセスはまずファイル全体を読み込み、変更したい値を修正した後、バッファ全体を再び書き戻す必要があります。

    属性メソッドの実装は、読み込みと書き込みの値に対して同一のバッファを操作する必要があります。

その他の注意点:

  • 書き込みにより、現在のファイルポジションに関係なくshow()メソッドが再武装されます。

  • バッファは常にPAGE_SIZEバイトの長さになります。i386ではこれは4096バイトです。

  • show()メソッドはバッファに印刷されたバイト数を返す必要があります。

  • show()は、ユーザースペースに返す値をフォーマットする際には sysfs_emit() または sysfs_emit_at() のみ使用する必要があります。

  • store()はバッファから使用したバイト数を返す必要があります。バッファ全体が使用された場合は、count引数を返すだけでよいです。

  • show()またはstore()は常にエラーを返すことができます。悪い値が届いた場合は、必ずエラーを返してください。

  • メソッドに渡されるオブジェクトは、sysfsの参照カウントによりメモリにピン止めされます。ただし、このオブジェクトが表す物理的な実体（例：デバイス）が存在しない可能性があります。必要に応じてその確認方法を確保してください。

デバイス属性の非常に単純（かつ無知な）実装例は:

static ssize_t show_name(struct device *dev, struct device_attribute *attr,
                        char *buf)
{
        return scnprintf(buf, PAGE_SIZE, "%s\n", dev->name);
}

static ssize_t store_name(struct device *dev, struct device_attribute *attr,
                        const char *buf, size_t count)
{
        snprintf(dev->name, sizeof(dev->name), "%.*s",
                (int)min(count, sizeof(dev->name) - 1), buf);
        return count;
}

static DEVICE_ATTR(name, S_IRUGO, show_name, store_name);

(注意: 実際の実装では、ユーザースペースがデバイスの名前を設定することはできません。)

トップレベルディレクトリレイアウト¶

sysfsのディレクトリ配置は、カーネルデータ構造の関係性を明らかにしています。

トップレベルのsysfsディレクトリは以下のようになります:

block/
bus/
class/
dev/
devices/
firmware/
net/
fs/

devices/はシステム内のデバイスのファイルシステム表現を含み、これは内部のカーネルデバイスツリーに直接マッピングされます。これは struct device.

bus/はカーネル内のさまざまなバスタイプのフラットなディレクトリレイアウトを含み、各バスのディレクトリには2つのサブディレクトリが含まれます:

devices/
drivers/

devices/はシステム内で発見された各デバイスのシンボリックリンクを含み、これらはroot/以下のデバイスのディレクトリにポイントします。

drivers/は特定のバス上のデバイスにロードされた各デバイスドライバーのディレクトリを含み、これはドライバーが複数のバスタイプをまたがないことを前提としています。

fs/は一部のファイルシステムのディレクトリを含み、現在各ファイルシステムが属性をエクスポートするには、fs/以下の独自の階層を作成する必要があります（例: ./fuse.txtを参照）。

dev/ ディレクトリには char/ と block/ という2つのディレクトリが含まれています。これらの2つのディレクトリ内には、<major>:<minor> という名前のシンボリックリンクが存在します。これらのシンボリックリンクは、指定されたデバイスの sysfs ディレクトリを指しています。/sys/dev は、stat(2) の結果からデバイスの sysfs インターフェースを迅速に検索するための方法です。

ドライバモデル固有の機能については、Documentation/driver-api/driver-model/ を参照してください。

現在のインターフェース¶

現在、sysfs には以下のインターフェースレイヤーが存在しています:

デバイス (include/linux/device.h)¶

構造:

struct device_attribute {
        struct attribute    attr;
        ssize_t (*show)(struct device *dev, struct device_attribute *attr,
                        char *buf);
        ssize_t (*store)(struct device *dev, struct device_attribute *attr,
                        const char *buf, size_t count);
};

宣言:

DEVICE_ATTR(_name, _mode, _show, _store);

作成/削除:

int device_create_file(struct device *dev, const struct device_attribute * attr);
void device_remove_file(struct device *dev, const struct device_attribute * attr);

バスドライバ (include/linux/device.h)¶

構造:

struct bus_attribute {
        struct attribute        attr;
        ssize_t (*show)(struct bus_type *, char * buf);
        ssize_t (*store)(struct bus_type *, const char * buf, size_t count);
};

宣言:

static BUS_ATTR_RW(name);
static BUS_ATTR_RO(name);
static BUS_ATTR_WO(name);

作成/削除:

int bus_create_file(struct bus_type *, struct bus_attribute *);
void bus_remove_file(struct bus_type *, struct bus_attribute *);

デバイスドライバ (include/linux/device.h)¶

構造:

struct driver_attribute {
        struct attribute        attr;
        ssize_t (*show)(struct device_driver *, char * buf);
        ssize_t (*store)(struct device_driver *, const char * buf,
                        size_t count);
};

宣言:

DRIVER_ATTR_RO(_name)
DRIVER_ATTR_RW(_name)

作成/削除:

int driver_create_file(struct device_driver *, const struct driver_attribute *);
void driver_remove_file(struct device_driver *, const struct driver_attribute *);

ドキュメンテーション¶

sysfs ディレクトリ構造および各ディレクトリ内の属性は、カーネルとユーザースペース間のABIを定義します。他のABI同様に、このABIは安定しており適切にドキュメント化されている必要があります。すべての新しいsysfs属性はDocumentation/ABIにドキュメント化する必要があります。詳しくはDocumentation/ABI/READMEを参照してください。
