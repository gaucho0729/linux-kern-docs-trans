VFAT¶

VFATの使用¶

vfatファイルシステムを使用するには、ファイルシステムタイプとして‘vfat’を使用します。つまり：

mount -t vfat /dev/fd0 /mnt

特別なパーティションフォーマッターは必要ありません。Linux内からフォーマットする場合は‘mkdosfs’を使用できます。

VFAT マウントオプション¶

uid=###

このファイルシステム上のすべてのファイルの所有者を設定します。デフォルトは現在のプロセスのuidです。

gid=###

このファイルシステム上のすべてのファイルのグループを設定します。デフォルトは現在のプロセスのgidです。

umask=###

パーミッションマスク（ファイルとディレクトリについては、 umask(1))。デフォルトは現在のプロセスのumaskです。

dmask=###

ディレクトリ用のパーミッションマスク。デフォルトは現在のプロセスのumaskです。

fmask=###

ファイル用のパーミッションマスク。デフォルトは現在のプロセスのumaskです。

allow_utime=###

このオプションは、mtime/atimeのパーミッションチェックを制御します。

-20: 現在のプロセスがファイルのグループIDのグループに属している場合、タイムスタンプを変更できます。

-2: 他のユーザーもタイムスタンプを変更できます。

デフォルトはdmaskオプションから設定されます。ディレクトリが書き込み可能であれば、utime(2)も許可されます。つまり ~dmask & 022 です。

通常utime(2)は現在のプロセスがファイルの所有者であるか、CAP_FOWNERの能力を持つことを確認します。しかしFATファイルシステムにはディスク上にuid/gidが存在しないため、通常のチェックは柔軟性が欠けます。このオプションを使用することで柔軟性を高めることができます。

codepage=###

FATファイルシステムの短いファイル名文字列に変換するためのコードページ番号を設定します。デフォルトはFAT_DEFAULT_CODEPAGEの設定を使用します。

iocharset=<name>

ユーザーが見えるファイル名と16ビットUnicode文字間の変換に使用する文字セット。長いファイル名はディスク上にUnicode形式で保存されますが、UnixはUnicodeを扱う方法を持っていません。デフォルトはFAT_DEFAULT_IOCHARSETの設定を使用します。

utf8オプションを使用してUTF-8の翻訳を行うこともできます。

注意

iocharset=utf8 推奨されません。不明な場合は、utf8オプションを使用することを検討してください。

utf8=<bool>

UTF-8はコンソールで使用されるUnicodeのファイルシステム安全なバージョンです。このオプションでファイルシステムで有効/無効にできます。‘uni_xlate’が設定されるとUTF-8は無効になります。デフォルトはFAT_DEFAULT_UTF8の設定を使用します。

uni_xlate=<bool>

未処理のUnicode文字を特殊なエスケープシーケンスに翻訳します。これにより、Unicode文字で作成されたファイル名をバックアップおよび復元できます。LinuxがUnicodeを本格的にサポートするまでは、このオプションが代替手段となります。このオプションを指定しない場合、翻訳が不可能な場合は「？」が使用されます。エスケープ文字は「:」です。これは、vfatファイルシステムでは他の文字として不適切なためです。使用されるエスケープシーケンスは「:」と4桁の16進数のUnicodeです。

nonumtail=<bool>

8.3形式の別名を作成する際、通常は別名が「~1」やチルダに続く数字で終わる形式になります。このオプションを指定した場合、ファイル名が「longfilename.txt」であり、「longfile.txt」がディレクトリに存在しない場合、短い別名として「longfile.txt」が使用され、「longfi~1.txt」にはなりません。

usefree

FSINFOに保存された「空きクラスタ数」の値を使用します。これにより、ディスクをスキャンせずに空きクラスタ数を決定できます。ただし、このオプションはデフォルトでは使用されません。最近のWindowsでは一部のケースでこの値を正しく更新しないからです。FSINFOに保存された「空きクラスタ数」が正しいと確認できる場合は、このオプションでディスクスキャンを回避できます。

quiet

特定の警告メッセージの表示を停止します。

check=s|r|n

大文字小文字の検出設定。

s: 厳格、大文字小文字を区別する

r: ゆるい、大文字小文字を区別しない

n: 通常、デフォルト設定、現在は大文字小文字を区別しない

nocase

これはvfatに対して非推奨となりました。使用するには shortname=win95 を呼び出してください。

shortname=lower|win95|winnt|mixed

短いファイル名の表示/作成設定。

lower: 表示時に小文字に変換し、作成時にWindows 95のルールを模倣する。

win95: 表示および作成時にWindows 95のルールを模倣する。

winnt: 表示および作成時にWindows NTのルールを模倣する。

mixed: 表示時にWindows NTのルールを模倣し、作成時にWindows 95のルールを模倣する。

デフォルト設定は mixed.

tz=UTC

タイムスタンプをUTCではなくローカル時間として解釈します。このオプションにより、WindowsのFATで使用されるローカル時間とLinuxが内部的に使用するUTC間の変換が無効になります。デバイス（デジタルカメラなど）をUTCで設定している場合に特に役立ち、ローカル時間の扱いの落とし穴を回避できます。

time_offset=minutes

FATで使用されるローカル時間からUTCへのタイムスタンプ変換のオフセットを設定します。つまり、<minutes>分を各タイムスタンプから引いて、Linuxが内部的に使用するUTCに変換します。これは、タイムゾーンが設定されている sys_tz とファイルシステムで使用されているタイムゾーンが異なる場合に役立ちます。ただし、このオプションでもDST（サマータイム）の影響ですべてのケースで正しいタイムスタンプが得られない場合があります。DST設定が異なる場合、タイムスタンプが1時間ずれることに注意してください。

showexec

設定すると、ファイルの実行権限ビットは拡張子が.EXE、.COM、または.BATの場合のみ許可されます。デフォルトでは設定されていません。

debug

設定可能です。ただし、現在の実装では使用されていません。

sys_immutable

設定すると、FATのATTR_SYS属性はLinuxのIMMUTABLEフラグとして扱われます。デフォルトでは設定されていません。

flush

設定すると、ファイルシステムは通常より早くディスクにフラッシュしようとします。デフォルトでは設定されていません。

rodir

FATにはATTR_RO（読み取り専用）属性があります。WindowsではディレクトリのATTR_ROは無視され、アプリケーションがフラグとしてのみ使用します（例：カスタマイズフォルダでは設定されています）。

ディレクトリにもATTR_ROを読み取り専用フラグとして使用したい場合は、このオプションを設定してください。

errors=panic|continue|remount-ro

重大なエラー時のFATの動作を指定します：panic（異常終了）、何もせず継続、またはパーティションを読み取り専用モードで再マウント（デフォルト動作）。

discard

設定すると、ブロックが解放されるときにブロックデバイスに対してdiscard/TRIMコマンドを発行します。これはSSDデバイスやスパース/スリムプロビジョニングされたLUNに有効です。

nfs=stale_rw|nostale_ro

FATファイルシステムをNFS経由で共有する場合にのみ有効化してください。

stale_rw: このオプションはディレクトリのインデックス（キャッシュ）を保持します inodes によって i_logstart NFS関連のコードで検索を改善するために使用されます。NFS経由でのフルファイル操作（読み取り/書き込み）はサポートされていますが、NFSサーバーでのキャッシュの削除によりESTALEエラーが発生する可能性があります。

nostale_ro: このオプションは、 inode ファイルのMS-DOSディレクトリエントリ内のディスク上の場所に基づいて、ファイル数とファイルハンドルを決定します。これにより、ファイルがinodeキャッシュから追い出された後でもESTALEが返されません。ただし、リネーム、作成、リンク解除などの操作により、以前は1つのファイルを指していたファイルハンドルが別のファイルを指す可能性があり、データ破損の原因になることがあります。そのため、このオプションはファイルシステムを読み取り専用でマウントします。

後方互換性を維持するため、 '-o nfs' も受け付けられ、デフォルトは「stale_rw」です。

dos1xfloppy <bool>: 0,1,yes,no,true,false

設定すると、バックイングデバイスのサイズに基づいてフォールバックデフォルトのBIOSパラメータブロック構成を使用します。これらの静的パラメータは、DOS 1.xが160キビ、180キビ、320キビ、360キビのフロッピーやフロッピーアイマジンを想定したデフォルトと一致します。

制限¶

fallocateでFALLOC_FL_KEEP_SIZEを使用する場合、ファイルのfallocated領域はumount/evictのタイミングで破棄されます。そのため、ユーザーはメモリ圧力によりinodeがメモリから追い出され、ファイルの最後のclose時にfallocated領域が破棄される可能性があることを認識しておく必要があります。その結果、fallocated領域に依存している場合、ファイルを再オープンした後にfallocateを再確認する必要があります。

可能性のある問題¶

  • vfat_valid_longnameは予約名を正しくチェックしていません。

  • ファイルシステムのルートディレクトリにボリューム名とディレクトリ名が同じ場合、ディレクトリ名が空ファイルとして表示されることがあります。

  • autoconvオプションが正しく動作していません。

vfatファイルシステムの変更を行う予定がある場合は、以下のURLからvfat配布に同梱されているテストスイートを入手してください

http://web.archive.org/web/*/http://bmrc.berkeley.edu/people/chaffee/vfat.html

このテストスイートはvfatファイルシステムの多くの部分をテストしており、新機能や未検証機能に対する追加テストが歓迎されます。

VFATファイルシステムの構造に関する注意点¶

このドキュメントはGalen C. Huntによって提供されました gchunt@cs.rochester.edu およびGordon Chaffeeによって軽く注釈が加えられています。

このドキュメントは、Windows NT 3.5およびWindows 95で使用される拡張FATファイルシステムに関する非常に粗い技術的な概要を示しています。以下の内容が正しいかどうかは保証しませんが、そう見えるようです。

拡張FATファイルシステムは、DOSバージョンに至るまで使用されていたFATファイルシステムとほぼ同じです 6.223410239847 :-). 主な変更点は長ファイル名の導入です。これらの名前は、スペースや小文字を含む最大255文字の長さをサポートし、従来の8.3短名とは異なります。

現在のWindows 95ファイルシステムにおける従来のFATエントリの説明は以下の通りです：

struct directory { // Short 8.3 names
        unsigned char name[8];          // file name
        unsigned char ext[3];           // file extension
        unsigned char attr;             // attribute byte
        unsigned char lcase;            // Case for base and extension
        unsigned char ctime_ms;         // Creation time, milliseconds
        unsigned char ctime[2];         // Creation time
        unsigned char cdate[2];         // Creation date
        unsigned char adate[2];         // Last access date
        unsigned char reserved[2];      // reserved values (ignored)
        unsigned char time[2];          // time stamp
        unsigned char date[2];          // date stamp
        unsigned char start[2];         // starting cluster number
        unsigned char size[4];          // size of the file
};

lcaseフィールドは、8.3名のベースおよび/または拡張子を大文字にするかどうかを指定します。このフィールドはWindows 95では使用されていないように見えますが、Windows NTでは使用されます。ファイル名の大文字小文字の互換性はWindows NTからWindows 95へは完全ではありません。逆方向にも完全ではありません。8.3名空間に収まるファイル名で、Windows NTで小文字で保存されたものはWindows 95で大文字で表示されます。

注意

注意: 空文字（null byte）は文字列の一部とみなされ、検索対象となる。 start および size 値は実際にはlittle endian整数値です。この構造体のフィールドの説明は公開知識であり、他の場所でも確認できます。

拡張FATシステムでは、マイクロソフトは拡張名を持つファイル用に追加のディレクトリエントリを挿入しています。(旧8.3エンコーディングスキームで法的に許容される任意の名前は追加のエントリを持ちません。) 私はこれらの追加エントリを「スロット」と呼んでいます。基本的に、スロットとはファイルの拡張名の最大13文字を保持する特別なフォーマットのディレクトリエントリです。スロットは、対応するファイルのディレクトリエントリに追加のラベリングとして考えるとわかりやすいでしょう。マイクロソフトはファイルの8.3エントリを「別名」と呼び、拡張スロットディレクトリエントリを「ファイル名」と呼んでいます。

スロットディレクトリエントリのC構造体は以下のようになります:

struct slot { // Up to 13 characters of a long name
        unsigned char id;               // sequence number for slot
        unsigned char name0_4[10];      // first 5 characters in name
        unsigned char attr;             // attribute byte
        unsigned char reserved;         // always 0
        unsigned char alias_checksum;   // checksum for 8.3 alias
        unsigned char name5_10[12];     // 6 more characters in name
        unsigned char start[2];         // starting cluster number
        unsigned char name11_12[4];     // last 2 characters in name
};

スロットのレイアウトが少し不自然に見えるのは、マイクロソフトが旧ソフトウェアとの互換性を維持するための努力によるものです。スロットは古いソフトウェアがパニックを起こさないように偽装されている必要があります。このため、以下の対策が講じられています:

  1. スロットディレクトリエントリの属性バイトは常に0x0fに設定されます。これは「隠し」「システム」「読み込み専用」「ボリュームラベル」属性を持つ古いディレクトリエントリに対応します。ほとんどの古いソフトウェアは「ボリュームラベル」ビットが設定されているディレクトリエントリを無視します。実際のボリュームラベルエントリは他の3つのビットが設定されていません。

  2. 開始クラスタは常に0に設定され、これはDOSファイルでは不可能な値です。

拡張FATシステムは後方互換性があるため、古いソフトウェアがディレクトリエントリを変更する可能性があります。スロットの有効性を保証するための対策が必要です。拡張FATシステムは以下の方法でスロットが実際に8.3ディレクトリエントリに属しているかを確認できます:

  1. 位置情報。ファイルのスロットは常に対応する8.3ディレクトリエントリの直後に続きます。さらに、各スロットにはその拡張ファイル名における順序を示すIDが割り当てられています。以下は「My Big File.Extension which is long」というファイルの8.3ディレクトリエントリとその対応する長い名前のスロットの非常に簡略化した例です:

    <proceeding files...>
<slot #3, id = 0x43, characters = "h is long">
<slot #2, id = 0x02, characters = "xtension whic">
<slot #1, id = 0x01, characters = "My Big File.E">
<directory entry, name = "MYBIGFIL.EXT">

    注意

    スロットは最後から順に保存されていることに注意してください。スロットは1からNまでの番号で、N番目のスロットは or'ed 0x40で最後のスロットであることを示しています。

  2. チェックサム。各スロットにはalias_checksum値が設定されています。チェックサムは以下のアルゴリズムで8.3名から計算されます:

    for (sum = i = 0; i < 11; i++) {
        sum = (((sum&1)<<7)|((sum&0xfe)>>1)) + name[i]
}

  3. 最終スロットに空きスペースがある場合、その最後の文字の後にUnicode NULL (0x0000) が保存されます。その後、最終スロット内の未使用の文字はすべてUnicode 0xFFFFに設定されます。

最後に、拡張名はUnicodeで保存されています。各Unicode文字はUTF-16LEエンコードで、2バイトまたは4バイトを占めます。
