kAFS: AFS FILESYSTEM¶

概要¶

このファイルシステムは、比較的シンプルでセキュアなAFSファイルシステムドライバーを提供します。現在開発中であり、完全な機能セットはまだ提供していません。サポートしている機能には次の通りです：

（*）セキュリティ（現在はAFS kaserverとKerberosIVチケットのみ）。

（*）ファイルの読み込みと書き込み。

（*）自動マウント。

（*）ローカルキャッシュ（fscache経由）。

サポートされていないAFSの機能には次の通りです：

（*）pioctl() システムコール。

コンパイル¶

このファイルシステムは、カーネルの構成オプションを有効にして有効化する必要があります：

CONFIG_AF_RXRPC         - The RxRPC protocol transport
CONFIG_RXKAD            - The RxRPC Kerberos security handler
CONFIG_AFS              - The AFS filesystem

さらに、デバッグを支援するために以下のオプションを有効にできます：

CONFIG_AF_RXRPC_DEBUG   - Permit AF_RXRPC debugging to be enabled
CONFIG_AFS_DEBUG        - Permit AFS debugging to be enabled

これらは、以下のファイル内のマスクを操作することにより、ダイナミックにデバッグメッセージを有効にすることができます：

/sys/module/af_rxrpc/parameters/debug
/sys/module/kafs/parameters/debug

使い方¶

ドライバーモジュールを挿入する際には、ルートセルを指定し、ボリュームロケーションサーバーのIPアドレス一覧を指定する必要があります：

modprobe rxrpc
modprobe kafs rootcell=cambridge.redhat.com:172.16.18.73:172.16.18.91

最初のモジュールはAF_RXRPCネットワークプロトコルドライバーです。これはRxRPCリモート操作プロトコルを提供し、ユーザー空間からもアクセス可能です。参照：

RxRPC ネットワークプロトコル

2番目のモジュールはkerberos RxRPCセキュリティドライバーで、3番目のモジュールはAFSファイルシステム用の実際のファイルシステムドライバーです。

モジュールがロードされた後、次の手順により追加のモジュールを追加できます：

echo add grand.central.org 18.9.48.14:128.2.203.61:130.237.48.87 >/proc/fs/afs/cells

「add」コマンドのパラメータは、セルの名前とそのセル内のボリュームロケーションサーバーの一覧で、後者はコロンで区切ります。

ファイルシステムは、次の例に似たコマンドによりどこでもマウントできます：

mount -t afs "%cambridge.redhat.com:root.afs." /afs
mount -t afs "#cambridge.redhat.com:root.cell." /afs/cambridge
mount -t afs "#root.afs." /afs
mount -t afs "#root.cell." /afs/cambridge

最初の文字は、R/Wボリューム（％）を確実に使用したい場合か、R/Oボリュームを好むがR/Wボリュームを使用することも可能な場合（#）により、ハッシュまたはパーセント記号になります。

ボリューム名に「.backup」または「.readonly」を接続することで、そのタイプのボリュームのみに接続するように指定できます。

セル名はオプションであり、マウント時に指定されない場合、modprobeで指定されたセル内で名前付きボリュームが検索されます。

追加のセルは/procを通じて追加できます（後述のセクションを参照）。

マウントポイント¶

AFSにはマウントポイントという概念があります。AFSでは、これらは特別な形式のシンボリックリンク（mountに渡される「デバイス名」と同じ形式）とみなされます。kAFSは、これらをユーザーにディレクトリとして提示し、フォローリンクの機能（つまりシンボリックリンクのセマンティクス）を持たせます。誰かがこれらにアクセスしようとすると、ターゲットボリュームがその場所で自動的にマウントされます（可能であれば）。

自動的にマウントされたファイルシステムは、最後に使用された後約20分後に自動的にアンマウントされます。代替として、umount()システムコールを使用して直接アンマウントすることもできます。

AFSボリュームを手動でアンマウントすると、その上にあるアイドル状態のサブマウントがまず削除されます。すべて削除された場合、要求されたボリュームもアンマウントされます。それ以外の場合は、エラーEBUSYが返されます。

これにより、管理者は/afsにマウントされた全体のAFSツリーを一度にアンマウントしようとすることができます。以下のように行うことで、

umount /afs

ダイナミック・ルート¶

サーバーレスマウントを作成するためのマウントオプションが利用可能です。このようなマウントを作成する例として、

mount -t afs none /afs -o dyn

これは、ルートに空のディレクトリを持つマウントを作成します。このディレクトリ内で名前を検索しようとすると、同名のセルを検索するマウントポイントが作成されます。例えば：

ls /afs/grand.central.org/

Proc Filesystem¶

AFSモジュールは「/proc/fs/afs/」ディレクトリを作成し、その中に以下のファイルを配置します:

(*) 「cells」ファイルは、afsモジュールが現在認識しているセルの一覧を表示します

使用回数:

[root@andromeda ~]# cat /proc/fs/afs/cells
USE NAME
  3 cambridge.redhat.com
(*) 各セルごとに、ボリュームの位置をリスト化するファイルを含むディレクトリ

そのセル内で認識されているサーバー、ボリューム、およびアクティブなサーバー:

[root@andromeda ~]# cat /proc/fs/afs/cambridge.redhat.com/servers
USE ADDR            STATE
  4 172.16.18.91        0
[root@andromeda ~]# cat /proc/fs/afs/cambridge.redhat.com/vlservers
ADDRESS
172.16.18.91
[root@andromeda ~]# cat /proc/fs/afs/cambridge.redhat.com/volumes
USE STT VLID[0]  VLID[1]  VLID[2]  NAME
  1 Val 20000000 20000001 20000002 root.afs

セルデータベース¶

ファイルシステムは、自身が知っているすべてのセルと、それらのセルのボリュームロケーションサーバーのIPアドレスに関する内部データベースを維持しています。システムが属するセルは、「rootcell=」という引数でmodprobeが実行されるときにデータベースに追加され、コンパイルされている場合は、カーネルコマンドラインに「kafs.rootcell=」という引数を使用して追加されます。

以下のコマンドに似たコマンドでさらにセルを追加できます:

echo add CELLNAME VLADDR[:VLADDR][:VLADDR]... >/proc/fs/afs/cells
echo add grand.central.org 18.9.48.14:128.2.203.61:130.237.48.87 >/proc/fs/afs/cells

現在はその他のセルデータベース操作は利用できません。

セキュリティ¶

セキュアな操作は、klogプログラムを使用してキーロックを取得することで開始されます。非常に原始的なklogプログラムは以下のURLで入手できます:

https://people.redhat.com/~dhowells/rxrpc/klog.c

これは以下のようにコンパイルする必要があります:

make klog LDLIBS="-lcrypto -lcrypt -lkrb4 -lkeyutils"

コンパイル後、以下のように実行します:

./klog

成功したと仮定すると、この操作により、サービスとセル名に基づいて名付けられたRxRPCタイプのキーロックが追加されます（例: 「afs@<cellname>」）。このキーロックはkeyctlプログラムを使用して確認できますし、/proc/keysをcatコマンドで表示することでも確認できます。

[root@andromeda ~]# keyctl show
Session Keyring
       -3 --alswrv      0     0  keyring: _ses.3268
        2 --alswrv      0     0   \_ keyring: _uid.0
111416553 --als--v      0     0   \_ rxrpc: afs@CAMBRIDGE.REDHAT.COM

現在、ユーザー名、リーマン、パスワードおよび提案されたチケットの有効期限はプログラムに組み込まれています。

AFSの機能を使用する前にキーロックを取得する必要はありませんが、取得しない場合、すべての操作はACLの匿名ユーザー部分によって制御されます。

キーロックを取得した場合、そのキーロックの保持者によるすべてのAFS操作（マウントおよび自動マウントを含む）はそのキーロックで保護されます。

あるファイルが特定のキーで開かれ、その後そのファイルディスクリプタがAF_UNIXソケットなどを通じて、そのキーを持っていないプロセスに渡された場合、ファイルの操作はファイルを開いた際に使用したキーで行われます。

The @sys 置換¶

現在のネットワークネームスペースの最大16つの@sys置換リストを構成するには、/proc/fs/afs/sysnameにリストを書き込みます：

[root@andromeda ~]# echo foo amd64_linux_26 >/proc/fs/afs/sysname

空のリストを書き込むことで完全にクリアできます：

[root@andromeda ~]# echo >/proc/fs/afs/sysname

現在のネットワークネームスペースの現在のリストを取得するには、以下を実行します：

[root@andromeda ~]# cat /proc/fs/afs/sysname
foo
amd64_linux_26

@sysが置換される際、リストの各要素は指定された順序で試行されます。

デフォルトでは、パターン「<arch>_linux_26」に一致する項目が含まれており、x86_64はamd64として表されます。
