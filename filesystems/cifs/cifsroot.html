ルートファイルシステムをSMB（cifs.ko）経由でマウントする¶

2019年にPaulo Alcantaraによって書かれました <palcantara@suse.de>

2019年にAurelien Aptelによって書かれました <aaptel@suse.com>

CONFIG_CIFS_ROOTオプションは、SMBプロトコルを介してcifs.koを介して実験的なルートファイルシステムのサポートを有効にします。

これは、'cifsroot='という新しいカーネルコマンドラインオプションを導入し、カーネルにルートファイルシステムをネットワーク経由でマウントするように指示します。SMBまたはCIFSプロトコルを使用します。

マウントするには、'ip='設定オプションを使用してネットワークスタックも設定する必要があります。詳細については、以下を参照してください。 NFSを介してルートファイルシステムをマウントする (nfsroot).

現在、CIFSルートマウントにはSMB1+UNIX拡張機能が必要であり、これはSambaサーバーのみでサポートされています。SMB1はプロトコルの古い非推奨バージョンですが、POSIX機能をサポートするために拡張されています（[1]を参照）。新しい推奨バージョンのプロトコル（SMB3）の同等の拡張機能はまだ完全に実装されていないため、SMB3は一部の必要なPOSIXファイルシステムオブジェクト（例: ブロックデバイス、パイプ、ソケット）をサポートしていません。

その結果、現在はCIFSルートがSMB1にデフォルトしますが、'vers='マウントオプションを使用して使用するバージョンを変更できます。SMB3 POSIX拡張機能が完全に実装されると、このデフォルトが変更されます。

サーバーの設定¶

SMB1+UNIX拡張機能を有効にするには、Sambaのsmb.confファイルにこれらのグローバル設定を設定する必要があります：

[global]
server min protocol = NT1
unix extension = yes        # default

カーネル コマンドライン¶

root=/dev/cifs

これは、基本的にカーネルにSMBプロトコルを介してルートファイルシステムをマウントするように指示する仮想デバイスです。

cifsroot=//<server-ip>/<share>[,options]

このオプションで指定された<server-ip>と<share>にあるSMB経由でルートファイルシステムをマウントするカーネルを有効にします。

デフォルトのマウントオプションはfs/cifs/cifsroot.cに設定されています。

server-ip

サーバーのIPv4アドレス。

share

SMB共有（rootfs）へのパス。

オプション

オプションのマウントオプション。詳細については、mount.cifs(8)を参照してください。

例¶

smb.confファイルでルートファイルシステムをSamba共有としてエクスポート：

...
[linux]
        path = /path/to/rootfs
        read only = no
        guest ok = yes
        force user = root
        force group = root
        browseable = yes
        writeable = yes
        admin users = root
        public = yes
        create mask = 0777
        directory mask = 0777
...

smbサービスを再起動：

# systemctl restart smb

CONFIG_CIFS_ROOTおよびCONFIG_IP_PNPオプションが有効なカーネルでQEMU下でテスト：

# qemu-system-x86_64 -enable-kvm -cpu host -m 1024 \
-kernel /path/to/linux/arch/x86/boot/bzImage -nographic \
-append "root=/dev/cifs rw ip=dhcp cifsroot=//10.0.2.2/linux,username=foo,password=bar console=ttyS0 3"

1: https://wiki.samba.org/index.php/UNIX_Extensions
