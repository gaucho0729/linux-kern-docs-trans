自動マウントサポート¶

ファイルシステムが自動マウントをサポートする場合（例: fs/afs/ にある kAFS や fs/nfs/ にある NFS）にサポートが提供されています。この機能には、内核でのマウント操作を実行できるようにする機能や、マウントポイントの劣化を要求できる機能が含まれます。後者はユーザー空間からも要求できます。

内核での自動マウント¶

「マウントトラップ」セクションを参照してください autofs - その動作方法

ユーザー空間から、以下のように実行できます:

[root@andromeda root]# mount -t afs \#root.afs. /afs
[root@andromeda root]# ls /afs
asd  cambridge  cambridge.redhat.com  grand.central.org
[root@andromeda root]# ls /afs/cambridge
afsdoc
[root@andromeda root]# ls /afs/cambridge/afsdoc/
ChangeLog  html  LICENSE  pdf  RELNOTES-1.2.2

そのあと、マウントポイントカタログを確認すると、以下のようなものが表示されます:

[root@andromeda root]# cat /proc/mounts
...
#root.afs. /afs afs rw 0 0
#root.cell. /afs/cambridge.redhat.com afs rw 0 0
#afsdoc. /afs/cambridge.redhat.com/afsdoc afs rw 0 0

自動マウントポイントの有効期限切れ¶

マウントポイントの自動有効期限切れは、別に記述されている自動マウントプロシージャーでそのマウントポイントを有効期限切れに設定しておけば簡単に実行できます。

有効期限切れを行うには、以下の手順を実行してください:

  1. 少なくとも1つのリストを作成し、有効期限切れする vfsmount をそのリストに追加できます。

  2. ->d_automount メソッドで新しいマウントポイントが作成されるときに、mnt_set_expiry() を使用して mnt をリストに追加してください:

    mnt_set_expiry(newmnt, &afs_vfsmounts);

  3. マウントポイントを有効期限切れにする場合は、このリストへのポインタを渡して mark_mounts_for_expiry() を呼び出してください。これにより、リスト内のすべての vfsmount が次の呼び出しで有効期限切れの可能性がマークされます。

    vfsmount がすでに有効期限切れフラグが設定されていて、使用カウントが 1（親の vfsmount みずammに参照されている）場合、そのマウントポイントは名前空間から削除され、破棄されます（有効期限切れとして実質的にアンマウントされます）。

    定期的な時間イベントを使ってこの処理を呼び出すのが最も簡単です。

mntput 呼び出しによって有効期限切れフラグがクリアされます。これにより、マウントポイントが最後にアクセスされた後で 2 回目の有効期限切れリクエストが行われたときにのみ有効期限切れが発生します。

マウントポイントが移動すると、有効期限切れリストから削除されます。有効期限切れ可能なマウントポイントにバインドマウントを実行すると、新しい vfsmount は有効期限切れリストに含まれず、有効期限切れしません。

名前空間がコピーされる場合、その中に含まれるすべてのマウントポイントもコピーされ、有効期限切れリストにあるマウントポイントのコピーは同じ有効期限切れリストに追加されます。

ユーザー空間駆動の有効期限切れ¶

代替として、ユーザー空間が任意のマウントポイントの有効期限切れを要求することも可能です（一部は拒否される場合があります - 例えば、現在のプロセスのルートファイルシステムの概念）。これは、umount() に MNT_EXPIRE フラグを渡すことで実現されます。このフラグは MNT_FORCE および MNT_DETACH と互換性がありません。

指定されたマウントポイントがumount()またはその親マウントポイント以外の何かによって参照されている場合、EBUSYエラーが返され、マウントポイントは期限切れとしてマークされず、アンマウントされません。

その時点でマウントポイントがすでに期限切れとしてマークされていなかった場合、EAGAINエラーが返され、アンマウントされません。

それ以外の場合、すでにマークされていて参照されていない場合は、通常通りアンマウントされます。

再度、umount()以外の何かがマウントポイントを確認するたびに、期限切れフラグがクリアされます。
