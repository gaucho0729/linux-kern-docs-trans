Ceph Distributed File System¶

Cephは、高性能、信頼性、拡張性を提供することを目的とした分散型ネットワークファイルシステムです。

基本的な機能には以下が含まれます:

  • POSIXセマンティクス

  • 1ノードから数千ノードにわたるスムーズなスケーリング

  • 高可用性と信頼性。単一の障害点がありません。

  • ストレージノード間でのN-wayデータレプリケーション

  • ノード障害からの高速な復旧

  • ノードの追加/削除に伴うデータの自動再バランス

  • 簡単な導入: 多くのFSコンポーネントはユーザー空間のデーモンです

また、

  • 柔軟なスナップショット（任意のディレクトリ）

  • 再帰的なアカウント管理（ネストされたファイル、ディレクトリ、バイト）

クラスターファイルシステム（GFS、OCFS2、GPFSなど）とは異なり、すべてのクライアントが共有ブロックデバイスに対称的にアクセスするのではなく、Cephはデータとメタデータ管理を独立したサーバークラスタに分離しています（Lustreに類似）。ただし、Lustreとは異なり、メタデータおよびストレージノードはすべてユーザー空間のデーモンとして動作します。ファイルデータはストレージノードで大容量のチャンクにストリップされ、ワークロードを分散し、高スループットを実現します。ストレージノードが故障した場合、クラスターモニタからの最小限の調整を伴い、ストレージノード自らが分散してデータを再レプリケートします。これによりシステムは非常に効率的で拡張性が高いです。

メタデータサーバーは、ファイルネームスペース上にあり、非常にスケーラブルな大規模な一貫した分散メモリキャッシュを形成します。ワークロードの変化に応じてメタデータを動的に再配分し、任意の（ただし、バイザンチンでない）ノード障害にも耐えます。メタデータサーバーは、一般的なワークロードのパフォーマンスを大幅に向上させるために、メタデータの保存方法に多少非伝統的なアプローチを取っています。特に、単一リンクを持つインノードはディレクトリ内に埋め込まれており、1つのI/O操作でディレクトリ全体のディレントとインノードをキャッシュにロードできます。非常に大きなディレクトリのコンテンツは、独立したメタデータサーバーによって分割管理され、スケーラブルな並列アクセスが可能になります。

このシステムは、ノード数が数個の小さなクラスタから数百ノード規模にスケーリングする際、管理者がデータセットを静的なボリュームに分割する必要もなく、データをサーバー間で移動する手間のかかるプロセスを経ることなく、自動的にデータの再バランス/移行を行います。ファイルシステムが満杯に近づくと、新しいノードを簡単に追加するだけで、システムは自動的に正常に動作します。

Cephには、システム内の任意のサブディレクトリ（およびそのネストされたコンテンツ）でスナップショットを作成できる柔軟なメカニズムが含まれています。スナップショットの作成および削除は、「mkdir .snap/foo」と「rmdir .snap/foo」のように簡単です。

さらに、Cephはディレクトリ内のネストされたファイルとバイト数に関する再帰的なアカウント管理も提供しています。つまり、システム内の任意のディレクトリで「getfattr -d foo」を実行すると、ネストされた正規ファイルとサブディレクトリの総数、およびすべてのネストされたファイルサイズの合計が表示されます。これにより、大容量のディスク使用量を識別する時間が比較的短縮されます。ファイルシステムの再帰的なスキャン（例：「du」など）が不要になるためです。

最後に、Cephはシステム内の任意のディレクトリにクォータを設定することも可能です。クォータは、そのディレクトリ階層の下に保存されるバイト数やファイル数を制限できます。クォータは拡張属性「ceph.quota.max_files」と「ceph.quota.max_bytes」を使用して設定します。例:

setfattr -n ceph.quota.max_bytes -v 100000000 /some/dir
getfattr -n ceph.quota.max_bytes /some/dir

現在のクォータ実装の制限として、クライアントがファイルシステムをマウントする際に制限に達した場合にライターを停止する協力を求めている点があります。改変または悪意のあるクライアントは、必要なデータ量を書き込むことができることを防ぐことはできません。

マウント構文¶

基本的なマウント構文は以下の通りです：

# mount -t ceph monip[:port][,monip2[:port]...]:/[subdir] mnt

クライアントが接続する際に全体のリストを取得するため、単一のモニタを指定するだけで十分です。（ただし、指定したモニタがダウンしている場合、マウントは失敗します。）モニタがデフォルトポートを使用している場合は、ポートは省略できます。したがって、モニタが1.2.3.4にある場合、

# mount -t ceph 1.2.3.4:/ /mnt/ceph

で十分です。/sbin/mount.cephがインストールされている場合は、IPアドレスの代わりにホスト名を使用できます。

マウントオプション¶

ip=A.B.C.D[:N]

クライアントがローカルでバインドするIPアドレスと/またはポートを指定します。通常はこのような操作の理由はほとんどありません。IPアドレスが指定されていない場合、クライアントのIPアドレスは、モニタとの接続が開始される際のアドレスから取得されます。

wsize=X

最大の書き込みサイズ（バイト単位）。デフォルト：64 MB。

rsize=X

最大の読み取りサイズ（バイト単位）。デフォルト：64 MB。

rasize=X

最大の読み取りアヘッドサイズ（バイト単位）。デフォルト：8 MB。

mount_timeout=X

非応答のCephファイルシステムのマウントタイムアウト値（秒単位）。デフォルトは60秒です。

caps_max=X

保持するキャップの最大数を指定します。使用していないキャップは、キャップ数が制限を超えたときに解放されます。デフォルトは0（制限なし）です。

rbytes

ディレクトリのstat()が呼ばれた際、st_sizeを「rbytes」（そのディレクトリ以下のすべてのファイルのサイズ合計）に設定します。これはデフォルトの動作です。

norbytes

ディレクトリに対してstat()が呼ばれた場合、そのディレクトリ内のエントリ数をst_sizeに設定します。

nocrc

データの書き込み時にCRC32C計算を無効化します。設定されている場合、ストレージノードはTCPのエラー訂正に依存してデータペイロード内のデータ破損を検出する必要があります。

dcache

クライアントがキャッシュにディレクトリ全体のコンテンツを保持している場合、dcacheの内容を使用してネガティブな検索とreaddirを実行します。(これは正しさに影響を与えません。クライアントは、リースまたは権限が有効であることを保証する場合にのみキャッシュされたメタデータを使用します。)

nodcache

上記のようにdcacheを使用しません。これにより複雑なコードの量を大幅に減らすことができ、正しさに影響を与えることなくパフォーマンスを犠牲にします。バグの追跡に有用です。

noasyncreaddir

上記のようにreaddir用にdcacheを使用しません。

noquotadf

ファイルシステム全体の使用状況をstatfsで報告します。ルートディレクトリのクォータを使用しません。

nocopyfrom

RADOSの'copy-from'操作を使用してリモートオブジェクトのコピーを行わないようにします。現在はcopy_file_rangeのみで使用されており、このオプションが設定されている場合、デフォルトのVFS実装に戻ります。

recover_session=<no|clean>

クライアントがブロックリストに載っている場合の自動再接続モードを設定します。利用可能なモードは「no」および「clean」です。デフォルトは「no」です。

  • no: クライアントがブロックリストに載っていることを検出しても再接続を試みません。ブロックリストに載った後、操作は一般的に失敗します。

  • clean: クライアントがブロックリストに載っていることを検出すると自動的にcephクラスターに再接続します。再接続中にクライアントは汚染されたデータ/メタデータ、ページキャッシュ、書き込み可能なファイルハンドルを無効化します。再接続後、ファイルロックが古くなり、MDSがそれらを追跡しなくなるため、inodeに古くなったファイルロックが含まれている場合、アプリケーションがすべての古くなったファイルロックを解放するまでinodeの読み書きが許可されません。
