汎用ファイルシステムキャッシング¶

概要¶

この機能はネットワークファイルシステム用の汎用的なキャッシュですが、ISO9660ファイルシステムなどの他の用途にも利用可能です。

FS-Cache はキャッシュバックエンド（例: CacheFS など）とネットワークファイルシステムの間で中間として機能します：

+---------+
|         |                        +--------------+
|   NFS   |--+                     |              |
|         |  |                 +-->|   CacheFS    |
+---------+  |   +----------+  |   |  /dev/hda5   |
             |   |          |  |   +--------------+
+---------+  +-->|          |  |
|         |      |          |--+
|   AFS   |----->| FS-Cache |
|         |      |          |--+
+---------+  +-->|          |  |
             |   |          |  |   +--------------+
+---------+  |   +----------+  |   |              |
|         |  |                 +-->|  CacheFiles  |
|  ISOFS  |--+                     |  /var/cache  |
|         |                        +--------------+
+---------+

別の言い方をすれば、FS-Cache はネットワークファイルシステムにキャッシュ機能を提供するモジュールであり、ユーザーにとってキャッシュが透明性を保つようにします：

+---------+
|         |
| Server  |
|         |
+---------+
     |                  NETWORK
~~~~~|~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
     |
     |           +----------+
     V           |          |
+---------+      |          |
|         |      |          |
|   NFS   |----->| FS-Cache |
|         |      |          |--+
+---------+      |          |  |   +--------------+   +--------------+
     |           |          |  |   |              |   |              |
     V           +----------+  +-->|  CacheFiles  |-->|  Ext3        |
+---------+                        |  /var/cache  |   |  /dev/sda6   |
|         |                        +--------------+   +--------------+
|   VFS   |                                ^                     ^
|         |                                |                     |
+---------+                                +--------------+      |
     |                  KERNEL SPACE                      |      |
~~~~~|~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~|~~~~~~|~~~~
     |                  USER SPACE                        |      |
     V                                                    |      |
+---------+                                           +--------------+
|         |                                           |              |
| Process |                                           | cachefilesd  |
|         |                                           |              |
+---------+                                           +--------------+

FS-Cache は、ネットワークファイルシステム（netfs）で開かれたすべてのファイルを完全にキャッシュにロードしてからアクセスを許可し、そのキャッシュからページを提供するという考え方は採用していません。なぜなら：

  1. キャッシュなしでの運用が現実的でなければならない。

  2. キャッシュのサイズに制限されるファイルのサイズは許容されません。

  3. すべての開かれたファイルの合計サイズ（これはマップされたライブラリも含みます）はキャッシュのサイズに制限されるべきではありません。

  4. ユーザーはファイル全体をダウンロードする必要があるわけではありません。たとえば「file」プログラムでファイルの一部に一時的なアクセスを行う場合などです。

代わりに、netfs（使用中の）が要求するたびにPAGE_SIZE単位でキャッシュを提供します。

FS-Cache は以下の機能を提供します：

  1. 複数のキャッシュを同時に使用できます。キャッシュはタグを指定して明示的に選択できます。

  2. キャッシュはいつでも追加または削除できます。

  3. netfs にはキャッシュ機能をファイルから引き上げるインターフェースが提供され、これは（2）の要件です。

  4. netfs へのインターフェースはエラーをできるだけ少なくし、netfs が無知なままであることを好む。

  5. クッキーは netfs に対してインデックス、ファイル、その他のオブジェクトを表します。最も簡単なクッキーは NULL ポインタであり、そこにはキャッシュされていないことを示します。

  6. netfs は動的に任意のインデックス階層を提案できますが、インデックス検索機能が再帰的でスタック領域が制限されており、インデックスは常にインデックスの子であることを理解しておく必要があります。

  7. データI/Oはnetfsのページを直接行います。netfsは、クッキーCで表されるデータファイルのインデックスBにあるページAが読み込まれるべきか、または書き込まれるべきかを示します。キャッシュバックエンドはそのページにI/Oを開始するかどうかは問いませんが、開始した場合はnetfsのコールバックが完了を示します。I/Oは同期的または非同期的であることができます。

  8. クッキーは解放時に「廃止」されます。この時点でFS-Cacheはそれらを非効力とし、そのルートにあるインデックス階層を再利用します。

  9. netfsはインデックス検索用に「match」関数を提供しています。この関数はマッチが成功したか否かを示すだけでなく、エントリを更新または削除する指示も指定できます。

  1. 可能な限り非同期で処理されます。

FS-Cacheは仮想インデックスツリーを維持しており、すべてのインデックス、ファイル、オブジェクト、ページがこのツリーに保持されています。このツリーの一部は1つまたは複数のキャッシュに実際に存在する可能性があります：

                                           FSDEF
                                             |
                        +------------------------------------+
                        |                                    |
                       NFS                                  AFS
                        |                                    |
           +--------------------------+                +-----------+
           |                          |                |           |
        homedir                     mirror          afs.org   redhat.com
           |                          |                            |
     +------------+           +---------------+              +----------+
     |            |           |               |              |          |
   00001        00002       00007           00125        vol00001   vol00002
     |            |           |               |                         |
 +---+---+     +-----+      +---+      +------+------+            +-----+----+
 |   |   |     |     |      |   |      |      |      |            |     |    |
PG0 PG1 PG2   PG0  XATTR   PG0 PG1   DIRENT DIRENT DIRENT        R/W   R/O  Bak
                     |                                            |
                    PG0                                       +-------+
                                                              |       |
                                                            00001   00003
                                                              |
                                                          +---+---+
                                                          |   |   |
                                                         PG0 PG1 PG2

上の例では、NFSとAFSの2つのnetfsがバックエンドとして使用されています。これらは異なるインデックス階層を持っています：

  • NFSのプライマリインデックスはサーバーごとのインデックスを含みます。各サーバーインデックスはNFSファイルハンドルでインデックス化され、データファイルオブジェクトを取得します。各データファイルオブジェクトはページ配列を持つかもしれませんが、拡張属性やディレクトリエントリなどの子オブジェクトを持つこともできます。拡張属性オブジェクト自体もページ配列の内容を持ちます。

  • AFSのプライマリインデックスはセルごとのインデックスを含みます。各セルインデックスは論理ボリュームごとのインデックスを含み、各ボリュームインデックスはそのボリュームの読み書き用、読み取り専用、バックアップミラー用の最大3つのインデックスを含みます。これらは vnode データファイルオブジェクトを含み、それぞれがページ配列を持つものです。

最も上位のインデックスは、個々のnetfsがエントリを持つFS-Cacheマスターアイテムです。

インデックスオブジェクトは、インデックス子を持つ場合を除き、複数のキャッシュに存在する可能性があります。非インデックスオブジェクトを持つインデックスは、1つのキャッシュにのみ存在すると仮定されます。

統計情報¶

FS-Cacheが以下のオプションでコンパイルされた場合：

CONFIG_FSCACHE_STATS=y
CONFIG_FSCACHE_HISTOGRAM=y

特定の統計情報を収集し、複数のprocファイルを通じて表示します。

/proc/fs/fscache/histogram¶

cat /proc/fs/fscache/histogram
JIFS  SECS  OBJ INST  OP RUNS   OBJ RUNS  RETRV DLY RETRIEVLS
===== ===== ========= ========= ========= ========= =========

これは、0 jiffiesからHZ-1 jiffiesまでの時間ごとのタスクの実行にかかった時間の分解を示しています。列は以下の通りです：

列

時間測定

OBJ INST

オブジェクトのインスタンス化にかかる時間

OP RUNS

操作処理にかかる時間

OBJ RUNS

オブジェクトイベント処理にかかる時間

RETRV DLY

読み込み要求から検索完了までの時間

RETRIEVLS

リトリーブの開始から終了までの時間

各行は特定の時間範囲を要したイベント数を示します。各ステップは1 jiffy単位です。JIFS列はカバーするjiffy範囲を、SECSフィールドはそれに相当する秒数を示します。

表示されるデータは、ファイルを表示する前に適切なキーリングにキーをアタッチしてフィルタリングできます。例えば：

keyctl add user fscache:objlist <restrictions> @s

<restrictions> は以下の文字から選択します：

K

オブジェクトキーのヘックスダンプを表示 (指定されていない場合は表示しない)

A

オブジェクト補助データのヘックスダンプを表示 (指定されていない場合は表示しない)

以下のペアリングされた文字も選択可能です：

C

クッキーを持つオブジェクトを表示

c

クッキーを持たないオブジェクトを表示

B

ビジー状態のオブジェクトを表示

b

ビジー状態でないオブジェクトを表示

W

待機中の書き込みを持つオブジェクトを表示

w

待機中の書き込みを持たないオブジェクトを表示

R

待受中の読み込みを持つオブジェクトを表示

r

待受中の読み込みを持たないオブジェクトを表示

S

キューに待機中の作業を持つオブジェクトを表示

s

キューに待機中の作業を持たないオブジェクトを表示

文字ペアのどちらも指定されていない場合、両方を含むとみなされます。例えば：

keyctl add user fscache:objlist KB @s

ビジー状態のオブジェクトを表示し、オブジェクトキーを一覧表示しますが、補助データのダンプは行いません。また「CcWwRrSs」も含意されますが、「B」が指定されているため、「b」は含意されません。

デフォルトではすべてのオブジェクトとすべてのフィールドが表示されます。
