カーネル内キャッシュオブジェクトの表現と管理¶

By: David Howells <dhowells@redhat.com>

表現¶

FS-Cacheは、netfsが現在関心を持つ各オブジェクトのカーネル内での表現を維持しています。このようなオブジェクトはfscache_cookie構造体で表され、cookieと呼ばれます。

FS-Cacheは、キャッシュバックエンドが現在積極的にキャッシュしているオブジェクトについても、別途カーネル内での表現を維持しています。このようなオブジェクトはfscache_object構造体で表され、オブジェクトと呼ばれます。キャッシュバックエンドは要求に応じてこれらのオブジェクトを割り当て、自身の表現に埋め込む必要があります。

cookieとオブジェクトの間には1対Nの関係があります。cookieは複数のオブジェクトで表される可能性があります（インデックスが複数のキャッシュに存在する場合）あるいは、オブジェクトを持たない場合もあります（キャッシュされていない場合）。

さらに、cookieとオブジェクトはどちらも階層構造を持っています。2つの階層構造は対応していますが、cookieの木は複数のキャッシュのオブジェクト木の合併を含む上位集合です：

    NETFS INDEX TREE               :      CACHE 1     :      CACHE 2
                                   :                  :
                                   :   +-----------+  :
                          +----------->|  IObject  |  :
      +-----------+       |        :   +-----------+  :
      |  ICookie  |-------+        :         |        :
      +-----------+       |        :         |        :   +-----------+
            |             +------------------------------>|  IObject  |
            |                      :         |        :   +-----------+
            |                      :         V        :         |
            |                      :   +-----------+  :         |
            V             +----------->|  IObject  |  :         |
      +-----------+       |        :   +-----------+  :         |
      |  ICookie  |-------+        :         |        :         V
      +-----------+       |        :         |        :   +-----------+
            |             +------------------------------>|  IObject  |
      +-----+-----+                :         |        :   +-----------+
      |           |                :         |        :         |
      V           |                :         V        :         |
+-----------+     |                :   +-----------+  :         |
|  ICookie  |------------------------->|  IObject  |  :         |
+-----------+     |                :   +-----------+  :         |
      |           V                :         |        :         V
      |     +-----------+          :         |        :   +-----------+
      |     |  ICookie  |-------------------------------->|  IObject  |
      |     +-----------+          :         |        :   +-----------+
      V           |                :         V        :         |
+-----------+     |                :   +-----------+  :         |
|  DCookie  |------------------------->|  DObject  |  :         |
+-----------+     |                :   +-----------+  :         |
                  |                :                  :         |
          +-------+-------+        :                  :         |
          |               |        :                  :         |
          V               V        :                  :         V
    +-----------+   +-----------+  :                  :   +-----------+
    |  DCookie  |   |  DCookie  |------------------------>|  DObject  |
    +-----------+   +-----------+  :                  :   +-----------+
                                   :                  :

上記の図では、ICookieとIObjectはインデックスを、DCookieとDObjectはデータストレージオブジェクトを表します。インデックスは複数のキャッシュに表現を持つ可能性がありますが、現在は非インデックスオブジェクトはそうできません。どのタイプのオブジェクトも完全に表現されていない可能性があります。

netfs APIの観点では、netfsは実際にcookieへのポインタのみを確認できます。cookie自体やそれに付随するオブジェクトはnetfsに隠されています。

オブジェクト管理ステートマシン¶

FS-Cache内で、アクティブな各オブジェクトは個別の状態機械で管理されます。オブジェクトの状態はfscache_object構造体のobject->stateに保持されます。cookieは、異なる状態にあるオブジェクトのセットを指すことができます。

各状態には、機械がその状態で起動した際に実行されるアクションが関連付けられています。4つの論理的な状態セットがあります：

  1. 準備: 親オブジェクトが準備完了になるのを待つ状態。表現は階層構造を持ち、オブジェクトは親オブジェクトに対して作成またはアクセスされる必要があります。

  2. 初期化: キャッシュ内の検索を行い、見つかった内容を検証し、必要に応じてディスクにメタデータを作成する状態。

  3. 通常動作: netfs操作がオブジェクトに対して実行可能で、オブジェクトの状態を更新する状態。

  4. 終了: オブジェクトをnetfs cookieから分離し、ディスクからオブジェクトを削除し、ディスクやシステムエラーを処理し、メモリ内のリソースを解放する状態。

ほとんどの場合、状態間の移行は通知されたイベントに応じて行われます。状態が処理を終えたら、通常はその状態に関心のあるイベントのマスク（object->event_mask）を設定し、ワーカースレッドを解放します。その後、イベントが発生した場合（fscache_raise_event()を呼び出すことで発生）、そのイベントがマスクされていない場合、オブジェクトは処理のためにキューイングされます（fscache_enqueue_object()を呼び出すことで）。

CPU時間の提供¶

さまざまな状態で行う作業は、スローワークファシリティのスレッドによってCPU時間として提供されました。これはワークキューのファシリティよりも優先的に使用された理由は以下の通りです：

  1. スレッドは特定の作業項目によって非常に長い時間完全に占拠されることがあります。これらの状態アクションは、検索、mkdir、create、setxattr、getxattr、truncate、unlink、rmdir、renameなどの同期的なジャーナル化されたディスクアクセスのシーケンスを実行している可能性があります。

  2. スレッドは実際の作業をあまり行わず、むしろI/Oに待機する時間が非常に長い場合があります。これは、単スレッドおよび1-per-CPUスレッドのワークキューが適切なスレッド数を保有しているとは限らないことを意味します。

ロックの簡略化¶

特定のオブジェクトの状態機関を同時に操作するスレッドは1つしか存在しないため、ロックの簡略化が可能になります。特に、ネットファイルシステム（netfs）のキャッシュオブジェクト（fscache_cookie）の表現をキャッシュバックエンドの表現（fscache_object）から分離する際のロックが簡略化されます。これはどちらの端からもリクエストされる可能性があります。

状態の集合¶

オブジェクト状態機関には、オブジェクトが存在する状態がいくつかあります。オブジェクトが自身をセットアップし、親オブジェクトが子オブジェクトへのアクセスを許可する状態に移行するのを待機する準備状態があります：

  1. State FSCACHE_OBJECT_INIT.

    オブジェクトを初期化し、親オブジェクトがアクティブになるのを待機します。キャッシュでは、親オブジェクトが自身を検索するまで、親オブジェクトからオブジェクトを検索することは不可能と期待されます。

オブジェクトが自身をセットアップし、オブジェクトメタデータをディスクからアクセスする初期化状態があります：

  1. State FSCACHE_OBJECT_LOOKING_UP.

    親オブジェクトを起点にディスク上でオブジェクトを検索します。FS-Cacheはキャッシュバックエンドがキャッシュを調査し、このオブジェクトがキャッシュに存在するかどうかを確認し、存在する場合に有効かどうか（整合性管理）を検証することを期待しています。

    キャッシュは、何らかの理由で検索に失敗した場合、fscache_object_lookup_negative()を呼び出して検索失敗を示し、成功した場合、fscache_obtained_object()を呼び出して成功を示すべきです。

    検索が完了した後、FS-Cacheはネットファイルシステム（netfs）が読み取り操作を実行できるようにします。ファイルがキャッシュされていなくても、読み取り操作は即座にENODATAで拒否されます。最初のページがキャッシュ解除されるまで、そのファイルのキャッシュから読み取るデータは存在しないためです。

  2. 状態 FSCACHE_OBJECT_CREATING。

    ディスク上にオブジェクトを作成します。親オブジェクトを起点として作成を行います。これはオブジェクトが見つからない場合、またはオブジェクトの整合性データがディスク上の内容が古くなったと示している場合に発生します。この状態ではFS-Cacheはキャッシュがオブジェクトを作成することを期待しています。

    作成が成功した場合はキャッシュがfscache_obtained_object()を呼び、失敗した場合はfscache_object_lookup_negative()を呼びます。

    作成が完了した後、FS-Cacheはネットファイルシステムがキューに積んでいた書き込み操作を処理を開始します。作成が失敗した場合は、書き込み操作は透明に破棄され、キャッシュに記録されません。

オブジェクトはネットファイルシステムのリクエストを処理するためにいくつかの通常の動作状態を経過します。

  1. 状態 FSCACHE_OBJECT_AVAILABLE。

    一時的な状態で、待機中の操作が開始され、子オブジェクトがFSCACHE_OBJECT_INIT状態から進展可能となり、一時的な検索データが解放されます。

  2. 状態 FSCACHE_OBJECT_ACTIVE。

    通常の動作状態です。この状態ではネットファイルシステムが行うリクエストがキャッシュに渡されます。

  3. 状態 FSCACHE_OBJECT_INVALIDATING。

    オブジェクトが無効化処理中です。この状態に移行すると、すべての待機中の読み取り、書き込み、属性変更操作が破棄されます。キャッシュを完全にクリアし再初期化するためです。その後、FSCACHE_OBJECT_UPDATING状態に移行します。

  4. 状態 FSCACHE_OBJECT_UPDATING。

    キャッシュ内のオブジェクトをネットファイルシステムの記録に基づいて更新します。これは整合性を維持するために使用される補助データの更新を含みます。

また、オブジェクトが自身をクリーンアップし、メモリを解放し、ディスクからデータを削除する可能性のある終了状態もあります。

  1. 状態 FSCACHE_OBJECT_LC_DYING。

    検索または作成エラーにより終了する場合にこの状態に移行します。これはディスクエラーまたはシステムエラーなどの原因で発生します。一時的なデータがクリーンアップされ、親オブジェクトが解放されます。

  2. 状態 FSCACHE_OBJECT_DYING。

    ネットファイルシステムが親クッキーを解放した場合、またはキャッシュが引き上げられた場合にこの状態に移行します。

    このオブジェクトを待っている子オブジェクトにCPU時間があてられるため、それらも自身を破壊できるようになる。このオブジェクトはすべての子オブジェクトが消え去るまで待機し、次状態へ進む。

  1. State FSCACHE_OBJECT_ABORT_INIT.

    このオブジェクトはFSCACHE_OBJECT_INIT状態で親を待っていたが、親が死んだ場合にこの状態になる。オブジェクトは自身を破壊し、親がFSCACHE_OBJECT_DYING状態から進めるようにする。

  2. State FSCACHE_OBJECT_RELEASING.

  3. State FSCACHE_OBJECT_RECYCLING.

    オブジェクトがすべての子オブジェクトを解放した後、netfsがクッキーを放棄したため死ぬ場合、この2つの状態のいずれかになる。最初の状態ではキャッシュデータが永続化されることが期待され、2番目の状態ではキャッシュデータが削除される。

  4. State FSCACHE_OBJECT_WITHDRAWING.

    キャッシュがオブジェクトをサービスから外すことを希望した場合、この状態になる。これはスペース確保のためでもあり、エラーのためでも、あるいは全体のキャッシュが外されるためでもある。

  5. State FSCACHE_OBJECT_DEAD.

    インメモリのオブジェクトレコードが削除準備になったときにこの状態になる。オブジェクトプロセッサはこの状態のオブジェクトを決して見ることはない。

イベントのセット¶

オブジェクトステートマシンに発生可能なイベントはいくつかある:

FSCACHE_OBJECT_EV_UPDATE

netfsがオブジェクトの更新を要求した場合。ステートマシンはキャッシュバックエンドにオブジェクトの更新を依頼し、キャッシュバックエンドはそのクッキー定義オプスを通じてnetfsに変更の詳細を尋ねる。

FSCACHE_OBJECT_EV_CLEARED

このイベントは以下の2つの状況で送信される:

  1. オブジェクトの最後の子オブジェクトがドロップされたとき、

  2. オブジェクト上の最後の未完了操作が完了したとき。

これは死んだ状態から進むためのイベントとして使用される。

FSCACHE_OBJECT_EV_ERROR

オブジェクトの処理中にI/Oエラーが発生した場合に送信される。

FSCACHE_OBJECT_EV_RELEASE, FSCACHE_OBJECT_EV_RETIRE

netfsが使用していたクッキーを放棄したときに送信されるイベント。netfsがバックイングオブジェクトを削除（retire）するか保持（retained）するかによって、選択されるイベントが異なる。

FSCACHE_OBJECT_EV_WITHDRAW

キャッシュバックエンドがオブジェクトを引き抜くことを希望したときに送信される。これはオブジェクトがnetfsのクッキーから分離される必要があることを意味する。

引き抜き、解放、廃止などのイベントはすべてオブジェクトステートマシンで処理されるため、両端が同時に接続を切断しようとした場合でも衝突が発生しても問題ない。ステートマシンはどちらか一方を優先し、もう一方の効果を無視することで対応できる。
