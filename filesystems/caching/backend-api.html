FS-Cache キャッシュバックエンドAPI¶

FS-Cacheシステムは、実際のキャッシュを提供することで、ネットワークファイルシステムやその他の関心者に対してサービスを提供できるようにするAPIを提供しています。

このAPIは<linux/fscache-cache.h>で宣言されています。

キャッシュの初期化と登録¶

最初に、バックエンドが提供したい各キャッシュに対してキャッシュ定義を初期化し登録する必要があります。たとえば、CacheFSはマウント時のfill_super()操作でこれを実行します。

キャッシュ定義(struct fscache_cache)は以下の呼び出しによって初期化する必要があります：

void fscache_init_cache(struct fscache_cache *cache,
                        struct fscache_cache_ops *ops,
                        const char *idfmt,
                        ...);

以下では:

  • 「cache」はキャッシュ定義へのポインタを指します；

  • 「ops」は、このキャッシュでバックエンドがサポートする操作のテーブルへのポインタです；そして

  • 「idfmt」は、キャッシュのラベルを構築するために使用するフォーマットおよびprintfスタイルの引数です。

次に、FS-Cacheにキャッシュを登録するために、以前に初期化したキャッシュ定義へのポインタを渡します：

int fscache_add_cache(struct fscache_cache *cache,
                      struct fscache_object *fsdef,
                      const char *tagname);

さらに2つの引数を提供する必要があります：

  • 「fsdef」は、このキャッシュ内のFS-Cacheマスターアイテムインデックスのオブジェクト表現へのポインタで、ネットファイルシステムのプライマリインデックスエントリがここで作成されます。FS-Cacheは成功時に呼び出し元のインデックスオブジェクトへの参照を保持し、キャッシュの削除時に解放します。

  • 「tagname」は、このキャッシュを名前付けるテキスト文字列で、NULLの場合は識別子が使用されます。CacheFSでは識別子は下位ブロックデバイスを名前付けるために設定され、tagはマウント時に提供できます。

この関数はメモリ不足の場合-EINVALを返し、タグが既に使用されている場合は-EEXISTを返します。成功時は0が返されます。

キャッシュの登録解除¶

キャッシュをシステムから削除するには、キャッシュ定義へのポインタを渡してこの関数を呼び出します：

void fscache_withdraw_cache(struct fscache_cache *cache);

CacheFSでは、これはput_super()によって呼び出されます。

セキュリティ¶

キャッシュメソッドは、以下の2つのコンテキストのいずれかで実行されます：

  1. ネットファイルシステム操作を発行したユーザースペースプロセス、または

  2. FS-Cacheスレッドプール内のプロセスのいずれか。

どちらの場合も、キャッシュへのアクセスに適切なコンテキストであるとは限りません。

呼び出し元プロセスのfsuid、fsgidおよびSELinuxセキュリティアイデンティティは、キャッシュドライバがキャッシュにアクセスする間、マスカレードされる可能性があります。これはキャッシュ側で処理し、FS-Cacheはこれに取り組みません。

制御と統計情報の表示¶

キャッシュは、sysfsとprocfsを通じてFS-Cacheのインターフェースを通じて外部にデータを提供することがあります。前者は制御用、後者は統計用です。

CONFIG_SYSFSが有効な場合、/sys/fs/fscache/<cachetag>/というsysfsのディレクトリが作成されます。これはkobject構造体fscache_cache::kobjを通じてアクセス可能で、キャッシュが自身の都合に合わせて使用します。

関連するデータ構造¶

  • インデックス/データファイル FS-Cache 表現クッキー:

    struct fscache_cookie {
        struct fscache_object_def       *def;
        struct fscache_netfs            *netfs;
        void                            *netfs_data;
        ...
};

    バックエンドにとって有用なフィールドは、オブジェクト定義、netfs定義、およびこのクッキーのnetfsデータを含みます。オブジェクト定義には、netfsが提供するインデックスエントリの読み込みおよび一致を行う関数が含まれており、これらはキャッシュ操作の一部を提供するために必要です。

  • キャッシュ内のオブジェクト表現:

    struct fscache_object {
        int                             debug_id;
        enum {
                FSCACHE_OBJECT_RECYCLING,
                ...
        }                               state;
        spinlock_t                      lock
        struct fscache_cache            *cache;
        struct fscache_cookie           *cookie;
        ...
};

    このような構造体は、キャッシュバックエンドによって割り当てられ、適切なキャッシュ操作が要求されるときにFS-Cacheに渡されます。CacheFSの場合、これらはCacheFSの内部オブジェクト構造に埋め込まれます。

    debug_idは、特定のオブジェクトを参照するデバッグメッセージで使用可能な単純な整数です。このような場合、"OBJ%x"を用いて一貫性を保つ必要があります。

    各オブジェクトは、それをバックするクッキーへのポインタを含みます。オブジェクトがFSCACHE_OBJECT_RECYCLING状態にある場合、put_object()が呼ばれたときにオブジェクトは廃止されます。fscache_object構造体はfscache_object_init(object)を呼び出して初期化する必要があります。

  • FS-Cache操作レコード:

    struct fscache_operation {
        atomic_t                usage;
        struct fscache_object   *object;
        unsigned long           flags;
#define FSCACHE_OP_EXCLUSIVE
        void (*processor)(struct fscache_operation *op);
        void (*release)(struct fscache_operation *op);
        ...
};

    FS-Cacheは、キャッシュを駆動する際のさまざまな非同期操作にCPU時間を割り当てるスレッドプールを持っています。これらは上記の構造体で表されます。プロセッサメソッドは操作にCPU時間を割り当てるため呼び出され、使用カウントが0に達したときにリリースメソッドが呼び出されて操作を解放します。

    操作はfscache_enqueue_operation()に登録する前に適切なフラグを設定することでオブジェクトに対して排他的に設定できます。操作がさらに処理時間を必要とする場合、再度登録する必要があります。

  • FS-Cache取得操作レコード:

    struct fscache_retrieval {
        struct fscache_operation op;
        struct address_space    *mapping;
        struct list_head        *to_do;
        ...
};

    このような構造体はFS-Cacheによって割り当てられ、netfsが行う取得および割当リクエストを記録します。この構造体はその後、バックエンドに渡され操作が実行されます。バックエンドはfscache_get_retrieval()を呼び出すことでこの構造体に追加のrefを取得し、fscache_put_retrieval()を呼び出すことでrefを破棄できます。

    バックエンドが検索作業を行うために、検索操作を使用できます。このため、バックエンドがretrieval->op.processorメソッドポインタを適切に設定し、fscache_enqueue_retrieval()を呼び出してスレッドプールにサブミットする必要があります。キャッシュファイルなどは、PG_lockがクリアされたときにページ検査をキューイングするためにこの機能を使用します。

    to_doフィールドは、キャッシュバックエンドが見 fit するように利用可能な空リストです。

  • FS-Cacheストレージ操作レコード:

    struct fscache_storage {
        struct fscache_operation op;
        pgoff_t                 store_limit;
        ...
};

    このタイプの構造体は、FS-Cacheが未完了の書き込みを記録するために割り当てられます。FS-Cache自身がこの操作をキューイングし、適切なタイミングでオブジェクトのwrite_page()メソッドを呼び出してストレージの実装を行います。

キャッシュ操作¶

キャッシュバックエンドは、キャッシュ内のデニゼンに対して実行可能な操作のテーブルをFS-Cacheに提供します。これらは次の構造体タイプに格納されています:

struct fscache_cache_ops

  • キャッシュプロバイダーの名前 [必須]:

    const char *name

    これは厳密には操作ではありませんが、バックエンドを名前付ける文字列を指す必要があります。

  • 新しいオブジェクトを割り当てる [必須]:

    struct fscache_object *(*alloc_object)(struct fscache_cache *cache,
                                       struct fscache_cookie *cookie)

    このメソッドは、特定のキャッシュでクッキーをバックするキャッシュオブジェクトの表現を割り当てるために使用されます。オブジェクトにfscache_object_init()を呼び出して初期化し、返す前に呼び出す必要があります。

    この関数は、複数の検索呼び出し用にインデックスキーを解析して、より使いやすい形式に変換するためにも使用できます。FS-Cacheは、検索が完了または中止された後、キャッシュが形式を解放できるようにlookup_complete()メソッドを呼び出します。

  • オブジェクトの検索および作成 [必須]:

    void (*lookup_object)(struct fscache_object *object)

    このメソッドは、オブジェクトがすでに割り当てられ、クッキーにアタッチされている場合にオブジェクトを検索するために使用されます。このメソッドは、オブジェクトがキャッシュに存在する場合にそれをキャッシュにインスタンス化する必要があります。

    メソッドは、オブジェクトがキャッシュに存在しないと判断した場合、すぐにfscache_object_lookup_negative()を呼び出す必要があります。オブジェクトが存在し、ネットファイルシステムが有効であると確認された場合、オブジェクトにデータを保存できる状態になったらfscache_obtained_object()を呼び出します。同様に、非存在オブジェクトが作成された後もfscache_obtained_object()を呼び出す必要があります。

    検索エラーが発生した場合、fscache_object_lookup_error()を呼び出してそのオブジェクトの検索を中止する必要があります。

  • 検索データの解放 [必須]:

    void (*lookup_complete)(struct fscache_object *object)

    このメソッドは、キャッシュが検索のために使用していたリソースを解放するようにキャッシュに依頼します。

  • オブジェクト参照カウントをインクリメント [必須]:

    struct fscache_object *(*grab_object)(struct fscache_object *object)

    このメソッドは、オブジェクトの参照カウントをインクリメントするために呼び出されます。キャッシュが引き抜かれているなどの理由で失敗する可能性があり、NULLを返します。成功した場合はオブジェクトポインタを返す必要があります。

  • オブジェクトのロック/アンロック [必須]:

    void (*lock_object)(struct fscache_object *object)
void (*unlock_object)(struct fscache_object *object)

    これらのメソッドは、オブジェクトを排他的にロックするために使用されます。ロックを保持しながらスケジューリングが可能である必要があるため、スピンロックでは不十分です。

  • オブジェクトのピン/アンピン [オプション]:

    int (*pin_object)(struct fscache_object *object)
void (*unpin_object)(struct fscache_object *object)

    これらのメソッドは、オブジェクトをキャッシュにピン留めするために使用されます。ピン留めされたオブジェクトは、スペースを確保するために回収されません。キャッシュ内の空き容量が不足している場合、-ENOSPCを返します。

  • オブジェクトの整合性状態の確認 [必須]:

    int (*check_consistency)(struct fscache_object *object)

    このメソッドは、キャッシュがオブジェクトの保存された補助データをネットファイルシステム（netfs）の状態と照合するように呼び出されます。整合している場合は0を、不整合な場合は-ESTALEを返します。-ENOMEMおよび-ERESTARTSYSも返す可能性があります。

  • オブジェクトの更新 [必須]:

    int (*update_object)(struct fscache_object *object)

    指定されたオブジェクトのインデックスエントリを更新するために呼び出されます。新しい情報はobject->cookie->netfs_dataに格納されています。これはobject->cookie->def->get_aux()/get_attr()を呼び出すことで取得できます。

  • データオブジェクトの無効化 [必須]:

    int (*invalidate_object)(struct fscache_operation *op)

    op->objectで指されるデータオブジェクトを無効化するために呼び出されます。このオブジェクトに保存されたすべてのデータを破棄し、attr_changed操作を実行する必要があります。呼び出し元はその後、オブジェクトの更新操作を実行します。

    fscache_op_complete()はopを返す前に呼び出さなければなりません。

  • オブジェクトの破棄 [必須]:

    void (*drop_object)(struct fscache_object *object)

    オブジェクトがクッキーからバインドされていないことを示すために呼び出されます。キャッシュは、オブジェクトがFSCACHE_OBJECT_RECYCLING状態にある場合、リソースを解放し、そのオブジェクトを廃止する必要があります。

    呼び出し元が保持している参照を解放する試みは行わないでください。呼び出し元が適切にput_object()メソッドを呼び出すことになります。

  • オブジェクト参照の解放 [必須]:

    void (*put_object)(struct fscache_object *object)

    オブジェクトへの参照を破棄するために使用されます。オブジェクトは、すべての参照が解放されたときに解放される可能性があります。

  • キャッシュの同期 [必須]:

    void (*sync)(struct fscache_cache *cache)

    バックエンドにキャッシュをバックイングデバイスと同期させるために呼び出されます。

  • キャッシュの分離 [必須]:

    void (*dissociate_pages)(struct fscache_cache *cache)

    キャッシュがキャッシュの引き抜きに伴うページの分離を実行するように呼び出されます。

  • ネットファイルシステムファイルの属性変更の通知 [必須]:

    int (*attr_changed)(struct fscache_object *object);

    ネットファイルシステムファイルの特定の属性（例えば、ファイルが到達できる最大サイズ）が変更されたことをキャッシュに通知するために呼び出されます。キャッシュは、クッキーのget_attr()メソッドを呼び出すことでこれらの属性をネットファイルシステムから読み取ることができます。

    キャッシュはファイルサイズ情報を使用して、キャッシュにスペースを確保する場合があります。また、FS-Cacheにオブジェクトごとに保存可能な最大バイト数を示すためにfscache_set_store_limit()を呼び出す必要があります。

    エラーが発生したか、またはキャッシュオブジェクトが拡張できない場合、このメソッドは負の値を返すことがあります。その場合、オブジェクトはサービスから外されます。

    この操作はFS-Cacheのスレッドプールから非同期に実行され、この操作の実行中にはネットファイルシステム（netfs）のストレージおよび取得操作は除外されます。

  • オブジェクトのデータ用にキャッシュスペースを確保する[オプション]:

    int (*reserve_space)(struct fscache_object *object, loff_t size);

    キャッシュにオブジェクトのデータおよびそのトラッキングに使用されるメタデータを保持するためのスペースを確保するよう要求するための呼び出しです。ゼロサイズは予約をキャンセルするリクエストとみなされます。

    成功した場合は0を返し、空き容量が不足している場合は-ENOSPC、その他のエラーの場合は-ENOMEMまたは-EIOを返す必要があります。

    予約はオブジェクトの現在のサイズを超える可能性があり、これにより今後の拡張が許可されます。オブジェクトの消費するスペースが予約を超過する場合、ページの割り当てリクエストを拒否することが許可されますが義務ではありません。オブジェクトが予約サイズより大きい場合、そのサイズまで削減されることがあります。

  • キャッシュからページを読み込むリクエスト[必須]:

    int (*read_or_alloc_page)(struct fscache_retrieval *op,
                          struct page *page,
                          gfp_t gfp)

    ネットファイルシステム（netfs）のページをキャッシュから読み込むため、またはそのページにバックイングブロックを確保するための呼び出しです。FS-Cacheは呼び出し前に可能な限りチェックを行いますが、主な作業はバックエンドに依存します。

    キャッシュにページがない場合、バックエンドがバックイングブロックを確保できた場合は-ENODATAを返し、できなかった場合は-ENOBUFSまたは-ENOMEMを返す必要があります。

    キャッシュに適切なデータがある場合、読み取り操作をキューに追加し0を返す必要があります。読み取りが完了した後、fscache_end_io()を呼び出す必要があります。

    キャッシュメタデータが保持されているページについてはfscache_mark_pages_cached()を呼び出す必要があります。これによりネットファイルシステム（netfs）にページが明示的にアンキャッシュされる必要があることを示します。この操作はページベクターを受取り、複数のページを一度にマークする機能を提供します。

    opが指す取得レコードは、キューに追加された各ページに対して保持され、ページのI/Oが正式に終了したときに解放されます。この目的にはfscache_get/put_retrieval()が利用可能です。

    取得記録はFS-Cacheスレッドプールを介してCPU時間を取得するために使用できます。この操作が必要な場合は、op->op.processorを適切な処理ルーチンを指すように設定し、適切なタイミングでfscache_enqueue_retrieval()を呼び出してCPU時間を要求する必要があります。例えば、ディスク読み込みの完了時に取得ルーチンをキューイングするなど、このような操作が可能です。取得記録のto_doフィールドはこのような目的で提供されています。

    I/Oエラーが発生した場合は、fscache_io_error()を呼び出し、可能な限り-ENOBUFSを返すか、または適切なエラーコードを伴ってfscache_end_io()を呼び出す必要があります。

    ページまたは複数のページが処理された後、fscache_put_retrieval()を呼び出す必要があります。これにより、すべてのページが処理されたときに操作が完了します。

  • キャッシュからページを読み込むことを要求します（必須）：

    int (*read_or_alloc_pages)(struct fscache_retrieval *op,
                           struct list_head *pages,
                           unsigned *nr_pages,
                           gfp_t gfp)

    これはread_or_alloc_page()メソッドに似ていますが、1つのページではなくページリストを渡します。読み込み操作が開始されたページは、指定されたマッピングのページキャッシュおよびLRUにも追加される必要があります。このようなページはまた、ページリストから削除され、 *nr_pages 各ページごとにカウンターを減らす必要があります。

    エラーが発生した場合（例：-ENOMEM）、そのエラーを返す必要があります。それ以外に、1つ以上のページが読み込めなかったり、割り当てられなかった場合、-ENOBUFSを返す必要があります。1つ以上のページが読み込めなかった場合、-ENODATAを返す必要があります。すべてのページが処理された場合は0を返す必要があります。

  • キャッシュにページを割り当てる要求（必須）：

    int (*allocate_page)(struct fscache_retrieval *op,
                     struct page *page,
                     gfp_t gfp)

    これはread_or_alloc_page()メソッドに似ていますが、キャッシュから読み込まない必要があります。キャッシュにデータが存在していても、取得する必要はありません。ただし、write_page()メソッドがキャッシュに書き込むために必要な内部メタデータを設定する必要があります。

    バックイングブロックが利用できない場合、-ENOBUFSを返す必要があります（他の問題が発生した場合は-ENOMEMを返します）。ブロックが成功裏に割り当てられた場合、netfsページをマークし0を返します。

  • キャッシュにページを割り当てる要求（必須）：

    int (*allocate_pages)(struct fscache_retrieval *op,
                      struct list_head *pages,
                      unsigned *nr_pages,
                      gfp_t gfp)

    これはallocate_page()メソッドの複数ページ版です。pagesとnr_pagesはread_or_alloc_pages()メソッドで扱うのと同じように扱う必要があります。

  • キャッシュにページを書き込む要求（必須）：

    int (*write_page)(struct fscache_storage *op,
                  struct page *page);

    これは、以前に成功したread_or_alloc_page()呼び出しや類似操作があったページからデータを書き込むために呼び出されます。FS-Cacheはマッピングを持たないページをフィルタリングします。

    このメソッドはFS-Cacheスレッドプールから非同期に呼び出されます。実際にデータを保存する必要はなく、このページの次の読み込み時に-ENODATAを返すことで十分です。

    エラーが発生した場合は負のエラーコードを返すべきで、それ以外はゼロを返すべきです。FS-Cacheはエラーに応じて適切なアクションを取るため、このオブジェクトの取り消しを行うことがあります。

    このメソッドが成功を返す場合、FS-Cacheはnetfsに適切に通知します。

  • 保持されている各ページごとのメタデータを破棄する [必須]:

    void (*uncache_page)(struct fscache_object *object, struct page *page)

    netfsのページがpagecacheから追い出されるときに呼ばれます。キャッシュバックエンドは、このページに対して保持している内部表現や追跡をすべて解除する必要があります。

FS-Cache ユーティリティ¶

FS-Cacheはキャッシュバックエンドが利用できるユーティリティを提供しています:

  • キャッシュ内のI/Oエラーの発生を記録する:

    void fscache_io_error(struct fscache_cache *cache)

    この関数はキャッシュ内でI/Oエラーが発生したことをFS-Cacheに通知します。この関数が呼ばれた後、指定されたキャッシュに対してnetfsからキャッシュバックエンドに渡される操作は、リソースの解結び（オブジェクトおよびページの解放）に限定されます。

    この関数は実際にキャッシュを撤回しません。その処理は別途行う必要があります。

  • 取得I/O完了処理を呼び出す:

    void fscache_end_io(struct fscache_retrieval *op, struct page *page,
                    int error);

    ページの取得試行が終了したことを記録するための関数です。成功した場合はエラーコードが0で、それ以外はエラーを示すべきです。

  • 取得または割当されたページの処理を記録する:

    void fscache_retrieval_complete(struct fscache_retrieval *op,
                                int n_pages);

    1つ以上のページが処理され、この操作の対象外になったことを記録するための関数です。操作で残っているページ数が0になったとき、操作が完了します。

  • 操作完了を記録する:

    void fscache_op_complete(struct fscache_operation *op);

    操作の完了を記録するための関数です。これにより、親オブジェクトの実行状態からこの操作が減算され、1つ以上の待機中の操作が実行可能になることがあります。

  • 最大ストレージ制限を設定する:

    void fscache_set_store_limit(struct fscache_object *object,
                             loff_t i_size);

    この関数はnetfsに対してFS-Cacheが試みる最大のバイト数を制限します。この制限を超えるページはfscache_read_alloc_page()などとともに-ENOBUFSで自動的に拒否されます。

  • ページをキャッシュ中としてマークする:

    void fscache_mark_pages_cached(struct fscache_retrieval *op,
                               struct pagevec *pagevec);

    複数のページをキャッシュ中としてマークします。この関数が呼ばれた後、netfsはfscache_uncache_page()を呼び出してこれらのページを解除する必要があります。

  • オブジェクトの整合性チェックを実行する:

    enum fscache_checkaux fscache_check_aux(struct fscache_object *object,
                                        const void *data,
                                        uint16_t datalen);

    netfsに、先ほど検索したオブジェクトの整合性チェックを実行するよう依頼します。オブジェクトに添付されたクッキーは使用するnetfsを決定し、dataとdatalenはキャッシュから取得した補助データの位置を指定する必要があります。

    3つの値のうちの1つが返されます:

    FSCACHE_CHECKAUX_OKAY

    コヒーレンスデータがオブジェクトがそのまま有効であることを示す場合

    FSCACHE_CHECKAUX_NEEDS_UPDATE

    整合性データの更新が必要ですが、それ以外のオブジェクトは有効です。

    FSCACHE_CHECKAUX_OBSOLETE

    整合性データは、オブジェクトが古くなっており、廃棄すべきであることを示しています。

  • 新規に割り当てられたオブジェクトを初期化する:

    void fscache_object_init(struct fscache_object *object);

    オブジェクト表現のすべてのフィールドを初期化します。

  • オブジェクトの破壊を示す:

    void fscache_object_destroyed(struct fscache_cache *cache);

    FS-Cacheに、キャッシュに所属していたオブジェクトが破壊され解放されたことを通知する必要があります。これにより、キャッシュの撤回プロセスがすべてのオブジェクトの破壊が完了しているのを待っている状態で継続できます。

  • オブジェクトのネガティブな検索を示す:

    void fscache_object_lookup_negative(struct fscache_object *object);

    オブジェクトの検索プロセスがネガティブな結果を返したことをFS-Cacheに通知します。

    この操作により、オブジェクトの状態が変更され、検索完了後に待機している読み取りがネットfsサーバーからデータを取得し始めることが可能になります。これは、この時点でキャッシュにデータが存在しないことが確実に分かっているためです。

    この関数はオブジェクトに対して複数回呼び出される可能性がありますが、最初の呼び出しのみが有効で、その後の呼び出しは無視されます。

  • オブジェクトが取得されたことを示す:

    void fscache_obtained_object(struct fscache_object *object);

    オブジェクトの検索プロセスがポジティブな結果を返したか、またはオブジェクトが作成されたことをFS-Cacheに通知します。これは特定のオブジェクトに対して一度だけ呼び出すべきです。

    オブジェクトの状態を変更して以下を示します:

    1. このオブジェクトにfscache_object_lookup_negative()が呼び出されていない場合、データが利用可能である可能性があり、読み取りが行われるようになります。

    2. このオブジェクトに対して書き込みが行われるようになります。

  • オブジェクトの検索が失敗したことを示す:

    void fscache_object_lookup_error(struct fscache_object *object);

    オブジェクトが致命的なエラー（通常はEIO）に遭遇したことをマークし、できるだけ早く撤回状態に移行させます。

  • 古いオブジェクトが見つかり廃棄されたことを示す:

    void fscache_object_retrying_stale(struct fscache_object *object);

    検索プロセスがキャッシュ内のnetfsが古いと判断したオブジェクトを見つけ、そのオブジェクトがキャッシュから廃棄され、再び検索が行われることを示します。

  • キャッシュバックエンドがオブジェクトを終了したことを示す:

    void fscache_object_mark_killed(struct fscache_object *object,
                                enum fscache_why_object_killed why);

    キャッシュバックエンドが予期せずにオブジェクトを終了したことを示します。whyパラメータは以下の理由を示す必要があります:

    FSCACHE_OBJECT_IS_STALE

    • オブジェクトが古くなっており、廃棄が必要です。

    FSCACHE_OBJECT_NO_SPACE

    • キャッシュスペースが不足していました。

    FSCACHE_OBJECT_WAS_RETIRED

    • オブジェクトが解放時に廃止されました。

    FSCACHE_OBJECT_WAS_CULLED

    • オブジェクトがスペース確保のために削除されました。

  • 取得および参照を解放する:

    void fscache_get_retrieval(struct fscache_retrieval *op);
void fscache_put_retrieval(struct fscache_retrieval *op);

    これらの2つの関数は、非同期データ取得とブロック割当を行う際、取得記録を保持するために使用されます。

  • 取得記録を処理キューに追加する:

    void fscache_enqueue_retrieval(struct fscache_retrieval *op);

    FS-Cacheスレッドプールによって取得記録を処理キューに追加します。プール内のスレッドの1つが、取得記録のop->op.processorコールバック関数を呼び出します。この関数は、コールバック関数内で呼び出される場合があります。

  • オブジェクトの状態名一覧:

    const char *fscache_object_states[];

    デバッグ目的で、オブジェクトの状態を表示用のテキスト文字列に変換するために使用できます。
