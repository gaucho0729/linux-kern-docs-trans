非同期操作の処理¶

By: David Howells <dhowells@redhat.com>

概要¶

FS-Cache は、データの保存および取得ルーチンのために非同期操作の処理機能を備えています。その操作は fscache_operation struct で表されますが、これらは通常他の構造体に埋め込まれています。

この機能はキャッシュバックエンドに利用可能であり、使用が期待されています。FS-Cache は操作を生成し、適切なキャッシュバックエンドに渡して完了処理を行います。

この機能を利用するには、<linux/fscache-cache.h> を #include する必要があります。

操作レコードの初期化¶

操作は fscache_operation struct に記録されます：

struct fscache_operation {
        union {
                struct work_struct fast_work;
                struct slow_work slow_work;
        };
        unsigned long           flags;
        fscache_operation_processor_t processor;
        ...
};

操作を発行したい場合は、この struct を埋め込んだ構造体を割り当ててください。これを初期化するには、以下の関数を呼び出してください：

void fscache_operation_init(struct fscache_operation *op,
                            fscache_operation_release_t release);

初期化する操作と、使用するリリース関数を指定してください。

op->flags パラメータには、CPU時間の提供と排他性を示す必要があります（パラメータセクションを参照）。

op->fast_work、op->slow_work および op->processor フラグは、CPU時間の提供に応じて適切に設定する必要があります（パラメータセクションを参照）。

操作の各送信前に op->flags に FSCACHE_OP_WAITING を設定し、その後待機する必要があります。

パラメータ¶

操作レコードのフラグパラメータには、いくつかのパラメータを設定できます。これらの操作で CPU時間の提供には3つのオプションがあります：

  1. 操作は同期的に実行できます（FSCACHE_OP_MYTHREAD）。スレッドは、他のスレッドにdeferしないで操作自体を処理したい場合にこのオプションを使用します。

    これは、例として CacheFiles でバックイングファイルシステムの readpages() を呼び出す際などに使用されます。readpages() は非同期データフェッチを行いますが、ページが存在するかどうかの判定は同期的に実行され、netfs はこの判定が完了するまで進みません。

    このオプションを使用する場合、FSCACHE_OP_WAITING を op->flags に設定し、操作を送信する前に実行スレッドが待機する必要があります：

    wait_on_bit(&op->flags, FSCACHE_OP_WAITING,
            TASK_UNINTERRUPTIBLE);

  2. 操作は高速非同期（FSCACHE_OP_FAST）で実行できます。このような操作は I/O で待機することはできません。

    これは、CacheFiles がバックイングfsのページをnetfsのページにコピーする際などに使用されます。

    このオプションを使用する場合、op->fast_work および op->processor を初期化する必要があります：

    INIT_WORK(&op->fast_work, do_some_work);

  3. 操作は遅延非同期（FSCACHE_OP_SLOW）として処理される場合があり、その場合は遅延処理ファシリティに処理を委譲します。このような操作はI/Oの待機を許可されます。

    これは、FS-Cacheがリモートサーバーから取得したページのバックグラウンド書き込みを処理するために使用される例です。

    このオプションを使用する場合、op->slow_workとop->processorは操作を送信する前に初期化しておく必要があります:

    fscache_operation_init_slow(op, processor)

さらに、操作は次の2つのタイプのいずれかです:

  1. 排他（FSCACHE_OP_EXCLUSIVE）。このタイプの操作は、対象オブジェクト上で他の操作と同時に実行できません。

    例として、属性変更操作があります。この操作では、書き込まれるファイルが切断される可能性があります。

  2. 共有可能。このタイプの操作は同時に実行可能です。他の操作が同時に実行されている場合でも、操作実装側が干渉を防ぐ必要があります。

手順¶

操作は次の手順で使用されます:

  1. 送信スレッドは操作を確保し、自身で初期化する必要があります。通常これは、汎用的なopを内包するより特定の構造体の一部です。

  2. 送信スレッドは、次の2つの関数のいずれかを使用して操作を処理に送信する必要があります:

    int fscache_submit_op(struct fscache_object *object,
                      struct fscache_operation *op);

int fscache_submit_exclusive_op(struct fscache_object *object,
                                struct fscache_operation *op);

    最初の関数は非排他操作を送信するためのもので、2番目の関数は排他操作を送信するためのものです。呼び出し元は依然としてFSCACHE_OP_EXCLUSIVEフラグを設定する必要があります。

    成功した場合、両方の関数は操作を指定されたオブジェクトに割り当てて0を返します。指定されたオブジェクトが永久に利用不可な場合、-ENOBUFSが返されます。

    オブジェクトがまだ検索中または作成中である場合、操作マネージャーはその操作を遅延します。オブジェクト上で競合する排他性の操作が進行中である場合も同様に操作が遅延されます。

    操作が非同期の場合、マネージャーはその操作の参照を保持します。そのため、呼び出し元は以下の関数に操作を渡して参照を解放する必要があります:

    void fscache_put_operation(struct fscache_operation *op);

  3. 送信スレッドが自身で作業を実行したい場合、FSCACHE_OP_MYTHREADで操作をマークした場合は、上記のようにFSCACHE_OP_WAITINGを監視し、必要に応じてオブジェクトの状態を確認する必要があります（オブジェクトがスレッドが待機している間に終了している可能性があります）。

    処理が終了した後、fscache_op_complete()とfscache_put_operation()を呼び出して操作を完了させます。

  4. 操作はオブジェクトに有効なロックを保持し、他の排他操作が競合するのを防ぎます。必要に応じてCPU時間のプロビジョニングオプションを調整することで、操作をキューイングしてさらに即時非同期処理を実行できます。例:

    op->flags &= ~FSCACHE_OP_TYPE;
op->flags |= ~FSCACHE_OP_FAST;

    呼び出す:

    void fscache_enqueue_operation(struct fscache_operation *op)

    これは、他の処理がワーカースレッドプールを使用できるようにするためのものです。

非同期コールバック¶

非同期モードで使用する場合、ワーカースレッドプールは操作へのポインタを伴ってプロセッサメソッドを呼び出します。その後、コンテナ構造体にアクセスするために以下の方法を使用します container_of():

static void fscache_write_op(struct fscache_operation *_op)
{
        struct fscache_storage *op =
                container_of(_op, struct fscache_storage, op);
...
}

呼び出し元は操作に参照を保持しており、プロセッサ関数が返るときにfscache_put_operation()を呼び出します。プロセッサ関数はfscache_enqueue_operation()を呼び出すか、追加の参照を取るかを選択できます。
