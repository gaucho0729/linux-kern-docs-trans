ファイルシステムマウントAPI¶

概要¶

新しいマウントの作成は、マルチステッププロセスとして行われます:

  1. ファイルシステムコンテキストを作成します。

  2. パラメータをパースし、コンテキストにアタッチします。パラメータはユーザー空間から個別に渡されることが想定されていますが、レガシーバイナリパラメータも処理可能です。

  3. 有効化し、事前処理を行います。

  4. スーパーブロックとマウント可能なルートを取得または作成します。

  5. マウントを実行します。

  6. エラーメッセージをコンテキストに添付して返します。

  7. コンテキストを破棄します。

これをサポートするために、file_system_type構造体が2つの新しいフィールドを獲得します:

int (*init_fs_context)(struct fs_context *fc);
const struct fs_parameter_description *parameters;

最初のフィールドは、ファイルシステム固有の部分を設定するために呼び出され、追加のスペースを含み、2番目のフィールドは登録時に検証用のパラメータ記述にポイントします。今後のシステムコールによる照会にも使用されます。

セキュリティ初期化が行われていますので注意してください。 RCU保護データ構造からデータ要素を削除した後、 ファイルシステムが呼ばれるようにして、ネームスペースの調整が最初に行われます。

ファイルシステムコンテキスト¶

スーパーブロックの作成と再構成はファイルシステムコンテキストによって制御されます。これはfs_context構造体で表されます:

struct fs_context {
        const struct fs_context_operations *ops;
        struct file_system_type *fs_type;
        void                    *fs_private;
        struct dentry           *root;
        struct user_namespace   *user_ns;
        struct net              *net_ns;
        const struct cred       *cred;
        char                    *source;
        char                    *subtype;
        void                    *security;
        void                    *s_fs_info;
        unsigned int            sb_flags;
        unsigned int            sb_flags_mask;
        unsigned int            s_iflags;
        unsigned int            lsm_flags;
        enum fs_context_purpose purpose:8;
        ...
};

fs_contextのフィールドは以下の通りです:

  • const struct fs_context_operations *ops

    これらはファイルシステムコンテキスト上で実行できる操作です（以下を参照）。これは->init_fs_context() file_system_type操作によって設定する必要があります。

  • struct file_system_type *fs_type

    構築または再構成されているファイルシステムのfile_system_typeへのポインタ。これはタイプオーナーへの参照を保持します。

  • void *fs_private

    ファイルシステムのプライベートデータへのポインタ。これはファイルシステムがパースしたオプションを保存する場所です。

  • struct dentry *root

    マウント可能なツリーのルート（間接的に、そのスーパーブロック）へのポインタ。これは->get_tree()操作によって埋められます。このフィールドが設定されている場合、root->d_sbへのアクティブな参照も保持する必要があります。

  • struct user_namespace *user_ns
struct net *net_ns

    呼び出しプロセスが使用しているネームスペースのサブセットがあります。これらは各ネームスペースへの参照を保持します。ファイルシステムは、自動マウントの親マウントスーパーブロックなどの他のソースを反映するために、サブスクライブされたネームスペースを置き換えることができます。

  • const struct cred *cred

    マウントャーの資格情報。これは資格情報への参照を保持します。

  • char *source

    これはソースを指定します。ブロックデバイス（例: /dev/sda1）であるか、NFSが望むような「host:/path」などのより複雑なものかもしれません。

  • char *subtype

    /proc/mountsに表示されるタイプに追加される文字列で、それを識別します（FUSEで使用されます）。ファイルシステムが望む場合は設定可能です。

  • void *security

    LSMがスーパーブロックのセキュリティデータを保持するための場所。関連するセキュリティ操作は以下に記載されています。

  • void *s_fs_info

    新しいスーパーブロックの提案されたs_fs_info、スーパーブロックで設定されます。 sget_fc()これはsuperblockを区別するために使用できます。

  • unsigned int sb_flags
unsigned int sb_flags_mask

    super_block::s_flagsに設定/クリアするSB_*フラグのビットはどれか。

  • unsigned int s_iflags

    superblockが作成されるときに、これらはs->s_iflagsとビットごとのOR演算されます。

  • enum fs_context_purpose

    コンテキストの目的を示します。利用可能な値は次のとおりです：

    FS_CONTEXT_FOR_MOUNT,

    明示的なマウント用の新しいsuperblock

    FS_CONTEXT_FOR_SUBMOUNT

    既存のマウントの自動サブマウント

    FS_CONTEXT_FOR_RECONFIGURE

    既存のマウントの変更

マウントコンテキストはvfs_new_fs_context()またはvfs_dup_fs_context()を呼び出すことで作成され、put_fs_context()で破棄されます。構造体は参照カウントされていません。

VFS、セキュリティ、ファイルシステムのマウントオプションはそれぞれvfs_parse_mount_option()で設定されます。古いmount(2)システムコールで提供されたページ単位のデータはgeneric_parse_monolithic()で解析できます。

マウント時に、ファイルシステムは任意のポインタからデータを取得してsuperblock（またはそれ以外のオブジェクト）にアタッチできるようにします。ただし、マウントコンテキスト内のポインタをクリアする必要があります。

ファイルシステムはマウントコンテキストを使ってリソースを割り当て、それらをピン留めすることもできます。たとえばNFSは適切なプロトコルバージョンモジュールをピン留めできます。

ファイルシステムコンテキスト操作¶

ファイルシステムコンテキストは操作テーブルを指しています：

struct fs_context_operations {
        void (*free)(struct fs_context *fc);
        int (*dup)(struct fs_context *fc, struct fs_context *src_fc);
        int (*parse_param)(struct fs_context *fc,
                           struct fs_parameter *param);
        int (*parse_monolithic)(struct fs_context *fc, void *data);
        int (*get_tree)(struct fs_context *fc);
        int (*reconfigure)(struct fs_context *fc);
};

これらの操作はマウント手順のさまざまな段階で呼び出され、ファイルシステムコンテキストを管理します。以下がその操作です：

  • void (*free)(struct fs_context *fc);

    コンテキストが破棄されるときに、ファイルシステム固有の部分をクリーンアップするために呼び出されます。一部のコンテキストが->get_tree()によって削除・NULL化されている可能性があるため、その点を認識しておく必要があります。

  • int (*dup)(struct fs_context *fc, struct fs_context *src_fc);

    ファイルシステムコンテキストが複製されるときに、ファイルシステム固有データを複製するために呼び出されます。エラーを返すことで複製失敗を示せます。

    警告

    注意: この操作が失敗しても、すぐにput_fs_context()が呼び出されるため、->dup() grace periodsを尊重しなければなりませんし、 は->free()でファイルシステム固有データを安全にします。

  • int (*parse_param)(struct fs_context *fc,
                   struct fs_parameter *param);

    パラメータがファイルシステムコンテキストに追加されるときに呼び出されます。paramはキー名と値オブジェクトを指します。VFS固有のオプションはすでに除外され、fc->sb_flagsがコンテキスト内で更新されています。セキュリティオプションも除外され、fc->securityが更新されています。

    パラメータはfs_parse()とfs_lookup_param()で解析できます。注意点として、ソース（複数可能）は「source」という名前のパラメータとして提示されます。

    成功時は0を返すか、負のエラーコードを返します。

  • int (*parse_monolithic)(struct fs_context *fc, void *data);

    mount(2)システムコールが呼び出され、データページを一度にすべて渡す場合に呼ばれます。この場合、コンマで区切られた「key[=val]」項目のリストであると予想される場合は、NULLに設定できます。

    戻り値は->parse_param()の戻り値と同じです。

    ファイルシステム（例：NFS）がデータを最初に確認し、標準のkey-valリストであると判断した場合、generic_parse_monolithic()に処理を委譲できます。

  • int (*get_tree)(struct fs_context *fc);

    ファイルシステムコンテキストに保存された情報を使ってマウント可能なルートとスーパーブロックを取得または作成するため呼び出されます（再構成は別のベクター経由で行われます）。ファイルシステムコンテキストから必要なリソースを分離してスーパーブロックに転送できます。

    成功時はfc->rootにマウント可能なルートを設定し0を返す必要があります。エラーの場合は負のエラーコードを返します。

    ユーザースペース駆動のコンテキストでは、特定のコンテキストに対してこの関数が一度しか呼び出せないように設定されます。

  • int (*reconfigure)(struct fs_context *fc);

    ファイルシステムコンテキストに保存された情報を使ってスーパーブロックを再構成するため呼び出されます。ファイルシステムコンテキストから必要なリソースを分離してスーパーブロックに転送できます。スーパーブロックはfc->root->d_sbから取得できます。

    成功時は0を返す必要があります。エラーの場合は負のエラーコードを返します。

    注意

    reconfigureはremount_fsの代替として意図されています。

ファイルシステムコンテキストセキュリティ¶

ファイルシステムコンテキストには、LSMsがマウントされるスーパーブロックのセキュリティコンテキストを構築するために使用できるセキュリティポインタが含まれています。新しいマウントコードがこの目的で使用する操作は以下の通りです：

  • int security_fs_context_alloc(struct fs_context *fc,
                              struct dentry *reference);

    fc->security（初期値はNULL）を初期化し、必要なリソースを確保します。成功時は0を、失敗時は負のエラーコードを返します。

    コンテキストがスーパーブロック再構成（FS_CONTEXT_FOR_RECONFIGURE）のために作成されている場合、root dentryを示します。サブマウント（FS_CONTEXT_FOR_SUBMOUNT）の場合も同様に、自動マウントポイントを示します。

  • int security_fs_context_dup(struct fs_context *fc,
                            struct fs_context *src_fc);

    fc->security（初期値はNULL）を初期化し、必要なリソースを確保します。src_fcは元のファイルシステムコンテキストを指し、参照として使用できます。成功時は0を、失敗時は負のエラーコードを返します。

  • void security_fs_context_free(struct fs_context *fc);

    fc->securityにアタッチされたものをクリーンアップします。注意点として、内容がスーパーブロックに転送され、get_tree中にポインタがクリアされる可能性があります。

  • int security_fs_context_parse_param(struct fs_context *fc,
                                    struct fs_parameter *param);

    各マウントパラメータに対して呼び出されます。引数は->parse_param()メソッドと同じです。パラメータをファイルシステムに渡す場合は0を、無視する場合は1を、拒否する場合はエラーを返す必要があります。

    paramが指す値は、文字列の場合は変更可能ですが、取得（値ポインタがNULLに設定される）場合もあります。取得された場合は1を返す必要があります。ファイルシステムに渡されないようにするためです。

  • int security_fs_context_validate(struct fs_context *fc);

    すべてのオプションが解析された後呼び出され、全体としてのパラメータを検証し、必要な割当を行います。これによりsecurity_sb_get_tree()とsecurity_sb_reconfigure()が失敗しにくくなります。0を返すか、負のエラーコードを返します。

    再構成の場合は、ターゲットスーパーブロックはfc->rootを通じてアクセス可能です。

  • int security_sb_get_tree(struct fs_context *fc);

    マウントプロセス中に呼び出され、指定されたスーパーブロックがマウント可能か確認し、セキュリティデータを転送します。0を返すか、負のエラーコードを返します。

  • void security_sb_reconfigure(struct fs_context *fc);

    LSMのコンテキストに再構成を適用するために呼び出されます。失敗してはなりません。エラーチェックやリソース割当は、パラメータ解析と検証のハンドラで事前に実行する必要があります。

  • int security_sb_mountpoint(struct fs_context *fc,
                           struct path *mountpoint,
                           unsigned int mnt_flags);

    マウントプロセス中に呼び出され、コンテキストに接続されたルートdentryが指定されたマウントポイントに接続可能か確認します。成功時は0を、失敗時は負のエラーコードを返します。

VFSファイルシステムコンテキストAPI¶

ファイルシステムコンテキストを作成する操作は4つあり、コンテキストの破壊は1つです。

  • struct fs_context *fs_context_for_mount(struct file_system_type *fs_type,
                                        unsigned int sb_flags);

    新しいマウントの設定に必要なファイルシステムコンテキストを割り当てます。これは新しいスーパーブロックか既存のスーパーブロックを共有するかに関わらず、スーパーブロックフラグを設定し、セキュリティを初期化し、fs_type->init_fs_context()を呼び出してファイルシステム固有データを初期化します。

    fs_typeはコンテキストを管理するファイルシステムタイプを指定し、sb_flagsはそのスーパーブロックに保存されるフラグを初期化します。

  • struct fs_context *fs_context_for_reconfigure(
         struct dentry *dentry,
         unsigned int sb_flags,
         unsigned int sb_flags_mask);

    既存のスーパーブロックを再構成するためにファイルシステムコンテキストを割り当てます。dentryは構成するスーパーブロックへの参照を提供し、sb_flagsとsb_flags_maskは変更すべきスーパーブロックフラグと変更後の値を示します。

  • struct fs_context *fs_context_for_submount(
         struct file_system_type *fs_type,
         struct dentry *reference);

    自動マウントポイントやその他の派生スーパーブロック用に新しいマウントを作成するためにファイルシステムコンテキストを割り当てます。fs_typeはコンテキストを管理するファイルシステムタイプを指定し、参照dentryはパラメータを提供します。名前空間は参照dentryのスーパーブロックから継承されます。

    参照するdentryがfs_typeと同じファイルシステムタイプである必要はないことに注意してください。

  • struct fs_context *vfs_dup_fs_context(struct fs_context *src_fc);

    ファイルシステムコンテキストを複製し、記録されたオプションをコピーし、保持するリソースを複製または追加で参照します。これは、ファイルシステムがネストされたマウント内でマウントを取得する必要がある場合（例：NFS4がターゲットサーバーのルートを内部的にマウントし、その後ターゲットディレクトリへのプライベートなパスウォークを実行する場合）に使用可能です。

    新しいコンテキストでの目的は古いコンテキストから継承されます。

  • void put_fs_context(struct fs_context *fc);

    ファイルシステムコンテキストを破壊し、保持するリソースを解放します。これは->free()操作を呼び出します。これはファイルシステムコンテキストを作成したすべてのユーザーが呼び出すことを意図しています。

    警告

    ファイルシステムコンテキストは参照カウントされないため、これは条件に関係なく破壊を引き起こします。

上記のすべての操作では、put操作を除き、返り値はマウントコンテキストポインタまたは負のエラーコードです。

残りの操作では、エラーが発生した場合、負のエラーコードが返されます。

  • int vfs_parse_fs_param(struct fs_context *fc,
                       struct fs_parameter *param);

    ファイルシステムコンテキストに単一のマウントパラメータを提供します。これは「source」パラメータとして指定されるソース/デバイスの指定を含み、ファイルシステムがこれをサポートする場合、複数回指定可能です。

    paramはパラメータのキー名と値を指定します。パラメータはまず標準的なマウントフラグ（SB_xxxフラグを設定して消費）またはセキュリティオプション（LSMが消費）に該当するかを確認し、その後ファイルシステムに渡されます。

    パラメータ値は型があり、次のいずれかです：

    fs_value_is_flag

    パラメータに値が指定されていない

    fs_value_is_string

    値は文字列

    fs_value_is_blob

    値はバイナリブロブ

    fs_value_is_filename

    値はファイル名* + dirfd

    fs_value_is_file

    値はオープンされたファイル（file*）

    値がある場合、その値はparam->{string,blob,name,file}の構造体内のユニオンに保存されます。注意点として、関数はポインタを奪ってクリアする可能性があり、その後はそのオブジェクトの処分を責任をもって行います。

  • int vfs_parse_fs_string(struct fs_context *fc, const char *key,
                        const char *value, size_t v_size);

    vfs_parse_fs_param()をラップし、渡された値文字列をコピーします。

  • int generic_parse_monolithic(struct fs_context *fc, void *data);

    sys_mount()データページを解析し、テキストリストとしての形式を想定します。これはkey[=val]オプションがコンマで区切られた形式で、リストの各項目をvfs_mount_option()に渡します。これは->parse_monolithic()メソッドがNULLの場合のデフォルトです。

  • int vfs_get_tree(struct fs_context *fc);

    マウント可能なルートとスーパーブロックを取得または作成し、ファイルシステムコンテキスト内のパラメータを使用してスーパーブロックを選択/構成します。これにより->get_tree()メソッドが呼び出されます。

  • struct vfsmount *vfs_create_mount(struct fs_context *fc);

    指定されたファイルシステムコンテキストのパラメータを使用してマウントを作成します。注意: この操作はマウントを何かに接続しません。

スーパーブロック作成ヘルパー¶

ファイルシステムがスーパーブロックの作成または検索に使用できるVFSのヘルパがいくつか用意されています。

  • struct super_block *
sget_fc(struct fs_context *fc,
        int (*test)(struct super_block *sb, struct fs_context *fc),
        int (*set)(struct super_block *sb, struct fs_context *fc));

    これはコアルーチンです。testがNULLでない場合、fs_contextに保持されている基準に一致する既存のスーパーブロックをtest関数を使用して検索します。一致が見つからない場合、新しいスーパーブロックが作成され、set関数が呼ばれて設定されます。

    set関数が呼ばれる前に、fc->s_fs_infoはsb->s_fs_infoに転送され、set関数が成功した場合（つまり0を返した場合）、fc->s_fs_infoはクリアされます。

以下のすべてのヘルパは sget_fc():

  • int vfs_get_super(struct fs_context *fc,
                  enum vfs_get_super_keying keying,
                  int (*fill_super)(struct super_block *sb,
                                    struct fs_context *fc))

    デバイスレスのスーパーブロックを作成/検索します。キーリングはこのタイプのスーパーブロックがいくつ存在可能で、どのように共有されるかを示します:

    1. vfs_get_single_super

      システム内にはこのようなスーパーブロックは1つしか存在できません。さらに新しいスーパーブロックを取得する試みはこの1つを取得し（パラメータの違いは無視されます）

    2. vfs_get_keyed_super

      このタイプのスーパーブロックは複数存在可能で、s_fs_infoポインタでキー付けされます（例: これはネームスペースを指しているかもしれません）。

    3. vfs_get_independent_super

      このタイプの独立スーパーブロックは複数存在可能です。この関数は既存のものをマッチせず、常に新しいものを生成します。

パラメータ説明¶

パラメータはlinux/fs_parser.hで定義された構造体を使用して説明されます。コアの説明構造体があり、すべてを結びつけています:

struct fs_parameter_description {
        const struct fs_parameter_spec *specs;
        const struct fs_parameter_enum *enums;
};

例:

enum {
        Opt_autocell,
        Opt_bar,
        Opt_dyn,
        Opt_foo,
        Opt_source,
};

static const struct fs_parameter_description afs_fs_parameters = {
        .specs          = afs_param_specs,
        .enums          = afs_param_enums,
};

メンバは以下の通りです:

  1. const struct fs_parameter_specification *specs;

    パラメータ仕様のテーブルで、nullエントリで終了します。エントリの型は:

    struct fs_parameter_spec {
        const char              *name;
        u8                      opt;
        enum fs_parameter_type  type:8;
        unsigned short          flags;
};

    「name」フィールドはパラメータキーに完全一致する文字列で、ワイルドカードやパターン、ケース無視はなしです。「opt」はfs_parser()関数が成功した場合に返す値です。

    「type」フィールドは望ましい値の型を示し、次のいずれかでなければなりません:

    TYPE NAME

    EXPECTED VALUE

    RESULT IN

    fs_param_is_flag

    値なし

    n/a

    fs_param_is_bool

    ブール値

    result->boolean

    fs_param_is_u32

    32ビット符号なし整数

    result->uint_32

    fs_param_is_u32_octal

    32ビットオクタリ整数

    result->uint_32

    fs_param_is_u32_hex

    32ビットヘキサデシマル整数

    result->uint_32

    fs_param_is_s32

    32ビット符号付き整数

    result->int_32

    fs_param_is_u64

    64ビット符号なし整数

  2. const struct fs_parameter_enum *enums;

    enum 値名のテーブルから整数へのマッピング表で、null エントリで終了する。これは次の型を持つ：

    struct fs_parameter_enum {
        u8              opt;
        char            name[14];
        u8              value;
};

    配列は { パラメータ ID, 名前 } でキー付けされた要素の無秩序なリストで、マッピングする値を示す。たとえば：

    static const struct fs_parameter_enum afs_param_enums[] = {
        { Opt_bar,   "x",      1},
        { Opt_bar,   "y",      23},
        { Opt_bar,   "z",      42},
};

    fs_param_is_enum 型のパラメータが見つかった場合、fs_parse() はその値を enum 表で検索し、結果をパース結果に保存する。

パーサーのポインタは file_system_type struct のパーサーポインタに指され、これは登録時に検証（CONFIG_VALIDATE_FS_PARSER=y の場合）を提供し、fsinfo() システムコールを介してユーザー空間から説明を照会できるようにする。

パラメータ補助関数¶

ファイルシステムや LSM が与えられたパラメータを処理するのに役立つ複数のユーティリティ関数が提供される。

  • int lookup_constant(const struct constant_table tbl[],
                    const char *name, int not_found);

    名前から整数へのマッピング表で、名前によって定数を検索する。この表は次の型を持つ要素の配列である：

    struct constant_table {
        const char      *name;
        int             value;
};

    マッチが見つかった場合、対応する値が返される。マッチが見つからない場合は、not_found 値が返される。

  • bool validate_constant_table(const struct constant_table *tbl,
                             size_t tbl_size,
                             int low, int high, int special);

    定数テーブルを検証する。すべての要素が適切に並んでおり、重複がなく、値が low と high の範囲内であることを確認する。ただし、範囲外の1つの特別な値を許容する。特別な値が不要な場合は、special を low-to-high の範囲内に設定するだけである。

    すべてが問題なければ true を返す。テーブルが無効な場合、エラーが dmesg にログされ、false を返す。

  • bool fs_validate_description(const struct fs_parameter_description *desc);

    これはパラメータ記述にいくつかの検証チェックを行います。記述が正しい場合は true を返し、そうでない場合は false を返します。検証が失敗した場合、エラーを dmesg にログします。

  • int fs_parse(struct fs_context *fc,
             const struct fs_parameter_description *desc,
             struct fs_parameter *param,
             struct fs_parse_result *result);

    これはパラメータの主な解釈器です。パラメータ記述を使用して、キー名でパラメータを検索し、それをオプション番号に変換して返します。

    成功した場合、パラメータのタイプがブール値、整数、または列挙型タイプを示す場合、この関数が値を変換し、結果を result->{boolean,int_32,uint_32,uint_64} に保存します。

    初期のマッチングに失敗した場合、キーは「no」プレフィックスが付加され、値が存在しない状態で検索が試行されます。このキーからプレフィックスを除去した状態で再検索が行われ、パラメータの型が fs_param_neg_with_no フラグを設定している場合、マッチングが成功し result->negated が true に設定されます。

    パラメータにマッチしなかった場合は -ENOPARAM を返します。パラメータにマッチしたが値が誤っている場合は -EINVAL を返します。それ以外の場合はパラメータのオプション番号を返します。

  • int fs_lookup_param(struct fs_context *fc,
                    struct fs_parameter *value,
                    bool want_bdev,
                    struct path *_path);

    文字列またはファイル名タイプを保持するパラメータを受け取り、パス検索を試行します。パラメータがブロックデバイスを期待する場合、インノデが実際にブロックデバイスを表しているかを確認します。

    成功した場合は 0 を返し、 *_path 失敗した場合は負のエラーコードを返します。
