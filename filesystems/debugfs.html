DebugFS¶

Copyright © 2009 Jonathan Corbet <corbet@lwn.net>

Debugfsは、カーネル開発者があらゆる情報をユーザー空間に公開できるシンプルな方法として存在しています。/procとは異なり、プロセスに関する情報のみを提供することを目的としており、sysfsとは異なり、ファイルごとに1つの値しか許容しないという厳しいルールがありますが、debugfsにはまったくルールがありません。開発者はここに望む情報を自由に配置できます。debugfsファイルシステムは、ユーザー空間に対して安定したABIを提供する意図は持ちません。理論上は、ここにエクスポートされるファイルには安定性の制約がありません。しかし現実の世界は常にそんなに単純ではありません。 1; また、debugfsインターフェースも、永続的にメンテナンスが必要であるという前提で設計されるべきです。

debugfsは通常、次のコマンドでマウントされます:

mount -t debugfs none /sys/kernel/debug

(あるいは同等の/etc/fstabの行)。debugfsのルートディレクトリはデフォルトではrootユーザーのみがアクセス可能です。アクセス権を変更するには、「uid」、「gid」、「mode」などのマウントオプションを使用します。

debugfs APIはモジュールに対してGPLのみでエクスポートされます。

debugfsを使用するコードでは<linux/debugfs.h>を含める必要があります。その後、最初の作業は少なくとも1つのディレクトリを作成して、debugfsファイルを保持することです:

struct dentry *debugfs_create_dir(const char *name, struct dentry *parent);

この関数が成功すれば、指定された親ディレクトリの下にnameという名前のディレクトリが作成されます。親がNULLの場合、debugfsのルートディレクトリにディレクトリが作成されます。成功した場合、返される値はstruct dentryポインタで、このディレクトリ内にファイルを作成するためのものであり、最後にクリーンアップする際に使用できます。ERR_PTR(-ERROR)が返された場合は何かがうまくいかなかったことを示し、ERR_PTR(-ENODEV)が返された場合はカーネルがdebugfsサポートを含んでいないことを示します。

debugfsディレクトリ内にファイルを作成する最も一般的な方法は以下の通りです:

struct dentry *debugfs_create_file(const char *name, umode_t mode,
                                   struct dentry *parent, void *data,
                                   const struct file_operations *fops);

ここで、nameは作成するファイル名、modeはファイルのアクセス権限、parentはファイルを保持するディレクトリ、dataは結果のinode構造体のi_privateフィールドに保存され、fopsはファイルの動作を実装するファイル操作のセットです。最低限、read()および/またはwrite()操作を提供する必要があります。他の操作は必要に応じて追加できます。再度、返される値は作成されたファイルのdentryポインタで、エラーの場合はERR_PTR(-ERROR)、debugfsサポートが欠如している場合はERR_PTR(-ENODEV)となります。

初期サイズを持つファイルを作成するには、以下の関数を使用できます:

void debugfs_create_file_size(const char *name, umode_t mode,
                              struct dentry *parent, void *data,
                              const struct file_operations *fops,
                              loff_t file_size);

file_sizeは初期のファイルサイズを表します。他のパラメータは関数debugfs_create_fileと同じです。

いくつかのケースでは、ファイル操作のセットを作成する必要はありません。debugfsコードは単純な状況向けに複数の補助関数を提供しています。単一の整数値を含むファイルは以下のいずれかで作成できます。

void debugfs_create_u8(const char *name, umode_t mode,
                       struct dentry *parent, u8 *value);
void debugfs_create_u16(const char *name, umode_t mode,
                        struct dentry *parent, u16 *value);
void debugfs_create_u32(const char *name, umode_t mode,
                        struct dentry *parent, u32 *value);
void debugfs_create_u64(const char *name, umode_t mode,
                        struct dentry *parent, u64 *value);

これらのファイルは指定された値の読み書きをサポートしています。特定のファイルが書き込みを許可しない場合は、モードビットを適切に設定してください。これらのファイルの値は10進数で表示され、16進数が適切な場合は以下の関数を使用してください。

void debugfs_create_x8(const char *name, umode_t mode,
                       struct dentry *parent, u8 *value);
void debugfs_create_x16(const char *name, umode_t mode,
                        struct dentry *parent, u16 *value);
void debugfs_create_x32(const char *name, umode_t mode,
                        struct dentry *parent, u32 *value);
void debugfs_create_x64(const char *name, umode_t mode,
                        struct dentry *parent, u64 *value);

開発者がエクスポートする値のサイズを知っている限り、これらの関数は有用です。ただし、一部の型は異なるアーキテクチャで幅が異なるため、状況が複雑になることがあります。このような特殊なケースをサポートする関数があります。

void debugfs_create_size_t(const char *name, umode_t mode,
                           struct dentry *parent, size_t *value);

予想通り、この関数はsize_t型の変数を表すdebugfsファイルを作成します。

同様に、unsigned long型の変数を10進数および16進数で処理する補助関数があります。

struct dentry *debugfs_create_ulong(const char *name, umode_t mode,
                                    struct dentry *parent,
                                    unsigned long *value);
void debugfs_create_xul(const char *name, umode_t mode,
                        struct dentry *parent, unsigned long *value);

ブール値は以下の関数を使用してdebugfsに配置できます。

struct dentry *debugfs_create_bool(const char *name, umode_t mode,
                                   struct dentry *parent, bool *value);

結果のファイルを読み込むと、非ゼロ値に対してY（Yes）またはN（No）が表示され、改行されます。書き込み時には大文字または小文字、または1と0を受付します。それ以外の入力は無視されます。

また、atomic_t型の値は以下の関数を使用してdebugfsに配置できます。

void debugfs_create_atomic_t(const char *name, umode_t mode,
                             struct dentry *parent, atomic_t *value)

このファイルの読み込みはatomic_t型の値を取得し、書き込みはatomic_t型の値を設定します。

別のオプションとして、任意のバイナリデータブロックを以下の構造体と関数でエクスポートできます。

struct debugfs_blob_wrapper {
    void *data;
    unsigned long size;
};

struct dentry *debugfs_create_blob(const char *name, umode_t mode,
                                   struct dentry *parent,
                                   struct debugfs_blob_wrapper *blob);

このファイルの読み込みはdebugfs_blob_wrapper構造体で指されるデータを返します。一部のドライバでは、「blobs」を静的なフォーマットテキスト出力の複数行を返す簡単な方法として使用しています。この関数はバイナリ情報をエクスポートできますが、メインラインにはこのようなコードが見られません。注意点として、以下の関数で作成されたすべてのファイルは読み取り専用です。 debugfs_create_blob() は読み取り専用です。

レジスタブロックをダンプしたい場合（開発中に頻繁に発生しますが、メインラインに到達するコードは少ないです）、debugfsは2つの関数を提供しています：1つはレジスタのみのファイルを作成し、もう1つは他の連続ファイルの中間にあるレジスタブロックを挿入します。

struct debugfs_reg32 {
    char *name;
    unsigned long offset;
};

struct debugfs_regset32 {
    const struct debugfs_reg32 *regs;
    int nregs;
    void __iomem *base;
    struct device *dev;     /* Optional device for Runtime PM */
};

debugfs_create_regset32(const char *name, umode_t mode,
                        struct dentry *parent,
                        struct debugfs_regset32 *regset);

void debugfs_print_regs32(struct seq_file *s, const struct debugfs_reg32 *regs,
                     int nregs, void __iomem *base, char *prefix);

「base」引数は0でもよいですが、reg32配列は__stringifyを使用して構築することを検討してください。複数のレジスタ名（マクロ）は実際にはレジスタブロックに対するベースからのバイトオフセットとして機能します。

debugfsにu32配列をダンプしたい場合は、以下の関数を使用してファイルを作成できます。

struct debugfs_u32_array {
    u32 *array;
    u32 n_elements;
};

void debugfs_create_u32_array(const char *name, umode_t mode,
                    struct dentry *parent,
                    struct debugfs_u32_array *array);

「array」引数は、配列のデータへのポインタと要素数をラップしています。注意: 配列が作成されると、そのサイズは変更できません。

デバイス関連の seq_file を作成するためのヘルパ関数があります:

void debugfs_create_devm_seqfile(struct device *dev,
                             const char *name,
                             struct dentry *parent,
                             int (*read_fn)(struct seq_file *s,
                                     void *data));

「dev」引数は、この debugfs ファイルに関連するデバイスであり、「read_fn」は seq_file の内容を印刷するために呼び出される関数ポインタです。

いくつかのディレクトリ関連のヘルパ関数もあります:

struct dentry *debugfs_rename(struct dentry *old_dir,
                              struct dentry *old_dentry,
                              struct dentry *new_dir,
                              const char *new_name);

struct dentry *debugfs_create_symlink(const char *name,
                                      struct dentry *parent,
                                      const char *target);

呼び出しを行うことで debugfs_rename() 既存の debugfs ファイルに新しい名前を付与し、別のディレクトリに配置することも可能です。new_name は呼び出し前の時点で存在してはいけません。返却値は、更新された情報を持つ old_dentry です。シンボリックリンクは debugfs_create_symlink().

すべての debugfs ユーザーが考慮すべき重要な点があります: debugfs で作成されたディレクトリの自動クリーンアップはありません。モジュールが明示的に debugfs エントリを削除せずにロード解除されると、多数の古くなったポインタと、非常に不適切な行動が発生します。したがって、すべての debugfs ユーザー - 少なくともモジュールとしてビルド可能なユーザーを含む - は、作成したすべてのファイルとディレクトリを削除する準備をしなければなりません。ファイルは以下のコマンドで削除可能です:

void debugfs_remove(struct dentry *dentry);

dentry の値は NULL またはエラー値であってもよいですが、その場合何も削除されません。

かつては debugfs ユーザーは、作成したすべての debugfs ファイルの dentry ポインタを覚える必要がありました。すべてのファイルをクリーンアップするためです。しかし現在はより文明的な時代に生きているため、debugfs ユーザーは以下の関数を呼び出すことができます:

void debugfs_remove_recursive(struct dentry *dentry);

この関数にトップレベルのディレクトリに対応する dentry ポインタを渡すと、そのディレクトリ以下のすべての階層が削除されます。
