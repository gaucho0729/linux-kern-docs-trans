enum positive_aop_returns¶

特定のセマンティクスを持つAOPリターンコード

定数

AOP_WRITEPAGE_ACTIVATE

ページの書き戻し処理が完了し、ページがまだロックされており、アクティブとみなされるべきであることを通知します。VMはこのヒントを使用してページをアクティブリストに戻すため、近い将来の書き戻し候補にはなりません。他の呼び出し元は、このリターンを取得した場合、ページをアンロックする必要があります。writepage(); によって返されます。

AOP_TRUNCATED_PAGE

ロックされたページを処理したAOPメソッドがページをアンロックし、ページが切り捨てられた可能性があります。呼び出し元は新しいページを取得して再試行する必要があります。AOPはライブロックを避けるための適切な対策を講じます。呼び出し元がページ参照を保持していた場合、再試行前にそれを解放する必要があります。readpage() によって返されます。

説明

address_space_operation 関数が呼び出し元に特別なセマンティクスを示すためにこれらの大きな定数を返します。これらはページ内のバイト数よりもはるかに大きく、ページごとの操作されたバイト数を返す関数に適しています。

struct address_space¶

キャッシュ可能でマッピング可能なオブジェクトの内容。

定義

struct address_space {
  struct inode            *host;
  struct xarray           i_pages;
  gfp_t gfp_mask;
  atomic_t i_mmap_writable;
#ifdef CONFIG_READ_ONLY_THP_FOR_FS;
  atomic_t nr_thps;
#endif;
  struct rb_root_cached   i_mmap;
  struct rw_semaphore     i_mmap_rwsem;
  unsigned long           nrpages;
  unsigned long           nrexceptional;
  pgoff_t writeback_index;
  const struct address_space_operations *a_ops;
  unsigned long           flags;
  errseq_t wb_err;
  spinlock_t private_lock;
  struct list_head        private_list;
  void *private_data;
  ANDROID_KABI_RESERVE(1);
  ANDROID_KABI_RESERVE(2);
  ANDROID_KABI_RESERVE(3);
  ANDROID_KABI_RESERVE(4);
};

void sb_start_write(struct super_block *sb)¶

スーパーブロックへの書き込みアクセスを取得する

パラメータ

struct super_block *sb

書き込むスーパーブロック

説明

プロセスがファイルシステムにデータまたはメタデータを書き込む（つまり、ページまたはインノードを汚染する）場合、操作をペアに埋め込む必要があります。 sb_start_write() - sb_end_write() ファイルシステムのフリーズに対する排他を取得するため。この関数はフリーズを防ぐライターカウントをインクリメントします。ファイルシステムがすでにフリーズされている場合、関数はその凍結が解かれるのを待機します。

フリーズ保護はロックとして動作するため、ユーザーはフリーズ保護とその他のファイルシステムロックの順序を維持する必要があります。通常、フリーズ保護は最も外側のロックになります。特に、以下の順序があります：

sb_start_write

-> i_mutex（書き込みパス、truncate、ディレクトリ操作、…）-> s_umount（freeze_super、thaw_super）

void wbc_detach_inode(struct writeback_control *wbc)¶

wbcをinodeから分離し、外国の検出を行います。

パラメータ

struct writeback_control *wbc

完了した書き戻しのwriteback_control

説明

inodeの書き戻し試行が完了した後、この関数を呼び出します。 wbc_attach_and_unlock_inode()任意のコンテキストで呼び出すことができます。

inodeの同時書き込み共有は非常にまれと予想されるため、memcgは最初の使用に基づいてページ所有権を追跡するだけで、その共有の有用性を大幅に制限しています。そのため、cgroup writebackはinodeごとに所有権を追跡します。inodeの同時書き込み共有のサポートは必要ないとされていますが、異なるcgroupが時間とともにinodeを書き込むことは非常に一般的です。さらに重要なのは、最初の使用に基づく課金は、誤った挙動を引き起こす可能性があるため（単一の外国ページがギガバイト単位のwritebackを誤って割り当てることも）、正確な処理が求められます。

この問題を解決するため、cgroup writebackはinodeの大多数の汚染度を検出し、所有権をそのinodeに移します。不必要な振動を避けるため、検出メカニズムは履歴を記録し、外国使用パターンが一定時間以上安定している場合にのみ、切り替えの判断を行います。

各writeback実行時に wbc Boyer-Moore多数決アルゴリズムを使用して、大多数のライターを検出します。多数決によるバイト数に加えて、現在のwbでの書き込みバイト数と、前回の勝者wbの書き込みバイト数（前回の現在のwbと、2回前の勝者、および前回の多数決候補の最大値）もカウントします。履歴の勝者を記録することで、絶対多数ではない場合でも、最もアクティブなライターを半信頼的に検出できます。

ラウンドの勝者が決定されると、その勝者が外国かどうか、およびラウンドで消費されたIO時間はinode->i_wb_frn_historyに記録されます。記録された外国IO時間がしきい値を超える場合、切り替えの判断が行われます。
