autofs - その動作方法¶

目的¶

autofs の目的は、さまざまなその他のファイルシステムのオンデマンドでのマウントと競合を避けて自動的にアンマウントすることです。これにより、以下の2つの主要な利点が得られます:

  1. 必要なファイルシステムがすべてマウントされるのを待つ必要はありません。遅延するファイルシステムにアクセスしようとするプロセスは遅延するかもしれませんが、他のプロセスは自由に実行できます。これは特にネットワークファイルシステム（例: NFS）やメディア変更ロボットで保存されたファイルシステムにおいて重要です。

  2. ファイルシステムの名前や場所はリモートデータベースに保存され、いつでも変更可能です。アクセス時のデータベースの内容がアクセス先のターゲットを提供します。ファイルシステム内の名前の解釈はデータベースに依存せず、プログラム的に実行することも可能で、ワイルドカードなどの機能を許可し、最初に名前をアクセスしたユーザーによって変化することもあります。

コンテキスト¶

「autofs」ファイルシステムモジュールは、autofs システムの一部にすぎません。ユーザースペースのプログラムも必要で、名前を検索してファイルシステムをマウントします。これは通常「automount」プログラムですが、他のツール（例: systemd）も「autofs」を使用できます。このドキュメントでは、カーネルモジュールとユーザースペースプログラムとの相互作用についてのみ説明します。以降のテキストではこれを「automount デーモン」または単に「デーモン」と呼びます。

「autofs」は Linux カーネルモジュールで、「autofs」ファイルシステムタイプを提供します。複数の「autofs」ファイルシステムをマウントでき、それぞれを個別に管理するか、同じデーモンで一括して管理できます。

マウントトラップ¶

autofsの実装の核心要素は、Linux VFSが提供するマウントトラップです。ファイルシステムによって提供される任意のディレクトリをトラップと指定できます。これは、autofsが役割を果たすために協働する2つの別個の機能を含みます。

DCACHE_NEED_AUTOMOUNT

dentryがDCACHE_NEED_AUTOMOUNTフラグを設定している場合（inodeがS_AUTOMOUNTを設定しているか、または直接設定可能）、それは（潜在的に）マウントトラップです。このディレクトリへのアクセスが「stat」を超えた場合、通常は d_op->d_automount() dentry操作が呼び出されます。このメソッドの役割は、ディレクトリにマウントすべきファイルシステムを検索し、それを返すことです。実際にこのファイルシステムのルートをディレクトリにマウントするのはVFSの責任です。

autofsはファイルシステム自体を検索しませんが、automountデーモンにメッセージを送り、それを検索してマウントするよう依頼します。autofsの d_automount メソッドは、デーモンがすべて準備完了を報告するのを待ってから、その後「NULL」を返します。これはマウントがすでに実行されたことを示します。VFSは何もマウントしませんが、すでに存在するマウントを辿ります。

この機能は、NFSなどのマウントトラップの一部のユーザーには十分ですが、autofsには不十分です。ディレクトリへのマウントが「 stat」を超えたとみなされるため、automountデーモンはトラップディレクトリにファイルシステムをマウントすることができません。そのために別のフラグがあります。

マウントポイントの有効期限切れ¶

VFSは、使用されていないマウントを自動的に期限切れさせるメカニズムを持っています。これは、dentry情報のdcacheから使用されていない情報を期限切れさせるのと同様です。これはMNT_SHRINKABLEフラグによって制御されます。この機能は、 d_automount()で作成されたマウントにのみ適用されます。 autofsはこのようなファイルシステムを返しませんが、自動マウントデーモンにマウントを依頼するため、デーモンにもアンマウントを関与させる必要があります。これにより、autofsは期限切れの制御により多くの権限を持ちます。

VFSは、 umount システムコールのMNT_EXPIREフラグを使用してマウントの期限切れをサポートしています。MNT_EXPIREでアンマウントを行うには、以前の試行が行われ、それ以降にファイルシステムがアクティブでなかったことが条件です。autofsはこの機能に依存せず、ファイルシステムが最近使用されたかを内部的に追跡しています。これにより、autofsディレクトリ内の個々の名前が別々に期限切れできます。

プロトコルバージョン4では、自動マウントデーモンがautofsファイルシステムにマウントされたファイルシステムをアンマウントしたり、シンボリックリンクや空のディレクトリをいつでも削除したりできます。アンマウントや削除が成功した場合、ファイルシステムはマウントまたは作成前の状態に戻されるため、名前のアクセスは通常の自動マウント処理をトリガーします。特に、 rmdir および unlink は、通常のファイルシステムが負のエントリをdcacheに残すのとは異なり、最近削除されたオブジェクトへのアクセスはautofsに処理を委譲します。

バージョン5では、トップレベルのディレクトリからアンマウントする場合を除き、これは安全ではありません。下位ディレクトリは常にマウントトラップではないため、ファイルシステムがアンマウントされると、他のプロセスはすぐに空のディレクトリを確認します。したがって、一般的には下記に記載するautofsの期限切れプロトコルを使用するのが最も安全です。

通常、デーモンは長時間使用されていないエントリのみを削除したいです。この目的でautofsは各ディレクトリまたはシンボリックリンクに「last_used」というタイムスタンプを保持します。シンボリックリンクの場合、実際にリンクが「使用」された最後の時間（リンクをたどって先の場所を確認した時間）を記録します。ディレクトリの場合、このフィールドはやや異なる方法で使用されます。マウント時に更新され、期限切れチェック時に使用中であることが確認された場合（つまりオープンしているファイルディスクリプタやプロセスのワーキングディレクトリ）やパスウォーク中に更新されます。パスウォーク時の更新は、頻繁にアクセスされる自動マウントの頻繁な期限切れと即時マウントを防ぎます。ただし、GUIが継続的にアクセスするか、アプリケーションが自動マウントディレクトリツリーを頻繁にスキャンする場合、実際に使用されていないマウントが蓄積する可能性があります。このようなケースを考慮するため、「strictexpire」というautofsのマウントオプションを使用して、「last_used”の更新をパスウォーク時に実行しないようにすることで、実際に使用されていないマウントの期限切れが防がれるようにします。

デーモンは、後述する「 ioctl 」を使用して、期限切れが発生する項目をautofsに尋ねることができます。マウントの場合、autofsはマウントツリー全体をアンマウントできるかどうかを検討します。マウントの場合、autofsはトップレベルディレクトリ内の各名前を検討し、それらのどれかがアンマウントおよびクリーンアップ可能かどうかを判断します。 direct mount 間接的 mount

間接マウントには、トップレベルの名前ではなく、実際にマウントされた葉（leaf）を検討するオプションがあります。これは当初、autofsバージョン4との互換性のために設計されたもので、Sun Formatの自動マウントマップでは非推奨とされています。ただし、amd形式のマウントマップ（一般的に間接マップ）では、amd自動マウントが個々のマウントに期限切れタイムアウトを設定できるため、このオプションは再利用可能です。ただし、必要な変更を実施するにはいくつかの困難があります。

autofsがディレクトリを検討する際には、 last_used 時間とマウント時に設定された「timeout」値を比較します（ただし、一部のケースではこのチェックは無視されます）。また、ディレクトリまたはその下にある項目が使用中かどうかを確認します。シンボリックリンクの場合、のみ「 last_used 時間のみが考慮されます。

ディレクトリまたはシンボリックリンクの期限切れをサポートしているように見える場合、アクションが実行されます。

autofsに期限切れを検討させる方法は2通りあります。1つ目の方法は、 AUTOFS_IOC_EXPIRE ioctlを使用することです。これは間接的なマウントにのみ有効です。ルートディレクトリに期限切れ対象の項目が存在する場合、その項目の名前を返します。名前が返された後、オートマウントデーモンはその名前の下にマウントされているファイルシステムを通常通りアンマウントする必要があります。上記のように、バージョン5のautofsでは非トップレベルのマウントには不安全です。そのため、現在の automount(8) はこのioctlを使用していません。

2つ目のメカニズムは、 AUTOFS_DEV_IOCTL_EXPIRE_CMD …または…、 AUTOFS_IOC_EXPIRE_MULTI ioctlを使用します。これは直接マウントおよび間接マウントの両方に有効です。オブジェクトを選択して期限切れさせる場合、以下の通知メカニズムを使用してデーモンに通知します。この操作はデーモンが期限切れ通知を確認するまでブロックされます。これにより、「EXPIRE」ioctlは通知処理を担当するスレッドとは異なるスレッドから送信する必要があります。

ioctlがブロックしている間、エントリは「期限切れ中」とマークされ、 d_manage デーモンがアンマウント完了を確認するまで（必要に応じて作成されたディレクトリを削除するなど）または中断されるまでブロックされます。

autofsとの通信：デーモンの検出¶

オートマウントデーモンとファイルシステム間の通信方法はいくつかあります。すでに確認したように、デーモンは通常のファイルシステム操作を使用してディレクトリやシンボリックリンクを作成・削除できます。autofsはプロセスグループID番号（getpgid(1)を参照）を確認して、操作を要求しているプロセスがデーモンかどうかを判断します。

autofsファイルシステムがマウントされる際、マウントプロセスのpgidが記録されます。ただし、「pgrp=」オプションが指定されている場合はその数値が記録されます。そのプロセスグループ内のプロセスが送信したリクエストはすべてデーモンからのものとみなされます。デーモンが停止・再起動が必要な場合、以下の説明で示すioctlを通じて新しいpgidを指定できます。

autofsファイルシステムがマウントされる際、'fd='マウントオプションでパイプの'書き込み'端を渡す必要があります。autofsはこのパイプに通知メッセージを書き込み、デーモンが応答します。バージョン5ではメッセージの形式は以下の通りです：

    現在使用中のプロトコルバージョンを返します。

    これは AUTOFS_IOC_EXPIRE ただし、デーモンに通知を送信し、デーモンが応答するまでブロックします。引数は2つの異なるフラグを含む整数です。

    AUTOFS_EXP_IMMEDIATE がその値に下がります。ただし、 last_used 時間は無視され、使用されていないオブジェクトが期限切れします。

    AUTOFS_EXP_FORCED 使用中の状態を無視し、使用中のオブジェクトも期限切れとみなされます。これは、デーモンがこの動作を要求していることを想定しており、umountを実行できることが前提です。

    AUTOFS_EXP_LEAVES 期限切れの対象として葉（leaf）を選択する代わりに、トップレベルの名前を選択します。これは、以下の条件が満たされている場合にのみ安全です maxproto は4です。

autofsとの通信: キャラクタデバイスioctl¶

autofsファイルシステムのルートを開くことは常に可能ではありません、特に direct マウントされたファイルシステムの場合です。自動マウントデーモンが再起動された場合、上記の通信チャネルのいずれも使って既存のマウントを再取得する方法がありません。このニーズに対応するため、"miscellaneous"（雑多）キャラクタデバイス（メジャーデバイス番号10、マイナーデバイス番号235）が利用可能です。このデバイスを使用してautofsファイルシステムと直接通信できますが、アクセスにはCAP_SYS_ADMINが必要です。

このデバイスで使用可能なioctlは、別途ドキュメントで説明されています autofs-mount-control.txt、ここでは簡潔にまとめます。各ioctlは、 autofs_dev_ioctl フィールドはRCU読み込み側クリティカルセクションのネストレベルを記録し、

struct autofs_dev_ioctl {
        __u32 ver_major;
        __u32 ver_minor;
        __u32 size;             /* total size of data passed in
                                 * including this struct */
        __s32 ioctlfd;          /* automount command fd */

        /* Command parameters */
        union {
                struct args_protover            protover;
                struct args_protosubver         protosubver;
                struct args_openmount           openmount;
                struct args_ready               ready;
                struct args_fail                fail;
                struct args_setpipefd           setpipefd;
                struct args_timeout             timeout;
                struct args_requester           requester;
                struct args_expire              expire;
                struct args_askumount           askumount;
                struct args_ismountpoint        ismountpoint;
        };

        char path[0];
};

のポインタを渡します。 OPEN_MOUNT および IS_MOUNTPOINT コマンドでは、ターゲットファイルシステムは パスで識別されます。他のコマンドでは、ファイルシステムは ioctlfd という、ルートに開かれたファイルディスクリプタで識別され、これは OPEN_MOUNT.

以下の ver_major および ver_minor は入出力パラメータで、要求されたバージョンがサポートされているかを確認し、カーネルモジュールがサポートできる最大バージョンを報告します。

コマンドは次の通りです:

  • AUTOFS_DEV_IOCTL_VERSION_CMD:

    バージョン番号を検証し、設定する以外には何もしません。

  • AUTOFS_DEV_IOCTL_OPENMOUNT_CMD:

    autofsファイルシステムのルートにオープンしたファイルディスクリプタを返します。ファイルシステムは名前とデバイス番号で識別され、これは openmount.devidに保存されています。既存のファイルシステムのデバイス番号は /proc/self/mountinfo.

  • AUTOFS_DEV_IOCTL_CLOSEMOUNT_CMD:

    同じく close(ioctlfd).

  • AUTOFS_DEV_IOCTL_SETPIPEFD_CMD:

    ファイルシステムがcatatonicモードにある場合、このコマンドは新しいパイプの書き込み端を setpipefd.pipefd で提供し、デーモンとの通信を再確立できます。呼び出しプロセスのプロセスグループがデーモンを識別します。

  • AUTOFS_DEV_IOCTL_REQUESTER_CMD:

    パス は、自動マウントされたファイルシステム内の名前でなければなりません。成功した場合、 requester.uid および requester.gid は、そのマウントをトリガーしたプロセスのUIDとGIDになります。

  • AUTOFS_DEV_IOCTL_ISMOUNTPOINT_CMD:

    pathが特定のタイプのマウントポイントであるかを確認します - 詳細は別途ドキュメントを参照してください。

  • AUTOFS_DEV_IOCTL_PROTOVER_CMD

  • AUTOFS_DEV_IOCTL_PROTOSUBVER_CMD

  • AUTOFS_DEV_IOCTL_READY_CMD

  • AUTOFS_DEV_IOCTL_FAIL_CMD

  • AUTOFS_DEV_IOCTL_CATATONIC_CMD

  • AUTOFS_DEV_IOCTL_TIMEOUT_CMD

  • AUTOFS_DEV_IOCTL_EXPIRE_CMD

  • AUTOFS_DEV_IOCTL_ASKUMOUNT_CMD

これらは同様に名付けられた AUTOFS_IOC ioctlコマンドと同様の機能を持ちますが、 FAIL は fail.status で明示的なエラー番号を指定できるため、 ENOENTを仮定するのではなく、この EXPIRE コマンドは AUTOFS_IOC_EXPIRE_MULTI.

猫の状態¶

自動マウントが「猫の状態」モードに入る場合があります。これは通知パイプへの書き込みが失敗した場合、または ioctl.

が明示的に要求した場合に発生します。猫の状態モードに入った際、パイプは閉じられ、未処理の通知はエラーで承認されます。 ENOENT.

猫の状態モードに入った後、存在しない名前へのアクセスは ENOENT を返しますが、既存のディレクトリへのアクセスはデーモンからのアクセスと同様に処理されるため、マウントトラップは発生しません。

ファイルシステムがマウントされている場合、_uid_ と _gid_ を指定してディレクトリやシンボリックリンクの所有権を設定できます。猫の状態モードでは、UIDが一致するプロセスはルートディレクトリにディレクトリやシンボリックリンクを作成できますが、他のディレクトリには作成できません。

猫の状態モードを脱出するには、 AUTOFS_DEV_IOCTL_OPENMOUNT_CMD ioctlを /dev/autofs.

の「ignore」マウントオプション¶

「ignore」マウントオプションは、アプリケーションにマウントエントリを表示する際には無視すべきであることを一般的なインジケーターとして提供します。

他のオペレーティングシステムで自動マウントを提供し、カーネルのマウントリストに基づいてユーザー空間にマウントリストを提供する場合、無効なマウントオプション（「ignore」は最も一般的なOSで使用されるオプション）が許可されており、自動マウントファイルシステムのユーザーがオプション的に使用できます。

これはユーザー空間のプログラムがマウントリストを読み込む際、自動マウントを考慮から除外するために意図的に使用されるものです。

autofs、名前空間、共有マウント¶

バインドマウントと名前空間を使用すると、自動マウントファイルシステムが1つ以上のファイルシステム名前空間内の複数の場所に表示されることがあります。この機能を正しく動作させるには、自動マウントファイルシステムは常に「共有」でマウントされるべきです。例:

mount --make-shared /autofs/mount/point

自動マウントデーモンは自動マウントファイルシステムに対して1つのマウント場所のみを管理でき、そのマウント場所が「共有」でない場合、他の場所は予期しない動作をします。特に、その他の場所へのアクセスは、 ELOOP error
