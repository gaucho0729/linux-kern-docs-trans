2.5.0以降の変更点:¶

—

推奨

新しいヘルパ関数: sb_bread(), sb_getblk(), sb_find_get_block(), set_bh(), sb_set_blocksize() および sb_min_blocksize()。

これらを使用してください。

sb_find_get_block() は 2.4 の get_hash_table() を置き換えます

—

推奨

新しいメソッド: ->alloc_inode() および ->destroy_inode()。

inode->u.foo_inode_i を削除してください

宣言:

struct foo_inode_info {
        /* fs-private stuff */
        struct inode vfs_inode;
};
static inline struct foo_inode_info *FOO_I(struct inode *inode)
{
        return list_entry(inode, struct foo_inode_info, vfs_inode);
}

inode->u.foo_inode_i ではなく FOO_I(inode) を使用してください

foo_alloc_inode() および foo_destroy_inode() を追加してください。前者は foo_inode_info を割り当てて ->vfs_inode のアドレスを返し、後者は FOO_I(inode) を解放する必要があります（インラインファイルシステムの例を参照してください）。

これらを super_operations の ->alloc_inode および ->destroy_inode として実装してください。

プライベートデータの明示的な初期化が必要です。通常、呼び出しとinodeのロック解除の間に実行してください。 iget_locked() およびロック解除の間に実行してください。

いつかは必須になります。

必須

file_system_type メソッドの変更 (->read_super から ->get_sb へ)

->read_super() は廃止されました。DECLARE_FSTYPE および DECLARE_FSTYPE_DEV も同様です。

foo_read_super() を、成功時に0を、エラー時に負数を返す関数に変更してください（-EINVAL 以外のより詳細なエラーコードも可）。これを foo_fill_super() と名付けてください。現在宣言:

int foo_get_sb(struct file_system_type *fs_type,
      int flags, const char *dev_name, void *data, struct vfsmount *mnt)
{
      return get_sb_bdev(fs_type, flags, dev_name, data, foo_fill_super,
                         mnt);
}

(s/bdev/nodev/ または s/bdev/single/ に応じて、類似の構文を使用してください）。

DECLARE_FSTYPE… を明示的な初期化に置き換え、->get_sb を foo_get_sb として設定してください。

必須

ロックの変更: ->s_vfs_rename_sem はクロスディレクトリのrename操作のみで使用されます。ほとんどの場合変更不要ですが、内部処理でグローバルな排他が必要だった場合は内部ロックを変更する必要があります。それ以外の排他保証は変わりません（つまり、親ディレクトリと被害ディレクトリがロックされるなど）。

新しいsuper_blockフィールド struct export_operations *s_export_op エクスポートの明示的なサポート（例: NFS経由）のために用意されています。構造はinclude/linux/fs.hでの宣言と、 ファイルシステムのエクスポート.

簡潔に説明すると、decode_fhとencode_fhの操作を定義し、ファイルハンドルのエンコード・デコードを可能にし、ファイルシステムがdecode_fh用の標準ヘルパ関数を使用し、このヘルパにファイルシステム固有のサポートを提供できるようにします（特にget_parent）。

コードが少し落ち着いたら、これはエクスポートに必要になる予定です。

必須

s_export_opはファイルシステムのエクスポートに現在必要です。isofs、ext2、ext3、resierfs、fatは非常に異なるファイルシステムの例です。

必須

iget4()とread_inode2コールバックは、iget5_locked()によって置き換えられました。以下がプロトタイプです:

struct inode *iget5_locked(struct super_block *sb, unsigned long ino,
                            int (*test)(struct inode *, void *),
                            int (*set)(struct inode *, void *),
                            void *data);

「test」はinode番号だけでは実際のファイルオブジェクトを特定できない場合に使用できる追加関数です。「set」は非ブロッキング関数で、新規に作成されたinodeの一部を初期化し、「test」関数が成功するようにします。「data」は「test」および「set」関数にオパケな値として渡されます。

inodeがiget5_locked()で作成された場合、I_NEWフラグが設定され、依然としてロックされています。ファイルシステムはこの初期化を完了する必要があります。inodeが初期化されると、unlock_new_inode()を呼び出してロックを解除しなければなりません。

ファイルシステムは適切なタイミングでi_inoを設定（およびテスト）する責任があります。また、superblockとinode番号を引数として受け取るだけのシンプルなiget_locked関数もあります。この関数はテストと設定を自動で行います。

e.g.:

inode = iget_locked(sb, ino);
if (inode->i_state & I_NEW) {
        err = read_inode_from_disk(inode);
        if (err < 0) {
                iget_failed(inode);
                return err;
        }
        unlock_new_inode(inode);
}

新しいinodeの設定プロセスが失敗した場合、注意してください。 iget_failed() inodeを無効化するように呼び出され、適切なエラーが呼び出し元に返される必要があります。

->getattr()が最後に使用されるようになりました。nfs、minixなどでの実例を参照してください。

必須

->revalidate()は廃止されました。ファイルシステムでこの機能を使用していた場合は、->getattr()を提供し、それを呼び出すようにしてください。シンボリックリンクで->revalidate()を使用していた場合は、->follow_link()/->readlink()に呼び出しを追加してください。

必須

->d_parentの変更はもはやBKLによって保護されません。以下のいずれかが真であれば読み取りアクセスは安全です：

  • ファイルシステムにクロスディレクトリのrename()がありません

  • 親がロックされていたことがわかっています（例：->lookup()引数の->d_parentを参照しています）。

  • ->rename()から呼び出されている場合

  • 子の->d_lockが保持されています

コードを検証し、必要な場合はロックを追加してください。上記の条件で保護されていない場所は、古いツリーでもリスクがあります。古いツリーではBKLに依存しており、これは誤動作を引き起こす可能性があります。古いツリーにはそのような保護されていない->d_parentへのアクセスがいくつかあり、オプスから静かなメモリ破壊までさまざまな問題を引き起こす可能性があります。

->truncateは削除されました。truncateのシーケンス全体は->setattr内で実装する必要があります。これは、ディスク上のサイズ変更を実装するファイルシステムでは必須です。まず、古いinode_setattrとvmtruncateのコピーから始め、vmtruncate + foofs_vmtruncateのシーケンスをゼロブロックの使用にかかわるblock_truncate_pageや類似のヘルパ関数の順序に再配置します。サイズの更新と、最終的なディスク上のtruncate処理が失敗しないようにします。setattr_prepare（以前はinode_change_okだった）は今ではATTR_SIZEのサイズチェックを含み、->setattrの開始時に無条件で呼び出す必要があります。

必須

->clear_inode()と->delete_inode()は削除されました。代わりに->evict_inode()を使用する必要があります。この関数は、inodeがevictされるたびに呼び出されます。リンクが残っているかどうかに関わらず呼び出されます。呼び出し元は ではありません ページキャッシュやinode関連のメタデータバッファをevictする必要があります。このメソッドは truncate_inode_pages_final() それらを除去するために使用する必要があります。呼び出し元は、->evict_inode()が呼ばれる際やその後に、アシンクロナスなwritebackがinodeに対して実行されていないことを保証します。

->drop_inode()は今ではintを返すようになりました。これは最終 iput() inode->i_lockが保持されている状態で呼び出され、ファイルシステムがinodeをdropする希望があるかどうかをtrueで返します。以前と同様に、generic_drop_inode()がデフォルトであり、適切に更新されています。generic_delete_inode()も存在し、これは単にreturn 1です。注意点として、すべての実際のevict作業は->drop_inode()が返る後で呼び出し元が行います。

以前と同様に、->evict_inode()の各呼び出しに対してclear_inode()は正確に1回呼び出される必要があります（以前は->delete_inode()の各呼び出しに対して同様でした）。以前とは異なり、inode関連のメタデータバッファ（つまりmark_buffer_dirty_inode()を使用している場合）を使用している場合は、clear_inode()を呼び出す前にinvalidate_inode_buffers()を呼び出す責任があります。

注意: ->write_inode()の開始時にi_nlinkをチェックし、ゼロであれば処理を中断するというのは および 更新処理が完了した後でも新しい読者が即座に開始する可能性があるため、以下のコードは読者がいないと信頼してはならない。 すでに 十分ではありません。最終的なunlink()と は、inodeが->write_inode()の途中で行われる可能性があります。たとえば、ディスク上のinodeを盲目的に解放してしまうと、->write_inode()がそれを書き込んでいる最中にその処理が行われる可能性があります。 iput() 今では、dcacheに未参照のdentryをキャッシュするかどうかをアドバイスするものに限定され、dentryのrefcountがゼロになるときにのみ呼び出されます。refcountがゼロに遷移しても、0回、1回、または複数回呼び出されることが許容される必要があります（例: 定数、恒等関数）。

推奨

vfsは現在、「rcu-walkモード」でパスウォークを試みています。これにより、dentryとinodeのアトミック操作とスケーラビリティの危険を回避します（参照 パスネーム検索）。d_hashとd_compareの変更（上記）は、この機能をサポートするために必要な変更の例です。より複雑なファイルシステムコールバックの場合、vfsはfs呼び出しの前に関数からrcu-walkモードを抜け出します。そのため、ファイルシステムに変更は必要ありません。ただし、これはコストが高く、rcu-walkモードのメリットを失います。ファイルシステムは、以下の例のようにrcu-walkモードを意識したコールバックを導入していきます。可能な限りこの機能を活用してください。

必須

d_revalidateは、ファイルシステムが提供する場合、パス要素ごとに呼び出されるコールバックです。これにはrcu-walkモードから抜け出す必要があります。これにより、rcu-walkモードで呼び出されることが可能になりました（nd->flags & LOOKUP_RCU）。ファイルシステムがrcu-walkを処理できない場合、-ECHILDを返してください。参照 Linux仮想ファイルシステムの概要 詳細についてはこちら。

permissionは、パスウォークの途中で多くのディレクトリinodeに対して呼び出されるinodeのパーミッションチェックです（実行権限の確認のため）。これには今後、rcu-walkモードを意識した処理が必要です（mask & MAY_NOT_BLOCK）。参照 Linux仮想ファイルシステムの概要 詳細についてはこちら。

  • →get_link()はRCUモードで呼び出される場合、NULLのdentryが渡されます

->iterate_shared() が追加されました。これは ->iterate() の並行実行バージョンです。struct file レベルでの排他は維持され（同 struct file での lseek との排他も）、ディレクトリが複数回開かれた場合、これらの関数が並行して呼ばれる可能性があります。もちろん、このメソッドとディレクトリ変更関数間の排他是維持されます。

->iterate() はすでに読み取り専用操作であるため、->iterate_shared() として使用できます。ただし、->iterate() が inode または dentry の内核データ構造を変更する場合、アクセスをシリアル化する必要があるかもしれません。dcache の事前種子付けを行っている場合は、d_alloc_parallel() に切り替える必要があります。内蔵コードの例を参照してください。

  • NULL ->destroy_inodeとNULL ->free_inodeの組み合わせはNULL/free_inode_nonrcuとして扱われ、互換性を維持します。

コールバック（->free_inode()経由であれ、明示的に call_rcu() ->destroy_inode()内では 禁止です スーパーブロック破壊に対する順序で実行されます。実際には、スーパーブロックおよび関連する構造体がすでに削除されている可能性があります。ファイルシステムドライバーは必ず存在しますが、それ以上の処理は推奨されません。コールバック内でメモリを解放するのは問題ありませんが、それ以上の処理は慎重に行い、できるだけ避けるべきです。
