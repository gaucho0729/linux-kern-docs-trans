24.8. ユーザー空間アプリケーションでFSとGSセグメントを使用する¶

x86アーキテクチャはセグメンテーションをサポートしています。メモリにアクセスする命令はセグメントレジスタベースのアドレッシングモードを使用できます。セグメント内のバイトアドレスを参照するための以下のような表記が使われます:

セグメントレジスタ:バイトアドレス

セグメントベースアドレスはバイトアドレスに加算され、結果となる仮想アドレスが計算されます。これにより、同一のバイトアドレス（つまり同じコード）で複数のデータインスタンスにアクセスできます。特定のインスタンスの選択は、セグメントレジスタ内のベースアドレスに完全に依存します。

32ビットモードではCPUが6つのセグメントを提供し、これらはセグメント制限もサポートします。制限はアドレス空間の保護を強制するために使用できます。

64ビットモードではCS/SS/DS/ESセグメントは無視され、ベースアドレスは常に0となりフルな64ビットアドレス空間を提供します。FSおよびGSセグメントは64ビットモードでも依然として機能します。

24.8.1. 一般的なFSおよびGSの使用¶

FSセグメントは通常、スレッドローカルストレージ（TLS）にアドレスを参照するために使用されます。FSは通常、ランタイムコードやスレッドライブラリによって管理されます。'__thread'ストレージクラス指定子で宣言された変数はスレッドごとにインスタンス化され、コンパイラはこれらの変数へのアクセスにFS:アドレスプレフィックスを生成します。各スレッドは独自のFSベースアドレスを持ち、複数スレッドのインスタンスにアクセスするための複雑なアドレスオフセット計算を省略して共通コードを使用できます。アプリケーションは、ランタイムやスレッドライブラリがスレッドごとのFSを管理している場合、FSを他の用途に使用すべきではありません。

GSセグメントは一般的な用途がなく、アプリケーションによって自由に使用できます。GCCおよびClangはアドレス空間識別子を介してGSベースのアドレッシングをサポートしています。

24.8.2. FS/GSベースアドレスの読み取りと書き込み¶

FS/GSベースアドレスを読み取る・書き込むためのメカニズムは以下の2つがあります:

  • arch_prctl()システムコール

  • FSGSBASE命令ファミリ

24.8.3. arch_prctl()によるFS/GSベースアドレスのアクセス¶

arch_prctl(2)ベースのメカニズムはすべての64ビットCPUおよびすべてのカーネルバージョンで利用可能です。

ベースアドレスの読み取り:

arch_prctl(ARCH_GET_FS, &fsbase); arch_prctl(ARCH_GET_GS, &gsbase);

ベースアドレスの書き込み:

arch_prctl(ARCH_SET_FS, fsbase); arch_prctl(ARCH_SET_GS, gsbase);

ARCH_SET_GS prctlはカーネル構成やセキュリティ設定により無効になる可能性があります。

24.8.4. FSGSBASE命令によるFS/GSベースアドレスのアクセス¶

Ivy Bridge CPU世代でインテルは、ユーザー空間からFSおよびGSベースレジスタを直接アクセスするための新しい命令セットを導入しました。これらの命令はAMD Family 17H CPUでもサポートされています。以下の命令が利用可能です:

RDFSBASE %reg

FSベースレジスタを読み込む

RDGSBASE %reg

GSベースレジスタを読み込む

WRFSBASE %reg

FSベースレジスタを書込む

WRGSBASE %3

GSベースレジスタを書込む

これらの命令はarch_prctl()システムコールのオーバーヘッドを回避し、ユーザー空間アプリケーションにおけるFS/GSアドレッシングモードの柔軟な使用を可能にします。これによりスレッドライブラリやランタイムがFSを用いて競合する問題は発生しますが、アプリケーションが自身の目的でFSを使用したい場合でも制限はありません。

24.8.4.1. FSGSBASE命令の有効化¶

これらの命令はCPUID レーフ7、EBXのビット0で列挙されます。利用可能な場合、/proc/cpuinfoはCPUのフラグエントリに'fsgsbase'を表示します。

命令の利用可能性は自動的に有効化されません。カーネルはCR4で明示的に有効化する必要があります。これは古いカーネルがGSレジスタの値について仮定を設けており、arch_prctl()経由でGSベースが設定される際にはその仮定を強制するためです。ユーザー空間がGSベースに任意の値を書込むことを許可すると、これらの仮定が破られることで不具合が発生する可能性があります。

FSGSBASEを有効にしていないカーネルでは、FSGSBASE命令の実行は#UD例外で失敗します。

カーネルはELF AUXベクターで有効状態の信頼できる情報を提供します。AUXベクターのHWCAP2_FSGSBASEビットが設定されている場合、カーネルはFSGSBASE命令を有効にしており、アプリケーションはそれらを使用できます。以下のコード例はこの検出方法を示しています:

#include <sys/auxv.h>
#include <elf.h>

/* Will be eventually in asm/hwcap.h */
#ifndef HWCAP2_FSGSBASE
#define HWCAP2_FSGSBASE        (1 << 1)
#endif

....

unsigned val = getauxval(AT_HWCAP2);

if (val & HWCAP2_FSGSBASE)
     printf("FSGSBASE enabled\n");

24.8.4.2. FSGSBASE命令コンパイラサポート¶

GCC 4.6.4以降はFSGSBASE命令用のイントリニクスを提供します。Clang 5もサポートしています。

_readfsbase_u64()

FSベースレジスタを読み込む

_readfsbase_u64()

GSベースレジスタを読み込む

_writefsbase_u64()

FSベースレジスタを書込む

_writegsbase_u64()

GSベースレジスタを書込む

これらのイントリニクスを使用するにはソースコードに<immintrin.h>を含め、コンパイラオプション-mfsgsbaseを追加する必要があります。

24.8.5. FS/GSベースアドレッシングのコンパイラサポート¶

GCC 6以降はNamed Address Spacesを介してFS/GSベースアドレッシングをサポートしています。GCCはx86で以下のアドレッシング空間識別子を実装しています:

__seg_fs

変数はFSベースでアドレッシングされる

__seg_gs

変数はGSベースでアドレッシングされる

これらのアドレッシング空間がサポートされている場合、プリプロセッサシンボル__SEG_FSと__SEG_GSが定義されます。フォールバックモードを実装するコードはこれらのシンボルが定義されているか確認する必要があります。使用例:

#ifdef __SEG_GS

long data0 = 0;
long data1 = 1;

long __seg_gs *ptr;

/* Check whether FSGSBASE is enabled by the kernel (HWCAP2_FSGSBASE) */
....

/* Set GS base to point to data0 */
_writegsbase_u64(&data0);

/* Access offset 0 of GS */
ptr = 0;
printf("data0 = %ld\n", *ptr);

/* Set GS base to point to data1 */
_writegsbase_u64(&data1);
/* ptr still addresses offset 0! */
printf("data1 = %ld\n", *ptr);

ClangはGCCのアドレス空間識別子を提供していませんが、Clang 2.6以降のバージョンでは属性ベースのメカニズムを用いてアドレス空間を提供しています:

__attribute__((address_space(256))

変数はGSベースでアドレッシングされる

__attribute__((address_space(257))

変数はFSベースでアドレッシングされる

24.8.6. FS/GSベースのアドレッシングとインラインアセンブリ¶

コンパイラがアドレス空間をサポートしない場合、インラインアセンブリを用いてFS/GSベースのアドレッシングモードを実装できます:

mov %fs:offset, %reg
mov %gs:offset, %reg

mov %reg, %fs:offset
mov %reg, %gs:offset
