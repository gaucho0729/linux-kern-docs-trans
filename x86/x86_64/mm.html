24.3. メモリ管理¶

24.3.1. 4段階ページテーブルを用いた完全な仮想メモリマップ¶

注意

  • 「-23 TB」などの負のアドレスは、64ビットアドレス空間の上から数えられるバイト単位の絶対アドレスです。絶対アドレスと上からの距離表現の両方で見たときにレイアウトが理解しやすくなります。

    たとえば0xffffe90000000000 == -23 TBは、64ビットアドレス空間の上からの23 TB下に位置します（ffffffffffffffff）。

    アドレス空間の上に近づくにつれて、表記はTBからGBへ、そしてMB/KBへと変わります。

  • 「16M TB」という表記は最初は不思議に感じるかもしれませんが、「16 EB」という表記より、64ビットアドレス空間がどれだけ巨大かを視覚的に理解しやすくなっています。16 EBは多くの人が最初に16エクサバイトと認識しないので、この表記法はより直感的です。

24.3.2. 5段階ページテーブルを用いた完全な仮想メモリマップ¶

注意

  • 56ビットアドレスでは、ユーザー空間メモリが512倍に拡張され、0.125 PBから64 PBに増えます。すべてのカーネルマッピングは-64 PBの開始オフセットにシフトし、多くの領域がより大きな物理メモリをサポートするよう拡張されます。

    Start addr    |   Offset   |     End addr     |  Size   | VM area description
========================================================================================================================
                  |            |                  |         |
 0000000000000000 |    0       | 00ffffffffffffff |   64 PB | user-space virtual memory, different per mm
__________________|____________|__________________|_________|___________________________________________________________
                  |            |                  |         |
 0100000000000000 |  +64    PB | feffffffffffffff | ~16K PB | ... huge, still almost 64 bits wide hole of non-canonical
                  |            |                  |         |     virtual memory addresses up to the -64 PB
                  |            |                  |         |     starting offset of kernel mappings.
__________________|____________|__________________|_________|___________________________________________________________
                                                            |
                                                            | Kernel-space virtual memory, shared between all processes:
____________________________________________________________|___________________________________________________________

 ff10000000000000 |  -60    PB | ff10ffffffffffff | 0.25 PB | LDT remap for PTI

                  |            |                  |         |

                  |            |                  |         | vaddr_end for KASLR

アーキテクチャは64ビット仮想アドレスを定義しています。実装ではこれより少ないビット数をサポートすることも可能です。現在サポートされているのは48ビットおよび57ビットの仮想アドレスです。ビット63から最も上位の実装ビットまでのビットは符号拡張されます。これにより、符号無しで解釈するとユーザー空間とカーネルアドレスの間に穴が生じます。

直接マッピングはシステム内のすべてのメモリを最高メモリアドレスまでカバーし（一部のケースではPCIメモリホールも含むことがあります）。

vmalloc領域は、ページフォールトハンドラを使用してプロセスのさまざまなPML4/PML5ページにラズリーに同期され、init_top_pgtを参照します。

EFIランタイムサービスは、64GBの大規模な仮想メモリウィンドウ内の「efi_pgd」PGDにマッピングされます（このサイズは任意で、必要に応じて後で増やすことができます）。これらのマッピングは他のカーネルPGDに含まれず、EFIランタイム呼び出し中にのみ利用可能です。

CONFIG_RANDOMIZE_MEMORYが有効な場合、すべての物理メモリの直接マッピング、vmalloc/ioremap領域、仮想メモリマップがランダム化されます。順序は保持されますが、起動時にベースアドレスが早めにオフセットされます。

ここを変更する際はKASLRとの衝突に注意してください。KASLRアドレス範囲はKASANシャドウ領域以外の何ものとも重なってはいけません。これはKASANがKASLRを無効にするため正しい設定です。

4段階および5段階のレイアウトにおいて、最後の2MBの穴におけるSTACKLEAK_POISON値: ffffffffffff4111
