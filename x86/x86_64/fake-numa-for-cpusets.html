24.5. Fake NUMA ためのCPUSets¶

著者

David Rientjes <rientjes@cs.washington.edu>

numa=fake と CPUSets を使用したリソース管理

このドキュメントでは、numa=fake x86_64 コマンドラインオプションを cpusets と組み合わせて使用し、粗いメモリ管理を行う方法について説明します。この機能を使用することで、連続したメモリのブロックを表す仮想 NUMA ノードを作成し、cpusets およびそのアタッチされたタスクに割り当てることができます。これにより、特定のタスククラスに利用可能なシステムメモリの量を制限できます。

cpusets の機能についての詳細情報は、 CPUSETSをご参照ください。あなたのニーズに応じて、さまざまな設定方法があります。numa=fake コマンドラインオプションと、仮想ノードを構成するさまざまな方法についての詳細情報は、 AMD64固有のブートオプション.

この導入の目的として、非常に基本的な NUMA エミュレーション設定「numa=fake=4*512」と仮定します。これにより、システムメモリが4つの512MBの等しいブロックに分割され、cpusets に割り当てることができます。この組み合わせをリソース制御で使い慣れるにつれて、扱う必要のあるノード数を最小限に抑えるためのより良い設定を決定できます。

dmesg によって報告されるように、「numa=fake=4*512」としてマシンは以下のように分割されます：

Faking node 0 at 0000000000000000-0000000020000000 (512MB)
Faking node 1 at 0000000020000000-0000000040000000 (512MB)
Faking node 2 at 0000000040000000-0000000060000000 (512MB)
Faking node 3 at 0000000060000000-0000000080000000 (512MB)
...
On node 0 totalpages: 130975
On node 1 totalpages: 131072
On node 2 totalpages: 131072
On node 3 totalpages: 131072

cpusets ファイルシステムのマウント手順に従って、 CPUSETS個々の cpusets に仮想ノード（つまり、連続したメモリアドレス空間）を割り当てることができます：

[root@xroads /]# mkdir exampleset
[root@xroads /]# mount -t cpuset none exampleset
[root@xroads /]# mkdir exampleset/ddset
[root@xroads /]# cd exampleset/ddset
[root@xroads /exampleset/ddset]# echo 0-1 > cpus
[root@xroads /exampleset/ddset]# echo 0-1 > mems

この cpuset、「ddset」は、メモリ割当に限っては仮想ノード 0 と 1 にのみアクセス可能になります（1G）。

これらの cpusets にタスクを割り当てることで、割り当てられたメモリノード（mems）に応じて、タスクに利用可能なメモリリソースを制限できます：

[root@xroads /exampleset/ddset]# echo $$ > tasks
[root@xroads /exampleset/ddset]# dd if=/dev/zero of=tmp bs=1024 count=1G
[1] 13425

/proc/meminfo で報告されるシステムメモリの使用量に注目してください。制限された cpuset のケースと制限なしのケース（つまり、fake NUMA cpuset に割り当てることなく同じ ‘dd’ コマンドを実行した場合）の違い：

名前

制限なし

制限

MemTotal

3091900 kB

3091900 kB

MemFree

42113 kB

1513236 kB

これにより、特定の cpusets に割り当てたタスクに対して粗いメモリ管理が可能になります。cpusets は階層構造を形成できるため、さまざまなタスククラスに応じたユースケースの組み合わせを実現できます。
