16. AMDメモリ暗号化¶

セキュアメモリ暗号化（SME）およびセキュア暗号化仮想化（SEV）は、AMDプロセッサに搭載されている機能です。

SMEは、標準のx86ページテーブルを使用して個々のメモリページを暗号化可能としてマークする機能を提供します。暗号化マークが設定されたページは、DRAMから読み込まれる際には自動的に復号され、DRAMに書き込まれる際には自動的に暗号化されます。これにより、SMEはシステムへの物理的な攻撃からDRAMの内容を保護するための機能として利用できます。

SEVは、ゲスト仮想マシン（VM）内でコードとデータを保護し、復号化されたバージョンがVM内部にのみ利用可能となるようにする暗号化された仮想マシンの実行を可能にします。SEVゲストVMにはプライベートメモリと共有メモリという概念があります。プライベートメモリはゲスト固有の鍵で暗号化され、共有メモリはホスト仮想化キーで暗号化されます。SMEが有効な場合、ホスト仮想化キーはSMEで使用される同じ鍵になります。

ページテーブルエントリに暗号化ビットが設定されている場合、ページが暗号化されます（以下でその位置を確認する方法を説明します）。暗号化ビットはcr3レジスタでも指定でき、これによりPGDテーブルの暗号化が可能になります。各ページテーブルレベルも、次のテーブルを指すページテーブルエントリに暗号化ビットを設定することで暗号化できます。これにより、全体のページテーブル階層を暗号化できます。注意として、cr3レジスタに暗号化ビットが設定されているからといって、階層全体が暗号化されているとは限りません。階層内の各ページテーブルエントリに暗号化ビットを設定しないとその状態は達成できません。理論的には、cr3に暗号化ビットを設定してPGDを暗号化するだけで、PUDエントリの暗号化ビットを設定しないと、そのエントリが指すPUDは暗号化されません。

SEVが有効な場合、インストラクションページとゲストページテーブルは常にプライベートと扱われます。ゲスト内のDMA操作はすべて共有メモリ上で実行しなければなりません。メモリ暗号化ビットは64ビットまたは32ビットPAEモードでゲストOSが制御しますが、その他のモードではSEVハードウェアがメモリ暗号化ビットを1に強制します。

SMEおよびSEVのサポートはCPUID指令を通じて確認できます。CPUID機能0x8000001fはSMEに関する情報を報告します：

0x8000001f[eax]:
        Bit[0] indicates support for SME
        Bit[1] indicates support for SEV
0x8000001f[ebx]:
        Bits[5:0]  pagetable bit number used to activate memory
                   encryption
        Bits[11:6] reduction in physical address space, in bits, when
                   memory encryption is enabled (this only affects
                   system physical addresses, not guest physical
                   addresses)

SMEのサポートがある場合、MSR 0xc00100010（MSR_K8_SYSCFG）を使用してSMEが有効かどうかを確認したり、メモリ暗号化を有効化したりできます：

0xc0010010:
        Bit[23]   0 = memory encryption features are disabled
                  1 = memory encryption features are enabled

SEVがサポートされている場合、MSR 0xc0010131 (MSR_AMD64_SEV)を使用してSEVがアクティブかどうかを確認できます。

0xc0010131:
        Bit[0]    0 = memory encryption is not active
                  1 = memory encryption is active

Linuxは、BIOSがメモリ暗号化を有効にした結果生じる物理アドレス空間の削減がシステムのアドレス空間リソース要件と競合しないと判断した場合、このビットをBIOSに依存して設定します。Linux起動時にこのビットが設定されていない場合、Linux自身が設定せず、メモリ暗号化は実行できません。

LinuxカーネルにおけるSMEの状態は以下の通りです：

  • サポートされている：CPUがSMEをサポートしている（CPUID指令を通じて判定）。

  • 有効化されている：サポートされており、MSR_K8_SYSCFGのビット23が設定されている。

  • アクティブ：サポートされており、有効化されており、Linuxカーネルがページテーブルエントリに暗号化ビットを適用している（カーネル内のSMEマスクがゼロでない）。

SMEはBIOSでも有効化およびアクティブ化できます。SMEがBIOSで有効化・アクティブ化されている場合、すべてのメモリアクセスが暗号化され、Linuxのメモリ暗号化サポートをアクティブ化する必要はありません。BIOSが単にSMEを有効化（MSR_K8_SYSCFGのビット23を設定）した場合、Linuxはデフォルトでメモリ暗号化を有効化できます（CONFIG_AMD_MEM_ENCRYPT_ACTIVE_BY_DEFAULT=y）またはカーネルコマンドラインにmem_encrypt=onを指定することで有効化できます。ただし、BIOSがSMEを有効化しない場合、Linuxがデフォルトで有効化設定されている場合でも、またはmem_encrypt=onを指定してもメモリ暗号化を有効化できません。
