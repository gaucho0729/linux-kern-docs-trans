著者

  • Fenghua Yu <fenghua.yu@intel.com>

  • Borislav Petkov <bp@suse.de>

カーネルはx86マイクロコードのロード機能を備えており、OS内でマイクロコードのロード方法を提供することを目的としています。潜在的な使用例は、OEMのエンドオブライフサポートを超えたプラットフォームでのマイクロコード更新、および再起動せずに長時間稼働するシステムでのマイクロコード更新です。

ローダーは3つのロード方法をサポートしています:

19.1. 早期ロードマイクロコード¶

カーネルは起動中にマイクロコードを非常に早期に更新できます。マイクロコードを早期にロードすることで、カーネル起動時の観測前にCPUの問題を修正できます。

マイクロコードはinitrdファイルに保存されています。起動中にそのファイルから読み込まれ、CPUコアにロードされます。

結合されたinitrdイメージの形式は、(圧縮されていない) cpio形式のマイクロコードが続き、(圧縮されている可能性がある)initrdイメージが続きます。ローダーは起動中に結合されたinitrdイメージを解析します。

cpio名前空間にあるマイクロコードファイルは以下の通りです:

インテルの場合:

kernel/x86/microcode/GenuineIntel.bin

AMDの場合:

kernel/x86/microcode/AuthenticAMD.bin

BSP（ブートストラッピングプロセッサ）の起動（SMP以前）中に、カーネルはinitrd内のマイクロコードファイルをスキャンします。CPUにマッチするマイクロコードが見つかった場合、BSPで適用され、その後すべてのAP（アプリケーションプロセッサ）にも適用されます。

ローダーはまた、CPUにマッチするマイクロコードをメモリに保存します。これにより、CPUがスリープ状態から復帰するときにキャッシュされたマイクロコードパッチが適用されます。

以下は、マイクロコードを含むinitrdを準備する粗い例です（これは通常、ディストリビューションがinitrdを再作成する際自動的に実行するため、自分で行う必要はありません。今後の参照用にここに記載しています）。

#!/bin/bash

if [ -z "$1" ]; then
    echo "You need to supply an initrd file"
    exit 1
fi

INITRD="$1"

DSTDIR=kernel/x86/microcode
TMPDIR=/tmp/initrd

rm -rf $TMPDIR

mkdir $TMPDIR
cd $TMPDIR
mkdir -p $DSTDIR

if [ -d /lib/firmware/amd-ucode ]; then
        cat /lib/firmware/amd-ucode/microcode_amd*.bin > $DSTDIR/AuthenticAMD.bin
fi

if [ -d /lib/firmware/intel-ucode ]; then
        cat /lib/firmware/intel-ucode/* > $DSTDIR/GenuineIntel.bin
fi

find . | cpio -o -H newc >../ucode.cpio
cd ..
mv $INITRD $INITRD.orig
cat ucode.cpio $INITRD.orig > $INITRD

rm -rf $TMPDIR

システムには、/lib/firmwareにマイクロコードパッケージをインストールする必要があります。それらのパスが別の場所にある場合や、プロセッサベンダーのサイトから直接ダウンロードした場合は、上記のパスを修正する必要があります。

19.2. 遅延ロード¶

マイクロコードをロードするための2つのレガシーなユーザースペースインターフェースがあります。それらは、/dev/cpu/microcode経由か、sysfs内の/sys/devices/system/cpu/microcode/reloadファイル経由で利用できます。

/dev/cpu/microcodeメソッドは、特別なユーザースペースツールが必要であるため非推奨とされています。

より簡単な方法は、ディストリビューションが提供するマイクロコードパッケージをインストールし、以下を実行することです:

# echo 1 > /sys/devices/system/cpu/microcode/reload

root権限で実行してください。

ロードメカニズムは、/lib/firmware/{intel-ucode,amd-ucode}にマイクロコードのblobを検索します。デフォルトのディストリビューションインストールパッケージはすでにそれらをそこに配置しています。

19.3. ビルドインマイクロコード¶

ローダーは、通常のビルトインファームウェアメソッド CONFIG_EXTRA_FIRMWARE を通じて供給されるビルトインマイクロコードのロードもサポートしています。現在は64ビットのみがサポートされています。

例を示します。

CONFIG_EXTRA_FIRMWARE="intel-ucode/06-3a-09 amd-ucode/microcode_amd_fam15h.bin"
CONFIG_EXTRA_FIRMWARE_DIR="/lib/firmware"

これは基本的に、ローカルに以下のツリー構造があることを意味します。

/lib/firmware/
|-- amd-ucode
...
|   |-- microcode_amd_fam15h.bin
...
|-- intel-ucode
...
|   |-- 06-3a-09
...

ビルドシステムがこれらのファイルを見つけ出し、最終的なカーネルイメージに統合できるようにするためです。早期ローダーはこれらを見つけ出し、適用します。

Needless to say, this method is not the most flexible one because it requires rebuilding the kernel each time updated microcode from the CPU vendor is available.
