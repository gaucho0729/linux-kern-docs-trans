8. Early Printk¶

x86システムでUSB2デバッグポートキーとデバッグケーブルを使用してearlyprintk=dbgpブートオプションを使用する方法

必要なのは、2台のコンピュータ、'USBデバッグキー'という特別なギア、および2本のUSBケーブルです。これらは以下のように接続します：

[host/target] <-------> [USB debug key] <-------> [client/console]

8.1. ハードウェア要件¶

  1. ホスト/ターゲットシステムはUSBデバッグポートの機能を備える必要があります。

    この機能を確認するには、lspci -vvvの出力で「Debug port」ビットを確認してください：

    # lspci -vvv
...
00:1d.7 USB Controller: Intel Corporation 82801H (ICH8 Family) USB2 EHCI Controller #1 (rev 03) (prog-if 20 [EHCI])
        Subsystem: Lenovo ThinkPad T61
        Control: I/O- Mem+ BusMaster+ SpecCycle- MemWINV- VGASnoop- ParErr- Stepping- SERR+ FastB2B- DisINTx-
        Status: Cap+ 66MHz- UDF- FastB2B+ ParErr- DEVSEL=medium >TAbort- <TAbort- <MAbort- >SERR- <PERR- INTx-
        Latency: 0
        Interrupt: pin D routed to IRQ 19
        Region 0: Memory at fe227000 (32-bit, non-prefetchable) [size=1K]
        Capabilities: [50] Power Management version 2
                Flags: PMEClk- DSI- D1- D2- AuxCurrent=375mA PME(D0+,D1-,D2-,D3hot+,D3cold+)
                Status: D0 PME-Enable- DSel=0 DScale=0 PME+
        Capabilities: [58] Debug port: BAR=1 offset=00a0
                     ^^^^^^^^^^^ <==================== [ HERE ]
        Kernel driver in use: ehci_hcd
        Kernel modules: ehci-hcd
...

    注意

    システムにデバッグポートの機能が表示されない場合、USBデバッグキーを使用できない可能性があります。

  2. NetChip USBデバッグケーブル/キーも必要です：

    http://www.plxtech.com/products/NET2000/NET20DC/default.asp

    これは、2つのUSB接続を持つ小さな青いプラスチックのコネクタです。電源はUSB接続から供給されます。

  3. もう1台のクライアント/コンソールシステムが必要です。そのシステムには高速USB 2.0ポートが必要です。

  4. NetChipデバイスは、「ホスト/ターゲット」システムの物理的なデバッグポートに直接接続する必要があります。物理的なデバッグポートと「ホスト/ターゲット」システムの間にUSBハブを使用することはできません。

    EHCIデバッグコントローラーは特定の物理的なUSBポートにバインドされており、NetChipデバイスはこのポートでのみ早期プリントクデバイスとして動作します。EHCIホストコントローラーは電気的に配線されており、EHCIデバッグコントローラーは最初の物理ポートに接続されており、ソフトウェアでこの設定を変更することはできません。物理的なポートはシステムの各ポートを試行して再起動することで確認できます。または、lsusbを使用するか、「ホスト/ターゲット」システムのさまざまなポートにUSBデバイスを接続して、USBスタックが生成するカーネル情報メッセージを確認できます。

    一部のハードウェアベンダーは物理的なコネクタでUSBデバッグポートを露出していない場合があります。このようなデバイスを見つけた場合は、ハードウェアベンダーに苦情を申し立てる必要があります。なぜなら、このポートを物理的にアクセス可能なポートに接続する理由はありませんからです。

  5. NetChipデバイスの多くのバージョンでは、クライアント/コンソールシステムをデバイスの右側に接続する必要があります（製品ロゴが上向きで左から右に読めるように）。理由は、5V電源がデバイスの一方の側からしか供給されず、再起動されない側に接続しなければならないからです。

8.2. ソフトウェア要件¶

  1. ホスト/ターゲットシステムでは：

以下のカーネル構成オプションを有効にする必要があります：

CONFIG_EARLY_PRINTK_DBGP=y

また、ブートコマンドラインに「earlyprintk=dbgp」を追加する必要があります。

注意

Grubを使用している場合は、/etc/grub.confの「kernel」行に追加してください。BIOSファームウェアシステムでGrub2を使用している場合は、/boot/grub2/grub.cfgの「linux」行に追加してください。EFIファームウェアシステムでGrub2を使用している場合は、/boot/grub2/grub.cfgまたは/boot/efi/EFI/<distro>/grub.cfgの「linux」または「linuxefi」行に追加してください。

複数のEHCIデバッグコントローラーがあるシステムでは、正しいEHCIデバッグコントローラー番号を指定する必要があります。順序はEHCIコントローラーのPCIバス列挙によって決まります。番号引数を指定しない場合のデフォルトは「0」または最初のEHCIデバッグコントローラーです。2番目のEHCIデバッグコントローラーを使用する場合は、コマンドラインに「earlyprintk=dbgp1」と指定してください。

注意

通常、earlyprintkコンソールは正規のコンソールが起動した後で無効になります。このチャネルを早期起動後に保持するには「earlyprintk=dbgp,keep」と指定してください。これはXorgなどの環境でのクラッシュデバッグに役立ちます。

  1. クライアント/コンソールシステムでは:

以下のカーネルのコンフィギュレーションオプションを有効にしてください:

CONFIG_USB_SERIAL_DEBUG=y

修正後のカーネルで次の起動時に/dev/ttyUSBxデバイスが表示されます。

これでカーネルメッセージのチャネルが準備完了です。お好みのターミナルエミュレータ（minicomなど）を起動し、/dev/ttyUSB0を使用するように設定してください。または「cat /dev/ttyUSBx」のraw出力を確認してください。

  1. Nvidia Southbridgeベースのシステムでは、カーネルがどのポートにデバッグデバイスが接続されているかを検出しようとします。

8.3. テスト¶

earlyprintk=dbgp,keepを指定し、ホスト/ターゲットシステムでカーネルメッセージを発生させることで出力をテストできます。たとえば、以下の操作で無害なカーネルメッセージを発生させることができます:

echo h > /proc/sysrq-trigger

ホスト/ターゲットシステムでは「dmesg」出力にこのヘルプラインが表示されます:

SysRq : HELP : loglevel(0-9) reBoot Crashdump terminate-all-tasks(E) memory-full-oom-kill(F) kill-all-tasks(I) saK show-backtrace-all-active-cpus(L) show-memory-usage(M) nice-all-RT-tasks(N) powerOff show-registers(P) show-all-timers(Q) unRaw Sync show-task-states(T) Unmount show-blocked-tasks(W) dump-ftrace-buffer(Z)

クライアント/コンソールシステムで実行してください:

cat /dev/ttyUSB0

ホストシステムでこのメッセージを発生させた後、すぐに上記のヘルプラインが表示されることを確認してください。

動作しない場合は、以下の linux-kernel@vger.kernel.org メールリストまたはx86メンテナに問い合わせてください。
