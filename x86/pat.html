13. PAT (Page Attribute Table)¶

x86 Page Attribute Table (PAT) は、ページ単位でメモリ属性を設定する機能を提供します。PAT は MTRR 設定と補完的な関係にあり、物理アドレス範囲でメモリタイプを設定する機能を提供します。ただし、PAT は MTRR よりも柔軟性が高いです。これは、ページ単位で属性を設定できる能力と、ハードウェアの制限が存在しないことが理由です。柔軟性の向上に伴い、同一の物理メモリに対して複数の仮想アドレスでメモリタイプのアリアスを避けるガイドラインが設けられています。

PAT はさまざまな種類のメモリ属性をサポートします。現在サポートされる主なメモリ属性は以下の通りです：

WB

ライトバック

UC

キャッシュなし

WC

ライトコンビネッド

WT

ライトスルー

UC-

キャッシュなしマイナス

13.2. ドライバ向けの高度なAPI¶

A. remap_pfn_range、io_remap_pfn_range、vmf_insert_pfn を使ってユーザーにページをエクスポート

ユーザー空間にページをエクスポートしたいドライバは、mmap インターフェースと以下の組み合わせを使用します：

  1. pgprot_noncached()

  2. io_remap_pfn_range() または remap_pfn_range() または vmf_insert_pfn()

PAT サポートにより、pgprot_writecombine という新しいAPIが追加されました。そのため、ドライバは pgprot_noncached() または pgprot_writecombine() のいずれかをステップ1で使用し、ステップ2を実行することで、これまで通りの処理が可能です。

さらに、ステップ2は内部的にメモリタイプリスト内で領域を UC または WC として追跡し、競合するマッピングを防ぐようにしています。

このAPIセットはI/O（RAM以外）領域でのみ動作します。ドライバがRAM領域をエクスポートする場合、上記のステップ0でset_memory_uc()またはset_memory_wc()を実行し、さらにそのページの使用状況を追跡し、ページが解放される前にset_memory_wb()を使用してプールを解放する必要があります。

13.3. MTRRのPAT／非PATシステムへの影響¶

以下の表は、x86でioremap*()呼び出しを使用する際、非PATおよびPATシステムにおいてライトコンビネーションMTRRを使用した場合の影響を示しています。理想的にはmtrr_add()の使用は、以下のものに置き換えられることになります。 arch_phys_wc_add() PATが有効なシステムでは無効な操作になります。領域がioremap_wc()／set_memory_wc()でI/Oマッピングされ、WC属性またはPATエントリでマッピングされている必要があります。I/Oメモリのキャッシュ不可領域とライトコンビネーションが望ましい領域を組み合わせるデバイスでは、ioremap_uc()を実行した後、set_memory_wc()を使用して有効なライトコンビネーション領域をホワイトリストに登録することを検討すべきです。ただし、有効なメモリタイプは実装定義とされ、この戦略はサイズ制約のある領域のデバイスで最終手段として使用できます。 arch_phys_wc_add() – 上記の表では「APIの推奨使用法ではない」という意味です。一部の–はカーネルによって厳格に強制されます。一部は現在は強制されていませんが、今後強制される可能性があります。

====  =======  ===  =========================  =====================
MTRR  Non-PAT  PAT  Linux ioremap value        Effective memory type
====  =======  ===  =========================  =====================
      PAT                                        Non-PAT |  PAT
      |PCD                                               |
      ||PWT                                              |
      |||                                                |
WC    000      WB   _PAGE_CACHE_MODE_WB             WC   |   WC
WC    001      WC   _PAGE_CACHE_MODE_WC             WC*  |   WC
WC    010      UC-  _PAGE_CACHE_MODE_UC_MINUS       WC*  |   UC
WC    011      UC   _PAGE_CACHE_MODE_UC             UC   |   UC
====  =======  ===  =========================  =====================

(*) denotes implementation defined and is discouraged

注意

ioremapおよび/procや/sysを通じたPCIアクセスでは、そのアドレスに既存のアリアスがある場合、返されるタイプはより制限されることがあります。例えば、既存のキャッシュ不可マッピングがある場合、新しいioremap_wcはライトコンビネーションを要求してもキャッシュ不可マッピングを返すことがあります。

ioremapおよびPCIアクセスを通じた/procや/sysでは、実際に返されるタイプは、そのアドレスに既存のアリアスがある場合、より制限されることがあります。例えば、既存のキャッシュ不可マッピングがある場合、ioremap_wcはライトコンビイングを要求してもキャッシュ不可マッピングを返すことがあります。

set_memory_[uc|wc|wt] と set_memory_wb はペアで使用する必要があります。ドライバはまず領域を uc、wc、または wt に設定し、使用後に wb に戻す処理を行います。

/proc/mtrr への書き込みは時間とともに PAT 基盤のインターフェースに置き換えられることになります。/proc/mtrr に書き込むユーザーは上記のインターフェースを使用することを推奨します。

ドライバは PCI BAR に ioremap_[uc|wc] を使用して [uc|wc] アクセスタイプでアクセスする必要があります。

ドライバは set_memory_[uc|wc|wt] を使用して RAM 範囲のアクセスタイプを設定する必要があります。
