23.1. IO-APIC¶

著者

Ingo Molnar <mingo@kernel.org>

ほとんどの（すべての）Intel-MP準拠SMPボードは、いわゆる「IO-APIC」と呼ばれる拡張された割込み制御器を搭載しています。これにより、ハードウェアの割込みを複数のCPUやCPUグループにルーティングすることが可能になります。IO-APICがなければ、ハードウェアからの割込みはOSを起動したCPU（通常はCPU#0）のみに届きます。

Linuxはすべての準拠SMPボードをサポートしており、複数のIO-APICを搭載したボードも含まれます。ハイエンドサーバーでは複数のIO-APICを用いてIRQ負荷をさらに分散します。

一部の古いボードではいくつかの問題が確認されていますが、これらの不具合は通常カーネルによって回避されます。MP準拠SMPボードでLinuxが起動しない場合は、まずlinux-smpメーリングリストアーカイブを確認してください。

IO-APIC割込みが有効な状態で起動すると、/proc/interruptsは次のようになります：

hell:~> cat /proc/interrupts
           CPU0
  0:    1360293    IO-APIC-edge  timer
  1:          4    IO-APIC-edge  keyboard
  2:          0          XT-PIC  cascade
 13:          1          XT-PIC  fpu
 14:       1448    IO-APIC-edge  ide0
 16:      28232   IO-APIC-level  Intel EtherExpress Pro 10/100 Ethernet
 17:      51304   IO-APIC-level  eth0
NMI:          0
ERR:          0
hell:~>

一部の割込みがまだ「XT PIC」として表示されていますが、これは問題ではありません。これらのIRQソースはパフォーマンスに影響を与えるものではありません。

ボードが作成したmp-tableが正常に動作しないという極めてまれなケースでは、pirq=ブートパラメータを使用して「手動でIRQエントリを構築」できます。ただし、これは非自明な作業であり、自動化することはできません。例として/etc/lilo.confのエントリ：

append="pirq=15,11,10"

実際の数字はシステムやPCIカード、およびそのPCIスロットの位置に依存します。通常、PCIスロットはPCIチップセットIRQルーティングファシリティ（入力PIRQ1-4ライン）に接続される前に「ダブルチェーン」されます：

          ,-.        ,-.        ,-.        ,-.        ,-.
PIRQ4 ----| |-.    ,-| |-.    ,-| |-.    ,-| |--------| |
          |S|  \  /  |S|  \  /  |S|  \  /  |S|        |S|
PIRQ3 ----|l|-. `/---|l|-. `/---|l|-. `/---|l|--------|l|
          |o|  \/    |o|  \/    |o|  \/    |o|        |o|
PIRQ2 ----|t|-./`----|t|-./`----|t|-./`----|t|--------|t|
          |1| /\     |2| /\     |3| /\     |4|        |5|
PIRQ1 ----| |-  `----| |-  `----| |-  `----| |--------| |
          `-'        `-'        `-'        `-'        `-'

すべてのPCIカードはPCI IRQを発生させ、これはINTA、INTB、INTC、INTDのいずれかです：

      ,-.
INTD--| |
      |S|
INTC--|l|
      |o|
INTB--|t|
      |x|
INTA--| |
      `-'

これらのINTA-D PCI IRQはカードごとにローカルであり、実際の意味はスロット位置に依存します。ダブルチェーン図を見てみると、スロット4に挿さったカードがINTA IRQを発生させると、PCIチップセットのPIRQ4ラインに信号が届きます。ほとんどのカードはINTAを発生させ、これはPIRQライン間での最適な負荷分散を実現します。（IRQソースの適切な分散は必須ではありませんが、パフォーマンス向上のためには共有しない割込みが望ましいです）スロット5はビデオカードに使用すべきで、通常は割込みを必要としないため、ダブルチェーンされません。

SCSIカード（IRQ11）がスロット1に、Tulipカード（IRQ9）がスロット2に挿さっている場合、以下のようなpirq=行を指定する必要があります：

append="pirq=11,9"

以下のスクリプトは、PCI構成からこのようなデフォルトのpirq=行を自動的に推測します：

echo -n pirq=; echo `scanpci | grep T_L | cut -c56-` | sed 's/ /,/g'

このスクリプトは、いくつかのスロットをスキップしているか、ボードがデフォルトのダイズィーチェインングをサポートしていない場合（またはIO-APICのPIRQピンが不思議な方法で接続されている場合）には動作しません。(例: 上記の場合、Slot3にSCSIカード（IRQ11）を挿して、Slot1を空にしていても)

append="pirq=0,9,11"

[値‘0’は一般的な‘プレースホルダー’であり、空（またはIRQを発生させない）スロットに予約されています。]

通常、正しいpirq=設定を見つけることは常に可能です。ただIRQ番号を適切に並べ替えるだけで…ただし時間がかかることがあります。‘誤った’pirq行は起動プロセスをフリーズさせたり、デバイスが正しく動作しなくなる原因になります（例: モジュールとして挿すと動作しない場合）。

2つのPCIバスがある場合、最大8つのpirq値を使用できますが、このようなボードは通常良い設定が既に用意されています。

必要な場合、不思議なpirq行が必要になるかもしれませんのでご注意ください:

append="pirq=0,0,0,0,0,0,9,11"

正しいpirq行を見つけるためにスマートな試行錯誤の技術を活用してください…

ご注意ください。このドキュメントでは説明されていない問題が発生した場合は、 linux-smp@vger.kernel.org または linux-kernel@vger.kernel.org にメールを送ってください。
