4. x86 ティポロジー¶

x86 テクノロジーのモデリングおよびカーネルにおける表現の主要な側面を文書化し、明確にしています。関連するコードを変更する際には、このドキュメントも更新・変更してください。

アーキテクチャを問わないトポロジーの定義は sysfs を通じて CPU テポロジー情報がエクスポートされる仕組みこちらに記載されています。このファイルは、x86 特有の違いや特徴を保持しており、一般的な定義には必ず適用されるとは限りません。したがって、Linux x86 におけるトポロジーを学ぶ際には、まず一般的な定義から読み始め、このファイルを併せて参照してください。

言うまでもないほど、コードは一般的な関数を使用すべきです。このファイルは のみ ここに ドキュメント x86 トポロジーの内部構造を説明しています。

Thomas Gleixner <tglx@linutronix.de> および Borislav Petkov <bp@alien8.de>.

トポロジー機能の主な目的は、コードが実行中のシステムの構造（スレッド、コア、パッケージなど）を知る・照合する・利用するための適切なインターフェースを提供することです。

カーネルは物理ソケットという概念には関心を持たないため、ソケットはソフトウェアにとって関係ありません。ソケットは電気機械的コンポーネントであり、かつてはソケットには常に1つのパッケージ（以下参照）が含まれていましたが、マルチチップモジュール（MCM）の登場により、ソケットに複数のパッケージを含むことが可能になりました。そのため、コード内にソケットに関する参照が残っている可能性はありますが、それらは歴史的なものであり、整理する必要があります。

システムのトポロジーは以下の単位で記述されます：

  • パッケージ

  • コア

  • スレッド

4.1. パッケージ¶

パッケージには複数のコアと共有リソース（例：DRAM コントローラー、共有キャッシュなど）が含まれます。

現代のシステムでは、パッケージとして「ダイ」を用いる場合もあります。

AMD におけるパッケージの用語は「ノード」です。

カーネルにおけるパッケージ関連のトポロジー情報：

  • cpuinfo_x86.x86_max_cores:

    パッケージ内のコア数。この情報は CPUID から取得されます。

  • cpuinfo_x86.x86_max_dies:

    パッケージ内のダイ数。この情報は CPUID から取得されます。

  • cpuinfo_x86.cpu_die_id:

    ダイの物理 ID。この情報は CPUID から取得されます。

  • cpuinfo_x86.phys_proc_id:

    パッケージの物理 ID。この情報は CPUID から取得され、パッケージ内のコアの APIC ID から導出されます。

    現代のシステムではこの値がソケットとして使用されます。ソケット内には複数のパッケージが存在する可能性があり、この値は cpu_die_id と異なる場合があります。

  • cpuinfo_x86.logical_proc_id:

    パッケージの論理 ID。BIOS がパッケージを一貫して列挙しない可能性があるため、論理パッケージ ID の概念を導入し、システム内の最大可能パッケージ数を計算し、パッケージを線形に列挙できるようにしています。

  • topology_max_packages():

    システム内の最大可能なパッケージ数。パッケージごとの機能で事前にパッケージ情報を確保するのに役立ちます。

  • cpu_llc_id:

    CPUごとの変数で、以下を含みます:

    • インテルの場合、共有しているLast Level Cacheを持つCPUリストの最初のAPIC ID

    • AMDの場合、Last Level Cacheを含むノードIDまたはコア複合体ID。一般的には、システム内でLLCを一意に識別する番号です。

4.2. コア¶

コアは1つ以上のスレッドから構成されます。スレッドがSMT型またはCMT型であるかは関係ありません。

AMDのCMTコアの呼称は「コンピュートユニット」ですが、カーネルは常に「コア」を使用します。

カーネルにおけるコア関連のトポロジ情報:

  • smp_num_siblings:

    コア内のスレッド数。パッケージ内のスレッド数は以下の式で計算できます:

    threads_per_package = cpuinfo_x86.x86_max_cores * smp_num_siblings

4.3. スレッド¶

スレッドは単一のスケジューリング単位です。論理的なLinux CPUに相当します。

AMDのCMTスレッドの呼称は「コンピュートユニットコア」ですが、カーネルは常に「スレッド」を使用します。

カーネルにおけるスレッド関連のトポロジ情報:

  • topology_core_cpumask():

    スレッドが属するパッケージ内のすべてのオンラインスレッドを含みます。

    オンラインスレッド数は/proc/cpuinfoの「siblings」で表示されます。

  • topology_sibling_cpumask():

    スレッドが属するコア内のすべてのオンラインスレッドを含みます。

  • topology_logical_package_id():

    スレッドが属する論理パッケージID。

  • topology_physical_package_id():

    スレッドが属する物理パッケージID。

  • topology_core_id();

    スレッドが属するコアID。これは/proc/cpuinfoの「core_id」でも表示されます。

4.4. システムトポロジの例¶

注意

LinuxのCPU列挙方法はBIOSがスレッドを列挙する方法に依存します。多くのBIOSはまずすべてのスレッド0を列挙し、その後すべてのスレッド1を列挙します。これにより、スレッド0の論理的なLinuxCPU番号がスレッドが有効か無効かに関わらず変わりません。これは単なる実装詳細であり、実際の影響はありません。

  1. 単一パッケージ、単一コア:

    [package 0] -> [core 0] -> [thread 0] -> Linux CPU 0

  2. 単一パッケージ、デュアルコア

    1. コアごとに1つのスレッド:

      [package 0] -> [core 0] -> [thread 0] -> Linux CPU 0
            -> [core 1] -> [thread 0] -> Linux CPU 1

    2. コアごとに2つのスレッド:

      [package 0] -> [core 0] -> [thread 0] -> Linux CPU 0
                        -> [thread 1] -> Linux CPU 1
            -> [core 1] -> [thread 0] -> Linux CPU 2
                        -> [thread 1] -> Linux CPU 3

      代替列挙:

      [package 0] -> [core 0] -> [thread 0] -> Linux CPU 0
                        -> [thread 1] -> Linux CPU 2
            -> [core 1] -> [thread 0] -> Linux CPU 1
                        -> [thread 1] -> Linux CPU 3

      AMDのCMTシステムにおける呼称:

      [node 0] -> [Compute Unit 0] -> [Compute Unit Core 0] -> Linux CPU 0
                             -> [Compute Unit Core 1] -> Linux CPU 1
         -> [Compute Unit 1] -> [Compute Unit Core 0] -> Linux CPU 2
                             -> [Compute Unit Core 1] -> Linux CPU 3

  1. デュアルパッケージ、デュアルコア

    1. コアごとに1つのスレッド:

      [package 0] -> [core 0] -> [thread 0] -> Linux CPU 0
            -> [core 1] -> [thread 0] -> Linux CPU 1

[package 1] -> [core 0] -> [thread 0] -> Linux CPU 2
            -> [core 1] -> [thread 0] -> Linux CPU 3

    2. コアごとに2つのスレッド:

      [package 0] -> [core 0] -> [thread 0] -> Linux CPU 0
                        -> [thread 1] -> Linux CPU 1
            -> [core 1] -> [thread 0] -> Linux CPU 2
                        -> [thread 1] -> Linux CPU 3

[package 1] -> [core 0] -> [thread 0] -> Linux CPU 4
                        -> [thread 1] -> Linux CPU 5
            -> [core 1] -> [thread 0] -> Linux CPU 6
                        -> [thread 1] -> Linux CPU 7

      代替列挙:

      [package 0] -> [core 0] -> [thread 0] -> Linux CPU 0
                        -> [thread 1] -> Linux CPU 4
            -> [core 1] -> [thread 0] -> Linux CPU 1
                        -> [thread 1] -> Linux CPU 5

[package 1] -> [core 0] -> [thread 0] -> Linux CPU 2
                        -> [thread 1] -> Linux CPU 6
            -> [core 1] -> [thread 0] -> Linux CPU 3
                        -> [thread 1] -> Linux CPU 7

      AMDのCMTシステムにおける呼称:

      [node 0] -> [Compute Unit 0] -> [Compute Unit Core 0] -> Linux CPU 0
                             -> [Compute Unit Core 1] -> Linux CPU 1
         -> [Compute Unit 1] -> [Compute Unit Core 0] -> Linux CPU 2
                             -> [Compute Unit Core 1] -> Linux CPU 3

[node 1] -> [Compute Unit 0] -> [Compute Unit Core 0] -> Linux CPU 4
                             -> [Compute Unit Core 1] -> Linux CPU 5
         -> [Compute Unit 1] -> [Compute Unit Core 0] -> Linux CPU 6
                             -> [Compute Unit Core 1] -> Linux CPU 7
