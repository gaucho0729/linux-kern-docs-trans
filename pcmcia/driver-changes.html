ドライバーチェンジ¶

このファイルは、2.6 における変更内容を詳しく説明しており、PCMCIA カードドライバの作成者に影響を与えるものです:

  • pcmcia_loop_config() と自動設定 (2.6.36 以降)

    もし struct pcmcia_device *p_dev->config_flags は適切に設定され、pcmcia_loop_config() は現在、特定の設定値を自動的に設定します。ただし、ドライバはコールバック関数でこれらの設定を上書きする可能性があります。現在提供されている自動設定オプションは以下の通りです:

    • CONF_AUTO_CHECK_VCC : Vcc の一致を確認

    • CONF_AUTO_SET_VPP : Vpp を設定

    • CONF_AUTO_AUDIO : 音声ラインを自動的に有効化（必要に応じて）

    • CONF_AUTO_SET_IO : I/O ポートリソース（->resource[0,1]）を設定

    • CONF_AUTO_SET_IOMEM : 最初の IOMEM リソース（->resource[2]）を設定

  • pcmcia_request_configuration -> pcmcia_enable_device (2.6.36 以降)

    pcmcia_request_configuration() は pcmcia_enable_device() にrenameされました。これは pcmcia_disable_device() と対応するためです。設定内容は現在、struct pcmcia_device に格納され、config_flags、config_index、config_base、vpp などのフィールドに保存されます。

  • pcmcia_request_window の変更 (2.6.36 以降)

    win_req_t ではなく、ドライバは以下の構造体を埋め込む必要があります struct pcmcia_device *p_dev->resource[2,3,4,5] 最大4つのioport範囲を指定できます。pcmcia_request_window()を呼び出した後、その領域は予約され、即座に使用可能になります – pcmcia_release_window()が呼び出されるまで有効です。

  • pcmcia_request_io の変更点 (2.6.36 以降)

    io_req_t ではなく、ドライバが埋めるべき構造体は struct pcmcia_device *p_dev->resource[0,1] 最大2つのioport範囲を指定できます。pcmcia_request_io()を呼び出した後、そのポートは予約され、pcmcia_request_configuration()を呼び出した後、使用可能になります。

  • dev_info_t は使用されなくなりました。cs_types.h も含めないでください (2.6.36 以降)

    dev_info_t といくつかのtypedefは削除されました。PCMCIAデバイスドライバではこれを使用しないでください。また、pcmcia/cs_types.h をインクルードしないでください。このファイルは削除されました。

  • dev_node_t は使用されなくなりました (2.6.35 以降)

    「dev_node_t」構造体を埋める必要はありません。

  • 新しいIRQ要求ルール (2.6.35 以降)

    古い pcmcia_request_irq() インターフェースではなく、ドライバは以下を選択できます:

    • request_irq/free_irq を直接呼び出す。IRQ は *p_dev->irq.

    • pcmcia_request_irq(p_dev, handler_t); を使用してください。PCMCIAコアは pcmcia_disable_device() またはデバイスの挿抜時に自動的にクリーンアップします。

  • cs_error / CS_CHECK / CONFIG_PCMCIA_DEBUG は使用されなくなりました (2.6.33 以降)

    cs_error() コールバックや CS_CHECK() マクロではなく、Linuxスタイルの戻り値チェックを使用してください。必要に応じて、「dev_dbg()」や「pr_debug()”.

  • 新しいCISタプルアクセス（2.6.33以降）

    1つの（生の）タプルのみを扱う場合は「pcmcia_get_tuple()」、すべてのタプルを扱う場合は「pcmcia_loop_tuple()」を使用する必要があります。MACアドレスをCISTPL_FUNCEからデコードするには、新しいヘルパー「pcmcia_get_mac_from_cis()」が追加されました。

  • 新しい構成ループヘルパー（2.6.28以降）

    「pcmcia_loop_config()」を呼び出すことで、ドライバはすべての構成オプションを反復処理できます。ドライバのprobe()フェーズでは、ほとんどの場合「pcmcia_get_{first,next}_tuple()」や「pcmcia_get_tuple_data()」「pcmcia_parse_tuple()」は直接使用しなくてよいです。

  • 新しいリリースヘルパー（2.6.17以降）

    「pcmcia_release_{configuration,io,irq,win}()」を呼び出す代わりに、「pcmcia_disable_device()」を呼び出すだけで十分です。PCMCIA_release_io()やPCMCIA_release_irq()を呼び出す正当な理由がなくなったため、それらのエクスポートは削除されました。

  • デタッチとREMOVALイベントコード、およびアタッチとINSERTIONコードを統合しました（2.6.16以降）：

    void (*remove)          (struct pcmcia_device *dev);
int (*probe)            (struct pcmcia_device *dev);

  • スリープ、再開、リセットをイベントハンドラから外しました（2.6.16以降）：

    int (*suspend)          (struct pcmcia_device *dev);
int (*resume)           (struct pcmcia_device *dev);

    struct pcmcia_driverで初期化され、(SUSPEND == RESET_PHYSICAL)と(RESUME == CARD_RESET)イベントを処理する必要があります。

  • struct pcmcia_driverでのイベントハンドラ初期化（2.6.13以降）

    イベントハンドラはすべてのイベントを通知されます。ドライバのstruct pcmcia_driverでイベント()コールバックとして初期化する必要があります。

  • pcmcia/version.hは使用しないでください（2.6.13以降）

    このファイルは最終的に削除される予定です。

  • カーネル内でのデバイス<->ドライバマッチング（2.6.13以降）

    PCMCIAデバイスと正しいドライバがカーネル空間でマッチングできます。詳細は'devicetable.txt'を参照してください。

  • デバイスモデル統合（2.6.11以降）

    struct pcmcia_deviceはデバイスモデルコアに登録され、handle_to_dev(client_handle_t * handle)を使用してSET_NETDEV_DEVなどに利用できます。

  • 内部I/Oポートアドレスをunsigned intに変換（2.6.11以降）

    PCMCIAカードドライバではioaddr_tをunsigned intに置き換える必要があります。

  • irq_maskとirq_listパラメータ（2.6.11以降）

    PCMCIAカードドライバではirq_maskとirq_listパラメータは使用しないでください。代わりにPCMCIAコアがどのIRQを使用するかを決定します。そのため、link->irq.IRQInfo2は無視されます。

  • client->PendingEventsは削除されました（2.6.11以降）

    client->PendingEventsは利用できなくなりました。

  • client->Attributesは削除されました（2.6.11以降）

    client->Attributesは未使用のため、すべてのPCMCIAカードドライバから削除されました

  • コア機能はもはや利用不可（2.6.11以降）

    以下の機能は、すべての内蔵ドライバーが使用していないため、カーネルソースから削除されました。また、外部ドライバーがこれらに依存していると報告されていません：

    pcmcia_get_first_region()
pcmcia_get_next_region()
pcmcia_modify_window()
pcmcia_set_event_mask()
pcmcia_get_first_window()
pcmcia_get_next_window()
  • モジュールの除去時にデバイスリストの反復処理は不要になりました（2.6.10以降）

    ドライバーの内部クライアントリストを反復処理し、モジュールの除去時に->detach()関数を呼び出す必要はありません。

  • リソース管理。（2.6.8以降）

    PCMCIAサブシステムはカードにリソースを割り当てますが、これらをbusyとしてマークしなくなりました。これにより、ドライバー開発者はLinuxの他のドライバーと同様にリソースを主張する責任があります。IO領域はrequest_region()を使用して使用中とマークし、メモリ領域はrequest_mem_region()を使用して使用中とマークしてください。name引数にはドライバー名へのポインタを指定してください。例としてpcnet_csの場合、nameは文字列「pcnet_cs」を指す必要があります。

  • CardServicesは廃止されました。2.4のCardServices()は、さまざまなサービスを呼び出すための大きなswitch文です。2.6では、これらのエントリポイントがすべてエクスポートされ、直接呼び出されます（ただし、pcmcia_report_error()は除きます。代わりにcs_error()を使用してください）。

  • struct pcmcia_driver は、{un,}register_pccard_driver ではなく、struct pcmcia_driver と pcmcia_{un,}register_driver を使用する必要があります。
