FPGAデバイス機能リスト（DFL）フレームワーク概要¶

著者:

  • Enno Luebbers <enno.luebbers@intel.com>

  • Xiao Guangrong <guangrong.xiao@linux.intel.com>

  • Wu Hao <hao.wu@intel.com>

デバイス機能リスト（DFL）FPGAフレームワーク（およびこのフレームワークに従うドライバ）は、低レイヤハードウェアの詳細を隠蔽し、ユーザー空間に対して統一インターフェースを提供します。アプリケーションはこれらのインターフェースを使用して、DFLをデバイスメモリで実装しているプラットフォーム上のFPGAアクセラレータを構成・列挙・オープン・アクセスできます。さらに、DFLフレームワークはFPGA再構成などのシステムレベルの管理機能を有効にします。

デバイス機能リスト（DFL）概要¶

デバイス機能リスト（DFL）は、デバイスMMIO領域内で機能ヘッダのリンクリストを定義し、拡張可能な方法で機能を追加する仕組みを提供します。ソフトウェアはこれらの予定されたデータ構造を歩くことで、FPGA機能を列挙できます：FPGAインターフェースユニット（FIU）、アクセラレートされた機能ユニット（AFU）およびプライベート機能、以下に示すように：

   Header            Header            Header            Header
+----------+  +-->+----------+  +-->+----------+  +-->+----------+
|   Type   |  |   |  Type    |  |   |  Type    |  |   |  Type    |
|   FIU    |  |   | Private  |  |   | Private  |  |   | Private  |
+----------+  |   | Feature  |  |   | Feature  |  |   | Feature  |
| Next_DFH |--+   +----------+  |   +----------+  |   +----------+
+----------+      | Next_DFH |--+   | Next_DFH |--+   | Next_DFH |--> NULL
|    ID    |      +----------+      +----------+      +----------+
+----------+      |    ID    |      |    ID    |      |    ID    |
| Next_AFU |--+   +----------+      +----------+      +----------+
+----------+  |   | Feature  |      | Feature  |      | Feature  |
|  Header  |  |   | Register |      | Register |      | Register |
| Register |  |   |   Set    |      |   Set    |      |   Set    |
|   Set    |  |   +----------+      +----------+      +----------+
+----------+  |      Header
              +-->+----------+
                  |   Type   |
                  |   AFU    |
                  +----------+
                  | Next_DFH |--> NULL
                  +----------+
                  |   GUID   |
                  +----------+
                  |  Header  |
                  | Register |
                  |   Set    |
                  +----------+

FPGAインターフェースユニット（FIU）は、FPGAへのインターフェース用の独立した機能ユニットを表します。例えば、FPGAマネジメントエンジン（FME）およびポート（後述のFMEおよびポートに関する詳細情報があります）。

アクセラレートされた機能ユニット（AFU）は、FPGAのプログラマブル領域を表し、常にFIU（例えば、ポート）としてその子として接続されます。

プライベート機能はFIUおよびAFUのサブ機能を表し、さまざまなIDを持つさまざまな機能ブロックである可能性がありますが、同じFIUまたはAFUに属するすべてのプライベート機能は、Next Device Feature Header（Next_DFH）ポインタを介して1つのリストにリンクする必要があります。

各FIU、AFUおよびプライベート機能は、自身の機能レジスタを実装できます。FIUおよびAFUの機能レジスタセットはヘッダレジスタセットと呼ばれ、例えばFMEヘッダレジスタセット、プライベート機能の場合は機能レジスタセットと呼ばれ、例えばFME部分再構成機能レジスタセットです。

このデバイス機能リストは機能をリンクする方法を提供し、ソフトウェアはこのリストを歩くことで各機能を簡単に見つけることができ、どのFPGAデバイスのレジスタ領域でも実装可能です。

FIU - FME（FPGAマネジメントエンジン）¶

FPGAマネジメントエンジンは再構成およびその他のインフラストラクチャ機能を実行します。各FPGAデバイスには1つのFMEのみがあります。

ユーザー空間アプリケーションはopen()を使用してFMEに排他アクセスを取得し、close()を使用して解放できます。

以下の機能はioctlを通じて公開されます：

  • ドライバAPIバージョンを取得（DFL_FPGA_GET_API_VERSION）

  • 拡張機能の確認 (DFL_FPGA_CHECK_EXTENSION)

  • ビットストリームのプログラミング (DFL_FPGA_FME_PORT_PR)

  • ポートをPFに割り当てる (DFL_FPGA_FME_PORT_ASSIGN)

  • PFからポートを解放する (DFL_FPGA_FME_PORT_RELEASE)

  • FMEグローバルエラーのIRQ数を取得 (DFL_FPGA_FME_ERR_GET_IRQ_NUM)

  • FMEエラーの割り込みトリガーを設定 (DFL_FPGA_FME_ERR_SET_IRQ)

sysfsを通じてさらに多くの機能が提供されています (/sys/class/fpga_region/regionX/dfl-fme.n/):

ビットストリームIDを読み込む (bitstream_id)

bitstream_idは静的FPGA領域のバージョンを示します。

ビットストリームメタデータを読み込む (bitstream_metadata)

bitstream_metadataは静的FPGA領域の詳細な情報を含みます。例えば、合成日時やシード値などです。

ポート数を読み込む (ports_num)

1つのFPGAデバイスは複数のポートを持つ場合があります。このsysfsインターフェースは、FPGAデバイスが持つポート数を示します。

グローバルエラー報告管理 (errors/)

エラー報告sysfsインターフェースは、ユーザーがハードウェアで検出されたエラーを読み込み、ログされたエラーをクリアできるようにします。

電源管理 (dfl_fme_power hwmon)

電源管理hwmon sysfsインターフェースは、ユーザーが電源管理情報を読み込むこと（消費電力、しきい値、しきい値ステータス、制限値など）および、さまざまなスロットリングレベルに応じた電源しきい値を設定できるようにします。

熱管理 (dfl_fme_thermal hwmon)

熱管理hwmon sysfsインターフェースは、ユーザーが熱管理情報を読み込むことができます（現在温度、しきい値、しきい値ステータスなど）。

パフォーマンスレポート

パフォーマンスカウンタはperf PMU APIを通じて提供されます。標準のperfツールを使用して、すべての利用可能なperfイベントを監視できます。詳細な情報については、下記のパフォーマンスカウンタセクションをご覧ください。

FIU - ポート¶

ポートは、静的FPGAファブリックと部分的に再構成可能な領域（AFUを含む）のインターフェースを表します。SWからアクセラレータへの通信を制御し、リセットやデバッグなどの機能を提供します。各FPGAデバイスは複数のポートを持つ場合がありますが、常にポートごとに1つのAFUがあります。

AFU¶

AFUはポートFIUに接続され、アクセラレータ専用の制御レジスタに使用する固定長のMMIO領域を提供します。

ユーザー空間アプリケーションは、ポートデバイスノードのopen()を使用してポートに接続されたAFUに排他アクセスを取得し、close()を使用して解放できます。

以下の機能はioctlを通じて公開されます：

  • ドライバAPIバージョンを取得（DFL_FPGA_GET_API_VERSION）

  • 拡張機能の確認 (DFL_FPGA_CHECK_EXTENSION)

  • ポート情報の取得 (DFL_FPGA_PORT_GET_INFO)

  • MMIO領域情報の取得 (DFL_FPGA_PORT_GET_REGION_INFO)

  • DMAバッファのマッピング (DFL_FPGA_PORT_DMA_MAP)

  • DMAバッファのアンマッピング (DFL_FPGA_PORT_DMA_UNMAP)

  • AFUのリセット (DFL_FPGA_PORT_RESET)

  • ポートエラーのIRQ数を取得 (DFL_FPGA_PORT_ERR_GET_IRQ_NUM)

  • ポートエラーの割込みトリガーを設定する (DFL_FPGA_PORT_ERR_SET_IRQ)

  • UINTの割込み数を取得する (DFL_FPGA_PORT_UINT_GET_IRQ_NUM)

  • UINTの割込みトリガーを設定する (DFL_FPGA_PORT_UINT_SET_IRQ)

DFL_FPGA_PORT_RESET:

FPGAポートとそのAFUをリセットします。ユーザースペースはDMAや部分再構成中にポートリセットをいつでも実行できます。ただし、システムレベルの問題を引き起こすことは決してなく、機能的な失敗（例: DMAやPR操作の失敗）に限られ、失敗から回復可能でなければなりません。

ユーザースペースアプリケーションは、アクセラレータMMIO領域をmmap()することもできます。

sysfsを通じてさらに多くの機能が公開されています: (/sys/class/fpga_region/<regionX>/<dfl-port.m>/):

アクセラレータGUID (afu_id) を読み取る

afu_idは、このAFUにプログラミングされたPRビットストリームを示します。

エラー報告 (errors/)

エラー報告sysfsインターフェースは、ユーザーがハードウェアで検出されたポート/AFUエラーを読み取るのを可能にし、記録されたエラーをクリアできます。

DFLフレームワーク概要¶

       +----------+    +--------+ +--------+ +--------+
       |   FME    |    |  AFU   | |  AFU   | |  AFU   |
       |  Module  |    | Module | | Module | | Module |
       +----------+    +--------+ +--------+ +--------+
               +-----------------------+
               | FPGA Container Device |    Device Feature List
               |  (FPGA Base Region)   |         Framework
               +-----------------------+
------------------------------------------------------------------
             +----------------------------+
             |   FPGA DFL Device Module   |
             | (e.g. PCIE/Platform Device)|
             +----------------------------+
               +------------------------+
               |  FPGA Hardware Device  |
               +------------------------+

カーネル内のDFLフレームワークは、コンテナデバイス（FPGAベース領域）を作成し、指定されたデバイス機能リストから機能デバイスとそのプライベート機能を検出する共通インターフェースを提供します。また、機能デバイス（例: FME、ポート、AFU）のリソースをコンテナデバイス下でプラットフォームデバイスを作成し、プライベート機能の操作を抽象化し、機能デバイスドライバに共通の操作を公開します。

FPGA DFLデバイスは、PCIeデバイスやプラットフォームデバイスなど、さまざまなハードウェアである場合があります。デバイスがシステムによって作成されると、常にDFLデバイスモジュールが最初にロードされます。このドライバーはドライバアーキテクチャのインフラストラクチャとして機能し、DFLフレームワークの共通インターフェースからデバイスメモリ内のDFLを検索し、それらと関連するリソースを処理します。(詳細な列挙APIについてはdrivers/fpga/dfl.cを参照してください)

FPGA Management Engine (FME)ドライバーは、DFLデバイスモジュールからFMEプラットフォームデバイスが作成された後に自動的にロードされるプラットフォームドライバーです。FPGA管理のための主要な機能を提供し、以下が含まれます:

  1. 静的なFPGA領域情報（例: バージョンとメタデータ）を公開します。ユーザーはFMEドライバーが公開するsysfsインターフェースを通じて関連情報を読み取れます。

  2. 部分再構成。FMEドライバーはPRサブ機能初期化中にFPGAマネージャー、FPGAブリッジ、FPGA領域を作成します。ユーザーからDFL_FPGA_FME_PORT_PR ioctlが送信されると、FPGA領域の共通インターフェース関数を呼び出して、指定されたポートへのPRビットストリームの部分再構成を完了します。

FMEドライバーと同様に、FPGA加速機能ユニット（AFU）ドライバーはAFUプラットフォームデバイスが作成された後、プローブされます。このモジュールの主な機能は、ユーザー空間アプリケーションが個々のアクセラレータにアクセスするためのインターフェースを提供すること、ポートの基本的なリセット制御、AFU MMIO領域のエクスポート、DMAバッファマッピングサービス機能を含みます。

機能プラットフォームデバイスが作成された後、マッチしたプラットフォームドライバーが自動的にロードされ、さまざまな機能を処理します。詳細な情報については、次のセクションを参照してください。このDFLフレームワークで既に実装された機能ユニットについて説明しています。

部分再構成¶

上記のように、アクセラレータはPRビットストリームファイルの部分再構成を通じて再構成できます。PRビットストリームファイルは、FPGAの正確な静的FPGA領域およびターゲット再構成可能領域（ポート）に生成されていなければなりません。それ以外の場合、再構成操作は失敗し、システムの不安定化を引き起こす可能性があります。この互換性は、PRビットストリームファイルのヘッダーに記載された互換性IDをターゲットFPGA領域が公開するcompat_idと比較することで確認できます。この確認は、再構成IOCTLを呼び出す前にユーザー空間で通常行われます。

FPGA仮想化 - PCIe SRIOV¶

このセクションでは、仮想マシン（VM）で実行されているアプリケーションからアクセラレータにアクセスを可能にする、DFLベースのFPGAデバイスにおける仮想化サポートについて説明します。このセクションでは、SRIOVサポートを持つPCIeベースのFPGAデバイスについてのみ説明します。

特定のFPGAデバイスがサポートする機能は、デバイス機能リストを通じて公開されます。以下に例を示します：

  +-------------------------------+  +-------------+
  |              PF               |  |     VF      |
  +-------------------------------+  +-------------+
      ^            ^         ^              ^
      |            |         |              |
+-----|------------|---------|--------------|-------+
|     |            |         |              |       |
|  +-----+     +-------+ +-------+      +-------+   |
|  | FME |     | Port0 | | Port1 |      | Port2 |   |
|  +-----+     +-------+ +-------+      +-------+   |
|                  ^         ^              ^       |
|                  |         |              |       |
|              +-------+ +------+       +-------+   |
|              |  AFU  | |  AFU |       |  AFU  |   |
|              +-------+ +------+       +-------+   |
|                                                   |
|            DFL based FPGA PCIe Device             |
+---------------------------------------------------+

FMEは常に物理ファンクション（PF）を通じてアクセスされます。

ポート（および関連するAFU）はデフォルトでPFを通じてアクセスされますが、PCIe SRIOVを通じて仮想ファンクション（VF）デバイスで公開することも可能です。各VFは1つのポートと1つのAFUを含み、分離を実現しています。ユーザーは、PCIe SRIOVインターフェースで作成された個々のVF（アクセラレータ）を仮想マシンに割り当てることができます。

仮想化のケースにおけるドライバの構成は以下の通りです：

 +-------++------++------+             |
 | FME   || FME  || FME  |             |
 | FPGA  || FPGA || FPGA |             |
 |Manager||Bridge||Region|             |
 +-------++------++------+             |
 +-----------------------+  +--------+ |             +--------+
 |          FME          |  |  AFU   | |             |  AFU   |
 |         Module        |  | Module | |             | Module |
 +-----------------------+  +--------+ |             +--------+
       +-----------------------+       |       +-----------------------+
       | FPGA Container Device |       |       | FPGA Container Device |
       |  (FPGA Base Region)   |       |       |  (FPGA Base Region)   |
       +-----------------------+       |       +-----------------------+
         +------------------+          |         +------------------+
         | FPGA PCIE Module |          | Virtual | FPGA PCIE Module |
         +------------------+   Host   | Machine +------------------+
-------------------------------------- | ------------------------------
          +---------------+            |          +---------------+
          | PCI PF Device |            |          | PCI VF Device |
          +---------------+            |          +---------------+

FPGA PCIeデバイスドライバーは、FPGA PCIe PFまたはVFデバイスが検出されたときに常に最初にロードされます。これは以下の機能を持ちます：

  • DFLフレームワークの共通インターフェースを使用して、FPGA PCIe PFおよびVFデバイスの列挙を完了します。

  • SRIOVをサポートします。

FMEデバイスドライバーはこのドライバアーキテクチャにおいて管理役割を果たします。ポートをPFから解放し、PFにポートを割り当てるioctlを提供します。ポートをPFから解放した後、PCIe SRIOV sysfsインターフェースを通じてこのポートをVFで公開することが安全です。

仮想マシンで実行されているアプリケーションからアクセラレータにアクセスを有効にするには、対応するAFUのポートをVFに割り当てるために以下の手順を実行する必要があります。

  1. デフォルトではPFがすべてのAFUポートを所有しています。ポートをVFに再割り当てするには、まずFMEデバイス上でDFL_FPGA_FME_PORT_RELEASE ioctlを介してポートを解放する必要があります。

  2. NポートがPFから解放されると、ユーザーは以下のコマンドを使用してSRIOVとVFを有効化できます。各VFはAFUを含む1つのポートのみを所有します。

    echo N > $PCI_DEVICE_PATH/sriov_numvfs

  3. 仮想マシンにVFを透過的に提供する

  4. VFの下にあるAFUは、仮想マシン内のアプリケーションからアクセス可能であり（VF内での同じドライバーを使用して）、動作します。

注意として、FMEはVFに割り当てられません。そのため、PRやその他の管理機能はPF経由でしか利用できません。

デバイスの列挙¶

このセクションでは、sysfs階層の/sys/class/fpga_region/下からFPGAデバイスをアプリケーションが列挙する方法について説明します。

以下例では、ホストに2つのDFLベースのFPGAデバイスがインストールされており、それぞれのFPGAデバイスには1つのFMEと2つのポート（AFU）があります。

FPGA領域は/sys/class/fpga_region/下に作成されます：

/sys/class/fpga_region/region0
/sys/class/fpga_region/region1
/sys/class/fpga_region/region2
...

アプリケーションは各regionXフォルダを検索し、機能デバイスが見つかった場合（例：「dfl-port.n」または「dfl-fme.m」が見つかった場合）、これはFPGAデバイスを表すベースのFPGA領域です。

各ベース領域には1つのFMEと2つのポート（AFU）が子デバイスとして含まれています：

/sys/class/fpga_region/region0/dfl-fme.0
/sys/class/fpga_region/region0/dfl-port.0
/sys/class/fpga_region/region0/dfl-port.1
...

/sys/class/fpga_region/region3/dfl-fme.1
/sys/class/fpga_region/region3/dfl-port.2
/sys/class/fpga_region/region3/dfl-port.3
...

一般的に、FME/AFUのsysfsインターフェースは次のようになります：

/sys/class/fpga_region/<regionX>/<dfl-fme.n>/
/sys/class/fpga_region/<regionX>/<dfl-port.m>/

「n」はすべてのFMEを連続して番号付けし、「m」はすべてのポートを連続して番号付けします。

ioctl()またはmmap()で使用するデバイスノードは次の通り参照できます：

/sys/class/fpga_region/<regionX>/<dfl-fme.n>/dev
/sys/class/fpga_region/<regionX>/<dfl-port.n>/dev

パフォーマンスカウンタ¶

パフォーマンスレポートはFME内で実装されたプライベートな機能です。ハードウェアで複数の独立した、システム全体のデバイスカウンタセットをサポートし、パフォーマンスイベント（「basic」、「cache」、「fabric」、「vtd」および「vtd_sip」カウンタ）を監視およびカウントします。ユーザーは標準のperfツールを使用してFPGAキャッシュヒット/ミス率、トランザクション数、AFUインターフェースクロックカウンタなどのFPGAパフォーマンスイベントを監視できます。

異なるFPGAデバイスはハードウェア実装に応じて異なるカウンタセットを持つ場合があります。例えば、一部のディスクリートFPGAカードはキャッシュを持たない場合があります。ユーザーは「perf list」を使用してターゲットハードウェアがサポートするperfイベントを確認できます。

ユーザーが標準のperf APIを使用してこれらのパフォーマンスカウンタにアクセスできるようにするため、ドライバーはperf PMUを作成し、/sys/bus/event_source/devices/dfl_fme* に関連するsysfsインターフェースを設置して、利用可能なperfイベントと設定オプションを記述します。

「format」ディレクトリは、struct perf_event_attr の config フィールドの形式を説明しています。config には 3 つのビットフィールドがあります：「evtype」は perf イベントが属するタイプを定義します。「event」はそのカテゴリ内でのイベントの識別子です。「portid」は FPGA 全体データか特定のポートを監視するカウンターを決定するために導入されました。

「events」ディレクトリは、perf ツールで直接使用可能なすべてのイベントの構成テンプレートを説明しています。たとえば、fab_mmio_read には「event=0x06,evtype=0x02,portid=0xff」という構成があり、このイベントはファブリックタイプ（0x02）に属し、ローカルイベントIDは 0x06 で、全体データの監視（portid=0xff）に使用されることが示されています。

perfの例的な使用法：

$# perf list |grep dfl_fme

dfl_fme0/fab_mmio_read/                              [Kernel PMU event]
<...>
dfl_fme0/fab_port_mmio_read,portid=?/                [Kernel PMU event]
<...>

$# perf stat -a -e dfl_fme0/fab_mmio_read/ <command>
or
$# perf stat -a -e dfl_fme0/event=0x06,evtype=0x02,portid=0xff/ <command>
or
$# perf stat -a -e dfl_fme0/config=0xff2006/ <command>

もう一つの例として、fab_port_mmio_read は特定のポートの mmio レッドを監視します。したがって、その構成テンプレートは「event=0x06,evtype=0x01,port, portid=?」です。この場合、portid は明示的に設定する必要があります。

perf の使用方法:

$# perf stat -a -e dfl_fme0/fab_port_mmio_read,portid=0x0/ <command>
or
$# perf stat -a -e dfl_fme0/event=0x06,evtype=0x02,portid=0x0/ <command>
or
$# perf stat -a -e dfl_fme0/config=0x2006/ <command>

ファブリックカウンターについてご注意ください。全体パフォーマンスイベント（fab_*) とポートパフォーマンスイベント（fab_port_*) はハードウェアで同じセットのカウンターを共有しているため、同時に監視することはできません。このセットのカウンターが全体データを監視するように設定されている場合、ポートごとのパフォーマンスデータはサポートされません。以下に例を示します:

$# perf stat -e dfl_fme0/fab_mmio_read/,dfl_fme0/fab_port_mmio_write,\
                                                  portid=0/ sleep 1

Performance counter stats for 'system wide':

               3      dfl_fme0/fab_mmio_read/
 <not supported>      dfl_fme0/fab_port_mmio_write,portid=0x0/

     1.001750904 seconds time elapsed

ドライバーはまた、「cpumask」sysfs 属性も提供しており、これにはこれらのパフォーマンスイベントにアクセスするための単一のCPU ID が含まれています。FPGA デバイス上のシステム全体のカウンターであるため、複数のCPUでのカウントは許可されていません。

現在のドライバーはサンプリングをサポートしていません。したがって、「perf record」はサポートされていません。

割込みサポート¶

一部のFMEおよびAFUプライベート機能は割込みを生成できます。上記のように、ユーザーはioctl (DFL_FPGA_*_GET_IRQ_NUM) を呼び出して、このプライベート機能でサポートされる割込みの有無や数を確認できます。ドライバーはまた、ユーザーが割込みが発生したときに通知を受け取れるように、eventfd 基盤の割込み処理メカニズムを実装しています。ユーザーはioctl (DFL_FPGA_*_SET_IRQ) を使ってドライバーにeventfdsを設定し、その後これらのeventfdsに対してpoll/selectを実行して通知を待つことができます。現在のDFLでは、3つのサブ機能（ポートエラー、FMEグローバルエラー、AFU割込み）が割込みをサポートしています。

新しいFIUsのサポートを追加¶

開発者はこのDFLフレームワーク内で新しい機能ブロック（FIUs）を作成した場合、新しい機能デバイス（FIU）用に新しいプラットフォームデバイスドライバーを開発する必要があります。既存の機能デバイスドライバー（例：FMEおよびポート/AFUプラットフォームデバイスドライバー）と同じ方法で、新しい機能デバイス（FIU）に対応する必要があります。さらに、DFLフレームワークの列挙コードにも変更が必要で、新しいFIUタイプの検出および関連するプラットフォームデバイスの作成に必要な処理を追加する必要があります。

新しいプライベート機能のサポートを追加¶

一部のケースでは、既存のFIUs（例: FMEまたはPort）に新しいプライベート機能を追加する必要があります。開発者はDFLフレームワーク内の列挙コードを触る必要がありません。各プライベート機能は自動的に解析され、DFLフレームワークによって作成されたFIUプラットフォームデバイスの下で関連するmmioリソースが自動的に検出されます。開発者は、一致した機能IDを持つサブ機能ドライバーのみを提供する必要があります。FME部分再構成サブ機能ドライバー（drivers/fpga/dfl-fme-pr.cを参照）が参考になります。

オープンな議論¶

FMEドライバーは現在、部分再構成用にユーザーに対してDFL_FPGA_FME_PORT_PRというioctlをエクスポートしています。今後、再構成用の統一されたユーザーインターフェースが追加された場合、FMEドライバーはioctlインターフェースからそれらに切り替える必要があります。
