S3C24XX スリープサポート¶

はじめに¶

S3C24XX は低電力スリープモードをサポートしており、SDRAM はセレフリッシュモードで維持され、必要な周辺機器以外は電源をオフにします。この仕組みの詳細については、サムスンの関連する CPU データシートをご参照ください。

要件¶

  1. 必要なリザーブ操作をサポートできるブートローダー

  2. リザーブ用の少なくとも1つのソースのサポート

  3. カーネルで CONFIG_PM が有効になっている

  4. 同時に電源を切られる Peripheral はスリープ/リザーブサポートが必要です。

リザーブ¶

S3C2410 ユーザーマニュアルはCPUをスリープ状態に移行し、リザーブするプロセスを定義しています。Linux コードのデフォルト動作は、リザーブ操作を再開するコードの物理アドレスを GSTATUS3 レジスタに設定します。

GSTATUS4 は現在、スリープコードによって無視されており、他の用途に自由に使用できます（例: EB2410ITX はこのレジスタを使用してメモリ設定を保存します）。

マシンサポート¶

マシン固有の関数は、ブートローダーがリザーブを実行可能であることを示す s3c_pm_init() 関数を呼び出す必要があります。これはマシンの定義に以下のコードを追加するだけでも可能です：

INITMACHINE(s3c_pm_init)

ボードが電源管理サポートのために他の設定を行う必要がある場合、s3c_pm_init() を呼び出す前に独自の初期化を行うことができます。

現在、リザーブアドレスの保存方法を上書きするサポートはありません。ボードでこの機能が必要な場合は、メンテナに連絡して必要な処理を相談してください。

注意: 元の late_initcall() の追加方法は誤っており、すべてのコンパイルされたマシンの pm 初期化が初期化されてしまいます。

以下は、IRQ_EINT0 の下降エッジからウェイクアップするためのテストコードの例です：

static irqreturn_t button_irq(int irq, void *pw)
{
    return IRQ_HANDLED;
}

statuc void __init machine_init(void)
{
    ...

    request_irq(IRQ_EINT0, button_irq, IRQF_TRIGGER_FALLING,
               "button-irq-eint0", NULL);

    enable_irq_wake(IRQ_EINT0);

    s3c_pm_init();
}

デバッグ¶

PM スリープを使用する際には以下の点を記憶してください：

  1. UART ドライバはスリープ時に UART ブロックのクロックを無効にします。そのため、printascii() や類似の UART 直接アクセスはデバッグを停止させます。

  2. pm コード自身は UART クロックを再有効化しようとしますが、UART が依存する外部クロックソースがその時点で有効であることを確認する必要があります。

  3. リザーブパスにデバッグコードを配置する場合、使用前に関連するクロックおよび Peripheral が設定されている必要があります（つまり、ブートローダー）。

    たとえば、UART から文字を送信する場合、ボーレートおよび UART コントロールが事前に設定されている必要があります。

設定¶

S3C2410 特定の設定は システムタイプ S3C2410 のスリープおよびリザーブサポートの構成方法を定義します

S3C2410 PM Suspend debug

このオプションは、実際のスリープの前後でシリアルコンソールにメッセージを出力し、発生している状況の詳細情報を提供します

S3C2410 PM Suspend Memory CRC

スリープの前後でメモリ全体をチェックサム計算し、内容の破損が発生していないか確認します

注意: CRCの計算にかかる時間はCPU速度とメモリのサイズに依存します。200MHzのS3C2410で64MbyteのRAM領域の場合、約4秒かかることがあります

この機能はCRC32関数が有効になっている必要があります

S3C2410 PM Suspend CRC Chunksize (KiB)

各CRCチャンクがカバーするメモリのサイズを定義します。小さな値を指定すると、CRCデータブロックのメモリ使用量は増えるものの、故障の検出精度が高まります
