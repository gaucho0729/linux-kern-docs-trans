インテル・アッサベット（SA-1110評価ボード）¶

参照してください: http://developer.intel.com

ジョン・G・ドーリーからもいくつかのノートがあります <jd5q@andrew.cmu.edu>: http://www.cs.cmu.edu/~wearable/software/assabet.html

カーネルのビルド¶

現在のデフォルト設定でカーネルをビルドするには:

make assabet_defconfig
make oldconfig
make zImage

結果として得られるカーネルイメージは、linux/arch/arm/boot/zImage にあります。

ブートローダーのインストール¶

アッサベットでLinuxを起動できるブートローダーはいくつかあります:

BLOB (http://www.lartmaker.nl/lartware/blob/)

BLOBはLARTプロジェクト内で使用されるブートローダーです。アッサベットのサポートを追加するために、いくつかの寄稿されたパッチがBLOBに統合されました。

コンパクのBootldr + ジョン・ドーリーのアッサベットサポート用パッチ (http://www.handhelds.org/Compaq/bootldr.html) (http://www.wearablegroup.org/software/bootldr/)

BootldrはコンパクがiPAQ Pocket PC用に開発したブートローダーです。ジョン・ドーリーはアッサベットとJFFSファイルシステムのサポートを追加する拡張パッチを制作しました。

RedBoot (http://sources.redhat.com/redboot/)

RedBootはRed HatがeCos RTOSハードウェア抽象レイヤーに基づいて開発したブートローダーです。多くのハードウェアプラットフォームをサポートしており、アッサベットもその一つです。

RedBootは現在、ネットワークサポートを備えている唯一のブートローダーであり、最も積極的にメンテナンスされているため、推奨されます。

RedBootでLinuxを起動するための簡単な例を以下に示します。ただし、まずRedBootをフラッシュメモリにインストールしておく必要があります。動作確認済みの事前にコンパイルされたRedBootバイナリは以下の場所から入手できます:

  • ftp://ftp.netwinder.org/users/n/nico/

  • ftp://ftp.arm.linux.org.uk/pub/linux/arm/people/nico/

  • ftp://ftp.handhelds.org/pub/linux/arm/sa-1100-patches/

redboot-assabet*.tgz を探してください。インストールに関する情報は redboot-assabet*.txt に記載されています。

初期RedBoot設定¶

ここで使用するコマンドは、オンラインで利用可能なRedBootユーザーズガイドに説明されています。 http://sources.redhat.com/ecos/docs.html説明についてはそちらを参照してください。

CFネットワークカード（私のアッサベットキットにはSocket Communications Inc.から提供されたCF+ LP-Eが含まれていました）を使用してTFTPファイル転送を行うことを強くお勧めします。RedBootが動く前にこのカードを挿す必要があります、なぜなら動的に検出できないからです。

フラッシュディレクトリを初期化するには:

fis init -f

非揮発性設定（BOOTPを使用するか、静的IPアドレスを使用するかなど）を初期化するには、次のコマンドを使用してください:

fconfig -i

カーネルイメージをフラッシュメモリに書き込む¶

まず、カーネルイメージをRAMにロードする必要があります。TFTPサーバーにzImageファイルが利用可能な場合、

load zImage -r -b 0x100000

シリアルポート経由でY-Modemアップロードを使用したい場合は:

load -m ymodem -r -b 0x100000

これをフラッシュメモリに書き込むには:

fis create "Linux kernel" -b 0x100000 -l 0xc0000

カーネルの起動¶

カーネルは起動にファイルシステムが必要です。ramdiskイメージは以下の手順でロードできます:

load ramdisk_image.gz -r -b 0x800000

再度、ファイル名を ‘-y ymodem’ に置き換えることで、TFTPではなくY-Modemアップロードを使用できます。

現在、カーネルはフラッシュメモリから以下のように取得できます:

fis load "Linux kernel"

または以前に説明した方法でロードすることもできます。カーネルを起動するには:

exec -b 0x100000 -l 0xc0000

ramdisk画像もフラッシュメモリに保存できますが、以下で説明するようにフラッシュメモリ用のファイルシステムにはより良い解決策があります。

JFFS2を使用する¶

JFFS2（Second Journalling Flash File System）は、書き込み可能なファイルシステムをフラッシュメモリに保存するための最も便利な方法かもしれません。JFFS2はMTDレイヤーと併用され、低レベルのフラッシュ管理を担当します。Linux MTDに関する詳細情報はオンラインで以下にあります: http://www.linux-mtd.infradead.org/. JFFS/JFFS2イメージの作成に関する情報とJFFSのハウツー記事は同じサイトから入手できます。

例えば、事前にコンパイルされたRedBootイメージ用に以下で述べたFTPサイトからサンプルのJFFS2イメージを取得できます。

このファイルをロードするには:

load sample_img.jffs2 -r -b 0x100000

結果は以下のようになります:

RedBoot> load sample_img.jffs2 -r -b 0x100000
Raw file loaded 0x00100000-0x00377424

現在、未割当のフラッシュメモリのサイズを把握する必要があります:

fis free

結果:

RedBoot> fis free
  0x500E0000 .. 0x503C0000

ファイルシステムのサイズやフラッシュメモリの種類によって、上の値は異なります。以下に使用例を示しますので、適切に自分の値に置き換えてください。

いくつかの値を決定する必要があります:

size of unallocated flash:      0x503c0000 - 0x500e0000 = 0x2e0000
size of the filesystem image:   0x00377424 - 0x00100000 = 0x277424

ファイルシステムイメージを当然ながら収める必要がありますが、すべての残りのフラッシュメモリスペースも確保したいです。これを書き込むには:

fis unlock -f 0x500E0000 -l 0x2e0000
fis erase -f 0x500E0000 -l 0x2e0000
fis write -b 0x100000 -l 0x277424 -f 0x500E0000
fis create "JFFS2" -n -f 0x500E0000 -l 0x2e0000

Linuxがブートプロセスでこれらが何であるかを発見した後、ファイルシステムはMTD「パーティション」に関連付けられます。RedBootから、'fis list'コマンドでこれらを表示できます:

RedBoot> fis list
Name              FLASH addr  Mem addr    Length      Entry point
RedBoot           0x50000000  0x50000000  0x00020000  0x00000000
RedBoot config    0x503C0000  0x503C0000  0x00020000  0x00000000
FIS directory     0x503E0000  0x503E0000  0x00020000  0x00000000
Linux kernel      0x50020000  0x00100000  0x000C0000  0x00000000
JFFS2             0x500E0000  0x500E0000  0x002E0000  0x00000000

しかしLinuxは以下のような表示をします:

SA1100 flash: probing 32-bit flash bus
SA1100 flash: Found 2 x16 devices at 0x0 in 32-bit mode
Using RedBoot partition definition
Creating 5 MTD partitions on "SA1100 flash":
0x00000000-0x00020000 : "RedBoot"
0x00020000-0x000e0000 : "Linux kernel"
0x000e0000-0x003c0000 : "JFFS2"
0x003c0000-0x003e0000 : "RedBoot config"
0x003e0000-0x00400000 : "FIS directory"

重要なのは、私たちが関心を持つパーティションの位置で、それは3番目のものです。Linux内でこれは/dev/mtdblock2に対応します。したがって、カーネルとそのルートファイルシステムをフラッシュメモリに配置してLinuxを起動するには、このRedBootコマンドが必要です:

fis load "Linux kernel"
exec -b 0x100000 -l 0xc0000 -c "root=/dev/mtdblock2"

JFFS以外のファイルシステム、例えばcramfsも使用可能です。ルートファイルシステムをNFS経由で起動したい場合もあります。また、ramdiskまたはNFSから起動しながら、フラッシュメモリにファイルシステムを直接書き込むことも可能です。Linux MTDリポジトリには、フラッシュメモリを操作するための多くのツールがあります（例：初期化）。JFFS2は、新規に初期化されたパーティションに直接マウントされ、ファイルを直接コピーできます。など…。

RedBootスクリプティング¶

Assabetを再起動するたびにコマンドを入力する必要があると、上のコマンドはあまり役立ちません。そのため、RedBootのスクリプティング機能を使用してブートプロセスを自動化することが可能です。

例えば、私はネットワーク上のTFTPサーバーから取得したカーネルとramdiskイメージでLinuxを起動するためにこれを使用します:

RedBoot> fconfig
Run script at boot: false true
Boot script:
Enter script, terminate with empty line
>> load zImage -r -b 0x100000
>> load ramdisk_ks.gz -r -b 0x800000
>> exec -b 0x100000 -l 0xc0000
>>
Boot script timeout (1000ms resolution): 3
Use BOOTP for network configuration: true
GDB connection port: 9000
Network debug at boot time: false
Update RedBoot non-volatile configuration - are you sure (y/n)? y

次に、Assabetの再起動はログインプロンプトを待つだけです。
