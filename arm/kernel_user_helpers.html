カーネル提供のユーザーヘルパー¶

これらは、ユーザー空間からカーネルメモリ内の固定アドレスからアクセス可能なカーネルが提供するユーザー用コードのセグメントです。これは、多くのARMプロセッサで実装されていないネイティブ機能や指令を必要とする操作をユーザー空間に提供するために使用されます。このコードは最適な効率のためにユーザーモードで直接実行されることが目的ですが、カーネルとの密接な関係によりユーザーライブラリに任せることはできません。実際には、使用可能な指令セットやSMPシステムかどうかによって、このコードはCPUごとに異なっていける可能性があります。言い換えれば、カーネルは必要に応じてこのコードを変更する権利を保有しています。ここに記載されているエントリポイントとその結果のみが安定して保証されます。

これは（ただし完全なVDSO実装とは排他的ではありません）VDSOの実装とは異なります。しかし、VDSOは定数を使ったアセンブリのトリックを防ぐため、このようなコードセグメントへの効率的なジャンプを妨げる可能性があります。また、これらのコードセグメントはユーザーコードに戻るまでに数サイクルしかかかりませんが、VDSOの間接遠隔呼び出しのオーバーヘッドは、このような最小限の操作に測定可能なオーバーヘッドをもたらします。

ユーザー空間は、最近のプロセッサでネイティブサポートがある場合、コンパイラが直接生成するコードやライブラリ呼び出しの実装内にこれらの機能をインラインで実装することを期待されます。ただし、コンパイルされたコードが他の用途で新しい指令を使用するため、古いARMプロセッサとの互換性を失う可能性がある場合を除き、これらのカーネル補助関数を使用しないでバイナリを生成しないでください。言い換えれば、他の用途で新しい指令を使用しない限り、古いプロセッサで実行できないバイナリを作成する必要はありません。

新しい補助関数が時間とともに追加されるため、古いカーネルは新しいカーネルに存在する補助関数を欠く場合があります。そのため、プログラムは、以下の__kuser_helper_versionの値を確認してから、どの補助関数も安全に呼び出せるかを判断する必要があります。この確認は理想的にはプロセス起動時に一度だけ行い、必要な補助関数がカーネルバージョンに提供されていない場合、早期に実行を中止する必要があります。

kuser_helper_version¶

Location: 0xffff0ffc

Reference declaration:

extern int32_t __kuser_helper_version;

Definition:

このフィールドには、現在実行中のカーネルが実装しているアシスタントの数が含まれています。ユーザー空間はこのフィールドを読み取ることで、特定のアシスタントの利用可能性を確認できます。

使用例:

#define __kuser_helper_version (*(int32_t *)0xffff0ffc)

void check_kuser_version(void)
{
      if (__kuser_helper_version < 2) {
              fprintf(stderr, "can't do atomic operations, kernel too old\n");
              abort();
      }
}

注意：

ユーザー空間は、このフィールドの値が単一のプロセスの寿命中に変化しないと想定できます。これは、このフィールドをライブラリの初期化時またはプログラムの起動フェーズにおいて一度読み取るだけで十分であることを意味します。

typedef void * (__kuser_get_tls_t)(void);

kuser_cmpxchg¶

Location: 0xffff0fc0

参照プロトタイプ:

int __kuser_cmpxchg(int32_t oldval, int32_t newval, volatile int32_t *ptr);

入力:

r0 = 旧値 r1 = 新値 r2 = ポインタ lr = 戻り先アドレス

出力:

r0 = 成功コード (ゼロまたは非ゼロ) Cフラグ = r0 == 0 の場合設定、r0 != 0 の場合クリア

破壊されるレジスタ:

r3, ip, フラグ

Definition:

アトミックに newval を *ptr に保存 *ptr only if *ptr oldval が等しい場合。変更された場合はゼロを返す *ptr 変更された場合はゼロを返す。交換が行われなかった場合はゼロ以外を返す。Cフラグも設定される *ptr 変更されたことで、呼び出し元のコードでのアセンブリ最適化を可能にする

使用例:

typedef int (__kuser_cmpxchg_t)(int oldval, int newval, volatile int *ptr);
#define __kuser_cmpxchg (*(__kuser_cmpxchg_t *)0xffff0fc0)

int atomic_add(volatile int *ptr, int val)
{
      int old, new;

      do {
              old = *ptr;
              new = old + val;
      } while(__kuser_cmpxchg(old, new, ptr));

      return new;
}

注意：

  • このルーチンは必要なメモリーバリアをすでに含んでいます

  • __kuser_helper_version >= 2 (カーネルバージョン 2.6.12 からの) にのみ有効です

kuser_cmpxchg64¶

場所: 0xffff0f60

参照プロトタイプ:

int __kuser_cmpxchg64(const int64_t *oldval,
                      const int64_t *newval,
                      volatile int64_t *ptr);

入力:

r0 = oldval へのポインタ r1 = newval へのポインタ r2 = ターゲット値へのポインタ lr = 戻り先アドレス

出力:

r0 = 成功コード (ゼロまたは非ゼロ) Cフラグ = r0 == 0 の場合設定、r0 != 0 の場合クリア

破壊されるレジスタ:

r3, lr, フラグ

Definition:

64 ビット値を原子的に保存します *newval の *ptr only if *ptr が 64 ビット値を指している場合 *oldval. 変更された場合はゼロを返します *ptr 変更された場合はゼロを返します。交換が行われなかった場合はゼロ以外を返します

Cフラグは、以下の条件が満たされる場合にも設定されます。 *ptr 変更されたことで、呼び出し元のコードでのアセンブリ最適化を可能にする

使用例:

typedef int (__kuser_cmpxchg64_t)(const int64_t *oldval,
                                  const int64_t *newval,
                                  volatile int64_t *ptr);
#define __kuser_cmpxchg64 (*(__kuser_cmpxchg64_t *)0xffff0f60)

int64_t atomic_add64(volatile int64_t *ptr, int64_t val)
{
      int64_t old, new;

      do {
              old = *ptr;
              new = old + val;
      } while(__kuser_cmpxchg64(&old, &new, ptr));

      return new;
}

注意：

  • このルーチンは必要なメモリーバリアをすでに含んでいます

  • このシーケンスの長さにより、これは2つの従来のkuser「スロット」をまたぐため、0xffff0f80は有効なエントリポイントとして使用されません。

  • __kuser_helper_versionが5以上である場合にのみ有効です（カーネルバージョン3.1から）。
