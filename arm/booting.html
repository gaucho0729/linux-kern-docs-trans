ARM Linuxの起動¶

著者: Russell King

日付: 2002年5月18日

以下のドキュメンテーションは2.4.18-rmk6以降のバージョンに適用されます。

ARM Linuxを起動するには、ブートローダーが必要です。ブートローダーはメインのカーネルが実行される前に動作する小さなプログラムであり、各種デバイスを初期化し、最終的にLinuxカーネルを呼び出して情報を渡します。

基本的に、ブートローダーは以下のものを提供する必要があります（最低限）:

  1. RAMの設定と初期化。

  2. シリアルポートの初期化。

  3. マシンタイプの検出。

  4. カーネルタグリストの設定。

  5. initramfsのロード。

  6. カーネルイメージの呼び出し。

1. RAMの設定と初期化¶

既存のブートローダー:

必須

新しいブートローダー:

必須

ブートローダーは、カーネルがシステムで揮発性データストレージとして使用するすべてのRAMを検出・初期化する必要があります。これは機種依存の方法で実行されます。（内部アルゴリズムを用いてすべてのRAMを自動的に検出・サイズ指定するか、機種のRAMに関する知識を使用するか、ブートローダー設計者に任せる他の方法を使用する可能性があります。）

2. シリアルポートの初期化¶

既存のブートローダー:

オプションですが推奨

新しいブートローダー:

オプションですが推奨

ブートローダーはターゲットに1つのシリアルポートを初期化・有効化する必要があります。これにより、カーネルのシリアルドライバーがカーネルコンソールとして使用するシリアルポートを自動的に検出できます（デバッグ目的やターゲットとの通信に一般的に使用されます）。

代替として、ブートローダーはタグリストを通じて、ポートやシリアル形式オプションを指定した「console=」オプションをカーネルに渡すことができます。詳しくは

カーネルのコマンドラインパラメータ.

3. マシンタイプの検出¶

既存のブートローダー:

オプション

新しいブートローダー:

DT専用プラットフォームを除き必須

ブートローダーは、実行しているマシンタイプを何らかの方法で検出する必要があります。これはハードコードされた値か、接続されたハードウェアを確認するアルゴリズムかはこのドキュメンテーションの範囲外です。最終的にはブートローダーはカーネルにMACH_TYPE_xxx値を提供できる必要があります（linux/arch/arm/tools/mach-typesを参照）。この値はレジスタr1に渡す必要があります。

DT専用プラットフォームでは、マシンタイプはデバイスツリーによって決定されます。マシンタイプをすべて1に設定 (~0) します。これは厳密には必要ではありませんが、既存のタイプと一致しないことを保証します。

4. ブートデータの設定¶

既存のブートローダー:

オプションですが強く推奨

新しいブートローダー:

必須

ブートローダーはカーネルに構成データを渡すためにタグリストまたはdtbイメージを提供する必要があります。ブートデータの物理アドレスはレジスタr2にカーネルに渡されます。

4a. カーネルタグリストの設定¶

ブートローダーはカーネルタグリストを作成し、初期化する必要があります。有効なタグリストはATAG_COREで始まり、ATAG_NONEで終了します。ATAG_COREタグは空でも空でないかもしれません。空のATAG_COREタグはサイズフィールドに「2」（0x00000002）が設定されます。ATAG_NONEはサイズフィールドをゼロに設定する必要があります。

リストに配置できるタグの数は任意です。繰り返しのタグが前のタグの情報を追加するか、それとも完全に置き換えるかは未定義です。一部のタグは前者、他のタグは後者の動作を行います。

ブートローダーは少なくともシステムメモリのサイズと位置、およびルートファイルシステムの位置を渡す必要があります。したがって、最小限のタグリストは以下のようになります：

              +-----------+
base ->       | ATAG_CORE |  |
              +-----------+  |
              | ATAG_MEM  |  | increasing address
              +-----------+  |
              | ATAG_NONE |  |
              +-----------+  v

タグリストはシステムRAMに保存する必要があります。

タグリストは、カーネルデコンプレッサーやinitrdの「bootp」プログラムが上書きしないメモリ領域に配置する必要があります。推奨される配置はRAMの最初の16KiBです。

4b. デバイスツリーの設定¶

ブートローダーは、デバイスツリーイメージ（dtb）を64ビットアライメントのアドレスにシステムRAMにロードし、ブートデータで初期化する必要があります。dtb形式の詳細はDocumentation/devicetree/booting-without-of.rstを参照してください。カーネルはdtb物理アドレスでdtbマジック値0xd00dfeedを検索し、タグリストではなくdtbが渡されたかを判断します。

ブートローダーは少なくともシステムメモリのサイズと位置、およびルートファイルシステムの位置を渡す必要があります。dtbはカーネルデコンプレッサーが上書きしないメモリ領域に配置する必要がありますが、カーネルのローメモリマッピング範囲内に収める必要があります。

安全な配置場所はRAMの開始位置から128MiB境界を超えた場所です。

5. initramfsのロード¶

既存のブートローダー:

オプション

新しいブートローダー:

オプション

initramfsを使用している場合、dtb同様に、カーネルデコンプレッサーが上書きしないメモリ領域に配置する必要があります。また、カーネルのローメモリマッピング範囲内に収める必要があります。

安全な配置場所は、デバイスツリーのblobがロードされる128MiB境界を超えた場所に配置するのが安全です。

6. カーネルイメージの呼び出し¶

既存のブートローダー:

必須

新しいブートローダー:

必須

カーネルzImageを呼び出すには2つのオプションがあります。zImageがフラッシュに保存されており、フラッシュから実行されるように正しくリンクされている場合、ブートローダーはフラッシュ内のzImageを直接呼び出すことが許可されます。

zImageはシステムRAMに配置され、そこから呼び出すことも可能です。カーネルはRAMの最初の128MiBに配置する必要があります。デコンプレッション前の再配置を避けるために32MiB以上にロードすることをお勧めします。これにより、ブートプロセスがやや速くなります。

raw（非zImage）カーネルをブートする場合、制約が厳しくなります。この場合、カーネルはシステムメモリ内のTEXT_OFFSET - PAGE_OFFSETにロードする必要があります。

いずれにせよ、以下の条件を満たす必要があります：

  • DMAをサポートするすべてのデバイスを停止し、メモリが不正なネットワークパケットやディスクデータによって破損しないようにします。これにより、デバッグにかかる時間を大幅に短縮できます。

  • CPUレジスタ設定

    • r0 = 0,

    • r1 = 上記（3）で発見したマシンタイプ番号。

    • r2 = システムRAM内のタグ付きリストの物理アドレス、またはシステムRAM内のデバイスツリーブロック（dtb）の物理アドレス

  • CPUモード

    すべての割込みは無効にする必要があります（IRQとFIQ）

    ARM仮想化拡張機能をサポートしないCPUでは、CPUはSVCモードでなければなりません。（Angelを除く特別な例外があります）

    仮想化拡張機能をサポートするCPUは、HYPモードで起動することで、カーネルがこれらの拡張機能を最大限に活用できるようになります。このようなCPUでは、事前にインストールされたハイパーコアが仮想化をすでに使用している場合を除き、このブート方法が推奨されます。

    何らかの理由でカーネルがHYPモードで起動しない場合、SVCモードで起動する必要があります。

  • キャッシュ、MMU

    MMUはオフにする必要があります。

    インストラクションキャッシュはオンでもオフでも可能です。

    データキャッシュはオフにする必要があります。

    カーネルがHYPモードで起動する場合、HYPモードの設定に上記の要件が適用されます。さらに、ハイパーコアへのトラップは無効にし、アーキテクチャ的に可能であればすべての周辺機器およびCPUリソースへのPL1アクセスを許可する必要があります。HYPモードへの移行以外では、仮想化拡張機能をサポートしていないカーネルが正常に起動できるようにするため、システム設定は追加の支援なしで正しい必要があります。

  • ブートローダーは、カーネルイメージの最初の命令にジャンプしてカーネルイメージを呼び出す必要があります。

    ARM指令セットをサポートするCPUでは、ARM状態で起動する必要があります。Thumb-2カーネルであっても同様です。

    Thumb指令セットのみをサポートするCPU（例：Cortex-MクラスのCPU）では、Thumb状態で起動する必要があります。
