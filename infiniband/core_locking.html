InfiniBandミドルレイヤーのロック¶

このガイドでは、InfiniBand midlayerが行うロックの前提条件を明確にし、midlayerの下にある低レベルドライバーやmidlayerを使用する上位プロトコルに対する要件を説明しています。

スリープと割込みコンテキスト¶

struct ib_deviceのすべてのメソッドの低レベルドライバーアイムPLEMENTATIONは、以下の例外を除いてスリープすることがあります。例外は以下のメソッドです：

  • create_ah

  • modify_ah

  • query_ah

  • destroy_ah

  • post_send

  • post_recv

  • poll_cq

  • req_notify_cq

これらはスリープしない可能性があり、任意のコンテキストから呼び出せる必要があります。

上位プロトコル消費者にエクスポートされる関連する関数：

  • rdma_create_ah

  • rdma_modify_ah

  • rdma_query_ah

  • rdma_destroy_ah

  • ib_post_send

  • ib_post_recv

  • ib_req_notify_cq

これらはしたがって、任意のコンテキストから呼び出すことができます。

さらに、低レベルドライバーがmidlayerを通じて非同期イベントをディスパッチする際に使用する関数

  • ib_dispatch_event

も任意のコンテキストから呼び出すことができます。

再入可能¶

low-level driverがエクスポートするstruct ib_deviceのすべてのメソッドは完全に再入可能でなければなりません。低レベルドライバーは、同一オブジェクトを複数の関数呼び出しが同時に実行される場合でも、一貫性を維持するためのすべての同期処理を実行する必要があります。

IB midlayerは関数呼び出しのシリアル化を行いません。

低レベルドライバーが再入可能であるため、上位プロトコル消費者はシリアル化を行う必要はありません。ただし、適切な結果を得るために一部のシリアル化が必要な場合があります。たとえば、消費者はib_poll_cq()を複数のCPUで同時に呼び出すことができますが、ib_poll_cq()の異なる呼び出し間での作業完了情報の順序は定義されていません。

コールバック¶

低レベルドライバーは、ib_deviceメソッド呼び出しの同じコールチェーンから直接コールバックを実行してはなりません。たとえば、low-level driverはpost_sendメソッドから消費者の完了イベントハンドラを直接呼び出すことはできません。代わりに、タスクレットをスケジュールしてコールバックを実行するなど、コールバックを遅延させる必要があります。

low-level driverは、同一のCQに対する複数の完了イベントハンドラが同時に呼び出されないようにする必要があります。ドライバーは、特定のCQに対して同時に1つのみCQイベントハンドラが実行されていることを保証しなければなりません。言い換えれば、以下の状況は許容されません：

      CPU1                                    CPU2

low-level driver ->
  consumer CQ event callback:
    /* ... */
    ib_req_notify_cq(cq, ...);
                                      low-level driver ->
    /* ... */                           consumer CQ event callback:
                                          /* ... */
    return from CQ event handler

完了イベントおよび非同期イベントコールバックが実行されるコンテキストは定義されていません。低レベルドライバーによっては、プロセスコンテキスト、ソフトIRQコンテキスト、または割込みコンテキストのいずれかになる可能性があります。上位レベルプロトコル消費者はコールバック内でスリープしてはいけません。

ホットプラグ¶

低レベルドライバーが消費者がデバイスを使用できるようにする際には、デバイスが利用可能であることを通知するために、 ib_register_device()この呼び出しを行う前にすべての初期化が完了している必要があります。ドライバーがこの呼び出しを行うまで、デバイスは利用可能でなければなりません。 ib_unregister_device() が返却した後には使用しません。

低レベルドライバーは、プロセスコンテキストから呼び出す必要があります。 ib_register_device() および ib_unregister_device() これらの呼び出しを通じて消費者がドライバーに逆にコールバックする場合に、デッドロックを引き起こす可能性のあるセマフォアを保持してはいけません。

上位レベルプロトコル消費者は、そのstruct ib_clientのaddメソッドがデバイスに対して呼び出された時点で、IBデバイスを使用を開始できます。消費者はremoveメソッドから戻る前に、デバイスに関するすべてのクリーンアップを完了し、すべてのリソースを解放する必要があります。

消費者はaddおよびremoveメソッド内でスリープすることが許可されています。
