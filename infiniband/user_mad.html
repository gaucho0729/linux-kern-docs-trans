ユーザースペースMADアクセス¶

デバイスファイル¶

各InfiniBandデバイスの各ポートには「umad」デバイスと「issm」デバイスが接続されています。たとえば、2ポートのHCA（Host Channel Adapter）は2つのumadデバイスと2つのissmデバイスを持ち、スイッチはスイッチポート0用にそれぞれ1つのデバイスを持ちます。

MADエージェントの作成¶

MADエージェントは、struct ib_user_mad_reg_reqを埋め込み、適切なデバイスファイルのファイルディスクリプタに対してIB_USER_MAD_REGISTER_AGENT ioctlを呼び出すことで作成できます。登録要求が成功した場合、32ビットのIDが構造体に返されます。例えば：

struct ib_user_mad_reg_req req = { /* ... */ };
ret = ioctl(fd, IB_USER_MAD_REGISTER_AGENT, (char *) &req);
if (!ret)
        my_agent = req.id;
else
        perror("agent register");

IB_USER_MAD_UNREGISTER_AGENT ioctlを使用してエージェントを解除できます。また、ファイルディスクリプタを通じて登録されたすべてのエージェントは、ディスクリプタが閉じるときに自動的に解除されます。

2014

新たに登録ioctlが提供され、登録時に追加のフィールドを指定できるようになりました。この登録呼び出しの利用者は、暗黙的にpkey_indexの使用を設定します（以下参照）。

MADの受信¶

MADはread()を使用して受信します。受信側はRMPPをサポートしています。read()に渡すバッファは、少なくともstruct ib_user_mad + 256バイト以上である必要があります。例えば：

渡されたバッファが受信したMAD（RMPP）を収容するサイズが不十分な場合、errnoはENOSPCに設定され、必要なバッファの長さはmad.lengthに設定されます。

通常のMAD（非RMPP）読み取りの例：

struct ib_user_mad *mad;
mad = malloc(sizeof *mad + 256);
ret = read(fd, mad, sizeof *mad + 256);
if (ret != sizeof mad + 256) {
        perror("read");
        free(mad);
}

RMPP読み取りの例：

struct ib_user_mad *mad;
mad = malloc(sizeof *mad + 256);
ret = read(fd, mad, sizeof *mad + 256);
if (ret == -ENOSPC)) {
        length = mad.length;
        free(mad);
        mad = malloc(sizeof *mad + length);
        ret = read(fd, mad, sizeof *mad + length);
}
if (ret < 0) {
        perror("read");
        free(mad);
}

実際のMADの内容に加えて、struct ib_user_madの他のフィールドには受信したMADに関する情報が埋め込まれます。例えば、リモートLIDはmad.lidに格納されます。

送信がタイムアウトした場合、mad.statusがETIMEDOUTに設定された受信が生成されます。成功したMADの受信の場合、mad.statusは0になります。

poll()/select()を使用してMADが読み込めるのを待つことができます。

MADの送信¶

MADはwrite()を使用して送信します。送信用のエージェントIDはMADのidフィールドに、宛先LIDはlidフィールドに設定します。送信側はRMPPをサポートしているため、任意の長さのMADを送信できます。例えば：

struct ib_user_mad *mad;

mad = malloc(sizeof *mad + mad_length);

/* fill in mad->data */

mad->hdr.id  = my_agent;        /* req.id from agent registration */
mad->hdr.lid = my_dest;         /* in network byte order... */
/* etc. */

ret = write(fd, &mad, sizeof *mad + mad_length);
if (ret != sizeof *mad + mad_length)
        perror("write");

トランザクションID¶

umadデバイスの利用者は、送信するMADにトランザクションIDフィールドの下位32ビット（ネットワークバイトオーダーでのフィールドの最下位ハーフ）を使用して、リクエスト/レスポンスペアを一致させることができます。上位32ビットはカーネルによって使用され、送信前に上書きされます。

P_Keyインデックスの処理¶

古いib_umadインターフェースは、送信されるMADに対してP_Keyインデックスを設定できず、受信したMADのP_Keyインデックスを取得する方法も提供していませんでした。struct ib_user_mad_hdrの新しいレイアウトが定義され、pkey_indexメンバが追加されました。ただし、古いアプリケーションとのバイナリ互換性を維持するため、この新しいレイアウトは、ファイルディスクリプタが他の用途に使用される前にIB_USER_MAD_ENABLE_PKEYまたはIB_USER_MAD_REGISTER_AGENT2 ioctlが呼び出されない限り使用されません。

2008年9月にIB_USER_MAD_ABI_VERSIONが6にインクリメントされ、struct ib_user_mad_hdrの新しいレイアウトがデフォルトで使用され、IB_USER_MAD_ENABLE_PKEY ioctlは削除されます。

IsSM機能ビットの設定¶

ポートのIsSM機能ビットを設定するには、対応するissmデバイスファイルを開くだけでよいです。IsSMビットがすでに設定されている場合、open呼び出しはそのビットがクリアされるまでブロックします（O_NONBLOCKフラグをopen()に渡した場合は、errnoがEAGAINに設定されて即座に返ります）。issmファイルが閉じられるとIsSMビットはクリアされます。issmファイルに対して読み取り、書き込みまたはその他の操作は行えません。

/devファイル¶

udevを用いて適切なキャラクタデバイスファイルを自動的に作成するには、次のルールのようなものを使います：

KERNEL=="umad*", NAME="infiniband/%k"
KERNEL=="issm*", NAME="infiniband/%k"

これにより、以下のデバイスノードが作成されます：

/dev/infiniband/umad0
/dev/infiniband/issm0

最初のポートに対応し、同様に続くため、これらのデバイスに関連するInfiniBandデバイスおよびポートは以下のファイルから確認できます：

/sys/class/infiniband_mad/umad0/ibdev
/sys/class/infiniband_mad/umad0/port

および：

/sys/class/infiniband_mad/issm0/ibdev
/sys/class/infiniband_mad/issm0/port
