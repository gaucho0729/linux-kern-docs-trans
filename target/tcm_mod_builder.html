TCM v4 ファブリックモジュールスクリプトジェネレータ¶

皆様へ

このドキュメントは、tcm_mod_builder.py スクリプトを使用して、独自の新しい TCM v4 ファブリック .ko モジュールを生成する mini-HOWTO です。生成されたモジュールはすぐにビルドしてロードし、新しい TCM/ConfigFS ファブリックスケルトンにアクセスを開始できます。以下のように単純に使用できます：

modprobe $TCM_NEW_MOD
mkdir -p /sys/kernel/config/target/$TCM_NEW_MOD

このスクリプトは、新しい drivers/target/$TCM_NEW_MOD/ を作成し、以下を行います

  1. drivers/target/target_core_fabric_configs.c のロジックに新しい API カルラを生成します（->make_tpg()、->drop_tpg()、->make_wwn()、->drop_wwn()）。これらは $TCM_NEW_MOD/$TCM_NEW_MOD_configfs.c に作成されます

  2. LKMs および TCM/ConfigFS ファブリックモジュールのロード/アンロードに必要な基本インフラストラクチャを生成します。これは skeleton struct target_core_fabric_ops API テンプレートを使用します

  3. ユーザーが定義した T10 Proto_Ident に基づき、drivers/target/target_core_fabric_lib.c のロジックを使用して、$TCM_NEW_MOD/$TCM_NEW_MOD_fabric.c に TransportID / Initiator および Target WWPN 関連の SPC-3 パーシステントリザーブハンドラを自動生成します

  4. $TCM_NEW_MOD/$TCM_NEW_MOD_fabric.c にすべてのその他のデータ I/O パスおよびファブリック依存属性ロジックの NOP API 呼び出しを生成します

tcm_mod_builder.py は必須パラメータである '-p $PROTO_IDENT' および '-m $FABRIC_MOD_name' に依存しており、スクリプトを実際に実行すると以下のようになります：

tcm_mod_builder.py の終了時に、drivers/target/Kbuild に以下の行を追加するよう求められます：

obj-$(CONFIG_TCM_NAB5000)       += tcm_nab5000/

drivers/target/Kconfig にも同様に以下の行を追加します：

source "drivers/target/tcm_nab5000/Kconfig"

  1. 「make menuconfig」を実行し、新しい CONFIG_TCM_NAB5000 オプションを選択します：

    <M>   TCM_NAB5000 fabric module
